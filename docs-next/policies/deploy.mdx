A deployment connects one or more policy versions to a target set of enrolled machines.

## Apply a deployment

<Tabs>
  <Tab title="Dashboard">
    1. Go to **Administration → Deploy policies**.
    2. Search by machine ID or display label. Expand the machine row.
    3. Select **edit**. Add the reviewed policy version and choose **observe** or its enforcing effect.
    4. Apply the change. The full selected set becomes one new deployment for that machine.
    5. Wait for the machine's next check-in and confirm the applied deployment and coverage state.
    6. Go to **Observe → Policy** to inspect live decisions.

    <Info>Screenshot placeholder: Expanded machine row, policy selector, effect selector, and applied deployment.</Info>
  </Tab>
  <Tab title="CLI">
    Cloud deployment endpoints are intentionally not exposed as ordinary `fp` commands. Check the machine locally, then deploy through the dashboard:

    ```bash
    failproofai config --status
    ```

    Use `fp sessions --env production --since 24h` and `fp events --event-type hook_completed` after deployment to verify activity reaches Cloud.
  </Tab>
</Tabs>

<Steps>
  <Step title="Select a version">
    Deploy the reviewed version, not the mutable draft you happen to have open.
  </Step>
  <Step title="Choose targets">
    Start with a non-production machine or a small cohort whose sessions you can inspect.
  </Step>
  <Step title="Observe decisions">
    Review matches, reasons, affected tools, and false positives without blocking work.
  </Step>
  <Step title="Enforce">
    Promote after the observed matches separate unsafe actions from valid ones.
  </Step>
  <Step title="Verify coverage">
    Confirm every intended machine has pulled the deployment and is reporting decisions.
  </Step>
</Steps>

Machines need the `policies:pull` capability. Event reporting is separately controlled by `events:add`; verify both when you expect Cloud analysis and enforcement.

<Warning>
  Enforcement management is an administrative Cloud workflow. Do not treat root-only enforcement routes as ordinary customer `/v1` API endpoints.
</Warning>
