```bash
npm install -g failproofai@latest && failproofai update
```

זה כל השדרוג. `npm` מחליף את ה-CLI; `failproofai update` עושה את השאר.

## למה קיימת פקודה שנייה

`npm install -g` מחליף דבר אחד בלבד — ה-CLI. שני חלקים נוספים של התקנת failproofai חיים מחוץ לחבילה בכוונה, וגם לא זז כשnpm רץ:

- **`~/.failproofai/`**, ההגדרות שלך, הרישום בענן, בחירת המדיניות והיסטוריה. גרסה חדשה עשויה לארגן זאת אחרת, וההארגון מחדש חייב להיעשות על ידי קוד שמכיר שתי צורות.
- **ה-daemon binary של `failproofaid`**, בכתובת `~/.failproofai/bin/failproofaid-<version>`. הוא בכוונה *לא* בתוך `node_modules`: שדרוג שהחליף את הקובץ תחת שירות פעיל היה מפנה daemon חי לבינארי שנבנה מקוד שונה, והסרת החבילה היתה מחקה אותו תחת שירות שהיה ואז crash-loops בכל איתחול.

אז אחרי `npm install -g` בלבד, ה-CLI חדש ו-daemon לא. `failproofaid` מסרב להתחיל מול פריסת בית שהוא לא מדבר — הגרסה החזקה של ההתאמה ההיא ולא השקטה — אז שני החצאים צריכים להיות מובאים ביחד. `failproofai update` היא הצעד הזה.

## מה הוא עושה

<Steps>
  <Step title="מפעיל כל הגדרות פריסה שממתינות">
    קוראת את הפריסה המתועדת ב-`~/.failproofai/VERSION` והפעיל את הצעדים שמביאים אותה לזו שגרסה זו דוברת. בדרך כלל אין — ראה [`failproofai migrate`](/he/cli/migrate).
  </Step>
  <Step title="מציבה את ה-daemon binary התואם במקום">
    מחבילת הפלטפורמה שnpm כבר הורידה במידת האפשר (ללא רשת), אחרת מנכס השחרור לגרסה זו בדיוק, SHA-256 מאומת לפני שהוא משמש.
  </Step>
  <Step title="מפעילה מחדש את השירות ומאשרת שהוא חזר">
    בדוקה ולא בהנחה — מנהל שירות דיווח על תהליך פעיל ברגע שהוא fork, וזה לא אותו דבר כמו שהוא עובד.
  </Step>
</Steps>

## אפשרויות

| דגל | השפעה |
|------|--------|
| `--no-daemon` | הצג את הבית בלבד, להשאיר את ה-daemon בגרסה הנוכחית שלו. |

<Warning>
  `--no-daemon` משאיר daemon בעל גרסה מוטה במקום. על מכונה המוגדרת להדרוש את ה-daemon, כל אירוע hook **נכשל סגור** אם ה-daemon לא יכול לענות — ו-daemon שמסרב להתחיל מול בית מהוגר לא יכול לענות. עדיף לתת לחצי ה-daemon לרוץ.
</Warning>

## אם משהו הולך לא בסדר

הפקודה יוצאת לא-אפס ואומרת איזה חצי נכשל. שתי מקרים שכדאי לדעת:

- **צעד הגדרה לא הסתיים.** הבית נשאר מסומן עם הפריסה *הישנה* שלו, אז הפקודה הבאה חוזרת עליה — הבית לעולם לא מסומן כעדכני בחוזק של הגדרה חלקית. עותקים של ההגדרות שלך והרישום בענן נשמרו לפני שהיה כל דבר, ב-`~/.failproofai/migrations/backup-layout<n>/`.
- **ה-daemon לא יכול היה להיות מופעל מחדש ללא סיסמה.** `sudo -n` משמש בכוונה, אז כלום לעולם לא מבקש מתוך תצוגת התקדמות. הפקודה מדפיסה את השורה המדויקת להפעלה בעצמך.

<Note>
  כלום כאן לא צריך את אשף ההתקנה האינטראקטיבי. ההגדרות שלך, הרישום בענן וגם בחירת המדיניות שורדים שדרוג, אז מכונה מהוגרת אוכפת בדיוק כמו שהיא עשתה קודם — מה שחשוב ביותר על מכונות שאין להן אף אחד יושב בהן: CI runner, fleet box, headless gateway.
</Note>

## אוטומציה שלה

`failproofai update` לא אינטראקטיבי וניתן להפעלה בבטחה כשאין כלום לעשות — היא מדווחת "לא הייתה צורך בהגדרה" ויוצאת 0. הצבתו אחרי כל שדרוג בתסריט הספקה או Dockerfile היא השימוש הכוונה:

```dockerfile
RUN npm install -g failproofai@latest && failproofai update --no-daemon
```

(`--no-daemon` בבנייה של תמונה, שם אין שירות להפעלה מחדש עדיין.)
