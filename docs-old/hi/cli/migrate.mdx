description: "~/.failproofai को इस संस्करण के लेआउट तक लाएं, और पहले देखें कि क्या होगा"
---

```bash
failproofai migrate --dry-run   # योजना प्रिंट करें, कुछ न बदलें
failproofai migrate             # इसे चलाएं
```

अधिकांश लोग इसे कभी टाइप नहीं करते। यह अपग्रेड के बाद पहली कमांड पर अपने आप चलता है, और [`failproofai update`](/hi/cli/update) इसे शामिल करता है। इसे सीधे तब प्राप्त करें जब आप योजना को होने से पहले देखना चाहते हों, या माइग्रेशन को अपने आप चलाना चाहते हों।

## संस्करण के बजाय लेआउट पर कुंजी रखी गई

`~/.failproofai/VERSION` एक **लेआउट** संख्या रिकॉर्ड करता है — डायरेक्टरी का आकार, जो इसे लिखने वाला रिलीज़ नहीं है। माइग्रेशन उस संख्या पर कुंजी रखे जाते हैं, जो एक लंबे अंतर को सस्ता बनाता है:

- npm संस्करण हर रिलीज़ पर बदलते हैं, दो लेआउट के बीच दर्जनों।
- तो एक मशीन जो **बिना किसी लेआउट परिवर्तन** के तीस रिलीज़ को छोड़ती है, **शून्य** माइग्रेशन चलाती है, तीस नो-ऑप्स नहीं।
- और एक मशीन जो एक साथ कई लेआउट को छोड़ती है, हर चरण को क्रम में चलाती है, प्रत्येक चरण केवल अपने स्वयं के दोनों सिरों को जानता है।

यह महत्वपूर्ण है क्योंकि npm एक स्थापित पैकेज को अपने आप अपडेट नहीं कर सकता। एक मशीन जो महीनों तक एक संस्करण पर बैठती है और फिर कई लेआउट को जंप करती है, वह असामान्य मामला नहीं है, बल्कि सामान्य मामला है।

## ड्राई रन

`--dry-run` सटीक चेन और उन फाइलों को प्रिंट करता है जो पहले सहेजी जाएंगी, और कुछ भी बदलता नहीं है — कोई माइग्रेशन नहीं, कोई बैकअप नहीं, कोई लेजर प्रविष्टि नहीं:

```
डिस्क पर लेआउट 2; यह बिल्ड 3 बोलता है।
1 चरण(ओं) चलेगा:
  2 → 3  लेआउट 2 → 3: config.toml और credentials.toml को JSON में ले जाएं, custom-policies/ को policies/ में वापस ले जाएं, नीति कॉन्फ़िग को रूट पर नेस्ट करें

ये ~/.failproofai/migrations/backup-layout2 में पहले कॉपी किए जाएंगे:
  VERSION
  config.toml
  credentials.toml
```

## क्या ले जाया जाता है, और क्या पुनर्निर्मित किया जाता है

होम में हर पथ घोषित करता है कि यह किस प्रकार का डेटा रखता है, और वह यह तय करता है कि क्या माइग्रेशन इसे फेंक सकता है। नियम: **व्युत्पन्न और पुनः प्राप्त करने योग्य को छोड़ा जा सकता है; जो कुछ आपने टाइप किया, अभी तक डिलीवर न किया गया कुछ भी, और मशीन को पहचानने वाला कुछ भी ले जाया जाता है।**

| ले जाया गया | पुनर्निर्मित या पुनः प्राप्त किया गया |
|---|---|
| `config.json` — सेटिंग्स, `daemon.configured`, अतिरिक्त कैप्चर पथ | ऑडिट कैश |
| `credentials.json` — आपका क्लाउड नामांकन | क्लाउड-प्रबंधित परिनियोजन (अगले पोल पर पुनः प्राप्त और डाइजेस्ट-सत्यापित) |
| `policies-config.json` — आपकी नीति चयन और पैरामीटर | डेमन स्क्रैच स्थिति |
| `policies/` — आपकी अपनी नीति फाइलें और वे हेल्पर जो वे आयात करते हैं | |
| `hook-activity/` — निर्णय लॉग जो डैशबोर्ड पढ़ता है | |
| अपलोड के लिए अभी भी कतार में अडिलीवर इवेंट | |
| `cursors/` — कलेक्टर वाटरमार्क | |
| `bin/` में डेमन बाइनरी | |

<Note>
  अडिलीवर इवेंट को छोड़ने के बजाय ले जाया जाता है क्योंकि नुकसान स्थायी होगा, धीमा नहीं: कलेक्टर का वाटरमार्क पहले से ही स्पूल में बैठी किसी भी चीज़ के आगे बढ़ गया है, इसलिए कोई भी ट्रांसक्रिप्ट की उस श्रेणी को फिर से कभी नहीं पढ़ेगा। माइग्रेशन डेमन को भी यह निर्देश देता है कि यह समाप्त होने के तुरंत बाद स्पूल किए गए को डिलीवर करे, इसलिए सामान्य परिणाम यह है कि ले जाने के लिए कुछ नहीं बचा है।
</Note>

एक *नए* संस्करण द्वारा `config.json`, `credentials.json` या `policies-config.json` में लिखी गई कुंजियाँ भी संरक्षित हैं, बजाय एक पुराने रीडर द्वारा छोड़ी गई।

## यह जो रिकॉर्ड छोड़ता है

```
~/.failproofai/migrations/
  applied.json                 हर चरण के लिए एक प्रविष्टि: लेआउट, CLI, टाइमस्टैम्प, अवधि, परिणाम
  backup-layout<n>/            अपरिहार्य फाइलों की कॉपियां, पहले चरण से पहले ली गई
```

`applied.json` यह उत्तर देता है "इस मशीन ने वास्तव में क्या किया है" — अपग्रेड के बाद कुछ गलत दिखने पर पहला सवाल पूछने लायक। इसे एक बग रिपोर्ट से जोड़ें।

बैकअप जानबूझकर पूरी डायरेक्टरी की कॉपी के बजाय छोटा है: माइग्रेशन अब डिज़ाइन द्वारा कुछ भी अपरिहार्य नहीं हटाता है, तो जो बीमा करने लायक है वह एक *चरण में खराबी* है, और ये कुछ फाइलें वह जगह हैं जहां ऐसी खराबी चोट पहुंचाएगी।

## यदि कोई चरण विफल हो

चेन वहीं रुक जाती है। `VERSION` केवल एक पूर्ण चरण द्वारा स्टैम्प किया जाता है, इसलिए होम अपने पुराने लेआउट के साथ चिह्नित रहता है और अगली कमांड इसे पुनः प्रयास करती है — एक होम कभी भी आंशिक माइग्रेशन की ताकत पर वर्तमान नहीं किया जाता है। चरण को `applied.json` में `"ok": false` के साथ रिकॉर्ड किया जाता है, और बैकअप वह जगह है जहां इसे लिया गया था।

## एक नए होम को माइग्रेट नहीं किया जाता है, अस्वीकार किया जाता है

यदि `~/.failproofai/` को एक **नए** failproofai द्वारा लिखा गया था जो आप चला रहे हैं, तो कमांड बंद हो जाती है और आपको इसके बजाय अपग्रेड करने के लिए कहता है। वह डेटा ठीक है और एक नई CLI इसे पढ़ता है; इससे "आगे" माइग्रेट करना एक चीज़ नहीं है जो मौजूद है, और इसे रीसेट करना कुछ पुनः प्राप्त करने योग्य को नष्ट कर देगा।

```
इस मशीन की failproofai डायरेक्टरी को एक नए संस्करण द्वारा लिखा गया था (लेआउट 4;
यह बिल्ड 3 बोलता है)। माइग्रेट करने के बजाय अपग्रेड करें:
  npm install -g failproofai@latest
```

डेमन एक ही नियम लागू करता है: `failproofaid` एक लेआउट के विरुद्ध शुरू होने से इनकार करता है जो वह नहीं बोलता है, बजाय पथों को पढ़ने और लिखने के जो स्थानांतरित हो गए हैं।
