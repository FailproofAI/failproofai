आम परिस्थितियों के लिए तुरंत उपयोग के लिए तैयार उदाहरण। प्रत्येक दिखाता है कि कैसे इंस्टॉल करें और क्या अपेक्षा करें।

---

## Claude Code के लिए hooks सेट अप करना

Failproof AI, Claude Code के साथ इसके [hooks सिस्टम](https://docs.anthropic.com/en/docs/claude-code/hooks) के माध्यम से एकीकृत होता है। जब आप `failproofai policies --install` चलाते हैं, तो यह Claude Code के `settings.json` में hook कमांड रजिस्टर करता है जो हर tool call पर चलते हैं।

<Steps>
  <Step title="failproofai इंस्टॉल करें">
    ```bash
    npm install -g failproofai
    ```
  </Step>
  <Step title="सभी built-in policies सक्षम करें">
    ```bash
    failproofai policies --install
    ```
  </Step>
  <Step title="सत्यापित करें कि hooks रजिस्टर हैं">
    ```bash
    cat ~/.claude/settings.json | grep failproofai
    ```

    आपको `PreToolUse`, `PostToolUse`, `Notification`, और `Stop` events के लिए hook entries दिखने चाहिए।
  </Step>
  <Step title="Claude Code चलाएं">
    ```bash
    claude
    ```

    Policies अब हर tool call पर स्वचालित रूप से चलते हैं। Claude को `sudo rm -rf /` चलाने के लिए कहने का प्रयास करें - यह ब्लॉक हो जाएगा।
  </Step>
</Steps>

## Agents SDK के लिए hooks सेट अप करना

यदि आप [Agents SDK](https://docs.anthropic.com/en/docs/agents-sdk) के साथ बिल्ड कर रहे हैं, तो आप एक ही hook सिस्टम को प्रोग्रामेटिक रूप से उपयोग कर सकते हैं।

<Steps>
  <Step title="अपने प्रोजेक्ट में failproofai इंस्टॉल करें">
    ```bash
    npm install failproofai
    ```
  </Step>
  <Step title="अपने agent में hooks कॉन्फ़िगर करें">
    अपने agent process बनाते समय hook कमांड पास करें। Hooks उसी तरह चलते हैं जैसे Claude Code में - stdin/stdout JSON के माध्यम से:

    ```bash
    failproofai --hook PreToolUse   # हर tool से पहले कॉल किया जाता है
    failproofai --hook PostToolUse  # हर tool के बाद कॉल किया जाता है
    ```
  </Step>
  <Step title="अपने agent के लिए एक custom policy लिखें">
    ```javascript
    import { customPolicies, allow, deny } from "failproofai";

    customPolicies.add({
      name: "limit-to-project-dir",
      description: "Agent को प्रोजेक्ट डायरेक्टरी के अंदर रखें",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        const path = String(ctx.toolInput?.file_path ?? "");
        if (path.startsWith("/") && !path.startsWith(ctx.session?.cwd ?? "")) {
          return deny("Agent प्रोजेक्ट डायरेक्टरी तक सीमित है");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="Custom policy इंस्टॉल करें">
    ```bash
    failproofai policies --install --custom ./my-agent-policies.js
    ```
  </Step>
</Steps>

## विनाशकारी कमांड ब्लॉक करें

सबसे आम सेटअप - agents को अपरिवर्तनीय नुकसान करने से रोकें।

```bash
failproofai policies --install block-sudo block-rm-rf block-force-push block-curl-pipe-sh
```

यह क्या करता है:
- `block-sudo` - सभी `sudo` कमांड ब्लॉक करता है
- `block-rm-rf` - recursive file deletion ब्लॉक करता है
- `block-force-push` - `git push --force` ब्लॉक करता है
- `block-curl-pipe-sh` - रिमोट scripts को shell में पाइप करना ब्लॉक करता है

## Secret leakage रोकें

Agents को tool output में credentials देखने या leak करने से रोकें।

```bash
failproofai policies --install sanitize-api-keys sanitize-jwt sanitize-connection-strings sanitize-bearer-tokens
```

ये `PostToolUse` पर चलते हैं - एक tool चलने के बाद, ये agent को दिखाने से पहले output को साफ करते हैं।

## Agents को Slack alerts भेजें जब उन्हें ध्यान की जरूरत हो

Slack को idle alerts भेजने के लिए notification hook का उपयोग करें।

```javascript
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "slack-on-idle",
  description: "Agent के इनपुट की प्रतीक्षा के समय Slack को alert भेजें",
  match: { events: ["Notification"] },
  fn: async (ctx) => {
    const webhookUrl = process.env.SLACK_WEBHOOK_URL;
    if (!webhookUrl) return allow();

    const message = String(ctx.payload?.message ?? "Agent इनपुट की प्रतीक्षा कर रहा है");
    const project = ctx.session?.cwd ?? "अज्ञात";

    try {
      await fetch(webhookUrl, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          text: `*${message}*\nProject: \`${project}\``,
        }),
        signal: AbortSignal.timeout(5000),
      });
    } catch {
      // अगर Slack तक पहुंच नहीं है तो agent को कभी ब्लॉक न करें
    }

    return allow();
  },
});
```

इसे इंस्टॉल करें:

```bash
SLACK_WEBHOOK_URL=https://hooks.slack.com/... failproofai policies --install --custom ./slack-alerts.js
```

## Agents को एक branch पर रखें

Agents को branches switch करने या protected ones को push करने से रोकें।

```javascript
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "stay-on-branch",
  description: "Agent को दूसरी branches checkout करने से रोकें",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = String(ctx.toolInput?.command ?? "");
    if (/git\s+checkout\s+(?!-b)/.test(cmd)) {
      return deny("मौजूदा branch पर रहें। यदि आवश्यक हो तो -b के साथ एक नई branch बनाएं।");
    }
    return allow();
  },
});
```

## Commits से पहले tests की आवश्यकता करें

Agents को committing से पहले tests चलाने के लिए याद दिलाएं।

```javascript
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "test-before-commit",
  description: "Agent को committing से पहले tests चलाने के लिए याद दिलाएं",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = String(ctx.toolInput?.command ?? "");
    if (/git\s+commit/.test(cmd)) {
      return instruct("Committing से पहले tests चलाएं। पहले `npm test` या `bun test` का उपयोग करें।");
    }
    return allow();
  },
});
```

## एक production repo को lock down करें

एक project-level config commit करें ताकि आपकी टीम के हर developer को same policies मिलें।

अपने repo में `.failproofai/policies-config.json` बनाएं:

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-force-push",
    "block-push-master",
    "block-env-files",
    "sanitize-api-keys",
    "sanitize-jwt"
  ],
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "release", "production"]
    }
  }
}
```

फिर इसे commit करें:

```bash
git add .failproofai/policies-config.json
git commit -m "Add failproofai team policies"
```

हर team member जिसके पास failproofai installed है, ये rules स्वचालित रूप से pick up करेंगे।

## Convention policies के साथ एक org-wide quality standard बनाएं

सबसे प्रभावी सेटअप: अपने repo में `.failproofai/policies/` commit करें जिसमें आपके प्रोजेक्ट के लिए tailored policies हों। हर team member को ये स्वचालित रूप से मिलते हैं — कोई install commands नहीं, कोई config changes नहीं।

<Steps>
  <Step title="डायरेक्टरी बनाएं और policies जोड़ें">
    ```bash
    mkdir -p .failproofai/policies
    ```

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    // अपनी टीम के preferred package manager को लागू करें
    // (या इसके बजाय built-in prefer-package-manager policy सक्षम करें)
    customPolicies.add({
      name: "enforce-bun",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        const cmd = String(ctx.toolInput?.command ?? "");
        if (/\bnpm\b/.test(cmd)) return deny("npm की जगह bun का उपयोग करें।");
        return allow();
      },
    });

    // Agent को committing से पहले tests चलाने के लिए याद दिलाएं
    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Committing से पहले tests चलाएं।");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="Git को commit करें">
    ```bash
    git add .failproofai/policies/
    git commit -m "Add team quality policies"
    ```
  </Step>
  <Step title="सुधार करते रहें">
    जैसे-जैसे आपकी टीम नई failure modes को हिट करती है, policies जोड़ें और push करें। हर कोई अपने अगले `git pull` पर update पाता है। ये policies एक living quality standard बन जाती हैं जो आपकी टीम के साथ बढ़ती हैं।
  </Step>
</Steps>

| फाइल | यह क्या दिखाता है |

| `policies-advanced/index.js` | Transitive imports, async hooks, PostToolUse output scrubbing, Stop event handling |
