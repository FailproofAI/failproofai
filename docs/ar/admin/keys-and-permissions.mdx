مفاتيح API تابعة للمؤسسة وتحمل صلاحيات صريحة. استخدم مفاتيح منفصلة لكل من: استقبال الوكيل وتسليم السياسات والمقيمين والأتمتة المستمرة والبرامج النصية الإدارية.

## إنشاء وتدوير المفتاح

<Tabs>
  <Tab title="Dashboard">
    1. انتقل إلى **Administration → Keys**، واختر **new key**، وأدخل اسم حمل العمل.
    2. اختر مجموعة صلاحيات واضبط الصلاحيات الفردية فقط عند عدم كفاية الإعداد المسبق.
    3. أنشئ المفتاح وانسخ سره لمرة واحدة فورًا.
    4. افتح المفتاح لاحقًا لتحديث المنح أو تعطيله أو إعادة إنشاء السر.

    درج الإنشاء هو المكان الذي تختار فيه أضيق المنح المطلوبة من قبل حمل العمل.

    ![درج مفتاح API الجديد مع إعدادات الصلاحيات والمنح الفردية.](/images/dashboard/key-create.png)

    بعد الإنشاء، تعرض صفحة المفاتيح البيانات الوصفية الدائمة وإجراءات الإدارة. لا يتم عرض السر لمرة واحدة مرة أخرى.

    ![صفحة مفاتيح API توضح صلاحيات المفتاح ووقت الإنشاء وإجراءات إعادة الإنشاء والتعطيل.](/images/dashboard/api-keys.png)

    استخدم هذه القائمة لمراجعة المنح بانتظام وتعطيل المفاتيح التي لم تعد مرتبطة بحمل عمل نشط.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp keys create production-agents \
      --add events:add \
      --add policies:pull
    fp keys show production-agents
    fp keys update production-agents --add events:read
    fp keys regenerate production-agents --yes
    fp keys disable production-agents
    ```

    أعد توجيه أو احفظ مخرجات الإنشاء/إعادة الإنشاء بأمان؛ يتم إرجاع السر مرة واحدة فقط.
  </Tab>
</Tabs>

الصلاحيتان المطلوبتان بواسطة جهاز Failproof AI المتصل مستقلتان:

- `events:add` ترسل الأحداث وبيانات الجلسة.
- `policies:pull` تسترجع نشرات السياسات المعينة.

أسرار المفاتيح تظهر عند الإنشاء أو إعادة الإنشاء. قم بتخزينها في مدير السرية وقم بتدويرها دون إعادة استخدام بيانات اعتماد المشغل التفاعلية.

## فهرس الصلاحيات

| المنطقة | الصلاحيات |
| --- | --- |
| الأحداث | `events:add`, `events:read` |
| المفاتيح | `keys:create`, `keys:read`, `keys:disable`, `keys:regenerate`؛ `keys:update` متاح فقط للجلسات البشرية |
| المستخدمون | `users:create`, `users:read`, `users:update`, `users:delete` |
| التقييمات | `evaluations:read`, `evaluations:trigger` |
| لوحات المعلومات | `dashboards:read`, `dashboards:write`, `dashboards:delete` |
| الاستعلامات | `queries:read`, `queries:write`, `queries:delete`, `queries:run` |
| المساعد | `agent:use` |
| الإعدادات | `settings:read`, `settings:write` |
| التنبيهات | `alerts:read`, `alerts:write` |
| المشاكل | `issues:read`, `issues:create`, `issues:close` |
| عمليات التدقيق | `audits:read`, `audits:write` |
| السياسات | `policies:read`, `policies:write`, `policies:pull` |
| الاستخدام | `usage:read` |

`orgs:admin` محجوزة لمشغل المثيل ولا يمكن منحها لمفتاح المؤسسة أو عضو عادي. الرموز المتقاعدة `incidents:*` و `alerts:ack` مقبولة للتوافق وتطبيع الصلاحيات الحالية `issues:*`.

مجموعات الصلاحيات المدمجة هي `read-only` و `standard` و `admin`. تضيف `standard` تفعيل التقييم وتنفيذ الاستعلامات والاستجابة للمشاكل واستخدام المساعد إلى صلاحيات القراءة. يزيل إنشاء المفتاح المنح الخاصة بالإنسان فقط حتى عندما تتضمن مجموعة الصلاحيات عليها.

<Warning>
  يمكن لمفاتيح النطاق على مستوى المثيل تحديد مؤسسة باستخدام رأس `X-AgentEye-Org`. عيّنها بشكل صريح على نشرات متعددة المؤسسات؛ قد يؤدي الحذف إلى تحديد المؤسسة الافتراضية.
</Warning>
