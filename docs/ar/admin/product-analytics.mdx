يرسل Failproof AI Cloud بيانات استخدام **عن البرنامج نفسه** إلى فريق الصيانة الخاص به. لا يتضمن أبداً بيانات الوكلاء الخاصة بك. على التثبيت المُستضاف ذاتياً، يكون مفعلاً بشكل افتراضي، ويمكنك إيقاف تشغيله.

## ما يتم جمعه

يحمل كل حدث خمسة أبعاد ولا شيء يعرّف هويتك:

| البُعد | مثال | ماهيته |
| --- | --- | --- |
| `product` | `agenteye` | المنتج الذي أرسله |
| `component` | `dashboard`, `server`, `cli` | جزء المنتج الذي أرسله |
| `app_version` | `0.0.1-beta.81` | الإصدار الذي تقوم بتشغيله |
| `deployment_kind` | `self_hosted` | ما إذا كان تثبيت عميل أم تطبيق عرض توضيحي أم أداة اختبار جودة أم جهاز تطوير |
| `org_id` | معرّف فريد عام | المنظمة التي حدث فيها الإجراء، كمعرّف معتم |

بالإضافة إلى ذلك، تسجل الأحداث **ما تم استخدامه، وليس محتواه أبداً**: أي صفحة تم عرضها (كنمط مسار مثل `/:org/sessions/:id`، وليس عنوان URL الفعلي)، وعدد المرشحات من أي نوع تم تطبيقها، وما إذا نجح إجراء ما، والوقت المستغرق.

يسجل تطبيق Slack اتصالات مساحة العمل والقطع، وربط الحساب، والأسئلة المطروحة، والرسوم البيانية المنشورة، وقرارات الموافقة، والأعطال حسب فئة ثابتة. ولا يتضمن أبداً معرّفات مساحة العمل أو المستخدم أو القناة في Slack أو البريد الإلكتروني أو الأسئلة أو الإجابات أو SQL أو الرموز.

### اسم منظمتك

جنباً إلى جنب مع `org_id` المعتم، نسجل اسم منظمتك وكود عنوان URL ولوحة المعلومات الخاصة به مرة واحدة، في سجل المنظمة بدلاً من كل حدث. يسمح لنا بمعرفة الحساب الذي ينتمي إليه النمط عندما ننظر إلى معدل الاعتماد أو نحقق في المشكلة التي أبلغت عنها. هذه هي المعلومة الوحيدة المعرّفة للهوية التي يرسلها المنتج عنك.

### إجمالي استخدامك

يقدم الخادم إجمالي استخدام المنظمة المقاس، وهي نفس الأرقام التي تراها في صفحة الاستخدام. هذه عبارة عن أرقام فقط: الأحداث والجلسات والوكلاء والبيئات وتشغيل التقييم والدرجات وتشغيل التدقيق والاستعلامات المحفوظة لوحات المعلومات والتنبيهات والمشاكل ومفاتيح API والأعضاء، بالإضافة إلى تواريخ نافذة القياس. لا تحتوي على معرّفات أو أسماء أو نص استعلام، وتصل سواء كان هناك أي شخص مسجل دخول أم لا.

## ما لا يتم جمعه أبداً

- **لا توجد توجيهات أو استجابات نموذج أو محتوى حدث**، لا كنص أو بادئة أو تجزئة
- **لا توجد معرّفات جلسة أو وكيل أو تتبع**
- **لا توجد أسماء درجات المقيم**
- **لا رسائل خطأ أو نصوص استثناء أو أجسام استجابة**، فقط رمز الحالة وفئة من قائمة ثابتة
- **لا توجد وسيطات أدوات أو SQL أو نص استعلام**
- **لا توجد تفاصيل تطبيق متصل.** قد يؤدي توصيل أو إلغاء عميل MCP إلى إرسال عدد الأذونات في الأكثر، وليس أبداً اسم التطبيق أو أي رمز
- **لا عناوين بريد إلكترونية**
- **لا عناوين URL أو سلاسل استعلام للمحيل**
- **لا تسجيل شاشة أو التقاط DOM أو تتبع النقرات والمؤشر**

## إيقاف التشغيل على تثبيت مستضاف ذاتياً

اضبط `DO_NOT_TRACK=1` على كل من لوحة المعلومات والخادم. يقررون بشكل منفصل، لذا قد يترك تعيينها على واحد فقط الآخر يبلغ. أعد تشغيل الخادم لتطبيق التغيير.

يصف ملف README الخاص بإصدارك إعدادات عدم المتابعة الأخرى وكيفية تأكيد إيقاف بيانات التلمتري.

## ping واحد عند إيقاف التشغيل

إذا قمت بإيقاف التشغيل باستخدام إعداد المنتج بدلاً من `DO_NOT_TRACK`، قد ترسل لوحة المعلومات **ping مجهول واحد** يسجل ذلك، باحتمالية 1 في 1000 لكل بدء عملية. يخبرنا عن عدد المشغلين الذين يوقفون بيانات التلمتري. لا يحتوي على معرّفات: لا توجد منظمة أو مستخدم أو اسم مضيف أو عنوان URL أو IP، فقط المنتج والمكون والإصدار ونوع النشر والسبب. لا يرسل الخادم المُيقّف شيئاً.

لا يتم إرساله أبداً عند استخدام `DO_NOT_TRACK`، وهذا هو السبب في أنه الإعداد المراد استخدامه إذا كانت سياستك تحظر أي بيانات تلمتري صادرة.

## حيث يذهب

إلى PostHog (`us.i.posthog.com`) عبر TLS على المنفذ 443. إنه اسم مضيف واحد فقط، لذلك يمكنك أيضاً حظره باستخدام قاعدة خروج واحدة.
