استخدم الإعدادات للقيم التشغيلية الخاصة بالنشر وتجاوزات نافذة السياق للنموذج. افحص مخطط الإعدادات قبل تغيير أي قيمة عبر واجهة برمجية التطبيقات أو واجهة سطر الأوامر.

## تغيير إعداد المنظمة

<Tabs>
  <Tab title="Dashboard">
    1. انتقل إلى **Administration → Settings**، ابحث عن مجموعة الإعدادات، واقرأ الوصف والمصدر الحالي.
    2. غيّر القيمة واحفظها.
    3. بالنسبة إلى نوافذ السياق للنموذج، أضف أو حدّث تجاوز النموذج وأكد الحد الفعال.
    4. تحقق مرة أخرى من الجلسات والمقاييس التي تعتمد على القيمة التي تم تغييرها.

    ![صفحة الإعدادات تعرض إعدادات المصادقة التشغيلية للمنظمة.](/images/dashboard/settings.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp settings list
    fp settings schema
    fp settings set <key> --value <scalar>
    fp settings set alerts.email_default_recipients \
      --json-value '["oncall@example.com"]'
    ```

    شغّل `fp settings set --help` لمعرفة نوع القيمة وأعلام التأكيد التي يستخدمها واجهة سطر الأوامر المثبتة.
  </Tab>
</Tabs>

## خيارات معالجة البيانات

يؤدي توصيل واجهة سطر أوامر Failproof AI إلى إرسال النسخ الكاملة بشكل افتراضي لأن التتبعات والتدقيقات تعتمد على محتواها. استخدم `--no-transcripts` عندما يجب بقاء الطلبات أو محتويات الملفات أو مدخلات المحطة الطرفية محلية؛ يمكن لا تزال الإبلاغ عن نشاط الخطاف وقرارات السياسة.

تُخزّن بيانات اعتماد الاستقبال المحلية بشكل منفصل عن إعدادات المراقب غير السرية وتُكتب برموز تقييدية. يجب بحال من الأحوال إدارة مفاتيح واجهات برمجية التطبيقات كأسرار إنتاجية.

## مرجع إعدادات المنظمة

جميع الإعدادات القابلة للتعديل عبر لوحة التحكم لها نطاق تنظيمي. يبقى السلوك على مستوى النشر بمثابة تكوين بيئة الخادم.

| المفتاح | القيمة الافتراضية | الغرض |
| --- | --- | --- |
| `allowed_sign_ins` | `[]` | قيّد الأعضاء الموجودين إلى رسائل بريد إلكترونية دقيقة أو `*@domain`؛ تعني القائمة الفارغة عدم وجود قيد إضافي. |
| `session_ttl_secs` | `86400` | مدة حياة جلسة لوحة التحكم؛ النطاق المقبول هو من 60 ثانية إلى 30 يوماً. |
| `otp_ttl_secs` | `600` | مدة حياة رمز المرة الواحدة ورابط السحر؛ النطاق المقبول هو 60–1800 ثانية. |
| `alerts.email_default_recipients` | `[]` | المستقبلون الافتراضيون عندما لا تتجاوز قناة البريد الإلكتروني للتنبيهات عنهم. |
| `alerts.slack_default_webhook` | فارغ | عنوان URL خطاف Slack الافتراضي الوارد. |
| `alerts.webhook_default_url` | فارغ | عنوان URL خطاف JSON الافتراضي العام. |
| `alerts.webhook_signing_secret` | فارغ | مفتاح HMAC-SHA256 المستخدم لرأس `X-AgentEye-Signature`؛ القراءات مقنّعة. |
| `alerts.enabled_channels` | البريد الإلكتروني، Slack، خطاف | أنواع القنوات على مستوى المنظمة التي قد توجهها قواعد التنبيهات. |
| `default_user_permissions` | `standard` | مجموعة الأذونات المسماة المختارة مسبقاً للدعوات الجديدة. |

`allowed_sign_ins` هو مرشح وليس منحة: يجب أن يكون الشخص بالفعل عضواً في المنظمة. استخدم قائمة فارغة للسماح لكل عضو؛ القيمة المجردة `*` مرفوضة. يجب أن تستخدم عناوين URL للتنبيهات بروتوكول HTTPS ما عدا عناوين التطوير المحلية.

## قائمة التحقق من الأمان

- استخدم HTTPS لاتصالات السحابة.
- حدّد نطاق المفاتيح إلى أصغر مجموعة أذونات.
- افصل بين بيئات الإنتاج وبيئات غير الإنتاج.
- راجع إعدادات النسخ الكاملة والتحرير قبل الطرح.
- دقّق في تغييرات المستخدم والمفتاح والمنظمة.
- اختبر متطلبات النسخ الاحتياطي والاحتفاظ والاستجابة للحوادث لنشرك.

<Warning>
  إيقاف التقاط النسخة الكاملة سيغيّر ما يمكن للتدقيقات والتحقيقات إثباته. سجّل القرار والقيود المتوقعة له.
</Warning>
