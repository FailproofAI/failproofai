اسحب بيانات الجلسة والأحداث والتقييم (وشغّل إعادة تقييمات) مباشرة من برنامج نصي أو عملاء ذكي، باستخدام JSON نظيف على stdout يتصل مباشرة بـ `jq`. تحول هذه الوصفات بيانات Failproof AI Observability إلى شيء يمكن لمستخدم المحطة الطرفية أو عملاء ذكي (Claude Code, Cursor) الاستعلام عنه وتشغيله تلقائياً، دون الحاجة للنقر عبر لوحة التحكم.

الأنماط أدناه جاهزة للنسخ والاستخدام المباشر مع CLI Failproof AI Observability (`agenteye`). للتثبيت والمصادقة والقائمة الكاملة بالخيارات، راجع [CLI](/ar/agenteye/cli)؛ شغّل `agenteye -h` أو `agenteye <command> -h` للحصول على المساعدة المدمجة.

## القواعد الذهبية

1. **خيارات عامة تأتي *قبل* الأمر.** `agenteye --json sessions` صحيح؛ `agenteye sessions --json` غير صحيح. الخيارات العامة هي `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, `--no-color`.
2. **مرر `--json` عند تحليل المخرجات.** البيانات تذهب إلى **stdout** كـ JSON؛ الحالة البشرية والأخطاء تذهب إلى **stderr**، بحيث يبقى stdout نظيفاً للاتصال بـ `jq`.
3. **افصل على رمز الخروج، وليس نص stderr**: `0` موافق · `1` خطأ غير متوقع · `2` معاملات سيئة · `3` لا يمكن الوصول إلى لوحة التحكم · `4` لم تسجل الدخول أو انتهت الجلسة · `5` إذن مفقود · `6` المورد غير موجود.
4. **اكتشف بـ `-h`.** كل أمر يوثق مرشحاته وتنسيقات القيم وشكل JSON.

## الإعداد لمرة واحدة

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com   # كي لا تكرر --base-url
agenteye login --email you@example.com                       # الصق الرمز المُرسل بالبريد؛ صالح ~24 ساعة
```

## تأكد من المصادقة قبل القيام بالعمل

`whoami` لا تُرجع خطأ في حالة الجلسة المفقودة أو منتهية الصلاحية؛ بدلاً من ذلك تُبلّغ عن `logged_in:false`، لذا يمكن لعملاء ذكي فحص حالة المصادقة بأمان. (قد تزال تخرج برمز غير صفر إذا لم يتم تعيين عنوان URL أساسي أو لم تكن لوحة التحكم قابلة للوصول.)

```bash
if [ "$(agenteye --json whoami | jq -r .logged_in)" != "true" ]; then
  echo "Not authenticated. Run: agenteye login" >&2; exit 1
fi
```

## ابحث عن جلسات فاشلة أو منخفضة التصنيف

```bash
# جلسات في آخر 24 ساعة حيث فشل التقييم
agenteye --json sessions --since 24h --status error | jq -r '.sessions[].session_id'

# تقييمات برصيص <= 0.5 على المفيدية، لعملاء واحد
agenteye --json evals --agent-id checkout-bot --score helpfulness:..0.5 \
  | jq '.evaluations[] | {session_id, scores}'
```

يعيش تصفية الرصيص على **`evals`**، وليس `sessions`. `--score KEY:MIN..MAX` قابل للتكرار والدمج بـ AND؛ أي حد أدنى أو أعلى اختياري (`..0.5` يعني ≤ 0.5, `0.9..` يعني ≥ 0.9). يمكنك تمرير ما يصل إلى 20 مرشح رصيص لكل طلب؛ المزيد يُرجع HTTP 400. `sessions` يشارك `--env`, `--status`, `--agent-id`, `--session-id` ومرشحات نطاق الوقت مع `evals`، لكن بدون `--score`.

## اقرأ جلسة واحدة من البداية إلى النهاية

لا توجد أمر `session show` واحد. ادمج مسار الحدث مع تقييم الجلسة:

```bash
# أحدث تقييم للجلسة (الحالة + الدرجات)
agenteye --json evals --session-id run-001 | jq '.evaluations[0] | {status, scores}'

# كل حدث في التشغيل (رفع --limit لمسح كامل)
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'

# فقط استدعاءات الأدوات في جلسة (--full مطلوب للحصول على payload الخام)
agenteye --json events --full --session-id run-001 --event-type tool_use,tool_result --all \
  | jq '.events[].payload'
```

> **ملاحظة:** بشكل افتراضي، `events` يقرأ علف سريع خالي من payload. كل حدث يحمل `summary` سطر واحد محسوب بالخادم بالإضافة إلى أعلام مثل `is_error` وعدادات التوكن، لكن `payload` يعود كـ `{}`. لسحب payload الخام، أضف `--full` (أو `--fields payload`). العلف الكامل أبطأ على نطاق واسع، لذا أبقه محدوداً: اجمع `--full` مع `--session-id` واحد.

## احضر كل شيء (التصفح)

النتائج أحدث أولاً ومصفوفة بـ cursor.

```bash
# نقرة واحدة: احضر ما يصل إلى 500 صف في صفحات من 200 صف
agenteye --json events --session-id run-001 --limit 500 --all > events.json

# تصفح يدوي: أعد next_cursor
page=$(agenteye --json events --limit 100)
cursor=$(echo "$page" | jq -r '.next_cursor // empty')
[ -n "$cursor" ] && agenteye --json events --limit 100 --cursor "$cursor"
```

## نحّف المخرجات بـ --fields

قيّد المفاتيح (في الجدول و `--json`) لتقليل ما يجب على عملاء ذكي قراءته.

```bash
agenteye --json sessions --since 7d --fields session_id,status,scores | jq -c '.sessions[]'
agenteye --json events --session-id run-001 --fields ts,event_type --all
```

أسماء الحقول المجهولة مرفوضة (الخروج `2`) مع القائمة الصحيحة، طريقة رخيصة لاكتشاف أسماء الحقول.

## اكتشف قيم المرشحات الصحيحة

```bash
agenteye --json list envs | jq -r '.values[]'           # قيم --env
agenteye --json list tools | jq -r '.values[]'          # أسماء الأدوات؛ أيضاً agents, models, event_types, ...
agenteye --json list score_filters | jq -r '.values[]'  # KEY صحيح لـ --score KEY:MIN..MAX
```

## اختر منظمتك (متعدد المستأجرين)

إذا كنت تنتمي إلى أكثر من منظمة واحدة، اختر المستأجر النشط عند تسجيل الدخول (يتم حفظه):

```bash
agenteye login --org acme --email you@corp.com   # عيّن المستأجر في نفس خطوة تسجيل الدخول
agenteye --json orgs list | jq -r '.orgs[].org_slug'
agenteye --org globex --json sessions --since 24h   # تجاوز لأمر واحد
```

تسجيل دخول متعدد المنظمات بدون `--org` يخرج برمز غير صفر ويطبع المنظمات للاختيار.

## وفّر مفتاح API لـ SDK/مجمّع

```bash
# السر يُطبع مرة واحدة، مع --json هو حقل .key
key=$(agenteye --json keys create ci-bot --add events:read.add | jq -r '.key')
agenteye keys regenerate ci-bot --yes    # دوّر؛ agenteye keys disable ci-bot --yes لإلغاء التفعيل
```

## شغّل استعلام محفوظ أو مرتجل

```bash
agenteye --json query run --sql "select count(*) from analytics.events" | jq '.rows'
agenteye --json query run errs --arg prod | jq '.rows'   # استعلام محفوظ + معامل موضعي $1
```

## فحص حادثة غير تفاعلياً

```bash
id=$(agenteye --json incidents list --state firing | jq -r '.incidents[0].id')
agenteye incidents ack "$id"
agenteye incidents assign "$id" --assignee you@corp.com
agenteye incidents resolve "$id" --yes
```

> **ملاحظة:** الطفرات تتخطى تلقائياً موجه التأكيد الخاص بها تحت `--json` أو عندما لا يكون stdin جهاز TTY، لذا لا تعلق العملاء أبداً؛ مرر `--yes`/`-y` لتخطيه بشكل صريح في مكان آخر.

## معالجة رمز الخروج في برنامج نصي

```bash
out=$(agenteye --json sessions --since 1h) || code=$?
case "${code:-0}" in
  0) echo "$out" | jq '.sessions | length' ;;
  4) echo "Session expired - run 'agenteye login'." >&2 ;;
  5) echo "Missing permission (ask an admin for evaluations:read)." >&2 ;;
  3) echo "Dashboard unreachable - check the URL." >&2 ;;
  *) echo "Unexpected error (exit ${code})." >&2 ;;
esac
```

## أشكال مخرجات JSON

| الأمر | stdout JSON (مع `--json`) |
|---|---|
| `whoami` | `{"logged_in": true, "id", "email", "is_instance_admin", "active_org", "permissions": [...], "memberships": [...]}` أو `{"logged_in": false}` |
| `orgs list` | `{"active_org", "orgs": [{"org_slug","org_name","permission_set","permissions"}]}` |
| `events` | `{"events": [...], "next_cursor": <cursor or null>}` |
| `evals` | `{"evaluations": [...], "next_cursor": <cursor or null>}` |
| `sessions` | `{"sessions": [...], "next_cursor": <cursor or null>}` |
| `errors` | `{"errors": [...], "next_cursor": <cursor or null>}` |
| `list <kind>` | `{"kind", "values": [...]}` |
| `keys list` / `keys create` | `{"keys": [...]}` / `{id, name, permissions, created_at, key}` (يظهر `key` مرة واحدة) |
| `query run` | `{columns: [{name,type}], rows: [[...]], truncated, elapsed_ms}` |
| `users list` / `settings list` | `{"users": [...]}` / `{"settings": [...]}` |
| `alerts list` / `incidents list` | `{"alerts": [...]}` / `{"incidents": [...]}` |
| إنشاء/تحديث/حذف (أي) | كائن المورد، أو `{"deleted": true, "id"}` للحذف |
| فشل (أي، مع `--json`) | `{"error": "...", "exit_code": <n>, "status"?: <http>, "hint"?: "..."}` على stdout |

- كل عنصر **حدث** (`events`): `id, session_id, agent_id, event_type, ts, payload, environment, summary, is_error, error_type, output_tokens, context_window, context_fill`. لاحظ أن `payload` هو `{}` ما لم تطلب العلف الكامل مع `--full` (أو `--fields payload`).
- كل عنصر **تقييم** (`evals`): `id, session_id, agent_id, environment, status, scores, reasoning, summary, error, attempt_count, duration_ms, completed_at, created_at`.
- كل عنصر **جلسة** (`sessions`): `session_id, agent_id, environment, status, scores, event_count, started_at, last_event_at, first_event_id, last_event_id, latest_evaluation`.

خيار `--fields` لكل أمر يقبل بالضبط أسماء حقول العنصر الخاص به. تختلف المجموعة بين `sessions` و `evals`، لذا قد يتم رفض الاسم الصحيح لأحدهما من قبل الآخر.
