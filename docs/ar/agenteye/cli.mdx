قم بتشغيل جميع ملاحظات Failproof AI من الطرفية أو من نص برمجي: بدون الحاجة للعودة إلى لوحة التحكم. تستعلم واجهة سطر الأوامر `agenteye` عن بيانات النظام (الجلسات وسجلات الأحداث والتقييمات) وتدير مؤسستك (مفاتيح API والمستخدمون والإعدادات والتنبيهات والحوادث والاستعلامات المحفوظة)، لذا استخدمها عندما تريد أتمتة فحص أو دمج الملاحظات في CI أو السماح لوكيل برمجي بفحص الإنتاج. كل أمر يدعم علم `--json`، لذا يعمل بنفس الكفاءة لك في سطر الأوامر أو لوكيل برمجي (Claude Code و Cursor) يستدعيه ويحلل النتيجة.

باستخدام ملف تنفيذي واحد يمكنك:

- **قراءة بياناتك**: `sessions` و `events` و `evals` و `errors` (تصفية حسب الوقت والوكيل والبيئة والنقاط).
- **إدارة مؤسستك**: `keys` و `users` و `settings` و `alerts` و `incidents`.
- **تشغيل التحليلات**: SQL محفوظة وأداة استعلام حسب الطلب (`query`).
- **اطلب من مساعد ذكي**: نفس محلل القراءة فقط الذي تتحدث معه في لوحة التحكم (`agent`).

> **ملاحظة:** هذه هي واجهة `agenteye` CLI، وهي أداة مختلفة عن daemon المجمع (`agenteye-collector`). تتحدث واجهة سطر الأوامر مع لوحة التحكم الخاصة بك؛ يرسل المجمع الأحداث إلى الخادم.

## البدء السريع

من لا شيء إلى أول نتيجة في أربع سطور. وجّه واجهة سطر الأوامر نحو لوحة التحكم الخاصة بك وسجّل الدخول وأكّد هويتك ثم اسحب آخر يوم من التشغيلات:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # emailed 6-digit code
agenteye whoami                                                                  # confirm user + active org
agenteye --json sessions --since 24h                                             # one row per agent run, last 24h
```

يطبع الأمر الأخير كائن JSON بأحدث الجلسات (الأحدث أولاً، محدود بـ 50 افتراضياً). مرره إلى `jq` لتقسيمه أو أسقط `--json` للحصول على جدول مربع وملون. يحمل كل صف حالة التشغيل وإذا قام محيّم بتقييمه، نقاط المقاييس الخاصة به (مختصرة هنا):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

يشرح بقية هذه الصفحة كل جزء: [التثبيت](#installation) في عزلة، [تسجيل الدخول](#authentication)، [الإعدادات](#configuration)، [الخيارات العامة والاتفاقيات](#global-options--conventions) التي تشاركها كل أمر، و[مرجع الأوامر الكامل](#command-reference).

## التثبيت

واجهة سطر الأوامر عبارة عن حزمة PyPI عامة باسم **`agenteye`**. ثبتها في بيئة معزولة بحيث يكون لديها دائماً اعتماديات خاصة بها:

```bash
pipx install agenteye
# or
uv tool install agenteye
```

يتطلب Python 3.10+. الأمر المثبت هو **`agenteye`**:

```bash
agenteye --version
agenteye --help
```

> **ملاحظة:** SDK Python لـ Failproof AI Observability أيضاً يستخدم اسم توزيع `agenteye`. يؤدي تثبيت واجهة سطر الأوامر باستخدام `pipx` أو `uv tool` (بدلاً من `pip install` في بيئة افتراضية مشتركة) إلى منع تضارب الاثنين. `pip install agenteye` البسيط جيد فقط إذا لم يتم تثبيت SDK في نفس البيئة.

## المصادقة

تقوم واجهة سطر الأوامر بالمصادقة **لوحة التحكم** برمز لمرة واحدة عبر البريد الإلكتروني:

```bash
agenteye login --email you@example.com
# A 6-digit code is emailed to you; paste it at the prompt.
```

يتم حفظ رمز الجلسة في `~/.agenteye/cli.json` (قابل للقراءة فقط بواسطتك، الوضع `0600`) وصالح لمدة 24 ساعة افتراضياً. عند انتهائه، قم بتشغيل `agenteye login` مرة أخرى.

```bash
agenteye whoami     # show the current user, active org, and permissions
agenteye logout     # revoke the session and clear the stored token
```

لا يرجع `whoami` أخطاء على جلسة مفقودة أو منتهية الصلاحية؛ بدلاً من ذلك يبلغ عن `logged_in: false`، لذا يمكن للنص البرمجي أو الوكيل استكشاف حالة المصادقة بأمان (يمكن أن يظل يخرج بكود غير صفري إذا لم يتم تعيين عنوان URL الأساسي أو كانت لوحة التحكم غير متاحة).

**المتطلبات:** يجب أن يُسمح لبريدك الإلكتروني بتسجيل الدخول إلى لوحة التحكم (اطلب من مسؤول Failproof AI Observability)، ويجب أن تكون لوحة التحكم متاحة على عنوان URL الأساسي الخاص بها (انظر [الإعدادات](#configuration)). إذا طلبت رمز ولم يصل أي رمز، فمن المحتمل أن بريدك الإلكتروني لم يتم تفعيله بعد لولوج لوحة التحكم.

## اختيار مؤسستك (متعدد المستأجرين)

إذا كانت حسابك تنتمي إلى أكثر من منظمة واحدة، اختر المنظمة النشطة **عند تسجيل الدخول**؛ يتم حفظها واستخدامها في كل أمر لاحق:

```bash
agenteye login --org acme           # authenticate and set the active tenant in one step
agenteye orgs list                  # the orgs you can access (the active one is marked)
agenteye orgs switch globex         # change the saved default
agenteye --org globex sessions      # override for a single command
```

إذا كنت تنتمي إلى منظمة واحدة بالضبط، يتم اختيارها تلقائياً ويمكنك تجاهل `--org` تماماً. إذا كنت تنتمي إلى عدة وأنت لم تختر واحدة، تسرد واجهة سطر الأوامر والتي تطلب إعادة التشغيل مع `--org <slug>`. يتم إرسال المنظمة النشطة إلى لوحة التحكم في كل طلب، وتتم دقة الأذونات **لكل منظمة**؛ يعرض `agenteye whoami` المنظمة النشطة وأذوناتك فيها وجميع عضويتك.

## الإعدادات

| الإعداد | العلم | متغير البيئة | الافتراضي |
|---|---|---|---|
| عنوان URL الأساسي للوحة التحكم | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **مطلوب** (بدون افتراضي) |
| المنظمة/المستأجر النشط | `--org` | `AGENTEYE_ORG` | يتم اختياره عند تسجيل الدخول؛ محفوظ في `~/.agenteye/cli.json` |
| رمز الجلسة | `--token` | `AGENTEYE_CLI_TOKEN` | من `~/.agenteye/cli.json` |
| إخراج JSON | `--json` | `AGENTEYE_CLI_JSON` | إيقاف |
| تخطي التحقق من TLS | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | إيقاف (محفوظ عند تسجيل الدخول) |
| انتظر المهلة الزمنية (ثواني) | `--timeout` | _(none)_ | 30 |
| تعطيل قياس الاستخدام | _(none)_ | `AGENTEYE_ANALYTICS_DISABLED` (أو `DO_NOT_TRACK`) | يتم تعطيل قياس الاستخدام حالياً؛ لا يتم إرسال أي شيء |

ترتيب الدقة هو **العلم → متغير البيئة → ملف الإعدادات**. لا يوجد افتراضي؛ يجب عليك توجيه واجهة سطر الأوامر نحو لوحة التحكم الخاصة بك، إما لكل أمر (`--base-url https://agenteye.example.com`) أو مرة واحدة عبر البيئة (يتم أيضاً حفظه بعد أول `login` الخاص بك):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

يحترم دليل الإعدادات `AGENTEYE_HOME` (نفس الاتفاقية المستخدمة من قبل SDK والمجمع)؛ إذا تم تعيينه، فإن `cli.json` يعيش في `$AGENTEYE_HOME/cli.json`.

### TLS موقّع ذاتياً أو داخلي

إذا تم تقديم لوحة التحكم الخاصة بك عبر HTTPS بشهادة موقّعة ذاتياً أو داخلية (على سبيل المثال، اسم مضيف موازن التحميل الخام)، فإن التحقق من TLS يرفضه برسالة `CERTIFICATE_VERIFY_FAILED`. مرر `--insecure` لتخطي التحقق من الشهادة:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

يتم **حفظ** `--insecure` **إلى `cli.json` عند تسجيل الدخول**، لذا تتخطى الأوامر اللاحقة التحقق تلقائياً؛ لا تحتاج إلى تكرار العلم. مرر `--secure` للاستدعاء المتحقق من مرة واحدة أو لحفظ التحقق مرة أخرى عند تسجيل الدخول التالي. تطبع واجهة سطر الأوامر تحذيراً إلى stderr قبل أي أمر يتصل بلوحة التحكم أثناء تعطيل التحقق. يؤدي تخطي التحقق إلى إزالة الحماية من هجمات الوسيط؛ تأكد من أنك تثق بمسار الشبكة إلى لوحة التحكم الخاصة بك (VPN أو الشبكة الخاصة وما إلى ذلك) قبل الاعتماد عليها.

## قياس الاستخدام والخصوصية

> **ملاحظة:** لا ترسل واجهة سطر الأوامر المشحونة **أي قياس استخدام اليوم.** مفتاح القتل الرئيسي قيد التشغيل، لذا لا يتم نقل أي شيء بغض النظر عن بيئتك. يصف القسم أدناه إمكانية عدم الاشتراك فقط إذا تم تفعيل قياس الاستخدام.

حتى عند تفعيله، فإن قياس الاستخدام سيكون **فقط تحليلات الاستخدام المجهولة**، وليس وكيلك أو جلستك أو بيانات الحدث:

- **لا تترك بيانات الوكيل أو الجلسة أو الحدث بنية الأساس الخاصة بك أبداً.** سيتم الإبلاغ عن استخدام واجهة سطر الأوامر فقط: اسم الأمر والأمر الفرعي (مثل `keys create`)، **أسماء** الأعلام التي استخدمتها (أبداً قيمها)، حالة النجاح/الخروج والمدة، بالإضافة إلى حدث لكل إجراء للطفرات (مثل `api_key_created` و `query_run`) تحتوي على أسماء/عدادات ثابتة فقط وأعداد خشنة. عنوان URL لوحة التحكم الخاص بك ورمز الجلسة والبريد الإلكتروني وملخص المنظمة وهويات الموارد و SQL وأسرار المفاتيح وعوامل تصفية الاستعلام **لن تكون أبداً** مرسلة. سيتم تحديد المشغلين فقط من خلال معرّف داخلي معتم، وليس عبر البريد الإلكتروني.
- **اختر عدم المشاركة مقدماً** بتعيين `AGENTEYE_ANALYTICS_DISABLED=1` في بيئة واجهة سطر الأوامر (تحترم واجهة سطر الأوامر أيضاً اتفاقية أداة متقاطعة `DO_NOT_TRACK=1`). يدخل هذا حيز التنفيذ في اللحظة التي يتم فيها تفعيل قياس الاستخدام، لذا يمكن لبيئة واعية بالخصوصية أن تبقى معطلة بشكل دائم.
- إذا تم تفعيل قياس الاستخدام، فستقوم واجهة سطر الأوامر بالإرسال مباشرة إلى PostHog (`https://us.i.posthog.com`)؛ ستصمت آلة تحجب تلك المضيف بصمت ولن تتأثر واجهة سطر الأوامر.

## الخيارات العامة والاتفاقيات

اقرأ هذا مرة واحدة؛ ينطبق على كل أمر.

- **تذهب الخيارات العامة قبل الأمر.** `agenteye --json sessions` صحيح؛ `agenteye sessions --json` خطأ في الاستخدام. الخيارات العامة هي `--json` و `--base-url` و `--org` و `--token` و `--insecure`/`--secure` و `--timeout` و `--quiet` و `--no-color`.
- **`--json` يطبع JSON نقي إلى stdout، وليس شيء آخر.** تذهب خطوط حالة المصادقة والتحذيرات والأخطاء البشرية إلى **stderr**، لذا فإن التقاط stdout مع `--json` يبقى نظيفاً لكي يدخل إلى `jq` حتى عندما يتم عرض خط الحالة. بدون `--json` تحصل على عرض مربع وملون لعيون الإنسان.
- **اكتشف باستخدام `--help`.** كل أمر وأمر فرعي له `--help` (والاسم المستعار `-h`): `agenteye -h` و `agenteye sessions -h` و `agenteye keys create -h`. تسرد المساعدة العليا أيضاً أكواد الخروج والخيارات العامة. لا توجد سطح موحد قابل للقراءة بالآلة عالمي؛ استخدم `--help` لكل أمر، بالإضافة إلى النطاق المحدد `agenteye query schema` و `agenteye settings schema` لهذين السجلين.
- **تخطي التأكيدات تلقائياً للنصوص البرمجية والوكلاء.** تطلب أوامر الإنشاء/التحديث/الحذف "هل أنت متأكد؟" في محطة تفاعلية، لكن **تتخطى هذه المطالبة تلقائياً ضمن `--json` أو كلما لم تكن stdin مرتبطة بـ TTY** (TTY هي جلسة محطة تفاعلية؛ الأنبوب أو عداء CI ليس)، لذا لا تتوقف النصوص البرمجية والوكلاء مطلقاً. مرر `--yes`/`-y` لتخطيها بشكل صريح. لأن المطالبة لن تطلق للوكيل، يجب على الوكيل تأكيد الإجراءات المدمرة مع الإنسان أولاً.
- **الترقيم**: النتائج هي الأحدث أولاً والترقيم مع المؤشر (كل صفحة تعيد رمز تستخدمه لجلب التالية). `--limit N` (اسم مستعار `-n`) يحد من الصفوف و**الافتراضي إلى 50**؛ `--all` يرقّم تلقائياً (في أجزاء من 200 صف) **حتى `--limit`**، لذا `--all` البسيط يتوقف عند 50 لا يزال. لكنس كامل مرر حد أعلى صريح عالي: `--all --limit 1000`. `--page-size N` يتحكم في الجزء لكل طلب (الحد الأقصى 200)؛ `--cursor <id>` يستأنف من `next_cursor` الصفحة السابقة.
- **عوامل تصفية الوقت:** `--since` تأخذ نافذة نسبية: `15m` أو `1h` أو `6h` أو `24h` أو `7d` أو `all` (إعدادات لوحة التحكم المسبقة). لنطاق أطول أو مخصص (قل آخر 30 يوماً)، استخدم `--from`/`--to`: طوابع زمنية UTC صريحة بصيغة ISO-8601 **مع `T` ومنطقة زمنية** (مثل `2026-06-01T00:00:00Z`) التي تتجاوز `--since`. القيمة المفصولة بمسافة أو بدون منطقة زمنية خطأ في الاستخدام.
- **`--fields a,b,c`** (على `events` و `sessions` و `evals` و `errors`) يقيد الإخراج إلى تلك المفاتيح، لكل من الجدول و `--json`. يتم رفض الأسماء غير المعروفة برسالة من القائمة الصحيحة، وهي طريقة رخيصة لاكتشاف أسماء الحقول.
- **`--file payload.json`** (أو `--file -` لقراءة stdin) يوفر جسم طلب JSON كامل حيث يحتوي المورد على شكل معقد (على `alerts create/update` و `settings set` و `users create/update`). يستخدم SQL الاستعلام المحفوظ `--sql @file.sql` بدلاً من ذلك.
- **عوامل تصفية متعددة القيم** مفصولة بفواصل → مطابقتها كمجموعة (اتحاد داخل مرشح واحد، و عبر عوامل تصفية): `--event-type tool_use,tool_result`. خيارات النقر ليست متغيرة، لذا `--add a b` أعطال. استخدم `--add a,b` أو كرر العلم (`--add a --add b`) أو اقتبس (`--add "a b"`).

## مرجع الأوامر

### ستستخدم هذه 5 أوامر الأكثر

معظم العمل اليومي يمر عبر حفنة من أوامر القراءة. ابدأ هنا، ثم تصل إلى السطح الكامل أدناه عندما تحتاجه:

| الأمر | ما يفعله | جرب |
|---|---|---|
| `sessions` | صف واحد لكل تشغيل وكيل: الوقت والبيئة والوكيل والحالة وأحدث نقاط. | `agenteye --json sessions --since 24h --status error` |
| `events` | مسار خطوة خام داخل تشغيل (أضف `--full` للحمولات). | `agenteye --json events --session-id run-001 --all` |
| `evals` | نتائج التقييم والنقاط؛ `--aggregate` يلفها. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | فقط الأحداث المعيبة؛ `--aggregate` للأعداد حسب النوع. | `agenteye --json errors --since 24h --aggregate` |
| `list` | اكتشف قيم التصفية الصحيحة (الوكلاء والبيئات والنماذج...). | `agenteye list agents` |

### كل ما يمكن لـ CLI أن تفعله

يتبع السطح الكامل. لدى CLI **18 أمراً على أعلى مستوى**. تقبل جميع أوامر القراءة `--json` والخيارات العامة أعلاه؛ قم بتشغيل `agenteye <command> -h` (أو `<command> <subcommand> -h`) للقائمة الشاملة من الأعلام وشكل JSON لأي واحد.

### الهوية: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # emailed one-time code; saves the session
agenteye logout                                       # clear the saved session on this machine
agenteye whoami                                       # current user, active org, permissions
agenteye version                                      # print the CLI version (same as --version)
agenteye help                                         # top-level help (same as --help)
```

يفحص `orgs` ويبدّل المستأجر النشط:

```bash
agenteye orgs list        # your orgs + your role in each (active one marked)
agenteye orgs switch acme # change the saved active org (omit the slug to pick from a list on a TTY)
agenteye orgs current     # identity card for the active org
agenteye orgs perms       # your permissions in the active org, grouped by resource
```

### الملاحظة (قراءة فقط): `events` · `sessions` · `evals` · `errors` · `list`

لا تحتاج أي من هذه إلى تأكيد. عوامل تصفية مشتركة: `--session-id` و `--agent-id` و `--env` (**ليس** `--environment`) ونطاق الوقت (`--since` / `--from` / `--to`).

```bash
# events (alias: the raw per-step trail), newest first
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: one row per agent run (time/env/agent/session/status; no score filtering)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: evaluation results + scores; --score filters by metric, --aggregate rolls up
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # status mix + per-key score stats

# errors: errored events; --aggregate for counts/sessions/agents/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: discover valid filter values before you filter
agenteye list envs        # also: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (على **`evals`** فقط وليس `sessions`) قابلة للتكرار و AND-مدمجة؛ أي حد اختياري (`..0.5` يعني ≤ 0.5، `0.9..` يعني ≥ 0.9). حتى 20 عامل تصفية درجة لكل طلب. `evals --scores-full` هي علم العرض للجدول البشري فقط**؛ يعرض كل زوج درجة بدلاً من الأول بعض زائد `+N` العد. ليس له تأثير تحت `--json`، الذي يعود دائماً كائن النقاط الكامل. لقراءة **جلسة واحدة من البداية إلى النهاية**، اجمع بين مسار الحدث وتقييمه:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # its scores + status
```

### إدارة (مقيدة بالأذونات): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: مفاتيح API. تم إنشاء السر محلياً وتم إرساله إلى الخادم (الذي يخزن فقط تجزئة) و**يُظهر مرة واحدة** على الإنشاء/إعادة الإنشاء؛ التقطه بعد ذلك. مع `--json` يظهر فقط في حقل `key`. المرجعي من **الاسم**.

```bash
agenteye keys list                                   # active keys first, then revoked
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # scope to what you need; prints the secret ONCE
agenteye keys create ops --permission-set standard --remove queries:run   # seed a preset, then trim
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rotate the secret (the old one stops working)
agenteye keys disable ci-bot --yes                   # revoke
```

تعمل الأذونات كـ `(permission-set ∪ --add) − --remove`. الرموز هي `slug:action` (مثل `events:read`) أو `slug:action.action` لتوسيع عدة على مورد واحد (`events:read.add` → `events:read` و `events:add`). الإعدادات المسبقة: `read-only` و `standard` و `admin`. الأذونات البشرية فقط (`keys:update`) لا يمكن منحها للمفتاح.

**`users`**: أعضاء المنظمة، مرجعي من **البريد الإلكتروني** (هو معرّف UUID أيضاً مقبول).

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predicts + confirms
agenteye users disable dev@corp.com --yes            # has protected/self guards
agenteye users enable dev@corp.com
```

**`settings`**: سجل ثابت (تقرأ وتغيير المفاتيح الموجودة؛ لا يمكنك إنشاء مفاتيح جديدة).

```bash
agenteye settings list                               # key · value · type · updated (secrets masked)
agenteye settings schema                             # what each key accepts (type · range · description)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: تعريفات التنبيه، مرجعي من **الاسم**. يأخذ `create` اسم موضعي بالإضافة إلى الأعلام أو جسم JSON كامل عبر `--file`.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME is required (positional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # fire a test notification
agenteye alerts delete high-errors --yes
```

**`incidents`**: حوادث التنبيه، مرجعي من المعرّف (تُقبل المعرّفات القصيرة). `show` يطبع سجل النشاط الكامل؛ اقرأه قبل التصرف.

```bash
agenteye incidents list --state firing                # also: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assignee must be an operator
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # open one manually against an alert
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### التحليلات والمساعد: `query` · `agent`

**`query`**: SQL محفوظ ضد متجر التحليلات الخاص بك بالإضافة إلى عداء حسب الطلب. يتم الإشارة إلى الاستعلامات المحفوظة من قبل **الاسم**؛ يتم التحقق من SQL على جانب الخادم (SELECT/WITH فقط، انتهاء الجلسة وحد الصف).

```bash
agenteye query schema [TABLE]                         # column layout of the analytics views
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # run a saved query + a positional $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: يتحدث مع **مساعد ذكي** مدمج (نفس محلل القراءة فقط الذي يمكنك الدردشة معه في لوحة التحكم). يتم الإشارة إلى الدردشات من خلال معرّف دردشة قصير (بادئة مقررة).

```bash
agenteye agent health                                 # is the AI assistant configured/reachable
agenteye agent models                                 # models you can pass to --model (default marked)
agenteye agent ask "which agents errored most in the last day?"    # starts a chat; prints its short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continue that chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## أكواد الخروج

| الرمز | المعنى |
|---|---|
| 0 | نجاح |
| 1 | خطأ غير متوقع (مثل لوحة التحكم أرجعت 5xx) |
| 2 | خطأ في الاستخدام (الحجج غير الصحيحة والأمر/العلم غير المعروف واسم التصادم) |
| 3 | لا يمكن الوصول إلى لوحة التحكم |
| 4 | غير مسجل أو جلسة منتهية الصلاحية؛ قم بتشغيل `agenteye login` |
| 5 | تم المصادقة عليه، لكن حسابك يفتقد الإذن المطلوب (الرسالة تسميها) |
| 6 | لم يتم العثور على المورد المطلوب (مثل معرّف الجلسة أو الحادثة غير المعروف) |

هذا يجعل واجهة سطر الأوامر آمنة للنصوص البرمجية: يمكن للوكيل البرمجي أن يتفرع على `4` لمطالبتك بإعادة المصادقة أو `5` لسطح الإذن المفقود. انظر [وصفات CLI للوكلاء](/ar/agenteye/cli-recipes) لأنماط معالجة رمز الخروج وأشكال إخراج JSON.
