شغّل كل ملاحظات Failproof AI من الطرفية أو البرنامج النصي: بدون جولات لوحة المعلومات. تستعلم واجهة سطر الأوامر `agenteye` عن بياناتك (الجلسات وسجلات الأحداث والتقييمات) وتدير مؤسستك (مفاتيح API والمستخدمون والإعدادات والتنبيهات والحوادث والاستعلامات المحفوظة)، لذا استخدمها عندما تريد أتمتة فحص أو ربط الملاحظات في CI أو السماح لوكيل ترميز بفحص الإنتاج. كل أمر يدعم علم `--json`، لذا يعمل بشكل متساوٍ لك في موجه الأوامر أو لوكيل ترميز (Claude Code أو Cursor) ينفذ ويحلل النتيجة.

مع ملف تنفيذي واحد يمكنك:

- **قراءة بياناتك**: `sessions`، `events`، `evals`، `errors` (تصفية حسب الوقت والوكيل والبيئة والنقاط).
- **إدارة مؤسستك**: `keys`، `users`، `settings`، `alerts`، `incidents`.
- **تشغيل التحليلات**: SQL محفوظ وأداة استعلام مخصص (`query`).
- **اسأل مساعد الذكاء الاصطناعي**: نفس محلل القراءة فقط الذي تتحدث معه في لوحة المعلومات (`agent`).

> **ملاحظة:** هذه واجهة سطر الأوامر `agenteye`، وهي أداة مختلفة عن عفريت المجمع (`agenteye-collector`). تتحدث واجهة سطر الأوامر مع لوحة المعلومات؛ يرسل المجمع الأحداث إلى الخادم.

## البدء السريع

من لا شيء إلى أول نتيجة لك في أربعة أسطر. وجّه واجهة سطر الأوامر إلى لوحة المعلومات الخاصة بك، وقم بتسجيل الدخول، وأكد من أنت، ثم اسحب آخر يوم من الجلسات:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # emailed 6-digit code
agenteye whoami                                                                  # confirm user + active org
agenteye --json sessions --since 24h                                             # one row per agent run, last 24h
```

يطبع الأمر الأخير كائن JSON للجلسات الأخيرة (الأحدث أولاً، محدود بـ 50 افتراضياً). أنبه إلى `jq` لتقسيمها، أو أسقط `--json` للحصول على جدول مصحح صناديق وملون. يحمل كل صف حالة التشغيل وإذا سجّلها محيّم، درجات المقاييس الخاصة به (مختصرة هنا):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

يشرح باقي هذه الصفحة كل جزء: [التثبيت](#installation) بشكل منفصل، [تسجيل الدخول](#authentication)، [الإعدادات](#configuration)، [الخيارات العامة والاتفاقيات](#global-options--conventions) التي يشاركها كل أمر، و[مرجع الأمر الكامل](#command-reference).

## التثبيت

واجهة سطر الأوامر عبارة عن حزمة PyPI عامة باسم **`agenteye`**. ثبتها في بيئة معزولة حتى تحتفظ دائماً بمعتمدياتها الخاصة:

```bash
pipx install agenteye
# or
uv tool install agenteye
```

يتطلب Python 3.10+. الأمر المثبت هو **`agenteye`**:

```bash
agenteye --version
agenteye --help
```

> **ملاحظة:** Python SDK لـ Failproof AI Observability يستخدم أيضاً اسم توزيع `agenteye`. يحافظ التثبيت باستخدام `pipx` أو `uv tool` (بدلاً من `pip install` في virtualenv مشترك) على عدم تصادم الاثنين. `pip install agenteye` عادي تماماً فقط إذا لم يتم تثبيت SDK في نفس البيئة.

## المصادقة

تصادق واجهة سطر الأوامر لـ **لوحة المعلومات** برمز لمرة واحدة مرسل عبر البريد:

```bash
agenteye login --email you@example.com
# A 6-digit code is emailed to you; paste it at the prompt.
```

يتم حفظ رمز الجلسة في `~/.agenteye/cli.json` (قابل للقراءة فقط من قبلك، الوضع `0600`) وهو صالح لمدة 24 ساعة افتراضياً. عند انتهاء صلاحيته، قم بتشغيل `agenteye login` مرة أخرى.

```bash
agenteye whoami     # show the current user, active org, and permissions
agenteye logout     # revoke the session and clear the stored token
```

`whoami` لا يخطئ أبداً على جلسة مفقودة أو منتهية الصلاحية؛ فإنه يبلغ `logged_in: false` بدلاً من ذلك، لذا يمكن للبرنامج النصي أو الوكيل اختبار حالة المصادقة بأمان (يمكنه الخروج برمز غير صفري إذا لم يتم تعيين عنوان URL أساسي أو كانت لوحة المعلومات غير قابلة للوصول).

**المتطلبات:** يجب السماح لبريدك الإلكتروني بتسجيل الدخول إلى لوحة المعلومات (اطلب من مسؤول Failproof AI Observability)، ويجب أن تكون لوحة المعلومات قابلة للوصول على عنوان URL الأساسي (انظر [الإعدادات](#configuration)). إذا طلبت رمزاً ولم يصل أي شيء، فمن المحتمل أنه لم يتم تفعيل بريدك الإلكتروني بعد للوصول إلى لوحة المعلومات.

## اختيار مؤسستك (متعدد المستأجر)

إذا كان حسابك ينتمي إلى أكثر من مؤسسة واحدة، اختر المؤسسة النشطة **عند تسجيل الدخول**؛ يتم حفظها واستخدامها في كل أمر لاحق:

```bash
agenteye login --org acme           # authenticate and set the active tenant in one step
agenteye orgs list                  # the orgs you can access (the active one is marked)
agenteye orgs switch globex         # change the saved default
agenteye --org globex sessions      # override for a single command
```

إذا كنت تنتمي إلى مؤسسة واحدة بالضبط يتم اختيارها تلقائياً ويمكنك تجاهل `--org` تماماً. إذا كنت تنتمي إلى عدة وليم تختر واحدة، فستقائم واجهة سطر الأوامر بقائمة وتطلب منك إعادة التشغيل باستخدام `--org <slug>`. يتم إرسال المؤسسة النشطة إلى لوحة المعلومات في كل طلب، ويتم حل أذوناتك **لكل مؤسسة**؛ يوضح `agenteye whoami` المؤسسة النشطة وأذوناتك فيها وجميع عضويات أخرى.

## الإعدادات

| الإعداد | العلم | متغير البيئة | القيمة الافتراضية |
|---|---|---|---|
| عنوان URL أساسي لوحة المعلومات | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **مطلوب** (بدون افتراضي) |
| المؤسسة/المستأجر النشط | `--org` | `AGENTEYE_ORG` | يتم الاختيار عند تسجيل الدخول؛ محفوظ في `~/.agenteye/cli.json` |
| رمز الجلسة | `--token` | `AGENTEYE_CLI_TOKEN` | من `~/.agenteye/cli.json` |
| إخراج JSON | `--json` | `AGENTEYE_CLI_JSON` | إيقاف |
| تخطي التحقق من TLS | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | إيقاف (محفوظ عند تسجيل الدخول) |
| مهلة الطلب (ثواني) | `--timeout` | _(لا شيء)_ | 30 |
| تعطيل قياس الاستخدام | _(لا شيء)_ | `AGENTEYE_ANALYTICS_DISABLED` (أو `DO_NOT_TRACK`) | تم تعطيل قياس الاستخدام حالياً؛ لا يتم إرسال شيء |

ترتيب الحل هو **العلم → متغير البيئة → ملف الإعدادات**. لا يوجد افتراضي؛ يجب عليك توجيه واجهة سطر الأوامر إلى لوحة المعلومات الخاصة بك، إما لكل أمر (`--base-url https://agenteye.example.com`) أو مرة واحدة عبر البيئة (يتم حفظها أيضاً بعد أول `login` لك):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

دليل الإعدادات يحترم `AGENTEYE_HOME` (نفس الاتفاقية المستخدمة من قبل SDK والمجمع)؛ إذا تم تعيينه، يعيش `cli.json` في `$AGENTEYE_HOME/cli.json`.

### TLS موقّع ذاتياً أو داخلي

إذا تم تقديم لوحة المعلومات الخاصة بك عبر HTTPS بشهادة موقّعة ذاتياً أو داخلية (على سبيل المثال، اسم مضيف موازن تحميل خام)، يرفضه التحقق من TLS برمز خطأ `CERTIFICATE_VERIFY_FAILED`. مرر `--insecure` لتخطي التحقق من الشهادة:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

يتم **حفظ `--insecure` إلى `cli.json` عند تسجيل الدخول**، لذا تخطي الأوامر اللاحقة التحقق تلقائياً؛ لا يجب عليك تكرار العلم. مرر `--secure` لاستدعاء تحقق لمرة واحدة، أو لحفظ التحقق بدلاً من ذلك عند تسجيل الدخول التالي. تطبع واجهة سطر الأوامر تحذيراً إلى stderr قبل أي أمر يتصل بلوحة المعلومات بينما يتم تعطيل التحقق. يزيل تخطي التحقق الحماية من هجمات man-in-the-middle؛ تأكد من أنك تثق في مسار الشبكة إلى لوحة المعلومات الخاصة بك (VPN أو شبكة فرعية خاصة، إلخ) قبل الاعتماد عليها.

## قياس الاستخدام والخصوصية

> **ملاحظة:** واجهة سطر الأوامر المشحونة **لا ترسل قياس استخدام اليوم.** مفتاح القتل الرئيسي قيد التشغيل، لذا لا يتم نقل شيء بغض النظر عن بيئتك. يصف القسم أدناه القدرة على عدم الاشتراك في حالة وعند تفعيل قياس الاستخدام.

حتى عند التمكين، سيكون قياس الاستخدام **تحليلات استخدام مجهولة فقط**، وليس أبداً وكيل أو جلسة أو بيانات حدث:

- **لا تغادر أبداً بيانات الوكيل أو الجلسة أو الحدث البنية التحتية الخاصة بك.** سيتم الإبلاغ عن استخدام واجهة سطر الأوامر فقط: اسم الأمر والأمر الفرعي (على سبيل المثال `keys create`)، **أسماء** الأعلام التي استخدمتها (لا قيم لها)، حالة النجاح/الخروج والمدة، بالإضافة إلى حدث لكل إجراء للطفرات (على سبيل المثال `api_key_created`، `query_run`) يحمل فقط أسماء/تعريفات ثابتة وأعداد خشنة. عنوان URL لوحة المعلومات الخاصة بك ورمز الجلسة والبريد الإلكتروني وشريط المؤسسة ومعرفات الموارد والمفاتيح السرية وفلاتر الاستعلام **لا يتم أبداً** إرسالها. سيتم التعرف على المشغلين فقط بواسطة معرف داخلي معتم، وليس بالبريد الإلكتروني.
- **اختر عدم الاشتراك قبل الوقت** عن طريق تعيين `AGENTEYE_ANALYTICS_DISABLED=1` في بيئة واجهة سطر الأوامر (تحترم واجهة سطر الأوامر أيضاً الاتفاقية `DO_NOT_TRACK=1` عبر الأدوات). يسري هذا عند تفعيل قياس الاستخدام، لذا يمكن للبيئة التي تولي أهمية للخصوصية البقاء بدون الاشتراك بشكل دائم.
- إذا تم تفعيل قياس الاستخدام، ستُرسل واجهة سطر الأوامر مباشرة إلى PostHog (`https://us.i.posthog.com`)؛ ستسكت آلة مع هذا المضيف المحظور وتُرسل لا شيء وستتأثر واجهة سطر الأوامر.

## الخيارات العامة والاتفاقيات

اقرأ هذا مرة واحدة؛ ينطبق على كل أمر.

- **تأتي الخيارات العامة قبل الأمر.** `agenteye --json sessions` صحيح؛ `agenteye sessions --json` خطأ الاستخدام. العامات هي `--json`، `--base-url`، `--org`، `--token`، `--insecure`/`--secure`، `--timeout`، `--quiet`، و`--no-color`.
- **يطبع `--json` JSON نقي إلى stdout وليس شيء آخر.** تذهب خطوط حالة الموارد البشرية والتحذيرات والأخطاء إلى **stderr**، لذا يبقى التقاط stdout `--json` نظيفاً للأنبوب إلى `jq` حتى عندما تظهر خط الحالة. بدون `--json` تحصل على عرض صناديق ملون لأعين البشر.
- **اكتشف باستخدام `--help`.** لكل أمر وأمر فرعي `--help` (والاسم المستعار `-h`): `agenteye -h`، `agenteye sessions -h`، `agenteye keys create -h`. يسرد المساعدة ذات المستوى الأعلى أيضاً رموز الخروج والخيارات العامة. لا توجد مساحة قابلة للقراءة من قبل الآلة عالمية؛ استخدم `--help` لكل أمر، بالإضافة إلى `agenteye query schema` و`agenteye settings schema` الخاصة بالمجال لهاتين السجلات.
- **تخطي التأكيدات تلقائياً للبرامج النصية والوكلاء.** تطلب أوامر الإنشاء/التحديث/الحذف "هل أنت متأكد؟" في محطة طرفية تفاعلية، لكن **تخطي هذا الطلب تحت `--json` أو عند عدم كون stdin TTY** (TTY هو جلسة طرفية تفاعلية؛ الأنبوب أو عداء CI ليس)، لذا لا تتعطل البرامج النصية والوكلاء أبداً. مرر `--yes`/`-y` لتخطيه بشكل صريح. لأن الطلب لن ينطلق للوكيل، يجب على الوكيل تأكيد الإجراءات المدمرة مع الإنسان أولاً.
- **الترقيم:** النتائج هي الأحدث أولاً والترقيم بالمؤشر (تُرجع كل صفحة رمزاً تستخدمه لجلب التالي). `--limit N` (الاسم المستعار `-n`) يحد الصفوف و**الافتراضي إلى 50**؛ `--all` يصفحة تلقائياً (في أجزاء من 200 صف) **حتى `--limit`**، لذا `--all` عارية توقف لا تزال عند 50. للفحص الكامل مرر حد عالي صريح: `--all --limit 1000`. `--page-size N` يتحكم في الجزء لكل طلب (أقصى 200)؛ `--cursor <id>` استأنف من `next_cursor` للصفحة السابقة.
- **مرشحات الوقت:** `--since` يأخذ نافذة نسبية: `15m`، `1h`، `6h`، `24h`، `7d`، أو `all` (الإعدادات المسبقة لوحة المعلومات). لنطاق أطول أو مخصص (قل آخر 30 يوماً)، استخدم `--from`/`--to`: طوابع زمنية ISO-8601 UTC صريحة **مع `T` ومنطقة زمنية** (مثل `2026-06-01T00:00:00Z`) التي تتجاوز `--since`. قيمة مفصولة بمسافة أو بدون منطقة زمنية هي خطأ الاستخدام.
- **`--fields a,b,c`** (على `events`، `sessions`، `evals`، `errors`) يقيد الإخراج إلى تلك المفاتيح، لكل الجدول و`--json`. يتم رفض الأسماء غير المعروفة برسالة القائمة الصحيحة، وهي طريقة رخيصة لاكتشاف أسماء الحقول.
- **`--file payload.json`** (أو `--file -` لقراءة stdin) توفر جسم طلب JSON كامل حيث تحتوي مورد إلى شكل معقد (على `alerts create/update`، `settings set`، و`users create/update`). استخدم SQL للاستعلام المحفوظ `--sql @file.sql` بدلاً من ذلك.
- **مرشحات متعددة القيم** مفصولة بفواصل → مطابقة كمجموعة (اتحاد داخل مرشح واحد، AND عبر المرشحات): `--event-type tool_use,tool_result`. خيارات النقر ليست متغيرة، لذا `--add a b` ينقطع. استخدم `--add a,b`، كرر العلم (`--add a --add b`)، أو اقتبس (`--add "a b"`).

## مرجع الأمر

### ستستخدم هذه الأوامر الخمسة في الغالب

يتم تشغيل معظم العمل اليومي من خلال حفنة من أوامر القراءة. ابدأ هنا، ثم توصل بالسطح الكامل أدناه عندما تحتاج إليه:

| الأمر | ما يفعله | جربه |
|---|---|---|
| `sessions` | صف واحد لكل تشغيل وكيل: الوقت والبيئة والوكيل والحالة وآخر درجة. | `agenteye --json sessions --since 24h --status error` |
| `events` | مسار خطوة خام داخل تشغيل (أضف `--full` للحمولات). | `agenteye --json events --session-id run-001 --all` |
| `evals` | نتائج التقييم والنقاط؛ `--aggregate` تلفهم. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | فقط الأحداث المخطأ؛ `--aggregate` للأعداد حسب النوع. | `agenteye --json errors --since 24h --aggregate` |
| `list` | اكتشف قيم المرشح الصحيحة (الوكلاء والبيئات والنماذج...). | `agenteye list agents` |

### كل ما يمكن لواجهة سطر الأوامر فعله

يتبع السطح الكامل. واجهة سطر الأوامر لها **18 أمر ذو مستوى أعلى**. جميع أوامر القراءة تقبل `--json` والخيارات العامة أعلاه؛ قم بتشغيل `agenteye <command> -h` (أو `<command> <subcommand> -h`) للقائمة الشاملة للأعلام وشكل JSON لأي واحد.

### الهوية: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # emailed one-time code; saves the session
agenteye logout                                       # clear the saved session on this machine
agenteye whoami                                       # current user, active org, permissions
agenteye version                                      # print the CLI version (same as --version)
agenteye help                                         # top-level help (same as --help)
```

`orgs` تفتش وتبديل المستأجر النشط:

```bash
agenteye orgs list        # your orgs + your role in each (active one marked)
agenteye orgs switch acme # change the saved active org (omit the slug to pick from a list on a TTY)
agenteye orgs current     # identity card for the active org
agenteye orgs perms       # your permissions in the active org, grouped by resource
```

### المراقبة (القراءة فقط): `events` · `sessions` · `evals` · `errors` · `list`

لا يحتاج أي من هؤلاء إلى تأكيد. المرشحات المشتركة: `--session-id`، `--agent-id`، `--env` (**ليس** `--environment`)، ونطاق الوقت (`--since` / `--from` / `--to`).

```bash
# events (alias: the raw per-step trail), newest first
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: one row per agent run (time/env/agent/session/status; no score filtering)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: evaluation results + scores; --score filters by metric, --aggregate rolls up
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # status mix + per-key score stats

# errors: errored events; --aggregate for counts/sessions/agents/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: discover valid filter values before you filter
agenteye list envs        # also: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (على **`evals`**، وليس `sessions`) قابل للتكرار و AND-مركب؛ كل حد اختياري (`..0.5` يعني ≤ 0.5، `0.9..` يعني ≥ 0.9). حتى 20 مرشح نقاط لكل طلب. `evals --scores-full` هو علم عرض لـ **جدول الإنسان فقط**؛ يظهر كل زوج النقاط بدلاً من الأول المتعدد زائد عد `+N`. لا تأثير تحت `--json`، الذي يُرجع دائماً كائن النقاط المكتمل. لقراءة **جلسة واحدة من البداية إلى النهاية**، قم بدمج مسار الحدث مع تقييمه:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # its scores + status
```

### الإدارة (حراس الأذونات): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: مفاتيح API. يتم إنشاء السر محلياً وإرساله إلى الخادم (الذي يخزن فقط التجزئة) و**يظهر مرة واحدة** على الإنشاء/إعادة التوليد؛ استخرجه بعد ذلك. مع `--json` يظهر فقط في حقل `key`. مرجعي من خلال **الاسم**.

```bash
agenteye keys list                                   # active keys first, then revoked
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # scope to what you need; prints the secret ONCE
agenteye keys create ops --permission-set standard --remove queries:run   # seed a preset, then trim
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rotate the secret (the old one stops working)
agenteye keys disable ci-bot --yes                   # revoke
```

تعمل الأذونات كـ `(permission-set ∪ --add) − --remove`. الرموز هي `slug:action` (مثل `events:read`) أو `slug:action.action` لتوسيع عدة على مورد واحد (`events:read.add` → `events:read`, `events:add`). الإعدادات المسبقة: `read-only`، `standard`، `admin`. الأذونات البشرية فقط (`keys:update`) لا يمكن منحها لمفتاح.

**`users`**: أعضاء المنظمة، مرجعيين من خلال **البريد الإلكتروني** (يتم قبول معرف UUID أيضاً).

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predicts + confirms
agenteye users disable dev@corp.com --yes            # has protected/self guards
agenteye users enable dev@corp.com
```

**`settings`**: سجل ثابت (تقرأ وتغيير المفاتيح الموجودة؛ لا يمكنك إنشاء مفاتيح جديدة).

```bash
agenteye settings list                               # key · value · type · updated (secrets masked)
agenteye settings schema                             # what each key accepts (type · range · description)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: تعريفات التنبيهات، مرجعية من خلال **الاسم**. `create` يأخذ موضع NAME زائد الأعلام أو جسم JSON كامل عبر `--file`.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME is required (positional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # fire a test notification
agenteye alerts delete high-errors --yes
```

**`incidents`**: حوادث التنبيهات، مرجعية حسب المعرف (يتم قبول المعرفات القصيرة). `show` طباعة سجل النشاط الكامل؛ اقرأه قبل التصرف.

```bash
agenteye incidents list --state firing                # also: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assignee must be an operator
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # open one manually against an alert
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### التحليلات والمساعد: `query` · `agent`

**`query`**: SQL محفوظ ضد متجر التحليلات الخاص بك بالإضافة إلى عداء مخصص. يتم الرجوع إلى الاستعلامات المحفوظة من خلال **الاسم**؛ يتم التحقق من SQL من جانب الخادم (SELECT/WITH فقط، مهلة البيان، حد الصف).

```bash
agenteye query schema [TABLE]                         # column layout of the analytics views
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # run a saved query + a positional $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: يتحدث إلى **مساعد الذكاء الاصطناعي** المدمج (نفس محلل القراءة فقط الذي يمكنك الدردشة معه في لوحة المعلومات). يتم الرجوع إلى الدردشات بواسطة معرف دردشة قصير (حل البادئة).

```bash
agenteye agent health                                 # is the AI assistant configured/reachable
agenteye agent models                                 # models you can pass to --model (default marked)
agenteye agent ask "which agents errored most in the last day?"    # starts a chat; prints its short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continue that chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## رموز الخروج

| الرمز | المعنى |
|---|---|
| 0 | النجاح |
| 1 | خطأ غير متوقع (مثل لوحة المعلومات أرجعت 5xx) |
| 2 | خطأ الاستخدام (حجج غير صحيحة وأمر/علم غير معروف واسم تصادم) |
| 3 | لا يمكن الوصول إلى لوحة المعلومات |
| 4 | لم تقم بتسجيل الدخول أو انتهت جلسة؛ قم بتشغيل `agenteye login` |
| 5 | تم المصادقة، لكن حسابك يفتقد الإذن المطلوب (الرسالة تسميه) |
| 6 | لم يتم العثور على المورد المطلوب (مثل معرف جلسة أو حادثة غير معروف) |

هذه تجعل واجهة سطر الأوامر آمنة للبرنامج: يمكن لوكيل ترميز أن يفرع على `4` لدعوتك لإعادة المصادقة، أو `5` لسطح الإذن المفقود. انظر [وصفات واجهة سطر الأوامر للوكلاء](/ar/agenteye/cli-recipes) لأنماط معالجة رمز الخروج وأشكال إخراج JSON.
