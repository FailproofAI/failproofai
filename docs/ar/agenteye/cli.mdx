قُد كل مراقبة Failproof AI من الطرفية أو السكريبت: بدون رحلات لوحة التحكم. يستعلم واجهة سطر الأوامر `agenteye` عن بيانات المتابعة والسجلات والتقييمات، ويدير مؤسستك (مفاتيح API والمستخدمون والإعدادات والتنبيهات والحوادث والاستعلامات المحفوظة)، لذا استخدمه عندما تريد أتمتة فحص أو دمج المراقبة في خط أنابيب CI، أو عندما تريد لوكيل برمجي فحص الإنتاج. كل أمر يدعم علم `--json`، بحيث يعمل بالتساوي معك في المحث أو مع وكيل برمجي (Claude Code، Cursor) ينفذ الأوامر ويحلل النتائج.

باستخدام ملف تنفيذي واحد يمكنك:

- **قراءة بيانات المتابعة**: `sessions`، `events`، `evals`، `errors` (مع تصفية حسب الوقت والوكيل والبيئة والنقاط).
- **إدارة مؤسستك**: `keys`، `users`، `settings`، `alerts`، `incidents`.
- **تشغيل التحليلات**: SQL محفوظ ومُشغِّل استعلامات مرتجل (`query`).
- **طرح الأسئلة على مساعد AI**: نفس المحلل للقراءة فقط الذي تتحادث معه في لوحة التحكم (`agent`).

> **ملاحظة:** هذه واجهة سطر الأوامر `agenteye`، وهي أداة مختلفة عن مجمِّع الأحداث (`agenteye-collector`). تتحدث واجهة سطر الأوامر إلى لوحة التحكم؛ يرسل المجمِّع الأحداث إلى الخادم.

## البدء السريع

من لا شيء إلى أول نتيجة في أربعة أسطر. وجِّه واجهة سطر الأوامر إلى لوحة التحكم، وسجِّل الدخول، وأكِّد هويتك، ثم اسحب آخر يوم من المتابعات:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # emailed 6-digit code
agenteye whoami                                                                  # confirm user + active org
agenteye --json sessions --since 24h                                             # one row per agent run, last 24h
```

الأمر الأخير يطبع كائن JSON بأحدث المتابعات (الأحدث أولاً، محدود بـ 50 افتراضياً). صِب النتيجة إلى `jq` للتقطيع، أو احذف `--json` للحصول على جدول ملون في صندوق. كل صف يحمل حالة المتابعة والنقاط المترية إن وجدت (مختصرة هنا):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

يشرح باقي هذه الصفحة كل جزء: [التثبيت](#installation) بمعزل تام، [تسجيل الدخول](#authentication)، [الإعدادات](#configuration)، [الاصطلاحات العامة](#global-options--conventions) التي يشاركها كل أمر، و[مرجع الأوامر الكامل](#command-reference).

## التثبيت

واجهة سطر الأوامر حزمة عامة في PyPI تسمى **`agenteye`**. ثبِّتها في بيئة معزولة بحيث يكون لها دائماً اعتماديات خاصة بها:

```bash
pipx install agenteye
# or
uv tool install agenteye
```

تتطلب Python 3.10+. الأمر المثبَّت هو **`agenteye`**:

```bash
agenteye --version
agenteye --help
```

> **ملاحظة:** استخدم Failproof AI Observability Python SDK أيضاً اسم التوزيع `agenteye`. التثبيت باستخدام `pipx` أو `uv tool` (بدلاً من `pip install` إلى virtualenv مشترك) يمنع التعارض بينهما. `pip install agenteye` العادي آمن فقط إذا لم تكن SDK مثبتة في نفس البيئة.

## المصادقة

تعتمد واجهة سطر الأوامر على **لوحة التحكم** باستخدام رمز أحادي الاستخدام يتم إرساله بالبريد الإلكتروني:

```bash
agenteye login --email you@example.com
# A 6-digit code is emailed to you; paste it at the prompt.
```

يتم تخزين رمز الجلسة في `~/.agenteye/cli.json` (قابل للقراءة فقط من قبلك، الوضع `0600`) وصالح لمدة 24 ساعة بشكل افتراضي. عند انتهائها، شغِّل `agenteye login` مرة أخرى.

```bash
agenteye whoami     # show the current user, active org, and permissions
agenteye logout     # revoke the session and clear the stored token
```

لا يخطئ `whoami` أبداً على جلسة مفقودة أو منتهية الصلاحية؛ بدلاً من ذلك، يبلِّغ عن `logged_in: false`، بحيث يمكن للسكريبت أو الوكيل اختبار حالة المصادقة بأمان (لكن يمكنه الخروج برمز غير صفري إذا لم تُعيِّن base URL أو لم تكن لوحة التحكم في متناول اليد).

**المتطلبات:** يجب أن يُسمح لبريدك الإلكتروني بتسجيل الدخول إلى لوحة التحكم (اطلب من مسؤول Failproof AI Observability)، ويجب أن تكون لوحة التحكم متاحة عند عنوان base URL (انظر [الإعدادات](#configuration)). إذا طلبت رمزاً ولم يصل، فربما لم يتم تفعيل بريدك الإلكتروني بعد للوصول إلى لوحة التحكم.

## اختيار مؤسستك (متعدد المستأجرين)

إذا كانت حسابك ينتمي إلى أكثر من مؤسسة واحدة، اختر المؤسسة النشطة **عند تسجيل الدخول**؛ يتم حفظها واستخدامها في كل أمر لاحق:

```bash
agenteye login --org acme           # authenticate and set the active tenant in one step
agenteye orgs list                  # the orgs you can access (the active one is marked)
agenteye orgs switch globex         # change the saved default
agenteye --org globex sessions      # override for a single command
```

إذا كنت تنتمي إلى مؤسسة واحدة بالضبط، يتم اختيارها تلقائياً ويمكنك تجاهل `--org` بالكامل. إذا كنت تنتمي إلى عدة مؤسسات ولم تختر واحدة، تسرد واجهة سطر الأوامر المؤسسات وتطلب منك إعادة التشغيل باستخدام `--org <slug>`. يتم إرسال المؤسسة النشطة إلى لوحة التحكم في كل طلب، وتُحلّ أذوناتك **لكل مؤسسة**؛ يعرض `agenteye whoami` المؤسسة النشطة وأذوناتك فيها وكل عضوياتك.

## الإعدادات

| الإعداد | العلم | متغير البيئة | القيمة الافتراضية |
|---|---|---|---|
| عنوان base URL للوحة التحكم | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **مطلوب** (بدون قيمة افتراضية) |
| المؤسسة/المستأجر النشط | `--org` | `AGENTEYE_ORG` | مختار عند تسجيل الدخول؛ محفوظ في `~/.agenteye/cli.json` |
| رمز الجلسة | `--token` | `AGENTEYE_CLI_TOKEN` | من `~/.agenteye/cli.json` |
| مخرجات JSON | `--json` | `AGENTEYE_CLI_JSON` | معطل |
| تخطي التحقق من TLS | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | معطل (محفوظ عند تسجيل الدخول) |
| مهلة الطلب (الثواني) | `--timeout` | _(none)_ | 30 |
| تعطيل بيانات الاستخدام | _(none)_ | `AGENTEYE_ANALYTICS_DISABLED` (أو `DO_NOT_TRACK`) | بيانات الاستخدام معطلة حالياً؛ لا يتم إرسال شيء |

ترتيب الحل هو **العلم → متغير البيئة → ملف الإعدادات**. لا توجد قيمة افتراضية؛ يجب أن توجِّه واجهة سطر الأوامر إلى لوحة التحكم، إما لكل أمر (`--base-url https://agenteye.example.com`) أو مرة واحدة عبر البيئة (يتم حفظها أيضاً بعد أول `login`):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

دليل الإعدادات يحترم `AGENTEYE_HOME` (نفس الاصطلاح المستخدم من قبل SDK والمجمِّع)؛ إذا تم تعيينه، يعيش `cli.json` في `$AGENTEYE_HOME/cli.json`.

### TLS ذاتي التوقيع أو داخلي

إذا تم تقديم لوحة التحكم عبر HTTPS بشهادة ذات توقيع ذاتي أو داخلية (على سبيل المثال، اسم مضيف موازن تحميل خام)، يرفض التحقق من TLS برسالة خطأ `CERTIFICATE_VERIFY_FAILED`. مرِّر `--insecure` لتخطي التحقق من الشهادة:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

يتم **حفظ `--insecure` إلى `cli.json` عند تسجيل الدخول**، بحيث تتخطى الأوامر اللاحقة التحقق تلقائياً؛ لا تحتاج إلى تكرار العلم. مرِّر `--secure` لاستدعاء موثق لمرة واحدة، أو لحفظ التحقق مرة أخرى عند تسجيل الدخول التالي. تطبع واجهة سطر الأوامر تحذيراً على stderr قبل أي أمر يتصل بلوحة التحكم بينما التحقق معطل. تخطي التحقق يزيل الحماية ضد هجمات man-in-the-middle؛ تأكد من أنك تثق في مسار الشبكة إلى لوحة التحكم (VPN، شبكة فرعية خاصة، إلخ) قبل الاعتماد عليها.

## بيانات الاستخدام والخصوصية

> **ملاحظة:** واجهة سطر الأوامر المشحونة **لا ترسل بيانات استخدام اليوم.** يوجد مفتاح إيقاف رئيسي، بحيث لا يتم نقل أي شيء بغض النظر عن البيئة الخاصة بك. يصف القسم أدناه إمكانية الانسحاب إذا وعندما تكون هناك بيانات استخدام على الإطلاق.

حتى عندما تكون مفعلة، ستكون بيانات الاستخدام **تحليلات استخدام مجهولة فقط**، وليس بيانات الوكيل أو الجلسة أو الأحداث:

- **لا تترك بيانات الوكيل أو الجلسة أو الأحداث البنية الأساسية أبداً.** سيتم الإبلاغ عن استخدام واجهة سطر الأوامر فقط: اسم الأمر والأمر الفرعي (مثلاً `keys create`)، **أسماء** الأعلام التي استخدمتها (ليس قيمها أبداً)، حالة النجاح/الخروج والمدة، بالإضافة إلى حدث واحد لكل عملية (مثلاً `api_key_created`، `query_run`) يحمل فقط أسماء/تعديلات ثابتة وعدد تقريبي. عنوان لوحة التحكم ورمز الجلسة والبريد الإلكتروني ومقطع المؤسسة ومعرفات الموارد والـ SQL وأسرار المفاتيح ومرشحات الاستعلام **لن** يتم إرسالها أبداً. سيتم تحديد المشغلين فقط برقم معرّف داخلي معتم، ليس بالبريد الإلكتروني.
- **استبعد مقدماً** بتعيين `AGENTEYE_ANALYTICS_DISABLED=1` في بيئة واجهة سطر الأوامر (تحترم واجهة سطر الأوامر أيضاً اصطلاح `DO_NOT_TRACK=1` عبر الأدوات). هذا يدخل حيز التنفيذ عندما تُفعَّل بيانات الاستخدام، بحيث يمكن للبيئة التي تهتم بالخصوصية أن تبقى مستبعدة بشكل دائم.
- إذا تم تفعيل بيانات الاستخدام، ستُرسل واجهة سطر الأوامر مباشرة إلى PostHog (`https://us.i.posthog.com`)؛ الجهاز الذي يمنع هذا المضيف سيرسل صمتاً ولا تتأثر واجهة سطر الأوامر.

## الخيارات العامة والاصطلاحات

اقرأ هذا مرة واحدة؛ ينطبق على كل أمر.

- **تأتي الخيارات العامة قبل الأمر.** `agenteye --json sessions` صحيح؛ `agenteye sessions --json` خطأ في الاستخدام. الخيارات العامة هي `--json`، `--base-url`، `--org`، `--token`، `--insecure`/`--secure`، `--timeout`، `--quiet`، و`--no-color`.
- **`--json` يطبع JSON نقي إلى stdout، وليس شيء آخر.** خطوط حالة بشرية وتحذيرات وأخطاء تذهب إلى **stderr**، بحيث تبقى لقطة `--json` stdout نظيفة للنقل إلى `jq` حتى عندما يُعرض خط حالة. بدون `--json` تحصل على عرض ملون مرسوم في صندوق للعين البشرية.
- **استكشف باستخدام `--help`.** لكل أمر وأمر فرعي `--help` (و`-h` الاختصار): `agenteye -h`، `agenteye sessions -h`، `agenteye keys create -h`. تُرسل مساعدة أعلى مستوى أيضاً رموز الخروج والخيارات العامة. لا يوجد تفريغ سطح قابل للقراءة من قبل الآلة عام؛ استخدم `--help` لكل أمر، بالإضافة إلى `agenteye query schema` و`agenteye settings schema` المتعلقة بالمجال لتلك السجلات.
- **التأكيدات تتخطى تلقائياً للنصوص والوكلاء.** أوامر الإنشاء/التحديث/الحذف تطالب بـ "هل أنت متأكد؟" في طرفية تفاعلية، لكن **تتخطى المطالبة تلقائياً تحت `--json` أو عندما لا تكون stdin ملف TTY** (TTY جلسة طرفية تفاعلية؛ أنبوب أو عداء CI ليس كذلك)، بحيث لا تتعطل النصوص والوكلاء. مرِّر `--yes`/`-y` لتخطيها بصراحة. لأن المطالبة لن تُطلَق للوكيل، يجب على الوكيل تأكيد الإجراءات المدمِّرة مع البشر أولاً.
- **الترقيم**: النتائج هي الأحدث أولاً والترقيم بالمؤشر (كل صفحة تعيد رمزاً تستخدمه لجلب التالي). `--limit N` (اختصار `-n`) يحد الصفوف و**يفترض 50**؛ `--all` يرقِّم تلقائياً (في أجزاء 200 صف) **حتى `--limit`**، بحيث يتوقف `--all` العادي عند 50. للمسح الكامل مرِّر حد صريح عالي: `--all --limit 1000`. `--page-size N` يتحكم في الجزء لكل طلب (أقصى 200)؛ `--cursor <id>` يستأنف من `next_cursor` الصفحة السابقة.
- **مرشحات الوقت:** `--since` يأخذ نافذة نسبية: `15m`، `1h`، `6h`، `24h`، `7d`، أو `all` (إعدادات لوحة التحكم المسبقة). لنطاق أطول أو مخصص (قل آخر 30 يوماً)، استخدم `--from`/`--to`: طوابع زمنية ISO-8601 UTC صريحة **مع `T` ومنطقة زمنية** (مثلاً `2026-06-01T00:00:00Z`) التي تستبدل `--since`. قيمة مفصولة بمسافة أو خالية من المنطقة الزمنية هي خطأ استخدام.
- **`--fields a,b,c`** (على `events`، `sessions`، `evals`، `errors`) تقيِّد المخرجات إلى تلك المفاتيح، للجدول و`--json`. الأسماء غير المعروفة يتم رفضها مع القائمة الصحيحة، طريقة رخيصة لاكتشاف أسماء الحقول.
- **`--file payload.json`** (أو `--file -` لقراءة stdin) توفِّر جسم طلب JSON كامل حيث يحتوي المورد على شكل معقد (على `alerts create/update`، `settings set`، و`users create/update`). SQL الاستعلام المحفوظ يستخدم `--sql @file.sql` بدلاً من ذلك.
- **مرشحات القيم المتعددة** مفصولة بفواصل → مطابقة كمجموعة (اتحاد داخل مرشح واحد، AND عبر المرشحات): `--event-type tool_use,tool_result`. خيارات النقر ليست متغيرة الطول، بحيث `--add a b` ينقطع. استخدم `--add a,b`، كرِّر العلم (`--add a --add b`)، أو اقتبس (`--add "a b"`).

## مرجع الأوامر

### ستستخدم هذه 5 أوامر الأكثر

معظم العمل اليومي يتم من خلال حفنة من أوامر القراءة. ابدأ هنا، ثم تناول السطح الكامل أدناه عندما تحتاجه:

| الأمر | ما يفعله | جرِّبه |
|---|---|---|
| `sessions` | صف واحد لكل تشغيل وكيل: الوقت والبيئة والوكيل والحالة والنقطة الأخيرة. | `agenteye --json sessions --since 24h --status error` |
| `events` | مسار خام لكل خطوة داخل تشغيل (أضِف `--full` للحمولات). | `agenteye --json events --session-id run-001 --all` |
| `evals` | نتائج التقييم والنقاط؛ `--aggregate` يدحرجها. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | فقط الأحداث المخطئة؛ `--aggregate` لعدد الأنواع. | `agenteye --json errors --since 24h --aggregate` |
| `list` | اكتشف قيم المرشح الصحيحة (الوكلاء والبيئات والنماذج...). | `agenteye list agents` |

### كل ما يمكن لواجهة سطر الأوامر فعله

يتبع السطح الكامل. واجهة سطر الأوامر لها **18 أمر على أعلى مستوى**. جميع أوامر القراءة تقبل `--json` والخيارات العامة أعلاه؛ شغِّل `agenteye <command> -h` (أو `<command> <subcommand> -h`) للقائمة الشاملة للأعلام وشكل JSON لأي منها.

### الهوية: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # emailed one-time code; saves the session
agenteye logout                                       # clear the saved session on this machine
agenteye whoami                                       # current user, active org, permissions
agenteye version                                      # print the CLI version (same as --version)
agenteye help                                         # top-level help (same as --help)
```

`orgs` يتفحص ويبدِّل المستأجر النشط:

```bash
agenteye orgs list        # your orgs + your role in each (active one marked)
agenteye orgs switch acme # change the saved active org (omit the slug to pick from a list on a TTY)
agenteye orgs current     # identity card for the active org
agenteye orgs perms       # your permissions in the active org, grouped by resource
```

### المراقبة (القراءة فقط): `events` · `sessions` · `evals` · `errors` · `list`

لا شيء من هذه يحتاج إلى تأكيد. المرشحات المشتركة: `--session-id`، `--agent-id`، `--env` (**ليس** `--environment`)، ونطاق الوقت (`--since` / `--from` / `--to`).

```bash
# events (alias: the raw per-step trail), newest first
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: one row per agent run (time/env/agent/session/status; no score filtering)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: evaluation results + scores; --score filters by metric, --aggregate rolls up
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # status mix + per-key score stats

# errors: errored events; --aggregate for counts/sessions/agents/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: discover valid filter values before you filter
agenteye list envs        # also: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (على **`evals`**، ليس `sessions`) قابل للتكرار وموافق عليه AND؛ كل حد اختياري (`..0.5` يعني ≤ 0.5، `0.9..` يعني ≥ 0.9). حتى 20 مرشح نقاط لكل طلب. `evals --scores-full` علم عرض **لجدول بشري فقط**؛ يعرض كل زوج نقاط بدلاً من الأول عدة بالإضافة إلى عدد `+N`. لا تأثير تحت `--json`، الذي يعيد دائماً كائن النقاط الكامل. لقراءة **جلسة واحدة من البداية إلى النهاية**، ادمج مسار الحدث مع تقييمه:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # its scores + status
```

### الإدارة (مع بوابة الأذن): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: مفاتيح API. السر يتم إنشاؤه محلياً، ويُرسل إلى الخادم (الذي يخزِّن فقط الملخص)، و**يُعرض مرة واحدة** عند الإنشاء/إعادة الإنشاء؛ التقطه حينئذ. مع `--json` يظهر فقط في الحقل `key`. مرجعي بـ **الاسم**.

```bash
agenteye keys list                                   # active keys first, then revoked
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # scope to what you need; prints the secret ONCE
agenteye keys create ops --permission-set standard --remove queries:run   # seed a preset, then trim
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rotate the secret (the old one stops working)
agenteye keys disable ci-bot --yes                   # revoke
```

تعمل الأذن كـ `(permission-set ∪ --add) − --remove`. الرموز هي `slug:action` (مثلاً `events:read`) أو `slug:action.action` للتوسع على مورد واحد (`events:read.add` → `events:read`، `events:add`). الإعدادات المسبقة: `read-only`، `standard`، `admin`. الأذن البشرية فقط (`keys:update`) لا يمكن منحها للمفتاح.

**`users`**: أعضاء المؤسسة، مرجعيين بـ **البريد الإلكتروني** (معرّف UUID يُقبل أيضاً).

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predicts + confirms
agenteye users disable dev@corp.com --yes            # has protected/self guards
agenteye users enable dev@corp.com
```

**`settings`**: سجل ثابت (تقرأ وتغيِّر المفاتيح الموجودة؛ لا يمكنك إنشاء أخرى جديدة).

```bash
agenteye settings list                               # key · value · type · updated (secrets masked)
agenteye settings schema                             # what each key accepts (type · range · description)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: تعريفات التنبيهات، مرجعية بـ **الاسم**. `create` يأخذ NAME موضعي بالإضافة إلى الأعلام أو جسم JSON كامل عبر `--file`.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME is required (positional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # fire a test notification
agenteye alerts delete high-errors --yes
```

**`incidents`**: حوادث التنبيهات، مرجعية برقم المعرّف (يُقبل الرقم القصير). `show` يطبع سجل النشاط الكامل؛ اقرأه قبل التصرف.

```bash
agenteye incidents list --state firing                # also: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assignee must be an operator
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # open one manually against an alert
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### التحليلات والمساعد: `query` · `agent`

**`query`**: SQL محفوظ مقابل متجر التحليلات بالإضافة إلى مُشغِّل مرتجل. الاستعلامات المحفوظة مرجعية بـ **الاسم**؛ يتم التحقق من صحة SQL خادماً (SELECT/WITH فقط، مهلة البيان، حد الصف).

```bash
agenteye query schema [TABLE]                         # column layout of the analytics views
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # run a saved query + a positional $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: يتحدث إلى **مساعد AI** المدمج (نفس المحلل للقراءة فقط الذي يمكنك التحادث معه في لوحة التحكم). الدردشات مرجعية برقم معرّف دردشة قصير (موضع-محلول).

```bash
agenteye agent health                                 # is the AI assistant configured/reachable
agenteye agent models                                 # models you can pass to --model (default marked)
agenteye agent ask "which agents errored most in the last day?"    # starts a chat; prints its short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continue that chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## رموز الخروج

| الرمز | المعنى |
|---|---|
| 0 | نجاح |
| 1 | خطأ غير متوقع (مثلاً لوحة التحكم أعادت 5xx) |
| 2 | خطأ استخدام (حجج غير صحيحة، أمر/علم غير معروف، تصادم اسم) |
| 3 | لا يمكن الوصول إلى لوحة التحكم |
| 4 | لم تسجِّل دخول أو انتهت صلاحية الجلسة؛ شغِّل `agenteye login` |
| 5 | تم المصادقة عليك، لكن حسابك يفتقد الأذن المطلوبة (الرسالة تسميها) |
| 6 | لم يتم العثور على المورد المطلوب (مثلاً معرّف جلسة أو حادثة غير معروف) |

هذه تجعل واجهة سطر الأوامر آمنة للنصوص: يمكن للوكيل البرمجي التفرع على `4` لطلب إعادة المصادقة، أو على `5` لعرض الأذن المفقودة. انظر [وصفات CLI للوكلاء](/ar/agenteye/cli-recipes) لأنماط معالجة رموز الخروج وأشكال مخرجات JSON.
