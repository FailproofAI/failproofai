يقوم مهندسوك بتشغيل OpenAI Codex كل يوم بالفعل. التقاط جلسات Codex يجلب تلك جلسات الكود إلى AgentEye كجلسات وأحداث عادية، لذا يمكنك البحث فيها وإعادة تشغيلها وتقييمها جنباً إلى جنب مع كل ما تراقبه آخر. إنه يكمل [Python SDK](/ar/agenteye/python-sdk): SDK يوفر أدوات للوكلاء الذين تكتبهم، بينما هذا يلتقط عمل Codex الذي يقوم به فريقك بالفعل — بدون أي تغيير في طريقة تشغيله.

قارئ خلفية صغير يقرأ نصوص جلسات Codex المحلية أثناء كتابتها ويرسلها إلى AgentEye. قارئ واحد لكل جهاز يلتقط كل سطح Codex محلي في نفس الوقت — لا توجد عملية إعداد لكل سطح.

نفس القارئ يلتقط وكلاء آخرين أيضاً — انظر [OpenClaw](/ar/agenteye/openclaw-capture) و [Hermes](/ar/agenteye/hermes-capture). فعّل كل واحد تقوم بتشغيله؛ يمكن لقارئ واحد أن يلتقط عدة في نفس الوقت.

---

## ما الذي يتم التقاطه

كل سطح Codex يعمل **محلياً** ينتج نفس نصوص الجلسات على القرص، والقارئ يلتقطها جميعاً:

- **واجهة سطر الأوامر** Codex و `codex exec`
- **ملحق VS Code / IDE**
- **تطبيق سطح المكتب**، عندما يقوم بتشغيل جلسة محلياً

كل جلسة Codex تصبح [جلسة](/ar/agenteye/sessions) AgentEye؛ رسائل المستخدم والمساعد والاستدلال واستدعاءات الأدوات ونتائج الأدوات واستخدام الرموز تصبح [أحداث](/ar/agenteye/event-stream) متطابقة. يتم تسجيل السطح الذي جاءت منه كل جلسة (CLI أو IDE أو سطح المكتب)، حتى تتمكن من التمييز بينها.

> **لا يتم التقاط الجلسات السحابية.** يقوم تطبيق سطح المكتب بشكل متزايد بتشغيل الجلسات في سحابة Codex ويحتفظ فقط بالبيانات الوصفية على الجهاز — لا توجد نصوص محلية للقراءة. يتم التقاط الجلسات المنفذة محلياً فقط.

---

## تشغيله

التقاط مطفأ حتى تقوم بتفعيله. قم بتثبيت القارئ باستخدام مفتاح API لديه صلاحية `events:add` (انظر [مفاتيح API](/ar/agenteye/api-keys))، وفعّل التقاط Codex:

```bash
curl -fsSL https://raw.githubusercontent.com/FailproofAI/agenteye-collector/main/install.sh \
  | sh -s -- --key <YOUR_API_KEY> --codex-enabled
```

يقوم ذلك بتثبيت القارئ وتسجيله كخدمة في الخلفية وبدء الالتقاط. تأكد من أنه يعمل:

```bash
agenteye-collector health
```

عند التشغيل الأول، يتم استكمال الجلسات الموجودة لديك من Codex مرة واحدة والنشاط الجديد ثم يتدفق في غضون ثوانٍ. ملفات Codex الخاصة بها يتم قراءتها فقط — لا تُعدَّل أبداً أو تُنقل أو تُحذف — وتُرسل كل جلسة مرة واحدة بالضبط، حتى عبر إعادة التشغيل.

---

## حيث يظهر

تظهر الجلسات المُلتقطة في **Sessions**، وأحداثها في تدفق **Events**، نفس الطريقة مع أي وكيل آخر تراقبه — لذا [إعادة تشغيل الجلسة](/ar/agenteye/sessions)، [البحث](/ar/agenteye/queries)، [التقييمات](/ar/agenteye/evaluations)، و [التنبيهات](/ar/agenteye/alerts) كلها تعمل عليها. قم بالتصفية حسب وكيل Codex لمشاهدتها بمفردها.

---

## الخصوصية

نصوص Codex تحتوي على الجلسة الكاملة — بما في ذلك مخرجات الأوامر ومحتويات الملفات وأي شيء قراءه أو كتبه Codex — ويمكن أن تحتوي على أسرار. يتم إرسال الجلسات المُلتقطة كما هي، لذا فعّل الالتقاط فقط على الأجهزة والفريقات التي يكون من المناسب فيها توحيد هذا المحتوى في AgentEye، وأعطِ القارئ مفتاحاً محدد النطاق إلى `events:add` فقط. انظر [الأمان](/ar/agenteye/security) لمعرفة كيفية الحفاظ على بيانات معزولة.
