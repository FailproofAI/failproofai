مهندسوك يشغلون OpenAI Codex يومياً بالفعل. التقاط جلسات Codex يجلب جلسات البرمجة تلك إلى AgentEye كجلسات وأحداث عادية، حتى تتمكن من البحث عنها وإعادة تشغيلها وتقييمها بجانب كل شيء آخر تراقبه. يكمل هذا [Python SDK](/ar/agenteye/python-sdk): يقوم SDK بتجهيز الوكلاء الذين تكتبهم، بينما يلتقط هذا عمل Codex الذي يقوم به فريقك بالفعل — دون أي تغيير في طريقة تشغيله.

جامع خلفي صغير يقرأ نصوص جلسات Codex المحلية أثناء كتابتها ويرسلها إلى AgentEye. جامع واحد لكل جهاز يلتقط كل سطح Codex محلي في نفس الوقت — لا توجد إعدادات لكل سطح.

يلتقط الجامع نفسه وكلاء آخرين أيضاً — راجع [OpenClaw](/ar/agenteye/openclaw-capture) و [Hermes](/ar/agenteye/hermes-capture). فعّل كل واحد منها تشغله؛ يمكن لجامع واحد أن يلتقط عدة منها في نفس الوقت.

---

## ما الذي يتم التقاطه

كل سطح Codex يعمل **محلياً** ينتج نفس نصوص الجلسات على القرص، والجامع يلتقط جميعها:

- واجهة سطر أوامر Codex **CLI** و `codex exec`
- **إضافة VS Code / IDE**
- **تطبيق سطح المكتب**، عند تشغيل جلسة محلياً

تصبح كل جلسة Codex [جلسة](/ar/agenteye/sessions) في AgentEye؛ رسائل المستخدم والمساعد والتفكير واستدعاءات الأدوات ونتائج الأدوات واستخدام الرموز تصبح [أحداث](/ar/agenteye/event-stream) متطابقة. يتم تسجيل السطح الذي جاءت منه كل جلسة (CLI أو IDE أو سطح المكتب)، حتى تتمكن من تمييزها.

> **الجلسات السحابية لا يتم التقاطها.** يقوم تطبيق سطح المكتب بشكل متزايد بتشغيل الجلسات في سحابة Codex ويحتفظ فقط بالبيانات الوصفية على الجهاز — لا توجد نصوص محلية للقراءة. يتم التقاط الجلسات المنفذة محلياً فقط.

---

## تشغيله

الالتقاط معطّل حتى تقوم بتفعيله. ثبّت الجامع باستخدام مفتاح API يملك صلاحية `events:add` (راجع [مفاتيح API](/ar/agenteye/api-keys))، وفعّل التقاط Codex:

```bash
curl -fsSL https://raw.githubusercontent.com/FailproofAI/agenteye-collector/main/install.sh \
  | sh -s -- --key <YOUR_API_KEY> --codex-enabled
```

هذا يثبّت الجامع ويسجله كخدمة خلفية ويبدأ الالتقاط. تأكد من أنه يعمل:

```bash
agenteye-collector health
```

عند التشغيل الأول، يتم ملء جلسات Codex الموجودة لديك مرة واحدة ثم تتدفق النشاطات الجديدة خلال ثوان. ملفات Codex الخاصة به تُقرأ فقط — لا تُعدّل أبداً أو تُنقل أو تُحذف — وتُرسل كل جلسة مرة واحدة بالضبط، حتى عبر عمليات إعادة التشغيل.

---

## حيث يظهر

الجلسات المقتنصة تظهر في **Sessions**، وأحداثها في تدفق **Events**، تماماً كما هو الحال مع أي وكيل آخر تراقبه — لذا [إعادة تشغيل الجلسة](/ar/agenteye/sessions) و [البحث](/ar/agenteye/queries) و [التقييمات](/ar/agenteye/evaluations) و [التنبيهات](/ar/agenteye/alerts) تعمل جميعها عليها. صفّ حسب وكيل Codex لرؤيتها بمفردها.

---

## الخصوصية

نصوص Codex تحتوي على الجلسة الكاملة — بما فيها مخرجات الأوامر ومحتويات الملفات وكل شيء قرأه Codex أو كتبه — وقد تحتوي على أسرار. الجلسات المقتنصة يتم شحنها كما هي، لذا فعّل الالتقاط فقط على الأجهزة والفرق حيث يكون من المناسب مركزة ذلك المحتوى في AgentEye، وأعط الجامع مفتاح نطاقه محدود إلى `events:add` فقط. راجع [الأمان](/ar/agenteye/security) لمعرفة كيفية الحفاظ على عزلة بيانات
