يتيح لك OpenTelemetry إرسال تتبعات الوكيل والسجلات والمقاييس إلى FailproofAI Cloud باستخدام بروتوكول OTLP/HTTP القياسي. إنه اختياري. تستمر عمليات التكامل الحالية في FailproofAI في العمل بدون تفعيله.

## احصل على مفتاح

إدخال OTLP مفعل دائماً لكل منظمة؛ لا توجد حاجة لتفعيل أي شيء. استخدم مفتاح Cloud API بصلاحية `events:add`، نفس الصلاحية المستخدمة لإبلاغ الوكيل.

في لوحة التحكم، **الصفحة الرئيسية → إعداد البداية الأولى** تحتوي على بطاقة **الاتصال باستخدام OpenTelemetry**: **إنشاء مفتاح المجمع** ينشئ مفتاح `events:add`، ويعرضه مرة واحدة مع متغيرات المُصدِّر، ويظهر حالة الاتصال. يمكنك أيضاً إنشاء واحد ضمن **الإعدادات → مفاتيح API** بالاختيار **إرسال السجلات فقط** تحت **مفتاح جديد**.

## توصيل وكيل الكود

قم بتوصيل جهازك باستخدام `failproofai config`، ثم اختر وكيل:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

أمر الإعداد يدعم Claude Code و Codex و Copilot ويختار Cloud أو مرحل محلي موثق حسب الحاجة. يستخدم Copilot المرحل المحلي تلقائياً. ابدأ خادم FailproofAI المكون قبل استخدام المرحل.

إذا كان FailproofAI يرسل بالفعل نسخ جلسات الوكيل، يسأل الإعداد ما إذا كنت تريد تبديل هذا الوكيل إلى OTEL. الافتراضي هو لا. قبول هذا يوقف تحميلات نسخ الجلسة لهذا الوكيل؛ لا يغير إنفاذ السياسة أو الإبلاغ من الوكلاء الآخرين.

## توصيل تطبيق

استخدم أداة OpenTelemetry الخاصة بتطبيقك مع متغيرات البيئة هذه:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

نقطة النهاية هي قاعدة OTLP الخاصة بـ Cloud، `https://app.befailproof.ai/otel`؛ المُصدِّر الخاص بك يضيف `/v1/traces` أو `/v1/logs` أو `/v1/metrics` بنفسه. متغيرات محددة لكل إشارة مثل `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` يتم استخدامها كما هي، لذا تحتاج المسار الكامل، على سبيل المثال `https://app.befailproof.ai/otel/v1/logs`.

استبدل `<key>` بمفتاح API الخاص بك. احفظ السر بعيداً عن سجل الأوامر وتسجيلات الشاشة والإعدادات المُدرجة. بالنسبة لجهاز مكون، `failproofai otel env --service my-agent` يطبع الكتلة بمفتاحها الموجود. يحتوي إخراجه على بيانات الاعتماد.

تقبل Cloud تصديرات OTLP/HTTP للتتبعات والسجلات والمقاييس، مثل protobuf أو JSON، بما في ذلك الطلبات المضغوطة بـ gzip. لا تقبل OTLP/gRPC.

يتم الاعتراف بالمقاييس لتوافق المُصدِّر لكن لا يتم تخزينها أو عرضها. تتبعات الوكيل المدعومة وسجلات وكيل الكود تصبح جلسات؛ الحقول التي لا ينشرها الوكيل تبقى غائبة.

## التقط نص الموجه

<Warning>
يمكن لالتقاط النص أن يتضمن الموجهات ووسائط الأداة والمحتوى الحساس الآخر. `failproofai otel enable` يفعله. أضف `--no-content` للحفاظ على التقاط الموجه والتفاصيل الأداة معطلة.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

بالنسبة لوكيل تقوم بتكوينه يدويًا، استخدم عناصر التحكم في التقاط المحتوى الخاصة به:

<Tabs>
  <Tab title="Claude Code">
    أضف هذه المتغيرات إلى بيئة وكيلك بجانب الكتلة التطبيقية أعلاه:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    عيّن كلا متغيري المحتوى إلى `0` لتجنب التقاط الموجهات وتفاصيل الأداة.
  </Tab>
  <Tab title="Codex">
    في إعدادات Codex للمستخدم، استخدم إعدادات OTEL الخاصة به:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    محتوى محادثة Codex موجود في السجلات؛ ترك التتبعات وقياسات وقت التشغيل الداخلي معطلة. يستخدم Codex نقطة النهاية الكاملة التي تقدمها. اضبط `log_user_prompt` على `false` لاستبعاد الموجهات؛ أمر الإعداد يحافظ على `false` صريح.
  </Tab>
  <Tab title="Gemini CLI">
    استخدم إعدادات القياس عن بُعد لـ Gemini مع المرحل المحلي:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI غير مدعوم بـ `failproofai otel enable`. قم بتكوينه يدويًا باستخدام مجمع موثق خاص بك. اضبط `logPrompts` على `false` لعدم التقاط الموجهات.
  </Tab>
  <Tab title="Copilot في VS Code">
    استخدم إعدادات مستخدم VS Code هذه:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    قم بتشغيل `failproofai otel enable copilot` لتفعيل المرحل الموثق. اضبط `captureContent` على `false` لاستبعاد المحتوى.
  </Tab>
</Tabs>

## تحقق أو تراجع عن الإعداد

يحتفظ المرحل بالقياس عن بُعد من خلال أعطال الشبكة والخادم المؤقتة
وإعادة المحاولة بعد التعافي. رفض دائم `400`، بما في ذلك حدث كبير جداً للتخزين، يتطلب تصحيح الحمل. يحتفظ المرحل
بالدفعة المرفوضة للفحص بدلاً من إرسالها بشكل متكرر.

بعد `401` أو `403`، استبدل بيانات الاعتماد بمفتاح يمنح `events:add`
لنفس المنظمة. إعادة الاتصال لا تعيد إرسال تصديرات OTLP المحتفظ بها المرفوضة لبيانات الاعتماد تلقائياً؛ اطلب من المشغل الخاص بك استرجاع تلك الدفعات.
احتفظ بها في منظمتهم الأصلية.

```bash
failproofai otel status
failproofai otel disable all
```

الحالة تميز الإعدادات التي يديرها FailproofAI عن القياس عن بُعد الذي قمت بتكوينه في مكان آخر. تعطيل استعادة الإعدادات المدارة السابقة واختيار تحميل النسخ السابق للوكيل.
