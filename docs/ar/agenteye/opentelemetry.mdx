يتيح لك OpenTelemetry إرسال تتبعات الوكيل والسجلات والمقاييس إلى FailproofAI Cloud باستخدام بروتوكول OTLP/HTTP القياسي. وهو اختياري. تستمر تكاملاتك الحالية مع FailproofAI في العمل دون تفعيله.

## تشغيل الاستقبال لمؤسستك

يقوم مسؤول المؤسسة بفتح **الإعدادات → OpenTelemetry** وتشغيل الاستقبال. استخدم مفتاح API للسحابة بصلاحية `events:add`، وهي نفس الصلاحية المستخدمة لإبلاغ الوكيل.

إذا كان الاستقبال مُيقفًا، فإن السحابة ترفض صادرات OTLP، لذا فإن `failproofai otel enable` لن يغير شيئًا وسيستمر وكيلاؤك في إرسال الجلسات بالطريقة المعتادة. قم بتشغيل `failproofai otel status` للتحقق من مفتاح المؤسسة، واطلب من مسؤول تشغيله.

## توصيل وكيل ترميز

اتصل بجهازك باستخدام `failproofai config`، ثم اختر وكيلاً:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

تدعم أمر الإعداد Claude Code و Codex و Copilot وتختار السحابة أو مرحل محلي مصرح به حسب الحاجة. يستخدم Copilot المرحل المحلي تلقائيًا. ابدأ مراقب FailproofAI المعروف قبل استخدام المرحل.

إذا كان FailproofAI يرسل بالفعل نصوص جلسة الوكيل، فسيطلب الإعداد ما إذا كنت تريد تبديل هذا الوكيل إلى OTEL. القيمة الافتراضية هي لا. تقبل التبديل يوقف تحميلات النص للوكيل؛ وهو لا يغير تطبيق السياسة أو الإبلاغ من الوكلاء الآخرين.

## توصيل تطبيق

استخدم جهاز قياس OpenTelemetry في تطبيقك مع متغيرات البيئة هذه:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

نقطة النهاية هي قاعدة OTLP للسحابة، `https://app.befailproof.ai/otel`؛ يضيف الصادر `/v1/traces` أو `/v1/logs` أو `/v1/metrics` بنفسه. يتم استخدام المتغيرات لكل إشارة مثل `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` كما هي، لذا تحتاج إلى المسار الكامل، على سبيل المثال `https://app.befailproof.ai/otel/v1/logs`.

استبدل `<key>` بمفتاح API الخاص بك. احفظ البيانات الحساسة بعيدًا عن سجل الأوامر وتسجيلات الشاشة والإعدادات المطبقة. بالنسبة للجهاز المعروف، `failproofai otel env --service my-agent` يطبع الكتلة بمفتاحها الموجود. يحتوي الإخراج الخاص به على بيانات اعتماد.

تقبل السحابة صادرات OTLP/HTTP للتتبعات والسجلات والمقاييس، كما protobuf أو JSON، بما في ذلك الطلبات المضغوطة بـ gzip. وهي لا تقبل OTLP/gRPC.

يتم الإقرار بالمقاييس لتوافق الصادر ولكن لا يتم تخزينها أو عرضها. تصبح التتبعات المدعومة للوكيل والسجلات جلسات؛ تبقى الحقول التي لا يصدرها الوكيل غائبة.

## التقاط نص الموجه

<Warning>
يمكن لقبض النص أن يتضمن الموجهات وحجج الأدوات والمحتوى الحساس الآخر. `failproofai otel enable` يشغله. أضف `--no-content` للحفاظ على قبض الموجهات وتفاصيل الأداة معطلة.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

بالنسبة للوكيل الذي تعرّفه يدويًا، استخدم عناصر تحكم قبض المحتوى الخاصة به:

<Tabs>
  <Tab title="Claude Code">
    أضف هذه المتغيرات إلى بيئة الوكيل إلى جانب كتلة التطبيق أعلاه:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    عيّن كلا متغيري المحتوى على `0` لتجنب قبض الموجهات وتفاصيل الأداة.
  </Tab>
  <Tab title="Codex">
    في إعدادات مستخدم Codex، استخدم إعدادات OTEL الخاصة به:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    محتوى محادثة Codex موجود في السجلات؛ اترك التتبعات وقياسات وقت التشغيل الداخلية معطلة. يستخدم Codex نقطة النهاية الكاملة التي توفرها. عيّن `log_user_prompt` على `false` لترك الموجهات؛ يحافظ أمر الإعداد على `false` الصريح.
  </Tab>
  <Tab title="Gemini CLI">
    استخدم إعدادات القياس في Gemini مع المرحل المحلي:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    لا يدعم Gemini CLI `failproofai otel enable`. عرّفه يدويًا بجامع مصرح به من عندك. عيّن `logPrompts` على `false` بدون قبض الموجهات.
  </Tab>
  <Tab title="Copilot في VS Code">
    استخدم إعدادات مستخدم VS Code هذه:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    قم بتشغيل `failproofai otel enable copilot` لتفعيل المرحل المصرح به. عيّن `captureContent` على `false` لحذف المحتوى.
  </Tab>
</Tabs>

## التحقق من الإعداد أو التراجع عنه

يحتفظ المرحل بالقياس عند حدوث أعطال الشبكة والخادم المؤقتة ويعيد المحاولة بعد التعافي. يتطلب رفض دائم `400`، بما في ذلك حدث كبير جدًا للتخزين، تصحيح الحمولة. يحتفظ المرحل بالدفعة المرفوضة للفحص بدلاً من إرسالها بشكل متكرر.

بعد `401` أو `403`، استبدل بيانات الاعتماد بمفتاح يمنح `events:add` لنفس المؤسسة. إعادة الاتصال لا تعيد إرسال صادرات OTLP المحتفظ بها تلقائيًا التي تم رفضها للحصول على بيانات اعتماد؛ اطلب من المشغل استرجاع تلك الدفعات. احتفظ بها في مؤسستك الأصلية.

```bash
failproofai otel status
failproofai otel disable all
```

يميز الحالة الإعدادات التي تدير FailproofAI عن القياس الذي عرّفته في مكان آخر. يستعيد التعطيل الإعدادات المدارة السابقة واختيار تحميل النص السابق للوكيل.
