يتيح لك OpenTelemetry إرسال تتبعات الوكيل والسجلات والمقاييس إلى FailproofAI Cloud باستخدام بروتوكول OTLP/HTTP القياسي. وهو اختياري. تستمر تكاملاتك الحالية مع FailproofAI في العمل دون تفعيله.

## تشغيل الاستقبال لمؤسستك

يفتح مسؤول المؤسسة **Settings → OpenTelemetry** ويشغل الاستقبال. استخدم مفتاح Cloud API بصلاحية `events:add`، وهي نفس الصلاحية المستخدمة لإرسال التقارير من الوكيل.

إذا كان الاستقبال معطلاً، سيرفض Cloud تصديرات OTLP، لذا فإن `failproofai otel enable` لن يغير شيئاً وسيستمر وكيلك في إرسال الجلسات بالطريقة المعتادة. شغّل `failproofai otel status` للتحقق من مفتاح المؤسسة، واطلب من مسؤول تشغيله.

## توصيل وكيل ترميز

اتصل بجهازك باستخدام `failproofai config`، ثم اختر وكيلاً:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

يدعم أمر الإعداد Claude Code وCodex وCopilot ويختار Cloud أو مرحل موثق محلي حسب الاقتضاء. يستخدم Copilot المرحل المحلي تلقائياً. شغّل daemon FailproofAI المعد قبل استخدام المرحل.

إذا كان FailproofAI يرسل بالفعل نسخ جلسات وكيل ما، سيطلب الإعداد ما إذا كنت تريد تبديل هذا الوكيل إلى OTEL. الخيار الافتراضي هو لا. قبول هذا يوقف تحميل النسخ لهذا الوكيل؛ لا يغير إنفاذ السياسة أو الإرسال من وكلاء آخرين.

## توصيل تطبيق

استخدم أداة OpenTelemetry الخاصة بتطبيقك مع متغيرات البيئة هذه:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

نقطة النهاية هي قاعدة OTLP في Cloud، `https://app.befailproof.ai/otel`؛ يضيف المُصدِّر الخاص بك `/v1/traces` أو `/v1/logs` أو `/v1/metrics` بنفسه. تُستخدم متغيرات لكل إشارة مثل `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` كما هي، لذا تحتاج إلى المسار الكامل، على سبيل المثال `https://app.befailproof.ai/otel/v1/logs`.

استبدل `<key>` بمفتاح API الخاص بك. أبقِ السر بعيداً عن سجل shell والتسجيلات الشاشة والتكوينات المرتبطة. بالنسبة لجهاز معد، يطبع `failproofai otel env --service my-agent` الكتلة بمفتاحها الموجود. يحتوي إخراجه على بيانات اعتماد.

يقبل Cloud تصديرات OTLP/HTTP للتتبعات والسجلات والمقاييس، بصيغة protobuf أو JSON، بما في ذلك الطلبات المضغوطة بـ gzip. لا يقبل OTLP/gRPC.

تُقرّ المقاييس لأغراض توافق المُصدِّر لكن لا تُخزّن أو تُعرض. تصبح التتبعات والسجلات المدعومة للوكيل جلسات؛ الحقول التي لا يصدِّرها الوكيل تبقى غائبة.

## حقن نص المطالبة

<Warning>
يمكن أن يتضمن حقن النص المطالبات وحجج الأداة والمحتوى الحساس الآخر. `failproofai otel enable` يشغله. أضف `--no-content` لإيقاف حقن المطالبات وتفاصيل الأداة.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

بالنسبة لوكيل تعده يدويًا، استخدم عناصر تحكم حقن النص الخاصة به:

<Tabs>
  <Tab title="Claude Code">
    أضف هذه المتغيرات إلى بيئة الوكيل الخاص بك جنباً إلى جنب مع الكتلة أعلاه:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    اضبط كلا متغيري المحتوى على `0` لتجنب حقن المطالبات وتفاصيل الأداة.
  </Tab>
  <Tab title="Codex">
    في تكوين مستخدم Codex، استخدم إعدادات OTEL الخاصة به:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    محتوى محادثة Codex موجود في السجلات؛ اترك التتبعات والمقاييس الداخلية معطلة. يستخدم Codex نقطة النهاية الكاملة التي توفرها. اضبط `log_user_prompt` على `false` لحذف المطالبات؛ يحافظ أمر الإعداد على `false` الواضح.
  </Tab>
  <Tab title="Gemini CLI">
    استخدم إعدادات القياس البعيد لـ Gemini مع المرحل المحلي:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI غير مدعوم بواسطة `failproofai otel enable`. عدّله يدويًا باستخدام مجمّع موثق من عندك. اضبط `logPrompts` على `false` لعدم حقن المطالبات.
  </Tab>
  <Tab title="Copilot في VS Code">
    استخدم إعدادات مستخدم VS Code هذه:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    شغّل `failproofai otel enable copilot` لتفعيل المرحل الموثق. اضبط `captureContent` على `false` لحذف المحتوى.
  </Tab>
</Tabs>

## فحص أو التراجع عن الإعداد

```bash
failproofai otel status
failproofai otel disable all
```

يميز الحالة بين الإعدادات التي تديرها FailproofAI والقياس البعيد الذي عدّلته في مكان آخر. التعطيل يستعيد الإعدادات المُدارة السابقة واختيار تحميل النسخ السابق للوكيل.
