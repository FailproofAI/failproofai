يتيح لك OpenTelemetry إرسال تتبعات الوكيل والسجلات والمقاييس إلى FailproofAI Cloud باستخدام بروتوكول OTLP/HTTP القياسي. إنه اختياري. التكاملات FailproofAI الموجودة لديك تستمر في العمل دون تفعيله.

## تفعيل الاستيعاب لمؤسستك

يفتح مسؤول المؤسسة **Settings → OpenTelemetry** ويفعل الاستيعاب. استخدم مفتاح Cloud API بصلاحية `events:add`، نفس الصلاحية المستخدمة لإبلاغ الوكيل.

إذا كان الاستيعاب معطلاً، فإن Cloud يرفض صادرات OTLP، لذلك `failproofai otel enable` لن يغير شيئاً ووكلاؤك سيستمرون في إرسال الجلسات بالطريقة المعتادة. قم بتشغيل `failproofai otel status` للتحقق من مفتاح المؤسسة، واطلب من المسؤول تفعيله.

## توصيل وكيل ترميزي

وصّل جهازك باستخدام `failproofai config`، ثم اختر وكيلاً:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

أمر الإعداد يدعم Claude Code و Codex و Copilot ويختار Cloud أو مرحل محلي موثق حسب الحاجة. يستخدم Copilot المرحل المحلي تلقائياً. ابدأ برنامج FailproofAI daemon المكون قبل استخدام المرحل.

إذا كان FailproofAI يرسل بالفعل نسخ جلسات الوكيل، يسأل الإعداد ما إذا كنت تريد تبديل هذا الوكيل إلى OTEL. الافتراضي هو لا. قبول ذلك يوقف تحميلات النسخة لهذا الوكيل؛ لا يغير فرض السياسة أو الإبلاغ من وكلاء آخرين.

## توصيل تطبيق

استخدم أداة OpenTelemetry الخاصة بتطبيقك مع متغيرات البيئة هذه:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

نقطة النهاية هي قاعدة OTLP الخاصة بـ Cloud، `https://app.befailproof.ai/otel`؛ جهاز التصدير الخاص بك يضيف `/v1/traces` أو `/v1/logs` أو `/v1/metrics` بنفسه. متغيرات لكل إشارة مثل `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` تُستخدم كما هي، لذا تحتاج المسار الكامل، على سبيل المثال `https://app.befailproof.ai/otel/v1/logs`.

استبدل `<key>` بمفتاح API الخاص بك. احفظ السر خارج سجل shell والتسجيلات والتكوين المرتكب. بالنسبة للجهاز المكون، `failproofai otel env --service my-agent` يطبع الكتلة بمفتاحه الموجود. يحتوي الإخراج على بيانات اعتماد.

Cloud يقبل صادرات OTLP/HTTP للتتبعات والسجلات والمقاييس، كـ protobuf أو JSON، بما في ذلك الطلبات المضغوطة بـ gzip. لا يقبل OTLP/gRPC.

يتم الإقرار بالمقاييس لتوافق جهاز التصدير لكن لا يتم تخزينها أو عرضها. تتبعات الوكيل المدعومة وسجلات الوكيل الترميزي تصبح جلسات؛ الحقول التي لا يصدرها الوكيل تبقى غائبة.

## التقاط نص الموجهة

<Warning>
التقاط النص يمكن أن يتضمن الموجهات وحجج الأداة ومحتوى حساس آخر. `failproofai otel enable` يفعله. أضف `--no-content` للاحتفاظ بالتقاط الموجهة وتفاصيل الأداة معطل.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

بالنسبة للوكيل الذي تكونه يدويًا، استخدم عناصر التحكم في التقاط المحتوى الخاصة به:

<Tabs>
  <Tab title="Claude Code">
    أضف هذه المتغيرات إلى بيئة الوكيل جنباً إلى جنب مع كتلة التطبيق أعلاه:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    اضبط كلا متغيري المحتوى على `0` لتجنب التقاط الموجهات وتفاصيل الأداة.
  </Tab>
  <Tab title="Codex">
    في تكوين المستخدم الخاص بـ Codex، استخدم إعدادات OTEL الخاصة به:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    محتوى محادثة Codex موجود في السجلات؛ اترك آثار وقت التشغيل الداخلي والمقاييس معطلة. يستخدم Codex نقطة النهاية الكاملة التي تقدمها. اضبط `log_user_prompt` على `false` لترك الموجهات؛ أمر الإعداد يحافظ على `false` صريح.
  </Tab>
  <Tab title="Gemini CLI">
    استخدم إعدادات الخدمة الداخلية الخاصة بـ Gemini مع المرحل المحلي:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI غير مدعوم بـ `failproofai otel enable`. كونه يدويًا باستخدام مجمع موثق من عندك. اضبط `logPrompts` على `false` لعدم التقاط الموجهات.
  </Tab>
  <Tab title="Copilot in VS Code">
    استخدم هذه إعدادات مستخدم VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    قم بتشغيل `failproofai otel enable copilot` لتفعيل المرحل الموثق. اضبط `captureContent` على `false` لحذف المحتوى.
  </Tab>
</Tabs>

## التحقق أو التراجع عن الإعداد

يحتفظ المرحل بالخدمة الداخلية من خلال أعطال الشبكة والخادم المؤقتة وإعادة المحاولة بعد الاسترجاع. رفض دائم `400`، بما في ذلك حدث كبير جداً للتخزين، يتطلب تصحيح الحمولة. يحتفظ المرحل بالدفعة المرفوضة للفحص بدلاً من إرسالها بشكل متكرر.

بعد `401` أو `403`، استبدل بيانات الاعتماد بمفتاح منح `events:add` لنفس المؤسسة. إعادة الاتصال لا تعيد إرسال صادرات OTLP المحتفظ بها المرفوضة للبيانات الاعتماد تلقائياً؛ اطلب من المشغل الخاص بك استرجاع تلك الدفعات. احتفظ بها في مؤسستها الأصلية.

```bash
failproofai otel status
failproofai otel disable all
```

يميز الحالة الإعدادات المدارة بواسطة FailproofAI من الخدمة الداخلية التي كونتها في مكان آخر. التعطيل يستعيد الإعدادات المدارة السابقة واختيار تحميل النسخة السابق للوكيل.
