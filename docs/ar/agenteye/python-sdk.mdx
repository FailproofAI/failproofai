شاهد بالضبط ما فعلته عملاء الذكاء الاصطناعي الخاصة بك في الإنتاج: كل تشغيل للعميل، استدعاء أداة، طلب نموذج، hook، والتدخل البشري. يسجل Failproof AI Observability Python SDK هذا المسار من داخل كود العميل الخاص بك حتى تتمكن من تصحيح الأخطاء والتدقيق وتقييم ما حدث. استخدمه كلما أردت من Failproof AI Observability مراقبة عملائك.

تحت الغطاء، يكتب SDK الأحداث المنظمة إلى ملفات JSONL محلية، ويلتقطها daemon المجمع ويرسلها إلى المنصة تلقائياً. لا تحتاج إلى إدارة تلك الملفات بنفسك.

## التثبيت

يتم توزيع SDK للعملاء كعجلة خاصة وليس من فهرس حزمة عام. يغطي الإعداد الخاص بك كيفية الحصول عليها وتثبيتها وتثبيتها — تحدث إلى جهة الاتصال الخاصة بك في Failproof AI إذا كنت بحاجة إلى الوصول.

بمجرد التثبيت، تأكد من امتلاكك له:

```bash
python -c "import agenteye; print(agenteye.__version__)"
```

هل تفضل السماح لعميل الترميز بالقيام بالتكامل كله؟ [Python SDK Agent Skill](/ar/agenteye/python-sdk-skill) يعرف مسار التثبيت، ويخطط لنقاط الأجهزة، ويكتبها، ويتحقق من وصول الأحداث.

## البدء السريع

```python
import agenteye

agenteye.configure(environment="production")

agenteye.event.agent_start(session_id="run-001", agent_id="planner", goal="answer user query")

agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    input={"query": "latest AI research"},
)

agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    output={"results": ["..."]},
)

agenteye.event.agent_end(session_id="run-001", agent_id="planner", outcome="success")
```

### أداة استدعاء حقيقية

في الممارسة العملية، تلف الكود الحالي للعميل الخاص بك. ضع قوسين حول استدعاء نموذج مع `model_request` قبل و`model_response` بعد، بحيث تمتد الحدثان على الطلب الحقيقي ويمكن لـ Failproof AI Observability إقرانهما:

```python
import anthropic
import agenteye

agenteye.configure(environment="production")
client = anthropic.Anthropic()

messages = [{"role": "user", "content": "Summarise today's incidents."}]

agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6",
    messages=messages,
)

reply = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=512,
    messages=messages,
)

agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model=reply.model,
    stop_reason=reply.stop_reason,
    input_tokens=reply.usage.input_tokens,
    output_tokens=reply.usage.output_tokens,
    content=[block.model_dump() for block in reply.content],
)
```

لف استدعاءات الأداة بنفس الطريقة مع `tool_use` و`tool_result`، وأعد استخدام `tool_call_id` واحد عبر الزوج.

إليك ما تبدو عليه تلك الأحداث بمجرد وصولها إلى لوحة المعلومات، مع ألوان مشفرة حسب النوع وقابلة للتصفية حسب البيئة والعميل والجلسة:

## configure()

```python
agenteye.configure(
    base_dir=None,           # Path | str | None. Default: $AGENTEYE_HOME or ~/.agenteye
    flush_interval=0.5,      # float, seconds between flush cycles
    environment=None,        # str | None. Deployment environment label
)
```

استدعِ مرة واحدة قبل أي استدعاء `event.*`. آمن للحذف؛ الإعدادات الافتراضية تعمل بسهولة. جميع الحجج بالكلمات الرئيسية فقط؛ مررها بالاسم كما هو موضح أعلاه.

عندما يكون `base_dir` هو `None` (الافتراضي)، يقرأ SDK `$AGENTEYE_HOME` إذا تم تعيينه،
وإلا يعود إلى `~/.agenteye`. هذا يطابق القرار الخاص به من جهة المجمع،
لذا يكفي متغير بيئة `AGENTEYE_HOME` واحد لتكوين مسار الحدث المشترك لكل من
SDK والمجمع.

## البيئة

سمِّ كل حدث ببيئة النشر (`production`، `staging`، `qa`، `canary`، إلخ). عيِّنها مرة واحدة؛ يرفقها SDK بكل حدث تلقائياً.

**الخيار 1: عبر `configure()`:**

```python
agenteye.configure(environment="production")
```

**الخيار 2: عبر متغير البيئة:**

```bash
export AGENTEYE_ENVIRONMENT=production
```

**الأولوية:** `configure(environment=...)` تفوز على متغير البيئة. إذا لم يتم تعيين أي منهما، فسيتم الافتراضي إلى `"dev"`.

تظهر قيمة البيئة كمرشح من الدرجة الأولى في لوحة المعلومات وتُخزن على الخادم للاستعلامات السريعة.

> **تحذير:** قيم البيئة يجب ألا تحتوي على فاصلة `,` حرفية. تستخدم مرشحات لوحة المعلومات الاختيار متعدد المفصول بفواصل على السلك (`?environment=prod,staging`)، لذا ستُقسّم بيئة مسماة `prod,blue` إلى قيمتين. يتم رفض الأحداث ذات البيئات التي تحتوي على فواصل في وقت الاستيعاب.

## البيانات والخصوصية

يسجل SDK فقط الحقول التي تمررها صراحةً. يتم التقاط الأوامر والرسائل والمدخلات والمخرجات والمحتوى النموذجي فقط لأنك تسلمها لاستدعاء `event.*`. لا يتم قراءة أي شيء من عمليتك أو التقاطه ضمناً. أي حقل تتركه لم يتم تعيينه يُحذف من الحدث بالكامل؛ لم يتم كتابته إلى القرص.

هذا يجعل الحذف اختيارك ومسؤوليتك. إذا كان الأمر أو حمل الأداة يحتوي على معلومات تحديد شخصية أو أسرار لا تريد تخزينها، فقم بإزالتها أو تمويهها قبل تمريرها إلى طريقة الحدث.

## مرجع الأحداث

تأتي معظم الأحداث في أزواج بدء/نهاية تشترك في معرّف الارتباط: `tool_use` و`tool_result` يشتركان في `tool_call_id`، `hook_triggered` و`hook_completed` يشتركان في `hook_id`، و`human_wait` و`human_input` يشتركان في `input_id`. أصدر الحدث الأول، قم بالعمل، ثم أصدر الحدث النهائي بنفس المعرّف. يطابق Failproof AI Observability الزوج ويحسب `duration_ms` لك، لذا لا تمرر `duration_ms` بنفسك.

![رسم بياني لتنفيذ نمط git للجلسة بجانب جدول الأحداث الخاص بها، تم إعادة بناؤه من الأحداث المقترنة، مع لوحة انهيار الأداة/النموذج/hook](/agenteye/images/session-detail.png)

تتطلب جميع طرق الأحداث هذين الحقلين:

| الحقل | النوع | الوصف |
|---|---|---|
| `session_id` | `str` | يحدد تشغيل العميل من المستوى الأعلى |
| `agent_id` | `str` | يحدد العميل الذي أصدر الحدث داخل الجلسة |

تقبل جميع الطرق أيضاً `**kwargs` تعسفية لبيانات وصفية مخصصة (انظر [الحقول المخصصة](#custom-fields)).

---

### `event.agent_start()`

يُصدر عندما يبدأ العميل العمل.

```python
agenteye.event.agent_start(
    session_id="run-001",
    agent_id="planner",
    goal="answer user query",   # str | None
    parent_id=None,             # str | None - parent agent_id for nested agents
)
```

---

### `event.agent_end()`

يُصدر عندما ينتهي العميل من العمل.

```python
agenteye.event.agent_end(
    session_id="run-001",
    agent_id="planner",
    outcome="success",          # str | None
    summary="Answered query",   # str | None
)
```

---

### `event.tool_use()`

يُصدر عندما يستدعي العميل أداة. اقرن مع `tool_result`؛ يحسب SDK `duration_ms` تلقائياً.

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",     # str, required
    tool_call_id="toolu_01",    # str, required - correlation key for the matching tool_result
    input={"query": "..."},     # dict | None
)
```

---

### `event.tool_result()`

يُصدر عندما تعود أداة. يرتبط مع `tool_use` عبر `tool_call_id`.

```python
agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",        # must match the prior tool_use
    output={"results": ["..."]},    # Any | None
    error=None,                     # str | None - set if the tool raised
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.model_request()`

يُصدر قبل إرسال أمر إلى نموذج لغة مباشرة.

```python
agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    messages=[                   # list[dict] | None - conversation turns
        {"role": "user", "content": "..."},
    ],
    system="You are helpful.",   # Any | None - str or list of content blocks
    tools=[                      # list[dict] | None - tool schemas offered to the model
        {"name": "search", "input_schema": {"type": "object"}},
    ],
)
```

تقبل إدخالات `messages` إما محتوى نصي عادي `content` أو قائمة كتل محتوى بنمط Anthropic. يمكن تمرير معاملات العينة (`temperature`، `max_tokens`، إلخ) كـ kwargs إضافية.

---

### `event.model_response()`

يُصدر عندما يعود نموذج اللغة برد.

```python
agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    stop_reason="end_turn",     # str | None
    input_tokens=1024,          # int | None
    output_tokens=256,          # int | None
    content=[                    # Any | None - str, or list of content blocks
        {"type": "text", "text": "..."},
    ],
    role="assistant",            # str | None
)
```

يقبل `content` إما نصاً عادياً (موفري عام) أو قائمة بكتل محتوى بنمط Anthropic. تعيش استدعاءات الأداة داخل `content` كـ `{"type": "tool_use", ...}` كتل، بدون حقل `tool_calls` منفصل.

---

### `event.hook_triggered()`

يُصدر عندما تنطلق hook. اقرن مع `hook_completed`؛ يحسب SDK `duration_ms` تلقائياً.

```python
agenteye.event.hook_triggered(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",   # str, required
    hook_id="hook-abc",         # str, required - correlation key
    trigger_event="tool_use",   # str | None
    input={"tool": "search"},   # Any | None
)
```

---

### `event.hook_completed()`

يُصدر عندما تنتهي hook. يرتبط مع `hook_triggered` عبر `hook_id`.

```python
agenteye.event.hook_completed(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",
    hook_id="hook-abc",         # must match the prior hook_triggered
    outcome="allow",            # str | None
    output=None,                # Any | None
    error=None,                 # str | None
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.error()`

يُصدر عندما يحدث خطأ لم يتم التعامل معه.

```python
agenteye.event.error(
    session_id="run-001",
    agent_id="planner",
    error_type="TimeoutError",  # str, required
    message="timed out",        # str, required
    traceback="Traceback...",   # str | None
)
```

## أحداث العنصر البشري في الحلقة

تمنحك أحداث العنصر البشري في الحلقة الإشراف على اللحظات التي يتدخل فيها شخص ما في تنفيذ العميل (في انتظار الموافقة، وتقديم المدخلات، والإيقاف المؤقت، أو إيقاف العميل). تتيح لك قياس المدة التي يستغرقها البشر للرد (يحسب SDK `duration_ms` على الأحداث المقترنة)، والتدقيق في من أوقف أو قاطع عميل، وبناء سير عمل الموافقة والإشراف التي تظهر على لوحة المعلومات.

### `event.human_wait()`

يُصدر عندما يوقف العميل التنفيذ لانتظار إدخال بشري. اقرن مع `human_input`؛ يحسب SDK `duration_ms` (المدة التي استغرقها الإنسان للرد).

```python
agenteye.event.human_wait(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",                          # str, required - correlation key for the matching human_input
    prompt="Do you approve this action?",        # str | None - the question shown to the human
    options=["approve", "reject", "defer"],      # list[str] | None - choices presented to the human
    reason="approval_required",                  # str | None - why the agent is waiting
)
```

### `event.human_input()`

يُصدر عندما يقدم الإنسان إدخالاً ويستأنف العميل. يرتبط مع `human_wait` عبر `input_id`. يتم حساب `duration_ms` تلقائياً ولا يجب أن يمرره المتصل.

```python
agenteye.event.human_input(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",    # str, required - must match the prior human_wait
    response="approve",    # str | None - the human's answer (free text or selected option)
    # duration_ms is computed automatically - do not pass it
)
```

### `event.human_pause()`

يُصدر عندما يوقف الإنسان بنشاط العميل (على سبيل المثال عبر تحكم لوحة المعلومات). تم إيقاف العميل مؤقتاً ولكن لم يتم إنهاؤه.

```python
agenteye.event.human_pause(
    session_id="run-001",
    agent_id="planner",
    reason="user_requested",  # str | None
    user_id="usr_42",         # str | None - who paused the agent
)
```

### `event.human_interrupt()`

يُصدر عندما يوقف الإنسان بنشاط العميل أثناء التنفيذ. على عكس `human_pause`، يتم إنهاء عمل العميل بدلاً من إيقافه المؤقت.

```python
agenteye.event.human_interrupt(
    session_id="run-001",
    agent_id="planner",
    reason="output_incorrect",       # str | None
    user_id="usr_42",                # str | None - who interrupted the agent
    at_step="tool_use:web_search",   # str | None - what the agent was doing when stopped
)
```

## الحقول المخصصة

أي حجج كلمات رئيسية إضافية يتم إلحاقها بالحدث بعد الحقول القياسية:

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="db_query",
    tool_call_id="toolu_02",
    tenant_id="acme",           # custom field
    region="us-east-1",         # custom field
)
```

`timestamp` و`type` و`environment` محفوظة وترفع `ValueError` (`Reserved field names cannot be used as custom fields: [...]`) إذا تم تمريرها كحقول مخصصة. `session_id` و`agent_id` معاملات مطلوبة في كل طريقة حدث ولا يمكن تمريرها مرة ثانية؛ يرفع Python `TypeError` إذا فعلت ذلك. عيّن البيئة مع `configure(environment=...)` (أو متغير `AGENTEYE_ENVIRONMENT`) بدلاً من ذلك.

احتفظ بالحمولات كـ JSON منظمة عندما تريد الاستعلام عن حقولها. القيم التي لا يدعمها JSON بشكل أصلي — مثل التواريخ والمعرّفات الفريدة والعشرية والمجموعات والبايتات وكائنات النموذج — يتم تحويلها إلى سلاسل نصية حتى يستمر التسجيل بأمان.

## كيفية كتابة الأحداث

يتم تخزين الأحداث في العملية وتفريغها إلى القرص كل `flush_interval` ثوان (الافتراضي 500 مللي ثانية). كل تفريغ يكتب ملف JSONL واحد:

```text
~/.agenteye/events/event-2026-04-01T12-00-00-000Z.jsonl
```

يراقب المجمع هذا المجلد ويرفع الملفات تلقائياً. لا تحتاج إلى إدارة هذه الملفات مباشرة.

يتم كتابة كل ملف بشكل ذري: يكتب SDK إلى ملف مؤقت ثم ينقله إلى المكان، لذا لا يرى المجمع أبداً ملف نصفي الكتابة. يتم تشغيل تفريغ نهائي أيضاً عند خروج العملية، لذا لا تُفقد الأحداث المخزنة مؤقتاً في الفترة الأخيرة. إذا كان المجمع غير متصل، تتراكم الأحداث ببساطة كملفات على القرص وتُرسل بمجرد عودته.
