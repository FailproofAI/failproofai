شاهد بالضبط ما فعله وكلاء الذكاء الاصطناعي لديك في الإنتاج: كل تشغيل للوكيل، واستدعاء الأداة، وطلب النموذج، والخطاف، والتدخل البشري. يسجل Python SDK لـ Failproof AI Observability هذا المسار من داخل كود الوكيل الخاص بك حتى تتمكن من تصحيح الأخطاء والتدقيق وتقييم ما حدث. استخدمه كلما أردت أن تراقب Failproof AI Observability وكلاءك.

تحت الغطاء، يكتب SDK الأحداث المنظمة إلى ملفات JSONL محلية، وتقوم العفريت المجمع باستقطاعها وإرسالها إلى المنصة تلقائياً. أنت لا تدير هذه الملفات بنفسك.

> **نصيحة:** جديد في Failproof AI Observability؟ هذه الصفحة هي مرجع أحداث SDK الكامل.

## التثبيت

يتم توزيع SDK للعملاء كعجلة خاصة بدلاً من فهرس حزم عام. يغطي الإعداد الخاص بك كيفية الحصول عليها وتثبيتها وتثبيتها — تحدث مع جهة الاتصال الخاصة بك في Failproof AI إذا كنت تحتاج إلى إمكانية الوصول.

بمجرد تثبيته، تأكد من أنك تمتلكه:

```bash
python -c "import agenteye; print(agenteye.__version__)"
```

تفضل السماح لعامل ترميز بالقيام بالتكامل كله؟ يعرف [Python SDK Agent Skill](/ar/agenteye/python-sdk-skill) مسار التثبيت، ويخطط نقاط الأداة، ويكتبها، ويتحقق من وصول الأحداث.

## البدء السريع

```python
import agenteye

agenteye.configure(environment="production")

agenteye.event.agent_start(session_id="run-001", agent_id="planner", goal="answer user query")

agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    input={"query": "latest AI research"},
)

agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    output={"results": ["..."]},
)

agenteye.event.agent_end(session_id="run-001", agent_id="planner", outcome="success")
```

### أداة استدعاء حقيقية

في الممارسة العملية تقوم بتغليف كود الوكيل الموجود لديك. ضع قوسين حول استدعاء نموذج بـ `model_request` قبل و `model_response` بعد، بحيث يغطي الحدثان الطلب الحقيقي ويمكن لـ Failproof AI Observability إقرانهما:

```python
import anthropic
import agenteye

agenteye.configure(environment="production")
client = anthropic.Anthropic()

messages = [{"role": "user", "content": "Summarise today's incidents."}]

agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6",
    messages=messages,
)

reply = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=512,
    messages=messages,
)

agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model=reply.model,
    stop_reason=reply.stop_reason,
    input_tokens=reply.usage.input_tokens,
    output_tokens=reply.usage.output_tokens,
    content=[block.model_dump() for block in reply.content],
)
```

غلّف استدعاءات الأدوات بنفس الطريقة باستخدام `tool_use` و `tool_result`، وأعد استخدام `tool_call_id` واحد عبر الزوج.

إليك ما تبدو عليه هذه الأحداث بمجرد وصولها إلى لوحة المعلومات، مع ترميز بألوان حسب النوع وقابلة للتصفية حسب البيئة والوكيل والجلسة:

## configure()

```python
agenteye.configure(
    base_dir=None,           # Path | str | None. Default: $AGENTEYE_HOME or ~/.agenteye
    flush_interval=0.5,      # float, seconds between flush cycles
    environment=None,        # str | None. Deployment environment label
)
```

اتصل مرة واحدة قبل أي استدعاء `event.*`. آمن للحذف؛ تعمل الافتراضيات بسهولة. جميع الحجج بالكلمات الرئيسية فقط؛ مررها بالاسم كما هو موضح أعلاه.

عندما يكون `base_dir` `None` (القيمة الافتراضية)، يقرأ SDK `$AGENTEYE_HOME` إذا تم تعيينه،
وإلا يعود إلى `~/.agenteye`. هذا يطابق دقة المجمع الخاصة به،
لذا يقوم متغير `AGENTEYE_HOME` env واحد بتكوين مجمع الأحداث المشترك لكل من
SDK والمجمع.

## البيئة

اجعل كل حدث مع علامة بيئة النشر (`production`، `staging`، `qa`، `canary`، إلخ). اضبطها مرة واحدة؛ سيقوم SDK بإرفاقها بكل حدث تلقائياً.

**الخيار 1: عبر `configure()`:**

```python
agenteye.configure(environment="production")
```

**الخيار 2: عبر متغير بيئة:**

```bash
export AGENTEYE_ENVIRONMENT=production
```

**الأولوية:** `configure(environment=...)` يفوز على متغير البيئة. إذا لم يتم تعيين أي منهما، الافتراضي هو `"dev"`.

تظهر قيمة البيئة كمرشح من الدرجة الأولى في لوحة المعلومات وتُخزن على الخادم للاستعلامات السريعة.

> **تحذير:** قيم البيئة يجب ألا تحتوي على فاصلة حرفية `,`. تستخدم مرشحات لوحة المعلومات التحديد المتعدد المفصول بفواصل على السلك (`?environment=prod,staging`)، لذا فإن البيئة المسماة `prod,blue` ستُقسم إلى قيمتين. يتم رفض الأحداث ذات البيئات التي تحتوي على فواصل عند وقت الاستقبال.

## البيانات والخصوصية

يسجل SDK فقط الحقول التي تمررها بصراحة. تُلتقط الأوامر والرسائل ومدخلات ومخرجات الأدوات والمحتوى النموذجي فقط لأنك تسليمها إلى استدعاء `event.*`. لا يتم قراءة أي شيء من عمليتك أو التقاطه بشكل ضمني. أي حقل تتركه غير مضبوط يُحذف من الحدث تماماً؛ لم يتم كتابته إلى القرص.

هذا يجعل الاستبدال اختيارك ومسؤوليتك. إذا كان الأمر أو حمل الأداة يحتوي على معلومات شخصية أو أسرار لا تريد تخزينها، قم بإزالتها أو إخفاء هويتها قبل تمريرها إلى طريقة الحدث.

## مرجع الحدث

تأتي معظم الأحداث في أزواج بدء/نهاية تشترك في معرف الارتباط: يشترك `tool_use` و `tool_result` في `tool_call_id`، ويشترك `hook_triggered` و `hook_completed` في `hook_id`، ويشترك `human_wait` و `human_input` في `input_id`. اعتمد حدث البداية، افعل العمل، ثم اعتمد حدث النهاية برفقة نفس المعرف. تطابق Failproof AI Observability الزوج وتحسب `duration_ms` لك، لذا لن تمرر `duration_ms` بنفسك.

![رسم بياني للتنفيذ على غرار git للجلسة بجانب الجدول الزمني للأحداث الخاصة بها، تم إعادة بناؤها من الأحداث المقترنة، مع لوحة تفصيل الأداة/النموذج/الخطاف](/agenteye/images/session-detail.png)

تتطلب جميع طرق الأحداث هذين الحقلين:

| الحقل | النوع | الوصف |
|---|---|---|
| `session_id` | `str` | يحدد تشغيل الوكيل من المستوى الأعلى |
| `agent_id` | `str` | يحدد أي وكيل داخل الجلسة انبعث الحدث |

تقبل جميع الطرق أيضاً `**kwargs` تعسفية للبيانات الوصفية المخصصة (انظر [الحقول المخصصة](#custom-fields)).

---

### `event.agent_start()`

يُصدر عندما يبدأ الوكيل العمل.

```python
agenteye.event.agent_start(
    session_id="run-001",
    agent_id="planner",
    goal="answer user query",   # str | None
    parent_id=None,             # str | None - parent agent_id for nested agents
)
```

---

### `event.agent_end()`

يُصدر عندما ينتهي الوكيل من العمل.

```python
agenteye.event.agent_end(
    session_id="run-001",
    agent_id="planner",
    outcome="success",          # str | None
    summary="Answered query",   # str | None
)
```

---

### `event.tool_use()`

يُصدر عندما يستدعي الوكيل أداة. اقرنها مع `tool_result`؛ يحسب SDK `duration_ms` تلقائياً.

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",     # str, required
    tool_call_id="toolu_01",    # str, required - correlation key for the matching tool_result
    input={"query": "..."},     # dict | None
)
```

---

### `event.tool_result()`

يُصدر عندما تُرجع أداة النتيجة. يرتبط مع `tool_use` عبر `tool_call_id`.

```python
agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",        # must match the prior tool_use
    output={"results": ["..."]},    # Any | None
    error=None,                     # str | None - set if the tool raised
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.model_request()`

يُصدر قبل إرسال أمر إلى نموذج لغة كبير.

```python
agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    messages=[                   # list[dict] | None - conversation turns
        {"role": "user", "content": "..."},
    ],
    system="You are helpful.",   # Any | None - str or list of content blocks
    tools=[                      # list[dict] | None - tool schemas offered to the model
        {"name": "search", "input_schema": {"type": "object"}},
    ],
)
```

تقبل مدخلات `messages` إما `content` نص عادي أو محتوى Anthropic على غرار قائمة `content`. يمكن تمرير معاملات العينة (`temperature`، `max_tokens`، إلخ) كـ kwargs إضافية.

---

### `event.model_response()`

يُصدر عندما يُرجع النموذج استجابة.

```python
agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    stop_reason="end_turn",     # str | None
    input_tokens=1024,          # int | None
    output_tokens=256,          # int | None
    content=[                    # Any | None - str, or list of content blocks
        {"type": "text", "text": "..."},
    ],
    role="assistant",            # str | None
)
```

يقبل `content` إما نص عادي (موفروا الخدمات العام) أو قائمة كتل محتوى على غرار Anthropic. تعيش استدعاءات الأدوات داخل `content` كـ `{"type": "tool_use", ...}` كتل، بدون حقل `tool_calls` منفصل.

---

### `event.hook_triggered()`

يُصدر عندما يطلق خطاف. اقرنه مع `hook_completed`؛ يحسب SDK `duration_ms` تلقائياً.

```python
agenteye.event.hook_triggered(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",   # str, required
    hook_id="hook-abc",         # str, required - correlation key
    trigger_event="tool_use",   # str | None
    input={"tool": "search"},   # Any | None
)
```

---

### `event.hook_completed()`

يُصدر عندما ينتهي خطاف. يرتبط مع `hook_triggered` عبر `hook_id`.

```python
agenteye.event.hook_completed(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",
    hook_id="hook-abc",         # must match the prior hook_triggered
    outcome="allow",            # str | None
    output=None,                # Any | None
    error=None,                 # str | None
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.error()`

يُصدر عندما يحدث خطأ غير معالج.

```python
agenteye.event.error(
    session_id="run-001",
    agent_id="planner",
    error_type="TimeoutError",  # str, required
    message="timed out",        # str, required
    traceback="Traceback...",   # str | None
)
```

## أحداث الإنسان في الحلقة

أحداث الإنسان في الحلقة تعطيك إشرافاً على اللحظات التي يتدخل فيها الشخص في تنفيذ الوكيل (انتظار الموافقة، تقديم إدخال، إيقاف مؤقت، أو إيقاف الوكيل). تسمح لك بقياس المدة التي يستغرقها الإنسان للرد (يحسب SDK `duration_ms` تلقائياً على الأحداث المقترنة)، وتدقيق من أوقف أو قاطع وكيلاً، وبناء سير عمل الموافقة والإشراف التي تظهر في لوحة المعلومات.

### `event.human_wait()`

يُصدر عندما يوقف الوكيل التنفيذ انتظاراً لإنسان لتقديم إدخال. اقرنه مع `human_input`؛ يحسب SDK `duration_ms` تلقائياً (كم من الوقت استغرق الإنسان للرد).

```python
agenteye.event.human_wait(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",                          # str, required - correlation key for the matching human_input
    prompt="Do you approve this action?",        # str | None - the question shown to the human
    options=["approve", "reject", "defer"],      # list[str] | None - choices presented to the human
    reason="approval_required",                  # str | None - why the agent is waiting
)
```

### `event.human_input()`

يُصدر عندما يقدم الإنسان إدخالاً واستئناف الوكيل. يرتبط مع `human_wait` عبر `input_id`. يتم حساب `duration_ms` تلقائياً ويجب عدم تمريره من قبل المتصل.

```python
agenteye.event.human_input(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",    # str, required - must match the prior human_wait
    response="approve",    # str | None - the human's answer (free text or selected option)
    # duration_ms is computed automatically - do not pass it
)
```

### `event.human_pause()`

يُصدر عندما يوقف الإنسان الوكيل بنشاط (على سبيل المثال عبر عنصر تحكم لوحة المعلومات). يتم تعليق الوكيل لكن ليس إنهاؤه.

```python
agenteye.event.human_pause(
    session_id="run-001",
    agent_id="planner",
    reason="user_requested",  # str | None
    user_id="usr_42",         # str | None - who paused the agent
)
```

### `event.human_interrupt()`

يُصدر عندما يوقف الإنسان الوكيل بنشاط أثناء التنفيذ. على عكس `human_pause`، يتم إنهاء عمل الوكيل بدلاً من تعليقه.

```python
agenteye.event.human_interrupt(
    session_id="run-001",
    agent_id="planner",
    reason="output_incorrect",       # str | None
    user_id="usr_42",                # str | None - who interrupted the agent
    at_step="tool_use:web_search",   # str | None - what the agent was doing when stopped
)
```

## الحقول المخصصة

أي حجج كلمات رئيسية إضافية تُُلحق بالحدث بعد الحقول القياسية:

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="db_query",
    tool_call_id="toolu_02",
    tenant_id="acme",           # custom field
    region="us-east-1",         # custom field
)
```

يتم حجز `timestamp` و `type` و `environment` وتطرح `ValueError` (`Reserved field names cannot be used as custom fields: [...]`) إذا تم تمريرها كحقول مخصصة. `session_id` و `agent_id` معاملات مطلوبة في كل طريقة حدث ولا يمكن توريدها مرة ثانية؛ يطرح Python `TypeError` إذا فعلت ذلك. اضبط البيئة بـ `configure(environment=...)` (أو متغير `AGENTEYE_ENVIRONMENT`) بدلاً من ذلك.

احفظ الحمولات كـ JSON منظم عندما تريد الاستعلام عن حقولها. يتم تحويل القيم التي لا يدعمها JSON بشكل أصلي — مثل التواريخ والمعرّفات الفريدة والعشرية والمجموعات والبايتات أو كائنات النموذج — إلى سلاسل حتى يستمر التسجيل بأمان.

## كيفية كتابة الأحداث

يتم مؤقتاً الأحداث داخل العملية وتفريغها إلى القرص كل `flush_interval` ثانية (الافتراضي 500 مللي ثانية). يكتب كل تفريغ ملف JSONL واحد:

```text
~/.agenteye/events/event-2026-04-01T12-00-00-000Z.jsonl
```

يراقب المجمع هذا الدليل ويحمل الملفات تلقائياً. لا تحتاج إلى إدارة هذه الملفات مباشرة.

يتم كتابة كل ملف بشكل ذري: يكتب SDK إلى ملف مؤقت ثم يعيد تسميته إلى مكانه، بحيث لا يرى المجمع ملف نصف مكتوب. يعمل تفريغ نهائي أيضاً عند خروج عمليتك، بحيث لا تُفقد الأحداث المؤقتة في الفترة الأخيرة. إذا كان المجمع غير متصل، تتراكم الأحداث ببساطة كملفات على القرص ويتم شحنها بمجرد عودتها للاتصال.
