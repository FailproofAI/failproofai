شاهد بالضبط ما فعلته وكلاء الذكاء الاصطناعي الخاص بك في الإنتاج: كل تشغيل وكيل، واستدعاء أداة، وطلب نموذج، وخطاف، وتدخل بشري. يسجل Failproof AI Observability Python SDK هذا المسار من داخل كود الوكيل الخاص بك حتى تتمكن من تصحيح الأخطاء والتدقيق وتقييم ما حدث. استخدمه كلما أردت أن يراقب Failproof AI Observability وكلاءك.

تحت غطاء المحرك، يكتب SDK أحداثًا منظمة إلى ملفات JSONL محلية، ويلتقطها مصدر جمع البيانات ويرسلها إلى المنصة تلقائيًا. أنت لا تدير هذه الملفات بنفسك.

> **تلميح:** جديد على Failproof AI Observability؟ هذه الصفحة هي مرجع حدث SDK الكامل.

## التثبيت

يتم توزيع SDK للعملاء كمجموعة خاصة بدلاً من فهرس الحزم العام. يغطي الإعداد الخاص بك كيفية الحصول عليه وتثبيته وتثبيت نسخة منه — تحدث إلى جهة اتصالك في Failproof AI إذا كنت بحاجة إلى الوصول.

بمجرد تثبيته، تأكد من أنك تمتلكه:

```bash
python -c "import agenteye; print(agenteye.__version__)"
```

تفضل السماح لوكيل ترميز بإجراء التكامل كله؟ يعرف [مهارة Python SDK Agent](/ar/agenteye/python-sdk-skill) مسار التثبيت، ويخطط لنقاط الأجهزة، ويكتبها، ويتحقق من وصول الأحداث.

## البدء السريع

```python
import agenteye

agenteye.configure(environment="production")

agenteye.event.agent_start(session_id="run-001", agent_id="planner", goal="answer user query")

agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    input={"query": "latest AI research"},
)

agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    output={"results": ["..."]},
)

agenteye.event.agent_end(session_id="run-001", agent_id="planner", outcome="success")
```

### أداة استدعاء حقيقية

في الواقع العملي، تقوم بتغليف كود الوكيل الموجود. ضع استدعاء نموذج بين `model_request` قبل و `model_response` بعده، بحيث يمتد الحدثان على الطلب الفعلي ويمكن لـ Failproof AI Observability أن يقرنهما:

```python
import anthropic
import agenteye

agenteye.configure(environment="production")
client = anthropic.Anthropic()

messages = [{"role": "user", "content": "Summarise today's incidents."}]

agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6",
    messages=messages,
)

reply = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=512,
    messages=messages,
)

agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model=reply.model,
    stop_reason=reply.stop_reason,
    input_tokens=reply.usage.input_tokens,
    output_tokens=reply.usage.output_tokens,
    content=[block.model_dump() for block in reply.content],
)
```

غلّف استدعاءات الأدوات بنفس الطريقة مع `tool_use` و `tool_result`، وأعد استخدام `tool_call_id` واحدة عبر الزوج.

إليك ما تبدو عليه هذه الأحداث بمجرد وصولها إلى لوحة المعلومات، مرمزة بألوان حسب النوع وقابلة للتصفية حسب البيئة والوكيل والجلسة:

## configure()

```python
agenteye.configure(
    base_dir=None,           # Path | str | None. Default: $AGENTEYE_HOME or ~/.agenteye
    flush_interval=0.5,      # float, seconds between flush cycles
    environment=None,        # str | None. Deployment environment label
)
```

اتصل مرة واحدة قبل أي استدعاء `event.*`. آمن للحذف؛ القيم الافتراضية تعمل مباشرة. جميع الحجج هي أسماء مفتاحية فقط؛ مررها بالاسم كما هو موضح أعلاه.

عندما يكون `base_dir` قيمته `None` (الافتراضي)، يقرأ SDK `$AGENTEYE_HOME` إذا تم تعيينه،
وإلا يعود إلى `~/.agenteye`. هذا يطابق دقة جامع البيانات الخاص به،
لذا متغير بيئة `AGENTEYE_HOME` واحد يوازن بين نطاق الحدث المشترك لكلا الـ SDK وجامع البيانات.

## البيئة

قم بتسمية كل حدث ببيئة نشر (`production`، `staging`، `qa`، `canary`، وما إلى ذلك). عيّنها مرة واحدة؛ يرفقها SDK بكل حدث تلقائيًا.

**الخيار 1: عبر `configure()`:**

```python
agenteye.configure(environment="production")
```

**الخيار 2: عبر متغير البيئة:**

```bash
export AGENTEYE_ENVIRONMENT=production
```

**الأولوية:** `configure(environment=...)` تفوز على متغير البيئة. إذا لم يتم تعيين أي منهما، الافتراضي هو `"dev"`.

تظهر قيمة البيئة كمرشح من الدرجة الأولى في لوحة المعلومات وتُخزن على الخادم لاستعلامات سريعة.

> **تحذير:** قيم البيئة يجب ألا تحتوي على فاصلة `,` حرفية. تستخدم مرشحات لوحة المعلومات متعدد التحديد المفصول بفواصل على السلك (`?environment=prod,staging`)، لذا البيئة المسماة `prod,blue` ستنقسم إلى قيمتين. يتم رفض الأحداث ذات البيئات التي تحتوي على فواصل في وقت الاستقبال.

## البيانات والخصوصية

يسجل SDK فقط الحقول التي تمررها بصراحة. يتم التقاط المحادثات والرسائل ومدخلات الأدوات والمخرجات ومحتوى النموذج فقط لأنك تسلمها إلى استدعاء `event.*`. لا يتم قراءة أي شيء من عمليتك ولا يتم التقاطه بشكل ضمني. أي حقل لا تقوم بتعيينه تم حذفه من الحدث بالكامل؛ لم يتم كتابته إلى القرص.

هذا يجعل التصحيح اختيارك ومسؤوليتك. إذا احتوت المحادثة أو حمولة الأداة على معلومات تعريف شخصي أو أسرار لا تود تخزينها، قم بتجريدها أو إخفاؤها قبل تمريرها إلى طريقة الحدث.

## مرجع الأحداث

تأتي معظم الأحداث في أزواج البدء/النهاية التي تشارك معرف الارتباط: `tool_use` و `tool_result` يشاركان `tool_call_id`، `hook_triggered` و `hook_completed` يشاركان `hook_id`، و `human_wait` و `human_input` يشاركان `input_id`. أصدر حدث البدء، وقم بالعمل، ثم أصدر حدث النهاية بنفس المعرف. يطابق Failproof AI Observability الزوج ويحسب `duration_ms` لك، لذا لا تمرر `duration_ms` بنفسك أبدًا.

![رسم بياني لتنفيذ جلسة على طراز git بجانب خط زمني للأحداث، معاد بناؤه من الأحداث المقترنة، مع لوحة تفصيل الأداة/النموذج/الخطاف](/agenteye/images/session-detail.png)

تتطلب جميع طرق الأحداث هذين الحقلين:

| الحقل | النوع | الوصف |
|---|---|---|
| `session_id` | `str` | يحدد تشغيل الوكيل من المستوى الأعلى |
| `agent_id` | `str` | يحدد أي وكيل داخل الجلسة أصدر الحدث |

تقبل جميع الطرق أيضًا `**kwargs` تعسفية لبيانات التعريف المخصصة (انظر [الحقول المخصصة](#custom-fields)).

---

### `event.agent_start()`

الصادر عند بدء الوكيل العمل.

```python
agenteye.event.agent_start(
    session_id="run-001",
    agent_id="planner",
    goal="answer user query",   # str | None
    parent_id=None,             # str | None - parent agent_id for nested agents
)
```

---

### `event.agent_end()`

الصادر عند انتهاء الوكيل من العمل.

```python
agenteye.event.agent_end(
    session_id="run-001",
    agent_id="planner",
    outcome="success",          # str | None
    summary="Answered query",   # str | None
)
```

---

### `event.tool_use()`

الصادر عند استدعاء الوكيل لأداة. اقترن مع `tool_result`؛ يحسب SDK `duration_ms` تلقائيًا.

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",     # str, required
    tool_call_id="toolu_01",    # str, required - correlation key for the matching tool_result
    input={"query": "..."},     # dict | None
)
```

---

### `event.tool_result()`

الصادر عند عودة الأداة. يرتبط مع `tool_use` عبر `tool_call_id`.

```python
agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",        # must match the prior tool_use
    output={"results": ["..."]},    # Any | None
    error=None,                     # str | None - set if the tool raised
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.model_request()`

الصادر قبل إرسال محادثة إلى نموذج لغة كبير مباشرة.

```python
agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    messages=[                   # list[dict] | None - conversation turns
        {"role": "user", "content": "..."},
    ],
    system="You are helpful.",   # Any | None - str or list of content blocks
    tools=[                      # list[dict] | None - tool schemas offered to the model
        {"name": "search", "input_schema": {"type": "object"}},
    ],
)
```

تقبل إدخالات `messages` إما محتوى نصي عادي `content` أو محتوى قائم على Anthropic على شكل قائمة الكتل `content`. يمكن تمرير معاملات أخذ العينات (`temperature`، `max_tokens`، إلخ) كـ kwargs إضافية.

---

### `event.model_response()`

الصادر عند عودة نموذج اللغة الكبير برد.

```python
agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    stop_reason="end_turn",     # str | None
    input_tokens=1024,          # int | None
    output_tokens=256,          # int | None
    content=[                    # Any | None - str, or list of content blocks
        {"type": "text", "text": "..."},
    ],
    role="assistant",            # str | None
)
```

يقبل `content` إما نصًا عاديًا (الموفرون العامون) أو قائمة كتل محتوى على طراز Anthropic. تعيش استدعاءات الأدوات داخل `content` كـ `{"type": "tool_use", ...}` كتل، بدون حقل `tool_calls` منفصل.

---

### `event.hook_triggered()`

الصادر عند تفعيل خطاف. اقترن مع `hook_completed`؛ يحسب SDK `duration_ms` تلقائيًا.

```python
agenteye.event.hook_triggered(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",   # str, required
    hook_id="hook-abc",         # str, required - correlation key
    trigger_event="tool_use",   # str | None
    input={"tool": "search"},   # Any | None
)
```

---

### `event.hook_completed()`

الصادر عند انتهاء الخطاف. يرتبط مع `hook_triggered` عبر `hook_id`.

```python
agenteye.event.hook_completed(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",
    hook_id="hook-abc",         # must match the prior hook_triggered
    outcome="allow",            # str | None
    output=None,                # Any | None
    error=None,                 # str | None
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.error()`

الصادر عند حدوث خطأ غير معالج.

```python
agenteye.event.error(
    session_id="run-001",
    agent_id="planner",
    error_type="TimeoutError",  # str, required
    message="timed out",        # str, required
    traceback="Traceback...",   # str | None
)
```

## أحداث التفاعل البشري

توفر أحداث التفاعل البشري إشرافًا على اللحظات التي يتدخل فيها شخص في تنفيذ الوكيل (انتظار الموافقة، تقديم المدخلات، إيقاف الوكيل مؤقتًا، أو إيقاف الوكيل). تسمح لك بقياس المدة التي يستغرقها البشر للرد (يحسب SDK `duration_ms` تلقائيًا على الأحداث المقترنة)، والتدقيق في من أيقف أو أعاق الوكيل، وبناء سير عمل الموافقة والإشراف التي تظهر في لوحة المعلومات.

### `event.human_wait()`

الصادر عند إيقاف الوكيل التنفيذ انتظارًا لتقديم مدخلات بشرية. اقترن مع `human_input`؛ يحسب SDK `duration_ms` تلقائيًا (المدة التي استغرقها البشر للرد).

```python
agenteye.event.human_wait(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",                          # str, required - correlation key for the matching human_input
    prompt="Do you approve this action?",        # str | None - the question shown to the human
    options=["approve", "reject", "defer"],      # list[str] | None - choices presented to the human
    reason="approval_required",                  # str | None - why the agent is waiting
)
```

### `event.human_input()`

الصادر عند تقديم مدخلات بشرية واستئناف الوكيل. يرتبط مع `human_wait` عبر `input_id`. يتم حساب `duration_ms` تلقائيًا ولا يجب أن يمرره المستدعي.

```python
agenteye.event.human_input(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",    # str, required - must match the prior human_wait
    response="approve",    # str | None - the human's answer (free text or selected option)
    # duration_ms is computed automatically - do not pass it
)
```

### `event.human_pause()`

الصادر عند إيقاف مشغل بشري للوكيل مؤقتًا بنشاط (على سبيل المثال عبر عنصر تحكم لوحة المعلومات). يتم إيقاف الوكيل ولكن لم يتم إنهاؤه.

```python
agenteye.event.human_pause(
    session_id="run-001",
    agent_id="planner",
    reason="user_requested",  # str | None
    user_id="usr_42",         # str | None - who paused the agent
)
```

### `event.human_interrupt()`

الصادر عند إيقاف مشغل بشري للوكيل بنشاط أثناء التنفيذ. بخلاف `human_pause`، يتم إنهاء عمل الوكيل بدلاً من إيقافه مؤقتًا.

```python
agenteye.event.human_interrupt(
    session_id="run-001",
    agent_id="planner",
    reason="output_incorrect",       # str | None
    user_id="usr_42",                # str | None - who interrupted the agent
    at_step="tool_use:web_search",   # str | None - what the agent was doing when stopped
)
```

## الحقول المخصصة

يتم إلحاق أي حجج كلمات رئيسية إضافية بالحدث بعد الحقول القياسية:

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="db_query",
    tool_call_id="toolu_02",
    tenant_id="acme",           # custom field
    region="us-east-1",         # custom field
)
```

`timestamp` و `type` و `environment` محفوظة وترفع `ValueError` (`Reserved field names cannot be used as custom fields: [...]`) إذا تم تمريرها كحقول مخصصة. `session_id` و `agent_id` معاملات مطلوبة في كل طريقة حدث ولا يمكن توفيرها مرة ثانية؛ يرفع Python `TypeError` إذا فعلت ذلك. عيّن البيئة مع `configure(environment=...)` (أو متغير `AGENTEYE_ENVIRONMENT`) بدلاً من ذلك.

احتفظ بالحمولات بصيغة JSON منظمة عندما تريد الاستعلام عن حقولها. القيم التي لا يدعمها JSON بشكل أصلي — مثل datetimes وUUIDs والكسور العشرية والمجموعات والبايتات وكائنات النموذج — يتم تحويلها إلى سلاسل نصية بحيث يستمر التسجيل بأمان.

## كيفية كتابة الأحداث

يتم تخزين الأحداث مؤقتًا في العملية وفرغها إلى القرص كل `flush_interval` ثانية (الافتراضي 500 مللي ثانية). يكتب كل فرغ ملف JSONL واحد:

```text
~/.agenteye/events/event-2026-04-01T12-00-00-000Z.jsonl
```

يراقب جامع البيانات هذا الدليل ويرفع الملفات تلقائيًا. لا تحتاج إلى إدارة هذه الملفات بشكل مباشر.

يتم كتابة كل ملف بشكل ذري: يكتب SDK إلى ملف مؤقت ثم يعيد تسميته في مكانه، لذا لا يرى جامع البيانات ملفًا مكتوبًا بشكل جزئي. يعمل فرغ نهائي أيضًا عند خروج عمليتك، لذا لا تُفقد الأحداث المخزنة مؤقتًا في الفترة الأخيرة. إذا كان جامع البيانات في وضع عدم الاتصال، تتراكم الأحداث ببساطة كملفات على القرص وتُرسل بمجرد عودته.
