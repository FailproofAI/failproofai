يخبر سياق الوكيل التدقيقات بما يوجد الوكيل من أجله، وما يجب أن ينتجه، وما يجب ألا يفعله أبداً. يخزن Failproof AI هذا السياق كعقد وكيل واحد لكل وكيل.

ينتمي سياق الوكيل إلى المؤسسة، وليس إلى تدقيق واحد. تكتبه مرة واحدة لكل وكيل، وكل تدقيق مدعوم بنموذج يشمل نطاقه ذلك الوكيل يستخدمه.

## إضافة سياق الوكيل

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **Analyze → audits**، حدد **agents**، واختر معرف الوكيل المبلغ عنه من جلساته.
    2. حدد **add content** أو **edit**.
    3. صف ما يقصد به الوكيل، وما يجب أن ينتجه، وماذا يعني الانتهاء، وعدد مرات تشغيله، وما يجب ألا يفعله أبداً.
    4. احفظ السياق، ثم عد إلى نموذج التدقيق وأكد أن الوكيل المحدد معروض كمغطى.

    ![درج Agents للتدقيق المستخدم لإضافة الغرض والتكرار والمخرجات وشروط الإكمال والسلوك المحظور للوكيل.](/images/dashboard/agent-context.png)

    يمكنك أيضاً إضافة أو تعديل سياق الوكيل من درج **agents** أثناء إنشاء أو تعديل تدقيق. يتم حفظه بشكل مستقل ويكون متاحاً فوراً لكل تدقيق قابل للتطبيق.
  </Tab>
  <Tab title="CLI">
    لا يعرض Cloud CLI أوامر العقد حالياً. استخدم واجهة برمجة التطبيقات العامة بمفتاح يحمل `audits:read` و `audits:write`:

    ```bash
    curl -X POST "https://app.befailproof.ai/v1/audits/contracts" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "agent_id": "nightly-reconciler",
        "enabled": true,
        "body": "# Purpose\nReconcile yesterday's payouts.\n\n## Outputs\nPublish a signed summary.\n\n## Must not\nNever modify ledger entries."
      }'
    ```

    اسرد العقود باستخدام `GET /v1/audits/contracts`؛ استرجع عقد واحد باستخدام `GET /v1/audits/contracts/{id}`. التحديث باستخدام `PUT` هو استبدال كامل ويتطلب `agent_id` و `body`.
  </Tab>
</Tabs>

## كتابة سياق مفيد

احفظ السياق تحت 5000 حرف واجعله قابلاً للاختبار. يحتوي السياق المفيد عادةً على:

- **الغرض:** سبب وجود الوكيل
- **المخرجات:** التحف أو الإجراءات التي يجب أن ينتجها
- **تم الانتهاء عندما:** الشرط الذي يجعل التشغيل ناجحاً
- **التكرار:** عدد مرات أو وقت تشغيله
- **يجب ألا:** الإجراءات والنتائج التي تكون غير مقبولة دائماً

```markdown
---
agent: nightly-reconciler
purpose: Reconcile yesterday's payouts and publish a signed summary.
cadence: Once daily after 02:00 UTC. Never more than once.
---

## Outputs
- A signed reconciliation summary in the finance channel.

## Done when
- Every payout is matched or explicitly flagged.

## Must not
- Modify ledger entries. Report discrepancies instead.
```

يحدد سياق الوكيل السلوك المتوقع؛ فهو لا يستطيع إخبار التحليل بالنتيجة التي يجب الوصول إليها أو تقييد الأدلة التي يفحصها. يتم تدقيق الوكلاء بدون سياق بشكل طبيعي، لكن Failproof AI لا يستطيع الحكم على سلوكهم مقابل النوايا الخاصة بالمؤسسة.

## إيقاف أو تغيير سياق الوكيل

- أيقف سياق الوكيل عندما يجب أن تتجاهل التدقيقات مؤقتاً. الإيقاف قابل للعكس.
- عدّل السياق عندما تتغير مسؤولية الوكيل. ينطبق النص الجديد على التشغيلات المستقبلية.
- تحقق من **last matched** عندما لا يبدو أن الوكيل الذي يعمل يستخدم سياقه. هذا عادةً يعني أن معرف الوكيل الخاص به لا يتطابق مع الاختبارات.
- احذف من خلال واجهة برمجة التطبيقات فقط عندما يجب تدمير النص بشكل دائم. تقدم لوحة التحكم بقصد الإيقاف بدلاً من الحذف.

يخزن كل تشغيل تدقيق لقطة سياق الوكيل المحددة التي استخدمها. التعديل أو الإيقاف أو حذف مورد العقد الحالي لا يعيد كتابة أساس النتائج السابقة.

<Info>
  قراءة العقود تتطلب `audits:read`. إنشاء أو تعديل أو إيقاف أو حذف العقود يتطلب `audits:write`.
</Info>
