استخدم التدقيقات المتكررة لأنماط الفشل التي قد تعود مع تغيير الوكلاء والمطالبات والأدوات والنماذج.

## تغيير الجدول الزمني

<Tabs>
  <Tab title="Dashboard">
    1. انتقل إلى **Analyze → Audits** وافتح التدقيق.
    2. افتح إعداداته وغيّر حالة التفعيل أو الفترة الزمنية أو نقطة التثبيت بتوقيت UTC أو وضع النافذة أو فترة البحث العكسي.
    3. احفظ التدقيق وأكّد وقت التشغيل التالي على بطاقة التدقيق.
    4. استخدم **run now** مرة واحدة بعد تغيير نطاق أو سياق رئيسي.

    ![محرر التدقيق يعرض الدورة وإطار المسح والنطاق وإعدادات التحليل والسياق وقنوات الإخطار.](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    راجع [مرجع `fp audits`](/ar/reference/cloud-cli#audits) للحصول على حدود الجدول الزمني وسلوك النافذة وجميع أوامر التدقيق.
  </Tab>
</Tabs>

اختر الدورة بناءً على سرعة وتكلفة المخاطرة:

| نمط المخاطرة | الدورة الأولية |
| --- | --- |
| إجراء إنتاجي عالي التأثير | يومي |
| انحدار سير العمل أو النموذج | أسبوعي |
| مراجعة الحوكمة أو الوصول | شهري |
| تحقيق إصدار لمرة واحدة | تشغيل مرة واحدة |

وازن بين إطار البحث العكسي والدورة بحيث لا تترك التشغيلات فجوات ولا تفحص بشكل متكرر سكان غير ضروري كبيراً. بعد تغيير الهدف أو السياق للتدقيق، قم بتشغيله يدويًا مرة واحدة قبل الاعتماد على النتيجة المجدولة التالية.

<Note>
  يتم تكوين التدقيقات المجدولة المحلية على الجهاز وتمسح سجل الوكيل المحلي. جداول التدقيق السحابية تعمل على جلسات Cloud. تعامل مع نتائجها وملكيتها بشكل منفصل.
</Note>
