استخدم المراجعات المتكررة لأنماط الفشل التي قد تعود مع تغير الوكلاء والمحفزات والأدوات والنماذج.

## تغيير الجدول الزمني

<Tabs>
  <Tab title="Dashboard">
    1. انتقل إلى **Analyze → Audits** وافتح المراجعة.
    2. افتح إعداداتها وغيّر حالة التفعيل أو الفترة الزمنية أو نقطة الارتساء بتوقيت UTC أو وضع النافذة أو فترة الاسترجاع.
    3. احفظ المراجعة وأكد وقت التشغيل التالي على بطاقة المراجعة.
    4. استخدم **run now** مرة واحدة بعد تغيير كبير في النطاق أو السياق.

    ![محرر المراجعة يعرض التكرار وشباك الكسح والنطاق وإعدادات التحليل والسياق وقنوات الإشعارات.](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    راجع [`fp audits` reference](/ar/reference/cloud-cli#audits) للتعرف على حدود الجدول الزمني وسلوك النافذة وجميع أوامر المراجعة.
  </Tab>
</Tabs>

اختر التكرار بناءً على سرعة وتكلفة المخاطر:

| نمط المخاطر | التكرار الابتدائي |
| --- | --- |
| إجراء الإنتاج عالي التأثير | يومي |
| انحدار سير العمل أو النموذج | أسبوعي |
| مراجعة الحوكمة أو الوصول | شهري |
| تحقيق الإصدار لمرة واحدة | تشغيل لمرة واحدة |

وازن بين نافذة الاسترجاع والتكرار بحيث لا تترك عمليات التشغيل فجوات ولا تعيد فحص عدد سكان كبير بلا داع. بعد تغيير هدف المراجعة أو سياقها، قم بتشغيلها يدويًا مرة واحدة قبل الاعتماد على نتيجة الجدول الزمني التالي.

<Note>
  يتم تكوين المراجعات المجدولة المحلية على الجهاز وتفحص سجل الوكيل المحلي. تعمل جداول المراجعة السحابية على جلسات Cloud. تعامل مع نتائجها والملكية بشكل منفصل.
</Note>
