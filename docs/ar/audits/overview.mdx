اطلع على كيفية انتقال عملية التدقيق من تشغيل مجدول إلى أعطال مدعومة بالأدلة يمكنك إصلاحها.

## فتح عمليات التدقيق

<Tabs>
  <Tab title="لوحة التحكم">
    انتقل إلى **تحليل → عمليات التدقيق**. تعرض الصفحة حالة الجدولة والنتائج المفتوحة والتشغيل الأخير والتشغيل التالي والتكرار وما إذا كانت عملية التدقيق تحتوي على صفحات موجزة أو مرجعية. حدد بطاقة للوصول إلى الإعدادات وسجل التشغيل؛ حدد **عملية تدقيق جديدة** لإنشاء واحدة.

    ![صفحة عمليات التدقيق تعرض عمليات التدقيق المتكررة مع جدولتها والحساسية وحالة التشغيل.](/images/dashboard/audits.png)
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

استخدم عملية التدقيق عندما تحتاج للإجابة على سؤال على مستوى السكان مثل:

- أين يتخلى الوكلاء عن المهام دون تصعيدها؟
- أي أعطال الأدوات تؤدي إلى محاولات إعادة محاولة غير فعالة؟
- هل يقوم الوكلاء بالوصول إلى البيانات خارج مسار العمل المقصود؟
- ما الذي تغير بعد إطلاق نموذج أو موجه أو أداة؟

## مسار الاستجابة لعملية التدقيق

```text
جلسة → عملية تدقيق → نتيجة → مشكلة → سياسة
                         ↘ تنبيه لتكرار
```

يجب أن تسمي النتيجة وضع الفشل وتشير إلى الأدلة. تمتلك المشكلة العلاج. تمنع السياسة نمط إجراء معروف؛ ينكشف التنبيه عن تكرار عندما لا يكون منع أو يحتاج إلى مراقبة.
