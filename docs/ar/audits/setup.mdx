تبدأ جودة التدقيق من نطاقه. الطلب الواسع مثل "ابحث عن المشاكل" ينتج نتائج أقل فائدة من سؤال فشل محدد.

## تكوين التدقيق

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **تحليل → التدقيقات → تدقيق جديد** وأدخل الاسم والوصف.
    2. عيّن التكرار، نافذة الوقت، نطاق الوكيل/البيئة، الأخطاء المتجاهلة، الحساسية، والحد الأقصى للنتائج.
    3. في **الوكلاء**، أضف أو راجع سياق الوكيل، ثم أضف إيجاز المشغل وأي عناوين URL مرجعية HTTPS عامة.
    4. اختر قنوات الإشعارات وحدد **إنشاء تدقيق**. يتم إدراج التشغيل الأول على الفور.

    ![نموذج التدقيق الجديد يحتوي على الاسم والوصف والتكرار والنافذة ونطاق البيئة والوكيل والأخطاء المتجاهلة وإعدادات التحليل والإيجاز وصفحات المرجع وقنوات الإشعارات.](/images/dashboard/audit-new.png)
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    ```bash
    fp audits create checkout-reliability \
      --description "Find checkout failures that agents do not recover from" \
      --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
      --schedule-interval-secs 86400 \
      --window-mode since_last \
      --sensitivity medium \
      --text-file ./checkout-audit-brief.txt \
      --url https://runbooks.example.com/checkout
    ```

    يتم إدراج التشغيل الأول على الفور. أدرج الإيجاز وعناوين URL المرجعية أثناء الإنشاء بحيث يتلقاها التشغيل.

    انظر المرجع الكامل [`fp audits create`](/ar/reference/cloud-cli#audits).
  </Tab>
</Tabs>

<Tip>
  ابدأ بجلسة فاشلة معروفة وعدة جلسات عادية. وهذا يعطي التدقيق مثالاً إيجابياً ومجموعة مقارنة.
</Tip>

<Info>
  يتم تخزين سياق التدقيق كمورد منفصل بحيث لا يؤدي تحرير التدقيق إلى إزالة المادة المرجعية بشكل عرضي.
</Info>
