يأتي failproofai مع 39 سياسة مدمجة تمنع أخطاء الوكيل الشائعة. تُفعّل كل سياسة على نوع حدث محدد واسم أداة معينة. تقبل تسع عشرة سياسة معاملات تسمح لك بضبط سلوكها دون كتابة كود. تفرض خمس سياسات سير عمل خط أنابيب commit → push → PR → CI قبل أن يتوقف Claude.

- **`block-`** — منع الوكيل من المتابعة.
- **`warn-`** — إعطاء الوكيل سياق إضافي حتى يتمكن من التصحيح الذاتي.
- **`sanitize-`** — مسح البيانات الحساسة من مخرجات الأداة قبل أن يراها الوكيل.

### مساحات الأسماء

كل سياسة توجد في فتحة `<namespace>/<name>`. تنتمي السياسات المدمجة إلى
مساحة الاسم **`failproofai/`** — على سبيل المثال، `failproofai/sanitize-jwt`. تمنع مساحة الاسم
التصادمات عند تحميل سياسات مخصصة أو من طرف ثالث بأسماء قصيرة متشابهة.

في إعدادك يمكنك الإشارة إلى سياسة مدمجة باسم قصير أو اسم مؤهل؛ كلا النموذجين يحلان إلى نفس السياسة:

```json
{
  "enabledPolicies": [
    "sanitize-jwt",
    "failproofai/block-rm-rf"
  ]
}
```

إذا كان الاسم لا يحتوي على `/`، يعامله failproofai على أنه ينتمي إلى مساحة الاسم الافتراضية
`failproofai`. الأسماء التي تحتوي بالفعل على `/` (مثل `myorg/foo`,
`custom/my-hook`) تُحتفظ بها كما هي.
- **`require-`** — منع حدث Stop حتى تُستيفي الشروط.

---

<Tip>
كل سياسة تدعم حقل `hint` اختياري في `policyParams`. يُضاف التلميح إلى رسالة deny أو instruct التي يراها Claude، مما يوفر إرشادات قابلة للتنفيذ دون تعديل كود السياسة. يعمل مع السياسات المدمجة والمخصصة والاتفاقية. انظر [Configuration → hint](/ar/configuration#hint-cross-cutting) للتفاصيل.
</Tip>

## أوامر خطرة

منع الوكلاء من تشغيل عمليات يصعب التراجع عنها أو التي قد تضر النظام المضيف.

### `block-sudo`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** ينكر أي أمر `sudo` أو `doas`.

يحجب أمرًا يشغل ملف تنفيذي للامتيازات **في موضع الأمر**. المطابقة هيكلية وليست نصية: يتم تقسيم الأمر إلى قطاعات كما تفعل الصدفة، يتم المشي خلال تعيينات البادئة (`FOO=bar`)، عمليات الإعادة، والمشغلات مع أعلامها (`env`, `nohup`, `timeout`, `xargs`, `sh -c`, …)، ويتم مقارنة ملف التنفيذ الناتج حسب **basename**. لذا فإن `/usr/bin/sudo`, `env sudo`, `timeout 5 sudo`, `"sudo"`, `\sudo` و`bash -c "sudo …"` كلها مرفوضة، و`doas` يُعامل كنفس الإمكانية تحت اسم مختلف.

لأنه يرتكز على موضع الأمر بدلاً من ظهور الكلمة في أي مكان، فإنه **لا** يُفعّل الأوامر التي تذكره فقط — `grep -r sudo /etc`, `cat /etc/sudoers`, `git commit -m "fix sudo handling"`, أو بديل `grep` يحتوي على الكلمة جميعها تعمل بشكل طبيعي.

<Warning>
يوقف المحاولة الواضحة؛ لا يغلق الفئة. وكيل يمكنه تشغيل قذيفة عشوائية يمكنه الوصول إلى الامتيازات بشكل غير مباشر — من خلال متغير (`S=sudo; $S …`)، أنبوب تم فك ترميزه base64، أو سكريبت مغلف على القرص — لأن فحص سلسلة أمر واحدة لا يمكن أن يتابع تلك. تعامل مع هذا كحاجز ضد الأخطاء والامتيازات العفوية، وليس كحد أمان ضد وكيل مصمم. يجب فرض الحد الحقيقي تحت الصدفة.
</Warning>

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | بادئات الأوامر الدقيقة المسموحة. تُطابق كل مدخلة رموز argv المحللة. |

**مثال:**

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    }
  }
}
```

مع هذا الإعداد، يُسمح بـ `sudo systemctl status nginx`، لكن `sudo rm /etc/hosts` مرفوض.

<Note>
تُطابق الأنماط رموز محللة، وليس سلسلة الأمر الخام. هذا يمنع الحرمان من خلال مشغلات الصدفة المُلحقة (على سبيل المثال، `sudo systemctl status x; rm -rf /` لا تطابق `sudo systemctl status *`).
</Note>

### `block-self-pause`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** ينكر `failproofai config --pause`، الذي يعلق الفرض في الجلسة. الإيقاف المؤقت قرار بشري — وكيل قادر على تشغيله يمكنه إيقاف كل سياسة أخرى بأمر واحد.

أضيق من [`block-failproofai-commands`](#block-failproofai-commands) بقصد، وليس مغطى به: تلك السياسة ترتكز على حد أمر، لذا `npx -y failproofai config --pause` لا تطابقها، وكونها واسعة غالبًا ما تُوقف حتى يتمكن الوكلاء من تشغيل `failproofai audit`. `--resume` و`--status` مسموح به — لا أحدهما يزيل الفرض.

يوقف المحاولة المباشرة، ليس الفئة الكاملة: يمكن للوكيل الوصول إلى نفس الحالة من خلال اسم مستعار أو سكريبت مغلف. إغلاقه بالكامل يتطلب أن يكون الإيقاف المؤقت غير قابل للوصول من استدعاء أداة على الإطلاق.

بدون معاملات.

## أوامر البنية التحتية

منع وكلاء الترميز من تشغيل CLIs للبنية التحتية أو تشغيل خطوط أنابيب CI/CD. جميع السياسات في هذه الفئة هي **اختيارية** (`defaultEnabled: false`) — الوكلاء الذين يحتاجون بشكل حقيقي إلى استدعاء `kubectl`، `terraform`، إلخ. لن يتعطلوا ما لم تفعّل السياسة. عند التفعيل، يتم رفض كل استدعاء للـ CLI المطابقة ما لم يطابق الأمر مدخلة في `allowPatterns`.

نحو القواعس النحوي هو نفسه [`block-sudo`](#block-sudo): تُطابق الرموز رموز argv محللة، `*` يكون بدل لرمز واحد، وأي أمر يحتوي على مشغل صدفة مستقل (`&&`, `||`, `|`, `;`) أو رمز به أحرف ميتاشار مدمجة يُرفض قبل مطابقة القائمة المسموحة لمنع حرمان الحقن.

### `block-kubectl`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** ينكر أي استدعاء `kubectl`.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | بادئات أوامر kubectl المسموحة. |

**مثال:**

```json
{
  "policyParams": {
    "block-kubectl": {
      "allowPatterns": ["kubectl get *", "kubectl describe *", "kubectl logs *"]
    }
  }
}
```

مع هذا الإعداد، يُسمح بـ `kubectl get pods` لكن `kubectl apply -f deploy.yaml` مرفوض.

### `block-gh-pipeline`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** ينكر أوامر فرعية `gh` CLI التالية التي تغيّر الحالة أو تشغّل خطوط أنابيب:

- `gh workflow run`, `gh workflow enable`, `gh workflow disable`
- `gh run rerun`, `gh run cancel`
- `gh pr merge`
- `gh release create`, `gh release delete`
- `gh cache delete`
- `gh secret set`, `gh secret delete`

أوامر فرعية `gh` للقراءة فقط مثل `gh pr view`, `gh pr list`, `gh run list`, `gh release view`, و`gh api repos/.../...` **لا** تُطابقها هذه السياسة — تُحتاج بشكل روتيني لفحوصات سير العمل (بما فيها `require-ci-green-before-stop` الخاص بـ failproofai).

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | استدعاءات محددة مكتوبة بشكل برمجي للسماح بها رغم أنها كانت ستُرفض. |

**مثال:**

```json
{
  "policyParams": {
    "block-gh-pipeline": {
      "allowPatterns": ["gh run rerun *"]
    }
  }
}
```

## الأسرار (معقمات)

منع الوكلاء من تسريب بيانات الاعتماد إلى السياق أو المخرجات الخاصة بهم. سياسات المعقّم تُفعّل أحداث **PostToolUse**. عند تشغيل Claude أمر Bash أو قراءة ملف أو استدعاء أي أداة، تفحص هذه السياسات المخرجات قبل إرجاعها إلى Claude. إذا تم اكتشاف نمط سري، تُعيد السياسة قرار deny يمنع المخرجات من تمريرها.

### `sanitize-jwt`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يمسح رموز JWT (ثلاث قطاعات base64url مفصولة بـ `.`).

بدون معاملات.

---

### `sanitize-api-keys`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يمسح تنسيقات مفاتيح API الشائعة: Anthropic (`sk-ant-`), OpenAI (`sk-`), GitHub PATs (`ghp_`), AWS access keys (`AKIA`), Stripe keys (`sk_live_`, `sk_test_`), و Google API keys (`AIza`).

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `additionalPatterns` | `{ regex: string; label: string }[]` | `[]` | أنماط regex إضافية للتعامل معها كأسرار. |

**مثال:**

```json
{
  "policyParams": {
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo internal API key" },
        { "regex": "pat_[0-9a-f]{40}", "label": "Internal PAT" }
      ]
    }
  }
}
```

**الحدث:** PostToolUse (جميع الأدوات)

## البيئة

## الوصول إلى الملفات

الحفاظ على عمل الوكلاء داخل حدود المشروع بعيدًا عن الملفات الحساسة.

### `block-read-outside-cwd`

**الحدث:** PreToolUse (Read, Bash)  
**الافتراضي:** ينكر قراءة الملفات خارج جذر المشروع. الحد هو `CLAUDE_PROJECT_DIR` (تعيينه مرة واحدة في الجلسة بواسطة Claude Code)، مع عودة للمجلد الحالي للجلسة عندما يكون هذا المتغير غير معين. استخدام جذر المشروع بدلاً من `cwd` الحي يعني أن الحد يبقى مستقرًا حتى بعد أن يقوم Claude بـ `cd` إلى مجلد فرعي.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPaths` | `string[]` | `[]` | بادئات مسار مطلقة مسموحة حتى لو كانت خارج جذر المشروع. |

**مثال:**

```json
{
  "policyParams": {
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company/config"]
    }
  }
}
```

---

### `block-secrets-write`

**الحدث:** PreToolUse (Write, Edit)  
**الافتراضي:** ينكر الكتابة إلى الملفات المستخدمة عادة للمفاتيح الخاصة والشهادات: `id_rsa`, `id_ed25519`, `*.key`, `*.pem`, `*.p12`, `*.pfx`.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `additionalPatterns` | `string[]` | `[]` | أنماط اسم ملف إضافية بأسلوب glob للحجب. |

**مثال:**

```json
{
  "policyParams": {
    "block-secrets-write": {
      "additionalPatterns": [".token", ".secret"]
    }
  }
}
```

## Git

منع الدفع العرضي والدفع الجبري وأخطاء الفرع التي يصعب التراجع عنها.

### `block-push-master`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** ينكر `git push origin main` و`git push origin master`.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `protectedBranches` | `string[]` | `["main", "master"]` | أسماء الفروع التي لا يمكن دفعها مباشرة. |

**مثال:**

```json
{
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "master", "release", "prod"]
    }
  }
}
```

## مديري الحزم

فرض أي مديري حزم يُسمح للوكيل باستخدامهم.

### `prefer-package-manager`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** معطّل. عند التفعيل، يحجب أي أمر مدير حزم ليس في قائمة `allowed` ويخبر Claude بإعادة كتابة الأمر باستخدام مدير مسموح.

يكتشف: pip, pip3, python -m pip, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo.

| المعامل | النوع | الافتراضي | الوصف |
|-----------|------|---------|-------------|
| `allowed` | string[] | `[]` | أسماء مديري الحزم المسموح بها. أي مدير مكتشف ليس في هذه القائمة يُحجب. عندما تكون فارغة، السياسة بلا تأثير. |
| `blocked` | string[] | `[]` | أسماء مديري إضافية للحجب خارج القائمة المدمجة (مثل `['pdm', 'pipx']`). |

قائمة الحجب المدمجة تغطي: pip, pip3, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo. استخدم `blocked` لإضافة مديري غير موجودين في هذه القائمة.

**مثال الإعداد:**

```json
{
  "enabledPolicies": ["prefer-package-manager"],
  "policyParams": {
    "prefer-package-manager": {
      "allowed": ["uv", "bun"],
      "blocked": ["pdm", "pipx"]
    }
  }
}
```

مع هذا الإعداد، `pip install flask` و`pdm install flask` كلاهما مرفوض برسالة تخبر Claude باستخدام `uv` أو `bun` بدلاً من ذلك. أوامر مثل `uv pip install flask` مسموحة لأن `uv` في قائمة المسموح وتُفحص أولاً.

## سير العمل

فرض سير عمل انتهاء جلسة منضبط. تُفعّل هذه السياسات حدث **Stop** وترفض الوكيل من الإيقاف حتى تُستيفي كل حالة. تتبع سلسلة اعتماد طبيعية: commit → push → PR → CI. إذا رفضت سياسة، يتم تخطي السياسات اللاحقة في السلسلة (الرفض يختصر).

جميع سياسات سير العمل هي **fail-open**: إذا لم تكن الأداة المطلوبة متاحة (مثل `gh` غير مثبت، لا يوجد git remote)، تسمح السياسة برسالة معلوماتية توضح لماذا تم تخطي الفحص.

### لكل CLI Stop Semantics

فرض Stop يختلف قليلاً عبر ستة CLIs مدعومة لأن كل واحد يفضح عقد "عامل انتهى" مختلفًا. **النتيجة** متساوية — الوكيل لا يفلت من الإيقاف أثناء فشل بوابة سير العمل — لكن **الآليات** تختلف. الجدول أدناه ملخص؛ فقط Pi لديها دقة محسوسة من المستخدم تستحق الفهم قبل تفعيل سياسة `require-*-before-stop`.

| CLI | متى تُفعّل البوابة | ماذا ترى |
|---|---|---|
| Claude Code | نفس حلقة الوكيل، على الفور | يستمر Claude في العمل — يصلح المشكلة، ثم يحاول الانتهاء مجددًا. لا انقطاع مرئي لك. |
| Codex | نفس حلقة الوكيل، على الفور | نفس Claude. |
| GitHub Copilot CLI | نفس حلقة الوكيل، على الفور | نفس Claude (يستخدم قناة إعادة المحاولة `{decision:"block", reason}` الخاصة بـ Copilot — تم التحقق التجريبي ضد Copilot CLI 1.0.41). |
| Cursor Agent | نفس حلقة الوكيل، على الفور | نفس Claude (يستخدم قناة `{followup_message}` الخاصة بـ Cursor — مع حد `loop_limit`، افتراضي 5 إعادات محاولة). |
| OpenCode | نفس حلقة الوكيل، على الفور | نفس Claude (يستخدم استدعاء SDK `client.session.prompt(...)` الخاص بـ OpenCode الموجه عبر `hookSpecificOutput.additionalContext`). |
| **Pi (pi-coding-agent)** | **دور المستخدم التالي** | **يتوقف Pi بشكل مرئي** عندما تُفعّل البوابة — يخرج حلقة الوكيل الخاص به وتُعاد إلى المطالبة. ثم تُفعّل البوابة المرة القادمة التي تُرسل فيها مطالبة: يُضيف failproofai التوجيه `MANDATORY ACTION REQUIRED` إلى موجه النظام لذلك الدور، مما يُرشد LLM لإكمال خطوة سير العمل (commit، push، إلخ) قبل فعل ما طلبته. |

<Note>
**قيد Pi.** لـ Pi `AgentEndEvent` (المعادل الأعلى المستوى لـ Claude's `Stop` hook) لا نوع Result — بحلول الوقت الذي تُفعّل، حلقة وكيل Pi قد خرجت بالفعل. Pi لا يمكنه إجبار إعادة محاولة نفس الحلقة بطريقة Claude / Copilot / Cursor / OpenCode. يُزيح failproofai البوابة إلى حدث `before_agent_start` الخاص بـ Pi (الذي يُفعّل بعد المطالبة التالية للمستخدم) حتى يستمر فرض فحص سير العمل، فقط على الدور التالي بدلاً من الحالي.

**ماذا يعني هذا في الممارسة:**

- بعد توقف Pi، يتم التقاط سبب الرفض في الذاكرة مفتاح بـ Pi session id. المطالبة القادمة جدًا التي تُرسلها في نفس عملية Pi تصفيها: يرى LLM التوجيه `MANDATORY ACTION REQUIRED` في أعلى موجه النظام الخاص به، commits (أو pushes / opens the PR / waits for CI)، وفقط ثم يستمر مع طلبك. سبب الرفض الملتقط هو مرة واحدة — بعد التصفية، البوابة واضحة.
- البوابة محدودة بعمر عملية Pi. إذا قمت بـ `Ctrl+C` Pi أو أغلقت بين الأدوار، يتم إسقاط المدخل في الذاكرة مع العملية وتُفوت البوابة. Claude, Copilot, Cursor, و OpenCode لديهم نفس الحد (اقتل الوكيل والبوابة تُفوت) — Pi فقط يجعله أكثر وضوحًا لأن الوكيل يخرج بشكل مرئي قبل فعل البوابة.
- يتم مسح deny معلق أيضًا على `session_shutdown` لأي سبب (`new` / `resume` / `fork` / `quit`)، لذا لا يمكن لبوابة قديمة من جلسة سابقة أن تتسرب إلى جلسة جديدة بدأت في نفس عملية Pi.

إذا احتجت إلى إعادة محاولة نفس الحلقة على أسلوب Claude، شغّل سياسات `Stop` تحت أي من CLIs الخمسة الأخرى المدعومة. نحن نتتبع Pi upstream لنوع Result مستقبلي على `AgentEndEvent` الذي سيسمح لنا بإغلاق هذه الفجوة.
</Note>

### `require-no-conflicts-before-stop`

**الحدث:** Stop  
**الافتراضي:** ينكر الإيقاف عندما لا يمكن للفرع الحالي دمج نظيف في فرع الأساس. تُؤكد السياسة أولاً أن هناك PR `OPEN` على GitHub للفرع — بدونها، لا توجد هدف دمج للفرض، لذا تختصر السياسة الكاملة للسماح. مرة واحدة PR `OPEN` موكدة، يعمل استكشافان مستقلان:

1. **محلي** — `git merge-tree --write-tree --name-only origin/<baseBranch> HEAD`. عند التضارب، رسالة الرفض تسمي الملفات المتضاربة حتى يعرف Claude بالضبط ماذا يحل.
2. **GitHub** — أعد استخدام نتيجة `gh pr view --json mergeable,state` المجلوبة بالفعل في الفحص المسبق. يمسك التضاربات التي `origin/<baseBranch>` القديمة محليًا ستفوتها (مثل الشخص الذي أنزل PR متضاربة على `main` منذ آخر جلب). نتيجة `CONFLICTING` ترفض. نتيجة `UNKNOWN` أيضًا ترفض وترشد Claude للانتظار ~10 ثوانٍ وإعادة الفحص قبل محاولة الإيقاف مجددًا — هذا يمنع false negatives بينما تعيد GitHub الحساب.

تتخطى بالكامل (تسمح) عند: `gh` ليست مثبتة، لا يوجد PR للفرع، حالة PR ليست `OPEN` (مثل `MERGED`, `CLOSED`)، أو `gh pr view` ترجع مخرجات غير محللة. أيضًا تفشل open عندما `origin/<baseBranch>` مفقود محليًا أو عندما لا توجد commits سابقة الأساس — تلك Layer 1 fall-throughs لا تزال تستشير mergeability المُخزن مؤقتًا قبل السماح.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `baseBranch` | `string` | `"main"` | فرع الأساس للتحقق من التضاربات ضده. |

<Note>
GitHub CLI (`gh`) مطلوب لهذه السياسة. تستخدم السياسة `gh pr view` للتأكيد من
أن PR `OPEN` موجود قبل تشغيل أي مستكشف تضارب — بدون `gh`، تختصر السياسة للسماح. شغّل `gh auth login` بـ personal access token لديه
`repo` scope لقراءة الوصول إلى pull requests.
</Note>

## تعطيل السياسات الفردية

أزل سياسة محددة من `enabledPolicies` في إعدادك، أو بدّلها في علامة Policies في لوحة التحكم.

```json
{
  "enabledPolicies": [
    "block-rm-rf",
    "sanitize-api-keys"
  ]
}
```

السياسات غير المدرجة في `enabledPolicies` لا تعمل، حتى لو كانت مدخلات `policyParams` موجودة لها.
