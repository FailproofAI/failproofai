يأتي failproofai مع 39 سياسة مدمجة تمسك بأنماط فشل الوكيل الشائعة. تعمل كل سياسة على حدث hook محدد واسم أداة محددة. تقبل تسع عشرة سياسة معاملات تتيح لك ضبط سلوكها دون كتابة أي كود. خمس سياسات سير عمل تفرض خط أنابيب commit → push → PR → CI قبل توقف Claude.

## نظرة عامة

يتم تجميع السياسات إلى فئات:

| الفئة | السياسات | نوع Hook |
|----------|----------|-----------|
| [الأوامر الخطرة](#dangerous-commands) | block-sudo, block-rm-rf, block-curl-pipe-sh, block-failproofai-commands, block-self-pause | PreToolUse |
| [أوامر البنية الأساسية](#infra-commands) | block-kubectl, block-terraform, block-aws-cli, block-gcloud, block-az-cli, block-helm, block-gh-pipeline | PreToolUse |
| [الأسرار (معقمات)](#secrets-sanitizers) | sanitize-jwt, sanitize-api-keys, sanitize-connection-strings, sanitize-private-key-content, sanitize-bearer-tokens | PostToolUse |
| [البيئة](#environment) | block-env-files, protect-env-vars | PreToolUse |
| [الوصول إلى الملفات](#file-access) | block-read-outside-cwd, block-secrets-write | PreToolUse |
| [Git](#git) | block-push-master, block-work-on-main, block-force-push, warn-git-amend, warn-git-stash-drop, warn-all-files-staged | PreToolUse |
| [قاعدة البيانات](#database) | warn-destructive-sql, warn-schema-alteration | PreToolUse |
| [التحذيرات](#warnings) | warn-large-file-write, warn-package-publish, warn-background-process, warn-global-package-install | PreToolUse |
| [مديرو الحزم](#package-managers) | prefer-package-manager | PreToolUse |
| [سير العمل](#workflow) | require-commit-before-stop, require-push-before-stop, require-pr-before-stop, require-no-conflicts-before-stop, require-ci-green-before-stop | Stop |

- **`block-`** — إيقاف الوكيل عن المتابعة.
- **`warn-`** — إعطاء الوكيل سياق إضافي حتى يتمكن من التصحيح الذاتي.
- **`sanitize-`** — مسح البيانات الحساسة من مخرجات الأداة قبل أن يراها الوكيل.

### المساحات

تعيش كل سياسة في مساحة `<namespace>/<name>`. السياسات المدمجة تنتمي إلى
مساحة **`failproofai/`** — على سبيل المثال، `failproofai/sanitize-jwt`. تمنع
المساحة التضاربات عند تحميل سياسات مخصصة أو تابعة لجهات خارجية
بأسماء قصيرة متشابهة.

في إعدادك، يمكنك الإشارة إلى سياسة مدمجة باسمها القصير أو اسمها
المؤهل؛ كلا الشكلين يحللان إلى نفس السياسة:

```json
{
  "enabledPolicies": [
    "sanitize-jwt",
    "failproofai/block-rm-rf"
  ]
}
```

إذا لم يكن الاسم يحتوي على `/`، يعامل failproofai اسم المساحة الافتراضية
`failproofai`. الأسماء التي تحتوي بالفعل على `/` (مثل `myorg/foo`,
`custom/my-hook`) تُبقى كما هي.
- **`require-`** — منع حدث التوقف حتى تُستوفى الشروط.

---

<Tip>
كل سياسة تدعم حقل `hint` اختياري في `policyParams`. يتم إلحاق التلميح برسالة deny أو instruct التي يراها Claude، مما يعطي إرشادات قابلة للتنفيذ دون تعديل كود السياسة. يعمل مع السياسات المدمجة والمخصصة والاتفاقية. انظر [التكوين → hint](/ar/configuration#hint-cross-cutting) للتفاصيل.
</Tip>

## الأوامر الخطرة

منع الوكلاء من تشغيل العمليات التي يصعب التراجع عنها أو التي قد تضر نظام المضيف.

### `block-sudo`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** ينكر أي أمر `sudo` أو `doas`.

يحجب أمراً يشغل ملف تنفيذي للترفيع **في موضع الأمر**. المطابقة هيكلية بدلاً من نصية: يتم تقسيم الأمر إلى أجزاء كما يفعل shell، يتم حذف تخصيصات البادئة (`FOO=bar`)، عمليات إعادة التوجيه، والعدّائين مع أعلامهم (`env`, `nohup`, `timeout`, `xargs`, `sh -c`, …)، ويتم مقارنة ملف التنفيذ الناتج بـ **basename**. إذن `/usr/bin/sudo`, `env sudo`, `timeout 5 sudo`, `"sudo"`, `\sudo` و `bash -c "sudo …"` كلها مرفوضة، و `doas` يُعامل كنفس القدرة تحت اسم مختلف.

لأنها تركز على موضع الأمر بدلاً من ظهور الكلمة في أي مكان، فإنها **لا** تعمل على الأوامر التي تذكره فقط — `grep -r sudo /etc`, `cat /etc/sudoers`, `git commit -m "fix sudo handling"`, أو تناوب `grep` يحتوي على الكلمة كلها تعمل بشكل طبيعي.

<Warning>
يوقف هذا المحاولة الواضحة؛ إنه لا يغلق الفئة. الوكيل الذي يمكنه تشغيل shell عشوائي لا يزال يمكنه الوصول إلى الترفيع بشكل غير مباشر — من خلال متغير (`S=sudo; $S …`), أنبوب مفك base64, أو سكريبت wrapper على القرص — لأنه لا يمكن لأي فحص لسلسلة أمر واحد متابعة تلك. عامل هذا كحاجز ضد الأخطاء والترفيع العارض، وليس كحد أمان ضد وكيل مصمم. الحد الحقيقي يجب أن ينفذ أسفل shell.
</Warning>

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | البادئات الدقيقة للأوامر المسموح بها. يتم مطابقة كل إدخال مقابل tokens argv المحللة. |

**مثال:**

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    }
  }
}
```

مع هذا الإعداد، `sudo systemctl status nginx` مسموح به، لكن `sudo rm /etc/hosts` مرفوض.

<Note>
تتم مطابقة الأنماط مقابل tokens المحللة، وليس سلسلة الأمر الخام. يمنع هذا الالتفاف عبر عوامل shell المضافة (مثل `sudo systemctl status x; rm -rf /` لا تطابق `sudo systemctl status *`).
</Note>

### `block-self-pause`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** ينكر `failproofai config --pause`, الذي يعلق الإنفاذ لجلسة. الإيقاف المؤقت هو قرار بشري — وكيل يمكنه تشغيله قد يطفئ كل سياسة أخرى بأمر واحد.

أضيق من [`block-failproofai-commands`](#block-failproofai-commands) عن قصد، وليس مغطى به: هذه السياسة ترتكز على حد أمر، إذن `npx -y failproofai config --pause` لا تطابقها، وكونها واسعة النطاق غالباً ما يتم إيقافها حتى تتمكن الوكلاء من تشغيل `failproofai audit`. `--resume` و `--status` مسموح بهما — لا أحدهما يزيل الإنفاذ.

يوقف هذا المحاولة المباشرة، ليس الفئة الكاملة: الوكيل لا يزال يمكنه الوصول إلى نفس الحالة من خلال alias أو سكريبت wrapper. إغلاقه بالكامل يتطلب أن يكون الإيقاف المؤقت غير قابل للوصول من استدعاء أداة تماماً.

لا معاملات.

## أوامر البنية الأساسية

منع وكلاء الكود من تشغيل CLIs البنية الأساسية أو تشغيل خطوط أنابيب CI/CD. جميع السياسات في هذه الفئة هي **opt-in** (`defaultEnabled: false`) — الوكلاء الذين يحتاجون بشرعية إلى استدعاء `kubectl`, `terraform`, وما إلى ذلك لن يتعطلوا إلا إذا قمت بتفعيل السياسة. عند التفعيل، كل استدعاء للـ CLI المطابق مرفوض إلا إذا كان الأمر يطابق إدخالاً في `allowPatterns`.

نحو القواعس نفسه كـ [`block-sudo`](#block-sudo): يتم مطابقة tokens مقابل argv المحللة، `*` هو wildcard لtoken واحد، وأي أمر يحتوي على عامل shell قائم بذاته (`&&`, `||`, `|`, `;`) أو token مع أحرف metacharacters مضمنة يرفض قبل مطابقة القائمة البيضاء لمنع التجاوزات بالحقن.

### `block-kubectl`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** ينكر أي استدعاء `kubectl`.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | بادئات أوامر kubectl المسموح بها. |

**مثال:**

```json
{
  "policyParams": {
    "block-kubectl": {
      "allowPatterns": ["kubectl get *", "kubectl describe *", "kubectl logs *"]
    }
  }
}
```

مع هذا الإعداد، `kubectl get pods` مسموح به لكن `kubectl apply -f deploy.yaml` مرفوض.

### `block-gh-pipeline`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** ينكر أوامر فرعية CLI `gh` التالية التي تغير الحالة أو تشغل خطوط أنابيب:

- `gh workflow run`, `gh workflow enable`, `gh workflow disable`
- `gh run rerun`, `gh run cancel`
- `gh pr merge`
- `gh release create`, `gh release delete`
- `gh cache delete`
- `gh secret set`, `gh secret delete`

أوامر فرعية `gh` للقراءة فقط مثل `gh pr view`, `gh pr list`, `gh run list`, `gh release view`, و `gh api repos/.../...` **لا** تطابق هذه السياسة — فهي مطلوبة بشكل روتيني لفحوصات سير العمل (بما في ذلك failproofai الخاصة `require-ci-green-before-stop`).

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | استدعاءات معينة مكتوبة بنصوص للسماح بها حتى لو كانت ستُرفض بخلاف ذلك. |

**مثال:**

```json
{
  "policyParams": {
    "block-gh-pipeline": {
      "allowPatterns": ["gh run rerun *"]
    }
  }
}
```

## الأسرار (معقمات)

منع الوكلاء من تسرب بيانات الاعتماد إلى سياقهم أو مخرجاتهم. سياسات المعقم تعمل على أحداث **PostToolUse**. عندما يشغل Claude أمر Bash، يقرأ ملف، أو يستدعي أي أداة، تتفتش هذه السياسات المخرجات قبل أن يتم إرجاعها إلى Claude. إذا تم الكشف عن نمط سري، تعيد السياسة قرار deny يمنع إرسال المخرجات مرة أخرى.

### `sanitize-jwt`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يمسح tokens JWT (ثلاث أجزاء base64url مفصولة بـ `.`).

لا معاملات.

---

### `sanitize-api-keys`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يمسح تنسيقات مفاتيح API الشائعة: Anthropic (`sk-ant-`), OpenAI (`sk-`), GitHub PATs (`ghp_`), مفاتيح وصول AWS (`AKIA`), مفاتيح Stripe (`sk_live_`, `sk_test_`), ومفاتيح Google API (`AIza`).

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `additionalPatterns` | `{ regex: string; label: string }[]` | `[]` | أنماط regex إضافية لمعاملتها كأسرار. |

**مثال:**

```json
{
  "policyParams": {
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "مفتاح API داخلي MyCo" },
        { "regex": "pat_[0-9a-f]{40}", "label": "PAT داخلي" }
      ]
    }
  }
}
```

---

### `sanitize-connection-strings`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يمسح سلاسل اتصال قاعدة البيانات التي تحتوي على بيانات اعتماد مضمنة (مثل `postgresql://user:password@host/db`).

لا معاملات.

---

### `sanitize-private-key-content`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يمسح كتل PEM (`-----BEGIN PRIVATE KEY-----`, `-----BEGIN RSA PRIVATE KEY-----`, إلخ).

لا معاملات.

---

### `sanitize-bearer-tokens`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يمسح رؤوس `Authorization: Bearer <token>` حيث يكون token 20 حرفاً أو أكثر.

لا معاملات.

## البيئة

حماية التكوين البيئي الحساس من الوصول أو التعريض من قبل الوكلاء.

### `block-env-files`

**الحدث:** PreToolUse (Bash, Read)  
**الافتراضي:** ينكر قراءة ملفات `.env` عبر `cat .env`, استدعاءات أداة Read مع `.env` كمسار الملف، إلخ.

لا يحجب `.envrc` أو ملفات البيئة الأخرى - فقط الملفات المسماة بالضبط `.env`.

لا معاملات.

---

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** ينكر الأوامر التي تطبع متغيرات البيئة: `printenv`, `env`, `echo $VAR`.

لا معاملات.

## الوصول إلى الملفات

حافظ على عمل الوكلاء داخل حدود المشروع وبعيداً عن الملفات الحساسة.

### `block-read-outside-cwd`

**الحدث:** PreToolUse (Read, Bash)  
**الافتراضي:** ينكر قراءة الملفات خارج جذر المشروع. الحد هو `CLAUDE_PROJECT_DIR` (مُعيّن مرة واحدة لكل جلسة بواسطة Claude Code)، مع fallback إلى دليل العمل الحالي للجلسة عندما لا يتم تعيين هذا المتغير. باستخدام جذر المشروع بدلاً من `cwd` المباشر يعني أن الحد يبقى مستقراً حتى بعد Claude `cd` في مجلد فرعي.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPaths` | `string[]` | `[]` | بادئات المسارات المطلقة المسموح بها حتى لو كانت خارج جذر المشروع. |

**مثال:**

```json
{
  "policyParams": {
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company/config"]
    }
  }
}
```

---

### `block-secrets-write`

**الحدث:** PreToolUse (Write, Edit)  
**الافتراضي:** ينكر الكتابة إلى الملفات المستخدمة عادة للمفاتيح الخاصة والشهادات: `id_rsa`, `id_ed25519`, `*.key`, `*.pem`, `*.p12`, `*.pfx`.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `additionalPatterns` | `string[]` | `[]` | أنماط اسم ملف إضافية (نمط glob) للحجب. |

**مثال:**

```json
{
  "policyParams": {
    "block-secrets-write": {
      "additionalPatterns": [".token", ".secret"]
    }
  }
}
```

## Git

منع الدفع العارضة، القوة-الدفع، وأخطاء الفرع التي يصعب التراجع عنها.

### `block-push-master`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** ينكر `git push origin main` و `git push origin master`.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `protectedBranches` | `string[]` | `["main", "master"]` | أسماء الفروع التي لا يمكن دفعها مباشرة. |

**مثال:**

```json
{
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "master", "release", "prod"]
    }
  }
}
```

<Tip>
للسماح بالدفع إلى جميع الفروع (بشكل فعلي تعطيل هذه السياسة دون إزالتها من `enabledPolicies`)، اضبط `protectedBranches: []`.
</Tip>

## مديرو الحزم

فرض مديري الحزم المسموح للوكيل باستخدامهم.

### `prefer-package-manager`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** معطل. عند التفعيل، يحجب أي أمر مدير حزم لا يكون في قائمة `allowed` ويخبر Claude لإعادة كتابة الأمر باستخدام مدير مسموح به.

الكشف عن: pip, pip3, python -m pip, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo.

| المعامل | النوع | الافتراضي | الوصف |
|-----------|------|---------|-------------|
| `allowed` | string[] | `[]` | أسماء مديري الحزم المسموح بها. أي مدير مكتشف لا يكون في هذه القائمة يتم حجبه. عندما يكون فارغاً، السياسة لا تفعل شيء. |
| `blocked` | string[] | `[]` | أسماء مديري إضافية لحجبها بعيداً عن القائمة المدمجة (مثل `['pdm', 'pipx']`). |

قائمة الحجب المدمجة تغطي: pip, pip3, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo. استخدم `blocked` لإضافة مديري غير موجودين في هذه القائمة.

**إعداد مثال:**

```json
{
  "enabledPolicies": ["prefer-package-manager"],
  "policyParams": {
    "prefer-package-manager": {
      "allowed": ["uv", "bun"],
      "blocked": ["pdm", "pipx"]
    }
  }
}
```

مع هذا الإعداد، `pip install flask` و `pdm install flask` كلاهما مرفوض برسالة تخبر Claude باستخدام `uv` أو `bun` بدلاً من ذلك. أوامر مثل `uv pip install flask` مسموح بها لأن `uv` في قائمة السماح وتتحقق أولاً.

## سير العمل

فرض سير عمل نهاية جلسة منضبط. تعمل هذه السياسات على حدث **Stop** وترفض الوكيل من التوقف حتى استيفاء كل حالة. تتبع سلسلة اعتماد طبيعية: commit → push → PR → CI. إذا رفضت السياسة، يتم تخطي السياسات اللاحقة في السلسلة (deny يقصر الدائرة).

جميع سياسات سير العمل هي **fail-open**: إذا لم تكن الأداة المطلوبة متاحة (مثل `gh` غير مثبت، لا توجد git remote)، تسمح السياسة برسالة معلوماتية تشرح سبب تخطي الفحص.

### دلالات Stop لكل CLI

إنفاذ التوقف يبدو مختلفاً قليلاً عبر ستة CLIs المدعومة لأن كل واحد يعرض عقد hook نهاية الوكيل المختلفة. **النتيجة** متطابقة — الوكيل لا يتمكن من التوقف بينما بوابة سير العمل تفشل — لكن **الميكانيكا** تختلف. الجدول أدناه يلخص؛ فقط Pi لديها quirk مرئي للمستخدم يستحق الفهم قبل تفعيل سياسة `require-*-before-stop`.

| CLI | عندما تعمل البوابة | ما ستراه |
|---|---|---|
| Claude Code | نفس حلقة الوكيل، على الفور | Claude يستمر في العمل — يصلح المشكلة، ثم يحاول الإنهاء مرة أخرى. لا انقطاع مرئي لك. |
| Codex | نفس حلقة الوكيل، على الفور | نفس Claude. |
| GitHub Copilot CLI | نفس حلقة الوكيل، على الفور | نفس Claude (يستخدم قناة إعادة محاولة Copilot `{decision:"block", reason}` — تم التحقق من تجريبياً ضد Copilot CLI 1.0.41). |
| Cursor Agent | نفس حلقة الوكيل، على الفور | نفس Claude (يستخدم قناة `{followup_message}` Cursor — محدودة بـ `loop_limit`, default 5 إعادة محاولات). |
| OpenCode | نفس حلقة الوكيل، على الفور | نفس Claude (يستخدم استدعاء SDK `client.session.prompt(...)` OpenCode الموجه عبر `hookSpecificOutput.additionalContext`). |
| **Pi (pi-coding-agent)** | **دورة المستخدم التالية** | **Pi يتوقف بشكل مرئي** عندما تعمل البوابة — حلقة الوكيل تخرج والعودة إلى الفور. ثم تعمل البوابة في المرة التالية التي تقدم فيها فوراً: failproofai يسبق مؤشر `MANDATORY ACTION REQUIRED` إلى نظام فوري ذلك الدور، يوجه الـ LLM لإكمال خطوة سير العمل (commit, push, وما إلى ذلك) قبل فعل ما طلبته. |

<Note>
**قيد Pi.** Pi الخاص `AgentEndEvent` (المكافئ البعيدي لـ Claude الخاص `Stop` hook) لا يوجد نوع Result — بواسطة الوقت الذي يعمل، حلقة وكيل Pi قد خرجت بالفعل. Pi لا يمكنها أن تُجبر على إعادة محاولة نفس الحلقة الطريقة التي يمكن Claude / Copilot / Cursor / OpenCode. failproofai يحول البوابة إلى حدث `before_agent_start` Pi (الذي يعمل بعد الفوري التالي) حتى يفرض فحص سير العمل، فقط على الدور التالي بدلاً من الدور الحالي.

**ما يعني هذا عملياً:**

- بعد Pi يتوقف، سبب الرفض يتم القبض عليه في الذاكرة مفتوح بـ Pi معرف الجلسة. الفوري التالي تماماً الذي تقدمه في نفس عملية Pi يسحبها: الـ LLM يرى مؤشر `MANDATORY ACTION REQUIRED` في أعلى فوري نظام ذلك، commits (أو pushes / يفتح PR / ينتظر CI), وفقط ثم يستمر مع طلبك. سبب الرفض المقبوض هو one-shot — مرة سحب، البوابة واضحة.
- البوابة محدودة بحياة عملية Pi. إذا `Ctrl+C` Pi أو قلت بين الدورات، في الذاكرة إدخال يتم إسقاط مع العملية والبوابة يتم تخطيها. Claude, Copilot, Cursor, و OpenCode نفس محدود (قتل الوكيل والبوابة تُخطى) — Pi فقط يجعلها أكثر مرئية لأن الوكيل يخرج بشكل مرئي قبل البوابة تعمل.
- رفض معلق أيضاً يتم مسحها على `session_shutdown` لأي سبب (`new` / `resume` / `fork` / `quit`)، لذا بوابة stale من جلسة سابقة لا يمكن تسرب إلى جلسة جديدة بدأت في نفس عملية Pi.

إذا تحتاج Claude-style same-loop إعادة محاولة، قم بتشغيل سياسات `Stop` تحت أي من الخمسة CLIs المدعومة الأخرى. نحن نتتبع Pi بعيداً لنوع Result مستقبلي على `AgentEndEvent` الذي يسمح لنا بإغلاق هذه الفجوة.
</Note>

### `require-no-conflicts-before-stop`

**الحدث:** Stop  
**الافتراضي:** ينكر التوقف عندما لا يمكن للفرع الحالي الدمج بنظافة في فرع القاعدة. تتحقق السياسة أولاً أن هناك PR `OPEN` على GitHub للفرع — بدونها، لا يوجد هدف دمج لإنفاذها، لذا السياسة بأكملها توقف للسماح. بمجرد تأكيد PRا `OPEN`، يعمل اثنان من التحقيقات المستقلة:

1. **محلي** — `git merge-tree --write-tree --name-only origin/<baseBranch> HEAD`. عند تضارب، رسالة الرفض تسمي الملفات المتضاربة حتى يعرف Claude بالضبط ما يجب إصلاحه.
2. **GitHub** — يعيد استخدام نتيجة `gh pr view --json mergeable,state` المجلوبة بالفعل في المدقق المسبق. يقبض التضاربات التي قد تفتقدها `origin/<baseBranch>` stale محلياً (مثل شخص هبط PR متضارب على `main` منذ آخر جلب). نتيجة `CONFLICTING` ترفض. نتيجة `UNKNOWN` أيضاً ترفض وتوجه Claude للانتظار ~10 ثوان وإعادة الفحص قبل محاولة التوقف مرة أخرى — يمنع هذا false negatives بينما GitHub تحسب.

توقف تماماً (تسمح) عندما: `gh` غير مثبت، لا يوجد PR للفرع، حالة PRا ليست `OPEN` (مثل `MERGED`, `CLOSED`)، أو `gh pr view` ترجع إخراج غير قابل للتحليل. أيضاً تفشل open عندما يفتقد `origin/<baseBranch>` محلياً أو عندما لا توجد التزامات قدمة من القاعدة — تلك توقيفات Layer 1 لا تزال استشارة قابلية دمج PR المخزنة مؤقتاً قبل السماح.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `baseBranch` | `string` | `"main"` | فرع القاعدة للفحص للتضاربات ضده. |

<Note>
GitHub CLI (`gh`) مطلوبة لهذه السياسة. تستخدم السياسة `gh pr view` لتأكيد
يوجد PR `OPEN` قبل تشغيل أي تحقيق تضارب — بدون `gh`، السياسة
توقف للسماح. اجرِ `gh auth login` برمز وصول شخصي له
نطاق `repo` للوصول القراءة إلى pull requests.
</Note>

## تعطيل السياسات الفردية

أزل سياسة محددة من `enabledPolicies` في إعدادك، أو بدّلها في علامة Policies لوحة معلومات.

```json
{
  "enabledPolicies": [
    "block-rm-rf",
    "sanitize-api-keys"

}
```

السياسات غير المدرجة في `enabledPolicies` لا تعمل، حتى لو كانت إدخالات `policyParams` موجودة لها.
