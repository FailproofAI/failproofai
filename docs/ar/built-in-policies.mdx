يأتي failproofai مع 39 سياسة مدمجة تلتقط أنماط فشل الوكيل الشائعة. تطلق كل سياسة على حدث خطاف معين واسم أداة محدد. تقبل تسع عشرة سياسة معاملات تتيح لك ضبط سلوكها دون كتابة أي كود. خمس سياسات للسير العملي تفرض خط أنابيب commit → push → PR → CI قبل أن يتوقف Claude.

## نظرة عامة

يتم تجميع السياسات في فئات:

| الفئة | السياسات | نوع الخطاف |
|----------|----------|-----------|
| [الأوامر الخطرة](#dangerous-commands) | block-sudo, block-rm-rf, block-curl-pipe-sh, block-failproofai-commands, block-self-pause | PreToolUse |
| [أوامر البنية التحتية](#infra-commands) | block-kubectl, block-terraform, block-aws-cli, block-gcloud, block-az-cli, block-helm, block-gh-pipeline | PreToolUse |
| [الأسرار (المنظفات)](#secrets-sanitizers) | sanitize-jwt, sanitize-api-keys, sanitize-connection-strings, sanitize-private-key-content, sanitize-bearer-tokens | PostToolUse |
| [البيئة](#environment) | block-env-files, protect-env-vars | PreToolUse |
| [الوصول للملفات](#file-access) | block-read-outside-cwd, block-secrets-write | PreToolUse |
| [Git](#git) | block-push-master, block-work-on-main, block-force-push, warn-git-amend, warn-git-stash-drop, warn-all-files-staged | PreToolUse |
| [قاعدة البيانات](#database) | warn-destructive-sql, warn-schema-alteration | PreToolUse |
| [التحذيرات](#warnings) | warn-large-file-write, warn-package-publish, warn-background-process, warn-global-package-install | PreToolUse |
| [مديري الحزم](#package-managers) | prefer-package-manager | PreToolUse |
| [السير العملي](#workflow) | require-commit-before-stop, require-push-before-stop, require-pr-before-stop, require-no-conflicts-before-stop, require-ci-green-before-stop | Stop |

- **`block-`** — منع الوكيل من المتابعة.
- **`warn-`** — إعطاء الوكيل سياق إضافي حتى يتمكن من تصحيح نفسه.
- **`sanitize-`** — محو البيانات الحساسة من مخرجات الأداة قبل أن يراها الوكيل.

### مساحات الأسماء

تعيش كل سياسة في فتحة `<namespace>/<name>`. السياسات المدمجة تنتمي إلى
مساحة الأسماء **`failproofai/`** — على سبيل المثال، `failproofai/sanitize-jwt`. تمنع مساحة الأسماء
التضارب عند تحميل سياسات مخصصة أو تابعة لجهات خارجية
بأسماء قصيرة متشابهة.

في إعدادك، يمكنك الإشارة إلى سياسة مدمجة باستخدام اسمها القصير أو
اسمها المؤهل؛ كلا النموذجين يحل نفس السياسة:

```json
{
  "enabledPolicies": [
    "sanitize-jwt",
    "failproofai/block-rm-rf"
  ]
}
```

إذا لم يكن للاسم `/`، يعامله failproofai كمنتمٍ إلى مساحة الأسماء الافتراضية
`failproofai`. الأسماء التي تحتوي بالفعل على `/` (مثل `myorg/foo`,
`custom/my-hook`) تبقى كما هي.
- **`require-`** — منع حدث الإيقاف حتى تتحقق الشروط.

---

<Tip>
كل سياسة تدعم حقل `hint` اختياري في `policyParams`. يتم إضافة التلميح إلى رسالة deny أو instruct التي يراها Claude، مما يوفر إرشادات قابلة للتنفيذ دون تعديل كود السياسة. يعمل مع السياسات المدمجة والمخصصة وسياسات المرجع. انظر [Configuration → hint](/ar/configuration#hint-cross-cutting) للتفاصيل.
</Tip>

## الأوامر الخطرة

منع الوكلاء من تشغيل العمليات التي يصعب التراجع عنها أو التي قد تضر بنظام المضيف.

### `block-sudo`

**الحدث:** PreToolUse (Bash)  
**الإفتراضي:** يرفض أي أمر `sudo` أو `doas`.

يمنع أمرًا يشغل ملف ثنائي للترقية **في موضع الأمر**. المطابقة بنيوية وليست نصية: يتم تقسيم الأمر إلى مقاطع بالطريقة التي تقسمها الغلاف، يتم حذف تعيينات البادئة (`FOO=bar`)، إعادة التوجيه، والعدائين مع أعلامهم (`env`, `nohup`, `timeout`, `xargs`, `sh -c`, …)، ويتم مقارنة الملف الثنائي الناتج ب **اسم الملف**. لذا فإن `/usr/bin/sudo`, `env sudo`, `timeout 5 sudo`, `"sudo"`, `\sudo` و `bash -c "sudo …"` كلها مرفوضة، و `doas` يتم التعامل معه كنفس الإمكانية تحت اسم مختلف.

نظرًا لأنه يرسو على موضع الأمر بدلاً من الكلمة التي تظهر في أي مكان، فإنه **لا** ينطلق على الأوامر التي تذكرها فقط — `grep -r sudo /etc`, `cat /etc/sudoers`, `git commit -m "fix sudo handling"`, أو `grep` التناوب الذي يحتوي على الكلمة كلها تعمل بشكل طبيعي.

<Warning>
هذا يوقف المحاولة الواضحة؛ لا يغلق الفئة. يمكن للوكيل الذي يمكنه تشغيل shell تعسفي الوصول إلى الترقية بشكل غير مباشر — من خلال متغير (`S=sudo; $S …`)، أنبوب مُشفر base64، أو سكريبت wrapper على القرص — لأن فحص سلسلة أمر واحدة لا يمكنه اتباع تلك. تعامل مع هذا كحماية ضد الأخطاء والترقية العرضية، وليس كحد أمان ضد وكيل مصمم. يجب فرض الحد الحقيقي أسفل الغلاف.
</Warning>

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | بادئات الأوامر الدقيقة المسموحة. يتم مطابقة كل إدخال مقابل رموز argv المُحللة. |

**مثال:**

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    }
  }
}
```

مع هذا الإعداد، يُسمح بـ `sudo systemctl status nginx`، لكن `sudo rm /etc/hosts` مرفوض.

<Note>
يتم مطابقة الأنماط مقابل الرموز المُحللة، وليس سلسلة الأمر الخام. هذا يمنع التحايل عن طريق المشغلات المرفقة بـ shell (على سبيل المثال `sudo systemctl status x; rm -rf /` لا تطابق `sudo systemctl status *`).
</Note>

### `block-self-pause`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** يرفض `failproofai config --pause`، الذي يعلق الإنفاذ لجلسة. الإيقاف قرار بشري — يمكن للوكيل القادر على تشغيله إيقاف كل سياسة أخرى بأمر واحد.

أضيق من [`block-failproofai-commands`](#block-failproofai-commands) بقصد، وليس مغطى به: تلك السياسة ترسو على حد الأمر، لذا لا تطابق `npx -y failproofai config --pause`، وكونها واسعة غالبًا ما يتم إيقاف تشغيلها حتى يتمكن الوكلاء من تشغيل `failproofai audit`. يُسمح بـ `--resume` و `--status` — لا يزيل أي منهما الإنفاذ.

هذا يوقف المحاولة المباشرة، وليس الفئة كلها: يمكن للوكيل الوصول إلى نفس الحالة من خلال اسم مستعار أو سكريبت wrapper. يتطلب إغلاقه بالكامل أن يكون الإيقاف غير قابل للوصول من استدعاء أداة على الإطلاق.

لا توجد معاملات.

## أوامر البنية التحتية

منع وكلاء الترميز من تشغيل CLIs البنية التحتية أو تشغيل خطوط أنابيب CI/CD. جميع السياسات في هذه الفئة **اختيارية** (`defaultEnabled: false`) — الوكلاء الذين يحتاجون بشكل حقيقي إلى استدعاء `kubectl`, `terraform`، إلخ. لن يتم الإخلال بهم إلا إذا قمت بتفعيل السياسة. عند التفعيل، يتم رفض كل استدعاء للـ CLI المتطابق إلا إذا كان الأمر يطابق إدخالاً في `allowPatterns`.

قواعد النمط هي نفسها [`block-sudo`](#block-sudo): يتم مطابقة الرموز مقابل argv المُحللة، `*` هو بدل لرمز واحد، وأي أمر يحتوي على مشغل shell مستقل (`&&`, `||`, `|`, `;`) أو رمز يحتوي على أحرف metacharacters مدمجة في shell يتم رفضه قبل مطابقة القائمة البيضاء لمنع تجاوزات الحقن.

### `block-kubectl`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** يرفض أي استدعاء `kubectl`.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | بادئات أوامر kubectl المسموحة. |

**مثال:**

```json
{
  "policyParams": {
    "block-kubectl": {
      "allowPatterns": ["kubectl get *", "kubectl describe *", "kubectl logs *"]
    }
  }
}
```

مع هذا الإعداد، يُسمح بـ `kubectl get pods` لكن يتم رفض `kubectl apply -f deploy.yaml`.

### `block-gh-pipeline`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** يرفض أوامر فرعية `gh` التالية التي تغير الحالة أو تشغل خطوط أنابيب:

- `gh workflow run`, `gh workflow enable`, `gh workflow disable`
- `gh run rerun`, `gh run cancel`
- `gh pr merge`
- `gh release create`, `gh release delete`
- `gh cache delete`
- `gh secret set`, `gh secret delete`

أوامر `gh` الفرعية للقراءة فقط مثل `gh pr view`, `gh pr list`, `gh run list`, `gh release view`, و `gh api repos/.../...` **لا** تطابقها هذه السياسة — فهي مطلوبة بشكل روتيني لفحوصات السير العملي (بما في ذلك `require-ci-green-before-stop` الخاص بـ failproofai).

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | استدعاءات معينة مكتوبة بالسكريبت للسماح بها حتى لو تم رفضها. |

**مثال:**

```json
{
  "policyParams": {
    "block-gh-pipeline": {
      "allowPatterns": ["gh run rerun *"]
    }
  }
}
```

## الأسرار (المنظفات)

منع الوكلاء من تسرب بيانات اعتماد إلى سياقهم أو مخرجاتهم. سياسات المنظفة تطلق على أحداث **PostToolUse**. عندما يشغل Claude أمر Bash، أو يقرأ ملف، أو يستدعي أي أداة، تفحص هذه السياسات المخرجات قبل إرجاعها إلى Claude. إذا تم اكتشاف نمط سري، تعيد السياسة قرار deny يمنع تمرير المخرجات.

### `sanitize-jwt`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يحذف رموز JWT (ثلاث مقاطع base64url مفصولة بـ `.`).

لا توجد معاملات.

---

### `sanitize-api-keys`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يحذف تنسيقات مفاتيح API الشائعة: Anthropic (`sk-ant-`), OpenAI (`sk-`), GitHub PATs (`ghp_`), AWS access keys (`AKIA`), Stripe keys (`sk_live_`, `sk_test_`), و Google API keys (`AIza`).

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `additionalPatterns` | `{ regex: string; label: string }[]` | `[]` | أنماط regex إضافية للتعامل معها كأسرار. |

**مثال:**

```json
{
  "policyParams": {
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo internal API key" },
        { "regex": "pat_[0-9a-f]{40}", "label": "Internal PAT" }
      ]
    }
  }
}
```

---

### `sanitize-connection-strings`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يحذف سلاسل اتصال قاعدة البيانات التي تحتوي على بيانات اعتماد مدمجة (مثل `postgresql://user:password@host/db`).

لا توجد معاملات.

---

### `sanitize-private-key-content`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يحذف كتل PEM (`-----BEGIN PRIVATE KEY-----`, `-----BEGIN RSA PRIVATE KEY-----`، إلخ).

لا توجد معاملات.

---

### `sanitize-bearer-tokens`

**الحدث:** PostToolUse (جميع الأدوات)  
**الافتراضي:** يحذف رؤوس `Authorization: Bearer <token>` حيث الرمز 20 حرفًا أو أكثر.

لا توجد معاملات.

## البيئة

حماية تكوين البيئة الحساسة من أن يقرأه الوكلاء أو يعرضوه.

### `block-env-files`

**الحدث:** PreToolUse (Bash, Read)  
**الافتراضي:** يرفض قراءة ملفات `.env` عبر `cat .env`، استدعاءات أداة Read بـ `.env` كمسار الملف، إلخ.

لا يمنع `.envrc` أو ملفات أخرى مرتبطة بالبيئة - فقط الملفات المسماة بالضبط `.env`.

لا توجد معاملات.

---

### `protect-env-vars`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** يرفض الأوامر التي تطبع متغيرات البيئة: `printenv`, `env`, `echo $VAR`.

لا توجد معاملات.

## الوصول للملفات

إبقاء الوكلاء يعملون داخل حدود المشروع بعيدًا عن الملفات الحساسة.

### `block-read-outside-cwd`

**الحدث:** PreToolUse (Read, Bash)  
**الافتراضي:** يرفض قراءة الملفات خارج جذر المشروع. الحد هو `CLAUDE_PROJECT_DIR` (عيّن مرة واحدة لكل جلسة بواسطة Claude Code)، مع fallback لمجلد العمل الحالي للجلسة عند عدم تعيين هذا المتغير. استخدام جذر المشروع بدلاً من `cwd` المباشر يعني أن الحد يبقى مستقرًا حتى بعد `cd` من Claude إلى مجلد فرعي.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `allowPaths` | `string[]` | `[]` | بادئات المسارات المطلقة المسموحة حتى إذا كانت خارج جذر المشروع. |

**مثال:**

```json
{
  "policyParams": {
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company/config"]
    }
  }
}
```

---

### `block-secrets-write`

**الحدث:** PreToolUse (Write, Edit)  
**الافتراضي:** يرفض الكتابة إلى الملفات المستخدمة عادة للمفاتيح الخاصة والشهادات: `id_rsa`, `id_ed25519`, `*.key`, `*.pem`, `*.p12`, `*.pfx`.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `additionalPatterns` | `string[]` | `[]` | أنماط اسم ملف إضافية (نمط glob) للمنع. |

**مثال:**

```json
{
  "policyParams": {
    "block-secrets-write": {
      "additionalPatterns": [".token", ".secret"]
    }
  }
}
```

## Git

منع الدفع العرضي والدفع القسري وأخطاء الفروع التي يصعب التراجع عنها.

### `block-push-master`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** يرفض `git push origin main` و `git push origin master`.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `protectedBranches` | `string[]` | `["main", "master"]` | أسماء الفروع التي لا يمكن الدفع إليها مباشرة. |

**مثال:**

```json
{
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "master", "release", "prod"]
    }
  }

```

## مديري الحزم

فرض مديري الحزم المسموح للوكيل باستخدامهم.

### `prefer-package-manager`

**الحدث:** PreToolUse (Bash)  
**الافتراضي:** معطّل. عند التفعيل، يمنع أي أمر مدير حزم ليس في قائمة `allowed` ويخبر Claude بإعادة كتابة الأمر باستخدام مدير مسموح.

يكتشف: pip, pip3, python -m pip, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo.

| المعامل | النوع | الافتراضي | الوصف |
|-----------|------|---------|-------------|
| `allowed` | string[] | `[]` | أسماء مديري الحزم المسموحة. أي مدير مكتشف ليس في هذه القائمة يتم منعه. عندما تكون فارغة، السياسة بدون تأثير. |
| `blocked` | string[] | `[]` | أسماء مديري حزم إضافية للمنع بعيدًا عن القائمة المدمجة (مثل `['pdm', 'pipx']`). |

قائمة المنع المدمجة تغطي: pip, pip3, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo. استخدم `blocked` لإضافة مديري حزم ليسوا في هذه القائمة.

**مثال على الإعداد:**

```json
{
  "enabledPolicies": ["prefer-package-manager"],
  "policyParams": {
    "prefer-package-manager": {
      "allowed": ["uv", "bun"],
      "blocked": ["pdm", "pipx"]
    }
  }
}
```

مع هذا الإعداد، يتم رفض `pip install flask` و `pdm install flask` معًا برسالة تخبر Claude باستخدام `uv` أو `bun` بدلاً من ذلك. أوامر مثل `uv pip install flask` مسموحة لأن `uv` في القائمة البيضاء ويتم فحصه أولاً.

## السير العملي

فرض سير عملي منضبط لنهاية الجلسة. تطلق هذه السياسات على حدث **Stop** وترفض الوكيل من الإيقاف حتى تتحقق كل شرط. تتبع سلسلة اعتماد طبيعية: commit → push → PR → CI. إذا رفضت السياسة، يتم تخطي السياسات اللاحقة في السلسلة (refuse short-circuits).

جميع سياسات السير العملي **fail-open**: إذا لم تكن الأداة المطلوبة متوفرة (مثل `gh` غير مثبتة، لا توجد git remote)، السياسة تسمح برسالة معلوماتية توضح سبب تخطي الفحص.

### دلالات Stop لكل CLI

يبدو فرض Stop مختلفًا قليلاً عبر ستة CLIs المدعومة لأن كل واحد يعرض عقد خطاف مختلف للـ "agent finished". النتيجة **متطابقة** — الوكيل لا يهرب من الإيقاف بينما بوابة السير العملي تفشل — لكن **الآليات** تختلف. يلخص الجدول أدناه؛ فقط Pi لديه خاصية مرئية للمستخدم تستحق الفهم قبل تفعيل سياسة `require-*-before-stop`.

| CLI | عندما تطلق البوابة | ما تراه |
|---|---|---|
| Claude Code | نفس حلقة الوكيل، فورًا | يستمر Claude في العمل — يصلح المشكلة، ثم يحاول الانتهاء مرة أخرى. لا انقطاع مرئي لك. |
| Codex | نفس حلقة الوكيل، فورًا | نفس Claude. |
| GitHub Copilot CLI | نفس حلقة الوكيل، فورًا | نفس Claude (يستخدم قناة إعادة محاولة Copilot `{decision:"block", reason}` — تم التحقق تجريبيًا مقابل Copilot CLI 1.0.41). |
| Cursor Agent | نفس حلقة الوكيل، فورًا | نفس Claude (يستخدم قناة `{followup_message}` من Cursor — محدودة بـ `loop_limit`، الافتراضي 5 محاولات). |
| OpenCode | نفس حلقة الوكيل، فورًا | نفس Claude (يستخدم استدعاء SDK `client.session.prompt(...)` من OpenCode الموجهة من خلال `hookSpecificOutput.additionalContext`). |
| **Pi (pi-coding-agent)** | **المنعطف التالي للمستخدم** | **Pi يتوقف بشكل مرئي** عندما تطلق البوابة — حلقة الوكيل الخاص به تخرج وتُعاد إلى الموجه. ثم تطلق البوابة في المرة التالية التي تقدم فيها موجهًا: يضع failproofai توجيهًا `MANDATORY ACTION REQUIRED` في موجه نظام هذا الدور، يوجه LLM لإكمال خطوة السير العملي (commit, push، إلخ) قبل فعل ما طلبته. |

<Note>
**قيد Pi.** `AgentEndEvent` من Pi (المعادل upstream لخطاف `Stop` من Claude) ليس له نوع Result — بحلول الوقت الذي ينطلق، حلقة الوكيل من Pi قد خرجت بالفعل. لا يمكن إجبار Pi على إعادة محاولة نفس الحلقة بالطريقة التي يمكن لـ Claude / Copilot / Cursor / OpenCode. يحول failproofai البوابة إلى حدث `before_agent_start` من Pi (الذي ينطلق بعد الموجه التالي للمستخدم) بحيث يتم تفعيل فحص السير العملي، فقط في الدور التالي بدلاً من الحالي.

**ما يعنيه هذا عمليًا:**

- بعد إيقاف Pi، يتم التقاط سبب الرفض في الذاكرة مفهرسًا بمعرّف جلسة Pi. الموجه التالي بالضبط الذي تقدمه في نفس عملية Pi يفرغه: يرى LLM توجيه `MANDATORY ACTION REQUIRED` في أعلى موجه النظام الخاص به، commits (أو يدفع / يفتح PR / ينتظر CI)، وفقط بعد ذلك يستمر مع طلبك. سبب الرفض الملتقط بحقنة واحدة — بمجرد تفريغه، البوابة واضحة.
- يحد البوابة بعمر عملية Pi. إذا `Ctrl+C` Pi أو قفلت بين الأدوار، تُسقط الإدخالة الموجودة في الذاكرة مع العملية والبوابة فاتت. Claude, Copilot, Cursor, و OpenCode لديهم نفس الحد (اقتل الوكيل والبوابة فاتت) — Pi فقط يجعلها أكثر وضوحًا لأن الوكيل يخرج بشكل مرئي قبل طلق البوابة.
- سقط معلق أيضًا عند `session_shutdown` لأي سبب (`new` / `resume` / `fork` / `quit`)، لذا بوابة قديمة من جلسة سابقة لا يمكن أن تتسرب إلى جلسة طازجة بدأت في نفس عملية Pi.

إذا احتجت إلى إعادة محاولة same-loop من نمط Claude، شغّل سياسات `Stop` تحت أي من CLIs الخمسة الأخرى المدعومة. نحن نتابع Pi upstream لنوع Result مستقبلي على `AgentEndEvent` الذي سيسمح لنا بإغلاق هذه الفجوة.
</Note>

### `require-no-conflicts-before-stop`

**الحدث:** Stop  
**الافتراضي:** يرفض الإيقاف عندما لا يمكن للفرع الحالي دمج نظيفًا في فرع القاعدة. تتحقق السياسة أولاً من وجود `OPEN` PR على GitHub للفرع — بدونه، لا توجد هدف دمج لفرضه، لذا تقصر السياسة كاملة للسماح. بمجرد تأكيد `OPEN` PR، تعمل مسحاتان مستقلتان:

1. **محلي** — `git merge-tree --write-tree --name-only origin/<baseBranch> HEAD`. عند النزاع، تسمي رسالة الرفض الملفات المتنازع عليها حتى يعرف Claude بالضبط ما يجب حله.
2. **GitHub** — يعيد استخدام نتيجة `gh pr view --json mergeable,state` المجلوبة بالفعل في precheck. يلتقط النزاعات التي قد تفتقدها `origin/<baseBranch>` المحلية القديمة (مثل شخص ما هبط PR متنازع عليه على `main` منذ آخر جلب). نتيجة `CONFLICTING` ترفض. نتيجة `UNKNOWN` أيضًا ترفض وتوجه Claude للانتظار ~10 ثوان وإعادة فحص قبل محاولة الإيقاف مرة أخرى — هذا يمنع النتائج السلبية الخاطئة بينما تعيد GitHub الحساب.

يتخطى بالكامل (يسمح) عندما: `gh` غير مثبتة، لا توجد PR للفرع، حالة PR ليست `OPEN` (مثل `MERGED`, `CLOSED`)، أو `gh pr view` تعيد مخرجات غير قابلة للتحليل. أيضًا فشل open عندما `origin/<baseBranch>` مفقودة محليًا أو عندما لا توجد commits قبل القاعدة — تلك المسقطات من الطبقة 1 لا تزال استشير mergeability المخزن مؤقتًا من PR قبل السماح.

**المعاملات:**

| المعامل | النوع | الافتراضي | الوصف |
|-------|------|---------|-------------|
| `baseBranch` | `string` | `"main"` | فرع القاعدة للفحص للنزاعات ضده. |

<Note>
GitHub CLI (`gh`) مطلوب لهذه السياسة. السياسة تستخدم `gh pr view` لتأكيد
وجود `OPEN` PR قبل تشغيل أي مسح نزاع — بدون `gh`، السياسة
تقصر للسماح. شغّل `gh auth login` بـ personal access token لديه
نطاق `repo` للوصول للقراءة إلى pull requests.
</Note>

## تعطيل سياسات فردية

أزل سياسة معينة من `enabledPolicies` في إعدادك، أو عطّلها في تبويب Policies بلوحة التحكم.

```json
{
  "enabledPolicies": [
```

السياسات غير المدرجة في `enabledPolicies` لا تعمل، حتى إذا كانت هناك إدخالات `policyParams` لها.
