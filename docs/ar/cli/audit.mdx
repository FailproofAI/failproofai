<Note>
  **ميزة تجريبية.** يتم شحن المراجعة كإصدار تجريبي بينما نجمع التعليقات المبكرة.
  قد يتغير فهرس الكاشف وتنسيق التقرير قبل الإصدار المستقر التالي. يرجى فتح مشكلة إذا بدا شيء ما غير صحيح.
</Note>

تُعرَّض المراجعة الآن كـ **/audit صفحة لوحة المعلومات**، وليس كأمر CLI فرعي. افتحها من شريط التنقل في لوحة المعلومات (بين Policies و Projects)، أو قم بزيارة `http://localhost:8020/audit` مباشرة عند تشغيل `failproofai` محليًا.

```bash
failproofai          # افتح لوحة المعلومات، ثم انقر على "Audit"
```

تقوم لوحة المعلومات بمسح نصوص CLI للوكيل السابقة على هذا الجهاز (Claude Code وCodex وCopilot وCursor وOpenCode وPi وGemini) وتقرير عدد المرات التي قام فيها الوكيل بأشياء بُنيت failproofai لإيقافها — فحوصات متغيرات البيئة والدفع القسري والبادئات المكررة `cd <cwd>` وحلقات الانتظار بالإسبات وإعادة قراءة الملفات المحررة للتو والمزيد.

بالنسبة لكل نص، يتم إعادة تشغيل كل حدث استخدام أداة عبر 39 سياسة مدمجة **و** عبر 8 كاشفات مراجعة فقط التي تتقاطع الأنماط غير المغطاة حتى الآن بسياسات وقت التشغيل. يتم تجميع الأعداد لكل سياسة / كاشف عبر جميع الجلسات.

## ما تحصل عليه

تتكون صفحة `/audit` من ستة أقسام:

1. **الهوية** — وكيلك المصنف إلى واحد من 8 نماذج أولية (`متفائل`, `cowboy`, `مستكشف`, `ذاكرة قصيرة الأمد`, `معماري مريب`, `بناء دقيق`, `مطرقة`, `شبح`) بناءً على الإشارة المرجحة عبر كل نص مدقق.
2. **نقاط القوة** — أرقام حقيقية مشتقة من المسح (نسبة استدعاء نظيفة، "0 تسريب بيانات اعتماد"، إلخ) محدودة بسياسات التطهير ذات الصلة التي تعمل فعلاً.
3. **النقاط** — 0-100 مع نطاقات S/A/B/C/D/F والارتفاع المتوقع إذا تم تفعيل كل سياسة موصى بها.
4. **النتائج** — بطاقات لكل سياسة مع ما حدث والتكلفة والأدلة المسجلة والأمر `failproofai policy add <slug>` الدقيق لتفعيل المدمج وقت التشغيل الذي كان سيمسكه.
5. **السياسات الموصى بها** — قائمة التثبيت المجمعة مع أمر `failproofai policies --install` الذي يعمل بضربة واحدة.
6. **تذكير المراجعة** — "عد بشكل أفضل." اضبط تذكير بريد إلكتروني لمدة 7 أيام عبر خادم API (يتطلب تسجيل الدخول؛ انظر [`failproofai auth`](/ar/cli/auth)).

## كاشفات المراجعة فقط

تكتشف أنماط السلوك "الغبي" التي لم يتم فرضها (حتى الآن) في الوقت الفعلي. تعمل فقط أثناء المراجعة ولا تحجب أبدًا استدعاء أداة مباشرة.

| الكاشف | ما يحسبه |
|---|---|
| `redundant-cd-cwd` | أوامر Bash تبدأ بـ `cd <cwd> && …` حتى لو كانت الأوامر تعمل بالفعل في `cwd`. |
| `prefer-edit-over-read-cat` | `cat`/`head`/`tail`/`less`/`more` على ملف مصدر واحد — استخدم أداة `Read`. |
| `prefer-edit-over-sed-awk` | تحريرات في الموقع `sed -i` / `awk … > file` — استخدم أداة `Edit`. |
| `prefer-write-over-heredoc` | كتابة الملفات بـ heredoc / متعدد الأسطر `echo > file` — استخدم أداة `Write`. |
| `sleep-polling-loop` | `sleep N` الطويل (≥ 30s) أو حلقات الاستطلاع `while …; sleep …; done`. |
| `find-from-root` | `find /`, `find /home`, `find /usr`، إلخ. — حدد النطاق إلى `cwd` بدلاً من ذلك. |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`، تخطي الخطافات. |
| `reread-after-edit` | `Read` لملف تم `Edit`/`Write` للتو في نفس الجلسة. |

## ذاكرات التخزين المؤقت

- **ذاكرة التخزين المؤقت لكل نص** في `~/.failproofai/cache/audit/<sha1>.json` مفهرسة بـ `(mtime, size, engineVersion, detectorVersion)` — تُلغى تلقائيًا عندما يتغير النص أو كود السياسة/الكاشف. يخزن كل إدخال أيضًا طابع وقت `cachedAt` كـ **بيانات وصفية TTL** (ليست جزءًا من مفتاح ذاكرة التخزين المؤقت)؛ يتم رفض الإدخالات الأقدم من **7 أيام** عند القراءة بحيث لا تتجاوز النتائج طويلة الأجل النية المتطورة للكاشف.
- **ذاكرة التخزين المؤقت للنتيجة الكاملة** في `~/.failproofai/audit-dashboard.json` (الوضع 0600). يسمح لوحة المعلومات بالعرض على الفور دون إعادة التشغيل. يتم رفضها أيضًا عند القراءة بعد **7 أيام TTL** — `/audit` ثم يسقط إلى حالته الفارغة ويطالب بتشغيل جديد. انقر `[ re-audit now ]` بالقرب من الأسفل من التقرير للتحديث؛ يقوم التشغيل الجديد ببث التقدم عبر شريط لاصق في الأعلى ويستبدل النتيجة في الموضع عند النجاح (لا يوجد إعادة تحميل الصفحة).

## ملاحظات

- **لا توجد طفرة.** تعاد المراجعة في وضع القراءة فقط. يتم تخطي `warn-repeated-tool-calls` لأن سترة الجانب الخاصة بكل جلسة ستُعدَّل وإلا.
- **سياسات سير العمل مستبعدة.** تعمل سياسات `require-*-before-stop` فقط على أحداث `Stop` و `execSync` مقابل حالة git المباشرة — لا تملك تفسيرًا ذا مغزى "ماذا كان سيحدث في 2025"، لذلك لا تظهر في أعداد المراجعة.
- **السياسات المخصصة مستبعدة.** لا يتم إعادة تشغيل الخطافات المخصصة من قبل المستخدم (قد تكون قد تغيرت منذ الجلسة الأصلية).
