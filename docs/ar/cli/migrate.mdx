```bash
failproofai migrate --dry-run   # print the plan, change nothing
failproofai migrate             # run it
```

معظم الناس لا يكتبون هذا أبداً. يعمل بنفسه عند أول أمر بعد ترقية، وتتضمنه
[`failproofai update`](/ar/cli/update). استخدمه مباشرة عندما تريد رؤية الخطة قبل حدوثها،
أو لتشغيل الترحيل بمفرده.

## يتم تحديده بناءً على التخطيط، وليس النسخة

`~/.failproofai/VERSION` يسجل رقم **التخطيط** — شكل المجلد، وليس الإصدار الذي كتبه.
يتم تحديد الترحيلات بناءً على هذا الرقم، وهو ما يجعل الفجوة الطويلة رخيصة الثمن:

- إصدارات npm تتغير عند كل إصدار، عشرات بينهما بين تخطيطين.
- لذا فإن الجهاز الذي يتخطى ثلاثين إصدار بدون **تغيير تخطيط** ينفذ **صفر**
  ترحيلات، وليس ثلاثين عملية لا.
- وجهاز يتخطى عدة تخطيطات مرة واحدة ينفذ كل خطوة بالترتيب، كل خطوة
  تعرف طرفيها الخاصين فقط.

هذا مهم لأن npm لا يمكنه تحديث حزمة مثبتة بمفردها. جهاز يجلس على نسخة واحدة
لعدة أشهر ثم يقفز عدة تخطيطات هو الحالة العادية، وليس الحالة الشاذة.

## التشغيل الجاف

`--dry-run` يطبع السلسلة الدقيقة والملفات التي ستُحفظ أولاً، ولا يغير شيئاً
على الإطلاق — لا ترحيل، لا نسخ احتياطي، لا إدخال دفتر اليوميات:

```
Layout 2 on disk; this build speaks 3.
1 step(s) would run:
  2 → 3  layout 2 → 3: carry config.toml and credentials.toml into JSON, move
         custom-policies/ back up into policies/, nest the policy config at the root

These would be copied to ~/.failproofai/migrations/backup-layout2 first:
  VERSION
  config.toml
  credentials.toml
```

## ما يتم نقله وما يتم إعادة بناؤه

كل مسار في المنزل يعلن نوع البيانات التي يحتفظ بها، وهذا يحدد ما إذا كان
الترحيل قد يتركه. القاعدة: **ما هو مشتق وقابل لإعادة الجلب قد يُحذف؛
أي شيء كتبته، أي شيء لم يتم توصيله بعد، وأي شيء يحدد الجهاز يتم نقله.**

| يتم نقله | يتم إعادة بناؤه أو إعادة جلبه |
|---|---|
| `config.json` — الإعدادات، `daemon.configured`، مسارات التقاط إضافية | ذاكرة تخزين المراجعة |
| `credentials.json` — التسجيل السحابي الخاص بك | النشرات المدارة بالسحابة (يتم جلبها مجدداً والتحقق من الملخص في الاستطلاع التالي) |
| `policies-config.json` — اختيار السياسة والمعاملات الخاصة بك | حالة الخدش الموجودة في الخادم |
| `policies/` — ملفات السياسة الخاصة بك والمساعدات التي تستوردها | |
| `hook-activity/` — سجل القرارات الذي تقرأه لوحة التحكم | |
| الأحداث غير المُسلَّمة التي تنتظر التحميل | |
| `cursors/` — علامات مائية منقب البيانات | |
| الثنائي الموجود في `bin/` | |

<Note>
  يتم نقل الأحداث غير المُسلَّمة بدلاً من حذفها لأن الخسارة ستكون دائمة، وليست بطيئة:
  علامة مائية منقب البيانات قد تقدمت بالفعل بعد أي شيء يجلس في الملف،
  لذا لن يقرأ أحد هذا النطاق من النص مرة أخرى. يطلب الترحيل أيضاً من الخادم توصيل
  ما هو في الملف بمجرد انتهائه، لذا النتيجة المعتادة أنه لا يوجد شيء يُنقل.
</Note>

المفاتيح التي كتبتها نسخة **أحدث** في `config.json` أو `credentials.json` أو
`policies-config.json` يتم الحفاظ عليها أيضاً، بدلاً من حذفها بواسطة قارئ أقدم.

## السجل الذي تتركه

```
~/.failproofai/migrations/
  applied.json                 entry واحدة لكل خطوة: layout، CLI، timestamp، مدة، النتيجة
  backup-layout<n>/            نسخ من الملفات التي لا يمكن استبدالها، مأخوذة قبل الخطوة الأولى
```

`applied.json` هو ما يجيب على سؤال "ماذا مرّ هذا الجهاز فعلاً" — السؤال
الأول الذي يستحق طرحه عندما يبدو شيء ما خاطئاً بعد الترقية. أرفقها
مع تقرير الخلل.

النسخة الاحتياطية متعمدة أن تكون صغيرة بدلاً من نسخة من المجلد بأكمله:
الترحيل لم يعد يحذف أي شيء لا يمكن استبداله بالتصميم، لذا ما يستحق التأمين
ضده هو **عيب في خطوة**، وهذه الملفات القليلة هي حيث قد يؤذي هذا العيب.

## إذا فشلت خطوة

تتوقف السلسلة هناك. `VERSION` يُختم فقط بواسطة خطوة اكتملت، لذا المنزل
يبقى مع تخطيطه القديم والأمر التالي يعيد محاولته — لا يتم وضع علامة على المنزل
بالتخطيط الحالي بناءً على ترحيل جزئي. يتم تسجيل الخطوة في `applied.json`
بـ `"ok": false`، والنسخة الاحتياطية حيث تم أخذها.

## يتم رفض المنزل الأحدث، وليس ترحيله

إذا كانت `~/.failproofai/` مكتوبة بواسطة failproofai **أحدث** من النسخة
التي تشغلها، يتوقف الأمر ويخبرك بالترقية بدلاً من ذلك. هذه البيانات بخير
وقارئ CLI أحدث يقرأها؛ الترحيل إلى الأمام منها ليس شيئاً موجوداً، وإعادة تعيينه
ستحطم شيئاً قابلاً للاسترجاع.

```
This machine's failproofai directory was written by a newer version (layout 4;
this build speaks 3). Upgrade rather than migrate:
  npm install -g failproofai@latest
```

الخادم ينطبق عليه نفس القانون: `failproofaid` يرفض البدء ضد تخطيط
لا يتحدثه، بدلاً من قراءة وكتابة المسارات التي تحركت.
