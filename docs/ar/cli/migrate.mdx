```bash
failproofai migrate --dry-run   # print the plan, change nothing
failproofai migrate             # run it
```

لا يكتب معظم الناس هذا الأمر. فهو يعمل تلقائياً عند أول أمر بعد الترقية، وَ [`failproofai update`](/ar/cli/update) يتضمنه. استخدمه مباشرة عندما تريد رؤية الخطة قبل تنفيذها، أو لتشغيل الترحيل بمفرده.

## مفتاح على أساس التخطيط وليس الإصدار

يسجل `~/.failproofai/VERSION` رقم **تخطيط** — شكل الدليل وليس الإصدار الذي كتبه. يتم تشفير الترحيلات على أساس هذا الرقم، وهذا هو ما يجعل الفجوة الكبيرة رخيصة:

- تتغير إصدارات npm مع كل إصدار، عشرات الإصدارات بين تخطيطين.
- لذا فإن الجهاز الذي يتخطى ثلاثين إصدار مع **عدم تغيير التخطيط** لا يشغل **صفر** ترحيل وليس ثلاثين عملية لا جدوى منها.
- والجهاز الذي يتخطى عدة تخطيطات دفعة واحدة يشغل كل خطوة بالترتيب، وكل خطوة تعرف فقط نهايتيها الخاصتين.

هذا مهم لأن npm لا يمكنه تحديث حزمة مثبتة بمفرده. الجهاز الذي يجلس على إصدار واحد لعدة أشهر ثم ينتقل إلى عدة تخطيطات هو الحالة العادية وليس الحالة الغريبة.

## التشغيل التجريبي

`--dry-run` يطبع السلسلة الدقيقة والملفات التي سيتم حفظها أولاً، ولا يغير شيئاً على الإطلاق — لا ترحيل، لا نسخة احتياطية، لا إدخال دفتر:

```
Layout 2 on disk; this build speaks 3.
1 step(s) would run:
  2 → 3  layout 2 → 3: carry config.toml and credentials.toml into JSON, move
         custom-policies/ back up into policies/, nest the policy config at the root

These would be copied to ~/.failproofai/migrations/backup-layout2 first:
  VERSION
  config.toml
  credentials.toml
```

## ما يتم نقله وما يتم إعادة بناؤه

كل مسار في المنزل يصرح بنوع البيانات التي يحتويها، وهذا يقرر ما إذا كان الترحيل قد يرميها بعيداً. القاعدة: **المشتق وقابل إعادة الجلب قد يتم حذفه؛ أي شيء كتبته، أي شيء لم يتم تسليمه بعد، وأي شيء يحدد الجهاز يتم نقله.**

| تم نقله | أعيد بناؤه أو تم إعادة جلبه |
|---|---|
| `config.json` — الإعدادات، `daemon.configured`، مسارات الالتقاط الإضافية | ذاكرة التدقيق |
| `credentials.json` — التسجيل السحابي الخاص بك | النشرات المُدارة من السحابة (إعادة جلب والتحقق من الملخص في الاستطلاع التالي) |
| `policies-config.json` — اختيار السياسة والمعاملات الخاصة بك | حالة الخدش المؤقتة للخادم |
| `policies/` — ملفات السياسة الخاصة بك والمساعدين الذين يستوردونهم | |
| `hook-activity/` — سجل القرار الذي تقرأه لوحة المعلومات | |
| الأحداث غير المُسلَّمة المتبقية في قائمة الانتظار للتحميل | |
| `cursors/` — علامات المياه الخاصة بالمجمِّع | |
| ثنائي الخادم في `bin/` | |

<Note>
  يتم نقل الأحداث غير المُسلَّمة بدلاً من حذفها لأن الخسارة ستكون دائمة وليست بطيئة: علامة مياه المجمِّع قد تقدمت بالفعل عن أي شيء موجود في البكرة، لذا لن يقرأ أي شيء تلك النطاق من النسخة مرة أخرى. يطلب الترحيل أيضاً من الخادم تسليم ما يتم تجميعه بمجرد الانتهاء، لذا فإن النتيجة المعتادة هي عدم بقاء أي شيء لنقله.
</Note>

المفاتيح التي كتبتها نسخة **أحدث** في `config.json` أو `credentials.json` أو `policies-config.json` يتم الحفاظ عليها أيضاً بدلاً من حذفها بواسطة قارئ أقدم.

## السجل الذي تتركه

```
~/.failproofai/migrations/
  applied.json                 one entry per step: layout, CLI, timestamp, duration, result
  backup-layout<n>/            copies of the irreplaceable files, taken before the first step
```

`applied.json` هو ما يجيب على "ماذا مرت هذه الآلة بالفعل" — السؤال الأول الذي يستحق طرحه عندما يبدو أن شيئاً ما خاطئ بعد الترقية. أرفقه بتقرير الخلل.

النسخة الاحتياطية متعمدة أن تكون صغيرة بدلاً من نسخة من الدليل بأكمله: لم يعد الترحيل يحذف أي شيء لا يمكن استبداله بالتصميم، لذا فإن ما يستحق التأمين ضده هو **عيب في خطوة**، وهذه الملفات القليلة هي حيث قد يؤذي هذا العيب.

## إذا فشلت خطوة

تتوقف السلسلة هناك. يتم ختم `VERSION` فقط بواسطة خطوة مكتملة، لذا يبقى المنزل موسوم بتخطيطه القديم والأمر التالي يعيد محاولته — لم يتم وسم المنزل أبداً على أنه حالي على أساس ترحيل جزئي. يتم تسجيل الخطوة في `applied.json` مع `"ok": false`، والنسخة الاحتياطية موجودة حيث تم أخذها.

## المنزل الأحدث مرفوض وليس مرحلاً

إذا تمت كتابة `~/.failproofai/` بواسطة **أحدث** failproofai مما تقوم بتشغيله، يتوقف الأمر ويخبرك بالترقية بدلاً من ذلك. تلك البيانات بخير و CLI الأحدث يقرأها؛ الترحيل "للأمام" منها ليس شيئاً موجوداً، وإعادة تعيينها ستدمر شيئاً يمكن استرجاعه.

```
This machine's failproofai directory was written by a newer version (layout 4;
this build speaks 3). Upgrade rather than migrate:
  npm install -g failproofai@latest
```

تطبق الخادم نفس القاعدة: `failproofaid` ترفض البدء ضد تخطيط لا تتحدثه، بدلاً من قراءة والكتابة إلى المسارات التي تحركت.
