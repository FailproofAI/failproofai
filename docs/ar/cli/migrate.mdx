```bash
failproofai migrate --dry-run   # print the plan, change nothing
failproofai migrate             # run it
```

معظم الأشخاص لا يكتبون هذا الأمر أبداً. فهو يعمل بنفسه تلقائياً عند تنفيذ أول أمر بعد ترقية النسخة، وأمر [`failproofai update`](/ar/cli/update) يتضمنه أيضاً. استخدمه مباشرة عندما تريد رؤية الخطة قبل تنفيذها، أو عندما تريد تشغيل الترحيل بمفرده.

## مفتاح للتخطيط وليس للإصدار

`~/.failproofai/VERSION` يسجل رقم **التخطيط** — شكل الدليل وليس الإصدار الذي كتبه. يتم ربط الترحيلات برقم التخطيط، مما يجعل الفجوة الطويلة منخفضة التكلفة:

- إصدارات npm تتغير مع كل إصدار، عشرات منها بين تخطيطين.
- لذا فإن الجهاز الذي يتخطى ثلاثين إصدار **بدون تغيير تخطيط** ينفذ **صفر** ترحيل وليس ثلاثين عملية فارغة.
- والجهاز الذي يتخطى عدة تخطيطات في وقت واحد ينفذ كل خطوة بالترتيب، كل خطوة تعرف طرفيها الخاصين فقط.

هذا مهم لأن npm لا يمكنه تحديث حزمة مثبتة بمفرده. جهاز يبقى على نسخة واحدة لأشهر ثم يقفز عدة تخطيطات هو الحالة العادية وليس الحالة الاستثنائية.

## التشغيل الجاف

`--dry-run` يطبع السلسلة الدقيقة والملفات التي سيتم حفظها أولاً، ولا يغير أي شيء على الإطلاق — بدون ترحيل، بدون نسخة احتياطية، بدون إدخال دفتر يوميات:

```
Layout 2 on disk; this build speaks 3.
1 step(s) would run:
  2 → 3  layout 2 → 3: carry config.toml and credentials.toml into JSON, move
         custom-policies/ back up into policies/, nest the policy config at the root

These would be copied to ~/.failproofai/migrations/backup-layout2 first:
  VERSION
  config.toml
  credentials.toml
```

## ما يتم نقله وما يتم إعادة بناؤه

كل مسار في الدليل يصرح بنوع البيانات التي يحتويها، وهذا يقرر ما إذا كان ترحيل قد يرميها. القاعدة: **المشتق والقابل لإعادة الجلب قد يتم حذفه؛ أي شيء كتبته، أي شيء لم يتم تسليمه بعد، وأي شيء يحدد الجهاز يتم نقله.**

| تم نقله | تم إعادة بناؤه أو إعادة جلبه |
|---|---|
| `config.json` — الإعدادات، `daemon.configured`، مسارات التقاط إضافية | ذاكرة تخزين مؤقت التدقيق |
| `credentials.json` — تسجيل الالتحاق بالسحابة | النشرات المدارة من السحابة (إعادة جلب والتحقق من الملخص عند الاستطلاع التالي) |
| `policies-config.json` — اختيار السياسة والمعاملات الخاصة بك | حالة الخدش المؤقتة للخادم |
| `policies/` — ملفات السياسة الخاصة بك والمساعدات التي تستوردها | |
| `hook-activity/` — سجل القرارات الذي تقرأه لوحة التحكم | |
| الأحداث غير المسلمة لا تزال في قائمة الانتظار للرفع | |
| `cursors/` — علامات المجمع | |
| ثنائي الخادم في `bin/` | |

<Note>
  يتم نقل الأحداث غير المسلمة بدلاً من حذفها لأن الخسارة ستكون دائمة وليست بطيئة: علامة المجمع قد تقدمت بالفعل بعد أي شيء موجود في البطاقة، لذا لن يقرأ أي شيء هذا النطاق من النسخة مرة أخرى. يطلب الترحيل أيضاً من الخادم تسليم ما هو موجود في البطاقة بمجرد انتهائه، لذا فإن النتيجة المعتادة هي عدم وجود أي شيء متبقي للنقل.
</Note>

يتم الحفاظ على مفاتيح نسخة *أحدث* كتبتها في `config.json` أو `credentials.json` أو `policies-config.json` أيضاً، بدلاً من حذفها بواسطة قارئ أقدم.

## السجل الذي يتركه

```
~/.failproofai/migrations/
  applied.json                 إدخال واحد لكل خطوة: التخطيط، CLI، الطابع الزمني، المدة، النتيجة
  backup-layout<n>/            نسخ من الملفات التي لا يمكن استبدالها، مأخوذة قبل الخطوة الأولى
```

`applied.json` هو ما يجيب على سؤال "ماذا مرت به هذه الآلة فعلاً" — أول سؤال يستحق طرحه عندما يبدو شيء خاطئ بعد ترقية. أرفقه بتقرير الخطأ.

النسخة الاحتياطية متعمد أن تكون صغيرة بدلاً من كونها نسخة من الدليل بالكامل: الترحيل لم يعد يحذف أي شيء لا يمكن استبداله بالتصميم، لذا فإن ما يستحق التأمين ضده هو *عيب في خطوة*، وهذه الملفات القليلة هي حيث قد يؤذي هذا العيب.

## إذا فشلت خطوة

تتوقف السلسلة هناك. يتم طبع `VERSION` فقط بواسطة خطوة اكتملت، لذا يبقى الدليل مميز بتخطيطه القديم والأمر التالي يعيد محاولته — لن يتم تمييز دليل بأنه حالي على أساس ترحيل جزئي. يتم تسجيل الخطوة في `applied.json` مع `"ok": false`، والنسخة الاحتياطية حيث تم أخذها.

## يتم رفض دليل أحدث وليس ترحيله

إذا تم كتابة `~/.failproofai/` بواسطة failproofai **أحدث** من النسخة التي تشغلها، يتوقف الأمر ويخبرك بالترقية بدلاً من ذلك. هذه البيانات صحيحة وقارئ CLI أحدث يقرأها؛ الترحيل "للأمام" منها ليس شيئاً موجوداً، وإعادة تعيينها ستدمر شيئاً قابلاً للاسترجاع.

```
This machine's failproofai directory was written by a newer version (layout 4;
this build speaks 3). Upgrade rather than migrate:
  npm install -g failproofai@latest
```

الخادم يطبق نفس القاعدة: `failproofaid` يرفض البدء ضد تخطيط لا يتحدثه، بدلاً من قراءة وكتابة المسارات التي تحركت.
