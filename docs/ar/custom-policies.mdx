تتيح لك السياسات المخصصة كتابة قواعد لأي سلوك وكيل: فرض اتفاقيات المشروع، منع الانجراف، حظر العمليات المدمرة، اكتشاف الوكلاء المعلقة، أو التكامل مع Slack وسير العمل الموافقة والمزيد. تستخدم نفس نظام أحداث الخطاف وقرارات `allow` و `deny` و `instruct` مثل السياسات المدمجة.

---

## مثال سريع

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

customPolicies.add({
  name: "no-production-writes",
  description: "Block writes to paths containing 'production'",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Write" && ctx.toolName !== "Edit") return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("production")) {
      return deny("Writes to production paths are blocked");
    }
    return allow();
  },
});
```

تثبيتها:

```bash
failproofai policies --install --custom ./my-policies.js
```

## طريقتان لتحميل السياسات المخصصة

### الخيار 1: قائم على الاتفاقية (موصى به)

انسخ ملفات `*policies.{js,mjs,ts}` إلى `.failproofai/policies/` وسيتم تحميلها تلقائياً — لا توجد علامات أو تغييرات في الإعدادات مطلوبة. يعمل هذا مثل Git hooks: انسخ الملف ويعمل.

```
# مستوى المشروع — يتم الالتزام به في Git ومشاركته مع الفريق
.failproofai/policies/security-policies.mjs
.failproofai/policies/workflow-policies.mjs

# المستوى الشخصي — شخصي، ينطبق على جميع المشاريع
~/.failproofai/policies/my-policies.mjs
```

**كيفية عمله:**
- تتم مسح كلا المجلدات (الاتحاد - وليس first-scope-wins)
- يتم تحميل الملفات أبجدياً داخل كل مجلد. البادئة بـ `01-` و `02-` للتحكم في الترتيب
- يتم تحميل الملفات المطابقة فقط لـ `*policies.{js,mjs,ts}`؛ يتم تجاهل الملفات الأخرى
- يتم تحميل كل ملف بشكل مستقل (فشل مفتوح لكل ملف)
- يعمل جنباً إلى جنب مع سياسات `--custom` صريحة والسياسات المدمجة

<Tip>
سياسات الاتفاقية هي أسهل طريقة لبناء معيار جودة لمؤسستك. التزم بـ `.failproofai/policies/` في Git وسيحصل كل عضو في الفريق على نفس القواعد تلقائياً — لا توجد حاجة لإعداد لكل مطور. مع اكتشاف فريقك لأنماط فشل جديدة، أضف سياسة وادفع. بمرور الوقت، تصبح هذه معيار جودة حي يستمر في التحسن مع كل مساهمة.
</Tip>

### الخيار 2: مسار ملف صريح

```bash
# التثبيت مع ملف سياسات مخصص
failproofai policies --install --custom ./my-policies.js

# استبدال مسارات السياسات المخصصة
failproofai policies --install --custom ./new-policies.js

# تكوين ملفات صريحة متعددة (محملة بترتيب العلم)
failproofai policies --install --custom ./security.js --custom ./workflow.js

# إزالة جميع مسارات السياسات المخصصة الصريحة من الإعدادات
failproofai policies --uninstall --custom
```

يتم تخزين المسارات المطلقة المحللة في `policies-config.json` باسم `customPoliciesPaths`. كرر `--custom` لتكوين ملفات متعددة. الإعدادات الموجودة التي تستخدم حقل `customPoliciesPath` القديم تستمر في العمل. يتم تحميل الملفات بشكل جديد في كل حدث خطاف - لا يوجد تخزين مؤقت بين الأحداث.

يظهر كل سياسة مسجلة مع تبديل خاص بها في لوحة التحكم. إيقاف السياسة يسجل معرفها المؤهل بالمصدر في `disabledCustomPolicies`؛ يستمر الملف والسياسات الأخرى في التحميل، بينما يتم استبعاد السياسة المعطلة قبل المطابقة. أسماء السياسات المكررة عبر الملفات لها تبديلات مستقلة.

### استخدام كليهما معاً

يمكن لسياسات الاتفاقية وملفات `--custom` الصريحة أن تتعايش. ترتيب التحميل:

1. ملفات `customPoliciesPaths` الصريحة (بالترتيب المكون)
2. ملفات اتفاقية المشروع (`{cwd}/.failproofai/policies/`، أبجدياً)
3. ملفات اتفاقية المستخدم (`~/.failproofai/policies/`، أبجدياً)

## API

### الاستيراد

```js
import { customPolicies, allow, deny, instruct } from "failproofai";
```

### `customPolicies.add(hook)`

تسجيل سياسة. استدعِ هذا عدة مرات حسب الحاجة لسياسات متعددة في نفس الملف.

```ts
customPolicies.add({
  name: string;                         // مطلوب - معرف فريد
  description?: string;                 // معروض في إخراج `failproofai policies`
  match?: { events?: HookEventType[] }; // تصفية حسب نوع الحدث؛ حذف للمطابقة مع الكل
  fn: (ctx: PolicyContext) => PolicyResult | Promise<PolicyResult>;
});
```

### مساعدو القرار

| الدالة | التأثير | الاستخدام عند |
|----------|--------|----------|
| `allow()` | السماح بالعملية صامتة | الإجراء آمن، لا توجد رسالة مطلوبة |
| `deny(message)` | حظر العملية | يجب ألا يتخذ الوكيل هذا الإجراء |
| `instruct(message)` | إضافة السياق دون حظر | إعطاء الوكيل سياق إضافي للبقاء على المسار |

`deny(message)` - تظهر الرسالة لـ Claude بادئة بـ `"Blocked by failproofai:"`. يؤدي واحد `deny` واحد إلى اختصار جميع التقييمات الإضافية.

`instruct(message)` - يتم إلحاق الرسالة بسياق Claude للاستدعاء الحالي للأداة. يتم تجميع جميع رسائل `instruct` وتسليمها معاً.

<Tip>
يمكنك إلحاق إرشادات إضافية بأي رسالة `deny` أو `instruct` بإضافة حقل `hint` في `policyParams` — لا يلزم تغيير الكود. يعمل هذا أيضاً مع سياسات مخصصة (`custom/`)، اتفاقية المشروع (`.failproofai-project/`)، واتفاقية المستخدم (`.failproofai-user/`). انظر [التكوين → hint](/ar/configuration#hint-cross-cutting) للحصول على التفاصيل.
</Tip>

### رسائل السماح المعلوماتية

`allow(message)` يسمح بالعملية **و** يرسل رسالة معلوماتية مرة أخرى إلى Claude. يتم تسليم الرسالة باسم `additionalContext` في استجابة stdout لمعالج الخطاف — نفس الآلية المستخدمة بواسطة `instruct`، لكن دلالياً مختلفة: إنها تحديث حالة، وليست تحذيراً.

| الدالة | التأثير | الاستخدام عند |
|----------|--------|----------|
| `allow(message)` | السماح وإرسال السياق إلى Claude | تأكيد فحص مرور، أو شرح سبب تخطي فحص |

حالات الاستخدام:
- **تأكيدات الحالة:** `allow("All CI checks passed.")` — يخبر Claude أن كل شيء أخضر
- **شروح الفتح الفاشلة:** `allow("GitHub CLI not installed, skipping CI check.")` — يخبر Claude لماذا تم تخطي فحص حتى يكون لديه سياق كامل
- **تراكم الرسائل المتعددة:** إذا أرجعت عدة سياسات `allow(message)`، يتم ربط جميع الرسائل بأسطر جديدة وتسليمها معاً

```js
customPolicies.add({
  name: "confirm-branch-status",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    const cwd = ctx.session?.cwd;
    if (!cwd) return allow("No working directory, skipping branch check.");

    // ... فحص حالة الفرع ...
    if (allPushed) {
      return allow("Branch is up to date with remote.");
    }
    return deny("Unpushed changes detected.");
  },
});
```

### حقول `PolicyContext`

| الحقل | النوع | الوصف |
|-------|------|-------------|
| `eventType` | `string` | `"PreToolUse"`، `"PostToolUse"`، `"Notification"`، `"Stop"` |
| `toolName` | `string \| undefined` | الأداة التي يتم استدعاؤها (مثل `"Bash"`، `"Write"`، `"Read"`) |
| `toolInput` | `Record<string, unknown> \| undefined` | معاملات إدخال الأداة |
| `payload` | `Record<string, unknown>` | حمولة الحدث الخام الكاملة من Claude Code |
| `session` | `SessionMetadata \| undefined` | سياق الجلسة (انظر أدناه) |

### حقول `SessionMetadata`

| الحقل | النوع | الوصف |
|-------|------|-------------|
| `sessionId` | `string` | معرف جلسة Claude Code |
| `cwd` | `string` | مجلس العمل لجلسة Claude Code |
| `transcriptPath` | `string` | المسار إلى ملف النسخة JSONL للجلسة |

### أنواع الأحداث

| الحدث | متى يتم تشغيله | محتويات `toolInput` |
|-------|--------------|----------------------|
| `PreToolUse` | قبل تشغيل Claude للأداة | إدخال الأداة (مثل `{ command: "..." }` لـ Bash) |
| `PostToolUse` | بعد اكتمال الأداة | إدخال الأداة + `tool_result` (الإخراج) |
| `Notification` | عند إرسال Claude إشعار | `{ message: "...", notification_type: "idle" \| "permission_prompt" \| ... }` - يجب أن تعيد الخطافات دائماً `allow()`، لا يمكنها حظر الإخطارات |
| `Stop` | عند انتهاء جلسة Claude | فارغ |

## ترتيب التقييم

يتم تقييم السياسات بهذا الترتيب:

1. السياسات المدمجة (بترتيب التعريف)
2. السياسات المخصصة الصريحة من `customPoliciesPath` (بترتيب `.add()`)
3. سياسات الاتفاقية من `.failproofai/policies/` للمشروع (الملفات أبجدياً، ترتيب `.add()` داخل)
4. سياسات الاتفاقية من `~/.failproofai/policies/` للمستخدم (الملفات أبجدياً، ترتيب `.add()` داخل)

<Note>
يؤدي أول `deny` إلى اختصار جميع السياسات اللاحقة. يتم تجميع جميع رسائل `instruct` وتسليمها معاً.
</Note>

## الاستيرادات الانتقالية

يمكن لملفات السياسات المخصصة استيراد الوحدات المحلية باستخدام المسارات النسبية:

```js
// my-policies.js
import { isBlockedPath } from "./utils.js";
import { checkApproval } from "./approval-client.js";

customPolicies.add({
  name: "approval-gate",
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const approved = await checkApproval(ctx.toolInput?.command, ctx.session?.sessionId);
    return approved ? allow() : deny("Approval required for this command");
  },
});
```

يتم حل جميع الاستيرادات النسبية التي يمكن الوصول إليها من ملف الإدخال. يتم تنفيذ هذا بإعادة كتابة استيرادات `from "failproofai"` إلى مسار dist الفعلي وإنشاء ملفات `.mjs` مؤقتة لضمان التوافق مع ESM.

## تصفية نوع الحدث

استخدم `match.events` للحد من موعد تشغيل السياسة:

```js
customPolicies.add({
  name: "require-summary-on-stop",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    // يتم التشغيل فقط عند انتهاء الجلسة
    // ctx.session.transcriptPath يحتوي على سجل الجلسة الكامل
    return allow();
  },
});
```

حذف `match` بالكامل للتشغيل في كل نوع حدث.

## معالجة الأخطاء وأنماط الفشل

السياسات المخصصة **فشل مفتوح**: الأخطاء لا تحظر السياسات المدمجة أو تعطل معالج الخطاف.

| الفشل | السلوك |
|---------|----------|
| `customPoliciesPath` لم يتم تعيينه | لا تعمل سياسات مخصصة صريحة؛ تستمر سياسات الاتفاقية والمدمجات بشكل طبيعي |
| الملف غير موجود | يتم تسجيل التحذير إلى `~/.failproofai/hook.log`؛ تستمر المدمجات |
| خطأ في البناء الجملة/الاستيراد (صريح) | يتم تسجيل الخطأ إلى `~/.failproofai/hook.log`؛ تم تخطي السياسات المخصصة الصريحة |
| خطأ في البناء الجملة/الاستيراد (اتفاقية) | خطأ تم تسجيله؛ هذا الملف تم تخطيه، لا تزال الملفات الاتفاقية الأخرى تحميل |
| `fn` يرمي في وقت التشغيل | خطأ تم تسجيله؛ يتم التعامل مع ذلك الخطاف باعتباره `allow`؛ تستمر الخطافات الأخرى |
| `fn` يستغرق أكثر من 10 ثوانٍ | تم تسجيل انتهاء المهلة؛ معامل كـ `allow` |
| مجلد الاتفاقية غير موجود | لا تعمل سياسات الاتفاقية؛ لا توجد أخطاء |

<Tip>
لتصحيح أخطاء السياسات المخصصة، راقب ملف السجل:

```bash
tail -f ~/.failproofai/hook.log
```
</Tip>

## مثال كامل: سياسات متعددة

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

// منع الوكيل من الكتابة إلى مجلد الأسرار
customPolicies.add({
  name: "block-secrets-dir",
  description: "Prevent agent from writing to secrets/ directory",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (!["Write", "Edit"].includes(ctx.toolName ?? "")) return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("secrets/")) return deny("Writing to secrets/ is not permitted");
    return allow();
  },
});

// إبقاء الوكيل على المسار: التحقق من الاختبارات قبل الالتزام
customPolicies.add({
  name: "remind-test-before-commit",
  description: "Keep the agent on track: verify tests pass before committing",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    if (/git\s+commit/.test(cmd)) {
      return instruct("Verify all tests pass before committing. Run `bun test` if you haven't already.");
    }
    return allow();
  },
});

// منع التغييرات غير المخطط لها في الاعتماديات أثناء فترة التجميد
customPolicies.add({
  name: "dependency-freeze",
  description: "Prevent unplanned dependency changes during freeze period",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    const isInstall = /^(npm install|yarn add|bun add|pnpm add)\s+\S/.test(cmd);
    if (isInstall && process.env.DEPENDENCY_FREEZE === "1") {
      return deny("Package installs are frozen. Unset DEPENDENCY_FREEZE to allow.");
    }
    return allow();
  },
});

export { customPolicies };
```

## أمثلة

يحتوي مجلد `examples/` على ملفات سياسات جاهزة للتشغيل:

| الملف | المحتويات |
|------|----------|
| `examples/policies-basic.js` | خمس سياسات للمبتدئين تغطي أنماط فشل الوكيل الشائعة |
| `examples/policies-advanced/index.js` | أنماط متقدمة: الاستيرادات الانتقالية، استدعاءات غير متزامنة، تنقية الإخراج، خطافات نهاية الجلسة |
| `examples/convention-policies/security-policies.mjs` | سياسات أمان قائمة على الاتفاقية (حظر كتابات .env، منع إعادة كتابة سجل Git) |
| `examples/convention-policies/workflow-policies.mjs` | سياسات سير عمل قائمة على الاتفاقية (تذكيرات الاختبار، ملفات الكتابة الحسابات) |

### استخدام أمثلة الملفات الصريحة

```bash
failproofai policies --install --custom ./examples/policies-basic.js
```

### استخدام أمثلة قائمة على الاتفاقية

```bash
# انسخ إلى مستوى المشروع
mkdir -p .failproofai/policies
cp examples/convention-policies/*.mjs .failproofai/policies/

# أو انسخ إلى المستوى الشخصي
mkdir -p ~/.failproofai/policies
cp examples/convention-policies/*.mjs ~/.failproofai/policies/
```

لا يلزم أمر تثبيت — يتم اختيار الملفات تلقائياً في حدث الخطاف التالي.
