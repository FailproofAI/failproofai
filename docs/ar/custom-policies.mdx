تتيح لك السياسات المخصصة كتابة قواعد لأي سلوك وكيل: فرض اتفاقيات المشروع، منع الانجراف، حجب العمليات المدمرة، اكتشاف الوكلاء العالقين، أو التكامل مع Slack وسير العمل الموافقة والمزيد. وتستخدم نفس نظام أحداث الخطاف وقرارات `allow` و `deny` و `instruct` مثل السياسات المدمجة.

---

## مثال سريع

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

customPolicies.add({
  name: "no-production-writes",
  description: "Block writes to paths containing 'production'",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Write" && ctx.toolName !== "Edit") return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("production")) {
      return deny("Writes to production paths are blocked");
    }
    return allow();
  },
});
```

ثبتها:

```bash
failproofai policies --install --custom ./my-policies.js
```

## طريقتان لتحميل السياسات المخصصة

### الخيار 1: القائم على الاتفاقية (موصى به)

انسخ ملفات `*policies.{js,mjs,ts}` إلى `.failproofai/policies/` وسيتم تحميلها تلقائياً - لا حاجة لأعلام أو تغييرات في الإعدادات. يعمل هذا مثل خطافات git: انسخ ملف، وهكذا يعمل.

```
# مستوى المشروع - يتم الالتزام به بـ git، مشاركته مع الفريق
.failproofai/policies/security-policies.mjs
.failproofai/policies/workflow-policies.mjs

# مستوى المستخدم - شخصي، ينطبق على جميع المشاريع
~/.failproofai/policies/my-policies.mjs
```

**كيف يعمل:**
- يتم مسح كلا المجلدين (الاتحاد - وليس نطاق أول النتائج)
- يتم تحميل الملفات أبجدياً داخل كل مجلد. ادرج البادئة `01-`, `02-` للتحكم في الترتيب
- يتم تحميل الملفات المطابقة فقط لـ `*policies.{js,mjs,ts}`؛ يتم تجاهل الملفات الأخرى
- يتم تحميل كل ملف بشكل مستقل (فشل مفتوح لكل ملف)
- يعمل جنباً إلى جنب مع السياسات المخصصة الصريحة والسياسات المدمجة

<Tip>
السياسات الاتفاقية هي أسهل طريقة لبناء معيار جودة لمؤسستك. التزم `.failproofai/policies/` بـ git وكل عضو في الفريق يحصل على نفس القواعد تلقائياً - لا حاجة لإعداد لكل مطور. عند اكتشاف فريقك أنماط فشل جديدة، أضف سياسة وادفع. بمرور الوقت، تصبح هذه معيار جودة حي يستمر في التحسن مع كل مساهمة.
</Tip>

### الخيار 2: مسار الملف الصريح

```bash
# التثبيت مع ملف السياسات المخصصة
failproofai policies --install --custom ./my-policies.js

# استبدال مسارات السياسات المخصصة
failproofai policies --install --custom ./new-policies.js

# تكوين ملفات صريحة متعددة (محملة بترتيب الأعلام)
failproofai policies --install --custom ./security.js --custom ./workflow.js

# إزالة جميع مسارات السياسات المخصصة الصريحة من الإعدادات
failproofai policies --uninstall --custom
```

يتم تخزين المسارات المطلقة المحللة في `policies-config.json` كـ `customPoliciesPaths`. كرر `--custom` لتكوين ملفات متعددة. تستمر الإعدادات الموجودة التي تستخدم حقل `customPoliciesPath` الموروث في العمل. يتم تحميل الملفات بشكل جديد في كل حدث خطاف - لا يوجد تخزين مؤقت بين الأحداث.

تظهر كل سياسة مسجلة مع تبديلها الخاص في لوحة المعلومات. إيقاف تشغيل سياسة يسجل معرفها المشروط بالمصدر في `disabledCustomPolicies`؛ يستمر الملف وسياساته الأخرى في التحميل، بينما يتم استبعاد السياسة المعطلة قبل مطابقة الحدث. السياسات ذات الأسماء المكررة عبر الملفات لها تبديلات مستقلة.

### استخدام كليهما معاً

يمكن للسياسات الاتفاقية وملفات `--custom` الصريحة أن توجد معاً. ترتيب التحميل:

1. ملفات `customPoliciesPaths` الصريحة (بالترتيب المكون)
2. ملفات الاتفاقية للمشروع (`{cwd}/.failproofai/policies/`, أبجدياً)
3. ملفات الاتفاقية للمستخدم (`~/.failproofai/policies/`, أبجدياً)

## واجهة برمجية التطبيقات

### الاستيراد

```js
import { customPolicies, allow, deny, instruct } from "failproofai";
```

### `customPolicies.add(hook)`

تسجيل سياسة. استدع هذا عدة مرات حسب الحاجة لسياسات متعددة في نفس الملف.

```ts
customPolicies.add({
  name: string;                         // مطلوب - معرف فريد
  description?: string;                 // معروض في مخرجات `failproofai policies`
  match?: { events?: HookEventType[] }; // التصفية حسب نوع الحدث؛ احذفها لمطابقة الكل
  fn: (ctx: PolicyContext) => PolicyResult | Promise<PolicyResult>;
});
```

### مساعدو القرار

| الدالة | التأثير | الاستخدام عند |
|----------|--------|----------|
| `allow()` | السماح بالعملية بصمت | الإجراء آمن، لا توجد رسالة مطلوبة |
| `deny(message)` | حجب العملية | لا يجب على الوكيل اتخاذ هذا الإجراء |
| `instruct(message)` | إضافة السياق دون الحجب | إعطاء الوكيل سياق إضافي للبقاء على المسار |

`deny(message)` - تظهر الرسالة لـ Claude مع البادئة `"Blocked by failproofai:"`. واحد `deny` يختصر جميع التقييمات الإضافية.

`instruct(message)` - يتم إضافة الرسالة إلى سياق Claude للاستدعاء الحالي للأداة. يتم تجميع جميع رسائل `instruct` وتسليمها معاً.

<Tip>
يمكنك إضافة إرشادات إضافية إلى أي رسالة `deny` أو `instruct` بإضافة حقل `hint` في `policyParams` - لا حاجة لتغيير الكود. يعمل هذا أيضاً مع السياسات المخصصة (`custom/`)، والاتفاقية للمشروع (`.failproofai-project/`)، والاتفاقية للمستخدم (`.failproofai-user/`). انظر [الإعدادات → hint](/ar/configuration#hint-cross-cutting) للتفاصيل.
</Tip>

### رسائل السماح المعلوماتية

`allow(message)` يسمح بالعملية **و** يرسل رسالة معلومات مرة أخرى إلى Claude. يتم تسليم الرسالة باسم `additionalContext` في استجابة stdout لمعالج الخطاف - نفس الآلية المستخدمة بـ `instruct`، لكن مختلفة دلالياً: إنها تحديث حالة، وليست تحذير.

| الدالة | التأثير | الاستخدام عند |
|----------|--------|----------|
| `allow(message)` | السماح وإرسال السياق إلى Claude | تأكيد فحص ممر، أو شرح سبب تخطي الفحص |

حالات الاستخدام:
- **تأكيدات الحالة:** `allow("All CI checks passed.")` - يخبر Claude أن كل شيء أخضر
- **شروحات الفشل المفتوح:** `allow("GitHub CLI not installed, skipping CI check.")` - يخبر Claude لماذا تم تخطي الفحص بحيث يكون لديه سياق كامل
- **رسائل متعددة تتراكم:** إذا عادت عدة سياسات `allow(message)`، يتم ربط جميع الرسائل بخطوط جديدة وتسليمها معاً

```js
customPolicies.add({
  name: "confirm-branch-status",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    const cwd = ctx.session?.cwd;
    if (!cwd) return allow("No working directory, skipping branch check.");

    // ... فحص حالة الفرع ...
    if (allPushed) {
      return allow("Branch is up to date with remote.");
    }
    return deny("Unpushed changes detected.");
  },
});
```

### حقول `PolicyContext`

| الحقل | النوع | الوصف |
|-------|------|-------------|
| `eventType` | `string` | `"PreToolUse"`, `"PostToolUse"`, `"Notification"`, `"Stop"` |
| `toolName` | `string \| undefined` | الأداة التي يتم استدعاؤها (مثل `"Bash"`, `"Write"`, `"Read"`) |
| `toolInput` | `Record<string, unknown> \| undefined` | معاملات إدخال الأداة |
| `payload` | `Record<string, unknown>` | حمل الحدث الخام الكامل من Claude Code |
| `session` | `SessionMetadata \| undefined` | سياق الجلسة (انظر أدناه) |

### حقول `SessionMetadata`

| الحقل | النوع | الوصف |
|-------|------|-------------|
| `sessionId` | `string` | معرف جلسة Claude Code |
| `cwd` | `string` | مجلد العمل لجلسة Claude Code |
| `transcriptPath` | `string` | مسار ملف النسخة JSONL للجلسة |

### أنواع الأحداث

| الحدث | متى يطلق | محتويات `toolInput` |
|-------|--------------|----------------------|
| `PreToolUse` | قبل تشغيل Claude لأداة | مدخلات الأداة (مثل `{ command: "..." }` لـ Bash) |
| `PostToolUse` | بعد اكتمال أداة | مدخلات الأداة + `tool_result` (المخرجات) |
| `Notification` | عندما يرسل Claude إشعار | `{ message: "...", notification_type: "idle" \| "permission_prompt" \| ... }` - يجب على الخطافات دائماً إرجاع `allow()`، لا يمكنها حجب الإشعارات |
| `Stop` | عند انتهاء جلسة Claude | فارغ |

## ترتيب التقييم

يتم تقييم السياسات بهذا الترتيب:

1. السياسات المدمجة (بترتيب التعريف)
2. السياسات المخصصة الصريحة من `customPoliciesPath` (بترتيب `.add()`)
3. سياسات الاتفاقية من `.failproofai/policies/` للمشروع (ملفات أبجدياً، ترتيب `.add()` داخل)
4. سياسات الاتفاقية من `~/.failproofai/policies/` للمستخدم (ملفات أبجدياً، ترتيب `.add()` داخل)

<Note>
أول `deny` يختصر جميع السياسات اللاحقة. يتم تجميع جميع رسائل `instruct` وتسليمها معاً.
</Note>

## الاستيرادات الانتقالية

يمكن لملفات السياسات المخصصة استيراد الوحدات المحلية باستخدام المسارات النسبية:

```js
// my-policies.js
import { isBlockedPath } from "./utils.js";
import { checkApproval } from "./approval-client.js";

customPolicies.add({
  name: "approval-gate",
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const approved = await checkApproval(ctx.toolInput?.command, ctx.session?.sessionId);
    return approved ? allow() : deny("Approval required for this command");
  },
});
```

تم حل جميع الاستيرادات النسبية الواصلة من ملف الإدخال. يتم تنفيذ هذا بإعادة كتابة استيرادات `from "failproofai"` إلى مسار dist الفعلي وإنشاء ملفات `.mjs` مؤقتة لضمان توافق ESM.

## تصفية نوع الحدث

استخدم `match.events` لتحديد متى تطلق السياسة:

```js
customPolicies.add({
  name: "require-summary-on-stop",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    // يطلق فقط عند انتهاء الجلسة
    // ctx.session.transcriptPath يحتوي على سجل الجلسة الكامل
    return allow();
  },
});
```

احذف `match` بالكامل لتطلق على كل نوع حدث.

## معالجة الأخطاء وأنماط الفشل

السياسات المخصصة هي **فشل مفتوح**: الأخطاء لا تحجب السياسات المدمجة أو تحطم معالج الخطاف.

| الفشل | السلوك |
|---------|----------|
| `customPoliciesPath` لم يتم تعيينه | لا تعمل سياسات مخصصة صريحة؛ تستمر السياسات الاتفاقية والمدمجة بشكل طبيعي |
| الملف غير موجود | تنبيه مسجل في `~/.failproofai/hook.log`؛ تستمر المدمجات |
| خطأ بناء/استيراد (صريح) | خطأ مسجل في `~/.failproofai/hook.log`؛ تم تخطي السياسات المخصصة الصريحة |
| خطأ بناء/استيراد (اتفاقية) | خطأ مسجل؛ هذا الملف تم تخطيه، ملفات الاتفاقية الأخرى لا تزال تحمل |
| `fn` يرمي أثناء التشغيل | خطأ مسجل؛ هذا الخطاف يعامل كـ `allow`؛ تستمر الخطافات الأخرى |
| `fn` يستغرق أطول من 10 ثوان | انتهاء الوقت مسجل؛ يعامل كـ `allow` |
| مجلد الاتفاقية مفقود | لا تعمل سياسات الاتفاقية؛ لا توجد أخطاء |

<Tip>
لتصحيح أخطاء السياسات المخصصة، راقب ملف السجل:

```bash
tail -f ~/.failproofai/hook.log
```
</Tip>

## مثال كامل: سياسات متعددة

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

// منع الوكيل من الكتابة إلى مجلد secrets/
customPolicies.add({
  name: "block-secrets-dir",
  description: "Prevent agent from writing to secrets/ directory",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (!["Write", "Edit"].includes(ctx.toolName ?? "")) return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("secrets/")) return deny("Writing to secrets/ is not permitted");
    return allow();
  },
});

// إبقاء الوكيل على المسار: التحقق من الاختبارات قبل الالتزام
customPolicies.add({
  name: "remind-test-before-commit",
  description: "Keep the agent on track: verify tests pass before committing",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    if (/git\s+commit/.test(cmd)) {
      return instruct("Verify all tests pass before committing. Run `bun test` if you haven't already.");
    }
    return allow();
  },
});

// منع تغييرات المسافة غير المخطط لها أثناء فترة التجميد
customPolicies.add({
  name: "dependency-freeze",
  description: "Prevent unplanned dependency changes during freeze period",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    const isInstall = /^(npm install|yarn add|bun add|pnpm add)\s+\S/.test(cmd);
    if (isInstall && process.env.DEPENDENCY_FREEZE === "1") {
      return deny("Package installs are frozen. Unset DEPENDENCY_FREEZE to allow.");
    }
    return allow();
  },
});

export { customPolicies };
```

## أمثلة

يحتوي مجلد `examples/` على ملفات سياسات جاهزة للتشغيل:

| الملف | المحتويات |
|------|----------|
| `examples/policies-basic.js` | خمس سياسات مبتدئة تغطي أنماط فشل الوكيل الشائعة |
| `examples/policies-advanced/index.js` | أنماط متقدمة: استيرادات انتقالية، استدعاءات غير متزامنة، كشط المخرجات، وخطافات نهاية الجلسة |
| `examples/convention-policies/security-policies.mjs` | سياسات الأمان القائمة على الاتفاقية (حجب كتابات .env، منع إعادة كتابة السجل git) |
| `examples/convention-policies/workflow-policies.mjs` | سياسات سير العمل القائمة على الاتفاقية (تذكيرات الاختبار، ملفات الكتابة الدقيقة) |

### استخدام أمثلة الملفات الصريحة

```bash
failproofai policies --install --custom ./examples/policies-basic.js
```

### استخدام أمثلة قائمة على الاتفاقية

```bash
# انسخ إلى مستوى المشروع
mkdir -p .failproofai/policies
cp examples/convention-policies/*.mjs .failproofai/policies/

# أو انسخ إلى مستوى المستخدم
mkdir -p ~/.failproofai/policies
cp examples/convention-policies/*.mjs ~/.failproofai/policies/
```

لا حاجة لأمر التثبيت - يتم التقاط الملفات تلقائياً على حدث الخطاف التالي.
