تتيح لك السياسات المخصصة كتابة قواعد لأي سلوك وكيل: فرض اتفاقيات المشروع، منع الانجراف، حجب العمليات المدمرة، كشف الوكلاء المتعثرين، أو التكامل مع Slack وسير عمل الموافقات وغيرها. تستخدم نفس نظام أحداث الخطاف وقرارات `allow` و `deny` و `instruct` المستخدمة في السياسات المدمجة.

---

## مثال سريع

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

customPolicies.add({
  name: "no-production-writes",
  description: "Block writes to paths containing 'production'",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Write" && ctx.toolName !== "Edit") return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("production")) {
      return deny("Writes to production paths are blocked");
    }
    return allow();
  },
});
```

ثبّتها:

```bash
failproofai policies --install --custom ./my-policies.js
```

## طريقتان لتحميل السياسات المخصصة

### الخيار 1: بناءً على الاتفاقية (موصى به)

ضع ملفات `*policies.{js,mjs,ts}` في المجلد `.failproofai/policies/` وسيتم تحميلها تلقائياً - لا توجد علامات أو تغييرات إعدادات مطلوبة. يعمل هذا مثل git hooks: ضع ملف، وكل شيء يعمل.

```
# مستوى المشروع — يتم الالتزام به في git، مشاركته مع الفريق
.failproofai/policies/security-policies.mjs
.failproofai/policies/workflow-policies.mjs

# المستوى الشخصي — شخصي، ينطبق على جميع المشاريع
~/.failproofai/policies/my-policies.mjs
```

**كيفية عمله:**
- تتم مسح كلا المجلدين (اتحاد - وليس الفوز بالنطاق الأول)
- يتم تحميل الملفات أبجدياً داخل كل مجلد. استخدم البادئة `01-` أو `02-` للتحكم في الترتيب
- يتم تحميل الملفات التي تطابق فقط `*policies.{js,mjs,ts}`؛ يتم تجاهل الملفات الأخرى
- يتم تحميل كل ملف بشكل مستقل (فشل مفتوح لكل ملف)
- يعمل جنباً إلى جنب مع السياسات المخصصة الصريحة والمدمجة `--custom`

<Tip>
سياسات الاتفاقية هي أسهل طريقة لبناء معيار جودة لمؤسستك. التزم بـ `.failproofai/policies/` في git وسيحصل كل عضو فريق على نفس القواعد تلقائياً - لا حاجة لإعداد منفصل لكل مطور. عندما يكتشف فريقك أوضاعاً فشل جديدة، أضف سياسة واضغط. بمرور الوقت تصبح معايير جودة حية تستمر في التحسن مع كل مساهمة.
</Tip>

### الخيار 2: مسار الملف الصريح

```bash
# التثبيت بملف سياسات مخصص
failproofai policies --install --custom ./my-policies.js

# استبدال مسارات السياسات المخصصة
failproofai policies --install --custom ./new-policies.js

# تكوين ملفات متعددة صريحة (يتم تحميلها بترتيب العلم)
failproofai policies --install --custom ./security.js --custom ./workflow.js

# إزالة جميع مسارات السياسات المخصصة الصريحة من الإعدادات
failproofai policies --uninstall --custom
```

يتم حفظ المسارات المطلقة المحللة في `policies-config.json` كـ `customPoliciesPaths`. كرر `--custom` لتكوين ملفات متعددة. الإعدادات الموجودة التي تستخدم حقل `customPoliciesPath` القديم تستمر في العمل. يتم تحميل الملفات بشكل جديد في كل حدث خطاف - لا يوجد تخزين مؤقت بين الأحداث.

يظهر كل سياسة مسجلة مع تبديلها الخاص في لوحة التحكم. يسجل إيقاف السياسة معرّف مؤهل المصدر في `disabledCustomPolicies`؛ يستمر الملف وسياساته الأخرى في التحميل، بينما يتم استبعاد السياسة المعطلة قبل مطابقة الحدث. أسماء السياسات المكررة عبر الملفات لها تبديلات مستقلة.

### استخدام كليهما معاً

يمكن أن تتعايش سياسات الاتفاقية وملفات `--custom` الصريحة. ترتيب التحميل:

1. ملفات `customPoliciesPaths` الصريحة (بالترتيب المكون)
2. ملفات الاتفاقية بمستوى المشروع (`{cwd}/.failproofai/policies/`، أبجدياً)
3. ملفات الاتفاقية على المستوى الشخصي (`~/.failproofai/policies/`، أبجدياً)

## API

### الاستيراد

```js
import { customPolicies, allow, deny, instruct } from "failproofai";
```

### `customPolicies.add(hook)`

تسجل سياسة. استدعِ هذا عدة مرات حسب الحاجة لسياسات متعددة في نفس الملف.

```ts
customPolicies.add({
  name: string;                         // مطلوب - معرّف فريد
  description?: string;                 // معروض في مخرجات `failproofai policies`
  match?: { events?: HookEventType[] }; // تصفية حسب نوع الحدث؛ احذف للمطابقة الكاملة
  fn: (ctx: PolicyContext) => PolicyResult | Promise<PolicyResult>;
});
```

### مساعدات القرار

| الدالة | التأثير | استخدم عندما |
|----------|--------|----------|
| `allow()` | السماح بالعملية بصمت | الإجراء آمن، لا توجد رسالة مطلوبة |
| `deny(message)` | حجب العملية | يجب ألا يتخذ الوكيل هذا الإجراء |
| `instruct(message)` | إضافة السياق دون حجب | أعط الوكيل سياقاً إضافياً للبقاء على المسار الصحيح |

`deny(message)` - تظهر الرسالة لـ Claude بادئة بـ `"Blocked by failproofai:"`. نفي واحد يختصر كل التقييم الإضافي.

`instruct(message)` - يتم إلحاق الرسالة بسياق Claude لاستدعاء الأداة الحالي. يتم تجميع جميع رسائل `instruct` وتسليمها معاً.

<Tip>
يمكنك إلحاق إرشادات إضافية بأي رسالة `deny` أو `instruct` بإضافة حقل `hint` في `policyParams` - لا حاجة لتغيير الكود. يعمل هذا أيضاً مع السياسات المخصصة (`custom/`) واتفاقيات المشروع (`.failproofai-project/`) والاتفاقيات الشخصية (`.failproofai-user/`). انظر [التكوين → hint](/ar/configuration#hint-cross-cutting) للتفاصيل.
</Tip>

### رسائل السماح المعلوماتية

`allow(message)` تسمح بالعملية **و** ترسل رسالة معلوماتية مرة أخرى إلى Claude. يتم تسليم الرسالة كـ `additionalContext` في استجابة stdout معالج الخطاف - نفس الآلية المستخدمة من قِبل `instruct`، لكن دلالياً مختلفة: إنها تحديث حالة، وليست تحذير.

| الدالة | التأثير | استخدم عندما |
|----------|--------|----------|
| `allow(message)` | السماح وإرسال السياق إلى Claude | تأكيد نجاح الفحص، أو شرح سبب تخطي الفحص |

حالات الاستخدام:
- **تأكيدات الحالة:** `allow("All CI checks passed.")` - يخبر Claude أن كل شيء أخضر
- **شروحات الفشل المفتوح:** `allow("GitHub CLI not installed, skipping CI check.")` - يخبر Claude لماذا تم تخطي الفحص لديه السياق الكامل
- **الرسائل المتعددة تتراكم:** إذا أرجعت عدة سياسات `allow(message)`، يتم دمج جميع الرسائل بفواصل أسطر وتسليمها معاً

```js
customPolicies.add({
  name: "confirm-branch-status",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    const cwd = ctx.session?.cwd;
    if (!cwd) return allow("No working directory, skipping branch check.");

    // ... check branch status ...
    if (allPushed) {
      return allow("Branch is up to date with remote.");
    }
    return deny("Unpushed changes detected.");
  },
});
```

### حقول `PolicyContext`

| الحقل | النوع | الوصف |
|-------|------|-------------|
| `eventType` | `string` | `"PreToolUse"`، `"PostToolUse"`، `"Notification"`، `"Stop"` |
| `toolName` | `string \| undefined` | الأداة التي يتم استدعاؤها (مثل `"Bash"`، `"Write"`، `"Read"`) |
| `toolInput` | `Record<string, unknown> \| undefined` | معاملات إدخال الأداة |
| `payload` | `Record<string, unknown>` | الحمل الخام الكامل للحدث من Claude Code |
| `session` | `SessionMetadata \| undefined` | سياق الجلسة (انظر أدناه) |

### حقول `SessionMetadata`

| الحقل | النوع | الوصف |
|-------|------|-------------|
| `sessionId` | `string` | معرّف جلسة Claude Code |
| `cwd` | `string` | مجلد العمل لجلسة Claude Code |
| `transcriptPath` | `string` | مسار ملف النسخ JSONL للجلسة |

### أنواع الأحداث

| الحدث | متى يحدث | محتويات `toolInput` |
|-------|--------------|----------------------|
| `PreToolUse` | قبل تشغيل Claude لأداة | إدخال الأداة (مثل `{ command: "..." }` للـ Bash) |
| `PostToolUse` | بعد انتهاء الأداة | إدخال الأداة + `tool_result` (المخرجات) |
| `Notification` | عند إرسال Claude إشعاراً | `{ message: "...", notification_type: "idle" \| "permission_prompt" \| ... }` - يجب أن تعود الخطافات دائماً `allow()`، لا يمكنها حجب الإشعارات |
| `Stop` | عند انتهاء جلسة Claude | فارغ |

## ترتيب التقييم

يتم تقييم السياسات بهذا الترتيب:

1. السياسات المدمجة (بترتيب التعريف)
2. السياسات المخصصة الصريحة من `customPoliciesPath` (بترتيب `.add()`)
3. سياسات الاتفاقية من مستوى المشروع `.failproofai/policies/` (الملفات أبجدياً، ترتيب `.add()` بداخلها)
4. سياسات الاتفاقية من مستوى المستخدم `~/.failproofai/policies/` (الملفات أبجدياً، ترتيب `.add()` بداخلها)

<Note>
نفي `deny` الأول يختصر جميع السياسات الإضافية. يتم تجميع جميع رسائل `instruct` وتسليمها معاً.
</Note>

## الاستيرادات الانتقالية

يمكن لملفات السياسات المخصصة استيراد الوحدات المحلية باستخدام المسارات النسبية:

```js
// my-policies.js
import { isBlockedPath } from "./utils.js";
import { checkApproval } from "./approval-client.js";

customPolicies.add({
  name: "approval-gate",
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const approved = await checkApproval(ctx.toolInput?.command, ctx.session?.sessionId);
    return approved ? allow() : deny("Approval required for this command");
  },
});
```

يتم حل جميع الاستيرادات النسبية التي يمكن الوصول إليها من ملف الإدخال. تم تنفيذ هذا بإعادة كتابة استيرادات `from "failproofai"` إلى مسار dist الفعلي وإنشاء ملفات `.mjs` مؤقتة لضمان توافق ESM.

## تصفية نوع الحدث

استخدم `match.events` لتحديد متى تحدث السياسة:

```js
customPolicies.add({
  name: "require-summary-on-stop",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    // تحدث فقط عند انتهاء الجلسة
    // ctx.session.transcriptPath يحتوي على سجل الجلسة الكامل
    return allow();
  },
});
```

احذف `match` تماماً لتحدث في كل نوع حدث.

## معالجة الأخطاء وأوضاع الفشل

السياسات المخصصة **فشل مفتوح**: الأخطاء لا تحجب السياسات المدمجة أو تعطل معالج الخطاف.

| الفشل | السلوك |
|---------|----------|
| `customPoliciesPath` غير مضبوط | لا تعمل السياسات المخصصة الصريحة؛ تستمر سياسات الاتفاقية والمدمجة بشكل طبيعي |
| الملف غير موجود | تحذير مسجل في `~/.failproofai/hook.log`؛ المدمجات تستمر |
| خطأ بناء جملة/استيراد (صريح) | خطأ مسجل في `~/.failproofai/hook.log`؛ السياسات المخصصة الصريحة تخطي |
| خطأ بناء جملة/استيراد (اتفاقية) | خطأ مسجل؛ هذا الملف تخطي، ملفات الاتفاقية الأخرى تحميل |
| `fn` يرفع خطأ في وقت التشغيل | خطأ مسجل؛ هذا الخطاف يتعامل معه كـ `allow`؛ الخطافات الأخرى تستمر |
| `fn` يستغرق أكثر من 10 ثوان | انتهاء المهلة الزمنية مسجلة؛ يتعامل معه كـ `allow` |
| مجلد الاتفاقية مفقود | لا تعمل سياسات الاتفاقية؛ لا خطأ |

<Tip>
لتصحيح أخطاء السياسات المخصصة، راقب ملف السجل:

```bash
tail -f ~/.failproofai/hook.log
```
</Tip>

## مثال كامل: سياسات متعددة

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

// منع الوكيل من الكتابة إلى مجلد secrets/
customPolicies.add({
  name: "block-secrets-dir",
  description: "Prevent agent from writing to secrets/ directory",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (!["Write", "Edit"].includes(ctx.toolName ?? "")) return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("secrets/")) return deny("Writing to secrets/ is not permitted");
    return allow();
  },
});

// إبقاء الوكيل على المسار الصحيح: التحقق من الاختبارات قبل الالتزام
customPolicies.add({
  name: "remind-test-before-commit",
  description: "Keep the agent on track: verify tests pass before committing",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    if (/git\s+commit/.test(cmd)) {
      return instruct("Verify all tests pass before committing. Run `bun test` if you haven't already.");
    }
    return allow();
  },
});

// منع تغييرات التبعيات غير المخطط لها أثناء التجميد
customPolicies.add({
  name: "dependency-freeze",
  description: "Prevent unplanned dependency changes during freeze period",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    const isInstall = /^(npm install|yarn add|bun add|pnpm add)\s+\S/.test(cmd);
    if (isInstall && process.env.DEPENDENCY_FREEZE === "1") {
      return deny("Package installs are frozen. Unset DEPENDENCY_FREEZE to allow.");
    }
    return allow();
  },
});

export { customPolicies };
```

## أمثلة

يحتوي المجلد `examples/` على ملفات سياسات جاهزة للتشغيل:

| الملف | المحتويات |
|------|----------|
| `examples/policies-basic.js` | خمس سياسات بدء تغطي أوضاع فشل الوكيل الشائعة |
| `examples/policies-advanced/index.js` | أنماط متقدمة: استيرادات انتقالية، استدعاءات غير متزامنة، تنظيف الإخراج، وخطافات نهاية الجلسة |
| `examples/convention-policies/security-policies.mjs` | سياسات أمان قائمة على الاتفاقية (حجب عمليات كتابة .env، منع إعادة كتابة سجل git) |
| `examples/convention-policies/workflow-policies.mjs` | سياسات سير عمل قائمة على الاتفاقية (تذكيرات الاختبار، ملفات كتابة التدقيق) |

### استخدام أمثلة الملفات الصريحة

```bash
failproofai policies --install --custom ./examples/policies-basic.js
```

### استخدام أمثلة قائمة على الاتفاقية

```bash
# نسخ إلى مستوى المشروع
mkdir -p .failproofai/policies
cp examples/convention-policies/*.mjs .failproofai/policies/

# أو نسخ إلى المستوى الشخصي
mkdir -p ~/.failproofai/policies
cp examples/convention-policies/*.mjs ~/.failproofai/policies/
```

لا تحتاج إلى أمر تثبيت - يتم التقاط الملفات تلقائياً عند حدث الخطاف التالي.
