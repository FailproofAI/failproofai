لوحة التحكم في failproofai هي تطبيق ويب محلي لمراقبة جلسات وكيل الذكاء الاصطناعي وإدارة السياسات. اطلع على ما فعله وكلاؤك أثناء غيابك.

---

## بدء لوحة التحكم

```bash
failproofai
```

يفتح على `http://localhost:8020`.

تقرأ لوحة التحكم بيانات المشروع والجلسة وإعدادات failproofai المحلية مباشرة من نظام الملفات. تُرسل الميزات المصرح بها الاختيارية، مثل تذكيرات التدقيق والدعوات، المعلومات المطلوبة لتلك الطلبات (بما في ذلك عناوين البريد الإلكتروني) إلى واجهات برمجية بعيدة.

## الصفحات

### المشاريع

تسرد جميع مشاريع Claude Code و OpenAI Codex و GitHub Copilot CLI _(beta)_ و Cursor Agent _(beta)_ و OpenCode _(beta)_ و Pi _(beta)_ و Hermes و OpenClaw و Factory Droid و Devin و Antigravity و Goose الموجودة على جهازك. يتم اكتشاف مشاريع Claude من `~/.claude/projects/` (أو المسار المعين بواسطة `CLAUDE_PROJECTS_PATH`)؛ يتم اكتشاف مشاريع Codex بمسح كل نسخة من النصوص الموجودة أسفل `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` وتجميعها حسب `cwd` المسجل في السجل الأول لكل جلسة؛ يتم اكتشاف مشاريع Copilot CLI بمسح كل `~/.copilot/session-state/<sessionId>/workspace.yaml` (قابل للتكوين عبر `COPILOT_HOME`) وتجميعها حسب حقل `cwd` الخاص بها؛ يتم اكتشاف مشاريع Cursor Agent بمسح البيانات الوصفية لكل جلسة أسفل `~/.cursor/agent-sessions/<sessionId>/` (قابل للتكوين عبر `CURSOR_HOME`، مع اختبار `conversations/` و `sessions/` كخيارات بديلة) للبحث عن `cwd` في `meta.json` / `session.json` / `workspace.yaml`؛ يتم اكتشاف مشاريع OpenCode بالاستعلام عن قاعدة بيانات SQLite الخاصة به على `~/.local/share/opencode/opencode.db` عبر `opencode db --format json` (نقرأ جداول `session` و `project` ونجمعها حسب `project_id`)؛ يتم اكتشاف مشاريع Pi بمسح نصوص JSONL لكل جلسة أسفل `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` (قابل للتكوين عبر `PI_SESSIONS_DIR`) واستخراج `cwd` من السجل الأول لكل جلسة؛ يتم قراءة جلسات بوابة Hermes مباشرة من متجر SQLite الخاص بكل ملف شخصي — `~/.hermes/state.db` بالإضافة إلى `~/.hermes/profiles/<name>/state.db` (قابل للتجاوز عبر `HERMES_HOME` أو `HERMES_DB_PATH` لقاعدة بيانات واحدة) — وتجميعها في مشاريع `hermes-<profile>-<source>` حسب الملف الشخصي و `source` (Slack/Telegram/cli/cron — جلسات البوابة ليس لديها cwd)؛ يتم قراءة جلسات بوابة OpenClaw من `~/.openclaw/agents/<agentId>/sessions/*.jsonl` وتجميعها في مشاريع `openclaw-<agentId>-<channel>` حسب الوكيل والقناة (أيضاً بدون cwd)؛ يتم اكتشاف مشاريع Factory Droid من نصوص JSONL على `~/.factory/sessions/<encoded-cwd>/*.jsonl` وتجميعها حسب cwd؛ مشاريع Devin من قاعدة بيانات SQLite الخاصة به على `~/.local/share/devin/cli/sessions.db` (مجمعة حسب `working_directory` لكل جلسة)؛ مشاريع Antigravity من نصوص JSONL على `~/.gemini/antigravity-cli/brain/<conversationId>/…/transcript_full.jsonl` وتجميعها حسب cwd؛ ومشاريع Goose من قاعدة بيانات SQLite الخاصة به على `~/.local/share/goose/sessions/sessions.db` (مجمعة حسب `working_dir` لكل جلسة). يتم عرض المشروع الذي تم استخدامه بواسطة عدة واجهات سطر أوامر كصف واحد مع جميع الشارات المطابقة. استخدم القائمة المنسدلة **CLI** أعلى الجدول للتصفية حسب واجهة سطر أوامر وكيل معينة؛ يحتفظ عنوان URL باختيارك كـ `?cli=claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose`.

Hermes و OpenClaw لديهما نطاق مستخدم وليس لديهما دليل عمل للتجميع، لذا يتم عرضهما كـ **شجرة مجلد قابلة للطي** — الملف الشخصي (أو الوكيل) على المستوى الأعلى، وقنواته أدناه — بينما تبقى كل واجهة سطر أوامر تستند إلى cwd صفاً مسطحاً. تجمع صفوف المجلد عدد الجلسات والنشاط الأخير لكل شيء تحتها، ويتم تذكر المجلدات المطوية بين الزيارات، والبحث الكلمات الرئيسية يوسع ما يطابقه.

يعرض كل مشروع:
- اسم المشروع (مشتق من مسار المجلد)
- شارة CLI — `Claude Code` (برتقالي)، `OpenAI Codex` (بنفسجي)، `GitHub Copilot` (أزرق)، `Cursor Agent` (أخضر فيروزي)، `OpenCode` (كهرماني)، `Pi` (وردي)، و/أو `Hermes` (نيلي)
- تاريخ أحدث نشاط للجلسة

انقر على مشروع لمشاهدة جلساته.

### الجلسات

تسرد جميع الجلسات داخل مشروع. تعرض كل جلسة:
- معرف الجلسة
- طوابع زمنية البداية والنهاية
- عدد استدعاءات الأدوات
- عدد نشاط Hook (السياسات التي تم تشغيلها)

استخدم مرشح نطاق التاريخ والبحث عن معرف الجلسة لتضييق القائمة. يتم ترقيم الجلسات.

انقر على جلسة لفتح عارض الجلسة.

### عارض الجلسة

يجيب عارض الجلسة على السؤال الأساسي للوكلاء المستقلين: ماذا فعل الوكيل، وهل ظل على المسار الصحيح؟ تشير شارة CLI بجانب الرأس إلى ما إذا كانت الجلسة نسخة من Claude Code أو OpenAI Codex أو GitHub Copilot CLI أو Cursor Agent أو OpenCode أو Pi أو Hermes أو OpenClaw أو Factory Droid أو Devin أو Antigravity أو Goose. يعرض جدول زمني لكل ما حدث في الجلسة:

- **الرسائل** - استجابات Claude النصية وطلبات المستخدم
- **استدعاءات الأدوات** - كل أداة استدعاها Claude، مع مدخلاتها ومخرجاتها
- **نشاط السياسة** - لكل استدعاء أداة، السياسات التي تم تشغيلها والقرار الذي أرجعته

يعرض شريط الإحصائيات في الأعلى مدة الجلسة والعدد الإجمالي لاستدعاءات الأدوات وملخصاً لقرارات hook (عد السماح / الرفض / التعليمات).

انقر على زر **تنزيل السجلات** لتصدير الجلسة. بالنسبة لجلسات Claude Code و Codex و Copilot و Cursor و Pi، تحصل على نص JSONL الأصلي على القرص بالكامل؛ بالنسبة إلى OpenCode (التي تعيش جلساتها في SQLite، وليس على القرص) تحصل على مستند JSON يعكس جداول `session` / `messages` / `parts` الأساسية.

### التدقيق

تقرير يركز على الشخصية لكيفية تصرف الوكيل الخاص بك فعلاً عبر الجلسات السابقة. يشغل نفس المسح مثل واجهة سطر أوامر `failproofai audit` لكنه يعرضه كملصق شاشة واحد قابل للمشاركة + أربعة أقسام أسفل الطي:

1. **الملصق** — يملأ المناظر الأولى الأولى. منطقة التقاط PNG المكتفية بذاتها مع شعار failproof_ai + تسمية التدقيق · فهرس النموذج الأصلي (`№ NN of 08`) + تاريخ التدقيق · درجة رقمية (0–100) + حبة ترتيب النسبة المئوية (`top 15%`) · اسم النموذج الأصلي (أحد `the optimist` أو `the cowboy` أو `the explorer` أو `the goldfish` أو `the paranoid architect` أو `the precision builder` أو `the hammer` أو `the ghost`) + شريط 3 كلمات · `// only N% of agents are this archetype` سطر الندرة · بلاطة رموز 8×8 بكسل · `audit yours → failproof.ai` تذييل. ثلاثة أزرار مشاركة تجلس خارج صندوق الالتقاط: `post your archetype` (نية X)، `share on linkedin`، `download poster`. يتم تشغيل الالتقاط عبر `html-to-image` بحيث يطابق PNG العرض على الشاشة بكسل مقابل بكسل (الحدود المتقطعة، قناع شعار SVG، التدرجات، مقاييس الخطوط — جميعها محفوظة).
2. **نقاط القوة** — قائمة صفوف هادئة من السلوكيات التي يقوم بها الوكيل الخاص بك بالفعل بشكل صحيح، مشتقة من بيانات التدقيق المباشرة (معدل استدعاء أداة نظيف، بدون دفع مباشر إلى main، صفر تسرب بيانات اعتماد، صفر عاصفة إعادة محاولة) — يتم سطح كل منها فقط عندما تكون السياسة ذات الصلة لديها سجل نظيف عبر نافذة التدقيق.
3. **الغرائب** — جدول ما انزلق، مرتب حسب الشدة: `when · what slipped + the policy that would've caught it · severity pill · seen`، حيث تقرأ التكرار `new` (مرة واحدة)، `N× seen` (2–9 مرات)، أو `recurring` (10+).
4. **كيفية التحسن** — قائمة صفوف هادئة، واحدة لكل سياسة موصوفة: اسم السياسة بأبيض، وصف بسطر واحد، أمر التثبيت + زر النسخ على الجانب الأيمن. يقرأ رأس القسم `enable all N → projected <score> · <tier>` (الدرجة التي ستصل إليها مع تطبيق كل إصلاح)، وزر `[install all]` الخاص به ينسخ أمر `failproofai policy add a b c …` المدمج لكل سياسة موصوفة.
5. **العودة بشكل أفضل** — بطاقتان جنباً إلى جنب. اليسار: اضبط تذكيراً (منتقي الإيقاع `3d` / `7d` / `14d` / `30d`؛ يستمر عبر `/api/auth/reminder` بعد المصادقة). اليمين: افتح مزايا failproof — `invite a friend` يفتح نموذجاً يأخذ قائمة مفصولة بفاصلة/مسافة/سطر جديد لرسائل البريد الإلكتروني للأصدقاء (بحد أقصى 10 لكل إرسال)، يُرسل بـ POST إلى `/api/audit/invite`، الذي ينقل إلى `POST /v0/invite` الخاص بخادم api. يرسل خادم api رسالة بريد إلكترونية واحدة لكل مستقبِل من `invite@failproof.ai` مع Cc للمُرسل و `Reply-To` معيّن، بحيث يرى المستقبِل من دعاه والمُرسل يحصل على نسخة في صندوق البريد الخاص به. يتم توجيه المستخدمين المجهولين عبر `AuthDialog` أولاً بحيث يُعرف بريد المُرسل الإلكتروني قبل خروج الدعوات. الاستحقاق / تحقق المزايا هو متابعة.

مدفوعة بوقت تشغيل `failproofai audit` — انظر إلى [Audit CLI](/ar/cli/audit) لمحرك المسح الأساسي والأعلام المدعومة وثوابت الذاكرة المؤقتة لكل نسخة. تخزن لوحة التحكم مؤقتاً النتيجة الأخيرة على `~/.failproofai/audit-dashboard.json` (الوضع `0600`، فتحة واحدة، تستبدل التشغيلات الجديدة) لذا فإن إعادة الزيارات فورية؛ **يتم رفض كل من ذاكرة التخزين المؤقت لكل نسخة والنتيجة الكاملة عند القراءة بمجرد أن تكون أقدم من 7 أيام** بحيث لا تخدم لوحة التحكم أبداً نتيجة قديمة بصمت لمدة أسبوع — بعد TTL `/audit` ينخفض إلى حالته الفارغة ويطالب بتشغيل جديد. انقر على `[ re-audit now ]` بالقرب من أسفل التقرير على `/api/audit/run` مع `noCache: true` — إعادة التدقيق تتجاوز الذاكرة المؤقتة لكل نسخة وتعيد مسح كل نسخة من الصفر بدلاً من إرجاع النتيجة المخزنة مؤقتاً بصمت — ولوحة التحكم تسأل عن `/api/audit/status` بسرعة 1Hz حتى ينتهي التشغيل؛ شريط تقدم وردي لزج يثبت على رأس المنفذ أثناء التشغيل مع مؤقت منقضٍ، والنتيجة الطازجة تتبادل في المكان عند النجاح (بدون إعادة تحميل الصفحة الكاملة؛ تترك إعادة التدقيق الفاشلة التقرير السابق سليماً). عند الفشل، يتحول الشريط إلى اللون الأحمر مع النسخ المفتاح بعيد المنال من `RerunError.kind` (`timeout` / `network` / `post_failed`). يتم تسطيح حالة الفراغ (بدون ذاكرة مؤقتة أو منتهية الصلاحية) وحالة الجلسات الصفرية (الذاكرة المؤقتة موجودة لكن المسح لم يجد نصوصاً) بشكل منفصل.

## التحديث التلقائي

تحتوي لوحة التحكم على مبدل تحديث تلقائي في الملاحة العلوية. عند التفعيل، تتحدث الصفحة الحالية بشكل دوري لعرض جلسات جديدة ونشاط سياسة جديد عند ظهورها. ضروري لمراقبة جلسات الوكيل المستقل طويلة المدى.

---

## تعطيل الصفحات

إذا كنت تحتاج فقط إلى بعض أجزاء لوحة التحكم، قم بتعيين `FAILPROOFAI_DISABLE_PAGES` إلى قائمة مفصولة بفاصلة من أسماء الصفحات:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

القيم الصالحة: `policies` أو `projects` أو `audit`.

---

## تكوين مسار المشاريع

بشكل افتراضي، تقرأ لوحة التحكم من دليل مشاريع Claude Code القياسي. تجاوزها لإعدادات مخصصة:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## الوصول من مضيف خارج localhost

عند تشغيل لوحة التحكم في **وضع المطور** (`npm run dev`) والوصول إليها من اسم مضيف آخر غير `localhost` - على سبيل المثال، نطاق مخصص أو عنوان IP بعيد أو عنوان URL نفق — قد تشاهد تحذيراً مثل:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

هذا هو Next.js يحجب الوصول بين الأصول إلى websocket HMR (إعادة تحميل الوحدة الساخنة) الخاص به، وهي ميزة يقتصر استخدامها على المطورين. للسماح بمضيفك، استخدم علم `--allowed-origins`:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

للعديد من المضيفين أو عناوين IP، مرّر قائمة مفصولة بفاصلة:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

يمكنك أيضاً تعيين متغير البيئة `FAILPROOFAI_ALLOWED_DEV_ORIGINS` بدلاً من ذلك:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
هذا ينطبق فقط على وضع المطور. عند تشغيل `failproofai` (وضع الإنتاج)، لا توجد websocket HMR ولا مشكلة مورد dev بين الأصول.
</Note>
