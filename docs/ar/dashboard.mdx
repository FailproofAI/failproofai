لوحة التحكم failproofai هي تطبيق ويب محلي لمراقبة جلسات وكيل الذكاء الاصطناعي الخاص بك وإدارة السياسات. اكتشف ما فعله وكلاؤك أثناء غيابك.

---

## بدء لوحة التحكم

```bash
failproofai
```

يتم الفتح على `http://localhost:8020`.

تقرأ لوحة التحكم بيانات المشروع والجلسة وإعدادات failproofai محليًا مباشرة من نظام الملفات. تُرسل الميزات المصادقة الاختيارية، مثل تذكيرات المراجعة والدعوات، المعلومات المطلوبة لتلك الطلبات (بما في ذلك عناوين البريد الإلكتروني) إلى واجهات برمجية بعيدة.

## الصفحات

### المشاريع

يسرد جميع مشاريع Claude Code و OpenAI Codex و GitHub Copilot CLI _(beta)_ و Cursor Agent _(beta)_ و OpenCode _(beta)_ و Pi _(beta)_ و Hermes و OpenClaw و Factory Droid و Devin و Antigravity و Goose الموجودة على جهازك. يتم اكتشاف مشاريع Claude من `~/.claude/projects/` (أو المسار المحدد بواسطة `CLAUDE_PROJECTS_PATH`); يتم اكتشاف مشاريع Codex من خلال مسح كل نسخة من الجلسات ضمن `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` وتجميعها حسب `cwd` المسجل في أول سجل بالجلسة; يتم اكتشاف مشاريع Copilot CLI من خلال مسح كل `~/.copilot/session-state/<sessionId>/workspace.yaml` (قابل للتكوين عبر `COPILOT_HOME`) وتجميعها حسب حقل `cwd`; يتم اكتشاف مشاريع Cursor Agent من خلال مسح البيانات الوصفية لكل جلسة ضمن `~/.cursor/agent-sessions/<sessionId>/` (قابل للتكوين عبر `CURSOR_HOME`، مع اختبار `conversations/` و `sessions/` كبدائل) للبحث عن `cwd` في `meta.json` / `session.json` / `workspace.yaml`; يتم اكتشاف مشاريع OpenCode من خلال الاستعلام عن قاعدة بيانات SQLite الخاصة بها في `~/.local/share/opencode/opencode.db` عبر `opencode db --format json` (نقرأ جداول `session` و `project` ونجمعها حسب `project_id`); يتم اكتشاف مشاريع Pi من خلال مسح نسخ الجلسات JSONL ضمن `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` (قابل للتكوين عبر `PI_SESSIONS_DIR`) واستخراج `cwd` من أول سجل بالجلسة; يتم قراءة جلسات بوابة Hermes مباشرة من متجر SQLite لكل ملف تعريف — `~/.hermes/state.db` بالإضافة إلى `~/.hermes/profiles/<name>/state.db` (قابل للتجاوز عبر `HERMES_HOME`، أو `HERMES_DB_PATH` لقاعدة بيانات واحدة) — وتجميعها في مشاريع `hermes-<profile>-<source>` حسب الملف التعريفي و `source` (Slack/Telegram/cli/cron — جلسات البوابة بلا cwd); يتم قراءة جلسات بوابة OpenClaw من `~/.openclaw/agents/<agentId>/sessions/*.jsonl` وتجميعها في مشاريع `openclaw-<agentId>-<channel>` حسب الوكيل والقناة (بدون cwd أيضًا); يتم اكتشاف مشاريع Factory Droid من نسخ الجلسات JSONL في `~/.factory/sessions/<encoded-cwd>/*.jsonl` وتجميعها حسب cwd; مشاريع Devin من قاعدة البيانات SQLite الخاصة بها في `~/.local/share/devin/cli/sessions.db` (مجمعة حسب `working_directory` لكل جلسة); مشاريع Antigravity من نسخ الجلسات JSONL في `~/.gemini/antigravity-cli/brain/<conversationId>/…/transcript_full.jsonl` وتجميعها حسب cwd; ومشاريع Goose من قاعدة البيانات SQLite الخاصة بها في `~/.local/share/goose/sessions/sessions.db` (مجمعة حسب `working_dir` لكل جلسة). يتم تصيير المشروع الذي استُخدم من قبل أكثر من CLI واحد كصف واحد مع جميع الشارات المتطابقة. استخدم القائمة المنسدلة **CLI** أعلى الجدول للتصفية حسب CLI وكيل محدد; تحتفظ عنوان URL بتحديدك كـ `?cli=claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose`.

Hermes و OpenClaw بنطاق المستخدم ولا توجد بهما مجلة عمل لتجميعها، لذلك يتم تصييرها كـ **شجرة مجلدات قابلة للطي** — الملف التعريفي (أو الوكيل) في المستوى الأعلى، قنواته تحته — بينما يبقى كل CLI يستند إلى cwd صفًا مسطحًا. تجمع صفوف المجلدات عدد الجلسات وأحدث نشاط لكل شيء تحتها، وتُذكّر المجلدات المطوية بين الزيارات، وبحث الكلمات الرئيسية يوسع ما يطابقه.

يعرض كل مشروع:
- اسم المشروع (مشتق من مسار المجلد)
- شارة CLI — `Claude Code` (برتقالي)، `OpenAI Codex` (بنفسجي)، `GitHub Copilot` (أزرق)، `Cursor Agent` (زمردي)، `OpenCode` (كهرماني)، `Pi` (وردي)، و/أو `Hermes` (نيلي)
- تاريخ أحدث نشاط للجلسة

انقر على مشروع لمشاهدة جلساته.

### الجلسات

يسرد جميع الجلسات ضمن مشروع. تعرض كل جلسة:
- معرّف الجلسة
- الطوابع الزمنية للبدء والانتهاء
- عدد استدعاءات الأدوات
- عدد نشاط الخطافات (السياسات التي تم تشغيلها)

استخدم عامل تصفية نطاق التاريخ وبحث معرف الجلسة لتضييق القائمة. يتم ترقيم الجلسات بالصفحات.

انقر على جلسة لفتح عارض الجلسة.

### عارض الجلسة

يجيب عارض الجلسة على السؤال الرئيسي للوكلاء المستقلين: ماذا فعل الوكيل، وهل بقي على المسار الصحيح؟ تشير شارة CLI بجانب الرأس إلى ما إذا كانت الجلسة نسخة من Claude Code أو OpenAI Codex أو GitHub Copilot CLI أو Cursor Agent أو OpenCode أو Pi أو Hermes أو OpenClaw أو Factory Droid أو Devin أو Antigravity أو Goose. يعرض خط زمني لكل شيء حدث في الجلسة:

- **الرسائل** - الاستجابات النصية Claude وطلبات المستخدم
- **استدعاءات الأدوات** - كل أداة استدعاها Claude، مع مدخلاتها ومخرجاتها
- **نشاط السياسة** - لكل استدعاء أداة، السياسات التي تم تشغيلها والقرار الذي أرجعته

يعرض شريط الإحصائيات في الأعلى مدة الجلسة وإجمالي استدعاءات الأدوات وملخص قرارات الخطافات (عدد allow / deny / instruct).

انقر على زر **Download Logs** لتصدير الجلسة. بالنسبة لجلسات Claude Code و Codex و Copilot و Cursor و Pi، تحصل على نسخة JSONL الأصلية على القرص بالكامل; بالنسبة لـ OpenCode (التي تعيش جلساتها في SQLite، وليس على القرص) تحصل على مستند JSON يعكس الجداول الأساسية `session` / `messages` / `parts`.

### التدقيق

تقرير يعكس الشخصية حول كيفية تصرف وكيلك بالفعل عبر الجلسات الماضية. يشغل نفس المسح مثل CLI `failproofai audit` لكنه يصيره كـ ملصق واحد قابل للمشاركة + أربعة أقسام تحت الطي:

1. **الملصق** — يملأ الإطار الأول. منطقة التقاط PNG مستقلة ذاتيًا مع شعار failproof_ai + تسمية التدقيق · فهرس نوع الشخصية (`№ NN of 08`) + تاريخ التدقيق · نقاط رقمية (0–100) + حبة ترتيب النسبة المئوية (`top 15%`) · اسم نوع الشخصية (أحدها `the optimist` أو `the cowboy` أو `the explorer` أو `the goldfish` أو `the paranoid architect` أو `the precision builder` أو `the hammer` أو `the ghost`) + شريط 3 كلمات رئيسية · خط ندرة `// only N% of agents are this archetype` · شريط رمز 8×8 بكسل · تذييل `audit yours → failproof.ai`. ثلاثة أزرار مشاركة تجلس خارج صندوق الالتقاط: `post your archetype` (X intent)، `share on linkedin`، `download poster`. يتم تشغيل الالتقاط من خلال `html-to-image` لذلك تطابق PNG العرض على الشاشة بكسل تلو الآخر (الحدود المتقطعة، قناع شعار SVG، التدرجات، مقاييس الخطوط — جميعها محفوظة).

2. **الأقوة** — قائمة الصفوف الهادئة ✓ للسلوكيات التي يقوم بها وكيلك بالفعل بشكل صحيح، مشتقة من بيانات التدقيق المباشرة (معدل استدعاء أداة نظيف، لا دفع مباشر للفرع الرئيسي، صفر تسرب بيانات اعتماد، صفر عواصف إعادة محاولة) — كل واحد يتم تسطيره فقط عندما يكون لدى السياسة ذات الصلة سجل نظيف عبر نافذة التدقيق.

3. **الغرائب** — جدول ما تسرب، مصنفة حسب الشدة: `when · what slipped + the policy that would've caught it · severity pill · seen`، حيث يقرأ التكرار `new` (مرة واحدة)، `N× seen` (2–9 مرات)، أو `recurring` (10+).

4. **كيفية التحسين** — قائمة صفوف هادئة، واحدة لكل سياسة موصوفة: اسم السياسة باللون الأبيض، وصف بسطر واحد، أمر التثبيت + زر النسخ على الجانب الأيمن. يقرأ رأس القسم `enable all N → projected <score> · <tier>` (الدرجة التي ستصل إليها مع تطبيق كل إصلاح)، وزر `[install all]` الخاص به ينسخ أمر `failproofai policy add a b c …` المدمج لكل سياسة موصوفة.

5. **العودة بشكل أفضل** — بطاقتان جنبًا إلى جنب. اليسار: اضبط تذكيرًا (اختيار إيقاع `3d` / `7d` / `14d` / `30d`; يستمر من خلال `/api/auth/reminder` بمجرد المصادقة). اليمين: فتح مزايا failproof — `invite a friend` يفتح نموذجًا يأخذ قائمة بريد إلكترونية لأصدقاء مفصولة بفواصل/مسافات/أسطر جديدة (بحد أقصى 10 لكل إرسال)، يقوم بـ POST إلى `/api/audit/invite`، الذي يحول إلى `POST /v0/invite` بخادم api. يرسل خادم api رسالة بريد إلكترونية واحدة لكل مستلم من `invite@failproof.ai` مع نسخة Cc للمرسل و `Reply-To` مضبوطة، بحيث يرى المستلم من دعاه والمرسل يحصل على نسخة في صندوق الوارد الخاص به. يتم توجيه المستخدمين المجهولين من خلال `AuthDialog` أولاً حتى يكون بريد المرسل معروفًا قبل إرسال الدعوات. تحقيق الاستحقاق/المزايا هو عملية متابعة.

مدفوع بواسطة وقت تشغيل `failproofai audit` — انظر [Audit CLI](/ar/cli/audit) لمحرك المسح الأساسي والأعلام المدعومة وثوابت الذاكرة المؤقتة لكل نسخة. تخزن لوحة التحكم أحدث نتيجة في `~/.failproofai/audit-dashboard.json` (الوضع `0600`، فتحة واحدة، التشغيلات الجديدة تستبدل) بحيث تكون الزيارات الثانية فورية; **يتم رفض كل من ذاكرة التخزين المؤقت لكل نسخة والنتيجة الإجمالية عند القراءة بمجرد تجاوز عمرها 7 أيام** لذا لا تقدم لوحة التحكم أبدًا نتيجة قديمة بصمت — بعد TTL `/audit` يسقط إلى الحالة الفارغة ويطلب تشغيلاً جديدًا. النقر على `[ re-audit now ]` بالقرب من أسفل التقرير يقوم بـ POST `/api/audit/run` مع `noCache: true` — إعادة التدقيق تتجاوز ذاكرة التخزين المؤقت لكل نسخة وتعيد مسح كل نسخة من الصفر بدلاً من إرجاع النتيجة المخزنة بصمت — ولوحة التحكم تستقصي `/api/audit/status` بـ 1Hz حتى ينتهي التشغيل; شريط تقدم وردي لزج يثبت أعلى الإطار خلال التشغيل مع مؤقت مقصود، وتحل النتيجة الطازجة محل مكانها عند النجاح (لا إعادة تحميل كاملة للصفحة; تترك إعادة تدقيق فاشلة التقرير السابق سليمًا). عند الفشل، يتحول الشريط إلى اللون الأحمر مع نسخ مفتاحة بعيدًا عن `RerunError.kind` (`timeout` / `network` / `post_failed`). يتم تسطير الحالة الفارغة (لا توجد ذاكرة تخزين مؤقت أو انتهت الصلاحية) وحالة الجلسات الصفرية (توجد ذاكرة تخزين مؤقت لكن المسح لم يعثر على أي نسخ) بشكل منفصل.

## التحديث التلقائي

توجد لوحة التحكم على تبديل التحديث التلقائي في التنقل العلوي. عند التمكين، تنعش الصفحة الحالية بشكل دوري لإظهار الجلسات الجديدة ونشاط السياسة عند ظهورها. ضروري لمراقبة جلسات الوكيل المستقل طويلة المدى.

## تعطيل الصفحات

إذا كنت تحتاج فقط إلى بعض أجزاء لوحة التحكم، اضبط `FAILPROOFAI_DISABLE_PAGES` على قائمة مفصولة بفواصل من أسماء الصفحات:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

القيم الصحيحة: `policies`، `projects`، `audit`.

---

## تكوين مسار المشاريع

افتراضيًا، تقرأ لوحة التحكم من دليل مشاريع Claude Code القياسي. اسحب جانبًا لإعدادات مخصصة:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## الوصول من مضيف بعيد عن localhost

عند تشغيل لوحة التحكم في **وضع dev** (`npm run dev`) والوصول إليها من اسم مضيف بخلاف `localhost` - على سبيل المثال، نطاق مخصص أو عنوان IP بعيد أو عنوان URL نفقي - قد تشاهد تحذيرًا مثل:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

هذا Next.js يحجب الوصول عبر الأصول إلى موارد HMR (تحديث الوحدة النمطية الساخنة) الخاصة به، وهي ميزة dev فقط. للسماح بمضيفك، استخدم علم `--allowed-origins`:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

لعدة مضيفات أو عناوين IP، مرر قائمة مفصولة بفواصل:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

يمكنك أيضًا تعيين متغير البيئة `FAILPROOFAI_ALLOWED_DEV_ORIGINS` بدلاً من ذلك:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
ينطبق هذا على وضع dev فقط. عند تشغيل `failproofai` (وضع الإنتاج)، لا يوجد موصل HMR ولا مشكلة مورد dev عبر الأصول.
</Note>
