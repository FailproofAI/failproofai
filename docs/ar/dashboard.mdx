لوحة معلومات failproofai هي تطبيق ويب محلي لمراقبة جلسات وكيل الذكاء الاصطناعي الخاص بك وإدارة السياسات. انظر إلى ما فعله وكلاؤك أثناء غيابك.

---

## بدء لوحة المعلومات

```bash
failproofai
```

يفتح على `http://localhost:8020`.

تقرأ لوحة المعلومات مباشرة من نظام الملفات - مجلدات مشاريع Claude Code وملفات تكوين failproofai. لا يتم كتابة أي شيء إلى خدمة بعيدة.

## الصفحات

### المشاريع

تسرد جميع مشاريع Claude Code و OpenAI Codex و GitHub Copilot CLI _(beta)_ و Cursor Agent _(beta)_ و OpenCode _(beta)_ و Pi _(beta)_ و Gemini CLI _(beta)_ الموجودة على جهازك. يتم اكتشاف مشاريع Claude من `~/.claude/projects/` (أو المسار المعين بواسطة `CLAUDE_PROJECTS_PATH`); يتم اكتشاف مشاريع Codex عن طريق مسح كل نسخة من السجلات تحت `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` والتجميع حسب `cwd` المسجل في السجل الأول لكل جلسة; يتم اكتشاف مشاريع Copilot CLI عن طريق مسح كل `~/.copilot/session-state/<sessionId>/workspace.yaml` (قابل للتكوين عبر `COPILOT_HOME`) والتجميع حسب حقل `cwd` الخاص به; يتم اكتشاف مشاريع Cursor Agent عن طريق مسح البيانات الوصفية لكل جلسة تحت `~/.cursor/agent-sessions/<sessionId>/` (قابل للتكوين عبر `CURSOR_HOME`، مع اختبار `conversations/` و `sessions/` كبدائل) للبحث عن عددي `cwd` في `meta.json` / `session.json` / `workspace.yaml`; يتم اكتشاف مشاريع OpenCode من خلال الاستعلام عن قاعدة البيانات SQLite الخاصة به على `~/.local/share/opencode/opencode.db` عبر `opencode db --format json` (نقرأ الجداول `session` و `project` والتجميع حسب `project_id`); يتم اكتشاف مشاريع Pi عن طريق مسح نسخ JSONL لكل جلسة تحت `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` (قابل للتكوين عبر `PI_SESSIONS_DIR`) وسحب `cwd` من السجل الأول لكل جلسة; يتم اكتشاف مشاريع Gemini CLI عن طريق مسح `~/.gemini/tmp/<basename>/chats/session-<timestamp>-<uuid-prefix>.jsonl` (قابل للتكوين عبر `GEMINI_SESSIONS_DIR`) واسترجاع cwd الكنسي من علامة نص `.project_root` المجاورة. يتم عرض المشروع الذي تم استخدامه بواسطة عدة واجهات سطر أوامر كصف واحد مع جميع الشارات المطابقة. استخدم القائمة المنسدلة **CLI** فوق الجدول للتصفية حسب واجهة سطر أوامر محددة; تحتفظ عنوان URL باختيارك كـ `?cli=claude|codex|copilot|cursor|opencode|pi|gemini`.

يعرض كل مشروع:
- اسم المشروع (مستمد من مسار المجلد)
- شارة CLI — `Claude Code` (برتقالي)، `OpenAI Codex` (بنفسجي)، `GitHub Copilot` (أزرق)، `Cursor Agent` (زمردي)، `OpenCode` (كهرماني)، `Pi` (وردي)، و/أو `Gemini CLI` (سماوي)
- تاريخ نشاط الجلسة الأخيرة

انقر على مشروع لمشاهدة جلساته.

### الجلسات

تسرد جميع الجلسات في المشروع. تعرض كل جلسة:
- معرّف الجلسة
- طوابع زمنية البدء والنهاية
- عدد استدعاءات الأدوات
- عدد نشاط الخطاف (السياسات التي تم تنشيطها)

استخدم مرشح نطاق التاريخ والبحث عن معرّف الجلسة لتضييق القائمة. يتم تقسيم الجلسات إلى صفحات.

انقر على جلسة لفتح عارض الجلسة.

### عارض الجلسة

يجيب عارض الجلسة على السؤال الرئيسي للوكلاء المستقلين: ماذا فعل الوكيل، وهل بقي على المسار الصحيح؟ تشير شارة CLI بجانب الرأس إلى ما إذا كانت الجلسة نسخة Claude Code أو OpenAI Codex أو GitHub Copilot CLI أو Cursor Agent أو OpenCode أو Pi أو Gemini CLI. يعرض خط زمني لكل ما حدث في جلسة:

- **الرسائل** - استجابات Claude النصية والمطالبات من المستخدم
- **استدعاءات الأدوات** - كل أداة استدعاها Claude، مع مدخلاتها ومخرجاتها
- **نشاط السياسة** - لكل استدعاء أداة، السياسات التي تم تنشيطها والقرار الذي أرجعته

تعرض شريط الإحصائيات في الأعلى مدة الجلسة وإجمالي استدعاءات الأدوات وملخص قرارات الخطاف (عدد السماح / الرفض / توجيه).

انقر على زر **Download Logs** لتصدير الجلسة. بالنسبة لجلسات Claude Code و Codex و Copilot و Cursor و Pi و Gemini، تحصل على نسخة JSONL الأصلية على القرص بدقة بايت لبايت; بالنسبة لـ OpenCode (التي تعيش جلساتها في SQLite، وليس على القرص) تحصل على وثيقة JSON تعكس جداول `session` / `messages` / `parts` الأساسية.

### التدقيق

تقرير مدفوع بالشخصية حول كيفية تصرف وكيلك بالفعل عبر الجلسات السابقة. يقوم بتشغيل نفس المسح الذي يقوم به CLI `failproofai audit` لكنه يعرضه كلوحة معلومات من ستة أقسام:

1. **الهوية** — تصنف وكيلك في أحد 8 نماذج أولية (`the optimist`، `the cowboy`، `the explorer`، `the goldfish`، `the paranoid architect`، `the precision builder`، `the hammer`، `the ghost`) بناءً على الكاشفات والسياسات التي تم تنشيطها ومدى شدتها. يعرض شعار 8×8 بكسل، وشعار النموذج الأولي، و "شائع في" / "المخاطر الأساسية" بصيغة، والسطر الختامي الواحد.
2. **عرض وكيلك** — يلتقط بطاقة الهوية كصورة PNG بحجم 1200×630 مناسبة للنشر على X / LinkedIn (انقر على `make poster`).
3. **نقاط القوة** — السلوكيات التي تم فحصها بالفعل والتي يقوم بها وكيلك بشكل صحيح، مشتقة من بيانات التدقيق المباشرة (معدل استدعاء الأداة النظيف، متوسط طول الجلسة، بدون تسرب بيانات اعتماد، بدون عواصف إعادة محاولة، إلخ).
4. **النقاط + قائمة الترتيب** — نقاط من 0–100 مع درجة حرف (S/A/B/C/D/F)، رسم بياني توزيعي يوضح أين تقع في المجموعة، نثر ("تبدأ B في 71. أنت بعيد 13 نقطة.")، وجدول قائمة ترتيب مع صفك المميز.
5. **النتائج** — بطاقات لكل نتيجة مصنفة حسب التأثير. تكشف كل بطاقة عما حدث، والتكلفة، عينة من الأدلة مع الأوامر المقبوضة الفعلية، وسياسة failproofai التي ستلتقط نفس النمط (`$ failproofai policy add <slug>`، انقر للنسخ).
6. **السياسات الموصى بها + حلقة الإرجاع** — شبكة لكل سياسة مدمجة غير مفعلة والتي ستسد فجوة، مع استدعاء النقاط المتوقعة، بالإضافة إلى "إعادة تدقيق في 7 أيام" CTA.

يتم تشغيله بواسطة وقت تشغيل `failproofai audit` — انظر [Audit CLI](/ar/cli/audit) لمحرك المسح الأساسي والأعلام المدعومة ثوابت ذاكرة التخزين المؤقت لكل نسخة. تخزن لوحة المعلومات أحدث النتائج في `~/.failproofai/audit-dashboard.json` (الوضع `0600`، فتحة واحدة، تستبدل التشغيل الجديد) بحيث تكون الزيارات فورية; **تم رفض ذاكرة التخزين المؤقت لكل نسخة والنتيجة الكاملة عند القراءة بمجرد أن تكون أقدم من 7 أيام** بحيث لا تخدم لوحة المعلومات صامتة نتيجة بعمر أسبوع واحد - بعد TTL `/audit` يسقط إلى حالته الفارغة ويطالب بتشغيل جديد. النقر على `[ re-audit now ]` بالقرب من أسفل التقرير يرسل بريداً إلى `/api/audit/run` وتستقصي لوحة المعلومات `/api/audit/status` بمعدل 1 هرتز حتى ينتهي التشغيل; يتم تثبيت شريط تقدم وردي لزج على أعلى المنفذ أثناء التشغيل مع مؤقت منقضٍ، والنتيجة تتبادل في الموقع عند النجاح (لا إعادة تحميل صفحة كاملة). عند الفشل، يتحول الشريط إلى الأحمر مع نسخ مفتاح إلى `RerunError.kind` (`timeout` / `network` / `post_failed`). يتم فصل الحالة الفارغة (بدون ذاكرة تخزين مؤقت أو منتهية الصلاحية) وحالة الجلسة الصفرية (توجد ذاكرة التخزين المؤقت لكن المسح لم يجد نسخ).

## التحديث التلقائي

لوحة المعلومات لديها تبديل تحديث تلقائي في التنقل العلوي. عند التفعيل، يتم تحديث الصفحة الحالية بشكل دوري لعرض الجلسات الجديدة ونشاط السياسة أثناء ظهورها. ضروري لمراقبة جلسات الوكيل المستقل طويلة الأجل.

---

## تعطيل الصفحات

إذا كنت تحتاج فقط إلى بعض أجزاء لوحة المعلومات، فاضبط `FAILPROOFAI_DISABLE_PAGES` على قائمة مفصولة بفواصل من أسماء الصفحات:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

القيم الصحيحة: `policies`، `projects`، `audit`.

---

## تكوين مسار المشاريع

بشكل افتراضي، تقرأ لوحة المعلومات من دليل مشاريع Claude Code القياسي. تجاوزها بحثاً عن الإعدادات المخصصة:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## الوصول من مضيف غير محلي

عند تشغيل لوحة المعلومات في **وضع التطوير** (`npm run dev`) والوصول إليها من اسم مضيف آخر غير `localhost` - على سبيل المثال، مجال مخصص، أو IP بعيد، أو عنوان URL بنفق - قد ترى تحذيراً مثل:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

هذا هو Next.js يحظر الوصول بين الأصول إلى websocket HMR الخاص به (إعادة تحميل الوحدة النمطية الفعلية)، والذي يعتبر ميزة خاصة بـ dev فقط. للسماح لمضيفك، استخدم العلم `--allowed-origins`:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

لعدة أجهزة كمبيوتر أو عناوين IP، مرر قائمة مفصولة بفواصل:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

يمكنك أيضاً تعيين متغير البيئة `FAILPROOFAI_ALLOWED_DEV_ORIGINS` بدلاً من ذلك:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
ينطبق هذا فقط على وضع التطوير. عند تشغيل `failproofai` (وضع الإنتاج)، لا يوجد websocket HMR ولا مشكلة في موارد dev بين الأصول.
</Note>
