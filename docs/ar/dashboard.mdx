لوحة معلومات failproofai هي تطبيق ويب محلي لمراقبة جلسات وكيل الذكاء الاصطناعي الخاص بك وإدارة السياسات. اطّلع على ما فعله وكلاؤك أثناء غيابك.

---

## بدء لوحة المعلومات

```bash
failproofai
```

يفتح على `http://localhost:8020`.

تقرأ لوحة المعلومات بيانات المشروع المحلي والجلسة وتكوين failproofai مباشرة من نظام الملفات. تُرسل الميزات المصرح بها الاختيارية، مثل تذكيرات التدقيق والدعوات، المعلومات اللازمة لتلك الطلبات (بما في ذلك عناوين البريد الإلكتروني) إلى واجهات برمجية بعيدة.

## الصفحات

### المشاريع

يسرد جميع مشاريع Claude Code و OpenAI Codex و GitHub Copilot CLI _(beta)_ و Cursor Agent _(beta)_ و OpenCode _(beta)_ و Pi _(beta)_ و Hermes و OpenClaw و Factory Droid و Devin و Antigravity و Goose الموجودة على جهازك. يتم اكتشاف مشاريع Claude من `~/.claude/projects/` (أو المسار المحدد بواسطة `CLAUDE_PROJECTS_PATH`); يتم اكتشاف مشاريع Codex من خلال مسح كل نسخة تحت `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` وتجميعها حسب `cwd` المسجل في السجل الأول لكل جلسة; يتم اكتشاف مشاريع Copilot CLI من خلال مسح كل `~/.copilot/session-state/<sessionId>/workspace.yaml` (قابل للتخصيص عبر `COPILOT_HOME`) وتجميعها حسب حقل `cwd`; يتم اكتشاف مشاريع Cursor Agent من خلال مسح البيانات الوصفية لكل جلسة تحت `~/.cursor/agent-sessions/<sessionId>/` (قابل للتخصيص عبر `CURSOR_HOME`، مع اختبار `conversations/` و `sessions/` كبدائل) عن قيمة `cwd` في `meta.json` / `session.json` / `workspace.yaml`; يتم اكتشاف مشاريع OpenCode من خلال الاستعلام عن قاعدة بيانات SQLite الخاصة بها في `~/.local/share/opencode/opencode.db` عبر `opencode db --format json` (نقرأ جداول `session` و `project` ونجمّع حسب `project_id`); يتم اكتشاف مشاريع Pi من خلال مسح نصوص JSONL لكل جلسة تحت `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` (قابل للتخصيص عبر `PI_SESSIONS_DIR`) واستخراج `cwd` من السجل الأول لكل جلسة; يتم قراءة جلسات بوابة Hermes مباشرة من متجر SQLite لكل ملف شخصي — `~/.hermes/state.db` بالإضافة إلى `~/.hermes/profiles/<name>/state.db` (قابل للتجاوز عبر `HERMES_HOME` أو `HERMES_DB_PATH` لقاعدة بيانات واحدة) — وتجميعها في مشاريع `hermes-<profile>-<source>` حسب الملف الشخصي و `source` (Slack/Telegram/cli/cron — جلسات البوابة ليس لديها cwd); يتم قراءة جلسات بوابة OpenClaw من `~/.openclaw/agents/<agentId>/sessions/*.jsonl` وتجميعها في مشاريع `openclaw-<agentId>-<channel>` حسب الوكيل والقناة (أيضًا بدون cwd); يتم اكتشاف مشاريع Factory Droid من نصوص JSONL في `~/.factory/sessions/<encoded-cwd>/*.jsonl` وتجميعها حسب cwd; مشاريع Devin من قاعدة بيانات SQLite الخاصة بها في `~/.local/share/devin/cli/sessions.db` (مجمعة حسب `working_directory` لكل جلسة); مشاريع Antigravity من نصوص JSONL في `~/.gemini/antigravity-cli/brain/<conversationId>/…/transcript_full.jsonl` وتجميعها حسب cwd; ومشاريع Goose من قاعدة بيانات SQLite الخاصة بها في `~/.local/share/goose/sessions/sessions.db` (مجمعة حسب `working_dir` لكل جلسة). يظهر المشروع الذي استخدمته أكثر من واجهة سطر أوامر واحدة كصف واحد بجميع الشارات المطابقة. استخدم القائمة المنسدلة **CLI** أعلى الجدول للتصفية حسب واجهة سطر أوامر وكيل محددة; يحتفظ الرابط باختيارك كـ `?cli=claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose`.

Hermes و OpenClaw يقتصران على الحساب الفردي وليس لديهما دليل عمل للتجميع حسبه، لذا يتم عرضهما كـ **شجرة مجلدات قابلة للطي** — الملف الشخصي (أو الوكيل) في المستوى الأعلى، ورسائله أسفله — بينما كل واجهة سطر أوامر قائمة على cwd تبقى صفًا مسطحًا. تلخص صفوف المجلدات عدد الجلسات والنشاط الأكثر حداثة لكل شيء تحتها، وتُتذكر المجلدات المطوية بين الزيارات، وكلمة بحث تتسع لأي شيء تطابقه.

يعرض كل مشروع:
- اسم المشروع (مشتق من مسار المجلد)
- شارة CLI — `Claude Code` (برتقالي)، `OpenAI Codex` (بنفسجي)، `GitHub Copilot` (أزرق)، `Cursor Agent` (أخضر زمردي)، `OpenCode` (كهرماني)، `Pi` (وردي)، و/أو `Hermes` (نيلي)
- تاريخ نشاط الجلسة الأكثر حداثة

انقر على مشروع لرؤية جلساته.

### الجلسات

يسرد جميع الجلسات داخل مشروع. تعرض كل جلسة:
- معرف الجلسة
- الطوابع الزمنية للبداية والنهاية
- عدد استدعاءات الأدوات
- عدد نشاط الخطافات (السياسات التي تم تفعيلها)

استخدم مرشح نطاق التاريخ وبحث معرف الجلسة لتضييق القائمة. يتم تقسيم الجلسات على صفحات.

انقر على جلسة لفتح عارض الجلسة.

### عارض الجلسة

يجيب عارض الجلسة على السؤال الرئيسي للوكلاء المستقلين: ماذا فعل الوكيل، وهل بقي على المسار الصحيح؟ تشير شارة CLI بجانب رأس الصفحة إلى ما إذا كانت الجلسة نسخة Claude Code أو OpenAI Codex أو GitHub Copilot CLI أو Cursor Agent أو OpenCode أو Pi أو Hermes أو OpenClaw أو Factory Droid أو Devin أو Antigravity أو Goose. تعرض خطًا زمنيًا بكل ما حدث في جلسة:

- **الرسائل** - استجابات Claude النصية وطلبات المستخدم
- **استدعاءات الأدوات** - كل أداة استدعاها Claude، مع مدخلاتها ومخرجاتها
- **نشاط السياسة** - لكل استدعاء أداة، السياسات التي تم تفعيلها والقرار الذي أرجعته

يعرض شريط الإحصائيات في الأعلى مدة الجلسة وإجمالي استدعاءات الأدوات وملخص قرارات الخطافات (عد allow / deny / instruct).

انقر على الزر **Download Logs** لتصدير الجلسة. بالنسبة لجلسات Claude Code و Codex و Copilot و Cursor و Pi، ستحصل على نسخة النص الأصلي على القرص JSONL كما هي؛ بالنسبة لـ OpenCode (التي تعيش جلساتها في SQLite، وليس على القرص)، ستحصل على مستند JSON يعكس جداول `session` / `messages` / `parts` الأساسية.

### التدقيق

تقرير يحركه الشخصية عن كيفية تصرف وكيلك بالفعل عبر الجلسات الماضية. يشغل نفس الفحص مثل CLI `failproofai audit` لكن يعرضه كملصق على شاشة واحدة قابل للمشاركة + أربعة أقسام أسفل الطية:

1. **الملصق** — يملأ عرض النافذة الأول. منطقة PNG قابلة للالتقاط مكتفية ذاتيًا تحتوي على شعار failproof_ai + تسمية التدقيق · مؤشر النموذج الأولي (`№ NN of 08`) + تاريخ التدقيق · درجة رقمية (0–100) + حبة ترتيب النسبة المئوية (`top 15%`) · اسم النموذج الأولي (واحد من `the optimist` و `the cowboy` و `the explorer` و `the goldfish` و `the paranoid architect` و `the precision builder` و `the hammer` و `the ghost`) + شريط 3 كلمات · سطر ندرة `// only N% of agents are this archetype` · بلاط sigil 8×8 بكسل · تذييل `audit yours → failproof.ai`. تجلس ثلاثة أزرار مشاركة خارج صندوق الالتقاط: `post your archetype` (نية X)، `share on linkedin`، `download poster`. يتم الالتقاط عبر `html-to-image` لذا يطابق PNG عرض الشاشة بكسل تلو بكسل (الحدود المتقطعة، قناع شعار SVG، التدرجات، مقاييس الخط — كل شيء محفوظ).
2. **نقاط القوة** — قائمة صفوف هادئة من السلوكيات التي يقوم بها وكيلك بالفعل بشكل صحيح، مشتقة من بيانات التدقيق المباشرة (معدل استدعاء أداة نظيف، لا توجد عمليات دفع مباشرة للرئيسية، لا تسريب بيانات اعتماد، لا عواصف إعادة محاولة) — يتم عرض كل واحدة فقط عندما تحتفظ السياسة ذات الصلة بسجل نظيف عبر نافذة التدقيق.
3. **الغرائب** — جدول بما انزلق، مرتبة حسب الخطورة: `when · what slipped + the policy that would've caught it · severity pill · seen`، حيث تقرأ التكرار `new` (مرة واحدة)، `N× seen` (2–9 مرات)، أو `recurring` (10+).
4. **كيفية التحسين** — قائمة صفوف هادئة، واحدة لكل سياسة موصى بها: اسم السياسة بالأبيض، وصف سطر واحد، أمر التثبيت + زر النسخ على الجانب الأيمن. يقرأ رأس القسم `enable all N → projected <score> · <tier>` (الدرجة التي ستصل إليها مع تطبيق كل إصلاح)، وزره `[install all]` ينسخ الأمر `failproofai policy add a b c …` المدمج لكل سياسة موصى بها.
5. **عد بشكل أفضل** — بطاقتان جنبًا إلى جنب. اليسار: اضبط تذكيرًا (منتقي قالب `3d` / `7d` / `14d` / `30d`; يستمر عبر `/api/auth/reminder` بمجرد المصادقة). اليمين: فتح مزايا failproof — `invite a friend` يفتح نموذجًا يأخذ قائمة بريد إلكترونية للأصدقاء مفصولة بفواصل/مسافات/أسطر جديدة (200 كحد أقصى لكل إرسال)، POSTs الحد الأقصى إلى `/api/audit/invite`، الذي يعيد التوجيه إلى `POST /v0/invite` على خادم api. يرسل خادم api بريدًا إلكترونيًا واحدًا لكل متلقٍ من `invite@failproof.ai` مع نسخ المرسل وتعيين `Reply-To`، لذا يرى المتلقي من دعاه والمرسل يحصل على نسخة في بريده الوارد. يتم توجيه المستخدمين المجهولين عبر `AuthDialog` أولاً بحيث يكون بريد المرسل معروفًا قبل إرسال الدعوات. الاستحقاق وتنفيذ المزايا هو ما يتبع ذلك.

يحركه وقت تشغيل `failproofai audit` — انظر [Audit CLI](/ar/cli/audit) لمحرك الفحص الأساسي والأعلام المدعومة وثوابت التخزين المؤقت لكل نسخة. تخزن لوحة المعلومات النتيجة الأخيرة في `~/.failproofai/audit-dashboard.json` (الوضع `0600`، فتحة واحدة، عمليات التشغيل الجديدة تحل محل) لذا تكون إعادة الزيارة فورية؛ **يتم رفض كل من التخزين المؤقت لكل نسخة والنتيجة الكاملة عند القراءة بمجرد أن تصبح أقدم من 7 أيام** لذا لا تقدم لوحة المعلومات نتيجة بعمر أسبوع بصمت — بعد انتهاء TTL يسقط `/audit` في حالته الفارغة ويطلب تشغيلًا جديدًا. ينشر النقر على `[ re-audit now ]` بالقرب من أسفل التقرير `/api/audit/run` مع `noCache: true` — تجاوز إعادة التدقيق التخزين المؤقت لكل نسخة وإعادة فحص كل نسخة من البداية بدلاً من الإرجاع الصامت للنتيجة المخزنة مؤقتًا — وتستقصي لوحة المعلومات `/api/audit/status` بمعدل 1Hz حتى ينتهي التشغيل; يثبت شريط تقدم وردي لاصق أعلى عرض النافذة أثناء التشغيل مع مؤقت مضى، والنتيجة الطازجة تحل محل في المكان عند النجاح (لا إعادة تحميل كاملة للصفحة؛ فشل إعادة التدقيق يترك التقرير السابق سليمًا). عند الفشل، يتحول الشريط إلى الأحمر مع نسخ مفتاح خارج `RerunError.kind` (`timeout` / `network` / `post_failed`). يتم عرض الحالة الفارغة (لا يوجد تخزين مؤقت أو منتهي الصلاحية) وحالة الصفر-جلسات (موجود تخزين مؤقت لكن الفحص لم يجد نصوصًا) بشكل منفصل.

## التحديث التلقائي

تحتوي لوحة المعلومات على تبديل تحديث تلقائي في الملاحة العلوية. عند تفعيله، تحدث الصفحة الحالية بشكل دوري لعرض جلسات جديدة ونشاط سياسة وهي تظهر. ضروري لمراقبة جلسات الوكلاء المستقلين طويلة المدى.

---

## تعطيل الصفحات

إذا كنت تحتاج فقط إلى بعض أجزاء لوحة المعلومات، عيّن `FAILPROOFAI_DISABLE_PAGES` إلى قائمة مفصولة بفواصل من أسماء الصفحات:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

القيم الصحيحة: `policies` و `projects` و `audit`.

---

## تكوين مسار المشاريع

بشكل افتراضي، تقرأ لوحة المعلومات من دليل مشاريع Claude Code القياسي. تجاوزها للإعدادات المخصصة:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## الوصول من مضيف غير localhost

عند تشغيل لوحة المعلومات في **وضع dev** (`npm run dev`) والوصول إليها من اسم مضيف آخر غير `localhost` - على سبيل المثال، مجال مخصص أو عنوان IP بعيد أو رابط نفق — قد تشاهد تحذيرًا مثل:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

هذا هو Next.js يحظر الوصول عبر الأصول إلى ويب سوكيت HMR (التحديث الفوري للوحدة)، وهي ميزة خاصة بـ dev فقط. للسماح للمضيف الخاص بك، استخدم علم `--allowed-origins`:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

لعدة مضيفات أو عناوين IP، مرر قائمة مفصولة بفواصل:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

يمكنك أيضًا تعيين متغير البيئة `FAILPROOFAI_ALLOWED_DEV_ORIGINS` بدلاً من ذلك:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
هذا ينطبق فقط على وضع dev. عند تشغيل `failproofai` (وضع الإنتاج)، لا يوجد ويب سوكيت HMR وليس هناك مشكلة مورد dev عبر الأصول.
</Note>
