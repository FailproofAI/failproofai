يقرأ تقييم Jev **جلسة منتهية** ويعطيها درجة من 0 إلى 1. استخدمه عندما تكون الإجابة معروفة مسبقاً، مثل "هل عبّر العميل عن الاستعجالية؟" أو "ما مدى إحباط العميل؟" يساعدك على إيجاد أنماط عبر التشغيلات؛ لا يوقف استدعاء أداة. للقرارات المتخذة **قبل** تشغيل أداة، استخدم [سياسات Jev](/ar/policies/jev).

## أنشئ واحدة في لوحة التحكم

1. افتح **analyse → checks → new evaluation** واختر **decision model** تحت **how should it score?**.
2. صِف سؤالاً واحداً وإجاباته الممكنة. على سبيل المثال: "هل وعد الوكيل برد مالي قبل التحقق من سياسة الاسترجاع؟ أجب نعم أو لا." في **review**، تحقق من **السؤال** وما يعنيه **نعم** و**لا**؛ نموذج القرار يعطي دائماً درجة.
3. [جرّبه](/ar/evaluations/test) على الجلسات الأخيرة، ثم [نشره](/ar/evaluations/deploy). يتم تقييم الجلسات المكتملة الجديدة؛ [استرجع البيانات القديمة](/ar/evaluations/deploy#score-sessions-you-already-have) إذا كنت تحتاج أيضاً إلى السجل التاريخي.

![نموذج تأليف التقييم المشترك، حيث تصف سؤالاً بإجابة ثابتة، وتراجع المسودة، وتنشر بعد الاختبار. المثال الموضح هو تقييم كود؛ سؤال Jev يستخدم نفس تدفق التأليف.](/images/dashboard/eval-authoring-draft.png)

عندما يقوم بالمسودة، يمكن لـ failproof أن يختار بين **كود**، **نموذج قرار** (Jev)، و[**llm as judge**](/ar/evaluations/judge). تحقق من اختياره قبل النشر. Jev يعطي درجة بدون تفسير نصي؛ اختر حاكماً عندما تحتاج إلى شرح. انظر [مرجع تقييم Jev](/ar/reference/jev-evaluations) لأنواع الأسئلة وحدود الدرجات.

## اقرأ الدرجات

افتح **analyse → checks → evals** واختر التقييم لرسم النتيجة حسب الوكيل والوقت. من محطة طرفية، يمكن لـ Cloud CLI قراءة نفس النتائج:

```bash
fp evals --since 7d
fp evals --aggregate --since 7d
```

من محطة طرفية، `fp evaluators` ينشئ وينشر تقييمات Jev و`fp evals` يقرأ نتائجها. انظر [مرجع Cloud CLI](/ar/reference/cloud-cli#evaluations) لكليهما.
