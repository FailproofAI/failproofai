يقرأ تقييم Jev **جلسة منتهية** ويعطيها درجة من 0 إلى 1. استخدمه عندما تكون الإجابة معروفة مسبقاً، مثل "هل عبّر العميل عن الاستعجالية؟" أو "ما مدى إحباط العميل؟" يساعدك في إيجاد أنماط عبر الجلسات؛ لا يوقف استدعاء الأداة. للقرارات المتخذة **قبل** تشغيل الأداة، استخدم [سياسات Jev](/ar/policies/jev).

## أنشئ واحداً في لوحة المعلومات

1. افتح **analyse → checks → new evaluation** واختر **decision model** تحت **how should it score?**.
2. اشرح سؤالاً واحداً وإجاباته الممكنة. على سبيل المثال: "هل وعد الوكيل برد المبلغ قبل التحقق من سياسة الاسترجاع؟ أجب بنعم أو لا." في **review**، تحقق من **السؤال** وما يعنيه **نعم** و**لا**؛ نموذج القرار يعطي دائماً درجة.
3. [جربه](/ar/evaluations/test) على الجلسات الأخيرة، ثم [نشره](/ar/evaluations/deploy). يتم تقييم الجلسات المكتملة الجديدة؛ [املأ السجل](/ar/evaluations/deploy#score-sessions-you-already-have) إذا كنت تحتاج أيضاً إلى السجل التاريخي.

عند الصياغة، يمكن لـ failproof أن تختار بين **code** و**نموذج القرار** (Jev) و[**llm as judge**](/ar/evaluations/judge). تحقق من اختيارها قبل النشر. Jev تعطي درجة بدون تفسيرات نصية؛ اختر قاضي عندما تحتاج إلى شرح. انظر [مرجع تقييم Jev](/ar/reference/jev-evaluations) لأنواع الأسئلة وحدود الدرجات.

## اقرأ الدرجات

افتح **analyse → checks → evals** واختر التقييم لرسم النتيجة حسب الوكيل والوقت. من محطة طرفية، يمكن لـ Cloud CLI قراءة نفس النتائج:

```bash
fp evals --since 7d
fp evals --aggregate --since 7d
```

من محطة طرفية، `fp evaluators` تؤلف وتنشر تقييمات Jev و `fp evals` تقرأ نتائجها. انظر [مرجع Cloud CLI](/ar/reference/cloud-cli#evaluations) لكليهما.
