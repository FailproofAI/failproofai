## إعداد الخطاطيف (Hooks) لـ Claude Code

يتكامل Failproof AI مع Claude Code عبر [نظام الخطاطيف](https://docs.anthropic.com/en/docs/claude-code/hooks). عند تشغيل `failproofai policies --install`، يتم تسجيل أوامر الخطاطيف في `settings.json` الخاص بـ Claude Code التي تعمل عند كل استدعاء أداة.

<Steps>
  <Step title="تثبيت failproofai">
    ```bash
    npm install -g failproofai
    ```
  </Step>
  <Step title="تفعيل جميع السياسات المدمجة">
    ```bash
    failproofai policies --install
    ```
  </Step>
  <Step title="التحقق من تسجيل الخطاطيف">
    ```bash
    cat ~/.claude/settings.json | grep failproofai
    ```

    يجب أن ترى إدخالات خطاطيف لأحداث `PreToolUse`، `PostToolUse`، `Notification`، و `Stop`.
  </Step>
  <Step title="تشغيل Claude Code">
    ```bash
    claude
    ```

    تعمل السياسات تلقائياً عند كل استدعاء أداة. حاول طلب Claude لتشغيل `sudo rm -rf /` - سيتم حجبها.
  </Step>
</Steps>

## إعداد الخطاطيف (Hooks) لـ Agents SDK

إذا كنت تبني باستخدام [Agents SDK](https://docs.anthropic.com/en/docs/agents-sdk)، يمكنك استخدام نفس نظام الخطاطيف برمجياً.

<Steps>
  <Step title="تثبيت failproofai في مشروعك">
    ```bash
    npm install failproofai
    ```
  </Step>
  <Step title="تكوين الخطاطيف في وكيلك">
    مرر أوامر الخطاطيف عند إنشاء عملية الوكيل. تعمل الخطاطيف بنفس الطريقة كما في Claude Code - عبر JSON في stdin/stdout:

    ```bash
    failproofai --hook PreToolUse   # يُستدعى قبل كل أداة
    failproofai --hook PostToolUse  # يُستدعى بعد كل أداة
    ```
  </Step>
  <Step title="اكتب سياسة مخصصة لوكيلك">
    ```javascript
    import { customPolicies, allow, deny } from "failproofai";

    customPolicies.add({
      name: "limit-to-project-dir",
      description: "اجعل الوكيل داخل مجلد المشروع",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        const path = String(ctx.toolInput?.file_path ?? "");
        if (path.startsWith("/") && !path.startsWith(ctx.session?.cwd ?? "")) {
          return deny("الوكيل مقتصر على مجلد المشروع");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="تثبيت السياسة المخصصة">
    ```bash
    failproofai policies --install --custom ./my-agent-policies.js
    ```
  </Step>
</Steps>

## حجب الأوامر الضارة

الإعداد الأكثر شيوعاً - منع الوكلاء من إحداث ضرر لا يمكن إصلاحه.

```bash
failproofai policies --install block-sudo block-rm-rf block-force-push block-curl-pipe-sh
```

ما يفعله:
- `block-sudo` - يحجب جميع أوامر `sudo`
- `block-rm-rf` - يحجب حذف الملفات بشكل متكرر
- `block-force-push` - يحجب `git push --force`
- `block-curl-pipe-sh` - يحجب إرسال النصوص البعيدة إلى shell

## منع تسرب الأسرار

منع الوكلاء من رؤية أو تسرب بيانات الاعتماد في مخرجات الأداة.

```bash
failproofai policies --install sanitize-api-keys sanitize-jwt sanitize-connection-strings sanitize-bearer-tokens
```

تعمل هذه السياسات على `PostToolUse` - بعد تشغيل الأداة، تقوم بتنظيف المخرجات قبل أن يراها الوكيل.

## الحصول على تنبيهات Slack عندما يحتاج الوكلاء إلى اهتمام

استخدم خطاف الإشعار لإعادة توجيه تنبيهات الخمول إلى Slack.

```javascript
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "slack-on-idle",
  description: "تنبيه Slack عندما ينتظر الوكيل الإدخال",
  match: { events: ["Notification"] },
  fn: async (ctx) => {
    const webhookUrl = process.env.SLACK_WEBHOOK_URL;
    if (!webhookUrl) return allow();

    const message = String(ctx.payload?.message ?? "الوكيل ينتظر");
    const project = ctx.session?.cwd ?? "unknown";

    try {
      await fetch(webhookUrl, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          text: `*${message}*\nProject: \`${project}\``,
        }),
        signal: AbortSignal.timeout(5000),
      });
    } catch {
      // لا تحجب الوكيل أبداً إذا كان Slack غير قابل للوصول
    }

    return allow();
  },
});
```

ثبّته:

```bash
SLACK_WEBHOOK_URL=https://hooks.slack.com/... failproofai policies --install --custom ./slack-alerts.js
```

## اجعل الوكلاء على فرع محدد

منع الوكلاء من تبديل الفروع أو الدفع إلى الفروع المحمية.

```javascript
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "stay-on-branch",
  description: "منع الوكيل من الانتقال إلى فروع أخرى",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = String(ctx.toolInput?.command ?? "");
    if (/git\s+checkout\s+(?!-b)/.test(cmd)) {
      return deny("ابق على الفرع الحالي. أنشئ فرعاً جديداً بـ -b إذا لزم الأمر.");
    }
    return allow();
  },
});
```

## طلب الاختبارات قبل الالتزام

تذكير الوكلاء بتشغيل الاختبارات قبل الالتزام.

```javascript
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "test-before-commit",
  description: "تذكير الوكيل بتشغيل الاختبارات قبل الالتزام",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = String(ctx.toolInput?.command ?? "");
    if (/git\s+commit/.test(cmd)) {
      return instruct("شغّل الاختبارات قبل الالتزام. استخدم `npm test` أو `bun test` أولاً.");
    }
    return allow();
  },
});
```

## قفل مستودع الإنتاج

التزم بتكوين على مستوى المشروع بحيث يحصل كل مطور في فريقك على نفس السياسات.

أنشئ `.failproofai/policies-config.json` في مستودعك:

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-force-push",
    "block-push-master",
    "block-env-files",
    "sanitize-api-keys",
    "sanitize-jwt"
  ],
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "release", "production"]
    }
  }
}
```

ثم التزم به:

```bash
git add .failproofai/policies-config.json
git commit -m "Add failproofai team policies"
```

كل عضو في الفريق لديه failproofai مثبت سيختار هذه القواعد تلقائياً.

## بناء معيار جودة على مستوى المؤسسة مع سياسات الاتفاقية

الإعداد الأكثر تأثيراً: التزم بـ `.failproofai/policies/` في مستودعك مع سياسات مخصصة لمشروعك. يحصل كل عضو في الفريق عليها تلقائياً - بدون أوامر تثبيت، بدون تغييرات في الإعداد.

<Steps>
  <Step title="أنشئ المجلد وأضف السياسات">
    ```bash
    mkdir -p .failproofai/policies
    ```

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    // فرض مدير الحزم المفضل لفريقك
    // (أو فعّل سياسة prefer-package-manager المدمجة بدلاً من ذلك)
    customPolicies.add({
      name: "enforce-bun",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        const cmd = String(ctx.toolInput?.command ?? "");
        if (/\bnpm\b/.test(cmd)) return deny("استخدم bun بدلاً من npm.");
        return allow();
      },
    });

    // تذكير الوكيل بتشغيل الاختبارات قبل الالتزام
    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("شغّل الاختبارات قبل الالتزام.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="التزم بـ git">
    ```bash
    git add .failproofai/policies/
    git commit -m "Add team quality policies"
    ```
  </Step>
  <Step title="استمر في التحسين">
    مع مواجهة فريقك لأنماط فشل جديدة، أضف السياسات واضغط. يحصل الجميع على التحديث عند `git pull` التالي. تصبح هذه السياسات معياراً حياً للجودة ينمو مع فريقك.
  </Step>
</Steps>

## أمثلة أخرى

يحتوي دليل [`examples/`](https://github.com/failproofai/failproofai/tree/main/examples) في المستودع على:

| الملف | ما يوضحه |
|------|----------|
| `policies-basic.js` | سياسات المبتدئين - حجب كتابات الإنتاج، الدفع القسري، النصوص المرسلة |
| `policies-notification.js` | تنبيهات Slack لإشعارات الخمول ونهاية الجلسة |
| `policies-advanced/index.js` | الواردات المتعدية، خطاطيف غير متزامنة، تنظيف مخرجات PostToolUse، معالجة أحداث Stop |
