## البدء السريع

<Steps>
  <Step title="تفعيل السياسات">
    السياسات هي قواعد تعمل قبل وبعد كل استدعاء أداة وكيل. فهي تلتقط الأوامر المدمرة، وتسرب الأسرار، وأنماط الفشل الأخرى قبل أن تسبب الضرر.

    ```bash
    failproofai policies --install
    ```

    هذا يكتب إدخالات خطافية في أدوات سطر الأوامر المثبتة لديك (Claude Code في `~/.claude/settings.json`، OpenAI Codex في `~/.codex/hooks.json`، GitHub Copilot CLI في `~/.copilot/hooks/failproofai.json`، Cursor Agent في `~/.cursor/hooks.json`، OpenCode في ملف المكون المُنشأ في `~/.config/opencode/plugins/failproofai.mjs` مع إدخال التسجيل في مصفوفة `plugin` في `~/.config/opencode/opencode.json`، Pi في `~/.pi/agent/settings.json`، Hermes في `~/.hermes/config.yaml`، OpenClaw في `~/.openclaw/openclaw.json`، Factory Droid في `~/.factory/hooks.json`، Devin CLI في `~/.config/devin/config.json`، Antigravity CLI في `~/.gemini/config/hooks.json`، أو Goose في دليل المكون المكتشف تلقائياً في `~/.agents/plugins/failproofai/hooks/hooks.json`). عندما يكون أكثر من واحد موجوداً، ستُطالب بالاختيار؛ مرر `--cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose` (أي مجموعة جزئية) لتخطي الطلب.

    GitHub Copilot CLI و Cursor Agent و OpenCode و Pi مدعومة بشكل **تجريبي** — قم بالتثبيت باستخدام `--cli copilot` أو `--cli cursor` أو `--cli opencode` أو `--cli pi`. Hermes (hermes-agent، بوابة Slack/Telegram) يتم تثبيتها على نطاق المستخدم باستخدام `--cli hermes` وهي **أيضاً** مصدر تدقيق غير متصل. OpenClaw (بوابة openclaw، مساعد متعدد القنوات مستضاف ذاتياً) يتم تثبيتها على نطاق المستخدم باستخدام `--cli openclaw` — ينفذ الفرض من خلال خطافات المكون داخل العملية (`before_agent_finalize` هو بوابة نهاية دور حقيقية، لذا تفرض المدمجات `require-*-before-stop`) — وهي **أيضاً** مصدر تدقيق غير متصل. Factory Droid (`droid`) يتم تثبيتها باستخدام `--cli factory` (نطاق المستخدم والمشروع) وهي **أيضاً** مصدر تدقيق غير متصل. Devin CLI (`devin`، Cognition) يتم تثبيتها باستخدام `--cli devin` (نطاق المستخدم والمشروع) وهي **أيضاً** مصدر تدقيق غير متصل. Antigravity CLI (`agy`) يتم تثبيتها باستخدام `--cli antigravity` (نطاق المستخدم والمشروع) وهي **أيضاً** مصدر تدقيق غير متصل. Goose (اسم الرمز goose، Block) يتم تثبيتها باستخدام `--cli goose` (نطاق المستخدم والمشروع) — يقوم المثبت ببساطة بإسقاط دليل مكون في `~/.agents/plugins/failproofai/` الذي يكتشفه Goose تلقائياً، وهو **أيضاً** مصدر تدقيق غير متصل.

    ```bash
    failproofai policies --install --scope project
    failproofai policies --install --cli codex --scope project
    failproofai policies --install --cli copilot --scope project
    failproofai policies --install --cli cursor --scope project
    failproofai policies --install --cli opencode --scope project
    failproofai policies --install --cli pi --scope project
    failproofai policies --install --cli hermes --scope user
    failproofai policies --install --cli openclaw --scope user
    failproofai policies --install --cli factory --scope project
    failproofai policies --install --cli devin --scope project
    failproofai policies --install --cli antigravity --scope project
    failproofai policies --install --cli goose --scope project
    failproofai policies --install block-sudo block-rm-rf sanitize-api-keys
    ```
  </Step>
  <Step title="التحقق">
    ```bash
    failproofai policies
    ```

    يعرض كل سياسة، سواء كانت مفعّلة، وأي معاملات مكوّنة.
  </Step>
  <Step title="تشغيل لوحة المعلومات">
    ```bash
    failproofai
    ```

    يفتح لوحة معلومات محلية في `http://localhost:8020` حيث يمكنك استعراض الجلسات، وفحص استدعاءات الأداة، وإدارة السياسات.
  </Step>
  <Step title="قم بتشغيل الوكيل الخاص بك">
    ابدأ Claude Code كالمعتاد. إذا حاول الوكيل شيئاً محفوفاً بالمخاطر، سيقطعه failproofai تلقائياً. اتركه قيد التشغيل دون مراقبة واستعرض ما حدث في لوحة المعلومات.
  </Step>
</Steps>

## كيف تعمل السياسات

في كل مرة يقوم فيها الوكيل بتشغيل أداة، يستدعي Claude Code failproofai كعملية فرعية:

```text
Claude Code  →  failproofai --hook PreToolUse  →  reads stdin JSON
                                                 evaluates policies
                                                 writes decision to stdout
```

تُرجع كل سياسة واحداً من ثلاثة قرارات:

- **allow** - يتابع الوكيل بشكل طبيعي
- **deny** - يتم حظر الإجراء، ويُخبر الوكيل بالسبب
- **instruct** - يتم إضافة سياق إضافي إلى طلب الوكيل

<Note>
تعمل السياسات في عمليتك المحلية. لا يتم إرسال أي شيء إلى خدمة بعيدة.
</Note>

## إعداد سياسات الفريق باستخدام السياسات القائمة على الاتفاقية

أسرع طريقة لإنشاء معايير الجودة عبر فريقك هي اتفاقية `.failproofai/policies/`. أسقط ملفات السياسات في هذا الدليل وسيتم تحميلها تلقائياً — بدون أعلام، بدون تغييرات الإعدادات، بدون أوامر التثبيت.

<Steps>
  <Step title="إنشاء دليل السياسات">
    ```bash
    mkdir -p .failproofai/policies
    ```
  </Step>
  <Step title="إضافة ملفات السياسات">
    انسخ الأمثلة الأولية أو اكتب الخاصة بك:

    ```bash
    cp node_modules/failproofai/examples/convention-policies/*.mjs .failproofai/policies/
    ```

    أو أنشئ واحداً جديداً:

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Run tests before committing.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="الالتزام بـ git">
    ```bash
    git add .failproofai/policies/
    git commit -m "Add team quality policies"
    ```

    يلتقط كل عضو في الفريق الذي لديه failproofai مثبت هذه السياسات تلقائياً. لا توجد حاجة إلى إعداد لكل مطور.
  </Step>
</Steps>

<Tip>
التزم بـ `.failproofai/policies/` في المستودع الخاص بك بحيث يشارك الفريق بأكمله نفس المعايير. مع اكتشاف فريقك لأنماط فشل جديدة، أضف السياسات واضغط — يحصل الجميع على التحديث عند `git pull` التالي لهم. بمرور الوقت، تصبح هذه السياسات معيار جودة حي يستمر في التحسن.
</Tip>

## تخزين البيانات

تبقى جميع الإعدادات والسجلات على جهازك:

| المسار | ما تخزنه |
|------|----------------|
| `~/.failproofai/policies/local-policies/policies-config.json` | إعدادات السياسة العامة |
| `~/.failproofai/hook-activity/` | سجل تنفيذ الخطافات (JSONL مقسمة) |
| `~/.failproofai/logs/` | سجلات التصحيح لأخطاء الخطاف المخصص |
| `.failproofai/policies-config.json` | إعدادات كل مشروع (معترف بها) |
| `.failproofai/policies-config.local.json` | الإجراءات الشخصية (مدرجة في gitignore) |

---

## إلغاء التثبيت

```bash
failproofai policies --uninstall
```

يزيل إدخالات الخطافات من `~/.claude/settings.json`. يتم الاحتفاظ بملفات الإعدادات في `~/.failproofai/`.
