## البدء السريع

<Steps>
  <Step title="تفعيل السياسات">
    السياسات هي قواعد تعمل قبل وبعد كل استدعاء أداة من الوكيل. تقوم بالقبض على الأوامر التخريبية وتسرب الأسرار وأوضاع الفشل الأخرى قبل أن تسبب ضررًا.

    ```bash
    failproofai policies --install
    ```

    يكتب هذا مدخلات الخطاف في أدوات سطر الأوامر المثبتة للوكيل (ملف `~/.claude/settings.json` الخاص بـ Claude Code، ملف `~/.codex/hooks.json` الخاص بـ OpenAI Codex، ملف `~/.copilot/hooks/failproofai.json` الخاص بـ GitHub Copilot CLI، ملف `~/.cursor/hooks.json` الخاص بـ Cursor Agent، مجلد البرنامج المساعد المولد من OpenCode في `~/.config/opencode/plugins/failproofai.mjs` بالإضافة إلى مدخل تسجيل في صفيف `plugin` في `~/.config/opencode/opencode.json`، ملف `~/.pi/agent/settings.json` الخاص بـ Pi، ملف `~/.hermes/config.yaml` الخاص بـ Hermes، ملف `~/.openclaw/openclaw.json` الخاص بـ OpenClaw، ملف `~/.factory/hooks.json` الخاص بـ Factory Droid، ملف `~/.config/devin/config.json` الخاص بـ Devin CLI، ملف `~/.gemini/config/hooks.json` الخاص بـ Antigravity CLI، أو مجلد البرنامج المساعد المكتشف تلقائيًا الخاص بـ Goose في `~/.agents/plugins/failproofai/hooks/hooks.json`). عند وجود أكثر من واحد ستتم مطالبتك؛ مرر `--cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose` (أي مجموعة فرعية) لتخطي المطالبة.

    GitHub Copilot CLI و Cursor Agent و OpenCode و Pi **نسخة تجريبية** — قم بالتثبيت باستخدام `--cli copilot` أو `--cli cursor` أو `--cli opencode` أو `--cli pi`. Hermes (hermes-agent، بوابة Slack/Telegram) يتم تثبيتها بنطاق المستخدم باستخدام `--cli hermes` وهي **أيضًا** مصدر تدقيق غير متصل. OpenClaw (بوابة openclaw، مساعد متعدد القنوات ذاتي الاستضافة) يتم تثبيتها بنطاق المستخدم باستخدام `--cli openclaw` — يتم تطبيق الفرض من خلال خطاطيف البرنامج المساعد داخل العملية (`before_agent_finalize` هي بوابة نهاية دور حقيقية، لذا تطبق ملفات `require-*-before-stop` المدمجة) — وهي **أيضًا** مصدر تدقيق غير متصل. Factory Droid (`droid`) يتم تثبيتها باستخدام `--cli factory` (نطاق المستخدم والمشروع) وهي **أيضًا** مصدر تدقيق غير متصل. Devin CLI (`devin`، Cognition) يتم تثبيتها باستخدام `--cli devin` (نطاق المستخدم والمشروع) وهي **أيضًا** مصدر تدقيق غير متصل. Antigravity CLI (`agy`) يتم تثبيتها باستخدام `--cli antigravity` (نطاق المستخدم والمشروع) وهي **أيضًا** مصدر تدقيق غير متصل. Goose (اسم رمز goose، Block) يتم تثبيتها باستخدام `--cli goose` (نطاق المستخدم والمشروع) — يقوم المثبت ببساطة بإسقاط مجلد البرنامج المساعد في `~/.agents/plugins/failproofai/` الذي يكتشفه Goose تلقائيًا، وهي **أيضًا** مصدر تدقيق غير متصل.

    ```bash
    failproofai policies --install --scope project
    failproofai policies --install --cli codex --scope project
    failproofai policies --install --cli copilot --scope project
    failproofai policies --install --cli cursor --scope project
    failproofai policies --install --cli opencode --scope project
    failproofai policies --install --cli pi --scope project
    failproofai policies --install --cli hermes --scope user
    failproofai policies --install --cli openclaw --scope user
    failproofai policies --install --cli factory --scope project
    failproofai policies --install --cli devin --scope project
    failproofai policies --install --cli antigravity --scope project
    failproofai policies --install --cli goose --scope project
    failproofai policies --install block-sudo block-rm-rf sanitize-api-keys
    ```
  </Step>
  <Step title="التحقق">
    ```bash
    failproofai policies
    ```

    يعرض كل سياسة، سواء كانت مفعلة، وأي معاملات مكونة.
  </Step>
  <Step title="تشغيل لوحة المعلومات">
    ```bash
    failproofai
    ```

    يفتح لوحة معلومات محلية على `http://localhost:8020` حيث يمكنك استعراض الجلسات وفحص استدعاءات الأدوات وإدارة السياسات.
  </Step>
  <Step title="تشغيل الوكيل">
    ابدأ Claude Code كالمعتاد. إذا حاول الوكيل فعل شيء محفوف بالمخاطر، سيقوم failproofai باعتراضه تلقائيًا. اتركه يعمل دون مراقبة وراجع ما حدث في لوحة المعلومات.
  </Step>
</Steps>

## كيفية عمل السياسات

في كل مرة يقوم الوكيل بتشغيل أداة، يستدعي Claude Code failproofai كعملية فرعية:

```text
Claude Code  →  failproofai --hook PreToolUse  →  يقرأ JSON من stdin
                                                 يقيّم السياسات
                                                 يكتب القرار إلى stdout
```

تعيد كل سياسة واحدة من ثلاثة قرارات:

- **allow** - يتابع الوكيل بشكل طبيعي
- **deny** - يتم حظر الإجراء، يتم إخبار الوكيل بالسبب
- **instruct** - يتم إضافة سياق إضافي إلى موجه الوكيل

<Note>
تعمل السياسات في عمليتك المحلية. لا يتم إرسال أي شيء إلى خدمة بعيدة.
</Note>

## إعداد سياسات الفريق باستخدام السياسات المبنية على الاتفاقية

الطريقة الأسرع لإنشاء معايير جودة في جميع أنحاء الفريق هي اتفاقية `.failproofai/policies/`. أسقط ملفات السياسات في هذا الدليل وسيتم تحميلها تلقائيًا — لا أعلام، لا تغييرات في الإعدادات، لا أوامر تثبيت.

<Steps>
  <Step title="إنشاء دليل السياسات">
    ```bash
    mkdir -p .failproofai/policies
    ```
  </Step>
  <Step title="إضافة ملفات السياسات">
    انسخ أمثلة البدء أو اكتب الخاص بك:

    ```bash
    cp node_modules/failproofai/examples/convention-policies/*.mjs .failproofai/policies/
    ```

    أو أنشئ واحدًا جديدًا:

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("قم بتشغيل الاختبارات قبل الالتزام.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="الالتزام بـ git">
    ```bash
    git add .failproofai/policies/
    git commit -m "إضافة سياسات جودة الفريق"
    ```

    يختار كل عضو في الفريق لديه failproofai مثبت هذه السياسات تلقائيًا. لا حاجة لإعداد منفصل لكل مطور.
  </Step>
</Steps>

<Tip>
التزم بـ `.failproofai/policies/` في مستودعك حتى يشاركك الفريق بأكمله نفس المعايير. مع اكتشاف الفريق لأوضاع فشل جديدة، أضف سياسات وادفع — يحصل الجميع على التحديث عند `git pull` التالي. بمرور الوقت تصبح هذه السياسات معيار جودة حي يستمر في التحسن.
</Tip>

## تخزين البيانات

تبقى جميع الإعدادات والسجلات على جهازك:

| المسار | ما يخزنه |
|------|----------------|
| `~/.failproofai/policies-config.json` | إعدادات السياسة العام |
| `~/.failproofai/policies/` | السياسات الخاصة بك — أسقط `*-policies.mjs` فيها، لا حاجة لإعدادات |
| `~/.failproofai/policies/cloud-policies/` | السياسات المنشورة على هذا الجهاز من قبل منظمتك |
| `~/.failproofai/hook-activity/` | سجل تنفيذ الخطاف (JSONL مقسمة) |
| `~/.failproofai/logs/` | سجلات الأخطاء لأخطاء الخطاف المخصص |
| `.failproofai/policies-config.json` | إعدادات لكل مشروع (مرتبطة) |
| `.failproofai/policies-config.local.json` | التجاوزات الشخصية (مستثناة من git) |

---

## الإلغاء

```bash
failproofai policies --uninstall
```

يزيل مدخلات الخطاف من `~/.claude/settings.json`. يتم الاحتفاظ بملفات الإعدادات في `~/.failproofai/`.
