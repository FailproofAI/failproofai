## البدء السريع

<Steps>
  <Step title="فعّل السياسات">
    السياسات هي قواعد تعمل قبل وبعد كل استدعاء أداة للوكيل. تلتقط الأوامر المدمرة، تسريب الأسرار، وأوضاع الفشل الأخرى قبل أن تسبب ضررًا.

    ```bash
    failproofai policies --install
    ```

    هذا يكتب مدخلات الخطاف في أدوات سطر الأوامر المثبتة للوكيل (Claude Code في `~/.claude/settings.json`، OpenAI Codex في `~/.codex/hooks.json`، GitHub Copilot CLI في `~/.copilot/hooks/failproofai.json`، Cursor Agent في `~/.cursor/hooks.json`، OpenCode في برنامج الحماية المُنتج في `~/.config/opencode/plugins/failproofai.mjs` بالإضافة إلى مدخل تسجيل في مصفوفة `plugin` في `~/.config/opencode/opencode.json`، Pi في `~/.pi/agent/settings.json`، Hermes في `~/.hermes/config.yaml`، OpenClaw في `~/.openclaw/openclaw.json`، Factory Droid في `~/.factory/hooks.json`، Devin CLI في `~/.config/devin/config.json`، Antigravity CLI في `~/.gemini/config/hooks.json`، أو Goose في مجلد البرنامج المكتشف تلقائيًا في `~/.agents/plugins/failproofai/hooks/hooks.json`). عند وجود أكثر من واحد، سيتم الطلب منك؛ مرّر `--cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose` (أي مجموعة جزئية) لتخطي الطلب.

    دعم GitHub Copilot CLI و Cursor Agent و OpenCode و Pi هو **بيتا** — ثبّت باستخدام `--cli copilot` أو `--cli cursor` أو `--cli opencode` أو `--cli pi`. Hermes (hermes-agent، بوابة Slack/Telegram) يثبت بنطاق المستخدم باستخدام `--cli hermes` وهو **أيضًا** مصدر تدقيق غير متصل. OpenClaw (بوابة openclaw، مساعد متعدد القنوات ذاتي الاستضافة) يثبت بنطاق المستخدم باستخدام `--cli openclaw` — يعمل الفرض من خلال خطافات البرنامج المضمن في العملية (`before_agent_finalize` هو بوابة نهاية الدور الحقيقية، لذلك تفرض الملفات المدمجة `require-*-before-stop`) — وهو **أيضًا** مصدر تدقيق غير متصل. Factory Droid (`droid`) يثبت باستخدام `--cli factory` (نطاق المستخدم والمشروع) وهو **أيضًا** مصدر تدقيق غير متصل. Devin CLI (`devin`، Cognition) يثبت باستخدام `--cli devin` (نطاق المستخدم والمشروع) وهو **أيضًا** مصدر تدقيق غير متصل. Antigravity CLI (`agy`) يثبت باستخدام `--cli antigravity` (نطاق المستخدم والمشروع) وهو **أيضًا** مصدر تدقيق غير متصل. Goose (اسم رمز goose، Block) يثبت باستخدام `--cli goose` (نطاق المستخدم والمشروع) — المثبت يضع مجلد برنامج في `~/.agents/plugins/failproofai/` الذي يكتشفه Goose تلقائيًا، وهو **أيضًا** مصدر تدقيق غير متصل.

    ```bash
    failproofai policies --install --scope project
    failproofai policies --install --cli codex --scope project
    failproofai policies --install --cli copilot --scope project
    failproofai policies --install --cli cursor --scope project
    failproofai policies --install --cli opencode --scope project
    failproofai policies --install --cli pi --scope project
    failproofai policies --install --cli hermes --scope user
    failproofai policies --install --cli openclaw --scope user
    failproofai policies --install --cli factory --scope project
    failproofai policies --install --cli devin --scope project
    failproofai policies --install --cli antigravity --scope project
    failproofai policies --install --cli goose --scope project
    failproofai policies --install block-sudo block-rm-rf sanitize-api-keys
    ```
  </Step>
  <Step title="التحقق">
    ```bash
    failproofai policies
    ```

    يعرض كل سياسة، وما إذا كانت مفعلة، وأي معاملات مكونة.
  </Step>
  <Step title="شغّل لوحة التحكم">
    ```bash
    failproofai
    ```

    يفتح لوحة تحكم محلية على `http://localhost:8020` حيث يمكنك استعراض الجلسات، وفحص استدعاءات الأدوات، وإدارة السياسات.
  </Step>
  <Step title="شغّل وكيلك">
    ابدأ Claude Code كالمعتاد. إذا حاول الوكيل فعل شيء محفوف بالمخاطر، يعترضه failproofai تلقائيًا. اتركه يعمل دون رقابة وراجع ما حدث في لوحة التحكم.
  </Step>
</Steps>

## كيفية عمل السياسات

في كل مرة يشغل فيها الوكيل أداة، يستدعي Claude Code failproofai كعملية فرعية:

```text
Claude Code  →  failproofai --hook PreToolUse  →  يقرأ JSON من stdin
                                                 يقيّم السياسات
                                                 يكتب القرار إلى stdout
```

كل سياسة تعيد أحد ثلاثة قرارات:

- **allow** - يسير الوكيل بشكل طبيعي
- **deny** - يتم حظر الإجراء، يتم إخبار الوكيل بالسبب
- **instruct** - يتم إضافة سياق إضافي إلى موجه الوكيل

<Note>
تعمل السياسات في عمليتك المحلية. لا يتم إرسال أي شيء إلى خدمة بعيدة.
</Note>

## أنشئ سياسات الفريق باستخدام السياسات المستندة إلى الاتفاقية

الطريقة الأسرع لإنشاء معايير الجودة عبر فريقك هي اتفاقية `.failproofai/policies/`. ضع ملفات السياسة في هذا المجلد وسيتم تحميلها تلقائيًا — بدون علامات، بدون تغييرات الإعدادات، بدون أوامر تثبيت.

<Steps>
  <Step title="أنشئ مجلد السياسات">
    ```bash
    mkdir -p .failproofai/policies
    ```
  </Step>
  <Step title="أضف ملفات السياسة">
    انسخ أمثلة البدء أو اكتب الخاص بك:

    ```bash
    cp node_modules/failproofai/examples/convention-policies/*.mjs .failproofai/policies/
    ```

    أو أنشئ واحدة جديدة:

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Run tests before committing.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="التزم بـ git">
    ```bash
    git add .failproofai/policies/
    git commit -m "Add team quality policies"
    ```

    كل عضو في الفريق لديه failproofai مثبت يلتقط هذه السياسات تلقائيًا. لا حاجة لإعداد منفصل لكل مطور.
  </Step>
</Steps>

<Tip>
التزم بـ `.failproofai/policies/` في مستودعك حتى يشارك الفريق بأكمله نفس المعايير. مع اكتشاف فريقك لأوضاع فشل جديدة، أضف سياسات واضغط — كل شخص يحصل على التحديث في `git pull` التالي. بمرور الوقت، تصبح هذه السياسات معيار جودة حي يستمر في التحسن.
</Tip>

## تخزين البيانات

تبقى جميع الإعدادات والسجلات على جهازك:

| المسار | ما يخزنه |
|------|------|
| `~/.failproofai/policies/local-policies/policies-config.json` | إعدادات السياسة العامة |
| `~/.failproofai/hook-activity/` | سجل تنفيذ الخطاف (JSONL مرقّم الصفحات) |
| `~/.failproofai/logs/` | سجلات تصحيح الأخطاء لأخطاء الخطاف المخصصة |
| `.failproofai/policies-config.json` | إعدادات كل مشروع (مرتكبة) |
| `.failproofai/policies-config.local.json` | الإجراءات الشخصية (مُتجاهلة من git) |

---

## إلغاء التثبيت

```bash
failproofai policies --uninstall
```

يزيل مدخلات الخطاف من `~/.claude/settings.json`. تحتفظ ملفات الإعدادات في `~/.failproofai/` بحالتها.
