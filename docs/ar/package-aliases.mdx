## الحزمة الرسمية

حزمة npm الأساسية هي **`failproofai`**:

```bash
npm install -g failproofai
# أو
bun add -g failproofai
```

---

## لماذا نمتلك أسماء الأسماء المستعارة

هجوم الاستخفاف بالنطاق (Typosquatting) هو هجوم شائع على سلسلة التوريد حيث يقوم جهة فاعلة خبيثة بتسجيل اسم حزمة يبعد ضغطة واحدة فقط عن حزمة شهيرة. المستخدمون غير المدركين الذين يخطئون في كتابة أمر التثبيت ينتهي بهم الحال إلى تشغيل كود يتحكم به المهاجم مع وصول كامل للنظام - وهذا هو بالضبط نوع التهديد الذي صُمم Failproof AI للدفاع ضده.

لإزالة هذا السطح الهجومي، **نحن نمتلك مسبقاً جميع الأخطاء الإملائية الشائعة والمتغيرات المختلفة** لاسم `failproofai` على npm. لا يمكن لأي طرف ثالث تسجيل أي من هذه الأسماء. كل واحد منها عبارة عن وكيل بسيط يقوم بتثبيت وتفويض العمل إلى حزمة `failproofai` الحقيقية.

> **لماذا قيد الانتظار؟** تمنع سياسة منع البريد العشوائي في npm الأسماء التي تُعتبر مطابقة لحزمة موجودة بعد إزالة علامات الترقيم وإجراء فحوصات التشابه. لقد تواصلنا مع فريق دعم npm لحجز هذه الأسماء لأغراض منع الاستخفاف. سيتم تفعيلها بمجرد الموافقة.

يمكنك التحقق من أن أي اسم مستعار منشور يمتلكه:

```bash
npm info failproof
# ابحث عن: "ExosphereHost Inc." في حقل maintainers
```

## كيف تعمل الأسماء المستعارة

كل حزمة مستعارة:

1. تسرد `failproofai` كتبعية - بحيث يتم تثبيت الحزمة الحقيقية ويصبح ملفها التنفيذي متاحاً
2. تعرّض ملفاً تنفيذياً يطابق اسمها الخاص (مثل `failprof-ai`) يوجه جميع الوسيطات إلى الملف التنفيذي `failproofai`

الوكيل عبارة عن نص Node من سطرين؛ لا توجد منطق، ولا استدعاءات شبكة، ولا جمع بيانات خارج ما تفعله `failproofai` نفسها.
