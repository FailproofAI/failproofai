قم بإنشاء ملف ينتهي بـ `policies.js` أو `policies.mjs` أو `policies.ts` تحت `.failproofai/policies/`. يتم تحميل ملفات الاتفاقية تلقائياً على نطاق المشروع والمستخدم.

## اختبر السياسة قبل النشر على السحابة

<Tabs>
  <Tab title="لوحة التحكم">
    1. ثبّت السياسة المخصصة على آلة اختبار واحدة وفعّل كلاً من الإجراء المطابق واللاعطل الشرعي.
    2. انتقل إلى **Observe → policy** وقارن القرارين.
    3. افتح كل جلسة مرتبطة تحقق من أن حمل الحدث يحتوي على أدلة كافية للقاعدة.
    4. عندما يكون السلوك صحيحاً، انقل المصدر المراجع إلى **Admin → policy editor** ونشر نسخة.

  </Tab>
  <Tab title="واجهة سطر الأوامر">
    ```bash
    failproofai policies --install --custom ./security.policies.ts \
      --cli claude --scope project
    failproofai policies
    ```

    يتم تحميل ملفات الاتفاقية تحت `.failproofai/policies/` بدون `--custom`. احتفظ بأمر تثبيت صريح في CI عندما يجب أن يفشل التحقق على وحدة معطلة.
  </Tab>
</Tabs>

```ts
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "protect-production-paths",
  description: "Block writes to production configuration",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Write" && ctx.toolName !== "Edit") return allow();
    const path = String(ctx.toolInput?.file_path ?? "").replaceAll("\\", "/");
    if (path.split("/").includes("production")) {
      return deny("Writes to production configuration require approval.");
    }
    return allow();
  },
});
```

هذا يطابق `production/config.yml` و `/srv/production/config.yml` و `/srv/production` و `C:\\production\\config.yml` لكل من `Write` و `Edit`. لا يطابق أسماء مثل `production-backup` لأن `production` يجب أن تكون جزءاً كاملاً من المسار.

تحقق وثبّت ملف صريح:

```bash
failproofai policies --install --custom ./security.policies.ts
```

يتضمن سياق السياسة نوع الحدث والحمل المعياري واسم الأداة والمدخلات وبيانات تعريف الجلسة والمعاملات واسم CLI المصدر عند توفره.

## اختبر مسارات الفشل

قم بتشغيل التحقق بعد تغيير ملف الإدخال أو أي وحدة محلية يستوردها:

```bash
failproofai policies --install --custom ./security.policies.ts --scope project
```

مسار CLI الصارم يفشل للملفات المفقودة وأخطاء بناء الجملة والاستيرادات غير المحلولة والاستثناءات ذات المستوى الأعلى ومهل تجاوز وقت تحميل الوحدة. في وقت الفرض، يتم تسجيل ملف مخصص معطل وتخطيه حتى تتمكن السياسات المدمجة من المتابعة. تعامل مع أي تحذير تحميل كخسارة للفرض المتوقع وأصدر تنبيهاً عليه في سجلات الإنتاج.

استخدم أسماء فريدة عالمياً عبر السياسات الصريحة والاتفاقية والمدارة من قبل السحابة. احتفظ بدوال السياسة حتمية وقيّد الاتصالات الخارجية بمهل زمنية قصيرة وأرجع `allow` أو `instruct` أو `deny` مقصود على كل مسار.

<Warning>
  السياسة المخصصة هي رمز إنفاذ. اختبر الحقول المفقودة وأسماء الأدوات البديلة والمدخلات المشوهة، وليس فقط المطابقة المتوقعة.
</Warning>
