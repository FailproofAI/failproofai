نشّر سياسة تمت مراجعتها على جهاز واحد في كل مرة. ابدأ في وضع المراقبة.

## الطرح من سطر الأوامر

```bash
fp policies test ./rule.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish no-force-push ./rule.mjs
fp fleet deploy <machine> --add no-force-push:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add no-force-push:enforce
```

يقيّم وضع المراقبة السياسة الفعلية ويسجل القرارات غير المسموحة، لكنه لا يحجب الوكيل.

<Warning>
  إن استخدام `--add no-force-push` بدون إضافة يطبق السياسة فوراً. أضف `:observe` لطرح خادع.
</Warning>

إذا تسبب التطبيق في مشاكل:

```bash
fp fleet history <machine>
fp fleet rollback <machine> <generation>
```

## النشر من لوحة التحكم

1. انتقل إلى **Admin → enforcement**.
2. افتح الجهاز المستهدف.
3. أضف إصدار السياسة مع التأثير **observe**.
4. طبّق النشر.
5. راجع النتائج تحت **Observe → policy**.
6. رقّ نفس الإصدار إلى **enforce** عندما تكون المطابقات صحيحة.

![محرر نشر الجهاز مع إصدارات السياسات وتأثيرات enforce و observe وإجراء تطبيق النشر.](/images/dashboard/enforcement-editor.png)

## استبدال أو مرحلة مسبقة من مجموعة

- `--remove <id>` يزيل سياسة واحدة.
- `--set <ref>...` يستبدل مجموعة السياسات الكاملة.
- `--create` يحضّر نشراً قبل أن يتحقق الجهاز للمرة الأولى.
- `fp fleet diff <machine>` يقارن الحالة المقصودة والمطبقة.

<Note>
  بدون Cloud، انشر حزمة باستخدام `failproofai publish --effect observe` وفتّش القرارات في لوحة التحكم المحلية.
</Note>

تحتاج الأجهزة إلى `policies:pull` لاستقبال النشرات و `events:add` للإبلاغ عن القرارات.
