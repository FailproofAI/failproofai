يربط النشر نسخة واحدة أو أكثر من السياسات بمجموعة مستهدفة من الأجهزة المسجلة.

## تطبيق نشر

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **المسؤول → الإنفاذ**، ابحث عن الجهاز، وقم بتوسيع صفه.
    2. اختر **تعديل**، أضف نسخة السياسة المراجعة، واختر **مراقبة** أو تأثيرها الإنفاذي.
    3. طبّق التغيير، ثم انتظر الفحص التالي للجهاز وأكّد حالة النشر والتغطية.
    4. انتقل إلى **مراقبة → سياسة** لفحص القرارات المباشرة.

    ![محرر نشر الجهاز يعرض نسخ السياسات وتأثيرات الإنفاذ والمراقبة وإجراء تطبيق النشر.](/images/dashboard/enforcement-editor.png)
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    لا يتم عن قصد كشف نقاط نهاية النشر السحابي كأوامر `fp` عادية. تحقق من الجهاز محليًا، ثم قم بالنشر عبر لوحة التحكم:

    ```bash
    failproofai config --status
    ```

    استخدم `fp sessions --env production --since 24h` و `fp events --event-type hook_completed` بعد النشر للتحقق من وصول النشاط إلى Cloud.
  </Tab>
</Tabs>

<Steps>
  <Step title="اختر النسخة والأهداف">
    قم بنشر نسخة تم مراجعتها وليس مسودة قابلة للتغيير، بدءًا بجهاز غير إنتاجي أو مجموعة صغيرة يمكنك فحص جلساتها.
  </Step>
  <Step title="مراقبة القرارات">
    راجع المطابقات والأسباب والأدوات المتأثرة والإيجابيات الخاطئة دون حجب العمل.
  </Step>
  <Step title="الإنفاذ والتحقق من التغطية">
    قم بالترقية بعد أن تفصل المطابقات المراقبة الإجراءات غير الآمنة عن الإجراءات الصحيحة، ثم تأكد من أن كل جهاز مستهدف قد سحب النشر ويُبلّغ عن القرارات.
  </Step>
</Steps>

تحتاج الأجهزة إلى قدرة `policies:pull`. يتم التحكم في تقارير الأحداث بشكل منفصل بواسطة `events:add`؛ تحقق من كليهما عندما تتوقع تحليل الـ Cloud والإنفاذ.

<Warning>
  إدارة الإنفاذ هي عملية سير عمل إدارية في الـ Cloud. لا تتعامل مع مسارات الإنفاذ الحصرية للجذر كنقاط نهاية `/v1` API عادية للعملاء.
</Warning>
