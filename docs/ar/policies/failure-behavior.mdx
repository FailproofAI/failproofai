بعد الإعداد، خدمة `failproofaid` المحلية هي المُقيِّم الوحيد. إذا لم تتمكن من الرد، يتم رفض الإجراءات المحمية بدلاً من السماح بها بصمت.

## تشخيص حظر على مستوى الجهاز

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

قم بتشغيل `failproofai config` لإصلاح الخدمة أو تثبيت الإصدار المطابق.

يمكن أن يبدو الفشلان متشابهين:

| الفشل | المعنى |
| --- | --- |
| الخدمة غير متاحة | المقبس ليس لديه مُقيِّم عامل خلفه |
| عدم تطابق الإصدار | واجهة سطر الأوامر والخدمة لا تتفقان على البروتوكول |

كلاهما يرفض، لكن تقارير الحالة تفصل بينهما.

## لن يتم تحميل حزمة

تحديد حزمة مفقودة أو مُعدَّلة أو غير صالحة يرفض الأحداث المغطاة بسياساتها المحددة. وهذا يمنع اختفاء حزمة مكسورة بينما يبدو الجهاز محمياً.

`failproofai policies` يسمي الحزمة وخطأ التحميل.

```bash
failproofai policies
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

البيانات الوصفية غير القابلة للقراءة توسع الرفض الآمن بدلاً من تضييقه بناءً على البيانات التي لا يمكن الوثوق بها.

## ما يبقى متاحاً

لوحة المعلومات المحلية وأوامر الحالة لا تزال تعمل بينما يفشل تقييم السياسة. استخدمها لتحديد الخدمة أو الحزمة أو الإصدار الذي يحتاج إلى إصلاح.

<Warning>
  لا تتجاوز قرار الإغلاق عند الفشل بحذف خدمة أو ملفات الحزمة. أصلح الخدمة أو أعد تثبيت الحزمة أو أزل التعيين من خلال واجهة سطر الأوامر بحيث يعود الجهاز إلى حالة معروفة.
</Warning>
