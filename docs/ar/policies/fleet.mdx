يجيب تغطية الأسطول على ما إذا كانت سياسة موجودة حيث توجد المخاطر. تتبع الأجهزة برقم معرف ثابت وتسمية سهلة القراءة للبشر، ثم قارن حالة النشر المخصصة والمبلغ عنها.

## فحص التغطية

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **Admin → enforcement** واستعرض إجمالي الفرض والمراقبة.
    2. ابحث عن جهاز حسب المعرّف أو التسمية، أو صفّ الأجهزة التي تفتقد السياسة.
    3. وسّع الصف لمقارنة السياسات المخصصة والنشر المبلغ عنه ووقت آخر تسجيل دخول والسجل.
    4. أعد التحديث بعد فترة الاستطلاع الخاصة بالجهاز عندما يظل النشر المطبق في حالة معلقة.

    ![أسطول الفرض يعرض تغطية السياسة وحالة نشر الجهاز وتعيينات المراقبة والفرض.](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    استخدم `fp events --agent-id <agent-id> --since 24h` للتأكد من وصول نشاط وكيل الجهاز إلى Cloud.
  </Tab>
</Tabs>

استخدم طرق عرض التغطية للعثور على:

- الأجهزة التي لم تسحب أبداً آخر نشر
- الأجهزة المسجلة التي توقفت عن الإبلاغ عن النشاط
- سياسة مخصصة للبيئة أو المجموعة الخاطئة
- انجراف الإصدار بعد تحديث متقطع

إعادة تسمية جهاز دون إعادة الاتصال به:

```bash
failproofai config --machine-label checkout-runner-03
```

فحص الحالة المحلية:

```bash
failproofai config --status
```

<Tip>
  استخدم التسميات التي تحدد حمل العمل والبيئة. أسماء المضيفين وحدها غالباً ما تكون غير كافية بعد التوسع التلقائي أو استبدال الجهاز.
</Tip>
