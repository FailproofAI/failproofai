يجيب تغطية الأسطول على السؤال حول ما إذا كانت السياسة موجودة حيث توجد المخاطر. تتبع الأجهزة من خلال معرّف مستقر وتسمية يمكن قراءتها من قبل الإنسان، ثم قارن بين حالة النشر المخصصة والمُبلغ عنها.

## التحقق من التغطية

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **Admin → enforcement** واستعرض إجمالي الأجهزة التي تفرض وتراقب.
    2. ابحث عن جهاز حسب المعرّف أو التسمية، أو قم بالتصفية للأجهزة التي تفتقد سياسة.
    3. وسّع الصف لمقارنة السياسات المعينة والنشر المُبلغ عنه ووقت آخر تسجيل دخول والسجل.
    4. أعِد التحديث بعد فترة استطلاع الجهاز عندما يبقى النشر المطبق قيد الانتظار.

    ![أسطول الإنفاذ يعرض تغطية السياسة وحالة نشر الجهاز وتعيينات المراقبة والإنفاذ.](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    استخدم `fp events --agent-id <agent-id> --since 24h` للتأكد من وصول نشاط وكيل الجهاز إلى السحابة.
  </Tab>
</Tabs>

استخدم عروض التغطية للبحث عن:

- الأجهزة التي لم تسحب آخر نشر مطلقاً
- الأجهزة المسجلة التي توقفت عن الإبلاغ عن النشاط
- سياسة معينة للبيئة أو المجموعة الخاطئة
- انجراف الإصدار بعد تحديث متقطع

إعادة تسمية جهاز دون إعادة الاتصال:

```bash
failproofai config --machine-label checkout-runner-03
```

التحقق من الحالة المحلية:

```bash
failproofai config --status
```

<Tip>
  استخدم تسميات تحدد حمل العمل والبيئة. غالباً ما تكون أسماء المضيفين وحدها غير كافية بعد الفرز التلقائي أو استبدال الجهاز.
</Tip>
