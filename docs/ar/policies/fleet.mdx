يجيب تغطية الأسطول عما إذا كانت سياسة موجودة حيث توجد المخاطرة. تتبع الأجهزة من خلال معرّف مستقر وتسمية قابلة للقراءة من قبل الإنسان، ثم قارن حالة النشر المخصصة والمبلغ عنها.

## التحقق من التغطية

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **المسؤول → الإنفاذ** واستعرض إجمالي الإنفاذ والمراقبة.
    2. ابحث عن جهاز حسب المعرّف أو التسمية، أو قم بالتصفية للأجهزة التي تفتقد سياسة.
    3. وسّع الصف لمقارنة السياسات المخصصة والنشر المبلغ عنه آخر تسجيل دخول والسجل.
    4. أعد التحديث بعد فترة الاستطلاع للجهاز عندما يبقى النشر المطبق قيد الانتظار.

    ![أسطول الإنفاذ يعرض تغطية السياسة وحالة نشر الجهاز وتعيينات المراقبة والإنفاذ.](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    استخدم `fp events --agent-id <agent-id> --since 24h` للتأكد من وصول نشاط وكيل الجهاز إلى السحابة.
  </Tab>
</Tabs>

استخدم طرق عرض التغطية للعثور على:

- الأجهزة التي لم تسحب النشر الأخير أبداً
- الأجهزة المسجلة التي توقفت عن الإبلاغ عن النشاط
- سياسة مخصصة للبيئة أو المجموعة الخاطئة
- انجراف الإصدار بعد تحديث متقطع

إعادة تسمية جهاز دون إعادة الاتصال:

```bash
failproofai config --machine-label checkout-runner-03
```

التحقق من الحالة المحلية:

```bash
failproofai config --status
```

<Tip>
  استخدم تسميات تحدد عبء العمل والبيئة. غالباً ما تكون أسماء المضيفين وحدها غير كافية بعد التوسيع التلقائي أو استبدال الجهاز.
</Tip>
