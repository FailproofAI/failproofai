يفصل Failproof AI بين اختيار السياسة وإعدادات الجهاز والديمون. يحافظ هذا على قابلية مراجعة خيارات سياسة المستودع بينما تبقى بيانات الاعتماد وحالة الديمون خارج المستودع.

## اختر نطاق السياسة

<Tabs>
  <Tab title="Dashboard">
    شغّل `failproofai` بدون معاملات لفتح لوحة تحكم السياسة المحلية. اختر نطاق المستخدم أو المشروع أو المحلي قبل تفعيل السياسة بحيث يتم كتابة التغيير في ملف التكوين المقصود.

    - **المستخدم** ينطبق على جميع المشاريع على هذا الجهاز.
    - **المشروع** ينتمي إلى المستودع ويمكن التزامه.
    - **المحلي** يستبدل مشروعًا واحدًا لمستخدم واحد ويجب أن يبقى مغفولاً من git.

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-rm-rf --scope user
    failproofai policy add block-force-push --scope project
    failproofai policy add warn-large-file-write --scope local
    failproofai policies
    ```

    لا يدعم كل مسند النطاق المحلي. يرفض الأمر الخط (CLI) نطاقًا لا يمكن للمسند المحدد تمثيله.
  </Tab>
</Tabs>

| النطاق | ملف تكوين السياسة |
| --- | --- |
| المشروع | `<project>/.failproofai/policies-config.json` |
| المحلي | `<project>/.failproofai/policies-config.local.json` |
| المستخدم | `~/.failproofai/policies-config.json` |

يتم دمج السياسات المفعلة كاتحاد. معاملات السياسة تستخدم النطاق الأول الذي يحدد المعاملات لتلك السياسة، بترتيب المشروع → المحلي → المستخدم. مسارات السياسة المخصصة الصريحة تستخدم النطاق الأول الذي يحددها.

## تكوين معاملات السياسة

<Tabs>
  <Tab title="Dashboard">
    افتح السياسة في لوحة تحكم المحلية، عدّل معاملات السياسة المدعومة، واحفظ في النطاق المحدد. قم بتشغيل إجراء وكيل متطابق وآخر غير متطابق، ثم تفقد القرار في **مراقبة → السياسة**.

  </Tab>
  <Tab title="CLI">
    عدّل `policies-config.json` للنطاق المحدد، ثم شغّل `failproofai policies` لظهور أسماء السياسات أو مفاتيح المعاملات غير المعروفة.

    ```json
    {
      "enabledPolicies": ["block-rm-rf", "block-force-push"],
      "policyParams": {
        "block-rm-rf": {
          "allowPaths": ["/tmp/build-output"]
        }
      }
    }
    ```

    ```bash
    failproofai policies
    ```
  </Tab>
</Tabs>

## افهم ملفات الجهاز

يحتوي `~/.failproofai` على ملفات منفصلة لحدود الثقة المنفصلة:

| المسار | الغرض |
| --- | --- |
| `config.json` | إعدادات الديمون والتدقيق والقياس عن بعد غير السرية |
| `credentials.json` | بيانات اعتماد السحابة؛ مخزنة بأذونات الملك فقط |
| `policies-config.json` | اختيار النطاق المستخدم للسياسات المدمجة والمعاملات والمسارات المخصصة الصريحة |
| `policies/` | سياسات الاتفاقية المستخدمة والقطع الأثرية للسياسات التي تديرها السحابة |
| `hook-activity/` | سجل قرار السياسة المحلي |
| `state/` | مسودة الديمون والصحة والإيقاف المؤقت وحالة وقت التشغيل |

استخدم `FAILPROOFAI_HOME` لنقل تخطيط الجهاز الكامل لحاوية أو اختبار معزول. لا تنقل مجلدات الحالة الفردية بشكل مستقل.

<Warning>
  لا تلتزم أبدًا `credentials.json`. ألتزم بتكوين سياسة المشروع وسياسات اتفاقية المشروع فقط بعد مراجعتها كرمز الإنفاذ.
</Warning>
