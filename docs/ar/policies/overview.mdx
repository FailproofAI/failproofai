تراقب السياسة إجراء الوكيل وترجع أحد ثلاثة قرارات:

- `allow` يسمح بالمتابعة.
- `instruct` يعطي الوكيل إرشادات عندما يدعمها الحامل الخاص به.
- `deny` يحجب الإجراء.

استخدم السياسات للسلوك المعروف والقابل للتكرار: حذف الملفات المحمية، والكشف عن الأسرار، والدفع إلى الفرع الخاطئ، أو تغيير البنية الأساسية للإنتاج.

## إضافة سياسات إلى هذا الجهاز

لا يختار الإعداد حزمة سياسات. أضف حزمة Failproof AI بعد الإعداد:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai policies
```

الحزمة لا تحتوي على حزمة مدمجة امتيازية. تُثبّت حزمتنا بنفس طريقة أي حزمة أخرى.

يمكن أن تأتي السياسات أيضاً من ملف محلي أو حزمة منشورة أو تعيين سحابي:

| المصدر | أضفها |
| --- | --- |
| ملف محلي | ضع `*policies.{js,mjs,ts}` تحت `.failproofai/policies/` |
| أي مسار ملف | `failproofai policies -i -c <path>` |
| حزمة منشورة | `failproofai policies add <owner>/<repo>` |
| السحابة | عيّنها في لوحة التحكم أو باستخدام `fp fleet deploy` |

`block-failproofai-commands` يعمل دائماً ولا يمكن إيقافه. فهو يمنع الوكيل من تعطيل الإنفاذ الخاص به.

## ملاحظة قبل الإنفاذ

يعمل وضع الملاحظة على السياسة الحقيقية ويسجل ما كان سيفعله، لكنه لا يحجب الوكيل.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

<Warning>
  الأمر `fp fleet deploy <machine> --add <id>` بدون إضافة ينفذ فوراً. أضف `:observe` للنشر المظلل.
</Warning>

السياسة التي تنتهي مهلتها في وضع الملاحظة تسجل السماح، لأن ذلك ما سيحدث أثناء الإنفاذ. يتم تسجيل قرارات الملاحظة غير المسموح بها فقط.

بالنسبة لحزمة تُستخدم بدون السحابة، انشرها باستخدام `failproofai publish --effect observe`.
