أنشئ سياسة تعمل، اختبرها محليًا، ثم انشرها كحزمة.

## الإنشاء والاختبار

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

يكتب `--init` سياسة تحظر بالفعل `git push --force`. عدّلها، اطلب من وكيلك محاولة الإجراء المحظور، وتحقق من **Policies → Activity** في لوحة التحكم المحلية.

يمكن لسياسة الحزمة أن تتضمن:

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-refunds",
  description: "Refunds above the limit need a human",
  category: "Billing",
  defaultEnabled: true,
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) => {
    // return allow(), instruct(), or deny()
  },
});
```

الإعداد الافتراضي لـ `defaultEnabled` هو `false`.

## النشر

التزم بملفاتك، ثم شغّل:

```bash
failproofai publish
```

يجد الأمر `publish` ملف السياسة، يتحقق منه باستخدام نفس محمّل التحميل المستخدم أثناء التثبيت، ويرفع أصول الحزمة إلى إصدار GitHub. يستخدم `GITHUB_TOKEN` أو `GH_TOKEN` أو `gh auth login`.

يجب أن تكون المستودع عام لأن التثبيت يستخدم HTTPS مجهول.

الإصدار الافتراضي هو SHA المكون من 12 حرفًا للالتزام الحالي. يرفض الأمر `publish` شجرة غير نظيفة أو دليل خارج Git ما لم تقدم `--version`. العلامة على `HEAD` تتفوق على SHA.

يثبتها المستخدمون باستخدام:

```bash
failproofai policies add owner/repo
```

## النشر في وضع المراقبة

```bash
failproofai publish --effect observe
```

يقيّم وضع المراقبة السياسة الفعلية ويسجل القرارات غير المسموحة، لكنه يسمح للوكيل بالمتابعة. ينسجل انتهاء المهلة الزمنية كسماح.

انشر مجددًا مع `--effect enforce` عندما تكون المطابقات المراقبة صحيحة.

## الخيارات المفيدة

| العلم | التأثير |
| --- | --- |
| `--init [file]` | اكتب سياسة بادئة |
| `--repo <owner>/<repo>` | اختر أو أنشئ المستودع |
| `--version <version>` | تجاوز الإصدار المستند إلى الالتزام |
| `--effect enforce\|observe` | اختر ما إذا كانت الحزمة تحظر |
| `--dry-run` | بناء والتحقق بدون نشر |
| `--allow-private` | انشر بشكل خاص، مع معرفة أن `policies add` لا يمكنه تثبيته |

```bash
failproofai publish --dry-run
failproofai publish ./guards.mjs --repo me/guards --version 2.0.0
```

<Note>
  أضف موضوع GitHub `failproofai-policies` بعد النشر حتى يتمكن [Policy Hub](https://befailproof.ai/policy-hub/) من فهرسة الحزمة. واجهة سطر الأوامر لا تفعل ذلك نيابة عنك.
</Note>

<Warning>
  إعادة تسمية السياسة هي تغيير كبير بالنسبة للاختيارات الموجودة. اجعل الأسماء مستقرة عبر الإصدارات.
</Warning>
