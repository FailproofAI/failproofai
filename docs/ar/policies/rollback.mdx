تقوم الاستعادة بتغيير النسخة المنشورة أو إزالة تعيين سياسة؛ إنها لا تمحو سجل القرارات الذي يشرح الحادثة.

## استعادة آلة

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **Admin → enforcement**، وقم بتوسيع الآلة المتأثرة، وحدد آخر مجموعة سياسة معروفة جيدة لها.
    2. اختر **edit**، واستعد تلك الإصدارات والتأثيرات، وطبق النشر الجديد.
    3. انتظر إعادة فحص الآلة، ثم تحقق من النشر المبلغ عنه.
    4. افتح **Observe → policy** والجلسات المتأثرة لتأكيد أن العمل الصالح لم يعد مغلقًا.

  </Tab>
  <Tab title="واجهة سطر الأوامر">
    استعادة نشر السحابة هي سير عمل لوحة التحكم. استخدم الحالة المحلية للتأكد من وصول النشر المصحح إلى الآلة:

    ```bash
    failproofai config --status
    ```

    `failproofai config --pause` توقف السياسات المدمجة والمخصصة والمتعارف عليها لجلسة محلية واحدة. إنها لا توقف سياسات Cloud المُدارة، لذا فهي ليست حلاً بديلاً لنشر Cloud سيء.
  </Tab>
</Tabs>

## متى تقوم بالاستعادة

- تمنع سياسة ما إجراءً إنتاجيًا متوقعًا.
- حجم المطابقة أعلى بشكل كبير مما توقعه الطرح المراقب.
- تعتمد سياسة على حقول لا توفرها عملية دمج.
- تغير نسخة جديدة السلوك خارج نمط الفشل المقصود.

بعد الاستعادة، افتح الجلسات المتأثرة وحدد الحالة التي تسببت في الإيجابية الخاطئة. أنشئ نسخة جديدة، واختبر كلاً من الحالات غير الآمنة والشرعية، ثم كرر مرحلة المراقبة.

<Warning>
  قد يكون إيقاف الإنفاذ مناسبًا أثناء حادثة ما، لكنه يوسع التعرض لكل سياسة نشطة في هذا النطاق. فضل استعادة إصدار السياسة المحدد عند الإمكان.
</Warning>
