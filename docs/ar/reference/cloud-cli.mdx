استخدم `fp` لفحص بيانات telemetry للـ Cloud، وإدارة الإنفاذ المدار من قبل Cloud (السياسات، نشرات الأسطول، قرارات الحماية)، وإدارة عمليات التدقيق والنتائج والمشاكل والتنبيهات والمفاتيح والمستخدمين والاستعلامات والإعدادات. استخدم [`failproofai`](/ar/reference/failproof-cli) للـ hooks المحلية والسياسات والالتقاط وتسجيل الآلات.

ثبّت Cloud CLI المُصدَّرة كأداة منعزلة. تتطلب Python 3.10 أو أحدث.

```bash
uv tool install fp-cloud-cli
fp version
```

التوزيع هو `fp-cloud-cli` والأمر المثبَّت هو `fp` — يختلفان لأن `fp` كان محجوزًا بالفعل على PyPI.

## تسجيل الدخول

`fp login` يرسل لك رمز سداسي الأرقام عبر البريد الإلكتروني ويحفظ الجلسة. عند التعامل مع لوحة تحكم تتمتع بشهادة ذاتية التوقيع، أضف `--insecure` عند تسجيل الدخول.

```bash
fp login
fp whoami
```

## بنية الجملة

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

يجب أن تأتي الخيارات العامة قبل الأمر:

```bash
fp --json sessions --since 24h
```

شغّل `fp COMMAND --help` أو `fp COMMAND SUBCOMMAND --help` للحصول على مساعدة من المحطة الطرفية.

### الأحداث

```text
fp events [OPTIONS]
```

تسرد الأحداث الفردية للـ agent. تستبعد التغذية الخفيفة الافتراضية الحمولات الخام؛ استخدم `--full` فقط للتحقيقات المحدودة.

| الخيار | الوصف |
| --- | --- |
| `--limit`, `-n <n>` | أقصى عدد صفوف إجمالي. الافتراضي: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, أو `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | نطاق ISO 8601 UTC؛ يتجاوز `--since`. |
| `--env <value>` | مرشح البيئة؛ كرّر أو افصل بفواصل الخيارات. |
| `--event-type <value>` | مرشح نوع الحدث؛ كرّر أو افصل بفواصل. |
| `--agent-id <value>` | مرشح agent؛ كرّر أو افصل بفواصل. |
| `--session-id <value>` | مرشح الجلسة؛ كرّر أو افصل بفواصل. |
| `--search <text>` | بحث نصي في الحمولة؛ قابل للتكرار، مع مطابقة أي مصطلح. |
| `--order asc\|desc` | ترتيب الوقت. الافتراضي: الأحدث أولاً. |
| `--all` | ترقيم الصفحات التلقائي حتى `--limit`. |
| `--cursor <token>` | استئناف من مؤشر معتم. |
| `--page-size <n>` | الصفوف لكل طلب مع `--all`؛ أقصى `200`. |
| `--full` | شمل الحمولات الخام من خلال نقطة نهاية الأحداث الأثقل. |
| `--fields <csv>` | إرجاع الحقول المحددة فقط؛ طلب `payload` يفعّل الوضع الكامل. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` يرقّم الصفحات **حتى `--limit`**، والذي يبلغ افتراضيًا **50** — لذا `--all` بمفرده يتوقف عند 50 صف. عندما يتوقف مبكرًا، تحتوي الاستجابة على `next_cursor` للاستئناف منه؛ `"next_cursor": null` يعني أن التغذية فعلاً تم استنزافها.
</Note>

#### خيارات إنشاء التدقيق

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| الخيار | الوصف |
| --- | --- |
| `--file <path>` | استند إلى التعريف على JSON، أو استخدم `-` للـ stdin. الأعلام الصريحة تتجاوز قيم الملف. |
| `--description <text>` | اذكر سؤال الفشل أو الغرض. |
| `--enabled` / `--disabled` | ابدأ الجدولة أو أيقفها. الافتراضي: مفعّل. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. الافتراضي: `86400`. |
| `--schedule-anchor <timestamp>` | طور UTC ثابت بصيغة ISO 8601. الافتراضي: الـ 09:00 UTC التالية. |
| `--window-mode since_last\|fixed` | استمر بعد آخر نافذة تم تحليلها بالكامل أو فتش بشكل متكرر نافذة متحركة. الافتراضي: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. الافتراضي: `604800`. |
| `--scope '<json>'` | أرشح حسب `environments`, `agent_ids`، أو حقول نطاق أخرى مدعومة. |
| `--ignore-error-type <type>` | استبعد أنواع الأخطاء؛ كرّر أو افصل بفواصل. |
| `--llm` / `--no-llm` | فعّل أو عطّل التحليل الذكي. الافتراضي: مفعّل. |
| `--top-k <n>` | احتفظ بـ `1`–`500` نتيجة. الافتراضي: `50`. |
| `--sensitivity low\|medium\|high` | عيّن حساسية الإبلاغ. الافتراضي: `medium`. |
| `--channels '<json>'` | مصفوفة قناة الإخطار. |
| `--text <brief>` | موجز مضمّن، بحد أقصى 8192 حرفًا. |
| `--text-file <path>` | اقرأ الموجز من ملف؛ متبادل الاستثناء مع `--text`. |
| `--url <https-url>` | أضف مرجعًا HTTPS عامًا؛ كرّر حتى خمس مرات. |

ضمّن السياق أثناء الإنشاء عندما يكون التشغيل الأول بحاجته. يلتزم الإنشاء بالتعريف والسياق معًا قبل بدء التشغيل المضغوط عليه.

<Note>
  `fp audits run` غير متزامن. استطلع `fp audits runs NAME` حتى ينجح آخر تشغيل أو يفشل قبل قراءة نتائجه.
</Note>

### السياسات

إصدارات السياسات المدارة من قبل Cloud. **الجلسة فقط** — كل أمر هنا باستثناء `fp policies test` يخرج `2` تحت مفتاح API، قبل أي طلب، لأن هذه طرق كتابة root فقط متعمدة غائبة من `/v1`. `fp policies test` هو الاستثناء المتعمد: يعمل بالكامل محليًا مقابل `node` ولا يتحدث إلى أي خادم، لذلك لا يحمل متطلب مصادقة ولا رفض الوضع الرئيسي ويعمل بدون تسجيل دخول وتحت مفتاح API على حد سواء.

| الأمر | الغرض | الخيارات |
| --- | --- | --- |
| `fp policies list` | أدرج إصدارات السياسات، الأحدث من كل سياسة أولاً. | — |
| `fp policies show POLICY_ID` | أظهر سياسة واحدة مع مصدرها. | — |
| `fp policies publish POLICY_ID [SOURCE]` | اضرب إصدارًا جديدًا؛ لا يحرر واحدًا في المكان. `SOURCE` هو مسار أو `@path` أو `-` للـ stdin — احذفه للصق. | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | أضفها مرة أخرى إلى كل نشر تمت إزالتها منه، مضروبة جيل جديد على كل واحد. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | أزلها من كل نشر تحمله، مضروبة جيل جديد على كل واحد. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | احذف إصدار سياسة. | `--yes`, `-y` |
| `fp policies test [SOURCE]` | شغّل سياسة محليًا مقابل سياق اصطناعي. يطبّق مرشح `match` لكل سياسة، لذا واحد لا يغطي الحدث/الأداة المعطاة تُبلّغ `skipped` بدلاً من تشغيل. يحتاج `node` على PATH. | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | صيّغ سياسة مع المساعد. اطبع المسودة ولا تفعل شيئًا آخر بشكل افتراضي. يحتاج `policies:write`. | `--out <path>`; `--publish <policy-id>` |

### الأسطول

أي الآلات تشغّل أي السياسات. **الجلسة فقط** — كل أمر هنا، بدون استثناء، يخرج `2` تحت مفتاح API.

| الأمر | الغرض | الخيارات |
| --- | --- | --- |
| `fp fleet list` | أدرج الآلات المسجلة وجيل النشر لديها. | — |
| `fp fleet show MACHINE_ID` | مجموعة السياسات التي تشغّلها آلة حاليًا. | — |
| `fp fleet deploy MACHINE_ID` | غيّر ما تطبّقه آلة. اطبع المجموعة الكاملة الناتجة أولاً، واسأل فقط على محطة طرفية تفاعلية بدون `--json`. | `--add`; `--remove`; `--set`; `--create`; `--yes`, `-y` |
| `fp fleet diff [MACHINE_ID]` | النية مقابل التسليم — ما تُخبر الآلة أن تشغّله مقابل ما سحبته آخر مرة. احذف المعرّف للأسطول بالكامل. | — |
| `fp fleet history MACHINE_ID` | كل جيل لآلة، الأحدث أولاً. | — |
| `fp fleet rollback MACHINE_ID GENERATION` | أعد تثبيت مجموعة السياسات للجيل الماضي. رقم الجيل يأتي من `fp fleet history MACHINE_ID`. | `--yes`, `-y` |
| `fp fleet rename MACHINE_ID LABEL` | أعط آلة تصنيفًا مقروءًا. المعرّف نفسه لا يتغير أبدًا. | — |

```bash
fp fleet history ci-runner-01
fp fleet rollback ci-runner-01 3
fp fleet rename ci-runner-01 "CI runner (eu-west)"
```

#### مراجع السياسات

`--add` و `--set` يأخذان مرجع سياسة، وليس معرّف مجرد:

| النموذج | المعنى |
| --- | --- |
| `id` | الإصدار الحالي، الأثر الحالي |
| `id@3` | الإصدار 3، الأثر الحالي |
| `id:observe` | الإصدار الحالي، مسجل لكن غير مطبّق |
| `id@3:observe` | الإصدار 3، مسجل لكن غير مطبّق |

التأثير هو `enforce` أو `observe`. الدقة هي: التأثير الصريح يفوز؛ وإلا التأثير المنشر بالفعل لهذه السياسة؛ وإلا `enforce`.

<Warning>
  `--add` مجرد **ينفّذ فورًا**. `fp fleet deploy ci-runner-01 --add checkout-guard` يبدأ الحظر على هذه الآلة بمجرد سحبها التالي. `:observe` هو ما يجعله نشرًا خفيًا:

  ```bash
  fp fleet deploy ci-runner-01 --add checkout-guard:observe   # records only
  fp fleet deploy ci-runner-01 --add checkout-guard           # enforces now
  ```

  المراقبة ليست معطلة. السياسة تُقيّم بشكل حقيقي، تحت نفس المهلة 10 ثوان ومعالجة الأخطاء نفسها كما العاملة، وكل الحكم غير السماح يتم تسجيله — فقط الإنفاذ يتم حجزه. وهذا ما يجعل القياس جديرًا بالقراءة.
</Warning>

#### الفروق والاستبدال والسباقات

`--add` و `--remove` يقرآن مجموعة الآلة الحالية ويطبقان دلتا، لذا لا شيء لم تسمّه يتم إزعاجه. `--add` مجرد على سياسة تشغّلها الآلة بالفعل يحتفظ بإصدارها المثبّت بدلاً من ترقيتها بصمت؛ مرّر `id@version` لتحريكها.

`--set` يستبدل كل شيء وهو الطريقة الوحيدة لإسقاط السياسات التي لا تسمّيها. لا يمكن دمجه مع `--add` أو `--remove`. عدم تمرير أي من الثلاثة هو خطأ الاستخدام، وليس no-op.

```bash
fp fleet deploy ci-runner-01 --add prod-guard@1:observe --remove old-rule
fp fleet deploy ci-runner-01 --set no-force-push --set no-secret-echo
```

الكتابة نفسها هي استبدال كامل على كل المسار، لأن نقطة النهاية تأخذ مجموعة السياسات كاملة. لا يوجد قفل من الجانب الخادم، لذا CLI يسجل الجيل الذي قرأه ويرفض إذا كانت النتيجة ليست بالضبط واحدة أعلى — هذا يعني شخص آخر نشر بينهما، والاستبدال لا يندمج. أعد قراءة مع `fp fleet show`، ثم نشّر مرة أخرى.

`--create` ينشّر على معرّف آلة لم يسجل دخول حتى الآن، لـ pre-staging. بدونه، معرّف لا يعرفه الخادم يُرفض، لأن الخطأ الإملائي سيضرب آلة لا أحد يمتلكها يحمل سياسات لا أحد يجمعها.

### الحماية

ما فعله الإنفاذ فعلاً. **الجلسة فقط**، نفس السبب أعلاه.

| الأمر | الغرض | الخيارات |
| --- | --- | --- |
| `fp guardrails summary` | التغطية والإجماليات المحظورة/المقيمة، شرارة الرفض، وجدول لكل السياسة. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |
| `fp guardrails timeline` | القرارات مجمعة على النافذة، مجموعة على كل مصدر سياسة. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |

صف `(no policy)` في الملخص طبيعي بدلاً من فجوة: معظم التقييمات تسمح بشيء لا أحد اعترض عليه، والصف يحافظ على المقام على الشاشة.

### نشّر سياسة بدون كسر أحد

المجموعات الثلاث أعلاه تشكل تسلسلاً واحدًا. قرّر محليًا، انشر، ظلل، قس، ثم أنفّذ.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

| الخطوة | لماذا موجودة |
| --- | --- |
| `fp policies test` | لا خادم ولا مصادقة. شغّل الملف الحقيقي مقابل السياق الذي تصفه واطبع السماح أو الرفض أو الإرشاد لكل سياسة مسجلة. `--expect` يحول ذلك إلى تأكيد CI. |
| `fp policies publish` | اضرب إصدارًا جديدًا غير قابل للتغيير؛ لا يحرر واحدًا في المكان. |
| `fp fleet deploy --add <id>:observe` | النشر الخفي. **`:observe` ليس اختياريًا هنا** — `--add` مجرد ينفّذ اللحظة التي تسحب الآلة. |
| `fp guardrails summary` | يفصل المطابقات غير الآمنة عن العمل الشرعي التي ستحظره السياسة أيضًا. |
| `fp fleet deploy --add <id>:enforce` | الترقية، بمجرد أن تقول الأحكام المسجلة ما توقعته. |
| `fp fleet rollback <machine> <generation>` | الطريقة للعودة إذا ذهب الإنفاذ خطأ. |

المعادل الآلة الواحدة، بدون Cloud يتضمن، ينشّر الحزمة مع `failproofai publish --effect observe` ويقرأ الأحكام المسجلة على [لوحة التحكم المحلية](/ar/reference/local-dashboard).

## الأعلام العامة

| الراية | الوصف |
| --- | --- |
| `--json` | أصدر JSON قابل للقراءة الآلية. |
| `--base-url <url>` | استخدم لوحة تحكم مستضافة ذاتيًا أو تطويرية. |
| `--org <slug>` | اختر مؤسسة لهذا الاستدعاء. |
| `--token <token>` | تجاوز رمز جلسة المستخدم المحفوظ. |
| `--api-key <key>` | المصادقة الأتمتة مع مفتاح API؛ لم يتم حفظها أبدًا. |
| `--timeout <seconds>` | مهلة HTTP؛ يجب أن تكون موجبة. الافتراضي: `30`. |
| `--quiet`, `-q` | أكتم إخراج الحالة على stderr. |
| `--no-color` | عطّل الإخراج الملون. |
| `--insecure` / `--secure` | عطّل أو استعد التحقق من شهادة TLS. |
| `--version` | اطبع الإصدار غير المعبأ وخرج. |
| `--help`, `-h` | أظهر المساعدة. |

`--api-key` مقصود للأتمتة. تسجيل الدخول وتبديل المؤسسة وأوامر المساعد تتطلب جلسة مستخدم.

## متغيرات البيئة

| المتغير | المعادل أو الغرض |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | نقّل دليل تكوين CLI (الافتراضي `~/.failproofai/fpcli`). |
| `FP_ANALYTICS_DISABLED` أو `DO_NOT_TRACK` | عطّل تحليلات CLI المجهولة. |
| `NO_COLOR` | عطّل الإخراج الملون. |

تتجاوز الأعلام الصريحة متغيرات البيئة، التي تتجاوز التكوين المحفوظ.

في وضع مفتاح API، المؤسسة المحفوظة بواسطة `fp login` البشري يتم **تجاهلها**، وليس تجاوزها فقط — فقط `--org` صريح أو `FP_ORG` يتم إرساله. لا شيء يتم وراثته من تسجيل دخول محفوظ، لذا مرّر `--org` كلما كان المفتاح يمكن أن يعمل لأكثر من مؤسسة واحدة. حذفه لا يفشل بصراخ: مفتاح نطاق الحالة بدون `--org` يتم حله من الجانب الخادم إلى المؤسسة **الافتراضية** ويجيب ببيانات تلك المؤسسة، بدون خطأ في أي مكان. شغّل `fp whoami` أولاً لتأكيد أي محاور مفتاح يتحدث إليها فعلاً.

<Warning>
  تهجئات `AGENTEYE_*` لهذه **لا تُقرأ بواسطة `fp`** ولم تكن أبدًا — CLI تعلن `FP_*` (`fp_cli/app.py`)، ومتغير غير معروف ليس خطأ. ضبط `AGENTEYE_DASHBOARD_URL` لا يستهدف CLI مرة أخرى؛ يتم تجاهله والأمر يشغّل بصمت مقابل لوحة التحكم المحفوظة بدلاً من ذلك.

  `AGENTEYE_HOME` و `AGENTEYE_ENVIRONMENT` موجودة بالفعل، لكنها تنتمي إلى **مجمّع وـ telemetry SDK**، وليس إلى هذا CLI.
</Warning>

<Warning>
  الأوامر التي تحذف أو تبطل أو تكتم أو تحل أو تستبدل التكوين تطالب بشكل افتراضي. استخدم `--yes` فقط بعد التحقق من المؤسسة النشطة والهدف.
</Warning>
