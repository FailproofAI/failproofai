استخدم `fp` للتحقق من تلمترية السحابة، وإدارة الإنفاذ المُدار من السحابة (السياسات، نشر الأسطول، قرارات الحماية)، وإدارة التدقيق والنتائج والمشاكل والتنبيهات والمفاتيح والمستخدمين والاستعلامات والإعدادات. استخدم [`failproofai`](/ar/reference/failproof-cli) للـ hooks المحلية والسياسات والالتقاط والتسجيل الآلي للآلات.

يمكنك أيضاً تأليف ونشر الأكواد المستضافة، وقيّمات LLM-judge و Jev، وإدارة لوحات البيانات، والتحقق من المشاعر، واستخدام مساعد لوحة البيانات من الطرفية.

ثبّت Cloud CLI المُصدر كأداة معزولة:

```bash
uv tool install fp-cloud-cli
fp version
```

## تسجيل الدخول

```bash
fp login
fp whoami
```

## بناء الجملة

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

يجب أن تأتي الخيارات العامة قبل الأمر:

```bash
fp --json sessions --since 24h
```

قم بتشغيل `fp COMMAND --help` أو `fp COMMAND SUBCOMMAND --help` للحصول على مساعدة من الطرفية.

## أوامر CLI

### تأليف قيّم

`fp evaluators` يؤلف التعاريف؛ `fp evals` يقرأ النتائج. مطلوب مثيل مُدار مفعّل (`fp evaluators instances`). التأليف يحتاج إلى `evaluations:trigger`؛ التشغيلات الجافة للجلسة وتشكيل المخطط يحتاجان أيضاً `events:read`.

الكود هو تعبير Python مقيد واحد. احفظ هذا باسم `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

حكم LLM:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

ملف Jev الثنائي والمقياس المدرج:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
يفعّل الإنشاء القيّم. النشر ينشئ نسخة جديدة غير قابلة للتغيير، ثم يعطّل النسخ الأقدم المفعّلة. الفشل اللاحق يترك النسخة الجديدة منشورة: افحص `evaluators list --all` قبل إعادة المحاولة.
رفض التشغيلات الجافة للحكم من قِبل السحابة. التشغيلات الجافة لـ Jev تنفق ميزانية النموذج.
تغطية الملء السابق تشمل قيّمات الكود والحكم و Jev وتقبل 90 يوماً كحد أقصى؛ تصطف فقط الجلسات التي لم يسجلها القيّم بعد. الحكم وتعبئة Jev تنفق ميزانية النموذج، لذا شغّل `fp evaluators backfill --dry-run` أولاً.
يظهر الإخراج البشري نتائج التشغيل الجاف لكل جلسة قبل الإنشاء/النشر.
تتوقف المعاينات الفاشلة عن الكتابة ما لم تمرر `--force` بشكل صريح بعد المراجعة.
</Warning>

يتطلب صياغة AI `fp login` ويكتب مواصفات مقبولة من قِبل الإنشاء/النشر:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| الأمر | الخيارات / السلوك |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | المصدر الكامل/الغلاف |
| `fp evaluators create` | `--key`, `--name`, `--version`, `--label` متكرر, `--condition EXPR\|@file`, مصدر واحد, `--dry-run-on` متكرر, `--disabled`, `--force` صريح للمعاينات الفاشلة |
| `fp evaluators deploy KEY` | أعلام المصدر نفسه؛ `--version`, `--backfill 7d` (أي نوع، 1–90 يوم), `--force`؛ النسخ الرقمية تزداد تلقائياً؛ يوفر KEY مواصفات ملف مفقودة `eval_key` |
| `fp evaluators draft "intent"` | جلسة؛ `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | أعلام المصدر أو `--file`, `--session` متكرر (الحد الأقصى 10)؛ بلا شيء = جمع فقط |
| `fp evaluators enable\|disable KEY[@VERSION]` | تبديل |
| `fp evaluators label KEY[@VERSION]` | `--add` متكرر, `--remove` |
| `fp evaluators instances\|schema\|jobs` | افحص الأسطول المُدار/المخطط/الوظائف |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`؛ كود، حكم و Jev |

أعلام الكود هي `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. أعلام الحكم هي `--judge --criteria TEXT`, `--step` متكرر و
`--threshold`. أعلام Jev هي `--jev noul --instructions --true --false` أو
`--jev score --instructions` مع 3–5 قيم `--level` مميزة، الأسوأ أولاً.
يتطلب الحكم/Jev درجة؛ العتبات هي 0–1. يتم رفض خطوات الحكم الثنائية.

تحتوي ملفات المواصفات على `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds` بالضبط.
`evaluator_source` للحكم/Jev هو سلسلة غلاف JSON. لا تضمّن معرّفات الصفوف أو
حالة مفعّلة أو بيانات تعريف الاستدلال AI. `--file` وأعلام المواصفات المنفصلة
حصرية؛ يمكن للنشر تجاوز نسخة الملف. ملفات الإخراج لا تُستبدل أبداً.

### عناصر تحكم لوحة البيانات الجديدة

جميع الأوامر تقبل `--json` عام. تخرج 404s المسار غير المعروف 6 مع "غير متاح
على هذا FailproofAI Cloud حتى الآن". تخرج 404s السجل المفقود أيضاً 6 لكن تبلّغ عن أن
السجل لم يُعثر عليه. أوامر الجلسة فقط ترفض وضع المفتاح قبل HTTP (خروج 2).

أوامر الإنسان تستخدم الملخصات والجداول. للتصديرات JSON الخام، مرّر `--json` عام
أو احفظ مع `--out FILE`؛ وإلا فإن جلسة وتصديرات استعلام JSON تظهر
عرض قابل للقراءة. تصديرات CSV تبقى CSV عادي للأنابيب.

| الأوامر | الخيارات / الملاحظات |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | إنشاء `--name`, `--description`, `--file` تعريف؛ تحديث يحافظ على الحقول غير المذكورة |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | إضافة `--query ID --chart TYPE --title`؛ الإعدادات/الهندسة أو التخطيط عبر `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | تصدير `--out`؛ السجل هو سجل التقييم |
| `fp sessions import FILE...` | Claude Code نسخ، Codex طرح أو حدث JSONL (`.gz` تمام)؛ `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`؛ يحتاج `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`؛ قائمة `--limit`؛ رسائل `--session-id` |
| `fp query compose "question"` | جلسة؛ `--run` |
| `fp query export [ID]` | أو `--sql`؛ `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | القضايا يمكن `--create --title --summary` أو `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON؛ تحديث `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | جلسة؛ يصوغ سياسة من أحداث منظمتك، لا ينشر أبداً |
| `fp policies backtest [FILE_OR_ID]` | جلسة؛ regex يعيد تشغيل الوحدة؛ `jev`/`both` (منشورة، أو `--semantic checks.json`) تقدّر مجاناً، `--run [--sample N]` ينفق بدل Jev؛ `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | جلسة؛ هل يمكن لسياسة منع هذه القضية |
| `fp issues facets` | القيم التي يمكن لمرشحات صندوق الوارد أن تأخذها، مع العدد |
| `fp agent brief` | جلسة؛ `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | جلسة؛ يشتق slug المحذوف، لا يبدّل المنظمة |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | مجموعات الإذن؛ إنشاء `--name --permission`؛ تحديث استبدال `--permission` أو دمج `--add/--remove`؛ `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | حذف حسب المعرّف |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` يحتاج مفتاح API؛ الخطة (العروض والمحاكمة) والمطالبة تتطلب جلسة موقّعة |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 رمز |
| `fp otel status\|enable\|disable` | مفتاح إدخال منظمة السحابة، وليس الالتقاط المحلي |
| `fp slack status\|disconnect` | جلسة |

`fp agent ask` يعرض SQL القطع الأثرية كجداول/إحصائيات من خلال `queries:run`.
الموافقات على الكتابة تظهر التغيير المقترح وتطالب على طرفية. البرامج النصية و
`--json` ترفض ما لم يكن `--approve` صريح. أشكال JSON الموجودة تبقى
غير مغيّرة عند عدم إرجاع القطعة الأثرية.


على الطرفية، `fp login` يبدأ على رابط، للتسجيل مع متصفحك أو SSO، ويفتحه (عبر SSH أو بدون عرض يظهره فقط، ويعمل من أي جهاز)؛ وافق عليه وتنتهي الطرفية بمفردها. تحصل هذه الطرفية على وصولك في جميع منظماتك حتى انتهاء الجلسة، لذا وافق فقط على رابط طلبته للتو. إذا بدأت تسجيل الدخول على شبكة مختلفة، تحصل على بريد إلكتروني بمجرد وجود الجلسة، وتحذرك الصفحة حيث يمكن للنشر أن يخبر. اضغط **Tab** للحصول على رمز 6 أرقام عبر البريد الإلكتروني بدلاً من ذلك، و Tab مرة أخرى للعودة. `--email`, `--json` وأي شيء بدون طرفية يستخدم الكود.

### الأحداث

```text
fp events [OPTIONS]
```

يسرد أحداث الوكيل الفردية. الخلاصة الخفيفة الافتراضية تستبعد الحمولات الخام؛ استخدم `--full` فقط للتحقيق المحدود.

| الخيار | الوصف |
| --- | --- |
| `--limit`, `-n <n>` | أقصى إجمالي صفوف. الافتراضي: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, أو `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | نطاق ISO 8601 UTC؛ يتجاوز `--since`. |
| `--env <value>` | مرشح البيئة؛ كرّر أو افصل بفواصل. |
| `--event-type <value>` | مرشح نوع الحدث؛ كرّر أو افصل بفواصل. |
| `--agent-id <value>` | مرشح الوكيل؛ كرّر أو افصل بفواصل. |
| `--session-id <value>` | مرشح الجلسة؛ كرّر أو افصل بفواصل. |
| `--search <text>` | بحث نصي الحمولة؛ قابل للتكرار، مع مطابقة أي مصطلح. |
| `--order asc\|desc` | ترتيب الوقت. الافتراضي: الأحدث أولاً. |
| `--all` | ترقيم تلقائي حتى `--limit`. |
| `--cursor <token>` | استئناف من مؤشر معتم. |
| `--page-size <n>` | صفوف لكل طلب مع `--all`؛ أقصى `200`. |
| `--full` | تضمين الحمولات الخام من خلال نقطة نهاية الحدث الأثقل. |
| `--fields <csv>` | إرجاع الحقول المحددة فقط؛ طلب `payload` يفعّل الوضع الكامل. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` يرقّم **حتى `--limit`**, الذي يرجح إلى **50** — لذا `--all` بمفرده يتوقف عند 50 صفاً. عندما يتوقف مبكراً، يحمل الرد `next_cursor` للاستئناف منه؛ `"next_cursor": null` يعني الخلاصة حقاً كانت مستنفدة.
</Note>

#### خيارات إنشاء التدقيق

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| الخيار | الوصف |
| --- | --- |
| `--file <path>` | أساس التعريف على JSON، أو استخدم `-` لـ stdin. أعلام صريحة تتجاوز قيم الملف. |
| `--description <text>` | اذكر سؤال الفشل أو الغرض. |
| `--enabled` / `--disabled` | ابدأ الجدولة أم لا. الافتراضي: مفعّل. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. الافتراضي: `86400`. |
| `--schedule-anchor <timestamp>` | مرحلة UTC ثابتة بصيغة ISO 8601. الافتراضي: 09:00 UTC التالية. |
| `--window-mode since_last\|fixed` | استمر بعد آخر نافذة محللة بالكامل أم افحص نافذة متجددة بشكل متكرر. الافتراضي: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. الافتراضي: `604800`. |
| `--scope '<json>'` | مرشح حسب `environments`, `agent_ids`, أو حقول نطاق مدعومة أخرى. |
| `--ignore-error-type <type>` | استبعد أنواع الأخطاء؛ كرّر أو افصل بفواصل. |
| `--llm` / `--no-llm` | فعّل أو عطّل التحليل الوكيل. الافتراضي: مفعّل. |
| `--top-k <n>` | احتفظ بـ `1`–`500` نتائج. الافتراضي: `50`. |
| `--sensitivity low\|medium\|high` | اضبط حساسية الإبلاغ. الافتراضي: `medium`. |
| `--channels '<json>'` | مصفوفة قناة الإخطار. |
| `--text <brief>` | ملخص مضمّن، 8,192 حرف كحد أقصى. |
| `--text-file <path>` | اقرأ الملخص من ملف؛ حصري مع `--text`. |
| `--url <https-url>` | أضف مراجع HTTPS عامة؛ كرّر حتى خمس مرات. |

ضمّن السياق أثناء الإنشاء عندما يحتاجه التشغيل الأول. ينفّذ الإنشاء التعريف والسياق معاً قبل بدء التشغيل في الطابور.

<Note>
  `fp audits run` غير متزامن. استقصِ `fp audits runs NAME` حتى ينجح أو يفشل آخر تشغيل قبل قراءة النتائج.
</Note>
