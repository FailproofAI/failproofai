استخدم `fp` للتفتيش على بيانات المراقبة السحابية، وإدارة الإنفاذ المدار سحابيًا (السياسات، نشر الأسطول، قرارات الحماية)، وإدارة عمليات التدقيق والنتائج والمشاكل والتنبيهات والمفاتيح والمستخدمين والاستعلامات والإعدادات. استخدم [`failproofai`](/ar/reference/failproof-cli) للخطافات المحلية والسياسات والالتقاط وتسجيل الآلات.

يمكنك أيضًا تأليف ونشر الكود المستضاف، ومقيّمات LLM-judge و Jev، وإدارة لوحات المعلومات، والتفتيش على المشاعر، واستخدام مساعد لوحة المعلومات من المحطة الطرفية.

ثبّت CLI السحابي المُصدر كأداة معزولة:

```bash
uv tool install fp-cloud-cli
fp version
```

## تسجيل الدخول

```bash
fp login
fp whoami
```

## بناء الجملة

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

يجب أن تأتي الخيارات العامة قبل الأمر:

```bash
fp --json sessions --since 24h
```

قم بتشغيل `fp COMMAND --help` أو `fp COMMAND SUBCOMMAND --help` للحصول على مساعدة من المحطة الطرفية.

## أوامر CLI

### تأليف مقيّم

يقوم `fp evaluators` بتأليف التعريفات؛ `fp evals` يقرأ النتائج. مثيل مُدار مُفعّل مطلوب (`fp evaluators instances`). يتطلب التأليف `evaluations:trigger`؛ جولات الجفاف للجلسة وتحديد مخطط أيضًا يحتاج إلى `events:read`.

الكود هو تعبير Python محدود واحد. احفظ هذا باسم `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

قاضي LLM:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

ملف Jev الثنائي وطوق مصنف:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
يفعّل الإنشاء المقيّم. ينشئ النشر نسخة جديدة ثابتة، ثم يعطّل الإصدارات الأقدم المفعّلة. قد يترك الفشل في المتابعة النسخة الجديدة منشورة: افحص `evaluators list --all` قبل إعادة المحاولة.
رفض Cloud جولات الجفاف للقاضي. تنفق جولات الجفاف Jev ميزانية النموذج.
يغطي التعبئة رجعية مقيّمات الكود والقاضي و Jev ويقبل 90 يومًا على الأكثر؛ فهي تصف فقط الجلسات التي لم يسجل المقيّم بعد. قد تنفق عمليات التعبئة الرجعية للقاضي و Jev ميزانية النموذج، لذا قم بتشغيل `fp evaluators backfill --dry-run` أولاً.
يعرض إخراج البشر نتائج جفاف لكل جلسة قبل الإنشاء/النشر.
تتوقف المعاينات الفاشلة عن الكتابة ما لم تمرر صراحةً `--force` بعد المراجعة.
</Warning>

يتطلب المسودة بواسطة AI `fp login` وتكتب مواصفات مقبولة من قبل الإنشاء/النشر:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| الأمر | الخيارات / السلوك |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | المصدر/المجلة الكاملة |
| `fp evaluators create` | `--key`, `--name`, `--version`, `--label` مكرر، `--condition EXPR\|@file`، مصدر واحد، `--dry-run-on` مكرر، `--disabled`، `--force` صريح للمعاينات الفاشلة |
| `fp evaluators deploy KEY` | نفس أعلام المصدر؛ `--version`, `--backfill 7d` (أي نوع، 1–90 يومًا)، `--force`؛ الإصدارات الرقمية تزداد تلقائيًا؛ KEY يوفر ملف مواصفات غير موجود `eval_key` |
| `fp evaluators draft "intent"` | جلسة؛ `--kind code\|judge\|jev`، `--out` |
| `fp evaluators dry-run` | أعلام المصدر أو `--file`، `--session` مكرر (الحد الأقصى 10)؛ بدون = ترجمة فقط |
| `fp evaluators enable\|disable KEY[@VERSION]` | بدّل |
| `fp evaluators label KEY[@VERSION]` | `--add` مكرر، `--remove` |
| `fp evaluators instances\|schema\|jobs` | افحص الأسطول/المخطط/الوظائف المدارة |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`؛ الكود والقاضي و Jev |

أعلام الكود هي `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. أعلام القاضي هي `--judge --criteria TEXT`, `--step` مكرر و
`--threshold`. أعلام Jev هي `--jev noul --instructions --true --false` أو
`--jev score --instructions` مع 3–5 قيم `--level` مختلفة، الأسوأ أولاً.
يتطلب القاضي/Jev درجة؛ الحدود الدنيا 0–1. يتم رفض خطوات القاضي الثنائية.

تحتوي ملفات المواصفات على بالضبط `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
`evaluator_source` للقاضي/Jev عبارة عن سلسلة مجلة JSON. لا تضمن معرّفات الصفوف،
حالة مُفعّلة، أو بيانات وصفية للمنطق AI. `--file` وأعلام المواصفات المنفصلة حصرية؛ يمكن للنشر تجاوز إصدار الملف. لا تُستبدل ملفات الإخراج أبدًا.

### عناصر لوحة المعلومات الجديدة

تقبل جميع الأوامر `--json` عام. خروج 404 من مسار غير معروف 6 مع رسالة بأن عدم توفرها
على FailproofAI Cloud هذا حتى الآن. خروج 404 المتعلق بالسجل الغير موجود أيضًا 6 لكن يُبلّغ بأن
السجل لم يُعثر عليه. تأمر الأوامر الخاصة بالجلسة الوضع الرئيسي قبل HTTP (خروج 2).

تستخدم أوامر البشر الملخصات والجداول. لتصدير JSON الخام، مرّر `--json` عام
أو احفظ بـ `--out FILE`؛ وإلا فإن جلسة وصادرات استعلام JSON تعرض
عرض قابل للقراءة. تبقى صادرات CSV بصيغة CSV عادية للأنابيب.

| الأوامر | الخيارات / الملاحظات |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | إنشاء `--name`, `--description`, `--file` تعريف؛ التحديث يحافظ على الحقول غير المذكورة |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | إضافة `--query ID --chart TYPE --title`؛ التكوين/الهندسة أو التخطيط عبر `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | تصدير `--out`؛ السجل هو سجل التقييم |
| `fp sessions import FILE...` | Claude Code نصوص، Codex rollouts أو حدث JSONL (`.gz` حسناً)؛ `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`؛ يحتاج `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`؛ قائمة `--limit`؛ رسائل `--session-id` |
| `fp query compose "question"` | جلسة؛ `--run` |
| `fp query export [ID]` | أو `--sql`؛ `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | المشاكل يمكنها `--create --title --summary` أو `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON؛ تحديث `--enabled/--disabled` |

| `fp policies backtest [FILE_OR_ID]` | جلسة؛ regex تعيد تشغيل الوحدة؛ `jev`/`both` (منشور، أو `--semantic checks.json`) تقدير مجاني، `--run [--sample N]` ينفق مخصص Jev؛ `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | جلسة؛ هل يمكن لسياسة منع هذه المشكلة |
| `fp issues facets` | قيم التصفية الصندوقية يمكنها أن تأخذ، مع الأعداد |
| `fp agent brief` | جلسة؛ `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | جلسة؛ تستخرج الملخص المحذوف، لا تبدل المنظمة |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | مجموعات الأذونات؛ إنشاء `--name --permission`؛ تحديث استبدل `--permission` أو دمج `--add/--remove`؛ `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | الحذف برقم الهوية |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` يحتاج مفتاح API؛ الخطة (العروض والتجربة) والمطالبة تتطلب جلسة موقّعة |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 رمز |
| `fp otel status\|enable\|disable` | مفتاح ingest منظمة Cloud، وليس الالتقاط المحلي |
| `fp slack status\|disconnect` | جلسة |

يعرض `fp agent ask` SQL الاصطناعي كجداول/إحصائيات عبر `queries:run`.
توافق الكتابة تعرض التغيير المقترح وتطالب على محطة طرفية. تأمر الكود والبرامج النصية و
`--json` برفض ما لم يكن `--approve` صريحًا. تبقى أشكال JSON الموجودة
دون تغيير عند عدم إرجاع أي اصطناعي.

### الأحداث

```text
fp events [OPTIONS]
```

يسرد أحداث الوكيل الفردية. يستبعد التغذية الخفيفة الافتراضية الحمولات الخام؛ استخدم `--full` فقط للتحقيق المحدود.

| الخيار | الوصف |
| --- | --- |
| `--limit`, `-n <n>` | الحد الأقصى للصفوف الإجمالية. الافتراضي: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, أو `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | نطاق ISO 8601 UTC؛ يتجاوز `--since`. |
| `--env <value>` | مرشح البيئة؛ كرر أو فاصل بفاصلة. |
| `--event-type <value>` | مرشح نوع الحدث؛ كرر أو فاصل بفاصلة. |
| `--agent-id <value>` | مرشح الوكيل؛ كرر أو فاصل بفاصلة. |
| `--session-id <value>` | مرشح الجلسة؛ كرر أو فاصل بفاصلة. |
| `--search <text>` | بحث نص الحمولة؛ قابل للتكرار، مع أي مصطلح متطابق. |
| `--order asc\|desc` | ترتيب الوقت. الافتراضي: الأحدث أولاً. |
| `--all` | صفحة تلقائية حتى `--limit`. |
| `--cursor <token>` | استئناف من مؤشر معتم. |
| `--page-size <n>` | صفوف لكل طلب مع `--all`؛ الحد الأقصى `200`. |
| `--full` | تضمين حمولات خام عبر نقطة الحدث الأثقل. |
| `--fields <csv>` | إرجاع الحقول المحددة فقط؛ يتطلب طلب `payload` الوضع الكامل. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` يصفحة **حتى `--limit`**، الذي افتراضيًا **50** — لذا `--all` وحده
  يتوقف عند 50 صف. عندما يتوقف مبكراً يحمل الرد
  `next_cursor` للاستئناف من؛ `"next_cursor": null` يعني التغذية فعلاً
  استنزفت.
</Note>

#### خيارات إنشاء التدقيق

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| الخيار | الوصف |
| --- | --- |
| `--file <path>` | أسس التعريف على JSON، أو استخدم `-` لـ stdin. تتجاوز الأعلام الصريحة قيم الملف. |
| `--description <text>` | حدد سؤال الفشل أو الغرض. |
| `--enabled` / `--disabled` | ابدأ الجدولة على أو إيقاف. الافتراضي: مُفعّل. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. الافتراضي: `86400`. |
| `--schedule-anchor <timestamp>` | مرحلة UTC ثابتة بشكل ISO 8601. الافتراضي: التالي 09:00 UTC. |
| `--window-mode since_last\|fixed` | استمر بعد آخر نافذة محللة بالكامل أو افحص نافذة متداولة بشكل متكرر. الافتراضي: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. الافتراضي: `604800`. |
| `--scope '<json>'` | رشح حسب `environments`, `agent_ids`, أو حقول نطاق مدعومة أخرى. |
| `--ignore-error-type <type>` | استبعد أنواع الأخطاء؛ كرر أو افصل بفواصل. |
| `--llm` / `--no-llm` | فعّل أو عطّل تحليل وكيل. الافتراضي: مُفعّل. |
| `--top-k <n>` | احتفظ بـ `1`–`500` نتيجة. الافتراضي: `50`. |
| `--sensitivity low\|medium\|high` | اضبط حساسية التقرير. الافتراضي: `medium`. |
| `--channels '<json>'` | مصفوفة قنوات الإخطار. |
| `--text <brief>` | موجز مضمنة، 8,192 أحرف كحد أقصى. |
| `--text-file <path>` | اقرأ الملخص من ملف؛ متنافي مع `--text`. |
| `--url <https-url>` | أضف مرجع HTTPS عام؛ كرر حتى خمس مرات. |

أضمن السياق أثناء الإنشاء عندما يحتاج التشغيل الأول إليه. يلتزم الإنشاء بالتعريف والسياق معاً قبل بدء التشغيل المدرج.

<Note>
  `fp audits run` غير متزامن. استقصِ `fp audits runs NAME` حتى ينجح التشغيل الأحدث أو ينجح قبل قراءة النتائج.
</Note>
