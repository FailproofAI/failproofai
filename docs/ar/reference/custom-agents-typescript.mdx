Node 20.9 أو أحدث. ESM و CommonJS. بدون تبعيات وقت التشغيل.

<Note>
  هذا SDK وبيثون يكتبان **نفس الأحداث إلى نفس الملف**. أسطول به وكلاء Node ووكلاء Python ينتج مجموعة جلسات واحدة وليس اثنتين، ولا شيء في لوحة التحكم يفرق بينهما. اختر لكل خدمة وليس لكل شركة.
</Note>

## التثبيت

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

محولات الإطار العمل مرسلة في الحزمة نفسها. الأطر العمل **اعتماديات نظير اختيارية** — معلنة حتى تكون النطاقات المدعومة مرئية وليست مثبتة نيابة عنك ويتم استيرادها فقط عند استدعاء `instrument()`.

## اتصل بخادم Failproof

متطابقة مع Python SDK: إنشاء مفتاح `events:add` تحت **Admin → Keys**، ثم [اتصل بالخادم](/ar/start/setup#connect-a-machine-to-cloud) على جهاز الوكيل. يكتب SDK إلى القرص؛ يشحن الخادم.

## الإعدادات

### رقع OpenTelemetry (اختياري)

ثبت OpenTelemetry بشكل منفصل مع `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
ثم أضف FailproofAI إلى معالجات مزود الخدمة:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

لمزود موجود، احتفظ بمعالجاته الأخرى في نفس القائمة. المزودون
الذين يعرضون `addSpanProcessor` يمكن بدلاً من ذلك تمريرهم ك `{ provider }`. بدون
خيارات، الإعداد يسجل مزود جديد فقط إذا لم يكن هناك مزود مسجل بالفعل.
`OtelSpanExporter` يمكن أيضاً استخدامه مباشرة مع معالج خاص بك.

التصديرات تمر عبر خادم FailproofAI المتصل؛ لا يرسل SDK أي
طلبات شبكة ولا يحتاج إلى مفتاح أو مستمع محلي. اطلب من مسؤول تفعيل
[استيعاب OpenTelemetry](/ar/agenteye/opentelemetry). `instrument()` بدون خيارات لا يفعل
هذا المُصدِّر. `uninstrument("otel")` يعطل معالج خاص به فقط.
سمات الرقع الخاصة بك تتحكم في التقاط المحتوى؛ فلش مزودك قبل الخروج.
OpenTelemetry يبقى تبعية تطبيق اختيارية وليست تبعية SDK صعبة.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| الخيار | ما يفعله |
| --- | --- |
| `environment` | التسمية على كل حدث — `production`, `staging`, `prod-eu`. الافتراضي `dev`. |
| `flushInterval` | كم مرة يكتب المؤقت إلى القرص بالثواني. الافتراضي `0.5`. |
| `baseDir` | أين تكتب. الافتراضي ملف الخادم وهو ما تريده ما لم تعرف خلاف ذلك. |

لا يتم تطبيق شيء ما لم يتم التحقق من صحته كله، لذا استدعاء مرفوض يترك SDK بالضبط كما كان بدلاً من امتلاك `baseDir` جديد والفترة القديمة.

عين بمتغير بيئة بدلاً من ذلك:

| المتغير | ما يفعله |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | يعين `environment` بدون تغيير الكود. خيار `configure()` يفوز به. |
| `FAILPROOFAI_HOME` | ينقل جذر Failproof AI الذي يحتفظ بالملف. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (افتراضي), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` يجعل أخطاء الأداة ترمي بدلاً من تسجيلها. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` يجعل مشكلة التوافق مع الإطار ترمي بدلاً من التحذير والمتابعة. |

<Warning>
  **لا فواصل في `environment`.** يقسم الاستيعاب هذا الحقل على الفواصل لبناء المرشحات، وتخطي أي حدث يحتوي علامته على أحدها — لذلك التشغيل كله يختفي بصمت. اكتب `prod-eu` وليس `prod,eu`.

  `configure({ environment: "prod,eu" })` يرمي حتى تكتشف فوراً. `AGENTEYE_ENVIRONMENT` لا يمكن أن يرمي — لا أحد يناديك — لذا يحذر مرة واحدة ويعود إلى `dev`.
</Warning>

وجه خطوط سجل SDK الخاصة إلى المسجل الخاص بك مع `failproofai.setLogger({ debug, info, warn, error })`.

## الإيقاف

الأحداث المخزنة مؤقتاً تُفرغ على `process.on("exit")`.

عملية مقتولة بإشارة لا تصل إلى ذلك أبداً، والافتراضي في Node لـ `SIGTERM` هو الإنهاء بدون تشغيل معالجات الخروج — لذا وكيل في حاوية يفقد كل ما لم تكتبه الفترة الأخيرة.

<Warning>
  **هذا SDK لن يثبت معالج إشارة لك.** تسجيل واحد يغير سلوك العملية: مستمع يقمع الإنهاء الافتراضي في Node، لذا مكتبة أضافت واحد ستوقف بصمت Ctrl-C من العمل. أضف الخاص بك:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

نص قصير العمر أو معالج بدون خادم يجب أن يفعل `await failproofai.flush()` قبل العودة — الفترة وحدها لا تضمن التسليم.

## الهوية

كل حدث ينتمي إلى جلسة ووكيل. **النطاقات تملأ الاثنين**، لذا نادراً ما تمررهم:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

تمرير `sessionId` أو `agentId` بشكل صريح يعمل أيضاً ويفوز. بدون قيد أو تمرير، الاستدعاء يرمي بدلاً من بث حدث Cloud سيتجاهله بصمت.

<Note>
  الهوية تركب على `AsyncLocalStorage`. تتابع `await`, `.then()`, المؤقتات وأي رد استدعاء تم إنشاؤه داخل النطاق. لا تتبع رد استدعاء تم تخزينه أثناء تشغيل واحد واستدعاء خلال آخر، أو عمل يتم تسليمه عبر حد `worker_threads` — لفف تلك في `failproofai.propagate()` أو أحداثها تهبط غير مرفقة.
</Note>

### النطاقات

| النطاق | ينبعث | الإرجاع |
| --- | --- | --- |
| `session(body)` | لا شيء — هوية فقط | ما يعيده `body` |
| `agent(id, options?, body)` | `agent_start`, ثم `agent_end` | ما يعيده `body` |
| `toolCall(name, options?, body)` | `tool_use`, ثم `tool_result` | ما يعيده `body` |

نص متزامن يبقى متزامناً: `agent("x", () => 1)` يعيد `1` وليس وعداً.

`toolCall` يسجل قيمة `body` المحللة كـ `output` للأداة، ما لم تخصص `call.output` بنفسك.

<Accordion title="دلالات الخروج" icon="arrow-right-from-bracket">

| ما حدث | الأحداث | `outcome` |
| --- | --- | --- |
| أعاد الكتلة | `agent_end` | `"success"`, أو `outcome` الخاص بك |
| رمت الكتلة | `error`, ثم `agent_end` | `"failed"` |
| `AbortError` | `agent_end` فقط | `"cancelled"` |

الخطأ يُعاد رميه دائماً.

فشل الأداة يُسجل على الورقة — `tool_result` مع سلسلة `error` — ولا ينبعث أي حدث `error` على مستوى التشغيل. واحد يمسكه حلقة الوكيل ليس فشل تشغيل، وواحد ينتشر يُبلَّغ عنه بالضبط مرة واحدة، بواسطة `agent()` المرفقة.

</Accordion>

<Accordion title="نموذج `using`" icon="brackets-curly">

عندما لا يكون العمل دالة واحدة — نطاق مفتوح في منشئ ومغلق في هدم، أو واحد يعبر تدفق تحكم موجود:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, ثم agent_end
```

كلا الشكليْن ينبعثان أحداث متطابقة بالبايت. فضل نموذج رد الاستدعاء: يعمل داخل `AsyncLocalStorage.run()`، لذا لا يوجد شيء يُفكك وكل فئة من أخطاء "مفتوح هنا، مغلق هناك" غير قابلة للوصول.

كتلة `using` التي تمسك بفشلها الخاص تبلغ عنه مع `span.fail(error)` — الموزع ليس له قناة استثناء خاصة به.

</Accordion>

## فهرس الأحداث

نفس خمسة عشر طريقة مثل Python SDK، في camelCase. معظمها يأتي في **أزواج** — تستدعي البداية، ثم النهاية، و SDK يؤقت الفجوة.

| | البدايات | النهايات |
| --- | --- | --- |
| **الوكلاء** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **النماذج** | `modelRequest` | `modelResponse` |
| **الأدوات** | `toolUse` | `toolResult` |
| **الخطافات** | `hookTriggered` | `hookCompleted` |
| **البشر** | `humanWait` | `humanInput` |

ثلاثة تقف وحدها: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="كل حقل، لكل طريقة" icon="table">

كل طريقة تأخذ أيضاً `sessionId` و `agentId`، التي تملأها النطاقات لك. أي شيء محذوف يُطرح بدلاً من إرساله ك JSON `null`.

| الطريقة | مطلوبة | اختيارية |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

أي مفتاح آخر تضيفه يصبح حقل حمولة مخصص. فضاء أي شيء خاص بالإطار `fw_*`؛ اسم يتضارب مع حقل معلن يُرفض بدلاً من الكتابة الصامتة فوق عمود مرفوع.

</Accordion>

<Warning>
  **`duration_ms` يُحسب وليس مقبول.** الطرق الأربع الختامية تؤقت الفجوة من بدايتها وترفض `duration_ms` مزود من المتصل — مدة مُبلَّغ عنها غير قابلة للتحريف.

  الأزواج تُطابق على **الجلسة** والمعرّف، لا أبداً على الوكيل. أداة مفتوحة تحت `planner` ومغلقة تحت `worker` تزال تطابق، وهو ما تفعله التشغيلات متعددة الوكلاء المتداخلة بالفعل.
</Warning>

## محولات الإطار العمل

```ts
await failproofai.instrument();              // مهما وجدت
await failproofai.instrument("langchain");   // واحد بالضبط
failproofai.uninstrument();                  // ضع كل شيء بالعودة
```

| الإطار | المدعوم | كيف يرتبط |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, لذا كل `invoke`/`stream`/`batch` مغطى بدون تمرير `callbacks:` في أي مكان — أو مرر `langchainHandler()` بنفسك ولا تصحح شيء. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` في موقع الاستدعاء، أو `instrument("ai")` لكل العملية على `ai` 7 (على 4–6 هذا اختياري — انظر أدناه). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, نموذج الوكيل وحل الأداة، وأداة تشغيل سير العمل/الخطوة. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (مشترك) زائد `AgentWorkflow.runStream`، لتشغيلات سير العمل وخطواتها. |

كل نطاق يُختبر ضد إطلاقات إطار حقيقية، في كلا الطرفين، كنموذج ES وـ CommonJS، في كل تشغيل CI.

التعيين هو Python SDK، لذا نفس البرنامج يرسم نفس الشجرة بأي لغة. البناء هو **وكيل** فقط إذا كان يملك حلقة قرار LLM — تشغيل رسم بياني أو سلسلة، استدعاء `generateText`/`streamText` من SDK AI، وكيل Mastra، تشغيل وكيل LlamaIndex. عقدة LangGraph أو خطوة سير عمل هي **خطاف** (`hook_triggered`/`hook_completed`)، لا أبداً وكيل متداخل. استدعاءات النموذج هي أزواج `model_request`/`model_response` مع عدد الرموز؛ استدعاءات الأداة تحمل معرّف استدعاء الأداة الخاص بالنموذج. فشل يُسجل مرة واحدة، على الحدث الذي حدث فيه.

محول فشل التثبيت يُسجل ويُتخطى؛ الآخرون يثبتون بشكل حتى الآن لأن LlamaIndex مكسور لا يجب أن يكلفك LangGraph.

<Note>
  `instrument()` بدون حجة يكتشف إطار من خلال ما إذا كان **يحل**، وليس ما إذا كان مستوردة بالفعل — Node لا تعرض ما يعادل Python `sys.modules` لنماذج ES. إطار قمت بتثبيته لكن لا تستخدمه سيتم استيراده وإصلاحه. سمِّ الذي تريده إذا أهمك ذلك.
</Note>

<Note>
  معظم هذه الأطر تشحن بناء نموذج ES وبناء CommonJS، والذي يحمل Node كنسختين غير مرتبطين. محولات الإصلاح النسخة التي يحملها التطبيق (ونسخة CommonJS أيضاً إذا كان شيء ما استدعى بالفعل)، لذا كلا نظامي الوحدة النمطية يعملان. إطار **مجمع في مخرجك الخاص** بواسطة esbuild أو webpack بعيد عن المتناول — استخدم مساعدات موقع الاستدعاء هناك: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain بدون إصلاح

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

المعالج يعمل مع أو بدون `instrument()` وأبداً لا يسجل مرتين. `instrument("langchain")` يأخذ `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` و `captureLimit`، كما يفعل محول Python؛ `metadata: { failproofai_sdk_session_id }` على استدعاء يختار الجلسة لهذا الاستدعاء.

### Vercel AI SDK

صادرات AI SDK وظائف عادية من نموذج ES، ونموذج ES مساحة اسم غير قابلة للتغيير حسب المواصفة — لا توجد مكان لإصلاح. يستخدم نقاط الامتداد التي توثقها SDK نفسها:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // على ai 7، `telemetry: telemetry({ … })` — نفس الكائن، الاسم الجديد
});
```

هذا هو التكامل كاملاً: رقعة وكيل، زوج طلب/استجابة نموذج لكل خطوة مع عدد الرموز، وكل استدعاء أداة. موقع استدعاء واحد يعمل على كل رئيسي — `ai` 4–6 يقرأ متتبع يحمله، `ai` 7 تكامل المراقبة.

`instrument("ai")` يفعل نفس الشيء في الكل العملية **على `ai` 7**: كل استدعاء، عبر قائمة تكامل المراقبة العام من SDK AI، وهو إضافي ولا يأخذ شيء من أحد آخر.

**على `ai` 4–6، `instrument("ai")` لا يسجل شيء بنفسه، ويسجل تحذير واحد يقول ذلك.** الخطاف الوحيد في الكل العملية هذه الرئيسيات لديها هو مزود متتبع OpenTelemetry العام — فتحة واحدة OpenTelemetry ترفض تسليمها مرة واحدة يُأخذ. تسجيل لنا سيرفض بصمت `NodeSDK.start()` لاحقاً في البدء وسيرسل رقعة http/database إلى متتبع لا يصدّر شيء. استخدم `telemetry()` في موقع الاستدعاء أو `wrapModel` هناك. إذا كانت العملية لا تشغل OpenTelemetry من تلقاء نفسها، اختر مع `instrument("ai", { registerGlobalTracer: true })`: ثم يسجل كل استدعاء يمرر `experimental_telemetry: { isEnabled: true }`، وفقط يأخذ الفتحة إذا كانت لا تزال فارغة. `registerGlobalTracer: false` يبقي الافتراضي ويسكت التحذير.

إذا فضلت لف النموذج مرة واحدة، `wrapModel` يرى استدعاءات النموذج فقط، لأن استدعاءات الأداة تحدث فوق طبقة النموذج. نموذج ملفوف بلا شيء حوله يُسجل كتشغيله الخاص. استدعاء مُدفق يُغلق مهما توقف الدفق — `stop_reason: "cancelled"` عندما ينسحب المستهلك، `"error"` مع الخطأ عندما يفشل في منتصف الطريق:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

استخدام الاثنين حسناً: الوسيط يلاحظ الاستدعاء يُسجل بالفعل ويؤجل، لذا كل استدعاء يُسجل مرة واحدة.

`functionId` يسمي رقعة الوكيل. احتفظ به منخفض-قدرة — يهبط في `agent_id`، جانب لوحة التحكم الأساسي.

### Next.js

`next build` يحزم تبعيات الخادم بشكل افتراضي، وإطار محزوم في البناء هو نسخة `instrument()` لا يمكن الوصول إليها. لف الإعداد مرة واحدة واستدعِ `instrument()` من خطاف بدء Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* الإعداد الخاص بك */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` يضيف LangChain و Mastra و LlamaIndex و SDK نفسه إلى `serverExternalPackages`، يحتفظ بقائمتك. بدونه، `instrument()` يحذر مرة واحدة لكل إطار لا يمكنه الوصول إليه بدلاً من الفشل الصامت؛ إذا قمت بسرد الحزم نفسك، اضبط `FAILPROOFAI_NEXT_EXTERNALS=1`. SDK AI و مساعدات موقع الاستدعاء تعمل كلاهما. طريق Edge تحصل بناء بدون عملية: استيراد SDK آمن ولا يسجل شيء.

### عدد الرموز في استدعاءات مُدفقة

APIs متوافقة مع OpenAI فقط تبلغ الاستخدام على دفق عندما يسأل العميل. LangChain و SDK AI يسألان؛ لـ LlamaIndex اشتت `additionalChatOptions: { stream_options: { include_usage: true } }` إلى `OpenAI` LLM، و لـ Mastra بناء النموذج مع الاستخدام مُفعّل (على سبيل المثال `createOpenAICompatible({ includeUsage: true })`). بخلاف ذلك استدعاءات نموذج مُدفقة لا تحمل عدد الرموز.

### بيئات التشغيل

Node ≥ 20.9, Bun و Deno — كل إطار، كنموذج ES و CommonJS، يُختبر على كل ضد تتبع Node. SDK يعمل جنباً إلى جنب مع خادم `failproofaid`، الذي يشحن ما يكتب.

## وكيلك الخاص — بدون إطار

لحلقة وكيل كتبتها بنفسك، أو إطار بدون محول. تبث الأحداث مع نفس API التي تستخدمها المحولات تحتها، لذا التتبع له نفس الشكل والجودة.

لا تحتاج إلى معرفة كيفية تنظيم الوكيل. كل وكيل مبني بالفعل لديه ثلاث أماكن، مهما كانت وظائفه تُسمى، وتلك الثلاث هي التكامل الكامل:

| حيث | ما تضيفه | ينبعث |
| --- | --- | --- |
| حيث **تشغيل واحد** يبدأ وينتهي | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **الدالة الوحيدة التي تستدعي النموذج** | `event.modelRequest` قبل، `event.modelResponse` بعد — كلا النصفين، حتى عند الفشل | زوج واحد لكل نوبة نموذج |
| **الدالة الوحيدة التي تشغل الأدوات** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

الهوية محيطة: كل شيء داخل `agent()` يهبط على تشغيل تلك الجلسة بدون أخذ معرّف، ولا شيء آخر في البرنامج يتغير — بما في ذلك مهما يكتب الوكيل بالفعل إلى قاعدة البيانات الخاصة به.

- **خدمة أو عامل:** مرّر معرّف طلب أو وظيفة خاص بك كـ `sessionId`، لذا جلسة على لوحة التحكم والسجل في السجلات أو قاعدة البيانات الخاصة بك هي نفس السلسلة.
- **وكلاء فرعيون:** تداخل استدعاءات `agent()`. الداخلية تنضم الجلسة مع الخارجية كـ `parent_id`.
- **بث الأزواج.** `modelRequest` بدون `modelResponse` هو رقعة لوحة التحكم تُظهرها كتشغيل للأبد — لذا `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) في الريبوسيتوري هو النسخة كاملة وقابلة للتشغيل: حلقة أداة OpenAI حقيقية معلنة بالضبط هكذا، تُشغل في CI على كل تغيير كنموذج ES و CommonJS.

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

## ما لن تفعله بالعملية الخاصة بك

| | |
| --- | --- |
| **حجب حلقة الوكيل الخاص بك** | الأحداث تذهب إلى قائمة انتظار في الذاكرة؛ مؤقت يكتبها. المؤقت هو `unref`'d، لذا استيراد هذه الحزمة أبداً لا يوقف نص الخروج. |
| **النمو بدون قيد** | قائمة الانتظار محدودة بالعد *و* بالبايتات المقاسة. بعد أي منهما، الأحداث الأقدم تُطرح وتحذير يقول ذلك — انقطاع المراقبة يجب ألا يصبح OOM القتل. |
| **أخذ العملية لأسفل** | حدث واحد غير قابل للترميز يُطرح وحده، وليس الدفعة حوله. getter برمي، مرجع دائري، `BigInt`، بديل وحيد: كل يُتعامل معه بدلاً من النشر. |
| **ترك دفعة نصف-مكتوبة** | المحتوى هو `fsync`ed قبل إعادة تسمية ذرية، والمجلد هو `fsync`ed بعد، وكتابة فاشلة تنظف الملف المؤقت. |
| **ترك الكتائب قابلة للقراءة** | الدفعات هي `0600` داخل مجلد `0700`. تحمل أهداف وتعجيز وحجج الأداة وإخراج الأداة. |
| **شحن بيانات الاعتماد** | مفاتيح API والرموز و JWTs وعنوانات محمل وتعيينات على شكل سر يُحذف قبل الوصول إلى القرص. الخادم يحذف مرة أخرى قبل الرفع. |
