Node 20.9 أو أحدث. ESM و CommonJS. بدون تبعيات وقت التشغيل.

<Note>
  هذا SDK والخاص بـ Python يكتبان **نفس الأحداث إلى نفس الملف الأساسي**. أسطول يحتوي على وكلاء Node و وكلاء Python ينتج مجموعة واحدة من الجلسات وليس اثنتين، وليس هناك شيء في لوحة المعلومات يميز بينهما. اختر لكل خدمة وليس لكل شركة.
</Note>

## التثبيت

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

محولات الإطار العمل مدرجة في الحزمة نفسها. الأطر العمل هي **تبعيات نظيرة اختيارية** — معلنة بحيث تكون النطاقات المدعومة مرئية، لم يتم تثبيتها نيابة عنك أبداً، وتم استيرادها فقط عند استدعاء `instrument()`.

## توصيل خادم Failproof

متطابق مع SDK الخاص بـ Python: أنشئ مفتاح `events:add` تحت **Admin → Keys**، ثم [قم بتوصيل الخادم](/ar/start/setup#connect-a-machine-to-cloud) على جهاز الوكيل. يكتب SDK إلى القرص؛ الخادم ينقل.

## الإعدادات

### رقع OpenTelemetry (اختياري)

ثبت OpenTelemetry بشكل منفصل باستخدام `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
ثم أضف FailproofAI إلى معالجات مزود الخدمة:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

بالنسبة لمزود الخدمة الموجود، احتفظ بمعالجاته الأخرى في نفس القائمة. يمكن لمزودي الخدمة الذين يعرّضون `addSpanProcessor` بدلاً من ذلك أن يتم تمريرهم باعتبارهم `{ provider }`. بدون خيارات، يسجل الإعداد مزود خدمة جديد فقط إذا لم يكن هناك مزود مسجل بالفعل.
يمكن أيضاً استخدام `OtelSpanExporter` مباشرة مع معالج خاص بك.

تمر الصادرات عبر خادم FailproofAI المتصل؛ لا يرسل SDK طلبات شبكة ولا يحتاج إلى مفتاح أو محطة استماع محلية. اطلب من المسؤول تفعيل [استيراد OpenTelemetry](/ar/agenteye/opentelemetry). `instrument()` بسيط لا يفعّل هذا المُصدّر. `uninstrument("otel")` يعطّل معالج خاص به فقط. تتحكم سمات الرقعة الخاصة بك في التقاط المحتوى؛ قم بتنظيف مزودك قبل الخروج.
OpenTelemetry تبقى تبعية تطبيق اختيارية وليست تبعية SDK صعبة.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| الخيار | ما الذي يفعله |
| --- | --- |
| `environment` | الملصق على كل حدث — `production`، `staging`، `prod-eu`. الافتراضي هو `dev`. |
| `flushInterval` | كم مرة يكتب المؤقت إلى القرص، بالثواني. الافتراضي هو `0.5`. |
| `baseDir` | أين تكتب. الافتراضي هو ملف الخادم الأساسي، وهو ما تريده ما لم تعرف غير ذلك. |

لا يتم تطبيق شيء ما لم يتم التحقق من صحة كل شيء، لذا فإن الاستدعاء المرفوض يترك SDK تماماً كما كان بدلاً من أن يكون `baseDir` جديد والفاصل الزمني القديم.

اضبط بمتغير بيئة بدلاً من ذلك:

| المتغير | ما الذي يفعله |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | يضبط `environment` بدون تغيير الكود. خيار `configure()` يتفوق عليه. |
| `FAILPROOFAI_HOME` | يحرك جذر Failproof AI الذي يحتوي على الملف الأساسي. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`، `info`، `warn` (افتراضي)، `error`، `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` يجعل أخطاء التطبيق ترمي بدلاً من تسجيلها. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` يجعل مشكلة توافق الإطار العمل ترمي بدلاً من التحذير والمتابعة. |

<Warning>
  **بدون فواصل في `environment`.** يقسم الاستيراد هذا الحقل على الفواصل لبناء المرشحات، ويخطي أي حدث يحتوي على واحد — لذلك تختفي مجموعة كاملة بصمت. اكتب `prod-eu` وليس `prod,eu`.

  `configure({ environment: "prod,eu" })` يرمي لذا تكتشف على الفور. `AGENTEYE_ENVIRONMENT` لا يمكن أن يرمي — لا أحد يستدعيك — لذا يحذر مرة واحدة ويعود إلى `dev`.
</Warning>

أرسل أسطر السجل الخاصة بـ SDK إلى المسجل الخاص بك باستخدام `failproofai.setLogger({ debug, info, warn, error })`.

## الإيقاف

يتم تنظيف الأحداث المخزنة مؤقتاً عند `process.on("exit")`.

العملية التي يتم قتلها بواسطة إشارة لا تصل إلى ذلك أبداً، والافتراضي لـ `SIGTERM` في Node هو الإنهاء بدون تشغيل معالجات الخروج — لذا يفقد الوكيل المحتوي على الحاوية كل ما لم تكتبه الفترة الأخيرة.

<Warning>
  **هذا SDK لن يثبت معالج إشارة نيابة عنك.** تسجيل واحد يغير سلوك العملية: يقوم المستمع بإخماد الإنهاء الافتراضي لـ Node، لذا فإن المكتبة التي أضافت واحد ستوقف Ctrl-C عن العمل بصمت. أضف ملكك الخاص:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

يجب على البرنامج النصي قصير الأجل أو معالج serverless أن ينتظر `await failproofai.flush()` قبل العودة — الفاصل الزمني وحده لا يضمن التسليم.

## الهوية

تنتمي كل حدث إلى جلسة ووكيل. **النطاقات تملأ كليهما**، لذا نادراً ما تمرر:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

تمرير `sessionId` أو `agentId` بشكل صريح يعمل بشكل جيد ويفوز. بدون ربط أو تمرير، يرمي الاستدعاء بدلاً من إرسال حدث قد يتجاهله السحابة بصمت.

<Note>
  تركب الهوية على `AsyncLocalStorage`. يتابع `await` و `.then()` والمؤقتات وأي رد اتصال تم إنشاؤه داخل النطاق. **لا** يتابع رد اتصال مخزن أثناء تشغيل واحد وتم استدعاؤه أثناء تشغيل آخر، أو عمل يتم تمريره عبر حد `worker_threads` — غلف تلك الأشياء في `failproofai.propagate()` أو الأحداث الخاصة بها تهبط غير متصلة.
</Note>

### النطاقات

| النطاق | يصدر | العوائد |
| --- | --- | --- |
| `session(body)` | لا شيء — الهوية فقط | كل ما يعود `body` |
| `agent(id, options?, body)` | `agent_start`، ثم `agent_end` | كل ما يعود `body` |
| `toolCall(name, options?, body)` | `tool_use`، ثم `tool_result` | كل ما يعود `body` |

يبقى الجسم المتزامن متزامناً: `agent("x", () => 1)` يعود `1`، وليس وعد.

يسجل `toolCall` القيمة المحلولة للجسم كـ `output` للأداة، ما لم تحدد `call.output` بنفسك.

<Accordion title="دلالات الخروج" icon="arrow-right-from-bracket">

| ما الذي حدث | الأحداث | `outcome` |
| --- | --- | --- |
| عاد الكتلة | `agent_end` | `"success"`، أو `outcome` الخاص بك |
| رمت الكتلة | `error`، ثم `agent_end` | `"failed"` |
| `AbortError` | `agent_end` فقط | `"cancelled"` |

يتم إعادة رفع الخطأ دائماً.

يتم تسجيل فشل الأداة على الورقة — `tool_result` مع سلسلة `error` — ولا يصدر حدث `error` على مستوى التشغيل. الذي يمسكه حلقة الوكيل ليس فشل تشغيل، والذي ينتشر يتم الإبلاغ عنه بالضبط مرة واحدة، بواسطة `agent()` المرفق.

</Accordion>

<Accordion title="نموذج `using`" icon="brackets-curly">

عندما لا يكون العمل دالة واحدة — نطاق مفتوح في منشئ ومغلق في تفكيك، أو أحد يتخطى سير التحكم الموجود:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result، ثم agent_end
```

كلا الشكلين يصدران أحداث متطابقة البايت. فضّل شكل رد الاتصال: يعمل داخل `AsyncLocalStorage.run()`، لذا لا يوجد شيء للتراجع عنه ويكون فئة الأخطاء كاملة غير قابلة للوصول بدلاً من "مفتوح هنا، مغلق هناك".

كتلة `using` التي تمسك بفشلها الخاص تبلغ عنها باستخدام `span.fail(error)` — المتاح لا يحتوي على قناة استثناء خاصة به.

</Accordion>

## كتالوج الأحداث

نفس خمسة عشر طريقة كما في Python SDK، بـ camelCase. معظمها يأتي في **أزواج** — تستدعي الفتاح، ثم الأقرب، و SDK يوقت الفجوة.

| | يفتح | يغلق |
| --- | --- | --- |
| **الوكلاء** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **النماذج** | `modelRequest` | `modelResponse` |
| **الأدوات** | `toolUse` | `toolResult` |
| **الخطافات** | `hookTriggered` | `hookCompleted` |
| **البشر** | `humanWait` | `humanInput` |

ثلاثة تقف بمفردها: `error`، `humanPause`، `humanInterrupt`.

<Accordion title="كل حقل، لكل طريقة" icon="table">

تأخذ كل طريقة أيضاً `sessionId` و `agentId`، والتي تملأها النطاقات نيابة عنك. يتم حذف أي شيء محذوف بدلاً من إرساله كـ JSON `null`.

| الطريقة | مطلوب | اختياري |
| --- | --- | --- |
| `agentStart` | — | `goal`، `parentId` |
| `agentEnd` | — | `outcome`، `summary` |
| `agentPause` | `pauseId` | `reason`، `userId` |
| `agentResume` | `pauseId` | `reason`، `userId` |
| `modelRequest` | — | `model`، `messages`، `system`، `tools`، `requestId` |
| `modelResponse` | — | `model`، `stopReason`، `inputTokens`، `outputTokens`، `content`، `role`، `requestId` |
| `toolUse` | `toolName`، `toolCallId` | `input` |
| `toolResult` | `toolName`، `toolCallId` | `output`، `error` |
| `hookTriggered` | `hookName`، `hookId` | `triggerEvent`، `input` |
| `hookCompleted` | `hookName`، `hookId` | `outcome`، `output`، `error` |
| `error` | `errorType`، `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`، `options`، `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`، `userId` |
| `humanInterrupt` | — | `reason`، `userId`، `atStep` |

أي مفتاح آخر تضيفه يصبح حقل حمل مخصص. حدد مساحة اسم أي شيء خاص بالإطار العمل `fw_*`؛ يتم رفض الاسم الذي يتعارض مع حقل معلن بدلاً من الكتابة فوق عمود مرفوع بصمت.

</Accordion>

<Warning>
  **`duration_ms` محسوب، وليس مقبول.** تقوم الطرق الأربع الختامية بتوقيت الفجوة من فاتحها ورفض `duration_ms` يوفره المستدعي — مدة مبلغ عنها لا يمكن تزويرها.

  تتطابق الأزواج على **الجلسة** والمعرف، لا على الوكيل أبداً. أداة مفتوحة تحت `planner` ومغلقة تحت `worker` لا تزال تتطابق، وهو ما تفعله عمليات التشغيل المتعددة الوكلاء المتداخلة بالفعل.
</Warning>

## محولات الإطار العمل

```ts
await failproofai.instrument();              // كل ما يمكنه العثور عليه
await failproofai.instrument("langchain");   // بالضبط واحد
failproofai.uninstrument();                  // ضع كل شيء بعودة
```

| الإطار العمل | المدعوم | كيفية الالتصاق |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x، LangGraph.js 0.4 – 1.x | `CallbackManager.configure`، لذا يغطي كل `invoke`/`stream`/`batch` دون تمرير `callbacks:` في أي مكان — أو مرّر `langchainHandler()` بنفسك ولا تصحح شيء. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` في موقع الاستدعاء، أو `instrument("ai")` للعملية الكاملة على `ai` 7 (على 4–6 هذا اختياري — انظر أدناه). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`، دقة نموذج الوكيل وأداته، وخطوات محرك سير العمل/التشغيل. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (مشترك) بالإضافة إلى `AgentWorkflow.runStream`، لعمليات سير العمل وخطواتها. |

يتم اختبار كل نطاق مقابل إصدارات الإطار العمل الحقيقية، في كلا الطرفين، كمودول ES وكـ CommonJS، على كل تشغيل CI.

التعيين هو SDK الخاص بـ Python، لذا يرسم نفس البرنامج نفس الشجرة بأي لغة. الإنشاء هو **وكيل** فقط إذا كان يمتلك حلقة قرار LLM — تشغيل الرسم البياني أو السلسلة، استدعاء `generateText`/`streamText` بـ AI SDK، وكيل Mastra، تشغيل وكيل LlamaIndex. عقدة LangGraph أو خطوة سير العمل هي **خطاف** (`hook_triggered`/`hook_completed`)، لا أبداً وكيل متداخل. استدعاءات النموذج هي أزواج `model_request`/`model_response` مع عدد الرموز؛ استدعاءات الأداة تحمل معرّف استدعاء الأداة الخاص بالنموذج. يتم تسجيل الفشل مرة واحدة، على الحدث الذي حدث فيه.

محول يفشل في التثبيت يتم تسجيله وتخطيه؛ الآخرون لا يزالون مثبتين، لأن LlamaIndex المكسور لا يجب أن يكلفك LangGraph.

<Note>
  `instrument()` بدون حجة يكتشف إطار العمل حسب ما إذا كان **يحل**، وليس حسب ما إذا كان مستوردة بالفعل — لا يعرّض Node ما يعادل Python's `sys.modules` لوحدات ES. سيتم استيراد وتصحيح إطار عمل قمت بتثبيته ولا تستخدمه. سمِ الذي تريده إذا كان هذا مهماً.
</Note>

<Note>
  معظم هذه الأطر العمل ترسل بناء وحدة ES وبناء CommonJS، والتي يحملها Node كنسختين غير مرتبطتين. تصحح المحولات النسخة التي يحملها تطبيقك (ونسخة CommonJS أيضاً إذا كان شيء ما قد `require`d بالفعل)، لذا كلا نظام الوحدات يعمل. إطار عمل **مجمع في ملفك الخاص** بواسطة esbuild أو webpack بعيد عن متناول اليد — استخدم مساعدي موقع الاستدعاء هناك: `langchainHandler()`، `telemetry()`، `wrapTool()`.
</Note>

### LangChain بدون تصحيح

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

يعمل المعالج مع أو بدون `instrument()` ولا يسجل مرتين. `instrument("langchain")` يأخذ `sessionId`، `captureContent`، `includeChains`، `graphCallbacks` و `captureLimit`، كما يفعل محول Python؛ `metadata: { failproofai_sdk_session_id }` على استدعاء يختار الجلسة لهذا الاستدعاء.

### Vercel AI SDK

يُصدّر AI SDK وظائف عادية من وحدة ES، ومساحة اسم وحدة ES غير قابلة للتغيير بالمواصفة — لا يوجد مكان للتصحيح. يستخدم نقاط الامتداد التي توثقها SDK نفسها:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // على ai 7، `telemetry: telemetry({ … })` — نفس الكائن، الاسم الجديد
});
```

هذا هو التكامل الكامل: رقعة وكيل، زوج طلب/استجابة نموذج لكل خطوة مع عدد الرموز، وكل استدعاء أداة. يعمل موقع استدعاء واحد على كل رئيسي — `ai` 4–6 اقرأ المتتبع الذي يحمله، `ai` 7 تكامل telemetry.

`instrument("ai")` يفعل نفس الشيء على مستوى العملية **على `ai` 7**: كل استدعاء، من خلال قائمة تكامل telemetry العامة لـ AI SDK، والتي تضيف ولا تأخذ من أي شخص آخر.

**على `ai` 4–6، `instrument("ai")` لا يسجل شيء بمفرده، ويسجل تحذير واحد قائلاً ذلك.** الخطاف الوحيد على مستوى العملية الذي تملكه هذه الرئيسيات هو مزود التتبع العام لـ OpenTelemetry — أحادي العنصر يرفض OpenTelemetry تسليمه مرة واحدة. تسجيل ملكنا سيرفض صراحة `NodeSDK.start()` لاحقاً في البدء وإرسال رقع http/database الخاصة بك إلى متتبع لا يُصدّر شيء. استخدم `telemetry()` في موقع الاستدعاء أو `wrapModel` هناك. إذا كانت العملية لا تشغل OpenTelemetry الخاصة بها، قم بالاختيار مع `instrument("ai", { registerGlobalTracer: true })`: ثم يسجل كل استدعاء يمرر `experimental_telemetry: { isEnabled: true }`، ويأخذ الأنصة فقط إذا كان لا يزال فارغاً. `registerGlobalTracer: false` يحافظ على الافتراضي ويسكت التحذير.

إذا كنت تفضل تغليف النموذج مرة واحدة، يرى `wrapModel` استدعاءات النموذج فقط، لأن استدعاءات الأداة تحدث فوق طبقة النموذج. نموذج ملفوف يُستدعى بدون شيء حوله يُسجل كتشغيل خاص به. استدعاء بث يغلق بأي طريقة يتوقف السحب — `stop_reason: "cancelled"` عندما يلغي المستهلك، `"error"` مع الخطأ عندما يفشل في منتصف الطريق:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

استخدام كليهما بخير: يلاحظ الوسيط أن الاستدعاء قد تم تسجيله بالفعل ويؤجل، لذا يتم تسجيل كل استدعاء مرة واحدة.

`functionId` يسمي رقعة الوكيل. اجعله منخفض الأساسية — ينزل في `agent_id`، وجهة لوحة المعلومات الأساسية.

### Next.js

`next build` يجمع تبعيات الخادم افتراضياً، وإطار العمل المجمع في البناء هو نسخة `instrument()` لا يمكنها الوصول إليها. غلف الإعدادات مرة واحدة واستدعِ `instrument()` من خطاف بدء تشغيل Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` يضيف LangChain و Mastra و LlamaIndex و SDK نفسه إلى `serverExternalPackages`، يحافظ على قائمتك. بدونه، `instrument()` يحذر مرة واحدة لكل إطار عمل لا يمكنه الوصول إليه بدلاً من الفشل الصامت؛ إذا قمت بإدراج الحزم بنفسك، عيّن `FAILPROOFAI_NEXT_EXTERNALS=1`. يعمل Vercel AI SDK ومساعدو موقع الاستدعاء بأي طريقة. مسار حافة يحصل على بناء لا-عملية: استيراد SDK آمن ولا يسجل شيء.

### عدد الرموز في استدعاءات البث

تقتصر واجهات برمجة تطبيقات OpenAI المتوافقة على الإبلاغ عن الاستخدام في بث عندما يطلبها العميل. تطلب LangChain و Vercel AI SDK؛ بالنسبة لـ LlamaIndex مرّر `additionalChatOptions: { stream_options: { include_usage: true } }` إلى `OpenAI` LLM الخاص بها، وبالنسبة لـ Mastra بناء النموذج مع تفعيل الاستخدام (على سبيل المثال `createOpenAICompatible({ includeUsage: true })`). خلاف ذلك، استدعاءات النموذج المبثوثة لا تحمل عدد رموز.

### البيئات

Node ≥ 20.9 و Bun و Deno — كل إطار عمل، كمودول ES وكـ CommonJS، يتم اختبارهما على كل واحد مقابل تتبع Node. يعمل SDK بجانب خادم `failproofaid`، الذي ينقل ما يكتبه.

## وكيلك الخاص — بدون إطار عمل

لحلقة وكيل كتبتها بنفسك، أو إطار عمل بدون محول. تصدر الأحداث بنفس واجهة برمجة التطبيقات التي تستخدمها المحولات تحتها، لذا يحتوي التتبع على نفس الشكل والجودة.

لا تحتاج إلى معرفة كيفية تنظيم الوكيل. لكل وكيل مبني يدوياً بالفعل ثلاث أماكن، مهما كانت وظائفه تسمى، وهذه الثلاثة هي التكامل كاملاً:

| حيث | ما يجب إضافته | يصدر |
| --- | --- | --- |
| حيث **تشغيل واحد** يبدأ وينتهي | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **دالة واحدة تستدعي النموذج** | `event.modelRequest` قبل، `event.modelResponse` بعد — كلا النصفين، حتى عند الفشل | زوج واحد لكل دور نموذج |
| **دالة واحدة تشغل الأدوات** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

الهوية محيطة: كل شيء داخل `agent()` ينزل على جلسة التشغيل بدون أخذ معرّف، ولا شيء آخر في البرنامج يتغير — بما في ذلك كل ما يكتبه الوكيل بالفعل في قاعدة البيانات الخاصة به.

- **خدمة أو عامل:** مرّر معرّف الطلب أو الوظيفة الخاص بك كـ `sessionId`، لذا جلسة على لوحة المعلومات والسجل في السجلات الخاصة بك أو قاعدة البيانات هي نفس السلسلة.
- **وكلاء فرعيون:** عش استدعاءات `agent()`. الداخلي ينضم إلى الجلسة مع الخارجي كـ `parent_id`.
- **أصدر الأزواج.** `modelRequest` بدون `modelResponse` هو رقعة تظهر لوحة المعلومات كتشغيل للأبد — لذا الـ `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) في المستودع هي النسخة الكاملة القابلة للتشغيل: حلقة أداة OpenAI حقيقية مُدرجة تماماً مثل هذا، يعمل في CI على كل تغيير كمودول ES وكـ CommonJS.

## التقييمات

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

## ما لن تفعله لعمليتك

| | |
| --- | --- |
| **حجب حلقة الوكيل الخاص بك** | تذهب الأحداث إلى قائمة في الذاكرة؛ يكتب المؤقت. المؤقت `unref`'d، لذا استيراد هذه الحزمة لا يوقف البرنامج النصي من الخروج. |
| **النمو بلا حدود** | تُحدّد القائمة بالعدد *و* بالبايتات المقاسة. بعد أي منهما، يتم تجاهل أقدم الأحداث وتحذير يقول ذلك — يجب أن لا يصبح انقطاع الاتصالات عملية OOM. |
| **أخذ العملية لأسفل** | حدث غير قابل للترميز واحد يُسقط وحده، وليس الحزمة حوله. رافع رمي، مرجع دائري، `BigInt`، بديل وحيد: كل واحد يُعامل بدلاً من النشر. |
| **ترك دفعة مكتوبة جزئياً** | يتم `fsync` المحتوى قبل إعادة تسمية ذرية، يتم `fsync` الدليل بعد، والكتابة الفاشلة تنظف ملف مؤقت. |
| **ترك نصوص قابلة للقراءة** | دفعات هي `0600` داخل دليل `0700`. تحمل أهداف وأسئلة وحجج الأداة ومخرجات الأداة. |
| **سفينة بيانات الاعتماد** | مفاتيح API والرموز و JWTs ورؤوس Bearer والتعيينات ذات الشكل السري تُحظر قبل وصول البايتات إلى القرص. الخادم يحظر مرة أخرى قبل الرفع. |
