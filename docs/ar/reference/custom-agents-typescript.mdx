Node 20.9 أو أحدث. ESM و CommonJS. بدون تبعيات وقت التشغيل.

<Note>
  يكتب SDK هذا والآخر من Python **نفس الأحداث في نفس ملف الانتظار**. الأسطول الذي يحتوي على وكلاء Node و وكلاء Python ينتج مجموعة واحدة من الجلسات وليس اثنتين، ولا شيء في لوحة المعلومات يميز بينهما. اختر لكل خدمة وليس لكل شركة.
</Note>

## التثبيت

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

توأتي موائم الإطار العمل في الحزمة نفسها. الأطر العمل **اختيارية من تبعيات النظير** — معلنة لتكون النطاقات المدعومة مرئية، لا يتم تثبيتها نيابة عنك، ويتم استيرادها فقط عند استدعاء `instrument()`.

## اتصل بخادم Failproof

متطابق مع SDK من Python: أنشئ مفتاح `events:add` تحت **Admin → Keys**، ثم [اتصل بالخادم](/ar/start/setup#connect-a-machine-to-cloud) على جهاز الوكيل. يكتب SDK إلى القرص؛ الخادم يقدم.

## الإعدادات

### رقاع OpenTelemetry (اختياري)

ثبّت OpenTelemetry بشكل منفصل مع `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
ثم أضف FailproofAI إلى معالجات مزود الخدمة:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

للمزود الموجود، احتفظ بمعالجاته الأخرى في نفس القائمة. يمكن للمزودين الذين يكشفون `addSpanProcessor` أن يتم تمريرهم بدلاً من ذلك كـ `{ provider }`. بدون خيارات، يسجل الإعداد مزود جديد فقط إذا لم يكن هناك مزود مسجل بالفعل.
يمكن أيضًا استخدام `OtelSpanExporter` مباشرة مع معالجك الخاص.

تمر الصادرات عبر خادم FailproofAI المتصل؛ لا يرسل SDK طلبات الشبكة ولا يحتاج إلى مفتاح أو مستمع محلي. اطلب من الإداري تفعيل [استيعاب OpenTelemetry](/ar/agenteye/opentelemetry). `instrument()` العادي لا يفعل هذا المُصدِّر. `uninstrument("otel")` يعطل معالج نفسه فقط.
تتحكم سمات الرقع الخاصة بك في التقاط المحتوى؛ قم بتدفق مزودك قبل الخروج.
يبقى OpenTelemetry تبعية تطبيق اختيارية وليس تبعية SDK قاسية.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| الخيار | ما الذي يفعله |
| --- | --- |
| `environment` | التسمية على كل حدث — `production` و `staging` و `prod-eu`. الإعدادات الافتراضية إلى `dev`. |
| `flushInterval` | عدد مرات كتابة المؤقت إلى القرص بالثواني. الإعدادات الافتراضية إلى `0.5`. |
| `baseDir` | حيث يتم الكتابة. الإعدادات الافتراضية إلى ملف انتظار الخادم، وهو ما تريده إلا إذا كنت تعرف خلاف ذلك. |

لا يتم تطبيق شيء ما لم يتم التحقق من صحة كل شيء، لذا فإن استدعاء مرفوض يترك SDK بالضبط كما كان بدلاً من أن يكون لديك `baseDir` جديد والفاصل الزمني القديم.

اضبط بواسطة متغير البيئة بدلاً من ذلك:

| المتغير | ما الذي يفعله |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | يعيّن `environment` بدون تغيير الكود. يفوز خيار `configure()` عليه. |
| `FAILPROOFAI_HOME` | نقل جذر Failproof AI الذي يحمل ملف الانتظار. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug` و `info` و `warn` (الافتراضي) و `error` و `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` يجعل أخطاء التجهيز ترمي بدلاً من أن تكون مسجلة. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` يجعل مشكلة توافق الإطار تلقي بدلاً من التحذير والمتابعة. |

<Warning>
  **بدون فواصل في `environment`.** يقسم الاستيعاب هذا الحقل على الفواصل لبناء مرشحاته ويتخطى أي حدث يحتوي تسميته على واحدة — لذا يختفي التشغيل كله بصمت. اكتب `prod-eu` وليس `prod,eu`.

  `configure({ environment: "prod,eu" })` يرمي حتى تكتشفها على الفور. `AGENTEYE_ENVIRONMENT` لا يمكن أن يرمي — لا أحد يتصل بك — لذا يحذر مرة واحدة ويعود إلى `dev`.
</Warning>

أوجّه أسطر سجل SDK الخاصة به إلى المسجل الخاص بك مع `failproofai.setLogger({ debug, info, warn, error })`.

## الإيقاف

يتم تدفق الأحداث المخزنة مؤقتًا على `process.on("exit")`.

العملية المقتولة بواسطة إشارة لا تصل أبدًا إلى تلك النقطة، والقيمة الافتراضية لـ Node لـ `SIGTERM` هي إنهاء بدون تشغيل معالجات الخروج — لذا يفقد الوكيل الموجود في حاوية كل ما لم تكتبه الفترة الأخيرة.

<Warning>
  **لن يقوم SDK هذا بتثبيت معالج إشارة لك.** يؤدي تسجيل واحد إلى تغيير سلوك العملية: يؤدي المستمع إلى قمع الإنهاء الافتراضي للعقدة، بحيث ستتوقف مكتبة أضافت واحدة بصمت عن العمل من Ctrl-C. أضف الخاص بك:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

يجب على البرنامج النصي قصير العمر أو معالج بدون خادم `await failproofai.flush()` قبل الإرجاع — لا تضمن الفترة وحدها التسليم.

## الهوية

ينتمي كل حدث إلى جلسة ووكيل. **تملأ النطاقات كليهما**، لذا نادراً ما تمررهما:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

تمرير `sessionId` أو `agentId` بوضوح لا يزال يعمل ويفوز. بدون ربط أو تمرير، يرمي الاستدعاء بدلاً من إرسال حدث قد يتجاهله Cloud بصمت.

<Note>
  تركب الهوية على `AsyncLocalStorage`. يتابع `await` و `.then()` والمؤقتات وأي رد نداء تم إنشاؤه داخل النطاق. **لا** يتابع رد نداء تم تخزينه أثناء تشغيل واحد واستدعاؤه أثناء آخر، أو العمل الذي تم نقله عبر حدود `worker_threads` — التفاف تلك في `failproofai.propagate()` أو أحداثها تهبط غير مرفقة.
</Note>

### النطاقات

| النطاق | ينبعث | يعيد |
| --- | --- | --- |
| `session(body)` | لا شيء — الهوية فقط | أيا كان `body` يعيد |
| `agent(id, options?, body)` | `agent_start`، ثم `agent_end` | أيا كان `body` يعيد |
| `toolCall(name, options?, body)` | `tool_use`، ثم `tool_result` | أيا كان `body` يعيد |

الجسم المتزامن يبقى متزامنًا: `agent("x", () => 1)` يعيد `1` وليس وعد.

`toolCall` يسجل القيمة المحلولة للجسم كمخرجات الأداة `output`، إلا إذا قمت بتعيين `call.output` بنفسك.

<Accordion title="دلالات الخروج" icon="arrow-right-from-bracket">

| ما حدث | الأحداث | `outcome` |
| --- | --- | --- |
| الكتلة عادت | `agent_end` | `"success"`، أو الخاص بك `outcome` |
| الكتلة رمت | `error`، ثم `agent_end` | `"failed"` |
| `AbortError` | `agent_end` فقط | `"cancelled"` |

يتم إعادة طرح الخطأ دائمًا.

يتم تسجيل فشل الأداة على الورقة — `tool_result` مع سلسلة `error` — ولا ينبعث حدث `error` على مستوى التشغيل. واحد يمسكه حلقة الوكيل ليس فشل تشغيل، وواحد ينتشر يتم الإبلاغ عنه بالضبط مرة واحدة، بواسطة `agent()` المرفقة.

</Accordion>

<Accordion title="نموذج `using`" icon="brackets-curly">

عندما لا يكون العمل دالة واحدة — نطاق مفتوح في مُنشئ وأغلق في هدم، أو واحد يتجاوز تدفق التحكم الموجود:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result، ثم agent_end
```

يصدر كلا الشكلين أحداثًا متطابقة البايت. فضّل نموذج رد النداء: يعمل داخل `AsyncLocalStorage.run()`، لذا لا يوجد شيء يتم فكه والفئة بأكملها من أخطاء `opened here, closed over there` غير قابلة للوصول.

تقرير كتلة `using` التي تمسك بفشلها الخاص به مع `span.fail(error)` — الموزع ليس لديه قناة استثناء خاصة به.

</Accordion>

## كتالوج الأحداث

نفس خمسة عشر طريقة كـ SDK من Python، في camelCase. معظمها يأتي في **أزواج** — تستدعي المفتاح، ثم الإغلاق، و SDK يحدد الفجوة.

| | المفتوح | الإغلاق |
| --- | --- | --- |
| **الوكلاء** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **النماذج** | `modelRequest` | `modelResponse` |
| **الأدوات** | `toolUse` | `toolResult` |
| **الخطافات** | `hookTriggered` | `hookCompleted` |
| **البشر** | `humanWait` | `humanInput` |

ثلاثة يقفون وحدهم: `error` و `humanPause` و `humanInterrupt`.

<Accordion title="كل حقل، لكل طريقة" icon="table">

تأخذ كل طريقة أيضًا `sessionId` و `agentId`، والتي تملأها النطاقات لك. يتم حذف أي شيء لم يتم حذفه بدلاً من إرساله كـ JSON `null`.

| الطريقة | مطلوب | اختياري |
| --- | --- | --- |
| `agentStart` | — | `goal` و `parentId` |
| `agentEnd` | — | `outcome` و `summary` |
| `agentPause` | `pauseId` | `reason` و `userId` |
| `agentResume` | `pauseId` | `reason` و `userId` |
| `modelRequest` | — | `model` و `messages` و `system` و `tools` و `requestId` |
| `modelResponse` | — | `model` و `stopReason` و `inputTokens` و `outputTokens` و `content` و `role` و `requestId` |
| `toolUse` | `toolName` و `toolCallId` | `input` |
| `toolResult` | `toolName` و `toolCallId` | `output` و `error` |
| `hookTriggered` | `hookName` و `hookId` | `triggerEvent` و `input` |
| `hookCompleted` | `hookName` و `hookId` | `outcome` و `output` و `error` |
| `error` | `errorType` و `message` | `traceback` |
| `humanWait` | `inputId` | `prompt` و `options` و `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason` و `userId` |
| `humanInterrupt` | — | `reason` و `userId` و `atStep` |

أي مفتاح آخر تضيفه يصبح حقل حمولة مخصص. مساحة أي شيء خاص بالإطار العمل `fw_*`؛ الاسم الذي يتعارض مع الحقل المعلن يتم رفضه بدلاً من الكتابة الصامتة فوق العمود المرقى.

</Accordion>

<Warning>
  **`duration_ms` محسوب وليس مقبول.** تحدد الطرق الأربع الإغلاق الفجوة من مفتاحها وترفض `duration_ms` المُرسل من المتصل — المدة المُبلغ عنها لا يمكن دحضها.

  يتم مطابقة الأزواج على **الجلسة** والمعرف، ولا يتم مطابقتها على الوكيل. الأداة المفتوحة تحت `planner` والمغلقة تحت `worker` لا تزال تقترن، وهو ما تفعله الأنظمة متعددة الوكلاء المتداخلة في الواقع.
</Warning>

## موائم الإطار العمل

```ts
await failproofai.instrument();              // مهما استطاعت أن تجد
await failproofai.instrument("langchain");   // بالضبط واحد
failproofai.uninstrument();                  // ضع كل شيء للخلف
```

| الإطار العمل | مدعوم | كيفية الارتباط |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x و LangGraph.js 0.4 – 1.x | `CallbackManager.configure`، حتى يتم تغطية كل `invoke`/`stream`/`batch` بدون تمرير `callbacks:` في أي مكان — أو قم بتمرير `langchainHandler()` بنفسك وعدم التصحيح. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` في موقع الاستدعاء، أو `instrument("ai")` للعملية برمتها على `ai` 7 (على 4–6 يكون ذلك اختياريًا — انظر أدناه). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream` وحل نموذج الوكيل والأداة وتشغيل سير العمل/محرك الخطوة. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (مشترك) بالإضافة إلى `AgentWorkflow.runStream` لتشغيل سير العمل وخطواتهم. |

يتم اختبار كل نطاق ضد إصدارات إطار العمل الحقيقية في كلا الطرفين كوحدة ES وكـ CommonJS على كل تشغيل CI.

المحاذاة هي SDK من Python، لذا يرسم البرنامج نفسه نفس الشجرة بأي لغة. يعتبر البناء **وكيلًا** فقط إذا كان يمتلك حلقة قرار LLM — تشغيل رسم بياني أو سلسلة أو استدعاء `generateText`/`streamText` من AI SDK أو وكيل Mastra أو تشغيل وكيل LlamaIndex. عقدة LangGraph أو خطوة سير العمل **خطاف** (`hook_triggered`/`hook_completed`)، وليس أبدًا وكيل متداخل. استدعاءات النموذج هي أزواج `model_request`/`model_response` مع عدد الرموز؛ تحمل استدعاءات الأداة معرف استدعاء الأداة الخاص بالنموذج. يتم تسجيل الفشل مرة واحدة على الحدث الذي حدث فيه.

موائر تفشل في التثبيت تسجل وتخطي؛ الآخرون لا يزالون يثبتون لأن LlamaIndex المكسور لا يجب أن يكلفك LangGraph.

<Note>
  `instrument()` بدون وسيطة يكتشف إطار عمل من خلال ما إذا كان **يحل**، وليس من خلال ما إذا كان مستوردًا بالفعل — لا تكشف Node عن ما يعادل Python `sys.modules` لوحدات ES. إطار عمل قمت بتثبيته لكن لا تستخدمه سيتم استيراده وإصلاحه. سمّ الواحد الذي تريده إذا كان هذا يهمك.
</Note>

<Note>
  معظم هذه الأطر العمل تشحن بناء وحدة ES وبناء CommonJS، والذي يحمل Node كنسختين غير مرتبطتين. تصحح الموائر النسخة التي يحملها التطبيق الخاص بك (والنسخة CommonJS أيضًا إذا كان شيء ما قد استدعى بالفعل `require`)، لذا تعمل كلا أنظمة الوحدة. إطار عمل **مجمّع في مخرجاتك الخاصة** بواسطة esbuild أو webpack خارج الوصول — استخدم مساعدات موقع الاستدعاء هناك: `langchainHandler()` و `telemetry()` و `wrapTool()`.
</Note>

### LangChain بدون إصلاح

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

يعمل المعالج مع أو بدون `instrument()` وأبدًا لا يسجل مرتين. `instrument("langchain")` يأخذ `sessionId` و `captureContent` و `includeChains` و `graphCallbacks` و `captureLimit` كموائر Python تفعل؛ `metadata: { failproofai_sdk_session_id }` على استدعاء يختار الجلسة لهذا الاستدعاء.

### Vercel AI SDK

يُصدّر AI SDK وظائف عادية من وحدة ES، وفضاء اسم وحدة ES غير قابل للتغيير بموجب المواصفات — لا يوجد مكان للإصلاح. يستخدم نقاط الامتداد التي توثقها SDK نفسها:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // على ai 7، `telemetry: telemetry({ … })` — نفس الكائن والاسم الجديد
});
```

هذا هو التكامل الكامل: امتداد وكيل وزوج طلب/استجابة نموذج لكل خطوة مع عدد الرموز وكل استدعاء أداة. موقع استدعاء واحد يعمل على كل رئيسي — `ai` 4–6 قراءة المتتبع الذي يحمله `ai` 7 تكامل القياس.

`instrument("ai")` يفعل نفس الشيء على مستوى العملية **على `ai` 7**: كل استدعاء عبر قائمة تكامل قياس AI SDK العالمية التي تكون إضافية ولا تأخذ شيئًا من قائمة أي شخص آخر.

**على `ai` 4–6، `instrument("ai")` لا يسجل شيئًا بنفسه وسجلات تحذير واحد بقول ذلك.** الخطاف على مستوى العملية الوحيد الذي لدى تلك الرؤساء هو مزود تتبع OpenTelemetry العالمي — فتحة واحدة ترفض OpenTelemetry أن تسلمها مرة واحدة تُؤخذ. سيؤدي تسجيل لنا إلى رفض `NodeSDK.start()` الخاص بك بصمت لاحقًا عند بدء التشغيل وإرسال رقاق http/database الخاصة بك إلى متتبع لا يُصدِّر شيئًا. استخدم `telemetry()` في موقع الاستدعاء أو `wrapModel` هناك. إذا لم تقم العملية بأي OpenTelemetry من تلقاء نفسها، اختر مع `instrument("ai", { registerGlobalTracer: true })`: يسجل كل استدعاء يمرر `experimental_telemetry: { isEnabled: true }`، وتأخذ الفتحة فقط إذا كانت لا تزال فارغة. `registerGlobalTracer: false` يحافظ على الافتراضي ويسكت التحذير.

إذا فضّلت التفاف النموذج مرة واحدة، `wrapModel` يرى استدعاءات النموذج فقط، لأن استدعاءات الأداة تحدث فوق طبقة النموذج. نموذج مغلف يُستدعى بلا شيء حوله يُسجل كتشغيل خاص به. استدعاء مُجرى يُغلق مهما توقف التدفق — `stop_reason: "cancelled"` عندما يلغي المستهلك `"error"` مع الخطأ عندما يفشل في منتصف الطريق:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

استخدام كليهما على ما يرام: يلاحظ البرنامج الوسيط أن الاستدعاء يتم تسجيله بالفعل ويؤجل، لذا يتم تسجيل كل استدعاء مرة واحدة.

`functionId` أسماء امتداد الوكيل. احتفظ بقلة عالية — هبوط في `agent_id` وجهة لوحة المعلومات الأساسية.

### Next.js

`next build` يجمع تبعيات الخادم بشكل افتراضي وإطار عمل مجمّع في الإنشاء نسخة `instrument()` لا يمكنها الوصول إليها. التفاف الإعدادات مرة واحدة واستدعاء `instrument()` من خطاف بدء التشغيل:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` يضيف LangChain و Mastra و LlamaIndex و SDK نفسه إلى `serverExternalPackages` الاحتفاظ بقائمتك. بدونها، `instrument()` يحذر مرة واحدة لكل إطار عمل لا يمكنه الوصول إليه بدلاً من الفشل بصمت؛ إذا أدرجت الحزم بنفسك، اضبط `FAILPROOFAI_NEXT_EXTERNALS=1`. يعمل Vercel AI SDK ومساعدات موقع الاستدعاء بأي طريقة. الطريق الحدي يحصل على بناء عدم تشغيل: استيراد SDK آمن وتسجيل لا شيء.

### عدد الرموز على استدعاءات مُجرّاة

تقارير API المتوافقة مع OpenAI فقط عن الاستخدام في دفق عندما يطلب العميل. LangChain و Vercel AI SDK اطلبت؛ لـ LlamaIndex تمرير `additionalChatOptions: { stream_options: { include_usage: true } }` إلى OpenAI LLM الخاص به وللماسترا بناء النموذج مع تفعيل الاستخدام (على سبيل المثال `createOpenAICompatible({ includeUsage: true })`). وإلا استدعاءات النموذج المُجرّاة تحمل عدد رموز.

### وقت التشغيل

Node ≥ 20.9 و Bun و Deno — كل إطار عمل كوحدة ES و CommonJS يتم اختباره على كل ضد تتبع Node. يعمل SDK بجانب خادم `failproofaid`، الذي يشحن ما يكتبه.

## وكيلك الخاص — بدون إطار عمل

لحلقة وكيل كتبتها بنفسك أو إطار عمل بدون موائر. تُصدِر الأحداث مع نفس API الموائر تستخدم تحتها، لذا يكون التتبع بنفس الشكل والجودة.

لا تحتاج إلى معرفة كيفية تنظيم الوكيل. لديك كل وكيل محلي الصنع بالفعل ثلاثة أماكن مهما تم استدعاء وظائفه وتلك الثلاثة هي التكامل الكامل:

| أين | ما الذي يتعين إضافته | ينبعث |
| --- | --- | --- |
| حيث **تشغيل واحد** يبدأ وينتهي | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **الدالة الوحيدة التي تستدعي النموذج** | `event.modelRequest` قبل و `event.modelResponse` بعد — كلا النصفين حتى في حالة الفشل | زوج واحد لكل منعطف نموذج |
| **الدالة الوحيدة التي تشغل الأدوات** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

الهوية محيطة: كل شيء داخل `agent()` يهبط على جلسة التشغيل بدون أخذ معرف ولا شيء آخر في البرنامج يتغير — بما في ذلك أيا كان الوكيل بالفعل يكتب إلى قاعدة البيانات الخاصة به.

- **خدمة أو عامل:** مرر معرف الطلب أو الوظيفة الخاصة بك كـ `sessionId` حتى تكون جلسة لوحة المعلومات والسجل في السجلات أو قاعدة البيانات الخاصة بك نفس السلسلة.
- **وكلاء فرعيين:** عش `agent()` يدعو. الداخلي ينضم إلى الجلسة مع الخارجي كـ `parent_id`.
- **أصدر الأزواج.** `modelRequest` بدون `modelResponse` امتداد يوضح لوحة المعلومات كتشغيل للأبد — ومن هنا `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) في المستودع هي النسخة الكاملة والقابلة للتشغيل: حلقة أداة OpenAI حقيقي موضح بالضبط مثل هذا التشغيل في CI عند كل تغيير كوحدة ES و CommonJS.

## التقييمات

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \

```

## ما لن تفعله بعمليتك

| | |
| --- | --- |
| **حجب حلقة الوكيل** | تذهب الأحداث إلى قائمة الانتظار في الذاكرة؛ مؤقت يكتبها. المؤقت هو `unref`'d، لذا استيراد هذه الحزمة أبدًا لا توقف البرنامج النصي من الخروج. |
| **النمو بدون حد** | تقتصر قائمة الانتظار على عدد *و* على بايتات مقيسة. بعد إما المزيد من الأحداث القديمة يتم تجاهلها وتحذير يقول ذلك — يجب ألا تصبح انقطاع قياس المسافات البعيدة جنون OOM. |
| **أخذ العملية لأسفل** | حدث واحد لا يمكن ترميزه يتم إسقاطه وحده وليس الدفعة حوله. المحصول رمي أو مرجع دائري أو `BigInt` أو بديل وحيد: كل يتم التعامل معه بدلاً من أن ينتشر. |
| **اترك دفعة نصف مكتوبة** | المحتوى هو `fsync`ed قبل إعادة تسمية ذرية والمجلد هو `fsync`ed بعد وفشل الكتابة ينظف ملفه المؤقت. |
| **اترك النصوص قابلة للقراءة** | الدفعات هي `0600` داخل مجلد `0700`. تحمل الأهداف والمحفوزات وحجج الأداة ومخرجات الأداة. |
| **شحن بيانات الاعتماد** | مفاتيح API والرموز و JWTs وورؤوس المولد والتعيينات على شكل سري يتم تعديلها قبل البايتات التي تصل إلى القرص. يعدل الخادم مرة أخرى قبل التحميل. |
