Node 20.9 أو أحدث. ESM و CommonJS. لا توجد متطلبات وقت التشغيل.

<Note>
  يكتب هذا SDK والإصدار الخاص بـ Python **نفس الأحداث في نفس الملف المؤقت**. أسطول يحتوي على وكلاء Node و Python ينتج مجموعة واحدة من الجلسات وليس اثنتين، ولا يميز لوحة المعلومات بينهما. اختر لكل خدمة وليس لكل شركة.
</Note>

## التثبيت

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

موائم الإطار العمل تأتي في الحزمة نفسها. الإطارات العمل **اعتماديات نظير اختيارية** — معلن عنها حتى تكون النطاقات المدعومة مرئية، لا يتم تثبيتها نيابة عنك، ويتم استيرادها فقط عند استدعاء `instrument()`.

## توصيل خادم Failproof

متطابق مع SDK الخاص بـ Python: أنشئ مفتاح `events:add` ضمن **Admin → Keys**، ثم [وصل الخادم](/ar/start/setup#connect-a-machine-to-cloud) على آلة الوكيل. يكتب SDK إلى القرص؛ يرسل الخادم.

## التكوين

### امتدادات OpenTelemetry (اختياري)

ثبّت OpenTelemetry بشكل منفصل باستخدام `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
ثم أضف FailproofAI إلى معالجات موفر الخدمة:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

لموفر موجود، احتفظ بمعالجاته الأخرى في نفس القائمة. الموفرون الذين يعرضون `addSpanProcessor` يمكن بدلاً من ذلك تمريرهم كـ `{ provider }`. بدون خيارات، يسجل الإعداد موفر جديد فقط إذا لم يكن هناك موفر مسجل بالفعل.
يمكن أيضًا استخدام `OtelSpanExporter` مباشرة مع معالجك الخاص.

تذهب التصديرات عبر خادم FailproofAI المتصل؛ لا يرسل SDK طلبات شبكة ولا يحتاج إلى مفتاح أو مستمع محلي. اطلب من مسؤول تفعيل
[استقبال OpenTelemetry](/ar/agenteye/opentelemetry). `instrument()` بسيط لا يفعّل هذا المُصدّر. `uninstrument("otel")` يعطّل معالجه فقط.
تحكم سمات span الخاصة بك في التقاط المحتوى؛ أفرغ موفرك قبل الخروج.
يبقى OpenTelemetry اعتمادية تطبيق اختيارية وليس اعتمادية SDK ثابتة.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| الخيار | ما يفعله |
| --- | --- |
| `environment` | الملصق على كل حدث — `production`, `staging`, `prod-eu`. الافتراضي هو `dev`. |
| `flushInterval` | كم مرة يكتب المؤقت إلى القرص بالثواني. الافتراضي هو `0.5`. |
| `baseDir` | حيث يتم الكتابة. الافتراضي هو ملف الخادم المؤقت وهو ما تريده ما لم تعرف خلاف ذلك. |

لا يتم تطبيق أي شيء إلا إذا تم التحقق من صحة كل شيء، لذا فإن استدعاء مرفوض يترك SDK تمامًا كما هو بدلاً من وجود `baseDir` جديد والفترة القديمة.

اضبطها حسب متغير البيئة بدلاً من ذلك:

| المتغير | ما يفعله |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | يعيّن `environment` بدون تغيير الكود. يفوز خيار `configure()` عليه. |
| `FAILPROOFAI_HOME` | ينقل جذر Failproof AI الذي يحتوي على الملف المؤقت. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (الافتراضي), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` يجعل أخطاء الأداة تطرح بدلاً من تسجيلها. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` يجعل مشكلة التوافق مع الإطار العمل تطرح بدلاً من التحذير والمتابعة. |

<Warning>
  **لا توجد فواصل في `environment`.** يقسم الاستقبال هذا الحقل على الفواصل لبناء مرشحاته، ويخطي أي حدث يحتوي تصنيفه على واحد — لذا يختفي تشغيل كامل بدون صوت. اكتب `prod-eu` وليس `prod,eu`.

  `configure({ environment: "prod,eu" })` يطرح حتى تكتشف فورًا. لا يمكن أن يطرح `AGENTEYE_ENVIRONMENT` — لا أحد ينادي عليك — لذا يحذر مرة واحدة ويعود إلى `dev`.
</Warning>

وجّه أسطر السجل الخاصة بـ SDK إلى المسجل الخاص بك مع `failproofai.setLogger({ debug, info, warn, error })`.

## الإغلاق

يتم تفريغ الأحداث المخزنة مؤقتًا عند `process.on("exit")`.

لا تصل عملية يقتلها إشارة أبدًا إلى ذلك، والافتراضي في Node لـ `SIGTERM` هو الإنهاء بدون تشغيل معالجات الخروج — لذا يفقد وكيل محتوي في حاوية ما كانت الفترة الأخيرة لم تكتبه.

<Warning>
  **لن يثبت هذا SDK معالج إشارة لك.** يغيّر تسجيل واحد سلوك العملية: يقضي المستمع على الافتراضي في Node، لذا ستتوقف مكتبة أضافتها بصمت عن عمل Ctrl-C. أضف الخاص بك:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

يجب على نص قصير العمر أو معالج بدون خادم أن ينفذ `await failproofai.flush()` قبل الإرجاع — الفترة وحدها لا تضمن التسليم.

## الهوية

كل حدث ينتمي إلى جلسة ووكيل. **النطاقات تملأ كليهما**، لذا نادرًا ما تمرره:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

تمرير `sessionId` أو `agentId` صراحة لا يزال يعمل ويفوز. بدون ربط أو تمرير، يطرح الاستدعاء بدلاً من بث حدث قد تتجاهله Cloud بصمت.

<Note>
  تركب الهوية على `AsyncLocalStorage`. تتبع `await`, `.then()`, المؤقتات وأي دالة استدعاء تم إنشاؤها داخل النطاق. لا تتبع دالة استدعاء تم تخزينها أثناء تشغيل واحد واستدعاؤها أثناء تشغيل آخر، ولا تعمل مع العمل الذي تم تمريره عبر حدود `worker_threads` — التفف حول تلك مع `failproofai.propagate()` أو تهبط الأحداث غير مرفقة.
</Note>

### النطاقات

| النطاق | يبث | يرجع |
| --- | --- | --- |
| `session(body)` | لا شيء — الهوية فقط | مهما أرجعت `body` |
| `agent(id, options?, body)` | `agent_start`, ثم `agent_end` | مهما أرجعت `body` |
| `toolCall(name, options?, body)` | `tool_use`, ثم `tool_result` | مهما أرجعت `body` |

يبقى الجسم المتزامن متزامنًا: `agent("x", () => 1)` يرجع `1` وليس وعد.

يسجل `toolCall` القيمة المحلولة للجسم كـ `output` الأداة ما لم تعيّن `call.output` بنفسك.

<Accordion title="دلالات الخروج" icon="arrow-right-from-bracket">

| ما حدث | الأحداث | `outcome` |
| --- | --- | --- |
| أرجع الكتلة | `agent_end` | `"success"` أو `outcome` الخاص بك |
| طرحت الكتلة | `error` ثم `agent_end` | `"failed"` |
| `AbortError` | `agent_end` فقط | `"cancelled"` |

يتم إعادة طرح الخطأ دائمًا.

يتم تسجيل فشل الأداة على الورقة — `tool_result` بسلسلة `error` — ولا يبث أي حدث `error` على مستوى التشغيل. واحد يمسكه حلقة الوكيل ليس فشل تشغيل، وواحد ينتشر يتم الإبلاغ عنه مرة واحدة بالضبط بواسطة الإغلاق `agent()`.

</Accordion>

<Accordion title="صيغة `using`" icon="brackets-curly">

عندما لا تكون العمل دالة واحدة — نطاق تم فتحه في منشئ وإغلاقه في هدم، أو واحد يمتد على التحكم في التدفق الموجود:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result، ثم agent_end
```

كلا الشكليين يبث أحداثًا متطابقة البايت. فضّل صيغة الاستدعاء: تعمل داخل `AsyncLocalStorage.run()`، لذا لا يوجد شيء للالتفاف حول هذا والفئة كاملة من أخطاء "فُتح هنا وأُغلق هناك" غير قابلة للوصول.

تقرير كتلة `using` التي تمسك فشلها الخاص مع `span.fail(error)` — لا يوجد قناة استثناء خاصة بالموزع.

</Accordion>

## كتالوج الأحداث

نفس الطرق الخمسة عشرة كـ SDK الخاص بـ Python بصيغة camelCase. معظمها يأتي بصيغة **أزواج** — تستدعي الفاتح، ثم الإغلاق، ويوقت SDK الفجوة.

| | يفتح | يغلق |
| --- | --- | --- |
| **الوكلاء** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **النماذج** | `modelRequest` | `modelResponse` |
| **الأدوات** | `toolUse` | `toolResult` |
| **الخطافات** | `hookTriggered` | `hookCompleted` |
| **البشر** | `humanWait` | `humanInput` |

ثلاثة تقف وحدها: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="كل حقل لكل طريقة" icon="table">

تأخذ كل طريقة أيضًا `sessionId` و `agentId`، التي تملأها النطاقات لك. يتم حذف أي شيء محذوف بدلاً من إرساله كـ JSON `null`.

| الطريقة | مطلوب | اختياري |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

أي مفتاح آخر تضيفه يصبح حقل حمولة مخصص. اجعل مساحة أي شيء خاص بالإطار العمل `fw_*`؛ الاسم الذي يتعارض مع حقل معلن يتم رفضه بدلاً من الكتابة فوق عمود مرفوع صامتًا.

</Accordion>

<Warning>
  **`duration_ms` محسوب وليس مقبول.** الطرق الأربع الإغلاق توقت الفجوة من الفاتح ترفض `duration_ms` المُزودة من المستدعي — مدة مبلغ عنها لا يمكن تزييفها.

  تطابق الأزواج على **الجلسة** والمعرف، أبدًا على الوكيل. أداة فُتحت تحت `planner` وأُغلقت تحت `worker` لا تزال تطابق، وهو ما تفعله التشغيلات متعددة الوكلاء المتداخلة بالفعل.
</Warning>

## موائم الإطار العمل

```ts
await failproofai.instrument();              // مهما تستطيع العثور عليه
await failproofai.instrument("langchain");   // بالضبط واحد
failproofai.uninstrument();                  // أعد كل شيء للخلف
```

| الإطار العمل | المدعوم | كيف يعلق |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`، لذا كل `invoke`/`stream`/`batch` مغطى بدون تمرير `callbacks:` في أي مكان — أو مرّر `langchainHandler()` بنفسك ولا تصحح أي شيء. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` في موقع الاستدعاء أو `instrument("ai")` للعملية كاملة على `ai` 7 (على 4–6 هذا اختياري — انظر أدناه). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`، النموذج الخاص بالوكيل وحل الأداة ومحرك تشغيل/خطوة سير العمل. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (مشترك) بالإضافة إلى `AgentWorkflow.runStream`، لتشغيلات سير العمل والخطوات. |

يتم اختبار كل نطاق ضد إصدارات الإطار العمل الحقيقية في كلا الطرفين كوحدة ES وكـ CommonJS على كل تشغيل CI.

التعيين هو الخاص بـ SDK الخاص بـ Python، لذا يرسم البرنامج نفسه نفس الشجرة بأي لغة. يكون البناء **وكيلاً** فقط إذا كان يمتلك حلقة قرار LLM — تشغيل الرسم البياني أو السلسلة أو استدعاء AI SDK `generateText`/`streamText` أو وكيل Mastra أو تشغيل وكيل LlamaIndex. عقدة LangGraph أو خطوة سير العمل هي **خطاف** (`hook_triggered`/`hook_completed`)، أبدًا وكيل متداخل. استدعاءات النموذج هي أزواج `model_request`/`model_response` بعدد الرموز؛ تحمل استدعاءات الأداة معرف استدعاء الأداة الخاص بالنموذج. يتم تسجيل الفشل مرة واحدة فقط على الحدث الذي حدث فيه.

يتم تسجيل مصفوفة تفشل في التثبيت وتخطيها؛ تثبيت البقية، لأن LlamaIndex المكسورة يجب ألا تكلفك LangGraph.

<Note>
  `instrument()` بدون وسيط يكتشف إطار عمل بما إذا **حل** وليس بما إذا تم استيراده بالفعل — Node لا يعرض ما يعادله لـ Python `sys.modules` لوحدات ES. إطار عمل لديك مثبت ولا تستخدمه سيتم استيراده وتصحيحه. سمّ الذي تريده إذا كان هذا مهمًا.
</Note>

<Note>
  يشحن معظم هذه الإطارات العمل بناء وحدة ES وبناء CommonJS وتحمل Node كنسختين غير مرتبطتين. تصحح المصفوفات النسخة التي يحملها التطبيق الخاص بك (وأيضًا النسخة CommonJS إذا كان شيء ما قد `require`ها بالفعل)، لذا تعمل كلا الأنظمة النمطية. إطار عمل **محزوم في الإخراج الخاص بك** بواسطة esbuild أو webpack خارج الوصول — استخدم مساعدات موقع الاستدعاء هناك: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain بدون تصحيح

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

يعمل المعالج مع أو بدون `instrument()` وأبدًا لا يسجل مرتين. `instrument("langchain")` يأخذ `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` و `captureLimit`، كما يفعل موائم Python؛ `metadata: { failproofai_sdk_session_id }` على الاستدعاء يختار الجلسة لذلك الاستدعاء.

### Vercel AI SDK

يُصدّر AI SDK دوال عادية من وحدة ES وفضاء أسماء وحدة ES غير قابل للتغيير حسب المواصفات — لا مكان للتصحيح. يستخدم نقاط الامتداد التي توثقها SDK نفسها:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // على ai 7, `telemetry: telemetry({ … })` — نفس الكائن والاسم الجديد
});
```

هذه هي التكامل كاملاً: امتداد وكيل وزوج طلب/استجابة نموذج لكل خطوة بعدد الرموز وكل استدعاء أداة. موقع استدعاء واحد يعمل على كل رقم رئيسي — يقرأ `ai` 4–6 الاقتفاء الذي يحمله، `ai` 7 تكامل التلمترة.

`instrument("ai")` يفعل نفس الشيء على مستوى العملية **على `ai` 7**: كل استدعاء عبر قائمة تكامل التلمترة العامة لـ AI SDK وهي إضافية وتأخذ لا شيء من شخص آخر.

**على `ai` 4–6, `instrument("ai")` لا يسجل أي شيء بنفسه ويسجل تحذير واحد يقول ذلك.** الخطاف على مستوى العملية الوحيد الذي تملكه تلك الإصدارات الرئيسية هو موفر المتتبع العام OpenTelemetry — فتحة واحدة OpenTelemetry ترفض تسليمها مرة واحدة تُؤخذ. تسجيل لنا سيرفض صامتًا `NodeSDK.start()` الخاص بك لاحقًا في البدء ويرسل رموز http/database الخاصة بك إلى متتبع لا يُصدّر أي شيء. استخدم `telemetry()` في موقع الاستدعاء أو `wrapModel` هناك. إذا لم تشغل العملية OpenTelemetry من تلقاء نفسها اختر باستخدام `instrument("ai", { registerGlobalTracer: true })`: ثم يسجل كل استدعاء يمرر `experimental_telemetry: { isEnabled: true }` ويأخذ الفتحة فقط إذا كانت لا تزال فارغة. `registerGlobalTracer: false` يحتفظ بالافتراضي ويسكت التحذير.

إذا كنت تفضل التفاف النموذج مرة واحدة `wrapModel` يرى استدعاءات النموذج فقط لأن استدعاءات الأداة تحدث فوق طبقة النموذج. تُسجل نموذج ملفوف مع لا شيء حوله كتشغيل خاص به. استدعاء مُبثّ يغلق كيفما يتوقف التيار — `stop_reason: "cancelled"` عندما يلغي المستهلك وقفه `"error"` مع الخطأ عندما يفشل في منتصف الطريق:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

استخدام كلاهما جيد: تلاحظ البرمجيات الوسيطة أن الاستدعاء مُسجل بالفعل وتؤجل، لذا يتم تسجيل كل استدعاء مرة واحدة.

`functionId` يسمي امتداد الوكيل. احفظ منخفضة القيمة — تهبط في `agent_id`، الجانب الأساسي لوحة المعلومات.

### Next.js

`next build` يحزم اعتماديات خادمك بشكل افتراضي وإطار عمل محزوم في البناء نسخة `instrument()` لا يمكنها الوصول إليها. التفف الإعداد مرة واحدة واستدعِ `instrument()` من خطاف بدء Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* الإعداد الخاص بك */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` يضيف LangChain و Mastra و LlamaIndex و SDK نفسه إلى `serverExternalPackages` محافظًا على قائمتك. بدونه `instrument()` يحذر مرة واحدة لكل إطار عمل لا يمكنه الوصول إليه بدلاً من الفشل بصمت؛ إذا أدرجت الحزم بنفسك عيّن `FAILPROOFAI_NEXT_EXTERNALS=1`. يعمل SDK تلمترة Vercel AI و مساعدات موقع الاستدعاء بأي طريقة. طريق حافة يحصل على بناء بلا عملية: استيراد SDK آمن ولا يسجل أي شيء.

### عدد الرموز على استدعاءات مُبثّة

فقط واجهات برمجية متوافقة OpenAI تبلغ الاستخدام على تيار عندما يطلب العميل. تطلب LangChain و Vercel AI SDK؛ لـ LlamaIndex مرّر `additionalChatOptions: { stream_options: { include_usage: true } }` إلى `OpenAI` LLM الخاص بها ول Mastra بناء النموذج مع الاستخدام المُفعّل (على سبيل المثال `createOpenAICompatible({ includeUsage: true })`). وإلا فإن استدعاءات النموذج المُبثّة لا تحمل عدد رموز.

### أوقات التشغيل

Node ≥ 20.9 و Bun و Deno — كل إطار عمل كوحدة ES وكـ CommonJS يُختبر على كل واحد ضد التتبع. يعمل SDK بجانب خادم `failproofaid` الذي يرسل ما يكتبه.

## وكيلك الخاص — لا إطار عمل

لحلقة وكيل كتبتها بنفسك أو إطار عمل بدون مصفوفة. تبث الأحداث مع نفس الواجهة البرمجية التي تستخدمها المصفوفات تحتها لذا الأثر له نفس الشكل والجودة.

لا تحتاج إلى معرفة كيفية ينظم الوكيل. كل وكيل مبني باليد بالفعل لديه ثلاث أماكن مهما كانت دوالها تُدعى وتلك الثلاثة هي التكامل كاملاً:

| أين | ما يجب إضافته | يبث |
| --- | --- | --- |
| حيث **تشغيل واحد** يبدأ وينتهي | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **الدالة الوحيدة التي تستدعي النموذج** | `event.modelRequest` قبل `event.modelResponse` بعد — كلا النصفين حتى عند الفشل | زوج واحد لكل دور نموذج |
| **الدالة الوحيدة التي تشغل الأدوات** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

الهوية محيطة: كل شيء داخل `agent()` يهبط على تشغيل تلك الجلسة بدون أخذ معرف ولا شيء آخر في البرنامج يتغير — بما في ذلك مهما كان الوكيل يكتبه بالفعل لقاعدة البيانات الخاصة به.

- **خدمة أو عامل:** مرّر معرف الطلب أو الوظيفة الخاص بك كـ `sessionId` بحيث تكون جلسة لوحة المعلومات والسجل في السجلات أو قاعدة البيانات الخاصة بك نفس السلسلة.
- **وكلاء فرعيون:** عش استدعاءات `agent()`. الداخلي يضم الجلسة مع الخارجي كـ `parent_id`.
- **ابث الأزواج.** `modelRequest` بدون `modelResponse` امتداد يظهره لوحة المعلومات يعمل للأبد — ومن ثم `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) في المستودع هو النسخة كاملة والقابلة للتشغيل: حلقة أداة OpenAI حقيقية مُأدّات تمامًا مثل هذا تشغيل في CI على كل تغيير كوحدة ES وكـ CommonJS.

## التقييمات

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \

## ما لن تفعله لعملية الخاص بك

| | |
| --- | --- |
| **حجب حلقة الوكيل الخاص بك** | تذهب الأحداث إلى قائمة انتظار في الذاكرة؛ مؤقت يكتبها. المؤقت `unref`'د لذا استيراد هذه الحزمة لا يوقف نص من الخروج. |
| **النمو بدون حد** | تُختبّ القائمة بالعدد **و** بالبايتات المقاسة. بعد أي منهما تُتجاهل الأحداث الأقدم وتقول تحذير — يجب ألا يصبح انقطاع التلمترة قتلاً OOM. |
| **خذ العملية للأسفل** | حدث واحد لا يمكن ترميزه يُسقط وحده وليس الدفعة حوله. الحصول على الرمي أو مرجع دائري أو `BigInt` أو بديل وحيد: كل واحد يُعالج بدلاً من نشره. |
| **اترك دفعة نصف مكتوبة** | يتم `fsync` المحتوى قبل إعادة تسمية ذرية والمجلد `fsync` بعد وكتابة فاشلة تُنظف ملفها المؤقت. |
| **اترك نصوص قابلة للقراءة** | الدفعات `0600` داخل مجلد `0700`. تحمل أهدافًا وموجهات واستدعاءات أداة ومخرجات الأداة. |
| **سفينة الأوراق المالية** | مفاتيح API والرموز و JWTs وتنبيهات المحمل والتخصيصات من شكل السر تُخفّى قبل الوصول البايتات للقرص. الخادم يخفي مجددًا قبل الرفع. |
