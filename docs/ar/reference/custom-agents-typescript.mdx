Node 20.9 أو الإصدارات الأحدث. ESM و CommonJS. بدون تبعيات وقت التشغيل.

<Note>
  هذا SDK والـ SDK الخاص بـ Python يكتبان **نفس الأحداث في نفس الملف المؤقت**. فريق به وكلاء Node و وكلاء Python ينتج مجموعة جلسات واحدة وليس اثنتين، ولا شيء في لوحة التحكم يميز بينهما. اختر حسب كل خدمة وليس حسب الشركة.
</Note>

## التثبيت

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

محولات الأطر العاملة مرفقة في الحزمة نفسها. الأطر العاملة **تبعيات نظير اختيارية** — معلن عنها حتى تكون الرتب المدعومة مرئية، لا تُثبت بدلاً عنك، وتُستورد فقط عند استدعاء `instrument()`.

## الاتصال بـ daemon FailproofAI

مطابق للـ SDK الخاص بـ Python: أنشئ مفتاح `events:add` ضمن **Admin → Keys**، ثم [اتصل بـ daemon](/ar/start/setup#connect-a-machine-to-cloud) على جهاز الوكيل. يكتب SDK إلى القرص؛ daemon يشحن البيانات.

## الإعدادات

### أنماط OpenTelemetry (مشروط)

ثبّت OpenTelemetry بشكل منفصل باستخدام `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
ثم أضف FailproofAI إلى معالجات موفر الخدمة:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

بالنسبة لموفر خدمة موجود، احتفظ بمعالجاته الأخرى في نفس القائمة. الموفرون الذين يكشفون `addSpanProcessor` يمكن بدلاً من ذلك تمريرهم كـ `{ provider }`. بدون خيارات، يسجل الإعداد موفر خدمة جديد فقط إذا لم يكن هناك موفر مسجل بالفعل. يمكن أيضاً استخدام `OtelSpanExporter` مباشرة مع معالج خاص بك.

تذهب الصادرات عبر daemon FailproofAI المتصل؛ SDK لا يرسل طلبات شبكة ولا يحتاج إلى مفتاح أو جهاز استماع محلي. اطلب من مسؤول تفعيل [بروتوكول OpenTelemetry](/ar/agenteye/opentelemetry). `instrument()` الفارغ لا يفعّل هذا المُصدّر. `uninstrument("otel")` يعطل معالج خاص به فقط. تحكم سمات النمط الخاصة بك بحفظ المحتوى؛ أفرغ موفر الخدمة قبل الخروج. OpenTelemetry يبقى تبعية تطبيق اختيارية وليس تبعية SDK قاسية.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| الخيار | ما يفعله |
| --- | --- |
| `environment` | التسمية على كل حدث — `production` أو `staging` أو `prod-eu`. الافتراضي هو `dev`. |
| `flushInterval` | عدد مرات كتابة المؤقت إلى القرص، بالثواني. الافتراضي هو `0.5`. |
| `baseDir` | مكان الكتابة. الافتراضي هو ملف daemon المؤقت وهو ما تريده ما لم تعرف غير ذلك. |

لا يتم تطبيق أي شيء إلا إذا تحقق كل شيء، لذا فإن استدعاء مرفوض يترك SDK بالضبط كما كان بدلاً من وجود `baseDir` جديد والفاصل الزمني القديم.

ضع الإعدادات حسب متغير البيئة بدلاً من ذلك:

| المتغير | ما يفعله |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | يضع `environment` بدون تغيير في الكود. خيار `configure()` يفوز عليه. |
| `FAILPROOFAI_HOME` | ينقل جذر Failproof AI الذي يحتفظ بالملف المؤقت. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug` أو `info` أو `warn` (الافتراضي) أو `error` أو `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` يجعل أخطاء التجهيز تطرح استثناء بدلاً من تسجيلها. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` يجعل مشكلة توافق الأطر تطرح استثناء بدلاً من تحذير والمتابعة. |

<Warning>
  **لا توجد فواصل في `environment`.** يقسم البروتوكول حقل البيئة على الفواصل لبناء المرشحات الخاصة به، ويتخطى أي حدث تسميته تحتوي على واحد — لذا فإن التشغيل كله يختفي بصمت. اكتب `prod-eu` وليس `prod,eu`.

  `configure({ environment: "prod,eu" })` يطرح استثناء حتى تكتشف على الفور. `AGENTEYE_ENVIRONMENT` لا يمكن أن يطرح — لا أحد يستدعيك — لذا يحذر مرة واحدة ويعود إلى `dev`.
</Warning>

وجّه خطوط السجل الخاصة بـ SDK إلى مسجلك باستخدام `failproofai.setLogger({ debug, info, warn, error })`.

## الإغلاق

يتم إفراغ الأحداث المخزنة مؤقتاً على `process.on("exit")`.

العملية المقتولة بإشارة لا تصل أبداً إلى ذلك، والافتراضي لـ Node لـ `SIGTERM` هو الإنهاء بدون تشغيل معالجات الخروج — لذا فإن وكيل مُحتوى يفقد أي شيء لم يكتبه الفاصل الزمني الأخير.

<Warning>
  **هذا SDK لن يثبت معالج إشارة لك.** يغير تسجيل واحد سلوك العملية: يقمع المستمع الافتراضي الخاص بـ Node، لذا فإن مكتبة أضافت واحداً ستتوقف بصمت عن جعل Ctrl-C يعمل. أضف الخاص بك:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

يجب على السكريبت قصير الأجل أو معالج بدون خادم أن يستدعي `await failproofai.flush()` قبل الإرجاع — الفاصل الزمني وحده لا يضمن التسليم.

## الهوية

كل حدث ينتمي إلى جلسة ووكيل. **النطاقات ملء كل منهما**، لذا نادراً ما تمرر:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

تمرير `sessionId` أو `agentId` بشكل صريح لا يزال يعمل ويفوز. بدون ربط أو تمرير، الاستدعاء يطرح بدلاً من انبعاث حدث Cloud قد يتجاهل بصمت.

<Note>
  الهوية تركب على `AsyncLocalStorage`. تتبع `await` و `.then()` والمؤقتات وأي callback تم إنشاؤه داخل النطاق. إنها **لا** تتبع callback تم تخزينه أثناء تشغيل واحد واستدعاؤه أثناء آخر، أو عمل يتم تمريره عبر حد `worker_threads` — لفّ تلك في `failproofai.propagate()` أو أحداثها تهبط بدون ارتباط.
</Note>

### النطاقات

| النطاق | الأحداث | الإرجاع |
| --- | --- | --- |
| `session(body)` | لا شيء — الهوية فقط | أيا كان ما تعيده `body` |
| `agent(id, options?, body)` | `agent_start` ثم `agent_end` | أيا كان ما تعيده `body` |
| `toolCall(name, options?, body)` | `tool_use` ثم `tool_result` | أيا كان ما تعيده `body` |

جسم متزامن يبقى متزامناً: `agent("x", () => 1)` يعيد `1` وليس وعد.

`toolCall` يسجل القيمة المحلولة للجسم كـ `output` للأداة، إلا إذا أسندت `call.output` بنفسك.

<Accordion title="دلالات الخروج" icon="arrow-right-from-bracket">

| ما حدث | الأحداث | `outcome` |
| --- | --- | --- |
| أعادت الكتلة | `agent_end` | `success` أو `outcome` الخاص بك |
| رمت الكتلة | `error` ثم `agent_end` | `failed` |
| `AbortError` | `agent_end` فقط | `cancelled` |

يتم إعادة رمي الخطأ دائماً.

يتم تسجيل فشل الأداة على الورقة — `tool_result` مع سلسلة `error` — وينبعث **لا** حدث `error` على مستوى التشغيل. أحد الذي يمسك بحلقة الوكيل ليس فشل تشغيل، وأحد ينتشر يتم الإبلاغ عنه بالضبط مرة واحدة، بواسطة `agent()` المرفق.

</Accordion>

<Accordion title="نموذج `using`" icon="brackets-curly">

عندما لا تكون العملية دالة واحدة — نطاق مفتوح في مُنشئ ومغلق في التفكيك، أو واحد يمتد عبر تدفق تحكم موجود:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result، ثم agent_end
```

كلا الشكلين ينبعثان أحداث متطابقة البايت. فضّل نموذج الاستدعاء: يعمل داخل `AsyncLocalStorage.run()`، لذا لا شيء للفك والفئة كاملة من أخطاء "مفتوح هنا ومغلق هناك" غير قابل للوصول.

كتلة `using` التي تمسك بفشلها الخاص تبلغ عنه باستخدام `span.fail(error)` — المتخلص ليس له قناة استثناء خاصة به.

</Accordion>

## كتالوج الأحداث

نفس الطرق الخمسة عشرة كما في SDK الخاص بـ Python، في camelCase. تأتي معظمها في **أزواج** — تستدعي الفاتحة، ثم الأغلق، و SDK يوقت الفجوة.

| | الفاتحة | الأغلق |
| --- | --- | --- |
| **الوكلاء** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **النماذج** | `modelRequest` | `modelResponse` |
| **الأدوات** | `toolUse` | `toolResult` |
| **الخطافات** | `hookTriggered` | `hookCompleted` |
| **البشر** | `humanWait` | `humanInput` |

ثلاثة تقف وحدها: `error` و `humanPause` و `humanInterrupt`.

<Accordion title="كل حقل، لكل طريقة" icon="table">

كل طريقة تأخذ أيضاً `sessionId` و `agentId` الذي تملأه النطاقات لك. أي شيء محذوف يتم حذفه بدلاً من إرساله كـ JSON `null`.

| الطريقة | مطلوب | اختياري |
| --- | --- | --- |
| `agentStart` | — | `goal` و `parentId` |
| `agentEnd` | — | `outcome` و `summary` |
| `agentPause` | `pauseId` | `reason` و `userId` |
| `agentResume` | `pauseId` | `reason` و `userId` |
| `modelRequest` | — | `model` و `messages` و `system` و `tools` و `requestId` |
| `modelResponse` | — | `model` و `stopReason` و `inputTokens` و `outputTokens` و `content` و `role` و `requestId` |
| `toolUse` | `toolName` و `toolCallId` | `input` |
| `toolResult` | `toolName` و `toolCallId` | `output` و `error` |
| `hookTriggered` | `hookName` و `hookId` | `triggerEvent` و `input` |
| `hookCompleted` | `hookName` و `hookId` | `outcome` و `output` و `error` |
| `error` | `errorType` و `message` | `traceback` |
| `humanWait` | `inputId` | `prompt` و `options` و `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason` و `userId` |
| `humanInterrupt` | — | `reason` و `userId` و `atStep` |

أي مفتاح آخر تضيفه يصبح حقل حمولة مخصص. مساحة اسم أي شيء خاص بالإطار `fw_*`؛ الاسم الذي يتضارب مع حقل معلن يتم رفضه بدلاً من الكتابة فوق عمود مرقى بصمت.

</Accordion>

<Warning>
  **يتم حساب `duration_ms` وليس قبوله.** الأربع طرق إغلاق توقت الفجوة من فاتحاتها وترفض `duration_ms` يوفره المتصل — مدة معلنة غير قابلة للتزييف.

  يتم مطابقة الأزواج على **الجلسة** والمعرّف، وليس أبداً على الوكيل. أداة مفتوحة تحت `planner` ومغلقة تحت `worker` تقترن أيضاً، وهو ما تفعله تشغيلات وكلاء متعددة متداخلة فعلاً.
</Warning>

## محولات الأطر العاملة

```ts
await failproofai.instrument();              // أياً كان ما يمكن أن تجده
await failproofai.instrument("langchain");   // واحد بالضبط
failproofai.uninstrument();                  // أعد كل شيء
```

| الإطار | مدعوم | كيفية الارتباط |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x و LangGraph.js 0.4 – 1.x | `CallbackManager.configure` لذا كل `invoke`/`stream`/`batch` مغطى بدون تمرير `callbacks:` في أي مكان — أو مرر `langchainHandler()` بنفسك ولا تصحح أي شيء. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` في موقع الاستدعاء أو `instrument("ai")` لكل العملية على `ai` 7 (على 4–6 هذا مشروط — انظر أدناه). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream` وحل نموذج الوكيل والأداة وحركة workflow تشغيل/خطوة. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (مشترك) زائد `AgentWorkflow.runStream` لـ workflow تشغيلات وخطواتها. |

كل نطاق يتم اختباره مقابل إصدارات إطار حقيقية في كلا الطرفين كـ ES module و كـ CommonJS على كل CI run.

التعيين هو الخاص بـ SDK الخاص بـ Python، لذا نفس البرنامج يرسم نفس الشجرة بأي لغة. البناء هو **وكيل** فقط إذا امتلك حلقة قرار LLM — graph أو chain run أو AI SDK `generateText`/`streamText` call أو Mastra agent أو LlamaIndex agent run. عقدة LangGraph أو workflow step هو **hook** (`hook_triggered`/`hook_completed`) أبداً وكيل متداخل. استدعاءات النموذج هي `model_request`/`model_response` أزواج مع عدد رموز؛ استدعاءات الأداة تحمل معرّف استدعاء أداة النموذج الخاص بها. يتم تسجيل الفشل مرة واحدة، على الحدث الذي حدث فيه.

محول يفشل في التثبيت يتم تسجيله وتخطيه؛ الآخرون يثبتون بشكل طبيعي لأن LlamaIndex المكسور لا يجب أن يكلفك LangGraph.

<Note>
  `instrument()` بدون حجة يكتشف إطار عاملة بما إذا كان **يحل** وليس بما إذا كان مستورد بالفعل — Node لا يكشف معادل Python لـ `sys.modules` لـ ES modules. الإطار الذي ثبتته ولا تستخدمه سيتم استيراده وإصلاحه. اسم الذي تريده إذا كان ذلك مهماً.
</Note>

<Note>
  معظم هذه الأطر العاملة تشحن بناء ES-module و بناء CommonJS وNode يحمّل كنسختين غير مرتبطتين. المحولات تصحح نسخة التطبيق الخاص بك (والنسخة CommonJS أيضاً إذا كان شيء ما `require`d بالفعل) لذا كلا نظام الوحدات يعملان. إطار **مجمعة في مخرجك الخاص** بواسطة esbuild أو webpack خارج متناول اليد — استخدم مساعدات موقع الاستدعاء هناك: `langchainHandler()` و `telemetry()` و `wrapTool()`.
</Note>

### LangChain بدون إصلاح

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

معالج يعمل مع أو بدون `instrument()` وأبداً لا يسجل مرتين. `instrument("langchain")` يأخذ `sessionId` و `captureContent` و `includeChains` و `graphCallbacks` و `captureLimit` كما يفعل محول Python؛ `metadata: { failproofai_sdk_session_id }` على استدعاء يختار جلسة لهذا الاستدعاء.

### Vercel AI SDK

يصدّر AI SDK دوال عادية من ES module وES module namespace غير قابل للتعديل حسب الخاصية — لا يوجد مكان لإصلاح. يستخدم نقاط التوسع التي يوثقها SDK بنفسه:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // على ai 7، `telemetry: telemetry({ … })` — نفس الكائن والاسم الجديد
});
```

هذه هي التكامل الكامل: span وكيل وزوج طلب نموذج/استجابة لكل خطوة مع عدد رموز وكل استدعاء أداة. موقع استدعاء واحد يعمل على كل رئيسي — `ai` 4–6 يقرأ tracer يحمله و `ai` 7 تكامل telemetry.

`instrument("ai")` يفعل نفس العملية على كل شيء **على `ai` 7**: كل استدعاء عبر قائمة تكامل telemetry العامة لـ AI SDK وهو إضافي ولا يأخذ من أي شخص آخر.

**على `ai` 4–6 `instrument("ai")` لا يسجل أي شيء بنفسه ويسجل تحذير واحد يقول ذلك.** الخطاف على كل العملية الوحيد الذي لديه تلك الرئيسيات هو موفر tracer OpenTelemetry العامة — فتحة واحدة OpenTelemetry ترفض تسليمها مرة واحدة تُؤخذ. تسجيل لنا يرفض بصمت `NodeSDK.start()` بنفسك لاحقاً في بدء التشغيل ويرسل http/database spans إلى tracer يصدّر بلا شيء. استخدم `telemetry()` في موقع الاستدعاء أو `wrapModel` هناك. إذا لم تشغل العملية OpenTelemetry بنفسها اشترك مع `instrument("ai", { registerGlobalTracer: true })`: ثم يسجل كل استدعاء يمرر `experimental_telemetry: { isEnabled: true }` ويأخذ الفتحة فقط إذا كان لا يزال فارغاً. `registerGlobalTracer: false` يحتفظ بالافتراضي ويصمت التحذير.

إذا فضّلت لف النموذج مرة واحدة `wrapModel` يرى استدعاءات نموذج فقط لأن استدعاءات الأداة تحدث فوق طبقة النموذج. نموذج مغلف يُستدعى مع لا شيء حوله يُسجل كتشغيل خاص بها. استدعاء ينسل يُغلق أيا كان كيف توقف التدفق — `stop_reason: "cancelled"` عندما يلغي المستهلك ذلك و `"error"` مع الخطأ عندما يفشل نصفاً:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

استخدام كليهما بخير: middleware يلاحظ الاستدعاء مسجل بالفعل ويؤجل لذا كل استدعاء يُسجل مرة واحدة.

`functionId` يسمي span الوكيل. اجعله قليل الأصل — إنه ينزل في `agent_id` facet لوحة التحكم الأساسي.

### Next.js

`next build` يجمع تبعيات الخادم الخاص بك افتراضياً وإطار عاملة مجمعة في البناء هي نسخة `instrument()` لا يمكن الوصول إليها. لف الإعدادات مرة واحدة واستدعِ `instrument()` من hook بدء تشغيل Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` يضيف LangChain و Mastra و LlamaIndex والـ SDK نفسه لـ `serverExternalPackages` محتفظاً بقائمتك. بدون ذلك `instrument()` يحذر مرة واحدة لكل إطار لا يمكنه الوصول إليه بدلاً من الفشل بصمت؛ إذا أدرجت الحزم بنفسك اضبط `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK ومساعدات موقع الاستدعاء تعمل بأي حال. Edge route يحصل على بناء no-op: استيراد SDK آمن ولا يسجل أي شيء.

### عدد الرموز على الاستدعاءات المرسلة

واجهات برمجية OpenAI-compatible فقط الاستخدام في تقرير عندما يطلب العميل. LangChain و Vercel AI SDK يطلبان؛ لـ LlamaIndex مرر `additionalChatOptions: { stream_options: { include_usage: true } }` إلى OpenAI LLM الخاص بها وللـ Mastra بناء النموذج مع تفعيل الاستخدام (مثلاً `createOpenAICompatible({ includeUsage: true })`). بخلاف ذلك استدعاءات نموذج مرسلة لا تحمل عدد رموز.

### Runtimes

Node ≥ 20.9 و Bun و Deno — كل إطار عاملة كـ ES module و كـ CommonJS يتم اختباره على كل مقابل trace Node. SDK يعمل بجانب daemon `failproofaid` والذي يشحن ما يكتبه.

## الوكيل الخاص بك — بدون إطار عاملة

لحلقة وكيل كتبتها بنفسك أو إطار عاملة بدون محول. تبعث الأحداث باستخدام نفس API محولات الاستخدام تحتها لذا الأثر له نفس الشكل والجودة.

لا تحتاج أن تعرف كيفية تنظيم الوكيل. كل وكيل مدمج يدويّاً بالفعل لديه ثلاثة أماكن مهما كانت دوالها تسمى وتلك الثلاثة هي التكامل كله:

| المكان | ما يجب إضافته | ينبعث |
| --- | --- | --- |
| حيث **تشغيل واحد** يبدأ وينتهي | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **الدالة الوحيدة التي تستدعي النموذج** | `event.modelRequest` قبل و `event.modelResponse` بعد — كلا النصفين حتى عند الفشل | زوج واحد لكل منعطف نموذج |
| **الدالة الوحيدة التي تشغل الأدوات** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

الهوية محيطة: كل شيء داخل `agent()` يهبط على جلسة التشغيل دون أخذ معرّف ولا شيء آخر في البرنامج يتغير — بما في ذلك أياً كان ما يكتبه الوكيل بالفعل لقاعدة البيانات الخاصة به.

- **خدمة أو عامل:** مرر معرّف الطلب أو الوظيفة الخاص بك كـ `sessionId` لذا جلسة على لوحة التحكم والسجل في سجلاتك أو قاعدة بيانات هي نفس السلسلة.
- **وكلاء فرعيون:** عش استدعاءات `agent()`. الداخلي ينضم الجلسة مع الخارج كـ `parent_id` خاصة به.
- **انبعث الأزواج.** `modelRequest` بدون `modelResponse` هو span لوحة التحكم تظهره كتشغيل إلى الأبد — من هنا `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) في المخزن هي النسخة الكاملة التي يمكن تشغيلها: حلقة أداة OpenAI حقيقية مُشفّرة بالضبط مثل هذا يتم تشغيلها في CI على كل تغيير كـ ES module و كـ CommonJS.

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

## ما لن تفعله بعملية

| | |
| --- | --- |
| **حظر حلقة الوكيل الخاص بك** | تذهب الأحداث إلى طابور في الذاكرة؛ المؤقت يكتبها. المؤقت `unref`'d لذا استيراد هذه الحزمة أبداً لا يوقف script من الخروج. |
| **ينمو بدون حدود** | الطابور يُحد بالعدد **و** بالبايتات المقاسة. بعد الأي منهما الأحداث الأقدم تُرمى وتحذير يقول ذلك — انقطاع telemetry يجب ألا يصبح OOM kill. |
| **خذ العملية لأسفل** | حدث واحد غير قابل للترميز يُرمى وحده وليس الدفعة حوله. getter رمي استثناء مرجع دائري `BigInt` surrogate وحيد: يتم التعامل مع كل بدلاً من الانتشار. |
| **اترك دفعة نصف مكتوبة** | يتم `fsync` المحتوى قبل إعادة تسمية ذرية والدليل `fsync`'d بعد وكتابة فاشلة تنظف ملفها المؤقت. |
| **اترك النصوص قابلة للقراءة** | الدفعات `0600` داخل دليل `0700`. تحمل الأهداف والمحفزات وحجج الأداة ومخرجات الأداة. |
| **سفينة أوراق الاعتماد** | مفاتيح API والرموز و JWTs والرؤوس bearer والمهام الشكلية السرية يتم تنقيحها قبل البايتات تصل القرص. يقوم daemon بالتنقيح مرة أخرى قبل التحميل. |
