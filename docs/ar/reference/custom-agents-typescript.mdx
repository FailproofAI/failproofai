Node 20.9 أو أحدث. ESM و CommonJS. بدون تبعيات في وقت التشغيل.

<Note>
  هذا SDK والإصدار من Python يكتبان **نفس الأحداث في نفس السبول**. أسطول يحتوي على وكلاء Node و وكلاء Python ينتج مجموعة واحدة من الجلسات وليس اثنتين، ولا يميز لوحة المعلومات بينهما. اختر لكل خدمة وليس لكل شركة.
</Note>

## التثبيت

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

محولات الإطار العمل موجودة في الحزمة نفسها. الأطر العمل **تبعيات نظيرة اختيارية** — معلنة حتى تكون النطاقات المدعومة مرئية وليست مثبتة نيابة عنك مطلقًا ويتم استيرادها فقط عند استدعاء `instrument()`.

## توصيل خادم Failproof

مطابق لـ SDK الخاص بـ Python: أنشئ مفتاح `events:add` ضمن **الإعدادات → مفاتيح API**، ثم [توصيل الخادم](/ar/start/setup#connect-a-machine-to-cloud) على جهاز الوكيل. SDK يكتب إلى القرص؛ الخادم يشحن.

## الإعدادات

### رصات OpenTelemetry (اختيار)

ثبت OpenTelemetry بشكل منفصل باستخدام `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
ثم أضف FailproofAI إلى معالجات مزود الخدمة الخاص بك:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

بالنسبة للمزود الموجود، احتفظ بمعالجاته الأخرى في نفس القائمة. المزودون الذين يعرضون `addSpanProcessor` يمكن بدلاً من ذلك أن يتم تمريرهم كـ `{ provider }`. بدون خيارات، يسجل الإعداد مزودًا جديدًا فقط إذا لم يكن هناك مزود مسجل بالفعل.
يمكن أيضًا استخدام `OtelSpanExporter` مباشرة مع معالج خاص بك.

الصادرات تمر عبر خادم FailproofAI المتصل؛ SDK لا يرسل طلبات شبكة وليس لديه حاجة لمفتاح أو مستمع محلي. [بث OpenTelemetry](/ar/agenteye/opentelemetry)
مفعل دائمًا في Cloud. `instrument()` بسيط لا يفعّل هذا المُصدِّر. `uninstrument("otel")` يعطّل معالج نفسه فقط.
سمات الرصة الخاصة بك تتحكم في التقاط المحتوى؛ اشطف مزودك قبل الخروج.
OpenTelemetry يبقى تبعية تطبيق اختيارية وليس تبعية SDK صعبة.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| الخيار | الوظيفة |
| --- | --- |
| `environment` | التسمية على كل حدث — `production`, `staging`, `prod-eu`. الافتراضي `dev`. |
| `flushInterval` | كم مرة يكتب المؤقت إلى القرص بالثواني. الافتراضي `0.5`. |
| `baseDir` | حيث يكتب. الافتراضي إلى سبول الخادم وهو ما تريده ما لم تعرف خلاف ذلك. |

لا يتم تطبيق أي شيء ما لم يتحقق كل ذلك، لذا فإن الاستدعاء المرفوض يترك SDK بالضبط كما كان بدلاً من امتلاك `baseDir` جديد والفترة القديمة.

تعيين بمتغير بيئة بدلاً من ذلك:

| المتغير | الوظيفة |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | يعين `environment` بدون تغيير الكود. خيار `configure()` يفوز عليه. |
| `FAILPROOFAI_HOME` | ينقل جذر Failproof AI الذي يحمل السبول. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (افتراضي), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` يجعل أخطاء المراقبة ترمي بدلاً من تسجيلها. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` يجعل مشكلة توافق الإطار العمل ترمي بدلاً من التحذير والمتابعة. |

<Warning>
  **بدون فواصل في `environment`.** يقسم البث هذا الحقل على الفواصل لبناء المرشحات الخاصة به، ويتخطى أي حدث تحتوي تسميته على واحد — لذا يختفي المسار الكامل بصمت. اكتب `prod-eu` وليس `prod,eu`.

  `configure({ environment: "prod,eu" })` يرمي حتى تكتشف فورًا. `AGENTEYE_ENVIRONMENT` لا يمكن أن يرمي — لا أحد يناديك — لذا فإنه يحذر مرة واحدة ويعود للخلف إلى `dev`.
</Warning>

وجه رسائل السجل الخاصة بـ SDK نفسه إلى سجلك باستخدام `failproofai.setLogger({ debug, info, warn, error })`.

## الإغلاق

يتم تفريغ الأحداث المخزنة مؤقتًا عند `process.on("exit")`.

عملية مقتولة بإشارة لن تصل إلى ذلك مطلقًا والقيمة الافتراضية لـ Node لـ `SIGTERM` هي الإنهاء بدون تشغيل معالجات الخروج — لذا فإن وكيل موجود في حاوية يفقد كل ما لم يكتبه الفاصل الزمني الأخير.

<Warning>
  **هذا SDK لن يثبت معالج إشارات لك.** تسجيل واحد يغير سلوك العملية: مستمع يقمع القيمة الافتراضية لـ Node، لذا فإن مكتبة أضافت واحدًا ستوقف Ctrl-C بصمت عن العمل. أضف واحدًا خاصًا بك:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

نص قصير الأجل أو معالج بدون خادم يجب أن يستدعي `await failproofai.flush()` قبل الإرجاع — الفاصل الزمني وحده لا يضمن التسليم.

## الهوية

كل حدث ينتمي إلى جلسة ووكيل. **النطاقات تملأهما**، لذا نادراً ما تمررهما:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

تمرير `sessionId` أو `agentId` بشكل صريح لا يزال يعمل والفوز. مع عدم ربط أو تمرير كليهما، الاستدعاء يرمي بدلاً من إصدار حدث Cloud سيتجاهله بصمت.

<Note>
  الهوية تركب على `AsyncLocalStorage`. إنها تتابع `await` و `.then()` والمؤقتات وأي استدعاء تم إنشاؤه داخل النطاق. إنها **لا** تتابع استدعاء مخزن أثناء تشغيل واحد وتم استدعاؤه أثناء تشغيل آخر أو عمل تم تمريره عبر حدود `worker_threads` — لفها في `failproofai.propagate()` أو ستهبط أحداثها غير مرفقة.
</Note>

### النطاقات

| النطاق | الإصدار | الإرجاع |
| --- | --- | --- |
| `session(body)` | لا شيء — الهوية فقط | ما يرجعه `body` |
| `agent(id, options?, body)` | `agent_start`, ثم `agent_end` | ما يرجعه `body` |
| `toolCall(name, options?, body)` | `tool_use`, ثم `tool_result` | ما يرجعه `body` |

الجسم المتزامن يبقى متزامنًا: `agent("x", () => 1)` يرجع `1` وليس وعدًا.

`toolCall` يسجل القيمة المحللة للجسم كـ `output` للأداة ما لم تعين `call.output` بنفسك.

<Accordion title="دلالات الخروج" icon="arrow-right-from-bracket">

| ما حدث | الأحداث | `outcome` |
| --- | --- | --- |
| أرجع الكتلة | `agent_end` | `"success"` أو `outcome` الخاص بك |
| رمت الكتلة | `error` ثم `agent_end` | `"failed"` |
| `AbortError` | `agent_end` فقط | `"cancelled"` |

الخطأ يتم إعادة رمه دائمًا.

الفشل في الأداة يتم تسجيله على الورقة — `tool_result` مع سلسلة `error` — ولا ينبعث حدث `error` على مستوى التشغيل. واحد يمسكه حلقة الوكيل ليس فشل تشغيل واحد ينتشر يتم الإبلاغ عنه بالضبط مرة واحدة بواسطة `agent()` المحيط.

</Accordion>

<Accordion title="نموذج `using`" icon="brackets-curly">

عندما لا تكون العملية دالة واحدة — يتم فتح نطاق في منشئ وإغلاقه في هدم أو واحد يمتد عبر التدفق الموجود:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

كلا الشكلين ينبعثان من الأحداث التي تطابق البايت. فضّل نموذج الاستدعاء: يعمل داخل `AsyncLocalStorage.run()` لذا لا يوجد شيء لفكه وفئة `opened here, closed over there` بأكملها من الأخطاء لا تُرجع.

كتلة `using` التي تمسك بفشلها الخاص تبلغ عنها باستخدام `span.fail(error)` — لا تحتوي الموزعة على قناة استثناء خاصة بها.

</Accordion>

## فهرس الأحداث

نفس خمسة عشر طريقة كـ SDK الخاص بـ Python بـ camelCase. معظمها يأتي بـ **أزواج** — تستدعي المفتاح ثم المغلق، و SDK يوقت الفجوة.

| | يفتح | يغلق |
| --- | --- | --- |
| **الوكلاء** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **النماذج** | `modelRequest` | `modelResponse` |
| **الأدوات** | `toolUse` | `toolResult` |
| **الخطافات** | `hookTriggered` | `hookCompleted` |
| **البشر** | `humanWait` | `humanInput` |

ثلاثة تقف بمفردها: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="كل حقل لكل طريقة" icon="table">

كل طريقة تأخذ أيضًا `sessionId` و `agentId` والتي يملأها النطاق لك. أي شيء حذف يتم حذفه بدلاً من الإرسال كـ JSON `null`.

| الطريقة | مطلوب | اختياري |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

أي مفتاح آخر تضيفه يصبح حقل حمولة مخصص. أسطر نطاق أي شيء خاص بالإطار العمل `fw_*`؛ اسم يتعارض مع حقل معلن يتم رفضه بدلاً من الكتابة فوق عمود مرفوع بصمت.

</Accordion>

<Warning>
  **`duration_ms` محسوب وليس مقبول.** الطرق الأربع للإغلاق توقت الفجوة من فتاحها وترفض `duration_ms` مزود من المتصل — المدة المبلغ عنها لا يمكن تزييفها.

  تتم مطابقة الأزواج على **الجلسة** والمعرف وليس على الوكيل. أداة تم فتحها ضمن `planner` وإغلاقها تحت `worker` لا تزال تتطابق وهو ما تفعله الأسطول متعدد الوكلاء المتداخلة بالفعل.
</Warning>

## محولات الإطار العمل

```ts
await failproofai.instrument();              // whatever it can find
await failproofai.instrument("langchain");   // exactly one
failproofai.uninstrument();                  // put everything back
```

| الإطار العمل | المدعومة | كيف تتعلق |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure` وبالتالي فإن كل `invoke`/`stream`/`batch` مغطاة بدون تمرير `callbacks:` في أي مكان — أو تمرير `langchainHandler()` بنفسك وعدم تصحيح أي شيء. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` في موقع الاستدعاء أو `instrument("ai")` للعملية برمتها على `ai` 7 (على 4–6 يكون اختياريًا — انظر أدناه). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream` وحل نموذج الوكيل والأداة وتشغيل سير العمل/محرك الخطوة. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (مشترك) بالإضافة إلى `AgentWorkflow.runStream` لتشغيل سير العمل وخطواتهم. |

يتم اختبار كل نطاق ضد إصدارات الإطار العمل الحقيقية في كلا الطرفين كمودول ES و CommonJS على كل تشغيل CI.

المخطط الموجود هو SDK الخاص بـ Python لذا فإن نفس البرنامج يرسم نفس الشجرة بأي لغة. يكون البناء **وكيلاً** فقط إذا كان يملك حلقة قرار LLM — سير عمل أو تشغيل سلسلة أو استدعاء Vercel AI SDK `generateText`/`streamText` أو وكيل Mastra أو تشغيل وكيل LlamaIndex. عقدة LangGraph أو خطوة سير عمل هي **خطاف** (`hook_triggered`/`hook_completed`) وليست أبدًا وكيلاً متداخلاً. استدعاءات النموذج هي أزواج `model_request`/`model_response` مع عدد الرموز؛ استدعاءات الأداة تحمل معرف استدعاء الأداة الخاص بـ النموذج نفسه. يتم تسجيل الفشل مرة واحدة على الحدث الذي حدث فيه.

محول فشل التثبيت يتم تسجيله وتخطيه؛ الآخرون لا يزالون يثبتون لأن LlamaIndex المكسورة يجب ألا تكلفك LangGraph.

<Note>
  `instrument()` بدون وسيط يكتشف إطار العمل حسب ما إذا كان **يحل** وليس حسب ما إذا كان مستورد بالفعل — Node لا يعرض ما يعادل Python's `sys.modules` لمودول ES. إطار عمل لديك مثبت ولكن لا تستخدمه سيتم استيراده وتصحيحه. سمّ الذي تريده إذا كان ذلك مهمًا.
</Note>

<Note>
  معظم هذه الأطر العمل شحنة بناء وحدة ES وبناء CommonJS والذي يحمل Node كنسختين غير ذات صلة. تقوم المحولات بتصحيح النسخة التي يحملها تطبيقك (ونسخة CommonJS أيضًا إذا كان شيء ما قد `require`ed بالفعل) لذا فإن كلا نظامي الوحدات يعملان. إطار عمل **معبأ في الإخراج الخاص بك** بواسطة esbuild أو webpack بعيد المنال — استخدم مساعدات موقع الاستدعاء هناك: `langchainHandler()` و `telemetry()` و `wrapTool()`.
</Note>

### LangChain بدون تصحيح

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

يعمل المعالج مع أو بدون `instrument()` ولا ينسخ السجلات مطلقًا. `instrument("langchain")` يأخذ `sessionId` و `captureContent` و `includeChains` و `graphCallbacks` و `captureLimit` كما يفعل محول Python؛ `metadata: { failproofai_sdk_session_id }` على استدعاء يختار الجلسة لهذا الاستدعاء.

### Vercel AI SDK

تُصدّر AI SDK وظائف عادية من وحدة ES ووحدة اسم ES تكون ثابتة بموجب المواصفات — لا يوجد مكان للتصحيح. إنها تستخدم نقاط الامتداد التي توثقها SDK نفسه:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // on ai 7, `telemetry: telemetry({ … })` — the same object, the new name
});
```

هذا هو التكامل الكامل: رصة وكيل وزوج طلب/رد نموذج لكل خطوة مع عدد الرموز واستدعاء كل أداة. موقع استدعاء واحد يعمل على كل ميجور — `ai` 4–6 اقرأ المتتبع الذي يحمله `ai` 7 تكامل القياس الجديد.

`instrument("ai")` يفعل نفس العملية على مستوى العملية **على `ai` 7**: كل استدعاء من خلال قائمة تكامل القياس العام لـ AI SDK وهي إضافة ولا تأخذ من قوائم أحد آخر.

**على `ai` 4–6 `instrument("ai")` لا يسجل أي شيء بنفسه ويسجل تحذيرًا واحدًا يقول ذلك.** أعلى خطاف عملية لديها هذه الدوريات هو مزود المتتبع العام OpenTelemetry — فتحة واحدة OpenTelemetry ترفض تسليمها مرة واحدة اتخذت. تسجيل الملك سيرفض بصمت `NodeSDK.start()` لك لاحقًا في البدء وإرسال رسائلك http/database إلى متتبع لا يُصدِّر أي شيء. استخدم `telemetry()` في موقع الاستدعاء أو `wrapModel` هناك. إذا لم تقم العملية برتقة OpenTelemetry خاصة بك اختيار التي تحتوي على `instrument("ai", { registerGlobalTracer: true })`: فإنه يسجل بعد ذلك كل استدعاء يمرر `experimental_telemetry: { isEnabled: true }` ويأخذ الفتحة فقط إذا كانت لا تزال فارغة. `registerGlobalTracer: false` يحتفظ بالقيمة الافتراضية ويصمت التحذير.

إذا فضلت لف النموذج مرة واحدة `wrapModel` يرى استدعاءات نموذج فقط لأن استدعاءات الأداة تحدث فوق طبقة النموذج. يتم تسجيل نموذج ملفوف يُستدعى مع لا شيء حوله كتشغيله الخاص. استدعاء دفق يغلق كيفما يتوقف الدفق — `stop_reason: "cancelled"` عندما يلغي المستهلك `"error"` مع الخطأ عندما يفشل في منتصف الطريق:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

استخدام كليهما بخير: تلاحظ البرمجيات الوسيطة الاستدعاء يتم تسجيله بالفعل والتأجيل لذا يتم تسجيل كل استدعاء مرة واحدة.

`functionId` يسمي رصة الوكيل. ابقِ منخفض الكاردينالية — ينزل في `agent_id` وهو الجانب الرئيسي لمنصة المعلومات.

### Next.js

`next build` حزم تبعيات الخادم الخاص بك بشكل افتراضي وإطار عمل معبأ في البناء هو نسخة `instrument()` لا يمكنها الوصول. لف الإعدادات مرة واحدة واستدعي `instrument()` من خطاف بدء تشغيل Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` يضيف LangChain و Mastra و LlamaIndex و SDK نفسه إلى `serverExternalPackages` محافظًا على قائمتك. بدونها `instrument()` يحذر مرة واحدة لكل إطار عمل لا يمكنه الوصول بدلاً من الفشل بصمت؛ إذا قمت بإدراج الحزم بنفسك اضبط `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK ومساعدات موقع الاستدعاء تعمل في كلا الاتجاهين. حافة الطريق تحصل على بناء لا عملي: استيراد SDK آمن ولا يسجل أي شيء.

### عدد الرموز على الاستدعاءات الموصولة

واجهات برمجية متوافقة OpenAI فقط تبلغ عن الاستخدام على التدفق عندما يطلب العميل. LangChain و Vercel AI SDK يطلبان؛ بالنسبة لـ LlamaIndex تمرير `additionalChatOptions: { stream_options: { include_usage: true } }` إلى `OpenAI` LLM الخاص به ولـ Mastra بناء النموذج مع تفعيل الاستخدام (على سبيل المثال `createOpenAICompatible({ includeUsage: true })`). خلاف ذلك استدعاءات نموذج موصول لا تحمل عدد رموز.

### أوقات التشغيل

Node ≥ 20.9 و Bun و Deno — كل إطار عمل كمودول ES و CommonJS يتم اختباره على كل واحد ضد تتبع Node. SDK يعمل بجانب خادم `failproofaid` والذي يشحن ما يكتبه.

## وكيلك الخاص — بدون إطار عمل

لحلقة وكيل كتبتها بنفسك أو إطار عمل بدون محول. تُصدر الأحداث بنفس API الذي تستخدمه المحولات تحت الأرض لذا فإن التتبع له نفس الشكل والجودة.

لا تحتاج إلى معرفة كيفية تنظيم الوكيل. كل وكيل مبني يدويًا بالفعل لديه ثلاثة أماكن مهما كانت وظائفه تُسمى وتلك الثلاثة هي التكامل الكامل:

| حيث | ما يجب إضافته | الإصدار |
| --- | --- | --- |
| حيث **تشغيل واحد** يبدأ وينتهي | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **الدالة الوحيدة التي تستدعي النموذج** | `event.modelRequest` قبل و `event.modelResponse` بعد — كلا النصفين حتى عند الفشل | زوج واحد لكل دور نموذج |
| **الدالة الوحيدة التي تشغل الأدوات** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

الهوية محيطة: كل شيء داخل `agent()` ينزل على جلسة هذا التشغيل بدون أخذ معرف ولا شيء آخر في البرنامج يتغير — بما في ذلك كل ما يكتبه الوكيل بالفعل إلى قاعدة بيانات خاصة به.

- **خدمة أو عامل:** مرر معرف الطلب أو الوظيفة الخاص بك كـ `sessionId` حتى تكون جلسة على لوحة المعلومات والسجل في السجلات الخاصة بك أو قاعدة البيانات نفس السلسلة.
- **الوكلاء الفرعيون:** تداخل استدعاءات `agent()`. الداخلي ينضم إلى الجلسة مع الخارجي كـ `parent_id`.
- **أصدر الأزواج.** `modelRequest` بدون `modelResponse` هو رصة تعرضها لوحة المعلومات كتشغيل للأبد — ومن هنا `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) في المستودع هو النسخة الكاملة والقابلة للتشغيل: حلقة أداة OpenAI حقيقية مشروعة بالضبط مثل هذا تعمل في CI على كل تغيير كمودول ES و CommonJS.

## التقييمات

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \

```

## ما لن يفعله بالعملية الخاصة بك

| | |
| --- | --- |
| **حجب حلقة الوكيل الخاصة بك** | الأحداث تدخل قائمة في الذاكرة؛ يكتب موقت لهم. المؤقت هو `unref`'d لذا فإن استيراد هذه الحزمة لا يوقف الإنهاء النصي مطلقًا. |
| **نمو بدون حد** | يتم تحديد القائمة حسب الحساب *و* من خلال البايتات المقاسة. بعد كل واحد، يتم التخلص من أقدم الأحداث وتحذير يقول ذلك — انقطاع القياس الجديد يجب ألا يصبح قتل OOM. |
| **خذ العملية لأسفل** | حدث واحد غير قابل للترميز يتم إسقاطه وحده وليس الدفعة حوله. جالب طرح أو مرجع دائري أو `BigInt` أو بديل واحد: يتم التعامل مع كل واحد بدلاً من انتشاره. |
| **ترك دفعة مكتوبة بشكل نصفي** | المحتوى هو `fsync`ed قبل إعادة تسمية ذرية والمجلد هو `fsync`ed بعد وكتابة فاشلة تنظف ملف مؤقت. |
| **ترك نصوص قابلة للقراءة** | الدفعات هي `0600` داخل مجلد `0700`. إنها تحمل أهدافًا وطلبات وحجج الأداة ومخرجات الأداة. |
| **شحن بيانات الاعتماد** | مفاتيح API والرموز والرموز المميزة والرؤوس السرية والمهام التي تشبه السرية يتم تحريرها قبل البايتات للوصول إلى القرص. الخادم يحرير مرة أخرى قبل التحميل. |
