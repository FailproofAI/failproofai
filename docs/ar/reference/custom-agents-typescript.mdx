Node 20.9 أو أحدث. ESM و CommonJS. لا توجد تبعيات وقت التشغيل.

<Note>
  هذا SDK والآخر من Python يكتبان **نفس الأحداث إلى نفس الاسطوانة**. أسطول يحتوي على وكلاء Node ووكلاء Python ينتج مجموعة واحدة من الجلسات وليس اثنتين، ولا يوجد شيء في لوحة التحكم يميز بينهما. اختر لكل خدمة وليس لكل شركة.
</Note>

## التثبيت

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

محولات الأطر مرسلة في الحزمة نفسها. الأطر هي **تبعيات نظير اختيارية** — معلنة بحيث تكون النطاقات المدعومة مرئية وليست مثبتة نيابة عنك أبدا، وتم استيرادها فقط عند استدعاء `instrument()`.

## توصيل مؤشر ترابط Failproof

مطابق لـ Python SDK: أنشئ مفتاح `events:add` ضمن **Admin → Keys**، ثم [صل مؤشر ترابط](/ar/start/setup#connect-a-machine-to-cloud) على جهاز الوكيل. يكتب SDK إلى القرص؛ مؤشر الترابط يشحن.

## الإعدادات

### فترات OpenTelemetry (اختيار)

ثبت OpenTelemetry بشكل منفصل باستخدام `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
بعد ذلك أضف FailproofAI إلى معالجات موفر خدمتك:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

بالنسبة لموفر خدمة موجود، احتفظ بمعالجاته الأخرى في نفس القائمة. يمكن تمرير موفري الخدمات الذين يعرضون `addSpanProcessor` بدلاً من ذلك كـ `{ provider }`. بدون خيارات، يسجل الإعداد موفر خدمة جديد فقط إذا لم يكن هناك موفر خدمة مسجل بالفعل.
يمكن أيضا استخدام `OtelSpanExporter` مباشرة مع معالجك الخاص.

تمر الصادرات عبر مؤشر ترابط FailproofAI المتصل؛ SDK لا يرسل طلبات شبكة ولا يحتاج إلى مفتاح أو محاكي استماع محلي. اطلب من مسؤول تفعيل [استيعاب OpenTelemetry](/ar/agenteye/opentelemetry). `instrument()` مجرد لا يفعل هذا المُصدِّر. `uninstrument("otel")` يعطّل معالجه الخاص فقط.
سمات الفترة الخاصة بك تتحكم في التقاط المحتوى؛ اشطف موفر خدمتك قبل الخروج.
يبقى OpenTelemetry تبعية تطبيق اختيارية، وليس تبعية SDK صعبة.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| الخيار | ما يفعله |
| --- | --- |
| `environment` | الملصق على كل حدث — `production` أو `staging` أو `prod-eu`. الافتراضي هو `dev`. |
| `flushInterval` | عدد مرات كتابة المؤقت إلى القرص بالثواني. الافتراضي هو `0.5`. |
| `baseDir` | مكان الكتابة. الافتراضي هو اسطوانة مؤشر الترابط، وهو ما تريده ما لم تعرف غير ذلك. |

لا يتم تطبيق أي شيء ما لم يتحقق الكل منه، لذا فإن استدعاء مرفوض يترك SDK تماما كما كان بدلا من وجود `baseDir` جديد والفترة القديمة.

اضبط بواسطة متغير البيئة بدلاً من ذلك:

| المتغير | ما يفعله |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | يضبط `environment` بدون تغيير الكود. خيار `configure()` يفوز عليه. |
| `FAILPROOFAI_HOME` | ينقل جذر Failproof AI الذي يحتوي على الاسطوانة. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug` أو `info` أو `warn` (افتراضي) أو `error` أو `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` يجعل أخطاء التجهيز ترمي بدلا من تسجيلها. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` يجعل مشكلة توافق الأطر ترمي بدلا من تحذير والمتابعة. |

<Warning>
  **بدون فواصل في `environment`.** يقسم الاستيعاب هذا الحقل على الفواصل لبناء مرشحاته، وتخطي أي حدث تسميته يحتوي على واحد — لذا فإن تشغيل كامل يختفي بصمت. اكتب `prod-eu` وليس `prod,eu`.

  `configure({ environment: "prod,eu" })` يرمي بحيث تكتشف على الفور. `AGENTEYE_ENVIRONMENT` لا يمكن أن يرمي — لا أحد يناديك — لذا فإنه يحذر مرة واحدة ويعود إلى `dev`.
</Warning>

وجّه سطور السجلات الخاصة بـ SDK إلى مسجلك باستخدام `failproofai.setLogger({ debug, info, warn, error })`.

## الإيقاف

يتم شطف الأحداث المخزنة مؤقتا عند `process.on("exit")`.

العملية المقتولة بواسطة إشارة لا تصل أبدا إلى ذلك، والافتراضي في Node لـ `SIGTERM` هو الإنهاء بدون تشغيل معالجات الخروج — لذا فإن وكيل بدون حاويات يفقد كل ما لم تكتبه الفترة الأخيرة.

<Warning>
  **هذا SDK لن يثبت معالج إشارة لك.** يؤدي تسجيل واحد إلى تغيير سلوك العملية: يثبط المستمع الافتراضي الافتراضي في Node، لذا فإن مكتبة أضافت واحدا ستتوقف بصمت عن Ctrl-C من العمل. أضف الخاص بك:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

يجب أن يقوم البرنامج النصي قصير الأجل أو معالج بدون خادم بـ `await failproofai.flush()` قبل العودة — الفترة الزمنية وحدها لا تضمن التسليم.

## الهوية

كل حدث ينتمي إلى جلسة ووكيل. **النطاقات تملأ كليهما**، لذا نادرا ما تمريرهما:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

تمرير `sessionId` أو `agentId` بشكل صريح لا يزال يعمل ويفوز. بدون ربط أو تمرير، يرمي الاستدعاء بدلا من إصدار حدث قد يتم التخلص منه بصمت.

<Note>
  الهوية تركب على `AsyncLocalStorage`. يتبع `await` و `.then()` والمؤقتات وأي رد نداء تم إنشاؤه داخل النطاق. لا يتبع رد نداء تم تخزينه أثناء تشغيل واحد واستدعاؤه أثناء تشغيل آخر، أو العمل الذي يتم تمريره عبر حدود `worker_threads` — لف تلك في `failproofai.propagate()` أو أحداثها تهبط بدون ربط.
</Note>

### النطاقات

| النطاق | يصدر | يرجع |
| --- | --- | --- |
| `session(body)` | لا شيء — الهوية فقط | أيا كان ما يرجعه `body` |
| `agent(id, options?, body)` | `agent_start` ثم `agent_end` | أيا كان ما يرجعه `body` |
| `toolCall(name, options?, body)` | `tool_use` ثم `tool_result` | أيا كان ما يرجعه `body` |

جسم متزامن يبقى متزامنا: `agent("x", () => 1)` يرجع `1` وليس وعدا.

`toolCall` يسجل قيمة الجسم المحللة كـ `output` الأداة، ما لم تعين `call.output` بنفسك.

<Accordion title="دلالات الخروج" icon="arrow-right-from-bracket">

| ما حدث | الأحداث | `outcome` |
| --- | --- | --- |
| أرجع الكتلة | `agent_end` | `"success"` أو `outcome` الخاص بك |
| رمت الكتلة | `error` ثم `agent_end` | `"failed"` |
| `AbortError` | `agent_end` فقط | `"cancelled"` |

يتم إعادة رمي الخطأ دائما.

يتم تسجيل فشل الأداة على الورقة — `tool_result` مع سلسلة `error` — وينبعث **لا** حدث `error` على مستوى التشغيل. واحد يمسكه حلقة الوكيل ليس فشل التشغيل، وواحد ينتشر يتم الإبلاغ عنه بالضبط مرة واحدة، بواسطة `agent()` المحيط.

</Accordion>

<Accordion title="نموذج `using`" icon="brackets-curly">

عندما لا تكون العمل وظيفة واحدة — نطاق مفتوح في المنشئ ومغلق في الهدم، أو واحد يعبر تدفق التحكم الموجود:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

كلا الشكلين ينبعث بايت متطابق الأحداث. فضّل نموذج رد النداء: يعمل داخل `AsyncLocalStorage.run()`، لذا لا يوجد شيء لفك والفئة بأكملها من أخطاء «مفتوح هنا ومغلق هناك» غير قابلة للوصول.

كتلة `using` التي تمسك بفشلها الخاص ترسله مع `span.fail(error)` — المخلص ليس لديه قناة استثناء خاصة به.

</Accordion>

## فهرس الأحداث

نفس خمسة عشر طريقة مثل Python SDK، في camelCase. معظمها يأتي في **أزواج** — تستدعي الفاتح، ثم الإغلاق، و SDK يوقت الفجوة.

| | يفتح | يغلق |
| --- | --- | --- |
| **الوكلاء** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **النماذج** | `modelRequest` | `modelResponse` |
| **الأدوات** | `toolUse` | `toolResult` |
| **الخطافات** | `hookTriggered` | `hookCompleted` |
| **البشر** | `humanWait` | `humanInput` |

ثلاثة تقف وحدها: `error` و `humanPause` و `humanInterrupt`.

<Accordion title="كل حقل، لكل طريقة" icon="table">

كل طريقة تأخذ أيضا `sessionId` و `agentId`، والتي تملأها النطاقات لك. أي شيء محذوف ينخفض بدلا من إرساله كـ JSON `null`.

| الطريقة | مطلوب | اختياري |
| --- | --- | --- |
| `agentStart` | — | `goal` و `parentId` |
| `agentEnd` | — | `outcome` و `summary` |
| `agentPause` | `pauseId` | `reason` و `userId` |
| `agentResume` | `pauseId` | `reason` و `userId` |
| `modelRequest` | — | `model` و `messages` و `system` و `tools` و `requestId` |
| `modelResponse` | — | `model` و `stopReason` و `inputTokens` و `outputTokens` و `content` و `role` و `requestId` |
| `toolUse` | `toolName` و `toolCallId` | `input` |
| `toolResult` | `toolName` و `toolCallId` | `output` و `error` |
| `hookTriggered` | `hookName` و `hookId` | `triggerEvent` و `input` |
| `hookCompleted` | `hookName` و `hookId` | `outcome` و `output` و `error` |
| `error` | `errorType` و `message` | `traceback` |
| `humanWait` | `inputId` | `prompt` و `options` و `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason` و `userId` |
| `humanInterrupt` | — | `reason` و `userId` و `atStep` |

أي مفتاح آخر تضيفه يصبح حقل حمولة مخصص. مساحة اسم أي شيء خاص بالأطر `fw_*`؛ اسم يتضارب مع حقل معلن يتم رفضه بدلا من سرقة عمود مرتقي بصمت.

</Accordion>

<Warning>
  **`duration_ms` يتم حسابه وليس مقبولا.** الطرق الأربع الإغلاق توقت الفجوة من الفاتح الخاص بهم وترفض `duration_ms` المموَّل من قبل المتصل — مدة مبلغة عنها لا يمكن دحضها.

  يتم مطابقة الأزواج على **الجلسة** والمعرف، لا على الوكيل أبدا. أداة مفتوحة تحت `planner` ومغلقة تحت `worker` لا تزال تقترن، وهو ما تفعله تشغيلات وكلاء متعددة متداخلة فعلا.
</Warning>

## محولات الأطر

```ts
await failproofai.instrument();              // whatever it can find
await failproofai.instrument("langchain");   // exactly one
failproofai.uninstrument();                  // put everything back
```

| الإطار | مدعوم | كيف يرفقها |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x و LangGraph.js 0.4 – 1.x | `CallbackManager.configure` لذا كل `invoke`/`stream`/`batch` مغطى بدون تمرير `callbacks:` في أي مكان — أو مرر `langchainHandler()` بنفسك ولا تصحح أي شيء. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` في موقع الاستدعاء، أو `instrument("ai")` للعملية بأكملها على `ai` 7 (على 4–6 وهذا اختياري — انظر أدناه). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream` وحل نموذج الوكيل والأداة وحل محرك تشغيل سير العمل/الخطوة. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (مشترك) بالإضافة إلى `AgentWorkflow.runStream` لتشغيل سير العمل وخطواتها. |

يتم اختبار كل نطاق مقابل إصدارات إطار عمل حقيقية، في كلا الطرفين، كـ ES module و CommonJS، في كل تشغيل CI.

المعيار هو Python SDK، لذا نفس البرنامج يرسم نفس الشجرة بأي لغة. البناء هو **وكيل** فقط إذا كان يمتلك حلقة قرار LLM — رسم بياني أو تشغيل سلسلة، استدعاء `generateText`/`streamText` لـ AI SDK، وكيل Mastra، تشغيل وكيل LlamaIndex. عقدة LangGraph أو خطوة سير عمل هي **خطاف** (`hook_triggered`/`hook_completed`)، لا وكيل متداخل أبدا. استدعاءات النموذج هي أزواج `model_request`/`model_response` مع عدد الرموز؛ استدعاءات الأداة تحمل معرف استدعاء الأداة الخاص بالنموذج. يتم تسجيل الفشل مرة واحدة، على الحدث الذي حدث فيه.

محول فاشل في التثبيت يتم تسجيله وتخطيه؛ الآخرون لا يزالون يثبتون، لأن LlamaIndex المحطم يجب ألا يكلفك LangGraph.

<Note>
  `instrument()` بدون حجة يكتشف إطار عمل حسب ما إذا كان يتحل، وليس حسب ما إذا كان مستوردا بالفعل — لا يفضح Node مكافئ Python `sys.modules` لـ ES modules. الإطار الذي لديك مثبت لكن لا تستخدمه سيتم استيراده وتصحيحه. سمِّ الذي تريده إذا كان ذلك مهما.
</Note>

<Note>
  معظم هذه الأطر تشحن بناء ES-module وبناء CommonJS، والذي يحمله Node كنسختين غير ذي صلة. تصحح المحولات النسخة التي يحملها تطبيقك (والنسخة CommonJS أيضا إذا كان شيء ما قد `require`د بالفعل)، لذا كلا نظامي الوحدات يعمل. إطار **محزم في إخراجك الخاص** بواسطة esbuild أو webpack غير قابل للوصول — استخدم المساعدات في موقع الاستدعاء هناك: `langchainHandler()` و `telemetry()` و `wrapTool()`.
</Note>

### LangChain بدون إصلاح

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

المعالج يعمل مع أو بدون `instrument()` ولا يسجل أبدا مزدوج. `instrument("langchain")` يأخذ `sessionId` و `captureContent` و `includeChains` و `graphCallbacks` و `captureLimit` كما يفعل محول Python؛ `metadata: { failproofai_sdk_session_id }` على استدعاء ينتقي الجلسة لهذا الاستدعاء.

### Vercel AI SDK

صادرات AI SDK وظائف عادية من وحدة ES، وفضاء الاسم لـ ES module غير قابل للتغيير بالمواصفة — لا يوجد مكان للتصحيح. يستخدم نقاط الامتداد التي يوثقها SDK نفسه:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // on ai 7, `telemetry: telemetry({ … })` — the same object, the new name
});
```

هذا هو التكامل الكامل: فترة وكيل واحد، زوج طلب نموذج/رد واحد لكل خطوة مع عدد الرموز، وكل استدعاء أداة. موقع استدعاء واحد يعمل على كل رائد — `ai` 4–6 يقرآن أداة التتبع الذي تحمله، `ai` 7 تكامل الملاحظات.

`instrument("ai")` يفعل نفس العملية على **`ai` 7** في جميع أنحاء العملية: كل استدعاء، من خلال قائمة تكامل الملاحظات العالمية للـ AI SDK، والتي تضيفية وتأخذ لا شيء من أي شخص آخر.

**على `ai` 4–6، `instrument("ai")` لا يسجل أي شيء بحد ذاته، ويسجل تحذيرا واحدا يقول ذلك.** الخطاف على مستوى العملية الوحيد الذي تملكه هذه الإصدارات الرئيسية هو موفر متتبع OpenTelemetry العام — فتحة واحدة يرفض OpenTelemetry تسليمها مرة واحدة اتخذت. تسجيل الخاص بنا سيرفض بصمت `NodeSDK.start()` الخاص بك لاحقا في البدء وإرسال أنماط http/database الخاصة بك إلى متتبع يصدر لا شيء. استخدم `telemetry()` في موقع الاستدعاء أو `wrapModel` هناك. إذا كانت العملية لا تشغل OpenTelemetry خاصة بها، اختر مع `instrument("ai", { registerGlobalTracer: true })`: فإنها ثم تسجل كل استدعاء يمرر `experimental_telemetry: { isEnabled: true }` وتأخذ الفتحة فقط إذا كانت فارغة لا تزال. `registerGlobalTracer: false` يحافظ على الافتراضي ويسكت التحذير.

إذا كنت تفضل لف النموذج مرة واحدة، فإن `wrapModel` يرى استدعاءات النموذج فقط، لأن استدعاءات الأداة تحدث فوق طبقة النموذج. نموذج ملفوف يُستدعى بدون شيء حوله يتم تسجيله كتشغيل خاص به. استدعاء بثي ينغلق كيفما توقف التدفق — `stop_reason: "cancelled"` عندما يلغي المستهلك، `"error"` مع الخطأ عندما يفشل في منتصفه:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

استخدام كليهما على ما يرام: يلاحظ الوسيط أن الاستدعاء يتم تسجيله بالفعل ويتراجع، لذا يتم تسجيل كل استدعاء مرة واحدة.

`functionId` يسمي فترة الوكيل. احتفظ بها منخفضة الكاردينالية — تنزل في `agent_id`، جانب لوحة التحكم الأساسي.

### Next.js

`next build` ينضغط تبعيات الخادم الخاص بك افتراضيا، والإطار المنضغط في البناء هو نسخة `instrument()` لا يمكنها الوصول إليه. لف الإعدادات مرة واحدة واستدعاء `instrument()` من خطاف بدء تشغيل Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` يضيف LangChain و Mastra و LlamaIndex و SDK نفسه إلى `serverExternalPackages` حفظ قائمتك الخاصة. بدونها، `instrument()` يحذر مرة واحدة لكل إطار لا يمكنه الوصول إليه بدلا من الفشل بصمت؛ إذا أدرجت الحزم بنفسك، اضبط `FAILPROOFAI_NEXT_EXTERNALS=1`. تعمل Vercel AI SDK ومساعدات موقع الاستدعاء بأي طريقة. الطريق Edge يحصل على بناء بدون عمليات: الاستيراد من SDK آمن ولا يسجل أي شيء.

### عدد الرموز على استدعاءات البث

API متوافقة OpenAI فقط تبلغ عن الاستخدام على بث عندما يطلب العميل. يطلب LangChain و Vercel AI SDK؛ بالنسبة لـ LlamaIndex مرر `additionalChatOptions: { stream_options: { include_usage: true } }` إلى `OpenAI` LLM، وبالنسبة لـ Mastra بناء النموذج مع تفعيل الاستخدام (على سبيل المثال `createOpenAICompatible({ includeUsage: true })`). وإلا فإن استدعاءات النموذج المبثوثة لا تحمل عدد الرموز.

### المسار

Node ≥ 20.9 و Bun و Deno — كل إطار عمل، كـ ES module وكـ CommonJS، تم اختباره على كل نقطة مقابل تتبع Node. يعمل SDK بجانب مؤشر ترابط `failproofaid` الذي ينقل ما يكتبه.

## وكيلك الخاص — لا إطار عمل

لحلقة وكيل كتبتها بنفسك، أو إطار بدون محول. تصدر الأحداث بنفس API الذي تستخدمه المحولات تحتها، لذا فإن التتبع له نفس الشكل والجودة.

لا تحتاج إلى معرفة كيف يتم تنظيم الوكيل. كل وكيل مبني يدويا بالفعل له ثلاثة أماكن، مهما كانت وظائفه تُسمى، وتلك الثلاثة هي التكامل الكامل:

| مكان | ما يضيفه | ينبعث |
| --- | --- | --- |
| حيث **تشغيل واحد** يبدأ وينتهي | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **الدالة الواحدة التي تستدعي النموذج** | `event.modelRequest` قبل و `event.modelResponse` بعد — كلا النصفين حتى عند الفشل | زوج واحد لكل منعطف نموذج |
| **الدالة الواحدة التي تشغل الأدوات** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

الهوية محيطة: كل شيء داخل `agent()` يهبط على جلسة التشغيل بدون أخذ معرف، ولا يتغير أي شيء آخر في البرنامج — بما في ذلك كل ما يكتبه الوكيل بالفعل إلى قاعدة البيانات الخاصة به.

- **خدمة أو عامل:** مرر معرف الطلب أو الوظيفة الخاص بك كـ `sessionId` بحيث تكون جلسة على لوحة التحكم والسجل في السجلات أو قاعدة البيانات الخاصة بك نفس السلسلة.
- **وكلاء فرعيون:** عش استدعاءات `agent()`. الداخلي ينضم إلى الجلسة مع الخارجي كـ `parent_id`.
- **انبعث الأزواج.** `modelRequest` بدون `modelResponse` هو فترة يعرضها لوحة التحكم كتشغيل إلى الأبد — ومن هنا `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) في المستودع هو الإصدار الكامل القابل للتشغيل: حلقة أداة OpenAI حقيقية مجهزة بالضبط مثل هذا، وتشغيل في CI في كل تغيير كـ ES module و CommonJS.

## التقييمات

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \

```

</Warning>

## ما لن تفعله لعمليتك

| | |
| --- | --- |
| **حجب حلقة الوكيل الخاص بك** | تذهب الأحداث إلى قائمة الانتظار في الذاكرة؛ مؤقت يكتبها. المؤقت غير مرجعي، لذا لا يوقف استيراد هذه الحزمة تشغيل البرنامج النصي. |
| **النمو بدون حد** | تكون قائمة الانتظار محدودة بالعدد **و** بالبايتات المقاسة. بعد أي منهما، يتم التخلص من الأحداث الأقدم وتحذير يقول ذلك — يجب ألا تصبح انقطاعات الملاحظات قتل OOM. |
| **أسقط العملية** | حدث غير قابل للترميز واحد ينخفض وحده وليس الدفعة حوله. المؤشر الرامي والمرجع الدائري و `BigInt` والمحارف البديل الوحيدة: كل واحدة يتم التعامل معها بدلا من نشرها. |
| **اترك دفعة نصف مكتوبة** | المحتوى `fsync`ed قبل إعادة تسمية ذرية، والدليل `fsync`ed بعده، وكتابة فاشلة تنظف ملفها المؤقت. |
| **ترك النصوص قابلة للقراءة** | الدفعات هي `0600` داخل دليل `0700`. تحمل أهداف وموجهات وحجج الأداة وإخراج الأداة. |
| **وكلاء الشحن** | مفاتيح API والرموز و JWTs وعناوين bearer والتعيينات على شكل سري يتم تحديثها قبل أن تصل البايتات إلى القرص. مؤشر الترابط يحدث مرة أخرى قبل التحميل. |
