Python 3.11 أو أحدث. بدون تبعيات وقت التشغيل. هل تستخدم إطار عمل؟ [LangChain و CrewAI و LlamaIndex و Pydantic AI](/ar/start/integrations) توظف نفسها بجرة واحدة.

<Note>
  هناك **TypeScript SDK** أيضًا، والاثنان يكتبان نفس الأحداث في نفس الملف المؤقت. أسطول يحتوي على وكلاء Node و وكلاء Python ينتج مجموعة واحدة من الجلسات، وليس اثنتين. اختر لكل خدمة، وليس لكل شركة.
</Note>

## التثبيت

```bash
pip install failproofai-sdk
```

يتم تثبيت الحزمة باسم `failproofai-sdk` واستيرادها في Python باسم `failproofai_sdk`. الإضافات الإطارية مثل `failproofai-sdk[langgraph]` تثبت الإطار نفسه؛ المحولات دائمًا تأتي في العجلة الأساسية.

## الإعدادات

### رقع OpenTelemetry (اختياري)

قم بتثبيت `opentelemetry-sdk` بشكل منفصل، ثم أرفق المُصدِّر الاختياري:

```python
import failproofai_sdk
from opentelemetry.sdk.trace import TracerProvider

provider = TracerProvider()
failproofai_sdk.instrument("otel", provider=provider)
with provider.get_tracer("my-agent").start_as_current_span(
    "agent", attributes={"gen_ai.operation.name": "invoke_agent"}
):
    pass
provider.force_flush()
```

الإعداد يستخدم مزودك المسجل إذا أغفلت `provider`، وينشئ واحدًا فقط
عندما لا يكون هناك واحد مسجل. يمكنك أيضًا تمرير `failproofai_sdk.OtelSpanExporter()`
مباشرة إلى معالج الزخة الخاص بك. تبقى المُصدِّرات الأخرى بدون تغيير.

يسلم خادم FailproofAI المتصل الصادرات؛ لا يحتاج SDK إلى إعداد شبكة
أو مفتاح أو مستمع محلي. يجب على المسؤول تفعيل
[بلع OpenTelemetry](/ar/agenteye/opentelemetry). `instrument()` بسيط لا يفعل أبدًا
تفعيل OTEL. `uninstrument("otel")` يعطل معالجه فقط.
تحكم آلية التوظيف الخاصة بك بالقبض على المحتوى. اغسل المزود قبل الخروج.
لا يزال SDK يعلن صفر تبعيات وقت تشغيل صعبة ويستورد OpenTelemetry
فقط عند الطلب.

```python
import failproofai_sdk

failproofai_sdk.configure(
    base_dir=None,
    flush_interval=0.5,
    environment="production",
)
```

| المعامل | ما الذي يفعله |
| --- | --- |
| `environment` | التسمية على كل حدث — `production` أو `staging` أو `prod-eu`. الافتراضي هو `dev`. |
| `flush_interval` | عدد مرات كتابة خيط الخلفية إلى القرص، بالثواني. الافتراضي هو `0.5`. |
| `base_dir` | مكان الكتابة. الافتراضي هو الملف المؤقت للخادم، وهو ما تريده ما لم تعرف خلاف ذلك. |

عيّن بمتغير البيئة بدلاً من ذلك:

| المتغير | ما الذي يفعله |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | يعيّن `environment` بدون تغيير الرمز، لعندما تنتمي التسمية إلى النشر بدلاً من التطبيق. معامل `configure()` يفوز عليه. |
| `FAILPROOFAI_HOME` | ينقل جذر Failproof AI الذي يحمل الملف المؤقت. |
| `FAILPROOFAI_SDK_STRICT` | `1` يجعل أخطاء التوظيف ترفع بدلاً من تسجيلها. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` يجعل مشكلة التوافق مع الإطار ترفع بدلاً من التحذير والمتابعة. |

<Warning>
  **لا توجد فواصل في `environment`.** يقسم البلع هذا الحقل على الفواصل لبناء مرشحاته، وتخطي أي حدث يحتوي التسمية على واحد — لذلك يختفي التشغيل بالكامل بصمت. اكتب `prod-eu`، وليس `prod,eu`.

  `configure(environment="prod,eu")` يرفع حتى تكتشف على الفور. `AGENTEYE_ENVIRONMENT` لا يمكن أن يرفع — لا أحد ينادي عليك — لذلك يحذر مرة واحدة ويعود إلى `dev`.
</Warning>

يتم قائمة الانتظار للأحداث في الذاكرة وكتابتها في الخلفية كل `flush_interval` ثانية، مع غسل نهائي عند خروج المترجم. تفقد العملية التي يتم قتلها بقوة أيًا كان لم يتم كتابته بعد.

## الهوية

كل حدث ينتمي إلى جلسة ووكيل. **تملأ النطاقات كليهما**، لذا نادرًا ما تمررهما:

```python
with failproofai_sdk.session():
    with failproofai_sdk.agent("planner"):
        failproofai_sdk.event.tool_use(tool_name="search", tool_call_id="c1")
```

تمرير `session_id` أو `agent_id` بشكل صريح لا يزال يعمل ويفوز. بدون ربط أو تمرير، يرفع الاستدعاء `TypeError` بدلاً من بث حدث Cloud سيرفضه بهدوء.

<Note>
  الهوية تركب على متغيرات السياق. تتبع مهام `asyncio` تلقائيًا، لكن **ليس** خيطًا جديدًا — لف العامل في `failproofai_sdk.propagate()` أو أحداثه تهبط غير مرفقة.
</Note>

## فهرس الأحداث

خمسة عشر طريقة. معظمها يأتي في **أزواج** — تستدعي الفاتح، ثم الأقرب، ويقيس SDK الفجوة.

| | يفتح | يغلق |
| --- | --- | --- |
| **الوكلاء** | `agent_start` | `agent_end` |
| | `agent_pause` | `agent_resume` |
| **النماذج** | `model_request` | `model_response` |
| **الأدوات** | `tool_use` | `tool_result` |
| **الخطافات** | `hook_triggered` | `hook_completed` |
| **البشر** | `human_wait` | `human_input` |

ثلاثة تقف بمفردها: `error` و `human_pause` و `human_interrupt`.

<Accordion title="كل حقل، لكل طريقة" icon="table">

كل طريقة تأخذ أيضًا `session_id` و `agent_id`، والتي تملأ النطاقات لك. أي شيء متروك كـ `None` يتم حذفه بدلاً من إرساله كـ JSON `null`، وكل طريقة ترجع `None`.

| الطريقة | مطلوب | اختياري |
| --- | --- | --- |
| `agent_start` | — | `goal` و `parent_id` |
| `agent_end` | — | `outcome` و `summary` |
| `agent_pause` | `pause_id` | `reason` و `user_id` |
| `agent_resume` | `pause_id` | `reason` و `user_id` |
| `model_request` | — | `model` و `messages` و `system` و `tools` و `request_id` |
| `model_response` | — | `model` و `stop_reason` و `input_tokens` و `output_tokens` و `content` و `role` و `request_id` و `duration_ms` |
| `tool_use` | `tool_name` و `tool_call_id` | `input` |
| `tool_result` | `tool_name` و `tool_call_id` | `output` و `error` |
| `hook_triggered` | `hook_name` و `hook_id` | `trigger_event` و `input` |
| `hook_completed` | `hook_name` و `hook_id` | `outcome` و `output` و `error` |
| `error` | `error_type` و `message` | `traceback` |
| `human_wait` | `input_id` | `prompt` و `options` و `reason` |
| `human_input` | `input_id` | `response` |
| `human_pause` | — | `reason` و `user_id` |
| `human_interrupt` | — | `reason` و `user_id` و `at_step` |

</Accordion>

<Warning>
  لوضع علامة على التشغيل كفشل، يجب أن يكون `outcome` واحدًا من `failed` أو `error` أو `timeout` أو `rejected`. أي شيء آخر — بما في ذلك الفشل القريب `failure` — يعتبر نجاحًا.
</Warning>

## الاقتران والمدة

**قاعدة واحدة: أعطِ الحدث الإغلاق نفس المعرف مثل فاتحه.** هذا ما يزاوجهم، وما يسمح لـ SDK بقياس الفجوة.

| الزوج | مطابق على |
| --- | --- |
| `tool_use` → `tool_result` | `tool_call_id` |
| `hook_triggered` → `hook_completed` | `hook_id` |
| `agent_pause` → `agent_resume` | `pause_id` |
| `human_wait` → `human_input` | `input_id` |
| `model_request` → `model_response` | `request_id` |

**لا تمرر `duration_ms` بنفسك.** يقيسه SDK، وتمريره يرفع `ValueError`.

الاستثناء الوحيد هو `model_response`، حيث تعرف فقط كمية الكمون الحقيقي للمزود. مرر عددًا صحيحًا من الميلي ثانية — يرفع العائم، لأن العمود عدد صحيح 32 بت وسيهبط فارغًا وإلا.

<Accordion title="الحالات الحدية" icon="circle-help">

- **المعرفات تحتاج فقط إلى أن تكون فريدة لكل نوع، لكل جلسة.** استدعاء أداة وخطاف يمكن أن يشاركا واحدًا؛ جلستان تعملان في نفس الوقت يمكن أن تعيد استخدام نفس المعرفات بدون تصادم.
- **لا تقتصر على وكيل.** زوج يفتح تحت وكيل واحد ويغلق تحت آخر لا يزال يطابق — وهي الحالة الطبيعية في الكود متعدد الوكلاء.
- **`request_id` اختياري لكن موصى به.** بدونه، تتطابق أحداث النموذج بترتيب وصولها، لذلك قد يسيء زوج استدعاء متزامن واحد في نفس الوكيل الاقتران.
- **زوج مقسم عبر العمليات** لا يزال يطابق في Cloud، لكن SDK لا يمكنه توقيتها — لا شيء في أي عملية رأى كلا النصفين.
- **في الحد الأقصى 10000 فاتح ينتظر أقرب في نفس الوقت.** بعد ذلك يتم حذف الأقدم، لذلك لا يمكن للتسرب أن ينمو بدون حد.

</Accordion>

## حقولك الخاصة

أي إضافة كلمة مفتاحية تمررها يتم تخزينها مع الحدث:

```python
failproofai_sdk.event.tool_use(
    tool_name="search", tool_call_id="c1",
    fw_tenant="acme", fw_region="eu-west-1",     # your own
)
```

يفضل أنواع JSON إذا كنت تريد الاستعلام عنها لاحقًا. أي شيء آخر — UUID أو datetime أو `Decimal` أو مجموعة أو بايتات أو كائن نموذج — يتم تخزينه كسلسلة نصية.

<Warning>
  **ضع بادئة لأسماء الحقول الخاصة بك.** يتم تطبيق الإضافات أخيرًا، لذلك حقل يسمى `model` أو `tool_name` أو `outcome` يستبدل بصمت الحقل الحقيقي. محولات الإطار تستخدم `fw_`؛ افعل الشيء نفسه ولا يمكن لأي شيء أن يصطدم.

  هذا هو أيضًا لماذا حقل اختياري مكتوب بشكل خاطئ أبدًا يخطئ — فقط يصبح حقل مخصص جديد. إذا كان حقل قياسي مفقودًا في Cloud، تحقق من التهجئة أولاً.
</Warning>

هذه الأسماء الخمسة محجوزة ومرفوضة تمامًا: `timestamp` و `session_id` و `agent_id` و `type` و `environment`.

## التسليم والتحقق

<Tabs>
  <Tab title="لوحة المعلومات">
    في **Observe → Events** تحقق من وجود `agent_start` أولاً و `agent_end` موجود أخيرًا. ثم افتح **Observe → Sessions** وتأكد من ظهور أحداث النموذج والأداة والإنسان والخطاف والخطأ بالترتيب المقصود. استخدم معرف الجلسة كمفتاح استكشاف الأخطاء الأساسي.
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    ```bash
    failproofai flush --wait --timeout 60
    failproofai config --status
    fp sessions --since 1h --env production --session-id <session-id>
    fp events --since 1h --session-id <session-id> --full
    ```
  </Tab>
</Tabs>

إذا كانت Cloud فارغة، افحص `$FAILPROOFAI_HOME/custom-agents/events`، وإلا `~/.failproofai/custom-agents/events`. ملفات JSONL تثبت بث SDK؛ ملف مؤقت متنامي يشير إلى إعدادات الخادم أو التسليم، بينما يشير ملف مؤقت فارغ إلى التوظيف أو عمر العملية.

<Note>
  افحص الملف المؤقت فقط عندما يكون الخادم متوقفًا. بينما يعمل، يجمع ويحذف كل دفعة خلال ميلي ثانية، لذا يتسابق إدراج الدليل مع المجمّع ويظهر أحداثًا أقل بكثير مما تم بثها.
</Note>

## منع الأخطاء في وقت التشغيل المخصص

استخدم النتائج المراجعة والزخ المرتبطة لتحديد الإجراء غير الآمن والأدلة المطلوبة والاستجابة المقصودة. يجب أن تفضي عملية الإنفاذ المخصصة الإجراء قبل التنفيذ وتمرر مدخلاته المنظمة إلى محرك السياسة وتطبق قرار السماح أو الإرشاد أو الرفض الناتج.

[اتصل بـ Failproof AI](mailto:support@befailproof.ai) وسنساعدك على تعيين حدود نموذج وأداة ودورة الحياة في وقت التشغيل إلى خطافات السياسة، ثم التحقق من عملية الدمج معك.
