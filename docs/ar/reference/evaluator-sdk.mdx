يستقبل المقيّم جلسة وكيل مكتملة ويُرجع إشارات الجودة التي تهمك: نقاط رقمية وتفسير لكل نقطة وملخص اختياري. يخزن Failproof AI هذه النتائج بجانب الآثار ويرسمها عبر الوكلاء والبيئات.

الحزمة هي `agenteye-evaluator`، مستوردة كـ `agenteye_evaluator`. تتطلب Python 3.10 أو أحدث وتعتمد على `fastapi` و`pydantic>=2` و`structlog`.

<Warning>
  **`pip install agenteye-evaluator` من PyPI العام ليس مسار التثبيت.** الحزمة منشورة فقط كعنصر إصدار خاص، والاسم غير مطالب به على PyPI العام — قد يسحب التثبيت غير المؤهل حزمة من شخص غريب إلى الخدمة التي تقرأ نصوصك الإنتاجية. استخدم السلم أدناه.
</Warning>

## إعداد مقيّم

<Steps>
  <Step title="تثبيت SDK">
    انزل في السلم وتوقف عند الدرجة الأولى التي تنطبق عليك.

    داخل المستودع الأحادي، حيث يوجد دليل `evaluator-sdk/`:

    ```bash
    pip install ./evaluator-sdk
    ```

    وإلا، من الإصدار الخاص. تُرفق عجلات بـ GitHub Releases على `agenteye-enterprise/releases`، بعلامات `evaluator-sdk/v<version>`، وتحتاج `gh auth login` بالإضافة إلى الوصول إلى هذا المستودع:

    ```bash
    gh release download evaluator-sdk/v<version> \
      --repo agenteye-enterprise/releases --pattern '*.whl'
    pip install ./agenteye_evaluator-*.whl
    ```

    إذا لم ينجح أي منهما، اطلب من جهة الاتصال الخاصة بك في Failproof AI العجلة بدلاً من ارتجال التثبيت.

    `uvicorn` ليس اعتماداً مقصوداً، لذا ثبّت الخادم بشكل منفصل:

    ```bash
    pip install 'uvicorn[standard]'
    ```
  </Step>

  <Step title="حدد ما يجب تقييمه">
    أنشئ `evaluator.py`. يتحقق هذا المثال مما إذا كانت جلسة تحتوي على أي استدعاءات أدوات فاشلة.

    ```python
    import os
    from agenteye_evaluator import Evaluator, EvalResponse

    app = Evaluator(token=os.environ.get("EVALUATOR_TOKEN"))

    @app.config
    def config():
        return {"inactivity_timeout_secs": 1800}

    @app.evaluator
    def evaluate(req):
        tool_errors = sum(
            1 for item in req.events
            if item.event_type == "tool_result" and item.payload.get("error")
        )
        return EvalResponse(
            scores={"tool_reliability": 1.0 if tool_errors == 0 else 0.0},
            reasoning={"tool_reliability": f"{tool_errors} tool errors"},
        )
    ```

    المنشئ الكامل هو `Evaluator(token: str | None = None, *, title: str = "AgentEye Evaluator")`. تتم مقارنة الرمز باستخدام `hmac.compare_digest`؛ `title` هو عنوان تطبيق FastAPI وهو زينة فقط.

    <Warning>
      `token=None` يعطّل المصادقة بالكامل. هذا جيد على جهاز محمول وثقب في الإنتاج، حيث يستقبل الموضوع نصوص جلسات كاملة.
    </Warning>
  </Step>

  <Step title="شغّله واختبره محلياً">
    اضبط رمزاً مشتركاً وابدأ المقيّم وأكد أن نقطة نهايته الصحية تستجيب.

    ```bash
    export EVALUATOR_TOKEN=<shared-token>
    uvicorn evaluator:app --host 0.0.0.0 --port 8080
    ```

    في طرفية أخرى:

    ```bash
    curl http://127.0.0.1:8080/health
    ```

    كل مزخرف يُرجع الدالة دون تغيير، لذا يبقى `evaluate(req)` قابلاً للاستدعاء مباشرة. هذا هو ما يجعل اختبارات الوحدة رخيصة — بناء `EvalRequest` واستدعاء المعالج، بدون HTTP.
  </Step>
</Steps>

## ربط المقيّم بـ Failproof AI

1. انشر المقيّم على عنوان URL HTTPS يمكن الوصول إليه بواسطة Failproof AI Cloud.
2. اضبط `EVALUATOR_ENDPOINT` باستخدام هذا العنوان وعيّن `EVALUATOR_TOKEN` إلى نفس الرمز المستخدم من قبل المقيّم. للسحابة المُدارة، اتصل بـ [support@befailproof.ai](mailto:support@befailproof.ai) لتكوين الاتصال.
3. قم بتشغيل تقييم وأكد أن نقاطه تظهر في Failproof AI.

<Tabs>
  <Tab title="لوحة التحكم">
    افتح جلسة مكتملة ضمن **Observe → Sessions** واختر **Run evaluation** إذا لم يتم تقييمها تلقائياً. راجع الحالة والنقاط والتفسير والملخص في لوحة **Evaluation** الخاصة بالجلسة.

    استخدم **Observe → Evaluations** لمقارنة النقاط عبر الوكلاء أو البيئات. استخدم **Observe → Metrics** لقياسات الكمون والتكلفة والرموز والقياسات الرقمية الأخرى.

    ابدأ بجلسة واحدة للتأكد من أن المقيّم أرجع مفاتيح النقاط المتوقعة وتفسيراً مفيداً لهذا التشغيل المحدد.

    ![عرض تفاصيل جلسة يظهر نقاط التقييم والتفسير بجانب آثاره.](/images/dashboard/session-detail.png)

    بمجرد أن تبدو النتائج الفردية صحيحة، استخدم لوحة تحكم التقييم لمقارنة هذه النقاط بمرور الوقت وعبر الوكلاء أو البيئات.

    ![لوحة تحكم الجودة ترسم نقاط المقيّم بمرور الوقت.](/images/dashboard/dashboard-quality.png)

    يجب أن تستخدم لوحة التحكم السليمة أسماء نقاط مستقرة؛ تغيير المفتاح ينشئ سلسلة منفصلة.
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    ```bash
    fp evals --since 1h --score tool_reliability:0..1
    fp evals --since 24h --aggregate
    ```
  </Tab>
</Tabs>

بالنسبة لمثيل Cloud موزع ذاتياً، يتم تعطيل التقييم التلقائي حتى يتم تعيين `EVALUATOR_ENDPOINT` على عملية الخادم. أعد تشغيل الخادم بعد تغيير متغيرات بيئة المقيّم.

## المزخرفات والمسارات

| المزخرف | المسار | مطلوب |
| --- | --- | --- |
| `@app.evaluator` | `POST /evaluate` | نعم. |
| `@app.job_lookup` | `GET /evaluate/{job_id}` | فقط إذا أرجعت `JobPending` في أي وقت. بدونه، تحصل الاستطلاعات على 404. |
| `@app.config` | `GET /config` | لا، لكن مطلوب لأي جلسة لا تصدر `agent_end` — انظر أدناه. |

كل مزخرف يقبل دالة متزامنة أو غير متزامنة، يُرجعها دون تغيير، ويرفع `ValueError` إذا سجلتها مرتين.

| المسار | المصادقة |
| --- | --- |
| `GET /health` | مفتوح حتى عند تعيين رمز. |
| `POST /evaluate` | Bearer. |
| `GET /evaluate/{job_id}` | Bearer. |
| `GET /config` | Bearer. |

مطابقة نظام Bearer غير حساسة لحالة الأحرف. `GET /config` بدون `@app.config` مسجل يُرجع دائماً `{"default_poll_interval_secs": 10}`، لذا يعلن SDK دائماً عن إيقاع.

يقيّد SDK أجسام طلبات التقييم بـ 25 ميجابايت، تم التحقق منها مقابل `Content-Length` قبل قراءة الجسم. الزيادة على الحد تحصل على 413، وهي 4xx وبالتالي نهائية. يتم تجاهل حقول الطلب المجهولة حتى تبقى الخدمات متوافقة مع نمو عقد الحدث.

<Warning>
  تسجيل `@app.config` باستخدام `inactivity_timeout_secs` هو ما يمكّن الماسح الاحتياطي. بدونه، جلسة لم تصدر `agent_end` — أي شيء مهجور أو متعطل أو لا يزال خاملاً — لا يتم إدراجه للتقييم على الإطلاق. تم حذف قيم الصفر أو أقل.
</Warning>

## أنواع SDK

| النوع | الحقول |
| --- | --- |
| `AgentEvent` | `id`, `ts`, `event_type`, `payload` |
| `EvalRequest` | `schema_version`, `session_id`, `agent_id`, `environment`, `started_at`, `ended_at`, `events` |
| `EvalResponse` | `scores`, `reasoning`, `summary` |
| `JobPending` | `job_id`, `next_poll_secs` |
| `EvaluatorConfig` | `inactivity_timeout_secs`, `default_poll_interval_secs` |

## حقول الطلب والاستجابة

| الحقل | النوع | ملاحظات |
| --- | --- | --- |
| `EvalRequest.schema_version` | `str` | حالياً `"1"`. |
| `session_id`, `agent_id`, `environment` | `str` | هوية الجلسة والبيئة. |
| `started_at` | `datetime` | طابع زمني للحدث الأول. |
| `ended_at` | `datetime \| None` | طابع زمني حدث `agent_end`، وليس "متى توقفت الجلسة". الجلسات المدرجة بواسطة الماسح الاحتياطي لم تكن لديها `agent_end` أبداً وتصل كـ `None`. |
| `events` | `list[AgentEvent]` | تدفق الحدث الكامل والمرتب. |
| `AgentEvent.id` | `int` | معرّف صف حدث الواجهة الخلفية. |
| `AgentEvent.ts` | `datetime` | طابع زمني للحدث. |
| `AgentEvent.event_type` | `str` | عائلة الحدث مثل `tool_use`. |
| `AgentEvent.payload` | `dict[str, Any]` | JSON الحدث بالكامل بشكل مسطح، لذا تجلس الحقول الخاصة بالحدث في المستوى الأعلى و`payload["type"]` يكرر `event_type`. |
| `EvalResponse.scores` | `dict[str, float] \| None` | الأبعاد الرقمية المرسومة في التقييمات. |
| `EvalResponse.reasoning` | `dict[str, str] \| None` | تفسيرات لكل نقطة؛ يجب أن تعكس المفاتيح `scores`. |
| `EvalResponse.summary` | `str \| None` | سرد التقييم الشامل. تم اقتطاعه عند 8192 بايت على جانب الخادم؛ `last_error` عند 2048. |

يستخدم التسلسل `exclude_none`، لذا يتم حذف الحقول غير المعيّنة بدلاً من إرسالها كـ `null`.

<Warning>
  الاشتقاق من مدة من `ended_at` يتعطل على البيانات الحقيقية. كل جلسة يدرجها الماسح الاحتياطي تصل مع `ended_at` معيّن إلى `None`. تحقق منه قبل الطرح.
</Warning>

## أشكال العودة

قد يُرجع معالجك بالضبط واحداً من ثلاثة أشياء. أي شيء آخر هو `TypeError`، والذي يظهر كـ 500.

| العودة | `status` السلك | نهائي |
| --- | --- | --- |
| `EvalResponse(...)` | `done` | نعم — تم تخزين النقاط. |
| `JobPending(job_id=...)` | `pending` | لا — يستطلع الخادم. |
| قاموس خام بـ `status` في `done` أو `pending` أو `error` | كما هو محدد | `error` نهائي. |

حالة `error` ليس لها نموذج مكتوب. للفشل بشكل نهائي يجب أن تُرجع قاموساً خاماً، و`error` يجب أن يكون `str` غير فارغ:

```python
return {"status": "error", "error": "model service unavailable"}
```

<Warning>
  **الرفع ليس الإبلاغ.** الاستثناء يصبح 500 عام جسمه `"evaluator raised an internal error"` — لا يصل نص الاستثناء الخاص بك أبداً إلى الخادم، والخادم يعامل كل 5xx كعابر ويحاول مجدداً. أرجع قاموس `error` عندما تريد تسجيل الفشل.
</Warning>

## عودة العمل غير المتزامن

استخدم `JobPending` عندما لا يمكن إكمال التقييم داخل طلب واحد. معرّف الوظيفة معتم بالنسبة إلى Failproof AI ويجب أن يبقى قابلاً للحل من خلال خدمتك حتى يتم جمع النتيجة أو انتهاء انتظار الخادم.

```python
from agenteye_evaluator import EvalRequest, EvalResponse, Evaluator, JobPending

app = Evaluator(token="shared-secret")

@app.evaluator
def start(req: EvalRequest) -> JobPending:
    job_id = enqueue(req)
    return JobPending(job_id=job_id, next_poll_secs=30)

@app.job_lookup
def lookup(job_id: str):
    result = get_result(job_id)
    if result is None:
        return JobPending(job_id=job_id, next_poll_secs=30)
    return EvalResponse(
        scores=result.scores,
        reasoning=result.reasoning,
        summary=result.summary,
    )
```

يتم اختيار إيقاع الاستطلاع بهذا الترتيب: `JobPending.next_poll_secs`, `EvaluatorConfig.default_poll_interval_secs`، ثم `EVALUATOR_POLLING_INTERVAL_SECS` الخاص بالخادم. يتم تثبيت القيم بين ثانية واحدة وساعة واحدة. الحد الأقصى لساعة الحائط الافتراضي للخادم هو ساعة واحدة، وبعدها يتم تسجيل النتيجة كـ `timeout`.

## إعدادات مشغل الخادم

التقييم التلقائي على نطاق النشر ويبقى معطلاً عندما يكون `EVALUATOR_ENDPOINT` غائباً.

| المتغير | الافتراضي | الغرض |
| --- | --- | --- |
| `EVALUATOR_ENDPOINT` | غير معيّن | عنوان URL الأساسي لخدمة المقيّم. |
| `EVALUATOR_TOKEN` | غير معيّن | رمز Bearer مشترك مع `Evaluator(token=...)`. |
| `EVALUATOR_WORKERS` | `2` | عمال المرسل المتزامن. |
| `EVALUATOR_CLAIM_BATCH` | `4` | جلسات مطالب بها لكل ممر مرسل. |
| `EVALUATOR_POLLING_INTERVAL_SECS` | `10` | إيقاع الاستطلاع غير المتزامن الاحتياطي. |
| `EVALUATOR_REQUEST_TIMEOUT_MS` | `30000` | مهلة المقيّم لكل طلب، تطبق على POST وعلى كل استطلاع. |
| `EVALUATOR_MAX_ATTEMPTS` | `5` | محاولات التسليم قبل الفشل النهائي. |
| `EVALUATOR_CONFIG_REFRESH_SECS` | `300` | إيقاع التحديث لـ `/config`. |
| `EVALUATOR_MAX_POLL_DURATION_SECS` | `3600` | أقصى وقت استطلاع غير متزامن على ساعة الحائط. |

نتيجتان من هذا الجدول تستحق أن تُذكر بوضوح:

- **عمال مرات دفعة المطالبة هي تزامنك.** في الافتراضيات التي تبلغ 8 مكالمات متزامنة ضد نقطة نهايتك، على نطاق النشر. قيّم الخدمة لهذا الرقم، وليس لواحد.
- **4xx نهائي و5xx و429 أو فشل النقل يتم إعادة محاولته** مع التراجع حتى `EVALUATOR_MAX_ATTEMPTS`. عدم تطابق الرمز هو 401، لذا يفشل فوراً بدلاً من إعادة المحاولة — وهذا ما يجب التحقق منه أولاً عندما لا يصل شيء.

يمكن للخادم أيضاً تقييد المنظمات التي تستخدم المقيّم العام للنشر. تعامل مع نقطة النهاية والرمز وإعادة المحاولة وتغييرات بوابة المنظمة كتكوين المشغل وأعد تشغيل الخادم أو قم بدرجه بعد تغييرها.

## الأمان والعمليات

- ضع المقيّم خلف HTTPS عندما يعبر المرور حد الشبكة الموثوق به.
- اضبط رمز bearer غير فارغ واحفظ نسختها متطابقة على كلا الخدمتين. `token=None` يقبل كل مستدع.
- لا تسجل الرمز أو المحفوظات الحساسة الكاملة من أحمال الطلب. لا يفعل SDK: فشل التحقق يُرجع 422 بدون صدى الحمل، 500s لا يصدى نص الاستثناء أبداً، والرمز لا يظهر في أي حقل سجل.
- اجعل المعالجات المتزامنة دعمية؛ قد تكرر المحاولات الطلب.
- استمر في حالة الوظيفة غير المتزامنة خارج ذاكرة العملية في الإنتاج.
- أرجع مفاتيح نقاط مستقرة. إعادة تسمية مفتاح تنشئ سلسلة رسم بياني جديدة بدلاً من تغيير الرسم القديم.

يصدر SDK سجلات دورة حياة منظمة مثل `eval received` و`eval responded` و`job lookup` و`config returned` و`auth rejected` واستثناءات المعالج. استجابات `/config` وسم `source="user"` مقابل `source="default"`، لذا يمكنك معرفة ما إذا تم التقاط `@app.config` الخاص بك. لا تكوّن معالجات السجل؛ استخدم تكوين السجل الخاص بتطبيق المضيف.
