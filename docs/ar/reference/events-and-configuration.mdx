## عائلات الأحداث

- بدء الوكيل وإنهاؤه وإيقافه مؤقتًا واستئنافه
- طلب واستجابة النموذج
- استخدام الأداة والنتيجة
- تفعيل Hook واكتماله
- انتظار الإنسان والإدخال والإيقاف المؤقت والمقاطعة
- الأخطاء الصريحة

يحمل كل حدث طابع زمني ومعرّف الجلسة ومعرّف الوكيل ونوع الحدث والبيئة. تحتوي الحقول الخاصة بالحدث على بيانات النموذج أو الأداة أو الارتباط أو النتيجة أو المحتوى أو المدة أو الخطأ.

## فحص عقد الحدث

<Tabs>
  <Tab title="لوحة التحكم">
    1. افتح **Observe → Events**.
    2. عيّن نافذة زمنية قصيرة وقم بالتصفية حسب البيئة والوكيل ونوع الحدث.
    3. حدد حدثًا لفحص حقوله المعيارية والحمل الأولي، ثم افتح جلسته لرؤية سياق التنفيذ.
    4. إذا كانت المدة المرتبطة مفقودة، تحقق من أن أحداث البدء والاكتمال تستخدم نفس معرّف الارتباط.

    استخدم مجرى الأحداث لتضييق البيانات على تشغيل وكيل واحد وفحص حقول الأحداث المعيارية.

    ![مجرى الأحداث المباشر مع مرشحات للبيئة والوكيل والجلسة ونوع الحدث.](/images/dashboard/events-stream.png)

    ثم اتبع الحدث إلى جلسته. يوضح التتبع ما حدث قبل الحدث وبعده مباشرة، وهذا ضروري عندما يكون الحمل الأولي غامضًا بمفرده.

    ![تتبع الجلسة المرتبط المستخدم لفحص الحدث في سياق التنفيذ.](/images/dashboard/session-detail.png)

    قارن معرّفات الارتباط والطوابع الزمنية عبر كلا العرضين عندما يكون الحدث أو المدة المقترنة مفقودة.
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    اكتشف قيم المرشح الصحيحة، ثم احصل على حمولات الأحداث الكاملة لجلسة واحدة:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    استخدم `fp --json events ... --fields ts,event_type,session_id,payload` للفحص القابل للقراءة الآلية.
  </Tab>
</Tabs>

## حقول SDK المحجوزة

لا تستخدم `timestamp` أو `session_id` أو `agent_id` أو `type` أو `environment` كحقول Python SDK مخصصة. يتم حساب مدد الأحداث المرتبطة مثل مدة نتيجة الأداة من قبل SDK ولا يمكن توفيرها يدويًا.

## الحدود المحلية

- تعيش حالة Failproof AI تحت `~/.failproofai` ما لم يتم تكوينها بشكل صريح بخلاف ذلك.
- يقوم `failproofai-sdk` دائمًا بإعادة التوجيه تحت `~/.failproofai/custom-agents`. ينقل `FAILPROOFAI_HOME` هذا المنزل؛ يتم إلحاق مقطع `custom-agents` دائمًا، وبالتالي لا يمكن وضع التوجيه خارجه. فقط `configure(base_dir=...)` الخاص بـ SDK يكتب في مكان آخر. يتم قراءة `AGENTEYE_HOME` من قبل `agenteye-collector` الأقدم لاختيار ما يجب مراقبته، وليس له تأثير بعد الآن على مكان كتابة SDK.
- يمكن تعيين علامات البيئة من خلال تكوين SDK أو `AGENTEYE_ENVIRONMENT`.
- يتم تخزين بيانات اعتماد Daemon بشكل منفصل عن الإعدادات غير السرية.

استخدم أسماء بيئات مستقرة منخفضة الأساسية. لا يتم دعم الفواصل في علامات بيئة daemon.

## تغيير علامة البيئة

<Tabs>
  <Tab title="لوحة التحكم">
    يتم تعيين علامات البيئة من قبل SDK الذي ينبعث منه أو من Failproof daemon. بعد تغيير واحد، افتح **Observe → Sessions** واستخدم مرشح البيئة للتأكد من أن الجلسات الجديدة تحمل القيمة الجديدة. تحتفظ الجلسات الموجودة ببيئتها الأصلية.

  </Tab>
  <Tab title="واجهة سطر الأوامر">
    بالنسبة إلى `failproofai-sdk`، قم بتكوين البيئة في الكود أو باستخدام متغير البيئة الخاص به. أعد تشغيل تكوين daemon عند تغيير الإعدادات على مستوى الجهاز.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
