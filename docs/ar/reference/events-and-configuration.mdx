## عائلات الأحداث

- بدء الوكيل والإنهاء والإيقاف المؤقت والاستئناف
- طلب النموذج والاستجابة
- استخدام الأداة والنتيجة
- تفعيل hook واكتماله
- انتظار الإنسان والمدخلات والإيقاف المؤقت والمقاطعة
- الأخطاء الصريحة

يحمل كل حدث طابع زمني ومعرّف الجلسة ومعرّف الوكيل ونوع الحدث والبيئة. تحتوي الحقول الخاصة بالحدث على بيانات النموذج والأداة والارتباط والنتيجة والمحتوى والمدة أو الخطأ.

## فحص عقد الحدث

<Tabs>
  <Tab title="لوحة التحكم">
    1. افتح **Observe → Events**.
    2. عيّن نافذة زمنية قصيرة وقم بالتصفية حسب البيئة والوكيل ونوع الحدث.
    3. حدد حدثًا لفحص حقوله المعايرة والحمولة الأولية، ثم افتح جلسته لرؤية سياق التنفيذ.
    4. إذا كانت مدة الزوج مفقودة، تحقق من أن أحداث البدء والإكمال تستخدم نفس معرّف الارتباط.

    استخدم تدفق الأحداث لتضييق البيانات على تشغيل وكيل واحد وفحص حقول الحدث المعايرة.

    ![تدفق الأحداث المباشر مع عوامل تصفية للبيئة والوكيل والجلسة ونوع الحدث.](/images/dashboard/events-stream.png)

    ثم اتبع الحدث إلى جلسته. يوضح التتبع ما حدث قبل وبعده مباشرة، وهو ضروري عندما تكون الحمولة وحدها غامضة.

    ![تتبع الجلسة المرتبط المستخدم لفحص الحدث في سياق التنفيذ.](/images/dashboard/session-detail.png)

    قارن معرّفات الارتباط والطوابع الزمنية عبر كلا العرضين عندما يكون الحدث المقترن أو المدة مفقودة.
  </Tab>
  <Tab title="CLI">
    اكتشف قيم التصفية الصحيحة، ثم جلب حمولات الأحداث الكاملة لجلسة واحدة:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    استخدم `fp --json events ... --fields ts,event_type,session_id,payload` للفحص الذي يمكن قراءته بواسطة الآلة.
  </Tab>
</Tabs>

## حقول SDK المحفوظة

لا تستخدم `timestamp` أو `session_id` أو `agent_id` أو `type` أو `environment` كحقول Python SDK مخصصة. يتم حساب مدات الأحداث المقترنة مثل مدة نتيجة الأداة بواسطة SDK ولا يمكن توفيرها يدويًا.

## الحدود المحلية

- تعيش حالة failproofai ضمن `~/.failproofai` ما لم يتم تكوينها بشكل صريح بخلاف ذلك.
- يستخدم `failproofai-sdk` `AGENTEYE_HOME` لتجاوز الدليل الأساسي الموروث.
- يمكن تعيين تسميات البيئة من خلال تكوين SDK أو `AGENTEYE_ENVIRONMENT`.
- يتم تخزين بيانات اعتماد daemon بشكل منفصل عن الإعدادات غير السرية.

استخدم أسماء بيئات مستقرة وقليلة العدد. الفواصل ليست مدعومة في تسميات بيئة daemon.

## تغيير تسمية البيئة

<Tabs>
  <Tab title="لوحة التحكم">
    يتم تعيين تسميات البيئة بواسطة SDK أو daemon failproofai المُصدِّر. بعد تغيير واحد، افتح **Observe → Sessions** واستخدم عامل تصفية البيئة للتأكد من أن الجلسات الجديدة تحمل القيمة الجديدة. تحتفظ الجلسات الموجودة بالبيئة الأصلية.

  </Tab>
  <Tab title="CLI">
    بالنسبة إلى `failproofai-sdk`، قم بتكوين البيئة في الكود أو باستخدام متغير البيئة الموروث. أعد تشغيل تكوين daemon عند تغيير الإعدادات على مستوى الآلة.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
