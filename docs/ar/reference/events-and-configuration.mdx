## عائلات الأحداث

- بدء الوكيل وإنهاؤه وإيقافه واستئناؤه
- طلب النموذج والاستجابة
- استخدام الأداة والنتيجة
- تفعيل الخطاف وإكماله
- انتظار الإنسان والمدخلات والإيقاف والمقاطعة
- الأخطاء الصريحة

يحمل كل حدث طابع زمني ومعرف جلسة ومعرف وكيل ونوع حدث وبيئة. تحتوي الحقول الخاصة بالحدث على بيانات النموذج والأداة والارتباط والنتيجة والمحتوى والمدة أو الخطأ.

## فحص عقد الحدث

<Tabs>
  <Tab title="لوحة التحكم">
    1. افتح **Observe → Events**.
    2. عيّن نافذة زمنية قصيرة وصفّي حسب البيئة والوكيل ونوع الحدث.
    3. حدد حدثًا لفحص حقوله المعايرة وحمله الخام، ثم افتح جلسته لرؤية سياق التنفيذ.
    4. إذا كانت مدة مقترنة مفقودة، تحقق من أن أحداث البدء والإكمال تستخدم نفس معرف الارتباط.

    استخدم تدفق الأحداث لتضييق البيانات على تشغيل واحد للوكيل وفحص حقول الحدث المعايرة.

    ![تدفق الأحداث المباشر مع مرشحات البيئة والوكيل والجلسة ونوع الحدث.](/images/dashboard/events-stream.png)

    ثم اتبع الحدث إلى جلسته. يُظهر التتبع ما حدث قبله وبعده مباشرة، وهو ضروري عندما يكون الحمل وحده غير واضح.

    ![تتبع الجلسة المرتبطة المستخدم لفحص الحدث في سياق التنفيذ.](/images/dashboard/session-detail.png)

    قارن معرفات الارتباط والطوابع الزمنية عبر كلا العرضين عندما يكون الحدث المقترن أو المدة مفقودة.
  </Tab>
  <Tab title="CLI">
    اكتشف قيم المرشح الصالحة، ثم جلب حمولات الأحداث الكاملة لجلسة واحدة:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    استخدم `fp --json events ... --fields ts,event_type,session_id,payload` للفحص الذي يمكن قراءته بواسطة الآلة.
  </Tab>
</Tabs>

## حقول SDK المحفوظة

لا تستخدم `timestamp` أو `session_id` أو `agent_id` أو `type` أو `environment` كحقول مخصصة لـ Python SDK. يتم حساب مدد الأحداث المقترنة مثل مدة نتيجة الأداة بواسطة SDK ولا يمكن توفيرها يدويًا.

## الحدود المحلية

- حالة Failproof AI موجودة ضمن `~/.failproofai` ما لم يتم تكوينها صراحة بخلاف ذلك.
- يتم تحويل `failproofai-sdk` دائمًا ضمن `~/.failproofai/custom-agents`. ينقل `FAILPROOFAI_HOME` هذا الموقع؛ يتم إلحاق قطاع `custom-agents` دائمًا، لذلك لا يمكن وضع التحويل خارجه. فقط `configure(base_dir=...)` الخاص بـ SDK يكتب في مكان آخر. يتم قراءة `AGENTEYE_HOME` بواسطة `agenteye-collector` الأقدم لاختيار ما يجب مراقبته، ولم تعد تؤثر على مكان كتابة SDK.
- يمكن تعيين تسميات البيئة من خلال تكوين SDK أو `AGENTEYE_ENVIRONMENT`.
- يتم تخزين بيانات اعتماد Daemon بشكل منفصل عن الإعدادات غير السرية.

استخدم أسماء بيئة مستقرة وذات عددية منخفضة. الفواصل غير مدعومة في تسميات بيئة daemon.

## تغيير تسمية البيئة

<Tabs>
  <Tab title="لوحة التحكم">
    يتم تعيين تسميات البيئة بواسطة SDK أو Failproof daemon الباعث. بعد تغيير أحدها، افتح **Observe → Sessions** واستخدم مرشح البيئة للتأكد من أن الجلسات الجديدة تحمل القيمة الجديدة. تحتفظ الجلسات الموجودة ببيئتها الأصلية.

  </Tab>
  <Tab title="CLI">
    بالنسبة لـ `failproofai-sdk`، قم بتكوين البيئة في الكود أو باستخدام متغير البيئة الموروث الخاص به. أعد تشغيل تكوين daemon عند تغيير إعدادات مستوى الجهاز.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
