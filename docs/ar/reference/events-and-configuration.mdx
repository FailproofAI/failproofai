## مفردات الأحداث

يحمل Failproof AI نوعين مختلفين من الأحداث، ولا تشترك أسماؤهما أبداً.

| المفردات | ينتج عن | تبدو الأسماء مثل | المرجع |
| --- | --- | --- | --- |
| أحداث القياس | `failproofai-sdk`، من داخل وكيلك | `tool_use`, `tool_result`, `hook_triggered`, `model_response` | [Python SDK](/ar/reference/custom-agents) |
| أحداث الـ Hook | عامل الوكيل، معياري بواسطة failproofai | `PreToolUse`, `PostToolUse`, `Stop`, `UserPromptSubmit` | [Custom policies](/ar/reference/policy-sdk#choose-the-event) |

يوحد جانب الـ hook أسماء الأحداث الخاصة بكل عامل إلى 29 نوعاً قانونياً. يحتوي جانب القياس على 15 طريقة وعقدها الخاص. `hook_triggered` و `PreToolUse` ليسا تهجئتين لشيء واحد.

## عائلات الأحداث

- بدء الوكيل والإنهاء والإيقاف المؤقت والاستئناف
- طلب الموديل والاستجابة
- استخدام الأداة والنتيجة
- تشغيل الـ hook واكتماله
- انتظار الإنسان والإدخال والإيقاف المؤقت والمقاطعة
- الأخطاء الصريحة

يحمل كل حدث طابعاً زمنياً ومعرف جلسة ومعرف وكيل ونوع حدث وبيئة. تحتوي الحقول الخاصة بالحدث على موديل أو أداة أو ارتباط أو نتيجة أو محتوى أو مدة أو بيانات الخطأ.

## فحص عقد الحدث

<Tabs>
  <Tab title="Dashboard">

    2. عيّن نافذة زمنية قصيرة وقيّد حسب البيئة والوكيل ونوع الحدث.
    3. اختر حدثاً لفحص حقوله المعيارية والحمل الخام، ثم افتح جلسته لرؤية سياق التنفيذ.
    4. إذا كانت المدة المقترنة مفقودة، تحقق من أن أحداث البدء والإكمال تستخدم نفس معرف الارتباط.

  </Tab>
  <Tab title="CLI">

## حقول SDK المحفوظة

تم رفض خمسة أسماء بشكل مطلق كحقول مخصصة، لأن SDK يعينها على كل حدث:

`timestamp`, `session_id`, `agent_id`, `type`, `environment`.

يتم قبول أحد عشر آخر لكن يتم التحقق من النوع، لأن نقطة نهاية الاستيعاب تستخرجها من الحمل إلى أعمدة مكتوبة وتخزن بصمت `NULL` لأي شيء من النوع الخاطئ. يرفع SDK بدلاً من ذلك، في موقع الاستدعاء حيث لا يزال بإمكانك رؤية ما أنتج القيمة.

| الأسماء | النوع المطلوب |
| --- | --- |
| `duration_ms`, `input_tokens`, `output_tokens` | `int`، ضمن النطاق الموجب 32 بت. يرفع العوم أو العدد المنطقي. |
| `tool_name`, `tool_call_id`, `hook_name`, `hook_id`, `input_id`, `pause_id`, `error_type`, `model` | `str`. ترفع `None`، لأن الصف سيصل إلى 200 OK وسيكون غير مرئي لكل مرشح على هذا الحقل. |

### المدد

يقيس SDK الفجوة بين أربعة أحداث مقترنة ويرفض `duration_ms` الذي تمرره بنفسك: `tool_use` → `tool_result`, `hook_triggered` → `hook_completed`, `agent_pause` → `agent_resume`, و `human_wait` → `human_input`.

`model_response` استثناء. لا يقيس SDK استدعاءات الموديل، لذا تمرر `duration_ms` بنفسك، كرقم صحيح بالميلي ثانية. انظر [قواعد الارتباط](/ar/reference/custom-agents) لمعرفة كيفية مطابقة زوج.

## الحدود المحلية

- تعيش حالة Failproof AI تحت `~/.failproofai` ما لم يتم تكوينها بشكل صريح بخلاف ذلك.
- تُكرّر `failproofai-sdk` دائماً تحت `~/.failproofai/custom-agents`. `FAILPROOFAI_HOME` ينقل هذا المنزل؛ يتم دائماً إضافة جزء `custom-agents`، لذا لا يمكن وضع الكسارة خارجه. فقط `configure(base_dir=...)` الخاص بـ SDK يكتب في مكان آخر. يُقرأ `AGENTEYE_HOME` بواسطة `agenteye-collector` الأقدم لاختيار ما يجب مراقبته، وهو لم يعد يؤثر على مكان كتابة SDK.
- بيانات الاعتماد تعيش في `~/.failproofai/credentials.json`، مكتوبة `0600`. لم تكن مقصودة في `config.json`، والتي تُكتب بعملية كتابة عادية وترث الـ umask، لذا تصل قابلة للقراءة من قبل كل مستخدم محلي على الجهاز.

استخدم أسماء بيئة مستقرة وقليلة الأساسية. يتم رفض الفاصلة على كلا الكاتبين: يرفضها الديمون في `collector.environment`، و SDK يرفعها على `configure(environment=...)`. السبب هو نفسه على كلا الجانبين - نقطة نهاية الاستيعاب تقسم هذا الحقل على الفواصل وتتخطى السطر بالكامل، وترد `200 OK` بينما لا تخزن أي شيء.

## تكوين الآلة

إعدادات الديمون غير السرية هي `~/.failproofai/config.json`. لا تحتوي `hooks_verbosity` و `redact` و `environment` على علامة CLI - قم بتحرير الملف مباشرة. يتم كتابة `sessions` و `hooks` و `machine_id` بواسطة `failproofai config` عند توصيل هذه الآلة بـ Cloud.

| المفتاح | القيم | الافتراضي | ما يتحكم فيه |
| --- | --- | --- | --- |
| `collector.sessions` | `true` / `false` | `false`، و `true` بمجرد الاتصال بـ Cloud | شحن نسخ جلسات الوكيل. تحمل النسخة الموجهات ومحتويات الملفات وأي شيء تم لصقه في طرفية. |
| `collector.hooks` | `true` / `false` | `true` | شحن نشاط الـ hook. يحمل القرارات وأسماء الأدوات، لا يحمل محتويات الملفات أبداً. |
| `collector.hooks_verbosity` | `all` / `decisions` / `off` | `decisions` | تحتفظ `decisions` بكل إنكار وتوجيه دقيق وتجمع ما يقرب من 99٪ الذي يسمح. |
| `collector.redact` | `minimal` / `off` | `minimal` | يتم تطبيق المسح قبل ترك أي شيء الجهاز. |
| `collector.environment` | أي سلسلة بدون فاصلة | `local` | التصنيف المختوم على كل حدث ترسله هذه الآلة. |
| `collector.machine_id` | أي سلسلة | معرّف موجود بالفعل على القرص، وإلا معرّف UUID عشوائي جديد | الآلة التي يجمع لوحة التحكم بيانات هذه تحتها. مكتوب بواسطة `--machine-id`. لا يتم اشتقاقه أبداً من اسم المضيف. |

<Note>
  `failproofai backfill --help` يسمي `~/.failproofai/config.toml`. هذا مسار قديم من تخطيط منزل سابق؛ لا يكتبه أي بناء حالي. الملف هو `config.json`.
</Note>

يرسل الاتصال بـ Cloud قرارات السياسة ونسخ الجلسة الكاملة.

<Warning>
  لا يقوم `--no-transcripts` بإيقاف النسخ على مسار الإعداد. `failproofai config --token <key> --no-transcripts` يحلل العلامة ثم لا يقرأها أبداً، والمعالج يتصل بالجلسات بغض النظر، لذا تستمر النسخ في الشحن بينما تعتقد أنك لم تختر.

  لإرسال القرارات فقط، عيّن `collector.sessions` إلى `false` في `~/.failproofai/config.json` بعد الاتصال:

  ```json
  {
    "collector": {
      "sessions": false
    }
  }
  ```
</Warning>

يتبع الملء الخلفي نفس إعدادات المجمع، لذا لا يرسل أبداً شيئاً تقول لك تكوينك أنك لا تريده. إعادة الإرسال آمنة: المسح حتمي، لذا تُجزأ الحدث المُعاد إرساله بشكل متطابق لإرساله الأول وينهار في الصف الموجود بالفعل.

## غيّر تسمية البيئة

يختم SDK والديمون كل منهما تسميتهما الخاصة، وتُعيّن في أماكن مختلفة.

<Tabs>
  <Tab title="Python SDK">
    عيّنها في الكود أو في بيئة العملية التي تُصدر الأحداث. الافتراضي هو `dev`.

    ```python
    import failproofai_sdk

    failproofai_sdk.configure(environment="production-us-east")
    ```

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    ```

    يُقرأ `AGENTEYE_ENVIRONMENT` فقط بواسطة `failproofai-sdk`. لا يقرأه CLI أو الديمون، لذا لا ينتج عن التصدير أي تغيير في الآلة.
  </Tab>
  <Tab title="Daemon">
    عدّل `collector.environment` في `~/.failproofai/config.json`. الافتراضي هو `local` وليس هناك علامة CLI تعيّنه.

    ```json
    {
      "collector": {
        "environment": "production-us-east"
      }
    }
    ```

    ```bash
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
  <Tab title="Dashboard">
    تُعيّن تسميات البيئة بواسطة SDK الباعث أو ديمون Failproof، لذا لا يوجد شيء يجب تغييره هنا. بعد تغيير واحدة في مصدرها، افتح **Observe → Sessions** واستخدم مرشح البيئة لتأكيد حمل الجلسات الجديدة القيمة الجديدة. تحتفظ الجلسات الموجودة ببيئتها الأصلية.
  </Tab>
</Tabs>
