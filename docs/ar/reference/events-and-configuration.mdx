## عائلات الأحداث

- بدء الوكيل وإنهاؤه والإيقاف المؤقت واستئناف التشغيل
- طلب النموذج والاستجابة
- استخدام الأداة والنتيجة
- تشغيل الخطاف واكتماله
- انتظار الإنسان والإدخال والإيقاف المؤقت والمقاطعة
- الأخطاء الصريحة

كل حدث يحمل طابع زمني ومعرّف جلسة ومعرّف وكيل ونوع حدث وبيئة. تحتوي الحقول الخاصة بالحدث على بيانات النموذج والأداة والارتباط والنتيجة والمحتوى والمدة أو الخطأ.

## فحص عقد الحدث

<Tabs>
  <Tab title="لوحة المعلومات">
    1. افتح **Observe → Events**.
    2. عيّن نافذة زمنية قصيرة وقم بالتصفية حسب البيئة والوكيل ونوع الحدث.
    3. حدد حدثًا لفحص حقوله المعايرة والحمولة الأولية، ثم افتح جلسته لرؤية سياق التنفيذ.
    4. إذا كانت المدة المقترنة مفقودة، تحقق من أن أحداث البداية والاكتمال تستخدم نفس معرّف الارتباط.

    استخدم تدفق الأحداث لتضييق البيانات إلى تشغيل وكيل واحد وفحص حقول الحدث المعايرة.

    ![تدفق الأحداث المباشر مع عوامل تصفية للبيئة والوكيل والجلسة ونوع الحدث.](/images/dashboard/events-stream.png)

    ثم اتبع الحدث إلى جلسته. يُظهر التتبع ما حدث مباشرة قبله وبعده، وهو ضروري عندما تكون الحمولة وحدها غامضة.

    ![تتبع الجلسة المرتبط المستخدم لفحص الحدث في سياق التنفيذ.](/images/dashboard/session-detail.png)

    قارن معرّفات الارتباط والطوابع الزمنية عبر كلا العرضين عندما يكون حدث مقترن أو مدة مفقودة.
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    اكتشف قيم التصفية الصالحة، ثم احصل على حمولات الأحداث الكاملة لجلسة واحدة:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    استخدم `fp --json events ... --fields ts,event_type,session_id,payload` للفحص الذي يمكن قراءته بواسطة الآلات.
  </Tab>
</Tabs>

## حقول SDK المحجوزة

لا تستخدم `timestamp` أو `session_id` أو `agent_id` أو `type` أو `environment` كحقول Python SDK مخصصة. يتم حساب مدات الأحداث المقترنة مثل مدة نتيجة الأداة بواسطة SDK ولا يمكن توفيرها يدويًا.

## الحدود المحلية

- يعيش Failproof AI تحت `~/.failproofai` ما لم يتم تكوينها بشكل صريح بخلاف ذلك.
- يستخدم `failproofai-sdk` `AGENTEYE_HOME` لتجاوز دليل البداية الخاص به القديم.
- يمكن تعيين تسميات البيئة من خلال تكوين SDK أو `AGENTEYE_ENVIRONMENT`.
- يتم تخزين بيانات اعتماد الخادم بشكل منفصل عن الإعدادات غير السرية.

استخدم أسماء بيئة مستقرة وقليلة الأساسية. الفواصل المنقوطة غير مدعومة في تسميات بيئة خادم Failproof AI.

## تغيير تسمية البيئة

<Tabs>
  <Tab title="لوحة المعلومات">
    يتم تعيين تسميات البيئة بواسطة SDK الباعث أو خادم Failproof AI. بعد تغيير أحدها، افتح **Observe → Sessions** واستخدم عامل تصفية البيئة للتأكد من أن الجلسات الجديدة تحمل القيمة الجديدة. تحتفظ الجلسات الموجودة بالبيئة الأصلية.

  </Tab>
  <Tab title="واجهة سطر الأوامر">
    بالنسبة إلى `failproofai-sdk`، قم بتكوين البيئة في الكود أو باستخدام متغير البيئة القديم الخاص به. أعد تشغيل تكوين الخادم عند تغيير الإعدادات على مستوى الجهاز.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
