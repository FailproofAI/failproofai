ثبّت CLI المحلي باستخدام `npm install -g failproofai`. قم بتشغيله بدون وسائط لفتح لوحة معلومات السياسات المحلية.

تتطلب الحزمة Node.js 20.9 أو أحدث. Bun 1.3 أو أحدث مدعوم للتطوير والتثبيتات من المصدر. `failproofai configure` و `failproofai setup` هما اسماء مستعارة لـ `failproofai config`. `failproofai policy` و `failproofai pack` و `failproofai p` كلها طرق كتابة `failproofai policies` — كانت الحزم والسياسات الفردية ثلاث أوامر لفكرة واحدة والآن هي أمر واحد. الكتابات القديمة لا تزال تعمل، مع استثناءين: `pack list <source>` أصبح الآن `policies show <source>`، و `pack build` أصبح الآن `publish`.

## إعداد جهاز

ثبّت CLI، ثم اقرأ مفتاح الجهاز في الغلاف. `read -s` يأخذه في موجه لا يعكس الصدى، لذا لا يظهر أبداً في أمر:

```bash
npm install -g failproofai
read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
```

ثم قم بإعداد الجهاز واختر ما ينفذه:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

`failproofai config` هو كل الإعداد: يثبّت خدمة `failproofaid` (جذر مرة واحدة — في محطة يطلب كلمة مرور sudo الخاصة بك، ويسأل مجدداً إذا انتهت صلاحيتها قبل انتهاء الإعداد؛ بدون محطة يستخدم `sudo -n` ولا يطالب أبداً)، ويربط الخطافات بكل CLI للعملاء الذي يجده، ويتصل بـ Cloud. بدون محطة — CI، حاوية، عملاء يقودها — يطبّق بدلاً من السؤال، ويخرج برمز 1 إذا كان أي شيء مطلوب منه لم يحدث.

في محطة، تبدأ خطوة **الاتصال بـ Cloud** على جهاز غير متصل بعد **تسجيل الدخول إلى FailproofAI Cloud** مباشرة؛ اضغط Tab للخيارات الأخرى، **لصق مفتاح API** أو **استخدام مفتوح المصدر**. يفتح تسجيل الدخول رابطاً — أو يطبعه عبر SSH أو بدون عرض، لفتحه على أي جهاز — حيث تسجل الدخول أو تقوم بإنشاء حساب، واختر أو أنشئ تنظيماً، وأذن للجهاز؛ تلتقط المحطة الموافقة بنفسها وتظهر من وافق وللتنظيم أي. يتم سك المفتاح فقط عند انتهاء الإعداد، بعد تثبيت الخادم. على جهاز متصل بالفعل بمفتاح يعمل، الخطوة عبارة عن قائمة بـ **الاحتفاظ بالاتصال الحالي** أولاً، لذلك إعادة تشغيل الإعداد لا تفتح متصفحاً بنفسه؛ المفتاح المحفوظ الذي لم يعد يعمل يبدأ تسجيل الدخول مرة أخرى مباشرة، ويقول السبب. يؤدي تسجيل الدخول مرة أخرى إلى إنشاء مفتاح جديد وترك المفتاح القديم يعمل حتى تقوم بإلغاء تفويضه. Cloud من قبل تسجيل دخول المتصفح يقول ذلك ويقدم الخيارات الأخرى.

يختار **لا** سياسات. هذا عمل الأمر الثاني، وبدونه لا تنفذ جهاز معد حديثاً سوى الحراس الذين يعملون دائماً.

يفضل متغير البيئة على `--token`: يمكن قراءة المعامل من سطر الأوامر من `ps` من قبل كل مستخدم على الصندوق. هذا كل ما يحمي المتغير — يهبط مفتاح مكتوب في أي أمر، `export` المضمن، في سجل الغلاف على أي حال، وهذا السبب يُقرأ مع `read -s` أعلاه. في CI، اضبطه من متجر الأسرار والاحتفظ بتتبع الغلاف (`set -x`) إيقاف، أو تتبع المطبوعات ذلك.

<Warning>
  `--connect <url>` يسجل جهازاً **معد بالفعل**. يعود بمجرد نجاح التسجيل — لا يثبّت الخادم ولا يربط أي خطافات. استخدم `failproofai config` العادي (أو `failproofai config --token <key>`) على جهاز لم يتم إعداده بعد، أو سيُقرأ كمتصل أثناء جمع وتنفيذ لا شيء.
</Warning>

قم بتشغيل `failproofai` بدون وسائط لفتح لوحة معلومات السياسات المحلية.

| الأمر | النتيجة |
| --- | --- |
| `failproofai config` | قم بإعداد الجهاز: العملاء، والخادم، و Cloud — قم بتسجيل الدخول عبر المتصفح، أو الصق مفتاحاً، أو ابقَ مفتوح المصدر. كل عميل على الجهاز يحصل أيضاً على مهارة صغيرة `failproofai` تشير إلى [مهارات FailproofAI](https://github.com/FailproofAI/skills) عبر الإنترنت |
| `failproofai config --token <key>` | قم بالإعداد والاتصال في تمريرة واحدة، بدون السؤال. مفتاح يحمل `jev:evaluate` يشغل أيضاً [Jev عبر FailproofAI Cloud](/ar/reference/jev-cloud) في وضع المراقبة، ما لم يكن هناك `jev.json` بالفعل أو تم إعطاء `--no-transcripts` |
| `failproofai config --connect <url>` | سجّل جهازاً **بالفعل** معد — لا خادم، لا خطافات |
| `failproofai config --status` | عرض الاتصال، والخادم، والتسليم، وحالة الإيقاف المؤقت |
| `failproofai policies` | قائمة السياسات المدمجة والمخصصة والاتفاقية والحزمة والمُدارة من Cloud |
| `failproofai policies --install` | ربط الخطافات في CLI للعملاء الخاصة بك. لا يمكّن أي سياسة بمفردها |
| `failproofai policies add <name>` | تمكين سياسة واحدة — مدمجة، أو `<pack-id>:<name>` من حزمة مثبتة |
| `failproofai policies remove <name>` | تعطيل سياسة واحدة، نفس التسمية |
| `failproofai policies --uninstall` | تعطيل السياسات أو إزالة خطافات الحزام |
| `failproofai policies show <owner>/<repo>` | ما تحمله الحزمة، تُقرأ من بيانها الوصفية، قبل أخذها |
| `failproofai policies show <owner>/<repo> --releases` | كل إصدار نشرته، وأيها هنا |
| `failproofai policies add <source>` | ثبّت حزمة سياسة من إصدار GitHub؛ لا يأخذ الوسم الأحدث ويثبّته |
| `failproofai publish` | شحن سياساتك الخاصة كحزمة؛ `--init` يكتب واحد للبدء منه، و `--min-cli-version <version>` يعيّن أقدم CLI قد يثبّته ([فحوصات Jev في حزمة](/ar/policies/publish-a-pack#jev-checks-in-a-pack)) |
| `failproofai policies remove <publisher/name>` | إلغاء تثبيت حزمة |
| `failproofai audit` | مسح سجل العملاء المحلي وفتح عرض التدقيق المحلي |
| `failproofai audit --schedule [days] --email <address>` | جدولة الفحوصات المحلية المتكررة وإرسال النتائج عبر البريد الإلكتروني |
| `failproofai audit --status` | عرض عنوان التقرير والفاصل الزمني والفحص المجدول التالي |
| `failproofai audit --no-schedule` | إيقاف الفحوصات المتكررة بدون حذف سجل التدقيق |
| `failproofai harness list` | قائمة مسارات الالتقاط الإضافية |
| `failproofai otel status` | فحص إعدادات [OpenTelemetry](/ar/reference/otel) الاختيارية |
| `failproofai jev --url <url> --key-stdin` | قم بإعداد Jev في خطوة واحدة؛ يتم أخذ المزود من مضيف عنوان URL |
| `failproofai jev setup --provider <kind> --key-stdin` | دع [Jev](/ar/reference/jev-providers) يحكم على استدعاءات الأدوات من خلال نقطة نهايتك والمفتاح الخاص بك |
| `failproofai jev setup --provider failproofai` | دع Jev يحكم على استدعاءات الأدوات [عبر FailproofAI Cloud](/ar/reference/jev-cloud)، مع مفتاح Cloud هذا الجهاز |
| `failproofai jev setup --mode <m>` | تبديل وضع Jev: `enforce`أو `observe` أو `off` (يحتفظ بالإعدادات، توقف السؤال عن Jev) |
| `failproofai jev status` | عرض إعدادات Jev والأذونات والارتجاعات الأخيرة؛ أبداً المفتاح |
| `failproofai jev test` | أرسل طلب Jev مباشر واحد وأظهر الكمون والإصدار؛ خروج 1 عندما تكون الإجابة متأخرة للخطافات أو خاطئة |
| `failproofai jev models` | قائمة معرّفات النماذج التي `GET <base>/models` يقول أن نقطة النهاية تخدمها |
| `failproofai jev remove` | إيقاف تشغيل Jev؛ تقوم الخطافات بتنفيذ سياسات regex تماماً كما هي |
| `failproofai flush --wait` | توصيل بكرة الحدث الحالية |
| `failproofai backfill --since 30d` | إعادة قراءة السجل الذي تم تمريره مسبقاً |
| `failproofai config --pause [duration]` | إيقاف جلسة محلية واحدة لمدة 30 دقيقة بشكل افتراضي، حتى 8 ساعات |
| `failproofai config --resume` | استئناف جلسة محلية مُيقفة واحدة؛ أضف `--all` لمسح جميع الإيقافات |
| `failproofai update` | إنهاء ترحيلات الحزم وتحديث الخادم |
| `failproofai migrate --dry-run` | معاينة أو تشغيل ترحيلات تخطيط المنزل المعلقة |
| `failproofai uninstall` | إزالة الخطافات، مهارة `failproofai` والخادم قبل إزالة الحزمة |
| `failproofai --version` | اطبع إصدار الحزمة المثبتة |
| `failproofai --help` | عرض الأوامر والاستخدام العام |
| `failproofai help <command>` | عرض خيارات أمر واحد وأمثلة، مثل `failproofai <command> --help` |

## علامات الإعدادات

| العلامة | الاستخدام |
| --- | --- |
| `--token <key>` | قم بالإعداد والاتصال بشكل غير تفاعلي؛ اقرأ أيضاً من `FAILPROOFAI_CLOUD_TOKEN` |
| `--oss` | استخدم مفتوح المصدر بدون اتصال Cloud؛ يُترك اتصال موجود كما هو |
| `--agents <a,b>` | تتبع هذه العملاء، أو `all`، بدون السؤال |
| `--url <url>` | الاتصال في مكان آخر غير `app.befailproof.ai`؛ اقرأ أيضاً من `FAILPROOFAI_CLOUD_URL` |
| `--connect <url>` | سجّل فقط، على جهاز معد بالفعل. تخطي الخادم وكل خطاف |
| `--machine-id <id>` | معرّف الجهاز لـ `--connect`؛ افتراضي لمعرّف مستقر |
| `--machine-label <name>` | بمفردها، أعد تسمية جهاز **متصل بالفعل**؛ لا تقوم أبداً بالإعداد. مع `--token`، اتصل تحت هذا الاسم؛ المفتاح المضبوط فقط في `FAILPROOFAI_CLOUD_TOKEN` غير كافٍ، لأن `--machine-label` بدون `--token` هو إعادة تسمية. مع `--oss` أو `--agents`، أعد تسمية جهاز متصل بالفعل ورفضه قبل الإعداد على جهاز ليس كذلك: `--oss` لا يتصل أبداً، و `--agents` يحتاج إلى مفتاح أو تسجيل دخول Cloud تفاعلي للاتصال |
| `--no-transcripts` | أرسل القرارات بدون محتوى النسخة، ولا تشغّل Cloud Jev، الذي سيرسل كل استدعاء أداة تم فحصها والموجه الأخير؛ يُزال `jev.json` الذي يشغّل Jev عبر FailproofAI Cloud |
| `--disconnect` | إيقاف سحب سياسات Cloud وتسليم الأحداث. إزالة أيضاً مفتاح Jev من Cloud و `jev.json` الذي يسمي FailproofAI Cloud؛ يُترك إعداد Jev الخاص بك في مكانه |
| `--status` | عرض حالة الجهاز الحالية |
| `--pause [duration]` | إيقاف أحدث جلسة في المجلد الحالي؛ يقبل ثواني أو دقائق أو ساعات ويفترض 30 دقيقة |
| `--resume` | إنهاء إيقاف مطابق مبكراً |
| `--session <id>` | استهدف جلسة صريحة للإيقاف أو الاستئناف |
| `--all` | مع `--resume`، أنهِ كل إيقاف نشط |

الإيقافات المحلية توقف السياسات المدمجة والمخصصة والاتفاقية والحزمة لجلسة واحدة. تنتهي دائماً، في الحد الأقصى 8 ساعات بعد الإيقاف الأول في التشغيل، ولا تعطل السياسات المُدارة من Cloud أو `block-failproofai-commands`، التي تكون دائماً قيد التشغيل ولا يمكن تعطيلها أو إيقافها بنفسها. يرفع هذا الحارس الطرق المباشرة التي قد يقف بها عملاء مزودون بأدوات أنفسهم: تشغيل `failproofai config --pause`، أو كتابة ملف الإيقاف تحت `~/.failproofai/state/sessions/`. يقرأ الأوامر، وليس ما يفعله البرنامج النصي عند تشغيله، لذا قد يصل البرنامج النصي الذي يكتبه العميل ثم يشغّله إلى نفس الحالة. يتم فحص ملف الإيقاف بحثاً عن انتهاء صلاحية محدودة وبداية لا تزيد عن دقيقة في المستقبل، وليس لمن كتبه.

## علامات السياسة

| العلامة | الاستخدام |
| --- | --- |
| `--install`, `-i` | ثبّت خطافات الحزام. الأسماء بعده تمكّن تلك السياسات؛ بدونها، لا تغييرات في السياسة |
| `--uninstall`, `-u` | تعطيل السياسات أو إزالة الخطافات |
| `--cli <names...>` | استهدف حزام واحد أو أكثر مدعوم |
| `--scope user\|project\|local\|all` | اختر نطاق التكوين؛ `all` للإلغاء |
| `--beta` | تضمين سياسات بيتا |
| `--custom`, `-c <path>` | مع `--install`، تحقق وحمّل ملف سياسة مخصص؛ قابل للتكرار. `--uninstall -c` يزيل كل ملف سياسة مخصص |
| `--policy`, `--only <a,b>` | ثبّت فقط هذه السياسات من حزمة |
| `--category <x,y>` | ثبّت فقط هذه الفئات من حزمة |
| `--all` | قائمة كل سياسة؛ مع حزمة، ثبّت كلها |
| `--releases` | مع `show`، قائمة إصدارات حزمة وأيها مثبت |

## علامات التسليم والصيانة

| الأمر | العلامات |
| --- | --- |
| `backfill` | `--since <30d\|6m\|1y\|YYYY-MM-DD>`, `--agents <a,b>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` (`-y`) |

### Backfill لكل حزام

`backfill` يعيد إرسال السجل الذي قرأه المجمع بالفعل، على جهاز متصل بـ Cloud. `--since` يعيّن النافذة لمعظم الأحزمة، مع استثناءين:

- **Goose و OpenCode و Devin** ترسل سجلهما الكامل، مهما قال `--since`: سجلهما يعيش في قاعدة بيانات يقرأها المجمع بدون نافذة زمنية، لذا يرسل `--dry-run` بكل الجلسات.
- سجل **Hermes** لا يتم إعادة إرساله بواسطة `backfill`.

يجب تشغيل `failproofai update` بعد `npm install -g failproofai@latest`؛ يقوم بترحيلات تخطيط المنزل، وثبّت ملف الخادم المطابق، ويعيد تشغيل الخدمة. ثم ينقل كل ملف تعريف Hermes الذي يستخدم FailproofAI بالفعل إلى المكون الإضافي الأصلي المرتبط ويطبع سطراً واحداً لكل ملف تعريف. `--no-daemon` يتخطى خطوة الخادم. `update` يخرج غير صفري عندما لا يمكن استبدال الخادم، أو فشل الترحيل، أو لا يمكن ترحيل ملف تعريف Hermes (على سبيل المثال لأن الخادم الذي يعمل لا يمكنه خدمة المكون الإضافي الأصلي، في هذه الحالة يُترك خطافات الغلاف في مكانها).

## مسارات الحزام

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

أسماء الأحزمة المدعومة هي `claude` و `codex` و `copilot` و `cursor` و `opencode` و `pi` و `hermes` و `openclaw` و `factory` و `devin` و `antigravity` و `goose`.

الملصقات ترتب معرّفات العملاء المشتقة عندما يحتوي جذران على نسخ من نفس المشروع. يتم رفض الجذور المتداخلة والملصقات المكررة لمنع الجمع المكرر أو فساد المؤشر. إعادة تكوين المسار الإضافي تُحمّل بدون إعادة تشغيل الخادم.

يمكن لبيئات الحاويات استبدال المسارات الإضافية المكونة للملفات بمتغير مفصول بفواصل مسمى `FAILPROOFAI_<HARNESS>_EXTRA_PATHS`، على سبيل المثال:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## متغيرات البيئة

استخدم ملفات الإعدادات للسلوك الدائم للجهاز. متغيرات البيئة مفيدة بشكل أساسي للحاويات والاختبارات وعملية واحدة.

| المتغير | الاستخدام |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | مفتاح Cloud، بدلاً من `--token`. يفضل هذا: يمكن قراءة المعامل من `ps` من قبل كل مستخدم. اضبطه مع `read -s` أو من متجر سري CI، لا تكتبه أبداً في أمر، الذي يهبط في سجل الغلاف على أي حال |
| `FAILPROOFAI_CLOUD_URL` | عنوان URL لـ Cloud، بدلاً من `--url`. نفس المتغير الذي يقرأه الخادم |
| `FAILPROOFAI_HOME` | نقل تخطيط `~/.failproofai` كاملاً |
| `FAILPROOFAI_LOG_LEVEL` | ضبط مستوى تفاصيل السجل المحلي |
| `FAILPROOFAI_HOOK_LOG_FILE` | اكتب تشخيصات الخطاف إلى ملف مختار |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | تعطيل بيانات المراقبة المجهولة لهذه العملية |
| `FAILPROOFAI_NO_FIRST_RUN=1` | تخطي الإعداد التفاعلي للتشغيل الأول |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | تخطي التدقيق المحلي بعد الإعداد |
| `FAILPROOFAI_LLM_BASE_URL` | تجاوز نقطة نهاية OpenAI المتوافقة المستخدمة بواسطة سياسات LLM |
| `FAILPROOFAI_LLM_API_KEY` | توفير مفتاح API المستخدم بواسطة سياسات LLM |
| `FAILPROOFAI_LLM_MODEL` | تحديد النموذج المستخدم بواسطة سياسات LLM |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | تحديد تحميل وحدة السياسة المخصصة |
| `FAILPROOFAI_NO_DOWNLOAD=1` | رفض جلب الحزم وملفات الخادم؛ ما يتم تثبيته يستمر في التنفيذ |
| `FAILPROOFAI_PACK_BASE_URL` | جلب الحزم من مرآة بدلاً من `github.com` |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | استبدال مسارات التقاط إضافية مكونة لحزام واحد |
| `NO_COLOR` | تعطيل إخراج المحطة الملون |

متغيرات المنزل الخاصة بالعملاء مثل `CLAUDE_PROJECTS_PATH` و `CURSOR_HOME` و `HERMES_HOME` و `OPENCLAW_HOME` تتجاوز حيث تكتشف Failproof AI جلسات محلية لذلك الحزام.

## إيقاف أو إزالة جهاز بأمان

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

إيقاف الجلسة المحلية لا يعطل السياسات المُدارة من Cloud. استعيد نشرات Cloud من **الإصلاح → نشر السياسات** في Cloud عندما تكون المراجعة نفسها هي المشكلة.

قبل إزالة حزمة npm، أزل الخطافات المثبتة والخادم:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

قم بتشغيل `failproofai <command> --help` لتفاصيل خاصة بالإصدار.

<Warning>
  قم بتشغيل `failproofai uninstall` قبل `npm rm -g failproofai`؛ npm لا يزيل خطافات العملاء المثبتة أو مهارة `failproofai` أو خدمة الخادم.
</Warning>
