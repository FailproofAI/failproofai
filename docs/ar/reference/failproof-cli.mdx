ثبّت CLI المحلي باستخدام `npm install -g failproofai`. شغّله بدون معاملات لفتح لوحة تحكم السياسات المحلية.

تتطلب الحزمة Node.js 20.9 أو أحدث. Bun 1.3 أو أحدث مدعوم للتطوير والتثبيتات من المصدر. `failproofai configure` و `failproofai setup` هما أسماء مستعارة لـ `failproofai config`. `failproofai policy` و `failproofai pack` و `failproofai p` هي جميعها نطاقات لـ `failproofai policies` — كانت الحزم والسياسات الفردية ثلاث أوامر لفكرة واحدة والآن هي واحدة فقط. النطاقات القديمة لا تزال تعمل، مع استثناءين: `pack list <source>` أصبح الآن `policies show <source>`، و `pack build` أصبح الآن `publish`.

## إعداد جهاز

ثبّت CLI، ثم اقرأ مفتاح الجهاز في الصدفة. `read -s` يأخذه في موجه لا يعكس، لذلك لا يظهر أبداً في أمر:

```bash
npm install -g failproofai
read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
```

ثم أعِد إعداد الجهاز واختر ما الذي سيطبقه:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

`failproofai config` هو إعداد كامل: يثبّت خدمة `failproofaid` (من root مرة واحدة — في المحطة يطلب كلمة مرور sudo الخاصة بك، ويسأل مرة أخرى إذا انتهت صلاحيتها قبل انتهاء الإعداد؛ بدون محطة يستخدم `sudo -n` ولا يطلب أبداً)، ويوصّل الخطاطيف في كل CLI وكيل يجده، ويتصل بـ Cloud. بدون محطة — CI أو حاوية أو وكيل يقودها — يطبّق بدلاً من السؤال، ويخرج 1 إذا لم يحدث شيء طُلب منه أن يحدث.

في المحطة، تبدأ خطوة **Connect to cloud** على جهاز لم يكن متصلاً بعد **logging in to FailproofAI Cloud** مباشرة؛ اضغط على Tab للخيارات الأخرى، **Paste an API key** أو **Use open source**. يفتح تسجيل الدخول رابطاً — أو يطبعه عبر SSH أو بدون عرض، للفتح على أي جهاز — حيث تقوم بالتسجيل أو تسجيل الدخول واختيار أو إنشاء منظمة وتفويض الجهاز؛ تلتقط المحطة الموافقة بنفسها وتوضح من وافق وعلى أي منظمة. يتم إصدار المفتاح فقط عند انتهاء الإعداد، بعد تثبيت الخادم. على جهاز متصل بالفعل بمفتاح عامل، تكون الخطوة قائمة مع **Keep current connection** أولاً، لذا لا يفتح إعادة تشغيل الإعداد متصفح من تلقاء نفسه؛ مفتاح محفوظ لا يعمل بعد الآن يبدأ تسجيل الدخول مرة أخرى مباشرة، ويقول السبب. يؤدي تسجيل الدخول مرة أخرى إلى إنشاء مفتاح جديد ويترك القديم يعمل حتى تلغيه. Cloud من قبل تسجيل دخول المتصفح يقول ذلك ويقدم الخيارات الأخرى.

يختار **no** سياسات. هذا عمل الأمر الثاني، وبدونه لا تطبّق آلة تم إعدادها حديثاً شيئاً سوى الحارس الذي يعمل دائماً.

فضّل متغير البيئة على `--token`: يمكن قراءة معامل سطر الأوامر من `ps` بواسطة كل مستخدم في الصندوق. هذا هو كل ما يحميه المتغير — مفتاح يُكتب في أي أمر، `export` مضمنة، يظل يهبط في سجل الصدفة، وهذا هو السبب في قراءته باستخدام `read -s` أعلاه. في CI، قم بتعيينه من مخزن المحفوظات وأبقِ تتبع الصدفة (`set -x`) معطلاً، وإلا فإن التتبع يطبعه.

<Warning>
  `--connect <url>` يسجّل جهازاً هو **بالفعل معد مسبقاً**. يعود بمجرد نجاح التسجيل — لا يثبّت الخادم ولا يوصّل أي خطاطيف. استخدم `failproofai config` عادياً (أو `failproofai config --token <key>`) على جهاز لم يتم إعداده بعد، وإلا فسيبدو متصلاً أثناء جمع وتطبيق لا شيء.
</Warning>

شغّل `failproofai` بدون معاملات لفتح لوحة تحكم السياسات المحلية.

| الأمر | النتيجة |
| --- | --- |
| `failproofai config` | أعِد إعداد الجهاز: الوكلاء والخادم و Cloud — سجّل الدخول عبر المتصفح أو الصق مفتاحاً أو ابقَ مفتوح المصدر. كل وكيل على الجهاز يحصل أيضاً على مهارة `failproofai` صغيرة تشير إليه في [مهارات FailproofAI](https://github.com/FailproofAI/skills) على الإنترنت |
| `failproofai config --token <key>` | أعِد الإعداد والاتصال في عملية واحدة، بدون السؤال عن أي شيء. مفتاح يحمل `jev:evaluate` يوّلد أيضاً [Jev عبر FailproofAI Cloud](/ar/reference/jev-cloud) في وضع المراقبة، ما لم يكن `jev.json` موجود بالفعل أو تم إعطاء `--no-transcripts` |
| `failproofai config --connect <url>` | سجّل جهازاً هو **بالفعل** معد — لا خادم، لا خطاطيف |
| `failproofai config --status` | أظهر حالة الاتصال والخادم والتسليم والإيقاف المؤقت |
| `failproofai policies` | اسرد السياسات المدمجة والمخصصة والعرفية والمجمّعة والمُدارة من Cloud |
| `failproofai policies --install` | وصّل الخطاطيف في CLIs الوكيل الخاص بك. لا تمكّن أي سياسة بمفردها |
| `failproofai policies add <name>` | مكّن سياسة واحدة — مدمجة أو `<pack-id>:<name>` من حزمة مثبتة |
| `failproofai policies remove <name>` | عطّل سياسة واحدة، نفس الترقيم |
| `failproofai policies --uninstall` | عطّل السياسات أو أزل خطاطيف الأداة |
| `failproofai policies show <owner>/<repo>` | ما الذي تحمله الحزمة، المقروءة من بيانها الوصفية، قبل أن تأخذها |
| `failproofai policies show <owner>/<repo> --releases` | كل إصدار نشره، وأيهما موجود هنا |
| `failproofai policies add <source>` | ثبّت حزمة سياسات من إصدار GitHub؛ لا يأخذ البطاقة الأحدث ويثبّتها |
| `failproofai publish` | شحن سياساتك الخاصة كحزمة؛ `--init` يكتب واحدة للبدء منها، و `--min-cli-version <version>` يعيّن أقدم CLI قد يثبّتها ([فحوصات Jev في حزمة](/ar/policies/publish-a-pack#jev-checks-in-a-pack)) |
| `failproofai policies remove <publisher/name>` | أزل حزمة |
| `failproofai audit` | امسح سجل الوكيل المحلي وافتح عرض التدقيق المحلي |
| `failproofai audit --schedule [days] --email <address>` | جدول عمليات مسح محلية متكررة ورسالة بريد إلكترونية للنتائج |
| `failproofai audit --status` | أظهر عنوان التقرير والفاصل الزمني والمسح المجدول التالي |
| `failproofai audit --no-schedule` | توقف عمليات المسح المتكررة دون حذف سجل التدقيق |
| `failproofai harness list` | اسرد مسارات الالتقاط الإضافية |
| `failproofai otel status` | فحص إعداد التقارير [OpenTelemetry](/ar/reference/otel) الاختياري |
| `failproofai jev --url <url> --key-stdin` | أعِد إعداد Jev في خطوة واحدة؛ يتم أخذ المزود من مضيف URL |
| `failproofai jev setup --provider <kind> --key-stdin` | دع [Jev](/ar/reference/jev-providers) يحكم على استدعاءات الأدوات من خلال نقطة نهايتك الخاصة والمفتاح |
| `failproofai jev setup --provider failproofai` | دع Jev يحكم على استدعاءات الأدوات [عبر FailproofAI Cloud](/ar/reference/jev-cloud)، بمفتاح Cloud لهذا الجهاز |
| `failproofai jev setup --mode <m>` | بدّل وضع Jev: `enforce` أو `observe` أو `off` (يحتفظ بالإعدادات، يتوقف عن سؤال Jev) |
| `failproofai jev status` | أظهر إعداد Jev وأذوناته والعودة مؤخراً؛ أبداً لا المفتاح |
| `failproofai jev test` | أرسل طلب Jev واحد مباشر وأظهر الكمون والإصدار الخاص به؛ يخرج 1 عندما تكون الإجابة متأخرة للخطاطيف أو خاطئة |
| `failproofai jev models` | اسرد معرفات النموذج التي يقول `GET <base>/models` نقطة النهاية تخدم |
| `failproofai jev remove` | أطفئ Jev؛ تشغيل الخطاطيف السياسات العادية بالضبط كما في السابق |
| `failproofai flush --wait` | سلّم ملف الأحداث الحالي |
| `failproofai backfill --since 30d` | أعِد قراءة السجل الذي تم تمريره مسبقاً |
| `failproofai config --pause [duration]` | أوقف جلسة محلية واحدة لمدة 30 دقيقة بشكل افتراضي، حتى 8 ساعات |
| `failproofai config --resume` | استئنف جلسة محلية معلقة واحدة؛ أضف `--all` لمسح جميع الإيقافات المؤقتة |
| `failproofai update` | أنهِ هجرات الحزم وحدّث الخادم |
| `failproofai migrate --dry-run` | معاينة أو تشغيل هجرات تخطيط المنزل المعلقة |
| `failproofai uninstall` | أزل الخطاطيف ومهارة `failproofai` والخادم قبل إزالة الحزمة |
| `failproofai --version` | اطبع إصدار الحزمة المثبتة |
| `failproofai --help` | أظهر الأوامر والاستخدام العام |

## أعلام الإعدادات

| العلم | الاستخدام |
| --- | --- |
| `--token <key>` | أعِد الإعداد والاتصال بشكل غير تفاعلي؛ اقرأ أيضاً من `FAILPROOFAI_CLOUD_TOKEN` |
| `--url <url>` | اتصل بمكان آخر غير `app.befailproof.ai`؛ اقرأ أيضاً من `FAILPROOFAI_CLOUD_URL` |
| `--connect <url>` | سجّل فقط، على جهاز معد بالفعل. تجاوز الخادم وكل خطاف |
| `--machine-id <id>` | اضبط معرف الجهاز المستقر |
| `--machine-label <name>` | أعد تسمية جهاز **متصل بالفعل**. بمفرده لا يشغّل أبداً الإعداد، لذا أعطه بعد `failproofai config`، وليس أثناء |
| `--no-transcripts` | أرسل القرارات بدون محتوى النصوص الأصلية، ولا تشغّل Cloud Jev، الذي سيرسل كل استدعاء أداة تم فحصه والموجه الأخير؛ يتم إزالة `jev.json` الذي يقوم بتشغيل Jev عبر FailproofAI Cloud |
| `--disconnect` | توقف سحب سياسات Cloud وتسليم الأحداث. يزيل أيضاً مفتاح Cloud Jev و `jev.json` التي تسمي FailproofAI Cloud؛ يتم ترك إعداد Jev الخاص بك في مكانه |
| `--status` | أظهر حالة الجهاز الحالية |
| `--pause [duration]` | أوقف الجلسة الأحدث في المجلد الحالي؛ يقبل الثواني أو الدقائق أو الساعات ويفترض 30 دقيقة بشكل افتراضي |
| `--resume` | أنهِ إيقافاً مطابقاً مبكراً |
| `--session <id>` | استهدف جلسة صريحة للإيقاف المؤقت أو الاستئناف |
| `--all` | مع `--resume`، أنهِ كل إيقاف نشط |

توقف الإيقافات المحلية السياسات المدمجة والمخصصة والعرفية والمجمّعة لجلسة واحدة. تنتهي دائماً ولا تعطّل السياسات المُدارة من Cloud. `block-failproofai-commands` — التي تكون دائماً على وضع التشغيل ولا يمكن تعطيلها أو إيقاف تشغيلها — تمنع وكيل مسجل من استخدام باب الهروب هذا بنفسه.

## أعلام السياسات

| العلم | الاستخدام |
| --- | --- |
| `--install`, `-i` | ثبّت خطاطيف الأداة. تمكّن الأسماء بعده تلك السياسات؛ بدونها، لا توجد تغييرات السياسات |
| `--uninstall`, `-u` | عطّل السياسات أو أزل الخطاطيف |
| `--cli <names...>` | استهدف واحداً أو أكثر من الأدوات المدعومة |
| `--scope user\|project\|local\|all` | اختر نطاق الإعدادات؛ `all` للإلغاء |
| `--beta` | قم بتضمين السياسات التجريبية |
| `--custom`, `-c <path>` | تحقق وحمّل ملف سياسة مخصص؛ قابل للتكرار |

## أعلام التسليم والصيانة

| الأمر | الأعلام |
| --- | --- |
| `backfill` | `--since <30d\|6m\|YYYY-MM-DD>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` |

يجب تشغيل `failproofai update` بعد `npm install -g failproofai@latest`؛ يقوم بهجرات تخطيط المنزل وتثبيت ثنائي الخادم المطابق واستئناف الخدمة. ثم ينقل كل ملف تعريف Hermes الذي يستخدم بالفعل FailproofAI إلى المكوّن الإضافي الأصلي المرتبط ويطبع سطر واحد لكل ملف تعريف. `--no-daemon` تخطي خطوة الخادم. يخرج `update` بقيمة غير صفرية عندما لا يمكن استبدال الخادم أو فشلت الهجرة أو لم يمكن نقل ملف تعريف Hermes (على سبيل المثال لأن الخادم الذي يعمل لا يمكنه خدمة المكوّن الإضافي الأصلي، في هذه الحالة يتم ترك خطاطيف الصدفة الخاصة به في مكانها).

## مسارات الأداة

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

أسماء الأدوات المدعومة هي `claude` و `codex` و `copilot` و `cursor` و `opencode` و `pi` و `hermes` و `openclaw` و `factory` و `devin` و `antigravity` و `goose`.

ملصقات namespace معرفات الوكيل المشتقة عندما يحتوي جذران على نسخ من نفس المشروع. يتم رفض الجذور المتداخلة والملصقات المكررة لمنع التجميع المكرر أو تلف المؤشر. إعادة تكوين المسار الإضافي بدون إعادة تشغيل الخادم.

يمكن لبيئات الحاوية استبدال المسارات الإضافية المُكونة في الملف بمتغير مفصول بفواصل يسمى `FAILPROOFAI_<HARNESS>_EXTRA_PATHS`، على سبيل المثال:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## متغيرات البيئة

استخدم ملفات الإعدادات للسلوك الدائم للجهاز. متغيرات البيئة الأكثر فائدة للحاويات والاختبارات وعملية واحدة.

| المتغير | الاستخدام |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | مفتاح Cloud، بدلاً من `--token`. فضّل هذا: يمكن قراءة المعامل من `ps` بواسطة كل مستخدم. عيّنه باستخدام `read -s` أو من مخزن سري في CI، أبداً لا بكتابة المفتاح في أمر، الذي يهبط في سجل الصدفة على أي حال |
| `FAILPROOFAI_CLOUD_URL` | عنوان URL في Cloud، بدلاً من `--url`. نفس المتغير الذي يقرأه الخادم |
| `FAILPROOFAI_HOME` | نقل التخطيط الكامل لـ `~/.failproofai` |
| `FAILPROOFAI_LOG_LEVEL` | اضبط مستوى تفصيل التسجيل المحلي |
| `FAILPROOFAI_HOOK_LOG_FILE` | اكتب تشخيصات الخطاف في ملف محدد |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | عطّل القياس الخاص بالاستخدام المجهول لهذه العملية |
| `FAILPROOFAI_NO_FIRST_RUN=1` | تجاوز إعداد التشغيل الأول التفاعلي |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | تجاوز التدقيق المحلي بعد الإعداد |
| `FAILPROOFAI_LLM_BASE_URL` | استبدل نقطة النهاية المتوافقة مع OpenAI المستخدمة بواسطة سياسات LLM |
| `FAILPROOFAI_LLM_API_KEY` | وفّر مفتاح API المستخدم بواسطة سياسات LLM |
| `FAILPROOFAI_LLM_MODEL` | اختر النموذج المستخدم بواسطة سياسات LLM |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | ربط تحميل وحدة السياسات المخصصة |
| `FAILPROOFAI_NO_DOWNLOAD=1` | رفض جلب الحزم والثنائيات الخادم؛ ما هو مثبت يبقى معمولاً به |
| `FAILPROOFAI_PACK_BASE_URL` | جلب الحزم من مرآة بدلاً من `github.com` |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | استبدل مسارات الالتقاط الإضافية المُكونة لأداة واحدة |
| `NO_COLOR` | عطّل إخراج المحطة الملون |

متغيرات المنزل الخاصة بالوكيل مثل `CLAUDE_PROJECTS_PATH` و `CURSOR_HOME` و `HERMES_HOME` و `OPENCLAW_HOME` تستبدل حيث يكتشف Failproof AI الجلسات المحلية لتلك الأداة.

## إيقاف أو إزالة جهاز بأمان

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

إيقاف جلسة محلية لا يعطّل السياسات المُدارة من Cloud. استعد نشرات Cloud من خلال سير عمل إنفاذ Cloud عندما تكون عملية الطرح نفسها هي المشكلة.

قبل إزالة حزمة npm، أزل الخطاطيف المثبتة والخادم:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

شغّل `failproofai <command> --help` للحصول على التفاصيل الخاصة بالإصدار.

<Warning>
  شغّل `failproofai uninstall` قبل `npm rm -g failproofai`؛ npm لا يزيل خطاطيف الوكيل المثبتة أو مهارة `failproofai` أو خدمة الخادم.
</Warning>
