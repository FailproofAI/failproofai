التسخيرة هي ما يعمل الوكيل فعلياً بداخله. يدعم Failproof AI اثنتي عشرة منها، في فئتين:

- **واجهات سطر الأوامر الترميزية** (10) — Claude Code، Codex، GitHub Copilot CLI، Cursor، OpenCode، Pi، Factory Droid، Devin CLI، Antigravity CLI، Goose
- **بوابات الدردشة والمساعد** (2) — Hermes (Slack، Telegram، cron)، OpenClaw (مساعد ذاتي الاستضافة)

تنطبق نفس السياسات وسجل الجلسات نفسه بغض النظر عن التسخيرة التي يعمل بها الوكيل. تقوم طبقة محول واحدة بتعيين أسماء الأحداث الأصلية لكل تسخيرة وأسماء الأدوات وحقول إدخال الأدوات على 29 حدثاً قانونياً قبل تشغيل أي سياسة.

وكيل يعمل في **لا واحد** من الاثنا عشر يتم تطعيمه مباشرة باستخدام [Python SDK](/ar/reference/custom-agents). هذا عقد مختلف، ويستحق التوضيح بصراحة: SDK توفر التتبع والجلسات والتقييمات والتدقيق — **لا تفرض السياسات بمفردها.** يتطلب حظر إجراء غير آمن قبل تنفيذه خطاف فرض عند حد أداة وقت التشغيل الخاص بك؛ [تواصل معنا](mailto:support@befailproof.ai) وسنقوم بتعيينها.

| التسخيرة | نطاقات الخطاف المدعومة |
| --- | --- |
| Claude Code | المستخدم، المشروع، المحلي |
| Codex، GitHub Copilot CLI، Cursor، OpenCode، Pi | المستخدم، المشروع |
| Factory Droid، Devin CLI، Antigravity CLI، Goose | المستخدم، المشروع |
| Hermes، OpenClaw | المستخدم |

كل تكامل يقوم بتوحيد أسماء أحداث الخطاف الأصلية وأسماء الأدوات وحقول إدخال الأدوات قبل تشغيل السياسات. يمكن لسياسة فقط أن تعمل على الأحداث التي تكشفها التسخيرة؛ اختبر سلوك نهاية الدور والتعليمات على التسخيرة والإصدار الدقيقين اللذين تنشرهما.

## القدرة على الفرض

تعني "الكتلة" أن القرار الذي أعادته محول التسخيرة الحالي يتم استهلاكه بواسطة التسخيرة المسماة. قد يحل الحظر بعد الأداة محل النتيجة المعروضة للنموذج ولكن لا يمكنه التراجع عن تأثير جانبي للأداة حدث بالفعل.

| التسخيرة | أحداث الحظر المثبتة | تحذيرات المراقبة فقط أو عدم الحظر |
| --- | --- | --- |
| Claude Code | `PreToolUse`، `UserPromptSubmit`، `PermissionRequest`، `Stop`، `SubagentStop`، `PreCompact`، والعديد من أحداث المهمة/الإعدادات | `PostToolUse`، دورة حياة الجلسة، الإخطارات، وأحداث ما بعد الفشل تكون ملاحظة فقط. |
| Codex | `PreToolUse`، `PermissionRequest`، `UserPromptSubmit`، `Stop`، `SubagentStop`، `PostToolUse` | يحل الحظر بعد الأداة محل النتيجة بعد التنفيذ؛ أحداث بداية الجلسة والضغط ملاحظة في المحول الحالي. |
| GitHub Copilot CLI | `PreToolUse`، `UserPromptSubmit`، `PermissionRequest`، `Stop`، `SubagentStop`، `PostToolUse` | يحل الحظر بعد الأداة محل النتيجة بعد التنفيذ؛ أحداث الجلسة والإخطار ملاحظة. |
| Cursor | `PreToolUse`، `UserPromptSubmit`، `Stop` | `PostToolUse` وأحداث الجلسة ملاحظة. |
| OpenCode | `PreToolUse` | أحداث ما بعد الأداة ودورة الحياة ملاحظة؛ معالجة التوقف الحالية هي توجيه لدور لاحق بدلاً من بوابة مثبتة. |
| Pi | `PreToolUse`، `UserPromptSubmit` | أحداث ما بعد الأداة ودورة الحياة ملاحظة؛ توجيه التوقف ينطبق على دور لاحق. |
| Hermes | `PreToolUse` | `deny()` يحظر. `instruct()` لا يوقف الاستدعاء: يعمل، والتوجيه يتم وضعه في بداية نتيجته. قرارات ما بعد الأداة والجلسة وتوقف الوكيل الفرعي ليست بوابات. |
| OpenClaw | `PreToolUse`، `UserPromptSubmit`، `Stop` | أحداث ما بعد الأداة وتوقف الوكيل الفرعي والضغط ملاحظة. |
| Factory Droid | `PreToolUse`، `UserPromptSubmit`، `Stop`، `PreCompact` | قرارات ما بعد الأداة وتوقف الوكيل الفرعي ملاحظة. |
| Devin CLI | `PreToolUse`، `UserPromptSubmit`، `Stop`، `PermissionRequest` مشروط | خطافات الإذن لا تعمل في كل وضع إذن؛ أحداث ما بعد الأداة والجلسة ملاحظة. |
| Antigravity CLI | `PreToolUse`، `Stop` | قرارات موجه المستخدم وما بعد الأداة ملاحظة؛ لا يزال يمكن حقن تعليمات المحث. |
| Goose | `PreToolUse` | أحداث موجه المستخدم وما بعد الأداة والجلسة ملاحظة. يوجد خطاف توقف حظر أصلي في المنطقة الأعلى ولكن لا يتم تثبيته بواسطة المحول الحالي. |

القدرات حساسة للإصدار. أعد الاختبار بعد ترقية CLI الوكيل، خاصة عندما تعتمد سياسة على سلوك المحث أو التوقف أو الإذن أو ما بعد الأداة بدلاً من بوابة قبل الأداة الشائعة.

### الإضافة الأصلية لـ Hermes

يتم دمج Hermes من خلال إضافة أصلية محلية الملف الشخصي بدلاً من أمر shell. يربط التثبيت كل ملف شخصي Hermes افتراضي وسمي `plugins/failproofai` بالإضافة المشحونة في حزمة npm (نسخة حيث لا يمكن إنشاء رابط رمزي)، وتمكينها في ملف الملف الشخصي `config.yaml`، ونقل مدخلات الخطاف الموروثة FailproofAI فقط. لأن الإضافة مرتبطة، `npm install -g failproofai@latest` يحدثها بدون إعادة تثبيت. هذا يتجنب توليد عملية في كل خطاف. تدعم الإضافة Hermes 0.20.0 والإصدارات الأحدث.

خطافات shell الموروثة (المثبتة بواسطة 1.0.5 والإصدارات الأقدم) **لا** تتحقق من مهام Hermes cron: كل تشغيل cron ينشئ نطاق خطاف خاص به، والذي تنضم إليه الإضافة الأصلية وخطافات shell `config.yaml` لا. `failproofai update` ينقل كل ملف شخصي يستخدم بالفعل FailproofAI إلى الإضافة المرتبطة. إذا كانت الخدمة قيد التشغيل لا يمكنها خدمة الإضافة، `update` يترك خطافات shell في المكان ويخرج برقم غير صفري؛ قم بتشغيل `failproofai config` لتحديث الخدمة، ثم `failproofai update` مرة أخرى. تحميل مهام Cron الإضافة على التشغيل التالي؛ أعد تشغيل البوابات والجلسات التفاعلية قيد التشغيل لتحميلها هناك.

على Hermes، `deny()` يحظر الاستدعاء و `instruct()` لا: الاستدعاء يعمل، والتوجيه يتم وضعه في بداية نتيجته — كمفتاح أول، `failproof_policy_reminder`، لنتيجة JSON، أو كخط قيادي `[FailproofAI policy reminder (...)]` — حتى يقرأ النموذج ذلك مع الإخراج، والبرامج النصية التي تحلل النتيجة تستمر في العمل. يتم عرض تذكير السياسة مرة واحدة في كل دور، ويتم الاحتفاظ به قصيراً على نتيجة كبيرة. استخدم `deny()` عندما يجب ألا يحدث إجراء على الإطلاق: `instruct()` لم يعد يوقف الإجراء أولاً. استدعاءات الأدوات المصنوعة من برنامج نصي `execute_code` تضع تذكيرها على نتيجة `execute_code` التي يقرأها النموذج؛ نسخة البرنامج النصي الخاصة به من النتيجة تُترك كما هي. يتم إخبار النموذج بعدم الاقتباس من التذكير في إجاباته.

بناء Hermes بدون برنامج وسيط الإضافة يعود إلى الاحتفاظ بالاستدعاء المطابق مرة واحدة مع "ارشادات سياسة FailproofAI"؛ قد تكرر استجابة النموذج التالية، أو تفعل نفس العمل بأداة أخرى، دون الاحتفاظ بها مرة أخرى.

أسماء الأدوات تطابق عبر إصدارات Hermes: `process_manage`، `cronjob_manage`، و `todo_list` (Hermes 0.21) تعامل مثل `process`، `cronjob`، و `todo` (Hermes 0.20). في كل مرة يحمل Hermes الإضافة، يكتب `heartbeat.json` في دليل الملف الشخصي `plugin-data/agent-plugin-failproofai-5296f299/`، ويسجل إصدار Hermes وسسار الإضافة والإصدار والخطافات التي قبلها Hermes. قم بتشغيل `failproofai config --status` للكشف عن ملف شخصي معطل أو غير كامل أو مكرر أو تم تكوينه حديثاً، أو ملف على خطافات shell الموروثة (يُبلغ عنه باسم "لم يتم فحص مهام Hermes cron").

### إضافة OpenClaw

يحمل OpenClaw FailproofAI كإضافة بوابة في العملية، مسجلة في كل ملف شخصي `openclaw.json`. مثل إضافة Hermes، يطلب خدمة `failproofaid` المحلية لكل حكم على المقبس، لذلك يحتاج إلى خدمة قيد التشغيل: يرفض التثبيت بدونها، وإذا لم تتمكن الخدمة من الإجابة، يتم حظر استدعاءات الأدوات والمحثات ويتم كتابة السبب إلى سجل البوابة. بعد `npm install -g failproofai@latest`، أعد تشغيل بوابة OpenClaw بحيث تحمل الإضافة المحدثة.

### ثقة خطاف Codex

يقوم Codex 0.129 وما بعده بتشغيل خطاف من `~/.codex/hooks.json` فقط بعد الموافقة عليه في `codex` التفاعلي (Hermes، Telegram، cron)؛ حتى ذلك الحين، كل جلسة Codex — بما في ذلك `codex exec` بدون رؤوس — تتخطاه. تعمل الخطافات في إعدادات نظام Codex، `/etc/codex/config.toml` على Linux و macOS، بدون الموافقة.

لذلك عندما `failproofai config` (أو `policies --install --cli codex` في نطاق المستخدم) يمكنه استخدام sudo، يكتب خطافات Codex في `/etc/codex/config.toml`، بين `# >>> failproofai managed hooks >>>` و `# <<< failproofai managed hooks <<<`، ويترك بقية الملف كما كانت. ينطبق الملف على كل حساب على الجهاز. `failproofai uninstall` وإلغاء تحديد Codex في `failproofai config` تأخذ الكتلة مرة أخرى.

بدون sudo، وعلى Windows، تبقى الخطافات في `~/.codex/hooks.json`. `failproofai config` و `failproofai config --status` ثم لا يحسبون Codex كفرض حتى تتم الموافقة على الخطافات، ويقولان كيفية إصلاحها: أعد تشغيل `failproofai config` والسماح بـ sudo، أو افتح `codex` مرة واحدة والموافقة على الخطافات.

## تثبيت الالتقاط وخطافات السياسة

<Tabs>
  <Tab title="لوحة التحكم">
    1. افتح **الإدارة → المفاتيح** وأنشئ مفتاحاً بـ `events:add` و `policies:pull`، مسمى للجهاز أو البيئة.
    2. على الجهاز المستهدف، قم بتوصيل CLI المحلي بالمفتاح المعروض وثبّت خطافات التسخيرة.
    3. ابدأ جلسة وكيل جديدة، ثم أكد أحداث الخطاف والجلسة تحت **الملاحظة → الأحداث**.
    4. افتح **الملاحظة → السياسة** لنفس نطاق الوقت وأكد أن قرار السياسة ينسب إلى الجهاز.

    يبدأ الاتصال بمفتاح الجهاز. تأكد من أنه يتضمن أذونات الابتلاع وتسليم السياسة قبل نسخ سره.

    ![درج مفتاح API الجديد المستخدم لمنح أذونات الابتلاع وتسليم السياسة.](/images/dashboard/key-create.png)

    بعد تثبيت الخطافات، يجب أن يعرض دفق الأحداث أحداثاً جديدة من الجهاز والبيئة التي ربطتها.

    ![دفق الأحداث المباشر المستخدم لتأكيد أن التسخيرة المثبتة حديثاً تقدم التقارير.](/images/dashboard/events-stream.png)

    أخيراً، تحقق من أن قرارات السياسة تُنسب إلى نفس الجهاز. هذا يؤكد أن التسخيرة تقدم تقارير نشاط السياسة بالإضافة إلى أحداث التتبع.

    ![صفحة السياسة المستخدمة للتحقق من قرارات السياسة من التسخيرة المتصلة حديثاً.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    اقرأ مفتاح الجهاز إلى shell. `read -s` يأخذه عند موجه لا يعكس، لذلك لا يظهر أبداً في أمر أو في سجل shell:

    ```bash
    read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
    ```

    ثم قم بإعداد الجهاز — هذا يربط الخطافات لكل تسخيرة مكتشفة، ويثبت الخدمة، ويتصل بـ Cloud:

    ```bash
    failproofai config
    failproofai policies add FailproofAI/policies
    ```

    الإعداد لا يمكّن أي سياسة بمفردها، وهذا ما الأمر الثاني موجود له.

    أو استهدف تسخيرات سميّة ونطاق تكوين:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    يبقى نطاق المشروع مع تكوين الخطاف بمستودع. يغطي نطاق المستخدم العمل عبر المستودعات. Claude Code يدعم أيضاً النطاق المحلي؛ الدعم يختلف حسب التسخيرة ورفض CLI المجموعات غير المدعومة.

    تحقق من الجهاز وأحداثه:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## إضافة مسار جلسة غير افتراضي

<Tabs>
  <Tab title="لوحة التحكم">
    يتم تسجيل المسارات الإضافية على الجهاز، وليس في Cloud. بعد إضافة واحد، افتح **الملاحظة → الجلسات**، وفلتر إلى بيئة الجهاز، وأكد ظهور الجلسات من المسار الجديد. افتح جلسة وتحقق من الوكيل والتسخيرة وطوابع أوقات الأحداث قبل الاعتماد عليها في تدقيق.

    ![قائمة الجلسات مصفاة إلى البيئة التي تستقبل البيانات من مسار الالتقاط الإضافي.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    أضف مساراً مع تسمية اختيارية، ثم افحص المسارات المكونة:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    أزل مساراً باستخدام `failproofai harness remove-path claude checkout`.
  </Tab>
</Tabs>

<Tip>
  قم بتشغيل جلسة جديدة واحدة بعد التثبيت. تحقق من دفق الأحداث المباشر وقرار السياسة الفعلي قبل توسيع النشر.
</Tip>
