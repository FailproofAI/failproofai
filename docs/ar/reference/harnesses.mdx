الخادم هو البيئة التي يعمل فيها الوكيل بالفعل. يدعم Failproof AI اثنا عشر منها، في فئتين:

- **أدوات سطر الأوامر لكتابة الأكواد** (10) — Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Factory Droid, Devin CLI, Antigravity CLI, Goose
- **بوابات الدردشة والمساعدات** (2) — Hermes (Slack, Telegram, cron), OpenClaw (مساعد موثوق بنفسك)

نفس السياسات وسجل الجلسة ذاته ينطبقان على أي خادم يعمل فيه الوكيل. طبقة محول واحدة تحول أسماء الأحداث الأصلية لكل خادم وأسماء الأدوات وحقول إدخال الأدوات إلى 29 حدثاً قياسياً قبل تطبيق أي سياسة.

وكيل يعمل في **لا أحد** من الاثني عشر خادم يتم توظيفه مباشرة باستخدام [Python SDK](/ar/reference/custom-agents). هذا عقد مختلف، ويستحق الإشارة بوضوح: SDK يوفر التتبع والجلسات والتقييمات والتدقيق — **إنه لا يفرض السياسات بمفرده.** منع الإجراء غير الآمن قبل تنفيذه يتطلب خطاف إنفاذ على حدود أداة وقتك؛ [اتصل بنا](mailto:support@befailproof.ai) وسنقوم بتعيينها.

| الخادم | نطاقات الخطاف المدعومة |
| --- | --- |
| Claude Code | المستخدم، المشروع، محلي |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | المستخدم، المشروع |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | المستخدم، المشروع |
| Hermes, OpenClaw | المستخدم |

تقوم كل عملية دمج بتطبيع أسماء أحداث الخطاف الأصلية وأسماء الأدوات وحقول إدخال الأدوات قبل تطبيق السياسات. لا يمكن لأي سياسة التصرف إلا على الأحداث التي يكشفها الخادم؛ اختبر السلوك في نهاية الدور والتعليمات على الخادم والإصدار بالضبط الذي تنشره.

## قدرة الإنفاذ

"البلوك" يعني أن الحكم المرتجع من المحول الحالي يتم استهلاكه بواسطة الخادم المسمى. قد يستبدل الحجب بعد الأداة النتيجة المعروضة للنموذج ولكن لا يمكنه الرجوع في تأثير جانبي للأداة حدث بالفعل.

| الخادم | أحداث الحجب المتحقق منها | تحذيرات الملاحظة فقط أو عدم الحجب |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact`, وعدة أحداث مهمة/إعدادات | `PostToolUse`, دورة حياة الجلسة، الإخطارات، وأحداث ما بعد الفشل قابلة للملاحظة. |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | الحجب بعد الأداة يستبدل النتيجة بعد التنفيذ؛ أحداث بداية الجلسة والضغط قابلة للملاحظة في المحول الحالي. |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | الحجب بعد الأداة يستبدل النتيجة بعد التنفيذ؛ أحداث الجلسة والإخطار قابلة للملاحظة. |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` وأحداث الجلسة قابلة للملاحظة. |
| OpenCode | `PreToolUse` | أحداث ما بعد الأداة ودورة الحياة قابلة للملاحظة؛ معالجة التوقف الحالية عبارة عن إرشاد لدور لاحق وليس بوابة موثوقة. |
| Pi | `PreToolUse`, `UserPromptSubmit` | أحداث ما بعد الأداة ودورة الحياة قابلة للملاحظة؛ إرشاد التوقف ينطبق على دور لاحق. |
| Hermes | `PreToolUse` | أحكام ما بعد الأداة والجلسة وتوقف الوكيل الفرعي ليست بوابات. |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | أحداث ما بعد الأداة والجلسة وتوقف الوكيل الفرعي والضغط قابلة للملاحظة. |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | أحكام ما بعد الأداة وتوقف الوكيل الفرعي قابلة للملاحظة. |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PermissionRequest` مشروط | لا تعمل خطافات الإذن في كل وضع إذن؛ أحداث ما بعد الأداة والجلسة قابلة للملاحظة. |
| Antigravity CLI | `PreToolUse`, `Stop` | أحكام مطالبة المستخدم وما بعد الأداة قابلة للملاحظة؛ يمكن بالتزامن تعليمات الموجه. |
| Goose | `PreToolUse` | أحداث مطالبة المستخدم وما بعد الأداة والجلسة قابلة للملاحظة. خطاف توقف حجب أصلي موجود في الأعلى لكن لا يتم تثبيته بواسطة المحول الحالي. |

القدرات حساسة للإصدار. أعد الاختبار بعد ترقية CLI وكيل، خاصة عندما تعتمد سياسة على سلوك الموجه أو التوقف أو الإذن أو ما بعد الأداة بدلاً من بوابة ما قبل الأداة الشائعة.

## تثبيت خطافات الالتقاط والسياسة

<Tabs>
  <Tab title="لوحة التحكم">
    1. افتح **الإدارة → المفاتيح** وأنشئ مفتاحاً مع `events:add` و `policies:pull`، مسمى للجهاز أو البيئة.
    2. على الجهاز المستهدف، اربط CLI المحلي بالمفتاح المعروض وثبت خطافات الخادم.
    3. ابدأ جلسة وكيل جديدة، ثم أكد أحداث الخطاف والجلسة تحت **مراقبة → الأحداث**.
    4. افتح **مراقبة → السياسة** لنفس نطاق الوقت وأكد أن قرار السياسة يُنسب للجهاز.

    يبدأ الاتصال بمفتاح آلة. تأكد من أنه يتضمن أذونات الهضم وتسليم السياسة قبل نسخ سره.

    ![درج مفتاح API الجديد المستخدم لمنح أذونات هضم الأحداث وتسليم السياسة.](/images/dashboard/key-create.png)

    بعد تثبيت الخطافات، يجب أن يعرض دفق الأحداث أحداثاً جديدة من الجهاز والبيئة التي اتصلت بها.

    ![دفق الأحداث المباشر المستخدم للتأكد من أن خادماً مثبتاً حديثاً يقدم تقارير.](/images/dashboard/events-stream.png)

    أخيراً، تحقق من أن قرارات السياسة تُنسب للجهاز ذاته. هذا يؤكد أن الخادم يقدم تقارير عن نشاط السياسة وكذلك أحداث التتبع.

    ![صفحة السياسة المستخدمة للتحقق من قرارات السياسة من خادم موصول حديثاً.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    ثبت الخطافات لكل خادم مكتشف:

    ```bash
    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>
    failproofai policies --install
    ```

    أو استهدف خوادم بأسماء ونطاق إعدادات:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    يحتفظ نطاق المشروع بتكوين الخطاف مع مستودع. يغطي النطاق ذو المستخدم العمل عبر المستودعات. Claude Code يدعم أيضاً النطاق المحلي؛ يختلف الدعم حسب الخادم ويرفض CLI المجموعات غير المدعومة.

    تحقق من الجهاز وأحداثه:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## أضف مسار جلسة غير افتراضي

<Tabs>
  <Tab title="لوحة التحكم">
    يتم تسجيل المسارات الإضافية على الجهاز، وليس في السحابة. بعد إضافة واحد، افتح **مراقبة → الجلسات**، وصفّي بيئة الجهاز، وأكد ظهور الجلسات من المسار الجديد. افتح جلسة وتحقق من الوكيل والخادم وطوابع زمن الحدث قبل الاعتماد عليها في تدقيق.

    ![قائمة الجلسات المصفاة إلى البيئة التي تتلقى البيانات من مسار التقاط إضافي.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    أضف مساراً مع تسمية اختيارية، ثم فتش المسارات المكونة:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    أزل مساراً باستخدام `failproofai harness remove-path claude checkout`.
  </Tab>
</Tabs>

<Tip>
  قم بتشغيل جلسة واحدة جديدة بعد التثبيت. تحقق من دفق الأحداث المباشر وقرار سياسة فعلي قبل توسيع الطرح.
</Tip>
