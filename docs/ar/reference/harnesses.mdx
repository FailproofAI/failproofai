التسخير هو ما يعمل وكيلك بداخله فعليًا. يدعم Failproof AI اثني عشر منها، في فئتين:

- **واجهات سطر الأوامر للبرمجة** (10) — Claude Code، Codex، GitHub Copilot CLI، Cursor، OpenCode، Pi، Factory Droid، Devin CLI، Antigravity CLI، Goose
- **بوابات الدردشة والمساعدين** (2) — Hermes (Slack، Telegram، cron)، OpenClaw (مساعد موزع ذاتيًا)

تنطبق نفس السياسات والسجل الجلسة نفسه على أي تسخير يعمل فيه الوكيل. تقوم طبقة محول واحدة بربط أسماء الأحداث الأصلية لكل تسخير وأسماء الأدوات ومجالات إدخال الأداة على 29 حدثًا قانونيًا قبل تشغيل أي سياسة.

وكيل يعمل في **لا** واحد من الاثني عشر يتم جهزته مباشرة باستخدام [SDK بايثون](/ar/reference/custom-agents). هذا عقد مختلف، ويستحق أن يُذكر بوضوح: يوفر SDK التتبع والجلسات والتقييمات والتدقيق — **لا ينفذ السياسات بمفرده.** حجب الإجراء غير الآمن قبل تنفيذه يتطلب خطاف فرض عند حد أداة وقت التشغيل الخاص بك؛ [اتصل بنا](mailto:support@befailproof.ai) وسنقوم بتعيينه.

## نطاقات الخطاف

| التسخير | نطاقات الخطاف المدعومة |
| --- | --- |
| Claude Code | المستخدم والمشروع والمحلي |
| Codex و GitHub Copilot CLI و Cursor و OpenCode و Pi | المستخدم والمشروع |
| Factory Droid و Devin CLI و Antigravity CLI و Goose | المستخدم والمشروع |
| Hermes و OpenClaw | المستخدم |

Claude Code هو التسخير الوحيد الذي يحتوي على نطاق **محلي**. لا تحتوي Hermes و OpenClaw على أي تكوين مشروع على الإطلاق — فهي نطاق المستخدم فقط، ويرفض واجهة سطر الأوامر `--scope project` بالنسبة لهما.

يقوم كل تكامل بتوحيد أسماء أحداث الخطاف الأصلية والأداة ومجالات إدخال الأداة قبل تشغيل السياسات. يمكن للسياسة فقط أن تعمل على الأحداث التي يكشفها التسخير؛ اختبر سلوك نهاية الدور والتعليمات على التسخير والإصدار الدقيق الذي تنشره.

## القدرة على الفرض

تعني كلمة "Block" أن الحكم الذي أرجعته محول الوكيل الحالي مستهلك بواسطة التسخير المسمى. قد يحل حجب ما بعد الأداة محل النتيجة المعروضة للنموذج ولكن لا يمكنه التراجع عن تأثير جانبي للأداة حدث بالفعل.

| التسخير | أحداث الحجب المتحققة | ملاحظات الرصد فقط أو عدم الحجب |
| --- | --- | --- |
| Claude Code | `PreToolUse`و `UserPromptSubmit` و `PermissionRequest` و `Stop` و `SubagentStop` و `PreCompact` وعدة أحداث مهمة/تكوين | `PostToolUse` ودورة حياة الجلسة والإخطارات والأحداث اللاحقة للفشل ملاحظاتية. |
| Codex | `PreToolUse` و `PermissionRequest` و `UserPromptSubmit` و `Stop` و `SubagentStop` و `PostToolUse` | يحل حجب ما بعد الأداة محل النتيجة بعد التنفيذ؛ أحداث بداية الجلسة والضغط ملاحظاتية في المحول الحالي. |
| GitHub Copilot CLI | `PreToolUse` و `UserPromptSubmit` و `PermissionRequest` و `Stop` و `SubagentStop` و `PostToolUse` | يحل حجب ما بعد الأداة محل النتيجة بعد التنفيذ؛ أحداث الجلسة والإخطار ملاحظاتية. |
| Cursor | `PreToolUse` و `UserPromptSubmit` و `Stop` | `PostToolUse` وأحداث الجلسة ملاحظاتية. |
| OpenCode | `PreToolUse` | أحداث ما بعد الأداة ودورة الحياة ملاحظاتية؛ معالجة التوقف الحالية هي إرشادات لدور لاحق وليست بوابة متحققة. `PermissionRequest` لا يعمل على الإطلاق. |
| Pi | `PreToolUse` و `UserPromptSubmit` | أحداث ما بعد الأداة ودورة الحياة ملاحظاتية؛ إرشادات التوقف تنطبق على دور لاحق. |
| Hermes | `PreToolUse` | أحكام ما بعد الأداة والجلسة والتوقف الفرعي ليست بوابات. لا يتم تثبيت حدث `Stop`. |
| OpenClaw | `PreToolUse` و `UserPromptSubmit` و `Stop` | أحداث ما بعد الأداة والجلسة والتوقف الفرعي والضغط ملاحظاتية. |
| Factory Droid | `PreToolUse` و `UserPromptSubmit` و `Stop` و `PreCompact` | أحكام ما بعد الأداة والتوقف الفرعي ملاحظاتية. |
| Devin CLI | `PreToolUse` و `UserPromptSubmit` و `Stop` و `PermissionRequest` مشروط | خطاف الإذن لا يعمل في كل وضع إذن؛ أحداث ما بعد الأداة والجلسة ملاحظاتية. |
| Antigravity CLI | `PreToolUse` و `Stop` | أحكام موجه المستخدم وما بعد الأداة ملاحظاتية؛ لا تزال تعليمات الموجه قابلة للحقن. |
| Goose | `PreToolUse` | موجه المستخدم وأحداث ما بعد الأداة والجلسة ملاحظاتية. يوجد خطاف توقف حجب أصلي في الأعلى ولكن لا يتم تثبيته بواسطة المحول الحالي. |

الحدث الغائب من كلا العمودين **لم يتم التحقق منه** — تعامل معه على أنه غير معروف، وليس كحد حجب.

### شروط على بوابة مدرجة

عدة صفوف أعلاه عبارة عن بوابات حقيقية محدودة أو مشروطة مع ذلك. السياسة التي تعتمد على أحدها تحتاج الشرط بقدر الصف.

| التسخير | الحدث | الشرط |
| --- | --- | --- |
| Claude Code | `Stop` و `SubagentStop` | محدود بواسطة `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`، الافتراضي 8. تم التخلص منه في مسارات نهاية الدور |
| Cursor | `Stop` | محدود بواسطة `loop_limit`، الافتراضي 5، ومستهلك فقط عند اكتمال الدور — ترك أو خطأ بدوره يتجاهله |
| Cursor | `Stop` | **لا تقوم أجهزة VM للعميل السحابي بتشغيل خطافات `stop` أو `subagentStop` على الإطلاق.** البوابة تغطي الجلسات المحلية فقط |
| Codex | `SubagentStop` | فقط ThreadSpawn subagents تتفق به؛ كل مصدر فرعي آخر لا يشغل الخطاف أبدًا |
| GitHub Copilot CLI | `SubagentStop` | تم تخطيه تماما للـ `isSidekick` subagents |
| Devin CLI | `PermissionRequest` | لا يطلق أبدًا تحت `--permission-mode dangerous`، وليس أبدًا للأدوات المنسوخة تلقائيًا للقراءة فقط |
| OpenCode | `PermissionRequest` | خطاف ميت: يتم الإعلان عن `permission.ask` وتوثيقه في الأعلى ولكن لا يتم استدعاؤه أبدًا، لذا السياسة لا تعمل حتى |
| Hermes | `Stop` | لا يتم تثبيت حدث `Stop`، بعن قصد. الخمس `require-*-before-stop` المدمجة غير قابلة للتطبيق على Hermes |
| Goose | `Stop` | النتيجة نفسها: لا يتم تثبيت `Stop`، لذا الخمس `require-*-before-stop` المدمجة غير قابلة للتطبيق |

### حيث `instruct()` يتدهور

`deny` ليس الحكم الوحيد الذي تعيده السياسة. `instruct()` يسلم الوكيل توجيهًا ويسمح بالإجراء — لكن ليس كل تسخير لديه قناة لحمله. حيث لا توجد واحدة، يسمح failproofai بالإجراء ويكتب التعليمات إلى stderr لسجلات المشغل؛ النموذج لا يراها.

| التسخير | الأحداث حيث `instruct()` يتدهور إلى ملاحظة stderr |
| --- | --- |
| Hermes | كل حدث |
| Goose | كل حدث |
| Pi | كل حدث باستثناء `Stop` |
| OpenClaw | كل حدث باستثناء `Stop` |
| Factory Droid | كل حدث باستثناء `Stop` |
| Antigravity CLI | كل حدث باستثناء `Stop` و `UserPromptSubmit` |

في كل مكان آخر، يتم إرجاع التعليمات من خلال قناة السياق الإضافية الخاصة بالتسخير.

### الإصدارات التي تم فحص هذه الادعاءات ضدها

الإصدار جزء من الادعاء، وليس حاشية سفلية. أعد الاختبار بعد ترقية عميل الوكيل، خاصة عندما تعتمد السياسة على سلوك الموجه أو التوقف أو الإذن أو ما بعد الأداة بدلاً من بوابة ما قبل الأداة الشائعة.

| --- | --- |
| Claude Code | 2.1.220 |

| GitHub Copilot CLI | 1.0.71، تمت إعادة قراءة بعض مواقع الاتصال في 1.0.68 و 1.0.78 |
| Cursor | cursor-agent 2026.07.16-899851b |
| OpenCode | 1.18.9، تم إعادة التحقق في 1.14.33 |
| Pi | 0.80.10 |
| Hermes | hermes-agent `5771a6e` |

</Warning>

## وضع عميل VS Code

وضع عميل Copilot Chat المدمج في VS Code **ليس تكاملاً ثالث عشر**. يكتشف تكوين الخطاف من `.github/hooks/*.json` و `~/.copilot/hooks/*.json` و `~/.claude/settings.json` — بالضبط المسارات التي تكتبها عمليات التثبيت `copilot` و `claude` بالفعل — ويستخدم نفس عقد deny الذي يشبه Claude. يفرض تثبيت أحدهما بالفعل داخل جلسات وضع عميل VS Code.

الميزة قيد المعاينة وتحتاج إلى اشتراك GitHub Copilot نشط بالإضافة إلى وضع الوكيل.

## تثبيت التقاط وخطافات السياسة

<Tabs>
  <Tab title="لوحة التحكم">
    1. افتح **Administration → Keys** وأنشئ مفتاحًا باستخدام `events:add` و `policies:pull`، باسم الجهاز أو البيئة.
    2. على الجهاز المستهدف، قم بتوصيل CLI المحلي بالمفتاح المعروض.
    3. ابدأ جلسة وكيل جديدة، ثم أكد خطاف الجلسة والأحداث تحت **Observe → Events**.
    4. افتح **Observe → policy** للإطار الزمني نفسه وأكد أن قرار السياسة ينسب إلى الجهاز.

    يبدأ الاتصال بمفتاح جهاز. أكد أنه يتضمن كلا من أذونات الابتلاع وتسليم السياسة قبل نسخ سره.

    ![درج مفتاح API الجديد المستخدم لمنح أذونات الابتلاع وتسليم السياسة.](/images/dashboard/key-create.png)

    بعد تثبيت الخطافات، يجب أن يعرض دفق الأحداث أحداثًا جديدة من الجهاز والبيئة التي قمت بتوصيلها.

    ![دفق الأحداث المباشر المستخدم لتأكيد أن التسخير المثبت حديثًا يقدم التقارير.](/images/dashboard/events-stream.png)

    أخيرًا، تحقق من أن قرارات السياسة تنسب إلى نفس الجهاز. يؤكد هذا أن التسخير يقدم تقارير نشاط السياسة بالإضافة إلى أحداث التتبع.

    ![صفحة السياسة المستخدمة للتحقق من قرارات السياسة من تسخير متصل حديثًا.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    `failproofai config` يصل الخطافات إلى كل عميل وكيل مدعوم يجده، ويثبت الخادم، ويتصل بـ Cloud عند وجود مفتاح:

    ```bash
    failproofai config --token <machine-key>
    failproofai policies add FailproofAI/policies
    ```

    الإعداد لا يختار سياسات، ولهذا السبب يوجد الأمر الثاني.

    لسلك تسخير واحد يدويًا — مع حذف `--cli`، `--install` يكتشف ما هو مثبت ويطالب:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    يحافظ نطاق المشروع على تكوين الخطاف مع المستودع. يغطي نطاق المستخدم العمل عبر المستودعات. تحقق من جدول النطاق أعلاه قبل دمج `--cli` و `--scope`؛ CLI يرفض الزوج غير المدعوم.

    تحقق من الجهاز وأحداثه:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

<Warning>
  في عمليات `copilot -p` بدون رأس التي بدأت من دليل جديد، لم يتم تحميل نطاق المشروع `.github/hooks/failproofai.json`. تعامل مع نطاق المستخدم على أنه نقطة الفرض الموثوقة لـ Copilot في CI حتى يتم التحقق من ذلك بطريقة أخرى.
</Warning>

## إضافة مسار جلسة غير افتراضي

<Tabs>
  <Tab title="لوحة التحكم">
    يتم تسجيل المسارات الإضافية على الجهاز، وليس في Cloud. بعد إضافة واحد، افتح **Observe → Sessions**، صفي حسب بيئة الجهاز، وأكد أن الجلسات من المسار الجديد تظهر. افتح جلسة وتحقق من الوكيل والتسخير وطوابع الوقت للحدث قبل الاعتماد عليها في التدقيق.

    ![قائمة الجلسات المفلترة إلى البيئة التي تتلقى البيانات من مسار الالتقاط الإضافي.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    أضف مسارًا بعلامة اختيارية، ثم تفتش المسارات المكونة:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    أزل مسارًا بـ `failproofai harness remove-path claude checkout`.

    العلامة تسمى معرفات الوكيل المشتقة. يحتفظ موقعا النسخ من نفس المشروع بنفس الرقم المشتق من النص، لذا بدون علامة يندمجان إلى وكيل واحد. يتم رفض الجذور المتداخلة والعلامات المكررة — انظر [مرجع CLI](/ar/reference/failproof-cli) لمعرفة سبب وجود كل رفض.
  </Tab>
</Tabs>

<Tip>
  قم بتشغيل جلسة جديدة واحدة بعد التثبيت. تحقق من دفق الأحداث المباشر وقرار سياسة فعلي قبل توسيع النشر.
</Tip>
