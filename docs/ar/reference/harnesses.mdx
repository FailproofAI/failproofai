يدعم Failproof AI Claude Code و Codex و GitHub Copilot CLI و Cursor و OpenCode و Pi و Hermes و OpenClaw و Factory Droid و Devin CLI و Antigravity CLI و Goose.

| أداة الوصل | نطاقات الخطافات المدعومة |
| --- | --- |
| Claude Code | المستخدم، المشروع، محلي |
| Codex و GitHub Copilot CLI و Cursor و OpenCode و Pi | المستخدم، المشروع |
| Factory Droid و Devin CLI و Antigravity CLI و Goose | المستخدم، المشروع |
| Hermes و OpenClaw | المستخدم |

تقوم كل عملية دمج بتطبيع أسماء أحداث الخطاف الأصلية وأسماء الأدوات وحقول مدخلات الأدوات قبل تشغيل السياسات. يمكن للسياسة أن تعمل فقط على الأحداث التي تكشفها أداة الوصل؛ اختبر سلوك نهاية الدور والتعليمات على أداة الوصل والإصدار المحدد الذي تنشره.

## قدرة الفرض

"الحظر" يعني أن الحكم الذي تعيده محول البيانات الحالي يتم استهلاكه بواسطة أداة الوصل المسماة. قد يستبدل الحظر بعد الأداة النتيجة المعروضة للنموذج لكنه لا يمكنه التراجع عن آثار جانبية للأداة حدثت بالفعل.

| أداة الوصل | أحداث الحظر المُتحقق منها | تحذيرات القراءة فقط أو عدم الحظر |
| --- | --- | --- |
| Claude Code | `PreToolUse` و `UserPromptSubmit` و `PermissionRequest` و `Stop` و `SubagentStop` و `PreCompact` وعدة أحداث متعلقة بالمهام/التكوين | `PostToolUse` ودورة حياة الجلسة والإخطارات وأحداث ما بعد الفشل هي أحداث مراقبة. |
| Codex | `PreToolUse` و `PermissionRequest` و `UserPromptSubmit` و `Stop` و `SubagentStop` و `PostToolUse` | يستبدل الحظر بعد الأداة النتيجة بعد التنفيذ؛ أحداث بداية الجلسة والضغط قابلة للمراقبة في محول البيانات الحالي. |
| GitHub Copilot CLI | `PreToolUse` و `UserPromptSubmit` و `PermissionRequest` و `Stop` و `SubagentStop` و `PostToolUse` | يستبدل الحظر بعد الأداة النتيجة بعد التنفيذ؛ أحداث الجلسة والإخطارات قابلة للمراقبة. |
| Cursor | `PreToolUse` و `UserPromptSubmit` و `Stop` | `PostToolUse` وأحداث الجلسة قابلة للمراقبة. |
| OpenCode | `PreToolUse` | أحداث ما بعد الأداة ودورة الحياة قابلة للمراقبة؛ معالجة التوقف الحالية هي توجيه لدور لاحق بدلاً من بوابة مُتحقق منها. |
| Pi | `PreToolUse` و `UserPromptSubmit` | أحداث ما بعد الأداة ودورة الحياة قابلة للمراقبة؛ توجيه التوقف ينطبق على دور لاحق. |
| Hermes | `PreToolUse` | أحكام ما بعد الأداة والجلسة وإيقاف الوكيل الفرعي ليست بوابات. |
| OpenClaw | `PreToolUse` و `UserPromptSubmit` و `Stop` | أحداث ما بعد الأداة والجلسة وإيقاف الوكيل الفرعي والضغط قابلة للمراقبة. |
| Factory Droid | `PreToolUse` و `UserPromptSubmit` و `Stop` و `PreCompact` | أحكام ما بعد الأداة وإيقاف الوكيل الفرعي قابلة للمراقبة. |
| Devin CLI | `PreToolUse` و `UserPromptSubmit` و `Stop` و `PermissionRequest` شرطي | خطافات الإذن لا تعمل في كل وضع إذن؛ أحداث ما بعد الأداة والجلسة قابلة للمراقبة. |
| Antigravity CLI | `PreToolUse` و `Stop` | أحكام موجه المستخدم وما بعد الأداة قابلة للمراقبة؛ يمكن حقن تعليمات الموجه. |
| Goose | `PreToolUse` | أحداث موجه المستخدم وما بعد الأداة والجلسة قابلة للمراقبة. يوجد خطاف إيقاف حظر أصلي في المنطقة العليا لكنه لم يتم تثبيته بواسطة محول البيانات الحالي. |

القدرات حساسة للإصدار. أعد الاختبار بعد ترقية واجهة سطر الأوامر للوكيل، خاصة عندما تعتمد السياسة على سلوك الموجه أو التوقف أو الإذن أو ما بعد الأداة بدلاً من بوابة ما قبل الأداة الشائعة.

## تثبيت خطافات الالتقاط والسياسة

<Tabs>
  <Tab title="لوحة التحكم">
    1. افتح **Administration → Keys** وأنشئ مفتاحاً يحتوي على `events:add` و `policies:pull` يحمل اسم الجهاز أو البيئة.
    2. على الجهاز المستهدف، قم بربط واجهة سطر الأوامر المحلية بالمفتاح المعروض وثبت خطافات أداة الوصل.
    3. ابدأ جلسة وكيل جديدة، ثم تأكد من خطافها وأحداث الجلسة تحت **Observe → Events**.
    4. افتح **Observe → policy** لنفس النافذة الزمنية وتأكد من أن قرار السياسة منسوب إلى الجهاز.

    يبدأ الاتصال بمفتاح الجهاز. تأكد من أنه يتضمن أذونات الاستقبال وتسليم السياسة قبل نسخ السر.

    ![درج مفتاح API الجديد المستخدم لمنح أذونات استقبال الأحداث وتسليم السياسة.](/images/dashboard/key-create.png)

    بعد تثبيت الخطافات، يجب أن يعرض تيار الأحداث أحداثاً جديدة من الجهاز والبيئة التي قمت بربطها.

    ![تيار الأحداث المباشر المستخدم لتأكيد أن أداة وصل مثبتة حديثاً تقوم بالإبلاغ.](/images/dashboard/events-stream.png)

    أخيراً، تحقق من أن قرارات السياسة منسوبة إلى نفس الجهاز. هذا يؤكد أن أداة الوصل تقوم بالإبلاغ عن نشاط السياسة بالإضافة إلى أحداث التتبع.

    ![صفحة السياسة المستخدمة للتحقق من قرارات السياسة من أداة وصل متصلة حديثاً.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    ثبت الخطافات لكل أداة وصل مكتشفة:

    ```bash
    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>
    failproofai policies --install
    ```

    أو استهدف أدوات وصل مسماة ونطاق تكوين:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    نطاق المشروع يحتفظ بتكوين الخطاف مع المستودع. نطاق المستخدم يغطي العمل عبر المستودعات. Claude Code يدعم أيضاً النطاق المحلي؛ الدعم يختلف حسب أداة الوصل وواجهة سطر الأوامر ترفض المجموعات غير المدعومة.

    تحقق من الجهاز وأحداثه:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## إضافة مسار جلسة غير افتراضي

<Tabs>
  <Tab title="لوحة التحكم">
    يتم تسجيل المسارات الإضافية على الجهاز، وليس في السحابة. بعد إضافة واحد، افتح **Observe → Sessions** وصفي حسب بيئة الجهاز وتأكد من ظهور الجلسات من المسار الجديد. افتح جلسة وتحقق من الوكيل وأداة الوصل وطوابع وقت الأحداث قبل الاعتماد عليها في تدقيق.

    ![قائمة الجلسات المصفاة إلى البيئة التي تستقبل البيانات من مسار الالتقاط الإضافي.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    أضف مساراً مع تسمية اختيارية، ثم تفحص المسارات المكونة:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    أزل مساراً باستخدام `failproofai harness remove-path claude checkout`.
  </Tab>
</Tabs>

<Tip>
  قم بتشغيل جلسة واحدة جديدة بعد التثبيت. تحقق من تيار الأحداث المباشر وقرار سياسة فعلي قبل توسيع النشر.
</Tip>
