أداة التشغيل هي البيئة التي يعمل فيها الوكيل بالفعل. يدعم Failproof AI اثنا عشر منها، في فئتين:

- **واجهات سطر الأوامر للترميز** (10) — Claude Code و Codex و GitHub Copilot CLI و Cursor و OpenCode و Pi و Factory Droid و Devin CLI و Antigravity CLI و Goose
- **بوابات الدردشة والمساعدين** (2) — Hermes (Slack و Telegram و cron) و OpenClaw (مساعد ذاتي الاستضافة)

تنطبق نفس السياسات وتاريخ الجلسة ذاته بغض النظر عن أداة التشغيل التي يعمل فيها الوكيل. طبقة محول واحدة تربط أسماء الأحداث الأصلية لكل أداة تشغيل وأسماء الأدوات وحقول إدخال الأدوات على 29 حدثًا قانونيًا قبل تشغيل أي سياسة.

الوكيل الذي لا يعمل في **أيًا** من الاثني عشر يتم الآلية مباشرة باستخدام [Python SDK](/ar/reference/custom-agents). هذا عقد مختلف، ويستحق التصريح به بوضوح: يوفر SDK التتبع والجلسات والتقييمات والتدقيق — **لا يفرض السياسات بمفرده.** منع الإجراء غير الآمن قبل تنفيذه يتطلب خطاف إنفاذ على حدود أداة وقتك؛ [تواصل معنا](mailto:support@befailproof.ai) وسنقوم بربطها.

| أداة التشغيل | نطاقات الخطاف المدعومة |
| --- | --- |
| Claude Code | المستخدم والمشروع والمحلي |
| Codex و GitHub Copilot CLI و Cursor و OpenCode و Pi | المستخدم والمشروع |
| Factory Droid و Devin CLI و Antigravity CLI و Goose | المستخدم والمشروع |
| Hermes و OpenClaw | المستخدم |

يقوم كل تكامل بتطبيع أسماء أحداث الخطاف الأصلية وأسماء الأدوات وحقول إدخال الأدوات قبل تشغيل السياسات. يمكن للسياسة التصرف فقط على الأحداث التي تكشفها أداة التشغيل؛ اختبر السلوك في نهاية الدور والتعليمات على أداة التشغيل والإصدار المحددة بالضبط التي تنشرها.

## القدرة على الإنفاذ

"حجب" يعني أن الحكم المُعاد من محول التكيف الحالي يتم استهلاكه بواسطة أداة التشغيل المسماة. قد يحل الحجب بعد الأداة محل النتيجة المعروضة على النموذج لكنه لا يمكنه التراجع عن تأثير جانبي للأداة حدث بالفعل.

| أداة التشغيل | أحداث الحجب المتحقق منها | تحذيرات الملاحظة فقط أو عدم الحجب |
| --- | --- | --- |
| Claude Code | `PreToolUse` و `UserPromptSubmit` و `PermissionRequest` و `Stop` و `SubagentStop` و `PreCompact` وعدة أحداث مهام/إعدادات | `PostToolUse` ودورة حياة الجلسة والإخطارات وأحداث ما بعد الفشل قابلة للملاحظة. |
| Codex | `PreToolUse` و `PermissionRequest` و `UserPromptSubmit` و `Stop` و `SubagentStop` و `PostToolUse` | يحل الحجب بعد الأداة محل النتيجة بعد التنفيذ؛ أحداث بدء الجلسة والضغط قابلة للملاحظة في المحول الحالي. |
| GitHub Copilot CLI | `PreToolUse` و `UserPromptSubmit` و `PermissionRequest` و `Stop` و `SubagentStop` و `PostToolUse` | يحل الحجب بعد الأداة محل النتيجة بعد التنفيذ؛ أحداث الجلسة والإخطار قابلة للملاحظة. |
| Cursor | `PreToolUse` و `UserPromptSubmit` و `Stop` | `PostToolUse` وأحداث الجلسة قابلة للملاحظة. |
| OpenCode | `PreToolUse` | أحداث ما بعد الأداة ودورة الحياة قابلة للملاحظة؛ معالجة الإيقاف الحالية هي توجيه لدور لاحق وليست بوابة متحققة. |
| Pi | `PreToolUse` و `UserPromptSubmit` | أحداث ما بعد الأداة ودورة الحياة قابلة للملاحظة؛ يسري توجيه الإيقاف على دور لاحق. |
| Hermes | `PreToolUse` | أحكام ما بعد الأداة والجلسة وإيقاف الوكيل الفرعي ليست بوابات. |
| OpenClaw | `PreToolUse` و `UserPromptSubmit` و `Stop` | أحداث ما بعد الأداة والجلسة وإيقاف الوكيل الفرعي والضغط قابلة للملاحظة. |
| Factory Droid | `PreToolUse` و `UserPromptSubmit` و `Stop` و `PreCompact` | أحكام ما بعد الأداة وإيقاف الوكيل الفرعي قابلة للملاحظة. |
| Devin CLI | `PreToolUse` و `UserPromptSubmit` و `Stop` و `PermissionRequest` المشروط | لا تعمل خطافات الإذن في كل وضع إذن؛ أحداث ما بعد الأداة والجلسة قابلة للملاحظة. |
| Antigravity CLI | `PreToolUse` و `Stop` | تحذيرات موجه المستخدم وما بعد الأداة قابلة للملاحظة؛ يمكن لا تزال حقن تعليمات المطالبة. |
| Goose | `PreToolUse` | أحداث موجه المستخدم وما بعد الأداة والجلسة قابلة للملاحظة. يوجد خطاف إيقاف حجب أصلي في المنبع لكنه لم يتم تثبيته بواسطة المحول الحالي. |

القدرات حساسة للإصدار. أعد الاختبار بعد ترقية CLI لوكيل معين، خاصة عندما تعتمد السياسة على سلوك الموجه أو الإيقاف أو الإذن أو ما بعد الأداة بدلاً من بوابة ما قبل الأداة الشائعة.

## تثبيت خطافات الالتقاط والسياسة

<Tabs>
  <Tab title="لوحة التحكم">
    1. افتح **الإدارة → المفاتيح** وأنشئ مفتاحًا بـ `events:add` و `policies:pull`، مسمى للجهاز أو البيئة.
    2. على الجهاز المستهدف، قم بتوصيل CLI المحلي بالمفتاح المعروض وتثبيت خطافات أداة التشغيل.
    3. ابدأ جلسة وكيل جديدة، ثم أكد أحداث الخطاف والجلسة الخاصة بها تحت **ملاحظة → الأحداث**.
    4. افتح **ملاحظة → السياسة** لنفس نطاق الوقت وأكد أن قرار السياسة يُعزى إلى الجهاز.

    يبدأ الاتصال بمفتاح الجهاز. أكد أنه يتضمن أذونات البث والتسليم السياسي قبل نسخ سره.

    ![درج مفتاح API الجديد المستخدم لمنح أذونات البث وتسليم السياسة.](/images/dashboard/key-create.png)

    بعد تثبيت الخطافات، يجب أن يعرض تدفق الأحداث أحداثًا جديدة من الجهاز والبيئة التي قمت بتوصيلها.

    ![تدفق الأحداث المباشر المستخدم لتأكيد أن أداة تشغيل مثبتة حديثًا تقدم تقارير.](/images/dashboard/events-stream.png)

    أخيرًا، تحقق من أن قرارات السياسة تُعزى إلى نفس الجهاز. هذا يؤكد أن أداة التشغيل تقدم تقارير عن نشاط السياسة وكذلك أحداث التتبع.

    ![صفحة السياسة المستخدمة للتحقق من قرارات السياسة من أداة تشغيل جديدة متصلة.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    تثبيت الخطافات لكل أداة تشغيل تم اكتشافها:

    ```bash
    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>
    failproofai policies --install
    ```

    أو استهدف أدوات تشغيل مسماة ونطاق إعدادات:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    يحتفظ نطاق المشروع بتكوين الخطاف مع مستودع. يغطي نطاق المستخدم العمل عبر المستودعات. Claude Code يدعم أيضًا نطاق محلي؛ يختلف الدعم حسب أداة التشغيل و CLI يرفض المجموعات غير المدعومة.

    تحقق من الجهاز وأحداثه:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## إضافة مسار جلسة غير افتراضي

<Tabs>
  <Tab title="لوحة التحكم">
    يتم تسجيل المسارات الإضافية على الجهاز وليس في السحابة. بعد إضافة واحد، افتح **ملاحظة → الجلسات**، صفي حسب بيئة الجهاز، وأكد أن الجلسات من المسار الجديد تظهر. افتح جلسة وتحقق من الوكيل ويتم أداة التشغيل وطوابع زمن الأحداث قبل الاعتماد عليها في التدقيق.

    ![قائمة الجلسات مصفاة إلى البيئة التي تستقبل البيانات من مسار الالتقاط الإضافي.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    أضف مسارًا بعلامة اختيارية ثم افحص المسارات المكونة:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    أزل مسارًا بـ `failproofai harness remove-path claude checkout`.
  </Tab>
</Tabs>

<Tip>
  قم بتشغيل جلسة جديدة واحدة بعد التثبيت. تحقق من كل من تدفق الأحداث المباشر وقرار السياسة الفعلي قبل توسيع الطرح.
</Tip>
