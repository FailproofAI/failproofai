يتم تقديم API العام تحت `/v1` على مصدر لوحة تحكم Failproof AI الخاصة بك.

## إنشاء مفتاح وإرسال طلب

<Tabs>
  <Tab title="لوحة التحكم">
    1. افتح **الإدارة → المفاتيح**، واختر **إنشاء مفتاح**، ثم اختر أضيق إعداد صلاحيات يغطي التكامل.
    2. أضف منح فردية فقط عند الحاجة، أنشئ المفتاح، وانسخ سره لمرة واحدة.
    3. أرسل طلب اختبار إلى `/v1/sessions` وأكد أن المفتاح يبقى نشطاً في صفحة المفاتيح.
    4. قم بتدوير أو تعطيل المفتاح من قائمة الإجراءات الخاصة به عند تغيير مالك التكامل.

    ![درج مفتاح API جديد يحتوي على إعدادات الصلاحيات والمنح الفردية.](/images/dashboard/key-create.png)

    يظهر درج الإنشاء أعلاه. السر لمرة واحدة يظهر فقط بعد تحديد **إنشاء**؛ انسخه قبل إغلاق هذا التأكيد.
  </Tab>
  <Tab title="CLI">
    أنشئ مفتاح قراءة واستخدمه مباشرة مع `fp` أو `curl`:

    ```bash
    fp keys create reliability-reader \
      --permission-set read-only

    fp --api-key <key> sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/sessions?limit=20" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY"
    ```
  </Tab>
</Tabs>

المفاتيح مرتبطة بمنظمة وإعداد صلاحيات. الطلب بدون الصلاحية المطلوبة للنقطة النهائية يعيد `403` ويحدد الصلاحية المفقودة.

## اختيار المنظمة

مفتاح المنظمة يعمل على منظمته تلقائياً. مفتاح ذو نطاق المثيل يمكنه اختيار منظمة لكل طلب:

<Tabs>
  <Tab title="لوحة التحكم">
    استخدم منتقي المنظمة في رأس لوحة التحكم قبل فتح **الإدارة → المفاتيح**. المفاتيح المُنشأة هناك تنتمي إلى المنظمة المحددة. أكد رابط المنظمة في عنوان URL وتفاصيل المفتاح قبل نسخ بيانات الاعتماد إلى الأتمتة.

  </Tab>
  <Tab title="CLI">
    استخدم `--org` قبل الأمر، أو أرسل رأس المنظمة لمفتاح API ذو نطاق المثيل.

    ```bash
    fp orgs list
    fp --org reliability-team sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/usage" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "X-AgentEye-Org: reliability-team"
    ```
  </Tab>
</Tabs>

استخدم صفحات النقطة النهائية المُنشأة في هذا القسم للمسارات الحالية والمعاملات ومتطلبات الصلاحيات وأكواد الحالة. تتم إنشاء المواصفة من تعليقات مسار الخادم والتحقق منها مقابل جهاز التوجيه `/v1`.

المواصفة الحالية لديها تغطية كاملة للمسار والطريقة والمعامل والصلاحية وكود الحالة. بعض أجسام الرد تبقى غير مكتوبة بقصد لأن الخادم لا يزال ينشئها كـ JSON ديناميكي. افحص رد حقيقي قبل إنشاء عميل مكتوب بقوة حول نقطة نهائية بدون مخطط رد.

استخدم `Content-Type: application/json` لكتابات JSON. اعتبر `401` كمصادقة مفقودة أو غير صحيحة، `403` كهوية صحيحة بدون الصلاحية المطلوبة، `404` كمورد مفقود أو غير قابل للوصول من المنظمة، `409` كصراع حالة، و`422` كقيمة حقل أو صلاحية غير صحيحة. تتضمن استجابات الخطأ رسالة قابلة للقراءة من الإنسان؛ فشل الصلاحيات أيضاً يسمي المنحة المطلوبة.

يستخدم تناول الأحداث JSON محدود بأسطر: كائن واحد كامل لكل سطر. تحقق من `accepted` و`skipped` في استجابة ناجحة. أعد محاولة الدفعة بالكامل بعد فشل في الشبكة أو استجابة HTTP 408 أو 429 أو 5xx؛ إعادة تشغيل نفس الأحداث آمنة. يمكن للدفعات التاريخية أن تمتد لعدة أشهر. إذا أرجع التناول `422` مع `error: "event_too_large"`، قلل حمولة الحدث المخالف قبل إعادة المحاولة. تقسيم الدفعة إلى طلبات أصغر لا يقلل من حجم حدث فردي. بالنسبة لاستيراد الملفات، أعد استخدام قطع `existing_before` الأصلي في المحاولات حتى تتمكن جلسة مخزنة جزئياً من الانتهاء.

## معرّفات الطلب

تحمل كل استجابة رأس `X-Request-Id`، وكل جسم خطأ JSON يتضمن نفس القيمة كـ `request_id`. اقتبسها عند الاتصال بالدعم: فهي تحدد ذلك الطلب الواحد.

يمكنك إرسال `X-Request-Id` الخاص بك لربط طلب بسجلاتك الخاصة. استخدم 32 حرفاً سادساً عشري صغيراً، مثل UUID v4 مع إزالة الشرطات. أي قيمة أخرى يتم استبدالها برقم معريف جديد، والذي يتم إرجاعه في الاستجابة.

<Warning>
  نشر إنفاذ السياسة يتم إدارته بقصد خارج السطح العام العادي `/v1`. استخدم سير عمل نشر السحابة المدعوم.
</Warning>
