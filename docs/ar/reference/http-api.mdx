يتم تقديم API العام ضمن `/v1` على أصل لوحة تحكم Failproof AI الخاصة بك.

## إنشاء مفتاح وإجراء طلب

<Tabs>
  <Tab title="Dashboard">
    1. افتح **Administration → Keys**، واختر **Create key**، واختر أضيق إعداد صلاحيات يغطي التكامل.
    2. أضف منحات فردية فقط عند الحاجة، وأنشئ المفتاح، وانسخ سره لمرة واحدة.
    3. أجرِ طلب اختبار إلى `/v1/sessions` وتأكد من بقاء المفتاح نشطاً في صفحة المفاتيح.
    4. قم بتدوير أو تعطيل المفتاح من قائمة الإجراءات الخاصة به عندما يتغير ملكية التكامل.

    ![درج المفتاح API الجديد مع إعدادات الصلاحيات والمنحات الفردية.](/images/dashboard/key-create.png)

    يظهر درج الإنشاء أعلاه. السر لمرة واحدة يظهر فقط بعد اختيار **create**؛ انسخه قبل إغلاق التأكيد.
  </Tab>
  <Tab title="CLI">
    أنشئ مفتاح قراءة واستخدمه مباشرة مع `fp` أو `curl`:

    ```bash
    fp keys create reliability-reader \
      --permission-set read-only

    fp --api-key <key> sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/sessions?limit=20" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY"
    ```
  </Tab>
</Tabs>

المفاتيح محدودة النطاق لمنظمة ومجموعة صلاحيات. الطلب بدون الصلاحية المطلوبة للنقطة النهائية يعيد `403` ويحدد الصلاحية المفقودة.

## اختيار المنظمة

مفتاح المنظمة يتصرف على منظمته تلقائياً. مفتاح محدود النطاق بالنسخة يمكنه تحديد منظمة لكل طلب:

<Tabs>
  <Tab title="Dashboard">
    استخدم مبدل المنظمة في رأس لوحة التحكم قبل فتح **Administration → Keys**. المفاتيح المُنشأة هناك تنتمي إلى المنظمة المحددة. تأكد من عنوان URL وتفاصيل المفتاح قبل نسخ بيانات الاعتماد في الأتمتة.

  </Tab>
  <Tab title="CLI">
    استخدم `--org` قبل الأمر، أو أرسل رأس المنظمة لمفتاح API محدود النطاق بالنسخة.

    ```bash
    fp orgs list
    fp --org reliability-team sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/usage" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "X-AgentEye-Org: reliability-team"
    ```
  </Tab>
</Tabs>

استخدم صفحات النقطة النهائية المُنشأة في هذا القسم للمسارات الحالية والمعاملات ومتطلبات الصلاحيات ورموز الحالة. المواصفات تُنشأ من تعليقات المسارات على الخادم وتُفحص مقابل جهاز التوجيه `/v1`.

المواصفات الحالية تمتلك تغطية كاملة للمسار والطريقة والمعامل والصلاحية ورمز الحالة. بعض أجسام الاستجابة تبقى بدون نوع عن قصد لأن الخادم لا يزال ينشئها كـ JSON ديناميكي. افحص استجابة حقيقية قبل إنشاء عميل مكتوب بقوة حول نقطة نهائية بدون مخطط استجابة.

استخدم `Content-Type: application/json` لكتابات JSON. اعتبر `401` كمصادقة مفقودة أو غير صالحة، و `403` كهوية صالحة بدون الصلاحية المطلوبة، و `404` كمورد مفقود أو يتعذر الوصول إليه من المنظمة، و `409` كتضارب الحالة، و `422` كحقل غير صالح أو قيمة صلاحية. تتضمن استجابات الخطأ رسالة يمكن قراءتها بواسطة الإنسان؛ كما تسمي فشل الصلاحيات المنحة المطلوبة.

<Warning>
  نشر تطبيق السياسة يُدار بقصد خارج سطح `/v1` العام العادي. استخدم سير عمل نشر السحابة المدعوم.
</Warning>
