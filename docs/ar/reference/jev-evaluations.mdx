تصف هذه الصفحة أشكال الأسئلة وقواعد التسجيل خلف [تقييمات Jev](/ar/evaluations/jev). بعض الأسئلة تتطلب من النموذج *قراءة* المحادثة، لكن ليس *الكتابة* عنها. "هل أعرب العميل عن الاستعجالية؟" له إجابتان. "كم كانوا محبطين؟" له عدد قليل منها، بالترتيب. تعرف كل إجابة قبل أن تسأل.

**تقييم التصنيف** مخصص لتلك الحالات بالضبط. تكتب السؤال والإجابات التي قد يعطيها، وينتج نموذج صغير مبني للتصنيف رقماً معايراً — لا نص حر أبداً.

<Note>
مثل القاضي، تقييم التصنيف يكلف استدعاء نموذج واحد لكل جلسة. بخلاف ذلك فهو نموذج صغير وحيد الغرض بدلاً من نموذج عام، لذا فهو أسرع وأرخص — لكنه لن يشرح نفسه أبداً. إذا كنت تحتاج إلى التفكير، استخدم [judge](/ar/evaluations/judge).
</Note>

## أي واحد أريد؟

| السؤال | الاستخدام |
| --- | --- |
| كم عدد استدعاءات الأدوات؟ | code |
| هل كانت الجلسة أقل من 30 ثانية؟ | code |
| هل أعرب العميل عن الاستعجالية؟ | **classifier** |
| أي فريق يجب أن يتعامل مع هذا: الفواتير أو الدعم التقني أو المبيعات؟ | **classifier** |
| كم كان العميل محبطاً؟ | **classifier** |
| هل كانت الإجابة صحيحة فعلاً؟ | **judge** |
| هل اتبعت سياسة التصعيد لدينا، ولماذا تعتقد ذلك؟ | **judge** |

القاعدة الأساسية: **قابل للعد → code، إجابات يمكنك إدراجها → classifier، يتطلب شرحاً → judge.**

لا تضطر إلى الاختيار مقدماً. صف ما تريد قياسه والمساعد يختار، ويخبرك بأيهما اختار ولماذا، ويمكنك تبديله.

## نوعا الأسئلة

### `noul` — هل هذا صحيح؟

إجابتان، وأنت تصف كليهما. النتيجة هي احتمال أن الوصف "الصحيح" ينطبق:

```json
{
  "instructions": "هل وعد المساعد برد مالي دون التحقق أولاً من سياسة الاسترداد؟",
  "criteria": {
    "true":  "تم الوعد برد مالي أو إصداره دون فحص السياسة مسبقاً أو الموافقة عليه",
    "false": "لم يتم الوعد برد مالي، أو كل استرداد تبع فحص السياسة"
  }
}
```

صف كلا الجانبين. "لم يتم التعبير عن الاستعجالية" هي إجابة حقيقية وقول ذلك يجعل الجانب الآخر أوضح.

### `score` — كم درجة من هذا؟

مقياس مرتب، **الأسوأ أولاً**. النتيجة هي حيث تقع الجلسة عليه، معاد تحجيمه إلى 0–1:

```json
{
  "instructions": "كم كان العميل محبطاً؟",
  "criteria": ["هادئ", "محبط", "غاضب جداً"]
}
```

**المقياس يأخذ ثلاثة إلى خمسة مستويات، ويجب أن تكون جميعها مختلفة.** يتم قياس كلا الحدين، ليس من حيث الأسلوب:

- **مستويان** ينهار إلى ما `noul` يفعله بالفعل بشكل أفضل، و**أكثر من خمسة** يجعل النموذج يتردد نحو الوسط بدلاً من الالتزام. تم تسجيل نفس السؤال على نفس الجلسة بـ 0.00 مع مستويين، 0.01 مع ثلاثة، و 0.55 مع عشرة.
- **المستويات المكررة** تقسم الإجابة بشكل تعسفي بينها. جلسة كانت غاضبة بوضوح سجلت 1.00 ضد `["هادئ", "محبط", "غاضب جداً"]` و 0.66 ضد `["غاضب", "غاضب", "غاضب"]` — رقم منسق جيداً بلا معنى.

الفئات بدون ترتيب — "الفواتير أو الدعم التقني أو المبيعات" — ليست مقياساً. اسأ عنها كـ `noul` لكل فئة، أو استخدم judge.

## قراءة النتائج

ينتج التصنيف **درجة** من 0 إلى 1، تماماً مثل judge، لذا فهو يخطط ويصفي وينشئ تنبيهات بنفس الطريقة. هناك فرقان يستحقان المعرفة:

- **لا يوجد تفكير.** الحقل فارغ، بقصد. هذا النموذج لا يشرح نفسه، واختراع شرح سيكون تلفيقاً وليس ميزة.
- **عدم اليقين مصنف.** تسأل `score` يبلغ عن ثقتها الخاصة، والنتيجة التي كان النموذج غير متأكد منها يتم وسمها `low_confidence` — لذا فإن "أي من هذه يجب أن ينظر إليها الإنسان" هو مرشح وليس تخمين. سؤال `noul` لا يبلغ عن الثقة، لذا لا يتم وسمه أبداً.

الجلسات الطويلة جداً تُقرأ على دفعات وتجمع معاً. عندما تكون الجلسة طويلة جداً لقراءتها بالكامل، تقول النتيجة عدد الأدوار التي تم حذفها — لن ترى أبداً حكماً يتم إصداره على جزء من جلسة يُعرض على أنه تم على كلها.

## الحدود

- **ثلاثة إلى خمسة مستويات مقياس، جميعها مختلفة.** انظر أعلاه؛ يتم فرض كلا الحدين وقت الإنشاء.
- **سؤال واحد لكل تقييم.** اسأ شيئين وتحصل على تقييمين، وهذا أيضاً ما تريده على الرسم البياني.
- **تحرير السؤال ينشر نسخة جديدة.** الدرجات القديمة والجديدة غير قابلة للمقارنة، لذا يتم الاحتفاظ بها منفصلة بدلاً من دمجها في خط اتجاه واحد.
- **يُنتج التصنيف دائماً درجة**، ولا يكون أبداً متريقة أو تأكيداً.
- **بلا تفكير**، كما هو الحال أعلاه. إذا كان الرقم سيجعل شخصاً ما يسأل "لماذا؟"، اكتب judge بدلاً من ذلك.

## الاختبار والملء العكسي

بخلاف judge، يمكن اختبار تقييم التصنيف **قبل** نشره — [اختبره](/ar/evaluations/test) ضد جلسات حقيقية بنفس الطريقة التي تختبر بها تقييم code، واقرأ الدرجات قبل أن يبدأ أي شيء.

يمكن أيضاً [ملؤه عكسياً](/ar/evaluations/deploy#score-sessions-you-already-have) على الجلسات التي لديك بالفعل. يكلف استدعاء نموذج واحد لكل جلسة، لذا حدد النافذة بقصد بدلاً من إعادة تشغيل كل شيء.
