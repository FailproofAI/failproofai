قم بتشغيل `failproofai` بدون معاملات لبدء لوحة المعلومات المدمجة على `http://localhost:8020`. تقرأ سجلات الوكيل المحلية وتكوين السياسة ونتائج التدقيق ونشاط الخطاف مباشرة من الجهاز.

على جهاز لم يتم إعداده، تقوم الأمر الأساسي بتشغيل إعداد الشغيل الأول قبل فتح لوحة المعلومات. يفعل ذلك فقط على محطة تفاعلية: عند الأنابيب أو في CI، يطبع تلميحاً بسطر واحد ويفتح لوحة المعلومات، لأن معالج لا يمكن لأحد الإجابة عليه يجب ألا يعطل الأمر الذي كتبته. اضبط `FAILPROOFAI_NO_FIRST_RUN=1` لتخطي إعادة التوجيه بالكامل والانتقال مباشرة إلى لوحة المعلومات.

لوحة المعلومات المحلية منفصلة عن Failproof AI Cloud. تعمل بدون حساب Cloud ولا تثبت أن الأحداث تم تسليمها إلى مؤسستك. على جهاز اكتمل إعداده، تم اتخاذ القرارات التي تعرضها من قبل مصيدة `failproofaid`، وهو المُقيِّم الوحيد هناك؛ على جهاز لم يتم إعداده، تقيم الخطافات في العملية.

## مناطق لوحة المعلومات

| المنطقة | ما يمكنك إنجازه |
| --- | --- |
| السياسات → النشاط | افحص قرارات السماح والإرشاد والرفض المحلية؛ قم بالتصفية حسب القرار والحدث وCLI والمصدر والسياسة والجلسة. |
| السياسات → التكوين | فعّل السياسات من حزمة مثبتة وعدّل المعاملات المدعومة وبدّل السياسات المخصصة والاتفاقية المكتشفة واختر أجهزة العمل المستهدفة. |
| المشاريع | استعرض المشاريع المكتشفة عبر سجلات الوكيل المدعومة وقارن جلساتهم الأخيرة. |
| جلسات المشروع | افتح نسخة محلية واحدة واستعرض الإدخالات المرتبة الأولية والوكلاء الفرعيين وحمّلها وربط نشاط السياسة. |
| التدقيق | استعرض آخر فحص دون اتصال والأنماط الخطرة والنقاط القوية والمشاريع المتأثرة والسياسات المدمجة المقترحة. |
| الإعدادات | قم بتكوين الفحوصات المحلية المجدولة وتقارير التدقيق المرسلة بالبريد عندما يدعمها المصيدة/المنصة. |

## راجع نشاط السياسة

<Tabs>
  <Tab title="لوحة المعلومات">
    1. افتح **السياسات → النشاط** وعيّن مرشحات القرار والمصدر.
    2. ضيّق حسب الحدث أو جهاز العمل أو اسم السياسة أو الجلسة.
    3. يحتوي الصف على القرار والحدث وجهاز العمل والأداة والسياسة وحالة الإذن والمدة. قم بتوسيعه للحصول على السبب الكامل وكل سياسة متطابقة والمصدر المقرر والنشر السحابي ومسار دليل العمل ونسخة الجلسة. يتم عرض اسم الأداة على الصف لكنه ليس مرشحاً.
    4. اتبع رابط الجلسة لوضع القرار في سياق النسخة.

    يمكن للصف الذي يبدو مرفوضاً أن يكون مراقبة على زوج جهاز عمل/حدث لا يستهلك الأحكام الحجزية. تشير عرض التفاصيل إلى قدرة الإنفاذ المتحققة.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    يتم تخزين النشاط المحلي تحت `~/.failproofai/hook-activity`. استخدم لوحة المعلومات بدلاً من تحرير هذه الملفات.
  </Tab>
</Tabs>

## قم بتكوين السياسات محلياً

<Tabs>
  <Tab title="لوحة المعلومات">
    1. افتح **السياسات → التكوين** واختر أجهزة العمل ونطاق التكوين. التبويب قابل للعنونة مباشرة على `http://localhost:8020/policies?tab=policies`.
    2. فعّل سياسة من حزمة مثبتة أو سياسة مخصصة أو اتفاقية مكتشفة.
    3. لسياسة محددة المعاملات، افتح عنصر التحكم في التكوين الخاص بها واحفظ القيم المدعومة.
    4. عد إلى النشاط وشغّل الإجراءات المطابقة وغير المطابقة.

    القائمة فارغة حتى يتم تثبيت حزمة — لا تجمع هذه النسخة أي سياسات خاصة بها، لذا قم بتشغيل `failproofai policies add FailproofAI/policies` أولاً. تعرض سياسات الاتفاقية مصدرها من المشروع أو المستخدم. قد تتطلب التغييرات صريحة المسار المخصص إعادة تشغيل تكوين CLI بحيث يتم تسجيل المسار المحدد.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies show FailproofAI/policies
    failproofai policies add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```

    `policies show <owner>/<repo>` يقرأ محتويات الحزمة قبل تثبيتها. `--scope` يأخذ `user` أو `project` أو `local`؛ فقط Claude Code يدعم `local`، و Hermes و OpenClaw يأخذان `user` فقط.
  </Tab>
</Tabs>

## استعرض المشاريع والجلسات

تجمع صفحة المشاريع متاجر السجل المحلي المدعومة. حدد مشروعاً لسرد جلساته، ثم افتح جلسة لعارض السجل الأولي وقطاعات الوكلاء الفرعيين وإجراء التحميل ونشاط السياسة المحدد للجلسة.

إذا كان المشروع أو الجلسة مفقودة، فأكد أن جهاز العمل يستخدم موقع السجل الافتراضي أو سجل جذراً إضافياً باستخدام `failproofai harness add-path <harness> [<label>=]<path>`.

## جدول التدقيقات دون اتصال

<Tabs>
  <Tab title="لوحة المعلومات">
    افتح **الإعدادات** وفعّل الفحص المجدول واختر الفترة الزمنية المدعومة له وقم بتكوين تسليم التقرير عند توفره. تقرر الصفحة التشغيل التالي والتشغيل الأخير ورمز الخروج وما إذا كانت المصيدة في الخلفية مدعومة على المنصة.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    غيّر عدد الأيام لتعيين فترة زمنية مختلفة من 1-90 يوم. عطّل المسح المتكرر باستخدام `failproofai audit --no-schedule`، والذي يوقف المؤقت ويتركك مسجل الدخول؛ قم بتشغيل `failproofai audit` لفحص تفاعلي فوري.

    يقيّدك الجدول في المرة الأولى، لأن النتائج يتم إرسالها بالبريد. يوفر `--email <address>` العنوان مقدماً وتخطي موجه تسجيل الدخول.
  </Tab>
</Tabs>

<Note>
  يبقى التحليل والنتائج على هذا الجهاز. يتم إرسال قياس الأداء المجهول لواجهة سطر الأوامر بشكل افتراضي ما لم تضبط `FAILPROOFAI_TELEMETRY_DISABLED=1`. تُرسل الفحوصات المجدولة أيضاً بيانات وصف الجهاز وقد ترسل ملخص النتائج المحدود بعد اختيارك.
</Note>

<Warning>
  يمكن لوحة المعلومات المحلية عرض الأوامر والإدخال الأداة ومحتوى الملف وإخراج المحطة من سجلات الوكيل المحلية. اربطها فقط بالواجهات الموثوقة وأيقف العملية عند اكتمال المراجعة.
</Warning>
