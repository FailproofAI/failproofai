قم بتشغيل `failproofai` بدون معاملات لبدء لوحة المعلومات المدمجة في `http://localhost:8020`. تقرأ سجلات الوكلاء المحليين وتكوين السياسات ونتائج التدقيق ونشاط الخطاف مباشرة من الجهاز.

لوحة المعلومات المحلية منفصلة عن Failproof AI Cloud. تعمل بدون حساب Cloud ولا تثبت تسليم الأحداث إلى مؤسستك.

## مناطق لوحة المعلومات

| المنطقة | ما يمكنك إنجازه |
| --- | --- |
| السياسات → النشاط | فحص قرارات allow و instruct و deny المحلية؛ التصفية حسب القرار والحدث والواجهة السطرية والأداة والمصدر والسياسة والجلسة. |
| السياسات → التكوين | تفعيل المدمجات وتحرير المعاملات المدعومة وتبديل السياسات المخصصة المكتشفة واختيار أجهزة الاختبار المستهدفة. |
| المشاريع | استعرض المشاريع المكتشفة عبر سجلات الوكلاء المدعومة وقارن جلساتهم الأخيرة. |
| جلسات المشروع | افتح نسخة محلية واحدة وراجع الإدخالات المرتبة الأولية والوكلاء الفرعيين وحمّلها وربط نشاط السياسات. |
| التدقيق | راجع آخر فحص غير متصل والأنماط المحفوفة بالمخاطر والنقاط القوية والمشاريع المتأثرة وسياسات المدمجات المقترحة. |
| الإعدادات | قم بتكوين الفحوصات المحلية المجدولة والتقارير المدقاة عبر البريد الإلكتروني عندما يدعمها المراقب/النظام الأساسي. |

## مراجعة نشاط السياسات

<Tabs>
  <Tab title="لوحة المعلومات">
    1. افتح **السياسات → النشاط** وعيّن مرشحات القرار والمصدر.
    2. ضيّق نطاق البحث حسب الحدث أو جهاز الاختبار أو الأداة أو اسم السياسة.
    3. وسّع صفًا لفحص السبب والسياسات المطابقة والمصدر وطريقة التنفيذ والمدة.
    4. اتبع ارتباط الجلسة لوضع القرار في سياق النسخة.

    يمكن لصف يبدو مرفوضًا أن يكون ملاحظتيًا على زوج جهاز اختبار/حدث لا يستهلك أحكامًا حجزية. يشير عرض التفاصيل إلى القدرة على الإنفاذ المتحقق منها.
  </Tab>
  <Tab title="واجهة سطرية">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    يتم تخزين النشاط المحلي تحت `~/.failproofai/hook-activity`. استخدم لوحة المعلومات بدلاً من تحرير هذه الملفات.
  </Tab>
</Tabs>

## تكوين السياسات محليًا

<Tabs>
  <Tab title="لوحة المعلومات">
    1. افتح **السياسات → التكوين** واختر أجهزة الاختبار ونطاق التكوين.
    2. فعّل سياسة مدمجة أو سياسة مخصصة مكتشفة.
    3. بالنسبة لسياسة مدمجة معاملات، افتح عنصر التحكم الخاص بها واحفظ القيم المدعومة.
    4. عُد إلى النشاط وشغّل الإجراءات المطابقة وغير المطابقة.

    تظهر سياسات الاتفاقية مصدرها أو مصدر المستخدم. قد تتطلب التغييرات المخصصة صريحة بمسار مخصص إعادة تشغيل تكوين الواجهة السطرية بحيث يتم تسجيل المسار المحدد.
  </Tab>
  <Tab title="واجهة سطرية">
    ```bash
    failproofai policy add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```
  </Tab>
</Tabs>

## استعراض المشاريع والجلسات

تجمع صفحة المشاريع متاجر السجلات المحلية المدعومة. حدد مشروعًا لعرض جلساته ثم افتح جلسة لعارض السجل الأولي وقطاعات الوكلاء الفرعيين وإجراء التحميل ونشاط السياسات ذات النطاق الجلسة.

إذا كان المشروع أو الجلسة مفقودة، تأكد من أن جهاز الاختبار يستخدم موقع السجل الافتراضي أو سجّل جذرًا إضافيًا باستخدام `failproofai harness add-path`.

## جدولة التدقيقات غير المتصلة

<Tabs>
  <Tab title="لوحة المعلومات">
    افتح **الإعدادات** وفعّل الفحص المجدول واختر فترته المدعومة وقم بتكوين تسليم التقرير عند توفره. تعرض الصفحة التشغيل التالي والتشغيل الأخير وكود الخروج وما إذا كان المراقب الخلفي مدعومًا على النظام الأساسي.
  </Tab>
  <Tab title="واجهة سطرية">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    غيّر عدد الأيام لتعيين فترة مختلفة 1–90 يوم. عطّل عمليات الفحص المتكررة باستخدام `failproofai audit --no-schedule`؛ قم بتشغيل `failproofai audit` لإجراء فحص تفاعلي فوري.
  </Tab>
</Tabs>

<Warning>
  يمكن لوحة المعلومات المحلية عرض المحفزات والمدخلات الأداة ومحتوى الملف ومخرجات الطرفية من سجلات الوكلاء المحليين. اربطها فقط بالواجهات الموثوقة وأوقف العملية عند اكتمال المراجعة.
</Warning>
