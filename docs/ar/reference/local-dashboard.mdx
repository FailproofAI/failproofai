قم بتشغيل `failproofai` بدون وسائط لبدء لوحة التحكم المدمجة على `http://localhost:8020`. تقرأ سجلات الوكيل المحلية وتكوين السياسة ونتائج التدقيق ونشاط hook مباشرة من الجهاز.

لوحة التحكم المحلية منفصلة عن Failproof AI Cloud. تعمل بدون حساب Cloud ولا تثبت أن الأحداث تم تسليمها لمؤسستك.

## مناطق لوحة التحكم

| المنطقة | ما يمكنك إنجازه |
| --- | --- |
| Policies → Activity | فحص قرارات السماح والتعليمات والرفض المحلية؛ الترشيح حسب القرار والحدث والـ CLI والأداة والمصدر والسياسة والجلسة. |
| Policies → Configure | تفعيل المدمجات وتحرير المعاملات المدعومة وتبديل السياسات المخصصة المكتشفة واختيار أطر العمل المستهدفة. |
| Projects | استعراض المشاريع المكتشفة عبر سجلات الوكيل المدعومة ومقارنة جلساتها الأخيرة. |
| Project sessions | افتح نسخة محلية واحدة واستعرض الإدخالات المرتبة والوكلاء الفرعيين وقم بتنزيلها ربط نشاط السياسة. |
| Audit | راجع آخر مسح غير متصل والأنماط المحفوفة بالمخاطر والنقاط القوية والمشاريع المتأثرة والسياسات المدمجة المقترحة. |
| Settings | قم بتكوين المسح المحلي المجدول والتقارير المرسلة عبر البريد الإلكتروني عندما يدعمها الخادم الحفاظ/المنصة. |

## مراجعة نشاط السياسة

<Tabs>
  <Tab title="Dashboard">
    1. افتح **Policies → Activity** وحدد مرشحات القرار والمصدر.
    2. ضيق نطاق البحث حسب الحدث أو إطار العمل أو الأداة أو اسم السياسة.
    3. وسّع الصف لفحص سببه والسياسات المطابقة والمصدر وطريقة التنفيذ والمدة.
    4. اتبع رابط الجلسة لوضع القرار في سياق النسخة.

    يمكن لصف يبدو مرفوضًا أن يكون ملاحظًا على زوج من إطار العمل/الحدث لا يستهلك أحكامًا حجزية. يشير عرض التفاصيل إلى قدرة الإنفاذ المؤكدة.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    يتم تخزين النشاط المحلي في `~/.failproofai/hook-activity`. استخدم لوحة التحكم بدلاً من تحرير هذه الملفات.
  </Tab>
</Tabs>

## قم بتكوين السياسات محليًا

<Tabs>
  <Tab title="Dashboard">
    1. افتح **Policies → Configure** واختر أطر العمل ونطاق التكوين.
    2. فعّل سياسة مدمجة أو سياسة مخصصة مكتشفة.
    3. بالنسبة للسياسة المدمجة ذات المعاملات، افتح عنصر التحكم في التكوين الخاص بها وحفظ القيم المدعومة.
    4. عد إلى Activity وقم بتشغيل الإجراءات المطابقة وغير المطابقة.

    تعرض سياسات الاتفاقية مصدرها من المشروع أو المستخدم. قد تتطلب التغييرات الصريحة للمسار المخصص إعادة تشغيل تكوين CLI حتى يتم تسجيل المسار المحدد.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```
  </Tab>
</Tabs>

## استعرض المشاريع والجلسات

تجمع صفحة Projects بين مخازن السجل المحلي المدعومة. حدد مشروعًا لإدراج جلساته، ثم افتح جلسة لعارض السجل الخام وأجزاء الوكيل الفرعي وإجراء التنزيل ونشاط السياسة المحدد بالجلسة.

إذا كان مشروع أو جلسة مفقودة، فتأكد من أن إطار العمل يستخدم موقع السجل الافتراضي أو قم بتسجيل جذر إضافي باستخدام `failproofai harness add-path`.

## جدول التدقيق غير المتصل

<Tabs>
  <Tab title="Dashboard">
    افتح **Settings**، فعّل المسح المجدول، اختر الفترة الزمنية المدعومة، وقم بتكوين تسليم التقرير عند توفره. تعرض الصفحة التشغيل التالي والتشغيل الأخير وكود الخروج وما إذا كان الخادم الحفاظ في الخلفية مدعومًا على المنصة.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    غيّر عدد الأيام لتعيين فترة زمنية مختلفة من 1-90 يومًا. عطّل الفحص المتكرر باستخدام `failproofai audit --no-schedule`؛ قم بتشغيل `failproofai audit` للمسح التفاعلي الفوري.
  </Tab>
</Tabs>

<Warning>
  يمكن لوحة التحكم المحلية عرض الأوامر والإدخال الخاص بالأداة ومحتوى الملف والإخراج الطرفي من سجلات الوكيل المحلية. ربطها فقط بالواجهات الموثوقة وأوقف العملية عند انتهاء المراجعة.
</Warning>
