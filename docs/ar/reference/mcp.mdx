قم بربط أداة ذكاء اصطناعي بـ Failproof AI Cloud والعمل ببيانات عملائك منها. يمكن لأداتك الاستعلام عن الجلسات والأحداث، وتشغيل SQL للقراءة فقط، وقراءة لوحات التحكم والتنبيهات والمشاكل والتدقيقات والسياسات، وإذا كنت تمتلك الإذن، إجراء تغييرات مثل إنشاء تنبيه أو نشر سياسة.

يتم تشغيل كل استدعاء بـ **أذوناتك الخاصة**، في **منظمة واحدة** تختارها عند الاتصال.

هناك عنوان واحد للجميع، مستضاف أو ذاتي الاستضافة:

```text
https://gateway.befailproof.ai/mcp
```

## قم بربط عميل

أضف العنوان إلى عميلك. في المرة الأولى التي يتم فيها استخدام أداة، سيتم فتح متصفحك. اختر مكان وجود Failproof AI Cloud الخاص بك وسجل الدخول واختر منظمة واحدة ثم حدد **السماح**. يؤدي **الإلغاء** إلى عدم ربط أي شيء.

تذكر الصفحة اسم التطبيق والمكان الذي يعود إليه. يتم وضع علامة على التطبيق الذي لا يتم تحديده من خلال عنوان الويب الخاص به بـ **تطبيق غير موثق**، لذا استمر فقط إذا بدأت هذا للتو من عميلك الخاص.

<Tabs>
  <Tab title="Claude">
    في claude.ai أو Claude Desktop، انتقل إلى **الإعدادات → الموصلات → إضافة موصل مخصص**. سمِّه `Failproof AI`، وأدخل العنوان، وحدد **إضافة**، ثم **الاتصال**.

    في خطط Team و Enterprise، يقوم المالك بإضافة الموصل للمنظمة أولاً. ثم يقوم كل شخص بربط حسابه الخاص.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    ثم قم بتشغيل `/mcp` داخل Claude Code، واختر `failproofai`، واختر **المصادقة**.
  </Tab>
  <Tab title="Cursor">
    أضف هذا إلى `~/.cursor/mcp.json`، أو إلى `.cursor/mcp.json` في مشروعك:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    يعرض Cursor **يتطلب تسجيل دخول** بجانب الخادم. حدده لتسجيل الدخول.
  </Tab>
  <Tab title="Codex">
    أضف هذا إلى `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    ثم قم بتشغيل `codex mcp login failproofai`.
  </Tab>
  <Tab title="عملاء آخرون">
    أي عميل يدعم خوادم MCP البعيدة عبر HTTP قابل للبث مع OAuth يعمل. أعطه العنوان أعلاه. لا يوجد معرف عميل أو سر لتكوينه.
  </Tab>
</Tabs>

## منظمة واحدة لكل اتصال

يعمل الاتصال فقط في المنظمة التي اخترتها. لاستخدام منظمتين، أضف الخادم مرتين تحت أسماء مختلفة، مثل `failproofai-acme` و `failproofai-sandbox`، وقم بربط كل منها بمنظمتها الخاصة.

لا تقبل المنظمات التجريبية الاتصالات. اختر منظمتك الخاصة بدلاً من ذلك.

## الأذونات

يمكن لاتصال أن يفعل ما يمكنك فعله في المنظمة، ضمن المجموعة أدناه. إنه يتبع أذوناتك الحالية: إذا منحك المسؤول المزيد، ستحصل الأداة عليه، وإذا أخذها، ستفقدها الأداة عند استدعاءها التالي.

| الإذن | يسمح للأداة بـ |
| --- | --- |
| `events:read` | إدراج الأحداث، قراءة نظرة عامة على الجلسة، إدراج الوكلاء والبيئات |
| `evaluations:read` | إدراج الجلسات، وقراءة وتلخيص نتائج التقييمات والمهام |
| `evaluations:trigger` | إنشاء التقييمات، ونشر إصدارات جديدة، وتشغيلها أو إيقافها، والملء المسبق، وإعادة تقييم الجلسة |
| `dashboards:read`, `dashboards:write` | قراءة لوحات التحكم، أو إنشاء وإعادة تسمية وإضافة استعلامات إليها |
| `queries:read`, `queries:write` | قراءة الاستعلامات المحفوظة، أو حفظها وتحريرها |
| `queries:run` | تشغيل استعلام SQL واحد للقراءة فقط وقراءة مخطط الاستعلام |
| `alerts:read`, `alerts:write` | قراءة التنبيهات، أو إنشاء وتحرير والتوقف والحذف واختبار |
| `issues:read` | قراءة المشاكل والاعتراف بها والتعليق عليها |
| `issues:create` | فتح مشكلة على تنبيه |
| `issues:close` | حل وإغلاق المشاكل |
| `audits:read`, `audits:write` | قراءة التدقيقات والتشغيلات والنتائج، أو إنشاء وتحرير التدقيقات وبدء التشغيل |
| `code_fixes:read` | معرفة كيفية إصلاح مشكلة والحصول على سياقها لوكيلك الخاص لإصلاحها |
| `code_fixes:write` | بدء إصلاح في Failproof AI Cloud، الذي يفتح طلب دمج على GitHub الخاص بك |
| `policies:read`, `policies:write` | قراءة السياسات والأجهزة والنشرات، أو نشر وزيادة وتراجع السياسات |

لا تحتاج بعض الأدوات إلى إذن لأنها لا تقرأ بيانات المنظمة: بناء روابط الجلسة والحدث، والبحث في هذه الوثائق.

لا يمكن لأداة ذكاء اصطناعي أن تلمس مفاتيح API أو المستخدمين أو الإعدادات أو إدارة المنظمة، كما لا يمكنها إرسال الأحداث.

## الموافقة على التغييرات

تطلب عمليات الكتابة منك أولاً ما إذا كان عميلك يمكنه عرض الموجه. ترى ما سيتغير وتحدد **الموافقة على هذا التغيير** للمتابعة. إذا رفضت أو لم ترد خلال حوالي 4 دقائق، فلن يتغير شيء. قد يتوقف بعض العملاء عن الانتظار بعد دقيقة واحدة، لذا يرجى الرد بسرعة.

<Warning>
  العميل الذي لا يدعم الموجهات لا يُطلب منه، وتعمل عملية الكتابة بمجرد أن يقوم العميل باستدعاء. هناك، التأكيد الخاص بعميلك هو الوحيد، لذا أبقِ على أدوات الكتابة مُفعّلة.
</Warning>

## التطبيقات المتصلة والإلغاء

**الإعدادات → التكاملات → MCP** يسرد تطبيقاتك المتصلة في المنظمة الحالية، مع أذوناتها وآخر استخدام. **الإلغاء** يقطع التطبيق فوراً. سيؤدي إزالة الخادم في عميلك إلى إلغاء الاتصال أيضاً.

يمكنك الاتصال بحد أقصى 5 تطبيقات لكل منظمة. سيؤدي توصيل نفس التطبيق مرة أخرى إلى استبدال اتصاله السابق.

## النشرات ذاتية الاستضافة

اختر **Failproof AI Cloud ذاتي الاستضافة** عند الاتصال، وأدخل العنوان الذي تسجل الدخول فيه. يجب أن يكون نشرك قابلاً للوصول عبر HTTPS عام.

تمر استدعاءات الأدوات ونتائجها عبر بوابة Failproof AI المستضافة في طريقها بين أداة الذكاء الاصطناعي والنشر الخاص بك. لا تخزنها البوابة.

## ما يحدث لبيانات الخاص بك

تذهب النتائج إلى أداة الذكاء الاصطناعي التي ربطتها، ويتعامل معها موفر الأداة بموجب شروطه الخاصة. لكل استدعاء أداة، يسجل Failproof AI اسم الأداة ونتيجتها ومدة استغراقها والمنظمة، ولا يسجل الحجج أو النتائج أبداً. انظر [سياسة الخصوصية](https://befailproof.ai/privacy/).
