وصّل أداة ذكاء اصطناعي إلى Failproof AI Cloud واعمل مع بيانات وكلائك منها. يمكن لأداتك الاستعلام عن الجلسات والأحداث، وتشغيل SQL للقراءة فقط، وقراءة لوحات المعلومات والتنبيهات والرؤى والتدقيقات والسياسات، وإذا كان لديك الإذن، إجراء تغييرات مثل إنشاء تنبيه أو نشر سياسة.

كل استدعاء يعمل بـ **أذوناتك الخاصة**، في **منظمة واحدة** تختارها عند الاتصال.

هناك عنوان واحد للجميع، مستضاف أو مستضاف ذاتياً:

```text
https://gateway.befailproof.ai/mcp
```

## وصّل عميلاً

أضف العنوان إلى عميلك. في المرة الأولى التي تُستخدم فيها أداة، يفتح متصفحك. اختر مكان وجود Failproof AI Cloud الخاص بك، وسجّل دخولك، واختر منظمة واحدة، وحدد **السماح**. **إلغاء** لا يوصل أي شيء.

تسمي الصفحة التطبيق وحيث يعود. يتم وضع علامة على التطبيق الذي لم يتم تحديده بعنوان ويب خاص به **تطبيق غير موثّق**، لذا تابع فقط إذا بدأت هذا للتو من عميلك الخاص.

<Tabs>
  <Tab title="Claude">
    في claude.ai أو Claude Desktop، انتقل إلى **الإعدادات → الموصلات → إضافة موصل مخصص**. سمّه `Failproof AI`، أدخل العنوان، حدد **إضافة**، ثم **اتصل**.

    في خطط Team و Enterprise، يضيف المالك الموصل للمنظمة أولاً. ثم يتصل كل شخص بحسابه الخاص.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    ثم شغّل `/mcp` داخل Claude Code، واختر `failproofai`، واختر **المصادقة**.
  </Tab>
  <Tab title="Cursor">
    أضف هذا إلى `~/.cursor/mcp.json`، أو إلى ملف `.cursor/mcp.json` في مشروعك:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    يعرض Cursor **يتطلب تسجيل دخول** بجانب الخادم. حدده لتسجيل الدخول.
  </Tab>
  <Tab title="Codex">
    أضف هذا إلى `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    ثم شغّل `codex mcp login failproofai`.
  </Tab>
  <Tab title="عملاء آخرون">
    أي عميل يدعم خوادم MCP البعيدة على HTTP قابل للبث مع OAuth يعمل. أعطه العنوان أعلاه. لا توجد معرّف عميل أو سر لتكوينه.
  </Tab>
</Tabs>

## منظمة واحدة لكل اتصال

الاتصال يعمل فقط في المنظمة التي اخترتها. لاستخدام منظمتين، أضف الخادم مرتين باسم مختلف، مثل `failproofai-acme` و `failproofai-sandbox`، وصّل كل واحد إلى منظمته الخاصة.

منظمات العرض التوضيحي لا تقبل الاتصالات. اختر منظمتك الخاصة بدلاً من ذلك.

## الأذونات

الاتصال يمكنه فعل ما يمكنك فعله في المنظمة، ضمن المجموعة أدناه. يتابع أذوناتك الحالية: إذا أعطاك مسؤول المزيد، تحصل الأداة عليه، وإذا أزالوا شيئاً ما، تفقده الأداة عند استدعائها التالي.

| الإذن | يسمح للأداة بـ |
| --- | --- |
| `events:read` | عرض قائمة الأحداث، قراءة نظرة عامة على الجلسة، عرض قائمة الوكلاء والبيئات |
| `evaluations:read` | عرض قائمة الجلسات، قراءة وتلخيص نتائج التقييمات والمهام |
| `evaluations:trigger` | إنشاء التقييمات، نشر إصدارات جديدة، تشغيلها أو إيقافها، الملء الرجعي، وإعادة تقييم جلسة |
| `dashboards:read`, `dashboards:write` | قراءة لوحات المعلومات، أو إنشاء وإعادة تسمية وإضافة استعلامات إليها |
| `queries:read`, `queries:write` | قراءة الاستعلامات المحفوظة، أو حفظها وتحريرها |
| `queries:run` | تشغيل استعلام SQL واحد للقراءة فقط وقراءة مخطط الاستعلام |
| `alerts:read`, `alerts:write` | قراءة التنبيهات، أو إنشاء وتحرير وإيقاف وحذف واختبار التنبيهات |
| `issues:read` | قراءة الرؤى، الاعتراف بها، والتعليق عليها |
| `issues:create` | فتح رؤية على تنبيه |
| `issues:close` | حل وإغلاق الرؤى |
| `audits:read`, `audits:write` | قراءة التدقيقات والعمليات والنتائج، أو إنشاء وتحرير التدقيقات وبدء عملية |
| `code_fixes:read` | معرفة كيفية إصلاح رؤية، والحصول على سياقها لوكيلك الخاص لإصلاحها |
| `code_fixes:write` | بدء إصلاح في Failproof AI Cloud، الذي يفتح طلب سحب على GitHub الخاص بك |
| `policies:read`, `policies:write` | قراءة السياسات والآلات والنشرات، أو نشر وتوزيع والتراجع عن السياسات |

عدد قليل من الأدوات لا تحتاج أذن لأنها لا تقرأ بيانات المنظمة: بناء روابط الجلسة والحدث، والبحث في هذه الوثائق.

لا يمكن لأداة ذكاء اصطناعي أن تلمس مفاتيح API أو المستخدمين أو الإعدادات أو إدارة المنظمة، ولا يمكنها إرسال أحداث.

## الموافقة على التغييرات

الكتابات تطلب منك أولاً إذا كان عميلك يمكنه عرض الموجه. ترى ما سيتغير وتحدد **الموافقة على هذا التغيير** للمتابعة. إذا رفضت أو لم ترد خلال حوالي 4 دقائق، لا شيء يتغير. قد يتوقف بعض العملاء عن الانتظار بعد دقيقة واحدة، لذا رد بسرعة.

<Warning>
  العميل الذي لا يدعم الموجهات لا يُسأل، وتعمل الكتابة حالما يقوم العميل بالاستدعاء. هناك، تأكيد عميلك الخاص هو الوحيد، لذا احتفظ به على أدوات الكتابة.
</Warning>

## التطبيقات المتصلة والإلغاء

**الإعدادات → التكاملات → MCP** تسرد تطبيقاتك المتصلة في المنظمة الحالية، مع أذوناتها واستخدامها الأخير. **إلغاء** يقطع تطبيق فوراً. إزالة الخادم في عميلك تلغي الاتصال أيضاً.

يمكنك أن يكون لديك حتى 5 تطبيقات متصلة لكل منظمة. توصيل نفس التطبيق مرة أخرى يستبدل اتصاله السابق.

## النشرات المستضافة ذاتياً

اختر **Failproof AI Cloud المستضاف ذاتياً** عند الاتصال، وأدخل العنوان الذي تسجل دخولك به. يجب أن يكون نشرك قابلاً للوصول عبر HTTPS العام.

استدعاءات الأداة ونتائجها تمر عبر بوابة Failproof AI المستضافة في طريقها بين أداة ذكاء اصطناعك ونشرك. البوابة لا تخزنها.

## ماذا يحدث لبيانانك

تذهب النتائج إلى أداة الذكاء الاصطناعي التي وصّلتها، ومزود تلك الأداة يتعاملها بموجب شروطه الخاصة. لكل استدعاء أداة، يسجل Failproof AI اسم الأداة ونتيجتها والمدة المستغرقة والمنظمة، أبداً الحجج أو النتائج. انظر [سياسة الخصوصية](https://befailproof.ai/privacy/).

## استكشاف الأخطاء

| ما تراه | ما يجب فعله |
| --- | --- |
| "بدأ في متصفح آخر" | أنهِ تسجيل الدخول في المتصفح الذي فتحه العميل، مع السماح بملفات تعريف الارتباط، وابدأ مرة أخرى من العميل |
| خطأ بعد **السماح** | الرابط يعمل مرة واحدة وينتهي بعد 10 دقائق، لذا ابدأ مرة أخرى من العميل |
| أداة كنت تتوقعها مفقودة | أنت لا تملك إذن لها في هذه المنظمة. اطلب من المسؤول. أنت لا تحتاج للإعادة اتصال بمجرد حصولك عليها |
| العميل يستمر في طلب تسجيل الدخول | تم إلغاء الاتصال، أو تركت المنظمة، أو لم تُستخدم لمدة 90 يوماً. اتصل مرة أخرى |
| "لديك 5 تطبيقات متصلة" | ألغِ واحداً تحت **الإعدادات → التكاملات → MCP**، ثم اتصل مرة أخرى |
