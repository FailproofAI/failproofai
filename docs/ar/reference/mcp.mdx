اربط أداة ذكاء اصطناعي بـ Failproof AI Cloud والعمل ببيانات وكلائك منها. يمكن لأداتك الاستعلام عن الجلسات والأحداث، وتشغيل SQL للقراءة فقط، وقراءة لوحات المعلومات والتنبيهات والمشاكل والتدقيقات والسياسات، وإذا كنت تمتلك الصلاحية، إجراء تغييرات مثل إنشاء تنبيه أو نشر سياسة.

كل استدعاء يعمل بـ **صلاحياتك الخاصة**، في **مؤسسة واحدة** تختارها عند الربط.

يوجد عنوان واحد للجميع، مستضاف أو موزع ذاتياً:

```text
https://gateway.befailproof.ai/mcp
```

## ربط عميل

أضف العنوان إلى عميلك. في المرة الأولى التي يتم فيها استخدام أداة، يفتح المتصفح الخاص بك. اختر مكان وجود Failproof AI Cloud الخاص بك، وسجل دخولك، واختر مؤسسة واحدة، وحدد **السماح**. **الإلغاء** لا يربط شيئاً.

تسمي الصفحة التطبيق والمكان الذي يعود إليه. يتم وضع علامة على التطبيق الذي لا يتم تحديده من خلال عنوان الويب الخاص به **تطبيق غير موثق**، لذا تابع فقط إذا بدأت للتو هذا من عميلك الخاص.

<Tabs>
  <Tab title="Claude">
    في claude.ai أو Claude Desktop، انتقل إلى **الإعدادات → الموصلات → إضافة موصل مخصص**. أطلق عليها اسم `Failproof AI`، أدخل العنوان، حدد **إضافة**، ثم **الربط**.

    في خطط Team و Enterprise، يضيف المالك الموصل للمؤسسة أولاً. يقوم كل شخص بعد ذلك بربط حسابه الخاص.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    ثم قم بتشغيل `/mcp` داخل Claude Code، وحدد `failproofai`، واختر **المصادقة**.
  </Tab>
  <Tab title="Cursor">
    أضف هذا إلى `~/.cursor/mcp.json`، أو إلى `.cursor/mcp.json` في مشروعك:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    يعرض Cursor **يتطلب تسجيل دخول** بجانب الخادم. حدده للتوقيع.
  </Tab>
  <Tab title="Codex">
    أضف هذا إلى `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    ثم قم بتشغيل `codex mcp login failproofai`.
  </Tab>
  <Tab title="عملاء آخرون">
    أي عميل يدعم خوادم MCP البعيدة عبر Streamable HTTP مع OAuth يعمل. أعطه العنوان أعلاه. لا توجد معرّف عميل أو سر للتكوين.
  </Tab>
</Tabs>

## مؤسسة واحدة لكل اتصال

يعمل الاتصال فقط في المؤسسة التي اخترتها. لاستخدام مؤسستين، أضف الخادم مرتين تحت أسماء مختلفة، مثل `failproofai-acme` و `failproofai-sandbox`، وربط كل واحد بمؤسستها الخاصة.

المؤسسات التوضيحية لا تقبل الاتصالات. اختر مؤسستك الخاصة بدلاً من ذلك.

## الصلاحيات

يمكن للاتصال أن يفعل ما يمكنك فعله في المؤسسة، ضمن المجموعة أدناه. إنه يتبع صلاحياتك الحالية: إذا أعطاك مسؤول المزيد، تحصل الأداة عليها، وإذا أخذها، تفقدها الأداة في استدعاؤها التالي.

| الصلاحية | تسمح الأداة |
| --- | --- |
| `events:read` | سرد الأحداث، وقراءة نظرة عامة على الجلسة، وسرد الوكلاء والبيئات |
| `evaluations:read` | سرد الجلسات، وقراءة وتلخيص نتائج التقييم والوظائف |
| `evaluations:trigger` | إنشاء تقييمات، ونشر نسخ جديدة، وتشغيلها أو إيقافها، والملء الخلفي، وإعادة تقييم جلسة |
| `dashboards:read`, `dashboards:write` | قراءة لوحات المعلومات، أو إنشاء وإعادة تسمية وإضافة استعلامات إليها |
| `queries:read`, `queries:write` | قراءة الاستعلامات المحفوظة، أو حفظ وتحريرها |
| `queries:run` | تشغيل استعلام SQL للقراءة فقط واحد وقراءة مخطط الاستعلام |
| `alerts:read`, `alerts:write` | قراءة التنبيهات، أو إنشاء وتحرير وإيقاف حمايتها وحذفها واختبارها |
| `issues:read` | قراءة المشاكل والاعتراف بها والتعليق عليها |
| `issues:create` | فتح مشكلة على تنبيه |
| `issues:close` | حل وإغلاق المشاكل |
| `audits:read`, `audits:write` | قراءة التدقيقات والتشغيلات والنتائج، أو إنشاء وتحرير التدقيقات وبدء التشغيل |
| `code_fixes:read` | معرفة كيفية إصلاح مشكلة والحصول على سياقها لوكيلك الخاص للإصلاح |
| `code_fixes:write` | بدء إصلاح في Failproof AI Cloud، الذي يفتح طلب دمج على GitHub الخاص بك |
| `policies:read`, `policies:write` | قراءة السياسات والأجهزة والنشرات، أو نشر وتطبيق وإرجاع السياسات |

بعض الأدوات لا تحتاج إلى صلاحية لأنها لا تقرأ بيانات المؤسسة: بناء روابط الجلسة والحدث، والبحث في هذه التوثيق.

لا يمكن لأداة ذكاء اصطناعي أبداً لمس مفاتيح API أو المستخدمين أو الإعدادات أو إدارة المؤسسة، ولا يمكنها إرسال الأحداث.

## الموافقة على التغييرات

تطلب الكتابات منك أولاً إذا كان عميلك قادراً على عرض الموجه. ترى ما سيتغير وتحدد **الموافقة على هذا التغيير** للمتابعة. إذا رفضت أو لم تجب خلال حوالي 4 دقائق، فلن يتغير شيء. قد يتوقف بعض العملاء عن الانتظار بعد دقيقة، لذا أجب بسرعة.

<Warning>
  العميل الذي لا يدعم الموجهات لن يُطلب منه، وتعمل الكتابة بمجرد أن يقوم العميل بالاستدعاء. هناك، تأكيد عميلك الخاص هو الوحيد، لذا ابقه قيد التشغيل لأدوات الكتابة.
</Warning>

## التطبيقات المتصلة والإلغاء

**الإعدادات → التكاملات → MCP** تسرد تطبيقاتك المتصلة في المؤسسة الحالية، مع صلاحياتها وآخر استخدام. **الإلغاء** يقطع التطبيق فوراً. إزالة الخادم في عميلك تلغي الاتصال أيضاً.

يمكنك الحصول على ما يصل إلى 5 تطبيقات متصلة لكل مؤسسة. الربط بنفس التطبيق مرة أخرى يستبدل اتصاله السابق.

## النشرات الموزعة ذاتياً

اختر **Failproof AI Cloud الموزع ذاتياً** عند الربط، وأدخل العنوان الذي تسجل دخولك فيه. يجب أن يكون النشر الخاص بك قابلاً للوصول عبر HTTPS العام.

تمر استدعاءات الأداة ونتائجها عبر بوابة Failproof AI المستضافة في طريقهما بين أداة الذكاء الاصطناعي والنشر الخاص بك. البوابة لا تخزنها.

## ما يحدث لبيانات الأشخاص الآخرين

تذهب النتائج إلى أداة الذكاء الاصطناعي التي ربطتها، ومزود هذه الأداة يتعامل معها بموجب شروطه الخاصة. لكل استدعاء أداة، يسجل Failproof AI اسم الأداة ونتيجتها والوقت الذي استغرقته والمؤسسة، أبداً الحجج أو النتائج. انظر [سياسة الخصوصية](https://befailproof.ai/privacy/).

## استكشاف الأخطاء والمشاكل

| ما تراه | ما يجب فعله |
| --- | --- |
| بدأ في متصفح آخر | أنهِ التوقيع في المتصفح الذي فتحه العميل، مع السماح بملفات تعريف الارتباط، وابدأ مرة أخرى من العميل |
| خطأ بعد **السماح** | الرابط يعمل مرة واحدة وينتهي بعد 10 دقائق، لذا ابدأ مرة أخرى من العميل |
| أداة متوقعة مفقودة | لا تمتلك صلاحيتها في هذه المؤسسة. اطلب من المسؤول. لا تحتاج إلى إعادة الاتصال بمجرد حصولك عليها |
| العميل يستمر في طلب التوقيع | تم إلغاء الاتصال أو تركت المؤسسة أو لم يتم استخدامها لمدة 90 يوماً. اتصل مرة أخرى |
| لديك 5 تطبيقات متصلة | ألغِ واحداً تحت **الإعدادات → التكاملات → MCP**، ثم اتصل مرة أخرى |
