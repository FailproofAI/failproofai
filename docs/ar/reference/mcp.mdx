قم بتوصيل أداة ذكاء اصطناعي بـ Failproof AI Cloud واعمل مع بيانات وكلائك منها. يمكن لأداتك الاستعلام عن الجلسات والأحداث، وتشغيل SQL للقراءة فقط، وقراءة لوحات المعلومات والتنبيهات والمشاكل والتدقيقات والسياسات، وإذا كنت تمتلك الصلاحية، إجراء تغييرات مثل إنشاء تنبيه أو نشر سياسة.

كل استدعاء يتم تشغيله بـ **صلاحياتك الخاصة**، في **منظمة واحدة** تختارها عند الاتصال.

هناك عنوان واحد للجميع، مستضاف أو ذاتي الاستضافة:

```text
https://gateway.befailproof.ai/mcp
```

## توصيل عميل

أضف العنوان إلى عميلك. في المرة الأولى التي يتم فيها استخدام أداة، يتم فتح متصفحك. اختر مكان استضافة Failproof AI Cloud، سجل الدخول، اختر منظمة واحدة، واختر **Allow**. **Cancel** لن يوصل أي شيء.

تسمي الصفحة التطبيق والمكان الذي يعود إليه. يتم تعليم التطبيق الذي لا يتم تحديده من خلال عنوان ويب خاص به بـ **unverified app**، لذا تابع فقط إذا بدأت للتو هذا من عميلك الخاص.

<Tabs>
  <Tab title="Claude">
    في claude.ai أو Claude Desktop، انتقل إلى **Settings → Connectors → Add custom connector**. سمّه `Failproof AI`، أدخل العنوان، اختر **Add**، ثم **Connect**.

    في خطط Team و Enterprise، يضيف المالك الموصل للمنظمة أولاً. ثم يقوم كل شخص بتوصيل حسابه الخاص.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    ثم قم بتشغيل `/mcp` داخل Claude Code، واختر `failproofai`، واختر **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    أضف هذا إلى `~/.cursor/mcp.json`، أو إلى ملف المشروع الخاص بك `.cursor/mcp.json`:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    يعرض Cursor **Needs login** بجوار الخادم. اختره لتسجيل الدخول.
  </Tab>
  <Tab title="Codex">
    أضف هذا إلى `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    ثم قم بتشغيل `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    أي عميل يدعم خوادم MCP البعيدة عبر Streamable HTTP مع OAuth يعمل. أعطه العنوان أعلاه. لا يوجد معرّف عميل أو سر للتكوين.
  </Tab>
</Tabs>

## منظمة واحدة لكل اتصال

يعمل الاتصال فقط في المنظمة التي اخترتها. لاستخدام منظمتين، أضف الخادم مرتين تحت أسماء مختلفة، مثل `failproofai-acme` و `failproofai-sandbox`، وقم بتوصيل كل واحد بمنظمته الخاصة.

المنظمات التجريبية لا تقبل الاتصالات. اختر منظمتك الخاصة بدلاً من ذلك.

## الصلاحيات

يمكن للاتصال أن يفعل ما يمكنك فعله في المنظمة، ضمن المجموعة أدناه. يتبع صلاحياتك الحالية: إذا أعطاك المسؤول المزيد، ستحصل الأداة عليه، وإذا أخذوا شيئاً ما، ستفقده الأداة في استدعاءها التالي.

| الصلاحية | تسمح للأداة بـ |
| --- | --- |
| `events:read` | قائمة الأحداث، قراءة نظرة عامة على الجلسة، قائمة الوكلاء والبيئات |
| `evaluations:read` | قائمة الجلسات، وقراءة وتلخيص نتائج التقييم والوظائف |
| `evaluations:trigger` | إنشاء التقييمات، نشر الإصدارات الجديدة، تشغيلها أو إيقاف تشغيلها، الملء بأثر رجعي، وإعادة تقييم الجلسة |
| `dashboards:read`, `dashboards:write` | قراءة لوحات المعلومات، أو إنشاء وإعادة تسمية والبحث عن الاستعلامات |
| `queries:read`, `queries:write` | قراءة الاستعلامات المحفوظة، أو حفظ وتحريرها |
| `queries:run` | تشغيل استعلام SQL واحد للقراءة فقط وقراءة مخطط الاستعلام |
| `alerts:read`, `alerts:write` | قراءة التنبيهات، أو إنشاء وتحرير وإيقاف وحذف واختبار التنبيهات |
| `issues:read` | قراءة المشاكل والإقرار بها والتعليق عليها |
| `issues:create` | فتح مشكلة على تنبيه |
| `issues:close` | حل وإغلاق المشاكل |
| `audits:read`, `audits:write` | قراءة التدقيقات والتشغيلات والنتائج، أو إنشاء وتحرير التدقيقات وبدء التشغيل |
| `code_fixes:read` | معرفة كيفية إصلاح المشكلة والحصول على سياقها لوكيلك الخاص لإصلاحها |
| `code_fixes:write` | بدء إصلاح في Failproof AI Cloud، الذي يفتح طلب سحب على GitHub الخاص بك |
| `policies:read`, `policies:write` | قراءة السياسات والآلات والنشرات، أو نشر وتطبيق والتراجع عن السياسات |

بعض الأدوات لا تحتاج إلى صلاحية لأنها لا تقرأ بيانات المنظمة: بناء روابط الجلسة والحدث، والبحث في هذه الوثائق.

لا يمكن لأداة ذكاء اصطناعي أن تلمس مفاتيح API أو المستخدمين أو الإعدادات أو إدارة المنظمة، وليس بإمكانها إرسال أحداث.

## الموافقة على التغييرات

الكتابات تطلب منك أولاً إذا كان عميلك يمكنه إظهار المطالبة. ترى ما سيتغير واختر **Approve this change** للمتابعة. إذا رفضت أو لم تجب في غضون حوالي 4 دقائق، فلن يحدث شيء. قد يتوقف بعض العملاء عن الانتظار بعد دقيقة واحدة، لذا أجب بسرعة.

<Warning>
  العميل الذي لا يدعم المطالبات لن يُسأل، والكتابة تعمل بمجرد أن يقوم العميل بالاستدعاء. هناك، تأكيد عميلك الخاص هو الوحيد، لذا اجعله قيد التشغيل لأدوات الكتابة.
</Warning>

## التطبيقات المتصلة والإلغاء

**Settings → Integrations → MCP** يسرد تطبيقاتك المتصلة في المنظمة الحالية، مع صلاحياتها والاستخدام الأخير. **Revoke** يقطع التطبيق على الفور. إزالة الخادم في عميلك تلغي الاتصال أيضاً.

يمكن أن يكون لديك ما يصل إلى 5 تطبيقات متصلة لكل منظمة. توصيل نفس التطبيق مرة أخرى يستبدل اتصاله السابق.

## النشرات ذاتية الاستضافة

اختر **Self-hosted Failproof AI Cloud** عند الاتصال، وأدخل العنوان الذي تسجل الدخول فيه. يجب أن تكون نشرتك قابلة للوصول عبر HTTPS العام.

استدعاءات الأداة والنتائج تمر عبر بوابة Failproof AI المستضافة في طريقها بين أداتك في الذكاء الاصطناعي ونشرتك. البوابة لا تخزنها.

## ما يحدث لبيانانك

تذهب النتائج إلى أداة الذكاء الاصطناعي التي وصلتها، ويتعامل مزود تلك الأداة معها بموجب شروطه الخاصة. لكل استدعاء أداة، يسجل Failproof AI اسم الأداة ونتيجتها ومدة استغراقها والمنظمة، وليس الحجج أو النتائج. انظر [privacy policy](https://befailproof.ai/privacy/).

## استكشاف الأخطاء

| ما تراه | ما يجب فعله |
| --- | --- |
| "Started in another browser" | أنهِ تسجيل الدخول في المتصفح الذي فتحه العميل، مع السماح بملفات تعريف الارتباط، وابدأ مرة أخرى من العميل |
| خطأ بعد **Allow** | الرابط يعمل مرة واحدة وينتهي صلاحيته بعد 10 دقائق، لذا ابدأ مرة أخرى من العميل |
| أداة كنت تتوقعها مفقودة | أنت لا تحمل صلاحيتها في هذه المنظمة. اطلب من المسؤول. لا تحتاج إلى إعادة الاتصال بمجرد حصولك عليها |
| العميل يستمر في طلب تسجيل الدخول | تم إلغاء الاتصال أو غادرت المنظمة أو لم يتم استخدامها لمدة 90 يوماً. قم بالاتصال مرة أخرى |
| "You have 5 connected apps" | ألغِ واحداً تحت **Settings → Integrations → MCP**، ثم قم بالاتصال مرة أخرى |
