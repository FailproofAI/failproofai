اتصل بأداة ذكاء اصطناعي بـ Failproof AI Cloud واعمل مع بيانات وكلائك منها. يمكن لأداتك الاستعلام عن الجلسات والأحداث، وتشغيل SQL للقراءة فقط، وقراءة لوحات المعلومات والتنبيهات والمشاكل والتدقيقات والسياسات، وإذا كنت تملك الإذن، إجراء تغييرات مثل إنشاء تنبيه أو نشر سياسة.

كل استدعاء يعمل بـ **أذوناتك الخاصة**، في **منظمة واحدة** تختارها عند الاتصال.

هناك عنوان واحد للجميع، مستضاف أو مستضاف ذاتياً:

```text
https://gateway.befailproof.ai/mcp
```

## اتصل بعميل

أضف العنوان إلى عميلك. في المرة الأولى التي تستخدم فيها أداة، يفتح متصفحك. اختر مكان Failproof AI Cloud الخاص بك، وسجل الدخول، واختر منظمة واحدة، وحدد **السماح**. يربط **إلغاء الأمر** لا شيء.

تسمي الصفحة التطبيق والمكان الذي يعود إليه. يتم وضع علامة على التطبيق الذي لم يتم تحديده برقم عنوان ويب خاص به **تطبيق غير معرّف**، لذا تابع فقط إذا بدأت للتو هذا من عميلك الخاص.

<Tabs>
  <Tab title="Claude">
    في claude.ai أو Claude Desktop، انتقل إلى **الإعدادات → الموصلات → إضافة موصل مخصص**. سمّه `Failproof AI`، أدخل العنوان، حدد **إضافة**، ثم **اتصل**.

    في خطط Team و Enterprise، يضيف المالك الموصل للمنظمة أولاً. ثم يتصل كل شخص بحسابه الخاص.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    ثم قم بتشغيل `/mcp` داخل Claude Code، وحدد `failproofai`، واختر **المصادقة**.
  </Tab>
  <Tab title="Cursor">
    أضف هذا إلى `~/.cursor/mcp.json`، أو إلى `.cursor/mcp.json` الخاص بمشروعك:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    يُظهر Cursor **يحتاج إلى تسجيل دخول** بجانب الخادم. حدده لتسجيل الدخول.
  </Tab>
  <Tab title="Codex">
    أضف هذا إلى `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    ثم قم بتشغيل `codex mcp login failproofai`.
  </Tab>
  <Tab title="عملاء آخرون">
    أي عميل يدعم خوادم MCP البعيدة على HTTP قابل للبث مع OAuth يعمل. أعطه العنوان أعلاه. لا توجد معرّف عميل أو سر يجب تكوينه.
  </Tab>
</Tabs>

## منظمة واحدة لكل اتصال

الاتصال يعمل فقط في المنظمة التي اخترتها. لاستخدام منظمتين، أضف الخادم مرتين تحت أسماء مختلفة، مثل `failproofai-acme` و `failproofai-sandbox`، وقم بربط كل منها بمنظمتها الخاصة.

المنظمات التجريبية لا تقبل الاتصالات. اختر منظمتك الخاصة بدلاً من ذلك.

## الأذونات

الاتصال يمكنه فعل ما يمكنك فعله في المنظمة، ضمن المجموعة أدناه. يتبع أذوناتك الحالية: إذا أعطاك الإدارة المزيد، تكتسب الأداة، وإذا أخذوا شيئاً ما، تفقده الأداة في استدعاءها التالي.

| الإذن | تسمح الأداة |
| --- | --- |
| `events:read` | إدراج الأحداث، قراءة نظرة عامة على الجلسة، إدراج الوكلاء والبيئات |
| `evaluations:read` | إدراج الجلسات، قراءة وتلخيص نتائج التقييم والمهام |
| `evaluations:trigger` | إنشاء التقييمات، نشر إصدارات جديدة، تشغيلها أو إيقافها، الملء الخلفي، وإعادة تقييم جلسة |
| `dashboards:read`, `dashboards:write` | قراءة لوحات المعلومات، أو إنشاء وإعادة تسمية وإضافة استعلامات إليها |
| `queries:read`, `queries:write` | قراءة الاستعلامات المحفوظة، أو حفظ وتحريرها |
| `queries:run` | تشغيل استعلام SQL واحد للقراءة فقط وقراءة مخطط الاستعلام |
| `alerts:read`, `alerts:write` | قراءة التنبيهات، أو إنشاء وتحرير وإيقاف وحذف واختبار التنبيهات |
| `issues:read` | قراءة المشاكل، والإقرار بها، والتعليق عليها |
| `issues:create` | فتح مشكلة في تنبيه |
| `issues:close` | حل وإغلاق المشاكل |
| `audits:read`, `audits:write` | قراءة التدقيقات والمشغلات والنتائج، أو إنشاء وتحرير التدقيقات وبدء تشغيل |
| `code_fixes:read` | معرفة كيفية إصلاح مشكلة، والحصول على سياقها لوكيلك الخاص لإصلاحها |
| `code_fixes:write` | بدء إصلاح في Failproof AI Cloud، الذي يفتح طلب دمج على GitHub الخاص بك |
| `policies:read`, `policies:write` | قراءة السياسات والآلات والنشرات، أو نشر وتطبيق ورجوع السياسات |

قد تحتاج بعض الأدوات إلى عدم وجود إذن لأنها لا تقرأ بيانات المنظمة: بناء روابط الجلسة والحدث، والبحث في هذه الوثائق.

لا يمكن لأداة ذكاء اصطناعي التعامل مع مفاتيح API أو المستخدمين أو الإعدادات أو إدارة المنظمة، ولا يمكنها إرسال أحداث.

## الموافقة على التغييرات

الكتابة تطلب منك أولاً إذا كان عميلك يمكنه عرض الموجه. ترى ما سيتغير وتحدد **الموافقة على هذا التغيير** للمتابعة. إذا رفضت أو لم تجب في غضون حوالي 4 دقائق، فلن يتغير شيء. قد يتوقف بعض العملاء عن الانتظار بعد دقيقة واحدة، لذا أجب بسرعة.

<Warning>
  العميل الذي لا يدعم الموجهات لا يُسأل، والكتابة تعمل فور قيام العميل بالاستدعاء. هناك، تأكيد عميلك الخاص هو الوحيد، لذا أبقها مفعلة لأدوات الكتابة.
</Warning>

## التطبيقات المتصلة وإلغاء الاتصال

**الإعدادات → المدمجة → MCP** يسرد تطبيقاتك المتصلة في المنظمة الحالية، مع أذوناتها واستخدامها الأخير. يقطع **إلغاء الاتصال** تطبيقاً في الحال. إزالة الخادم في عميلك تلغي الاتصال أيضاً.

يمكنك الحصول على ما يصل إلى 5 تطبيقات متصلة لكل منظمة. ربط نفس التطبيق مرة أخرى يستبدل اتصاله السابق.

## النشرات المستضافة ذاتياً

اختر **Failproof AI Cloud المستضاف ذاتياً** عند الاتصال، وأدخل العنوان الذي تسجل الدخول إليه. يجب أن يكون نشرك قابلاً للوصول عبر HTTPS العام.

استدعاءات الأداة ونتائجها تمر عبر بوابة Failproof AI المستضافة في طريقها بين أداة الذكاء الاصطناعي الخاصة بك والنشر. لا تخزنها البوابة.

## ما يحدث لبياناتك

النتائج تذهب إلى أداة الذكاء الاصطناعي التي اتصلت بها، ومزود تلك الأداة يتعامل معها بموجب شروطه الخاصة. لكل استدعاء أداة، يسجل Failproof AI اسم الأداة ونتيجتها ومدة استغراقها والمنظمة، أبداً الحجج أو النتائج. راجع [سياسة الخصوصية](https://befailproof.ai/privacy/).

## استكشاف الأخطاء

| ما تراه | ما يجب فعله |
| --- | --- |
| "بدأ في متصفح آخر" | أنهِ تسجيل الدخول في المتصفح الذي فتحه العميل، مع السماح بملفات تعريف الارتباط، وابدأ مرة أخرى من العميل |
| خطأ بعد **السماح** | الرابط يعمل مرة واحدة وينتهي الصلاحية بعد 10 دقائق، لذا ابدأ مرة أخرى من العميل |
| أداة توقعتها مفقودة | أنت لا تملك إذنها في هذه المنظمة. اطلب من الإدارة. لا تحتاج إلى إعادة الاتصال بمجرد حصولك عليها |
| العميل يستمر في طلب تسجيل الدخول | تم إلغاء الاتصال، أو تركت المنظمة، أو لم تُستخدم لمدة 90 يوماً. اتصل مرة أخرى |
| "لديك 5 تطبيقات متصلة" | ألغِ اتصال واحد تحت **الإعدادات → المدمجة → MCP**، ثم اتصل مرة أخرى |
