وصّل أداة ذكاء اصطناعي إلى Failproof AI Cloud واعمل مع بيانات وكلائك منها. يمكن لأداتك الاستعلام عن الجلسات والأحداث، وتشغيل SQL للقراءة فقط، وقراءة لوحات التحكم والتنبيهات والرؤى والتدقيقات والسياسات، وإذا كان لديك الإذن، إجراء تغييرات مثل إنشاء تنبيه أو نشر سياسة.

كل استدعاء يعمل بـ **أذوناتك الخاصة**، في **منظمة واحدة** تختارها عند الاتصال.

هناك عنوان واحد للجميع، مستضاف أو مستضاف ذاتياً:

```text
https://gateway.befailproof.ai/mcp
```

## وصّل عميل

أضف العنوان إلى عميلك. في المرة الأولى التي تُستخدم فيها أداة، يفتح متصفحك. اختر مكان وجود Failproof AI Cloud الخاص بك، وسجّل الدخول، واختر منظمة واحدة، وحدد **السماح**. **الإلغاء** لا يربط أي شيء.

تسمي الصفحة التطبيق والمكان الذي يعود إليه. التطبيق الذي لا يتم تحديده بعنوانه الويب الخاص به يتم وضع علامة عليه **تطبيق غير موثّق**، لذلك تابع فقط إذا كنت قد بدأت للتو هذا من عميلك الخاص.

<Tabs>
  <Tab title="Claude">
    في claude.ai أو Claude Desktop، انتقل إلى **الإعدادات → الموصلات → إضافة موصل مخصص**. سمِّه `Failproof AI`، أدخل العنوان، حدد **إضافة**، ثم **اتصل**.

    في خطط Team و Enterprise، يضيف المالك الموصل للمنظمة أولاً. يوصّل كل شخص حسابه الخاص بعد ذلك.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    ثم شغّل `/mcp` داخل Claude Code، واختر `failproofai`، واختر **المصادقة**.
  </Tab>
  <Tab title="Cursor">
    أضف هذا إلى `~/.cursor/mcp.json`، أو إلى ملف `.cursor/mcp.json` في مشروعك:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    يعرض Cursor **يتطلب تسجيل دخول** بجانب الخادم. حدده لتسجيل الدخول.
  </Tab>
  <Tab title="Codex">
    أضف هذا إلى `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    ثم شغّل `codex mcp login failproofai`.
  </Tab>
  <Tab title="عملاء آخرون">
    أي عميل يدعم خوادم MCP البعيدة عبر HTTP قابل للبث مع OAuth يعمل. أعطه العنوان أعلاه. لا يوجد معرّف عميل أو سر لتكوينه.
  </Tab>
</Tabs>

## منظمة واحدة لكل اتصال

الاتصال يعمل فقط في المنظمة التي اخترتها. لاستخدام منظمتين، أضف الخادم مرتين باسمين مختلفين، مثل `failproofai-acme` و `failproofai-sandbox`، ووصّل كل واحد إلى منظمته الخاصة.

منظمات العرض التوضيحي لا تقبل الاتصالات. اختر منظمتك الخاصة بدلاً من ذلك.

## الأذونات

يمكن للاتصال أن يفعل ما يمكنك فعله في المنظمة، ضمن المجموعة أدناه. يتبع أذوناتك الحالية: إذا أعطاك المسؤول المزيد، تحصل الأداة عليها، وإذا أزالها، تفقدها الأداة في استدعاؤها التالي.

| الإذن | يتيح للأداة |
| --- | --- |
| `events:read` | عرض قائمة الأحداث، قراءة نظرة عامة على جلسة، عرض قائمة الوكلاء والبيئات |
| `evaluations:read` | عرض قائمة الجلسات، قراءة وتلخيص نتائج التقييمات والمهام |
| `evaluations:trigger` | إنشاء التقييمات، نشر إصدارات جديدة، تشغيلها أو إيقافها، الملء الخلفي، وإعادة تقييم جلسة |
| `dashboards:read`، `dashboards:write` | قراءة لوحات التحكم، أو إنشاء وإعادة تسمية وإضافة استعلامات إليها |
| `queries:read`، `queries:write` | قراءة الاستعلامات المحفوظة، أو حفظها وتحريرها |
| `queries:run` | تشغيل استعلام SQL واحد للقراءة فقط وقراءة مخطط الاستعلام |
| `alerts:read`، `alerts:write` | قراءة التنبيهات، أو إنشاء وتحرير وإيقافها مؤقتاً وحذفها واختبارها |
| `issues:read` | قراءة الرؤى والاعتراف بها والتعليق عليها |
| `issues:create` | فتح رؤية على تنبيه |
| `issues:close` | حل وإغلاق الرؤى |
| `audits:read`، `audits:write` | قراءة التدقيقات والتشغيلات والنتائج، أو إنشاء وتحرير التدقيقات وبدء تشغيل |
| `code_fixes:read` | رؤية كيفية إصلاح رؤية والحصول على سياقها لوكيلك الخاص لإصلاحها |
| `code_fixes:write` | بدء إصلاح في Failproof AI Cloud، الذي يفتح طلب سحب على GitHub الخاص بك |
| `policies:read`، `policies:write` | قراءة السياسات والآلات والنشرات، أو نشر ونشر والتراجع عن السياسات |

عدد قليل من الأدوات لا تحتاج إلى إذن لأنها لا تقرأ بيانات المنظمة: بناء روابط الجلسة والحدث، والبحث في هذه الوثائق.

لا يمكن لأداة ذكاء اصطناعي أن تلمس مفاتيح API أو المستخدمين أو الإعدادات أو إدارة المنظمة، ولا يمكنها إرسال أحداث.

## الموافقة على التغييرات

الكتابات تطلب منك أولاً إذا كان عميلك يمكنه عرض الموجه. ترى ما سيتغير وتحدد **الموافقة على هذا التغيير** للمتابعة. إذا رفضت أو لم تجب في غضون حوالي 4 دقائق، لا شيء يتغير. بعض العملاء يتوقفون عن الانتظار بعد دقيقة واحدة، لذلك أجب بسرعة.

<Warning>
  العميل الذي لا يدعم المحثات لا يُسأل، ويعمل الكتابة فور إجراء استدعاء العميل. هناك، تأكيد عميلك الخاص هو الوحيد، لذا احتفظ به قيد التشغيل لأدوات الكتابة.
</Warning>

## التطبيقات المتصلة والإلغاء

**الإعدادات → التكاملات → MCP** تسرد تطبيقاتك المتصلة في المنظمة الحالية، مع أذوناتها واستخدامها الأخير. **الإلغاء** يقطع تطبيق فوراً. إزالة الخادم في عميلك تلغي الاتصال أيضاً.

يمكنك الحصول على ما يصل إلى 5 تطبيقات متصلة لكل منظمة. وصل نفس التطبيق مرة أخرى يستبدل اتصاله السابق.

## النشرات المستضافة ذاتياً

اختر **Failproof AI Cloud المستضاف ذاتياً** عند الاتصال، وأدخل العنوان الذي تسجل الدخول فيه. يجب أن تكون نشرتك قابلة للوصول عبر HTTPS العام.

استدعاءات الأداة ونتائجها تمر عبر بوابة Failproof AI المستضافة في طريقها بين أداتك الذكاء الاصطناعي ونشرتك. البوابة لا تخزنها.

## ما يحدث لبياناتك

النتائج تذهب إلى أداة الذكاء الاصطناعي التي وصلتها، وموفر تلك الأداة يتعاملها بموجب شروطه الخاصة. لكل استدعاء أداة، يسجل Failproof AI اسم الأداة ونتيجتها والوقت الذي استغرقته والمنظمة، أبداً الحجج أو النتائج. انظر [سياسة الخصوصية](https://befailproof.ai/privacy/).

## استكشاف الأخطاء وإصلاحها

| ما تراه | ما تفعله |
| --- | --- |
| "بدأ في متصفح آخر" | أكمل تسجيل الدخول في المتصفح الذي فتحه العميل، مع السماح بملفات تعريف الارتباط، وابدأ مرة أخرى من العميل |
| خطأ بعد **السماح** | الرابط يعمل مرة واحدة وينتهي بعد 10 دقائق، لذا ابدأ مرة أخرى من العميل |
| أداة كنت تتوقعها مفقودة | أنت لا تملك إذنها في هذه المنظمة. اطلب من المسؤول. لا تحتاج إلى إعادة الاتصال بمجرد حصولك عليها |
| العميل يستمر في طلب تسجيل الدخول | تم إلغاء الاتصال، أو تركت المنظمة، أو ظل غير مستخدم لمدة 90 يوم. اتصل مرة أخرى |
| "لديك 5 تطبيقات متصلة" | ألغِ أحدها تحت **الإعدادات → التكاملات → MCP**، ثم اتصل مرة أخرى |
