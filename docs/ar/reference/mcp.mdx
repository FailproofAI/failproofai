توصيل أداة ذكاء اصطناعي بـ Failproof AI Cloud والعمل ببيانات وكلائك منها. يمكن لأداتك الاستعلام عن الجلسات والأحداث وتشغيل SQL للقراءة فقط وقراءة لوحات المعلومات والتنبيهات والمشاكل والمراجعات والسياسات، وإذا كنت تمتلك الإذن، إجراء تغييرات مثل إنشاء تنبيه أو نشر سياسة.

تعمل كل استدعاء بـ **أذوناتك الخاصة** في **منظمة واحدة** تختارها عند الاتصال.

يوجد عنوان واحد للجميع، سواء كان مستضافًا أو ذاتي الاستضافة:

```text
https://gateway.befailproof.ai/mcp
```

## توصيل عميل

أضف العنوان إلى عميلك. في المرة الأولى التي يتم فيها استخدام أداة، يفتح متصفحك. اختر مكان وجود Failproof AI Cloud، وقم بتسجيل الدخول، واختر منظمة واحدة، وحدد **Allow**. **Cancel** لن يوصل أي شيء.

تحدد الصفحة اسم التطبيق والمكان الذي يعود إليه. يتم وضع علامة على التطبيق الذي لا يتم تحديده بواسطة عنوانه الويب الخاص **unverified app**، لذا استمر فقط إذا بدأت للتو هذا من عميلك الخاص.

<Tabs>
  <Tab title="Claude">
    في claude.ai أو Claude Desktop، انتقل إلى **Settings → Connectors → Add custom connector**. سمِّها `Failproof AI`، أدخل العنوان، حدد **Add**، ثم **Connect**.

    في خطط Team و Enterprise، يضيف المالك الموصِّل للمنظمة أولاً. ثم يقوم كل شخص بتوصيل حسابه الخاص.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    ثم شغّل `/mcp` داخل Claude Code، وحدد `failproofai`، واختر **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    أضف هذا إلى `~/.cursor/mcp.json`، أو إلى `.cursor/mcp.json` في مشروعك:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    يعرض Cursor **Needs login** بجانب الخادم. حدده لتسجيل الدخول.
  </Tab>
  <Tab title="Codex">
    أضف هذا إلى `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    ثم شغّل `codex mcp login failproofai`.
  </Tab>
  <Tab title="عملاء آخرون">
    أي عميل يدعم خوادم MCP البعيدة عبر Streamable HTTP مع OAuth يعمل. أعطه العنوان أعلاه. لا توجد معرّف عميل أو سري للتكوين.
  </Tab>
</Tabs>

## منظمة واحدة لكل اتصال

يعمل الاتصال فقط في المنظمة التي اخترتها. لاستخدام منظمتين، أضف الخادم مرتين تحت أسماء مختلفة، مثل `failproofai-acme` و `failproofai-sandbox`، وصل كل واحد بمنظمته الخاصة.

المنظمات التجريبية لا تقبل الاتصالات. اختر منظمتك الخاصة بدلاً من ذلك.

## الأذونات

يمكن للاتصال أن يفعل ما تستطيع فعله في المنظمة، ضمن المجموعة أدناه. يتبع أذوناتك الحالية: إذا أعطاك المسؤول المزيد، تحصل الأداة عليها، وإذا أزال شيئًا ما، تفقده الأداة في استدعاؤها التالي.

| الإذن | تسمح الأداة بـ |
| --- | --- |
| `events:read` | قائمة الأحداث وقراءة نظرة عامة على الجلسة وقائمة الوكلاء والبيئات |
| `evaluations:read` | قائمة الجلسات وقراءة وتلخيص نتائج التقييم والمهام |
| `evaluations:trigger` | إنشاء تقييمات ونشر إصدارات جديدة وتشغيلها أو إيقافها والملء والتقييم مجددًا للجلسة |
| `dashboards:read`, `dashboards:write` | قراءة لوحات المعلومات أو إنشاء وإعادة تسمية وإضافة استعلامات إليها |
| `queries:read`, `queries:write` | قراءة الاستعلامات المحفوظة أو حفظ وتحريرها |
| `queries:run` | تشغيل استعلام SQL واحد للقراءة فقط وقراءة مخطط الاستعلام |
| `alerts:read`, `alerts:write` | قراءة التنبيهات أو إنشاء وتحرير وإيقاف وحذف واختبار التنبيهات |
| `issues:read` | قراءة المشاكل والإقرار بها والتعليق عليها |
| `issues:create` | فتح مشكلة حول تنبيه |
| `issues:close` | حل وإغلاق المشاكل |
| `audits:read`, `audits:write` | قراءة المراجعات والتشغيلات والنتائج أو إنشاء وتحرير المراجعات وبدء تشغيل |
| `code_fixes:read` | معرفة كيفية إصلاح مشكلة والحصول على سياقها لوكيلك الخاص للإصلاح |
| `code_fixes:write` | بدء إصلاح في Failproof AI Cloud، والذي يفتح طلب دمج على GitHub الخاص بك |
| `policies:read`, `policies:write` | قراءة السياسات والآلات والنشرات أو نشر وتطبيق ودرجة الرجوع للسياسات |

عدد قليل من الأدوات لا تحتاج إلى إذن لأنها لا تقرأ بيانات المنظمة: بناء روابط الجلسات والأحداث والبحث في هذه التوثيق.

لا يمكن لأداة ذكاء اصطناعي أبدًا أن تلمس مفاتيح API أو المستخدمين أو الإعدادات أو إدارة المنظمة، ولا يمكنها إرسال الأحداث.

## الموافقة على التغييرات

تطلب الكتابات منك أولاً إذا كان بإمكان عميلك عرض الطلب. تري ما سيتغير وتحدد **Approve this change** للمتابعة. إذا رفضت أو لم تجيب في حوالي 4 دقائق، لن يتغير شيء. قد يتوقف بعض العملاء عن الانتظار بعد دقيقة واحدة، لذا أجب بسرعة.

<Warning>
  العميل الذي لا يدعم الطلبات لن يُسأل، وتعمل الكتابة بمجرد قيام العميل بالاستدعاء. هناك، تأكيد عميلك الخاص هو الوحيد، لذا أبقه قيد التشغيل لأدوات الكتابة.
</Warning>

## التطبيقات المتصلة والإلغاء

**Settings → Integrations → MCP** يسرد تطبيقاتك المتصلة في المنظمة الحالية، مع أذوناتها واستخدامها الأخير. **Revoke** يقطع التطبيق على الفور. يؤدي إزالة الخادم في عميلك أيضًا إلى إلغاء الاتصال.

يمكنك الحصول على ما يصل إلى 5 تطبيقات متصلة لكل منظمة. يؤدي توصيل نفس التطبيق مجددًا إلى استبدال اتصاله السابق.

## النشرات ذاتية الاستضافة

اختر **Self-hosted Failproof AI Cloud** عند الاتصال، وأدخل العنوان الذي تسجل الدخول إليه. يجب أن يكون نشرك قابلاً للوصول عبر HTTPS العام.

تمر استدعاءات الأداة ونتائجها عبر بوابة Failproof AI المستضافة في طريقها بين أداة الذكاء الاصطناعي الخاصة بك والنشر الخاص بك. البوابة لا تخزنها.

## ما يحدث لبيانات هذه

تذهب النتائج إلى أداة الذكاء الاصطناعي التي وصلتها، وقدم الخدمة لتلك الأداة يتعامل معها بموجب شروطه الخاصة. لكل استدعاء أداة، يسجل Failproof AI اسم الأداة ونتائجها والوقت المستغرق والمنظمة، وليس أبدًا الحجج أو النتائج. انظر [privacy policy](https://befailproof.ai/privacy/).

## استكشاف الأخطاء والإصلاح

| ما تراه | ماذا تفعل |
| --- | --- |
| "Started in another browser" | أكمل تسجيل الدخول في المتصفح الذي فتحه العميل، مع السماح بـ ملفات تعريف الارتباط، وابدأ مجددًا من العميل |
| خطأ بعد **Allow** | يعمل الرابط مرة واحدة وينتهي بعد 10 دقائق، لذا ابدأ مجددًا من العميل |
| أداة متوقعة مفقودة | أنت لا تحتفظ بإذنها في هذه المنظمة. اطلب من المسؤول. لا تحتاج إلى إعادة الاتصال بمجرد حصولك عليها |
| العميل يطلب منك تسجيل الدخول باستمرار | تم إلغاء الاتصال أو تركت المنظمة أو ظلت غير مستخدمة لمدة 90 يومًا. اتصل مجددًا |
| "You have 5 connected apps" | أزل أحدها تحت **Settings → Integrations → MCP**، ثم اتصل مجددًا |

لا تزال عالقًا؟ راسل [support@befailproof.ai](mailto:support@befailproof.ai).
