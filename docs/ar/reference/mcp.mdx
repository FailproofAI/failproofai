قم بتوصيل أداة ذكاء اصطناعي بـ Failproof AI Cloud والعمل مع بيانات وكلائك منها. يمكن لأداتك الاستعلام عن الجلسات والأحداث، وتشغيل SQL للقراءة فقط، وقراءة لوحات المعلومات والتنبيهات والمشاكل والتدقيقات والسياسات، وإذا كنت تمتلك الإذن، إجراء تغييرات مثل إنشاء تنبيه أو نشر سياسة.

تعمل كل استدعاء برقابتك **الخاصة**، في **منظمة واحدة** تختارها عند الاتصال.

هناك عنوان واحد للجميع، مستضاف أو ذاتي الاستضافة:

```text
https://gateway.befailproof.ai/mcp
```

## توصيل عميل

أضف العنوان إلى عميلك. في المرة الأولى التي يتم فيها استخدام أداة، يفتح متصفحك. اختر مكان وجود Failproof AI Cloud الخاص بك، وسجّل الدخول، واختر منظمة واحدة، وحدد **السماح**. **إلغاء** لا يربط أي شيء.

تسمي الصفحة التطبيق والمكان الذي يعود إليه. يتم تمييز التطبيق الذي لم يتم التعرف عليه من خلال عنوان ويب خاص به كـ **تطبيق غير موثوق**، لذا تابع فقط إذا بدأت للتو هذا من عميلك الخاص.

<Tabs>
  <Tab title="Claude">
    في claude.ai أو Claude Desktop، انتقل إلى **Settings → Connectors → Add custom connector**. سمِّه `Failproof AI`، وأدخل العنوان، واختر **Add**، ثم **Connect**.

    في خطط Team و Enterprise، يضيف المالك الموصل للمنظمة أولاً. ثم يقوم كل شخص بتوصيل حسابه الخاص.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    ثم قم بتشغيل `/mcp` داخل Claude Code، واختر `failproofai`، وحدد **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    أضف هذا إلى `~/.cursor/mcp.json`، أو إلى `.cursor/mcp.json` الخاص بمشروعك:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    يظهر Cursor **Needs login** بجوار الخادم. حدده لتسجيل الدخول.
  </Tab>
  <Tab title="Codex">
    أضف هذا إلى `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    ثم قم بتشغيل `codex mcp login failproofai`.
  </Tab>
  <Tab title="عملاء آخرون">
    أي عميل يدعم خوادم MCP البعيدة عبر Streamable HTTP مع OAuth يعمل. أعطه العنوان أعلاه. لا توجد معرّف عميل أو سر لتكوينه.
  </Tab>
</Tabs>

## منظمة واحدة لكل اتصال

يعمل الاتصال فقط في المنظمة التي اخترتها. لاستخدام منظمتين، أضف الخادم مرتين بأسماء مختلفة، مثل `failproofai-acme` و `failproofai-sandbox`، وقم بتوصيل كل منها بمنظمته الخاصة.

لا تقبل المنظمات التجريبية الاتصالات. اختر منظمتك الخاصة بدلاً من ذلك.

## الأذونات

يمكن للاتصال القيام بما يمكنك القيام به في المنظمة، ضمن المجموعة أدناه. يتبع أذوناتك الحالية: إذا أعطاك المسؤول المزيد، تكتسب الأداة ذلك، وإذا أخذ شيئاً بعيداً، تفقده الأداة في الاستدعاء التالي.

| الإذن | يسمح للأداة بـ |
| --- | --- |
| `events:read` | سرد الأحداث، وقراءة نظرة عامة على الجلسة، وسرد الوكلاء والبيئات |
| `evaluations:read` | سرد الجلسات، وقراءة وتلخيص نتائج التقييم والمهام |
| `evaluations:trigger` | إنشاء تقييمات، ونشر إصدارات جديدة، وتشغيلها أو إيقافها، والملء الرجعي، وإعادة تقييم الجلسة |
| `dashboards:read`, `dashboards:write` | قراءة لوحات المعلومات، أو إنشاء وإعادة تسمية وإضافة استعلامات لها |
| `queries:read`, `queries:write` | قراءة الاستعلامات المحفوظة، أو حفظ وتحريرها |
| `queries:run` | تشغيل استعلام SQL واحد للقراءة فقط وقراءة مخطط الاستعلام |
| `alerts:read`, `alerts:write` | قراءة التنبيهات، أو إنشاء وتحرير وإيقاف وحذف واختبار التنبيهات |
| `issues:read` | قراءة المشاكل والإقرار بها والتعليق عليها |
| `issues:create` | فتح مشكلة على تنبيه |
| `issues:close` | حل وإغلاق المشاكل |
| `audits:read`, `audits:write` | قراءة التدقيقات والتشغيلات والنتائج، أو إنشاء وتحرير التدقيقات وبدء التشغيل |
| `code_fixes:read` | معرفة كيفية إصلاح مشكلة والحصول على السياق الخاص بها حتى يتمكن وكيلك من إصلاحها |
| `code_fixes:write` | بدء إصلاح في Failproof AI Cloud، الذي يفتح طلب سحب على GitHub الخاص بك |
| `policies:read`, `policies:write` | قراءة السياسات والآلات والنشرات، أو نشر ونشر والتراجع عن السياسات |

تحتاج عدة أدوات إلى أي إذن لأنها لا تقرأ بيانات المنظمة: بناء روابط الجلسة والحدث، والبحث في هذه الوثائق.

لا يمكن لأداة ذكاء اصطناعي أبداً لمس مفاتيح API أو المستخدمين أو الإعدادات أو إدارة المنظمة، ولا يمكنها إرسال الأحداث.

## الموافقة على التغييرات

تطلب عمليات الكتابة منك أولاً إذا كان عميلك يمكنه عرض الموجه. ترى ما سيتغير وتحدد **الموافقة على هذا التغيير** للمتابعة. إذا رفضت أو لم تجب في غضون حوالي 4 دقائق، فلن يتغير شيء. قد يتوقف بعض العملاء عن الانتظار بعد دقيقة، لذا أجب بسرعة.

<Warning>
  العميل الذي لا يدعم المحفزات لا يُسأل، ويتم تشغيل الكتابة بمجرد قيام العميل باستدعاء. هناك، تأكيد عميلك الخاص هو الوحيد، لذا أبقِ على أدوات الكتابة مفعلة.
</Warning>

## التطبيقات المتصلة والإلغاء

**Settings → Integrations → MCP** يسرد تطبيقاتك المتصلة في المنظمة الحالية، مع أذوناتها واستخدامها الأخير. **Revoke** يقطع التطبيق على الفور. يؤدي إزالة الخادم في عميلك أيضاً إلى إلغاء الاتصال.

يمكنك الحصول على ما يصل إلى 5 تطبيقات متصلة لكل منظمة. يؤدي توصيل نفس التطبيق مرة أخرى إلى استبدال اتصاله السابق.

## النشرات ذاتية الاستضافة

اختر **Self-hosted Failproof AI Cloud** عند الاتصال، وأدخل العنوان الذي تسجل الدخول فيه. يجب أن يكون نشرك متاحاً عبر HTTPS عام.

تمر استدعاءات الأدوات ونتائجها عبر بوابة Failproof AI المستضافة في طريقها بين أداتك الذكاء الاصطناعي ونشرك. البوابة لا تخزنها.

## ما يحدث لبيانات الخاص بك

تذهب النتائج إلى أداة ذكاء اصطناعي متصلة، ويتعامل مزود تلك الأداة معها وفقاً لشروطه الخاصة. لكل استدعاء أداة، يسجل Failproof AI اسم الأداة ونتيجتها والوقت المستغرق والمنظمة، أبداً الحجج أو النتائج. انظر [سياسة الخصوصية](https://befailproof.ai/privacy/).

| ما تراه | ما العمل |
| --- | --- |
| "بدأ في متصفح آخر" | أنهِ تسجيل الدخول في المتصفح الذي فتحه العميل، مع السماح بملفات تعريف الارتباط، وابدأ من جديد من العميل |

| أداة كنت تتوقعها مفقودة | أنت لا تملك إذنها في هذه المنظمة. اطلب من مسؤول. لا تحتاج إلى إعادة الاتصال بمجرد امتلاكها |
| العميل يطلب منك تسجيل الدخول باستمرار | تم إلغاء الاتصال أو تركت المنظمة أو ظل غير مستخدم لمدة 90 يوماً. قم بالاتصال مرة أخرى |
| لديك 5 تطبيقات متصلة | أبطل أحدها ضمن **Settings → Integrations → MCP**، ثم قم بالاتصال مرة أخرى |
