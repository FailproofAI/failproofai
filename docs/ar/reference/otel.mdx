يقوم `failproofai otel` بتكوين تقارير OpenTelemetry الاختيارية إلى FailproofAI Cloud. أولاً، قم بربط جهازك باستخدام `failproofai config` واطلب من مسؤول المؤسسة تفعيل **Settings → OpenTelemetry**.

يطلب الإعداد التفاعلي عن OpenTelemetry بعد حقل مفتاح Cloud ومنتقي العميل. تبدأ الخطوة الاختيارية بـ No افتراضياً. اختر Yes لاختيار عملاء OTEL؛ يعمل نفس الكود المُفعّل بعد كتابة الاتصال. اضغط Esc قبل الإعداد لعدم تطبيق أي تغييرات. الإعداد غير المراقب والمفتاح المُزوّد وووضع المصدر المفتوح والاحتفاظ بـ اتصال محفوظ لا يضيفونك إلى الاشتراك.

## تفعيل عميل

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

العملاء المدعومون هم `claude` و `codex` و `copilot` (VS Code). يتطلب إعداد Copilot ملف تنفيذي لـ VS Code أو امتداد Copilot مثبت. ديركتوري إعدادات متبقي وحده غير كافٍ؛ يتخطى الإعداد Copilot عند عدم العثور على أي منهما.

يرسل `--local` إلى المرحل المحلي بدلاً من الإرسال مباشرة إلى Cloud. يستخدم Copilot المرحل تلقائياً لأن إعداداته لا يمكنها تخزين رأس المصادقة.

يستمع المرحل فقط على جهازك. يلتقط مقيم FailproofAI المعد التغيير خلال ثوان؛ لا تحتاج إلى إعادة تشغيله. إذا كانت تطبيق آخر يمتلك منفذ المرحل، ستبلغ التقارير عنه كمعطل وسيستمر المقيم في التشغيل.

<Warning>
التقاط النص مُفعّل افتراضياً. أضف `--no-content` لحذف الفحوصات وتفاصيل الأداة. يمكن لإصدارات العميل أن تعرض عناصر تحكم محتوى مختلفة؛ راجع ما يُصدّره عميلك قبل استخدامه مع البيانات الحساسة.
</Warning>

يُصدّر Codex سجلات المحادثة فقط، وليس تتبعات وقت التشغيل الداخلية أو المقاييس. يبقى `log_user_prompt = false` الصريح في تكوين Codex معطلاً؛ يطبع التفعيل ملاحظة عند الحفاظ على هذا الاختيار.

### اختر مسار إبلاغ واحد

إذا كان إبلاغ النسخة المكتوبة قيد التشغيل لعميل، يسأل الإعداد:

> يُرسل failproofai بالفعل جلسات Claude Code إلى Cloud. هل تريد إرسالها باستخدام OTEL بدلاً من ذلك؟ سيتوقف تحميل النسخة المكتوبة لـ Claude Code.

الافتراضي هو No. يقبل `--yes` التبديل بدون موجه. العملاء الآخرون وإنفاذ السياسة لم يتأثروا.

ينتظر إعداد Codex تأكيد المقيم لتغيير المجمع قبل كتابة إعدادات المُصدّر. إذا انتهت مهلة التأكيد، يحذرك الإعداد من الانتظار قبل بدء Codex.

يحتفظ Config v2 بقائمة التتبع المتذكرة في `agents.selected` (وتاريخ الاكتشاف في `agents.seen`). يبقى التفضيل النسخة المكتوبة لكل عميل في `collector.agents.<agent>.sessions`، وملكية OTEL في `otel.agents`، وإعدادات المرحل في `collector.otlp.enabled` / `collector.otlp.port`. تحافظ هذه المفاتيح المنفصلة على قابلية قراءة تكوينات OTEL القديمة: يمكن للإعداد تغيير قائمة التتبع دون فقدان تفضيل النقل أو الحالة المطلوبة لاستعادة إعدادات عميلك.

## فتش الإعداد

```bash
failproofai otel status
```

يعرض Status كل عميل، ما إذا كانت إعداداته مُدارة بواسطة FailproofAI، وجهتها، ومفتاح الامتصاص في المؤسسة، وحالة المرحل، وآخر نتيجة تحميل للمرحل.

يعني `unknown` لمفتاح المؤسسة أن الخادم لم يوفره أو لم يتمكن من الوصول إليه. لا يعتبر خطأ ولا يمنع التكوين على إصدار Cloud أقدم.

إذا لم يكن Cloud يدعم OTEL بعد، يحتفظ المرحل بالصادرات المرفوضة بدلاً من التخلص منها. إذا كان امتصاص المؤسسة معطلاً، لن يكتب `enable` شيئاً وينهي مع خطأ؛ اطلب من مسؤول تفعيله أولاً.

## طبع التكوين لتطبيق

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

الإخراج عبارة عن كتلة بيئة shell لمُصدّر OTLP/HTTP. يعيّن إخراج Cloud `OTEL_EXPORTER_OTLP_ENDPOINT` إلى قاعدة OTLP في Cloud، `https://<cloud>/otel`، والمُصدّر يُلحق `/v1/<signal>`؛ متغير لكل إشارة مثل `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` يحتاج إلى الكامل `https://<cloud>/otel/v1/logs`. يشير الإخراج المحلي إلى المرحل، `http://127.0.0.1:<port>`. يتضمن إخراج Cloud مفتاح API المُعدّ؛ تعامل معه كـ سر. يحذف الإخراج المحلي المفتاح. لاستخدام الإخراج المحلي، فعّل أولاً عميلاً محلياً بحيث يعمل المرحل.

## استعيد الإعدادات السابقة

```bash
failproofai otel disable claude
failproofai otel disable all
```

يستعيد Disable فقط الإعدادات التي كتبها FailproofAI، ويحافظ على التغييرات غير ذات الصلة، ويستعيد اختيار إبلاغ النسخة المكتوبة السابق لكل عميل. عند تعطيل آخر عميل محلي مُدار، يتوقف المرحل عن قبول الصادرات.

بالنسبة لـ Codex، يسجل Disable أيضاً `collector.agents.codex.sessions_resume_after` (ميلي ثانية epoch). تُعتبر بايتات الطرح الموجودة مسلّمة بحيث لا تُحمّل مرة أخرى الجلسات الملتقطة باستخدام OTEL؛ لا تزال الإضافات اللاحقة تتدفق عبر إبلاغ النسخة المكتوبة.

يدعم كل أمر `--help`. راجع [OpenTelemetry في Cloud](/ar/agenteye/opentelemetry) لأمثلة التطبيق والعميل البرمجي.
