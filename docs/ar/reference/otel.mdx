يقوم `failproofai otel` بتكوين إعادة التقارير الاختيارية لـ OpenTelemetry إلى FailproofAI Cloud. أولاً، قم بربط جهازك باستخدام `failproofai config` واطلب من مسؤول المنظمة تفعيل **Settings → OpenTelemetry**.

يطلب الإعداد التفاعلي معلومات حول OpenTelemetry بعد حقل مفتاح Cloud ومنتقي الوكيل. الخطوة الاختيارية تكون افتراضياً على "لا". اختر "نعم" لاختيار وكلاء OTEL؛ سيتم تشغيل نفس كود التفعيل بعد كتابة الاتصال. اضغط Esc قبل الإعداد يعني عدم تطبيق أي تغييرات. الإعداد غير المراقب والمفتاح المزود وكود مفتوح المصدر والاحتفاظ بالاتصال المحفوظ لن يختاروك.

## تفعيل وكيل

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

الوكلاء المدعومون هم `claude` و `codex` و `copilot` (VS Code). يتطلب إعداد Copilot تطبيق VS Code قابل للتنفيذ أو ملحق Copilot مثبتاً. دليل إعدادات متبقٍ وحده لا يكفي؛ يتجاوز الإعداد Copilot عندما لا يتم العثور على أي منهما.

`--local` يرسل إلى الترحيل المحلي بدلاً من الإرسال المباشر إلى Cloud. يستخدم Copilot الترحيل تلقائياً لأن إعداداته لا يمكنها تخزين رأس المصادقة.

يستمع الترحيل فقط على جهازك. يختار خيط FailproofAI المُعد التغيير في غضون ثوانٍ؛ لا تحتاج إلى إعادة تشغيله. إذا كانت تطبيق آخر يمتلك منفذ الترحيل، يُبلّغ الحالة عنه كمُيقف ويستمر الخيط في التشغيل.

<Warning>
التقاط النص مفعّل افتراضياً. أضف `--no-content` لحذف الأوامر وتفاصيل الأدوات. يمكن لإصدارات الوكيل أن تكشف عن ضوابط محتوى مختلفة؛ راجع ما يُصدّره وكيلك قبل استخدامه مع البيانات الحساسة.
</Warning>

يُصدّر Codex سجلات المحادثة فقط، وليس آثار وقت التشغيل الداخلي أو المقاييس. يبقى `log_user_prompt = false` الصريح في تكوين Codex الخاص بك مُيقفاً؛ يطبع التفعيل ملاحظة عندما يحافظ على هذا الاختيار.

### اختر مسار إعداد التقارير واحد

إذا كان إعداد النص قيد التشغيل لوكيل ما، يطرح الإعداد السؤال:

> يُرسل failproofai بالفعل جلسات Claude Code إلى Cloud. هل تريد إرسالها باستخدام OTEL بدلاً من ذلك؟ سيتوقف تحميل النص الكامل لـ Claude Code.

الخيار الافتراضي هو لا. `--yes` يقبل التبديل بدون موجه. الوكلاء الآخرون وتطبيق السياسات غير متأثرين.

ينتظر إعداد Codex تأكيد الخيط لتغيير المجمع قبل كتابة إعدادات المُصدِّر الخاصة به. إذا انتهت مهلة التأكيد، يحذرك الإعداد من الانتظار قبل بدء Codex.

يحتفظ Config v2 بقائمة التتبع المتذكرة في `agents.selected` (ويظل سجل الكشف في `agents.seen`). يبقى التفضيل لكل وكيل للنص في `collector.agents.<agent>.sessions`، وملكية OTEL في `otel.agents`، وإعدادات الترحيل في `collector.otlp.enabled` / `collector.otlp.port`. تحافظ هذه المفاتيح المنفصلة على قراءة تكوينات OTEL القديمة: يمكن للإعداد تغيير قائمة التتبع دون فقدان تفضيل النقل أو الحالة المطلوبة لاستعادة إعدادات الوكيل الخاصة بك.

## افحص الإعداد

```bash
failproofai otel status
```

تعرض الحالة كل وكيل، سواء كانت إعداداته مُدارة بواسطة FailproofAI، وجهته، ومفتاح الجمع الخاص بالمنظمة، وحالة الترحيل، ونتيجة تحميل الترحيل الأخير.

`unknown` لمفتاح المنظمة يعني أن الخادم لم يوفره أو لم يتمكن من الوصول إليه. لا يعتبر خطأ ولا يمنع التكوين على إصدار Cloud أقدم.

إذا كان Cloud لا يدعم OTEL بعد، يحتفظ الترحيل بالصادرات المرفوضة بدلاً من التخلص منها. إذا كان جمع المنظمة مُيقفاً، فإن `enable` لا تكتب أي شيء وتخرج برسالة خطأ؛ اطلب من مسؤول تشغيله أولاً.

## اطبع التكوين لتطبيق

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

المخرجات عبارة عن كتلة متغيرات بيئة shell لمُصدِّر OTLP/HTTP. يضع مخرج Cloud `OTEL_EXPORTER_OTLP_ENDPOINT` إلى قاعدة Cloud OTLP، `https://<cloud>/otel`، ويُلحق المُصدِّر `/v1/<signal>`؛ متغير لكل إشارة مثل `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` يحتاج إلى `https://<cloud>/otel/v1/logs` الكامل. يشير مخرج محلي إلى الترحيل، `http://127.0.0.1:<port>`. يتضمن مخرج Cloud مفتاح API المُكوّن؛ عامله كسري. يحذف مخرج محلي المفتاح. لاستخدام المخرج المحلي، أولاً فعّل وكيل محلي حتى يعمل الترحيل.

## استعيد الإعدادات السابقة

```bash
failproofai otel disable claude
failproofai otel disable all
```

يستعيد التعطيل فقط الإعدادات التي كتبها FailproofAI، ويحتفظ بالتغييرات غير ذات الصلة، ويستعيد اختيار إعادة تقارير النص السابق لكل وكيل. عندما يتم تعطيل آخر وكيل محلي مُدار، يتوقف الترحيل عن قبول الصادرات.

بالنسبة لـ Codex، يسجل التعطيل أيضاً `collector.agents.codex.sessions_resume_after` (بايتات بصيغة epoch milliseconds). يتم التعامل مع بايتات الطرح الموجودة كمُسلَّمة بحيث لا يتم تحميل الجلسات المُلتقطة باستخدام OTEL مرة أخرى؛ لا تزال الإضافات اللاحقة تتدفق عبر إعادة تقارير النص.

يدعم كل أمر `--help`. راجع [OpenTelemetry in Cloud](/ar/agenteye/opentelemetry) للتطبيق وأمثلة وكلاء البرمجة.
