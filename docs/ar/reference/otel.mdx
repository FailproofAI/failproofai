يقوم `failproofai otel` بتكوين إعداد OpenTelemetry الاختياري للإبلاغ إلى FailproofAI Cloud. أولاً اتصل بجهازك باستخدام `failproofai config` واطلب من مسؤول المؤسسة تفعيل **Settings → OpenTelemetry**.

يطرح الإعداد التفاعلي أسئلة حول OpenTelemetry بعد حقل مفتاح Cloud واختيار الوكيل. الخطوة الاختيارية تفترض عدم الموافقة بشكل افتراضي. اختر نعم لاختيار وكلاء OTEL؛ سيتم تشغيل نفس كود التفعيل بعد كتابة الاتصال. الضغط على Esc قبل الإعداد لن يطبق أي تغييرات. الإعداد غير المراقب والمفتاح المرسل وضع المصدر المفتوح والاحتفاظ بالاتصال المحفوظ لا يختارونك للانضمام.

## تفعيل وكيل

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

الوكلاء المدعومون هم `claude` و `codex` و `copilot` (VS Code). يتطلب إعداد Copilot ملف تنفيذي VS Code أو امتداد Copilot مثبتاً. مجرد ترك دليل الإعدادات ليس كافياً؛ يتخطى الإعداد Copilot عندما لا يتم العثور على أي منهما.

`--local` يرسل إلى المعيد المحلي بدلاً من إرساله مباشرة إلى Cloud. يستخدم Copilot المعيد تلقائياً لأن إعداداته لا يمكنها تخزين رأس المصادقة.

يستمع المعيد فقط على جهازك. يلتقط مصدر بيانات FailproofAI المكون التغيير خلال ثوان؛ لا تحتاج إلى إعادة تشغيله. إذا كانت تطبيقاً آخر يملك منفذ المعيد، فإن التقرير يبلغ عنه كمغلق والعفريت يستمر في التشغيل.

<Warning>
التقاط النص مفعل بشكل افتراضي. أضف `--no-content` لحذف تفاصيل الطلبات والأدوات. قد تعرض إصدارات الوكيل عناصر تحكم محتوى مختلفة؛ راجع ما يُصدره وكيلك قبل استخدامه مع بيانات حساسة.
</Warning>

يُصدر Codex سجلات المحادثة فقط، وليس تتبعات أو مقاييس وقت التشغيل الداخلية. `log_user_prompt = false` صريحة في تكوين Codex الخاص بك تبقى معطلة؛ التفعيل يطبع ملاحظة عند الحفاظ على هذا الاختيار.

### اختر مسار إبلاغ واحد

إذا كان الإبلاغ عن النص قيد التشغيل لوكيل ما، فإن الإعداد يسأل:

> يُرسل failproofai بالفعل جلسات Claude Code إلى Cloud. إرسالها باستخدام OTEL بدلاً من ذلك؟ سيتوقف تحميل النسخة من Claude Code.

الافتراضي هو لا. `--yes` يقبل المفتاح بدون موجه. الوكلاء الآخرون وتطبيق السياسة غير متأثرين.

ينتظر إعداد Codex تأكيد العفريت للتغيير المجمِّع قبل كتابة إعدادات المُصدِّر. إذا انتهت مهلة التأكيد، يحذرك الإعداد للانتظار قبل بدء Codex.

يحتفظ Config v2 بقائمة التتبع المتذكرة في `agents.selected` (وسجل الكشف في `agents.seen`). يبقى تفضيل النسخة لكل وكيل في `collector.agents.<agent>.sessions`، وملكية OTEL في `otel.agents`، وإعدادات المعيد في `collector.otlp.enabled` / `collector.otlp.port`. تحافظ هذه المفاتيح المنفصلة على إمكانية قراءة تكوينات OTEL القديمة: يمكن للإعداد تغيير قائمة التتبع دون فقدان تفضيل النقل أو الحالة اللازمة لاستعادة إعدادات الوكيل الخاص بك.

## افحص الإعداد

```bash
failproofai otel status
```

يعرض الحالة كل وكيل، سواء تم إدارة إعداداته بواسطة FailproofAI، وجهته، مفتاح الامتصاص الخاص بالمؤسسة، حالة المعيد، وآخر نتيجة تحميل المعيد.

`unknown` لمفتاح المؤسسة يعني أن الخادم لم يقدمه أو لم يتمكن من الوصول إليه. إنه ليس خطأ ولا يمنع التكوين في إصدار Cloud الأقدم.

إذا كان Cloud لا يدعم OTEL حتى الآن، فإن المعيد يحتفظ بالتصديرات المرفوضة بدلاً من التخلص منها. إذا كان امتصاص المؤسسة معطلاً، فإن `enable` لا يكتب شيئاً ويخرج بخطأ؛ اطلب من مسؤول تشغيله أولاً.

## اطبع التكوين لتطبيق

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

الإخراج عبارة عن كتلة متغيرات بيئة الصدفة لمُصدِّر OTLP/HTTP. يعيّن إخراج Cloud `OTEL_EXPORTER_OTLP_ENDPOINT` إلى قاعدة OTLP الخاصة بـ Cloud، `https://<cloud>/otel`، والمُصدِّر يُلحق `/v1/<signal>`؛ قد تحتاج متغيرة لكل إشارة مثل `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` إلى `https://<cloud>/otel/v1/logs` الكامل. يشير إخراج المحلي إلى المعيد، `http://127.0.0.1:<port>`. يتضمن إخراج Cloud مفتاح API المكون؛ تعامل معه كسر. يحذف إخراج المحلي المفتاح. لاستخدام إخراج المحلي، فعّل أولاً وكيلاً محلياً حتى يعمل المعيد.

## استعد الإعدادات السابقة

```bash
failproofai otel disable claude
failproofai otel disable all
```

يستعيد التعطيل فقط الإعدادات التي كتبها FailproofAI، ويحافظ على التغييرات غير ذات الصلة، ويستعيد اختيار الإبلاغ عن النسخة السابق لكل وكيل. عندما يتم تعطيل آخر وكيل محلي مُدار، يتوقف المعيد عن قبول التصديرات.

بالنسبة إلى Codex، يسجل التعطيل أيضاً `collector.agents.codex.sessions_resume_after` (ملي ثانية من الحقبة الزمنية). تُعتبر بايتات الطرح الموجودة مُسلَّمة حتى لا يتم تحميل الجلسات المُلتقطة باستخدام OTEL مرة أخرى؛ التحاقات لاحقة لا تزال تتدفق عبر الإبلاغ عن النسخة.

يدعم كل أمر `--help`. اطلع على [OpenTelemetry في Cloud](/ar/agenteye/opentelemetry) للحصول على أمثلة التطبيقات والوكلاء البرمجيين.
