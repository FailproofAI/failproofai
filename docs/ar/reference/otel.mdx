يقوم `failproofai otel` بتكوين إعداد OpenTelemetry الاختياري للإبلاغ إلى FailproofAI Cloud. أولاً، قم بربط جهازك باستخدام `failproofai config`. يكون استقبال OpenTelemetry مفعلاً دائماً في Cloud، لذلك لا توجد مفاتيح تنظيمية لتفعيلها.

يطرح الإعداد التفاعلي أسئلة حول OpenTelemetry بعد حقل مفتاح Cloud واختيار الوكيل. تفترض الخطوة الاختيارية الافتراضي لا. اختر نعم لاختيار وكلاء OTEL؛ يتم تشغيل نفس كود التفعيل بعد كتابة الاتصال. اضغط Esc قبل الإعداد لا ينطبق أي تغييرات. لا يقوم الإعداد غير المراقب أو المفتاح المرفق أو الوضع مفتوح المصدر أو الاحتفاظ بالاتصال المحفوظ بتسجيلك الاشتراك.

## تفعيل وكيل

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

الوكلاء المدعومون هم `claude` و `codex` و `copilot` (VS Code). يتطلب إعداد Copilot ملف تنفيذي VS Code أو امتداد Copilot مثبتاً. دليل الإعدادات المتبقي وحده ليس كافياً؛ يتخطى الإعداد Copilot عند عدم العثور على أي منهما.

`--local` يرسل إلى مرحل محلي بدلاً من الإرسال مباشرة إلى Cloud. يستخدم Copilot المرحل تلقائياً لأن إعداداته لا يمكنها تخزين رأس المصادقة.

يستمع المرحل فقط على جهازك. سيلتقط FailproofAI daemon المكون لديك التغيير في غضون ثوان؛ لا تحتاج إلى إعادة تشغيله. إذا كانت تطبيق آخر يمتلك منفذ المرحل، فسيرفع التقرير حالته كمغلقة ويستمر daemon في التشغيل.

<Warning>
التقاط النص مفعل بشكل افتراضي. أضف `--no-content` لحذف الطلبات وتفاصيل الأداة. يمكن لإصدارات الوكيل أن تعرض عناصم تحكم محتوى مختلفة؛ قم بمراجعة ما يصدره وكيلك قبل استخدامه مع البيانات الحساسة.
</Warning>

يصدر Codex سجلات المحادثة فقط، وليس آثار وقت التشغيل الداخلي أو المقاييس. يبقى `log_user_prompt = false` الصريح في إعداد Codex الخاص بك مغلقاً؛ يطبع التفعيل ملاحظة عند الحفاظ على هذا الخيار.

### اختر مسار إبلاغ واحد

إذا كان الإبلاغ عن النسخة مفعلاً لوكيل، يطرح الإعداد:

> failproofai بالفعل يرسل جلسات Claude Code إلى Cloud. إرسالها مع OTEL بدلاً من ذلك؟ سيتوقف تحميل النسخة لـ Claude Code.

الافتراضي هو لا. `--yes` يقبل التبديل بدون موجه. الوكلاء الآخرون وإنفاذ السياسة لا يتأثران.

ينتظر إعداد Codex تأكيد daemon لتغيير المجمع قبل كتابة إعدادات المُصدِّر. إذا انتهت مهلة المؤقت للتأكيد، يحذرك الإعداد للانتظار قبل بدء Codex.

تحتفظ Config v2 بقائمة التتبع المتذكرة في `agents.selected` (وسجل الكشف في `agents.seen`). يبقى تفضيل النسخة لكل وكيل في `collector.agents.<agent>.sessions`، ملكية OTEL في `otel.agents`، وإعدادات المرحل في `collector.otlp.enabled` / `collector.otlp.port`. تحافظ هذه المفاتيح المنفصلة على إمكانية قراءة تكوينات OTEL القديمة: يمكن للإعداد تغيير قائمة التتبع دون فقدان تفضيل النقل أو الحالة المطلوبة لاستعادة إعدادات الوكيل.

## فحص الإعداد

```bash
failproofai otel status
```

تُظهر الحالة كل وكيل، سواء كانت إعداداته مُدارة بواسطة FailproofAI، وجهته، ومفتاح استقبال المنظمة، وحالة المرحل، ونتيجة آخر تحميل للمرحل.

تعني `unknown` بالنسبة لمفتاح المنظمة أن الخادم لم يوفره أو لم يتمكن من الوصول إليه. إنه ليس خطأ ولا يمنع التكوين على إصدار Cloud أقدم.

إذا كان Cloud لا يدعم OTEL بعد، فسيحتفظ المرحل بالصادرات المرفوضة بدلاً من التخلص منها. إذا أبلغ إصدار Cloud أقدم عن استقبال المنظمة كمغلق، فإن `enable` لا تكتب شيئاً وتخرج برسالة خطأ.

## طباعة التكوين لتطبيق

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

الناتج هو كتلة بيئة shell لمُصدِّر OTLP/HTTP. يقوم ناتج Cloud بتعيين `OTEL_EXPORTER_OTLP_ENDPOINT` إلى قاعدة OTLP للـ Cloud، `https://<cloud>/otel`، والمُصدِّر يلحق `/v1/<signal>`؛ يحتاج متغير لكل إشارة مثل `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` إلى `https://<cloud>/otel/v1/logs` الكامل. يشير الناتج المحلي إلى المرحل، `http://127.0.0.1:<port>`. يتضمن ناتج Cloud مفتاح API المكون؛ تعامل معه كسر. يحذف الناتج المحلي المفتاح. لاستخدام الناتج المحلي، قم أولاً بتفعيل وكيل محلي حتى يعمل المرحل.

## استعد إعداداتك السابقة

```bash
failproofai otel disable claude
failproofai otel disable all
```

يستعيد التعطيل فقط الإعدادات التي كتبها FailproofAI، ويحتفظ بالتغييرات غير ذات الصلة، ويستعيد خيار الإبلاغ عن النسخة السابق لكل وكيل. عند تعطيل آخر وكيل محلي مُدار، يتوقف المرحل عن قبول الصادرات.

بالنسبة لـ Codex، يسجل التعطيل أيضاً `collector.agents.codex.sessions_resume_after` (بايتات epoch بالميلي ثانية). يتم التعامل مع بايتات الطرح الموجودة كمُسلَّمة بحيث لا يتم تحميل الجلسات المُلتقطة مع OTEL مرة أخرى؛ لا تزال الإلحاقات اللاحقة تتدفق من خلال الإبلاغ عن النسخة.

يدعم كل أمر `--help`. انظر [OpenTelemetry في Cloud](/ar/agenteye/opentelemetry) للحصول على أمثلة التطبيق ووكيل الترميز.
