يقوم `failproofai otel` بتكوين تقارير OpenTelemetry الاختيارية إلى FailproofAI Cloud. أولاً، قم بتوصيل جهازك باستخدام `failproofai config` واطلب من مسؤول المنظمة تفعيل **Settings → OpenTelemetry**.

يطلب الإعداد التفاعلي معلومات عن OpenTelemetry بعد حقل مفتاح Cloud ومنتقي العميل. الخطوة الاختيارية تفترض بشكل افتراضي No. اختر Yes لاختيار عملاء OTEL؛ يتم تشغيل نفس كود التفعيل بعد كتابة الاتصال. الضغط على Esc قبل الإعداد لا يطبق أي تغييرات. الإعداد بدون تفاعل، ومفتاح مزود، والوضع مفتوح المصدر، والاحتفاظ بالاتصال المحفوظ لا يختارونك.

## تفعيل عميل

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

العملاء المدعومون هم `claude` و `codex` و `copilot` (VS Code). يتطلب إعداد Copilot ملف تنفيذي VS Code أو ملحق Copilot مثبت. دليل الإعدادات المتبقي وحده ليس كافياً؛ يتجاوز الإعداد Copilot عندما لا يتم العثور على أي منهما.

يرسل `--local` إلى المرحِّل المحلي بدلاً من الإرسال مباشرة إلى Cloud. يستخدم Copilot المرحِّل تلقائياً لأن إعداداته لا يمكنها تخزين رأس المصادقة.

يستمع المرحِّل فقط على جهازك. سيلتقط وحدة FailproofAI المُشكَّلة التغيير في غضون ثوان؛ لا تحتاج إلى إعادة تشغيل. إذا كانت تطبيق آخر يمتلك منفذ المرحِّل، فإن الحالة تُبلغ عنه كمغلق وتستمر الوحدة في العمل.

<Warning>
التقاط النص مفعل افتراضياً. أضف `--no-content` لحذف الرسائل وتفاصيل الأدوات. يمكن لإصدارات العميل أن تكشف عناصر تحكم محتوى مختلفة؛ راجع ما يُصدِّره عميلك قبل استخدامه مع البيانات الحساسة.
</Warning>

يُصدِّر Codex سجلات الحوار فقط، وليس تتبعات وقت التشغيل الداخلية أو المقاييس. يبقى `log_user_prompt = false` الصريح في تكوين Codex مغلقاً؛ التفعيل يطبع ملاحظة عند الحفاظ على هذا الاختيار.

### اختر مسار إبلاغ واحد

إذا كان إبلاغ النسخة مفعلاً لعميل ما، يسأل الإعداد:

> يرسل failproofai بالفعل جلسات Claude Code إلى Cloud. إرسالها مع OTEL بدلاً من ذلك؟ يتوقف تحميل النسخة لـ Claude Code.

الافتراضي هو No. يقبل `--yes` التبديل بدون موجه. العملاء الآخرون وتطبيق السياسة لا يتأثران.

ينتظر إعداد Codex تأكيد الوحدة لتغيير المجمّع قبل كتابة إعدادات المُصدِّر. إذا انتهت مهلة التأكيد، يحذرك الإعداد من الانتظار قبل بدء Codex.

يحتفظ Config v2 بقائمة التتبع المتذكرة في `agents.selected` (وسجل الكشف في `agents.seen`). يبقى التفضيل المتعلق بنسخة لكل عميل في `collector.agents.<agent>.sessions`، وملكية OTEL في `otel.agents`، وإعدادات المرحِّل في `collector.otlp.enabled` / `collector.otlp.port`. تحتفظ هذه المفاتيح المنفصلة بتكوينات OTEL القديمة قابلة للقراءة: يمكن للإعداد أن يغيّر قائمة التتبع دون فقدان تفضيل النقل أو الحالة المطلوبة لاستعادة إعدادات عميلك.

## فتّش الإعداد

```bash
failproofai otel status
```

تعرض الحالة كل عميل، وما إذا كانت إعداداته مُدارة من قِبل FailproofAI، والوجهة، ومفتاح الاستيعاب في المنظمة، وحالة المرحِّل، ونتيجة التحميل الأخير للمرحِّل.

يعني `unknown` لمفتاح المنظمة أن الخادم لم يوفره أو لم يتمكن من الوصول إليه. إنها ليست خطأ ولا تمنع التكوين على إصدار Cloud أقدم.

إذا كان Cloud لا يدعم OTEL حتى الآن، يحتفظ المرحِّل بالصادرات المرفوضة بدلاً من تجاهلها. إذا كان استيعاب المنظمة مغلقاً، فإن `enable` لا يكتب شيئاً ويخرج مع خطأ؛ اطلب من المسؤول تفعيله أولاً.

## اطبع التكوين لتطبيق

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

المخرجات عبارة عن كتلة بيئة shell لمُصدِّر OTLP/HTTP. يحدد مخرجات Cloud `OTEL_EXPORTER_OTLP_ENDPOINT` إلى قاعدة OTLP في Cloud، `https://<cloud>/otel`، ويلحق المُصدِّر `/v1/<signal>`؛ قد تحتاج متغيرة لكل إشارة مثل `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` إلى `https://<cloud>/otel/v1/logs` الكاملة. تشير المخرجات المحلية إلى المرحِّل، `http://127.0.0.1:<port>`. تتضمن مخرجات Cloud مفتاح API المُشكَّل؛ تعاملها على أنها سر. تحذف المخرجات المحلية المفتاح. لاستخدام المخرجات المحلية، أولاً فعّل عميلاً محلياً بحيث يعمل المرحِّل.

## استعد الإعدادات السابقة

```bash
failproofai otel disable claude
failproofai otel disable all
```

يستعيد التعطيل فقط الإعدادات التي كتبها FailproofAI، يحتفظ بالتغييرات غير المرتبطة، ويستعيد اختيار تقارير النسخة السابق لكل عميل. عندما يتم تعطيل آخر عميل محلي مُدار، يتوقف المرحِّل عن قبول الصادرات.

بالنسبة إلى Codex، يسجل التعطيل أيضاً `collector.agents.codex.sessions_resume_after` (ملي ثانية epoch). تُعامَل بايتات الانتشار الموجودة على أنها مُسلَّمة بحيث لا يتم تحميل الجلسات المسجلة مع OTEL مرة أخرى؛ لا تزال الإضافات اللاحقة تتدفق عبر تقارير النسخة.

تدعم كل أوامر `--help`. اطّلع على [OpenTelemetry في Cloud](/ar/agenteye/opentelemetry) للحصول على أمثلة التطبيق والعميل البرمجة.
