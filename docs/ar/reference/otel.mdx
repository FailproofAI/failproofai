يقوم `failproofai otel` بتكوين تقارير OpenTelemetry الاختيارية إلى FailproofAI Cloud. أولاً قم بتوصيل جهازك باستخدام `failproofai config`. يكون استقبال OpenTelemetry قيد التشغيل دائماً في Cloud، لذا لا توجد مفاتيح تنظيمية لتفعيلها.

يطلب الإعداد التفاعلي معلومات حول OpenTelemetry بعد حقل مفتاح Cloud واختيار الوكيل. تحتفظ الخطوة الاختيارية بالقيمة الافتراضية لا. اختر نعم لاختيار وكلاء OTEL؛ الكود نفسه الذي يفعّل هذا ينفذ بعد كتابة الاتصال. اضغط Esc قبل الانتهاء من الإعداد لا ينفذ أي تغييرات. الإعداد غير المراقب والمفتاح المُزود وكذلك الوضع مفتوح المصدر والاحتفاظ بالاتصال المحفوظ لا يختارون الالتزام.

## تفعيل وكيل

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

الوكلاء المدعومون هم `claude` و `codex` و `copilot` (VS Code). يتطلب إعداد Copilot ملف تنفيذ VS Code أو ملحق Copilot مثبت. دليل إعدادات متبقٍ وحده لا يكفي؛ يتخطى الإعداد Copilot عندما لا يكون أي منهما موجوداً.

يرسل `--local` إلى الموصل المحلي بدلاً من الإرسال مباشرة إلى Cloud. يستخدم Copilot الموصل تلقائياً لأن إعداداته لا يمكنها تخزين رأس المصادقة.

يستمع الموصل فقط على جهازك. سيلتقط الخادم FailproofAI المُعدّ لديك التغيير في غضون ثوان؛ لا تحتاج إلى إعادة تشغيله. إذا كانت تطبيق آخر يمتلك منفذ الموصل، فسيبلغ الحالة عنه كمُطفأ والخادم يستمر في التشغيل.

<Warning>
التقاط النص مفعّل بشكل افتراضي. أضف `--no-content` لحذف المحفوظات وتفاصيل الأداة. قد تكشف إصدارات الوكيل عن عناصر تحكم محتوى مختلفة؛ راجع ما يصدّره وكيلك قبل استخدامه مع البيانات الحساسة.
</Warning>

يصدّر Codex سجلات المحادثة فقط، وليس تتبع وقت التشغيل الداخلي أو المقاييس. `log_user_prompt = false` صريح في ملف تكوين Codex الخاص بك يبقى مطفأ؛ يطبع التفعيل ملاحظة عند الحفاظ على هذا الخيار.

### اختر مسار التقرير الواحد

إذا كان تقرير النسخة على تشغيل لوكيل ما، يسأل الإعداد:

> failproofai بالفعل يرسل جلسات Claude Code إلى Cloud. إرسالها مع OTEL بدلاً من ذلك؟ تحميل النسخة لـ Claude Code يتوقف.

القيمة الافتراضية هي لا. `--yes` يقبل التبديل بدون موجه. الوكلاء الآخرون وإنفاذ السياسة لا يتأثران.

ينتظر إعداد Codex من الخادم تأكيد تغيير المجمّع قبل كتابة إعدادات المُصدِّر الخاص به. إذا انتهت مهلة التأكيد، يحذرك الإعداد للانتظار قبل بدء Codex.

تحتفظ الإصدار 2 من Config بقائمة التتبع المتذكرة في `agents.selected` (وسجل الكشف في `agents.seen`). يبقى تفضيل النسخة لكل وكيل في `collector.agents.<agent>.sessions`، ملكية OTEL في `otel.agents`، وإعدادات الموصل في `collector.otlp.enabled` / `collector.otlp.port`. تحافظ هذه المفاتيح المنفصلة على قابلية قراءة تكوينات OTEL القديمة: يمكن للإعداد تغيير قائمة التتبع دون فقدان تفضيل النقل أو الحالة المطلوبة لاستعادة إعدادات الوكيل الخاص بك.

## تفقد الإعداد

```bash
failproofai otel status
```

تعرض الحالة كل وكيل وما إذا كانت إعداداته مُدارة بواسطة FailproofAI ووجهته ومفتاح استقبال المنظمة وحالة الموصل والنتيجة الأخيرة لتحميل الموصل.

`unknown` بخصوص مفتاح المنظمة يعني أن الخادم لم يوفره أو لم يتمكن من الوصول إليه. ليس خطأ ولا يمنع التكوين على إصدار Cloud أقدم.

إذا كان Cloud لا يدعم OTEL بعد، فإن الموصل يحتفظ بالتصديرات المرفوضة بدلاً من التخلص منها. إذا أبلغ إصدار Cloud أقدم عن استقبال المنظمة كمطفأ، `enable` لا يكتب شيء وينتهي برسالة خطأ.

## طباعة التكوين لتطبيق

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

الناتج عبارة عن كتلة بيئة shell لمُصدِّر OTLP/HTTP. ناتج Cloud يحدد `OTEL_EXPORTER_OTLP_ENDPOINT` إلى قاعدة OTLP في Cloud، `https://<cloud>/otel`، والمُصدِّر يلحق `/v1/<signal>`؛ متغير لكل إشارة مثل `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` يحتاج إلى كامل `https://<cloud>/otel/v1/logs`. الناتج المحلي يشير إلى الموصل، `http://127.0.0.1:<port>`. ناتج Cloud يتضمن مفتاح API المُعدّ؛ تعامل معه كسر. الناتج المحلي يحذف المفتاح. لاستخدام الناتج المحلي، أولاً فعّل وكيل محلي حتى يعمل الموصل.

## استعد إعداداتك السابقة

```bash
failproofai otel disable claude
failproofai otel disable all
```

يعيد الإلغاء فقط الإعدادات التي كتبها FailproofAI، ويحتفظ بالتغييرات غير ذات الصلة، ويستعيد خيار تقرير النسخة السابقة لكل وكيل. عندما يكون آخر وكيل محلي مُدار معطّل، يتوقف الموصل عن قبول التصديرات.

بالنسبة لـ Codex، يسجل الإلغاء أيضاً `collector.agents.codex.sessions_resume_after` (بايتات جزء من الثانية). يتم التعامل مع بايتات الطرح الموجودة كمُسلّمة حتى لا يتم تحميل الجلسات التي تم التقاطها باستخدام OTEL مرة أخرى؛ لا تزال الإلحاقات اللاحقة تتدفق من خلال تقرير النسخة.

كل أمر يدعم `--help`. انظر [OpenTelemetry في Cloud](/ar/agenteye/opentelemetry) للتطبيق وأمثلة وكلاء الترميز.
