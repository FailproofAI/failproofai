يقوم `failproofai otel` بتكوين إرسال OpenTelemetry الاختياري إلى FailproofAI Cloud. قم أولاً بربط جهازك باستخدام `failproofai config` واطلب من مسؤول المؤسسة تفعيل **Settings → OpenTelemetry**.

يطرح الإعداد التفاعلي أسئلة حول OpenTelemetry بعد حقل مفتاح Cloud واختيار العميل. الخطوة الاختيارية تفتراض الإجابة بـ لا. اختر نعم لاختيار عملاء OTEL؛ يتم تشغيل نفس كود التفعيل بعد كتابة الاتصال. يؤدي الضغط على Esc قبل الإعداد إلى عدم تطبيق أي تغييرات. الإعداد غير المراقب، والمفتاح المسلّم، وصيغة المصدر المفتوح، والحفاظ على اتصال محفوظ لن يؤدي إلى تفعيلك.

## تفعيل عميل

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

العملاء المدعومون هم `claude` و `codex` و `copilot` (VS Code). يتطلب إعداد Copilot ملف تنفيذي VS Code أو تثبيت Copilot. دليل الإعدادات المتبقي وحده غير كافٍ؛ يتخطى الإعداد Copilot عند عدم العثور على أي منهما.

`--local` يرسل إلى المرحّل المحلي بدلاً من الإرسال مباشرة إلى Cloud. يستخدم Copilot المرحّل تلقائياً لأن إعداداته لا يمكنها تخزين رأس المصادقة.

يستمع المرحّل فقط على جهازك. يلتقط مراقب FailproofAI المُعد التغيير في غضون ثوانٍ؛ لا تحتاج إلى إعادة تشغيله. إذا كانت تطبيق آخر يمتلك منفذ المرحّل، فإن الحالة تبلغ عنه كمُطفأ والمراقب يستمر في التشغيل.

<Warning>
التقاط النص مُفعّل بشكل افتراضي. أضف `--no-content` لحذف المحفوظات وتفاصيل الأداة. يمكن لإصدارات العميل أن تكشف عن عناصر تحكم محتوى مختلفة؛ راجع ما يُصدّره العميل قبل استخدامه مع البيانات الحساسة.
</Warning>

يصدّر Codex سجلات المحادثات فقط، وليس التتبعات أو المقاييس الداخلية للتشغيل. يبقى `log_user_prompt = false` صريح في تكوين Codex الخاص بك معطّلاً؛ يطبع التفعيل ملاحظة عند حفظ هذا الاختيار.

### اختر مسار إرسال واحد

إذا كان إرسال النسخة مُفعّلاً لعميل، يطرح الإعداد السؤال:

> failproofai يرسل بالفعل جلسات Claude Code إلى Cloud. هل تريد إرسالها عبر OTEL بدلاً من ذلك؟ سيتوقف تحميل النسخة لـ Claude Code.

الافتراضي هو لا. `--yes` يقبل التبديل بدون موجه. العملاء الآخرون وتطبيق السياسات لا يتأثران.

ينتظر إعداد Codex أن يؤكد المراقب تغيير المجمّع قبل كتابة إعدادات المُصدّر. إذا انتهت مهلة المؤكد، يحذرك الإعداد بالانتظار قبل بدء Codex.

يحافظ الإصدار 2 من الإعداد على قائمة التتبع المتذكرة في `agents.selected` (وسجل الكشف في `agents.seen`). يبقى تفضيل النسخة لكل عميل في `collector.agents.<agent>.sessions`، وملكية OTEL في `otel.agents`، وإعدادات المرحّل في `collector.otlp.enabled` / `collector.otlp.port`. تحافظ هذه المفاتيح المنفصلة على قراءة تكوينات OTEL القديمة: يمكن للإعداد تغيير قائمة التتبع دون فقدان تفضيل النقل أو الحالة اللازمة لاستعادة إعدادات العميل.

## فحص الإعداد

```bash
failproofai otel status
```

تعرض الحالة كل عميل، سواء تم إدارة إعداداته بواسطة FailproofAI، وجهته، ومفتاح الاستيعاب الخاص بالمؤسسة، وحالة المرحّل، ونتيجة آخر تحميل للمرحّل.

تعني `unknown` لمفتاح المؤسسة أن الخادم لم يوفره أو لم يتمكن من الوصول إليه. إنه ليس خطأ ولا يمنع التكوين في إصدار Cloud أقدم.

إذا لم يدعم Cloud OTEL بعد، فسيحتفظ المرحّل بالصادرات المرفوضة بدلاً من التخلص منها. إذا كان الاستيعاب الخاص بالمؤسسة معطّلاً، فإن `enable` لن يكتب شيئاً ويخرج برسالة خطأ؛ اطلب من المسؤول تفعيله أولاً.

## طباعة الإعداد لتطبيق

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

المُخرجات عبارة عن كتلة متغيرات بيئة shell لمُصدّر OTLP/HTTP. يعيّن المُخرج على Cloud `OTEL_EXPORTER_OTLP_ENDPOINT` إلى قاعدة OTLP الخاصة بـ Cloud، `https://<cloud>/otel`، والمُصدّر يُلحق `/v1/<signal>`؛ متغير خاص بكل إشارة مثل `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` يحتاج إلى كامل `https://<cloud>/otel/v1/logs`. يشير المخرج المحلي إلى المرحّل، `http://127.0.0.1:<port>`. يتضمن المخرج على Cloud مفتاح API المُعد؛ تعامل معه كسر. يحذف المخرج المحلي المفتاح. لاستخدام المخرج المحلي، قم أولاً بتفعيل عميل محلي بحيث يعمل المرحّل.

## استعادة الإعدادات السابقة

```bash
failproofai otel disable claude
failproofai otel disable all
```

يستعيد التعطيل فقط الإعدادات التي كتبها FailproofAI، ويحتفظ بالتغييرات غير ذات الصلة، ويستعيد اختيار إرسال النسخة السابق لكل عميل. عند تعطيل آخر عميل محلي مُدار، يتوقف المرحّل عن قبول الصادرات.

بالنسبة إلى Codex، يسجل التعطيل أيضاً `collector.agents.codex.sessions_resume_after` (مللي ثانية الحقبة). يتم التعامل مع البايتات الموجودة للمراجعة كمُسلّمة بحيث لا يتم تحميل الجلسات المستخرجة مع OTEL مرة أخرى؛ لا تزال الإضافات اللاحقة تتدفق عبر إرسال النسخة.

يدعم كل أمر `--help`. انظر إلى [OpenTelemetry في Cloud](/ar/agenteye/opentelemetry) للحصول على أمثلة التطبيق وعميل الترميز.
