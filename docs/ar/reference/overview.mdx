يغطي [مرجع HTTP API](/ar/reference/http-api) المُنشأ السطح العام `/v1`. تشرح الصفحات المكتوبة يدويًا سير العمل الذي يمتد عبر نقاط نهاية متعددة أو يستخدم واجهات إدارية خارج ذلك السطح العام.

## توصيل وكيل والتحقق من البيانات

<Tabs>
  <Tab title="لوحة التحكم">
    1. افتح **Administration → Keys**، وأنشئ مفتاحًا باستخدام `events:add` و `policies:pull`، وانسخ السر.
    2. قم بتكوين التكامل باستخدام الصفحة المطابقة أعلاه.
    3. افتح **Observe → Events** للتأكد من وصول الأحداث، ثم **Observe → Sessions** للتأكد من تشكيل عمليات تشغيل كاملة.
    4. قم بالتصفية بناءً على بيئة التكامل وتفتيش جلسة واحدة للحصول على نموذج وأداة وخطأ وحقول السياسة التي يحتاجها التدقيق.

    ابدأ بدرج المفاتيح. تحدد المنح المحددة ما إذا كانت الآلة يمكنها إرسال الأحداث وتلقي السياسات التي تديرها Cloud.

    ![درج مفتاح API الجديد المستخدم لمنح أذونات الابتلاع وتسليم السياسة.](/images/dashboard/key-create.png)

    بعد توصيل التكامل، استخدم قائمة الجلسات للتأكد من تجميع أحداثه في عمليات تشغيل كاملة في البيئة المتوقعة.

    ![قائمة الجلسات المستخدمة للتحقق من أن التكامل المتصل حديثًا يبلغ عن عمليات تشغيل الوكيل الكاملة.](/images/dashboard/sessions-list.png)

    افتح إحدى هذه الجلسات قبل اعتبار التكامل مكتملًا؛ يجب أن يحتوي الأثر على نموذج وأداة وخطأ وأدلة السياسة التي يحتاجها التدقيق الخاص بك.
  </Tab>
  <Tab title="CLI">
    قم بإنشاء مفتاح آلة، وقم بتوصيل خادم Failproof، والتحقق من الجلسة الأولى.

    ```bash
    fp keys create agent-production \
      --add events:add \
      --add policies:pull

    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>

    failproofai flush --wait
    fp sessions --since 1h --env production
    fp events --since 1h --env production --limit 20
    ```

    استخدم `fp --json sessions ...` عندما تستهلك أداة أخرى النتيجة. يجب أن تأتي الأعلام العامة مثل `--json` و `--org` و `--base-url` قبل الأمر.

    راجع [مرجع Failproof AI CLI](/ar/reference/failproof-cli) للأوامر المحلية و [مرجع Failproof Cloud CLI](/ar/reference/cloud-cli#cli-commands) لأوامر `fp`.
  </Tab>
</Tabs>
