تحول السياسات المخصصة نمط الفشل من تتبعاتك أو عملياتك التدقيقية إلى قرار يعمل أثناء عمل الوكيل. يمكن للسياسة السماح بإجراء ما أو توجيه الوكيل أو رفض الإجراء قبل أن يسبب حادثة أخرى.

استخدم سياسة مخصصة عندما يعتمد السلوك على أدواتك أو مساراتك أو أوامرك أو بيئاتك أو قواعدك التشغيلية. راجع [كتالوج السياسات المدمجة](/ar/policies/builtin-catalog) أولاً حتى لا تعيد إنشاء تحكم موجود.

## ابدأ بقاعدة ضيقة

تحجب هذه السياسة أوامر Kubernetes المدمرة فقط عندما يستهدف الأمر الإنتاج. كل شيء خارج نمط الفشل الدقيق هذا يعيد `allow()`.

```ts
import { customPolicies, allow, deny } from "failproofai";

const DESTRUCTIVE_KUBECTL = /\bkubectl\s+(delete|replace)\b/i;
const PRODUCTION_TARGET = /(?:--context|--namespace|-n)\s+(prod|production)\b/i;

customPolicies.add({
  name: "block-destructive-production-kubectl",
  description: "Block destructive Kubernetes commands against production",
  match: { events: ["PreToolUse"] },
  fn: async ({ toolName, toolInput }) => {
    if (toolName !== "Bash") return allow();

    const command = String(toolInput?.command ?? "");
    if (!DESTRUCTIVE_KUBECTL.test(command)) return allow();
    if (!PRODUCTION_TARGET.test(command)) return allow();

    return deny(
      "Destructive production Kubernetes commands require the approved deployment workflow.",
    );
  },
});
```

السياسات الجيدة ضيقة بما يكفي لشرحها في جملة واحدة. طابق الإجراء الملاحظ—وليس القصد الذي تأمل أن يكون لدى الوكيل—وأعد `allow()` بمجرد عدم انطباق القاعدة.

## اختر قرارًا

| المساعد | النتيجة | استخدمه عندما |
| --- | --- | --- |
| `allow(reason?)` | تستمر العملية. | السياسة لا تنطبق أو الإجراء آمن. |
| `instruct(reason)` | تستمر العملية، ويتم إيصال السبب إلى الوكيل على الحدافير التي لديها قناة له. | تريد توجيه الوكيل نحو نهج أفضل دون فرض ثابت. |
| `deny(reason)` | تحجب العملية على أزواج الحدافير والأحداث التي تم التحقق من استهلاكها لحكم حاجز. | يجب ألا تستمر العملية. |

اكتب السبب للوكيل الذي يجب أن يتعافى. اشرح ما تم اكتشافه وما يجب أن يفعله بدلاً من ذلك.

### حيث يصل `instruct()` فعلاً

يحتاج `instruct()` إلى قناة سياق إضافية في الحداف. ستة حدافير ليس لديها أي على بعض الأحداث أو جميع الأحداث؛ هناك تسمح العملية والرسالة تكتب إلى stderr، حيث لا يقرأها الوكيل أبدًا.

| الحداف | الأحداث التي توصل التعليمات |
| --- | --- |
| Claude وCodex وCopilot وCursor وDevin وOpenCode | يحمل `PreToolUse` و`PostToolUse` و`UserPromptSubmit` و`PermissionRequest` كسياق إضافي. يحمل `Stop` و`SubagentStop` من خلال قناة إعادة المحاولة بدلاً من ذلك. كل حدث آخر يصدر رسالة يتجاهلها الحداف. |
| Antigravity | `UserPromptSubmit` و`Stop` فقط. |
| Factory وPi وOpenClaw | `Stop` فقط. |
| Hermes وGoose | لا شيء. السماح دائمًا بإضافة ملاحظة stderr. |

لا يطلق أي حداف جميع الأحداث الكنسية الـ 29، لذا يتم تقييد الصف الأول بما يثبته كل واحد — التعليمات توصل فقط على حدث يطلقه الحداف فعلاً. تحقق من مجموعة الأحداث المثبتة لكل حداف في [حدافير الوكيل](/ar/reference/harnesses) قبل الاعتماد على واحد.

<Warning>
  لا تستخدم `instruct()` لحد أمان. على Hermes وGoose لا تصل إلى الوكيل أبدًا، وعلى Antigravity وFactory وPi وOpenClaw لا تصل إليه على أحداث الأدوات. استخدم `deny()` عندما يجب منع العملية.
</Warning>

## كائن السياسة

```ts
customPolicies.add({
  name: "policy-name",
  description: "What this policy prevents",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => allow(),
});
```

| الحقل | مطلوب | الوصف |
| --- | --- | --- |
| `name` | نعم | معرّف مستقر للسياسة. احتفظ بالأسماء فريدة عبر الملفات. |
| `description` | لا | الغرض الذي يمكن قراءته بواسطة الإنسان والمعروض في قوائم السياسات والقرارات. |
| `match.events` | لا | أنواع الأحداث التي تستدعي السياسة. إغفال `match` يستدعيها لكل حدث متاح. |
| `fn` | نعم | دالة متزامنة أو غير متزامنة تعيد نتيجة `allow` أو `instruct` أو `deny`. |

صفّ الأدوات داخل `fn`. `match.toolNames` ليس جزءًا من نوع السياسة المخصصة العامة.

قد تحمل السياسة المنشورة داخل حزمة حقلين إضافيين، `category` و`defaultEnabled`. انظر [من ملف إلى حزمة](#from-a-file-to-a-pack).

## سياق السياسة

تستقبل كل سياسة `PolicyContext`.

| الحقل | النوع | ما يحتويه |
| --- | --- | --- |
| `eventType` | `HookEventType` | الحدث الموحد قيد التقييم حاليًا. |
| `toolName` | `string \| undefined` | اسم الأداة الكنسي مثل `Bash` أو `Read` أو `Write` أو `Edit`. |
| `toolInput` | `Record<string, unknown> \| undefined` | الإدخال الموحد للاستدعاء الأداة الحالي. |
| `payload` | `Record<string, unknown>` | حمل الحدث الموحد الكامل. |
| `session` | `SessionMetadata \| undefined` | معرّف الجلسة ودليل العمل ومسار النسخة الاحتياطية وكيفية الإذن وبيانات وصفية الحداف عند توفرها. |
| `cli` | `string \| undefined` | حداف الوكيل المصدر، مثل `claude` أو `codex` أو `cursor`. |
| `params` | `Record<string, unknown>` | معاملات هذه السياسة. تعلن سياسة مدمجة أو حزمة مخطط، والقيم التي كوّنها المستخدم يتم دمجها على الإعدادات الافتراضية. سياسة في ملف مخصص تعلن عن عدم وجود مخطط، لذلك تستقبل أي شيء قام المستخدم بتكوينه تحت اسمه، و`{}` عندما لا يتم تكوين شيء. |

تعامل مع كل قيمة اختيارية على أنها اختيارية حقيقة. إصدارات الوكيل وأنواع الأحداث لا توفر جميعها نفس الحقول.

### مدخلات الأدوات الشائعة

يوحد Failproof AI الأدوات الشائعة عبر الحدافير المدعومة بحيث يمكن لسياسة عادة استخدام شكل إدخال واحد.

| الأداة | الحقول الشائعة |
| --- | --- |
| `Bash` | `command` |
| `Read` | `file_path` |
| `Write` | `file_path`, `content` |
| `Edit` | `file_path`, `old_string`, `new_string` |
| `Grep` | `pattern`, `path` |

استخدم القسر الدفاعي لأن قيم مدخلات الأداة يتم كتابتها على أنها `unknown`:

```ts
const command = String(ctx.toolInput?.command ?? "");
const filePath = String(ctx.toolInput?.file_path ?? "");
```

## اختر الحدث

| الحدث | عندما يعمل | الاستخدام النموذجي |
| --- | --- | --- |
| `PreToolUse` | قبل تنفيذ أداة. | حجب أو توجيه الأوامر والكتابات والقراءات والإجراءات الخارجية. هذا هو الحارس. |
| `PostToolUse` | بعد تنفيذ الأداة بالفعل. | فحص أو استبدال النتيجة التي يقرأها النموذج. لا يمكنها التراجع عن التأثير الجانبي—الكتابة أو الأمر حدث بالفعل—وعلى عشرة من اثني عشر حداف لا يمكن للحكم إيقاف أي شيء. فقط Codex وCopilot يستهلكونها، وحتى هناك تحل محل النتيجة التي يقرأها النموذج بدلاً من منع الاستدعاء. لا تستخدمها أبدًا كحارس. |
| `PermissionRequest` | عندما يطلب الوكيل الإذن. | تطبيق قواعد الإذن الخاصة بالمنظمة. |
| `UserPromptSubmit` | قبل متابعة الفوري المقدم. | رفض التعليمات المحظورة أو إضافة توجيهات سير العمل. |
| `Stop` | عندما يحاول الوكيل الانتهاء. | طلب شرط إكمال يمكن الوصول إليه، مثل خطوة التحقق المحلية. |
| `SubagentStop` | عندما يحاول وكيل فرعي الانتهاء. | بوابة العمل المفوضة قبل عودتها إلى الأب. |
| `SessionStart` / `SessionEnd` | عند حدود الجلسة. | تسجيل أو فحص حالة على مستوى الجلسة. |

توفر الأحداث والسلوك الحاجز تعتمد على حداف الوكيل، والاختلافات كبيرة: Failproof AI لا يثبت خطاف `Stop` لـ Goose أو Hermes، لذلك بوابة الإيقاف لا تعمل أبدًا على أي منهما. انظر [حدافير الوكيل](/ar/reference/harnesses) قبل الاعتماد على حدث عبر أسطول مختلط.

<Accordion title="جميع أسماء أحداث السياسة">
  `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PermissionDenied`, `PostToolUse`, `PostToolUseFailure`, `Notification`, `SubagentStart`, `SubagentStop`, `TaskCreated`, `TaskCompleted`, `Stop`, `StopFailure`, `TeammateIdle`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `FileChanged`, `WorktreeCreate`, `WorktreeRemove`, `PreCompact`, `PostCompact`, `Elicitation`, `ElicitationResult`, `UserPromptExpansion`, `PostToolBatch`, و`Setup`. هذه هي المجموعة الكاملة من 29 اسم حدث كنسي يتم توحيد معجم الأحداث الخاص به لكل حداف فيها.
</Accordion>

## تأليف أنماط السياسات الشائعة

### حجب الكتابة إلى المسارات المحمية

```ts
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-generated-file-edits",
  description: "Require generated files to be changed through their generator",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (!["Write", "Edit"].includes(ctx.toolName ?? "")) return allow();

    const filePath = String(ctx.toolInput?.file_path ?? "");
    if (!/(^|\/)(dist|generated)\//.test(filePath)) return allow();

    return deny("Edit the source and run the generator instead of changing generated output.");
  },
});
```

### إعطاء توجيهات غير حاجزة

```ts
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "prefer-reviewed-deploy-command",
  description: "Guide agents toward the reviewed deployment wrapper",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();

    const command = String(ctx.toolInput?.command ?? "");
    if (!/^kubectl\s+apply\b/.test(command.trim())) return allow();

    return instruct("Use ./scripts/deploy-reviewed instead of invoking kubectl directly.");
  },
});
```

### بوابة إكمال الجلسة

```ts
import { execFileSync } from "node:child_process";
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "require-clean-typecheck",
  description: "Require the project typecheck to pass before the agent finishes",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    const cwd = ctx.session?.cwd;
    if (!cwd) return allow();

    try {
      execFileSync("bunx", ["tsc", "--noEmit"], {
        cwd,
        stdio: "ignore",
        timeout: 8_000,
      });
      return allow();
    } catch {
      return deny("Fix the typecheck errors before finishing the task.");
    }
  },
});
```

<Warning>
  يمكن لحدث `Stop` المرفوض أن يجعل الوكيل يعيد المحاولة. فقط بوابة على شرط يمكن للوكيل تحقيقه في البيئة الحالية، وقيد كل استدعاء عملية فرعية أو شبكة.
</Warning>

## تحميل ملفات السياسة

### ملفات الاتفاقية

ملفات الاتفاقية تحمل تلقائيًا:

```text
<project>/.failproofai/policies/security-policies.ts
~/.failproofai/policies/personal-policies.mjs
```

- يتم تحميل مشاريع ودلائل سياسة المستخدم.
- ملفات التحميل أبجديًا داخل كل دليل.
- يجب أن ينتهي الملف بـ `policies.js` أو `policies.mjs` أو `policies.ts`.
- يدعم استدعاءات `customPolicies.add()` المتعددة في ملف واحد.
- يدعم الاستيراد النسبي من الوحدات المحلية.
- يمكن التزام سياسات المشروع بحيث تتبع نفس القواعد المستودع.

<Warning>
  ملف في الدليل الذي لا ينتهي اسمه بـ `policies.{js,mjs,ts}` تم تخطيه. يبدو مثبتًا ولا ينفذ أي شيء. قائمة المحمل بكل ملف تم تخطيه مع الاسم الذي يجب إعادة تسميته؛ اقرأ هذا التحذير بدلاً من افتراض أن السياسة حية. شحنت هذه المستودع `block-version-bumps.mjs` بهذه الطريقة، والحارس المكتوب بعد نتوء إصدار سيء لم يعمل أبدًا.
</Warning>

يحمل `~/.failproofai/policies/` أيضًا دليلين فرعيين لم تضعهما هناك: `cloud-policies/` للنشرات التي تديرها الأسطول و`packs/` للحزم المثبتة. المحمل لا ينزل أبدًا إلى أي منهما، لذلك لا يتم التقاط أي شيء فيهما كسياسة اتفاقية غير تحقق منها.

### إيقاف سياسة مكتشفة

مفتاحان في `policies-config.json` يطفئان سياسات الاتفاقية دون حذف أو إعادة تسمية الملف:

| المفتاح | التأثير |
| --- | --- |
| `disabledCustomPolicies` | مصفوفة من معرّفات السياسة المؤهلة بالمصدر التي لم تسجل. |
| `customPoliciesEnabled` | اضبط على `false` لإيقاف تحميل `.failproofai/policies/` بالكامل. الغياب يعني مفعل. |

تكتب علامة التبويب **السياسات → التكوين** في [لوحة التحكم المحلية](/ar/reference/local-dashboard) `disabledCustomPolicies` بالنسبة لك. `customPoliciesEnabled` تكتب بـ `failproofai config` أو بيدويًا.

### ملفات صريحة

استخدم المسارات الصريحة عندما يجب أن يسمي التحقق أو التكوين ملف الإدخال مباشرة:

```bash
failproofai policies --install \
  --custom ./security.policies.ts \
  --custom ./workflow.policies.ts \
  --scope project
```

تحمل الملفات الصريحة أولاً، متبوعة بملفات اتفاقية المشروع ثم ملفات اتفاقية المستخدم. اكتشف ملف من خلال كلا المسارين يتم تحميله مرة واحدة.

## التحقق والاختبار

`-c` هو الشكل القصير لـ `--custom` و`-i` لـ `--install`. ينفذ الملف الآن، في أي مسار واسم ملف:

```bash
failproofai policies -i -c ./checkout-policies.ts
failproofai policies
```

اطلب من وكيلك فعل الشيء الذي حجبته وشاهده يتم رفضه. لم يتم نشر أي شيء ولا يتأثر جهاز آخر.

التحقق ينفذ الوحدة من خلال المحمل الإنتاجي ويؤكد أنها تسجل سياسة واحدة على الأقل. يعترف بالملفات المفقودة وأخطاء بناء الجملة والاستيراد غير المحلول والاستثناءات على مستوى أعلى وانتهاء المهلة الزمنية لتحميل الوحدة. لا يثبت أن منطق المطابقة الخاص بك صحيح.

اختبر على الأقل هذه الحالات:

- إجراء واحد يجب أن يطابق وينتج السبب المقصود للسياسة.
- إجراء قريب لكن آمن واحد يجب أن يعيد `allow()`.
- حقول أداة مفقودة أو منسقة بشكل سيء.
- بناء جملة الأمر البديل والمسارات والاقتباسات والحالة والمسافة البيضاء.
- تبعية عملية فرعية أو شبكة غير متاحة.

نسب النتيجة إلى سياستك المخصصة ضمن **السياسات → النشاط** على لوحة التحكم المحلية. اختبار محجوب ليس كافيًا إذا اتخذت سياسة مدمجة مختلفة القرار.

## السلوك وقت التشغيل

- تقيم السياسات المدمجة قبل السياسات المخصصة.
- يوقف أول `deny` تقييم السياسات الإضافية.
- يمكن دمج نتائج `instruct` متعددة عندما لا تنكر أي سياسة الحدث.
- لدالة السياسة مهلة زمنية تنفيذ بمدة 10 ثواني. تحميل الوحدة على مستوى أعلى له نفس المهلة.
- قذف استثناء أو انتهاء المهلة الزمنية مسجل ومعامل على أنه `allow()`.
- ملف اتفاقية يفشل في التحميل يتم تخطيه؛ ملفات مخصصة أخرى والسياسات المدمجة تستمر.
- تمرير المراقبة تشغل السياسة لأنها وتسجل أي حكم غير السماح دون فرضه. طبقتان تضبطانها: `failproofai publish --effect observe` على حزمة تنشرها، و`fp fleet deploy <machine> --add <id>:observe` على نشر السحابة. في كلتا الحالتين يتم تقييم السياسة تحت نفس مهلة 10 ثواني كما هو الحال في حالة الإنفاذ، لذلك سياسة التي تنتهي المهلة الزمنية لتسجيل السماح.

### حيث المحمل يفشل مغلق بدلاً من ذلك

القاعدة المفتوحة المجانية أعلاه تغطي ملفًا أسقطته بنفسك. مسارات اثنين بقصد القيام بالعكس، لأن كلاهما يعني أن هذا الجهاز أخبر أنه كان لديه إنفاذ لا يملكه.

| الموقف | النتيجة |
| --- | --- |
| لا يمكن تحميل حزمة محددة، أو الهضم المثبت لا يطابق | كل حدث في النطاق الذي أعلنته تلك الحزمة محظور، ينسب إلى `pack/failproofai-pack-unavailable`. `UserPromptSubmit` يعلم بدلاً من الرفض، حتى لا تحتجز أبدًا بعيدًا عن الوكيل الذي تحتاجه لإصلاحه. بيانات وصفية الحزمة غير القابلة للقراءة توسع النطاق المرفوض بدلاً من تضييقه. |
| الخادم `failproofaid` لا يمكن الوصول إليه على جهاز أكمل الإعداد | كل حدث محظور. لم يتم قراءة أي مخطط وسياسة مخصصة لا تعمل، لأن خادم لا يمكن الوصول إليه لم يكن بإمكانه تشغيلهما. عدم تطابق إصدار البروتوكول يرفض أيضًا، مع رسالة تسمي `failproofai config`. |

على جهاز أكمل الإعداد، `failproofaid` هو المقيّم الوحيد، لذا `fn` الخاص بك يعمل داخل عامل دافئ الخادم بدلاً من عملية الخطاف. يسمح عميل الخطاف بـ 150 ملي ثانية للاتصال و 30 ثانية للإجابة، بشكل مريح فوق المهلة الزمنية الثابتة 10 ثواني كل دالة سياسة تحصل عليها.

ابق وحدات السياسة حتمية وسريعة. تجنب استدعاءات الشبكة على مستوى أعلى أو بدء الخادم. قيد العمل داخل `fn`، اعترض بفشل التبعية، واختر بقصد ما إذا كان هذا الفشل يجب السماح أو رفض العملية.

## من ملف إلى حزمة

الحزمة هي كيفية أن يصبح ملف السياسة شيئًا يمكن للآلات الأخرى تثبيته. أمران يأخذانك من لا شيء إلى حزمة منشورة:

```bash
failproofai publish --init
failproofai publish
```

`--init` يسأل ما يسمى الحزمة، يكتب `<name>.mjs`، ويتوقف. الملف ليس قالب مع فراغ—إنه سياسة واحدة تحجب بالفعل `git push --force`، لذلك أول شيء تحرره هو شيء يعمل. ثبته محليًا باستخدام `failproofai policies -i -c ./<name>.mjs`، ثم شغل `failproofai publish` من داخل مستودع git الذي يحمله.

حقلان أهمان بمجرد شحن سياسة في حزمة:

| الحقل | ماذا يفعل |
| --- | --- |
| `category` | ما يختاره `failproofai policies add <owner>/<repo> --category git,database` عليه. |
| `defaultEnabled` | ما إذا كانت `failproofai policies add <owner>/<repo>` مجردة تشغل هذه السياسة. الافتراضي هو `false`. |

تعيين `--effect` لكل حزمة بدلاً من كل سياسة: `failproofai publish --effect observe` ينشر حزمة تسجل ما كانت سياساتها قررت وتحجب لا شيء. الافتراضي هو `enforce`. هذا وضع المراقبة على جهاز واحد بدون اتصال السحابة — اقرأ القرارات المسجلة مرة أخرى تحت **السياسات → النشاط** على لوحة التحكم المحلية.

إصدار الحزمة هو رمز الالتزام 12 أحرف قصير الذي تم بناؤه منه، لذا `publish` يرفض خارج فحص git وعلى شجرة قذرة. انظر [نشر حزمة](/ar/policies/publish-a-pack) للتدفق الكامل، و[حزم السياسة](/ar/policies/packs) لكيفية تحل الكل إصدار.

## تصدير API

| التصدير | الغرض |
| --- | --- |
| `customPolicies.add(policy)` | تسجيل سياسة مخصصة عند تحميل الوحدة. |
| `allow(reason?)` | السماح بالعملية. |
| `instruct(reason)` | السماح بالعملية وتوفير التوجيه حيث يدعم. |
| `deny(reason)` | حجب العملية حيث يدعم. |
| `getCustomHooks()` | إعادة السياسات المسجلة حاليًا في سجل وحدة. |
| `clearCustomHooks()` | مسح هذا السجل، بشكل أساسي للاختبارات والمحملات. |

TypeScript تصدر `PolicyContext` و`PolicyResult` و`CustomHook` و`PolicyDecision` و`PolicyFunction`.
