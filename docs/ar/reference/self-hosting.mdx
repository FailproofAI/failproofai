## المتطلبات الأساسية

- Kubernetes 1.27 أو أحدث مع إمكانية الوصول كمسؤول المجموعة
- `kubectl` مع دعم Kustomize
- Helm 3
- الوصول إلى صور `ghcr.io/agenteye-enterprise` الخاصة
- اسما نطاق DNS: أحدهما للوحة التحكم والآخر للاستقبال
- تخزين دائم لـ PostgreSQL و ClickHouse
- cert-manager و Traefik، أو بنية إدخال وشهادات معادلة متكيفة في overlay الخاص بك
- SMTP لتسجيل الدخول بكود مرة واحدة والإشعارات في الإنتاج

توفر شجرة المصدر overlay موجهة لـ AWS/EKS و overlay منفصل لـ GCP/GKE. لا تجمع بين تعليماتها الخاصة بالشهادات وموازن الحمل والنسخ الاحتياطية: يستخدم GKE تكوين DNS-01 و GCS و التوسع التلقائي الخاص به.

## تسلسل النشر

<Steps>
  <Step title="تحضير المجموعة">
    ثبّت cert-manager وأجهزة التحكم الخاصة بالإدخال العام ولوحة التحكم، تحقق من موازنات الحمل الخاصة بها، ثم أنشئ النطاق وبيانات اعتماد سحب الصور وبيانات اعتماد قاعدة البيانات ومفتاح المسؤول الأولي وأسرار المصادقة وSMTP.
  </Step>
  <Step title="إعداد النطاقات العامة">
    اضبط `INGEST_DOMAIN` و `DASHBOARD_DOMAIN` في ملف بيئة النطاق المُنشأ من overlay وأنشئ سجلات DNS تشير إلى موازنات الحمل المطابقة.
  </Step>
  <Step title="تطبيق والتحقق من overlay منصة واحدة">
    استخدم overlay customer/EKS أو GCP. افحص مخرجات Kustomize المعروضة، طبّقها، وأكّد أن جميع أحمال العمل والشهادات وصلت إلى حالتها المقصودة قبل تسجيل الآلات.
  </Step>
  <Step title="تعزيز الوصول والاستقبال">
    قم بتسجيل الدخول كمسؤول محمي، أنشئ مفتاح آلة بنطاق المنظمة، وأرسل جلسة اختبار صغيرة عبر نقطة الاستقبال العامة.
  </Step>
</Steps>

## الخدمات المطلوبة والاختيارية

| المكون | المتطلب |
| --- | --- |
| ClickHouse | مطلوب. يرفض الخادم البدء بدون مخزن الأحداث الكنسي الخاص به. |
| PostgreSQL | مطلوب للمستخدمين والمنظمات والكائنات المحفوظة وحالة مستوى التحكم. |
| Redis | اختياري. يتدهور الخادم ولوحة التحكم إلى السلوك المدعوم بقاعدة البيانات عند عدم توفره. |
| SMTP | اختياري للتطوير، مطلوب لإنتاج بريد OTP والإخطارات. |
| Evaluator | اختياري. يبقى التقييم التلقائي معطلاً بدون `EVALUATOR_ENDPOINT`. |
| Assistant/audit LLM | اختياري. تبقى ميزات المساعد والتدقيق المدعومة بـ LLM خاملة حتى يتم تكوين اتصال LLM. |
| النسخة الاحتياطية لتخزين الكائنات | موصى به بشدة لأرشيفات النسخ الاحتياطية لـ PostgreSQL و ClickHouse. |

### سعة التدقيق وتسليم الفشل

قم بتشغيل التدققات على نشر audit-agent المخصص عند توفره. يقبل كل pod من audit-agent تحقيقاً واحداً بشكل افتراضي؛ قم بتوسيع الإنتاجية بالنسخ المتماثلة بدلاً من رفع التزامن لكل pod بدون زيادة الذاكرة أيضاً. يمكن للخادم إرسال `server replicas × AUDIT_WORKERS` تدققات بالتوازي، لذا يجب أن تكون سعة المُرسل كبيرة بما يكفي لملء أسطول audit-agent.

عندما يكون كل فتحة audit-agent مشغولة، ينتظر التدقيق ويحاول مجدداً لمدة تصل إلى ربع دورته، محدود بستة ساعات. إذا لم تصبح أي فتحة متاحة، ينتهي التشغيل بدون نتائج ويرسل بريد فشل. تتطلب حالات الفشل المتكررة "مشغول" نسخاً متماثلة أكثر من audit-agent أو نقاط دورة أكثر تباعداً. تشير حالات الفشل المتكررة "إيقاف التشغيل" إلى pods غير مستقرة أو نشر متكرر بدلاً من عدم كفاية السعة.

تتطلب إخطارات الفشل قناة بريد مفعلة و SMTP. تستخدم مستقبلات التدقيق، ثم تعود إلى `alerts.email_default_recipients` عندما لا يكون للتدقيق قناة بريد.

## المصادقة والبريد

تستخدم لوحة التحكم البريد الإلكتروني والرموز لمرة واحدة. بدون SMTP، تسجل نشرات التطوير رموز OTP في مخرجات الخادم. عند تعيين `SMTP_HOST`، يكون اسم المستخدم وكلمة المرور والمرسل مطلوبين كمجموعة وإلا يرفض الخادم البدء.

`SMTP_TLS` قيمة منطقية. النقل المشفر المدعوم هو STARTTLS، عادة على المنفذ 587؛ SMTPS الضمني على المنفذ 465 غير مدعوم من قِبل نقل الخادم الحالي.

اضبط عنوان URL لوحة التحكم العام بشكل صحيح لأن رسائل البريد الإلكتروني OTP والتنبيهات والحوادث والتدقيقات تستخدمه للروابط العميقة. تتحكم عضوية المنظمة في من يمكنه طلب رمز؛ يمكن لكل منظمة تقييد تسجيلات أعضائها الخاصة بشكل إضافي في **Administration → Settings**.

## متطلبات متعددة المستأجرين

قبل إنشاء منظمة ثانية، قم بتكوين سر استقاقة ClickHouse قوي ومستقر للمنظمة وأبقِه متطابقاً عبر جميع نسخ الخادم. يمكن لتدويره بدون هجرة منسقة أن يتيم مستخدمي ClickHouse الخاصين بالمنظمة.

أبق مستمع المسؤول على المستوى الداخلي. وحدة التحكم المشغل المُتاحة اختيارية وتم تصميمها لـ `kubectl port-forward`، وليس الإدخال العام. يتطلب تفعيلها مفتاح API قوي خاص بها وصندوق بريد super-admin وتسليم SMTP للعامل الثاني الفعال.

### CLI منظمة Break-glass

يأتي `agenteye-orgctl` داخل صورة الخادم ويتحدث مباشرة إلى PostgreSQL و ClickHouse. يبقى متاحاً عندما يكون الخادم العام أو وحدة التحكم المشغل غير صحي.

```bash
kubectl -n agenteye exec deploy/server -- \
  agenteye-orgctl org create --slug acme --name "Acme Corp"
kubectl -n agenteye exec deploy/server -- agenteye-orgctl org list
kubectl -n agenteye exec deploy/server -- \
  agenteye-orgctl member add --org acme --email ops@acme.com --set admin --protected
```

تتضمن العمليات المدعومة للمنظمة الإنشاء والقائمة وإعادة التسمية والحذف الناعم والاستعادة وإعادة توفير مستخدم ClickHouse وإدارة تاريخ الفواتير والأعلام المميزة والتنقية التي لا رجعة فيها. تتضمن العمليات العضو الإضافة والقائمة والتحديث والإزالة وتجاوزات الأذونات وحالة المسؤول المحمي.

استخدم soft-delete قبل التنقية. `org purge` لا رجعة فيها وتتطلب حذف المنظمة أولاً. لا يمكن إزالة الأعضاء المحميين أو خفض رتبتهم من خلال صفحة المستخدمين العادية للمنظمة حتى يقوم مشغل بإلغاء حمايتهم بشكل صريح.

## قائمة التحقق من جاهزية الإنتاج

- يتم حل DNS للاستقبال ولوحة التحكم لمسارات إدخال مختلفة مقصودة.
- TLS صالح؛ استخدم TLS متبادل على الاستقبال حيث يتطلبها نشرك.
- يحتوي PostgreSQL و ClickHouse على تنبيهات السعة.
- تتضمن النسخ الاحتياطية كلا المتاجر وإجراء استعادة مختبر.
- التنبيهات على صمت الاستقبال وفشل أحمال العمل وانتهاء صلاحية الشهادة والضغط التخزيني والنسخ الاحتياطية القديمة.
- يتم جمع السجلات المنظمة بدون تكرار خط أنابيب سجل مجموعة موجود.
- لم يتم تغيير التزامن الخاص بـ Evaluator والتدقيق والعامل التنبيهي بدون دليل قائمة الانتظار المقاس.
- تم تسجيل إصدار تطبيق مثبت وإجراء تراجع قبل الترقيات.
