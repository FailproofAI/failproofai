يجيب مساعد السحابة في Failproof AI على الأسئلة حول أسطولك باستخدام اللغة الطبيعية. يمكنه تحليل الجلسات والأعطال وتشغيل الاستعلامات وبناء لوحات التحكم والتحقيق في التقييمات والتنبيهات والمساعدة في إنشاء وتشغيل التدقيقات دون الحاجة إلى ترجمة المهمة إلى شاشات المنتج أو أوامر CLI. في لوحة التحكم، يُطلق على الزر اسم **Open agent chat**؛ وفي [`fp` CLI](/ar/reference/cloud-cli) يكون **fp agent** مجموعة الأوامر.

```text
Why did production checkout agents regress this week?
Build a dashboard for tool failures, latency, and evaluation scores.
Create an audit that finds agents retrying the same failed action without changing approach.
Show me the sessions behind the most common audit finding.
```

يعمل المساعد مع البيانات والأذونات المتاحة في المنظمة النشطة. راجع الأدلة والتغييرات المقترحة قبل تطبيق الإجراءات التي تؤثر على المستخدمين أو الوكلاء الآخرين.

<Note>
  يعمل المساعد في لوحة التحكم والدردشات الخاصة به تتعلق بشخص، لذا لا توجد مسار API خلفه يمكن لمفتاح أن يستدعيه. كل فئة من فئات `fp agent` الفرعية تتطلب جلسة معتمدة (`fp login`) وإذن `agent:use`، وتخرج برمز 2 تحت `--api-key` أو `FP_API_KEY`. لا يمكن لمفتاح API أن يصل إليه، لذا يجب على وظيفة مجدولة أن تحمل رمز جلسة معتمد في `--token` أو `FP_TOKEN`. هذا يعمل — `fp agent ask` يقرأ السؤال من stdin عندما لا يكون هناك TTY — لكن رمز الجلسة ينتهي بعد حوالي 24 ساعة من `fp login`، مما يجعل المساعد خيارًا سيئًا للأتمتة غير المراقبة حتى وإن كان يعمل.
</Note>

## اسأل المساعد

<Tabs>
  <Tab title="لوحة التحكم">
    1. اختر **Open agent chat** واصف ما تريد فهمه أو إنشاءه أو تشغيله.
    2. راجع استدعاءات الأدوات والجداول ونتائج الاستعلام الخاصة بالمساعد أثناء عمله.
    3. افتح الجلسة أو التنبيه أو الاستعلام المُشار إليه للتحقق من النتيجة مقابل بيانات المصدر.
    4. ابدأ دردشة جديدة للتحقيق في موضوع مختلف، أو استخدم سجل الدردشة لمتابعة نفس خط التحليل.

    ![مساعد السحابة يجيب على سؤال الملاحظة مع التحليل الداعم والاستعلامات.](/images/dashboard/assistant.png)
  </Tab>
  <Tab title="CLI">
    ابدأ بـ `health`. يوضح ما إذا كان المساعد مفعّلاً لهذا النشر وما إذا كان نموذج LLM مُعدًا له. حيث لا يوجد LLM، يفشل `ask` و`models` يُبلّغ أنه لا يوجد — `chats` و`show` و`rename` و`delete` لا تستشير الصحة أبدًا وتستمر في العمل.

    ```bash
    fp agent health
    fp agent models
    fp agent ask "Which production checkout agents had the most tool errors in the last 24 hours?"
    ```

    يسرد `fp agent models` النماذج التي يسمح بها هذا النشر وأيها الافتراضي. مرّر واحدًا إلى `ask --model <name>`. ربط الإجابة بالنص الذي لديك بالفعل باستخدام `--page-context <text>`، وأنبوب السؤال على stdin بدلاً من تمريره كحجة عندما يأتي من ملف أو أمر سابق:

    ```bash
    cat incident-notes.md | fp agent ask --model <model>
    ```

    يتم حفظ كل سؤال في دردشة. بدون `--chat` يبدأ واحدة جديدة ويطبع معرّفها القصير؛ مع `--chat` يستمر في هذا الخيط.

    ```bash
    fp agent chats
    fp agent show <chat-id>
    fp agent ask "Open representative sessions" --chat <chat-id>
    fp agent rename <chat-id> --title "checkout regression"
    fp agent delete <chat-id> --yes
    ```

    يسرد `fp agent chats` دردشاتك الأحدث أولاً كـ `chat-id · title · messages · updated`، حيث `updated` هي عمر آخر نشاط في الدردشة. المعرّف `chat-id` الموضح هو القصير — أول 8 أحرف — و`show` و`rename` و`delete` و`ask --chat` كلها تحل هذا البادئة. معرف لا يطابق أي شيء يخرج مع رمز 6 مع صندوق `chat not found`؛ واحد يطابق عدة يطلب بادئة أطول.

    يؤكد `fp agent delete` أولاً. `--yes` يتخطى الطلب، وكذلك أي استدعاء غير تفاعلي: تحت `--json`، أو مع إعادة توجيه stdin، يتقدم دون السؤال.
  </Tab>
</Tabs>

## العمل بفعالية مع المساعد

- أعطه هدفًا أولاً؛ أضف بيئة أو سير عمل أو نطاق زمني عندما تكون تلك الحدود مهمة.
- تعامل مع SQL المُنشأ والملخصات كأداة تحقيق وليس دليلاً نهائيًا.
- افتح جلسات تمثيلية قبل إنشاء تدقيق أو مشكلة أو تنبيه أو سياسة.
- احفظ عوامل المنظمة والبيئة والوقت صريحة.
- احفظ SQL مفيد كاستعلام حتى يتمكن مشغل آخر من إعادة إنتاج النتيجة.

<Warning>
  يتم تطبيق طبقتي أذونات، وتفشلان بطرق مختلفة. `agent:use` يسد الميزة نفسها: بدونها، `fp agent` ودردشة لوحة التحكم غير متاحة. ثم تُحد الإجابات من خلال أذونات البيانات للمستخدم المعتمد — `events:read` و`evaluations:read` و`queries:run` و`policies:read` — لذا فإن المستخدم الذي يمكنه فتح المساعد قد يحصل على إجابة فارغة للبيانات التي لا يمكنه قراءتها. لا تُوسّع الأذونات لجعل سؤال يعمل؛ اطلب من مشغل مصرح بتشغيل التحقيق بدلاً من ذلك. انظر [Keys and permissions](/ar/admin/keys-and-permissions).
</Warning>
