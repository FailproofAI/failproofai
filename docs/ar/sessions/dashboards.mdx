تجمع لوحات المعلومات الاستعلامات المحفوظة في عرض تشغيلي. قم بإنشاء واحدة حول قرار تتوقع أن يتخذه شخص ما—وليس حول كل مقياس متاح.

## بناء لوحة معلومات

<Tabs>
  <Tab title="لوحة المعلومات">
    1. انتقل إلى **Analyze → Queries**، أنشئ أو افتح استعلاماً محفوظاً، وتحقق من نتيجته.
    2. حدد **add to dashboard**، ثم اختر لوحة معلومات موجودة أو أنشئ واحدة ضمن **Analyze → Dashboards**.
    3. افتح لوحة المعلومات، ادخل إلى وضع التحرير، رتب البطاقات، واحفظ التخطيط.
    4. عد إلى الاستعلام عندما تحتاج إلى تغيير البيانات أو المرشحات خلف بطاقة.

    ![لوحة معلومات مكونة من استعلامات محفوظة لحجم الأحداث والأخطاء والكمون واستخدام رموز النموذج.](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    عمليات CRUD في لوحة المعلومات غير مكشوفة بواسطة Cloud CLI الحالي. استخدم CLI لبناء والتحقق من الاستعلام المحفوظ، ثم أضفه إلى لوحة معلومات في الواجهة.

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

تتضمن مجموعات لوحات المعلومات المفيدة:

- **النماذج:** الحجم، الكمون، استخدام الرموز، معدل الأخطاء، ودرجات التقييم.
- **التقييمات:** معدل النجاح واتجاهات الدرجات حسب الوكيل أو البيئة.
- **الأدوات:** حجم المكالمات، معدل الفشل، المدة، والمكالمات المتكررة.
- **الخطافات والسياسات:** القرارات والرفض ومعدل مطابقة السياسة.
- **مقاييس سير العمل المخصص:** النتائج من حقول الأحداث والـ SQL الخاصة بك.

ابدأ بالاستعلام المحفوظ، تحقق من نتيجته، ثم أضفه كبطاقة. حافظ على مرشحات الإنتاج والتطوير صريحة حتى لا تخفي حركة المرور الاختبارية الانحدار.

<Tip>
  أعطِ كل لوحة معلومات مالكاً وسؤال رد، مثل هل موثوقية checkout-agent أسوأ من الأسبوع الماضي؟
</Tip>
