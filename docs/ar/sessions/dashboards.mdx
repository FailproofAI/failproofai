تجمع لوحات المعلومات الاستعلامات المحفوظة في عرض تشغيلي. قم ببناء واحدة حول قرار تتوقع أن يتخذه شخص ما—وليس حول كل مقياس متاح.

## بناء لوحة معلومات

<Tabs>
  <Tab title="Dashboard">
    1. انتقل إلى **Analyze → Queries**، وأنشئ أو افتح استعلاماً محفوظاً، وتحقق من النتيجة.
    2. حدد **add to dashboard**، ثم اختر لوحة معلومات موجودة أو أنشئ واحدة جديدة ضمن **Analyze → Dashboards**.
    3. افتح لوحة المعلومات، ادخل وضع التحرير، رتب البطاقات، وحفظ التخطيط.
    4. عد إلى الاستعلام عندما تحتاج لتغيير البيانات أو المرشحات خلف بطاقة.

    ![لوحة معلومات مكونة من استعلامات محفوظة لحجم الأحداث والأخطاء والزمن الكامن واستخدام رموز النموذج.](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    عمليات CRUD للوحة المعلومات غير متاحة بواسطة واجهة سطر الأوامر السحابية الحالية. استخدم واجهة سطر الأوامر لبناء والتحقق من الاستعلام المحفوظ، ثم أضفه إلى لوحة معلومات في واجهة المستخدم.

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

تتضمن مجموعات لوحات المعلومات المفيدة:

- **النماذج:** الحجم والزمن الكامن واستخدام الرموز ومعدل الأخطاء ودرجات التقييم.
- **التقييمات:** معدل النجاح واتجاهات الدرجات حسب الوكيل أو البيئة.
- **الأدوات:** حجم الاستدعاءات ومعدل الفشل والمدة والاستدعاءات المكررة.
- **الخطافات والسياسات:** القرارات والرفضات ومعدل مطابقة السياسة.
- **مقاييس سير العمل المخصصة:** النتائج من حقول الأحداث والبيانات الخاصة بك والـ SQL.

ابدأ باستعلام محفوظ، تحقق من النتيجة، ثم أضفه كبطاقة. اجعل مرشحات الإنتاج والتطوير صريحة حتى لا يخفي حركة المرور الاختبارية انحداراً.

<Tip>
  أعط كل لوحة معلومات مالك وسؤال استجابة، مثل "هل أصبحت موثوقية checkout-agent أسوأ من الأسبوع الماضي؟"
</Tip>
