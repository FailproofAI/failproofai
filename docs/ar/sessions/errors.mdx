يوفر لك قسم الأخطاء عرضاً موجهاً نحو الفشل عبر الجلسات. جمّع حسب نوع الخطأ أو الوكيل أو البيئة أو النموذج أو الأداة أو نافذة زمنية للعثور على مشاكل تشغيلية متكررة.

## التحقق من الأخطاء

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **Observe → Errors**.
    2. صفّ حسب البيئة أو نوع الحدث أو نوع الخطأ أو الوكيل أو معرف الجلسة أو نص البحث.
    3. وسّع خطأ مجمّع لمشاهدة مثيلاته. حدد صفاً لفتح الحدث الدقيق في جلسته.
    4. حدد عنصر التحكم بالجرس على خطأ تمثيلي لبدء تنبيه للأخطاء المماثلة.

    ![صفحة الأخطاء تعرض رسم بياني للفشل وأخطاء مجمّعة والعنصر التحكم لإنشاء تنبيه.](/images/dashboard/errors.png)
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    ```bash
    fp errors --env production --since 24h
    fp errors --error-type TimeoutError --agent-id checkout-agent
    fp errors --aggregate --env production --since 7d
    ```

    استخدم `fp events --full --session-id <id>` عندما تحتاج إلى حمولة البيانات الأولية خلف ملخص الخطأ.
  </Tab>
</Tabs>

## استخدم قسم الأخطاء عندما تحتاج إلى

- العثور على فئة الخطأ الأكثر تكراراً في الإنتاج.
- تحديد ما إذا كانت أداة واحدة أو نموذج واحد يسبب قفزة.
- الانتقال من عدد مجمّع إلى جلسات تمثيلية.
- إنشاء تنبيه للتكرار.
- إدراج السكان المتأثرين في عملية تدقيق.

الخطأ هو حدث ملاحظ. التقييم الفاشل هو حكم جودة، وبحث التدقيق هو نمط فشل تم التحقق منه. احتفظ بهذه الفروقات عند تحديد سير العمل الاستجابة المراد استخدامه.
