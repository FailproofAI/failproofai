يوفر لك قسم الأخطاء عرضًا موجهًا نحو الفشل عبر الجلسات. قم بالتجميع حسب نوع الخطأ أو الوكيل أو البيئة أو النموذج أو الأداة أو نافذة زمنية لاكتشاف المشاكل التشغيلية المتكررة.

## التحقيق في الأخطاء

<Tabs>
  <Tab title="Dashboard">
    1. انتقل إلى **Observe → Errors**.
    2. قم بالتصفية حسب البيئة أو نوع الحدث أو نوع الخطأ أو الوكيل أو معرف الجلسة أو نص البحث.
    3. وسّع الخطأ المجمّع لعرض حالاته. حدد صفًا لفتح الحدث بالضبط في جلسته.
    4. حدد عنصر التحكم بالجرس على خطأ تمثيلي لبدء تنبيه للأخطاء المماثلة.

    ![صفحة الأخطاء تعرض رسم بياني للفشل وأخطاء مجمعة وعنصر التحكم لإنشاء تنبيه.](/images/dashboard/errors.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp errors --env production --since 24h
    fp errors --error-type TimeoutError --agent-id checkout-agent
    fp errors --aggregate --env production --since 7d
    ```

    استخدم `fp events --full --session-id <id>` عندما تحتاج إلى حمل البيانات الأولية خلف ملخص الخطأ.
  </Tab>
</Tabs>

## استخدم الأخطاء عندما تحتاج إلى

- العثور على فئة الخطأ الأكثر تكرارًا في الإنتاج.
- تحديد ما إذا كانت أداة أو نموذج واحد يسبب ارتفاعًا.
- الانتقال من عدد مجمع إلى جلسات تمثيلية.
- إنشاء تنبيه للتكرار.
- تضمين السكان المتأثرين في تدقيق.

الخطأ هو حدث ملاحظ. التقييم الفاشل هو حكم على الجودة، والتحديد المدقق هو نمط فشل تم التحقق منه. احتفظ بهذه التمييزات عند تحديد سير العمل للاستجابة المراد استخدامه.
