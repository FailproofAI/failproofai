تساعدك الأحداث المباشرة على تأكيد التجهيز ومراقبة تشغيل محفوف بالمخاطر دون انتظار انتهاء الجلسة.

## مراقبة النشاط

<Tabs>
  <Tab title="لوحة المراقبة">
    1. انتقل إلى **Observe → Events**.
    2. ابدأ بإطار الوقت الحالي وبدون مرشحات لتأكيد وصول البيانات.
    3. قم بالتصفية حسب البيئة أو نوع الحدث أو الوكيل أو الجلسة. استخدم البحث عن نص الحمولة.
    4. حدد حدثًا لفحص ملخصه والتفاصيل. اتبع رابط جلسته للحصول على التتبع الكامل.

    ![تيار الأحداث المباشر مع مرشحات الوقت والبيئة ونوع الحدث والوكيل والنموذج والسياق والجلسة والنص.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    يستبعد التغذية الافتراضية الحمولات الخام. استخدم `--full` فقط لتحقيق محدود الجلسة.
  </Tab>
</Tabs>

استخدم تيار الأحداث للإجابة على ثلاثة أسئلة فورية:

- هل الوكيل المتوقع يقدم تقارير إلى البيئة الصحيحة؟
- هل استدعاءات النموذج واستدعاءات الأداة وقرارات السياسة تصل بالترتيب الصحيح؟
- هل توقفت الجلسة عن الإحراز تقدم أو بدأت بتكرار إجراء؟

تشمل أنواع الأحداث أحداث دورة حياة الوكيل وطلبات النموذج والردود وحالات الاستخدام والنتائج وتنفيذ الخطاف والانتظار البشري والمقاطعات والأخطاء الصريحة. تربط معرفات الارتباط الأحداث المقترنة مثل استدعاء الأداة ونتيجتها.

<Tip>
  حافظ على العرض المباشر واسعًا أثناء التحقق من التكامل الجديد. أضف المرشحات فقط بعد رؤية الحدث الأول؛ قد يبدو المرشح غير الصحيح كفشل في الاستيعاب.
</Tip>

إذا لم تظهر أي أحداث، قم بتشغيل `failproofai config --status`، ثم [استكشف مشاكل الاستيعاب](/ar/reference/troubleshooting).
