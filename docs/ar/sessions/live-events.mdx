تساعدك الأحداث المباشرة على تأكيد الأدوات المدمجة ومراقبة التشغيل المحفوف بالمخاطر دون انتظار انتهاء الجلسة.

## مراقبة النشاط

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **Observe → Events**.
    2. ابدأ بنافذة الوقت الحالية بدون عوامل تصفية لتأكيد وصول البيانات.
    3. صفّي حسب البيئة أو نوع الحدث أو الوكيل أو الجلسة. استخدم البحث لنصوص في الحمولة.
    4. حدد حدثًا لفحص ملخصه وتفاصيله. اتبع رابط جلسته للحصول على التتبع الكامل.

    ![تدفق الأحداث المباشرة مع عوامل تصفية الوقت والبيئة ونوع الحدث والوكيل والنموذج والسياق والجلسة والنص.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    يستبعد التغذية الافتراضية الحمولات الخام. استخدم `--full` فقط لتحقيق جلسة محدودة النطاق.
  </Tab>
</Tabs>

استخدم تدفق الأحداث للإجابة على ثلاث أسئلة فورية:

- هل يُبلِّغ الوكيل المتوقع عن البيئة الصحيحة؟
- هل تصل استدعاءات النموذج واستدعاءات الأدوات وقرارات السياسة بالترتيب الصحيح؟
- هل توقفت الجلسة عن إحراز تقدم أم بدأت تكرار إجراء ما؟

تشمل أنواع الأحداث أحداث دورة حياة الوكيل، وطلبات الاستجابة من النموذج، واستخدام الأدوات والنتائج، وتنفيذ الخطاف، والانتظار البشري والمقاطعات، والأخطاء الصريحة. تربط معرّفات الارتباط الأحداث المزدوجة مثل استدعاء الأداة ونتيجتها.

<Tip>
  اجعل العرض المباشر واسعًا أثناء التحقق من تكامل جديد. أضف عوامل التصفية فقط بعد رؤية الحدث الأول؛ فقد يبدو عامل التصفية غير الصحيح وكأنه فشل في الاستيعاب.
</Tip>

إذا لم تظهر أي أحداث، فشغّل `failproofai config --status`، ثم [استكشف مشاكل الاستيعاب](/ar/reference/troubleshooting).
