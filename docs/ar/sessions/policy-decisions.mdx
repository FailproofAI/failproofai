تعرض قرارات السياسة ما قامت به Failproof AI أثناء تشغيل الوكيل.

<Tabs>
  <Tab title="لوحة التحكم">
    انتقل إلى **Observe → policy** لمراجعة القرارات ومعدل الحظر والأجهزة والتعيينات المنشرة.

    ![صفحة السياسة تعرض إجمالي القرارات وفلتر الأجهزة ونشاط الإنفاذ بمرور الوقت وجدول خريطة السياسة.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp guardrails summary --since 24h
    fp guardrails timeline --since 24h
    failproofai policies
    failproofai config --status
    ```

    يقبل `--since` القيم `1h` أو `6h` أو `24h` أو `7d`. أضف `--machine <id>` للتركيز على جهاز واحد.
  </Tab>
</Tabs>

## قراءة نشر المراقبة

يقوم وضع المراقبة بتشغيل السياسة الفعلية وتسجيل أي قرار `deny` أو `instruct`. لا يزال بإمكان الوكيل المتابعة.

```bash
fp fleet deploy <machine> --add <policy>:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add <policy>:enforce
```

<Warning>
  إن `--add <policy>` البسيط يفرض على الفور عندما لا تحتوي السياسة على نشر موجود. أضف `:observe` لنشر ظل.
</Warning>

يتم تسجيل قرارات المراقبة غير المسموح بها فقط. يتم تسجيل انتهاء المهلة الزمنية كـ allow، لأن هذا هو ما يحدث أيضًا في وضع الإنفاذ.

القرار deny المسجل ليس إثباتًا على أن أداة الاختبار أوقفت الإجراء. يتم التحقق من رفع أدوات الاتصال عبر جميع أدوات الاختبار المدعومة الـ 12؛ تختلف الأحداث الأخرى. راجع [قدرة الإنفاذ](/ar/reference/harnesses#enforcement-capability).

## التحقيق في النتيجة غير المتوقعة

| ما تراه | تحقق من |
| --- | --- |
| لا توجد قرارات | `failproofai config --status` وما إذا كانت الجلسة متوقفة |
| العديد من الرفوض بدون اسم سياسة | [سلوك فشل السياسة](/ar/policies/failure-behavior) |
| يتم حظر كل إجراء محمي | ما إذا كانت خدمة `failproofaid` سليمة |
| قرار حظر لا يمكنك تعطيله | `block-failproofai-commands` مفعّل دائمًا |
| لا توجد بيانات لـ `--env production` | تستخدم الأجهزة الجديدة البيئة `local` |
