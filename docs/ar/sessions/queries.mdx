الاستعلامات هي الطبقة المرنة تحت لوحات المعلومات والتدقيقات والتحقيقات. استخدم SQL المخصص لاختبار فكرة، ثم احفظ الاستعلام عندما يصبح جزءاً من سير عمل متكرر.

## إنشاء وتشغيل استعلام

<Tabs>
  <Tab title="Dashboard">
    1. انتقل إلى **Analyze → Queries** واختر **new query**.
    2. افتح متصفح المخطط واختر الحقول من بيانات الحدث أو الجلسة أو التقييم.
    3. اكتب SQL، أضف المعاملات عند الحاجة، وشغّل الاستعلام.
    4. احفظه باسم وصف واضح، ثم استخدم **add to dashboard** عندما يجب مراقبة النتيجة.

    يجمع محرر الاستعلام بين مخطط الأحداث وSQL والمعاملات ومعاينة النتائج بحيث يمكنك التحقق من السؤال قبل الحفظ.

    ![محرر استعلام SQL مع متصفح مخطط وشبكة نتائج مباشرة.](/images/dashboard/query-lab.png)

    ثم تظهر الاستعلامات المحفوظة في المكتبة المشتركة، حيث يمكن لزملائك إعادة تشغيلها أو إضافة نتائجها إلى لوحات المعلومات.

    ![مكتبة الاستعلامات المحفوظة التي تحتوي على استعلامات مدمجة وأخرى مخصصة قابلة لإعادة الاستخدام.](/images/dashboard/queries.png)

    استخدم اسماً وصفاً واضحاً بحيث تبقى النتيجة مفهومة دون الحاجة لفتح SQL الخاص بها مجدداً.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    استخدم `fp query list` للعثور على معرّفات و`fp query delete <query-id>` لحذف استعلام محفوظ.
  </Tab>
</Tabs>

## الاستخدامات الشائعة

- ابحث عن جلسات تحتوي على استدعاءات متكررة لنفس الأداة.
- قارن درجات التقييم عبر النماذج أو البيئات.
- قس الوقت بين انتظار الإنسان والاستئناف.
- حدّد رفضات السياسة متبوعة بحل بديل ناجح.
- بناء مجموعة سكانية لعملية تدقيق.

افتح **Queries → Schema** قبل الكتابة ضد حقول غير مألوفة. فضّل مرشحات الوقت والبيئة الصريحة، وحافظ على حدود النتائج أثناء الاستكشاف.

<Warning>
  يمكن للاستعلام تحديد نمط مريب، لكنه لا يثبت نمط الفشل بذاته. افتح آثار تمثيلية أو شغّل عملية تدقيق قبل تحويل النتيجة إلى سياسة.
</Warning>
