الاستعلامات هي الطبقة المرنة التي تقع تحت لوحات المعلومات والتدقيق والتحقيقات. استخدم SQL المخصص لاختبار فكرة، ثم احفظ الاستعلام عندما يصبح جزءًا من سير عمل متكرر.

## إنشاء وتشغيل استعلام

<Tabs>
  <Tab title="Dashboard">
    1. انتقل إلى **Analyze → Queries** وحدد **new query**.
    2. افتح متصفح المخطط واختر الحقول من بيانات الحدث أو الجلسة أو التقييم.
    3. اكتب SQL، أضف معاملات عند الحاجة، وشغّل الاستعلام.
    4. احفظه باسم وصف واضح، ثم استخدم **add to dashboard** عندما يجب مراقبة النتيجة.

    يجمع محرر الاستعلام بين مخطط الحدث وSQL والمعاملات ومعاينة النتيجة حتى تتمكن من التحقق من السؤال قبل حفظه.

    ![محرر استعلامات SQL مع متصفح مخطط وشبكة نتائج مباشرة.](/images/dashboard/query-lab.png)

    تظهر الاستعلامات المحفوظة بعد ذلك في المكتبة المشتركة، حيث يمكن لزملائك إعادة تشغيلها أو إضافة نتائجهم إلى لوحات المعلومات.

    ![مكتبة الاستعلامات المحفوظة التي تحتوي على استعلامات مدمجة وقابلة لإعادة الاستخدام مخصصة.](/images/dashboard/queries.png)

    استخدم اسمًا وصفًا واضحًا بحيث تبقى النتيجة مفهومة دون الحاجة إلى إعادة فتح SQL الخاص بها.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    استخدم `fp query list` للعثور على المعرفات و`fp query delete <query-id>` لحذف استعلام محفوظ.
  </Tab>
</Tabs>

## الاستخدامات الشائعة

- العثور على الجلسات التي تحتوي على استدعاءات متكررة لنفس الأداة.
- مقارنة درجات التقييم عبر النماذج أو البيئات.
- قياس الوقت بين انتظار المستخدم واستئناف العملية.
- تحديد رفض السياسة متبوعًا ببديل ناجح.
- بناء مجموعة متماثلة للتدقيق.

افتح **Queries → Schema** قبل الكتابة ضد حقول غير مألوفة. فضّل مرشحات الوقت والبيئة الصريحة، واحتفظ بحدود النتائج أثناء الاستكشاف.

<Warning>
  يمكن للاستعلام تحديد نمط مريب، لكنه لا يحدد نمط الفشل بمفرده. افتح التتبعات الممثلة أو شغّل تدقيقًا قبل تحويل النتيجة إلى سياسة.
</Warning>
