الاستعلامات هي الطبقة المرنة التي تقع تحت لوحات التحكم والتدقيقات والتحقيقات. استخدم SQL الفوري لاختبار فكرة، ثم احفظ الاستعلام عندما يصبح جزءًا من سير عمل متكرر.

## إنشاء وتشغيل استعلام

<Tabs>
  <Tab title="Dashboard">
    1. انتقل إلى **Analyze → Queries** وحدد **new query**.
    2. افتح متصفح المخطط واختر الحقول من بيانات الحدث أو الجلسة أو التقييم.
    3. اكتب SQL، أضف معاملات عند الحاجة، وشغّل الاستعلام.
    4. احفظه باسم ووصف واضحين، ثم استخدم **add to dashboard** عندما يجب مراقبة النتيجة.

    يجمع محرر الاستعلامات بين مخطط الحدث و SQL والمعاملات ومعاينة النتيجة حتى تتمكن من التحقق من السؤال قبل حفظه.

    ![محرر استعلامات SQL مع متصفح المخطط وشبكة النتائج المباشرة.](/images/dashboard/query-lab.png)

    تظهر الاستعلامات المحفوظة بعد ذلك في المكتبة المشتركة، حيث يمكن لزملائك إعادة تشغيلها أو إضافة نتائجها إلى لوحات التحكم.

    ![مكتبة الاستعلامات المحفوظة التي تحتوي على استعلامات مدمجة وفعلية قابلة لإعادة الاستخدام.](/images/dashboard/queries.png)

    استخدم اسمًا ووصفًا واضحين حتى تبقى النتيجة مفهومة بدون إعادة فتح SQL الخاص بها.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    استخدم `fp query list` للعثور على معرفات و `fp query delete <query-id>` لحذف استعلام محفوظ.
  </Tab>
</Tabs>

## الاستخدامات الشائعة

- ابحث عن الجلسات التي تحتوي على استدعاءات متكررة لنفس الأداة.
- قارن درجات التقييم عبر النماذج أو البيئات.
- قس الوقت بين انتظار الإنسان والاستئناف.
- حدد الرفض بناءً على السياسة متبوعًا ببديل ناجح.
- بناء مجموعة سكانية لتدقيق.

افتح **Queries → Schema** قبل الكتابة ضد الحقول غير المألوفة. فضّل عوامل التصفية الصريحة للوقت والبيئة، واحتفظ بحدود النتيجة أثناء الاستكشاف.

<Warning>
  يمكن للاستعلام تحديد نمط مريب، لكنه لا ينشئ وضع الفشل بمفرده. افتح آثارًا تمثيلية أو قم بتشغيل تدقيق قبل تحويل النتيجة إلى سياسة.
</Warning>
