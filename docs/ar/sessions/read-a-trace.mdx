يحول التتبع تدفق الأحداث المسطح إلى قصة السببية للتشغيل. اقرأه من أول نقطة اختلاف، وليس بالعكس من آخر خطأ.

## فتح التتبع

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **Observe → Sessions** وافتح جلسة.
    2. استخدم ملخص الملف الشخصي للتحقق من النتيجة والتوقيت والأخطاء ودرجات التقييم.
    3. امسح الجدول الزمني والخريطة المصغرة. صفّ أنواع الأحداث أو الوقت عندما تكون الجلسة كبيرة.
    4. حدد حدثاً للتفتيش عليه. استخدم **export** لـ JSON المقيّم، أو انسخ عنوان URL للصفحة لمشاركة ارتباط عميق للدليل المحدد.

    ![عرض تفاصيل الجلسة يتضمن رسم بياني التنفيذ وجدول الأحداث لوحة التقييم وتفصيل الأداة والنموذج والخطاف.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    استخدم تغذية الأحداث الخفيفة أولاً. اطلب الحمولات الكاملة فقط عندما لا تحتوي ملخصات الأحداث على دليل كافٍ.
  </Tab>
</Tabs>

<Steps>
  <Step title="توجيه نفسك">
    أكد الوكيل والبيئة والتوقيت والنتيجة والمدة، ثم ابحث عن الأخطاء والفترات الطويلة والأدوات المكررة والانتظار البشري ورفض قرارات السياسة.
  </Step>
  <Step title="وسّع الحدث المريب الأول">
    تفتش على طلبه واستجابته وإدخال الأداة والإخراج ومعرّف الارتباط. المحتوى الحساس مرئي فقط عند تمكين التقاط النسخة وتسمح الأذونات بذلك.
  </Step>
  <Step title="تفتش السياق السابق">
    غالباً ما يكون السبب في حدث واحد قبله: استجابة نموذج غير صحيحة أو نتيجة أداة مفقودة أو افتراض قديم.
  </Step>
  <Step title="حول الدليل إلى إجراء">
    أضف الجلسة إلى نطاق التدقيق أو ربطها بمشكلة أو استخدم وضع الفشل لتأليف سياسة.
  </Step>
</Steps>

<Warning>
  المدة الطويلة لا تعني دائماً كمون النموذج. افصل بين وقت النموذج والأداة والخطاف والانتظار البشري قبل أن تقرر ما يجب إصلاحه.
</Warning>
