يحول التتبع تدفق الأحداث المسطح إلى القصة السببية للتشغيل. اقرأه من أول اختلاف، وليس للخلف من آخر خطأ.

## فتح التتبع

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **Observe → Sessions** وافتح جلسة.
    2. استخدم ملخص الملف الشخصي للتحقق من النتيجة والتوقيت والأخطاء ودرجات التقييم.
    3. افحص الخط الزمني والخريطة المصغرة. صفّ أنواع الأحداث أو الوقت عندما تكون الجلسة كبيرة.
    4. حدد حدثاً لفحصه. استخدم **export** للحصول على JSON المقيِّم، أو انسخ عنوان URL للصفحة لمشاركة رابط عميق إلى الأدلة المحددة.

    ![عرض تفاصيل جلسة يتضمن رسم بياني للتنفيذ وخط زمني للأحداث ولوحة التقييم وتفصيل الأداة والنموذج والخطاف.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    استخدم تدفق الأحداث الخفيف أولاً. اطلب الحمولات الكاملة فقط عندما لا تحتوي ملخصات الأحداث على أدلة كافية.
  </Tab>
</Tabs>

<Steps>
  <Step title="توجيه نفسك">
    تأكد من الوكيل والبيئة والتوقيت والنتيجة والمدة، ثم ابحث عن الأخطاء والفترات الطويلة والأدوات المتكررة والانتظار البشري والقرارات السياسية المرفوضة.
  </Step>
  <Step title="وسّع أول حدث مريب">
    افحص طلبه واستجابته ومدخل الأداة ومخرجاتها ومعرّف الارتباط. يكون المحتوى الحساس مرئياً فقط عند تفعيل التقاط النسخة والسماح بأذوناتك.
  </Step>
  <Step title="افحص السياق السابق">
    غالباً ما تكون السبب في حدث واحد أبكر: استجابة نموذج غير صحيحة أو نتيجة أداة مفقودة أو افتراض قديم.
  </Step>
  <Step title="حوّل الأدلة إلى إجراء">
    أضف الجلسة إلى نطاق التدقيق أو اربطها بمشكلة أو استخدم وضع الفشل لإنشاء سياسة.
  </Step>
</Steps>

<Warning>
  المدة الطويلة لا تعني دائماً زمن انتظار النموذج. افصل بين وقت النموذج والأداة والخطاف والانتظار البشري قبل تحديد ما يجب إصلاحه.
</Warning>
