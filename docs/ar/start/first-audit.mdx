---
title: "تشغيل فحص الفشل الأول لديك"
description: "أنشئ تدقيقًا من لوحة التحكم السحابية أو واجهة سطر أوامر fp وراجع النتائج الأولى."
icon: "scan-search"
---

يحول التدقيق مجموعة من الجلسات إلى نتائج فشل مصنفة مدعومة بالأدلة. ابدأ بسؤال فشل واحد محدد.

<Tabs>
  <Tab title="Dashboard">
    <Steps>
      <Step title="فتح التدقيقات">
        في شريط جانب Cloud، انتقل إلى **Analyze → Audits**. اختر **new audit**.
      </Step>
      <Step title="إعداد التدقيق">
        أدخل اسمًا وهدف فشل مباشرًا، مثل "البحث عن جلسات الإنتاج التي تعيد محاولة استدعاء الدفع الفاشل نفسه دون تغيير الإدخال أو التصعيد." اختر الوكيل والبيئة ونطاق الوقت والجدولة. أضف ملخصًا قصيرًا وعناوين URL مرجعية عندما يحتاج المدقق إلى قواعد سير العمل الخاصة بك.
      </Step>
      <Step title="الإنشاء والانتظار حتى اكتمال التشغيل">
        اختر **create audit**. يتم وضع التشغيل الأول في قائمة الانتظار على الفور. افتح بطاقة التدقيق لمراقبة حركتها من الانتظار إلى التشغيل إلى الاكتمال.
      </Step>
    </Steps>

    بعد اكتمال التشغيل، افتح نتيجة واراجع دليل جلستها. يمكنك بعد ذلك الإقرار بها أو تعيينها أو رفضها أو كتمها أو حلها.

    ![نتيجة تدقيق مكتملة تعرض وصف الفشل والإجراء الموصى به والأدلة الداعمة والجلسات المتأثرة.](/images/dashboard/audit-finding.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits create payment-retry-failures \
      --description "Find production sessions that retry a failed payment call without changing input or escalating" \
      --scope '{"environments":["production"]}' \
      --text "Escalate after two unchanged payment failures"

    fp audits list
    fp audits runs payment-retry-failures
    fp audits findings --audit payment-retry-failures
    fp audits finding <finding-id>
    ```

    أضف سياق مرجعي، ثم أعد تحديثه عند تغيير المصدر:

    ```bash
    fp audits context-set payment-retry-failures --url https://example.com/payment-runbook
    fp audits context-refresh payment-retry-failures
    fp audits run payment-retry-failures
    ```

    استخدم `fp audits ack <finding-id>` أو `fp audits assign <finding-id> --to <email>` أو `fp audits dismiss <finding-id>` أو `fp audits mute <finding-id>` أو `fp audits resolve <finding-id>` أو `fp audits reopen <finding-id>` لنقل النتيجة عبر مراحل الفحص.
  </Tab>
</Tabs>

بعد ذلك، [منع الفشل الأول لديك باستخدام سياسة](/ar/start/first-policy) لإجراء يمكن تكراره ومؤكد.
