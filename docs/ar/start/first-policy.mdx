ابدأ بسلوك تريد إيقافه وإجراء شرعي يجب أن يستمر في العمل.

## جرب سياسة معروضة أولاً

```bash
failproofai policies
failproofai policies add block-rm-rf
```

يتضمن Failproof AI 39 سياسة معروضة. تحقق من [الكتالوج](/ar/policies/builtin-catalog) قبل كتابة سياسة جديدة.

## اكتب واختبر سياستك الخاصة

<Steps>
  <Step title="إنشاء سياسة عاملة">
    ```bash
    failproofai publish --init guards.mjs
    ```

    هذا ينشئ سياسة تحظر `git push --force`. عدّلها لقاعدتك.
  </Step>
  <Step title="فرضها على هذا الجهاز">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    اطلب من الوكيل تنفيذ الإجراء المحظور، ثم تحقق من **Policies → Activity** في لوحة المعلومات المحلية.
  </Step>
  <Step title="احتفظ بها أو أزلها">
    ضع ملف `*policies.mjs` ضمن `.failproofai/policies/` لتحميله تلقائياً.

    أزل الملفات المخصصة الصريحة باستخدام:

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## شاركها

انشر حزمة عامة:

```bash
failproofai publish
```

يمكن لأي شخص تثبيتها باستخدام `failproofai policies add <owner>/<repo>`. أضف موضوع GitHub `failproofai-policies` بنفسك حتى يتمكن [Policy Hub](https://befailproof.ai/policy-hub/) من فهرستها.

للنشر على Cloud:

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  أمر `--add checkout-guard` بدون بادئة يفرض فوراً. أضف `:observe` لتسجيل ما ستفعله السياسة دون حظر الوكيل.
</Warning>

انظر إلى [نشر حزمة](/ar/policies/publish-a-pack) أو [نشر السياسات](/ar/policies/deploy) للعملية الكاملة.
