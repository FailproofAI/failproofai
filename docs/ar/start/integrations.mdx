## قبل أن تبدأ

شيئان يفترض هذا المسار وجودهما، لا أحدهما يفعله الكود أدناه من أجلك:

| المتطلب | السبب |
| --- | --- |
| Python 3.10 أو أحدث | الحد الأدنى الذي تعلنه SDK. |
| آلة تم إعدادها باستخدام `failproofai config` | هذا الأمر يثبت daemon failproofaid، و daemon هو الشيء الوحيد الذي ينقل ما تكتبه SDK. بدونها، تتراكم الدفعات في دليل spool ولا تغادر أبداً. |

<Note>
  **هذا المسار يسجل؛ إنه لا ينفذ.** SDK تلتقط ما فعله وكيلك. تعمل السياسات من خطاف داخل CLI وكيل، لذا فرض السياسة على وكيل إطار العمل يعني وضع خطاف في وقت التشغيل الخاص بك — انظر [السياسات](/ar/policies/overview).
</Note>

## ثلاثة أسطر، أي إطار عمل

<CodeGroup>
```bash LangGraph
pip install 'failproofai-sdk[langgraph]'
```

```bash CrewAI
pip install 'failproofai-sdk[crewai]'
```

```bash LlamaIndex
pip install 'failproofai-sdk[llamaindex]'
```

```bash Pydantic AI
pip install 'failproofai-sdk[pydantic-ai]'
```

```bash Custom agents
pip install failproofai-sdk
```
</CodeGroup>

```python
import failproofai_sdk

failproofai_sdk.configure(environment="production")
failproofai_sdk.instrument()          # يكتشف الأطر التي استوردتها

with failproofai_sdk.session():
    ...                               # استدعاء وكيلك الموجود، دون تغيير
```

لا ديكوريترز على دوالك، لا callback تُمرر إلى استدعاءاتك، لا ids مرسلة عبر الكود. فقط الاستدعاء داخل الجلسة يختلف:

<Tabs>
  <Tab title="LangGraph">
    ```python
    graph.invoke({"messages": [HumanMessage("...")]})
    ```
  </Tab>
  <Tab title="CrewAI">
    ```python
    Crew(agents=[analyst, writer], tasks=[gather, summarise]).kickoff()
    ```
  </Tab>
  <Tab title="LlamaIndex">
    ```python
    await agent.run("...")        # تحت `async with failproofai_sdk.session():`
    ```
  </Tab>
  <Tab title="Pydantic AI">
    ```python
    agent.run_sync("...")
    ```
  </Tab>
  <Tab title="Custom agents">
    ```python
    with failproofai_sdk.agent("planner"):
        with failproofai_sdk.tool_call("search", input={"q": q}) as t:
            t.output = search(q)
    ```
  </Tab>
</Tabs>

التثبيت الإضافي يثبت **الإطار العملي**. كل محول يأتي في wheel الأساسي، لذا المشروع الذي يحتوي بالفعل على إطاره لا يحتاج إلى أي إضافي على الإطلاق.

## تحقق من وصوله

شغّل جلسة واحدة مُجهزة، ثم افتح **Observe → Sessions** واختر بيئتك. يظهر التشغيل كتتبع مُعاد بناؤه.

إذا لم يصل شيء، تأكد من إعداد الآلة والاتصال بها باستخدام `failproofai config --status`. إذا لم تكن كذلك، شغّل `failproofai config`. انظر [اختر إعدادك](/ar/start/setup).

<Warning>
  لا تتحقق من دليل spool لتأكيد التسليم. يجمع daemon Failproof كل دفعة ويحذفها في ميلي ثانية، لذا قراءتها تتسابق مع المجمّع وتُظهر أحداث أقل بكثير مما تم إصدارها.
</Warning>

لإثبات أن SDK تكتب على الإطلاق، قم بإيقاف daemon أولاً، ثم شغّل جلستك وابحث في `~/.failproofai/custom-agents/events/`. مع تشغيل daemon، دليل فارغ هو الحالة الصحية.

<CodeGroup>
```bash Linux
sudo systemctl stop failproofaid@$USER
```

```bash macOS
sudo launchctl bootout system/ai.failproof.failproofaid.$USER
```
</CodeGroup>

شغّل `failproofai config` بعدها لإعادتها. أثناء توقف daemon، أحداث الخطاف على هذه الآلة ليس لديها محقق ويتم رفضها، لذا قم بإيقافها فقط لمدة ما تستغرقه الفحص.
