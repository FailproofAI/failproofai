قم بإعداد Failproof AI على جهاز واحد، ثم ابقَ محليًا أو تواصل مع Cloud.

إذا كان وكيلك يعمل في [harness مدعوم](/ar/reference/harnesses)، اتبع هذه الخطوات. بالنسبة للوكلاء المبنيين باستخدام LangChain أو CrewAI أو LlamaIndex أو Pydantic AI أو بيئة التشغيل الخاصة بك، ابدأ بـ [instrument your agent](/ar/start/integrations).

## دع وكيلك يوجه الإعداد

قم بتثبيت مهارة Failproof AI الشاملة في وكيل متوافق:

```bash
npx skills add FailproofAI/skills
```

يقوم هذا بتثبيت المهارة الشاملة ومهارات الأخصائيين الخاصة بها. استخدم `--skill failproofai` إذا كنت تريد المهارة الشاملة فقط. إنها تفهم الإعداد المحلي و Cloud وصحة daemon والجلسات والتدقيق والسياسات وحل المشاكل. فهي توجه العمل وتوجه المهام المتخصصة إلى مهارة Failproof AI الصحيحة؛ وهي لا تحل محل تثبيت CLI أدناه.

## إعداد الجهاز

<Steps>
  <Step title="قم بتثبيت وتكوين Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    يقوم الإعداد بتثبيت خدمة الخلفية وربط كل وكيل مدعوم يجده. قد يطلب وصول المسؤول مرة واحدة. يدعم Linux و macOS.
  </Step>

  <Step title="اختر السياسات">
    الإعداد لا يختار أي مجموعة سياسات. أضف مجموعة Failproof AI:

    ```bash
    failproofai policies add FailproofAI/policies
    failproofai policies
    ```

    الأمر الثاني يعرض كل سياسة على هذا الجهاز وما إذا كانت مفعلة. حتى تضيف مجموعة، فقط `block-failproofai-commands` يعمل.
  </Step>

  <Step title="تحقق من الجهاز">
    ```bash
    failproofai config --status
    ```

    يقدم هذا تقريرًا عن الخدمة واتصال Cloud وحالة الإيقاف المؤقت.
  </Step>
</Steps>

## اختر محلي أو Cloud

<Tabs>
  <Tab title="ابقَ محليًا">
    لا يلزم حساب.

    ```bash
    failproofai
    failproofai audit
    ```

    يفتح الأمر الأول لوحة التحكم المحلية في `http://localhost:8020`. يقوم الأمر الثاني بفحص سجل الوكيل الموجود بالفعل على هذا الجهاز.
  </Tab>

  <Tab title="اتصل بـ Cloud">
    أنشئ مفتاح جهاز في Failproof AI Cloud، ثم قم بتشغيل:

    ```bash
    failproofai config --token <machine-key>
    failproofai config --status
    ```

    يتلقى Cloud قرارات السياسة وكتابات جلسات العمل. لإرسال القرارات فقط، قم بالاتصال أولاً، ثم اضبط `collector.sessions` على `false` في `~/.failproofai/config.json`؛ علم الإعداد الحالي `--no-transcripts` لا ينطبق على هذا الإعداد. بالنسبة للأوامر المشتركة و CI، استخدم `FAILPROOFAI_CLOUD_TOKEN` بدلاً من وضع المفتاح في سجل الأوامر.
  </Tab>
</Tabs>

## تحقق منه

قم بتشغيل أحد وكلائك واطلب منه تنفيذ مهمة عادية. ثم:

يتم التحقق من رفض استدعاء الأداة على جميع harnesses المدعومة الـ 12. يتم التحقق من إنفاذ نهاية الدور على 8؛ قد تكون أزواج أحداث harness الأخرى قابلة للملاحظة فقط أو غير مؤكدة.

- افتح **Policies → Activity** في لوحة التحكم المحلية لرؤية قرارات السياسة.
- افتح **Observe → Sessions** في Cloud لرؤية التشغيل الكامل.
- قم بتشغيل `failproofai audit` للبحث عن أنماط محفوفة بالمخاطر أو مهدرة.

<Warning>
  بعد الإعداد، تكون خدمة `failproofaid` هي المقيّم. إذا لم تتمكن من الإجابة، يتم رفض الإجراءات المحمية. قم بتشغيل `failproofai config --status` عندما يتوقف الوكيل بشكل غير متوقع.
</Warning>
