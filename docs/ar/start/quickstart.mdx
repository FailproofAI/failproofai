يوفر هذا البدء السريع تشغيل جهاز واحد لإرسال الجلسات، وتشغيل تدقيق، ونشر سياسة. استخدم المهارة لإعداد Failproof AI، أو اتبع الخطوات اليدوية.

**أي المسارات تناسبك؟** إذا كان وكيلك يعمل في أحد [الأطر المدعومة](/ar/reference/harnesses) الـ 12 — واجهة سطر أوامر برمجية أو بوابة مثل Hermes أو OpenClaw — اتبع الخطوات أدناه؛ تحتاج إلى Node.js 20.9 أو إصدار أحدث. إذا لم يكن لدى وكيلك إطار عمل، فقم بتجهيزه باستخدام [Python SDK](/ar/reference/python-sdk) للتتبع والتدقيق، ثم عد إلى [تشغيل فحص الفشل الأول](/ar/start/first-audit)؛ الإنفاذ في هذا المسار يحتاج إلى hook في وقت التشغيل.

        يتفحص وكيلك المشروع، ويختار التكامل ذا الصلة، ويجري الإعداد، ويتحقق منه. راجع [مستودع مهارات FailproofAI](https://github.com/FailproofAI/skills) للحصول على المهارات الفردية وخيارات التثبيت المتقدمة.
      </Step>

  <Tab title="الإعداد اليدوي">
    ## قبل أن تبدأ

1. افتح [لوحة تحكم Failproof AI](https://app.befailproof.ai) وأنشئ حساباً أو سجل الدخول باستخدام بريدك الإلكتروني للعمل.
2. انتقل إلى **Administration → Keys** وأنشئ مفتاحاً باستخدام `events:add` و `policies:pull`.
3. انسخ السر لمرة واحدة وقم بتخزينه على الجهاز المستهدف:

```bash
export FAILPROOFAI_KEY="<one-time-secret>"
```

    ## التثبيت

<Steps>
  <Step title="ثبت وصل Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config --connect https://app.befailproof.ai --token "$FAILPROOFAI_KEY"
    ```

    يتم إرسال نصوص الجلسات بشكل افتراضي. أضف `--no-transcripts` للإبلاغ عن نشاط hook وقرارات السياسة دون محتوى النص.

    إذا كان لدى هذا الجهاز بالفعل سجل وكيل، معاينة واستيراد آخر سبعة أيام، ثم انتظر انتهاء التسليم. تخطَّ هذه الخطوة على جهاز جديد.

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    افتح **Sessions** في Failproof AI واختر جلسة مستوردة.
  </Step>
  <Step title="ثبت hooks الوكيل والسياسات">
    يربط Failproof AI بإطار العمل الخاص بك وينصب السياسات المدمجة الـ 40. استخدمها لرؤية قرارات السياسة المحلية وجرب الإنفاذ قبل أن يقوم Failproof AI بتدقيق جلساتك وكتابة السياسات لوكلائك.

    دع المثبت يكتشف إطار العمل الخاص بك، أو قم بتسمية واحد صراحةً. كل واحد من الـ 12 هو قيمة `--cli` صحيحة — `claude`، `codex`، `copilot`، `cursor`، `opencode`، `pi`، `hermes`، `openclaw`، `factory`، `devin`، `antigravity`، `goose`.

    ```bash
    failproofai policies --install --cli claude --scope user     # a coding CLI
    failproofai policies --install --cli hermes --scope user     # a Slack/Telegram gateway
    ```

    يتم التحقق من حظر استدعاء أداة قبل تشغيله في جميع الـ 12. يتم التحقق من بوابات نهاية الدور في 8 — راجع [قدرة الإنفاذ](/ar/reference/harnesses#enforcement-capability) للحصول على مصفوفة لكل إطار عمل.
  </Step>
  <Step title="دقق السلوك">
    اتبع [تشغيل فحص الفشل الأول](/ar/start/first-audit). استخدم هدفاً ملموساً مثل "ابحث عن الجلسات حيث أعاد الوكيل محاولة أداة فاشلة دون تغيير نهجه."
  </Step>
  <Step title="منع الفشل">
    اتبع [منع فشلك الأول بسياسة](/ar/start/first-policy). ابدأ بوضع المراقبة، افحص المطابقات، ثم طبق الإصدار المراجع.
  </Step>
</Steps>

<Check>
  قم بتشغيل `failproofai config --status`. يبلغ الإعداد الصحي عن اتصال السحابة وحالة daemon وما إذا كان الإنفاذ معلقاً.
</Check>
