## مسار الإنتاج الموصى به

1. قم بتوصيل جهاز غير موجود في الإنتاج مع تفعيل التقاط النصوص.
2. تحقق من الجلسات والتقييمات في السحابة.
3. أنشئ تدقيقاً لنمط خطأ معروف.
4. انشر السياسة الأولى في وضع المراقبة.
5. توسّع إلى الإنتاج بعد مراجعة المطابقات والإيجابيات الخاطئة.

## توصيل جهاز بالسحابة

<Tabs>
  <Tab title="لوحة التحكم">
    1. انتقل إلى **الإدارة → المفاتيح** وأنشئ مفتاحاً بصلاحيات `events:add` و `policies:pull`.
    2. انسخ السر لمرة واحدة إلى الجهاز المستهدف.
    3. بعد تشغيل أمر اتصال واجهة سطر الأوامر، انتقل إلى **الإدارة → الفرض** وتأكد من ظهور الجهاز.
    4. انتقل إلى **المراقبة → الأحداث** وتأكد من وصول حدثه الأول.

    يعرض درج المفتاح الصلاحيتين المطلوبتين من قبل جهاز متصل: بلع الأحداث وتسليم السياسة.

    ![درج مفتاح واجهة برمجية جديد يستخدم لمنح صلاحيات بلع الأحداث وتسليم السياسة.](/images/dashboard/key-create.png)

    بعد الاتصال، يجب أن يظهر الجهاز في الفرض مع حالة السياسة المطلوبة والمبلغ عنها.

    ![أسطول الفرض مع جهاز مسجل موسع لإظهار حالة السياسة المطلوبة وحالة النشر.](/images/dashboard/enforcement-fleet.png)

    يؤكد الحدث الأول الذي يصل على أن برنامج التشغيل يمكنه تسليم البيانات إلى السحابة، بغض النظر عن نشر السياسة.

    ![دفق الأحداث المباشر يعرض أحداث الوكيل والنموذج والأداة الحديثة.](/images/dashboard/events-stream-current.png)

    استمر فقط بعد ظهور الجهاز وحدثه الأول.
  </Tab>
  <Tab title="واجهة سطر الأوامر">
    ```bash
    failproofai config --connect https://app.befailproof.ai \
      --token "$FAILPROOFAI_KEY" \
      --machine-label checkout-runner-01

    failproofai policies --install --cli claude --scope user
    failproofai config --status
    ```

    أضف `--no-transcripts` عندما يجب أن يبقى محتوى النص محلياً.
  </Tab>
</Tabs>

يتحقق الاتصال بالسحابة من بلع الأحداث وتسليم السياسة بشكل مستقل. قد يكون المفتاح صحيحاً لكن ينقصه صلاحية واحدة مطلوبة. استخدم `failproofai config --status` لمعرفة القدرة المكونة.

<Info>
  كتابة إعداد السحابة بيانات الاعتماد المحلية فقط بعد نجاح القدرة ذات الصلة. فشل التحقق لا يترك جهازاً يبدو متصلاً عندما لا يكون كذلك.
</Info>
