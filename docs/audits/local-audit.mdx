A local audit reads agent history already on this machine and opens results at `http://localhost:8020/audit`. It needs no account.

```bash
failproofai audit
```

The scan covers history from all supported harnesses it finds. It replays the 39-policy catalog built into this version; installed packs and custom policies are not included.

## Read the result

Start with the most frequent findings, then open the affected session before enabling enforcement.

Three limits matter:

- The audit reconstructs tool events, not `Stop`, so `require-*-before-stop` policies do not appear.
- Eight “Audit-only” checks identify wasteful patterns without an exact matching policy.
- `warn-repeated-tool-calls` is skipped because replaying it would modify transcript-side state.

For an enforceable finding, use the policy command shown in the result. Check [harness enforcement support](/reference/harnesses#enforcement-capability) before relying on it.

The cached result lives at `~/.failproofai/audit/dashboard.json` and expires after seven days.

## Schedule scans

```bash
failproofai audit --schedule 7
failproofai audit --status
failproofai audit --no-schedule
```

The interval accepts 1–90 days and defaults to 7. First-time scheduling requires an interactive sign-in. The background service must be running.

### What leaves the machine

An interactive audit sends no findings. Anonymous CLI telemetry is enabled by default; disable it with `FAILPROOFAI_TELEMETRY_DISABLED=1`.

After you opt into scheduling, each scheduled scan sends the machine ID, label, platform, and scan window. If harmful patterns are found, it also sends a limited digest with counts, timestamps, and up to three redacted examples. Clean scans send no findings and no email.

<Warning>
  Audit results are evidence for review, not proof that every flagged action is unsafe. Check the session before turning a finding into blocking enforcement.
</Warning>
