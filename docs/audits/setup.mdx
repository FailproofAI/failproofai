The quality of an audit starts with its scope. A broad request such as “find problems” produces less useful results than a concrete failure question.

## Configure the audit

<Tabs>
  <Tab title="Dashboard">
    1. Go to **analyse → checks → new audit** — or **new check**, and answer **failures i don't know about yet**. Under **what it looks for**, describe the failure; asking failproof in the box at the top of the page drafts the whole form.
    2. On **review**, set the name, **what it reads** (environments and agents), **how often**, the time window, **how picky** (sensitivity), and **failures per run**.
    3. Under **what the audit knows**, add notes about your agents (the operator brief), any public HTTPS reference URLs, and errors to ignore, and check the [agent context](/audits/agent-contracts) of the agents in scope.
    4. Under **who hears about it**, choose email or Slack and select **create audit →**. The first run queues immediately.

    ![The new audit form with name, description, cadence, window, environment and agent scope, ignored errors, analysis settings, brief, reference pages, and notification channels.](/images/dashboard/audit-new.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits create checkout-reliability \
      --description "Find checkout failures that agents do not recover from" \
      --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
      --schedule-interval-secs 86400 \
      --window-mode since_last \
      --sensitivity medium \
      --text-file ./checkout-audit-brief.txt \
      --url https://runbooks.example.com/checkout
    ```

    The first run queues immediately. Include the brief and reference URLs during creation so that run receives them.

    See the complete [`fp audits create` reference](/reference/cloud-cli#audits).
  </Tab>
</Tabs>

<Tip>
  Start with a known failed session and several normal sessions. This gives the audit both a positive example and a comparison set.
</Tip>

<Info>
  Audit context is stored as its own resource so editing an audit does not accidentally remove the reference material.
</Info>
