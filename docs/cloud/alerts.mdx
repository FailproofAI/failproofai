Alerts evaluate rules on a schedule and notify email, Slack, webhook, or the dashboard.

![The Alerts page: a grid of alert-rule cards, each showing its trigger, evaluation window, channels, and an info, warning, or critical severity badge](/cloud/images/alerts.png)
*Each rule shows its condition, interval, destination, and severity.*

## Choose notification channels

Attach one or more channels to a rule:

- **Email**, to whoever should know.
- **Slack**, a rich message with a button that jumps straight to the issue.
- **Webhook**, a JSON POST for PagerDuty, Opsgenie, or your own endpoint, with an optional signature so the receiver can trust it.
- **In-dashboard**, quiet by design, for when you are tuning a rule and do not want to page anyone yet.

Set the severity to info, warning, or critical.

## Create a rule

Create rules in the dashboard form. The generated JSON is available for API use.

![The new-alert form: name and description, an enabled toggle, and a trigger picker offering metric threshold, custom SQL, evaluation score, compound eval, and per-event conditions](/cloud/images/alert-new.png)
*Pick a trigger and the form swaps in the right fields; Save writes the rule.*

The happy path is quick: name it, pick a **trigger** (what to watch), set the **threshold and window** (how bad, over how long), attach at least one **channel**, then **Save** and hit **Test** to fire a synthetic notification and confirm every destination is wired up. Under the hood that produces a small spec like:

```json
{ "metric": "p95_latency_ms", "op": ">", "value": 5000, "window_secs": 900 }
```

You are not limited to one kind of signal. Pick the trigger that matches how you think about the failure:

| Trigger | Fires when |
|---|---|
| **Metric threshold** | a preset metric (error rate, p95 or p99 latency, event or error counts, token spend) crosses your line over a window |
| **Custom SQL** | your own read-only query returns a row, or a value it computes crosses a threshold |
| **Evaluation score** | an evaluator score's average (say, hallucination) crosses a threshold |
| **Compound eval** | several score checks combine with any, all, or at-least-N logic, to catch a regression that only shows across scores |
| **Per event** | a single matching event lands: a specific agent, a specific error type, or a message substring |

On the [Errors page](/cloud/errors), select **+ alert** to open a prefilled rule.

**Where to find it:** Alerts live at `/<org-slug>/alerts`. Creating, editing, deleting, and testing rules needs **`alerts:write`**; `alerts:read` is enough to look. The recipient picker lists your org's members by name, so you can page a person without leaving the form.

## Page me only when it is real

The **M of N** filter requires a set number of recent checks to fail. For example, **3 of
5** fires after three breaches in five checks. The default **1 of 1** fires on the first
breach. Available intervals are 1m, 5m, 15m, and 1h.

## What happens when an alert fires

A breach opens an **issue** and pages your channels once. From there your team acknowledges it, assigns an owner, talks it through, and resolves it, all against a clean, attributed record. That triage workflow has its own home: see [Issues](/cloud/issues).
