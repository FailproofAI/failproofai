The dashboard lives at [app.befailproof.ai](https://app.befailproof.ai), and every page is
scoped to your organization: `app.befailproof.ai/<org-slug>/sessions`.

The sidebar has three sections, and they follow the loop. **analyse** is where you find out
what happened and what is going wrong. **fix** is where you do something about it. **admin**
is where you run it for your team.

<Note>
  New here? Don't read this page top to bottom — it is a map, not a tour. Start with
  [Create your workspace](/start/sign-up) and come back when you want to know what a
  particular sidebar item is for.
</Note>

## analyse

| Sidebar item | Answers | Page |
|---|---|---|
| **Issues** | What is broken right now, who owns it, and what has happened so far | [Issues](/cloud/issues) |
| **Audits** | What is going wrong that nobody wrote a rule for | [Audits](/cloud/audits) |
| **Sessions** | What did this specific run actually do, step by step | [Sessions](/cloud/sessions) · [Event stream](/cloud/event-stream) |
| **Policies** | Which rules exist, at which versions | [Policy editor](/cloud/policy-editor) |
| **Errors** | Everything that failed, grouped so a burst reads as one problem | [Errors](/cloud/errors) |
| **Dashboards** | The numbers over time — models, tools, hooks, evals, and boards you build | [Charts and boards](/cloud/dashboards) · [Performance](/cloud/performance) · [Online evals](/cloud/evaluations) |
| **Queries** | Anything the fixed pages don't answer, in SQL | [Queries](/cloud/queries) |

**Issues** is the one to keep open. An alert breach, an audit finding, or a person opens an
issue; it lands in a shared inbox with a state, an owner, and an append-only timeline.

**Dashboards** groups several things the docs cover separately, because they are separate
ideas: the **Models / Tools / Hooks** tabs are latency and cost vitals
([Performance](/cloud/performance)), the **Evals** tab is quality scores
([Online evals](/cloud/evaluations)), and **custom** boards are saved queries pinned as
charts ([Charts and boards](/cloud/dashboards)).

## fix

| Sidebar item | Answers | Page |
|---|---|---|
| **Policy editor** | Write a rule and publish it as an immutable version | [Policy editor](/cloud/policy-editor) |
| **Deploy Policies** | Which machines run which version, and is my rollout live | [Deploy policies](/cloud/deploy-policies) |
| **Alerts** | Page me when a number I already care about crosses a line | [Alerts](/cloud/alerts) |

Writing a policy and putting it on a fleet are deliberately two pages, because they are two
decisions. **Deploy Policies** shows the deployment each machine has *actually fetched and
verified* — not the one you assigned — which is the fact you want before assuming a rollout
landed. It also surfaces machines reporting activity while enforcing nothing.

## Reaching it without the dashboard

- **The cloud CLI** — read your data and administer your org from a terminal or a script;
  every command takes `--json`. It ships under the package name `agenteye`.
  [Cloud CLI →](/cloud/cli)
- **The AI assistant** — ask questions in plain English inside the dashboard, with links to
  the evidence behind every answer. [Assistant →](/cloud/assistant)
- **Agent skills** — hand the CLI to a coding agent and let it answer "is anything broken
  today?" for you. [Agent skills →](/cloud/agent-skills)
- **A REST API** — everything the dashboard and CLI do is backed by it. Call it with a
  [scoped key](/cloud/admin).
