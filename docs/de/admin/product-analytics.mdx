Failproof AI Cloud sendet Nutzungstelemetrie **über die Software selbst** an ihre Betreiber. Sie enthält niemals Daten Ihrer Agenten. Bei einer selbst gehosteten Installation ist sie standardmäßig aktiviert und kann deaktiviert werden.

## Was erfasst wird

Jedes Ereignis trägt fünf Dimensionen und enthält keine personenbezogenen Daten:

| Dimension | Beispiel | Bedeutung |
| --- | --- | --- |
| `product` | `agenteye` | Welches Produkt das Ereignis gesendet hat |
| `component` | `dashboard`, `server`, `cli` | Welcher Teil des Produkts das Ereignis gesendet hat |
| `app_version` | `0.0.1-beta.81` | Die von Ihnen ausgeführte Build-Version |
| `deployment_kind` | `self_hosted` | Ob es sich um eine Kundeninstallation, unsere Demo, unser QA oder einen Entwicklungsrechner handelt |
| `org_id` | eine UUID | In welcher Organisation die Aktion stattgefunden hat, als undurchsichtiger Bezeichner |

Darüber hinaus zeichnen Ereignisse auf, **was verwendet wurde, niemals was darin enthalten war**: Welche Seite aufgerufen wurde (als Routenmuster wie `/:org/sessions/:id`, niemals die echte URL), wie viele Filter welcher Art angewendet wurden, ob eine Aktion erfolgreich war und wie lange sie dauerte.

Die Slack-App erfasst Workspace-Verbindungen und -Trennungen, Kontoverknüpfungen, gestellte Fragen, gepostete Diagramme, Genehmigungsentscheidungen und Fehler nach einer festen Kategorie. Sie enthält niemals Slack-Workspace-, Benutzer- oder Kanal-IDs, E-Mail-Adressen, Fragen, Antworten, SQL oder Tokens.

### Der Name Ihrer Organisation

Neben der undurchsichtigen `org_id` erfassen wir den Namen, den URL-Slug und die Dashboard-Adresse Ihrer Organisation einmalig – in einem Organisationsdatensatz statt bei jedem Ereignis. So können wir erkennen, zu welchem Konto ein Muster gehört, wenn wir die Nutzung analysieren oder ein von Ihnen gemeldetes Problem untersuchen. Dies ist die einzige identifizierende Information, die das Produkt über Sie sendet.

### Ihre Nutzungsgesamtwerte

Der Server meldet die gemessenen Nutzungsgesamtwerte jeder Organisation – dieselben Zahlen, die Sie auf der Nutzungsseite sehen. Es handelt sich ausschließlich um Zählwerte: Ereignisse, Sitzungen, Agenten, Umgebungen, Evaluierungsläufe, Bewertungen, Audit-Läufe, gespeicherte Abfragen, Dashboards, Benachrichtigungen, Probleme, API-Schlüssel und Mitglieder sowie die Datumsgrenzen des Messzeitraums. Sie enthalten keine Bezeichner, Namen oder Abfragetexte und werden unabhängig davon übermittelt, ob jemand angemeldet ist.

## Was niemals erfasst wird

- **Keine Prompts, Modellantworten oder Ereignisinhalte** – weder als Text, Präfix noch als Hash
- **Keine Sitzungs-, Agenten- oder Trace-Bezeichner**
- **Keine Bewertungsnamen von Evaluatoren**
- **Keine Fehlermeldungen, Ausnahmetexte oder Antworttexte** – nur ein Statuscode und eine Kategorie aus einer festen Liste
- **Keine Tool-Argumente, SQL oder Abfragetexte**
- **Keine Details zu verbundenen Apps.** Das Verbinden oder Widerrufen eines MCP-Clients sendet höchstens eine Berechtigungsanzahl, niemals den App-Namen oder ein Token
- **Keine E-Mail-Adressen**
- **Keine Referrer-URLs oder Abfragestrings**
- **Keine Bildschirmaufzeichnung, DOM-Erfassung oder Klick- und Cursorverfolgung**

## Deaktivierung bei einer selbst gehosteten Installation

Setzen Sie `DO_NOT_TRACK=1` sowohl im Dashboard als auch im Server. Da beide unabhängig voneinander entscheiden, lässt das Setzen auf nur einer Seite die andere weiterhin berichten. Starten Sie den Server neu, damit die Änderung wirksam wird.

Die README-Datei Ihres Releases beschreibt die weiteren Opt-out-Einstellungen und wie Sie überprüfen können, dass die Telemetrie deaktiviert ist.

## Ein einmaliger Ping beim Opt-out

Wenn Sie sich über eine Produkteinstellung statt über `DO_NOT_TRACK` abmelden, kann das Dashboard **einen anonymen Ping** senden, der dies mit einer Wahrscheinlichkeit von 1 zu 1000 pro Prozessstart aufzeichnet. Er teilt uns mit, wie viele Betreiber die Telemetrie deaktivieren. Er enthält keine Bezeichner: keine Organisation, keinen Benutzer, keinen Hostnamen, keine URL und keine IP-Adresse – nur Produkt, Komponente, Version, Deployment-Art und Grund. Ein abgemeldeter Server sendet nichts.

Er wird niemals gesendet, wenn Sie `DO_NOT_TRACK` verwenden – weshalb das die empfohlene Einstellung ist, wenn Ihre Richtlinien jegliche ausgehende Telemetrie untersagen.

## Wohin die Daten gehen

An PostHog (`us.i.posthog.com`) über TLS auf Port 443. Es ist ein einzelner Hostname, den Sie daher auch mit einer einzigen Egress-Regel blockieren können.

Wie wir mit personenbezogenen Daten im Allgemeinen umgehen, erfahren Sie in der [Datenschutzrichtlinie](https://befailproof.ai/privacy/).
