Failproof AI Cloud sendet Nutzungstelemetrie **über die Software selbst** an ihre Maintainer. Die Daten Ihrer Agents sind darin niemals enthalten. Bei einer selbst gehosteten Installation ist die Telemetrie standardmäßig aktiviert und kann deaktiviert werden.

## Was erfasst wird

Jedes Ereignis enthält fünf Dimensionen und keinerlei personenbezogene Informationen:

| Dimension | Beispiel | Bedeutung |
| --- | --- | --- |
| `product` | `agenteye` | Welches Produkt das Ereignis gesendet hat |
| `component` | `dashboard`, `server`, `cli` | Welcher Teil des Produkts das Ereignis gesendet hat |
| `app_version` | `0.0.1-beta.81` | Der verwendete Build |
| `deployment_kind` | `self_hosted` | Ob es sich um eine Kundeninstallation, unsere Demo, unser QA oder eine Entwicklermaschine handelt |
| `org_id` | eine UUID | In welcher Organisation die Aktion stattfand, als opaker Bezeichner |

Darüber hinaus zeichnen Ereignisse auf, **was genutzt wurde, niemals was darin enthalten war**: welche Seite aufgerufen wurde (als Routenmuster wie `/:org/sessions/:id`, niemals die echte URL), wie viele Filter welcher Art angewendet wurden, ob eine Aktion erfolgreich war und wie lange sie gedauert hat.

Die Slack-App erfasst Workspace-Verbindungen und -Trennungen, Kontoverknüpfungen, gestellte Fragen, gepostete Diagramme, Genehmigungsentscheidungen und Fehler nach einer festen Kategorie. Sie enthält niemals Slack-Workspace-, Benutzer- oder Kanal-IDs, E-Mail-Adressen, Fragen, Antworten, SQL oder Tokens.

### Der Name Ihrer Organisation

Neben der opaken `org_id` erfassen wir den Namen Ihrer Organisation, den URL-Slug und die Dashboard-Adresse einmalig – in einem Organisationsdatensatz und nicht in jedem einzelnen Ereignis. So können wir erkennen, welchem Konto ein Muster gehört, wenn wir die Nutzung analysieren oder ein von Ihnen gemeldetes Problem untersuchen. Dies ist die einzige identifizierende Information, die das Produkt über Sie sendet.

### Ihre Nutzungsgesamtwerte

Der Server meldet für jede Organisation die gemessenen Nutzungsgesamtwerte – dieselben Zahlen, die Sie auf der Nutzungsseite sehen. Es handelt sich ausschließlich um Zählwerte: Ereignisse, Sitzungen, Agents, Umgebungen, Evaluierungsdurchläufe, Scores, Audit-Durchläufe, gespeicherte Abfragen, Dashboards, Benachrichtigungen, Issues, API-Schlüssel und Mitglieder sowie die Datumsangaben des Messzeitraums. Sie enthalten keine Bezeichner, Namen oder Abfragetext und werden unabhängig davon übermittelt, ob jemand angemeldet ist.

## Was niemals erfasst wird

- **Keine Prompts, Modellantworten oder Ereignisinhalte** – weder als Text, Präfix noch als Hash
- **Keine Sitzungs-, Agent- oder Trace-Bezeichner**
- **Keine Evaluator-Score-Namen**
- **Keine Fehlermeldungen, Exception-Texte oder Response-Bodies** – nur ein Statuscode und eine Kategorie aus einer festen Liste
- **Keine Tool-Argumente, SQL oder Abfragetext**
- **Keine Details zu verbundenen Apps.** Das Verbinden oder Widerrufen eines MCP-Clients sendet höchstens eine Berechtigungsanzahl, niemals den App-Namen oder ein Token
- **Keine E-Mail-Adressen**
- **Keine Referrer-URLs oder Query-Strings**
- **Keine Bildschirmaufzeichnung, DOM-Erfassung oder Klick- und Cursornachverfolgung**

## Deaktivierung bei einer selbst gehosteten Installation

Setzen Sie `DO_NOT_TRACK=1` sowohl für das Dashboard als auch für den Server. Beide entscheiden unabhängig voneinander – wenn Sie es nur für einen setzen, sendet der andere weiterhin Telemetrie. Starten Sie den Server neu, damit die Änderung wirksam wird.

Die README-Datei Ihres Releases beschreibt die weiteren Opt-out-Einstellungen und erklärt, wie Sie bestätigen können, dass die Telemetrie deaktiviert ist.

## Ein einzelner Ping beim Opt-out

Wenn Sie sich über eine Produkteinstellung statt über `DO_NOT_TRACK` abmelden, kann das Dashboard **einen anonymen Ping** senden, der dies erfasst – mit einer Wahrscheinlichkeit von 1 zu 1000 pro Prozessstart. Damit erfahren wir, wie viele Betreiber die Telemetrie deaktivieren. Der Ping enthält keine Bezeichner: keine Organisation, keinen Benutzer, keinen Hostnamen, keine URL oder IP-Adresse – nur Produkt, Komponente, Version, Deployment-Art und Grund. Ein Server im Opt-out-Zustand sendet nichts.

Dieser Ping wird niemals gesendet, wenn Sie `DO_NOT_TRACK` verwenden. Das ist daher die empfohlene Einstellung, wenn Ihre Richtlinien jegliche ausgehende Telemetrie untersagen.

## Ziel der Daten

Die Daten werden über TLS auf Port 443 an PostHog (`us.i.posthog.com`) übermittelt. Es handelt sich um einen einzigen Hostnamen, sodass Sie ihn auch mit einer einzigen Egress-Regel blockieren können.

Informationen zum allgemeinen Umgang mit personenbezogenen Daten finden Sie in unserer [Datenschutzrichtlinie](https://befailproof.ai/privacy/).
