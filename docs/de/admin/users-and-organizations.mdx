Organisationen isolieren Sitzungen, Auswertungen, Audits, Issues, Alerts, Abfragen, Dashboards, Benutzer und Schlüssel. Überprüfen Sie die aktive Organisation, bevor Sie administrative Ressourcen ändern.

## Mitglieder und Organisationen verwalten

<Tabs>
  <Tab title="Dashboard">
    1. Verwenden Sie den Organisations-Umschalter oben in der Cloud-Seitenleiste, um die Organisation zu wechseln.
    2. Gehen Sie zu **Administration → Benutzer**, um Mitglieder zu suchen oder nach Aktivitätsstatus und Rolle zu filtern.
    3. Wählen Sie **Neuer Benutzer**, geben Sie die E-Mail-Adresse ein, wählen Sie ein Berechtigungsset aus und passen Sie bei Bedarf Überschreibungen an.
    4. Öffnen Sie einen Benutzer später, um Berechtigungen zu aktualisieren, die Anmeldung zu deaktivieren oder das Konto wieder zu aktivieren.

    ![Die Benutzerseite zeigt Mitglieds-E-Mail-Adressen, Berechtigungssets sowie Bearbeitungs- und Deaktivierungsoptionen.](/images/dashboard/users.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp orgs list
    fp orgs switch reliability-team
    fp orgs current
    fp orgs perms

    fp users create engineer@example.com --permission-set standard
    fp users show engineer@example.com
    fp users update engineer@example.com --add audits:write
    fp users disable engineer@example.com
    fp users enable engineer@example.com
    ```
  </Tab>
</Tabs>

Administratoren können Benutzer anlegen, aktualisieren, deaktivieren und wieder aktivieren sowie das für ihre Rolle passende Berechtigungsset zuweisen. Die API verwendet für die Deaktivierung einen Löschvorgang, entfernt dabei jedoch weder das Konto noch den Mitgliedschaftsdatensatz.

<Warning>
  Das Deaktivieren eines Benutzers verhindert, dass sich diese Identität in jeder Organisation anmelden kann – nicht nur in der aktuell ausgewählten. Durch erneutes Aktivieren werden die globale Anmeldung und die Berechtigungen des Mitglieds in dieser Organisation wiederhergestellt.
</Warning>

<Tip>
  Vergeben Sie für Service-Accounts beschreibende Namen, die einem Workload und einem Verantwortlichen zugeordnet sind. Vermeiden Sie die gemeinsame Nutzung von Schlüsseln zwischen Organisationen oder zwischen Personen und Maschinen.
</Tip>
