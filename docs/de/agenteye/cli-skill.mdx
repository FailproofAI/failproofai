Fragen Sie Ihren Coding-Agenten *„Ist heute irgendetwas kaputt?"* und lassen Sie ihn die Antwort direkt aus Ihren Live-Daten von Failproof AI Observability liefern – ganz ohne Befehle auswendig zu lernen. Der **Failproof AI Observability CLI Skill** (`agenteye-cli`) ist ein *Agent Skill*: ein kleines Verzeichnis mit Anweisungen, das ein Coding-Agent wie Claude Code oder Codex bei Bedarf lädt. Er bringt dem Agenten bei, Ihre Observability-Umgebung über die [`agenteye` CLI](/de/agenteye/cli) per Klartextanfragen zu steuern – zum Beispiel *„Erstell CI einen Key, der nur Events pushen darf"* oder *„Bestätige den aktiven Incident und weise ihn mir zu."*

Es handelt sich **nicht** um einen Dienst oder eine separate Binary; es gibt nichts zu deployen. Der Skill setzt auf der bereits installierten CLI auf: Der Agent führt `agenteye --json …` aus, parst das saubere JSON und antwortet Ihnen in Prosaform. Alles, was er tun kann, könnten Sie auch selbst durch Eingabe derselben Befehle erledigen.

---

## Verhältnis zu den anderen Failproof AI Observability-Schnittstellen

Failproof AI Observability bietet vier Wege zu denselben Daten und Steuerelementen. Sie ergänzen sich gegenseitig:

| Schnittstelle | Was es ist | Wo es läuft | Wann Sie es verwenden |
|---|---|---|---|
| **[CLI](/de/agenteye/cli)** | Die Befehls- und Flag-Referenz für `agenteye` | Ihr Terminal | Wenn Sie einen bestimmten Befehl ausführen oder skripten möchten |
| **[CLI-Rezepte](/de/agenteye/cli-recipes)** | Copy-paste-`jq`/Pipeline-Muster | Ihr Terminal / Skripte | Wenn Sie die CLI in Automatisierungen einbinden |
| **CLI Skill** (dieses Dokument) | Ein natürlichsprachlicher Einstieg in die CLI | Ihr Coding-Agent auf Ihrer Workstation | Wenn Sie einfach fragen und den Agenten den passenden Befehl wählen lassen möchten |
| **[Evaluator Skill](/de/agenteye/evaluator-skill)** | Ein verwandter Skill, der Ihren Scoring-Service entwirft und aufbaut | Ihr Coding-Agent auf Ihrer Workstation | Wenn Sie Eval-Scores *erzeugen* statt lesen möchten |
| **[Python SDK Skill](/de/agenteye/python-sdk-skill)** | Ein verwandter Skill, der Ihren Agenten so instrumentiert, dass er Telemetriedaten ausgibt | Ihr Coding-Agent auf Ihrer Workstation | Wenn Ihr Agent die Events, die dieser Skill liest, erst *produzieren* soll |
| **[In-Dashboard-KI-Assistent](/de/agenteye/assistant)** | Ein im Dashboard eingebetteter Chat | Serverseitig (im Dashboard) | Wenn Sie im Dashboard Fragen zu Ihren Daten stellen möchten |

Der Skill selbst hat keine eigenen Berechtigungen; er übersetzt lediglich Ihre Worte in CLI-Aufrufe, die als Sie ausgeführt werden:

```mermaid
flowchart TD
    YOU["Sie: 'Bestätige den aktiven Incident'"] --> AGENT["Coding-Agent (Claude Code / Codex)<br/>lädt den agenteye-cli Skill"]
    AGENT --> CLI["agenteye --json incidents ack ..."]
    CLI -->|Ihre authentifizierte CLI-Session| API["Observability Dashboard API"]
```

### vs. den In-Dashboard-KI-Assistenten: ein wichtiger Unterschied

Das sind zwei verschiedene Tools mit sehr unterschiedlichem Wirkungsradius:

- Der **In-Dashboard-KI-Assistent** ([AI assistant](/de/agenteye/assistant)) ist ein im Dashboard eingebetteter Chat, der durch den Agentendienst betrieben wird. Er ist **nur lesend plus genehmigungspflichtige Erstellung**: Er kann gespeicherte Abfragen und Dashboards entwerfen, aber jede Schreibaktion wartet auf Ihre explizite Bestätigung per Klick, und er löscht nie. Er ist durch die `agent:use`-Berechtigung geschützt und sieht immer nur Daten der Organisation, die Sie gerade betrachten.
- Der **CLI Skill** läuft auf *Ihrer* Workstation innerhalb *Ihres* Coding-Agenten und steuert die `agenteye` CLI als **Sie**. Er kann den **vollen Funktionsumfang der CLI einschließlich Mutationen** ausführen (API-Keys erstellen/rotieren/deaktivieren, Org-Einstellungen ändern, Incidents auflösen, gespeicherte Abfragen löschen) – begrenzt allein durch die Berechtigungen Ihres CLI-Logins. Behandeln Sie ihn genauso sorgfältig, wie Sie diese Befehle manuell eingeben würden.

## Voraussetzungen

1. Die **`agenteye` CLI installiert** und im `PATH` (siehe die [CLI](/de/agenteye/cli)-Referenz: `pipx install agenteye`).
2. Ihre **Dashboard-URL** konfiguriert (`AGENTEYE_DASHBOARD_URL` oder der Agent übergibt `--base-url`).
3. Eine **aktive Session**: Führen Sie selbst zuerst `agenteye login` aus. Der Skill **kann** den per E-Mail zugesandten Einmalcode-Login nicht für Sie abschließen; er wird Sie auffordern, `agenteye login` auszuführen, wenn die Session fehlt oder abgelaufen ist (CLI-Exit-Code `4`).

Beachten Sie, dass er als eigenes Verzeichnis ausgeliefert wird und **nicht** im `pipx install agenteye`-Paket enthalten ist – suchen Sie dort also nicht danach.

## Installation des Skills

Der schnellste Weg ist die [`skills`](https://skills.sh)-CLI, die das Verzeichnis abruft und an den Ort legt, wo Ihr Agent sucht:

```bash
# Claude Code, nur dieses Projekt
npx skills add FailproofAI/skills --skill agenteye-cli -a claude-code

# Alle Projekte (installiert nach ~/.claude/skills/)
npx skills add FailproofAI/skills --skill agenteye-cli -a claude-code -g --copy

# Stattdessen Codex
npx skills add FailproofAI/skills --skill agenteye-cli -a codex
```

Anschließend verwalten Sie ihn wie jeden anderen Skill:

```bash
npx skills list -a claude-code      # was ist installiert
npx skills update agenteye-cli      # neueste Version holen
npx skills remove agenteye-cli      # entfernen
```

Bevorzugen Sie manuelle Installation? Ein Agent Skill ist lediglich ein Verzeichnis mit einer `SKILL.md` (plus optionalen Referenzen), das Kopieren funktioniert also ebenfalls:

- **Claude Code**: Legen Sie das Verzeichnis `agenteye-cli/` in `~/.claude/skills/` (alle Projekte) oder `<Ihr-Repo>/.claude/skills/` (nur dieses Repo). Claude Code erkennt es automatisch – prüfen Sie dies mit der `/skills`-Liste oder stellen Sie einfach eine Frage, die zur Beschreibung passt.
- **Codex (OpenAI)**: Codex liest dieselbe `SKILL.md`. Die mitgelieferte `agents/openai.yaml` setzt `allow_implicit_invocation: true`, sodass Codex den Skill automatisch auswählt, wenn eine Aufgabe passt; andernfalls rufen Sie ihn explizit als `$agenteye-cli` auf.

## Sicherheit: Mutationen fragen NICHT nach, wenn ein Agent die CLI ausführt

> **Warnung:** Lesen Sie dies, bevor Sie einem Agenten erlauben, Änderungen vorzunehmen.

Die `agenteye` CLI fragt normalerweise *„Sind Sie sicher?"* vor einer destruktiven Aktion. Sie **überspringt diese Bestätigung automatisch, wenn sie nicht an ein Terminal gebunden ist (was genau der Fall ist, wenn ein Coding-Agent sie ausführt), und `--json` überspringt sie ebenfalls.** Die Sicherheitsabfrage wird für den Agenten also **nicht** erscheinen.

Der Skill ist darauf ausgelegt, das zu kompensieren: Er ist angewiesen, den genauen Befehl anzugeben, den er ausführen wird, und Ihr explizites **OK einzuholen, bevor eine Zustandsänderung erfolgt**. Halten Sie diese Disziplin aufrecht. Wenn Sie Failproof AI Observability über einen Agenten steuern, *sind Sie* der Bestätigungsschritt. Die zustandsändernden Befehle, auf die Sie achten sollten:

- `keys create` / `update` / `disable` / `regenerate`
- `users create` / `update` / `disable` / `enable`
- `settings set`
- `alerts create` / `update` / `delete` / `test`
- die schreibenden `incidents`-Unterbefehle: `ack` / `assign` / `resolve` / `open` / `comment-add` / `comment-delete` / `subscribe` / `unsubscribe`
- `query create` / `update` / `delete`
- `agent rename` / `delete`
- `orgs switch`

Alles unter **Observe** (`events`, `sessions`, `evals`, `errors`, `list`, `whoami`, `orgs list/current/perms`) ist schreibgeschützt und ändert nichts.

Da der Agent als **Sie** agiert, kann er nur das tun, wozu Ihr Login berechtigt ist; Berechtigungen werden **pro Organisation** aufgelöst (siehe [API-Keys](/de/agenteye/api-keys)). Ein Befehl, für den Sie keine Berechtigung haben, gibt Exit-Code `5` mit dem genauen Namen der benötigten Berechtigung zurück, sodass der Agent Ihnen präzise sagen kann, was Sie bei einem Administrator anfragen müssen, anstatt undurchsichtig zu scheitern.

## Was Sie fragen können

So sieht ein echter Durchlauf aus – erst eine Abfrage, dann eine Änderung, die auf Ihre Bestätigung wartet:

```text
Sie   ▸ Ist in den letzten 24 Stunden irgendetwas schiefgelaufen?

Agent ▸ Ausführen: agenteye --json errors --since 24h --aggregate
        3 Fehlertypen in den letzten 24 Stunden. Der häufigste ist TimeoutError
        (18 Vorkommen, alle beim checkout-agent), dann RateLimited (5).
        Soll ich die fehlgeschlagenen Sessions für TimeoutError anzeigen?

Sie   ▸ Erstell CI einen Key, der nur Events pushen darf.

Agent ▸ Das erstellt einen API-Key. Ich führe aus:
          agenteye keys create ci --add events:add
        OK zum Fortfahren?

Sie   ▸ ja

Agent ▸ Fertig. Key „ci" wurde mit events:add erstellt.
        Das Secret wird nur einmal angezeigt – speichern Sie es jetzt. Ich kann es nicht erneut ausgeben.
```

Der Skill ordnet jede natürlichsprachliche Absicht dem passenden `agenteye`-Befehl zu, ermittelt gültige Werte zuerst (`list <kind>`, `whoami`), um nicht zu raten, und nennt den genauen Befehl vor jeder Änderung. Weitere Beispiele:

- *„Ist in den letzten 24 Stunden etwas kaputt / fehlgeschlagen?"* → `errors --since 24h --aggregate`, dann eine Aufschlüsselung.
- *„Warum ist Session `run-001` fehlgeschlagen?"* → `events --session-id run-001 --all` + `evals --session-id run-001`.
- *„Wie entwickelt sich die Qualität diese Woche?"* → `evals --aggregate --since 7d`, dann Einblick in niedrig bewertete Läufe.
- *„Erstell CI einen Key, der nur Events pushen darf."* → `keys create ci --add events:add` (er nennt den Befehl, erstellt ihn dann und erfasst das einmalige Secret).
- *„Wer hat Zugriff? Mach Dana zu Read-only."* → `users list` → `users update dana@… --permission-set read-only` (nach Ihrer Bestätigung).
- *„Bestätige den aktiven Incident und weise ihn mir zu."* → `incidents list --state firing` → `incidents ack <id>` / `incidents assign <id> you@…`.

Die genauen Befehle, Flags und JSON-Strukturen dahinter finden Sie in der [CLI](/de/agenteye/cli)-Referenz und den [CLI-Rezepten für Agenten](/de/agenteye/cli-recipes).
