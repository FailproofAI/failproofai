Alle Fehler Ihrer Agenten auf einen Blick – gruppiert, sodass ein massiver Ausbruch als einzelnes Problem erscheint. Sie gelangen mit einem Klick von „irgendetwas ist rot" direkt zu dem genauen Lauf, der fehlgeschlagen ist, ohne einen Live-Feed durchscrollen zu müssen.

*Die Fehlerseite: ein Histogramm der Fehler über die Zeit, mit wiederholten Fehlern, die zu einer Zeile pro Vorfall zusammengefasst werden.*

## Jeder Fehler – bereits für Sie gesammelt

Wenn ein Agent abstürzt, sollten Sie nicht in einem Live-Ereignisstrom scrollen müssen und hoffen, die roten Zeilen zu erwischen, bevor sie verschwinden. Die Seite **Errors** übernimmt die Sammlung für Sie. Sie bündelt alles, was das Dashboard rot markieren würde, auf einer einzigen Triaging-Oberfläche – sodass das Erste, was Sie sehen, das ist, was fehlschlägt, und nicht, wo Sie suchen müssen.

Dabei erfasst sie mehr als nur die offensichtlichen Fehler. Neben expliziten `error`-Ereignissen zeigt Failproof AI Observability auch die stillen Fehler: Jede `tool_result`-, `hook_completed`- oder `agent_end`-Meldung, deren Nutzdaten einen Fehlschlag enthalten, erscheint hier. Ein Tool, das einen Fehler zurückgegeben hat, oder ein Hook, der schlecht beendet wurde – das entgeht Ihnen nicht mehr, nur weil keine laute Ausnahme geworfen wurde.

Ganz oben zeigt ein Histogramm Fehler über die Zeit. Ein Blick genügt, um zu erkennen, ob es sich um ein stetiges Hintergrundrauschen oder eine Spitze handelt, die vor wenigen Minuten begann – damit Sie sofort wissen, ob Sie alles stehen und liegen lassen müssen.

Wie jede Beobachtungsoberfläche ist die Fehlerseite auf Ihre Organisation beschränkt und lässt sich nach Zeitraum, Umgebung, Agent und Sitzung filtern. So können Sie aus einer flottenweit gültigen Liste auf den einen Agenten oder die eine Umgebung eingrenzen, die Sie wirklich interessiert.

## Ein Vorfall – nicht hundert identische Zeilen

Eine einzelne defekte Abhängigkeit kann denselben Fehler hunderte Male pro Minute auslösen. Unverarbeitet ergibt das eine Wand nahezu identischer Zeilen, die das Einzige, was Sie wirklich sehen müssen, begraben.

Failproof AI Observability fasst Wiederholungsfehler, die dieselbe Sitzung und denselben Fehlertyp teilen, zu einer einzigen Zeile zusammen. Ein Ausbruch erscheint als ein Vorfall. Sie zählen Probleme, keine Log-Zeilen – und das Signal, das zählt, bleibt oben, statt von seinem eigenen Volumen überwältigt zu werden.

## Von „irgendetwas ist rot" zum genauen Ereignis

Klicken Sie auf eine Zeile, um direkt in die Sitzung dieses Laufs zu gelangen, positioniert auf dem exakten Ereignis, das fehlgeschlagen ist. Kein Kopieren von Sitzungs-IDs, kein Scrollen auf der Suche nach dem Moment, in dem es schiefging: Sie landen genau dort, mit dem vollständigen Ausführungsgraphen auf einen Blick, sodass Sie sehen können, was der Agent in den Momenten vor dem Absturz getan hat.

Wenn Sie `alerts:write` besitzen, trägt jede Zeile außerdem einen **+ alert**-Button. Ein Klick darauf öffnet in Observability eine neue Alarmregel, die bereits so vorausgefüllt ist, dass derselbe Fehler erneut erfasst wird. Der Vorfall, den Sie gerade bearbeitet haben, benachrichtigt Sie beim nächsten Mal, anstatt Sie zweimal zu überraschen.

**Wo Sie es finden:** Die Seite **Errors** befindet sich im Beobachtungsbereich des Dashboards unter `/<org-slug>/errors`.

## Verwandtes

- [Alerts](/de/agenteye/alerts): Jeden Fehler in eine Benachrichtigungsregel umwandeln.
- [Incidents](/de/agenteye/incidents): Einen ausgelösten Alarm von offen bis gelöst verfolgen.
- [Sessions](/de/agenteye/sessions): Den vollständigen Lauf hinter einem Fehler öffnen.
- [Audits](/de/agenteye/audits): Observability Fehlermuster in Ihren Läufen für Sie finden lassen.
