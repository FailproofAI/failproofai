Alle Fehler Ihrer Agents an einem Ort – gruppiert, sodass ein Fehlersturm als einzelnes Problem erscheint. Sie gelangen mit einem Klick von „irgendetwas ist rot" zum genauen Run, der den Fehler verursacht hat, ohne in einem Live-Feed danach suchen zu müssen.

## Jeder Fehler – bereits für Sie gesammelt

Wenn ein Agent abstürzt, sollten Sie nicht in einem Live-Event-Stream scrollen müssen und hoffen, die roten Zeilen zu erwischen, bevor sie verschwinden. Die **Errors**-Seite übernimmt die Sammlung für Sie. Sie bündelt alles, was das Dashboard rot einfärben würde, auf einer einzigen Triage-Oberfläche – das Erste, was Sie sehen, ist *was* fehlschlägt, nicht *wo* Sie suchen müssen.

Dabei werden auch die stillen Fehler erkannt. Neben expliziten `error`-Events zeigt Failproof AI Observability auch die unscheinbaren Fehler: jedes `tool_result`, `hook_completed` oder `agent_end`, dessen Payload einen Fehler enthält, erscheint hier. Ein Tool, das einen Fehler zurückgegeben hat, oder ein Hook, der fehlerhaft beendet wurde, entgeht Ihnen nicht mehr nur, weil keine laute Exception ausgelöst wurde.

Am oberen Rand zeigt ein Histogramm die Fehler über die Zeit. Auf einen Blick erkennen Sie, ob es sich um ein gleichmäßiges Hintergrundrauschen oder um eine Spitze handelt, die vor wenigen Minuten begann – damit wissen Sie sofort, ob Sie alles stehen und liegen lassen müssen.

Wie jede Observe-Oberfläche ist die Errors-Seite auf Ihre Organisation beschränkt und lässt sich nach Zeitraum, Umgebung, Agent und Session filtern. So können Sie eine flottenweit gültige Liste auf den einen Agent oder die eine Umgebung eingrenzen, die Sie wirklich interessiert.

## Ein Vorfall – nicht hundert identische Zeilen

Eine einzelne defekte Abhängigkeit kann denselben Fehler hunderte Male pro Minute auslösen. Unbearbeitet ergibt das eine Wand nahezu identischer Zeilen, die das Wesentliche begräbt.

Failproof AI Observability fasst wiederkehrende Fehler mit derselben Session und demselben Fehlertyp zu einer einzigen Zeile zusammen. Ein Fehlersturm erscheint als ein Vorfall. Sie zählen Probleme, keine Log-Zeilen – und das relevante Signal bleibt oben, statt von seinem eigenen Volumen übertönt zu werden.

## Von „irgendetwas ist rot" zum genauen Event

Klicken Sie auf eine Zeile, um direkt in die Session dieses Runs zu gelangen – positioniert auf dem genauen Event, das fehlgeschlagen ist. Kein Kopieren von Session-IDs, kein Scrollen auf der Suche nach dem Moment des Scheiterns: Sie landen direkt dort, mit dem vollständigen Ausführungsgraphen auf einen Blick, sodass Sie sehen, was der Agent in den Momenten vor dem Fehler getan hat.

Wenn Sie `alerts:write`-Berechtigung haben, trägt jede Zeile außerdem einen **+ alert**-Button. Klicken Sie darauf, öffnet Observability eine neue Alert-Regel, die bereits vorausgefüllt ist, um denselben Fehler erneut abzufangen. Der Vorfall, den Sie gerade triagiert haben, wird zu dem, der Sie beim nächsten Mal benachrichtigt – anstatt Sie zweimal zu überraschen.

**Wo Sie es finden:** Die **Errors**-Seite befindet sich im Observe-Bereich des Dashboards unter `/<org-slug>/errors`.

- [Incidents](/de/agenteye/incidents): Einen ausgelösten Alert von offen bis gelöst verfolgen.
- [Sessions](/de/agenteye/sessions): Den vollständigen Run hinter einem Fehler öffnen.
