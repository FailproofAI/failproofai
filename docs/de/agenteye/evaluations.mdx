Qualitätsprobleme finden Sie jetzt selbst – bevor Sie davon durch eine Nutzerbeschwerde erfahren. Schließen Sie einmalig Ihren eigenen Bewertungsdienst an, und Failproof AI Observability bewertet jeden abgeschlossenen Run automatisch. Ein Abfall in der Hilfsbereitschaft oder ein Anstieg bei Halluzinationen wird sichtbar, bevor ein Kunde davon betroffen ist.

![Das Sessions-Raster mit einer Ergebnisspalte: Jeder Run trägt eine Bewertungsstatus-Pille und farbcodierte Badges für Hilfsbereitschaft, Faktentreue und Tool-Effizienz](/agenteye/images/sessions-list.png)

*Jeder Run im Sessions-Raster trägt seine Bewertungen; rote, gelbe und grüne Badges lassen schwache Runs sofort hervorstechen, ohne dass Sie ein einziges Transkript öffnen müssen.*

## Manuelles Stichproben nehmen beenden

Früher haben Sie eine Handvoll Runs stichprobenartig geprüft und gehofft, dass der Rest in Ordnung war. Jetzt wird jede abgeschlossene Session in dem Moment bewertet, in dem sie endet – auf den Dimensionen, die Ihnen wichtig sind: Hilfsbereitschaft, Tool-Effizienz, Faktentreue, Sicherheit oder was auch immer Ihren Qualitätsmaßstab ausmacht. Sie definieren die Score-Schlüssel; Failproof AI Observability speichert, verfolgt und zeigt alles an, was Ihr Evaluator zurücksendet. Kein Run bleibt unbewertet, und Sie erfahren von einer Regression nicht mehr erst durch ein Support-Ticket.

Die Bewertungen erscheinen direkt im Sessions-Raster unter **`/<org-slug>/sessions`** (Seitenleiste → *observe* → *sessions*) – ein Badge-Cluster pro Zeile. Möchten Sie nur die Runs sehen, die nicht bestanden haben? Filtern Sie das Raster nach Bewertungsbereich, z. B. Hilfsbereitschaft unter 0,5, und rufen Sie genau die Runs auf, die es wert sind, gelesen zu werden. Zum Anzeigen von Bewertungen ist die Berechtigung `evaluations:read` erforderlich.

## Verstehen, warum ein Run schlecht bewertet wurde

Eine Zahl sagt Ihnen, dass ein Run schwach war; die Session-Seite sagt Ihnen warum. Öffnen Sie einen beliebigen Run, und die rechte Leiste beginnt mit der übergeordneten Zusammenfassung, gefolgt von einem Balken pro Dimension mit der eigenen Begründung Ihres Evaluators darunter. So gelangen Sie in Sekunden von „dieser Run erzielte 0,4 bei der Faktentreue" zu der genauen Aussage, die falsch war.

![Die rechte Leiste einer Session: die Bewertungszusammenfassung oben, dann pro Dimension Bewertungsbalken jeweils mit einer Zeile Begründung, neben der vollständigen Ereignis-Timeline](/agenteye/images/session-detail.png)

*Die Session-Detailansicht: Zusammenfassung, dimensionsbezogene Bewertungsbalken und die Begründung hinter jeder Bewertung – direkt neben der Ereignis-Timeline des Runs.*

Haben Sie einen schärferen Evaluator eingesetzt oder schauen Sie sich einen Run an, der abgestürzt ist, bevor er bewertet werden konnte? Ein **Re-evaluate**-Button (geschützt durch `evaluations:trigger`) bewertet die Session neu und hängt das frische Ergebnis an deren Timeline an, sodass frühere Bewertungen als Verlauf sichtbar bleiben. Sie finden ihn unter **`/<org-slug>/sessions/<session-id>`**.

## Qualitätstrend der gesamten Flotte beobachten

Ein einzelner schlecht bewerteter Run ist Rauschen; eine ganze Kohorte, die absackt, ist ein Signal. Gespeicherte Dashboards verwandeln Ihre Bewertungen in einen Trend, den Sie auf einen Blick verfolgen können: durchschnittliche Hilfsbereitschaft diese Woche im Vergleich zur letzten, pro Agent, pro Umgebung.

![Ein Qualitäts-Dashboard: durchschnittliche Bewertungsbalken pro Evaluatordimension neben einem zeitlichen Verlauf](/agenteye/images/dashboard-quality.png)

*Ein gespeichertes Qualitäts-Dashboard zeigt den Verlauf der von Ihnen hervorgehobenen Score-Schlüssel – so ist ein langsamer Drift längst offensichtlich, bevor er zu einem Vorfall wird.*

Dashboards befinden sich unter **`/<org-slug>/dashboards`** (Seitenleiste → *analyze* → *dashboards*), werden innerhalb Ihrer gesamten Organisation geteilt, und jede Karte fasst die zugehörigen Sessions zusammen: Anzahl, Durchschnitt jedes hervorgehobenen Scores und ein Trend-Sparkline. „Open in sessions" führt Sie direkt in die vorgefilterten Runs hinter einer beliebigen Zahl. Zum Anzeigen sind `dashboards:read` und `evaluations:read` erforderlich.

## Einen Evaluator einmalig anschließen

Die Bewertung ist optional und bleibt vollständig deaktiviert, bis Sie Failproof AI Observability auf einen Scorer ausrichten. Sie richten einen kleinen HTTP-Dienst ein (Observability liefert eine funktionsfähige Referenzimplementierung, die Sie kopieren können), setzen zwei Werte auf Ihrem Server, und von da an wird jeder Run automatisch für Sie bewertet. Die vollständige Anleitung, den Scoring-Vertrag und das SDK finden Sie im ausführlichen Leitfaden.

Sind Sie sich nicht sicher, welche Dimensionen es überhaupt wert sind, bewertet zu werden? Die [Evaluator-Agent-Skill](/de/agenteye/evaluator-skill) lässt einen Coding-Agenten das anhand Ihrer eigenen Sessions herausarbeiten und den Dienst dann erstellen und deployen.
