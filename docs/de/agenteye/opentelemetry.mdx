OpenTelemetry ermöglicht es Ihnen, Agent-Traces, Logs und Metriken über das standardmäßige OTLP/HTTP-Protokoll an Failproof AI Cloud zu senden. Die Nutzung ist optional. Bestehende Failproof AI-Integrationen funktionieren weiterhin ohne diese Funktion.

## Schlüssel erstellen

Die OTLP-Aufnahme ist für jede Organisation standardmäßig aktiviert; es sind keine weiteren Schritte erforderlich. Verwenden Sie einen Cloud-API-Schlüssel mit der Berechtigung `events:add` – dieselbe Berechtigung, die auch für die Agent-Berichterstattung genutzt wird.

Im Dashboard enthält **Home → Ersteinrichtung** eine Karte **Mit OpenTelemetry verbinden**: Über **Collector-Schlüssel erstellen** wird ein `events:add`-Schlüssel angelegt, einmalig zusammen mit den Exporter-Variablen angezeigt und der Verbindungsstatus eingeblendet. Alternativ können Sie unter **Einstellungen → API-Schlüssel** einen neuen Schlüssel mit der Option **Nur Logs senden** erstellen.

## Coding-Agent verbinden

Verbinden Sie Ihren Rechner mit `failproofai config` und wählen Sie anschließend einen Agent:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Der Setup-Befehl unterstützt Claude Code, Codex und Copilot und wählt je nach Situation Cloud oder einen lokalen authentifizierten Relay. Copilot verwendet automatisch den lokalen Relay. Starten Sie den konfigurierten Failproof AI-Daemon, bevor Sie den Relay nutzen.

Falls Failproof AI bereits Sitzungstranskripte eines Agents sendet, fragt das Setup, ob dieser Agent auf OTEL umgestellt werden soll. Die Standardantwort ist „Nein". Bei Zustimmung werden Transkript-Uploads für diesen Agent gestoppt; die Policy-Durchsetzung und Berichte anderer Agents bleiben davon unberührt.

## Anwendung verbinden

Verwenden Sie die OpenTelemetry-Instrumentierung Ihrer Anwendung mit diesen Umgebungsvariablen:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Der Endpunkt ist die OTLP-Basis von Cloud, `https://app.befailproof.ai/otel`; Ihr Exporter hängt selbst `/v1/traces`, `/v1/logs` oder `/v1/metrics` an. Signalspezifische Variablen wie `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` werden unverändert übernommen und benötigen daher den vollständigen Pfad, z. B. `https://app.befailproof.ai/otel/v1/logs`.

Ersetzen Sie `<key>` durch Ihren API-Schlüssel. Bewahren Sie das Secret außerhalb der Shell-Historie, Bildschirmaufzeichnungen und eingecheckter Konfigurationsdateien auf. Für einen konfigurierten Rechner gibt `failproofai otel env --service my-agent` den Block mit dem vorhandenen Schlüssel aus. Die Ausgabe enthält ein Credential.

Cloud akzeptiert OTLP/HTTP-Exporte für Traces, Logs und Metriken als Protobuf oder JSON, einschließlich gzip-komprimierter Anfragen. OTLP/gRPC wird nicht unterstützt.

Metriken werden zur Exporter-Kompatibilität bestätigt, aber weder gespeichert noch angezeigt. Unterstützte Agent-Traces und Coding-Agent-Logs werden zu Sitzungen; Felder, die der Agent nicht exportiert, bleiben leer.

## Prompt-Text erfassen

<Warning>
Die Texterfassung kann Prompts, Tool-Argumente und andere sensible Inhalte umfassen. `failproofai otel enable` aktiviert diese Funktion. Fügen Sie `--no-content` hinzu, um die Erfassung von Prompts und Tool-Details zu deaktivieren.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Für einen manuell konfigurierten Agent verwenden Sie dessen eigene Einstellungen zur Inhaltserfassung:

<Tabs>
  <Tab title="Claude Code">
    Fügen Sie diese Variablen zur Umgebung Ihres Agents hinzu, zusammen mit dem Anwendungsblock oben:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Setzen Sie beide Inhaltsvariablen auf `0`, um die Erfassung von Prompts und Tool-Details zu deaktivieren.
  </Tab>
  <Tab title="Codex">
    Verwenden Sie in der Benutzerkonfiguration von Codex dessen OTEL-Einstellungen:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Konversationsinhalte von Codex befinden sich in Logs; interne Laufzeit-Traces und Metriken sollten deaktiviert bleiben. Codex verwendet den vollständigen von Ihnen angegebenen Endpunkt. Setzen Sie `log_user_prompt` auf `false`, um Prompts auszuschließen; der Setup-Befehl behält ein explizit gesetztes `false` bei.
  </Tab>
  <Tab title="Gemini CLI">
    Verwenden Sie die Telemetrieeinstellungen von Gemini mit dem lokalen Relay:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI wird von `failproofai otel enable` nicht unterstützt. Konfigurieren Sie es manuell mit einem eigenen authentifizierten Collector. Setzen Sie `logPrompts` auf `false`, um keine Prompts zu erfassen.
  </Tab>
  <Tab title="Copilot in VS Code">
    Verwenden Sie diese VS Code-Benutzereinstellungen:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Führen Sie `failproofai otel enable copilot` aus, um den authentifizierten Relay zu aktivieren. Setzen Sie `captureContent` auf `false`, um Inhalte auszulassen.
  </Tab>
</Tabs>

## Setup überprüfen oder rückgängig machen

Der Relay puffert Telemetriedaten bei vorübergehenden Netzwerk- und Serverausfällen und
wiederholt die Übertragung nach der Wiederherstellung. Eine dauerhafte `400`-Ablehnung – einschließlich eines
zu großen Events – erfordert eine Korrektur der Nutzlast. Der Relay behält den
abgelehnten Batch zur Überprüfung, anstatt ihn wiederholt zu senden.

Nach einer `401`- oder `403`-Antwort ersetzen Sie das Credential durch einen Schlüssel mit `events:add`-Berechtigung
für dieselbe Organisation. Eine erneute Verbindung sendet zurückgehaltene OTLP-Exporte, die wegen ungültiger Credentials abgelehnt wurden, nicht automatisch erneut; bitten Sie Ihren Operator, diese Batches wiederherzustellen.
Behalten Sie diese in ihrer ursprünglichen Organisation.

```bash
failproofai otel status
failproofai otel disable all
```

Der Status unterscheidet zwischen von Failproof AI verwalteten Einstellungen und anderweitig konfigurierter Telemetrie. „Disable" stellt die vorherigen verwalteten Einstellungen und die zuvor gewählte Transkript-Upload-Option des Agents wieder her.
