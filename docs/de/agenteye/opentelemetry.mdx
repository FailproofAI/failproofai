OpenTelemetry ermöglicht es Ihnen, Agent-Traces, Logs und Metriken über das standardisierte OTLP/HTTP-Protokoll an Failproof AI Cloud zu senden. Die Nutzung ist optional. Ihre bestehenden FailproofAI-Integrationen funktionieren weiterhin, ohne dass Sie diese Funktion aktivieren müssen.

## Ingest für Ihre Organisation aktivieren

Ein Organisationsadministrator öffnet **Einstellungen → OpenTelemetry** und aktiviert den Ingest. Verwenden Sie einen Cloud-API-Schlüssel mit der Berechtigung `events:add` – dieselbe Berechtigung, die auch für das Agent-Reporting verwendet wird.

Wenn der Ingest deaktiviert ist, lehnt Cloud OTLP-Exporte ab, sodass `failproofai otel enable` keine Wirkung hat und Ihre Agents Sitzungen weiterhin auf dem üblichen Weg senden. Führen Sie `failproofai otel status` aus, um den Organisationsschalter zu prüfen, und bitten Sie einen Administrator, ihn zu aktivieren.

## Einen Coding-Agent verbinden

Verbinden Sie Ihren Rechner mit `failproofai config` und wählen Sie anschließend einen Agent:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Der Setup-Befehl unterstützt Claude Code, Codex und Copilot und wählt je nach Situation Cloud oder ein lokal authentifiziertes Relay. Copilot verwendet automatisch das lokale Relay. Starten Sie den konfigurierten FailproofAI-Daemon, bevor Sie das Relay nutzen.

Sendet FailproofAI bereits Sitzungstranskripte eines Agents, fragt das Setup, ob dieser Agent auf OTEL umgestellt werden soll. Die Standardantwort ist „Nein". Eine Bestätigung stoppt die Transkript-Uploads für diesen Agent; die Richtliniendurchsetzung und das Reporting anderer Agents bleiben davon unberührt.

## Eine Anwendung verbinden

Verwenden Sie die OpenTelemetry-Instrumentierung Ihrer Anwendung mit den folgenden Umgebungsvariablen:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Der Endpunkt ist die OTLP-Basis von Cloud, `https://app.befailproof.ai/otel`; Ihr Exporter hängt `/v1/traces`, `/v1/logs` oder `/v1/metrics` selbst an. Signalspezifische Variablen wie `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` werden unverändert verwendet und benötigen daher den vollständigen Pfad, z. B. `https://app.befailproof.ai/otel/v1/logs`.

Ersetzen Sie `<key>` durch Ihren API-Schlüssel. Halten Sie das Secret aus dem Shell-Verlauf, Bildschirmaufzeichnungen und eingecheckten Konfigurationsdateien heraus. Auf einem konfigurierten Rechner gibt `failproofai otel env --service my-agent` den Block mit dem vorhandenen Schlüssel aus. Die Ausgabe enthält ein Credential.

Cloud akzeptiert OTLP/HTTP-Exporte für Traces, Logs und Metriken – als Protobuf oder JSON, einschließlich gzip-komprimierter Anfragen. OTLP/gRPC wird nicht unterstützt.

Metriken werden zur Exporter-Kompatibilität bestätigt, aber weder gespeichert noch angezeigt. Unterstützte Agent-Traces und Coding-Agent-Logs werden zu Sitzungen; Felder, die der Agent nicht exportiert, bleiben leer.

## Prompt-Text erfassen

<Warning>
Die Texterfassung kann Prompts, Tool-Argumente und andere sensible Inhalte umfassen. `failproofai otel enable` aktiviert diese Funktion. Fügen Sie `--no-content` hinzu, um die Erfassung von Prompts und Tool-Details zu deaktivieren.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Für einen manuell konfigurierten Agent verwenden Sie dessen eigene Einstellungen zur Inhaltserfassung:

<Tabs>
  <Tab title="Claude Code">
    Fügen Sie diese Variablen zur Umgebung Ihres Agents hinzu, zusammen mit dem oben beschriebenen Anwendungsblock:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Setzen Sie beide Inhaltsvariablen auf `0`, um die Erfassung von Prompts und Tool-Details zu vermeiden.
  </Tab>
  <Tab title="Codex">
    Verwenden Sie in der Benutzerkonfiguration von Codex die entsprechenden OTEL-Einstellungen:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Konversationsinhalte von Codex befinden sich in den Logs; interne Laufzeit-Traces und Metriken sollten deaktiviert bleiben. Codex verwendet den vollständigen Endpunkt, den Sie angeben. Setzen Sie `log_user_prompt` auf `false`, um Prompts auszuschließen; der Setup-Befehl behält ein explizites `false` bei.
  </Tab>
  <Tab title="Gemini CLI">
    Verwenden Sie die Telemetrieeinstellungen von Gemini mit dem lokalen Relay:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI wird von `failproofai otel enable` nicht unterstützt. Konfigurieren Sie es manuell mit einem eigenen authentifizierten Collector. Setzen Sie `logPrompts` auf `false`, um keine Prompts zu erfassen.
  </Tab>
  <Tab title="Copilot in VS Code">
    Verwenden Sie diese VS Code-Benutzereinstellungen:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Führen Sie `failproofai otel enable copilot` aus, um das authentifizierte Relay zu aktivieren. Setzen Sie `captureContent` auf `false`, um Inhalte auszulassen.
  </Tab>
</Tabs>

## Setup prüfen oder rückgängig machen

Das Relay behält Telemetriedaten bei vorübergehenden Netzwerk- und Serverausfällen und
wiederholt die Übertragung nach der Wiederherstellung. Eine dauerhafte `400`-Ablehnung – einschließlich eines Ereignisses,
das zu groß zum Speichern ist – erfordert eine Korrektur der Nutzlast. Das Relay behält den
abgelehnten Batch zur Überprüfung, anstatt ihn wiederholt zu senden.

Nach einem `401`- oder `403`-Fehler ersetzen Sie das Credential durch einen Schlüssel mit der Berechtigung `events:add`
für dieselbe Organisation. Eine erneute Verbindung sendet wegen fehlender Credentials abgelehnte OTLP-Exporte nicht automatisch erneut; bitten Sie Ihren Operator, diese Batches wiederherzustellen.
Behalten Sie diese in ihrer ursprünglichen Organisation.

```bash
failproofai otel status
failproofai otel disable all
```

Status unterscheidet zwischen von FailproofAI verwalteten Einstellungen und von Ihnen anderweitig konfigurierter Telemetrie. Disable stellt die vorherigen verwalteten Einstellungen und die frühere Transkript-Upload-Einstellung des Agents wieder her.
