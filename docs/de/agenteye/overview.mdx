Failproof AI Observability ist eine selbst gehostete Plattform zum Beobachten, Bewerten und Verbessern Ihrer KI-Agenten im Produktivbetrieb. Sie zeichnet alles auf, was Ihre Agenten tun (jeden Tool-Aufruf, jede Modellanfrage, jeden Hook und jeden Fehler), bewertet die Qualität jedes Runs und zeigt Ihnen die Fehler, nach denen Sie gar nicht gesucht hätten – alles in einem Dashboard, das Sie in Ihrer eigenen Infrastruktur betreiben.

Wenn Sie KI-Agenten deployen und es satt haben zu rätseln, warum ein Run schiefgelaufen ist, sind Sie hier genau richtig. Diese Seite erklärt, was Failproof AI Observability bietet und wie die einzelnen Komponenten zusammenpassen – bevor Sie irgendetwas installieren.

## Warum Teams es nutzen

- **Sehen Sie, was Ihr Agent wirklich getan hat.** Jeder Run wird zu einem lesbaren, Git-artigen Ausführungsgraphen: welche Tools parallel liefen, welche Sub-Agenten abgezweigt sind, wo er ins Stocken geriet und was er gekostet hat.
- **Qualitätsregressionen automatisch erkennen.** Binden Sie einen kleinen Scoring-Dienst an, und Failproof AI Observability bewertet jeden abgeschlossenen Run – sodass ein Rückgang der Hilfsbereitschaft oder eine Zunahme von Halluzinationen von selbst auffällt.
- **Fehler finden, für die Sie keine Regel geschrieben haben.** Wiederkehrende Audits durchsuchen Ihre Logs sitzungsübergreifend nach Fehler-Clustern, Latenz-Ausreißern, niedrigen Scores und feststeckenden Runs und liefern Ihnen priorisierte, beleggestützte Erkenntnisse.
- **Alarmierung, wenn es darauf ankommt.** Schwellenwertregeln feuern bei Fehlerrate, Latenz, Kosten oder Evaluator-Scores und öffnen Incidents, die Sie bestätigen, zuweisen und auflösen können.
- **Fragen auf Deutsch stellen.** Ein KI-Assistent im Dashboard beantwortet Fragen wie „Wie entwickelt sich die Qualität in Prod diese Woche?" auf Basis Ihrer eigenen Daten. Jede Änderung, die er vornimmt, erfordert eine Genehmigung.
- **Behalten Sie Ihre Daten.** Failproof AI Observability wird selbst gehostet: Ereignisse, Prompts und Analysen bleiben in Ihrer eigenen Infrastruktur.

## Was Sie erhalten

Failproof AI Observability ist um drei Ideen herum aufgebaut (**observe**, **analyze** und **admin**), die sich in der linken Seitenleiste des Dashboards widerspiegeln.

**Observe** (die unverfälschte Wahrheit darüber, was passiert ist):

- **[Event Stream](/de/agenteye/event-stream)**: die live, schrittweise Aufzeichnung jedes Runs (Tool-Aufrufe, Modellaufrufe, Hooks, Fehler).
- **[Sessions](/de/agenteye/sessions)**: diese Ereignisse zu einer Zeile pro Run zusammengefasst, jeweils bereit zur Bewertung, mit einem Git-artigen Ausführungsgraphen.
- **[Performance-Metriken](/de/agenteye/telemetry)**: oberflächenspezifische Latenz-Heatmaps und p50/p95/p99-Vitaldaten für Modelle, Tools und Hooks, sodass ein Tail-Ausreißer vom Median auffällt.
- **[Fehlerverfolgung](/de/agenteye/error-tracking)**: eine einzige Triage-Oberfläche für alles, was schiefgelaufen ist, einen Klick von einem ausgelösten Alert entfernt.

![Die Tools-Observe-Seite: eine Latenz-Heatmap, ein Perzentilband und ein Tool-Verteilungsbalken über 24 Zeitkörbe](/agenteye/images/tools.png)

*Jede Observe-Oberfläche kombiniert eine Sparkline und p50/p95/p99-Vitaldaten mit einer Latenz-Heatmap und einem Perzentilband. Gezeigt: Tools.*

**Analyze** (Aktivitäten in Erkenntnisse umwandeln):

- **[Queries](/de/agenteye/queries)** und **[Dashboards](/de/agenteye/dashboards)**: gespeichertes SQL über Ihre Ereignisse und Evaluierungen, in gemeinsam genutzte, organisationsweite Dashboards eingebettet.
- **[Evaluations](/de/agenteye/evaluations)**: Qualitäts-Scores, die von Ihrem eigenen Evaluator-Dienst erzeugt werden, mit Begründung pro Score.
- **[Audits](/de/agenteye/audits)**: wiederkehrende Untersuchungen, die sitzungsübergreifend Fehlermuster aufdecken.
- **[Alerts](/de/agenteye/alerts)** und **[Incidents](/de/agenteye/incidents)**: Schwellenwertregeln, die Sie alarmieren, plus ein Incident-Workflow zur Triage.

**Interfaces** (erreichen Sie Ihre Daten auf Ihre Weise):

- **[CLI](/de/agenteye/cli-and-agents)**: steuern Sie Ihr gesamtes Deployment vom Terminal oder einem Skript aus, und lassen Sie einen Coding-Agent es auf Englisch für Sie erledigen.
- **[KI-Assistent](/de/agenteye/assistant)**: stellen Sie Fragen zu Ihren Agenten in natürlicher Sprache, direkt im Dashboard.
- **REST API**: alles, was Dashboard und CLI tun, wird durch eine REST API unterstützt, die Sie direkt mit einem bereichsbeschränkten [API-Key](/de/agenteye/api-keys) aufrufen können – Ereignisse erfassen, Sessions und Evaluierungen abfragen sowie Dashboards, Alerts, Audits, Benutzer und Keys verwalten, sodass Sie Failproof AI Observability in Ihr eigenes Tooling integrieren können.

**Admin** (für Ihr Team betreiben):

- **[API-Keys](/de/agenteye/api-keys)**: bereichsbeschränkte Tokens für den Collector, das Dashboard und den Assistenten.
- **Benutzer**: passwortlose, E-Mail-basierte Anmeldung mit einer Allowlist.
- **Einstellungen**: organisationsweite Konfiguration, einschließlich Überschreibungen des Modell-Kontextfensters.

## Wie die Komponenten zusammenpassen

Daten fließen in einer Richtung, von Ihrem Agenten-Code zum Dashboard: Ihr Agent (über das Python SDK) sendet Ereignisse an den agenteye-collector, der sie an den Server weiterleitet, der wiederum das Dashboard bedient. Zwei optionale Dienste ergänzen das Ganze – ein Scoring-Dienst (Evaluierungen) und ein KI-Assistenten-Dienst (der Chat im Dashboard).

- **Python SDK**: Sie fügen Ihrem Agenten einige `agenteye.event.*`-Aufrufe hinzu; Ereignisse werden lokal gepuffert.
- **agenteye-collector**: ein schlanker Daemon auf jedem Agenten-Rechner, der Ereignisse bündelt und an den Server sendet.
- **Server**: nimmt Ihre Ereignisse entgegen, hält den Betriebszustand in Ihren eigenen Datenbanken vor und stellt die REST API bereit, die Dashboard, CLI und Ihre eigenen Integrationen verwenden.
- **Dashboard**: wo Sie alles erkunden.
- **Optionale Dienste**: ein Scoring-Dienst (Evaluierungen) und ein KI-Assistenten-Dienst (der Chat im Dashboard).

Das in der gesamten Dokumentation verwendete Vokabular (*event, session, evaluation, audit, finding, incident*) finden Sie unter [Concepts](/de/agenteye/concepts).
