Stellen Sie Ihren Agentendaten beliebige Fragen und erhalten Sie in Sekunden eine Antwort. Failproof AI Observability bietet Ihnen eine Bibliothek gespeicherter, sofort ausführbarer Abfragen über Ihre Events und Auswertungen – damit starten Sie von einem funktionierenden Beispiel statt vor einem leeren SQL-Editor.

![Die Bibliothek gespeicherter Abfragen: ein Raster wiederverwendbarer Abfragen, sowohl eingebaute Voreinstellungen als auch eigene](/agenteye/images/queries.png)

*Ihre Bibliothek gespeicherter Abfragen unter `/<org-slug>/queries`: eingebaute Voreinstellungen direkt neben den Abfragen, die Ihr Team gespeichert hat.*

## Von einer Vorlage starten, nicht von einer leeren Seite

Sie müssen sich keine Tabellennamen merken oder SQL von Grund auf schreiben. Die Bibliothek öffnet sich mit eingebauten Voreinstellungen für die Fragen, die Teams am häufigsten stellen – direkt neben den Abfragen, die Ihr eigenes Team gespeichert und benannt hat. Wählen Sie eine aus, die Ihrer Anforderung nahekommt, und Sie sind dem Ergebnis bereits sehr nah.

Jede gespeicherte Abfrage ist organisationsweit verfügbar und wird geteilt – die nützlichen Abfragen, die Ihre Kollegen schreiben, stehen also auch Ihnen zur Verfügung. Benennen Sie eine Abfrage und versehen Sie sie einmal mit einer Beschreibung, und jeder in Ihrer Organisation kann sie finden, ausführen oder ihre Ergebnisse später auf einem Dashboard anheften.

Sie finden sie unter `/<org-slug>/queries`.

## Im SQL-Composer anpassen und ausführen

Öffnen Sie eine beliebige Abfrage – sie landet sofort im SQL-Composer, wo Sie sie anpassen und die Antwort unmittelbar sehen können: kein Export, kein Umweg, kein Warten auf andere.

![Der SQL-Abfrage-Composer mit einer laufenden gespeicherten Abfrage, einer Schema-Seitenleiste und einem Live-Ergebnisraster](/agenteye/images/query-lab.png)

*Der SQL-Composer: Ihre Abfrage auf der linken Seite, eine Schema-Seitenleiste damit Sie nie einen Spaltennamen raten müssen, und ein Live-Ergebnisraster darunter.*

- **Eine Schema-Seitenleiste** listet die Analytics-Tabellen und ihre Spalten auf, sodass Sie eine Abfrage gestalten können, ohne nach Feldnamen suchen zu müssen.
- **Ein Live-Ergebnisraster** liefert Zeilen im Moment der Ausführung, sodass Sie in Sekunden iterieren statt endlos zu raten.
- **Schreibgeschützt by Design.** Abfragen werden gegen Ihren Event-Store ausgeführt und serverseitig validiert: Nur `SELECT`- und `WITH`-Anweisungen sind erlaubt, mit einem Anweisungs-Timeout und einer Zeilenobergrenze. Eine Erkundungsabfrage kann Ihre Daten niemals verändern, und eine außer Kontrolle geratene wird automatisch gestoppt.

Zufrieden mit dem Ergebnis? Speichern Sie es zurück in die Bibliothek, damit das gesamte Team davon profitiert, oder heften Sie die Ausgabe als Linien-, Balken-, Flächen- oder Kuchendiagramm-Kachel auf ein Dashboard.

## Vom Terminal aus ausführen oder vom Assistenten schreiben lassen

Dieselben gespeicherten Abfragen begleiten Sie überall, wo Sie arbeiten:

- **Vom Terminal aus.** Die `agenteye`-CLI listet, führt aus und speichert exakt dieselben Abfragen, sodass Sie ein Ergebnis in ein Skript einfügen, in CI integrieren oder an einen Coding-Agenten weitergeben können.

```bash
agenteye query list                 # die gleichen gespeicherten Abfragen, vom Terminal aus
agenteye query run errs --arg prod  # eine ausführen und die Zeilen ausgeben (--json zum Weiterleiten hinzufügen)
```

  Siehe [CLI and agents](/de/agenteye/cli-and-agents) für den vollständigen Befehlssatz.

- **Vom KI-Assistenten.** Nicht sicher, wie Sie das SQL formulieren sollen? Fragen Sie den [KI-Assistenten](/de/agenteye/assistant) im Dashboard auf normalem Deutsch – er entwirft die Abfrage und speichert sie für Sie in Ihrer Bibliothek.

Das Ausführen einer gespeicherten Abfrage ist durch die Berechtigung `queries:run` abgesichert, die getrennt von den Berechtigungen zum Erstellen oder Löschen von Abfragen gehalten wird – so können Sie Lesezugriff gewähren, ohne dass jeder die Bibliothek umschreiben kann.
