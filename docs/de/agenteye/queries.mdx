Stellen Sie beliebige Fragen zu Ihren Agent-Daten und erhalten Sie in Sekunden eine Antwort. Failproof AI Observability bietet Ihnen eine Bibliothek mit gespeicherten, sofort ausführbaren Abfragen über Ihre Events und Auswertungen – damit starten Sie mit einem funktionierenden Beispiel statt vor einem leeren SQL-Editor.

![Die Bibliothek gespeicherter Abfragen: ein Raster wiederverwendbarer Abfragen, sowohl eingebaute Voreinstellungen als auch eigene](/agenteye/images/queries.png)

*Ihre Bibliothek gespeicherter Abfragen unter `/<org-slug>/queries`: eingebaute Voreinstellungen neben den Abfragen, die Ihr Team gespeichert hat.*

## Mit einer Vorlage starten, nicht mit einer leeren Seite

Sie müssen sich keine Tabellennamen merken oder SQL von Grund auf neu schreiben. Die Bibliothek öffnet sich mit eingebauten Voreinstellungen für die Fragen, die Teams am häufigsten stellen – direkt neben den Abfragen, die Ihr Team gespeichert und benannt hat. Wählen Sie eine aus, die Ihrem Ziel nahekommt, und Sie sind dem Ergebnis schon einen großen Schritt nähergekommen.

Jede gespeicherte Abfrage ist organisations-weit gültig und geteilt – nützliche Abfragen Ihrer Kollegen stehen also auch Ihnen zur Verfügung. Benennen Sie eine Abfrage und geben Sie ihr einmal eine Beschreibung, und alle in Ihrer Organisation können sie finden, ausführen oder ihre Ergebnisse später auf einem Dashboard anheften.

Zu finden unter `/<org-slug>/queries`.

## Im SQL-Composer anpassen und ausführen

Öffnen Sie eine beliebige Abfrage und sie wird im SQL-Composer geladen, wo Sie sie anpassen und die Antwort sofort sehen können – kein Export, kein Hin-und-Her, kein Warten auf andere.

![Der SQL-Abfrage-Composer mit einer gespeicherten Abfrage, einer Schema-Seitenleiste und einem Live-Ergebnisraster](/agenteye/images/query-lab.png)

*Der SQL-Composer: Ihre Abfrage links, eine Schema-Seitenleiste damit Sie nie einen Spaltennamen raten müssen, und ein Live-Ergebnisraster darunter.*

- **Eine Schema-Seitenleiste** listet die Analysetabellen und ihre Spalten auf, sodass Sie eine Abfrage gestalten können, ohne nach Feldnamen suchen zu müssen.
- **Ein Live-Ergebnisraster** gibt Zeilen zurück, sobald Sie die Abfrage ausführen – iterieren Sie in Sekunden statt immer wieder zu raten.
- **Schreibgeschützt by Design.** Abfragen werden gegen Ihren Event-Speicher ausgeführt und auf dem Server validiert: Nur `SELECT`- und `WITH`-Anweisungen sind erlaubt, mit einem Statement-Timeout und einer Zeilenobergrenze. Eine explorative Abfrage kann Ihre Daten nie verändern, und eine unkontrolliert laufende wird für Sie gestoppt.

Mit dem Ergebnis zufrieden? Speichern Sie es zurück in die Bibliothek, damit das gesamte Team davon profitiert, oder heften Sie die Ausgabe als Linien-, Balken-, Flächen- oder Tortendiagramm-Kachel auf ein Dashboard.

## Vom Terminal aus ausführen oder vom Assistenten schreiben lassen

Dieselben gespeicherten Abfragen begleiten Sie überall:

- **Vom Terminal aus.** Das `agenteye`-CLI listet, führt aus und speichert genau dieselben Abfragen, sodass Sie ein Ergebnis in ein Skript einbetten, in CI einbinden oder an einen Coding-Agent weitergeben können.

```bash
agenteye query list                 # die gleichen gespeicherten Abfragen, vom Terminal aus
agenteye query run errs --arg prod  # eine ausführen und die Zeilen ausgeben (--json zum Weiterleiten hinzufügen)
```

  Den vollständigen Befehlssatz finden Sie unter [CLI und Agents](/de/agenteye/cli-and-agents).

- **Vom KI-Assistenten.** Nicht sicher, wie Sie das SQL formulieren sollen? Fragen Sie den integrierten [KI-Assistenten](/de/agenteye/assistant) im Dashboard auf natürlichem Deutsch, und er entwirft die Abfrage und speichert sie für Sie in Ihrer Bibliothek.

Das Ausführen einer gespeicherten Abfrage ist durch die Berechtigung `queries:run` geschützt, die getrennt von den Berechtigungen zum Erstellen oder Löschen von Abfragen verwaltet wird – so können Sie Lesezugriff gewähren, ohne allen die Möglichkeit zu geben, die Bibliothek zu verändern.
