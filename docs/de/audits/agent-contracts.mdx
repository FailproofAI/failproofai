Der Agentenkontext teilt Audits mit, wofür ein Agent existiert, was er produzieren muss und was er niemals tun darf. Failproof AI speichert diesen Kontext als einen Agenten-Vertrag pro Agent.

Der Agentenkontext gehört zur Organisation, nicht zu einem einzelnen Audit. Sie schreiben ihn einmal pro Agent, und jedes modellgestützte Audit, dessen Umfang diesen Agenten einschließt, verwendet ihn.

## Agentenkontext hinzufügen

<Tabs>
  <Tab title="Dashboard">
    1. Gehen Sie zu **Analyze → audits**, wählen Sie **agents** und wählen Sie die Agenten-ID aus, die von seinen Sitzungen gemeldet wird.
    2. Wählen Sie **add content** oder **edit**.
    3. Beschreiben Sie, wofür der Agent gedacht ist, was er produzieren muss, was „abgeschlossen" bedeutet, wie oft er ausgeführt werden soll und was er niemals tun darf.
    4. Speichern Sie den Kontext, kehren Sie dann zum Audit-Formular zurück und bestätigen Sie, dass der ausgewählte Agent als abgedeckt angezeigt wird.

    ![Die Agents-Schublade des Audits, mit der Zweck, Häufigkeit, Ausgaben, Abschlussbedingungen und verbotenes Verhalten für einen Agenten hinzugefügt werden können.](/images/dashboard/agent-context.png)

    Sie können den Agentenkontext auch über die **agents**-Schublade hinzufügen oder bearbeiten, während Sie ein Audit erstellen oder bearbeiten. Er wird unabhängig gespeichert und ist sofort für jedes anwendbare Audit verfügbar.
  </Tab>
  <Tab title="CLI">
    Das Cloud CLI stellt noch keine Vertragsbefehle bereit. Verwenden Sie die öffentliche API mit einem Schlüssel, der `audits:read` und `audits:write` besitzt:

    ```bash
    curl -X POST "https://app.befailproof.ai/v1/audits/contracts" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "agent_id": "nightly-reconciler",
        "enabled": true,
        "body": "# Purpose\nReconcile yesterday's payouts.\n\n## Outputs\nPublish a signed summary.\n\n## Must not\nNever modify ledger entries."
      }'
    ```

    Listen Sie Verträge mit `GET /v1/audits/contracts` auf; rufen Sie einen einzelnen Vertrag mit `GET /v1/audits/contracts/{id}` ab. Eine Aktualisierung mit `PUT` ist ein vollständiger Ersatz und erfordert sowohl `agent_id` als auch `body`.
  </Tab>
</Tabs>

## Nützlichen Kontext schreiben

Halten Sie den Kontext unter 5.000 Zeichen und gestalten Sie ihn testbar. Nützlicher Kontext enthält in der Regel:

- **Zweck:** warum der Agent existiert
- **Ausgaben:** Artefakte oder Aktionen, die er produzieren muss
- **Abgeschlossen, wenn:** die Bedingung, die einen Lauf als erfolgreich einstuft
- **Häufigkeit:** wie oft oder wann er ausgeführt werden soll
- **Darf nicht:** Aktionen und Ergebnisse, die immer unakzeptabel sind

```markdown
---
agent: nightly-reconciler
purpose: Reconcile yesterday's payouts and publish a signed summary.
cadence: Once daily after 02:00 UTC. Never more than once.
---

## Outputs
- A signed reconciliation summary in the finance channel.

## Done when
- Every payout is matched or explicitly flagged.

## Must not
- Modify ledger entries. Report discrepancies instead.
```

Der Agentenkontext beschreibt das erwartete Verhalten; er kann der Analyse nicht vorschreiben, zu welchem Ergebnis sie gelangen soll oder welche Beweise sie untersuchen darf. Agenten ohne Kontext werden normal auditiert, aber Failproof AI kann ihr Verhalten nicht anhand organisationsspezifischer Absichten beurteilen.

## Agentenkontext pausieren oder ändern

- Pausieren Sie den Agentenkontext, wenn Audits ihn vorübergehend ignorieren sollen. Das Pausieren ist umkehrbar.
- Bearbeiten Sie den Kontext, wenn sich die Verantwortung des Agenten ändert. Der neue Text gilt für zukünftige Läufe.
- Prüfen Sie **last matched**, wenn ein laufender Agent seinen Kontext scheinbar nie verwendet. Dies bedeutet in der Regel, dass seine Agenten-ID nicht mit der Telemetrie übereinstimmt.
- Löschen Sie über die API nur dann, wenn der Text dauerhaft vernichtet werden muss. Das Dashboard bietet absichtlich „Pausieren" statt „Löschen" an.

Jeder Audit-Lauf speichert die genaue Agentenkontext-Momentaufnahme, die er verwendet hat. Das Bearbeiten, Pausieren oder Löschen der aktuellen Vertragsressource überschreibt nicht die Grundlage früherer Erkenntnisse.

<Info>
  Für das Lesen von Verträgen ist `audits:read` erforderlich. Für das Erstellen, Bearbeiten, Pausieren oder Löschen wird `audits:write` benötigt.
</Info>
