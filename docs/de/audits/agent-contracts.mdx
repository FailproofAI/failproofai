Der Agenten-Kontext teilt Audits mit, wofür jeder Agent existiert, was er produzieren muss und was er niemals tun darf. Failproof AI speichert diesen Kontext als einen Agenten-Vertrag pro Agent.

Der Agenten-Kontext gehört zur Organisation, nicht zu einem einzelnen Audit. Du schreibst ihn einmal pro Agent, und jedes modellgestützte Audit, dessen Umfang diesen Agenten einschließt, verwendet ihn.

## Agenten-Kontext hinzufügen

<Tabs>
  <Tab title="Dashboard">
    1. Gehe zu **Analyse → Audits**, wähle **Agents** und wähle die Agent-ID aus, die von seinen Sitzungen gemeldet wird.
    2. Wähle **Inhalt hinzufügen** oder **Bearbeiten**.
    3. Beschreibe, wofür der Agent gedacht ist, was er produzieren muss, was „fertig" bedeutet, wie oft er ausgeführt werden soll und was er niemals tun darf.
    4. Speichere den Kontext, kehre dann zum Audit-Formular zurück und bestätige, dass der ausgewählte Agent als abgedeckt angezeigt wird.

    ![Das Agents-Drawer des Audits, mit dem Zweck, Kadenz, Ausgaben, Abschlussbedingungen und verbotenes Verhalten für einen Agenten hinzugefügt werden.](/images/dashboard/agent-context.png)

    Du kannst den Agenten-Kontext auch über das **Agents**-Drawer hinzufügen oder bearbeiten, während du ein Audit erstellst oder bearbeitest. Er wird unabhängig gespeichert und ist sofort für jedes zutreffende Audit verfügbar.
  </Tab>
  <Tab title="CLI">
    Die Cloud-CLI stellt noch keine Vertrags-Befehle bereit. Verwende die öffentliche API mit einem Schlüssel, der `audits:read` und `audits:write` besitzt:

    ```bash
    curl -X POST "https://app.befailproof.ai/v1/audits/contracts" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "agent_id": "nightly-reconciler",
        "enabled": true,
        "body": "# Purpose\nReconcile yesterday's payouts.\n\n## Outputs\nPublish a signed summary.\n\n## Must not\nNever modify ledger entries."
      }'
    ```

    Verträge auflisten mit `GET /v1/audits/contracts`; einen einzelnen Vertrag abrufen mit `GET /v1/audits/contracts/{id}`. Das Aktualisieren mit `PUT` ist ein vollständiger Ersatz und erfordert sowohl `agent_id` als auch `body`.
  </Tab>
</Tabs>

## Nützlichen Kontext schreiben

Halte den Kontext unter 5.000 Zeichen und gestalte ihn überprüfbar. Nützlicher Kontext enthält in der Regel:

- **Zweck:** warum der Agent existiert
- **Ausgaben:** Artefakte oder Aktionen, die er produzieren muss
- **Fertig, wenn:** die Bedingung, die eine Ausführung erfolgreich macht
- **Kadenz:** wie oft oder wann er ausgeführt werden soll
- **Darf nicht:** Aktionen und Ergebnisse, die immer inakzeptabel sind

```markdown
---
agent: nightly-reconciler
purpose: Reconcile yesterday's payouts and publish a signed summary.
cadence: Once daily after 02:00 UTC. Never more than once.
---

## Outputs
- A signed reconciliation summary in the finance channel.

## Done when
- Every payout is matched or explicitly flagged.

## Must not
- Modify ledger entries. Report discrepancies instead.
```

Der Agenten-Kontext beschreibt das erwartete Verhalten; er kann der Analyse nicht vorschreiben, zu welchem Schluss sie kommen soll, oder einschränken, welche Belege sie untersucht. Agents ohne Kontext werden normal geprüft, aber Failproof AI kann ihr Verhalten nicht an organisationsspezifischen Absichten messen.

## Agenten-Kontext pausieren oder ändern

- Pausiere den Agenten-Kontext, wenn Audits ihn vorübergehend ignorieren sollen. Das Pausieren ist umkehrbar.
- Bearbeite den Kontext, wenn sich die Verantwortlichkeit des Agenten ändert. Der neue Text gilt für zukünftige Ausführungen.
- Überprüfe **Zuletzt abgeglichen**, wenn ein laufender Agent seinen Kontext scheinbar nie verwendet. Dies bedeutet normalerweise, dass seine Agent-ID nicht mit der Telemetrie übereinstimmt.
- Lösche über die API nur dann, wenn der Text dauerhaft vernichtet werden muss. Das Dashboard bietet absichtlich „Pausieren" statt „Löschen" an.

Jede Audit-Ausführung speichert den genauen Agenten-Kontext-Snapshot, den sie verwendet hat. Das Bearbeiten, Pausieren oder Löschen der aktuellen Vertrags-Ressource überschreibt nicht die Grundlage früherer Erkenntnisse.

<Info>
  Das Lesen von Verträgen erfordert `audits:read`. Das Erstellen, Bearbeiten, Pausieren oder Löschen erfordert `audits:write`.
</Info>
