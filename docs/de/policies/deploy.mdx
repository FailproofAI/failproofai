Deploye eine geprüfte Policy schrittweise auf eine Maschine nach der anderen. Beginne im Beobachtungsmodus.

## Rollout über die CLI

```bash
fp policies test ./rule.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish no-force-push ./rule.mjs
fp fleet deploy <machine> --add no-force-push:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add no-force-push:enforce
```

Der Beobachtungsmodus wertet die echte Policy aus und protokolliert Nicht-Allow-Entscheidungen, blockiert den Agenten jedoch nicht.

<Warning>
  Ein einfaches `--add no-force-push` setzt die Policy sofort durch. Füge `:observe` für einen Shadow-Rollout hinzu.
</Warning>

Falls die Durchsetzung Probleme verursacht:

```bash
fp fleet history <machine>
fp fleet rollback <machine> <generation>
```

## Deployment über das Dashboard

1. Gehe zu **Admin → Enforcement**.
2. Öffne die Zielmaschine.
3. Füge die Policy-Version mit dem Effekt **observe** hinzu.
4. Wende das Deployment an.
5. Überprüfe die Ergebnisse unter **Observe → Policy**.
6. Hebe dieselbe Version auf **enforce** an, wenn die Treffer korrekt sind.

![Der Maschinen-Deployment-Editor mit Policy-Versionen, Enforce- und Observe-Effekten sowie der Aktion zum Anwenden des Deployments.](/images/dashboard/enforcement-editor.png)

## Ein Set ersetzen oder vorab einrichten

- `--remove <id>` entfernt eine einzelne Policy.
- `--set <ref>...` ersetzt das komplette Policy-Set.
- `--create` bereitet ein Deployment vor, bevor eine Maschine sich erstmals einbucht.
- `fp fleet diff <machine>` vergleicht den beabsichtigten und den angewendeten Zustand.

<Note>
  Ohne Cloud veröffentlichst du ein Pack mit `failproofai publish --effect observe` und prüfst Entscheidungen im lokalen Dashboard.
</Note>

Maschinen benötigen `policies:pull`, um Deployments zu empfangen, und `events:add`, um Entscheidungen zu melden.
