Die Flottenabdeckung vergleicht, was Cloud zugewiesen hat, mit dem, was jede Maschine zuletzt angewendet hat.

## Eine Maschine prüfen

```bash
failproofai config --status
failproofai flush --wait --timeout 120
```

Über Cloud:

```bash
fp fleet list
fp fleet diff
fp fleet show <machine-id>
```

`fp fleet` erfordert eine angemeldete Sitzung, keinen API-Schlüssel.

| Befehl | Funktion |
| --- | --- |
| `fp fleet list` | Maschinen und Deployment-Status auflisten |
| `fp fleet show <machine>` | Policy-Set einer Maschine anzeigen |
| `fp fleet deploy <machine> --add <ref>` | Eine Policy hinzufügen oder aktualisieren |
| `fp fleet deploy <machine> --remove <id>` | Eine Policy entfernen |
| `fp fleet deploy <machine> --set <ref>...` | Das gesamte Set ersetzen |
| `fp fleet diff [machine]` | Vorgesehene und angewendete Versionen vergleichen |
| `fp fleet history <machine>` | Deployment-Generationen auflisten |
| `fp fleet rollback <machine> <generation>` | Eine Generation wiederherstellen |
| `fp fleet rename <machine> "<label>"` | Das Cloud-Label ändern |

<Warning>
  `--set` ersetzt das vollständige Policy-Set. Ein einfaches `--add <id>` setzt eine neue Policy sofort durch. Verwenden Sie `--add <id>:observe` für ein schrittweises Rollout im Beobachtungsmodus.
</Warning>

## Beobachten, dann durchsetzen

```bash
fp fleet deploy ci-runner-01 --add prod-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add prod-guard:enforce
```

Der Beobachtungsmodus wertet die tatsächliche Policy aus und zeichnet Nicht-allow-Entscheidungen auf, ohne den Agenten zu blockieren.

## Maschinenidentität

Die Maschinen-ID ist unveränderlich und identifiziert die Maschine eindeutig. Das Label dient nur der Anzeige und kann geändert werden:

```bash
failproofai config --machine-label checkout-runner-03
fp fleet rename <machine-id> "Checkout runner 03"
```

Das Ändern des Labels stellt keine neue Verbindung her und erneuert keinen Schlüssel für die Maschine.
