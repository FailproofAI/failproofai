Jev liest einen Tool-Aufruf im Kontext dessen, was die Person den Agenten zu tun gebeten hat. Verwende es, wenn eine Richtlinie auf Basis von String-Matching gültige Arbeit blockiert oder eine riskante Aktion übersieht, die Kontext erfordert. Es antwortet zusammen mit deinen Richtlinien am `PreToolUse`- oder `PermissionRequest`-Gate. Für eine Bewertung **nach** dem Ende einer Sitzung verwendest du [Jev evaluations](/de/evaluations/jev).

## Im Beobachtungsmodus starten

Installiere Failproof AI und hänge Hooks an ein [unterstütztes Harness](/de/reference/harnesses) an. Verwende failproofai 1.0.8-beta.0 oder neuer.

Failproof AI enthält keine Jev-Prüfungen. Installiere sie als Paket, da Jev sonst nichts zu prüfen hat und nie aufgerufen wird:

```bash
failproofai policies add FailproofAI/jev-policies
```

Wähle dann, wie Anfragen Jev erreichen:

| Route | Erster Schritt |
| --- | --- |
| FailproofAI Cloud | Verbinde dich mit einem **Machine**-Schlüssel, der `jev:evaluate` enthält. Auf einem Computer ohne Jev-Konfiguration aktiviert `failproofai config` Jev im Beobachtungsmodus. |
| Eigener Anbieter | Öffne im lokalen Dashboard **Settings → Jev**, wähle den Anbieter, füge seinen Token ein und wähle **observe**. Oder führe `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key` aus. |

![Die Jev-Einstellungen im lokalen Dashboard: Anbieter, Endpunkt, Token und Beobachtungsmodus, bevor Jev aktiviert wird.](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` prüft den Endpunkt. Um den Hook-Pfad zu überprüfen, bitte einen mit Hooks versehenen Agenten, sein Datei-Lese-Tool auf `README.md` anzuwenden. Stelle sicher, dass dieser Tool-Aufruf in der Sitzung erscheint, und prüfe dann **Policies → Activity** im [lokalen Dashboard](/de/reference/local-dashboard#review-policy-activity). Der Jev-Zähler in `status` sollte steigen. Der Beobachtungsmodus zeichnet auf, was Jev entschieden hätte, während das bisherige Richtlinienergebnis weiterhin gilt.

## Entscheiden, wann durchgesetzt wird

Eine **harte** Richtlinie hat immer das letzte Wort. Jev kann eine Ablehnung nur bei einer Richtlinie aufheben, die ausdrücklich als **reviewable** markiert ist, und nur dann, wenn die betreffende Richtlinie die benannte Concern geprüft hat. Lies [policy authority](/de/policies/authority), bevor du dich auf eine Freigabe verlässt. Jev kann auch eigenständig warnen oder ablehnen. Wenn es keine Antwort geben kann, entscheidet das Richtlinienergebnis über diesen Aufruf.

Sobald die Beobachtungsergebnisse korrekt aussehen, wechselst du in **Settings → Jev** in den Durchsetzungsmodus oder führst Folgendes aus:

```bash
failproofai jev setup --mode enforce
```

Informationen zu Anbieter-URLs, Cloud-Schlüsseln, Konfiguration, Fallbacks und den mit jeder Anfrage gesendeten Daten findest du in der [Jev-Integrationsreferenz](/de/reference/jev).
