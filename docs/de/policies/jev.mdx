Jev liest einen Tool-Aufruf im Kontext dessen, was die Person den Agenten zu tun gebeten hat. Verwende es, wenn eine auf Zeichenkettenabgleich basierende Policy valide Arbeit blockiert oder eine riskante Aktion übersieht, die Kontext erfordert. Es antwortet zusammen mit deinen Policies am `PreToolUse`- oder `PermissionRequest`-Gate. Für eine Bewertung **nach** dem Ende einer Sitzung verwende [Jev evaluations](/de/evaluations/jev).

## Im Beobachtungsmodus starten

Installiere Failproof AI und hänge Hooks an ein [unterstütztes Harness](/de/reference/harnesses) an. Verwende failproofai 1.0.8-beta.0 oder neuer.

Failproof AI enthält keine Jev-Prüfungen. Installiere sie als Pack, sonst hat Jev nichts zu überprüfen und wird nie aufgerufen:

```bash
failproofai policies add FailproofAI/jev-policies
```

Wähle dann, wie Anfragen Jev erreichen:

| Route | Erster Schritt |
| --- | --- |
| FailproofAI Cloud | Verbinde dich mit einem **Machine**-Key, der `jev:evaluate` besitzt. Auf einer Maschine ohne Jev-Konfiguration schaltet `failproofai config` Jev im Beobachtungsmodus ein. |
| Eigener Anbieter | Öffne im lokalen Dashboard **Settings → Jev**, wähle den Anbieter, füge dessen Token ein und wähle **observe**. Oder führe `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key` aus. |

![Die Jev-Einstellungen des lokalen Dashboards: Anbieter, Endpunkt, Token und Beobachtungsmodus, bevor Jev aktiviert wird.](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` prüft den Endpunkt. Um den Hook-Pfad zu überprüfen, bitte einen mit Hooks versehenen Agenten, sein Dateilesewerkzeug auf `README.md` anzuwenden. Bestätige, dass dieser Tool-Aufruf in der Sitzung erscheint, und inspiziere dann **Policies → Activity** im [lokalen Dashboard](/de/reference/local-dashboard#review-policy-activity). Der Jev-Zähler in `status` sollte sich erhöhen. Der Beobachtungsmodus zeichnet auf, wie Jev entschieden hätte, während dein bestehendes Policy-Ergebnis weiterhin gilt.

## Entscheiden, wann durchgesetzt wird

Eine **harte** Policy hat immer das letzte Wort. Jev kann ein Deny nur von einer Policy aufheben, die explizit als **reviewable** markiert ist, und nur wenn es das benannte Anliegen dieser Policy geprüft hat. Lies [policy authority](/de/policies/authority), bevor du dich auf eine Freigabe verlässt. Jev kann auch eigenständig warnen oder ablehnen. Kann es nicht antworten, entscheidet das Policy-Ergebnis über diesen Aufruf.

Sobald die Beobachtungsergebnisse korrekt aussehen, wechsle in **Settings → Jev** in den Durchsetzungsmodus oder führe aus:

```bash
failproofai jev setup --mode enforce
```

Informationen zu Anbieter-URLs, Cloud-Keys, Konfiguration, Fallbacks und den mit jeder Anfrage gesendeten Daten findest du in der [Jev-Integrationsreferenz](/de/reference/jev).
