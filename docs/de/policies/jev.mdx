Jev liest einen Tool-Aufruf im Kontext dessen, was die Person dem Agenten aufgetragen hat. Nutze es, wenn eine auf String-Matching basierende Richtlinie gültige Arbeit blockiert oder eine riskante Aktion übersieht, die Kontext erfordert. Es antwortet zusammen mit deinen Richtlinien am `PreToolUse`- oder `PermissionRequest`-Gate. Für eine Bewertung **nach** dem Ende einer Sitzung verwende [Jev-Evaluierungen](/de/evaluations/jev).

## Im Beobachtungsmodus starten

Installiere Failproof AI und hänge Hooks an ein [unterstütztes Harness](/de/reference/harnesses). Verwende failproofai 1.0.8-beta.0 oder höher.

Failproof AI enthält keine Jev-Prüfungen. Installiere sie als Paket, andernfalls hat Jev nichts zu prüfen und wird niemals aufgerufen:

```bash
failproofai policies add FailproofAI/jev-policies
```

Wähle anschließend, wie Anfragen Jev erreichen:

| Route | Erster Schritt |
| --- | --- |
| FailproofAI Cloud | Verbinde dich mit einem **Machine**-Schlüssel, der `jev:evaluate` enthält. Auf einem Rechner ohne Jev-Konfiguration aktiviert `failproofai config` Jev im Beobachtungsmodus. |
| Eigener Anbieter | Öffne im lokalen Dashboard **Einstellungen → Jev**, wähle den Anbieter, füge dessen Token ein und wähle **observe**. Oder führe aus: `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key`. |

![Die Jev-Einstellungen im lokalen Dashboard: Anbieter, Endpunkt, Token und Beobachtungsmodus, bevor Jev aktiviert wird.](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` prüft den Endpunkt. Um den Hook-Pfad zu überprüfen, bitte einen angebundenen Agenten, sein Datei-Lese-Tool auf `README.md` anzuwenden. Stelle sicher, dass dieser Tool-Aufruf in der Sitzung erscheint, und prüfe dann **Richtlinien → Aktivität** im [lokalen Dashboard](/de/reference/local-dashboard#review-policy-activity). Der Jev-Zähler in `status` sollte sich erhöhen. Der Beobachtungsmodus zeichnet auf, was Jev entschieden hätte, während dein bestehendes Richtlinienergebnis weiterhin gilt.

## Entscheiden, wann durchgesetzt werden soll

Eine **harte** Richtlinie hat immer das letzte Wort. Jev kann ein Deny nur bei einer Richtlinie aufheben, die ausdrücklich als **reviewable** markiert ist, und nur wenn sie das benannte Anliegen dieser Richtlinie geprüft hat. Lies [Richtlinien-Autorität](/de/policies/authority), bevor du dich auf eine Freigabe verlässt. Jev kann auch eigenständig warnen oder ablehnen. Wenn es keine Antwort geben kann, entscheidet das Richtlinienergebnis diesen Aufruf.

Sobald die Beobachtungsergebnisse korrekt aussehen, wechsle in den Durchsetzungsmodus unter **Einstellungen → Jev** oder führe aus:

```bash
failproofai jev setup --mode enforce
```

Für Anbieter-URLs, Cloud-Schlüssel, Konfiguration, Fallbacks und die mit jeder Anfrage gesendeten Daten siehe die [Jev-Integrationsreferenz](/de/reference/jev).
