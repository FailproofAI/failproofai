Erstelle eine funktionierende Richtlinie, teste sie lokal und veröffentliche sie dann als Pack.

## Erstellen und testen

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

`--init` erstellt eine Richtlinie, die `git push --force` bereits blockiert. Bearbeite sie, weise deinen Agenten an, die blockierte Aktion auszuführen, und überprüfe **Policies → Activity** im lokalen Dashboard.

Eine Pack-Richtlinie kann Folgendes enthalten:

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-refunds",
  description: "Refunds above the limit need a human",
  category: "Billing",
  defaultEnabled: true,
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) => {
    // return allow(), instruct(), or deny()
  },
});
```

`defaultEnabled` hat standardmäßig den Wert `false`.

## Veröffentlichen

Committe deine Dateien und führe dann aus:

```bash
failproofai publish
```

Publish findet die Richtliniendatei, validiert sie mit demselben Loader, der bei der Installation verwendet wird, und lädt die Pack-Assets in ein GitHub-Release hoch. Es verwendet `GITHUB_TOKEN`, `GH_TOKEN` oder `gh auth login`.

Das Repository muss öffentlich sein, da die Installation anonymes HTTPS verwendet.

Die Standardversion ist der 12-stellige SHA des aktuellen Commits. Publish lehnt einen unsauberen Tree oder ein Verzeichnis außerhalb von Git ab, es sei denn, du gibst `--version` an. Ein Tag auf `HEAD` hat Vorrang vor dem SHA.

Benutzer installieren es mit:

```bash
failproofai policies add owner/repo
```

## Im Observe-Modus veröffentlichen

```bash
failproofai publish --effect observe
```

Der Observe-Modus wertet die echte Richtlinie aus und zeichnet Entscheidungen auf, die kein allow sind, lässt den Agenten jedoch weitermachen. Ein Timeout wird als allow gewertet.

Veröffentliche erneut mit `--effect enforce`, wenn die beobachteten Treffer korrekt sind.

## Nützliche Optionen

| Flag | Wirkung |
| --- | --- |
| `--init [file]` | Erstellt eine Einstiegsrichtlinie |
| `--repo <owner>/<repo>` | Repository auswählen oder erstellen |
| `--version <version>` | Die commit-basierte Version überschreiben |
| `--effect enforce|observe` | Festlegen, ob das Pack blockiert |
| `--dry-run` | Erstellen und validieren ohne zu veröffentlichen |
| `--allow-private` | Privat veröffentlichen, in dem Wissen, dass `policies add` es nicht installieren kann |

```bash
failproofai publish --dry-run
failproofai publish ./guards.mjs --repo me/guards --version 2.0.0
```

<Note>
  Füge das GitHub-Topic `failproofai-policies` nach der Veröffentlichung hinzu, damit der [Policy Hub](https://befailproof.ai/policy-hub/) das Pack indizieren kann. Die CLI setzt es nicht automatisch für dich.
</Note>

<Warning>
  Das Umbenennen einer Richtlinie ist eine Breaking Change für bestehende Auswahlen. Halte Namen über Releases hinweg stabil.
</Warning>
