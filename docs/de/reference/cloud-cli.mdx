Verwende `fp`, um Cloud-Telemetrie zu untersuchen, cloud-verwaltete Durchsetzung (Policies, Fleet-Deployments, Guardrail-Entscheidungen) zu verwalten sowie Audits, Findings, Issues, Alerts, Schlüssel, Benutzer, Abfragen und Einstellungen zu administrieren. Verwende [`failproofai`](/de/reference/failproof-cli) für lokale Hooks, Policies, Capture und Machine-Enrollment.

Du kannst außerdem gehosteten Code, LLM-Judge- und Jev-Evaluatoren erstellen und deployen, Dashboards verwalten, Sentiment analysieren und den Dashboard-Assistenten direkt vom Terminal aus nutzen.

Installiere das veröffentlichte Cloud CLI als isoliertes Tool:

```bash
uv tool install fp-cloud-cli
fp version
```

## Anmelden

```bash
fp login
fp whoami
```

## Syntax

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Globale Optionen müssen vor dem Befehl angegeben werden:

```bash
fp --json sessions --since 24h
```

Führe `fp COMMAND --help` oder `fp COMMAND SUBCOMMAND --help` aus, um Terminal-Hilfe zu erhalten.

## CLI-Befehle

### Einen Evaluator erstellen

`fp evaluators` erstellt Definitionen; `fp evals` liest Ergebnisse. Eine aktivierte verwaltete Instanz ist erforderlich (`fp evaluators instances`). Für das Erstellen wird `evaluations:trigger` benötigt; Session-Trockendurchläufe und Schema-Profiling erfordern zusätzlich `events:read`.

Code ist ein eingeschränkter Python-Ausdruck. Speichere dies als `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM-Judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev Binary und benotetes Rubric:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
Beim Erstellen wird der Evaluator aktiviert. Deploy erstellt eine neue unveränderliche Version und deaktiviert dann ältere aktivierte Versionen. Ein fehlgeschlagener Folgeschritt hinterlässt die neue Version als veröffentlicht: Prüfe `evaluators list --all` bevor du es erneut versuchst.
Judge-Trockendurchläufe werden von Cloud abgelehnt. Jev-Trockendurchläufe verbrauchen Modellbudget.
Backfill deckt Code-, Judge- und Jev-Evaluatoren ab und akzeptiert maximal 90 Tage; es werden nur Sessions eingereiht, die ein Evaluator noch nicht bewertet hat. Judge- und Jev-Backfills verbrauchen Modellbudget, führe daher zuerst `fp evaluators backfill --dry-run` aus.
Die menschenlesbare Ausgabe zeigt Trockendurchlauf-Ergebnisse pro Session, bevor etwas erstellt/deployt wird.
Fehlgeschlagene Vorschauen stoppen den Schreibvorgang, es sei denn, du übergibst nach der Überprüfung explizit `--force`.
</Warning>

KI-gestütztes Entwerfen erfordert `fp login` und schreibt eine Spezifikation, die von create/deploy akzeptiert wird:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Befehl | Optionen / Verhalten |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Vollständige Quelle/Envelope |
| `fp evaluators create` | `--key`, `--name`, `--version`, wiederholtes `--label`, `--condition EXPR\|@file`, eine Quelle, wiederholtes `--dry-run-on`, `--disabled`, explizites `--force` für fehlgeschlagene Vorschauen |
| `fp evaluators deploy KEY` | Dieselben Quell-Flags; `--version`, `--backfill 7d` (beliebige Art, 1–90 Tage), `--force`; numerische Versionen werden automatisch erhöht; KEY ergänzt einen fehlenden Spec-File `eval_key` |
| `fp evaluators draft "intent"` | Session; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Quell-Flags oder `--file`, wiederholtes `--session` (maximal 10); keine = nur kompilieren |
| `fp evaluators enable\|disable KEY[@VERSION]` | Umschalten |
| `fp evaluators label KEY[@VERSION]` | Wiederholtes `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | Verwaltete Fleet/Schema/Jobs untersuchen |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; Code, Judge und Jev |

Code-Flags sind `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. Judge-Flags sind `--judge --criteria TEXT`, wiederholtes `--step` und
`--threshold`. Jev-Flags sind `--jev noul --instructions --true --false` oder
`--jev score --instructions` mit 3–5 verschiedenen `--level`-Werten, schlechtester zuerst.
Judge/Jev erfordern einen Score; Schwellenwerte liegen zwischen 0–1. Binäre Judge-Steps werden abgelehnt.

Spec-Dateien enthalten genau `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
Judge/Jev `evaluator_source` ist ein JSON-Envelope-String. Zeilen-IDs, Aktivierungsstatus oder KI-Reasoning-Metadaten dürfen nicht enthalten sein. `--file` und diskrete Spec-Flags schließen sich gegenseitig aus; deploy kann die Version der Datei überschreiben. Ausgabedateien werden nie überschrieben.

### Neue Dashboard-Steuerelemente

Alle Befehle akzeptieren globales `--json`. Unbekannte-Route-404s beenden sich mit Exit-Code 6 und der Meldung „not available on this FailproofAI Cloud yet". Fehlender-Datensatz-404s beenden sich ebenfalls mit Exit-Code 6, melden jedoch, dass der Datensatz nicht gefunden wurde. Reine Session-Befehle verweigern den API-Key-Modus vor HTTP (Exit-Code 2).

Menschenlesbare Befehle verwenden Zusammenfassungen und Tabellen. Für rohe JSON-Exporte übergib globales `--json` oder speichere mit `--out FILE`; andernfalls zeigen Session- und JSON-Abfrage-Exporte eine lesbare Ansicht. CSV-Exporte bleiben einfaches CSV für die Weiterverarbeitung in Pipelines.

| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | Erstellen mit `--name`, `--description`, `--file`-Definition; Update behält nicht erwähnte Felder |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | Hinzufügen mit `--query ID --chart TYPE --title`; Konfiguration/Geometrie oder Layout via `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | Export mit `--out`; history ist Evaluierungshistorie |
| `fp sessions import FILE...` | Claude Code Transkripte, Codex-Rollouts oder Event-JSONL (`.gz` ok); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; benötigt `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; list `--limit`; messages `--session-id` |
| `fp query compose "question"` | Session; `--run` |
| `fp query export [ID]` | Oder `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Issues können mit `--create --title --summary` oder `--create --file` erstellt werden |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; Update mit `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | Session; entwirft eine Policy auf Basis der Events deiner Organisation, veröffentlicht nie |
| `fp policies backtest [FILE_OR_ID]` | Session; regex replayed das Modul; `jev`/`both` (veröffentlicht oder `--semantic checks.json`) schätzen kostenlos, `--run [--sample N]` verbraucht Jev-Kontingent; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | Session; könnte eine Policy dieses Issue verhindern |
| `fp issues facets` | Werte, die die Inbox-Filter annehmen können, mit Zählungen |
| `fp agent brief` | Session; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | Session; leitet fehlenden Slug ab, wechselt nicht die Organisation |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | Berechtigungssets; create mit `--name --permission`; update ersetzt `--permission` oder führt zusammen mit `--add/--remove`; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | Löschen nach ID |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` benötigt einen API-Key; plan (Angebote und Trial) und claim erfordern eine angemeldete Session |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1.000.000 Tokens |
| `fp otel status\|enable\|disable` | Cloud-Org-Ingest-Schalter, kein lokales Capture |
| `fp slack status\|disconnect` | Session |

`fp agent ask` rendert Artefakt-SQL als Tabellen/Statistiken über `queries:run`.
Schreib-Genehmigungen zeigen die vorgeschlagene Änderung an und fragen auf einem Terminal nach. Skripte und
`--json` lehnen ab, es sei denn, `--approve` wird explizit angegeben. Bestehende JSON-Strukturen bleiben unverändert, wenn kein Artefakt zurückgegeben wird.

Auf einem Terminal startet `fp login` mit einem Link zum Anmelden über den Browser oder SSO und öffnet ihn (über SSH oder ohne Display wird er nur angezeigt; er funktioniert von jedem Gerät aus); autorisiere ihn und das Terminal schließt den Vorgang selbstständig ab. Dieses Terminal erhält Zugang zu allen deinen Organisationen, bis die Session abläuft — autorisiere daher nur einen Link, den du gerade selbst angefordert hast. Wenn der Login in einem anderen Netzwerk gestartet wurde, erhältst du eine E-Mail, sobald die Session existiert, und die Seite warnt dich, sofern der Deployment-Standort erkennbar ist. Drücke **Tab** für einen 6-stelligen Code per E-Mail und Tab erneut, um zurückzugehen. `--email`, `--json` und alles ohne Terminal verwenden den Code.

### Events

```text
fp events [OPTIONS]
```

Listet einzelne Agent-Events auf. Der standardmäßige Light-Feed schließt rohe Payloads aus; verwende `--full` nur für eine begrenzte Untersuchung.

| Option | Beschreibung |
| --- | --- |
| `--limit`, `-n <n>` | Maximale Gesamtanzahl Zeilen. Standard: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` oder `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC-Bereich; überschreibt `--since`. |
| `--env <value>` | Umgebungsfilter; Werte wiederholen oder kommagetrennt angeben. |
| `--event-type <value>` | Event-Typ-Filter; Werte wiederholen oder kommagetrennt angeben. |
| `--agent-id <value>` | Agent-Filter; Werte wiederholen oder kommagetrennt angeben. |
| `--session-id <value>` | Session-Filter; Werte wiederholen oder kommagetrennt angeben. |
| `--search <text>` | Payload-Textsuche; wiederholbar, ein beliebiger Begriff muss übereinstimmen. |
| `--order asc\|desc` | Zeitliche Sortierung. Standard: neueste zuerst. |
| `--all` | Automatisch paginieren bis `--limit`. |
| `--cursor <token>` | Wiederaufnahme ab einem undurchsichtigen Cursor. |
| `--page-size <n>` | Zeilen pro Anfrage mit `--all`; Maximum `200`. |
| `--full` | Rohe Payloads über den schwergewichtigeren Event-Endpunkt einschließen. |
| `--fields <csv>` | Nur ausgewählte Felder zurückgeben; Anforderung von `payload` aktiviert den Full-Modus. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` paginiert **bis zu `--limit`**, was standardmäßig **50** ist — daher stoppt `--all` allein bei 50 Zeilen. Wenn es vorzeitig stoppt, enthält die Antwort einen `next_cursor` zur Fortsetzung; `"next_cursor": null` bedeutet, dass der Feed tatsächlich erschöpft ist.
</Note>

#### Audit-Erstellungsoptionen

```bash

  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Option | Beschreibung |
| --- | --- |
| `--file <path>` | Die Definition auf JSON basieren oder `-` für stdin verwenden. Explizite Flags überschreiben Datei-Werte. |
| `--description <text>` | Die Fehlerfrage oder den Zweck beschreiben. |
| `--enabled` / `--disabled` | Planung ein- oder ausschalten. Standard: aktiviert. |

| `--schedule-anchor <timestamp>` | Feste UTC-Phase im ISO 8601-Format. Standard: nächstes 09:00 UTC. |
| `--window-mode since_last\|fixed` | Nach dem letzten vollständig analysierten Fenster fortfahren oder wiederholt ein rollendes Fenster untersuchen. Standard: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Standard: `604800`. |
| `--scope '<json>'` | Nach `environments`, `agent_ids` oder anderen unterstützten Scope-Feldern filtern. |
| `--ignore-error-type <type>` | Fehlertypen ausschließen; wiederholen oder kommagetrennt angeben. |
| `--llm` / `--no-llm` | Agentische Analyse aktivieren oder deaktivieren. Standard: aktiviert. |

| `--sensitivity low\|medium\|high` | Meldeempfindlichkeit festlegen. Standard: `medium`. |

Kontext beim Erstellen einschließen, wenn der erste Durchlauf ihn benötigt. Die Erstellung übergibt die Definition und den Kontext gemeinsam, bevor der eingereihte Durchlauf beginnt.

<Note>
  `fp audits run` ist asynchron. Rufe `fp audits runs NAME` ab, bis der letzte Durchlauf erfolgreich abgeschlossen ist oder fehlschlägt, bevor du seine Findings liest.
</Note>

<Warning>
  Die `AGENTEYE_*`-Schreibweisen dieser Variablen werden von `fp` **nicht gelesen** und waren es nie — das CLI deklariert `FP_*` (`fp_cli/app.py`), und eine unbekannte Variable ist kein Fehler. Das Setzen von `AGENTEYE_DASHBOARD_URL` ändert das Ziel des CLI nicht; es wird ignoriert und der Befehl läuft stillschweigend gegen das gespeicherte Dashboard.

  `AGENTEYE_HOME` und `AGENTEYE_ENVIRONMENT` existieren noch, gehören aber zum **Collector und dem Telemetrie-SDK**, nicht zu diesem CLI.
</Warning>

<Warning>
  Befehle, die Konfigurationen löschen, widerrufen, unterdrücken, lösen oder ersetzen, fragen standardmäßig nach. Verwende `--yes` erst nach Überprüfung der aktiven Organisation und des Ziels.
</Warning>
