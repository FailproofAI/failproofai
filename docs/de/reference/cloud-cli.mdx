Verwende `fp` zum Einsehen von Cloud-Telemetrie, zur Verwaltung cloud-gesteuerter Durchsetzung (Richtlinien, Fleet-Deployments, Guardrail-Entscheidungen) sowie zur Verwaltung von Audits, Findings, Issues, Alerts, Keys, Benutzern, Abfragen und Einstellungen. Verwende [`failproofai`](/de/reference/failproof-cli) für lokale Hooks, Richtlinien, Erfassung und Maschinenregistrierung.

Du kannst außerdem gehosteten Code, LLM-Judge- und Jev-Evaluatoren erstellen und deployen, Dashboards verwalten, Stimmungen analysieren und den Dashboard-Assistenten vom Terminal aus nutzen.

Installiere die veröffentlichte Cloud CLI als isoliertes Tool:

```bash
uv tool install fp-cloud-cli
fp version
```

## Anmelden

```bash
fp login
fp whoami
```

## Syntax

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Globale Optionen müssen vor dem Befehl stehen:

```bash
fp --json sessions --since 24h
```

Führe `fp COMMAND --help` oder `fp COMMAND SUBCOMMAND --help` für Terminal-Hilfe aus.

## CLI-Befehle

### Evaluator erstellen

`fp evaluators` erstellt Definitionen; `fp evals` liest Ergebnisse. Eine aktivierte verwaltete Instanz ist erforderlich (`fp evaluators instances`). Das Erstellen erfordert `evaluations:trigger`; Session-Dry-Runs und Schema-Profiling benötigen zusätzlich `events:read`.

Code ist ein eingeschränkter Python-Ausdruck. Speichere dies als `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM Judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev binär und abgestufte Rubrik:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
Die Erstellung aktiviert den Evaluator. Deploy erstellt eine neue unveränderliche Version und deaktiviert dann ältere aktivierte Versionen. Ein fehlgeschlagener Folgeschritt hinterlässt die neue Version veröffentlicht: Prüfe `evaluators list --all` vor einem erneuten Versuch.
Judge-Dry-Runs werden von Cloud abgelehnt. Jev-Dry-Runs verbrauchen Modellbudget.
Backfill umfasst Code-, Judge- und Jev-Evaluatoren und akzeptiert maximal 90 Tage; es werden nur Sessions in die Warteschlange aufgenommen, die ein Evaluator noch nicht bewertet hat. Judge- und Jev-Backfills verbrauchen Modellbudget, daher zuerst `fp evaluators backfill --dry-run` ausführen.
Die menschliche Ausgabe zeigt Session-Dry-Run-Ergebnisse vor dem Erstellen/Deployen.
Fehlgeschlagene Vorschauen stoppen den Schreibvorgang, sofern du nicht explizit `--force` nach der Prüfung angibst.
</Warning>

KI-gestütztes Erstellen erfordert `fp login` und schreibt eine Spezifikation, die von create/deploy akzeptiert wird:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Befehl | Optionen / Verhalten |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Vollständige Quelle/Hülle |
| `fp evaluators create` | `--key`, `--name`, `--version`, wiederholtes `--label`, `--condition EXPR\|@file`, eine Quelle, wiederholtes `--dry-run-on`, `--disabled`, explizites `--force` bei fehlgeschlagenen Vorschauen |
| `fp evaluators deploy KEY` | Gleiche Quell-Flags; `--version`, `--backfill 7d` (jede Art, 1–90 Tage), `--force`; numerische Versionen werden automatisch erhöht; KEY liefert einen fehlenden Spec-Datei-`eval_key` |
| `fp evaluators draft "intent"` | Session; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Quell-Flags oder `--file`, wiederholtes `--session` (maximal 10); ohne = nur kompilieren |
| `fp evaluators enable\|disable KEY[@VERSION]` | Umschalten |
| `fp evaluators label KEY[@VERSION]` | Wiederholtes `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | Verwaltete Fleet/Schema/Jobs einsehen |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; Code, Judge und Jev |

Code-Flags sind `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. Judge-Flags sind `--judge --criteria TEXT`, wiederholtes `--step` und
`--threshold`. Jev-Flags sind `--jev noul --instructions --true --false` oder
`--jev score --instructions` mit 3–5 verschiedenen `--level`-Werten, schlechtester zuerst.
Judge/Jev erfordern einen Score; Schwellenwerte liegen zwischen 0 und 1. Binäre Judge-Steps werden abgelehnt.

Spec-Dateien enthalten genau `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
Judge/Jev `evaluator_source` ist ein JSON-Hüllen-String. Keine Zeilen-IDs,
Aktivierungsstatus oder KI-Reasoning-Metadaten einfügen. `--file` und diskrete Spec-Flags schließen sich gegenseitig aus; deploy kann die Version der Datei überschreiben. Ausgabedateien werden nie überschrieben.

### Neue Dashboard-Steuerungen

Alle Befehle akzeptieren globales `--json`. Unbekannte-Route-404s beenden mit Exit-Code 6 und der Meldung "not available on this FailproofAI Cloud yet". Fehlende-Eintrag-404s beenden ebenfalls mit Exit-Code 6, melden aber, dass der Eintrag nicht gefunden wurde. Session-only-Befehle verweigern den Key-Modus vor HTTP (Exit 2).

Menschliche Befehle verwenden Zusammenfassungen und Tabellen. Für rohe JSON-Exporte globales `--json` übergeben oder mit `--out FILE` speichern; andernfalls zeigen Session- und JSON-Abfrageexporte eine lesbare Ansicht. CSV-Exporte bleiben für die Weiterverarbeitung in reinem CSV.

| --- | --- |

| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | Add: `--query ID --chart TYPE --title`; Konfiguration/Geometrie oder Layout via `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | Export: `--out`; history ist Auswertungshistorie |
| `fp sessions import FILE...` | Claude Code Transkripte, Codex-Rollouts oder Ereignis-JSONL (`.gz` ok); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; erfordert `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; list: `--limit`; messages: `--session-id` |
| `fp query compose "question"` | Session; `--run` |
| `fp query export [ID]` | Oder `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Issues können `--create --title --summary` oder `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; update: `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | Session; entwirft eine Richtlinie aus den Ereignissen deiner Organisation, veröffentlicht nie |
| `fp policies backtest [FILE_OR_ID]` | Session; regex spielt das Modul ab; `jev`/`both` (veröffentlicht oder `--semantic checks.json`) schätzt kostenlos, `--run [--sample N]` verbraucht Jev-Guthaben; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | Session; könnte eine Richtlinie dieses Problem verhindern |

| `fp orgs create --name N [--slug S]` | Session; leitet fehlenden Slug ab, wechselt die Organisation nicht |

| `fp users delete ID` / `fp users defaults` | Löschung nach ID |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` benötigt einen API-Key; plan (Angebote und Testversion) und claim erfordern eine angemeldete Session |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1.000.000 Token |
| `fp otel status\|enable\|disable` | Cloud-Org-Ingest-Schalter, keine lokale Erfassung |
| `fp slack status\|disconnect` | Session |

`fp agent ask` rendert Artefakt-SQL als Tabellen/Statistiken über `queries:run`.
Schreibgenehmigungen zeigen die vorgeschlagene Änderung und fragen auf einem interaktiven Terminal nach. Skripte und `--json` lehnen ab, sofern `--approve` nicht explizit angegeben ist. Bestehende JSON-Strukturen bleiben unverändert, wenn kein Artefakt zurückgegeben wird.

### Ereignisse

```text
fp events [OPTIONS]
```

Listet einzelne Agent-Ereignisse auf. Der standardmäßige leichte Feed schließt rohe Payloads aus; verwende `--full` nur für eine begrenzte Untersuchung.

| Option | Beschreibung |
| --- | --- |
| `--limit`, `-n <n>` | Maximale Gesamtzeilen. Standard: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` oder `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC-Bereich; überschreibt `--since`. |
| `--env <value>` | Umgebungsfilter; wiederholen oder kommagetrennte Werte. |
| `--event-type <value>` | Ereignistyp-Filter; wiederholen oder kommagetrennte Werte. |
| `--agent-id <value>` | Agent-Filter; wiederholen oder kommagetrennte Werte. |
| `--session-id <value>` | Session-Filter; wiederholen oder kommagetrennte Werte. |
| `--search <text>` | Payload-Textsuche; wiederholbar, bei Übereinstimmung eines beliebigen Begriffs. |
| `--order asc\|desc` | Zeitreihenfolge. Standard: neueste zuerst. |
| `--all` | Automatisch paginieren bis zu `--limit`. |
| `--cursor <token>` | Ab einem undurchsichtigen Cursor fortsetzen. |
| `--page-size <n>` | Zeilen pro Anfrage mit `--all`; maximal `200`. |
| `--full` | Rohe Payloads über den schwereren Ereignis-Endpunkt einschließen. |
| `--fields <csv>` | Nur ausgewählte Felder zurückgeben; Anforderung von `payload` aktiviert den Full-Modus. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` paginiert **bis zu `--limit`**, das standardmäßig **50** ist — `--all` allein stoppt also bei 50 Zeilen. Wenn es frühzeitig stoppt, enthält die Antwort einen `next_cursor` zum Fortsetzen; `"next_cursor": null` bedeutet, dass der Feed tatsächlich erschöpft war.
</Note>

#### Audit-Create-Optionen

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Option | Beschreibung |
| --- | --- |
| `--file <path>` | Definition auf JSON basieren oder `-` für stdin verwenden. Explizite Flags überschreiben Dateiwerte. |
| `--description <text>` | Die Fehlerfrage oder den Zweck angeben. |
| `--enabled` / `--disabled` | Planung ein- oder ausschalten. Standard: aktiviert. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Standard: `86400`. |
| `--schedule-anchor <timestamp>` | Feste UTC-Phase in ISO 8601-Form. Standard: nächster 09:00 UTC. |
| `--window-mode since_last\|fixed` | Nach dem letzten vollständig analysierten Fenster fortsetzen oder wiederholt ein rollendes Fenster prüfen. Standard: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Standard: `604800`. |

| `--channels '<json>'` | Benachrichtigungskanal-Array. |

Kontext bei der Erstellung einbeziehen, wenn der erste Lauf ihn benötigt. Die Erstellung übernimmt die Definition und den Kontext gemeinsam, bevor der geplante Lauf beginnt.

<Note>
  `fp audits run` ist asynchron. Bis zum Abschluss oder Fehler des letzten Laufs `fp audits runs NAME` abfragen, bevor die Findings gelesen werden.
</Note>

<Warning>

</Warning>

</Warning>
