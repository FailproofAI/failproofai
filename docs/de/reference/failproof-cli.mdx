Installation mit `npm install -g failproofai`. Starte `failproofai` ohne Argumente, um das lokale Dashboard zu öffnen.

## Kernbefehle

| Befehl | Funktion |
| --- | --- |
| `failproofai config` | Agents, den Hintergrunddienst und optionale Cloud-Verbindung einrichten |
| `failproofai config --token <key>` | Einrichten und verbinden ohne Rückfragen |
| `failproofai config --status` | Verbindung, Dienstversion und Pause-Status anzeigen |
| `failproofai policies` | Richtlinien und deren Aktivierungsstatus auflisten |
| `failproofai policies add <name>` | Eine Richtlinie aktivieren |
| `failproofai policies add <owner>/<repo>` | Ein Richtlinienpaket installieren |
| `failproofai policies remove <name-or-pack>` | Eine Richtlinie deaktivieren oder ein Paket entfernen |
| `failproofai policies show <owner>/<repo>` | Ein Paket vor der Installation prüfen |
| `failproofai publish` | Eigene Richtlinien als Paket veröffentlichen |
| `failproofai audit` | Lokale Agent-Verlaufsdaten scannen |
| `failproofai harness` | Zusätzliche Sitzungsorte verwalten |
| `failproofai flush` | Warteschlange mit Ereignissen sofort senden |
| `failproofai backfill` | Ältere Agent-Verlaufsdaten erneut einlesen |
| `failproofai update` | Ein npm-Upgrade abschließen und den Dienst aktualisieren |
| `failproofai uninstall` | Hooks und den Dienst entfernen |

`policy`, `pack` und `p` sind akzeptierte Aliasse für `policies`, jedoch verwendet die Dokumentation `policies`.

## Maschine einrichten

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

Bei der Einrichtung wird kein Richtlinienpaket ausgewählt. Bevor du eines hinzufügst, wird nur `block-failproofai-commands` ausgeführt.

Für die unbeaufsichtigte Cloud-Einrichtung:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Um Entscheidungen ohne Transkripte zu senden, verbinde zunächst und setze `collector.sessions` in `~/.failproofai/config.json` auf `false`. Das aktuelle Setup-Flag `--no-transcripts` wird zwar geparst, wendet diese Einstellung jedoch nicht an.

Verwende `--machine-label <name>` nach der Verbindung der Maschine, um sie umzubenennen. `--connect <url>` ist der eingeschränktere Befehl zum reinen Anmelden einer bereits eingerichteten Maschine.

## Richtlinien und Pakete

```bash
failproofai policies
failproofai policies add block-sudo
failproofai policies show owner/repo
failproofai policies add owner/repo --category git,database
failproofai policies remove owner/repo
```

Alles mit einem Schrägstrich ist eine Paketquelle; alles ohne einen Schrägstrich ist ein Richtlinienname.

Nützliche Flags zur Paketauswahl:

| Flag | Verwendung |
| --- | --- |
| `--policy a,b` | Benannte Richtlinien auswählen |
| `--category x,y` | Kategorien auswählen |
| `--all` | Alles auswählen |
| `--cli <agents...>` | Auf benannte Harnesses beschränken |

Verwende `failproofai policies -i -c <path>`, um eine benutzerdefinierte Richtlinie aus einem beliebigen Pfad zu laden. Konventionsdateien mit dem Namen `*policies.{js,mjs,ts}` unter `.failproofai/policies/` werden automatisch geladen.

## Durchsetzung pausieren

```bash
failproofai config --pause 10m
failproofai config --status
failproofai config --resume
```

Eine Pause gilt für eine lokale Sitzung und läuft stets ab. Sie pausiert keine Cloud-verwalteten Richtlinien und auch nicht `block-failproofai-commands`.

## Audit und Zustellung

```bash
failproofai audit
failproofai audit --schedule 7 --email team@example.com
failproofai audit --status
failproofai flush --wait
failproofai backfill --since 30d --dry-run
```

`backfill` liest `~/.failproofai/config.json`. Lasse `--dry-run` weg, um den Verlauf erneut zu senden.

## Zusätzliche Sitzungsorte

```bash
failproofai harness list
failproofai harness add-path claude work=/srv/team/.claude/projects
failproofai harness remove-path claude work
```

Labels verhindern, dass Sitzungen aus zwei kopierten Home-Verzeichnissen unter derselben abgeleiteten Agent-ID zusammengeführt werden.

Unterstützte Harnesses sind `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity` und `goose`. Die Scope-Unterstützung unterscheidet sich; siehe [Harnesses](/de/reference/harnesses).

## Nützliche Umgebungsvariablen

| Variable | Verwendung |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | Cloud-Maschinenschlüssel |
| `FAILPROOFAI_CLOUD_URL` | Die Cloud-URL überschreiben |
| `FAILPROOFAI_HOME` | Das lokale Statusverzeichnis verschieben |
| `FAILPROOFAI_NO_DOWNLOAD=1` | Paket- und Dienst-Downloads verweigern |
| `FAILPROOFAI_DAEMON_BASE_URL` | Einen Dienst-Binär-Spiegel verwenden |
| `FAILPROOFAI_PACK_BASE_URL` | Einen Paketspiegel verwenden |
| `FAILPROOFAI_NO_FIRST_RUN=1` | Erststart-Aufforderungen deaktivieren |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | Anonyme CLI-Telemetrie deaktivieren |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | Zusätzliche Pfade für einen Harness ersetzen |
| `NO_COLOR` | Terminalfarbe deaktivieren |

## Entfernen oder aktualisieren

```bash
npm install -g failproofai@latest
failproofai update
```

Vor dem Entfernen des Pakets:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

<Warning>
  Führe `failproofai uninstall` aus, bevor du das npm-Paket entfernst. npm entfernt keine installierten Hooks und keinen Hintergrunddienst.
</Warning>

Führe `failproofai help <command>` aus, um die vollständigen Optionen deiner installierten Version zu sehen.
