Diese Seite beschreibt die Frageformen und Bewertungsregeln hinter [Jev-Evaluierungen](/de/evaluations/jev). Manche Fragen erfordern, dass ein Modell das Gespräch *liest*, aber nicht darüber *schreibt*. „Hat der Kunde Dringlichkeit ausgedrückt?" hat zwei Antworten. „Wie frustriert waren sie?" hat eine Handvoll, in einer bestimmten Reihenfolge. Alle Antworten stehen fest, bevor man überhaupt fragt.

Eine **Klassifikations-Evaluierung** ist genau dafür gedacht. Sie schreiben die Frage und die möglichen Antworten, und ein kleines, speziell für die Klassifikation entwickeltes Modell liefert eine kalibrierte Zahl zurück — niemals Freitext.

<Note>
Wie ein Richter kostet eine Klassifikations-Evaluierung einen Modellaufruf pro Sitzung. Anders als ein Richter ist es jedoch ein kleines, zweckgebundenes Modell und kein allgemeines — daher ist es schneller und günstiger, erklärt sich aber nie selbst. Wenn Sie die Begründung benötigen, verwenden Sie einen [Richter](/de/evaluations/judge).
</Note>

## Was brauche ich?

| Frage | Verwendung |
| --- | --- |
| Wie viele Tool-Aufrufe gab es? | Code |
| Dauerte die Sitzung unter 30 Sekunden? | Code |
| Hat der Kunde Dringlichkeit ausgedrückt? | **Klassifikator** |
| Welches Team soll sich darum kümmern: Abrechnung, Technik oder Vertrieb? | **Klassifikator** |
| Wie frustriert war der Kunde? | **Klassifikator** |
| War die Antwort tatsächlich korrekt? | **Richter** |
| Hat es unsere Eskalationsrichtlinie befolgt, und warum meinen Sie das? | **Richter** |

Die Faustregel lautet: **Zählbares → Code, auflistbare Antworten → Klassifikator, Erklärung erforderlich → Richter.**

Sie müssen das nicht vorab entscheiden. Beschreiben Sie, was gemessen werden soll, und der Assistent wählt aus, teilt Ihnen die Wahl mit Begründung mit, und Sie können jederzeit wechseln.

## Die zwei Fragetypen

### `noul` — ist das wahr?

Zwei Antworten, und Sie beschreiben beide. Das Ergebnis ist die Wahrscheinlichkeit, dass die „wahre" Beschreibung zutrifft:

```json
{
  "instructions": "Did the assistant promise a refund without first checking the refund policy?",
  "criteria": {
    "true":  "A refund was promised or issued with no prior policy check or approval",
    "false": "No refund was promised, or every refund followed a policy check"
  }
}
```

Beschreiben Sie beide Seiten. „Keine Dringlichkeit geäußert" ist eine echte Antwort, und sie zu benennen macht die andere präziser.

### `score` — wie viel davon?

Eine geordnete Rubrik, **schlechtestes zuerst**. Das Ergebnis gibt an, wo die Sitzung auf dieser Skala liegt, neu skaliert auf 0–1:

```json
{
  "instructions": "How frustrated is the customer?",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
```

**Eine Rubrik umfasst drei bis fünf Stufen, die alle voneinander verschieden sein müssen.** Beide Grenzen sind gemessen, nicht stilistisch:

- **Zwei Stufen** reduzieren sich auf das, was `noul` bereits besser leistet, und **mehr als fünf** verleiten das Modell dazu, zur Mitte hin zu hedgen, anstatt sich festzulegen. Dieselbe Frage über dieselbe Sitzung ergab 0,00 mit zwei Stufen, 0,01 mit drei und 0,55 mit zehn.
- **Wiederholte Stufen** verteilen die Antwort willkürlich zwischen ihnen. Eine Sitzung, die eindeutig wütend war, erzielte 1,00 gegenüber `["Calm", "Frustrated", "Very angry"]` und 0,66 gegenüber `["Angry", "Angry", "Angry"]` — eine wohlgeformte Zahl, die nichts bedeutet.

Kategorien ohne Reihenfolge — „Abrechnung, Technik oder Vertrieb" — sind keine Rubrik. Stellen Sie sie als `noul` pro Kategorie oder verwenden Sie einen Richter.

## Ergebnisse verstehen

Ein Klassifikator liefert einen **Score** von 0 bis 1, genau wie ein Richter, sodass er auf dieselbe Weise in Diagrammen dargestellt, gefiltert und für Warnungen verwendet werden kann. Zwei Unterschiede sind erwähnenswert:

- **Es gibt keine Begründung.** Das Feld ist absichtlich leer. Dieses Modell erklärt sich nicht, und eine Erklärung zu erfinden wäre eine Fälschung, keine Funktion.
- **Unsicherheit wird gekennzeichnet.** Eine `score`-Frage meldet ihre eigene Konfidenz, und ein Ergebnis, bei dem das Modell unsicher war, wird mit `low_confidence` markiert — sodass „welche davon soll sich ein Mensch ansehen" ein Filter und kein Ratespiel ist. Eine `noul`-Frage meldet keine Konfidenz und wird daher nie gekennzeichnet.

Sehr lange Sitzungen werden in Auszügen gelesen und kombiniert. Wenn eine Sitzung zu lang ist, um vollständig gelesen zu werden, gibt das Ergebnis an, wie viele Gesprächsrunden ausgelassen wurden — Sie werden nie ein Urteil sehen, das auf einem Teil einer Sitzung basiert, aber als vollständig dargestellt wird.

## Grenzen

- **Drei bis fünf Rubrikstufen, alle verschieden.** Siehe oben; beide Grenzen werden beim Erstellen durchgesetzt.
- **Eine Frage pro Evaluierung.** Stellen Sie zwei Fragen, erhalten Sie zwei Evaluierungen — was auch das ist, was Sie in einem Diagramm wollen.
- **Das Bearbeiten der Frage veröffentlicht eine neue Version.** Alte und neue Scores sind nicht vergleichbar und werden daher getrennt gehalten, anstatt in einer einzigen Trendlinie vermischt zu werden.
- **Ein Klassifikator liefert immer einen Score**, niemals eine Metrik oder eine Behauptung.
- **Keine Begründung**, wie oben beschrieben. Wenn eine Zahl jemanden zu „warum?" veranlasst, schreiben Sie stattdessen einen Richter.

## Testen und Backfill

Anders als ein Richter **kann** eine Klassifikations-Evaluierung getestet werden, bevor Sie sie einsetzen — [testen Sie sie](/de/evaluations/test) an echten Sitzungen auf dieselbe Weise wie eine Code-Evaluierung, und lesen Sie die Scores, bevor etwas live geht.

Sie kann auch über bereits vorhandene Sitzungen [zurückgefüllt werden](/de/evaluations/deploy#score-sessions-you-already-have). Da pro Sitzung ein Modellaufruf anfällt, wählen Sie das Zeitfenster bewusst aus, anstatt alles erneut zu verarbeiten.
