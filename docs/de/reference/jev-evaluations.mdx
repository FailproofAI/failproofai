Diese Seite beschreibt die Frageformen und Bewertungsregeln hinter [Jev-Evaluierungen](/de/evaluations/jev). Manche Fragen erfordern ein Modell, das das Gespräch *liest*, aber nicht darüber *schreibt*. „Hat der Kunde Dringlichkeit ausgedrückt?" hat zwei Antworten. „Wie frustriert waren sie?" hat eine Handvoll, in einer bestimmten Reihenfolge. Sie kennen jede Antwort, bevor Sie fragen.

Eine **Klassifizierer-Evaluierung** ist genau dafür gedacht. Sie schreiben die Frage und die möglichen Antworten, und ein kleines, speziell für die Klassifizierung entwickeltes Modell gibt eine kalibrierte Zahl zurück — niemals Freitext.

<Note>
Wie ein Richter kostet eine Klassifizierer-Evaluierung einen Modellaufruf pro Sitzung. Im Gegensatz zu einem Richter handelt es sich jedoch um ein kleines, zweckgebundenes Modell und nicht um ein allgemeines — es ist daher schneller und günstiger, erklärt sich aber nie selbst. Wenn Sie die Begründung benötigen, verwenden Sie einen [Richter](/de/evaluations/judge).
</Note>

## Was möchte ich verwenden?

| Frage | Verwenden |
| --- | --- |
| Wie viele Tool-Aufrufe gab es? | Code |
| Dauerte die Sitzung unter 30 Sekunden? | Code |
| Hat der Kunde Dringlichkeit ausgedrückt? | **Klassifizierer** |
| Welches Team soll sich darum kümmern: Abrechnung, Technik oder Vertrieb? | **Klassifizierer** |
| Wie frustriert war der Kunde? | **Klassifizierer** |
| War die Antwort tatsächlich korrekt? | **Richter** |
| Hat es unsere Eskalationsrichtlinie befolgt, und warum denken Sie das? | **Richter** |

Die Faustregel: **Zählbares → Code, aufzählbare Antworten → Klassifizierer, Erklärung erforderlich → Richter.**

Sie müssen sich nicht im Voraus entscheiden. Beschreiben Sie, was gemessen werden soll, und der Assistent wählt aus, teilt Ihnen mit, was er gewählt hat und warum — und Sie können jederzeit wechseln.

## Die zwei Fragetypen

### `noul` — ist das wahr?

Zwei Antworten, und Sie beschreiben beide. Das Ergebnis ist die Wahrscheinlichkeit, dass die „wahre" Beschreibung zutrifft:

```json
{
  "instructions": "Did the assistant promise a refund without first checking the refund policy?",
  "criteria": {
    "true":  "A refund was promised or issued with no prior policy check or approval",
    "false": "No refund was promised, or every refund followed a policy check"
  }
}
```

Beschreiben Sie beide Seiten. „Keine Dringlichkeit ausgedrückt" ist eine echte Antwort, und diese anzugeben macht die andere schärfer.

### `score` — wie viel davon?

Eine geordnete Rubrik, **schlechteste zuerst**. Das Ergebnis gibt an, wo die Sitzung auf dieser Skala liegt, normiert auf 0–1:

```json
{
  "instructions": "How frustrated is the customer?",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
```

**Eine Rubrik umfasst drei bis fünf Stufen, die alle unterschiedlich sein müssen.** Beide Grenzen sind gemessen, nicht stilistisch:

- **Zwei Stufen** kollabieren in das, was `noul` bereits besser leistet, und **mehr als fünf** veranlassen das Modell, zur Mitte hin auszuweichen, anstatt sich festzulegen. Dieselbe Frage über dieselbe Sitzung ergab 0,00 bei zwei Stufen, 0,01 bei drei und 0,55 bei zehn.
- **Wiederholte Stufen** teilen die Antwort willkürlich auf. Eine Sitzung, die eindeutig wütend war, erzielte 1,00 gegen `["Calm", "Frustrated", "Very angry"]` und 0,66 gegen `["Angry", "Angry", "Angry"]` — eine wohlgeformte Zahl, die nichts bedeutet.

Kategorien ohne Reihenfolge — „Abrechnung, Technik oder Vertrieb" — sind keine Rubrik. Stellen Sie sie als `noul` pro Kategorie, oder verwenden Sie einen Richter.

## Ergebnisse lesen

Ein Klassifizierer erzeugt einen **Score** von 0 bis 1, genau wie ein Richter — er wird also in Diagrammen dargestellt, gefiltert und löst Benachrichtigungen auf dieselbe Weise aus. Zwei Unterschiede sind wichtig:

- **Es gibt keine Begründung.** Das Feld ist absichtlich leer. Dieses Modell erklärt sich nicht selbst, und eine Erklärung zu erfinden wäre eine Fälschung und kein Feature.
- **Unsicherheit wird gekennzeichnet.** Eine `score`-Frage gibt ihre eigene Konfidenz an, und ein Ergebnis, bei dem das Modell unsicher war, wird mit `low_confidence` markiert — „welche davon sollte ein Mensch sich ansehen?" ist also ein Filter und keine Schätzung. Eine `noul`-Frage gibt keine Konfidenz an und wird daher nie markiert.

Sehr lange Sitzungen werden in Ausschnitten gelesen und kombiniert. Wenn eine Sitzung zu lang ist, um vollständig gelesen zu werden, gibt das Ergebnis an, wie viele Gesprächsrunden ausgelassen wurden — Sie werden nie ein Urteil sehen, das auf einem Teil einer Sitzung basiert und als eines präsentiert wird, das auf der gesamten basiert.

## Grenzen

- **Drei bis fünf Rubrikstufen, alle unterschiedlich.** Siehe oben; beide Grenzen werden bei der Erstellung erzwungen.
- **Eine Frage pro Evaluierung.** Stellen Sie zwei Fragen, erhalten Sie zwei Evaluierungen — was auch das ist, was Sie in einem Diagramm möchten.
- **Das Bearbeiten der Frage veröffentlicht eine neue Version.** Alte und neue Bewertungen sind nicht vergleichbar, daher werden sie getrennt gehalten und nicht in eine Trendlinie gemischt.
- **Ein Klassifizierer erzeugt immer einen Score**, niemals eine Metrik oder eine Aussage.
- **Keine Begründung**, wie oben beschrieben. Wenn eine Zahl jemanden zu „warum?" veranlassen wird, schreiben Sie stattdessen einen Richter.

## Testen und Backfill

Im Gegensatz zu einem Richter **kann** eine Klassifizierer-Evaluierung getestet werden, bevor Sie sie einsetzen — [testen Sie sie](/de/evaluations/test) gegen echte Sitzungen auf dieselbe Weise wie eine Code-Evaluierung, und lesen Sie die Bewertungen, bevor etwas live geht.

Sie kann auch über bereits vorhandene Sitzungen [nachgefüllt](/de/evaluations/deploy#score-sessions-you-already-have) werden. Es kostet einen Modellaufruf pro Sitzung — wählen Sie das Zeitfenster daher bewusst, anstatt alles erneut zu verarbeiten.
