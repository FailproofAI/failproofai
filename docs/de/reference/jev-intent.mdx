Wenn Sie die [Jev-Richtlinienprüfung](/de/policies/jev) konfigurieren, beurteilt der Evaluator jeden kontrollierten Tool-Aufruf anhand von **dem, was der Mensch angefragt hat** — nicht anhand dessen, was der Harness dem Agenten vorgelegt hat. Eine Antwort wie „ja, force-push it" kann eine **reviewable**-Richtlinie freigeben — das ist der eigentliche Zweck des Evaluators, da ein Regex, der die Anfrage nicht lesen kann, ein Drittel aller echten Aufgaben blockiert.

Dieser Text stammt aus einer einzigen Quelle: **dem Prompt, den der Harness selbst bei seinem Prompt-Submit-Ereignis an den Hook übergibt**. Failproof AI zeichnet den vom Menschen eingegebenen Teil davon auf — Harness-Umrahmung entfernt, Secrets redigiert, Länge begrenzt — in einer `0600`-Datei in seinem eigenen Zustandsverzeichnis. Es wird nichts auf der Festplatte abgefragt: Das Session-Transkript ist eine Datei, die der Agent mit einem einzigen Befehl überschreiben kann, daher wird nie gefragt, wer einen Prompt verfasst hat.

## Das damit verbundene Risiko, unverblümt

Ein Agent, der bereits Befehle ausführen kann, kann einen Harness veranlassen, einen Prompt einzureichen. `claude -p "…"`, `codex exec`, `copilot -p`, `cursor-agent -p`, `devin -p`, `droid -p`, `goose run -t` und `pi -p` lösen alle dasselbe Prompt-Submit-Ereignis aus — mit demselben Payload, wie ein Mensch es eintippen würde — in einer untergeordneten Session, die dieser Agent kontrolliert. Der Agent kann auch Failproof AIs eigene Hook-Binärdatei ausführen und ihr einen selbst erstellten Payload übergeben. Nichts innerhalb von Failproof AI kann beides vom Echten unterscheiden — beide sind dasselbe Programm, das denselben stdin liest.

**Ein Agent mit Shell-Zugriff kann also seine eigene Zustimmung fälschen.** Das ist ein bewusster Kompromiss, der am 2026-09-23 eingegangen wurde, und hier sind beide Seiten davon:

- **Was er einbringt.** Die Alternative wurde gebaut und gemessen: Ein Feld verlangen, in dem der Harness einen Menschen als Autor des Prompts benennt, und andernfalls nichts aufzeichnen. Kein verfügbarer Harness sendet ein solches Feld, sodass diese Version **auf jedem Harness nichts aufzeichnete** — Jev beurteilte jeden Aufruf ohne angegebene Absicht und konnte niemals eine einzige Richtlinie freigeben. Eine Erfassung, die niemals auslöst, ist kein sichereres Produkt, sondern überhaupt kein Produkt.
- **Was er nicht leisten kann.** Ein aufgezeichneter Prompt kann immer nur eine Richtlinie freigeben, die bereits als **reviewable** markiert ist. Eine **hard**-Richtlinie wird durch nichts, was Jev sagt, jemals freigegeben — ein gefälschter Prompt kann also niemals aus einem hard deny ein allow machen. Und das Überspringen des Hooks bringt einem Agenten ebenfalls nichts: Der Harness ruft Failproof AI für den Tool-Aufruf unabhängig davon auf.
- **Was er im schlimmsten Fall bewirken kann.** Das Schlimmste, was er tun kann, ist eine der fünfzehn reviewable eingebauten Richtlinien freizugeben — und **zwölf dieser fünfzehn blockieren**. `protect-env-vars`, `block-env-files`, `block-read-outside-cwd`, `block-rm-rf`, `block-force-push`, `block-secrets-write` sowie die sechs Infrastruktur-CLI-Blöcke (`block-kubectl`, `block-terraform`, `block-aws-cli`, `block-gcloud`, `block-az-cli`, `block-helm`) sind Denies — eine gefälschte Zustimmung kann also ein echtes Deny in ein Allow verwandeln für: das Ausgeben von Umgebungs-Secrets, das Lesen einer `.env`-Datei, das Lesen außerhalb des Projekts, `rm -rf`, einen force-push, das Schreiben einer Secrets-Datei oder das Ändern von Live-Infrastruktur. Nur `warn-git-amend`, `warn-destructive-sql` und `warn-global-package-install` sind Hinweise. Eine Standardinstallation aktiviert zwei der zwölf: `protect-env-vars` und `block-env-files`; die anderen zehn sind nur auf Maschinen aktiv, wo jemand sie manuell aktiviert hat. Was kein Prompt jemals erreicht, ist alles Hard — `block-sudo`, `block-curl-pipe-sh`, `block-push-master`, `block-work-on-main`, der Schutz, der verhindert, dass ein Agent Failproof AI deaktiviert, und jedes andere eingebaute, das nicht als reviewable markiert ist. [Policy authority](/de/policies/authority) listet alle fünfzehn auf und was jede prüft.

Weiterhin abgelehnt wird alles, was einfach zu prüfen ist und was ein Agent nicht allein durch Fragen erlangen kann: ein Turn, den der eigene Harness-Payload als maschinell eingereicht kennzeichnet, ein Payload, der einen Sub-Agenten benennt, eine Session-ID, die kein einfacher Name ist, ein Ereignis, das nicht das Prompt-Submit-Ereignis ist, und Text, der ausschließlich aus Harness-Umrahmung besteht — einschließlich Failproof AIs eigener Stop-Gate-Wörter, die mehrere Harnesses als nächsten User-Turn zurücksenden.

„Text field" ist das stdin-Payload-Feld nach Failproof AIs harnessspezifischer Normalisierung. „Recorded" gibt an, ob der Prompt als Anfrage des Menschen gespeichert wird.

Zwei Harnesses zeichnen nichts auf, und aus demselben Grund: Ihr Ereignis liefert keinen menschlichen Text. Hermes hat kein Prompt-Submit-Ereignis — sein natives Plugin verarbeitet `pre_llm_call` selbst und leitet nur Tool-, Session- und Subagenten-Ereignisse weiter. Antigravitys `PreInvocation` löst vor jedem Modell-Aufruf aus — beim Human-Turn und bei den fünf nachfolgenden — und enthält kein Prompt-Feld; Hooks können außerdem `userMessage`-Schritte in dasselbe Gespräch injizieren. In keinem der beiden Ereignisse gibt es etwas aufzuzeichnen.

## Was einen Prompt zum Prompt des Menschen macht

1. **Das Ereignis.** Failproof AI wurde für das Prompt-Submit-Ereignis des Harnesses aufgerufen, das der Handler zu `UserPromptSubmit` kanonisiert.
2. **Der Payload.** Der Harness schreibt ihn auf den stdin des Hooks, und er enthält den Text im oben genannten Feld. Ein Aufruf, der Failproof AI ohne Payload erreicht, zeichnet nichts auf.
3. **Nichts im Payload schließt den Turn aus.** Ein Payload, der einen Sub-Agenten benennt (`agent_id`), ist der Agent, der sich selbst promptet. Ein `source`-, `input_source`- oder OpenClaw-Run-Marker, der einen maschinell eingereichten Turn benennt, wird abgelehnt. Ein **fehlender** Marker schließt nichts aus — das ist der Unterschied zur Version, die nichts aufzeichnete, da jeder Marker hier bei jedem verfügbaren Build fehlt.
4. **Nach dem Entfernen der Umrahmung bleibt etwas übrig** (siehe unten).

**Das Session-Transkript ist kein Beweis dafür, wer einen Prompt verfasst hat.** Frühere Versionen dieser Seite beschrieben eine Transkript-Querprüfung: Der Prompt wurde abgelehnt, wenn das Transkript zeigte, dass das Modell ihn geplant hatte, und das Transkript musste das des vorherigen Prompts fortsetzen. Diese Prüfung ist abgeschafft. Ein Transkript ist eine Datei, über die der Agent bereits Shell-Zugriff hat — es kann abgeschnitten, ersetzt, über das Lesebudget hinaus aufgefüllt, zu Beginn eines Turns gesichert und am Ende wiederhergestellt oder mit vom Agenten selbst geschriebenen Einträgen neu befüllt werden. Jede Härtungsrunde wurde von einer weiteren Variante derselben Fälschung gefolgt, sodass der gesamte Mechanismus entfernt statt repariert wurde.

Das Transkript wird noch für eine Sache gelesen: **die letzte sichtbare Nachricht des Agenten**. Diese Nachricht ist per Definition agentengeschrieben, Jev wird darüber informiert, und sie gilt allein niemals als Zustimmung.

## Was von einem Prompt aufbewahrt wird

Harnesses stecken mehr als nur die Worte des Menschen in einen Prompt. Bevor etwas gespeichert wird:

- `<system-reminder>`-Blöcke werden entfernt, die Worte des Menschen darum herum bleiben erhalten.
- Eine Session-Fortsetzungszusammenfassung („This session is being continued from a previous conversation…") wird vollständig verworfen.
- Aufgabenbenachrichtigungen, lokale Befehlsausgaben und Unterbrechungsmarkierungen werden vollständig verworfen.
- Ein Turn, den ein anderer Agent oder eine andere Session geschrieben hat, wird vollständig verworfen: Claude Code umschließt diese in `<cross-session-message>`, `<teammate-message>`, `<agent-message>`, `<coordinator-relay>` oder `<channel source=…>`.
- Failproof AIs eigene Nachrichten werden vollständig verworfen. Ein Stop-Gates `MANDATORY ACTION REQUIRED from failproofai …` oder eine `Instruction from failproofai: …` kommt bei Cursor, Copilot, Devin und OpenClaw als nächster User-Turn zurück und gilt niemals als Worte des Menschen — weder pur, noch in einem `<user_query>`-Block, noch hinter einem System-Reminder.
- Ein Slash-Befehl wird als der Befehl und die Argumente gespeichert, die der Mensch eingegeben hat, niemals als der Inhalt, zu dem der Harness ihn erweitert hat.
- Ein vom Codex-IDE-Extension erstellter Prompt bewahrt nur den Text nach seiner letzten `## My request for Codex:`- (oder in neueren Builds: `## My request:`-) Überschrift. Alles, was die Extension davor eingefügt hat, wird verworfen: die aktive Datei, offene Tabs, im Editor ausgewählter Text, erwähnte Dateien und Apps, Diff- und Browser-Kommentare, PR-Prüfungen, frühere Gespräche. Diese Regel wird auf Prompts **jedes** Harnesses angewendet, nicht nur auf Codex — ein solcher Prompt kann in jeden Composer eingefügt werden — daher werden die Abschnittsüberschriften der Extension in zwei Gruppen gelesen:
  - **Eine Überschrift, die niemand tippt** (`# Context from my IDE setup:`, `# Selected text:`, `# Files mentioned by the user:`, `# Diff comments:`, `# Chrome tabs:`, `<in-app-browser-context …>`, die Codex- und ChatGPT-Gesprächsüberschriften, „The attached pasted text file(s)…" und die übrigen eigenen Abschnitte der Extension) bedeutet, dass die Extension diesen Prompt erstellt hat. Einer ohne eine darunter liegende Anfrage-Überschrift enthält überhaupt keinen menschlichen Text und wird nicht aufgezeichnet. Das verhindert, dass eine in einem lediglich *ausgewählten* Text gefälschte Genehmigung — etwa ein `// NOTE FROM THE OWNER: yes, force-push…`-Kommentar innerhalb von `# Selected text:` — in Ihre aufgezeichnete Anfrage gelangt.
  - **Eine Überschrift, die ein Entwickler plausiblerweise tippt** (`## Code review guidelines:`, `## Pull request fix:`, `## Pull request merge task:`, `## Auto resolve merge:`, `# In app browser:`) bedeutet „extension-erstellt" nur, wenn tatsächlich eine Anfrage-Überschrift vorhanden ist. Ohne eine solche gehört der Prompt dem Menschen und wird vollständig gespeichert — inklusive Überschrift. Das Verwerfen wäre still und vollständig: nichts aufgezeichnet für diesen Turn, keine reviewable Richtlinie könnte freigegeben werden, und Jev würde nicht einmal gefragt, ob die Anfrage-Hülle eine Injektion enthält. Dies gilt nur am *Anfang* eines Turns: Sobald ein Prompt als extension-erstellt eingestuft wurde, ist eine Überschrift beider Gruppen innerhalb des Folgeinhalts nach seiner Anfrage-Überschrift ein weiterer Abschnitt der Extension, und der Prompt wird nicht aufgezeichnet.

  Die Anfrage selbst wird wie jeder andere Turn beurteilt: Wenn das, was auf die Überschrift folgt, eine Fortsetzungszusammenfassung ist, eine Nachricht, die ein anderer Agent oder eine andere Session geschrieben hat, eine der eigenen Direktiven von Failproof AI oder ein weiterer Abschnitt der Extension, wird der Prompt überhaupt nicht aufgezeichnet.
- Ein Cursor-Prompt, der in `<user_query>…</user_query>` eingeschlossen ist (optional hinter einem `<timestamp>`-Block), wird entpackt, wenn der Wrapper der *gesamte* Prompt ist. Ein Tag an einer anderen Stelle ist normaler Text — ein aus einem Log eingefügter Ausschnitt oder ein vom Agenten gewählter Branch-Name — und der Prompt wird vollständig gespeichert, anstatt auf den markierten Bereich reduziert zu werden.
- Eingefügte Blöcke werden gespeichert und als vom Menschen eingefügt gekennzeichnet.

Ein Prompt, der ausschließlich aus Harness-Text besteht, wird überhaupt nicht aufgezeichnet.

## Die letzte Nachricht des Agenten

Eine Antwort wie „ja" bedeutet ohne die Frage, auf die sie antwortet, nichts. Wenn ein Prompt aufgezeichnet wird, liest Failproof AI auch die letzte sichtbare Nachricht des Agenten aus dem Session-Transkript **zu diesem Zeitpunkt** und speichert sie zusammen mit dem Prompt. Jev erhält sie in einem eigenen Feld, als agentengeschrieben gekennzeichnet: Sie erklärt eine kurze Antwort und gilt allein niemals als Anfrage des Menschen. Sie ist das Einzige, wofür das Transkript gelesen wird, und das Schlimmste, was ein umgeschriebenes Transkript tun kann, ist eine vom Agenten geschriebene Nachricht dort einzutragen, wo eine vom Agenten geschriebene Nachricht erwartet wird.

Sie wird vom Ende des Transkripts gelesen, höchstens die letzten 4 MB. Unterstützte Transkriptformate sind Claude Code, Codex-Rollouts (ältere `agent_message`-Ereignisse und neuere `AgentMessage`-Einträge), Cursor, Copilot `events.jsonl` sowie das Pi-, Factory- und OpenClaw-Session-JSONL. Claude Codes eigene synthetische Nachrichten, API-Fehlermeldungen und Subagenten-(Sidechain-)Nachrichten werden übersprungen. Für Goose und OpenCode, die Sessions in SQLite speichern, für Devin, dessen Transkript ein einzelnes JSON-Dokument ist, sowie für OpenClaw, dessen `before_agent_run`-Ereignis keinen Transkriptpfad enthält, gibt es keinen Snapshot.

## Speicherung

| Eigenschaft | Wert |
| --- | --- |
| Speicherort | `~/.failproofai/state/semantic/sessions/<profile>/<session-id>.json`, wobei `<profile>` das Agenten-Profil ist, in das der Prompt eingegeben wurde: `<integration>.<instance-id>` für einen Agenten, den FailproofAI kennt (die Identität, auf die Cloud-Richtlinien abzielen), oder andernfalls nur `<integration>` |
| Berechtigungen | Datei `0600`, Verzeichnis `0700`. Jedes übergeordnete Verzeichnis bis zu `~/.failproofai` unterliegt derselben Regel wie das Verzeichnis von `jev.json`: Eines, in das jemand anderes **schreiben** kann, kann umbenannt und ersetzt werden — daher entfernt der Lesepfad diese Schreibbits, wo möglich, und liest **nichts**, wo dies nicht möglich ist. Ein aufgezeichneter Prompt ist dann abwesend statt gefälscht, und nichts wird freigegeben |
| Pro Session gespeichert | die letzten 5 Prompts; ein Prompt, der mit dem vorherigen identisch ist, ersetzt ihn, statt einen neuen Slot zu belegen |
| Zeitfenster | Prompts, die älter als 6 Stunden sind, werden ignoriert |
| Größe | Jeder Prompt und jede Agenten-Nachricht ist auf 6.000 Zeichen begrenzt, wobei Anfang und Ende erhalten bleiben |
| Secrets | Vor dem Schreiben mit denselben Mustern wie die `sanitize-*`-Richtlinien redigiert. Ein Text mit mehr als 48.000 Zeichen wird als seine ersten 28.800 und letzten 19.200 Zeichen redigiert, und der Text neben diesen Schnittstellen, wo ein Secret aufgeteilt worden sein könnte, wird niemals gespeichert |

Eine Session-ID, die etwas anderes als Buchstaben, Ziffern, `.`, `_` und `-` enthält oder länger als 128 Zeichen ist, wird niemals als Dateiname verwendet — für sie wird also nichts aufgezeichnet.

Eine Session-Datei existiert erst, nachdem ein Prompt darin aufgezeichnet wurde. Sie enthält nur Prompts — keinen Ursprungszustand, keinen Transkript-Marker — und wird gelöscht, sobald sie länger als das Sechsstunden-Fenster inaktiv war, wenn eine neue Session ihren ersten Prompt schreibt.

Ein Prompt wird nur für dasselbe Agenten-Profil und dieselbe Session-ID zurückgelesen, unter der er aufgezeichnet wurde. Session-IDs kommen vom Agenten, sodass zwei Profile dieselbe verwenden können; die Zuordnung nach Profil stellt sicher, dass die Worte eines Profils niemals als Anfrage eines anderen zählen. Dateien aus einem früheren Layout (`sessions/<session-id>.json`) können nicht angeben, welches Profil sie geschrieben hat, werden daher niemals gelesen und verfallen mit dem Sechsstunden-Fenster.

Nichts wird aufgezeichnet, sofern kein Jev-Endpunkt konfiguriert ist. Im FailproofAI-Cloud-Jev-Modus wird für ein Agenten-Profil nichts aufgezeichnet, dem keine Cloud-Jev-Prüfung zugewiesen ist und dessen Prüfung kein installiertes Pack enthält.

### Das Projektstammverzeichnis

„Innerhalb des Projekts" — wogegen `read-outside-workspace` und die anderen Pfadprüfungen urteilen — bedeutet innerhalb des Projekts, in dem sich die Session bei ihrem **ersten geprüften Aufruf** befand. Der Stamm wird dann fixiert, und ein späteres `cd` verschiebt ihn nicht; ein `cd` ändert jedoch weiterhin, wie ein relativer Pfad aufgelöst wird. Würde er dem `cd` folgen, würde `cd ~/.ssh` in einem Aufruf `~/.ssh` zum Projekt für den nächsten machen.

Die Fixierung erfolgt in `~/.failproofai/state/semantic/roots/<session-id>.json` und enthält `{root, at}`: Datei `0600`, Verzeichnis `0700`, und dieselbe Session-ID-Regel wie oben. Dateien, die älter als 7 Tage sind, werden gelöscht, wenn eine neue Session ihren Stamm fixiert. Ein `roots`-Verzeichnis, in das andere Benutzer schreiben können, wird ignoriert, und stattdessen wird der Stamm des Live-Verzeichnisses verwendet. Um eine Session neu zu fixieren, löschen Sie deren Datei.

## Bekannte Einschränkungen

- **Ein Prompt ist nur so vertrauenswürdig wie der Hook-Aufruf.** Alles hier liest den Payload, den der Harness auf den stdin des Hooks geschrieben hat. Ein Agent, der Befehle ausführen kann, kann den Harness ohne Benutzeroberfläche ausführen (`claude -p` und die sieben weiteren oben genannten) oder Failproof AIs eigene Hook-Binärdatei mit einem selbst erstellten Payload aufrufen und einen Prompt aufzeichnen, den niemand eingegeben hat. Dies ist der akzeptierte Kompromiss, der oben beschrieben wird: Er gibt nur reviewable Richtlinien frei, niemals eine hard — aber zwölf der fünfzehn reviewable eingebauten sind Denies, sodass ein gefälschter Prompt bei diesen zwölf einen echten Block in ein Allow verwandeln kann.
- **Sub-Agenten-Erkennung ist Claude-spezifisch.** Ein Payload, der `agent_id` enthält, wird auf keinem Harness aufgezeichnet. Das ist das Feld, das Claude Code, Factory Droid und Devin verwenden würden. Codex löst sein Prompt-Ereignis innerhalb von Sub-Agenten-Threads aus, Copilot führt In-Process-Sidekicks aus, Goose hat ein `delegate`-Tool und OpenClaw führt Personas aus — keines davon kennzeichnet den Payload auf eine erkennbare Weise, sodass ein Sub-Agenten-Prompt auf diesen Harnesses als eigener der Session aufgezeichnet wird. OpenClaws `openclaw.agentId` ist **nicht** dieses Merkmal: Das mitgelieferte Plugin setzt es bei jedem Run, auch beim des Eigentümers.
- **Scheduler ohne Markierung.** Claude Codes `schedule_wakeup` und `loop_wakeup` sowie OpenClaws `cron`- und `heartbeat`-Trigger werden abgelehnt, weil diese Harnesses es im Payload angeben. Gooses eigener Scheduler (`goose schedule add`) und Codex's `codex exec` geben nichts an, sodass ein von ihnen gestarteter Run wie jeder andere aufgezeichnet wird.
- **Die letzte Nachricht eines Agenten kann eine vom Agenten gewählte Nachricht sein.** Das Transkript ist nicht authentifiziert, sodass ein Agent, der sein eigenes Transkript schreibt, entscheiden kann, was seine „letzte Nachricht" besagt. Sie wird als agentengeschrieben gekennzeichnet und gibt allein nichts frei — beachten Sie jedoch, dass der v1-Pfad von `decide.ts` es ermöglicht, die deterministische Prüfung „Hat der Benutzer dieses Ziel benannt" zu erfüllen, sodass ein Agent, der sein Transkript kontrolliert, einen Zielnamen liefern kann, den ein Override benötigt.
- **Ein Prompt, der mit einer der maschinellen Erweiterungs-Überschriften beginnt, wird vollständig verworfen.** Beginnen Sie einen Prompt mit `# Selected text:`, `# Diff comments:`, `# Chrome tabs:` oder einer anderen Abschnittsüberschrift aus der ersten Gruppe oben, und schreiben Sie keine `## My request:`-Überschrift, so wird für diesen Turn nichts aufgezeichnet — und daher auch nichts freigegeben. Das ist beabsichtigt: Diese Abschnitte enthalten Text, den jemand anderes kontrolliert (ausgewählter Code, der Diff-Kommentar eines Reviewers, ein Seitentitel), und diesen als Ihre Worte aufzuzeichnen wäre das größere Versagen. Überschriften, die ein Entwickler plausiblerweise tippt, befinden sich in der zweiten Gruppe und verwerfen einen Prompt niemals allein.
- **OpenCode zeichnet in der Praxis nichts auf.** Sein `message.updated`-Ereignis enthält im aktuellen OpenCode keinen Text, und es löst auch für die untergeordneten Sessions aus, die sein Task-Tool erstellt, deren „Benutzer"-Nachricht der übergeordnete Agent geschrieben hat.
- **`CODEX_HOME` wird** von der Rollout-Erkennung in `lib/codex-sessions.ts` **nicht berücksichtigt**. Dies betrifft nur den Ort, an dem nach einem Agenten-Nachrichten-Snapshot gesucht wird, nicht die Frage, ob ein Prompt aufgezeichnet wird.
