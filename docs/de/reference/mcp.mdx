Verbinde ein KI-Tool mit Failproof AI Cloud und arbeite damit mit den Daten deiner Agenten. Dein Tool kann Sitzungen und Ereignisse abfragen, schreibgeschütztes SQL ausführen, Dashboards, Alerts, Insights, Audits und Richtlinien lesen und – sofern du die entsprechende Berechtigung besitzt – Änderungen vornehmen, wie z. B. einen Alert erstellen oder eine Richtlinie deployen.

Jeder Aufruf läuft mit **deinen eigenen** Berechtigungen in **einer** Organisation, die du beim Verbinden auswählst.

Es gibt eine Adresse für alle – gehostet oder selbst gehostet:

```text
https://gateway.befailproof.ai/mcp
```

## Client verbinden

Füge die Adresse deinem Client hinzu. Beim ersten Aufruf eines Tools öffnet sich dein Browser. Wähle aus, wo sich deine Failproof AI Cloud befindet, melde dich an, wähle eine Organisation und klicke auf **Erlauben**. **Abbrechen** stellt keine Verbindung her.

Die Seite zeigt den Namen der App und wohin sie zurückleitet. Eine App, die nicht durch ihre eigene Webadresse identifiziert wird, wird als **nicht verifizierte App** gekennzeichnet – fahre daher nur fort, wenn du diesen Vorgang gerade selbst von deinem Client aus gestartet hast.

<Tabs>
  <Tab title="Claude">
    Gehe in claude.ai oder Claude Desktop zu **Einstellungen → Connectors → Benutzerdefinierten Connector hinzufügen**. Benenne ihn `Failproof AI`, gib die Adresse ein, wähle **Hinzufügen** und dann **Verbinden**.

    Bei Team- und Enterprise-Plänen fügt ein Inhaber den Connector zunächst für die Organisation hinzu. Danach verbindet jede Person ihr eigenes Konto.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    Führe dann innerhalb von Claude Code `/mcp` aus, wähle `failproofai` und klicke auf **Authentifizieren**.
  </Tab>
  <Tab title="Cursor">
    Füge Folgendes zu `~/.cursor/mcp.json` oder zur `.cursor/mcp.json` deines Projekts hinzu:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor zeigt **Login erforderlich** neben dem Server an. Klicke darauf, um dich anzumelden.
  </Tab>
  <Tab title="Codex">
    Füge Folgendes zu `~/.codex/config.toml` hinzu:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    Führe dann `codex mcp login failproofai` aus.
  </Tab>
  <Tab title="Andere Clients">
    Jeder Client, der Remote-MCP-Server über Streamable HTTP mit OAuth unterstützt, funktioniert. Gib ihm die obige Adresse. Es ist keine Client-ID oder kein Secret zu konfigurieren.
  </Tab>
</Tabs>

## Eine Organisation pro Verbindung

Eine Verbindung agiert ausschließlich in der Organisation, die du ausgewählt hast. Um zwei Organisationen zu nutzen, füge den Server zweimal unter verschiedenen Namen hinzu, z. B. `failproofai-acme` und `failproofai-sandbox`, und verbinde jede mit ihrer eigenen Organisation.

Demo-Organisationen akzeptieren keine Verbindungen. Wähle stattdessen deine eigene Organisation.

## Berechtigungen

Eine Verbindung kann alles tun, was du in der Organisation tun kannst – innerhalb des unten aufgeführten Rahmens. Sie folgt deinen aktuellen Berechtigungen: Wenn ein Admin dir mehr Rechte gibt, erhält das Tool sie ebenfalls, und wenn etwas entzogen wird, verliert das Tool es beim nächsten Aufruf.

| Berechtigung | Erlaubt dem Tool |
| --- | --- |
| `events:read` | Ereignisse auflisten, Sitzungsübersicht lesen, Agenten und Umgebungen auflisten |
| `evaluations:read` | Sitzungen auflisten sowie Auswertungsergebnisse und -jobs lesen und zusammenfassen |
| `evaluations:trigger` | Auswertungen erstellen, neue Versionen veröffentlichen, aktivieren oder deaktivieren, auffüllen und eine Sitzung neu auswerten |
| `dashboards:read`, `dashboards:write` | Dashboards lesen oder erstellen, umbenennen und Abfragen hinzufügen |
| `queries:read`, `queries:write` | Gespeicherte Abfragen lesen oder speichern und bearbeiten |
| `queries:run` | Eine schreibgeschützte SQL-Abfrage ausführen und das Abfrageschema lesen |
| `alerts:read`, `alerts:write` | Alerts lesen oder erstellen, bearbeiten, pausieren, löschen und testen |
| `issues:read` | Insights lesen, bestätigen und kommentieren |
| `issues:create` | Ein Insight zu einem Alert öffnen |
| `issues:close` | Insights lösen und schließen |
| `audits:read`, `audits:write` | Audits, Durchläufe und Findings lesen oder Audits erstellen und bearbeiten sowie einen Durchlauf starten |
| `code_fixes:read` | Sehen, wie ein Insight behoben werden kann, und seinen Kontext für den eigenen Agenten abrufen |
| `code_fixes:write` | Eine Korrektur in Failproof AI Cloud starten, die einen Pull Request auf deinem GitHub öffnet |
| `policies:read`, `policies:write` | Richtlinien, Maschinen und Deployments lesen oder Richtlinien veröffentlichen, deployen und zurückrollen |

Einige Tools benötigen keine Berechtigung, da sie keine Organisationsdaten lesen: das Erstellen von Sitzungs- und Ereignis-Links sowie die Suche in dieser Dokumentation.

Ein KI-Tool kann niemals API-Keys, Benutzer, Einstellungen oder die Organisationsverwaltung berühren und kann keine Ereignisse senden.

## Änderungen genehmigen

Schreiboperationen fragen zunächst nach, wenn dein Client die Eingabeaufforderung anzeigen kann. Du siehst, was sich ändern wird, und wählst **Diese Änderung genehmigen**, um fortzufahren. Wenn du ablehnst oder innerhalb von etwa 4 Minuten nicht antwortest, ändert sich nichts. Manche Clients hören nach einer Minute auf zu warten, also antworte zeitnah.

<Warning>
  Bei einem Client, der keine Eingabeaufforderungen unterstützt, wird nicht nachgefragt, und ein Schreibvorgang wird ausgeführt, sobald der Client den Aufruf macht. Dort ist die eigene Bestätigung deines Clients die einzige – lasse sie daher für Schreib-Tools aktiviert.
</Warning>

## Verbundene Apps und Widerrufen

**Einstellungen → Integrationen → MCP** listet deine verbundenen Apps in der aktuellen Organisation auf, zusammen mit ihren Berechtigungen und der letzten Nutzung. **Widerrufen** trennt eine App sofort. Das Entfernen des Servers in deinem Client widerruft die Verbindung ebenfalls.

Du kannst bis zu 5 verbundene Apps pro Organisation haben. Wenn du dieselbe App erneut verbindest, wird ihre frühere Verbindung ersetzt.

## Selbst gehostete Deployments

Wähle beim Verbinden **Selbst gehostete Failproof AI Cloud** und gib die Adresse ein, unter der du dich anmeldest. Dein Deployment muss über öffentliches HTTPS erreichbar sein.

Tool-Aufrufe und ihre Ergebnisse werden über das gehostete Failproof AI-Gateway zwischen deinem KI-Tool und deinem Deployment weitergeleitet. Das Gateway speichert sie nicht.

## Was mit deinen Daten passiert

Ergebnisse gehen an das KI-Tool, das du verbunden hast, und der Anbieter dieses Tools verarbeitet sie gemäß seinen eigenen Nutzungsbedingungen. Bei jedem Tool-Aufruf protokolliert Failproof AI den Namen des Tools, sein Ergebnis, die Dauer und die Organisation – niemals die Argumente oder Ergebnisse. Siehe die [Datenschutzrichtlinie](https://befailproof.ai/privacy/).

## Fehlerbehebung

| Was du siehst | Was zu tun ist |
| --- | --- |
| „In einem anderen Browser gestartet" | Schließe die Anmeldung im Browser ab, den der Client geöffnet hat, mit aktivierten Cookies, und starte erneut vom Client aus |
| Ein Fehler nach **Erlauben** | Der Link funktioniert nur einmal und läuft nach 10 Minuten ab – starte daher erneut vom Client aus |
| Ein erwartetes Tool fehlt | Du hast nicht die entsprechende Berechtigung in dieser Organisation. Wende dich an einen Admin. Du musst dich nach Erhalt der Berechtigung nicht erneut verbinden |
| Der Client fordert dich wiederholt zur Anmeldung auf | Die Verbindung wurde widerrufen, du hast die Organisation verlassen oder sie war 90 Tage lang ungenutzt. Verbinde dich erneut |
| „Du hast 5 verbundene Apps" | Widerrufe eine unter **Einstellungen → Integrationen → MCP** und verbinde dich dann erneut |
