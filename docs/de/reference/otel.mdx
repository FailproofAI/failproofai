`failproofai otel` konfiguriert die optionale OpenTelemetry-Berichterstattung an FailproofAI Cloud. Verbinden Sie zunächst Ihren Rechner mit `failproofai config` und bitten Sie einen Organisations-Administrator, unter **Settings → OpenTelemetry** die Funktion zu aktivieren.

Die interaktive Einrichtung fragt nach OpenTelemetry, nachdem das Cloud-Schlüsselfeld und die Agent-Auswahl abgeschlossen sind. Dieser optionale Schritt ist standardmäßig auf „Nein" gesetzt. Wählen Sie „Ja", um OTEL-Agents auszuwählen; derselbe Aktivierungscode wird ausgeführt, sobald die Verbindung gespeichert wurde. Wenn Sie vor Abschluss der Einrichtung Esc drücken, werden keine Änderungen übernommen. Die unbeaufsichtigte Einrichtung, ein bereitgestellter Schlüssel, der Open-Source-Modus und das Beibehalten einer gespeicherten Verbindung aktivieren OpenTelemetry nicht automatisch.

## Einen Agent aktivieren

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Die unterstützten Agents sind `claude`, `codex` und `copilot` (VS Code). Die Copilot-Einrichtung erfordert eine ausführbare VS-Code-Datei oder eine installierte Copilot-Erweiterung. Ein übrig gebliebenes Einstellungsverzeichnis allein genügt nicht; die Einrichtung überspringt Copilot, wenn keines von beidem gefunden wird.

`--local` sendet an den lokalen Relay statt direkt an Cloud. Copilot verwendet den Relay automatisch, da seine Einstellungen den Authentifizierungs-Header nicht speichern können.

Der Relay lauscht ausschließlich auf Ihrem Rechner. Ihr konfigurierter FailproofAI-Daemon übernimmt die Änderung innerhalb weniger Sekunden; ein Neustart ist nicht erforderlich. Wenn eine andere Anwendung den Relay-Port belegt, meldet der Status diesen als inaktiv, und der Daemon läuft weiter.

<Warning>
Die Texterfassung ist standardmäßig aktiviert. Fügen Sie `--no-content` hinzu, um Eingabeaufforderungen und Tool-Details auszulassen. Agent-Versionen können unterschiedliche Inhaltssteuerungen bereitstellen; prüfen Sie, was Ihr Agent exportiert, bevor Sie ihn mit sensiblen Daten verwenden.
</Warning>

Codex exportiert ausschließlich Gesprächsprotokolle, keine internen Laufzeit-Traces oder Metriken. Ein explizit gesetztes `log_user_prompt = false` in Ihrer Codex-Konfiguration bleibt deaktiviert; bei der Aktivierung wird ein Hinweis ausgegeben, wenn diese Einstellung beibehalten wird.

### Einen Übermittlungsweg auswählen

Wenn die Transkript-Berichterstattung für einen Agent aktiv ist, fragt die Einrichtung:

> failproofai already sends Claude Code sessions to Cloud. Send them with OTEL instead? Transcript upload for Claude Code stops.

Der Standard ist „Nein". Mit `--yes` wird der Wechsel ohne Bestätigung akzeptiert. Andere Agents und die Richtlinien-Durchsetzung sind davon nicht betroffen.

Die Codex-Einrichtung wartet auf die Bestätigung der Collector-Änderung durch den Daemon, bevor die Exporter-Einstellungen geschrieben werden. Wenn die Bestätigung abläuft, warnt die Einrichtung, dass Sie warten sollten, bevor Sie Codex starten.

Config v2 speichert die gemerkte Tracing-Liste unter `agents.selected` (und den Erkennungsverlauf unter `agents.seen`). Die agentenbezogene Transkript-Einstellung verbleibt unter `collector.agents.<agent>.sessions`, der OTEL-Besitz unter `otel.agents` und die Relay-Einstellungen unter `collector.otlp.enabled` / `collector.otlp.port`. Diese getrennten Schlüssel halten alte OTEL-Konfigurationen lesbar: Die Einrichtung kann die Tracing-Liste ändern, ohne die Transportpräferenz oder den für die Wiederherstellung der Agent-Einstellungen erforderlichen Zustand zu verlieren.

## Einrichtung prüfen

```bash
failproofai otel status
```

Der Status zeigt jeden Agent, ob seine Einstellungen von FailproofAI verwaltet werden, sein Ziel, den Organisations-Ingest-Schalter, den Relay-Zustand und das letzte Relay-Upload-Ergebnis.

`unknown` beim Organisations-Schalter bedeutet, dass der Server diesen nicht bereitgestellt hat oder nicht erreichbar war. Dies ist kein Fehler und verhindert keine Konfiguration bei einer älteren Cloud-Version.

Wenn Cloud OTEL noch nicht unterstützt, behält der Relay abgelehnte Exporte, anstatt sie zu verwerfen. Wenn der Organisations-Ingest deaktiviert ist, schreibt `enable` nichts und beendet sich mit einem Fehler; bitten Sie einen Administrator, diesen zuerst zu aktivieren.

## Konfiguration für eine Anwendung ausgeben

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

Die Ausgabe ist ein Shell-Umgebungsblock für einen OTLP/HTTP-Exporter. Die Cloud-Ausgabe setzt `OTEL_EXPORTER_OTLP_ENDPOINT` auf die OTLP-Basis von Cloud, `https://<cloud>/otel`, und der Exporter hängt `/v1/<signal>` an; eine signalspezifische Variable wie `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` benötigt den vollständigen Pfad `https://<cloud>/otel/v1/logs`. Die lokale Ausgabe verweist auf den Relay, `http://127.0.0.1:<port>`. Die Cloud-Ausgabe enthält den konfigurierten API-Schlüssel; behandeln Sie diesen als Geheimnis. Die lokale Ausgabe lässt den Schlüssel weg. Um die lokale Ausgabe zu verwenden, aktivieren Sie zunächst einen lokalen Agent, damit der Relay läuft.

## Frühere Einstellungen wiederherstellen

```bash
failproofai otel disable claude
failproofai otel disable all
```

„Disable" stellt ausschließlich die von FailproofAI geschriebenen Einstellungen wieder her, behält nicht verwandte Änderungen und stellt die frühere Transkript-Berichterstattungs-Einstellung jedes Agents wieder her. Wenn der letzte verwaltete lokale Agent deaktiviert wird, stellt der Relay keine Exporte mehr entgegen.

Für Codex zeichnet „disable" außerdem `collector.agents.codex.sessions_resume_after` (Epoch-Millisekunden) auf. Vorhandene Rollout-Bytes gelten als zugestellt, sodass mit OTEL erfasste Sitzungen nicht erneut hochgeladen werden; spätere Ergänzungen fließen weiterhin über die Transkript-Berichterstattung.

Jeder Befehl unterstützt `--help`. Weitere Informationen zu Anwendungs- und Coding-Agent-Beispielen finden Sie unter [OpenTelemetry in Cloud](/de/agenteye/opentelemetry).
