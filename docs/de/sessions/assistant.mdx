Gib dem Failproof Assistant einen beliebigen Auftrag in Failproof AI – in natürlicher Sprache. Er kann Sitzungen und Fehler analysieren, Abfragen ausführen, Dashboards erstellen, Evaluierungen und Alerts untersuchen sowie beim Erstellen und Ausführen von Audits helfen, ohne dass du Aufgaben in Produktansichten oder CLI-Befehle übersetzen musst.

```text
Why did production checkout agents regress this week?
Build a dashboard for tool failures, latency, and evaluation scores.
Create an audit that finds agents retrying the same failed action without changing approach.
Show me the sessions behind the most common audit finding.
```

Der Assistent arbeitet mit den Daten und Berechtigungen, die in der aktiven Organisation verfügbar sind. Überprüfe die Nachweise und vorgeschlagenen Änderungen, bevor du Aktionen anwendest, die andere Benutzer oder Agents betreffen.

## Den Assistenten verwenden

<Tabs>
  <Tab title="Dashboard">
    1. Wähle **Open agent chat** und beschreibe, was du verstehen, erstellen oder durchführen möchtest.
    2. Verfolge die Tool-Aufrufe, Tabellen und Abfrageergebnisse des Assistenten während er arbeitet.
    3. Öffne die referenzierte Sitzung, den Alert oder die Abfrage, um das Ergebnis gegen die Quelldaten zu prüfen.
    4. Starte einen neuen Chat für eine andere Untersuchung oder nutze den Chat-Verlauf, um die gleiche Analyse fortzuführen.

    ![Der Cloud-Assistent beantwortet eine Observability-Frage mit unterstützender Analyse und Abfragen.](/images/dashboard/assistant.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp agent health
    fp agent models
    fp agent ask "Which production checkout agents had the most tool errors in the last 24 hours?"
    fp agent chats
    fp agent show <chat-id>
    fp agent ask "Open representative sessions" --chat <chat-id>
    ```

    Verwende `fp agent rename <chat-id> --title <title>`, um eine Untersuchung leicht erkennbar zu halten, und `fp agent delete <chat-id>`, um sie zu entfernen.
  </Tab>
</Tabs>

## Effektiv mit dem Assistenten arbeiten

- Gib zuerst ein Ziel vor; ergänze Umgebung, Workflow oder Zeitraum, wenn diese Grenzen relevant sind.
- Behandle generiertes SQL und Zusammenfassungen als Hilfsmittel für die Untersuchung, nicht als abschließenden Beweis.
- Öffne repräsentative Sitzungen, bevor du einen Audit, ein Issue, einen Alert oder eine Policy erstellst.
- Halte Filter für Organisation, Umgebung und Zeitraum explizit.
- Speichere nützliches SQL als Abfrage, damit ein anderer Operator das Ergebnis reproduzieren kann.

<Warning>
  Der Assistent kann nur das lesen, worauf dein aktueller Benutzer Zugriff hat. Erweitere keine Berechtigungen, um eine Frage zu beantworten – bitte stattdessen einen autorisierten Operator, die Untersuchung durchzuführen.
</Warning>
