Beauftragen Sie den Failproof Assistant, beliebige Aufgaben in Failproof AI in natürlicher Sprache auszuführen. Er kann Sitzungen und Fehler analysieren, Abfragen ausführen, Dashboards erstellen, Evaluierungen und Warnmeldungen untersuchen sowie Audits erstellen und durchführen – ohne dass Sie die Aufgabe in Produktoberflächen oder CLI-Befehle übersetzen müssen.

```text
Why did production checkout agents regress this week?
Build a dashboard for tool failures, latency, and evaluation scores.
Create an audit that finds agents retrying the same failed action without changing approach.
Show me the sessions behind the most common audit finding.
```

Der Assistant arbeitet mit den Daten und Berechtigungen der aktiven Organisation. Prüfen Sie seine Belege und vorgeschlagenen Änderungen, bevor Sie Aktionen anwenden, die andere Benutzer oder Agents betreffen.

## Den Assistant befragen

<Tabs>
  <Tab title="Dashboard">
    1. Wählen Sie **Open agent chat** und beschreiben Sie, was Sie verstehen, erstellen oder steuern möchten.
    2. Beobachten Sie während der Arbeit des Assistants seine Tool-Aufrufe, Tabellen und Abfrageergebnisse.
    3. Öffnen Sie die referenzierte Sitzung, Warnmeldung oder Abfrage, um das Ergebnis mit den Quelldaten zu verifizieren.
    4. Starten Sie einen neuen Chat für eine andere Untersuchung oder nutzen Sie den Chat-Verlauf, um die gleiche Analyse fortzusetzen.

    ![The Cloud assistant answering an observability question with supporting analysis and queries.](/images/dashboard/assistant.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp agent health
    fp agent models
    fp agent ask "Which production checkout agents had the most tool errors in the last 24 hours?"
    fp agent chats
    fp agent show <chat-id>
    fp agent ask "Open representative sessions" --chat <chat-id>
    ```

    Verwenden Sie `fp agent rename <chat-id> --title <title>`, um eine Untersuchung leicht wiedererkennbar zu halten, und `fp agent delete <chat-id>`, um sie zu entfernen.
  </Tab>
</Tabs>

## Effektiv mit dem Assistant arbeiten

- Nennen Sie zuerst ein Ziel; fügen Sie eine Umgebung, einen Workflow oder einen Zeitraum hinzu, wenn diese Einschränkungen relevant sind.
- Betrachten Sie generiertes SQL und Zusammenfassungen als Hilfsmittel für die Untersuchung, nicht als abschließende Belege.
- Öffnen Sie repräsentative Sitzungen, bevor Sie ein Audit, ein Issue, eine Warnmeldung oder eine Policy erstellen.
- Geben Sie Organisation, Umgebung und Zeitfilter stets explizit an.
- Speichern Sie nützliches SQL als Abfrage, damit ein anderer Operator das Ergebnis reproduzieren kann.

<Warning>
  Der Assistant kann nur das lesen, worauf Ihr aktueller Benutzer Zugriff hat. Erweitern Sie keine Berechtigungen, um eine Frage zu ermöglichen; bitten Sie stattdessen einen autorisierten Operator, die Untersuchung durchzuführen.
</Warning>
