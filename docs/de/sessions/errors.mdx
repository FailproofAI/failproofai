„Fehler" bietet eine fehlerorientierte Übersicht über alle Sitzungen. Gruppieren Sie nach Fehlertyp, Agent, Umgebung, Modell, Tool oder Zeitfenster, um wiederkehrende Betriebsprobleme zu identifizieren.

## Fehler untersuchen

<Tabs>
  <Tab title="Dashboard">
    1. Navigieren Sie zu **Beobachten → Fehler**.
    2. Filtern Sie nach Umgebung, Ereignistyp, Fehlertyp, Agent, Sitzungs-ID oder Suchtext.
    3. Erweitern Sie einen gruppierten Fehler, um die einzelnen Vorkommen anzuzeigen. Wählen Sie eine Zeile aus, um das genaue Ereignis in seiner Sitzung zu öffnen.
    4. Wählen Sie das Glocken-Symbol bei einem repräsentativen Fehler aus, um einen Alert für ähnliche Fehler einzurichten.

    ![Die Fehlerseite mit einem Fehler-Histogramm, gruppierten Fehlern und der Steuerung zum Erstellen eines Alerts.](/images/dashboard/errors.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp errors --env production --since 24h
    fp errors --error-type TimeoutError --agent-id checkout-agent
    fp errors --aggregate --env production --since 7d
    ```

    Verwenden Sie `fp events --full --session-id <id>`, wenn Sie die Rohdaten hinter einer Fehlerzusammenfassung benötigen.
  </Tab>
</Tabs>

## Einsatzbereiche

- Häufigste Fehlerklasse in der Produktionsumgebung ermitteln.
- Feststellen, ob ein bestimmtes Tool oder Modell einen Anstieg verursacht.
- Von einer aggregierten Anzahl zu repräsentativen Sitzungen springen.
- Einen Alert für wiederkehrende Fehler einrichten.
- Die betroffene Population in ein Audit einbeziehen.

Ein Fehler ist ein beobachtetes Ereignis. Eine fehlgeschlagene Evaluierung ist ein Qualitätsurteil, und ein Audit-Befund ist ein untersuchtes Fehlermuster. Beachten Sie diese Unterschiede, wenn Sie entscheiden, welchen Reaktionsworkflow Sie verwenden möchten.
