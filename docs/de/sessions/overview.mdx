Eine Session ist der beste Ausgangspunkt, wenn ein Agent unerwartet reagiert. Sie fasst die Modellanfragen, Antworten, Tool-Aufrufe, menschliche Interaktionen, Fehler, Auswertungen und Policy-Entscheidungen zusammen, die zu einem Run gehören.

Sessions sehen gleich aus, unabhängig davon, welches Harness sie erzeugt hat. Ein Claude Code-Run, der ein Repository umschreibt, ein Hermes-Agent, der einem Kunden in Slack antwortet, und ein mit dem SDK instrumentierter Python-Dienst landen alle im selben Trace-Format – eine einzige Ansicht deckt die gesamte Flotte ab.

Verfolgen Sie einen Agent-Run von seinem Ziel über Modellaufrufe und Tools bis hin zur endgültigen Antwort.

## Eine Session finden

<Tabs>
  <Tab title="Dashboard">
    1. Navigieren Sie in der Cloud-Seitenleiste zu **Observe → Sessions**.
    2. Legen Sie das Zeitfenster fest und filtern Sie nach Umgebung, Status, Agent oder Session-ID.
    3. Fügen Sie Score- oder Metrik-Bereiche hinzu, wenn Sie einen Qualitäts-, Kosten-, Token- oder Latenz-Schnitt benötigen.
    4. Wählen Sie eine Zeile aus, um den zugehörigen Trace zu öffnen. Verwenden Sie das Kopiersymbol neben der Session-ID beim Teilen.

    ![Die Sessions-Liste zeigt eine Zeile pro Run mit Filtern für Umgebung, Agent, Status und Auswertungsscore.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    Fügen Sie `--agents` hinzu, um Multi-Agent-Runs aufzuklappen, `--all` für die Paginierung oder `--fields`, um die Ausgabespalten auszuwählen.
  </Tab>
</Tabs>

## Was Sie tun können

- Einen Run nach Agent, Umgebung, Zeit, Modell, Ereignistyp oder Fehlerstatus finden.
- Die genaue Abfolge nachverfolgen, die zu einem Ergebnis geführt hat.
- Erfolgreiche und fehlgeschlagene Runs vergleichen.
- Die Belege öffnen, die von einem Audit-Befund oder Alert-Vorfall verwendet wurden.
- Eine Session exportieren, wenn Sie eine Offline-Aufzeichnung benötigen.

## Eine zuverlässige Untersuchungsreihenfolge

1. Das Session-Ziel und die Umgebung bestätigen.
2. Den ersten Fehler oder die erste unerwartete Entscheidung finden – nicht nur den abschließenden Fehler.
3. Den Modellkontext und die Tool-Eingabe unmittelbar davor prüfen.
4. Retries, Latenz und menschliche Unterbrechungen überprüfen.
5. Auswertungsscores und Policy-Entscheidungen reviewen.
