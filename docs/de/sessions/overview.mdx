Eine Session ist der beste Ausgangspunkt, wenn sich ein Agent unerwartet verhält. Sie verknüpft die Modellanfragen, Antworten, Tool-Aufrufe, menschliche Interaktionen, Fehler, Auswertungen und Policy-Entscheidungen, die zu einem Lauf gehören.

Sessions sehen gleich aus, unabhängig davon, welches Harness sie erzeugt hat. Ein Claude Code-Lauf, der ein Repository umschreibt, ein Hermes-Agent, der einem Kunden in Slack antwortet, und ein mit dem SDK instrumentierter Python-Dienst landen alle im selben Trace-Format – so deckt eine einzige Ansicht die gesamte Flotte ab.

Verfolgen Sie einen Agent-Lauf von seinem Ziel über Model-Aufrufe und Tools bis zur abschließenden Antwort.

## Eine Session finden

Wenn eine Session nach Erreichen Ihres Laufkontingents im Cold Storage gehalten wurde,
werden durch eine Erhöhung des Kontingents innerhalb desselben Abrechnungszeitraums
berechtigte Sessions älteste zuerst freigegeben. Wiederholte Zustellversuche führen nicht dazu,
dass eine Session das Kontingent doppelt verbraucht.

<Tabs>
  <Tab title="Dashboard">
    1. Navigieren Sie in der Cloud-Seitenleiste zu **Observe → Sessions**.
    2. Legen Sie das Zeitfenster fest und filtern Sie nach Umgebung, Status, Agent oder Session-ID.
    3. Fügen Sie Score- oder Metrik-Bereiche hinzu, wenn Sie einen Ausschnitt nach Qualität, Kosten, Token oder Latenz benötigen.
    4. Wählen Sie eine Zeile aus, um den zugehörigen Trace zu öffnen. Verwenden Sie das Kopiersymbol neben der Session-ID beim Teilen.

    ![Die Sessions-Liste mit einer Zeile pro Lauf sowie Filtern für Umgebung, Agent, Status und Auswertungs-Score.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    Fügen Sie `--agents` hinzu, um Multi-Agent-Läufe aufzuklappen, `--all` für die Paginierung oder `--fields`, um Ausgabespalten auszuwählen.
  </Tab>
</Tabs>

## Was Sie tun können

- Einen Lauf nach Agent, Umgebung, Zeit, Modell, Event-Typ oder Fehlerzustand finden.
- Die genaue Abfolge nachverfolgen, die zu einem Ergebnis geführt hat.
- Erfolgreiche und fehlgeschlagene Läufe vergleichen.
- Die Belege öffnen, die einem Audit-Befund oder einem Alert-Vorfall zugrunde liegen.
- Eine Session exportieren, wenn Sie eine Offline-Aufzeichnung benötigen.

## Eine verlässliche Untersuchungsreihenfolge

1. Ziel und Umgebung der Session bestätigen.
2. Den ersten Fehler oder die erste unerwartete Entscheidung finden – nicht nur den abschließenden Fehler.
3. Den Modellkontext und den Tool-Eingabewert unmittelbar davor prüfen.
4. Wiederholungsversuche, Latenz und menschliche Unterbrechungen überprüfen.
5. Auswertungs-Scores und Policy-Entscheidungen überprüfen.
