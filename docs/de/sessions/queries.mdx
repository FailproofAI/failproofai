Abfragen bilden die flexible Schicht unterhalb von Dashboards, Audits und Untersuchungen. Teste eine Idee mit Ad-hoc-SQL, und speichere die Abfrage, sobald sie Teil eines regelmäßigen Workflows wird.

## Eine Abfrage erstellen und ausführen

<Tabs>
  <Tab title="Dashboard">
    1. Gehe zu **Analyze → Queries** und wähle **new query**.
    2. Öffne den Schema-Browser und wähle Felder aus den Ereignis-, Sitzungs- oder Auswertungsdaten.
    3. Schreibe SQL, füge bei Bedarf Parameter hinzu und führe die Abfrage aus.
    4. Speichere sie mit einem aussagekräftigen Namen und einer Beschreibung, und verwende **add to dashboard**, wenn das Ergebnis überwacht werden soll.

    Der Abfrage-Editor vereint das Ereignisschema, SQL, Parameter und eine Ergebnisvorschau, sodass du die Fragestellung vor dem Speichern validieren kannst.

    ![Der SQL-Abfrage-Editor mit Schema-Browser und Live-Ergebnisraster.](/images/dashboard/query-lab.png)

    Gespeicherte Abfragen erscheinen anschließend in der gemeinsamen Bibliothek, wo Teammitglieder sie erneut ausführen oder ihre Ergebnisse zu Dashboards hinzufügen können.

    ![Die gespeicherte Abfragebibliothek mit wiederverwendbaren vordefinierten und benutzerdefinierten Abfragen.](/images/dashboard/queries.png)

    Verwende einen klaren Namen und eine aussagekräftige Beschreibung, damit das Ergebnis auch ohne erneutes Öffnen des SQL verständlich bleibt.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    Verwende `fp query list`, um IDs zu finden, und `fp query delete <query-id>`, um eine gespeicherte Abfrage zu entfernen.
  </Tab>
</Tabs>

## Häufige Anwendungsfälle

- Sitzungen finden, in denen dasselbe Tool wiederholt aufgerufen wurde.
- Auswertungswerte über verschiedene Modelle oder Umgebungen hinweg vergleichen.
- Die Zeit zwischen einer menschlichen Wartezeit und der Fortsetzung messen.
- Richtlinienablehnungen identifizieren, auf die eine erfolgreiche Alternative folgte.
- Eine Kohorte für ein Audit zusammenstellen.

Öffne **Queries → Schema**, bevor du mit unbekannten Feldern arbeitest. Bevorzuge explizite Zeit- und Umgebungsfilter und halte Ergebnislimits während der Erkundungsphase ein.

<Warning>
  Eine Abfrage kann ein verdächtiges Muster identifizieren, begründet jedoch für sich genommen noch keinen Fehlermodus. Öffne repräsentative Traces oder führe ein Audit durch, bevor du das Ergebnis in eine Richtlinie überführst.
</Warning>
