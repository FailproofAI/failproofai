---
title: "Verhindern Sie Ihren ersten Fehler mit einer Policy"
description: "Erstellen Sie eine Policy-Version, stellen Sie sie im Beobachtungsmodus bereit und setzen Sie sie anschließend durch."
icon: "shield-check"
---

Verwenden Sie eine Policy erst dann, wenn Sie die unsichere Aktion und die legitimen Aktionen, die weiterhin erlaubt bleiben müssen, klar beschreiben können.

<Tabs>
  <Tab title="Dashboard">
    <Steps>
      <Step title="Policy erstellen">
        Gehen Sie zu **Admin → Policy-Editor**. Beginnen Sie mit der Demo-Policy, überprüfen oder bearbeiten Sie deren Quellcode und wählen Sie dann **Version veröffentlichen**. Durch die Veröffentlichung wird die unveränderliche Version erstellt, die Sie auf Maschinen bereitstellen können.

        ![Die Compose-Ansicht des Policy-Editors mit einer Demo-Policy, die als unveränderliche Version veröffentlicht werden soll.](/images/dashboard/policy-editor.png)
      </Step>
      <Step title="Auf einer Maschine bereitstellen">
        Gehen Sie zu **Admin → Durchsetzung**, erweitern Sie die Zielmaschine und wählen Sie **Diese Maschine bearbeiten**. Fügen Sie die veröffentlichte Demo-Policy hinzu, fixieren Sie deren Version, wählen Sie **Beobachten** und wenden Sie die Bereitstellung an.

        ![Der Editor für die Maschinenbereitstellung mit einer ausgewählten veröffentlichten Policy-Version im Beobachtungsmodus, bevor die Bereitstellung angewendet wird.](/images/dashboard/enforcement-editor.png)
      </Step>
      <Step title="Policy überprüfen">
        Führen Sie eine neue Agent-Sitzung auf dieser Maschine aus und öffnen Sie dann **Beobachten → Policy**. Wählen Sie die Maschine aus und bestätigen Sie, dass die Demo-Policy in der Policy-Zuordnung und der Entscheidungszeitlinie angezeigt wird. Der Beobachtungsmodus zeichnet auf, was die Policy tun würde, ohne die Aktion zu blockieren.

        ![Die Policy-Seite mit Entscheidungsgesamtzahlen, Durchsetzungsaktivität im Zeitverlauf sowie lokalen und Cloud-verwalteten Policy-Zuordnungen.](/images/dashboard/policy-observe.png)
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    Die Erstellung von Cloud-Policies und die Fleet-Bereitstellung sind administrative Workflows. Verwenden Sie die lokale CLI, um dieselbe Policy vor der Veröffentlichung zu validieren:

    ```bash
    failproofai policies --install --custom ./payment-retry.policies.ts \
      --cli claude --scope project
    failproofai config --status
    ```

    Verwenden Sie `fp`, um Cloud-sichtbare Policy-Entscheidungen zu prüfen:

    ```bash
    fp events --event-type hook_completed --env production --since 24h
    fp sessions --env production --since 24h
    ```

    Die Cloud CLI stellt keine Routen für die ausschließlich durch Administratoren verwaltete Durchsetzungsbereitstellung bereit. Veröffentlichen Sie Versionen über **Admin → Policy-Editor** und stellen Sie sie über **Admin → Durchsetzung** bereit.
  </Tab>
</Tabs>
