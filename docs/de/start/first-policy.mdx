Beginnen Sie mit einem Verhalten, das Sie unterbinden möchten, und einer legitimen Aktion, die weiterhin funktionieren muss.

## Zuerst eine geprüfte Richtlinie ausprobieren

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI enthält 39 geprüfte Richtlinien. Schauen Sie in den [Katalog](/de/policies/builtin-catalog), bevor Sie eine neue schreiben.

## Eine eigene Richtlinie schreiben und testen

<Steps>
  <Step title="Eine funktionierende Richtlinie erstellen">
    ```bash
    failproofai publish --init guards.mjs
    ```

    Dies schreibt eine Richtlinie, die `git push --force` blockiert. Bearbeiten Sie sie für Ihre eigene Regel.
  </Step>
  <Step title="Auf diesem Computer durchsetzen">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    Fordern Sie Ihren Agenten auf, die blockierte Aktion auszuführen, und überprüfen Sie dann **Policies → Activity** im lokalen Dashboard.
  </Step>
  <Step title="Behalten oder entfernen">
    Legen Sie eine `*policies.mjs`-Datei unter `.failproofai/policies/` ab, um sie automatisch zu laden.

    Explizite benutzerdefinierte Dateien entfernen Sie mit:

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## Teilen

Ein öffentliches Paket veröffentlichen:

```bash
failproofai publish
```

Anschließend kann es jeder mit `failproofai policies add <owner>/<repo>` installieren. Fügen Sie das GitHub-Topic `failproofai-policies` selbst hinzu, damit der [Policy Hub](https://befailproof.ai/policy-hub/) es indizieren kann.

Für ein Cloud-Rollout:

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  Ein einfaches `--add checkout-guard` setzt sofort durch. Fügen Sie `:observe` hinzu, um aufzuzeichnen, was die Richtlinie tun würde, ohne den Agenten zu blockieren.
</Warning>

Weitere Informationen zum vollständigen Ablauf finden Sie unter [Paket veröffentlichen](/de/policies/publish-a-pack) oder [Richtlinien deployen](/de/policies/deploy).
