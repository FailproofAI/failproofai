---
title: "Verhindern Sie Ihren ersten Fehler mit einer Richtlinie"
description: "Erstellen Sie eine Richtlinienversion, stellen Sie sie im Beobachtungsmodus bereit und erzwingen Sie sie dann."
icon: "shield-check"
---

Verwenden Sie eine Richtlinie erst, wenn Sie die unsichere Aktion und die legitimen Aktionen, die weiterhin erlaubt sein müssen, beschreiben können.

<Tabs>
  <Tab title="Dashboard">
    <Steps>
      <Step title="Richtlinie erstellen">
        Gehen Sie zu **Admin → Richtlinien-Editor**. Beginnen Sie mit der Demo-Richtlinie, überprüfen oder bearbeiten Sie deren Quellcode, und wählen Sie dann **Version veröffentlichen**. Durch die Veröffentlichung wird die unveränderliche Version erstellt, die Sie auf Maschinen bereitstellen können.

        ![Die Compose-Ansicht des Richtlinien-Editors mit einer Demo-Richtlinie, die als unveränderliche Version bereit zur Veröffentlichung ist.](/images/dashboard/policy-editor.png)
      </Step>
      <Step title="Auf einer Maschine bereitstellen">
        Gehen Sie zu **Admin → Durchsetzung**, erweitern Sie die Zielmaschine und wählen Sie **diese Maschine bearbeiten**. Fügen Sie die veröffentlichte Demo-Richtlinie hinzu, fixieren Sie deren Version, wählen Sie **Beobachten** und wenden Sie die Bereitstellung an.

        ![Der Maschinen-Bereitstellungseditor mit einer ausgewählten veröffentlichten Richtlinienversion im Beobachtungsmodus, bevor die Bereitstellung angewendet wird.](/images/dashboard/enforcement-editor.png)
      </Step>
      <Step title="Richtlinie überprüfen">
        Führen Sie eine neue Agentensitzung auf dieser Maschine aus und öffnen Sie dann **Beobachten → Richtlinie**. Wählen Sie die Maschine aus und bestätigen Sie, dass die Demo-Richtlinie in der Richtlinienzuordnung und der Entscheidungszeitachse erscheint. Der Beobachtungsmodus zeichnet auf, was die Richtlinie tun würde, ohne die Aktion zu blockieren.

        ![Die Richtlinien-Seite mit Entscheidungsgesamtzahlen, Durchsetzungsaktivität im Zeitverlauf sowie lokalen und Cloud-verwalteten Richtlinienzuordnungen.](/images/dashboard/policy-observe.png)
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    Das Erstellen von Cloud-Richtlinien und die Fleet-Bereitstellung sind administrative Workflows. Verwenden Sie die lokale CLI, um dieselbe Richtlinie vor der Veröffentlichung zu validieren:

    ```bash
    failproofai policies --install --custom ./payment-retry.policies.ts \
      --cli claude --scope project
    failproofai config --status
    ```

    Verwenden Sie `fp`, um Cloud-sichtbare Richtlinienentscheidungen zu prüfen:

    ```bash
    fp events --event-type hook_completed --env production --since 24h
    fp sessions --env production --since 24h
    ```

    Beide Schritte sind auch über die CLI verfügbar: `fp policies publish <id> <file>` erstellt eine Version und `fp fleet deploy <machine-id> --add <id>` stellt sie auf einer Maschine bereit. Die Dashboard-Entsprechungen sind **Admin → Richtlinien-Editor** und **Admin → Durchsetzung**.
  </Tab>
</Tabs>
