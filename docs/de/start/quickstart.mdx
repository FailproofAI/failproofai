Dieser Schnellstart richtet eine Maschine für das Session-Reporting ein, führt ein Audit durch und stellt eine Policy bereit. Nutzen Sie den Skill zur Einrichtung oder folgen Sie den manuellen Schritten.

**Welcher Weg passt zu Ihnen?** Wenn Ihr Agent in einem der 12 unterstützten [Harnesses](/de/reference/harnesses) läuft — einem Coding-CLI oder einem Gateway wie Hermes oder OpenClaw — folgen Sie den nachstehenden Schritten; Sie benötigen Node.js 20.9 oder neuer. Wenn Ihr Agent kein Harness hat, instrumentieren Sie ihn mit dem [Python SDK](/de/reference/custom-agents) für Tracing und Audits und steigen Sie dann bei [Ersten Fehlercheck ausführen](/de/start/first-audit) wieder ein; die Durchsetzung erfordert auf diesem Weg einen Hook in Ihrer Laufzeitumgebung.

  <Tab title="Manuelle Einrichtung">
    ## Installation

<Steps>
  <Step title="Failproof AI installieren und verbinden">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    Dieser eine Befehl erledigt die gesamte Einrichtung: Er installiert den lokalen Daemon (einmalig als Root), verbindet Hooks mit allen gefundenen Agent-CLIs und verbindet diese Maschine mit der Cloud.

    Bei **Connect to cloud** beginnt die Einrichtung sofort mit der Anmeldung bei FailproofAI Cloud (drücken Sie Tab für weitere Optionen: API-Key einfügen oder Open Source verwenden). Es wird ein Link in Ihrem Browser geöffnet (über SSH oder auf einer Maschine ohne Display wird der Link ausgegeben, damit Sie ihn auf einem beliebigen Gerät öffnen können). Registrieren oder melden Sie sich an, bestätigen Sie die Organisation — oder erstellen Sie direkt eine neue — und klicken Sie auf **Authorize**. Name und Berechtigungen des Keys werden für Sie festgelegt. Sie benötigen vorab kein Konto.

    Das Terminal erkennt dies automatisch und zeigt an, wer die Genehmigung erteilt hat und für welche Organisation. Bestätigen Sie die zu tracenden Agents, und die Einrichtung ist abgeschlossen. Der Key der Maschine wird erst in diesem Moment erstellt, nachdem der Daemon installiert wurde — ein abgebrochener Vorgang hinterlässt also keinen Key. Er erscheint unter **Administration → Keys** mit der Bezeichnung **cli login** und kann dort widerrufen werden.

    <Accordion title="Kein Browser oder Terminal verfügbar? Verwenden Sie einen Key (CI, Container, Provisionierungsskripte)">
      Gehen Sie im [Failproof AI-Dashboard](https://app.befailproof.ai) zu **Administration → Keys** und erstellen Sie einen Key mit `events:add` und `policies:pull`. Wenn Sie [Jev über FailproofAI Cloud](/de/reference/jev-cloud) nutzen möchten, wählen Sie das **machine**-Preset, das auch `jev:evaluate` gewährt. Kopieren Sie das einmalige Secret und lesen Sie es auf der Zielmaschine in eine Shell ein — `read -s` nimmt es an einer Eingabeaufforderung entgegen, die keine Eingabe anzeigt:

      ```bash
      read -rs FAILPROOFAI_KEY && export FAILPROOFAI_KEY
      FAILPROOFAI_CLOUD_TOKEN="$FAILPROOFAI_KEY" failproofai config
      ```

      Den Key über die Umgebungsvariable statt über `--token` zu übergeben, hält ihn aus `ps` heraus, wo jeder Benutzer der Maschine die Argumente eines Befehls lesen kann. Er bleibt damit nicht aus der Shell-History heraus — das erreicht `read -s`. In CI sollten Sie ihn als maskiertes Secret einschleusen und Shell-Tracing (`set -x`) deaktiviert lassen, da sonst der Trace ihn ausgibt. Bei einem interaktiven Lauf können Sie auch bei **Connect to cloud** die Option **Paste an API key** wählen.
    </Accordion>

    Session-Transkripte werden standardmäßig übermittelt. Fügen Sie `--no-transcripts` hinzu, um Hook-Aktivitäten und Policy-Entscheidungen ohne Transkriptinhalt zu melden.

    <Warning>
      Greifen Sie hier nicht zu `failproofai config --connect <url>`. Dieses Flag registriert eine Maschine, die **bereits** eingerichtet ist, und kehrt sofort zurück — ohne Daemon, ohne Hooks — sodass die Maschine in der Cloud erscheinen würde, ohne etwas zu erfassen oder durchzusetzen.
    </Warning>

    Wenn diese Maschine bereits Agent-Historie hat, zeigen Sie die letzten sieben Tage in der Vorschau an, importieren Sie sie und warten Sie, bis die Übertragung abgeschlossen ist. Überspringen Sie diesen Schritt auf einer neuen Maschine.

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    Öffnen Sie **Sessions** in Failproof AI und wählen Sie eine importierte Session aus.
  </Step>
  <Step title="Failproof AI mit einem Harness verbinden">
    Der vorherige Schritt hat bereits alle erkannten Agent-CLIs verbunden. Führen Sie ihn für ein einzelnes Harness erneut aus, wenn Sie es benötigen, oder um ein nachträglich installiertes Harness hinzuzufügen. Alle 12 sind gültige `--cli`-Werte — `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, `goose`.

    ```bash
    failproofai policies --install --cli claude --scope user     # ein Coding-CLI
    failproofai policies --install --cli hermes --scope user     # ein Slack/Telegram-Gateway
    ```

    Das Blockieren eines Tool-Calls vor seiner Ausführung wird auf allen 12 unterstützt. Turn-End-Gates werden auf 8 unterstützt — die harnessspezifische Matrix finden Sie unter [Durchsetzungsfähigkeit](/de/reference/harnesses#enforcement-capability).
  </Step>
  <Step title="Durchsetzungsregeln festlegen">
    Das Verbinden von Hooks aktiviert keine Policy. Die Einrichtung wählt absichtlich keine aus — diese Entscheidung liegt bei Ihnen — nehmen Sie daher ein Pack:

    ```bash
    failproofai policies add FailproofAI/policies
    ```

    Das Pack wird aus seinem GitHub-Release abgerufen, prüfsummenverifiziert und auf den exakt aufgelösten Tag gepinnt. Es enthält 39 Policies und aktiviert die 10, die sein Manifest als sicher für den unbeaufsichtigten Betrieb markiert. Nutzen Sie diese, um lokale Policy-Entscheidungen zu beobachten und die Durchsetzung auszuprobieren, bevor Failproof AI Ihre Sessions auditiert und Policies für Ihre Agents schreibt.

    Lesen Sie jedes Pack vor der Übernahme mit `failproofai policies show <owner>/<repo>`, und lesen Sie [Policy-Packs](/de/policies/packs) für die Übernahme nur eines Teils davon.

    Bis dieser Schritt ausgeführt wird, ist das einzige aktive Durchsetzungselement `block-failproofai-commands` — der stets aktive Schutz, der verhindert, dass ein Agent Failproof AI deaktiviert. `failproofai policies` listet auf, was aktiv ist.
  </Step>
  <Step title="Verhalten auditieren">
    Folgen Sie [Ersten Fehlercheck ausführen](/de/start/first-audit). Verwenden Sie ein konkretes Ziel, z. B. „Sessions finden, bei denen der Agent ein fehlschlagendes Tool ohne Änderung seiner Vorgehensweise erneut versucht hat."
  </Step>
  <Step title="Den Fehler verhindern">
    Folgen Sie [Ersten Fehler mit einer Policy verhindern](/de/start/first-policy). Beginnen Sie im Beobachtungsmodus, prüfen Sie Treffer, und setzen Sie dann die überprüfte Version durch.
  </Step>
</Steps>

<Check>
  Führen Sie `failproofai config --status` aus. Eine funktionsfähige Einrichtung meldet die Cloud-Verbindung, den Daemon-Zustand und ob die Durchsetzung pausiert ist.
</Check>

## Jev-Einrichtung

Verwenden Sie [Jev](/de/start/use-jev), um abgeschlossene Sessions anhand einer Frage mit bekannten Antworten zu bewerten oder um Tool-Calls im Kontext zu prüfen, bevor sie ausgeführt werden. Die Seite **Jev verwenden** enthält beide Einrichtungspfade.
