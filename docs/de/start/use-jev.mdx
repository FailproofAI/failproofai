Jev hilft an zwei Punkten eines Agenten-Durchlaufs: Eine abgeschlossene Sitzung anhand bekannter Antworten bewerten oder einen Tool-Aufruf im Kontext der gestellten Aufgabe überprüfen.

<Tabs>
  <Tab title="Jev-Evaluierungen">
    Verwende eine Jev-Evaluierung, wenn eine abgeschlossene Sitzung anhand einer Frage mit wenigen bekannten Antworten bewertet werden kann, zum Beispiel: „Hat der Kunde nach einer Rückerstattung gefragt? Antworte mit Ja oder Nein." Damit lassen sich Muster über mehrere Sitzungen hinweg erkennen.

    ## Eine Evaluierung erstellen

    Öffne im Cloud-Dashboard **Analyze → eval authoring → new eval**. Gib eine Frage mit festen Antwortmöglichkeiten ein, wähle **draft** und überprüfe, ob ein Classifier-Score ausgewählt wurde. [Teste sie](/de/evaluations/test) mit echten Sitzungen und stelle sie dann bereit.

    ![Das gemeinsame Formular zur Erstellung von Evaluierungen, in dem du eine Frage beschreibst, den Entwurf überprüfst und ihn bereitstellst. Dieser Screenshot zeigt einen Code-Entwurf; verwende für Jev eine Frage mit festen Antwortmöglichkeiten.](/images/dashboard/eval-authoring-draft.png)

    ## Die Ergebnisse lesen

    Nachdem eine neue Sitzung abgeschlossen ist, öffne **Observe → Evaluations** oder verwende die Cloud-CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    Die CLI liest Ergebnisse; das Erstellen einer Jev-Evaluierung erfolgt derzeit über das Dashboard. Unter [Jev-Evaluierungen](/de/evaluations/jev) findest du Fragetypen und Beispiele.
  </Tab>
  <Tab title="Jev-Richtlinien">
    Verwende die Jev-Richtlinienüberprüfung, wenn eine auf String-Matching basierende Richtlinie den Kontext deiner Anfrage benötigt, um zu entscheiden, ob ein Tool-Aufruf sicher ist. Beginne im **observe**-Modus, damit du Jevs Antworten einsehen kannst, während deine installierten Richtlinien weiterhin über jeden Aufruf entscheiden.

    Jevs Prüfungen stammen aus einem Paket; Failproof AI liefert keines mit. Bis du eines installierst, fragt Jev nichts ab – auch wenn es konfiguriert ist:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Cloud-Jev einrichten

    Öffne im Cloud-Dashboard **Administration → Keys** und erstelle einen Schlüssel mit dem **machine**-Preset. Verwende ihn mit `failproofai config`, wie im [Schnellstart](/de/start/quickstart) beschrieben. Auf einem Gerät ohne bestehende Jev-Konfiguration wird Cloud-Jev damit im observe-Modus aktiviert. Überprüfe die Verbindung mit:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Einen eigenen Endpunkt verwenden

    Öffne im lokalen Dashboard **Settings → Jev**. Wähle den Anbieter, füge sein Token ein, wähle **observe** und schalte Jev ein.

    ![Das lokale Jev-Einstellungsfenster mit einem Anbieter, einem Token-Feld und ausgewähltem observe-Modus.](/images/dashboard/jev-settings.png)

    Oder konfiguriere und teste deinen Endpunkt im Terminal:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Weise einen eingebundenen Agenten an, sein Datei-Lese-Tool auf `README.md` anzuwenden. Bestätige, dass dieser Tool-Aufruf in der Sitzung erscheint, und überprüfe ihn dann unter **Policies → Activity** im lokalen Dashboard. Sobald die observe-Ergebnisse stimmig aussehen, erklärt [Jev-Richtlinien](/de/policies/jev), wann die Durchsetzung sinnvoll ist. Informationen zu Anbietern und Konfiguration findest du in der [Integrations-Referenz](/de/reference/jev).
  </Tab>
</Tabs>
