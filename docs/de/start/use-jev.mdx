Jev hilft an zwei Punkten eines Agenten-Laufs: eine abgeschlossene Sitzung anhand bekannter Antworten bewerten oder einen Tool-Aufruf im Kontext Ihrer Anfrage an den Agenten überprüfen.

<Tabs>
  <Tab title="Jev-Evaluierungen">
    Verwenden Sie eine Jev-Evaluierung, wenn eine abgeschlossene Sitzung anhand einer Frage mit wenigen bekannten Antworten bewertet werden kann, z. B. „Hat der Kunde nach einer Erstattung gefragt? Antworten Sie mit Ja oder Nein." Dies hilft Ihnen, Muster über Sitzungen hinweg zu erkennen.

    ## Eine Evaluierung erstellen

    Öffnen Sie im Cloud-Dashboard **Analyze → eval authoring → new eval**. Geben Sie eine Frage mit festen Antworten ein, wählen Sie **draft** aus und prüfen Sie, ob eine Klassifizierungsbewertung gewählt wurde. [Testen Sie diese](/de/evaluations/test) an echten Sitzungen und veröffentlichen Sie sie anschließend.

    ![Das gemeinsame Eval-Authoring-Formular, in dem Sie eine Frage beschreiben, den Entwurf überprüfen und ihn veröffentlichen. Dieser Screenshot zeigt einen Code-Entwurf; verwenden Sie für Jev eine Frage mit festen Antworten.](/images/dashboard/eval-authoring-draft.png)

    ## Die Bewertungen lesen

    Nachdem eine neue Sitzung abgeschlossen ist, öffnen Sie **Observe → Evaluations** oder verwenden Sie die Cloud-CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    Die CLI liest Bewertungen; das Erstellen einer Jev-Evaluierung erfolgt derzeit über das Dashboard. Siehe [Jev-Evaluierungen](/de/evaluations/jev) für Fragetypen und Beispiele.
  </Tab>
  <Tab title="Jev-Richtlinien">
    Verwenden Sie die Jev-Richtlinienüberprüfung, wenn eine auf Zeichenkettenabgleich basierende Richtlinie den Kontext Ihrer Anfrage benötigt, um zu entscheiden, ob ein Tool-Aufruf sicher ist. Beginnen Sie im **observe**-Modus, damit Sie die Antworten von Jev prüfen können, während Ihre installierten Richtlinien weiterhin jeden Aufruf entscheiden.

    Jevs Prüfungen stammen aus einem Paket; Failproof AI liefert keines mit. Bis Sie diese installieren, stellt Jev keine Fragen, auch wenn es konfiguriert ist:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Cloud-Jev einrichten

    Öffnen Sie im Cloud-Dashboard **Administration → Keys** und erstellen Sie einen Schlüssel mit der Voreinstellung **machine**. Verwenden Sie ihn mit `failproofai config`, wie im [Schnellstart](/de/start/quickstart) gezeigt. Auf einem Rechner ohne vorhandene Jev-Konfiguration aktiviert dies Cloud-Jev im observe-Modus. Überprüfen Sie die Verbindung mit:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Eigenen Endpunkt verwenden

    Öffnen Sie im lokalen Dashboard **Settings → Jev**. Wählen Sie den Anbieter aus, fügen Sie dessen Token ein, wählen Sie **observe** und aktivieren Sie Jev.

    ![Das lokale Jev-Einstellungsfenster mit einem Anbieter, Tokenfeld und ausgewähltem observe-Modus.](/images/dashboard/jev-settings.png)

    Oder konfigurieren und testen Sie Ihren Endpunkt über ein Terminal:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Bitten Sie einen eingebundenen Agenten, sein Dateilesewerkzeug auf `README.md` anzuwenden. Stellen Sie sicher, dass dieser Tool-Aufruf in der Sitzung erscheint, und prüfen Sie ihn dann unter **Policies → Activity** im lokalen Dashboard. Sobald die Beobachtungsergebnisse korrekt aussehen, erklärt [Jev-Richtlinien](/de/policies/jev), wann eine Durchsetzung sinnvoll ist. Einzelheiten zu Anbietern und zur Konfiguration finden Sie in der [Integrationsreferenz](/de/reference/jev).
  </Tab>
</Tabs>
