Jev unterstützt an zwei Punkten eines Agent-Laufs: Bewerte eine abgeschlossene Sitzung anhand bekannter Antworten, oder überprüfe einen Tool-Aufruf im Kontext dessen, was du den Agenten zu tun gebeten hast.

<Tabs>
  <Tab title="Jev-Evaluierungen">
    Verwende eine Jev-Evaluierung, wenn eine abgeschlossene Sitzung anhand einer Frage mit einigen bekannten Antworten bewertet werden kann, z. B. „Hat der Kunde nach einer Rückerstattung gefragt? Antworte mit Ja oder Nein." Sie hilft dir, sitzungsübergreifende Muster zu erkennen.

    ## Eine Evaluierung erstellen

    Öffne im Cloud-Dashboard **Analyse → Checks → Neuer Check** (oder **Neue Evaluierung**). Beschreibe eine Frage mit festen Antworten, überprüfe die entworfene Regel, und stelle sicher, dass **Art der Prüfung** das **Entscheidungsmodell** ist — das ist Jev. [Teste sie](/de/evaluations/test) an echten Sitzungen und aktiviere sie dann.

    ![Das gemeinsame Formular zur Erstellung von Evaluierungen, in dem du eine Frage beschreibst, den Entwurf überprüfst und ihn bereitstellst. Dieser Screenshot zeigt einen Code-Entwurf; verwende für Jev eine Frage mit festen Antworten.](/images/dashboard/eval-authoring-draft.png)

    ## Die Bewertungen lesen

    Nachdem eine neue Sitzung abgeschlossen ist, öffne **Analyse → Checks → Evals** und wähle die Evaluierung aus, oder verwende die Cloud-CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    Die CLI liest Bewertungen; das Erstellen einer Jev-Evaluierung erfolgt derzeit über das Dashboard. Unter [Jev-Evaluierungen](/de/evaluations/jev) findest du Fragetypen und Beispiele.
  </Tab>
  <Tab title="Jev-Richtlinien">
    Verwende die Jev-Richtlinienüberprüfung, wenn eine auf String-Matching basierende Richtlinie den Kontext deiner Anfrage benötigt, um zu entscheiden, ob ein Tool-Aufruf sicher ist. Beginne im **Beobachtungs**-Modus, damit du Jevs Antworten prüfen kannst, während deine installierten Richtlinien weiterhin jeden Aufruf entscheiden.

    Jevs Prüfungen stammen aus einem Paket; Failproof AI liefert keines mit. Bis du eines installierst, stellt Jev keine Fragen, auch wenn es konfiguriert ist:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Cloud-Jev einrichten

    Öffne im Cloud-Dashboard **Einstellungen → API-Schlüssel** und wähle unter **Neuer Schlüssel** die Option **ein Gerät, auf dem failproofai läuft**. Verwende ihn mit `failproofai config` wie im [Quickstart](/de/start/quickstart) beschrieben. Auf einem Gerät ohne bestehende Jev-Konfiguration aktiviert dies Cloud-Jev im Beobachtungsmodus. Überprüfe die Verbindung mit:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Einen eigenen Endpunkt verwenden

    Öffne im lokalen Dashboard **Einstellungen → Jev**. Wähle den Anbieter aus, füge dessen Token ein, wähle **Beobachten** und aktiviere Jev.

    ![Das lokale Jev-Einstellungsfenster mit einem Anbieter, einem Token-Feld und ausgewähltem Beobachtungsmodus.](/images/dashboard/jev-settings.png)

    Oder konfiguriere und teste deinen Endpunkt über ein Terminal:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Bitte einen verknüpften Agenten, sein Dateilesewerkzeug auf `README.md` anzuwenden. Bestätige, dass dieser Tool-Aufruf in der Sitzung erscheint, und überprüfe ihn dann unter **Richtlinien → Aktivität** im lokalen Dashboard. Sobald die Beobachtungsergebnisse korrekt aussehen, erklärt [Jev-Richtlinien](/de/policies/jev), wann eine Durchsetzung sinnvoll ist. Anbieterdetails und Konfiguration findest du in der [Integrationsreferenz](/de/reference/jev).
  </Tab>
</Tabs>
