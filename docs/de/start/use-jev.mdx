Jev hilft an zwei Punkten während eines Agent-Runs: Bewerte eine abgeschlossene Sitzung anhand bekannter Antworten, oder überprüfe einen Tool-Aufruf im Kontext dessen, was du den Agenten zu tun gebeten hast.

<Tabs>
  <Tab title="Jev evals">
    Verwende ein Jev-Eval, wenn eine abgeschlossene Sitzung anhand einer Frage mit wenigen bekannten Antworten bewertet werden kann, zum Beispiel: „Hat der Kunde nach einer Rückerstattung gefragt? Antworte mit Ja oder Nein." Es hilft dir, Muster über Sitzungen hinweg zu erkennen.

    ## Ein Eval erstellen

    Öffne im Cloud-Dashboard **Analyze → eval authoring → new eval**. Gib eine Frage mit fester Antwort ein, wähle **draft**, und prüfe, ob ein Classifier-Score ausgewählt wurde. [Teste es](/de/evaluations/test) mit echten Sitzungen und veröffentliche es anschließend.

    ![Das gemeinsame Eval-Authoring-Formular, in dem du eine Frage beschreibst, den Entwurf überprüfst und ihn veröffentlichst. Dieser Screenshot zeigt einen Code-Entwurf; verwende für Jev eine Frage mit fester Antwort.](/images/dashboard/eval-authoring-draft.png)

    ## Die Bewertungen lesen

    Nachdem eine neue Sitzung abgeschlossen ist, öffne **Observe → Evaluations** oder verwende die Cloud CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    Die CLI liest Bewertungen; das Erstellen eines Jev-Evals erfolgt derzeit über das Dashboard. Siehe [Jev evaluations](/de/evaluations/jev) für Fragetypen und Beispiele.
  </Tab>
  <Tab title="Jev policies">
    Verwende die Jev-Richtlinienprüfung, wenn eine auf String-Matching basierende Richtlinie den Kontext deiner Anfrage benötigt, um zu entscheiden, ob ein Tool-Aufruf sicher ist. Beginne im **observe**-Modus, damit du Jevs Antworten inspizieren kannst, während deine installierten Richtlinien weiterhin über jeden Aufruf entscheiden.

    Jevs Prüfungen stammen aus einem Paket; Failproof AI liefert keines mit. Bis du eines installierst, stellt Jev keine Fragen – auch wenn es konfiguriert ist:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Cloud Jev einrichten

    Öffne im Cloud-Dashboard **Administration → Keys** und erstelle einen Schlüssel mit dem **machine**-Preset. Verwende ihn mit `failproofai config` wie im [Quickstart](/de/start/quickstart) beschrieben. Auf einem Rechner ohne bestehende Jev-Konfiguration aktiviert dies Cloud Jev im observe-Modus. Überprüfe die Verbindung mit:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Eigenen Endpunkt verwenden

    Öffne im lokalen Dashboard **Settings → Jev**. Wähle den Anbieter aus, füge dessen Token ein, wähle **observe** und aktiviere Jev.

    ![Das lokale Jev-Einstellungsfenster mit einem Anbieter, einem Token-Feld und aktiviertem observe-Modus.](/images/dashboard/jev-settings.png)

    Oder konfiguriere und teste deinen Endpunkt über ein Terminal:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Bitte einen verknüpften Agenten, sein Datei-Lese-Tool auf `README.md` anzuwenden. Bestätige, dass dieser Tool-Aufruf in der Sitzung erscheint, und inspiziere ihn dann unter **Policies → Activity** im lokalen Dashboard. Sobald die observe-Ergebnisse korrekt aussehen, erklärt [Jev policies](/de/policies/jev), wann eine Durchsetzung sinnvoll ist. Einzelheiten zu Anbietern und Konfiguration findest du in der [Integrationsreferenz](/de/reference/jev).
  </Tab>
