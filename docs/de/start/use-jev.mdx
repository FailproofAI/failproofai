Jev hilft an zwei Stellen in einem Agent-Durchlauf: Bewertung einer abgeschlossenen Sitzung anhand bekannter Antworten oder Überprüfung eines Tool-Calls im Kontext Ihrer Anfrage an den Agenten.

<Tabs>
  <Tab title="Jev Evals">
    Verwenden Sie einen Jev-Eval, wenn eine abgeschlossene Sitzung anhand einer Frage mit wenigen bekannten Antworten bewertet werden kann, z. B. „Hat der Kunde eine Rückerstattung verlangt? Antwort: Ja oder Nein." Es hilft Ihnen, Muster sitzungsübergreifend zu erkennen.

    ## Einen Eval erstellen

    Öffnen Sie im Cloud-Dashboard **Analyze → eval authoring → new eval**. Geben Sie eine Frage mit festgelegter Antwort ein, wählen Sie **draft** und überprüfen Sie, ob ein Classifier-Score ausgewählt wurde. [Testen Sie ihn](/de/evaluations/test) anhand echter Sitzungen und stellen Sie ihn dann bereit.

    ![Das gemeinsame Eval-Authoring-Formular, in dem Sie eine Frage beschreiben, den Entwurf prüfen und ihn bereitstellen. Dieser Screenshot zeigt einen Code-Entwurf; verwenden Sie für Jev eine Frage mit festgelegter Antwort.](/images/dashboard/eval-authoring-draft.png)

    ## Die Bewertungen lesen

    Nachdem eine neue Sitzung abgeschlossen ist, öffnen Sie **Observe → Evaluations** oder verwenden Sie die Cloud CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    Die CLI liest Bewertungen; das Erstellen eines Jev-Evals erfolgt derzeit über das Dashboard. Unter [Jev-Evaluierungen](/de/evaluations/jev) finden Sie Fragetypen und Beispiele.
  </Tab>
  <Tab title="Jev-Richtlinien">
    Verwenden Sie die Jev-Richtlinienprüfung, wenn eine zeichenkettenbasierte Richtlinie den Kontext Ihrer Anfrage benötigt, um zu entscheiden, ob ein Tool-Call sicher ist. Starten Sie im **observe**-Modus, damit Sie Jevs Antworten einsehen können, während Ihre installierten Richtlinien weiterhin über jeden Aufruf entscheiden.

    Jevs Prüfungen stammen aus einem Pack; Failproof AI liefert keinen mit. Bis Sie diese installieren, stellt Jev keine Fragen, selbst wenn es konfiguriert ist:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Cloud Jev einrichten

    Öffnen Sie im Cloud-Dashboard **Administration → Keys** und erstellen Sie einen Schlüssel mit dem Preset **machine**. Verwenden Sie ihn mit `failproofai config` wie im [Schnellstart](/de/start/quickstart) beschrieben. Auf einem Rechner ohne bestehende Jev-Konfiguration wird Cloud Jev dadurch im Observe-Modus aktiviert. Überprüfen Sie die Verbindung mit:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Eigenen Endpunkt verwenden

    Öffnen Sie im lokalen Dashboard **Settings → Jev**. Wählen Sie den Anbieter, fügen Sie dessen Token ein, wählen Sie **observe** und aktivieren Sie Jev.

    ![Das lokale Jev-Einstellungsfenster mit einem Anbieter, einem Token-Feld und ausgewähltem Observe-Modus.](/images/dashboard/jev-settings.png)

    Oder konfigurieren und testen Sie Ihren Endpunkt über ein Terminal:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Bitten Sie einen eingebundenen Agenten, sein Datei-Lese-Tool auf `README.md` anzuwenden. Vergewissern Sie sich, dass dieser Tool-Call in der Sitzung erscheint, und prüfen Sie ihn anschließend unter **Policies → Activity** im lokalen Dashboard. Sobald die Observe-Ergebnisse korrekt aussehen, erklärt [Jev-Richtlinien](/de/policies/jev), wann Durchsetzung angebracht ist. Anbieterdetails und Konfigurationshinweise finden Sie in der [Integrationsreferenz](/de/reference/jev).
  </Tab>
</Tabs>
