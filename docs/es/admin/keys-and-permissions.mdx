Usa una clave distinta para cada persona, máquina o tarea de automatización. Otorga únicamente los permisos que necesite.

## Crear y rotar una clave

Usa **Admin → Keys** o el Cloud CLI:

```bash
fp keys list
fp keys create "audit automation" --add audits:read
fp keys disable "audit automation"
```

Guarda el secreto en el momento de creación; no se mostrará de nuevo. Para rotar, crea una clave de reemplazo, actualiza el consumidor y luego deshabilita la clave antigua.

## Claves de máquina

Una clave de máquina conecta el servicio local con Cloud:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Una máquina conectada puede necesitar dos capacidades:

- `policies:pull` para recibir políticas gestionadas desde Cloud.
- `events:add` para enviar decisiones y sesiones.

El estado las reporta por separado, ya que una puede funcionar mientras la otra no.

## Permisos comunes

| Permiso | Permite |
| --- | --- |
| `events:add` | Enviar eventos |
| `events:read` | Leer eventos y errores |
| `evaluations:read` | Leer sesiones y evaluaciones |
| `audits:read` / `audits:write` | Revisar o gestionar auditorías |
| `policies:read` / `policies:write` | Revisar o desplegar políticas |
| `policies:pull` | Obtener asignaciones de políticas para la máquina |
| `keys:create` / `keys:disable` | Crear o deshabilitar claves |
| `orgs:admin` | Administración de la organización a nivel de instancia; no asignable a una clave de organización |

Algunos comandos administrativos de `fp fleet` y `fp guardrails` requieren una sesión de usuario autenticada en lugar de una clave de API. El texto de ayuda de cada comando lo indica antes de realizar la solicitud.

<Warning>
  Nunca reutilices credenciales de ingesta como `AGENTEYE_KEY` o `AGENTEYE_API_KEY` como `FP_API_KEY`. Corresponden a sistemas y permisos distintos.
</Warning>
