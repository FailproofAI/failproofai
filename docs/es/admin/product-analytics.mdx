Failproof AI Cloud envía telemetría de uso **sobre el propio software** a sus mantenedores. Nunca incluye los datos de tus agentes. En una instalación autohospedada está activada por defecto y puedes desactivarla.

## Qué se recopila

Cada evento incluye cinco dimensiones y ningún dato que identifique a una persona:

| Dimensión | Ejemplo | Qué es |
| --- | --- | --- |
| `product` | `agenteye` | Qué producto lo envió |
| `component` | `dashboard`, `server`, `cli` | Qué parte del producto lo envió |
| `app_version` | `0.0.1-beta.81` | La versión que estás ejecutando |
| `deployment_kind` | `self_hosted` | Si se trata de una instalación de cliente, nuestra demo, nuestro QA o una máquina de desarrollo |
| `org_id` | un UUID | En qué organización ocurrió la acción, como identificador opaco |

Además de esos campos, los eventos registran **qué se usó, nunca el contenido**: qué página se visualizó (como patrón de ruta, por ejemplo `/:org/sessions/:id`, nunca la URL real), cuántos filtros de qué tipo se aplicaron, si una acción tuvo éxito y cuánto tiempo tomó.

La aplicación de Slack registra conexiones y desconexiones de espacios de trabajo, vinculaciones de cuentas, preguntas formuladas, gráficos publicados, decisiones de aprobación y fallos por categoría fija. Nunca incluye identificadores del espacio de trabajo, usuario o canal de Slack, correo electrónico, preguntas, respuestas, SQL ni tokens.

### El nombre de tu organización

Junto al `org_id` opaco, registramos el nombre de tu organización, el slug de URL y la dirección del dashboard una sola vez, en un registro de organización en lugar de en cada evento. Esto nos permite identificar a qué cuenta pertenece un patrón cuando analizamos la adopción o investigamos un problema que reportaste. Esta es la única información identificadora que el producto envía sobre ti.

### Los totales de uso de tu organización

El servidor reporta los totales de uso medido de cada organización, los mismos números que ves en la página de Uso. Son solo conteos: eventos, sesiones, agentes, entornos, ejecuciones de evaluación, puntuaciones, ejecuciones de auditoría, consultas guardadas, dashboards, alertas, incidencias, claves de API y miembros, más las fechas del período de medición. No contienen identificadores, nombres ni texto de consultas, y se envían independientemente de si hay alguien conectado.

## Qué nunca se recopila

- **No se recopilan prompts, respuestas de modelos ni contenido de eventos**, ni como texto, prefijo ni hash
- **No se recopilan identificadores de sesión, agente ni traza**
- **No se recopilan nombres de puntuaciones de evaluadores**
- **No se recopilan mensajes de error, texto de excepciones ni cuerpos de respuesta**, solo un código de estado y una categoría de una lista fija
- **No se recopilan argumentos de herramientas, SQL ni texto de consultas**
- **No se recopilan detalles de aplicaciones conectadas.** Conectar o revocar un cliente MCP envía como máximo un recuento de permisos, nunca el nombre de la aplicación ni ningún token
- **No se recopilan direcciones de correo electrónico**
- **No se recopilan URLs de referencia ni cadenas de consulta**
- **No se realizan grabaciones de pantalla, captura del DOM ni seguimiento de clics y cursor**

## Desactivar en una instalación autohospedada

Establece `DO_NOT_TRACK=1` tanto en el dashboard como en el servidor. Cada uno decide de forma independiente, por lo que configurarlo solo en uno deja al otro enviando telemetría. Reinicia el servidor para que el cambio surta efecto.

El README de tu versión describe las demás opciones de exclusión y cómo confirmar que la telemetría está desactivada.

## Un ping al optar por salir

Si te excluyes mediante una configuración del producto en lugar de `DO_NOT_TRACK`, el dashboard puede enviar **un ping anónimo** registrando eso, con una probabilidad de 1 entre 1000 por inicio de proceso. Esto nos indica cuántos operadores desactivan la telemetría. No contiene identificadores: ni organización, usuario, nombre de host, URL ni IP, solo el producto, componente, versión, tipo de despliegue y motivo. Un servidor con la opción desactivada no envía nada.

Este ping nunca se envía cuando usas `DO_NOT_TRACK`, razón por la que esa es la configuración a usar si tu política prohíbe cualquier telemetría saliente.

## A dónde va

A PostHog (`us.i.posthog.com`) mediante TLS en el puerto 443. Es un único nombre de host, por lo que también puedes bloquearlo con una sola regla de salida.

Para conocer cómo gestionamos la información personal de manera más amplia, consulta la [política de privacidad](https://befailproof.ai/privacy/).
