Controla toda la Observabilidad de Failproof AI desde la terminal o un script: sin viajes al dashboard. La CLI `agenteye` consulta tus datos (sesiones, registros de eventos, evaluaciones) y administra tu organización (claves API, usuarios, configuración, alertas, incidentes, consultas guardadas), así que úsala cuando quieras automatizar una verificación, integrar la Observabilidad en CI, o dejar que un agente de codificación inspeccione producción. Cada comando admite la opción `--json`, por lo que funciona igual de bien para ti en un prompt o para un agente de codificación (Claude Code, Cursor) que ejecuta comandos y analiza el resultado.

Con un solo binario puedes:

- **Leer tus datos**: `sessions`, `events`, `evals`, `errors` (filtra por tiempo, agente, entorno, puntuación).
- **Gestionar tu organización**: `keys`, `users`, `settings`, `alerts`, `incidents`.
- **Ejecutar análisis**: SQL guardado y un ejecutor de consultas ad-hoc (`query`).
- **Consultar el asistente de IA**: el mismo analista de solo lectura con el que chateas en el dashboard (`agent`).

> **Nota:** Esta es la CLI `agenteye`, una herramienta distinta del daemon recolector (`agenteye-collector`). La CLI se comunica con tu dashboard; el recolector envía eventos al servidor.

## Inicio rápido

De cero a tu primer resultado en cuatro líneas. Apunta la CLI a tu dashboard, inicia sesión, confirma quién eres y luego obtén el último día de ejecuciones:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # código de 6 dígitos por email
agenteye whoami                                                                  # confirma usuario + org activa
agenteye --json sessions --since 24h                                             # una fila por ejecución del agente, últimas 24h
```

Ese último comando imprime un objeto JSON con las sesiones más recientes (las más nuevas primero, con un máximo de 50 por defecto). Pásalo por `jq` para filtrarlo, o elimina `--json` para obtener una tabla enmarcada y con colores. Cada fila incluye el estado de la ejecución y, si un evaluador la puntuó, sus puntuaciones métricas (abreviadas aquí):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

El resto de esta página explica cada parte: [instalación](#installation) en entorno aislado, [inicio de sesión](#authentication), [configuración](#configuration), las [convenciones globales](#global-options--conventions) que comparten todos los comandos y la [referencia completa de comandos](#command-reference).

## Instalación

La CLI es un paquete público de PyPI llamado **`agenteye`**. Instálalo en un entorno aislado para que siempre tenga sus propias dependencias:

```bash
pipx install agenteye
# o
uv tool install agenteye
```

Requiere Python 3.10+. El comando instalado es **`agenteye`**:

```bash
agenteye --version
agenteye --help
```

> **Nota:** El SDK de Python de Observabilidad de Failproof AI también usa el nombre de distribución `agenteye`. Instalar la CLI con `pipx` o `uv tool` (en lugar de `pip install` en un virtualenv compartido) evita que ambos entren en conflicto. Un simple `pip install agenteye` está bien solo si el SDK no está instalado en el mismo entorno.

## Autenticación

La CLI se autentica ante el **dashboard** con un código de un solo uso enviado por email:

```bash
agenteye login --email you@example.com
# Se te enviará un código de 6 dígitos por email; pégalo cuando se te pida.
```

El token de sesión se guarda en `~/.agenteye/cli.json` (legible solo por ti, modo `0600`) y es válido por 24 horas de forma predeterminada. Cuando expire, ejecuta `agenteye login` de nuevo.

```bash
agenteye whoami     # muestra el usuario actual, la org activa y los permisos
agenteye logout     # revoca la sesión y elimina el token almacenado
```

`whoami` nunca produce un error si la sesión falta o ha expirado; en su lugar reporta `logged_in: false`, por lo que un script o agente puede comprobar el estado de autenticación de forma segura (aunque puede devolver un código de salida distinto de cero si no hay URL base configurada o el dashboard no es accesible).

**Requisitos:** tu email debe tener permiso para iniciar sesión en el dashboard (consúltalo con tu administrador de Observabilidad de Failproof AI) y el dashboard debe ser accesible en su URL base (consulta [Configuración](#configuration)). Si solicitas un código y no llega, probablemente tu email aún no está habilitado para acceder al dashboard.

## Elegir tu organización (multi-tenant)

Si tu cuenta pertenece a más de una organización, elige la activa **al iniciar sesión**; se guarda y se usa en todos los comandos posteriores:

```bash
agenteye login --org acme           # autenticarse y establecer el tenant activo en un solo paso
agenteye orgs list                  # las orgs a las que tienes acceso (la activa está marcada)
agenteye orgs switch globex         # cambia el valor predeterminado guardado
agenteye --org globex sessions      # sobrescribe para un único comando
```

Si perteneces a exactamente una organización, se selecciona automáticamente y puedes ignorar `--org` por completo. Si perteneces a varias y no eliges una, la CLI las lista y te pide que vuelvas a ejecutar el comando con `--org <slug>`. La org activa se envía al dashboard en cada solicitud y tus permisos se resuelven **por org**; `agenteye whoami` muestra la org activa, tus permisos en ella y todas tus membresías.

## Configuración

| Ajuste | Opción | Variable de entorno | Valor predeterminado |
|---|---|---|---|
| URL base del dashboard | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **requerido** (sin valor predeterminado) |
| Org/tenant activa | `--org` | `AGENTEYE_ORG` | elegida al iniciar sesión; guardada en `~/.agenteye/cli.json` |
| Token de sesión | `--token` | `AGENTEYE_CLI_TOKEN` | de `~/.agenteye/cli.json` |
| Salida JSON | `--json` | `AGENTEYE_CLI_JSON` | desactivada |
| Omitir verificación TLS | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | desactivada (guardada al iniciar sesión) |
| Tiempo de espera de solicitudes (segundos) | `--timeout` | _(ninguna)_ | 30 |
| Deshabilitar telemetría de uso | _(ninguna)_ | `AGENTEYE_ANALYTICS_DISABLED` (o `DO_NOT_TRACK`) | la telemetría está actualmente desactivada; no se envía nada |

El orden de resolución es **opción → variable de entorno → archivo de configuración**. No hay valor predeterminado; debes apuntar la CLI a tu dashboard, ya sea por comando (`--base-url https://agenteye.example.com`) o una sola vez mediante la variable de entorno (también se guarda tras tu primer `login`):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

El directorio de configuración respeta `AGENTEYE_HOME` (la misma convención usada por el SDK y el recolector); si está definido, `cli.json` reside en `$AGENTEYE_HOME/cli.json`.

### TLS autofirmado o interno

Si tu dashboard se sirve a través de HTTPS con un certificado autofirmado o interno (por ejemplo, un nombre de host de balanceador de carga sin procesar), la verificación TLS lo rechazará con un error `CERTIFICATE_VERIFY_FAILED`. Usa `--insecure` para omitir la verificación de certificado:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` **se guarda en `cli.json` cuando inicias sesión**, por lo que los comandos posteriores omiten la verificación automáticamente; no necesitas repetir la opción. Usa `--secure` para una llamada verificada puntual, o para volver a activar la verificación en tu próximo inicio de sesión. La CLI imprime una advertencia en stderr antes de cualquier comando que contacte el dashboard mientras la verificación está desactivada. Omitir la verificación elimina la protección contra ataques de intermediario; asegúrate de confiar en la ruta de red hacia tu dashboard (VPN, subred privada, etc.) antes de depender de esta opción.

## Telemetría y privacidad

> **Nota:** La CLI publicada **no envía ninguna telemetría de uso actualmente.** Hay un interruptor maestro activado, por lo que nada se transmite independientemente de tu entorno. La sección siguiente describe la capacidad de exclusión para el caso de que la telemetría llegue a habilitarse algún día.

Incluso si estuviera habilitada, la telemetría sería **únicamente análisis de uso anónimos**, nunca tus datos de agente, sesión o evento:

- **Ningún dato de agente, sesión o evento sale jamás de tu infraestructura.** Solo se reportaría el uso de la CLI: el nombre del comando y subcomando (p. ej. `keys create`), los **nombres** de las opciones que usaste (nunca sus valores), el estado de éxito/salida y la duración, más un evento por acción para mutaciones (p. ej. `api_key_created`, `query_run`) que solo contiene nombres/enumeraciones estáticos y recuentos aproximados. La URL de tu dashboard, el token de sesión, el email, el slug de la org, los IDs de recursos, el SQL, los secretos de claves y los filtros de consulta **nunca** se enviarían. Los operadores se identificarían solo mediante un ID interno opaco, nunca por email.
- **Excluirte de antemano** configurando `AGENTEYE_ANALYTICS_DISABLED=1` en el entorno de la CLI (la CLI también respeta la convención entre herramientas `DO_NOT_TRACK=1`). Esto surte efecto en el momento en que la telemetría se active alguna vez, por lo que un entorno con conciencia de privacidad puede permanecer excluido de forma permanente.
- Si la telemetría estuviera habilitada, la CLI enviaría directamente a PostHog (`https://us.i.posthog.com`); una máquina con ese host bloqueado no enviaría nada de forma silenciosa y la CLI no se vería afectada.

## Opciones globales y convenciones

Lee esto una vez; se aplica a todos los comandos.

- **Las opciones globales van ANTES del comando.** `agenteye --json sessions` es correcto; `agenteye sessions --json` es un error de uso. Las opciones globales son `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet` y `--no-color`.
- **`--json` imprime JSON puro en stdout y nada más.** Las líneas de estado, advertencias y errores para el usuario van a **stderr**, por lo que una captura de stdout con `--json` permanece limpia para pasarla a `jq` aunque se muestre una línea de estado. Sin `--json` obtienes una vista enmarcada y con colores pensada para los ojos humanos.
- **Descubre con `--help`.** Cada comando y subcomando tiene `--help` (y el alias `-h`): `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`. La ayuda del nivel superior también lista los códigos de salida y las opciones globales. No hay un volcado global legible por máquina; usa `--help` por comando, más `agenteye query schema` y `agenteye settings schema` específicos de dominio para esos dos registros.
- **Las confirmaciones se omiten automáticamente para scripts y agentes.** Los comandos de creación/actualización/eliminación muestran "¿estás seguro?" en una terminal interactiva, pero **omiten ese aviso automáticamente con `--json` o cuando stdin no es un TTY** (un TTY es una sesión de terminal interactiva; una tubería o un ejecutor de CI no lo es), por lo que los scripts y los agentes nunca se quedan bloqueados. Usa `--yes`/`-y` para omitirlo explícitamente. Como el aviso no se mostrará para un agente, el agente debería confirmar las acciones destructivas con el humano primero.
- **Paginación:** los resultados están ordenados del más reciente al más antiguo y se pagina mediante cursor (cada página devuelve un token que usas para obtener la siguiente). `--limit N` (alias `-n`) limita las filas y **tiene un valor predeterminado de 50**; `--all` pagina automáticamente (en bloques de 200 filas) **hasta `--limit`**, por lo que un `--all` sin más parámetros sigue deteniéndose en 50. Para un recorrido completo, pasa un límite alto explícito: `--all --limit 1000`. `--page-size N` controla el bloque por solicitud (máximo 200); `--cursor <id>` reanuda desde el `next_cursor` de una página anterior.
- **Filtros de tiempo:** `--since` acepta una ventana relativa: `15m`, `1h`, `6h`, `24h`, `7d`, o `all` (los ajustes predefinidos del dashboard). Para un rango más largo o personalizado (por ejemplo, los últimos 30 días), usa `--from`/`--to`: marcas de tiempo UTC explícitas en ISO-8601 **con `T` y zona horaria** (p. ej. `2026-06-01T00:00:00Z`) que reemplazan a `--since`. Un valor separado por espacios o sin zona horaria es un error de uso.
- **`--fields a,b,c`** (en `events`, `sessions`, `evals`, `errors`) restringe la salida a esas claves, tanto en la tabla como en `--json`. Los nombres desconocidos se rechazan con la lista de válidos, una forma rápida de descubrir los nombres de campo.
- **`--file payload.json`** (o `--file -` para leer stdin) proporciona un cuerpo de solicitud JSON completo cuando un recurso tiene una forma compleja (en `alerts create/update`, `settings set` y `users create/update`). El SQL de las consultas guardadas usa `--sql @file.sql` en su lugar.
- **Los filtros de varios valores** se separan por comas → se comparan como un conjunto (unión dentro de un filtro, AND entre filtros): `--event-type tool_use,tool_result`. Las opciones de Click no son variádicas, por lo que `--add a b` falla. Usa `--add a,b`, repite la opción (`--add a --add b`), o usa comillas (`--add "a b"`).

## Referencia de comandos

### Los 5 comandos que más usarás

La mayor parte del trabajo diario se realiza con un puñado de comandos de lectura. Empieza aquí y recurre a la superficie completa más abajo cuando la necesites:

| Comando | Qué hace | Pruébalo |
|---|---|---|
| `sessions` | Una fila por ejecución del agente: tiempo, entorno, agente, estado, última puntuación. | `agenteye --json sessions --since 24h --status error` |
| `events` | El rastro detallado por paso dentro de una ejecución (añade `--full` para los payloads). | `agenteye --json events --session-id run-001 --all` |
| `evals` | Resultados de evaluación y puntuaciones; `--aggregate` los agrupa. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | Solo los eventos con error; `--aggregate` para recuentos por tipo. | `agenteye --json errors --since 24h --aggregate` |
| `list` | Descubre los valores válidos de los filtros (agentes, entornos, modelos, …). | `agenteye list agents` |

### Todo lo que puede hacer la CLI

A continuación se muestra la superficie completa. La CLI tiene **18 comandos de nivel superior**. Todos los comandos de lectura aceptan `--json` y las opciones globales anteriores; ejecuta `agenteye <comando> -h` (o `<comando> <subcomando> -h`) para la lista exhaustiva de opciones y el formato JSON de cualquier comando.

### Identidad: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # código de un solo uso por email; guarda la sesión
agenteye logout                                       # elimina la sesión guardada en esta máquina
agenteye whoami                                       # usuario actual, org activa, permisos
agenteye version                                      # imprime la versión de la CLI (igual que --version)
agenteye help                                         # ayuda de nivel superior (igual que --help)
```

`orgs` inspecciona y cambia el tenant activo:

```bash
agenteye orgs list        # tus orgs + tu rol en cada una (la activa está marcada)
agenteye orgs switch acme # cambia la org activa guardada (omite el slug para elegir de una lista en un TTY)
agenteye orgs current     # tarjeta de identidad de la org activa
agenteye orgs perms       # tus permisos en la org activa, agrupados por recurso
```

### Observar (solo lectura): `events` · `sessions` · `evals` · `errors` · `list`

Ninguno de estos requiere confirmación. Filtros compartidos: `--session-id`, `--agent-id`, `--env` (**no** `--environment`) y el rango de tiempo (`--since` / `--from` / `--to`).

```bash
# events (alias: el rastro detallado por paso), del más reciente al más antiguo
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: una fila por ejecución del agente (tiempo/entorno/agente/sesión/estado; sin filtrado por puntuación)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: resultados de evaluación + puntuaciones; --score filtra por métrica, --aggregate agrupa
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # mix de estados + estadísticas de puntuación por clave

# errors: eventos con error; --aggregate para recuentos/sesiones/agentes/última vez visto
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: descubre los valores válidos de los filtros antes de filtrar
agenteye list envs        # también: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (en **`evals`**, no en `sessions`) es repetible y se combina con AND; cualquiera de los límites es opcional (`..0.5` significa ≤ 0.5, `0.9..` significa ≥ 0.9). Hasta 20 filtros de puntuación por solicitud. `evals --scores-full` es una opción de visualización **solo para la tabla humana**; muestra todos los pares de puntuaciones en lugar de los primeros más un recuento `+N`. No tiene efecto con `--json`, que siempre devuelve el objeto de puntuaciones completo. Para leer **una sesión de principio a fin**, combina el rastro de eventos con su evaluación:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # sus puntuaciones + estado
```

### Gestionar (con restricción de permisos): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: claves API. El secreto se genera localmente, se envía al servidor (que solo almacena un hash) y **se muestra una sola vez** al crear/regenerar; captúralo en ese momento. Con `--json` aparece únicamente en el campo `key`. Se referencia por **nombre**.

```bash
agenteye keys list                                   # claves activas primero, luego revocadas
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # limita al ámbito que necesitas; imprime el secreto UNA VEZ
agenteye keys create ops --permission-set standard --remove queries:run   # parte de un preset y luego recorta
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rota el secreto (el antiguo deja de funcionar)
agenteye keys disable ci-bot --yes                   # revocar
```

Los permisos funcionan como `(permission-set ∪ --add) − --remove`. Los tokens son `slug:acción` (p. ej. `events:read`) o `slug:acción.acción` para expandir varios en un recurso (`events:read.add` → `events:read`, `events:add`). Presets: `read-only`, `standard`, `admin`. Los permisos exclusivos para humanos (`keys:update`) no se pueden otorgar a una clave.

**`users`**: miembros de la organización, referenciados por **email** (también se acepta un ID UUID).

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predice + confirma
agenteye users disable dev@corp.com --yes            # tiene protecciones para el usuario protegido/propio
agenteye users enable dev@corp.com
```

**`settings`**: un registro fijo (lees y cambias claves existentes; no puedes crear nuevas).

```bash
agenteye settings list                               # clave · valor · tipo · actualizado (secretos enmascarados)
agenteye settings schema                             # qué acepta cada clave (tipo · rango · descripción)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: definiciones de alerta, referenciadas por **nombre**. `create` acepta un NAME posicional más opciones o un cuerpo JSON completo mediante `--file`.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME es obligatorio (posicional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # envía una notificación de prueba
agenteye alerts delete high-errors --yes
```

**`incidents`**: incidentes de alerta, referenciados por ID (se aceptan IDs cortos). `show` imprime el registro completo de actividad; léelo antes de actuar.

```bash
agenteye incidents list --state firing                # también: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # el asignado debe ser un operador
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # abre uno manualmente contra una alerta
agenteye incidents comment-add <id> "causa raíz: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### Análisis y asistente: `query` · `agent`

**`query`**: SQL guardado contra tu almacén de análisis más un ejecutor ad-hoc. Las consultas guardadas se referencian por **nombre**; el SQL se valida en el servidor (solo SELECT/WITH, tiempo de espera de sentencia, límite de filas).

```bash
agenteye query schema [TABLE]                         # esquema de columnas de las vistas de análisis
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # ejecuta una consulta guardada + un $1 posicional
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "eventos con error (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: se comunica con el **asistente de IA** integrado (el mismo analista de solo lectura con el que puedes chatear en el dashboard). Los chats se referencian por un chat-id corto (resuelto por prefijo).

```bash
agenteye agent health                                 # comprueba si el asistente de IA está configurado/accesible
agenteye agent models                                 # modelos que puedes pasar a --model (el predeterminado marcado)
agenteye agent ask "¿qué agentes tuvieron más errores en el último día?"    # inicia un chat; imprime su ID corto
agenteye agent ask --chat <short-id> "¿y qué herramientas llamaron?"   # continúa ese chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "análisis de errores" ; agenteye agent delete <short-id>
```

## Códigos de salida

| Código | Significado |
|---|---|
| 0 | Éxito |
| 1 | Error inesperado (p. ej. el dashboard devolvió un 5xx) |
| 2 | Error de uso (argumentos inválidos, comando/opción desconocido, colisión de nombres) |
| 3 | No se puede alcanzar el dashboard |
| 4 | No has iniciado sesión o la sesión ha expirado; ejecuta `agenteye login` |
| 5 | Autenticado, pero tu cuenta no tiene el permiso requerido (el mensaje lo indica) |
| 6 | El recurso solicitado no se encontró (p. ej. sesión o ID de incidente desconocido) |

Esto hace que la CLI sea segura para usar en scripts: un agente de codificación puede ramificar con un `4` para pedirte que vuelvas a autenticarte, o con un `5` para mostrar el permiso que falta. Consulta [Recetas de CLI para agentes](/es/agenteye/cli-recipes) para ver patrones de manejo de códigos de salida y formatos de salida JSON.
