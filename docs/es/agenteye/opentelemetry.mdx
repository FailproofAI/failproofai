OpenTelemetry te permite enviar trazas, logs y métricas de agentes a FailproofAI Cloud usando el protocolo estándar OTLP/HTTP. Es opcional. Tus integraciones existentes con FailproofAI siguen funcionando sin necesidad de activarlo.

## Activar la ingesta para tu organización

Un administrador de la organización abre **Configuración → OpenTelemetry** y activa la ingesta. Usa una clave de API de Cloud con permiso `events:add`, el mismo permiso que se usa para los informes de agentes.

Si la ingesta está desactivada, Cloud rechaza las exportaciones OTLP, por lo que `failproofai otel enable` no tiene efecto y tus agentes continúan enviando sesiones de la manera habitual. Ejecuta `failproofai otel status` para verificar el estado de la organización y pide a un administrador que la active.

## Conectar un agente de codificación

Conecta tu máquina con `failproofai config` y luego elige un agente:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

El comando de configuración es compatible con Claude Code, Codex y Copilot, y elige entre Cloud o un relay local autenticado según corresponda. Copilot usa el relay local automáticamente. Inicia el daemon de FailproofAI configurado antes de usar el relay.

Si FailproofAI ya envía las transcripciones de sesión de un agente, el proceso de configuración preguntará si deseas cambiar ese agente a OTEL. El valor predeterminado es No. Aceptar detiene las cargas de transcripciones para ese agente; no modifica la aplicación de políticas ni los informes de otros agentes.

## Conectar una aplicación

Usa la instrumentación de OpenTelemetry de tu aplicación con estas variables de entorno:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

El endpoint es la base OTLP de Cloud, `https://app.befailproof.ai/otel`; tu exportador añade `/v1/traces`, `/v1/logs` o `/v1/metrics` automáticamente. Las variables por señal, como `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, se usan tal cual, por lo que requieren la ruta completa; por ejemplo, `https://app.befailproof.ai/otel/v1/logs`.

Reemplaza `<key>` con tu clave de API. Mantén el secreto fuera del historial de shell, grabaciones de pantalla y configuraciones confirmadas en el repositorio. En una máquina configurada, `failproofai otel env --service my-agent` imprime el bloque con su clave existente. Su salida contiene una credencial.

Cloud acepta exportaciones OTLP/HTTP de trazas, logs y métricas, en formato protobuf o JSON, incluyendo solicitudes comprimidas con gzip. No acepta OTLP/gRPC.

Las métricas se reconocen por compatibilidad con el exportador, pero no se almacenan ni se muestran. Las trazas de agentes y los logs de agentes de codificación compatibles se convierten en sesiones; los campos que el agente no exporta permanecen ausentes.

## Capturar texto de prompts

<Warning>
La captura de texto puede incluir prompts, argumentos de herramientas y otro contenido sensible. `failproofai otel enable` la activa. Añade `--no-content` para mantener desactivada la captura de prompts y detalles de herramientas.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Para un agente que configures manualmente, usa sus propios controles de captura de contenido:

<Tabs>
  <Tab title="Claude Code">
    Añade estas variables al entorno de tu agente junto con el bloque de aplicación anterior:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Establece ambas variables de contenido en `0` para evitar la captura de prompts y detalles de herramientas.
  </Tab>
  <Tab title="Codex">
    En la configuración de usuario de Codex, usa sus ajustes de OTEL:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    El contenido de las conversaciones de Codex se encuentra en los logs; deja desactivadas las trazas internas de tiempo de ejecución y las métricas. Codex usa el endpoint completo que proporcionas. Establece `log_user_prompt` en `false` para excluir los prompts; el comando de configuración conserva un `false` explícito.
  </Tab>
  <Tab title="Gemini CLI">
    Usa la configuración de telemetría de Gemini con el relay local:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI no es compatible con `failproofai otel enable`. Configúralo manualmente con un colector autenticado propio. Establece `logPrompts` en `false` para no capturar prompts.
  </Tab>
  <Tab title="Copilot in VS Code">
    Usa estos ajustes de usuario de VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Ejecuta `failproofai otel enable copilot` para habilitar el relay autenticado. Establece `captureContent` en `false` para omitir el contenido.
  </Tab>
</Tabs>

## Verificar o deshacer la configuración

```bash
failproofai otel status
failproofai otel disable all
```

El estado distingue entre los ajustes gestionados por FailproofAI y la telemetría que configuraste en otro lugar. Deshabilitar restaura los ajustes gestionados anteriores y la elección previa de carga de transcripciones del agente.
