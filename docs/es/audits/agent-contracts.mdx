El contexto del agente indica a las auditorías para qué existe cada agente, qué debe producir y qué nunca debe hacer. Failproof AI almacena este contexto como un contrato de agente por agente.

El contexto del agente pertenece a la organización, no a una auditoría individual. Se escribe una vez por agente, y cada auditoría respaldada por un modelo cuyo ámbito incluya ese agente lo utiliza.

## Añadir contexto del agente

<Tabs>
  <Tab title="Panel de control">
    1. Ve a **Analyze → audits**, selecciona **agents** y elige el ID de agente reportado por sus sesiones.
    2. Selecciona **add content** o **edit**.
    3. Describe para qué sirve el agente, qué debe producir, qué significa "completado", con qué frecuencia debe ejecutarse y qué nunca debe hacer.
    4. Guarda el contexto, luego vuelve al formulario de auditoría y confirma que el agente seleccionado aparece como cubierto.

    ![El cajón de Agents de la auditoría, usado para añadir propósito, cadencia, salidas, condiciones de finalización y comportamiento prohibido de un agente.](/images/dashboard/agent-context.png)

    También puedes añadir o editar el contexto del agente desde el cajón **agents** mientras creas o editas una auditoría. Se guarda de forma independiente y está disponible de inmediato para todas las auditorías aplicables.
  </Tab>
  <Tab title="CLI">
    La CLI de Cloud todavía no expone comandos de contrato. Usa la API pública con una clave que tenga `audits:read` y `audits:write`:

    ```bash
    curl -X POST "https://app.befailproof.ai/v1/audits/contracts" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "agent_id": "nightly-reconciler",
        "enabled": true,
        "body": "# Purpose\nReconcile yesterday's payouts.\n\n## Outputs\nPublish a signed summary.\n\n## Must not\nNever modify ledger entries."
      }'
    ```

    Lista los contratos con `GET /v1/audits/contracts`; recupera un contrato concreto con `GET /v1/audits/contracts/{id}`. La actualización con `PUT` es un reemplazo completo y requiere tanto `agent_id` como `body`.
  </Tab>
</Tabs>

## Escribir contexto útil

Mantén el contexto por debajo de 5.000 caracteres y hazlo verificable. Un contexto útil normalmente incluye:

- **Propósito:** por qué existe el agente
- **Salidas:** artefactos o acciones que debe producir
- **Completado cuando:** la condición que hace que una ejecución sea exitosa
- **Cadencia:** con qué frecuencia o cuándo debe ejecutarse
- **No debe:** acciones y resultados que siempre son inaceptables

```markdown
---
agent: nightly-reconciler
purpose: Reconcile yesterday's payouts and publish a signed summary.
cadence: Once daily after 02:00 UTC. Never more than once.
---

## Outputs
- A signed reconciliation summary in the finance channel.

## Done when
- Every payout is matched or explicitly flagged.

## Must not
- Modify ledger entries. Report discrepancies instead.
```

El contexto del agente establece el comportamiento esperado; no puede indicarle al análisis qué conclusión debe alcanzar ni restringir qué evidencia examina. Los agentes sin contexto se auditan con normalidad, pero Failproof AI no puede juzgar su comportamiento en relación con la intención específica de la organización.

## Pausar o modificar el contexto del agente

- Pausa el contexto del agente cuando las auditorías deban ignorarlo temporalmente. La pausa es reversible.
- Edita el contexto cuando cambien las responsabilidades del agente. El nuevo texto se aplica a las ejecuciones futuras.
- Revisa **last matched** cuando un agente en ejecución nunca parece usar su contexto. Normalmente esto significa que su ID de agente no coincide con la telemetría.
- Elimina a través de la API solo cuando el texto deba destruirse de forma permanente. El panel de control ofrece intencionalmente la opción de pausar en lugar de eliminar.

Cada ejecución de auditoría almacena el snapshot exacto del contexto del agente que utilizó. Editar, pausar o eliminar el recurso de contrato actual no reescribe la base de hallazgos anteriores.

<Info>
  Leer contratos requiere `audits:read`. Crearlos, editarlos, pausarlos o eliminarlos requiere `audits:write`.
</Info>
