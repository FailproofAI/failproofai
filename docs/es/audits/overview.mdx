Una auditoría examina un conjunto seleccionado de sesiones en busca de un objetivo de fallo definido. Combina evidencia de rastros, resultados de evaluaciones, coincidencias de políticas y contexto de referencia para producir hallazgos sobre los que puedes actuar.

Descubre cómo una auditoría va desde una ejecución programada hasta fallos respaldados por evidencia que puedes corregir.

## Abrir auditorías

<Tabs>
  <Tab title="Dashboard">
    Ve a **Analyze → Audits**. La página muestra el estado programado, los hallazgos abiertos, la última ejecución, la próxima ejecución, la cadencia y si la auditoría tiene un resumen o páginas de referencia. Selecciona una tarjeta para ver la configuración e historial de ejecuciones; selecciona **new audit** para crear una.

    ![La página de Audits mostrando auditorías recurrentes con su programación, sensibilidad y estado de ejecución.](/images/dashboard/audits.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

Usa una auditoría cuando necesites responder una pregunta a nivel de población, como:

- ¿Dónde abandonan los agentes las tareas sin escalar?
- ¿Qué fallos de herramientas conducen a reintentos ineficaces?
- ¿Están los agentes accediendo a datos fuera del flujo de trabajo previsto?
- ¿Qué cambió después de una actualización de modelo, prompt o herramienta?

## Flujo de respuesta de auditoría

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert for recurrence
```

Un hallazgo debe nombrar el modo de fallo y apuntar a la evidencia. Un issue gestiona la remediación. Una política previene un patrón de acción conocido; una alerta detecta la recurrencia cuando la prevención no es posible o requiere monitoreo.
