Una auditoría revisa múltiples ejecuciones de agentes en función de un objetivo y devuelve hallazgos respaldados por evidencia.

## Local o en la nube

| | Auditoría local | Auditoría en la nube |
| --- | --- | --- |
| Comando | `failproofai audit` | `fp audits` |
| Lee | Historial de agentes en esta máquina | Sesiones en tu organización en la nube |
| Produce | Resultados locales en `localhost:8020/audit` | Hallazgos, problemas y alertas compartidos |
| Requiere | Sin cuenta | Conexión a la nube y clave API |

Usa una auditoría local para una revisión rápida de una sola máquina. Usa la nube cuando un equipo necesite una auditoría recurrente entre agentes y máquinas.

## Preguntas que puede responder una auditoría

- ¿Dónde se detienen los agentes sin escalar?
- ¿Qué fallos de herramientas llevan a reintentos ineficaces?
- ¿Están los agentes accediendo a datos fuera del flujo de trabajo previsto?
- ¿Qué cambió tras una actualización de modelo, prompt o herramienta?

## Abrir auditorías en la nube

Ve a **Analizar → Auditorías**, o usa:

```bash
fp audits list
fp audits show <audit-name>
fp audits findings --status open --limit 20
```

Los comandos de auditoría utilizan el nombre de la auditoría o el ID completo. Los hallazgos se referencian por su propio ID.

## Del hallazgo a la prevención

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert
```

Un hallazgo apunta a evidencia. Un problema gestiona la respuesta. Una política previene un patrón de acción conocido; una alerta vigila la recurrencia.

No todos los hallazgos deben convertirse en una política. Un hallazgo de tipo `policy` describe una regla ejecutable. Un hallazgo de tipo `failure` o `improvement` puede requerir en cambio un cambio en el flujo de trabajo, el prompt, el modelo o la herramienta.
