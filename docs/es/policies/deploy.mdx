Despliega una política revisada en una máquina a la vez. Comienza en modo observación.

## Despliegue desde la CLI

```bash
fp policies test ./rule.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish no-force-push ./rule.mjs
fp fleet deploy <machine> --add no-force-push:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add no-force-push:enforce
```

El modo observación evalúa la política real y registra las decisiones que no son allow, pero no bloquea al agente.

<Warning>
  Un `--add no-force-push` sin modificador aplica la política de inmediato. Añade `:observe` para un despliegue en modo sombra.
</Warning>

Si la aplicación de la política causa problemas:

```bash
fp fleet history <machine>
fp fleet rollback <machine> <generation>
```

## Despliegue desde el panel de control

1. Ve a **Admin → enforcement**.
2. Abre la máquina de destino.
3. Añade la versión de la política con efecto **observe**.
4. Aplica el despliegue.
5. Revisa los resultados en **Observe → policy**.
6. Promueve la misma versión a **enforce** cuando las coincidencias sean correctas.

![El editor de despliegue de máquinas con versiones de política, efectos enforce y observe, y la acción de aplicar despliegue.](/images/dashboard/enforcement-editor.png)

## Reemplazar o preparar un conjunto

- `--remove <id>` elimina una política.
- `--set <ref>...` reemplaza el conjunto completo de políticas.
- `--create` prepara un despliegue antes de que una máquina se registre por primera vez.
- `fp fleet diff <machine>` compara el estado previsto y el estado aplicado.

<Note>
  Sin Cloud, publica un paquete con `failproofai publish --effect observe` e inspecciona las decisiones en el panel de control local.
</Note>

Las máquinas necesitan `policies:pull` para recibir despliegues y `events:add` para reportar decisiones.
