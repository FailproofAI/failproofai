---
title: "Políticas"
description: "Guía o bloquea a un agente antes de que un fallo conocido se repita."
icon: "shield-check"
---

Una política observa la acción de un agente y devuelve una de tres decisiones:

- `allow` continúa.
- `instruct` proporciona orientación al agente cuando su entorno de ejecución lo soporta.
- `deny` bloquea la acción.

Usa políticas para comportamientos conocidos y repetibles: eliminar archivos protegidos, exponer secretos, hacer push a la rama incorrecta o modificar infraestructura de producción.

## Añadir políticas a esta máquina

La configuración inicial no incluye ningún paquete de políticas. Añade el paquete de Failproof AI después de la configuración:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai policies
```

El paquete no contiene un pack integrado con privilegios especiales. El nuestro se instala de la misma manera que el de cualquier otro.

Las políticas también pueden provenir de un archivo local, un paquete publicado o una asignación en la nube:

| Origen | Cómo añadirlo |
| --- | --- |
| Archivo local | Coloca `*policies.{js,mjs,ts}` en `.failproofai/policies/` |
| Cualquier ruta de archivo | `failproofai policies -i -c <path>` |
| Paquete publicado | `failproofai policies add <owner>/<repo>` |
| Nube | Asígnalo desde el panel de control o con `fp fleet deploy` |

`block-failproofai-commands` siempre se ejecuta y no puede desactivarse. Impide que un agente deshabilite su propio sistema de cumplimiento.

## Observar antes de aplicar

El modo observación ejecuta la política real y registra lo que habría hecho, pero no bloquea al agente.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

<Warning>
  Un `fp fleet deploy <machine> --add <id>` sin modificadores aplica la política de inmediato. Añade `:observe` para un despliegue en modo sombra.
</Warning>

Una política que supera el tiempo de espera en modo observación registra un allow, ya que eso es lo que ocurriría durante la aplicación. Solo las decisiones observadas que no sean allow se registran.

Para un paquete utilizado sin la nube, publícalo con `failproofai publish --effect observe`.
