Usa `fp` para inspeccionar la telemetría de Cloud, gestionar la aplicación administrada en la nube (políticas, despliegues de flota, decisiones de guardrail) y administrar auditorías, hallazgos, incidencias, alertas, claves, usuarios, consultas y configuraciones. Usa [`failproofai`](/es/reference/failproof-cli) para hooks locales, políticas, captura e incorporación de máquinas.

También puedes crear y desplegar código hospedado, evaluadores LLM-judge y Jev, gestionar
dashboards, inspeccionar el sentimiento y usar el asistente del dashboard desde la terminal.

Instala el Cloud CLI publicado como herramienta aislada:

```bash
uv tool install fp-cloud-cli
fp version
```

## Iniciar sesión

```bash
fp login
fp whoami
```

## Sintaxis

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Las opciones globales deben ir antes del comando:

```bash
fp --json sessions --since 24h
```

Ejecuta `fp COMMAND --help` o `fp COMMAND SUBCOMMAND --help` para obtener ayuda en la terminal.

## Comandos del CLI

### Crear un evaluador

`fp evaluators` crea definiciones; `fp evals` lee los resultados. Se requiere una instancia administrada habilitada (`fp evaluators instances`). La creación necesita
`evaluations:trigger`; las ejecuciones en seco de sesiones y el perfilado de esquemas también necesitan `events:read`.

El código es una expresión Python restringida. Guarda esto como `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev binario y rúbrica de calificación:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
La creación habilita el evaluador. Deploy crea una nueva versión inmutable y luego
deshabilita las versiones anteriores habilitadas. Un seguimiento fallido deja la nueva versión
publicada: inspecciona `evaluators list --all` antes de reintentar.
Los dry-runs de Judge son rechazados por Cloud. Los dry-runs de Jev consumen presupuesto de modelo.
El backfill cubre evaluadores de código, judge y Jev y acepta como máximo 90 días; solo encola sesiones que un evaluador aún no ha puntuado. Los backfills de Judge y Jev consumen presupuesto de modelo, así que ejecuta `fp evaluators backfill --dry-run` primero.
La salida en modo humano muestra los resultados del dry-run por sesión antes de crear/desplegar.
Las vistas previas fallidas detienen la escritura a menos que pases explícitamente `--force` después de revisar.
</Warning>

La redacción con IA requiere `fp login` y escribe una especificación aceptada por create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Revisa la clave, la fuente y la condición del borrador antes de habilitarlo.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Comando | Opciones / comportamiento |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Fuente/envoltorio completo |
| `fp evaluators create` | `--key`, `--name`, `--version`, `--label` repetido, `--condition EXPR\|@file`, una fuente, `--dry-run-on` repetido, `--disabled`, `--force` explícito para vistas previas fallidas |
| `fp evaluators deploy KEY` | Mismos flags de fuente; `--version`, `--backfill 7d` (cualquier tipo, 1–90 días), `--force`; las versiones numéricas se autoincrement; KEY proporciona un `eval_key` de archivo de especificación faltante |
| `fp evaluators draft "intent"` | Sesión; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Flags de fuente o `--file`, `--session` repetido (máximo 10); ninguno = solo compilar |
| `fp evaluators enable\|disable KEY[@VERSION]` | Alternar |
| `fp evaluators label KEY[@VERSION]` | `--add`, `--remove` repetidos |
| `fp evaluators instances\|schema\|jobs` | Inspeccionar flota administrada/esquema/trabajos |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; código, judge y Jev |

Los flags de código son `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. Los flags de Judge son `--judge --criteria TEXT`, `--step` repetido y
`--threshold`. Los flags de Jev son `--jev noul --instructions --true --false` o
`--jev score --instructions` con 3–5 valores `--level` distintos, del peor al mejor.
Judge/Jev requieren una puntuación; los umbrales van de 0 a 1. Los pasos de judge binarios son rechazados.

Los archivos de especificación contienen exactamente `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
El `evaluator_source` de Judge/Jev es una cadena JSON envuelta. No incluyas IDs de fila,
estado habilitado ni metadatos de razonamiento de IA. `--file` y los flags de especificación discretos son
mutuamente excluyentes; deploy puede sobreescribir la versión del archivo. Los archivos de salida nunca se sobreescriben.

### Nuevos controles del dashboard

Todos los comandos aceptan `--json` global. Los errores 404 de ruta desconocida salen con código 6 indicando "no disponible
en este FailproofAI Cloud todavía". Los errores 404 de registro faltante también salen con código 6 pero informan que el
registro no fue encontrado. Los comandos exclusivos de sesión rechazan el modo de clave antes de HTTP (salida 2).

Los comandos en modo humano usan resúmenes y tablas. Para exportaciones JSON sin procesar, pasa `--json`
global o guarda con `--out FILE`; de lo contrario, las exportaciones de sesión y consulta JSON muestran
una vista legible. Las exportaciones CSV se mantienen como CSV puro para tuberías.

| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; list con `--limit`; messages con `--session-id` |
| `fp query compose "question"` | Sesión; `--run` |
| `fp query export [ID]` | O `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Issues puede usar `--create --title --summary` o `--create --file` |

| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` necesita una clave de API; plan (ofertas y prueba) y claim requieren una sesión con usuario autenticado |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1 000 000 tokens |
| `fp otel status\|enable\|disable` | Interruptor de ingesta de la organización en Cloud, no captura local |
| `fp slack status\|disconnect` | Sesión |

`fp agent ask` renderiza SQL de artefactos como tablas/estadísticas a través de `queries:run`.
Las aprobaciones de escritura muestran el cambio propuesto y solicitan confirmación en una terminal. Los scripts y
`--json` lo rechazan a menos que `--approve` sea explícito. Las formas JSON existentes se mantienen
sin cambios cuando no se devuelve ningún artefacto.

```bash
fp login
fp login --email you@example.com --org reliability-team
fp whoami
```

En una terminal, `fp login` comienza con un enlace para iniciar sesión con tu navegador o SSO, y lo abre (sobre SSH o sin pantalla solo lo muestra, y funciona desde cualquier dispositivo); autorízalo y la terminal finaliza sola. Esa terminal obtiene tu acceso en todas tus organizaciones hasta que expire la sesión, así que solo autoriza un enlace que tú mismo acabas de solicitar. Si el inicio de sesión comenzó en una red diferente, recibes un correo electrónico una vez que existe la sesión, y la página te advierte desde dónde puede detectarlo el despliegue. Presiona **Tab** para recibir un código de 6 dígitos por correo electrónico en su lugar, y Tab de nuevo para volver. `--email`, `--json` y cualquier cosa sin terminal usan el código.

### Eventos

```text
fp events [OPTIONS]
```

Lista eventos individuales del agente. El feed ligero predeterminado excluye los payloads sin procesar; usa `--full` solo para una investigación acotada.

| Opción | Descripción |
| --- | --- |
| `--limit`, `-n <n>` | Máximo total de filas. Predeterminado: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` o `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Rango UTC en ISO 8601; reemplaza `--since`. |
| `--env <value>` | Filtro de entorno; repite o separa valores con comas. |
| `--event-type <value>` | Filtro de tipo de evento; repite o separa valores con comas. |
| `--agent-id <value>` | Filtro de agente; repite o separa valores con comas. |
| `--session-id <value>` | Filtro de sesión; repite o separa valores con comas. |
| `--search <text>` | Búsqueda de texto en payload; repetible, coincide con cualquier término. |
| `--order asc\|desc` | Orden temporal. Predeterminado: más reciente primero. |
| `--all` | Paginación automática hasta `--limit`. |
| `--cursor <token>` | Continuar desde un cursor opaco. |
| `--page-size <n>` | Filas por solicitud con `--all`; máximo `200`. |
| `--full` | Incluir payloads sin procesar a través del endpoint de eventos más pesado. |
| `--fields <csv>` | Devolver solo los campos seleccionados; solicitar `payload` activa el modo completo. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` pagina **hasta `--limit`**, que por defecto es **50** — así que `--all` solo
  se detiene en 50 filas. Cuando se detiene antes de tiempo, la respuesta incluye un
  `next_cursor` para continuar; `"next_cursor": null` significa que el feed realmente se
  agotó.
</Note>

#### Opciones de creación de auditoría

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Opción | Descripción |
| --- | --- |
| `--file <path>` | Basar la definición en JSON, o usar `-` para stdin. Los flags explícitos sobreescriben los valores del archivo. |
| `--description <text>` | Enunciar la pregunta de fallo o el propósito. |
| `--enabled` / `--disabled` | Iniciar la programación activada o desactivada. Predeterminado: activada. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Predeterminado: `86400`. |

Incluye el contexto durante la creación cuando la primera ejecución lo necesite. La creación confirma la definición y el contexto juntos antes de que comience la ejecución en cola.

  `fp audits run` es asíncrono. Monitorea `fp audits runs NAME` hasta que la última ejecución tenga éxito o falle antes de leer sus hallazgos.

<Warning>
  Las variantes `AGENTEYE_*` de estas variables **no son leídas por `fp`** y nunca lo fueron — el CLI declara `FP_*` (`fp_cli/app.py`), y una variable desconocida no es un error. Establecer `AGENTEYE_DASHBOARD_URL` no redirige el CLI; se ignora y el comando se ejecuta silenciosamente contra el dashboard guardado.

  `AGENTEYE_HOME` y `AGENTEYE_ENVIRONMENT` aún existen, pero pertenecen al **collector y al SDK de telemetría**, no a este CLI.
</Warning>

</Warning>
