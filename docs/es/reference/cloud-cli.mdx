Usa `fp` para inspeccionar la telemetría de Cloud y gestionar auditorías, hallazgos, incidencias, alertas, claves, usuarios, consultas y configuraciones. Usa [`failproofai`](/es/reference/failproof-cli) para hooks locales, políticas, captura e incorporación de máquinas.

Instala el Cloud CLI publicado como herramienta aislada:

```bash
uv tool install fp-cli
fp version
```

## Iniciar sesión

```bash
fp login
fp whoami
```

## Sintaxis

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Las opciones globales deben ir antes del comando:

```bash
fp --json sessions --since 24h
```

Ejecuta `fp COMMAND --help` o `fp COMMAND SUBCOMMAND --help` para obtener ayuda en la terminal.

## Comandos de la CLI

### Autenticación

| Comando | Propósito | Opciones |
| --- | --- | --- |
| `fp login` | Inicia sesión con un código de un solo uso enviado por correo y selecciona una organización. | `--email`, `-e`; `--org`; `--force` |
| `fp logout` | Revoca y elimina la sesión de usuario guardada. | — |
| `fp whoami` | Muestra la identidad actual, el modo de autenticación, la organización y los permisos. | — |
| `fp version` | Muestra la versión instalada de la CLI. | — |
| `fp help` | Muestra la ayuda de comandos de nivel superior. | — |

```bash
fp login --email you@example.com --org reliability-team
fp whoami
```

### Eventos

```text
fp events [OPTIONS]
```

Lista eventos individuales del agente. El feed ligero predeterminado excluye los payloads sin procesar; usa `--full` solo para investigaciones acotadas.

| Opción | Descripción |
| --- | --- |
| `--limit`, `-n <n>` | Número máximo total de filas. Por defecto: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` o `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Rango UTC en ISO 8601; anula `--since`. |
| `--env <value>` | Filtro de entorno; repite o separa los valores con comas. |
| `--event-type <value>` | Filtro de tipo de evento; repite o separa los valores con comas. |
| `--agent-id <value>` | Filtro de agente; repite o separa los valores con comas. |
| `--session-id <value>` | Filtro de sesión; repite o separa los valores con comas. |
| `--search <text>` | Búsqueda de texto en el payload; repetible, coincide con cualquier término. |
| `--order asc\|desc` | Orden temporal. Por defecto: más reciente primero. |
| `--all` | Pagina automáticamente hasta `--limit`. |
| `--cursor <token>` | Reanuda desde un cursor opaco. |
| `--page-size <n>` | Filas por petición con `--all`; máximo `200`. |
| `--full` | Incluye payloads sin procesar mediante el endpoint de eventos más pesado. |
| `--fields <csv>` | Devuelve solo los campos seleccionados; solicitar `payload` activa el modo completo. |

```bash
fp events --session-id <session-id> --order asc --all
fp --json events --full --session-id <session-id> --all
```

### Claves de API

| Comando | Propósito | Opciones |
| --- | --- | --- |
| `fp keys list` | Lista las claves de la organización. | `--show-id`; `--fields <csv>` |
| `fp keys show NAME` | Muestra una clave y sus permisos. | — |
| `fp keys create NAME` | Crea una clave y revela su secreto una única vez. | `--permission-set`; `--add`; `--remove` |
| `fp keys update NAME` | Reemplaza el conjunto de permisos o ajusta los permisos existentes. | `--permission-set`; `--add`; `--remove`; `--yes`, `-y` |
| `fp keys regenerate NAME` | Rota el secreto y revela el nuevo una única vez. | `--yes`, `-y` |
| `fp keys disable NAME` | Revoca una clave de forma permanente. | `--yes`, `-y` |

Los tokens de permiso usan el formato `resource:action`, por ejemplo `events:add`. Repite `--add`, separa los tokens con comas o usa acciones con puntos como `events:read.add`.

### Alertas

| Comando | Propósito | Opciones |
| --- | --- | --- |
| `fp alerts list` | Lista las reglas de alerta. | `--show-id` |
| `fp alerts show NAME` | Muestra una alerta. | — |
| `fp alerts create NAME` | Crea una alerta. | `--file`; `--description`; `--severity`; `--trigger-kind`; `--trigger-spec`; `--channels`; `--eval-interval-secs`; `--min-breaches`; `--eval-window` |

#### Opciones de creación de auditorías

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Opción | Descripción |
| --- | --- |
| `--file <path>` | Basa la definición en JSON, o usa `-` para stdin. Los flags explícitos anulan los valores del archivo. |
| `--description <text>` | Define la pregunta de fallo o el propósito. |
| `--enabled` / `--disabled` | Inicia la planificación activada o desactivada. Por defecto: activada. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Por defecto: `86400`. |
| `--schedule-anchor <timestamp>` | Fase UTC fija en formato ISO 8601. Por defecto: siguiente 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continúa después de la última ventana completamente analizada o inspecciona repetidamente una ventana deslizante. Por defecto: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Por defecto: `604800`. |
| `--scope '<json>'` | Filtra por `environments`, `agent_ids` u otros campos de scope compatibles. |
| `--ignore-error-type <type>` | Excluye tipos de error; repite o separa con comas. |
| `--llm` / `--no-llm` | Activa o desactiva el análisis agéntico. Por defecto: activado. |
| `--top-k <n>` | Conserva entre `1` y `500` hallazgos. Por defecto: `50`. |
| `--sensitivity low\|medium\|high` | Establece la sensibilidad de reporte. Por defecto: `medium`. |
| `--channels '<json>'` | Array de canales de notificación. |
| `--text <brief>` | Resumen en línea, máximo 8.192 caracteres. |
| `--text-file <path>` | Lee el resumen desde un archivo; mutuamente exclusivo con `--text`. |
| `--url <https-url>` | Añade una referencia HTTPS pública; repite hasta cinco veces. |

Incluye contexto durante la creación cuando la primera ejecución lo necesite. La creación confirma la definición y el contexto juntos antes de que comience la ejecución en cola.

<Note>
  `fp audits run` es asíncrono. Consulta `fp audits runs NAME` hasta que la última ejecución finalice con éxito o falle antes de leer sus hallazgos.
</Note>

## Flags globales

| Flag | Descripción |
| --- | --- |
| `--json` | Emite JSON legible por máquina. |
| `--base-url <url>` | Usa un dashboard alojado de forma autónoma o de desarrollo. |
| `--org <slug>` | Selecciona una organización para esta invocación. |
| `--token <token>` | Anula el token de sesión de usuario guardado. |
| `--api-key <key>` | Autentica la automatización con una clave de API; nunca se guarda. |
| `--timeout <seconds>` | Tiempo de espera HTTP; debe ser positivo. Por defecto: `30`. |
| `--quiet`, `-q` | Suprime la salida de estado en stderr. |
| `--no-color` | Deshabilita la salida con color. |
| `--insecure` / `--secure` | Deshabilita o restaura la verificación del certificado TLS. |
| `--version` | Imprime la versión y sale. |
| `--help`, `-h` | Muestra la ayuda. |

`--api-key` está pensado para automatización. El inicio de sesión, el cambio de organización y los comandos del asistente requieren una sesión de usuario.

## Variables de entorno

| Variable | Equivalente o propósito |
| --- | --- |
| `AGENTEYE_DASHBOARD_URL` | `--base-url` |
| `AGENTEYE_ORG` | `--org` |
| `AGENTEYE_CLI_TOKEN` | `--token` |
| `AGENTEYE_CLI_API_KEY` | `--api-key` |
| `AGENTEYE_CLI_JSON` | `--json` |
| `AGENTEYE_INSECURE` | `--insecure` |
| `AGENTEYE_HOME` | Reubica el directorio de configuración actual de la CLI. |
| `AGENTEYE_ANALYTICS_DISABLED` o `DO_NOT_TRACK` | Deshabilita el análisis anónimo de la CLI. |
| `NO_COLOR` | Deshabilita la salida con color. |

Los flags explícitos anulan las variables de entorno, que a su vez anulan la configuración guardada. En el modo de clave de API, selecciona el tenant explícitamente con `--org` o `AGENTEYE_ORG`.

<Warning>
  Los comandos que eliminan, revocan, silencian, resuelven o reemplazan configuración solicitan confirmación por defecto. Usa `--yes` solo después de verificar la organización activa y el objetivo.
</Warning>
