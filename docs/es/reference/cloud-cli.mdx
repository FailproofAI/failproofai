Usa `fp` para inspeccionar la telemetría de Cloud, gestionar la aplicación administrada en la nube (políticas, despliegues de flota, decisiones de guardrail) y administrar auditorías, hallazgos, incidencias, alertas, claves, usuarios, consultas y configuraciones. Usa [`failproofai`](/es/reference/failproof-cli) para hooks locales, políticas, captura e inscripción de máquinas.

También puedes crear y desplegar código alojado, evaluadores LLM-judge y Jev, gestionar
dashboards, inspeccionar el sentimiento y usar el asistente del dashboard desde la terminal.

Instala el Cloud CLI publicado como herramienta aislada:

```bash
uv tool install fp-cloud-cli
fp version
```

## Iniciar sesión

```bash
fp login
fp whoami
```

## Sintaxis

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Las opciones globales deben ir antes del comando:

```bash
fp --json sessions --since 24h
```

Ejecuta `fp COMMAND --help` o `fp COMMAND SUBCOMMAND --help` para obtener ayuda en la terminal.

## Comandos de la CLI

### Crear un evaluador

`fp evaluators` crea definiciones; `fp evals` lee resultados. Se requiere una instancia administrada habilitada (`fp evaluators instances`). La creación necesita
`evaluations:trigger`; los dry-runs de sesión y el perfilado de esquemas también necesitan `events:read`.

El código es una expresión Python restringida. Guarda esto como `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev binario y rúbrica graduada:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
La creación habilita el evaluador. Deploy crea una nueva versión inmutable y luego
deshabilita las versiones anteriores habilitadas. Un fallo posterior deja la nueva versión
publicada: inspecciona `evaluators list --all` antes de reintentar.
Cloud rechaza los dry-runs de judge. Los dry-runs de Jev consumen presupuesto de modelo.
El backfill cubre evaluadores de código, judge y Jev y acepta un máximo de 90 días; solo encola las sesiones que un evaluador aún no ha puntuado. Los backfills de judge y Jev consumen presupuesto de modelo, así que ejecuta primero `fp evaluators backfill --dry-run`.
La salida en modo humano muestra los resultados del dry-run por sesión antes de crear/desplegar.
Las vistas previas fallidas detienen la escritura a menos que pases explícitamente `--force` tras la revisión.
</Warning>

La redacción con IA requiere `fp login` y escribe una especificación aceptada por create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Comando | Opciones / comportamiento |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Fuente/envelope completo |
| `fp evaluators create` | `--key`, `--name`, `--version`, `--label` repetible, `--condition EXPR\|@file`, una fuente, `--dry-run-on` repetible, `--disabled`, `--force` explícito para vistas previas fallidas |
| `fp evaluators deploy KEY` | Mismas opciones de fuente; `--version`, `--backfill 7d` (cualquier tipo, 1–90 días), `--force`; las versiones numéricas se autoincrementan; KEY proporciona el `eval_key` del archivo de especificación si falta |
| `fp evaluators draft "intent"` | Sesión; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Opciones de fuente o `--file`, `--session` repetible (máximo 10); ninguno = solo compilar |
| `fp evaluators enable\|disable KEY[@VERSION]` | Alternar |
| `fp evaluators label KEY[@VERSION]` | `--add`, `--remove` repetibles |
| `fp evaluators instances\|schema\|jobs` | Inspeccionar flota/esquema/trabajos administrados |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; código, judge y Jev |

Las opciones de código son `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. Las opciones de judge son `--judge --criteria TEXT`, `--step` y
`--threshold` repetibles. Las opciones de Jev son `--jev noul --instructions --true --false` o
`--jev score --instructions` con 3–5 valores distintos de `--level`, del peor al mejor.
Judge/Jev requieren una puntuación; los umbrales van de 0 a 1. Los pasos de judge binarios son rechazados.

Los archivos de especificación contienen exactamente `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
El `evaluator_source` de judge/Jev es una cadena de envelope JSON. No incluyas IDs de fila,
estado habilitado ni metadatos de razonamiento de IA. `--file` y las opciones de especificación discretas son
exclusivos entre sí; deploy puede sobreescribir la versión del archivo. Los archivos de salida nunca se sobreescriben.

### Nuevos controles del dashboard

Todos los comandos aceptan `--json` global. Los 404 de ruta desconocida salen con código 6 y mensaje "not available
on this FailproofAI Cloud yet". Los 404 de registro faltante también salen con código 6 pero reportan que el
registro no fue encontrado. Los comandos exclusivos de sesión deniegan el modo clave antes del HTTP (salida 2).

Los comandos en modo humano usan resúmenes y tablas. Para exportaciones JSON sin procesar, pasa el global
`--json` o guarda con `--out FILE`; de lo contrario, las exportaciones de sesión y consulta JSON muestran
una vista legible. Las exportaciones CSV permanecen como CSV simple para su uso en tuberías.

| Comandos | Opciones / notas |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | Crear `--name`, `--description`, `--file` definición; update conserva los campos no mencionados |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | Añadir `--query ID --chart TYPE --title`; configuración/geometría o layout mediante `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | Exportar `--out`; history es el historial de evaluaciones |
| `fp sessions import FILE...` | Transcripciones de Claude Code, rollouts de Codex o evento JSONL (`.gz` permitido); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; requiere `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; list `--limit`; messages `--session-id` |
| `fp query compose "question"` | Sesión; `--run` |
| `fp query export [ID]` | O `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Issues puede `--create --title --summary` o `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; update `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | Sesión; redacta una política a partir de los eventos de tu organización, nunca publica |
| `fp policies backtest [FILE_OR_ID]` | Sesión; regex reproduce el módulo; `jev`/`both` (publicados, o `--semantic checks.json`) estiman de forma gratuita, `--run [--sample N]` consume la cuota de Jev; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | Sesión; si una política podría prevenir esta incidencia |
| `fp issues facets` | Valores que pueden tomar los filtros de la bandeja de entrada, con conteos |
| `fp agent brief` | Sesión; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | Sesión; deriva el slug omitido, no cambia de organización |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | Conjuntos de permisos; create `--name --permission`; update reemplaza `--permission` o combina `--add/--remove`; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | Eliminación por id |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` requiere una clave API; plan (ofertas y prueba) y claim requieren una sesión iniciada |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1.000.000 tokens |
| `fp otel status\|enable\|disable` | Interruptor de ingesta de la organización en Cloud, no captura local |
| `fp slack status\|disconnect` | Sesión |

`fp agent ask` renderiza SQL de artefactos como tablas/estadísticas a través de `queries:run`.
Las aprobaciones de escritura muestran el cambio propuesto y solicitan confirmación en una terminal interactiva. Los scripts y
`--json` rechazan a menos que `--approve` sea explícito. Las formas JSON existentes permanecen
sin cambios cuando no se devuelve ningún artefacto.

### Eventos

```text
fp events [OPTIONS]
```

Lista eventos individuales del agente. El feed ligero predeterminado excluye los payloads sin procesar; usa `--full` solo para una investigación acotada.

| Opción | Descripción |
| --- | --- |
| `--limit`, `-n <n>` | Máximo total de filas. Predeterminado: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` o `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Rango UTC en ISO 8601; sobreescribe `--since`. |
| `--env <value>` | Filtro de entorno; repite o separa valores con comas. |
| `--event-type <value>` | Filtro de tipo de evento; repite o separa valores con comas. |
| `--agent-id <value>` | Filtro de agente; repite o separa valores con comas. |
| `--session-id <value>` | Filtro de sesión; repite o separa valores con comas. |
| `--search <text>` | Búsqueda de texto en el payload; repetible, coincide con cualquier término. |
| `--order asc\|desc` | Orden temporal. Predeterminado: más reciente primero. |
| `--all` | Pagina automáticamente hasta `--limit`. |
| `--cursor <token>` | Continuar desde un cursor opaco. |
| `--page-size <n>` | Filas por solicitud con `--all`; máximo `200`. |
| `--full` | Incluir payloads sin procesar a través del endpoint de eventos más completo. |
| `--fields <csv>` | Devolver solo los campos seleccionados; solicitar `payload` activa el modo completo. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` pagina **hasta `--limit`**, que por defecto es **50** — así que `--all` por sí solo
  se detiene en 50 filas. Cuando se detiene antes de tiempo, la respuesta incluye un
  `next_cursor` para continuar; `"next_cursor": null` significa que el feed realmente se agotó.
</Note>

#### Opciones de creación de auditoría

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Opción | Descripción |
| --- | --- |
| `--file <path>` | Basar la definición en JSON, o usar `-` para stdin. Las opciones explícitas sobreescriben los valores del archivo. |
| `--description <text>` | Indicar la pregunta de fallo o el propósito. |
| `--enabled` / `--disabled` | Iniciar la programación activada o desactivada. Predeterminado: habilitado. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Predeterminado: `86400`. |
| `--schedule-anchor <timestamp>` | Fase UTC fija en formato ISO 8601. Predeterminado: próximas 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continuar después de la última ventana completamente analizada o inspeccionar repetidamente una ventana deslizante. Predeterminado: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Predeterminado: `604800`. |
| `--scope '<json>'` | Filtrar por `environments`, `agent_ids` u otros campos de ámbito compatibles. |
| `--ignore-error-type <type>` | Excluir tipos de error; repite o separa con comas. |
| `--llm` / `--no-llm` | Habilitar o deshabilitar el análisis agente. Predeterminado: habilitado. |
| `--top-k <n>` | Conservar `1`–`500` hallazgos. Predeterminado: `50`. |

Incluye el contexto durante la creación cuando la primera ejecución lo necesite. La creación confirma la definición y el contexto juntos antes de que comience la ejecución en cola.

<Warning>
  Los nombres `AGENTEYE_*` de estas variables **no son leídos por `fp`** y nunca lo fueron — la CLI declara `FP_*` (`fp_cli/app.py`), y una variable desconocida no es un error. Establecer `AGENTEYE_DASHBOARD_URL` no redirige la CLI; se ignora y el comando se ejecuta silenciosamente contra el dashboard guardado.

  `AGENTEYE_HOME` y `AGENTEYE_ENVIRONMENT` aún existen, pero pertenecen al **recolector y al SDK de telemetría**, no a esta CLI.
</Warning>

</Warning>
