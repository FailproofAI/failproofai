Usa `fp` para inspeccionar la telemetría de Cloud, gestionar la aplicación administrada en la nube (políticas, despliegues de flota, decisiones de guardarraíles) y administrar auditorías, hallazgos, incidencias, alertas, claves, usuarios, consultas y configuraciones. Usa [`failproofai`](/es/reference/failproof-cli) para hooks locales, políticas, captura e inscripción de máquinas.

Instala el Cloud CLI publicado como herramienta aislada:

```bash
uv tool install fp-cloud-cli
fp version
```

## Iniciar sesión

```bash
fp login
fp whoami
```

## Sintaxis

```text
fp [OPCIONES_GLOBALES] COMANDO [SUBCOMANDO] [ARGUMENTOS] [OPCIONES]
```

Las opciones globales deben ir antes del comando:

```bash
fp --json sessions --since 24h
```

Ejecuta `fp COMANDO --help` o `fp COMANDO SUBCOMANDO --help` para ver la ayuda en el terminal.

### Eventos

```text
fp events [OPTIONS]
```

Lista eventos individuales de agentes. El feed ligero predeterminado excluye los payloads sin procesar; usa `--full` únicamente para una investigación acotada.

| Opción | Descripción |
| --- | --- |
| `--limit`, `-n <n>` | Máximo total de filas. Predeterminado: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` o `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Rango UTC en ISO 8601; sustituye a `--since`. |
| `--env <value>` | Filtro de entorno; repite o separa valores con comas. |
| `--event-type <value>` | Filtro de tipo de evento; repite o separa valores con comas. |
| `--agent-id <value>` | Filtro de agente; repite o separa valores con comas. |
| `--session-id <value>` | Filtro de sesión; repite o separa valores con comas. |
| `--search <text>` | Búsqueda de texto en el payload; repetible, coincide con cualquier término. |
| `--order asc\|desc` | Orden temporal. Predeterminado: más reciente primero. |
| `--all` | Paginación automática hasta `--limit`. |
| `--cursor <token>` | Reanuda desde un cursor opaco. |
| `--page-size <n>` | Filas por solicitud con `--all`; máximo `200`. |
| `--full` | Incluye los payloads sin procesar a través del endpoint de eventos más pesado. |
| `--fields <csv>` | Devuelve solo los campos seleccionados; solicitar `payload` activa el modo completo. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` pagina **hasta `--limit`**, cuyo valor predeterminado es **50**, por lo que `--all` solo se detiene en 50 filas. Cuando se detiene antes de tiempo, la respuesta incluye un `next_cursor` para reanudar; `"next_cursor": null` indica que el feed realmente se agotó.
</Note>

#### Opciones de creación de auditorías

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Opción | Descripción |
| --- | --- |
| `--file <path>` | Basa la definición en JSON o usa `-` para stdin. Los flags explícitos sobrescriben los valores del archivo. |
| `--description <text>` | Indica la pregunta de fallo o el propósito. |
| `--enabled` / `--disabled` | Inicia la programación activada o desactivada. Predeterminado: habilitada. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Predeterminado: `86400`. |
| `--schedule-anchor <timestamp>` | Fase UTC fija en formato ISO 8601. Predeterminado: próximas 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continúa tras la última ventana completamente analizada o inspecciona repetidamente una ventana deslizante. Predeterminado: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Predeterminado: `604800`. |
| `--scope '<json>'` | Filtra por `environments`, `agent_ids` u otros campos de alcance compatibles. |
| `--ignore-error-type <type>` | Excluye tipos de error; repite o separa con comas. |
| `--llm` / `--no-llm` | Habilita o deshabilita el análisis agéntico. Predeterminado: habilitado. |
| `--top-k <n>` | Retiene entre `1` y `500` hallazgos. Predeterminado: `50`. |
| `--sensitivity low\|medium\|high` | Establece la sensibilidad de los informes. Predeterminado: `medium`. |
| `--channels '<json>'` | Array de canales de notificación. |
| `--text <brief>` | Resumen en línea, máximo 8 192 caracteres. |
| `--text-file <path>` | Lee el resumen desde un archivo; mutuamente exclusivo con `--text`. |
| `--url <https-url>` | Añade una referencia HTTPS pública; repite hasta cinco veces. |

Incluye el contexto durante la creación cuando la primera ejecución lo necesite. La creación confirma la definición y el contexto juntos antes de que comience la ejecución en cola.

<Note>
  `fp audits run` es asíncrono. Sondea `fp audits runs NAME` hasta que la última ejecución tenga éxito o falle antes de leer sus hallazgos.
</Note>

### Políticas

Versiones de políticas administradas en la nube. **Solo para sesión** — todos los comandos aquí salen con código `2` bajo una clave de API, antes de cualquier solicitud, porque estas son rutas de escritura de nivel raíz deliberadamente ausentes de `/v1`.

| Comando | Propósito | Opciones |
| --- | --- | --- |
| `fp policies list` | Lista las versiones de políticas. | `--json` |
| `fp policies show POLICY_ID` | Muestra una política con su fuente. | — |
| `fp policies publish NAME PATH` | Crea una versión a partir de un archivo `.mjs` local. | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | La vuelve a añadir a todos los despliegues de los que fue eliminada, creando una nueva generación en cada uno. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | La elimina de todos los despliegues que la contienen, creando una nueva generación en cada uno. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | Elimina una versión de política. | `--yes`, `-y` |
| `fp policies test PATH` | Ejecuta una política localmente contra un contexto sintético. Aplica el filtro `match` de cada política, por lo que una que no cubra el evento/herramienta dado se notifica como `skipped` en lugar de ejecutarse. | `--event`; `--tool`; `--command`; `--file-path`; `--expect` |
| `fp policies compose PROMPT` | Redacta una política con el asistente. Requiere `policies:write`. | — |

## Flags globales

| Flag | Descripción |
| --- | --- |
| `--json` | Emite JSON legible por máquinas. |
| `--base-url <url>` | Usa un dashboard autohospedado o de desarrollo. |
| `--org <slug>` | Selecciona una organización para esta invocación. |
| `--token <token>` | Sobrescribe el token de sesión de usuario guardado. |
| `--api-key <key>` | Autentica la automatización con una clave de API; nunca se guarda. |
| `--timeout <seconds>` | Tiempo de espera HTTP; debe ser positivo. Predeterminado: `30`. |
| `--quiet`, `-q` | Suprime la salida de estado en stderr. |
| `--no-color` | Deshabilita la salida con colores. |
| `--insecure` / `--secure` | Deshabilita o restaura la verificación del certificado TLS. |
| `--version` | Imprime la versión instalada y sale. |
| `--help`, `-h` | Muestra la ayuda. |

`--api-key` está pensado para automatización. Los comandos de inicio de sesión, cambio de organización y asistente requieren una sesión de usuario.

## Variables de entorno

| Variable | Equivalente o propósito |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | Reubica el directorio de configuración de la CLI (predeterminado: `~/.failproofai/fpcli`). |
| `FP_ANALYTICS_DISABLED` o `DO_NOT_TRACK` | Deshabilita las analíticas anónimas de la CLI. |
| `NO_COLOR` | Deshabilita la salida con colores. |

Los flags explícitos sobrescriben las variables de entorno, que a su vez sobrescriben la configuración guardada. En el modo de clave de API, selecciona el tenant explícitamente con `--org` o `FP_ORG`.

<Warning>
  Los equivalentes `AGENTEYE_*` de estas variables **no son leídos por `fp`** ni nunca lo fueron — la CLI declara `FP_*` (`fp_cli/app.py`), y una variable desconocida no es un error. Establecer `AGENTEYE_DASHBOARD_URL` no redirige la CLI; se ignora y el comando se ejecuta silenciosamente contra el dashboard guardado.

  `AGENTEYE_HOME` y `AGENTEYE_ENVIRONMENT` siguen existiendo, pero pertenecen al **colector y al SDK de telemetría**, no a esta CLI.
</Warning>

<Warning>
  Los comandos que eliminan, revocan, suprimen, resuelven o reemplazan configuraciones muestran un prompt de confirmación por defecto. Usa `--yes` solo después de verificar la organización activa y el objetivo.
</Warning>
