Los dashboards combinan consultas guardadas en una vista operativa. Constrúyelos en torno a una decisión que esperas que alguien tome, no alrededor de cada métrica disponible.

## Crear un dashboard

<Tabs>
  <Tab title="Dashboard">
    1. Ve a **Analyze → Queries**, crea o abre una consulta guardada y valida su resultado.
    2. Selecciona **add to dashboard**, luego elige un dashboard existente o crea uno en **Analyze → Dashboards**.
    3. Abre el dashboard, activa el modo de edición, organiza los paneles y guarda el diseño.
    4. Vuelve a la consulta cuando necesites cambiar los datos o los filtros detrás de un panel.

    ![Un dashboard compuesto por consultas guardadas sobre volumen de eventos, errores, latencia y uso de tokens del modelo.](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    Las operaciones CRUD de dashboards no están disponibles en el CLI de Cloud actual. Usa el CLI para crear y verificar la consulta guardada, luego agrégala a un dashboard desde la interfaz.

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

Algunos grupos de dashboards útiles incluyen:

- **Modelos:** volumen, latencia, uso de tokens, tasa de errores y puntuaciones de evaluación.
- **Evaluaciones:** tasa de éxito y tendencias de puntuación por agente o entorno.
- **Herramientas:** volumen de llamadas, tasa de fallos, duración y llamadas repetidas.
- **Hooks y políticas:** decisiones, denegaciones y tasa de coincidencia de políticas.
- **Métricas personalizadas de flujo de trabajo:** resultados de tus propios campos de eventos y SQL.

Comienza con una consulta guardada, valida su resultado y agrégala como panel. Mantén los filtros de producción y desarrollo explícitos para que el tráfico de pruebas no oculte una regresión.

<Tip>
  Asigna a cada dashboard un responsable y una pregunta de referencia, como por ejemplo: "¿Es la fiabilidad del checkout-agent peor que la semana pasada?"
</Tip>
