Las consultas son la capa flexible que subyace a los paneles, auditorías e investigaciones. Usa SQL ad-hoc para probar una idea y luego guarda la consulta cuando se convierta en parte de un flujo de trabajo recurrente.

## Crear y ejecutar una consulta

<Tabs>
  <Tab title="Panel de control">
    1. Ve a **Analyze → Queries** y selecciona **new query**.
    2. Abre el explorador de esquema y elige campos de los datos de eventos, sesiones o evaluaciones.
    3. Escribe el SQL, agrega parámetros cuando sea necesario y ejecuta la consulta.
    4. Guárdala con un nombre y descripción claros, y luego usa **add to dashboard** cuando el resultado deba monitorizarse.

    El editor de consultas combina el esquema de eventos, SQL, parámetros y una vista previa de resultados para que puedas validar la pregunta antes de guardarla.

    ![El editor de consultas SQL con un explorador de esquema y una cuadrícula de resultados en vivo.](/images/dashboard/query-lab.png)

    Las consultas guardadas aparecen en la biblioteca compartida, donde los compañeros de equipo pueden volver a ejecutarlas o agregar sus resultados a los paneles.

    ![La biblioteca de consultas guardadas que contiene consultas integradas y personalizadas reutilizables.](/images/dashboard/queries.png)

    Usa un nombre y descripción claros para que el resultado sea comprensible sin necesidad de abrir de nuevo el SQL.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    Usa `fp query list` para encontrar IDs y `fp query delete <query-id>` para eliminar una consulta guardada.
  </Tab>
</Tabs>

## Usos comunes

- Encontrar sesiones con llamadas repetidas a la misma herramienta.
- Comparar puntuaciones de evaluación entre modelos o entornos.
- Medir el tiempo entre una espera humana y la reanudación.
- Identificar denegaciones de políticas seguidas de una alternativa exitosa.
- Construir una cohorte para una auditoría.

Abre **Queries → Schema** antes de escribir consultas sobre campos desconocidos. Prefiere filtros explícitos de tiempo y entorno, y mantén límites en los resultados durante la exploración.

<Warning>
  Una consulta puede identificar un patrón sospechoso, pero por sí sola no establece el modo de fallo. Abre trazas representativas o ejecuta una auditoría antes de convertir el resultado en una política.
</Warning>
