title: "Leer un trace"
description: "Encuentra el evento que cambió el curso de una sesión de agente."

---

Un trace convierte un flujo de eventos plano en la historia causal de la ejecución. Léelo desde la primera divergencia, no hacia atrás desde el último error.

## Abrir el trace

<Tabs>
  <Tab title="Dashboard">
    1. Ve a **Observe → Sessions** y abre una sesión.
    2. Usa el resumen del perfil para verificar el resultado, el tiempo, los errores y las puntuaciones de evaluación.
    3. Revisa el timeline y el minimapa. Filtra por tipos de evento o por tiempo cuando la sesión sea extensa.
    4. Selecciona un evento para inspeccionarlo. Usa **export** para obtener el JSON del evaluador, o copia la URL de la página para compartir un enlace directo a la evidencia seleccionada.

    ![Vista de detalle de una sesión con su grafo de ejecución, timeline de eventos, panel de evaluación y desglose de herramientas, modelo y hooks.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    Usa primero el feed ligero de eventos. Solicita los payloads completos solo cuando los resúmenes de eventos no contengan evidencia suficiente.
  </Tab>
</Tabs>

<Steps>
  <Step title="Oriéntate">
    Confirma el agente, el entorno, el tiempo, el resultado y la duración; luego busca errores, spans largos, herramientas repetidas, esperas de usuarios y decisiones de política denegadas.
  </Step>
  <Step title="Expande el primer evento sospechoso">
    Inspecciona su solicitud, respuesta, entrada de herramienta, salida e ID de correlación. El contenido sensible solo es visible cuando la captura de transcripción está habilitada y tus permisos lo permiten.
  </Step>
  <Step title="Inspecciona el contexto anterior">
    La causa suele estar un evento antes: una respuesta incorrecta del modelo, un resultado de herramienta faltante o una suposición desactualizada.
  </Step>
  <Step title="Convierte la evidencia en acción">
    Añade la sesión a un ámbito de auditoría, vincúlala a un issue o usa el modo de fallo para crear una política.
  </Step>
</Steps>

<Warning>
  Una duración larga no siempre implica latencia del modelo. Separa el tiempo del modelo, de las herramientas, de los hooks y de la espera del usuario antes de decidir qué corregir.
</Warning>
