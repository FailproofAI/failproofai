title: "Leer un trace"
description: "Encuentra el evento que cambió el curso de una sesión del agente."
icon: "route"
---

Un trace convierte un flujo plano de eventos en la historia causal de la ejecución. Léelo desde la primera divergencia, no hacia atrás desde el último error.

## Abrir el trace

<Tabs>
  <Tab title="Dashboard">
    1. Ve a **Observe → Sessions** y abre una sesión.
    2. Usa el resumen del perfil para verificar el resultado, el tiempo de ejecución, los errores y las puntuaciones de evaluación.
    3. Examina la línea de tiempo y el minimapa. Filtra tipos de eventos o intervalos de tiempo cuando la sesión sea extensa.
    4. Selecciona un evento para inspeccionarlo. Usa **export** para obtener el JSON del evaluador, o copia la URL de la página para compartir un enlace directo a la evidencia seleccionada.

    ![Vista de detalle de una sesión con su gráfico de ejecución, línea de tiempo de eventos, panel de evaluación y desglose de herramientas, modelo y hooks.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    Usa primero el feed de eventos ligero. Solicita los payloads completos solo cuando los resúmenes de eventos no contengan suficiente evidencia.
  </Tab>
</Tabs>

<Steps>
  <Step title="Oriéntate">
    Confirma el agente, el entorno, el tiempo de ejecución, el resultado y la duración; luego busca errores, spans largos, herramientas repetidas, esperas humanas y decisiones de política denegadas.
  </Step>
  <Step title="Expande el primer evento sospechoso">
    Inspecciona su solicitud, respuesta, entrada y salida de la herramienta, y el ID de correlación. El contenido sensible solo es visible cuando la captura de transcripciones está habilitada y tus permisos lo permiten.
  </Step>
  <Step title="Inspecciona el contexto anterior">
    La causa suele estar un evento antes: una respuesta incorrecta del modelo, un resultado de herramienta faltante o una suposición desactualizada.
  </Step>
  <Step title="Convierte la evidencia en acción">
    Agrega la sesión a un alcance de auditoría, vincúlala a un issue o usa el modo de fallo para crear una política.
  </Step>
</Steps>

<Warning>
  Una duración larga no siempre significa latencia del modelo. Separa el tiempo del modelo, las herramientas, los hooks y la espera humana antes de decidir qué corregir.
</Warning>
