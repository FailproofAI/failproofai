Failproof AI registra lo que hacen los agentes y decide qué pueden hacer.

## Observar

| Término | Significado |
| --- | --- |
| Session | Una ejecución de agente |
| Event | Una acción dentro de una sesión |
| Trace | La vista ordenada de una sesión |
| Evaluation | Una puntuación o valoración |
| Audit | Una revisión de múltiples sesiones |
| Finding | Evidencia de un patrón de fallo |
| Issue | La respuesta de la que alguien es responsable |
| Alert | Una regla que detecta recurrencia |

## Aplicar

| Término | Significado |
| --- | --- |
| Harness | El entorno donde se ejecuta un agente |
| Hook | Un punto donde el harness solicita una decisión |
| Policy | Una regla que permite, orienta o bloquea |
| Policy pack | Un conjunto de políticas versionado que cualquiera puede instalar |
| Daemon | El servicio local que evalúa las políticas |
| Deployment | Políticas asignadas a una máquina |

## El flujo de trabajo

```text
Session → Audit → Finding → Issue → Policy
```

Empieza con evidencia. Identifica el fallo recurrente, asigna la respuesta y luego prevenlo.

Una política devuelve `allow`, `instruct` o `deny`. La orientación mediante `instruct` depende del harness; usa `deny` cuando la acción deba detenerse.

El modo de observación es independiente de la decisión. Ejecuta la política real y registra lo que haría, mientras permite que el agente continúe.

<Warning>
  Un simple `fp fleet deploy <machine> --add <policy>` aplica la política de inmediato. Añade `:observe` para un despliegue en modo sombra.
</Warning>

La configuración inicial no elige ningún policy pack. Antes de añadir uno, solo se ejecuta `block-failproofai-commands`. El catálogo compilado contiene 39 políticas en 9 categorías.

Consulta los [harnesses compatibles](/es/reference/harnesses#enforcement-capability) antes de asumir que un evento puede bloquear en cualquier entorno de agente.
