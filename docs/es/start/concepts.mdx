| Concepto | Qué significa | Qué puedes lograr |
| --- | --- | --- |
| Sesión | Una tarea o ejecución de un agente | Reconstruir un resultado individual |
| Evento | Una acción registrada en una sesión | Inspeccionar una llamada al modelo, uso de herramienta, error, acción humana o decisión de política |
| Traza | La vista ordenada y anidada de una sesión | Comprender la causalidad en lugar de leer registros desconectados |
| Evaluación | Una puntuación o juicio sobre una sesión | Rastrear calidad, cumplimiento, costo o latencia de forma continua |
| Auditoría | Una revisión de una población de sesiones seleccionadas | Buscar patrones de fallo con un objetivo y una cadencia definidos |
| Hallazgo | Un fallo respaldado por evidencia descubierto por una auditoría | Ver el modo de fallo, la gravedad y las sesiones afectadas |
| Incidencia | Un registro de respuesta duradero | Asignar, discutir y resolver un hallazgo o incidente de alerta |
| Alerta | Una regla que detecta recurrencias | Notificar a los responsables cuando una condición conocida vuelve a aparecer |
| Política | Una regla evaluada durante la actividad del agente | Observar, bloquear o redirigir comportamientos de riesgo |
| Despliegue | Un rollout de políticas versionado hacia máquinas | Controlar dónde se ejecuta una política y revertirla de forma segura |

## El ciclo de fiabilidad

Comienza desde la evidencia. Una sesión muestra lo que ocurrió. Una auditoría determina si se trata de un error aislado o de un patrón. Un hallazgo identifica el modo de fallo; una incidencia gestiona la respuesta. Una política previene el mismo comportamiento, mientras que las alertas te informan si la condición vuelve a aparecer.

<Warning>
  Un `failproofai audit` local analiza el historial del agente en local. Una auditoría recurrente en la nube revisa las sesiones almacenadas en Failproof AI Cloud. Son flujos de trabajo independientes con distinto alcance y programación.
</Warning>
