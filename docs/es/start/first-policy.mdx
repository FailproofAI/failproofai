Empieza con un comportamiento que quieras detener y una acción legítima que deba seguir funcionando.

## Prueba primero una política revisada

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI incluye 39 políticas revisadas. Consulta el [catálogo](/es/policies/builtin-catalog) antes de escribir una nueva.

## Escribe y prueba la tuya propia

<Steps>
  <Step title="Crea una política funcional">
    ```bash
    failproofai publish --init guards.mjs
    ```

    Esto escribe una política que bloquea `git push --force`. Edítala para tu regla.
  </Step>
  <Step title="Aplícala en esta máquina">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    Pídele a tu agente que realice la acción bloqueada y luego revisa **Policies → Activity** en el panel local.
  </Step>
  <Step title="Consérvala o elimínala">
    Coloca un archivo `*policies.mjs` dentro de `.failproofai/policies/` para cargarlo automáticamente.

    Elimina los archivos personalizados explícitos con:

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## Compártela

Publica un pack público:

```bash
failproofai publish
```

Cualquiera podrá instalarlo con `failproofai policies add <owner>/<repo>`. Añade el tema de GitHub `failproofai-policies` tú mismo para que el [Policy Hub](https://befailproof.ai/policy-hub/) pueda indexarlo.

Para un despliegue en Cloud:

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  Un `--add checkout-guard` sin modificadores aplica el bloqueo de inmediato. Añade `:observe` para registrar lo que haría la política sin bloquear al agente.
</Warning>

Consulta [publicar un pack](/es/policies/publish-a-pack) o [desplegar políticas](/es/policies/deploy) para ver el flujo de trabajo completo.
