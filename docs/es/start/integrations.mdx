## Antes de empezar

Dos cosas que este camino asume, ninguna de las cuales hace el código a continuación:

| Requisito | Por qué |
| --- | --- |
| Python 3.10 o superior | El mínimo que declara el SDK. |
| Una máquina configurada con `failproofai config` | Ese comando instala el daemon failproofaid, y el daemon es lo único que envía lo que escribe el SDK. Sin él, los lotes se acumulan en el directorio de cola y nunca salen. |

<Note>
  **Este camino registra; no aplica políticas.** El SDK captura lo que hizo tu agente. Las políticas se activan desde un hook dentro de un CLI de agente, por lo que aplicarlas en un agente de framework implica colocar un hook en tu propio runtime — consulta [Políticas](/es/policies/overview).
</Note>

## Tres líneas, cualquiera que sea el framework

<CodeGroup>
```bash LangGraph
pip install 'failproofai-sdk[langgraph]'
```

```bash CrewAI
pip install 'failproofai-sdk[crewai]'
```

```bash LlamaIndex
pip install 'failproofai-sdk[llamaindex]'
```

```bash Pydantic AI
pip install 'failproofai-sdk[pydantic-ai]'
```

```bash Custom agents
pip install failproofai-sdk
```
</CodeGroup>

```python
import failproofai_sdk

failproofai_sdk.configure(environment="production")
failproofai_sdk.instrument()          # detecta los frameworks que importaste

with failproofai_sdk.session():
    ...                               # tu llamada al agente existente, sin cambios
```

Sin decoradores en tus funciones, sin callbacks pasados a tus llamadas, sin ids distribuidos por todo tu código. Solo la llamada dentro de la sesión es diferente:

<Tabs>
  <Tab title="LangGraph">
    ```python
    graph.invoke({"messages": [HumanMessage("...")]})
    ```
  </Tab>
  <Tab title="CrewAI">
    ```python
    Crew(agents=[analyst, writer], tasks=[gather, summarise]).kickoff()
    ```
  </Tab>
  <Tab title="LlamaIndex">
    ```python
    await agent.run("...")        # bajo `async with failproofai_sdk.session():`
    ```
  </Tab>
  <Tab title="Pydantic AI">
    ```python
    agent.run_sync("...")
    ```
  </Tab>
  <Tab title="Custom agents">
    ```python
    with failproofai_sdk.agent("planner"):
        with failproofai_sdk.tool_call("search", input={"q": q}) as t:
            t.output = search(q)
    ```
  </Tab>
</Tabs>

El extra instala el **framework**. Todos los adaptadores se incluyen en la rueda base, por lo que un proyecto que ya tiene su framework no necesita ningún extra en absoluto.

## Verifica que llegó

Ejecuta una sesión instrumentada y luego abre **Observe → Sessions** y selecciona tu entorno. La ejecución aparece como una traza reconstruida.

Si no llega nada, confirma que la máquina está configurada y conectada con `failproofai config --status`. Si no lo está, ejecuta `failproofai config`. Consulta [Elige tu configuración](/es/start/setup).

<Warning>
  No compruebes el directorio de cola para confirmar la entrega. El daemon de Failproof recopila y elimina cada lote en milisegundos, por lo que leerlo compite con el colector y muestra muchos menos eventos de los que se emitieron.
</Warning>

Para comprobar que el SDK está escribiendo, detén primero el daemon, luego ejecuta tu sesión y mira en `~/.failproofai/custom-agents/events/`. Con el daemon en ejecución, un directorio vacío es el estado correcto.

<CodeGroup>
```bash Linux
sudo systemctl stop failproofaid@$USER
```

```bash macOS
sudo launchctl bootout system/ai.failproof.failproofaid.$USER
```
</CodeGroup>

Ejecuta `failproofai config` después para restaurarlo. Mientras el daemon esté detenido, los eventos de hook en esta máquina no tienen evaluador y se deniegan, así que detenlo solo el tiempo que dure la comprobación.
