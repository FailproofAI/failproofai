Este inicio rápido conecta una máquina para que reporte sesiones, ejecuta una auditoría y despliega una política. Usa la skill para configurar Failproof o sigue los pasos manuales.

**¿Cuál es tu camino?** Si tu agente corre en uno de los 12 [harnesses](/es/reference/harnesses) compatibles — una CLI de programación, o un gateway como Hermes o OpenClaw — sigue los pasos a continuación; necesitas Node.js 20.9 o posterior. Si tu agente no tiene harness, instrumétalo con el [SDK de Python](/es/reference/custom-agents) para trazado y auditorías, y luego retoma en [Ejecuta tu primera verificación de fallos](/es/start/first-audit); la aplicación de políticas en esa ruta requiere un hook en tu runtime.

  <Tab title="Configuración manual">
    ## Instalación

<Steps>
  <Step title="Instala y conecta Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    Ese único comando abarca toda la configuración: instala el daemon local (una sola vez como root), conecta los hooks a cada CLI de agente que encuentre y vincula esta máquina a Cloud.

    En **Connect to cloud**, la configuración inicia sesión en FailproofAI Cloud de inmediato (presiona Tab para las otras opciones: pegar una clave de API o usar la versión open source). Abre un enlace en tu navegador (por SSH, o en una máquina sin pantalla, imprime el enlace para que puedas abrirlo en cualquier dispositivo). Regístrate o inicia sesión, confirma la organización — o crea una en ese mismo momento — y haz clic en **Authorize**. El nombre y los permisos de la clave se configuran automáticamente. No necesitas tener una cuenta previamente.

    La terminal lo detecta sola y muestra quién lo autorizó y para qué organización. Confirma los agentes que deseas rastrear y la configuración finaliza. La clave de la máquina se crea solo en ese momento, después de que el daemon está instalado, por lo que si abandonas el proceso no queda ninguna clave; aparece en **Administration → Keys** marcada como **cli login**, donde puedes revocarla.

    <Accordion title="¿Sin navegador ni terminal a mano? Usa una clave (CI, contenedores, scripts de aprovisionamiento)">
      En el [panel de Failproof AI](https://app.befailproof.ai), ve a **Administration → Keys** y crea una clave con `events:add` y `policies:pull`. Si planeas usar [Jev a través de FailproofAI Cloud](/es/reference/jev-cloud), elige el preset **machine**, que también otorga `jev:evaluate`. Copia el secreto de un solo uso e introdúcelo en un shell de la máquina de destino — `read -s` lo solicita en un prompt que no lo muestra en pantalla:

      ```bash
      read -rs FAILPROOFAI_KEY && export FAILPROOFAI_KEY
      FAILPROOFAI_CLOUD_TOKEN="$FAILPROOFAI_KEY" failproofai config
      ```

      Pasar la clave por el entorno en lugar de `--token` evita que aparezca en `ps`, donde cualquier usuario de la máquina puede leer los argumentos de un comando. No evita que quede en el historial del shell — para eso es el `read -s`. En CI, inyéctala como un secreto enmascarado y mantén el trazado del shell (`set -x`) desactivado, o el trazado la imprimirá. En una ejecución interactiva también puedes elegir **Paste an API key** en **Connect to cloud**.
    </Accordion>

    Los transcritos de sesión se envían por defecto. Añade `--no-transcripts` para reportar la actividad de hooks y las decisiones de políticas sin el contenido de los transcritos.

    <Warning>
      No uses `failproofai config --connect <url>` aquí. Ese flag registra una máquina que **ya** está configurada y regresa de inmediato — sin daemon, sin hooks — por lo que la máquina aparecería en Cloud sin recopilar ni aplicar nada.
    </Warning>

    Si esta máquina ya tiene historial de agentes, previsualiza e importa los últimos siete días, luego espera a que la entrega finalice. Omite este paso en una máquina nueva.

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    Abre **Sessions** en Failproof AI y selecciona una sesión importada.
  </Step>
  <Step title="Conecta Failproof AI a un harness">
    El paso anterior ya conectó cada CLI de agente que detectó. Vuelve a ejecutarlo para un harness específico cuando lo necesites, o para agregar uno instalado posteriormente. Cada uno de los 12 es un valor válido para `--cli` — `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, `goose`.

    ```bash
    failproofai policies --install --cli claude --scope user     # una CLI de programación
    failproofai policies --install --cli hermes --scope user     # un gateway de Slack/Telegram
    ```

    El bloqueo de una llamada de herramienta antes de que se ejecute está verificado en los 12. Los gates de fin de turno están verificados en 8 — consulta la [capacidad de aplicación](/es/reference/harnesses#enforcement-capability) para la matriz por harness.
  </Step>
  <Step title="Elige qué aplicar">
    Conectar los hooks no activa ninguna política. La configuración no elige ninguna deliberadamente — esa decisión es tuya — así que añade un pack:

    ```bash
    failproofai policies add FailproofAI/policies
    ```

    El pack se descarga desde su release de GitHub, se verifica su checksum y se fija al tag exacto que resolvió. Incluye 39 políticas y activa las 10 que su manifiesto marca como seguras para habilitar de forma desatendida. Úsalas para ver las decisiones de políticas locales y probar la aplicación antes de que Failproof AI audite tus sesiones y escriba políticas para tus agentes.

    Lee cualquier pack antes de añadirlo con `failproofai policies show <owner>/<repo>`, y consulta los [packs de políticas](/es/policies/packs) para añadir solo una parte.

    Hasta que esto se ejecute, lo único que aplica políticas es `block-failproofai-commands` — el guard siempre activo que evita que un agente desactive Failproof AI. `failproofai policies` lista lo que está activo.
  </Step>
  <Step title="Audita el comportamiento">
    Sigue [Ejecuta tu primera verificación de fallos](/es/start/first-audit). Usa un objetivo concreto, como "encontrar sesiones donde el agente reintentó una herramienta fallida sin cambiar su enfoque."
  </Step>
  <Step title="Previene el fallo">
    Sigue [Previene tu primer fallo con una política](/es/start/first-policy). Comienza en modo observación, inspecciona las coincidencias y luego aplica la versión revisada.
  </Step>
</Steps>

<Check>
  Ejecuta `failproofai config --status`. Una configuración saludable reporta la conexión a cloud, el estado del daemon y si la aplicación de políticas está pausada.
</Check>

</Tabs>

## Configuración de Jev

Usa [Jev](/es/start/use-jev) para puntuar sesiones finalizadas contra una pregunta con respuestas conocidas, o para revisar llamadas de herramientas en contexto antes de que se ejecuten. La página **Use Jev** incluye ambas rutas de configuración.
