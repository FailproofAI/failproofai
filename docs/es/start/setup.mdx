Failproof AI puede ejecutarse completamente en una sola máquina o conectarse a Cloud para sesiones compartidas y gestión de políticas.

## Local, sin cuenta

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai
```

Esto instala el servicio, conecta los agentes compatibles, añade un paquete de políticas y abre el panel de control en `http://localhost:8020`.

Ejecuta `failproofai audit` para analizar el historial de agentes que ya se encuentre en la máquina.

## Conectar Failproof AI Cloud

Crea una clave de máquina en Cloud y luego ejecuta:

```bash
failproofai config --token <machine-key>
failproofai config --machine-label checkout-runner-01
failproofai policies add FailproofAI/policies
failproofai config --status
```

O exporta `FAILPROOFAI_CLOUD_TOKEN=<machine-key>` y ejecuta `failproofai config` sin argumentos adicionales. En máquinas compartidas y en entornos de CI se recomienda usar la variable de entorno para que la clave no quede registrada en el historial del shell ni en los listados de procesos.

Cloud utiliza una sola conexión para dos tareas distintas:

- Obtener las políticas asignadas a esta máquina.
- Enviar las decisiones de políticas y las transcripciones de sesiones.

Para enviar únicamente las decisiones, conéctate primero y luego establece `collector.sessions` en `false` dentro de `~/.failproofai/config.json`. No dependas de `--no-transcripts`: la ruta de configuración actual analiza el flag pero no lo aplica. Consulta [eventos y configuración](/es/reference/events-and-configuration#machine-configuration).

<Note>
  `--machine-label` renombra una máquina que ya está conectada. Ejecútalo después del comando de configuración, no como parte de la primera conexión.
</Note>

## Configuración desatendida

`failproofai config` no requiere ningún flag especial para el modo no interactivo. En CI o en un contenedor, aplica la configuración solicitada sin solicitar confirmación.

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

El acceso de administrador es necesario una sola vez para instalar el servicio en segundo plano. La configuración nunca abre un prompt interactivo de contraseña `sudo`: o bien se completa sin necesitarlo, o imprime los comandos que un administrador debe ejecutar.

## Compatibilidad de plataformas

La configuración es compatible con Linux y macOS. En otras plataformas, el proceso finaliza sin escribir hooks ni dejar un estado de configuración parcial.
