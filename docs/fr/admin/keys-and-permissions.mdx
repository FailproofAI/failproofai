Utilisez une clé distincte pour chaque personne, machine ou tâche d'automatisation. N'accordez que les permissions nécessaires.

## Créer et faire tourner une clé

Utilisez **Admin → Keys**, ou le Cloud CLI :

```bash
fp keys list
fp keys create "audit automation" --add audits:read
fp keys disable "audit automation"
```

Enregistrez le secret au moment de sa création ; il ne sera plus affiché ensuite. Pour faire tourner une clé, créez un remplaçant, mettez à jour le consommateur, puis désactivez l'ancienne clé.

## Clés machine

Une clé machine connecte le service local au Cloud :

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Une machine connectée peut nécessiter deux capacités :

- `policies:pull` pour recevoir les politiques gérées par le Cloud.
- `events:add` pour envoyer des décisions et des sessions.

Le statut les signale séparément, car l'une peut fonctionner sans l'autre.

## Permissions courantes

| Permission | Autorise |
| --- | --- |
| `events:add` | Envoyer des événements |
| `events:read` | Lire les événements et les erreurs |
| `evaluations:read` | Lire les sessions et les évaluations |
| `audits:read` / `audits:write` | Consulter ou gérer les audits |
| `policies:read` / `policies:write` | Consulter ou déployer des politiques |
| `policies:pull` | Récupérer les affectations de politiques machine |
| `keys:create` / `keys:disable` | Créer ou désactiver des clés |
| `orgs:admin` | Administration d'organisation au niveau de l'instance ; non assignable à une clé d'organisation |

Certaines commandes administratives `fp fleet` et `fp guardrails` nécessitent une session utilisateur connectée plutôt qu'une clé API. Leur texte d'aide l'indique avant d'effectuer une requête.

<Warning>
  Ne réutilisez jamais des identifiants d'ingestion tels que `AGENTEYE_KEY` ou `AGENTEYE_API_KEY` en tant que `FP_API_KEY`. Ils appartiennent à des systèmes et des permissions différents.
</Warning>
