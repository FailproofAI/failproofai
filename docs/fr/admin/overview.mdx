L'administration est la partie Cloud de Failproof AI. Les organisations, membres, clés API, paramètres d'organisation et la consommation mesurée nécessitent tous une connexion Cloud.

<Note>
  Failproof AI fonctionne également sans aucun compte. Une machine locale applique les politiques, conserve l'historique de session sur disque, sert le [tableau de bord local](/fr/reference/local-dashboard) sur `localhost:8020`, et exécute `failproofai audit` sans rien envoyer nulle part. Consultez la [configuration machine](/fr/reference/events-and-configuration#machine-configuration) pour les clés `collector` locales. Ignorez le reste de cette section si vous n'utilisez pas Cloud.
</Note>

## Où se trouvent les contrôles

<Tabs>
  <Tab title="Tableau de bord">
    Le groupe **admin** de la barre latérale Cloud regroupe l'**éditeur de politiques**, l'**application**, l'**utilisation**, les **clés**, les **utilisateurs** et les **paramètres**.

    ![Le groupe admin de la barre latérale Cloud avec l'éditeur de politiques, l'application, l'utilisation, les clés, les utilisateurs et les paramètres.](/images/dashboard/admin-navigation.png)
  </Tab>
  <Tab title="CLI">
    Installez le CLI Cloud en tant qu'outil isolé, puis connectez-vous :

    ```bash
    uv tool install fp-cloud-cli
    fp login
    fp whoami
    fp usage
    ```

    Placez les options globales avant la commande, par exemple `fp --org reliability-team --json usage`.
  </Tab>
</Tabs>

## Utilisateur connecté ou clé API

`fp` fonctionne selon l'un des deux modes d'authentification, et ce choix détermine quelles commandes sont disponibles. Une commande qu'une clé API ne peut pas exécuter est refusée avant l'ouverture d'une connexion, avec indication du motif, plutôt que de laisser une erreur 401 ou 403 parler à sa place.

| Commande | Clé API | Permission |
| --- | --- | --- |
| `fp whoami` | Oui | aucune |
| `fp usage` | Oui | `usage:read` |
| `fp keys list` / `show` | Oui | `keys:read` |
| `fp keys create` | Oui | `keys:create` |
| `fp keys disable` | Oui | `keys:disable` |
| `fp keys regenerate` | Oui | `keys:regenerate` |
| `fp keys update` | Non | `keys:update`, qu'aucune clé ne peut détenir |
| `fp users list` / `show` | Oui | `users:read` |
| `fp users create` | Oui | `users:create` |
| `fp users update` | Oui | `users:update` |
| `fp users disable` / `enable` | Oui | `users:delete` |
| `fp settings list` / `schema` | Oui | `settings:read` |
| `fp settings set` | Oui | `settings:write` |
| `fp orgs list` / `switch` / `current` / `perms` | Non | session connectée uniquement |

`fp usage` est la commande à confier à un script de reporting : elle s'exécute sans surveillance sous une clé et ne nécessite que `usage:read`.
