Les paramètres d'organisation s'appliquent à tous les membres de cette organisation Cloud. Modifiez-les depuis **Admin → settings** ou avec `fp settings`.

```bash
fp settings list
fp settings set <key> <value>
```

## Gestion des données

Par défaut, une machine connectée envoie les décisions de politique ainsi que les transcriptions complètes des sessions. Pour n'envoyer que les décisions, définissez `collector.sessions` sur `false` dans le fichier `~/.failproofai/config.json` de la machine après la connexion. L'indicateur de configuration `--no-transcripts` ne s'applique pas à ce paramètre.

Les identifiants sont nettoyés sur la machine avant l'envoi, mais cette suppression constitue un filet de sécurité, et non un substitut au contrôle d'accès.

L'utilisation locale seule ne nécessite aucun compte. L'historique des sessions et les audits restent sur la machine, sauf si les audits locaux planifiés envoient l'identité de la machine et un résumé limité après activation volontaire. La télémétrie CLI anonyme peut être désactivée avec `FAILPROOFAI_TELEMETRY_DISABLED=1`.

## Identifiants

Les jetons de machine sont stockés sous `~/.failproofai/` avec des permissions limitées au propriétaire. Ils ne sont pas intégrés dans la définition du service.

Utilisez des clés distinctes pour les personnes, l'automatisation et les machines. Accordez à chacune uniquement les permissions dont elle a besoin, effectuez une rotation lors d'un changement de responsable, et révoquez-la lorsque la machine ou le workflow est mis hors service.

## Liste de vérification

- N'accordez que les permissions strictement nécessaires.
- Définissez `collector.sessions` sur `false` là où le contenu complet n'est pas utile.
- Vérifiez qui peut déployer des politiques d'application.
- Testez les politiques en mode observation avant leur mise en application.
- Gardez les libellés des machines clairs et les identifiants stables.
- Exécutez `failproofai config --status` après avoir modifié les paramètres de connexion.

Consultez [clés et permissions](/fr/admin/keys-and-permissions) pour le catalogue des permissions.
