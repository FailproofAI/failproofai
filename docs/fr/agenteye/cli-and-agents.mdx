Votre déploiement complet de Failproof AI Observability, accessible en une seule commande. Vérifiez la production, générez une clé API ou acquittez un incident sans quitter votre terminal, puis scriptez tout cela dans votre CI, ou laissez un agent de codage le faire pour vous en langage naturel.

```bash
pipx install agenteye
agenteye login --email you@example.com      # a 6-digit code lands in your inbox
agenteye --json sessions --since 24h         # every agent run from the last day, newest first
```

*Le CLI `agenteye` communique avec votre tableau de bord. C'est un outil distinct du collecteur, qui envoie les événements au serveur.*

## Votre déploiement complet, en une seule commande

Fini de jongler entre les onglets pour répondre à une simple question. Le CLI `agenteye` lit vos données et administre votre organisation depuis un unique binaire — une vérification qui nécessitait auparavant de naviguer dans le tableau de bord devient une seule ligne que vous pouvez relancer, mettre en alias ou coller dans un runbook. Vous disposez de quatre surfaces :

- **Lire vos données :** `sessions`, `events`, `evals` et `errors`, filtrés par date, agent et environnement.
- **Gérer votre organisation :** `keys`, `users`, `settings`, `alerts` et `incidents`.
- **Exécuter des analyses :** SQL sauvegardé et un exécuteur `query` ad hoc sur vos données d'événements.
- **Interroger l'assistant :** `agent ask` accède au même analyste en lecture seule avec lequel vous discutez dans le tableau de bord.

Installez-le une fois avec `pipx`, connectez-vous avec un code à 6 chiffres reçu par e-mail, et vous êtes prêt. La session dure environ une journée ; relancez `agenteye login` à l'expiration. Utilisez-le pour vérifier ponctuellement la production, provisionner une clé ou trier un incident actif, tout cela sans ouvrir un navigateur :

```bash
agenteye errors --since 24h --aggregate      # what is breaking, grouped by error type
agenteye incidents list --state firing       # what is on fire right now
agenteye keys create ci --add events:add     # a key that can only push events, secret shown once
```

Une habitude à retenir : les options globales comme `--json` se placent avant la commande. `agenteye --json sessions` est correct ; `agenteye sessions --json` ne l'est pas.

## Scriptez-le, intégrez-le dans votre CI

Chaque commande accepte `--json`, et cela change tout. Le JSON propre va sur stdout tandis que les statuts et avertissements lisibles par l'humain vont sur stderr — ainsi, une capture avec `--json` se passe directement dans `jq` sans ligne parasite à supprimer. C'est ce qui rend le CLI aussi efficace pour vous à l'invite de commande que pour un agent de codage qui analyse la sortie :

```bash
agenteye --json sessions --since 24h --status error | jq -r '.sessions[].session_id'
```

Il est conçu pour fonctionner sans surveillance. Les invites de confirmation sont ignorées automatiquement lorsqu'aucun terminal n'est attaché, de sorte que rien ne bloque dans un pipeline. Chaque commande retourne un code de sortie significatif : `0` succès, `4` non connecté, `5` permission manquante (le message la nomme explicitement, par exemple `alerts:write`), `3` tableau de bord inaccessible. Un script peut bifurquer sur un `4` pour se réauthentifier, ou sur un `5` pour vous indiquer exactement ce qu'il faut demander à un administrateur, plutôt que d'échouer silencieusement.

## Laissez un agent de codage le piloter en langage naturel

Mieux encore, vous ne devriez pas avoir à mémoriser ces options du tout. La **compétence CLI** est un petit dossier Agent Skill nommé `agenteye-cli` qui apprend à un agent de codage tel que Claude Code ou Codex à piloter le CLI à partir de requêtes en langage naturel. Demandez « est-ce que quelque chose est cassé aujourd'hui ? » et l'agent choisit la commande, l'exécute à votre place et répond en prose.

Pour Claude Code, déposez le dossier `agenteye-cli` dans `~/.claude/skills/` et il est automatiquement découvert. Failproof AI Observability fournit le dossier ; il n'y a rien de supplémentaire à installer, car il ne fait que piloter le CLI que vous avez déjà installé. Connectez-vous d'abord vous-même : la compétence ne peut pas effectuer la connexion par code envoyé par e-mail à votre place.

Comme l'agent exécute le CLI en tant que vous, il peut tout faire que votre connexion autorise, lectures comme écritures : créer des clés, modifier des paramètres, résoudre des incidents. L'invite « êtes-vous sûr ? » du CLI ne se déclenche pas pour un agent ; la compétence est donc conçue pour énoncer la commande exacte et attendre votre accord avant toute modification. Vous êtes l'étape de confirmation.

```text
you    Why did session run-001 fail?

agent  Running: agenteye --json events --session-id run-001 --all
       The checkout-agent hit a TimeoutError on its third tool call.
```

Les lectures restent instantanées, et chaque écriture marque une pause pour vous :

```text
you    Give CI a key that can only push events.

agent  This creates an API key. I'll run:
         agenteye keys create ci --add events:add
       OK to proceed?

you    yes

agent  Done. Key "ci" created with events:add only. The secret is shown once, so store it now.
```
