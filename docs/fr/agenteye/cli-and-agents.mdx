Tout votre déploiement Failproof AI Observability, à portée d'une seule commande. Vérifiez la production, générez une clé API ou acquittez un incident sans quitter votre terminal, puis scriptez n'importe quelle opération dans votre CI, ou laissez un agent de code le faire pour vous en langage naturel.

```bash
pipx install agenteye
agenteye login --email you@example.com      # un code à 6 chiffres arrive dans votre boîte mail
agenteye --json sessions --since 24h         # toutes les exécutions d'agent des dernières 24 h, les plus récentes en premier
```

*Le CLI `agenteye` communique avec votre tableau de bord. C'est un outil distinct du collecteur, qui envoie les événements au serveur.*

## Tout votre déploiement, à portée d'une seule commande

Fini les allers-retours entre onglets pour répondre à une question rapide. Le CLI `agenteye` lit vos données et administre votre organisation depuis un seul binaire, de sorte qu'une vérification qui nécessitait auparavant de naviguer dans le tableau de bord devient une ligne que vous pouvez relancer, aliaser ou coller dans un runbook. Quatre surfaces sont disponibles :

- **Lire vos données :** `sessions`, `events`, `evals` et `errors`, filtrés par période, agent et environnement.
- **Gérer votre organisation :** `keys`, `users`, `settings`, `alerts` et `incidents`.
- **Lancer des analyses :** SQL sauvegardé et un runner `query` ad hoc sur vos données d'événements.
- **Interroger l'assistant :** `agent ask` accède au même analyste en lecture seule que vous utilisez dans le tableau de bord.

Installez-le une fois avec `pipx`, connectez-vous avec un code à 6 chiffres reçu par e-mail, et vous êtes prêt. La session dure environ une journée ; relancez `agenteye login` à son expiration. Utilisez-le pour vérifier ponctuellement la production, provisionner une clé ou trier un incident en cours, le tout sans ouvrir un navigateur :

```bash
agenteye errors --since 24h --aggregate      # ce qui plante, regroupé par type d'erreur
agenteye incidents list --state firing       # ce qui est en feu en ce moment
agenteye keys create ci --add events:add     # une clé qui ne peut qu'envoyer des événements, secret affiché une seule fois
```

Un point important à retenir : les options globales comme `--json` se placent avant la commande. `agenteye --json sessions` est correct ; `agenteye sessions --json` ne l'est pas.

## Scriptez-le, intégrez-le dans votre CI

Chaque commande accepte `--json`, ce qui change tout. Le JSON brut est envoyé vers stdout tandis que les messages d'état et avertissements lisibles par l'humain vont vers stderr, ainsi une capture `--json` se branche directement dans `jq` sans ligne parasite à supprimer. C'est ce qui rend le CLI aussi efficace pour vous à l'invite de commande que pour un agent de code analysant la sortie :

```bash
agenteye --json sessions --since 24h --status error | jq -r '.sessions[].session_id'
```

Il est conçu pour fonctionner de manière non supervisée. Les invites de confirmation sont ignorées automatiquement lorsqu'aucun terminal n'est attaché, rien ne se bloque donc dans un pipeline, et chaque commande retourne un code de sortie significatif : `0` succès, `4` non connecté, `5` permission manquante (le message la nomme explicitement, par exemple `alerts:write`), `3` tableau de bord inaccessible. Un script peut se brancher sur un `4` pour se réauthentifier ou sur un `5` pour indiquer exactement ce qu'il faut demander à un administrateur, plutôt que d'échouer silencieusement.

## Laissez un agent de code le piloter en langage naturel

Mieux encore, vous ne devriez pas avoir à mémoriser tous ces flags. La **compétence CLI** est un petit dossier Agent Skill nommé `agenteye-cli` qui apprend à un agent de code comme Claude Code ou Codex à piloter le CLI à partir de requêtes en langage naturel. Demandez « est-ce que quelque chose est cassé aujourd'hui ? » et l'agent choisit la commande, l'exécute en votre nom et vous répond en prose.

Pour Claude Code, déposez le dossier `agenteye-cli` dans `~/.claude/skills/` et il est automatiquement découvert. Failproof AI Observability fournit le dossier ; il n'y a rien de supplémentaire à installer, car il pilote simplement le CLI que vous avez déjà installé. Connectez-vous vous-même au préalable : la compétence ne peut pas effectuer la connexion par code e-mail à votre place.

Comme l'agent exécute le CLI en votre nom, il peut tout faire selon les permissions de votre session, en lecture comme en écriture : créer des clés, modifier des paramètres, résoudre des incidents. L'invite de confirmation du CLI ne se déclenche pas pour un agent, aussi la compétence est-elle conçue pour indiquer la commande exacte et attendre votre accord avant toute modification. Vous êtes l'étape de confirmation.

```text
vous    Pourquoi la session run-001 a-t-elle échoué ?

agent   Exécution : agenteye --json events --session-id run-001 --all
        Le checkout-agent a rencontré une TimeoutError lors de son troisième appel d'outil.
```

Les lectures restent instantanées, et chaque écriture marque une pause pour vous :

```text
vous    Donne à CI une clé qui ne peut qu'envoyer des événements.

agent   Cela crée une clé API. Je vais exécuter :
          agenteye keys create ci --add events:add
        OK pour continuer ?

vous    oui

agent   Fait. La clé "ci" a été créée avec events:add uniquement. Le secret n'est affiché qu'une seule fois, enregistrez-le maintenant.
```
