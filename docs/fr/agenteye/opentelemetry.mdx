OpenTelemetry vous permet d'envoyer des traces d'agents, des journaux et des métriques vers FailproofAI Cloud en utilisant le protocole standard OTLP/HTTP. Cette fonctionnalité est optionnelle. Vos intégrations FailproofAI existantes continuent de fonctionner sans l'activer.

## Activer l'ingestion pour votre organisation

Un administrateur de l'organisation ouvre **Paramètres → OpenTelemetry** et active l'ingestion. Utilisez une clé API Cloud avec la permission `events:add`, la même permission utilisée pour les rapports d'agents.

Si l'ingestion est désactivée, Cloud refuse les exports OTLP ; ainsi, `failproofai otel enable` n'a aucun effet et vos agents continuent d'envoyer les sessions de la manière habituelle. Exécutez `failproofai otel status` pour vérifier le paramètre au niveau de l'organisation, et demandez à un administrateur de l'activer.

## Connecter un agent de codage

Connectez votre machine avec `failproofai config`, puis choisissez un agent :

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

La commande de configuration prend en charge Claude Code, Codex et Copilot, et choisit automatiquement entre Cloud et un relais authentifié local selon le cas. Copilot utilise le relais local automatiquement. Démarrez votre daemon FailproofAI configuré avant d'utiliser le relais.

Si FailproofAI envoie déjà les transcriptions de sessions d'un agent, la configuration vous demande si vous souhaitez basculer cet agent vers OTEL. La réponse par défaut est Non. En acceptant, vous arrêtez les envois de transcriptions pour cet agent ; cela ne modifie pas l'application des politiques ni les rapports des autres agents.

## Connecter une application

Utilisez l'instrumentation OpenTelemetry de votre application avec ces variables d'environnement :

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Le point de terminaison est la base OTLP de Cloud, `https://app.befailproof.ai/otel` ; votre exportateur y ajoute automatiquement `/v1/traces`, `/v1/logs` ou `/v1/metrics`. Les variables par signal telles que `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` sont utilisées telles quelles, elles doivent donc inclure le chemin complet, par exemple `https://app.befailproof.ai/otel/v1/logs`.

Remplacez `<key>` par votre clé API. Gardez ce secret hors de l'historique du shell, des enregistrements d'écran et des configurations versionnées. Pour une machine déjà configurée, `failproofai otel env --service my-agent` affiche le bloc avec la clé existante. Sa sortie contient un identifiant confidentiel.

Cloud accepte les exports OTLP/HTTP pour les traces, les journaux et les métriques, en protobuf ou JSON, y compris les requêtes compressées en gzip. Il n'accepte pas OTLP/gRPC.

Les métriques sont acquittées pour la compatibilité avec les exportateurs, mais ne sont ni stockées ni affichées. Les traces d'agents et les journaux d'agents de codage pris en charge deviennent des sessions ; les champs que l'agent n'exporte pas restent absents.

## Capturer le texte des prompts

<Warning>
La capture de texte peut inclure des prompts, des arguments d'outils et d'autres contenus sensibles. `failproofai otel enable` l'active. Ajoutez `--no-content` pour désactiver la capture des prompts et des détails d'outils.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Pour un agent configuré manuellement, utilisez ses propres contrôles de capture de contenu :

<Tabs>
  <Tab title="Claude Code">
    Ajoutez ces variables à l'environnement de votre agent, en complément du bloc applicatif ci-dessus :

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Définissez les deux variables de contenu à `0` pour éviter la capture des prompts et des détails d'outils.
  </Tab>
  <Tab title="Codex">
    Dans la configuration utilisateur de Codex, utilisez ses paramètres OTEL :

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Le contenu des conversations Codex se trouve dans les journaux ; laissez les traces d'exécution internes et les métriques désactivées. Codex utilise le point de terminaison complet que vous fournissez. Définissez `log_user_prompt` à `false` pour exclure les prompts ; la commande de configuration préserve un `false` explicite.
  </Tab>
  <Tab title="Gemini CLI">
    Utilisez les paramètres de télémétrie de Gemini avec le relais local :

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI n'est pas pris en charge par `failproofai otel enable`. Configurez-le manuellement avec un collecteur authentifié de votre choix. Définissez `logPrompts` à `false` pour désactiver la capture des prompts.
  </Tab>
  <Tab title="Copilot in VS Code">
    Utilisez ces paramètres utilisateur VS Code :

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Exécutez `failproofai otel enable copilot` pour activer le relais authentifié. Définissez `captureContent` à `false` pour omettre le contenu.
  </Tab>
</Tabs>

## Vérifier ou annuler la configuration

```bash
failproofai otel status
failproofai otel disable all
```

La commande status distingue les paramètres gérés par FailproofAI de ceux que vous avez configurés ailleurs. La commande disable restaure les paramètres gérés précédents ainsi que le choix précédent de l'agent concernant l'envoi de transcriptions.
