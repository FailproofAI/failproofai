Utilisez les audits récurrents pour les modes de défaillance susceptibles de réapparaître à mesure que les agents, les prompts, les outils et les modèles évoluent.

## Modifier le planning

<Tabs>
  <Tab title="Dashboard">
    1. Accédez à **Analyze → Audits** et ouvrez l'audit.
    2. Ouvrez ses paramètres et modifiez l'état d'activation, l'intervalle, l'ancre UTC, le mode de fenêtre ou le lookback.
    3. Enregistrez l'audit et vérifiez la prochaine heure d'exécution sur la carte d'audit.
    4. Utilisez **run now** une fois après un changement majeur de périmètre ou de contexte.

    ![L'éditeur d'audit affichant la cadence, la fenêtre de balayage, le périmètre, les paramètres d'analyse, le contexte et les canaux de notification.](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    Consultez la [référence `fp audits`](/fr/reference/cloud-cli#audits) pour les limites de planification, le comportement des fenêtres et toutes les commandes d'audit.
  </Tab>
</Tabs>

Choisissez la cadence en fonction de la gravité et du coût du risque :

| Modèle de risque | Cadence initiale |
| --- | --- |
| Action de production à fort impact | Quotidienne |
| Régression de workflow ou de modèle | Hebdomadaire |
| Révision de gouvernance ou d'accès | Mensuelle |
| Investigation ponctuelle de version | Exécution unique |

Alignez la fenêtre de lookback sur la cadence afin que les exécutions ne laissent ni lacunes ni n'examinent de manière répétée une population inutilement large. Après avoir modifié l'objectif ou le contexte d'un audit, exécutez-le manuellement une fois avant de vous fier au prochain résultat planifié.

<Note>
  Les audits planifiés locaux sont configurés sur la machine et analysent l'historique local des agents. Les plannings d'audits Cloud s'appliquent aux sessions Cloud. Traitez leurs résultats et leur propriété séparément.
</Note>
