Effectuez un audit local pour une revue immédiate et privée avant de connecter une machine à Failproof AI Cloud. Il analyse les historiques d'agents déjà stockés sur votre machine, rejoue l'activité des outils via les politiques intégrées, et ouvre un tableau de bord de résultats en local.

## Lancer un audit interactif

<Tabs>
  <Tab title="Tableau de bord">
    L'audit local démarre depuis le CLI car il doit découvrir les historiques sur la machine en cours. Exécutez `failproofai audit` ; après l'analyse, Failproof AI lance le tableau de bord intégré et ouvre **http://localhost:8020/audit**.

    Dans la vue d'audit, examinez le nombre de sessions, d'appels d'outils, de projets et de correspondances de politiques. Commencez par les résultats les plus fréquents, puis inspectez le projet concerné et l'historique de l'agent avant d'activer l'application des politiques.

    <Info>Le tableau de bord d'audit local est distinct de **Analyser → Audits** dans Failproof AI Cloud. Les audits locaux restent sur la machine et ne nécessitent ni compte ni connexion réseau.</Info>
  </Tab>
  <Tab title="CLI">
    ```bash
    npm install -g failproofai
    failproofai audit
    ```

    La commande effectue une analyse complète de chaque historique pris en charge qu'elle trouve. La commande actuelle n'accepte pas de filtres tels que `--since`, `--cli`, `--project`, `--port` ou `--no-open`.

    Laissez le processus s'exécuter pendant l'utilisation du tableau de bord local. Appuyez sur <kbd>Ctrl</kbd>+<kbd>C</kbd> lorsque vous avez terminé.
  </Tab>
</Tabs>

Les adaptateurs d'audit actuels peuvent lire les historiques de Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Hermes, OpenClaw, Factory, Devin, Antigravity et Goose. Seuls les historiques disponibles localement sont analysés.

## Planifier des audits locaux récurrents

<Tabs>
  <Tab title="Tableau de bord">
    Ouvrez **Paramètres** dans le tableau de bord local, activez les audits planifiés, choisissez l'intervalle et renseignez l'adresse e-mail qui doit recevoir les résultats. Le tableau de bord et le CLI mettent à jour la même configuration machine.
  </Tab>
  <Tab title="CLI">
    Activez un audit hebdomadaire et envoyez les résultats à l'adresse indiquée :

    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    L'intervalle accepte des valeurs de 1 à 90 jours et vaut 7 par défaut si omis. La première configuration vous connecte si nécessaire ; `--email` fournit l'adresse du rapport sans demande de confirmation.

    Arrêtez la planification sans supprimer l'historique d'audit local :

    ```bash
    failproofai audit --no-schedule
    ```
  </Tab>
</Tabs>

Le démon exécute les analyses planifiées en arrière-plan, actualise le résultat mis en cache utilisé par le tableau de bord local, et envoie le rapport configuré par e-mail. Utilisez `failproofai audit` pour lancer immédiatement une analyse interactive.

## Passer des preuves locales aux opérations Cloud

Un audit local constitue une base de référence rapide. Connectez la machine à Failproof AI Cloud lorsque vous avez besoin de traces partagées, d'audits de population récurrents, de résultats et de problèmes, d'alertes, de déploiement de politiques à l'échelle de l'organisation ou d'une vue de la santé du parc.

<Warning>
