Failproof AI aide les équipes à comprendre ce que les agents ont fait, à identifier là où ils ont échoué, et à déployer des garde-fous avant que le même comportement ne se reproduise.

Un **harness** est l'environnement dans lequel votre agent s'exécute réellement. Failproof AI s'intègre à 12 d'entre eux — des CLI de codage comme Claude Code et Codex, des passerelles de chat comme Hermes, des assistants auto-hébergés comme OpenClaw — et les mêmes événements, les mêmes politiques et le même historique de session s'appliquent à chacun. Les agents sans harness remontent leurs données via le [SDK Python](/fr/reference/python-sdk), qui les trace et les audite ; l'application d'une politique dans ce cas nécessite un hook dans votre propre environnement d'exécution.

> **Session → Audit → Constat → Ticket → Politique**<br />
> Tracez ce qui s'est passé, identifiez l'échec, gérez la réponse, puis évitez que le même comportement ne se reproduise lors des prochaines exécutions.

## Par où commencer

Si vous déployez votre premier agent instrumenté, commencez par le [démarrage rapide](/fr/start/quickstart). Si des données arrivent déjà, ouvrez [Sessions](/fr/sessions/overview) et inspectez une exécution réelle avant de configurer des audits ou des politiques.
