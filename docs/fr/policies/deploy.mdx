Déployez une politique révisée sur une machine à la fois. Commencez en mode observation.

## Déploiement depuis la CLI

```bash
fp policies test ./rule.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish no-force-push ./rule.mjs
fp fleet deploy <machine> --add no-force-push:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add no-force-push:enforce
```

Le mode observation évalue la politique réelle et enregistre les décisions autres que allow, mais ne bloque pas l'agent.

<Warning>
  Un `--add no-force-push` sans suffixe applique l'enforcement immédiatement. Ajoutez `:observe` pour un déploiement en mode shadow.
</Warning>

Si l'application pose des problèmes :

```bash
fp fleet history <machine>
fp fleet rollback <machine> <generation>
```

## Déploiement depuis le tableau de bord

1. Allez dans **Admin → enforcement**.
2. Ouvrez la machine cible.
3. Ajoutez la version de la politique avec l'effet **observe**.
4. Appliquez le déploiement.
5. Consultez les résultats sous **Observe → policy**.
6. Faites passer la même version en **enforce** lorsque les correspondances sont correctes.

![L'éditeur de déploiement de machine avec les versions de politiques, les effets enforce et observe, et l'action d'application du déploiement.](/images/dashboard/enforcement-editor.png)

## Remplacer ou pré-configurer un ensemble

- `--remove <id>` supprime une politique.
- `--set <ref>...` remplace l'ensemble complet de politiques.
- `--create` prépare un déploiement avant qu'une machine se connecte pour la première fois.
- `fp fleet diff <machine>` compare l'état prévu et l'état appliqué.

<Note>
  Sans Cloud, publiez un pack avec `failproofai publish --effect observe` et inspectez les décisions dans le tableau de bord local.
</Note>

Les machines ont besoin de `policies:pull` pour recevoir les déploiements et de `events:add` pour signaler les décisions.
