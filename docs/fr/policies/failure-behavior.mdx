description: "Comprendre pourquoi Failproof AI refuse les actions lorsque l'évaluation ne peut pas s'exécuter."

---

Après configuration, le service local `failproofaid` est le seul évaluateur. S'il ne peut pas répondre, les actions protégées sont refusées plutôt que silencieusement autorisées.

## Diagnostiquer un blocage à l'échelle de la machine

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

Exécutez `failproofai config` pour réparer le service ou installer la version correspondante.

Deux types d'échecs peuvent se ressembler :

| Échec | Signification |
| --- | --- |
| Service inaccessible | Le socket n'a pas d'évaluateur fonctionnel derrière lui |
| Incompatibilité de version | Le CLI et le service ne s'accordent pas sur le protocole |

Les deux entraînent un refus, mais le statut les signale séparément.

## Un pack ne se charge pas

Un pack sélectionné qui est manquant, modifié ou invalide refuse les événements couverts par ses politiques sélectionnées. Cela empêche un pack défectueux de disparaître pendant que la machine semble protégée.

`failproofai policies` indique le nom du pack et l'erreur de chargement.

```bash
failproofai policies
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

Des métadonnées illisibles élargissent le refus de sécurité au lieu de le restreindre à partir de données auxquelles on ne pouvait pas faire confiance.

## Ce qui reste disponible

Le tableau de bord local et les commandes de statut continuent de fonctionner pendant que l'évaluation des politiques est en échec. Utilisez-les pour identifier le service, le pack ou la version qui nécessite une réparation.

<Warning>
  Ne contournez pas une décision de fermeture en cas d'échec en supprimant les fichiers du service ou du pack. Réparez le service, réinstallez le pack, ou supprimez l'assignation via le CLI afin que la machine revienne à un état connu.
</Warning>
