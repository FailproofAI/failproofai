La couverture de flotte répond à la question : une politique existe-t-elle là où le risque existe ? Suivez les machines par identifiant stable et libellé lisible, puis comparez leur état de déploiement assigné et rapporté.

## Vérifier la couverture

<Tabs>
  <Tab title="Tableau de bord">
    1. Allez dans **Admin → enforcement** et examinez les totaux en mode application et observation.
    2. Recherchez une machine par identifiant ou libellé, ou filtrez pour afficher les machines sans politique.
    3. Développez une ligne pour comparer les politiques assignées, le déploiement rapporté, le dernier check-in et l'historique.
    4. Actualisez après l'intervalle d'interrogation de la machine lorsqu'un déploiement appliqué reste en attente.

    ![La flotte Enforcement affichant la couverture des politiques, l'état de déploiement des machines, et les assignations en observation et en application.](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    Utilisez `fp events --agent-id <agent-id> --since 24h` pour confirmer que l'activité de l'agent de la machine atteint bien le Cloud.
  </Tab>
</Tabs>

Utilisez les vues de couverture pour identifier :

- Les machines qui n'ont jamais récupéré le dernier déploiement
- Les machines enrôlées qui ont cessé de rapporter leur activité
- Une politique assignée au mauvais environnement ou cohorte
- Une dérive de version après une mise à jour interrompue

Renommer une machine sans la reconnecter :

```bash
failproofai config --machine-label checkout-runner-03
```

Vérifier l'état local :

```bash
failproofai config --status
```

<Tip>
  Utilisez des libellés qui identifient la charge de travail et l'environnement. Les noms d'hôte seuls sont souvent insuffisants après un autoscaling ou un remplacement de machine.
</Tip>
