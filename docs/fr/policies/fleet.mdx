La couverture de la flotte compare ce que Cloud a assigné avec ce que chaque machine a dernièrement appliqué.

## Vérifier une machine

```bash
failproofai config --status
failproofai flush --wait --timeout 120
```

Depuis Cloud :

```bash
fp fleet list
fp fleet diff
fp fleet show <machine-id>
```

`fp fleet` nécessite une session authentifiée, et non une clé API.

| Commande | Effet |
| --- | --- |
| `fp fleet list` | Lister les machines et leur état de déploiement |
| `fp fleet show <machine>` | Afficher le jeu de politiques d'une machine |
| `fp fleet deploy <machine> --add <ref>` | Ajouter ou mettre à jour une politique |
| `fp fleet deploy <machine> --remove <id>` | Supprimer une politique |
| `fp fleet deploy <machine> --set <ref>...` | Remplacer l'intégralité du jeu |
| `fp fleet diff [machine]` | Comparer les versions prévues et appliquées |
| `fp fleet history <machine>` | Lister les générations de déploiement |
| `fp fleet rollback <machine> <generation>` | Restaurer une génération |
| `fp fleet rename <machine> "<label>"` | Modifier le label Cloud |

<Warning>
  `--set` remplace l'intégralité du jeu de politiques. Un simple `--add <id>` applique immédiatement une nouvelle politique. Utilisez `--add <id>:observe` pour un déploiement en mode fantôme.
</Warning>

## Observer, puis appliquer

```bash
fp fleet deploy ci-runner-01 --add prod-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add prod-guard:enforce
```

Le mode observation évalue la politique réelle et enregistre les décisions non-allow sans bloquer l'agent.

## Identité de la machine

L'identifiant de la machine est stable et l'identifie de façon unique. Le label est uniquement affiché et peut être modifié :

```bash
failproofai config --machine-label checkout-runner-03
fp fleet rename <machine-id> "Checkout runner 03"
```

Modifier le label ne reconnecte pas la machine et ne renouvelle pas ses clés.
