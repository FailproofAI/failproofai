Utilisez le scope pour décider qui reçoit une politique locale :

| Scope | S'applique à |
| --- | --- |
| `user` | Vos agents supportés sur cette machine |
| `project` | Les agents s'exécutant dans ce projet |
| `local` | Claude uniquement, dans les paramètres locaux du projet |
| `all` | Désinstallation uniquement |

```bash
failproofai policies add block-sudo --scope user
failproofai policies add block-rm-rf --scope project
```

Hermes et OpenClaw prennent en charge le scope `user` uniquement. La plupart des autres harnais supportent les scopes `user` et `project`. Claude prend également en charge le scope `local`. Voir [Harnais](/fr/reference/harnesses).

## Paramètres des politiques

Les paramètres des politiques se trouvent dans `policies-config.json` au scope correspondant. Utilisez la vue **Politiques → Configurer** du tableau de bord local lorsque c'est possible.

Un paramètre appartient à une politique et modifie la façon dont cette politique décide. Par exemple, une liste d'autorisation peut permettre à une politique de blocage d'accepter des commandes ou des chemins connus comme sûrs.

Les fichiers de politiques personnalisées peuvent être chargés automatiquement depuis `.failproofai/policies/`, ou explicitement :

```bash
failproofai policies -i -c ./guards.mjs --scope project
```

Supprimez les chemins explicites avec :

```bash
failproofai policies -u -c
```

## Fichiers

| Fichier | Rôle |
| --- | --- |
| `~/.failproofai/config.json` | Paramètres de la machine et du collecteur |
| `policies-config.json` | Politiques activées et paramètres pour un scope |
| `.failproofai/policies/*policies.mjs` | Politiques chargées par convention |
| `~/.failproofai/policies/packs/installed.json` | Packs installés et sélections |

Ne modifiez pas directement les artefacts des packs installés. Réinstallez ou publiez une version corrigée.
