Une politique surveille une action d'agent et retourne l'une des trois décisions suivantes :

- `allow` continue.
- `instruct` fournit des instructions à l'agent lorsque son environnement le prend en charge.
- `deny` bloque l'action.

Utilisez les politiques pour des comportements connus et répétitifs : suppression de fichiers protégés, exposition de secrets, push sur la mauvaise branche, ou modification d'une infrastructure de production.

## Ajouter des politiques sur cette machine

La configuration initiale ne sélectionne aucun pack de politiques. Ajoutez le pack Failproof AI après l'installation :

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai policies
```

Le package ne contient pas de pack intégré privilégié. Le nôtre s'installe de la même manière que celui de n'importe qui d'autre.

Les politiques peuvent également provenir d'un fichier local, d'un pack publié ou d'une assignation Cloud :

| Source | Comment l'ajouter |
| --- | --- |
| Fichier local | Placez `*policies.{js,mjs,ts}` dans `.failproofai/policies/` |
| Chemin de fichier quelconque | `failproofai policies -i -c <path>` |
| Pack publié | `failproofai policies add <owner>/<repo>` |
| Cloud | Assignez-le depuis le tableau de bord ou avec `fp fleet deploy` |

`block-failproofai-commands` s'exécute toujours et ne peut pas être désactivé. Il empêche un agent de désactiver sa propre application des règles.

## Observer avant d'appliquer

Le mode observation exécute la politique réelle et enregistre ce qu'elle aurait fait, sans bloquer l'agent.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

<Warning>
  Un simple `fp fleet deploy <machine> --add <id>` applique la politique immédiatement. Ajoutez `:observe` pour un déploiement en mode miroir.
</Warning>

Une politique qui expire en mode observation enregistre un allow, car c'est ce qui se passerait lors de l'application. Seules les décisions observées différentes de allow sont enregistrées.

Pour un pack utilisé sans Cloud, publiez-le avec `failproofai publish --effect observe`.
