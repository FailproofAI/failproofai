Créez une politique fonctionnelle, testez-la localement, puis publiez-la sous forme de pack.

## Créer et tester

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

`--init` génère une politique qui bloque déjà `git push --force`. Modifiez-la, demandez à votre agent d'essayer l'action bloquée, puis consultez **Policies → Activity** dans le tableau de bord local.

Une politique de pack peut inclure :

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-refunds",
  description: "Refunds above the limit need a human",
  category: "Billing",
  defaultEnabled: true,
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) => {
    // return allow(), instruct(), or deny()
  },
});
```

`defaultEnabled` vaut `false` par défaut.

## Publier

Commitez vos fichiers, puis exécutez :

```bash
failproofai publish
```

La commande publish localise le fichier de politique, le valide avec le même chargeur utilisé lors de l'installation, et téléverse les ressources du pack vers une release GitHub. Elle utilise `GITHUB_TOKEN`, `GH_TOKEN` ou `gh auth login`.

Le dépôt doit être public car l'installation utilise HTTPS anonyme.

La version par défaut est le SHA à 12 caractères du commit courant. La commande publish refuse un arbre de travail non propre ou un répertoire hors d'un dépôt Git, sauf si vous fournissez `--version`. Un tag sur `HEAD` prend la priorité sur le SHA.

Les utilisateurs l'installent avec :

```bash
failproofai policies add owner/repo
```

## Publier en mode observation

```bash
failproofai publish --effect observe
```

Le mode observation évalue la politique réelle et enregistre les décisions autres que allow, mais laisse l'agent continuer. Un timeout est enregistré comme un allow.

Publiez à nouveau avec `--effect enforce` lorsque les correspondances observées sont correctes.

## Options utiles

| Option | Effet |
| --- | --- |
| `--init [file]` | Génère une politique de départ |
| `--repo <owner>/<repo>` | Choisit ou crée le dépôt |
| `--version <version>` | Remplace la version basée sur le commit |
| `--effect enforce|observe` | Détermine si le pack bloque les actions |
| `--dry-run` | Construit et valide sans publier |
| `--allow-private` | Publie en privé, en sachant que `policies add` ne pourra pas l'installer |

```bash
failproofai publish --dry-run
failproofai publish ./guards.mjs --repo me/guards --version 2.0.0
```

<Note>
  Ajoutez le topic GitHub `failproofai-policies` après la publication afin que le [Policy Hub](https://befailproof.ai/policy-hub/) puisse indexer le pack. L'interface CLI ne le définit pas automatiquement.
</Note>

<Warning>
  Renommer une politique est un changement cassant pour les sélections existantes. Gardez des noms stables d'une release à l'autre.
</Warning>
