Utilisez `fp` pour inspecter la télémétrie Cloud, gérer l'application gérée par le cloud (politiques, déploiements de flotte, décisions de garde-fous) ainsi que les audits, résultats, problèmes, alertes, clés, utilisateurs, requêtes et paramètres. Utilisez [`failproofai`](/fr/reference/failproof-cli) pour les hooks locaux, les politiques, la capture et l'inscription des machines.

Installez le Cloud CLI publié comme outil isolé. Il nécessite Python 3.10 ou une version plus récente.

```bash
uv tool install fp-cloud-cli
fp version
```

La distribution est `fp-cloud-cli` et la commande installée est `fp` — elles diffèrent car `fp` était déjà pris sur PyPI.

## Connexion

`fp login` vous envoie un code à six chiffres par e-mail et sauvegarde la session. Pour un tableau de bord avec un certificat auto-signé, ajoutez `--insecure` au moment de la connexion.

```bash
fp login
fp whoami
```

## Syntaxe

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Les options globales doivent précéder la commande :

```bash
fp --json sessions --since 24h
```

Exécutez `fp COMMAND --help` ou `fp COMMAND SUBCOMMAND --help` pour l'aide dans le terminal.

### Événements

```text
fp events [OPTIONS]
```

Liste les événements d'agent individuels. Le flux léger par défaut exclut les charges utiles brutes ; utilisez `--full` uniquement pour une investigation délimitée.

| Option | Description |
| --- | --- |
| `--limit`, `-n <n>` | Nombre maximum de lignes. Par défaut : `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, ou `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Plage UTC ISO 8601 ; remplace `--since`. |
| `--env <value>` | Filtre d'environnement ; répétable ou séparé par des virgules. |
| `--event-type <value>` | Filtre par type d'événement ; répétable ou séparé par des virgules. |
| `--agent-id <value>` | Filtre par agent ; répétable ou séparé par des virgules. |
| `--session-id <value>` | Filtre par session ; répétable ou séparé par des virgules. |
| `--search <text>` | Recherche dans le texte de la charge utile ; répétable, avec correspondance sur n'importe quel terme. |
| `--order asc\|desc` | Ordre chronologique. Par défaut : les plus récents en premier. |
| `--all` | Pagination automatique jusqu'à `--limit`. |
| `--cursor <token>` | Reprendre depuis un curseur opaque. |
| `--page-size <n>` | Lignes par requête avec `--all` ; maximum `200`. |
| `--full` | Inclure les charges utiles brutes via l'endpoint d'événement plus lourd. |
| `--fields <csv>` | Retourner uniquement les champs sélectionnés ; demander `payload` active le mode complet. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` pagine **jusqu'à `--limit`**, qui vaut **50** par défaut — ainsi `--all` seul s'arrête à 50 lignes. Lorsqu'il s'arrête tôt, la réponse contient un `next_cursor` pour reprendre ; `"next_cursor": null` signifie que le flux était vraiment épuisé.
</Note>

#### Options de création d'audit

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Option | Description |
| --- | --- |
| `--file <path>` | Baser la définition sur du JSON, ou utiliser `-` pour stdin. Les options explicites remplacent les valeurs du fichier. |
| `--description <text>` | Énoncer la question sur la défaillance ou l'objectif. |
| `--enabled` / `--disabled` | Démarrer la planification activée ou désactivée. Par défaut : activé. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Par défaut : `86400`. |
| `--schedule-anchor <timestamp>` | Phase UTC fixe en format ISO 8601. Par défaut : prochain 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continuer après la dernière fenêtre entièrement analysée ou inspecter répétitivement une fenêtre glissante. Par défaut : `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Par défaut : `604800`. |
| `--scope '<json>'` | Filtrer par `environments`, `agent_ids`, ou d'autres champs de portée supportés. |
| `--ignore-error-type <type>` | Exclure des types d'erreurs ; répétable ou séparé par des virgules. |
| `--llm` / `--no-llm` | Activer ou désactiver l'analyse agentique. Par défaut : activé. |
| `--top-k <n>` | Conserver `1`–`500` résultats. Par défaut : `50`. |
| `--sensitivity low\|medium\|high` | Définir la sensibilité des rapports. Par défaut : `medium`. |
| `--channels '<json>'` | Tableau de canaux de notification. |
| `--text <brief>` | Résumé en ligne, maximum 8 192 caractères. |
| `--text-file <path>` | Lire le résumé depuis un fichier ; mutuellement exclusif avec `--text`. |
| `--url <https-url>` | Ajouter une référence HTTPS publique ; répétable jusqu'à cinq fois. |

Incluez le contexte lors de la création lorsque la première exécution en a besoin. La création valide la définition et le contexte ensemble avant le début de l'exécution mise en file d'attente.

<Note>
  `fp audits run` est asynchrone. Interrogez `fp audits runs NAME` jusqu'à ce que la dernière exécution réussisse ou échoue avant de lire ses résultats.

#### Références de politiques

`--add` et `--set` prennent une référence de politique, pas un id nu :

| Forme | Signification |
| --- | --- |
| `id` | Version actuelle, effet actuel |
| `id@3` | Version 3, effet actuel |
| `id:observe` | Version actuelle, enregistrée mais non appliquée |
| `id@3:observe` | Version 3, enregistrée mais non appliquée |

L'effet est `enforce` ou `observe`. La résolution est : un effet explicite l'emporte ; sinon l'effet déjà déployé pour cette politique ; sinon `enforce`.

<Warning>
  Un `--add` nu **applique immédiatement**. `fp fleet deploy ci-runner-01 --add checkout-guard` commence à bloquer sur cette machine dès sa prochaine récupération. `:observe` est ce qui en fait un déploiement shadow :

  ```bash
  fp fleet deploy ci-runner-01 --add checkout-guard:observe   # enregistre uniquement
  fp fleet deploy ci-runner-01 --add checkout-guard           # applique maintenant
  ```

  Observe n'est pas désactivé. La politique est évaluée pour de vrai, avec le même délai d'attente de 10 secondes et la même gestion des erreurs qu'une politique appliquée, et chaque verdict non-allow est enregistré — seule l'application est suspendue. C'est ce qui rend la mesure digne d'être lue.
</Warning>

#### Deltas, remplacement et courses aux données

`--add` et `--remove` lisent l'ensemble actuel de la machine et appliquent un delta, rien de ce que vous n'avez pas nommé n'est perturbé. Un `--add` nu sur une politique que la machine exécute déjà conserve sa version épinglée plutôt que de la mettre à niveau silencieusement ; passez `id@version` pour la déplacer.

`--set` remplace tout et est le seul moyen d'abandonner des politiques que vous ne nommez pas. Il ne peut pas être combiné avec `--add` ou `--remove`. Ne passer aucun des trois est une erreur d'utilisation, pas une opération sans effet.

```bash
fp fleet deploy ci-runner-01 --add prod-guard@1:observe --remove old-rule
fp fleet deploy ci-runner-01 --set no-force-push --set no-secret-echo
```

L'écriture elle-même est un remplacement complet sur chaque chemin, car l'endpoint prend l'ensemble complet des politiques. Il n'y a pas de verrou côté serveur, donc le CLI enregistre la génération qu'il a lue et refuse si le résultat n'est pas exactement un de plus — cela signifie que quelqu'un d'autre a déployé entre-temps, et un remplacement ne fusionne pas. Relisez avec `fp fleet show`, puis redéployez.

`--create` déploie vers un id de machine qui ne s'est pas encore connecté, pour la pré-configuration. Sans lui, un id que le serveur ne connaît pas est refusé, car une faute de frappe créerait sinon une machine que personne ne possède portant des politiques que personne ne collecte.

### Garde-fous

Ce qu'a réellement fait l'application. **Session uniquement**, pour la même raison que ci-dessus.

| Commande | Objectif | Options |
| --- | --- | --- |
| `fp guardrails summary` | Couverture, totaux bloqués/évalués, une sparkline de refus, et la table par politique. | `--since` (`1h`, `6h`, `24h`, `7d`) ; `--machine` |
| `fp guardrails timeline` | Décisions regroupées sur la fenêtre, totalisées pour toutes les sources de politiques. | `--since` (`1h`, `6h`, `24h`, `7d`) ; `--machine` |

Une ligne `(no policy)` dans le résumé est normale plutôt qu'un manque : la plupart des évaluations sont des allow auxquels personne n'a objecté, et la ligne maintient le dénominateur visible à l'écran.

### Déployer une politique sans rien casser

Les trois groupes ci-dessus forment une séquence. Décidez en local, publiez, faites un shadow, mesurez, puis appliquez.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

| Étape | Pourquoi elle est là |
| --- | --- |
| `fp policies test` | Pas de serveur, pas d'authentification. Exécute le vrai fichier contre un contexte que vous décrivez et affiche allow, deny, ou instruct par politique enregistrée. `--expect` en fait une assertion CI. |
| `fp policies publish` | Crée une nouvelle version immuable ; ne modifie jamais une version existante. |
| `fp fleet deploy --add <id>:observe` | Le déploiement shadow. **`:observe` n'est pas optionnel ici** — un `--add` nu applique dès que la machine récupère. |
| `fp guardrails summary` | Sépare les correspondances non sûres du travail légitime que la politique aurait également bloqué. |
| `fp fleet deploy --add <id>:enforce` | Promotion, une fois que les verdicts enregistrés correspondent à ce que vous attendiez. |
| `fp fleet rollback <machine> <generation>` | Le chemin de retour si l'application tourne mal. |

L'équivalent sur une seule machine, sans Cloud, consiste à publier le pack avec `failproofai publish --effect observe` et à lire les verdicts enregistrés sur le [tableau de bord local](/fr/reference/local-dashboard).

## Options globales

| Option | Description |
| --- | --- |
| `--json` | Émettre du JSON lisible par machine. |
| `--base-url <url>` | Utiliser un tableau de bord auto-hébergé ou de développement. |
| `--org <slug>` | Sélectionner une organisation pour cette invocation. |
| `--token <token>` | Remplacer le jeton de session utilisateur sauvegardé. |
| `--api-key <key>` | Authentifier l'automatisation avec une clé API ; jamais sauvegardée. |
| `--timeout <seconds>` | Délai d'attente HTTP ; doit être positif. Par défaut : `30`. |
| `--quiet`, `-q` | Supprimer la sortie de statut sur stderr. |
| `--no-color` | Désactiver la sortie colorée. |
| `--insecure` / `--secure` | Désactiver ou restaurer la vérification des certificats TLS. |
| `--version` | Afficher la version déballée et quitter. |
| `--help`, `-h` | Afficher l'aide. |

`--api-key` est destiné à l'automatisation. La connexion, le changement d'organisation et les commandes d'assistant nécessitent une session utilisateur.

## Variables d'environnement

| Variable | Équivalent ou objectif |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | Déplacer le répertoire de configuration CLI (par défaut `~/.failproofai/fpcli`). |
| `FP_ANALYTICS_DISABLED` ou `DO_NOT_TRACK` | Désactiver les analyses CLI anonymes. |
| `NO_COLOR` | Désactiver la sortie colorée. |

Les options explicites remplacent les variables d'environnement, qui remplacent la configuration sauvegardée.

En mode clé API, l'organisation sauvegardée par un `fp login` humain est **ignorée**, pas seulement remplacée — seul un `--org` explicite ou `FP_ORG` est envoyé. Rien n'est hérité d'une connexion sauvegardée, alors passez `--org` chaque fois que la clé peut agir pour plus d'une organisation. L'omettre ne provoque pas d'erreur explicite : une clé à portée d'instance sans `--org` est résolue côté serveur vers l'organisation **par défaut** et répond avec les données de cette organisation, sans aucune erreur. Exécutez `fp whoami` en premier pour confirmer à quel tenant une clé parle réellement.

<Warning>
  Les variantes `AGENTEYE_*` de ces variables ne sont **pas lues par `fp`** et ne l'ont jamais été — le CLI déclare `FP_*` (`fp_cli/app.py`), et une variable inconnue n'est pas une erreur. Définir `AGENTEYE_DASHBOARD_URL` ne redirige pas le CLI ; c'est ignoré et la commande s'exécute silencieusement contre le tableau de bord sauvegardé.

  `AGENTEYE_HOME` et `AGENTEYE_ENVIRONMENT` existent encore, mais ils appartiennent au **collecteur et au SDK de télémétrie**, pas à ce CLI.
</Warning>

<Warning>
  Les commandes qui suppriment, révoquent, masquent, résolvent ou remplacent une configuration demandent confirmation par défaut. Utilisez `--yes` uniquement après avoir vérifié l'organisation active et la cible.
</Warning>
