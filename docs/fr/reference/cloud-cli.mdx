Utilisez `fp` pour inspecter la télémétrie Cloud, gérer l'application des règles gérées dans le cloud (politiques, déploiements de flotte, décisions de garde-fous), et administrer les audits, les constatations, les problèmes, les alertes, les clés, les utilisateurs, les requêtes et les paramètres. Utilisez [`failproofai`](/fr/reference/failproof-cli) pour les hooks locaux, les politiques, la capture et l'enrôlement des machines.

Vous pouvez également créer et déployer du code hébergé, des évaluateurs LLM-juge et Jev, gérer des tableaux de bord, inspecter le sentiment et utiliser l'assistant du tableau de bord depuis le terminal.

Installez le Cloud CLI publié en tant qu'outil isolé :

```bash
uv tool install fp-cloud-cli
fp version
```

## Connexion

```bash
fp login
fp whoami
```

## Syntaxe

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Les options globales doivent précéder la commande :

```bash
fp --json sessions --since 24h
```

Exécutez `fp COMMAND --help` ou `fp COMMAND SUBCOMMAND --help` pour obtenir l'aide dans le terminal.

## Commandes CLI

### Créer un évaluateur

`fp evaluators` crée des définitions ; `fp evals` lit les résultats. Une instance gérée activée est requise (`fp evaluators instances`). La création nécessite `evaluations:trigger` ; les simulations de session et le profilage de schéma nécessitent également `events:read`.

Le code est une expression Python restreinte. Enregistrez ceci sous `error_free.py` :

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

Juge LLM :

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Rubrique binaire et notée Jev :

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
La création active l'évaluateur. Le déploiement crée une nouvelle version immuable, puis désactive les versions activées antérieures. Un échec lors du suivi laisse la nouvelle version publiée : inspectez `evaluators list --all` avant de réessayer.
Les simulations de juge sont refusées par Cloud. Les simulations Jev consomment du budget de modèle.
Le remplissage rétroactif couvre les évaluateurs de code, juge et Jev et accepte au maximum 90 jours ; il ne met en file d'attente que les sessions qu'un évaluateur n'a pas encore notées. Les remplissages rétroactifs juge et Jev consomment du budget de modèle, donc exécutez d'abord `fp evaluators backfill --dry-run`.
La sortie lisible affiche les résultats de simulation par session avant création/déploiement.
Les aperçus échoués interrompent l'écriture sauf si vous passez explicitement `--force` après examen.
</Warning>

La rédaction par IA nécessite `fp login` et génère une spec acceptée par create/deploy :

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Examinez la clé, la source et la condition du brouillon avant de l'activer.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Commande | Options / comportement |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Source/enveloppe complète |
| `fp evaluators create` | `--key`, `--name`, `--version`, `--label` (répétable), `--condition EXPR\|@file`, une source, `--dry-run-on` (répétable), `--disabled`, `--force` explicite pour les aperçus échoués |
| `fp evaluators deploy KEY` | Mêmes indicateurs de source ; `--version`, `--backfill 7d` (tout type, 1–90 jours), `--force` ; les versions numériques s'incrémentent automatiquement ; KEY fournit un `eval_key` manquant dans le fichier spec |
| `fp evaluators draft "intent"` | Session ; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Indicateurs de source ou `--file`, `--session` répétable (maximum 10) ; aucun = compilation uniquement |
| `fp evaluators enable\|disable KEY[@VERSION]` | Bascule |
| `fp evaluators label KEY[@VERSION]` | `--add`, `--remove` répétables |
| `fp evaluators instances\|schema\|jobs` | Inspecter la flotte/schéma/tâches gérés |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run` ; code, juge et Jev |

Les indicateurs de code sont `--code FILE|-`, `--result-kind score|metric|assertion`, `--timeout S`. Les indicateurs de juge sont `--judge --criteria TEXT`, `--step` répétable et `--threshold`. Les indicateurs Jev sont `--jev noul --instructions --true --false` ou `--jev score --instructions` avec 3–5 valeurs `--level` distinctes, de la pire à la meilleure.
Juge/Jev nécessitent un score ; les seuils sont entre 0 et 1. Les étapes de juge binaires sont rejetées.

Les fichiers spec contiennent exactement `eval_key`, `display_name`, `eval_version`, `result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
L'`evaluator_source` juge/Jev est une chaîne d'enveloppe JSON. N'incluez pas les identifiants de ligne, l'état activé ou les métadonnées de raisonnement IA. `--file` et les indicateurs de spec discrets sont exclusifs ; deploy peut remplacer la version du fichier. Les fichiers de sortie ne sont jamais écrasés.

### Nouveaux contrôles du tableau de bord

Toutes les commandes acceptent le `--json` global. Les 404 de route inconnue quittent avec le code 6 et le message « not available on this FailproofAI Cloud yet ». Les 404 d'enregistrement manquant quittent également avec le code 6 mais indiquent que l'enregistrement n'a pas été trouvé. Les commandes réservées aux sessions refusent le mode clé avant HTTP (quittent avec le code 2).

Les commandes lisibles utilisent des résumés et des tableaux. Pour les exports JSON bruts, passez `--json` en global ou enregistrez avec `--out FILE` ; sinon, les exports de session et de requête JSON affichent une vue lisible. Les exports CSV restent en CSV brut pour le pipage.

| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | Créer `--name`, `--description`, `--file` définition ; update préserve les champs non mentionnés |

| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since` ; list `--limit` ; messages `--session-id` |
| `fp query compose "question"` | Session ; `--run` |
| `fp query export [ID]` | Ou `--sql` ; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Les problèmes peuvent `--create --title --summary` ou `--create --file` |

| `fp otel status\|enable\|disable` | Interrupteur d'ingestion de l'org Cloud, pas la capture locale |
| `fp slack status\|disconnect` | Session |

`fp agent ask` affiche le SQL des artefacts sous forme de tableaux/statistiques via `queries:run`.
Les approbations d'écriture affichent la modification proposée et invitent l'utilisateur sur un terminal interactif. Les scripts et `--json` refusent sauf si `--approve` est explicite. Les formes JSON existantes restent inchangées lorsqu'aucun artefact n'est renvoyé.

### Événements

```text
fp events [OPTIONS]
```

Liste les événements d'agent individuels. Le flux léger par défaut exclut les charges utiles brutes ; utilisez `--full` uniquement pour une investigation bornée.

| Option | Description |
| --- | --- |
| `--limit`, `-n <n>` | Nombre maximum de lignes total. Par défaut : `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` ou `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Plage UTC ISO 8601 ; remplace `--since`. |
| `--env <value>` | Filtre d'environnement ; répétable ou valeurs séparées par des virgules. |
| `--event-type <value>` | Filtre de type d'événement ; répétable ou valeurs séparées par des virgules. |
| `--agent-id <value>` | Filtre d'agent ; répétable ou valeurs séparées par des virgules. |
| `--session-id <value>` | Filtre de session ; répétable ou valeurs séparées par des virgules. |
| `--search <text>` | Recherche textuelle dans la charge utile ; répétable, avec correspondance sur n'importe quel terme. |
| `--order asc\|desc` | Ordre temporel. Par défaut : du plus récent au plus ancien. |
| `--all` | Pagination automatique jusqu'à `--limit`. |
| `--cursor <token>` | Reprendre depuis un curseur opaque. |
| `--page-size <n>` | Lignes par requête avec `--all` ; maximum `200`. |
| `--full` | Inclure les charges utiles brutes via l'endpoint d'événement plus lourd. |
| `--fields <csv>` | Retourner uniquement les champs sélectionnés ; demander `payload` active le mode complet. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` pagine **jusqu'à `--limit`**, qui vaut par défaut **50** — donc `--all` seul s'arrête à 50 lignes. Lorsqu'il s'arrête prématurément, la réponse contient un `next_cursor` pour reprendre ; `"next_cursor": null` signifie que le flux est réellement épuisé.
</Note>

#### Options de création d'audit

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Option | Description |
| --- | --- |
| `--file <path>` | Baser la définition sur du JSON, ou utiliser `-` pour stdin. Les indicateurs explicites remplacent les valeurs du fichier. |
| `--description <text>` | Énoncer la question d'échec ou l'objectif. |
| `--enabled` / `--disabled` | Démarrer la planification activée ou désactivée. Par défaut : activé. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Par défaut : `86400`. |
| `--schedule-anchor <timestamp>` | Phase UTC fixe au format ISO 8601. Par défaut : prochain 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continuer après la dernière fenêtre entièrement analysée ou inspecter de manière répétée une fenêtre glissante. Par défaut : `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Par défaut : `604800`. |
| `--scope '<json>'` | Filtrer par `environments`, `agent_ids` ou d'autres champs de portée pris en charge. |
| `--ignore-error-type <type>` | Exclure des types d'erreurs ; répétable ou séparé par des virgules. |
| `--llm` / `--no-llm` | Activer ou désactiver l'analyse agentique. Par défaut : activé. |
| `--top-k <n>` | Conserver `1`–`500` constatations. Par défaut : `50`. |
| `--sensitivity low\|medium\|high` | Définir la sensibilité des rapports. Par défaut : `medium`. |
| `--channels '<json>'` | Tableau de canaux de notification. |
| `--text <brief>` | Résumé en ligne, maximum 8 192 caractères. |
| `--text-file <path>` | Lire le résumé depuis un fichier ; mutuellement exclusif avec `--text`. |
| `--url <https-url>` | Ajouter une référence HTTPS publique ; répétable jusqu'à cinq fois. |

Incluez le contexte lors de la création si la première exécution en a besoin. La création valide la définition et le contexte ensemble avant le début de l'exécution mise en file d'attente.

<Note>
  `fp audits run` est asynchrone. Interrogez `fp audits runs NAME` jusqu'à ce que la dernière exécution réussisse ou échoue avant de lire ses constatations.
</Note>

Les indicateurs explicites remplacent les variables d'environnement, qui remplacent la configuration enregistrée. En mode clé API, sélectionnez explicitement le locataire avec `--org` ou `FP_ORG`.

<Warning>
  Les orthographes `AGENTEYE_*` de ces variables **ne sont pas lues par `fp`** et ne l'ont jamais été — le CLI déclare `FP_*` (`fp_cli/app.py`), et une variable inconnue n'est pas une erreur. Définir `AGENTEYE_DASHBOARD_URL` ne redirige pas le CLI ; elle est ignorée et la commande s'exécute silencieusement contre le tableau de bord enregistré.

  `AGENTEYE_HOME` et `AGENTEYE_ENVIRONMENT` existent toujours, mais ils appartiennent au **collecteur et au SDK de télémétrie**, pas à ce CLI.
</Warning>

<Warning>
  Les commandes qui suppriment, révoquent, masquent, résolvent ou remplacent une configuration invitent à la confirmation par défaut. N'utilisez `--yes` qu'après avoir vérifié l'organisation active et la cible.
</Warning>
