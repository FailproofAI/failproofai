Utilisez `fp` pour inspecter la télémétrie Cloud, gérer l'application des règles cloud (politiques, déploiements de flotte, décisions de garde-fous), et gérer les audits, constatations, problèmes, alertes, clés, utilisateurs, requêtes et paramètres. Utilisez [`failproofai`](/fr/reference/failproof-cli) pour les hooks locaux, les politiques, la capture et l'enrôlement des machines.

Installez la Cloud CLI publiée comme outil isolé :

```bash
uv tool install fp-cloud-cli
fp version
```

## Connexion

```bash
fp login
fp whoami
```

## Syntaxe

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Les options globales doivent précéder la commande :

```bash
fp --json sessions --since 24h
```

Exécutez `fp COMMAND --help` ou `fp COMMAND SUBCOMMAND --help` pour obtenir l'aide dans le terminal.

### Événements

```text
fp events [OPTIONS]
```

Liste les événements d'agent individuels. Le flux léger par défaut exclut les charges utiles brutes ; utilisez `--full` uniquement pour une investigation délimitée.

| Option | Description |
| --- | --- |
| `--limit`, `-n <n>` | Nombre maximal de lignes. Défaut : `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, ou `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Plage UTC ISO 8601 ; remplace `--since`. |
| `--env <value>` | Filtre d'environnement ; répétable ou valeurs séparées par des virgules. |
| `--event-type <value>` | Filtre de type d'événement ; répétable ou valeurs séparées par des virgules. |
| `--agent-id <value>` | Filtre d'agent ; répétable ou valeurs séparées par des virgules. |
| `--session-id <value>` | Filtre de session ; répétable ou valeurs séparées par des virgules. |
| `--search <text>` | Recherche textuelle dans la charge utile ; répétable, avec correspondance sur n'importe quel terme. |
| `--order asc\|desc` | Ordre temporel. Défaut : les plus récents en premier. |
| `--all` | Pagination automatique jusqu'à `--limit`. |
| `--cursor <token>` | Reprendre à partir d'un curseur opaque. |
| `--page-size <n>` | Lignes par requête avec `--all` ; maximum `200`. |
| `--full` | Inclure les charges utiles brutes via l'endpoint d'événements plus lourd. |
| `--fields <csv>` | Retourner uniquement les champs sélectionnés ; demander `payload` active le mode complet. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` pagine **jusqu'à `--limit`**, dont la valeur par défaut est **50** — ainsi `--all` seul s'arrête à 50 lignes. Lorsqu'il s'arrête prématurément, la réponse contient un `next_cursor` pour reprendre ; `"next_cursor": null` signifie que le flux a réellement été épuisé.
</Note>

#### Options de création d'audit

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Option | Description |
| --- | --- |
| `--file <path>` | Baser la définition sur du JSON, ou utiliser `-` pour stdin. Les drapeaux explicites remplacent les valeurs du fichier. |
| `--description <text>` | Énoncer la question d'échec ou l'objectif. |
| `--enabled` / `--disabled` | Démarrer la planification activée ou désactivée. Défaut : activée. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Défaut : `86400`. |
| `--schedule-anchor <timestamp>` | Phase UTC fixe en format ISO 8601. Défaut : prochain 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continuer après la dernière fenêtre entièrement analysée ou inspecter de façon répétée une fenêtre glissante. Défaut : `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Défaut : `604800`. |
| `--scope '<json>'` | Filtrer par `environments`, `agent_ids`, ou d'autres champs de portée pris en charge. |
| `--ignore-error-type <type>` | Exclure des types d'erreurs ; répétable ou séparés par des virgules. |
| `--llm` / `--no-llm` | Activer ou désactiver l'analyse agentique. Défaut : activée. |
| `--top-k <n>` | Conserver `1`–`500` constatations. Défaut : `50`. |
| `--sensitivity low\|medium\|high` | Définir la sensibilité des rapports. Défaut : `medium`. |
| `--channels '<json>'` | Tableau de canaux de notification. |
| `--text <brief>` | Résumé en ligne, maximum 8 192 caractères. |
| `--text-file <path>` | Lire le résumé depuis un fichier ; mutuellement exclusif avec `--text`. |
| `--url <https-url>` | Ajouter une référence HTTPS publique ; répétable jusqu'à cinq fois. |

Incluez le contexte lors de la création lorsque la première exécution en a besoin. La création valide la définition et le contexte ensemble avant que l'exécution mise en file d'attente ne commence.

<Note>
  `fp audits run` est asynchrone. Interrogez `fp audits runs NAME` jusqu'à ce que la dernière exécution réussisse ou échoue avant de lire ses constatations.
</Note>

### Politiques

Versions de politiques gérées dans le cloud. **Session uniquement** — chaque commande ici se termine avec le code `2` sous une clé API, avant toute requête, car ce sont des routes d'écriture réservées aux root délibérément absentes de `/v1`.

| Commande | Objectif | Options |
| --- | --- | --- |
| `fp policies list` | Lister les versions de politiques. | `--json` |

| `fp policies publish NAME PATH` | Créer une version à partir d'un fichier `.mjs` local. | `--description` ; `--no-verify` |
| `fp policies enable POLICY_ID` | La rajouter à chaque déploiement dont elle avait été retirée, en créant une nouvelle génération à chaque fois. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | La retirer de chaque déploiement qui la porte, en créant une nouvelle génération à chaque fois. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | Supprimer une version de politique. | `--yes`, `-y` |
| `fp policies test PATH` | Exécuter une politique localement contre un contexte synthétique. Applique le filtre `match` de chaque politique, de sorte qu'une politique ne couvrant pas l'événement/outil donné est signalée comme `skipped` plutôt qu'exécutée. | `--event` ; `--tool` ; `--command` ; `--file-path` ; `--expect` |
| `fp policies compose PROMPT` | Rédiger une politique avec l'assistant. Nécessite `policies:write`. | — |

## Drapeaux globaux

| Drapeau | Description |
| --- | --- |
| `--json` | Émettre du JSON lisible par machine. |
| `--base-url <url>` | Utiliser un tableau de bord auto-hébergé ou de développement. |
| `--org <slug>` | Sélectionner une organisation pour cette invocation. |
| `--token <token>` | Remplacer le jeton de session utilisateur enregistré. |
| `--api-key <key>` | Authentifier l'automatisation avec une clé API ; jamais enregistrée. |
| `--timeout <seconds>` | Délai d'expiration HTTP ; doit être positif. Défaut : `30`. |
| `--quiet`, `-q` | Supprimer la sortie de statut sur stderr. |
| `--no-color` | Désactiver la sortie colorée. |
| `--insecure` / `--secure` | Désactiver ou restaurer la vérification du certificat TLS. |
| `--version` | Afficher la version installée et quitter. |
| `--help`, `-h` | Afficher l'aide. |

`--api-key` est destiné à l'automatisation. La connexion, le changement d'organisation et les commandes d'assistant nécessitent une session utilisateur.

## Variables d'environnement

| Variable | Équivalent ou objectif |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | Déplacer le répertoire de configuration CLI (défaut `~/.failproofai/fpcli`). |

| `NO_COLOR` | Désactiver la sortie colorée. |

Les drapeaux explicites remplacent les variables d'environnement, qui remplacent la configuration enregistrée. En mode clé API, sélectionnez explicitement le tenant avec `--org` ou `FP_ORG`.

<Warning>
  Les variantes `AGENTEYE_*` de ces variables **ne sont pas lues par `fp`** et ne l'ont jamais été — la CLI déclare `FP_*` (`fp_cli/app.py`), et une variable inconnue n'est pas une erreur. Définir `AGENTEYE_DASHBOARD_URL` ne redirige pas la CLI ; elle est ignorée et la commande s'exécute silencieusement contre le tableau de bord enregistré.

  `AGENTEYE_HOME` et `AGENTEYE_ENVIRONMENT` existent toujours, mais ils appartiennent au **collecteur et au SDK de télémétrie**, et non à cette CLI.
</Warning>
