## Familles d'événements

- Démarrage, fin, pause et reprise d'agent
- Requête et réponse du modèle
- Utilisation et résultat d'outil
- Déclenchement et achèvement de hook
- Attente humaine, saisie, pause et interruption
- Erreurs explicites

Chaque événement porte un horodatage, un identifiant de session, un identifiant d'agent, un type d'événement et un environnement. Les champs spécifiques à l'événement contiennent des données de modèle, d'outil, de corrélation, de résultat, de contenu, de durée ou d'erreur.

## Inspecter un contrat d'événement

<Tabs>
  <Tab title="Tableau de bord">
    1. Ouvrez **Observe → Events**.
    2. Définissez une courte fenêtre temporelle et filtrez par environnement, agent et type d'événement.
    3. Sélectionnez un événement pour inspecter ses champs normalisés et sa charge utile brute, puis ouvrez sa session pour voir le contexte d'exécution.
    4. Si une durée appariée est manquante, vérifiez que les événements de début et de fin utilisent le même identifiant de corrélation.

    Utilisez le flux Events pour restreindre les données à une seule exécution d'agent et inspecter les champs d'événement normalisés.

    ![Le flux Events en direct avec des filtres pour l'environnement, l'agent, la session et le type d'événement.](/images/dashboard/events-stream.png)

    Suivez ensuite l'événement dans sa session. La trace montre ce qui s'est passé juste avant et après, ce qui est nécessaire lorsque la charge utile seule est ambiguë.

    ![La trace de session liée utilisée pour inspecter l'événement dans son contexte d'exécution.](/images/dashboard/session-detail.png)

    Comparez les identifiants de corrélation et les horodatages dans les deux vues lorsqu'un événement apparié ou une durée est manquant.
  </Tab>
  <Tab title="CLI">
    Découvrez les valeurs de filtre valides, puis récupérez les charges utiles complètes des événements pour une session :

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    Utilisez `fp --json events ... --fields ts,event_type,session_id,payload` pour une inspection lisible par machine.
  </Tab>
</Tabs>

## Champs réservés du SDK

N'utilisez pas `timestamp`, `session_id`, `agent_id`, `type` ou `environment` comme champs Python SDK personnalisés. Les durées d'événements appariés, telles que la durée du résultat d'outil, sont calculées par le SDK et ne peuvent pas être fournies manuellement.

## Limites locales

- L'état de Failproof AI réside sous `~/.failproofai` sauf configuration explicite contraire.
- `failproofai-sdk` spooule toujours sous `~/.failproofai/custom-agents`. `FAILPROOFAI_HOME` déplace ce répertoire home ; le segment `custom-agents` est toujours ajouté, de sorte que le spool ne peut pas être placé en dehors de celui-ci. Seul le propre `configure(base_dir=...)` du SDK écrit ailleurs. `AGENTEYE_HOME` est lu par l'ancien `agenteye-collector` pour choisir ce qu'il surveille, et n'affecte plus l'endroit où le SDK écrit.
- Les labels d'environnement peuvent être définis via la configuration du SDK ou `AGENTEYE_ENVIRONMENT`.
- Les identifiants du daemon sont stockés séparément des paramètres non secrets.

Utilisez des noms d'environnement stables et à faible cardinalité. Les virgules ne sont pas prises en charge dans les labels d'environnement du daemon.

## Modifier un label d'environnement

<Tabs>
  <Tab title="Tableau de bord">
    Les labels d'environnement sont assignés par le SDK émetteur ou le daemon Failproof. Après en avoir modifié un, ouvrez **Observe → Sessions** et utilisez le filtre d'environnement pour confirmer que les nouvelles sessions portent la nouvelle valeur. Les sessions existantes conservent leur environnement d'origine.

  </Tab>
  <Tab title="CLI">
    Pour `failproofai-sdk`, configurez l'environnement dans le code ou avec sa variable d'environnement héritée. Relancez la configuration du daemon lors de la modification des paramètres au niveau de la machine.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
