Installez avec `npm install -g failproofai`. Exécutez `failproofai` sans arguments pour ouvrir le tableau de bord local.

## Commandes principales

| Commande | Description |
| --- | --- |
| `failproofai config` | Configurer les agents, le service en arrière-plan et la connexion Cloud optionnelle |
| `failproofai config --token <key>` | Configurer et connecter sans questions |
| `failproofai config --status` | Afficher la connexion, la version du service et l'état de pause |
| `failproofai policies` | Lister les politiques et leur état d'activation |
| `failproofai policies add <name>` | Activer une politique |
| `failproofai policies add <owner>/<repo>` | Installer un pack de politiques |
| `failproofai policies remove <name-or-pack>` | Désactiver une politique ou supprimer un pack |
| `failproofai policies show <owner>/<repo>` | Inspecter un pack avant de l'installer |
| `failproofai publish` | Publier vos politiques sous forme de pack |
| `failproofai audit` | Analyser l'historique local des agents |
| `failproofai harness` | Gérer les emplacements de session supplémentaires |
| `failproofai flush` | Envoyer immédiatement les événements en file d'attente |
| `failproofai backfill` | Relire l'historique plus ancien des agents |
| `failproofai update` | Finaliser une mise à jour npm et mettre à jour le service |
| `failproofai uninstall` | Supprimer les hooks et le service |

`policy`, `pack` et `p` sont des alias acceptés pour `policies`, mais la documentation utilise `policies`.

## Configurer une machine

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

La configuration ne sélectionne aucun pack de politiques par défaut. Avant d'en ajouter un, seule la politique `block-failproofai-commands` est active.

Pour une configuration Cloud automatisée sans interaction :

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Pour envoyer les décisions sans les transcriptions, connectez d'abord la machine puis définissez `collector.sessions` à `false` dans `~/.failproofai/config.json`. Le flag de configuration `--no-transcripts` est analysé mais n'applique pas ce paramètre.

Utilisez `--machine-label <name>` après la connexion de la machine pour la renommer. `--connect <url>` est la commande restreinte d'enrôlement uniquement pour une machine déjà configurée.

## Politiques et packs

```bash
failproofai policies
failproofai policies add block-sudo
failproofai policies show owner/repo
failproofai policies add owner/repo --category git,database
failproofai policies remove owner/repo
```

Tout ce qui contient un slash est une source de pack ; tout ce qui n'en contient pas est un nom de politique.

Options de sélection de pack utiles :

| Flag | Utilisation |
| --- | --- |
| `--policy a,b` | Sélectionner des politiques par nom |
| `--category x,y` | Sélectionner des catégories |
| `--all` | Tout sélectionner |
| `--cli <agents...>` | Restreindre aux harnesses nommés |

Utilisez `failproofai policies -i -c <path>` pour charger une politique personnalisée depuis n'importe quel chemin. Les fichiers de convention nommés `*policies.{js,mjs,ts}` dans `.failproofai/policies/` se chargent automatiquement.

## Mettre en pause l'application des politiques

```bash
failproofai config --pause 10m
failproofai config --status
failproofai config --resume
```

Une pause s'applique à une seule session locale et expire toujours. Elle ne suspend pas les politiques gérées par le Cloud ni la politique `block-failproofai-commands`.

## Audit et envoi des données

```bash
failproofai audit
failproofai audit --schedule 7 --email team@example.com
failproofai audit --status
failproofai flush --wait
failproofai backfill --since 30d --dry-run
```

`backfill` lit `~/.failproofai/config.json`. Supprimez `--dry-run` pour renvoyer l'historique.

## Emplacements de session supplémentaires

```bash
failproofai harness list
failproofai harness add-path claude work=/srv/team/.claude/projects
failproofai harness remove-path claude work
```

Les labels empêchent la fusion de sessions issues de deux répertoires dupliqués sous le même identifiant d'agent dérivé.

Les harnesses pris en charge sont `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity` et `goose`. La prise en charge des scopes diffère ; consultez [Harnesses](/fr/reference/harnesses).

## Variables d'environnement utiles

| Variable | Utilisation |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | Clé machine Cloud |
| `FAILPROOFAI_CLOUD_URL` | Remplacer l'URL Cloud |
| `FAILPROOFAI_HOME` | Déplacer le répertoire d'état local |
| `FAILPROOFAI_NO_DOWNLOAD=1` | Refuser les téléchargements de packs et de service |
| `FAILPROOFAI_DAEMON_BASE_URL` | Utiliser un miroir du binaire de service |
| `FAILPROOFAI_PACK_BASE_URL` | Utiliser un miroir de packs |
| `FAILPROOFAI_NO_FIRST_RUN=1` | Désactiver les invites de première exécution |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | Désactiver la télémétrie CLI anonyme |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | Remplacer les chemins supplémentaires pour un harness |
| `NO_COLOR` | Désactiver les couleurs du terminal |

## Supprimer ou mettre à jour

```bash
npm install -g failproofai@latest
failproofai update
```

Avant de supprimer le package :

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

<Warning>
  Exécutez `failproofai uninstall` avant de supprimer le package npm. npm ne supprime pas les hooks installés ni le service en arrière-plan.
</Warning>

Exécutez `failproofai help <command>` pour obtenir la liste complète des options de votre version installée.
