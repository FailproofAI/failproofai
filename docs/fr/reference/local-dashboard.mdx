Exécutez `failproofai` sans arguments pour démarrer le tableau de bord intégré à l'adresse `http://localhost:8020`. Il lit directement les historiques des agents locaux, la configuration des politiques, les résultats d'audit et l'activité des hooks depuis la machine.

Sur une machine qui n'a pas encore été configurée, la commande simple lance d'abord l'assistant de configuration initiale avant d'ouvrir le tableau de bord. Cela se produit uniquement dans un terminal interactif : en mode pipé ou en CI, elle affiche un message d'indication sur une ligne et ouvre le tableau de bord, car un assistant auquel personne ne peut répondre ne doit jamais bloquer la commande que vous avez saisie. Définissez `FAILPROOFAI_NO_FIRST_RUN=1` pour ignorer complètement la redirection et accéder directement au tableau de bord.

Le tableau de bord local est distinct de Failproof AI Cloud. Il fonctionne sans compte Cloud et ne prouve pas que les événements ont été transmis à votre organisation. Sur une machine dont la configuration est terminée, les décisions affichées ont été prises par le daemon `failproofaid`, qui est le seul évaluateur ; sur une machine non configurée, les hooks s'évaluent en cours de processus.

## Sections du tableau de bord

| Section | Ce que vous pouvez accomplir |
| --- | --- |
| Politiques → Activité | Examiner les décisions allow, instruct et deny locales ; filtrer par décision, événement, CLI, source, politique et session. |
| Politiques → Configurer | Activer les politiques d'un pack installé, modifier les paramètres pris en charge, activer ou désactiver les politiques personnalisées et de convention découvertes, et sélectionner les harnais cibles. |
| Projets | Parcourir les projets découverts dans les historiques d'agents pris en charge et comparer leurs sessions les plus récentes. |
| Sessions de projet | Ouvrir une transcription locale, consulter les entrées ordonnées brutes et les sous-agents, la télécharger et corréler l'activité des politiques. |
| Audit | Examiner la dernière analyse hors ligne, les modèles risqués, les points forts, les projets concernés et les politiques intégrées suggérées. |
| Paramètres | Configurer les analyses locales planifiées et les rapports d'audit envoyés par e-mail lorsque le daemon/la plateforme les prend en charge. |

## Consulter l'activité des politiques

<Tabs>
  <Tab title="Tableau de bord">
    1. Ouvrez **Politiques → Activité** et définissez les filtres de décision et de source.
    2. Affinez par événement, harnais, nom de politique ou session.
    3. La ligne affiche la décision, l'événement, le harnais, l'outil, la politique, le mode de permission et la durée. Développez-la pour accéder à la raison complète, chaque politique correspondante, la source décisionnelle, le déploiement cloud, ainsi que le répertoire de travail et le chemin de transcription de la session. Le nom de l'outil est affiché sur la ligne mais ne constitue pas un filtre.
    4. Suivez le lien de session pour replacer la décision dans le contexte de la transcription.

    Une ligne présentant un aspect de refus peut rester observationnelle sur une paire harnais/événement qui ne consomme pas les verdicts de blocage. La vue détaillée indique la capacité d'application vérifiée.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    L'activité locale est stockée dans `~/.failproofai/hook-activity`. Utilisez le tableau de bord plutôt que de modifier ces fichiers directement.
  </Tab>
</Tabs>

## Configurer les politiques localement

<Tabs>
  <Tab title="Tableau de bord">
    1. Ouvrez **Politiques → Configurer** et choisissez les harnais et la portée de configuration. L'onglet est accessible directement à l'adresse `http://localhost:8020/policies?tab=policies`.
    2. Activez une politique d'un pack installé, ou une politique personnalisée ou de convention découverte.
    3. Pour une politique paramétrée, ouvrez son contrôle de configuration et enregistrez les valeurs prises en charge.
    4. Retournez dans Activité et exécutez des actions correspondantes et non correspondantes.

    La liste est vide jusqu'à ce qu'un pack soit installé — cette version ne compile aucune politique propre, donc exécutez d'abord `failproofai policies add FailproofAI/policies`. Les politiques de convention affichent leur source de projet ou d'utilisateur. Les modifications explicites de chemin personnalisé peuvent nécessiter de relancer la configuration CLI afin que le chemin sélectionné soit enregistré.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies show FailproofAI/policies
    failproofai policies add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```

    `policies show <owner>/<repo>` lit le contenu d'un pack avant de l'installer. `--scope` accepte `user`, `project` ou `local` ; seul Claude Code prend en charge `local`, et Hermes et OpenClaw n'acceptent que `user`.
  </Tab>
</Tabs>

## Parcourir les projets et les sessions

La page Projets regroupe les magasins d'historique locaux pris en charge. Sélectionnez un projet pour lister ses sessions, puis ouvrez une session pour accéder au visualiseur de journaux bruts, aux segments de sous-agents, à l'action de téléchargement et à l'activité des politiques limitée à la session.

Si un projet ou une session est manquant, vérifiez que le harnais utilise son emplacement d'historique par défaut ou enregistrez une racine supplémentaire avec `failproofai harness add-path <harness> [<label>=]<path>`.

## Planifier des audits hors ligne

<Tabs>
  <Tab title="Tableau de bord">
    Ouvrez **Paramètres**, activez l'analyse planifiée, choisissez l'intervalle pris en charge et configurez la remise des rapports lorsque cette option est disponible. La page indique la prochaine exécution, la dernière exécution, le code de sortie et si le daemon en arrière-plan est pris en charge sur la plateforme.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    Modifiez le nombre de jours pour définir un intervalle différent compris entre 1 et 90 jours. Désactivez les analyses récurrentes avec `failproofai audit --no-schedule`, ce qui arrête le minuteur tout en vous maintenant connecté ; exécutez `failproofai audit` pour lancer une analyse interactive immédiate.

    La planification vous connecte lors de la première utilisation, car les résultats sont envoyés par e-mail. `--email <address>` fournit l'adresse à l'avance et ignore l'invite de connexion.
  </Tab>
</Tabs>

<Note>
  L'analyse et les résultats restent sur cette machine. La télémétrie CLI anonyme est envoyée par défaut, sauf si vous définissez `FAILPROOFAI_TELEMETRY_DISABLED=1`. Les analyses planifiées envoient également des métadonnées de la machine et peuvent envoyer un résumé limité des résultats après que vous ayez donné votre accord.
</Note>

<Warning>
  Le tableau de bord local peut afficher des invites, des entrées d'outils, du contenu de fichiers et des sorties de terminal provenant des historiques d'agents locaux. Liez-le uniquement à des interfaces de confiance et arrêtez le processus une fois la consultation terminée.
</Warning>
