Choisissez l'intégration la plus adaptée à l'environnement où votre agent s'exécute déjà.

Cette section couvre deux outils en ligne de commande ayant des rôles distincts. `failproofai` s'exécute sur la machine où tourne votre agent et applique les politiques au sein de la boucle d'agent ; `fp` communique avec Failproof AI Cloud et récupère ce que cette boucle a effectué. La configuration des machines n'est prise en charge que sous Linux et macOS — `failproofai config` refuse de s'exécuter sur tout autre système et n'écrit rien, afin d'éviter de laisser une machine à moitié configurée.

## Connecter un agent et vérifier les données

<Tabs>
  <Tab title="Tableau de bord">
    1. Ouvrez **Administration → Clés**, créez une clé avec `events:add` et `policies:pull`, puis copiez le secret.
    2. Configurez l'intégration en utilisant la page correspondante ci-dessus.
    3. Ouvrez **Observer → Événements** pour confirmer l'arrivée des événements, puis **Observer → Sessions** pour confirmer qu'ils forment des exécutions complètes.
    4. Filtrez par environnement de l'intégration et inspectez une session pour vérifier la présence des champs modèle, outil, erreur et politique requis par les audits.

    Commencez par le tiroir des clés. Les autorisations sélectionnées déterminent si la machine peut envoyer des événements et recevoir des politiques gérées par le Cloud.

    ![Le tiroir de création de clé API utilisé pour accorder les permissions d'ingestion d'événements et de livraison de politiques.](/images/dashboard/key-create.png)

    Après avoir connecté l'intégration, utilisez la liste des Sessions pour confirmer que ses événements sont regroupés en exécutions complètes dans l'environnement attendu.

    ![La liste des Sessions utilisée pour vérifier qu'une intégration nouvellement connectée rapporte des exécutions d'agent complètes.](/images/dashboard/sessions-list.png)

    Ouvrez l'une de ces sessions avant de considérer l'intégration comme terminée ; la trace doit contenir le modèle, l'outil, l'erreur et les preuves de politique dont vos audits ont besoin.
  </Tab>
  <Tab title="CLI">
    Créez une clé machine, configurez et connectez cette machine, choisissez des politiques, puis vérifiez la première session.

    ```bash
    fp keys create agent-production \
      --add events:add \
      --add policies:pull

    failproofai config --token <machine-key>

    failproofai policies add FailproofAI/policies

    failproofai flush --wait
    fp sessions --since 1h
    fp events --since 1h --limit 20
    ```

    Aucune des deux commandes de vérification ne filtre par environnement, car une machine fraîchement configurée estampille chaque événement avec `local`. N'ajoutez `--env production` qu'après avoir défini `collector.environment` — voir [Modifier un libellé d'environnement](/fr/reference/events-and-configuration#change-an-environment-label).

    Passer un token est la demande de connexion, donc `failproofai config --token <machine-key>` accomplit la même chose en une seule commande. Préférez la variable d'environnement : un argument est lisible via `ps` par tous les utilisateurs de la machine, et il se retrouve dans l'historique du shell et les journaux CI.

    L'étape des politiques n'est pas optionnelle. `failproofai config` installe le daemon et connecte tous les CLI d'agents pris en charge, mais ne choisit délibérément aucune politique — ainsi, une machine fraîchement configurée n'applique rien tant que vous n'avez pas ajouté un pack.

    Utilisez `fp --json sessions ...` lorsqu'un autre outil doit consommer le résultat. Les options globales telles que `--json`, `--org` et `--base-url` doivent être placées avant la commande.

    Consultez la [référence CLI Failproof AI](/fr/reference/failproof-cli) pour les commandes locales et la [référence CLI Failproof Cloud](/fr/reference/cloud-cli#cli-commands) pour les commandes `fp`.
  </Tab>
