Commencez par :

```bash
failproofai config --status
failproofai policies
```

## Un agent n'est pas connecté

Relancez la configuration :

```bash
failproofai config
```

La configuration est compatible Linux et macOS. Elle nécessite un accès administrateur une seule fois pour installer le service, mais ne demande jamais de mot de passe sudo.

Vérifiez les chemins et les portées des harnais dans [Harnais](/fr/reference/harnesses).

## Une session est manquante

```bash
failproofai flush --wait
failproofai backfill --since 30d --dry-run
failproofai harness list
```

Retirez `--dry-run` pour renvoyer l'historique ancien. Ajoutez un autre emplacement de transcription avec :

```bash
failproofai harness add-path <harness> [label=]<path>
```

Utilisez un label lorsque deux emplacements contiennent des copies du même projet.

## Toute action protégée est refusée

Sur une machine configurée, `failproofaid` est le seul évaluateur. S'il ne peut pas répondre, les actions protégées échouent de manière sécurisée.

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

Exécutez `failproofai config` pour réparer ou réinstaller le service.

## Un pack refuse des actions

`failproofai policies` identifie les packs qui ne peuvent pas se charger. Un pack sélectionné échoue de manière sécurisée plutôt que de disparaître.

Causes fréquentes :

- L'artefact a été modifié après l'installation.
- Le manifeste et les politiques intégrées sont en désaccord.
- Le fichier est manquant ou ne peut pas être importé.
- Le pack utilise un événement, un outil ou une forme de politique non pris en charge.

Supprimez le pack ou installez une version corrigée :

```bash
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

## Le cloud est déconnecté

Préférez une variable d'environnement pour la clé :

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
failproofai config --status
```

Une machine peut récupérer des politiques et envoyer des activités de manière indépendante. Le statut indique les deux.

## Une politique n'a pas bloqué

Vérifiez trois points :

1. La politique est activée : `failproofai policies`.
2. Son événement et son outil correspondent à l'action.
3. Ce harnais peut appliquer l'événement.

Un refus d'appel d'outil est vérifié sur les 12 harnais pris en charge. Les autres événements varient. Consultez [la capacité d'application](/fr/reference/harnesses#enforcement-capability).

## Les téléchargements sont bloqués

- `FAILPROOFAI_NO_DOWNLOAD=1` refuse les téléchargements réseau.
- `FAILPROOFAI_DAEMON_BASE_URL` redirige les téléchargements du service vers un miroir.
- `FAILPROOFAI_PACK_BASE_URL` redirige les téléchargements de packs vers un miroir.

Les packs installés continuent d'être appliqués lorsque les téléchargements sont désactivés.
