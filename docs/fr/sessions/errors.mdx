La vue Erreurs vous offre une perspective centrée sur les échecs à travers toutes les sessions. Regroupez par type d'erreur, agent, environnement, modèle, outil ou fenêtre temporelle pour identifier les problèmes opérationnels récurrents.

## Analyser les erreurs

<Tabs>
  <Tab title="Tableau de bord">
    1. Accédez à **Observer → Erreurs**.
    2. Filtrez par environnement, type d'événement, type d'erreur, agent, ID de session ou texte de recherche.
    3. Développez une erreur groupée pour afficher ses occurrences. Sélectionnez une ligne pour ouvrir l'événement exact dans sa session.
    4. Cliquez sur la commande de cloche sur une erreur représentative pour créer une alerte sur les erreurs similaires.

    ![La page Erreurs affichant un histogramme d'échecs, des erreurs groupées et la commande de création d'alerte.](/images/dashboard/errors.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp errors --env production --since 24h
    fp errors --error-type TimeoutError --agent-id checkout-agent
    fp errors --aggregate --env production --since 7d
    ```

    Utilisez `fp events --full --session-id <id>` lorsque vous avez besoin du contenu brut associé à un résumé d'erreur.
  </Tab>
</Tabs>

## Utilisez la vue Erreurs pour

- Identifier la classe d'erreur la plus fréquente en production.
- Déterminer si un outil ou un modèle est à l'origine d'un pic.
- Passer d'un comptage agrégé aux sessions représentatives.
- Créer une alerte en cas de récurrence.
- Inclure la population affectée dans un audit.

Une erreur est un événement observé. Un échec d'évaluation est un jugement qualitatif, et une anomalie d'audit est un schéma d'échec analysé. Gardez ces distinctions à l'esprit pour choisir le flux de réponse approprié.
