Une session est le meilleur point de départ lorsqu'un agent se comporte de manière inattendue. Elle regroupe les requêtes au modèle, les réponses, les appels d'outils, les interactions humaines, les erreurs, les évaluations et les décisions de politique qui appartiennent à une même exécution.

Les sessions se présentent de la même façon quel que soit le harnais qui les a produites. Une exécution Claude Code réécrivant un dépôt, un agent Hermes répondant à un client dans Slack, et un service Python instrumenté avec le SDK aboutissent tous dans le même format de trace — une seule vue couvre donc l'ensemble de la flotte.

Suivez une exécution d'agent depuis son objectif jusqu'aux appels de modèle, aux outils et à la réponse finale.

## Trouver une session

<Tabs>
  <Tab title="Tableau de bord">
    1. Dans la barre latérale Cloud, accédez à **Observe → Sessions**.
    2. Définissez la fenêtre temporelle, puis filtrez par environnement, statut, agent ou ID de session.
    3. Ajoutez des plages de scores ou de métriques lorsque vous avez besoin d'un filtre sur la qualité, le coût, les tokens ou la latence.
    4. Sélectionnez une ligne pour ouvrir sa trace. Utilisez le contrôle de copie à côté de l'ID de session pour le partager.

    ![La liste des sessions affichant une ligne par exécution avec des filtres sur l'environnement, l'agent, le statut et le score d'évaluation.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    Ajoutez `--agents` pour développer les exécutions multi-agents, `--all` pour paginer, ou `--fields` pour choisir les colonnes de sortie.
  </Tab>
</Tabs>

## Ce que vous pouvez faire

- Trouver une exécution par agent, environnement, heure, modèle, type d'événement ou état d'erreur.
- Suivre la séquence exacte qui a produit un résultat.
- Comparer des exécutions réussies et échouées.
- Ouvrir les preuves utilisées par un résultat d'audit ou un incident d'alerte.
- Exporter une session lorsque vous avez besoin d'un enregistrement hors ligne.

## Un ordre d'investigation fiable

1. Confirmer l'objectif et l'environnement de la session.
2. Identifier la première erreur ou décision inattendue — pas seulement l'échec final.
3. Inspecter le contexte du modèle et l'entrée de l'outil immédiatement avant cela.
4. Vérifier les nouvelles tentatives, la latence et les interruptions humaines.
5. Examiner les scores d'évaluation et les décisions de politique.
