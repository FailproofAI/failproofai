Une session correspond à une exécution d'agent. Elle regroupe le prompt, les appels au modèle, les outils, les erreurs, les interventions humaines, les décisions de politique et le résultat final.

## Où se trouvent les sessions

<Tabs>
  <Tab title="Local">
    Exécutez `failproofai` pour ouvrir le tableau de bord sur `http://localhost:8020`. L'historique des sessions reste sur cette machine.
  </Tab>
  <Tab title="Cloud">
    Connectez la machine, puis ouvrez **Observe → Sessions** :

    ```bash
    export FAILPROOFAI_CLOUD_TOKEN="<key>"
    failproofai config
    ```

    Le Cloud reçoit les transcripts complets par défaut. Pour n'envoyer que les décisions de politique, connectez-vous d'abord, puis définissez `collector.sessions` sur `false` dans `~/.failproofai/config.json`. L'option de configuration `--no-transcripts` n'applique pas ce paramètre.
  </Tab>
</Tabs>

Les sessions proviennent des 12 [harnais d'agents](/fr/reference/harnesses) pris en charge ainsi que des agents instrumentés avec le [SDK Python](/fr/reference/custom-agents).

## Trouver une session

Dans le Cloud, filtrez par période, environnement, statut, agent ou identifiant de session. Depuis la CLI :

```bash
fp sessions --since 24h
fp sessions --status error,timeout --agent-id checkout-agent
fp --json sessions --session-id <session-id>
```

Utilisez `fp errors --since 24h` pour les échecs qui n'ont jamais été évalués. `fp sessions --status` utilise le résultat de la dernière évaluation ; une session non évaluée n'a donc pas de statut.

## Lire une exécution

1. Confirmez l'objectif de l'agent et son environnement.
2. Repérez la première erreur ou décision inattendue.
3. Examinez le contexte du modèle et l'entrée de l'outil juste avant celle-ci.
4. Vérifiez les tentatives de relance, la latence et les interruptions humaines.
5. Passez en revue les évaluations et les décisions de politique.

## Si une session est manquante

```bash
failproofai flush --wait
failproofai config --status
failproofai backfill --since 30d --dry-run
```

Utilisez `failproofai harness add-path <harness> [<label>=]<path>` lorsque des sessions se trouvent en dehors de l'emplacement habituel du harnais, comme un autre profil, le répertoire home d'un conteneur ou un répertoire d'équipe monté.
