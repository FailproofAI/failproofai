Une session est le meilleur point de départ lorsqu'un agent se comporte de manière inattendue. Elle regroupe les requêtes au modèle, les réponses, les appels d'outils, les interactions humaines, les erreurs, les évaluations et les décisions de politique appartenant à une même exécution.

Suivez une exécution d'agent depuis son objectif jusqu'à la réponse finale, en passant par les appels au modèle et les outils.

## Trouver une session

<Tabs>
  <Tab title="Dashboard">
    1. Dans la barre latérale Cloud, accédez à **Observer → Sessions**.
    2. Définissez la fenêtre temporelle, puis filtrez par environnement, statut, agent ou identifiant de session.
    3. Ajoutez des plages de scores ou de métriques pour affiner par qualité, coût, tokens ou latence.
    4. Sélectionnez une ligne pour ouvrir sa trace. Utilisez le bouton de copie situé à côté de l'identifiant de session pour le partager.

    ![La liste des sessions affichant une ligne par exécution avec des filtres par environnement, agent, statut et score d'évaluation.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    Ajoutez `--agents` pour développer les exécutions multi-agents, `--all` pour paginer, ou `--fields` pour choisir les colonnes de sortie.
  </Tab>
</Tabs>

## Ce que vous pouvez faire

- Retrouver une exécution par agent, environnement, période, modèle, type d'événement ou état d'erreur.
- Suivre la séquence exacte qui a produit un résultat.
- Comparer les exécutions réussies et échouées.
- Consulter les preuves utilisées par un résultat d'audit ou un incident d'alerte.
- Exporter une session pour en conserver un enregistrement hors ligne.

## Un ordre d'investigation fiable

1. Confirmez l'objectif et l'environnement de la session.
2. Identifiez la première erreur ou décision inattendue — pas seulement l'échec final.
3. Examinez le contexte du modèle et l'entrée de l'outil juste avant cet événement.
4. Vérifiez les nouvelles tentatives, la latence et les interruptions humaines.
5. Passez en revue les scores d'évaluation et les décisions de politique.
