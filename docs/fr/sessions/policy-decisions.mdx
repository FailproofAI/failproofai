Les décisions de politique indiquent ce que Failproof AI a effectué lors d'une exécution d'agent.

<Tabs>
  <Tab title="Tableau de bord">
    Accédez à **Observe → policy** pour examiner les décisions, le taux de blocage, les machines et les assignations déployées.

    ![La page Policy affichant les totaux de décisions, un filtre par machine, l'activité d'application dans le temps et le tableau de correspondance des politiques.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp guardrails summary --since 24h
    fp guardrails timeline --since 24h
    failproofai policies
    failproofai config --status
    ```

    `--since` accepte `1h`, `6h`, `24h` ou `7d`. Ajoutez `--machine <id>` pour cibler une machine spécifique.
  </Tab>
</Tabs>

## Lire un déploiement en mode observation

Le mode observation exécute la politique réelle et enregistre toute décision `deny` ou `instruct`. L'agent est toujours autorisé à continuer.

```bash
fp fleet deploy <machine> --add <policy>:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add <policy>:enforce
```

<Warning>
  Un `--add <policy>` sans suffixe applique immédiatement la politique lorsque celle-ci n'a pas de déploiement existant. Ajoutez `:observe` pour un déploiement en mode fantôme.
</Warning>

Seules les décisions observées non-allow sont enregistrées. Un délai d'expiration est enregistré comme allow, car c'est également le comportement en mode d'application.

Un deny enregistré ne prouve pas que le système a arrêté l'action. Les deny d'appels d'outils sont vérifiés sur l'ensemble des 12 harnais pris en charge ; les autres événements peuvent varier. Consultez [la capacité d'application](/fr/reference/harnesses#enforcement-capability).

## Investiguer un résultat inattendu

| Ce que vous observez | Vérification |
| --- | --- |
| Aucune décision | `failproofai config --status` et si la session est en pause |
| Nombreux deny sans nom de politique | [Comportement en cas d'échec de politique](/fr/policies/failure-behavior) |
| Toute action protégée est refusée | Si le service `failproofaid` est en bonne santé |
| Un deny que vous ne pouvez pas désactiver | `block-failproofai-commands` est toujours actif |
| Aucune donnée pour `--env production` | Les nouvelles machines utilisent l'environnement `local` |
