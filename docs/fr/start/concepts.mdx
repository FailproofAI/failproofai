Failproof AI enregistre les actions des agents et détermine ce qu'ils sont autorisés à faire.

## Observer

| Terme | Signification |
| --- | --- |
| Session | Une exécution d'agent |
| Événement | Une action au sein d'une session |
| Trace | La vue ordonnée d'une session |
| Évaluation | Un score ou un jugement |
| Audit | Un examen de plusieurs sessions |
| Constat | La preuve d'un schéma d'échec |
| Problème | La réponse dont quelqu'un est responsable |
| Alerte | Une règle qui détecte les récurrences |

## Appliquer

| Terme | Signification |
| --- | --- |
| Harness | L'environnement dans lequel un agent s'exécute |
| Hook | Un point où le harness demande une décision |
| Politique | Une règle qui autorise, guide ou bloque |
| Pack de politiques | Un ensemble de politiques versionné que tout le monde peut installer |
| Daemon | Le service local qui évalue les politiques |
| Déploiement | Les politiques assignées à une machine |

## Le flux de travail

```text
Session → Audit → Finding → Issue → Policy
```

Commencez par les preuves. Identifiez l'échec récurrent, désignez un responsable, puis prévenez sa réapparition.

Une politique retourne `allow`, `instruct` ou `deny`. Le guidage via `instruct` dépend du harness ; utilisez `deny` lorsque l'action doit être stoppée.

Le mode Observe est indépendant de la décision. Il applique la politique réelle et enregistre ce qu'elle ferait, tout en laissant l'agent continuer.

<Warning>
  Un simple `fp fleet deploy <machine> --add <policy>` s'applique immédiatement. Ajoutez `:observe` pour un déploiement en mode shadow.
</Warning>

La configuration initiale ne choisit aucun pack de politiques. Avant d'en ajouter un, seule `block-failproofai-commands` est active. Le catalogue compilé contient 39 politiques réparties en 9 catégories.

Consultez les [harnesses supportés](/fr/reference/harnesses#enforcement-capability) avant de supposer qu'un événement peut bloquer dans tous les environnements d'agents.
