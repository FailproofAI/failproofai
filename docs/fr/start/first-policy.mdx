---
title: "Évitez votre premier incident avec une politique"
description: "Créez une version de politique, déployez-la en mode observation, puis appliquez-la."
icon: "shield-check"
---

N'utilisez une politique qu'après avoir clairement identifié l'action non sécurisée et les actions légitimes qui doivent rester autorisées.

<Tabs>
  <Tab title="Tableau de bord">
    <Steps>
      <Step title="Créer la politique">
        Accédez à **Admin → éditeur de politiques**. Commencez par la politique de démonstration, examinez ou modifiez son code source, puis sélectionnez **publier la version**. La publication crée une version immuable que vous pouvez déployer sur les machines.

        ![Vue de composition de l'éditeur de politiques avec une politique de démonstration prête à être publiée en tant que version immuable.](/images/dashboard/policy-editor.png)
      </Step>
      <Step title="Déployer sur une machine">
        Accédez à **Admin → application**, développez la machine cible et sélectionnez **modifier cette machine**. Ajoutez la politique de démonstration publiée, épinglez sa version, choisissez **observer**, puis appliquez le déploiement.

        ![L'éditeur de déploiement machine avec une version de politique publiée sélectionnée en mode observation avant l'application du déploiement.](/images/dashboard/enforcement-editor.png)
      </Step>
      <Step title="Vérifier la politique">
        Lancez une nouvelle session d'agent sur cette machine, puis ouvrez **Observer → politique**. Sélectionnez la machine et confirmez que la politique de démonstration apparaît dans le mappage des politiques et la chronologie des décisions. Le mode observation enregistre ce que la politique ferait sans bloquer l'action.

        ![La page Politique affichant le total des décisions, l'activité d'application dans le temps, ainsi que les mappages de politiques locaux et gérés depuis le Cloud.](/images/dashboard/policy-observe.png)
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    La création de politiques dans le Cloud et le déploiement sur une flotte sont des workflows d'administration. Utilisez le CLI local pour valider la même politique avant de la publier :

    ```bash
    failproofai policies --install --custom ./payment-retry.policies.ts \
      --cli claude --scope project
    failproofai config --status
    ```

    Utilisez `fp` pour inspecter les décisions de politique visibles depuis le Cloud :

    ```bash
    fp events --event-type hook_completed --env production --since 24h
    fp sessions --env production --since 24h
    ```

    Le CLI Cloud n'expose pas les routes de déploiement d'application réservées aux administrateurs. Publiez les versions depuis **Admin → éditeur de politiques** et déployez-les depuis **Admin → application**.
  </Tab>
</Tabs>
