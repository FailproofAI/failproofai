Commencez par identifier un comportement à bloquer et une action légitime qui doit continuer à fonctionner.

## Essayez d'abord une politique vérifiée

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI inclut 39 politiques vérifiées. Consultez le [catalogue](/fr/policies/builtin-catalog) avant d'en écrire une nouvelle.

## Rédigez et testez la vôtre

<Steps>
  <Step title="Créez une politique fonctionnelle">
    ```bash
    failproofai publish --init guards.mjs
    ```

    Cela génère une politique qui bloque `git push --force`. Modifiez-la selon votre règle.
  </Step>
  <Step title="Appliquez-la sur cette machine">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    Demandez à votre agent d'effectuer l'action bloquée, puis vérifiez **Policies → Activity** dans le tableau de bord local.
  </Step>
  <Step title="Conservez-la ou supprimez-la">
    Placez un fichier `*policies.mjs` dans `.failproofai/policies/` pour le charger automatiquement.

    Supprimez les fichiers personnalisés explicites avec :

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## Partagez-la

Publiez un pack public :

```bash
failproofai publish
```

N'importe qui pourra ensuite l'installer avec `failproofai policies add <owner>/<repo>`. Ajoutez vous-même le topic GitHub `failproofai-policies` pour que le [Policy Hub](https://befailproof.ai/policy-hub/) puisse l'indexer.

Pour un déploiement Cloud :

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  Un simple `--add checkout-guard` applique la politique immédiatement. Ajoutez `:observe` pour enregistrer ce que la politique aurait fait sans bloquer l'agent.
</Warning>

Consultez [publier un pack](/fr/policies/publish-a-pack) ou [déployer des politiques](/fr/policies/deploy) pour le flux de travail complet.
