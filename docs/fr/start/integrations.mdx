## Avant de commencer

Cette approche suppose deux choses, qu'aucun des codes ci-dessous ne fait pour vous :

| Prérequis | Pourquoi |
| --- | --- |
| Python 3.10 ou version plus récente | Le minimum requis par le SDK. |
| Une machine configurée avec `failproofai config` | Cette commande installe le démon failproofaid, et ce démon est le seul à transmettre ce que le SDK écrit. Sans lui, les lots s'accumulent dans le répertoire de file d'attente et ne sont jamais envoyés. |

<Note>
  **Cette approche enregistre ; elle n'applique pas de règles.** Le SDK capture ce que votre agent a fait. Les politiques se déclenchent depuis un hook dans une CLI d'agent — appliquer des règles sur un agent de framework signifie donc placer un hook dans votre propre runtime. Voir [Policies](/fr/policies/overview).
</Note>

## Trois lignes, quel que soit le framework

<CodeGroup>
```bash LangGraph
pip install 'failproofai-sdk[langgraph]'
```

```bash CrewAI
pip install 'failproofai-sdk[crewai]'
```

```bash LlamaIndex
pip install 'failproofai-sdk[llamaindex]'
```

```bash Pydantic AI
pip install 'failproofai-sdk[pydantic-ai]'
```

```bash Custom agents
pip install failproofai-sdk
```
</CodeGroup>

```python
import failproofai_sdk

failproofai_sdk.configure(environment="production")
failproofai_sdk.instrument()          # détecte les frameworks que vous avez importés

with failproofai_sdk.session():
    ...                               # votre appel d'agent existant, inchangé
```

Pas de décorateurs sur vos fonctions, pas de callback passé à vos appels, pas d'identifiants à faire circuler dans votre code. Seul l'appel à l'intérieur de la session diffère :

<Tabs>
  <Tab title="LangGraph">
    ```python
    graph.invoke({"messages": [HumanMessage("...")]})
    ```
  </Tab>
  <Tab title="CrewAI">
    ```python
    Crew(agents=[analyst, writer], tasks=[gather, summarise]).kickoff()
    ```
  </Tab>
  <Tab title="LlamaIndex">
    ```python
    await agent.run("...")        # sous `async with failproofai_sdk.session():`
    ```
  </Tab>
  <Tab title="Pydantic AI">
    ```python
    agent.run_sync("...")
    ```
  </Tab>
  <Tab title="Custom agents">
    ```python
    with failproofai_sdk.agent("planner"):
        with failproofai_sdk.tool_call("search", input={"q": q}) as t:
            t.output = search(q)
    ```
  </Tab>
</Tabs>

L'installation supplémentaire correspond au **framework**. Chaque adaptateur est inclus dans le package de base, donc un projet qui dispose déjà de son framework n'a besoin d'aucun supplément.

## Vérifier que les données sont arrivées

Lancez une session instrumentée, puis ouvrez **Observe → Sessions** et sélectionnez votre environnement. L'exécution apparaît sous forme de trace reconstruite.

Si rien n'arrive, vérifiez que la machine est configurée et connectée avec `failproofai config --status`. Si ce n'est pas le cas, exécutez `failproofai config`. Voir [Choose your setup](/fr/start/setup).

<Warning>
  Ne vérifiez pas le répertoire de file d'attente pour confirmer la livraison. Le démon Failproof collecte et supprime chaque lot en quelques millisecondes — le lire entre en compétition avec le collecteur et affiche bien moins d'événements que ceux qui ont été émis.
</Warning>

Pour s'assurer que le SDK écrit bien, arrêtez d'abord le démon, lancez votre session, puis inspectez `~/.failproofai/custom-agents/events/`. Lorsque le démon tourne, un répertoire vide est l'état normal attendu.

<CodeGroup>
```bash Linux
sudo systemctl stop failproofaid@$USER
```

```bash macOS
sudo launchctl bootout system/ai.failproof.failproofaid.$USER
```
</CodeGroup>

Exécutez `failproofai config` ensuite pour le relancer. Pendant l'arrêt du démon, les événements de hook sur cette machine n'ont pas d'évaluateur et sont refusés — ne l'arrêtez donc que le temps nécessaire à la vérification.
