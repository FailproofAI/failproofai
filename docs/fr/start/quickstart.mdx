Installez Failproof AI sur une machine, puis restez en local ou connectez-vous au Cloud.

Si votre agent s'exécute dans un [environnement d'exécution compatible](/fr/reference/harnesses), suivez ces étapes. Pour les agents construits avec LangChain, CrewAI, LlamaIndex, Pydantic AI ou votre propre runtime, commencez par [instrumenter votre agent](/fr/start/integrations).

## Laissez votre agent guider la configuration

Installez la compétence principale Failproof AI dans un agent compatible :

```bash
npx skills add FailproofAI/skills
```

Cette commande installe la compétence principale ainsi que ses compétences spécialisées. Utilisez `--skill
failproofai` si vous souhaitez uniquement la compétence principale. Elle comprend la configuration locale et Cloud,
l'état du service, les sessions, les audits, les politiques et le dépannage. Elle guide le travail
et achemine les tâches spécialisées vers la bonne compétence Failproof AI ; elle ne remplace
pas l'installation CLI décrite ci-dessous.

## Configurer la machine

<Steps>
  <Step title="Installer et configurer Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    L'installation déploie le service en arrière-plan et connecte tous les agents compatibles détectés. Elle peut demander des droits administrateur une seule fois. Compatible avec Linux et macOS.
  </Step>

  <Step title="Choisir les politiques">
    L'installation ne sélectionne aucun pack de politiques par défaut. Ajoutez le pack Failproof AI :

    ```bash
    failproofai policies add FailproofAI/policies
    failproofai policies
    ```

    La deuxième commande affiche toutes les politiques actives sur cette machine et indique si chacune est activée. Tant qu'aucun pack n'est ajouté, seule `block-failproofai-commands` est appliquée.
  </Step>

  <Step title="Vérifier la machine">
    ```bash
    failproofai config --status
    ```

    Cette commande affiche l'état du service, la connexion Cloud et l'état de pause.
  </Step>
</Steps>

## Choisir entre local et Cloud

<Tabs>
  <Tab title="Rester en local">
    Aucun compte n'est requis.

    ```bash
    failproofai
    failproofai audit
    ```

    La première commande ouvre le tableau de bord local à l'adresse `http://localhost:8020`. La seconde analyse l'historique des agents déjà présent sur cette machine.
  </Tab>

  <Tab title="Se connecter au Cloud">
    Créez une clé machine dans Failproof AI Cloud, puis exécutez :

    ```bash
    failproofai config --token <machine-key>
    failproofai config --status
    ```

    Le Cloud reçoit les décisions de politique et les transcriptions de session. Pour n'envoyer que les décisions, connectez-vous d'abord, puis définissez `collector.sessions` à `false` dans `~/.failproofai/config.json` ; l'option de configuration `--no-transcripts` n'applique pas ce paramètre. Pour les shells partagés et les environnements CI, utilisez `FAILPROOFAI_CLOUD_TOKEN` plutôt que d'inclure la clé dans l'historique des commandes.
  </Tab>
</Tabs>

## Vérifier le fonctionnement

Lancez l'un de vos agents et demandez-lui d'effectuer une tâche habituelle. Ensuite :

Le refus d'un appel d'outil est vérifié sur les 12 environnements d'exécution compatibles. L'application en fin de tour est vérifiée sur 8 ; les autres paires environnement-événement peuvent être uniquement observables ou non vérifiées.

- Ouvrez **Politiques → Activité** dans le tableau de bord local pour consulter les décisions de politique.
- Ouvrez **Observer → Sessions** dans le Cloud pour voir l'exécution complète.
- Exécutez `failproofai audit` pour détecter des comportements risqués ou inutiles.

<Warning>
  Après l'installation, le service `failproofaid` est l'évaluateur. S'il ne peut pas répondre, les actions protégées sont refusées. Exécutez `failproofai config --status` si un agent s'arrête de manière inattendue.
</Warning>
