Failproof AI peut fonctionner entièrement sur une seule machine ou se connecter au Cloud pour des sessions partagées et une gestion centralisée des politiques.

## Local, sans compte

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai
```

Cette commande installe le service, connecte les agents compatibles, ajoute un pack de politiques et ouvre le tableau de bord à l'adresse `http://localhost:8020`.

Exécutez `failproofai audit` pour analyser l'historique des agents déjà présents sur la machine.

## Connecter Failproof AI Cloud

Créez une clé machine dans Cloud, puis exécutez :

```bash
failproofai config --token <machine-key>
failproofai config --machine-label checkout-runner-01
failproofai policies add FailproofAI/policies
failproofai config --status
```

Vous pouvez également exporter `FAILPROOFAI_CLOUD_TOKEN=<machine-key>` et lancer simplement `failproofai config`. Privilégiez la variable d'environnement sur les machines partagées et en CI afin que la clé n'apparaisse pas dans l'historique du shell ou dans la liste des processus.

Cloud utilise une seule connexion pour deux rôles distincts :

- Récupérer les politiques assignées à cette machine.
- Envoyer les décisions de politiques et les transcriptions de sessions.

Pour n'envoyer que les décisions, connectez-vous d'abord, puis définissez `collector.sessions` à `false` dans `~/.failproofai/config.json`. Ne comptez pas sur `--no-transcripts` : le chemin de configuration actuel analyse bien ce flag, mais ne l'applique pas. Voir [événements et configuration](/fr/reference/events-and-configuration#machine-configuration).

<Note>
  `--machine-label` renomme une machine déjà connectée. Exécutez cette commande après la commande de configuration initiale, et non lors de la première connexion.
</Note>

## Configuration sans intervention

`failproofai config` ne nécessite pas de flag spécial pour fonctionner en mode non interactif. En CI ou dans un conteneur, la configuration demandée est appliquée sans aucune invite.

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Un accès administrateur est nécessaire une seule fois pour installer le service en arrière-plan. La configuration n'ouvre jamais une invite `sudo` interactive pour demander un mot de passe : elle réussit sans en avoir besoin, ou affiche les commandes qu'un administrateur doit exécuter manuellement.

## Plateformes supportées

La configuration fonctionne sur Linux et macOS. Sur toute autre plateforme, le processus s'arrête sans écrire de hooks ni laisser d'état de configuration partiel.
