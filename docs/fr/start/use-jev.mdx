Jev intervient à deux moments dans l'exécution d'un agent : évaluer une session terminée par rapport à des réponses connues, ou examiner un appel d'outil dans le contexte de ce que vous avez demandé à l'agent de faire.

<Tabs>
  <Tab title="Évaluations Jev">
    Utilisez une évaluation Jev lorsqu'une session terminée peut être notée par rapport à une question ayant quelques réponses connues, par exemple « Le client a-t-il demandé un remboursement ? Répondez par oui ou non. » Cela vous aide à identifier des tendances entre les sessions.

    ## Créer une évaluation

    Dans le tableau de bord Cloud, ouvrez **Analyze → eval authoring → new eval**. Saisissez une question à réponse fixe, sélectionnez **draft**, et vérifiez qu'un score classificateur a bien été choisi. [Testez-la](/fr/evaluations/test) sur de vraies sessions, puis déployez-la.

    ![Le formulaire partagé de création d'évaluation où vous décrivez une question, examinez le brouillon et le déployez. Cette capture d'écran montre un brouillon de code ; utilisez une question à réponse fixe pour Jev.](/images/dashboard/eval-authoring-draft.png)

    ## Lire les scores

    Après la fin d'une nouvelle session, ouvrez **Observe → Evaluations** ou utilisez le CLI Cloud :

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    Le CLI lit les scores ; la création d'une évaluation Jev passe actuellement par le tableau de bord. Consultez [les évaluations Jev](/fr/evaluations/jev) pour les types de questions et des exemples.
  </Tab>
  <Tab title="Politiques Jev">
    Utilisez la révision par politique Jev lorsqu'une politique basée sur la correspondance de chaînes nécessite le contexte de votre requête pour déterminer si un appel d'outil est sûr. Commencez en mode **observe** afin de pouvoir inspecter les réponses de Jev pendant que vos politiques installées continuent de trancher chaque appel.

    Les vérifications de Jev proviennent d'un pack ; Failproof AI n'en fournit aucun. Tant que vous ne les installez pas, Jev ne pose aucune question, même s'il est configuré :

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Configurer Cloud Jev

    Dans le tableau de bord Cloud, ouvrez **Administration → Keys** et créez une clé avec le préréglage **machine**. Utilisez-la avec `failproofai config` comme indiqué dans le [guide de démarrage rapide](/fr/start/quickstart). Sur une machine sans configuration Jev existante, cela active Cloud Jev en mode observe. Vérifiez la connexion avec :

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Utiliser votre propre point de terminaison

    Dans le tableau de bord local, ouvrez **Settings → Jev**. Choisissez le fournisseur, collez son jeton, sélectionnez **observe**, puis activez Jev.

    ![Le panneau de paramètres Jev local avec un fournisseur, un champ de jeton et le mode observe sélectionné.](/images/dashboard/jev-settings.png)

    Ou configurez et testez votre point de terminaison depuis un terminal :

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Demandez à un agent connecté d'utiliser son outil de lecture de fichiers sur `README.md`. Confirmez que cet appel d'outil apparaît dans la session, puis inspectez-le sous **Policies → Activity** dans le tableau de bord local. Une fois que les résultats en mode observe vous semblent corrects, [les politiques Jev](/fr/policies/jev) expliquent quand passer à l'application. Pour les détails des fournisseurs et la configuration, consultez la [référence d'intégration](/fr/reference/jev).
  </Tab>
</Tabs>
