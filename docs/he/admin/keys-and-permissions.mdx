השתמש במפתח נפרד לכל אדם, מכונה או עבודת אוטומציה. הענק רק את ההרשאות שהוא זקוק להן.

## יצירה וסיבוב של מפתח

השתמש ב-**Admin → Keys**, או ב-Cloud CLI:

```bash
fp keys list
fp keys create "audit automation" --add audits:read
fp keys disable "audit automation"
```

שמור את הסוד בזמן יצירתו; הוא לא יוצג שוב. בצע סיבוב על ידי יצירת החלפה, עדכון הצרכן, ואז השבתת המפתח הישן.

## מפתחות מכונה

מפתח מכונה מחבר את השירות המקומי ל-Cloud:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

מכונה מחוברת עשויה להזדקק לשתי יכולות:

- `policies:pull` לקבלת מדיניות מנוהלת ב-Cloud.
- `events:add` לשליחת החלטות ותרומות.

דוחות סטטוס מדווחים על אלה בנפרד מכיוון שאחת עשויה לעבוד בעוד השנייה לא.

## הרשאות נפוצות

| הרשאה | מאפשרת |
| --- | --- |
| `events:add` | שלח אירועים |
| `events:read` | קרא אירועים ושגיאות |
| `evaluations:read` | קרא תרומות והערכות |
| `audits:read` / `audits:write` | בדוק או נהל ביקורות |
| `policies:read` / `policies:write` | בדוק או פרוס מדיניות |
| `policies:pull` | משוך הקצאות מדיניות מכונה |
| `keys:create` / `keys:disable` | צור או השבת מפתחות |
| `orgs:admin` | ניהול ארגון ברמת מופע; לא ניתן להקצאה למפתח ארגון |

כמה פקודות ניהול `fp fleet` ו-`fp guardrails` דורשות פעילות משתמש מחובר ולא מפתח API. טקסט העזרה שלהם קובע זאת לפני הגשת בקשה.

<Warning>
  לעולם אל תשתמש שוב בהרשאות בילוע כגון `AGENTEYE_KEY` או `AGENTEYE_API_KEY` כ-`FP_API_KEY`. הם משרתים מערכות והרשאות שונות.
</Warning>
