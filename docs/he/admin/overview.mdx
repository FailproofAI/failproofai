ניהול הוא החלק של Cloud ב-Failproof AI. ארגונים, חברים, מפתחות API, הגדרות ארגון וצריכה מדודה כולם דורשים חיבור Cloud.

<Note>
  Failproof AI פועל גם ללא חשבון כלל. מכונה מקומית אוכפת מדיניות, שומרת את היסטוריית ההפעלות שלה בדיסק, משרתת את [לוח המחוונים המקומי](/he/reference/local-dashboard) על `localhost:8020`, ומריצה `failproofai audit` ללא שליחת משהו לשום מקום. ראה [תצורת מכונה](/he/reference/events-and-configuration#machine-configuration) עבור מפתחות `collector` מקומיים. דלג על שאר הסעיף הזה אם אתה לא משתמש בـ Cloud.
</Note>

## אדם שנכנס, או מפתח API

`fp` פועל באחד משני מצבי הנמקה, והחלוקה קובעת אילו פקודות פועלות. פקודה שמפתח API אינו יכול לבצע מסרבת לפני שהוא פותח חיבור וממנה את הסיבה, במקום להשאיר 401 או 403 לעמוד במקומו.

| פקודה | מפתח API | הרשאה |
| --- | --- | --- |
| `fp whoami` | כן | אף אחד |
| `fp usage` | כן | `usage:read` |
| `fp keys list` / `show` | כן | `keys:read` |
| `fp keys create` | כן | `keys:create` |
| `fp keys disable` | כן | `keys:disable` |
| `fp keys regenerate` | כן | `keys:regenerate` |
| `fp keys update` | לא | `keys:update`, שאף מפתח לא יכול להחזיק |
| `fp users list` / `show` | כן | `users:read` |
| `fp users create` | כן | `users:create` |
| `fp users update` | כן | `users:update` |
| `fp users disable` / `enable` | כן | `users:delete` |
| `fp settings list` / `schema` | כן | `settings:read` |
| `fp settings set` | כן | `settings:write` |
| `fp orgs list` / `switch` / `current` / `perms` | לא | הפעלה שנכנסה בלבד |

`fp usage` היא הפקודה שניתן להעביר לסקריפט דיווח: היא פועלת ללא השגחה תחת מפתח ודורשת רק `usage:read`.
