ארגונים מבודדים בין הם מושבים, הערכות, ביקורות, בעיות, התראות, שאילתות, לוחות בקרה, משתמשים ומפתחות. אשר את הארגון הפעיל לפני ששינוי כל משאב מנהלי.

## בחירת הארגון

<Tabs>
  <Tab title="Dashboard">
    השתמש במחליף הארגונים בחלק העליון של סרגל הצד של ה-Cloud. הכל מתחתיו — כולל כל דף ב-**admin** — קורא וכותב אז לארגון זה.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp orgs list
    fp orgs switch reliability-team
    fp orgs current
    fp orgs perms
    ```

    `fp orgs switch` ללא slug פותח בוררת חצים המתחילה בארגון הנוכחי שלך; ריצה לא-אינטראקטיבית חוזרת לשאלה ממוספרת, ותחת `--json` דרוש slug. הבחירה נשמרת ב-`~/.failproofai/fpcli/cli-auth.json`, כך שפקודות מאוחרות יותר שולחות אותה כשוכר פעיל. עקוף אותה לפקודה אחת עם `--org <slug>` או `FP_ORG`.
  </Tab>
</Tabs>

<Note>
  כל פקודת `fp orgs` צריכה בן אדם מחובר ודוחה תחת מפתח API, מכיוון שחברות בארגון שייכת לאדם ומפתח כבר פועל עבור ארגון אחד. הפקודות `fp users` למטה עובדות בשתי הדרכים.
</Note>

## ניהול חברים

<Tabs>
  <Tab title="Dashboard">
    1. עברו ל-**admin → users** וחפשו חברים לפי דוא״ל, או צמצמו את הרשימה עם שבבי המסנן `protected`, `admin`, `standard` ו-`read-only`.
    2. בחרו **new user**, הזינו את הדוא״ל, בחרו סט הרשאות ותאימו עדכונים לכל חבר במידת הצורך.
    3. פתחו חבר מאוחר יותר כדי לשנות הענקות, להשבית כניסה או להפעיל את החשבון שוב.

    ![דף המשתמשים עם תיבת החיפוש בדוא״ל, שבבי המסנן וכרטיס חבר המציג את ההענקות שלו מקובצות לפי משאב.](/images/dashboard/users.png)

    שבבי ההענקה בתמונה זו קדמו לשינוי השם מ-`incidents:*` ל-`issues:*`; רשימת [ההרשאות הנפוצות](/he/admin/keys-and-permissions#common-permissions) עדכנית.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp users list
    fp users list --active-only
    fp users create engineer@example.com --permission-set standard
    fp users show engineer@example.com
    fp users update engineer@example.com --add audits:write
    fp users disable engineer@example.com
    fp users enable engineer@example.com
    ```

    חברים מתייחסים לפי דוא״ל ופתורים ללא תלות באותיות גדולות וקטנות, כך ש-`fp users show Alice.Chen@Example.com` ו-`fp users create alice.chen@example.com` מתייחסים לאותו אדם.
  </Tab>
</Tabs>

### הענקות, ומה כל פועל צריך

הענקות חברים משתמשות בחשבון זהה לזה של מפתחות: הענקות יעילות הן `(set ∪ added) − removed`, ו-`--add` / `--remove` לוקחות אסימונים קומפקטיים של `slug:action.action` כאשר פעולות מנוקדות מתרחבות. ראו [מפתחות והרשאות](/he/admin/keys-and-permissions).

| פועל | הרשאה | הערות |
| --- | --- | --- |
| `fp users list` / `show` | `users:read` | `--active-only` מסתיר חברים משבתים. |
| `fp users create` | `users:create` | `--permission-set` זורע את התפקיד; `--add` / `--remove` שכבות עדכונים. |
| `fp users update` | `users:update` | `--permission-set` **מחליף** את העדכונים לכל חבר של החבר; `--add` / `--remove` בלבד הם הדרגתיים כנגד ההענקות הנוכחיות שלהם. |
| `fp users disable` / `enable` | `users:delete` | שניהם, כולל הפעלה — הענקו זאת בכוונה. |

השבתה דוחה שני מקרים במפורש, כשגיאה Forbidden ולא כהודעת אימות: חבר **protected** לא יכול להיות משבת, ולא תוכלו להשבית את חשבון שלכם. השבתת חבר כבר משבת, או הפעלה של אחד כבר פעיל, היא no-op שקט. ה-API משתמש בפעולת מחיקה להשבתה, אך היא לא מסירה את החשבון ולא את רשומת החברות שלו.

שני הגדרות ארגוניות שולטות בחברות: `default_user_permissions` בחרות מראש את סט ההרשאות עבור הזמנה חדשה, ו-`allowed_sign_ins` שערים אילו כתובות יכולות לקבל קוד כניסה בכלל. נהלו אותם מ[דף ההגדרות](/he/admin/settings-and-security).

<Warning>
  השבתת משתמש חוסמת את הזהות הזו מכניסה לכל ארגון, לא רק לארגון שנבחר כרגע. הפעלה מחדש משחזרת כניסה גלובלית והרשאות החבר בארגון זה.
</Warning>

<Tip>
  תן לחשבונות שירות שמות תיאוריים קשורים לעומס עבודה ובעלים. אל תשתפו מפתח בין ארגונים, או בין אדם למכונה.
</Tip>
