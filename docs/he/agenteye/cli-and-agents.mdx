כל פריסת Failproof AI Observability שלך, בפקודה אחת בלבד. בדוק את הייצור, צור מפתח API, או אשר תקרית מבלי לעזוב את הטרמינל שלך, ואז כתוב סקריפט עבור כל זה ל-CI, או תן לסוכן קוד לעשות זאת עבורך בשפה טבעית.

```bash
pipx install agenteye
agenteye login --email you@example.com      # a 6-digit code lands in your inbox
agenteye --json sessions --since 24h         # every agent run from the last day, newest first
```

*ה-`agenteye` CLI מתדבר עם הדשבורד שלך. זוהי כלי שונה מהמאסף, שמעביר אירועים לשרת.*

## כל הפריסה שלך, בפקודה אחת בלבד

הפסק לקפוץ בין כרטיסיות כדי לענות על שאלה מהירה. ה-`agenteye` CLI קורא את הנתונים שלך וניהול את הארגון שלך מבינארי יחיד, כך שבדיקה שהייתה פירושה ללחוץ דרך הדשבורד הופכת לשורה אחת שאתה יכול להריץ מחדש, ליצור כינוי לה, או להדביק לתוך runbook. אתה מקבל ארבע משטחים:

- **קרא את הנתונים שלך:** `sessions`, `events`, `evals`, ו-`errors`, מסוננים לפי זמן, סוכן וסביבה.
- **נהל את הארגון שלך:** `keys`, `users`, `settings`, `alerts`, ו-`incidents`.
- **הרץ אנליטיקה:** SQL שמור בתוספת `query` runner ad-hoc על נתוני האירועים שלך.
- **שאל את העוזר:** `agent ask` מגיע לאותו אנליסט קריאה בלבד שאתה משוחח איתו בדשבורד.

התקן את זה פעם אחת עם `pipx`, היכנס עם קוד 6-ספרתי שנשלח בדוא"ל, והוא מוכן. ההפעלה נמשכת כחצי יום; הרץ מחדש את `agenteye login` כאשר היא תפוג. השתמש בו כדי לבדוק את הייצור, לספק מפתח, או לבצע בדיקה של תקרית שנורה, הכל מבלי לפתוח דפדפן:

```bash
agenteye errors --since 24h --aggregate      # what is breaking, grouped by error type
agenteye incidents list --state firing       # what is on fire right now
agenteye keys create ci --add events:add     # a key that can only push events, secret shown once
```

הרגל אחד שחשוב לדעת: אפשרויות גלובליות כמו `--json` מופיעות לפני הפקודה. `agenteye --json sessions` נכון; `agenteye sessions --json` לא.

## כתוב סקריפט שלו, חבר אותו ל-CI

כל פקודה מקבלת `--json`, וזה משנה הכל. JSON נקי הולך ל-stdout בעוד מצב אנושי והתראות הולכות ל-stderr, כך שתופסת `--json` מעבירה ישר ל-`jq` ללא שורה תועה לבדוק. זו הסיבה שה-CLI טוב באותה מידה עבורך בהנמקה וגם עבור סוכן קוד שמנתח פלט:

```bash
agenteye --json sessions --since 24h --status error | jq -r '.sessions[].session_id'
```

זה בנוי כדי להריץ ללא פיקוח. הנחיות אישור מדלגות אוטומטית כאשר אין טרמינל מצורף, כך שכלום לא תלוי בצינור, וכל פקודה מחזירה קוד יציאה משמעותי: `0` הצלחה, `4` לא מחובר, `5` הרשאה חסרה (ההודעה קוראת לה, לדוגמה `alerts:write`), `3` הדשבורד בלתי נגיש. סקריפט יכול להתפצל על `4` כדי להחזיר הסכמה או על `5` כדי לומר לך בדיוק למה לבקש ממנהל, במקום להיכשל בעיוורון.

## תן לסוכן קוד לנהוג בו בשפה טבעית

אפילו יותר טוב, לא צריך לזכור את כל הדגלים האלה בכלל. **ה-CLI skill** היא תיקייה קטנה של Agent Skill בשם `agenteye-cli` שמלמדת סוכן קוד כגון Claude Code או Codex לנהוג ב-CLI מבקשות בשפה טבעית. שאל "האם משהו התקלקל היום?" והסוכן בוחר את הפקודה, מריץ אותה כמוך, והופע בפרוזה.

עבור Claude Code, שחרר את תיקיית `agenteye-cli` ל-`~/.claude/skills/` והוא בגילוי אוטומטי. Failproof AI Observability מספק את התיקייה; אין שום דבר נוסף להתקיל, משום שזה רק נוהג ב-CLI שכבר התקנת. היכנס בעצמך תחילה: ה-skill לא יכול להשלים את ההתחברות של הקוד הנשלח בדוא"ל עבורך.

מכיוון שהסוכן מריץ את ה-CLI כמוך, הוא יכול לעשות הכל שההרשאה שלך מאפשרת, קריאה וכתיבה כאחד: ליצור מפתחות, לשנות הגדרות, לפתור תקריות. הנחיית "האם אתה בטוח?" של ה-CLI לא כוללת סוכן, כך שה-skill כתוב כדי להצהיר על הפקודה המדויקת וחכות להסכמתך לפני כל שינוי. אתה שלב האישור.

```text
you    Why did session run-001 fail?

agent  Running: agenteye --json events --session-id run-001 --all
       The checkout-agent hit a TimeoutError on its third tool call.
```

הקריאות נשארות מיידיות, וכל כתיבה מעצרת עבורך:

```text
you    Give CI a key that can only push events.

agent  This creates an API key. I'll run:
         agenteye keys create ci --add events:add
       OK to proceed?

you    yes

agent  Done. Key "ci" created with events:add only. The secret is shown once, so store it now.
```
