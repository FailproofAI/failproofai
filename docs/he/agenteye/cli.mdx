הנע את כל Failproof AI Observability מהטרמינל או מסקריפט: ללא חזרות לדוח הבקרה. ה-CLI של `agenteye` משאל את הנתונים שלך (sessions, event logs, evaluations) ומנהל את הארגון שלך (API keys, users, settings, alerts, incidents, saved queries), אז פנה אליו כאשר אתה רוצה להפעיל אימות אוטומטי, לחבר Observability ל-CI, או להניח לסוכן קוד לבדוק את הייצור. כל פקודה תומכת בדגל `--json`, כך שהיא עובדת באותה מידה טובה עבורך בזמן הקלדה או עבור סוכן קוד (Claude Code, Cursor) המפעיל וניתח את התוצאה.

עם בינרי אחד אתה יכול:

- **לקרוא את הנתונים שלך**: `sessions`, `events`, `evals`, `errors` (סנן לפי זמן, סוכן, env, ניקוד).
- **לנהל את הארגון שלך**: `keys`, `users`, `settings`, `alerts`, `incidents`.
- **להריץ ניתוח**: SQL שמור וסוכן שואל query אד-הוק (`query`).
- **לשאול את עוזר ה-AI**: אותו אנליסט לקריאה בלבד שאתה משוחח איתו בדוח הבקרה (`agent`).

> **הערה:** זהו ה-CLI של `agenteye`, כלי שונה מה-daemon של הקולט (`agenteye-collector`). ה-CLI מדבר עם דוח הבקרה שלך; הקולט משדר אירועים לשרת.

## התחלה מהירה

מכלום לתוצאה הראשונה שלך בארבע שורות. הצבע את ה-CLI לדוח הבקרה שלך, התחבר, אשר מי אתה, ואז משוך את היום האחרון של ריצות:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # emailed 6-digit code
agenteye whoami                                                                  # confirm user + active org
agenteye --json sessions --since 24h                                             # one row per agent run, last 24h
```

הפקודה האחרונה הזו מדפיסה אובייקט JSON של ה-sessions האחרונים (החדשים ביותר ראשונים, מוגבל ל-50 כברירת מחדל). צרור אותו אל `jq` כדי לחתוך אותו, או הסר `--json` עבור טבלה מתופסת וצבעונית. כל שורה נושאת את סטטוס הריצה וקצר, אם מעריך קלע אותה, ניקודות המדד שלה (מקוצרת כאן):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

שאר הדף מסביר כל חלק: [התקנה](#installation) בבידוד, [התחברות](#authentication), [תצורה](#configuration), [הקונוונציות הגלובליות](#global-options--conventions) שכל פקודה חולקת, ו-[אסמכתא פקודה מלאה](#command-reference).

## התקנה

ה-CLI הוא חבילה ציבורית של PyPI בשם **`agenteye`**. התקן אותה בסביבה מבודדת כך שתמיד יש לה תלויות משלה:

```bash
pipx install agenteye
# or
uv tool install agenteye
```

זה דורש Python 3.10+. הפקודה המותקנת היא **`agenteye`**:

```bash
agenteye --version
agenteye --help
```

> **הערה:** ה-Python SDK של Failproof AI Observability משתמש גם בשם ההפצה `agenteye`. התקנת ה-CLI עם `pipx` או `uv tool` (במקום `pip install` לסביבה וירטואלית משותפת) מונעת את ההתנגשות בין השניים. `pip install agenteye` פשוט בסדר רק אם ה-SDK אינו מותקן באותה סביבה.

## הכרות עם הזהות

ה-CLI מוצא עצמו בדוח הבקרה עם קוד חד-פעמי בדוא"ל:

```bash
agenteye login --email you@example.com
# A 6-digit code is emailed to you; paste it at the prompt.
```

אסימון הסשן מאוחסן ב-`~/.agenteye/cli.json` (ניתן קריאה רק על ידי אתה, mode `0600`) וחוקי עד 24 שעות כברירת מחדל. כשפג תוקו, הפעל את `agenteye login` שוב.

```bash
agenteye whoami     # show the current user, active org, and permissions
agenteye logout     # revoke the session and clear the stored token
```

`whoami` לא משגה עם סשן חסר או פג תוקו; זה מדווח במקום `logged_in: false`, כך שסקריפט או סוכן יכול לחקור את מצב ההכרות בבטחה (זה עדיין יכול לצאת משום דבר שאינו אפס אם אין קביעת URL בסיס או דוח הבקרה אינו ניתן להשג).

**דרישות:** האימייל שלך חייב להיות מורשה להתחבר לדוח הבקרה (שאל את מנהל ה-Failproof AI Observability), ודוח הבקרה חייב להיות ניתן להשג בכתובת ה-URL הבסיסית שלו (ראה [תצורה](#configuration)). אם אתה מבקש קוד וחלקו לא מגיע, סביר להניח שהאימייל שלך עדיין לא מופעל לגישה לדוח הבקרה.

## בחירת הארגון שלך (multi-tenant)

אם החשבון שלך משייך ליותר מארגון אחד, בחר את הפעיל **בזמן ההתחברות**; הוא נשמר ומשמש לכל פקודה מאוחרת יותר:

```bash
agenteye login --org acme           # authenticate and set the active tenant in one step
agenteye orgs list                  # the orgs you can access (the active one is marked)
agenteye orgs switch globex         # change the saved default
agenteye --org globex sessions      # override for a single command
```

אם אתה משייך בדיוק לארגון אחד הוא נבחר באופן אוטומטי ואתה יכול להתעלם לגמרי מ-`--org`. אם אתה משייך למספר ואתה לא בוחר אחד, ה-CLI מתייג אותם ושואל אותך להפעיל מחדש עם `--org <slug>`. הארגון הפעיל נשלח לדוח הבקרה בכל בקשה, וההרשאות שלך נפתרות **לכל ארגון**; `agenteye whoami` מציג את הארגון הפעיל, ההרשאות שלך בו, וכל החברויות שלך.

## תצורה

| הגדרה | דגל | משתנה סביבה | ברירת מחדל |
|---|---|---|---|
| Dashboard base URL | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **required** (no default) |
| Active org/tenant | `--org` | `AGENTEYE_ORG` | chosen at login; saved in `~/.agenteye/cli.json` |
| Session token | `--token` | `AGENTEYE_CLI_TOKEN` | from `~/.agenteye/cli.json` |
| JSON output | `--json` | `AGENTEYE_CLI_JSON` | off |
| Skip TLS verification | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | off (saved at login) |
| Request timeout (seconds) | `--timeout` | _(none)_ | 30 |
| Disable usage telemetry | _(none)_ | `AGENTEYE_ANALYTICS_DISABLED` (or `DO_NOT_TRACK`) | telemetry is currently disabled; nothing is sent |

סדר ההחלטה הוא **flag → environment variable → config file**. אין ברירת מחדל; עליך להצביע על ה-CLI לדוח הבקרה שלך, או לכל פקודה (`--base-url https://agenteye.example.com`) או פעם דרך הסביבה (היא נשמרת גם אחרי ה-`login` הראשון שלך):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

ספריית התצורה מכבדת את `AGENTEYE_HOME` (אותה קונוונציה המשמשת את ה-SDK והקולט); אם הוא מוגדר, `cli.json` חי ב-`$AGENTEYE_HOME/cli.json`.

### TLS חתום עצמי או פנימי

אם דוח הבקרה שלך מוגש ב-HTTPS עם תעודה חתומה עצמית או פנימית (לדוגמה, שם מארח load-balancer גולמי), אימות TLS דוחה אותו עם שגיאת `CERTIFICATE_VERIFY_FAILED`. העבור `--insecure` כדי לדלג על אימות תעודה:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` הוא **שמור ל-`cli.json` כשאתה מתחבר**, כך שפקודות מאוחרות יותר דלג על אימות באופן אוטומטי; אתה לא צריך לחזור על הדגל. העבור `--secure` לשיחה מאומתת חד-פעמית, או כדי לשמור את האימות בחזרה בהתחברות הבאה שלך. ה-CLI מדפיס אזהרה ל-stderr לפני כל פקודה שיוצרת קשר עם דוח הבקרה בעוד שאימות כבוי. דילוג על אימות מסיר הגנה נגד התקפות איש-בתוך-האמצע; ודא שאתה סומך על הנתיב של הרשת לדוח הבקרה שלך (VPN, תת-רשת פרטית וכו') לפני שתסתמך עליו.

## טלמטריה והגנת פרטיות

> **הערה:** ה-CLI המשדר **אינו שולח טלמטריה שימוש היום.** מתג ההשמדה הגלוני כבוי, כך שלא משדרים כלום ללא קשר לסביבתך. הסעיף למטה מתאר את יכולת ההסתגדרות אם ומתי טלמטריה אי-פעם מופעלת.

גם כשמופעלת, הטלמטריה תהיה **ניתוח שימוש אנונימי בלבד**, לעולם לא הסוכן, הסשן או נתוני האירוע שלך:

- **לא סוכן, סשן או נתוני אירוע שלך אי-פעם משאיר את התשתית שלך.** רק שימוש ב-CLI היה מדווח: שם הפקודה והתת-פקודה (למשל `keys create`), **שמות** הדגלים שהשתמשת בהם (לעולם לא הערכים שלהם), סטטוס הצלחה/יציאה ומשך זמן, בתוספת אירוע לכל פעולה עבור מוטציות (למשל `api_key_created`, `query_run`) נושאת רק שמות/enums סטטיים וספירות גסות. כתובת ה-URL של דוח הבקרה, אסימון סשן, דוא"ל, slug ארגון, מזהי משאב, SQL, סודות מפתח וסינוני query לא יימשדרו **לעולם**. מפעילים היו מזוהים רק על ידי מזהה פנימי אטום, לא על ידי דוא"ל.
- **הסתגדר מראש** על ידי הגדרת `AGENTEYE_ANALYTICS_DISABLED=1` בסביבה של ה-CLI (ה-CLI גם מכבד את הקונוונציה החוצה-כלית `DO_NOT_TRACK=1`). זה יחול ברגע שטלמטריה מופעלת אי-פעם, כך שסביבה פנימית מודעת לפרטיות יכולה להישאר מוסתרת באופן קבוע.
- אם טלמטריה הייתה מופעלת, ה-CLI היה שולח ישירות ל-PostHog (`https://us.i.posthog.com`); מכונה עם אותו מארח חסום היתה שותקת ולא שולחת כלום וה-CLI לא היה מושפע.

## אפשרויות גלובליות וקונוונציות

קרא את זה פעם אחת; זה חל על כל פקודה.

- **אפשרויות גלובליות הולכות לפני הפקודה.** `agenteye --json sessions` נכון; `agenteye sessions --json` היא שגיאת שימוש. הגלובליים הם `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet` וגם `--no-color`.
- **`--json` מדפיס JSON טהור ל-stdout, ותו לא.** שורות סטטוס אנושי, אזהרות וטעויות הולכות ל-**stderr**, כך שלקיחת stdout של `--json` נשארת נקייה לצינור אל `jq` גם כשמוצגת שורת סטטוס. ללא `--json` אתה מקבל תצוגה מתופסת וצבעונית עבור עיני אנושות.
- **גלה עם `--help`.** לכל פקודה ותת-פקודה יש `--help` (והכינוי `-h`): `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`. העזרה ברמה העליונה מתייגת גם את קודי היציאה והאפשרויות הגלובליות. אין חילול משטח קריא-מכונה גלובאלי; השתמש ב-`--help` לכל פקודה, בתוספת ה-`agenteye query schema` וה-`agenteye settings schema` הספציפיים לתחום לשני הרגיסטים הללו.
- **אישורים דילוגים אוטומטיים לסקריפטים וסוכנים.** צור/עדכן/מחק פקודות מודח "האם אתה בטוח?" בטרמינל אינטראקטיבי, אך **דלג אוטומטי על הבקשה תחת `--json` או בכל פעם שstdin אינו TTY** (TTY היא סשן טרמינל אינטראקטיבי; צינור או רץ CI אינו כך), כך שסקריפטים וסוכנים לעולם לא קופאים. העבור `--yes`/`-y` כדי לדלג עליו בשמירות. כי הבקשה לא תירה לסוכן, סוכן צריך לאשר פעולות הרסניות עם האדם תחילה.
- **דפדוף:** תוצאות חדשות תחילה ודפדוף שמור על גבול (כל עמוד מחזיר אסימון שבו אתה משתמש כדי להביא את הבא). `--limit N` (כינוי `-n`) מקודד שורות ו-**ברירות מחדל ל-50**; `--all` משדרות אוטומטית (בקטעים של 200 שורות) **עד `--limit`**, כך שחשמל `--all` עדיין עוצר ב-50. עבור סוויפ מלא העבור cap גבוה מפורש: `--all --limit 1000`. `--page-size N` שולטת בקטע לכל בקשה (max 200); `--cursor <id>` חוזר מה-`next_cursor` של דף קודם.
- **סינוני זמן:** `--since` לוקח חלון יחסי: `15m`, `1h`, `6h`, `24h`, `7d`, או `all` (הנוכחי של דוח הבקרה). עבור טווח ארוך יותר או מותאם אישית (למשל 30 הימים האחרונים), השתמש ב-`--from`/`--to`: זמני חותמות UTF-8 מפורשים **עם `T` ו-timezone** (למשל `2026-06-01T00:00:00Z`) שחוקק `--since`. ערך מופרד מחלל או ללא timezone הוא שגיאת שימוש.
- **`--fields a,b,c`** (על `events`, `sessions`, `evals`, `errors`) מגביל את הפלט לאותם מפתחות, עבור הטבלה וה-`--json`. שמות לא ידועים דחויים עם הרשימה החוקית, דרך זולה לגלות שמות שדות.
- **`--file payload.json`** (או `--file -` קרא stdin) מסדר גוף בקשת JSON מלא שבו משאב בעל צורה מורכבת (על `alerts create/update`, `settings set` וגם `users create/update`). SQL שמור שימוש `--sql @file.sql` במקום.
- **סינני רב-ערך** הם פסיקים-מופרדים → תואמים כקבוצה (איחוד בתוך סינן אחד, AND על פני סינונים): `--event-type tool_use,tool_result`. אפשרויות לחיצה אינן variadic, כך ש-`--add a b` שובר. השתמש ב-`--add a,b`, חזור על הדגל (`--add a --add b`), או צטט (`--add "a b"`).

## אסמכתא פקודה

### אתה תשתמש ב-5 הפקודות הללו בעיקר

רוב העבודה היומית עובדת דרך קומץ של פקודות קריאה. התחל כאן, ואז פנה לפני ה-surface המלא למטה כשאתה צריך את זה:

| פקודה | מה היא עושה | נסה את זה |
|---|---|---|
| `sessions` | שורה אחת לכל ריצת סוכן: זמן, env, סוכן, סטטוס, ניקוד אחרון. | `agenteye --json sessions --since 24h --status error` |
| `events` | שביל גולמי לכל שלב בתוך ריצה (הוסף `--full` עבור payload). | `agenteye --json events --session-id run-001 --all` |
| `evals` | תוצאות הערכה וניקודות; `--aggregate` משדרות אותם. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | רק אירועים שגויים; `--aggregate` לספירות לפי סוג. | `agenteye --json errors --since 24h --aggregate` |
| `list` | גלה את ערכי הסינון החוקיים (סוכנים, envs, דגמים, …). | `agenteye list agents` |

### הכל שה-CLI יכול לעשות

ה-surface המלא עוקב. ל-CLI יש **18 פקודות ברמה עליונה**. כל פקודות קריאה מקבלות `--json` והאפשרויות הגלובליות לעיל; הפעל `agenteye <command> -h` (או `<command> <subcommand> -h`) עבור רשימת הדגל ממצה וצורת JSON של כל אחת.

### זהות: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # emailed one-time code; saves the session
agenteye logout                                       # clear the saved session on this machine
agenteye whoami                                       # current user, active org, permissions
agenteye version                                      # print the CLI version (same as --version)
agenteye help                                         # top-level help (same as --help)
```

`orgs` בודק ומחליף את ה-tenant הפעיל:

```bash
agenteye orgs list        # your orgs + your role in each (active one marked)
agenteye orgs switch acme # change the saved active org (omit the slug to pick from a list on a TTY)
agenteye orgs current     # identity card for the active org
agenteye orgs perms       # your permissions in the active org, grouped by resource
```

### צפה (קריאה בלבד): `events` · `sessions` · `evals` · `errors` · `list`

אף אחד מאלה לא צריך אישור. סינונים משותפים: `--session-id`, `--agent-id`, `--env` (**not** `--environment`), וטווח הזמן (`--since` / `--from` / `--to`).

```bash
# events (alias: the raw per-step trail), newest first
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: one row per agent run (time/env/agent/session/status; no score filtering)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: evaluation results + scores; --score filters by metric, --aggregate rolls up
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # status mix + per-key score stats

# errors: errored events; --aggregate for counts/sessions/agents/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: discover valid filter values before you filter
agenteye list envs        # also: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (על **`evals`**, לא `sessions`) חוזר ו-AND-משולבות; כל קשור הוא אופציונאלי (`..0.5` פירושו ≤ 0.5, `0.9..` פירושו ≥ 0.9). עד 20 סינני ניקוד לכל בקשה. `evals --scores-full` היא דגל תצוגה לטבלה **אנושית בלבד**; הוא מציג כל זוג ניקוד במקום הראשון כמה בתוספת ספירת `+N`. אין השפעה תחת `--json`, השוב תמיד מחזיר את אובייקט הניקוד המלא. לקריאה **סשן אחד מקצה לקצה**, שלב את שביל האירוע שלו עם ההערכה שלו:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # its scores + status
```

### ניהול (permission-gated): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: API keys. הסוד נוצר מקומי, שלח לשרת (השוקל רק a hash), ו-**מוצג פעם אחת** על יצירה/רגנרציה; תופס אותו אז. עם `--json` זה מופיע רק בשדה `key`. מועמד לפי **שם**.

```bash
agenteye keys list                                   # active keys first, then revoked
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # scope to what you need; prints the secret ONCE
agenteye keys create ops --permission-set standard --remove queries:run   # seed a preset, then trim
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rotate the secret (the old one stops working)
agenteye keys disable ci-bot --yes                   # revoke
```

הרשאות עבודה כמו `(permission-set ∪ --add) − --remove`. אסימונים הם `slug:action` (למשל `events:read`) או `slug:action.action` להרחבת כמה על משאב אחד (`events:read.add` → `events:read`, `events:add`). נוכחי: `read-only`, `standard`, `admin`. הרשאות קרובות בלבד אנוש (`keys:update`) לא יכולות להיות מוענקות למפתח.

**`users`**: חברי ארגון, מועמדים לפי **אימייל** (מזהה UUID מקובל גם).

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predicts + confirms
agenteye users disable dev@corp.com --yes            # has protected/self guards
agenteye users enable dev@corp.com
```

**`settings`**: רישום קבוע (קרא ושנה מפתחות קיימים; אתה לא יכול ליצור חדשים).

```bash
agenteye settings list                               # key · value · type · updated (secrets masked)
agenteye settings schema                             # what each key accepts (type · range · description)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: הגדרות התראה, מועמדות לפי **שם**. `create` לוקח NAME פוזיציוני בתוספת דגלים או גוף JSON מלא דרך `--file`.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME is required (positional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # fire a test notification
agenteye alerts delete high-errors --yes
```

**`incidents`**: התראה אירועים, מועמדות לפי id (מזהים קצרים מקובל). `show` מדפיס את יומן הפעילות המלא; קרא אותו לפני ש-פועל.

```bash
agenteye incidents list --state firing                # also: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assignee must be an operator
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # open one manually against an alert
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### ניתוח וסוכן: `query` · `agent`

**`query`**: SQL שמור נגד חנות ניתוח שלך בתוספת סוכן ad-hoc. שמור queries מועמדות לפי **שם**; ה-SQL מאומת ממש על ידי שרת (בחירה/עם רק, timeout הצהרה, cap שורה).

```bash
agenteye query schema [TABLE]                         # column layout of the analytics views
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # run a saved query + a positional $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: מדברת ל-**עוזר AI** המובנה (אותו אנליסט לקריאה בלבד שאתה יכול לשוחח איתו בדוח הבקרה). צ'אטים מועמדות לפי chat-id קצר (פתור קדימה).

```bash
agenteye agent health                                 # is the AI assistant configured/reachable
agenteye agent models                                 # models you can pass to --model (default marked)
agenteye agent ask "which agents errored most in the last day?"    # starts a chat; prints its short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continue that chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## קודי יציאה

| קוד | משמעות |
|---|---|
| 0 | הצלחה |
| 1 | שגיאה בלתי צפויה (למשל דוח הבקרה החזיר 5xx) |
| 2 | שגיאת שימוש (טיעונים לא חוקיים, פקודה/דגל לא ידוע, התנגשות שם) |
| 3 | לא יכול להגיע לדוח הבקרה |
| 4 | לא מתחבר או סשן פג; הפעל `agenteye login` |
| 5 | מחובר, אך החשבון שלך חסר ההרשאה הנדרשת (ההודעה שם זה) |
| 6 | המשאב המבוקש לא נמצא (למשל session או incident id לא ידוע) |

אלה עושים את ה-CLI בטוח לסקריפט: סוכן קוד יכול להתפצל בחזקת `4` כדי להנחות אותך להתחבר מחדש, או `5` כדי להשטח את ההרשאה החסרה. ראה [CLI recipes for agents](/he/agenteye/cli-recipes) עבור דפוסי exit-code-handling וצורות פלט JSON.
