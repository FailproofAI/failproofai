נהל את כל Failproof AI Observability מהטרמינל או מסקריפט: ללא התחברות לדשבורד. CLI ה-`agenteye` שואל על הנתונים שלך (sessions, event logs, evaluations) ומנהל את הארגון שלך (API keys, users, settings, alerts, incidents, saved queries), אז השתמש בו כאשר אתה רוצה להפעיל בדיקה אוטומטית, לחבר Observability ל-CI, או לתת לסוכן קוד לבדוק production. כל פקודה תומכת בדגל `--json`, כך שהיא עובדת בהחלט גם בשביל אתה בשורת הפקודה וגם בשביל סוכן קוד (Claude Code, Cursor) שמפעיל קליפה וניתח את התוצאה.

עם בינרי אחד תוכל:

- **קרא את הנתונים שלך**: `sessions`, `events`, `evals`, `errors` (סנן לפי זמן, סוכן, env, ציון).
- **נהל את הארגון שלך**: `keys`, `users`, `settings`, `alerts`, `incidents`.
- **הרץ ניתוח**: SQL שמור וריצה ad-hoc queries (`query`).
- **שאל את העוזר AI**: אותו אנליסט read-only שאתה משוחח איתו בדשבורד (`agent`).

> **הערה:** זה ה-CLI `agenteye`, כלי שונה מה-daemon של collector (`agenteye-collector`). ה-CLI מדבר עם הדשבורד שלך; ה-collector שולח events לשרת.

## Quickstart

מ-0 לתוצאה הראשונה שלך בארבע שורות. הצבע את ה-CLI לדשבורד שלך, התחבר, אשר מי אתה, ואחר כך משוך את הריצות של היום האחרון:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # emailed 6-digit code
agenteye whoami                                                                  # confirm user + active org
agenteye --json sessions --since 24h                                             # one row per agent run, last 24h
```

הפקודה האחרונה הדפסה JSON object של ה-sessions האחרונים (החדש ביותר קודם, מוגבל ל-50 כברירת מחדל). צנור אותו ל-`jq` כדי לחתוך אותו, או הוריד את `--json` לטבלה מוגן וצבעונית. כל שורה נושאת את סטטוס הריצה וההערות שלה, ואם מעריך הערך שלו, את ציוני המדד שלו (מקוצרים כאן):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

שאר הדף מסביר כל חלק: [התקנה](#installation) בבידוד, [התחברות](#authentication), [הגדרה](#configuration), ה-[יחידות גלובליות](#global-options--conventions) שכל פקודה חולקת, ו[ה-command reference המלא](#command-reference).

## Installation

ה-CLI הוא חבילת PyPI ציבורית בשם **`agenteye`**. התקן אותה בסביבה מבודדת כדי שתמיד יהיו לה התלויות שלה:

```bash
pipx install agenteye
# or
uv tool install agenteye
```

זה דורש Python 3.10+. הפקודה המותקנת היא **`agenteye`**:

```bash
agenteye --version
agenteye --help
```

> **הערה:** Python SDK של Failproof AI Observability משתמש גם בשם הפצה `agenteye`. התקנת ה-CLI עם `pipx` או `uv tool` (במקום `pip install` ל-virtualenv משותף) מונעת שניהם להתנגש. `pip install agenteye` רגיל בסדר רק אם ה-SDK לא מותקן באותה סביבה.

## Authentication

ה-CLI מתחבר ל-**dashboard** עם קוד חד-פעמי באימייל:

```bash
agenteye login --email you@example.com
# A 6-digit code is emailed to you; paste it at the prompt.
```

טוקן ה-session מאוחסן ב-`~/.agenteye/cli.json` (קריא רק לך, mode `0600`) והוא חוקי 24 שעות כברירת מחדל. כאשר הוא פג, הרץ `agenteye login` שוב.

```bash
agenteye whoami     # show the current user, active org, and permissions
agenteye logout     # revoke the session and clear the stored token
```

`whoami` לעולם לא שגיאות בـ session חסר או פג; הוא דיווח `logged_in: false` במקום זאת, אז סקריפט או סוכן יכול לחקור באופן בטוח את מצב הזקיפויות (הוא עדיין יכול לצאת non-zero אם לא מוגדר base URL או אי-אפשר להגיע לדשבורד).

**דרישות:** האימייל שלך חייב להיות בעל הרשאה להתחבר לדשבורד (שאל את מנהל ה-Failproof AI Observability שלך), והדשבורד חייב להיות מגיע בכתובת ה-base URL שלו (ראה [Configuration](#configuration)). אם אתה מבקש קוד ואף אחד לא מגיע, האימייל שלך כנראה עדיין לא מופעל עבור גישה לדשבורד.

## בחירת הארגון שלך (multi-tenant)

אם החשבון שלך שייך ליותר מארגון אחד, בחר את הפעיל **בעת התחברות**; הוא שמור וב-use לכל פקודה מאוחרת יותר:

```bash
agenteye login --org acme           # authenticate and set the active tenant in one step
agenteye orgs list                  # the orgs you can access (the active one is marked)
agenteye orgs switch globex         # change the saved default
agenteye --org globex sessions      # override for a single command
```

אם אתה שייך בדיוק לארגון אחד הוא נבחר באופן אוטומטי ותוכל להתעלם מ-`--org` לחלוטין. אם אתה שייך לכמה ולא בחרת באחד, ה-CLI מפרט אותם וביקש מך להריץ מחדש עם `--org <slug>`. הארגון הפעיל נשלח לדשבורד בכל בקשה, וההרשאות שלך מוחלות **לפי ארגון**; `agenteye whoami` מציג את הארגון הפעיל, את ההרשאות שלך בו, וכל החברויות שלך.

## Configuration

| Setting | Flag | Environment variable | Default |
|---|---|---|---|
| Dashboard base URL | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **required** (no default) |
| Active org/tenant | `--org` | `AGENTEYE_ORG` | chosen at login; saved in `~/.agenteye/cli.json` |
| Session token | `--token` | `AGENTEYE_CLI_TOKEN` | from `~/.agenteye/cli.json` |
| JSON output | `--json` | `AGENTEYE_CLI_JSON` | off |
| Skip TLS verification | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | off (saved at login) |
| Request timeout (seconds) | `--timeout` | _(none)_ | 30 |
| Disable usage telemetry | _(none)_ | `AGENTEYE_ANALYTICS_DISABLED` (or `DO_NOT_TRACK`) | telemetry is currently disabled; nothing is sent |

סדר הרזולוציה הוא **flag → environment variable → config file**. אין ברירת מחדל; עליך להצביע על ה-CLI לדשבורד שלך, או לכל פקודה (`--base-url https://agenteye.example.com`) או פעם דרך ה-environment (הוא גם שמור לאחר ה-`login` הראשון שלך):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

ספריית ה-configuration מכבדת את `AGENTEYE_HOME` (אותו כלל המשמש את SDK וה-collector); אם מוגדר, `cli.json` גר ב-`$AGENTEYE_HOME/cli.json`.

### Self-signed או פנימי TLS

אם הדשבורד שלך מוגש דרך HTTPS עם תעודה self-signed או פנימית (לדוגמה, שם מארח load-balancer גולמי), אימות TLS דוחה אותה עם שגיאת `CERTIFICATE_VERIFY_FAILED`. העבור `--insecure` כדי לדלג על אימות תעודה:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` **נשמר ל-`cli.json` כאשר אתה מתחבר**, אז פקודות מאוחרות יותר דולגות על אימות באופן אוטומטי; אתה לא צריך לחזור על הדגל. העבור `--secure` לשיחה מאומתת חד-פעמית, או כדי לשמור על אימות חזרה בעת ה-login הבא שלך. ה-CLI מדפיס אזהרה ל-stderr לפני כל פקודה שיוצרת קשר לדשבורד בזמן שאימות מבוטל. דילוג על אימות מסיר הגנה נגד התקפות man-in-the-middle; ודא שאתה סומך על נתיב הרשת לדשבורד שלך (VPN, private subnet, וכו') לפני הסתמכות עליו.

## Telemetry & privacy

> **הערה:** ה-CLI המשוגר שלח **אין telemetry שימוש היום.** קטל-switch master נמצא בהפעלה, ולכן שום דבר לא מועבר ללא תלות בסביבה שלך. הסעיף להלן מתאר את יכולת ה-opt-out אם וכאשר telemetry אי-פעם מופעלת.

גם כאשר מופעלת, telemetry תהיה **רק analytics שימוש אנונימי**, לעולם לא הסוכן, session, או event שלך:

- **אף סוכן, session, או event data לעולם לא יעזוב את האינפ"ס שלך.** רק שימוש CLI יידווח: שם הפקודה וה-subcommand (למשל `keys create`), **השמות** של הדגלים שהשתמשת בהם (לעולם לא הערכים שלהם), סטטוס הצלחה/יציאה, ומשך הזמן, בתוספת event לפעולה לכל פעולה (למשל `api_key_created`, `query_run`) הנושאת רק שמות סטטיים/enums וספירות גסות. כתובת הדשבורד שלך, session token, אימייל, org slug, resource ids, SQL, key secrets, וסינוני שאילתה **לעולם** לא יישלחו. מפעילים יזוהו רק לפי id פנימי אטום, לעולם לא לפי אימייל.
- **Opt out ahead of time** על ידי הגדרה `AGENTEYE_ANALYTICS_DISABLED=1` בסביבה של ה-CLI (ה-CLI גם מכבד את כלל ה-cross-tool `DO_NOT_TRACK=1`). זה נכנס לתוקף ברגע שה-telemetry כשמופעלת, אז סביבה שמודעת לפרטיות יכולה להישמר opted out לצמיתות.
- אם telemetry הייתה מופעלת, ה-CLI ישלח ישירות ל-PostHog (`https://us.i.posthog.com`); מכונה שיש לה את ה-host הזה חסום תשלח בשקט שום דבר וה-CLI לא יושפע.

## Global options & conventions

קרא את זה פעם אחת; הוא חל על כל פקודה.

- **אפשרויות גלובליות הולכות BEFORE הפקודה.** `agenteye --json sessions` נכון; `agenteye sessions --json` היא שגיאת שימוש. הגלובליות הן `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, ו-`--no-color`.
- **`--json` הדפסה JSON טהור ל-stdout, ושום דבר אחר.** שורות סטטוס אדם, אזהרות, ושגיאות הולכות ל-**stderr**, אז `--json` stdout capture נשאר נקי כדי להצנור ל-`jq` גם כאשר שורת סטטוס מוצגת. ללא `--json` אתה מקבל תצוגה מוגנת וצבעונית לעיני אדם.
- **גלה עם `--help`.** לכל פקודה ו-subcommand יש `--help` (ו-`-h` alias): `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`. העזרה ברמה העליונה גם רשומה של קודי היציאה ואפשרויות גלובליות. אין שטח משטח machine-readable גלובלי; השתמש ב-`--help` לכל פקודה, בתוספת ה-`agenteye query schema` וה-`agenteye settings schema` הספציפי לדומיין עבור שתי הרגיסטריות הללו.
- **אישורים auto-skip לסקריפטים וסוכנים.** פקודות Create/update/delete מהפכות "האם אתה בטוח?" בטרמינל אינטראקטיבי, אך **auto-skip את הבקשה בעת `--json` או בכל פעם שלא TTY stdin** (TTY הוא session טרמינל אינטראקטיבי; pipe או CI runner לא), אז סקריפטים וסוכנים לעולם לא תלויים. עבור `--yes`/`-y` כדי לדלג עליה במפורש. מכיוון שהבקשה לא תופעל לסוכן, סוכן צריך לאשר פעולות הרסניות עם האדם קודם.
- **Pagination:** התוצאות הן newest-first ו-cursor-paginated (כל דף מחזיר טוקן בו אתה משתמש כדי להביא את הדף הבא). `--limit N` (alias `-n`) מכסה שורות ו**ברירות מחדל ל-50**; `--all` auto-paginates (בקטעי 200 שורות) **עד `--limit`**, אז `--all` חצוף עדיין עוצר בתוך 50. עבור סחיפה מלאה אשר cap מפורש גבוה: `--all --limit 1000`. `--page-size N` שולט בקטע לכל בקשה (מקס 200); `--cursor <id>` חוזר מ-`next_cursor` של דף קודם.
- **Time filters:** `--since` לוקח חלון יחסי: `15m`, `1h`, `6h`, `24h`, `7d`, או `all` (ה-presets של הדשבורד). לטווח ארוך יותר או מותאם אישית (למשל 30 ימים אחרונים), השתמש ב-`--from`/`--to`: ISO-8601 UTC explicit timestamps **עם `T` ו-timezone** (למשל `2026-06-01T00:00:00Z`) שדורסים את `--since`. ערך מופרד ברווח או ללא timezone היא שגיאת שימוש.
- **`--fields a,b,c`** (על `events`, `sessions`, `evals`, `errors`) מגביל את הפלט לאלה שמפתחים, לשם הטבלה ו-`--json`. שמות לא ידועים נדחות עם רשימה תקפה, דרך זולה לגלות שמות שדות.
- **`--file payload.json`** (או `--file -` לקריאה stdin) מספקת גוף בקשה JSON מלא כאשר משאב יש צורה מורכבת (על `alerts create/update`, `settings set`, ו-`users create/update`). Saved-query SQL משתמש ב-`--sql @file.sql` במקום זאת.
- **Multi-value filters** הם comma-separated → תאימה כערכה (union בתוך filter אחד, AND על פני filters): `--event-type tool_use,tool_result`. אפשרויות Click לא variadic, אז `--add a b` שבור. השתמש ב-`--add a,b`, חזור על הדגל (`--add a --add b`), או ציטוט (`--add "a b"`).

## Command reference

### תשתמש ב-5 פקודות אלה ביותר

עבודה יומיומית רובה דרך קומץ של פקודות קריאה. התחל כאן, ואחר כך הגיע לפני השטח המלא להלן כאשר אתה צריך את זה:

| Command | What it does | Try it |
|---|---|---|
| `sessions` | One row per agent run: time, env, agent, status, latest score. | `agenteye --json sessions --since 24h --status error` |
| `events` | The raw per-step trail inside a run (add `--full` for payloads). | `agenteye --json events --session-id run-001 --all` |
| `evals` | Evaluation results and scores; `--aggregate` rolls them up. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | Just the errored events; `--aggregate` for counts by type. | `agenteye --json errors --since 24h --aggregate` |
| `list` | Discover the valid filter values (agents, envs, models, …). | `agenteye list agents` |

### הכל שה-CLI יכול לעשות

השטח המלא הבא. לה-CLI יש **18 פקודות ברמה העליונה**. כל פקודות הקריאה מקבלות `--json` ואת האפשרויות הגלובליות לעיל; הרץ `agenteye <command> -h` (או `<command> <subcommand> -h`) להקד exhaustive דגל רשימה ו-JSON צורת כל אחד.

### Identity: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # emailed one-time code; saves the session
agenteye logout                                       # clear the saved session on this machine
agenteye whoami                                       # current user, active org, permissions
agenteye version                                      # print the CLI version (same as --version)
agenteye help                                         # top-level help (same as --help)
```

`orgs` תופסים וחליפים את הטנסנט הפעיל:

```bash
agenteye orgs list        # your orgs + your role in each (active one marked)
agenteye orgs switch acme # change the saved active org (omit the slug to pick from a list on a TTY)
agenteye orgs current     # identity card for the active org
agenteye orgs perms       # your permissions in the active org, grouped by resource
```

### Observe (read-only): `events` · `sessions` · `evals` · `errors` · `list`

כל אלה לא צריכים אישור. Shared filters: `--session-id`, `--agent-id`, `--env` (**לא** `--environment`), ו-time range (`--since` / `--from` / `--to`).

```bash
# events (alias: the raw per-step trail), newest first
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: one row per agent run (time/env/agent/session/status; no score filtering)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: evaluation results + scores; --score filters by metric, --aggregate rolls up
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # status mix + per-key score stats

# errors: errored events; --aggregate for counts/sessions/agents/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: discover valid filter values before you filter
agenteye list envs        # also: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (על **`evals`**, לא `sessions`) הוא repeatable ו-AND-combined; כל קשור הוא optional (`..0.5` משמעות ≤ 0.5, `0.9..` משמעות ≥ 0.9). עד 20 score filters לכל בקשה. `evals --scores-full` היא דגל תצוגה ל-**human table בלבד**; הוא מציג כל score זוג במקום הראשון כמה בתוספת `+N` ספר. אין לו השפעה תחת `--json`, המחזיר תמיד את ה-score object השלם. כדי לקרוא **session אחד end-to-end**, חבור את event trail עם ה-evaluation שלו:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # its scores + status
```

### Manage (permission-gated): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: API keys. הסוד נוצר locally, נשלח לשרת (מאחסן רק hash), ו**מוצג פעם אחת** על create/regenerate; לכוד אותו אז. עם `--json` זה מופיע רק בשדה `key`. הערה לפי **name**.

```bash
agenteye keys list                                   # active keys first, then revoked
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # scope to what you need; prints the secret ONCE
agenteye keys create ops --permission-set standard --remove queries:run   # seed a preset, then trim
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rotate the secret (the old one stops working)
agenteye keys disable ci-bot --yes                   # revoke
```

הרשאות עובדות כ-`(permission-set ∪ --add) − --remove`. Tokens הם `slug:action` (למשל `events:read`) או `slug:action.action` כדי להרחיב כמה על משאב אחד (`events:read.add` → `events:read`, `events:add`). Presets: `read-only`, `standard`, `admin`. הרשאות אדם בלבד (`keys:update`) לא יכול להיות מוענק ל-key.

**`users`**: org members, הערה לפי **email** (UUID id גם מתקבל).

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predicts + confirms
agenteye users disable dev@corp.com --yes            # has protected/self guards
agenteye users enable dev@corp.com
```

**`settings`**: רגיסטרי קבוע (אתה קורא ומשנה מפתחות קיימים; אתה לא יכול ליצור חדשים).

```bash
agenteye settings list                               # key · value · type · updated (secrets masked)
agenteye settings schema                             # what each key accepts (type · range · description)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: הגדרות alert, הערה לפי **name**. `create` לוקח positional NAME בתוספת דגלים או גוף JSON מלא דרך `--file`.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME is required (positional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # fire a test notification
agenteye alerts delete high-errors --yes
```

**`incidents`**: alert incidents, הערה לפי id (short ids מקובלת). `show` הדפסה רישום פעילות מלא; קרא את זה לפני הפעלה.

```bash
agenteye incidents list --state firing                # also: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assignee must be an operator
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # open one manually against an alert
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### Analytics & assistant: `query` · `agent`

**`query`**: SQL שמור נגד analytics store שלך בתוספת ריצה ad-hoc. Saved queries הערה לפי **name**; ה-SQL מעודכן בחיזוק server-side (SELECT/WITH בלבד, statement timeout, row cap).

```bash
agenteye query schema [TABLE]                         # column layout of the analytics views
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # run a saved query + a positional $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: דברים ל-**AI assistant** מובנה (אותו אנליסט read-only שאתה יכול לשוחח איתו בדשבורד). Chats הערה לפי short chat-id (prefix-resolved).

```bash
agenteye agent health                                 # is the AI assistant configured/reachable
agenteye agent models                                 # models you can pass to --model (default marked)
agenteye agent ask "which agents errored most in the last day?"    # starts a chat; prints its short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continue that chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | Unexpected error (e.g. the dashboard returned a 5xx) |
| 2 | Usage error (invalid arguments, unknown command/flag, name collision) |
| 3 | Cannot reach the dashboard |
| 4 | Not logged in or session expired; run `agenteye login` |
| 5 | Authenticated, but your account lacks the required permission (the message names it) |
| 6 | The requested resource was not found (e.g. unknown session or incident id) |

אלה עושה את ה-CLI בטוח לתסריט: coding agent יכול to branch על `4` כדי להנחות אותך להתחבר מחדש, או `5` כדי להנפיק את ההרשאה החסרה. ראה [CLI recipes for agents](/he/agenteye/cli-recipes) לsystème exit-code-handling וצורות JSON output.
