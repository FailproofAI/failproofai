OpenTelemetry מאפשר לך לשלוח עקבות סוכנים, יומנים ומדדים ל-FailproofAI Cloud תוך שימוש בפרוטוקול OTLP/HTTP הסטנדרטי. זה אופציונלי. האינטגרציות FailproofAI הקיימות שלך ממשיכות לעבוד ללא הפעלתו.

## הפעלת הנתונים הנכנסים עבור הארגון שלך

מנהל ארגון פותח **Settings → OpenTelemetry** והופך את הנתונים הנכנסים להפעילים. השתמש במפתח Cloud API עם הרשאת `events:add`, אותה הרשאה המשמשת לדיווח סוכנים.

אם הנתונים הנכנסים כבויים, Cloud דוחה ייצוא OTLP, ולכן `failproofai otel enable` לא משנה דבר והסוכנים שלך ממשיכים לשלוח סשנים בדרך הרגילה. הרץ `failproofai otel status` כדי לבדוק את המתג של הארגון, ובקש מנהל להפעיל אותו.

## חיבור סוכן קידוד

חבר את המכונה שלך עם `failproofai config`, ואז בחר סוכן:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

פקודת ההתקנה תומכת ב-Claude Code, Codex ו-Copilot ובוחרת ב-Cloud או בממסר מאומת מקומי לפי הצורך. Copilot משתמש בממסר המקומי באופן אוטומטי. הפעל את דמון FailproofAI המוגדר שלך לפני שימוש בממסר.

אם FailproofAI כבר שולח תמלילי סשן של סוכן, ההתקנה שואלת אם להחליף סוכן זה ל-OTEL. ברירת המחדל היא לא. קבלה מפסיקה העלאות תמלילים לסוכן זה; זה לא משנה אכיפת מדיניות או דיווח מסוכנים אחרים.

## חיבור יישום

השתמש בתכניו OpenTelemetry של היישום שלך עם משתני הסביבה הבאים:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

נקודת הסיום היא בסיס OTLP של Cloud, `https://app.befailproof.ai/otel`; המייצא שלך מוסיף `/v1/traces`, `/v1/logs`, או `/v1/metrics` בעצמו. משתנים לכל אות כגון `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` משמשים כמו שהם, ולכן הם צריכים את הנתיב המלא, לדוגמה `https://app.befailproof.ai/otel/v1/logs`.

החלף את `<key>` עם מפתח ה-API שלך. שמור על הסוד בחוץ מהיסטוריה של המעטפת, הקלטות מסך וקונפיגורציה מעוגנת. עבור מכונה מוגדרת, `failproofai otel env --service my-agent` מדפיס את הבלוק עם המפתח הקיים שלו. הפלט שלו מכיל אישור.

Cloud מקבל ייצוא OTLP/HTTP לעקבות, יומנים ומדדים, כ-protobuf או JSON, כולל בקשות דחוסות gzip. הוא לא מקבל OTLP/gRPC.

מדדים מתקבלים לתאימות מייצא אך לא מאוחסנים או מוצגים. עקבות סוכנים נתמכים וייומני סוכנים קידוד הופכים לסשנים; שדות שהסוכן לא מייצא נשארים נעדרים.

## לכידת טקסט הנושא

<Warning>
לכידת הטקסט יכולה לכלול נושאים, טיעוני כלים ותוכן רגיש אחר. `failproofai otel enable` מפעילה אותו. הוסף `--no-content` כדי לשמור על לכידת נושא ופרט כלים כבויה.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

עבור סוכן שתקצה ידנית, השתמש בבקרות לכידת תוכן משלו:

<Tabs>
  <Tab title="Claude Code">
    הוסף את המשתנים הבאים לסביבת הסוכן שלך לצד בלוק היישום למעלה:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    קבע את שני משתני התוכן ל-`0` כדי להימנע מלכידת נושאים ופרטי כלים.
  </Tab>
  <Tab title="Codex">
    בקונפיגורציית משתמש של Codex, השתמש בהגדרות OTEL שלו:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    תוכן שיחת Codex נמצא ביומנים; השאר עקבות זמן ריצה פנימיים ומדדים כבויים. Codex משתמש בנקודת הסיום המלאה שאתה מספק. קבע `log_user_prompt` ל-`false` כדי להשאיר נושאים; פקודת ההתקנה שומרת על `false` מפורש.
  </Tab>
  <Tab title="Gemini CLI">
    השתמש בהגדרות הטלמטריה של Gemini עם הממסר המקומי:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI לא נתמך על ידי `failproofai otel enable`. קצה אותו ידנית עם אספן מאומת משלך. קבע `logPrompts` ל-`false` כדי שלא לתעד נושאים.
  </Tab>
  <Tab title="Copilot in VS Code">
    השתמש בהגדרות משתמש של VS Code הבאות:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    הרץ `failproofai otel enable copilot` כדי להפעיל את הממסר המאומת. קבע `captureContent` ל-`false` כדי להשמיט תוכן.
  </Tab>
</Tabs>

## בדיקה או ביטול התקנה

הממסר שומר על טלמטריה דרך כשלים זמניים בחיבור ובשרת ונסיונות חוזרים לאחר התאוששות. דחיית `400` קבועה, כולל אירוע שגדול מדי לאחסון, דורשת תיקון של הטעינה. הממסר שומר את האצווה שנדחתה לבדיקה ולא שולח אותה שוב וחוזר חלילה.

לאחר `401` או `403`, החלף את האישור עם מפתח המעניק `events:add` לאותו ארגון. החיבור מחדש לא שולח מחדש באופן אוטומטי ייצוא OTLP שנשמר שנדחה לאישורים; בקש מהמפעיל שלך להחזיר את האצווות הללו. שמור אותם בארגון המקורי שלהם.

```bash
failproofai otel status
failproofai otel disable all
```

המצב מבחין בהגדרות שנוהלו על ידי FailproofAI מטלמטריה שקצית במקום אחר. ביטול משחזר את הגדרות הניהול הקודמות ובחירת העלאת התמליל הקודמת של הסוכן.
