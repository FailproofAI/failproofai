OpenTelemetry מאפשר לך לשלוח traces, logs ו-metrics של agents ל-FailproofAI Cloud באמצעות פרוטוקול OTLP/HTTP הסטנדרטי. זה אופציונלי. ההintegrations הקיימים שלך של FailproofAI ממשיכים לעבוד בלי להפעיל זאת.

## קבל מפתח

OTLP ingest פעיל תמיד לכל ארגון; אין שום דבר להפעיל. השתמש במפתח Cloud API עם הרשאת `events:add`, אותה הרשאה המשמשת לדיווח agents.

בדashboard, **home → first-run setup** יש כרטיס **connect with OpenTelemetry**: **create collector key** יוצר מפתח `events:add`, מציג אותו פעם אחת עם משתני exporter, ומציג את סטטוס ההחיבור. אתה יכול גם ליצור אחד תחת **settings → api keys** על ידי בחירת **sending logs only** תחת **new key**.

## חבר coding agent

חבר את המכונה שלך עם `failproofai config`, ואז בחר agent:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

פקודת ההגדרה תומכת ב-Claude Code, Codex ו-Copilot וברירת מחדל בחירה בין Cloud או relay מאומת מקומי בהתאמה. Copilot משתמש בrelay המקומי באופן אוטומטי. הפעל את ה-FailproofAI daemon שהוגדר שלך לפני שימוש ב-relay.

אם FailproofAI כבר שולח session transcripts של agent, ההגדרה שואלת אם להחליף את ה-agent לـ OTEL. ברירת המחדל היא No. קבלה עוצרת uploads של transcripts לאותו agent; זה לא משנה enforcement של policies או reporting מ-agents אחרים.

## חבר אפליקציה

השתמש ב-OpenTelemetry instrumentation של האפליקציה שלך עם משתני סביבה אלה:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

ה-endpoint הוא OTLP base של Cloud, `https://app.befailproof.ai/otel`; ה-exporter שלך מוסיף `/v1/traces`, `/v1/logs` או `/v1/metrics` בעצמו. משתנים per-signal כמו `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` משמשים כמו שהם, כך שהם צריכים את הנתיב המלא, למשל `https://app.befailproof.ai/otel/v1/logs`.

החלף את `<key>` במפתח ה-API שלך. שמור את הsecret בחוץ מhistory של shell, screen recordings וconfiguration שהוcommit. עבור מכונה שהוגדרה, `failproofai otel env --service my-agent` מדפיס את הבלוק עם המפתח הקיים שלו. הoutput שלו מכיל credential.

Cloud מקבל OTLP/HTTP exports עבור traces, logs ו-metrics, כ-protobuf או JSON, כולל requests דחוסים ב-gzip. זה לא מקבל OTLP/gRPC.

Metrics מאושרים לתאימות exporter אך לא מאוחסנים או מוצגים. Supported agent traces ו-coding-agent logs הופכים ל-sessions; fields שה-agent לא exports נשארים חסרים.

## תפוס טקסט של prompts

<Warning>
קפטור של טקסט יכול לכלול prompts, tool arguments וtarget other sensitive content. `failproofai otel enable` מפעיל זאת. הוסף `--no-content` כדי לשמור קפטור של prompts וtool-detail כבוי.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

עבור agent שאתה מגדיר ידנית, השתמש בcontent-capture controls שלו:

<Tabs>
  <Tab title="Claude Code">
    הוסף משתנים אלה לסביבה של ה-agent שלך לצד הבלוק של האפליקציה למעלה:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    הגדר את שני משתני ה-content ל-`0` כדי להימנע מקפטור של prompts וtool details.
  </Tab>
  <Tab title="Codex">
    בconfiguration של המשתמש של Codex, השתמש בהגדרות OTEL שלו:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    תוכן conversation של Codex הוא ב-logs; השאר internal runtime traces ו-metrics מנוטרלים. Codex משתמש בendpoint המלא שאתה מספק. הגדר את `log_user_prompt` ל-`false` כדי להשאיר prompts בחוץ; פקודת ההגדרה משמרת `false` מפורש.
  </Tab>
  <Tab title="Gemini CLI">
    השתמש בהגדרות telemetry של Gemini עם ה-relay המקומי:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI לא נתמך על ידי `failproofai otel enable`. הגדר זאת ידנית עם collector מאומת שלך. הגדר את `logPrompts` ל-`false` לאף קפטור של prompts.
  </Tab>
  <Tab title="Copilot in VS Code">
    השתמש בהגדרות אלה של VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    הפעל `failproofai otel enable copilot` כדי להפעיל את ה-relay המאומת. הגדר את `captureContent` ל-`false` כדי להשמיט תוכן.
  </Tab>
</Tabs>

## בדוק או בטל הגדרה

ה-relay שומר telemetry דרך כשלים זמניים של network וserver ו-retries לאחר recovery. דחייה קבועה של `400`, כולל event שגדול מדי לאחסון, דורשת תיקון של ה-payload. ה-relay שומר את ה-batch שנדחה לבדיקה במקום לשלוח אותו שוב וSharon.

לאחר `401` או `403`, החלף את הcredential עם מפתח המעניק `events:add` לאותו ארגון. התחברות מחדש לא שולחת שוב באופן אוטומטי OTLP exports שנשמרו שנדחו עבור credentials; בקש מה-operator שלך לשחזר את הbatches האלה. שמור אותם בארגון המקורי שלהם.

```bash
failproofai otel status
failproofai otel disable all
```

Status מבחין בין הגדרות המנוהלות על ידי FailproofAI לבין telemetry שהגדרת במקום אחר. Disable משחזר את ההגדרות המנוהלות הקודמות ובחירת ה-transcript-upload הקודמת של ה-agent.
