OpenTelemetry מאפשר לך לשלוח traces, logs ו-metrics של agents ל-FailproofAI Cloud באמצעות פרוטוקול OTLP/HTTP הסטנדרטי. זה אופציונלי. האינטגרציות FailproofAI הקיימות שלך ממשיכות לעבוד ללא הפעלת התכונה.

## הפעל ingest עבור הארגון שלך

מנהל ארגון פותח **Settings → OpenTelemetry** והופך ingest למופעל. השתמש ב-Cloud API key עם הרשאת `events:add`, אותה הרשאה המשמשת לדיווח agents.

אם ingest כבוי, Cloud דוחה OTLP exports, כך ש-`failproofai otel enable` לא משנה דבר וה-agents שלך ממשיכים לשלוח sessions בדרך הרגילה. הרץ `failproofai otel status` כדי לבדוק את המתג של הארגון, והשאל מנהל להפעיל אותו.

## חבר coding agent

חבר את המכונה שלך עם `failproofai config`, ואז בחר agent:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

פקודת ההגדרה תומכת ב-Claude Code, Codex ו-Copilot ובוחרת ב-Cloud או ב-local authenticated relay לפי הצורך. Copilot משתמש ב-local relay באופן אוטומטי. הפעל את ה-FailproofAI daemon המוגדר שלך לפני שימוש ב-relay.

אם FailproofAI כבר שולח session transcripts של agent, setup שואל האם להחליף את ה-agent ל-OTEL. ברירת המחדל היא לא. קבלת ההצעה עוצרת uploads של transcripts עבור ה-agent הזה; זה לא משנה את אכיפת המדיניות או דיווח מ-agents אחרים.

## חבר יישום

השתמש בטלמטריה OpenTelemetry של היישום שלך עם משתני סביבה אלה:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

נקודת הקצה היא OTLP base של Cloud, `https://app.befailproof.ai/otel`; ה-exporter שלך מוסיף `/v1/traces`, `/v1/logs`, או `/v1/metrics` בעצמו. משתנים לפי אות כמו `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` משמשים כמו שהם, כך שהם זקוקים לנתיב מלא, לדוגמה `https://app.befailproof.ai/otel/v1/logs`.

החלף את `<key>` ב-API key שלך. שמור את הסוד מחוץ להיסטוריית shell, הקלטות מסך וקונפיגורציה committed. עבור מכונה מוגדרת, `failproofai otel env --service my-agent` מדפיס את הבלוק עם ה-key הקיים שלו. הפלט שלו מכיל credential.

Cloud מקבל OTLP/HTTP exports עבור traces, logs ו-metrics, כ-protobuf או JSON, כולל בקשות דחוסות gzip. הוא לא מקבל OTLP/gRPC.

Metrics מאושרים לתאימות exporter אך לא מאוחסנים או מוצגים. Agent traces ו-coding-agent logs נתמכים הופכים ל-sessions; שדות שה-agent לא מייצא נשארים חסרים.

## לכוד טקסט prompt

<Warning>
הלכידה של טקסט יכולה לכלול prompts, arguments של tools וטקסט רגיש אחר. `failproofai otel enable` הופך אותה למופעלת. הוסף `--no-content` כדי להשאיר את הלכידה של prompt וטקסט tool-detail כבויה.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

עבור agent שאתה מגדיר ידנית, השתמש בקנטרולים שלו לתפיסת תוכן:

<Tabs>
  <Tab title="Claude Code">
    הוסף משתנים אלה לסביבת ה-agent שלך לצד הבלוק היישום לעיל:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    הגדר את שני משתני התוכן ל-`0` כדי להימנע מלכידת prompts ופרטי tools.
  </Tab>
  <Tab title="Codex">
    בקונפיגורציה של המשתמש של Codex, השתמש בהגדרות OTEL שלו:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    תוכן שיחה של Codex נמצא ב-logs; השאר traces וmetricsrantיות כבויים. Codex משתמש בנקודת הקצה השלמה שאתה מספק. הגדר `log_user_prompt` ל-`false` כדי להשמיט prompts; פקודת ההגדרה שומרת `false` מפורש.
  </Tab>
  <Tab title="Gemini CLI">
    השתמש בהגדרות הטלמטריה של Gemini עם ה-local relay:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI לא נתמך על ידי `failproofai otel enable`. הגדר אותו ידנית עם collector מאומת משלך. הגדר `logPrompts` ל-`false` כדי לא ללכוד prompts.
  </Tab>
  <Tab title="Copilot in VS Code">
    השתמש בהגדרות משתמש VS Code אלה:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    הרץ `failproofai otel enable copilot` כדי להפעיל את ה-relay המאומת. הגדר `captureContent` ל-`false` כדי להשמיט תוכן.
  </Tab>
</Tabs>

## בדוק או בטל הגדרה

ה-relay שמר טלמטריה דרך כשלים זמניים של רשת וserver ו-retries לאחר התאוששות. דחייה קבועה של `400`, כולל event שגדול מדי לאחסון, דורשת תיקון ה-payload. ה-relay שומר את ה-batch שנדחה לבדיקה במקום לשלוח אותו שוב ושוב.

לאחר `401` או `403`, החלף את ה-credential בעזרת key שמעניק `events:add` עבור אותו ארגון. חיבור מחדש לא משלח automaticlyאוטומטית ל-OTLP exports שנדחו עקב credentials; בקש מה-operator שלך להחזיר את ה-batches האלה. שמור אותם בארגון המקורי שלהם.

```bash
failproofai otel status
failproofai otel disable all
```

Status מבדיל הגדרות המנוהלות על ידי FailproofAI מטלמטריה שהגדרת במקום אחר. Disable משחזר את הגדרות managed קודמות ובחירת ה-transcript-upload הקודמת של ה-agent.
