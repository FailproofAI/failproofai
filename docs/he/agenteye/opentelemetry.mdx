OpenTelemetry מאפשר לך לשלוח traces, logs ו-metrics של agents ל-FailproofAI Cloud תוך שימוש בפרוטוקול OTLP/HTTP הסטנדרטי. זה אופציונלי. ההשתלבויות הקיימות שלך ב-FailproofAI ממשיכות לעבוד ללא הפעלתו.

## הפעל ingest עבור הארגון שלך

מנהל ארגון פותח **Settings → OpenTelemetry** והפעל את ingest. השתמש ב-Cloud API key עם הרשאת `events:add`, אותה הרשאה המשמשת לדיווח agents.

אם ingest כבוי, Cloud דוחה ייצוא OTLP, ולכן `failproofai otel enable` לא משנה כלום והagents שלך ממשיכים לשלוח sessions בדרך הרגילה. הרץ `failproofai otel status` כדי לבדוק את המתג של הארגון, ובקש מ-admin להפעיל אותו.

## חבר coding agent

חבר את המכונה שלך עם `failproofai config`, ואז בחר agent:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

פקודת ההגדרה תומכת ב-Claude Code, Codex ו-Copilot ובוחרת Cloud או authenticated relay מקומי לפי הצורך. Copilot משתמש ב-local relay באופן אוטומטי. הפעל את daemon ה-FailproofAI המוגדר שלך לפני שימוש ב-relay.

אם FailproofAI כבר שולח session transcripts של agent, ההגדרה שואלת האם להעביר את ה-agent הזה ל-OTEL. ברירת המחדל היא No. קבלה עוצרת uploads של transcripts עבור agent זה; זה לא משנה enforcement של מדיניות או דיווח מ-agents אחרים.

## חבר יישום

השתמש בinstrumentation של OpenTelemetry של היישום שלך עם משתני הסביבה הבאים:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

ה-endpoint הוא בסיס OTLP של Cloud, `https://app.befailproof.ai/otel`; ה-exporter שלך מוסיף `/v1/traces`, `/v1/logs` או `/v1/metrics` בעצמו. משתני per-signal כמו `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` משמשים כما-הם, ולכן הם זקוקים לנתיב מלא, למשל `https://app.befailproof.ai/otel/v1/logs`.

החלף את `<key>` ב-API key שלך. שמור את הסוד מחוץ להיסטוריית shell, reencodings של מסך וקבצי תצורה committed. עבור מכונה מוגדרת, `failproofai otel env --service my-agent` מדפיס את הבלוק עם ה-key הקיים שלו. הפלט שלו מכיל credential.

Cloud מקבל ייצוא OTLP/HTTP עבור traces, logs ו-metrics, כ-protobuf או JSON, כולל בקשות דחוסות gzip. זה לא מקבל OTLP/gRPC.

Metrics מאושרים לתאימות exporter אך אינם מאוחסנים או מוצגים. Agent traces נתמכים והcoding-agent logs הופכים לsessions; שדות שה-agent לא מייצא נשארים חסרים.

## תפוס טקסט של prompt

<Warning>
text capture יכול לכלול prompts, tool arguments וחומר רגיש אחר. `failproofai otel enable` מפעיל זאת. הוסף `--no-content` כדי להשאיר את capture של prompt וtool-detail כבויים.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

עבור agent שאתה מגדיר ידנית, השתמש בcontrol capture של תוכן שלו:

<Tabs>
  <Tab title="Claude Code">
    הוסף משתנים אלה לסביבת ה-agent שלך לצד הבלוק היישום לעיל:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    הגדר את שני משתני התוכן ל-`0` כדי להימנע מ-capture של prompts וtool details.
  </Tab>
  <Tab title="Codex">
    בתצורת המשתמש של Codex, השתמש בהגדרות OTEL שלו:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    תוכן שיחת Codex נמצא ב-logs; השאר internal runtime traces ו-metrics כבויים. Codex משתמש בendpoint המלא שאתה מספק. הגדר את `log_user_prompt` ל-`false` כדי להשאיר prompts בחוץ; פקודת ההגדרה שומרת `false` מפורש.
  </Tab>
  <Tab title="Gemini CLI">
    השתמש בהגדרות הטלמטריה של Gemini עם ה-local relay:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI לא נתמך על ידי `failproofai otel enable`. הגדר אותו ידנית עם collector מאומת משלך. הגדר את `logPrompts` ל-`false` לאין capture של prompt.
  </Tab>
  <Tab title="Copilot in VS Code">
    השתמש בהגדרות משתמש VS Code אלה:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    הרץ `failproofai otel enable copilot` כדי להפעיל את ה-relay המאומת. הגדר את `captureContent` ל-`false` כדי להשמיט תוכן.
  </Tab>
</Tabs>

## בדוק או בטל הגדרה

ה-relay שומר על טלמטריה דרך כשלים זמניים בנטוורק ובשרת ו-retries לאחר התאוששות. דחייה קבועה של `400`, כולל event שגדול מדי לאחסון, דורשת תיקון payload. ה-relay שומר על הbatch שנדחה לבדיקה במקום לשלוח אותו שוב ושוב.

לאחר `401` או `403`, החלף את credential בkey המעניק `events:add` לאותו ארגון. התחברות מחדש לא משלחת מחדש באופן אוטומטי ייצוא OTLP שנשמר שנדחה עבור credentials; בקש מהoperator שלך להחזיר את batch-ים אלה. שמור אותם בארגון המקורי שלהם.

```bash
failproofai otel status
failproofai otel disable all
```

Status מבדיל בין הגדרות המנוהלות על ידי FailproofAI לטלמטריה שהגדרת במקום אחר. Disable משחזר את ההגדרות המנוהלות הקודמות והבחירה הקודמת של transcript-upload של ה-agent.
