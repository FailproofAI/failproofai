OpenTelemetry מאפשר לכם לשלוח traces, logs ו-metrics של agents ל-FailproofAI Cloud באמצעות פרוטוקול OTLP/HTTP סטנדרטי. זה אופציונלי. ההשלמות ה-FailproofAI הקיימות שלכם ממשיכות לעבוד ללא הפעלתו.

## הפעילו ingest עבור הארגון שלכם

admin בארגון פותח **Settings → OpenTelemetry** והופך את ingest להפעיל. השתמשו ב-Cloud API key עם הרשאת `events:add`, אותה הרשאה המשמשת לדיווח על agents.

אם ingest כבוי, Cloud דוחה OTLP exports, כך שהרצת `failproofai otel enable` לא משנה דבר והagents שלכם ממשיכים לשלוח sessions בדרך הרגילה. הריצו `failproofai otel status` כדי לבדוק את מתג הארגון, ובקשו מadmin להפעיל אותו.

## חברו coding agent

חברו את המכונה שלכם עם `failproofai config`, ואז בחרו בagent:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

פקודת ההגדרה תומכת ב-Claude Code, Codex ו-Copilot ובוחרת Cloud או local authenticated relay כנדרש. Copilot משתמש ב-local relay באופן אוטומטי. הפעילו את ה-FailproofAI daemon המוגדר לפני שימוש ב-relay.

אם FailproofAI כבר שולח session transcripts של agent, ההגדרה שואלת האם להעביר את ה-agent לפרוטוקול OTEL. ברירת המחדל היא No. קבלה מפסיקה העלאות transcript עבור ה-agent; היא לא משנה את אכיפת המדיניות או דיווח מagents אחרים.

## חברו יישום

השתמשו בinstrumentation OpenTelemetry של היישום שלכם עם משתני הסביבה הבאים:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

ה-endpoint הוא בסיס OTLP של Cloud, `https://app.befailproof.ai/otel`; ה-exporter שלכם מוסיף `/v1/traces`, `/v1/logs` או `/v1/metrics` בעצמו. משתנים לכל-signal כמו `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` משמשים כמו שהם, כך שהם צריכים את הנתיב המלא, לדוגמה `https://app.befailproof.ai/otel/v1/logs`.

החליפו את `<key>` בAPI key שלכם. שמרו על הסוד מחוץ לhistory של shell, screen recordings וconfiguration שמתחויבבים. עבור מכונה מוגדרת, `failproofai otel env --service my-agent` מדפיס את הבלוק עם ה-key הקיים שלו. הפלט שלו מכיל credential.

Cloud מקבל OTLP/HTTP exports עבור traces, logs ו-metrics, כ-protobuf או JSON, כולל requests דחוסים ב-gzip. הוא לא מקבל OTLP/gRPC.

Metrics מאושרים לתאימות exporter אך אינם מאוחסנים או מוצגים. Supported agent traces ו-coding-agent logs הופכים ל-sessions; שדות שה-agent לא מייצא נשארים חסרים.

## לכדו טקסט prompt

<Warning>
Text capture יכול לכלול prompts, tool arguments וחומר רגיש אחר. `failproofai otel enable` הופך אותו להיות מופעל. הוסיפו `--no-content` כדי לשמור על prompt ו-tool-detail capture כבוי.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

עבור agent שאתם מגדירים ידנית, השתמשו בקטגוריות content-capture שלו:

<Tabs>
  <Tab title="Claude Code">
    הוסיפו משתנים אלה לסביבה של ה-agent לצד בלוק היישום למעלה:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    הגדירו את שני משתני התוכן ל-`0` כדי להימנע מלכידת prompts וtool details.
  </Tab>
  <Tab title="Codex">
    בconfiguration המשתמש של Codex, השתמשו בהגדרות OTEL שלו:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex conversation content נמצא ב-logs; השאירו internal runtime traces ו-metrics כבויים. Codex משתמש בה-endpoint המלא שאתם מספקים. הגדירו את `log_user_prompt` ל-`false` כדי להשאיר prompts בחוץ; פקודת ההגדרה שומרת `false` מפורש.
  </Tab>
  <Tab title="Gemini CLI">
    השתמשו בהגדרות telemetry של Gemini עם ה-local relay:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI אינו נתמך על ידי `failproofai otel enable`. הגדירו אותו ידנית עם collector מאומת משלכם. הגדירו את `logPrompts` ל-`false` לשום lkidah של prompts.
  </Tab>
  <Tab title="Copilot in VS Code">
    השתמשו בהגדרות המשתמש של VS Code הבאות:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    הריצו `failproofai otel enable copilot` כדי להפעיל את ה-relay המאומת. הגדירו את `captureContent` ל-`false` כדי להשמיט תוכן.
  </Tab>
</Tabs>

## בדקו או בטלו הגדרה

ה-relay שומר על telemetry דרך כשלים זמניים ברשת וב-server וחוזר על ניסיון לאחר התאוששות. דחיית `400` קבועה, כולל event שגדול מדי לאחסון, דורשת תיקון ה-payload. ה-relay שומר על הbatch שנדחה לבדיקה במקום לשלוח אותו שוב ושוב.

לאחר `401` או `403`, החליפו את הcredential בkey שמעניק `events:add` עבור אותו ארגון. התחברות מחדש לא שולחת מחדש באופן אוטומטי OTLP exports שנשמרו שנדחו עבור credentials; בקשו מה-operator שלכם להחזיר את אותם batches. שמרו אותם בארגון המקורי שלהם.

```bash
failproofai otel status
failproofai otel disable all
```

Status מבדיל הגדרות שנוהלו על ידי FailproofAI מטלמטריה שהגדרתם במקום אחר. Disable משחזר את ההגדרות המנוהלות הקודמות ובחירת ה-transcript-upload הקודמת של ה-agent.
