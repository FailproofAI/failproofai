OpenTelemetry מאפשר לך לשלוח traces, logs ו-metrics של agents ל-FailproofAI Cloud באמצעות פרוטוקול OTLP/HTTP סטנדרטי. זה אופציונלי. האינטגרציות FailproofAI הקיימות שלך ממשיכות לעבוד ללא הפעלת התכונה הזו.

## הפעלת ingest עבור הארגון שלך

מנהל ארגון פותח את **Settings → OpenTelemetry** והופעל את ה-ingest. השתמש ב-Cloud API key עם הרשאת `events:add`, אותה הרשאה המשמשת לדיווח agents.

אם ה-ingest כבוי, Cloud דוחה ייצוא OTLP, כך ש-`failproofai otel enable` לא משנה כלום וה-agents שלך ממשיכים לשלוח sessions בדרך הרגילה. הרץ את `failproofai otel status` כדי לבדוק את מתג הארגון, והבקש מ-admin להפעיל את זה.

## חיבור coding agent

חבר את המכונה שלך עם `failproofai config`, ואז בחר agent:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

פקודת ההגדרה תומכת ב-Claude Code, Codex ו-Copilot ובוחרת Cloud או authenticated relay מקומי לפי הצורך. Copilot משתמש ב-local relay באופן אוטומטי. הפעל את ה-FailproofAI daemon המוגדר שלך לפני שימוש ב-relay.

אם FailproofAI כבר שולח session transcripts של agent, ההגדרה שואלת האם לעבור את ה-agent הזה ל-OTEL. ברירת המחדל היא No. הקבלה עוצרת uploads של transcript עבור ה-agent הזה; היא לא משנה את כפיית המדיניות או דיווח מ-agents אחרים.

## חיבור אפליקציה

השתמש בinstrumentation OpenTelemetry של האפליקציה שלך עם משתני הסביבה הללו:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

ה-endpoint הוא בסיס OTLP של Cloud, `https://app.befailproof.ai/otel`; ה-exporter שלך מוסיף `/v1/traces`, `/v1/logs` או `/v1/metrics` בעצמו. משתנים לכל-signal כמו `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` משמשים כ-is, כך שהם צריכים את הנתיב המלא, לדוגמה `https://app.befailproof.ai/otel/v1/logs`.

החלף את `<key>` ב-API key שלך. שמור את הסוד מחוץ לhistory של shell, screen recordings וconfiguration שהעלו על commit. עבור מכונה מוגדרת, `failproofai otel env --service my-agent` מודפס את הבלוק עם ה-key הקיים שלו. ה-output שלו מכיל credential.

Cloud מקבל ייצוא OTLP/HTTP עבור traces, logs ו-metrics, כ-protobuf או JSON, כולל בקשות דחוסות gzip. זה לא מקבל OTLP/gRPC.

Metrics מאושרים לתאימות exporter אך אינם מאוחסנים או מוצגים. Supported agent traces וcoding-agent logs הופכים ל-sessions; שדות שה-agent לא מייצא נשארים חסרים.

## לכידת טקסט של prompt

<Warning>
לכידת טקסט יכולה לכלול prompts, tool arguments וכל תוכן רגיש אחר. `failproofai otel enable` מפעיל את זה. הוסף `--no-content` כדי שלא להקליט prompt וtool-detail capture.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

עבור agent שאתה מגדיר באופן ידני, השתמש בcontrol שלו שלו לlכידת תוכן:

<Tabs>
  <Tab title="Claude Code">
    הוסף משתנים אלה לסביבה של ה-agent שלך לצד בלוק האפליקציה למעלה:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    הגדר את שתי משתני התוכן ל-`0` כדי להימנע מלכידת prompts וtool details.
  </Tab>
  <Tab title="Codex">
    בתצורת המשתמש של Codex, השתמש בהגדרות OTEL שלו:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    תוכן השיחה של Codex נמצא ב-logs; השאר internal runtime traces ו-metrics מבוטלים. Codex משתמש ב-endpoint המלא שאתה מספק. הגדר את `log_user_prompt` ל-`false` כדי להשאיר prompts בחוץ; פקודת ההגדרה משמרת `false` מפורש.
  </Tab>
  <Tab title="Gemini CLI">
    השתמש בהגדרות טלמטריה של Gemini עם ה-local relay:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI לא נתמך על ידי `failproofai otel enable`. הגדר אותו ידנית עם collector מאומת משלך. הגדר את `logPrompts` ל-`false` לאין לכידת prompt.
  </Tab>
  <Tab title="Copilot in VS Code">
    השתמש בהגדרות המשתמש של VS Code הללו:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    הרץ את `failproofai otel enable copilot` כדי להפעיל את authenticated relay. הגדר את `captureContent` ל-`false` כדי להשמיט תוכן.
  </Tab>
</Tabs>

## בדיקה או ביטול של הגדרה

```bash
failproofai otel status
failproofai otel disable all
```

Status מבדיל בין הגדרות שהנהלת FailproofAI מטלמטריה שהגדרת במקום אחר. Disable משחזר את הגדרות ה-managed הקודמות ובחירת ה-transcript-upload הקודמת של ה-agent.
