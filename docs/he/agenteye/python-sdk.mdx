ראו בדיוק מה שהסוכנים ה-AI שלכם עשו בייצור: כל הרצה של סוכן, קריאת כלי, בקשת מודל, hook והתערבות אנושית. ה-SDK של Failproof AI Observability Python מתעד את השביל הזה מתוך קוד הסוכן שלכם כדי שתוכלו לבצע ניפוי באגים, ביקורת והערכה של מה שקרה. השתמשו בו בכל פעם שאתם רוצים ש-Failproof AI Observability יעקוב אחר הסוכנים שלכם.

מתחת למכסה המנוע, ה-SDK כותב אירועים מובנים לקבצי JSONL מקומיים, ושרת האספן אוסף אותם וכולל אותם לפלטפורמה באופן אוטומטי. אתם לא מנהלים את הקבצים האלה בעצמכם.

> **עצה:** חדש ל-Failproof AI Observability? דף זה הוא ההתייחסות השלמה של אירועי ה-SDK.

## התקנה

ה-SDK מופץ ללקוחות כ-wheel פרטי ולא מאינדקס חבילות ציבורי. התרגום שלכם מכסה כיצד להשיג אותו, להתקין אותו ולהצמיד אותו — דברו עם איש הקשר שלכם ב-Failproof AI אם אתם זקוקים לגישה.

לאחר התקנתו, אשרו שיש לכם אותו:

```bash
python -c "import agenteye; print(agenteye.__version__)"
```

מעדיפים לתת לסוכן קידוד לעשות את כל השילוב? [Python SDK Agent Skill](/he/agenteye/python-sdk-skill) יודע את נתיב ההתקנה, מתכנן את נקודות הציוד, כותב אותן ומאמת שהאירועים מגיעים.

## התחלה מהירה

```python
import agenteye

agenteye.configure(environment="production")

agenteye.event.agent_start(session_id="run-001", agent_id="planner", goal="answer user query")

agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    input={"query": "latest AI research"},
)

agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    output={"results": ["..."]},
)

agenteye.event.agent_end(session_id="run-001", agent_id="planner", outcome="success")
```

### ציוד של קריאה בפועל

בפועל אתם עוטפים את קוד הסוכן הקיים שלכם. תחום קריאה למודל עם `model_request` לפני ו-`model_response` אחרי, כך שני האירועים משתרעים על הבקשה בפועל וה-Failproof AI Observability יכול להתאים אותם:

```python
import anthropic
import agenteye

agenteye.configure(environment="production")
client = anthropic.Anthropic()

messages = [{"role": "user", "content": "Summarise today's incidents."}]

agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6",
    messages=messages,
)

reply = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=512,
    messages=messages,
)

agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model=reply.model,
    stop_reason=reply.stop_reason,
    input_tokens=reply.usage.input_tokens,
    output_tokens=reply.usage.output_tokens,
    content=[block.model_dump() for block in reply.content],
)
```

עטפו קריאות כלים באותו אופן עם `tool_use` ו-`tool_result`, תוך שימוש חוזר באותו `tool_call_id` על פני הזוג.

הנה איך נראים אירועים אלה לאחר שהם מגיעים לתDashboard, מקודדים בצבע לפי סוג וניתן לסנן לפי סביבה, סוכן וסשן:

## configure()

```python
agenteye.configure(
    base_dir=None,           # Path | str | None. Default: $AGENTEYE_HOME or ~/.agenteye
    flush_interval=0.5,      # float, seconds between flush cycles
    environment=None,        # str | None. Deployment environment label
)
```

קרא פעם אחת לפני כל קריאת `event.*`. בטוח להשמיט; ברירות המחדל עובדות מחוץ לקופסה. כל הארגומנטים הם רק מילות מפתח; העברו אותם לפי שם כמו למעלה.

כאשר `base_dir` הוא `None` (ברירת המחדל), ה-SDK קורא `$AGENTEYE_HOME` אם מוגדר,
אחרת חוזר אל `~/.agenteye`. זה תואם את ההחלטה של אספן עצמו,
כך שמשתנה `AGENTEYE_HOME` אחד env מגדיר את spooler האירועים הרחוקים לשניהם
ה-SDK והאספן.

## סביבה

סמנו כל אירוע עם סביבת פריסה (`production`, `staging`, `qa`, `canary`, וכו'). קבעו אותו פעם אחת; ה-SDK מצרף אותו לכל אירוע באופן אוטומטי.

**אפשרות 1: דרך `configure()`:**

```python
agenteye.configure(environment="production")
```

**אפשרות 2: דרך משתנה סביבה:**

```bash
export AGENTEYE_ENVIRONMENT=production
```

**עדיפות:** `configure(environment=...)` מנצח על משתנה הסביבה. אם לא קבעתם אף אחד, ברירת המחדל היא `"dev"`.

ערך הסביבה מופיע כמסנן מדרגה ראשונה בתDashboard וגם מאוחסן בשרת לשאילתות מהירות.

> **אזהרה:** ערכי סביבה לא חייבים להכיל פסיק `,` מילולי. מסננים Dashboard משתמשים בבחירה מרובה מופרדת בפסיק בחוט (`?environment=prod,staging`), כך שסביבה בשם `prod,blue` תחולק לשני ערכים. אירועים עם סביבות המכילות פסיק נדחים בזמן ספיגה.

## נתונים וגוגנות

ה-SDK מתעד רק את השדות שאתם מעבירים במפורש. הנושאים, ההודעות, הקלטים ופלטי הכלים והתוכן של המודל נתפסים אך ורק מכיוון שהעברתם אותם לקריאת `event.*`. שום דבר לא נקרא מתהליך שלכם או נתפס בצורה מובנית. כל שדה שלא הגדרתם מושמט לחלוטין מהאירוע; הוא לא כתוב לדיסק.

זה הופך את ההסתרה לבחירה שלכם ולאחריות שלכם. אם נושא או טעינת כלי מכיל PII או סודות שלא הייתם רוצים לאחסן, הסירו או סיכו זאת לפני שתעבירו אותו לשיטת האירוע.

## התייחסות אירועים

רוב האירועים מגיעים בזוגות התחלה/סיום החולקים מזהה מתאם: `tool_use` ו-`tool_result` חולקים `tool_call_id`, `hook_triggered` ו-`hook_completed` חולקים `hook_id`, ו-`human_wait` ו-`human_input` חולקים `input_id`. פלוטו את אירוע ההתחלה, עשו את העבודה, ואז פלוטו את אירוע הסיום עם אותו מזהה. Failproof AI Observability מתאים את הזוג ומחשב עבורכם `duration_ms`, כך שלא אתם עצמכם מעבירים `duration_ms`.

![גרף הביצוע בסגנון git של סשן ליד ציר הזמן שלו, שנבנה מחדש מהאירועים המזווגים, עם פאנל פירוט הכלים/מודל/hook](/agenteye/images/session-detail.png)

כל שיטות אירועים דורשות את שני השדות הבאים:

| שדה | סוג | תיאור |
|---|---|---|
| `session_id` | `str` | מזהה את הרצת הסוכן ברמה הגבוהה ביותר |
| `agent_id` | `str` | מזהה איזה סוכן בתוך הסשן פלט את האירוע |

כל השיטות מקבלות גם `**kwargs` שרירותי למטא-נתונים מותאמים אישית (ראו [שדות מותאמים אישית](#custom-fields)).

### `event.agent_start()`

נפלט כאשר סוכן מתחיל עבודה.

```python
agenteye.event.agent_start(
    session_id="run-001",
    agent_id="planner",
    goal="answer user query",   # str | None
    parent_id=None,             # str | None - parent agent_id for nested agents
)
```

---

### `event.agent_end()`

נפלט כאשר סוכן סיים עבודה.

```python
agenteye.event.agent_end(
    session_id="run-001",
    agent_id="planner",
    outcome="success",          # str | None
    summary="Answered query",   # str | None
)
```

---

### `event.tool_use()`

נפלט כאשר סוכן מזמין כלי. התאימו עם `tool_result`; ה-SDK מחשב `duration_ms` באופן אוטומטי.

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",     # str, required
    tool_call_id="toolu_01",    # str, required - correlation key for the matching tool_result
    input={"query": "..."},     # dict | None
)
```

---

### `event.tool_result()`

נפלט כאשר כלי חוזר. קשורה עם `tool_use` דרך `tool_call_id`.

```python
agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",        # must match the prior tool_use
    output={"results": ["..."]},    # Any | None
    error=None,                     # str | None - set if the tool raised
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.model_request()`

נפלט ממש לפני שליחת הנושא ל-LLM.

```python
agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    messages=[                   # list[dict] | None - conversation turns
        {"role": "user", "content": "..."},
    ],
    system="You are helpful.",   # Any | None - str or list of content blocks
    tools=[                      # list[dict] | None - tool schemas offered to the model
        {"name": "search", "input_schema": {"type": "object"}},
    ],
)
```

רישומי `messages` מקבלים או תוכן מחרוזת פשוט `content` או תוכן מדוגמת Anthropic עם רשימה של בלוקים `content`. פרמטרים דגימה (`temperature`, `max_tokens`, וכו') יכולים להעבר כ-kwargs נוספים.

---

### `event.model_response()`

נפלט כאשר ה-LLM מחזיר תשובה.

```python
agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    stop_reason="end_turn",     # str | None
    input_tokens=1024,          # int | None
    output_tokens=256,          # int | None
    content=[                    # Any | None - str, or list of content blocks
        {"type": "text", "text": "..."},
    ],
    role="assistant",            # str | None
)
```

`content` מקבל או מחרוזת פשוט (ספקים גנריים) או רשימת בלוקי תוכן בסגנון Anthropic. קריאות כלים חיות בתוך `content` כ-`{"type": "tool_use", ...}` בלוקים, ללא שדה `tool_calls` נפרד.

---

### `event.hook_triggered()`

נפלט כאשר hook משתחרר. התאימו עם `hook_completed`; ה-SDK מחשב `duration_ms` באופן אוטומטי.

```python
agenteye.event.hook_triggered(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",   # str, required
    hook_id="hook-abc",         # str, required - correlation key
    trigger_event="tool_use",   # str | None
    input={"tool": "search"},   # Any | None
)
```

---

### `event.hook_completed()`

נפלט כאשר hook מסיים. קשורה עם `hook_triggered` דרך `hook_id`.

```python
agenteye.event.hook_completed(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",
    hook_id="hook-abc",         # must match the prior hook_triggered
    outcome="allow",            # str | None
    output=None,                # Any | None
    error=None,                 # str | None
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.error()`

נפלט כאשר שגיאה לא טופלה מתרחשת.

```python
agenteye.event.error(
    session_id="run-001",
    agent_id="planner",
    error_type="TimeoutError",  # str, required
    message="timed out",        # str, required
    traceback="Traceback...",   # str | None
)
```

## אירועי התערבות אנושית

אירועי התערבות אנושית מעניקים לכם פיקוח על הרגעים שבהם אדם צעד אל התשלום של הסוכן (המתנה לאישור, הספקת קלט, השהיה או עצירת הסוכן). הם מאפשרים לכם למדוד כמה זמן בני אדם לוקחים להגיב (ה-SDK מחשב באופן אוטומטי `duration_ms` על אירועים מזווגים), לבצע ביקורת על מי עצר או הפריע לסוכן, ולבנות זרימות אישור וכיווץ המופיעות בתDashboard.

### `event.human_wait()`

נפלט כאשר הסוכן מעצור ביצוע כדי להמתין לאדם לספק קלט. התאימו עם `human_input`; ה-SDK מחשב באופן אוטומטי `duration_ms` (כמה זמן האדם לקח להגיב).

```python
agenteye.event.human_wait(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",                          # str, required - correlation key for the matching human_input
    prompt="Do you approve this action?",        # str | None - the question shown to the human
    options=["approve", "reject", "defer"],      # list[str] | None - choices presented to the human
    reason="approval_required",                  # str | None - why the agent is waiting
)
```

### `event.human_input()`

נפלט כאשר אדם מספק קלט והסוכן מחדש. קשורה עם `human_wait` דרך `input_id`. `duration_ms` מחושב באופן אוטומטי ואסור להעבר על ידי הקורא.

```python
agenteye.event.human_input(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",    # str, required - must match the prior human_wait
    response="approve",    # str | None - the human's answer (free text or selected option)
    # duration_ms is computed automatically - do not pass it
)
```

### `event.human_pause()`

נפלט כאשר אדם באופן פעיל עוצר את הסוכן (למשל דרך בקרת תDashboard). הסוכן מושהה אך לא מסיים.

```python
agenteye.event.human_pause(
    session_id="run-001",
    agent_id="planner",
    reason="user_requested",  # str | None
    user_id="usr_42",         # str | None - who paused the agent
)
```

### `event.human_interrupt()`

נפלט כאשר אדם באופן פעיל עוצר את הסוכן בביצוע. בניגוד ל-`human_pause`, עבודת הסוכן מסתיימת ולא מושהה.

```python
agenteye.event.human_interrupt(
    session_id="run-001",
    agent_id="planner",
    reason="output_incorrect",       # str | None
    user_id="usr_42",                # str | None - who interrupted the agent
    at_step="tool_use:web_search",   # str | None - what the agent was doing when stopped
)
```

## שדות מותאמים אישית

כל ארגומנטים מילות מפתח נוספים מצורפים לאירוע אחרי השדות הרגילים:

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="db_query",
    tool_call_id="toolu_02",
    tenant_id="acme",           # custom field
    region="us-east-1",         # custom field
)
```

`timestamp`, `type` ו-`environment` שמורים ולהעלות `ValueError` (`Reserved field names cannot be used as custom fields: [...]`) אם התחיל כשדות מותאמים אישית. `session_id` ו-`agent_id` הם פרמטרים נדרשים על כל שיטת אירוע ולא יכולים להסופק שוב; Python מעלה `TypeError` אם אתם עושים זאת. קבעו את הסביבה עם `configure(environment=...)` (או משתנה `AGENTEYE_ENVIRONMENT`) במקום זאת.

שמור על עומסי עבודה כ-JSON מובנה כאשר אתה רוצה לשאול את התחומים שלהם. ערכים שה-JSON לא תומך בהם באופן מקובל — כמו datetimes, UUIDs, decimals, sets, bytes או model objects — מומרים למחרוזות כך שההקלטה ממשיכה בבטחה.

## כיצד אירועים כתובים

אירועים מוצמדים בתוך התהליך ודוחפים לדיסק כל `flush_interval` שניות (ברירת המחדל 500 ms). כל flush כותב קובץ JSONL אחד:

```text
~/.agenteye/events/event-2026-04-01T12-00-00-000Z.jsonl
```

האספן מעקב על ספרייה זו ומעלה קבצים באופן אוטומטי. אתם לא צריכים לנהל את הקבצים הללו ישירות.

כל קובץ כתוב בצורה אטומית: ה-SDK כותב לקובץ זמני ואז משם שמות אותו למקום, כך שהאספן לא רואה קובץ חצי-כתוב. flush סופי גם פועל כאשר התהליך שלכם יוצא, כך שאירועים מוצמדים במרווח האחרון לא אבדו. אם האספן אופליין, אירועים פשוט מתצברים כקבצים בדיסק וספינה ברגע שחוזרים.
