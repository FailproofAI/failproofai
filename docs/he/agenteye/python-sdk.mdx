ראה בדיוק מה עשו הסוכנים AI שלך בייצור: כל ריצה של סוכן, קריאת כלי, בקשת מודל, hook, והתערבות אנושית. ה-SDK של Failproof AI Observability Python מתעד את השביל הזה מתוך קוד הסוכן שלך כדי שתוכל לבצע ניפוי שגיאות, ביקורת והערכה של מה שקרה. השתמש בו בכל פעם שאתה רוצה ש-Failproof AI Observability יراقب את הסוכנים שלך.

בעומק, ה-SDK כותב אירועים מובנים לקבצי JSONL מקומיים, ודומון האספן אוסף אותם ושולח אותם לפלטפורמה באופן אוטומטי. אתה לא מנהל את הקבצים האלה בעצמך.

> **Tip:** חדש ל-Failproof AI Observability? דף זה הוא הרשימה המלאה של אירועי ה-SDK.

## Installation

ה-SDK מופץ ללקוחות כ-wheel פרטי ולא מאינדקס חבילות ציבורי. ההטמעה שלך מכסה כיצד להשיג אותו, להתקין אותו ולקבע אותו — דברו עם איש הקשר של Failproof AI שלך אם אתה זקוק לגישה.

לאחר התקנתו, אשר שיש לך אותו:

```bash
python -c "import agenteye; print(agenteye.__version__)"
```

מעדיף לתת לסוכן קידוד לטפל בכל ההשתלבות? [Python SDK Agent Skill](/he/agenteye/python-sdk-skill) יודע את נתיב ההתקנה, מתכנן את נקודות הציוד, כותב אותן ומאמת שהאירועים מגיעים.

## Quick Start

```python
import agenteye

agenteye.configure(environment="production")

agenteye.event.agent_start(session_id="run-001", agent_id="planner", goal="answer user query")

agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    input={"query": "latest AI research"},
)

agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    output={"results": ["..."]},
)

agenteye.event.agent_end(session_id="run-001", agent_id="planner", outcome="success")
```

### Instrumenting a real call

בפועל אתה עוטף את קוד הסוכן הקיים שלך. בטל קריאת מודל עם `model_request` לפני ו-`model_response` אחרי, כדי ששני האירועים יתפרסו על הבקשה האמיתית וה-Failproof AI Observability יוכל לזווג אותם:

```python
import anthropic
import agenteye

agenteye.configure(environment="production")
client = anthropic.Anthropic()

messages = [{"role": "user", "content": "Summarise today's incidents."}]

agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6",
    messages=messages,
)

reply = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=512,
    messages=messages,
)

agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model=reply.model,
    stop_reason=reply.stop_reason,
    input_tokens=reply.usage.input_tokens,
    output_tokens=reply.usage.output_tokens,
    content=[block.model_dump() for block in reply.content],
)
```

עטוף קריאות כלים באותו אופן עם `tool_use` ו-`tool_result`, תוך שימוש חוזר באותו `tool_call_id` על פני הצמד.

הנה איך נראים אירועים אלה לאחר שהם מגיעים לדשבורד, קוד צבע לפי סוג וניתן לסינון לפי סביבה, סוכן וסשן:

## configure()

```python
agenteye.configure(
    base_dir=None,           # Path | str | None. Default: $AGENTEYE_HOME or ~/.agenteye
    flush_interval=0.5,      # float, seconds between flush cycles
    environment=None,        # str | None. Deployment environment label
)
```

התקשר פעם אחת לפני כל קריאת `event.*`. בטוח להשמיט; ברירות המחדל עובדות מחוסר הקופה. כל הארגומנטים הם רק מילות-מפתח; העבר אותם לפי שם כפי שמוצג לעיל.

כאשר `base_dir` הוא `None` (ברירת המחדל), ה-SDK קורא את `$AGENTEYE_HOME` אם הוא מוגדר, אחרת חוזר ל-`~/.agenteye`. זה תואם את ההחלטה של האספן שלו, אז משתנה סביבה יחיד `AGENTEYE_HOME` מגדיר את ספור האירועים המשותף עבור ה-SDK והאספן.

## Environment

תייגו כל אירוע עם סביבת פריסה (`production`, `staging`, `qa`, `canary` וכו'). הגדר אותו פעם אחת; ה-SDK מחבר אותו לכל אירוע באופן אוטומטי.

**Option 1: via `configure()`:**

```python
agenteye.configure(environment="production")
```

**Option 2: via environment variable:**

```bash
export AGENTEYE_ENVIRONMENT=production
```

**Priority:** `configure(environment=...)` מנצח משתנה הסביבה. אם לא מוגדר כלום, ברירת המחדל היא `"dev"`.

ערך הסביבה מופיע כמסנן מחלקה ראשונה בדשבורד ומאוחסן בשרת לשאילתות מהירות.

> **Warning:** ערכי סביבה חייבים שלא להכיל פסיק ליטרלי `,`. מסנני הדשבורד משתמשים בבחירה מרובה מופרדת בפסיקים על החוט (`?environment=prod,staging`), אז סביבה בשם `prod,blue` תחולק לשני ערכים. אירועים עם סביבות המכילות פסיקים נדחים בזמן הצמודים.

## Data and privacy

ה-SDK רושם רק את השדות שאתה מעביר בקביעות. Prompts, הודעות, כניסות והפקות כלים, ותוכן מודל נתפסים רק לכן שאתה מעביר אותם לקריאת `event.*`. כום לא נקרא מהתהליך שלך או נתפס בעקיפין. כל שדה שתשאיר ללא הגדרה מושמט מהאירוע כולו; זה לא כתוב לדיסק.

זה הופך את הריזוקציה לבחירה שלך ולאחריות שלך. אם prompt או payload כלי מכיל PII או סודות שלא היית רוצה לאחסן, הסר או mask זה לפני שתעביר אותו לשיטת האירוע.

## Event Reference

רוב האירועים מגיעים בזוגות התחלה/סיום החולקים מזהה קורלציה: `tool_use` ו-`tool_result` חולקים `tool_call_id`, `hook_triggered` ו-`hook_completed` חולקים `hook_id`, ו-`human_wait` ו-`human_input` חולקים `input_id`. פלוט את אירוע ההתחלה, בצע את העבודה, ואז פלוט את אירוע הסיום עם אותו מזהה. Failproof AI Observability תתאים את הצמד ותחשב `duration_ms` עבורך, אז אתה לעולם לא עובר `duration_ms` בעצמך.

![A session's git-style execution graph beside its event timeline, reconstructed from the paired events, with the tool/model/hook breakdown panel](/agenteye/images/session-detail.png)

כל שיטות האירוע דורשות שני שדות אלה:

| Field | Type | Description |
|---|---|---|
| `session_id` | `str` | זיהוי ריצת הסוכן ברמה העליונה |
| `agent_id` | `str` | זיהוי איזה סוכן בתוך הסשן פלט את האירוע |

כל השיטות מקבלות גם `**kwargs` שרירותי עבור metadata מותאם (ראה [Custom Fields](#custom-fields)).

---

### `event.agent_start()`

פלט כאשר סוכן מתחיל לעבוד.

```python
agenteye.event.agent_start(
    session_id="run-001",
    agent_id="planner",
    goal="answer user query",   # str | None
    parent_id=None,             # str | None - parent agent_id for nested agents
)
```

---

### `event.agent_end()`

פלט כאשר סוכן מסיים לעבוד.

```python
agenteye.event.agent_end(
    session_id="run-001",
    agent_id="planner",
    outcome="success",          # str | None
    summary="Answered query",   # str | None
)
```

---

### `event.tool_use()`

פלט כאשר סוכן מזמן כלי. זווג עם `tool_result`; ה-SDK חושב `duration_ms` אוטומטית.

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",     # str, required
    tool_call_id="toolu_01",    # str, required - correlation key for the matching tool_result
    input={"query": "..."},     # dict | None
)
```

---

### `event.tool_result()`

פלט כאשר כלי חוזר. מתואם עם `tool_use` דרך `tool_call_id`.

```python
agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",        # must match the prior tool_use
    output={"results": ["..."]},    # Any | None
    error=None,                     # str | None - set if the tool raised
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.model_request()`

פלט רגע לפני שליחת prompt ל-LLM.

```python
agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    messages=[                   # list[dict] | None - conversation turns
        {"role": "user", "content": "..."},
    ],
    system="You are helpful.",   # Any | None - str or list of content blocks
    tools=[                      # list[dict] | None - tool schemas offered to the model
        {"name": "search", "input_schema": {"type": "object"}},
    ],
)
```

ערכי `messages` מקבלים `content` מחרוזת פשוטה או Anthropic-style list-of-blocks `content`. params דגימה (`temperature`, `max_tokens` וכו') יכולים להיות מועברים כ-kwargs נוסף.

---

### `event.model_response()`

פלט כאשר ה-LLM מחזיר תגובה.

```python
agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    stop_reason="end_turn",     # str | None
    input_tokens=1024,          # int | None
    output_tokens=256,          # int | None
    content=[                    # Any | None - str, or list of content blocks
        {"type": "text", "text": "..."},
    ],
    role="assistant",            # str | None
)
```

`content` מקבל מחרוזת פשוטה (ספקים גנריים) או רשימה של Anthropic-style content blocks. קריאות כלים חיות בתוך `content` כבלוקים `{"type": "tool_use", ...}`, ללא שדה `tool_calls` נפרד.

---

### `event.hook_triggered()`

פלט כאשר hook שורה. זווג עם `hook_completed`; ה-SDK חושב `duration_ms` אוטומטית.

```python
agenteye.event.hook_triggered(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",   # str, required
    hook_id="hook-abc",         # str, required - correlation key
    trigger_event="tool_use",   # str | None
    input={"tool": "search"},   # Any | None
)
```

---

### `event.hook_completed()`

פלט כאשר hook מסיים. מתואם עם `hook_triggered` דרך `hook_id`.

```python
agenteye.event.hook_completed(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",
    hook_id="hook-abc",         # must match the prior hook_triggered
    outcome="allow",            # str | None
    output=None,                # Any | None
    error=None,                 # str | None
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.error()`

פלט כאשר שגיאה שלא טיפלת בה מתרחשת.

```python
agenteye.event.error(
    session_id="run-001",
    agent_id="planner",
    error_type="TimeoutError",  # str, required
    message="timed out",        # str, required
    traceback="Traceback...",   # str | None
)
```

## Human-in-the-Loop Events

אירועי Human-in-the-loop נותנים לך פיקוח על הרגעים שבהם אדם נכנס לביצוע הסוכן (המתנה לאישור, מתן קלט, עצירה או עצירת הסוכן). הם מאפשרים לך למדוד כמה זמן לוקח לבני אדם להגיב (ה-SDK מחשב `duration_ms` אוטומטית על האירועים המזווגים), ביקורת מי השהה או הפריע לסוכן, ובנייה של זרימות אישור והשגחה שמופיעות בדשבורד.

### `event.human_wait()`

פלט כאשר הסוכן עוצר את הביצוע כדי להמתין לאדם להספקת קלט. זווג עם `human_input`; ה-SDK מחשב `duration_ms` אוטומטית (כמה זמן לקח לאדם להגיב).

```python
agenteye.event.human_wait(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",                          # str, required - correlation key for the matching human_input
    prompt="Do you approve this action?",        # str | None - the question shown to the human
    options=["approve", "reject", "defer"],      # list[str] | None - choices presented to the human
    reason="approval_required",                  # str | None - why the agent is waiting
)
```

### `event.human_input()`

פלט כאשר אדם מספק קלט והסוכן מתחדש. מתואם עם `human_wait` דרך `input_id`. `duration_ms` מחושב אוטומטית ולא חייב להיות מועבר על ידי הקורא.

```python
agenteye.event.human_input(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",    # str, required - must match the prior human_wait
    response="approve",    # str | None - the human's answer (free text or selected option)
    # duration_ms is computed automatically - do not pass it
)
```

### `event.human_pause()`

פלט כאשר אדם פעיל עוצר את הסוכן (למשל דרך בקרה בדשבורד). הסוכן מושעה אך לא מסתיים.

```python
agenteye.event.human_pause(
    session_id="run-001",
    agent_id="planner",
    reason="user_requested",  # str | None
    user_id="usr_42",         # str | None - who paused the agent
)
```

### `event.human_interrupt()`

פלט כאשר אדם פעיל עוצר את הסוכן באמצע ביצוע. בשונה מ-`human_pause`, עבודת הסוכן מסתיימת ולא מושעה.

```python
agenteye.event.human_interrupt(
    session_id="run-001",
    agent_id="planner",
    reason="output_incorrect",       # str | None
    user_id="usr_42",                # str | None - who interrupted the agent
    at_step="tool_use:web_search",   # str | None - what the agent was doing when stopped
)
```

## Custom Fields

כל ארגומנטים ה-keyword נוספים מוספים לאירוע אחרי השדות הסטנדרטיים:

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="db_query",
    tool_call_id="toolu_02",
    tenant_id="acme",           # custom field
    region="us-east-1",         # custom field
)
```

`timestamp`, `type` ו-`environment` שמורים ועלולים להעלות `ValueError` (`Reserved field names cannot be used as custom fields: [...]`) אם מועברים כשדות מותאמים. `session_id` ו-`agent_id` הם פרמטרים נדרשים בכל שיטת אירוע ולא ניתן לספק אותם פעם שנייה; Python עלול להעלות `TypeError` אם אתה עושה זאת. הגדר את הסביבה עם `configure(environment=...)` (או משתנה `AGENTEYE_ENVIRONMENT`) במקום.

שמור payloads כ-JSON מובנה כאשר אתה רוצה לשאול את השדות שלהם. ערכים שה-JSON לא תמיד תומך בהם — כגון datetimes, UUIDs, decimals, sets, bytes, או objects מודל — מומרים לחוטים כדי שהתיעוד ימשיך בבטחה.

## How Events Are Written

אירועים buffered בתהליך ו-flushed לדיסק כל `flush_interval` שניות (500 ms כברירת מחדל). כל flush כותב קובץ JSONL אחד:

```text
~/.agenteye/events/event-2026-04-01T12-00-00-000Z.jsonl
```

האספן מפקח על תיקייה זו ומעלה קבצים באופן אוטומטי. אתה לא צריך לנהל את הקבצים האלה ישירות.

כל קובץ כתוב באופן אטומי: ה-SDK כותב לקובץ זמני ואז שינוי שם אותו למקום, כדי שהאספן לעולם לא יראה קובץ חצי כתוב. flush סופי גם רץ כאשר התהליך שלך יוצא, אז אירועים buffered בפרק הזמן האחרון לא אבודים. אם האספן לא מקוון, אירועים פשוט מצטברים כקבצים על דיסק וחוצה ברגע שהוא חוזר.
