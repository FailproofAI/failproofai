מסמך זה מסביר כיצד failproofai עובד בפנים: כיצד מערכת ה-hook מיירטת קריאות כלי Agent, כיצד קונפיג מטוענת ומתמזגת, כיצד מדיניויות מוערכות, וכיצד לוח הבקרה עוקב אחר פעילות agent.

---

## סקירה כללית

ל-failproofai יש שתי תת-מערכות עצמאיות:

1. **Hook handler** - תהליך CLI מהיר שקורא Claude Code על כל קריאת כלי agent. מעריך מדיניויות וחוזר עם החלטה.
2. **Agent Monitor (Dashboard)** - יישום ווב Next.js לניטור נתונים של agent וניהול מדיניויות.

שתי התת-מערכות חולקות קבצי קונפיג ב-`~/.failproofai/` ובתיקיית `.failproofai/` של הפרויקט, אך הן פועלות כתהליכים נפרדים ותקשרו רק דרך מערכת הקבצים.

## Hook handler

### שילוב עם Claude Code

כשאתה מריץ `failproofai policies --install`, הוא כותב רשומות כמו זו ל-`~/.claude/settings.json`:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "failproofai --hook PreToolUse"
          }
        ]
      }
    ],
    "PostToolUse": [ ... ]
  }
}
```

Claude Code אז מזמן את `failproofai --hook PreToolUse` כתהליך משנה לפני כל קריאת כלי, ומעביר עומס עבודה JSON על stdin.

### פורמט עומס עבודה

```json
{
  "session_id": "abc123",
  "transcript_path": "/home/user/.claude/projects/myproject/sessions/abc123.jsonl",
  "cwd": "/home/user/myproject",
  "permission_mode": "default",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": { "command": "sudo apt install nodejs" }
}
```

עבור `PostToolUse` events, העומס עבודה מכיל גם `tool_result` עם פלט הכלי.

המטפל אוכף מגבלת 1 MB ל-stdin. עומסי עבודה העולים על זה מושלכים וכל המדיניויות מתירות בתמונה.

### פורמט התגובה

**Deny (PreToolUse):**
```json
{
  "hookSpecificOutput": {
    "permissionDecision": "deny",
    "permissionDecisionReason": "Blocked by failproofai: sudo command blocked"
  }
}
```

**Deny (PostToolUse):**
```json
{
  "hookSpecificOutput": {
    "additionalContext": "Blocked by failproofai because: API key detected in output"
  }
}
```

**Instruct (כל event מלבד Stop):**
```json
{
  "hookSpecificOutput": {
    "additionalContext": "Instruction from failproofai: Verify tests pass before committing."
  }
}
```

**Stop event instruct:**
- קוד יציאה: `2`
- סיבה כתובה ל-stderr (לא stdout)

**Allow:**
- קוד יציאה: `0`
- stdout ריק

**Allow עם הודעה:**

`allow(message)` מאפשר למדיניות לשלוח הקשר מידע חזרה ל-Claude גם כשהפעולה מורשית. מטפל ה-hook כותב את ה-JSON הבא ל-**stdout** (לא קובץ קונפיג — זו תגובת המטפל ל-Claude Code, בדיוק כמו תגובות deny ו-instruct לעיל):

```json
// Written to stdout by the hook handler process
{
  "hookSpecificOutput": {
    "additionalContext": "All CI checks passed on branch 'feat/my-feature'."
  }
}
```
- קוד יציאה: `0` (הפעולה מורשית)
- כשמדיניויות מרובות חוזרות `allow` עם הודעה, ההודעות שלהן משולבות עם שורות חדשות ל-`additionalContext` יחיד
- אם לא מדיניות מספקת הודעה, stdout ריק (כמו לפני)

### צינור עיבוד

`src/hooks/handler.ts` מיישם את צינור מלא:

```text
stdin JSON
  → parse payload (max 1 MB)
  → extract session metadata (session_id, cwd, tool_name, tool_input, etc.)
  → readMergedHooksConfig(cwd)    ← merges project + local + global config
  → register enabled builtin policies with resolved params
  → load custom policies from customPoliciesPath (if set)
  → register custom policies into policy registry
  → evaluate all policies (builtins first, then custom)
      → first deny short-circuits
      → instruct decisions accumulate
      → allow messages accumulate
  → write JSON decision to stdout
  → persist event to ~/.failproofai/hook-activity/current.jsonl
  → exit
```

כל התהליך פועל ב-פחות מ-100ms עבור עומסי עבודה טיפוסיים ללא קריאות LLM.

## טעינת הקונפיג

`src/hooks/hooks-config.ts` מיישם טעינת קונפיג בתלת-טווח.

```text
[1] {cwd}/.failproofai/policies-config.json        ← project  (highest priority)
[2] {cwd}/.failproofai/policies-config.local.json  ← local
[3] ~/.failproofai/policies-config.json             ← global   (lowest priority)
```

לוגיקת מזג:
- `enabledPolicies` - איחוד דטפוקט לכל שלושת הקבצים
- `policyParams` - מפתח למדיניות, הקובץ הראשון שמגדיר אותו מנצח לחלוטין
- `customPoliciesPath` - הקובץ הראשון שמגדיר אותו מנצח
- `llm` - הקובץ הראשון שמגדיר אותו מנצח

לוח הבקרה ממשי משתמש ב-`readHooksConfig()` (global בלבד) לקריאה וכתיבה, מכיוון שהוא לא מוזמן עם cwd של פרויקט.

## הערכת מדיניות

`src/hooks/policy-evaluator.ts` מריץ מדיניויות בסדר.

עבור כל מדיניות:

1. חפש את סכימה `params` של המדיניות (אם יש לה).
2. קרא `policyParams[policy.name]` מהקונפיג המתמזג.
3. מזג ערכים שסופקו על ידי משתמש על פני ברירות מחדל של סכימה כדי להפיק `ctx.params`.
4. קרא ל-`policy.fn(ctx)` עם ההקשר שנפתר.
5. אם התוצאה היא `deny`, עצור מיד והחזר את ההחלטה הזו.
6. אם התוצאה היא `instruct`, כנס את ההודעה והמשך.
7. אם התוצאה היא `allow`, המשך למדיניות הבאה.

לאחר שכל המדיניויות פועלות:
- אם `deny` הוחזר, פלוט את תגובת ה-deny.
- אם `instruct` מחזירים נאספו, פלוט תגובה `instruct` יחיד עם כל ההודעות משולבות.
- אחרת, פלוט תגובת allow (stdout ריק, יציאה 0).

## מדיניויות מובנות

`src/hooks/builtin-policies.ts` מגדיר את כל 39 המדיניויות המובנות כאובייקטי `BuiltinPolicyDefinition`:

```typescript
interface BuiltinPolicyDefinition {
  name: string;
  description: string;
  fn: (ctx: PolicyContext) => PolicyResult;
  match: {
    events: HookEventType[];
    tools?: string[];
  };
  defaultEnabled: boolean;
  category: string;
  beta?: boolean;
  params?: PolicyParamsSchema;
}
```

מדיניויות המקבלות `params` מטפלות ב-`PolicyParamsSchema` עם סוגים וברירות מחדל לכל פרמטר. מערכת הערכת המדיניות משדרת ערכים שנפתרו ל-`ctx.params` לפני קריאה ל-`fn`. פונקציות מדיניות קוראות ל-`ctx.params` ללא null-guarding מכיוון שברירות מחדל תמיד מיושמות תחילה.

התאמת דפוסים בתוך מדיניויות משתמשת בטוקנים מפורסמים של פקודות (argv), לא התאמה של מחרוזת גולמית. זה מונע עקיפה דרך הזרקת מפעיל shell (למשל, דפוס עבור `sudo systemctl status *` לא יכול להיות עקוף על ידי הוספת `; rm -rf /` לפקודה).

## מדיניויות מותאמות אישית

`src/hooks/custom-hooks-registry.ts` מיישם רישום `globalThis`-backed:

```typescript
const REGISTRY_KEY = "__failproofai_custom_hooks__";

export const customPolicies = {
  add(hook: CustomHook): void { ... }
};

export function getCustomHooks(): CustomHook[] { ... }
export function clearCustomHooks(): void { ... }  // used in tests
```

`src/hooks/custom-hooks-loader.ts` טוען קובץ מדיניות משתמש:

1. קרא `customPoliciesPath` מקונפיג; דלג אם לא קיים.
2. פתור לנתיב מוחלט; בדוק שהקובץ קיים.
3. כתוב מחדש את כל `from "failproofai"` imports לנתיב dist בפועל כדי `customPolicies` יפתור לאותו רישום `globalThis`.
4. כתוב מחדש ביחס הדדי imports מקומיות כדי להבטיח תאימות ESM.
5. כתוב קבצי `.mjs` זמניים ו-`import()` קובץ הרשומה.
6. קרא ל-`getCustomHooks()` כדי לאחזר hooks רשומה.
7. נקה את כל הקבצים הזמניים בבלוק `finally`.

בכל שגיאה (קובץ לא נמצא, שגיאת תחביר, כשל import), השגיאה מתועדת ל-`~/.failproofai/hook.log` והטוען חוזר מערך ריק. מדיניויות מובנות אינן מושפעות.

מדיניויות מותאמות אישית מוערכות לאחר כל המדיניויות המובנות. `deny` של מדיניות מותאמת אישית עדיין מקצר עוד יותר מדיניויות מותאמות אישית (אך כל המובנות כבר פעלו בנקודה זו).

## רישום פעילות

לאחר כל hook event, המטפל מוסיף שורת JSONL ל-`~/.failproofai/hook-activity/current.jsonl`, שמסתובב ל-`page-<timestamp>-<seq>.jsonl` ברגע שהוא מגיע לעמוד:

```json
{
  "timestamp": "2026-04-06T12:34:56.789Z",
  "sessionId": "abc123",
  "eventType": "PreToolUse",
  "toolName": "Bash",
  "policyName": "block-sudo",
  "decision": "deny",
  "reason": "sudo command blocked by failproofai",
  "durationMs": 12
}
```

שורה אחת למדיניות שעשתה החלטה שאינה allow. החלטות Allow לא מתועדות (כדי לשמור את הקובץ קטן).

## ארכיטקטורת לוח הבקרה

לוח הבקרה הוא יישום **Next.js 16** המשתמש ב-App Router עם React Server Components ו-Server Actions.

```text
app/
  layout.tsx                  ← Root layout (theme, telemetry, nav)
  projects/page.tsx           ← Server component: list all Claude projects
  project/[name]/page.tsx     ← Server component: list sessions in a project
  project/[name]/session/
    [sessionId]/page.tsx      ← Server component: render session viewer
  policies/page.tsx           ← Client component: policy management + activity log
  actions/
    get-hooks-config.ts       ← Read config + policy list
    update-hooks-config.ts    ← Toggle policy on/off
    update-policy-params.ts   ← Update policy parameters
    get-hook-activity.ts      ← Paginate/search activity log
    install-hooks-web.ts      ← Install/remove hooks from the browser
  api/
    download/[project]/[session]/route.ts   ← Per-CLI session export (JSONL or JSON)
```

**זרימת נתונים:**

- רכיבי Page קוראים ל-`lib/projects.ts` ו-`lib/log-entries.ts` כדי לקרוא נתוני פרויקט/נתון ישירות מהמערכת של הקבצים (אין שכבת API לקריאות).
- דף Policies משתמש ב-Server Actions לכל מוטציות (toggle, update params, install/remove).
- צופה נתונים מנתח פורמט JSONL של Claude transcript ומעביר ציר זמן של הודעות וקריאות כלים.

**החלטות עיצוב עיקריות:**

- בלא בסיס נתונים - כל המצב הקבוע נמצא בקבצים רגילים (`~/.failproofai/`, `~/.claude/projects/`).
- Server Actions עבור מוטציות - לא צריך REST API עבור פעולות CRUD.
- React Server Components עבור עמודי קריאה - טעינה ראשונית מהירה יותר, אין חבילה לקוח לאחזור נתונים.
- רכיבי Client רק במקום בו נדרשת אינטראקטיביות (toggles מדיניות, חיפוש פעילות, צופה log).
