התרעות משגרות עיניים על תנאי הניתן למדידה ויוצרות תקרית כאשר הוא מופעל. השתמש בהן כאשר כישלון צריך לייצר תגובה במהלך הזמן, בין אם מדיניות יכולה לחסום זאת ובין אם לא.

## יצירה ובדיקה של התרעה

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Analyze → Alerts** ובחר **new alert**. אתה יכול גם להתחיל מהפעמון בטעות מייצגת.
    2. הזן את השם, החומרה, סוג ההפעלה, התנאי, מרווח ההערכה, ספירת ההפרה, החלון והערוצים.
    3. שמור את ההתרעה, פתח את דף הפרטים שלה והשהל **test**.
    4. עבור אל **Analyze → Issues** כדי להודות, להקצות, לדון, להירשם ולפתור תקריות שנוצרו על ידי ההתרעה.

    החלק הראשון של הטופס מזהה את ההתרעה והאות שצריכה להפעיל אותה.

    ![החלק הראשון של טופס new-alert עם השם, התיאור, מצב ממוכן וסוג הפעלה שלו.](/images/dashboard/alert-new-trigger.png)

    החלק השני שולט על כמה זמן התנאי חייב להתמשך, כמה פעמים הוא מוערך והיכן נשלחות הודעות.

    ![החלק השני של טופס new-alert עם לוגיקת הפרה, לוח זמנים, חומרה, ערוצי משלוח ופעולת יצירה.](/images/dashboard/alert-new-routing.png)

    לאחר השמירה, השתמש ברשימת ההתרעות כדי לאשר שהכלל מופעל וכי ההפעלה, החלון, החומרה והערוצים שלו תואמים את מה שהתכוונת.

    ![דף ההתרעות המציג כללי התרעה עם ההפעלה, חלונות ההערכה, הערוצים וחומרתם.](/images/dashboard/alerts.png)

    בדוק את ההתרעה לפני התלות בה לתגובה בייצור.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp alerts create high-errors \
      --trigger-kind metric_threshold \
      --severity warning \
      --trigger-spec '{"metric":"error_count","op":">","value":50,"window_secs":900}'

    fp alerts show high-errors
    fp alerts test high-errors
    fp alerts update high-errors --severity critical --yes
    ```

    השתמש ב-`fp alerts list` כדי לבדוק כללים והשתמש ב-`fp alerts delete <name>` כדי להסיר אחד.

    ראה את ההפניה [`fp alerts`](/he/reference/cloud-cli#alerts) לקבוצת הפקודה השלמה של ההתרעה.
  </Tab>
</Tabs>

תנאי התרעה יכולים להיות מבוססים על שגיאות, ציוני הערכה, שילובי הערכה או SQL מותאם. הוסף מקבלים, בדוק את הכלל ופתח את התקרית שנוצרה כדי להודות, להקצות, להגיב, להירשם ולפתור אותה.

## עיצוב התרעה טוב

- תן שם לתנאי וזרימת העבודה המושפעת.
- הגבל את הסביבה בבירור.
- הגדר חלון וסף שמונעים תגובה לאירוע אחד חסר מזיק.
- כלול קישור או שאילתה המוביל את גורמי התגובה להפעלות.
- הקצה בעלים לפני הפעלת הכלל.

<Tip>
  לאחר פתרון ממצא ביקורת, הוסף התרעה כאשר אותו כישלון יכול להתרחש מחדש מחוץ לכיסוי המדיניות.
</Tip>
