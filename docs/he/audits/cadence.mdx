השתמשו בביקורות חוזרות עבור מצבי כשל שיכולים להופיע מחדש כאשר סוכנים, הנחיות, כלים ודגמים משתנים.

## שינוי התוכנית

<Tabs>
  <Tab title="Dashboard">
    1. עברו ל-**Analyze → Audits** ופתחו את הביקורת.
    2. פתחו את ההגדרות שלה ושנו את מצב ההפעלה, המרווח, עוגן UTC, מצב החלון או ההסתכלות לאחור.
    3. שמרו את הביקורת והאשרו את זמן ההרצה הבא בכרטיס הביקורת.
    4. השתמשו ב-**run now** פעם אחת לאחר שינוי היקף או הקשר משמעותי.

    ![עורך הביקורת המציג תדירות, חלון גריפה, היקף, הגדרות ניתוח, הקשר וערוצי התראה.](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    ראו את ה-[ייחוס `fp audits`](/he/reference/cloud-cli#audits) לגבלות תוכנית, התנהגות חלון וכל פקודות הביקורת.
  </Tab>
</Tabs>

בחרו תדירות מהירות וממחיר הסיכון:

| דפוס סיכון | תדירות התחלה |
| --- | --- |
| פעולה בייצור בהשפעה גבוהה | יומי |
| רגרסיה של סרטון עבודה או דגם | שבועי |
| סקירת כיצה או גישה | חודשי |
| חקירת שחרור חד-פעמי | הרץ פעם אחת |

הרימו את חלון ההסתכלות לאחור עם התדירות כך שהריצות לא יעזבו פערים וגם לא יבדקו שוב אוכלוסיה גדולה במיותר. לאחר שינוי המטרה או ההקשר של ביקורת, הריצו אותה ידנית פעם אחת לפני שאתם מסתמכים על התוצאה המתוזמנת הבאה.

<Note>
  ביקורות מתוזמנות מקומיות מוגדרות במכונה וסורקות היסטוריית סוכנים מקומית. לוחות זמנים של ביקורות ענן מופעלים בהפגנות Cloud. התייחסו לתוצאות שלהם והבעלות בנפרד.
</Note>
