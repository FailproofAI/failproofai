ממצא הוא הצהרה המתבססת על ראיות של הביקורת אודות כשל. בעיה היא תהליך העבודה הקבוע להתגובה אליה.

## מיון והקצאת העבודה

<Tabs>
  <Tab title="לוח בקרה">
    1. פתחו את **Analyze → Audits**, בחרו ריצה שהושלמה, ובחרו ממצא כדי לבדוק את הניתוח שלו, ההמלצה, הסשנים, ושאילתות הראיות.
    2. אשרו, הקצו, דחו, השתיקו, פתרו, או פתחו מחדש את הממצא לאחר בדיקת הראיות שלו.
    3. עברו ל-**Analyze → Issues** וסננו את תיבת הדואר הקבועה לפי סטטוס, חומרה, או מוקצה.
    4. פתחו את הבעיה כדי להקצות אותה, הוסיפו הערות או מנויים, ופתרו אותה לאחר אימות התיקון.

    התחילו בסיכום הממצא. אשרו שתיאור הכשל, התגובה המומלצת, החומרה, והדירוג מסכימים עם הסשנים שציפיתם שהביקורת תבחן.

    ![ממצא ביקורת עם חומרה, ספירת מופעים, ניתוח סיבה שורש, פעולה מומלצת, גורמי דירוג, וראיות.](/images/dashboard/audit-finding.png)

    לאחר מכן, פתחו סשן מושפע במקום להחליט רק מהסיכום. העקבול המקושר צריך להציג את האירוע המדויק ו-payload התומכים בממצא.

    ![סשן המקושר מממצא ביקורת, שנפתח בשגיאה הרלוונטית עם מטא-נתוני האירוע ו-payload גולמי.](/images/dashboard/audit-linked-session.png)

    לאחר אימות הראיות, השתמשו ב-Issues כדי לתת לתגובה בעלים ולעקוב אחריה בעצמאות מריצות ביקורת עתידיות.

    ![תיבת הדואר של Issues המציגה עבודה ממלאת, מאושרת, ופתורה עם חומרה ובעלות.](/images/dashboard/incidents.png)

    פתחו את הבעיה כדי להקליט הערות חקירה, להודיע למנויים, ולשמור על היסטוריית התגובה. פתרו אותה רק לאחר פריסת התיקון ואימותו.

    ![תצוגה מפורטת של בעיה עם המקור שלה, ראיות הפרה, מוקצים, מנויים, ציר זמן, והערות.](/images/dashboard/incident-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits findings --audit checkout-reliability --status open
    fp audits finding <finding-id>
    fp audits ack <finding-id> --reason "owner assigned"
    fp audits assign <finding-id> --to engineer@example.com

    fp issues list
    fp issues show <issue-id>
    fp issues assign <issue-id> --assignee engineer@example.com
    fp issues comment-add <issue-id> --body "policy is in observe mode"
    fp issues resolve <issue-id> --yes
    ```

    השתמשו ב-`fp issues subscribe <issue-id>`, `fp issues unsubscribe <issue-id>`, ו-`fp issues subscribers <issue-id>` כדי לנהל משקיפים.

    ראו את [ההתייחסות למודול ביקורת וסוגיות של Cloud CLI](/he/reference/cloud-cli#audits) ממצאי ביקורת ו-[`fp issues`](/he/reference/cloud-cli#issues) לניהול בעיות.
  </Tab>
</Tabs>

## בדוקו ממצא

אשרו שהוא מכיל:

- מצב כשל יציב, לא רק כותרת חד-פעמית
- חומרה והשפעה תפעולית
- מזהי סשן מושפעים או שאילתות תומכות
- הקשר מספיק כדי לשחזר את ההתנהגות
- תגובה מוצעת התואמת את הראיות

## השתמשו בבעיה כדי לנהל את התגובה

יצרו או קשרו בעיה כאשר הממצא זקוק להקצאה, דיון, שינויי סטטוס, הערות, או מנויים. בעיות יכולות גם לייצג תחזוקות אזעקה וסוגיות שדווחו ידנית, וזו הסיבה שהן נמצאות תחת תגובת ביקורת ולא בניווט ראשי.

פתרו את הבעיה כאשר התיקון פרוס ומאומת. פתרו את הממצא כאשר מצב הכשל טופל עבור אוכלוסיית הביקורת. רגעים אלה עלולים להיות שונים.

## הפכו בעיה לטיוטת מדיניות

<Tabs>
  <Tab title="לוח בקרה">
    1. פתחו את הבעיה ובדקו את הממצא שלה, הסשנים המצוטטים, הסיבה שורש, וההמלצה.
    2. בחרו **generate policy** ובדקו את תוצאת הכשירות וכוונת האכיפה המוצעת. תוצאה של **no policy** פירושה שההתנהגות עשויה לדרוש אזעקה, שינוי זרימת עבודה, או תגובה אנושית במקום.
    3. בחרו **write this policy**, לאחר מכן בדקו וחנו את המקור שנוצר ב-**Admin → policy editor** לפני בחירה ב-**publish version**. השתמשו ב-**open the editor anyway** כאשר אתם לא מסכימים עם בדיקת הכשירות.
    4. עברו ל-**Admin → enforcement**, פרסו את הגרסה במצב **observe**, ובדקו את ההחלטות שלה תחת **Observe → policy** לפני אכיפה.

    כותרת הבעיה, תיאור הממצא, הסיבה שורש, ההמלצה, וכוונת הכשירות עוזרים להרכיב את הטיוטה. שום דבר לא פורסם או פורסם בצורה אוטומטית.
  </Tab>
  <Tab title="CLI">
    השתמשו ב-CLI כדי לבדוק את הראיות לפני פתיחת הבעיה בלוח הבקרה:

    ```bash
    fp issues show <issue-id>
    fp audits finding <finding-id>
    fp events --session-id <session-id> --full --all
    ```

    כשירות מדיניות, פרסום Cloud, ופריסת צי הם זרימות עבודה של לוח בקרה. השתמשו ב-`failproofai policies --install --custom <file>` כאשר אתם רוצים לאמת תחילה מקור מדיניות שווה ערך באופן מקומי.
  </Tab>
</Tabs>
