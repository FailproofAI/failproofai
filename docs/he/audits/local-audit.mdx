本地审核读取已在此机器上的代理历史，并在 `http://localhost:8020/audit` 上打开结果。它不需要帐户。

```bash
failproofai audit
```

扫描涵盖它找到的所有支持的工具的历史。它重放此版本中内置的 39 项政策目录；不包括已安装的包和自定义政策。

## 读取结果

从最常见的发现开始，然后在启用强制执行前打开受影响的会话。

三个限制很重要：

- 审核重建工具事件，而不是 `Stop`，所以 `require-*-before-stop` 政策不会出现。
- 八项"仅审核"检查可识别浪费模式，而无需完全匹配的政策。
- `warn-repeated-tool-calls` 被跳过，因为重放它会修改记录端的状态。

对于可强制执行的发现，使用结果中显示的政策命令。在依赖它之前，检查[工具强制执行支持](/he/reference/harnesses#enforcement-capability)。

缓存的结果位于 `~/.failproofai/audit/dashboard.json`，七天后过期。

## 安排扫描

```bash
failproofai audit --schedule 7
failproofai audit --status
failproofai audit --no-schedule
```

间隔接受 1–90 天，默认为 7。首次安排需要交互式登录。后台服务必须运行。

### 什么会离开机器

交互式审核不发送任何发现。默认启用匿名 CLI 遥测；使用 `FAILPROOFAI_TELEMETRY_DISABLED=1` 禁用它。

选择调度后，每次计划扫描都会发送机器 ID、标签、平台和扫描窗口。如果发现有害模式，它还会发送包含计数、时间戳和最多三个已编辑示例的有限摘要。清洁扫描不发送任何发现和电子邮件。

<Warning>
  审核结果是供审查的证据，不是证明每个标记的操作都不安全。在将发现转换为阻止强制执行之前，检查会话。
</Warning>
