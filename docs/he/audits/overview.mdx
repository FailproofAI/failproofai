## ביקורת מקומית או בענן

| | ביקורת מקומית | ביקורת בענן |
| --- | --- | --- |
| פקודה | `failproofai audit` | `fp audits` |
| קורא מ | היסטוריית סוכנים במחשב זה | הפעלות בארגון ענן שלך |
| מייצר | תוצאות מקומיות ב-`localhost:8020/audit` | ממצאים משותפים, בעיות, והתרעות |
| דורש | ללא חשבון | חיבור ענן ומפתח API |

השתמש בביקורת מקומית לסקר מהיר של מחשב אחד. השתמש בענן כאשר לצוות נדרשת ביקורת חוזרת על סוכנים ומחשבים.

## שאלות שביקורת יכולה לענות עליהן

- איפה סוכנים עוצרים ללא הסלמה?
- אילו כשלי כלים מובילים לנסיונות חוזרים לא יעילים?
- האם סוכנים ניגשים לנתונים מחוץ לזרימת העבודה המיועדת?
- מה השתנה לאחר עדכון מודל, הנחיה, או כלי?

## פתח ביקורות בענן

עבור אל **Analyze → Audits**, או השתמש ב:

```bash
fp audits list
fp audits show <audit-name>
fp audits findings --status open --limit 20
```

פקודות ביקורת משתמשות בשם הביקורת או במזהה מלא. ממצאים מועברים לפי מזהה שלהם.

## מממצא למניעה

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert
```

ממצא מצביע על עדות. בעיה בעלת אחריות התגובה. מדיניות מונעת דפוס פעולה ידוע; התרעה צופה בחזרה על ההתרחשות.

לא כל ממצא צריך להפוך למדיניות. ממצא `policy` מתאר כלל שניתן להוציא לפועל. `failure` או `improvement` עשויים להצריך שינוי בזרימת עבודה, הנחיה, מודל, או כלי בחום.
