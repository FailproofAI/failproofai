審核חוקר קבוצה נבחרת של סשנים למטרת כשל מוגדרת. הוא משלב עדויות מעקב, תוצאות הערכה, טביעות מדיניות, והקשר ייחוס כדי להפיק ממצאים שתוכל לפעול עליהם.

ראה כיצד審核 עובר מריצה מתוזמנת לכשלים מגובי עדויות שתוכל לתקן.

## פתח審核

<Tabs>
  <Tab title="Dashboard">
    עבור אל **Analyze → Audits**. הדף מציג מצב מתוזמן, ממצאים פתוחים, ריצה אחרונה, ריצה הבאה, קדנציה, והאם ל審核 יש דפי brief או reference. בחר בכרטיס לקביעות והיסטוריית ריצות; בחר **new audit** כדי ליצור אחד.

    ![דף Audits המציג審核 חוזרים עם לוח הזמנים, הרגישות, ומצב הריצה שלהם.](/images/dashboard/audits.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

השתמש ב審核 כאשר אתה צריך לענות על שאלה ברמת אוכלוסיה כגון:

- היכן agents מנטשים משימות ללא הסלמה?
- אילו כשלי כלי מובילים לניסיונות חוזרים לא יעילים?
- האם agents ניגשים לנתונים מחוץ לתזרים העבודה המיועד?
- מה השתנה לאחר שחרור מודל, prompt, או כלי?

## זרימת תגובת審核

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert for recurrence
```

ממצא צריך לתת שם למצב הכשל ולהצביע על עדות. Issue שולט בתיקון. Policy מונע דפוס פעולה ידוע; alert גוזל חזרה כאשר מניעה אינה אפשרית או זקוקה לניטור.
