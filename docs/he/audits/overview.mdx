ביקורת חוקרת קבוצה נבחרת של הפעלות בחיפוש אחר מטרת כשל מסוימת. היא משלבת ראיות עקבות, תוצאות הערכה, פגיעות בנהלים והקשר התייחסות כדי לייצר ממצאים שעליהם תוכל לפעול.

ראה כיצד ביקורת עוברת מריצה מתוזמנת לכשלים תמוכים בראיות שתוכל לתקן.

## פתח ביקורות

<Tabs>
  <Tab title="Dashboard">
    עבור אל **Analyze → Audits**. הדף מציג מצב מתוזמן, ממצאים פתוחים, ריצה אחרונה, ריצה הבאה, קדנציה, והאם לביקורת יש עמודי תיאור קצר או התייחסות. בחר בכרטיס להגדרות והיסטוריית ריצה; בחר **new audit** כדי ליצור אחד.

    ![עמוד הביקורות המציג ביקורות חוזרות עם לוח הזמנים, הרגישות ומצב הריצה שלהם.](/images/dashboard/audits.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

השתמש בביקורת כאשר עליך לענות על שאלה ברמת אוכלוסיה כגון:

- היכן סוכנים נטשים משימות ללא הסלמה?
- אילו כשלי כלים מובילים לנסיונות חוזרים לא יעילים?
- האם סוכנים ניגשים לנתונים מחוץ לזרימת העבודה המכוונת?
- מה השתנה לאחר שחרור מודל, הנחיה או כלי?

## זרימת תגובה ביקורת

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert for recurrence
```

ממצא צריך לשמור את מצב הכשל ולהצביע על ראיות. בעיה תחזיק בתיקון. נהל למנע דפוס פעולה ידוע; התראה גוזרת הישנות כאשר מניעה אינה אפשרית או צריכה ניטור.
