השתמש בהם כיעדים ראשוניים, ואז הוסף את הסוכן, הסביבה והזרימת העבודה הצפויה שלך.

<Tabs>
  <Tab title="Dashboard">
    עבור אל **Analyze → Audits → New audit**. שורת מתכון מעמוד זה היא ה**תיאור** — מה אתה מצפה שביקורת זו תתפוס. כללי הזרימה שהופכים את היעד לנשפט יעברו לתוך **הבריף שלך**, בכרטיסיית **מה זה יודע**: רקע שהמודל קורא לפני שהוא מסתכל על אירוע בודד, מוגבל ל-8,192 תווים, מתווסף למה שביקורת כבר מחפשת. בריף לעולם לא מחליף את היעד ולעולם לא הוכחה למציאה.

    אחר כך הגדר היקף ב**מה זה קורא**, כי חצי מהמתכונים האלה הם רעש ללא זה. סביבות וסוכנים מצמצמים את האוכלוסיה; **errors to ignore** מפרטת את סוגי השגיאות שאתה מצפה וטיפול בהם בעיצוב, כך שהם מפסיקים להיחשב ככשלים. זה לוקח רק שמות סוגי שגיאות, וזה מה שמונע מהמתכון של לולאת ניסיון מחדש מהצפה.

    טופס ביקורת חדש הופך מתכון לבדיקת כשל שניתנת להוצאה לפועל על ידי הוספת היקף, הקשר, קצב ודעות על התראות.

    ![טופס ביקורת חדש מוגדר עם יעד ממוקד, לוח זמנים, היקף סוכן וסביבה, הקשר וערוצי התראות.](/images/dashboard/audit-new.png)

    לאחר היצירה, אשר שביקורת מופיעה ברשימה עם הסטטוס והלוח הזמנים הצפויים לפני התיבה על ריצות חוזרות.

    פתח את הריצה הראשונה וחדד את המתכון אם הממצאים שלו רחבים או צרים יותר ממצב הכשל המיועד.
  </Tab>
  <Tab title="CLI">
    שמור מתכון כקובץ טקסט וצרף אותו במהלך היצירה:

    ```bash
    fp audits create retry-loop-review \
      --description "Find agents that repeat a failing tool call without changing anything" \
      --scope '{"environments":["production"]}' \
      --ignore-error-type RateLimitRetried \
      --text-file ./retry-loop-audit.txt \
      --schedule-interval-secs 86400
    ```

    `--text` ו-`--text-file` הן שתי דרכים לשלוח את אותו בריף; העבר אחד, לא שניים. הוסף עמודי התייחסות עם `--url`, עד חמישה, `https://` ציבורי בלבד. שלח את כל זה עם בקשת היצירה: ביקורת מופעלת חדשה מגיעה מיד, כך שהקשר שנכתב בקריאה שנייה עלול להחמיץ את הריצה הראשונה.
  </Tab>
</Tabs>

## שפוט את המתכון, לא רק את הניסוח

שתי הגדרות משנות את התוצאה יותר מהניסוח. **רגישות** (`low`, `medium`, `high`, ברירת מחדל `medium`) מחליטה כמה שמחדל ריצה מסמנת דפוס; **findings per run** (`--top-k`, ברירת מחדל 50) מגדיל כמה הוא שומר. הרם רגישות לשאלה שבה מהות עולה יותר מחיוב שגוי, והנמך אותה לדפוס כמות שאחרת היה מלא את התור. כל מתכון למטה מציין נקודת התחלה — שנה אותה לאחר קריאת הריצה הראשונה, לא לפני.

הטלת משימות וסקלנות אנוש שהוחמצו הם שיפוטים כנגד מה שסוכן היה אמור לעשות, לא כנגד שגיאה שהעלה. כתוב תחילה את [agent context](/he/audits/agent-contracts) של סוכן זה, או לניתוח אין תקן לדירוג נגדו.

<AccordionGroup>
  <Accordion title="לולאות ניסיון חוזרות">
    מצא הפעלות שבהן הסוכן חוזר על אותו קריאת כלי כושלת ללא שינוי קלט, בחירה בכלי חלופי או הסלמה לאדם.

    התחל ב-`medium`, ורשום את סוגי השגיאות שאתה מנסה שוב בכוונה תחת **errors to ignore**.
  </Accordion>
  <Accordion title="שימוש כלי שגוי">
    מצא הפעלות שבהן הכלי שנבחר אינו תואם את המשימה המוצהרת, או שבו קלט כלי מפר תנאים מקדימים נדרשים של זרימת העבודה.

    התחל ב-`medium`. שים את התנאים המקדימים עצמם בבריף; ללא זה לניתוח אין כלל לבדיקה.
  </Accordion>
  <Accordion title="גישה לנתונים לא בטוחה">
    מצא הפעלות שקוראות, כותבות או משדרות נתונים רגישים מחוץ לנתיבים ושירותים המאושרים לסוכן זה.

    התחל ב-`high`. חשיפה שהוחמצה עולה יותר מחיוב שגוי שאתה דוחה פעם אחת.
  </Accordion>
  <Accordion title="הטלת משימה">
    מצא הפעלות המסתיימות ללא התוצאה המבוקשת, שגיאה ברורה, או מסירה מפורשת לאדם.

    התחל ב-`medium`, וכתוב תחילה את פרק **Done when** של הסוכן — מתכון זה הוא שיפוט כנגדו.
  </Accordion>
  <Accordion title="הידרדרות בעלות או בהשהיה">
    מצא הפעלות שמודל, כלי או משך הזמן הכולל שלהן עולה על תקציב צפוי, וזהה את דפוס האירוע האחראי.

    התחל ב-`low` והרם אותו אם הריצה הראשונה דקה. תקציבים שייכים לבריף, וכל סוג שגיאה ששביל איטי מעלה בעיצוב שייך ב**errors to ignore**.
  </Accordion>
  <Accordion title="סקלנות אנוש שהוחמצה">
    מצא הפעלות שבהן ביטחון, כשל חוזר או הוראת מדיניות דרשה החלטה אנושית אך הסוכן המשיך בעצמאות.

    התחל ב-`high`, ודקלור את כלל ההסלמה בפרק **Must not** של הסוכן כך שהניתוח מדרג כנגדו.
  </Accordion>
</AccordionGroup>

## קבל תשובה ראשונה לפני שיצרת משהו

כמה מהדפוסים האלה כבר יש להם גלאים לא מקוונים בביקורת המקומית, אשר קוראת את הסטוריות סוכן במכונה שלך ולא צריכה חשבון:

| גלאי | דפוס שהוא סופר |
| --- | --- |
| `sleep-polling-loop` | `sleep` ארוך, או לולאת בדיקה `while … sleep … done` |
| `reread-after-edit` | קריאה של קובץ שהסוכן זה עתה ערך או כתב |
| `find-from-root` | `find` כנגד `/` או ספריה אחרת ברמה גבוהה |
| `redundant-cd-cwd` | `cd` לתוך הספריה שהעטפת כבר נמצאת בה |
| `prefer-edit-over-read-cat` | `cat`, `head`, `tail`, `less`, או `more` על קובץ מקור יחיד |
| `prefer-edit-over-sed-awk` | עריכות בהמקום דרך `sed -i` או `awk … > file` |
| `prefer-write-over-heredoc` | תוכן רב-שורה שנכתב דרך heredoc או `echo > file` |
| `git-commit-no-verify` | `git commit --no-verify`, דילוג על וו |

גלאים אלה סופרים; הם לא חוסמים, והשום אחד מהם לא מודד עלות או השהיה. הרץ `failproofai audit` כדי לראות אילו דפוסי קליפה בזבזניים וסכנה סוכנים שלך כבר מייצרים לפני ששלמת לביקורת Cloud של אותו קרקע — ראה [Audit local agent history](/he/audits/local-audit).
