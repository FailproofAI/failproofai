איכות הביקורת מתחילה בהיקפה. בקשה רחבה כמו "מצא בעיות" מייצרת תוצאות פחות שימושיות מאשר שאלת כשל קונקרטית.

## הגדרת הביקורת

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Analyze → Audits → New audit** והכנס שם ותיאור.
    2. הגדר את התדירות, חלון הזמן, היקף סוכן/סביבה, שגיאות שיתעלמו, רגישות וממצאים מרביים.
    3. ב**agents**, הוסף או בדוק הקשר סוכן, ואז הוסף את תיאור המפעיל וכל כתובות HTTPS ציבוריות.
    4. בחר ערוצי התראה ובחר **create audit**. ההרצה הראשונה בתור מיד.

    ![טופס הביקורת החדש עם שם, תיאור, תדירות, חלון, היקף סביבה וסוכן, שגיאות שיתעלמו, הגדרות ניתוח, תיאור, עמודי הפניה וערוצי התראה.](/images/dashboard/audit-new.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits create checkout-reliability \
      --description "Find checkout failures that agents do not recover from" \
      --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
      --schedule-interval-secs 86400 \
      --window-mode since_last \
      --sensitivity medium \
      --text-file ./checkout-audit-brief.txt \
      --url https://runbooks.example.com/checkout
    ```

    ההרצה הראשונה בתור מיד. כלול את התיאור וכתובות הייחוס במהלך יצירה כדי שהריצה תקבל אותם.

    ראה את ה[`fp audits create` reference](/he/reference/cloud-cli#audits) המלא.
  </Tab>
</Tabs>

<Tip>
  התחל עם סשן כשל ידוע וכמה סשנים רגילים. זה נותן לביקורת גם דוגמה חיובית וגם קבוצת השוואה.
</Tip>

<Info>
  הקשר ביקורת מאוחסן כמשאב שלו, ולכן עריכת ביקורת לא מסירה בטעות את חומר ההפניה.
</Info>
