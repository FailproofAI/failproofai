failproofai מגיע עם 39 מדיניות מובנות הקוטפות מצבי כשל נפוצים של סוכנים. כל מדיניות מופעלת על סוג אירוע hook ספציפי ושם כלי. תשע עשרה מדיניות מקבלות פרמטרים המאפשרים לך להתאים את התנהגותן ללא כתיבת קוד. חמש מדיניות זרימת עבודה אוכפות צנרת commit → push → PR → CI לפני שClaude עוצר.

מדיניות מקובצות לקטגוריות:

|----------|----------|-----------|
| [פקודות מסוכנות](#dangerous-commands) | block-sudo, block-rm-rf, block-curl-pipe-sh, block-failproofai-commands, block-self-pause | PreToolUse |

| [מסד נתונים](#database) | warn-destructive-sql, warn-schema-alteration | PreToolUse |
| [אזהרות](#warnings) | warn-large-file-write, warn-package-publish, warn-background-process, warn-global-package-install | PreToolUse |
| [מנהלי חבילות](#package-managers) | prefer-package-manager | PreToolUse |
| [זרימת עבודה](#workflow) | require-commit-before-stop, require-push-before-stop, require-pr-before-stop, require-no-conflicts-before-stop, require-ci-green-before-stop | Stop |

- **`block-`** — עצור סוכן מהמשך.
- **`warn-`** — תן לסוכן הקשר נוסף כדי שיוכל להתקן עצמי.
- **`sanitize-`** — תנקה נתונים רגישים מפלט כלי לפני שהסוכן רואה אותו.

### Namespaces

כל מדיניות גרה בחריץ `<namespace>/<name>`. מדיניות מובנות שייכות ל-namespace **`failproofai/`** — לדוגמה, `failproofai/sanitize-jwt`. ה-namespace מונע התנגשויות כאשר אתה גם טוען מדיניות מותאמות או של צד שלישי עם שמות קצרים דומים.

בתצורה שלך תוכל להתייחס ל-built-in בשם הקצר או בשם המתוקן; שני הטפוסים מתפזרים לאותה מדיניות:

```json
{
  "enabledPolicies": [
    "sanitize-jwt",
    "failproofai/block-rm-rf"
  ]
}
```

אם לשם אין `/`, failproofai מתייחס אליו כשייך ל-namespace ברירת המחדל `failproofai`. שמות שכבר מכילים `/` (למשל `myorg/foo`, `custom/my-hook`) נשמרים כשהם.
- **`require-`** — חסום את אירוע Stop עד שמתקיימים תנאים.

---

<Tip>
כל מדיניות תומכת בשדה `hint` אופציונלי ב-`policyParams`. ה-hint מתווסף להודעת deny או instruct שClaude רואה, ומספק הנחיה פעולה ללא שינוי קוד מדיניות. עובד עם מדיניות מובנות, מותאמות וקונוונציה. ראה [Configuration → hint](/he/configuration#hint-cross-cutting) לפרטים.
</Tip>

## פקודות מסוכנות

מנע סוכנים מהפעלת פעולות שקשה להביא אותן חזרה או שיכולות להזיק למערכת המארח.

### `block-sudo`

**Event:** PreToolUse (Bash)  
**Default:** דוחה כל פקודת `sudo` או `doas`.

חוסם פקודה שמפעילה בינארית הגבהה **בעמדת פקודה**. התאמה היא מבנית ולא טקסטית: הפקודה מתחלקת לקטעים כפי שמעטפת תעשה זאת, השמות קדם (`FOO=bar`), ההפניות, והרצים עם הדגלים שלהם (`env`, `nohup`, `timeout`, `xargs`, `sh -c`, …) מוסרים, והבינארי שנוצר מושווה לפי **basename**. כך `/usr/bin/sudo`, `env sudo`, `timeout 5 sudo`, `"sudo"`, `\sudo` ו-`bash -c "sudo …"` כולם דחויים, ו-`doas` מתייחס לאותה יכולת תחת שם אחר.

מכיוון שזה עוגן בעמדת פקודה ולא במילה המופיעה בכל מקום, זה **לא** מופעל בפקודות שפשוט מזכירות אותה — `grep -r sudo /etc`, `cat /etc/sudoers`, `git commit -m "fix sudo handling"`, או חילופי `grep` המכילים את המילה כולם פועלים בדרך כלל.

<Warning>
זה עוצר את הניסיון הברור; זה לא סוגר את המחלקה. סוכן שיכול להפעיל shell שרירותי עדיין יכול להגיע להגבהה בעקיפין — דרך משתנה (`S=sudo; $S …`), צנרת מפוענחת base64, או סקריפט wrapper בדיסק — מכיוון שאף בדיקה של מחרוזת פקודה בודדת לא יכולה לעקוב אחר אלה. התייחס לזה כמעקף נגד שגיאות והגבהה זדונית, לא כגבול ביטחוני נגד סוכן נחוש. גבול אמיתי צריך להיות אכוף מתחת ל-shell.
</Warning>

**Parameters:**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | קדימות פקודה מדויקות המותרות. כל ערך מותאם לאלטוקנים שנתחו. |

**Example:**

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    }
  }
}
```

עם הקונפיגורציה הזו, `sudo systemctl status nginx` מותר, אך `sudo rm /etc/hosts` דחוי.

<Note>
Pattern מותאמות לאלטוקנים שנתחו, לא למחרוזת פקודה גולמית. זה מונע bypass דרך אופרטורים shell מצורפים (למשל `sudo systemctl status x; rm -rf /` לא תואם `sudo systemctl status *`).
</Note>

### `block-self-pause`

**Event:** PreToolUse (Bash)  
**Default:** דוחה `failproofai config --pause`, המשהה אכיפה לסשן. השהיה היא החלטה אנושית — סוכן המסוגל להפעיל אותה יכול להדליק כל מדיניות אחרת עם פקודה יחידה.

צר יותר מ-[`block-failproofai-commands`](#block-failproofai-commands) בכוונה, ולא כלול בה: המדיניות הזו עוגן בגבול פקודה, כך `npx -y failproofai config --pause` לא תואם אותה, ובהיותה רחבה היא לעתים קרובות מושבתת כדי שסוכנים יוכלו להפעיל `failproofai audit`. `--resume` ו-`--status` מותרות — לא אחד מהם מסיר אכיפה.

זה עוצר את הניסיון הישיר, לא את כל המחלקה: סוכן עדיין יכול להגיע לאותו מצב דרך alias או סקריפט wrapper. סגירתו מלא דורשת את ההשהיה להיות בלתי ניתנת להשגה מקריאת כלי בכלל.

אין פרמטרים.

## פקודות תשתית

עצור סוכני קידוד מהפעלת CLIs תשתית או הדלקת צנרות CI/CD. כל המדיניות בקטגוריה זו היא **opt-in** (`defaultEnabled: false`) — סוכנים שלגיטימי צריכים להתקשר ל-`kubectl`, `terraform`, וכו' לא יופרעו אלא אם אתה מפעיל את המדיניות. כאשר מופעלת, כל הפעלה של ה-CLI המתאים דחויה אלא אם הפקודה תואמת ערך ב-`allowPatterns`.

דקדוק ה-pattern זהה ל-[`block-sudo`](#block-sudo): אלטוקנים מותאמים לargv שנתחו, `*` היא wildcard לאלט אחד, וכל פקודה המכילה אופרטור shell עצמאי (`&&`, `||`, `|`, `;`) או אלט עם metacharacters shell מובנה נדחות לפני התאמת allowlist כדי למנוע bypasses הזרקה.

### `block-kubectl`

**Event:** PreToolUse (Bash)  
**Default:** דוחה כל הפעלה של `kubectl`.

**Parameters:**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | kubectl קדימות פקודה המותרות. |

**Example:**

```json
{
  "policyParams": {
    "block-kubectl": {
      "allowPatterns": ["kubectl get *", "kubectl describe *", "kubectl logs *"]
    }
  }
}
```

עם הקונפיגורציה הזו, `kubectl get pods` מותר אך `kubectl apply -f deploy.yaml` דחוי.

### `block-gh-pipeline`

**Event:** PreToolUse (Bash)  
**Default:** דוחה את תתי-הפקודות `gh` CLI הבאות המעירות מצב או מדלקות צנרות:

- `gh workflow run`, `gh workflow enable`, `gh workflow disable`
- `gh run rerun`, `gh run cancel`
- `gh pr merge`
- `gh release create`, `gh release delete`
- `gh cache delete`
- `gh secret set`, `gh secret delete`

תתי-פקודות `gh` קריאה-בלבד כגון `gh pr view`, `gh pr list`, `gh run list`, `gh release view`, ו-`gh api repos/.../...` הן **לא** מתאימות על ידי מדיניות זו — הן נחוצות בדרך כלל לבדיקות זרימת עבודה (כולל של failproofai העצמי `require-ci-green-before-stop`).

**Parameters:**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | הפעלות scripted ספציפיות לאפשר גם כי הן היו דחויות אחרת. |

**Example:**

```json
{
  "policyParams": {
    "block-gh-pipeline": {
      "allowPatterns": ["gh run rerun *"]
    }
  }
}
```

## סודות (מנקים)

עצור סוכנים מלדלוף credentials לתוך ההקשר או הפלט שלהם. מדיניות מנקים מופעלת בערוי **PostToolUse**. כאשר Claude מפעיל פקודת Bash, קורא קובץ, או קורא לכל כלי, מדיניות אלה בודקות את הפלט לפני שהוא מוחזר ל-Claude. אם דפוס סוד מתגלה, המדיניות מחזירה החלטת deny המונעת את הפלט מהעברה חזרה.

### `sanitize-jwt`

**Event:** PostToolUse (כל הכלים)  
**Default:** ריסוס JWT tokens (שלוש קטעי base64url מופרדים על ידי `.`).

אין פרמטרים.

---

### `sanitize-api-keys`

**Event:** PostToolUse (כל הכלים)  
**Default:** ריסוס פורמטי מפתח API נפוצים: Anthropic (`sk-ant-`), OpenAI (`sk-`), GitHub PATs (`ghp_`), מפתחות גישה AWS (`AKIA`), מפתחות Stripe (`sk_live_`, `sk_test_`), ומפתחות Google API (`AIza`).

**Parameters:**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `additionalPatterns` | `{ regex: string; label: string }[]` | `[]` | דפוסי regex נוספים להתייחס אליהם כסודות. |

**Example:**

```json
{
  "policyParams": {
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo internal API key" },
        { "regex": "pat_[0-9a-f]{40}", "label": "Internal PAT" }
      ]
    }
  }
}
```

---

### `sanitize-connection-strings`

**Event:** PostToolUse (כל הכלים)  
**Default:** ריסוס מחרוזות חיבור מסד נתונים המכילות credentials מובנים (למשל `postgresql://user:password@host/db`).

אין פרמטרים.

---

### `sanitize-private-key-content`

**Event:** PostToolUse (כל הכלים)  
**Default:** ריסוס בלוקי PEM (`-----BEGIN PRIVATE KEY-----`, `-----BEGIN RSA PRIVATE KEY-----`, וכו').

אין פרמטרים.

---

### `sanitize-bearer-tokens`

**Event:** PostToolUse (כל הכלים)  
**Default:** ריסוס כותרי `Authorization: Bearer <token>` כאשר ה-token הוא 20 או יותר תווים.

אין פרמטרים.

## סביבה

הגן על קונפיגורציית סביבה רגישה מקריאה או חשיפה על ידי סוכנים.

### `block-env-files`

**Event:** PreToolUse (Bash, Read)  
**Default:** דוחה קריאה של קבצי `.env` דרך `cat .env`, קריאות ב-`Read` tool עם `.env` כנתיב הקובץ, וכו'.

לא חוסם `.envrc` או קבצים סביבה-סמוכים אחרים - רק קבצים בשם בדיוק `.env`.

אין פרמטרים.

---

### `protect-env-vars`

**Event:** PreToolUse (Bash)  
**Default:** דוחה פקודות הדפסת משתנים סביבה: `printenv`, `env`, `echo $VAR`.

אין פרמטרים.

## גישת קבצים

שמור סוכנים עובדים בתוך גבולות פרויקט וחוץ מקבצים רגישים.

### `block-read-outside-cwd`

**Event:** PreToolUse (Read, Bash)  
**Default:** דוחה קריאה של קבצים מחוץ לשורש הפרויקט. הגבול הוא `CLAUDE_PROJECT_DIR` (מוגדר פעם לכל סשן על ידי Claude Code), עם fallback ל-cwd הנוכחי של הסשן כאשר משתנה זה לא מוגדר. שימוש בשורש הפרויקט ולא ב-`cwd` החי פירושו הגבול נשאר יציב גם אחרי Claude `cd`s לתקייה משנית.

**Parameters:**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `allowPaths` | `string[]` | `[]` | קדימות נתיב מוחלט המותרות גם אם מחוץ לשורש הפרויקט. |

**Example:**

```json
{
  "policyParams": {
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company/config"]
    }
  }
}
```

---

### `block-secrets-write`

**Event:** PreToolUse (Write, Edit)  
**Default:** דוחה כתיבה לקבצים בשימוש נפוץ למפתחות פרטיים ותעודות: `id_rsa`, `id_ed25519`, `*.key`, `*.pem`, `*.p12`, `*.pfx`.

**Parameters:**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `additionalPatterns` | `string[]` | `[]` | דפוסי שם קובץ נוספים (glob-style) לחסם. |

**Example:**

```json
{
  "policyParams": {
    "block-secrets-write": {
      "additionalPatterns": [".token", ".secret"]
    }
  }
}
```

## Git

מנע pushes אקראיות, force-pushes, וטעויות ענף קשות לביטול.

### `block-push-master`

**Event:** PreToolUse (Bash)  
**Default:** דוחה `git push origin main` ו-`git push origin master`.

**Parameters:**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `protectedBranches` | `string[]` | `["main", "master"]` | שמות ענפים שלא ניתן לדחוף אליהם ישירות. |

**Example:**

```json
{
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "master", "release", "prod"]
    }
  }
}
```

<Tip>
כדי להרשות דחיפה לכל הענפים (למעשה השבתת מדיניות זו ללא הסרתה מ-`enabledPolicies`), הגדר `protectedBranches: []`.
</Tip>

---

## מנהלי חבילות

אכוף אילו מנהלי חבילות הסוכן רשאי להשתמש.

### `prefer-package-manager`

**Event:** PreToolUse (Bash)  
**Default:** מושבת. כאשר מופעלת, חוסמת כל פקודת מנהל חבילות שאינה ברשימת `allowed` ואומרת ל-Claude לשכתוב את הפקודה בעזרת מנהל מותר.

מזהה: pip, pip3, python -m pip, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `allowed` | string[] | `[]` | שמות מנהל חבילות מותרים. כל מנהל מזוהה שלא ברשימה זו נחסם. כאשר ריק, המדיניות היא no-op. |
| `blocked` | string[] | `[]` | שמות מנהל נוספים לחסם מעבר לרשימה המובנית (למשל `['pdm', 'pipx']`). |

רשימת ה-block המובנית מכסה: pip, pip3, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo. השתמש ב-`blocked` כדי להוסיף מנהלים שאינם ברשימה זו.

**Example configuration:**

```json
{
  "enabledPolicies": ["prefer-package-manager"],
  "policyParams": {
    "prefer-package-manager": {
      "allowed": ["uv", "bun"],
      "blocked": ["pdm", "pipx"]
    }
  }
}
```

עם תצורה זו, `pip install flask` ו-`pdm install flask` שניהם דחויים עם הודעה שאומרת ל-Claude להשתמש ב-`uv` או `bun` במקום. פקודות כגון `uv pip install flask` מותרות מכיוון `uv` נמצא ברשימת ההרשאה ובודקות תחילה.

## זרימת עבודה

אכוף זרימת עבודה משמעותית בסוף סשן. מדיניות אלה מופעלות באירוע **Stop** ודחות את הסוכן מהעצירה עד שכל תנאי מתקיים. הם עוקבים אחר שרשרת תלות טבעית: commit → push → PR → CI. אם מדיניות דחויה, מדיניות מאוחרות יותר בשרשרת דלות (deny short-circuits).

כל מדיניות זרימת עבודה היא **fail-open**: אם הכלי הנדרש לא זמין (למשל `gh` לא מותקן, אין git remote), המדיניות מאפשרת עם הודעה מידע המסבירה מדוע הבדיקה דלטה.

### סמנטיקה Stop לכל-CLI

אכיפת Stop נראית מעט שונה על פני שישת ה-CLIs הנתמכים מכיוון שלכל אחת חוזה hook event שונה של נתונים. התוצאה **הם** זהים — הסוכן לא חוסך ממסוף זרימת עבודה סוגר — אך ה-**מכניקה** שונה. הטבלה למטה מסכמת; רק Pi יש יוצא דופן ידע למשתמש שווה הבנה לפני הפעלת מדיניות `require-*-before-stop`.

| CLI | כאשר ה-gate מתפעל | מה אתה רואה |
|---|---|---|
| Claude Code | אותו loop סוכן, מיד | Claude ממשיך לעבוד — מתקן את הבעיה, ואז מנסה לסיים שוב. אין הפרעה ניראית לך. |
| Codex | אותו loop סוכן, מיד | אותו דבר כמו Claude. |
| GitHub Copilot CLI | אותו loop סוכן, מיד | אותו דבר כמו Claude (משתמש ב-`{decision:"block", reason}` ערוץ ריטריי של Copilot — אומת אמפיריקליות מול Copilot CLI 1.0.41). |
| Cursor Agent | אותו loop סוכן, מיד | אותו דבר כמו Claude (משתמש ב-`{followup_message}` ערוץ של Cursor — מכוסה ב-`loop_limit`, ברירת מחדל 5 ריטריז). |
| OpenCode | אותו loop סוכן, מיד | אותו דבר כמו Claude (משתמש בקריאת `client.session.prompt(...)` SDK של OpenCode מכוונת דרך `hookSpecificOutput.additionalContext`). |
| **Pi (pi-coding-agent)** | **תור משתמש הבא** | **Pi עוצר בצורה ניראית** כאשר ה-gate מתפעל — loop הסוכן שלו יוצא והוא מוחזר ללך. ה-gate אז מתפעל בפעם הבאה שאתה מגיש prompt: failproofai קדימה צירוף directive `MANDATORY ACTION REQUIRED` לsystem prompt של turn זה, מציע ל-LLM להשלים את שלב זרימת העבודה (commit, push, וכו') לפני העשיית מה שביקשת. |

<Note>
**Pi limitation.** `AgentEndEvent` של Pi (המקביל עם מעלה ל-Claude hook `Stop`) אין סוג Result — בזמן שזה מתפעל, loop הסוכן של Pi כבר יצא. Pi לא יכול להיאלץ ל-retry אותו loop כמו Claude / Copilot / Cursor / OpenCode יכולים. failproofai משנה את ה-gate ל-event `before_agent_start` של Pi (שמתפעל אחרי ה-prompt הבא של המשתמש) כדי הבדיקה זרימת עבודה עדיין אוכפה, רק בתור הבא ולא הנוכחי.

**מה זה אומר בפרקטיקה:**

- אחרי Pi עוצר, הסיבה deny נתפסת בזיכרון באפתח לפי Pi session id. ה-prompt הרבה הבא שאתה מגיש בתהליך Pi זהה מוזג אותו: ה-LLM רואה את directive `MANDATORY ACTION REQUIRED` בחלק העליון של system prompt שלו, commits (או דוחף / פותח את ה-PR / מחכה ל-CI), ורק אז ממשיך עם בקשתך. הסיבה deny שנתפסה היא one-shot — פעם אחת מוזג, ה-gate נקי.
- ה-gate מוגבל ליווצא החיים של Pi. אם אתה `Ctrl+C` Pi או יוצא בין turns, הערך בזיכרון דחוי יחד עם התהליך וה-gate חסר. Claude, Copilot, Cursor, ו-OpenCode יש אותו קשור (הרוג הסוכן וה-gate חסר) — Pi רק עושה את זה ניראות יותר מכיוון הסוכן יוצא בצורה ניראית לפני ה-gate מתפעל.
- deny תלוי גם נקבל על `session_shutdown` לכל סיבה (`new` / `resume` / `fork` / `quit`), כך gate ישן מpior session לא יכול לדלוף לתוך session טרי התחיל באותו תהליך Pi.

אם אתה צריך retry same-loop בסגנון Claude, הפעל את המדיניות `Stop` תחת כל אחד מ-5 ה-CLIs הנתמכים האחרים. אנחנו עוקבים Pi upstream לסוג Result עתידי ב-`AgentEndEvent` שיאפשר לנו לסגור את הפער הזה.
</Note>

### `require-no-conflicts-before-stop`

**Event:** Stop  
**Default:** דוחה עצירה כאשר הענף הנוכחי לא יכול merge בצורה נקייה לענף ה-base. המדיניות קודם כל מאשרת שיש `OPEN` PR ב-GitHub לענף — ללא אחד, אין merge target לאכוף, כל המדיניות short-circuits להרשאה. פעם `OPEN` PR מאושרת, שתי בדיקות בלתי-תלויות ממשיכות:

1. **Local** — `git merge-tree --write-tree --name-only origin/<baseBranch> HEAD`. בהתנגשות, הודעת deny שמות קבצים המתנגשים כדי Claude יודע בדיוק מה לפתור.
2. **GitHub** — משתמש שוב ב-`gh pr view --json mergeable,state` תוצאה כבר fetched בפרה-בדיקה. תופסת התנגשות שישנה מקומית `origin/<baseBranch>` היתה חסרה (לדוג ראה ספר conflict PR ב-`main` מאז ה-fetch האחרון). `CONFLICTING` תוצאה דוחה. `UNKNOWN` תוצאה גם דוחה ומציע ל-Claude להמתין ~10 שניות והחזור-בדיקה לפני ניסיון לעצור שוב — זה מונע false negatives תוך GitHub recomputes.

דלוקים לחלוטין (מאפשרים) כאשר: `gh` לא מותקנת, אין PR לענף, ה-PR state אינו `OPEN` (למשל `MERGED`, `CLOSED`), או `gh pr view` מחזיר פלט לא parseable. גם נכשל פתוח כאשר `origin/<baseBranch>` חסר מקומית או כאשר אין commits קדימה של base — אלה Layer 1 fall-throughs עדיין consulted cached PR mergeability לפני הרשאה.

**Parameters:**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `baseBranch` | `string` | `"main"` | Base branch לבדיקה עבור התנגשות נגד. |

<Note>
GitHub CLI (`gh`) נדרשת למדיניות זו. המדיניות משתמשת `gh pr view` לאשר
`OPEN` PR קיימת לפני הפעלת כל probe התנגשות — ללא `gh`, המדיניות
short-circuits להרשאה. הפעל `gh auth login` עם personal access token יש
`repo` scope לקריאה גישה ל-pull requests.
</Note>

הסר מדיניות ספציפית מ-`enabledPolicies` בקונפיגורציה שלך, או החלף את זה ב-dashboard של לשונית Policies.

מדיניות לא רשומה ב-`enabledPolicies` לא פועלות, גם אם ערכי `policyParams` קיימים בהם.
