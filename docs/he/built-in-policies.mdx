failproofai משלוח עם 39 מדיניויות מובנות שתופסות מצבי כשל נפוצים של סוכנים. כל מדיניות מופעלת על סוג אירוע hook ספציפי ושם כלי. תשע עשרה מדיניויות מקבלות פרמטרים המאפשרים לך להתאים את התנהגותן ללא כתיבת קוד. חמש מדיניויות זרימת עבודה אוכפות pipeline של commit → push → PR → CI לפני שClaude עוצר.

- **`block-`** — עצור את הסוכן מלהמשיך.
- **`warn-`** — תן לסוכן הקשר נוסף כדי שיוכל להתקן את עצמו.
- **`sanitize-`** — נקה נתונים רגישים מפלט כלי לפני שהסוכן רואה זאת.

### מרחבי שם (Namespaces)

כל מדיניות חיה בחריץ `<namespace>/<name>`. מדיניויות מובנות שייכות ל
**`failproofai/`** namespace — לדוגמה, `failproofai/sanitize-jwt`. ה
namespace מונע התנגשויות כאשר אתה גם טוען מדיניויות מותאמות או צד שלישי
עם שמות קצרים דומים.

בתצורה שלך אתה יכול להתייחס למדיניות מובנית בשם קצר או שם מוסמך; שתי הצורות מתפקדות לאותה מדיניות:

```json
{
  "enabledPolicies": [
    "sanitize-jwt",
    "failproofai/block-rm-rf"
  ]
}
```

אם לשם אין `/`, failproofai מתייחס אליו כשייך ל
namespace ברירת המחדל `failproofai`. שמות שכבר מכילים `/` (לדוגמה `myorg/foo`,
`custom/my-hook`) נשמרים כמו שהם.
- **`require-`** — חסום את אירוע Stop עד שתנאים מתקיימים.

---

<Tip>
כל מדיניות תומכת בשדה `hint` אופציוני ב`policyParams`. ה hint מתווסף להודעת deny או instruct שClaude רואה, נותן הדרכה פעולית ללא שינוי קוד מדיניות. עובד עם מדיניויות מובנות, מותאמות ותקנות. ראה [תצורה → hint](/he/configuration#hint-cross-cutting) לפרטים.
</Tip>

## פקודות מסוכנות

מנע סוכנים מהפעלת פעולות שקשה לבטל או שיכולות לפגוע במערכת המחשב.

### `block-sudo`

**אירוע:** PreToolUse (Bash)  
**ברירת מחדל:** דוחה כל פקודה `sudo` או `doas`.

חוסם פקודה שמפעילה בינארי הגבלת הרשאות **במיקום הפקודה**. התאמה היא מבנית ולא טקסטואלית: הפקודה מתחלקת לקטעים כפי שהקליפה תעשה, הקצאות קידומת (`FOO=bar`), הפניות, וממנהלים עם הדגלים שלהם (`env`, `nohup`, `timeout`, `xargs`, `sh -c`, ...) מופנו, והבינארי המתקבל מושווה ל**basename**. לכן `/usr/bin/sudo`, `env sudo`, `timeout 5 sudo`, `"sudo"`, `\sudo` ו `bash -c "sudo …"` כולם דחויים, ו`doas` מטופל כאותו כושר תחת שם שונה.

מכיוון שהוא עוגן למיקום הפקודה ולא למילה המופיעה בכל מקום, היא **לא** מופעלת על פקודות שמזכירות אותה בלבד — `grep -r sudo /etc`, `cat /etc/sudoers`, `git commit -m "fix sudo handling"`, או `grep` alternation המכיל את המילה הם כולם פועלים בדרך כלל.

<Warning>
זה עוצר את הנסיון הברור; זה לא סוגר את המחלקה. סוכן שיכול להפעיל shell שרירותי עדיין יכול להגיע להגבלת הרשאות בעקיפין — דרך משתנה (`S=sudo; $S …`), צינור שמפוענח ב base64, או סקריפט wrapper בדיסק — מכיוון ששום בדיקה של מחרוזת פקודה יחידה לא יכולה לעקוב אחרי אלה. התייחס לזה כמו כמעקף לטעויות והסלמה מטונפת, לא כגבול ביטחוני נגד סוכן נחוש. גבול אמיתי חייב להיות אכוף מתחת לקליפה.
</Warning>

**פרמטרים:**

| פרמטר | סוג | ברירת מחדל | תיאור |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | קידומות פקודה מדויקות המותרות. כל ערך מותאם לאזמן argv שנתוענ. |

**דוגמה:**

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    }
  }
}
```

עם תצורה זו, `sudo systemctl status nginx` מותר, אבל `sudo rm /etc/hosts` דחוי.

<Note>
דפוסים מותאמים לאזמנים שנתוענו, לא למחרוזת הפקודה הגולמית. זה מונע עקיפה דרך אופרטורים קליפה מצורפים (לדוגמה `sudo systemctl status x; rm -rf /` לא תואם `sudo systemctl status *`).
</Note>

### `block-self-pause`

**אירוע:** PreToolUse (Bash)  
**ברירת מחדל:** דוחה `failproofai config --pause`, אשר משהה אכיפה לסשן. השהיה היא החלטה אנושית — סוכן שיכול להפעיל אותה יכול להשבית כל מדיניות אחרת עם פקודה יחידה.

צרה יותר מ[`block-failproofai-commands`](#block-failproofai-commands) בכוונה, ולא כוללת בו: המדיניות ההיא עוגנת לגבול פקודה, לכן `npx -y failproofai config --pause` לא תואם אותו, וכשהיא רחבה היא לעתים קרובות משבתת כדי סוכנים יוכלו להפעיל `failproofai audit`. `--resume` ו `--status` מותרים — אף אחד מהם לא מסיר אכיפה.

זה עוצר את הנסיון הישיר, לא את כל המחלקה: סוכן עדיין יכול להגיע לאותו מצב דרך alias או סקריפט wrapper. סגירת זה לחלוטין דורשת שה pause יהיה בלתי נגיש מקריאת כלי בכלל.

ללא פרמטרים.

## פקודות תשתית

עצור סוכני קידוד מהפעלת CLIs תשתית או הפעלת pipelines CI/CD. כל המדיניויות בקטגוריה זו הן **opt-in** (`defaultEnabled: false`) — סוכנים שצריכים בצורה לגיטימית לקרוא ל`kubectl`, `terraform`, וכו' לא יופרעו אלא אם תפעיל את המדיניות. בהפעלה, כל הפעלה של ה CLI התואמת דחויה אלא אם הפקודה תואמת ערך ב`allowPatterns`.

דקדוק הדפוס זהה ל[`block-sudo`](#block-sudo): אזמנים מותאמים לאזמנים שנתוענו, `*` הוא wildcard לאזמן אחד, וכל פקודה המכילה אופרטור קליפה עצמאי (`&&`, `||`, `|`, `;`) או אזמן עם metacharacters קליפה מוטבעים דחויה לפני התאמת allowlist למניעת עקיפות הזרקה.

### `block-kubectl`

**אירוע:** PreToolUse (Bash)  
**ברירת מחדל:** דוחה כל הפעלה של `kubectl`.

**פרמטרים:**

| פרמטר | סוג | ברירת מחדל | תיאור |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | קידומות פקודה kubectl המותרות. |

**דוגמה:**

```json
{
  "policyParams": {
    "block-kubectl": {
      "allowPatterns": ["kubectl get *", "kubectl describe *", "kubectl logs *"]
    }
  }
}
```

עם תצורה זו, `kubectl get pods` מותר אבל `kubectl apply -f deploy.yaml` דחוי.

## סודות (מנקות)

עצור סוכנים מהדלפת אישורים להקשר או פלט שלהם. מדיניויות מנקות מופעלות על אירועי **PostToolUse**. כאשר Claude מפעיל פקודת Bash, קורא קובץ, או קורא לכלי כלשהו, המדיניויות הללו בודקות את הפלט לפני שהוא מוחזר לClaude. אם דפוס סוד מזוהה, המדיניות מחזירה החלטת deny המונעת את הפלט מלהעבור חזרה.

### `sanitize-jwt`

**אירוע:** PostToolUse (כל כלי)  
**ברירת מחדל:** מחזיק JWT tokens (שלושה קטעי base64url מופרדים בנקודה).

ללא פרמטרים.

---

### `sanitize-api-keys`

**אירוע:** PostToolUse (כל כלי)  
**ברירת מחדל:** מחזיק פורמטים API key נפוצים: Anthropic (`sk-ant-`), OpenAI (`sk-`), GitHub PATs (`ghp_`), AWS access keys (`AKIA`), Stripe keys (`sk_live_`, `sk_test_`), וGoogle API keys (`AIza`).

**פרמטרים:**

| פרמטר | סוג | ברירת מחדל | תיאור |
|-------|------|---------|-------------|
| `additionalPatterns` | `{ regex: string; label: string }[]` | `[]` | דפוסי regex נוספים לטיפול בהם כסודות. |

**דוגמה:**

```json
{
  "policyParams": {
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo internal API key" },
        { "regex": "pat_[0-9a-f]{40}", "label": "Internal PAT" }
      ]
    }
  }
}
```

## גישה לקבצים

שמור סוכנים עובדים בתוך גבולות פרויקט וחוק מקבצים רגישים.

### `block-read-outside-cwd`

**אירוע:** PreToolUse (Read, Bash)  
**ברירת מחדל:** דוחה קריאה של קבצים מחוץ לשורש הפרויקט. הגבול הוא `CLAUDE_PROJECT_DIR` (מוגדר פעם לכל סשן על ידי Claude Code), עם fallback ל cwd הנוכחי של הסשן כאשר המשתנה הזה אינו מוגדר. שימוש בשורש הפרויקט במקום ה cwd חי פירושו שהגבול נשאר יציב אפילו לאחר Claude `cd`s לתת-תיקייה.

**פרמטרים:**

## מנהלי חבילות

כופה איזה מנהלי חבילות מותר לסוכן להשתמש בהם.

### `prefer-package-manager`

**אירוע:** PreToolUse (Bash)  
**ברירת מחדל:** משבתת. בהפעלה, חוסמת כל פקודת מנהל חבילות לא ברשימה `allowed` ואומר לClaude לכתוב מחדש את הפקודה באמצעות מנהל מותר.

מגלה: pip, pip3, python -m pip, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo.

| פרמטר | סוג | ברירת מחדל | תיאור |
|-----------|------|---------|-------------|
| `allowed` | string[] | `[]` | שמות מנהלי חבילות מותרים. כל מנהל שמגולה שלא ברשימה זו דחוי. כאשר ריק, המדיניות היא no-op. |
| `blocked` | string[] | `[]` | שמות מנהלים נוספים לחסימה מעבר לרשימה המובנית (לדוגמה `['pdm', 'pipx']`). |

רשימת החסימה המובנית מכסה: pip, pip3, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo. השתמש ב`blocked` להוספת מנהלים לא ברשימה זו.

**דוגמה של תצורה:**

```json
{
  "enabledPolicies": ["prefer-package-manager"],
  "policyParams": {
    "prefer-package-manager": {
      "allowed": ["uv", "bun"],
      "blocked": ["pdm", "pipx"]
    }
  }
}
```

עם תצורה זו, `pip install flask` ו `pdm install flask` שניהם דחויים עם הודעה לClaude להשתמש ב `uv` או `bun` במקום. פקודות כמו `uv pip install flask` מותרות מכיוון ש `uv` ברשימה המותר וברור תחילה.

## זרימת עבודה

כופה זרימת עבודה מסודרת בסוף סשן. המדיניויות הללו מופעלות על אירוע **Stop** ודוחות את הסוכן מעצירה עד שכל תנאי מתקיימים. הם עוקבים אחר שרשרת תלות טבעית: commit → push → PR → CI. אם מדיניות דוחה, מדיניויות מאוחרות יותר בשרשרת דילוג (deny short-circuits).

כל מדיניויות זרימת עבודה הן **fail-open**: אם הכלי הנדרש אינו זמין (לדוגמה `gh` לא מותקן, אין git remote), המדיניות מאפשרת עם הודעה אינפורמטיבית המסבירה מדוע הבדיקה דולגה.

### Stop Semantics לכל CLI

Stop enforcement נראה קצת שונה על פני שישה CLIs נתמכים מכיוון שלכל אחד מהם יש חוזה hook שונה של `<agent finished>`. ה**outcome** הוא זהה — הסוכן לא יוכל להיות בעצור כששער זרימת עבודה נכשל — אבל ה**mechanics** שונים. הטבלה שלהלן מסכמת; רק Pi יש quirk שגלוי למשתמש שכדאי להבין לפני שתאפשר מדיניות `require-*-before-stop`.

| CLI | כאשר השער מופעל | מה אתה רואה |
|---|---|---|
| Claude Code | אותה לולאת סוכן, מייד | Claude ממשיך לעבוד — מתקן את הבעיה, ואז מנסה להיות בעצור שוב. ללא הפרעה גלויה לך. |
| Codex | אותה לולאת סוכן, מייד | זהה ל Claude. |
| GitHub Copilot CLI | אותה לולאת סוכן, מייד | זהה ל Claude (משתמש בערוץ ההנצחה של Copilot `{decision:"block", reason}` — אומתה אמפירית כנגד Copilot CLI 1.0.41). |
| Cursor Agent | אותה לולאת סוכן, מייד | זהה ל Claude (משתמש בערוץ `{followup_message}` של Cursor — מוגבל ל `loop_limit`, ברירת מחדל 5 ניסיונות). |
| OpenCode | אותה לולאת סוכן, מייד | זהה ל Claude (משתמש ב `client.session.prompt(...)` SDK call מותמר דרך `hookSpecificOutput.additionalContext`). |
| **Pi (pi-coding-agent)** | **סיבוב משתמש הבא** | **Pi עוצר בגלוי** כאשר השער מופעל — לולאת הסוכן שלה יוצא ואתה חוזר להנמקה. השער אז מופעל בפעם הבאה שאתה שולח הנמקה: failproofai קדימה תוספת ניהול `MANDATORY ACTION REQUIRED` להנמקת סיבוב זו, משמעות LLM להשלים את שלב זרימת העבודה (commit, push, וכו') לפני כל מה שביקשת. |

<Note>
**Pi limitation.** ה `AgentEndEvent` של Pi (שווה ערך upstream של Claude's `Stop` hook) אין סוג Result — עד שזה מופעל, לולאת הסוכן של Pi כבר יצאה. Pi לא יכול להיות מכופה לנסות שוב אותה לולאה כמו Claude / Copilot / Cursor / OpenCode יכול. failproofai משמעות השער ל `before_agent_start` אירוע Pi (אשר מופעל לאחר ההנמקה הבאה של המשתמש) כדי שהבדיקת זרימת העבודה כל עוד אוכפה, רק בסיבוב הבא במקום הנוכחי.

**מה זה אומר בפרקטיקה:**

- לאחר Pi עוצר, סיבת הדחייה נתפסת בזיכרון מולבש על ידי Pi session id. ההנמקה הבאה בדיוק שאתה משלח באותה תהליך Pi מנקז אותו: LLM רואה את ההנמקה `MANDATORY ACTION REQUIRED` בחלק העליון של מערכת ההנמקה שלו, commits (או pushes / opens PR / מחכה CI), וגם מעבר אז עם ההנמקה שלך. סיבת הדחייה שנתפסה היא חד פעמית — כשנמצה, השער ברור.
- השער מוגבל על ידי Pi's lifetime תהליך. אם `Ctrl+C` Pi או יוצא בין סיבובים, ערך הזיכרון מופל יחד עם התהליך והשער מיפה. Claude, Copilot, Cursor, ו OpenCode יש את אותו bound (הרוג את הסוכן והשער מיפה) — Pi רק עושה יותר גלוי מכיוון שהסוכן בגלוי יוצא לפני השער מופעל.
- דחייה תלויה הוא גם ברור ב `session_shutdown` לכל סיבה (`new` / `resume` / `fork` / `quit`), לכן שער מיושנה מסשן קודם לא יכול ניצול לתוך סשן טרי שהוקם באותו תהליך Pi.

אם אתה צריך Claude-style same-loop retry, הפעל את `Stop` policies תחת כל אחד משנים חמשה CLIs נתמכים אחרים. אנחנו עוקבים Pi upstream לסוג Result עתיד על `AgentEndEvent` אשר היה לתת לנו סגור הפער.
</Note>

### `require-no-conflicts-before-stop`

**אירוע:** Stop  
**ברירת מחדל:** דוחה עצירה כאשר הענף הנוכחי לא יכול מנקי merge לתוך ענף base. המדיניות קודם מאשר יש`OPEN` PR על GitHub לענף — ללא אחד, אין merge target לאכיפה, לכן כל מדיניות short-circuits לאפשור. פעם `OPEN` PR מאושר, שתי בדיקות עצמאיות הפעולה:

1. **Local** — `git merge-tree --write-tree --name-only origin/<baseBranch> HEAD`. עם סכסוך, הודעת deny שמות ה conflicted files כדי Claude יודע בדיוק מה לפתור.
2. **GitHub** — מחדש `gh pr view --json mergeable,state` תוצאה כבר fetched בפרה בדיקה. תופסות סכסוכים ש stale local `origin/<baseBranch>` היה miss (לדוגמה מישהו נחת conflicting PR על `main` מאז last fetch). `CONFLICTING` תוצאה דוחה. `UNKNOWN` תוצאה גם דוחה ומנחה Claude להמתין ~10 seconds וקביעה חוזרת לפני כל מה שנסיון לעצור שוב — זה מונע false negatives בזמן GitHub recomputes.

דלג לגמרי (מאפשר) כאשר: `gh` לא מותקן, אין PR קיים לענף, PR של state איננו `OPEN` (לדוגמה `MERGED`, `CLOSED`), או `gh pr view` מחזיר פלט unparseable. גם נכשלות פתוח כאשר `origin/<baseBranch>` missing locally או כאשר אין commits קדימה של base — אלה Layer 1 fall-throughs עדיין בדוק ה cached PR mergeability לפני הרשה.

**פרמטרים:**

| פרמטר | סוג | ברירת מחדל | תיאור |
|-------|------|---------|-------------|
| `baseBranch` | `string` | `"main"` | Base branch לבדוק סכסוכים נגד. |

<Note>
GitHub CLI (`gh`) נדרש למדיניות זו. המדיניות משתמש `gh pr view` לאשר
`OPEN` PR קיים לפני כל בדיקת סכסוך הפעולה — ללא `gh`, המדיניות
short-circuits לאפשור. הפעל `gh auth login` עם personal access token ש
`repo` scope לקריאה לגישה פול בקשות.
</Note>

## משבתת מדיניויות בודדות

הסר מדיניות ספציפית מ `enabledPolicies` בתצורה שלך, או toggle זה משבתת באפליקציית תחת Policies tab.

```json
{
  "enabledPolicies": [
    "block-rm-rf",
    "sanitize-api-keys"
  ]
}
```

מדיניויות לא רשום ב `enabledPolicies` לא הפעולה, גם אם `policyParams` ערכים קיימים להם.
