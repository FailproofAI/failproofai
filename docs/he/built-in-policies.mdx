failproofai מגיע עם 39 מדיניויות מובנות שתופסות מצבי כשל נפוצים של סוכנים. כל מדיניות מופעלת על סוג אירוע ווק מסוים ושם כלי. תשע עשרה מדיניויות מקבלות פרמטרים המאפשרים לך לכוונן את ההתנהגות שלהן ללא כתיבת קוד. חמש מדיניויות זרימת עבודה אוכפות צינור commit → push → PR → CI לפני שClaude עוצר.

## סקירה כללית

מדיניויות מקובצות לקטגוריות:

| קטגוריה | מדיניויות | סוג ווק |
|----------|----------|-----------|
| [פקודות מסוכנות](#dangerous-commands) | block-sudo, block-rm-rf, block-curl-pipe-sh, block-failproofai-commands, block-self-pause | PreToolUse |
| [פקודות תשתית](#infra-commands) | block-kubectl, block-terraform, block-aws-cli, block-gcloud, block-az-cli, block-helm, block-gh-pipeline | PreToolUse |
| [סודות (מנקים)](#secrets-sanitizers) | sanitize-jwt, sanitize-api-keys, sanitize-connection-strings, sanitize-private-key-content, sanitize-bearer-tokens | PostToolUse |
| [סביבה](#environment) | block-env-files, protect-env-vars | PreToolUse |
| [גישה לקבצים](#file-access) | block-read-outside-cwd, block-secrets-write | PreToolUse |
| [Git](#git) | block-push-master, block-work-on-main, block-force-push, warn-git-amend, warn-git-stash-drop, warn-all-files-staged | PreToolUse |
| [בסיס נתונים](#database) | warn-destructive-sql, warn-schema-alteration | PreToolUse |
| [אזהרות](#warnings) | warn-large-file-write, warn-package-publish, warn-background-process, warn-global-package-install | PreToolUse |
| [מנהלי חבילות](#package-managers) | prefer-package-manager | PreToolUse |
| [זרימת עבודה](#workflow) | require-commit-before-stop, require-push-before-stop, require-pr-before-stop, require-no-conflicts-before-stop, require-ci-green-before-stop | Stop |

- **`block-`** — עצור את הסוכן מהמשך.
- **`warn-`** — תן לסוכן הקשר נוסף כדי שיוכל להתאושש בעצמו.
- **`sanitize-`** — טיהור נתונים רגישים מפלט כלים לפני שהסוכן רואה זאת.

### מרחבי שמות

כל מדיניות נמצאת בחריץ `<namespace>/<name>`. מדיניויות מובנות שייכות ל-
מרחב השמות **`failproofai/`** — למשל, `failproofai/sanitize-jwt`. מרחב השמות
מונע התנגשויות כאשר אתה גם טוען מדיניויות מותאמות או של צד שלישי
עם שמות קצרים דומים.

בתצורה שלך תוכל להתייחס למדיניות מובנית בשם קצר או בשם
מלא; שתי הצורות מתפתרות לאותה מדיניות:

```json
{
  "enabledPolicies": [
    "sanitize-jwt",
    "failproofai/block-rm-rf"
  ]
}
```

אם לשם אין `/`, failproofai מתייחס אליו כשייך למרחב השמות
ברירת המחדל `failproofai`. שמות שכבר מכילים `/` (למשל `myorg/foo`,
`custom/my-hook`) נשמרים כמו שהם.
- **`require-`** — חסום את אירוע ה-Stop עד שתנאים מתמלאים.

---

<Tip>
כל מדיניות תומכת בשדה `hint` אופציונלי ב-`policyParams`. ה-hint מתווסף להודעת deny או instruct ש-Claude רואה, ונותן הנחיה פעולית ללא שינוי קוד מדיניות. עובד עם מדיניויות מובנות, מותאמות ו-convention. ראה [Configuration → hint](/he/configuration#hint-cross-cutting) לפרטים.
</Tip>

## פקודות מסוכנות

מנע מסוכנים להפעיל פעולות שקשה להשיב או שעלולות להזיק למערכת המארח.

### `block-sudo`

**אירוע:** PreToolUse (Bash)  
**ברירת מחדל:** דוחה כל פקודה `sudo` או `doas`.

חוסם פקודה שמפעילה בינארי הגבהה **במיקום הפקודה**. התאמה היא מבנית ולא טקסטואלית: הפקודה מפוצלת לקטעים בדרך שהקליל היה עושה, הקצאות קידומת (`FOO=bar`), הפניות, והנוגים עם הדגלים שלהם (`env`, `nohup`, `timeout`, `xargs`, `sh -c`, …) מוזרקים, והבינארי המתקבל מושווה ב-**basename**. אז `/usr/bin/sudo`, `env sudo`, `timeout 5 sudo`, `"sudo"`, `\sudo` ו-`bash -c "sudo …"` כולם דחויים, ו-`doas` מטופל כאותה יכולת בשם אחר.

מכיוון שהוא עוגן למיקום הפקודה ולא לכך שהמילה מופיעה בכל מקום, הוא **לא** מופעל בפקודות שרק מזכירות אותו — `grep -r sudo /etc`, `cat /etc/sudoers`, `git commit -m "fix sudo handling"`, או `grep` alternation שמכילה את המילה כולם פועלים בדרך כלל.

<Warning>
זה עוצר את הניסיון הברור; זה לא סוגר את המעמד. סוכן שיכול להפעיל shell שרירותי עדיין יכול להגיע להגבהה בעקיפין — דרך משתנה (`S=sudo; $S …`), צינור שפוענח base64, או סקריפט wrapper על הדיסק — מכיוון שאין בדיקה של מחרוזת פקודה יחידה שיכולה לעקוב אחרי אלה. התייחס לזה כממתן כנגד טעויות והגבהה זדונית, לא כגבול אבטחה כנגד סוכן נחוש. גבול אמיתי צריך להיות אכוף מתחת ל-shell.
</Warning>

**פרמטרים:**

| פרמ | סוג | ברירת מחדל | תיאור |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | קידומות פקודה מדויקות המותרות. כל ערך מושווה כנגד אסימוני argv המנותחים. |

**דוגמה:**

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    }
  }
}
```

עם תצורה זו, `sudo systemctl status nginx` מותר, אך `sudo rm /etc/hosts` דחוי.

<Note>
דפוסים מושווים כנגד אסימונים מנותחים, לא מחרוזת הפקודה הגולמית. זה מונע עלילה דרך אופרטורים shell מצורפים (למשל `sudo systemctl status x; rm -rf /` לא תואם `sudo systemctl status *`).
</Note>

### `block-self-pause`

**אירוע:** PreToolUse (Bash)  
**ברירת מחדל:** דוחה `failproofai config --pause`, המשהה אכיפה לפי הפעלה. השהיה היא החלטה אנושית — סוכן שיכול להפעיל אותה יכול לכבות כל מדיניות אחרת בפקודה יחידה.

צר יותר מ-[`block-failproofai-commands`](#block-failproofai-commands) בכוונה, ולא מכוסה על ידה: מדיניות זו עוגנת על גבול פקודה, אז `npx -y failproofai config --pause` לא תואמת אותה, ובהיותה רחבה היא לעתים קרובות מכובה כדי שסוכנים יוכלו להפעיל `failproofai audit`. `--resume` ו-`--status` מותרים — לא אחד מהם מסיר אכיפה.

זה עוצר את הניסיון הישיר, לא את המעמד השלם: סוכן עדיין יכול להגיע לאותו מצב דרך alias או סקריפט wrapper. סגירתו באופן מלא דורשת שההשהיה תהיה בלתי נגישה מקריאת כלי בכלל.

ללא פרמטרים.

## פקודות תשתית

עצור סוכנים קידוד מהפעלת CLIs תשתית או הגדרת צינורות CI/CD. כל מדיניויות בקטגוריה זו הן **opt-in** (`defaultEnabled: false`) — סוכנים שבאמת צריכים לקרוא `kubectl`, `terraform`, וכו' לא יופרעו אלא אם אתה מפעיל את המדיניות. כאשר מופעלת, כל הזעקה של ה-CLI המתאים דחויה אלא אם הפקודה תואמת ערך ב-`allowPatterns`.

דקדוק הדפוס זהה ל-[`block-sudo`](#block-sudo): אסימונים מושווים כנגד argv מנותח, `*` הוא wildcard לאסימון אחד, וכל פקודה המכילה אופרטור shell עצמאי (`&&`, `||`, `|`, `;`) או אסימון עם תווי metacharacter shell מוטבעים דחויה לפני התאמת allowlist כדי למנוע עלילות injection.

### `block-kubectl`

**אירוע:** PreToolUse (Bash)  
**ברירת מחדל:** דוחה כל הזעקת `kubectl`.

**פרמטרים:**

| פרמ | סוג | ברירת מחדל | תיאור |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | קידומות פקודה kubectl המותרות. |

**דוגמה:**

```json
{
  "policyParams": {
    "block-kubectl": {
      "allowPatterns": ["kubectl get *", "kubectl describe *", "kubectl logs *"]
    }
  }
}
```

עם תצורה זו, `kubectl get pods` מותר אך `kubectl apply -f deploy.yaml` דחוי.

## סודות (מנקים)

עצור סוכנים מדליפת credentials להקשר או פלט שלהם. מדיניויות מנקה מופעלות על אירועי **PostToolUse**. כאשר Claude מפעיל פקודת Bash, קורא קובץ, או קורא כל כלי, מדיניויות אלה בודקות את הפלט לפני שהוא מוחזר ל-Claude. אם דפוס סוד זוהה, המדיניות מחזירה החלטת deny שמנעת מהפלט להיות מעביר חזרה.

### `sanitize-jwt`

**אירוע:** PostToolUse (כל הכלים)  
**ברירת מחדל:** ערוך אסימוני JWT (שלוש קטעי base64url מופרדים ב-`.`).

ללא פרמטרים.

---

### `sanitize-api-keys`

**אירוע:** PostToolUse (כל הכלים)  
**ברירת מחדל:** ערוך פורמטים נפוצים של מפתח API: Anthropic (`sk-ant-`), OpenAI (`sk-`), GitHub PATs (`ghp_`), AWS access keys (`AKIA`), Stripe keys (`sk_live_`, `sk_test_`) וGoogle API keys (`AIza`).

**פרמטרים:**

| פרמ | סוג | ברירת מחדל | תיאור |
|-------|------|---------|-------------|
| `additionalPatterns` | `{ regex: string; label: string }[]` | `[]` | דפוסי regex נוספים להתייחס כסודות. |

**דוגמה:**

```json
{
  "policyParams": {
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo internal API key" },
        { "regex": "pat_[0-9a-f]{40}", "label": "Internal PAT" }
      ]
    }
  }
}
```

---

### `sanitize-connection-strings`

**אירוע:** PostToolUse (כל הכלים)  
**ברירת מחדל:** ערוך מחרוזות חיבור בסיס נתונים המכילות credentials מוטבעים (למשל `postgresql://user:password@host/db`).

ללא פרמטרים.

---

**אירוע:** PostToolUse (כל הכלים)  
**ברירת מחדל:** ערוך בלוקים PEM (`-----BEGIN PRIVATE KEY-----`, `-----BEGIN RSA PRIVATE KEY-----`, וכו').

ללא פרמטרים.

---

### `sanitize-bearer-tokens`

**אירוע:** PostToolUse (כל הכלים)  
**ברירת מחדל:** ערוך כותרות `Authorization: Bearer <token>` כאשר האסימון הוא 20 תווים או יותר.

ללא פרמטרים.

## גישה לקבצים

שמור סוכנים שעובדים בתוך גבולות פרויקט ורחוק מקבצים רגישים.

### `block-read-outside-cwd`

**אירוע:** PreToolUse (Read, Bash)  
**ברירת מחדל:** דוחה קריאת קבצים מחוץ לשורש הפרויקט. הגבול הוא `CLAUDE_PROJECT_DIR` (מוגדר פעם ליד הפעלה על ידי Claude Code), עם fallback לתיקיית העבודה הנוכחית של ההפעלה כאשר משתנה זה אינו מוגדר. שימוש בשורש הפרויקט ולא ב-`cwd` החי פירושו שהגבול נשאר יציב אפילו לאחר Claude `cd`s לתת-ספריה.

**פרמטרים:**

| פרמ | סוג | ברירת מחדל | תיאור |
|-------|------|---------|-------------|
| `allowPaths` | `string[]` | `[]` | קידומות נתיב מוחלט המותרות אפילו אם מחוץ לשורש הפרויקט. |

**דוגמה:**

```json
{
  "policyParams": {
    "block-read-outside-cwd": {
```

## מנהלי חבילות

אוכף אילו מנהלי חבילות הסוכן מורשה להשתמש.

### `prefer-package-manager`

**אירוע:** PreToolUse (Bash)  
**ברירת מחדל:** השבתה. כאשר מופעל, חוסם כל פקודת מנהל חבילות לא ב-רשימת `allowed` ואומר Claude לשכתב את הפקודה באמצעות מנהל חבילות מורשה.

מגלה: pip, pip3, python -m pip, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo.

| פרמטר | סוג | ברירת מחדל | תיאור |
|-----------|------|---------|-------------|
| `allowed` | string[] | `[]` | שמות מנהלי חבילות מורשים. כל מנהל גלוי לא ברשימה זו חסום. כאשר ריק, המדיניות היא no-op. |
| `blocked` | string[] | `[]` | שמות מנהלי חבילות נוספים לחסום מעבר לרשימה המובנית (למשל `['pdm', 'pipx']`). |

רשימת החסום המובנית מכסה: pip, pip3, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo. השתמש ב-`blocked` כדי להוסיף מנהלים לא ברשימה זו.

**תצורה דוגמה:**

```json
{
  "enabledPolicies": ["prefer-package-manager"],
  "policyParams": {
    "prefer-package-manager": {
      "allowed": ["uv", "bun"],
      "blocked": ["pdm", "pipx"]
    }
  }
}
```

עם תצורה זו, `pip install flask` ו-`pdm install flask` שניהם דחויים עם הודעה האומרת Claude להשתמש ב-`uv` או `bun` במקום. פקודות כמו `uv pip install flask` מותרות מכיוון `uv` נמצא בallow-list ובודק ראשון.

## זרימת עבודה

אוכף זרימת עבודה מתורגלת בסיום הפעלה. מדיניויות אלה מופעלות על אירוע **Stop** ודוחות את הסוכן מהעצירה עד שכל תנאי מתמלאים. הם עוקבים אחרי שרשרת תלות טבעית: commit → push → PR → CI. אם מדיניות דוחה, מדיניויות מאוחרות יותר בשרשרת מדולגות (deny short-circuits).

כל מדיניויות זרימת עבודה הן **fail-open**: אם הכלי הנדרש אינו זמין (למשל `gh` לא מותקן, אין remote git), המדיניות מרשה עם הודעה מידעית המסבירה מדוע הבדיקה דלגה.

### סמנטיקת Stop לפי CLI

אכיפת Stop נראית קצת אחרת על פני ששת ה-CLIs הנתמכים מכיוון שלכל אחד יש חוזה ווק "agent finished" שונה. **התוצאה** זהה — הסוכן לא מתחמק מהעצירה בעוד שער זרימת עבודה נכשל — אך **המכניקה** שונה. הטבלה למטה מסכמת; רק Pi יש quirk ראוי לתשומת לב למשתמש לפני שהחלטת להפעיל מדיניות `require-*-before-stop`.

| CLI | מתי שער מופעל | מה אתה רואה |
|---|---|---|
| Claude Code | אותה לולאת סוכן, מיד | Claude ממשיך לעבוד — תיקוני הבעיה, ואז מנסה להסיים שוב. אין הפסקה גלויה לך. |
| Codex | אותה לולאת סוכן, מיד | זהה ל-Claude. |
| GitHub Copilot CLI | אותה לולאת סוכן, מיד | זהה ל-Claude (משתמש בערוץ retry של Copilot `{decision:"block", reason}` — אומת באופן אמפירי נגד Copilot CLI 1.0.41). |
| Cursor Agent | אותה לולאת סוכן, מיד | זהה ל-Claude (משתמש בערוץ `{followup_message}` של Cursor — מוגבל ל-`loop_limit`, ברירת מחדל 5 retries). |
| OpenCode | אותה לולאת סוכן, מיד | זהה ל-Claude (משתמש בקריאת `client.session.prompt(...)` SDK של OpenCode מנותבת דרך `hookSpecificOutput.additionalContext`). |
| **Pi (pi-coding-agent)** | **תור משתמש הבא** | **Pi עוצר כדי שנראה כשער מופעל — לולאת הסוכן שלה יוצאת והחזרה לפרומפט. השער חוזר פעם הבאה שאתה משדר פרומפט: failproofai מקדים הנחיית `MANDATORY ACTION REQUIRED` לsystem prompt של תור זה, הנחיית ה-LLM להשלים את צעד זרימת העבודה (commit, push, וכו') לפני ביצוע מה שביקשת. |

<Note>
**Pi limitation.** `AgentEndEvent` של Pi (המקבילה upstream של Claude's `Stop` hook) אין סוג Result — בזמן שהוא מופעל, לולאת הסוכן של Pi כבר יצאה. Pi לא ניתן לאלץ לנסות שוב את אותה לולאה בדרך ש-Claude / Copilot / Cursor / OpenCode יכולים. failproofai משנה את השער ל-`before_agent_start` event של Pi (המופעל לאחר הפרומפט הבא של המשתמש) כדי שבדיקת זרימת העבודה עדיין אוכפת, רק בתור הבא ולא בנוכחי.

**מה זה אומר בפועל:**

- לאחר Pi עוצר, ה-deny reason נתפס בזיכרון מקודד על ידי Pi session id. הפרומפט הבא בדיוק שאתה משדר באותה Pi process משאבות אותו: ה-LLM רואה את הנחיית `MANDATORY ACTION REQUIRED` בראש system prompt שלו, commits (או pushes / opens the PR / waits for CI), ורק אז ממשיך עם הבקשה שלך. ה-deny reason המיוחס הוא one-shot — ברגע שמשאבות, השער ברור.
- השער מוגבל על ידי lifetime התהליך של Pi. אם `Ctrl+C` Pi או quit בין הופעות, הערך בזיכרון מוטל ביחד עם התהליך והשער מחומק. Claude, Copilot, Cursor ו-OpenCode יש את אותה קשור (kill the agent and the gate is missed) — Pi רק עושה זה יותר גלוי מכיוון שהסוכן גלוי יוצא לפני הנעל.
- א pending deny גם ניקוי ב-`session_shutdown` לכל סיבה (`new` / `resume` / `fork` / `quit`), כך שסטייה gate מפעלת קודמת לא יכולה לדלוף לתוך פעלה טרייה התחילה באותו Pi process.

אם אתה צריך retry same-loop בדרך Claude, הפעיל את ה-`Stop` policies שלך תחת כל אחד מחמשת CLIs הנתמכים האחרים. אנחנו מעקבים אחרי Pi upstream עבור future Result type על `AgentEndEvent` שזה יאפשר לנו לסגור את הפער הזה.
</Note>

### `require-no-conflicts-before-stop`

**אירוע:** Stop  
**ברירת מחדל:** דוחה עצירה כאשר ענף הנוכחי לא יכול להתמזג בנקיון לתוך ענף הבסיס. המדיניות קודם כל מאשרת יש `OPEN` PR ב-GitHub לענף — ללא אחד, אין merge target להוביל, כל המדיניות short-circuits להרשות. ברגע ש-`OPEN` PR מאושרת, שני בדיקות עצמאיות פועלות:

1. **Local** — `git merge-tree --write-tree --name-only origin/<baseBranch> HEAD`. ב-conflict, הודעת deny שמות הקבצים המתנגשים כדי Claude יודע בדיוק מה לפתור.
2. **GitHub** — בשימוש חוזר ב-`gh pr view --json mergeable,state` result כבר fetched ב-precheck. קריאה conflicts שסטייה מקומית `origin/<baseBranch>` היה מחומק (למשל מישהו נחת conflicting PR ב-`main` מאז last fetch). `CONFLICTING` result דוחה. `UNKNOWN` result גם דוחה והנחה Claude להמתין ~10 שניות ו-re-check לפני ניסיון להפסיק שוב — זה מנע false negatives בעוד GitHub recomputes.

דילוג כרוכו (מרשה) כאשר: `gh` אינו מותקן, אין PR לענף, ה-PR's state אינו `OPEN` (למשל `MERGED`, `CLOSED`), או `gh pr view` חוזר unparseable output. גם fails open כאשר `origin/<baseBranch>` חסרה מקומית או אין commits קדימה של בסיס — fall-throughs Layer 1 אלה עדיין היועץ בקashed PR mergeability לפני אישור.

**פרמטרים:**

| פרמ | סוג | ברירת מחדל | תיאור |
|-------|------|---------|-------------|
| `baseBranch` | `string` | `"main"` | ענף בסיס לבדוק conflicts נגד. |

<Note>
GitHub CLI (`gh`) נדרשת עבור מדיניות זו. המדיניות משתמשת ב-`gh pr view` לאשר
`OPEN` PR קיים לפני הפעלת כל בדיקת conflict — ללא `gh`, המדיניות
short-circuits להרשות. הפעל `gh auth login` עם personal access token שיש לו
`repo` scope לקריאה access לpull requests.
</Note>

## השבתת מדיניויות בודדות

הסר מדיניות ספציפית מ-`enabledPolicies` בתצורה שלך, או הפעל אותה בלשונית Policies של הדשבורד.

```json
{
  "enabledPolicies": [
    "block-rm-rf",
    "sanitize-api-keys"
  ]
}
```

מדיניויות לא רשומות ב-`enabledPolicies` אינן פועלות, גם אם `policyParams` entries קיימים להם.
