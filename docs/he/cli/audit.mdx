הביקורת מחדשת את הפעלת תמלילי agent-CLI העברים שלך דרך מנוע המדיניות של failproofai ומרנדרת דוח חזותי שניתן לשיתוף בעמוד לוח המחוונים **`/audit`** — אבטיפוס הסוכן שלך, ציון 0–100, ובדיוק אילו מדיניויות היו תופסות מה.

לוח המחוונים סורק את תמלילי agent CLI עברים במכונה זו (Claude Code, Codex, Copilot, Cursor, OpenCode, Pi) ודיווח כמה פעמים הסוכן עשה דברים שבנוי failproofai כדי לעצור — בדיקות env-var, force pushes, בתחילית `cd <cwd>` מיותרת, לולאות sleep-polling, קריאה חוזרת של קבצים שלתו נערכו, ועוד.

עבור כל תמליל, כל event של tool-use מחדש את הפעלתו דרך 39 מדיניויות בנויות **וגם** דרך 8 גלאים שהם audit-only שתופסים דפוסים שעדיין לא מכוסים על ידי מדיניויות runtime. ספירות מצטברות לכל מדיניות / גלאי בכל הפעלות.

## מה אתה מקבל

העמוד `/audit` הוא **כרזה** של מסך יחיד שניתן לשיתוף ואחריו ארבע חלקים מתחת לקפל:

1. **כרזה** — זהות הסוכן שלך במבט חטוף: **אבטיפוסו** (אחד מ-8 — `optimist`, `cowboy`, `explorer`, `goldfish`, `paranoid architect`, `precision builder`, `hammer`, `ghost`), מילות המפתח של הדמות שלו, כמה נדיר אותו אבטיפוס, וציון **0–100** עם פס רמה (`S` עד `bottom tier`). בנוי לשיתוף — פרסם ב-X או LinkedIn, או הורד אותו כ-PNG.
2. **`// strengths`** — מה הסוכן שלך כבר עושה טוב, כמספרים אמיתיים מהסריקה (למשל clean-tool-call %, `0` push-to-main attempts), מוצג רק כאשר למדיניות הרלוונטית יש רקורד נקי.
3. **`// quirks`** — מה חמק: טבלה מדורגת של התנהגויות שfailproofai היה תופס — *מתי* זה קרה בפעם האחרונה, *מה חמק* (ובנוי שהיה חוסם אותו), ה*חומרה* שלו, וכמה פעמים זה היה *רואה* (`new` / `recurring` / `N× seen`).
4. **`// how to improve`** — רשימת התיקון המוצעת: שורה אחת לכל מדיניות עם `failproofai policy add <slug>` להעתקה והדבקה, בתוספת כפתור **install all** המאפשר כל המלצה בבת אחת ומראה את ה**ציון הצפוי** שלך אם כן.
5. **`// come back better`** — בנה את ההרגל: הגדר **תזכורת** חדשה audit (`3d` / `7d` / `14d` / `30d`) או audit שוב עכשיו, **הזמן חבר** להריץ את הביקורת שלהם (נשלח מ-failproof.ai, Cc אליך). תזכורות והזמנות דורשות כניסה.

## ביקורות מתוזמנות

אם אתה מריץ את **failproofaid daemon** (ראה [`failproofai config`](/he/cli/install-policies)),
הוא יכול להריץ את הביקורת בשבילך בלוח זמנים ולרנדר את דוח `/audit` ברקע. זה **כבוי כברירת מחדל**, מכיוון שהסריקה קוראת את *תוכן* כל תמליל פעולת agent במכונה זו — שום דבר לא סורק בטיימר עד שתבקש זאת.

הפעל אותו ב-`~/.failproofai/config.toml`:

```toml
[audit]
auto = true
interval_days = 7
```

| Key | משמעות |
|---|---|
| `auto` | `true` מאפשר את הסריקה המתוזמנת. כל דבר אחר — חסר, `false`, `"yes"` — כבוי. |
| `interval_days` | ימים בין סריקות. קצוב ל-1–90; `0`, שלילי או לא מספר חוזר ל-`7`. |

- הלוח הזמנים הוא **wall-clock**, אז הוא שורד suspend וreboot: מחשב נייד שהיה במצב שינה תחת הזמן הקבוע שלו פועל **פעם אחת** בהעירה, לעולם לא backlog.
- כל הפעלה היא תהליך נפרד, בעדיפות נמוכה (`nice 19`) — לעולם לא נתיב ה-hook של ה-daemon, שנשאר חופשי כדי להשיב על קריאות tool.
- סריקה מודלפת אם `failproofai audit` או ההרצה מחדש של לוח המחוונים כבר בטיסה; היא מנסה שוב בקרוב במקום להיחשב ככישלון.
- התקדמות נכתבת ל-`~/.failproofai/state/audit-schedule.json` (הפעלה אחרונה, הבאה צפויה). ה-daemon בעלות הקובץ — שנה את הקצב ב-`config.toml`.

<Note>
אם הפעלת זאת במכונה שהוקמה על ידי failproofai ישן יותר, הרץ
`failproofai config` פעם אחת. הגדרת השירות של ה-daemon זקוקה לערך אחד נוסף לפני שהוא יכול להשיק את ה-CLI, והרענון הוא חלק מהפקודה הזאת.
</Note>

## גלאים שהם audit-only

אלה חוקרים דפוסי התנהגות "טיפשית" שלא (עדיין) אינם מופעלים בזמן אמת. הם רצים רק במהלך הביקורת ולעולם לא חוסמים קריאת tool חיה.

| גלאי | מה הוא סופר |
|---|---|
| `redundant-cd-cwd` | פקודות Bash המתחילות ב-`cd <cwd> && …` גם כי הפקודות כבר רצות ב-`cwd`. |
| `prefer-edit-over-read-cat` | `cat`/`head`/`tail`/`less`/`more` בקובץ מקור יחיד — השתמש בכלי `Read`. |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` עריכות במקום — השתמש בכלי `Edit`. |
| `prefer-write-over-heredoc` | Heredoc / `echo > file` מרובה שורות כתיבת קבצים — השתמש בכלי `Write`. |
| `sleep-polling-loop` | `sleep N` ארוך (≥ 30s) או `while …; sleep …; done` לולאות polling. |
| `find-from-root` | `find /`, `find /home`, `find /usr` וכו' — התחום ל-`cwd`. |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, דילוג על hooks. |
| `reread-after-edit` | `Read` של קובץ שזה עתה `Edit`/`Write` באותה פעלולה. |

## מטמונים

- **מטמון לכל-תמליל** ב-`~/.failproofai/cache/audit/<sha1>.json` שמנויי על ידי `(mtime, size, engineVersion, detectorVersion)` — מבטל באופן אוטומטי כאשר התמליל או קוד המדיניות/גלאי משתנים. כל ערך גם מאחסן חותם זמן `cachedAt` כ**מטא-נתון TTL** (לא חלק מממפתח המטמון); ערכים ישנים יותר מ-**7 ימים** נדחים בקריאה כך שתוצאות חיות-ארוך לא יחיו מעבר לכוונת גלאי מתפתחת.
- **מטמון של תוצאה שלמה** ב-`~/.failproofai/audit-dashboard.json` (mode 0600). מאפשר ללוח המחוונים להרנדר באופן מיידי בניווט ללא הרצה מחדש. גם נדחה בקריאה אחרי ה-**7 יום TTL** — `/audit` אז נופל דרך למצבו הריק ותוך הנחת סריקה טרייה. לחץ על `[ re-audit now ]` בסביבות תחתית הדוח כדי לרענן — re-audit שולח `noCache: true`, אז הוא עוקף את מטמון התמליל-לכל ומסרק מחדש כל תמליל במקום להחזיר את התוצאה המקוישת; ההרצה זורמת התקדמות דרך רצועה דבוקה למעלה ומחליפה את התוצאה במקום בהצלחה (אין טעינת דף מחדש; re-audit שנכשל שומר את הדוח הקודם).

## הערות

- **אין מוטציה.** הביקורת חוקרת במצב read-only. `warn-repeated-tool-calls` מדולל מכיוון שה-sidecar לכל-פעלולה שלו היה משונה אחרת.
- **מדיניויות זרימת עבודה מדולל.** `require-*-before-stop` מדיניויות יורות רק על `Stop` events ו-`execSync` נגד מצב ה-git החי — אין להם פרשנות משמעותית "מה היה קורה ב-2025", אז הם לא מופיעים בספירות ביקורת.
- **מדיניויות מותאמות אישית מדולל.** hooks מותאמות אישית מסופקות משתמש לא מחדשות פעולה (הן אולי השתנו מאז הפעלולה המקורית).
