הביקורת כעת חשופה כ-**/audit dashboard page**, לא כ-CLI subcommand. פתחו אותה מתוך navbar של הדוחשבורד (בין Policies ו-Projects), או בקרו ישירות ב-`http://localhost:8020/audit` כאשר מריצים `failproofai` באופן מקומי.

```bash
failproofai          # open the dashboard, then click "Audit"
```

הדוחשבורד סורק תמלילי CLI של סוכן קודמים במכונה זו (Claude Code, Codex, Copilot, Cursor, OpenCode, Pi, Gemini) ודיווח כמה פעמים הסוכן עשה דברים שfailproofai בנוי כדי לעצור — בדיקות של משתני env, force pushes, קידומי `cd <cwd>` מיותרים, sleep-polling loops, קריאה חוזרת של קבצים שזה עתה נערכו, ועוד.

לכל תמליל, כל אירוע tool-use מוקדם שוב דרך 39 המדיניויות המובנות **וגם** דרך 8 גלאים המיוחדים לביקורת התופסים דפוסים שעדיין לא מכוסים על ידי מדיניויות runtime. הספירות מצטברות לכל מדיניות / גלאי על פני כל הפעלות.

## מה אתה מקבל

הדף `/audit` מרכיב שש סעיפים:

1. **Identity** — הסוכן שלך מסווג לאחד מ-8 אב-טיפוסים (`optimist`, `cowboy`, `explorer`, `goldfish`, `paranoid architect`, `precision builder`, `hammer`, `ghost`) בהתאם לאות המשוקלל על פני כל תמליל שביקורת.
2. **Strengths** — מספרים אמיתיים הנובעים מהסריקה (clean-call %, "0 credential leaks", וכו') המגודרים בעקבות המדיניויות sanitize הרלוונטיות בעצם נורים.
3. **Score** — 0-100 עם S/A/B/C/D/F bands והעלייה הצפויה אם כל מדיניות מומלצת תהיה מופעלת.
4. **Findings** — כרטיסי per-policy עם מה קרה, עלות, ראיות שנתפסו, ו-`failproofai policy add <slug>` המדויק להפעלת ה-builtin בזמן חי שהיה תופס אותו.
5. **Prescribed policies** — רשימת התקנה מצטברת עם פקודה `failproofai policies --install` חד-פעמית.
6. **Re-audit reminder** — "תחזרו יותר טוב." הגדרו תזכורת דוא"ל של 7 ימים דרך ה-api-server (דורש כניסה; ראו [`failproofai auth`](/he/cli/auth)).

## גלאים המיוחדים לביקורת

אלה תופסים דפוסי "stupid behavior" שלא (עדיין) מאונצים בזמן חי. הם רצים רק במהלך הביקורת ולעולם לא חוסמים קריאת כלי חי.

| Detector | מה זה סופר |
|---|---|
| `redundant-cd-cwd` | פקודות Bash החלות ב-`cd <cwd> && …` למרות שפקודות כבר רצות ב-`cwd`. |
| `prefer-edit-over-read-cat` | `cat`/`head`/`tail`/`less`/`more` בקובץ מקור יחיד — השתמשו בכלי `Read`. |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` עריכות in-place — השתמשו בכלי `Edit`. |
| `prefer-write-over-heredoc` | Heredoc / `echo > file` רב-שורות כתיבת קבצים — השתמשו בכלי `Write`. |
| `sleep-polling-loop` | `sleep N` ארוך (≥ 30s) או `while …; sleep …; done` polling loops. |
| `find-from-root` | `find /`, `find /home`, `find /usr`, וכו' — ממדו ל-`cwd` במקום. |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, דילוג על hooks. |
| `reread-after-edit` | `Read` של קובץ שזה עתה `Edit`/`Write` באותה הפעלה. |

## Caches

- **Per-transcript cache** ב-`~/.failproofai/cache/audit/<sha1>.json` שמופתח ב-`(mtime, size, engineVersion, detectorVersion)` — מבטל בצורה אוטומטית כאשר התמליל או קוד המדיניות/גלאי משתנה. כל רשומה גם מאחסנת חותמת זמן `cachedAt` כ-**TTL metadata** (לא חלק ממפתח המטמון); רשומות שקדמו ליותר מ-**7 ימים** דחויות בקריאה כדי שתוצאות ארוכות טווח לא יחיו יותר מכוונת גלאי משתנה.
- **Whole-result cache** ב-`~/.failproofai/audit-dashboard.json` (mode 0600). מאפשר לדוחשבורד להציג תוצאות באופן מיידי בניווט ללא הפעלה חוזרת. גם דחוי בקריאה אחרי ה-**7-day TTL** — `/audit` אז נופל למצב הריק שלו ומנהל פעולה הנ ה-run טרי. לחצו `[ re-audit now ]` ליד התחתית של הדוח לרענון; ה-run החדש זורם התקדמות דרך רצועה דבוקה בחלק העליון ומחליף את התוצאה במקום בהצלחה (אין טעינה מחדש של דף).

## הערות

- **No mutation.** הביקורת מוקדמת במצב read-only. `warn-repeated-tool-calls` דולג מכיוון שה-sidecar שלה per-session אחרת היה משתנה.
- **Workflow policies skipped.** מדיניויות `require-*-before-stop` נורים רק באירועי `Stop` ו-`execSync` כנגד state git חי — אין להם פירוש משמעותי "מה היה קורה ב-2025", ולכן הם לא מופיעים בספירות ביקורת.
- **Custom policies skipped.** hooks חד-פעמי מסופקים משתמש לא מוקדמים (הם אולי השתנו מאז ההפעלה המקורית).
