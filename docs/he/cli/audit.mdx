הביקורת מפעילה מחדש את תמלילי ה-agent-CLI בעברך דרך מנוע המדיניות של failproofai וממציאה דוח ויזואלי וניתן לשיתוף בעמוד לוח הבקרה **`/audit`** — הטיפוס של הסוכן שלך, ניקוד 0–100, וממש אילו מדיניויות היו קופצות את מה.

## הפעלה

שלוש דרכים פנימה — כולן נוחתות באותה דוח `/audit`.

<CodeGroup>

```bash npx (ללא התקנה)
npx -y failproofai audit
```

```bash failproofai audit
failproofai audit
```

```bash failproofai (לוח בקרה)
failproofai
```

</CodeGroup>

לוח הבקרה סורק תמלילי agent CLI בעבר ב-machine זה (Claude Code, Codex, Copilot, Cursor, OpenCode, Pi) ודיווחים כמה פעמים הסוכן עשה דברים שבנוי failproofai כדי לעצור — בדיקות env-var, דחיפות כפויות, קידומות `cd <cwd>` יתירות, לולאות sleep-polling, קריאה מחדש של קבצים שנערכו זה עתה, ועוד.

עבור כל תמליל, כל אירוע שימוש בכלי מופעל מחדש דרך 39 מדיניויות מובנות **וגם** דרך 8 גלאים המיוחדים לביקורת התופסים דפוסים שעדיין לא מכוסים על ידי מדיניויות זמן ריצה. הספירות משולבות לכל מדיניות / גלאי על פני כל ההישיבות.

## מה אתה מקבל

עמוד `/audit` הוא **פוסטר** בעמוד יחיד וניתן לשיתוף ואחריו ארבע סעיפים מתחת לקפל:

1. **Poster** — הזהות של הסוכן שלך בהבט ראשון: שלו **archetype** (אחד מ-8 — `optimist`, `cowboy`, `explorer`, `goldfish`, `paranoid architect`, `precision builder`, `hammer`, `ghost`), מילות-מפתח של האישיות שלו, עד כמה נדיר הטיפוס הזה, וניקוד **0–100** עם להקת רמה (`S` למטה לתחתון). בנוי לשיתוף — הוסף ל-X או LinkedIn, או הורד אותו כ-PNG.
2. **`// strengths`** — מה הסוכן שלך כבר עושה טוב, כמספרים אמיתיים מהסריקה (למשל clean-tool-call %, `0` push-to-main attempts), מוצג רק כאשר למדיניות הרלוונטית יש רקורד נקי.
3. **`// quirks`** — מה חדר דרך: טבלה דורגת של התנהגויות שבנוי failproofai כדי לתפוס — *מתי* זה קרה לאחרונה, *מה חדר* (וה-builtin שהיה חוסם אותו), ה-*severity* שלו, וכמה פעמים זה *נראה* (`new` / `recurring` / `N× seen`).
4. **`// how to improve`** — רשימת ההתיקון המוינה: שורה אחת לכל מדיניות עם `failproofai policy add <slug>` העתק-הדבק, בתוספת כפתור **install all** המאפשר כל המלצה בבת אחת ומציג את **ניקוד משוער** אם עשית זאת.
5. **`// come back better`** — בנה את ההרגל: הגדר **reminder** לביקורת חוזרת בדוא״ל (`3d` / `7d` / `14d` / `30d`) או בצע ביקורת עכשיו, **and invite a friend** להפעיל את הביקורת שלהם (נשלח מ-failproof.ai, Cc לך). הזכרונות וההזמנות דורשים כניסה.

## ביקורות מתוזמנות

אם אתה מפעיל את **daemon failproofaid** (ראה [`failproofai config`](/he/cli/install-policies)),
הוא יכול להפעיל מחדש את הביקורת עבורך בלוח זמנים ולרענן את דוח `/audit` ב-background. זה **כבוי כברירת מחדל**, מכיוון שהסריקה קוראת את *contents* של כל תמליל הישיבה של סוכן ב-machine זה — שום דבר לא סורק בטיימר עד שאתה מבקש זאת.

הפעל זאת ב-`~/.failproofai/config.json` — הוסף את המפתח `audit` לצד כל מה שהקובץ כבר מחזיק:

```json
{
  "audit": {
    "auto": true,
    "interval_days": 7
  }
}
```

| מפתח | משמעות |
|---|---|
| `auto` | `true` מאפשר את הסריקה המתוזמנת. כל דבר אחר — נעדר, `false`, `"yes"` — הוא כבוי. |
| `interval_days` | ימים בין סריקות. מחובר ל-1–90; `0`, שלילי או לא-מספר חוזר לברירת מחדל `7`. |

- הלוח הזמנים הוא **wall-clock**, כך שהוא שורד השהיה וריסטרטים: למחשב נייד שהיה במתן עבר לזמן הקצוב שלו פעם **once** על עירוד, לא אף פעם רשימת המתנה.
- כל ריצה היא תהליך נפרד, בעדיפות נמוכה (`nice 19`) — לעולם לא נתיב ה-daemon hook שלך, שנשאר חופשי לענות על קריאות כלים.
- סריקה מדולגת אם `failproofai audit` או חזוזור לוח הבקרה כבר בטיסה; זה מנסה שוב זמן קצר אחר כך במקום להיות מטופל ככישלון.
- התקדמות כתובה ל-`~/.failproofai/state/audit-schedule.json` (ריצה אחרונה, הבא קצוב). ה-daemon בבעלות הקובץ הזה — שנה את הקצב ב-`config.json`.

<Note>
אם הפעלת זאת ב-machine שהוגדר על ידי failproofai ישן יותר, הפעל
`failproofai config` פעם אחת. להגדרת השירות של ה-daemon צריך רשומה אחת נוספת לפני שהוא יכול לשגר את ה-CLI, והרענון הוא חלק מהפקודה הזאת.
</Note>

## גלאי-ביקורת-בלבד

אלה גוררים דפוסי התנהגות עלוקה לא (עדיין) כפויים בזמן אמת. הם רצים רק במהלך הביקורת ולעולם לא חוסמים קריאת כלי חיה.

| גלאי | מה זה סופר |
|---|---|
| `redundant-cd-cwd` | פקודות Bash המתחילות ב-`cd <cwd> && …` למרות שפקודות כבר רצות ב-`cwd`. |
| `prefer-edit-over-read-cat` | `cat`/`head`/`tail`/`less`/`more` בקובץ מקור יחיד — השתמש בכלי `Read`. |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` עריכות מקום — השתמש בכלי `Edit`. |
| `prefer-write-over-heredoc` | Heredoc / `echo > file` multi-line כתיבת קבצים — השתמש בכלי `Write`. |
| `sleep-polling-loop` | `sleep N` ארוכה (≥ 30s) או `while …; sleep …; done` לולאות סריקה. |
| `find-from-root` | `find /`, `find /home`, `find /usr` וכו' — scope ל-`cwd` במקום זאת. |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, דילוג על hooks. |
| `reread-after-edit` | `Read` של קובץ ש`Edit`/`Write` זה עתה באותה הישיבה. |

## יציבות

- **יציבות-לפי-תמליל** ב-`~/.failproofai/cache/audit/<sha1>.json` מקבוצות על ידי `(mtime, size, engineVersion, detectorVersion)` — מפיק באופן אוטומטי כאשר התמליל או קוד המדיניות / גלאי משתנה. כל רשומה מאחסנת גם `cachedAt` timestamp כ-**TTL metadata** (לא חלק מהמפתח המטמון); רשומות קדומות יותר מ-**7 ימים** נדחות על קריאה כדי שתוצאות חיות ארוכות לא יחיו יותר מכוונת גלאי מתפתחת.
- **יציבות-תוצאה-שלמה** ב-`~/.failproofai/audit-dashboard.json` (mode 0600). תן ללוח הבקרה להציג באופן מיידי על ניווט מבלי להפעיל מחדש. גם נדחה על קריאה עבור **7-day TTL** — `/audit` אז נופל דרך למצב הריק שלו ותוקיף ריצה טרייה. לחץ על `[ re-audit now ]` קרוב לתחתית הדוח לרענון — re-audit שולח `noCache: true`, כך שהוא עוקף את יציבות ה-per-transcript ושוב סורק כל תמליל במקום להחזיר את התוצאה במטמון; הריצה זורמת התקדמות דרך סרגל דבוק עליון והחליפה את התוצאה במקום בהצלחה (לא טעינה דף; re-audit שנכשל שומר את הדוח הקודם).

## הערות

- **אין מוטציה.** הביקורת מופעלת מחדש במצב קרא-בלבד. `warn-repeated-tool-calls` מדולגת מכיוון שה-sidecar ליחידה שלה אחרת היה משתנה.
- **מדיניויות זרימת עבודה דלוגה.** מדיניויות `require-*-before-stop` יורים רק על אירועי `Stop` ו-`execSync` נגד מצב ה-git החיה — אין להם פירוש משמעותי של כל דבר ב-2025", כך שהם לא מופיעים בספירות הביקורת.
- **מדיניויות מותאמות אישית דלוגה.** hooks מסופקים על ידי משתמש אינם מופעלים מחדש (הם עלולים להשתנות מאז ההישיבה המקורית).
