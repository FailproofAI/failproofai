---

```bash
failproofai migrate --dry-run   # print the plan, change nothing
failproofai migrate             # run it
```

רוב האנשים לעולם לא מקלידים זאת. היא רצה בעצמה בפקודה הראשונה אחרי שדרוג, ו-[`failproofai update`](/he/cli/update) כוללת אותה. השתמש בה ישירות כאשר אתה רוצה לראות את התוכנית לפני שזה קורה, או להריץ את ההעברה בעצמה.

## מותאם לפריסה, לא לגרסה

`~/.failproofai/VERSION` שומר מספר **פריסה** — צורת הספריה, לא ההוצאה שכתבה אותה. העברות מותאמות למספר זה, וזה מה שהופך פער ארוך לזול:

- גרסאות npm משתנות בכל הוצאה, עשרות מהן בין שתי פריסות.
- אז מכונה שמדלגת על שלוש עשרים הוצאות עם **אין שינוי בפריסה** מריצה **אפס** העברות, לא שלוש עשרים ריקים.
- ומכונה שמדלגת על מספר פריסות בבת אחת מריצה כל שלב בסדר, כל שלב יודע רק את שני הקצוות שלו.

זה חשוב כי npm לא יכול לעדכן חבילה מותקנת בעצמו. מכונה שישבה על גרסה אחת במשך חודשים ואז קפצה מספר פריסות היא המקרה הנורמלי, לא זה האקזוטי.

## ההרצה הייבוש

`--dry-run` מדפיס את השרשרת המדויקת והקבצים שיישמרו קודם לכן, ולא משנה כלום כלל — אין העברה, אין גיבוי, אין ערך בספר:

```
Layout 2 on disk; this build speaks 3.
1 step(s) would run:
  2 → 3  layout 2 → 3: carry config.toml and credentials.toml into JSON, move
         custom-policies/ back up into policies/, nest the policy config at the root

These would be copied to ~/.failproofai/migrations/backup-layout2 first:
  VERSION
  config.toml
  credentials.toml
```

## מה מועבר ומה בנוי מחדש

כל נתיב בספריית הבית מצהיר איזה סוג של נתונים הוא מחזיק, וזה קובע אם העברה רשאית להשליך אותו. הכלל: **גזור וניתן להישב רשאי להיחסל; כל דבר שהקלדת, כל דבר שעדיין לא הסופק, וכל דבר המזהה את המכונה מועבר.**

| מועבר | בנוי מחדש או מוזחק |
|---|---|
| `config.json` — הגדרות, `daemon.configured`, נתיבי לכידה נוספים | מטמון הביקורת |
| `credentials.json` — הרישום בענן שלך | פריסות מנוהלות בענן (מוזחקות מחדש ואימות תיבול בסקר הבא) |
| `policies-config.json` — בחירת המדיניות שלך ופרמטרים | מצב שטח של דמון |
| `policies/` — קבצי המדיניות שלך והעוזרים שהם יבואו | |
| `hook-activity/` — יומן ההחלטות שדוח הבקרה קורא | |
| אירועים שטרם סופקו עדיין בתור העלאה | |
| `cursors/` — סימני מים של אספן | |
| הקובץ הבינארי של הדמון בתוך `bin/` | |

<Note>
  אירועים שטרם סופקו מועברים במקום להיחסל כי ההפסד יהיה קבוע, לא איטי: סימן המים של אספן כבר התקדם חלף כל דבר בממשק, אז שום דבר לא יקרא שום טווח של תמלול שוב. ההעברה גם מבקשת מהדמון להסיע מה שבממשק ברגע שהוא מסיים, אז התוצאה הרגילה היא שאין כלום שנותר להעביר.
</Note>

מפתחות שגרסה **חדשה יותר** כתבה לתוך `config.json`, `credentials.json` או `policies-config.json` משמרים גם כן, במקום להיחסל על ידי קורא ישן יותר.

## הרשומה שהיא משאירה

```
~/.failproofai/migrations/
  applied.json                 ערך אחד לכל שלב: פריסה, CLI, חותמת זמן, משך, תוצאה
  backup-layout<n>/            עותקים של קבצים בלתי ניתן להחלפה, שצולמו לפני השלב הראשון
```

`applied.json` היא מה שמענה — מה זו המכונה הזו בעצם עברה — השאלה הראשונה שכדאי לשאול כאשר משהו נראה לא בסדר לאחר שדרוג. צרף אותה לדוח באג.

הגיבוי קטן בכוונה במקום עותק של כל הספריה: ההעברה כבר לא מוחקת כלום בלתי ניתן להחלפה בעיצוב, אז מה שכדאי לבטח נגדו היא **פגם בשלב**, וקבצים ספורים אלה הם המקום שבו פגם כזה פוגע.

## אם שלב נכשל

השרשרת עוצרת שם. `VERSION` מתבול רק על ידי שלב שהושלם, אז הבית נשאר מסומן עם פריסתו הישנה והפקודה הבאה מנסה שוב — בית לעולם לא מסומן כנוכחי על כוחו של העברה חלקית. השלב מתועד בתוך `applied.json` עם `"ok": false`, והגיבוי הוא המקום בו הוא צולם.

## בית בחדש מסרב, לא מועבר

אם `~/.failproofai/` נכתב על ידי **חדש יותר** failproofai מזה שאתה מריץ, הפקודה עוצרת ואומרת לך לשדרג במקום. נתונים אלה בסדר גמור וקורא CLI חדש יותר קורא אותם; העברה קדמית מזה לא קיימת, ואיפוס זה יהרוס משהו שניתן להשיגו.

```
This machine's failproofai directory was written by a newer version (layout 4;
this build speaks 3). Upgrade rather than migrate:
  npm install -g failproofai@latest
```

הדמון מיישם את אותו כלל: `failproofaid` מסרב להתחיל נגד פריסה שהוא לא מדבר, במקום לקרוא ולכתוב נתיבים שהתנעו.
