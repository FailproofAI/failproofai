failproofai משתמש בקובצי הגדרה JSON כדי לשלוט באילו מדיניות פעילה, כיצד הם מתנהגים, ומאיפה מדיניות מותאמת אישית נטענת. ההגדרה תוכננה להיות קלה לשיתוף עם הצוות שלך - יבול אותה לריפו שלך וכל מפתח יקבל את אותה רשת בטיחות agent.

---

## היקפי הגדרה

יש שלושה היקפי הגדרה, המוערכים בסדר עדיפות:

| היקף | נתיב קובץ | מטרה |
|-------|-----------|---------|
| **project** | `.failproofai/policies-config.json` | הגדרות לפי ריפו, מובעות לשליטה בגרסאות |
| **local** | `.failproofai/policies-config.local.json` | עקיפות אישיות לפי ריפו, בתוך gitignore |
| **global** | `~/.failproofai/policies-config.json` | ברירות ברמת משתמש בכל הפרויקטים |

כאשר failproofai מקבל אירוע hook, הוא טוען ומיזג את כל שלושת הקבצים שקיימים עבור ספריית העבודה הנוכחית.

### כללי מיזוג

**`enabledPolicies`** - האיחוד של כל שלושת ההיקפים. מדיניות שהוגדרה כפעילה בכל רמה פעילה.

```text
project:  ["block-sudo"]
local:    ["block-rm-rf"]
global:   ["block-sudo", "sanitize-api-keys"]

resolved: ["block-sudo", "block-rm-rf", "sanitize-api-keys"]  ← deduplicated union
```

**`policyParams`** - ההיקף הראשון שמגדיר params למדיניות נתונה מנצח לחלוטין. אין מיזוג עמוק של ערכים בתוך params של מדיניות.

```text
project:  block-sudo → { allowPatterns: ["sudo apt-get update"] }
global:   block-sudo → { allowPatterns: ["sudo systemctl status"] }

resolved: { allowPatterns: ["sudo apt-get update"] }   ← project wins, global ignored
```

```text
project:  (no block-sudo entry)
local:    (no block-sudo entry)
global:   block-sudo → { allowPatterns: ["sudo systemctl status"] }

resolved: { allowPatterns: ["sudo systemctl status"] }  ← falls through to global
```

**`customPoliciesPaths` / `customPoliciesPath`** - ההיקף הראשון שמגדיר אחת מהצורות מנצח.

**`disabledCustomPolicies`** - איחוד בכל ההיקפים. לוח המחוונים כותב מזהה מתוקצר מקור כאן כשאתה מכבה מדיניות בודדת מקובץ מדיניות מפורש או כישרון. מדיניות שלא מופיעה בתור נשארת פעילה כברירת מחדל; המזהים כוללים את קובץ המקור כך שמדיניות בעלות אותו שם בקבצים מרובים יכולות להיות שולטות בעצמאות.

**`llm`** - ההיקף הראשון שמגדיר זה מנצח.

## פורמט קובץ הגדרה

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-push-master",
    "sanitize-api-keys",
    "sanitize-jwt",
    "block-env-files",
    "block-read-outside-cwd"
  ],
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    },
    "block-push-master": {
      "protectedBranches": ["main", "release", "prod"]
    },
    "block-rm-rf": {
      "allowPaths": ["/tmp"]
    },
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company"]
    },
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo API key" }
      ]
    },
    "warn-large-file-write": {
      "thresholdKb": 512
    }
  },
  "customPoliciesPath": "/home/alice/myproject/my-policies.js"
}
```

## ייחוס שדה

### `enabledPolicies`

Type: `string[]`

רשימת שמות מדיניות להפעלה. השמות חייבים להתאים בדיוק למזהי מדיניות המוצגים על ידי `failproofai policies`. ראה [Built-in Policies](/he/built-in-policies) לרשימה המלאה.

מדיניות שלא ב-`enabledPolicies` בלתי פעילה, גם אם יש לה ערכים ב-`policyParams`.

### `policyParams`

Type: `Record<string, Record<string, unknown>>`

עקיפות parameter לפי מדיניות. המפתח החיצוני הוא שם המדיניות; המפתחות הפנימיים ספציפיים למדיניות. כל מדיניות תיעד את הפרמטרים הזמינים שלה ב-[Built-in Policies](/he/built-in-policies).

אם למדיניות יש פרמטרים אך אתה לא מציין אותם, משתמשים בברירות המחדל המובנות של המדיניות. משתמשים שלא מגדירים `policyParams` כלל מקבלים התנהגות זהה לגרסאות קודמות.

מפתחות לא ידועים בתוך בלוק params של מדיניות מתעלמים בשקט בעת הפעלת hook אך מסומנים כאזהרות כשאתה מריץ `failproofai policies`.

#### `hint` (רוחב-כרוכה)

Type: `string` (אופציונלי)

הודעה מצורפת לסיבה כשמדיניות מחזירה `deny` או `instruct`. השתמש בה כדי לתן Claude הנחיה פעולה ללא שינוי המדיניות עצמה.

עובד עם כל סוג מדיניות — מובנה, מותאם אישית (`custom/`), כישרון פרויקט (`.failproofai-project/`), או כישרון משתמש (`.failproofai-user/`).

```json
{
  "policyParams": {
    "block-force-push": {
      "hint": "Try creating a fresh branch instead."
    },
    "block-sudo": {
      "allowPatterns": ["sudo apt-get"],
      "hint": "Use apt-get directly without sudo."
    },
    "custom/my-policy": {
      "hint": "Ask the user for approval first."
    }
  }
}
```

כשה-`block-force-push` דוחה, Claude רואה: *"Force-pushing is blocked. Try creating a fresh branch instead."*

ערכים שאינם מחרוזת ומחרוזות ריקות מתעלמות בשקט. אם `hint` לא מוגדר, התנהגות לא משתנה (תואמת לאחור).

### `customPoliciesPath`

Type: `string` (נתיב מוחלט)

נתיב לקובץ JavaScript המכיל מדיניות hook מותאמת אישית. זה מוגדר באופן אוטומטי על ידי `failproofai policies --install --custom <path>` (הנתיב מחושב לערך מוחלט לפני שמחסנונים).

הקובץ נטען מחדש בכל אירוע hook - אין קיצוץ. ראה [Custom Policies](/he/custom-policies) לפרטי תחבור.

### מדיניות מבוססות כישרון

בנוסף ל-`customPoliciesPath` המפורש, failproofai גוגל ממלא אוטומטית וטוען קבצי מדיניות מספריות `.failproofai/policies/`:

| רמה | ספריה | היקף |
|-------|-----------|-------|
| Project | `.failproofai/policies/` | משותף עם צוות דרך בקרת גרסאות |
| User | `~/.failproofai/policies/custom-policies/` | אישי, חל על כל הפרויקטים |

<Note>
  ספריית הרמה של המשתמש ירדה רמה אחת בארגון מחדש של ספרייה ביתית.
  קבצים שנותרו בנתיב הישן `~/.failproofai/policies/` מועברים
  ל-`custom-policies/` באופן אוטומטי בפעם הראשונה שתריץ כל פקודת `failproofai`
  לאחר שדרוג, והפקודה אומרת לך אילו קבצים היא העבירה.
</Note>

**התאמת קובץ:** רק קבצים התואמים `*policies.{js,mjs,ts}` נטענים (למשל `security-policies.mjs`, `workflow-policies.js`). קבצים אחרים בספריה מתעלמים.

**אין צורך בהגדרה:** מדיניות כישרון אינה דורשת ערכים ב-`policies-config.json`. פשוט זרוק קבצים לספריה והם נבחרו בו אירוע hook הבא.

**טעינה איחוד:** שתי ספריות כישרון פרויקט משתמש סורקות. כל קבצים התואמים משתי רמות נטענים (בשונה מ-`customPoliciesPath` שמשתמש ב-first-scope-wins).

ראה [Custom Policies](/he/custom-policies) לפרטים נוספים ודוגמאות.

### `llm`

Type: `object` (אופציונלי)

תצורת לקוח LLM עבור מדיניות שעושות קריאות AI. לא נדרש לרוב ההגדרות.

```json
{
  "llm": {
    "model": "claude-sonnet-4-6",
    "apiKey": "sk-ant-..."
  }
}
```

## ניהול הגדרה מה-CLI

הפקודות `policies --install` ו-`policies --uninstall` כותבות לקובץ הגדרות hook של CLIשל agent שלך (נקודות כניסה hook), בעוד `policies-config.json` הוא הקובץ שאתה מנהל ישירות. השניים נפרדים:

- **הגדרות Agent CLI** — אומרת ל-agent להתקשר `failproofai --hook <event>` בכל שימוש כלי:
  - **Claude Code**: `~/.claude/settings.json` (משתמש), `<cwd>/.claude/settings.json` (פרויקט), `<cwd>/.claude/settings.local.json` (מקומי)
  - **OpenAI Codex**: `~/.codex/hooks.json` (משתמש), `<cwd>/.codex/hooks.json` (פרויקט) — Codex אין לו היקף `local`
  - **GitHub Copilot CLI _(beta)_**: `~/.copilot/hooks/failproofai.json` (משתמש), `<cwd>/.github/hooks/failproofai.json` (פרויקט) — Copilot אין לו היקף `local`. ערכי Hook משתמשים בשדות פקודה `bash`/`powershell` של Copilot בשם OS עם `timeoutSec`; הקובץ נושא סימן `version: 1` ברמה עליונה. Copilot CLI support הוא **beta** בזמן שאנו מאמתים את `events.jsonl` record schema (אשר docs הציבוריות לא מציינות) כנגד יותר sessions בעולם האמיתי. **VS Code Copilot Chat agent mode (Preview)** קורא תצורות hook מ-`.github/hooks/*.json`, `~/.copilot/hooks/*.json`, ו-`~/.claude/settings.json` (נשלט על ידי הגדרת `chat.hookFilesLocations`) באמצעות חוזה Claude-shaped זהה `{hookSpecificOutput:{permissionDecision:"deny",…}}` — הנתיבים המדויקים שה-`copilot` integration וגם ה-`claude` integration (`~/.claude/settings.json`) כבר כותבים, כך ש-`failproofai policies --install --cli copilot` (או `--cli claude`) **כבר אוכף ב-VS Code agent mode** ללא צורך בintegration נפרד `vscode` (מאומת חיות מ-logs גילוי של VS Code).
  - **Cursor Agent _(beta)_**: `~/.cursor/hooks.json` (משתמש), `<cwd>/.cursor/hooks.json` (פרויקט) — Cursor אין לו היקף `local`. ערכי Hook משתמשים בטופס Claude-shaped `{type, command, timeout}` (ללא פיצול `bash`/`powershell`), אך מאוחסנים תחת מפתחות אירוע camelCase (`preToolUse`, `beforeSubmitPrompt`, …) במערך שטוח לפי [schemas hook](https://cursor.com/docs/hooks) של Cursor; הקובץ נושא סימן `version: 1` ברמה עליונה. ההנדלר מנרמל camelCase → PascalCase דרך `CURSOR_EVENT_MAP` כך שמדיניות built-in קיימות ממשיכות ללא שינוי. Cursor Agent support הוא **beta** בזמן שאנו מאמתים את Cursor's transcript on-disk format (לא מצויין בdocs הציבוריות) כנגד יותר התקנות בעולם האמיתי.
  - **OpenCode _(beta)_**: `~/.config/opencode/opencode.json` + `~/.config/opencode/plugins/failproofai.mjs` (משתמש), `<cwd>/.opencode/opencode.json` + `<cwd>/.opencode/plugins/failproofai.mjs` (פרויקט) — OpenCode אין לו היקף `local`. בשונה מחמש CLIs אחרות, OpenCode אין **ללא external-command hook system**: היא טוענת plugins JS/TS in-process מרוכזות המרשומות באופן מפורש דרך מערך `plugin: []` ב-`opencode.json` (auto-discovery מ-`.opencode/plugins/` הוא **לא** איך plugins נטענים ב-opencode v1.14.33). Install שוקל shim plugin קטן שמעבד-קורא ל-binary failproofai ומתרגם את החזרת JSON Claude-shape של binary חזרה לסמנטיקה plugin: `throw new Error()` לdeny tool-event (בטל את קריאת הכלי), `client.session.prompt(...)` לinstruct ו-deny של `Stop`/`SubagentStop` (שלח את סיבת deny בתור הודעת המשתמש הבאה — הערוץ force-retry היחיד שכן `session.idle` הוא notification-only והזריקה ממנו היא no-op), ו-no-op לallow. ה-shim מנרמל שמות כלים (lowercase → PascalCase דרך `OPENCODE_TOOL_MAP`) ומפתחות arg של tool-input (camelCase → snake_case דרך `OPENCODE_TOOL_INPUT_MAP` ל-`Read`/`Write`/`Edit`, למשל `filePath` → `file_path`, `oldString` → `old_string`) לפני קדימה ל-binary, כך שbuiltins בדיקת נתיב כמו `block-read-outside-cwd`, `block-env-files`, ו-`block-secrets-write` ממשיכים ללא שינוי בקריאות כלי OpenCode. Sessions חיות ב-SQLite DB של opencode ב-`~/.local/share/opencode/opencode.db`; צופה session של לוח המחוונים קורא אותם דרך `opencode db --format json` ו-`opencode export <id>`. OpenCode support הוא **beta** בזמן שאנו מאמתים התנהגות ברחבי גרסאות וכנגד יותר sessions בעולם האמיתי. ראה את [OpenCode plugins docs](https://opencode.ai/docs/plugins/).
  - **Pi _(beta)_**: `~/.pi/agent/settings.json` (משתמש), `<cwd>/.pi/settings.json` (פרויקט) — Pi אין לו היקף `local`. Pi טוענת extension packages TypeScript בעת startup; קובץ הגדרות הוא מערך מחרוזות שטוח `{"packages": ["./relative/path", …]}`. failproofai כותבת ערך packages-array בודד המצביע על ספרייה `pi-extension/` של שלה. ה-extension מנויה פנימית לאירועי `tool_call`/`user_bash`/`input`/`session_start` של Pi ושוקלת לקובץ `failproofai --hook <Event> --cli pi`; ההנדלר מנרמל underscore_lower_snake_case → PascalCase דרך `PI_EVENT_MAP` כך שמדיניות built-in קיימות ממשיכות ללא שינוי. args של tool input גם מנורמל דרך `PI_TOOL_INPUT_MAP` (Read/Write/Edit של Pi מסלק `path` במקום `file_path`; מיפוי המפתח ברמה עליונה מאפשר ל-`block-env-files` ו-`block-secrets-write` להמשיך — ל-`block-read-outside-cwd` כבר היה fallback `path`). Pi support הוא **beta** בזמן שExtension API ו-session-log layout של Pi מתייצבות.
  - **Hermes (hermes-agent)**: `~/.hermes/config.yaml` (**היקף משתמש בלבד** — Hermes אין לו תצורה project/local). Hermes הוא **gateway** Slack/Telegram, כך שone install יוצר קריאות כלים מכל platform (Slack/Telegram/cli/cron) **וגם** subagents פנימיים. ערכי Hook הם זוג `{command, timeout}` (timeout ב-**seconds**) תחת מפה `hooks:` חפה לפי אירועי snake_case של Hermes (`pre_tool_call`/`post_tool_call`/`on_session_start`/`on_session_end`/`subagent_stop`); ההנדלר מנרמל אירועים דרך `HERMES_EVENT_MAP` ושמות כלים דרך `HERMES_TOOL_MAP` כך שמדיניות built-in ממשיכות ללא שינוי. התצורה עורכת דרך round-trip YAML `Document` משמרת הערות כך שהגדרות אחרות של המפעיל שרדות, וinstall מגדיר `hooks_auto_accept: true` כך ש-gateway headless (no TTY) מריץ hooks ללא consent prompt. ה-evaluator פולט חוזה stdout `{"decision":"block","reason"}` של Hermes (Hermes תעלם ממילות יציאה). **Limitations:** Hermes אין אירוע turn-end `Stop`, כך שbuiltins `require-*-before-stop` לעולם לא ממשיכים לזה (לא חל, לא שבור); `instruct` מתדרדר ל-allow-with-logged-note (ללא ערוץ additional-context); וredaction סוד output (`sanitize-*`) לא יכול לשכתב פלט כלי על פני חוזה shell-hook. Hermes הוא **גם** מקור **audit** offline — לוח המחוונים קורא sessions gateway שלו ישירות מ-`~/.hermes/state.db`.
  - **OpenClaw (openclaw gateway)**: `~/.openclaw/openclaw.json` (**היקף משתמש בלבד** — OpenClaw אין לו תצורה project/local). כמו Hermes, OpenClaw היא **gateway** מרובת ערוצים self-hosted, כך שone install יוצרת קריאות כלים מכל ערוץ ו-subagents פנימיים שלה. Enforcement מתבצע דרך **in-process plugin hooks** של OpenClaw (ה-hooks מבוססי קובץ פנימיים שלה הם observation-only ולא יכולים לחסום), כך — כמו OpenCode/Pi — failproofai משלחת static `openclaw-plugin/` package שמזרות async-ערך את binary failproofai ומתרגמת את הפסק. Install רושם את ספרייה plugin הנשלחת ב-`plugins.load.paths[]` של `openclaw.json` ומאפשרת אותה תחת `plugins.entries.failproofai` (עם `hooks.allowConversationAccess: true`, נדרש עבור hooks שיחה גולמיים). ה-evaluator פולט פסק שטוח `{permission, reason}` וה-shim ממפה אותו לצורה חזרה של כל hook: `before_tool_call → {block:true, blockReason}` (**PreToolUse**), `before_agent_run → {outcome:"block", reason}` (**UserPromptSubmit**), ו-`before_agent_finalize → {action:"revise", reason}` (**Stop** — שער turn-end אמיתי, כך שbuiltins `require-*-before-stop` **אוכפים** ב-OpenClaw, בשונה מ-Hermes). אירועים ושמות כלים מנרמלים binary-side דרך `OPENCLAW_EVENT_MAP`/`OPENCLAW_TOOL_MAP` (`exec→Bash`, `read→Read`, …) כך שמדיניות built-in ממשיכות ללא שינוי; ה-shim נכשל פתוח בכל שגיאת spawn/parse/timeout. OpenClaw הוא **גם** מקור **audit** offline — לוח המחוונים קורא sessions שלה ב-JSONL ב-`~/.openclaw/agents/<agentId>/sessions/<uuid>.jsonl`.
  - **Factory Droid (`droid`)**: `~/.factory/hooks.json` (משתמש), `<cwd>/.factory/hooks.json` (פרויקט) — Factory אין לו היקף `local`. droid משלחת external-command hook system בסגנון Claude, אך עם שתי פיתויים מאומתות חיות כנגד droid v0.171.0: (1) שמות אירוע חיים ברמה **top level** של `hooks.json` — אין **ללא עטיפת `"hooks"`** (droid דוחה אחת); אירועי כלים (`PreToolUse`/`PostToolUse`) נושאים `"matcher": "*"`, אירועים שאינם כלים משמיטים אותו. (2) Deny מונע על ידי hook **exit code 2 + stderr**, לא החלטת JSON — הענף `factory` של ה-evaluator מחזיר exit 2 עבור אירועי כלים/prompt ו-`{decision:"block", reason}` רק באירוע turn-end `Stop` (ערוץ force-retry היחיד של droid). אירועים כבר PascalCase (ללא event map) והחיבור הוא Claude snake_case; רק שמות כלים מנורמל דרך `FACTORY_TOOL_MAP` (`Execute→Bash`, `Create→Write`, `FetchUrl→WebFetch`, …). Factory הוא **גם** מקור **audit** offline — לוח המחוונים קורא sessions on-disk JSONL שלה ב-`~/.factory/sessions/<encoded-cwd>/<sessionId>.jsonl`.
  - **Devin CLI (`devin`, Cognition)**: `~/.config/devin/config.json` (משתמש), `<cwd>/.devin/config.json` (פרויקט) — Devin אין לו היקף `local`. Devin הוא **pure Claude-clone** מאומת חיות כנגד devin v3000.1.27: היא משתמשת בschema `"hooks"`-wrapper Claude סטנדרטי (כתיבות הן merge-preserving כך שמפתחות אחרים של קובץ ההגדרות — `org_id`, `theme_mode`, … — שרדות), שמות אירוע PascalCase כבר (ללא event map, ללא ענף הנדלר), וחיבור stdin snake_case Claude (ללא נורמליזציה). הענף `devin` של ה-evaluator דוחה עם `{"decision":"block","reason"}` JSON ב-stdout ב-exit 0 עבור **כל** אירוע (מאומת — הבלוק עקף `--permission-mode dangerous`); באירוע turn-end `Stop` הסיבה נושאת את הניסוח force-retry חובה כך שbuiltins `require-*-before-stop` אוכפים. רק שמות כלים מנורמל דרך `DEVIN_TOOL_MAP` (`exec→Bash`; `tool_input.command` כבר קנוני). Devin הוא **גם** מקור **audit** offline — לוח המחוונים קורא sessions SQLite שלה ב-`~/.local/share/devin/cli/sessions.db` (כל שורה `sessions` נושאת `working_directory` אמיתי, כך sessions מקובצות לפי project cwd כמו Claude).
  - **Antigravity CLI (`agy`)**: `~/.gemini/config/hooks.json` (משתמש), `<cwd>/.agents/hooks.json` (פרויקט) — Antigravity אין לו היקף `local`. בשונה מFactory/Devin, Antigravity יש שלה **חוזה משלה** (לא Claude-clone), מאומת חיות כנגד agy v1.1.2. `hooks.json` משתמש בschema **named-hook**: המפתח ברמה עליונה הוא hook *name* (`"failproofai"`) שערכו הוא מפה אירוע→handlers — אירועי כלים (`PreToolUse`/`PostToolUse`) עוטפים handlers ב-`{matcher:"*", hooks:[…]}`, בעוד `PreInvocation`/`Stop` הם **flat** handler arrays (named hooks אחרות שמרות). החיבור stdin הוא **camelCase protojson** (`toolCall:{name,args}`, `conversationId`, `workspacePaths`, `transcriptPath`) — failproofai מנרמל אותו ל-snake_case לפני פעולה של מדיניות, וממפה args PascalCase של `run_command` (`CommandLine`/`Cwd`) דרך `ANTIGRAVITY_TOOL_INPUT_MAP`. הענף `antigravity` של ה-evaluator משתמש בצורות התגובה **שלה** של Antigravity: `{decision:"deny", reason}` חוסם כלי/prompt (exit 0), `{decision:"continue", reason}` באירוע turn-end `Stop` מחודש לולאה (כך שbuiltins `require-*-before-stop` אוכפים), ו-`{injectSteps:[{ephemeralMessage}]}` משדר הנחיה ב-`PreInvocation` (→ `UserPromptSubmit`). שמות כלים מנורמל דרך `ANTIGRAVITY_TOOL_MAP` (`run_command→Bash`, `view_file→Read`, …). Antigravity הוא **גם** מקור **audit** offline — לוח המחוונים קורא transcripts plain-JSONL שלה ב-`~/.gemini/antigravity-cli/brain/<conversationId>/.system_generated/logs/transcript_full.jsonl` (conversation index ב-`conversation_summaries.db`).
  - **Goose (codename goose, Block)**: `~/.agents/plugins/failproofai/hooks/hooks.json` (משתמש), `<cwd>/.agents/plugins/failproofai/hooks/hooks.json` (פרויקט) — Goose אין לו היקף `local`. Enforcement משתמש בsystem **hooks** של Goose, spec **Open Plugins** ביצירה: ה-installer פשוט שוקל את ספרייה `failproofai` plugin ו-Goose auto-גוגל אותה בעת startup (self-registering אותה לתוך `~/.config/goose/config.yaml`). ה-`hooks.json` משתמש בschema Open Plugins **עם** top-level wrapper `"hooks"`, והמatcher הוא **שמיט** בכל אירוע — ערך `"*"` בודד הוא regex בלתי תקף שאינו תואם כלום (מאומת חיות כנגד goose v1.43.0). שמות אירוע כבר PascalCase (ללא event map); החיבור stdin משתמש ב-`event`/`working_dir`, שה-handler מנרמל ל-`hook_event_name`/`cwd`. הענף `goose` של ה-evaluator דוחה עם `{"decision":"block","reason"}` JSON ב-stdout ב-exit 0, מוקבל באירוע **`PreToolUse`** בלבד (משלח ב-goose ≥ v1.37.0) — שממלא על כלי shell **וגם בתוך subagents משולחים**, כך שהוא נקודת דין היחידה המספיקה; שגיאת hook אחרת נכשלת **פתוח**. Goose אין **אירוע `Stop`**, כך שbuiltins `require-*-before-stop` לא חלים (כמו Hermes). שמות כלים מנורמל דרך `GOOSE_TOOL_MAP` (`shell→Bash`, `write→Write`, `todo__todo_write→TodoWrite`, …) ומפתחות נתיב דרך `GOOSE_TOOL_INPUT_MAP` (`path`/`source` → `file_path`). Goose הוא **גם** מקור **audit** offline — לוח המחוונים קורא sessions SQLite שלה ב-`~/.local/share/goose/sessions/sessions.db` (כל שורה `sessions` נושאת `working_dir` אמיתי, כך sessions מקובצות לפי project cwd כמו Devin; `--no-session` scratch runs מסוננים).
- **`policies-config.json`** — אומרת ל-failproofai איזו מדיניות להעריך ובאילו params (משותפת בכל CLIs agent)

Pass `--cli claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose` לכיוון agent ספציפי (מופרדים במרחק או חוזרים עבור כל תת-קבוצה):

```bash
failproofai policies --install --cli codex --scope project
failproofai policies --install --cli copilot --scope project
failproofai policies --install --cli cursor --scope project
failproofai policies --install --cli opencode --scope project
failproofai policies --install --cli pi --scope project
failproofai policies --install --cli hermes --scope user
failproofai policies --install --cli openclaw --scope user
failproofai policies --install --cli factory --scope project
failproofai policies --install --cli devin --scope project
failproofai policies --install --cli antigravity --scope project
failproofai policies --install --cli goose --scope project
failproofai policies --install --cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose
```

כאשר `--cli` משוקלל, `failproofai` מגלה אילו CLIs agent מותקנים (`which claude` / `which codex` / `which copilot` / `which cursor-agent` / `which opencode` / `which pi` / `which hermes` / `which openclaw` / `which droid` / `which devin` / `which agy` / `which goose`):

- **CLI אחת מגולה** — auto-בוחרת את ה-CLI ללא הנחיה.
- **CLIs מרובות מגוללות** בטרמינל אינטראקטיבי — מציגה prompt single-select מניפולציה화살-key מקובצת לסעיף `Detected (N)` (עם שורת aggregate `Install for all N detected` + כל CLI מזוהה בנפרד) וסעיף `Not installed (M) · install hooks ahead of time` המפרט כל CLI שאינו תומך כאפשרות forward-install (↑↓ לעברים, Enter להוד, ^C ליציאה). זרימת הביטול מציגה רק את סעיף Detected.
- **CLIs מרובות מגוללות** בריצה לא-אינטראקטיבית (CI, no TTY) — מתקנות עבור כל CLIs מגוללות ללא הנחיה.
- **אף אחד לא מגולה** — פולט חזרה ל-`claude`, עם אזהרה שלא מצאנו binary agent ב-PATH; פקודת hook כתובה עדיין כך היא מופעלת ברגע שתתקין אחד.

תוכל לערוך `policies-config.json` ישירות בכל עת; שינויים נכנסים לתוקף מיד באירוע hook הבא ללא צורך בהפעלה מחדש.

## דוגמה: תצורה ברמת פרויקט עם ברירות ברירת צוות

Commit `.failproofai/policies-config.json` לריפו שלך:

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-push-master",
    "sanitize-api-keys",
    "block-env-files"
  ],
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "release", "hotfix"]
    }
  }
}
```

כל מפתח יכול אז ליצור `.failproofai/policies-config.local.json` (gitignored) עבור עקיפות אישיות ללא השפעה על חברי צוות.
