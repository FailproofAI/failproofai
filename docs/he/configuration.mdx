failproofai משתמש בקובצי הגדרות JSON כדי לשלוט על אילו מדיניות פעילה, כיצד הן מתנהגות, ומהיכן מדיניות מותאמת נטענת. ההגדרה מעוצבת להיות קלה לשיתוף עם הצוות שלך - התחייב אותה למאגר שלך וכל מפתח יקבל את אותו רשת הבטיחות של הסוכן.

---

## טחונים הגדרה

ישנם שלוש טחונים הגדרה, המוערכים בסדר עדיפויות:

| טחון | נתיב קובץ | מטרה |
|-------|-----------|---------|
| **project** | `.failproofai/policies-config.json` | הגדרות לכל ריפו, מחויבות לבקרת גרסאות |
| **local** | `.failproofai/policies-config.local.json` | עקיפות אישיות לכל ריפו, מדוממו לעיתים |
| **global** | `~/.failproofai/policies-config.json` | ברירות מחדל ברמת משתמש בכל הפרויקטים |

כאשר failproofai קיבל אירוע hook, הוא טוען ומיזג את כל שלוש הקבצים שקיימים בתיקיית העבודה הנוכחית.

### כללי מיזוג

**`enabledPolicies`** - האיחוד של כל שלוש הטחונים. מדיניות שהופעלה בכל רמה היא פעילה.

```text
project:  ["block-sudo"]
local:    ["block-rm-rf"]
global:   ["block-sudo", "sanitize-api-keys"]

resolved: ["block-sudo", "block-rm-rf", "sanitize-api-keys"]  ← איחוד כפול-מנוקה
```

**`policyParams`** - הטחון הראשון שמגדיר פרמטרים עבור מדיניות נתונה זוכה לחלוטין. אין מיזוג עמוק של ערכים בתוך פרמטרי המדיניות.

```text
project:  block-sudo → { allowPatterns: ["sudo apt-get update"] }
global:   block-sudo → { allowPatterns: ["sudo systemctl status"] }

resolved: { allowPatterns: ["sudo apt-get update"] }   ← project מנצח, global מתעלם
```

```text
project:  (no block-sudo entry)
local:    (no block-sudo entry)
global:   block-sudo → { allowPatterns: ["sudo systemctl status"] }

resolved: { allowPatterns: ["sudo systemctl status"] }  ← נופל דרך ל-global
```

**`customPoliciesPaths` / `customPoliciesPath`** - הטחון הראשון שמגדיר כל צורה מנצח.

**`disabledCustomPolicies`** - איחוד בכל הטחונים. לוח המחוונים כותב מזהה כשם מקורי כאן כאשר אתה מכבה מדיניות בודדת מקובץ מדיניות מפורש או קונבנציה. מדיניות שלא רשומה נשארת מופעלת כברירת מחדל; מזהים כוללים את קובץ המקור כך שמדיניות בעלות שם זהה בקבצים מרובים יכולות להיות מבוקרות בנפרד.

**`llm`** - הטחון הראשון שמגדיר אותו מנצח.

## פורמט קובץ הגדרות

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-push-master",
    "sanitize-api-keys",
    "sanitize-jwt",
    "block-env-files",
    "block-read-outside-cwd"
  ],
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    },
    "block-push-master": {
      "protectedBranches": ["main", "release", "prod"]
    },
    "block-rm-rf": {
      "allowPaths": ["/tmp"]
    },
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company"]
    },
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo API key" }
      ]
    },
    "warn-large-file-write": {
      "thresholdKb": 512
    }
  },
  "customPoliciesPath": "/home/alice/myproject/my-policies.js"
}
```

## התייחסות לשדה

### `enabledPolicies`

Type: `string[]`

רשימת שמות מדיניות להפעלה. שמות חייבים להתאים בדיוק למזהי המדיניות המוצגים על ידי `failproofai policies`. ראה [מדיניות מובנה](/he/built-in-policies) לרשימה המלאה.

מדיניות שלא ב-`enabledPolicies` אינן פעילות, גם אם יש להם ערכים ב-`policyParams`.

### `policyParams`

Type: `Record<string, Record<string, unknown>>`

עקיפות פרמטרים לכל מדיניות. המפתח החיצוני הוא שם המדיניות; המפתחות הפנימיים הם ספציפיים למדיניות. כל מדיניות מתועדת בפרמטרים הזמינים שלה ב-[מדיניות מובנה](/he/built-in-policies).

אם למדיניות יש פרמטרים אך אתה לא מציין אותם, ברירות המחדל המובנות של המדיניות משמשות. משתמשים שאינם מגדירים `policyParams` בכלל מקבלים התנהגות זהה לגרסאות קודמות.

מפתחות לא ידועים בתוך בלוק הפרמטרים של מדיניות מתעלמים בשקט בעת הפעלת hook אך מסומנים כאזהרות כאשר אתה מריץ `failproofai policies`.

#### `hint` (חוצה-חיתוך)

Type: `string` (optional)

הודעה מצורפת לסיבה כאשר מדיניות מחזירה `deny` או `instruct`. השתמש בה כדי לתת Claude הדרכה פעולה ללא שינוי המדיניות עצמה.

עובד עם כל סוג מדיניות — מובנה, מותאם (`custom/`), קונבנציה פרויקט (`.failproofai-project/`), או קונבנציה משתמש (`.failproofai-user/`).

```json
{
  "policyParams": {
    "block-force-push": {
      "hint": "נסה ליצור ענף טרי במקום זאת."
    },
    "block-sudo": {
      "allowPatterns": ["sudo apt-get"],
      "hint": "השתמש ב-apt-get ישירות ללא sudo."
    },
    "custom/my-policy": {
      "hint": "בקש אישור מהמשתמש תחילה."
    }
  }
}
```

כאשר `block-force-push` דוחה, Claude רואה: *"Push בכוח חסום. נסה ליצור ענף טרי במקום זאת."*

ערכים שאינם string ומחרוזות ריקות מתעלמים בשקט. אם `hint` לא מוגדר, ההתנהגות אינה משתנה (תואם לאחור).

### `customPoliciesPath`

Type: `string` (absolute path)

נתיב לקובץ JavaScript המכיל מדיניות hook מותאמות. זה מוגדר באופן אוטומטי על ידי `failproofai policies --install --custom <path>` (הנתיב מוגדר לחלוט לפני שהוא מאוחסן).

הקובץ נטען בעדכניות על כל אירוע hook - אין שימור בזיכרון מטמון. ראה [מדיניות מותאמות](/he/custom-policies) לפרטי יצירה.

### מדיניות מבוססות קונבנציה

בנוסף ל-`customPoliciesPath` המפורש, failproofai גילה וטוען באופן אוטומטי קובצי מדיניות מתיקיות `.failproofai/policies/`:

| רמה | תיקיה | טחון |
|-------|-----------|-------|
| Project | `.failproofai/policies/` | משותף לצוות דרך בקרת גרסאות |
| User | `~/.failproofai/policies/` | אישי, חל על כל הפרויקטים |

<Note>
  הנח את המדיניות שלך ישירות ל-`~/.failproofai/policies/`. תיקיית ה-`cloud-policies/` לצדם מחזיקה מדיניות שהם ייצגו של הארגון שלך למכונה זו - גילוי אינו יורד לתתי-תיקיות, כך שזה לעולם לא סרוק, ולא דבר שאתה שם ב-`policies/` יכול להתנגש איתו.

  אם אתה משדרג מגרסה שהשתמשה ב-`~/.failproofai/policies/custom-policies/`, הכל בתיקיה זו — קובצי המדיניות שלך, כל `lib/` של עוזרים שהם מייבאים, וכל קובצי נתונים שהם קוראים — מועברים חזרה באופן אוטומטי בפעם הראשונה שאתה מריץ פקודת `failproofai`, והפקודה אומרת לך מה היא העבירה.
</Note>

**התאמת קובץ:** רק קובצים התואמים `*policies.{js,mjs,ts}` נטענים (למשל `security-policies.mjs`, `workflow-policies.js`). קובצים אחרים בתיקיה מתעלמים.

**אין הגדרה נדרשת:** מדיניות קונבנציה אינן דורשות ערכים ב-`policies-config.json`. פשוט הנח קבצים בתיקיה והם יוצאלקוט באירוע hook הבא.

**טעינת איחוד:** גם תיקיות קונבנציה פרויקט וגם משתמש סרוקות. כל קובצים תואמים משתי הרמות נטענים (בניגוד ל-`customPoliciesPath` שמשתמש בזכיית טחון ראשון).

ראה [מדיניות מותאמות](/he/custom-policies) לפרטים נוספים ודוגמאות.

### `llm`

Type: `object` (optional)

תצורת לקוח LLM עבור מדיניות שמבצעות קריאות AI. לא נדרש עבור רוב ההתקנות.

```json
{
  "llm": {
    "model": "claude-sonnet-4-6",
    "apiKey": "sk-ant-..."
  }
}
```

## ניהול תצורה מ-CLI

הפקודות `policies --install` ו-`policies --uninstall` כותבות לקובץ הגדרות hook של ה-CLI של הסוכן שלך (נקודות כניסה hook), בעוד `policies-config.json` הוא הקובץ שאתה מנהל ישירות. השניים נפרדים:

- **הגדרות Agent CLI** — אומר לסוכן להקרא ל-`failproofai --hook <event>` בכל שימוש בכלי:
  - **Claude Code**: `~/.claude/settings.json` (user), `<cwd>/.claude/settings.json` (project), `<cwd>/.claude/settings.local.json` (local)
  - **OpenAI Codex**: `~/.codex/hooks.json` (user), `<cwd>/.codex/hooks.json` (project) — Codex אינו בעל טחון `local`
  - **GitHub Copilot CLI _(beta)_**: `~/.copilot/hooks/failproofai.json` (user), `<cwd>/.github/hooks/failproofai.json` (project) — Copilot אינו בעל טחון `local`. ערכי Hook משתמשים בשדות הפקודה המקודדים בהתאם ל-OS של Copilot `bash`/`powershell` עם `timeoutSec`; הקובץ נושא סימן `version: 1` ברמה עליונה. תמיכת Copilot CLI היא **beta** בזמן שאנחנו מאשרים את סכימת רשומת `events.jsonl` (שהתיעוד הציבורי לא מציין) מול יותר הפעלות בעולם האמיתי. **VS Code Copilot Chat agent mode (Preview)** קורא תצורות hook מ-`.github/hooks/*.json`, `~/.copilot/hooks/*.json`, ו-`~/.claude/settings.json` (משולט על ידי הגדרת `chat.hookFilesLocations`) באמצעות אותו חוזה בצורת Claude `{hookSpecificOutput:{permissionDecision:"deny",…}}` — הנתיבים המדויקים שהשילוב `copilot` וההשילוב `claude` (`~/.claude/settings.json`) כבר כותבים, כך `failproofai policies --install --cli copilot` (או `--cli claude`) **כבר אוכף ב-VS Code agent mode** ללא שילוב `vscode` נפרד נדרש (מאומת לחי מתוך יומני גילוי של VS Code).
  - **Cursor Agent _(beta)_**: `~/.cursor/hooks.json` (user), `<cwd>/.cursor/hooks.json` (project) — Cursor אינו בעל טחון `local`. ערכי Hook משתמשים בצורה בצורת Claude `{type, command, timeout}` (אין חלוקת `bash`/`powershell`), אך מאוחסנים תחת מפתחות אירוע camelCase (`preToolUse`, `beforeSubmitPrompt`, …) במערך שטוח לפי סכימת [hooks](https://cursor.com/docs/hooks) של Cursor; הקובץ נושא סימן `version: 1` ברמה עליונה. המטפל מקנן camelCase → PascalCase דרך `CURSOR_EVENT_MAP` כך שמדיניות מובנות קיימות ללא שינוי. תמיכת Cursor Agent היא **beta** בזמן שאנחנו מאשרים את תמלול של Cursor על-דיסק (לא מוגדר בתיעוד הציבורי) מול יותר התקנות בעולם האמיתי.
  - **OpenCode _(beta)_**: `~/.config/opencode/opencode.json` + `~/.config/opencode/plugins/failproofai.mjs` (user), `<cwd>/.opencode/opencode.json` + `<cwd>/.opencode/plugins/failproofai.mjs` (project) — OpenCode אינו בעל טחון `local`. בניגוד לחמשת ה-CLIs האחרים, OpenCode אינו בעל מערכת hook פקודה חיצונית: הוא טוען תוך-תהליך JS/TS plugins המובהרים באופן מפורש דרך מערך ה-`plugin: []` ב-`opencode.json` (auto-discovery מ-`.opencode/plugins/` אינו איך plugins טוענים ב-opencode v1.14.33). Install משמיט plugin shim קטן שלפי subprocess-call את הבינארי failproofai ותרגם את התגובה JSON בצורת Claude של הבינארי בחזרה לסמנטיקה של plugin: `throw new Error()` לכלי-event deny (מבטל את קריאת הכלי), `client.session.prompt(...)` עבור instruct AND עבור `Stop` / `SubagentStop` deny (מגיש את סיבת ה-deny כהודעת המשתמש הבאה — הערוץ המיזיון-כוח היחיד מאז `session.idle` הוא התראה בלבד והטלה מה זה היא no-op), ו-no-op עבור allow. ה-shim מקנן שמות כלי (lowercase → PascalCase דרך `OPENCODE_TOOL_MAP`) וכלי-input arg מפתחות (camelCase → snake_case דרך `OPENCODE_TOOL_INPUT_MAP` עבור `Read` / `Write` / `Edit`, למשל `filePath` → `file_path`, `oldString` → `old_string`) לפני העברה לבינארי, כך בדיקת-נתיב builtins כמו `block-read-outside-cwd`, `block-env-files`, ו-`block-secrets-write` אש ללא שינוי בקריאות כלי OpenCode. סשנים חיים בבסיס נתונים SQLite של opencode ב-`~/.local/share/opencode/opencode.db`; צפה הסשן של לוח המחוונים קורא אותם דרך `opencode db --format json` ו-`opencode export <id>`. תמיכת OpenCode היא **beta** בזמן שאנחנו מאשרים התנהגות בחצי-גרסות ומול יותר סשנים בעולם האמיתי. ראה את [OpenCode plugins docs](https://opencode.ai/docs/plugins/).
  - **Pi _(beta)_**: `~/.pi/agent/settings.json` (user), `<cwd>/.pi/settings.json` (project) — Pi אינו בעל טחון `local`. Pi טוען חבילות הרחבה TypeScript בעת ההתחלה; קובץ ההגדרות היא מערך מחרוזת שטוח `{"packages": ["./relative/path", …]}`. failproofai כותב ערך packages-array יחיד המצביע על תיקייתו `pi-extension/` של Bundle. הרחבה בעצמה מנויה ל-`tool_call` של Pi / `user_bash` / `input` / `session_start` אירועים ו-shells out ל-`failproofai --hook <Event> --cli pi`; המטפל מקנן underscore_lower_snake_case → PascalCase דרך `PI_EVENT_MAP` כך שמדיניות מובנות קיימות ללא שינוי. כלי input args מקנן גם דרך `PI_TOOL_INPUT_MAP` (Pi של Read / Write / Edit מסר `path` במקום `file_path`; מיפוי המפתח ברמה עליונה תן ל-`block-env-files` ו-`block-secrets-write` אש — `block-read-outside-cwd` כבר היה `path` fallback). תמיכת Pi היא **beta** בזמן שממשק Extension של Pi וסכימת session-log מתייצבות.
  - **Hermes (hermes-agent)**: `~/.hermes/config.yaml` (**user scope only** — Hermes אינו בעל תצורת project/local). Hermes היא **gateway** של Slack/Telegram, כך ההתקנה אחת מיירט קריאות כלי מכל פלטפורמה (Slack/Telegram/cli/cron) **וגם** תת-סוכנים פנימיים. ערכי Hook הם `{command, timeout}` pair (timeout ב-**secondi**) תחת מפה `hooks:` מקודדת לפי אירועי snake_case של Hermes (`pre_tool_call` / `post_tool_call` / `on_session_start` / `on_session_end` / `subagent_stop`); המטפל מקנן אירועים דרך `HERMES_EVENT_MAP` ושמות כלי דרך `HERMES_TOOL_MAP` כך מדיניות מובנות אש ללא שינוי. התצורה נערכת דרך `Document` YAML משמר-הערה round-trip כך ההגדרות האחרות של המפעיל שורדות, וה-install קובע `hooks_auto_accept: true` כך ה-gateway headless (no TTY) מריץ את ה-hooks ללא בקשת הסכמה. המעריך פולט חוזה stdout של Hermes `{"decision":"block","reason"}` (Hermes מתעלם מ-exit codes). **Limitations:** Hermes אינו בעל אירוע `Stop` של turn-end, כך ה-`require-*-before-stop` builtins לעולם לא אש עבור זה (יישומי, לא שבור); `instruct` הירוד ל-allow-with-logged-note (אין ערוץ הקשר נוסף); וביצוע-secret redaction (`sanitize-*`) לא יכול לשכתב כלי output על חוזה shell-hook. Hermes היא **גם** מקור ביקורת **offline** — לוח המחוונים קורא סשני gateway שלו ישירות מ-`~/.hermes/state.db`.
  - **OpenClaw (openclaw gateway)**: `~/.openclaw/openclaw.json` (**user scope only** — OpenClaw אינו בעל תצורת project/local). כמו Hermes, OpenClaw היא **gateway** מהפעלה עצמית multi-channel, כך ההתקנה אחת מיירטת קריאות כלי מכל ערוץ ותת-סוכניה פנימיים. אכיפה פועלת דרך **in-process plugin hooks** של OpenClaw (hook file-based שלו הם observation-only ולא יכולים לחסום), כך — כמו OpenCode/Pi — failproofai משודר plugin סטטי `openclaw-plugin/` תוך-חבילה שasync-spawns את הבינארי failproofai ותרגם את הפסק. Install רושם את ספריית plugin shipped ב-`openclaw.json` של `plugins.load.paths[]` ומאפשר אותו תחת `plugins.entries.failproofai` (עם `hooks.allowConversationAccess: true`, חובה עבור raw-conversation hooks). המעריך פולט `{permission, reason}` פסק שטוח והשימור מיפה אותו לצורת חזרה ילידה של כל hook: `before_tool_call → {block:true, blockReason}` (**PreToolUse**), `before_agent_run → {outcome:"block", reason}` (**UserPromptSubmit**), ו-`before_agent_finalize → {action:"revise", reason}` (**Stop** — שער turn-end אמיתי, כך ה-`require-*-before-stop` builtins **אכוף** ב-OpenClaw, בניגוד ל-Hermes). אירועים ושמות כלי מקנן בצד בינארי דרך `OPENCLAW_EVENT_MAP` / `OPENCLAW_TOOL_MAP` (`exec→Bash`, `read→Read`, …) כך מדיניות מובנות אש ללא שינוי; ה-shim נכשל open כל spawn/parse/timeout שגיאה. OpenClaw היא **גם** מקור ביקורת **offline** — לוח המחוונים קורא את סשני JSONL שלו ב-`~/.openclaw/agents/<agentId>/sessions/<uuid>.jsonl`.
  - **Factory Droid (`droid`)**: `~/.factory/hooks.json` (user), `<cwd>/.factory/hooks.json` (project) — Factory אינו בעל טחון `local`. droid משודר מערכת hook פקודה חיצונית בצורת Claude, אך עם שתי קיצים מאומתים לחי מול droid v0.171.0: (1) שמות אירוע חיים ב-**top level** של `hooks.json` — אין **אין `"hooks"` wrapper** (droid דוחה אחד); כלי אירועים (`PreToolUse`/`PostToolUse`) נושאים `"matcher": "*"`, אירועים שאינם כלי משמיטים אותו. (2) Deny הוא מונע על ידי hook **exit code 2 + stderr**, לא החלטה JSON — ענף `factory` של המעריך מחזיר exit 2 עבור כלי/prompt אירועים ו-`{decision:"block", reason}` רק על האירוע turn-end `Stop` (ערוץ retry-כוח יחיד של droid). אירועים כבר PascalCase (אין event map) וה-payload הוא Claude snake_case; רק שמות כלי מקנן דרך `FACTORY_TOOL_MAP` (`Execute→Bash`, `Create→Write`, `FetchUrl→WebFetch`, …). Factory היא **גם** מקור ביקורת **offline** — לוח המחוונים קורא את סשני JSONL שלו על-דיסק ב-`~/.factory/sessions/<encoded-cwd>/<sessionId>.jsonl`.
  - **Devin CLI (`devin`, Cognition)**: `~/.config/devin/config.json` (user), `<cwd>/.devin/config.json` (project) — Devin אינו בעל טחון `local`. Devin היא **pure Claude-clone** מאומתת לחי מול devin v3000.1.27: היא משתמשת בסכימת Claude `"hooks"`-wrapper סטנדרטית (כתיבות הן merge-preserving כך המפתחות האחרים של קובץ ההגדרות — `org_id`, `theme_mode`, … — שורדות), שמות אירוע כבר-PascalCase (אין event map, אין ענף handler), ו-Claude snake_case stdin payload (אין נורמליזציה). ענף `devin` של המעריך דוחה עם JSON `{"decision":"block","reason"}` על stdout ב-exit 0 עבור **כל** אירוע (מאומת — החסום עקף `--permission-mode dangerous`); על אירוע turn-end `Stop` הסיבה נושאת MANDATORY-ACTION force-retry ניסוח כך ה-`require-*-before-stop` builtins אכוף. רק שמות כלי מקנן דרך `DEVIN_TOOL_MAP` (`exec→Bash`; `tool_input.command` כבר קנוני). Devin היא **גם** מקור ביקורת **offline** — לוח המחוונים קורא את סשני SQLite שלו ב-`~/.local/share/devin/cli/sessions.db` (כל `sessions` שורה נושאת `working_directory` אמיתי, כך סשנים קבוצה לפי פרויקט cwd כמו Claude).
  - **Antigravity CLI (`agy`)**: `~/.gemini/config/hooks.json` (user), `<cwd>/.agents/hooks.json` (project) — Antigravity אינו בעל טחון `local`. בניגוד ל-Factory/Devin, Antigravity בעלת שלה **חוזה משלה** (לא Claude-clone), מאומתת לחי מול agy v1.1.2. `hooks.json` משתמש בסכימת **named-hook**: המפתח ברמה עליונה הוא שם hook *name* (`"failproofai"`) שערכו הוא event→handlers map — כלי אירועים (`PreToolUse`/`PostToolUse`) עוטפים handlers ב-`{matcher:"*", hooks:[…]}`, בעוד `PreInvocation`/`Stop` הם **flat** handler arrays (named hooks אחרים משומרים). ה-stdin payload הוא **camelCase protojson** (`toolCall:{name,args}`, `conversationId`, `workspacePaths`, `transcriptPath`) — failproofai מנרמל אותו ל-snake_case לפני מדיניות רצות, ומיפוי `run_command` של PascalCase args (`CommandLine`/`Cwd`) דרך `ANTIGRAVITY_TOOL_INPUT_MAP`. ענף `antigravity` של המעריך משתמש בצורות תגובה **משלו** של Antigravity: `{decision:"deny", reason}` חוסם כלי/prompt (exit 0), `{decision:"continue", reason}` על turn-end `Stop` re-enters הלולאה (כך ה-`require-*-before-stop` builtins אכוף), ו-`{injectSteps:[{ephemeralMessage}]}` injects הוראה על `PreInvocation` (→ `UserPromptSubmit`). שמות כלי מקנן דרך `ANTIGRAVITY_TOOL_MAP` (`run_command→Bash`, `view_file→Read`, …). Antigravity היא **גם** מקור ביקורת **offline** — לוח המחוונים קורא את טרנסקריפטים JSONL-רגיל שלו ב-`~/.gemini/antigravity-cli/brain/<conversationId>/.system_generated/logs/transcript_full.jsonl` (אינדקס שיחה ב-`conversation_summaries.db`).
  - **Goose (codename goose, Block)**: `~/.agents/plugins/failproofai/hooks/hooks.json` (user), `<cwd>/.agents/plugins/failproofai/hooks/hooks.json` (project) — Goose אינו בעל טחון `local`. אכיפה משתמשת **hooks** של Goose מערכת, סכימת Open Plugins **cross-agent**: ה-installer פשוט משמיט את תיקיית הpluggin `failproofai` וה-Goose auto-discovers אותו בעת ההתחלה (self-registering זה ל-`~/.config/goose/config.yaml`). ה-`hooks.json` משתמש בסכימת Open Plugins **עם** `"hooks"` wrapper ברמה עליונה, והמתאם הוא **omitted** בכל אירוע — `"*"` ערום הוא regex לא חוקי שמתאים כלום (מאומת לחי מול goose v1.43.0). שמות אירוע כבר PascalCase (אין event map); ה-stdin payload משתמש `event`/`working_dir`, שהמטפל מנרמל ל-`hook_event_name`/`cwd`. ענף `goose` של המעריך דוחה עם JSON `{"decision":"block","reason"}` על stdout ב-exit 0, מכובד על ה-**`PreToolUse`** אירוע בלבד (משודר ב-goose ≥ v1.37.0) — שאש עבור כלי shell **וגם בתוך delegated subagents**, כך זה הנקודת deny יחידה מספיקה; כל hook error אחר נכשל **open**. Goose אינו בעל **אירוע `Stop`**, כך ה-`require-*-before-stop` builtins לא חל (כמו עם Hermes). שמות כלי מקנן דרך `GOOSE_TOOL_MAP` (`shell→Bash`, `write→Write`, `todo__todo_write→TodoWrite`, …) ומפתחות נתיב דרך `GOOSE_TOOL_INPUT_MAP` (`path`/`source` → `file_path`). Goose היא **גם** מקור ביקורת **offline** — לוח המחוונים קורא את סשני SQLite שלו ב-`~/.local/share/goose/sessions/sessions.db` (כל `sessions` שורה נושאת `working_dir` אמיתי, כך סשנים קבוצה לפי פרויקט cwd כמו Devin; `--no-session` scratch רצות מסוננות).
- **`policies-config.json`** — אומר ל-failproofai אילו מדיניות להעריך ועם אילו params (משותף בכל agent CLIs)

Pass `--cli claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose` כדי לכוון סוכן ספציפי (space-separated או חוזר עבור כל תת-קבוצה):

```bash
failproofai policies --install --cli codex --scope project
failproofai policies --install --cli copilot --scope project
failproofai policies --install --cli cursor --scope project
failproofai policies --install --cli opencode --scope project
failproofai policies --install --cli pi --scope project
failproofai policies --install --cli hermes --scope user
failproofai policies --install --cli openclaw --scope user
failproofai policies --install --cli factory --scope project
failproofai policies --install --cli devin --scope project
failproofai policies --install --cli antigravity --scope project
failproofai policies --install --cli goose --scope project
failproofai policies --install --cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose
```

כאשר `--cli` משמיט, failproofai מגלה אילו agent CLIs מותקנים (`which claude` / `which codex` / `which copilot` / `which cursor-agent` / `which opencode` / `which pi` / `which hermes` / `which openclaw` / `which droid` / `which devin` / `which agy` / `which goose`):

- **CLI אחד זוהה** — auto-selects CLI זה ללא בקשת הנושא.
- **Multiple CLIs זוהה** במסוף אינטראקטיבי — מציג בחירה יחידה בעזרת חץ-מפתח הנתמכת קבוצה לתוך סעיף `Detected (N)` (עם שורה `Install for all N detected` aggregate + כל CLI זוהה בנפרד) וסעיף `Not installed (M) · install hooks ahead of time` רישום כל CLI שלא זוהה שנתמך כאפשרות forward-install (↑↓ לנוע, Enter לבחור, ^C לצאת). זרימת uninstall מציגה רק את סעיף Detected.
- **Multiple CLIs זוהה** בריצה לא-אינטראקטיבית (CI, no TTY) — מתקן עבור כל CLIs זוהה ללא בקשת הנושא.
- **None זוהה** — falls back ל-`claude`, עם אזהרה שלא בינארי סוכן נמצא ב-PATH; פקודת ה-hook עדיין כתובה כך הוא מופעל ברגע שאתה מתקן אחד.

אתה יכול לערוך `policies-config.json` ישירות בכל זמן; שינויים נכנסו לתוקף מיד על אירוע hook הבא ללא צורך בהפעלה מחדש.

## שידרוגים שומרים את התצורה שלך

גרסה חדשה של failproofai עשויה לארגן `~/.failproofai/` שונה. כאשר היא כן, הפקודה הראשונה לאחר השדרוג מעביר את התיקיה, ו**התצורה שלך נישאת, לא אפס**:

| שמורה | נבנה מחדש |
|---|---|
| בחירת המדיניות שלך ופרמטרים (`policies-config.json`) | ה-audit cache |
| ההגדרות שלך, כולל `daemon.configured` ונתיבי capture נוספים (`config.json`) | Cloud-managed policy deployments — re-fetched וגם-verified בבדיקה הבאה |
| ההשמה של cloud שלך (`credentials.json`) | Daemon scratch state |
| קבצי המדיניות שלך ב-`policies/`, ו-helpers שהם מייבאים | |
| יומן ההחלטה שלוח המחוונים קורא, ואירועים טרם מסורים | |

מפתחות שנכתבו על ידי failproofai *חדש יותר* משומרים גם כן, במקום להיות מושלך על ידי קורא ישן — כך נעים בין גרסאות אינו שוקל שוקלי הגדרות או הוא כיוון.

אתה **לא** צריך לריצה setup שוב אחר כך: מכונה מהוגרת אוכף בדיוק כפי שהיא עשתה קודם, שהוא מה שהופך שדרוג בטוח על מכונות עם אף אחד לא יושב בהם. כל הגירה מתועדת ב-`~/.failproofai/migrations/applied.json`, וקבצים irreplaceable מועתקים ל-`~/.failproofai/migrations/backup-layout<n>/` לפני כל דבר רץ.

ראה [`failproofai update`](/he/cli/update) עבור upgrade של שורה אחת, ו-[`failproofai migrate`](/he/cli/migrate) — כולל `--dry-run` — לפרטים.

## דוגמה: תצורת פרויקט-רמה עם ברירות מחדל של צוות

Commit `.failproofai/policies-config.json` לריפו שלך:

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-push-master",
    "sanitize-api-keys",
    "block-env-files"
  ],
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "release", "hotfix"]
    }
  }
}
```

כל מפתח יכול אז ליצור `.failproofai/policies-config.local.json` (gitignored) עבור עקיפות אישיות ללא השפעה על teammates.
