מדיניות מותאמת מאפשרת לך לכתוב כללים עבור כל התנהגות של agents: אכוף קונבנציות בפרויקט, מנע סטייה, צור שערים לפעולות הרסניות, זהה agents תקועים, או התחבר ל-Slack, זרימות אישור, ועוד. הם משתמשים באותה מערכת אירועי hook ובהחלטות `allow`, `deny`, `instruct` כמו מדיניות מובנית.

---

## דוגמה מהירה

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

customPolicies.add({
  name: "no-production-writes",
  description: "Block writes to paths containing 'production'",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Write" && ctx.toolName !== "Edit") return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("production")) {
      return deny("Writes to production paths are blocked");
    }
    return allow();
  },
});
```

התקן אותה:

```bash
failproofai policies --install --custom ./my-policies.js
```

## שתי דרכים לטעינת מדיניות מותאמת

### אפשרות 1: מבוססת קונבנציה (מומלצת)

שחרר קבצי `*policies.{js,mjs,ts}` לתוך `.failproofai/policies/` והם יטענו באופן אוטומטי - לא צריך דגלים או שינויי הגדרות. זה עובד כמו git hooks: שחרר קובץ, זה פשוט עובד.

```
# Project level — committed to git, shared with the team
.failproofai/policies/security-policies.mjs
.failproofai/policies/workflow-policies.mjs

# User level — personal, applies to all projects
~/.failproofai/policies/my-policies.mjs
```

**איך זה עובד:**
- שתי ספריות פרויקט ומשתמש סורקות (איחוד — לא first-scope-wins)
- קבצים טוענים בסדר אלפביתי בכל ספרייה. הוסף קידומת עם `01-`, `02-` לשליטה בסדר
- רק קבצים התואמים ל-`*policies.{js,mjs,ts}` טוענים; קבצים אחרים מתעלמים
- כל קובץ טוען באופן עצמאי (fail-open לכל קובץ)
- עובד לצד `--custom` מפורש ומדיניות מובנית

<Tip>
מדיניות קונבנציה היא הדרך הקלה ביותר לבנות תקן איכות עבור הארגון שלך. commit את `.failproofai/policies/` ל-git וכל חברי הצוות מקבלים אותם כללים באופן אוטומטי — לא צריך setup לכל מפתח. כשהצוות שלך מגלה מצבי כשל חדשים, הוסף מדיניות ודחוף. עם הזמן אלה הופכים לתקן איכות חי שמשתפר עם כל תרומה.
</Tip>

### אפשרות 2: נתיב קובץ מפורש

```bash
# Install with a custom policies file
failproofai policies --install --custom ./my-policies.js

# Replace the custom policy paths
failproofai policies --install --custom ./new-policies.js

# Configure multiple explicit files (loaded in flag order)
failproofai policies --install --custom ./security.js --custom ./workflow.js

# Remove all explicit custom policy paths from config
failproofai policies --uninstall --custom
```

נתיבים אבסולוטיים שנפתרו מאוחסנים ב-`policies-config.json` כ-`customPoliciesPaths`. חזור על `--custom` להגדרת קבצים מרובים. קונפיגים קיימים המשתמשים בשדה `customPoliciesPath` המדור הישן ממשיכים לעבוד. קבצים טוענים טרי בכל אירוע hook - אין caching בין אירועים.

כל מדיניות רשומה מופיעה עם toggle משלה בדוח הבקרה. החלפת מדיניות off מתעדת את ה-ID המתוקן בקורא ב-`disabledCustomPolicies`; הקובץ והמדיניות האחרות שלו ממשיכות לטעון, בעוד שהמדיניות המכוהנת מוחרגת לפני התאמת אירוע. שמות מדיניות כפולים בקבצים יש toggles עצמאי.

### שימוש בשניהם ביחד

מדיניות קונבנציה וקבצי `--custom` מפורשים יכולים להתקיים. סדר טעינה:

1. קבצי `customPoliciesPaths` מפורשים (בסדר מוגדר)
2. קבצי קונבנציה פרויקט (`{cwd}/.failproofai/policies/`, אלפביתי)
3. קבצי קונבנציה משתמש (`~/.failproofai/policies/`, אלפביתי)

## API

### ייבוא

```js
import { customPolicies, allow, deny, instruct } from "failproofai";
```

### `customPolicies.add(hook)`

רושם מדיניות. התקשר זה כמה פעמים שצריך עבור מדיניות מרובה באותו קובץ.

```ts
customPolicies.add({
  name: string;                         // required - unique identifier
  description?: string;                 // shown in `failproofai policies` output
  match?: { events?: HookEventType[] }; // filter by event type; omit to match all
  fn: (ctx: PolicyContext) => PolicyResult | Promise<PolicyResult>;
});
```

### עוזרי החלטה

| פונקציה | אפקט | השתמש כאשר |
|----------|--------|----------|
| `allow()` | אפשר את הפעולה בשקט | הפעולה בטוחה, לא צריך הודעה |
| `deny(message)` | חסום את הפעולה | ה-agent לא צריך לבצע פעולה זו |
| `instruct(message)` | הוסף הקשר ללא חסימה | תן ל-agent הקשר נוסף להישאר על המסלול |

`deny(message)` - ההודעה מופיעה ל-Claude עם קידומת `"Blocked by failproofai:"`. ה-deny אחד מקצר את כל ההערכה הנוספת.

`instruct(message)` - ההודעה מצורפת להקשר של Claude לקריאת הכלי הנוכחי. כל הודעות `instruct` מצטברות ומועברות ביחד.

<Tip>
אתה יכול להוסיף הדרכה נוספת לכל `deny` או הודעת `instruct` על ידי הוספת שדה `hint` ב-`policyParams` — לא צריך שינוי קוד. זה עובד עבור מדיניות מותאמת (`custom/`), קונבנציה פרויקט (`.failproofai-project/`), וקונבנציה משתמש (`.failproofai-user/`) גם כן. ראה [Configuration → hint](/he/configuration#hint-cross-cutting) לפרטים.
</Tip>

### הודעות allow מידע

`allow(message)` מאפשר את הפעולה **וגם** שולח הודעת מידע חזרה ל-Claude. ההודעה מועברת כ-`additionalContext` בתגובת stdout של handler hook — אותה מנגנון המשמש `instruct`, אך שונה מבחינה סמנטית: זו עדכון סטטוס, לא אזהרה.

| פונקציה | אפקט | השתמש כאשר |
|----------|--------|----------|
| `allow(message)` | אפשר ושלח הקשר ל-Claude | אשר בדיקה עברה, או הסבר מדוע בדיקה דילגה |

מקרי שימוש:
- **אישורי סטטוס:** `allow("All CI checks passed.")` — אומר ל-Claude שהכל ירוק
- **הסברי fail-open:** `allow("GitHub CLI not installed, skipping CI check.")` — אומר ל-Claude מדוע בדיקה דילגה כדי שיהיה לו הקשר מלא
- **הודעות מרובות מצטברות:** אם מדיניות מרובה כל אחת מחזירה `allow(message)`, כל ההודעות מחוברות עם newlines ומועברות ביחד

```js
customPolicies.add({
  name: "confirm-branch-status",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    const cwd = ctx.session?.cwd;
    if (!cwd) return allow("No working directory, skipping branch check.");

    // ... check branch status ...
    if (allPushed) {
      return allow("Branch is up to date with remote.");
    }
    return deny("Unpushed changes detected.");
  },
});
```

### שדות `PolicyContext`

| שדה | סוג | תיאור |
|-------|------|-------------|
| `eventType` | `string` | `"PreToolUse"`, `"PostToolUse"`, `"Notification"`, `"Stop"` |
| `toolName` | `string \| undefined` | הכלי שנקרא (למשל `"Bash"`, `"Write"`, `"Read"`) |
| `toolInput` | `Record<string, unknown> \| undefined` | פרמטרי הקלט של הכלי |
| `payload` | `Record<string, unknown>` | payload אירוע גולמי מלא מ-Claude Code |
| `session` | `SessionMetadata \| undefined` | הקשר הפעלה (ראה להלן) |

### שדות `SessionMetadata`

| שדה | סוג | תיאור |
|-------|------|-------------|
| `sessionId` | `string` | Claude Code מזהה הפעלה |
| `cwd` | `string` | ספרייה עובדת של הפעלה Claude Code |
| `transcriptPath` | `string` | נתיב לקובץ תמלול JSONL של ההפעלה |

### סוגי אירוע

| אירוע | מתי הוא מופעל | תוכן `toolInput` |
|-------|--------------|----------------------|
| `PreToolUse` | לפני ה-Claude הוא מריץ כלי | קלט הכלי (למשל `{ command: "..." }` עבור Bash) |
| `PostToolUse` | אחרי כלי מסתיים | קלט הכלי + `tool_result` (הפלט) |
| `Notification` | כאשר Claude שולח הודעה | `{ message: "...", notification_type: "idle" \| "permission_prompt" \| ... }` - hooks חייב תמיד להחזיר `allow()`, הם לא יכולים לחסום הודעות |
| `Stop` | כאשר הפעלה Claude מסתיימת | ריק |

## סדר הערכה

מדיניות מוערכת בסדר זה:

1. מדיניות מובנית (בסדר הגדרה)
2. מדיניות מותאמת מפורשת מ-`customPoliciesPath` (בסדר `.add()`)
3. מדיניות קונבנציה מפרויקט `.failproofai/policies/` (קבצים אלפביתי, סדר `.add()` בתוך)
4. מדיניות קונבנציה מ-`~/.failproofai/policies/` משתמש (קבצים אלפביתי, סדר `.add()` בתוך)

<Note>
ה-deny הראשון מקצר את כל המדיניות המעקבות. כל הודעות `instruct` מצטברות ומועברות ביחד.
</Note>

## ייבואים זמניים

קבצי מדיניות מותאמת יכולים לייבא מודולים מקומיים באמצעות נתיבים יחסיים:

```js
// my-policies.js
import { isBlockedPath } from "./utils.js";
import { checkApproval } from "./approval-client.js";

customPolicies.add({
  name: "approval-gate",
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const approved = await checkApproval(ctx.toolInput?.command, ctx.session?.sessionId);
    return approved ? allow() : deny("Approval required for this command");
  },
});
```

כל הייבואים היחסיים הנגישים מקובץ הכניסה מתבררים. זה מיושם על ידי שכתוב `from "failproofai"` ייבואים לנתיב dist בפועל ויצירת קבצי `.mjs` זמניים כדי להבטיח תאימות ESM.

## סינון סוג אירוע

השתמש ב-`match.events` להגבלת מתי מדיניות מופעלת:

```js
customPolicies.add({
  name: "require-summary-on-stop",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    // Only fires when the session ends
    // ctx.session.transcriptPath contains the full session log
    return allow();
  },
});
```

השמט `match` לחלוטין כדי להדליק בכל סוג אירוע.

## טיפול בשגיאות ומצבי כשל

מדיניות מותאמת היא **fail-open**: שגיאות לעולם לא חוסמות מדיניות מובנית או קורסות את handler hook.

| כשל | התנהגות |
|---------|----------|
| `customPoliciesPath` לא קבוע | אין מדיניות מותאמת מפורשת; מדיניות קונבנציה ומובנית ממשיכות בדרך כלל |
| קובץ לא נמצא | אזהרה מתועדת ל-`~/.failproofai/hook.log`; מובנים ממשיכים |
| שגיאת סינטקס/ייבוא (מפורש) | שגיאה מתועדת ל-`~/.failproofai/hook.log`; מדיניות מותאמת מפורשת דלג |
| שגיאת סינטקס/ייבוא (קונבנציה) | שגיאה מתועדת; קובץ זה דלג, קבצי קונבנציה אחרים עדיין טוענים |
| `fn` זורק בזמן ריצה | שגיאה מתועדת; hook זה מטופל כ-`allow`; hook אחרים ממשיכים |
| `fn` לוקח יותר מ-10 שניות | זמן קצוב מתועד; מטופל כ-`allow` |
| ספרייה קונבנציה חסרה | אין מדיניות קונבנציה; אין שגיאה |

<Tip>
לדבאג שגיאות מדיניות מותאמת, צפה בקובץ היומן:

```bash
tail -f ~/.failproofai/hook.log
```
</Tip>

## דוגמה מלאה: מדיניות מרובה

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

// Prevent agent from writing to secrets/ directory
customPolicies.add({
  name: "block-secrets-dir",
  description: "Prevent agent from writing to secrets/ directory",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (!["Write", "Edit"].includes(ctx.toolName ?? "")) return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("secrets/")) return deny("Writing to secrets/ is not permitted");
    return allow();
  },
});

// Keep the agent on track: verify tests before committing
customPolicies.add({
  name: "remind-test-before-commit",
  description: "Keep the agent on track: verify tests pass before committing",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    if (/git\s+commit/.test(cmd)) {
      return instruct("Verify all tests pass before committing. Run `bun test` if you haven't already.");
    }
    return allow();
  },
});

// Prevent unplanned dependency changes during freeze
customPolicies.add({
  name: "dependency-freeze",
  description: "Prevent unplanned dependency changes during freeze period",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    const isInstall = /^(npm install|yarn add|bun add|pnpm add)\s+\S/.test(cmd);
    if (isInstall && process.env.DEPENDENCY_FREEZE === "1") {
      return deny("Package installs are frozen. Unset DEPENDENCY_FREEZE to allow.");
    }
    return allow();
  },
});

export { customPolicies };
```
