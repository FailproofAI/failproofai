מדיניויות מותאמות אישית מאפשרות לך לכתוב כללים לכל התנהגות סוכן: כפוף קונבנציות בפרויקט, מנע סטייה, חסום פעולות הורסות, זהה סוכנים תקועים, או התשלב עם Slack, זרימות אישור ועוד. הם משתמשים באותו מערכת אירועי hook ובהחלטות `allow`, `deny`, `instruct` כמו מדיניויות מובנות.

---

## דוגמה מהירה

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

customPolicies.add({
  name: "no-production-writes",
  description: "Block writes to paths containing 'production'",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Write" && ctx.toolName !== "Edit") return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("production")) {
      return deny("Writes to production paths are blocked");
    }
    return allow();
  },
});
```

התקן אותה:

```bash
failproofai policies --install --custom ./my-policies.js
```

## שתי דרכים לטעון מדיניויות מותאמות אישית

### אפשרות 1: מבוססת קונבנציה (מומלץ)

שים קבצי `*policies.{js,mjs,ts}` בתוך `.failproofai/policies/` והם יטענו אוטומטית — אין צורך בדגלים או שינויי קונפיגורציה. זה עובד כמו git hooks: שים קובץ, זה פשוט עובד.

```
# Project level — committed to git, shared with the team
.failproofai/policies/security-policies.mjs
.failproofai/policies/workflow-policies.mjs

# User level — personal, applies to all projects
~/.failproofai/policies/my-policies.mjs
```

**איך זה עובד:**
- שתי תיקיות — הפרויקט והמשתמש — סרוקות (איחוד — לא first-scope-wins)
- קבצים טוענים בסדר אלפביתי בתוך כל תיקייה. תחילית עם `01-`, `02-` לשליטה בסדר
- רק קבצים התואמים `*policies.{js,mjs,ts}` טוענים; קבצים אחרים מתעלמים
- כל קובץ טוען בנפרד (fail-open לכל קובץ)
- עובד לצד `--custom` מפורש ומדיניויות מובנות

<Tip>
מדיניויות קונבנציה הן הדרך הקלה ביותר לבנות תקן איכות לארגון שלך. קבע `.failproofai/policies/` ב-git וכל חבר בצוות מקבל את אותם כללים אוטומטית — אין צורך בהתקנה לפי מפתח. כאשר הצוות שלך גוכל כשלים חדשים, הוסף מדיניות ודחוף. עם הזמן אלה הופכות לתקן איכות חי שמשתפר עם כל תרומה.
</Tip>

### אפשרות 2: נתיב קובץ מפורש

```bash
# Install with a custom policies file
failproofai policies --install --custom ./my-policies.js

# Replace the custom policy paths
failproofai policies --install --custom ./new-policies.js

# Configure multiple explicit files (loaded in flag order)
failproofai policies --install --custom ./security.js --custom ./workflow.js

# Remove all explicit custom policy paths from config
failproofai policies --uninstall --custom
```

נתיבים מוחלטים מיושרים מאוחסנים ב-`policies-config.json` כ-`customPoliciesPaths`. חזור על `--custom` להגדרת קבצים מרובים. קונפיגורציות קיימות המשתמשות בשדה `customPoliciesPath` של מורשת ממשיכות לעבוד. קבצים טוענים מחדש בכל אירוע hook — אין כנון בין אירועים.

כל מדיניות רשומה מופיעה עם ההחלפה שלה בלוח המחוונים. הדפקת מדיניות כבויה רושמת את ה-ID המוסמך למקור שלה ב-`disabledCustomPolicies`; הקובץ ומדיניויות אחרות שלו ממשיכים להיטען, בזמן שהמדיניות המנוטרלת מודרת לפני התאמת אירועים. שמות מדיניויות שכופלו על פני קבצים יש להם החלפות עצמאיות.

### שימוש בשתיהן ביחד

מדיניויות קונבנציה וקבצי `--custom` מפורשים יכולים להתקיים. סדר טעינה:

1. קבצי `customPoliciesPaths` מפורשים (בסדר מוגדר)
2. קבצי קונבנציה בפרויקט (`{cwd}/.failproofai/policies/`, אלפביתי)
3. קבצי קונבנציה למשתמש (`~/.failproofai/policies/`, אלפביתי)

## API

### ייבוא

```js
import { customPolicies, allow, deny, instruct } from "failproofai";
```

### `customPolicies.add(hook)`

רושם מדיניות. קרא זה כמה פעמים שצריך למדיניויות מרובות באותו קובץ.

```ts
customPolicies.add({
  name: string;                         // required - unique identifier
  description?: string;                 // shown in `failproofai policies` output
  match?: { events?: HookEventType[] }; // filter by event type; omit to match all
  fn: (ctx: PolicyContext) => PolicyResult | Promise<PolicyResult>;
});
```

### עוזרי החלטה

| פונקציה | השפעה | השתמש כאשר |
|----------|--------|----------|
| `allow()` | אפשר את הפעולה בשקט | הפעולה בטוחה, אין צורך בהודעה |
| `deny(message)` | חסום את הפעולה | הסוכן לא צריך לבצע פעולה זו |
| `instruct(message)` | הוסף הקשר ללא חסימה | תן לסוכן הקשר נוסף להישארות בעקבות |

`deny(message)` - ההודעה מופיעה ל-Claude עם קידומת `"Blocked by failproofai:"`. `deny` יחיד מקצר כל הערכה נוספת.

`instruct(message)` - ההודעה מצורפת להקשר של Claude לקריאת הכלי הנוכחית. כל הודעות `instruct` מצטברות ומועברות ביחד.

<Tip>
אתה יכול להוסיף הנחיה נוספת לכל `deny` או `instruct` הודעה על ידי הוספת שדה `hint` ב-`policyParams` — אין צורך בשינוי קוד. זה עובד עבור מדיניויות מותאמות אישית (`custom/`), קונבנציה בפרויקט (`.failproofai-project/`), וקונבנציה למשתמש (`.failproofai-user/`) גם כן. ראה [Configuration → hint](/he/configuration#hint-cross-cutting) לפרטים.
</Tip>

### הודעות allow מידע

`allow(message)` מאפשר את הפעולה **וגם** שולח הודעת מידע חזרה ל-Claude. ההודעה מועברת כ-`additionalContext` בתגובת stdout של מטפל ה-hook — אותו מנגנון המשמש ב-`instruct`, אך שונה מבחינה סמנטית: זו עדכון סטטוס, לא אזהרה.

| פונקציה | השפעה | השתמש כאשר |
|----------|--------|----------|
| `allow(message)` | אפשר ושלח הקשר ל-Claude | אישור בדיקה עברה, או הסברה מדוע בדיקה דולגה |

מקרי שימוש:
- **אישורי סטטוס:** `allow("All CI checks passed.")` — אומר ל-Claude שהכל ירוק
- **הסברות fail-open:** `allow("GitHub CLI not installed, skipping CI check.")` — אומר ל-Claude למה בדיקה דולגה כך שיש לה הקשר מלא
- **הודעות מרובות מצטברות:** אם מספר מדיניויות כל אחת מחזירה `allow(message)`, כל ההודעות משולבות עם שורות חדשות ומועברות ביחד

```js
customPolicies.add({
  name: "confirm-branch-status",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    const cwd = ctx.session?.cwd;
    if (!cwd) return allow("No working directory, skipping branch check.");

    // ... check branch status ...
    if (allPushed) {
      return allow("Branch is up to date with remote.");
    }
    return deny("Unpushed changes detected.");
  },
});
```

### שדות `PolicyContext`

| שדה | סוג | תיאור |
|-------|------|-------------|
| `eventType` | `string` | `"PreToolUse"`, `"PostToolUse"`, `"Notification"`, `"Stop"` |
| `toolName` | `string \| undefined` | הכלי הנקרא (למשל `"Bash"`, `"Write"`, `"Read"`) |
| `toolInput` | `Record<string, unknown> \| undefined` | פרמטרי הקלט של הכלי |
| `payload` | `Record<string, unknown>` | עומס אירוע גולמי מלא מ-Claude Code |
| `session` | `SessionMetadata \| undefined` | הקשר הסשן (ראה להלן) |

### שדות `SessionMetadata`

| שדה | סוג | תיאור |
|-------|------|-------------|
| `sessionId` | `string` | Claude Code session identifier |
| `cwd` | `string` | ספריית העבודה של הסשן Claude Code |
| `transcriptPath` | `string` | נתיב לקובץ התמליל JSONL של הסשן |

### סוגי אירוע

| אירוע | מתי הוא שורה | תוכן `toolInput` |
|-------|--------------|----------------------|
| `PreToolUse` | לפני Claude מריץ כלי | קלט הכלי (למשל `{ command: "..." }` עבור Bash) |
| `PostToolUse` | לאחר סיום כלי | קלט הכלי + `tool_result` (הפלט) |
| `Notification` | כאשר Claude שולח התראה | `{ message: "...", notification_type: "idle" \| "permission_prompt" \| ... }` - hooks חייבים תמיד להחזיר `allow()`, הם לא יכולים לחסום התראות |
| `Stop` | כאשר הסשן Claude מסתיים | ריק |

## סדר הערכה

מדיניויות מוערכות בסדר זה:

1. מדיניויות מובנות (בסדר הגדרה)
2. מדיניויות מותאמות אישית מפורשות מ-`customPoliciesPath` (בסדר `.add()`)
3. מדיניויות קונבנציה מפרויקט `.failproofai/policies/` (קבצים אלפביתיים, סדר `.add()` בתוך)
4. מדיניויות קונבנציה מ-`~/.failproofai/policies/` למשתמש (קבצים אלפביתיים, סדר `.add()` בתוך)

<Note>
ה-`deny` הראשון מקצר את כל המדיניויות הבאות. כל הודעות `instruct` מצטברות ומועברות ביחד.
</Note>

## ייבוא ציבורי

קבצי מדיניות מותאמות אישית יכולים לייבא מודולים מקומיים באמצעות נתיבים יחסיים:

```js
// my-policies.js
import { isBlockedPath } from "./utils.js";
import { checkApproval } from "./approval-client.js";

customPolicies.add({
  name: "approval-gate",
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const approved = await checkApproval(ctx.toolInput?.command, ctx.session?.sessionId);
    return approved ? allow() : deny("Approval required for this command");
  },
});
```

כל ייבואים יחסיים שניתן להשיג מקובץ הכניסה מיושרים. זה מיושם על ידי כתיבה מחדש של ייבואי `from "failproofai"` לנתיב dist בפועל ויצירת קבצי `.mjs` זמניים להבטחת תאימות ESM.

## סינון סוגי אירוע

השתמש ב-`match.events` להגבלת מתי מדיניות שורה:

```js
customPolicies.add({
  name: "require-summary-on-stop",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    // Only fires when the session ends
    // ctx.session.transcriptPath contains the full session log
    return allow();
  },
});
```

השמט `match` לחלוטין כדי שיישרה על כל סוג אירוע.

## טיפול בשגיאות ומצבי כשל

מדיניויות מותאמות אישית הן **fail-open**: שגיאות לעולם לא חוסמות מדיניויות מובנות או קורסות את מטפל ה-hook.

| כשל | התנהגות |
|---------|----------|
| `customPoliciesPath` לא מוגדר | אין מדיניויות מותאמות אישית מפורשות; מדיניויות קונבנציה ומובנות ממשיכות בדרך כלל |
| קובץ לא נמצא | אזהרה מוגדרת ל-`~/.failproofai/hook.log`; מובנויות ממשיכות |
| שגיאת תחביר/ייבוא (מפורש) | שגיאה מוגדרת ל-`~/.failproofai/hook.log`; מדיניויות מותאמות אישית מפורשות דלוגות |
| שגיאת תחביר/ייבוא (קונבנציה) | שגיאה מוגדרת; קובץ זה דלוג, קבצי קונבנציה אחרים עדיין טוענים |
| `fn` זורק בזמן ריצה | שגיאה מוגדרת; ה-hook המטופל כ-`allow`; חוקים אחרים ממשיכים |
| `fn` לוקח יותר מ-10 שניות | timeout מוגדר; מטופל כ-`allow` |
| ספריית קונבנציה חסרה | אין מדיניויות קונבנציה; אין שגיאה |

<Tip>
כדי לנפות שגיאות מדיניות מותאמות אישית, צפה בקובץ יומן:

```bash
tail -f ~/.failproofai/hook.log
```
</Tip>

## דוגמה מלאה: מדיניויות מרובות

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

// Prevent agent from writing to secrets/ directory
customPolicies.add({
  name: "block-secrets-dir",
  description: "Prevent agent from writing to secrets/ directory",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (!["Write", "Edit"].includes(ctx.toolName ?? "")) return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("secrets/")) return deny("Writing to secrets/ is not permitted");
    return allow();
  },
});

// Keep the agent on track: verify tests before committing
customPolicies.add({
  name: "remind-test-before-commit",
  description: "Keep the agent on track: verify tests pass before committing",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    if (/git\s+commit/.test(cmd)) {
      return instruct("Verify all tests pass before committing. Run `bun test` if you haven't already.");
    }
    return allow();
  },
});

// Prevent unplanned dependency changes during freeze
customPolicies.add({
  name: "dependency-freeze",
  description: "Prevent unplanned dependency changes during freeze period",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    const isInstall = /^(npm install|yarn add|bun add|pnpm add)\s+\S/.test(cmd);
    if (isInstall && process.env.DEPENDENCY_FREEZE === "1") {
      return deny("Package installs are frozen. Unset DEPENDENCY_FREEZE to allow.");
    }
    return allow();
  },
});

export { customPolicies };
```
