מדיניות מותאמות מאפשרת לך לכתוב כללים לכל התנהגות של סוכן: אכוף קונוונציות פרויקט, מנע סטייה, חסום פעולות הרסניות, גלה סוכנים תקועים, או שלב עם Slack, זרימות אישור, ועוד. הם משתמשים באותו מערכת אירועים וחלטות `allow`, `deny`, `instruct` כמו המדיניות המובנית.

---

## דוגמה מהירה

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

customPolicies.add({
  name: "no-production-writes",
  description: "Block writes to paths containing 'production'",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Write" && ctx.toolName !== "Edit") return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("production")) {
      return deny("Writes to production paths are blocked");
    }
    return allow();
  },
});
```

התקן אותו:

```bash
failproofai policies --install --custom ./my-policies.js
```

## שתי דרכים לטעון מדיניות מותאמות

### אפשרות 1: קונוונציה (מומלץ)

זרוק קבצי `*policies.{js,mjs,ts}` אל תוך `.failproofai/policies/` והם יטענו באופן אוטומטי — לא צריך דגלים או שינויי תצורה. זה פועל כמו git hooks: זרוק קובץ, זה פשוט עובד.

```
# רמת פרויקט — מחוייב ל-git, משותף עם הצוות
.failproofai/policies/security-policies.mjs
.failproofai/policies/workflow-policies.mjs

# רמת משתמש — אישי, חל על כל הפרויקטים
~/.failproofai/policies/my-policies.mjs
```

**איך זה עובד:**
- שתי תיקיות (פרויקט ומשתמש) סרוקות (union — לא first-scope-wins)
- קבצים טעונים באופן אלפאביתי בכל תיקייה. הוסף קידומת עם `01-`, `02-` לשליטה בסדר
- רק קבצים המתאימים `*policies.{js,mjs,ts}` טעונים; קבצים אחרים מתעלמים
- כל קובץ טעון באופן עצמאי (fail-open לקובץ)
- עובד יחד עם `--custom` מפורשים ומדיניות מובנית

<Tip>
מדיניות קונוונציה היא הדרך הקלה ביותר לבנות תקן איכות לארגון שלך. בצע commit ל-`.failproofai/policies/` ל-git וכל חברי הצוות יקבלו את אותם הכללים באופן אוטומטי — לא צריך הגדרה לכל מפתח. כשהצוות שלך מגלה מצבי כשל חדשים, הוסף מדיניות ודחוף. עם הזמן אלה הופכים לתקן איכות חי שמשתפר עם כל תרומה.
</Tip>

### אפשרות 2: נתיב קובץ מפורש

```bash
# התקן עם קובץ מדיניות מותאם
failproofai policies --install --custom ./my-policies.js

# החלף את נתיבי המדיניות המותאמים
failproofai policies --install --custom ./new-policies.js

# הגדר קבצים מפורשים מרובים (טעונים בסדר דגל)
failproofai policies --install --custom ./security.js --custom ./workflow.js

# הסר את כל נתיבי המדיניות המותאמים המפורשים מהתצורה
failproofai policies --uninstall --custom
```

נתיבים מוחלטים שנפתרו מאוחסנים ב-`policies-config.json` כ-`customPoliciesPaths`. חזור על `--custom` להגדרת קבצים מרובים. תצורות קיימות המשתמשות בשדה `customPoliciesPath` הישן ממשיכות לעבוד. קבצים טעונים טריים בכל אירוע hook - אין קש בין אירועים.

כל מדיניות רשומה מופיעה עם הדלקתו שלה בלוח המחוונים. הדלקת מדיניות מתעדת את מזהה ה-ID המוסמך המקור ב-`disabledCustomPolicies`; הקובץ ומדיניויות אחרות שלו ממשיכות לטעון, בעוד המדיניות המופסקת מוחרגת לפני התאמת אירועים. שמות מדיניות משוכפלים על פני קבצים יש להם הדלקות עצמאיות.

### שימוש בשניהם ביחד

מדיניות קונוונציה וקבצי `--custom` מפורשים יכולים להתקיים. סדר הטעינה:

1. קבצי `customPoliciesPaths` מפורשים (בסדר מוגדר)
2. קבצי קונוונציה פרויקט (`{cwd}/.failproofai/policies/`, אלפאביתי)
3. קבצי קונוונציה משתמש (`~/.failproofai/policies/`, אלפאביתי)

## API

### ייבוא

```js
import { customPolicies, allow, deny, instruct } from "failproofai";
```

### `customPolicies.add(hook)`

רושם מדיניות. קרא לזה כמה פעמים שצריך למדיניויות מרובות באותו קובץ.

```ts
customPolicies.add({
  name: string;                         // נדרש - מזהה ייחודי
  description?: string;                 // מוצג בפלט `failproofai policies`
  match?: { events?: HookEventType[] }; // סנן לפי סוג אירוע; השמט כדי להתאים את הכל
  fn: (ctx: PolicyContext) => PolicyResult | Promise<PolicyResult>;
});
```

### עוזרי החלטה

| פונקציה | השפעה | השתמש כשL |
|---------|--------|----------|
| `allow()` | אפשר את הפעולה בשקט | הפעולה בטוחה, לא צריך הודעה |
| `deny(message)` | חסום את הפעולה | הסוכן לא צריך לבצע פעולה זו |
| `instruct(message)` | הוסף הקשר בלי לחסום | תן לסוכן הקשר נוסף להישאר במסלול |

`deny(message)` - ההודעה מופיעה ל-Claude עם קידומת `"Blocked by failproofai:"`. ה-`deny` יחיד קטע את כל ההערכה הנוספת.

`instruct(message)` - ההודעה מצורפת להקשר של Claude לקריאת הכלי הנוכחית. כל הודעות `instruct` מצטברות ומסופקות יחד.

<Tip>
אתה יכול להוסיף הנחיות נוספות לכל `deny` או `instruct` הודעה על ידי הוספת שדה `hint` ב-`policyParams` — לא צריך שינוי קוד. זה עובד גם למדיניות מותאמות (`custom/`), קונוונציה פרויקט (`.failproofai-project/`), וקונוונציה משתמש (`.failproofai-user/`). ראה [Configuration → hint](/he/configuration#hint-cross-cutting) לפרטים.
</Tip>

### הודעות allow אינפורמטיביות

`allow(message)` מאפשר את הפעולה **וגם** שולח הודעה אינפורמטיבית בחזרה ל-Claude. ההודעה מועברת כ-`additionalContext` בתגובת stdout של מטפל ה-hook — אותו מנגנון המשמש `instruct`, אך שונה מבחינה סמנטית: זו עדכון סטטוס, לא אזהרה.

| פונקציה | השפעה | השתמש כשL |
|---------|--------|----------|
| `allow(message)` | אפשר ושלח הקשר ל-Claude | אשר בדיקה עברה, או הסבר למה בדיקה דלגה |

מקרי שימוש:
- **אישורי סטטוס:** `allow("All CI checks passed.")` — אומר ל-Claude שהכל ירוק
- **הסברי fail-open:** `allow("GitHub CLI not installed, skipping CI check.")` — אומר ל-Claude למה בדיקה דלגה כך שיש לו הקשר מלא
- **הודעות מרובות מצטברות:** אם מדיניויות מרובות כל אחת מחזירה `allow(message)`, כל ההודעות משולבות בשורות חדשות ומועברות יחד

```js
customPolicies.add({
  name: "confirm-branch-status",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    const cwd = ctx.session?.cwd;
    if (!cwd) return allow("No working directory, skipping branch check.");

    // ... check branch status ...
    if (allPushed) {
      return allow("Branch is up to date with remote.");
    }
    return deny("Unpushed changes detected.");
  },
});
```

### שדות `PolicyContext`

| שדה | סוג | תיאור |
|-----|-----|--------|
| `eventType` | `string` | `"PreToolUse"`, `"PostToolUse"`, `"Notification"`, `"Stop"` |
| `toolName` | `string \| undefined` | הכלי קריאה (למשל `"Bash"`, `"Write"`, `"Read"`) |
| `toolInput` | `Record<string, unknown> \| undefined` | פרמטרי קלט של הכלי |
| `payload` | `Record<string, unknown>` | אירוע גולמי מלא מ-Claude Code |
| `session` | `SessionMetadata \| undefined` | הקשר הפעלה (ראה למטה) |

### שדות `SessionMetadata`

| שדה | סוג | תיאור |
|-----|-----|--------|
| `sessionId` | `string` | מזהה הפעלה Claude Code |
| `cwd` | `string` | ספריית עבודה של הפעלה Claude Code |
| `transcriptPath` | `string` | נתיב לקובץ תמלול JSONL של ההפעלה |

### סוגי אירועים

| אירוע | מתי הוא נורה | תוכן `toolInput` |
|-------|------------|------------------|
| `PreToolUse` | לפני Claude הפעלת כלי | קלט הכלי (למשל `{ command: "..." }` עבור Bash) |
| `PostToolUse` | לאחר השלמת כלי | קלט הכלי + `tool_result` (הפלט) |
| `Notification` | כשClaude שולח הודעה | `{ message: "...", notification_type: "idle" \| "permission_prompt" \| ... }` - hooks חייבים תמיד להחזיר `allow()`, הם לא יכולים לחסום הודעות |
| `Stop` | כשהפעלה Claude מסתיימת | ריק |

## סדר הערכה

מדיניויות מוערכות בסדר זה:

1. מדיניות מובנית (בסדר הגדרה)
2. מדיניות מותאמות מפורשות מ-`customPoliciesPath` (בסדר `.add()`)
3. מדיניות קונוונציה מפרויקט `.failproofai/policies/` (קבצים אלפאביתיים, סדר `.add()` בתוך)
4. מדיניויות קונוונציה מ-`~/.failproofai/policies/` משתמש (קבצים אלפאביתיים, סדר `.add()` בתוך)

<Note>
ה-`deny` הראשון קטע את כל המדיניויות הלאחרונות. כל הודעות `instruct` מצטברות ומועברות יחד.
</Note>

## ייבואים טרנזיטיביים

קבצי מדיניות מותאמות יכולים לייבא מודולים מקומיים בשימוש נתיבים יחסיים:

```js
// my-policies.js
import { isBlockedPath } from "./utils.js";
import { checkApproval } from "./approval-client.js";

customPolicies.add({
  name: "approval-gate",
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const approved = await checkApproval(ctx.toolInput?.command, ctx.session?.sessionId);
    return approved ? allow() : deny("Approval required for this command");
  },
});
```

כל הייבואים היחסיים הנגישים מקובץ הכניסה מוגדלים. זה מיושם על ידי שכתוב ייבואי `from "failproofai"` לנתיב ההפצה בפועל ויצירת קבצי `.mjs` זמניים כדי להבטיח תאימות ESM.

## סינון סוג אירוע

השתמש ב-`match.events` להגבלת מתי מדיניות נורה:

```js
customPolicies.add({
  name: "require-summary-on-stop",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    // רק נורה כשההפעלה מסתיימת
    // ctx.session.transcriptPath מכיל את יומן ההפעלה המלא
    return allow();
  },
});
```

השמט את `match` לחלוטין כדי להנורות בכל סוג אירוע.

## טיפול בשגיאות ומצבי כשל

מדיניות מותאמות היא **fail-open**: שגיאות לעולם לא חוסמות מדיניות מובנית או מקרקעות את מטפל ה-hook.

| כשל | התנהגות |
|-----|----------|
| `customPoliciesPath` לא מוגדר | אין מדיניות מותאמות מפורשות הנורות; קונוונציה ומובנית ממשיכים בדרך כלל |
| קובץ לא נמצא | אזהרה רשומה ל-`~/.failproofai/hook.log`; מובנית ממשיכה |
| שגיאה סינטקס/ייבוא (מפורש) | שגיאה רשומה ל-`~/.failproofai/hook.log`; מדיניות מותאמות מפורשות דלוגות |
| שגיאה סינטקס/ייבוא (קונוונציה) | שגיאה רשומה; הקובץ הזה דלוג, קבצי קונוונציה אחרים טוענים עדיין |
| `fn` זורק בעת ריצה | שגיאה רשומה; ה-hook הזה מטופל כ-`allow`; hooks אחרים ממשיכים |
| `fn` לוקח יותר מ-10s | timeout רשום; מטופל כ-`allow` |
| ספריית קונוונציה חסרה | אין מדיניות קונוונציה הנורות; אין שגיאה |

<Tip>
כדי ללדוג שגיאות מדיניות מותאמות, צפה בקובץ היומן:

```bash
tail -f ~/.failproofai/hook.log
```
</Tip>

## דוגמה מלאה: מדיניויות מרובות

```js
// my-policies.js
import { customPolicies, allow, deny, instruct } from "failproofai";

// מנע מהסוכן לכתוב לספריית secrets/
customPolicies.add({
  name: "block-secrets-dir",
  description: "Prevent agent from writing to secrets/ directory",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (!["Write", "Edit"].includes(ctx.toolName ?? "")) return allow();
    const path = ctx.toolInput?.file_path ?? "";
    if (path.includes("secrets/")) return deny("Writing to secrets/ is not permitted");
    return allow();
  },
});

// שמור על הסוכן במסלול: אמת בדיקות לפני commit
customPolicies.add({
  name: "remind-test-before-commit",
  description: "Keep the agent on track: verify tests pass before committing",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    if (/git\s+commit/.test(cmd)) {
      return instruct("Verify all tests pass before committing. Run `bun test` if you haven't already.");
    }
    return allow();
  },
});

// מנע שינויים בתלויות לא מתוכננים במהלך הקפאה
customPolicies.add({
  name: "dependency-freeze",
  description: "Prevent unplanned dependency changes during freeze period",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = ctx.toolInput?.command ?? "";
    const isInstall = /^(npm install|yarn add|bun add|pnpm add)\s+\S/.test(cmd);
    if (isInstall && process.env.DEPENDENCY_FREEZE === "1") {
      return deny("Package installs are frozen. Unset DEPENDENCY_FREEZE to allow.");
    }
    return allow();
  },
});

export { customPolicies };
```

### שימוש בדוגמאות קונוונציה

```bash
# עתק לרמת פרויקט
mkdir -p .failproofai/policies
cp examples/convention-policies/*.mjs .failproofai/policies/

# או עתק לרמת משתמש
mkdir -p ~/.failproofai/policies
cp examples/convention-policies/*.mjs ~/.failproofai/policies/
```

לא צריך פקודת התקנה — הקבצים נקטפים באופן אוטומטי באירוע ה-hook הבא.
