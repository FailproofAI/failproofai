לוח בקרה failproofai הוא יישום אינטרנט מקומי לניטור הפעלות של סוכני AI וניהול מדיניויות. ראה מה עשו הסוכנים שלך בזמן שלא הייתה בעיניים.

---

## הפעלת לוח הבקרה

```bash
failproofai
```

נפתח בכתובת `http://localhost:8020`.

לוח הבקרה קורא ישירות מקובץ המערכת - תיקיות הפרויקט Claude Code וקובצי ההגדרות של failproofai. שום דבר לא נכתב לשירות מרוחק.

## עמודים

### פרויקטים

רשימה של כל פרויקטי Claude Code, OpenAI Codex, GitHub Copilot CLI _(beta)_, Cursor Agent _(beta)_, OpenCode _(beta)_, Pi _(beta)_, ו-Gemini CLI _(beta)_ שנמצאים במכונה שלך. פרויקטי Claude מתגלים מתוך `~/.claude/projects/` (או הנתיב שהוגדר על ידי `CLAUDE_PROJECTS_PATH`); פרויקטי Codex מתגלים על ידי סריקה של כל תמליל תחת `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` וקיבוץ לפי ה-`cwd` המוקלט בתיעוד הראשון של כל הפעלה; פרויקטי Copilot CLI מתגלים על ידי סריקה של כל `~/.copilot/session-state/<sessionId>/workspace.yaml` (שניתן להגדיר דרך `COPILOT_HOME`) וקיבוץ לפי שדה ה-`cwd` שלו; פרויקטי Cursor Agent מתגלים על ידי סריקה של מטאדטה לכל הפעלה תחת `~/.cursor/agent-sessions/<sessionId>/` (שניתן להגדיר דרך `CURSOR_HOME`, כאשר `conversations/` ו-`sessions/` נבדקים כחלופה) לקבלת `cwd` סקלרי ב-`meta.json` / `session.json` / `workspace.yaml`; פרויקטי OpenCode מתגלים על ידי שאילתה על מסד הנתונים SQLite שלו ב-`~/.local/share/opencode/opencode.db` דרך `opencode db --format json` (אנו קוראים את הטבלאות `session` ו-`project` וקיבוץ לפי `project_id`); פרויקטי Pi מתגלים על ידי סריקה של תמליל JSONL לכל הפעלה תחת `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` (שניתן להגדיר דרך `PI_SESSIONS_DIR`) וקבלת `cwd` מתיעוד הראשון של כל הפעלה; פרויקטי Gemini CLI מתגלים על ידי סריקה של `~/.gemini/tmp/<basename>/chats/session-<timestamp>-<uuid-prefix>.jsonl` (שניתן להגדיר דרך `GEMINI_SESSIONS_DIR`) וחזרה ל-cwd הקנוני מסימן הטקסט הסמוך `.project_root`. פרויקט שהשתמש בו מספר CLIs מוצג בשורה אחת עם כל התג המתאים. השתמש בתפריט ה-**CLI** מעל הטבלה כדי לסנן לפי CLI סוכן ספציפי; כתובת ה-URL שומרת את הבחירה שלך כ-`?cli=claude|codex|copilot|cursor|opencode|pi|gemini`.

כל פרויקט מציג:
- שם הפרויקט (נגזר מנתיב התיקייה)
- תג CLI — `Claude Code` (כתום), `OpenAI Codex` (סגול), `GitHub Copilot` (כחול), `Cursor Agent` (אזמרגד), `OpenCode` (amber), `Pi` (ורוד), ו/או `Gemini CLI` (sky)
- תאריך של פעילות הפעלה האחרונה

לחץ על פרויקט כדי לראות את ההפעלות שלו.

### הפעלות

רשימה של כל ההפעלות בתוך פרויקט. כל הפעלה מציגה:
- מזהה הפעלה
- חותמות זמן של התחלה וסיום
- מספר קריאות כלים
- ספירת פעילות ווה (מדיניויות שכבו)

השתמש בסינון טווח התאריכים וחיפוש מזהה הפעלה כדי לצמצם את הרשימה. הפעלות מחולקות לעמודים.

לחץ על הפעלה כדי לפתוח את התצוגה של הפעלה.

### צופה הפעלות

צופה ההפעלות משיב לשאלה הקריטית עבור סוכנים אוטונומיים: מה עשה הסוכן, והאם הוא נשאר על המסלול? תג CLI ליד הכותרת מציין אם ההפעלה היא תמליל Claude Code, OpenAI Codex, GitHub Copilot CLI, Cursor Agent, OpenCode, Pi, או Gemini CLI. היא מציגה ציר זמן של כל מה שקרה בהפעלה:

- **הודעות** - תגובות הטקסט של Claude וכן הנושאים של המשתמש
- **קריאות כלים** - כל כלי שקרא Claude, עם הקלט והתוצאה שלו
- **פעילות מדיניות** - עבור כל קריאת כלי, אילו מדיניויות כבו ומה היא ההחלטה שהחזירו

סרגל הנתונים בחלק העליון מציג את משך ההפעלה, סך הכל קריאות כלים וסיכום החלטות ווה (ספירות allow / deny / instruct).

לחץ על כפתור **Download Logs** כדי לייצא את ההפעלה. עבור הפעלות Claude Code, Codex, Copilot, Cursor, Pi ו-Gemini אתה מקבל את התמליל JSONL המקורי בדיסק בייט על בייט; עבור OpenCode (שההפעלות שלו חיות ב-SQLite, לא בדיסק) אתה מקבל מסמך JSON המשקף את הטבלאות `session` / `messages` / `parts` הבסיסיות.

### ביקורת

דוח מונע אישיות של התנהגות הסוכן שלך בפועל על פני הפעלות קודמות. הוא מפעיל את אותה סריקה כמו ה-CLI `failproofai audit` אך מעניק אותה כלוח בקרה בעל שישה חלקים:

1. **זהות** — מסווג את הסוכן שלך לאחד מ-8 אבות טיפוס (`the optimist`, `the cowboy`, `the explorer`, `the goldfish`, `the paranoid architect`, `the precision builder`, `the hammer`, `the ghost`) בהתאם לאילו גלאיים + מדיניויות כבו וכמה כבד. מעניק sigil בגודל 8×8 פיקסל, תגיית archetype, מסגור של common in / primary risk, וה-one-liner של הסיום.
2. **הצג את הסוכן שלך** — לוכד את כרטיס הזהות כ-PNG של 1200×630 המתאים לפרסום ב-X / LinkedIn (לחץ על `make poster`).
3. **חוזקות** — התנהגויות מסומנות בירוק שהסוכן שלך כבר עושה נכון, הנגזרות מנתוני הביקורת החיים (שיעור קריאת כלים נקי, אורך הפעלה ממוצע, אפס דיווח אישורים, אפס סערות ניסיון חוזר וכו').
4. **ניקוד + לוח דירוג** — ניקוד של 0–100 עם ציון אות (S/A/B/C/D/F), היסטוגרמת הפצה המציגה היכן אתה נופל בקוהורט, פרוז (a B starts at 71. you're 13 points away.), וטבלת לוח דירוג עם השורה שלך מודגשת.
5. **ממצאים** — כרטיסי ממצאים מדורגים לפי השפעה. כל כרטיס משטח מה קרה, מה זה עולה לו, דוגמה ראיות עם פקודות שנתפסו בפועל, והמדיניות failproofai שתתפוס את אותו דפוס (`$ failproofai policy add <slug>`, לחץ-להעתקה).
6. **מדיניויות מיועדות + לולאת חזרה** — רשת של כל מדיניות מובנית שלא הופעלה שתסגור פער, עם הערת score הנחזקת, בתוספת CTA של re-audit in 7 days.

מונע על ידי זמן ריצה של `failproofai audit` — ראה [Audit CLI](/he/cli/audit) לסריקה הבסיסית, דגלים נתמכים, וקביעות cache לכל תמליל. לוח הבקרה משמר את התוצאה האחרונה בכתובת `~/.failproofai/audit-dashboard.json` (mode `0600`, חריץ יחיד, ריצות חדשות מחליפות) כך שבקרים חוזרים מיידיים; **גם ה-per-transcript וגם ה-whole-result caches דחויים בקריאה ברגע שהם ישנים יותר מ-7 ימים** כך שלוח הבקרה לא יוגש שקט לתוצאה בשבוע-יום — בעבר ה-TTL `/audit` נופל דרכו למצב הריק ומזהיר לריצה טרייה. לחיצה על `[ re-audit now ]` ליד תחתית הדוח POSTs `/api/audit/run` ולוח הבקרה שוקל `/api/audit/status` ב-1Hz עד שהריצה מסתיימת; סרט ההתקדמות הוורוד הדבוק מנעל לחלק העליון של ה-viewport במהלך הריצה עם טיימר שחלוף, והתוצאה מתחלפת במקום בהצלחה (ללא טעינה מחדש של העמוד המלא). בכישלון הסרט הופך לאדום עם עותק מפותח בחזרה לתוך `RerunError.kind` (`timeout` / `network` / `post_failed`). מצב ריק (ללא cache או פג תוקף) ומצב אפס-הפעלות (cache קיים אך הסריקה לא מצאה תמליל) משטחים בנפרד.

## ריענון אוטומטי

לוח הבקרה יש כפתור toggle ריענון אוטומטי בניווט העליון. כשהוא מופעל, העמוד הנוכחי מתרענן תקופתית כדי להציג הפעלות חדשות ופעילות מדיניות כשהם מופיעים. חיוני לניטור הפעלות סוכן אוטונומיות ארוכות.

## השבתת עמודים

אם אתה צריך רק חלקים מסוימים של לוח הבקרה, הגדר `FAILPROOFAI_DISABLE_PAGES` לרשימה מופרדת בפסיקים של שמות עמודים:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

ערכים תקפים: `policies`, `projects`, `audit`.

## הגדרת נתיב הפרויקטים

כברירת מחדל, לוח הבקרה קורא מספרייה הפרויקט של Claude Code הסטנדרטית. עקוף אותה להגדרות מותאם אישית:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## גישה מכונחך host שאינו localhost

כאשר הפעלת את לוח הבקרה ב-**mode פיתוח** (`npm run dev`) וגישה אליו מ-hostname אחר מלבד `localhost` - לדוגמה, דומיין מותאם, IP מרוחק, או כתובת URL מעברת - ייתכן שתראה אזהרה כמו:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

זה Next.js חוסם גישה cross-origin ל-websocket HMR (hot module reload) שלו, שהוא תכונה של dev בלבד. כדי לאפשר את ה-host שלך, השתמש בדגל `--allowed-origins`:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

עבור hosts או IPs מרובים, העבר רשימה מופרדת בפסיקים:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

אתה יכול גם להגדיר את משתנה הסביבה `FAILPROOFAI_ALLOWED_DEV_ORIGINS` במקום זאת:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
זה חל רק ל-dev mode. כאשר מפעיל את `failproofai` (production mode), אין websocket HMR ואין בעיית cross-origin dev resource.
</Note>
