לוח הבקרה של failproofai היא אפליקציית רשת מקומית לעקיבה אחר סשני הסוכנים שלך ניהול מדיניות. ראו מה עשו הסוכנים שלך בזמן שלא היית שם.

---

## הפעלת לוח הבקרה

```bash
failproofai
```

נפתח ב־`http://localhost:8020`.

לוח הבקרה קורא את נתוני הפרויקט, הסשן והגדרות failproofai המקומיות ישירות מהמערכת הקבצים. תכונות עם אימות אופציוני, כמו תזכורות ביקורת והזמנות, שולחות את המידע הנדרש לבקשות אלה (כולל כתובות דוא״ל) לממשקי API מרוחקים.

## עמודים

### פרויקטים

מפרטת את כל פרויקטי Claude Code, OpenAI Codex, GitHub Copilot CLI _(beta)_, Cursor Agent _(beta)_, OpenCode _(beta)_, Pi _(beta)_, Hermes, OpenClaw, Factory Droid, Devin, Antigravity ו־Goose שנמצאו במחשב שלך. פרויקטי Claude מתגלים מ־`~/.claude/projects/` (או הנתיב שהוגדר על ידי `CLAUDE_PROJECTS_PATH`); פרויקטי Codex מתגלים בסריקה של כל תמלול תחת `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` וקיבוץ על פי ה־`cwd` המתועד בתיעוד הראשון של כל סשן; פרויקטי Copilot CLI מתגלים בסריקה של כל `~/.copilot/session-state/<sessionId>/workspace.yaml` (ניתן להגדרה דרך `COPILOT_HOME`) וקיבוץ על פי שדה ה־`cwd` שלו; פרויקטי Cursor Agent מתגלים בסריקה של מטא־נתונים לכל סשן תחת `~/.cursor/agent-sessions/<sessionId>/` (ניתן להגדרה דרך `CURSOR_HOME`, עם `conversations/` ו־`sessions/` בדיקה כאפשרויות חלופיות) לחיפוש סקלר `cwd` ב־`meta.json` / `session.json` / `workspace.yaml`; פרויקטי OpenCode מתגלים בשאילתה למסד הנתונים SQLite שלו ב־`~/.local/share/opencode/opencode.db` דרך `opencode db --format json` (אנו קוראים את טבלאות `session` ו־`project` וקובצים על פי `project_id`); פרויקטי Pi מתגלים בסריקה של תמלולי JSONL לכל סשן תחת `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` (ניתן להגדרה דרך `PI_SESSIONS_DIR`) וחילוץ ה־`cwd` מתיעוד הראשון של כל סשן; סשני שער Hermes נקראים ישירות מחנות SQLite של כל פרופיל — `~/.hermes/state.db` בתוספת `~/.hermes/profiles/<name>/state.db` (ניתן לעקיפה דרך `HERMES_HOME`, או `HERMES_DB_PATH` עבור מסד נתונים יחיד) — וקובצים לפרויקטי `hermes-<profile>-<source>` לפי פרופיל ו־`source` (Slack/Telegram/cli/cron — לסשני שער אין cwd); סשני שער OpenClaw נקראים מ־`~/.openclaw/agents/<agentId>/sessions/*.jsonl` וקובצים לפרויקטי `openclaw-<agentId>-<channel>` לפי סוכן וערוץ (גם ללא cwd); פרויקטי Factory Droid מתגלים מתמלולי JSONL ב־`~/.factory/sessions/<encoded-cwd>/*.jsonl` וקובצים לפי cwd; פרויקטי Devin ממסד הנתונים SQLite שלו ב־`~/.local/share/devin/cli/sessions.db` (קובצים לפי `working_directory` של כל סשן); פרויקטי Antigravity מתמלולי JSONL ב־`~/.gemini/antigravity-cli/brain/<conversationId>/…/transcript_full.jsonl` וקובצים לפי cwd; ופרויקטי Goose ממסד הנתונים SQLite שלו ב־`~/.local/share/goose/sessions/sessions.db` (קובצים לפי `working_dir` של כל סשן). פרויקט שהשתמשו בו CLIs מרובים מוצג כשורה יחידה עם כל התגים התואמים. השתמשו בתפריט הנפתח **CLI** מעל הטבלה כדי לסנן לפי CLI סוכן ספציפי; הכתובת שומרת את הבחירה שלכם כ־`?cli=claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose`.

Hermes ו־OpenClaw הם בהיקף משתמש ואין להם ספריית עבודה לקיבוץ לפיה, כך שהם מוצגים כ־**עץ תיקיות ניתן להתארה** — פרופיל (או סוכן) ברמה העליונה, הערוצים שלו מתחתיו — בעוד שכל CLI מבוסס cwd נשאר שורה שטוחה. שורות תיקייה מקדנו את ספירת הסשן והפעילות האחרונה ביותר של הכל שמתחתיהן, תיקיות שמור עליהן זכורות בין ביקורים, וחיפוש מילות מפתח מרחיב כל מה שהוא תואם.

כל פרויקט מציג:
- שם פרויקט (המגוזר מנתיב התיקייה)
- תג CLI — `Claude Code` (כתום), `OpenAI Codex` (סגול), `GitHub Copilot` (כחול), `Cursor Agent` (ירוק־כחול), `OpenCode` (כהה), `Pi` (ורוד), ו/או `Hermes` (אינדיגו)
- תאריך של פעילות הסשן האחרון ביותר

לחצו על פרויקט כדי לראות את הסשנים שלו.

### סשנים

מפרטת את כל הסשנים בתוך פרויקט. כל סשן מציג:
- מזהה סשן
- חותמות זמן של התחלה וסיום
- מספר קריאות כלים
- ספירת פעילות ווק (מדיניות שהופעלו)

השתמשו בסנן טווח התאריכים וחיפוש מזהה סשן כדי לצמצם את הרשימה. סשנים מחולקים לעמודים.

לחצו על סשן כדי לפתוח את צופה הסשן.

### צופה סשן

צופה הסשן עונה על השאלה החיונית לסוכנים עצמאיים: מה עשה הסוכן, והאם הוא נשאר בעקבוות? תג CLI ליד הכותרת מציין האם הסשן הוא תמלול Claude Code, OpenAI Codex, GitHub Copilot CLI, Cursor Agent, OpenCode, Pi, Hermes, OpenClaw, Factory Droid, Devin, Antigravity או Goose. הוא מציג ציר הזמן של כל מה שקרה בסשן:

- **הודעות** - תגובות טקסט של Claude והודעות משתמש
- **קריאות כלים** - כל כלי שהזמן Claude, עם הקלט והפלט שלו
- **פעילות מדיניות** - לכל קריאת כלים, איזו מדיניות הופעלה ואיזה החלטה היא החזירה

סרגל הנתונים בחלק העליון מציג משך הסשן, סך הכל קריאות כלים וסיכום החלטות ווק (ספירות allow / deny / instruct).

לחצו על כפתור **Download Logs** כדי לייצא את הסשן. עבור סשני Claude Code, Codex, Copilot, Cursor ו־Pi אתם מקבלים את תמלול JSONL המקורי בדיסק בתים־לתוך־בתים; עבור OpenCode (שהסשנים שלו חיים ב־SQLite, לא בדיסק) אתם מקבלים מסמך JSON המשקף את טבלאות `session` / `messages` / `parts` הבסיסיות.

### ביקורת

דוח מונעי אישיות של איך הסוכן שלכם באמת התנהג ברחבי סשנים קודמים. מריץ את אותה הסריקה של CLI `failproofai audit` אך מוצג אותה כפוסטר יחיד המסך משותף + ארבע סעיפים תחת הקפלדה:

1. **פוסטר** — מלא את חלון הראשון. אזור קבוע בעצמו PNG עם הלוגו failproof_ai + תווית ביקורת · אינדקס אב־טיפוס (`№ NN of 08`) + תאריך ביקורת · ניקוד מספרי (0–100) + כדור דירוג אחוזון (`top 15%`) · שם אב־הטיפוס (אחד מ־`the optimist`, `the cowboy`, `the explorer`, `the goldfish`, `the paranoid architect`, `the precision builder`, `the hammer`, `the ghost`) + רצועת 3 מילות מפתח · `// only N% of agents are this archetype` שורת נדירות · אריח איתות 8×8 פיקסל · `audit yours → failproof.ai` כרגל. שלושה כפתורי שיתוף יושבים בדיוק מחוץ לתיבת התפיסה: `post your archetype` (כוונת X), `share on linkedin`, `download poster`. התפיסה עוברת דרך `html-to-image` כך ש־PNG תואם את ההצגה על־מסך פיקסל־לפיקסל (גבולות מקוטעים, מסיכת לוגו SVG, הדרגות, מדדי גופן — הכל שמור).
2. **חוזקות** — שורה שקטה ✓ רשימה של התנהגויות שהסוכן שלכם כבר עושה נכון, המגוזרת מנתוני הביקורת החיים (קצב קריאות כלים נקי, ללא דחיפות ישירות לראשי, אפס דליפות אישור, אפס סערות ניסיון חוזר) — כל אחת מוצגת רק כאשר למדיניות הרלוונטית יש שיא נקי ברחבי חלון הביקורת.
3. **ייחודיות** — טבלה של מה שהחמיץ, מדורג לפי חומרה: `when · what slipped + the policy that would've caught it · severity pill · seen`, כאשר ההישנות קוראת `new` (פעם אחת), `N× seen` (2–9 פעמים), או `recurring` (10+).
4. **איך להשתפר** — שורה שקטה, אחת לכל מדיניות בהצעה: שם מדיניות בלבן, תיאור בשורה אחת, פקודת התקנה + כפתור עותק בצד ימין. כותרת הסעיף קוראת `enable all N → projected <score> · <tier>` (הניקוד שהיית מגיע אליו עם כל התיקונים המיושמים), וכפתור `[install all]` שלה מעתיק את פקודת `failproofai policy add a b c …` המשולבת לכל מדיניות בהצעה.
5. **חזור טוב יותר** — שתי כרטיסיות זו לזו. שמאל: הגדר תזכורת (בחר קדנציה `3d` / `7d` / `14d` / `30d`; קיים דרך `/api/auth/reminder` ברגע שאומת). ימין: בטל נעילה של יתרונות failproof — `invite a friend` פותח דיאלוג שלוקח רשימה של דוא״לים של חברים מופרדים בפסיקים/רווחים/שורות חדשות (מקסימום 10 לשליחה), הודעה עליהם לכתובת `/api/audit/invite`, שמעביר לכתובת `POST /v0/invite` של שרת ה־API. שרת ה־API שולח דוא״ל אחד לכל נמען מ־`invite@failproof.ai` עם ה־Cc של שולח וה־`Reply-To` מוגדר, כך שהנמען רואה מי הזמין אותו והשולח מקבל עותק בתיבת הדוא״ל שלו. משתמשים אנונימיים מנותבים דרך `AuthDialog` תחילה כך שדוא״ל השולח ידוע לפני יציאת הזמנות. הזכאות / מילוי יתרונות הוא המשך.

מונעת על ידי זמן ריצה `failproofai audit` — ראו [Audit CLI](/he/cli/audit) עבור מנוע סריקה בסיס, דגלים נתמכים ובלתי־משתנים בטמון לכל תמלול. לוח הבקרה טומן את התוצאה האחרונה ב־`~/.failproofai/audit-dashboard.json` (מצב `0600`, משבצת יחידה, ריצות חדשות דורסות) כך שביקורים חוזרים מיידיים; **גם הטמון לכל תמלול והתוצאה שלמה נדחים בקריאה ברגע שהם יותר מ־7 ימים** כך שלוח הבקרה לעולם לא משרת בשתיקה תוצאה בן שבוע — מעבר ל־TTL `/audit` נופל לכמות הריקה שלו ובקשות לריצה טרייה. לחיצה על `[ re-audit now ]` ליד תחתית הדוח כותבת `/api/audit/run` עם `noCache: true` — ביקורת חוזרת עוקפת את הטמון לכל תמלול וסורקת מחדש כל תמלול מאפס במקום להחזיר בשתיקה את התוצאה המטומנת — ולוח הבקרה משוקלל `/api/audit/status` ב־1Hz עד לסיום הריצה; פס התקדמות ורוד דביק מתפר לחלק העליון של חלון הצפייה במהלך הריצה עם טיימר שחלף, והתוצאה הטרייה מתחלפת למקום בהצלחה (אין טעינה מחדש של דף מלא; ביקורת חוזרת שנכשלה משאירה את הדוח הקודם כשלם). בכשל הפס הופך לאדום עם עותק מפתח בטיפול ב־`RerunError.kind` (`timeout` / `network` / `post_failed`). כמות ריקה (אין טמון או פג תוקף) וכמות סשנים־אפס (טמון קיים אך הסריקה לא מצאה תמלולים) משטחים בנפרד.

## ריענון אוטומטי

לוח הבקרה יש תאום ריענון אוטומטי בניווט העליון. בעת הפעלה, העמוד הנוכחי מתרענן מעת לעת כדי להציג סשנים חדשים ופעילות מדיניות כפי שהם מופיעים. חיוני לעקיבה אחר סשני סוכן עצמאי פעילים ארוכי־טווח.

## השבתת עמודים

אם אתם זקוקים רק לחלקים מסוימים של לוח הבקרה, הגדרו `FAILPROOFAI_DISABLE_PAGES` לרשימה מופרדת בפסיקים של שמות עמודים:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

ערכים תקפים: `policies`, `projects`, `audit`.

## הגדרת נתיב הפרויקטים

כברירת מחדל, לוח הבקרה קורא מספריית הפרויקטים של Claude Code הסטנדרטית. עקפו אותה להגדרות מותאמות אישית:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## גישה מערך מחשב שאינו localhost

בעת הפעלת לוח הבקרה ב־**מצב פיתוח** (`npm run dev`) וגישה אליו מערכת שם מחשב שאינה `localhost` - לדוגמה, תחום מותאם אישית, IP מרוחק, או כתובת URL מנותבת — ייתכן שתראו אזהרה כמו:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

זה Next.js חוסם גישה חוצה־מקור לשקע HMR (hot module reload) שלו, שהוא תכונה לפיתוח בלבד. כדי לאפשר את המערח שלכם, השתמשו בדגל `--allowed-origins`:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

למערחות מרובות או IPs, העברו רשימה מופרדת בפסיקים:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

אתם יכולים גם להגדיר את משתנה הסביבה `FAILPROOFAI_ALLOWED_DEV_ORIGINS` במקום:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
זה חל רק על מצב פיתוח. בעת הפעלת `failproofai` (מצב ייצור), אין שקע HMR ואין בעיית משאבי פיתוח חוצים־מקור.
</Note>
