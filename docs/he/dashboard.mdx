לוח הבקרה של failproofai היא יישומון אינטרנט מקומי לניטור סשנים של סוכני AI שלך וניהול מדיניות. ראה מה עשו הסוכנים שלך בזמן שלא היית שם.

---

## הפעלת לוח הבקרה

```bash
failproofai
```

נפתח ב־`http://localhost:8020`.

לוח הבקרה קורא נתוני פרויקט, סשן וקונפיגורציה של failproofai מקומיים ישירות מהמערכת הקובצים. תכונות עם אימות אופציוני, כמו תזכוכות ביקורת והזמנות, שולחות את המידע הדרוש לבקשות אלו (כולל כתובות דוא״ל) ל־API מרחוק.

## דפים

### Projects

מפרט את כל פרויקטי Claude Code, OpenAI Codex, GitHub Copilot CLI _(beta)_, Cursor Agent _(beta)_, OpenCode _(beta)_, Pi _(beta)_, Hermes, OpenClaw, Factory Droid, Devin, Antigravity, וגם Goose שנמצאו במחשבך. פרויקטי Claude מגילים מ־`~/.claude/projects/` (או הנתיב שנקבע על ידי `CLAUDE_PROJECTS_PATH`); פרויקטי Codex מגילים על ידי סריקת כל תמליל תחת `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` וקיבוץ לפי ה־`cwd` שתועד בתיעוד הראשון של כל סשן; פרויקטי Copilot CLI מגילים על ידי סריקת כל `~/.copilot/session-state/<sessionId>/workspace.yaml` (קונפיגורבילי דרך `COPILOT_HOME`) וקיבוץ לפי שדה `cwd` שלו; פרויקטי Cursor Agent מגילים על ידי סריקת מטא־דטה לפי סשן תחת `~/.cursor/agent-sessions/<sessionId>/` (קונפיגורבילי דרך `CURSOR_HOME`, עם `conversations/` ו־`sessions/` הנדסקות כחלופות) לחיפוש סקלר `cwd` ב־`meta.json` / `session.json` / `workspace.yaml`; פרויקטי OpenCode מגילים על ידי שאילתה של SQLite DB שלו ב־`~/.local/share/opencode/opencode.db` דרך `opencode db --format json` (אנחנו קוראים את הטבלאות `session` ו־`project` וקיבוץ לפי `project_id`); פרויקטי Pi מגילים על ידי סריקת תמליל JSONL לפי סשן תחת `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` (קונפיגורבילי דרך `PI_SESSIONS_DIR`) וחילוץ ה־`cwd` מהתיעוד הראשון של כל סשן; סשני gateway של Hermes קוראים ישירות מחנות SQLite של כל פרופיל — `~/.hermes/state.db` בתוספת `~/.hermes/profiles/<name>/state.db` (עשוי להיות עקיף דרך `HERMES_HOME`, או `HERMES_DB_PATH` לבסיס נתונים יחיד) — וקיבוץ לפרויקטים `hermes-<profile>-<source>` לפי פרופיל ו־`source` (Slack/Telegram/cli/cron — לסשני gateway אין cwd); סשני gateway של OpenClaw קוראים מ־`~/.openclaw/agents/<agentId>/sessions/*.jsonl` וקיבוץ לפרויקטים `openclaw-<agentId>-<channel>` לפי סוכן וערוץ (גם ללא cwd); פרויקטי Factory Droid מגילים מתמליל JSONL ב־`~/.factory/sessions/<encoded-cwd>/*.jsonl` וקיבוץ לפי cwd; פרויקטי Devin מ־SQLite DB שלו ב־`~/.local/share/devin/cli/sessions.db` (קיבוץ לפי `working_directory` של כל סשן); פרויקטי Antigravity מתמליל JSONL ב־`~/.gemini/antigravity-cli/brain/<conversationId>/…/transcript_full.jsonl` וקיבוץ לפי cwd; וגם פרויקטי Goose מ־SQLite DB שלו ב־`~/.local/share/goose/sessions/sessions.db` (קיבוץ לפי `working_dir` של כל סשן). פרויקט שהשתמש בו CLI מרובים מרונדר כשורה יחידה עם כל התגים המתאימים. השתמש בתפריט הנפתח **CLI** מעל הטבלה לסינון לפי CLI סוכן ספציפי; ה־URL שומר את הבחירה שלך כ־`?cli=claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose`.

Hermes ו־OpenClaw הם בהיקף משתמש ואין להם ספריית עבודה לקיבוץ לפיה, אז הם מרונדרים כ־**עץ תיקייה מכווץ** — פרופיל (או סוכן) בשכבה העליונה, הערוצים שלו מתחתיו — בעוד כל CLI מבוסס cwd נשאר שורה שטוחה. שורות תיקייה מגלגלות את ספירת הסשנים והפעילות הاחרונה ביותר של הכל שתחתיהן, תיקיות מכווצות זוכרות בין ביקורים, וחיפוש מילות מפתח מרחיב כל מה שהוא תואם.

כל פרויקט מציג:
- שם פרויקט (נגזר מנתיב התיקייה)
- תג CLI — `Claude Code` (כתום), `OpenAI Codex` (סגול), `GitHub Copilot` (כחול), `Cursor Agent` (זמרד), `OpenCode` (ענבר), `Pi` (ורוד), ו/או `Hermes` (אינדיגו)
- תאריך הפעילות האחרונה ביותר של הסשן

לחץ על פרויקט כדי לראות את הסשנים שלו.

### Sessions

מפרט את כל הסשנים בפרויקט. כל סשן מציג:
- מזהה סשן
- חותמות זמן התחלה וסיום
- מספר קריאות כלים
- ספירת פעילות hook (מדיניות שנעולו)

השתמש במסנן טווח התאריך וחיפוש מזהה סשן כדי לצמצם את הרשימה. סשנים מחולקים לעמודים.

לחץ על סשן כדי לפתוח את מציג הסשן.

### מציג סשן

מציג הסשן עונה על השאלה העיקרית לסוכנים אוטונומיים: מה עשה הסוכן, והאם הוא נשאר בעקבוצה? תג CLI ליד הכותרת מציין אם הסשן הוא Claude Code, OpenAI Codex, GitHub Copilot CLI, Cursor Agent, OpenCode, Pi, Hermes, OpenClaw, Factory Droid, Devin, Antigravity, או Goose transcript. זה מציג ציר זמן של כל מה שקרה בסשן:

- **Messages** - תגובות טקסט של Claude והנחות משתמש
- **Tool calls** - כל כלי ש־Claude הפעיל, עם הקלט וההפקה שלו
- **Policy activity** - עבור כל קריאת כלי, אילו מדיניות נעולו ואיזו החלטה הן החזירו

סרגל הסטטיסטיקה בחלק העליון מציג משך סשן, סך הכל קריאות כלים, ותקציר של החלטות hook (ספירות allow / deny / instruct).

לחץ על כפתור **Download Logs** כדי לייצא את הסשן. עבור Claude Code, Codex, Copilot, Cursor, ו־Pi סשנים אתה מקבל את תמליל JSONL המקורי בדיסק בערך בדיוק; עבור OpenCode (שהסשנים שלו חיים ב־SQLite, לא בדיסק) אתה מקבל מסמך JSON המשקף את הטבלאות `session` / `messages` / `parts` הבסיסיות.

### Audit

דוח מונע בעלות אישיות כיצד הסוכן שלך התנהג בפועל על פני סשנים קודמים. מפעיל את אותה הסריקה כמו CLI `failproofai audit` אך מרונדר אותה כפוסטר של מסך יחיד שניתן לשתוף + ארבע חלקים מתחת לגיפול:

1. **Poster** — ממלא את תצוגה הראשונה. אזור הקapture המכיל PNG עצמאי עם סימן failproof_ai + תווית ביקורת · אינדקס ארכיטיפ (`№ NN של 08`) + תאריך ביקורת · ציון מספרי (0–100) + כדור דירוג אחוז (`top 15%`) · שם הארכיטיפ (אחד מתוך `the optimist`, `the cowboy`, `the explorer`, `the goldfish`, `the paranoid architect`, `the precision builder`, `the hammer`, `the ghost`) + פס 3 מילות מפתח · `// רק N% של סוכנים הם הארכיטיפ הזה` שורת נדירות · אריח סיגיל בגודל 8×8 פיקסל · `audit yours → failproof.ai` כניסה. שלושה כפתורי שיתוף יושבים בחוץ מקופסת ה־capture: `post your archetype` (X intent), `share on linkedin`, `download poster`. ה־Capture רץ דרך `html-to-image` כך שה־PNG תואם את ה־render שלעומת המסך בדיוק לפיקסל (גבולות מחוטים, מסכת לוגו SVG, גרדיאנטים, מדדי גופן — הכל שמור).
2. **Strengths** — רשימת שורות רגועה ✓ של התנהגויות שהסוכן שלך כבר עושה נכון, נגזרות מנתוני הביקורת החיים (קצב קריאות כלים נקי, אין דחיפות ישירות ל־main, זרימת אישור אפס, סערות retry אפס) — כל אחת מוצגת רק כאשר למדיניות הרלוונטית יש רקורד נקי על פני חלון הביקורת.
3. **Quirks** — טבלה של מה שהעלה דלל, דורג לפי חומרה: `when · what slipped + המדיניות שהייתה תופסת אותה · חומרה pill · seen`, כאשר החזרה היא `new` (פעם אחת), `N× seen` (2–9 פעמים), או `recurring` (10+).
4. **How to improve** — רשימת שורות רגועה, אחת למדיניות מנויה: שם המדיניות בלבן, תיאור שורה אחת, פקודת התקנה + כפתור העתקה בצד ימין. כותרת הסעיף קוראת `enable all N → projected <score> · <tier>` (הציון שתגיע אליו עם כל התיקון יישום), וה־`[install all]` שלה מעתיק את הפקודה המשולבת `failproofai policy add a b c …` עבור כל מדיניות מנויה.
5. **Come back better** — שתי כרטיסים זה לצד זה. שמאל: הגדר תזכוכת (`3d` / `7d` / `14d` / `30d` בורר קדנציה; מתמיד דרך `/api/auth/reminder` פעם authed). ימין: בטל failproof perks — `invite a friend` פותח מודאל שלוקח רשימה של כתובות דוא״ל של חברים מופרדות בפסיק/רווח/שורה חדשה (מקסימום 10 לשליחה), POSTs אותן ל־`/api/audit/invite`, המעביר ל־`POST /v0/invite` של ה־api-server. ה־api-server שולח דוא״ל אחד לכל נמען מ־`invite@failproof.ai` עם ה־Cc של השולח וה־`Reply-To` שנקבע, כך שהנמען רואה מי הזמין אותם והשולח מקבל עותק בתיבת הדוא״ל שלהם. משתמשים אנונימיים מוגדרים דרך ה־`AuthDialog` תחילה כך שכתובת הדוא״ל של השולח ידועה לפני שההזמנות יוצאות. הקצאה / קיום perks היא עקיבה.

מונעת על ידי ריצת `failproofai audit` — ראה [Audit CLI](/he/cli/audit) לקנס הסריקה הבסיס, דגלים נתמכים, וקביעות cache לפי תמליל. לוח הבקרה מטמון את התוצאה האחרונה ב־`~/.failproofai/audit-dashboard.json` (mode `0600`, משבצת יחידה, ריצות חדשות דורסות) כך שביקורים חוזרים מיידיים; **גם cache לפי תמליל וגם cache התוצאה הכוללת נדחו בקריאה ברגע שהם מעל 7 ימים** כך שלוח הבקרה לעולם לא משמש בשקט תוצאה בן שבוע — עבור TTL `/audit` נופל דרך למצב הריק שלו ומהנהן ריצה טרייה. לחיצה על `[ re-audit now ]` ליד תחתית הדוח POSTs `/api/audit/run` עם `noCache: true` — re-audit עוקף את cache לפי תמליל וסורק מחדש כל תמליל מאפס במקום להחזיר בשקט את התוצאה המטמונה — ולוח הבקרה פולל `/api/audit/status` ב־1Hz עד שהריצה מסתיימת; פס התקדמות ורוד דבוק מצמיד לחלק העליון של viewport במהלך הריצה עם טיימר שחלף, והתוצאה הטרייה מחליפה במקום בהצלחה (אין טעינה מחדש של עמוד מלא; re-audit כושל משאיר את הדוח הקודם בשלום). בכשל הרצועה הופכת אדומה עם העתקה מקשורה של ה־`RerunError.kind` (`timeout` / `network` / `post_failed`). מצב ריק (אין cache או פג) ומצב אפס-סשנים (cache קיים אך הסריקה לא מצאה תמליל) מוצגים בנפרד.

## ריענון אוטומטי

ללוח הבקרה יש הפעלה/השבתה של ריענון אוטומטי בניווט העליון. כאשר מופעל, העמוד הנוכחי מרעננן מעת לעת כדי להציג סשנים חדשים ופעילות מדיניות כאשר הם מופיעים. חיוני לניטור סשנים סוכנים אוטונומיים ארוכי טווח.

## השבתת דפים

אם אתה צריך רק חלקים מסוימים של לוח הבקרה, הגדר `FAILPROOFAI_DISABLE_PAGES` לרשימה מופרדת בפסיקים של שמות דפים:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

ערכים חוקיים: `policies`, `projects`, `audit`.

## הגדרת נתיב הפרויקטים

כברירת מחדל, לוח הבקרה קורא מספריית הפרויקטים של Claude Code הסטנדרטית. עקוף אותה להגדרות מותאמות:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## גישה מ־host שאינו localhost

כאשר פועל לוח הבקרה ב־**dev mode** (`npm run dev`) ונגישות אליו מ־hostname אחר מ־`localhost` — לדוגמה, דומיין מותאם אישית, IP מרחוק, או URL מנופה — ייתכן שתראה אזהרה כמו:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

זה Next.js חוסם גישה בחצייה של מקורות ל־HMR (hot module reload) websocket שלו, שהוא תכונה dev בלבד. כדי לאשר את ה־host שלך, השתמש בדגל `--allowed-origins`:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

עבור hosts או IPs מרובים, העבור רשימה מופרדת בפסיקים:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

אתה יכול גם להגדיר את משתנה סביבה `FAILPROOFAI_ALLOWED_DEV_ORIGINS` במקום זאת:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
זה חל רק על dev mode. כאשר פועל `failproofai` (production mode), אין websocket HMR ואין בעיית dev resource בחצייה של מקורות.
</Note>
