failproofai dashboard היא יישומת אינטרנט מקומית למעקב אחר סשנים של סוכני AI שלך וניהול מדיניות. ראה מה עשו הסוכנים שלך בזמן שלא היית כאן.

---

## הפעלת ה-Dashboard

```bash
failproofai
```

נפתח בכתובת `http://localhost:8020`.

ה-Dashboard קורא נתוני פרויקט, סשן ותצורת failproofai מקומיים ישירות מהמערכת הקבצים. תכונות מאומתות אופציונליות, כגון תזכורי ביקורת והזמנות, שולחות את המידע הדרוש לבקשות אלה (כולל כתובות דוא"ל) ל-API מרחוקים.

## עמודים

### Projects

מפרטת את כל פרויקטי Claude Code, OpenAI Codex, GitHub Copilot CLI _(beta)_, Cursor Agent _(beta)_, OpenCode _(beta)_, Pi _(beta)_, Hermes, OpenClaw, Factory Droid, Devin, Antigravity ו-Goose שנמצאו במחשבך. פרויקטי Claude מגוגלים מ-`~/.claude/projects/` (או הנתיב שהוגדר על ידי `CLAUDE_PROJECTS_PATH`); פרויקטי Codex מגוגלים על ידי סריקת כל תמלול תחת `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` וקיבוץ לפי ה-`cwd` שנרשם בשיא הראשון של כל סשן; פרויקטי Copilot CLI מגוגלים על ידי סריקת כל `~/.copilot/session-state/<sessionId>/workspace.yaml` (שניתן לתצורה דרך `COPILOT_HOME`) וקיבוץ לפי שדה ה-`cwd` שלו; פרויקטי Cursor Agent מגוגלים על ידי סריקת מטא-נתונים לסשן תחת `~/.cursor/agent-sessions/<sessionId>/` (שניתן לתצורה דרך `CURSOR_HOME`, עם `conversations/` ו-`sessions/` מחוקרים כחלופות) ל-`cwd` סקלרי ב-`meta.json` / `session.json` / `workspace.yaml`; פרויקטי OpenCode מגוגלים על ידי שאילתה ל-SQLite DB שלו ב-`~/.local/share/opencode/opencode.db` דרך `opencode db --format json` (אנחנו קוראים את טבלאות `session` ו-`project` וקיבוץ לפי `project_id`); פרויקטי Pi מגוגלים על ידי סריקת תמלולי JSONL לסשן תחת `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` (שניתן לתצורה דרך `PI_SESSIONS_DIR`) וקלט ה-`cwd` מהשיא הראשון של כל סשן; סשנים של Hermes gateway נקראים ישירות מחנות ה-SQLite של כל פרופיל — `~/.hermes/state.db` בתוספת `~/.hermes/profiles/<name>/state.db` (עשוי להיות ברידוק דרך `HERMES_HOME` או `HERMES_DB_PATH` לבסיס נתונים יחיד) — וקיובצו לפרויקטים `hermes-<profile>-<source>` לפי פרופיל ו-`source` (Slack/Telegram/cli/cron — סשנים של gateway אין להם cwd); סשנים של OpenClaw gateway נקראים מ-`~/.openclaw/agents/<agentId>/sessions/*.jsonl` וקיובצו לפרויקטים `openclaw-<agentId>-<channel>` לפי סוכן וערוץ (גם cwd-less); פרויקטי Factory Droid מגוגלים מתמלולי JSONL ב-`~/.factory/sessions/<encoded-cwd>/*.jsonl` וקיובצו לפי cwd; פרויקטי Devin מה-SQLite DB שלו ב-`~/.local/share/devin/cli/sessions.db` (קיובצו לפי `working_directory` של כל סשן); פרויקטי Antigravity מתמלולי JSONL ב-`~/.gemini/antigravity-cli/brain/<conversationId>/…/transcript_full.jsonl` וקיובצו לפי cwd; ופרויקטי Goose מה-SQLite DB שלו ב-`~/.local/share/goose/sessions/sessions.db` (קיובצו לפי `working_dir` של כל סשן). פרויקט ששימש בו מספר CLI מתוך עצמו כשורה יחידה עם כל התגים התואמים. השתמש בתפריט **CLI** מעל הטבלה לסינון לפי CLI של סוכן ספציפי; ה-URL שומר את הבחירה שלך כ-`?cli=claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose`.

Hermes ו-OpenClaw הם בתחום המשתמש ואין להם ספריית עבודה לקיבוץ לפיה, לכן הם מתוך כ-**עץ תיקיה מתקפל** — פרופיל (או סוכן) בקצה העליון, הערוצים שלו תחתיו — בעוד שכל CLI מבוסס-cwd נשאר שורה שטוחה. שורות תיקיה מלפופות ספירת הסשן והפעילות האחרונה ביותר של הכל תחתיהן, תיקיות מכופפות זכורות בין ביקורים, וחיפוש מילות מפתח מרחיב כל מה שהוא תואם.

כל פרויקט מציג:
- שם פרויקט (נגזר מנתיב התיקיה)
- תג CLI — `Claude Code` (כתום), `OpenAI Codex` (סגול), `GitHub Copilot` (כחול), `Cursor Agent` (ירוק), `OpenCode` (ענבר), `Pi` (ורוד), ו/או `Hermes` (אינדיגו)
- תאריך של הפעילות האחרונה בסשן

לחץ על פרויקט כדי לראות את הסשנים שלו.

### Sessions

מפרטת את כל הסשנים בתוך פרויקט. כל סשן מציג:
- מזהה סשן
- חותמות זמן התחלה וסיום
- מספר קריאות כלים
- ספירת פעילות hook (מדיניות שהוציאו)

השתמש בסינון טווח התאריכים וחיפוש מזהה סשן כדי לצמצם את הרשימה. סשנים מעדפויים.

לחץ על סשן כדי לפתוח את צופה הסשן.

### Session viewer

צופה הסשן עונה על השאלה המפתח לסוכנים אוטונומיים: מה עשה הסוכן, והאם הוא נשאר בעקבות? תג CLI ליד הכותרת מעיד אם הסשן הוא תמלול Claude Code, OpenAI Codex, GitHub Copilot CLI, Cursor Agent, OpenCode, Pi, Hermes, OpenClaw, Factory Droid, Devin, Antigravity או Goose. זה מציג ציר הזמן של כל מה שקרה בסשן:

- **Messages** - תגובות טקסט של Claude והנושאות של משתמשים
- **Tool calls** - כל כלי שקרא Claude, עם הקלט והפלט שלו
- **Policy activity** - לכל קריאת כלים, אילו מדיניות הוציאו ואיזו החלטה הם החזירו

סרגל הנתונים בחלקו העליון מציג משך סשן, סה"כ קריאות כלים ודוח סיכום של החלטות hook (ספירות allow / deny / instruct).

לחץ על הכפתור **Download Logs** כדי לייצא את הסשן. לסשנים Claude Code, Codex, Copilot, Cursor ו-Pi אתה מקבל את תמלול JSONL המקורי על-הדיסק בייט-לייט; לסשנים OpenCode (שהסשנים שלו חיים ב-SQLite, לא בדיסק) אתה מקבל מסמך JSON המשקף את טבלאות `session` / `messages` / `parts` הבסיסיות.

### Audit

דוח מנוסח אישיות כיצד הסוכן שלך התנהג בפועל לאחר סשנים קודמים. מפעיל את אותה הסריקה כמו CLI `failproofai audit` אך מעניק אותה כמו כרזה חד-מסך משתפת + ארבע קטעים מתחת לקיפול:

1. **Poster** — ממלא את תצוגת הנמל הראשונה. אזור לכידה בעצמו PNG עם הסימון failproof_ai + תווית ביקורת · אינדקס אַרכִיטִיפּוּס (`№ NN of 08`) + תאריך ביקורת · ניקוד מספרי (0–100) + כדור דרגת אחוזון (`top 15%`) · שם האַרכִיטִיפּוּס (אחד מ-`the optimist`, `the cowboy`, `the explorer`, `the goldfish`, `the paranoid architect`, `the precision builder`, `the hammer`, `the ghost`) + רצועת 3-מילות מפתח · `// only N% of agents are this archetype` שורת רידות · אריח סיגיל 8×8 פיקסל · `audit yours → failproof.ai` תחתית. שלושה כפתורי שיתוף יושבים מחוץ לתיבת הלכידה: `post your archetype` (כוונת X), `share on linkedin`, `download poster`. הלכידה עוברת דרך `html-to-image` כך ש-PNG תואם את העל-מסך מכל פיקסל (גבולות מקווקוים, מסיכת לוגו SVG, מעברים, מטרי גופנים — הכל שמור).
2. **Strengths** — רשימת שורות רגועה ✓ של התנהגויות שהסוכן שלך כבר עושה נכון, הנגזרת מנתוני הביקורת החיים (שיעור קריאת כלים נקי, אין דחיפות ישירות לראשי, אפס דליפות אישור, אפס סערות ניסיון חוזר) — כל אחד מסופח רק כשלמדיניות הרלוונטית יש רקורד נקי על פני חלון הביקורת.
3. **Quirks** — טבלה של מה שחמק, דורג לפי חומרה: `when · what slipped + the policy that would've caught it · severity pill · seen`, כאשר הישיבה חוזרת קורא `new` (פעם אחת), `N× seen` (2–9 פעמים) או `recurring` (10+).
4. **How to improve** — רשימת שורות רגועה, אחת לכל מדיניות שנקבעה: שם מדיניות לבן, תיאור שורה אחת, פקודת התקנה + כפתור העתקה בצד ימין. כותרת הסעיף קורא `enable all N → projected <score> · <tier>` (הניקוד שתגיע אליו עם כל תיקון שיושם), וה-`[install all]` שלו כפתור העתקות את הפקודה `failproofai policy add a b c …` משולבת לכל מדיניות שנקבעה.
5. **Come back better** — שתי כרטיסים זה לצד זה. שמאל: קבע תזכורת (בורר קדנס `3d` / `7d` / `14d` / `30d`; מתמיד דרך `/api/auth/reminder` כשמואמת). ימין: פתח ללא נעילה perks failproof — `invite a friend` פותח מודאלי שלוקח רשימת דוא"ל של חברים מופרדת בפסיקים/רווחים/שורה חדשה (מקסימום 10 לשליחה), עמיתות אותם ל-`/api/audit/invite`, שהם להעביר ל-`POST /v0/invite` של api-server. api-server שולח דוא"ל אחד לכל נמען מ-`invite@failproof.ai` עם השולח Cc'd וה-`Reply-To` קבוע, כך שהנמען רואה מי הזמין אותם והשולח מקבל עותק בתיבת הדואר שלו. משתמשים אנונימיים מופנים דרך ה-`AuthDialog` תחילה כדי שהדוא"ל של השולח ידוע לפני שההזמנות יוצאות. זכאות / השלמת perks היא המשך.

מונע על ידי הזמן ריצה של `failproofai audit` — ראה [Audit CLI](/he/cli/audit) לקצה סריקה בסיסי, דגלים נתמכים וקביעות מטמון לתמלול. ה-Dashboard משמור את התוצאה האחרונה ב-`~/.failproofai/audit-dashboard.json` (מצב `0600`, חריץ יחיד, ריצות חדשות דורסות) כדי שביקורים חוזרים תוך מיידיים; **גם מטמון התמלול לכל-תמלול וגם תוצאה כוללת נדחים בקריאה כשהם ישנים מ-7 ימים** כדי שה-Dashboard לעולם לא יעזוב שקט תוצאה בן שבועות — בעבר ה-TTL `/audit` נופלת דרך מצבו הריק שלה ומנויים ריצה טרייה. לחיצה `[ re-audit now ]` ליד תחתית הדוח POST `/api/audit/run` עם `noCache: true` — ביקורת חוזרת מתעקף מטמון התמלול לכל-תמלול וסורקים כל תמלול שוב מאפס במקום שקט החזרת התוצאה בקופסה — וה-Dashboard סקרים `/api/audit/status` ב-1Hz עד שהריצה מסתיימת; רצועת התקדמות ורודה דביקה מצייתת לחלקו העליון של תצוגת השומר במהלך הריצה עם טיימר שחלף, והתוצאה טרייה מחליפה במקום בהצלחה (אין טעינה מחדש של עמוד מלא; ביקורת חוזרת נכשלת משאירה את הדוח הקודם בשלום). בכישלון הרצועה הופכת אדומה עם העתקה מקושרת ל-`RerunError.kind` (`timeout` / `network` / `post_failed`). מצב ריק (אין מטמון או פקיעה) ומצב אפס-סשנים (מטמון קיים אבל הסריקה לא מצאה תמלולים) משטחים בנפרד.

## Auto-refresh

ל-Dashboard יש הגדרה auto-refresh בניווט עליון. כשמופעל, העמוד הנוכחי מרענן בתדירות כדי להציג סשנים חדשים ופעילות מדיניות כאשר הם מופיעים. הכרחי למעקב סשנים סוכנים אוטונומיים ארוכי ריצה.

## השבתת עמודים

אם אתה זקוק רק לחלקים מסוימים של ה-Dashboard, קבע `FAILPROOFAI_DISABLE_PAGES` לרשימה מופרדת פסיקים של שמות עמודים:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

ערכים תקפים: `policies`, `projects`, `audit`.

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## גישה מ-non-localhost host

בעת הפעלת ה-Dashboard **dev mode** (`npm run dev`) וגישה אליו מ-hostname אחר מ-`localhost` - למשל, דומיין מותאם, IP מרחוק, או URL מינהור — ייתכן שתראה אזהרה כמו:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

זה Next.js חסימה גישה cross-origin ל-HMR שלו (hot module reload) websocket, שהוא תכונה dev-only. כדי לאפשר את ה-host שלך, השתמש בדגל `--allowed-origins`:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

עבור מספר hosts או IPs, עבור רשימה מופרדת פסיקים:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

אתה יכול גם קבע את משתנה הסביבה `FAILPROOFAI_ALLOWED_DEV_ORIGINS` במקום:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
זה חל רק על dev mode. בעת הפעלת `failproofai` (production mode), אין websocket HMR ואין בעיה משאב dev cross-origin.
</Note>
