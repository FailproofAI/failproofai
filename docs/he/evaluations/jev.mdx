הערכת Jev קוראת **סשן שהסתיים** ותוחזרת ניקוד בין 0 ל-1. השתמש בה כאשר התשובה ידועה מראש, כמו "האם הלקוח הביע דחיפות?" או "כמה היה הלקוח תסכול?" היא עוזרת למצוא דפוסים על פני ריצות; היא לא עוצרת קריאת כלי. לקבלת החלטות שנעשו **לפני** שכלי מתבצע, השתמש ב-[מדיניות Jev](/he/policies/jev).

## צור אחת בלוח הבקרה

1. פתח **analyse → checks → new evaluation** ובחר **decision model** תחת **how should it score?**.
2. תאר שאלה אחת ותשובותיה האפשריות. לדוגמה: "האם הסוכן הבטיח החזר כספי לפני בדיקת מדיניות ההחזרים? ענה כן או לא." בעמוד **review**, בדוק את **השאלה** ומה **כן אומר** ו**לא אומר**; מודל החלטה תמיד נותן ניקוד.
3. [נסה זאת](/he/evaluations/test) על סשנים אחרונים, ואז [פרוס אותה](/he/evaluations/deploy). סשנים שהסתיימו חדשים מקבלים ניקוד; [מלא אחורה](/he/evaluations/deploy#score-sessions-you-already-have) אם אתה גם צריך היסטוריה.

![טופס כתיבת ההערכה המשותפת, שבו אתה מתאר שאלה בתשובה קבועה, בודק את הטיוטה, ופורס לאחר בדיקה. הדוגמה המוצגת היא הערכת קוד; שאלת Jev משתמשת באותה זרימת כתיבה.](/images/dashboard/eval-authoring-draft.png)

כאשר היא משרטטת, failproof יכול לבחור בין **code**, **decision model** (Jev), ו-[**llm as judge**](/he/evaluations/judge). בדוק את הבחירה שלו לפני פריסה. Jev נותן ניקוד ללא נימוקי פרוזה; בחר שופט כשאתה צריך הסבר. ראה את [הפניה להערכת Jev](/he/reference/jev-evaluations) לסוגי שאלות וגבולות ניקוד.

## קרא את הניקודים

פתח **analyse → checks → evals** ובחר בהערכה כדי לתרשים את התוצאה לפי סוכן וזמן. מטרמינל, ה-Cloud CLI יכול לקרוא את אותן תוצאות:

```bash
fp evals --since 7d
fp evals --aggregate --since 7d
```

מטרמינל, `fp evaluators` מחבר ופורס הערכות Jev ו-`fp evals` קורא את התוצאות שלהן. ראה את [הפניה Cloud CLI](/he/reference/cloud-cli#evaluations) לשניהם.
