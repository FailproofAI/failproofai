הערכת Jev קוראת **סשן שהושלם** ומעניקה ציון בין 0 ל-1. השתמש בה כאשר התשובה ידועה מראש, כגון "האם הלקוח הביע דחיפות?" או "כמה מתוסכל היה הלקוח?" זה עוזר לך למצוא דפוסים על פני הרצות; זה לא עוצר קריאה לכלי. לצורך החלטות שנתקבלו **לפני** הרצת כלי, השתמש ב-[מדיניות Jev](/he/policies/jev).

## צור אחד בלוח הבקרה

1. פתח **analyse → checks → new evaluation** ובחר **decision model** תחת **how should it score?**.
2. תאר שאלה אחת ותשובותיה האפשריות. לדוגמה: "האם הסוכן הבטיח להחזיר כסף לפני בדיקת מדיניות ההחזרים? ענה כן או לא." ב-**review**, בדוק את **question** ומה **yes means** ו-**no means**; מודל החלטה תמיד מעניק ציון.
3. [נסה את זה](/he/evaluations/test) בסשנים אחרונים, ואז [פרוס אותו](/he/evaluations/deploy). סשנים שהושלמו חדשים מקבלים ציון; [מלא רקע](/he/evaluations/deploy#score-sessions-you-already-have) אם אתה צריך גם היסטוריה.

![טופס תיקייה משותפת להרכבת הערכה, שבו אתה מתאר שאלה בתשובה קבועה, בודק את הטיוטה ופורס לאחר בדיקה. הדוגמה המוצגת היא הערכת קוד; שאלת Jev משתמשת בזרימת תיקייה זהה.](/images/dashboard/eval-authoring-draft.png)

כאשר זה משדרג, failproof יכול לבחור בין **code**, **decision model** (Jev), ו-[**llm as judge**](/he/evaluations/judge). בדוק את הבחירה שלו לפני הפריסה. Jev מעניק ציון ללא נימוק בפרוזה; בחר שופט כאשר אתה צריך הסבר. ראה את [התייחסות הערכת Jev](/he/reference/jev-evaluations) לסוגי שאלות וגבולות ציון.

## קרא את הציונים

פתח **analyse → checks → evals** ובחר בהערכה כדי לתרגם את התוצאה לפי סוכן וזמן. מטרמינל, ה-Cloud CLI יכול לקרוא את אותן תוצאות:

```bash
fp evals --since 7d
fp evals --aggregate --since 7d
```

מטרמינל, `fp evaluators` מחבר ופורס הערכות Jev ו-`fp evals` קוראת את התוצאות שלהם. ראה את [התייחסות Cloud CLI](/he/reference/cloud-cli#evaluations) לשניהם.
