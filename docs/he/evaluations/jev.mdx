הערכת Jev קוראת **סשן שהסתיים** ותותנה ציון מ-0 עד 1. השתמש בה כאשר התשובה ידועה מראש, כמו "האם הלקוח הביע דחיפות?" או "כמה מאוכזב היה הלקוח?" זה עוזר לך למצוא דפוסים על פני ריצות; זה לא עוצר קריאת כלי. לקבלת החלטות שנעשו **לפני** הפעלת כלי, השתמש ב-[Jev policies](/he/policies/jev).

## צור אחת בדשבורד

1. פתח את **Analyze → eval authoring** והבחר **new eval**.
2. תאר שאלה אחת וההתשובות האפשריות שלה. לדוגמה: "האם הסוכן הבטיח החזרת כספים לפני בדיקת מדיניות ההחזרות? ענה כן או לא." בחר **draft** וסקור שהתוצאה היא ציון מסווג.
3. [בדוק זאת](/he/evaluations/test) בסשנים אחרונים, לאחר מכן [הפרוס אותה](/he/evaluations/deploy). סשנים שהסתיימו חדשים מקבלים ציון; [מלא את ההיסטוריה](/he/evaluations/deploy#score-sessions-you-already-have) אם אתה צריך גם נתונים קודמים.

![טופס authoring eval משותף, שם אתה מתאר שאלה בעלת תשובה קבועה, בודק את הטיוטה והמפיץ לאחר בדיקה. הדוגמה המוצגת היא הערכת קוד; שאלת Jev משתמשת בזרימת authoring זהה.](/images/dashboard/eval-authoring-draft.png)

העוזר יכול לבחור בין קוד, סיווג Jev ו-[judge](/he/evaluations/judge). בדוק את הבחירה שלו לפני הפרוס. Jev נותן ציון ללא נימוק בעל משמעות; בחר judge כאשר אתה צריך הסבר. ראה את [reference הערכות Jev](/he/reference/jev-evaluations) לסוגי שאלות וגבולות ציון.

## קרא את הציונים

פתח את **Observe → Evaluations** כדי לתרשים את התוצאה לפי סוכן וזמן. מטרמינל, Cloud CLI יכול לקרוא את אותן התוצאות:

```bash
fp evals --since 7d
fp evals --aggregate --since 7d
```

Cloud CLI קורא תוצאות; authoring והפרוס מתרחשים בדשבורד. ראה את [Cloud CLI reference](/he/reference/cloud-cli#evaluations) לסננים.
