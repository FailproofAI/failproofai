הערכת Jev קוראת **סשן סיום** ותותנת ניקוד בין 0 ל-1. השתמש בה כאשר התשובה ידועה מראש, כמו "האם הלקוח הביע דחיפות?" או "כמה מתוסכל היה הלקוח?" זה עוזר לך למצוא דפוסים על פני הרצות; זה לא עוצר קריאת כלי. בעבור החלטות שנעשות **לפני** הרצת כלי, השתמש ב-[מדיניות Jev](/he/policies/jev).

## יצור אחד בלוח הבקרה

1. פתח **Analyze → eval authoring** ובחר **new eval**.
2. תאר שאלה אחת ותשובותיה האפשריות. לדוגמה: "האם הסוכן הבטיח החזר כסף לפני בדיקת מדיניות ההחזרים? ענה כן או לא." בחר **draft** וסקור שהתוצאה היא ניקוד מסווג.
3. [בדוק אותו](/he/evaluations/test) בסשנים אחרונים, ואז [הצבת אותו](/he/evaluations/deploy). סשנים חדשים שהושלמו מקבלים ניקוד; [מלא בחזרה](/he/evaluations/deploy#score-sessions-you-already-have) אם אתה צריך גם היסטוריה.

![טופס אימות Eval משותף, שבו אתה מתאר שאלה בתשובה קבועה, משוחזר את הטיוטה ומצבת אחרי בדיקה. הדוגמה המוצגת היא הערכת קוד; שאלת Jev משתמשת בזרימת אימות זהה.](/images/dashboard/eval-authoring-draft.png)

העוזר יכול לבחור בין קוד, סיווג Jev, ו-[שופט](/he/evaluations/judge). בדוק את הבחירה שלו לפני הצבה. Jev נותן ניקוד ללא נימוקים בפרוזה; בחר שופט כאשר אתה צריך הסבר. ראה את [ייחוס הערכת Jev](/he/reference/jev-evaluations) עבור סוגי שאלות ומגבלות ניקוד.

## קרא את הניקודים

פתח **Observe → Evaluations** כדי לתרשים את התוצאה לפי סוכן וזמן. מטרמינל, Cloud CLI יכול לקרוא את אותן התוצאות:

```bash
fp evals --since 7d
fp evals --aggregate --since 7d
```

Cloud CLI קורא תוצאות; אימות והצבה מתרחשים בלוח הבקרה. ראה את [ייחוס Cloud CLI](/he/reference/cloud-cli#evaluations) עבור מסננים.
