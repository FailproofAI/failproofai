## דרישות

- **Node.js** >= 20.9.0
- **Bun** >= 1.3.0 (אופציונלי - נדרש רק לבניה מקוד מקור)

---

## התקנה

<CodeGroup>

```bash npm
npm install -g failproofai
```

```bash bun
bun add -g failproofai
```

</CodeGroup>

## התחלה מהירה

<Steps>
  <Step title="הפעל מדיניויות">
    מדיניויות הן כללים שרצים לפני ואחרי כל קריאת כלי של אג'נט. הם תופסים פקודות הרסניות, דליפות סודות ומצבי כשל אחרים לפני שהם גורמים נזק.

    ```bash
    failproofai policies --install
    ```

    הפקודה זו כותבת ערכי hook לתוך ממשקי ה-CLI של האג'נט המותקנים (Claude Code ל`~/.claude/settings.json`, OpenAI Codex ל`~/.codex/hooks.json`, GitHub Copilot CLI ל`~/.copilot/hooks/failproofai.json`, Cursor Agent ל`~/.cursor/hooks.json`, OpenCode לשימת ה-plugin שנוצרה ב`~/.config/opencode/plugins/failproofai.mjs` בתוספת ערך רישום במערך `plugin` של `~/.config/opencode/opencode.json`, Pi ל`~/.pi/agent/settings.json`, Hermes ל`~/.hermes/config.yaml`, OpenClaw ל`~/.openclaw/openclaw.json`, Factory Droid ל`~/.factory/hooks.json`, Devin CLI ל`~/.config/devin/config.json`, Antigravity CLI ל`~/.gemini/config/hooks.json`, או תיקיית ה-plugin שגוגל גילתה באופן אוטומטי של Goose ב`~/.agents/plugins/failproofai/hooks/hooks.json`). כאשר יותר מאחד קיים, תוביל לשאלה; העבר `--cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose` (כל תת-קבוצה) כדי לדלג על השאלה.

    GitHub Copilot CLI, Cursor Agent, OpenCode, ו-Pi תמך הוא **beta** — התקן עם `--cli copilot`, `--cli cursor`, `--cli opencode`, או `--cli pi`. Hermes (hermes-agent, שער Slack/Telegram) מתקין בתחום משתמש עם `--cli hermes` והוא **גם** מקור ביקורת לא מקוון. OpenClaw (שער openclaw, עוזר רב-ערוצי מסודר עצמאי) מתקין בתחום משתמש עם `--cli openclaw` — אכיפה פועלת דרך hook-י plugin שלו בתוך התהליך (`before_agent_finalize` הוא שער סיום תור אמיתי, כך שה-`require-*-before-stop` המובנים אוכפים) — והוא **גם** מקור ביקורת לא מקוון. Factory Droid (`droid`) מתקין עם `--cli factory` (תחום משתמש + פרויקט) והוא **גם** מקור ביקורת לא מקוון. Devin CLI (`devin`, Cognition) מתקין עם `--cli devin` (תחום משתמש + פרויקט) והוא **גם** מקור ביקורת לא מקוון. Antigravity CLI (`agy`) מתקין עם `--cli antigravity` (תחום משתמש + פרויקט) והוא **גם** מקור ביקורת לא מקוון. Goose (שם קוד goose, Block) מתקין עם `--cli goose` (תחום משתמש + פרויקט) — המתקין פשוט משחרר תיקיית plugin ב`~/.agents/plugins/failproofai/` שהוא Goose מגלה באופן אוטומטי, והוא **גם** מקור ביקורת לא מקוון.

    ```bash
    failproofai policies --install --scope project
    failproofai policies --install --cli codex --scope project
    failproofai policies --install --cli copilot --scope project
    failproofai policies --install --cli cursor --scope project
    failproofai policies --install --cli opencode --scope project
    failproofai policies --install --cli pi --scope project
    failproofai policies --install --cli hermes --scope user
    failproofai policies --install --cli openclaw --scope user
    failproofai policies --install --cli factory --scope project
    failproofai policies --install --cli devin --scope project
    failproofai policies --install --cli antigravity --scope project
    failproofai policies --install --cli goose --scope project
    failproofai policies --install block-sudo block-rm-rf sanitize-api-keys
    ```
  </Step>
  <Step title="אמת">
    ```bash
    failproofai policies
    ```

    מציג כל מדיניות, האם היא מופעלת, וכל פרמטרים שהוגדרו.
  </Step>
  <Step title="הפעל את לוח הבקרה">
    ```bash
    failproofai
    ```

    פותח לוח בקרה מקומי ב`http://localhost:8020` שבו אתה יכול לרשום הפעלות, לבדוק קריאות כלים, ולנהל מדיניויות.
  </Step>
  <Step title="הפעל את האג'נט שלך">
    הפעל את Claude Code כרגיל. אם האג'נט מנסה משהו מסוכן, failproofai יחסום אותו באופן אוטומטי. השאר אותו רץ ללא השגחה ובדוק מה קרה בלוח הבקרה.
  </Step>
</Steps>

## כיצד מדיניויות עובדות

בכל פעם שאג'נט מפעיל כלי, Claude Code קורא ל-failproofai כ-subprocess:

```text
Claude Code  →  failproofai --hook PreToolUse  →  קורא JSON מ-stdin
                                                 מעריך מדיניויות
                                                 כותב החלטה ל-stdout
```

כל מדיניות מחזירה אחת משלוש החלטות:

- **allow** - האג'נט ממשיך בדרך רגילה
- **deny** - הפעולה חסומה, לאג'נט מסברים למה
- **instruct** - הקשר נוסף מוסף להנחיות של האג'נט

<Note>
מדיניויות רצות בתהליך המקומי שלך. שום דבר לא נשלח לשירות מרוחק.
</Note>

## הגדר מדיניויות קבוצתיות עם מדיניויות מבוססות על קונבנציה

הדרך המהירה ביותר לעיצוב תקנים איכות על פני הקבוצה שלך היא הקונבנציה `.failproofai/policies/`. הניח קבצי מדיניויות בתיקייה זו והם יטענו באופן אוטומטי — ללא דגלים, ללא שינויי הגדרה, ללא פקודות התקנה.

<Steps>
  <Step title="צור את תיקיית המדיניויות">
    ```bash
    mkdir -p .failproofai/policies
    ```
  </Step>
  <Step title="הוסף קבצי מדיניויות">
    העתק דוגמאות התחלה או כתוב שלך:

    ```bash
    cp node_modules/failproofai/examples/convention-policies/*.mjs .failproofai/policies/
    ```

    או צור חדש:

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Run tests before committing.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="אשר ל-git">
    ```bash
    git add .failproofai/policies/
    git commit -m "Add team quality policies"
    ```

    כל חברי הקבוצה שיש להם failproofai מותקן יבחרו את המדיניויות הללו באופן אוטומטי. אין צורך בהגדרה לפי מפתח.
  </Step>
</Steps>

<Tip>
אשר את `.failproofai/policies/` למאגר שלך כדי שכל הקבוצה תחלוק את אותם התקנים. כאשר הקבוצה שלך גילתה מצבי כשל חדשים, הוסף מדיניויות והדחף — כולם מקבלים את העדכון ב-`git pull` הבא שלהם. לאורך זמן המדיניויות הללו הופכות לתקן איכות חי השומר ובשיפור מתמיד.
</Tip>

## אחסון נתונים

כל התצורה והיומנים נשמרים על המכונה שלך:

| נתיב | מה הוא מאחסן |
|------|----------------|
| `~/.failproofai/policies/local-policies/policies-config.json` | תצורת מדיניות גלובלית |
| `~/.failproofai/hook-activity/` | היסטוריית הבצוע של hook (JSONL בעמודים) |
| `~/.failproofai/logs/` | יומנים לניפוי שגיאות לשגיאות hook מותאמות |
| `.failproofai/policies-config.json` | תצורה לכל פרויקט (מאושרת) |
| `.failproofai/policies-config.local.json` | עקיפות אישיות (ב-gitignore) |

---

## הסרה

```bash
failproofai policies --uninstall
```

מסיר ערכי hook מ`~/.claude/settings.json`. קבצי הגדרה ב`~/.failproofai/` נשמרים.
