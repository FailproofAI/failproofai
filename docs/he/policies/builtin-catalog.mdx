38 מתוך 39 המדיניויות המובנות מסופקות כחבילת `FailproofAI/policies`; `block-failproofai-commands` משלחה כקומפילציה לתוך החבילה מכיוון שחבילה לא עשויה להכריז על `alwaysOn`. החבילה המותקנת היא מקור האמת עבור מה שמכונה זו יכולה להטיל:

```bash
failproofai policies show FailproofAI/policies   # the catalog, as published
failproofai policies                             # what is enabled here
```

`failproofai policies` מפרטת קבצים מותאמים אישית, קבצי קונוונציה, חבילות מותקנות והקצאות Cloud. אין לה סעיף מובנה, כך שהיא לא יכולה לענות על "אילו מובנות קיימות" — `policies show` וה-[Policy Hub](https://befailproof.ai/policy-hub/FailproofAI/policies/) הם המקום שבו שאלה זו מתובררת.

## ברירות מחדל, וכיצד לבחור

`failproofai policies add FailproofAI/policies` בסיסי מפעיל את ברירות המחדל של החבילה עצמה — 10 השורות המסומנות **on** להלן. `block-failproofai-commands` פועל בכל מקרה ואינו חלק מאותה בחירה. `--all` לוקח הכול; `--category <slug>` ו-`--policy <name>` לוקחים פרוסה. ה-slug ליד כל כותרת הוא מה ש-`--category` תואם:

```bash
failproofai policies add FailproofAI/policies --category git,database
```

`block-failproofai-commands` היא **תמיד on**. היא נרשמת בכל הערכה בין אם היא מופיעה בבחירתך או לא, ולא ניתן להשבית או להשהות אותה — שומר כנגד הסוכן שמכבה את ההטלה שהסוכן יכול להכבות אינו שומר. חבילה לא עשויה להכריז על `alwaysOn`, וזו הסיבה שמדיניות זו משלחה כקומפילציה לתוך החבילה במקום בחבילה.

## Sanitize — `sanitize`

אלה פועלות על `PostToolUse`, לאחר שהכלי כבר רץ. הן **מזהות ומסרבות לתוצאת הכלי**; הן לא מעדכנות תת-מחרוזת ומוחזרות חזרה את השאר.

סירוב כאן מגיע אל המודל רק על ההרנסות שצורכות `PostToolUse` verdict — **codex** ו-**copilot**, כאשר הסיבה מחליפה את כל תוצאת הכלי. על claude, cursor, opencode, pi, hermes, openclaw, factory, devin, antigravity וgoose, `PostToolUse` היא observe-only: הגילוי נרשם ופלט עדיין מגיע למודל.

| מדיניות | הדק | ברירת מחדל | תוצאה |
| --- | --- | --- | --- |
| `sanitize-jwt` | `PostToolUse` | on | סירוב תוצאת כלי המכילה JWT. |
| `sanitize-api-keys` | `PostToolUse` | on | סירוב תוצאת כלי המכילה OpenAI, Anthropic, GitHub, AWS, Stripe או Google key. |
| `sanitize-connection-strings` | `PostToolUse` | on | סירוב תוצאת כלי המכילה מחרוזת חיבור מסד נתונים עם אישורים משובצים. |
| `sanitize-private-key-content` | `PostToolUse` | on | סירוב תוצאת כלי המכילה תוכן PEM private-key. |
| `sanitize-bearer-tokens` | `PostToolUse` | on | סירוב תוצאת כלי המכילה token `Authorization: Bearer`. |

## Workflow — `workflow`

כל חמש פועלות על `Stop` וכבויות כברירת מחדל.

| מדיניות | ברירת מחדל | תוצאה |
| --- | --- | --- |
| `require-commit-before-stop` | off | סירוב השלמה בזמן שעבודה מעקב נשארת uncommitted. |
| `require-push-before-stop` | off | סירוב השלמה בזמן שcommits נשארים local-only. |
| `require-pr-before-stop` | off | דרוש pull request עבור הענף הנוכחי. |
| `require-no-conflicts-before-stop` | off | דרוש merge נקי כנגד ענף base מוגדר. |
| `require-ci-green-before-stop` | off | דרוש שCI checks על current HEAD commit יעברו, מתעלמים משליטות cured על prior commits. |

אלה צריכות harness שלה `Stop` verdict צורך. זה לא כל harness:

| Harness | `Stop` |
| --- | --- |
| claude, codex, copilot, cursor, openclaw, factory, devin, antigravity | מאומת לחסום: סירוב כפה turn נוסף |
| pi | Observe. הסיבה מובאת לתוך ה-turn הבא כהוראה, לא כ-gate |
| goose, hermes | אין `Stop` hook מותקנת, כך שחמש אלה לעולם לא עלויות |
| opencode | לא מאומת. `Stop` אינו בין האירועים opencode צורך verdict מ |

Cursor Cloud Agent VMs אינם מריצים stop hooks בכלל, כך שסשן Cursor שם אינו מכוסה למרות שLocal Cursor אינו.

<Note>
  `warn-*` המדיניויות מחזירות `instruct`, לא `deny`. (`prefer-package-manager` היא החריג בין non-`block-*` שמות: היא מחזירה `deny`, כך שהיא חוסמת בכל harness שצורך `PreToolUse` verdict — שהוא כל שנים עשר.) על Hermes ו-Goose, על Pi, OpenClaw ו-Factory מחוץ לערוץ `Stop`, וב-Antigravity מחוץ `Stop` ו-`UserPromptSubmit`, `instruct` משתנה לallow בתוספת הערה על stderr — הסוכן לא מובח. `UserPromptSubmit` של Antigravity היא ערוץ שני אמיתי: ההוראה מוזרקת כהודעה זמנית לפני שהמודל רץ.
</Note>

## ייחוס הפרמטרים

הגדר פרמטרים תחת `policyParams` object של ההיקף שנבחר. סוגים מאומתים על ידי כל מדיניות.

| מדיניות | פרמטר | סוג וברירת מחדל |
| --- | --- | --- |
| `sanitize-api-keys` | `additionalPatterns` | `pattern[]`, `[]`; entries contain `regex` and `label` |
| `block-read-outside-cwd` | `allowPaths` | `string[]`, `[]` |
| `block-sudo` | `allowPatterns` | `string[]`, `[]` |
| `block-rm-rf` | `allowPaths` | `string[]`, `[]` |
| Infrastructure blockers | `allowPatterns` | `string[]`, `[]` |
| `block-secrets-write` | `additionalPatterns` | `string[]`, `[]` |
| `block-push-master` | `protectedBranches` | `string[]`, `["main", "master"]` |
| `block-work-on-main` | `protectedBranches` | `string[]`, `["main", "master"]` |
| `prefer-package-manager` | `allowed`, `blocked` | `string[]`, `[]` |
| `warn-large-file-write` | `thresholdKb` | `number`, `1024` |
| `require-push-before-stop` | `remote`, `baseBranch` | `string`, `"origin"`; `string`, `"main"` |
| `require-pr-before-stop` | `baseBranch` | `string`, `"main"` |
| `require-no-conflicts-before-stop` | `baseBranch` | `string`, `"main"` |

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status"]
    },
    "block-push-master": {
      "protectedBranches": ["main", "release"]
    }
  }
}
```

<Note>
  שם מדיניות בסיס כמפתח `policyParams` מוכר עבור `FailproofAI/policies` בלבד. עבור כל חבילה אחרת המפתח הוא `pack/<owner>/<repo>/<policy>` — החבילה של זר המכריזה על אותו שם מדיניות מקבלת את ברירות המחדל של הסכימה, לא את הפרמטרים שלך.
</Note>

<Warning>
  דפוס allow מרחיב את מה שסוכן עלול לעשות. בדוק את tokenization מדויק וגרסאות פקודה על ה-target harness לפני פריסה על פני fleet.
</Warning>
