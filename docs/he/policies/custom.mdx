צור קובץ המסתיים ב-`policies.js`, `policies.mjs`, או `policies.ts` תחת `.failproofai/policies/`. קבצי קונוונציה נטענים באופן אוטומטי בהיקף פרויקט והיקף משתמש.

## בדוק את המדיניות לפני פרסום בענן

<Tabs>
  <Tab title="לוח בקרה">
    1. התקן את המדיניות המותאמת אישית על מכונת בדיקה אחת וזַעזע גם פעולה תואמת וגם אי-התאמה לגיטימית.
    2. עבור אל **Observe → policy** והשווה בין שתי ההחלטות.
    3. פתח כל סשן מקושר ודרג שמטען האירוע מכיל מספיק ראיות עבור הכלל.
    4. כאשר ההתנהגות נכונה, העבר את הקוד שנבדק אל **Admin → policy editor** ופרסם גרסה.

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies --install --custom ./security.policies.ts \
      --cli claude --scope project
    failproofai policies
    ```

    קבצי קונוונציה תחת `.failproofai/policies/` נטענים ללא `--custom`. שמור על פקודת התקנה מפורשת ב-CI כאשר אימות צריך להיכשל על מודול שבור.
  </Tab>
</Tabs>

```ts
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "protect-production-paths",
  description: "Block writes to production configuration",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Write" && ctx.toolName !== "Edit") return allow();
    const path = String(ctx.toolInput?.file_path ?? "").replaceAll("\\", "/");
    if (path.split("/").includes("production")) {
      return deny("Writes to production configuration require approval.");
    }
    return allow();
  },
});
```

זה תואם ל-`production/config.yml`, `/srv/production/config.yml`, `/srv/production`, ו-`C:\\production\\config.yml` עבור `Write` ו-`Edit`. זה לא תואם לשמות כמו `production-backup` מכיוון ש-`production` חייב להיות קטע נתיב שלם.

אמת והתקן קובץ מפורש:

```bash
failproofai policies --install --custom ./security.policies.ts
```

הקשר של המדיניות כולל סוג האירוע, מטען מנורמל, שם וקלט כלי, מטא-נתוני סשן, פרמטרים, ו-CLI מקור כאשר זמין.

## בדוק נתיבי כישלון

הרץ אימות לאחר שינוי קובץ הכניסה או כל מודול מקומי שהוא מייבא:

```bash
failproofai policies --install --custom ./security.policies.ts --scope project
```

נתיב CLI קפדני נכשל עבור קבצים חסרים, שגיאות תחביר, ייבוא שלא פתור, חריגים ברמה עליונה, וזמני תם הטעינה של מודול. בזמן אכיפה, קובץ מותאם אישית שבור מוקד ומדולג כך שמדיניויות מובנות יכולות להמשיך. התייחס לכל אזהרת טעינה כאובדן של אכיפה צפויה והנפק התראה בה בקופה רישום ייצור.

השתמש בשמות ייחודיים גלובלית בכל המדיניויות המפורשות, הקונוונציה, וניהול ענן. שמור על פונקציות מדיניות דטרמיניסטיות, קשור קריאות חיצוניות בזמני פקיעה קצרים, והחזר `allow`, `instruct`, או `deny` בכוונה בכל נתיב.

<Warning>
  מדיניות מותאמת אישית היא קוד אכיפה. בדוק שדות חסרים, שמות כלים חלופיים, וקלט מעוות—לא רק התאמה צפויה.
</Warning>
