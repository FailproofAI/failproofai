הצגה מחברת גרסת מדיניות אחת או יותר לקבוצת כלי המחשבים המנויים המיועדים.

## החלת הצגה

<Tabs>
  <Tab title="Dashboard">
    1. עבור ל- **Admin → enforcement**, מצא את כלי המחשב והרחב את השורה שלו.
    2. בחר ב- **edit**, הוסף את גרסת המדיניות שנבדקה, ובחר ב- **observe** או בהשפעת ההאכיפה שלו.
    3. החל את השינוי, ואז חכה לבדיקה הבאה של כלי המחשב וודא את מצב ההצגה והכיסוי שלו.
    4. עבור ל- **Observe → policy** לבדיקת החלטות חיות.

    ![עורך הצגת כלי המחשב עם גרסות מדיניות, השפעות enforce ו- observe, וביצוע הפעולה של הצגה.](/images/dashboard/enforcement-editor.png)
  </Tab>
  <Tab title="CLI">
    נקודות קצה של הצגה בענן אינן חשופות בכוונה כפקודות `fp` רגילות. בדוק את כלי המחשב באופן מקומי, ואז הצג דרך לוח המחוונים:

    ```bash
    failproofai config --status
    ```

    השתמש ב- `fp sessions --env production --since 24h` וב- `fp events --event-type hook_completed` אחרי ההצגה לאימות שפעילות מגיעה ל- Cloud.
  </Tab>
</Tabs>

<Steps>
  <Step title="בחר את הגרסה והיעדים">
    הצג גרסה שנבדקה, לא טיוטה הניתנת לשינוי, החל מכלי מחשב שאינו בייצור או קוהורטה קטנה שאתה יכול לבדוק את ההפעלות שלה.
  </Step>
  <Step title="בדוק החלטות">
    בדוק התאמות, סיבות, כלים מושפעים וחיוביים שווא ללא חסימת עבודה.
  </Step>
  <Step title="אכוף ואמת כיסוי">
    קדם לאחר התאמות שנצפו הפרדות בין פעולות לא בטוחות לפעולות תקפות, ואז אשר שלכל כלי מחשב המיועד הורדה ההצגה ודיווח החלטות.
  </Step>
</Steps>

כלי המחשב זקוקים ליכולת `policies:pull`. דיווח אירועים נשלט בנפרד על ידי `events:add`; אמת את שניהם כאשר אתה מצפה לניתוח וניהול אכיפה בענן.

<Warning>
  ניהול אכיפה הוא זרימת עבודה בענן מנהלית. אל תתייחס לנתבי אכיפה בעלי הרשאות root בלבד כנקודות קצה רגילות `/v1` API של הלקוח.
</Warning>
