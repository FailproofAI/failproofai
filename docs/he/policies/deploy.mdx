פריסה מחברת גרסה אחת או יותר של מדיניות לקבוצת מטרה של מכונות רשומות.

## החל פריסה

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Admin → enforcement**, חפש את המכונה והרחב את השורה שלה.
    2. בחר **edit**, הוסף את גרסת המדיניות שנבדקה, ובחר **observe** או את אפקט האכיפה שלה.
    3. החל את השינוי, ואז המתן לבדיקת הבאה של המכונה ואשר את מצב הפריסה והכיסוי שלה.
    4. עבור אל **Observe → policy** כדי לבדוק החלטות חיות.

    ![עורך פריסת המכונה עם גרסאות מדיניות, אפקטי enforce ו-observe, וקטע הפעולה של החלת פריסה.](/images/dashboard/enforcement-editor.png)
  </Tab>
  <Tab title="CLI">
    בצע פריסה מהשורת הפקודה באמצעות `fp fleet`. בדוק את הסט המתקבל לפני החלתו — `deploy` מדפיס את התוכנית המלאה וביקשת **רק בטרמינל אינטראקטיבי ללא `--json`**. תחת `--json`, עם `--yes`, או עם stdin מועבר (שלב CI, סקריפט, agent המריץ פקודות) היא מיושמת מיד ללא תוכנית ללא הודעה — אז הרץ תחילה `fp fleet show <machine>` אם אתה רוצה בדיקה:

    ```bash
    fp fleet list
    fp fleet show <machine-id>
    fp fleet deploy <machine-id> --add no-force-push
    ```

    `fp fleet diff <machine-id>` מציג כוונה לעומת הובלה (מכונה קוראת כ-`behind` עד שהיא תשאול בפעם הבאה), `fp fleet history <machine-id>` מפרט את הדורות, ו-`fp fleet rollback <machine-id> <generation>` משחזר אחד — היא מסרבת אם אותו דור שם מדיניות מאז משוקללת או מחוקה.

    בדוק את המכונה עצמה באמצעות `failproofai config --status`, והשתמש ב-`fp sessions --env production --since 24h` ו-`fp events --event-type hook_completed` לאחר הפריסה כדי לאמת שפעילות מגיעה ל-Cloud.
  </Tab>
</Tabs>

<Steps>
  <Step title="בחר את הגרסה והמטרות">
    בצע פריסה של גרסה שנבדקה, לא טיוטה הניתנת לשינוי, החל ממכונה שאינה בייצור או קוהורטה קטנה שאת ההפעלות שלה אתה יכול לבדוק.
  </Step>
  <Step title="צפה בהחלטות">
    בדוק התאמות, סיבות, כלים המושפעים והחיוביים שליליים ללא חסימת עבודה.
  </Step>
  <Step title="אכיפה ואימות כיסוי">
    קדם לאחר התאמות שנצפו להפריד פעולות בלתי בטוחות מעשויות תקפות, ואז אשר שכל מכונה מיועדת משכה את הפריסה ודיווחת על החלטות.
  </Step>
</Steps>

מכונות זקוקות ליכולת `policies:pull`. דיווח אירועים נשלט בנפרד על ידי `events:add`; אמת את שניהם כאשר אתה מצפה לניתוח Cloud ואכיפה.

<Warning>
  ניהול אכיפה הוא זרימת עבודה מנהלית של Cloud. אל תתייחס לנתיבי אכיפה רק-שורש כנקודות קצה API רגילות של `/v1` הלקוח.
</Warning>
