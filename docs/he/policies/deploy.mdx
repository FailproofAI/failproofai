פריסה מחברת גרסה אחת או יותר של מדיניות אל קבוצת מטרה של מכונות רשומות.

## החלת פריסה

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Admin → enforcement**, חפש את המכונה והרחב את השורה שלה.
    2. בחר **edit**, הוסף את גרסת המדיניות שנבדקה, ובחר **observe** או את השפעתה האכיפה.
    3. החל את השינוי, ולאחר מכן חכה להתחברות הבאה של המכונה והשלם את מצב הפריסה וההסתרה שלה.
    4. עבור אל **Observe → policy** לבדיקת החלטות חיות.

    ![עורך פריסת המכונה עם גרסאות מדיניות, השפעות enforce ו-observe, וההרשאה החלת פריסה.](/images/dashboard/enforcement-editor.png)
  </Tab>
  <Tab title="CLI">
    נקודות קצה של פריסה בענן אינן חשופות כוונה כפקודות `fp` רגילות. בדוק את המכונה באופן מקומי, ואז פרוס דרך לוח הבקרה:

    ```bash
    failproofai config --status
    ```

    השתמש ב-`fp sessions --env production --since 24h` וב-`fp events --event-type hook_completed` לאחר הפריסה כדי לאמת שפעילות מגיעה לענן.
  </Tab>
</Tabs>

<Steps>
  <Step title="בחר את הגרסה והיעדים">
    פרוס גרסה שנבדקה, לא טיוטה הניתנת לשינוי, החל ממכונה שאינה production או קוהורט קטן שאתה יכול לבדוק את הסשנים שלו.
  </Step>
  <Step title="התבונן בהחלטות">
    בדוק התאמות, סיבות, כלים מושפעים והחיוביות כוזבות ללא חסימת עבודה.
  </Step>
  <Step title="אכיפה וביקורת כיסוי">
    הרם לאחר התאמות שנצפו הפרדת פעולות בלתי בטוחות מעל פעולות תקפות, ואז אשר שלכל מכונה מיועדת הורדה את הפריסה ודיווחה החלטות.
  </Step>
</Steps>

מכונות זקוקות ליכולת `policies:pull`. דיווח אירועים נשלט בנפרד על ידי `events:add`; אמת את שניהם כאשר אתה מצפה לניתוח וכיפוי בענן.

<Warning>
  ניהול כיפוי הוא זרימת עבודה בענן מינהלית. אל תתייחס לנתיבים אכיפה בלבד root כאל נקודות קצה API `/v1` רגילות של לקוח.
</Warning>
