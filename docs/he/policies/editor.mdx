השתמש בעורך המדיניויות כדי להפוך ממצא או בעיה לכלל הניתן להטמעה. שמור על הפרדה בין יצירת מדיניות להטמעה כך שטיוטה לא תוכל שינוי שקט בהתנהגות בתחום הפעול.

כאשר לבעיה יש דפוס פעולה חוזר, פתח אותה תחת **Analyze → issues** ובחר **generate policy**. Failproof AI מסביר תחילה האם מדיניות יכולה להביע את הבעיה, ואז מעביר את הכוונה המתוקנת והקשר המציאות לעורך. המקור שנוצר נשאר טיוטה עד שתפרסם אותו.

## פרסום גרסת מדיניות

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Admin → policy editor** ובעמודת **compose**, תאר את מצב הכשל או הדבק את מקור ה-JavaScript policy.
    2. אמת את המקור ותקן כל שגיאה שדווחה.
    3. הזן את זהות המדיניות ופרסם אותה, לאחר מכן השתמש ב-**library** כדי להשוות או להשבית גרסאות.
    4. בחר **enforcement** כאשר הגרסה מוכנה לפרישה בתוך המכונה.

    ![תצוגת הרכבה של עורך המדיניויות עם זהות מדיניות, טיוטה בסיוע AI, אימות מקור, ובקרי פרסום.](/images/dashboard/policy-editor.png)
  </Tab>
  <Tab title="CLI">
    פרסם מ-CLI באמצעות `fp policies publish`. זה יוצר **גרסה חדשה** ולעולם לא עורך אחת במקום, והוא בודק ניתוח מקור עם node לפני השליחה — שום דבר בהמשך לא עושה זאת, כך ששגיאת תחביר הייתה מופיעה אחרת במכונה בזמן הטמעה:

    ```bash
    fp policies test ./checkout.policy.mjs --command "git push --force" --expect deny
    fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
    ```

    פרסום לא מטמיע דבר — גרסה חדשה יושבת ללא שימוש עד ש-`fp fleet deploy` מניחה אותה במכונה. `fp policies compose "<plain English>"` יוצרת טיוטת מקור בעזרת Cloud assistant והדפסה אותה לבדיקה ולא מפרסמת אותה.

    כדי להתקין מדיניות לתוך agent CLI מקומי במקום זאת (לא Cloud), השתמש ב-`failproofai policies --install --custom ./checkout.policies.ts --cli claude --scope project`.
  </Tab>
</Tabs>

## רשימת בדיקה של יצירה

1. שם את מצב הכשל בשפה תפעולית.
2. בחר את אירועי ה-hook והכלים המכילים ראיות מספיקות להחלטה.
3. כתוב את התנאי הצר ביותר התואם להתנהגות לא בטוחה.
4. החזר סיבה שמספרת לסוכן או למפעיל מה לעשות בשלב הבא.
5. הוסף דוגמאות שצריכות להתאים ודוגמאות שחייבות להישאר מותרות.
6. שמור גרסה חדשה וביקש ביקורת.

השתמש ב-`instruct` כאשר הסוכן יכול בתוקף תיקון הקורס. השתמש ב-`deny` כאשר ההתרת הפעולה תיצור סיכון בלתי קביל או בלתי הפיך.

<Info>
  גרסאות מדיניות הן קלטי פריסה בלתי שינויים. עריכת טיוטה יוצרת גרסה חדשה; היא לא צריכה לשכתב את הגרסה שכבר הוקצתה למכונות.
</Info>
