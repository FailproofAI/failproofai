לאחר ההתקנה, השירות `failproofaid` המקומי הוא ההערך היחיד. אם הוא לא יכול לענות, פעולות מוגנות מדוחות במקום להיות מורשות בשקט.

## אבחון חסימה כוללת של המכונה

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

הריץ `failproofai config` כדי לתקן את השירות או להתקין את הגרסה המתאימה.

שני כשלונות יכולים להיראות דומים:

| כשלון | משמעות |
| --- | --- |
| Service unreachable | לשקע אין מערכת הערכה עובדת מאחוריו |
| Version mismatch | ה-CLI והשירות חלוקים בדעתם לגבי הפרוטוקול |

שניהם דוחים, אך דוחות מצב מדווחים אותם בנפרד.

## חבילה לא תיטען

חבילה שנבחרה שחסרה, שונתה או לא תקינה דוחה את האירועים המכוסים על ידי המדיניויות שלה שנבחרו. זה מונע מחבילה שבורה להיעלם בזמן שהמכונה נראית מוגנת.

`failproofai policies` מציין את החבילה ואת שגיאת הטעינה.

```bash
failproofai policies
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

מטא-נתונים בלתי קריאים מרחיבים את הדחיית הבטיחות במקום לצמצם אותה מנתונים שלא ניתן היה להם לסמוך.

## מה נשאר זמין

לוח המחוונים המקומי ופקודות המצב עדיין עובדים בזמן שהערכת המדיניות נכשלת. השתמש בהן כדי לזהות את השירות, החבילה או הגרסה שזקוקה לתיקון.

<Warning>
  אל תעקוף החלטת כשלון-סגור על ידי מחיקת קבצי שירות או חבילה. תקן את השירות, התקן מחדש את החבילה, או הסר את ההקצאה דרך ה-CLI כדי שהמכונה תחזור למצב ידוע.
</Warning>
