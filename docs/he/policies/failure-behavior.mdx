Failproof AI מעוצב כך שכשל בהטמעה יהיה גלוי במקום לאפשר בשתיקה עבודה מסוכנת.

## אבחון בלוק סגור כשלון

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Admin → enforcement** ופתח את המכונה.
    2. בדוק את ה-check-in האחרון שלה, ההפצה שהוקצתה וההפצה שדווחה.
    3. עבור אל **Observe → policy** ופתח את הסשן של ההחלטה המסורבת.
    4. אשר אם הסיבה דווחת על נגישות daemon, גרסה skew, או המדיניות עצמה.

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    npm install -g failproofai@latest
    failproofai config
    ```

    הפעלה חוזרת של `failproofai config` מעדכנת ומפעילה מחדש את ה-daemon לאחר שדרוג חבילה.
  </Tab>
</Tabs>

על מכונה המוגדרת לשימוש ב-`failproofaid`, ה-daemon הוא הערכן היחיד. אם הוא אינו נגיש או שגרסת הפרוטוקול שלו אינה תואמת ל-CLI, הערכת hook נכשלת סגורה. הפעולה מסורבת עם סיבה המנחה את המפעיל לבדוק או לעדכן את ה-daemon.

לפני תצורת daemon, hooks מעריכות מדיניות בתהליך. ברגע שתצורת daemon נרשמת, Failproof AI לא חוזרת בשתיקה למעריך שני כאשר ה-daemon נכשל.

## הגב להחלטה סגורה כשלון

1. הפעל `failproofai config --status`.
2. אם גרסאות שונות, הפעל מחדש את `failproofai config` לאחר עדכון החבילה.
3. אם ה-daemon אינו נגיש, בדוק את מצב השירות שלו ורישומים מקומיים.
4. חזור לעבודת agent רק לאחר שנתיב הערכת מדיניות ידוע הוא בריא.

<Warning>
  אל תנסה שוב ושוב את הפעולה הממונעת. תגובה סגורה כשלון פירושה שהמערכת לא יכלה לקבוע שהפעולה הייתה בטוחה.
</Warning>
