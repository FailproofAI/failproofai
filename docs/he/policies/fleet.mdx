כיסוי הצי עונה על השאלה האם קיימת מדיניות במקום שבו הסיכון קיים. עקוב אחר מכונות לפי מזהה יציב ותווית קריאה לאדם, ואז השווה את מצב הפריסה המוקצה והדווח שלהן.

## בדוק כיסוי

<Tabs>
  <Tab title="Dashboard">
    1. עבור לעמוד **Admin → enforcement** וסקור את סכומי האכיפה והתצפית.
    2. חפש מכונה לפי מזהה או תווית, או סנן עבור מכונות חסרות מדיניות.
    3. הרחב שורה כדי להשוות בין מדיניות מוקצאות, פריסה דווחת, בדיקת כניסה אחרונה והיסטוריה.
    4. רענן לאחר מרווח הסקר של המכונה כאשר פריסה מיושמת נשארת בהמתנה.

    ![הצי Enforcement המציג כיסוי מדיניות, מצב פריסת מכונה, והקצאות צפייה ואכיפה.](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    השתמש ב-`fp events --agent-id <agent-id> --since 24h` כדי לאשר שפעילות הסוכן של המכונה מגיעה ל-Cloud.
  </Tab>
</Tabs>

השתמש בתצוגות כיסוי כדי למצוא:

- מכונות שמעולם לא משכו את הפריסה העדכנית
- מכונות רשומות שהפסיקו לדווח על פעילות
- מדיניות שהוקצתה לסביבה או קוהורט שגויים
- סחיפה גרסה לאחר עדכון שהופרע

שנה שם של מכונה ללא חיבור מחדש:

```bash
failproofai config --machine-label checkout-runner-03
```

בדוק מצב מקומי:

```bash
failproofai config --status
```

<Tip>
  השתמש בתוויות המזהות עומס עבודה וסביבה. שמות מארחים לבדם לעתים קרובות אינם מספקים לאחר auto-scaling או החלפת מכונה.
</Tip>
