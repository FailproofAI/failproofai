כיסוי הצי עונה על השאלה האם מדיניות קיימת כאשר הסיכון קיים. עקוב אחר מכונות באמצעות מזהה יציב ותווית קריאה-בנושא, ואז השווה את מצב ההפעלה שהוקצה להם לעומת זה שדוּוח.

## בדוק כיסוי

<Tabs>
  <Tab title="Dashboard">
    1. לך אל **Admin → enforcement** וסקור את סכומי האכיפה והתצפית.
    2. חפש מכונה לפי מזהה או תווית, או סנן מכונות שחסרה להן מדיניות.
    3. הרחב שורה כדי להשוות בין מדיניויות שהוקצו, הפעלה שדוּוחה, בדיקה אחרונה, והיסטוריה.
    4. רענן לאחר מרווח הסקר של המכונה כאשר פריסה שהוחלה נותרה בהמתנה.

    ![צי Enforcement המציג כיסוי מדיניות, מצב פריסה של מכונה, ו הקצאות צפייה ואכיפה.](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    השתמש ב `fp events --agent-id <agent-id> --since 24h` כדי לאשר שפעילות הסוכן של המכונה מגיעה ל Cloud.
  </Tab>
</Tabs>

השתמש בתצוגות כיסוי כדי למצוא:

- מכונות שלעולם לא משכו את הפריסה האחרונה
- מכונות רשומות שהפסיקו לדווח על פעילות
- מדיניות שהוקצתה לסביבה או קוהורטה שגויה
- סחיפת גרסה לאחר עדכון שנקטע

שנה שם של מכונה ללא חיבור מחדש:

```bash
failproofai config --machine-label checkout-runner-03
```

בדוק מצב מקומי:

```bash
failproofai config --status
```

<Tip>
  השתמש בתוויות המזהות עומס עבודה וסביבה. שמות מחשב בלבד לעתים קרובות אינם מספקים לאחר הגדלת קנה מידה או החלפת מכונה.
</Tip>
