Failproof AI מפריד בין בחירת מדיניות לבין הגדרות מכונה ותהליך רקע. זה שומר על בחירות מדיניות של מאגר כדי להיות ניתנות לבדיקה בעוד שתעודות אישור וסטטוס התהליך נשארים מחוץ למאגר.

## בחר סקופ מדיניות

<Tabs>
  <Tab title="Dashboard">
    הרץ `failproofai` ללא ארגומנטים כדי לפתוח את לוח הבקרה של המדיניות המקומית. בחר סקופ של משתמש, פרויקט או מקומי לפני הפעלת מדיניות כך שהשינוי יכתב לקובץ התצורה המיועד.

    - **User** חל על פני פרויקטים במכונה זו.
    - **Project** שייך למאגר ויכול להיות מחויב.
    - **Local** מחליף פרויקט אחד עבור משתמש אחד ויש להישאר ב-gitignore.

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-rm-rf --scope user
    failproofai policy add block-force-push --scope project
    failproofai policy add warn-large-file-write --scope local
    failproofai policies
    ```

    לא כל התקנה תומכת בסקופ מקומי. ה-CLI דוחה סקופ שהתקנה נבחרת לא יכולה לייצג.
  </Tab>
</Tabs>

| סקופ | קובץ תצורת מדיניות |
| --- | --- |
| Project | `<project>/.failproofai/policies-config.json` |
| Local | `<project>/.failproofai/policies-config.local.json` |
| User | `~/.failproofai/policies-config.json` |

מדיניויות מופעלות מתמזגות כאיחוד. פרמטרי מדיניות משתמשים בסקופ הראשון המגדיר פרמטרים עבור אותה מדיניות, בסדר project → local → user. נתיבי מדיניות מותאמים אישית מפורשים משתמשים בסקופ הראשון המגדיר אותם.

## הגדר פרמטרי מדיניות

<Tabs>
  <Tab title="Dashboard">
    פתח את המדיניות בלוח הבקרה המקומי, ערוך את הפרמטרים הנתמכים שלה, והשמר בסקופ הנבחר. הרץ פעולת סוכן תואמת ולא תואמת, ואז בדוק את ההחלטה ב-**Observe → policy**.

  </Tab>
  <Tab title="CLI">
    ערוך את `policies-config.json` של הסקופ הנבחר, ואז הרץ `failproofai policies` כדי להציג שמות מדיניות או מפתחות פרמטרים לא ידועים.

    ```json
    {
      "enabledPolicies": ["block-rm-rf", "block-force-push"],
      "policyParams": {
        "block-rm-rf": {
          "allowPaths": ["/tmp/build-output"]
        }
      }
    }
    ```

    ```bash
    failproofai policies
    ```
  </Tab>
</Tabs>

## הבן את קובצי המכונה

`~/.failproofai` מכיל קבצים נפרדים עבור גבולות אמון נפרדים:

| נתיב | מטרה |
| --- | --- |
| `config.json` | הגדרות תהליך רקע, ביקורת וטלמטריה שאינן סודיות |
| `credentials.json` | תעודות אישור בענן; מאוחסנות עם הרשאות בעלים בלבד |
| `policies-config.json` | בחירת בנייה בסקופ משתמש, פרמטרים ונתיבים מותאמים אישית מפורשים |
| `policies/` | מדיניויות קונוונציה משתמש ותיקיות מדיניות מנוהלות בענן |
| `hook-activity/` | יומן החלטות מדיניות מקומי |
| `state/` | תהליך רקע, בריאות, השהייה וסטטוס ריצה |

השתמש ב-`FAILPROOFAI_HOME` כדי להעביר את פריסת המכונה המלאה עבור קונטיינר או בדיקה מבודדת. אל תעביר ספריות מצב בודדות באופן עצמאי.

<Warning>
  לעולם אל תחייב `credentials.json`. חייב תצורת מדיניות של פרויקט ומדיניויות קונוונציה של פרויקט רק לאחר סקירתם כקוד אכיפה.
</Warning>
