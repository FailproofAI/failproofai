מדיניות מراقבת פעולת סוכן והחזרת אחד משלוש החלטות:

- `allow` ממשיך.
- `instruct` נותן הדרכה לסוכן כאשר ההרמס שלו תומך בה.
- `deny` חוסם את הפעולה.

השתמש במדיניויות לתנהגות ידועה וחוזרת: מחיקת קבצים מוגנים, חשיפת סודות, דחיפה לענף הלא נכון, או שינוי תשתית ייצור.

## הוסף מדיניויות למכונה זו

ההגדרה לא בוחרת חבילת מדיניות. הוסף את חבילת Failproof AI לאחר ההגדרה:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai policies
```

החבילה אינה מכילה חבילה משובצת בעלת הרשאות. שלנו מותקנת באותו אופן כמו של כל אחד אחר.

מדיניויות יכולות גם לבוא מקובץ מקומי, חבילה פורסומת, או השמה בענן:

| מקור | הוסף אותה |
| --- | --- |
| קובץ מקומי | הצב `*policies.{js,mjs,ts}` תחת `.failproofai/policies/` |
| כל נתיב קובץ | `failproofai policies -i -c <path>` |
| חבילה פורסומת | `failproofai policies add <owner>/<repo>` |
| ענן | הקצה זאת בלוח המחוונים או עם `fp fleet deploy` |

`block-failproofai-commands` תמיד פועל ולא ניתן להשבית אותו. הוא עוצר סוכן מהשבתת האכיפה שלו.

## התבוננות לפני אכיפה

מצב התבוננות מריץ את המדיניות האמיתית ורושם מה היא הייתה עושה, אך אינו חוסם את הסוכן.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

<Warning>
  `fp fleet deploy <machine> --add <id>` חוסר קוד מכפה מיד. הוסף `:observe` לגלגול צל.
</Warning>

מדיניות שחוקה בתוך מצב התבוננות רושמת התרה, מכיוון זה מה שיקרה בעת אכיפה. רק החלטות בתבוננות שאינן התרה מתועדות.

לחבילה המשמשת ללא ענן, פרסם אותה עם `failproofai publish --effect observe`.
