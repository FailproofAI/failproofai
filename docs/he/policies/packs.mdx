חבילת מדיניות היא ערכה בגרסה של מדיניויות שפורסמה כ-release ציבורי ב-GitHub. החבילה אינה משלחת חבילה משלה; התקן את שלנו כמו כל חבילה אחרת:

```bash
failproofai policies show FailproofAI/policies
failproofai policies add FailproofAI/policies
```

`show` קורא את ה-manifest ללא הרצת קוד החבילה.

## בחר מה להתקין

```bash
failproofai policies add owner/repo --policy block-refunds
failproofai policies add owner/repo --category billing,git
failproofai policies add owner/repo --all
```

ללא בחירה, החבילה משתמשת בברירות ברירת המחדל של המוציא לאור שלה. הוספה מחדש של release חדש יותר שומר את הבחירה הקיימת שלך.

כל דבר עם slash הוא מקור חבילה. כל דבר ללא slash הוא שם מדיניות.

## הצמד release

| מקור | תוצאה |
| --- | --- |
| `owner/repo` | Release החדש ביותר, מוצמד לאחר החלטה |
| `owner/repo@a1b2c3d4e5f6` | Release מבוסס-commit מדויק |
| `owner/repo@v2.1.0` | Release בעל שם מדויק |
| כתובת URL של GitHub release | ה-release בכתובת URL זו |

חבילה בדרך כלל משתמשת ב-SHA commit בן 12 תווים שעליו היא נבנתה. השתמש ב-`failproofai policies show owner/repo --releases` כדי לראות סדר release.

## ניהול חבילות מותקנות

```bash
failproofai policies
failproofai policies remove block-refunds
failproofai policies add block-refunds
failproofai policies remove owner/repo
```

אם שתי חבילות מותקנות מכילות את אותו שם מדיניות, ה-CLI מסרב לשם ישן שאינו בר-הבחנה. בחר את המדיניות דרך חבילה אחת או הסר התקנה של החבילה השנייה.

## בטיחות וזמינות

כל release מכיל manifest, קוד מדיניות מקופל, ו-checksums. Failproof AI מוודא את ה-digest המוקלט לפני הטעינה. Checksums מוכיחים שהבתים תואמים את ה-release; הם אינם מוכיחים מי פרסם אותו.

חבילה שנבחרה שלא יכולה להטען נכשלת בצורה סגורה לאירועים שהיא הצהירה עליהם. ראה [התנהגות כשל מדיניות](/he/policies/failure-behavior).

| משתנה | השפעה |
| --- | --- |
| `FAILPROOFAI_NO_DOWNLOAD=1` | סרב להורדות חדשות; חבילות מותקנות ממשיכות לפעול |
| `FAILPROOFAI_PACK_BASE_URL` | השתמש במראה |
| `FAILPROOFAI_PACK_DIR` | הזז את חנות החבילות |

עיין בחבילות ב-[Policy Hub](https://befailproof.ai/policy-hub/) או [פרסם את שלך](/he/policies/publish-a-pack).
