צרו מדיניות שעובדת, בדקו אותה בקומה המקומית, ואז פרסמו אותה כחבילה.

## יצירה ובדיקה

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

`--init` כותב מדיניות שכבר חוסמת `git push --force`. ערכו אותה, בקשו מהסוכן שלכם לנסות את הפעולה החסומה, ובדקו את **Policies → Activity** בלוח הבקרה המקומי.

חבילת מדיניות יכולה להכיל:

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-refunds",
  description: "Refunds above the limit need a human",
  category: "Billing",
  defaultEnabled: true,
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) => {
    // return allow(), instruct(), or deny()
  },
});
```

`defaultEnabled` מוגדר כברירת מחדל ל-`false`.

## פרסום

קמקמו את הקבצים שלכם, ואז הריצו:

```bash
failproofai publish
```

Publish מוצא את קובץ המדיניות, מאמת אותו עם אותו טוען המשמש בזמן ההתקנה, ועולה את נכסי החבילה לשחרור ב-GitHub. הוא משתמש ב-`GITHUB_TOKEN`, `GH_TOKEN`, או `gh auth login`.

המאגר חייב להיות ציבורי מכיוון שהתקנה משתמשת ב-HTTPS אנונימי.

הגרסה המוגדרת כברירת מחדל היא ה-SHA של 12 תווים של הקומיט הנוכחי. Publish מסרב לעץ מלוכלך או לתיקייה מחוץ ל-Git אלא אם כן אתם מספקים `--version`. תג ב-`HEAD` מנצח על פני ה-SHA.

משתמשים מתקינים זאת עם:

```bash
failproofai policies add owner/repo
```

## פרסום במצב התבוננות

```bash
failproofai publish --effect observe
```

מצב התבוננות מעריך את המדיניות האמיתית ורושם החלטות שאינן allow, אך מאפשר לסוכן להמשיך. זמן קצוב רושם כ-allow.

פרסמו שוב עם `--effect enforce` כאשר ההתאמות שנצפו נכונות.

## אפשרויות שימושיות

| דגל | אפקט |
| --- | --- |
| `--init [file]` | כתוב מדיניות התחלה |
| `--repo <owner>/<repo>` | בחרו או צרו את המאגר |
| `--version <version>` | שכתבו את הגרסה המבוססת על קומיט |
| `--effect enforce|observe` | בחרו אם החבילה חוסמת |
| `--dry-run` | בנו ואמתו ללא פרסום |
| `--allow-private` | פרסמו באופן פרטי, בידע ש-`policies add` לא יכול להתקין זאת |

```bash
failproofai publish --dry-run
failproofai publish ./guards.mjs --repo me/guards --version 2.0.0
```

<Note>
  הוסיפו את נושא GitHub `failproofai-policies` לאחר הפרסום כדי שה-[Policy Hub](https://befailproof.ai/policy-hub/) יוכל לאינדקס את החבילה. ה-CLI לא מגדיר זאת עבורכם.
</Note>

<Warning>
  שינוי שם של מדיניות הוא שינוי משבר עבור בחירות קיימות. שמרו על שמות יציבים בין הוצאות.
</Warning>
