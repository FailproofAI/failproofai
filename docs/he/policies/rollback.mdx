חזרה לגרסה קודמת משנה את הגרסה הפרוסה או מסירה הקצאת מדיניות; היא לא מוחקת את היסטוריית ההחלטות המסבירה את התקרית.

## חזרה לגרסה קודמת של מכונה

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Admin → enforcement**, הרחב את המכונה המושפעת וזהה את מערך המדיניות הטוב האחרון הידוע שלה.
    2. בחר **edit**, שחזר את הגרסאות והאפקטים הללו, והחל את הפריסה החדשה.
    3. המתן לתשדור המכונה, ואז אמת את הפריסה שדווחה.
    4. פתח **Observe → policy** וגם את הסשנים המושפעים כדי לאשר שעבודה תקינה כבר לא חסומה.

  </Tab>
  <Tab title="CLI">
    מצא את הדור שלפיו חוזרים, החזר אותו בתוקף, ואז אשר שהוא הגיע ליעדו:

    ```bash
    fp fleet history ci-runner-01
    fp fleet rollback ci-runner-01 3
    fp fleet diff ci-runner-01
    failproofai config --status
    ```

    `fp fleet rollback` יוצר דור **חדש** הנושא את מערך העתיק במקום לסובב לאחור את המונה, כך שההיסטוריה נשארת append-only. היא מסרבת אם דור זה מציין מדיניות שנוטרלה או נמחקה מאז — השרת אומר זאת ולא משחזר מערך שלא ניתן להעביר.

    `fp fleet diff` מציג כוונה לעומת הסגה. מכונה נקראת כסטייה עד שהיא שוב כן משוכללת, לכן בדוק את ההבדל לפני שאתה מסיק שהחזרה לא התקבלה. `failproofai config --status` מאשר זאת במכונה עצמה.
  </Tab>
</Tabs>

## הפסקה היא לא חזרה לגרסה קודמת

הפסקה משעה כל מדיניות שותקנת מקומית ל**סשן יחיד**, ותמיד פקעה מעצמה — pack, קבצים מותאמים, קבצי קונוונציה ו-builtins כמו כן. רק מדיניויות מנוהלות בענן והשומר התמידי `block-failproofai-commands` ממשיכים לאכוף. אז הפסקה היא לא דרך עקיפה לפריסת ענן רעה, וזו רדיוס פיצוץ רחב יותר ממה שזה נראה: pack היא המקום בו בעצם כל ההגנה המקומית חיה, ושומר ה-pack fail-closed מדולג לזמן ההפסקה.

| פקודה | השפעה |
|---|---|
| `failproofai config --pause` | סשן הסוכן העדכני ביותר בדירקטוריה זו, 30 דקות |
| `failproofai config --pause 10m` | זמן נתון. מקסימום 8 שעות; סיומת `s`/`m`/`h`, מספר חסר משמעות דקות |
| `failproofai config --pause --session <id>` | מטרה סשן ספציפי |
| `failproofai config --resume` | סיים את ההפסקה מוקדם |
| `failproofai config --resume --all` | סיים כל הפסקה פעילה |
| `failproofai config --status` | מה מושהה ומתי זה מסתיים |

## מתי לחזור לגרסה קודמת

- מדיניות חוסמת פעולת ייצור צפויה.
- נפח ההתאמה גבוה באופן מהותי מהרולאוט שנצפה צפה.
- מדיניות תלויה בשדות שאינטגרציה לא מספקת.
- גרסה חדשה משנה התנהגות מחוץ למצב הכישלון הרצוי.

לאחר חזרה לגרסה קודמת, פתח את הסשנים המושפעים וזהה את התנאי שגרם לחיוב חיובי שגוי. צור גרסה חדשה, בדוק גם את המקרה הבלתי בטוח והגיטימי באופן מקומי, ואז עבור בחזרה דרך observe לפני שאתה אוכף שוב:

```bash
fp policies test ./policy.mjs --tool Bash --command '<the legitimate case>' --expect allow
fp policies publish my-policy ./policy.mjs
fp fleet deploy ci-runner-01 --add my-policy:observe
fp guardrails summary --since 24h --machine ci-runner-01
```

`:observe` הוא מה שהופך את זה לרולאוט צל. `fp fleet deploy ... --add my-policy` בחשמלות **אוכף מיד** — השפעה מושמטת מתפקדת לאפקט כבר פרוס, ואז ל-`enforce` — שעל מדיניות שחזרת אותה בדיוק פירושו החזרת התקרית. במצב Observe מדיניות נמדדת בעדיין באופן אמיתי ורשמת כל פסק דין שאינו-allow; רק ההגנה מוחזקת בחזקה, אז `fp guardrails summary` מודדת את הגרסה החדשה לעומת אותו תעבורה שהשברה על הישנה. קדם עם `--add my-policy:enforce` כשהמספרים אומרים כן.

<Warning>
  הפסקת אכיפה יכולה להיות מתאימה במהלך תקרית, אך היא מרחיבה חשיפה לכל מדיניות פעילה בטווח זה. העדיפו חזרה לגרסה קודמת של גרסת מדיניות ספציפית כאשר זה אפשרי.
</Warning>
