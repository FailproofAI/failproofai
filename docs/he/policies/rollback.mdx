גרסת מדיניות שפורסמה לעולם לא משתנה. עריכת מדיניות ופרסום שוב יוצרת גרסה חדשה; לעולם לא משכתבת את זו שכבר על המכונות. זה מה שהופך את החזרה לגרסה קודמת לבטוחה: הגרסה האחרונה הטובה עדיין שם, בדיוק בת לבת, והחזרה לא מחוקה את היסטוריית ההחלטות שמסבירה מה השתבש.

## חיפוש גרסה

<Tabs>
  <Tab title="Dashboard">
    עבור אל **Admin → policy editor** ופתח את **library** כדי להשוות גרסאות של מדיניות או להשבית אחת.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp policies list                 # כל גרסת מדיניות
    fp policies show <policy-id>     # גרסה אחת, עם המקור שלה
    ```
  </Tab>
</Tabs>

## חזרה לגרסה קודמת על מכונה

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Admin → enforcement**, הרחב את המכונה שהושפעה, וזהה את קבוצת המדיניות הטובה האחרונה שלה.
    2. בחר **edit**, שחזר את הגרסאות והאפקטים האלה, והחל את ההצבה החדשה.
    3. המתן לבדיקה שלך של המכונה, ולאחר מכן אמת את ההצבה המדווחת.
    4. פתח את **Observe → policy** והסשנים המושפעים כדי לאשר שעבודה תקינה כבר לא חסומה.
  </Tab>
  <Tab title="CLI">
    כל הצבה למכונה היא דור שמסופר. רשום אותם, ואז חזר לאחד:

    ```bash
    fp fleet history <machine-id>
    fp fleet rollback <machine-id> <generation>
    ```

    `rollback` יוצר דור חדש שנושא את הקבוצה הישנה במקום להחזיר את המונה, כך שהיסטוריה נשארת append-only, והוא מסרב לדור שקוראים לו מדיניות מכיוון שהושבתה או נמחקה. זה דורש סשן עם כניסה חתום עם `policies:write`. `fp fleet diff <machine-id>` מראה מה היה מעוצב לעומת מה שהמכונה יישמה — זה נקרא `behind` עד שהמכונה תסקור בפעם הבאה — ובמכונה עצמה, `failproofai policies` מפרטת את ההצבה שהיא מפעילה.
  </Tab>
</Tabs>

## הסר מדיניות אחת מכל מכונה

```bash
fp policies disable <policy-id>    # הסר אותה מכל הצבה שנושאת אותה
fp policies enable <policy-id>     # הוסף אותה חזרה
```

כל אחת יוצרת דור חדש בכל הצבה שהיא משפיעה עליה. חזרה לגרסה קודמת של אחד מהדורים האלה היא לא איך אתה משחזר `disable`, אם כן — `rollback` מסרב לדור שקוראים לו מדיניות שהושבתה, וכל דור מלפני ההשבתה קוראים לזה. `fp policies enable` היא הדרך חזרה, והיא יוצרת את הדור שלה בתורה.

## חזרה לגרסה קודמת של חבילה

חבילה מוקצית לשחרור שהתקנת, כך שחזרה אליה אומרת התקנת אחת קודמת:

```bash
failproofai policies show FailproofAI/policies --releases   # כל גרסה שפרסמה, וכאיזו זו כאן
failproofai policies add FailproofAI/policies@a1b2c3d4e5f6   # הקצה את זו
```

ללא טרמינל, או עם `--policy`, `--category` או `--all`, הוספה מחדש שומרת על תת-הקבוצה שבחרת. בטרמינל ללא אלה, הוא פותח את הבוחר מסומן מראש עם ברירות ההפקה של המחבר, ומה שאתה מסמן מחליף את הבחירה שלך — אז סמן שוב את מה שהיה לך.

## מתי לחזור לגרסה קודמת

- מדיניות חוסמת פעולת ייצור צפויה.
- נפח התאמה גבוה משמעותית מהחזוי ההנפקה שנצפה.
- מדיניות תלויה בשדות שאינטגרציה לא מספקת.
- גרסה חדשה משנה התנהגות מחוץ לאופן הכישלון המעוצב.

לאחר חזרה לגרסה קודמת, פתח את הסשנים המושפעים ומצא את התנאי מאחורי החיובי השקרי. פרסום גרסה חדשה, [בדיקה](/he/policies/test) של מקרה בלתי בטוח וגם חוקי, והתבונן בו שוב לפני אכיפה.

<Warning>
  `failproofai config --pause` הולך מדיניות מקומיות לסשן אחד ולעולם לא מנוהלות בענן, אז זה לא יציאה מהצבת ענן רעה. השהיה גם מרחיבה חשיפה לכל מדיניות בהיקף שלה; העדף חזרה לגרסה קודמת של הגרסה היחידה שמתנהגת בצורה לא תקינה.
</Warning>
