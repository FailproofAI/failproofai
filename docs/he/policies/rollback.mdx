חזרה לגרסה קודמת משנה את הגרסה המפורסת או מסירה הקצאת מדיניות; היא לא מוחקת את היסטוריית ההחלטות המסבירה את התקרית.

## חזרה לגרסה קודמת של מכונה

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Admin → enforcement**, הרחב את המכונה המושפעת, וזהה את מערך המדיניות האחרון הידוע שלה כתקין.
    2. בחר **edit**, שחזר את הגרסאות והאפקטים הללו, והחל את הפריסה החדשה.
    3. המתן לבדיקה של המכונה, ולאחר מכן אמת את הפריסה המדווחת.
    4. פתח **Observe → policy** ואת הסשנים המושפעים כדי לאשר שעבודה תקינה כבר לא חסומה.

  </Tab>
  <Tab title="CLI">
    חזרה לגרסה קודמת של פריסה בענן היא זרימת עבודה של לוח בקרה. השתמש בסטטוס מקומי כדי לאשר שהפריסה המתוקנת הגיעה למכונה:

    ```bash
    failproofai config --status
    ```

    `failproofai config --pause` מעצרת מדיניויות מובנות, מותאמות ותיקיות לסשן מקומי אחד. היא לא מעצרת מדיניויות המנוהלות בענן, כך שזה לא עקיפה לפריסה רעה של ענן.
  </Tab>
</Tabs>

## מתי לבצע חזרה לגרסה קודמת

- מדיניות חוסמת פעולת ייצור צפויה.
- נפח התאמות גבוה משמעותית מהחזוי שנצפה ברולאאוט.
- מדיניות תלויה בשדות שאינטגרציה לא מספקת.
- גרסה חדשה משנה התנהגות מחוץ למצב הכשל המיועד.

לאחר חזרה לגרסה קודמת, פתח את הסשנים המושפעים וזהה את התנאי שגרם לחיוביות שקרית. צור גרסה חדשה, בדוק גם את המקרים הלא בטוחים והלגיטימיים, ולאחר מכן חזור על שלב ההשגחה.

<Warning>
  השהיית כפיה יכולה להיות מתאימה במהלך תקרית, אך היא מרחיבה חשיפה עבור כל מדיניות פעילה בסקופ זה. עדיף לבצע חזרה לגרסה קודמת של גרסת המדיניות הספציפית כאשר זה אפשרי.
</Warning>
