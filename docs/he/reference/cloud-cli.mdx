השתמש ב-`fp` כדי לבדוק טלמטריה של Cloud, לנהל הנפקה מנוהלת בענן (מדיניות, פריסות צי, החלטות guardrail), ולנהל ביקורות, ממצאים, בעיות, התראות, מפתחות, משתמשים, שאילתות והגדרות. השתמש ב-[`failproofai`](/he/reference/failproof-cli) ל-hooks מקומיים, מדיניות, capture והרשמת מכונות.

התקן את Failproof Cloud CLI שוחרר כך שיהיה כלי מבודד. הוא דורש Python 3.10 או חדש יותר.

```bash
uv tool install fp-cloud-cli
fp version
```

ההפצה היא `fp-cloud-cli` והפקודה המותקנת היא `fp` — הם שונים כי `fp` כבר תפוס ב-PyPI.

## התחברות

`fp login` שולח לך קוד בן שש ספרות בדוא"ל וישמור את ההפעלה. מול לוח מחוונים עם תעודה חתומה בעצמה, הוסף `--insecure` בזמן ההתחברות.

```bash
fp login
fp whoami
```

## תחביר

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

אפשרויות גלובליות חייבות להיות לפני הפקודה:

```bash
fp --json sessions --since 24h
```

הרץ `fp COMMAND --help` או `fp COMMAND SUBCOMMAND --help` לעזרה בטרמינל.

### אירועים

```text
fp events [OPTIONS]
```

רישום אירועי agent בודדים. הזנת ברור ברירת המחדל לא כוללת עומסים גולמיים; השתמש ב-`--full` רק לחקירה מוגבלת.

| אפשרות | תיאור |
| --- | --- |
| `--limit`, `-n <n>` | מקסימום שורות כוללות. ברירת מחדל: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, או `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | טווח ISO 8601 UTC; משכנע את `--since`. |
| `--env <value>` | סנן סביבה; חזור או הפרד בפסיקים ערכים. |
| `--event-type <value>` | סנן סוג אירוע; חזור או הפרד בפסיקים ערכים. |
| `--agent-id <value>` | סנן agent; חזור או הפרד בפסיקים ערכים. |
| `--session-id <value>` | סנן הפעלה; חזור או הפרד בפסיקים ערכים. |
| `--search <text>` | חיפוש טקסט במטען; ניתן לחזור, כל מונח תואם. |
| `--order asc\|desc` | סדר זמן. ברירת מחדל: חדש ביותר קודם. |
| `--all` | עדכון עמודים אוטומטי עד ל-`--limit`. |
| `--cursor <token>` | חידוש מסמן אטום. |
| `--page-size <n>` | שורות לבקשה עם `--all`; מקסימום `200`. |
| `--full` | כללו עומסים גולמיים דרך נקודת הקצה של אירוע כבדה יותר. |
| `--fields <csv>` | החזר רק שדות נבחרים; בקשה של `payload` מאפשרת מצב מלא. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` עדכונים **עד ל-`--limit`**, שהברירה שלו היא **50** — כך שבלבד `--all` עוצר ב-50 שורות. כאשר הוא עוצר מוקדם, התגובה נושאת `next_cursor` לחידוש; `"next_cursor": null` אומר שהזנה באמת הוצאה מהשימוש.
</Note>

#### אפשרויות יצירת ביקורת

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| אפשרות | תיאור |
| --- | --- |
| `--file <path>` | בסיס ההגדרה ב-JSON, או השתמש ב-`-` ל-stdin. דגלים מפורשים משכנעים ערכי קובץ. |
| `--description <text>` | ציין את שאלת ההכשל או המטרה. |
| `--enabled` / `--disabled` | התחלת תזמון או כיבוי. ברירת מחדל: מאופשרת. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. ברירת מחדל: `86400`. |
| `--schedule-anchor <timestamp>` | שלב UTC קבוע בצורת ISO 8601. ברירת מחדל: 09:00 UTC הבא. |
| `--window-mode since_last\|fixed` | המשך אחרי חלון מנותח אחרון לחלוטין או הגדר מחדש טווח מתגלגל. ברירת מחדל: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. ברירת מחדל: `604800`. |
| `--scope '<json>'` | סינון לפי `environments`, `agent_ids`, או שדות scope אחרים נתמכים. |
| `--ignore-error-type <type>` | לא לכלול סוגי שגיאות; חזור או הפרד בפסיקים. |
| `--llm` / `--no-llm` | הפעלה או השבתה ניתוח agentic. ברירת מחדל: מאופשרת. |
| `--top-k <n>` | שמור `1`–`500` ממצאים. ברירת מחדל: `50`. |
| `--sensitivity low\|medium\|high` | קביעת רגישות דיווח. ברירת מחדל: `medium`. |
| `--channels '<json>'` | מערך ערוץ הודעה. |
| `--text <brief>` | ביאור מובנה, מקסימום 8,192 תווים. |
| `--text-file <path>` | קריאת הביאור מקובץ; בלעדי הדדיות עם `--text`. |
| `--url <https-url>` | הוסף התיקייה ציבורית HTTPS; חזור עד חמש פעמים. |

כללו הקשר במהלך היצירה כאשר ההרצה הראשונה צריכה אותה. יצירה מחייבת את ההגדרה וההקשר יחד לפני הרצה בתור התחיל.

<Note>
  `fp audits run` הוא אסינכרוני. סקור `fp audits runs NAME` עד שההרצה העדכנית תצליח או תיכשל לפני קריאת ממצאיה.
</Note>

| `fp issues assign INCIDENT_ID` | החלפת מוקצים; השמט את האפשרות כדי להסיר אותם. | חזור `--assignee` |
| `fp issues resolve INCIDENT_ID` | פתרון בעיה. | `--yes`, `-y` |
| `fp issues comment-list INCIDENT_ID` | רישום הערות. | — |
| `fp issues comment-add INCIDENT_ID` | הוספת הערה. | בדיוק אחד מ-`--body`, `--file` |
| `fp issues comment-delete INCIDENT_ID COMMENT_ID` | מחיקת הערה. | `--yes`, `-y` |
| `fp issues subscribers INCIDENT_ID` | רישום מנויים. | — |
| `fp issues subscribe INCIDENT_ID` | הנו עצמך או מפעיל אחר. | `--email` |
| `fp issues unsubscribe INCIDENT_ID` | הסרת מנוי. | `--email` |

מדינות בעיה תקפות הן `firing`, `acknowledged`, ו-`resolved`. חומרות בעיה עצמאיות הן `info`, `warning`, ו-`critical`.

### מדיניות

גרסות מדיניות מנוהלות בענן. **Session-only** — כל פקודה כאן חוץ מ-`fp policies test` יוצאת `2` תחת מפתח API, לפני כל בקשה, כי אלה נתיבים כתיבה בלבד בשורש בכוונה הנעדרים מ-`/v1`. `fp policies test` הוא יוצא דופן בכוונה: הוא פועל כולו מקומית נגד `node` ולא מדבר לשום שרת, אז זה לא נושא דרישת אימות או סירוב מצב מפתח וגם עובד מחוץ לחוק ותחת מפתח API גם כן.

| פקודה | מטרה | אפשרויות |
| --- | --- | --- |
| `fp policies list` | רישום גרסאות מדיניות, החדש ביותר של כל מדיניות תחילה. | — |
| `fp policies show POLICY_ID` | הצגת מדיניות אחת, עם המקור שלה. | — |
| `fp policies publish POLICY_ID [SOURCE]` | טבעת גרסה חדשה; זה לעולם לא משנה אחד בחיים. `SOURCE` הוא נתיב, `@path`, או `-` ל-stdin — השמט את זה כדי להדביק. | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | הוספה חזרה לכל פריסה הוסרה ממנה, טבעת דור חדש על כל אחד. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | הסרה מכל פריסה נושאת אותה, טבעת דור חדש על כל אחד. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | מחיקת גרסת מדיניות. | `--yes`, `-y` |
| `fp policies test [SOURCE]` | הרצת מדיניות מקומית נגד הקשר סינתטי. חל כל מסנן `match` של מדיניות, כך שאחד שלא מכסה את האירוע/הכלי הנתון מדווח `skipped` במקום הרצה. צריך `node` ב-PATH. | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | טיוטה של מדיניות עם העוזר. הדפסת הטיוטה ותחת כל מצב אחר כברירת מחדל. צריך `policies:write`. | `--out <path>`; `--publish <policy-id>` |

### צי

אילו מכונות מריצות אילו מדיניות. **Session-only** — כל פקודה כאן, ללא יוצא דופן, יוצאת `2` תחת מפתח API.

| פקודה | מטרה | אפשרויות |
| --- | --- | --- |
| `fp fleet list` | רישום מכונות רשומות וגרסת הפריסה שלהן. | — |
| `fp fleet show MACHINE_ID` | קבוצת מדיניות שמכונה מריצה כרגע. | — |
| `fp fleet deploy MACHINE_ID` | שינוי מה מכונה אוכפת. הדפסת כל קבוצה וביקוש תוצאה רק בטרמינל אינטראקטיבי ללא `--json`. | `--add`; `--remove`; `--set`; `--create`; `--yes`, `-y` |
| `fp fleet diff [MACHINE_ID]` | כוונה לעומת מסירה — מה מכונה אמורה להריץ נגד מה הוא משך אחרון. השמט את ה-id עבור כל הצי. | — |
| `fp fleet history MACHINE_ID` | כל דור למכונה, החדש ביותר קודם. | — |
| `fp fleet rollback MACHINE_ID GENERATION` | הפעלה מחדש של קבוצת מדיניות של דור עבר. מספר הדור מגיע מ-`fp fleet history MACHINE_ID`. | `--yes`, `-y` |
| `fp fleet rename MACHINE_ID LABEL` | תן תווית קריאה למכונה. ה-id עצמו לעולם לא משתנה. | — |

```bash
fp fleet history ci-runner-01
fp fleet rollback ci-runner-01 3
fp fleet rename ci-runner-01 "CI runner (eu-west)"
```

#### הפניות מדיניות

`--add` ו-`--set` לוקחים הפניה מדיניות, לא מזהה חשוף:

| צורה | פירוש |
| --- | --- |
| `id` | גרסה נוכחית, השפעה נוכחית |
| `id@3` | גרסה 3, השפעה נוכחית |
| `id:observe` | גרסה נוכחית, הוקלטה אך לא אכוצה |
| `id@3:observe` | גרסה 3, הוקלטה אך לא אכוצה |

ההשפעה היא `enforce` או `observe`. רזולוציה היא: השפעה מפורשת מנצחת; אחרת ההשפעה כבר פרוסה לאותה מדיניות; אחרת `enforce`.

<Warning>
  ערום `--add` **אוכפת מיידית**. `fp fleet deploy ci-runner-01 --add checkout-guard` מתחיל לחסום על מכונה זו ברגע שהיא משכה בפעם הבאה. `:observe` הוא מה שהופך את זה לצבירה צל:

  ```bash
  fp fleet deploy ci-runner-01 --add checkout-guard:observe   # records only
  fp fleet deploy ci-runner-01 --add checkout-guard           # enforces now
  ```

  צפיפות לא כבויה. המדיניות מוערכת בצורה אמיתית, תחת אותו תזמון 10 שניות והטיפול שגיאה זהה כמו מאכיף, וכל פסק דין שאינו-אפשר מוקלט — רק האכיפה מוחזקת בחוץ. זה מה שהופך את המדידה לשווה קריאה.
</Warning>

#### דלתא, החלפה, וקורסים

`--add` ו-`--remove` קריאה את קבוצת הנוכחי של מכונה וביישום דלתא, כך שלא מטפלים בכלום שלא השמות. ערום `--add` על מדיניות המכונה כבר מריצה שמור הגרסה עם קנה מידה במקום שדיכוי משדרג אותה; עבור `id@version` כדי להעביר אותה.

`--set` מחליף הכל וזה הדרך היחידה ליהפול מדיניות שלא השמות. זה לא יכול להיות משוודה עם `--add` או `--remove`. עבור לא מהשלושה הוא שגיאת שימוש, לא לא-אופ.

```bash
fp fleet deploy ci-runner-01 --add prod-guard@1:observe --remove old-rule
fp fleet deploy ci-runner-01 --set no-force-push --set no-secret-echo
```

הכתיבה עצמה היא החלפה מלאה על כל נתיב, כי נקודת הקצה לוקחת כל קבוצת מדיניות. אין נעילה צדדית שרת, אז CLI מתעד את הדור הוא קרא ודוחה אם התוצאה היא לא בדיוק דור גבוה יותר — כי משהו אחר פורס בתוך, וה-החלפה לא מתמזג. קרא מחדש עם `fp fleet show`, ואז פריסה שוב.

`--create` פריסה למכונה id שלא בדק עדיין, עבור ערוך-שלב. ללא זה, מזהה ה-id השרת לא יודע מוסרב, כי שגיאת הקלדה תיטע מכונה שאיש בעלים לא משכתו מדיניות שאיש אוסף.

### Guardrails

מה אכיפה בעצם עשה. **Session-only**, אותה סיבה כמו למעלה.

| פקודה | מטרה | אפשרויות |
| --- | --- | --- |
| `fp guardrails summary` | כיסוי, בלוקדה/הערכה סכומים, ספארקליין דוחה, ו-per-policy הטבלה. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |
| `fp guardrails timeline` | החלטות זלגודקדות על החלון, סכומים על פני כל מקור מדיניות. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |

שורה `(no policy)` בסיכום היא נורמלית במקום פער: רוב הערכות הן מאפשר שום דבר התנגד, והשורה שומרת על המכנה על המסך.

### גלגל מדיניות ללא שבירת מישהו

שלוש הקבוצות לעיל הן רצף אחד. החליט מקומית, פרסם, צל, מדידה, ואז אכיף.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

| שלב | למה זה שם |
| --- | --- |
| `fp policies test` | שום שרת ואין אימות. הורץ הקובץ בפועל נגד הקשר אתה מתאר והדפסות אפשור, דוחה, או הנחה לכל מדיניות רשומה. `--expect` הופך את זה ל-CI קביעה. |
| `fp policies publish` | טבעת גרסה חדשה בלתי ניתנת לשינוי; זה לעולם לא משנה אחד בחיים. |
| `fp fleet deploy --add <id>:observe` | צבירה הצל. **`:observe` לא אופציוני כאן** — ערום `--add` אוכפת ברגע שמכונה משכה. |
| `fp guardrails summary` | מבדיל התאמות לא בטוחות מהעבודה הלגיטימית המדיניות גם חסמה. |
| `fp fleet deploy --add <id>:enforce` | קידום, ברגע שפסקי דין מוקלטים אומרים מה ציפית. |
| `fp fleet rollback <machine> <generation>` | הדרך חזרה אם אכיפה הולכת לא בסדר. |

המקום יחיד-מכונה, עם ללא ענן המעורב, הוא פרסום החפיסה עם `failproofai publish --effect observe` וקריאה פסקי דין מוקלטים על [לוח מחוונים מקומי](/he/reference/local-dashboard).

דגלים מפורשים דורסים משתנים סביבה, דורסים תצורה שמורה.

במצב מפתח API הארגון שמור על ידי בן אדם `fp login` הוא **התעלם**, לא רק דרוס — רק מפורש `--org` או `FP_ORG` נשלח. כלום לא עברות מהתחברות שמורה, אז עבור `--org` כאשר המפתח יכול לפעול לארגון יותר מאחד. השמטה אותו לא נכשל בקול רם: מפתח scope-instance עם לא `--org` פתרה צדדי שרת לארגון **ברירת מחדל** וענה עם הנתונים של ארגון זה, עם שום שגיאה בכל מקום. הרץ `fp whoami` קודם כדי לאשר טנט מפתח בעצם מדבר ל.

<Warning>
  `AGENTEYE_*` קולמתה של אלה הן **לא קרא על ידי `fp`** ומעולם לא היו — ה-CLI מעולם `FP_*` (`fp_cli/app.py`), וממשתנה לא ידוע לא שגיאה. קביעה `AGENTEYE_DASHBOARD_URL` לא retarget את ה-CLI; זה התעלם ופקודה בשקט רץ נגד לוח מחוונים שמור במקום.

  `AGENTEYE_HOME` ו-`AGENTEYE_ENVIRONMENT` עדיין קיימים, אך הם שייכים **למאסף וה-SDK טלמטריה**, לא ל-CLI זה.
</Warning>

<Warning>
  פקודות שמחק, ביטול, דיכוי, פתור, או החלפה תצורה דרוש כברירת מחדל. השתמש `--yes` רק אחרי אימות הארגון הפעיל והיעד.
</Warning>
