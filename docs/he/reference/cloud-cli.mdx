השתמש ב-`fp` כדי לבדוק טלמטריה של Cloud, לנהל אכיפה המנוהלת בענן (מדיניות, פריסות fleet, החלטות guardrail), ולנהל ביקורות, ממצאים, בעיות, התראות, מפתחות, משתמשים, שאילתות והגדרות. השתמש ב-[`failproofai`](/he/reference/failproof-cli) לחוקים מקומיים, מדיניות, capture, וחברות מכונה.

אתה יכול גם לכתוב ולפרוס קוד מתוכנן, מעריכי LLM-judge ו-Jev, לנהל לוחות בקרה, לבדוק סנטימנט, ולהשתמש בעוזר לוח הבקרה מהטרמינל.

התקן את Cloud CLI שוחרר ככלי מבודד:

```bash
uv tool install fp-cloud-cli
fp version
```

## כניסה

```bash
fp login
fp whoami
```

## תחביר

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

אפשרויות גלובליות חייבות להופיע לפני הפקודה:

```bash
fp --json sessions --since 24h
```

הרץ `fp COMMAND --help` או `fp COMMAND SUBCOMMAND --help` לעזרה בטרמינל.

## פקודות CLI

### כתיבת מעריך

`fp evaluators` כותב הגדרות; `fp evals` קורא תוצאות. נדרשת מופע מנוהל מופעל (`fp evaluators instances`). כתיבה דורשת `evaluations:trigger`; ריצות ניסיון בישיבה וקביעת פרופיל סכימה דורשות גם `events:read`.

הקוד הוא ביטוי Python מוגבל אחד. שמור זאת כ-`error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

שופט LLM:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

קובץ Jev בינארי וקנקן מדורג:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
הפעלה מאפשרת את המעריך. פריסה יוצרת גרסה חדשה בלתי משתנה, ואז מסוגלת גרסאות ישנות מופעלות. כשל במעקב משאיר את הגרסה החדשה פורסמה: בדוק `evaluators list --all` לפני ניסיון חוזר.
ריצות ניסיון של judge מורחקות על ידי Cloud. ריצות ניסיון של Jev מוציאות תקציב מודל.
מילוי חוזר מכסה מעריכי קוד, judge ו-Jev ומקבל לכל היותר 90 ימים; הוא מתור רק ישיבות שלמעריך עדיין לא ניקוד. מילוי חוזר של judge ו-Jev מוציא תקציב מודל, אז הרץ `fp evaluators backfill --dry-run` תחילה.
פלט אנושי מראה תוצאות ניסיון לכל ישיבה לפני יצירה/פריסה.
תצוגות מקדימות כושלות עוצרות את הכתיבה אלא אם כן תעביר בצורה מפורשת `--force` לאחר סקירה.
</Warning>

טיוטה מעוררת AI דורשת `fp login` וכותבת spec המקובלת על ידי create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| פקודה | אפשרויות / התנהגות |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | מקור מלא/מעטפת |
| `fp evaluators create` | `--key`, `--name`, `--version`, חוזר `--label`, `--condition EXPR\|@file`, מקור אחד, חוזר `--dry-run-on`, `--disabled`, מפורש `--force` לתצוגות מקדימות כושלות |
| `fp evaluators deploy KEY` | דגלי מקור זהים; `--version`, `--backfill 7d` (כל סוג, 1–90 ימים), `--force`; גרסאות מספריות גדלות באופן אוטומטי; KEY סופק בקובץ spec חסר `eval_key` |
| `fp evaluators draft "intent"` | ישיבה; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | דגלי מקור או `--file`, חוזר `--session` (מקסימום 10); אף אחד = קומפילציה בלבד |
| `fp evaluators enable\|disable KEY[@VERSION]` | החלף |
| `fp evaluators label KEY[@VERSION]` | חוזר `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | בדוק fleet/schema/jobs מנוהל |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; קוד, judge ו-Jev |

דגלי קוד הם `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. דגלי Judge הם `--judge --criteria TEXT`, חוזר `--step` ו-
`--threshold`. דגלי Jev הם `--jev noul --instructions --true --false` או
`--jev score --instructions` עם 3–5 ערכי `--level` ברורים, הגרוע ביותר תחילה.
Judge/Jev דורשים ניקוד; סף הם 0–1. שלבי judge בינאריים נדחים.

קובצי Spec מכילים בדיוק `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
`evaluator_source` של Judge/Jev הוא מחרוזת מעטפת JSON. אל תכלול מזהי שורה,
מצב מופעל, או מטא-נתונים של עדן AI. `--file` ודגלי spec נפרדים הם
בלעדיים; פריסה יכולה לעקוף את הגרסה של הקובץ. קובצי פלט לעולם לא יכתבו אחרון.

### בקרות לוח בקרה חדשות

כל הפקודות מקבלות `--json` גלובלי. 404s של נתיבי לא ידועים יוצאים 6 עם "לא זמין
בـ FailproofAI Cloud זה עדיין". 404s של רקורד חסר יוצאים גם 6 אך מדווחים כי
הרקורד לא נמצא. ישיבה בלבד פקודות דחו מצב מפתח לפני HTTP (יציאה 2).

פקודות אנוש משתמשות בסיכומים וטבלאות. לדירוג JSON גולמי, עבור `--json` גלובלי
או שמור עם `--out FILE`; אחרת ישיבה וייצוא שאילתת JSON מראים
תצוגה קריאה. ייצוא CSV נשאר CSV רגיל לצנרור.

| פקודות | אפשרויות / הערות |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | יצור `--name`, `--description`, `--file` הגדרה; עדכון שמור שדות שלא הוזכרו |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | הוסף `--query ID --chart TYPE --title`; תצורה/גיאומטריה או פריסה דרך `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | ייצוא `--out`; היסטוריה היא היסטוריית הערכה |
| `fp sessions import FILE...` | Claude Code תמלילים, גלילות Codex או JSONL אירוע (`.gz` בסדר); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; דורש `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; רשימה `--limit`; הודעות `--session-id` |
| `fp query compose "question"` | ישיבה; `--run` |
| `fp query export [ID]` | או `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | בעיות יכול `--create --title --summary` או `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; עדכון `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | ישיבה; טיוטה מדיניות מאירועי הארגון שלך, לעולם לא פורסמה |
| `fp policies backtest [FILE_OR_ID]` | ישיבה; regex משחק חוזר למודול; `jev`/`both` (פורסם, או `--semantic checks.json`) להעריך בחינם, `--run [--sample N]` מוציא הקצאת Jev; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | ישיבה; האם מדיניות יכלה למנוע בעיה זו |
| `fp issues facets` | ערכים שמסננים תיבת הדואר יכולים לקחת, עם ספירות |
| `fp agent brief` | ישיבה; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | ישיבה; נגזר slug שהושמט, לא מחליף ארגון |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | קבוצות הרשאה; יצור `--name --permission`; עדכון החלף `--permission` או מזג `--add/--remove`; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | מחיקה לפי id |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` דורש מפתח API; plan (הצעות וניסיון) ותביעה דורשים ישיבה חתומה |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 אסימונים |
| `fp otel status\|enable\|disable` | Cloud org ingest switch, לא capture מקומי |
| `fp slack status\|disconnect` | ישיבה |

`fp agent ask` מעביר SQL אמנציפציה כטבלאות/סטטיסטיקה דרך `queries:run`.
כתיבה אישורים מראים את השינוי המוצע ולהנחות בטרמינל. סקריפטים ו-
`--json` דחו אלא אם כן `--approve` הוא מפורש. צורות JSON קיימות להישאר
ללא שינוי כאשר לא מוחזר אמנציפציה.

בטרמינל, `fp login` מתחיל בקישור, להיכנס עם הדפדפן או SSO שלך, ופותח אותו (דרך SSH או ללא תצוגה זה רק מראה זאת, והוא עובד מכל מכשיר); אשר אותו והטרמינל מסיים בעצמו. הטרמינל הזה מקבל את הגישה שלך בכל הארגונים שלך עד שהישיבה פוקעת, אז רק אשר קישור שביקשת זה עתה. אם ההתחברות התחילה ברשת שונה, אתה מקבל דוא"ל ברגע שהישיבה קיימת, והעמוד מזהיר אותך למקום שהפריסה יכולה להגיד. לחץ על **Tab** לקוד 6 ספרות בדוא"ל במקום, ו-Tab שוב כדי לחזור. `--email`, `--json` וכל דבר ללא טרמינל משתמש בקוד.

### אירועים

```text
fp events [OPTIONS]
```

מפרט אירועי סוכן בודדים. ההנמקה קלה ברירת מחדל לא כוללת עומסי גולם; השתמש ב-`--full` רק לחקירה מוגבלת.

| אפשרות | תיאור |
| --- | --- |
| `--limit`, `-n <n>` | שורות כוללות מקסימום. ברירת מחדל: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, או `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | טווח UTC ISO 8601; עקיפה `--since`. |
| `--env <value>` | מסנן סביבה; חזור או פסיק-נפרד ערכים. |
| `--event-type <value>` | מסנן סוג אירוע; חזור או פסיק-נפרד ערכים. |
| `--agent-id <value>` | מסנן סוכן; חזור או פסיק-נפרד ערכים. |
| `--session-id <value>` | מסנן ישיבה; חזור או פסיק-נפרד ערכים. |
| `--search <text>` | חיפוש טקסט עומס; חוזר, עם כל כדי התאמה. |
| `--order asc\|desc` | סדר זמן. ברירת מחדל: חדש ביותר תחילה. |
| `--all` | פגינציה אוטומטית עד `--limit`. |
| `--cursor <token>` | התחדש מקרסור אטום. |
| `--page-size <n>` | שורות לכל בקשה עם `--all`; מקסימום `200`. |
| `--full` | כלול עומסי גולם דרך נקודת הקצה של אירוע כבדה יותר. |
| `--fields <csv>` | החזר רק שדות נבחרים; בקשת `payload` מאפשרת מצב מלא. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` פגינציה **עד `--limit`**, שברירת המחדל שלה היא **50** — אז `--all` בעצמו עוצר ב- 50 שורות. כאשר זה עוצר מוקדם התגובה נושא
  `next_cursor` להתחדש מ; `"next_cursor": null` אומר שההנמקה באמת הייתה מחוסלת.
</Note>

#### אפשרויות ביקורת יצור

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| אפשרות | תיאור |
| --- | --- |
| `--file <path>` | בסיס ההגדרה ב-JSON, או השתמש ב-`-` עבור stdin. דגלים מפורשים עקיפה ערכי קובץ. |
| `--description <text>` | ציין את שאלת הכשל או המטרה. |
| `--enabled` / `--disabled` | תחל תזמון בחוצץ או כבוי. ברירת מחדל: מופעל. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. ברירת מחדל: `86400`. |
| `--schedule-anchor <timestamp>` | פאזה קבועה UTC בצורת ISO 8601. ברירת מחדל: הבא 09:00 UTC. |
| `--window-mode since_last\|fixed` | המשך אחרי החלון מנותח לאחרונה או בדוק שוב ושוב חלון מתגלגל. ברירת מחדל: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. ברירת מחדל: `604800`. |
| `--scope '<json>'` | מסנן לפי `environments`, `agent_ids`, או שדות scope תמיכה אחרים. |
| `--ignore-error-type <type>` | הוציא סוגי שגיאה; חזור או פסיק-נפרד. |
| `--llm` / `--no-llm` | הפעל או בטל אנליזה agentית. ברירת מחדל: מופעל. |
| `--top-k <n>` | שמור ממצאים `1`–`500`. ברירת מחדל: `50`. |
| `--sensitivity low\|medium\|high` | הגדר רגישות דיווח. ברירת מחדל: `medium`. |
| `--channels '<json>'` | מערך ערוץ התראה. |
| `--text <brief>` | תיק מובנה, מקסימום 8,192 תווים. |
| `--text-file <path>` | קרא תיק מקובץ; בלעדי הדדי עם `--text`. |
| `--url <https-url>` | הוסף ייחוס HTTPS ציבורי; חזור עד חמש פעמים. |

כלול הקשר במהלך יצירה כאשר הריצה הראשונה דורשת זאת. יצירה תחייבת את ההגדרה והקשר יחד לפני שהריצה המתורה מתחילה.

<Note>
  `fp audits run` הוא asynchronous. סקור `fp audits runs NAME` עד שהריצה העדכנית מצליחה או נכשלת לפני קריאת ממצאים שלה.
</Note>
