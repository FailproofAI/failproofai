השתמש ב-`fp` כדי לבדוק טלמטריה בענן, לנהל אכיפה מנוהלת בענן (מדיניות, פריסות צי, החלטות מגן), ולנהל ביקורות, ממצאים, בעיות, התראות, מפתחות, משתמשים, שאילתות והגדרות. השתמש ב-[`failproofai`](/he/reference/failproof-cli) לחוקי מקומיים, מדיניות, תיעוד והרשמת מכונות.

אתה יכול גם לכתוב ולפרוס קוד מתוכנן, מעריכי LLM-judge ו-Jev, לנהל לוחות בקרה, לבדוק סנטימנט, ולהשתמש בעוזר לוח הבקרה מהטרמינל.

התקן את Cloud CLI שוחרר ככלי מבודד:

```bash
uv tool install fp-cloud-cli
fp version
```

## התחברות

```bash
fp login
fp whoami
```

## תחביר

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

אפשרויות גלובליות חייבות להופיע לפני הפקודה:

```bash
fp --json sessions --since 24h
```

הרץ `fp COMMAND --help` או `fp COMMAND SUBCOMMAND --help` לעזרה בטרמינל.

## פקודות CLI

### כתוב מעריך

`fp evaluators` כותב הגדרות; `fp evals` קורא תוצאות. דרוש מופע מנוהל מופעל (`fp evaluators instances`). כתיבה דורשת `evaluations:trigger`; ריצות יבשות וניתוח סכימה דורשות גם `events:read`.

הקוד הוא ביטוי Python מוגבל אחד. שמור את זה כ-`error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

שופט LLM:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

בינרי Jev ורובריקה מדורגת:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
יצירה מאפשרת את המעריך. פריסה יוצרת גרסה חדשה בלתי ניתנת לשינוי, ואז מבטלת גרסאות ישנות מופעלות. כישלון בתابעה משאיר את הגרסה החדשה מפורסמת: בדוק `evaluators list --all` לפני ניסיון חוזר.
ריצות יבשות של שופט מדוחות על ידי Cloud. ריצות יבשות של Jev משקיעות תקציב דגם.
מילוי אחורי מכסה מעריכי קוד, שופט ו-Jev ומקבל לכל היותר 90 ימים; הוא מעמיד בתור רק הפעלות שמעריך לא ציין עדיין. מילוי אחורי של שופט ו-Jev משקיע תקציב דגם, כך שהרץ `fp evaluators backfill --dry-run` קודם.
פלט אנושי מציג תוצאות ריצה יבשות לכל הפעלה לפני יצירה/פריסה.
תצוגות מקדימות כושלות עוצרות את הכתיבה אלא אם תעביר בעצמאות `--force` לאחר בדיקה.
</Warning>

טיוטה בעזרת AI דורשת `fp login` וכותבת מפרט המקובל על ידי create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# בדוק את המפתח, המקור והתנאי של הטיוטה לפני הפעלתו.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| פקודה | אפשרויות / התנהגות |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | מקור/מעטפת מלא |
| `fp evaluators create` | `--key`, `--name`, `--version`, חוזר `--label`, `--condition EXPR\|@file`, מקור אחד, חוזר `--dry-run-on`, `--disabled`, `--force` ברור לתצוגות מקדימות כושלות |
| `fp evaluators deploy KEY` | דגלי מקור זהים; `--version`, `--backfill 7d` (כל סוג, 1–90 ימים), `--force`; גרסאות מספריות מתגברות אוטומטית; KEY מסופק מפרט חסר `eval_key` |
| `fp evaluators draft "intent"` | הפעלה; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | דגלי מקור או `--file`, חוזר `--session` (מקסימום 10); אף אחד = הידור בלבד |
| `fp evaluators enable\|disable KEY[@VERSION]` | החלפה |
| `fp evaluators label KEY[@VERSION]` | חוזר `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | בדוק צי מנוהל/סכימה/עבודות |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; קוד, שופט ו-Jev |

דגלי קוד הם `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. דגלי שופט הם `--judge --criteria TEXT`, חוזר `--step` ו-
`--threshold`. דגלי Jev הם `--jev noul --instructions --true --false` או
`--jev score --instructions` עם 3–5 ערכי `--level` ברורים, הגרוע ביותר קודם.
שופט/Jev דורש ניקוד; סף הם 0–1. שלבי שופט בינרי מדוחים.

קבצי מפרט מכילים בדיוק `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
`evaluator_source` של שופט/Jev היא מחרוזת מעטפת JSON. אל תכלול מזהי שורה,
מצב מופעל, או נתונים של מטא-נימוק בעזרת AI. `--file` ודגלי מפרט בדידים הם
בעלי אופי בלעדי; פריסה יכולה לעקוף את גרסת הקובץ. קבצי פלט לעולם אינם מוחזרים.

### בקרות לוח בקרה חדשות

כל הפקודות מקבלות גלובלי `--json`. 404s של נתיב לא ידוע יוצאים עם 6 עם "לא זמין
על StackExchange זה FailproofAI Cloud עדיין". 404s של רקורד חסר יוצאים גם עם 6 אך דיווחים כי
הרקורד לא נמצא. פקודות רק הפעלה דוחות מצב מפתח לפני HTTP (יציאה 2).

פקודות אנושיות משתמשות בסיכומים וטבלאות. לייצוא JSON גולמי, העבור גלובלי
`--json` או שמור עם `--out FILE`; אחרת הפעלה וייצוא שאילתה JSON מראים
תצוגה קריאה. ייצוא CSV נשאר CSV רגיל להנחה.

| פקודות | אפשרויות / הערות |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | צור `--name`, `--description`, `--file` הגדרה; עדכון משמר שדות לא מוזכרים |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | הוסף `--query ID --chart TYPE --title`; config/geometry או layout דרך `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | ייצוא `--out`; history הוא היסטוריית הערכה |
| `fp sessions import FILE...` | Claude Code תמליל, Codex rollouts או אירוע JSONL (`.gz` בסדר); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; דורש `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; רשימה `--limit`; הודעות `--session-id` |
| `fp query compose "question"` | הפעלה; `--run` |
| `fp query export [ID]` | או `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | בעיות יכולות `--create --title --summary` או `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; עדכון `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | הפעלה; טיוטת מדיניות מאירועי הארגון שלך, אף פעם לא מפרסמת |
| `fp policies backtest [FILE_OR_ID]` | הפעלה; regex מחזור את המודול; `jev`/`both` (מפורסם, או `--semantic checks.json`) להערכה בחינם, `--run [--sample N]` משקיע בהקצבה Jev; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | הפעלה; האם יכלה מדיניות למנוע בעיה זו |
| `fp issues facets` | ערכים שמסננים תיבת הדואר יכולים לקחת, עם ספירות |
| `fp agent brief` | הפעלה; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | הפעלה; גוזר slug מושמט, לא מעביר org |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | קבוצות הרשאה; יצור `--name --permission`; עדכון החלפה `--permission` או מיזוג `--add/--remove`; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | מחיקה לפי id |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` דורש מפתח API; plan (הצעות וניסיון) והטבה דורשים הפעלה חתומה |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 אסימונים |
| `fp otel status\|enable\|disable` | סוג הארגון בענן, לא תיעוד מקומי |
| `fp slack status\|disconnect` | הפעלה |

`fp agent ask` מעניק artifact SQL כטבלאות/נתונים דרך `queries:run`.
אישורי כתיבה מראים את השינוי המוצע ומהווים בטרמינל. סקריפטים ו-
`--json` דוחים אלא אם תעביר בעצמאות `--approve`. צורות JSON קיימות נשארות
ללא שינוי כאשר לא מוחזר artifact.

### אירועים

```text
fp events [OPTIONS]
```

רשום אירועי סוכן בודדים. הזנת האור ברירת המחדל משללת מטענים גולמיים; השתמש ב-`--full` רק לחקירה מוגבלת.

| אפשרות | תיאור |
| --- | --- |
| `--limit`, `-n <n>` | מקסימום שורות סה״כ. ברירת מחדל: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, או `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | טווח ISO 8601 UTC; דורס `--since`. |
| `--env <value>` | מסנן סביבה; חזור או הפרד בפסיקים. |
| `--event-type <value>` | מסנן סוג אירוע; חזור או הפרד בפסיקים. |
| `--agent-id <value>` | מסנן סוכן; חזור או הפרד בפסיקים. |
| `--session-id <value>` | מסנן הפעלה; חזור או הפרד בפסיקים. |
| `--search <text>` | חיפוש טקסט מטען; חוזר, עם התאמת כל מונח. |
| `--order asc\|desc` | סדר זמן. ברירת מחדל: החדשות ביותר ראשון. |
| `--all` | עמודי חיפוש אוטומטיים עד `--limit`. |
| `--cursor <token>` | חזור מסמן כלל. |
| `--page-size <n>` | שורות לכל בקשה עם `--all`; מקסימום `200`. |
| `--full` | כלול מטענים גולמיים דרך נקודת הקצה של אירוע כבד יותר. |
| `--fields <csv>` | החזר רק שדות נבחרים; ביקוש `payload` מאפשר מצב מלא. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` עמודי חיפוש **עד `--limit`**, המהווה ברירת מחדל **50** — כך `--all` בעצמו עוצר ב-50 שורות. כאשר הוא עוצר מוקדם התגובה נושאת
  `next_cursor` להמשך מ; `"next_cursor": null` פירושו ההזנה באמת נכלא.
</Note>

#### אפשרויות יצירת ביקורת

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| אפשרות | תיאור |
| --- | --- |
| `--file <path>` | בסיס הגדרה ל-JSON, או השתמש בקו קו עבור stdin. דגלים ברורים דורסים ערכי קובץ. |
| `--description <text>` | ציין שאלת כישלון או מטרה. |
| `--enabled` / `--disabled` | תחל לתזמן על או כבוי. ברירת מחדל: מופעל. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. ברירת מחדל: `86400`. |
| `--schedule-anchor <timestamp>` | שלב UTC קבוע בצורת ISO 8601. ברירת מחדל: הבא 09:00 UTC. |
| `--window-mode since_last\|fixed` | המשך לאחר החלון המנותח לאחרונה או בדוק חלון גלגול בחוזקה. ברירת מחדל: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. ברירת מחדל: `604800`. |
| `--scope '<json>'` | סנן לפי `environments`, `agent_ids`, או שדות היקף אחרים נתמכים. |
| `--ignore-error-type <type>` | אל תכלול סוגי שגיאה; חזור או הפרד בפסיקים. |
| `--llm` / `--no-llm` | אפשר או בטל ניתוח סוכני. ברירת מחדל: מופעל. |
| `--top-k <n>` | שמור `1`–`500` ממצאים. ברירת מחדל: `50`. |
| `--sensitivity low\|medium\|high` | הגדר רגישות דיווח. ברירת מחדל: `medium`. |
| `--channels '<json>'` | מערך ערוץ התראה. |
| `--text <brief>` | תמצית מובנה, מקסימום 8,192 תווים. |
| `--text-file <path>` | קרא את התמצית מקובץ; בעלות בלעדיות עם `--text`. |
| `--url <https-url>` | הוסף ייחוס HTTPS ציבורי; חזור עד חמש פעמים. |

כלול הקשר במהלך יצירה כאשר ההפעלה הראשונה צריכה אותו. יצירה מתחייבת בהגדרה וההקשר ביחד לפני ההפעלה בתור תחילה.

<Note>
  `fp audits run` הוא אסינכרוני. סקור `fp audits runs NAME` עד שההפעלה האחרונה מצליחה או נכשלת לפני קריאת ממצאיה.
</Note>

  האיות `AGENTEYE_*` של אלה הם **לא קרא על ידי `fp`** והיו אף פעם לא — ה-CLI מכריז `FP_*` (`fp_cli/app.py`), ומשתנה לא ידוע אינו שגיאה. הגדר `AGENTEYE_DASHBOARD_URL` לא מתאם את ה-CLI; זה מתעלם והפקודה בשקט פועלת נגד לוח הבקרה השמור בעוד.

  `AGENTEYE_HOME` ו-`AGENTEYE_ENVIRONMENT` אמנם עדיין קיימים, אך הם שייכים ל-**אוספת טלמטריה ו-SDK**, לא ל-CLI זה.
</Warning>
