השתמש ב-`fp` כדי לבחון טלמטריה של Cloud, לנהל אכיפה מנוהלת בענן (מדיניות, פריסות צי, החלטות guardrail), ולנהל ביקורות, ממצאים, בעיות, התראות, מפתחות, משתמשים, שאילתות והגדרות. השתמש ב-[`failproofai`](/he/reference/failproof-cli) עבור hooks מקומיים, מדיניות, capture, והרשמת מכונות.

התקן את Cloud CLI המשוחרר ככלי מבודד:

```bash
uv tool install fp-cloud-cli
fp version
```

## התחברות

```bash
fp login
fp whoami
```

## תחביר

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

אפשרויות גלובליות חייבות להופיע לפני הפקודה:

```bash
fp --json sessions --since 24h
```

הרץ `fp COMMAND --help` או `fp COMMAND SUBCOMMAND --help` לעזרה בטרמינל.

### אירועים

```text
fp events [OPTIONS]
```

מציין אירועי agent בודדים. הפיד הקל המוגדר כברירת מחדל אינו כולל payload גולמיים; השתמש ב-`--full` רק לחקירה מוגבלת.

| אפשרות | תיאור |
| --- | --- |
| `--limit`, `-n <n>` | מספר שורות כולל מרבי. ברירת מחדל: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, או `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | טווח ISO 8601 UTC; עוקף את `--since`. |
| `--env <value>` | סינון סביבה; חזור על הערכים או הפרד בפסיקים. |
| `--event-type <value>` | סינון סוג אירוע; חזור על הערכים או הפרד בפסיקים. |
| `--agent-id <value>` | סינון agent; חזור על הערכים או הפרד בפסיקים. |
| `--session-id <value>` | סינון סשן; חזור על הערכים או הפרד בפסיקים. |
| `--search <text>` | חיפוש טקסט payload; חוזר על עצמו, כל מונח תואם. |
| `--order asc\|desc` | סדר זמן. ברירת מחדל: החדש ביותר תחילה. |
| `--all` | עמידה אוטומטית עד `--limit`. |
| `--cursor <token>` | חזור מ-cursor אטום. |
| `--page-size <n>` | שורות לכל בקשה עם `--all`; מרבי `200`. |
| `--full` | כלול payload גולמיים דרך נקודת הקצה של האירוע הכבדה יותר. |
| `--fields <csv>` | החזר רק שדות נבחרים; בקשת `payload` מאפשרת מצב מלא. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` עומד בעמידה **עד `--limit`**, שברירת המחדל שלו היא **50** — כך `--all` בכשלעצמו עוצר ב-50 שורות. כאשר זה עוצר מוקדם, התגובה נושאת `next_cursor` להמשך מ-; `"next_cursor": null` פירושו שהפיד באמת היה מותש.
</Note>

#### אפשרויות יצירת ביקורת

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| אפשרות | תיאור |
| --- | --- |
| `--file <path>` | בסיס את ההגדרה על JSON, או השתמש ב-`-` ל-stdin. דגלים מפורשים עוקפים ערכי קובץ. |
| `--description <text>` | ציין את שאלת הכישלון או המטרה. |
| `--enabled` / `--disabled` | התחל תזמון או כבוי. ברירת מחדל: מופעל. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. ברירת מחדל: `86400`. |
| `--schedule-anchor <timestamp>` | שלב UTC קבוע בצורת ISO 8601. ברירת מחדל: 09:00 UTC הבא. |
| `--window-mode since_last\|fixed` | המשך לאחר החלון האחרון שנותח במלואו או בדוק שוב חלון מתגלגל. ברירת מחדל: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. ברירת מחדל: `604800`. |
| `--scope '<json>'` | סנן לפי `environments`, `agent_ids`, או שדות תחום נתמכים אחרים. |
| `--ignore-error-type <type>` | אל תכלול סוגי שגיאה; חזור על הערכים או הפרד בפסיקים. |
| `--llm` / `--no-llm` | הפוך ניתוח agentic. ברירת מחדל: מופעל. |
| `--top-k <n>` | שמור `1`–`500` ממצאים. ברירת מחדל: `50`. |
| `--sensitivity low\|medium\|high` | הגדר רגישות דיווח. ברירת מחדל: `medium`. |
| `--channels '<json>'` | מערך ערוץ התראה. |
| `--text <brief>` | בהבהרה מובנית, מרבי 8,192 תווים. |
| `--text-file <path>` | קרא את ההבהרה מקובץ; בלעדי הדדית עם `--text`. |
| `--url <https-url>` | הוסף ייחוס HTTPS ציבורי; חזור עד חמש פעמים. |

כלול הקשר במהלך היצירה כאשר ההרצה הראשונה זקוקה לו. יצירה מחייבת את ההגדרה וההקשר יחד לפני שההרצה המויתרת מתחילה.

<Note>
  `fp audits run` הוא אסינכרוני. סקור `fp audits runs NAME` עד שההרצה האחרונה תצליח או תכשל לפני קריאת הממצאים שלה.
</Note>

| `fp issues comment-list INCIDENT_ID` | רשום הערות. | — |
| `fp issues comment-add INCIDENT_ID` | הוסף הערה. | בדיוק אחד מ-`--body`, `--file` |
| `fp issues comment-delete INCIDENT_ID COMMENT_ID` | מחק הערה. | `--yes`, `-y` |
| `fp issues subscribers INCIDENT_ID` | רשום מנויים. | — |
| `fp issues subscribe INCIDENT_ID` | הירשם לעצמך או למפעיל אחר. | `--email` |
| `fp issues unsubscribe INCIDENT_ID` | הסר מנוי. | `--email` |

מצבי בעיה תקפים הם `firing`, `acknowledged`, ו-`resolved`. חמורות בעיה עצמאיות הן `info`, `warning`, ו-`critical`.

### מדיניות

גרסאות מדיניות מנוהלות בענן. **Session-only** — כל פקודה כאן יוצא `2` תחת מפתח API, לפני כל בקשה, כי אלה נתיבי כתיבה של root בכוונון לא קיימים ב-`/v1`.

| פקודה | מטרה | אפשרויות |
| --- | --- | --- |
| `fp policies list` | רשום גרסאות מדיניות. | `--json` |
| `fp policies show POLICY_ID` | הצג מדיניות אחת, עם המקור שלה. | — |
| `fp policies publish NAME PATH` | מטבע גרסה מ-`.mjs` מקומי. | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | הוסף אותה חזרה לכל פריסה שהיא הוסרה ממנה, מטבע דור חדש בכל אחת. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | הסר אותה מכל פריסה הנושאת אותה, מטבע דור חדש בכל אחת. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | מחק גרסת מדיניות. | `--yes`, `-y` |
| `fp policies test PATH` | הרץ מדיניות מקומית מול הקשר סינתטי. מחיל סינון `match` של כל מדיניות, כך שאחד שלא כיסה את האירוע/הכלי שניתן דווח `skipped` במקום להרוץ. | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | טיוטה מדיניות עם העוזר. צריך `policies:write`. | — |

## דגלים גלובליים

| דגל | תיאור |

דגלים מפורשים עוקפים משתנים סביבה, שעוקפים קביעה שמורה. במצב מפתח API, בחר את השוכר במפורש עם `--org` או `FP_ORG`.

<Warning>
  ההיגויים `AGENTEYE_*` של אלה הם **לא נקרא על ידי `fp`** ולא היו אי פעם — ה-CLI מעיד `FP_*` (`fp_cli/app.py`), ומשתנה לא ידוע לא שגיאה. הגדרה `AGENTEYE_DASHBOARD_URL` לא retarget את CLI; זה מתעלם והפקודה בשקט פועלת מול הלוח השמור במקום זאת.

</Warning>
