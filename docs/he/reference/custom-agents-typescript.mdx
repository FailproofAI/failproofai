## Install

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

מתאמי המסגרת משתלחים בחבילה עצמה. המסגרות הן **תלויות עמיתות אופציונליות** — מוצהרות כך שהטווחים הנתמכים גלויים, לא מותקנים בשמך, ויובאו רק כאשר קוראים ל-`instrument()`.

## חבר את daemon של Failproof

זהה ל-SDK של Python: צור מפתח `events:add` תחת **Admin → Keys**, ואז [חבר את daemon](/he/start/setup#connect-a-machine-to-cloud) על מכונת ה-agent. ה-SDK כותב לדיסק; ה-daemon משלח.

## Configuration

### OpenTelemetry spans (opt in)

התקן OpenTelemetry בנפרד עם `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
לאחר מכן הוסף את FailproofAI למעבדי ספק שלך:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

לספק קיים, שמור על מעבדים אחרים שלו באותה רשימה. ספקים שחושפים `addSpanProcessor` יכולים במקום זאת להעביר כ-`{ provider }`. ללא אפשרויות, setup מרשם ספק חדש רק אם אין ספק שכבר רשום.
`OtelSpanExporter` יכול גם לשמש ישירות עם המעבד שלך.

הייצוא עובר דרך ה-daemon של FailproofAI המחובר; ה-SDK לא שולח בקשות רשת וזקוק למפתח או listener מקומי. בקש מ-admin להפעיל
[OpenTelemetry ingest](/he/agenteye/opentelemetry). `instrument()` חוסי לא מפעיל את exporter זה. `uninstrument("otel")` מנטרל רק את המעבד שלו. תכונות span שלך שולטות בתפיסת תוכן; flush את ספק שלך לפני יציאה.
OpenTelemetry נשאר תלות אפליקציה אופציונלית, לא תלות SDK קשה.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Option | What it does |
| --- | --- |
| `environment` | התווית בכל ירוי — `production`, `staging`, `prod-eu`. ברירת המחדל היא `dev`. |
| `flushInterval` | כמה פעמים המשימון כותב לדיסק, בשניות. ברירת המחדל היא `0.5`. |
| `baseDir` | היכן לכתוב. ברירת המחדל היא ספול של daemon, שזה מה שאתה רוצה אלא אם אתה יודע אחרת. |

שום דבר לא מיושם אלא אם הכל מאומת, כך שקריאה דחויה משאירה את ה-SDK בדיוק כפי שהיה במקום `baseDir` חדש ומרווח ישן.

קבע לפי משתנה סביבה במקום:

| Variable | What it does |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | קובע את `environment` ללא שינוי קוד. אפשרות `configure()` מנצחת עליה. |
| `FAILPROOFAI_HOME` | מעביר את שורש Failproof AI שמחזיק את הספול. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (ברירת מחדל), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` הופך שגיאות כשור לזורק במקום להיות רשום. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` הופך בעיית תאימות מסגרת לזורק במקום אזהרה והמשך. |

<Warning>
  **אין פסיקים ב-`environment`.** Ingest מפצל את השדה הזה על פסיקים כדי לבנות את המסננים שלו, וקופץ כל ירוי שתווית שלו מכילה אחד — כך ריצה שלמה נעלמת בשקט. כתוב `prod-eu`, לא `prod,eu`.

  `configure({ environment: "prod,eu" })` זורק כדי שתגלה מיד. `AGENTEYE_ENVIRONMENT` לא יכול לזרוק — לא אחד קוראה לך — כך שהוא מאיים פעם אחת ופוקד חזרה ל-`dev`.
</Warning>

התווך לקווי רישום של ה-SDK עצמו לתוך הרשם שלך עם `failproofai.setLogger({ debug, info, warn, error })`.

## Shutdown

ירויים במאגר נשטפו על `process.on("exit")`.

תהליך שנהרג בעל ידי סימן לעולם לא מגיע לזה, וברירת המחדל של Node ל-`SIGTERM` היא להסתיים ללא הפעלת מטפלי יציאה — כך agent בקונטיינר מאבד כל מה שהמרווח האחרון לא כתב.

<Warning>
  **SDK זה לא יתקין מטפל סימנים בשבילך.** רישום אחד משנה את התנהגות התהליך שלך: ממשך מעכב את ברירת ההנחה של Node, כך ספרייה שהוסיפה אחד תעצור בשקט את Ctrl-C מעבודה. הוסף שלך:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

סקריפט בעל חיים קצרים או handler של serverless צריך `await failproofai.flush()` לפני החזרה — המרווח לבדו לא מבטיח משלוח.

## Identity

כל ירוי שייך ל-session ול-agent. **ה-scopes ממלאים את שניהם**, כך שאתה רק לעתים קרובות מעביר אותם:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

העברת `sessionId` או `agentId` במפורש עדיין עובדת ומנצחת. ללא כלא שיוגבל ולא עבר, הקריאה זורקת במקום לפוקד ירוי Cloud שיודבק בשקט.

<Note>
  Identity רוכבת על `AsyncLocalStorage`. היא עוקבת `await`, `.then()`, timers וכל callback שנוצר בתוך ה-scope. היא **לא** עוקבת callback שמאוחסן במהלך ריצה אחת ונקרא במהלך אחרת, או עבודה שנסרקה על פני גבול `worker_threads` — עטוף אלה ב-`failproofai.propagate()` או הירויים שלהם נוחתים ללא קשר.
</Note>

### Scopes

| Scope | Emits | Returns |
| --- | --- | --- |
| `session(body)` | nothing — identity only | whatever `body` returns |
| `agent(id, options?, body)` | `agent_start`, then `agent_end` | whatever `body` returns |
| `toolCall(name, options?, body)` | `tool_use`, then `tool_result` | whatever `body` returns |

גוף סינכרוני נשאר סינכרוני: `agent("x", () => 1)` חוזר `1`, לא הבטחה.

`toolCall` רושם את הערך שנפתר של הגוף כ-`output` של הכלי, אלא אם אתה מקצה `call.output` בעצמך.

<Accordion title="Exit semantics" icon="arrow-right-from-bracket">

| What happened | Events | `outcome` |
| --- | --- | --- |
| הגוש הוחזר | `agent_end` | `"success"`, or your `outcome` |
| הגוש זרק | `error`, then `agent_end` | `"failed"` |
| ביטול `AbortError` | `agent_end` only | `"cancelled"` |

השגיאה תמיד מושלכת מחדש.

כשל בכלי נרשם על העלה — `tool_result` עם מחרוזת `error` — ואינו פוקד ירוי `error` ברמה הריצה. אחד שלולאת ה-agent תופסת אינה כשל ריצה, ואחד שמתפשט מדווח בדיוק פעם אחת, על ידי `agent()` של הכלל.

</Accordion>

<Accordion title="The `using` form" icon="brackets-curly">

כאשר העבודה אינה פונקציה יחידה — scope שנפתח בקונסטרוקטור וסגור בפירוק, או אחד שרוכב על זרימת בקרה קיימת:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

שתי הצורות פוקדות ירויים בדיוק בתוך בתים. עדיף צורת callback: היא עובדת בתוך `AsyncLocalStorage.run()`, כך שאין כלום להתרוקן וכל המעמד של באגים "נפתח כאן, סגור שם" בלתי משיג.

`using` בלוק שתופס את הכישלון שלו מדווח עם `span.fail(error)` — ל-disposer אין ערוץ יוצא מן הכלל שלו.

</Accordion>

## Event catalog

אותם חמישה-עשר שיטות כמו Python SDK, ב-camelCase. רובם באים ב-**זוגות** — אתה קורא ל-opener, אחר כך ל-closer, וה-SDK מתזמן את הפער.

| | Opens | Closes |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Models** | `modelRequest` | `modelResponse` |
| **Tools** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **Humans** | `humanWait` | `humanInput` |

שלוש עומדות לבד: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Every field, per method" icon="table">

כל שיטה לוקחת גם `sessionId` ו-`agentId`, שה-scopes ממלאים עבורך. כל מה שמושמט נשמט במקום להשלח כ-JSON `null`.

| Method | Required | Optional |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

כל מפתח אחר שתוסיף הופך לשדה payload מותאם אישית. Namespace כל דבר ספציפי למסגרת `fw_*`; שם שמתנגש עם שדה מוצהר מסורב במקום להשתנות בשקט עמודה שמקודמת.

</Accordion>

<Warning>
  **`duration_ms` מחושב, לא מקובל.** ארבע השיטות הסוגרות מתזמנות את הפער מ-opener שלהן וסורבות `duration_ms` שמסופק קורא — משך דיווח אינו בלתי זיוף.

  זוגות תואם בהתחשב ב-**session** ובה-id, לא על ה-agent. כלי שנפתח תחת `planner` וסגור תחת `worker` עדיין זוגות, שזה מה שהריצות מולטי-agent מקוננות בפועל עושות.
</Warning>

## Framework adapters

```ts
await failproofai.instrument();              // whatever it can find
await failproofai.instrument("langchain");   // exactly one
failproofai.uninstrument();                  // put everything back
```

| Framework | Supported | How it attaches |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, כך שכל `invoke`/`stream`/`batch` מכוסה ללא העברה `callbacks:` כל מקום — או להעביר `langchainHandler()` עצמך ותיקה כלום. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` בחזית הקריאה, או `instrument("ai")` לכל התהליך ב-`ai` 7 (ב-4–6 זה opt-in — ראה להלן). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, מודל ה-agent וההחלטה כלי, ומנוע ריצת הזרימה/שלב. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (subscribed) בתוספת `AgentWorkflow.runStream`, לריצה זרימה וצעדים שלהם. |

כל טווח נבחן כנגד ביטויי מסגרת אמיתיים, בשני הקצוות, כמו מודול ES וכ-CommonJS, בכל ריצת CI.

המיפוי הוא של Python SDK, כך שאותו תוכנית רומזת את אותה עץ בשפה אחת. קונסטרוקט הוא **agent** רק אם הוא בעלות לולאת החלטה LLM — ריצת גרף או שרשרת, ממשק SDK `generateText`/`streamText` קריאה, agent Mastra, ריצת agent LlamaIndex. קנה או שלב זרימה LangGraph הוא **hook** (`hook_triggered`/`hook_completed`), לעולם לא agent מקונן. קריאות מודל הן `model_request`/`model_response` זוגות עם ספירות token; קריאות כלי נושאות את מזהה קריאת הכלי של המודל. כשל נרשם פעם אחת, בירוי שהוא קרה.

adapter שנכשלת להתקנה היא רשום וחקוקה; האחרים עדיין מתקנים, כי LlamaIndex שבור לא צריך לעלות לך LangGraph.

<Note>
  `instrument()` ללא ארגומנט מגלה מסגרת ב-**resolves**, לא ב-whether היא כבר יובאה — Node חשפה שום שווה ערך ל-Python של `sys.modules` עבור מודולי ES. מסגרת שיש לך מותקנת אך לא משתמש תובא וחקוקה. שם את האחד שתרצה אם זה חשוב.
</Note>

<Note>
  רוב ההטלות משלחות בנייה ES-module ובנייה CommonJS, שNode טוען כשתי עותקים ללא קשר. adapters תיקה את העותק שהיישום שלך טוען (ועותק CommonJS גם כן אם משהו כבר `require`ד זה), כך שני מערכות המודול עובדים. מסגרת **bundled לתוך התפוקה שלך** על ידי esbuild או webpack הוא מחוץ להישג — השתמש בעוזרים לאתר הקריאה שם: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain without patching

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

ה-handler עובד עם או ללא `instrument()` ולא עולה לעולם על הרשמה. `instrument("langchain")` לוקח `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` ו-`captureLimit`, כפי ש-adapter של Python עושה; `metadata: { failproofai_sdk_session_id }` בקריאה בורר את ה-session עבור אותו הודעה.

### Vercel AI SDK

ה-SDK של AI מייצא פונקציות פשוטות מ-ES מודול, ומודול מודול ES אינו משתנה על פי מפרט — אין איפה לתיקה. הוא משתמש בנקודות הרחבה שהיא עצמה מסמיכה:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // on ai 7, `telemetry: telemetry({ … })` — the same object, the new name
});
```

זה האינטגרציה השלמה: span של agent, זוג model request/response לכל שלב עם ספירות token, וכל קריאת כלי. חזית אחת עובדת בכל major — `ai` 4–6 קרא את tracer זה נושא, `ai` 7 את אינטגרציית telemetry.

`instrument("ai")` עושה את אותו תהליך כל התהליך **ב-`ai` 7**: כל קריאה, דרך רשימת אינטגרציית telemetry גלובלית של AI SDK, שהיא תוספת ותופסת שום דבר מאחרים.

**ב-`ai` 4–6, `instrument("ai")` רושם כלום בעצמו, ויומן אחד אזהרה אומרת כך.** ה-hook כל-תהליך היחיד שיש לאלה הגדול הוא ספק tracer OpenTelemetry גלובלי — חניה אחת OpenTelemetry משתנה בחזרה אחד פעם התפוס. רישום שלנו סורב בשקט את `NodeSDK.start()` שלך מאוחר בהתחלה ושולח http/database spans שלך ל-tracer שייצא כלום. השתמש `telemetry()` בחזית הקריאה או `wrapModel` שם. אם התהליך לא מריץ OpenTelemetry שלו, בחר פנימה עם `instrument("ai", { registerGlobalTracer: true })`: הוא אז רושם כל קריאה שמעביר `experimental_telemetry: { isEnabled: true }`, ורק לוקח את החניה אם היא עדיין ריקה. `registerGlobalTracer: false` שומר ברירת מחדל וששתקות האזהרה.

אם תרצה במקום זאת לעטוף את המודל פעם, `wrapModel` רואה שיחות מודל בלבד, כי קריאות כלי קורות מעל שכבת המודל. מודל עטוף קרא עם כלום סביבו נרשם כריצה משלו. קריאה משודרת סוגרת כיצד זרם עוצר — `stop_reason: "cancelled"` כאשר הצרכן מבטל זה, `"error"` עם השגיאה כאשר היא נכשלת חציוני:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

השתמש בשניהם בסדר: ה-middleware מבחין את הקריאה כבר רשומה ודופקת, כך כל קריאה רשומה פעם אחת.

`functionId` שם את span agent. שמור את זה נמוך-cardinality — הוא נוחת ב-`agent_id`, facet לוח הבקרה קדמי.

### Next.js

`next build` חבילות תלויות של שרת שלך כברירת מחדל, ומסגרת חבילה לתוך הבנייה היא עותק `instrument()` לא יכול להגיע. עטוף את ה-config פעם אחת וקרא `instrument()` מ-hook התחלה של Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` מוסיף LangChain, Mastra, LlamaIndex וה-SDK עצמו ל-`serverExternalPackages`, שמירה רשימה שלך. ללא זה, `instrument()` מאיים פעם בחבילה לא יכול להגיע במקום כישלון שקט; אם אתה רשום החבילות בעצמך, קבע `FAILPROOFAI_NEXT_EXTERNALS=1`. ממשק SDK של Vercel ועוזרי קריאה-אתר עובדים כך או כמו. קצה קנה קבל בנייה לא-op: ייבוא SDK בטוח ורשום כלום.

### Token counts on streamed calls

OpenAI-compatible APIs רק דיווח שימוש בזרם כאשר הלקוח שואל. LangChain וממשק SDK של Vercel שואל; ל-LlamaIndex להעביר `additionalChatOptions: { stream_options: { include_usage: true } }` ל-`OpenAI` LLM שלו, וביצוע Mastra את המודל עם שימוש מופעל (למשל `createOpenAICompatible({ includeUsage: true })`). אחרת זרימה קריאות מודל לשא ספירות token.

### Runtimes

Node ≥ 20.9, Bun ו-Deno — כל מסגרת, כמו ES מודול וכ-CommonJS, נבחן בכל נגד Node trace. ה-SDK רץ לצד daemon של `failproofaid`, שנושא מה זה כותב.

## Your own agent — no framework

לולאת agent שכתבת בעצמך, או מסגרת ללא adapter. אתה פוקד את הירויים עם אותו API ש-adapters משתמשות תחתון, כך זרמון יש את אותה צורה וכמות.

אתה לא צריך לדעת כיצד ה-agent מוארגן. כל agent ממכונה כבר יש שלוש מקומות, אלמה פונקציות שלו קוראים, ואלה שלוש כולה אינטגרציה:

| Where | What to add | Emits |
| --- | --- | --- |
| היכן **ריצה אחת** מתחילה ומסתיימת | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **פונקציה אחת שקוראות למודל** | `event.modelRequest` לפני, `event.modelResponse` לאחר — שני חצאים, גם בכישלון | זוג אחד בכל סיבוב מודל |
| **פונקציה אחת שמריצות כלים** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

זהות סביבתי: הכל בתוך `agent()` נוחתות בריצה של ה-session ללא לוקח id, ודבר אחר בתוכנית משתנה — כולל כל מה שה-agent כבר כותב למאגר שלו.

- **שירות או עובד:** להעביר בקשה או כלי שלך id כ-`sessionId`, כך session בלוח הבקרה וה-record בתוך יומנים או מסד נתונים שלך קו אחד.
- **Sub-agents:** מקן `agent()` קריאות. הפנימי מצטרף ל-session עם החיצוני כ-`parent_id` שלו.
- **פוקד את הזוגות.** `modelRequest` ללא `modelResponse` הוא span לוח הבקרה מראה כמו ריצה לעד — מכאן ה-`catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) במאגר הוא הגמור, runnable גרסה: לולאת כלי OpenAI אמיתית כלים בדיוק ככה, ריצה ב-CI בכל שינוי כמו ES מודול וכ-CommonJS.

## Evaluations

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

ראה את [Evaluator SDK reference](/he/reference/evaluator-sdk) ל-protocol, הגדרות עובד וסוגי תוצאות.

<Warning>
  **הערכה חייבת להשיב.** פונקציה סינכרונית שאף פעם לא חוזרת חוסמת את החוט היחיד שיש ל-Node, וללא timeout יכול להגיע בזמן שהוא עושה. כתוב `async` הערכות.
</Warning>

## What it will not do to your process

| | |
| --- | --- |
| **חסום לולאת ה-agent שלך** | ירויים נכנסים לתור בזיכרון; משימון כותב אותם. המשימון הוא `unref`'d, כך ייבוא חבילה זו לא עוצר סקריפט מיציאה. |
| **גדל ללא קשור** | התור מיכל על ידי ספירה *ו*על ידי בתים שנמדדו. העבר לכל אחד, הירויים הקדומים מותחות ואזהרה אומרת כך — הפסקת telemetry חייבת לא להיות OOM הריגה. |
| **קח את התהליך למטה** | ירוי אחד שלא ניתן להקליד מישור לבדו, לא אצווה סביבו. זורק getter, הפניה מעגלית, `BigInt`, surrogate לבד: כל אחד מטופל במקום להפץ. |
| **השאר חצי-כתוב אצווה** | תוכן הוא `fsync`ed לפני שינוי אטומי, המדריך הוא `fsync`ed לאחר, וכישלון כתיבה מנקה קובץ זמני שלו. |
| **עזוב תמלילים קריאים** | אצוות הן `0600` בתוך `0700` ספריה. הם נושאים מטרות, הנחיות, ויכוחים כלי וכלי פלט. |
| **ship credentials** | API keys, tokens, JWTs, bearer headers וביטויים סודיים-צורה מחוקים לפני הבתים להגיע לדיסק. ה-daemon redacts שוב לפני upload. |
