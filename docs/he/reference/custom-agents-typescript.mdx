## התקנה

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

ה-framework adapters משלוחים בחבילה עצמה. ה-frameworks הם **optional peer dependencies** — מוצהרים כך שהטווחים הנתמכים גלויים, לעולם לא מותקנים בשמך, ומיובאים רק כשקוראים ל-`instrument()`.

## התחברות ל-Failproof daemon

זהה ל-SDK של Python: צור מפתח `events:add` תחת **Admin → Keys**, ואז [התחבר ל-daemon](/he/start/setup#connect-a-machine-to-cloud) על מכונת ה-agent. ה-SDK כותב לדיסק; ה-daemon משלוח.

## Configuration

### OpenTelemetry spans (opt in)

התקן את OpenTelemetry בנפרד עם `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
ואז הוסף את FailproofAI לממעבדי ספק שלך:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

עבור ספק קיים, שמור על המעבדים האחרים שלו באותה רשימה. ספקים
שחושפים `addSpanProcessor` יכולים במקום זאת להיות מועברים כ-`{ provider }`. ללא
אפשרויות, setup רושם ספק חדש רק אם אף ספק לא רשום כבר.
`OtelSpanExporter` יכול גם לשמש ישירות עם המעבד שלך.

ייצוא עובר דרך ה-FailproofAI daemon המחובר; ה-SDK לא שולח בקשות רשת
ולא צריך מפתח או listener מקומי. שאל admin להפעיל
[OpenTelemetry ingest](/he/agenteye/opentelemetry). `instrument()` חשוף לא
מפעיל את ה-exporter הזה. `uninstrument("otel")` משבית רק את המעבד שלו.
ה-span attributes שלך שולטים בתפיסת תוכן; flush את ה-provider לפני יציאה.
OpenTelemetry נשאר dependency אפליקציה אופציונלי, לא hard SDK dependency.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Option | מה זה עושה |
| --- | --- |
| `environment` | התווית על כל אירוע — `production`, `staging`, `prod-eu`. ברירת מחדל ל-`dev`. |
| `flushInterval` | כמה בתדירות הטיימר כותב לדיסק, בשניות. ברירת מחדל ל-`0.5`. |
| `baseDir` | היכן לכתוב. ברירת מחדל ל-spool של ה-daemon, שהוא מה שאתה רוצה אלא אם אתה יודע אחרת. |

כלום לא מיושם אלא אם הכל עובר אימות, כך שקריאה שנדחתה משאירה את ה-SDK בדיוק כמו שהיה במקום `baseDir` חדש והמרווח הישן.

הגדר לפי משתנה סביבה במקום:

| Variable | מה זה עושה |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | מגדיר `environment` ללא שינוי קוד. אפשרות `configure()` מנצחת עליה. |
| `FAILPROOFAI_HOME` | מעביר את Failproof AI root שמחזיק את ה-spool. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (ברירת מחדל), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` גורם לשגיאות כשור לזרוק במקום להיות מתועדות. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` גורם לבעיית תאימות framework לזרוק במקום להזהיר ולהמשיך. |

<Warning>
  **ללא פסיקים ב-`environment`.** Ingest מפצל את השדה הזה על פסיקים כדי לבנות את ה-filters שלו, ודולג על כל אירוע שהתווית שלו מכילה אחד — כל כך ריצה שלמה נעלמת בשקט. כתוב `prod-eu`, לא `prod,eu`.

  `configure({ environment: "prod,eu" })` זורק כך שתגלה מיד. `AGENTEYE_ENVIRONMENT` לא יכול לזרוק — כלום לא קוראים לך — כך שהוא מזהיר פעם אחת ונופל בחזרה ל-`dev`.
</Warning>

הנתב את שורות היומן שלו של ה-SDK לתוך ה-logger שלך עם `failproofai.setLogger({ debug, info, warn, error })`.

## Shutdown

אירועים buffered צצים ב-`process.on("exit")`.

תהליך שנהרס על ידי אות לעולם לא מגיע לזה, ובברירת המחדל של Node ל-`SIGTERM` הוא סיום ללא הפעלת exit handlers — כך שagent בקונטיינר מאבד כל מה שהמרווח האחרון לא כתב.

<Warning>
  **ה-SDK הזה לא יתקין signal handler בשבילך.** הרשמת אחד משנה את התנהגות התהליך שלך: listener מדכא את ברירת המחדל של Node, כך שספרייה שהוסיפה אחת תעצור בשקט את Ctrl-C מלעבוד. הוסף שלך:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

סקריפט קצר חיים או handler serverless צריך `await failproofai.flush()` לפני החזרה — המרווח לבדו לא מבטיח משלוח.

## Identity

כל אירוע שייך ל-session וגם ל-agent. **ה-scopes ממלאים את שניהם**, כך שאתה רק מעט מעביר אותם:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

עדיין עובד ניתוח `sessionId` או `agentId` במפורש והיוצא לפועל מנצח. ללא אף אחד bound ולא מועבר, הקריאה זורקת במקום להשמיט אירוע Cloud תיודע שלא.

<Note>
  Identity רוכב על `AsyncLocalStorage`. הוא עוקב `await`, `.then()`, timers וכל callback שנוצר בתוך ה-scope. זה **לא** עוקב callback המאוחסן במהלך ריצה אחת ויקום במהלך אחרת, או עבודה שהעברת גבול `worker_threads` — עטוף אלה ב-`failproofai.propagate()` או האירועים שלהם נוחתים ללא קשר.
</Note>

### Scopes

| Scope | Emits | Returns |
| --- | --- | --- |
| `session(body)` | כלום — identity רק | כל מה `body` מחזיר |
| `agent(id, options?, body)` | `agent_start`, ואז `agent_end` | כל מה `body` מחזיר |
| `toolCall(name, options?, body)` | `tool_use`, ואז `tool_result` | כל מה `body` מחזיר |

body סינכרוני נשאר סינכרוני: `agent("x", () => 1)` מחזיר `1`, לא promise.

`toolCall` רושם את ערך ה-body המופשט כפלט `output` של הכלי, אלא אם אתה מקצה `call.output` בעצמך.

<Accordion title="Exit semantics" icon="arrow-right-from-bracket">

| מה קרה | Events | `outcome` |
| --- | --- | --- |
| ה-block חזר | `agent_end` | `"success"`, או שלך `outcome` |
| ה-block זרק | `error`, ואז `agent_end` | `"failed"` |
| `AbortError` | רק `agent_end` | `"cancelled"` |

השגיאה תמיד נזרקת מחדש.

כשל כלים רשום על העלה — `tool_result` עם מחרוזת `error` — ופולטת **לא** אירוע `error` ברמת ריצה. אחד שלולאת ה-agent תופס איננו כשל ריצה, ואחד שמתפשט מדווח בדיוק פעם אחת, על ידי `agent()` המכיל.

</Accordion>

<Accordion title="הטופס `using`" icon="brackets-curly">

כאשר העבודה איננה פונקציה יחידה — scope פתוח בבנאי וסגור בעקיפה, או אחד שעוקف את זרימת הבקרה הקיימת:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

שני הטפוסים פולטים אירועים byte-identical. עדיף את הטופס callback: הוא רץ בתוך `AsyncLocalStorage.run()`, כך שאין כלום לפתוח וכל מחלקת החיידקים "פתוח כאן, סגור שם" אינה ניתנת לכישרון.

`using` block שתופס את הכשל שלו מדווח עליו עם `span.fail(error)` — ל-disposer אין ערוץ יוצא משלו.

</Accordion>

## Event catalog

אותם חמישה עשר שיטות כמו ה-SDK של Python, ב-camelCase. רוב בא ב-**זוגות** — אתה קוראים opener, ואז closer, וה-SDK מתזמן את הפער.

| | Opens | Closes |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Models** | `modelRequest` | `modelResponse` |
| **Tools** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **Humans** | `humanWait` | `humanInput` |

שלושה עומדים בעצמם: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="כל שדה, לכל שיטה" icon="table">

כל שיטה לוקחת גם `sessionId` ו-`agentId`, אשר ה-scopes ממלאים בשבילך. כל מה שהוחמץ נופל ולא נשלח כ-JSON `null`.

| Method | Required | Optional |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

כל מפתח אחר שתוסיף הופך לשדה custom payload. Namespace כל דבר framework-specific `fw_*`; שם שמתנגש עם שדה מוצהר נדחה במקום שלל דורס עמודה שהועלתה.

</Accordion>

<Warning>
  **`duration_ms` מחושב, לא מקובל.** ארבע השיטות הסוגרות מתזמנות את הפער מה-opener שלהן ודחות ספק `duration_ms` — משך דווח הוא unfalsifiable.

  זוגות תואמים ב-**session** וה-id, לעולם לא ב-agent. כלי פתוח תחת `planner` וסגור תחת `worker` עדיין זוג, שהוא מה שריצות multi-agent קינון בעצם עושות.
</Warning>

## Framework adapters

```ts
await failproofai.instrument();              // כל מה שהוא יכול למצוא
await failproofai.instrument("langchain");   // בדיוק אחד
failproofai.uninstrument();                  // שים הכל חזרה
```

| Framework | Supported | איך זה צמוד |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, כך שכל `invoke`/`stream`/`batch` מכוסה ללא העברת `callbacks:` לשום מקום — או pass `langchainHandler()` בעצמך ותיקט כלום. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` בקריאת האתר, או `instrument("ai")` עבור כל התהליך ב-`ai` 7 (ב-4–6 זה opt-in — ראה להלן). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, ה-model וה-tool resolution של ה-agent, ו-workflow run/step engine. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (subscribed) בתוספת `AgentWorkflow.runStream`, עבור workflow runs וה-steps שלהם. |

כל טווח נבדק כנגד הפצות framework אמיתיות, בשני הקצוות, כמודול ES וכ-CommonJS, בכל ריצת CI.

ה-mapping הוא של ה-SDK של Python, כך שאותו תוכנית משורטטת אותו עץ בשפה כלשהי. קונסטרוקט הוא **agent** רק אם הוא בעל לולאת החלטות LLM — graph או chain run, קריאת AI SDK `generateText`/`streamText`, agent Mastra, ריצת agent LlamaIndex. LangGraph node או workflow step הוא **hook** (`hook_triggered`/`hook_completed`), לעולם לא agent קינון. קריאות model הן `model_request`/`model_response` זוגות עם ספירות tokens; קריאות כלים נושאות ה-tool call id שלו של ה-model. כשל רשום פעם אחת, על האירוע שקרה בו.

adapter שנכשל בהתקנה מתועד ודילוג; האחרים עדיין מתקנים, מכיוון LlamaIndex שבור לא צריך לעלות לך LangGraph.

<Note>
  `instrument()` ללא ארגומנט מזהה framework ב-**resolves**, לא אם הוא כבר מיובא — Node לא חושף שום שווה ערך ל-Python's `sys.modules` עבור ES modules. framework שהתקנת אך לא משתמשת בו יובא ותיקט. ציין את זה שאתה רוצה אם זה חשוב.
</Note>

<Note>
  רוב ה-frameworks האלה מוטבע build ES-module ובuild CommonJS, אשר Node טוען כשתי עותקים לא קשורים. ה-adapters תיקטו את העותק שהיישום שלך טוען (ו-CommonJS copy כן אם משהו כבר `require`'d זה), כך שחבילת הרגולים שניהם עובדות. framework **bundled לתוך הפלט שלך** על ידי esbuild או webpack הוא לא ניתן להשגה — השתמש ב-call-site helpers שם: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain ללא תיקוע

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

ה-handler עובד עם או בלי `instrument()` ולעולם לא double-records. `instrument("langchain")` לוקח `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` ו-`captureLimit`, כמו ה-adapter של Python; `metadata: { failproofai_sdk_session_id }` בקריאה בוחר את ה-session עבור ההשקה הזו.

### Vercel AI SDK

ה-AI SDK מייצא פונקציות פשוטות מ-ES module, ו-ES module namespace בעל משתנה לפי ספציפיקציה — אין מקום לתיקוע. זה משתמש בנקודות הרחבה שה-SDK עצמו תיעד:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // ב-ai 7, `telemetry: telemetry({ … })` — אותו אובייקט, השם החדש
});
```

זה שילוב שלם: span agent, זוג model request/response לכל צעד עם ספירות tokens, וכל קריאת כלים. אתר קריאה אחד עובד בכל major — `ai` 4–6 קורא את ה-tracer שהוא נושא, `ai` 7 ה-telemetry integration.

`instrument("ai")` עושה את אותו תהליך process-wide **ב-`ai` 7**: כל קריאה, דרך ה-AI SDK's global telemetry-integration list, שהוא תוסף ותופס כלום מלא של מישהו אחר.

**ב-`ai` 4–6, `instrument("ai")` רושם כלום בעצמו, ומתועד אזהרה אחת כך.** ה-process-wide hook היחיד שהם major יש הוא ה-global OpenTelemetry tracer provider — slot יחיד OpenTelemetry מסרב להיות בדעה אחת פעם. הרשמת שלנו תדחה שלך שלך בשקט `NodeSDK.start()` מאוחר בהתחלה ותשלח את ה-http/database spans שלך ל-tracer שמייצא כלום. השתמש `telemetry()` בקריאת אתר או `wrapModel` שם. אם התהליך לא מריץ OpenTelemetry של שלו, opt ב-`instrument("ai", { registerGlobalTracer: true })`: זה אז רשום כל קריאה שעברה `experimental_telemetry: { isEnabled: true }`, ותופס רק את ה-slot אם הוא עדיין ריק. `registerGlobalTracer: false` מקפיא את ברירת המחדל ושתיקות האזהרה.

אם אתה מעדיף לעטוף את ה-model פעם אחת, `wrapModel` רואה קריאות model רק, מכיוון קריאות כלים קורות מעל שכבת ה-model. model wrapped הנקרא עם כלום סביבו מתועד כ-run שלו. קריאה streamed סוגרת כיצד הזרם עוצר — `stop_reason: "cancelled"` כאשר הצרכן מבטל זה, `"error"` עם השגיאה כשזה נכשל חלקי:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

שימוש בשניהם בסדר: ה-middleware שם לב הקריאה כבר מתועדת ודחוי, כך שכל קריאה תתועד פעם אחת.

`functionId` שמות את ה-agent span. שמור זה בעלות נמוכה — זה נוחת ב-`agent_id`, ה-primary dashboard facet.

### Next.js

`next build` bundles את ה-dependencies של ה-server כברירת מחדל, ו-framework bundled לבניית הוא עותק `instrument()` לא יכול להגיע. עטוף את ה-config פעם אחת ו-call `instrument()` מ-Next's startup hook:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
```

`withFailproofai` מוסיף LangChain, Mastra, LlamaIndex וה-SDK עצמו ל-`serverExternalPackages`, שמירה על הרשימה שלך. ללא זה, `instrument()` מזהיר פעם אחת לכל framework זה לא יכול להגיע במקום להשמיט בשקט; אם אתה רשום את החבילות בעצמך, הגדר `FAILPROOFAI_NEXT_EXTERNALS=1`. ה-Vercel AI SDK והעוזרים של call-site עובדים כל דרך. Edge route מקבל בניית no-op: ייבוא ה-SDK הוא בטוח ורשום כלום.

### Token counts על streamed calls

OpenAI-compatible APIs רק דווח שימוש בזרם כאשר הלקוח שואל. LangChain וה-Vercel AI SDK שאל; עבור LlamaIndex pass `additionalChatOptions: { stream_options: { include_usage: true } }` ל-`OpenAI` LLM שלו, ועבור Mastra בנה את ה-model עם שימוש מאופשר (לדוגמה `createOpenAICompatible({ includeUsage: true })`). אחרת streamed model calls לא יישא ספירות tokens.

### Runtimes

Node ≥ 20.9, Bun ודו — כל framework, כמודול ES וכ-CommonJS, נבדק בכל נגד ה-trace של Node. ה-SDK רץ ליד ה-`failproofaid` daemon, אשר משלוח מה שהוא כותב.

## agent שלך — לא framework

עבור לולאת agent שכתבת בעצמך, או framework ללא adapter. אתה פולט את האירועים עם אותו API ה-adapters משתמשים מתחתון, כך שה-trace יש אותו צורה וחומר.

אתה לא צריך לדעת כיצד ה-agent מאורגן. כל agent בנוי ביד כבר יש שלוש מקומות, כל כך הפונקציות שלו יקראו, וזה שלוש הם הכל ה-integration:

| Where | מה להוסיף | Emits |
| --- | --- | --- |
| היכן **run אחד** מתחיל וסיום | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **פונקציה אחת שקוראת ל-model** | `event.modelRequest` לפני, `event.modelResponse` לאחר — שני החצאים, גם בכשל | זוג אחד לכל מפנה model |
| **פונקציה אחת שמריצה כלים** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

זהות היא סביבה: הכל בתוך `agent()` נוחת על ריצה של ה-session ללא קבלת id, ולא משהו אחר בתוכנית משתנה — כולל כל מה ש-agent כבר כותב לשל שלו database.

- **שירות או עובד:** pass סביב request או job id שלך כ-`sessionId`, כך session על ה-dashboard וה-record בתוך יומנים שלך או database הם אותה מחרוזת.
- **Sub-agents:** קן `agent()` קריאות. זה הפנימי מצטרף ה-session עם החיצוני כ-`parent_id`.
- **Emit את הזוגות.** `modelRequest` ללא `modelResponse` הוא span ה-dashboard מראה כמו רץ לנצח — מכאן ה-`catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) במאגר הוא השלם, גרסה runnable: לולאת כלי אמיתי OpenAI מכויילת בדיוק ככה, ריצה ב-CI בכל שינוי כמודול ES וכ-CommonJS.

## Evaluations

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

ראה את [Evaluator SDK reference](/he/reference/evaluator-sdk) עבור הפרוטוקול, הגדרות עובד וסוגי התוצאה.

<Warning>
  **הערכה חייבת להניב.** פונקציה סינכרונית שלעולם לא חוזרת חוסמת את ה-thread היחיד שיש ל-Node, ולא timeout יכול לירות בזמן שזה עושה. כתוב `async` הערכות.
</Warning>

## מה זה לא יעשה לתהליך שלך

| | |
| --- | --- |
| **בלוק לולאת ה-agent שלך** | אירועים נכנסים לתור בזיכרון; טיימר כותב אותם. ה-טיימר הוא `unref`'d, כך ייבוא החבילה הזו לעולם לא עוצר סקריפט יוצא. |
| **גדל ללא מחובר** | התור גובה על ידי ספור *ו* על ידי bytes שנמדדו. עבר שניהם, האירועים הישנים ביותר נמחקו והאזהרה אומרת כך — הפסקת תלמטריה חייבת לא להפוך ל-OOM kill. |
| **קח את התהליך למטה** | אירוע unencodable אחד נשמט לבדו, לא הפק סביבו. getter זורק, reference מעגלי, `BigInt`, surrogate לבד: כל אחד טיפל במקום להתפשט. |
| **השאר חצי-כתוב batch** | תוכן הוא `fsync`ed לפני atomic rename, הספריה הוא `fsync`ed אחרי, וכשל כתוב מנקה את הקובץ הזמני שלו. |
| **השאר תמלילים קריאים** | Batches הם `0600` בתוך `0700` ספריה. הם נושאים יעדים, הנמקות, ארגומנטים של כלים ופלט כלים. |
| **ספן אישורים** | API keys, tokens, JWTs, bearer headers וחברות shaped סודות redacted לפני bytes להגיע לדיסק. ה-daemon redacts שוב לפני upload. |
