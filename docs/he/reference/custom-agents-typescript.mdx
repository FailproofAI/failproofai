## Install

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

ה-framework adapters משלחים בחבילה עצמה. הפריימוורקים הם **peer dependencies אופציונליים** — מוצהרים כך שהטווחים הנתמכים גלויים, לעולם לא מותקנים בשמך, ומיובאים רק כאשר אתה קורא `instrument()`.

## Connect the Failproof daemon

זהה ל-Python SDK: צור מפתח `events:add` תחת **settings → api keys**, ואז [התחבר ל-daemon](/he/start/setup#connect-a-machine-to-cloud) במכונת ה-agent. ה-SDK כותב לדיסק; ה-daemon משלח.

## Configuration

### OpenTelemetry spans (opt in)

התקן את OpenTelemetry בנפרד עם `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
ואז הוסף את FailproofAI לעיבודי של ספק:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

עבור ספק קיים, שמור את המעבדים האחרים שלו באותה רשימה. ספקים
שחושפים `addSpanProcessor` יכולים במקום זאת להיות מועברים כ-`{ provider }`. ללא
אפשרויות, ההתקנה רושמת ספק חדש רק אם אין ספק רשום כבר.
`OtelSpanExporter` יכול גם להיות בשימוש ישיר עם המעבד שלך.

הייצוא עובר דרך ה-FailproofAI daemon המחובר; ה-SDK לא שולח
בקשות רשת ולא זקוק למפתח או למאזין מקומי. [OpenTelemetry ingest](/he/agenteye/opentelemetry)
תמיד פעיל בקלאוד. `instrument()` חשוף לא
מאפשר את המייצא הזה. `uninstrument("otel")` משבית רק את המעבד שלו.
תכונות ה-span שלך שולטות בתפיסת התוכן; flush את הספק שלך לפני יציאה.
OpenTelemetry נשאר תלות יישום אופציונלית, לא תלות SDK קשה.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Option | What it does |
| --- | --- |
| `environment` | התווית בכל אירוע — `production`, `staging`, `prod-eu`. ברירת מחדל ל-`dev`. |
| `flushInterval` | כמה עתים הטיימר כותב לדיסק, בשניות. ברירת מחדל ל-`0.5`. |
| `baseDir` | איפה לכתוב. ברירת מחדל לספול של ה-daemon, שזה מה שאתה רוצה אלא אם אתה יודע אחרת. |

כלום לא מיושם אלא אם כל זה מתאמת, כך שקריאה דחויה משאירה את ה-SDK בדיוק כמו שהיה במקום עם `baseDir` חדש והמרווח הישן.

הגדר לפי משתנה סביבה במקום:

| Variable | What it does |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | הגדר את `environment` ללא שינוי קוד. אפשרות `configure()` מנצחת עליו. |
| `FAILPROOFAI_HOME` | הזיז את שורש Failproof AI ההוא שמחזיק את הספול. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (ברירת מחדל), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` עושה שגיאות עדכון זורקות במקום להיות מנוהלות. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` עושה בעיית תאימות פריימוורק זורקת במקום להזהיר ולהמשיך. |

<Warning>
  **אין פסיקים ב-`environment`.** הספיגה מחלקת את השדה על פסיקים לבניית המסננים שלה, וחוזקה כל אירוע שתווית שלה מכילה אחד — כך ריצה שלמה נעלמת בשקט. כתוב `prod-eu`, לא `prod,eu`.

  `configure({ environment: "prod,eu" })` זורקת כדי שתגלה מיד. `AGENTEYE_ENVIRONMENT` לא יכול לזרוק — כלום לא קורא לך — כך שהוא מזהיר פעם אחת ונופל חזרה ל-`dev`.
</Warning>

נתב את שורות היומן של ה-SDK עצמו ללוגר שלך עם `failproofai.setLogger({ debug, info, warn, error })`.

## Shutdown

אירועים במאגר זיזו ב-`process.on("exit")`.

תהליך שהוביל בין-בוצר אף פעם לא מגיע לזה, וברירת ברירת המחדל של Node ל-`SIGTERM` היא להסתיים ללא הפעלת מטפלי יציאה — כך ש-agent בתוך מכולה מאבד מה האינטרוול האחרון לא כתב.

<Warning>
  **ה-SDK הזה לא יתקין עבורך מטפל סגנל.** הרישום של אחד משנה את התנהגות התהליך שלך: מאזין דוכא את ברירת ברירת המחדל של Node, כך שספריה שהוסיפה אחת היתה בשקט עוצרת את Ctrl-C מעבודה. הוסף שלך:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

סקריפט קצר חיים או מטפל serverless צריך `await failproofai.flush()` לפני שהוא חוזר — המרווח לבד לא מבטיח משלוח.

## Identity

כל אירוע שייך לסשן ו-agent. **ההיקפים ממלאים את שניהם**, כך שאתה נדיר מעביר אותם:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

העברת `sessionId` או `agentId` בגלוי עדיין עובדת וזוכה. ללא כל משויכות או מועבר, הקריאה זורקת במקום לשדר אירוע שקלאוד היה דחה בשקט.

<Note>
  הזהות רוכבת על `AsyncLocalStorage`. היא עוקבת `await`, `.then()`, טיימרים וכל קריאה שחזרה לתוך ההיקף. היא **לא** עוקבת קריאה מאוחסנת במהלך ריצה אחת והיזמה במהלך אחר, או עבודה שהעברו על פני גבול `worker_threads` — גלוף אלה ב-`failproofai.propagate()` או האירועים שלהם נוחתים לא מחובר.
</Note>

### Scopes

| Scope | Emits | Returns |
| --- | --- | --- |
| `session(body)` | כלום — זהות רק | מה שגוף `body` חוזר |
| `agent(id, options?, body)` | `agent_start`, ואחר כך `agent_end` | מה שגוף `body` חוזר |
| `toolCall(name, options?, body)` | `tool_use`, ואחר כך `tool_result` | מה שגוף `body` חוזר |

גוף סינכרוני נשאר סינכרוני: `agent("x", () => 1)` חוזר `1`, לא הבטחה.

`toolCall` מקליט את הערך שפתרון הגוף כפלט `output` של הכלי, אלא אם אתה משתמש `call.output` בעצמך.

<Accordion title="Exit semantics" icon="arrow-right-from-bracket">

| What happened | Events | `outcome` |
| --- | --- | --- |
| הבלוק חזר | `agent_end` | `"success"`, או `outcome` שלך |
| הבלוק זרק | `error`, ואחר כך `agent_end` | `"failed"` |
| `AbortError` | `agent_end` בלבד | `"cancelled"` |

השגיאה תמיד מעבר לזרוק.

כישלון כלי נרשם על העלה — `tool_result` עם מחרוזת `error` — וזורק **כלום** הפעלת רמה `error` אירוע. זה שלולא האגן agent הוא לא כישלון בריצה, וזה שהמשך הוא דווח בדיוק פעם אחת, על ידי ההטבעה `agent()`.

</Accordion>

<Accordion title="The `using` form" icon="brackets-curly">

כאשר העבודה היא לא פונקציה יחידה — היקף שנפתח בבנאי וסגור בהורסה, או אחד שחוצה זרימת שליטה קיימת:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

שתי הצורות פולטות אירועים בת-זהה בתים. העדיפות צורת הקריאה החוזרת: היא רצה בתוך `AsyncLocalStorage.run()`, כך שאין שום דבר להיפטר וכל הסוג של ״פתוח כאן, סגור שם״ באגים אינו ניתן להשגה.

בלוק `using` שתופס את הכישלון שלו עצמו דיווח זה עם `span.fail(error)` — למגרש אין ערוץ חריגה משלו.

</Accordion>

## Event catalog

אותם חמישה עשר מתודות כמו Python SDK, ב-camelCase. רוביים מגיעים ב-**זוגות** — אתה קורא את ה-opener, ואחר כך את ה-closer, וה-SDK מתיים את הפער.

| | Opens | Closes |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Models** | `modelRequest` | `modelResponse` |
| **Tools** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **Humans** | `humanWait` | `humanInput` |

שלוש עומדות לבד: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Every field, per method" icon="table">

כל מתודה גם לוקחת `sessionId` ו-`agentId`, שהיקפים ממלאים עבורך. כל דבר שהושמט נשמט במקום להישלח כ-JSON `null`.

| Method | Required | Optional |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

כל מפתח אחר שתוסיף הופך לשדה עומס מותאם. Namespace כל דבר ספציפי לפריימוורק `fw_*`; שם שמתנגש עם שדה מוצהר מסרב במקום לדרוס בשקט עמודה מקודמת.

</Accordion>

<Warning>
  **`duration_ms` מחושב, לא מקובל.** ארבע המתודות סגירה משעות את הפער מה-opener שלהם ודחו `duration_ms` בעל קורא — משך דיווח לא ניתן לזיוף.

  הזוגות מתאימים על הסשן **ו** ה-id, לעולם לא על ה-agent. כלי שנפתח תחת `planner` וסגור תחת `worker` עדיין זוגות, שזה מה ריצות רב-agent מקוננות בעצם עושות.
</Warning>

## Framework adapters

```ts
await failproofai.instrument();              // whatever it can find
await failproofai.instrument("langchain");   // exactly one
failproofai.uninstrument();                  // put everything back
```

| Framework | Supported | How it attaches |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, כך שכל `invoke`/`stream`/`batch` מכוסה ללא עברת `callbacks:` בכל מקום — או עבור `langchainHandler()` בעצמך וטלאי כלום. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` בקרא אתר, או `instrument("ai")` לכל התהליך ב-`ai` 7 (ב-4–6 שהוא הצטיידות — ראה להלן). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, מודל האגן שלו ופתרון כלי, ומנוע ריצה/שלב זרימת עבודה. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (מנויה) בתוספת `AgentWorkflow.runStream`, לריצות זרימת עבודה והשלבים שלהם. |

כל טווח נבדק כנגד שחרורי פריימוורק אמיתיים, בשני הקצוות, כמו מודול ES וכמו CommonJS, בכל ריצת CI.

המיפוי הוא של Python SDK, כך שאותו תוכנית משרטטת את אותו עץ בכל שפה. בנייה היא **agent** רק אם היא בעלת לולאת החלטה של LLM — ריצה גרף או שרשרת, קריאה Vercel AI SDK `generateText`/`streamText`, Mastra agent, ריצה LlamaIndex agent. צומת LangGraph או שלב זרימת עבודה הוא **hook** (`hook_triggered`/`hook_completed`), לעולם לא agent מקונן. קריאות דגם הן `model_request`/`model_response` זוגות עם ספירת סימנים; קריאות כלי נושאות מזהה קריאת כלי משלה של הדגם. כישלון נרשם פעם אחת, על האירוע שהוא התרחש בו.

מתאם שנכשל בהתקנה מנוהל ודלג; האחרים עדיין מתקנים, כי LlamaIndex שבור לא צריך להעלות עלויות לך LangGraph.

<Note>
  `instrument()` ללא טיעון מגלה פריימוורק לפי בין-מתפקד, לא לפי בין-היבוא כבר — Node לא חושפת שקול Python של `sys.modules` למודולי ES. פריימוורק שהתקנת אבל לא משתמש יובא וטיאל. תן שם לאחד שאתה רוצה אם זה משנה.
</Note>

<Note>
  רוביים של פריימוורקים אלה משלחים בנייה מודול ES והתקנה CommonJS, שקשת עומס כשני עותקים לא קשור. המתאמים טיאל העותק היישום שלך עומסים (וגם העותק CommonJS אם משהו כבר `require`d זה), כך שתא מערכות מודול עובדות. פריימוורק **מונציא לתוך פלט שלך** על ידי esbuild או webpack הוא לא ניתן להשגה — השתמש בעוזרי אתר זימון שם: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain without patching

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

המטפל עובד עם או ללא `instrument()` ולעולם לא רשומים כפול. `instrument("langchain")` לוקחת `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` ו-`captureLimit`, כמו המתאם Python עושה; `metadata: { failproofai_sdk_session_id }` בקריאה בוחרת את הסשן להזמנה.

### Vercel AI SDK

ה-AI SDK מייצא פונקציות מישרות מ-ES מודול, ו-ES מודול נתיב הוא בלתי הפיך לפי מפרט — אין שום מקום לטלאי. הוא משתמש בנקודות ההרחבה שה-SDK עצמו מתעד:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // on ai 7, `telemetry: telemetry({ … })` — the same object, the new name
});
```

שלם הוא האינטגרציה: טווח agent, זוג בקשה דגם / תגובה לכל שלב עם ספירות סימנים, וכל קריאה כלי. אתר קריאה אחד עובד על כל גדול — `ai` 4–6 קרא את ה-tracer זה משא, `ai` 7 ה-telemetry אינטגרציה.

`instrument("ai")` עושה את אותו תהליך כל-רחב **ב-`ai` 7**: כל קריאה, דרך רשימת אינטגרציית telemetry גלובלית של AI SDK, שהיא תוסף ו-takes כלום מאיש אחר של.

**ב-`ai` 4–6, `instrument("ai")` רשומות כלום לפי עצמה, ויומן אזהרה אחת אומר כל כך.** ה-process-wide hook היחידה כי גדול יש היא tracer ספק OpenTelemetry גלובלי — חריץ בודד OpenTelemetry מסרבת להסגר פעם לקחה. הרישום שלנו היה בשקט מסרב שלך `NodeSDK.start()` מאוחר יותר בהתחלה ושלח http / מסד נתונים של spans ל-tracer שמייצא כלום. השתמש `telemetry()` בקרא אתר או `wrapModel` שם. אם התהליך אינו פועל OpenTelemetry משלו, בחר ב-`instrument("ai", { registerGlobalTracer: true })`: זה ואז רשומות כל קריאה שעברת `experimental_telemetry: { isEnabled: true }`, וכן לוקחת החריץ רק אם זה עדיין ריק. `registerGlobalTracer: false` שמר את ברירת ברירת המחדל וחרישות את האזהרה.

אם היית עדיף עטוף את המודל פעם אחת, `wrapModel` רואה קריאות דגם בלבד, כי קריאות כלי קורות מעל שכבת הדגם. דגם עטוף בקריאה עם כלום סביבו נרשם כריצה משלו. קריאה זורמת סגורה איך ה-stream עוצר — `stop_reason: "cancelled"` כאשר הצרכן מבטל זה, `"error"` עם השגיאה כאשר זה נכשל חלק דרך:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

שימוש בשניהם בסדר: ה-middleware מבחין הקריאה כבר נרשמת ודוחה, כך שכל קריאה נרשמת פעם אחת.

`functionId` שמות טווח ה-agent. שמור על זה עמוק-cardinality — זה נוחתת ב-`agent_id`, לוח ראשי את היבט.

### Next.js

`next build` חבילות תלויות השרת שלך לפי ברירת מחדל, וא פריימוורק קופץ לתוך הבנייה היא עותק `instrument()` לא יכול להגיע. עטוף את ההגדרה פעם אחת וקרא `instrument()` מקראוק ההתחלה של Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` מוסיף LangChain, Mastra, LlamaIndex והן SDK עצמה ל-`serverExternalPackages`, שמירה רשימה משלך. ללא זה, `instrument()` מזהיר פעם אחת לכל פריימוורק זה לא יכול להגיע במקום נכשל בשקט; אם אתה מחזיק כל כך את החבילות, הגדר `FAILPROOFAI_NEXT_EXTERNALS=1`. ה-Vercel AI SDK וה-call-site עוזרים עובדים כך או כל כך. קצה נתיב מקבל בנייה no-op: ייבוא ה-SDK בטוח ורשומות כלום.

### Token counts on streamed calls

OpenAI-compatible ממשקים רק דיווח שימוש על זרם כאשר הלקוח שואל. LangChain ו-Vercel AI SDK שאול; עבור LlamaIndex עבור `additionalChatOptions: { stream_options: { include_usage: true } }` ל-`OpenAI` LLM שלה, וב-Mastra בנה את הדגם עם שימוש מופעל (עבור דוגמה `createOpenAICompatible({ includeUsage: true })`). אחרת זרמו קריאות דגם לא נשא ספירות סימנים.

### Runtimes

Node ≥ 20.9, Bun וDeno — כל פריימוורק, כמו ES מודול וכמו CommonJS, נבדקה בכל אחד נגד עקבות של Node. ה-SDK רץ לצד ה-`failproofaid` daemon, שמספן מה זה כותב.

## Your own agent — no framework

עבור לולאת agent שכתבת בעצמך, או פריימוורק ללא מתאם. אתה פולט את האירועים עם אותו ממשק API המתאמים משתמשים תחתוני, כך העקבות יש את אותו צורה וטוב.

אתה לא צריך לדעת איך ה-agent בנאי. כל agent בנוי-ביד כבר יש שלוש מקומות, מה הפונקציות שלה קראו, וכי שלוש את כל השילוב:

| Where | What to add | Emits |
| --- | --- | --- |
| כאשר **ריצה אחת** מתחילה ומסתיימת | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **הפונקציה אחת שקרא מודל** | `event.modelRequest` לפני, `event.modelResponse` לאחר — שתי חצאים, אפילו על כישלון | זוג אחד לכל מודל פנה |
| **הפונקציה אחת שרצות כלים** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

זהות היא סביבתית: הכל בתוך `agent()` נוחתות על הריצה של ההסשן ללא לקיחת id, וכלום אחר בתוכנית משתנה — כולל מה האגן כבר כותב למסד נתונים משלו.

- **שירות או עובד:** עבור את המזהה בקשה משלך או מזהה עבודה כ-`sessionId`, כך הסשן בלוח הבקרה והתיעוד בתוך היומנים או מסד הנתונים שלך הם אותו מחרוזת.
- **תת-agents:** קן `agent()` קורא. ה-`parent_id` פנימי שלך קרן ההסשן עם החיצוני.
- **פולט הזוגות.** `modelRequest` עם `modelResponse` לא זוג את הטווח לוח הבקרה מראה כמו פועל לעד — לפיכך `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) ב-repository הוא הגמור, בגרסה runnable: לולאת כלי OpenAI אמיתית מכוונת בדיוק ככה, רון ב-CI בכל שינוי כמו ES מודול וכמו CommonJS.

## Evaluations

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

ראה את [Evaluator SDK reference](/he/reference/evaluator-sdk) לפרוטוקול, הגדרות עובד וסוגי התוצאה.

<Warning>
  **הערכה חייבת להניב.** פונקציה סינכרוני שלעולם לא חוזר חוסמת את חוט אחד קשה שצומת כל כך, ולא timeout יכול להיות כשהיא כן. כתוב הערכות `async`.
</Warning>

## What it will not do to your process

| | |
| --- | --- |
| **חסום לולאה agent שלך** | אירועים נכנסו לתור בזיכרון; טיימר כותב אותם. הטיימר היא `unref`'d, כך ייבוא חבילה זו לא עוצרת סקריפט יוצא. |
| **גדול ללא כמות** | התור מכוסה לפי ספר *ו* לפי בתים מדוד. בעבר או, האירועים הישנים ביותר מושמטים ואזהרה אומר כל כך — הפסקה טלמטריה חייבת לא הפוך OOM להרוג. |
| **קח את התהליך למטה** | אירוע אחד שלא יכול להיות מקודד נשמט לבד, לא הקבוצה סביבו. קרא זריקה, הפניה מעגלית, `BigInt`, מופרד בודד: אחד כל כך לעומת להיות מכונעים. |
| **עזוב קבוצה חצי-כתוב** | תוכן היא `fsync`ed לפני שם אטומי, התיקייה היא `fsync`ed אחרי, וכלא כתוב לנקות קובץ זמני. |
| **עזוב תעתוקים ניתן לקריאה** | קבוצות `0600` בתוך `0700` תיקייה. הם נושאו יעדים, בקשות, טיעוני כלי וכלי פלט. |
| **כלי דרכונים** | מפתחות API, טוקנים, JWTs, כותרות נושא וסיכום-shaped הקצאות מעד לפני הבתים לא דיסק. ה-daemon מעד שוב לפני העלאה. |
