## התקנה

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

ה-framework adapters משולחים בחבילה עצמה. ה-frameworks הם **optional peer dependencies** — הם מוצהרים כדי שהטווחים הנתמכים יהיו גלויים, הם לעולם לא מותקנים בשמכם, ומיובאים רק כאשר אתם קוראים ל-`instrument()`.

## חיבור ל-Failproof daemon

זהה ל-Python SDK: צרו מפתח `events:add` תחת **Admin → Keys**, ואז [חברו את ה-daemon](/he/start/setup#connect-a-machine-to-cloud) על מכונת הסוכן. ה-SDK כותב לדיסק; ה-daemon משדר.

## הגדרה

### OpenTelemetry spans (opt in)

התקינו את OpenTelemetry בנפרד עם `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
ואז הוסיפו את FailproofAI ל-processors של ה-provider שלכם:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

עבור provider קיים, שמרו את ה-processors האחרים שלו באותה רשימה. Providers
שחושפים `addSpanProcessor` יכולים במקום זאת להיות מועברים כ-`{ provider }`. ללא
אפשרויות, ההגדרה מרשמת provider חדש רק אם אין provider רשום כבר.
`OtelSpanExporter` יכול גם להיות בשימוש ישיר עם ה-processor שלכם.

Exports עוברים דרך ה-FailproofAI daemon המחובר; ה-SDK לא שולח בקשות ברשת וואָל צריך מפתח או listener מקומי. בקשו ממנהל להפעיל
[OpenTelemetry ingest](/he/agenteye/opentelemetry). `instrument()` חשופה לא מפעילה את ה-exporter הזה. `uninstrument("otel")` מכבה רק את ה-processor שלה. ה-span attributes שלכם שולטים בלכידת תוכן; flush את ה-provider שלכם לפני יציאה.
OpenTelemetry נשארת תלות יישום אופציונלית, לא תלות קשה של SDK.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| אפשרות | מה היא עושה |
| --- | --- |
| `environment` | התווית בכל אירוע — `production`, `staging`, `prod-eu`. ברירת המחדל היא `dev`. |
| `flushInterval` | באיזו תדירות הטיימר כותב לדיסק, בשניות. ברירת המחדל היא `0.5`. |
| `baseDir` | איפה לכתוב. ברירת המחדל היא ה-spool של ה-daemon, שזה מה שאתם רוצים אלא אם אתם יודעים אחרת. |

שום דבר לא מיושם אלא אם הכל עובר אימות, כך שקריאה שנדחתה משאירה את ה-SDK בדיוק כפי שהוא היה במקום `baseDir` חדש והמרווח הישן.

קבעו דרך משתנה סביבה במקום:

| משתנה | מה הוא עושה |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | קובע את `environment` ללא שינוי קוד. אפשרות `configure()` מנצחת אותה. |
| `FAILPROOFAI_HOME` | מעביר את שורש Failproof AI המחזיק את ה-spool. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (ברירת מחדל), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` גורם לשגיאות כיול לזרוק במקום להיות מרשומות. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` גורם לבעיית תאימות framework לזרוק במקום להזהיר ולהמשיך. |

<Warning>
  **אין פסיקים ב-`environment`.** ה-Ingest מפצלת את השדה הזה בפסיקים כדי לבנות את הסינונים שלה, ומדלגת על כל אירוע שהתווית שלו מכילה אחד — כל ריצה חסרה בשקט. כתבו `prod-eu`, לא `prod,eu`.

  `configure({ environment: "prod,eu" })` זורקת כדי שתגלו מיד. `AGENTEYE_ENVIRONMENT` לא יכולה לזרוק — כלום לא קורא לכם — כך שהיא מזהירה פעם אחת וחוזרת ל-`dev`.
</Warning>

הנתיבו את שורות היומן של ה-SDK עצמו ל-logger שלכם עם `failproofai.setLogger({ debug, info, warn, error })`.

## כיבוי

אירועים ממומלחים נשטפים ב-`process.on("exit")`.

תהליך שנהרג בסימן לעולם לא מגיע לזה, וברירת המחדל של Node עבור `SIGTERM` היא להסתיים ללא הפעלת exit handlers — כך שסוכן שמור בקונטיינר מאבד כל מה שהמרווח האחרון לא כתב.

<Warning>
  **ה-SDK הזה לא יתקין signal handler בשמכם.** רישום אחד משנה את התנהגות התהליך שלכם: listener מדכא את ברירת המחדל של Node, כך שספריה שהוספה אחד תשתיק בשקט את Ctrl-C מלעבוד. הוסיפו שלכם:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

סקריפט קצר או handler serverless צריך `await failproofai.flush()` לפני ההחזרה — המרווח לבדו לא מבטיח משלוח.

## זהות

כל אירוע שייך ל-session וסוכן. **ה-scopes ממלאים את שניהם**, כך שאתם נדירות עוברים אותם:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

העברה של `sessionId` או `agentId` בבירור עדיין עובדת ומנצחת. ללא שניהם קשורים או מועברים, הקריאה זורקת במקום לפתוק אירוע ש-Cloud היה שוקט מודע לדחוש.

<Note>
  הזהות רוכבת על `AsyncLocalStorage`. היא עוקבת `await`, `.then()`, טיימרים וכל callback שנוצרה בתוך ה-scope. זה **לא** עוקב callback שנשמרה במהלך ריצה אחת וזומנה במהלך אחרת, או עבודה העברה על פני גבול `worker_threads` — עטפו אלה ב-`failproofai.propagate()` או האירועים שלהם נחתים unattached.
</Note>

### Scopes

| Scope | פולטים | חוזרים |
| --- | --- | --- |
| `session(body)` | כלום — זהות בלבד | כל מה ש-`body` חוזרת |
| `agent(id, options?, body)` | `agent_start`, ואז `agent_end` | כל מה ש-`body` חוזרת |
| `toolCall(name, options?, body)` | `tool_use`, ואז `tool_result` | כל מה ש-`body` חוזרת |

גוף סינכרוני נשאר סינכרוני: `agent("x", () => 1)` חוזרת `1`, לא promise.

`toolCall` רושמת את הערך שנפתר של ה-body כ-`output` של הכלי, אלא אם אתם מקצים `call.output` בעצמכם.

<Accordion title="Exit semantics" icon="arrow-right-from-bracket">

| מה קרה | אירועים | `outcome` |
| --- | --- | --- |
| הבלוק חזר | `agent_end` | `"success"`, או ה-`outcome` שלכם |
| הבלוק זרק | `error`, ואז `agent_end` | `"failed"` |
| `AbortError` | רק `agent_end` | `"cancelled"` |

השגיאה תמיד מושלכת מחדש.

כשל כלי רשום על העלה — `tool_result` עם string `error` — ואינו פולט **כל** אירוע `error` ברמת ריצה. אחד שלולאת הסוכן תופסת אינו כשל ריצה, ואחד שמתפשט מדווח בדיוק פעם אחת, על ידי ה-`agent()` המקיפה.

</Accordion>

<Accordion title="The `using` form" icon="brackets-curly">

כאשר העבודה אינה פונקציה בודדת — scope שנפתח בקונסטרוקטור וסגור בטיהור, או אחד שצדי קיימים זרימת שליטה:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

שתי הטפסים פולטות אירועים זהים בייטים. העדיפו את הטופס callback: הוא פועל בתוך `AsyncLocalStorage.run()`, כך שאין שום דבר לפתור ורוב המחלקה של באגים "פתוח כאן, סגור שם" אינה ניתנת להשגה.

`using` בלוק התופס כשל משלו דיווחים אותו עם `span.fail(error)` — ל-disposer אין ערוץ חריג משלה.

</Accordion>

## Event catalog

אותם חמישה עשר שיטות כמו Python SDK, ב-camelCase. רובם באים ב-**זוגות** — אתם קוראים ל-opener, ואז ל-closer, וה-SDK מתזמן את הפער.

| | פותח | סוגר |
| --- | --- | --- |
| **סוכנים** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **מודלים** | `modelRequest` | `modelResponse` |
| **כלים** | `toolUse` | `toolResult` |
| **hooks** | `hookTriggered` | `hookCompleted` |
| **אנשים** | `humanWait` | `humanInput` |

שלושה עומדים בעצמם: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Every field, per method" icon="table">

כל שיטה גם לוקחת `sessionId` ו-`agentId`, שה-scopes ממלאים בעבורכם. כל דבר שהושמט מושמט וממש בתוך JSON `null`.

| שיטה | נדרשת | אופציונלי |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

כל מפתח אחר שתוסיפו הופך לשדה payload מותאם. Namespace כל דבר ספציפי framework `fw_*`; שם שמתנגש עם שדה מוכרז נדחה במקום שיתרגם בשקט עמודה מקודמת.

</Accordion>

<Warning>
  **`duration_ms` מחושבת, לא מקובלת.** הארבע שיטות סגירה מתזמנות את הפער מ-opener שלהן ודוחות `duration_ms` שסופקה על ידי קורא — משך דיווח אינו falsifiable.

  זוגות מתאימים ב-**session** וב-id, לעולם לא בסוכן. כלי שנפתח תחת `planner` וסגור תחת `worker` עדיין זוג, שזה מה שרצים מרובי-סוכנים מקוננים בעצם עושים.
</Warning>

## Framework adapters

```ts
await failproofai.instrument();              // whatever it can find
await failproofai.instrument("langchain");   // exactly one
failproofai.uninstrument();                  // put everything back
```

| Framework | נתמך | איך זה מצמיד |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, כך שכל `invoke`/`stream`/`batch` מכוסה ללא העברת `callbacks:` בכל מקום — או העברו `langchainHandler()` בעצמכם ותאתו כלום. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` בקריאה, או `instrument("ai")` לכל התהליך ב-`ai` 7 (ב-4–6 זה opt-in — ראה להלן). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, רזולוציית מודל וכלי של הסוכן, ודוד ריצה/שלב workflow. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (subscribed) פלוס `AgentWorkflow.runStream`, לריצות workflow וההימים שלהן. |

כל טווח נבדק נגד שחרורי framework אמיתיים, בשני הקצוות, כ-ES module וכ-CommonJS, בכל ריצה CI.

ה-mapping הוא של Python SDK, כך שאותה תכנית מציירת את אותה עץ בכל שפה. קונסטרוקט הוא **סוכן** רק אם הוא בעלות על לולאת החלטה LLM — ריצה גרף או chain, קריאה `generateText`/`streamText` של AI SDK, סוכן Mastra, ריצת סוכן LlamaIndex. צומת LangGraph או שלב workflow הוא **hook** (`hook_triggered`/`hook_completed`), לעולם לא סוכן מקונן. קריאות מודל הן זוגות `model_request`/`model_response` עם ספירות טוקן; קריאות כלים נושאות את tool call id של המודל שלהם. כשל רשום פעם אחת, באירוע שקרה בו.

adapter שנכשל בהתקנה מרשום וממורח; האחרים עדיין מתקינים, כי LlamaIndex שבור לא צריך להעלות אתכם LangGraph.

<Note>
  `instrument()` ללא ארגומנט מגלה framework על ידי אם זה **מתחיל**, לא אם זה כבר מיובא — Node לא חושף שום שוויון של Python's `sys.modules` עבור ES modules. framework שיש לכם מותקנת אך לא משתמשים יובא וישולח. קרא לזה שאתה רוצה אם זה משנה.
</Note>

<Note>
  רוב ה-frameworks האלה משלחים בנייה ES-module ובנייה CommonJS, שה-Node טוען כשתי עותקים לא קשורים. ה-adapters תופרים את העותק שהיישום שלכם טוען (וגם העותק CommonJS אם משהו כבר `require`d אותו), כך ששתי מערכות המודול עובדות. framework **bundled לתוך הפלט שלכם** על ידי esbuild או webpack אינו ניתן להשגה — השתמשו בעוזרים של קריאה: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain without patching

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

הטיפול עובד עם או ללא `instrument()` ולעולם לא מתעד כפול. `instrument("langchain")` לוקח `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` ו-`captureLimit`, כמו adapter Python; `metadata: { failproofai_sdk_session_id }` בקריאה בוחרת את ה-session לזימון זה.

### Vercel AI SDK

AI SDK מייצאת פונקציות רגילות מ-ES module, ו-ES module namespace הוא בלתי משתנה בהנחה — אין מקום לתאתות. הוא משתמש בנקודות התרחבות שה-SDK עצמו משם את זה:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // on ai 7, `telemetry: telemetry({ … })` — the same object, the new name
});
```

זוהי האינטגרציה המלאה: span סוכן, זוג בקשה/תגובה מודל לכל שלב עם ספירות טוקן, וכל קריאת כלי. אתר קריאה אחד פועל על כל ראשי — `ai` 4–6 קרא את ה-tracer שהוא נושא, `ai` 7 את אינטגרציית ה-telemetry.

`instrument("ai")` עושה את אותו תהליך רחב-תהליך **ב-`ai` 7**: כל קריאה, דרך רשימת אינטגרציית telemetry הגלובלית של AI SDK, שהיא תוסף ולא לוקח מאף אחד.

**ב-`ai` 4–6, `instrument("ai")` לא מתעדת כלום בעצמה, ומרשמת אזהרה אחת אומרת כך.** ה-hook ברמת-עולמית היחיד שלאותם חברים יש הוא הספק tracer OpenTelemetry הגלובלי — חריץ יחיד OpenTelemetry מסרב לתהות פעם אחת שהוא נלקח. רישום שלנו היה שוקט מודע מסרב את `NodeSDK.start()` שלך מאוחר יותר בתחילת ויתור ושלוח את http/database spans שלך ל-tracer שלא מייצא כלום. השתמשו ב-`telemetry()` בקריאה או ב-`wrapModel` שם. אם התהליך לא פועל OpenTelemetry משלו, בחרו ב-`instrument("ai", { registerGlobalTracer: true })`: הוא אז מתעדת כל קריאה העוברת `experimental_telemetry: { isEnabled: true }`, והוא לוקח את החריץ רק אם זה עדיין ריק. `registerGlobalTracer: false` שומר על ברירת המחדל ומשתיק את האזהרה.

אם תעדיפו לעטוף את המודל פעם אחת, `wrapModel` רואה רק קריאות מודל, כי קריאות כלים קורות מעל שכבת המודל. מודל עטוף שקרא עם כלום סביבו מתעדת כ-run משלה. קריאה משוטחת סגורה כיצד ה-stream עוצר — `stop_reason: "cancelled"` כאשר הצרכן מבטל אותה, `"error"` עם השגיאה כשהוא נכשל באמצע:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

השתמשו בשניים זה בסדר: ה-middleware מבחין שהקריאה כבר מתעדת וטיולים, כך שכל קריאה מתעדת פעם אחת.

`functionId` שמות את span הסוכן. שמור אותה cardinality נמוכה — זה נוחת ב-`agent_id`, aspect דשבורד ראשי.

### Next.js

`next build` חבילות תלויות שרתך כברירת מחדל, וframework בנוי לתוך הבנייה הוא עותק `instrument()` לא יכול להגיע. עטוף את ההגדרה פעם אחת וקרא `instrument()` מ-hook ההנעה של Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` מוסיף LangChain, Mastra, LlamaIndex וה-SDK עצמו ל-`serverExternalPackages`, השמירה על הרשימה שלך. ללא זה, `instrument()` מזהירה פעם אחת לכל framework זה לא יכול להגיע במקום להיכשל שוקט; אם אתה רשימה את החבילות בעצמך, קבע `FAILPROOFAI_NEXT_EXTERNALS=1`. ה-Vercel AI SDK ועוזרים קריאה-קריאה עובדים בכל מקרה. קריאה Edge מקבלת בנייה no-op: ייבוא ה-SDK בטוח ו-records כלום.

### Token counts on streamed calls

רק OpenAI-compatible APIs דיווח שימוש ב-stream כאשר הלקוח שואל. LangChain והוא Vercel AI SDK בקשה; עבור LlamaIndex pass `additionalChatOptions: { stream_options: { include_usage: true } }` ל-LLM `OpenAI` שלו, ועבור Mastra בנו את המודל עם שימוש מובנה (לדוגמה `createOpenAICompatible({ includeUsage: true })`). אחרת streamed קריאות מודל אינן נושאות ספירות טוקן.

### Runtimes

Node ≥ 20.9, Bun ו-Deno — כל framework, כ-ES module וכ-CommonJS, נבדק על כל נגד Node's עקבות. ה-SDK פועל ליד ה-`failproofaid` daemon, שמשדר את מה שהוא כותב.

## סוכן משלך — ללא framework

עבור לולאת סוכן שכתבתם בעצמכם, או framework ללא adapter. פעמיים פולטים את האירועים עם אותו API adapters להשתמש מתחתיה, כך שהעקבות יש אותה צורה וטיבי.

אתה לא צריך לדעת כיצד הסוכן מארגן. כל סוכן בנוי בידי יד כבר יש שלושה מקומות, כל מה הפונקציות שלה נקראות, ואלה שלושת כל האינטגרציה:

| איפה | מה להוסיף | פולטים |
| --- | --- | --- |
| איפה **אחד ריצה** מתחיל וסוף | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| ה-**אחד פונקציה המפעילה את המודל** | `event.modelRequest` לפני, `event.modelResponse` אחרי — שתי החצאים, אפילו בכשל | זוג אחד לכל מודל סיבוב |
| ה-**אחד פונקציה רצים כלים** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

זהות היא סביבה: הכל בתוך `agent()` נוחת על session של ריצה זה ללא לקיחת id, וכלום אחר בתכנית משתנה — כולל כל מה שהסוכן כבר כותב לה בסיס הנתונים שלה.

- **שירות או עובד:** עברו את הבקשה או id של עבודה שלך כ-`sessionId`, כך ש-session בדשבורד ורשומה בתוך היומנים או בסיס הנתונים משלך הם מחרוזת זהה.
- **תת-סוכנים:** קן `agent()` קריאות. הפנימית מצטרפת ל-session עם החיצון כ-`parent_id`.
- **פלוט הזוגות.** `modelRequest` ללא `modelResponse` הוא span הדשבורד מציג כפועל לעד — מכאן `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) בתיקיית המאגר הוא הגרסה השלמה, בעלת שרוש: לולאת כלי OpenAI אמיתית מכויילת בדיוק כמו זו, פועלת ב-CI בכל שינוי כ-ES module וכ-CommonJS.

## Evaluations

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

ראה את [Evaluator SDK reference](/he/reference/evaluator-sdk) לפרוטוקול, הגדרות העובד וסוגי התוצאה.

  **הערכה חייבת להשיג.** פונקציה סינכרונית שלעולם לא חוזרת חוסמת את החוט האחד שלצומת, וללא timeout יכול לשרוף בזמן שזה עושה. כתוב `async` הערכות.
</Warning>

## מה זה לא יעשה לתהליך שלך

| | |
| --- | --- |
| **חסום לולאת הסוכן שלך** | אירועים הולכים לתור בזיכרון; טיימר כותב אותם. הטיימר הוא `unref`'d, כך שייבוא חבילה זו לעולם לא עוצר סקריפט יציאה. |
| **גדול ללא קשור** | תור מכוסה על ידי ספירה *ו* על ידי בתים שנמדדו. עבר שניהם, האירועים הישנים ביותר מושלכים וקריאה אזהרה אומרת כך — הפסקת telemetry חייבת לא להיות הרג OOM. |
| **קח את התהליך למטה** | אירוע unencodable אחד מושלך לבדו, לא אות סביבו. getter זורק, התייחסות מעגלית, `BigInt`, משחק surrogate כהה: כל אחד מטופל במקום להפצה. |
| **עזוב חצי בתוך batch** | תוכן הוא `fsync`ed לפני שם atomic, התיקיה הוא `fsync`ed אחרי, וכתיבה כושלת ינקה את קבצה הזמני. |
| **עזוב תמלול קריא** | אזימי `0600` בתוך `0700` תיקיה. הם נושאים מטרות, הנמקות, כלי טיעונים וכלי פלט. |
| **שיח ויורים** | API keys, אסימנים, JWTs, נושאי כותרות ודיווחים צורה סוד מסופחים לפני הבתים להגיע לדיסק. ה-daemon מעבור שוב לפני upload. |
