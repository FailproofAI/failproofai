## Install

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

ה-framework adapters משלחים בחבילה עצמה. ה-frameworks הם **peer dependencies אופציונליים** — מוצהרים כדי שהטווחים הנתמכים יהיו גלויים, לעולם לא מותקנים בשמך, ומיובאים רק כשאתה קורא ל-`instrument()`.

## Connect the Failproof daemon

זהה ל-SDK של Python: צור מפתח `events:add` תחת **Admin → Keys**, ואז [חבר את הדיימון](/he/start/setup#connect-a-machine-to-cloud) על מכונת ה-agent. ה-SDK כותב לדיסק; הדיימון משלח.

## Configuration

### OpenTelemetry spans (opt in)

התקן את OpenTelemetry בנפרד עם `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
ואז הוסף את FailproofAI לעיבודי ה-provider שלך:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

עבור provider קיים, שמור על העיבודים האחרים שלו באותה רשימה. Providers שחושפים `addSpanProcessor` יכולים במקום זאת להיות מועברים כ-`{ provider }`. ללא אפשרויות, ההגדרה רושמת provider חדש רק אם אין provider רשום כבר.
`OtelSpanExporter` יכול גם לשמש ישירות עם העיבוד שלך.

ייצוא עובר דרך הדיימון של FailproofAI המחובר; ה-SDK לא שולח בקשות רשת וא לא צריך מפתח או listener מקומי. בקש מ-admin להפעיל
[OpenTelemetry ingest](/he/agenteye/opentelemetry). `instrument()` בלי אפשרויות לא מפעיל את ה-exporter הזה. `uninstrument("otel")` משבית רק את ה-processor שלו.
מאפייני ה-span שלך שולטים בתפיסת תוכן; flush את ה-provider שלך לפני היציאה.
OpenTelemetry נשאר תלות של אפליקציה אופציונלית, לא תלות קשה של SDK.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Option | What it does |
| --- | --- |
| `environment` | התווית על כל אירוע — `production`, `staging`, `prod-eu`. ברירת מחדל היא `dev`. |
| `flushInterval` | כמה פעמים בשנייה הטיימר כותב לדיסק. ברירת מחדל היא `0.5`. |
| `baseDir` | לאן לכתוב. ברירת מחדל היא הספול של הדיימון, שזה מה שאתה רוצה אלא אם אתה יודע אחרת. |

שום דבר לא מיושם אלא אם הכל תקף, כך שקריאה דחויה משאירה את ה-SDK בדיוק כפי שהוא היה במקום שיהיה ל-`baseDir` חדש ולהפוך ישן.

קבע לפי משתנה סביבה במקום:

| Variable | What it does |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | קובע `environment` ללא שינוי קוד. אפשרות `configure()` מנצחת עליו. |
| `FAILPROOFAI_HOME` | מעביר את שורש ה-Failproof AI המחזיק את הספול. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (ברירת מחדל), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` גורם לשגיאות עיצוב להטיל במקום להיות רשומות. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` גורם לבעיית תאימות framework להטיל במקום להזהיר ולהמשיך. |

<Warning>
  **אין פסיקים ב-`environment`.** Ingest מפצל את השדה הזה על פסיקים כדי לבנות את הסינונים שלו, וחוקר כל אירוע שעל התווית שלו יש אחד — כך שצריכה שלמה נעלמת בשקט. כתוב `prod-eu`, לא `prod,eu`.

  `configure({ environment: "prod,eu" })` מטיל כך שתגלה מיד. `AGENTEYE_ENVIRONMENT` לא יכול להטיל — שום דבר לא קורא לך — אז היא מזהירה פעם אחת וחוזרת ל-`dev`.
</Warning>

ניתוב של שורות יומן משלה של ה-SDK אל ה-logger שלך עם `failproofai.setLogger({ debug, info, warn, error })`.

## Shutdown

אירועים buffered ממולאים ב-`process.on("exit")`.

תהליך שנהרג על ידי סיגנל לעולם לא מגיע לזה, וברירת המחדל של Node ל-`SIGTERM` היא להסתיים ללא הפעלת מטפלי יציאה — אז agent מכוננות מאבד מה שהמרווח האחרון לא כתב.

<Warning>
  **SDK זה לא יתקין מטפל סיגנל בשביל אתה.** רישום אחד משנה את ההתנהגות של התהליך שלך: listener מדכא את ברירת המחדל של Node, כך שספרייה שהוספה אחת תשתיק בשקט את Ctrl-C מלעבוד. הוסף שלך:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

סקריפט חיים קצר או מטפל serverless צריך `await failproofai.flush()` לפני ההחזרה — המרווח לבדו לא מבטיח משלוח.

## Identity

כל אירוע שייך ל-session וגם ל-agent. **ה-scopes ממלאים את שניהם**, אז אתה רק לעתים נדירות עובר אותם:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

העברה של `sessionId` או `agentId` בחירה גם עובדת ומנצחת. ללא כך שקשור וגם לא עבר, הקריאה מטילה במקום לפעול אירוע שה-Cloud יזלזל בשקט.

<Note>
  Identity רוכב על `AsyncLocalStorage`. היא עוקבת `await`, `.then()`, timers וכל callback שנוצר בתוך ה-scope. היא **לא** עוקבת callback המאוחסן במהלך ריצה אחת והיה צפוי במהלך אחרת, או עבודה שהועברה על פני גבול `worker_threads` — עטוף אלה ב-`failproofai.propagate()` או האירועים שלהם נחתים.
</Note>

### Scopes

| Scope | Emits | Returns |
| --- | --- | --- |
| `session(body)` | nothing — identity only | whatever `body` returns |
| `agent(id, options?, body)` | `agent_start`, then `agent_end` | whatever `body` returns |
| `toolCall(name, options?, body)` | `tool_use`, then `tool_result` | whatever `body` returns |

גוף סינכרוני נשאר סינכרוני: `agent("x", () => 1)` מחזיר `1`, לא הבטחה.

`toolCall` רושם את הערך שפחת של הגוף כ-`output` של הכלי, אלא אם אתה מקצה `call.output` בעצמך.

<Accordion title="Exit semantics" icon="arrow-right-from-bracket">

| What happened | Events | `outcome` |
| --- | --- | --- |
| הבלוק חזר | `agent_end` | `"success"`, or your `outcome` |
| הבלוק הטיל | `error`, then `agent_end` | `"failed"` |
| an `AbortError` | `agent_end` only | `"cancelled"` |

השגיאה תמיד מוטלת מחדש.

כשל בכלי מוקלט על העלה — `tool_result` עם מחרוזת `error` — ואינו משדר אירוע `error` ברמת הריצה. כזו שלולאת ה-agent תופסת אינה כשל בריצה, וכזו שמתפשטת מדווח בדיוק פעם אחת, על ידי ה-`agent()` המקיף.

</Accordion>

<Accordion title="The `using` form" icon="brackets-curly">

כאשר העבודה אינה פונקציה יחידה — scope פתוח בבנייה וסגור בפירוק, או אחד שחוצה זרימת בקרה קיימת:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

שתי הטפוסות משדרות אירועים זהים לבתים. עדיף את הטופס callback: הוא רץ בתוך `AsyncLocalStorage.run()`, אז אין שום דבר להתגלגל והמחלקה כולה של באגים של פתח כאן, סגור שם אינה מעוקה.

`using` block שתופס את הכישלון שלו שלה דיווחים עם `span.fail(error)` — למטפל לא יש ערוץ חריג משלו.

</Accordion>

## Event catalog

אותן חמש עשרה שיטות כמו ה-SDK של Python, בـ camelCase. רבה מהן באות ב**זוגות** — אתה קורא לפותח, ואז לסוגר, וה-SDK מתווה את הפער.

| | Opens | Closes |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Models** | `modelRequest` | `modelResponse` |
| **Tools** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **Humans** | `humanWait` | `humanInput` |

שלוש עומדות לבד: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Every field, per method" icon="table">

כל שיטה גם לוקחת `sessionId` ו-`agentId`, שה-scopes ממלאות בשביל אתה. כל שום דבר השמט הוא ירד בקבלות JSON `null`.

| Method | Required | Optional |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

כל מפתח אחר שאתה מוסיף הופך לשדה עומס מותאם אישית. מרחב כל דבר framework ספציפי `fw_*`; שם שמתנגש עם שדה מוצהר מסרב בקבלות שם של שמירה בשקט על טור מעודן.

</Accordion>

<Warning>
  **`duration_ms` מחושב, לא מקבל.** ארבע השיטות הסוגרות מתווחות את הפער מהפותח שלהן ודחות `duration_ms` בקבלות של קורא — משך דו'ח אינו זיוף.

  זוגות מתאימים על **ה-session** וה-id, לעולם לא על ה-agent. כלי שנפתח תחת `planner` וסגור תחת `worker` עדיין מתאים, מה שמה multi-agent ריצה בעצם עושה.
</Warning>

## Framework adapters

```ts
await failproofai.instrument();              // whatever it can find
await failproofai.instrument("langchain");   // exactly one
failproofai.uninstrument();                  // put everything back
```

| Framework | Supported | How it attaches |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, כדי כל `invoke`/`stream`/`batch` מכוסה ללא עביר `callbacks:` בכול מקום — או לעבור `langchainHandler()` עצמך וטלאה שום דבר. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` באתר הקריאה, או `instrument("ai")` לכל התהליך ב-`ai` 7 (על 4–6 שהוא בחירה — ראה למטה). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, מודל ה-agent ופתרון כלי, ותנוע זרימת עבודה/שלב. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (enrolled) בתוספת `AgentWorkflow.runStream`, לריצת זרימת עבודה ושלבים שלהם. |

כל טווח נבדק כנגד שחרור framework אמיתי, בשני קצוות, כמו מודול ES וכמו CommonJS, על כל ריצת CI.

המיפוי הוא של ה-SDK של Python, כך שאותו תוכנית מציירת אותה עץ בשתי שפות. קונסטרוקט הוא **agent** רק אם היא בעלת לולאת החלטה של LLM — ריצה גרף או שרשרת, קריאה `generateText`/`streamText` של AI SDK, agent של Mastra, ריצה agent של LlamaIndex. צומת LangGraph או שלב זרימת עבודה הוא **hook** (`hook_triggered`/`hook_completed`), לעולם לא agent מקונן. קריאות מודל הן `model_request`/`model_response` זוגות עם ספירת טוקן; קריאות כלי נושאות את ה-id קריאת הכלי שלה של המודל. כשל מוקלט פעם אחת, על האירוע זה קרה בו.

Adapter שנכשל בהתקנה מורשם וחוקר; האחרים עדיין מתקינים, כי LlamaIndex שבור אינו צריך להיות עולים לך LangGraph.

<Note>
  `instrument()` ללא טיעון מגלה framework על ידי הם זה **פתר**, לא אם הוא כבר יובא — Node חושף לא שוויון של Python `sys.modules` לגבי מודולים ES. Framework שהתקנת אבל לא משתמש יובא וטלאה. שם זה שאתה רוצה אם שחקנים זה.
</Note>

<Note>
  רוב מערכות אלה משלח בנייה ES-module ובנייה CommonJS, אשר Node טוען כשתיים קשורות לא. ה-adapters טלאה את ההעתק היישום שלך טוען (וגם ההעתק CommonJS אם משהו כבר `require`d זה), כך שכל מערכות מודול עובדות. Framework **bundled לתוך יחידת שלך** על ידי esbuild או webpack חוץ מהישג — השתמש באתר קריאה עוזרים שם: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain without patching

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

המטפל עובד עם או ללא `instrument()` וקרא לעולם כפול-רישום. `instrument("langchain")` לוקח `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` ו-`captureLimit`, כמו ה-adapter של Python; `metadata: { failproofai_sdk_session_id }` על קריאה בחירות ה-session עבור אמצעי זה.

### Vercel AI SDK

AI SDK ייצוא פונקציות בדוקות מ-ES module, ו-ES module namespace הוא immutable לפי ציון — אין מקום לטלאה. הוא משתמש בנקודות הרחבה SDK עצמו עיצובים:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // on ai 7, `telemetry: telemetry({ … })` — the same object, the new name
});
```

זה השלם integration: agent span, pair model request/response לכל שלב עם ספירת טוקן, וכל קריאת כלי. אתר קריאה אחד עובד על כל ראשי — `ai` 4–6 קריאה את tracer זה נושא, `ai` 7 ה-telemetry integration.

`instrument("ai")` עושה אותו תהליך-רחב **על `ai` 7**: כל קריאה, דרך ה-AI SDK רשימת integration telemetry גלובלי, אשר וספיר ולוקח כלום מ-anybody אחרים.

**על `ai` 4–6, `instrument("ai")` רישומים שום דבר לפי עצמו, ו-logs אזהרה אחת כך.** ה-only תהליך-רחב ווק אלה majors עבור הוא הגלובלי OpenTelemetry tracer provider — חניה יחידה OpenTelemetry מסרב להעביר פעם לקוח. רישום שלנו בשקט היה מסרב שלך `NodeSDK.start()` אחר יותר בהקמה ויעבור http/database spans שלך ל-tracer שמייצא כלום. השתמש ב-`telemetry()` באתר קריאה או `wrapModel` שם. אם התהליך מפעיל שום OpenTelemetry משלו, בחירה עם `instrument("ai", { registerGlobalTracer: true })`: זה אחרי רישומים כל קריאה שעובר `experimental_telemetry: { isEnabled: true }`, וחנויה רק אם זה עדיין ריק. `registerGlobalTracer: false` משמר את ברירת המחדל וקול אזהרה.

אם היית די עטוף מודל פעם, `wrapModel` רואה מודל קריאות בלבד, כי קריאות כלי קורים מעל שכבת מודל. מודל מהופך נקרא עם כלום סביב רושם כשלו מפעיל. קריאה זרם סגור אף כי זרם עצור — `stop_reason: "cancelled"` כאשר צרכן ביטול זה, `"error"` עם שגיאה כאשר זה נכשל חלק-דרך:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

שימוש שניהם בסדר: ה-middleware לו מבחין קריאה כבר להיות רושם וחורה, כל קריאה רושם פעם.

`functionId` שמות ה-agent span. שמור זה נמוך-cardinality — זה נחתים ב-`agent_id`, יחידה דאשבורד facet.

### Next.js

`next build` חבילות תלויות שרת שלך לפי ברירת מחדל, וframework bundled לתוך הבנייה הוא עותק `instrument()` לא יכול להגיע. עטוף הקונפיג פעם וקרא `instrument()` מ-Next hook קנימה:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` מוסיף LangChain, Mastra, LlamaIndex וה-SDK עצמו ל-`serverExternalPackages`, שמירה רשימה שלך. בלי זה, `instrument()` מזהיר פעם אחת לכל framework זה לא יכול להגיע בקבלות כושל בשקט; אם רשימה החבילות עצמך, קבע `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK וקריאה-אתר עוזרים עבודה או דרך. Edge מסלול קובץ בנייה שום דבר: ייבוא SDK בטוח וא רישום כלום.

### Token counts on streamed calls

OpenAI-compatible APIs רק דו"ח שימוש על זרם כאשר הלקוח שואל. LangChain וה-Vercel AI SDK שאל; עבור LlamaIndex לעבור `additionalChatOptions: { stream_options: { include_usage: true } }` ל-`OpenAI` LLM שלו, וה-Mastra בנייה מודל עם שימוש enabled (לדוגמה `createOpenAICompatible({ includeUsage: true })`). אחר זרם מודל קריאות לשא לא טוקן ספירות.

### Runtimes

Node ≥ 20.9, Bun ו-Deno — כל framework, כמו ES module וכמו CommonJS, נבדק על כל נגד Node זה. SDK רץ לצד `failproofaid` daemon, אשר משלח מה שיש כתוב.

## Your own agent — no framework

עבור agent לופ אתה כתוב עצמך, או framework ללא adapter. אתה משדר האירועים עם אותו API adapters להשתמש תחתון, אל כך עקיבות אותו צורה וגודל.

אתה לא צריך לדעת איך ה-agent ארגון. כל בעל-ידיים agent כבר יש שלוש מקומות, מה הפונקציות שלו קרא, ושלוש אלה הן שלם integration:

| Where | What to add | Emits |
| --- | --- | --- |
| איפה **ריצה אחת** מתחיל וגם סיום | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **פונקציה אחת זה קורא לתדר** | `event.modelRequest` לפני, `event.modelResponse` אחרי — שתי החצים, אפילו על כישלון | אחד pair לכל מודל סיבוב |
| **פונקציה אחת זה מפעיל כלים** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Identity הוא שנוך: כל דבר בתוך `agent()` נחתים על זה ריצה session ללא לוקח id, וכלום אחרת בתוכנית שינויים — כולל מה agent כבר כותב ל-database שלו.

- **שירות או עובד:** לעבור id בקשה או עבודה שלך כמו `sessionId`, אל session על הדאשבורד ו-record בלוגים שלך או database אותו מחרוזת.
- **Sub-agents:** gnested `agent()` קריאות. הפנימי אחד מצטרף ה-session עם החיצוני כמו `parent_id`.
- **Emit ה-pairs.** `modelRequest` עם אף לא `modelResponse` הוא span הדאשבורד מראה כמו ריצה לנצח — מכאן ה-`catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) בריפוזיטוריה הוא השלם, runnable גרסה: בפועל OpenAI כלי לולאה עיצוב בדיוק כמו זה, ריצה ב-CI על כל שינוי כמו ES module וכמו CommonJS.

## Evaluations

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

ראה [Evaluator SDK reference](/he/reference/evaluator-sdk) עבור הפרוטוקול, הגדרות עובד וה-types תוצאה.

<Warning>
  **evaluation חייבת להניב.** פונקציה סינכרוני שלעולם לא חוזרים בלוקים ה-one thread Node יש, וא timeout יכול קש כאילו זה עושה. כתוב `async` evaluations.
</Warning>

## What it will not do to your process

| | |
| --- | --- |
| **Block your agent loop** | אירועים ללך לתוך תור בזיכרון; טיימר כותב אותם. הטיימר הוא `unref`'d, כך ייבוא חבילה זו לעולם עצור סקריפט יוצאים. |
| **Grow without bound** | התור הוא capped על ידי ספור *וגם* על ידי מדוד בתים. חלף או, חדשות אירועים discarded וחוקר אזהרה כך — telemetry הפסקה חייבת להיות אינו הוא OOM הרוג. |
| **Take the process down** | כלום unencodable אירוע הוא drop לבד, לא ה-batch סביב זה. סוגר יזרוק, הפניה מעגלית, `BigInt`, לבד surrogate: כל אחד התעשה במקום להתפשט. |
| **Leave a half-written batch** | תוכן היא `fsync`ed לפני atomic שינוי שם, ה-directory היא `fsync`ed אחרי, ו-failed כתיבה נקה זה קובץ זמני. |
| **Leave transcripts readable** | קבוצות הן `0600` בתוך `0700` directory. הם נושאים מטרות, מונעות, כלי טיעונים ו-tool פלט. |
| **Ship credentials** | API מפתחות, tokens, JWTs, bearer ראשים ו-secret עיצוב מטלות redacted לפני הבתים להגיע דיסק. דיימון redacts שוב לפני upload. |
