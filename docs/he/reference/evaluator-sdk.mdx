מעריך מקבל סשן סוכן שהושלם ומחזיר אותות איכות שחשובים לך: ניקוד מספרי, הסבר לכל ניקוד, וסיכום אופציונלי. Failproof AI שומר את התוצאות הללו לצד העקבה ומתווה אותן על פני סוכנים וסביבות.

החבילה היא `agenteye-evaluator`, המיובאת כ-`agenteye_evaluator`. היא דורשת Python 3.10 או חדש יותר וכוללת תלויות על `fastapi`, `pydantic>=2`, ו-`structlog`.

<Warning>
  **`pip install agenteye-evaluator` מ-PyPI הציבורי אינו נתיב ההתקנה.** החבילה מפורסמת רק כחטיבת שחרור פרטית, והשם אינו תפוס ב-PyPI הציבורי — התקנה לא מסומנת עלולה למשוך חבילה של מישהו אחר לשירות שקורא תמלילים בייצור שלך. השתמש בסולם להלן.
</Warning>

## הגדרת מעריך

<Steps>
  <Step title="התקן את ה-SDK">
    עבור במורד לסולם זה והפסק בשלב הראשון שחל עליך.

    בתוך המונורפו, שם קיימת תיקייה `evaluator-sdk/`:

    ```bash
    pip install ./evaluator-sdk
    ```

    אחרת, מהשחרור הפרטי. גלגלים מצורפים ל-GitHub Releases ב-`agenteye-enterprise/releases`, מתויגים `evaluator-sdk/v<version>`, ואתה זקוק ל-`gh auth login` בתוספת גישה למאגר זה:

    ```bash
    gh release download evaluator-sdk/v<version> \
      --repo agenteye-enterprise/releases --pattern '*.whl'
    pip install ./agenteye_evaluator-*.whl
    ```

    אם שום דבר לא עוזר, בקש מאנשי הקשר של Failproof AI שלך את הגלגל במקום לשדל התקנה.

    `uvicorn` בכוונה לא תלות, אז התקן את השרת בנפרד:

    ```bash
    pip install 'uvicorn[standard]'
    ```
  </Step>

  <Step title="הגדר מה לדרג">
    צור `evaluator.py`. דוגמה זו בודקת האם סשן מכיל קריאות כלים שנכשלו.

    ```python
    import os
    from agenteye_evaluator import Evaluator, EvalResponse

    app = Evaluator(token=os.environ.get("EVALUATOR_TOKEN"))

    @app.config
    def config():
        return {"inactivity_timeout_secs": 1800}

    @app.evaluator
    def evaluate(req):
        tool_errors = sum(
            1 for item in req.events
            if item.event_type == "tool_result" and item.payload.get("error")
        )
        return EvalResponse(
            scores={"tool_reliability": 1.0 if tool_errors == 0 else 0.0},
            reasoning={"tool_reliability": f"{tool_errors} tool errors"},
        )
    ```

    הבנאי המלא הוא `Evaluator(token: str | None = None, *, title: str = "AgentEye Evaluator")`. הטוקן מושווה עם `hmac.compare_digest`; `title` הוא כותרת אפליקציית FastAPI וקוסמטי.

    <Warning>
      `token=None` משבית אימות לחלוטין. זה בסדר בלפטופ וחור בייצור, שבו נקודת הקצה מקבלת תמלילי סשן שלמים.
    </Warning>
  </Step>

  <Step title="הפעל ובדוק מקומית">
    קבע טוקן משותף, הפעל את המעריך, ואשר שנקודת הקצה של בריאותו מגיבה.

    ```bash
    export EVALUATOR_TOKEN=<shared-token>
    uvicorn evaluator:app --host 0.0.0.0 --port 8080
    ```

    בטרמינל אחר:

    ```bash
    curl http://127.0.0.1:8080/health
    ```

    כל דקורטור מחזיר את הפונקציה ללא שינוי, כך ש-`evaluate(req)` נשאר קריא ישירות. זה מה שהופך בדיקות יחידה לזולות — בנה `EvalRequest` וקרא למטפל, אין HTTP מעורב.
  </Step>
</Steps>

## חבר את המעריך ל-Failproof AI

1. פרוס את המעריך בכתובת HTTPS שניתן להגיע אליה על ידי Failproof AI Cloud.
2. הגדר את `EVALUATOR_ENDPOINT` עם כתובת זו וקבע את `EVALUATOR_TOKEN` לאותו טוקן המשמש את המעריך. עבור Cloud מנוהל, צור קשר עם [support@befailproof.ai](mailto:support@befailproof.ai) כדי להגדיר את החיבור.
3. הפעל הערכה ואשר שהניקודים שלה מופיעים ב-Failproof AI.

<Tabs>
  <Tab title="לוח בקרה">
    פתח סשן שהושלם תחת **Observe → Sessions** ובחר **Run evaluation** אם לא הוערך באופן אוטומטי. בדוק את הסטטוס, הניקודים, ההיגיון וסיכום בלוח **Evaluation** של הסשן.

    השתמש ב-**Observe → Evaluations** כדי להשוות ניקודים על פני סוכנים או סביבות. השתמש ב-**Observe → Metrics** לקביעת זמן, עלות, טוקן, ומדידות מספריות אחרות.

    התחל עם סשן אחד כדי לאשר שהמעריך החזיר את מפתחות הניקוד הצפויים והיגיון שימושי לרצף ספציפי זה.

## דקורטורים ונתיבים

| דקורטור | נתיב | נדרש |
| --- | --- | --- |
| `@app.evaluator` | `POST /evaluate` | כן. |
| `@app.job_lookup` | `GET /evaluate/{job_id}` | רק אם אי פעם אתה מחזיר `JobPending`. ללא זה, סקירות מקבלות 404. |
| `@app.config` | `GET /config` | לא, אך נדרש לכל סשן שלא פעם משדר `agent_end` — ראה להלן. |

כל דקורטור מקבל פונקציה סינכרוני או אסינכרוני, מחזיר אותה ללא שינוי, וגורם `ValueError` אם אתה רושם אותה פעמיים.

| נתיב | אימות |
| --- | --- |
| `GET /health` | פתוח גם כאשר טוקן מוגדר. |
| `POST /evaluate` | Bearer. |
| `GET /evaluate/{job_id}` | Bearer. |
| `GET /config` | Bearer. |

התאמת סכימת Bearer אינה רגישה לאותיות גדולות וקטנות. `GET /config` ללא `@app.config` רשום עדיין מחזיר `{"default_poll_interval_secs": 10}`, כך ש-SDK תמיד מפרסם קצב.

ה-SDK מגביל את גופי בקשת הערכה ל-25 MiB, בדקו כנגד `Content-Length` לפני שהגוף נקרא. מעל הגבול הוא 413, שהוא 4xx ולכן מסופי. שדות בקשה לא ידועים מתעלמים כך ששירותים נשארים תואמים כחוזה האירוע גדל.

<Warning>
  רישום `@app.config` עם `inactivity_timeout_secs` הוא מה שמאפשר את סורק הנפילה. ללא זה, סשן שלא פעם משדר `agent_end` — כל דבר נטוש, קריסה או עדיין בחלל — לא מנויד לערכה כלל. ערכים של אפס או פחות מוסרים.
</Warning>

## סוגי SDK

| סוג | שדות |
| --- | --- |
| `AgentEvent` | `id`, `ts`, `event_type`, `payload` |
| `EvalRequest` | `schema_version`, `session_id`, `agent_id`, `environment`, `started_at`, `ended_at`, `events` |
| `EvalResponse` | `scores`, `reasoning`, `summary` |
| `JobPending` | `job_id`, `next_poll_secs` |
| `EvaluatorConfig` | `inactivity_timeout_secs`, `default_poll_interval_secs` |

## שדות בקשה והתגובה

| שדה | סוג | הערות |
| --- | --- | --- |
| `EvalRequest.schema_version` | `str` | כרגע `"1"`. |
| `session_id`, `agent_id`, `environment` | `str` | זהות סשן וסביבה. |
| `started_at` | `datetime` | חותמת זמן של האירוע הראשון. |
| `ended_at` | `datetime \| None` | חותמת הזמן של אירוע `agent_end`, לא מה זה עתה הסשן עצר. סשנים במנویד על ידי סורק חוסר הפעילות מעולם לא היו `agent_end` והגיעו `None`. |
| `events` | `list[AgentEvent]` | זרם אירוע מסודר מלא. |
| `AgentEvent.id` | `int` | מזהה שורת אירוע backend. |
| `AgentEvent.ts` | `datetime` | חותמת זמן של אירוע. |
| `AgentEvent.event_type` | `str` | משפחת אירוע כגון `tool_use`. |
| `AgentEvent.payload` | `dict[str, Any]` | כל JSON אירוע משטוח, כך ששדות ספציפיים לאירוע יושבים בשורה עליונה ו-`payload["type"]` משכפל `event_type`. |
| `EvalResponse.scores` | `dict[str, float] \| None` | מימדים מספריים שתרטו בהערכות. |
| `EvalResponse.reasoning` | `dict[str, str] \| None` | הסברים לכל ניקוד; מפתחות צריכים לשקף `scores`. |
| `EvalResponse.summary` | `str \| None` | נרטיב הערכה כללי. קצוצה ב-8192 בתים צד שרת; `last_error` ב-2048. |

הסדרה משתמשת ב-`exclude_none`, כך ששדות לא מוגדרים מושמטים במקום לשלוח כ-`null`.

<Warning>
  הגזירת משך מ-`ended_at` קורסת על נתונים אמיתיים. כל סשן שסורק חוסר הפעילות מנויד מגיע עם `ended_at` מוגדר ל-`None`. בדוק זה לפני הפחתה.
</Warning>

## צורות החזרה

מטפלך עלול להחזיר בדיוק אחד משלוש דברים. כל דבר אחר הוא `TypeError`, המופיע כ-500.

| החזרה | `status` טלגרף | מסופי |
| --- | --- | --- |
| `EvalResponse(...)` | `done` | כן — ניקודים מאוחסנים. |
| `JobPending(job_id=...)` | `pending` | לא — השרת עורך סקר. |
| `dict` גולמי עם `status` ב-`done`, `pending`, או `error` | כמו שניתן | `error` הוא מסופי. |

ה-`error` סטטוס אין לו מודל טיפוסי. כדי להיכשל מסופי, עליך להחזיר dict גולמי, ו-`error` חייב להיות `str` שאינו ריק:

```python
return {"status": "error", "error": "model service unavailable"}
```

<Warning>
  **הרמה אינה דיווח.** חריגה הופכת ל-500 גנרי שגופו הוא `"evaluator raised an internal error"` — טקסט החריגה שלך לא מגיע לשרת, והשרת מתייחס לכל 5xx כחולף וחוזר עליו. החזר את ה-`error` dict כאשר ברצונך לתקן את הכישלון.
</Warning>

## החזר עבודה אסינכרוני

השתמש ב-`JobPending` כאשר הערכה לא יכולה להסתיים בתוך בקשה אחת. מזהה העבודה אטום ל-Failproof AI וחייב להישאר פתיר על ידי שירות שלך עד שהתוצאה נאספת או פעם השרת פקעה.

```python
from agenteye_evaluator import EvalRequest, EvalResponse, Evaluator, JobPending

app = Evaluator(token="shared-secret")

@app.evaluator
def start(req: EvalRequest) -> JobPending:
    job_id = enqueue(req)
    return JobPending(job_id=job_id, next_poll_secs=30)

@app.job_lookup
def lookup(job_id: str):
    result = get_result(job_id)
    if result is None:
        return JobPending(job_id=job_id, next_poll_secs=30)
    return EvalResponse(
        scores=result.scores,
        reasoning=result.reasoning,
        summary=result.summary,
    )
```

קצב סקר נבחר בהזמנה זו: `JobPending.next_poll_secs`, `EvaluatorConfig.default_poll_interval_secs`, ואז `EVALUATOR_POLLING_INTERVAL_SECS` של השרת. ערכים מהודקים בין שנייה אחת לשעה אחת. כובע חדש זומנת של השרת הוא שעה אחת, לאחר מכן התוצאה מתועדת כ-`timeout`.

## הגדרות מפעיל שרת

הערכה אוטומטית היא ברחבי ההטמעה ונשארת בטלה כאשר `EVALUATOR_ENDPOINT` נעדר.

| משתנה | ברירת מחדל | מטרה |
| --- | --- | --- |
| `EVALUATOR_ENDPOINT` | לא מוגדר | כתובת URL בסיס של שירות המעריך. |
| `EVALUATOR_TOKEN` | לא מוגדר | טוקן Bearer משותף עם `Evaluator(token=...)`. |
| `EVALUATOR_WORKERS` | `2` | עובדי מנפיק בו-זמנית. |
| `EVALUATOR_CLAIM_BATCH` | `4` | סשנים תבויים לכל מעבר משדר. |
| `EVALUATOR_POLLING_INTERVAL_SECS` | `10` | קצב הסקר האסינכרוני חוסר ברירה. |
| `EVALUATOR_REQUEST_TIMEOUT_MS` | `30000` | פרק זמן הערכה לכל בקשה, המוחל על POST ולכל סקר. |
| `EVALUATOR_MAX_ATTEMPTS` | `5` | ניסיונות אספקה לפני כישלון מסופי. |
| `EVALUATOR_CONFIG_REFRESH_SECS` | `300` | קצב רענון עבור `/config`. |
| `EVALUATOR_MAX_POLL_DURATION_SECS` | `3600` | משך סקר אסינכרוני זומנת קיר מרבי. |

שתי תוצאות של הטבלה הזו שווה להצהיר בגלוי:

- **עובדים פעמים טענה אצווה הוא הקביעות שלך.** בברירות המחדל שהוא 8 שיחות בו-זמנית כנגד נקודת הקצה שלך, ברחבי ההטמעה. גודל השירות לכמות זו, לא עבור אחד.
- **4xx הוא מסופי ו-5xx, 429, או כישלון תחבורה מתוקן** עם גב עד `EVALUATOR_MAX_ATTEMPTS`. חוסר התאמה של טוקן הוא 401, כך שהוא נכשל מיד במקום להחזור — וזה מה לבדוק ראשון כאשר שום דבר לא מגיע.

השרת יכול גם להגביל אילו ארגונים משתמשים בהמעריך בדיחה גלובלי ההטמעה. התייחס לנקודת קצה, טוקן, חזרה, וארגון-שער שינויים כהגדרת מפעיל והפעל מחדש או גלגל את השרת לאחר שינוים.

## אבטחה ותפעול

- הנח את המעריך מאחורי HTTPS כאשר התנועה חוצה גבול רשת מהימן.
- הגדר טוקן bearer לא ריק והשמור אותו זהה בשני שירותים. `token=None` מקבל כל קורא.
- אל תתעד את הטוקן או הנושאות רגישות מלאות מעומסי בקשה. ה-SDK לא: כישלונות אימות מחזירים 422 ללא הד המשמעת, 500s אל פעם הד טקסט חריגה, והטוקן מופיע בשום שדה יומן.
- הפוך מטפלים סינכרוני בעלות תפלה; ניסיונות חוזרים עלולים לחזור על בקשה.
- התמיד מדינת עבודה אסינכרוני חוץ זיכרון תהליך בייצור.
- החזר מפתחות ניקוד יציבים. שינוי שם מפתח יוצר סדרת תרשים חדשה במקום שינוי הישן.

ה-SDK משדר יומנים סטרוקטוריים לחיים כגון `eval received`, `eval responded`, `job lookup`, `config returned`, `auth rejected`, וחריגות מטפל. `/config` תגובות תג `source="user"` כנגד `source="default"`, כך שתוכל להגיד אם ה-`@app.config` שלך הורים. זה לא הגדרות מטפלי יומן; השתמש בהגדרת יומן של יישום הערכה.
