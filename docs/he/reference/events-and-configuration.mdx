## משפחות אירועים

- התחלה, סיום, השהייה וחידוש של סוכן
- בקשה ותגובה של מודל
- שימוש בכלי ותוצאה
- Hook הופעל והושלם
- המתנת אדם, קלט, השהייה והפסקה
- שגיאות מפורשות

כל אירוע נושא חותמת זמן, מזהה הפעלה, מזהה סוכן, סוג אירוע וסביבה. שדות ספציפיים לאירוע מכילים נתוני מודל, כלים, קורלציה, תוצאה, תוכן, משך זמן או שגיאה.

## בדיקת חוזה אירוע

<Tabs>
  <Tab title="Dashboard">
    1. פתח **Observe → Events**.
    2. הגדר חלון זמן קצר ופלטר לפי סביבה, סוכן וסוג אירוע.
    3. בחר אירוע כדי לבדוק את השדות המנורמלים שלו ותוכן הגולמי שלו, ולאחר מכן פתח את ההפעלה שלו כדי לראות את הקשר לביצוע.
    4. אם משך זמן מזוווג חסר, ודא שאירועי ההתחלה והשלמה משתמשים באותו מזהה קורלציה.

    השתמש בזרם Events כדי לצמצם את הנתונים להפעלה אחת של סוכן ובדוק את שדות האירוע המנורמלים.

    ![זרם Events חי עם מסננים לסביבה, סוכן, הפעלה וסוג אירוע.](/images/dashboard/events-stream.png)

    לאחר מכן עקוב אחר האירוע להפעלה שלו. ה-trace מציג מה קרה מיד לפני ואחרי זה, וזה הכרחי כאשר ה-payload לבדו אינו ברור.

    ![זינוק ה-session המקושר המשמש לבדיקת האירוע בהקשר ביצוע.](/images/dashboard/session-detail.png)

    השווה מזהי קורלציה וחותמות זמן בשתי התצוגות כאשר אירוע מזוווג או משך זמן חסר.
  </Tab>
  <Tab title="CLI">
    גלה ערכי פילטור חוקיים, ואז הבא עלויות אירוע מלא להפעלה אחת:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    השתמש ב-`fp --json events ... --fields ts,event_type,session_id,payload` לבדיקה הניתנת לקריאת מכונה.
  </Tab>
</Tabs>

## שדות SDK שמורים

אל תשתמש ב-`timestamp`, `session_id`, `agent_id`, `type` או `environment` כשדות Python SDK מותאמים. משכי אירוע מזוווגים כגון משך זמן של תוצאת כלים מחושבים על ידי ה-SDK ולא ניתן לספק אותם ידנית.

## גבולות מקומיים

- מצב Failproof AI חי תחת `~/.failproofai` אלא אם צוין אחרת במפורש.
- `failproofai-sdk` משתמש ב-`AGENTEYE_HOME` לעקוף את ספריית הבסיס המסורתי שלו.
- ניתן להגדיר תוויות סביבה דרך קונפיגורציית SDK או `AGENTEYE_ENVIRONMENT`.
- אישורי Daemon מאוחסנים בנפרד מהגדרות שאינן סודיות.

השתמש בשמות סביבה יציבים וקרדינליות נמוכה. פסיקים אינם נתמכים בתוויות סביבת daemon.

## שינוי תווית סביבה

<Tabs>
  <Tab title="Dashboard">
    תוויות סביבה מוקצות על ידי ה-SDK הפולט או daemon של Failproof AI. לאחר שינוי אחד, פתח **Observe → Sessions** והשתמש במסנן הסביבה כדי לאשר שהפעלות חדשות נושאות את הערך החדש. הפעלות קיימות שומרות על הסביבה המקורית שלהן.

  </Tab>
  <Tab title="CLI">
    עבור `failproofai-sdk`, הגדר את הסביבה בקוד או עם משתנה הסביבה המסורתי שלו. הפעל מחדש קונפיגורציית daemon בעת שינוי הגדרות ברמת מכונה.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
