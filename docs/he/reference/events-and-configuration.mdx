## משפחות אירועים

- התחלת סוכן, סיום, השהייה וחידוש
- בקשת דגם והתגובה
- שימוש בכלים והתוצאה
- התפעיל ההוק והושלם
- המתן אדם, קלט, השהייה והפסקה
- שגיאות מפורשות

כל אירוע נושא חתימת זמן, מזהה הפעלה, מזהה סוכן, סוג אירוע וסביבה. שדות ספציפיים לאירוע מכילים נתונים של דגם, כלי, קורלציה, תוצאה, תוכן, משך זמן או שגיאה.

## בדוק חוזה אירוע

<Tabs>
  <Tab title="Dashboard">
    1. פתח **Observe → Events**.
    2. הגדר חלון זמן קצר וסנן לפי סביבה, סוכן וסוג אירוע.
    3. בחר אירוע כדי לבדוק את השדות המנורמלים שלו ותשלום גולמי, ולאחר מכן פתח את ההפעלה שלו כדי לראות את הקשר ההוצאה לפועל.
    4. אם משך זמן מזוודה חסר, אמת שהאירועים של התחלה והשלמה משתמשים באותו מזהה קורלציה.

    השתמש בזרם Events כדי לצמצם את הנתונים לריצת סוכן אחת ובדוק את השדות האירוע המנורמלים.

    ![זרם האירועים החי עם פילטרים לסביבה, סוכן, הפעלה וסוג אירוע.](/images/dashboard/events-stream.png)

    לאחר מכן עקוב אחר האירוע להפעלה שלו. העקיבה מראה מה קרה מיד לפני ואחרי זה, וזה הכרחי כאשר התשלום לבדו אינו חד משמעי.

    ![עקיבת ההפעלה המקושרת המשמשת לבדוק את האירוע בהקשר הביצוע.](/images/dashboard/session-detail.png)

    השוו מזהי קורלציה וחתימות זמן בשתי התצוגות כאשר אירוע מזוודה או משך זמן חסר.
  </Tab>
  <Tab title="CLI">
    גלה ערכי סינון חוקיים, ולאחר מכן אחזר תשלומי אירוע מלאים להפעלה אחת:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    השתמש ב-`fp --json events ... --fields ts,event_type,session_id,payload` לבדיקה הניתנת לקריאה של מכונה.
  </Tab>
</Tabs>

## שדות SDK שמורים

אל תשתמש ב-`timestamp`, `session_id`, `agent_id`, `type` או `environment` כשדות SDK מותאמים אישית ב-Python. משכי אירועים מזווגים כמו משך זמן תוצאת כלי מחושבים על ידי ה-SDK ולא ניתן לספק אותם ידנית.

## גבולות מקומיים

- מצב Failproof AI גר תחת `~/.failproofai` אלא אם כן מוגדר אחרת בבירור.
- `failproofai-sdk` תמיד משדר תחת `~/.failproofai/custom-agents`. `FAILPROOFAI_HOME` מעביר את הבית הזה; הקטע `custom-agents` תמיד מוצמד, ולכן לא ניתן למקם את הספול מחוצה לו. רק ה-`configure(base_dir=...)` שלו כתב במקום אחר. `AGENTEYE_HOME` נקרא על ידי ה-`agenteye-collector` הישן כדי לבחור מה לצפות, וכבר לא משפיע על המקום בו ה-SDK כותב.
- ניתן להגדיר תוויות סביבה דרך קונפיגורציית SDK או `AGENTEYE_ENVIRONMENT`.
- אישורי Daemon מאוחסנים בנפרד מהגדרות שאינן סודיות.

השתמש בשמות סביבה יציבים וקטנים-קרדינליות. פסיקים אינם נתמכים בתוויות סביבת daemon.

## שנה תווית סביבה

<Tabs>
  <Tab title="Dashboard">
    תוויות סביבה מוקצות על ידי ה-SDK הפולט או daemon של Failproof. לאחר שינוי אחד, פתח **Observe → Sessions** והשתמש בפילטר הסביבה כדי לאשר שהפעלות חדשות נושאות את הערך החדש. הפעלות קיימות שומרות על הסביבה המקורית שלהן.

  </Tab>
  <Tab title="CLI">
    עבור `failproofai-sdk`, קונפיגור את הסביבה בקוד או עם משתנה הסביבה הישן שלו. הפעל מחדש את קונפיגורציית daemon בעת שינוי הגדרות ברמת מכונה.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
