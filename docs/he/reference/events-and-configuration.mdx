## שתי אוצרות מילים של אירועים

Failproof AI מנהל שני סוגים שונים של אירועים, ואף פעם הם לא חולקים שם.

| אוצר מילים | מיוצר על ידי | שמות נראים כמו | הפניה |
| --- | --- | --- | --- |
| אירועי טלמטריה | `failproofai-sdk`, מתוך הסוכן שלך | `tool_use`, `tool_result`, `hook_triggered`, `model_response` | [Python SDK](/he/reference/custom-agents) |
| אירועי Hook | הסוכן harness, מנורמל על ידי failproofai | `PreToolUse`, `PostToolUse`, `Stop`, `UserPromptSubmit` | [מדיניות מותאמת](/he/reference/policy-sdk#choose-the-event) |

צד ה-hook מנרמל את שמות האירוע העצמיים של כל harness ל-29 סוגים קנוניים. צד הטלמטריה כולל 15 שיטות וחוזה שדה משלו. `hook_triggered` ו-`PreToolUse` אינם שתי דרכים לאיות דבר אחד.

## משפחות אירועים

- התחלה, סיום, השהייה וחידוש הסוכן
- בקשת מודל והתגובה
- שימוש ותוצאה של כלי
- Hook הופעל והושלם
- המתנת אדם, קלט, השהייה והפרעה
- שגיאות מפורשות

כל אירוע כולל חותמת זמן, מזהה סשן, מזהה סוכן, סוג אירוע וסביבה. שדות ספציפיים לאירוע מכילים מודל, כלי, קורלציה, תוצאה, תוכן, משך זמן או נתוני שגיאה.

## בדוק חוזה אירוע

<Tabs>
  <Tab title="לוח בקרה">
    1. פתח את **Observe → Events**.
    2. הגדר חלון זמן קצר וסנן לפי סביבה, סוכן וסוג אירוע.
    3. בחר אירוע כדי לבדוק את השדות המנורמלים שלו וה-payload גולמי, ואז פתח את הסשן שלו כדי לראות את הקשר של ההוצאה לפועל.
    4. אם משך זמן בזוג חסר, אמת כי אירועי ההתחלה ההשלמה משתמשים באותו מזהה קורלציה.

    השתמש בזרם Events כדי לצמצם את הנתונים להפעלה אחת של סוכן ובדוק את שדות האירוע המנורמלים.

    ![זרם Events חי עם מסננים לסביבה, סוכן, סשן וסוג אירוע.](/images/dashboard/events-stream.png)

    לאחר מכן עקוב אחר האירוע לתוך הסשן שלו. ה-trace מציג מה קרה מיד לפני ואחרי אותו, וזה נחוץ כאשר ה-payload לבדו עמום.

    ![עקבת הסשן המקושרת המשמשת לבדיקת האירוע בהקשר הוצאה לפועל.](/images/dashboard/session-detail.png)

    השווה את מזהי הקורלציה וחותמות הזמן בשתי התצוגות כאשר אירוע בזוג או משך זמן חסר.
  </Tab>
  <Tab title="CLI">
    גלה ערכי מסננים תקפים, ואז אחזר payload אירועים מלא לסשן אחד:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    השתמש ב-`fp --json events ... --fields ts,event_type,session_id,payload` לבדיקה קריאה לקורא מכונה.
  </Tab>

## שדות SDK שמורים

חמישה שמות נדחים בחומרה כשדות מותאמים, משום ש-SDK מגדיר אותם בכל אירוע:

`timestamp`, `session_id`, `agent_id`, `type`, `environment`.

עוד אחד עשר מתקבלים אך בדוקים לסוג, משום שנקודת הקצה של הטמעת רשימה מוציאה אותם מה-payload לעמודות מוקלדות ובשתיקה אחסנים `NULL` לכל דבר מהסוג הלא נכון. ה-SDK מעלה במקום זאת, בנקודת הקריאה שבה עדיין תוכל לראות מה הפיק את הערך.

| שמות | סוג נדרש |
| --- | --- |
| `duration_ms`, `input_tokens`, `output_tokens` | `int`, בטווח 32-ביט לא חתום. float או bool מעלה. |
| `tool_name`, `tool_call_id`, `hook_name`, `hook_id`, `input_id`, `pause_id`, `error_type`, `model` | `str`. `None` מעלה, משום שהשורה תגיע ב-200 OK ותהיה בלתי נראית לכל מסנן בשדה זה. |

### משכי זמן

ה-SDK מודד את הפער בין ארבעה אירועים בזוג ודוחה `duration_ms` שאתה עובר בעצמך: `tool_use` → `tool_result`, `hook_triggered` → `hook_completed`, `agent_pause` → `agent_resume`, ו-`human_wait` → `human_input`.

`model_response` הוא החריג. ה-SDK אף פעם לא מודד קריאות מודל, כך שאתה מספק `duration_ms` בעצמך, כמספר שלם של אלפיות השנייה. ראה [כללי קורלציה](/he/reference/custom-agents) כיצד זוג מתאים.

## גבולות מקומיים

- מצב Failproof AI חי תחת `~/.failproofai` אלא אם הוא מוגדר במפורש אחרת.
- `failproofai-sdk` תמיד מטיל תחת `~/.failproofai/custom-agents`. `FAILPROOFAI_HOME` משנה את הבית הזה; הקטע `custom-agents` תמיד מצורף, כך שהסנה לא יכול להיות ממוקם מחוצה לו. רק ה-SDK שלו `configure(base_dir=...)` כותב במקום אחר. `AGENTEYE_HOME` נקרא על ידי ה-`agenteye-collector` הישן יותר כדי לבחור מה לצפות, וכבר לא משפיע על היכן ה-SDK כותב.
- אישורים חיים ב-`~/.failproofai/credentials.json`, כתוב `0600`. הם בכוונה לא ב-`config.json`, הכתוב בכתיבה פשוטה וירושת ה-umask, כך שהוא נוחת קריא לכל משתמש מקומי בתיבה.

השתמש בשמות סביבה יציבים ובעלי קרדינליות נמוכה. פסיק נדחה בשני הכותבים: ה-daemon דוחה אחד ב-`collector.environment`, וה-SDK מעלה ב-`configure(environment=...)`. הסיבה זהה משני הצדדים — נקודת הקצה של הטמעת רשימה מחלקת שדה זה בפסיקים ודילג על השורה כולה, מענה `200 OK` תוך שמאחסן כלום.

## קונפיגורציה של מכונה

ההגדרות שאינן סודיות של ה-daemon הן `~/.failproofai/config.json`. `hooks_verbosity`, `redact` ו-`environment` אין להם דגל CLI — ערוך את הקובץ ישירות. `sessions`, `hooks` ו-`machine_id` נכתבים על ידי `failproofai config` כאשר הוא מחבר מכונה זו לענן.

| מפתח | ערכים | ברירת מחדל | מה היא שולטת |
| --- | --- | --- | --- |
| `collector.sessions` | `true` / `false` | `false`, ו-`true` ברגע שתתחבר לענן | שלח תמלילי סשן סוכן. תמליל נושא הנמקות, תכני קבצים וכל מה שהדביקו לטרמינל. |
| `collector.hooks` | `true` / `false` | `true` | שלח פעילות hook. נושא החלטות ושמות כלים, לא תוכני קבצים. |
| `collector.hooks_verbosity` | `all` / `decisions` / `off` | `decisions` | `decisions` שומר כל deny ו-instruct מדוקדק ומצטבר את הערך 99% בערך המאפשרים. |
| `collector.redact` | `minimal` / `off` | `minimal` | השחקה מיושמת לפני שום דבר עוזב את המכונה. |
| `collector.environment` | כל מחרוזת ללא פסיק | `local` | התווית שחותומה על כל אירוע שמכונה זו שולחת. |
| `collector.machine_id` | כל מחרוזת | מזהה כבר על הדיסק, אחרת UUID אקראי טרי | איזה מכונה לוח הבקרה מקבץ נתונים זה תחתיה. נכתב על ידי `--machine-id`. זה לעולם לא נגזר מ-hostname. |

<Note>
  `failproofai backfill --help` שמות `~/.failproofai/config.toml`. זה נתיב מיושן מתוך פריסה בבית קודמת; אף בנייה נוכחית לא כותבת אותה. הקובץ הוא `config.json`.
</Note>

התחברות לענן שולחת גם החלטות מדיניות וגם תמלילי סשן מלאים.

<Warning>
  `--no-transcripts` לא מכבה תמלילים בנתיב ההגדרה. `failproofai config --token <key> --no-transcripts` מנתח את הדגל ואז לעולם לא קורא אותו, והוכשר מתחבר עם הפעלות בכל זאת, כך תמלילים ממשיכים לשלוח בעוד אתה מאמין שהרשעת.

  כדי לשלוח החלטות בלבד, הגדר את `collector.sessions` ל-`false` ב-`~/.failproofai/config.json` לאחר התחברות:

    ```json
  {
    "collector": {
      "sessions": false
    }
  }
    ```
</Warning>

backfill עוקב אחר הגדרות האספן זהות, כך שהוא לעולם לא שולח משהו שהקונפיגורציה שלך אומרת שאתה לא רוצה. שליחה חוזרת בטוחה: השחקה היא דטרמיניסטית, כך שאירוע המשודר מחדש מתפתל זהה לשליחה הראשונה שלו ומתמוטט לשורה שכבר שם.

## שנה תווית סביבה

ה-SDK וה-daemon כל אחד חותם את התווית שלהם, והם מוגדרים במקומות שונים.

<Tabs>
  <Tab title="Python SDK">
    הגדר אותו בקוד, או בסביבה של התהליך הפולט את האירועים. ברירת המחדל היא `dev`.

    ```python
    import failproofai_sdk

    failproofai_sdk.configure(environment="production-us-east")
    ```

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    ```

    `AGENTEYE_ENVIRONMENT` נקרא רק על ידי `failproofai-sdk`. לא CLI ולא daemon קוראים אותו, כך שייצוא זה לא משנה כלום לגבי המכונה.
  </Tab>
  <Tab title="Daemon">
    ערוך את `collector.environment` ב-`~/.failproofai/config.json`. ברירת המחדל היא `local` ואף דגל CLI אינו מגדיר אותה.

    ```json
    {
      "collector": {
        "environment": "production-us-east"
      }
    }
    ```

    ```bash
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
  <Tab title="לוח בקרה">
    תוויות סביבה מוקצות על ידי ה-SDK הפולט או Failproof daemon, כך שאין כלום לשנות כאן. לאחר שינוי אחד במקורו, פתח **Observe → Sessions** והשתמש במסנן הסביבה כדי לאשר סשנים חדשים נושאים את הערך החדש. סשנים קיימים שומרים על הסביבה המקורית שלהם.
  </Tab>
</Tabs>
