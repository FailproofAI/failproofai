## משפחות אירועים

- התחלת Agent, סיום, השהייה וחידוש
- בקשה ותגובה של מודל
- שימוש בכלי וקבלת תוצאה
- Hook שהופעל והושלם
- המתנה אנושית, קלט, השהייה והפרעה
- שגיאות מפורשות

כל אירוע נושא חותם זמן, מזהה session, מזהה Agent, סוג אירוע וסביבה. שדות ספציפיים לאירוע מכילים נתונים של מודל, כלי, קורלציה, תוצאה, תוכן, משך זמן או שגיאה.

## בדוק חוזה אירוע

<Tabs>
  <Tab title="Dashboard">
    1. פתח **Observe → Events**.
    2. הגדר חלון זמן קצר וסנן לפי סביבה, Agent וסוג אירוע.
    3. בחר אירוע כדי לבדוק את השדות המנורמלים שלו והעומס הגולמי שלו, ואז פתח את ה-session שלו כדי לראות את הקשר של הביצוע.
    4. אם משך זמן בזוג חסר, וודא שאירועי ההתחלה והסיום משתמשים באותו מזהה קורלציה.

    השתמש בזרם Events כדי לצמצם את הנתונים לביצוע Agent אחד ובדוק את שדות האירוע המנורמלים.

    ![זרם Events חי עם מסננים לסביבה, Agent, session וסוג אירוע.](/images/dashboard/events-stream.png)

    לאחר מכן עקוב אחר האירוע ל-session שלו. ה-trace מראה מה קרה מיד לפני ואחרי, וזה הכרחי כאשר העומס לבדו אינו ברור.

    ![ה-session trace המקושר המשמש לבדיקת האירוע בהקשר הביצוע.](/images/dashboard/session-detail.png)

    השווה מזהי קורלציה וחותמי זמן בשתי התצוגות כאשר אירוע בזוג או משך זמן חסר.
  </Tab>
  <Tab title="CLI">
    גלה ערכי סינון תקפים, ואז אחזר עומסי אירוע מלאים עבור session אחד:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    השתמש ב-`fp --json events ... --fields ts,event_type,session_id,payload` לבדיקה הניתנת לקריאה של מכונה.
  </Tab>
</Tabs>

## שדות SDK שמורים

אל תשתמש ב-`timestamp`, `session_id`, `agent_id`, `type` או `environment` כשדות Python SDK מותאמים אישית. משכי אירועים בזוג כגון משך זמן של תוצאת כלי מחושבים על ידי ה-SDK ולא ניתן לספקם באופן ידני.

## גבולות מקומיים

- מצב Failproof AI חי תחת `~/.failproofai` אלא אם צוין אחרת.
- `failproofai-sdk` תמיד ממטיל תחת `~/.failproofai/custom-agents`. `FAILPROOFAI_HOME` מעביר את הבית הזה; קטע `custom-agents` תמיד מובחן, כך שלא ניתן להנחות את ההשפלה מחוצה לו. רק `configure(base_dir=...)` של ה-SDK עצמו כותב במקום אחר. `AGENTEYE_HOME` נקרא על ידי `agenteye-collector` הישן בחירת מה להקשיב, וכבר לא משפיע על כתיבת ה-SDK.
- ניתן להגדיר תוויות סביבה דרך קונפיגורציית SDK או `AGENTEYE_ENVIRONMENT`.
- אישורי Daemon מאוחסנים בנפרד מהגדרות שאינן סודיות.

השתמש בשמות סביבה יציבים וקטנים. פסיקים אינם נתמכים בתוויות סביבה של Daemon.

## שינוי תווית סביבה

<Tabs>
  <Tab title="Dashboard">
    תוויות סביבה מוקצות על ידי ה-SDK הפולט או Failproof daemon. לאחר שינוי של אחד, פתח **Observe → Sessions** והשתמש בסינון הסביבה כדי לאשר שסשנים חדשים נושאים את הערך החדש. סשנים קיימים שומרים על הסביבה המקורית שלהם.

  </Tab>
  <Tab title="CLI">
    עבור `failproofai-sdk`, הגדר את הסביבה בקוד או עם משתנה הסביבה הישן שלה. הפעל מחדש את קונפיגורציית Daemon בעת שינוי הגדרות ברמת המכונה.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
