התקן את ה-CLI המקומי עם `npm install -g failproofai`. הפעל אותו ללא ארגומנטים כדי לפתוח את לוח הבקרה של המדיניות המקומית.

החבילה דורשת Node.js 20.9 או חדש יותר. Bun 1.3 או חדש יותר נתמך לפיתוח והתקנות מקורות. `failproofai configure` ו-`failproofai setup` הם כינויים עבור `failproofai config`. `failproofai policy`, `failproofai pack` ו-`failproofai p` הם כולם ניסוחים של `failproofai policies` — packs ומדיניויות יחידות היו שלוש פקודות לרעיון אחד והם כעת אחד. הניסוחים הישנים עדיין עובדים, עם שני חריגים: `pack list <source>` הוא כעת `policies show <source>`, ו-`pack build` הוא כעת `publish`.

## הגדר מכונה

התקן את ה-CLI, ואז קרא את מפתח המכונה לתוך ה-shell. `read -s` לוקח אותו בהודעת-זימון שלא משקפת, כך שהוא לעולם לא מופיע בפקודה:

```bash
npm install -g failproofai
read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
```

ואז הגדר את המכונה ובחר מה היא תאכוף:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

`failproofai config` הוא כל ההגדרה: היא מתקינה את שירות `failproofaid` (root פעם אחת — בטרמינל היא שואלת את סיסמת ה-sudo שלך, ושואלת שוב אם היא פקעה לפני הסיום; ללא טרמינל היא משתמשת ב-`sudo -n` ולעולם לא מציעה בקשה), חוטים hooks לכל agent CLI שהיא מוצאת, והתחברות ל-Cloud. ללא טרמינל — CI, קונטיינר, agent המנהל את זה — היא חלה במקום לשאול, ויוצאת 1 אם משהו שהיא התבקשה לעשות לא קרה.

בטרמינל, שלב ה-**Connect to cloud** במכונה שעדיין לא מחוברת מתחיל **logging in to FailproofAI Cloud** מיד; לחץ על Tab עבור האפשרויות האחרות, **Paste an API key** או **Use open source**. ההתחברות פותחת קישור — או מדפיסה אותו על SSH או ללא תצוגה, כדי לפתוח בכל מכשיר — שבו אתה נרשם או נכנס, בוחר או יוצר ארגון, ומאשר את המכונה; הטרמינל קולט את האישור בעצמו ומציג מי אישר את זה ולאיזה ארגון. המפתח מוטבע רק כאשר ההגדרה מסתיימת, לאחר התקנת ה-daemon. במכונה שכבר מחוברת עם מפתח עובד, השלב הוא תפריט עם **Keep current connection** ראשון, כך שהפעלה חוזרת של setup לעולם לא פותחת דפדפן בעצמה; מפתח שמור שכבר לא עובד מתחיל להתחבר שוב מיד, ואומר למה. ההתחברות שוב יוצרת מפתח חדש ומשאירה את הישן לעבוד עד שאתה מבטל אותו. Cloud מלפני browser login אומר כך ומציע את האפשרויות האחרות.

היא בוחרת **no** policies. זו עבודתה של הפקודה השנייה, וללא זה מכונה שהוגדרה זה עתה לא תאכוף שום דבר אלא ה-always-on guard.

העדף את משתנה הסביבה על `--token`: טיעון שורת פקודה קריא מ-`ps` על ידי כל משתמש בתיבה. זה כל מה שהמשתנה מגן עליו — מפתח שהוקלד לכל פקודה, `export` כלול, עדיין נוחת בהיסטוריית ה-shell, וזו הסיבה שהוא נקרא עם `read -s` למעלה. ב-CI, הגדר אותו מחנות הסודות והשאר את ה-shell tracing (`set -x`) כבוי, או העקבות מדפיסים אותו.

<Warning>
  `--connect <url>` רושם מכונה שכבר **מוגדרת**. היא חוזרת ברגע שההנייה מצליחה — היא לא מתקינה את ה-daemon ואינה חוטה hooks. השתמש ב-`failproofai config` פשוט (או `failproofai config --token <key>`) במכונה שלא הוגדרה עדיין, או היא תקרא כמתחברת בעת אסיפה ואכיפה של שום דבר.
</Warning>

הרץ `failproofai` ללא ארגומנטים כדי לפתוח את לוח הבקרה של המדיניות המקומית.

| פקודה | תוצאה |
| --- | --- |
| `failproofai config` | הגדר את המכונה: agents, daemon, ו-Cloud — התחבר דרך הדפדפן, הדבק מפתח, או הישאר open source. כל agent במכונה מקבל גם מיומנות קטנה של `failproofai` שמצביעה עליה ב-[FailproofAI skills](https://github.com/FailproofAI/skills) באינטרנט |
| `failproofai config --token <key>` | הגדר והתחבר בפעם אחת, ללא שאלות. מפתח שנושא `jev:evaluate` גם מפעיל את [Jev through FailproofAI Cloud](/he/reference/jev-cloud) במצב observe, אלא אם כן `jev.json` כבר קיים או `--no-transcripts` ניתן |
| `failproofai config --connect <url>` | רשום מכונה שכבר **מוגדרת** — ללא daemon, ללא hooks |
| `failproofai config --status` | הצג חיבור, daemon, delivery, ו-pause state |
| `failproofai policies` | רשום builtin, custom, convention, pack, ו-Cloud-managed policies |
| `failproofai policies --install` | חוט hooks לתוך agent CLIs שלך. לא מאפשר שום מדיניות בפני עצמו |
| `failproofai policies add <name>` | הפעל מדיניות אחת — builtin, או `<pack-id>:<name>` מ-pack מותקן |
| `failproofai policies remove <name>` | כבה מדיניות אחת, אותה הנמקה |
| `failproofai policies --uninstall` | כבה policies או הסר harness hooks |
| `failproofai policies show <owner>/<repo>` | מה pack נושא, קרא מ-manifest שלו, לפני שאתה לוקח את זה |
| `failproofai policies show <owner>/<repo> --releases` | כל גרסה שהוא פרסם, ואיזה אחד כאן |
| `failproofai policies add <source>` | התקן policy pack מ-GitHub release; ללא tag לוקח את החדש ביותר וקובע אותו |
| `failproofai publish` | שלח את המדיניויות שלך כ-pack; `--init` כותב אחד כדי להתחיל ממנו, ו-`--min-cli-version <version>` קובע את ה-CLI הישן ביותר שעשוי להתקין אותו ([Jev checks in a pack](/he/policies/publish-a-pack#jev-checks-in-a-pack)) |
| `failproofai policies remove <publisher/name>` | הסר pack |
| `failproofai audit` | סרוק היסטוריית agent מקומית והצג את התצוגה audit המקומית |
| `failproofai audit --schedule [days] --email <address>` | תזמן סריקות מקומיות חוזרות וצור דוח על הממצאים שלהן |
| `failproofai audit --status` | הצג את כתובת הדוח, המרווח, והסריקה הקבועה הבאה |
| `failproofai audit --no-schedule` | עצור סריקות חוזרות ללא מחיקת היסטוריית audit |
| `failproofai harness list` | רשום נתיבי capture נוספים |
| `failproofai otel status` | בדוק דיווח [OpenTelemetry](/he/reference/otel) אופציונלי |
| `failproofai jev --url <url> --key-stdin` | הגדר את Jev בצעד אחד; הספק נלקח מ-host של ה-URL |
| `failproofai jev setup --provider <kind> --key-stdin` | אפשר ל-[Jev](/he/reference/jev-providers) לשפוט tool calls דרך endpoint ו-key שלך |
| `failproofai jev setup --provider failproofai` | אפשר לJev לשפוט tool calls [through FailproofAI Cloud](/he/reference/jev-cloud), עם Cloud key של מכונה זו |
| `failproofai jev setup --mode <m>` | עבור את מצב Jev: `enforce`, `observe`, או `off` (שמור את הקונפיג, עצור לבקש Jev) |
| `failproofai jev status` | הצג את Jev config, ההרשאות שלו ופלפולים אחרונים; לעולם לא המפתח |
| `failproofai jev test` | שלח בקשת Jev חיה אחת והצג את latency וגרסה שלה; יוצא 1 כאשר התשובה מאוחרת עבור hooks או שגויה |
| `failproofai jev models` | רשום את model ids ש-`GET <base>/models` אומר endpoint משרת |
| `failproofai jev remove` | כבה Jev; hooks הרץ את regex policies בדיוק כמו קודם |
| `failproofai flush --wait` | הנמק את ה-event spool הנוכחי |
| `failproofai backfill --since 30d` | קרא שוב היסטוריה שעברה קודם לכן |
| `failproofai config --pause [duration]` | השהה sitzung מקומי אחד ל-30 דקות כברירת מחדל, עד 8 שעות |
| `failproofai config --resume` | חדש sitzung מקומי מושהה אחד; הוסף `--all` כדי לנקות את כל ההשהיות |
| `failproofai update` | סיים הגדרות חבילה והדק את ה-daemon |
| `failproofai migrate --dry-run` | תצוגה מקדימה או הפעלה של הגדרות בית ממתינות |
| `failproofai uninstall` | הסר hooks, את המיומנות `failproofai` ו-daemon לפני הסרת החבילה |
| `failproofai --version` | הדפס את גרסת החבילה המותקנת |
| `failproofai --help` | הצג פקודות ושימוש גלובלי |

## דגלי הגדרה

| דגל | שימוש |
| --- | --- |
| `--token <key>` | הגדר והתחבר ללא אינטראקציה; גם קרא מ-`FAILPROOFAI_CLOUD_TOKEN` |
| `--url <url>` | התחבר למקום אחר מאשר `app.befailproof.ai`; גם קרא מ-`FAILPROOFAI_CLOUD_URL` |
| `--connect <url>` | רושם בלבד, במכונה שכבר מוגדרת. מדלג על ה-daemon וכל hook |
| `--machine-id <id>` | הגדר את machine ID היציב |
| `--machine-label <name>` | שנה שם למכונה שכבר **מחוברת**. בפני עצמו הוא לעולם לא מפעיל setup, לכן תן אותו לאחר `failproofai config`, לא בזמן |
| `--no-transcripts` | שלח החלטות ללא תוכן כתוב, ואל תפעיל Cloud Jev, שישלח כל tool call שנבדק וה-prompt האחרון; `jev.json` שהשאיר את Jev דרך FailproofAI Cloud הוסר |
| `--disconnect` | עצור Cloud policy pulls ו-event delivery. גם מסיר את Cloud Jev key ו-`jev.json` שמנהל את FailproofAI Cloud; ההגדרה Jev שלך נשמרת במקום |
| `--status` | הצג מצב מכונה נוכחי |
| `--pause [duration]` | השהה את ה-session החדש ביותר בתיקייה הנוכחית; מקבל שניות, דקות, או שעות וברירת מחדל 30 דקות |
| `--resume` | סיים pause תואם מוקדם |
| `--session <id>` | כוון session מפורש ל-pause או resume |
| `--all` | עם `--resume`, סיים כל pause פעיל |

השהיות מקומיות משעות builtin, custom, convention, ו-pack policies לsitzung אחד. הן תמיד פוקעות ואינן משבית Cloud-managed policies. `block-failproofai-commands` — שתמיד פעיל ולא יכול להיות משביתו או השהיה בעצמו — מונע agent מיוצר מלהשתמש בדרך הבריחה זו.

## דגלי מדיניות

| דגל | שימוש |
| --- | --- |
| `--install`, `-i` | התקן harness hooks. שמות אחריו מאפשרים את המדיניויות הללו; ללא כל דבר, ללא שינויי מדיניות |
| `--uninstall`, `-u` | כבה policies או הסר hooks |
| `--cli <names...>` | כוון harness אחד או יותר נתמך |
| `--scope user\|project\|local\|all` | בחר את scope ההגדרה; `all` ל-uninstall |
| `--beta` | כלול beta policies |
| `--custom`, `-c <path>` | אמת וטען קובץ מדיניות מותאם; חוזרת |

## דגלי delivery ותחזוקה

| פקודה | דגלים |
| --- | --- |
| `backfill` | `--since <30d\|6m\|YYYY-MM-DD>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` |

`failproofai update` צריך להיות מופעל לאחר `npm install -g failproofai@latest`; היא מבצעת הגדרות בית, מתקינה את binary daemon המתאים, ומפעילה את השירות מחדש. היא אז מעבירה כל Hermes profile שכבר משתמש ב-FailproofAI לתוסף native המקושר ומדפיסה שורה אחת לפי profile. `--no-daemon` מדלג על שלב ה-daemon. `update` יוצא non-zero כאשר daemon לא יכול להיות מוחלף, הגדרה נכשלה, או Hermes profile לא יכול להיות מהורה (לדוגמה כי ה-daemon הפועל לא יכול להשרת את תוסף native, במקרה זה shell hooks שלו נשארו במקום).

## Harness paths

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

שמות harness נתמכים הם `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, ו-`goose`.

Labels namespace derived agent IDs כאשר שני roots מכילים עותקים של אותו פרויקט. Overlapping roots ו-duplicate labels נדחים כדי למנוע collection כפול או cursor corruption. תצורת extra-path טוען מחדש ללא daemon restart.

סביבות קונטיינר יכולות להחליף קבצים מוגדרים נתיבים נוספים עם משתנה מופרד בפסיק בשם `FAILPROOFAI_<HARNESS>_EXTRA_PATHS`, לדוגמה:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## משתני סביבה

השתמש בקבצי הגדרה להתנהגות מכונה קבועה. משתני סביבה הם שימושיים ביותר עבור קונטיינרים, בדיקות, ותהליך אחד.

| משתנה | שימוש |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | Cloud key, במקום `--token`. העדף את זה: טיעון קריא מ-`ps` על ידי כל משתמש. הגדר אותו עם `read -s` או מחנות סודות CI, לעולם לא על ידי הקלדת המפתח לפקודה, שנוחת בהיסטוריית shell כך או כך |
| `FAILPROOFAI_CLOUD_URL` | Cloud URL, במקום `--url`. אותו משתנה שה-daemon קורא |
| `FAILPROOFAI_HOME` | שהעבר את `~/.failproofai` layout כמו |
| `FAILPROOFAI_LOG_LEVEL` | הגדר רמת logging מקומית |
| `FAILPROOFAI_HOOK_LOG_FILE` | כתוב hook diagnostics לקובץ נבחר |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | השבת telemetry אנונימי תהליך זה |
| `FAILPROOFAI_NO_FIRST_RUN=1` | דלג על setup first-run אינטראקטיבי |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | דלג על audit מקומי post-setup |
| `FAILPROOFAI_LLM_BASE_URL` | עקוף את OpenAI-compatible endpoint משמש LLM policies |
| `FAILPROOFAI_LLM_API_KEY` | ספק את API key משמש LLM policies |
| `FAILPROOFAI_LLM_MODEL` | בחר את המודל משמש LLM policies |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | Bound custom policy module loading |
| `FAILPROOFAI_NO_DOWNLOAD=1` | סרב להביא packs ו-daemon binaries; מה מותקן ממשיך אכיפה |
| `FAILPROOFAI_PACK_BASE_URL` | תביא packs מ-mirror במקום `github.com` |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | החלף נתיבי capture נוספים מוגדרים ל-harness אחד |
| `NO_COLOR` | השבת צבע טרמינל |

Agent-specific home משתנים כגון `CLAUDE_PROJECTS_PATH`, `CURSOR_HOME`, `HERMES_HOME`, ו-`OPENCLAW_HOME` עוקפים היכן Failproof AI גילוי local sessions ל-harness זה.

## השהה או הסר מכונה בבטחה

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

pause local session לא משביתה Cloud-managed policies. שחזר Cloud deployments דרך Cloud enforcement workflow כאשר ה-rollout עצמו הוא הבעיה.

לפני הסרת החבילה npm, הסר installed hooks ו-daemon:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

הרץ `failproofai <command> --help` לפרטים ספציפיים לגרסה.

<Warning>
  הרץ `failproofai uninstall` לפני `npm rm -g failproofai`; npm לא מסיר installed agent hooks, מיומנות `failproofai` או שירות daemon.
</Warning>
