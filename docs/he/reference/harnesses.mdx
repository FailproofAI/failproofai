חיבור הוא כל מה שהסוכן שלך בעצם רץ בתוכו. Failproof AI תומך בשנים עשר מהם, בשתי קטגוריות:

- **ממשקי שורת פקודה לקידוד** (10) — Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Factory Droid, Devin CLI, Antigravity CLI, Goose
- **שערי צ'אט ועוזרים** (2) — Hermes (Slack, Telegram, cron), OpenClaw (עוזר מארח עצמאי)

אותן מדיניויות והיסטוריית הפעלות זהה חלים לפי איזה חיבור הסוכן רץ בו. שכבת מתאם אחת ממפה את שמות האירועים המקוריים של כל חיבור, שמות הכלים ושדות קלט כלים ל-29 אירועים קנוניים לפני הרצת כל מדיניות.

סוכן שרץ ב**אף אחד** מ-12 החיבורים מקבל אינסטרומנטציה ישירה עם [Python SDK](/he/reference/custom-agents). זה חוזה שונה, ומעיר זאת בבירור: ה-SDK מספק מעקב, הפעלות, הערכות וביקורות — **הוא לא אוכף מדיניות בעצמו.** חסימת פעולה לא בטוחה לפני ההוצאה לפועל דורשת hook אכיפה בגבול הכלים של הזמן ריצה שלך; [צרו איתנו קשר](mailto:support@befailproof.ai) והנו נמפה את זה.

## טווחי Hook

| חיבור | טווחי hook נתמכים |
| --- | --- |
| Claude Code | משתמש, פרויקט, מקומי |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | משתמש, פרויקט |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | משתמש, פרויקט |
| Hermes, OpenClaw | משתמש |

Claude Code הוא החיבור היחיד עם טווח **מקומי**. Hermes ו-OpenClaw אין להם כל תצורת פרויקט — הם רק טווח משתמש, והממשק בשורת הפקודה דוחה `--scope project` עבורם.

כל אינטגרציה מנרמלת את שמות אירועי ה-hook המקוריים שלה, שמות כלים ושדות קלט כלים לפני הרצת מדיניויות. מדיניות יכולה לפעול רק על אירועים שהחיבור חושף; בדקו התנהגות של סוף תור והנחיות בחיבור וגרסה המדוקדקים שבהם אתם פורסים.

## יכולת אכיפה

"Block" פירושו שגזירת החיזור של המתאם הנוכחי נצרכת על ידי החיבור שצוין. חסימה לאחר כלי עשויה להחליף את התוצאה שהוצגה למודל אך אינה יכולה להחזיר בחזור תופעת צד של כלים שכבר התרחשה.

| חיבור | אירועי חסימה מאומתים | הערות חסימה יחיד-צפייה או לא-חוסמים |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact` ומספר אירועי משימה/תצורה | `PostToolUse`, מחזור חיים הפעלה, התראות ואירועים לאחר כשל הם תצפיתיים. |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | חסימה לאחר כלי מחליפה את התוצאה לאחר ביצוע; אירועי התחלת הפעלה וקומפקטי הם תצפיתיים במתאם הנוכחי. |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | חסימה לאחר כלי מחליפה את התוצאה לאחר ביצוע; אירועי הפעלה והתראה הם תצפיתיים. |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` ואירועי הפעלה הם תצפיתיים. |
| OpenCode | `PreToolUse` | אירועים לאחר כלי ומחזור חיים הם תצפיתיים; טיפול עצירה נוכחי הוא הנחיה לתור מאוחר יותר ולא שער מאומת. `PermissionRequest` לא פועל כלל. |
| Pi | `PreToolUse`, `UserPromptSubmit` | אירועים לאחר כלי ומחזור חיים הם תצפיתיים; הנחיית עצירה חלה על תור מאוחר יותר. |
| Hermes | `PreToolUse` | הערכות לאחר כלי, הפעלה וסוף סוכן-תת אינם שערים. אין אירוע `Stop` מותקן. |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | אירועים לאחר כלי, הפעלה, סוף סוכן-תת וקומפקטציה הם תצפיתיים. |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | הערכות לאחר כלי וסוף סוכן-תת הן תצפיתיות. |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PermissionRequest` מותנה | hooks הרשאה לא פועלות בכל מצב הרשאה; אירועים לאחר כלי והפעלה הם תצפיתיים. |
| Antigravity CLI | `PreToolUse`, `Stop` | גזירות הנחיית משתמש ולאחר כלי הן תצפיתיות; הנחיות הנחיה עדיין יכולות להיות מוזרקות. |
| Goose | `PreToolUse` | אירועי הנחיית משתמש, לאחר כלי והפעלה הם תצפיתיים. קיים hook עצירה חוסם מקורי במעלה אך לא מותקן על ידי המתאם הנוכחי. |

אירוע שחסר משתי עמודות הוא **לא מאומת** — התייחסו אליו כלא ידוע, לעולם לא כחוסם.

### תנאים על שער רשום

מספר שורות למעלה הן שערים אמיתיים שעם זאת מוגבלים או מותנים. מדיניות התלויה באחד מאלה צריכה את התנאי בדיוק כמו את השורה.

| חיבור | אירוע | תנאי |
| --- | --- | --- |
| Claude Code | `Stop`, `SubagentStop` | מוגבל על ידי `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`, ברירת מחדל 8. הושלך בנתיבי סוף-תור |
| Cursor | `Stop` | מוגבל על ידי `loop_limit`, ברירת מחדל 5, וצרוך רק כאשר התור מסתיים — ביטול משתמש או שגיאת תור משליכים אותו |
| Cursor | `Stop` | **Cursor Cloud Agent VMs אינם מריצים hooks `stop` או `subagentStop` כלל.** השער מכסה הפעלות מקומיות בלבד |
| Codex | `SubagentStop` | רק ThreadSpawn subagents משדרים את זה; כל מקור subagent אחר לא מעולם מריץ את ה-hook |
| GitHub Copilot CLI | `SubagentStop` | דלג לחלוטין עבור subagents `isSidekick` |
| Devin CLI | `PermissionRequest` | לא מופעל תחת `--permission-mode dangerous`, ולא עבור כלים אוטומטיים קריאה-בלבד מאושרים |
| OpenCode | `PermissionRequest` | hook מת: `permission.ask` מוצהר ותיעד במעלה אך לא מעולם מופעל, כך שהמדיניות לא אפילו מופעלת |
| Hermes | `Stop` | אין אירוע `Stop` מותקן, בבחירה. חמישת `require-*-before-stop` הבנויים הם חלים על Hermes |
| Goose | `Stop` | אותה תוצאה: לא `Stop` מותקן, כך שחמישת `require-*-before-stop` הבנויים הם חלים |

### היכן `instruct()` מתדרדר

`deny` אינה ההערכה היחידה שמדיניות מחזירה. `instruct()` נותן לסוכן הנחיה ומאפשר לפעולה להמשיך — אך לא לכל חיבור יש ערוץ לשאת אחת. היכן שאין, failproofai מאפשר את הפעולה וכותב את ההנחיה ל-stderr לקלטות של המפעיל; המודל לא רואה את זה.

| חיבור | אירועים שבהם `instruct()` מתדרדר להערה stderr |
| --- | --- |
| Hermes | כל אירוע |
| Goose | כל אירוע |
| Pi | כל אירוע פרט ל-`Stop` |
| OpenClaw | כל אירוע פרט ל-`Stop` |
| Factory Droid | כל אירוע פרט ל-`Stop` |
| Antigravity CLI | כל אירוע פרט ל-`Stop` ו-`UserPromptSubmit` |

בכל מקום אחר, ההנחיה מוחזרת דרך ערוץ הקשר נוסף של החיבור שלו.

## מצב סוכן VS Code

מצב סוכן Copilot Chat המובנה של VS Code **אינו אינטגרציה שלוש עשרה**. הוא מגלה תצורת hook מ-`.github/hooks/*.json`, `~/.copilot/hooks/*.json` ו-`~/.claude/settings.json` — בדיוק הנתיבים שה-`copilot` ו-`claude` מתקנות כבר כתובים — ומשתמש בחוזה deny בצורת Claude זהה. התקנה של אחד כבר אוכפת בתוך הפעלות מצב סוכן VS Code.

התכונה היא תצוגה מקדימה וזקוקה למנוי GitHub Copilot פעיל בתוספת מצב סוכן.

## התקן hooks צפייה ומדיניות

<Tabs>
  <Tab title="Dashboard">
    1. פתחו **Administration → Keys** וצרו מפתח עם `events:add` ו-`policies:pull`, שם לפי המכונה או הסביבה.
    2. במכונה היעד, חברו את ה-CLI המקומי עם המפתח המוצג.
    3. התחילו הפעלת סוכן חדשה, ולאחר מכן אשרו את hook וחיזור אירועי ההפעלה שלה תחת **Observe → Events**.
    4. פתחו **Observe → policy** עבור אותו חלון זמן ואשרו שהחלטת מדיניות מיוחסת למכונה.

    התחברות מתחילה עם מפתח מכונה. אשרו שהוא כולל הרשאות אינג'סט וחלוקת מדיניות לפני העתקת הסוד שלה.

    ![המגירה של מפתח API חדש המשמשת להעניית הרשאות אינג'סט מדיניות ו-delivery.](/images/dashboard/key-create.png)

    לאחר התקנת ה-hooks, זרם Events צריך להציג אירועים חדשים מהמכונה והסביבה שחברתם.

    ![זרם Events החי המשמש לאימות שחיבור harness שהותקן לאחרונה מדווח.](/images/dashboard/events-stream.png)

    לבסוף, אשרו שהחלטות מדיניות מיוחסות לאותה מכונה. זה מאשר שהחיבור מדווח על פעילות מדיניות כמו גם אירועי זיהוי.

    ![דף המדיניות המשמש לאימות החלטות מדיניות מחיבור harness המחובר לאחרונה.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    `failproofai config` חוטים hooks לכל CLI סוכן נתמך שהוא מוצא, מתקין את הדיימון, וחיבורי Cloud כאשר מפתח קיים:

    ```bash
    failproofai config --token <machine-key>
    failproofai policies add FailproofAI/policies
    ```

    ההגדרה בוחרת אין מדיניויות, וזו הסיבה שהפקודה השנייה שם.

    לחוט חיבור אחד ביד — עם `--cli` הושמט, `--install` מגלה מה מותקן ו­­­asks:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    טווח פרויקט שומר תצורת hook עם מאגר. טווח משתמש מכסה עבודה על פני מאגרים. בדוק את טבלת ה-scope למעלה לפני שילוב `--cli` ו-`--scope`; ה-CLI דוחה זוג לא נתמך.

    אשרו את המכונה ואירועיה:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

<Warning>
  בהרצות headless `copilot -p` שהתחילו מתיקייה טרייה, הפרויקט-scope `.github/hooks/failproofai.json` **לא** נטען. התייחסו לטווח משתמש כנקודת אכיפה אמינה עבור Copilot ב-CI עד שזה מאומת אחרת.
</Warning>

## הוסף נתיב הפעלה לא-ברירת מחדל

<Tabs>
  <Tab title="Dashboard">
    נתיבים נוספים רושמים על המכונה, לא בעננו. לאחר הוספת אחד, פתחו **Observe → Sessions**, סננו לסביבת המכונה, ואשרו הפעלות מהנתיב החדש מופיעות. פתחו הפעלה ובדקו את הסוכן, החיבור, וחותמות זמן אירוע לפני התאמה עליו בביקורת.

    ![רשימת ה-Sessions מסוננת לסביבה שמקבלת נתונים מנתיב צפייה נוסף.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    הוסף נתיב עם תווית אופציונלית, ולאחר מכן בחן את הנתיבים המוגדרים:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    הסר נתיב עם `failproofai harness remove-path claude checkout`.

    התווית מרחב שמות זיהויות סוכן נגזרות. שתי מיקומים המחזיקים עותקים של אותו פרויקט מפיקים את אותו id מהתמליל, כך בלא תווית הם מתמזגים לסוכן אחד. שורשים חופפים ותוויות כפולות מסורבות — ראה [ה-CLI reference](/he/reference/failproof-cli) למה כל דחיה קיימת.
  </Tab>
</Tabs>

<Tip>
  הרץ הפעלה חדשה אחת לאחר התקנה. אשרו גם את זרם האירועים החי וגם החלטת מדיניות ממשית לפני הרחבת ההטבעה.
</Tip>
