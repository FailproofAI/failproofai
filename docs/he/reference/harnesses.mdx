Failproof AI תומך ב-Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Hermes, OpenClaw, Factory Droid, Devin CLI, Antigravity CLI, ו-Goose.

| חיבור | scope של hook נתמך |
| --- | --- |
| Claude Code | User, project, local |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | User, project |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | User, project |
| Hermes, OpenClaw | User |

כל אינטגרציה מנרמלת את שמות אירועי ה-hook המקוריים שלה, שמות הכלים, ושדות ה-tool-input לפני הפעלת מדיניות. מדיניות יכולה לפעול רק על אירועים שה-harness חושף; בדוק התנהגות end-of-turn והוראה בדיוק על ה-harness והגרסה שאתה פורס.

## יכולת הטלת חוק

"Block" פירושו שהוועדה שהוחזרה מהמתאם הנוכחי נצרכת על ידי ה-harness המסוים. חסימה לאחר כלי עשויה להחליף את התוצאה המוצגת למודל אך לא יכולה לשנות השפעה צדדית של כלי שכבר התרחשה.

| חיבור | אירועי חסימה מאומתים | זהירויות שנצפות בלבד או לא בעלות חסימה |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact`, וכמה אירועים של משימה/תצורה | `PostToolUse`, מחזור חיים של הפעלה, הודעות, ואירועים לאחר כשל הם תצפיתיים. |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | חסימה לאחר כלי מחליפה את התוצאה לאחר הביצוע; אירועי התחלת הפעלה וקיבוץ הם תצפיתיים במתאם הנוכחי. |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | חסימה לאחר כלי מחליפה את התוצאה לאחר הביצוע; אירועי הפעלה והודעה הם תצפיתיים. |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` ואירועי הפעלה הם תצפיתיים. |
| OpenCode | `PreToolUse` | אירועים לאחר כלי ומחזור חיים הם תצפיתיים; טיפול Stop נוכחי הוא הדרכה לתור מאוחר יותר ולא שער מאומת. |
| Pi | `PreToolUse`, `UserPromptSubmit` | אירועים לאחר כלי ומחזור חיים הם תצפיתיים; הדרכת stop חלה על תור מאוחר יותר. |
| Hermes | `PreToolUse` | וועדות לאחר כלי, הפעלה, וחסימת subagent אינן שערים. |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | אירועים לאחר כלי, הפעלה, subagent-stop, וקיבוץ הם תצפיתיים. |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | וועדות לאחר כלי וחסימת subagent הן תצפיתיות. |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, מותנה `PermissionRequest` | hook של הרשאה אינם פועלים בכל מצב הרשאה; אירועים לאחר כלי והפעלה הם תצפיתיים. |
| Antigravity CLI | `PreToolUse`, `Stop` | וועדות של user-prompt ולאחר כלי הן תצפיתיות; הוראות prompt עדיין ניתן להזריק. |
| Goose | `PreToolUse` | אירועים של user-prompt, לאחר כלי, והפעלה הם תצפיתיים. hook stop בעל חסימה מקוריות קיימת בעל זרם אך לא מותקנת על ידי המתאם הנוכחי. |

יכולות רגישות לגרסה. בדוק מחדש לאחר שדרוג ממשק CLI של agent, במיוחד כאשר מדיניות מסתמכת על התנהגות prompt, stop, permission, או post-tool במקום השער pre-tool הנפוץ.

## התקן capture וhooks של מדיניות

<Tabs>
  <Tab title="Dashboard">
    1. פתח **Administration → Keys** וצור מפתח עם `events:add` ו-`policies:pull`, ששמו מיועד למכונה או סביבה.
    2. במכונת היעד, חבר את ממשק ה-CLI המקומי עם המפתח המוצג והתקן את ה-harness hooks.
    3. התחל הפעלת agent חדשה, ואז אשר את האירועים של hook והפעלה שלה תחת **Observe → Events**.
    4. פתח **Observe → policy** לאותו חלון זמן ואשר שהחלטת מדיניות מיוחסת למכונה.

    החיבור מתחיל עם מפתח של מכונה. אשר שהוא כולל הן הרשאות הספיגה והן הרשאות מסירת מדיניות לפני העתקת ההסוד שלו.

    ![מגירת מפתח API חדשה המשמשת להעניית הרשאות ספיגה ומסירת מדיניות.](/images/dashboard/key-create.png)

    לאחר התקנת ה-hooks, זרם ה-Events צריך להציג אירועים חדשים מהמכונה והסביבה שהתחברת אליה.

    ![זרם ה-Events החי המשמש לאישור ש-harness שהותקן זה עתה מדווח.](/images/dashboard/events-stream.png)

    לבסוף, אשר שהחלטות מדיניות מיוחסות לאותה מכונה. זה מאשר שה-harness מדווח על פעילות מדיניות וכן על אירועי עקיבה.

    ![עמוד המדיניות המשמש לאימות החלטות מדיניות מ-harness שחובר זה עתה.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    התקן hooks לכל harness שנגלה:

    ```bash
    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>
    failproofai policies --install
    ```

    או היעד לשם harnesses ול-scope של תצורה:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    Project scope שמור hook תצורה עם מאגר. User scope מכסה עבודה על פני מאגרים. Claude Code תומך גם ב-local scope; התמיכה משתנה לפי harness וה-CLI דוחה שילובים שלא נתמכו.

    אשר את המכונה והאירועים שלה:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## הוסף נתיב הפעלה שאינו ברירת מחדל

<Tabs>
  <Tab title="Dashboard">
    נתיבים נוספים רשומים על המכונה, לא בענן. לאחר הוספת אחד, פתח **Observe → Sessions**, סנן לסביבה של המכונה, ואשר שהפעלות מהנתיב החדש מופיעות. פתח הפעלה ובדוק את ה-agent, harness, וחותמות זמן של אירוע לפני שתעשה בהן שימוש בביקורת.

    ![רשימת ה-Sessions המסוננת לסביבה המקבלת נתונים מנתיב ה-capture הנוסף.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    הוסף נתיב עם תווית אופציונלית, ואז בדוק את הנתיבים המוגדרים:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    הסר נתיב עם `failproofai harness remove-path claude checkout`.
  </Tab>
</Tabs>

<Tip>
  הפעל הפעלה חדשה אחת לאחר ההתקנה. אשר גם את זרם האירועים החי וגם החלטת מדיניות בפועל לפני הרחבת ה-rollout.
</Tip>
