חיבור הוא כל מה שהסוכן שלך בעצם רץ בתוכו. Failproof AI תומך בשנים עשר מהם, בשתי קטגוריות:

- **CLI קודינג** (10) — Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Factory Droid, Devin CLI, Antigravity CLI, Goose
- **שערים לצ'אט ועוזרים** (2) — Hermes (Slack, Telegram, cron), OpenClaw (עוזר אירוח עצמי)

אותן מדיניות ואותו היסטוריית הפעלה חלים על כל חיבור שהסוכן רץ בתוכו. שכבת מתאם אחת ממפה את שמות האירועים המקוריים של כל חיבור, שמות הכלים ושדות קלט כלים על 29 אירועים קנוניים לפני הפעלת כל מדיניות.

סוכן שרץ בשום אחד מהשנים עשר מתורגם ישירות עם [Python SDK](/he/reference/custom-agents). זה חוזה שונה, וכדאי להציג בבירור: ה-SDK מספק עקיבה, הפעלות, הערכות וביקורות — **הוא לא אוכף מדיניות בעצמו.** חסימת פעולה בלתי בטוחה לפני ביצוע דורשת חוק אכיפה בגבול הכלים של זמן הריצה שלך; [צור קשר איתנו](mailto:support@befailproof.ai) ואנחנו נממפה את זה.

| חיבור | טווח חוקים נתמך |
| --- | --- |
| Claude Code | משתמש, פרויקט, מקומי |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | משתמש, פרויקט |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | משתמש, פרויקט |
| Hermes, OpenClaw | משתמש |

כל אינטגרציה מנרמלת שמות אירועי חוקים מקוריים, שמות כלים ושדות קלט כלים לפני הפעלת מדיניות. מדיניות יכולה לפעול רק על אירועים שהחיבור חושף; בדוק התנהגות סוף תור והדרכה בחיבור ובגרסה המדויקים שבהם תפרוס.

## יכולת אכיפה

"חסום" פירושו שהוצאת הגזר של המתאם הנוכחי נצרכת על ידי החיבור המצוין. חסימה לאחר הכלי עשויה להחליף את התוצאה המוצגת למודל אך לא יכולה לבטל אפקט צד של כלי שכבר התרחש.

| חיבור | אירועי חסימה מאומתים | אזהרות ללא חסימה או ללא חסימה |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact`, ואירועי משימה/קונפיגורציה נוספים | `PostToolUse`, מחזור חיים הפעלה, הודעות, ואירועים לאחר כשל הם תצפיתניים. |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | חסימה לאחר כלי מחליפה את התוצאה לאחר ביצוע; אירועי התחלת הפעלה וקומפקטיות הם תצפיתניים במתאם הנוכחי. |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | חסימה לאחר כלי מחליפה את התוצאה לאחר ביצוע; אירועי הפעלה והודעה הם תצפיתניים. |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` ואירועי הפעלה הם תצפיתניים. |
| OpenCode | `PreToolUse` | אירועי לאחר כלי ומחזור חיים הם תצפיתניים; טיפול עצירה נוכחי הוא הדרכה לתור מאוחר יותר ולא שער מאומת. |
| Pi | `PreToolUse`, `UserPromptSubmit` | אירועי לאחר כלי ומחזור חיים הם תצפיתניים; הדרכת עצירה חלה על תור מאוחר יותר. |
| Hermes | `PreToolUse` | גזרי לאחר כלי, הפעלה וסוכן-עצירה הם לא שערים. |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | אירועי לאחר כלי, הפעלה, סוכן-עצירה וקומפקטיות הם תצפיתניים. |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | גזרי לאחר כלי וסוכן-עצירה הם תצפיתניים. |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, תנאי `PermissionRequest` | חוקי הרשאה לא רצים בכל מצב הרשאה; אירועי לאחר כלי והפעלה הם תצפיתניים. |
| Antigravity CLI | `PreToolUse`, `Stop` | גזרי הנמקה משתמש ולאחר כלי הם תצפיתניים; הוראות הנמקה עדיין יכולות להיות מוזרקות. |
| Goose | `PreToolUse` | אירועי הנמקה משתמש, לאחר כלי והפעלה הם תצפיתניים. חוק עצירה חסימה מקומי קיים במעלה הזרם אך אינו מותקן על ידי המתאם הנוכחי. |

יכולות תלויות גרסה. בדוק מחדש לאחר שדרוג CLI של סוכן, במיוחד כאשר מדיניות מסתמכת על התנהגות הנמקה, עצירה, הרשאה או לאחר כלי במקום השער הקדם-כלים הנפוץ.

## התקן חיבורי תפיסה וחוקים

<Tabs>
  <Tab title="לוח בקרה">
    1. פתח **ניהול → מפתחות** וצור מפתח עם `events:add` ו-`policies:pull`, בשם המכונה או הסביבה.
    2. במכונת היעד, חבר את ה-CLI המקומי עם המפתח המוצג והתקן את חיבורי החוק.
    3. התחל הפעלת סוכן חדשה, ואז אשר את אירועי החוק וההפעלה שלה תחת **צפוי → אירועים**.
    4. פתח **צפוי → מדיניות** לאותו חלון זמן ואשר שהחלטת מדיניות מיוחסת למכונה.

    החיבור מתחיל עם מפתח מכונה. אשר שהוא כולל הן הרשאות הטלה וקבלת מדיניות לפני העתקת הסוד שלו.

    ![המגירה מפתח API החדשה המשמשת להעניק הרשאות הטלה ושילוח מדיניות.](/images/dashboard/key-create.png)

    לאחר התקנת החוקים, זרם האירועים צריך להראות אירועים חדשים מהמכונה והסביבה שחיברת.

    ![זרם האירועים הלייב המשמש לאישור הדוח החדש של חיבור.](/images/dashboard/events-stream.png)

    לבסוף, אשר שהחלטות מדיניות מיוחסות לאותה מכונה. זה מאשר שהחיבור דוגל בפעילות מדיניות כמו גם אירועי עקיבה.

    ![דף המדיניות המשמש לאימות החלטות מדיניות מחיבור מחובר חדש.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    התקן חוקים לכל חיבור שזוהה:

    ```bash
    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>
    failproofai policies --install
    ```

    או עבור חיבורים ממוקדים וטווח קונפיגורציה:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    טווח פרויקט שומר קונפיגורציה חוק עם מאגר. טווח משתמש מכסה עבודה על פני מאגרים. Claude Code תומך גם בטווח מקומי; התמיכה משתנה לפי חיבור וה-CLI דוחה שילובים בלתי נתמכים.

    אשר את המכונה והאירועים שלה:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## הוסף נתיב הפעלה שאינו ברירת מחדל

<Tabs>
  <Tab title="לוח בקרה">
    נתיבים נוספים רשומים במכונה, לא בקלאוד. לאחר הוספת אחד, פתח **צפוי → הפעלות**, סנן לסביבת המכונה, ואשר שהפעלות מהנתיב החדש מופיעות. פתח הפעלה וחפש את הסוכן, החיבור וחותמות הזמן של אירועים לפני הסתמכות עליה בביקורת.

    ![רשימת ההפעלות מסוננת לסביבה המקבלת נתונים מנתיב התפיסה הנוסף.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    הוסף נתיב עם תווית אופציונלית, ואז בדוק את הנתיבים המוגדרים:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    הסר נתיב עם `failproofai harness remove-path claude checkout`.
  </Tab>
</Tabs>

<Tip>
  הפעל הפעלה חדשה אחת לאחר התקנה. אשר גם את זרם האירועים הלייב וגם החלטת מדיניות בפועל לפני הרחבת ההוצאה.
</Tip>
