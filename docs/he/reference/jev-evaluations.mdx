עמוד זה מתאר את צורות השאלות וכללי הניקוד מאחורי [Jev evaluations](/he/evaluations/jev). חלק מהשאלות דורשות מודל *לקרוא* את השיחה, אך לא *לכתוב* עליה. "האם הלקוח הביע דחיפות?" יש שתי תשובות. "כמה מתוסכלים הם היו?" יש כמה, בסדר. אתה יודע כל תשובה לפני שאתה שואל.

**classifier evaluation** היא בדיוק לאלה. אתה כותב את השאלה והתשובות שהיא עשויה לתת, ומודל קטן שנבנה לסיווג מחזיר מספר מכויל — לא קטע טקסט חופשי.

<Note>
כמו שופט, classifier evaluation עולה קריאה למודל לכל סשן. בשונה ממנו זהו מודל קטן, בעל מטרה יחידה, וזה מהיר וזול יותר — אך הוא לא יסביר את עצמו. אם אתה צריך את ההנמקה, השתמש ב-[judge](/he/evaluations/judge).
</Note>

## איזה אחד אני רוצה?

| שאלה | השתמש ב |
| --- | --- |
| כמה קריאות כלים היו? | code |
| האם הסשן היה פחות מ-30 שניות? | code |
| האם הלקוח הביע דחיפות? | **classifier** |
| איזה צוות צריך להתמודד עם זה: billing, technical, או sales? | **classifier** |
| כמה מתוסכל היה הלקוח? | **classifier** |
| האם התשובה באמת הייתה נכונה? | **judge** |
| האם זה עקב את מדיניות ההסלמה שלנו, ולמה אתה חושב שכן? | **judge** |

הכלל של אצבע: **countable → code, תשובות שאתה יכול לרשום → classifier, צריך הסבר → judge.**

אתה לא חייב להחליט מראש. תאר את מה שאתה רוצה למדוד והעוזר בוחר, אומר לך איזה הוא בחר ולמה, ואתה יכול להחליף.

## שני סוגי השאלות

### `noul` — האם זה נכון?

שתי תשובות, ואתה מתאר את שתיהן. התוצאה היא ההסתברות שתיאור "true" מתאים:

```json
{
  "instructions": "Did the assistant promise a refund without first checking the refund policy?",
  "criteria": {
    "true":  "A refund was promised or issued with no prior policy check or approval",
    "false": "No refund was promised, or every refund followed a policy check"
  }
}
```

תאר את שני הצדדים. "לא בוטא כל דחיפות" היא תשובה אמיתית וההשמטה שלה הופכת את השנייה לחדה יותר.

### `score` — כמה מזה?

rubric מסודר, **הגרוע ביותר ראשון**. התוצאה היא היכן הסשן נוחת עליו, שנשנה לקנה מידה של 0–1:

```json
{
  "instructions": "How frustrated is the customer?",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
```

**rubric לוקח שלוש עד חמש רמות, והן חייבות להיות שונות.** שתי הגבולות נמדדים, לא סגנוני:

- **שתי רמות** מתכנסות למה ש-`noul` כבר עושה טוב יותר, ו**יותר מחמש** גורם למודל להתנודד לכיוון האמצע במקום להתחייב. אותה שאלה על אותו סשן קיבלה ניקוד 0.00 עם שתי רמות, 0.01 עם שלוש, ו-0.55 עם עשר.
- **רמות חוזרות** מחלקות את התשובה בשרירותיות ביניהן. סשן שהיה ללא ספק כועס קיבל ניקוד 1.00 מול `["Calm", "Frustrated", "Very angry"]` ו-0.66 מול `["Angry", "Angry", "Angry"]` — מספר שנוצר היטב שאין לו משמעות.

קטגוריות ללא סדר — "billing, technical, או sales" — אינן rubric. שאל אותן כ-`noul` לכל קטגוריה, או השתמש בשופט.

## קריאת התוצאות

classifier מייצר **score** מ-0 עד 1, בדיוק כמו שופט, כך שהוא תרשימים, מסנן ותריגרים התראות בדרך זהה. שתי הבדלים כדאי לדעת:

- **אין הנמקה.** השדה ריק, בכוונה. מודל זה לא מסביר את עצמו, והמצאת הסבר תהיה זיוף ולא תכונה.
- **אי-ודאות מסומנת.** שאלת `score` דיווחים על הביטחון שלו, ותוצאה שהמודל היה לא בטוח בה מתויגת `low_confidence` — כך "אילו מאלה צריך אדם להסתכל עליה" היא מסנן ולא ניחוש. שאלת `noul` לא דיווחת ביטחון, כך שהיא לא מסומנת לעולם.

סשנים ארוכים מאוד נקראים בקטעים ומשולבים. כאשר סשן ארוך מדי כדי לקרוא במלואו, התוצאה אומרת כמה תורים הושמטו — לעולם לא תראה שיפוט שנעשה על חלק מסשן שהוצג כאחד שנעשה על כולו.

## מגבלות

- **שלוש עד חמש רמות rubric, כולן מובחנות.** ראה לעיל; שני הגבולות מאומתים בעת הכתיבה.
- **שאלה אחת לכל evaluation.** אם תשאל שני דברים, תקבל שתי evaluations, שזה גם מה שאתה רוצה בתרשים.
- **עריכת השאלה מפרסמת גרסה חדשה.** ניקודים ישנים וחדשים אינם ניתנים להשוואה, כך שהם נשמרים בנפרד במקום להתערבב לקו מגמה אחד.
- **classifier תמיד מייצר score**, לא מטריקה או קביעה.
- **אין הנמקה**, כפי שלעיל. אם מספר יגרום למישהו לשאול "למה?", כתוב שופט במקום זאת.

## בדיקה והחזר

בשונה משופט, classifier evaluation **יכולה** להיבדק לפני שתעביר אותה — [בדוק אותה](/he/evaluations/test) מול סשנים אמיתיים באותו אופן שבו תבדוק evaluation של קוד, וקרא את הניקודים לפני שכל דבר יוצא לפועל.

זה יכול גם להיות [backfilled](/he/evaluations/deploy#score-sessions-you-already-have) על סשנים שכבר יש לך. זה עולה קריאה למודל לכל סשן, כך שתחום את החלון בכוונה כבול מאשר לחזור על הכל.
