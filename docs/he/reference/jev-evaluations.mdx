דף זה מתאר את צורות השאלות וכללי ההערכה מאחורי [Jev evaluations](/he/evaluations/jev). בחלק מהשאלות נדרש למודל *לקרוא* את השיחה, אך לא *לכתוב* עליה. "האם הלקוח הביע דחיפות?" יש שתי תשובות. "כמה מתוסכלים היו?" יש כמה תשובות, בסדר מסוים. אתה יודע כל תשובה לפני שאתה שואל.

**הערכת מסווג** (classifier evaluation) היא בדיוק לאלה. אתה כותב את השאלה והתשובות שהיא עלולה לתת, ומודל קטן שנבנה לסיווג מחזיר מספר מכוילן — לעולם לא טקסט חופשי.

<Note>
כמו שופט, הערכת מסווג עולה קריאה אחת של מודל לכל סשן. בניגוד לשופט, זהו מודל קטן חד-מטרתי ולא כללי, כך שזה מהיר וזול יותר — אך זה לעולם לא יסביר את עצמו. אם אתה צריך את ההנמקה, השתמש ב-[judge](/he/evaluations/judge).
</Note>

## איזה אני רוצה?

| שאלה | שימוש |
| --- | --- |
| כמה קריאות כלים היו? | code |
| האם הסשן היה מתחת ל-30 שניות? | code |
| האם הלקוח הביע דחיפות? | **classifier** |
| איזה צוות צריך לטפל בזה: חיובים, טכני או מכירות? | **classifier** |
| כמה מתוסכל היה הלקוח? | **classifier** |
| האם התשובה הייתה למעשה נכונה? | **judge** |
| האם זה עקב את מדיניות ההסלמה שלנו, ולמה אתה חושב שכן? | **judge** |

כלל הבוט: **ניתן לספירה → code, תשובות שאתה יכול לרשום → classifier, זקוק להסברה → judge.**

אתה לא צריך להחליט מראש. תאר מה אתה רוצה למדוד והעוזר בוחר, אומר לך איזה הוא בחר ולמה, ואתה יכול להחליף.

## שני סוגי השאלות

### `noul` — האם זה נכון?

שתי תשובות, ואתה מתאר את שתיהן. התוצאה היא ההסתברות שתיאור "האמת" משתלב:

```json
{
  "instructions": "Did the assistant promise a refund without first checking the refund policy?",
  "criteria": {
    "true":  "A refund was promised or issued with no prior policy check or approval",
    "false": "No refund was promised, or every refund followed a policy check"
  }
}
```

תאר את שני הצדדים. "לא הובעה דחיפות" היא תשובה אמיתית ואומר זאת הופך את השני לחד.

### `score` — כמה מזה?

רובריקה מסודרת, **הגרועה ביותר קודם**. התוצאה היא היכן הסשן נוחת בה, מחודשת לסקלה 0–1:

```json
{
  "instructions": "How frustrated is the customer?",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
```

**רובריקה דורשת שלוש עד חמש רמות, וכולן חייבות להיות שונות.** שני הגבולות נמדדים, לא סטיליסטיים:

- **שתי רמות** קורסות למה `noul` כבר עושה טוב יותר, ו**יותר מחמש** גורמות למודל להסתער לעבר האמצע במקום להתחייב. אותה שאלה על אותו סשן קיבלה 0.00 עם שתי רמות, 0.01 עם שלוש, ו-0.55 עם עשר.
- **רמות חוזרות** מפצלות את התשובה באופן שרירותי ביניהן. סשן שהיה בבירור כועס קיבל 1.00 מול `["Calm", "Frustrated", "Very angry"]` ו-0.66 מול `["Angry", "Angry", "Angry"]` — מספר מעוצב היטב שלא אומר כלום.

קטגוריות ללא סדר — "חיובים, טכני או מכירות" — אינן רובריקה. שאל אותן כ-`noul` לכל קטגוריה, או השתמש בשופט.

## קריאת התוצאות

מסווג מייצר **ניקוד** מ-0 ל-1, בדיוק כמו שופט, כך שזה משרטט, מסנן וגורם להתרעות באותו אופן. שני הבדלים כדאי לדעת:

- **אין הנמקה.** השדה ריק, בכוונה. מודל זה לא מסביר את עצמו, והמצאת הסברה תהיה זיוף ולא תכונה.
- **אי-ודאות מתויגת.** שאלת `score` מדווחת על הביטחון שלה, וגם תוצאה שהמודל היה לא בטוח לגביה מתויגת `low_confidence` — כך "אילו מאלה צריך אדם להסתכל עליהן" הוא מסנן ולא ניחוש. שאלת `noul` לא מדווחת ביטחון, כך שזה לעולם לא מתויג.

סשנים ארוכים מאוד נקראים בקטעים ומשולבים. כאשר סשן ארוך מדי לקריאה מלאה, התוצאה אומרת כמה סיבובים הושמטו — לעולם לא תראה שיפוט שנעשה על חלק מהסשן המוצג ככזה שנעשה על כולו.

## מגבלות

- **שלוש עד חמש רמות רובריקה, כולן ברורות.** ראה למעלה; שני הגבולות מאומתים בזמן כתיבה.
- **שאלה אחת לכל הערכה.** שאל שתי דברים ותקבל שתי הערכות, שזה גם מה שאתה רוצה בגרף.
- **עריכת השאלה מפרסמת גרסה חדשה.** ניקוד ישן וחדש לא ניתנים להשוואה, כך שהם נשמרים בנפרד במקום להיערבב לשורת מגמה אחת.
- **מסווג תמיד מייצר ניקוד**, לעולם לא מדד או טענה.
- **אין הנמקה**, כנ"ל. אם מספר יגרום למישהו לשאול "למה?", כתוב שופט במקום.

## בדיקה ומילוי אחורה

בניגוד לשופט, הערכת מסווג **יכולה** להיבדק לפני שאתה משדרג אותה — [בדוק אותה](/he/evaluations/test) מול סשנים אמיתיים כמו שהיית בודק הערכת קוד, וקרא את הניקוד לפני שדבר כלשהו עולה לאוויר.

זה יכול גם להיות [ממולא אחורה](/he/evaluations/deploy#score-sessions-you-already-have) על סשנים שיש לך כבר. זה עולה קריאה אחת של מודל לכל סשן, כך שתחום את החלון בכוונה במקום להחזיר הכל.
