דף זה מתאר את צורות השאלות וכללי הניקוד מאחורי [Jev evaluations](/he/evaluations/jev). חלק מהשאלות דורשות שמודל *יקרא* את השיחה, אך לא *יכתוב* עליה. "האם הלקוח הביע דחיפות?" יש שתי תשובות. "כמה הם היו מתוסכלים?" יש כמה תשובות, לפי סדר. אתה יודע כל תשובה לפני שאתה שואל.

**classifier evaluation** היא בדיוק לאלה. אתה כותב את השאלה ואת התשובות שהיא עשויה לתת, ומודל קטן שנבנה בשביל סיווג מחזיר מספר מכיול — לעולם לא טקסט חופשי.

<Note>
כמו שופט, classifier evaluation עולה קריאת מודל לכל סשן. בשונה משופט, זה מודל קטן, חד-תכלית במקום מודל כללי, אז זה מהיר וזול יותר — אבל זה לעולם לא יסביר את עצמו. אם אתה צריך את ההיגיון, השתמש ב[judge](/he/evaluations/judge).
</Note>

## איזה אחד אני רוצה?

| שאלה | השתמש |
| --- | --- |
| כמה קריאות tool היו? | code |
| האם הסשן היה מתחת ל-30 שניות? | code |
| האם הלקוח הביע דחיפות? | **classifier** |
| איזה צוות צריך להתמודד עם זה: billing, technical, או sales? | **classifier** |
| כמה הלקוח היה מתוסכל? | **classifier** |
| האם התשובה הייתה בעצם נכונה? | **judge** |
| האם זה עקב את מדיניות ההסלמה שלנו, ולמה אתה חושב כך? | **judge** |

כלל האצבע: **ניתן לספור → code, תשובות שאתה יכול לרשום → classifier, דורש הסבר → judge.**

אתה לא צריך להחליט מראש. תאר מה אתה רוצה למדוד והעוזר יבחר, יגיד לך איזה הוא בחר ולמה, ואתה יכול להחליף.

## שני סוגי השאלות

### `noul` — האם זה נכון?

שתי תשובות, ואתה מתאר את שתיהן. התוצאה היא ההסתברות שתיאור "הנכון" מתאים:

```json
{
  "instructions": "Did the assistant promise a refund without first checking the refund policy?",
  "criteria": {
    "true":  "A refund was promised or issued with no prior policy check or approval",
    "false": "No refund was promised, or every refund followed a policy check"
  }
}
```

תאר את שני הצדדים. "לא הביעו דחיפות" היא תשובה אמיתית ואומר כך הופך את השנייה לחדה יותר.

### `score` — כמה מזה?

rubric מסודר, **הגרוע ביותר ראשון**. התוצאה היא איפה הסשן נחות בו, המוקטן ל-0–1:

```json
{
  "instructions": "How frustrated is the customer?",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
```

**rubric לוקח שלוש עד חמש רמות, וכולן חייבות להיות שונות.** שתי הגבולות נמדדות, לא סטיליסטיות:

- **שתי רמות** מקורסות למה `noul` כבר עושה טוב יותר, ו**יותר מחמש** גורמות למודל להתנדנד לכיוון האמצע במקום להתחייב. אותה שאלה על אותו סשן הניקוד 0.00 עם שתי רמות, 0.01 עם שלוש, ו-0.55 עם עשרה.
- **רמות חזרות** מפצלות את התשובה באופן שרירותי ביניהן. סשן שהיה ללא ספק כועס הניקוד 1.00 בעד `["Calm", "Frustrated", "Very angry"]` ו-0.66 בעד `["Angry", "Angry", "Angry"]` — מספר טוב-מעוצב שלא אומר כלום.

קטגוריות ללא סדר — "billing, technical, או sales" — אינן rubric. שאל אותן כ-`noul` לפי קטגוריה, או השתמש ב-judge.

## קריאת התוצאות

classifier מייצרת **score** מ-0 עד 1, בדיוק כמו judge, אז זה מתרשם, מסנן ותופעל התרעות באותו אופן. שתי הבדלים שווים ללמוד:

- **אין הנמקה.** השדה ריק, בכוונה. מודל זה לא מסביר את עצמו, והמצאת הסבר הייתה זיוף במקום תכונה.
- **אי-ודאות מתויגת.** שאלת `score` מדווחת את הביטחון שלה, ותוצאה שהמודל לא היה בטוח בה מתויגת `low_confidence` — כך "איזה מאלה צריך אדם להסתכל" הוא מסנן ולא ניחוש. שאלת `noul` לא מדווחת ביטחון, אז היא לעולם לא מתויגת.

סשנים ארוכים מאוד נקראים בקטעים ומשולבים. כשסשן ארוך מדי בשביל קריאה מלאה, התוצאה אומרת כמה פניות הושמטו — לעולם לא תראה שיפוט שנעשה על חלק מסשן המצגנו כאחד שנעשה על כולו.

## גבולות

- **שלוש עד חמש רמות rubric, כולן נפרדות.** ראה למעלה; שתי הגבולות מאומתות בזמן הקריאה.
- **שאלה אחת לכל evaluation.** שאל שתיים ותקבל שתי evaluations, וזה גם מה שאתה רוצה בתרשים.
- **עריכת השאלה מפרסמת גרסה חדשה.** ניקודי ישנים וחדשים לא ניתנים להשוואה, אז הם נשמרים בנפרד במקום לחלוט לתוך קו מגמה אחד.
- **classifier תמיד מייצרת score**, לעולם לא metric או assertion.
- **אין הנמקה**, כנ"ל. אם מספר יגרום למישהו לשאול "למה?", כתוב judge במקום.

## בדיקה ומילוי נתונים

בשונה מ-judge, classifier evaluation **יכולה** להיבדק לפני שתפרוס אותה — [בדוק אותה](/he/evaluations/test) בעד סשנים אמיתיים באותו אופן שאתה היית בדיקה code evaluation, וקרא את הניקודים לפני שום דבר עולה לשידור.

זה יכול גם להיות [מלא נתונים](/he/evaluations/deploy#score-sessions-you-already-have) על סשנים שיש לך כבר. זה עולה קריאת מודל לכל סשן, אז היקף את החלון בכוונה במקום להשמיע הכל מחדש.
