זהו הסימוכין של הספק והקונפיגורציה עבור [מדיניות Jev](/he/policies/jev) עם המפתח שלך. מדיניות Regex משווה מחרוזות. הן לא יכולות להבדיל בין `rm -rf build/` שביקשת לבין `rm -rf ~` שהחליקה לתוך תוכנית, כך שהן חוסמות יותר מדי במקום אחד ותו מעט בעוד מקום. **Jev**, המסווג של TypeSafe, קורא את הקריאה לעומת מה שבעצם ביקשת וענה על קבוצה של שאלות כן/לא עליה בבקשה אחת מהירה.

עם נקודת הקצה של Jev שלך ומפתח מוגדר, Failproof AI שואל את Jev לגבי כל קריאת כלי **לצד** מדיניות regex, לעולם לא במקום שלהן:

- הדחיה של מדיניות **קשה** היא סופית. Jev לא יכול לחסלה. כל מדיניות היא קשה אלא אם כן היא מסומנת בבירור כבתלות לבדיקה וקוראת בשם את בדיקות Jev המכוסות בה, כך שמדיניות מותאמת, חבילה או Cloud שלא אומרת כלום היא קשה, והשומר על ההגנה העצמית שתמיד פעיל הוא תמיד קשה.
- הדחיה של מדיניות **בתלות לבדיקה** עשויה להיות מחוסלת, אך רק כאשר Jev נשאל לגבי הדאגה המדויקת שמדיניות זו מכסה וענה "אין כאן כלום" או "המשתמש ביקש את זה". בדיקה שמוצאת את הדאגה כממשית, כאשר המשתמש לא ביקש את הקריאה, שומרת על הדחיה — אפילו כאשר הפסק שלה בעצמו הוא רק אזהרה בלבד, כי לפני קריאת כלי אזהרה לא עוצרת את הסוכן. וכאשר בדיקה זו היא אחת שיכולה לדחות (חשיפת סוד, הוצאת אישורים, מחיקה הרסנית, ...), שום דבר לא מתחסל בקריאה זו.
- בלוק יכול עדיין להיות **אזהרה** כאשר הקריאה היא שלב של המשימה שנתת ולא מגיעה רחוק יותר: Jev משנה את הדחיה שלו להנצחה לאזהרה, והאזהרה הזו — שם מה שבעצם לא בסדר עם הקריאה — מחליפה את הבלוק של המדיניות.
- Jev יכול גם להזהיר או לדחות בעצמו, לנזק שאף regex לא מתאר.
- אם Jev לא יכול לענות (timeout, rate limit, שגיאת שרת, אין קרדיטים, גרסת מודל בלתי צפויה), הקריאה הזו מקבלת את תוצאת regex, בדיוק כמו ללא Jev.
- Jev לעולם לא עושה קריאה יותר מתירה מן המדיניויות שלך בלבד אלא אם היא קראה את הקריאה כולה וונשאלה לגבי הדאגה המדויקת. כל משהו פחות מכך — קריאה גדולה מדי לשליחה כולה, הזרקה חשודה — מבטל את הקלירנס ושומר על כל דחיה.

<Note>
ללא קונפיגורציה של Jev שום דבר לא משתנה: hooks מריצים את מדיניות regex בדיוק כמו שתמיד. הקונפיגורציה היא כל ה opt-in.
</Note>

<Tip>
ב FailproofAI Cloud? אתה לא צריך מפתח משלך: מכונה המחוברת עם מפתח שנושא את `jev:evaluate` יכול להשתמש ב Jev בתכנית הארגון שלך. ראה [Jev דרך FailproofAI Cloud](/he/reference/jev-cloud).
</Tip>

## לפני שתתחיל

התקן **failproofai 1.0.8-beta.0 או אחרון יותר** וצרף את hooks שלו ל [harness נתמך](/he/reference/harnesses) על המכונה שבה פועל הסוכן שלך. עקוב אחרי ה [quickstart](/he/start/quickstart) אם זו מכונה חדשה, או [הגדר אכיפה מקומית](/he/start/setup#enforce-locally) אם אינך משתמש ב Cloud. בדוק את ה CLI שהותקן עם `failproofai --version`.

קבל מפתח API מספק שלהלן, או הכן נקודת קצה תואמת ואת המפתח שלה. Jev משוקלל קריאות כלי בשם בשער `PreToolUse` או `PermissionRequest`. זה יכול להנפיק פסק דין משלו, אך חיסול של דחיית מדיניות קיימת דורש גם מדיניות מותקנת המסומנת [בתלות לבדיקה](/he/policies/authority). דחיות מדיניות קשות נשארות סופיות.

## בחר ספק

Jev ניתן להגעה דרך חמש נתיבים. הביא מפתח לאחד מהם.

| ספק | `--provider` | נקודת קצה | מודל ברירת מחדל | הערות |
| --- | --- | --- | --- | --- |
| TypeSafe | `typesafe` | `api.typesafe.ai/v1/systemone` | `jev-1.13.0` | פיקוד גרסה מדויק. |
| OpenRouter | `openrouter` | `openrouter.ai/api/v1/systemone` | `typesafe/jev-1.13` | בקשות מנוטרלות לנקודות קצה של שמירת אפס נתונים בלבד, ללא fallback לספק אחר. מדווח גרסה בתאריך כגון `typesafe/jev-1.13-20260917`. |
| Vercel AI Gateway | `vercel` | `ai-gateway.vercel.sh/typesafe/v1/systemone` | `typesafe-ai/jev` | שומות ל Jev רק לפי כינוי, כך שהגרסה שענתה מתועדת כלא מאומתת. |
| Cloudflare Workers AI | `cloudflare` | `api.cloudflare.com/client/v4/accounts/<id>/ai/run` | `typesafe/jev` | דורש `--account-id`. בערך שש קריאות לשנייה לכל מפתח נמדדו לפני HTTP 429. |
| נקודת קצה משלך | `custom` | `<base-url>/systemone` | `jev-1.13.0` | כל נקודת קצה שמקבלת את גוף הבקשה של TypeSafe ומדווחת איזה מודל ענה. `https` בלבד; plain `http` לשם hosp loopback (`localhost`, `127.0.0.1`, `::1`) מקובל לבדיקה מקומית. |

<Warning>
עם התכונה bring-your-own-key של Vercel, בקשה שנכשלה מנוסתה שוב בשקט עם אישורים של Vercel. אם אתה צריך כל קריאה להיות מחויבת ל, וראוי על ידי, חשבון TypeSafe משלך בלבד, השתמש ב TypeSafe ישירות.
</Warning>

## הגדר את זה

פקודה אחת, נקודת הקצה והמפתח. התחל במצב `observe` כדי שתוכל לבדוק את הפסקי הדין של Jev בעוד המדיניויות הקיימות ממשיכות להחליט קריאות:

```bash
failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
```

### ה URL בוחר את הספק

אתה לא צריך לשם את הספק: ה **host** של ה URL הוא איזה אחד זה.

| host URL | ספק | גם צריך |
| --- | --- | --- |
| `api.typesafe.ai` | `typesafe` | — |
| `openrouter.ai` | `openrouter` | — |
| `ai-gateway.vercel.sh` | `vercel` | — |
| `api.cloudflare.com` | `cloudflare` | `--account-id <32-hex-account-id>` |
| כל host אחר | `custom` | — ה URL שנתת הוא ה base URL |

שלוש דברים נובעים מזה:

- **ה URL שהוא ה API שלעצמו של הספק לא כותב override.** `--url https://api.typesafe.ai/v1` מייצר בדיוק את הקונפיגורציה ש `--provider typesafe` היה לעשות. תן נתיב או host אחר על ספק ידוע והוא מאוחסן כ base URL, כפי ש `--base-url` יאחסן אותו.
- **`--provider` עדיין עוקף את ההסקה**, וזה איך אתה מגיע ל proxy שמדבר API של ספק מ host משלך: `--url https://jev-proxy.internal/v1 --provider typesafe`.
- **`--provider` שסותר את ה host נדחה**, לא נעשה ניחוש. `--provider openrouter --url https://api.typesafe.ai/v1` לא כותב שום דבר ואומר למה: שתי הכתיבות לא מסכימות היכן המפתח שלך עומד להישלח. אותו זוג נדחה מ `jev setup --base-url` ומלוח הבקרה של הגדרות Jev. (`--provider custom` לא סתירה — זה אומר "התייחס ל URL זה כלעצמו" — חוץ על host של Cloudflare, שנקודת קצה לכל חשבון שלה לא יכול להגיע נתיב מותאם.)

`--url` מאומת בדיוק כמו `baseUrl` בקובץ הקונפיגורציה, ודחוי באותם מילים: `https`, או plain `http` ל host loopback (`localhost`, `127.0.0.1`, `::1`) בכל מצב. סיכון: שום דבר לא מאמת שרת loopback, כך שבזמן שהוא למטה תהליך מקומי אחר יכול לקחת את הפורט שלו וענות; השתמש `https` מחוץ לבדיקה מקומית.

### המפתח

שלח אותו ב `--key-stdin`, או הרץ את הפקודה בטרמינל ללא זה והדבק את המפתח בהנחיה מסיכה. כל דרך זה הולך ישר לקובץ הקונפיגורציה ומעולם לא מודפס בחזרה.

`failproofai jev setup` לוקח אותות דגלים ודרך בן זקנים של כל זה: `setup --provider <kind>` שבו תרצה יותר לשם את הספק מאשר את ה URL.

### `--token`, וזה עולה לך

`--token <token>` שם את המפתח בשורת הפקודה, שזו הדרך המהירה ביותר להגדיר מכונה והיחידה איות שמשאיר את המפתח בכל מקום אך בקובץ הקונפיגורציה:

```bash
failproofai jev --url https://openrouter.ai/api/v1 --token <token>
```

<Warning>
טיעון שורת פקודה נמצא בקובץ ההיסטוריה של הקליפ שלך לאחר מכן, ובעוד הפקודה רצה זה בתהליך רשימה — קריאה מ `/proc` בכל דבר שרץ בהיותך. `setup` אומר כן בכל פעם `--token` משמש. העדף `--key-stdin` על מכונה שאתה משתף, בהפגנה מוקלטת, או בכל מקום קובץ ההיסטוריה מסונכרן; סובב מפתח שהעברת בדרך זו אם זה משנה.
</Warning>

`--token`, `--key-stdin` ו `--key-from-env` הם בלעדיים זה לזה: תן אחד.

ואז שלח בקשה חיה קטנה אחת כדי לבדוק את המפתח, את נקודת הקצה ואיזה Jev ענה:

```bash
failproofai jev test
```

```text
  failproofai jev test                                            ok · 523 ms

  provider      cloudflare
  model asked   typesafe/jev
  answered by   jev-1.13.0 (Jev 1.13 family — verified)
  latency       523 ms — within the 3000 ms timeout
```

`jev test` יוצא 1, ואומר כן בכותרת שלו, כאשר התשובה מגיעה לאחר ה timeout (כל hook יחזור לתוך regex כ `timeout`) או תשובות שאלת הבדיקה שלה בצורה לא נכונה.

Hooks קראו את הקונפיגורציה על כל קריאת כלי, כך שזה חל מהבא. אין שום דבר להפעיל מחדש, עם או בלי ה daemon.

## בדוק מה זה עושה

```bash
failproofai jev status
failproofai jev status --json
```

`status` מציגה את הספק, נקודת הקצה, מודל, מצב, קובץ הקונפיגורציה והרשאותיו, ומעולם לא המפתח. מתחתיו זה מסכם פעילות אחרונה: כמה קריאות Jev הערכה, כמה פעמים זה חזר לתוך regex ולמה, הקובע שלו, ואילו מדיניויות בתלות לבדיקה זה מחוסל.

## אמת קריאה אמיתית

התחל סשן חדש בסוכן משוקלל. בקש ממנו להשתמש בכלי קריאת הקבצים שלו על `README.md` ודווח את הכותרת. אשר כי הסשן מכיל את קריאת הכלי הזו, ואז הרץ `failproofai jev status` שוב: ספירת הקריאה המוערכת הלא-אחרונה שלו צריכה להיות גדלה. פתח **Policies → Activity** ב [לוח הבקרה המקומי](/he/reference/local-dashboard#review-policy-activity) כדי לבדוק את פסק הדין של Jev של הקריאה ואת המצב. במצב observe, תוצאת המדיניות עדיין מחליטה את הקריאה. קלירנס מופיע רק אם מדיניות בתלות לבדיקה תאמה וJev מחסל כל בדיקה בשם; קריאה רגילה עשויה לא להיות בעלת מדיניות לחיסול.

## מצב Observe

`enforce` הוא ברירת המחדל. כדי לראות Jev ללא לתן לו לשנות כל החלטה, עבור ל `observe`: Jev עדיין שאול ופסקי הדין שלו מתועדים, אך תוצאת regex היא מה שמעצימה.

```bash
failproofai jev setup --mode observe
failproofai jev setup --mode enforce
failproofai jev setup --mode off
```

`off` משמר את הקונפיגורציה — נקודת הקצה והמפתח — ומפסיק לשאול Jev: hooks הריצו את מדיניות regex בדיוק כמו ללא קונפיגורציה, ו `failproofai jev status` אומר "off (switched off)". חזור עם `--mode observe` או `--mode enforce`.

הפעלת `setup` מחדש לאותו הספק משמר את המפתח המאוחסן, כך שעברת מצב היא דגל אחד. ספק החלפה מתחיל מחדש ושואל את מפתח הספק הזה. כך גם `--base-url` שמעביר בקשות למארח אחר: מפתח מאוחסן משלח רק לשם הוא ניתן ל, או ל API שלעצמו של הספק.

## קובץ הקונפיגורציה

הכל חי בקובץ אחד, `~/.failproofai/jev.json`, כתוב על ידי `setup`:

```json
{
  "provider": "cloudflare",
  "apiKey": "<your key>",
  "accountId": "<32-hex-account-id>",
  "mode": "enforce",
  "timeoutMs": 3000
}
```

| שדה | משמעות |
| --- | --- |
| `provider` | `typesafe`, `openrouter`, `vercel`, `cloudflare` או `custom` — או `failproofai`, שמפתח שלו מגיע מחיבור FailproofAI Cloud במקום קובץ זה (ראה [Jev דרך FailproofAI Cloud](/he/reference/jev-cloud)). |
| `apiKey` | נשלח כ `Authorization: Bearer <key>`. |
| `baseUrl` | נדרש ל `custom`; החליפ את ה API של הספק אחרת. חייב להיות `https`. Plain `http` ל `localhost` מקובל רק עם `mode: observe`: שום דבר לא מאמת שרת מקומי, כך שכאשר ה proxy שלך למטה כל תהליך במכונה, כולל הסוכן שיוכלל, יכול לענות במקומו. |
| `accountId` | Cloudflare בלבד: 32 תווי hex קטנים. |
| `model` | החליף את מזהה המודל של ברירת ברירת ברירת של ספק. מזהה גרסה חייב לשם Jev 1.13. ערך המעוצב כמו מפתח API נדחה (ולא חוזר בחזרה), כך שמפתח הודבק ל `--model` מעולם לא מאוחסן או נשלח כמודל. |
| `timeoutMs` | כמה זמן קריאת כלי חוכה Jev לפני השימוש בתוצאת regex. 100–10000, ברירת מחדל 3000. |
| `mode` | `enforce` (ברירת מחדל), `observe`, או `off` (שמור את הקונפיגורציה, הרץ Jev בלא). |

שלושה כללים להגן עליו:

- **רק בעלים.** זה כתוב עם הרשאות `0600`. העתק שכל משתמש או קבוצה אחרת יכול לקרוא או לכתוב **נדחה**, and hooks חזור לתוך regex עד שתריץ `chmod 600 ~/.failproofai/jev.json` או `setup` שוב. הספרייה גם בדוקה: `~/.failproofai` חייב לא להיות **writable** על ידי כל אחד אחר, כי מי שיכול לכתוב שם יכול להחליף את הקובץ בכל מקרה אחד הרשאות שלו. `setup` לוקח את ה bits כתיבה אלה אם זה מוצא אותם. `failproofai jev status` אומר כשקובץ קונפיגורציה נדחה וההצגה את הספק ה URL שם: מישהו אחר היה יכול שינוי אותו, כך לבדוק זה שלך לפני `chmod`. הפעלת `setup` מחדש על כל קובץ כזה לוקח את המפתח המאוחסן שלו רק ל API של הספק; כל נקודת קצה אחרת זה שמות צריך את המפתח שוב (`--key-stdin`), או `--base-url default` כדי לשלוח בקשות חזרה לספק.
- **גלובלי בלבד.** מאגר לא יכול להפוך את Jev, להצביע אליו בנקודת קצה אחרת או לבחור את המודל שלו: `.failproofai/jev.json` בתוך פרויקט מתעלם, והספק, URL, מודל וחשבון id נקראו רק מקובץ זה — מעולם לא מהסביבה, שהגדרות סוכן של מאגר יכולות להגדיר. (`FAILPROOFAI_HOME` לא דרך סביב זה: זה מעביר את כל תיקיית failproofai, המדיניויות שלך כללה, למקום אחר במקום להפניית Jev בעצמה.)
- **המפתח בלבד עשוי לבוא מהסביבה.** אם לקובץ אין `apiKey`, `FAILPROOFAI_JEV_API_KEY` מספק אותה לסשן זה (`setup --key-from-env` כותב קובץ כזה). זה לא מעולם מחליף מפתח קובץ גורמים, וזה לא יכול להפוך את Jev ללא הקובץ. היכן המשתנה לא מוגדר, Jev הוא פשוט לא לשרוול זה: `failproofai jev status` אומר כן, יוצא 0 וישאיר את הקונפיגורציה לבדה (`status --json` דוחות `"status": "key-missing"` עם `"reason": "no-env-key"`). ה `failproofaid` daemon לא רואה את הסביבה של הקליפ שלך, כך על מכונה הגדר עם `failproofai config`, שמור את המפתח בקובץ.

## איזה Jev ענה

סף ההחלטה של Failproof AI התוכננו על Jev 1.13, כך תשובה משמשת רק כאשר זה בא מאותה משפחה: `jev-1.13.x`, או שלOpenRouter `typesafe/jev-1.13-<date>`. היכן ספק שם Jev רק לפי כינוי ודוחה לא גרסה (Vercel, וCloudflare כאשר זה לא אומר), התשובה משמשת ותועדה כלא מאומתת. A `custom` נקודת קצה חייבת דווח את המודל שענה; היוצא מן הכלל היחידה הוא גרסה בלתי גרסה `--model` השם התצורה שלך עבור זה, איזה, הדהד בחזרה, מתועדת כלא מאומתת באותו אופן. תשובה דיווח כל גרסה אחרת, או `custom` תשובה דיווח אף אחד, לא משמש: קריאה זו חוזר לתוך regex עם הסיבה `model-mismatch`.

## כאשר Jev לא יכול לענות

כל אלה חוזרות לתוך תוצאת regex לקריאה זו וומתועדת עם הסיבה שלה, אשר `failproofai jev status` סכומים:

| סיבה | סיבה |
| --- | --- |
| `timeout` | אין תשובה ב `timeoutMs`. |
| `http-429` | הספק rate-simited המפתח. |
| `rate-limited` | מחוד הגדלה שלעצמו של Failproof AI העלמת הקריאה בחזרה לפני שליחת זה: 5 בקשות שנייה, בפרץ של עד 5, ואף אחד רגע אחרי הספק ענה `429`. לא הספק. |
| `http-500`, `http-502`, `http-503`, … | שגיאת שרת בספק. הסטטוס המדויק מתועד. |
| `out-of-credits` | HTTP 402: חשבון הספק אין קרדיטים שנותרו. |
| `provider-refused` | HTTP 402 מCloudflare קרא "Model execution failed (Payment error)": הספק נמנע מהרצת המודל על בקשה זו. בדרך כלל לא חיוב, כך טיפול במחסור לא יהיה להזיז אותו. |
| `http-401`, `http-403` | המפתח נדחה. |
| `http-404` | שום דבר משרת ב `<base>/systemone`, כך ה base URL הוא לא נכון — `/systemone` נוספה אליו, וכל ספק משרת אותו בשורש הגרסה שלו. `failproofai jev models` מציגה מה הנקודה הקצה לא משרת. |
| `network` | נקודת הקצה לא היתה יכולה להגיע. |
| `http-301`, `http-302`, `http-307`, `http-308` | נקודת הקצה ענתה עם הפניה. הפניות מעולם לא לוקחות, כך התשובה רק אי פעם מגיעה מה URL בקונפיגורציה שלך; סט `--base-url` ל URL הסופי. |
| `malformed` | נקודת הקצה ענתה, אך לא עם תשובה Jev — גוף זה לא JSON, או אחד עם אף תשובות בה. |
| `cloudflare-error`, `cloudflare-incomplete` | עטיפת Cloudflare דיווחה כשל, או עבודה שלא היתה סיימה. |
| `model-mismatch` | גרסה Jev אחרת מאשר 1.13 ענתה, או `custom` נקודת קצה לא אומרת איזה מודל ענה. |
| `request-cut` | **לא הפסקה.** Jev ענה; זה הוא גרם רק חלק מהקריאה, כך תשובה שלה מחוסלה שום דבר. ראה [כאשר Jev ענה, אך לא בהקריאה כולה](#when-jev-answered-but-not-on-the-whole-call). |

`failproofai jev status` יכול להציג כמה סיבות הרבה יותר נדיר גם, כגון `upstream-error` (התשובה נשא הוא סיבה של הספק) או `config`, וסך הכל כל סיבה זה לא יכול לשם כמו `other`.

`request-cut` הוא בטבלה זו כי `failproofai jev status` סיכומים זה עם השאר, וכי זה גם משאיר כל דחיה עמידה. זה הסיבה היחידה כאן שאומרת שום דבר לגבי הספק שלך: בקשה הגיעה וJev ענה זה. בניגוד לכל שורה מעלה זה, שעדיין סופר זה ענה — שלעצמו דחיה או אזהרה חל על גבי תוצאת regex ולא להיות מהוסר. כך חלוץ של אלה אומר קריאות הן מגיעות למשקיל גדולה מדי לשליחה כולה, לא כי נקודת קצה שלך הוא בצרה, וטיפול במחסור או שינוי ה URL לא יהיה להזיז את המספר.

## כאשר Jev ענה, אך לא בהקריאה כולה

שתי דברים נוספים יכולים לקרות, ורוב שום מהם היא Jev כשל לענות. שניהם אודות כמה מהקריאה, או של השיחה, התאמה לתוך בקשה אחת.

**חלק מהקריאה עצמה לא התאמה.** קריאת כלי נשלח בתוך תקציב קבוע, וחריג אחד — גדול מאוד `Write`, MCP גופה ענק, פקודה מרופדת החוצה את כובע — נשלח עם מה התאמה. Jev עדיין ענה, ותשובה שלה עדיין סופר: שלעצמו דחיה או אזהרה חל כרגיל. מה זה לא יכול לעשות הוא **חיסול** כלום, כי פסק דין נתן בחלק מקריאה לא פסק דין בקריאה. כל כך כל דחיה מדיניות עמידה, וקריאה מתועדת כהחזרה למטה עם הסיבה `request-cut`, אשר `failproofai jev status` סיכומים לצד הסיבות לעיל. הכלל זה נתן לך: עישון קריאה גדולה יכול עלות זה קלירנס, וזה לא יכול אי פעם קנות אחד.

**הודעה לא התאמה.** הנדים בן זקנים הדבקתי, הודעה של הסוכן האחרון, או הנדים משקיל זה של שלעצמו חנות כבר כובע. **שום דבר לא משתנה**: הקריאה הוא שפוט, מחוסל ותועדה בדיוק כמו כל אחד אחר, וזה לא סופר כהחזרה למטה. אורך מה אתה סוג כלא מעולם מחליט פסק דין, וחיסול לא יכול לייצר הסכמה: היכן הנדים הגיע כבר כובע, „you לא ביקשת זה" מפסיק להיות מסקנה שיכול להיות נמשך מזה בכל, כמו הבאות אחד.

הקו בין שניים הוא מי כתב הטקסט. הקריאה הוא הסוכן של, וכלל זה תן אורך שלו חיסור חומרה יהיה כלל הסוכן יכול להשתמש; הנדים שלך הוא שלך, ויחס אורך שלו כאות רק אי פעם מוקצה הדבקה של מפרט או ערימה עקוב.

## מה משאיר המכונה

עבור כל קריאת כלי Jev מעריך, בקשה אחת הולכת לספק שלך, וביצוע:

- קריאת הכלי עצמו, עם סודות כגון API מפתחות, נושא אסימונים ו `KEY=` מטלות מתוקן;
- הנדים אחרונות הקרובות אתה סוג, עם טקסט הוקלוד הסוכן של שלו נוסף הוסר;
- הודעה של הסוכן של האחרון לפני הנדים הקרובות שלך, תווית כמו כתוב סוכן;
- עובדות מחושב מקומית, כגון בין נתיב בתוך הפרויקט — האחד הסשן הוא בראשונה סקירה קוראה, [מוקבע לסשן](/he/reference/jev-intent#the-project-root) — והענף גיט הנוכחי.

הוא הולך רק לנקודת הקצה בקונפיגורציה שלך, תחת המפתח שלך.

## כבה את זה

```bash
failproofai jev remove
```

זה מחיקות `~/.failproofai/jev.json`. מהקריאה כלי הבא, hooks הריצו את מדיניות regex בדיוק כמו לפני. האחסון ל-סיום תחת `~/.failproofai/state/semantic/` (תועדה נדים ב `sessions/`, פרויקט שורשים ב `roots/`) מושארות במקום וגיל החוצה. כדי לעצור לשאול Jev אך לשמור קונפיגורציה, השתמש `failproofai jev setup --mode off` במקום זה.

## ייחוס פקודה

| פקודה | תוצאה |
| --- | --- |
| `failproofai jev --url <url> --key-stdin` | הגדר אותו בפקודה אחת; הספק מגיע מ host של ה URL |
| `failproofai jev --url <url> --token <token>` | אותו דבר, עם המפתח בשורת פקודה — ההיסטוריה שלך וה-תהליך רשימה ראה אותו |
| `failproofai jev setup --provider <kind> --key-stdin` | כתוב הקונפיגורציה ממפתח צינור על stdin |
| `failproofai jev setup --provider <kind>` | אותו דבר, לבקשות מפתח בהנדים כיסוי |
| `failproofai jev setup --key-from-env` | לא חנות מפתח; קרא `FAILPROOFAI_JEV_API_KEY` לכל סשן |
| `failproofai jev setup --mode observe` | החלף מצב (`enforce`, `observe` או `off`), כאשר המפתח המאוחסן |
| `failproofai jev setup --model <id>` / `--base-url <url>` | כיתוב המודל או API גלם; `default` ברור יעיל |
| `failproofai jev setup --timeout-ms <n>` | שנה לכל קריאה תקציב |
| `failproofai jev status [--json]` | קונפיגורציה, הרשאות ופעילות אחרונה; אי פעם המפתח |
| `failproofai jev test [--json]` | בקשה חיה אחת: קובע והגרסה שענה |
| `failproofai jev models [--provider <kind>] [--url <base>] [--json]` | המודל ids כי נקודת קצה של `/models` דוחות, סימון התצורה אחת |
| `failproofai jev remove` | מחק הקונפיגורציה; Jev הוא לא |
