זהו הרeferenceשל ספק ותצורה ל[מדיניויות Jev](/he/policies/jev) עם המפתח שלך. מדיניויות Regex תואמות מחרוזות. הן אינן יכולות להבחין בין `rm -rf build/` שביקשת ל-`rm -rf ~` שהחלקת לתוך תוכנית, כך שהן חוסמות יותר מדי במקום אחד וקצת מדי במקום אחר. **Jev**, המסווג של TypeSafe, קורא את הקריאה מול מה שבאמת ביקשת ומענה לסדרת שאלות כן/לא עליה בבקשה אחת מהירה.

כשקצה Jev שלך ומפתח מוגדרים, Failproof AI שואל את Jev לגבי כל קריאת כלי **לצד** מדיניויות regex, לעולם לא במקום שלהן:

- הדחיית **hard** של מדיניות היא סופית. Jev אינו יכול לנקות אותה. כל מדיניות היא hard אלא אם היא מסומנת במפורש כreviewable וקוראת לבדיקות Jev המכסות אותה, כך שמדיניות custom, pack או Cloud שלא אומרת כלום היא hard, וגם שומר ההגנה העצמי שתמיד פועל הוא תמיד hard.
- הדחיית **reviewable** של מדיניות עשויה להיות מנוקה, אך רק כאשר Jev הישאל לגבי הדאגה המדויקת שהמדיניות מכסה והשיב "לא כאן" או "המשתמש ביקש את זה". בדיקה שמוצאת את הדאגה כממשית, כאשר המשתמש לא ביקש את הקריאה, שומרת את הדחיית — אפילו כאשר הפסק שלה הוא רק אזהרה בלבד, כיוון שלפני קריאת כלי אזהרה לא עוצרת את הסוכן. וכאשר הבדיקה היא כזו שיכולה לדחות (החשיפת סוד, הוצאת אישור מחוסנות, מחיקה הרסנית, ...), כלום אינו מנוקה בקריאה זו.
- חסימה עשויה עדיין להפוך ל**אזהרה** כאשר הקריאה היא שלב של המשימה שנתת והגיעה לא רחוק יותר: Jev מרכך את הדחיית שלו לאזהרה, והאזהרה הזו — השם מה באמת לא בסדר עם הקריאה — מחליפה את החסימה של המדיניות.
- Jev יכול גם להזהיר או לדחות בעצמו, על קנס שאף regex לא מתאר.
- אם Jev אינו יכול לענות (timeout, rate limit, שגיאת שרת, אין credits, גרסת מודל בלתי צפויה), הקריאה הזו מקבלת את תוצאת ה-regex, בדיוק כמו ללא Jev.
- Jev לעולם לא הופך קריאה לתירותית יותר ממדיניויות שלך לבדן אלא אם הוא קרא את כל הקריאה והישאל לגבי הדאגה המדויקת. כל דבר פחות — קריאה גדולה מדי לשליחה כחד, injection חשוד — משלוף את ההיתרים ושומר על כל דחיית.

<Note>
ללא תצורת Jev כלום לא משתנה: hooks מריצים את מדיניויות ה-regex בדיוק כפי שהם תמיד עשו. התצורה היא כל ה-opt-in.
</Note>

<Tip>
בFaliureproof AI Cloud? אתה לא צריך מפתח שלך: מכונה המחוברת עם מפתח הנושא `jev:evaluate` יכולה להשתמש ב-Jev בתוכניית ההארגון שלך. ראה [Jev דרך Failproof AI Cloud](/he/reference/jev-cloud).
</Tip>

## לפני שתתחיל

התקן **failproofai 1.0.8-beta.0 או חדש יותר** וצרף את hooks שלו ל[harness נתמך](/he/reference/harnesses) על המכונה שבה האגנט שלך רץ. עקוב אחר ה[quickstart](/he/start/quickstart) אם זו מכונה חדשה, או [הגדר אכיפה מקומית](/he/start/setup#enforce-locally) אם אתה לא משתמש ב-Cloud. בדוק את ה-CLI המותקן עם `failproofai --version`.

קבל מפתח API מספק למטה, או הכן נקודה קצה תואמת ומפתח שלה. Jev סוקר קריאות כלי בשם ב-`PreToolUse` או ב-`PermissionRequest` gate. זה יכול להוציא פסק דין משלו, אך נקיון של דחיית מדיניות קיימת דורש גם מדיניות מותקנת המסומנת [reviewable](/he/policies/authority). דחיות מדיניות Hard נשארות סופיות.

## בחר ספק

Jev ניתן להגעה דרך חמש נתיבים. הביאו מפתח לכל אחד מהם.

| ספק | `--provider` | Endpoint | מודל ברירת מחדל | הערות |
| --- | --- | --- | --- | --- |
| TypeSafe | `typesafe` | `api.typesafe.ai/v1/systemone` | `jev-1.13.0` | pin גרסה מדויקת. |
| OpenRouter | `openrouter` | `openrouter.ai/api/v1/systemone` | `typesafe/jev-1.13` | בקשות מנותבות לנקודות קצה בעבור zero-data-retention בלבד, ללא חזרה לספק אחר. דוחה גרסה מתוארחת כמו `typesafe/jev-1.13-20260917`. |
| Vercel AI Gateway | `vercel` | `ai-gateway.vercel.sh/typesafe/v1/systemone` | `typesafe-ai/jev` | שומות Jev רק לפי כינוי, כך שהגרסה המענה מתועדת כלא מאומתת. |
| Cloudflare Workers AI | `cloudflare` | `api.cloudflare.com/client/v4/accounts/<id>/ai/run` | `typesafe/jev` | צורך `--account-id`. בערך שש קריאות בשנייה לכל מפתח נמדדו לפני HTTP 429. |
| נקודת הקצה שלך | `custom` | `<base-url>/systemone` | `jev-1.13.0` | כל נקודת קצה המקבלת גוף בקשה של TypeSafe וודוחה איזה מודל השיב. `https` בלבד; plain `http` לhost loopback (`localhost`, `127.0.0.1`, `::1`) מקובל לבדיקה מקומית. |

<Warning>
עם תכונת ה-bring-your-own-key של Vercel, בקשה כושלת מוחזרת בשקט עם אישורים של Vercel. אם אתה צריך כל קריאה חויבת ל, וראויה על ידי, החשבון TypeSafe שלך בלבד, השתמש ישירות ב-TypeSafe.
</Warning>

## הגדרה

פקודה אחת, endpoint והמפתח. התחל בעבור `observe` כדי שתוכל לבדוק את פסקי הדין של Jev בעוד שהמדיניויות הקיימות ממשיכות להחליט על קריאות:

```bash
failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
```

### ה-URL בוחר את הספק

אתה לא צריך להוציא את שם הספק: ה**host** של ה-URL הוא איזה הוא.

| URL host | ספק | גם צריך |
| --- | --- | --- |
| `api.typesafe.ai` | `typesafe` | — |
| `openrouter.ai` | `openrouter` | — |
| `ai-gateway.vercel.sh` | `vercel` | — |
| `api.cloudflare.com` | `cloudflare` | `--account-id <32-hex-account-id>` |
| כל host אחר | `custom` | — ה-URL שנתת הוא ה-base URL |

שלוש דברים נובעים מזה:

- **URL שהוא ה-API של הספק כתב אין override.** `--url https://api.typesafe.ai/v1` מייצר בדיוק את התצורה `--provider typesafe` היה. תן path או host שונה בספק ידוע וזה מאוחסן כ-base URL, כמו `--base-url` היה מאחסן.
- **`--provider` עדיין עוקף את ה-inference**, שהיא איך אתה מגיע proxy שמדברת ה-API של ספק מ-host של שלך: `--url https://jev-proxy.internal/v1 --provider typesafe`.
- **`--provider` שמנוגד ל-host מסרב**, לא מנחשים. `--provider openrouter --url https://api.typesafe.ai/v1` כותב כלום ואומר למה: שתי האיות חלוקות על המקום שבו המפתח שלך עומד להישלח. אותו זוג נדחה מ-`jev setup --base-url` ומפיקת ה-dashboard של Jev. (`--provider custom` אינו סתירה — פירוש עבור "הגדר URL זה כעצמו" — חוץ מעל host של Cloudflare, שתא custom route אינו יכול להגיע לנקודת הקצה שלה לכל חשבון.)

`--url` מאומת בדיוק כמו `baseUrl` בקובץ התצורה, ודחויה באותם המילים: `https`, או plain `http` לhost loopback (`localhost`, `127.0.0.1`, `::1`) בכל מצב. סיכון: כלום לא מאמת שרת loopback, אז בעוד זה למטה תהליך מקומי אחר יכול לקחת את ההנמקה ולענות; השתמש ב-`https` מחוץ לבדיקה מקומית.

### המפתח

שחלו אותו עם `--key-stdin`, או הפעל את הפקודה בטרמינל ללא זה והדבק את המפתח ב-prompt מסוכן. שתיהן הן משם וישר לקובץ התצורה ולא פעם הודפסו חזרה.

`failproofai jev setup` לוקח את אותם הדגלים והוא longhand לכל זה: `setup --provider <kind>` שבו היית מעדיף להוציא את שם הספק מאשר ה-URL.

### `--token`, וכמה זה עולה

`--token <token>` שם את המפתח בשורת הפקודה, שהוא הדרך המהירה ביותר להגדיר מכונה והאיות היחידה שמשאיר את המפתח כל מקום אבל קובץ התצורה:

```bash
failproofai jev --url https://openrouter.ai/api/v1 --token <token>
```

<Warning>
טיעון שורת פקודה נמצא בקובץ ההיסטוריה של הקונכייה שלך לאחר מכן, ובזמן הפקודה מריצה זה בדרך הרשימה של התהליך — קריאה מ-`/proc` על ידי כל דבר רץ כמוך. `setup` אומר כל כמו `--token` משמש. העדיפות `--key-stdin` על מכונה שאתה משתף, בהקלטה שהוקלטה, או בכל מקום קובץ ההיסטוריה סינכרונה; סובב מפתח שהעברת בדרך זו אם זה משנה.
</Warning>

`--token`, `--key-stdin` and `--key-from-env` בלעדיות זה לזה: תן אחד.

אז שלח בקשה חיה קטנה אחת כדי לבדוק את המפתח, endpoint וAiJev השיב:

```bash
failproofai jev test
```

```text
  failproofai jev test                                            ok · 523 ms

  provider      cloudflare
  model asked   typesafe/jev
  answered by   jev-1.13.0 (Jev 1.13 family — verified)
  latency       523 ms — within the 3000 ms timeout
```

`jev test` יצאים 1, ואומר כן בכותרתו, כאשר התשובה מגיעה אחרי ה-timeout (כל hook היה נופלת חזרה ל-regex כמו `timeout`) או תשובות את שאלת הבדיקה שלה בצורה שגויה.

Hooks קראו את התצורה בכל קריאת כלי, אז זה חל מהקריאה הבאה. אין כלום לתחילה מחדש, עם או ללא ה-daemon.

## בדוק מה זה עושה

```bash
failproofai jev status
failproofai jev status --json
```

`status` מראה את הספק, endpoint, מודל, מצב, קובץ התצורה והרשאות שלו, ולעולם לא את המפתח. מתחתיו זה מסכם פעילות אחרונה: כמה קריאות Jev הערך, כמה פעמים זה נפל חזרה ל-regex ולמה, להסתמך שלו, וויקיפדיה מדיניויות reviewable זה מנוקה.

## אמת קריאה אמיתית

התחל סeshion חדשה באגנט המחובר. בקש מזה להשתמש בכלי קריאת הקובץ שלו ב-`README.md` ודוח את הכותרת. אמת שהsession מכיל את הקריאה ההיא כלי, אז הפעל `failproofai jev status` שוב: הספירה שלו בקריאה מוערכת אחרונה צריכה להגדל. פתח **Policies → Activity** בדשבורד **[ציודי מקומי](/he/reference/local-dashboard#review-policy-activity) **ך לבדוק את הפסק הדין של Jev של הקריאה ואת המצב שלה. ב-observe mode, תוצאת המדיניות עדיין מחליטה את הקריאה. ברור מופיע רק אם מדיניות reviewable תאם וJev מנוקה כל בדיקה בשם; קריאה רגילה עשויה להיות ללא מדיניות לנקות.

## Observe מצב

`enforce` הוא ברירת המחדל. כדי לצפות ב-Jev ללא שם זה משנה כל החלטה, עבור ל-`observe`: Jev עדיין הישאל ופסקי הדין שלו מתועדים, אך תוצאת ה-regex היא מה שמאומץ.

```bash
failproofai jev setup --mode observe
failproofai jev setup --mode enforce
failproofai jev setup --mode off
```

`off` שומר את התצורה — endpoint והמפתח — ו\stop בקשת Jev: hooks מריצים את מדיניויות ה-regex בדיוק כמו ללא תצורה, וש`failproofai jev status` אומר "off (switched off)". החלף חזרה עם `--mode observe` או `--mode enforce`.

Re-running `setup` לאותו ספק שומר את המפתח מאוחסן, אז מצב עבור היא דגל אחד. החלפת ספק מתחיל מחדש וביקשות עבור המפתח של ספק זה. אז `--base-url` שעוברים בקשות לhost אחרת: מפתח מאוחסן רק שלח ל-host זה ניתן עבור, או ל-API של הספק שלו שלו.

## קובץ התצורה

כל דבר חי בקובץ אחד, `~/.failproofai/jev.json`, כתוב על ידי `setup`:

```json
{
  "provider": "cloudflare",
  "apiKey": "<your key>",
  "accountId": "<32-hex-account-id>",
  "mode": "enforce",
  "timeoutMs": 3000
}
```

| Field | Meaning |
| --- | --- |
| `provider` | `typesafe`, `openrouter`, `vercel`, `cloudflare` or `custom` — or `failproofai`, whose key comes from the FailproofAI Cloud connection instead of this file (see [Jev through FailproofAI Cloud](/he/reference/jev-cloud)). |
| `apiKey` | שלח כ-`Authorization: Bearer <key>`. |
| `baseUrl` | נדרש עבור `custom`; מחליף את ה-API base של הספק אחרת. חייבת להיות `https`. Plain `http` ל-`localhost` מקובל רק עם `mode: observe`: כלום לא מאמת שרת מקומי, אז בזמן שה-proxy שלך למטה כל תהליך על המכונה, כולל האגנט נשפט, יכול לענות במקום שלו. |
| `accountId` | Cloudflare בלבד: 32 תווים hex קטנים. |
| `model` | מחליף את מזהה המודל של ברירת המחדל של הספק. מזהה גרסה חייב להוציא Jev 1.13. ערך שעוצב כמו מפתח API סירב (ולא חזר חזרה), אז מפתח הדבק ל-`--model` לעולם לא מאוחסן או נשלח כמודל. |
| `timeoutMs` | כמה זמן קריאת כלי מחכה עבור Jev לפני שימוש בתוצאת ה-regex. 100–10000, ברירת מחדל 3000. |
| `mode` | `enforce` (ברירת מחדל), `observe`, or `off` (שמור את התצורה, הפעל לא Jev). |

שלוש כללים מגנים עליו:

- **רק הבעלים.** זה כתוב עם הרשאות `0600`. העתק שכל משתמש או קבוצה אחרת יכולה קרא או לכתוב אל היא **מסרבת**, ו-hooks חזרה ל-regex עד שתפעיל `chmod 600 ~/.failproofai/jev.json` או `setup` שוב. ה-directory בדוק גם: `~/.failproofai` חייבת לא להיות **כתיבה** על ידי מישהו אחר, כי מי יכול לכתוב שם יכול להחליף את הקובץ כל הרשאות שלו הן. `setup` לוקח את ביטים הכתיבה בהם אם זה משם. `failproofai jev status` אומר כאשר תצורה נדחתה ו\shows endpoint הקובץ שומות: מישהו אחר יכול היה שינוי זה, אז בדוק זה שלך לפני `chmod`. Re-running `setup` על קובץ כזה נושא המפתח המאוחסן שלו רק ל-API שלו הספק; כל endpoint אחרת שהוא שומות צריך את המפתח שוב (`--key-stdin`), או `--base-url default` לשלח בקשות חזרה לספק.
- **רק גלובלי.** מאגר לא יכול הופכת Jev, נקודה זה בנקודת קצה אחרת או בחר את המודל שלו: `.failproofai/jev.json` בתוך פרויקט זה מתעלמים, וספק, URL, מודל וחשבון id נקראים רק מקובץ זה — לעולם לא מהסביבה, שהגדרות האגנט של המאגר יכול קבוצה. (`FAILPROOFAI_HOME` אינו דרך סביב כך: זה עוברת הכל failproofai directory, שלך מדיניויות כלול, ולא ל-Jev ב.oown.)
- **רק המפתח לבדו עלול לבוא מסביבה.** אם הקובץ אין `apiKey`, `FAILPROOFAI_JEV_API_KEY` מסופק עבור סעיף זה (`setup --key-from-env` כתיבה קובץ כזה). זה לעולם לא מחליף מפתח הקובץ מחזיק, וזה לא יכול להופכת Jev ללא הקובץ. שבו משתנה לא קבוצה, Jev הוא כנראה עבור קונכייה: `failproofai jev status` אומר כך, יצאים 0 ולעזוב התצורה לבדה (`status --json` דוחות `"status": "key-missing"` עם `"reason": "no-env-key"`). ה-daemon `failproofaid` אינו רואה את הסביבה של קונכיית שלך, אז על מכונה הגדרה עם `failproofai config`, שמור את המפתח בקובץ.

## איזה Jev משיב

Failproof AI's בחירתsolve סף תו calibrated עבור Jev 1.13, אז תשובה משמשת רק כאשר זה מגיע משפחה: `jev-1.13.x`, או OpenRouter עבור `typesafe/jev-1.13-<date>`. שבו ספק שמות Jev רק על ידי כינוי וודוחות אין גרסה (Vercel, וCloudflare כאשר זה לא סיפור), התשובה משמשת ומתועדת כלא מאומתת. `custom` endpoint חייבת ודוחות המודל השיב; ה- exception אחד הוא unversioned `--model` שם יש על פנימה עבור זה, אשר, echoed חזרה, מתועדת כלא מאומתת בדומה דרך. התשובה הוא דוחות כל גרסה אחרת, או `custom` תשובה דוחות כלום, לא משמשים: הקריאה כי חזרה ל-regex עם הסיבה `model-mismatch`.

## כאשר Jev אינו יכול לענות

כל אלה חזרה ל-regex תוצאה עבור הקריאה כי ו\recorded עם הסיבה שלו, ש `failproofai jev status` totals:

| סיבה | סיבה |
| --- | --- |
| `timeout` | אין תשובה בתוך `timeoutMs`. |
| `http-429` | הספק rate-limited את המפתח. |
| `rate-limited` | Failproof AI's שלו limiter של הסתיים קריאה לפני שליחה: 5 בקשות דפי ש\burst של עד 5, ו\nothing דקה אחרי הספק תשובות `429`. לא הספק. |
| `http-500`, `http-502`, `http-503`, … | שגיאה שרת בספק. הסטטוס המדויק מתועדת. |
| `out-of-credits` | HTTP 402: חשבון הספק אין credits שנותרו. |
| `provider-refused` | HTTP 402 מCloudflare קריאה עם Message "Model execution failed (Payment error)": הספק סירב להשמיע המודל בבקשה זו. בדרך כלל לא חיוב, אז עבור credits לא להזיז זה. |
| `http-401`, `http-403` | המפתח נדחה. |
| `http-404` | כלום זה כיבד ב-`<base>/systemone`, כאן base URL זה לא נכון — `/systemone` הוא מוספיעה עליו, וכל ספק זה כיבד בגרסה שלו שורש. `failproofai jev models` מראה מה endpoint כן כיבד. |
| `network` | ה-endpoint לא יכול להיות מגיע אל. |
| `http-301`, `http-302`, `http-307`, `http-308` | ה-endpoint answered עם redirect. Redirects הם לעולם לא עקוב, אז התשובה רק לעולם מגיע מה-URL בתצורה שלך; קבוצה `--base-url` לה-URL הסופית. |
| `malformed` | ה-endpoint answered, אך לא עם תשובה Jev — גוף שזה לא JSON, או אחד עם אין תשובות. |
| `cloudflare-error`, `cloudflare-incomplete` | Cloudflare's כיס דיווח כשל, או עבודה שלא הוטמעה. |
| `model-mismatch` | גרסה Jev אחרת מ-1.13 answered, או `custom` endpoint לא סיפור איזה מודל answered. |
| `request-cut` | **לא שבר.** Jev answered; זה היה הצג רק חלק הקריאה, אז התשובה מנוקה כלום. ראה [כאשר Jev answered, אך לא בכל הקריאה](#when-jev-answered-but-not-on-the-whole-call). |

`failproofai jev status` יכול להציג סיבות נדירות גם כן, כמו `upstream-error` (התשובה נשאה שלו הספק הטעות) או `config`, ו\totals כל סיבה זה לא יכול להוציא כמו `other`.

`request-cut` בטבלה כי `failproofai jev status` totals זה עם השאר, וכי זה גם עוזב כל תיקיה ללא עמידה. זה סיבה אחת שבו סיפור כלום על הספק שלך: הבקשה הגיעה וJev answered זה. בניגוד לכל שורה מעל זה, התשובה עדיין counts — Jev תו דחייה או אזהרה מתחיל עם regex תוצאה ולא זה מנותח. אז הפעם שלהם אומר קריאות מגיעות מהמעריך גדול מדי לשלוח בחד, לא כי endpoint שלך לא בריא, וטופל credits או הקרה URL לא להזיז את המספר.

## כאשר Jev answered, אך לא בכל הקריאה

שתיים עוד דברים עלול לקרות, ואף אחד לא Jev כשל לענות. שתיהן הן על כמה הקריאה, או השיחה, התאם לשורה אחת בקשה.

**חלק הקריאה עצמו לא התאם.** כלי קריאה משלח בתוך תקציב קבוע, וOutsized אחד — גדול ורות `Write`, ענק MCP גוף, פקודה מרופדת לה-cap — משלח עם מה התאם. Jev עדיין answered, ותשובה עדיין counts: תו דחייה או אזהרה מתחיל כרגיל. מה זה לא יכול לעשות **מנוקה** כלום, כי פסק דין נתן בחלק קריאה לא פסק דין עבור קריאה. אז כל מדיניות דחיית עמידה, והקריאה מתועדת כנסיגה עם הסיבה `request-cut`, ש `failproofai jev status` totals לצד הסיבות מעל. הכלל זה נותן לך: יצור קריאה גדול יכול דמות להיקבל clearances, ויכול לעולם לא רכישה אחד.

**הודעה לא התאם.** אורך prompt יש פסטה, Brokers הודעה האחרונה, או prompt זה evaluator קיים סכם כבר capped. **כלום לא משתנה**: הקריאה היא שפט, מנוקה וmattoed בדיוק כל אחרת, וזה לא counted כנסיגה. האורך של מה סוג לעולם מחליט פסק דין, ו\cut לא יכול בייצור הסכמה: שבו prompt הגיע כבר capped, "אתה לא ביקשת זה" חדל להיות מסקנה שיכול להיות מתוך זה הכל, ולא הופכת אחד.

קו בין השניים היא מי כתיבה את הטקסט. קריאה היא האגנט, וכלל שהיא באורך Subtract קפדנות היה כלל האגנט יכול להשתמש; prompt שלך זה שלך, וטיפול אורך כסימן רק לעולם punished הדבק מפרט או ערימה trace.

## מה עוזב את המכונה

עבור כל כלי קריאה Jev evaluates, בקשה אחת הולכת לספק שלך, בנושא:

- קריאת כלי עצמו, עם סודות כמו מפתחות API, Bearer tokens וקצות `KEY=` מנוקה;
- prompts אחרונות אתה סוג, עם טקסט harness של האגנט הוסיף הסרה;
- הודעת האגנט האחרונה לפני prompt החדש ביותר של שלך, מסומנת כנכתב-agent;
- עובדות קומפילויד locally, כמו אם נתיב בתוך הפרויקט — אחד הsession היה בראשון סקור קריאה, [pinned לsession](/he/reference/jev-intent#the-project-root) — וגדל git branch יותר כן.

זה הולכת רק לendpoint בתצורה שלך, תחת המפתח שלך.

## כבו את זה

```bash
failproofai jev remove
```

זה מחק `~/.failproofai/jev.json`. מהקריאה כלי הבאה, hooks להפעיל את מדיניויות ה-regex בדיוק כמו לפני. Per-session stores תחת `~/.failproofai/state/semantic/` (Recorded prompts בתוך `sessions/`, שורשי פרויקט בתוך `roots/`) עוזבו במקום וגיל מחוץ. לעצור בקשת Jev אך שמור התצורה, להשתמש `failproofai jev setup --mode off` בעוד.

## Command reference

| פקודה | Outcome |
| --- | --- |
| `failproofai jev --url <url> --key-stdin` | הגדר את זה בפקודה אחת; הספק מגיע מ-URL's host |
| `failproofai jev --url <url> --token <token>` | Same, עם המפתח בשורת הפקודה — ההיסטוריה שלך וכל תהליך רשמות רואים את זה |
| `failproofai jev setup --provider <kind> --key-stdin` | כתוב את התצורה מ-key piped בstdin |
| `failproofai jev setup --provider <kind>` | Same, בבקשה עבור המפתח ב-prompt מסוכן |
| `failproofai jev setup --key-from-env` | שמור לא המפתח; קרא `FAILPROOFAI_JEV_API_KEY` לכל סעיף |
| `failproofai jev setup --mode observe` | Switch מצב (`enforce`, `observe` or `off`), שמור את המפתח מאוחסן |
| `failproofai jev setup --model <id>` / `--base-url <url>` | עקוף את המודל או API base; `default` מנקה את העקוף |
| `failproofai jev setup --timeout-ms <n>` | שנה את עבור כל קריאה תקציב |
| `failproofai jev status [--json]` | תצורה, הרשאות ופעילות אחרונה; לעולם המפתח |
| `failproofai jev test [--json]` | בקשה חיה אחת: latency והגרסה ש answered |
| `failproofai jev models [--provider <kind>] [--url <base>] [--json]` | מדל ids שendpoint ש`/models` דוחות, מסומן המוגדר אחד |
| `failproofai jev remove` | מחק את התצורה; Jev הוא כבו |
