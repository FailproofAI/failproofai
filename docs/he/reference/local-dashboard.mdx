הריצו את `failproofai` ללא ארגומנטים כדי להתחיל את לוח הבקרה המוקנה בכתובת `http://localhost:8020`. הוא קורא היסטוריות סוכנים מקומיות, תצורת מדיניות, תוצאות ביקורות ופעילות hook ישירות מהמחשב.

לוח הבקרה המקומי נפרד מ-Failproof AI Cloud. הוא עובד ללא חשבון Cloud ואינו מוכיח שהאירועים נמסרו לארגון שלך.

## אזורי לוח הבקרה

| אזור | מה אתה יכול להשיג |
| --- | --- |
| Policies → Activity | בדקו החלטות allow, instruct ו-deny מקומיות; סננו לפי החלטה, אירוע, CLI, כלי, מקור, מדיניות והפעלה. |
| Policies → Configure | הפעילו beiltins מובנים, ערכו פרמטרים נתמכים, עברו על מדיניות מותאמות שגילו, וחרו harnesses מטרה. |
| Projects | עיינו בפרויקטים שגילו על פני היסטוריות סוכנים נתמכות והשוו את ההפעלות האחרונות שלהם. |
| Project sessions | פתחו תנס מקומי אחד, בדקו ערכים מעוקלים גולמיים וסוכנים משנה, הורידו אותו, וקשרו פעילות מדיניות. |
| Audit | בדקו את הסריקה הלא מקוונת האחרונה, דפוסים בסיכון, נקודות חוזק, פרויקטים מושפעים ומדיניות beiltins מומלצת. |
| Settings | תצורה לתסריטים מקומיים מתוזמנים וקבלת דוחות ביקורות בדוא״ל כאשר ה-daemon/platform תומכים בכך. |

## ביקורת פעילות מדיניות

<Tabs>
  <Tab title="Dashboard">
    1. פתחו **Policies → Activity** וקבעו את סנני ההחלטה והמקור.
    2. צמצמו לפי אירוע, harness, כלי או שם מדיניות.
    3. הרחיבו שורה כדי לבדוק את הסיבה שלה, מדיניות תואמות, מקור, מצב ביצוע ומשך הזמן.
    4. עקבו אחר הקישור של ההפעלה כדי למקם את ההחלטה בהקשר הנסקריפט.

    שורה שנראית כמו denied עדיין יכולה להיות תצפיתית על צמד harness/event שלא צורך קבלות חסימה. התצוגה המפורטת מדגישה יכולת אכיפה מאומתת.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    פעילות מקומית מאוחסנת תחת `~/.failproofai/hook-activity`. השתמשו בלוח הבקרה במקום לערוך קבצים אלו.
  </Tab>
</Tabs>

## תצורת מדיניות מקומית

<Tabs>
  <Tab title="Dashboard">
    1. פתחו **Policies → Configure** וחרו את ה-harnesses וההיקף של התצורה.
    2. הפעילו מדיניות מובנית או מדיניות מותאמת שגילו.
    3. עבור מדיניות מובנית פרמטרית, פתחו את בקרת התצורה שלה ושמרו ערכים נתמכים.
    4. חזרו לפעילות והריצו פעולות תואמות ואי-תואמות.

    מדיניות קונוונציה מציגה את מקור הפרויקט או המשתמש שלהם. שינויים בנתיב מותאם מפורש עשויים לדרוש הרצה מחדש של תצורת CLI כך שהנתיב הנבחר יירשם.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```
  </Tab>
</Tabs>

## עיון בפרויקטים והפעלות

עמוד הפרויקטים משלב חנויות היסטוריה מקומיות נתמכות. בחרו פרויקט כדי לרשום את ההפעלות שלו, ופתחו הפעלה עבור צופה הלוג הגולמי, קטעי סוכנים משנה, פעולת הורדה ופעילות מדיניות בהיקף ההפעלה.

אם פרויקט או הפעלה חסרים, אשרו שה-harness משתמש בموקום ההיסטוריה שלו או רשמו שורש נוסף עם `failproofai harness add-path`.

## תזמון ביקורות לא מקוונות

<Tabs>
  <Tab title="Dashboard">
    פתחו **Settings**, הפעילו סריקה מתוזמנת, בחרו בהיקף הנתמך שלה, והגדירו משלוח דוח כאשר זה זמין. העמוד מדווח על ההרצה הבאה, ההרצה האחרונה, קוד יציאה וקובע אם ה-daemon background נתמך בפלטפורמה.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    שנו את מספר הימים כדי להגדיר היקף שונה של 1–90 ימים. השבתו סריקות חוזרות עם `failproofai audit --no-schedule`; הריצו את `failproofai audit` לסריקה אינטראקטיבית מיידית.
  </Tab>
</Tabs>

<Warning>
  לוח הבקרה המקומי יכול להציג הנחיות, קלט כלים, תוכן קובץ ופלט טרמינל מהיסטוריות סוכנים מקומיות. קשרו אותו רק לממשקים מהימנים ועצרו את התהליך כאשר הביקורת הושלמה.
</Warning>
