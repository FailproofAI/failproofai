הרץ את `failproofai` ללא ארגומנטים כדי להפעיל את לוח הבקרה המצורף ב-`http://localhost:8020`. הוא קורא היסטוריות סוכנים מקומיות, תצורת מדיניות, תוצאות ביקורת ופעילות ווק ישירות מהמכונה.

לוח הבקרה המקומי הוא נפרד מ-Failproof AI Cloud. הוא עובד ללא חשבון Cloud ולא מוכיח שאירועים סופקו לארגון שלך.

## אזורי לוח הבקרה

| אזור | מה אתה יכול להשיג |
| --- | --- |
| Policies → Activity | בדוק החלטות allow, instruct ו-deny מקומיות; סנן לפי החלטה, אירוע, CLI, כלי, מקור, מדיניות והפעלה. |
| Policies → Configure | הפעל builtins, ערוך פרמטרים נתמכים, הפעל/כבה מדיניות מותאמות שהתגלו, ובחר harnesses היעד. |
| Projects | עיין בפרויקטים שהתגלו על פני היסטוריות סוכנים נתמכות והשווה את ההפעלות האחרונות שלהם. |
| Project sessions | פתח תמליל מקומי אחד, סקור כניסות מסודרות גולמיות וסוכנים משנים, הורד אותו וקשר פעילות מדיניות. |
| Audit | סקור את הסריקה הלא מקוונת האחרונה, דפוסים מסוכנים, חוזקות, פרויקטים המושפעים ומדיניות builtins מוצעת. |
| Settings | תצור סריקות מקומיות מתוזמנות ודוחות ביקורת בדוא״ל כאשר ה-daemon/platform תומך בהם. |

## סקור פעילות מדיניות

<Tabs>
  <Tab title="לוח בקרה">
    1. פתח **Policies → Activity** והגדר את מסנני ההחלטה והמקור.
    2. צמצם לפי אירוע, harness, כלי או שם מדיניות.
    3. הרחב שורה כדי לבדוק את הסיבה שלה, מדיניות תואמות, מקור, מצב ביצוע ומשך הזמן.
    4. עקוב אחר קישור ההפעלה כדי למקם את ההחלטה בהקשר התמליל.

    שורה שנראית כ-denied יכולה עדיין להיות תצפית על זוג harness/event שלא צורך גזירות חוסימה. תצוגת הפרטים מדגישה יכולת אכיפה מאומתת.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    פעילות מקומית מאוחסנת תחת `~/.failproofai/hook-activity`. השתמש בלוח הבקרה במקום לערוך קבצים אלה.
  </Tab>
</Tabs>

## תצור מדיניות באופן מקומי

<Tabs>
  <Tab title="לוח בקרה">
    1. פתח **Policies → Configure** ובחר ב-harnesses וטווח התצורה.
    2. הפעל builtin או מדיניות מותאמת שהתגלתה.
    3. עבור builtin עם פרמטרים, פתח את בקרת התצורה שלו ושמור ערכים נתמכים.
    4. חזור ל-Activity והרץ פעולות תואמות ואי-תואמות.

    מדיניות קונבנציה מציגה את מקור הפרויקט או המשתמש שלהם. שינויים מפורשים של custom-path עשויים לדרוש הרצה מחדש של תצורת CLI כך שהנתיב שנבחר יתועד.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```
  </Tab>
</Tabs>

## עיין בפרויקטים והפעלות

דף Projects משלב חנויות היסטוריה מקומיות נתמכות. בחר בפרויקט כדי לרשום את ההפעלות שלו, ואז פתח הפעלה עבור תצוגת הרישום הגולמית, קטעי סוכנים משנים, פעולת הורדה ופעילות מדיניות בטווח ההפעלה.

אם פרויקט או הפעלה חסרים, אשר שהרתיחה משתמשת בموقع ההיסטוריה הברירה שלה או רשום שורש נוסף עם `failproofai harness add-path`.

## תזמן ביקורות לא מקוונות

<Tabs>
  <Tab title="לוח בקרה">
    פתח **Settings**, הפעל סריקה מתוזמנת, בחר במרווח הנתמך שלה, וכוונן את הספקת הדוח כאשר היא זמינה. הדף מדווח על ההרצה הבאה, ההרצה האחרונה, קוד היציאה וההאם daemon ברקע נתמך בפלטפורמה.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    שנה את מספר הימים כדי להגדיר מרווח שונה בן 1–90 ימים. השבת סריקות חוזרות ונשנות עם `failproofai audit --no-schedule`; הרץ את `failproofai audit` עבור סריקה אינטראקטיבית מיידית.
  </Tab>
</Tabs>

<Warning>
  לוח הבקרה המקומי יכול להציג הנחיות, קלט כלים, תוכן קבצים ופלט טרמינל מהיסטוריות סוכנים מקומיות. קשר אותו רק לממשקים מהימנים ועצור את התהליך כאשר הסקירה הושלמה.
</Warning>
