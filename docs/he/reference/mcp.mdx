חבר כלי AI ל-Failproof AI Cloud ועבוד עם הנתונים של הסוכנים שלך ממנו. הכלי שלך יכול לשאול עבור סשנים והאירועים, להריץ SQL בקריאה בלבד, לקרוא דשבורדים, התראות, בעיות, ביקורות ומדיניות, ואם יש לך הרשאה, לבצע שינויים כגון יצירת התראה או פריסת מדיניות.

כל קריאה פועלת עם **הרשאות שלך**, באחת **ארגון** אחד שתבחר בעת ההתחברות.

יש כתובת אחת לכולם, בהנהלה עצמית או בעצמי:

```text
https://gateway.befailproof.ai/mcp
```

## חברות לקוח

הוסף את הכתובת ללקוח שלך. בפעם הראשונה שבה משתמשים בכלי, הדפדפן שלך נפתח. בחר היכן נמצא Failproof AI Cloud שלך, היכנס לחשבון שלך, בחר ארגון אחד, ובחר **אפשר**. **ביטול** לא מחבר שום דבר.

הדף שם את האפליקציה ולאיזה מקום היא חוזרת. אפליקציה שלא מזוהה על ידי כתובת הרשת שלה מסומנת **אפליקציה לא מאומתת**, אז המשך רק אם זה עתה התחלת זאת מהלקוח שלך.

<Tabs>
  <Tab title="Claude">
    ב-claude.ai או Claude Desktop, עבור אל **Settings → Connectors → Add custom connector**. שם אותו `Failproof AI`, הזן את הכתובת, בחר **Add**, ואז **Connect**.

    בתוכניות Team ו-Enterprise, בעלים מוסיף את ההשחבור של הארגון תחילה. לאחר מכן כל אדם מחבר את החשבון שלו.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    לאחר מכן הרץ `/mcp` בתוך Claude Code, בחר `failproofai`, ובחר **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    הוסף זאת ל-`~/.cursor/mcp.json`, או ל-`mcp.json` של הפרויקט שלך:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor מציג **Needs login** ליד השרת. בחר בו כדי להיכנס.
  </Tab>
  <Tab title="Codex">
    הוסף זאת ל-`~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    לאחר מכן הרץ `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    כל לקוח התומך בשרתי MCP מרחוק על HTTP זרימי עם OAuth עובד. תן לו את הכתובת לעיל. אין מזהה לקוח או סוד להגדרה.
  </Tab>
</Tabs>

## ארגון אחד לכל התחברות

חיבור פועל רק בארגון שבחרת. כדי להשתמש בשני ארגונים, הוסף את השרת פעמיים תחת שמות שונים, כגון `failproofai-acme` ו-`failproofai-sandbox`, וחבר כל אחד לארגון שלו.

ארגוני הדמו לא מקבלים חיבורים. בחר בארגון שלך במקום זאת.

## הרשאות

חיבור יכול לעשות מה שאתה יכול לעשות בארגון, בתוך הסט להלן. זה עוקב אחרי ההרשאות הנוכחיות שלך: אם מנהל נותן לך יותר, הכלי משיג זאת, ואם הם לוקחים משהו משם, הכלי מאבד זאת בקריאה הבאה שלו.

| הרשאה | מאפשר לכלי |
| --- | --- |
| `events:read` | רישום אירועים, קריאת סקירה כללית של סשן, רישום סוכנים וסביבות |
| `evaluations:read` | רישום סשנים, קריאה וסיכום תוצאות הערכה וביצוע עבודות |
| `evaluations:trigger` | יצירת הערכות, פרסום גרסאות חדשות, הפעלה וכיבוי שלהן, מילוי לאחור והערכה מחדש של סשן |
| `dashboards:read`, `dashboards:write` | קריאת דשבורדים, או יצירה, שינוי שם והוספת שאילתות אליהם |
| `queries:read`, `queries:write` | קריאת שאילתות שמורות, או שמירה וערוך שלהן |
| `queries:run` | הרצת שאילתת SQL אחת בקריאה בלבד וקריאה של סכמת השאילתה |
| `alerts:read`, `alerts:write` | קריאת התראות, או יצירה, עריכה, השהיה, מחיקה and בדיקה שלהן |
| `issues:read` | קריאת בעיות, הכרה בהן וטיפול בהן |
| `issues:create` | פתיחת בעיה בהתראה |
| `issues:close` | פתרון וסגירת בעיות |
| `audits:read`, `audits:write` | קריאת ביקורות, הרצות וממצאים, או יצירה וערוך ביקורות והתחלת הרצה |
| `code_fixes:read` | ראה כיצד לתקן בעיה, קבל את ההקשר שלה עבור הסוכן שלך לתיקון |
| `code_fixes:write` | התחל תיקון ב-Failproof AI Cloud, המציג בקשת משיכה ב-GitHub שלך |
| `policies:read`, `policies:write` | קריאת מדיניות, מכונות וגזירות, או פרסום, פריסה וחזרה על מדיניות |

כמה כלים לא צריכים הרשאה מכיוון שהם לא קוראים נתוני ארגון: בניית קישורי סשן והאירוע, וחיפוש בתיעוד זה.

כלי AI לעולם לא יכול לגעת במפתחות API, משתמשים, הגדרות או ניהול ארגוני, וזה לא יכול לשלוח אירועים.

## אישור שינויים

כתבות שואלות אותך תחילה אם הלקוח שלך יכול להציג את ההנמקה. אתה רואה מה ישתנה ובוחר **אשר שינוי זה** כדי להמשיך. אם אתה דוחה או לא עונה תוך כ-4 דקות, שום דבר לא משתנה. כמה לקוחות מפסיקים להמתין אחרי דקה, אז התשובה מהר.

<Warning>
  לקוח שאינו תומך בהנמקות לא נשאל, וכתבה פועלת ברגע שהלקוח עושה את הקריאה. שם, ההיכרות של הלקוח שלך הוא היחיד, אז שמור אותו פועל לכלים לכתיבה.
</Warning>

## אפליקציות מחוברות וביטול

**Settings → Integrations → MCP** מפרט את האפליקציות המחוברות שלך בארגון הנוכחי, עם ההרשאות שלהן והשימוש האחרון. **ביטול** חותך אפליקציה מיד. הסרת השרת בלקוח שלך גם מבטלת את ההתחברות.

אתה יכול להיות עד 5 אפליקציות מחוברות לכל ארגון. חיבור אותה אפליקציה שוב מחליף את ההתחברות הקודמת שלה.

## פריסות בנהלול עצמי

בחר **Self-hosted Failproof AI Cloud** בעת ההתחברות, והזן את הכתובת שבה אתה מתחבר. ההפקה שלך חייבת להיות נגישה דרך HTTPS ציבורי.

קריאות כלים והתוצאות שלהם עוברות דרך שער Failproof AI המוזן בדרכם בין כלי ה-AI שלך להפקה שלך. השער לא אחסון אותם.

## מה קורה לנתונים שלך

תוצאות הולכות לכלי ה-AI שחיברת, וספק הכלי הזה מטפל בהם לפי התנאים שלו. לכל קריאה כלי, Failproof AI רשומי שם הכלי, התוצאה שלו, כמה זמן לקח, וארגון, לעולם לא את הטיעונים או התוצאות. ראה את [מדיניות הפרטיות](https://befailproof.ai/privacy/).
