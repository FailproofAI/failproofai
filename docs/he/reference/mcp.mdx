חבר כלי AI ל-Failproof AI Cloud והשתמש בנתוני הסוכנים שלך מתוכו. הכלי שלך יכול לשלח שאילתות לפעילויות וסטטיסטיקות, להפעיל SQL לקריאה בלבד, לקרוא לוח מחוונים, התראות, בעיות, ביקורות ומדיניות, ואם יש לך את ההרשאה, לבצע שינויים כגון יצירת התראה או פריסת מדיניות.

כל קריאה מתבצעת עם **ההרשאות שלך שלך**, בארגון **אחד** שתבחר בעת ההתחברות.

יש כתובת אחת לכולם, מעוגנת או מושמת בעצמך:

```text
https://gateway.befailproof.ai/mcp
```

## חברת לקוח

הוסף את הכתובת ללקוח שלך. בפעם הראשונה שבה משתמשים בכלי, הדפדפן שלך נפתח. בחר היכן ה-Failproof AI Cloud שלך נמצא, התחבר, בחר ארגון אחד, ובחר **Allow**. **Cancel** לא מחבר כלום.

הדף מציין את שם האפליקציה ולאן היא חוזרת. אפליקציה שאינה מזוהה בכתובת האינטרנט שלה משלה מסומנת כ-**unverified app**, לכן המשך רק אם התחלת זה עתה מהלקוח שלך.

<Tabs>
  <Tab title="Claude">
    ב-claude.ai או Claude Desktop, עבור ל-**Settings → Connectors → Add custom connector**. קרא לו `Failproof AI`, הזן את הכתובת, בחר **Add**, ואז **Connect**.

    בתוכניות Team ו-Enterprise, בעל מוסיף את המחבר עבור הארגון תחילה. לאחר מכן כל אדם מחבר את החשבון שלו.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    לאחר מכן הפעל `/mcp` בתוך Claude Code, בחר `failproofai`, ובחר **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    הוסף זאת ל-`~/.cursor/mcp.json`, או ל-`mcp.json` של הפרויקט שלך:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor מציג **Needs login** ליד השרת. בחר בו כדי להתחבר.
  </Tab>
  <Tab title="Codex">
    הוסף זאת ל-`~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    לאחר מכן הרץ `codex mcp login failproofai`.
  </Tab>
  <Tab title="לקוחות אחרים">
    כל לקוח התומך בשרתי MCP מרוחקים על פני Streamable HTTP עם OAuth עובד. תן לו את הכתובת למעלה. אין ID לקוח או סוד להגדיר.
  </Tab>
</Tabs>

## ארגון אחד לכל חיבור

חיבור פועל רק בארגון שבחרת. כדי להשתמש בשני ארגונים, הוסף את השרת פעמיים בשמות שונים, כגון `failproofai-acme` ו-`failproofai-sandbox`, וחבר כל אחד לארגון שלו.

ארגוני ניסיון לא מקבלים חיבורים. בחר בארגון משלך במקום זאת.

## הרשאות

חיבור יכול לעשות מה שאתה יכול לעשות בארגון, בתוך הקבוצה למטה. זה עוקב אחרי ההרשאות הנוכחיות שלך: אם מנהל נותן לך עוד, הכלי מקבל את זה, ואם הם לוקחים משהו משם, הכלי מאבד את זה בקריאה הבאה שלו.

| הרשאה | מאפשרת לכלי |
| --- | --- |
| `events:read` | הצג רשימת סטטיסטיקות, קרא סקירה של פעילות, הצג רשימת סוכנים וסביבות |
| `evaluations:read` | הצג רשימת פעילויות, קרא וסכם תוצאות והשגות הערכה |
| `evaluations:trigger` | צור הערכות, פרסם גרסאות חדשות, הפעל או כבה אותן, גיבוי חזרה, והערך מחדש פעילות |
| `dashboards:read`, `dashboards:write` | קרא לוח מחוונים, או צור, שנה שם והוסף שאילתות אליהם |
| `queries:read`, `queries:write` | קרא שאילתות שמורות, או שמור וערוך אותן |
| `queries:run` | הרץ שאילתת SQL אחת לקריאה בלבד וקרא את סכימת השאילתה |
| `alerts:read`, `alerts:write` | קרא התראות, או צור, ערוך, השהה, מחק ובדוק אותן |
| `issues:read` | קרא בעיות, הכר בהן והעיר עליהן |
| `issues:create` | פתח בעיה בהתראה |
| `issues:close` | פתור וסגור בעיות |
| `audits:read`, `audits:write` | קרא ביקורות, הרצות ממצאים, או צור וערוך ביקורות והפעל הרצה |
| `code_fixes:read` | ראה כיצד לתקן בעיה, וקבל את ההקשר שלה כדי שהסוכן שלך יוכל לתקן |
| `code_fixes:write` | התחל תיקיה ב-Failproof AI Cloud, המפתח בקשת משיכה ב-GitHub שלך |
| `policies:read`, `policies:write` | קרא מדיניות, מכונות והצבות, או פרסם, פרוס וחזור על מדיניות |

כמה כלים אינם זקוקים להרשאה מכיוון שהם לא קוראים נתוני ארגון: בניית קישורי פעילות ועסטטיסטיקה, וחיפוש בתיעוד זה.

כלי AI לעולם לא יכול לגעת במפתחות API, משתמשים, הגדרות או ניהול ארגון, וזה לא יכול לשלוח סטטיסטיקות.

## אישור שינויים

כתיבה שואלת אותך תחילה אם הלקוח שלך יכול להציג את ההודעה. אתה רואה מה יתשנה ובוחר **Approve this change** כדי להמשיך. אם אתה מסרב או לא עונה תוך כ-4 דקות, שום דבר לא משתנה. כמה לקוחות מפסיקים להמתין אחרי דקה, אז תשיב במהירות.

<Warning>
  לקוח שאינו תומך בהודעות לא נשאל, וכתיבה מתבצעת ברגע שהלקוח מבצע את הקריאה. שם, ההאשה של הלקוח שלך היא היחידה, אז שמור אותה במצב כבוי לכלים כתובים.
</Warning>

## אפליקציות מחוברות וביטול

**Settings → Integrations → MCP** מפרט את האפליקציות המחוברות שלך בארגון הנוכחי, עם ההרשאות שלהן וההשתמש האחרון. **Revoke** חותך אפליקציה מיד. הסרת השרת בלקוח שלך גם מבטלת את החיבור.

יכול להיות לך עד 5 אפליקציות מחוברות לכל ארגון. חיבור של אותה אפליקציה שוב מחליף את החיבור הקודם שלה.

## פריסות מושמות בעצמן

בחר **Self-hosted Failproof AI Cloud** בעת ההתחברות, והזן את הכתובת שבה אתה מתחבר. הפריסה שלך חייבת להיות נגישה ב-HTTPS ציבורי.

קריאות כלים והתוצאות שלהם עוברות דרך שער Failproof AI מעוגן בדרכן בין כלי ה-AI שלך לפריסה שלך. השער לא שומר אותם.

## מה קורה לנתונים שלך

התוצאות עוברות לכלי ה-AI שחיברת, וספק הכלי משלך מטפל בהם בתנאים שלו. עבור כל קריאת כלי, Failproof AI רושם את שם הכלי, את התוצאה שלו, כמה זמן לקח, והארגון, לעולם לא את הטיעונים או התוצאות. ראה את [מדיניות הפרטיות](https://befailproof.ai/privacy/).

## פתרון בעיות

| מה אתה רואה | מה לעשות |
| --- | --- |
| "Started in another browser" | סיים כניסה בדפדפן שהלקוח פתח, עם עוגיות מותרות, והתחל שוב מהלקוח |
| שגיאה אחרי **Allow** | הקישור עובד פעם אחת ופוקע אחרי 10 דקות, לכן התחל שוב מהלקוח |
| כלי שציפית לו חסר | אתה לא מחזיק בהרשאה שלו בארגון זה. בקש מאדמין. אתה לא צריך להתחבר מחדש ברגע שיש לך את זה |
| הלקוח מעדכן אותך להתחבר | החיבור בוטל, עזבת את הארגון, או הוא לא שימש למשך 90 ימים. התחבר שוב |
| "You have 5 connected apps" | בטל אחד תחת **Settings → Integrations → MCP**, ואז התחבר שוב |
