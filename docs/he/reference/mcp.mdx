חבר כלי AI ל-Failproof AI Cloud והתחל לעבוד עם נתוני הסוכנים שלך מתוכו. הכלי שלך יכול לשאול על הפעלות ואירועים, להריץ SQL לקריאה בלבד, לקרוא לוחות בקרה, התריעות, בעיות, ביקורות ומדיניויות, ואם יש לך את ההרשאה, לבצע שינויים כמו יצירת התרעה או פריסת מדיניות.

כל קריאה פועלת עם **ההרשאות שלך**, באחת מ**ארגון** אחד שתבחר בעת החיבור.

יש כתובת אחת לכולם, מארוחת או בעצמאות:

```text
https://gateway.befailproof.ai/mcp
```

## חיבור לקוח

הוסף את הכתובת ללקוח שלך. בפעם הראשונה בה משתמשים בכלי, הדפדפן שלך נפתח. בחר איפה ה-Failproof AI Cloud שלך נמצא, היכנס, בחר ארגון אחד, ובחר **Allow**. **Cancel** לא מחבר כלום.

הדף מציין את שם האפליקציה והמקום שהיא חוזרת אליו. אפליקציה שאינה מזוהה על ידי כתובת אינטרנט שלה משלה מסומנת **unverified app**, אז המשך רק אם בדיוק התחלת זה מהלקוח שלך.

<Tabs>
  <Tab title="Claude">
    ב-claude.ai או Claude Desktop, עבור ל-**Settings → Connectors → Add custom connector**. שם את זה `Failproof AI`, הכנס את הכתובת, בחר **Add**, ואז **Connect**.

    בתוכניות Team ו-Enterprise, בעלים מוסיף את הקונקטור עבור הארגון תחילה. לאחר מכן, כל אדם מחבר את החשבון שלו.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    לאחר מכן הריץ `/mcp` בתוך Claude Code, בחר `failproofai`, ובחר **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    הוסף את זה ל-`~/.cursor/mcp.json`, או ל-`.cursor/mcp.json` של הפרויקט שלך:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor מציג **Needs login** לצד השרת. בחר בו כדי להיכנס.
  </Tab>
  <Tab title="Codex">
    הוסף את זה ל-`~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    לאחר מכן הריץ `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    כל לקוח התומך בשרתי MCP מרוחקים על פני Streamable HTTP עם OAuth עובד. תן לו את הכתובת למעלה. אין מזהה לקוח או סוד להגדרה.
  </Tab>
</Tabs>

## ארגון אחד לכל חיבור

חיבור פועל רק בארגון שבחרת. כדי להשתמש בשני ארגונים, הוסף את השרת פעמיים תחת שמות שונים, כמו `failproofai-acme` ו-`failproofai-sandbox`, וחבר כל אחד לארגון שלו.

ארגונים דמו לא מקבלים חיבורים. בחר בארגון שלך במקום זאת.

## הרשאות

חיבור יכול לעשות מה שאתה יכול לעשות בארגון, בתוך הסט להלן. זה עוקב אחר ההרשאות הנוכחיות שלך: אם מנהל נותן לך יותר, הכלי מקבל את זה, ואם הוא לוקח משהו, הכלי מאבד את זה בקריאה הבאה שלו.

| הרשאה | מאפשרת את הכלי |
| --- | --- |
| `events:read` | רשימת אירועים, קרא מבט חזותי של הפעלה, רשימת סוכנים וסביבות |
| `evaluations:read` | רשימת הפעלות, קרא וסכם תוצאות והעבודות של הערכה |
| `evaluations:trigger` | יצור הערכות, פרסם גרסאות חדשות, הדלק אותן או כבה אותן, מלא בחזרה, והערך מחדש הפעלה |
| `dashboards:read`, `dashboards:write` | קרא לוחות בקרה, או צור, שנה שם, והוסף שאילתות אליהם |
| `queries:read`, `queries:write` | קרא שאילתות שמורות, או שמור וערוך אותן |
| `queries:run` | הריץ שאילתת SQL אחת לקריאה בלבד וקרא את סכימת השאילתה |
| `alerts:read`, `alerts:write` | קרא התריעות, או צור, ערוך, עצור, מחק, ובדוק אותן |
| `issues:read` | קרא בעיות, הוקדש להן, ותגובה עליהן |
| `issues:create` | פתח בעיה בהתרעה |
| `issues:close` | פתור וסגור בעיות |
| `audits:read`, `audits:write` | קרא ביקורות, הפעלות, ממצאים, או צור וערוך ביקורות וזרוק הפעלה |
| `code_fixes:read` | ראה כיצד לתקן בעיה, וקבל את ההקשר שלה לסוכן שלך לתיקון |
| `code_fixes:write` | התחל תיקון ב-Failproof AI Cloud, שפותח בקשת pull ב-GitHub שלך |
| `policies:read`, `policies:write` | קרא מדיניויות, מכונות וקביעות, או פרסם, הצב, וגלגל בחזרה מדיניויות |

כמה כלים לא זקוקים להרשאה כי הם לא קוראים נתוני ארגון: בנייה של קישורי הפעלה ואירוע, וחיפוש בתיעוד זה.

כלי AI לא יכול לעולם לגעת במפתחות API, משתמשים, הגדרות, או ניהול ארגון, וזה לא יכול לשלוח אירועים.

## אישור שינויים

כתבות שואלות אותך תחילה אם הלקוח שלך יכול להציג את ההנחיה. אתה רואה מה ישתנה ובוחר **Approve this change** כדי להמשיך. אם אתה דוחה או לא עונה תוך כ-4 דקות, שום דבר לא משתנה. כמה לקוחות מפסיקים להמתין אחרי דקה, אז השב במהירות.

<Warning>
  לקוח שאינו תומך בהנחיות לא נשאל, וכתיבה פועלת ברגע שהלקוח מבצע את הקריאה. שם, האישור של הלקוח שלך הוא היחיד, אז הבא אותו על כלים לכתיבה.
</Warning>

## אפליקציות מחוברות והסרת הרשאות

**Settings → Integrations → MCP** מפרט את האפליקציות המחוברות שלך בארגון הנוכחי, עם ההרשאות והשימוש האחרון שלהן. **Revoke** חוסם אפליקציה באופן מיידי. הסרת השרת בלקוח שלך גם מבטלת את החיבור.

אתה יכול להיות בעל עד 5 אפליקציות מחוברות לכל ארגון. חיבור של אותה אפליקציה שוב מחליף את החיבור הקודם שלה.

## פריסות בעצמאות

בחר **Self-hosted Failproof AI Cloud** בעת החיבור, והזן את הכתובת בה אתה נכנס. הפריסה שלך חייבת להיות נגישה על פני HTTPS ציבורי.

קריאות כלים והתוצאות שלהם עוברות דרך שער Failproof AI מארוח בדרכם בין הכלי AI שלך לבין הפריסה שלך. השער לא מאחסן אותם.

## מה קורה לנתונים שלך

התוצאות הולכות לכלי AI שחיברת, וספק הכלי הזה מטפל בהם בתנאים שלו. לכל קריאת כלי, Failproof AI מרשם את שם הכלי, את התוצאה שלו, כמה זמן זה לקח, והארגון, לעולם לא את הטיעונים או התוצאות. ראה את [מדיניות הפרטיות](https://befailproof.ai/privacy/).

## פתרון בעיות

| מה אתה רואה | מה לעשות |
| --- | --- |
| "Started in another browser" | סיים כניסה בדפדפן שהלקוח פתח, עם קבצי cookie מותרים, והתחל שוב מהלקוח |
| שגיאה אחרי **Allow** | הקישור עובד פעם אחת וחולף לאחר 10 דקות, אז התחל שוב מהלקוח |
| כלי שציפית לו חסר | אין לך את ההרשאה שלו בארגון זה. בקש מהמנהל. אתה לא צריך להתחבר מחדש ברגע שיש לך את זה |
| הלקוח ממשיך לבקש ממך להיכנס | החיבור בוטל, עזבת את הארגון, או הוא לא שומש במשך 90 ימים. התחבר שוב |
| "You have 5 connected apps" | בטל את ההרשאה לאחד תחת **Settings → Integrations → MCP**, ואז התחבר שוב |
