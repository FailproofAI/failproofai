חבר כלי AI ל-Failproof AI Cloud ועבוד עם נתוני הסוכנים שלך ממנו. הכלי שלך יכול לשאול על הפעלות ואירועים, להריץ SQL קריאה בלבד, לקרוא לוחות מידע, התראות, בעיות, ביקורות ומדיניות, וכן, אם יש לך את ההרשאה, לבצע שינויים כמו יצירת התראה או פריסת מדיניות.

כל קריאה פועלת עם **ההרשאות שלך**, בארגון **אחד** שתבחר בעת ההתחברות.

יש כתובת אחת לכולם, בהוסטינג או בעצמי:

```text
https://gateway.befailproof.ai/mcp
```

## חיבור לקוח

הוסף את הכתובת ללקוח שלך. בפעם הראשונה שבה משתמשים בכלי, הדפדפן שלך נפתח. בחר איפה נמצאת Failproof AI Cloud שלך, התחבר, בחר ארגון אחד, וסמן **Allow**. **Cancel** לא מחבר דבר.

העמוד מציין את שם האפליקציה והמקום שבו היא חוזרת אליו. אפליקציה שלא מזוהה בכתובת האינטרנט שלה מסומנת **unverified app**, אז המשך רק אם הרגע התחלת זאת מלקוח שלך.

<Tabs>
  <Tab title="Claude">
    ב-claude.ai או Claude Desktop, עבור ל-**Settings → Connectors → Add custom connector**. שם אותו `Failproof AI`, הזן את הכתובת, בחר **Add**, ואחריו **Connect**.

    בתוכניות Team ו-Enterprise, בעלים מוסיף את הקonnector לארגון תחילה. כל אדם לאחר מכן מחבר את החשבון שלו.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    לאחר מכן הרץ `/mcp` ב-Claude Code, בחר `failproofai`, ובחר **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    הוסף זאת ל-`~/.cursor/mcp.json`, או ל-`mcp.json` של הפרויקט שלך:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor יציג **Needs login** ליד השרת. בחר אותו כדי להתחבר.
  </Tab>
  <Tab title="Codex">
    הוסף זאת ל-`~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    לאחר מכן הרץ `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    כל לקוח התומך בשרתי MCP רחוקים על פני HTTP Streamable עם OAuth עובד. תן לו את הכתובת למעלה. אין מזהה לקוח או סוד להגדרה.
  </Tab>
</Tabs>

## ארגון אחד לכל חיבור

חיבור פועל רק בארגון שבחרת. כדי להשתמש בשני ארגונים, הוסף את השרת פעמיים עם שמות שונים, כגון `failproofai-acme` ו-`failproofai-sandbox`, וחבר כל אחד לארגון משלו.

ארגוני Demo לא מקבלים חיבורים. בחר בארגון משלך במקום זאת.

## הרשאות

חיבור יכול לעשות מה שאתה יכול לעשות בארגון, בתוך הקבוצה להלן. זה עוקב אחר ההרשאות הנוכחיות שלך: אם מנהל מקבל לך עוד, הכלי מקבל את זה, ואם הם לוקחים משהו משם, הכלי מאבד את זה בקריאה הבאה שלו.

| הרשאה | מאפשרת לכלי |
| --- | --- |
| `events:read` | רשום אירועים, קרא סקירה כללית של הפעלה, רשום סוכנים וסביבות |
| `evaluations:read` | רשום הפעלות, וקרא וסכום תוצאות והעבודות של הערכה |
| `evaluations:trigger` | צור הערכות, פרסם גרסאות חדשות, הדלק אותן או כבה אותן, מלא לאחור, והערך מחדש הפעלה |
| `dashboards:read`, `dashboards:write` | קרא לוחות מידע, או צור, שנה שם, והוסף שאילתות אליהם |
| `queries:read`, `queries:write` | קרא שאילתות שמורות, או שמור וערוך אותן |
| `queries:run` | הרץ שאילתת SQL קריאה בלבד אחת וקרא את סכמת השאילתה |
| `alerts:read`, `alerts:write` | קרא התראות, או צור, ערוך, הושהה, מחק, ובדוק אותן |
| `issues:read` | קרא בעיות, הכר בהן, והגב עליהן |
| `issues:create` | פתח בעיה בהתראה |
| `issues:close` | פתור וסגור בעיות |
| `audits:read`, `audits:write` | קרא ביקורות, הרצות ממצאים, או צור וערוך ביקורות והתחל הרצה |
| `code_fixes:read` | ראה כיצד לתקן בעיה, וקבל את ההקשר שלה לסוכן שלך כדי לתקן |
| `code_fixes:write` | התחל תיקון ב-Failproof AI Cloud, שפותח בקשת pull ב-GitHub שלך |
| `policies:read`, `policies:write` | קרא מדיניות, מכונות, וגזירות, או פרסם, פרוס, וגלגל חזור מדיניות |

כמה כלים לא צריכים הרשאה כי הם לא קוראים נתוני ארגון: בניית קישורי הפעלה ואירוע, וחיפוש בתיעוד זה.

כלי AI לא יכול לגעת בעולם בקשות API, משתמשים, הגדרות, או ניהול ארגון, והוא לא יכול לשלוח אירועים.

## אישור שינויים

כתיבות שואלות אותך תחילה אם הלקוח שלך יכול להציג את הנוסחה. אתה רואה מה ישתנה ובחר **Approve this change** כדי להמשיך. אם אתה דוחה או לא עונה תוך כ-4 דקות, שום דבר לא משתנה. חלק מהלקוחות מפסיקים להמתין לאחר דקה, אז השב במהירות.

<Warning>
  לקוח שאינו תומך בנוסחאות לא נשאל, וכתיבה פועלת ברגע שהלקוח מבצע את הקריאה. שם, האישור שלך בלקוח הוא היחיד, אז שמור עליו מופעל לכלי כתיבה.
</Warning>

## אפליקציות מחוברות וביטול

**Settings → Integrations → MCP** רשום את האפליקציות המחוברות שלך בארגון הנוכחי, עם ההרשאות שלהן והשימוש האחרון. **Revoke** מנתק אפליקציה מיד. הסרת השרת בלקוח שלך גם מביטלת את החיבור.

אתה יכול להיות עם עד 5 אפליקציות מחוברות לכל ארגון. חיבור של אותה אפליקציה שוב מחליף את החיבור הקודם שלה.

## פריסות בעצמי

בחר **Self-hosted Failproof AI Cloud** בעת ההתחברות, והזן את הכתובת שבה אתה מתחבר. הפריסה שלך חייבת להיות נגישה על פני HTTPS ציבורי.

קריאות כלים והתוצאות שלהם עוברות דרך שער Failproof AI המוזמן בדרכן בין כלי AI שלך לפריסה שלך. השער לא שומר אותן.

## מה קורה לנתונים שלך

התוצאות הולכות לכלי AI שחיברת, וספק הכלי של הכלי מטפל בהם תחת התנאים שלו. עבור כל קריאת כלי, Failproof AI עוקב אחר שם הכלי, התוצאה שלו, כמה זמן זה לקח, והארגון, לעולם לא הטיעונים או התוצאות. ראה את [מדיניות הפרטיות](https://befailproof.ai/privacy/).

## פתרון בעיות

| מה אתה רואה | מה לעשות |
| --- | --- |
| "Started in another browser" | סיים את ההתחברות בדפדפן שהלקוח פתח, עם קוקיז מורשה, והתחל שוב מהלקוח |
| שגיאה לאחר **Allow** | הקישור עובד פעם אחת ופג תוקף אחרי 10 דקות, אז התחל שוב מהלקוח |
| כלי שציפית לו חסר | אין לך את ההרשאה שלו בארגון זה. שאל מנהל. אתה לא צריך להתחבר מחדש ברגע שיש לך את זה |
| הלקוח ממשיך לבקש ממך להתחבר | החיבור בוטל, עזבת את הארגון, או הוא לא בשימוש 90 ימים. התחבר שוב |
| "You have 5 connected apps" | בטל אחת תחת **Settings → Integrations → MCP**, ואחריה התחבר שוב |
