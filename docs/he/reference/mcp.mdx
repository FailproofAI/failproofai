חבר כלי AI ל-Failproof AI Cloud והתחל לעבוד עם נתוני הסוכנים שלך מתוכו. הכלי שלך יכול לשאול שאלות על סשנים ואירועים, להריץ SQL לקריאה בלבד, לקרוא לוחות מחוונים, התראות, בעיות, ביקורות ומדיניות, וגם לבצע שינויים כמו יצירת התראה או פריסת מדיניות, אם יש לך את ההרשאה.

כל קריאה תרוץ עם **ההרשאות שלך**, בארגון **אחד** שתבחר בעת החיבור.

יש כתובת אחת לכולם, מתחזוקה או בהגדרה עצמית:

```text
https://gateway.befailproof.ai/mcp
```

## חיבור לקוח

הוסף את הכתובת ללקוח שלך. בפעם הראשונה שכלי משמש, הדפדפן שלך נפתח. בחר איפה ה-Failproof AI Cloud שלך נמצא, היכנס, בחר ארגון אחד, ובחר **Allow**. **Cancel** לא יחבר כלום.

הדף קורא לשם האפליקציה ולאן היא חוזרת. אפליקציה שאינה מזוהה בכתובת האינטרנט שלה סומנה **unverified app**, אז המשך רק אם הנחת את זה זה עתה מלקוח שלך.

<Tabs>
  <Tab title="Claude">
    ב-claude.ai או Claude Desktop, עבור ל-**Settings → Connectors → Add custom connector**. קרא לזה `Failproof AI`, הכנס את הכתובת, בחר **Add**, ואז **Connect**.

    בתוכניות Team ו-Enterprise, בעליון מוסיף את המחבר לארגון תחילה. כל אדם אחר יחבר את חשבונו שלו.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    אז הרץ `/mcp` ב-Claude Code, בחר `failproofai`, ובחר **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    הוסף זאת ל-`~/.cursor/mcp.json`, או ל-`.cursor/mcp.json` של הפרויקט שלך:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor מציג **Needs login** ליד השרת. בחר אותו כדי להיכנס.
  </Tab>
  <Tab title="Codex">
    הוסף זאת ל-`~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    אז הרץ `codex mcp login failproofai`.
  </Tab>
  <Tab title="לקוחות אחרים">
    כל לקוח התומך בשרתי MCP מרוחקים דרך Streamable HTTP עם OAuth עובד. תן לו את הכתובת למעלה. אין מזהה לקוח או סוד להגדרה.
  </Tab>
</Tabs>

## ארגון אחד לכל חיבור

חיבור פועל רק בארגון שבחרת. כדי להשתמש בשני ארגונים, הוסף את השרת פעמיים תחת שמות שונים, כגון `failproofai-acme` ו-`failproofai-sandbox`, וחבר כל אחד לארגון שלו.

ארגונים ניסיוניים אינם מקבלים חיבורים. בחר בארגון שלך במקום זאת.

## הרשאות

חיבור יכול לעשות מה שאתה יכול לעשות בארגון, בתוך הסדר למטה. זה עוקב אחר ההרשאות הנוכחיות שלך: אם מנהל מעניק לך עוד, הכלי מקבל אותה, ואם הם לוקחים משהו משם, הכלי מאבד אותה בקריאה הבאה שלה.

| Permission | Lets the tool |
| --- | --- |
| `events:read` | רשום אירועים, קרא סקירה כללית של סשן, רשום סוכנים וסביבות |
| `evaluations:read` | רשום סשנים, קרא וסכם תוצאות הערכה ועבודות |
| `evaluations:trigger` | צור הערכות, פרסם גרסאות חדשות, הפעל וכבה אותן, מלא וחזור על הערכה של סשן |
| `dashboards:read`, `dashboards:write` | קרא לוחות מחוונים, או צור, שנה שם והוסף שאילתות אליהם |
| `queries:read`, `queries:write` | קרא שאילתות שמורות, או שמור וערוך אותן |
| `queries:run` | הרץ שאילתת SQL קריאה בלבד אחת וקרא את סכימת השאילתה |
| `alerts:read`, `alerts:write` | קרא התראות, או צור, ערוך, השהה, מחק ובדוק אותן |
| `issues:read` | קרא בעיות, הודא אותן וכתוב הערות עליהן |
| `issues:create` | פתח בעיה בהתראה |
| `issues:close` | פתור וסגור בעיות |
| `audits:read`, `audits:write` | קרא ביקורות, הרצות ממצאים, או צור וערוך ביקורות והתחל הרצה |
| `code_fixes:read` | ראה כיצד לתקן בעיה, וקבל את ההקשר שלה עבור הסוכן שלך לתיקון |
| `code_fixes:write` | התחל תיקון ב-Failproof AI Cloud, שפותח בקשת pull ב-GitHub שלך |
| `policies:read`, `policies:write` | קרא מדיניות, מכונות וכריסויות, או פרסם, פרוס ותגלול חזור למדיניות |

כמה כלים אינם זקוקים להרשאה מכיוון שהם קוראים נתוני ארגון ללא אחסון: בנייה של קישורי סשן ואירוע, וחיפוש תיעוד זה.

כלי AI אינו יכול לגעת בשום מקרה במפתחות API, משתמשים, הגדרות או ניהול ארגון, וגם אינו יכול לשלוח אירועים.

## אישור שינויים

כתיבות שואלות אותך תחילה אם הלקוח שלך יכול להציג את ההנחיה. אתה רואה מה ישתנה ובוחר **Approve this change** כדי להמשיך. אם אתה דוחה או לא עונה תוך כחצי 4 דקות, שום דבר לא משתנה. חלק מהלקוחות חדלו לחכות לאחר דקה, אז תענה במהירות.

<Warning>
  לקוח שאינו תומך בהנחיות אינו שואל, וכתיבה תרוץ ברגע שהלקוח מבצע את הקריאה. שם, ההצהרה שלך של הלקוח היא היחידה, אז שמור אותה על כלים לכתיבה.
</Warning>

## אפליקציות מחוברות וביטול אישור

**Settings → Integrations → MCP** מפרטת את האפליקציות המחוברות שלך בארגון הנוכחי, עם ההרשאות שלהן והשימוש האחרון. **Revoke** חוזה אפליקציה מיד. הסרת השרת בלקוח שלך גם מבטלת את החיבור.

אתה יכול להיות עם עד 5 אפליקציות מחוברות לכל ארגון. חיבור של אותה אפליקציה שוב מחליף את החיבור הקודם שלה.

## פריסות בהגדרה עצמית

בחר **Self-hosted Failproof AI Cloud** בעת החיבור, והכנס את הכתובת שבה אתה נכנס. הפריסה שלך חייבת להיות זמינה דרך HTTPS ציבורי.

קריאות כלים והתוצאות שלהם עוברות דרך שער Failproof AI המתוחזק בדרכן בין כלי ה-AI שלך לבין הפריסה שלך. השער לא מאחסן אותן.

## מה קורה לנתונים שלך

התוצאות הולכות לכלי ה-AI שחיברת, וספק הכלי הזה מטפל בהם על פי התנאים שלו. לכל קריאת כלי, Failproof AI רושם את שם הכלי, את התוצאה שלו, כמה זמן זה לקח, ואת הארגון, לעולם לא את הטיעונים או התוצאות. ראה את [privacy policy](https://befailproof.ai/privacy/).

## פתרון בעיות

| What you see | What to do |
| --- | --- |
| "Started in another browser" | סיים הכניסה בדפדפן שהלקוח פתח, עם עוגיות מופעלות, והתחל שוב מהלקוח |
| שגיאה לאחר **Allow** | הקישור עובד פעם אחת ופקע לאחר 10 דקות, אז התחל שוב מהלקוח |
| כלי שקיווית אליו חסר | אין לך את ההרשאה שלו בארגון זה. שאל מנהל. אתה לא צריך להתחבר שוב ברגע שיש לך אותה |
| הלקוח ממשיך לבקש ממך להיכנס | החיבור בוטל, עזבת את הארגון, או הוא לא שימש למשך 90 ימים. חבר שוב |
