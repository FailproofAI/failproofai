חבר כלי AI ל-Failproof AI Cloud והשתמש בנתונים של הסוכנים שלך מתוכו. הכלי שלך יכול לשאול קוויות ולקבל אירועים, להפעיל SQL לקריאה בלבד, לקרוא לוחות מחוונים, התראות, תובנות, ביקורות ומדיניויות, וגם, אם יש לך את ההרשאה, לבצע שינויים כמו יצירת התראה או פריסת מדיניות.

כל קריאה פועלת עם **ההרשאות שלך**, בארגון **אחד** שתבחר בעת ההתחברות.

יש כתובת אחת לכולם, מתורחקת או שמורה בעצמך:

```text
https://gateway.befailproof.ai/mcp
```

## חיבור לקוח

הוסף את הכתובת ללקוח שלך. בפעם הראשונה שבה משתמשים בכלי, הדפדפן שלך נפתח. בחר היכן Failproof AI Cloud שלך נמצא, היכנס לחשבון, בחר ארגון אחד, ובחר **Allow**. **Cancel** לא מחבר כלום.

הדף שומר על שם האפליקציה וההתאמה אליה היא חוזרת. אפליקציה שלא מזוהה על ידי כתובת האינטרנט שלה סימנה **unverified app**, כך שתמשוך קדימה רק אם הרגע התחלת את זה מלקוח שלך.

<Tabs>
  <Tab title="Claude">
    ב-claude.ai או Claude Desktop, עבור ל-**Settings → Connectors → Add custom connector**. תן לו את השם `Failproof AI`, הזן את הכתובת, בחר **Add**, ואחריו **Connect**.

    בתוכניות Team ו-Enterprise, בעלים מוסיף את המחבר לארגון תחילה. לאחר מכן כל אדם מחבר את החשבון שלהם.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    לאחר מכן הרץ `/mcp` בתוך Claude Code, בחר `failproofai`, ובחר **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    הוסף זאת ל-`~/.cursor/mcp.json`, או ל-`.cursor/mcp.json` של הפרויקט שלך:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor מציג **Needs login** ליד השרת. בחר אותו כדי להיכנס לחשבון.
  </Tab>
  <Tab title="Codex">
    הוסף זאת ל-`~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    לאחר מכן הרץ `codex mcp login failproofai`.
  </Tab>
  <Tab title="לקוחות אחרים">
    כל לקוח התומך בשרתי MCP מרוחקים על HTTP משדר עם OAuth עובד. תן לו את הכתובת לעיל. אין ID או סוד של לקוח להגדרה.
  </Tab>
</Tabs>

## ארגון אחד לכל חיבור

חיבור פועל רק בארגון שבחרת. כדי להשתמש בשני ארגונים, הוסף את השרת פעמיים תחת שמות שונים, כגון `failproofai-acme` ו-`failproofai-sandbox`, וחבר כל אחד לארגון שלו.

ארגוני ההדגמה לא מקבלים חיבורים. בחר את הארגון שלך במקום זאת.

## הרשאות

חיבור יכול לעשות מה שאתה יכול לעשות בארגון, בתוך הסט להלן. זה עוקב אחר ההרשאות הנוכחיות שלך: אם מנהל נותן לך עוד, הכלי מקבל את זה, ואם הם לוקחים משהו הרחק, הכלי מאבד את זה בקריאה הבאה.

| הרשאה | מאפשרת לכלי |
| --- | --- |
| `events:read` | רשימת אירועים, קריאת סקירה של קוויה, רשימת סוכנים וסביבות |
| `evaluations:read` | רשימת קוויות, קריאה וסיכום תוצאות והעבודות של הערכה |
| `evaluations:trigger` | יצירת הערכות, פרסום גרסאות חדשות, הפעלה וכיבוי שלהן, מילוי לאחור, והערכה מחדש של קוויה |
| `dashboards:read`, `dashboards:write` | קריאת לוחות מחוונים, או יצירה, שינוי שם, והוספת שאילתות אליהם |
| `queries:read`, `queries:write` | קריאת שאילתות שמורות, או שמירה וערוך שלהן |
| `queries:run` | הרצת שאילתה SQL לקריאה בלבד אחת וקריאת סכמת השאילתה |
| `alerts:read`, `alerts:write` | קריאת התראות, או יצירה, עריכה, השהיית, מחיקה, ובדיקה שלהן |
| `issues:read` | קריאת תובנות, הכרה בהן, והערה עליהן |
| `issues:create` | פתיחת תובנה על התראה |
| `issues:close` | פתרון וסגירה של תובנות |
| `audits:read`, `audits:write` | קריאת ביקורות, הרצות וממצאים, או יצירה וערוך של ביקורות והתחלת הרצה |
| `code_fixes:read` | ראה כיצד לתקן תובנה, וקבל את ההקשר שלה כדי שהסוכן שלך שלו לתקן |
| `code_fixes:write` | התחל תיקון ב-Failproof AI Cloud, אשר פותח בקשת pull ב-GitHub שלך |
| `policies:read`, `policies:write` | קריאת מדיניויות, מכונות ופריסות, או פרסום, פריסה וחזרה של מדיניויות |

כמה כלים לא צריכים הרשאה כי הם לא קוראים נתונים של ארגון: בניית קישורי קוויה ואירוע, וחיפוש בתיעוד זה.

כלי AI לעולם לא יכול לגעת במפתחות API, משתמשים, הגדרות, או ניהול ארגון, וזה לא יכול לשלוח אירועים.

## אישור שינויים

כתיבות שואלות אותך קודם אם הלקוח שלך יכול להציג את ההנמקה. אתה רואה מה ישתנה ובוחר **Approve this change** כדי להמשיך. אם אתה דוחה או לא עונה תוך כ-4 דקות, כלום לא משתנה. חלק מהלקוחות מפסיקים להמתין אחרי דקה, אז ענה במהירות.

<Warning>
  לקוח שלא תומך בהנמקות לא נשאל, וכתיבה מתבצעת מייד כאשר הלקוח מבצע את הקריאה. שם, האישור של הלקוח שלך הוא היחיד, אז שמרו אותו למטרות כלי כתיבה.
</Warning>

## אפליקציות מחוברות וביטול

**settings → integrations → MCP** מפרטת את האפליקציות המחוברות שלך בארגון הנוכחי, עם ההרשאות שלהן והשימוש האחרון. **Revoke** חותך אפליקציה מייד. הסרת השרת בלקוח שלך גם משחררת את החיבור.

אתה יכול להיות עם עד 5 אפליקציות מחוברות לכל ארגון. חיבור של אותה אפליקציה שוב מחליף את החיבור המוקדם שלה.

## פריסות שמורות בעצמן

בחר **Self-hosted Failproof AI Cloud** בעת ההתחברות, והזן את הכתובת שאתה כניסה בה. הפריסה שלך חייבת להיות נגישה על פני HTTPS ציבוריים.

קריאות כלים ותוצאותיהן עוברות דרך שער Failproof AI המתורחק בדרכן בין הכלי AI שלך לבין הפריסה שלך. השער לא שומר עליהם.

## מה קורה לנתונים שלך

התוצאות עוברות לכלי ה-AI שחיברת, וספק הכלי הזה מטפל בהן בתנאים שלו. לכל קריאה כלי, Failproof AI רושמת את שם הכלי, את התוצאה שלו, כמה זמן זה לקח, והארגון, אף פעם לא את הטיעונים או התוצאות. ראה את [מדיניות הפרטיות](https://befailproof.ai/privacy/).
