חבר כלי AI ל-Failproof AI Cloud והתחל לעבוד עם נתוני הסוכנים שלך מתוכו. הכלי שלך יכול לשאול על session וevents, להריץ SQL קריאה-בלבד, לקרוא דוחות בקרה, התראות, issues, audits ומדיניויות, וכן, אם יש לך את ההרשאה, לבצע שינויים כגון יצירת התראה או הפצת מדיניות.

כל קריאה פועלת עם **ההרשאות שלך**, בארגון **אחד** שאתה בוחר בעת ההתחברות.

יש כתובת אחת לכולם, מתארחת או self-hosted:

```text
https://gateway.befailproof.ai/mcp
```

## חבר קליינט

הוסף את הכתובת לקליינט שלך. בפעם הראשונה בה משתמשים בכלי, הדפדפן שלך נפתח. בחר איפה ה-Failproof AI Cloud שלך נמצא, התחבר, בחר ארגון אחד, ובחר **Allow**. **Cancel** לא מחבר כלום.

הדף מציין את שם האפליקציה ולאן היא חוזרת. אפליקציה שאינה מזוהה על ידי כתובת ווב שלה מסומנת **unverified app**, אז המשך רק אם זה עתה התחלת זאת מהקליינט שלך.

<Tabs>
  <Tab title="Claude">
    ב-claude.ai או Claude Desktop, עבור ל-**Settings → Connectors → Add custom connector**. תן לו את השם `Failproof AI`, הזן את הכתובת, בחר **Add**, ואז **Connect**.

    בתוכניות Team ו-Enterprise, בעלים מוסיף את ה-connector עבור הארגון תחילה. כל אדם אחר כך מחבר את החשבון שלו.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    לאחר מכן הרץ `/mcp` בתוך Claude Code, בחר `failproofai`, ובחר **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    הוסף זאת ל-`~/.cursor/mcp.json`, או ל-`.cursor/mcp.json` של הפרוייקט שלך:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor מציג **Needs login** ליד השרת. בחר בו כדי להתחבר.
  </Tab>
  <Tab title="Codex">
    הוסף זאת ל-`~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    לאחר מכן הרץ `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    כל קליינט התומך בשרתי MCP מרוחקים דרך Streamable HTTP עם OAuth עובד. תן לו את הכתובת לעיל. אין client ID או secret לתצורה.
  </Tab>
</Tabs>

## ארגון אחד לכל חיבור

חיבור פועל רק בארגון שבחרת. כדי להשתמש בשני ארגונים, הוסף את השרת פעמיים תחת שמות שונים, כגון `failproofai-acme` ו-`failproofai-sandbox`, וחבר כל אחד לארגון שלו.

ארגוני Demo אינם מקבלים חיבורים. בחר את הארגון שלך במקום זאת.

## הרשאות

חיבור יכול לעשות את מה שאתה יכול לעשות בארגון, בתוך הקבוצה להלן. הוא פועל לפי ההרשאות הנוכחיות שלך: אם מנהל נותן לך יותר, הכלי מקבל זאת, ואם הם לוקחים משהו, הכלי מאבד אותו בקריאה הבאה.

| הרשאה | מאפשרת לכלי |
| --- | --- |
| `events:read` | רשימת events, קריאת סקירת session, רשימת סוכנים וסביבות |
| `evaluations:read` | רשימת sessions, וקריאה וסיכום תוצאות והעבודות של הערכות |
| `evaluations:trigger` | יצירת הערכות, פרסום גרסאות חדשות, הדלקה וכיבוי שלהן, backfill, וחישוב מחדש של session |
| `dashboards:read`, `dashboards:write` | קריאת דוחות בקרה, או יצירה, שינוי שם והוספת שאילתות אליהם |
| `queries:read`, `queries:write` | קריאת שאילתות שמורות, או שמירה ועריכה שלהן |
| `queries:run` | הרץ שאילתת SQL קריאה-בלבד אחת וקרא את schema של השאילתה |
| `alerts:read`, `alerts:write` | קריאת התראות, או יצירה, עריכה, השהיה, מחיקה וניסיון שלהן |
| `issues:read` | קריאת issues, הכרה בהם, והוספת תגובות |
| `issues:create` | פתח issue על התראה |
| `issues:close` | פתור וסגור issues |
| `audits:read`, `audits:write` | קריאת audits, runs, וממצאים, או יצירה ועריכה של audits והתחלת run |
| `code_fixes:read` | ראה כיצד לתקן issue, ותקבל את ההקשר שלו עבור הסוכן שלך כדי לתקן |
| `code_fixes:write` | התחל תיקייה ב-Failproof AI Cloud, המוציאה pull request ל-GitHub שלך |
| `policies:read`, `policies:write` | קריאת מדיניויות, מכונות והפצות, או פרסום, הפצה וחזרה למדיניויות |

כמה כלים לא זקוקים להרשאה מכיוון שהם לא קוראים נתוני ארגון: בניית קישורי session ו-event, וחיפוש בתיעוד זה.

כלי AI לעולם לא יכול לגעת ב-API keys, משתמשים, הגדרות, או ניהול ארגוני, והוא לא יכול לשלוח events.

## אישור שינויים

כתיבות שואלות אותך תחילה אם הקליינט שלך יכול להציג את ההנחיה. אתה רואה מה יתשנה ובוחר **Approve this change** כדי להמשיך. אם אתה דוחה או לא משיב תוך כ-4 דקות, כלום לא משתנה. חלק מהקליינטים מפסיקים להמתין אחרי דקה, אז השב במהירות.

<Warning>
  קליינט שלא תומך בהנחיות לא נשאל, וכתיבה תרוץ ברגע שהקליינט מבצע את הקריאה. שם, ההשהייה שלך בקליינט היא היחידה, אז שמור אותה דולקת לכלים של כתיבה.
</Warning>

## אפליקציות מחוברות וביטול

**Settings → Integrations → MCP** מציינת את האפליקציות המחוברות שלך בארגון הנוכחי, עם ההרשאות שלהן והשימוש האחרון. **Revoke** חותך אפליקציה מיד. הסרת השרת בקליינט שלך גם מבטלת את החיבור.

אתה יכול להיות בעל עד 5 אפליקציות מחוברות לכל ארגון. חיבור של אותה אפליקציה שוב מחליף את החיבור הקודם שלה.

## פריסות self-hosted

בחר **Self-hosted Failproof AI Cloud** בעת ההתחברות, והזן את הכתובת שאליה אתה מתחבר. ההפצה שלך חייבת להיות נגישה דרך HTTPS ציבורית.

קריאות כלים והתוצאות שלהם עוברות דרך שער Failproof AI המתארח בדרך בין כלי ה-AI שלך לפריסה שלך. השער לא אוחסן אותם.

## מה קורה לנתונים שלך

התוצאות הולכות לכלי ה-AI שחיברת, וספק הכלי של אותו כלי מטפל בהם על ​​פי התנאים שלו. עבור כל קריאת כלי, Failproof AI רושם את שם הכלי, את התוצאה שלו, כמה זמן זה לקח, והארגון, לעולם לא את הטיעונים או התוצאות. ראה את [מדיניות הפרטיות](https://befailproof.ai/privacy/).

## פתרון בעיות

| מה אתה רואה | מה לעשות |
| --- | --- |
| "Started in another browser" | סיים את ההתחברות בדפדפן שהקליינט פתח, כשעוגיות מופעלות, והתחל מחדש מהקליינט |
| שגיאה לאחר **Allow** | הקישור פועל פעם אחת ותוקפו פג לאחר 10 דקות, אז התחל מחדש מהקליינט |
| כלי שהצפית הוא חסר | אין לך את ההרשאה שלו בארגון זה. שאל מנהל. אתה לא צריך להתחבר מחדש ברגע שיש לך אותו |
| הקליינט ממשיך לבקש ממך להתחבר | החיבור בוטל, עזבת את הארגון, או הוא לא שימש למשך 90 ימים. התחבר מחדש |
| "You have 5 connected apps" | בטל אחד תחת **Settings → Integrations → MCP**, ואז התחבר מחדש |
