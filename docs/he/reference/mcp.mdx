חבר כלי AI ל-Failproof AI Cloud והתחל לעבוד עם הנתונים של החכמים שלך מתוכו. הכלי שלך יכול לשאול על הפעלות ויוצאים, להריץ SQL לקריאה בלבד, לקרוא לוחות בקרה, התראות, תובנות, ביקורות ומדיניות, וגם אם יש לך את ההרשאה, לבצע שינויים כגון יצירת התראה או פרוסום מדיניות.

כל קריאה רצה עם **ההרשאות שלך**, ב**ארגון אחד** שתבחר בעת ההתחברות.

יש כתובת אחת לכולם, מתורחלת או בעלת מנהל עצמי:

```text
https://gateway.befailproof.ai/mcp
```

## חיבור לקוח

הוסף את הכתובת ללקוח שלך. בפעם הראשונה שכלי משמש, הדפדפן שלך נפתח. בחר היכן Failproof AI Cloud שלך נמצא, היכנס לחשבון, בחר ארגון אחד, ובחר **Allow**. **Cancel** לא מחבר כלום.

הדף מציין את שם האפליקציה ולאן היא חוזרת. אפליקציה שלא מזוהה על ידי כתובת האינטרנט שלה משודרגת **unverified app**, אז המשך רק אם הרגע התחלת את זה מהלקוח שלך.

<Tabs>
  <Tab title="Claude">
    ב-claude.ai או Claude Desktop, עבור ל-**Settings → Connectors → Add custom connector**. תן לו את השם `Failproof AI`, הזן את הכתובת, בחר **Add**, ואז **Connect**.

    בתוכניות Team ו-Enterprise, בעל מוסיף את המחבר לארגון תחילה. לאחר מכן, כל אדם מחבר את החשבון שלו.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    לאחר מכן הרץ `/mcp` בתוך Claude Code, בחר `failproofai`, וגם בחר **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    הוסף זאת ל-`~/.cursor/mcp.json`, או לקובץ `.cursor/mcp.json` של הפרויקט שלך:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor מציג **Needs login** לצד השרת. בחר אותו כדי להיכנס.
  </Tab>
  <Tab title="Codex">
    הוסף זאת ל-`~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    לאחר מכן הרץ `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    כל לקוח התומך בשרתי MCP מרוחקים על Streamable HTTP עם OAuth עובד. תן לו את הכתובת למעלה. אין מזהה לקוח או סודי להגדיר.
  </Tab>
</Tabs>

## ארגון אחד לכל חיבור

חיבור פועל רק בארגון שבחרת. כדי להשתמש בשני ארגונים, הוסף את השרת פעמיים תחת שמות שונים, כגון `failproofai-acme` ו-`failproofai-sandbox`, וחבר כל אחד לארגון שלו.

ארגוני ההדגמה לא מקבלים חיבורים. בחר את הארגון שלך במקום זאת.

## הרשאות

חיבור יכול לעשות מה שאתה יכול לעשות בארגון, בתוך הערכה להלן. זה עוקב אחר ההרשאות הנוכחיות שלך: אם מנהל נותן לך עוד, הכלי מקבל את זה, ואם הם לוקחים משהו הרחק, הכלי מאבד את זה בקריאה הבאה.

| הרשאה | מאפשרת לכלי |
| --- | --- |
| `events:read` | רשימת אירועים, קריאת סקירה כללית של הפעלה, רשימת חכמים וסביבות |
| `evaluations:read` | רשימת הפעלות, קריאה וסיכום תוצאות ועבודות הערכה |
| `evaluations:trigger` | יצירת הערכות, פרסום גרסאות חדשות, הפעלה וכיבוי שלהן, מילוי לאחור, והערכה מחדש של הפעלה |
| `dashboards:read`, `dashboards:write` | קריאת לוחות בקרה, או יצירה, שינוי שם, והוספת שאילתות אליהם |
| `queries:read`, `queries:write` | קריאת שאילתות שמורות, או שמירה וערכתן |
| `queries:run` | הרץ שאילתת SQL אחת לקריאה בלבד וקרא את סכימת השאילתה |
| `alerts:read`, `alerts:write` | קריאת התראות, או יצירה, עריכה, השהיה, מחיקה ובדיקתן |
| `issues:read` | קריאת תובנות, הכרה בהן, והערה על הן |
| `issues:create` | פתיחת תובנה על התראה |
| `issues:close` | פתרון וסגירת תובנות |
| `audits:read`, `audits:write` | קריאת ביקורות, הפעלות וממצאים, או יצירה וערכתן של ביקורות ותחילת ריצה |
| `code_fixes:read` | ראה כיצד לתקן תובנה, וקבל את ההקשר שלה עבור החכם שלך לתיקון |
| `code_fixes:write` | התחל תיקון ב-Failproof AI Cloud, שפותח בקשת pull ב-GitHub שלך |
| `policies:read`, `policies:write` | קריאת מדיניות, מכונות ופרוסומים, או פרסום, פרוסום והחזרת מדיניות |

כמה כלים לא צריכים הרשאה מכיוון שהם לא קוראים נתוני ארגון: בנייה של קישורי הפעלה ואירוע, וחיפוש תיעוד זה.

כלי AI לא יכול אפילו לגעת במפתחות API, משתמשים, הגדרות, או ניהול ארגונים, וגם לא יכול לשלוח אירועים.

## אישור שינויים

כתבות שואלות אותך תחילה אם הלקוח שלך יכול להציג את ההנחיה. אתה רואה מה ישתנה ובוחר **Approve this change** כדי להמשיך. אם אתה דוחה או לא עונה תוך כ-4 דקות, כלום לא משתנה. חלק מהלקוחות מפסיקים להמתין אחרי דקה, אז ענה במהירות.

<Warning>
  לקוח שאינו תומך בהנחיות לא נשאל, וכתיבה רצה ברגע שהלקוח מבצע את הקריאה. שם, הרשות של הלקוח הוא היחידה, אז תשמור על זה בחזקה עבור כלים כתיבה.
</Warning>

## אפליקציות מחוברות וביטול

**settings → integrations → MCP** מפרטת את האפליקציות המחוברות שלך בארגון הנוכחי, עם ההרשאות שלהן והשימוש האחרון. **Revoke** חותך אפליקציה באופן מיידי. הסרת השרת בלקוח שלך גם מבטלת את החיבור.

אתה יכול להחזיק עד 5 אפליקציות מחוברות לכל ארגון. חיבור של אותה אפליקציה שוב מחליף את החיבור המוקדם שלה.

## פרוסומים בעלי מנהל עצמי

בחר **Self-hosted Failproof AI Cloud** בעת ההתחברות, והזן את הכתובת שלך בה אתה נכנס. הפרוסום שלך חייב להיות זמין על HTTPS ציבורי.

קריאות כלים והתוצאות שלהם עוברים דרך שער Failproof AI המתורחל בדרכם בין כלי ה-AI שלך לפרוסום שלך. השער לא מאחזן אותם.

## מה קורה לנתונים שלך

התוצאות עוברות ללקוח ה-AI שחיברת, וספק הכלי הזה מטפל בהן בהתחייבות של עצמו. עבור כל קריאת כלי, Failproof AI רושמת את שם הכלי, את התוצאה שלו, כמה זמן זה לקח, והארגון, לעולם לא את הטיעונים או התוצאות. ראה את [מדיניות הפרטיות](https://befailproof.ai/privacy/).
