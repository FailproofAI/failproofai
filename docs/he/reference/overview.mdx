## חבר סוכן ואמת נתונים

<Tabs>
  <Tab title="לוח בקרה">
    1. פתח **Administration → Keys**, צור מפתח עם `events:add` ו-`policies:pull`, והעתק את הסוד.
    2. הגדר את האינטגרציה באמצעות העמוד התואם למעלה.
    3. פתח **Observe → Events** כדי לאשר שאירועים מגיעים, ואז **Observe → Sessions** כדי לאשר שהם יוצרים הפעלות שלמות.
    4. סנן לסביבה של האינטגרציה ובדוק session אחד עבור שדות המודל, הכלי, השגיאה והמדיניות הנחוצים לביקורות.

    התחל עם מגירת המפתחות. ההנחות שנבחרו קובעות האם המכונה יכולה לשלוח אירועים ולקבל מדיניות המנוהלת על ידי Cloud.

    ![מגירת המפתח הציבוריים החדשה המשמשת להנחת הרשאות ספיגת אירועים והעברת מדיניות.](/images/dashboard/key-create.png)

    לאחר חיבור האינטגרציה, השתמש ברשימת Sessions כדי לאשר שהאירועים שלה מקובצים לתוך הפעלות שלמות בסביבה הצפויה.

    ![רשימת Sessions המשמשת לאימות שאינטגרציה המחוברת לאחרונה מדווחת על הפעלות סוכן שלמות.](/images/dashboard/sessions-list.png)

    פתח את אחת מההפעלות הללו לפני שתשקול שהאינטגרציה שלמה; העקבה צריכה להכיל את המודל, הכלי, השגיאה והראיות המדיניות שהביקורות שלך זקוקות להן.
  </Tab>
  <Tab title="CLI">
    צור מפתח מכונה, חבר את daemon ה-Failproof, ואמת את ה-session הראשון.

    ```bash
    fp keys create agent-production \
      --add events:add \
      --add policies:pull

    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>

    failproofai flush --wait
    fp sessions --since 1h --env production
    fp events --since 1h --env production --limit 20
    ```

    השתמש ב-`fp --json sessions ...` כשכלי אחר תצרוך את התוצאה. דגלים גלובליים כגון `--json`, `--org`, ו-`--base-url` חייבים לבוא לפני הפקודה.

    ראה את [הפניית Failproof AI CLI](/he/reference/failproof-cli) עבור פקודות מקומיות ו-[הפניית Failproof Cloud CLI](/he/reference/cloud-cli#cli-commands) עבור פקודות `fp`.
  </Tab>
</Tabs>
