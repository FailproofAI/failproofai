## חבר agent וודא נתונים

<Tabs>
  <Tab title="Dashboard">
    1. פתח **Administration → Keys**, צור key עם `events:add` ו-`policies:pull`, והעתק את הסוד.
    2. הגדר את האינטגרציה באמצעות הדף התואם למעלה.
    3. פתח **Observe → Events** כדי לאשר שהאירועים הגיעו, ואז **Observe → Sessions** כדי לאשר שהם יוצרים runs שלמות.
    4. סנן לסביבה של האינטגרציה ובידוק session אחד עבור שדות המודל, כלי, שגיאה ו-policy הדרושים לאודיטים.

    התחל עם מגירת הרכוש. ההענקות שנבחרו קובעות אם המכונה יכולה לשלוח אירועים וקבל policies המנוהלים על ידי Cloud.

    ![מגירת ה-API key החדשה המשמשת להענקת הרשאות של event ingestion ו-policy delivery.](/images/dashboard/key-create.png)

    לאחר חיבור האינטגרציה, השתמש בשימוש ב-Sessions list כדי לאשר שהאירועים שלה מקובצים לתוך runs שלמות בסביבה הצפויה.

    ![רשימת Sessions המשמשת לאימות שאינטגרציה שזה עתה התחברה מדווחת agent runs שלמות.](/images/dashboard/sessions-list.png)

    פתח את אחת מהסעיפים הללו לפני שתשקול את האינטגרציה כשלמה; ה-trace צריך להכיל את הראיות של מודל, כלי, שגיאה ו-policy שאודיטים שלך צריכים.
  </Tab>
  <Tab title="CLI">
    צור machine key, חבר את ה-Failproof daemon, ואמת את ה-session הראשון.

    ```bash
    fp keys create agent-production \
      --add events:add \
      --add policies:pull

    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>

    failproofai flush --wait
    fp sessions --since 1h --env production
    fp events --since 1h --env production --limit 20
    ```

    השתמש ב-`fp --json sessions ...` כאשר כלי אחר יצרוך את התוצאה. דגלים גלובליים כגון `--json`, `--org` ו-`--base-url` חייבים להגיע לפני הפקודה.

    ראה [ההפניה Failproof AI CLI](/he/reference/failproof-cli) לפקודות מקומיות ו-[ההפניה Failproof Cloud CLI](/he/reference/cloud-cli#cli-commands) לפקודות `fp`.
  </Tab>
</Tabs>
