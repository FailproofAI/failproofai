בחר את השילוב הקרוב ביותר למקום שבו הסוכן שלך כבר פועל.

קטע זה מכסה שני כלי שורת פקודה עם משימות שונות. `failproofai` פועל על המכונה שעליה פועל הסוכן שלך ואוכף מדיניות בתוך לולאת הסוכן; `fp` משוחח עם Failproof AI Cloud וקורא בחזרה מה שלולאה זו עשתה. הגדרת מכונה נתמכת רק ב-Linux וב-macOS — `failproofai config` מסרב בכל דבר אחר ולא כותב שום דבר, במקום להשאיר מכונה חצי-מוגדרת מאחור.

עמודי HTTP API שנוצרו מכסים את משטח `/v1` הציבורי. עמודים שנכתבו ביד מסבירים זרימות עבודה המשתרעות על מספר נקודות קצה או משתמשים בממשקי אדמיניסטרציה מחוץ למשטח הציבורי הזה.

## חבר סוכן ואימות נתונים

<Tabs>
  <Tab title="לוח בקרה">
    1. פתח **Administration → Keys**, צור מפתח עם `events:add` ו-`policies:pull`, והעתק את הסוד.
    2. הגדר את השילוב באמצעות הדף המתאים למעלה.
    3. פתח **Observe → Events** כדי לאשר שאירועים מגיעים, ואז **Observe → Sessions** כדי לאשר שהם יוצרים הרצות שלמות.
    4. סנן לסביבת השילוב ובדוק מושב אחד עבור שדות הדוגמן, הכלי, השגיאה והמדיניות הנחוצים להדקות.

    התחל במגירת המפתחות. ההקצאות שנבחרו קובעות אם המכונה יכולה לשלוח אירועים ולקבל מדיניות מנוהלת Cloud.

    ![מגירת המפתח API החדשה המשמשת להעניית הרשאות לספיגת אירועים והעברת מדיניות.](/images/dashboard/key-create.png)

    לאחר חיבור השילוב, השתמש ברשימת המושבים כדי לאשר שהאירועים שלו מקובצים להרצות שלמות בסביבה הצפויה.

    ![רשימת המושבים המשמשת לאימות שהשילוב החדש המחובר דיווח על הרצות סוכנים שלמות.](/images/dashboard/sessions-list.png)

    פתח את אחד מהמושבים הללו לפני שתשקול את השילוב הושלם; הטrace צריך להכיל את הדוגמן, הכלי, השגיאה, וראיות המדיניות שההדקות שלך זקוקות להן.
  </Tab>
  <Tab title="CLI">
    צור מפתח מכונה, הגדר מכונה זו וחבר אותה, בחר מדיניות, ואז אמת את המושב הראשון.

    ```bash
    fp keys create agent-production \
      --add events:add \
      --add policies:pull

    failproofai config --token <machine-key>

    failproofai policies add FailproofAI/policies

    failproofai flush --wait
    fp sessions --since 1h
    fp events --since 1h --limit 20
    ```

    אף אחת מפקודות האימות אינה מסננת בסביבה, מכיוון שמכונה שזה עתה הוגדרה חותמת כל אירוע `local`. הוסף `--env production` רק לאחר שהגדרת את `collector.environment` — ראה [שנה תווית סביבה](/he/reference/events-and-configuration#change-an-environment-label).

    העברת token היא הבקשה לחיבור, כך ש-`failproofai config --token <machine-key>` עושה את אותו הדבר בפקודה אחת. העדף את משתנה הסביבה: ארגומנט קריא מ-`ps` על ידי כל משתמש בתיבה, וזה נוחת בהיסטוריית הקליפה וביומנים של CI.

    שלב המדיניות אינו אופציונלי. `failproofai config` מתקין את daemon וחוט כל CLI סוכנים נתמך, אך הוא בחירה מכוונת שום מדיניות, כך שמכונה שזה עתה הוגדרה לא אוכפת שום דבר עד שתוסיף חבילה.

    השתמש ב-`fp --json sessions ...` כאשר כלי אחר יצרוך את התוצאה. דגלים גלובליים כמו `--json`, `--org`, ו-`--base-url` חייבים להגיע לפני הפקודה.

    ראה את [הפניית Failproof AI CLI](/he/reference/failproof-cli) לפקודות מקומיות והפניית [Failproof Cloud CLI](/he/reference/cloud-cli#cli-commands) עבור פקודות `fp`.
  </Tab>
</Tabs>
