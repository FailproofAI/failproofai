עוזר הענן של Failproof AI עונה על שאלות לגבי הצי שלך בשפה טבעית. הוא יכול לנתח הפעלות וכשלים, להריץ שאילתות, לבנות לוחות בקרה, לחקור הערכות וקביעות אזעקה, ולעזור ליצור ולהריץ ביקורות ללא צורך לתרגם את המשימה למסכי מוצר או פקודות CLI. בלוח הבקרה הבקרה מתויגת **Open agent chat**; ב-[`fp` CLI](/he/reference/cloud-cli) זו קבוצת הפקודה `fp agent`.

```text
Why did production checkout agents regress this week?
Build a dashboard for tool failures, latency, and evaluation scores.
Create an audit that finds agents retrying the same failed action without changing approach.
Show me the sessions behind the most common audit finding.
```

העוזר עובד עם הנתונים וההרשאות הזמינים בארגון הפעיל. בדוק את ההוכחות והשינויים המוצעים שלו לפני החלת פעולות המשפיעות על משתמשים או סוכנים אחרים.

<Note>
  העוזר פועל בלוח הבקרה והצ'אטים שלו שייכים לאדם, ולכן אין נתיב API מאחוריו שמפתח יכול להשתמש בו. כל תת-פקודת `fp agent` דורשת הפעלה חתומה (`fp login`) והרשאה `agent:use`, ויוצא 2 תחת `--api-key` או `FP_API_KEY`. מפתח API לא יכול להגיע אליו, לכן לעבודה מתוזמנת צריך לשאת אסימון הפעלה חתום ב-`--token` או `FP_TOKEN`. זה עובד — `fp agent ask` קורא את השאלה מ-stdin כאשר אין TTY — אבל אסימון הפעלה פוקע בערך 24 שעות לאחר `fp login`, מה שהופך את העוזר לבחירה גרועה לאוטומציה ללא השגחה למרות שהוא פועל.
</Note>

## שאל את העוזר

<Tabs>
  <Tab title="לוח בקרה">
    1. בחר **Open agent chat** ותאר מה אתה רוצה להבין, ליצור או להפעיל.
    2. בדוק את קריאות הכלים, הטבלאות ותוצאות השאילתה של העוזר בזמן שהוא עובד.
    3. פתח את ההפעלה, האזעקה או השאילתה המצוטטת כדי לאמת את התוצאה מול נתוני המקור.
    4. התחל צ'אט חדש לחקירה שונה, או השתמש בהיסטוריית הצ'אט כדי להמשיך את אותו קו של ניתוח.

    ![עוזר הענן עונה על שאלת צפייה עם ניתוח וביצוע שאילתות תומכים.](/images/dashboard/assistant.png)
  </Tab>
  <Tab title="CLI">
    התחל עם `health`. זה דיווח האם העוזר מופעל לפריסה זו ואם LLM מוגדר עבורו. כאשר אין LLM, `ask` נכשל ו-`models` דיווחים ללא אף אחד — `chats`, `show`, `rename` ו-`delete` לעולם לא בודקים בריאות וממשיכים לעבוד.

    ```bash
    fp agent health
    fp agent models
    fp agent ask "Which production checkout agents had the most tool errors in the last 24 hours?"
    ```

    `fp agent models` מפרט את המודלים שהפריסה הזו מאפשרת ואיזה הוא ברירת המחדל. העבר אחד ל-`ask --model <name>`. הציבור תשובה בטקסט שיש לך כבר עם `--page-context <text>`, וצינור את השאלה ב-stdin במקום להעביר אותה כטיעון כשהיא מגיעה מקובץ או פקודה קודמת:

    ```bash
    cat incident-notes.md | fp agent ask --model <model>
    ```

    כל שאלה נשמרת לצ'אט. ללא `--chat` היא מתחילה חדשה ודפסות את הקיצור שלה; עם `--chat` היא ממשיכה את הכיש הזה.

    ```bash
    fp agent chats
    fp agent show <chat-id>
    fp agent ask "Open representative sessions" --chat <chat-id>
    fp agent rename <chat-id> --title "checkout regression"
    fp agent delete <chat-id> --yes
    ```

    `fp agent chats` מפרט את הצ'אטים שלך החדשים ביותר תחילה כ-`chat-id · title · messages · updated`, כאשר `updated` הוא גיל הפעילות האחרונה של הצ'אט. ה-`chat-id` המוצג הוא הקצר — 8 התווים הראשונים — ו-`show`, `rename`, `delete` ו-`ask --chat` כולם פתרים את הקידומת. קוד שלא תואם שום דבר יוצא 6 עם קופסת `chat not found`; זה שמתאים למספר רב שואל לקידומת ארוכה יותר.

    `fp agent delete` מאשר תחילה. `--yes` מדלג על ההנמקה, וכך גם כל הפעלה ללא אינטראקטיבית: תחת `--json`, או עם stdin מעוד, הוא ממשיך ללא שאלה.
  </Tab>
</Tabs>

## עבודה יעילה עם העוזר

- תן לו מטרה תחילה; הוסף סביבה, זרימת עבודה או טווח זמן כאשר הגבולות הללו חשובים.
- התייחס ל-SQL שנוצר וסיכומים כעזרה לחקירה, לא כראיה סופית.
- פתח הפעלות נציגות לפני יצירת ביקורת, בעיה, אזעקה או מדיניות.
- שמור סינני ארגון, סביבה וזמן מפורשים.
- שמור SQL שימושי כשאילתה כדי שמפעיל אחר יוכל לשחזר את התוצאה.

<Warning>
  שתי שכבות הרשאה חלות, וההן נכשלות בצורה שונה. `agent:use` שער את התכונה עצמה: ללא זה, `fp agent` ו-dashboard chat אינם זמינים. התשובות מוגבלות אחר כך לרשאות הנתונים של המשתמש המחובר — `events:read`, `evaluations:read`, `queries:run`, `policies:read` — כך שמשתמש שיכול לפתוח את העוזר עדיין עלול לקבל תשובה ריקה לנתונים שהוא לא יכול לקרוא. אל תרחיב הרשאות כדי להפוך שאלה לעבודה; בקש ממפעיל מורשה להריץ את החקירה במקום זאת. ראה [Keys and permissions](/he/admin/keys-and-permissions).
</Warning>
