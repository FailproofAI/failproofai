לוחות בקרה משלבים שאילתות שנשמרו לתוך תצוגה תפעולית. בנה אחד סביב החלטה שאתה מצפה שמישהו יקבל—לא סביב כל מדד זמין.

## בנה לוח בקרה

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Analyze → Queries**, צור או פתח שאילתה שנשמרה, ותאשר את התוצאה שלה.
    2. בחר **add to dashboard**, ואז בחר לוח בקרה קיים או צור אחד תחת **Analyze → Dashboards**.
    3. פתח את לוח הבקרה, עבור למצב עריכה, סדר את הטילים, ושמור את הפריסה.
    4. חזור לשאילתה כשאתה צריך לשנות את הנתונים או המסננים מאחורי טיל.

    ![לוח בקרה המורכב משאילתות שנשמרו לנפח אירועים, שגיאות, איחור והשימוש בטוקנים של מודל.](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    CRUD לוח בקרה אינו חשוף ב-Cloud CLI הנוכחי. השתמש ב-CLI לבניה ואימות של השאילתה השמורה, ואז הוסף אותה ללוח בקרה בממשק המשתמש.

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

קבוצות לוח בקרה שימושיות כוללות:

- **Models:** נפח, איחור, שימוש בטוקנים, שיעור שגיאות, וציוני הערכה.
- **Evaluations:** שיעור הצלחה ומגמות ניקוד לפי סוכן או סביבה.
- **Tools:** נפח קריאות, שיעור כשלים, משך זמן, וקריאות חוזרות.
- **Hooks and policies:** החלטות, דחיות, וקצב התאמת מדיניות.
- **Custom workflow metrics:** תוצאות מהשדות וה-SQL שלך.

התחל עם שאילתה שנשמרה, תאשר את התוצאה שלה, ואז הוסף אותה כטיל. שמור מסננים של ייצור ופיתוח במפורש כדי שתעבור בדיקה לא תחביא נסיגה.

<Tip>
  תן לכל לוח בקרה בעלים ושאלת תגובה, כמו "האם אמינות checkout-agent גרועה יותר מאשבוע שעבר?"
</Tip>
