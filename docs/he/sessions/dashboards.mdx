לוחות בקרה משלבים שאילתות שנשמרו לתצוגה תפעולית. בנו אחד סביב החלטה שאתם מצפים שמישהו יקבל—לא סביב כל מדד זמין.

## בנו לוח בקרה

<Tabs>
  <Tab title="Dashboard">
    1. עברו ל-**Analyze → Queries**, בחרו או פתחו שאילתה שנשמרה, ותקפו את התוצאה שלה.
    2. בחרו **add to dashboard**, ואז בחרו בלוח קיים או בנו אחד חדש תחת **Analyze → Dashboards**.
    3. פתחו את לוח הבקרה, היכנסו למצב עריכה, סדרו את הרעיונות, וחסכו את הפריסה.
    4. חזרו לשאילתה כאשר תצטרכו לשנות את הנתונים או הסינונים מאחורי רעיון.

    ![לוח בקרה המורכב משאילתות שנשמרו לנפח אירועים, שגיאות, עיכוב וניצול אסימוני מודל.](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    CRUD של לוח בקרה אינו חשוף על ידי ה-Cloud CLI הנוכחי. השתמשו ב-CLI כדי לבנות ולאמת את השאילתה השמורה, ואז הוסיפו אותה ללוח בקרה בממשק המשתמש.

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

קבוצות לוחות בקרה שימושיות כוללות:

- **Models:** נפח, עיכוב, שימוש אסימוני, שיעור שגיאה וניקוד הערכה.
- **Evaluations:** שיעור הצלחה ומגמות ניקוד לפי סוכן או סביבה.
- **Tools:** נפח קריאה, שיעור כשל, משך ועריכות חוזרות.
- **Hooks and policies:** החלטות, הכחשות ושיעור התאמה מדיניות.
- **Custom workflow metrics:** תוצאות מעל השדות והSQL שלכם.

התחילו בשאילתה שמורה, תקפו את התוצאה שלה, ואז הוסיפו אותה כרעיון. שמרו על סינוני ייצור ופיתוח מפורשים כדי שתנועת בדיקה לא תסתיר נסיגה.
