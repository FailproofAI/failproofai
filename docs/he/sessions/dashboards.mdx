לוחות בקרה משלבים שאילתות שמורות לתצוגה תפעולית. בנו אחד סביב החלטה שצפויה שמישהו יקבל—ולא סביב כל מדד זמין.

## בנו לוח בקרה

<Tabs>
  <Tab title="לוח בקרה">
    1. עברו ל-**Analyze → Queries**, צרו או פתחו שאילתה שמורה, ואמתו את התוצאה שלה.
    2. בחרו **add to dashboard**, ואז בחרו לוח בקרה קיים או צרו אחד תחת **Analyze → Dashboards**.
    3. פתחו את לוח הבקרה, נכנסו למצב עריכה, סדרו את הרעפים, ושמרו את הפריסה.
    4. חזרו לשאילתה כאשר אתם צריכים לשנות את הנתונים או המסננים מאחורי רעף.

    ![לוח בקרה המורכב משאילתות שמורות לנפח אירועים, שגיאות, זמן התגובה ושימוש בטוקנים של מודל.](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    CRUD של לוח בקרה לא חשוף ב-CLI בענן הנוכחי. השתמשו ב-CLI כדי לבנות ולאמת את השאילתה השמורה, ואז הוסיפו אותה ללוח בקרה בממשק המשתמש.

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

קבוצות לוחות בקרה שימושיות כוללות:

- **Models:** נפח, זמן התגובה, שימוש בטוקנים, שיעור שגיאות וניקוד הערכה.
- **Evaluations:** שיעור הצלחה וטרנדי ניקוד לפי סוכן או סביבה.
- **Tools:** נפח קריאות, שיעור כישלון, משך זמן וקריאות חוזרות.
- **Hooks and policies:** החלטות, דחייות ושיעור התאמת מדיניות.
- **Custom workflow metrics:** תוצאות משדות אירוע וSQL משלכם.

התחילו בשאילתה שמורה, אמתו את התוצאה שלה, ואז הוסיפו אותה כרעף. שמרו מסננים של ייצור ופיתוח מפורשים כך שתנועת בדיקה לא תסתיר נסיגה.

<Tip>
  תנו לכל לוח בקרה בעלים ושאלת תגובה, כגון "האם אמינות checkout-agent גרועה יותר מהשבוע שעבר?"
</Tip>
