אירועים חי עוזרים לכם לאשר את הציוד וצפות בריצה בעלת סיכון ללא חיכוי לסיום הסשן.

## צפייה בפעילות

<Tabs>
  <Tab title="Dashboard">
    1. עברו אל **Observe → Events**.
    2. התחילו עם חלון הזמן הנוכחי ללא סנונים כדי לאשר שנתונים מגיעים.
    3. סננו לפי סביבה, סוג אירוע, סוכן או סשן. השתמשו בחיפוש לטקסט בעומס.
    4. בחרו באירוע כדי לבדוק את ריכוזו והפרטים שלו. עקבו אחר קישור הסשן שלו למעקב המלא.

    ![זרם האירועים החי עם זמן, סביבה, סוג אירוע, סוכן, מודל, הקשר, סשן וסנני טקסט.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    הזנת ברירת המחדל משמיטה עומסים גולמיים. השתמשו ב-`--full` רק לחקירת סשן מוגבל.
  </Tab>
</Tabs>

השתמשו בזרם האירועים לענות על שלוש שאלות מיידיות:

- האם הסוכן הצפוי מדווח לסביבה הנכונה?
- האם קריאות מודל, קריאות כלים והחלטות מדיניות מגיעות בסדר?
- האם הסשן הפסיק להעלות התקדמות או התחיל לחזור על פעולה?

סוגי אירועים כוללים אירועי מחזור חיים של סוכן, בקשות ותגובות מודל, שימוש בכלים ותוצאות, ביצוע וו, המתנה של בני אדם והפסקות, ושגיאות מפורשות. מזהי תאם מצטרפים לאירועים זוגיים כגון קריאת כלי והתוצאה שלה.

<Tip>
  שמרו על התצוגה החי רחבה בעת אימות של אינטגרציה חדשה. הוסיפו סננים רק לאחר שתראו את האירוע הראשון; סנן שגוי יכול להיראות כמו ספיגה שנכשלה.
</Tip>

אם לא מופיעים אירועים, הריצו את `failproofai config --status`, ואז [טרו בעיות בספיגה](/he/reference/troubleshooting).
