אירועים בזמן אמת עוזרים לכם לאשר את הקביעה וללמוד על ריצה בסיכון ללא צפייה להסתיום של התא.

## צפייה בפעילות

<Tabs>
  <Tab title="Dashboard">
    1. עברו ל-**Observe → Events**.
    2. התחילו עם חלון הזמן הנוכחי ללא סינונים כדי לאשר שנתונים הגיעים.
    3. סננו לפי סביבה, סוג אירוע, סוכן או תא. השתמשו בחיפוש לטקסט של payload.
    4. בחרו באירוע כדי לבדוק את סיכומו ופרטיו. עקבו אחרי קישור התא שלו כדי לראות את העקבות המלאים.

    ![זרם Events בזמן אמת המציג תעבורה מ-Hermes chat gateway ותוך כדי ריצות coding-CLI, מסוננת לפי זמן, סביבה, סוג אירוע, סוכן, מודל, קונטקסט ותא.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    הזרם ברירת המחדל משמיט payloads גולמיים. השתמשו ב-`--full` רק לחקירה של תא מוגבל.
  </Tab>
</Tabs>

השתמשו בזרם האירועים כדי לענות על שלוש שאלות מיידיות:

- האם הסוכן הצפוי מדווח לסביבה הנכונה?
- האם קריאות מודל, קריאות כלים והחלטות מדיניות הגיעו בסדר?
- האם התא הפסיק להתקדם או התחיל לחזור על פעולה?

סוגי אירועים כוללים אירועי מחזור חיים של סוכן, בקשות ותגובות מודל, שימוש בכלים ותוצאות, ביצוע hook, המתנות והפרעות אנושיות, וטעויות מפורשות. מזהי מתאם חיברו אירועים זוגיים כמו קריאת כלי והתוצאה שלה.

<Tip>
  שמרו על התצוגה החי רחבה בעת אימות אינטגרציה חדשה. הוסיפו סינונים רק אחרי שתראו את האירוע הראשון; סינון לא נכון יכול להיראות כמו קליטה שהנכשלה.
</Tip>

אם לא מופיעים אירועים, הריצו `failproofai config --status`, ואז [פתרו בעיות בקליטה](/he/reference/troubleshooting).

סוכנים שלא פועלים באחד ממ-12 ה-[harnesses](/he/reference/harnesses) הנתמכים מדווחים על אותם סוגי אירועים דרך ה-[Python SDK](/he/reference/python-sdk), כולל אירועי האנוש-בתוך-התא (`human_wait`, `human_input`, `human_interrupt`) שגטוויי וסוכנים בייצור מסתמכים עליהם.
