אירועים בזמן אמת עוזרים לכם לאשר את התקנת האינסטרומנטציה וצפייה בריצה מסוכנת ללא הצורך להמתין לסיום הסשן.

## צפייה בפעילות

<Tabs>
  <Tab title="Dashboard">
    1. עברו אל **Observe → Events**.
    2. התחילו עם חלון הזמן הנוכחי ללא סינונים כדי לאשר שהנתונים מגיעים.
    3. סננו לפי סביבה, סוג אירוע, סוכן או סשן. השתמשו בחיפוש לטקסט בעומס הנתונים.
    4. בחרו באירוע כדי לבדוק את הסיכום והפרטים שלו. עקבו אחר קישור הסשן שלו לעקבול המלא.

    ![זרם Events חי המציג תעבורה מ-Hermes chat gateway לצד ריצות coding-CLI, מסונן לפי זמן, סביבה, סוג אירוע, סוכן, מודל, קונטקסט וסשן.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    הזרם המוגדר כברירת מחדל משמיט עומסי נתונים גולמיים. השתמשו ב-`--full` רק לבדיקת סשן מוגבל.
  </Tab>
</Tabs>

השתמשו בזרם האירועים כדי לענות על שלוש שאלות מיידיות:

- האם הסוכן הצפוי דיווח לסביבה הנכונה?
- האם קריאות מודל, קריאות כלי והחלטות מדיניות מגיעות בסדר?
- האם הסשן הפסיק להתקדם או התחיל לחזור על אותה פעולה?

סוגי אירועים כוללים אירועי מחזור חיים של סוכן, בקשות ותשובות של מודל, שימוש בכלים ותוצאות, ביצוע hook, המתנה אנושית והפסקות, ושגיאות מפורשות. מזהי קורלציה חוברים אירועים זוגיים כגון קריאת כלי והתוצאה שלה.

<Tip>
  שמרו על התצוגה החיה רחבה בזמן אימות אינטגרציה חדשה. הוסיפו סינונים רק לאחר שתראו את האירוע הראשון; סינון שגוי יכול להיראות ככשל בספיגה.
</Tip>

אם לא מופיעים אירועים, הריצו את `failproofai config --status`, ואז [בצעו פתרון בעיות בספיגה](/he/reference/troubleshooting).

סוכנים שלא פועלים באחד מ-12 [harnesses](/he/reference/harnesses) הנתמכים דיווחים על אותם סוגי אירועים דרך [Python SDK](/he/reference/custom-agents), כולל אירועי הלולאה האנושית (`human_wait`, `human_input`, `human_interrupt`) שסוכני gateway וייצור תלויים בהם.
