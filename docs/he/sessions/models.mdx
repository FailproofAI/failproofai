השתמש ב-Models כדי לראות אם מהימנות או עלות השתנו עם מודל, סוכן, סביבה או טווח זמן.

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Observe → Models**.
    2. הגדר את טווח הזמן, ואז סנן לפי סביבה, מודל, סוכן או מזהה הפעלה.
    3. בדוק את זמן התגובה, צריכת האסימונים, שימוש בחלון ההקשר וחלוקת המודלים.
    4. בחר נקודה בתרשים או קטע בהתפלגות כדי לפתוח את האירועים התואמים.

    ![דף Models המציג תצוגות של זמן תגובה, אחוזון, אסימון, עלות, חלון הקשר והתפלגות מודלים.](/images/dashboard/models.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp list models
    fp events --event-type model_request,model_response --since 24h
    fp --json events --event-type model_response --since 24h --all --limit 500 --fields ts,agent_id,session_id,output_tokens,context_window,context_fill
    ```

    כל שלושתם דורשים `events:read`.

    `--fields` משנה את הטורים; הוא לא מסנן שורות. צרף אותו עם `--event-type` וחלון זמן, או שתקבל את 50 האירועים החדישים ביותר מכל סוג עם `output_tokens` ו-`context_fill` ריקים בכל האירועים שאינם של מודל. `--all` עוצר ב-`--limit`, שברירת המחדל שלו היא 50.

    קרא `context_fill` ליד `context_window`: נתון מילוי משמעו שום דבר בלי החלון שנמדד עליו.

    הדיימון חותם כל אירוע עם סביבה `local` אלא אם כן תשנה זאת, כך ש-`--env production` לא תואם דבר בהתקנה סטנדרטית. ראה [שנה תווית סביבה](/he/reference/events-and-configuration#change-an-environment-label).
  </Tab>
</Tabs>

## מה ה-CLI יכול ולא יכול להציג

זרימת האירועים בברירת המחדל היא ללא עומס. היא מכילה `output_tokens`, `context_window` ו-`context_fill` כטורים מעודכנים, ושום דבר אחר על קריאת מודל:

| ערך | איפה זה נמצא |
| --- | --- |
| אסימונים פלט, חלון הקשר, מילוי הקשר | טורי זרימה קלה — זמינים ישירות מ-`fp events`. |
| שם המודל | עומס — השתמש ב-`fp events --full`, מוגבל להפעלה אחת. |
| אסימוני קלט | עומס — ה-SDK מתעד את שני החלקים, רק חלק הפלט מעודכן. |
| זמן תגובה לקריאה | אין טור `duration_ms` בזרימה הקלה, ו-`model_response` של ה-SDK גם לא מכיל. הסק אותו על ידי שיוך הבקשה לתגובתה. |

`model_request` ו-`model_response` מתאימים ל-`request_id`. שדה זה קיים בדיוק כדי שניתן יהיה להתאים בקשה לתשובתה, וזו הדרך היחידה לחשב זמן תגובה לקריאה מאירועים גולמיים:

```bash
fp --json events --full --event-type model_request,model_response --session-id <session-id> --all --limit 500
```

שמות מודלים מגיעים כפי שהם מכל שיא של רתיעה. שום דבר בנתיב הלכידה לא מנרמל אותם, ולכן מודל בסיסי אחד יכול להופיע תחת מספר מזהים ספציפיים לספק בתרשים ההתפלגות. הפעל `fp list models` כדי לראות את הכתיבה שלדו בפועל.

השתמש בשאילתה שמורה לאגרגטים ברמת מודל שאינם חשופים כפקודת CLI ייעודית.
