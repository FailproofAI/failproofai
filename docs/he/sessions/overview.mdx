סשן הוא נקודת ההתחלה הטובה ביותר כאשר agent מתנהג בצורה בלתי צפויה. הוא מחבר את בקשות המודל, התגובות, קריאות הכלים, האינטראקציות האנושיות, השגיאות, ההערכות וההחלטות המדיניות השייכות להרצה אחת.

סשנים נראים זהים ללא קשר לאיזה harness ייצר אותם. הרצת Claude Code שכותבת מחדש ריפוזיטוריום, agent Hermes שעונה ללקוח ב-Slack, ושירות Python שמצויד ב-SDK - כולם מגיעים לאותה תבנית trace, כך שתצפית אחת מכסה את כל הFleet.

עקוב אחר הרצה אחת של agent מהמטרה שלו דרך קריאות המודל, הכלים והתגובה הסופית.

## מצא סשן

<Tabs>
  <Tab title="Dashboard">
    1. בסרגל הצד של Cloud, עבור ל-**Observe → Sessions**.
    2. קבע את חלון הזמן, ואז סנן לפי environment, status, agent, או session ID.
    3. הוסף score או metric ranges כאשר אתה זקוק לפרוסת quality, cost, token, או latency.
    4. בחר בשורה לפתיחת ה-trace שלה. השתמש בפקד ההעתקה ליד session ID בעת שיתוף.

    ![רשימת Sessions המציגה שורה אחת לכל הרצה עם מסננים של environment, agent, status, ו-evaluation score.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    הוסף `--agents` להרחבת הרצות multi-agent, `--all` לעימוד, או `--fields` לבחירת עמודות output.
  </Tab>
</Tabs>

## מה אתה יכול לעשות

- מצא הרצה לפי agent, environment, זמן, model, event type, או error state.
- עקוב אחר הרצף המדויק שהוביל לתוצאה.
- השווה הרצות מוצלחות ושנכשלו.
- פתח את הראיות המשמשות ממצא ביקורת או incident של alert.
- ייצא סשן כאשר אתה זקוק לרשומה offline.

## סדר חקירה אמין

1. אשר את goal ו-environment של הסשן.
2. מצא את השגיאה הראשונה או ההחלטה בלתי צפויה - לא רק את הכישלון הסופי.
3. בדוק את context המודל ו-tool input מיד לפניו.
4. בדוק retries, latency, ו-human interruptions.
5. סקור את evaluation scores וההחלטות המדיניות.
