הפעלה היא ריצה אחת של סוכן. היא מחברת את ההנמקה, קריאות המודל, הכלים, טעויות, קלט אנושי, החלטות מדיניות, והתוצאה הסופית.

## היכן הפעלות חיות

<Tabs>
  <Tab title="Local">
    הפעל את `failproofai` כדי לפתוח את הלוח בחיווג `http://localhost:8020`. היסטוריית ההפעלות נשארת במחשב זה.
  </Tab>
  <Tab title="Cloud">
    חבר את המחשב, ואז פתח את **Observe → Sessions**:

    ```bash
    export FAILPROOFAI_CLOUD_TOKEN="<key>"
    failproofai config
    ```

    Cloud מקבל תמלולים מלאים כברירת מחדל. כדי לשלוח החלטות מדיניות בלבד, חבר תחילה, ואז הגדר את `collector.sessions` ל-`false` בקובץ `~/.failproofai/config.json`. דגל ההגדרה הנוכחי `--no-transcripts` אינו חל על הגדרה זו.
  </Tab>
</Tabs>

הפעלות מגיעות מ-12 [קונסולות סוכנים](/he/reference/harnesses) בתמיכה ומסוכנים שהותקנו באמצעות ה-[Python SDK](/he/reference/custom-agents).

## מצא הפעלה

ב-Cloud, סנן לפי זמן, סביבה, סטטוס, סוכן, או מזהה הפעלה. מה-CLI:

```bash
fp sessions --since 24h
fp sessions --status error,timeout --agent-id checkout-agent
fp --json sessions --session-id <session-id>
```

השתמש ב-`fp errors --since 24h` לתקלות שמעולם לא הוערכו. `fp sessions --status` משתמש בתוצאת ההערכה העדכנית ביותר, כך שלהפעלה שלא הוערכה אין סטטוס.

## קרא הפעלה

1. אשר את היעד והסביבה של הסוכן.
2. מצא את הטעות או ההחלטה הלא צפויה הראשונה.
3. בחן את הקשר של המודל וקלט הכלי מיד לפניה.
4. בדוק ניסיונות חוזרים, זמן תגובה, והפרעות אנושיות.
5. סקור הערכות והחלטות מדיניות.

## אם הפעלה חסרה

```bash
failproofai flush --wait
failproofai config --status
failproofai backfill --since 30d --dry-run
```

השתמש ב-`failproofai harness add-path <harness> [<label>=]<path>` כאשר הפעלות חיות מחוץ למיקום הרגיל של קונסולה, כגון פרופיל אחר, בית המכל, או ספרייה בעלת קבוצה מעוגנת.
