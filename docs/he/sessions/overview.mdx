session הוא נקודת ההתחלה הטובה ביותר כאשר agent מתנהג בצורה בלתי צפויה. הוא משלב את בקשות המודל, התגובות, קריאות הכלים, האינטראקציות האנושיות, השגיאות, הערכות ההערכה והחלטות המדיניות השייכות להרצה אחת.

sessions נראים זהים ללא תלות באיזה harness ייצר אותם. הרצת Claude Code שכתובה מחדש של מאגר, agent Hermes שעונה לעמית ב-Slack, ושירות Python שמכשיר עם ה-SDK כולם נחתים באותו פורמט trace, כך שתצוגה אחת מכסה את כל הצי.

עקוב אחרי הרצה אחת של agent מהיעד שלו דרך קריאות מודל, כלים, והתגובה הסופית.

## מצא session

אם session הוחזק בקר אחסון קר לאחר שהגעת להקצאת ההרצות שלך, הגדלת ההקצאה בתוך אותו חלון חיוב משחררת sessions זכאות מהקדומות ביותר. חידושי משלוח אינם גורמים ל-session לצרוך הקצאה פעמיים.

<Tabs>
  <Tab title="Dashboard">
    1. בסרגל הצד Cloud, עבור ל-**Observe → Sessions**.
    2. הגדר את חלון הזמן, ואז סנן לפי סביבה, סטטוס, agent, או session ID.
    3. הוסף טווחי ציון או מדדים כאשר אתה צריך פרוסת איכות, עלות, token, או latency.
    4. בחר בשורה לפתוח את ה-trace שלה. השתמש בפקד ההעתקה ליד session ID בעת שיתוף שלה.

    ![רשימת Sessions המציגה שורה אחת לכל הרצה עם filters של סביבה, agent, סטטוס, וציון הערכה.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    הוסף `--agents` להרחבת הרצות multi-agent, `--all` לעימוד, או `--fields` לבחירת עמודות פלט.
  </Tab>
</Tabs>

## מה אתה יכול לעשות

- מצא הרצה לפי agent, סביבה, זמן, מודל, סוג אירוע, או מצב שגיאה.
- עקוב אחרי הסדר הדיוק שייצר תוצאה.
- השווה הרצות מוצלחות וכושלות.
- פתח את ההוכחה המשמשת ממצאי ביקורת או תקרית alert.
- ייצא session כאשר אתה צריך רשומה לא מקוונת.

## סדר חקירה אמין

1. אשר את יעד ה-session והסביבה.
2. מצא את השגיאה הראשונה או ההחלטה בלתי צפויה—לא רק את הכישלון הסופי.
3. בדוק את ההקשר של המודל וקלט הכלי מיד לפניו.
4. בדוק את חידושי הניסיון, latency, והפרעות אנושיות.
5. בדוק ציוני הערכה והחלטות מדיניות.
