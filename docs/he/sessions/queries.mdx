שאילתות הן השכבה הגמישה שתחתיה עומדים דשבורדים, ביקורות וחקירות. השתמש ב-SQL ad-hoc כדי לבדוק רעיון, ואז שמור את השאילתה כאשר היא הופכת לחלק מזרימת עבודה חוזרת.

## יצירה והרצה של שאילתה

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Analyze → Queries** ובחר **new query**.
    2. פתח את דפדפן הסכימה בחר שדות מנתוני האירוע, הסשן או ההערכה.
    3. כתוב SQL, הוסף פרמטרים כאשר יש צורך, והרץ את השאילתה.
    4. שמור אותה עם שם ותיאור ברורים, ואז השתמש ב-**add to dashboard** כאשר התוצאה צריכה להיות מנוטרת.

    עורך השאילתות משלב את סכימת האירוע, SQL, פרמטרים וחזקת תוצאות חיה כך שתוכל לאמת את השאלה לפני שמירה.

    ![עורך שאילתות SQL עם דפדפן סכימה וגריד תוצאות חי.](/images/dashboard/query-lab.png)

    שאילתות שמורות מופיעות לאחר מכן בספריה המשותפת, שם חברי הצוות יכולים להריץ אותן מחדש או להוסיף את התוצאות שלהן לדשבורדים.

    ![ספריית השאילתות השמורות המכילה שאילתות מובנות וחד-פעמיות שניתן לשימוש חוזר.](/images/dashboard/queries.png)

    השתמש בשם ותיאור ברורים כך שהתוצאה תישאר ברורה ללא פתיחה מחדש של ה-SQL שלה.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    השתמש ב-`fp query list` כדי למצוא מזהים ו-`fp query delete <query-id>` כדי להסיר שאילתה שמורה.
  </Tab>
</Tabs>

## שימושים נפוצים

- מצא סשנים עם קריאות חוזרות לאותו כלי.
- השווה ציוני הערכה בין מודלים או סביבות.
- מדוד זמן בין המתנה של אדם להדמיה מחדש.
- זהה שלילות מדיניות ואחריהן חלופה מוצלחת.
- בנה קוהורט לביקורת.

פתח **Queries → Schema** לפני כתיבה נגד שדות לא מוכרים. העדף מסננים זמן וסביבה ברורים, ושמור על הגבלות תוצאות במהלך חקירה.

<Warning>
  שאילתה יכולה לזהות דפוס חשוד, אך היא אינה קובעת את מצב הכשל בעצמה. פתח עקבות מייצגים או הרץ ביקורת לפני שתפוך את התוצאה למדיניות.
</Warning>
