שאילתות הן השכבה הגמישה שמתחת לדוחות המידע, הביקורות והחקירות. השתמש ב-SQL ספונטני לבדיקת רעיון, ואז שמור את השאילתה כאשר היא הופכת לחלק מזרימת עבודה חוזרת.

## יצירה והרצת שאילתה

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Analyze → Queries** ובחר **new query**.
    2. פתח את דפדפן הסכימה ובחר שדות מנתוני האירוע, ההפעלה או ההערכה.
    3. כתוב SQL, הוסף פרמטרים בעת הצורך, והרץ את השאילתה.
    4. שמור אותה עם שם וישור ברורים, ואז השתמש ב-**add to dashboard** כאשר התוצאה צריכה להיות מנוטרת.

    עורך השאילתות משלב את סכימת האירוע, SQL, הפרמטרים ותצוגה מקדימה של התוצאה, כך שתוכל לאמת את השאלה לפני שמירה.

    ![עורך שאילתות SQL עם דפדפן סכימה ורשת תוצאות חיה.](/images/dashboard/query-lab.png)

    שאילתות שנשמרו מופיעות לאחר מכן בספריה המשותפת, שם חברי הצוות יכולים להריץ אותן מחדש או להוסיף את התוצאות שלהן לדוחות מידע.

    ![ספריית השאילתות השמורות המכילה שאילתות מובנות וחד-פעמיות ניתנות לשימוש חוזר.](/images/dashboard/queries.png)

    השתמש בשם וביישור ברורים כך שהתוצאה תישאר מובנת ללא צורך לפתוח מחדש את ה-SQL שלה.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    השתמש ב-`fp query list` כדי למצוא מזהים ו-`fp query delete <query-id>` כדי להסיר שאילתה שמורה.
  </Tab>
</Tabs>

## שימושים נפוצים

- מצא הפעלות עם קריאות חוזרות לאותו כלי.
- השווה ציוני הערכה בין דגמים או סביבות.
- מדוד זמן בין המתנה אנושית לחידוש.
- זהה שלילות מדיניות ואחריהן חלופה מוצלחת.
- בנה קוהורטה לביקורת.

פתח **Queries → Schema** לפני כתיבה כנגד שדות לא מוכרים. העדף מסננים זמן וסביבה מפורשים, ושמור על גבולות תוצאות במהלך חקירה.

<Warning>
  שאילתה יכולה לזהות דפוס חשוד, אך היא אינה קובעת את מצב הכשל בעצמה. פתח עקבות נציגים או הרץ ביקורת לפני הפיכת התוצאה למדיניות.
</Warning>
