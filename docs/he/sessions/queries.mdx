שאילתות הן השכבה הגמישה שמתחת לדשבורדים, ביקורות וחקירות. השתמש ב-SQL ad-hoc כדי לבדוק רעיון, ואז שמור את השאילתה כאשר היא הופכת לחלק מתזרים עבודה קבוע.

## יצירה והרצת שאילתה

<Tabs>
  <Tab title="Dashboard">
    1. עבור ל-**Analyze → Queries** ובחר **new query**.
    2. פתח את דפדפן הסכימה ובחר שדות מנתוני האירוע, הסשן או ההערכה.
    3. כתוב SQL, הוסף פרמטרים כאשר יש צורך, והרץ את השאילתה.
    4. שמור אותה עם שם ותיאור ברורים, ואז השתמש ב-**add to dashboard** כאשר התוצאה צריכה להיות מנוטרת.

    עורך השאילתות משלב את סכימת האירוע, SQL, פרמטרים ותצוגה מקדימה של התוצאה כדי שתוכל לאמת את השאלה לפני השמירה.

    ![עורך שאילתות SQL עם דפדפן סכימה וגריד תוצאות חי.](/images/dashboard/query-lab.png)

    שאילתות שנשמרו מופיעות אז בספריית המשותפת, שם חברי הצוות יכולים להריץ אותן מחדש או להוסיף את התוצאות שלהם לדשבורדים.

    ![ספריית השאילתות השמורות המכילה שאילתות מובנות וקבועות ניתנות לשימוש חוזר.](/images/dashboard/queries.png)

    השתמש בשם ותיאור ברורים כדי שהתוצאה תישאר מובנת ללא פתיחה מחדש של SQL שלה.
  </Tab>
  <Tab title="CLI">
    עבוד בסדר שבו SQL עצמו עובד: בדוק את הסכימה, הרץ את ההצהרה ad-hoc, ואז שמור אותה ברגע שהיא זוכה לשם.

    ```bash
    fp query schema
    fp query schema events

    fp query run --sql "SELECT agent_id, count() FROM analytics.events GROUP BY agent_id"
    fp query run --sql @retry-loops.sql

    fp query create "retry loops" --sql @retry-loops.sql --description "repeated tool calls per session"
    ```

    הכל לאחר מכן לוקח את **השם** של השאילתה, לא id:

    ```bash
    fp query list
    fp query run "retry loops"
    fp query show "retry loops"
    fp query update "retry loops" --sql @retry-loops-v2.sql --yes
    fp query delete "retry loops" --yes
    ```

    השמות ייחודיים לכל ארגון, וזה מה שהופך אותם לידית בטוחה. UUID בצורה של id מתקבל בכל מקום שבו שם הוא, אך `fp query list` לא מדפיס אחד — העמודות שלו הן `name`, `description`, `created by` ו-`created` (כשהשאילתה הופקדה, לא כשעדכנו אותה לאחרונה). הוסף `--show-id` לעמודת id קצרה, או קרא `--json`, שתמיד מכיל את ה-id המלא.

    קשור פרמטרים עמדתיים של שאילתה שמורה עם `--arg` (alias `--param`), חזור על כל אחד לכל `$1..$N` בסדר:

    ```bash
    fp query run <query-name> --arg agent-codegen --arg 0.5
    ```

    | Subcommand | Permission | Notes |
    | --- | --- | --- |
    | `fp query schema [TABLE]` | `queries:read` | העבר שם טבלה כדי לסנן לעמודות שלה. |
    | `fp query list` | `queries:read` | `--show-id` חושף ids; `--fields` משדרים שדות גולמיים. |
    | `fp query show <name>` | `queries:read` | כרטיס מטא-נתונים בתוספת SQL מלא. |
    | `fp query create <name> --sql ...` | `queries:write` | התנגשות שם דחויה מראש. |
    | `fp query update <name>` | `queries:write` | העבר לפחות אחד מ-`--name`, `--sql`, `--description`. מאשר תחילה; no-op יוצא ללא שמירה. |
    | `fp query delete <name>` | `queries:delete` | מאשר תחילה, עם תצוגה מקדימה של מה שהולך. |
    | `fp query run <name>` or `--sql ...` | `queries:run` | בדיוק אחד משניהם. `--limit` ו-`--all` מתאימים את תצוגת הטבלה. |

    `update` ו-`delete` מציעים רק במסוף אינטראקטיבי. תחת `--json`, או עם stdin מופנה, הם ממשיכים ללא שאלה — כך `--yes` הוא למקרה המסוף, לא לסקריפטים.

    שאילתות פועלות כנגד בריכת ניתוח בלבד קריאה. `--sql @file.sql` קורא את ההצהרה מקובץ, שזה הטופס שכדאי לשמור בשליטת גרסה.
  </Tab>
</Tabs>

## סקריפט של שאילתה

`fp --json query run` מחזיר כל שורה ללא קשר לגובה תצוגת הטבלה, בצורה `{columns: [{name, type}], rows: [[...]], truncated, elapsed_ms}`:

```bash
fp --json query run "retry loops" | jq '.rows | length'
```

`fp --json query schema` מחזיר `{schema, columns: [{table, column, type, nullable}]}`, שזו הצורה הניתנת לקריאה של המכונה של דפדפן הסכימה.

שתי כשלים שכדאי לטפל בהן בקוד יציאה ולא בפארזינג טקסט: שם שלא תואם דבר מעניין `✗ no query named "…"` ויוצא 6, ושגיאה SQL או ביצוע מעניין `✗ query failed — …` עם הפרט שלה של השרת מקופל פנימה.

## שימושים נפוצים

- מצא סשנים עם קריאות חוזרות לאותו כלי.
- השווה ניקוד הערכה בין מודלים או סביבות.
- מדוד זמן בין המתנה אנושית וחידוש.
- זהה הכחשות מדיניות ואחריות בחלופה מוצלחת.
- בנה קוהורט לביקורת.

פתח את הסכימה — **Analyze → Queries** בדשבורד, או `fp query schema` — לפני כתיבה כנגד שדות לא מוכרים. העדף מסננים זמן וסביבה מפורשים, וקבל מגבלות תוצאות במהלך חקירה.

<Warning>
  שאילתה יכולה לזהות דפוס חשוד, אך היא לא קובעת את מצב הכשל בעצמה. פתח עקבות נציגים או הרץ ביקורת לפני הפוך התוצאה למדיניות.
</Warning>
