שאילתות הן שכבת הגמישות שמתחת לדוחות, ביקורות וחקירות. השתמש ב-SQL ad-hoc כדי לבחון רעיון, ואז שמור את השאילתה כאשר היא הופכת לחלק מזרימת עבודה קבועה.

## יצירה והרצה של שאילתה

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Analyze → Queries** ובחר **new query**.
    2. פתח את מתصفح הסכימה ובחר שדות מנתוני האירוע, ההפעלה או ההערכה.
    3. כתוב SQL, הוסף פרמטרים במידת הצורך, והרץ את השאילתה.
    4. שמור אותה עם שם ותיאור ברורים, ואז השתמש ב-**add to dashboard** כאשר יש לנטר את התוצאה.

    עורך השאילתות משלב את סכימת האירועים, SQL, פרמטרים וגלוי תוצאות חי, כך שתוכל לאמת את השאלה לפני שמירה.

    ![עורך שאילתות SQL עם מתصפה סכימה וגריד תוצאות חי.](/images/dashboard/query-lab.png)

    שאילתות שמורות מופיעות לאחר מכן בספרייה המשותפת, שם חברי הצוות יכולים להריץ אותן מחדש או להוסיף את התוצאות שלהן לדוחות.

    ![ספרייה שמורה של Queries המכילה שאילתות מובנות וקסטום הניתנות לשימוש חוזר.](/images/dashboard/queries.png)

    השתמש בשם ותיאור ברורים כך שהתוצאה תישאר מובנת ללא פתיחה מחדש של ה-SQL שלה.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    השתמש ב-`fp query list` כדי למצוא מזהים וב-`fp query delete <query-id>` כדי להסיר שאילתה שמורה.
  </Tab>
</Tabs>

## שימושים נפוצים

- חפש הפעלות עם קריאות חוזרות לאותו כלי.
- השווה ציוני הערכה בין מודלים או סביבות.
- מדוד זמן בין המתנה אנושית לחידוש.
- זהה שלילות מדיניות שלאחריהן בחר חלופה מוצלחת.
- בנה קוהורטה לביקורת.

פתח **Queries → Schema** לפני כתיבה מול שדות לא מוכרים. עדיף לפילטרים מפורשים של זמן וסביבה, ושמור על גבולות תוצאות במהלך חקירה.

<Warning>
  שאילתה יכולה לזהות דפוס חשוד, אך היא לא מבססת את אופן הכשל בעצמה. פתח עקבות מייצגים או הרץ ביקורת לפני הפוך את התוצאה למדיניות.
</Warning>
