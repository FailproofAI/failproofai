עקבות הופכים זרם אירועים שטוח לסיפור סיבתי של הריצה. קרא אותם מההבדלות הראשונות, לא לאחור מהשגיאה האחרונה.

## פתיחת העקבות

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Observe → Sessions** ופתח סשן.
    2. השתמש בסיכום הפרופיל כדי לבדוק תוצאה, עיתוי, שגיאות וניקוד הערכה.
    3. סרוק את ציר הזמן והמפה המקטנת. סנן סוגי אירועים או זמן כאשר הסשן גדול.
    4. בחר אירוע כדי לבדוק אותו. השתמש ב**export** עבור JSON של מעריך, או העתק את כתובת ה-URL של הדף כדי לשתף קישור עמוק לראיה שנבחרה.

    ![תצוגת פרטי סשן עם גרף ביצוע, ציר זמן אירועים, לוח הערכה, וטבלת פירוק כלים, מודל וקישור.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    השתמש בהזנת האירועים הקלה תחילה. בקש עומסים מלאים רק כאשר סיכומי האירועים לא מכילים מספיק ראיות.
  </Tab>
</Tabs>

<Steps>
  <Step title="התמצאות">
    אשר את הסוכן, הסביבה, העיתוי, התוצאה ומשך הזמן, לאחר מכן סרוק שגיאות, טווחים ארוכים, כלים חוזרים, המתנות של בנים אדם והחלטות מדיניות מסורבות.
  </Step>
  <Step title="הרחב את האירוע החשוד הראשון">
    בדוק את בקשתו, תגובתו, קלט הכלי, פלט וקוד קורלציה. תוכן רגיש גלוי רק כאשר יצירת תמלול מופעלת וההרשאות שלך מאפשרות זאת.
  </Step>
  <Step title="בדוק את ההקשר שלפני">
    הגורם לעתים קרובות יושב אירוע אחד יותר מוקדם: תגובת מודל לא נכונה, תוצאת כלי חסרה או הנחה ישנה.
  </Step>
  <Step title="הפוך את הראיות לפעולה">
    הוסף את הסשן לתחום ביקורת, קשר אותו לבעיה, או השתמש במצב הכישלון כדי לכתוב מדיניות.
  </Step>
</Steps>

<Warning>
  משך זמן ארוך לא תמיד אומר עיכוב בדגם. הפרד בין זמן מודל, כלי, קישור והמתנה של בנים אדם לפני שתחליט מה לתקן.
</Warning>
