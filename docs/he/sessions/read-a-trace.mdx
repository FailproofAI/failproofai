עקבות היא ציר הזמן של הרצה אחת של סוכן. התחל באירוע הראשון בלתי צפוי, לא בשגיאה הסופית.

<Tabs>
  <Tab title="Dashboard">
    1. פתח את **Observe → Sessions**.
    2. בחר בהפעלה.
    3. חפש את השגיאה הראשונה, קריאת כלי חריגה, המתנה ארוכה, או החלטת מדיניות.
    4. פתח את האירוע ובדוק את הבקשה, התגובה, הקלט והפלט.

    ![תצוגת פרטי הפעלה עם גרף ההוצאה לפועל, ציר הזמן של האירועים, לוח ההערכה, וחלוקת הכלים, המודל והקו שלה.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all --limit 5000
    fp --json events --full --session-id <session-id> --all --limit 2000
    ```

    השתמש ב-`--full` רק כאשר סיכום האירוע חסר ראיות מספיקות. `next_cursor` שאינו null פירושו שהגעת לגבול לפני הסוף.
  </Tab>
</Tabs>

## עקוב אחר הראיות

1. אשר את הסוכן, המטרה, הסביבה והתוצאה.
2. מצא את השגיאה או ההחלטה הבלתי צפויה הראשונה.
3. בדוק את האירוע מיד לפניו.
4. עקוב אחר מזהים תואמים בזוגות בקשה ותגובה.
5. הפוך את הראיות לביקורת, בעיה או מדיניות.

| זוג | שדה מתואם |
| --- | --- |
| בקשת מודל ותגובה | `request_id` |
| קריאת כלי ותוצאה | `tool_call_id` |
| התחלה והשלמה של קו | `hook_id` |
| השהיית סוכן וחידוש | `pause_id` |
| המתנה אדם וקלט | `input_id` |

החלטה מופיעה ב-`hook_completed`. שורה זו מציינת את התוצאה ומקור המדיניות. החלטה במצב observe מופיעה כ-allow עם הפסק הדין האפשרי ב-`failproofai_observed`.

<Warning>
  משך הפעלה ארוך לא תמיד הוא זמן תגובה של מודל. הפריד בין זמן מודל, כלי, קו והמתנת אדם לפני שתחליט מה לתקן.
</Warning>
