| מושג | משמעות | מה אתה יכול להשיג |
| --- | --- | --- |
| Session | משימה אחת של agent או הרצה אחת | שחזור תוצאה בודדת |
| Event | פעולה אחת שנרשמה ב-session | בדיקה של קריאת מודל, שימוש בכלי, שגיאה, פעולת אדם או החלטת policy |
| Trace | התצוגה המסודרת והמקוננת של session | הבנת סיבתיות במקום קריאת יומנים מנותקים |
| Evaluation | ניקוד או שיפוט על session | ניתוב איכות, קביעות, עלות או זמן תגובה ברציפות |
| Audit | סקירה של אוכלוסיית session שנבחרה | חיפוש אחר דפוסי כישלון עם מטרה וקצב מוגדרים |
| Finding | כישלון שנתגלה ב-audit עם תמיכה בהוכחות | ראיית מצב הכישלון, חומרה וה-sessions המושפעים |
| Issue | רשומת תגובה עמידה | הקצאה, דיון וביצוע של Finding או incident של alert |
| Alert | כלל המגלה הישנות | הודעה למגיבים כאשר תנאי ידוע חוזר |
| Policy | כלל שמוערך במהלך פעילות agent | צפייה, חסימה או הפניה מחדש של התנהגות סוכנת |
| Deployment | גלגול policy בעל גרסה למכונות | שליטה איפה policy פועל וחזרה בטוחה |

## לולאת הזמינות

התחל מהוכחות. Session מראה מה קרה. Audit קובע אם זו טעות מבודדת או דפוס. Finding מזהה את מצב הכישלון; Issue בעלות על התגובה. Policy מונע התנהגות זהה, בעוד שalerts אומרים לך אם התנאי חוזר.

<Warning>
  `failproofai audit` מקומי סורק את ההיסטוריה של agent המקומית. Cloud audit החוזר בוחן sessions המאוחסנות ב-Failproof AI Cloud. הם זרימות עבודה נפרדות עם scope ותזמון שונים.
</Warning>
