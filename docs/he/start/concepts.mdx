---

| מושג | משמעות | מה ניתן להשיג |
| --- | --- | --- |
| Session | משימת agent אחת או הרצה אחת | שיחזור תוצאה בודדת |
| Event | פעולה מוקלטת אחת בתוך session | בדיקה של קריאת מודל, שימוש בכלי, שגיאה, פעולה אנושית או החלטת policy |
| Trace | התצוגה המסודרת והמקוננת של session | הבנת סיבתיות במקום קריאה של לוגים מנותקים |
| Evaluation | ניקוד או שיפוט על session | עקוב אחר איכות, תאימות, עלות או זמן תגובה בצורה מתמשכת |
| Audit | בדיקה של אוכלוסיית session נבחרת | חיפוש אחר דפוסי כישל עם מטרה וקצב מוגדרים |
| Finding | כישל תומך בראיות שהתגלה על ידי audit | ראה את מצב הכישל, חומרה והשפעה על sessions |
| Issue | רקורד תגובה קבוע | הקצה, דון והחלק תגיד או אירוע התראה |
| Alert | כלל שמגלה חזרה על התרחשות | הודע למגיבים כאשר תנאי ידוע חוזר |
| Policy | כלל המוערך במהלך פעילות agent | צפה, חסום או הפנה התנהגות מסוכנת |
| Deployment | הטלת policy בגרסה לחשבונות | שלוט היכן policy פועל וחזור לאחור בבטיחות |

## לולאת האמינות

התחל מראיות. session מראה מה קרה. audit קובע האם זו טעות מבודדת או דפוס. finding מזהה את מצב הכישל; issue הוא בעלים של התגובה. policy מונע התנהגות זהה, בעוד שalerts מודיעים לך אם התנאי חוזר.

<Warning>
  failproofai audit מקומי סורק היסטוריית agent מקומית. Failproof AI Cloud audit חוזר בדקות sessions המאוחסנות ב-Failproof AI Cloud. הם זרימות עבודה נפרדות עם טווח וזמנוט שונים.
</Warning>
