| מושג | משמעות | מה אתה יכול להשיג |
| --- | --- | --- |
| Session | משימה או ריצה אחת של agent | שחזור תוצאה בודדת |
| Event | פעולה אחת שתועדה ב-session | בדיקת קריאת מודל, שימוש בכלי, שגיאה, פעולה אנושית או החלטת מדיניות |
| Trace | התצוגה הממוינת והמקוננת של session | הבנת סיבתיות במקום קריאת יומנים מנותקים |
| Evaluation | ניקוד או שיקול על session | מעקב אחר איכות, ציות, עלות או חביון בעדכון קבוע |
| Audit | סקירה של אוכלוסיית session שנבחרה | חיפוש דפוסי כשל עם מטרה וקצב מוגדרים |
| Finding | כשל מבוסס-ראיות שגילה audit | צפייה במצב הכשל, חומרת הבעיה וה-sessions המושפעים |
| Issue | רשומת תגובה עמידה | הקצאה, דיון והחלטה על finding או אירוע alert |
| Alert | כלל המזהה חזרה | הודעה ללוחמי הכיבוי כאשר תנאי ידוע חוזר |
| Policy | כלל המוערך במהלך פעילות agent | צפייה, חסימה או הפניה חוזרת של התנהגות מסוכנת |
| Deployment | הטלת מדיניות עם גרסה לשרי-קצה | שליטה היכן מדיניות פועלת וביצוע rollback בטוח |

## לולאת האמינות

התחל מראיות. Session מראה מה קרה. Audit קובע האם זו טעות מבודדת או דפוס. Finding מזהה את מצב הכשל; issue בעלות על התגובה. Policy מונע את אותה התנהגות, בעוד שalerts אומרים לך אם התנאי חוזר.

<Warning>
  `failproofai audit` מקומי סורק היסטוריית agent מקומית. Audit ענן חוזר בודק sessions המאוחסנות ב-Failproof AI Cloud. אלו הם זרימי עבודה נפרדים עם scope וזמנון שונים.
</Warning>
