Failproof AI מתעד את מה שעושים agents ומחליט מה הם רשאים לעשות.

## Observe

| Term | משמעות |
| --- | --- |
| Session | הרצת agent אחת |
| Event | פעולה אחת בתוך session |
| Trace | התצוגה המסודרת של session |
| Evaluation | ניקוד או שיפוט |
| Audit | בדיקה של הרבה sessions |
| Finding | ראיות לתבנית כשל |
| Issue | התגובה שמישהו אחראי לה |
| Alert | כלל שמוצא חזרה על התופעה |

## Enforce

| Term | משמעות |
| --- | --- |
| Harness | הסביבה שבה רץ agent |
| Hook | נקודה שבה ה-harness שואל על החלטה |
| Policy | כלל שמאפשר, מנחה או חוסם |
| Policy pack | קבוצת policies מוגדרת גרסה שכל אחד יכול להתקין |
| Daemon | השירות המקומי שמעריך policies |
| Deployment | Policies המוקצים למכונה |

## The workflow

```text
Session → Audit → Finding → Issue → Policy
```

התחל בראיות. מצא את הכשל החוזר, הקצה את התגובה, ואז מנע אותו.

Policy מחזיר `allow`, `instruct`, או `deny`. הנחיה דרך `instruct` תלויה ב-harness; השתמש ב-`deny` כאשר על הפעולה להיעצר.

Observe mode הוא נפרד מההחלטה. הוא מריץ את ה-policy האמיתי ומתעד מה הוא היה עושה תוך שהוא מאפשר ל-agent להמשיך.

<Warning>
  `fp fleet deploy <machine> --add <policy>` חשוף אוכף מיד. הוסף `:observe` לגלגול צל.
</Warning>

Setup לא בוחר policy pack. לפני שתוסיף אחד, רק `block-failproofai-commands` רץ. הקטלוג המהודר מכיל 39 policies על פני 9 קטגוריות.

ראה [harnesses נתמכים](/he/reference/harnesses#enforcement-capability) לפני שאתה מניח שאירוע יכול לחסום בכל סביבת agent.
