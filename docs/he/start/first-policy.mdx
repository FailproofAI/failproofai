התחל עם התנהגות שאתה רוצה להפסיק ופעולה לגיטימית שחייבת להמשיך לעבוד.

## נסה מדיניות שנבדקה תחילה

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI כולל 39 מדיניויות שנבדקו. בדוק את ה-[קטלוג](/he/policies/builtin-catalog) לפני שכתיבת חדשה.

## כתוב ובדוק שלך

<Steps>
  <Step title="צור מדיניות עובדת">
    ```bash
    failproofai publish --init guards.mjs
    ```

    זה כותב מדיניות החוסמת `git push --force`. ערוך אותה לפי הכלל שלך.
  </Step>
  <Step title="אכוף אותה על המכונה הזו">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    בקש מהאגנט שלך לבצע את הפעולה החסומה, ואז בדוק את **Policies → Activity** בלוח המחוונים המקומי.
  </Step>
  <Step title="שמור או הסר אותה">
    הנח קובץ `*policies.mjs` תחת `.failproofai/policies/` כדי לטעון אותו באופן אוטומטי.

    הסר קבצים מותאמים אישית מפורשים עם:

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## שתף אותה

פרסם חבילה ציבורית:

```bash
failproofai publish
```

כל אחד יכול להתקין אותה עם `failproofai policies add <owner>/<repo>`. הוסף את הנושא בגיטהאב `failproofai-policies` בעצמך כדי ש-[Policy Hub](https://befailproof.ai/policy-hub/) יוכל לאינדקס אותה.

עבור rollout ענן:

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  `--add checkout-guard` בודד אכוף מיד. הוסף `:observe` כדי לתעד מה המדיניות הייתה עושה ללא חסימת האגנט.
</Warning>

ראה [פרסם חבילה](/he/policies/publish-a-pack) או [פרוס מדיניויות](/he/policies/deploy) עבור זרימת העבודה המלאה.
