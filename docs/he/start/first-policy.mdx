השתמש במדיניות רק לאחר שתוכל לתאר את הפעולה בלתי בטוחה ואת הפעולות החוקיות שחייבות להישמר כמותרות.

<Tabs>
  <Tab title="Dashboard">
    <Steps>
      <Step title="כתוב את המדיניות">
        עבור אל **Admin → policy editor**. התחל עם מדיניות ההדגמה, בדוק או ערוך את קוד המקור שלה, ואז בחר **publish version**. פרסום יוצר את הגרסה הבלתי ניתנת לשינוי שתוכל להציג על מכונות.

        ![תצוגת compose של עורך המדיניות עם מדיניות הדגמה מוכנה לפרסום כגרסה בלתי ניתנת לשינוי.](/images/dashboard/policy-editor.png)
      </Step>
      <Step title="הצגה על מכונה">
        עבור אל **Admin → enforcement**, הרחב את המכונה היעד, ובחר **edit this machine**. הוסף את מדיניות ההדגמה שפורסמה, הצמד את הגרסה שלה, בחר **observe**, והחל את ההצגה.

        ![עורך הצגת מכונה עם גרסה של מדיניות שפורסמה שנבחרה במצב observe לפני יישום ההצגה.](/images/dashboard/enforcement-editor.png)
      </Step>
      <Step title="אמת את המדיניות">
        הפעל הפעלת agent חדשה על אותה מכונה, ואז פתח **Observe → policy**. בחר את המכונה ואשר שמדיניות ההדגמה מופיעה במיפוי המדיניות ובציר הזמן של ההחלטות. מצב observe רושם מה המדיניות הייתה עושה ללא חסימת הפעולה.

        ![הדף Policy המציג סך הכל החלטות, פעילות אכיפה לאורך זמן, ומיפוי מדיניות מוקומי וממנוהל בענן.](/images/dashboard/policy-observe.png)
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    יצירת מדיניות בענן והצגת fleet הם זרימות עבודה ניהוליות. השתמש ב-CLI המקומי לאימות אותה מדיניות לפני פרסומה:

    ```bash
    failproofai policies --install --custom ./payment-retry.policies.ts \
      --cli claude --scope project
    failproofai config --status
    ```

    השתמש ב-`fp` לבדיקת החלטות מדיניות הגלויות לענן:

    ```bash
    fp events --event-type hook_completed --env production --since 24h
    fp sessions --env production --since 24h
    ```

    שתי הצעדים זמינים גם מה-CLI: `fp policies publish <id> <file>` משכך גרסה ו-`fp fleet deploy <machine-id> --add <id>` מעמידה אותה על מכונה. המקבילים לדשבורד הם **Admin → policy editor** ו-**Admin → enforcement**.
  </Tab>
</Tabs>
