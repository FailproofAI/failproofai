השתמש במדיניות רק לאחר שתוכל לתאר את הפעולה לא בטוחה והפעולות החוקיות שחייבות להישאר מורשות.

<Tabs>
  <Tab title="Dashboard">
    <Steps>
      <Step title="כתוב את המדיניות">
        עבור אל **Admin → policy editor**. התחל עם מדיניות ההדגמה, בדוק או ערוך את המקור שלה, ואז בחר **publish version**. פרסום יוצר את הגרסה הבלתי ניתנת לשינוי שאתה יכול לפרוס למכונות.

        ![תצוגת הרכב של עורך המדיניות עם מדיניות הדגמה מוכנה לפרסום כגרסה בלתי ניתנת לשינוי.](/images/dashboard/policy-editor.png)
      </Step>
      <Step title="פרוס אותה למכונה">
        עבור אל **Admin → enforcement**, הרחב את המכונה היעד, ובחר **edit this machine**. הוסף את מדיניות ההדגמה המפורסמת, הצמד את הגרסה שלה, בחר **observe**, והחל את הפריסה.

        ![עורך פריסת המכונה עם גרסת מדיניות מפורסמת שנבחרה במצב צפייה לפני החלת הפריסה.](/images/dashboard/enforcement-editor.png)
      </Step>
      <Step title="אמת את המדיניות">
        הפעל הפעלת סוכן חדשה על אותה מכונה, ואז פתח את **Observe → policy**. בחר את המכונה וודא שמדיניות ההדגמה מופיעה במיפוי המדיניות וציר הזמן של ההחלטות. מצב צפייה רושם את מה שהמדיניות הייתה עושה מבלי לחסום את הפעולה.

        ![דף המדיניות המציג סך הכל החלטות, פעילות אכיפה לאורך זמן, ומיפוי מדיניות מקומי ומנוהל בענן.](/images/dashboard/policy-observe.png)
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    עריכת מדיניות בענן ופריסת צי הם זרימות עבודה ניהוליות. השתמש ב-CLI המקומי כדי לאמת את אותה מדיניות לפני פרסומה:

    ```bash
    failproofai policies --install --custom ./payment-retry.policies.ts \
      --cli claude --scope project
    failproofai config --status
    ```

    השתמש ב-`fp` כדי לבדוק החלטות מדיניות הגלויות בענן:

    ```bash
    fp events --event-type hook_completed --env production --since 24h
    fp sessions --env production --since 24h
    ```

    CLI בענן לא חושף מסלולי פריסת אכיפה לשימוש אך ורק ב-root. פרסם גרסות מ-**Admin → policy editor** ופרוס אותן מ-**Admin → enforcement**.
  </Tab>
</Tabs>
