הגדר את Failproof AI במכונה אחת, ואז שהה בחלק המקומי או התחבר לענן.

אם הסוכן שלך פועל ב[harness נתמך](/he/reference/harnesses), עקוב אחר שלבים אלה. לסוכנים שנבנו עם LangChain, CrewAI, LlamaIndex, Pydantic AI, או runtime משלך, התחל ב[instrument your agent](/he/start/integrations).

## תן לסוכן שלך להנחות את ההגדרה

התקן את Failproof AI umbrella skill לסוכן תואם:

```bash
npx skills add FailproofAI/skills
```

זה מתקין את ה-umbrella skill ואת אחיות המומחיות שלו. השתמש ב-`--skill failproofai` אם אתה רוצה רק את ה-umbrella. זה מבין הגדרה מקומית וענן, בריאות daemon, sessions, audits, מדיניויות, וטיוב תקלות. זה מנחה את העבודה ומנתב משימות מיוחדות לכישור Failproof AI הנכון; זה לא מחליף את התקנת ה-CLI למטה.

## הגדר את המכונה

<Steps>
  <Step title="התקן והגדר את Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    ההגדרה מתקינה את שירות הרקע ומחברת כל סוכן נתמך שהיא מוצאת. ייתכן שהוא יבקש גישת מנהל פעם אחת. זה תומך ב-Linux וב-macOS.
  </Step>

  <Step title="בחר מדיניויות">
    ההגדרה בוחרת שום חבילת מדיניות. הוסף את חבילת Failproof AI:

    ```bash
    failproofai policies add FailproofAI/policies
    failproofai policies
    ```

    הפקודה השנייה מציגה כל מדיניות במכונה זו וגם אם היא פועלת. עד שתוסיף חבילה, רק `block-failproofai-commands` פועל.
  </Step>

  <Step title="בדוק את המכונה">
    ```bash
    failproofai config --status
    ```

    זה מדווח על השירות, חיבור ענן, וממנע בעמדת השהיה.
  </Step>
</Steps>

## בחר מקומי או ענן

<Tabs>
  <Tab title="שהה בחלק המקומי">
    אין צורך בחשבון.

    ```bash
    failproofai
    failproofai audit
    ```

    הפקודה הראשונה פותחת את לוח המחוונים המקומי ב-`http://localhost:8020`. השנייה סורקת את היסטוריית הסוכן שכבר במכונה זו.
  </Tab>

  <Tab title="התחבר לענן">
    צור מפתח מכונה בענן Failproof AI, ואז הפעל:

    ```bash
    failproofai config --token <machine-key>
    failproofai config --status
    ```

    הענן מקבל החלטות מדיניות ותמלילי session. כדי לשלוח החלטות בלבד, התחבר תחילה, ואז הגדר `collector.sessions` ל-`false` ב-`~/.failproofai/config.json`; דגל ההגדרה `--no-transcripts` הנוכחי לא מחיל את ההגדרה הזו. לשימוש בקליפות משותפות וב-CI, השתמש ב-`FAILPROOFAI_CLOUD_TOKEN` במקום להכניס את המפתח בהיסטוריית הפקודות.
  </Tab>
</Tabs>

## אמת את זה

הפעל אחד מהסוכנים שלך וביקש ממנו לבצע משימה רגילה. לאחר מכן:

שלילת קריאת כלי מאומתת בכל 12 harnesses נתמכים. אכיפת end-turn מאומתת על 8; זוגות harness-event אחרים עשויים להיות רק צפייה או לא מאומתים.

- פתח **Policies → Activity** בלוח המחוונים המקומי כדי לראות החלטות מדיניות.
- פתח **Observe → Sessions** בענן כדי לראות את ההרצה המלאה.
- הפעל `failproofai audit` כדי לחפש דפוסים מסוכנים או בזבזניים.

<Warning>
  לאחר ההגדרה, שירות `failproofaid` הוא המחשבון. אם הוא לא יכול לענות, פעולות מוגנות נשללות. הפעל `failproofai config --status` כאשר סוכן מפסיק בצורה בלתי צפויה.
</Warning>
