התחלה מהירה זו מעלה מכונה אחת לדיווח הפעלות, מפעילה ביקורת, והנוסחת מדיניות. השתמש בכישרון להגדיר את Failproof AI, או בצע את השלבים ידני.

**איזה נתיב שלך?** אם האגנט שלך פועל באחד מ-12 [מכלולים](/he/reference/harnesses) הנתמכים — CLI קידוד, או שער כמו Hermes או OpenClaw — בצע את השלבים להלן; אתה צריך Node.js 20.9 ואחרונה. אם לאגנט שלך אין מכלול, הנח אותו באמצעות [Python SDK](/he/reference/custom-agents) עבור עקיבה וביקורות, ואז חזור ל-[הרץ את בדיקת הכשל הראשונה שלך](/he/start/first-audit); אכיפה בנתיב זה דורשת hook בהרטיים שלך.

  <Tab title="הגדרה ידנית">
    ## התקן

<Steps>
  <Step title="התקן והתחבר ל-Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    הפקודה אחת זו היא כל ההגדרה: היא מתקינה את הדימון המקומי (root פעם אחת), חוברת hooks לכל CLI של אגנט שהוא מוצא, ומחברת את המכונה הזו לענן.

    ב-**Connect to cloud**, ההגדרה מתחילה להתחבר אותך ל-FailproofAI Cloud מיד (לחץ על Tab עבור האפשרויות האחרות: הדבק מפתח API, או השתמש בקוד פתוח). הוא פותח קישור בדפדפן שלך (דרך SSH, או במכונה ללא תצוגה, הוא מדפיס את הקישור כדי שתוכל לפתוח אותו בכל מכשיר). הירשם או התחבר, אשר את הארגון — או צור אחד שם — ולחץ על **Authorize**. שם המפתח והרשאותיו מוגדרים עבורך. אתה לא צריך חשבון מראש.

    הטרמינל מבחין בעצמו ומציג מי אישר אותו ועבור איזה ארגון. אשר את האגנטים לעקיבה, וההגדרה מסתיימת. מפתח המכונה נוצר רק בנקודה זו, לאחר התקנת הדימון, כך שריצה שאתה מנטוש לא משאיר מפתח אחריך; הוא מופיע תחת **Administration → Keys** מסומן **cli login**, שם אתה יכול להשלות אותו.

    <Accordion title="אין דפדפן או טרמינל בהישג יד? השתמש במפתח (CI, containers, provisioning scripts)">
      בלוח הבקרה של [Failproof AI](https://app.befailproof.ai), עבור אל **Administration → Keys** וצור מפתח עם `events:add` ו-`policies:pull`. אם אתה מתכנן להשתמש ב-[Jev דרך FailproofAI Cloud](/he/reference/jev-cloud), בחר בתצוגה המקדימה של **machine**, שגם מעניקה `jev:evaluate`. העתק את הסוד החד-פעמי וקרא אותו לשרך במכונת היעד — `read -s` לוקח אותו בהנחיה שלא משדרת:

      ```bash
      read -rs FAILPROOFAI_KEY && export FAILPROOFAI_KEY
      FAILPROOFAI_CLOUD_TOKEN="$FAILPROOFAI_KEY" failproofai config
      ```

      העברת המפתח דרך הסביבה ולא `--token` שומרת אותה מ-`ps`, שם כל משתמש במכונה יכול לקרוא ארגומנטים של פקודה. היא לא משמרת אותה מ-shell history — קריאתה עם `read -s` היא מה שעושה זאת. ב-CI, הזרק אותה כסוד מוסווה והשאר tracing של shell (`set -x`) כבוי, או העקיבה תדפיס אותה. בריצה אינטראקטיבית אתה יכול גם לבחור **Paste an API key** ב-**Connect to cloud** במקום.
    </Accordion>

    תמלילי הפעלה נשלחים בברירת מחדל. הוסף `--no-transcripts` כדי לדווח על פעילות hook והחלטות מדיניות ללא תוכן תמליל.

    <Warning>
      אל תגע ל-`failproofai config --connect <url>` כאן. הדגל הזה רושם מכונה שהיא **כבר** מוגדרת וחוזרת מיד — ללא daemon, ללא hooks — כך המכונה תופיע בענן תוך שלא תאסוף או תאכוף כלום.
    </Warning>

    אם למכונה זו כבר יש היסטוריית אגנט, תצוגה מקדימה ויבוא של שבעת הימים האחרונים, ואז חכה שהמסירה תסתיים. דלג על שלב זה במכונה חדשה.

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    פתח את **Sessions** ב-Failproof AI ובחר בהפעלה יבואה.
  </Step>
  <Step title="צרף את Failproof AI למכלול">
    השלב הקודם כבר חיבר כל CLI של אגנט שהוא גילה. הרץ אותו שוב עבור מכלול אחד בבירור כשאתה צריך, או כדי להוסיף מכלול שהותקן לאחר מכן. כל אחד מ-12 הוא ערך `--cli` חוקי — `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, `goose`.

    ```bash
    failproofai policies --install --cli claude --scope user     # a coding CLI
    failproofai policies --install --cli hermes --scope user     # a Slack/Telegram gateway
    ```

    חסימת קריאה לכלי לפני שהיא פועלת מאומתת בכל 12. שערים לסיום תור מאומתים ב-8 — ראה [יכולת אכיפה](/he/reference/harnesses#enforcement-capability) עבור מטריצת per-harness.
  </Step>
  <Step title="בחר מה לאכוף">
    חיבור hooks אינו מאפשר מדיניות. ההגדרה בחרה בכוונה באף אחד — ההחלטה הזו היא שלך — אז קח חבילה:

    ```bash
    failproofai policies add FailproofAI/policies
    ```

    החבילה מתקבלת משחרור GitHub שלה, אומת checksum, ונעוצה לתג המדויק שהוא התפתח. היא נושאת 39 מדיניות וממירה את ה-10 המדיניות שלה מסימנת כבטוחה להפעלה ללא השגחה. השתמש בהם כדי לראות החלטות מדיניות מקומיות וChuck כיצד אכיפה לפני ש-Failproof AI מבקר את ההפעלות שלך וכותבת מדיניות עבור האגנטים שלך.

    קרא כל חבילה לפני שתקח אותה עם `failproofai policies show <owner>/<repo>`, וראה [policy packs](/he/policies/packs) לעיסוק בחלק בלבד מחבילה.

    עד שזה רץ, הדבר היחיד שאוכף הוא `block-failproofai-commands` — השומר שתמיד פועל שעוצר אגנט מכיבוי Failproof AI. `failproofai policies` מפרטת מה בעל.
  </Step>
  <Step title="בדוק את ההתנהגות">
    בצע [הרץ את בדיקת הכשל הראשונה שלך](/he/start/first-audit). השתמש במטרה קונקרטית כמו "מצא הפעלות שבהן האגנט ניסה שוב כלי שנכשל מבלי לשנות את הגישה שלו."
  </Step>
  <Step title="מנע את הכשל">
    בצע [מנע את הכשל הראשון שלך עם מדיניות](/he/start/first-policy). התחל במצב צפייה, בחן התאמות, ואז אכוף את הגרסה שנבדקה.
  </Step>
</Steps>

<Check>
  הרץ `failproofai config --status`. הגדרה בריאה מדווחת על חיבור הענן, מצב daemon, והאם אכיפה מושהה.
</Check>

## הגדרת Jev

השתמש ב-[Jev](/he/start/use-jev) לדירוג של הפעלות שהושלמו מול שאלה עם תשובות ידועות, או לסקור קריאות לכלים בהקשר לפני שהם רצים. לדף **Use Jev** יש שני נתיבי הגדרה.
