## נתיב ייצור מומלץ

1. חבר מכונה שאינה בייצור עם ספיגת תמלילים מופעלת.
2. אמת הפעלות והערכות ב-Cloud.
3. צור ביקורת עבור מצב כשל ידוע.
4. פרוס את המדיניות הראשונה במצב Observe.
5. הרחב לייצור לאחר בדיקת התאמות וחיוביים כוזבים.

## חבר מכונה ל-Cloud

<Tabs>
  <Tab title="Dashboard">
    1. עבור אל **Administration → Keys** וצור מפתח עם `events:add` ו-`policies:pull`.
    2. העתק את הסוד החד-פעמי למכונת היעד.
    3. לאחר הרצת פקודת התחברות של CLI, עבור אל **Admin → enforcement** והאשר שהמכונה מופיעה.
    4. עבור אל **Observe → Events** והאשר שהאירוע הראשון שלה הגיע.

    תא המפתח מציג את שתי ההרשאות הנדרשות על ידי מכונה מחוברת: ספיגת אירועים ואספקת מדיניויות.

    ![תא מפתח API חדש המשמש להענקת הרשאות ספיגת אירועים ואספקת מדיניויות.](/images/dashboard/key-create.png)

    לאחר התחברות, המכונה צריכה להופיע ב-Enforcement עם מצב המדיניות הרצוי שלה ודוח ההפריסה.

    ![צי Enforcement עם מכונה רשומה המורחבת להצגת מצב המדיניות הרצוי שלה ודוח ההפריסה.](/images/dashboard/enforcement-fleet.png)

    האירוע הראשון שהגיע מאשר שהדאימון יכול להציע נתונים ל-Cloud, ללא תלות בפריסת מדיניויות.

    ![זרם האירועים החי המציג אירועי Agent, Model וTool אחרונים.](/images/dashboard/events-stream-current.png)

    המשך רק לאחר שגם המכונה וגם האירוע הראשון שלה נראים.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --connect https://app.befailproof.ai \
      --token "$FAILPROOFAI_KEY" \
      --machine-label checkout-runner-01

    failproofai policies --install --cli claude --scope user
    failproofai config --status
    ```

    הוסף `--no-transcripts` כאשר תוכן התמלילים חייב להישאר מקומי.
  </Tab>
</Tabs>

התחברות ל-Cloud מאמתת ספיגת אירועים ואספקת מדיניויות ללא תלות. מפתח עשוי להיות תקף אך מחוסר הרשאה אחת נדרשת. השתמש ב-`failproofai config --status` כדי לראות איזו יכולת מוגדרת.

<Info>
  הגדרת Cloud כותבת אישורים מקומיים רק לאחר שהיכולת הרלוונטית מצליחה. אימות כושל לא משאיר מכונה נראית מחוברת כאשר היא לא.
</Info>
