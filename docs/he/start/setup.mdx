Failproof AI יכול לפעול לחלוטין על מכונה אחת או להתחבר ל-Cloud לשיתוף שיחות וניהול מדיניות.

## Local, ללא חשבון

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai
```

זה מתקין את השירות, מחבר agents נתמכים, מוסיף חבילת מדיניות, ופותח את לוח הבקרה ב-`http://localhost:8020`.

הרץ `failproofai audit` כדי סרוק את היסטוריית agent שכבר קיימת על המכונה.

## התחבר ל-Failproof AI Cloud

צור machine key ב-Cloud, ואז הרץ:

```bash
failproofai config --token <machine-key>
failproofai config --machine-label checkout-runner-01
failproofai policies add FailproofAI/policies
failproofai config --status
```

או ייצא `FAILPROOFAI_CLOUD_TOKEN=<machine-key>` והרץ `failproofai config` בסיסי. עדיף להשתמש במשתנה הסביבה על מכונות משותפות וב-CI כדי שהמפתח לא יגיע להיסטוריית shell או לרשימות תהליכים.

Cloud משתמש בחיבור אחד לשתי עבודות נפרדות:

- משוך מדיניויות שהוקצו למכונה זו.
- שלח החלטות מדיניות וטרנסקריפציות שיחות.

כדי לשלוח החלטות בלבד, התחבר תחילה, ואז הגדר את `collector.sessions` ל-`false` ב-`~/.failproofai/config.json`. אל תסתמוך על `--no-transcripts`: נתיב ההגדרה הנוכחי פועל עם הדגל אך לא מחיל אותו. ראה [events and configuration](/he/reference/events-and-configuration#machine-configuration).

<Note>
  `--machine-label` שינויי שם של מכונה שכבר מחוברת. הרץ אותו אחרי פקודת ההגדרה, לא כחלק מהחיבור הראשון.
</Note>

## הגדרה ללא השגחה

`failproofai config` לא דורש דגל מיוחד לא-אינטרקטיבי. ב-CI או בקונטיינר הוא מחיל את ההגדרה המבוקשת ללא הנחיות.

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

גישת מנהל נדרשת פעם אחת כדי להתקין את השירות ברקע. ההגדרה לא פותחת לעולם הנחיית סיסמה אינטרקטיבית `sudo`: היא או מצליחה ללא אחת או מדפיסה את הפקודות שמנהל חייב להריץ.
