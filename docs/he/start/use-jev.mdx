Jev עוזר בשתי נקודות בהפעלת agent: הערך הפעלה שהסתיימה מול תשובות ידועות, או בדוק קריאת כלי בהקשר של מה שביקשת מה-agent לעשות.

<Tabs>
  <Tab title="הערכות Jev">
    השתמש בהערכת Jev כאשר הפעלה שהסתיימה ניתנת להערכה מול שאלה עם כמה תשובות ידועות, כגון "האם הלקוח ביקש זיכוי? ענה כן או לא." זה עוזר לך למצוא דפוסים על פני הפעלות.

    ## צור הערכה

    בלוח הבקרה של Cloud, פתח **Analyze → eval authoring → new eval**. הזן שאלה אחת בתשובה קבועה, בחר **draft**, וודא שבחר ניקוד מסווג. [בדוק זאת](/he/evaluations/test) בהפעלות אמיתיות, ואז פרוס אותה.

    ![טופס הערכה משותף שבו אתה מתאר שאלה, בודק את הטיוטה, ופורסם אותה. צילום מסך זה מציג טיוטת קוד; השתמש בשאלה בתשובה קבועה עבור Jev.](/images/dashboard/eval-authoring-draft.png)

    ## קרא את הניקודים

    לאחר שהפעלה חדשה הסתיימה, פתח **Observe → Evaluations** או השתמש ב-Cloud CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    ה-CLI קורא ניקודים; יצירת הערכת Jev משתמשת כרגע בלוח הבקרה. ראה [הערכות Jev](/he/evaluations/jev) לסוגי שאלות ודוגמאות.
  </Tab>
  <Tab title="מדיניות Jev">
    השתמש בבדיקת מדיניות Jev כאשר מדיניות תואמת מחרוזת זקוקה להקשר של הבקשה שלך כדי להחליט אם קריאת כלי בטוחה. התחל במצב **observe** כדי שתוכל לבדוק את התשובות של Jev בזמן שהמדיניות המותקנת שלך עדיין מחליטה על כל קריאה.

    בדיקות Jev מגיעות מחבילה; Failproof AI לא משלחת אף אחת. עד שתתקין אותן, Jev לא שואל כלום, גם כשהוא מוגדר:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## הגדר Cloud Jev

    בלוח הבקרה של Cloud, פתח **Administration → Keys** וצור מפתח עם הערך **machine**. השתמש בו עם `failproofai config` כפי שמוצג ב-[quickstart](/he/start/quickstart). על מכונה ללא קונפיגורציית Jev קיימת, זה מאפשר Cloud Jev במצב observe. בדוק את החיבור עם:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## השתמש בנקודת הקצה שלך

    בלוח הבקרה המקומי, פתח **Settings → Jev**. בחר את הספק, הדבק את הטוקן שלו, בחר **observe**, והפעל את Jev.

    ![לוח הגדרות Jev המקומי עם ספק, שדה טוקן, ומצב observe שנבחר.](/images/dashboard/jev-settings.png)

    או הגדר ובדוק את נקודת הקצה שלך מטרמינל:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    בקש מ-agent בקוקו להשתמש בכלי קריאת הקבצים שלו ב-`README.md`. אשר שקריאת הכלי הזו מופיעה בהפעלה, ואז בדוק אותה תחת **Policies → Activity** בלוח הבקרה המקומי. לאחר שתוצאות ה-observe נראות נכונות, [מדיניות Jev](/he/policies/jev) מסבירה מתי לאכוף. לפרטי ספק והגדרה, ראה את [התייחסות האינטגרציה](/he/reference/jev).
  </Tab>
