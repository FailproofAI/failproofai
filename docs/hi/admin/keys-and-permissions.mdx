प्रत्येक व्यक्ति, मशीन या स्वचालन कार्य के लिए एक अलग कुंजी का उपयोग करें। केवल उसे आवश्यक अनुमतियाँ दें।

## कुंजी बनाएँ और घुमाएँ

**Admin → Keys** का उपयोग करें, या Cloud CLI का:

```bash
fp keys list
fp keys create "audit automation" --add audits:read
fp keys disable "audit automation"
```

गुप्त को बनाते समय स्टोर करें; इसे फिर से नहीं दिखाया जाएगा। एक प्रतिस्थापन बनाकर, उपभोक्ता को अपडेट करके, फिर पुरानी कुंजी को अक्षम करके घुमाएँ।

## मशीन कुंजियाँ

एक मशीन कुंजी स्थानीय सेवा को Cloud से जोड़ती है:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

एक जुड़ी हुई मशीन को दो क्षमताओं की आवश्यकता हो सकती है:

- `policies:pull` Cloud-प्रबंधित नीतियों को प्राप्त करने के लिए।
- `events:add` निर्णय और सत्र भेजने के लिए।

स्थिति इन्हें अलग से रिपोर्ट करती है क्योंकि एक काम कर सकता है जबकि दूसरा नहीं।

## सामान्य अनुमतियाँ

| अनुमति | अनुमति देता है |
| --- | --- |
| `events:add` | घटनाएँ भेजें |
| `events:read` | घटनाएँ और त्रुटियाँ पढ़ें |
| `evaluations:read` | सत्र और मूल्यांकन पढ़ें |
| `audits:read` / `audits:write` | ऑडिट की समीक्षा करें या प्रबंधित करें |
| `policies:read` / `policies:write` | नीतियों की समीक्षा करें या तैनात करें |
| `policies:pull` | मशीन नीति असाइनमेंट खींचें |
| `keys:create` / `keys:disable` | कुंजियाँ बनाएँ या अक्षम करें |
| `orgs:admin` | उदाहरण-स्तरीय संगठन प्रशासन; एक संगठन कुंजी को असाइन करने योग्य नहीं |

कुछ प्रशासनिक `fp fleet` और `fp guardrails` आदेशों के लिए API कुंजी के बजाय एक हस्ताक्षरित-इन उपयोगकर्ता सत्र की आवश्यकता होती है। उनका सहायता पाठ अनुरोध करने से पहले इसे बताता है।

<Warning>
  कभी भी अंतर्ग्रहण क्रेडेंशियल जैसे `AGENTEYE_KEY` या `AGENTEYE_API_KEY` को `FP_API_KEY` के रूप में पुन: उपयोग न करें। वे विभिन्न सिस्टम और अनुमतियों की सेवा करते हैं।
</Warning>
