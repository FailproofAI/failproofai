API कुंजियाँ एक संगठन से संबंधित होती हैं और स्पष्ट अनुमतियाँ रखती हैं। एजेंट इनजेशन, नीति डिलीवरी, मूल्यांकनकर्ता, CI स्वचालन और प्रशासनिक स्क्रिप्ट के लिए अलग-अलग कुंजियाँ उपयोग करें।

## कुंजी बनाएँ और घुमाएँ

<Tabs>
  <Tab title="Dashboard">
    1. **Administration → Keys** पर जाएँ, **new key** चुनें, और वर्कलोड का नाम दर्ज करें।
    2. अनुमति सेट चुनें और केवल तब व्यक्तिगत अनुमतियाँ समायोजित करें जब प्रीसेट अपर्याप्त हो।
    3. कुंजी बनाएँ और उसके एकबारी गुप्त को तुरंत कॉपी करें।
    4. बाद में कुंजी खोलें ताकि आप अनुदान अपडेट कर सकें, इसे अक्षम कर सकें, या गुप्त को पुनः उत्पन्न कर सकें।

    निर्माण ड्रॉअर वह जगह है जहाँ आप वर्कलोड द्वारा आवश्यक सबसे संकीर्ण अनुदान चुनते हैं।

    ![अनुमति प्रीसेट और व्यक्तिगत अनुदान के साथ नई API कुंजी ड्रॉअर।](/images/dashboard/key-create.png)

    निर्माण के बाद, कुंजी पृष्ठ स्थायी मेटाडेटा और प्रबंधन कार्य दिखाता है। एकबारी गुप्त फिर से नहीं दिखाया जाता है।

    ![API कुंजी पृष्ठ जो कुंजी अनुमतियाँ, निर्माण समय, और पुनः उत्पन्न करें और अक्षम करें कार्य दिखाता है।](/images/dashboard/api-keys.png)

    इस सूची का उपयोग करके नियमित रूप से अनुदान की समीक्षा करें और उन कुंजियों को अक्षम करें जो अब सक्रिय वर्कलोड से मेल नहीं खाती हैं।
  </Tab>
  <Tab title="CLI">
    ```bash
    fp keys create production-agents \
      --add events:add \
      --add policies:pull
    fp keys show production-agents
    fp keys update production-agents --add events:read
    fp keys regenerate production-agents --yes
    fp keys disable production-agents
    ```

    सुरक्षित रूप से create/regenerate आउटपुट को रीडायरेक्ट या कैप्चर करें; गुप्त एक बार दिया जाता है।
  </Tab>
</Tabs>

एक कनेक्टेड Failproof AI मशीन द्वारा आवश्यक दो अनुमतियाँ स्वतंत्र हैं:

- `events:add` घटनाएँ और सत्र डेटा भेजता है।
- `policies:pull` निर्दिष्ट नीति तैनाती प्राप्त करता है।

कुंजी गुप्त निर्माण या पुनः उत्पन्न होने पर दिखाई देते हैं। उन्हें एक गुप्त प्रबंधक में संग्रहीत करें और उन्हें ऑपरेटर की इंटरैक्टिव साख का पुनः उपयोग किए बिना घुमाएँ।

## अनुमति सूची

| क्षेत्र | अनुमतियाँ |
| --- | --- |
| घटनाएँ | `events:add`, `events:read` |
| कुंजियाँ | `keys:create`, `keys:read`, `keys:disable`, `keys:regenerate`; `keys:update` केवल मानव-सत्र के लिए है |
| उपयोगकर्ता | `users:create`, `users:read`, `users:update`, `users:delete` |
| मूल्यांकन | `evaluations:read`, `evaluations:trigger` |
| डैशबोर्ड | `dashboards:read`, `dashboards:write`, `dashboards:delete` |
| क्वेरीज़ | `queries:read`, `queries:write`, `queries:delete`, `queries:run` |
| सहायक | `agent:use` |
| सेटिंग | `settings:read`, `settings:write` |
| अलर्ट | `alerts:read`, `alerts:write` |
| समस्याएँ | `issues:read`, `issues:create`, `issues:close` |
| ऑडिट | `audits:read`, `audits:write` |
| नीतियाँ | `policies:read`, `policies:write`, `policies:pull` |
| उपयोग | `usage:read` |

`orgs:admin` उदाहरण ऑपरेटर के लिए आरक्षित है और किसी संगठन कुंजी या साधारण सदस्य को प्रदान नहीं किया जा सकता है। सेवानिवृत्त `incidents:*` और `alerts:ack` टोकन संगतता के लिए स्वीकृत हैं और वर्तमान `issues:*` अनुमतियों को सामान्य बनाते हैं।

अंतर्निहित अनुमति सेट `read-only`, `standard`, और `admin` हैं। `standard` मानव-केवल अनुदान को पढ़ने की अनुमतियों में मूल्यांकन ट्रिगरिंग, क्वेरी निष्पादन, समस्या प्रतिक्रिया, और सहायक उपयोग जोड़ता है। कुंजी निर्माण मानव-केवल अनुदान को हटाता है भले ही अनुमति सेट उन्हें शामिल करता हो।

<Warning>
  उदाहरण-स्कोप्ड कुंजियाँ `X-AgentEye-Org` हेडर के साथ संगठन का चयन कर सकती हैं। इसे बहु-संगठन तैनाती पर स्पष्ट रूप से सेट करें; चूक डिफ़ॉल्ट संगठन का चयन कर सकता है।
</Warning>
