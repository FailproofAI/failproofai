प्रशासन Failproof AI का Cloud भाग है। संगठन, सदस्य, API कुंजियाँ, org सेटिंग्स, और मीटर की गई खपत को सभी को Cloud कनेक्शन की आवश्यकता है।

<Note>
  Failproof AI बिना किसी खाते के भी चलता है। एक स्थानीय मशीन नीति को लागू करती है, अपना सत्र इतिहास डिस्क पर रखती है, [स्थानीय डैशबोर्ड](/hi/reference/local-dashboard) को `localhost:8020` पर परोसती है, और `failproofai audit` को बिना कहीं कुछ भेजे चलाती है। स्थानीय `collector` कुंजियों के लिए [मशीन कॉन्फ़िगरेशन](/hi/reference/events-and-configuration#machine-configuration) देखें। यदि आप Cloud का उपयोग नहीं कर रहे हैं तो इस अनुभाग के बाकी भाग को छोड़ें।
</Note>

## नियंत्रण कहाँ रहते हैं

<Tabs>
  <Tab title="Dashboard">
    Cloud साइडबार का **admin** समूह **policy editor**, **enforcement**, **usage**, **keys**, **users**, और **settings** रखता है।

    ![Cloud साइडबार का admin समूह policy editor, enforcement, usage, keys, users, और settings के साथ।](/images/dashboard/admin-navigation.png)
  </Tab>
  <Tab title="CLI">
    Cloud CLI को एक अलग टूल के रूप में इंस्टॉल करें, फिर साइन इन करें:

    ```bash
    uv tool install fp-cloud-cli
    fp login
    fp whoami
    fp usage
    ```

    वैश्विक विकल्प कमांड से पहले रखें, उदाहरण के लिए `fp --org reliability-team --json usage`।
  </Tab>
</Tabs>

## हस्ताक्षरित मानव, या API कुंजी

`fp` दो प्रमाणीकरण मोड में से एक में चलता है, और विभाजन यह तय करता है कि कौन से कमांड काम करते हैं। एक कमांड जो API कुंजी नहीं कर सकती, कनेक्शन खोलने से पहले इनकार करती है और कारण नाम देती है, बजाय 401 या 403 को खड़ा रहने देने के।

| कमांड | API कुंजी | अनुमति |
| --- | --- | --- |
| `fp whoami` | हाँ | कोई नहीं |
| `fp usage` | हाँ | `usage:read` |
| `fp keys list` / `show` | हाँ | `keys:read` |
| `fp keys create` | हाँ | `keys:create` |
| `fp keys disable` | हाँ | `keys:disable` |
| `fp keys regenerate` | हाँ | `keys:regenerate` |
| `fp keys update` | नहीं | `keys:update`, जो कोई कुंजी नहीं रख सकती |
| `fp users list` / `show` | हाँ | `users:read` |
| `fp users create` | हाँ | `users:create` |
| `fp users update` | हाँ | `users:update` |
| `fp users disable` / `enable` | हाँ | `users:delete` |
| `fp settings list` / `schema` | हाँ | `settings:read` |
| `fp settings set` | हाँ | `settings:write` |
| `fp orgs list` / `switch` / `current` / `perms` | नहीं | केवल हस्ताक्षरित सत्र |

`fp usage` एक रिपोर्टिंग स्क्रिप्ट को देने के लिए कमांड है: यह एक कुंजी के तहत बिना निरीक्षण के चलता है और केवल `usage:read` की आवश्यकता है।
