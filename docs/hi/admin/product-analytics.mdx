Failproof AI Cloud अपने रखरखाव कर्ताओं को अपने बारे में उपयोग टेलीमेट्री भेजता है **सॉफ्टवेयर के बारे में**। इसमें कभी आपके agents का डेटा शामिल नहीं होता। self-hosted install पर यह डिफ़ॉल्ट रूप से चालू होता है, और आप इसे बंद कर सकते हैं।

## क्या एकत्र किया जाता है

प्रत्येक event पाँच dimensions ले जाता है और कुछ भी नहीं जो किसी व्यक्ति की पहचान करता है:

| Dimension | उदाहरण | यह क्या है |
| --- | --- | --- |
| `product` | `agenteye` | कौन सा उत्पाद इसे भेजा |
| `component` | `dashboard`, `server`, `cli` | उत्पाद का कौन सा हिस्सा इसे भेजा |
| `app_version` | `0.0.1-beta.81` | आप जो build चला रहे हैं |
| `deployment_kind` | `self_hosted` | क्या यह ग्राहक install है, हमारा demo है, हमारा QA है, या dev machine है |
| `org_id` | एक UUID | कौन सा organization action हुआ, एक opaque identifier के रूप में |

इसके अतिरिक्त, events रिकॉर्ड करते हैं **क्या उपयोग किया गया था, कभी यह नहीं कि इसमें क्या था**: कौन सा page देखा गया (route pattern जैसे `/:org/sessions/:id` के रूप में, कभी असली URL नहीं), कितने filters किस तरह के लागू किए गए, क्या कोई action सफल रहा, और इसमें कितना समय लगा।

Slack app workspace connects और disconnects, account links, पूछे गए प्रश्न, पोस्ट किए गए charts, approval decisions, और fixed category द्वारा failures रिकॉर्ड करता है। इसमें कभी Slack workspace, user, या channel IDs, email, प्रश्न, उत्तर, SQL, या tokens शामिल नहीं होते।

### आपके organization का नाम

Opaque `org_id` के साथ, हम आपके organization का नाम, URL slug, और dashboard address एक बार रिकॉर्ड करते हैं, हर event पर नहीं बल्कि एक organization record पर। यह हमें बताता है कि adoption को देखते समय या आपने जो समस्या रिपोर्ट की थी उसकी जाँच करते समय कौन सा pattern किस account से संबंधित है। यह एक मात्र पहचान जानकारी है जो product आपके बारे में भेजता है।

### आपके उपयोग का कुल

Server प्रत्येक organization के metered usage totals रिपोर्ट करता है, वही संख्याएँ जो आप Usage page पर देखते हैं। ये केवल counts हैं: events, sessions, agents, environments, evaluation runs, scores, audit runs, saved queries, dashboards, alerts, issues, API keys, और members, साथ ही metering window की तारीखें। इसमें कोई identifiers, नाम, या query text नहीं होता है, और यह भले ही कोई भी sign in न हो।

## क्या कभी एकत्र नहीं किया जाता है

- **कोई prompts, model responses, या event content नहीं**, न text के रूप में, न prefix के रूप में, और न ही hash के रूप में
- **कोई session, agent, या trace identifiers नहीं**
- **कोई evaluator score names नहीं**
- **कोई error messages, exception text, या response bodies नहीं**, केवल एक status code और एक fixed list से category
- **कोई tool arguments, SQL, या query text नहीं**
- **कोई connected-app details नहीं**। MCP client को connect या revoke करना सर्वाधिक एक permission count भेजता है, कभी app का नाम या कोई token नहीं
- **कोई email addresses नहीं**
- **कोई referrer URLs या query strings नहीं**
- **कोई screen recording, DOM capture, या click और cursor tracking नहीं**

## self-hosted install पर इसे बंद करें

dashboard और server दोनों पर `DO_NOT_TRACK=1` सेट करें। वे अलग-अलग तय करते हैं, इसलिए इसे केवल एक पर सेट करने से दूसरा रिपोर्ट करता रहता है। परिवर्तन लागू करने के लिए server को restart करें।

आपकी release README अन्य opt-out settings और यह पुष्टि करने के लिए कि telemetry बंद है, कैसे करें इसका विवरण देता है।

## जब आप opt out करते हैं तब एक ping

यदि आप `DO_NOT_TRACK` के बजाय product setting के साथ opt out करते हैं, तो dashboard **एक anonymous ping** भेज सकता है जो रिकॉर्ड करता है, 1 in 1000 की probability के साथ प्रत्येक process start पर। यह हमें बताता है कि कितने operators telemetry को बंद करते हैं। इसमें कोई identifiers नहीं होते: कोई organization, user, hostname, URL, या IP नहीं, केवल product, component, version, deployment kind, और reason। एक opted-out server कुछ भी नहीं भेजता।

जब आप `DO_NOT_TRACK` का उपयोग करते हैं तो यह कभी नहीं भेजा जाता, जिसका कारण यह है कि यदि आपकी नीति किसी भी outbound telemetry को मना करती है तो वह उपयोग करने के लिए सेटिंग है।

## यह कहाँ जाता है

PostHog (`us.i.posthog.com`) पर TLS के over port 443 पर। यह एक hostname है, इसलिए आप इसे एकल egress rule के साथ भी block कर सकते हैं।
