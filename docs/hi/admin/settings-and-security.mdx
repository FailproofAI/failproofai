परिनियोजन-विशिष्ट परिचालन मानों और मॉडल संदर्भ-विंडो ओवरराइड के लिए सेटिंग्स का उपयोग करें। API या CLI के माध्यम से कोई मान बदलने से पहले सेटिंग्स स्कीमा का निरीक्षण करें।

## किसी संगठन की सेटिंग को बदलें

<Tabs>
  <Tab title="Dashboard">
    1. **Administration → Settings** पर जाएं, सेटिंग ग्रुप खोजें, और इसके विवरण और वर्तमान स्रोत को पढ़ें।
    2. मान को बदलें और सहेजें।
    3. मॉडल संदर्भ विंडो के लिए, मॉडल ओवरराइड जोड़ें या अपडेट करें और प्रभावी सीमा की पुष्टि करें।
    4. परिवर्तित मान पर निर्भर सत्रों और मेट्रिक्स को दोबारा जांचें।

    ![संगठन प्रमाणीकरण और परिचालन सेटिंग्स दिखाने वाला सेटिंग्स पृष्ठ।](/images/dashboard/settings.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp settings list
    fp settings schema
    fp settings set <key> --value <scalar>
    fp settings set alerts.email_default_recipients \
      --json-value '["oncall@example.com"]'
    ```

    `fp settings set --help` चलाएं ताकि इंस्टॉल की गई CLI द्वारा उपयोग किए जाने वाले मान प्रकार और पुष्टि ध्वज देख सकें।
  </Tab>
</Tabs>

## डेटा हैंडलिंग विकल्प

Failproof AI CLI को जोड़ने से डिफ़ॉल्ट रूप से ट्रांसक्रिप्ट भेजे जाते हैं क्योंकि ट्रेस और ऑडिट उनकी सामग्री पर निर्भर करते हैं। जब प्रॉम्प्ट, फ़ाइल सामग्री, या टर्मिनल इनपुट स्थानीय रहना चाहिए तो `--no-transcripts` का उपयोग करें; हुक गतिविधि और नीति निर्णय अभी भी रिपोर्ट किए जा सकते हैं।

स्थानीय अंतर्ग्रहण क्रेडेंशियल गैर-गुप्त डेमॉन सेटिंग्स से अलग से संग्रहीत किए जाते हैं और प्रतिबंधात्मक अनुमतियों के साथ लिखे जाते हैं। API कुंजियों को अभी भी उत्पादन रहस्यों के रूप में प्रबंधित किया जाना चाहिए।

## संगठन सेटिंग संदर्भ

सभी डैशबोर्ड-संपादन योग्य सेटिंग्स संगठन-स्कोप्ड हैं। परिनियोजन-व्यापी व्यवहार सर्वर पर्यावरण कॉन्फ़िगरेशन रहता है।

| कुंजी | डिफ़ॉल्ट | उद्देश्य |
| --- | --- | --- |
| `allowed_sign_ins` | `[]` | मौजूदा सदस्यों को सटीक ईमेल या `*@domain` तक सीमित करें; एक खाली सूची का अर्थ है कि कोई अतिरिक्त प्रतिबंध नहीं है। |
| `session_ttl_secs` | `86400` | डैशबोर्ड सत्र जीवनकाल; स्वीकृत सीमा 60 सेकंड से 30 दिन है। |
| `otp_ttl_secs` | `600` | OTP और जादुई-लिंक जीवनकाल; स्वीकृत सीमा 60–1800 सेकंड है। |
| `alerts.email_default_recipients` | `[]` | डिफ़ॉल्ट प्राप्तकर्ता जब कोई अलर्ट ईमेल चैनल उन्हें ओवरराइड न करे। |
| `alerts.slack_default_webhook` | खाली | डिफ़ॉल्ट Slack आने वाला-webhook URL। |
| `alerts.webhook_default_url` | खाली | डिफ़ॉल्ट सामान्य JSON webhook URL। |
| `alerts.webhook_signing_secret` | खाली | `X-AgentEye-Signature` हेडर के लिए उपयोग की जाने वाली HMAC-SHA256 कुंजी; रीड मास्क किए जाते हैं। |
| `alerts.enabled_channels` | email, Slack, webhook | संगठन-व्यापी चैनल प्रकार जो अलर्ट नियम भेज सकते हैं। |
| `default_user_permissions` | `standard` | नई निमंत्रणों के लिए पूर्वनिर्धारित नामित अनुमति सेट। |

`allowed_sign_ins` एक फ़िल्टर है, अनुदान नहीं: एक व्यक्ति पहले से ही संगठन सदस्य होना चाहिए। हर सदस्य को अनुमति देने के लिए एक खाली सूची का उपयोग करें; अकेली मान `*` अस्वीकार की जाती है। अलर्ट URL को लूपबैक विकास पतों को छोड़कर HTTPS का उपयोग करना चाहिए।

## सुरक्षा जांचसूची

- Cloud कनेक्शन के लिए HTTPS का उपयोग करें।
- कुंजियों को सबसे छोटी अनुमति सेट तक स्कोप करें।
- उत्पादन और गैर-उत्पादन वातावरण को अलग करें।
- रोलआउट से पहले ट्रांसक्रिप्ट और रिडैक्शन सेटिंग्स की समीक्षा करें।
- उपयोगकर्ता, कुंजी, और संगठन परिवर्तनों का ऑडिट करें।
- अपने परिनियोजन के लिए बैकअप, प्रतिधारण, और घटना प्रतिक्रिया आवश्यकताओं का परीक्षण करें।
