परिस्थिति-विशिष्ट परिचालन मानों और मॉडल संदर्भ-विंडो ओवरराइड के लिए सेटिंग्स का उपयोग करें। API या CLI के माध्यम से कोई मान बदलने से पहले सेटिंग्स स्कीमा का निरीक्षण करें।

## संगठन सेटिंग बदलें

<Tabs>
  <Tab title="Dashboard">
    1. **Administration → Settings** पर जाएं, सेटिंग समूह खोजें, और इसके विवरण और वर्तमान स्रोत को पढ़ें।
    2. मान बदलें और इसे सहेजें।
    3. मॉडल संदर्भ विंडो के लिए, मॉडल ओवरराइड जोड़ें या अपडेट करें और प्रभावी सीमा की पुष्टि करें।
    4. उन सत्रों और मेट्रिक्स को फिर से जांचें जो बदले गए मान पर निर्भर हैं।

    ![संगठन प्रमाणीकरण और परिचालन सेटिंग्स दिखाने वाला सेटिंग्स पृष्ठ।](/images/dashboard/settings.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp settings list
    fp settings schema
    fp settings set <key> --value <scalar>
    fp settings set alerts.email_default_recipients \
      --json-value '["oncall@example.com"]'
    ```

    स्थापित CLI द्वारा उपयोग किए जाने वाले मान प्रकार और पुष्टि झंडे के लिए `fp settings set --help` चलाएं।
  </Tab>
</Tabs>

## डेटा हैंडलिंग विकल्प

Failproof AI CLI को कनेक्ट करना डिफ़ॉल्ट रूप से ट्रांसक्रिप्ट भेजता है क्योंकि ट्रेस और ऑडिट उनके सामग्री पर निर्भर हैं। जब प्रॉम्प्ट, फाइल सामग्री, या टर्मिनल इनपुट स्थानीय रहना चाहिए तो `--no-transcripts` का उपयोग करें; हुक गतिविधि और नीति निर्णय अभी भी रिपोर्ट किए जा सकते हैं।

स्थानीय इनजेस्ट क्रेडेंशियल गैर-गोपनीय डेमॉन सेटिंग्स से अलग से संग्रहीत हैं और प्रतिबंधात्मक अनुमतियों के साथ लिखे गए हैं। API कुंजियां अभी भी उत्पादन रहस्यों के रूप में प्रबंधित की जानी चाहिए।

## संगठन सेटिंग संदर्भ

सभी डैशबोर्ड-संपादन योग्य सेटिंग्स संगठन-स्कोप्ड हैं। परिस्थिति-व्यापी व्यवहार सर्वर पर्यावरण कॉन्फ़िगरेशन रहता है।

| कुंजी | डिफ़ॉल्ट | उद्देश्य |
| --- | --- | --- |
| `allowed_sign_ins` | `[]` | मौजूदा सदस्यों को सटीक ईमेल या `*@domain` तक सीमित करें; खाली सूची का मतलब कोई अतिरिक्त प्रतिबंध नहीं है। |
| `session_ttl_secs` | `86400` | डैशबोर्ड सत्र आजीवन; स्वीकृत श्रेणी 60 सेकंड से 30 दिन है। |
| `otp_ttl_secs` | `600` | OTP और जादू-लिंक आजीवन; स्वीकृत श्रेणी 60–1800 सेकंड है। |
| `alerts.email_default_recipients` | `[]` | डिफ़ॉल्ट प्राप्तकर्ता जब कोई सतर्कता ईमेल चैनल उन्हें ओवरराइड नहीं करता है। |
| `alerts.slack_default_webhook` | खाली | डिफ़ॉल्ट Slack आने वाला-वेबहुक URL। |
| `alerts.webhook_default_url` | खाली | डिफ़ॉल्ट जेनेरिक JSON वेबहुक URL। |
| `alerts.webhook_signing_secret` | खाली | `X-AgentEye-Signature` हेडर के लिए उपयोग की जाने वाली HMAC-SHA256 कुंजी; पढ़ने को मुखौटा लगाया जाता है। |
| `alerts.enabled_channels` | ईमेल, Slack, वेबहुक | संगठन-व्यापी चैनल प्रकार जो सतर्कता नियम भेज सकते हैं। |
| `default_user_permissions` | `standard` | नई आमंत्रण के लिए पूर्वचयनित अनुमति समूह। |

`allowed_sign_ins` एक फिल्टर है, अनुदान नहीं: एक व्यक्ति पहले से ही एक संगठन सदस्य होना चाहिए। प्रत्येक सदस्य को अनुमति देने के लिए खाली सूची का उपयोग करें; नंगा मान `*` अस्वीकार कर दिया जाता है। लूपबैक विकास पते को छोड़कर, सतर्कता URL को HTTPS का उपयोग करना चाहिए।

## सुरक्षा चेकलिस्ट

- Cloud कनेक्शन के लिए HTTPS का उपयोग करें।
- कुंजियों को सबसे छोटे अनुमति समूह में स्कोप करें।
- उत्पादन और गैर-उत्पादन वातावरण को अलग करें।
- रोलआउट से पहले ट्रांसक्रिप्ट और रिडेक्शन सेटिंग्स की समीक्षा करें।
- उपयोगकर्ता, कुंजी, और संगठन परिवर्तन का ऑडिट करें।
- अपनी परिस्थिति के लिए बैकअप, प्रतिधारण, और घटना प्रतिक्रिया आवश्यकताओं का परीक्षण करें।
