संगठन सत्रों, मूल्यांकनों, ऑडिट, मुद्दों, अलर्ट, क्वेरी, डैशबोर्ड, उपयोगकर्ताओं और कुंजियों को अलग करते हैं। प्रशासनिक संसाधनों को बदलने से पहले सक्रिय संगठन की पुष्टि करें।

## सदस्यों और संगठनों का प्रबंधन करें

<Tabs>
  <Tab title="Dashboard">
    1. संगठनों को बदलने के लिए Cloud साइडबार के शीर्ष पर संगठन स्विचर का उपयोग करें।
    2. सदस्यों को खोजने या सक्रिय स्थिति और भूमिका के आधार पर फ़िल्टर करने के लिए **Administration → Users** पर जाएं।
    3. **नया उपयोगकर्ता** चुनें, ईमेल दर्ज करें, अनुमति सेट चुनें, और यदि आवश्यक हो तो ओवरराइड को समायोजित करें।
    4. बाद में एक उपयोगकर्ता को खोलें ताकि आप अनुदान को अपडेट कर सकें, साइन-इन को अक्षम कर सकें, या खाते को फिर से सक्षम कर सकें।

    ![सदस्य ईमेल पते, अनुमति सेट, और संपादन तथा अक्षम नियंत्रण दिखाने वाला उपयोगकर्ता पृष्ठ।](/images/dashboard/users.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp orgs list
    fp orgs switch reliability-team
    fp orgs current
    fp orgs perms

    fp users create engineer@example.com --permission-set standard
    fp users show engineer@example.com
    fp users update engineer@example.com --add audits:write
    fp users disable engineer@example.com
    fp users enable engineer@example.com
    ```
  </Tab>
</Tabs>

प्रशासक उपयोगकर्ताओं को बना सकते हैं, अपडेट कर सकते हैं, अक्षम कर सकते हैं, और फिर से सक्षम कर सकते हैं, फिर उनकी भूमिका के लिए उपयुक्त अनुमति सेट असाइन कर सकते हैं। API अक्षम करने के लिए एक डिलीट ऑपरेशन का उपयोग करता है, लेकिन यह खाते या इसके सदस्यता रिकॉर्ड को हटाता नहीं है।

<Warning>
  किसी उपयोगकर्ता को अक्षम करने से केवल वर्तमान में चुने गए संगठन में नहीं, बल्कि प्रत्येक संगठन में साइन इन करने से उस पहचान को ब्लॉक कर दिया जाता है। फिर से सक्षम करने से सदस्य की वैश्विक साइन-इन और इस संगठन में अनुमतियों को बहाल किया जाता है।
</Warning>

<Tip>
  सेवा खातों को एक कार्यभार और मालिक से जुड़े वर्णनात्मक नाम दें। संगठनों के बीच या लोगों और मशीनों के बीच कुंजियों को साझा करने से बचें।
</Tip>
