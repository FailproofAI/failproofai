संगठन सत्र, मूल्यांकन, ऑडिट, समस्याएं, अलर्ट, प्रश्न, डैशबोर्ड, उपयोगकर्ता और कुंजियों को अलग करते हैं। प्रशासनिक संसाधनों को बदलने से पहले सक्रिय संगठन की पुष्टि करें।

## सदस्यों और संगठनों का प्रबंधन करें

<Tabs>
  <Tab title="Dashboard">
    1. संगठनों को बदलने के लिए Cloud साइडबार के शीर्ष पर संगठन स्विचर का उपयोग करें।
    2. सदस्यों को खोजने या सक्रिय स्थिति और भूमिका के अनुसार फ़िल्टर करने के लिए **Administration → Users** पर जाएं।
    3. **new user** चुनें, ईमेल दर्ज करें, एक अनुमति सेट चुनें, और यदि आवश्यक हो तो ओवरराइड को समायोजित करें।
    4. अनुदान अपडेट करने, साइन-इन अक्षम करने, या खाते को फिर से सक्षम करने के लिए बाद में एक उपयोगकर्ता खोलें।

    ![Users पृष्ठ जो सदस्य ईमेल पते, अनुमति सेट, और संपादन और अक्षम नियंत्रण दिखाता है।](/images/dashboard/users.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp orgs list
    fp orgs switch reliability-team
    fp orgs current
    fp orgs perms

    fp users create engineer@example.com --permission-set standard
    fp users show engineer@example.com
    fp users update engineer@example.com --add audits:write
    fp users disable engineer@example.com
    fp users enable engineer@example.com
    ```
  </Tab>
</Tabs>

प्रशासक उपयोगकर्ताओं को बना सकते हैं, अपडेट कर सकते हैं, अक्षम कर सकते हैं और फिर से सक्षम कर सकते हैं, फिर उनकी भूमिका के लिए उपयुक्त अनुमति सेट असाइन कर सकते हैं। API अक्षम करने के लिए एक delete ऑपरेशन का उपयोग करता है, लेकिन यह खाते या इसके सदस्यता रिकॉर्ड को हटाता नहीं है।

<Warning>
  किसी उपयोगकर्ता को अक्षम करने से केवल वर्तमान में चयनित संगठन के बजाय हर संगठन में उस पहचान को साइन इन करने से रोका जाता है। पुनः सक्षम करने से वैश्विक साइन-इन और इस संगठन में सदस्य की अनुमतियां बहाल होती हैं।
</Warning>

<Tip>
  सेवा खातों को एक कार्यभार और मालिक से जुड़े वर्णनात्मक नाम दें। संगठनों के बीच या लोगों और मशीनों के बीच कुंजियां साझा करने से बचें।
</Tip>
