संगठन सत्र, मूल्यांकन, ऑडिट, समस्याएं, सचेतनाएं, प्रश्न, डैशबोर्ड, उपयोगकर्ता और कुंजियों को अलग रखते हैं। प्रशासनिक संसाधनों को बदलने से पहले सक्रिय संगठन की पुष्टि करें।

## सदस्यों और संगठनों का प्रबंधन करें

<Tabs>
  <Tab title="Dashboard">
    1. Cloud साइडबार के शीर्ष पर संगठन स्विचर का उपयोग करके संगठनों को बदलें।
    2. सदस्यों को खोजने या सक्रिय स्थिति और भूमिका के आधार पर फ़िल्टर करने के लिए **Administration → Users** पर जाएं।
    3. **नया उपयोगकर्ता** चुनें, ईमेल दर्ज करें, एक अनुमति सेट चुनें, और यदि आवश्यक हो तो ओवरराइड को समायोजित करें।
    4. बाद में किसी उपयोगकर्ता को खोलें ताकि अनुदान अपडेट कर सकें, साइन-इन अक्षम कर सकें, या खाते को फिर से सक्षम कर सकें।

    ![Users पृष्ठ जो सदस्य ईमेल पते, अनुमति सेट, और संपादन और अक्षम नियंत्रण दिखा रहा है।](/images/dashboard/users.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp orgs list
    fp orgs switch reliability-team
    fp orgs current
    fp orgs perms

    fp users create engineer@example.com --permission-set standard
    fp users show engineer@example.com
    fp users update engineer@example.com --add audits:write
    fp users disable engineer@example.com
    fp users enable engineer@example.com
    ```
  </Tab>
</Tabs>

प्रशासक उपयोगकर्ताओं को बना सकते हैं, अपडेट कर सकते हैं, अक्षम कर सकते हैं, और फिर से सक्षम कर सकते हैं, फिर उनकी भूमिका के लिए उपयुक्त अनुमति सेट निर्दिष्ट कर सकते हैं। API अक्षम करने के लिए एक डिलीट ऑपरेशन का उपयोग करता है, लेकिन यह खाते या उसके सदस्यता रिकॉर्ड को हटाता नहीं है।

<Warning>
  किसी उपयोगकर्ता को अक्षम करना उस पहचान को केवल वर्तमान में चयनित संगठन में नहीं, बल्कि प्रत्येक संगठन में साइन इन करने से रोकता है। फिर से सक्षम करने से वैश्विक साइन-इन और इस संगठन में सदस्य की अनुमतियां बहाल हो जाती हैं।
</Warning>

<Tip>
  सेवा खातों को एक कार्यभार और मालिक से जुड़े वर्णनात्मक नाम दें। संगठनों के बीच या लोगों और मशीनों के बीच कुंजियों को साझा करने से बचें।
</Tip>
