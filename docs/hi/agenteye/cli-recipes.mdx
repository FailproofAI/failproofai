सेशन, इवेंट, और इवैलुएशन डेटा को सीधे एक स्क्रिप्ट या कोडिंग एजेंट से खींचें (और पुनः-इवैलुएशन ट्रिगर करें), जिसमें stdout पर स्वच्छ JSON हो जो सीधे `jq` में पाइप करता है। ये रेसिपीज़ Failproof AI Observability के डेटा को एक टर्मिनल उपयोगकर्ता या AI कोडिंग एजेंट (Claude Code, Cursor) के लिए कुछ ऐसा बनाते हैं जिसे वे क्वेरी और ऑटोमेट कर सकें, डैशबोर्ड के माध्यम से क्लिक किए बिना।

नीचे दिए गए पैटर्न Failproof AI Observability CLI (`agenteye`) के लिए कॉपी-पेस्ट के लिए तैयार हैं। इंस्टॉलेशन, ऑथेंटिकेशन, और पूर्ण विकल्प सूची के लिए [CLI](/hi/agenteye/cli) देखें; `agenteye -h` या `agenteye <command> -h` चलाएं अंतर्निहित सहायता के लिए।

## गोल्डन नियम

1. **ग्लोबल विकल्प कमांड से *पहले* जाते हैं।** `agenteye --json sessions` सही है; `agenteye sessions --json` नहीं है। ग्लोबल्स हैं `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, `--no-color`।
2. **जब भी आप आउटपुट को पार्स करें `--json` पास करें।** डेटा **stdout** पर JSON के रूप में जाता है; मानव स्थिति और त्रुटियां **stderr** पर जाती हैं, इसलिए stdout `jq` में पाइप करने के लिए स्वच्छ रहता है।
3. **stderr टेक्स्ट के बजाय exit code पर ब्रांच करें**: `0` ठीक है · `1` अप्रत्याशित त्रुटि · `2` बुरे तर्क · `3` डैशबोर्ड तक नहीं पहुंच सकता · `4` लॉगिन नहीं है या समाप्त · `5` अनुमति गायब · `6` संसाधन नहीं मिला।
4. **`-h` के साथ खोजें।** प्रत्येक कमांड अपने फ़िल्टर, वैल्यू फॉर्मेट, और JSON आकार को दस्तावेज़ करता है।

## एकबारी सेटअप

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com   # ताकि आप --base-url दोहराएं नहीं
agenteye login --email you@example.com                       # ईमेल किए गए कोड को पेस्ट करें; ~24h वैध
```

## काम करने से पहले auth की पुष्टि करें

`whoami` कभी गायब या समाप्त सेशन पर त्रुटि नहीं देता; यह इसके बजाय `logged_in:false` रिपोर्ट करता है, इसलिए एक एजेंट सुरक्षित रूप से auth स्थिति को जांच सकता है। (यदि कोई base URL सेट नहीं है या डैशबोर्ड तक नहीं पहुंचा जा सकता है तो यह अभी भी गैर-शून्य exit कर सकता है।)

```bash
if [ "$(agenteye --json whoami | jq -r .logged_in)" != "true" ]; then
  echo "Not authenticated. Run: agenteye login" >&2; exit 1
fi
```

## विफल या कम-स्कोरिंग सेशन खोजें

```bash
# पिछले 24h में सेशन जिनका evaluation एरर किया
agenteye --json sessions --since 24h --status error | jq -r '.sessions[].session_id'

# evaluations स्कोरिंग <= 0.5 helpfulness पर, एक agent के लिए
agenteye --json evals --agent-id checkout-bot --score helpfulness:..0.5 \
  | jq '.evaluations[] | {session_id, scores}'
```

स्कोर फ़िल्टरिंग **`evals`** पर रहती है, न कि `sessions`। `--score KEY:MIN..MAX` दोहराई जा सकती है और AND-संयुक्त है; किसी भी सीमा वैकल्पिक है (`..0.5` का अर्थ है ≤ 0.5, `0.9..` का अर्थ है ≥ 0.9)। आप प्रति request 20 स्कोर फ़िल्टर तक पास कर सकते हैं; अधिक HTTP 400 रिटर्न करता है। `sessions` `--env`, `--status`, `--agent-id`, `--session-id`, और समय-सीमा फ़िल्टर को `evals` के साथ साझा करता है, लेकिन `--score` नहीं है।

## एक सेशन अंत से अंत तक पढ़ें

कोई एक `session show` कमांड नहीं है। event trail को सेशन के evaluation के साथ संयोजित करें:

```bash
# सेशन का नवीनतम evaluation (status + scores)
agenteye --json evals --session-id run-001 | jq '.evaluations[0] | {status, scores}'

# run में प्रत्येक event (एक पूर्ण sweep के लिए --limit बढ़ाएं)
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'

# सिर्फ एक session में tool calls (raw payload प्राप्त करने के लिए --full आवश्यक है)
agenteye --json events --full --session-id run-001 --event-type tool_use,tool_result --all \
  | jq '.events[].payload'
```

> **नोट:** डिफ़ॉल्ट रूप से, `events` एक तेज़, payload-मुक्त फ़ीड पढ़ता है। प्रत्येक event एक सर्वर-कंप्यूटेड वन-लाइन `summary` प्लस `is_error` और टोकन काउंट जैसे फ़्लैग ले जाता है, लेकिन `payload` `{}` के रूप में वापस आता है। raw payload खींचने के लिए, `--full` (या `--fields payload`) जोड़ें। पूर्ण फ़ीड बड़े पैमाने पर धीमी है, इसलिए इसे बंधी रखें: `--full` को एक एकल `--session-id` के साथ जोड़ी।

## सब कुछ लाएं (pagination)

परिणाम सबसे नए-पहले और cursor-paginated हैं।

```bash
# एकबारी: 200-पंक्ति पृष्ठों में 500 पंक्तियों तक लाएं
agenteye --json events --session-id run-001 --limit 500 --all > events.json

# मैनुअल paging: next_cursor को वापस फ़ीड करें
page=$(agenteye --json events --limit 100)
cursor=$(echo "$page" | jq -r '.next_cursor // empty')
[ -n "$cursor" ] && agenteye --json events --limit 100 --cursor "$cursor"
```

## --fields के साथ आउटपुट को स्लिम करें

कम करने के लिए keys को प्रतिबंधित करें (तालिका और `--json` दोनों में) एक एजेंट को जो पढ़ना चाहिए।

```bash
agenteye --json sessions --since 7d --fields session_id,status,scores | jq -c '.sessions[]'
agenteye --json events --session-id run-001 --fields ts,event_type --all
```

अज्ञात field names को अस्वीकार किया जाता है (exit `2`) वैध सूची के साथ, field names खोजने का एक सस्ता तरीका।

## वैध फ़िल्टर values खोजें

```bash
agenteye --json list envs | jq -r '.values[]'           # --env के लिए values
agenteye --json list tools | jq -r '.values[]'          # tool नाम; agents, models, event_types भी, …
agenteye --json list score_filters | jq -r '.values[]'  # --score KEY:MIN..MAX के लिए वैध KEY
```

## अपना org चुनें (multi-tenant)

यदि आप एक से अधिक org से संबंधित हैं, login पर सक्रिय tenant चुनें (यह सहेजा हुआ है):

```bash
agenteye login --org acme --email you@corp.com   # login के समान step में tenant सेट करें
agenteye --json orgs list | jq -r '.orgs[].org_slug'
agenteye --org globex --json sessions --since 24h   # एक कमांड के लिए override करें
```

`--org` के बिना एक multi-org login गैर-शून्य exit करता है और चुनने के लिए orgs प्रिंट करता है।

## SDK/collector के लिए API key provision करें

```bash
# secret ONCE प्रिंट किया जाता है, --json के साथ यह .key field है
key=$(agenteye --json keys create ci-bot --add events:read.add | jq -r '.key')
agenteye keys regenerate ci-bot --yes    # rotate; agenteye keys disable ci-bot --yes को revoke करें
```

## एक saved या ad-hoc query चलाएं

```bash
agenteye --json query run --sql "select count(*) from analytics.events" | jq '.rows'
agenteye --json query run errs --arg prod | jq '.rows'   # एक saved query + एक positional $1
```

## एक incident को non-interactively triage करें

```bash
id=$(agenteye --json incidents list --state firing | jq -r '.incidents[0].id')
agenteye incidents ack "$id"
agenteye incidents assign "$id" --assignee you@corp.com
agenteye incidents resolve "$id" --yes
```

> **नोट:** Mutations `--json` के तहत अपना confirmation prompt auto-skip करते हैं या जब stdin TTY नहीं है, इसलिए agents कभी hang नहीं करते; कहीं और स्पष्ट रूप से skip करने के लिए `--yes`/`-y` पास करें।

## एक script में exit-code handling

```bash
out=$(agenteye --json sessions --since 1h) || code=$?
case "${code:-0}" in
  0) echo "$out" | jq '.sessions | length' ;;
  4) echo "Session expired - run 'agenteye login'." >&2 ;;
  5) echo "Missing permission (ask an admin for evaluations:read)." >&2 ;;
  3) echo "Dashboard unreachable - check the URL." >&2 ;;
  *) echo "Unexpected error (exit ${code})." >&2 ;;
esac
```

## JSON आउटपुट आकार

| कमांड | stdout JSON (`--json` के साथ) |
|---|---|
| `whoami` | `{"logged_in": true, "id", "email", "is_instance_admin", "active_org", "permissions": [...], "memberships": [...]}` या `{"logged_in": false}` |
| `orgs list` | `{"active_org", "orgs": [{"org_slug","org_name","permission_set","permissions"}]}` |
| `events` | `{"events": [...], "next_cursor": <cursor या null>}` |
| `evals` | `{"evaluations": [...], "next_cursor": <cursor या null>}` |
| `sessions` | `{"sessions": [...], "next_cursor": <cursor या null>}` |
| `errors` | `{"errors": [...], "next_cursor": <cursor या null>}` |
| `list <kind>` | `{"kind", "values": [...]}` |
| `keys list` / `keys create` | `{"keys": [...]}` / `{id, name, permissions, created_at, key}` (`key` एक बार दिखाया जाता है) |
| `query run` | `{columns: [{name,type}], rows: [[...]], truncated, elapsed_ms}` |
| `users list` / `settings list` | `{"users": [...]}` / `{"settings": [...]}` |
| `alerts list` / `incidents list` | `{"alerts": [...]}` / `{"incidents": [...]}` |
| create/update/delete (कोई भी) | resource object, या deletes के लिए `{"deleted": true, "id"}` |
| failure (कोई भी, `--json` के साथ) | `{"error": "...", "exit_code": <n>, "status"?: <http>, "hint"?: "..."}` stdout पर |

- प्रत्येक **event** item (`events`): `id, session_id, agent_id, event_type, ts, payload, environment, summary, is_error, error_type, output_tokens, context_window, context_fill`। ध्यान दें कि `payload` `{}` है जब तक आप `--full` (या `--fields payload`) के साथ पूर्ण फ़ीड का अनुरोध न करें।
- प्रत्येक **evaluation** item (`evals`): `id, session_id, agent_id, environment, status, scores, reasoning, summary, error, attempt_count, duration_ms, completed_at, created_at`।
- प्रत्येक **session** item (`sessions`): `session_id, agent_id, environment, status, scores, event_count, started_at, last_event_at, first_event_id, last_event_id, latest_evaluation`।

प्रत्येक कमांड का `--fields` ठीक अपने स्वयं की item के field names स्वीकार करता है। `sessions` और `evals` के बीच सेट भिन्न है, इसलिए एक के लिए वैध नाम दूसरे द्वारा अस्वीकार किया जा सकता है।
