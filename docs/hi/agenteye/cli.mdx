Failproof AI Observability को टर्मिनल या स्क्रिप्ट से पूरी तरह चलाएं: कोई डैशबोर्ड राउंड-ट्रिप नहीं। `agenteye` CLI आपके डेटा (सेशन, इवेंट लॉग, इवैलुएशन) को क्वेरी करता है और आपके org को प्रबंधित करता है (API कुंजियाँ, उपयोगकर्ता, सेटिंग्स, अलर्ट, इंसिडेंट, सेव किए गए क्वेरी), इसलिए इसका उपयोग करें जब आप एक चेक को ऑटोमेट करना चाहते हैं, CI में Observability को जोड़ना चाहते हैं, या एक कोडिंग एजेंट को प्रोडक्शन का निरीक्षण करने देना चाहते हैं। हर कमांड `--json` फ़्लैग को सपोर्ट करता है, इसलिए यह आपके लिए प्रॉम्प्ट पर या कोडिंग एजेंट (Claude Code, Cursor) द्वारा शेल आउट और परिणाम पार्स करने के लिए समान रूप से अच्छी तरह काम करता है।

एक बाइनरी के साथ आप कर सकते हैं:

- **अपना डेटा पढ़ें**: `sessions`, `events`, `evals`, `errors` (समय, एजेंट, env, स्कोर द्वारा फ़िल्टर करें)।
- **अपने org को प्रबंधित करें**: `keys`, `users`, `settings`, `alerts`, `incidents`।
- **एनालिटिक्स चलाएं**: सेव किए गए SQL और एक एड-हॉक क्वेरी रनर (`query`)।
- **AI असिस्टेंट से पूछें**: वही रीड-ऑनली एनालिस्ट जिससे आप डैशबोर्ड में चैट करते हैं (`agent`)।

> **नोट:** यह `agenteye` CLI है, कलेक्टर डेमॉन (`agenteye-collector`) से एक अलग टूल। CLI आपके डैशबोर्ड से बात करता है; कलेक्टर सर्वर को इवेंट भेजता है।

## क्विकस्टार्ट

कुछ भी न होने से लेकर आपके पहले परिणाम तक चार लाइनों में। CLI को अपने डैशबोर्ड पर पॉइंट करें, साइन इन करें, पुष्टि करें कि आप कौन हैं, फिर पिछले एक दिन के रन्स को खींचें:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # emailed 6-digit code
agenteye whoami                                                                  # confirm user + active org
agenteye --json sessions --since 24h                                             # one row per agent run, last 24h
```

वह अंतिम कमांड सबसे हाल के सेशन का एक JSON ऑब्जेक्ट प्रिंट करता है (सबसे नया पहले, डिफ़ॉल्ट रूप से 50 तक सीमित)। इसे `jq` में पाइप करें इसे स्लाइस करने के लिए, या `--json` ड्रॉप करें एक बॉक्सबद्ध, रंगीन टेबल के लिए। प्रत्येक पंक्ति रन की स्थिति और, यदि एक इवैलुएटर ने इसे स्कोर किया है, तो इसके मेट्रिक स्कोर (यहाँ संक्षिप्त) ले जाती है:

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

इस पृष्ठ के बाकी हिस्से प्रत्येक टुकड़े को समझाते हैं: [अलग से स्थापना](#installation), [साइन इन करना](#authentication), [कॉन्फ़िगरेशन](#configuration), [ग्लोबल कन्वेंशन](#global-options--conventions) जो हर कमांड साझा करता है, और [पूर्ण कमांड संदर्भ](#command-reference)।

## स्थापना

CLI एक सार्वजनिक PyPI पैकेज है जिसका नाम **`agenteye`** है। इसे एक अलग-थलग पर्यावरण में स्थापित करें ताकि इसके हमेशा अपने dependencies हों:

```bash
pipx install agenteye
# or
uv tool install agenteye
```

इसे Python 3.10+ की आवश्यकता है। स्थापित कमांड **`agenteye`** है:

```bash
agenteye --version
agenteye --help
```

> **नोट:** Failproof AI Observability Python SDK भी `agenteye` डिस्ट्रिब्यूशन नाम का उपयोग करता है। CLI को `pipx` या `uv tool` के साथ स्थापित करना (साझा virtualenv में `pip install` के बजाय) दोनों को टकराने से बचाता है। एक साधारण `pip install agenteye` ठीक है केवल अगर SDK उसी पर्यावरण में स्थापित नहीं है।

## प्रमाणीकरण

CLI **डैशबोर्ड** को एक ईमेल किए गए वन-टाइम कोड के साथ प्रमाणित करता है:

```bash
agenteye login --email you@example.com
# A 6-digit code is emailed to you; paste it at the prompt.
```

सेशन टोकन `~/.agenteye/cli.json` में संग्रहीत होता है (केवल आपके द्वारा पढ़ने योग्य, मोड `0600`) और डिफ़ॉल्ट रूप से 24 घंटे के लिए वैध है। जब यह समाप्त हो जाता है, तो `agenteye login` फिर से चलाएं।

```bash
agenteye whoami     # show the current user, active org, and permissions
agenteye logout     # revoke the session and clear the stored token
```

`whoami` कभी भी एक लापता या समाप्त सेशन पर त्रुटि नहीं देता; यह इसके बजाय `logged_in: false` रिपोर्ट करता है, इसलिए एक स्क्रिप्ट या एजेंट प्रमाणन स्थिति को सुरक्षित रूप से जांच सकता है (अगर कोई बेस URL सेट नहीं है या डैशबोर्ड अप्राप्य है तो यह अभी भी गैर-शून्य एक्सिट कर सकता है)।

**आवश्यकताएं:** आपका ईमेल डैशबोर्ड में साइन इन करने के लिए अनुमत होना चाहिए (अपने Failproof AI Observability एडमिनिस्ट्रेटर से पूछें), और डैशबोर्ड इसके बेस URL पर पहुंचने योग्य होना चाहिए ([कॉन्फ़िगरेशन](#configuration) देखें)। यदि आप एक कोड का अनुरोध करते हैं और कोई नहीं आता है, तो आपका ईमेल संभवतः अभी तक डैशबोर्ड एक्सेस के लिए सक्षम नहीं है।

## अपना org चुनें (मल्टी-टेनेंट)

यदि आपका खाता एक से अधिक org से संबंधित है, तो **साइन इन पर** सक्रिय को चुनें; यह सेव किया जाता है और हर बाद की कमांड के लिए उपयोग किया जाता है:

```bash
agenteye login --org acme           # authenticate and set the active tenant in one step
agenteye orgs list                  # the orgs you can access (the active one is marked)
agenteye orgs switch globex         # change the saved default
agenteye --org globex sessions      # override for a single command
```

यदि आप बिल्कुल एक org से संबंधित हैं तो यह स्वचालित रूप से चुना जाता है और आप `--org` को पूरी तरह नजरअंदाज कर सकते हैं। यदि आप कई से संबंधित हैं और एक नहीं चुनते हैं, तो CLI उन्हें सूचीबद्ध करता है और आपको `--org <slug>` के साथ फिर से चलाने के लिए कहता है। सक्रिय org हर अनुरोध पर डैशबोर्ड को भेजा जाता है, और आपकी अनुमतियां **प्रति org** हल की जाती हैं; `agenteye whoami` सक्रिय org, इसमें आपकी अनुमतियां, और सभी आपकी सदस्यताएं दिखाता है।

## कॉन्फ़िगरेशन

| सेटिंग | फ़्लैग | पर्यावरण चर | डिफ़ॉल्ट |
|---|---|---|---|
| डैशबोर्ड बेस URL | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **आवश्यक** (कोई डिफ़ॉल्ट नहीं) |
| सक्रिय org/tenant | `--org` | `AGENTEYE_ORG` | साइन इन पर चुना गया; `~/.agenteye/cli.json` में सेव किया गया |
| सेशन टोकन | `--token` | `AGENTEYE_CLI_TOKEN` | `~/.agenteye/cli.json` से |
| JSON आउटपुट | `--json` | `AGENTEYE_CLI_JSON` | बंद |
| TLS सत्यापन छोड़ें | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | बंद (साइन इन पर सेव किया गया) |
| अनुरोध टाइमआउट (सेकंड) | `--timeout` | _(कोई नहीं)_ | 30 |
| उपयोग टेलीमेट्री अक्षम करें | _(कोई नहीं)_ | `AGENTEYE_ANALYTICS_DISABLED` (या `DO_NOT_TRACK`) | टेलीमेट्री वर्तमान में अक्षम है; कुछ नहीं भेजा जाता |

रेज़ॉल्यूशन क्रम **फ़्लैग → पर्यावरण चर → कॉन्फ़िग फ़ाइल** है। कोई डिफ़ॉल्ट नहीं है; आपको CLI को अपने डैशबोर्ड पर पॉइंट करना चाहिए, या तो प्रति-कमांड (`--base-url https://agenteye.example.com`) या एक बार पर्यावरण के माध्यम से (यह आपके पहले `login` के बाद भी सेव किया जाता है):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

कॉन्फ़िगरेशन निर्देशिका `AGENTEYE_HOME` को सम्मान करती है (SDK और कलेक्टर द्वारा उपयोग की जाने वाली एक ही कन्वेंशन); यदि सेट है, `cli.json` `$AGENTEYE_HOME/cli.json` में रहती है।

### Self-signed या आंतरिक TLS

यदि आपका डैशबोर्ड HTTPS पर एक self-signed या आंतरिक सर्टिफिकेट के साथ परोसा जाता है (उदाहरण के लिए, एक कच्चा लोड-बैलेंसर hostname), TLS सत्यापन इसे एक `CERTIFICATE_VERIFY_FAILED` त्रुटि के साथ अस्वीकार करता है। सर्टिफिकेट सत्यापन छोड़ने के लिए `--insecure` पास करें:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` **साइन इन करते समय `cli.json` में सेव किया जाता है**, इसलिए बाद की कमांड स्वचालित रूप से सत्यापन छोड़ देते हैं; आपको फ़्लैग को दोहराना नहीं पड़ता। एक वन-ऑफ सत्यापित कॉल के लिए `--secure` पास करें, या अपने अगले साइन इन पर सत्यापन को वापस सेव करें। CLI डैशबोर्ड से संपर्क करते समय किसी भी कमांड से पहले stderr में एक चेतावनी प्रिंट करता है जबकि सत्यापन अक्षम है। सत्यापन छोड़ना man-in-the-middle हमलों के खिलाफ सुरक्षा को हटाता है; इस पर भरोसा करने से पहले सुनिश्चित करें कि आप अपने डैशबोर्ड के लिए नेटवर्क पथ पर विश्वास करते हैं (VPN, निजी सबनेट, आदि)।

## टेलीमेट्री और गोपनीयता

> **नोट:** भेजी गई CLI **आज कोई उपयोग टेलीमेट्री नहीं भेजती।** एक मास्टर किल स्विच चालू है, इसलिए आपके पर्यावरण की परवाह किए बिना कुछ भी प्रेषित नहीं होता है। नीचे दिया गया अनुभाग opt-out क्षमता का वर्णन करता है यदि और जब टेलीमेट्री कभी सक्षम हो जाए।

भले ही सक्षम हो, टेलीमेट्री **केवल गुमनाम उपयोग एनालिटिक्स** होगी, कभी आपका एजेंट, सेशन, या इवेंट डेटा नहीं:

- **कोई एजेंट, सेशन, या इवेंट डेटा कभी भी आपके infrastructure को छोड़ नहीं देता।** केवल CLI उपयोग रिपोर्ट किया जाएगा: कमांड और सबकमांड नाम (जैसे `keys create`), आपके द्वारा उपयोग किए गए flags के **नाम** (कभी उनके मान नहीं), सफलता/exit स्थिति, और अवधि, साथ ही mutations के लिए एक प्रति-action इवेंट (जैसे `api_key_created`, `query_run`) केवल स्थिर नाम/enums और coarse काउंट ले जाते हुए। आपका डैशबोर्ड URL, सेशन टोकन, ईमेल, org slug, संसाधन ids, SQL, key secrets, और क्वेरी फ़िल्टर **कभी नहीं** भेजे जाएंगे। ऑपरेटर्स को केवल एक opaque आंतरिक id द्वारा पहचाना जाएगा, कभी ईमेल द्वारा नहीं।
- टेलीमेट्री सक्षम होने से पहले ही opt out करें `AGENTEYE_ANALYTICS_DISABLED=1` को CLI के पर्यावरण में सेट करके (CLI क्रॉस-टूल `DO_NOT_TRACK=1` कन्वेंशन को भी सम्मान करता है)। यह टेलीमेट्री को चालू करने के क्षण लागू होता है, इसलिए एक गोपनीयता-सचेत पर्यावरण स्थायी रूप से opted out रह सकता है।
- यदि टेलीमेट्री सक्षम किया गया था, तो CLI सीधे PostHog (`https://us.i.posthog.com`) को भेजेगा; उस होस्ट को ब्लॉक किए गए एक मशीन चुपचाप कुछ नहीं भेजेगी और CLI अप्रभावित होगी।

## ग्लोबल विकल्प और कन्वेंशन

इसे एक बार पढ़ें; यह हर कमांड पर लागू होता है।

- **ग्लोबल विकल्प कमांड से BEFORE जाते हैं।** `agenteye --json sessions` सही है; `agenteye sessions --json` एक उपयोग त्रुटि है। ग्लोबल्स हैं `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, और `--no-color`।
- **`--json` stdout को शुद्ध JSON प्रिंट करता है, और कुछ नहीं।** मानव स्थिति लाइनें, चेतावनियां, और त्रुटियां **stderr** पर जाती हैं, इसलिए एक `--json` stdout कैप्चर `jq` में पाइप करने के लिए स्वच्छ रहता है भले ही एक स्थिति लाइन दिखाई जाए। `--json` के बिना आप मानव आँखों के लिए एक बॉक्सबद्ध, रंगीन दृश्य प्राप्त करते हैं।
- **`--help` के साथ खोजें।** हर कमांड और सबकमांड के पास `--help` होता है (और `-h` alias): `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`। शीर्ष-स्तरीय सहायता exit codes और ग्लोबल विकल्पों को भी सूचीबद्ध करती है। कोई ग्लोबल मशीन-पढ़ने योग्य सतह डंप नहीं है; प्रति-कमांड `--help` का उपयोग करें, साथ ही डोमेन-विशिष्ट `agenteye query schema` और `agenteye settings schema` उन दोनों रजिस्ट्रियों के लिए।
- **पुष्टियां स्क्रिप्ट और एजेंटों के लिए ऑटो-स्किप करती हैं।** Create/update/delete कमांड एक interactive टर्मिनल में "क्या आप निश्चित हैं?" को प्रॉम्प्ट करती हैं, लेकिन **`--json` के तहत या जब भी stdin एक TTY नहीं है तो ऑटो-स्किप करती हैं** (एक TTY एक interactive टर्मिनल सेशन है; एक पाइप या CI रनर नहीं है), इसलिए स्क्रिप्ट और एजेंट कभी भी हैंग नहीं करते। इसे स्पष्ट रूप से छोड़ने के लिए `--yes`/`-y` पास करें। क्योंकि प्रॉम्प्ट एक एजेंट के लिए फायर नहीं करेगी, एक एजेंट को विनाशकारी क्रियाओं की पुष्टि पहले मानव से करनी चाहिए।
- **पेजिनेशन:** परिणाम सबसे नए-पहले हैं और cursor-paginated हैं (प्रत्येक पृष्ठ एक टोकन देता है जो आप अगले को प्राप्त करने के लिए उपयोग करते हैं)। `--limit N` (alias `-n`) पंक्तियों को cap करता है और **डिफ़ॉल्ट रूप से 50**; `--all` auto-paginates (200-row chunks में) **`--limit` तक**, इसलिए एक बेयर `--all` अभी भी 50 पर रुकता है। एक पूर्ण sweep के लिए एक उच्च स्पष्ट cap पास करें: `--all --limit 1000`। `--page-size N` प्रति-request chunk को नियंत्रित करता है (अधिकतम 200); `--cursor <id>` एक prior पृष्ठ के `next_cursor` से फिर से शुरू करता है।
- **समय फ़िल्टर:** `--since` एक relative विंडो लेता है: `15m`, `1h`, `6h`, `24h`, `7d`, या `all` (डैशबोर्ड के presets)। एक लंबी या custom range के लिए (कहें पिछले 30 दिन), `--from`/`--to` का उपयोग करें: स्पष्ट ISO-8601 UTC timestamps **`T` और एक timezone के साथ** (जैसे `2026-06-01T00:00:00Z`) जो `--since` को override करते हैं। एक space-separated या timezone-less मान एक उपयोग त्रुटि है।
- **`--fields a,b,c`** (on `events`, `sessions`, `evals`, `errors`) आउटपुट को उन keys तक सीमित करता है, टेबल और `--json` दोनों के लिए। अज्ञात नामों को वैध सूची के साथ अस्वीकार किया जाता है, field नामों की खोज करने के लिए एक सस्ता तरीका।
- **`--file payload.json`** (या `--file -` stdin को पढ़ने के लिए) एक पूर्ण JSON request body प्रदान करता है जहाँ एक संसाधन के पास एक complex shape होता है (`alerts create/update`, `settings set`, और `users create/update` पर)। Saved-query SQL `--sql @file.sql` का उपयोग करता है इसके बजाय।
- **Multi-value फ़िल्टर** comma-separated हैं → एक set के रूप में matched हैं (एक फ़िल्टर के भीतर union, फ़िल्टर में AND): `--event-type tool_use,tool_result`। क्लिक विकल्प variadic नहीं हैं, इसलिए `--add a b` breaks करता है। `--add a,b`, फ़्लैग को दोहराएं (`--add a --add b`), या quote करें (`--add "a b"`)।

## कमांड संदर्भ

### आप इन 5 कमांडों को सबसे अधिक उपयोग करेंगे

अधिकांश दिन-प्रतिदिन का काम कुछ read कमांड के माध्यम से चलता है। यहाँ शुरू करें, फिर जब आपको इसकी आवश्यकता हो तो नीचे पूर्ण सतह तक पहुंचें:

| कमांड | यह क्या करता है | इसे आजमाएं |
|---|---|---|
| `sessions` | एक agent run प्रति पंक्ति: समय, env, agent, स्थिति, नवीनतम स्कोर। | `agenteye --json sessions --since 24h --status error` |
| `events` | एक run के अंदर raw per-step trail (payloads के लिए `--full` जोड़ें)। | `agenteye --json events --session-id run-001 --all` |
| `evals` | मूल्यांकन परिणाम और स्कोर; `--aggregate` उन्हें roll up करता है। | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | केवल errored events; counts द्वारा प्रकार के लिए `--aggregate`। | `agenteye --json errors --since 24h --aggregate` |
| `list` | वैध फ़िल्टर मान (agents, envs, models, …) की खोज करें। | `agenteye list agents` |

### CLI क्या कर सकता है सब कुछ

पूर्ण सतह अनुसरण करता है। CLI में **18 शीर्ष-स्तरीय कमांड** हैं। सभी read कमांड `--json` और ऊपर दिए गए ग्लोबल विकल्पों को स्वीकार करते हैं; किसी एक के लिए exhaustive flag सूची और JSON shape के लिए `agenteye <command> -h` (या `<command> <subcommand> -h`) चलाएं।

### पहचान: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # emailed one-time code; saves the session
agenteye logout                                       # clear the saved session on this machine
agenteye whoami                                       # current user, active org, permissions
agenteye version                                      # print the CLI version (same as --version)
agenteye help                                         # top-level help (same as --help)
```

`orgs` सक्रिय tenant की जांच करता है और switches करता है:

```bash
agenteye orgs list        # your orgs + your role in each (active one marked)
agenteye orgs switch acme # change the saved active org (omit the slug to pick from a list on a TTY)
agenteye orgs current     # identity card for the active org
agenteye orgs perms       # your permissions in the active org, grouped by resource
```

### अवलोकन करें (रीड-ऑनली): `events` · `sessions` · `evals` · `errors` · `list`

इनमें से कोई भी पुष्टि की आवश्यकता नहीं है। साझा फ़िल्टर: `--session-id`, `--agent-id`, `--env` (**न** `--environment`), और समय range (`--since` / `--from` / `--to`)।

```bash
# events (alias: the raw per-step trail), newest first
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: one row per agent run (time/env/agent/session/status; no score filtering)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: evaluation results + scores; --score filters by metric, --aggregate rolls up
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # status mix + per-key score stats

# errors: errored events; --aggregate for counts/sessions/agents/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: discover valid filter values before you filter
agenteye list envs        # also: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (on **`evals`**, न `sessions`) दोहराया जाता है और AND-combined होता है; या तो bound optional है (`..0.5` मतलब ≤ 0.5, `0.9..` मतलब ≥ 0.9)। प्रति request तक 20 score फ़िल्टर। `evals --scores-full` **मानव table के लिए ही** एक display flag है; यह हर स्कोर pair को दिखाता है पहले कुछ के बजाय plus एक `+N` count। यह `--json` के तहत कोई प्रभाव नहीं पड़ता है, जो हमेशा पूर्ण score ऑब्जेक्ट देता है। **एक session को end-to-end पढ़ने के लिए**, event trail को इसके evaluation के साथ combine करें:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # its scores + status
```

### प्रबंधित करें (अनुमति-gated): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: API keys। Secret स्थानीय रूप से generated होता है, सर्वर को भेजा जाता है (जो केवल एक hash store करता है), और **एक बार shown होता है** create/regenerate पर; इसे तब capture करें। `--json` के साथ यह केवल `key` field में दिखाई देता है। **नाम** द्वारा referenced।

```bash
agenteye keys list                                   # active keys first, then revoked
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # scope to what you need; prints the secret ONCE
agenteye keys create ops --permission-set standard --remove queries:run   # seed a preset, then trim
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rotate the secret (the old one stops working)
agenteye keys disable ci-bot --yes                   # revoke
```

अनुमतियां `(permission-set ∪ --add) − --remove` के रूप में काम करती हैं। Tokens `slug:action` हैं (जैसे `events:read`) या `slug:action.action` एक resource पर कई को expand करने के लिए (`events:read.add` → `events:read`, `events:add`)। Presets: `read-only`, `standard`, `admin`। मानव-only अनुमतियां (`keys:update`) एक key को grant नहीं की जा सकतीं।

**`users`**: org सदस्य, **ईमेल** द्वारा referenced (एक UUID id भी स्वीकृत है)।

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predicts + confirms
agenteye users disable dev@corp.com --yes            # has protected/self guards
agenteye users enable dev@corp.com
```

**`settings`**: एक fixed registry (आप मौजूदा keys को पढ़ते और बदलते हैं; आप नए नहीं बना सकते)।

```bash
agenteye settings list                               # key · value · type · updated (secrets masked)
agenteye settings schema                             # what each key accepts (type · range · description)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: alert परिभाषाएं, **नाम** द्वारा referenced। `create` एक positional NAME plus flags या `--file` के माध्यम से एक पूर्ण JSON body लेता है।

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME is required (positional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # fire a test notification
agenteye alerts delete high-errors --yes
```

**`incidents`**: alert incidents, id द्वारा referenced (short ids स्वीकृत हैं)। `show` पूर्ण activity log को प्रिंट करता है; कार्य करने से पहले इसे पढ़ें।

```bash
agenteye incidents list --state firing                # also: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assignee must be an operator
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # open one manually against an alert
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### एनालिटिक्स और असिस्टेंट: `query` · `agent`

**`query`**: आपके analytics store के विरुद्ध saved SQL plus एक ad-hoc रनर। Saved queries **नाम** द्वारा referenced; SQL सर्वर-side validate किया जाता है (SELECT/WITH only, statement timeout, row cap)।

```bash
agenteye query schema [TABLE]                         # column layout of the analytics views
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # run a saved query + a positional $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: built-in **AI असिस्टेंट** से बात करता है (वही रीड-ऑनली एनालिस्ट जिससे आप डैशबोर्ड में चैट कर सकते हैं)। Chats एक short chat-id द्वारा referenced (prefix-resolved)।

```bash
agenteye agent health                                 # is the AI assistant configured/reachable
agenteye agent models                                 # models you can pass to --model (default marked)
agenteye agent ask "which agents errored most in the last day?"    # starts a chat; prints its short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continue that chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## Exit codes

| कोड | मतलब |
|---|---|
| 0 | सफलता |
| 1 | अप्रत्याशित त्रुटि (जैसे डैशबोर्ड ने एक 5xx लौटाया) |
| 2 | उपयोग त्रुटि (अमान्य arguments, अज्ञात command/flag, नाम collision) |
| 3 | डैशबोर्ड तक पहुंचने में असमर्थ |
| 4 | साइन इन नहीं किया गया या सेशन समाप्त; `agenteye login` चलाएं |
| 5 | प्रमाणित, लेकिन आपके खाते में आवश्यक अनुमति नहीं है (संदेश इसे नाम देता है) |
| 6 | अनुरोधित संसाधन नहीं मिला (जैसे अज्ञात session या incident id) |

ये CLI को स्क्रिप्ट करने के लिए सुरक्षित बनाते हैं: एक कोडिंग एजेंट एक `4` पर फिर से प्रमाणित करने के लिए आपको प्रॉम्प्ट करने के लिए branch कर सकता है, या एक `5` पर लापता अनुमति को surface करने के लिए। [एजेंटों के लिए CLI recipes](/hi/agenteye/cli-recipes) देखें exit-code-handling पैटर्न और JSON आउटपुट shapes के लिए।
