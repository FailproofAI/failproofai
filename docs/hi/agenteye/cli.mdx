Failproof AI Observability के सभी कार्यों को टर्मिनल या स्क्रिप्ट से चलाएं: कोई डैशबोर्ड चक्कर नहीं। `agenteye` CLI आपके डेटा (sessions, event logs, evaluations) को query करता है और आपके org को प्रबंधित करता है (API keys, users, settings, alerts, incidents, saved queries), इसलिए जब आप कोई check स्वचालित करना चाहते हैं, CI में Observability जोड़ना चाहते हैं, या coding agent को production निरीक्षण करने दिखाना चाहते हैं, तो इसका उपयोग करें। प्रत्येक command एक `--json` flag को सपोर्ट करता है, इसलिए यह आपके लिए prompt पर या coding agent (Claude Code, Cursor) के लिए shell out करके result parse करने में समान रूप से काम करता है।

एक binary के साथ आप ये कर सकते हैं:

- **अपना डेटा पढ़ें**: `sessions`, `events`, `evals`, `errors` (समय, agent, env, score द्वारा फ़िल्टर करें)।
- **अपने org को प्रबंधित करें**: `keys`, `users`, `settings`, `alerts`, `incidents`।
- **विश्लेषण चलाएं**: saved SQL और ad-hoc query runner (`query`)।
- **AI assistant से पूछें**: वही read-only analyst जिससे आप डैशबोर्ड में चैट करते हैं (`agent`)।

> **नोट:** यह `agenteye` CLI है, collector daemon (`agenteye-collector`) से एक अलग tool है। CLI आपके डैशबोर्ड से बात करता है; collector events को server पर भेजता है।

## Quickstart

कुछ भी नहीं से अपना पहला result चार लाइनों में प्राप्त करें। CLI को अपने डैशबोर्ड पर point करें, sign in करें, confirm करें कि आप कौन हैं, फिर पिछले दिन के runs pull करें:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # emailed 6-digit code
agenteye whoami                                                                  # confirm user + active org
agenteye --json sessions --since 24h                                             # one row per agent run, last 24h
```

वह अंतिम command सबसे हाल के sessions का एक JSON object print करता है (सबसे नए पहले, डिफ़ॉल्ट रूप से 50 तक सीमित)। इसे `jq` में pipe करें इसे slice करने के लिए, या table के लिए `--json` drop करें। प्रत्येक row run की status और, यदि evaluator ने इसे score किया है, तो इसके metric scores (यहाँ abbreviated) रखता है:

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

यह पृष्ठ बाकी सब कुछ समझाता है: isolated में [installing](#installation), [signing in](#authentication), [configuration](#configuration), [global conventions](#global-options--conventions) जो हर command share करता है, और [full command reference](#command-reference)।

## Installation

CLI एक public PyPI package है जिसका नाम **`agenteye`** है। इसे एक isolated environment में install करें ताकि इसके हमेशा अपने dependencies हों:

```bash
pipx install agenteye
# or
uv tool install agenteye
```

इसे Python 3.10+ की आवश्यकता है। Installed command है **`agenteye`**:

```bash
agenteye --version
agenteye --help
```

> **नोट:** Failproof AI Observability Python SDK भी `agenteye` distribution name का उपयोग करता है। `pipx` या `uv tool` के साथ CLI install करना (shared virtualenv में `pip install` करने के बजाय) दोनों को collision से बचाता है। एक साधारण `pip install agenteye` ठीक है केवल अगर SDK एक ही environment में install नहीं है।

## Authentication

CLI **dashboard** के साथ एक emailed one-time code द्वारा authenticate करता है:

```bash
agenteye login --email you@example.com
# A 6-digit code is emailed to you; paste it at the prompt.
```

Session token को `~/.agenteye/cli.json` में store किया जाता है (केवल आप readable, mode `0600`) और डिफ़ॉल्ट रूप से 24 घंटों के लिए valid है। जब यह expire हो जाता है, तो `agenteye login` फिर से चलाएं।

```bash
agenteye whoami     # show the current user, active org, and permissions
agenteye logout     # revoke the session and clear the stored token
```

`whoami` कभी missing या expired session पर error नहीं देता; इसके बजाय `logged_in: false` report करता है, इसलिए एक script या agent safely auth state को probe कर सकता है (यह अभी भी non-zero exit कर सकता है अगर कोई base URL set नहीं है या dashboard unreachable है)।

**Requirements:** आपका email dashboard में sign in करने की अनुमति दी जानी चाहिए (अपने Failproof AI Observability administrator से पूछें), और dashboard इसके base URL पर reachable होना चाहिए (देखें [Configuration](#configuration))। यदि आप एक code request करते हैं और कोई नहीं आता है, तो आपका email शायद dashboard access के लिए अभी enabled नहीं है।

## अपने org को चुनना (multi-tenant)

यदि आपका account एक से अधिक org से संबंधित है, तो **login पर** active को चुनें; यह saved है और हर बाद के command के लिए उपयोग किया जाता है:

```bash
agenteye login --org acme           # authenticate and set the active tenant in one step
agenteye orgs list                  # the orgs you can access (the active one is marked)
agenteye orgs switch globex         # change the saved default
agenteye --org globex sessions      # override for a single command
```

यदि आप बिल्कुल एक org से संबंधित हैं तो यह automatically select किया जाता है और आप पूरी तरह `--org` को ignore कर सकते हैं। यदि आप कई से संबंधित हैं और कोई एक pick नहीं करते हैं, तो CLI उन्हें सूचीबद्ध करता है और आपको `--org <slug>` के साथ re-run करने के लिए कहता है। Active org हर request पर dashboard को भेजा जाता है, और आपकी permissions **per org** resolve होती हैं; `agenteye whoami` active org, उसमें आपकी permissions, और आपकी सभी memberships दिखाता है।

## Configuration

| Setting | Flag | Environment variable | Default |
|---|---|---|---|
| Dashboard base URL | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **required** (no default) |
| Active org/tenant | `--org` | `AGENTEYE_ORG` | chosen at login; saved in `~/.agenteye/cli.json` |
| Session token | `--token` | `AGENTEYE_CLI_TOKEN` | from `~/.agenteye/cli.json` |
| JSON output | `--json` | `AGENTEYE_CLI_JSON` | off |
| Skip TLS verification | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | off (saved at login) |
| Request timeout (seconds) | `--timeout` | _(none)_ | 30 |
| Disable usage telemetry | _(none)_ | `AGENTEYE_ANALYTICS_DISABLED` (or `DO_NOT_TRACK`) | telemetry is currently disabled; nothing is sent |

Resolution order है **flag → environment variable → config file**। कोई default नहीं है; आपको CLI को अपने dashboard पर point करना चाहिए, या तो per-command (`--base-url https://agenteye.example.com`) या एक बार environment के माध्यम से (यह आपके पहले `login` के बाद भी saved है):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

Configuration directory `AGENTEYE_HOME` को honour करता है (वही convention जो SDK और collector द्वारा उपयोग किया जाता है); यदि set है, तो `cli.json` `$AGENTEYE_HOME/cli.json` में रहता है।

### Self-signed या internal TLS

यदि आपका dashboard एक self-signed या internal certificate के साथ HTTPS पर serve किया जाता है (उदाहरण के लिए, एक raw load-balancer hostname), तो TLS verification इसे `CERTIFICATE_VERIFY_FAILED` error से reject करता है। Certificate verification को skip करने के लिए `--insecure` pass करें:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` **login करते समय `cli.json` में saved है**, इसलिए बाद के commands automatically verification को skip करते हैं; आपको flag को repeat नहीं करना है। One-off verified call के लिए `--secure` pass करें, या verification को अपने अगले login पर वापस save करने के लिए। CLI dashboard से contact करने वाले किसी भी command से पहले stderr पर एक warning print करता है जबकि verification disabled है। Verification को skip करना man-in-the-middle attacks से protection को remove करता है; अपने dashboard के network path पर भरोसा करने से पहले सुनिश्चित करें कि आप उस पर rely कर सकते हैं (VPN, private subnet, etc.)।

## Telemetry & privacy

> **नोट:** Shipped CLI आज **कोई usage telemetry नहीं भेजता है।** एक master kill switch on है, इसलिए आपके environment की परवाह किए बिना कुछ भी transmitted नहीं है। नीचे दिया गया section telemetry के लिए opt-out capability describe करता है यदि और जब कभी telemetry enable किया जाए।

भले ही enable हो, telemetry **anonymous usage analytics केवल** होगा, कभी नहीं आपके agent, session, या event data:

- **कोई agent, session, या event data कभी आपके infrastructure को नहीं छोड़ता है।** केवल CLI usage report किया जाएगा: command और subcommand name (e.g. `keys create`), flags के **names** जो आपने use किए (कभी नहीं उनकी values), success/exit status, और duration, साथ ही mutations के लिए एक per-action event (e.g. `api_key_created`, `query_run`) केवल static names/enums और coarse counts carry करते हुए। आपका dashboard URL, session token, email, org slug, resource ids, SQL, key secrets, और query filters कभी **नहीं** भेजे जाएंगे। Operators को केवल एक opaque internal id द्वारा identify किया जाएगा, कभी email द्वारा नहीं।
- **Ahead of time opt out करें** CLI के environment में `AGENTEYE_ANALYTICS_DISABLED=1` set करके (CLI cross-tool `DO_NOT_TRACK=1` convention को भी honour करता है)। यह उस क्षण लागू होता है जब telemetry को ever turn on किया जाता है, इसलिए एक privacy-conscious environment permanently opted out रह सकता है।
- यदि telemetry enable होता, तो CLI directly PostHog को (`https://us.i.posthog.com`) भेजता; एक machine जिसके पास वह host blocked है silently कुछ नहीं भेजता और CLI unaffected होता।

## Global options & conventions

यह एक बार पढ़ें; यह हर command पर लागू होता है।

- **Global options command से BEFORE जाते हैं।** `agenteye --json sessions` सही है; `agenteye sessions --json` एक usage error है। Globals हैं `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, और `--no-color`।
- **`--json` stdout को pure JSON print करता है, और कुछ नहीं।** Human status lines, warnings, और errors **stderr** को जाते हैं, इसलिए एक `--json` stdout capture even जब एक status line shown हो clean रहता है `jq` में pipe करने के लिए। `--json` के बिना आप एक boxed, colourised view पाते हैं human eyes के लिए।
- **`--help` के साथ discover करें।** हर command और subcommand के पास `--help` है (और `-h` alias): `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`। Top-level help exit codes और global options को भी list करता है। कोई global machine-readable surface dump नहीं है; per-command `--help` use करें, साथ ही domain-specific `agenteye query schema` और `agenteye settings schema` उन दोनों registries के लिए।
- **Confirmations scripts और agents के लिए auto-skip होती हैं।** Create/update/delete commands एक interactive terminal में "are you sure?" prompt देते हैं, लेकिन **`--json` के under auto-skip जब stdin एक TTY नहीं है** (एक TTY एक interactive terminal session है; एक pipe या CI runner नहीं), इसलिए scripts और agents कभी hang नहीं होते। Explicitly skip करने के लिए `--yes`/`-y` pass करें। क्योंकि prompt एक agent के लिए नहीं fire करेगा, एक agent को destructive actions को human के साथ confirm करना चाहिए।
- **Pagination:** results newest-first हैं और cursor-paginated हैं (प्रत्येक page एक token return करता है जो आप next को fetch करने के लिए use करते हैं)। `--limit N` (alias `-n`) rows को cap करता है और **defaults to 50**; `--all` auto-paginates (200-row chunks में) **`--limit` तक**, इसलिए एक bare `--all` अभी भी 50 पर stop होता है। एक full sweep के लिए एक high explicit cap pass करें: `--all --limit 1000`। `--page-size N` per-request chunk को control करता है (max 200); `--cursor <id>` एक prior page के `next_cursor` से resume करता है।
- **Time filters:** `--since` एक relative window लेता है: `15m`, `1h`, `6h`, `24h`, `7d`, या `all` (dashboard के presets)। एक longer या custom range के लिए (say last 30 days), `--from`/`--to` use करें: explicit ISO-8601 UTC timestamps **`T` और एक timezone के साथ** (e.g. `2026-06-01T00:00:00Z`) जो `--since` को override करते हैं। एक space-separated या timezone-less value एक usage error है।
- **`--fields a,b,c`** (on `events`, `sessions`, `evals`, `errors`) output को उन keys में restrict करता है, table और `--json` दोनों के लिए। Unknown names को valid list के साथ reject किया जाता है, field names को discover करने का एक cheap तरीका।
- **`--file payload.json`** (या `--file -` stdin को read करने के लिए) एक full JSON request body supply करता है जहाँ एक resource के पास एक complex shape है (on `alerts create/update`, `settings set`, और `users create/update`)। Saved-query SQL `--sql @file.sql` instead use करता है।
- **Multi-value filters** comma-separated हैं → एक set के रूप में matched (union within one filter, AND across filters): `--event-type tool_use,tool_result`। Click options variadic नहीं हैं, इसलिए `--add a b` breaks। `--add a,b` use करें, flag को repeat करें (`--add a --add b`), या quote करें (`--add "a b"`)।

## Command reference

### आप इन 5 commands को सबसे अधिक use करेंगे

Most day-to-day work एक handful read commands के through चलती है। यहाँ शुरू करें, फिर full surface के लिए पहुँचें जब आपको चाहिए:

| Command | What it does | Try it |
|---|---|---|
| `sessions` | एक row per agent run: time, env, agent, status, latest score। | `agenteye --json sessions --since 24h --status error` |
| `events` | एक run के अंदर raw per-step trail (payloads के लिए `--full` add करें)। | `agenteye --json events --session-id run-001 --all` |
| `evals` | Evaluation results और scores; `--aggregate` उन्हें roll up करता है। | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | सिर्फ errored events; `--aggregate` type द्वारा counts के लिए। | `agenteye --json errors --since 24h --aggregate` |
| `list` | Valid filter values को discover करें (agents, envs, models, …)। | `agenteye list agents` |

### CLI सब कुछ कर सकता है

Full surface follows। CLI के पास **18 top-level commands** हैं। सभी read commands `--json` और ऊपर global options को accept करते हैं; किसी एक के exhaustive flag list और JSON shape के लिए `agenteye <command> -h` (या `<command> <subcommand> -h`) run करें।

### Identity: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # emailed one-time code; saves the session
agenteye logout                                       # clear the saved session on this machine
agenteye whoami                                       # current user, active org, permissions
agenteye version                                      # print the CLI version (same as --version)
agenteye help                                         # top-level help (same as --help)
```

`orgs` active tenant को inspects और switches करता है:

```bash
agenteye orgs list        # your orgs + your role in each (active one marked)
agenteye orgs switch acme # change the saved active org (omit the slug to pick from a list on a TTY)
agenteye orgs current     # identity card for the active org
agenteye orgs perms       # your permissions in the active org, grouped by resource
```

### Observe (read-only): `events` · `sessions` · `evals` · `errors` · `list`

इनमें से कोई भी एक confirmation की जरूरत नहीं है। Shared filters: `--session-id`, `--agent-id`, `--env` (**not** `--environment`), और time range (`--since` / `--from` / `--to`)।

```bash
# events (alias: the raw per-step trail), newest first
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: one row per agent run (time/env/agent/session/status; no score filtering)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: evaluation results + scores; --score filters by metric, --aggregate rolls up
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # status mix + per-key score stats

# errors: errored events; --aggregate for counts/sessions/agents/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: discover valid filter values before you filter
agenteye list envs        # also: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (on **`evals`**, not `sessions`) repeatable है और AND-combined है; या तो bound optional है (`..0.5` का मतलब ≤ 0.5, `0.9..` का मतलब ≥ 0.9)। एक request per 20 score filters तक। `evals --scores-full` एक display flag है **human table केवल के लिए**; यह हर score pair को first few plus एक `+N` count की बजाय दिखाता है। यह `--json` के under कोई effect नहीं है, जो हमेशा complete score object return करता है। **एक session को end-to-end read करने के लिए**, event trail को उसके evaluation के साथ combine करें:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # its scores + status
```

### Manage (permission-gated): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: API keys। Secret को locally generate किया जाता है, server को भेजा जाता है (जो केवल एक hash store करता है), और create/regenerate पर **once shown** किया जाता है; उसे तब capture करें। `--json` के साथ यह केवल `key` field में appear होता है। **name** द्वारा referenced।

```bash
agenteye keys list                                   # active keys first, then revoked
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # scope to what you need; prints the secret ONCE
agenteye keys create ops --permission-set standard --remove queries:run   # seed a preset, then trim
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rotate the secret (the old one stops working)
agenteye keys disable ci-bot --yes                   # revoke
```

Permissions `(permission-set ∪ --add) − --remove` के रूप में काम करते हैं। Tokens `slug:action` हैं (e.g. `events:read`) या `slug:action.action` एक resource पर कई को expand करने के लिए (`events:read.add` → `events:read`, `events:add`)। Presets: `read-only`, `standard`, `admin`। Human-only permissions (`keys:update`) को एक key को grant नहीं किया जा सकता।

**`users`**: org members, **email** द्वारा referenced (एक UUID id को भी accept किया जाता है)।

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predicts + confirms
agenteye users disable dev@corp.com --yes            # has protected/self guards
agenteye users enable dev@corp.com
```

**`settings`**: एक fixed registry (आप existing keys को read और change करते हैं; आप नए ones create नहीं कर सकते)।

```bash
agenteye settings list                               # key · value · type · updated (secrets masked)
agenteye settings schema                             # what each key accepts (type · range · description)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: alert definitions, **name** द्वारा referenced। `create` एक positional NAME plus flags या `--file` के through एक full JSON body लेता है।

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME is required (positional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # fire a test notification
agenteye alerts delete high-errors --yes
```

**`incidents`**: alert incidents, id द्वारा referenced (short ids accepted)। `show` full activity log को print करता है; उससे पहले इसे पढ़ें।

```bash
agenteye incidents list --state firing                # also: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assignee must be an operator
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # open one manually against an alert
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### Analytics & assistant: `query` · `agent`

**`query`**: आपके analytics store के लिए saved SQL plus एक ad-hoc runner। Saved queries **name** द्वारा referenced; SQL को server-side validate किया जाता है (SELECT/WITH केवल, statement timeout, row cap)।

```bash
agenteye query schema [TABLE]                         # column layout of the analytics views
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # run a saved query + a positional $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: built-in **AI assistant** से बात करता है (वही read-only analyst जिससे आप dashboard में chat कर सकते हैं)। Chats एक short chat-id (prefix-resolved) द्वारा referenced हैं।

```bash
agenteye agent health                                 # is the AI assistant configured/reachable
agenteye agent models                                 # models you can pass to --model (default marked)
agenteye agent ask "which agents errored most in the last day?"    # starts a chat; prints its short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continue that chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | Unexpected error (e.g. the dashboard returned a 5xx) |
| 2 | Usage error (invalid arguments, unknown command/flag, name collision) |
| 3 | Cannot reach the dashboard |
| 4 | Not logged in or session expired; run `agenteye login` |
| 5 | Authenticated, but your account lacks the required permission (the message names it) |
| 6 | The requested resource was not found (e.g. unknown session or incident id) |

ये CLI को script के लिए safe बनाते हैं: एक coding agent एक `4` को branch कर सकता है आपको re-authenticate करने के लिए prompt करने के लिए, या एक `5` missing permission को surface करने के लिए। Exit-code-handling patterns और JSON output shapes के लिए [CLI recipes for agents](/hi/agenteye/cli-recipes) देखें।
