Failproof AI Observability को टर्मिनल या स्क्रिप्ट से चलाएं: कोई डैशबोर्ड चक्कर नहीं। `agenteye` CLI आपके डेटा (सेशन, इवेंट लॉग, मूल्यांकन) को क्वेरी करता है और आपके संगठन (API कुंजियां, उपयोगकर्ता, सेटिंग, सतर्कताएं, घटनाएं, सहेजी गई क्वेरीज) का प्रबंधन करता है। जब आप किसी जांच को स्वचालित करना चाहते हैं, Observability को CI में जोड़ना चाहते हैं, या किसी कोडिंग एजेंट को production का निरीक्षण करने देना चाहते हैं, तो इसका उपयोग करें। प्रत्येक कमांड `--json` फ्लैग को समर्थन करता है, इसलिए यह आपके लिए प्रॉम्प्ट पर या किसी कोडिंग एजेंट (Claude Code, Cursor) के लिए समान रूप से काम करता है जो परिणाम को शेल करता है और पार्स करता है।

एक बाइनरी के साथ आप कर सकते हैं:

- **अपना डेटा पढ़ें**: `sessions`, `events`, `evals`, `errors` (समय, एजेंट, env, स्कोर के अनुसार फ़िल्टर करें)।
- **अपने संगठन का प्रबंधन करें**: `keys`, `users`, `settings`, `alerts`, `incidents`।
- **विश्लेषण चलाएं**: सहेजी गई SQL और एक ad-hoc क्वेरी रनर (`query`)।
- **AI सहायक से पूछें**: वही read-only विश्लेषक जो आप डैशबोर्ड में चैट करते हैं (`agent`)।

> **नोट:** यह `agenteye` CLI है, कलेक्टर डेमॉन (`agenteye-collector`) से एक अलग टूल। CLI आपके डैशबोर्ड से बात करता है; कलेक्टर सर्वर को इवेंट भेजता है।

## क्विकस्टार्ट

कुछ नहीं से अपना पहला परिणाम चार पंक्तियों में प्राप्त करें। CLI को अपने डैशबोर्ड पर इंगित करें, साइन इन करें, पुष्टि करें कि आप कौन हैं, फिर पिछले दिन की रन खींचें:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # emailed 6-digit code
agenteye whoami                                                                  # confirm user + active org
agenteye --json sessions --since 24h                                             # one row per agent run, last 24h
```

वह अंतिम कमांड सबसे हाल के सेशन का एक JSON ऑब्जेक्ट प्रिंट करता है (नवीनतम पहले, डिफ़ॉल्ट रूप से 50 तक सीमित)। इसे `jq` में पाइप करें इसे स्लाइस करने के लिए, या `--json` को ड्रॉप करें एक बॉक्सबद्ध, रंगीन तालिका के लिए। प्रत्येक पंक्ति रन की स्थिति और, यदि किसी मूल्यांकनकर्ता ने इसे स्कोर किया है, तो इसके मीट्रिक स्कोर (यहां संक्षिप्त) ले जाती है:

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

इस पृष्ठ के बाकी हिस्से प्रत्येक भाग को समझाते हैं: [स्थापन](#installation) अलग-थलग, [साइन इन करना](#authentication), [कॉन्फ़िगरेशन](#configuration), [वैश्विक सम्मेलन](#global-options--conventions) जो प्रत्येक कमांड साझा करते हैं, और [पूर्ण कमांड संदर्भ](#command-reference)।

## स्थापन

CLI एक सार्वजनिक PyPI पैकेज है जिसका नाम **`agenteye`** है। इसे एक अलग environment में स्थापित करें ताकि इसके हमेशा अपने dependencies हों:

```bash
pipx install agenteye
# or
uv tool install agenteye
```

इसके लिए Python 3.10+ की आवश्यकता है। स्थापित कमांड **`agenteye`** है:

```bash
agenteye --version
agenteye --help
```

> **नोट:** Failproof AI Observability Python SDK भी `agenteye` वितरण नाम का उपयोग करता है। CLI को `pipx` या `uv tool` के साथ स्थापित करना (एक साझा virtualenv में `pip install` के बजाय) दोनों को टकराने से रोकता है। एक सादा `pip install agenteye` ठीक है केवल यदि SDK उसी environment में स्थापित नहीं है।

## प्रमाणीकरण

CLI **डैशबोर्ड** को एक emailed one-time कोड के साथ प्रमाणित करता है:

```bash
agenteye login --email you@example.com
# A 6-digit code is emailed to you; paste it at the prompt.
```

सेशन टोकन `~/.agenteye/cli.json` में संग्रहीत है (केवल आपके द्वारा पठनीय, mode `0600`) और डिफ़ॉल्ट रूप से 24 घंटे के लिए मान्य है। जब यह समाप्त हो जाए, `agenteye login` फिर से चलाएं।

```bash
agenteye whoami     # show the current user, active org, and permissions
agenteye logout     # revoke the session and clear the stored token
```

`whoami` एक missing या expired सेशन पर कभी error नहीं करता; यह इसके बजाय `logged_in: false` की रिपोर्ट करता है, इसलिए एक स्क्रिप्ट या एजेंट सुरक्षित रूप से auth state को probe कर सकता है (यदि कोई base URL सेट नहीं है या डैशबोर्ड अप्राप्य है तो यह अभी भी non-zero निकल सकता है)।

**आवश्यकताएं:** आपकी ईमेल को डैशबोर्ड में साइन इन करने की अनुमति दी जानी चाहिए (अपने Failproof AI Observability प्रशासक से पूछें), और डैशबोर्ड अपने base URL पर पहुंचने योग्य होना चाहिए (देखें [कॉन्फ़िगरेशन](#configuration))। यदि आप कोड का अनुरोध करते हैं और कोई नहीं आता है, तो आपकी ईमेल शायद डैशबोर्ड access के लिए अभी तक enabled नहीं है।

## अपने org को चुनना (multi-tenant)

यदि आपका खाता एक से अधिक org से संबंधित है, तो **login पर** सक्रिय को चुनें; यह सहेजा जाता है और हर बाद की कमांड के लिए उपयोग किया जाता है:

```bash
agenteye login --org acme           # authenticate and set the active tenant in one step
agenteye orgs list                  # the orgs you can access (the active one is marked)
agenteye orgs switch globex         # change the saved default
agenteye --org globex sessions      # override for a single command
```

यदि आप बिल्कुल एक org से संबंधित हैं तो यह automatically चुना जाता है और आप `--org` को पूरी तरह से ignore कर सकते हैं। यदि आप कई से संबंधित हैं और एक को नहीं चुनते हैं, तो CLI उन्हें सूचीबद्ध करता है और आपसे `--org <slug>` के साथ फिर से चलाने के लिए कहता है। सक्रिय org हर अनुरोध पर डैशबोर्ड को भेजा जाता है, और आपकी permissions **प्रति org** को resolve किया जाता है; `agenteye whoami` सक्रिय org, इसमें आपकी permissions, और आपकी सभी memberships दिखाता है।

## कॉन्फ़िगरेशन

| सेटिंग | फ्लैग | Environment variable | डिफ़ॉल्ट |
|---|---|---|---|
| Dashboard base URL | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **आवश्यक** (कोई डिफ़ॉल्ट नहीं) |
| सक्रिय org/tenant | `--org` | `AGENTEYE_ORG` | login पर चुना गया; `~/.agenteye/cli.json` में सहेजा गया |
| Session token | `--token` | `AGENTEYE_CLI_TOKEN` | `~/.agenteye/cli.json` से |
| JSON output | `--json` | `AGENTEYE_CLI_JSON` | off |
| TLS verification को स्किप करें | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | off (login पर सहेजा गया) |
| Request timeout (सेकंड) | `--timeout` | _(none)_ | 30 |
| उपयोग telemetry को अक्षम करें | _(none)_ | `AGENTEYE_ANALYTICS_DISABLED` (या `DO_NOT_TRACK`) | telemetry वर्तमान में अक्षम है; कुछ नहीं भेजा जाता है |

Resolution order **flag → environment variable → config file** है। कोई डिफ़ॉल्ट नहीं है; आपको CLI को अपने डैशबोर्ड पर इंगित करना होगा, या तो प्रति-कमांड (`--base-url https://agenteye.example.com`) या एक बार environment के माध्यम से (यह आपके पहले `login` के बाद भी सहेजा जाता है):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

Configuration directory `AGENTEYE_HOME` को honor करता है (SDK और कलेक्टर द्वारा उपयोग किया जाने वाला समान सम्मेलन); यदि सेट है, `cli.json` `$AGENTEYE_HOME/cli.json` में रहता है।

### Self-signed या internal TLS

यदि आपका डैशबोर्ड HTTPS पर एक self-signed या internal certificate के साथ served है (उदाहरण के लिए, एक raw load-balancer hostname), तो TLS verification इसे `CERTIFICATE_VERIFY_FAILED` error के साथ reject करता है। Certificate verification को स्किप करने के लिए `--insecure` पास करें:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` **login पर `cli.json` में सहेजा जाता है**, इसलिए बाद की कमांडें automatically verification को स्किप करती हैं; आपको flag को दोहराना नहीं है। एक one-off verified call के लिए `--secure` पास करें, या verification को आपने अगले login पर वापस बदल दें। CLI डैशबोर्ड से संपर्क करने वाली किसी भी कमांड के लिए stderr पर एक warning प्रिंट करता है जबकि verification अक्षम है। Verification को स्किप करना man-in-the-middle attacks के खिलाफ सुरक्षा को हटाता है; इसके आधार पर भरोसा करने से पहले सुनिश्चित करें कि आप अपने डैशबोर्ड के नेटवर्क पथ (VPN, private subnet, आदि) पर भरोसा करते हैं।

## Telemetry & privacy

> **नोट:** shipped CLI **आज कोई usage telemetry नहीं भेजता है।** एक master kill switch चालू है, इसलिए कुछ भी आपके environment की परवाह किए बिना transmitted नहीं है। नीचे का section opt-out capability का वर्णन करता है यदि और जब telemetry कभी enabled हो।

यहां तक कि enabled होने पर, telemetry **केवल anonymous usage analytics** होगा, कभी नहीं आपका agent, session, या event data:

- **कोई agent, session, या event data कभी भी आपके infrastructure को नहीं छोड़ता है।** केवल CLI usage की रिपोर्ट की जाएगी: command और subcommand नाम (जैसे `keys create`), आपके द्वारा उपयोग किए गए flags के **नाम** (कभी नहीं उनके values), success/exit status, और duration, साथ ही mutations के लिए एक per-action event (जैसे `api_key_created`, `query_run`) जो केवल static names/enums और coarse counts ले जाता है। आपका dashboard URL, session token, email, org slug, resource ids, SQL, key secrets, और query filters **कभी** नहीं भेजे जाएंगे। Operators को केवल एक opaque internal id द्वारा identify किया जाएगा, कभी नहीं ईमेल से।
- **आगे से opt out करें** CLI के environment में `AGENTEYE_ANALYTICS_DISABLED=1` सेट करके (CLI cross-tool `DO_NOT_TRACK=1` सम्मेलन को भी honor करता है)। यह प्रभाव लेता है जिस क्षण telemetry कभी बदल दिया जाता है, इसलिए एक privacy-conscious environment स्थायी रूप से opted out रह सकता है।
- यदि telemetry enabled होता, तो CLI सीधे PostHog (`https://us.i.posthog.com`) को भेजता; एक मशीन जिसके पास वह host blocked है वह silently कुछ नहीं भेजता और CLI unaffected होगा।

## वैश्विक विकल्प और सम्मेलन

यह एक बार पढ़ें; यह प्रत्येक कमांड पर लागू होता है।

- **वैश्विक विकल्प कमांड से BEFORE जाते हैं।** `agenteye --json sessions` सही है; `agenteye sessions --json` एक usage error है। Globals `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, और `--no-color` हैं।
- **`--json` pure JSON को stdout पर प्रिंट करता है, और कुछ नहीं।** मानव status lines, warnings, और errors **stderr** पर जाते हैं, इसलिए एक `--json` stdout capture even जब एक status line दिखाया जाए तब भी clean रहता है `jq` में पाइप करने के लिए। `--json` के बिना आप मानव आँखों के लिए एक बॉक्सबद्ध, रंगीन view पाते हैं।
- **`--help` के साथ खोजें।** प्रत्येक command और subcommand में `--help` (और `-h` alias) है: `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`। Top-level help भी exit codes और global options को सूचीबद्ध करता है। कोई global machine-readable surface dump नहीं है; per-command `--help` का उपयोग करें, साथ ही domain-specific `agenteye query schema` और `agenteye settings schema` उन दोनों registries के लिए।
- **Confirmations scripts और agents के लिए auto-skip करते हैं।** Create/update/delete commands एक interactive terminal में "are you sure?" prompt करते हैं, लेकिन **`--json` के तहत या जब भी stdin एक TTY नहीं है** (एक TTY एक interactive terminal session है; एक pipe या एक CI runner नहीं है) उस prompt को auto-skip करते हैं, इसलिए scripts और agents कभी hang नहीं करते। `--yes`/`-y` को explicitly skip करने के लिए पास करें। क्योंकि prompt एक agent के लिए fire नहीं होगा, एक agent को destructive actions की मानव के साथ पहले पुष्टि करनी चाहिए।
- **Pagination:** results newest-first हैं और cursor-paginated हैं (प्रत्येक page एक token return करता है जो आप अगला fetch करने के लिए उपयोग करते हैं)। `--limit N` (alias `-n`) rows को cap करता है और **डिफ़ॉल्ट रूप से 50** है; `--all` auto-paginates करता है (200-row chunks में) **`--limit` तक**, इसलिए एक bare `--all` अभी भी 50 पर बंद हो जाता है। एक full sweep के लिए एक high explicit cap pass करें: `--all --limit 1000`। `--page-size N` per-request chunk को नियंत्रित करता है (max 200); `--cursor <id>` एक prior page के `next_cursor` से resume करता है।
- **Time filters:** `--since` एक relative window लेता है: `15m`, `1h`, `6h`, `24h`, `7d`, या `all` (dashboard के presets)। एक longer या custom range के लिए (say last 30 days), `--from`/`--to` का उपयोग करें: explicit ISO-8601 UTC timestamps **`T` और एक timezone के साथ** (जैसे `2026-06-01T00:00:00Z`) जो `--since` को override करते हैं। एक space-separated या timezone-less value एक usage error है।
- **`--fields a,b,c`** (`events`, `sessions`, `evals`, `errors` पर) output को उन keys तक प्रतिबंधित करता है, table और `--json` दोनों के लिए। Unknown names को valid list के साथ reject किया जाता है, field names को खोजने का एक सस्ता तरीका।
- **`--file payload.json`** (या `--file -` stdin पढ़ने के लिए) एक full JSON request body supply करता है जहां एक resource का एक complex shape है (`alerts create/update`, `settings set`, और `users create/update` पर)। Saved-query SQL `--sql @file.sql` का उपयोग करता है।
- **Multi-value filters** comma-separated हैं → एक set के रूप में matched (union एक filter के भीतर, AND filters के पार): `--event-type tool_use,tool_result`। Click options variadic नहीं हैं, इसलिए `--add a b` breaks। `--add a,b` का उपयोग करें, flag को repeat करें (`--add a --add b`), या quote करें (`--add "a b"`)।

## कमांड संदर्भ

### आप इन 5 कमांडों को सबसे अधिक उपयोग करेंगे

अधिकांश दिन-प्रतिदिन का काम कुछ read commands के माध्यम से चलता है। यहाँ से शुरू करें, फिर जब आपको इसकी आवश्यकता हो तो नीचे पूरी surface तक पहुँचें:

| कमांड | यह क्या करता है | इसे आजमाएं |
|---|---|---|
| `sessions` | एक agent run प्रति row: time, env, agent, status, latest score। | `agenteye --json sessions --since 24h --status error` |
| `events` | एक run के अंदर raw per-step trail (payloads के लिए `--full` जोड़ें)। | `agenteye --json events --session-id run-001 --all` |
| `evals` | Evaluation results और scores; `--aggregate` उन्हें roll करता है। | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | केवल errored events; `--aggregate` type के अनुसार counts के लिए। | `agenteye --json errors --since 24h --aggregate` |
| `list` | valid filter values (agents, envs, models, …) को खोजें। | `agenteye list agents` |

### CLI जो कुछ भी कर सकता है

पूरी surface अनुसरण करती है। CLI में **18 top-level commands** हैं। सभी read commands `--json` और ऊपर दिए गए global options को accept करते हैं; किसी भी एक के लिए exhaustive flag list और JSON shape के लिए `agenteye <command> -h` (या `<command> <subcommand> -h`) चलाएं।

### Identity: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # emailed one-time code; saves the session
agenteye logout                                       # clear the saved session on this machine
agenteye whoami                                       # current user, active org, permissions
agenteye version                                      # print the CLI version (same as --version)
agenteye help                                         # top-level help (same as --help)
```

`orgs` सक्रिय tenant का निरीक्षण और स्विच करता है:

```bash
agenteye orgs list        # your orgs + your role in each (active one marked)
agenteye orgs switch acme # change the saved active org (omit the slug to pick from a list on a TTY)
agenteye orgs current     # identity card for the active org
agenteye orgs perms       # your permissions in the active org, grouped by resource
```

### Observe (read-only): `events` · `sessions` · `evals` · `errors` · `list`

इनमें से कोई भी confirmation की आवश्यकता नहीं है। Shared filters: `--session-id`, `--agent-id`, `--env` (**नहीं** `--environment`), और time range (`--since` / `--from` / `--to`)।

```bash
# events (alias: the raw per-step trail), newest first
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: one row per agent run (time/env/agent/session/status; no score filtering)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: evaluation results + scores; --score filters by metric, --aggregate rolls up
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # status mix + per-key score stats

# errors: errored events; --aggregate for counts/sessions/agents/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: discover valid filter values before you filter
agenteye list envs        # also: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (**`evals` पर**, `sessions` नहीं) repeatable है और AND-combined है; कोई भी bound optional है (`..0.5` means ≤ 0.5, `0.9..` means ≥ 0.9)। प्रति request 20 score filters तक। `evals --scores-full` **human table केवल** के लिए एक display flag है; यह पहले कुछ के बजाय प्रत्येक score pair दिखाता है plus एक `+N` count। यह `--json` के तहत कोई प्रभाव नहीं है, जो हमेशा complete score object return करता है। **एक session end-to-end को पढ़ने** के लिए, event trail को उसके evaluation के साथ combine करें:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # its scores + status
```

### Manage (permission-gated): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: API keys। Secret locally generate होता है, server को भेजा जाता है (जो केवल एक hash store करता है), और **एक बार दिखाया जाता है** create/regenerate पर; तब इसे capture करें। `--json` के साथ यह केवल `key` field में दिखाई देता है। **नाम** से referenced।

```bash
agenteye keys list                                   # active keys first, then revoked
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # scope to what you need; prints the secret ONCE
agenteye keys create ops --permission-set standard --remove queries:run   # seed a preset, then trim
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rotate the secret (the old one stops working)
agenteye keys disable ci-bot --yes                   # revoke
```

Permissions `(permission-set ∪ --add) − --remove` के रूप में काम करती हैं। Tokens `slug:action` (जैसे `events:read`) या `slug:action.action` एक resource पर कई को expand करने के लिए (`events:read.add` → `events:read`, `events:add`)। Presets: `read-only`, `standard`, `admin`। Human-only permissions (`keys:update`) एक key को grant नहीं किए जा सकते।

**`users`**: org members, **email** द्वारा referenced (एक UUID id भी accepted है)।

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predicts + confirms
agenteye users disable dev@corp.com --yes            # has protected/self guards
agenteye users enable dev@corp.com
```

**`settings`**: एक fixed registry (आप existing keys को read और change करते हैं; आप नए नहीं create कर सकते)।

```bash
agenteye settings list                               # key · value · type · updated (secrets masked)
agenteye settings schema                             # what each key accepts (type · range · description)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: alert definitions, **नाम** द्वारा referenced। `create` एक positional NAME plus flags या `--file` के माध्यम से एक full JSON body लेता है।

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME is required (positional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # fire a test notification
agenteye alerts delete high-errors --yes
```

**`incidents`**: alert incidents, id द्वारा referenced (short ids accepted)। `show` full activity log print करता है; act करने से पहले पढ़ें।

```bash
agenteye incidents list --state firing                # also: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assignee must be an operator
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # open one manually against an alert
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### Analytics & assistant: `query` · `agent`

**`query`**: आपके analytics store के विरुद्ध saved SQL plus एक ad-hoc runner। Saved queries **नाम** द्वारा referenced हैं; SQL को server-side validate किया जाता है (केवल SELECT/WITH, statement timeout, row cap)।

```bash
agenteye query schema [TABLE]                         # column layout of the analytics views
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # run a saved query + a positional $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: built-in **AI assistant** से बात करता है (वही read-only विश्लेषक जो आप डैशबोर्ड में चैट कर सकते हैं)। Chats एक short chat-id (prefix-resolved) द्वारा referenced हैं।

```bash
agenteye agent health                                 # is the AI assistant configured/reachable
agenteye agent models                                 # models you can pass to --model (default marked)
agenteye agent ask "which agents errored most in the last day?"    # starts a chat; prints its short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continue that chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## Exit codes

| Code | अर्थ |
|---|---|
| 0 | सफलता |
| 1 | अप्रत्याशित error (जैसे dashboard ने एक 5xx return किया) |
| 2 | Usage error (invalid arguments, unknown command/flag, name collision) |
| 3 | Dashboard तक पहुंच नहीं सकते |
| 4 | Logged in नहीं हैं या session expired; `agenteye login` चलाएं |
| 5 | Authenticated, लेकिन आपके account को required permission की कमी है (message इसे names करता है) |
| 6 | Requested resource नहीं मिला (जैसे unknown session या incident id) |

ये CLI को script करने के लिए सुरक्षित बनाते हैं: एक coding agent एक `4` पर branch कर सकता है आपको re-authenticate करने के लिए prompt करने के लिए, या एक `5` missing permission को surface करने के लिए। [Agents के लिए CLI recipes](/hi/agenteye/cli-recipes) में exit-code-handling patterns और JSON output shapes देखें।
