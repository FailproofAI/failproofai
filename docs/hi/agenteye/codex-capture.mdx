आपके engineers हर दिन OpenAI Codex चलाते हैं। Codex session capture उन कोडिंग सेशन को AgentEye में सामान्य सेशन और इवेंट के रूप में लाता है, ताकि आप उन्हें खोज सकें, रीप्ले कर सकें, और आप जो कुछ और भी देखते हैं उसके साथ उनका मूल्यांकन कर सकें। यह [Python SDK](/hi/agenteye/python-sdk) को पूरक करता है: SDK आप द्वारा लिखे गए agents को instrument करता है, जबकि यह आपकी टीम द्वारा पहले से चलाए जा रहे Codex कार्य को कैप्चर करता है — इसे चलाने के तरीके में कोई बदलाव नहीं।

एक छोटा background collector Codex के स्थानीय session transcripts को जब वे लिखे जाते हैं तब पढ़ता है और उन्हें AgentEye को भेजता है। एक मशीन प्रति collector सभी स्थानीय Codex surfaces को एक साथ कैप्चर करता है — कोई per-surface setup नहीं है।

यही collector अन्य agents को भी कैप्चर करता है — [OpenClaw](/hi/agenteye/openclaw-capture) और [Hermes](/hi/agenteye/hermes-capture) देखें। आप जो भी चलाते हैं उसे सक्षम करें; एक single collector एक साथ कई को कैप्चर कर सकता है।

---

## यह क्या कैप्चर करता है

हर Codex surface जो **स्थानीय रूप से** चलता है वही disk पर session transcripts बनाता है, और collector सभी को उठाता है:

- Codex **CLI** और `codex exec`
- **VS Code / IDE extension**
- **desktop app**, जब यह स्थानीय रूप से एक सेशन चलाता है

प्रत्येक Codex सेशन एक AgentEye [session](/hi/agenteye/sessions) बन जाता है; इसके user और assistant संदेश, reasoning, tool calls, tool results, और token usage से मेल खाने वाले [events](/hi/agenteye/event-stream) बनते हैं। प्रत्येक सेशन किस surface (CLI, IDE, या desktop) से आया है यह दर्ज किया जाता है, ताकि आप उन्हें अलग बता सकें।

> **Cloud sessions कैप्चर नहीं किए जाते।** Desktop app तेजी से Codex cloud में सेशन चलाता है और मशीन पर केवल उनके metadata रखता है — कोई स्थानीय transcript नहीं है। केवल स्थानीय रूप से executed sessions ही कैप्चर किए जाते हैं।

## इसे चालू करें

Capture तब तक बंद रहता है जब तक आप इसे सक्षम नहीं करते। Collector को एक API key के साथ इंस्टॉल करें जिसमें `events:add` permission है ([API keys](/hi/agenteye/api-keys) देखें), और Codex capture को चालू करें:

```bash
curl -fsSL https://raw.githubusercontent.com/FailproofAI/agenteye-collector/main/install.sh \
  | sh -s -- --key <YOUR_API_KEY> --codex-enabled
```

यह collector को इंस्टॉल करता है, इसे एक background service के रूप में register करता है, और कैप्चरिंग शुरू करता है। पुष्टि करें कि यह चल रहा है:

```bash
agenteye-collector health
```

पहली बार चलाने पर, आपके मौजूदा Codex सेशन एक बार backfill किए जाते हैं और नई activity तब कुछ सेकंड में stream होती है। Codex की अपनी फाइलें केवल पढ़ी ही जाती हैं — कभी modified, moved, या deleted नहीं — और प्रत्येक सेशन बिल्कुल एक बार shipped होता है, भले ही restarts के पार हो।

---

## यह कहाँ दिखाई देता है

Captured sessions **Sessions** में दिखाई देते हैं, और उनकी events **Events** stream में, बिल्कुल किसी अन्य agent की तरह जिसे आप observe करते हैं — तो [session replay](/hi/agenteye/sessions), [search](/hi/agenteye/queries), [evaluations](/hi/agenteye/evaluations), और [alerts](/hi/agenteye/alerts) सभी इन पर काम करते हैं। Codex agent द्वारा filter करें उन्हें अपने आप पर देखने के लिए।

---

## गोपनीयता

Codex transcripts में पूरा सेशन होता है — command output, file contents, और कुछ भी जो Codex ने read या write किया — और इसमें secrets हो सकते हैं। Captured sessions को as-is shipped किया जाता है, तो capture को केवल उन मशीन और टीमों पर सक्षम करें जहाँ उस content को AgentEye में centralize करना appropriate है, और collector को केवल `events:add` के लिए scoped एक key दें। अपने data को isolated कैसे रखा जाता है यह देखने के लिए [Security](/hi/agenteye/security) देखें।
