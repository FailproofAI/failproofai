आपके इंजीनियर पहले से ही हर दिन OpenAI Codex चलाते हैं। Codex session capture उन कोडिंग सेशन को AgentEye में सामान्य सेशन और इवेंट्स के रूप में लाता है, ताकि आप उन्हें खोज सकें, रीप्ले कर सकें, और उन सभी चीजों के आगे उनका मूल्यांकन कर सकें जो आप देखते हैं। यह [Python SDK](/hi/agenteye/python-sdk) को पूरक बनाता है: SDK आपके द्वारा लिखे गए agents को माप करता है, जबकि यह आपकी टीम द्वारा पहले से चलाए जा रहे Codex काम को कैप्चर करता है — इसे चलाने के तरीके में कोई बदलाव किए बिना।

एक छोटा background collector Codex के स्थानीय सेशन transcripts को जैसे ही वे लिखे जाते हैं, पढ़ता है और उन्हें AgentEye को भेजता है। एक मशीन के प्रति एक collector एक साथ हर स्थानीय Codex surface को कैप्चर करता है — कोई प्रति-surface setup नहीं है।

एक ही collector अन्य agents को भी कैप्चर करता है — [OpenClaw](/hi/agenteye/openclaw-capture) और [Hermes](/hi/agenteye/hermes-capture) देखें। जो भी आप चलाते हैं उसे enable करें; एक भी collector एक बार में कई को कैप्चर कर सकता है।

---

## यह क्या कैप्चर करता है

हर Codex surface जो **स्थानीय रूप से** चलता है, समान on-disk सेशन transcripts का उत्पादन करता है, और collector उन सभी को उठाता है:

- Codex **CLI** और `codex exec`
- **VS Code / IDE extension**
- **desktop app**, जब यह स्थानीय रूप से सेशन चलाता है

प्रत्येक Codex सेशन एक AgentEye [session](/hi/agenteye/sessions) बन जाता है; इसके user और assistant messages, reasoning, tool calls, tool results, और token usage मिलान करने वाले [events](/hi/agenteye/event-stream) बन जाते हैं। वह surface जिससे प्रत्येक सेशन आया था (CLI, IDE, या desktop) दर्ज किया जाता है, ताकि आप उन्हें अलग बता सकें।

> **क्लाउड सेशन कैप्चर नहीं किए जाते हैं।** Desktop app तेजी से Codex क्लाउड में सेशन चलाता है और केवल उनके मेटाडेटा को मशीन पर रखता है — पढ़ने के लिए कोई स्थानीय transcript नहीं है। केवल स्थानीय रूप से निष्पादित सेशन कैप्चर किए जाते हैं।

---

## इसे चालू करें

Capture तब तक बंद है जब तक आप इसे enable नहीं करते। Collector को `events:add` permission वाली API key के साथ install करें (देखें [API keys](/hi/agenteye/api-keys)), और Codex capture को चालू करें:

```bash
curl -fsSL https://raw.githubusercontent.com/FailproofAI/agenteye-collector/main/install.sh \
  | sh -s -- --key <YOUR_API_KEY> --codex-enabled
```

यह collector को install करता है, इसे एक background service के रूप में register करता है, और कैप्चरिंग शुरू करता है। पुष्टि करें कि यह चल रहा है:

```bash
agenteye-collector health
```

पहले run पर, आपके मौजूदा Codex सेशन एक बार backfill किए जाते हैं और नई activity फिर कुछ सेकंड में stream होती है। Codex की अपनी फ़ाइलें केवल कभी read की जाती हैं — कभी modify, move, या delete नहीं की जाती हैं — और प्रत्येक सेशन बिल्कुल एक बार ship किया जाता है, restarts के भी पार।

---

## यह कहाँ दिखाई देता है

कैप्चर किए गए सेशन **Sessions** में दिखाई देते हैं, और उनके events **Events** stream में, किसी अन्य agent के समान जिसे आप देखते हैं — तो [session replay](/hi/agenteye/sessions), [search](/hi/agenteye/queries), [evaluations](/hi/agenteye/evaluations), और [alerts](/hi/agenteye/alerts) सभी उन पर काम करते हैं। उन्हें अपने आप पर देखने के लिए Codex agent द्वारा filter करें।

---

## गोपनीयता

Codex transcripts में पूरा सेशन होता है — command output, file contents, और कुछ भी जो Codex ने पढ़ा या लिखा सहित — और इसमें secrets हो सकते हैं। कैप्चर किए गए सेशन जैसे-तैसे ship किए जाते हैं, इसलिए capture को केवल उन मशीनों पर और उन टीमों के लिए enable करें जहाँ उस content को AgentEye में centralize करना उपयुक्त है, और collector को केवल `events:add` scope वाली key दें। अपने data को कैसे isolated रखा जाता है, इसके लिए [Security](/hi/agenteye/security) देखें।
