अपने agents द्वारा उत्पन्न प्रत्येक विफलता को एक स्थान पर देखें, समूहीकृत करें ताकि शोरगुल की burst को एक ही समस्या के रूप में पढ़ा जा सके। आपको "कुछ लाल है" से उस सटीक run तक एक-क्लिक पथ मिलता है जो टूट गया, बिना लाइव फीड को स्क्रॉल किए।

*Errors पृष्ठ: समय के साथ विफलताओं का एक histogram, प्रति incident एक पंक्ति में समान विफलताएँ संक्षिप्त।*

## हर विफलता, पहले से आपके लिए एकत्रित

जब कोई agent टूटता है, तो आपको लाइव event stream को स्क्रॉल करते हुए लाल पंक्तियों को दूर स्क्रॉल होने से पहले पकड़ने की कोशिश नहीं करनी चाहिए। **Errors** पृष्ठ आपके लिए संग्रह करता है। यह dashboard को लाल रंग में दिखाई देने वाली सभी चीजों को एक triage surface में एकत्रित करता है, ताकि आप जो पहली चीज देखते हैं वह यह है कि क्या विफल हो रहा है, न कि वहाँ जाने के लिए कहाँ।

और यह स्पष्ट लोगों से अधिक को पकड़ता है। स्पष्ट `error` events के साथ-साथ, Failproof AI Observability quiet failures को भी surface करता है: कोई भी `tool_result`, `hook_completed`, या `agent_end` जिसके payload में विफलता है, यहाँ दिखाई देता है। एक tool जो error return करता है, या एक hook जो badly exit करता है, अब आपसे नहीं छूटता क्योंकि कोई जोर से exception throw नहीं करता।

शीर्ष भर में, एक histogram समय के साथ errors को प्लॉट करता है। एक नज़र आपको बताता है कि क्या यह एक स्थिर background trickle है या एक spike जो कुछ मिनट पहले शुरू हुआ, इसलिए आप तुरंत जानते हैं कि क्या आपको जो कर रहे हैं उसे छोड़ना चाहिए।

हर observe surface की तरह, Errors पृष्ठ आपके organization के लिए scoped है और date range, environment, agent, और session द्वारा filters करता है। इसका अर्थ है कि आप fleet-wide list ले सकते हैं और इसे उस एक agent या एक environment तक narrow कर सकते हैं जिसकी आपको वास्तव में परवाह है।

## एक incident, सौ समान पंक्तियाँ नहीं

एक ही टूटी हुई dependency प्रति मिनट सैकड़ों बार एक ही error को fire कर सकती है। raw छोड़ दिए जाने पर, यह लगभग-समान पंक्तियों की एक दीवार है जो एक चीज को दफन करती है जिसे आपको वास्तव में देखने की आवश्यकता है।

Failproof AI Observability repeat failures को collapse करता है जो एक ही session और error type share करते हैं एक single row में। एक burst एक incident के रूप में दिखता है। आप समस्याएँ गिनते हैं, log lines नहीं, और जो signal मायने रखता है वह अपने volume से दबा दिए जाने के बजाय शीर्ष पर रहता है।

## "कुछ लाल है" से सटीक event तक

किसी भी पंक्ति पर क्लिक करें और सीधे उस run के session के अंदर आएँ, उस exact event पर positioned जो विफल हुई। कोई session IDs copying नहीं, कोई scrolling नहीं: आप सीधे वहाँ पहुँचते हैं, full execution graph एक glance दूर है ताकि आप देख सकें कि agent ने उन क्षणों में क्या किया जब यह टूट गया।

यदि आपके पास `alerts:write` है, तो हर पंक्ति में एक **+ alert** बटन भी है। इस पर क्लिक करें और Observability एक नया alert rule खोलता है जो उसी failure को फिर से पकड़ने के लिए पहले से भरा हुआ है। वह incident जिसे आपने अभी triage किया है वह बन जाता है जो अगली बार आपको page करता है, आपको दो बार आश्चर्यचकित करने के बजाय।

**इसे कहाँ खोजें:** **Errors** पृष्ठ dashboard के observe section में रहता है, `/<org-slug>/errors` पर।
