जिस पल आपका agent कुछ करता है, आप उसे देख सकते हैं। Event Stream आपकी production में हर agent की live pulse है: कोई इंतज़ार नहीं, कोई logs को grep करने की ज़रूरत नहीं, कोई अनुमान लगाना नहीं कि अभी-अभी क्या हुआ।

![The live Event Stream: colour-coded event rows tailing in real time, filterable by environment, agent, session, event type, and free text](/agenteye/images/events-stream.png)

*आपके org के हर agent से हर event, सबसे नया पहले, जैसे-जैसे होता है update होता है।*

## हर agent की live pulse

जब एक agent एक run शुरू करता है, एक model को कॉल करता है, एक tool को fire करता है, एक hook चलाता है, या एक error से टकराता है, तो row स्ट्रीम के top पर तुरंत दिखाई देता है। यह आपके पूरे organization में हर agent के हर event को tail करता है, सबसे नया पहले, ताकि आपके पास हमेशा एक current picture हो, stale नहीं।

इसका मतलब है कि किसी box पर log files को tail करने की कोई ज़रूरत नहीं, machines को grep करने की ज़रूरत नहीं, timestamps को manually stitch करने की ज़रूरत नहीं। आप एक page खोलते हैं और आप पहले से ही production को देख रहे हैं।

Rows को type के अनुसार colour-coded किया गया है, ताकि आप हर line को parse करने की जगह एक नज़र में स्ट्रीम को पढ़ सकें। एक नज़र में, हर row आपको यह दिखाता है:

- **इसका type**, colour-coded: `agent_start`, `model_response`, `tool_use`, `hook_completed`, `error`, और अन्य।
- **क्या हुआ का one-line summary**, ताकि आपको शायद ही कभी सिर्फ gist पाने के लिए कुछ खोलने की ज़रूरत हो।
- **Token counts** step के लिए।
- **A context-window fill badge** जहाँ यह लागू होता है, ताकि prompt growth और compaction के करीब आना उन्हें bite करने से पहले visible हों।

Live देखना मतलब आप एक bad deploy, एक runaway loop, या errors का एक burst तुरंत पकड़ते हैं, कल के log review में नहीं।

## वह एक run खोजें जो मायने रखता है

जब कुछ गलत दिखता है, तो आप firehose नहीं चाहते। आप वह single run चाहते हैं जो टूटा। Stream जल्दी filter करता है: environment के अनुसार, agent के अनुसार, session के अनुसार, event type के अनुसार, या free text के अनुसार।

Session id या agent id के अनुसार filter करें ताकि आप एक run को इसके पहले event से लेकर अंतिम event तक follow कर सकें। Event type के अनुसार filter करें ताकि एक single kind की activity को isolate कर सकें, उदाहरण के लिए org में हर `error` एक view में। Filters को stack करें ताकि आप "everything, everywhere" से "this agent, in prod, erroring" तक कुछ clicks में narrow कर सकें, फिर जो आप पाते हैं उस पर कार्य करें।

Free-text search सीधे एक message, एक tool name, या एक id को काट देता है जो आपके पास पहले से हाथ में है, तो एक customer report सेकंड में exact run में बदल जाती है।

## इसे कहाँ खोजें

Event Stream आपका org home है। Sign in करें और यह पहली surface है जहाँ आप land करते हैं, `/<org-slug>/` पर, ताकि triage शुरू होता है आप जैसे ही पहुंचते हैं।

इसके पीछे, आपके agents SDK के माध्यम से events emit करते हैं, collector उन्हें आपके Failproof AI Observability server को ship करता है, और stream उन्हें tail करता है जैसे वे infrastructure में पहुंचते हैं जिस पर आप control करते हैं। जब आप raw trail की जगह rolled-up view चाहते हैं, तो हर run के events एक single row में collapse करते हैं Sessions पर, एक click दूर।

यह raw source of truth है जिसके आधार पर हर दूसरी observe surface बनता है, तो जब एक number कहीं और गलत दिखता है, तो stream वह जगह है जहाँ आप confirm करते हैं कि वास्तव में क्या हुआ।
