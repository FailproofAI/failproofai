जिस क्षण आपका agent कुछ करता है, आप इसे देखते हैं। Event Stream production में हर agent पर आपकी live pulse है: कोई इंतज़ार नहीं, कोई log grepping नहीं, कोई अनुमान नहीं कि अभी क्या हुआ।

![The live Event Stream: colour-coded event rows tailing in real time, filterable by environment, agent, session, event type, and free text](/agenteye/images/events-stream.png)

*आपके org के हर agent का हर event, सबसे नया पहले, जैसे-जैसे यह होता है update हो रहा है।*

## हर agent पर आपकी live pulse

जब कोई agent एक run शुरू करता है, model को कॉल करता है, एक tool fire करता है, hook चलाता है, या error में आता है, तो row जिस पण्य यह होता है stream के top पर दिखाई देता है। यह आपके पूरे organization के हर agent के हर event को tail करता है, सबसे नया पहले, ताकि आपके पास हमेशा एक current picture हो, न कि पुरानी।

इसका मतलब यह है कि कहीं किसी box पर log files को tail करने की कोई ज़रूरत नहीं, machines के across grep करने की कोई ज़रूरत नहीं, timestamps को हाथ से जोड़ने की कोई ज़रूरत नहीं। आप एक page खोलते हैं और आप पहले से ही production को देख रहे हैं।

Rows को type से colour-coded किया जाता है, ताकि आप हर line को parse करने के बजाय एक नज़र में stream को पढ़ सकें। एक नज़र में, हर row आपको यह दिखाता है:

- **इसका type**, colour-coded: `agent_start`, `model_response`, `tool_use`, `hook_completed`, `error`, और बहुत कुछ।
- **क्या हुआ इसका one-line summary**, ताकि आपको rarely कुछ खोलने की ज़रूरत हो।
- **Token counts** इस step के लिए।
- **एक context-window fill badge** जहाँ यह applicable हो, ताकि prompt growth और एक approaching compaction दिखाई दे।

इसे live देखना मतलब आप एक bad deploy, एक runaway loop, या एक burst of errors को पकड़ते हैं जैसे यह होता है, कल के log review में नहीं।

## वह एक run खोजें जो मायने रखता है

जब कुछ गलत दिखता है, तो आप firehose नहीं चाहते हैं। आप वह single run चाहते हैं जो टूट गया। Stream fast filter करता है: environment के हिसाब से, agent के हिसाब से, session के हिसाब से, event type के हिसाब से, या free text के हिसाब से।

एक run को अपने पहले event से लेकर अपने last event तक follow करने के लिए session id या agent id के हिसाब से filter करें। एक single kind of activity को isolate करने के लिए event type के हिसाब से filter करें, उदाहरण के लिए पूरे org के सभी `error` एक view में। "सब कुछ, हर जगह" से "यह agent, prod में, erroring" में जाने के लिए filters को stack करें कुछ clicks में, फिर जो आप find करते हैं उस पर action लें।

Free-text search सीधे एक message, एक tool name, या एक id तक पहुंचता है जो आपके पास पहले से है, इसलिए एक customer report seconds में exact run में बदल जाता है।

## इसे कहाँ खोजें

Event Stream आपका org home है। Sign in करें और यह पहली surface है जिस पर आप land करते हैं, `/<org-slug>/` पर, इसलिए triage आपके arrive करने के दूसरे ही पल शुरू होता है।

इसके पीछे, आपके agents SDK के through events emit करते हैं, collector उन्हें आपके Failproof AI Observability server तक ship करता है, और stream उन्हें tail करता है जैसे वे infrastructure में arrive करते हैं जिसे आप control करते हैं। जब आप raw trail के बजाय rolled-up view चाहते हैं, तो हर run के events Sessions पर एक single row में collapse हो जाते हैं, एक click दूर।

यह raw source of truth है जिस पर हर दूसरी observe surface build होती है, इसलिए जब कोई number कहीं और गलत दिखता है, तो stream वह जगह है जहाँ आप confirm करते हैं कि actually क्या हुआ।
