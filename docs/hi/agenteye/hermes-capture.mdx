[Hermes](https://hermes-agent.nousresearch.com) आपकी टीम को उसी जगह से जवाब देता है जहाँ वह पहले से काम कर रही है — Slack, Telegram, CLI, scheduled runs। Hermes session capture इन सभी को AgentEye में साधारण सेशन और events के रूप में लाता है, इसलिए जिस assistant से आपकी टीम हर दिन बात करती है वह उतना ही observable है जितना कि agents जो आप स्वयं लिखते हैं।

एक छोटा सा background collector Hermes के local session store को पढ़ता है जैसे ही वह लिखा जाता है और सेशन को AgentEye को भेजता है। यह [Codex](/hi/agenteye/codex-capture) और [OpenClaw](/hi/agenteye/openclaw-capture) capture के समान तरीके से काम करता है, और एक collector एक साथ कई को capture कर सकता है।

---

## यह क्या capture करता है

मशीन पर हर Hermes session को capture किया जाता है, भले ही वह किस channel से आया हो। प्रत्येक एक AgentEye [session](/hi/agenteye/sessions) बन जाता है; इसके user और assistant messages, tool calls, और tool results matching [events](/hi/agenteye/event-stream) बन जाते हैं।

जिस channel से एक session शुरू हुआ — Slack, Telegram, CLI, या एक scheduled run — वह session पर recorded किया जाता है, इसलिए आप उन्हें अलग बता सकते हैं और एक बार में एक को filter कर सकते हैं। इसके साथ वह model आता है जिस पर session चला, chat और person जिससे यह शुरू हुआ, और जब एक session ने दूसरे को spawn किया, तो इसके parent के लिए link।

Sessions उसी समय appear होते हैं जब Hermes उन्हें शुरू करता है, चाहे कुछ भी कहा गया हो या नहीं, और एक turn का reply और इसके tool calls उस क्रम में रहते हैं जिस क्रम में वह actually happened। जब एक session समाप्त होता है तो आप यह भी प्राप्त करते हैं कि यह क्यों समाप्त हुआ, इसकी cost क्या थी, और इसने कितने tokens का उपयोग किया।

## इसे चालू करें

Capture तब तक बंद रहता है जब तक आप इसे enable नहीं करते। Collector को एक API key के साथ install करें जिसके पास `events:add` permission है ([API keys](/hi/agenteye/api-keys) देखें), और Hermes capture को चालू करें:

```bash
curl -fsSL https://raw.githubusercontent.com/FailproofAI/agenteye-collector/main/install.sh \
  | sh -s -- --key <YOUR_API_KEY> --hermes-enabled
```

यह collector को install करता है, इसे एक background service के रूप में register करता है, और capture शुरू करता है। पुष्टि करें कि यह चल रहा है:

```bash
agenteye-collector health
```

एक ही मशीन पर एक से अधिक agents को capture कर रहे हैं? उसी command में प्रत्येक का flag जोड़ें — उदाहरण के लिए `--hermes-enabled --codex-enabled`।

पहली बार चलाने पर, आपके existing Hermes sessions एक बार backfill किए जाते हैं और नई activity फिर कुछ ही seconds में stream होती है। Hermes का अपना data केवल read किया जाता है — कभी भी modify या delete नहीं किया जाता — और प्रत्येक message एक बार भेजा जाता है, restarts के भी बाद।

`health` यह भी बताता है कि क्या collector द्वारा capture किया गया सब कुछ actually AgentEye तक पहुँचा। अगर एक batch deliver नहीं किया जा सका तो वह keep किया जाता है और retry किया जाता है rather than discarded किया जाता है, और check तब तक unhealthy report करता है जब तक कुछ भी outstanding है — तो "healthy" मतलब आपका data arrive हुआ, merely नहीं कि process alive है।

## यह कहाँ दिखाई देता है

Captured sessions **Sessions** में दिखाई देते हैं, और उनके events **Events** stream में, किसी भी अन्य agent की तरह जिसे आप observe करते हैं — इसलिए [session replay](/hi/agenteye/sessions), [search](/hi/agenteye/queries), [evaluations](/hi/agenteye/evaluations), और [alerts](/hi/agenteye/alerts) सभी उन पर काम करते हैं। Hermes agent द्वारा filter करें उन्हें अपने आप पर देखने के लिए।

---

## Privacy

Hermes sessions में full transcript होता है — command output, file contents, और कुछ भी जो agent ने read या write किया — सहित, और इसमें secrets हो सकते हैं। Captured sessions as-is भेजे जाते हैं, इसलिए capture केवल उसी जगह enable करें जहाँ उस content को AgentEye में centralize करना appropriate है, और collector को एक key दें जो केवल `events:add` के लिए scoped है। [Security](/hi/agenteye/security) देखें कि आपके data को कैसे isolated रखा जाता है।
