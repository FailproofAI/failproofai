[Hermes](https://hermes-agent.nousresearch.com) आपकी टीम को उन्हीं जगहों से जवाब देता है जहाँ वे पहले से काम करते हैं — Slack, Telegram, CLI, scheduled runs। Hermes session capture इन सभी को AgentEye में ordinary sessions और events के रूप में लाता है, इसलिए जिस assistant से आपकी टीम रोज बात करती है, वह उतना ही observable है जितना कि agents जो आप खुद लिखते हैं।

एक छोटा background collector Hermes के local session store को पढ़ता है जैसे-जैसे वह लिखा जाता है और sessions को AgentEye में भेजता है। यह [Codex](/hi/agenteye/codex-capture) और [OpenClaw](/hi/agenteye/openclaw-capture) capture के समान तरीके से काम करता है, और एक collector एक साथ कई को capture कर सकता है।

---

## यह क्या capture करता है

Machine पर हर Hermes session capture होता है, चाहे वह किसी भी channel से आया हो। प्रत्येक एक AgentEye [session](/hi/agenteye/sessions) बन जाता है; इसके user और assistant messages, tool calls, और tool results संबंधित [events](/hi/agenteye/event-stream) बन जाते हैं।

जिस channel से session शुरू हुआ था — Slack, Telegram, CLI, या scheduled run — वह session पर record होता है, ताकि आप उन्हें अलग बता सकें और एक बार में एक को filter कर सकें। इसके साथ वह model भी आता है जिस पर session चला, chat और व्यक्ति जिससे यह शुरू हुआ था, और जब session ने दूसरा spawn किया था, तो अपने parent के साथ link।

Sessions तुरंत दिखाई देते हैं जब Hermes उन्हें शुरू करता है, चाहे कुछ कहा गया हो या नहीं, और एक turn का reply और इसके tool calls वही क्रम में रहते हैं जिस क्रम में वे वास्तव में घटे। जब session समाप्त होता है, तो आप यह भी जानते हैं कि इसे क्यों समाप्त किया गया, इसकी cost क्या थी, और इसने कितने tokens का उपयोग किया।

## इसे चालू करें

Capture तब तक off रहता है जब तक आप इसे enable न करें। `events:add` permission वाली API key के साथ collector install करें (देखें [API keys](/hi/agenteye/api-keys)), और Hermes capture चालू करें:

```bash
curl -fsSL https://raw.githubusercontent.com/FailproofAI/agenteye-collector/main/install.sh \
  | sh -s -- --key <YOUR_API_KEY> --hermes-enabled
```

यह collector को install करता है, इसे background service के रूप में register करता है, और capturing शुरू करता है। confirm करें कि यह चल रहा है:

```bash
agenteye-collector health
```

एक ही machine पर एक से अधिक agent capture कर रहे हैं? उसी command में प्रत्येक का flag जोड़ें — उदाहरण के लिए `--hermes-enabled --codex-enabled`।

पहली बार run करने पर, आपके मौजूदा Hermes sessions एक बार backfill होते हैं और नई activity फिर कुछ सेकंड में stream होती है। Hermes के अपने data को केवल read किया जाता है — कभी modify या delete नहीं किया जाता — और प्रत्येक message एक बार shipped होता है, restarts के बीच भी।

`health` आपको यह भी बताता है कि क्या collector द्वारा capture किया गया सभी कुछ वास्तव में AgentEye तक पहुंचा। यदि कोई batch deliver नहीं हो सकती तो वह keep की जाती है और retry की जाती है, discard नहीं की जाती, और check unhealthy report करता है जब तक कुछ outstanding है — तो "healthy" का मतलब है कि आपका data पहुंचा, केवल यह नहीं कि process alive है।

## यह कहाँ दिखाई देता है

Captured sessions **Sessions** में दिखाई देते हैं, और उनकी events **Events** stream में, किसी भी अन्य agent के समान जिसे आप observe करते हैं — तो [session replay](/hi/agenteye/sessions), [search](/hi/agenteye/queries), [evaluations](/hi/agenteye/evaluations), और [alerts](/hi/agenteye/alerts) सभी उन पर काम करते हैं। उन्हें अकेले देखने के लिए Hermes agent द्वारा filter करें।

---

## गोपनीयता

Hermes sessions में पूरा transcript होता है — command output, file contents, और कुछ भी जो agent ने read या write किया — और इसमें secrets हो सकते हैं। Captured sessions as-is shipped होते हैं, इसलिए capture केवल उन जगहों पर enable करें जहाँ उस content को AgentEye में centralize करना उपयुक्त हो, और collector को `events:add` तक scoped की गई key दें। देखें [Security](/hi/agenteye/security) कि आपके data को कैसे isolated रखा जाता है।
