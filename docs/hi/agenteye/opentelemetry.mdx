OpenTelemetry आपको standard OTLP/HTTP protocol का उपयोग करके agent traces, logs, और metrics को FailproofAI Cloud को भेजने देता है। यह वैकल्पिक है। आपकी मौजूदा FailproofAI integrations इसे सक्षम किए बिना काम करती रहती हैं।

## एक key प्राप्त करें

OTLP ingest हर organisation के लिए हमेशा चालू रहता है; सक्षम करने के लिए कुछ भी नहीं है। `events:add` अनुमति वाली Cloud API key का उपयोग करें, वही अनुमति जो agent reporting के लिए उपयोग की जाती है।

Dashboard में, **home → first-run setup** के पास एक **connect with OpenTelemetry** कार्ड है: **create collector key** एक `events:add` key बनाता है, इसे exporter variables के साथ एक बार दिखाता है, और connection status दिखाता है। आप **settings → api keys** के तहत एक और भी बना सकते हैं **new key** के तहत **sending logs only** चुनकर।

## एक coding agent को कनेक्ट करें

`failproofai config` के साथ अपनी machine को कनेक्ट करें, फिर एक agent चुनें:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

setup command Claude Code, Codex, और Copilot को support करता है और जैसा उपयुक्त हो Cloud या एक local authenticated relay चुनता है। Copilot स्वचालित रूप से local relay का उपयोग करता है। relay का उपयोग करने से पहले अपने configured FailproofAI daemon को शुरू करें।

यदि FailproofAI पहले से किसी agent की session transcripts भेज रहा है, तो setup पूछता है कि क्या उस agent को OTEL पर स्विच करना है। डिफ़ॉल्ट No है। स्वीकृति उस agent के लिए transcript uploads को बंद करती है; यह policy enforcement या अन्य agents से reporting को नहीं बदलता है।

## एक application को कनेक्ट करें

इन environment variables के साथ अपने application की OpenTelemetry instrumentation का उपयोग करें:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

endpoint Cloud का OTLP base है, `https://app.befailproof.ai/otel`; आपका exporter स्वयं `/v1/traces`, `/v1/logs`, या `/v1/metrics` को जोड़ता है। Per-signal variables जैसे `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` को as-is उपयोग किया जाता है, इसलिए उन्हें full path की आवश्यकता है, उदाहरण के लिए `https://app.befailproof.ai/otel/v1/logs`।

`<key>` को अपनी API key से बदलें। secret को shell history, screen recordings, और committed configuration से दूर रखें। एक configured machine के लिए, `failproofai otel env --service my-agent` अपनी मौजूदा key के साथ ब्लॉक प्रिंट करता है। इसका output एक credential रखता है।

Cloud OTLP/HTTP exports को traces, logs, और metrics के लिए स्वीकार करता है, protobuf या JSON के रूप में, gzip-compressed requests सहित। यह OTLP/gRPC को स्वीकार नहीं करता है।

Metrics को exporter compatibility के लिए स्वीकार किया जाता है लेकिन store या display नहीं किए जाते हैं। समर्थित agent traces और coding-agent logs sessions बन जाते हैं; fields जो agent export नहीं करता वह absent रहते हैं।

## Prompt text को कैप्चर करें

<Warning>
Text capture में prompts, tool arguments, और अन्य sensitive content शामिल हो सकता है। `failproofai otel enable` इसे चालू करता है। prompt और tool-detail capture को बंद रखने के लिए `--no-content` जोड़ें।
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

एक agent के लिए जिसे आप manually configure करते हैं, अपने content-capture controls का उपयोग करें:

<Tabs>
  <Tab title="Claude Code">
    इन variables को अपने agent की environment में ऊपर दिए गए application block के साथ जोड़ें:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    prompts और tool details को capture करने से बचने के लिए दोनों content variables को `0` पर सेट करें।
  </Tab>
  <Tab title="Codex">
    Codex की user configuration में, इसकी OTEL settings का उपयोग करें:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex conversation content logs में है; internal runtime traces और metrics को disabled रखें। Codex आपके द्वारा दिया गया complete endpoint का उपयोग करता है। prompts को छोड़ने के लिए `log_user_prompt` को `false` पर सेट करें; setup command एक explicit `false` को preserve करता है।
  </Tab>
  <Tab title="Gemini CLI">
    local relay के साथ Gemini की telemetry settings का उपयोग करें:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI को `failproofai otel enable` द्वारा support नहीं किया जाता है। इसे manually अपने authenticated collector के साथ configure करें। prompt capture के लिए नहीं `logPrompts` को `false` पर सेट करें।
  </Tab>
  <Tab title="Copilot in VS Code">
    इन VS Code user settings का उपयोग करें:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    authenticated relay को सक्षम करने के लिए `failproofai otel enable copilot` चलाएँ। content को छोड़ने के लिए `captureContent` को `false` पर सेट करें।
  </Tab>
</Tabs>

## Setup को जाँचें या पूर्ववत करें

relay temporary network और server failures के माध्यम से telemetry को बनाए रखता है और recovery के बाद retry करता है। एक permanent `400` rejection, एक event भी जो store करने के लिए बहुत बड़ा है, payload को सही करने की आवश्यकता है। relay rejected batch को inspect के लिए रखता है इसके बजाय बार-बार इसे भेजने के।

एक `401` या `403` के बाद, credential को एक ऐसी key से बदलें जो same organisation के लिए `events:add` को grant करे। Reconnecting स्वचालित रूप से credentials के लिए refused OTLP exports को resend नहीं करता; उन batches को recover करने के लिए अपने operator से पूछें। उन्हें अपने original organisation में रखें।

```bash
failproofai otel status
failproofai otel disable all
```

Status FailproofAI द्वारा manage किए गए settings को उन telemetry से अलग करता है जिन्हें आपने कहीं और configure किया है। Disable पिछली manage की गई settings को बहाल करता है और agent की पिछली transcript-upload choice को बहाल करता है।
