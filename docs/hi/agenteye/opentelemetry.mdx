OpenTelemetry आपको agent traces, logs, और metrics को FailproofAI Cloud में standard OTLP/HTTP protocol का उपयोग करके भेजने देता है। यह optional है। आपके existing FailproofAI integrations इसे enable किए बिना काम करते रहेंगे।

## अपने organisation के लिए ingest को चालू करें

एक organisation admin **Settings → OpenTelemetry** खोलता है और ingest को चालू करता है। `events:add` permission वाली Cloud API key का उपयोग करें, यही permission agent reporting के लिए भी उपयोग की जाती है।

यदि ingest बंद है, तो Cloud OTLP exports को refuse करता है, इसलिए `failproofai otel enable` कोई प्रभाव नहीं डालता और आपके agents sessions को सामान्य तरीके से भेजते रहते हैं। organisation switch को जांचने के लिए `failproofai otel status` चलाएं, और एक admin से इसे चालू करने के लिए कहें।

## एक coding agent को कनेक्ट करें

`failproofai config` के साथ अपनी machine को कनेक्ट करें, फिर एक agent चुनें:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

setup command Claude Code, Codex, और Copilot को support करता है और जहां आवश्यक हो Cloud या local authenticated relay को चुनता है। Copilot स्वचालित रूप से local relay का उपयोग करता है। relay का उपयोग करने से पहले अपने configured FailproofAI daemon को start करें।

यदि FailproofAI पहले से किसी agent के session transcripts भेज रहा है, तो setup पूछता है कि उस agent को OTEL में switch करें या नहीं। डिफ़ॉल्ट नहीं है। स्वीकृति देने से उस agent के लिए transcript uploads रुक जाते हैं; यह policy enforcement या अन्य agents से reporting में परिवर्तन नहीं करता है।

## एक application को कनेक्ट करें

इन environment variables के साथ अपने application के OpenTelemetry instrumentation का उपयोग करें:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

endpoint Cloud का OTLP base है, `https://app.befailproof.ai/otel`; आपका exporter स्वयं `/v1/traces`, `/v1/logs`, या `/v1/metrics` को append करता है। Per-signal variables जैसे `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` जैसे-जैसे हैं उपयोग किए जाते हैं, इसलिए उन्हें full path की आवश्यकता है, उदाहरण के लिए `https://app.befailproof.ai/otel/v1/logs`।

`<key>` को अपनी API key से replace करें। secret को shell history, screen recordings, और committed configuration से बाहर रखें। एक configured machine के लिए, `failproofai otel env --service my-agent` इसकी existing key के साथ block को print करता है। इसके output में एक credential होता है।

Cloud traces, logs, और metrics के लिए OTLP/HTTP exports को स्वीकार करता है, protobuf या JSON के रूप में, gzip-compressed requests सहित। यह OTLP/gRPC को स्वीकार नहीं करता है।

Metrics को exporter compatibility के लिए स्वीकार किया जाता है लेकिन stored या displayed नहीं किए जाते हैं। Supported agent traces और coding-agent logs sessions बन जाते हैं; जो fields agent export नहीं करता वे अनुपस्थित रहते हैं।

## Prompt text को capture करें

<Warning>
Text capture में prompts, tool arguments, और अन्य sensitive content शामिल हो सकते हैं। `failproofai otel enable` इसे चालू करता है। `--no-content` जोड़ें ताकि prompt और tool-detail capture बंद रहें।
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

एक agent के लिए जिसे आप manually configure करते हैं, इसके अपने content-capture controls का उपयोग करें:

<Tabs>
  <Tab title="Claude Code">
    इन variables को अपने agent के environment में ऊपर दिए गए application block के साथ add करें:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    prompts और tool details को capture करने से बचने के लिए दोनों content variables को `0` पर set करें।
  </Tab>
  <Tab title="Codex">
    Codex के user configuration में, इसकी OTEL settings का उपयोग करें:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex conversation content logs में है; internal runtime traces और metrics को disabled रखें। Codex आप जो complete endpoint provide करते हैं उसका उपयोग करता है। prompts को बाहर छोड़ने के लिए `log_user_prompt` को `false` पर set करें; setup command एक explicit `false` को preserve करता है।
  </Tab>
  <Tab title="Gemini CLI">
    Local relay के साथ Gemini की telemetry settings का उपयोग करें:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI `failproofai otel enable` द्वारा supported नहीं है। इसे manually अपने authenticated collector के साथ configure करें। prompt capture के लिए नहीं होने के लिए `logPrompts` को `false` पर set करें।
  </Tab>
  <Tab title="Copilot in VS Code">
    ये VS Code user settings का उपयोग करें:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Authenticated relay को enable करने के लिए `failproofai otel enable copilot` चलाएं। content को omit करने के लिए `captureContent` को `false` पर set करें।
  </Tab>
</Tabs>

## Setup को जांचें या undo करें

```bash
failproofai otel status
failproofai otel disable all
```

Status FailproofAI द्वारा managed settings को उन telemetry से अलग करता है जिन्हें आपने कहीं और configure किया है। Disable पिछली managed settings और agent की पिछली transcript-upload choice को restore करता है।
