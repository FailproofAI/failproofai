अपने कोडिंग एजेंट को बताएं *"इस एजेंट में Failproof AI Observability जोड़ें"* और इसे अपने लूप को पढ़ने, यह पता लगाने, कि उपकरणीकरण कहाँ होना चाहिए, इसे लिखने, और काम पूरा करने से पहले घटनाओं को सत्यापित करने दें।

**Python SDK skill** (`agenteye-python-sdk`) एक *Agent Skill* है: निर्देशों का एक फोल्डर जिसे Claude Code या Codex जैसे कोडिंग एजेंट द्वारा आवश्यकता पड़ने पर लोड किया जाता है। यह एजेंट को [Python SDK](/hi/agenteye/python-sdk) का उपयोग करना सिखाता है — यह एक लाइब्रेरी नहीं है, और यह SDK के काम करने के तरीके में कुछ नहीं बदलता।

## उपकरणीकरण लिखना आसान है और चुप-चाप गलत होना भी आसान है

SDK छोटा है: तेरह घटना विधियाँ, सभी कीवर्ड-only हैं। एक कोडिंग एजेंट [Python SDK](/hi/agenteye/python-sdk) संदर्भ को पढ़ सकता है और एक मिनट में प्रशंसनीय उपकरणीकरण तैयार कर सकता है।

समस्या यह है कि यह SDK गलत होने पर कोई त्रुटि नहीं उठाता, और गलत उपकरणीकरण बिल्कुल सही उपकरणीकरण जैसा दिखता है जब तक कोई डैशबोर्ड खोलकर इसे खाली न पाए। जो गलतियाँ वास्तविक समय बर्बाद करती हैं वे सभी मौन हैं:

| गलती | आप क्या देखते हैं |
|---|---|
| कोई `agent_start` नहीं | हर घटना उतरती है। शून्य सेशन। |
| पर्यावरण कभी सेट नहीं किया गया | सब कुछ काम करता है, `dev` के तहत दाखिल। |
| `outcome="failure"` | रन हरे रंग में दिखता है — केवल `failed`, `error`, `timeout`, `rejected` गिनती करते हैं। |
| एक गलत वर्तनी वाली फील्ड का नाम | स्वीकृत और एक नई फील्ड के रूप में संग्रहीत। |
| थ्रेड पूल से उत्सर्जित घटनाएँ | चुप-चाप हटा दी गई। |

इनमें से कोई भी त्रुटि नहीं उठाता। ये परीक्षणों में दिखाई नहीं देते। ये सभी skill में हैं, एक अनुबंध के रूप में कथित हैं जिसमें वह जाँच है जो इसे पकड़ता है।

## यह क्या करता है, क्रम में

Skill वही तीन चरण चलाता है जो एक सावधान इंजीनियर करेगा:

1. **योजना बनाएँ।** यह आपके एजेंट लूप को पढ़ता है और दो प्रश्न पूछता है जिनका उत्तर केवल आप दे सकते हैं: एक रन क्या मायने रखता है (आपका `session_id`), और कौन से अलग करने योग्य अभिनेता हैं (आपका `agent_id`)। यह कोड लिखने से पहले इन पर सहमति प्राप्त करता है, क्योंकि बाद में उन्हें बदलने से आपका इतिहास विभाजित हो जाता है और ट्रेंड टूट जाते हैं।
2. **लिखें।** यह प्रति रन एक बार पहचान को बाँधता है बजाय इसे हर कॉल साइट के माध्यम से थ्रेड करने के, और यह एक समवर्ती-सुरक्षित आकार चुनता है — एक ऐसी विवरण जो महत्वपूर्ण है, क्योंकि स्पष्ट शॉर्टकट चुप-चाप दो ओवरलैपिंग रन को एक सेशन में मिला देता है।
3. **सत्यापित करें।** यह आपके एजेंट को चलाता है और परिणामी घटना फाइलों को पढ़ता है, यह जाँचता है कि `agent_start` मौजूद है, पर्यावरण सही है, और एक रन ने एक सेशन का उत्पादन किया है।

वह तीसरा चरण है जिसे लोग छोड़ देते हैं। SDK घटनाओं को स्थानीय फाइलों में लिखता है, इसलिए एक संपूर्ण एकीकरण लैपटॉप पर बिना सर्वर, API कुंजी या नेटवर्क के सिद्ध किया जा सकता है — जो बिल्कुल वही कारण है कि skill इसे करने पर जोर देता है।

## यह अन्य skills से कैसे संबंधित है

तीन skills, एक स्वच्छ विभाजन:

| Skill | इसे तब प्राप्त करें जब | यह क्या स्पर्श करता है |
|---|---|---|
| **Python SDK skill** (यह पृष्ठ) | आप चाहते हैं कि आपका एजेंट *उत्सर्जित* करे दूरदर्शिता — "अवलोकनीयता जोड़ें", "मेरा एजेंट क्यों नहीं दिख रहा है?" | आपके एजेंट के रिपो में कोड लिखता है। कुछ भी नहीं पढ़ता। |
| **[Evaluator skill](/hi/agenteye/evaluator-skill)** | आप चाहते हैं *स्कोर* करने के लिए रन — "हमें क्या मापना चाहिए?" | आपके रिपो में कोड लिखता है; दूरदर्शिता पढ़ता है |
| **[CLI skill](/hi/agenteye/cli-skill)** | आप चाहते हैं *पढ़ने* के लिए क्या हुआ, या अपने डिप्लॉयमेंट को संचालित करें | CLI को आप के रूप में चलाता है, परिवर्तन सहित |

वे उस क्रम में हस्तांतरित करते हैं: यह skill घटनाएँ बहता है, मूल्यांकन उन्हें स्कोर करता है, CLI उन्हें वापस पढ़ता है। जब तक आपका एजेंट सेशन उत्सर्जित नहीं करता, तब तक मूल्यांकन करने के लिए कुछ नहीं है और पढ़ने के लिए कुछ नहीं है, इसलिए यदि आप शुरुआत से शुरू कर रहे हैं, तो यहाँ से शुरू करें।

## पूर्वापेक्षाएँ

1. **Python 3.10+** और एजेंट कोडबेस जिसे आप उपकरणीकृत करना चाहते हैं।
2. **SDK।** इसे ग्राहकों को सार्वजनिक इंडेक्स से सार्वजनिक व्हील के बजाय निजी रूप से वितरित किया जाता है — आपकी शुरुआत इसे कैसे प्राप्त करें और इंस्टॉल करें यह बताती है। Skill इंस्टॉल पथ जानता है और यदि यह इसे नहीं खोज सकता तो आपसे पूछेगा बजाय अनुमान लगाने के।
3. **कुछ नहीं।** कोई डैशबोर्ड लॉगिन नहीं, कोई API कुंजी नहीं, कोई नेटवर्क नहीं। Skill उन घटना फाइलों के विरुद्ध सत्यापित करता है जो SDK लिखती है, इसलिए यह ऑफलाइन काम पूरा कर सकता है और अपना काम साबित कर सकता है।

## इसे कहाँ प्राप्त करें

Skill सार्वजनिक [`FailproofAI/skills`](https://github.com/FailproofAI/skills) संग्रह में रहता है:

```bash
npx skills add FailproofAI/skills --skill agenteye-python-sdk -a claude-code
```

हर परियोजना के लिए इसे इंस्टॉल करने के लिए `-g` जोड़ें केवल वर्तमान के बजाय, और `--copy` यदि आपका पर्यावरण symlinks का पालन नहीं करता। Codex के लिए, `-a codex` पास करें।

## इसे मैन्युअल रूप से इंस्टॉल करना

Agent Skills फोल्डर हैं जिनमें `SKILL.md` और संदर्भ हैं। यदि आप installer का उपयोग नहीं करना चाहते हैं:

- **Claude Code**: `agenteye-python-sdk/` फोल्डर को `~/.claude/skills/` (हर परियोजना) या `<your-repo>/.claude/skills/` (केवल वह रिपो) में कॉपी करें। Claude Code इसे स्वचालित रूप से खोज लेता है — `/skills` सूची जाँचें, या बस कुछ ऐसा पूछें जो इससे मेल खाता हो।
- **Codex**: Codex एक ही `SKILL.md` पढ़ता है। बंडल की गई `agents/openai.yaml` `allow_implicit_invocation: true` सेट करती है, इसलिए यह तब स्वचालित रूप से चयनित होता है जब कोई कार्य मेल खाता है; अन्यथा इसे `$agenteye-python-sdk` के रूप में आह्वान करें।

**कोड रखने वाली रिपॉजिटरी में अपने एजेंट को चलाएँ जिसे आप उपकरणीकृत करना चाहते हैं** — skill कोड का प्रस्ताव करने से पहले आपके एजेंट लूप को पढ़ता है।

## एक सेशन कैसा दिखता है

```text
आप   ▸ इस एजेंट में Failproof AI Observability जोड़ें।

एजेंट ▸ आपके लूप को पढ़ा — tools.py में एक tool dispatcher, llm.py में एक Anthropic
        wrapper। कोड लिखने से पहले दो प्रश्न।

        एक रन क्या मायने रखता है? आप सेशन को समवर्ती रूप से संभालते हैं, इसलिए मैं
        request id का उपयोग करूँगा जो आपके पास पहले से ctx.request_id में है —
        फिर एक सेशन यहाँ और आपके लॉग में एक request एक ही स्ट्रिंग हैं।

        और अभिनेता कौन हैं? मुझे एक planner पथ और एक researcher
        पथ दिखता है। उन्हें अलग से लेबल करें, या क्या वह आपके लिए एक एजेंट है?

आप   ▸ Request id सही है। वे एक एजेंट हैं, इसे "assistant" कहें।

एजेंट ▸ पूरा हुआ। Dispatcher और LLM client को लपेटा; agent_start और
        agent_end bracket handle_request, त्रुटि पथ सहित। पहचान के लिए
        एक context-local का उपयोग किया — आपका dispatcher thread pool में tools चलाता है,
        और सरल दृष्टिकोण से समवर्ती रन को बिना कहे एक सेशन में मिल सकते हैं।

        एक वास्तविक रन के विरुद्ध सत्यापित: 11 घटनाएँ 4 फाइलों में —
        agent_start, model_request/response, tool_use/tool_result x3,
        agent_end (outcome=success)। environment=production, प्रति request एक सेशन,
        जोड़ी हुई अवधि।

        एक चीज़ मैंने नहीं की: आपके worker pool in batch.py सीधे executor को
        सबमिट करता है, इसलिए वहाँ से घटनाएँ हटा दी जाएँगी। क्या आप चाहते हैं
        कि मैं वह भी ठीक करूँ?
```

ध्यान देने योग्य पैटर्न: यह कोड पढ़ता है प्रस्ताव देने से पहले, केवल उन प्रश्नों पूछता है जिनका आप उत्तर दे सकते हैं, एक id का पुन: उपयोग करता है जो आपके पास पहले से है, समवर्ती-सुरक्षित आकार चुनता है *क्योंकि* यह thread pool देखता है, और सफलता घोषित करने के बजाय **वास्तविक घटनाओं को पढ़कर सत्यापित करता है** — फिर वह एक जगह का संकेत देता है जहाँ वह जानता है चुप-चाप असफल होगा।

## आप इससे क्या पूछ सकते हैं

- *"मेरा एजेंट डैशबोर्ड पर क्यों नहीं दिख रहा है?"* → सीढ़ी पर चलता है: क्या घटनाएँ लिखी जा रही हैं, क्या `agent_start` है, क्या पर्यावरण सही है, क्या संग्राहक एक ही जगह पढ़ रहा है।
- *"सब कुछ dev के तहत उतर रहा है।"* → पर्यावरण कभी सेट नहीं किया गया था, या बाद में कॉल द्वारा रीसेट किया गया था।
- *"टोकन ट्रैकिंग जोड़ें।"* → आपके LLM wrapper को खोजता है और मॉडल, stop reason, और उपयोग रिकॉर्ड करता है।
- *"उप-एजेंट को भी उपकरणीकृत करें।"* → एक सेशन, अलग एजेंट लेबल, अपने माता-पिता के तहत नेस्टेड।
- *"उपकरणीकरण के लिए परीक्षण लिखें।"* → SDK को एक अस्थायी निर्देशिका की ओर इंगित करता है और घटनाओं पर assert करता है जो इसने लिखीं।

## क्या ध्यान रखें

**इसे सत्यापित करने दें।** वह चरण जो इस skill को उपयोग करने योग्य बनाता है आखिरी है — आपके एजेंट को चलाना और घटनाओं को वापस पढ़ना। एक एजेंट जो उपकरणीकरण लिखता है और रुकता है, आसान आधा किया है, और आधा जो चुप-चाप असफल होता है दूसरा है।

**नाम तय करें कोड से पहले।** `session_id` और `agent_id` वे अक्ष हैं जिनके द्वारा हर सतह समूह बनाती है। बाद में उन्हें नाम बदलने से इतिहास विभाजित हो जाता है: पुराने रन पुरानी लेबल रखते हैं और आपके ट्रेंड टूट जाते हैं। Skill पूछेगा; उत्तर एक मिनट के विचार के लायक है।

**यदि आपका एजेंट सार्वजनिक इंडेक्स से SDK स्थापित करने का प्रस्ताव देता है, तो skill लोड नहीं हुई है।** SDK निजी रूप से वितरित किया जाता है। वह प्रस्ताव एक विश्वसनीय संकेत है कि आपका कोडिंग एजेंट अनुमान लगा रहा है बजाय skill का पालन करने के — इसे वहाँ रोकें और जाँचें कि skill स्थापित है।

इसके आगे इसका विस्फोट त्रिज्या छोटी है: यह आपकी कार्य निर्देशिका में कोड लिखता है और घटना फाइलें जहाँ आप कहते हैं। यह अपने डिप्लॉयमेंट से कुछ नहीं पढ़ता और इसमें कुछ नहीं बदलता।
