अपने AI agents ने production में क्या किया, यह बिल्कुल देखें: हर agent run, tool call, model request, hook, और human intervention। Failproof AI Observability Python SDK आपके agent code के अंदर से उस trail को record करता है ताकि आप debug, audit, और evaluate कर सकें कि क्या हुआ। जब भी आप चाहें कि Failproof AI Observability आपके agents को observe करे, तब इसका उपयोग करें।

SDK internally structured events को local JSONL files में write करता है, और collector daemon इन्हें pick up करके automatically platform को भेज देता है। आपको इन फ़ाइलों को स्वयं manage नहीं करना पड़ता।

## Installation

SDK को customers के लिए private wheel के रूप में distribute किया जाता है, न कि public package index से। आपके onboarding में कवर किया गया है कि इसे कैसे obtain करें, install करें, और pin करें — अगर आपको access की ज़रूरत है तो अपने Failproof AI contact से बात करें।

एक बार install हो जाने के बाद, confirm करें कि आपके पास है:

```bash
python -c "import agenteye; print(agenteye.__version__)"
```

क्या coding agent को पूरे integration को करने देना पसंद है? [Python SDK Agent Skill](/hi/agenteye/python-sdk-skill) install path जानता है, instrumentation points plan करता है, उन्हें write करता है, और verify करता है कि events land हो रहे हैं।

## Quick Start

```python
import agenteye

agenteye.configure(environment="production")

agenteye.event.agent_start(session_id="run-001", agent_id="planner", goal="answer user query")

agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    input={"query": "latest AI research"},
)

agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    output={"results": ["..."]},
)

agenteye.event.agent_end(session_id="run-001", agent_id="planner", outcome="success")
```

### एक real call को instrument करना

व्यवहार में आप अपने existing agent code को wrap करते हैं। एक model call को `model_request` के साथ bracket करें पहले और `model_response` के बाद, ताकि दोनों events real request को span करें और Failproof AI Observability उन्हें pair कर सके:

```python
import anthropic
import agenteye

agenteye.configure(environment="production")
client = anthropic.Anthropic()

messages = [{"role": "user", "content": "Summarise today's incidents."}]

agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6",
    messages=messages,
)

reply = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=512,
    messages=messages,
)

agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model=reply.model,
    stop_reason=reply.stop_reason,
    input_tokens=reply.usage.input_tokens,
    output_tokens=reply.usage.output_tokens,
    content=[block.model_dump() for block in reply.content],
)
```

Tool calls को same तरीके से wrap करें `tool_use` और `tool_result` के साथ, pair के across एक ही `tool_call_id` को reuse करते हुए।

यहाँ है कि वे events dashboard पर कैसे दिखते हैं, type द्वारा colour-coded और environment, agent, और session द्वारा filterable:

## configure()

```python
agenteye.configure(
    base_dir=None,           # Path | str | None. Default: $AGENTEYE_HOME or ~/.agenteye
    flush_interval=0.5,      # float, seconds between flush cycles
    environment=None,        # str | None. Deployment environment label
)
```

किसी भी `event.*` call से पहले एक बार call करें। Safe है omit करना; defaults out of the box काम करते हैं। सभी arguments keyword-only हैं; उन्हें ऊपर दिखाए अनुसार name से pass करें।

जब `base_dir` `None` हो (default), SDK `$AGENTEYE_HOME` को read करता है अगर set है,
अन्यथा `~/.agenteye` पर fallback करता है। यह collector के अपने resolution से match करता है,
ताकि single `AGENTEYE_HOME` env var SDK और collector दोनों के लिए shared event spool को configure करे।

## Environment

हर event को deployment environment (`production`, `staging`, `qa`, `canary`, आदि) के साथ label करें। इसे एक बार set करें; SDK automatically हर event को attach करता है।

**Option 1: `configure()` के via:**

```python
agenteye.configure(environment="production")
```

**Option 2: environment variable के via:**

```bash
export AGENTEYE_ENVIRONMENT=production
```

**Priority:** `configure(environment=...)` environment variable को win करता है। अगर कोई भी set नहीं है, तो default `"dev"` है।

Environment value dashboard में first-class filter के रूप में appear करता है और server पर fast queries के लिए store किया जाता है।

> **Warning:** Environment values में literal `,` comma नहीं होना चाहिए। Dashboard filters wire पर comma-separated multi-select use करते हैं (`?environment=prod,staging`), तो `prod,blue` नाम का एक environment दो values में split हो जाएगा। Comma-containing environments वाले events ingest time पर reject होते हैं।

## Data and privacy

SDK सिर्फ उन fields को record करता है जो आप explicitly pass करते हैं। Prompts, messages, tool inputs और outputs, और model content capture होते हैं सिर्फ क्योंकि आप उन्हें `event.*` call को hand करते हैं। कुछ नहीं read होता आपकी process से और कुछ नहीं capture होता implicitly। कोई भी field जो आप unset छोड़ते हैं वह event से completely omit होता है; यह disk पर write नहीं होता।

यह redaction को आपकी choice और आपकी responsibility बनाता है। अगर कोई prompt या tool payload में PII या secrets हैं जिन्हें आप store नहीं करना चाहते, उन्हें strip या mask करें event method को pass करने से पहले।

## Event Reference

अधिकांश events start/end pairs में आते हैं जो एक correlation ID share करते हैं: `tool_use` और `tool_result` एक `tool_call_id` share करते हैं, `hook_triggered` और `hook_completed` एक `hook_id` share करते हैं, और `human_wait` और `human_input` एक `input_id` share करते हैं। Start event emit करें, work करें, फिर end event emit करें same ID के साथ। Failproof AI Observability pair को match करता है और `duration_ms` को compute करता है आपके लिए, तो आप कभी `duration_ms` को स्वयं pass नहीं करते।

![A session's git-style execution graph beside its event timeline, reconstructed from the paired events, with the tool/model/hook breakdown panel](/agenteye/images/session-detail.png)

सभी event methods को ये दो fields require हैं:

| Field | Type | Description |
|---|---|---|
| `session_id` | `str` | Top-level agent run को identify करता है |
| `agent_id` | `str` | Identify करता है कि session के अंदर कौन सा agent event को emit किया |

सभी methods arbitrary `**kwargs` को भी accept करते हैं custom metadata के लिए (देखें [Custom Fields](#custom-fields))।

### `event.agent_start()`

Emitted होता है जब एक agent काम शुरू करता है।

```python
agenteye.event.agent_start(
    session_id="run-001",
    agent_id="planner",
    goal="answer user query",   # str | None
    parent_id=None,             # str | None - nested agents के लिए parent agent_id
)
```

---

### `event.agent_end()`

Emitted होता है जब एक agent काम finish करता है।

```python
agenteye.event.agent_end(
    session_id="run-001",
    agent_id="planner",
    outcome="success",          # str | None
    summary="Answered query",   # str | None
)
```

---

### `event.tool_use()`

Emitted होता है जब एक agent एक tool invoke करता है। `tool_result` के साथ pair करें; SDK auto-compute करता है `duration_ms`।

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",     # str, required
    tool_call_id="toolu_01",    # str, required - matching tool_result के लिए correlation key
    input={"query": "..."},     # dict | None
)
```

---

### `event.tool_result()`

Emitted होता है जब एक tool return करता है। `tool_id` के via `tool_use` के साथ correlate होता है।

```python
agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",        # prior tool_use से match करना चाहिए
    output={"results": ["..."]},    # Any | None
    error=None,                     # str | None - set करें अगर tool ने raise किया
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.model_request()`

Emitted होता है एक LLM को prompt भेजने से ठीक पहले।

```python
agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - कोई भी provider/model string; validated नहीं
    messages=[                   # list[dict] | None - conversation turns
        {"role": "user", "content": "..."},
    ],
    system="You are helpful.",   # Any | None - str या content blocks की list
    tools=[                      # list[dict] | None - tool schemas offered को model को
        {"name": "search", "input_schema": {"type": "object"}},
    ],
)
```

`messages` entries plain string `content` या Anthropic-style list-of-blocks `content` को accept करते हैं। Sampling params (`temperature`, `max_tokens`, आदि) को extra kwargs के रूप में pass किया जा सकता है।

---

### `event.model_response()`

Emitted होता है जब LLM एक response return करता है।

```python
agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - कोई भी provider/model string; validated नहीं
    stop_reason="end_turn",     # str | None
    input_tokens=1024,          # int | None
    output_tokens=256,          # int | None
    content=[                    # Any | None - str, या Anthropic-style content blocks की list
        {"type": "text", "text": "..."},
    ],
    role="assistant",            # str | None
)
```

`content` plain string (generic providers) या Anthropic-style content blocks की list को accept करता है। Tool calls `content` के अंदर `{"type": "tool_use", ...}` blocks के रूप में live करते हैं, separate `tool_calls` field के साथ नहीं।

---

### `event.hook_triggered()`

Emitted होता है जब एक hook fire करता है। `hook_completed` के साथ pair करें; SDK auto-compute करता है `duration_ms`।

```python
agenteye.event.hook_triggered(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",   # str, required
    hook_id="hook-abc",         # str, required - correlation key
    trigger_event="tool_use",   # str | None
    input={"tool": "search"},   # Any | None
)
```

---

### `event.hook_completed()`

Emitted होता है जब एक hook finish करता है। `hook_id` के via `hook_triggered` के साथ correlate होता है।

```python
agenteye.event.hook_completed(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",
    hook_id="hook-abc",         # prior hook_triggered से match करना चाहिए
    outcome="allow",            # str | None
    output=None,                # Any | None
    error=None,                 # str | None
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.error()`

Emitted होता है जब एक unhandled error होता है।

```python
agenteye.event.error(
    session_id="run-001",
    agent_id="planner",
    error_type="TimeoutError",  # str, required
    message="timed out",        # str, required
    traceback="Traceback...",   # str | None
)
```

## Human-in-the-Loop Events

Human-in-the-loop events आपको उन moments पर oversight देते हैं जहाँ एक person agent के execution में step करता है (approval के लिए waiting, input provide करना, pause करना, या agent को stop करना)। वे आपको measure करने देते हैं कि humans को respond करने में कितना समय लगता है (SDK auto-compute करता है paired events पर `duration_ms`), audit करते हैं कि किसने agent को pause या interrupt किया, और approval और oversight workflows build करते हैं जो dashboard में surface होते हैं।

### `event.human_wait()`

Emitted होता है जब agent execution को pause करता है एक human के लिए input provide करने के लिए wait करने को। `human_input` के साथ pair करें; SDK auto-compute करता है `duration_ms` (human को respond करने में कितना समय लगा)।

```python
agenteye.event.human_wait(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",                          # str, required - matching human_input के लिए correlation key
    prompt="Do you approve this action?",        # str | None - question जो human को दिखाया गया
    options=["approve", "reject", "defer"],      # list[str] | None - human को presented choices
    reason="approval_required",                  # str | None - क्यों agent wait कर रहा है
)
```

### `event.human_input()`

Emitted होता है जब human input provide करता है और agent resume करता है। `input_id` के via `human_wait` के साथ correlate होता है। `duration_ms` auto-compute होता है और caller द्वारा pass नहीं किया जाना चाहिए।

```python
agenteye.event.human_input(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",    # str, required - prior human_wait से match करना चाहिए
    response="approve",    # str | None - human का answer (free text या selected option)
    # duration_ms is computed automatically - do not pass it
)
```

### `event.human_pause()`

Emitted होता है जब एक human actively agent को pause करता है (जैसे dashboard control के via)। Agent suspend होता है लेकिन terminate नहीं।

```python
agenteye.event.human_pause(
    session_id="run-001",
    agent_id="planner",
    reason="user_requested",  # str | None
    user_id="usr_42",         # str | None - किसने agent को pause किया
)
```

### `event.human_interrupt()`

Emitted होता है जब एक human actively agent को mid-execution में stop करता है। `human_pause` के unlike, agent का काम terminate होता है न कि suspend।

```python
agenteye.event.human_interrupt(
    session_id="run-001",
    agent_id="planner",
    reason="output_incorrect",       # str | None
    user_id="usr_42",                # str | None - किसने agent को interrupt किया
    at_step="tool_use:web_search",   # str | None - agent क्या कर रहा था जब stop किया गया
)
```

## Custom Fields

कोई भी extra keyword arguments standard fields के बाद appended होते हैं:

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="db_query",
    tool_call_id="toolu_02",
    tenant_id="acme",           # custom field
    region="us-east-1",         # custom field
)
```

`timestamp`, `type`, और `environment` reserved हैं और `ValueError` raise करते हैं (`Reserved field names cannot be used as custom fields: [...]`) अगर custom fields के रूप में pass किए जाएँ। `session_id` और `agent_id` हर event method पर required parameters हैं और दूसरी बार supply नहीं किए जा सकते; Python `TypeError` raise करता है अगर आप करते हैं। Environment को `configure(environment=...)` के साथ set करें (या `AGENTEYE_ENVIRONMENT` variable) इसके बजाय।

Payloads को structured JSON के रूप में रखें जब आप उनके fields को query करना चाहते हैं। Values जो JSON natively support नहीं करता—जैसे datetimes, UUIDs, decimals, sets, bytes, या model objects—strings में convert होते हैं ताकि recording safely continue हो।

## How Events Are Written

Events को in-process buffer किया जाता है और हर `flush_interval` seconds में (default 500 ms) disk पर flush किया जाता है। प्रत्येक flush एक JSONL file write करता है:

```text
~/.agenteye/events/event-2026-04-01T12-00-00-000Z.jsonl
```

Collector इस directory को watch करता है और files को automatically upload करता है। आपको इन files को directly manage करने की ज़रूरत नहीं है।

प्रत्येक file atomically write होती है: SDK एक temporary file में write करता है और फिर इसे rename करता है, तो collector को कभी half-written file नहीं दिखाई देती। एक final flush भी आपके process के exit होने पर run करता है, तो last interval में buffered events lose नहीं होते। अगर collector offline है, तो events simply disk पर files के रूप में accumulate होते हैं और एक बार वह back आए तो ship होते हैं।
