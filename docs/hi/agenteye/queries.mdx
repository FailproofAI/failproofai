अपने एजेंट डेटा से कोई भी प्रश्न पूछें और सेकंड में उत्तर पाएं। Failproof AI Observability आपको आपकी events और evaluations पर सहेजे गए, तुरंत चलाने के लिए तैयार queries की एक लाइब्रेरी देता है, ताकि आप खाली SQL editor से शुरुआत करने के बजाय एक कार्यशील उदाहरण से शुरुआत कर सकें।

![saved-queries लाइब्रेरी: पुन: उपयोग करने योग्य queries का एक ग्रिड, दोनों built-in presets और custom ones](/agenteye/images/queries.png)

*आपकी saved-queries लाइब्रेरी `/<org-slug>/queries` पर: built-in presets आपकी टीम द्वारा सहेजी गई queries के साथ-साथ।*

## एक preset से शुरुआत करें, खाली पृष्ठ से नहीं

आपको table names याद रखने या SQL को शुरुआत से लिखने की जरूरत नहीं है। लाइब्रेरी सवालों के लिए built-in presets के साथ खुलती है जो टीमें सबसे अधिक पूछती हैं, ठीक आपकी टीम द्वारा सहेजी और नाम दी गई queries के बगल में। एक ऐसा चुनें जो आप जो चाहते हैं उसके करीब हो और आप उत्तर के आधे रास्ते तक पहुंच जाएंगे।

प्रत्येक saved query org-scoped और shared है, इसलिए उपयोगी वाले आपके teammates लिखते हैं वह आपके भी हो जाते हैं। एक query का नाम दें और एक बार description दें, और आपके org में कोई भी इसे ढूंढ सकता है, चला सकता है, या बाद में इसके परिणामों को dashboard पर pin कर सकता है।

इसे `/<org-slug>/queries` पर खोजें।

## इसे SQL composer में समायोजित करें और चलाएं

कोई भी query खोलें और यह SQL composer में उतर जाता है, जहां आप इसे समायोजित कर सकते हैं और तुरंत उत्तर देख सकते हैं: कोई export नहीं, कोई round-trip नहीं, किसी और की प्रतीक्षा नहीं।

![SQL query composer एक saved query को चलाता है, एक schema sidebar और एक live result grid के साथ](/agenteye/images/query-lab.png)

*SQL composer: आपकी query बाईं ओर, एक schema sidebar ताकि आप कभी column name का अनुमान न लगाएं, और नीचे एक live result grid।*

- **एक schema sidebar** analytics tables और उनके columns को lay out करता है, ताकि आप field names की खोज किए बिना एक query को shape कर सकें।
- **एक live result grid** rows को तुरंत return करता है जब आप चलाते हैं, इसलिए आप अनुमान और पुन: अनुमान लगाने के बजाय सेकंड में iterate कर सकते हैं।
- **डिज़ाइन द्वारा Read-only।** Queries आपकी event store के विरुद्ध चलाई जाती हैं और सर्वर पर validate की जाती हैं: केवल `SELECT` और `WITH` statements की अनुमति है, statement timeout और row cap के साथ। एक exploratory query कभी आपके डेटा को modify नहीं कर सकती, और एक runaway को आपके लिए रोक दिया जाता है।

परिणाम से खुश हैं? इसे लाइब्रेरी में वापस सहेजें ताकि पूरी टीम इसे प्राप्त करे, या इसके output को एक line, bar, area, या pie tile के रूप में dashboard पर pin करें।

## उन्हें terminal से चलाएं, या assistant को उन्हें लिखने दें

समान saved queries आपके साथ कहीं भी चलते हैं:

- **Terminal से।** `agenteye` CLI उन्हीं saved queries को list, run, और save करता है, इसलिए आप एक result को script में drop कर सकते हैं, इसे CI में wire कर सकते हैं, या इसे एक coding agent को दे सकते हैं।

```bash
agenteye query list                 # the same saved queries, from your terminal
agenteye query run errs --arg prod  # run one and print the rows (add --json to pipe it)
```

  पूरे command set के लिए [CLI and agents](/hi/agenteye/cli-and-agents) देखें।

- **AI assistant से।** SQL को कैसे phrase करें यह सुनिश्चित नहीं हैं? dashboard में [AI assistant](/hi/agenteye/assistant) से plain English में पूछें और यह query को draft करेगा और आपकी लाइब्रेरी में आपके लिए save करेगा।

एक saved query को चलाना `queries:run` permission द्वारा गेट किया जाता है, queries को create या delete करने की permissions से अलग रखा जाता है, इसलिए आप read access दे सकते हैं बिना हर किसी को लाइब्रेरी को rewrite करने देता।
