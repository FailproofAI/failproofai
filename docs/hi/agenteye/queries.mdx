अपने एजेंट डेटा से कोई भी सवाल पूछें और सेकंड में जवाब पाएं। Failproof AI Observability आपको अपनी events और evaluations पर सहेजे गए, तुरंत चलने वाली क्वेरीज़ की एक लाइब्रेरी देता है, ताकि आप एक खाली SQL एडिटर की जगह एक काम करने वाले उदाहरण से शुरुआत कर सकें।

![सहेजी गई क्वेरीज़ की लाइब्रेरी: पुनः प्रयोग करने योग्य क्वेरीज़ का ग्रिड, दोनों built-in presets और कस्टम](/agenteye/images/queries.png)

*आपकी सहेजी गई क्वेरीज़ की लाइब्रेरी `/<org-slug>/queries` पर: built-in presets आपकी टीम द्वारा सहेजी गई क्वेरीज़ के साथ।*

## एक प्रीसेट से शुरु करें, खाली पृष्ठ से नहीं

आपको टेबल के नाम याद रखने या SQL को शुरू से लिखने की ज़रूरत नहीं है। लाइब्रेरी built-in presets के साथ खुलती है जो टीमें सबसे ज्यादा पूछती हैं, ठीक आपकी टीम द्वारा सहेजी गई और नामांकित क्वेरीज़ के बगल में। एक ऐसा चुनें जो आप जो चाहते हैं उसके करीब हो और आप ज्यादातर जवाब तक पहुंच गए होंगे।

हर सहेजी गई क्वेरी org-scoped और साझा की गई है, इसलिए आपके सहकर्मियों द्वारा लिखी गई उपयोगी क्वेरीज़ आपकी भी बन जाती हैं। एक क्वेरी का नाम रखें और इसे एक बार विवरण दें, और आपके org में कोई भी इसे ढूंढ सकता है, चला सकता है, या बाद में इसके परिणामों को डैशबोर्ड पर पिन कर सकता है।

इसे `/<org-slug>/queries` पर खोजें।

## इसे SQL composer में संपादित करें और चलाएं

कोई भी क्वेरी खोलें और यह SQL composer में उतरती है, जहां आप इसे समायोजित कर सकते हैं और तुरंत उत्तर देख सकते हैं: कोई export नहीं, कोई round-trip नहीं, किसी और की प्रतीक्षा नहीं।

![SQL क्वेरी composer एक सहेजी गई क्वेरी चला रहा है, स्कीमा साइडबार और लाइव रिज़ल्ट ग्रिड के साथ](/agenteye/images/query-lab.png)

*SQL composer: आपकी क्वेरी बाईं ओर, एक स्कीमा साइडबार ताकि आप कभी कॉलम का नाम न भूलें, और नीचे एक लाइव रिज़ल्ट ग्रिड।*

- **एक स्कीमा साइडबार** analytics टेबल और उनके कॉलमों को दिखाता है, ताकि आप फील्ड नामों की खोज किए बिना एक क्वेरी बना सकें।
- **एक लाइव रिज़ल्ट ग्रिड** चलाने के क्षण ही rows लौटाता है, ताकि आप अनुमान लगाने और फिर से अनुमान लगाने के बजाय सेकंड में iterate कर सकें।
- **डिज़ाइन के अनुसार read-only।** क्वेरीज़ आपके event store के विरुद्ध चलती हैं और सर्वर पर validate होती हैं: केवल `SELECT` और `WITH` स्टेटमेंट की अनुमति है, एक statement timeout और एक row cap के साथ। एक exploratory क्वेरी कभी भी आपके डेटा को modify नहीं कर सकती, और एक runaway को आपके लिए रोक दिया जाता है।

परिणाम से खुश? इसे लाइब्रेरी में वापस सहेजें ताकि पूरी टीम इसे पा सके, या इसके आउटपुट को डैशबोर्ड पर एक line, bar, area, या pie tile के रूप में पिन करें।

## उन्हें terminal से चलाएं, या सहायक को उन्हें लिखने दें

वही सहेजी गई क्वेरीज़ आपके साथ जहां भी आप काम करते हैं वहां जाती हैं:

- **Terminal से।** `agenteye` CLI उन्हीं क्वेरीज़ को list, run, और save करता है, ताकि आप एक परिणाम को script में डाल सकें, इसे CI में wire कर सकें, या इसे एक coding agent को दे सकें।

```bash
agenteye query list                 # वही सहेजी गई क्वेरीज़, आपके terminal से
agenteye query run errs --arg prod  # एक को चलाएं और rows को प्रिंट करें (पाइप करने के लिए --json जोड़ें)
```

  पूरे command set के लिए [CLI and agents](/hi/agenteye/cli-and-agents) देखें।

- **AI सहायक से।** SQL को कैसे phrase करें इसके बारे में निश्चित नहीं? डैशबोर्ड [AI assistant](/hi/agenteye/assistant) को plain English में सवाल पूछें और यह क्वेरी का ड्राफ्ट तैयार करेगा और इसे आपकी लाइब्रेरी में सहेज देगा।

एक सहेजी गई क्वेरी चलाना `queries:run` permission द्वारा gated है, क्वेरीज़ को create या delete करने की permissions से अलग रखा गया है, ताकि आप read access दे सकें बिना सभी को लाइब्रेरी को फिर से लिखने दिए।
