Failproof AI Observability आपके production agents के करीब काम करने के लिए बनाया गया है, जिसका मतलब है कि यह आपके prompts, tool inputs, और outputs को देखता है। यह पृष्ठ समझाता है कि यह डेटा को कैसे isolated, controlled रखता है और आपके हाथों में कैसे रहता है। यदि आप सुरक्षा समीक्षा के लिए Failproof AI Observability का मूल्यांकन कर रहे हैं, तो यहां से शुरुआत करें।

---

## आपका डेटा आपके environment में रहता है

Failproof AI Observability self-hosted है। Events, prompts, model responses, और analytics आपके अपने databases में, आपके अपने environment में stored हैं। कुछ भी third-party SaaS को storage के लिए नहीं भेजा जाता, और आपका डेटा आपके अपने cloud account में रहता है।

---

## टेनेंट आइसोलेशन

एक Failproof AI Observability instance कई organizations को host कर सकता है, और प्रत्येक storage layer पर isolated है — database द्वारा लागू किया जाता है, सिर्फ UI द्वारा नहीं:

- एक organization का operational data (users, keys, dashboards, saved queries) उस org के लिए scoped है, और cross-org reads को database द्वारा ही blocked किया जाता है।
- हर ingested event को अपना owning org के साथ stamp किया जाता है, इसलिए एक organization के events को कभी दूसरा organization नहीं पढ़ सकता।

हर dashboard route एक org slug (`/<org-slug>/…`) के तहत scoped है।

---

## साइन-इन

Failproof AI Observability passwordless, email-based साइन-इन का उपयोग करता है। phish या leak करने के लिए कोई पासवर्ड नहीं है। एक user एक one-time code (या एक one-click magic link) request करता है, जो उन्हें email किया जाता है और जल्दी expire हो जाता है। साइन-इन एक **allowlist** द्वारा gated है: केवल email addresses (या domains) जिन्हें आप permit करते हैं, authenticate कर सकते हैं।

## API keys के साथ Scoped access

हर client एक API key के साथ authenticate करता है जो granular, least-privilege permissions carry करता है। एक collector को केवल `events:add` की जरूरत है; एक dashboard या assistant key read-only हो सकता है; destructive actions (delete, regenerate) अलग grants हैं जिन्हें आप include करना चुनते हैं।

![API keys पृष्ठ: हर key के permission grants, read, write, और destructive scope द्वारा colour-coded](/agenteye/images/api-keys.png)

Setup के लिए admin bootstrap key रखें, और बाकी सब कुछ के लिए narrow keys issue करें। [API keys](/hi/agenteye/api-keys) देखें।

## एक read-only, approval-gated assistant

In-dashboard [AI assistant](/hi/agenteye/assistant) आपके डेटा पर सवालों का जवाब देता है, लेकिन यह design द्वारा constrained है:

- यह **default द्वारा read-only है**: इसका SQL एक guard के माध्यम से चलता है जो केवल `SELECT`/`WITH` queries, single-statement, एक row cap के साथ permit करता है।
- जो कुछ भी यह बनाता है (एक saved query, एक dashboard) **approval-gated है**: आप हर write को approve करने से पहले review करते हैं।
- यह **कभी delete नहीं कर सकता**।

तो एक teammate पूछ सकता है "कौन से agents इस हफ्ते सबसे ज्यादा error हुए?" और जवाब पर act कर सकता है, बिना assistant के बिना आपके डेटा को अपने आप change या remove करने में सक्षम होने के।

## ट्रांजिट में

सभी traffic HTTPS पर चलता है। आप अपने certificates के साथ TLS terminate करते हैं, इसलिए collector-to-server और browser-to-server traffic transit में encrypted है।
