यह दस्तावेज़ समझाता है कि failproofai आंतरिक रूप से कैसे काम करता है: हुक सिस्टम एजेंट टूल कॉल को कैसे इंटरसेप्ट करता है, कॉन्फ़िग कैसे लोड और मर्ज होती है, पॉलिसीज़ कैसे इवैल्यूएट होती हैं, और डैशबोर्ड एजेंट एक्टिविटी को कैसे मॉनिटर करता है।

---

## अवलोकन

failproofai के दो स्वतंत्र सबसिस्टम हैं:

1. **हुक हैंडलर** - एक तेज़ CLI सबप्रोसेस जिसे Claude Code हर एजेंट टूल कॉल पर इनवोक करता है। पॉलिसीज़ का मूल्यांकन करता है और एक निर्णय लौटाता है।
2. **एजेंट मॉनिटर (डैशबोर्ड)** - एजेंट सेशन की मॉनिटरिंग और पॉलिसीज़ को प्रबंधित करने के लिए एक Next.js वेब एप्लिकेशन।

दोनों सबसिस्टम `~/.failproofai/` और प्रोजेक्ट की `.failproofai/` डायरेक्टरी में कॉन्फ़िग फ़ाइलें साझा करते हैं, लेकिन वे अलग-अलग प्रोसेस के रूप में चलते हैं और केवल फ़ाइलसिस्टम के माध्यम से संचार करते हैं।

## हुक हैंडलर

### Claude Code के साथ इंटीग्रेशन

जब आप `failproofai policies --install` चलाते हैं, तो यह `~/.claude/settings.json` में इस तरह की प्रविष्टियां लिखता है:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "failproofai --hook PreToolUse"
          }
        ]
      }
    ],
    "PostToolUse": [ ... ]
  }
}
```

Claude Code फिर प्रत्येक टूल कॉल से पहले `failproofai --hook PreToolUse` को एक सबप्रोसेस के रूप में इनवोक करता है, stdin पर एक JSON पेलोड पास करते हुए।

### पेलोड फॉर्मेट

```json
{
  "session_id": "abc123",
  "transcript_path": "/home/user/.claude/projects/myproject/sessions/abc123.jsonl",
  "cwd": "/home/user/myproject",
  "permission_mode": "default",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": { "command": "sudo apt install nodejs" }
}
```

`PostToolUse` इवेंट के लिए, पेलोड में टूल के आउटपुट के साथ `tool_result` भी होता है।

हैंडलर 1 MB stdin लिमिट लागू करता है। इस सीमा को पार करने वाले पेलोड को डिस्कार्ड कर दिया जाता है और सभी पॉलिसीज़ निहितार्थ से अनुमति देती हैं।

### रेस्पॉन्स फॉर्मेट

**अस्वीकार करें (PreToolUse):**
```json
{
  "hookSpecificOutput": {
    "permissionDecision": "deny",
    "permissionDecisionReason": "Blocked by failproofai: sudo command blocked"
  }
}
```

**अस्वीकार करें (PostToolUse):**
```json
{
  "hookSpecificOutput": {
    "additionalContext": "Blocked by failproofai because: API key detected in output"
  }
}
```

**निर्देश (Stop को छोड़कर किसी भी इवेंट):**
```json
{
  "hookSpecificOutput": {
    "additionalContext": "Instruction from failproofai: Verify tests pass before committing."
  }
}
```

**Stop इवेंट निर्देश:**
- एक्जिट कोड: `2`
- Stderr को कारण लिखा गया है (stdout नहीं)

**अनुमति दें:**
- एक्जिट कोड: `0`
- खाली stdout

**संदेश के साथ अनुमति दें:**

`allow(message)` एक पॉलिसी को जब भी ऑपरेशन की अनुमति दी जाती है तो Claude को सूचनात्मक संदर्भ भेजने देता है। हुक हैंडलर निम्नलिखित JSON को **stdout** पर लिखता है (कॉन्फ़िग फ़ाइल नहीं — यह हैंडलर की प्रतिक्रिया है Claude Code को, बिल्कुल अस्वीकार और निर्देश प्रतिक्रियाओं की तरह):

```json
// हुक हैंडलर प्रोसेस द्वारा stdout को लिखा गया
{
  "hookSpecificOutput": {
    "additionalContext": "All CI checks passed on branch 'feat/my-feature'."
  }
}
```
- एक्जिट कोड: `0` (ऑपरेशन की अनुमति है)
- जब कई पॉलिसीज़ एक संदेश के साथ `allow` लौटाती हैं, तो उनके संदेश को एक एकल `additionalContext` स्ट्रिंग में नई लाइनों से जोड़ा जाता है
- अगर कोई पॉलिसी कोई संदेश नहीं देती है, तो stdout खाली है (पहले की तरह)

### प्रोसेसिंग पाइपलाइन

`src/hooks/handler.ts` पूरी पाइपलाइन को लागू करता है:

```text
stdin JSON
  → parse payload (max 1 MB)
  → extract session metadata (session_id, cwd, tool_name, tool_input, etc.)
  → readMergedHooksConfig(cwd)    ← merges project + local + global config
  → register enabled builtin policies with resolved params
  → load custom policies from customPoliciesPath (if set)
  → register custom policies into policy registry
  → evaluate all policies (builtins first, then custom)
      → first deny short-circuits
      → instruct decisions accumulate
      → allow messages accumulate
  → write JSON decision to stdout
  → persist event to ~/.failproofai/hook-activity/current.jsonl
  → exit
```

बिना LLM कॉल वाले विशिष्ट पेलोड के लिए पूरी प्रक्रिया 100ms से कम में चलती है।

## कॉन्फ़िग लोडिंग

`src/hooks/hooks-config.ts` तीन-स्कोप कॉन्फ़िग लोडिंग लागू करता है।

```text
[1] {cwd}/.failproofai/policies-config.json        ← project  (highest priority)
[2] {cwd}/.failproofai/policies-config.local.json  ← local
[3] ~/.failproofai/policies-config.json             ← global   (lowest priority)
```

मर्ज लॉजिक:
- `enabledPolicies` - तीनों फ़ाइलों में डिडुप्लिकेटेड यूनियन
- `policyParams` - प्रति-पॉलिसी कुंजी, पहली फ़ाइल जो इसे परिभाषित करती है पूरी तरह जीत जाती है
- `customPoliciesPath` - पहली फ़ाइल जो इसे परिभाषित करती है जीत जाती है
- `llm` - पहली फ़ाइल जो इसे परिभाषित करती है जीत जाती है

वेब डैशबोर्ड पढ़ने और लिखने के लिए `readHooksConfig()` (केवल ग्लोबल) का उपयोग करता है, क्योंकि इसे प्रोजेक्ट cwd के साथ इनवोक नहीं किया जाता है।

## पॉलिसी इवैल्यूएशन

`src/hooks/policy-evaluator.ts` क्रम में पॉलिसीज़ चलाता है।

प्रत्येक पॉलिसी के लिए:

1. पॉलिसी के `params` स्कीमा को देखें (यदि इसके पास है)।
2. मर्ज की गई कॉन्फ़िग से `policyParams[policy.name]` पढ़ें।
3. `ctx.params` का उत्पादन करने के लिए स्कीमा डिफ़ॉल्ट पर यूजर-प्रदान किए गए मानों को मर्ज करें।
4. रिज़ॉल्व किए गए संदर्भ के साथ `policy.fn(ctx)` को कॉल करें।
5. यदि परिणाम `deny` है, तो तुरंत रुकें और उस निर्णय को लौटाएं।
6. यदि परिणाम `instruct` है, तो संदेश को जमा करें और जारी रखें।
7. यदि परिणाम `allow` है, तो अगली पॉलिसी पर जारी रखें।

सभी पॉलिसीज़ चलने के बाद:
- यदि कोई `deny` लौटाया गया था, तो अस्वीकार प्रतिक्रिया उत्सर्जित करें।
- यदि कोई `instruct` रिटर्न एकत्र किए गए थे, तो एक एकल निर्देश प्रतिक्रिया उत्सर्जित करें सभी संदेशों को जोड़ा हुआ।
- अन्यथा, एक अनुमति प्रतिक्रिया उत्सर्जित करें (खाली stdout, एक्जिट 0)।

## बिल्ट-इन पॉलिसीज़

`src/hooks/builtin-policies.ts` सभी 39 बिल्ट-इन पॉलिसीज़ को `BuiltinPolicyDefinition` ऑब्जेक्ट के रूप में परिभाषित करता है:

```typescript
interface BuiltinPolicyDefinition {
  name: string;
  description: string;
  fn: (ctx: PolicyContext) => PolicyResult;
  match: {
    events: HookEventType[];
    tools?: string[];
  };
  defaultEnabled: boolean;
  category: string;
  beta?: boolean;
  params?: PolicyParamsSchema;
}
```

पॉलिसीज़ जो `params` स्वीकार करती हैं वे प्रत्येक पैरामीटर के लिए प्रकार और डिफ़ॉल्ट के साथ एक `PolicyParamsSchema` घोषित करती हैं। पॉलिसी इवैल्यूएटर `fn` को कॉल करने से पहले `ctx.params` में रिज़ॉल्व किए गए मानों को इंजेक्ट करता है। पॉलिसी फंक्शन `ctx.params` को पढ़ते हैं बिना null-गार्डिंग के क्योंकि डिफ़ॉल्ट हमेशा पहले लागू होते हैं।

पॉलिसीज़ के अंदर पैटर्न मिलान पार्स किए गए कमांड टोकन (argv) का उपयोग करता है, कच्ची स्ट्रिंग मिलान नहीं। यह शेल ऑपरेटर इंजेक्शन के माध्यम से बाईपास को रोकता है (उदाहरण के लिए `sudo systemctl status *` के लिए एक पैटर्न कमांड के अंत में `; rm -rf /` जोड़कर बाईपास नहीं किया जा सकता)।

## कस्टम पॉलिसीज़

`src/hooks/custom-hooks-registry.ts` एक `globalThis`-समर्थित रजिस्ट्री लागू करता है:

```typescript
const REGISTRY_KEY = "__failproofai_custom_hooks__";

export const customPolicies = {
  add(hook: CustomHook): void { ... }
};

export function getCustomHooks(): CustomHook[] { ... }
export function clearCustomHooks(): void { ... }  // used in tests
```

`src/hooks/custom-hooks-loader.ts` यूजर की पॉलिसी फ़ाइल को लोड करता है:

1. कॉन्फ़िग से `customPoliciesPath` पढ़ें; यदि अनुपस्थित है तो छोड़ दें।
2. निरपेक्ष पथ में रिज़ॉल्व करें; फ़ाइल के अस्तित्व की जांच करें।
3. सभी `from "failproofai"` इम्पोर्ट को वास्तविक dist पथ में पुनः लिखें ताकि `customPolicies` उसी `globalThis` रजिस्ट्री को रिज़ॉल्व करे।
4. ESM संगतता सुनिश्चित करने के लिए ट्रांसिटिव लोकल इम्पोर्ट को पुनरावर्ती रूप से पुनः लिखें।
5. अस्थायी `.mjs` फ़ाइलें लिखें और प्रविष्टि फ़ाइल को `import()` करें।
6. पंजीकृत हुक को पुनः प्राप्त करने के लिए `getCustomHooks()` को कॉल करें।
7. `finally` ब्लॉक में सभी अस्थायी फ़ाइलों को साफ करें।

किसी भी त्रुटि पर (फ़ाइल नहीं मिली, सिंटैक्स त्रुटि, इम्पोर्ट विफलता), त्रुटि को `~/.failproofai/hook.log` में लॉग किया जाता है और लोडर एक खाली सरणी लौटाता है। बिल्ट-इन पॉलिसीज़ अप्रभावित हैं।

कस्टम पॉलिसीज़ सभी बिल्ट-इन पॉलिसीज़ के बाद इवैल्यूएट की जाती हैं। एक कस्टम पॉलिसी `deny` अभी भी आगे की कस्टम पॉलिसीज़ को शॉर्ट-सर्किट करता है (लेकिन सभी बिल्ट-इन पहले से ही उस बिंदु तक चल चुकी हैं)।

## एक्टिविटी लॉगिंग

प्रत्येक हुक इवेंट के बाद, हैंडलर `~/.failproofai/hook-activity/current.jsonl` में एक JSONL लाइन जोड़ता है, जो एक बार पेज तक पहुंचने पर `page-<timestamp>-<seq>.jsonl` में रोटेट होता है:

```json
{
  "timestamp": "2026-04-06T12:34:56.789Z",
  "sessionId": "abc123",
  "eventType": "PreToolUse",
  "toolName": "Bash",
  "policyName": "block-sudo",
  "decision": "deny",
  "reason": "sudo command blocked by failproofai",
  "durationMs": 12
}
```

प्रत्येक पॉलिसी के लिए एक लाइन जो गैर-अनुमति निर्णय लेती है। अनुमति निर्णय लॉग नहीं किए जाते हैं (फ़ाइल को छोटा रखने के लिए)।

## डैशबोर्ड आर्किटेक्चर

डैशबोर्ड एक **Next.js 16** एप्लिकेशन है जो App Router के साथ React Server Components और Server Actions का उपयोग करता है।

```text
app/
  layout.tsx                  ← Root layout (theme, telemetry, nav)
  projects/page.tsx           ← Server component: list all Claude projects
  project/[name]/page.tsx     ← Server component: list sessions in a project
  project/[name]/session/
    [sessionId]/page.tsx      ← Server component: render session viewer
  policies/page.tsx           ← Client component: policy management + activity log
  actions/
    get-hooks-config.ts       ← Read config + policy list
    update-hooks-config.ts    ← Toggle policy on/off
    update-policy-params.ts   ← Update policy parameters
    get-hook-activity.ts      ← Paginate/search activity log
    install-hooks-web.ts      ← Install/remove hooks from the browser
  api/
    download/[project]/[session]/route.ts   ← Per-CLI session export (JSONL or JSON)
```

**डेटा फ्लो:**

- पेज कंपोनेंट्स `lib/projects.ts` और `lib/log-entries.ts` को कॉल करते हैं प्रोजेक्ट/सेशन डेटा को सीधे फ़ाइलसिस्टम से पढ़ने के लिए (पढ़ने के लिए कोई API परत नहीं)।
- पॉलिसीज़ पेज सभी म्यूटेशन के लिए Server Actions का उपयोग करता है (टॉगल, params अपडेट, इंस्टॉल/निकालें)।
- सेशन व्यूअर Claude के JSONL ट्रांसक्रिप्ट फॉर्मेट को पार्स करता है और संदेश और टूल कॉल की एक टाइमलाइन रेंडर करता है।

**मुख्य डिज़ाइन निर्णय:**

- कोई डेटाबेस नहीं - सभी स्थायी स्थिति सादी फ़ाइलों में है (`~/.failproofai/`, `~/.claude/projects/`)।
- म्यूटेशन के लिए Server Actions - CRUD ऑपरेशन के लिए कोई REST API की आवश्यकता नहीं।
- पेज पढ़ने के लिए React Server Components - तेज़ प्रारंभिक लोड, डेटा फेचिंग के लिए कोई क्लायंट बंडल नहीं।
- क्लायंट कंपोनेंट केवल जहां इंटरएक्टिविटी की आवश्यकता है (पॉलिसी टॉगल, एक्टिविटी सर्च, लॉग व्यूअर)।
