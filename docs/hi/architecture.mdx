यह दस्तावेज़ बताता है कि failproofai आंतरिक रूप से कैसे काम करता है: हुक सिस्टम एजेंट टूल कॉल्स को कैसे इंटरसेप्ट करता है, कॉन्फ़िग को कैसे लोड और मर्ज किया जाता है, पॉलिसीज का मूल्यांकन कैसे होता है, और डैशबोर्ड एजेंट गतिविधि की निगरानी कैसे करता है।

---

## अवलोकन

failproofai के दो स्वतंत्र सबसिस्टम हैं:

1. **हुक हैंडलर** - एक तेज़ CLI सबप्रोसेस जो Claude Code हर एजेंट टूल कॉल पर इनवोक करता है। पॉलिसीज का मूल्यांकन करता है और एक निर्णय देता है।
2. **एजेंट मॉनिटर (डैशबोर्ड)** - एजेंट सेशन की निगरानी और पॉलिसीज को प्रबंधित करने के लिए एक Next.js वेब एप्लिकेशन।

दोनों सबसिस्टम `~/.failproofai/` और प्रोजेक्ट की `.failproofai/` निर्देशिका में कॉन्फ़िग फ़ाइलें साझा करते हैं, लेकिन वे अलग-अलग प्रक्रियाओं के रूप में चलते हैं और केवल फ़ाइल सिस्टम के माध्यम से संचार करते हैं।

---

## हुक हैंडलर

### Claude Code के साथ एकीकरण

जब आप `failproofai policies --install` चलाते हैं, तो यह `~/.claude/settings.json` में ऐसी प्रविष्टियाँ लिखता है:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "failproofai --hook PreToolUse"
          }
        ]
      }
    ],
    "PostToolUse": [ ... ]
  }
}
```

फिर Claude Code प्रत्येक टूल कॉल से पहले एक सबप्रोसेस के रूप में `failproofai --hook PreToolUse` को इनवोक करता है, stdin पर एक JSON पेलोड पास करता है।

### पेलोड प्रारूप

```json
{
  "session_id": "abc123",
  "transcript_path": "/home/user/.claude/projects/myproject/sessions/abc123.jsonl",
  "cwd": "/home/user/myproject",
  "permission_mode": "default",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": { "command": "sudo apt install nodejs" }
}
```

`PostToolUse` इवेंट्स के लिए, पेलोड में `tool_result` भी होता है जिसमें टूल का आउटपुट होता है।

हैंडलर 1 MB का stdin लिमिट लागू करता है। इस सीमा से अधिक पेलोड को त्याग दिया जाता है और सभी पॉलिसीज निहित रूप से अनुमति देती हैं।

### प्रतिक्रिया प्रारूप

**डेनी (PreToolUse):**
```json
{
  "hookSpecificOutput": {
    "permissionDecision": "deny",
    "permissionDecisionReason": "Blocked by failproofai: sudo command blocked"
  }
}
```

**डेनी (PostToolUse):**
```json
{
  "hookSpecificOutput": {
    "additionalContext": "Blocked by failproofai because: API key detected in output"
  }
}
```

**इंस्ट्रक्ट (Stop को छोड़कर कोई भी इवेंट):**
```json
{
  "hookSpecificOutput": {
    "additionalContext": "Instruction from failproofai: Verify tests pass before committing."
  }
}
```

**Stop इवेंट इंस्ट्रक्ट:**
- एक्जिट कोड: `2`
- कारण stderr में लिखा गया (stdout में नहीं)

**अनुमति:**
- एक्जिट कोड: `0`
- खाली stdout

**संदेश के साथ अनुमति:**

`allow(message)` एक पॉलिसी को Claude को सूचनात्मक संदर्भ भेजने की अनुमति देता है भले ही ऑपरेशन की अनुमति हो। हुक हैंडलर निम्नलिखित JSON को **stdout** में लिखता है (कॉन्फ़िग फ़ाइल में नहीं — यह हैंडलर की Claude Code को प्रतिक्रिया है, बिल्कुल डेनी और इंस्ट्रक्ट प्रतिक्रियाओं की तरह):

```json
// हुक हैंडलर प्रक्रिया द्वारा stdout में लिखा गया
{
  "hookSpecificOutput": {
    "additionalContext": "All CI checks passed on branch 'feat/my-feature'."
  }
}
```
- एक्जिट कोड: `0` (ऑपरेशन की अनुमति है)
- जब कई पॉलिसीज `allow` को संदेश के साथ देती हैं, तो उनके संदेश नई लाइनों के साथ एक एकल `additionalContext` स्ट्रिंग में जुड़े होते हैं
- यदि कोई पॉलिसी संदेश प्रदान नहीं करती है, तो stdout खाली है (पहले की तरह)

### प्रोसेसिंग पाइपलाइन

`src/hooks/handler.ts` पूरी पाइपलाइन को लागू करता है:

```text
stdin JSON
  → पेलोड को पार्स करें (अधिकतम 1 MB)
  → सेशन मेटाडेटा निकालें (session_id, cwd, tool_name, tool_input, आदि)
  → readMergedHooksConfig(cwd)    ← प्रोजेक्ट + लोकल + ग्लोबल कॉन्फ़िग मर्ज करता है
  → सक्षम बिल्ट-इन पॉलिसीज को हल किए गए पैराम्स के साथ रजिस्टर करें
  → customPoliciesPath से कस्टम पॉलिसीज लोड करें (यदि सेट है)
  → कस्टम पॉलिसीज को पॉलिसी रजिस्ट्री में रजिस्टर करें
  → सभी पॉलिसीज का मूल्यांकन करें (पहले बिल्ट-इन, फिर कस्टम)
      → पहला डेनी शॉर्ट-सर्किट करता है
      → इंस्ट्रक्ट निर्णय जमा होते हैं
      → संदेशों की अनुमति जमा होती है
  → JSON निर्णय को stdout में लिखें
  → इवेंट को ~/.failproofai/hook-activity/current.jsonl में बनाए रखें
  → एक्जिट करें
```

पारंपरिक पेलोड के साथ पूरी प्रक्रिया 100ms के तहत चलती है बिना LLM कॉल्स के।

## कॉन्फ़िग लोडिंग

`src/hooks/hooks-config.ts` तीन-स्कोप कॉन्फ़िग लोडिंग को लागू करता है।

```text
[1] {cwd}/.failproofai/policies-config.json        ← प्रोजेक्ट  (सर्वोच्च प्राथमिकता)
[2] {cwd}/.failproofai/policies-config.local.json  ← स्थानीय
[3] ~/.failproofai/policies-config.json             ← ग्लोबल   (सबसे कम प्राथमिकता)
```

मर्ज लॉजिक:
- `enabledPolicies` - तीनों फ़ाइलों में डुप्लिकेट यूनियन
- `policyParams` - प्रति-पॉलिसी कुंजी, पहली फ़ाइल जो इसे परिभाषित करती है पूरी तरह जीतती है
- `customPoliciesPath` - पहली फ़ाइल जो इसे परिभाषित करती है जीतती है
- `llm` - पहली फ़ाइल जो इसे परिभाषित करती है जीतती है

वेब डैशबोर्ड पढ़ने और लिखने के लिए `readHooksConfig()` (केवल ग्लोबल) का उपयोग करता है, क्योंकि यह प्रोजेक्ट cwd के साथ इनवोक नहीं किया जाता है।

## पॉलिसी मूल्यांकन

`src/hooks/policy-evaluator.ts` पॉलिसीज को क्रम में चलाता है।

प्रत्येक पॉलिसी के लिए:

1. पॉलिसी के `params` स्कीमा को देखें (यदि इसमें एक है)।
2. मर्ज किए गए कॉन्फ़िग से `policyParams[policy.name]` को पढ़ें।
3. उपयोगकर्ता-प्रदत्त मानों को स्कीमा डिफ़ॉल्ट पर मर्ज करें `ctx.params` का उत्पादन करने के लिए।
4. हल किए गए संदर्भ के साथ `policy.fn(ctx)` को कॉल करें।
5. यदि परिणाम `deny` है, तो तुरंत बंद करें और उस निर्णय को रिटर्न करें।
6. यदि परिणाम `instruct` है, तो संदेश को जमा करें और जारी रखें।
7. यदि परिणाम `allow` है, तो अगली पॉलिसी पर जाएं।

सभी पॉलिसीज चलने के बाद:
- यदि कोई `deny` रिटर्न किया गया था, तो डेनी प्रतिक्रिया उत्सर्जित करें।
- यदि कोई `instruct` रिटर्न एकत्र किए गए थे, तो सभी संदेशों को जुड़े हुए एक एकल इंस्ट्रक्ट प्रतिक्रिया उत्सर्जित करें।
- अन्यथा, एक अनुमति प्रतिक्रिया उत्सर्जित करें (खाली stdout, एक्जिट 0)।

## बिल्ट-इन पॉलिसीज

`src/hooks/builtin-policies.ts` सभी 39 बिल्ट-इन पॉलिसीज को `BuiltinPolicyDefinition` ऑब्जेक्ट्स के रूप में परिभाषित करता है:

```typescript
interface BuiltinPolicyDefinition {
  name: string;
  description: string;
  fn: (ctx: PolicyContext) => PolicyResult;
  match: {
    events: HookEventType[];
    tools?: string[];
  };
  defaultEnabled: boolean;
  category: string;
  beta?: boolean;
  params?: PolicyParamsSchema;
}
```

जो पॉलिसीज `params` स्वीकार करती हैं वे प्रत्येक पैरामीटर के लिए प्रकार और डिफ़ॉल्ट के साथ `PolicyParamsSchema` घोषित करती हैं। पॉलिसी मूल्यांकनकर्ता `fn` को कॉल करने से पहले हल किए गए मानों को `ctx.params` में इंजेक्ट करता है। पॉलिसी फंक्शन `ctx.params` को नल-गार्ड के बिना पढ़ते हैं क्योंकि डिफ़ॉल्ट हमेशा पहले लागू होते हैं।

पॉलिसीज के अंदर पैटर्न मैचिंग कच्ची स्ट्रिंग मैचिंग के बजाय पार्स किए गए कमांड टोकन (argv) का उपयोग करता है। यह शेल ऑपरेटर इंजेक्शन के माध्यम से बाईपास को रोकता है (उदाहरण के लिए `sudo systemctl status *` के लिए एक पैटर्न कमांड में `; rm -rf /` जोड़कर बाईपास नहीं किया जा सकता है)।

## कस्टम पॉलिसीज

`src/hooks/custom-hooks-registry.ts` `globalThis`-समर्थित रजिस्ट्री को लागू करता है:

```typescript
const REGISTRY_KEY = "__failproofai_custom_hooks__";

export const customPolicies = {
  add(hook: CustomHook): void { ... }
};

export function getCustomHooks(): CustomHook[] { ... }
export function clearCustomHooks(): void { ... }  // परीक्षणों में उपयोग किया जाता है
```

`src/hooks/custom-hooks-loader.ts` उपयोगकर्ता की पॉलिसी फ़ाइल को लोड करता है:

1. कॉन्फ़िग से `customPoliciesPath` को पढ़ें; यदि अनुपस्थित है तो छोड़ दें।
2. पूर्ण पथ में हल करें; फ़ाइल मौजूद है यह जांचें।
3. `customPolicies` वास्तविक dist पथ में हल हो जाए यह सुनिश्चित करने के लिए सभी `from "failproofai"` आयातों को वास्तविक dist पथ में फिर से लिखें।
4. ESM संगतता सुनिश्चित करने के लिए ट्रांजिटिव स्थानीय आयातों को पुनरावर्ती रूप से फिर से लिखें।
5. अस्थायी `.mjs` फ़ाइलें लिखें और प्रविष्टि फ़ाइल को `import()` करें।
6. रजिस्टर किए गए हुक्स को प्राप्त करने के लिए `getCustomHooks()` को कॉल करें।
7. सभी अस्थायी फ़ाइलों को `finally` ब्लॉक में साफ करें।

किसी भी त्रुटि (फ़ाइल नहीं मिली, सिंटैक्स त्रुटि, आयात विफलता) पर, त्रुटि को `~/.failproofai/hook.log` में लॉग किया जाता है और लोडर एक खाली सरणी देता है। बिल्ट-इन पॉलिसीज प्रभावित नहीं होती हैं।

कस्टम पॉलिसीज सभी बिल्ट-इन पॉलिसीज के बाद मूल्यांकन की जाती हैं। एक कस्टम पॉलिसी `deny` अभी भी आगे की कस्टम पॉलिसीज को शॉर्ट-सर्किट करता है (लेकिन सभी बिल्ट-इन पहले ही चल चुकी हैं)।

## गतिविधि लॉगिंग

प्रत्येक हुक इवेंट के बाद, हैंडलर `~/.failproofai/hook-activity/current.jsonl` में एक JSONL लाइन जोड़ता है, जो एक पेज तक पहुंचने पर `page-<timestamp>-<seq>.jsonl` में घूमती है:

```json
{
  "timestamp": "2026-04-06T12:34:56.789Z",
  "sessionId": "abc123",
  "eventType": "PreToolUse",
  "toolName": "Bash",
  "policyName": "block-sudo",
  "decision": "deny",
  "reason": "sudo command blocked by failproofai",
  "durationMs": 12
}
```

प्रत्येक पॉलिसी के लिए एक पंक्ति जिसने एक गैर-अनुमति निर्णय दिया। अनुमति निर्णयों को लॉग नहीं किया जाता है (फ़ाइल को छोटा रखने के लिए)।

## डैशबोर्ड आर्किटेक्चर

डैशबोर्ड एक **Next.js 16** एप्लिकेशन है जो ऐप राउटर के साथ React Server Components और Server Actions का उपयोग करता है।

```text
app/
  layout.tsx                  ← रूट लेआउट (थीम, टेलीमेट्री, nav)
  projects/page.tsx           ← सर्वर कंपोनेंट: सभी Claude प्रोजेक्ट्स को सूचीबद्ध करें
  project/[name]/page.tsx     ← सर्वर कंपोनेंट: प्रोजेक्ट में सेशन सूचीबद्ध करें
  project/[name]/session/
    [sessionId]/page.tsx      ← सर्वर कंपोनेंट: सेशन व्यूअर रेंडर करें
  policies/page.tsx           ← क्लाइंट कंपोनेंट: पॉलिसी प्रबंधन + गतिविधि लॉग
  actions/
    get-hooks-config.ts       ← कॉन्फ़िग + पॉलिसी सूची पढ़ें
    update-hooks-config.ts    ← पॉलिसी चालू/बंद करें
    update-policy-params.ts   ← पॉलिसी पैरामीटर अपडेट करें
    get-hook-activity.ts      ← गतिविधि लॉग को पेजिनेट/खोजें
    install-hooks-web.ts      ← ब्राउज़र से हुक्स को इंस्टॉल/हटाएं
  api/
    download/[project]/[session]/route.ts   ← प्रति-CLI सेशन एक्सपोर्ट (JSONL या JSON)
```

**डेटा प्रवाह:**

- पेज कंपोनेंट्स फ़ाइल सिस्टम से सीधे प्रोजेक्ट/सेशन डेटा पढ़ने के लिए `lib/projects.ts` और `lib/log-entries.ts` को कॉल करते हैं (पढ़ने के लिए API लेयर नहीं)।
- पॉलिसीज पेज सभी म्यूटेशन (टॉगल, पैरामीटर अपडेट, इंस्टॉल/हटाएं) के लिए Server Actions का उपयोग करता है।
- सेशन व्यूअर Claude के JSONL ट्रांसक्रिप्ट प्रारूप को पार्स करता है और संदेशों और टूल कॉल्स की एक समयरेखा रेंडर करता है।

**मुख्य डिजाइन निर्णय:**

- कोई डेटाबेस नहीं - सभी स्थिर स्थिति सादी फ़ाइलों (`~/.failproofai/`, `~/.claude/projects/`) में है।
- म्यूटेशन के लिए Server Actions - CRUD ऑपरेशन के लिए कोई REST API की आवश्यकता नहीं है।
- पेज पढ़ने के लिए React Server Components - तेज़ प्रारंभिक लोड, डेटा फेचिंग के लिए कोई क्लाइंट बंडल नहीं।
- क्लाइंट कंपोनेंट केवल जहां इंटरएक्टिविटी की आवश्यकता है (पॉलिसी टॉगल, गतिविधि खोज, लॉग व्यूअर)।
