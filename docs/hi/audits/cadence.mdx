आवर्ती ऑडिट का उपयोग उन विफलता मोड के लिए करें जो एजेंट, प्रॉम्प्ट, टूल और मॉडल के बदलने पर फिर से दिखाई दे सकते हैं।

## शेड्यूल बदलें

<Tabs>
  <Tab title="Dashboard">
    1. **Analyze → Audits** पर जाएं और ऑडिट खोलें।
    2. इसकी सेटिंग खोलें और सक्षम स्थिति, अंतराल, UTC एंकर, विंडो मोड, या लुकबैक बदलें।
    3. ऑडिट सहेजें और ऑडिट कार्ड पर अगले रन का समय पुष्टि करें।
    4. किसी बड़े दायरे या संदर्भ परिवर्तन के बाद एक बार **run now** का उपयोग करें।

    ![ऑडिट एडिटर जो cadence, sweep window, scope, analysis settings, context, और notification channels दिखाता है।](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    शेड्यूल सीमा, विंडो व्यवहार, और सभी ऑडिट कमांड के लिए [`fp audits` संदर्भ](/hi/reference/cloud-cli#audits) देखें।
  </Tab>
</Tabs>

जोखिम की गति और लागत से आवृत्ति चुनें:

| जोखिम पैटर्न | शुरुआती आवृत्ति |
| --- | --- |
| उच्च प्रभाव वाली उत्पादन कार्रवाई | दैनिक |
| वर्कफ़्लो या मॉडल प्रतिगमन | साप्ताहिक |
| शासन या पहुंच समीक्षा | मासिक |
| एकबारी रिलीज़ जांच | एक बार चलाएं |

लुकबैक विंडो को आवृत्ति के साथ संरेखित करें ताकि रन न तो अंतराल छोड़ें और न ही अनावश्यक रूप से बड़ी आबादी की बार-बार जांच करें। किसी ऑडिट के लक्ष्य या संदर्भ को बदलने के बाद, अगले निर्धारित परिणाम पर भरोसा करने से पहले इसे मैन्युअल रूप से एक बार चलाएं।

<Note>
  स्थानीय निर्धारित ऑडिट मशीन पर कॉन्फ़िगर किए जाते हैं और स्थानीय एजेंट इतिहास को स्कैन करते हैं। क्लाउड ऑडिट शेड्यूल Cloud सेशन पर काम करते हैं। उनके परिणामों और स्वामित्व को अलग से मानें।
</Note>
