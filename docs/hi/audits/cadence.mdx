ऐसी विफलता मोड्स के लिए पुनरावर्ती ऑडिट का उपयोग करें जो एजेंट्स, प्रॉम्प्ट्स, टूल्स और मॉडल्स के बदलने पर फिर से सामने आ सकती हैं।

## शेड्यूल बदलें

<Tabs>
  <Tab title="Dashboard">
    1. **Analyze → Audits** पर जाएं और ऑडिट खोलें।
    2. इसकी सेटिंग्स खोलें और सक्षम स्थिति, अंतराल, UTC एंकर, विंडो मोड, या लुकबैक बदलें।
    3. ऑडिट सहेजें और ऑडिट कार्ड पर अगले रन का समय पुष्टि करें।
    4. किसी प्रमुख स्कोप या संदर्भ परिवर्तन के बाद एक बार **run now** का उपयोग करें।

    ![ऑडिट एडिटर जो कैडेंस, स्वीप विंडो, स्कोप, विश्लेषण सेटिंग्स, संदर्भ और सूचना चैनल दिखाता है।](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    शेड्यूल सीमाएं, विंडो व्यवहार और सभी ऑडिट कमांड के लिए [`fp audits` संदर्भ](/hi/reference/cloud-cli#audits) देखें।
  </Tab>
</Tabs>

जोखिम की गति और लागत से कैडेंस चुनें:

| जोखिम पैटर्न | शुरुआती कैडेंस |
| --- | --- |
| उच्च-प्रभाव उत्पादन क्रिया | दैनिक |
| वर्कफ़्लो या मॉडल प्रतिगमन | साप्ताहिक |
| गवर्नेंस या एक्सेस समीक्षा | मासिक |
| एक-बार रिलीज जांच | एक बार चलाएं |

लुकबैक विंडो को कैडेंस के साथ संरेखित करें ताकि रन न तो अंतराल छोड़ें और न ही अनावश्यक रूप से बड़ी आबादी की बार-बार जांच करें। किसी ऑडिट का लक्ष्य या संदर्भ बदलने के बाद, अगले निर्धारित परिणाम पर भरोसा करने से पहले इसे एक बार मैन्युअल रूप से चलाएं।

<Note>
  स्थानीय निर्धारित ऑडिट मशीन पर कॉन्फ़िगर किए जाते हैं और स्थानीय एजेंट इतिहास को स्कैन करते हैं। क्लाउड ऑडिट शेड्यूल क्लाउड सत्रों पर काम करते हैं। उनके परिणामों और स्वामित्व को अलग से व्यवहार करें।
</Note>
