## स्थानीय या क्लाउड

| | स्थानीय ऑडिट | क्लाउड ऑडिट |
| --- | --- | --- |
| कमांड | `failproofai audit` | `fp audits` |
| पढ़ता है | इस मशीन पर एजेंट इतिहास | आपके क्लाउड संगठन में सेशन |
| उत्पादन करता है | `localhost:8020/audit` पर स्थानीय परिणाम | साझा निष्कर्ष, समस्याएं और अलर्ट |
| आवश्यकता | कोई खाता नहीं | क्लाउड कनेक्शन और API कुंजी |

एक स्थानीय ऑडिट का उपयोग एक मशीन की त्वरित समीक्षा के लिए करें। क्लाउड का उपयोग करें जब किसी टीम को एजेंट और मशीनों के पार आवर्ती ऑडिट की आवश्यकता हो।

## ऑडिट जो प्रश्नों का उत्तर दे सकता है

- एजेंट कहां बिना एस्केलेट किए रुक जाते हैं?
- कौन सी टूल विफलताएं अप्रभावी पुनः प्रयासों की ओर ले जाती हैं?
- क्या एजेंट इच्छित वर्कफ़्लो के बाहर डेटा तक पहुंच रहे हैं?
- मॉडल, प्रॉम्प्ट या टूल अपडेट के बाद क्या बदला?

## क्लाउड ऑडिट खोलें

**Analyze → Audits** पर जाएं, या उपयोग करें:

```bash
fp audits list
fp audits show <audit-name>
fp audits findings --status open --limit 20
```

ऑडिट कमांड ऑडिट नाम या पूर्ण ID का उपयोग करते हैं। निष्कर्षों का संदर्भ उनकी स्वयं की ID द्वारा दिया जाता है।

## निष्कर्ष से रोकथाम तक

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert
```

एक निष्कर्ष साक्ष्य की ओर संकेत करता है। एक समस्या प्रतिक्रिया का मालिक है। एक policy एक ज्ञात क्रिया पैटर्न को रोकता है; एक alert पुनरावृत्ति के लिए देखभाल करता है।

हर निष्कर्ष को नीति में नहीं बदलना चाहिए। एक `policy` निष्कर्ष एक लागू करने योग्य नियम का वर्णन करता है। एक `failure` या `improvement` को इसके बजाय वर्कफ़्लो, प्रॉम्प्ट, मॉडल या टूल परिवर्तन की आवश्यकता हो सकती है।
