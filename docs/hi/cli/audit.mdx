  अगली स्थिर रिलीज़ से पहले डिटेक्टर कैटलॉग और रिपोर्ट फॉर्मेट बदल सकते हैं। यदि कुछ गलत दिखे तो कृपया एक issue खोलें।

ऑडिट आपके पिछले एजेंट-CLI ट्रांसक्रिप्ट को failproofai की पॉलिसी इंजन के माध्यम से दोबारा चलाता है और **`/audit` डैशबोर्ड पेज** पर एक शेयरेबल, विजुअल रिपोर्ट रेंडर करता है — आपके एजेंट का आर्कटाइप, 0–100 स्कोर, और बिल्कुल कौन सी पॉलिसीज़ क्या पकड़ती।

## इसे चलाएं

तीन तरीके — सभी एक ही `/audit` रिपोर्ट पर पहुंचते हैं।

<CodeGroup>

```bash npx (कोई इंस्टॉल नहीं)
npx -y failproofai audit
```

```bash failproofai audit
failproofai audit
```

```bash failproofai (डैशबोर्ड)
failproofai
```

<Tip>
  उपयोग देखने के लिए `failproofai audit -h` (या `--help`) चलाएं। ऑडिट **पूरी तरह ऑफलाइन** चलता है — कोई अकाउंट या नेटवर्क आवश्यक नहीं — और डैशबोर्ड तब तक सेवा देता रहता है जब तक आप इसे `Ctrl+C` से बंद न करें।
</Tip>

डैशबोर्ड इस मशीन पर पिछले एजेंट CLI ट्रांसक्रिप्ट स्कैन करता है (Claude Code, Codex, Copilot, Cursor, OpenCode, Pi) और रिपोर्ट करता है कि एजेंट ने कितनी बार failproofai को रोकने के लिए बनाई गई चीजें कीं — env-var चेक, force pushes, बेकार `cd <cwd>` प्रीफिक्स, sleep-polling लूप्स, अभी-अभी एडिट की गई फाइलें दोबारा पढ़ना, और बहुत कुछ।

प्रत्येक ट्रांसक्रिप्ट के लिए, हर tool-use इवेंट को 39 बिल्टइन पॉलिसीज़ **और** 8 ऑडिट-केवल डिटेक्टर्स के माध्यम से दोबारा चलाया जाता है जो ऐसे पैटर्न पकड़ते हैं जो अभी तक रनटाइम पॉलिसीज़ द्वारा कवर नहीं हैं। गणनाएं सभी सत्रों में प्रति पॉलिसी / डिटेक्टर एकत्र की जाती हैं।

## आपको क्या मिलता है

`/audit` पेज एक सिंगल-स्क्रीन, शेयरेबल **पोस्टर** है जिसके बाद चार fold-के-नीचे सेक्शन हैं:

1. **पोस्टर** — आपके एजेंट की पहचान एक नज़र में: इसका **आर्कटाइप** (8 में से एक — `optimist`, `cowboy`, `explorer`, `goldfish`, `paranoid architect`, `precision builder`, `hammer`, `ghost`), इसके व्यक्तित्व कीवर्ड, वह आर्कटाइप कितना दुर्लभ है, और एक **0–100 स्कोर** टियर बैंड के साथ (`S` से `bottom tier`)। शेयर करने के लिए बनाया गया — X या LinkedIn पर पोस्ट करें, या इसे PNG के रूप में डाउनलोड करें।
2. **`// strengths`** — आपका एजेंट पहले से क्या अच्छा करता है, स्कैन से वास्तविक संख्याओं के रूप में (जैसे clean-tool-call %, `0` push-to-main प्रयास), केवल जहां प्रासंगिक पॉलिसी का एक स्वच्छ रिकॉर्ड है।
3. **`// quirks`** — जो फिसल गया: failproofai द्वारा पकड़े जाने वाले व्यवहारों की एक रैंक की गई टेबल — *कब* यह आखिरी बार हुआ, *क्या फिसल गया* (और बिल्टइन जो इसे ब्लॉक करता), इसकी *गंभीरता*, और यह कितनी बार *दिखा* (`new` / `recurring` / `N× seen`)।
4. **`// how to improve`** — निर्धारित फिक्स सूची: प्रति पॉलिसी एक पंक्ति कॉपी-पेस्ट `failproofai policy add <slug>` के साथ, साथ ही एक **install all** बटन जो हर सिफारिश को एक बार में सक्षम करता है और आपका **अनुमानित स्कोर** दिखाता है यदि आप ऐसा करते।
5. **`// come back better`** — आदत बनाएं: एक फिर-से-ऑडिट ईमेल **reminder** सेट करें (`3d` / `7d` / `14d` / `30d`) या अभी फिर-से-ऑडिट करें, और **एक दोस्त को आमंत्रित करें** अपना खुद का ऑडिट चलाने के लिए (failproof.ai से भेजा गया, आपको Cc किया गया)। Reminders और invites के लिए साइन-इन आवश्यक है — [`failproofai auth`](/hi/cli/auth) देखें।

## ऑडिट-केवल डिटेक्टर्स

ये "स्टूपिड बिहेवियर" पैटर्न डिटेक्ट करते हैं जो (अभी तक) रीयल टाइम में लागू नहीं हैं। ये केवल ऑडिट के दौरान चलते हैं और कभी भी लाइव tool call को ब्लॉक नहीं करते।

| डिटेक्टर | क्या गिनता है |
|---|---|
| `redundant-cd-cwd` | `cd <cwd> && …` से शुरू होने वाली Bash कमांड भले ही कमांड पहले से ही `cwd` में चलते हों। |
| `prefer-edit-over-read-cat` | एक एकल सोर्स फाइल पर `cat`/`head`/`tail`/`less`/`more` — Read टूल का उपयोग करें। |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` इन-प्लेस एडिट्स — Edit टूल का उपयोग करें। |
| `prefer-write-over-heredoc` | Heredoc / मल्टी-लाइन `echo > file` फाइलें लिखना — Write टूल का उपयोग करें। |
| `sleep-polling-loop` | लंबे `sleep N` (≥ 30s) या `while …; sleep …; done` पोलिंग लूप्स। |
| `find-from-root` | `find /`, `find /home`, `find /usr`, आदि — `cwd` में scope करें। |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, हुक्स को स्किप करता है। |
| `reread-after-edit` | एक फाइल का `Read` जो अभी-अभी उसी सत्र में `Edit`/`Write` था। |

## कैश

- **प्रति-ट्रांसक्रिप्ट कैश** `~/.failproofai/cache/audit/<sha1>.json` पर `(mtime, size, engineVersion, detectorVersion)` से key किया गया — स्वचालित रूप से अमान्य होता है जब ट्रांसक्रिप्ट या पॉलिसी/डिटेक्टर कोड बदलता है। प्रत्येक entry में **TTL metadata** के रूप में एक `cachedAt` टाइमस्टैम्प भी होता है (कैश key का हिस्सा नहीं); **7 दिन** से पुरानी entries को read पर खारिज कर दिया जाता है ताकि लंबे समय के परिणाम विकसित होने वाले डिटेक्टर intent को आउटलाइव न करें।
- **संपूर्ण-परिणाम कैश** `~/.failproofai/audit-dashboard.json` पर (mode 0600)। डैशबोर्ड को बिना re-run किए नेविगेशन पर तुरंत रेंडर करने देता है। **7-दिन TTL** के बाद read पर भी खारिज कर दिया जाता है — `/audit` फिर अपनी खाली स्थिति में गिरता है और एक fresh run के लिए प्रेरित करता है। रिपोर्ट के निचले हिस्से के पास `[ re-audit now ]` पर क्लिक करें refresh करने के लिए — re-audit `noCache: true` भेजता है, इसलिए यह प्रति-ट्रांसक्रिप्ट कैश को बायपास करता है और cached result रिटर्न करने के बजाय हर ट्रांसक्रिप्ट को दोबारा स्कैन करता है; run एक sticky top strip के माध्यम से progress स्ट्रीम करता है और success पर परिणाम को जगह में स्वैप करता है (कोई पेज reload नहीं; एक failed re-audit पिछली रिपोर्ट रखता है)।

## नोट्स

- **कोई mutation नहीं।** ऑडिट read-only mode में दोबारा चलाता है। `warn-repeated-tool-calls` को स्किप किया जाता है क्योंकि इसका per-session sidecar अन्यथा संशोधित होता।
- **वर्कफ़्लो पॉलिसीज़ स्किप की गई।** `require-*-before-stop` पॉलिसीज़ केवल `Stop` events और live git state के विरुद्ध `execSync` पर फायर करती हैं — उनका "2025 में क्या हुआ होता" की कोई सार्थक व्याख्या नहीं है, इसलिए ये ऑडिट गणनाओं में दिखाई नहीं देते।
- **कस्टम पॉलिसीज़ स्किप की गई।** यूजर-सप्लाई की गई कस्टम hooks को दोबारा नहीं चलाया जाता (वे मूल सत्र के बाद से बदल सकते हैं)।
