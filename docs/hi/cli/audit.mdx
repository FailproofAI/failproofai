  अगले स्थिर रिलीज़ से पहले डिटेक्टर कैटलॉग और रिपोर्ट फॉर्मेट बदल सकते हैं। यदि कुछ गलत लगे तो कृपया एक इश्यू खोलें।

ऑडिट आपके पिछले एजेंट-CLI ट्रांसक्रिप्ट्स को failproofai की पॉलिसी इंजन के माध्यम से फिर से चलाता है और **`/audit` डैशबोर्ड पेज** पर एक शेयरेबल, विजुअल रिपोर्ट रेंडर करता है — आपके एजेंट का आर्कटाइप, 0–100 स्कोर, और ठीक से यह दिखाता है कि कौन सी पॉलिसीज़ को क्या पकड़ा होता।

## इसे चलाएं

तीन तरीके — सभी एक ही `/audit` रिपोर्ट पर पहुंचते हैं।

<CodeGroup>

```bash npx (no install)
npx -y failproofai audit
```

```bash failproofai audit
failproofai audit
```

```bash failproofai (dashboard)
failproofai
```

<Tip>
  उपयोग देखने के लिए `failproofai audit -h` (या `--help`) चलाएं। ऑडिट **पूरी तरह ऑफलाइन** चलता है — कोई खाता या नेटवर्क आवश्यक नहीं है — और डैशबोर्ड तब तक सेवा प्रदान करता है जब तक आप इसे `Ctrl+C` से बंद न करें।
</Tip>

डैशबोर्ड इस मशीन पर पिछले एजेंट CLI ट्रांसक्रिप्ट्स को स्कैन करता है (Claude Code, Codex, Copilot, Cursor, OpenCode, Pi) और रिपोर्ट करता है कि एजेंट कितनी बार वह काम करता है जो failproofai को रोकने के लिए बनाया गया है — env-var चेक, force push, redundant `cd <cwd>` प्रीफिक्स, sleep-polling लूप्स, अभी-अभी एडिट की गई फाइलें दोबारा पढ़ना, और बहुत कुछ।

प्रत्येक ट्रांसक्रिप्ट के लिए, हर tool-use इवेंट को 39 बिल्ट-इन पॉलिसीज़ **और** 8 audit-only डिटेक्टर्स के माध्यम से फिर से चलाया जाता है जो रनटाइम पॉलिसीज़ द्वारा अभी तक कवर नहीं किए गए पैटर्न को पकड़ते हैं। सभी सेशन्स में प्रति पॉलिसी / डिटेक्टर काउंट्स को एकत्रित किया जाता है।

## आपको क्या मिलता है

`/audit` पेज एक single-screen, शेयरेबल **पोस्टर** है जिसके बाद चार below-the-fold सेक्शन हैं:

1. **Poster** — आपके एजेंट की पहचान एक नज़र में: इसका **आर्कटाइप** (8 में से एक — `optimist`, `cowboy`, `explorer`, `goldfish`, `paranoid architect`, `precision builder`, `hammer`, `ghost`), इसके व्यक्तित्व के कीवर्ड, वह आर्कटाइप कितना दुर्लभ है, और 0–100 **स्कोर** एक टियर बैंड के साथ (`S` से `bottom tier` तक)। शेयर करने के लिए बनाया गया — X या LinkedIn पर पोस्ट करें, या इसे PNG के रूप में डाउनलोड करें।
2. **`// strengths`** — आपका एजेंट पहले से क्या अच्छी तरह करता है, स्कैन से वास्तविक संख्याओं के रूप में (जैसे clean-tool-call %, `0` push-to-main प्रयास), केवल जहां प्रासंगिक पॉलिसी के पास एक स्वच्छ रिकॉर्ड है।
3. **`// quirks`** — क्या सरक गया: failproofai को पकड़ा जाता behaviors की एक रैंकिंग वाली तालिका — *कब* यह आखिरी बार हुआ, *क्या सरक गया* (और बिल्ट-इन जो इसे ब्लॉक करता), इसकी *गंभीरता*, और यह कितनी बार *देखा गया* (`new` / `recurring` / `N× seen`)।
4. **`// how to improve`** — निर्धारित फिक्स लिस्ट: प्रति पॉलिसी एक पंक्ति copy-paste `failproofai policy add <slug>` के साथ, प्लस **install all** बटन जो हर सिफारिश को एक बार में सक्षम करता है और आपका **projected score** दिखाता है यदि आप करते।
5. **`// come back better`** — आदत बनाएं: एक re-audit email **reminder** सेट करें (`3d` / `7d` / `14d` / `30d`) या अभी फिर से ऑडिट करें, और **एक दोस्त को आमंत्रित करें** अपना स्वयं का ऑडिट चलाने के लिए (failproof.ai से भेजा गया, आपको Cc किया गया)। Reminders और invites को साइन-इन की आवश्यकता है।

## शेड्यूल किए गए ऑडिट्स

यदि आप **failproofaid daemon** चलाते हैं (देखें [`failproofai config`](/hi/cli/install-policies)),
यह आपके लिए शेड्यूल पर ऑडिट को फिर से चला सकता है और `/audit` रिपोर्ट को बैकग्राउंड में रीफ्रेश कर सकता है। यह **डिफॉल्ट रूप से बंद** है, क्योंकि स्कैन इस मशीन पर हर एजेंट सेशन ट्रांसक्रिप्ट की *सामग्री* पढ़ता है — कुछ भी टाइमर पर स्कैन नहीं होता जब तक आप इसके लिए न कहें।

इसे `~/.failproofai/config.toml` में चालू करें:

```toml
[audit]
auto = true
interval_days = 7
```

| Key | Meaning |
|---|---|
| `auto` | `true` शेड्यूल किए गए स्कैन को सक्षम करता है। कुछ भी और — अनुपस्थित, `false`, `"yes"` — बंद है। |
| `interval_days` | स्कैन के बीच दिन। 1–90 तक क्लैम्प किया गया; `0`, नकारात्मक या गैर-संख्या `7` पर वापस जाता है। |

- शेड्यूल **wall-clock** है, इसलिए यह suspend और reboots से बचता है: एक लैपटॉप जो अपने कारण समय के दौरान सो रहा था **एक बार** wake पर चलता है, कभी backlog नहीं।
- प्रत्येक रन एक अलग, low-priority (`nice 19`) प्रक्रिया है — कभी daemon के hook path का नहीं, जो tool calls का उत्तर देने के लिए स्वतंत्र रहता है।
- एक स्कैन छोड़ दिया जाता है यदि `failproofai audit` या डैशबोर्ड के re-run पहले से ही चल रहे हैं; इसे जल्द ही फिर से प्रयास किया जाता है बजाय failure के रूप में माने जाने के।
- Progress को `~/.failproofai/state/audit-schedule.json` में लिखा जाता है (last run, next due)। Daemon उस फाइल के मालिक हैं — `config.toml` में cadence बदलें।

<Note>
यदि आपने इसे एक पुराने failproofai द्वारा सेट की गई मशीन पर सक्षम किया है, तो एक बार `failproofai config` चलाएं। Daemon की service definition को इसे लॉन्च करने से पहले CLI एक अतिरिक्त entry की आवश्यकता है, और refresh उस command का हिस्सा है।
</Note>

## Audit-only डिटेक्टर्स

ये real time में अभी (अभी तक) लागू नहीं किए गए "stupid behavior" पैटर्न का पता लगाते हैं। वे केवल ऑडिट के दौरान चलते हैं और कभी live tool call को ब्लॉक नहीं करते।

| Detector | क्या यह गिनता है |
|---|---|
| `redundant-cd-cwd` | Bash कमांड जो `cd <cwd> && …` से शुरू होते हैं भले ही कमांड पहले से `cwd` में चलते हों। |
| `prefer-edit-over-read-cat` | एकल स्रोत फाइल पर `cat`/`head`/`tail`/`less`/`more` — `Read` tool का उपयोग करें। |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` in-place edits — `Edit` tool का उपयोग करें। |
| `prefer-write-over-heredoc` | Heredoc / multi-line `echo > file` लिखती फाइलें — `Write` tool का उपयोग करें। |
| `sleep-polling-loop` | लंबे `sleep N` (≥ 30s) या `while …; sleep …; done` polling loops। |
| `find-from-root` | `find /`, `find /home`, `find /usr`, आदि। — `cwd` के बजाय स्कोप करें। |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, hooks को छोड़ते हुए। |
| `reread-after-edit` | एक फाइल का `Read` जो उसी सेशन में अभी-अभी `Edit`/`Write` था। |

## Caches

- **Per-transcript cache** `~/.failproofai/cache/audit/<sha1>.json` पर `(mtime, size, engineVersion, detectorVersion)` द्वारा keyed — transcript या policy/detector code बदलने पर स्वचालित रूप से अमान्य हो जाता है। प्रत्येक entry एक `cachedAt` टाइमस्टैम्प को **TTL metadata** के रूप में भी स्टोर करता है (cache key का हिस्सा नहीं); **7 दिन** से पुरानी entries को read पर अस्वीकार किया जाता है ताकि लंबे समय तक चलने वाले परिणाम विकसित होते डिटेक्टर intent को outlive न करें।
- **Whole-result cache** `~/.failproofai/audit-dashboard.json` पर (mode 0600)। डैशबोर्ड को re-running के बिना navigation पर तुरंत रेंडर करने देता है। **7-day TTL** के बाद read पर भी अस्वीकार किया जाता है — `/audit` फिर अपने empty state में गिरता है और एक ताज़ा run के लिए प्रेरित करता है। रिपोर्ट के निचले हिस्से के पास `[ re-audit now ]` पर क्लिक करें refresh करने के लिए — re-audit `noCache: true` भेजता है, इसलिए यह per-transcript cache को bypass करता है और cached result देने के बजाय हर transcript को फिर से स्कैन करता है; run एक sticky top strip के माध्यम से progress को stream करता है और success पर result को जगह में swap करता है (कोई page reload नहीं; एक failed re-audit पिछली रिपोर्ट रखता है)।

## नोट्स

- **कोई mutation नहीं।** ऑडिट read-only mode में फिर से चलाता है। `warn-repeated-tool-calls` को छोड़ दिया जाता है क्योंकि इसका per-session sidecar अन्यथा संशोधित हो जाएगा।
- **Workflow policies छोड़े गए।** `require-*-before-stop` policies केवल `Stop` events और live git state के विरुद्ध `execSync` पर fire होती हैं — उनके पास कोई सार्थक "2025 में क्या हुआ होता" interpretation नहीं है, इसलिए वे audit counts में दिखाई नहीं देते।
- **कस्टम policies छोड़े गए।** User-supplied कस्टम hooks को फिर से चलाया नहीं जाता (वे मूल सेशन के बाद से बदल सकते हैं)।
