<Note>
  **बीटा फीचर।** ऑडिट बीटा के रूप में शिप किया जा रहा है जबकि हम प्रारंभिक फीडबैक एकत्र करते हैं।
  डिटेक्टर कैटलॉग और रिपोर्ट फॉर्मेट अगले स्थिर रिलीज़ से पहले बदल सकते हैं। यदि कुछ गलत लगे
  तो कृपया एक इश्यू खोलें।
</Note>

ऑडिट आपकी पिछली एजेंट-CLI ट्रांसक्रिप्ट्स को failproofai की पॉलिसी इंजन के माध्यम से फिर से चलाता है और **`/audit` डैशबोर्ड पृष्ठ** पर एक साझा किए जाने योग्य, विजुअल रिपोर्ट प्रस्तुत करता है — आपके एजेंट का आर्किटाइप, 0–100 स्कोर, और बिल्कुल कौन सी पॉलिसीज़ क्या पकड़ती।

## इसे चलाएं

तीन तरीके — सभी समान `/audit` रिपोर्ट पर पहुंचते हैं।

<CodeGroup>

```bash npx (कोई इंस्टॉल नहीं)
npx -y failproofai audit
```

```bash failproofai audit
failproofai audit
```

```bash failproofai (डैशबोर्ड)
failproofai
```

</CodeGroup>

  ऑफलाइन** चलता है — कोई खाता या नेटवर्क आवश्यक नहीं — और डैशबोर्ड तब तक सेवा देता रहता है
  जब तक आप इसे `Ctrl+C` से बंद न कर दें।

डैशबोर्ड इस मशीन पर पिछली एजेंट CLI ट्रांसक्रिप्ट्स को स्कैन करता है (Claude Code, Codex, Copilot, Cursor, OpenCode, Pi) और रिपोर्ट करता है कि एजेंट ने कितनी बार वे काम किए जो failproofai को रोकने के लिए बनाया गया है — env-var चेक, force push, redundant `cd <cwd>` उपसर्ग, sleep-polling लूप, अभी-अभी संपादित की गई फाइलों को फिर से पढ़ना, और बहुत कुछ।

प्रत्येक ट्रांसक्रिप्ट के लिए, हर tool-use इवेंट को 39 builtin पॉलिसीज़ **और** 8 audit-only डिटेक्टर्स के माध्यम से फिर से चलाया जाता है जो उन पैटर्न को पकड़ते हैं जो अभी तक runtime पॉलिसीज़ द्वारा कवर नहीं हैं। गिनती सभी सत्रों में प्रति पॉलिसी / डिटेक्टर एकत्र की जाती है।

## आपको क्या मिलता है

`/audit` पेज एक एकल-स्क्रीन, साझा किए जाने योग्य **पोस्टर** है जिसके बाद चार fold-के-नीचे अनुभाग हैं:

1. **पोस्टर** — आपके एजेंट की पहचान एक नजर में: इसका **आर्किटाइप** (8 में से एक — `optimist`, `cowboy`, `explorer`, `goldfish`, `paranoid architect`, `precision builder`, `hammer`, `ghost`), इसके व्यक्तित्व कीवर्ड, वह आर्किटाइप कितना दुर्लभ है, और एक **0–100 स्कोर** एक स्तर बैंड के साथ (`S` से `bottom tier`)। साझा करने के लिए बनाया गया — X या LinkedIn पर पोस्ट करें, या इसे PNG के रूप में डाउनलोड करें।
2. **`// strengths`** — आपका एजेंट पहले से ही क्या अच्छी तरह करता है, स्कैन से वास्तविक संख्याओं के रूप में (जैसे clean-tool-call %, `0` push-to-main प्रयास), केवल वहां दिखाया जाता है जहां प्रासंगिक पॉलिसी का एक स्वच्छ रिकॉर्ड है।
3. **`// quirks`** — क्या अंतराल में फिसला: failproofai जो पकड़ता उसके व्यवहारों की एक रैंक की गई तालिका — *कब* यह आखिरी बार हुआ, *क्या फिसला* (और builtin जो इसे अवरुद्ध करता), इसकी *गंभीरता*, और यह कितनी बार *देखा* गया (`new` / `recurring` / `N× seen`)।
4. **`// how to improve`** — निर्धारित सुधार सूची: एक row प्रति पॉलिसी copy-paste `failproofai policy add <slug>` के साथ, साथ ही एक **सभी को इंस्टॉल करें** बटन जो हर सिफारिश को एक बार में सक्षम करता है और आपके **अनुमानित स्कोर** दिखाता है यदि आप करते।
5. **`// come back better`** — आदत बनाएं: एक re-audit ईमेल **reminder** सेट करें (`3d` / `7d` / `14d` / `30d`) या अभी re-audit करें, और **किसी मित्र को आमंत्रित करें** अपना स्वयं का ऑडिट चलाने के लिए (failproof.ai से भेजा गया, आपको Cc किया गया)। Reminders और invites को साइन-इन की आवश्यकता है।

## निर्धारित ऑडिट

यदि आप **failproofaid daemon** चलाते हैं (देखें [`failproofai config`](/hi/cli/install-policies)),
यह आपके लिए अनुसूची पर ऑडिट को फिर से चला सकता है और `/audit` रिपोर्ट को
पृष्ठभूमि में ताज़ा कर सकता है। यह **डिफ़ॉल्ट रूप से बंद है**, क्योंकि स्कैन इस मशीन पर हर एजेंट सत्र ट्रांसक्रिप्ट की *सामग्री* को पढ़ता है — कुछ भी टाइमर पर स्कैन नहीं करता जब तक आप इसके लिए नहीं कहते।

`~/.failproofai/config.json` में इसे चालू करें — `audit` कुंजी जोड़ें साथ में
जो कुछ भी फाइल पहले से ही रखती है:

```json
{
  "audit": {
    "auto": true,
    "interval_days": 7
  }
}
```

| कुंजी | अर्थ |
|---|---|
| `auto` | `true` निर्धारित स्कैन को सक्षम करता है। कुछ भी और — अनुपस्थित, `false`, `"yes"` — बंद है। |
| `interval_days` | स्कैन के बीच दिन। 1–90 के लिए क्लैंप किया गया; `0`, नकारात्मक या non-number `7` पर फॉल बैक करता है। |

- शेड्यूल **wall-clock** है, इसलिए यह suspend और reboot से बचता है: एक लैपटॉप
  जो अपने due समय के माध्यम से सो रहा था **एक बार** wake पर चलता है, कभी backlog नहीं।
- प्रत्येक चलन एक अलग, low-priority (`nice 19`) प्रक्रिया है — कभी daemon की
  hook path नहीं, जो tool calls का उत्तर देने के लिए स्वतंत्र रहता है।
- एक स्कैन छोड़ दिया जाता है यदि `failproofai audit` या डैशबोर्ड का re-run पहले से
  चल रहा है; इसे जल्द ही फिर से कोशिश की जाती है न कि विफलता के रूप में माना जाता है।
- प्रगति `~/.failproofai/state/audit-schedule.json` को लिखी जाती है (last run,
  next due)। Daemon उस फाइल का मालिक है — `config.json` में cadence बदलें।

<Note>
यदि आपने एक पुराने failproofai द्वारा सेट अप की गई मशीन पर इसे सक्षम किया है, तो एक बार
`failproofai config` चलाएं। Daemon की service परिभाषा को CLI को launch करने से पहले एक अतिरिक्त
entry की आवश्यकता है, और refresh उस command का हिस्सा है।
</Note>

## Audit-only डिटेक्टर्स

ये उन "stupid behavior" पैटर्न को डिटेक्ट करते हैं जो (अभी तक) real time में लागू नहीं हैं। वे केवल ऑडिट के दौरान चलते हैं और कभी भी live tool call को ब्लॉक नहीं करते।

| डिटेक्टर | यह क्या गिनता है |
|---|---|
| `redundant-cd-cwd` | Bash कमांड जो `cd <cwd> && …` से शुरू होते हैं भले ही कमांड पहले से `cwd` में चलते हों। |
| `prefer-edit-over-read-cat` | एक एकल source फाइल पर `cat`/`head`/`tail`/`less`/`more` — `Read` tool का उपयोग करें। |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` in-place संपादन — `Edit` tool का उपयोग करें। |
| `prefer-write-over-heredoc` | Heredoc / multi-line `echo > file` फाइलें लिखना — `Write` tool का उपयोग करें। |
| `sleep-polling-loop` | लंबा `sleep N` (≥ 30s) या `while …; sleep …; done` polling लूप। |
| `find-from-root` | `find /`, `find /home`, `find /usr`, आदि। — `cwd` के लिए scope करें। |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, hooks को छोड़ना। |
| `reread-after-edit` | एक फाइल का `Read` जो अभी-अभी `Edit`/`Write` था समान सत्र में। |

## कैशेज़

- **Per-transcript cache** at `~/.failproofai/cache/audit/<sha1>.json` keyed by `(mtime, size, engineVersion, detectorVersion)` — जब ट्रांसक्रिप्ट या policy/detector कोड बदलता है तो स्वचालित रूप से अमान्य हो जाता है। प्रत्येक entry एक `cachedAt` timestamp भी स्टोर करता है **TTL मेटाडेटा** के रूप में (cache key का हिस्सा नहीं); **7 दिन** से पुरानी entries को read पर reject किया जाता है ताकि long-lived results विकसित होते detector intent को outlive न करें।
- **Whole-result cache** at `~/.failproofai/audit-dashboard.json` (mode 0600)। डैशबोर्ड को navigation पर तुरंत render करने देता है बिना re-running के। read पर **7-day TTL** के बाद भी reject किया जाता है — `/audit` फिर अपनी empty state में गिरता है और fresh run के लिए prompt करता है। रिपोर्ट के नीचे के पास `[ re-audit now ]` पर क्लिक करें refresh करने के लिए — re-audit `noCache: true` भेजता है, इसलिए यह per-transcript cache को बायपास करता है और हर ट्रांसक्रिप्ट को फिर से स्कैन करता है cached result return करने की बजाय; run एक sticky top strip के माध्यम से progress stream करता है और success पर result को जगह में swap करता है (कोई page reload नहीं; एक failed re-audit पिछली report रखता है)।

## नोट्स

- **कोई mutation नहीं।** ऑडिट read-only mode में फिर से चलता है। `warn-repeated-tool-calls` छोड़ दिया जाता है क्योंकि इसका per-session sidecar अन्यथा modified होता।
- **Workflow policies छोड़े गए।** `require-*-before-stop` policies केवल `Stop` events पर और live git state के विरुद्ध `execSync` पर fire होती हैं — उनके पास कोई meaningful "what would have happened in 2025" interpretation नहीं है, इसलिए वे audit counts में प्रकट नहीं होती।
- **Custom policies छोड़े गए।** User-supplied custom hooks को फिर से चलाया नहीं जाता (वे original session के बाद से बदल गए हो सकते हैं)।
