## Dashboard

| Variable | Description |
|----------|-------------|
| `PORT` | Dashboard port (default: `8020`) |
| `CLAUDE_PROJECTS_PATH` | Override where Claude Code project folders are found |
| `FAILPROOFAI_DISABLE_PAGES=policies,projects` | Comma-separated dashboard pages to hide |
| `FAILPROOFAI_ALLOWED_DEV_ORIGINS` | Hosts/IPs allowed to access dev resources. Same as `--allowed-origins`. |

## Logging

| Variable | Description |
|----------|-------------|
| `FAILPROOFAI_LOG_LEVEL=info\|warn\|error` | Server log level (default: `warn`) |
| `FAILPROOFAI_HOOK_LOG_FILE` | Custom hook log file path, or `true` for default (`~/.failproofai/logs/hooks.log`) |

## Telemetry

failproofai डिफ़ॉल्ट रूप से anonymous usage telemetry रिपोर्ट करता है। इसे बंद करने के दो तरीके हैं, और वे जो भी अधिक प्रतिबंधक है उसे लागू करते हैं — एक environment variable कभी भी किसी ऐसी चीज़ को फिर से सक्षम नहीं कर सकता जिसे config फ़ाइल ने बंद कर दिया है।

| Variable | Description |
|----------|-------------|
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | इस प्रक्रिया के लिए anonymous usage telemetry को अक्षम करें |

इसे मशीन के लिए स्थायी रूप से अक्षम करने के लिए, इसे `~/.failproofai/config.toml` में जोड़ें:

```toml
[telemetry]
enabled = false
```

<Note>
Config फ़ाइल वह विकल्प है जो आप तब उपयोग करते हैं जब आप **failproofaid daemon** चलाते हैं।
Daemon एक system-scope सेवा है, और इसका environment आपके shell से निर्यात किए गए variables को शामिल नहीं करता — इसलिए `FAILPROOFAI_TELEMETRY_DISABLED` इस तक नहीं पहुंच सकता। `[telemetry] enabled = false` को CLI और daemon दोनों द्वारा पढ़ा जाता है।
</Note>

Daemon केवल अपने **lifecycle** की रिपोर्ट करता है: कि यह शुरू हुआ (और क्या पिछला run cleanly से exit हुआ), कि यह बंद हुआ, जब इसका evaluation worker spawn या restart किया गया, जब एक collector task विफल हुआ, और एक cloud-policy pull का परिणाम। ये low-cardinality values और counts ले जाते हैं — कभी एक फ़ाइल path, एक command, एक policy, एक prompt, या transcript से पढ़ी गई कोई भी चीज़ नहीं। कोई per-tool-call event नहीं है।

## Authentication

| Variable | Description |
|----------|-------------|
| `FAILPROOF_API_URL` | Dashboard auth dialog द्वारा उपयोग किए जाने वाले api-server base URL को override करें। `https://api.befailproof.ai` को डिफ़ॉल्ट करता है; एक local api-server चलाते समय `http://localhost:8080` (या कहीं और) पर सेट करें। |
| `FAILPROOFAI_AUTH_DIR` | Override जहां `auth.json` संग्रहीत है (default: `~/.failproofai`)। ज्यादातर isolated tests के लिए उपयोगी है। |

## First-run prompt

| Variable | Description |
|----------|-------------|
| `FAILPROOFAI_NO_FIRST_RUN=1` | पहली bare `failproofai` invocation पर policies install करने का प्रस्ताव देने वाले prompt को छोड़ें |

## LLM (policy evaluation के लिए)

| Variable | Description |
|----------|-------------|
| `FAILPROOFAI_LLM_BASE_URL` | LLM API endpoint (default: `https://api.openai.com/v1`) |
| `FAILPROOFAI_LLM_API_KEY` | LLM-powered policies के लिए API key |
| `FAILPROOFAI_LLM_MODEL` | Model name (default: `gpt-4o-mini`) |
