---
title: होम डायरेक्टरी को माइग्रेट करें
description: "~/.failproofai को इस संस्करण के लेआउट तक लाएं, और पहले देखें कि क्या होगा"
---

```bash
failproofai migrate --dry-run   # योजना प्रिंट करें, कुछ न बदलें
failproofai migrate             # इसे चलाएं
```

अधिकांश लोग इसे कभी टाइप नहीं करते। यह अपग्रेड के बाद पहली कमांड पर अपने आप चलता है, और [`failproofai update`](/hi/cli/update) इसे शामिल करता है। इसे सीधे तब प्राप्त करें जब आप योजना को घटित होने से पहले देखना चाहते हों, या माइग्रेशन को अपने आप चलाना चाहते हों।

## लेआउट पर कुंजी है, संस्करण पर नहीं

`~/.failproofai/VERSION` एक **लेआउट** नंबर रिकॉर्ड करता है — डायरेक्टरी का आकार, न कि वह रिलीज़ जिसने इसे लिखा। माइग्रेशन उस नंबर पर कुंजी होते हैं, जो एक लंबे अंतराल को सस्ता बनाता है:

- npm संस्करण हर रिलीज़ पर बदलते हैं, दो लेआउट के बीच दर्जनों।
- तो एक मशीन जो तीस रिलीज़ को छोड़ देती है **कोई लेआउट परिवर्तन नहीं** होने पर **शून्य** माइग्रेशन चलाती है, तीस नो-ऑप्स नहीं।
- और एक मशीन जो एक साथ कई लेआउट छोड़ देती है हर कदम को क्रम में चलाती है, प्रत्येक कदम केवल अपने दोनों सिरों को जानता है।

यह मायने रखता है क्योंकि npm अपने आप पर एक स्थापित पैकेज को अपडेट नहीं कर सकता। एक मशीन जो महीनों तक एक संस्करण पर बैठी रहती है और फिर कई लेआउट छोड़ जाती है यह सामान्य मामला है, अनोखा नहीं।

## ड्राई रन

`--dry-run` सटीक श्रृंखला और फाइलें प्रिंट करता है जो सबसे पहले सहेजी जाएंगी, और बिल्कुल कुछ नहीं बदलता — कोई माइग्रेशन नहीं, कोई बैकअप नहीं, कोई लेजर प्रविष्टि नहीं:

```
डिस्क पर लेआउट 2; यह बिल्ड 3 बोलता है।
1 कदम(ों) को चलाया जाएगा:
  2 → 3  लेआउट 2 → 3: config.toml और credentials.toml को JSON में ले जाएं, कस्टम-पॉलिसीज़/ को वापस पॉलिसीज़/ में ले जाएं, पॉलिसी कॉन्फ़िग को रूट पर नेस्ट करें

ये ~/.failproofai/migrations/backup-layout2 में पहले कॉपी किए जाएंगे:
  VERSION
  config.toml
  credentials.toml
```

## क्या किया जाता है, और क्या फिर से बनाया जाता है

होम डायरेक्टरी में हर पथ घोषित करता है कि यह किस प्रकार का डेटा रखता है, और यह निर्धारित करता है कि माइग्रेशन इसे फेंक सकता है या नहीं। नियम: **व्युत्पन्न और पुनः प्राप्य को छोड़ा जा सकता है; जो कुछ आपने टाइप किया, जो अभी तक दिया नहीं गया है, और जो मशीन को पहचानता है उसे किया जाता है।**

| किया जाता है | फिर से बनाया या पुनः प्राप्त |
|---|---|
| `config.json` — सेटिंग्स, `daemon.configured`, अतिरिक्त कैप्चर पथ | ऑडिट कैश |
| `credentials.json` — आपका क्लाउड नामांकन | क्लाउड-प्रबंधित तैनातियां (अगले पोल पर पुनः प्राप्त और डाइजेस्ट-सत्यापित) |
| `policies-config.json` — आपकी पॉलिसी चयन और पैरामीटर | डेमॉन स्क्रैच स्थिति |
| `policies/` — आपकी अपनी पॉलिसी फाइलें और वे हेल्पर जो वे आयात करते हैं | |
| `hook-activity/` — निर्णय लॉग जो डैशबोर्ड पढ़ता है | |
| अपलोड के लिए अभी भी कतार में न दी गई घटनाएं | |
| `cursors/` — कलेक्टर वाटरमार्क | |
| `bin/` में डेमॉन बाइनरी | |

<Note>
  न दी गई घटनाओं को छोड़ा जाने के बजाय किया जाता है क्योंकि नुकसान स्थायी होगा, धीमा नहीं: कलेक्टर का वाटरमार्क पहले से ही स्पूल में बैठी किसी भी चीज़ के आगे निकल गया है, तो कोई भी ट्रांसक्रिप्ट की उस श्रृंखला को फिर से कभी नहीं पढ़ेगा। माइग्रेशन डेमॉन को भी कहता है कि यह समाप्त होने के बाद स्पूल में क्या है उसे दिया जाए, तो सामान्य परिणाम यह है कि किया जाने के लिए कुछ नहीं रहता।
</Note>

कुंजियाँ जो एक *नवीनतर* संस्करण ने `config.json`, `credentials.json` या `policies-config.json` में लिखी हैं, वह भी संरक्षित हैं, एक पुराने पाठक द्वारा छोड़ी जाने के बजाय।

## यह जो रिकॉर्ड छोड़ता है

```
~/.failproofai/migrations/
  applied.json                 प्रति कदम एक प्रविष्टि: लेआउट, CLI, टाइमस्टैम्प, अवधि, परिणाम
  backup-layout<n>/            पहले कदम से पहले लिए गए अपरिवर्तनीय फाइलों की प्रतियां
```

`applied.json` वह है जो "इस मशीन ने वास्तव में क्या किया है" का उत्तर देता है — अपग्रेड के बाद कुछ गलत दिखने पर पूछने के लिए पहला सवाल। इसे एक बग रिपोर्ट से संलग्न करें।

बैकअप जानबूझकर पूरी डायरेक्टरी की प्रतिलिपि के बजाय छोटा है: माइग्रेशन अब डिज़ाइन के अनुसार कुछ भी अपरिवर्तनीय नहीं हटाता है, तो जो बीमा के लायक है वह एक *कदम में कमी* है, और ये कुछ फाइलें वह हैं जहां ऐसी एक कमी चोट पहुंचाएगी।

## अगर एक कदम विफल हो

श्रृंखला वहीं रुक जाती है। `VERSION` को केवल एक पूर्ण कदम द्वारा मुहर लगाई जाती है, तो होम अपने पुराने लेआउट के साथ चिह्नित रहता है और अगली कमांड इसे फिर से ट्राई करती है — एक होम को कभी आंशिक माइग्रेशन की ताकत पर वर्तमान नहीं किया जाता है। कदम `applied.json` में `"ok": false` के साथ रिकॉर्ड किया जाता है, और बैकअप वह है जहां इसे लिया गया था।

## एक नवीनतर होम को माइग्रेट नहीं किया जाता है, अस्वीकार किया जाता है

अगर `~/.failproofai/` एक **नवीनतर** failproofai द्वारा लिखा गया था जो आप चला रहे हैं, कमांड रुक जाती है और आपको अपग्रेड करने के लिए कहती है। वह डेटा ठीक है और एक नवीनतर CLI इसे पढ़ता है; इससे "आगे" माइग्रेट करना एक चीज़ नहीं है जो मौजूद है, और इसे रीसेट करने से कुछ पुनः प्राप्य नष्ट हो जाएगा।

```
इस मशीन की failproofai डायरेक्टरी एक नवीनतर संस्करण द्वारा लिखी गई थी (लेआउट 4;
यह बिल्ड 3 बोलता है)। माइग्रेट करने के बजाय अपग्रेड करें:
  npm install -g failproofai@latest
```

डेमॉन एक ही नियम लागू करता है: `failproofaid` एक लेआउट के खिलाफ शुरू करने से इनकार करता है जो यह नहीं बोलता है, बजाय पथ को पढ़ने और लिखने के जो स्थानांतरित हो गए हैं।
