description: "~/.failproofai को इस संस्करण के लेआउट तक लाएं, और पहले देखें कि क्या होगा"
---

```bash
failproofai migrate --dry-run   # योजना प्रिंट करें, कुछ न बदलें
failproofai migrate             # इसे चलाएं
```

अधिकांश लोग इसे कभी टाइप नहीं करते। यह अपग्रेड के बाद पहली कमांड पर अपने आप चलता है, और [`failproofai update`](/hi/cli/update) इसे शामिल करता है। इसे सीधे तब चलाएं जब आप योजना को घटित होने से पहले देखना चाहते हैं, या माइग्रेशन को अपने आप चलाना चाहते हैं।

## संस्करण के बजाय लेआउट पर आधारित

`~/.failproofai/VERSION` एक **लेआउट** संख्या रिकॉर्ड करता है — डायरेक्टरी का आकार, उस रिलीज़ नहीं जिसने इसे लिखा। माइग्रेशन उस संख्या पर आधारित होते हैं, जो एक लंबे अंतराल को सस्ता बनाता है:

- npm संस्करण हर रिलीज़ पर बदलते हैं, दो लेआउट के बीच दर्जनों।
- तो एक मशीन जो **कोई लेआउट परिवर्तन नहीं** के साथ तीस रिलीज़ को छोड़ देती है, **शून्य** माइग्रेशन चलाती है, तीस व्यर्थ नहीं।
- और एक मशीन जो एक साथ कई लेआउट को छोड़ देती है, प्रत्येक चरण को क्रम में चलाती है, प्रत्येक चरण केवल अपने दोनों सिरों को जानता है।

यह महत्वपूर्ण है क्योंकि npm एक स्थापित पैकेज को अपने आप अपडेट नहीं कर सकता। एक मशीन जो महीनों तक एक संस्करण पर बैठी रहती है और फिर कई लेआउट को कूद जाती है, यह सामान्य स्थिति है, असामान्य नहीं।

## ड्राई रन

`--dry-run` सटीक श्रृंखला और उन फ़ाइलों को प्रिंट करता है जो पहले सहेजी जाएंगी, और बिल्कुल कुछ नहीं बदलता — कोई माइग्रेशन नहीं, कोई बैकअप नहीं, कोई लेजर प्रविष्टि नहीं:

```
डिस्क पर लेआउट 2; यह बिल्ड 3 बोलता है।
1 चरण चलेंगे:
  2 → 3  लेआउट 2 → 3: config.toml और credentials.toml को JSON में ले जाएं, 
         custom-policies/ को policies/ में वापस ले जाएं, नीति कॉन्फ़िग को रूट पर नेस्ट करें

ये ~/.failproofai/migrations/backup-layout2 में पहले कॉपी किए जाएंगे:
  VERSION
  config.toml
  credentials.toml
```

## क्या किया जाता है और क्या पुनः बनाया जाता है

होम में हर पथ घोषणा करता है कि यह किस प्रकार का डेटा रखता है, और यह तय करता है कि क्या माइग्रेशन इसे फेंक सकता है। नियम: **व्युत्पन्न और पुनः प्राप्ति योग्य को छोड़ा जा सकता है; कुछ भी जो आपने टाइप किया, कुछ भी जो अभी तक वितरित नहीं हुआ, और कुछ भी जो मशीन की पहचान करता है उसे किया जाता है।**

| किया जाता है | पुनः बनाया या पुनः प्राप्त किया जाता है |
|---|---|
| `config.json` — सेटिंग्स, `daemon.configured`, अतिरिक्त कैप्चर पाथ | ऑडिट कैश |
| `credentials.json` — आपका क्लाउड नामांकन | क्लाउड-प्रबंधित तैनाती (अगले पोल पर पुनः प्राप्त और डाइजेस्ट-सत्यापित) |
| `policies-config.json` — आपकी नीति चयन और पैरामीटर | डेमन स्क्रैच स्थिति |
| `policies/` — आपकी अपनी नीति फ़ाइलें और सहायक जो वे आयात करते हैं | |
| `hook-activity/` — निर्णय लॉग जो डैशबोर्ड पढ़ता है | |
| अभी तक वितरित न किए गए इवेंट अभी भी अपलोड के लिए कतार में हैं | |
| `cursors/` — कलेक्टर वाटरमार्क | |
| `bin/` में डेमन बाइनरी | |

<Note>
  अप्रदत्त इवेंट को छोड़ा जाता है न कि गिराया जाता है क्योंकि नुकसान स्थायी होगा, धीमा नहीं: कलेक्टर का वाटरमार्क पहले ही स्पूल में बैठी किसी भी चीज़ के आगे बढ़ चुका है, इसलिए कोई भी ट्रांसक्रिप्ट की उस श्रेणी को फिर कभी नहीं पढ़ेगा। माइग्रेशन डेमन को स्पूल किए गए को समाप्त होने के तुरंत बाद वितरित करने के लिए भी कहता है, इसलिए सामान्य परिणाम यह है कि ले जाने के लिए कुछ नहीं बचा है।
</Note>

जो कुंजियां एक **नए** संस्करण ने `config.json`, `credentials.json` या `policies-config.json` में लिखी हैं, वे भी संरक्षित हैं, न कि एक पुराने पाठक द्वारा गिराई गई।

## यह जो रिकॉर्ड छोड़ता है

```
~/.failproofai/migrations/
  applied.json                 प्रति चरण एक प्रविष्टि: लेआउट, CLI, टाइमस्टैम्प, अवधि, परिणाम
  backup-layout<n>/            अपरिवर्तनीय फ़ाइलों की प्रतियां, पहले चरण से पहले ली गईं
```

`applied.json` वह है जो "इस मशीन ने वास्तव में क्या सहा है" का जवाब देता है — अपग्रेड के बाद कुछ गलत दिखाई देने पर पूछने वाला पहला सवाल। इसे एक बग रिपोर्ट से जोड़ें।

बैकअप जानबूझकर पूरी डायरेक्टरी की कॉपी के बजाय छोटा है: माइग्रेशन डिजाइन के अनुसार अब कुछ भी अपरिवर्तनीय को हटाता नहीं है, इसलिए जो बीमा करने योग्य है वह **एक चरण में दोष** है, और ये कुछ फ़ाइलें हैं जहां ऐसा दोष चोट पहुंचाएगा।

## यदि एक चरण विफल हो जाता है

श्रृंखला वहां रुक जाती है। `VERSION` केवल एक चरण द्वारा स्टैम्प किया जाता है जो पूरा हुआ, इसलिए होम अपने पुराने लेआउट के साथ चिह्नित रहता है और अगली कमांड इसे पुनः प्रयास करती है — एक होम को आंशिक माइग्रेशन की ताकत पर कभी भी वर्तमान में चिह्नित नहीं किया जाता है। चरण को `applied.json` में `"ok": false` के साथ रिकॉर्ड किया जाता है, और बैकअप वह है जहां इसे लिया गया था।

## एक नया होम अस्वीकार किया जाता है, माइग्रेट नहीं किया जाता

यदि `~/.failproofai/` को एक **नए** failproofai द्वारा लिखा गया था जो आप चला रहे हैं, तो कमांड रुक जाती है और आपको इसके बजाय अपग्रेड करने के लिए कहती है। वह डेटा ठीक है और एक नए CLI इसे पढ़ते हैं; इससे "आगे" माइग्रेट करना एक चीज़ नहीं है जो मौजूद है, और इसे रीसेट करना कुछ पुनः प्राप्य को नष्ट करेगा।

```
इस मशीन की failproofai डायरेक्टरी एक नए संस्करण द्वारा लिखी गई थी (लेआउट 4;
यह बिल्ड 3 बोलता है)। माइग्रेट के बजाय अपग्रेड करें:
  npm install -g failproofai@latest
```

डेमन वही नियम लागू करता है: `failproofaid` एक लेआउट के विरुद्ध शुरू होने से इनकार करता है जो यह नहीं बोलता, पाथ को पढ़ने और लिखने के बजाय जो चले गए हैं।
