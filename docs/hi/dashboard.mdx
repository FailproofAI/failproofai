failproofai डैशबोर्ड आपके AI एजेंट सेशन की निगरानी करने और नीतियों को प्रबंधित करने के लिए एक स्थानीय वेब एप्लिकेशन है। देखें कि आपके एजेंट आपकी अनुपस्थिति में क्या कर रहे थे।

---

## डैशबोर्ड शुरू करना

```bash
failproofai
```

`http://localhost:8020` पर खुलता है।

डैशबोर्ड सीधे फाइलसिस्टम से पढ़ता है - आपके Claude Code प्रोजेक्ट फोल्डर और failproofai कॉन्फ़िगरेशन फाइलें। कोई भी डेटा दूरस्थ सेवा में नहीं लिखा जाता है।

---

## पृष्ठ

### प्रोजेक्ट

आपकी मशीन पर मिले सभी Claude Code, OpenAI Codex, GitHub Copilot CLI _(beta)_, Cursor Agent _(beta)_, OpenCode _(beta)_, Pi _(beta)_, और Gemini CLI _(beta)_ प्रोजेक्ट सूचीबद्ध करता है। Claude प्रोजेक्ट `~/.claude/projects/` से खोजे जाते हैं (या `CLAUDE_PROJECTS_PATH` द्वारा सेट किए गए पथ से); Codex प्रोजेक्ट `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` के तहत प्रत्येक ट्रांसक्रिप्ट को स्कैन करके और प्रत्येक सेशन के पहले रिकॉर्ड में दर्ज `cwd` द्वारा समूहीकृत करके खोजे जाते हैं; Copilot CLI प्रोजेक्ट प्रत्येक `~/.copilot/session-state/<sessionId>/workspace.yaml` को स्कैन करके खोजे जाते हैं (`COPILOT_HOME` के माध्यम से कॉन्फ़िगर योग्य) और इसके `cwd` फील्ड द्वारा समूहीकृत; Cursor Agent प्रोजेक्ट `~/.cursor/agent-sessions/<sessionId>/` के तहत प्रति-सेशन मेटाडेटा को स्कैन करके खोजे जाते हैं (`CURSOR_HOME` के माध्यम से कॉन्फ़िगर योग्य, `conversations/` और `sessions/` फॉलबैक के रूप में जांचे जाते हैं) `meta.json` / `session.json` / `workspace.yaml` में `cwd` स्केलर के लिए; OpenCode प्रोजेक्ट `~/.local/share/opencode/opencode.db` पर अपने SQLite DB को `opencode db --format json` के माध्यम से क्वेरी करके खोजे जाते हैं (हम `session` और `project` टेबल पढ़ते हैं और `project_id` द्वारा समूहीकृत करते हैं); Pi प्रोजेक्ट `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` के तहत प्रति-सेशन JSONL ट्रांसक्रिप्ट को स्कैन करके खोजे जाते हैं (`PI_SESSIONS_DIR` के माध्यम से कॉन्फ़िगर योग्य) और प्रत्येक सेशन के पहले रिकॉर्ड से `cwd` प्राप्त करते हैं; Gemini CLI प्रोजेक्ट `~/.gemini/tmp/<basename>/chats/session-<timestamp>-<uuid-prefix>.jsonl` को स्कैन करके खोजे जाते हैं (`GEMINI_SESSIONS_DIR` के माध्यम से कॉन्फ़िगर योग्य) और भाई `.project_root` टेक्स्ट मार्कर से विहित cwd को पुनः प्राप्त करते हैं। एक प्रोजेक्ट जिसे कई CLIs द्वारा उपयोग किया गया है, एक एकल पंक्ति के रूप में प्रस्तुत किया जाता है जिसमें सभी मिलती हुई बैज होती हैं। टेबल के ऊपर **CLI** ड्रॉपडाउन का उपयोग करके एक विशिष्ट एजेंट CLI द्वारा फ़िल्टर करें; URL आपकी पसंद को `?cli=claude|codex|copilot|cursor|opencode|pi|gemini` के रूप में सुरक्षित रखता है।

प्रत्येक प्रोजेक्ट दिखाता है:
- प्रोजेक्ट नाम (फोल्डर पथ से प्राप्त)
- एक CLI बैज — `Claude Code` (नारंगी), `OpenAI Codex` (बैंगनी), `GitHub Copilot` (नीला), `Cursor Agent` (पन्ना), `OpenCode` (एम्बर), `Pi` (गुलाबी), और/या `Gemini CLI` (आसमानी)
- सबसे हालिया सेशन गतिविधि की तारीख

इसके सेशन को देखने के लिए एक प्रोजेक्ट पर क्लिक करें।

### सेशन

एक प्रोजेक्ट के भीतर सभी सेशन सूचीबद्ध करता है। प्रत्येक सेशन दिखाता है:
- सेशन ID
- शुरुआत और समाप्ति टाइमस्टैम्प
- टूल कॉल की संख्या
- हुक गतिविधि गणना (नीतियां जो सक्रिय हुईं)

सूची को संकीर्ण करने के लिए दिनांक श्रेणी फ़िल्टर और सेशन ID खोज का उपयोग करें। सेशन पृष्ठांकित हैं।

सेशन दर्शक को खोलने के लिए एक सेशन पर क्लिक करें।

### सेशन दर्शक

सेशन दर्शक स्वायत्त एजेंट के लिए मुख्य प्रश्न का उत्तर देता है: एजेंट ने क्या किया, और क्या यह ट्रैक पर रहा? हेडर के बगल में एक CLI बैज इंगित करता है कि सेशन Claude Code, OpenAI Codex, GitHub Copilot CLI, Cursor Agent, OpenCode, Pi, या Gemini CLI ट्रांसक्रिप्ट है। यह एक सेशन में हुई सभी चीजों की एक समयरेखा दिखाता है:

- **संदेश** - Claude के टेक्स्ट प्रतिक्रियाएं और उपयोगकर्ता संकेत
- **टूल कॉल** - Claude द्वारा आमंत्रित प्रत्येक टूल, इसके इनपुट और आउटपुट के साथ
- **नीति गतिविधि** - प्रत्येक टूल कॉल के लिए, कौन सी नीतियां सक्रिय हुईं और वे किस निर्णय पर पहुंची

शीर्ष पर सांख्यिकी बार सेशन की अवधि, कुल टूल कॉल, और हुक निर्णयों का सारांश (allow / deny / instruct गणना) दिखाता है।

सेशन को निर्यात करने के लिए **Download Logs** बटन पर क्लिक करें। Claude Code, Codex, Copilot, Cursor, Pi, और Gemini सेशन के लिए आप मूल ऑन-डिस्क JSONL ट्रांसक्रिप्ट बाइट-फॉर-बाइट प्राप्त करते हैं; OpenCode के लिए (जिसके सेशन SQLite में रहते हैं, डिस्क पर नहीं) आप एक JSON दस्तावेज़ प्राप्त करते हैं जो अंतर्निहित `session` / `messages` / `parts` टेबल को प्रतिबिंबित करता है।

### ऑडिट

आपके एजेंट ने पिछले सेशन में वास्तव में कैसे व्यवहार किया है, इसकी एक व्यक्तित्व-संचालित रिपोर्ट। `failproofai audit` CLI के समान स्कैन चलाता है लेकिन इसे एक छह-सेक्शन डैशबोर्ड के रूप में प्रस्तुत करता है:

1. **Identity** — आपके एजेंट को 8 आर्केटाइप में से एक में वर्गीकृत करता है (`the optimist`, `the cowboy`, `the explorer`, `the goldfish`, `the paranoid architect`, `the precision builder`, `the hammer`, `the ghost`) इस आधार पर कि कौन सी डिटेक्टर + नीतियां सक्रिय हुईं और कितनी भारी। एक 8×8 पिक्सेल सिगिल, आर्केटाइप टैगलाइन, "common in" / "primary risk" फ्रेमिंग, और समापन एक-पंक्ति को प्रस्तुत करता है।
2. **Show off your agent** — पहचान कार्ड को X / LinkedIn पर पोस्ट करने के लिए उपयुक्त 1200×630 PNG के रूप में कैप्चर करता है (`make poster` पर क्लिक करें)।
3. **Strengths** — हरी-चेक की गई व्यवहार जो आपका एजेंट पहले से सही तरीके से करता है, लाइव ऑडिट डेटा से प्राप्त (स्वच्छ टूल-कॉल दर, औसत सेशन लंबाई, शून्य क्रेडेंशियल लीक, शून्य रिट्राई तूफान, आदि)।
4. **Score + leaderboard** — 0–100 स्कोर लेटर ग्रेड के साथ (S/A/B/C/D/F), एक वितरण हिस्टोग्राम जो दिखाता है कि आप समूह में कहाँ हैं, गद्य ("a B starts at 71. you're 13 points away."), और एक लीडरबोर्ड टेबल आपकी पंक्ति हाइलाइट के साथ।
5. **Findings** — प्रभाव द्वारा रैंक किए गए प्रति-निष्कर्ष कार्ड। प्रत्येक कार्ड क्या हुआ, इसकी लागत, वास्तविक कैप्चर की गई कमांड के साथ एक साक्ष्य नमूना, और failproofai नीति जो समान पैटर्न को पकड़ेगी (`$ failproofai policy add <slug>`, क्लिक-टू-कॉपी) को उजागर करता है।
6. **Prescribed policies + return loop** — प्रत्येक अक्षम बिल्ट-इन नीति का एक ग्रिड जो एक अंतर को बंद करेगी, एक प्रोजेक्टेड-स्कोर कॉलआउट के साथ, साथ ही "re-audit in 7 days" CTA।

`failproofai audit` रनटाइम द्वारा संचालित — अंतर्निहित स्कैन इंजन, समर्थित फ्लैग, और प्रति-ट्रांसक्रिप्ट कैश अपरिवर्तनीयों के लिए [Audit CLI](/hi/cli/audit) देखें। डैशबोर्ड `~/.failproofai/audit-dashboard.json` पर नवीनतम परिणाम को कैश करता है (मोड `0600`, एकल स्लॉट, नई रन ओवरराइट करती हैं) ताकि दोबारा आना तत्काल हो; **प्रति-ट्रांसक्रिप्ट और संपूर्ण-परिणाम दोनों कैश को एक बार पढ़ने पर अस्वीकृत कर दिया जाता है जब वे 7 दिन से पुराने हों** ताकि डैशबोर्ड कभी भी चुप्पी से एक सप्ताह पुराना परिणाम न परोसे — TTL के पास `/audit` अपनी खाली स्थिति में गिरता है और एक ताज़ा रन को संकेत देता है। रिपोर्ट के नीचे `[ re-audit now ]` पर क्लिक करने से `/api/audit/run` को POST किया जाता है और डैशबोर्ड रन समाप्त होने तक 1Hz पर `/api/audit/status` को पोल करता है; रन के दौरान एक चिपचिपा गुलाबी प्रगति पट्टी दृश्य के शीर्ष पर पिन करती है, एक बीता हुआ टाइमर के साथ, और परिणाम सफलता पर स्थान पर स्वैप किए जाते हैं (पूर्ण पृष्ठ पुनः लोड नहीं)। विफलता पर पट्टी `RerunError.kind` (`timeout` / `network` / `post_failed`) से कीड्स की प्रति के साथ लाल हो जाती है। खाली स्थिति (कोई कैश नहीं या समाप्त) और शून्य-सेशन स्थिति (कैश मौजूद है लेकिन स्कैन ने कोई ट्रांसक्रिप्ट नहीं पाई) अलग से प्रस्तुत की जाती हैं।

## ऑटो-रिफ्रेश

डैशबोर्ड के शीर्ष नेविगेशन में ऑटो-रिफ्रेश टॉगल है। जब सक्षम होता है, तो वर्तमान पृष्ठ नए सेशन और नीति गतिविधि दिखाने के लिए समय-समय पर रिफ्रेश होता है जैसे ही वे दिखाई देते हैं। लंबे समय तक चलने वाले स्वायत्त एजेंट सेशन की निगरानी के लिए आवश्यक।

---

## पृष्ठ अक्षम करना

यदि आपको डैशबोर्ड के कुछ हिस्सों की आवश्यकता है, तो `FAILPROOFAI_DISABLE_PAGES` को पृष्ठ नामों की अल्पविरामांकित सूची में सेट करें:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

वैध मान: `policies`, `projects`, `audit`।

---

## प्रोजेक्ट पथ कॉन्फ़िगर करना

डिफ़ॉल्ट रूप से, डैशबोर्ड मानक Claude Code प्रोजेक्ट निर्देशिका से पढ़ता है। कस्टम सेटअप के लिए इसे ओवरराइड करें:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## एक non-localhost होस्ट से एक्सेस करना

जब **dev मोड** (`npm run dev`) में डैशबोर्ड चलाते हैं और `localhost` के अलावा एक होस्टनाम से इसे एक्सेस करते हैं - उदाहरण के लिए, एक कस्टम डोमेन, एक दूरस्थ IP, या एक टनल किया गया URL — आप एक चेतावनी देख सकते हैं जैसे:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

यह Next.js अपने HMR (हॉट मॉड्यूल रीलोड) वेबसॉकेट के लिए क्रॉस-ऑरिजिन एक्सेस को ब्लॉक कर रहा है, जो एक dev-only फीचर है। अपने होस्ट को अनुमति देने के लिए, `--allowed-origins` फ्लैग का उपयोग करें:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

कई होस्ट या IPs के लिए, अल्पविरामांकित सूची पास करें:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

आप इसके बजाय `FAILPROOFAI_ALLOWED_DEV_ORIGINS` पर्यावरण चर भी सेट कर सकते हैं:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
यह केवल dev मोड पर लागू होता है। जब `failproofai` चलाते हैं (production मोड), कोई HMR वेबसॉकेट और कोई क्रॉस-ऑरिजिन dev संसाधन समस्या नहीं होती है।
</Note>
