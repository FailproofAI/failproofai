failproofai डैशबोर्ड आपके AI एजेंट सेशन की निगरानी और नीतियों का प्रबंधन करने के लिए एक स्थानीय वेब एप्लिकेशन है। देखें कि आपके एजेंट आपकी अनुपस्थिति में क्या कर रहे थे।

---

## डैशबोर्ड शुरू करना

```bash
failproofai
```

`http://localhost:8020` पर खुलता है।

डैशबोर्ड स्थानीय प्रोजेक्ट, सेशन और failproofai कॉन्फ़िगरेशन डेटा को सीधे फाइल सिस्टम से पढ़ता है। ऑडिट रिमाइंडर और आमंत्रण जैसी वैकल्पिक सत्यापित सुविधाएं, इन अनुरोधों के लिए आवश्यक जानकारी (ईमेल पते सहित) को दूरस्थ API को भेजती हैं।

## पृष्ठ

### प्रोजेक्ट

आपकी मशीन पर मिले सभी Claude Code, OpenAI Codex, GitHub Copilot CLI _(beta)_, Cursor Agent _(beta)_, OpenCode _(beta)_, Pi _(beta)_, Hermes, OpenClaw, Factory Droid, Devin, Antigravity और Goose प्रोजेक्ट को सूचीबद्ध करता है। Claude प्रोजेक्ट `~/.claude/projects/` से खोजे जाते हैं (या `CLAUDE_PROJECTS_PATH` द्वारा सेट किए गए पथ से); Codex प्रोजेक्ट `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` के तहत प्रत्येक ट्रांसक्रिप्ट को स्कैन करके और प्रत्येक सेशन के पहले रिकॉर्ड में दर्ज `cwd` द्वारा समूहीकृत करके खोजे जाते हैं; Copilot CLI प्रोजेक्ट प्रत्येक `~/.copilot/session-state/<sessionId>/workspace.yaml` को स्कैन करके (`COPILOT_HOME` के माध्यम से कॉन्फ़िगरेबल) और इसके `cwd` फील्ड द्वारा समूहीकृत करके खोजे जाते हैं; Cursor Agent प्रोजेक्ट `~/.cursor/agent-sessions/<sessionId>/` (`CURSOR_HOME` के माध्यम से कॉन्फ़िगरेबल, `conversations/` और `sessions/` को फॉलबैक के रूप में जांचा जाता है) के तहत प्रति-सेशन मेटाडेटा को स्कैन करके `meta.json` / `session.json` / `workspace.yaml` में `cwd` स्केलर के लिए खोजे जाते हैं; OpenCode प्रोजेक्ट `~/.local/share/opencode/opencode.db` पर इसके SQLite DB को `opencode db --format json` के माध्यम से क्वेरी करके खोजे जाते हैं (हम `session` और `project` टेबल पढ़ते हैं और `project_id` द्वारा समूहीकृत करते हैं); Pi प्रोजेक्ट `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` (`PI_SESSIONS_DIR` के माध्यम से कॉन्फ़िगरेबल) के तहत प्रति-सेशन JSONL ट्रांसक्रिप्ट को स्कैन करके और प्रत्येक सेशन के पहले रिकॉर्ड से `cwd` को निकालकर खोजे जाते हैं; Hermes गेटवे सेशन प्रत्येक प्रोफाइल के SQLite स्टोर से सीधे पढ़े जाते हैं — `~/.hermes/state.db` साथ ही `~/.hermes/profiles/<name>/state.db` (`HERMES_HOME` के माध्यम से ओवरराइड करने योग्य, या एक एकल डेटाबेस के लिए `HERMES_DB_PATH`) — और प्रोफाइल और `source` (Slack/Telegram/cli/cron — गेटवे सेशन के कोई cwd नहीं) द्वारा `hermes-<profile>-<source>` प्रोजेक्ट में समूहीकृत; OpenClaw गेटवे सेशन `~/.openclaw/agents/<agentId>/sessions/*.jsonl` से पढ़े जाते हैं और एजेंट और चैनल द्वारा `openclaw-<agentId>-<channel>` प्रोजेक्ट में समूहीकृत (cwd रहित भी); Factory Droid प्रोजेक्ट `~/.factory/sessions/<encoded-cwd>/*.jsonl` पर JSONL ट्रांसक्रिप्ट से खोजे जाते हैं और cwd द्वारा समूहीकृत; Devin प्रोजेक्ट `~/.local/share/devin/cli/sessions.db` पर इसके SQLite DB से (प्रत्येक सेशन के `working_directory` द्वारा समूहीकृत); Antigravity प्रोजेक्ट `~/.gemini/antigravity-cli/brain/<conversationId>/…/transcript_full.jsonl` पर JSONL ट्रांसक्रिप्ट से और cwd द्वारा समूहीकृत; और Goose प्रोजेक्ट `~/.local/share/goose/sessions/sessions.db` पर इसके SQLite DB से (प्रत्येक सेशन के `working_dir` द्वारा समूहीकृत)। एक प्रोजेक्ट जो कई CLIs द्वारा उपयोग किया गया है, सभी मेल खाने वाले बैज के साथ एक एकल पंक्ति के रूप में प्रदर्शित होता है। तालिका के ऊपर **CLI** ड्रॉपडाउन का उपयोग करके एक विशिष्ट एजेंट CLI द्वारा फ़िल्टर करें; URL आपकी चयन को `?cli=claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose` के रूप में संरक्षित करता है।

Hermes और OpenClaw उपयोगकर्ता-स्कोप्ड हैं और समूहीकृत करने के लिए कोई कार्य निर्देशिका नहीं है, इसलिए वे **संपूर्ण फ़ोल्डर ट्री** के रूप में प्रदर्शित होते हैं — शीर्ष स्तर पर प्रोफाइल (या एजेंट), उसके नीचे इसके चैनल — जबकि हर cwd-आधारित CLI एक फ्लैट पंक्ति रहता है। फ़ोल्डर पंक्तियां उनके अंतर्गत सभी चीजों के सेशन काउंट और सबसे हाल की गतिविधि को रोल अप करती हैं, संपूर्ण फ़ोल्डर visits के बीच याद किए जाते हैं, और एक कीवर्ड खोज जो कुछ भी मेल खाता है उसे विस्तारित करती है।

प्रत्येक प्रोजेक्ट दिखाता है:
- प्रोजेक्ट नाम (फ़ोल्डर पथ से व्युत्पन्न)
- एक CLI बैज — `Claude Code` (नारंगी), `OpenAI Codex` (बैंगनी), `GitHub Copilot` (नीला), `Cursor Agent` (पन्ना), `OpenCode` (एम्बर), `Pi` (गुलाबी), और/या `Hermes` (नीला-बैंगनी)
- सबसे हाल की सेशन गतिविधि की तारीख

एक प्रोजेक्ट पर क्लिक करके इसके सेशन देखें।

### सेशन

एक प्रोजेक्ट के भीतर सभी सेशन को सूचीबद्ध करता है। प्रत्येक सेशन दिखाता है:
- सेशन ID
- शुरुआत और समाप्ति टाइमस्टैम्प
- टूल कॉल्स की संख्या
- हुक गतिविधि काउंट (नीतियां जो सक्रिय हुईं)

सूची को कम करने के लिए तारीख रेंज फ़िल्टर और सेशन ID खोज का उपयोग करें। सेशन को पृष्ठांकित किया जाता है।

सेशन व्यूअर खोलने के लिए एक सेशन पर क्लिक करें।

### सेशन व्यूअर

सेशन व्यूअर स्वायत्त एजेंट के लिए मुख्य प्रश्न का उत्तर देता है: एजेंट ने क्या किया, और क्या यह ट्रैक पर रहा? हेडर के बगल में एक CLI बैज इंगित करता है कि सेशन Claude Code, OpenAI Codex, GitHub Copilot CLI, Cursor Agent, OpenCode, Pi, Hermes, OpenClaw, Factory Droid, Devin, Antigravity या Goose ट्रांसक्रिप्ट है। यह एक सेशन में हुई सभी चीजों की एक समयरेखा दिखाता है:

- **संदेश** - Claude के टेक्स्ट प्रतिक्रियाएं और उपयोगकर्ता प्रॉम्प्ट
- **टूल कॉल्स** - हर टूल जो Claude ने आह्वान किया, इसके इनपुट और आउटपुट के साथ
- **नीति गतिविधि** - प्रत्येक टूल कॉल के लिए, कौन सी नीतियां सक्रिय हुईं और उन्होंने क्या निर्णय दिया

शीर्ष पर स्टेट्स बार सेशन अवधि, कुल टूल कॉल्स, और हुक निर्णयों का सारांश (allow / deny / instruct काउंट) दिखाता है।

सेशन को निर्यात करने के लिए **Download Logs** बटन पर क्लिक करें। Claude Code, Codex, Copilot, Cursor और Pi सेशन के लिए आप मूल डिस्क पर JSONL ट्रांसक्रिप्ट बाइट-फॉर-बाइट प्राप्त करते हैं; OpenCode के लिए (जिसके सेशन SQLite में रहते हैं, डिस्क पर नहीं) आप एक JSON दस्तावेज़ प्राप्त करते हैं जो अंतर्निहित `session` / `messages` / `parts` टेबल को दर्पणित करता है।

### ऑडिट

आपके एजेंट की वास्तविक व्यवहार पद्धति के बारे में गत सेशन में एक व्यक्तित्व-संचालित रिपोर्ट। `failproofai audit` CLI के समान स्कैन चलाता है लेकिन इसे एक एकल-स्क्रीन साझा करने योग्य पोस्टर + चार नीचे-फोल्ड सेक्शन के रूप में प्रस्तुत करता है:

1. **पोस्टर** — पहले व्यूपोर्ट को भरता है। failproof_ai वर्डमार्क + ऑडिट लेबल के साथ आत्मनिर्भर PNG-कैप्चर क्षेत्र · आर्कटाइप इंडेक्स (`№ NN of 08`) + ऑडिट तारीख · संख्यात्मक स्कोर (0–100) + पर्सेंटाइल रैंक पिल (`top 15%`) · आर्कटाइप नाम (एक `the optimist`, `the cowboy`, `the explorer`, `the goldfish`, `the paranoid architect`, `the precision builder`, `the hammer`, `the ghost` में से) + 3-कीवर्ड पट्टी · `// only N% of agents are this archetype` दुर्लभता लाइन · 8×8 पिक्सल सिजिल टाइल · `audit yours → failproof.ai` फुटर। तीन शेयर बटन कैप्चर बॉक्स के बाहर बैठते हैं: `post your archetype` (X intent), `share on linkedin`, `download poster`। कैप्चर `html-to-image` के माध्यम से चलता है इसलिए PNG ऑन-स्क्रीन रेंडर पिक्सल-फॉर-पिक्सल मेल खाता है (डैश्ड बॉर्डर, SVG लोगो मास्क, ग्रेडिएंट, फ़ॉन्ट मेट्रिक्स — सभी संरक्षित)।
2. **शक्तियां** — शांत ✓ पंक्ति सूची आपके एजेंट द्वारा पहले से ही सही तरीके से किए जाने वाले व्यवहार, लाइव ऑडिट डेटा से व्युत्पन्न (स्वच्छ टूल-कॉल दर, मुख्य में कोई सीधे पुश नहीं, शून्य क्रेडेंशियल रिसाव, शून्य रिट्राई तूफान) — प्रत्येक केवल तभी सामने आया जब संबंधित नीति के पास ऑडिट विंडो में एक स्वच्छ रिकॉर्ड हो।
3. **विशेषताएं** — गंभीरता द्वारा रैंक की गई तालिका क्या स्लिप हुआ: `when · what slipped + the policy that would've caught it · severity pill · seen`, जहां पुनरावृत्ति `new` (एक बार), `N× seen` (2–9 बार), या `recurring` (10+) पढ़ता है।
4. **सुधार कैसे करें** — शांत पंक्ति सूची, प्रत्येक निर्धारित नीति के लिए एक: सफेद में नीति नाम, एक-लाइन विवरण, दाईं ओर स्थापन कमांड + कॉपी बटन। सेक्शन हेडर `enable all N → projected <score> · <tier>` पढ़ता है (वह स्कोर जिस तक आप हर फिक्स लागू होने से पहुंचेंगे), और इसका `[install all]` बटन हर निर्धारित नीति के लिए संयुक्त `failproofai policy add a b c …` कमांड को कॉपी करता है।
5. **बेहतर वापसी करें** — दो साथ-साथ कार्ड। बाएं: एक रिमाइंडर सेट करें (`3d` / `7d` / `14d` / `30d` कैडेंस पिकर; सत्यापित होने के बाद `/api/auth/reminder` के माध्यम से स्थिर रहता है)। दाएं: failproof सुविधाओं को अनलॉक करें — `invite a friend` एक मोडल खोलता है जो कॉमा/स्पेस/न्यूलाइन-अलग की गई दोस्त ईमेल की सूची (प्रति भेजने के लिए अधिकतम 10) लेता है, उन्हें `/api/audit/invite` को POSTs, जो api-server के `POST /v0/invite` को अग्रेषित करता है। api-server `invite@failproof.ai` से एक ईमेल प्रति प्राप्तकर्ता भेजता है प्रेषक Cc'd और `Reply-To` सेट करके, इसलिए प्राप्तकर्ता देखता है कि किसने उन्हें आमंत्रित किया और प्रेषक को उनके इनबॉक्स में एक कॉपी मिलता है। अनाम उपयोगकर्ता `AuthDialog` के माध्यम से रूट किए जाते हैं पहले ताकि प्रेषक का ईमेल आमंत्रण भेजने से पहले ज्ञात हो। Entitlement / perks पूर्ति एक फॉलो-अप है।

`failproofai audit` रनटाइम द्वारा संचालित — अंतर्निहित स्कैन इंजन, समर्थित फ्लैग, और प्रति-ट्रांसक्रिप्ट कैश अपरिवर्तनीय के लिए [Audit CLI](/hi/cli/audit) देखें। डैशबोर्ड सबसे हाल का परिणाम `~/.failproofai/audit-dashboard.json` (मोड `0600`, एकल स्लॉट, नया चलाता है ओवरराइट करता है) में कैश करता है इसलिए पुनः विजिट तत्काल होते हैं; **प्रति-ट्रांसक्रिप्ट और पूरे-परिणाम दोनों कैश को पढ़ने पर अस्वीकार किया जाता है एक बार वे 7 दिन से पुराने हो जाते हैं** इसलिए डैशबोर्ड कभी भी चुप्पी से एक सप्ताह पुराना परिणाम नहीं देता है — TTL `/audit` के पिछले अपने खाली स्थिति में गिरता है और एक ताजा चलाव का संकेत देता है। रिपोर्ट के नीचे के पास `[ re-audit now ]` क्लिक करना `noCache: true` के साथ `/api/audit/run` को POSTs — re-audit प्रति-ट्रांसक्रिप्ट कैश को बायपास करता है और चुप्पी से कैश की गई परिणाम देने के बजाय शुरुआत से प्रत्येक ट्रांसक्रिप्ट को फिर से स्कैन करता है — और डैशबोर्ड 1Hz पर `/api/audit/status` को पोल करता है जब तक चलाव समाप्त न हो जाए; व्यूपोर्ट के शीर्ष पर एक चिपचिपी गुलाबी प्रगति पट्टी चलाव के दौरान एक बीता हुआ टाइमर के साथ पिन करती है, और ताज़ा परिणाम सफलता पर जगह में स्वैप करता है (कोई पूर्ण-पृष्ठ पुनः लोड नहीं; एक विफल re-audit पूर्व रिपोर्ट को बरकरार छोड़ता है)। विफलता पर पट्टी `RerunError.kind` (`timeout` / `network` / `post_failed`) से कॉपी किए गए लाल हो जाता है। खाली स्थिति (कोई कैश या समाप्त) और शून्य-सेशन स्थिति (कैश मौजूद है लेकिन स्कैन को कोई ट्रांसक्रिप्ट नहीं मिला) अलग से सामने आती है।

## पृष्ठों को अक्षम करना

यदि आपको डैशबोर्ड के केवल कुछ भाग की आवश्यकता है, तो `FAILPROOFAI_DISABLE_PAGES` को पृष्ठ नामों की कॉमा-अलग सूची में सेट करें:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

मान्य मान: `policies`, `projects`, `audit`।

---

## प्रोजेक्ट पथ को कॉन्फ़िगर करना

डिफ़ॉल्ट रूप से, डैशबोर्ड मानक Claude Code प्रोजेक्ट निर्देशिका से पढ़ता है। कस्टम सेटअप के लिए इसे ओवरराइड करें:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## localhost के अलावा किसी अन्य होस्ट से एक्सेस करना

जब डैशबोर्ड को **डेव मोड** में चलाया जाता है (`npm run dev`) और इसे `localhost` के अलावा किसी hostname से एक्सेस किया जाता है - उदाहरण के लिए, एक कस्टम डोमेन, एक रिमोट IP, या एक टनल्ड URL — आप इस तरह एक चेतावनी देख सकते हैं:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

यह Next.js अपने HMR (हॉट मॉड्यूल रीलोड) वेबसॉकेट के लिए क्रॉस-ऑरिजिन एक्सेस को ब्लॉक कर रहा है, जो एक डेव-ओनली फीचर है। अपने होस्ट की अनुमति देने के लिए, `--allowed-origins` फ्लैग का उपयोग करें:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

कई होस्ट या IP के लिए, कॉमा-अलग सूची पास करें:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

आप बजाय `FAILPROOFAI_ALLOWED_DEV_ORIGINS` पर्यावरण चर को भी सेट कर सकते हैं:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
यह केवल डेव मोड पर लागू होता है। जब `failproofai` (उत्पादन मोड) चलाया जाता है, तो कोई HMR वेबसॉकेट और कोई क्रॉस-ऑरिजिन डेव संसाधन मुद्दा नहीं होता है।
</Note>
