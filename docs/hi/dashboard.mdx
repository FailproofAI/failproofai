failproofai डैशबोर्ड एक स्थानीय वेब एप्लिकेशन है जो आपके AI एजेंट सेशन को मॉनिटर करने और नीतियों को प्रबंधित करने के लिए है। देखें कि आपके एजेंट आपके दूर रहते हुए क्या करते थे।

---

## डैशबोर्ड शुरू करना

```bash
failproofai
```

`http://localhost:8020` पर खुलता है।

डैशबोर्ड स्थानीय प्रोजेक्ट, सेशन, और failproofai कॉन्फ़िगरेशन डेटा को सीधे फ़ाइलसिस्टम से पढ़ता है। वैकल्पिक प्रमाणित सुविधाएं, जैसे ऑडिट रिमाइंडर और निमंत्रण, इन अनुरोधों के लिए आवश्यक जानकारी (ईमेल पते सहित) को दूरस्थ API को भेजते हैं।

## पृष्ठ

### प्रोजेक्ट

आपकी मशीन पर पाए गए सभी Claude Code, OpenAI Codex, GitHub Copilot CLI _(beta)_, Cursor Agent _(beta)_, OpenCode _(beta)_, Pi _(beta)_, Hermes, OpenClaw, Factory Droid, Devin, Antigravity, और Goose प्रोजेक्ट सूचीबद्ध करता है। Claude प्रोजेक्ट `~/.claude/projects/` से खोजे जाते हैं (या `CLAUDE_PROJECTS_PATH` द्वारा सेट पाथ); Codex प्रोजेक्ट `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` के तहत प्रत्येक ट्रांसक्रिप्ट को स्कैन करके और प्रत्येक सेशन के पहले रिकॉर्ड में दर्ज `cwd` द्वारा समूहीकृत करके खोजे जाते हैं; Copilot CLI प्रोजेक्ट प्रत्येक `~/.copilot/session-state/<sessionId>/workspace.yaml` को स्कैन करके (`COPILOT_HOME` के माध्यम से कॉन्फ़िगरेबल) और इसके `cwd` फ़ील्ड द्वारा समूहीकृत करके खोजे जाते हैं; Cursor Agent प्रोजेक्ट `~/.cursor/agent-sessions/<sessionId>/` के तहत प्रति-सेशन मेटाडेटा को स्कैन करके (`CURSOR_HOME` के माध्यम से कॉन्फ़िगरेबल, फॉलबैक के रूप में `conversations/` और `sessions/` की जांच की जाती है) `meta.json` / `session.json` / `workspace.yaml` में `cwd` स्केलर के लिए खोजे जाते हैं; OpenCode प्रोजेक्ट `~/.local/share/opencode/opencode.db` पर इसके SQLite DB को `opencode db --format json` के माध्यम से क्वेरी करके खोजे जाते हैं (हम `session` और `project` टेबल पढ़ते हैं और `project_id` द्वारा समूहीकृत करते हैं); Pi प्रोजेक्ट `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` के तहत प्रति-सेशन JSONL ट्रांसक्रिप्ट को स्कैन करके (`PI_SESSIONS_DIR` के माध्यम से कॉन्फ़िगरेबल) और प्रत्येक सेशन के पहले रिकॉर्ड से `cwd` निकालकर खोजे जाते हैं; Hermes गेटवे सेशन प्रत्येक प्रोफ़ाइल के SQLite स्टोर से सीधे पढ़े जाते हैं — `~/.hermes/state.db` और `~/.hermes/profiles/<name>/state.db` (`HERMES_HOME` के माध्यम से ओवरराइडेबल, या एकल डेटाबेस के लिए `HERMES_DB_PATH`) — और प्रोफ़ाइल और `source` (Slack/Telegram/cli/cron — गेटवे सेशन के पास कोई cwd नहीं) द्वारा `hermes-<profile>-<source>` प्रोजेक्ट में समूहीकृत किए जाते हैं; OpenClaw गेटवे सेशन `~/.openclaw/agents/<agentId>/sessions/*.jsonl` से पढ़े जाते हैं और एजेंट और चैनल द्वारा `openclaw-<agentId>-<channel>` प्रोजेक्ट में समूहीकृत किए जाते हैं (cwd के बिना भी); Factory Droid प्रोजेक्ट `~/.factory/sessions/<encoded-cwd>/*.jsonl` पर JSONL ट्रांसक्रिप्ट से खोजे जाते हैं और cwd द्वारा समूहीकृत किए जाते हैं; Devin प्रोजेक्ट इसके `~/.local/share/devin/cli/sessions.db` पर SQLite DB से (प्रत्येक सेशन के `working_directory` द्वारा समूहीकृत); Antigravity प्रोजेक्ट `~/.gemini/antigravity-cli/brain/<conversationId>/…/transcript_full.jsonl` पर JSONL ट्रांसक्रिप्ट से और cwd द्वारा समूहीकृत; और Goose प्रोजेक्ट इसके `~/.local/share/goose/sessions/sessions.db` पर SQLite DB से (प्रत्येक सेशन के `working_dir` द्वारा समूहीकृत)। एक प्रोजेक्ट जो कई CLI द्वारा उपयोग किया गया है, सभी मिलान बैज के साथ एक एकल पंक्ति के रूप में प्रदर्शित होता है। तालिका के ऊपर **CLI** ड्रॉपडाउन का उपयोग करके एक विशिष्ट एजेंट CLI द्वारा फ़िल्टर करें; URL आपकी चयन को `?cli=claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose` के रूप में संरक्षित करता है।

Hermes और OpenClaw उपयोगकर्ता-स्कोप हैं और समूहीकरण के लिए कोई कार्य निर्देशिका नहीं है, इसलिए वे एक **संक्षिप्त फ़ोल्डर ट्री** के रूप में प्रदर्शित होते हैं — शीर्ष स्तर पर प्रोफ़ाइल (या एजेंट), इसके नीचे चैनल — जबकि प्रत्येक cwd-आधारित CLI एक सपाट पंक्ति बनी रहती है। फ़ोल्डर पंक्तियां उनके अंतर्गत सेशन गणना और सबसे हाल की गतिविधि को रोल करती हैं, संक्षिप्त फ़ोल्डर दौरों के बीच याद किए जाते हैं, और एक कीवर्ड खोज जो भी मेल खाती है उसे विस्तृत करती है।

प्रत्येक प्रोजेक्ट दिखाता है:
- प्रोजेक्ट का नाम (फ़ोल्डर पाथ से व्युत्पन्न)
- एक CLI बैज — `Claude Code` (नारंगी), `OpenAI Codex` (बैंगनी), `GitHub Copilot` (नीला), `Cursor Agent` (पन्ना), `OpenCode` (एम्बर), `Pi` (गुलाबी), और/या `Hermes` (इंडिगो)
- सबसे हाल की सेशन गतिविधि की तारीख

एक प्रोजेक्ट पर क्लिक करके इसके सेशन देखें।

### सेशन

एक प्रोजेक्ट के भीतर सभी सेशन सूचीबद्ध करता है। प्रत्येक सेशन दिखाता है:
- सेशन ID
- शुरुआत और समाप्त समय मुहूर्त
- टूल कॉल की संख्या
- हुक गतिविधि गणना (नीतियां जो सक्रिय हुईं)

सूची को संकीर्ण करने के लिए तारीख श्रेणी फ़िल्टर और सेशन ID खोज का उपयोग करें। सेशन पृष्ठांकित हैं।

एक सेशन पर क्लिक करके सेशन व्यूअर खोलें।

### सेशन व्यूअर

सेशन व्यूअर स्वायत्त एजेंट के लिए मुख्य प्रश्न का उत्तर देता है: एजेंट ने क्या किया, और क्या यह ट्रैक पर रहा? हेडर के बगल में एक CLI बैज यह दर्शाता है कि सेशन Claude Code, OpenAI Codex, GitHub Copilot CLI, Cursor Agent, OpenCode, Pi, Hermes, OpenClaw, Factory Droid, Devin, Antigravity, या Goose ट्रांसक्रिप्ट है। यह एक सेशन में हुई सभी चीजों का एक समयरेखा दिखाता है:

- **संदेश** - Claude के पाठ प्रतिक्रिया और उपयोगकर्ता प्रॉम्प्ट
- **टूल कॉल** - Claude द्वारा आह्वान किए गए प्रत्येक टूल, इसके इनपुट और आउटपुट के साथ
- **नीति गतिविधि** - प्रत्येक टूल कॉल के लिए, कौन सी नीतियां सक्रिय हुईं और उन्होंने कौन सा निर्णय दिया

शीर्ष पर स्टेट्स बार सेशन अवधि, कुल टूल कॉल, और हुक निर्णयों का एक सारांश दिखाता है (allow / deny / instruct गणना)।

सेशन निर्यात करने के लिए **Download Logs** बटन पर क्लिक करें। Claude Code, Codex, Copilot, Cursor, और Pi सेशन के लिए आप मूल डिस्क पर JSONL ट्रांसक्रिप्ट बाइट-दर-बाइट प्राप्त करते हैं; OpenCode (जिसके सेशन SQLite में हैं, डिस्क पर नहीं) के लिए आप एक JSON दस्तावेज़ प्राप्त करते हैं जो अंतर्निहित `session` / `messages` / `parts` टेबल को प्रतिबिंबित करता है।

### ऑडिट

आपके एजेंट के पिछले सेशन में वास्तव में कैसे व्यवहार किया गया है, इसकी एक व्यक्तित्व-चालित रिपोर्ट। `failproofai audit` CLI के समान स्कैन चलाता है लेकिन इसे एक एकल-स्क्रीन साझा करने योग्य पोस्टर + चार नीचे-गुना अनुभागों के रूप में प्रदान करता है:

1. **पोस्टर** — पहले व्यूपोर्ट को भरता है। failproof_ai वर्डमार्क + ऑडिट लेबल के साथ स्व-निहित PNG-कैप्चर क्षेत्र · आर्कटाइप इंडेक्स (`№ NN of 08`) + ऑडिट तारीख · संख्यात्मक स्कोर (0–100) + प्रतिशत पद गोली (`top 15%`) · आर्कटाइप नाम (एक से अधिक `the optimist`, `the cowboy`, `the explorer`, `the goldfish`, `the paranoid architect`, `the precision builder`, `the hammer`, `the ghost`) + 3-कीवर्ड पट्टी · `// only N% of agents are this archetype` दुर्लभता पंक्ति · 8×8 पिक्सेल सिगिल टाइल · `audit yours → failproof.ai` फुटर। तीन शेयर बटन कैप्चर बॉक्स के ठीक बाहर बैठते हैं: `post your archetype` (X intent), `share on linkedin`, `download poster`। कैप्चर `html-to-image` के माध्यम से चलता है इसलिए PNG स्क्रीन पर दिखाई देने वाले पिक्सल-दर-पिक्सल से मेल खाता है (dashed सीमाएं, SVG लोगो मास्क, ग्रेडिएंट, फ़ॉन्ट मेट्रिक्स — सभी संरक्षित)।
2. **शक्तियां** — शांत ✓ पंक्ति सूची आपके एजेंट की पहले से सही करी जाने वाली व्यवहार, लाइव ऑडिट डेटा से व्युत्पन्न (स्वच्छ टूल-कॉल दर, main में कोई सीधे पुश नहीं, शून्य क्रेडेंशियल लीक, शून्य पुनः प्रयास तूफान) — प्रत्येक केवल तब सामने आता है जब संबंधित नीति के पास ऑडिट विंडो में एक स्वच्छ रिकॉर्ड हो।
3. **विलक्षणताएं** — गंभीरता द्वारा रैंक की गई सारणी जो फिसल गई: `when · what slipped + the policy that would've caught it · severity pill · seen`, जहां पुनरावृत्ति `new` (एक बार), `N× seen` (2–9 बार), या `recurring` (10+) को पढ़ता है।
4. **सुधार कैसे करें** — शांत पंक्ति सूची, प्रत्येक निर्धारित नीति के लिए एक: सफेद में नीति का नाम, एक-पंक्ति विवरण, स्थापित कमांड + दाईं ओर कॉपी बटन। अनुभाग शीर्षक `enable all N → projected <score> · <tier>` पढ़ता है (आप हर सुधार लागू करके पहुंचने वाला स्कोर), और इसका `[install all]` बटन प्रत्येक निर्धारित नीति के लिए संयुक्त `failproofai policy add a b c …` कमांड की प्रतिलिपि बनाता है।
5. **बेहतर वापसी आओ** — दो साइड-दर-साइड कार्ड। बाईं ओर: एक रिमाइंडर सेट करें (`3d` / `7d` / `14d` / `30d` कैडेंस पिकर; authed होने के बाद `/api/auth/reminder` के माध्यम से दृढ़)। दाईं ओर: failproof perks को अनलॉक करें — `invite a friend` एक modal खोलता है जो अल्पविराम/स्पेस/न्यूलाइन-अलग दोस्त ईमेल की सूची लेता है (प्रति भेजने के लिए अधिकतम 10), उन्हें `/api/audit/invite` को POST करता है, जो api-server के `POST /v0/invite` को अग्रेषित करता है। api-server `invite@failproof.ai` से प्रत्येक प्राप्तकर्ता को एक ईमेल भेजता है, प्रेषक Cc'd के साथ और `Reply-To` सेट के साथ, इसलिए प्राप्तकर्ता देखता है कि किसने उन्हें आमंत्रित किया और प्रेषक को उनके इनबॉक्स में एक प्रति मिलता है। अनाम उपयोगकर्ताओं को पहले `AuthDialog` के माध्यम से रूट किया जाता है इसलिए निमंत्रण भेजने से पहले प्रेषक का ईमेल ज्ञात हो। Entitlement / perks पूर्तिक्रम एक अनुवर्ती है।

`failproofai audit` रनटाइम द्वारा संचालित — अंतर्निहित स्कैन इंजन, समर्थित फ़्लैग, और प्रति-ट्रांसक्रिप्ट कैश अपरिवर्तनीय के लिए [Audit CLI](/hi/cli/audit) देखें। डैशबोर्ड `~/.failproofai/audit-dashboard.json` पर नवीनतम परिणाम को कैश करता है (mode `0600`, एकल स्लॉट, नई रन अधिलेखन) इसलिए पुनः दौरे तत्काल हैं; **प्रति-ट्रांसक्रिप्ट और संपूर्ण-परिणाम कैश दोनों को पढ़ने पर अस्वीकार कर दिया जाता है एक बार वे 7 दिन से अधिक पुराने हो जाते हैं** इसलिए डैशबोर्ड कभी भी चुपचाप एक सप्ताह पुराना परिणाम नहीं देता है — TTL के अतीत `/audit` अपनी खाली स्थिति में गिरता है और एक ताजा रन के लिए संकेत देता है। रिपोर्ट के नीचे के निकट `[ re-audit now ]` पर क्लिक करने से `/api/audit/run` को `noCache: true` के साथ POST करता है — re-audit प्रति-ट्रांसक्रिप्ट कैश को बायपास करता है और कैश किए गए परिणाम को चुपचाप लौटाने के बजाय प्रत्येक ट्रांसक्रिप्ट को स्क्रैच से फिर से स्कैन करता है — और डैशबोर्ड रन समाप्त होने तक 1Hz पर `/api/audit/status` को पोल करता है; एक sticky pink progress strip रन के दौरान एक elapsed timer के साथ viewport के शीर्ष पर पिन करता है, और ताजा परिणाम सफलता पर स्थान पर स्वैप करता है (कोई पूर्ण-पृष्ठ पुनः लोड नहीं; एक विफल re-audit पूर्व रिपोर्ट को बरकरार रखता है)। विफलता पर पट्टी लाल में बदल जाती है और `RerunError.kind` (`timeout` / `network` / `post_failed`) के साथ कॉपी कुंजीबद्ध। खाली स्थिति (कोई कैश नहीं या समाप्त) और शून्य-सेशन स्थिति (कैश मौजूद है लेकिन स्कैन को कोई ट्रांसक्रिप्ट नहीं मिले) अलग से सामने आते हैं।

### नीतियां

## स्वत: ताज़ा करना

डैशबोर्ड में शीर्ष नेविगेशन में एक स्वत: ताज़ा करना टॉगल है। जब सक्षम होता है, तो वर्तमान पृष्ठ नए सेशन और नीति गतिविधि को दिखाने के लिए आवधिक रूप से ताज़ा होता है। लंबे समय तक चलने वाले स्वायत्त एजेंट सेशन को मॉनिटर करने के लिए आवश्यक।

---

## पृष्ठों को अक्षम करना

यदि आपको डैशबोर्ड के केवल कुछ हिस्सों की आवश्यकता है, तो `FAILPROOFAI_DISABLE_PAGES` को पृष्ठ नामों की अल्पविराम-अलग सूची में सेट करें:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

मान्य मान: `policies`, `projects`, `audit`।

---

## प्रोजेक्ट पाथ कॉन्फ़िगर करना

डिफ़ॉल्ट रूप से, डैशबोर्ड मानक Claude Code प्रोजेक्ट निर्देशिका से पढ़ता है। कस्टम सेटअप के लिए इसे ओवरराइड करें:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## एक non-localhost होस्ट से एक्सेस करना

जब **dev mode** में डैशबोर्ड चल रहा हो (`npm run dev`) और इसे `localhost` के अलावा किसी होस्टनाम से एक्सेस किया जा रहा हो - उदाहरण के लिए, एक कस्टम डोमेन, एक रिमोट IP, या एक tunneled URL - आप एक चेतावनी देख सकते हैं जैसे:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

यह Next.js अपने HMR (hot module reload) websocket के लिए cross-origin पहुंच को ब्लॉक कर रहा है, जो एक dev-only फीचर है। अपने होस्ट को अनुमति देने के लिए, `--allowed-origins` फ़्लैग का उपयोग करें:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

कई होस्ट या IP के लिए, एक अल्पविराम-अलग सूची पास करें:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

आप `FAILPROOFAI_ALLOWED_DEV_ORIGINS` environment variable को इसके बजाय सेट कर सकते हैं:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
यह केवल dev mode पर लागू होता है। जब `failproofai` चल रहा हो (production mode), कोई HMR websocket नहीं है और कोई cross-origin dev resource समस्या नहीं है।
</Note>
