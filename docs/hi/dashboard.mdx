failproofai डैशबोर्ड आपके AI एजेंट सेशन की निगरानी करने और नीतियों का प्रबंधन करने के लिए एक स्थानीय वेब एप्लिकेशन है। देखें कि आपके एजेंट ने आपकी अनुपस्थिति में क्या किया।

---

## डैशबोर्ड शुरू करना

```bash
failproofai
```

`http://localhost:8020` पर खुलता है।

डैशबोर्ड स्थानीय प्रोजेक्ट, सेशन और failproofai कॉन्फ़िगरेशन डेटा को फाइलसिस्टम से सीधे पढ़ता है। ऑडिट रिमाइंडर और निमंत्रण जैसी वैकल्पिक प्रमाणीकृत सुविधाएं, उन अनुरोधों के लिए आवश्यक जानकारी (ईमेल पते सहित) को दूरस्थ API को भेजती हैं।

## पृष्ठ

### प्रोजेक्ट

आपकी मशीन पर मिले सभी Claude Code, OpenAI Codex, GitHub Copilot CLI _(बीटा)_, Cursor Agent _(बीटा)_, OpenCode _(बीटा)_, Pi _(बीटा)_, Hermes, OpenClaw, Factory Droid, Devin, Antigravity और Goose प्रोजेक्ट को सूचीबद्ध करता है। Claude प्रोजेक्ट `~/.claude/projects/` से खोजे जाते हैं (या `CLAUDE_PROJECTS_PATH` द्वारा सेट किए गए पथ से); Codex प्रोजेक्ट `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` के तहत प्रत्येक ट्रांसक्रिप्ट को स्कैन करके और प्रत्येक सेशन के पहले रिकॉर्ड में दर्ज `cwd` द्वारा समूहीकृत करके खोजे जाते हैं; Copilot CLI प्रोजेक्ट प्रत्येक `~/.copilot/session-state/<sessionId>/workspace.yaml` को स्कैन करके (`COPILOT_HOME` के माध्यम से कॉन्फ़िगरेबल) और इसके `cwd` फील्ड द्वारा समूहीकृत करके खोजे जाते हैं; Cursor Agent प्रोजेक्ट `~/.cursor/agent-sessions/<sessionId>/` के तहत प्रति-सेशन मेटाडेटा को स्कैन करके (`CURSOR_HOME` के माध्यम से कॉन्फ़िगरेबल, `conversations/` और `sessions/` फॉलबैक के रूप में जांचे जाते हैं) `meta.json` / `session.json` / `workspace.yaml` में `cwd` स्केलर के लिए खोजे जाते हैं; OpenCode प्रोजेक्ट `~/.local/share/opencode/opencode.db` पर इसके SQLite DB को क्वेरी करके `opencode db --format json` के माध्यम से खोजे जाते हैं (हम `session` और `project` टेबल को पढ़ते हैं और `project_id` द्वारा समूहीकृत करते हैं); Pi प्रोजेक्ट `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` के तहत प्रति-सेशन JSONL ट्रांसक्रिप्ट को स्कैन करके (`PI_SESSIONS_DIR` के माध्यम से कॉन्फ़िगरेबल) और प्रत्येक सेशन के पहले रिकॉर्ड से `cwd` को खींचकर खोजे जाते हैं; Hermes गेटवे सेशन प्रत्येक प्रोफाइल के SQLite स्टोर से सीधे पढ़े जाते हैं — `~/.hermes/state.db` प्लस `~/.hermes/profiles/<name>/state.db` (`HERMES_HOME` द्वारा ओवरराइडेबल, या एकल डेटाबेस के लिए `HERMES_DB_PATH`) — और `hermes-<profile>-<source>` प्रोजेक्ट में प्रोफाइल और `source` द्वारा समूहीकृत किए जाते हैं (Slack/Telegram/cli/cron — गेटवे सेशन के पास कोई cwd नहीं); OpenClaw गेटवे सेशन `~/.openclaw/agents/<agentId>/sessions/*.jsonl` से पढ़े जाते हैं और `openclaw-<agentId>-<channel>` प्रोजेक्ट में एजेंट और चैनल द्वारा समूहीकृत किए जाते हैं (cwd भी नहीं); Factory Droid प्रोजेक्ट `~/.factory/sessions/<encoded-cwd>/*.jsonl` पर JSONL ट्रांसक्रिप्ट से खोजे जाते हैं और cwd द्वारा समूहीकृत किए जाते हैं; Devin प्रोजेक्ट `~/.local/share/devin/cli/sessions.db` पर इसके SQLite DB से (प्रत्येक सेशन के `working_directory` द्वारा समूहीकृत); Antigravity प्रोजेक्ट `~/.gemini/antigravity-cli/brain/<conversationId>/…/transcript_full.jsonl` पर JSONL ट्रांसक्रिप्ट से और cwd द्वारा समूहीकृत; और Goose प्रोजेक्ट `~/.local/share/goose/sessions/sessions.db` पर इसके SQLite DB से (प्रत्येक सेशन के `working_dir` द्वारा समूहीकृत)। एक प्रोजेक्ट जिसका उपयोग कई CLI द्वारा किया गया है, वह सभी मेल खाने वाले बैज के साथ एक एकल पंक्ति के रूप में प्रदर्शित होता है। किसी विशिष्ट एजेंट CLI द्वारा फ़िल्टर करने के लिए तालिका के ऊपर **CLI** ड्रॉपडाउन का उपयोग करें; URL आपकी चुनाव को `?cli=claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose` के रूप में संरक्षित करता है।

Hermes और OpenClaw उपयोगकर्ता-स्कोप्ड हैं और समूहबद्ध करने के लिए कोई कार्यशील निर्देशिका नहीं है, इसलिए वे एक **संक्षेप्त फोल्डर पेड़** के रूप में प्रदर्शित होते हैं — शीर्ष स्तर पर प्रोफाइल (या एजेंट), उसके नीचे चैनल — जबकि प्रत्येक cwd-आधारित CLI एक सपाट पंक्ति रहता है। फोल्डर पंक्तियां उनके अंदर की हर चीज के सेशन काउंट और सबसे हाल की गतिविधि को रोल अप करती हैं, संक्षिप्त फोल्डर को विज़िट के बीच याद रखा जाता है, और कीवर्ड खोज जो कुछ भी मेल खाती है उसे विस्तृत करती है।

प्रत्येक प्रोजेक्ट दिखाता है:
- प्रोजेक्ट का नाम (फोल्डर पथ से लिया गया)
- एक CLI बैज — `Claude Code` (नारंगी), `OpenAI Codex` (बैंगनी), `GitHub Copilot` (नीला), `Cursor Agent` (पन्ना), `OpenCode` (एम्बर), `Pi` (गुलाबी), और/या `Hermes` (नीलकांत)
- सबसे हाल की सेशन गतिविधि की तारीख

किसी प्रोजेक्ट को क्लिक करने से इसके सेशन देख सकते हैं।

### सेशन

किसी प्रोजेक्ट के सभी सेशन को सूचीबद्ध करता है। प्रत्येक सेशन दिखाता है:
- सेशन ID
- शुरुआत और समाप्ति टाइमस्टैम्प
- टूल कॉल की संख्या
- हुक गतिविधि काउंट (नीतियां जो फायर हुईं)

सूची को कम करने के लिए तारीख सीमा फ़िल्टर और सेशन ID खोज का उपयोग करें। सेशन को पृष्ठांकित किया गया है।

किसी सेशन को क्लिक करके सेशन व्यूअर खोलें।

### सेशन व्यूअर

सेशन व्यूअर स्वायत्त एजेंट के लिए मुख्य प्रश्न का उत्तर देता है: एजेंट ने क्या किया, और क्या यह ट्रैक पर रहा? हेडर के बगल में एक CLI बैज यह दर्शाता है कि सेशन Claude Code, OpenAI Codex, GitHub Copilot CLI, Cursor Agent, OpenCode, Pi, Hermes, OpenClaw, Factory Droid, Devin, Antigravity या Goose ट्रांसक्रिप्ट है। यह एक सेशन में हुई हर चीज की एक समयरेखा दिखाता है:

- **संदेश** - Claude के पाठ प्रतिक्रियाएं और उपयोगकर्ता प्रॉम्प्ट
- **टूल कॉल** - हर टूल जिसे Claude ने आमंत्रित किया, इसके इनपुट और आउटपुट के साथ
- **नीति गतिविधि** - प्रत्येक टूल कॉल के लिए, कौन सी नीतियां फायर हुईं और उन्होंने कौन सा निर्णय लौटाया

शीर्ष पर स्टैट्स बार सेशन की अवधि, कुल टूल कॉल, और हुक निर्णय का सारांश (allow / deny / instruct काउंट) दिखाता है।

सेशन को निर्यात करने के लिए **Download Logs** बटन को क्लिक करें। Claude Code, Codex, Copilot, Cursor और Pi सेशन के लिए आप मूल ऑन-डिस्क JSONL ट्रांसक्रिप्ट बाइट-दर-बाइट प्राप्त करते हैं; OpenCode के लिए (जिसके सेशन डिस्क पर नहीं, SQLite में रहते हैं) आप अंतर्निहित `session` / `messages` / `parts` टेबल को मिररिंग करने वाला एक JSON दस्तावेज़ प्राप्त करते हैं।

### ऑडिट

आपके एजेंट ने पिछले सेशन में वास्तव में कैसा व्यवहार किया है, इसका एक व्यक्तित्व-संचालित रिपोर्ट। `failproofai audit` CLI के समान ही स्कैन चलाता है लेकिन इसे एक एकल-स्क्रीन शेयरेबल पोस्टर + चार नीचे-के-गुना भागों के रूप में प्रस्तुत करता है:

1. **पोस्टर** — पहले व्यूपोर्ट को भरता है। failproof_ai वर्डमार्क + ऑडिट लेबल के साथ स्व-संपूर्ण PNG-कैप्चर क्षेत्र · आर्केटाइप इंडेक्स (`№ NN of 08`) + ऑडिट दिनांक · संख्यात्मक स्कोर (0–100) + प्रतिशतता रैंक गोली (`top 15%`) · आर्केटाइप नाम (एक `the optimist`, `the cowboy`, `the explorer`, `the goldfish`, `the paranoid architect`, `the precision builder`, `the hammer`, `the ghost` में से) + 3-कीवर्ड स्ट्रिप · `// only N% of agents are this archetype` दुर्लभता लाइन · 8×8 पिक्सल सिगिल टाइल · `audit yours → failproof.ai` पाद लेख। तीन शेयर बटन कैप्चर बॉक्स के बाहर बैठे हैं: `post your archetype` (X intent), `share on linkedin`, `download poster`। कैप्चर `html-to-image` के माध्यम से चलता है इसलिए PNG ऑन-स्क्रीन रेंडर से पिक्सल-दर-पिक्सल मेल खाता है (डैश्ड बॉर्डर, SVG लोगो मास्क, ग्रेडिएंट, फॉंट मेट्रिक्स — सभी संरक्षित)।
2. **शक्तियां** — शांत ✓ पंक्ति सूची आपके एजेंट ने जो व्यवहार पहले से ही सही तरीके से करता है, लाइव ऑडिट डेटा से लिया गया (स्वच्छ टूल-कॉल दर, मुख्य में कोई प्रत्यक्ष पुश नहीं, शून्य क्रेडेंशियल लीक, शून्य पुनः प्रयास तूफान) — प्रत्येक तभी सामने आता है जब प्रासंगिक नीति के पास ऑडिट विंडो में स्वच्छ रिकॉर्ड हो।
3. **विचित्रताएं** — तालिका कि क्या फिसल गई, गंभीरता द्वारा रैंक की गई: `when · what slipped + the policy that would've caught it · severity pill · seen`, जहां पुनरावृत्ति `new` (एक बार), `N× seen` (2–9 बार), या `recurring` (10+) को पढ़ता है।
4. **कैसे सुधारें** — शांत पंक्ति सूची, प्रत्येक निर्धारित नीति के लिए एक: सफेद में नीति का नाम, एक-पंक्ति विवरण, इंस्टॉल कमांड + दाईं ओर कॉपी बटन। सेक्शन हेडर `enable all N → projected <score> · <tier>` को पढ़ता है (वह स्कोर जो आप हर फिक्स लागू करने से प्राप्त करेंगे), और इसका `[install all]` बटन हर निर्धारित नीति के लिए संयुक्त `failproofai policy add a b c …` कमांड को कॉपी करता है।
5. **बेहतर वापस आएं** — दो साथ-साथ कार्ड। बाईं ओर: एक रिमाइंडर सेट करें (`3d` / `7d` / `14d` / `30d` कैडेंस पिकर; एक बार प्रमाणीकृत होने के बाद `/api/auth/reminder` के माध्यम से बना रहता है)। दाईं ओर: failproof सुविधाएं अनलॉक करें — `invite a friend` एक मोडल खोलता है जो अल्पविराम/स्पेस/न्यूलाइन-अलग की गई मित्र ईमेल सूची लेता है (प्रति भेज अधिकतम 10), उन्हें `/api/audit/invite` को POST करता है, जो api-server के `POST /v0/invite` को अग्रेषित करता है। api-server `invite@failproof.ai` से प्रत्येक प्राप्तकर्ता को एक ईमेल भेजता है जिसमें प्रेषक को Cc किया जाता है और `Reply-To` सेट किया जाता है, इसलिए प्राप्तकर्ता देखता है कि किसने उन्हें आमंत्रित किया और प्रेषक को अपने इनबॉक्स में एक प्रति मिलती है। गुमनाम उपयोगकर्ताओं को `AuthDialog` के माध्यम से रूट किया जाता है ताकि प्रेषक का ईमेल निमंत्रण जाने से पहले ज्ञात हो। पात्रता / सुविधा पूर्ति एक अनुवर्ती है।

`failproofai audit` रनटाइम द्वारा संचालित — अंतर्निहित स्कैन इंजन, समर्थित ध्वज और प्रति-ट्रांसक्रिप्ट कैश अपरिवर्तनीयों के लिए [Audit CLI](/hi/cli/audit) देखें। डैशबोर्ड `~/.failproofai/audit-dashboard.json` पर नवीनतम परिणाम को कैश करता है (मोड `0600`, एकल स्लॉट, नई रनें ओवरराइट करती हैं) इसलिए फिर से विज़िट तत्काल हैं; **प्रति-ट्रांसक्रिप्ट और पूरे परिणाम दोनों कैश को 7 दिनों से पुराने होने पर पढ़ने पर अस्वीकार कर दिया जाता है** इसलिए डैशबोर्ड कभी भी चुप चाप एक सप्ताह पुरानी परिणाम नहीं देता है — TTL के बाद `/audit` अपनी खाली अवस्था में गिरता है और एक ताज़ा रन का संकेत देता है। रिपोर्ट के निचले भाग के पास `[ re-audit now ]` को क्लिक करने से `/api/audit/run` को `noCache: true` के साथ POST किया जाता है — पुन: ऑडिट प्रति-ट्रांसक्रिप्ट कैश को बाईपास करता है और कैश की गई परिणाम को चुप चाप वापस न करने के बजाय शुरुआत से हर ट्रांसक्रिप्ट को फिर से स्कैन करता है — और डैशबोर्ड `/api/audit/status` को 1Hz पर चलाया जाता है जब तक रन समाप्त न हो जाए; एक चिपचिपी गुलाबी प्रगति पट्टी रन के दौरान व्यूपोर्ट के शीर्ष पर पिन की जाती है एक बीता हुआ टाइमर के साथ, और ताज़ा परिणाम सफलता पर स्थान में स्वैप करता है (कोई पूर्ण-पृष्ठ पुनः लोड नहीं; एक विफल पुन: ऑडिट पूर्व रिपोर्ट को अक्षुण्ण रखता है)। विफलता पर पट्टी लाल हो जाती है `RerunError.kind` (`timeout` / `network` / `post_failed`) से कॉपी के साथ। खाली अवस्था (कोई कैश नहीं या समाप्त) और शून्य-सेशन अवस्था (कैश मौजूद है लेकिन स्कैन को कोई ट्रांसक्रिप्ट नहीं मिला) को अलग से सामने लाया जाता है।

डैशबोर्ड के पास शीर्ष नेविगेशन में एक ऑटो-रिफ्रेश टॉगल है। सक्षम होने पर, वर्तमान पृष्ठ समय-समय पर नए सेशन और नीति गतिविधि दिखाने के लिए रीफ्रेश करता है क्योंकि वे दिखाई देते हैं। लंबे समय तक चलने वाले स्वायत्त एजेंट सेशन की निगरानी के लिए आवश्यक।

## पृष्ठ अक्षम करना

यदि आपको डैशबोर्ड के केवल कुछ भागों की आवश्यकता है, तो `FAILPROOFAI_DISABLE_PAGES` को पृष्ठ नामों की अल्पविराम-अलग सूची में सेट करें:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

मान्य मान: `policies`, `projects`, `audit`।

---

## प्रोजेक्ट पथ कॉन्फ़िगर करना

डिफ़ॉल्ट रूप से, डैशबोर्ड मानक Claude Code प्रोजेक्ट निर्देशिका से पढ़ता है। कस्टम सेटअप के लिए इसे ओवरराइड करें:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## गैर-localhost होस्ट से एक्सेस करना

जब डैशबोर्ड को **dev मोड** (`npm run dev`) में चला रहे हों और इसे `localhost` के अलावा किसी होस्टनेम से एक्सेस कर रहे हों - उदाहरण के लिए, एक कस्टम डोमेन, एक दूरस्थ IP, या एक टनलिंग किया गया URL - आप जैसी चेतावनी देख सकते हैं:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

यह Next.js अपने HMR (हॉट मॉड्यूल रीलोड) वेबसॉकेट तक क्रॉस-ऑरिजिन एक्सेस को ब्लॉक कर रहा है, जो एक dev-only सुविधा है। अपने होस्ट को अनुमति देने के लिए `--allowed-origins` ध्वज का उपयोग करें:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

कई होस्ट या IP के लिए, एक अल्पविराम-अलग सूची पास करें:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

आप इसके बजाय `FAILPROOFAI_ALLOWED_DEV_ORIGINS` पर्यावरण चर भी सेट कर सकते हैं:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
यह केवल dev मोड पर लागू होता है। जब `failproofai` (production मोड) चला रहे हों, तो कोई HMR वेबसॉकेट नहीं है और कोई क्रॉस-ऑरिजिन dev संसाधन समस्या नहीं है।
</Note>
