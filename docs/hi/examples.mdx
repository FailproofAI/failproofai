सामान्य परिदृश्यों के लिए तैयार उदाहरण। प्रत्येक में दिखाया गया है कि कैसे इंस्टॉल करें और क्या उम्मीद करें।

---

## Claude Code के लिए hooks सेट अप करना

Failproof AI, Claude Code से इसकी [hooks system](https://docs.anthropic.com/en/docs/claude-code/hooks) के माध्यम से एकीकृत होता है। जब आप `failproofai policies --install` चलाते हैं, तो यह Claude Code के `settings.json` में hook कमांड को रजिस्टर करता है जो हर tool call पर फायर होते हैं।

<Steps>
  <Step title="failproofai को इंस्टॉल करें">
    ```bash
    npm install -g failproofai
    ```
  </Step>
  <Step title="सभी built-in policies को सक्षम करें">
    ```bash
    failproofai policies --install
    ```
  </Step>
  <Step title="सत्यापित करें कि hooks रजिस्टर हैं">
    ```bash
    cat ~/.claude/settings.json | grep failproofai
    ```

    आपको `PreToolUse`, `PostToolUse`, `Notification`, और `Stop` इवेंट्स के लिए hook entries दिखाई देने चाहिए।
  </Step>
  <Step title="Claude Code चलाएं">
    ```bash
    claude
    ```

    नीतियां अब हर tool call पर स्वचालित रूप से चलती हैं। Claude को `sudo rm -rf /` चलाने के लिए कहने की कोशिश करें - यह ब्लॉक हो जाएगा।
  </Step>
</Steps>

## Agents SDK के लिए hooks सेट अप करना

यदि आप [Agents SDK](https://docs.anthropic.com/en/docs/agents-sdk) के साथ निर्माण कर रहे हैं, तो आप प्रोग्रामेटिक रूप से एक ही hook system का उपयोग कर सकते हैं।

<Steps>
  <Step title="अपने प्रोजेक्ट में failproofai को इंस्टॉल करें">
    ```bash
    npm install failproofai
    ```
  </Step>
  <Step title="अपने एजेंट में hooks को कॉन्फ़िगर करें">
    अपनी एजेंट प्रक्रिया बनाते समय hook कमांड पास करें। हुक Claude Code जैसे ही फायर होते हैं - stdin/stdout JSON के माध्यम से:

    ```bash
    failproofai --hook PreToolUse   # प्रत्येक tool से पहले कॉल किया जाता है
    failproofai --hook PostToolUse  # प्रत्येक tool के बाद कॉल किया जाता है
    ```
  </Step>
  <Step title="अपने एजेंट के लिए एक कस्टम policy लिखें">
    ```javascript
    import { customPolicies, allow, deny } from "failproofai";

    customPolicies.add({
      name: "limit-to-project-dir",
      description: "Keep the agent inside the project directory",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        const path = String(ctx.toolInput?.file_path ?? "");
        if (path.startsWith("/") && !path.startsWith(ctx.session?.cwd ?? "")) {
          return deny("Agent is restricted to the project directory");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="कस्टम policy को इंस्टॉल करें">
    ```bash
    failproofai policies --install --custom ./my-agent-policies.js
    ```
  </Step>
</Steps>

## विनाशकारी कमांड को ब्लॉक करें

सबसे आम सेटअप - एजेंटों को अपरिवर्तनीय नुकसान करने से रोकें।

```bash
failproofai policies --install block-sudo block-rm-rf block-force-push block-curl-pipe-sh
```

यह क्या करता है:
- `block-sudo` - सभी `sudo` कमांड को ब्लॉक करता है
- `block-rm-rf` - रिकर्सिव फाइल deletion को ब्लॉक करता है
- `block-force-push` - `git push --force` को ब्लॉक करता है
- `block-curl-pipe-sh` - दूरस्थ स्क्रिप्ट्स को shell में pipe करना ब्लॉक करता है

## Secret leakage को रोकें

एजेंटों को tool output में credentials को देखने या leak करने से रोकें।

```bash
failproofai policies --install sanitize-api-keys sanitize-jwt sanitize-connection-strings sanitize-bearer-tokens
```

ये `PostToolUse` पर फायर होते हैं - एक tool चलने के बाद, वे एजेंट के देखने से पहले output को scrub करते हैं।

## जब एजेंट को ध्यान की आवश्यकता हो तो Slack alerts प्राप्त करें

notification hook का उपयोग करके idle alerts को Slack पर फॉरवर्ड करें।

```javascript
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "slack-on-idle",
  description: "Alert Slack when the agent is waiting for input",
  match: { events: ["Notification"] },
  fn: async (ctx) => {
    const webhookUrl = process.env.SLACK_WEBHOOK_URL;
    if (!webhookUrl) return allow();

    const message = String(ctx.payload?.message ?? "Agent is waiting");
    const project = ctx.session?.cwd ?? "unknown";

    try {
      await fetch(webhookUrl, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          text: `*${message}*\nProject: \`${project}\``,
        }),
        signal: AbortSignal.timeout(5000),
      });
    } catch {
      // अगर Slack तक नहीं पहुंचा है तो कभी भी एजेंट को ब्लॉक न करें
    }

    return allow();
  },
});
```

इसे इंस्टॉल करें:

```bash
SLACK_WEBHOOK_URL=https://hooks.slack.com/... failproofai policies --install --custom ./slack-alerts.js
```

## एजेंटों को एक branch पर रखें

एजेंटों को branches को स्विच करने या protected ones पर push करने से रोकें।

```javascript
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "stay-on-branch",
  description: "Prevent the agent from checking out other branches",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = String(ctx.toolInput?.command ?? "");
    if (/git\s+checkout\s+(?!-b)/.test(cmd)) {
      return deny("Stay on the current branch. Create a new branch with -b if needed.");
    }
    return allow();
  },
});
```

## Commits से पहले tests की आवश्यकता है

एजेंटों को commit करने से पहले tests चलाने के लिए याद दिलाएं।

```javascript
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "test-before-commit",
  description: "Remind the agent to run tests before committing",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = String(ctx.toolInput?.command ?? "");
    if (/git\s+commit/.test(cmd)) {
      return instruct("Run tests before committing. Use `npm test` or `bun test` first.");
    }
    return allow();
  },
});
```

## एक production repo को lock down करें

एक project-level config commit करें ताकि आपकी टीम के हर डेवलपर को एक ही policies मिलें।

अपने repo में `.failproofai/policies-config.json` बनाएं:

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-force-push",
    "block-push-master",
    "block-env-files",
    "sanitize-api-keys",
    "sanitize-jwt"
  ],
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "release", "production"]
    }
  }
}
```

फिर इसे commit करें:

```bash
git add .failproofai/policies-config.json
git commit -m "Add failproofai team policies"
```

हर टीम सदस्य जिसके पास failproofai installed है, स्वचालित रूप से इन नियमों को ले जाएगा।

## Convention policies के साथ एक org-wide quality standard बनाएं

सबसे प्रभावशाली सेटअप: अपने repo में `.failproofai/policies/` commit करें जो आपके प्रोजेक्ट के लिए तैयार की गई policies के साथ। हर टीम सदस्य को स्वचालित रूप से मिलते हैं — कोई install commands नहीं, कोई config changes नहीं।

<Steps>
  <Step title="निर्देशिका बनाएं और policies जोड़ें">
    ```bash
    mkdir -p .failproofai/policies
    ```

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    // अपनी टीम के पसंदीदा package manager को लागू करें
    // (या बजाय इसके built-in prefer-package-manager policy को सक्षम करें)
    customPolicies.add({
      name: "enforce-bun",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        const cmd = String(ctx.toolInput?.command ?? "");
        if (/\bnpm\b/.test(cmd)) return deny("Use bun instead of npm.");
        return allow();
      },
    });

    // एजेंट को commit करने से पहले tests चलाने के लिए याद दिलाएं
    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Run tests before committing.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="Git में commit करें">
    ```bash
    git add .failproofai/policies/
    git commit -m "Add team quality policies"
    ```
  </Step>
  <Step title="सुधार करते रहें">
    जैसे ही आपकी टीम को नई failure modes का सामना करना पड़े, policies जोड़ें और push करें। हर किसी को अपने अगले `git pull` पर update मिलता है। ये policies एक living quality standard बन जाती हैं जो आपकी टीम के साथ बढ़ते हैं।
  </Step>
</Steps>

## अधिक उदाहरण

repo के [`examples/`](https://github.com/failproofai/failproofai/tree/main/examples) निर्देशिका में शामिल हैं:

| फाइल | यह क्या दिखाता है |
|------|---------------|
| `policies-basic.js` | Starter policies - production writes, force-push, piped scripts को ब्लॉक करें |
| `policies-notification.js` | Idle notifications और session end के लिए Slack alerts |
| `policies-advanced/index.js` | Transitive imports, async hooks, PostToolUse output scrubbing, Stop event handling |
