## आवश्यकताएं

- **Node.js** >= 20.9.0
- **Bun** >= 1.3.0 (वैकल्पिक - केवल स्रोत से बनाने के लिए आवश्यक)

## इंस्टॉलेशन

<CodeGroup>

npm install -g failproofai

```bash bun
bun add -g failproofai
```

## त्वरित शुरुआत

<Steps>
  <Step title="नीतियों को सक्षम करें">
    नीतियां ऐसे नियम हैं जो हर एजेंट टूल कॉल से पहले और बाद में चलती हैं। वे विनाशकारी कमांड, सीक्रेट लीकेज, और अन्य विफलता मोड को नुकसान पहुंचाने से पहले पकड़ लेती हैं।

    ```bash
    failproofai policies --install
    ```

    यह आपके इंस्टॉल किए गए एजेंट CLIs में हुक प्रविष्टियां लिखता है (Claude Code का `~/.claude/settings.json`, OpenAI Codex का `~/.codex/hooks.json`, GitHub Copilot CLI का `~/.copilot/hooks/failproofai.json`, Cursor Agent का `~/.cursor/hooks.json`, OpenCode का `~/.config/opencode/plugins/failproofai.mjs` पर जेनरेट की गई प्लगइन शिम और `~/.config/opencode/opencode.json` के `plugin` एरे में एक रजिस्ट्रेशन प्रविष्टि, Pi का `~/.pi/agent/settings.json`, Hermes का `~/.hermes/config.yaml`, OpenClaw का `~/.openclaw/openclaw.json`, Factory Droid का `~/.factory/hooks.json`, Devin CLI का `~/.config/devin/config.json`, Antigravity CLI का `~/.gemini/config/hooks.json`, या Goose का ऑटो-डिस्कवर किया गया प्लगइन डायरेक्टरी `~/.agents/plugins/failproofai/hooks/hooks.json`)। जब एक से अधिक मौजूद हों तो आपको प्रॉम्प्ट किया जाएगा; प्रॉम्प्ट को छोड़ने के लिए `--cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose` (कोई भी सबसेट) पास करें।

    GitHub Copilot CLI, Cursor Agent, OpenCode, और Pi समर्थन **बीटा** हैं — `--cli copilot`, `--cli cursor`, `--cli opencode`, या `--cli pi` के साथ इंस्टॉल करें। Hermes (hermes-agent, एक Slack/Telegram गेटवे) `--cli hermes` के साथ यूजर-स्कोप इंस्टॉल करता है और **साथ ही** एक ऑफलाइन ऑडिट स्रोत है। OpenClaw (openclaw गेटवे, एक स्व-होस्टेड मल्टी-चैनल असिस्टेंट) `--cli openclaw` के साथ यूजर-स्कोप इंस्टॉल करता है — प्रवर्तन इसके इन-प्रोसेस प्लगइन हुक्स के माध्यम से चलता है (`before_agent_finalize` एक असली टर्न-एंड गेट है, इसलिए `require-*-before-stop` बिल्ट-इन लागू करते हैं) — और **साथ ही** एक ऑफलाइन ऑडिट स्रोत है। Factory Droid (`droid`) `--cli factory` के साथ इंस्टॉल करता है (यूजर + प्रोजेक्ट स्कोप) और **साथ ही** एक ऑफलाइन ऑडिट स्रोत है। Devin CLI (`devin`, Cognition) `--cli devin` के साथ इंस्टॉल करता है (यूजर + प्रोजेक्ट स्कोप) और **साथ ही** एक ऑफलाइन ऑडिट स्रोत है। Antigravity CLI (`agy`) `--cli antigravity` के साथ इंस्टॉल करता है (यूजर + प्रोजेक्ट स्कोप) और **साथ ही** एक ऑफलाइन ऑडिट स्रोत है। Goose (कोडनेम goose, Block) `--cli goose` के साथ इंस्टॉल करता है (यूजर + प्रोजेक्ट स्कोप) — इंस्टॉलर बस `~/.agents/plugins/failproofai/` पर एक प्लगइन डायरेक्टरी ड्रॉप करता है जिसे Goose ऑटो-डिस्कवर करता है, और यह **साथ ही** एक ऑफलाइन ऑडिट स्रोत है।

    ```bash
    failproofai policies --install --scope project
    failproofai policies --install --cli codex --scope project
    failproofai policies --install --cli copilot --scope project
    failproofai policies --install --cli cursor --scope project
    failproofai policies --install --cli opencode --scope project
    failproofai policies --install --cli pi --scope project
    failproofai policies --install --cli hermes --scope user
    failproofai policies --install --cli openclaw --scope user
    failproofai policies --install --cli factory --scope project
    failproofai policies --install --cli devin --scope project
    failproofai policies --install --cli antigravity --scope project
    failproofai policies --install --cli goose --scope project
    failproofai policies --install block-sudo block-rm-rf sanitize-api-keys
    ```
  </Step>
  <Step title="सत्यापित करें">
    ```bash
    failproofai policies
    ```

    हर नीति, चाहे वह सक्षम हो, और किसी भी कॉन्फ़िगर किए गए पैरामीटर को दिखाता है।
  </Step>
  <Step title="डैशबोर्ड लॉन्च करें">
    ```bash
    failproofai
    ```

    `http://localhost:8020` पर एक स्थानीय डैशबोर्ड खोलता है जहां आप सेशन ब्राउज़ कर सकते हैं, टूल कॉल का निरीक्षण कर सकते हैं, और नीतियों को प्रबंधित कर सकते हैं।
  </Step>
  <Step title="अपना एजेंट चलाएं">
    Claude Code को सामान्य रूप से शुरू करें। यदि एजेंट कुछ जोखिमपूर्ण कोशिश करता है, तो failproofai स्वचालित रूप से इसे रोक देता है। इसे अनुपस्थित छोड़ें और डैशबोर्ड में देखें कि क्या हुआ।
  </Step>
</Steps>

## नीतियां कैसे काम करती हैं

हर बार जब एक एजेंट कोई टूल चलाता है, Claude Code failproofai को एक सबप्रोसेस के रूप में कॉल करता है:

```text
Claude Code  →  failproofai --hook PreToolUse  →  stdin JSON पढ़ता है
                                                 नीतियों का मूल्यांकन करता है
                                                 stdout को निर्णय लिखता है
```

प्रत्येक नीति तीन निर्णयों में से एक देती है:

- **allow** - एजेंट सामान्य रूप से आगे बढ़ता है
- **deny** - कार्य अवरुद्ध हो जाता है, एजेंट को बताया जाता है कि क्यों
- **instruct** - एजेंट के प्रॉम्प्ट में अतिरिक्त संदर्भ जोड़ा जाता है

<Note>
नीतियां आपकी स्थानीय प्रक्रिया में चलती हैं। कुछ भी दूरस्थ सेवा को नहीं भेजा जाता है।
</Note>

## सम्मेलन-आधारित नीतियों के साथ टीम नीतियां सेट करें

अपनी पूरी टीम में गुणवत्ता मानकों को स्थापित करने का सबसे तेज़ तरीका `.failproofai/policies/` सम्मेलन है। इस डायरेक्टरी में नीति फाइलें ड्रॉप करें और वे स्वचालित रूप से लोड हो जाती हैं — कोई फ्लैग, कोई कॉन्फ़िग परिवर्तन, कोई इंस्टॉल कमांड नहीं।

<Steps>
  <Step title="नीति डायरेक्टरी बनाएं">
    ```bash
    mkdir -p .failproofai/policies
    ```
  </Step>
  <Step title="नीति फाइलें जोड़ें">
    स्टार्टर उदाहरण कॉपी करें या अपने स्वयं के लिखें:

    ```bash
    cp node_modules/failproofai/examples/convention-policies/*.mjs .failproofai/policies/
    ```

    या एक नई फाइल बनाएं:

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Run tests before committing.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="git में कमिट करें">
    ```bash
    git add .failproofai/policies/
    git commit -m "Add team quality policies"
    ```

    जिस भी टीम सदस्य के पास failproofai इंस्टॉल है वह स्वचालित रूप से इन नीतियों को उठाता है। कोई प्रति-डेवलपर सेटअप की आवश्यकता नहीं है।
  </Step>
</Steps>

<Tip>
अपने रिपो में `.failproofai/policies/` कमिट करें ताकि पूरी टीम समान मानकों को साझा करे। जैसे-जैसे आपकी टीम नई विफलता मोड की खोज करती है, नीतियां जोड़ें और पुश करें — हर किसी को अपने अगले `git pull` पर अपडेट मिलता है। समय के साथ ये नीतियां एक जीवंत गुणवत्ता मानक बन जाती हैं जो लगातार सुधार करती रहती है।
</Tip>

## डेटा भंडारण

सभी कॉन्फ़िगरेशन और लॉग आपकी मशीन पर रहते हैं:

| पथ | यह क्या संग्रहीत करता है |
|------|----------------|
| `~/.failproofai/policies/local-policies/policies-config.json` | वैश्विक नीति कॉन्फ़िगरेशन |
| `~/.failproofai/hook-activity/` | हुक निष्पादन इतिहास (पेजेड JSONL) |
| `~/.failproofai/logs/` | कस्टम हुक त्रुटियों के लिए डीबग लॉग |
| `.failproofai/policies-config.json` | प्रति-प्रोजेक्ट कॉन्फ़िगरेशन (कमिट किया गया) |
| `.failproofai/policies-config.local.json` | व्यक्तिगत ओवरराइड (gitignored) |

## अनइंस्टॉल करना

```bash
failproofai policies --uninstall
```

`~/.claude/settings.json` से हुक प्रविष्टियां हटाता है। `~/.failproofai/` में कॉन्फ़िगरेशन फाइलें रखी जाती हैं।
