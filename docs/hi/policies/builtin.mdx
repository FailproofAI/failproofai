अंतर्निर्मित नीतियां गुप्त हैंडलिंग, पर्यावरण फाइलें, विनाशकारी शेल कमांड, संरक्षित शाखाएं, क्लाउड और बुनियादी ढांचे के उपकरण, पैकेज प्रकाशन, दोहराई गई कॉल, और कार्य-अंत वर्कफ़्लो जांच को कवर करती हैं।

## अंतर्निर्मित नीति को सक्षम और सत्यापित करें

<Tabs>
  <Tab title="डैशबोर्ड">
    1. स्थानीय CLI के साथ एक जुड़ी हुई मशीन पर नीति को इंस्टॉल करें।
    2. उपकरण युक्त एजेंट में एक सुरक्षित परीक्षण क्रिया चलाएं।
    3. **Observe → policy** पर जाएं और नीति के नाम, मशीन पर्यावरण, या निर्णय के आधार पर फ़िल्टर करें।
    4. मेल खाने वाली टूल इनपुट और लौटाए गए कारण को पुष्टि करने के लिए लिंक किए गए सत्र को खोलें।

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies
    failproofai policy add block-rm-rf --cli claude --scope project
    failproofai config --status
    ```

    `failproofai policy remove block-rm-rf --cli claude --scope project` के साथ इसे हटाएं।
  </Tab>
</Tabs>

अपने इंस्टॉल किए गए संस्करण में उपलब्ध नीतियों को सूचीबद्ध करें:

```bash
failproofai policies
```

किसी प्रोजेक्ट के लिए एक नीति सक्षम करें:

```bash
failproofai policy add block-rm-rf --scope project
```

चयनित उपकरणों के लिए कई नीतियां सक्षम करें:

```bash
failproofai policies --install block-sudo block-force-push \
  --cli claude codex --scope project
```

कुछ नीतियां पैरामीटर स्वीकार करती हैं या बीटा के रूप में चिह्नित होती हैं। रोलआउट से पहले विवरण, मिलान स्कोप, और डिफ़ॉल्ट व्यवहार की समीक्षा करें। एक नीति जो एक वर्कफ़्लो की सुरक्षा करती है, दूसरे में वैध ऑपरेशन को ब्लॉक कर सकती है।

<Tip>
  भंडार-विशिष्ट अपेक्षाओं के लिए प्रोजेक्ट स्कोप को प्राथमिकता दें और मशीन-व्यापी सुरक्षा आवश्यकताओं के लिए उपयोगकर्ता स्कोप को प्राथमिकता दें।
</Tip>
