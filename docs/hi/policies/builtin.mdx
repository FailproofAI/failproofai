बिल्ट-इन नीतियां गुप्त हैंडलिंग, पर्यावरण फाइलें, विनाशकारी शेल कमांड, संरक्षित ब्रांच, क्लाउड और बुनियादी ढांचा उपकरण, पैकेज प्रकाशन, दोहराई गई कॉल और कार्य समाप्ति वर्कफ़्लो जांच को कवर करती हैं।

## एक बिल्ट-इन नीति सक्षम करें और सत्यापित करें

<Tabs>
  <Tab title="Dashboard">
    1. स्थानीय CLI के साथ एक जुड़ी हुई मशीन पर नीति को इंस्टॉल करें।
    2. उपकरण एजेंट में एक सुरक्षित परीक्षण क्रिया चलाएं।
    3. **Observe → policy** पर जाएं और नीति के नाम, मशीन वातावरण या निर्णय द्वारा फ़िल्टर करें।
    4. मेल खाने वाली टूल इनपुट और लौटाए गए कारण की पुष्टि करने के लिए लिंक किए गए सत्र को खोलें।

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies
    failproofai policy add block-rm-rf --cli claude --scope project
    failproofai config --status
    ```

    इसे `failproofai policy remove block-rm-rf --cli claude --scope project` के साथ हटाएं।
  </Tab>
</Tabs>

अपने स्थापित संस्करण में उपलब्ध नीतियों की सूची देखें:

```bash
failproofai policies
```

एक परियोजना के लिए एक नीति सक्षम करें:

```bash
failproofai policy add block-rm-rf --scope project
```

चयनित हार्नेस के लिए कई नीतियां सक्षम करें:

```bash
failproofai policies --install block-sudo block-force-push \
  --cli claude codex --scope project
```

कुछ नीतियां पैरामीटर स्वीकार करती हैं या बीटा के रूप में चिह्नित हैं। रोलआउट से पहले विवरण, मेल की गई स्कोप और डिफ़ॉल्ट व्यवहार की समीक्षा करें। एक नीति जो एक वर्कफ़्लो की सुरक्षा करती है वह दूसरे में वैध संचालन को ब्लॉक कर सकती है।
