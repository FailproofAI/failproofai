एक नीति लिखने से पहले [builtin कैटलॉग](/hi/policies/builtin-catalog) देखें। समीक्षा की गई नियम आमतौर पर एक नई नीति से अधिक सुरक्षित होती है।

## एक कार्यशील नीति से शुरू करें

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

स्टार्टर ब्लॉक `git push --force` को ब्लॉक करता है। इसे संपादित करें, अपने एजेंट को ब्लॉक की गई कार्रवाई का प्रयास करने के लिए कहें, और **Policies → Activity** का निरीक्षण करें।

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "protect-production",
  description: "Production changes need a human",
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) =>
    String(ctx.toolInput?.command ?? "").includes("production")
      ? deny("Ask a human before changing production.")
      : allow(),
});
```

एक नीति `allow()`, `deny(message)`, या `instruct(message)` लौटाती है। `deny` का उपयोग करें जब कार्रवाई को रोकना चाहिए; हर harness एजेंट को वापस निर्देश प्रदान नहीं कर सकता।

## स्वचालित रूप से लोड करें

फ़ाइलों को नाम `*policies.js`, `*policies.mjs`, या `*policies.ts` के साथ यहां रखें:

- `.failproofai/policies/` एक प्रोजेक्ट के लिए।
- `~/.failproofai/policies/` आपके यूजर के लिए।

## विफलता पथों का परीक्षण करें

असुरक्षित कार्रवाई और वैध काम दोनों का परीक्षण करें जो समान दिखते हों। पुष्टि करें कि निर्णय आपकी नीति से आया है, न कि किसी अन्य नियम से।

स्पष्ट टेस्ट फ़ाइलों को हटाएं:

```bash
failproofai policies -u -c
```

जब नीति तैयार हो, तो [एक पैक प्रकाशित करें](/hi/policies/publish-a-pack) या [इसे Cloud के माध्यम से तैनात करें](/hi/policies/deploy)।
