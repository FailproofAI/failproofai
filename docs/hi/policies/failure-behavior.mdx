Failproof AI को इस तरह डिज़ाइन किया गया है कि प्रवर्तन विफलता दृश्यमान हो, जिससे जोखिम भरा काम चुप्पी से अनुमति न पाए।

## विफलता-बंद ब्लॉक का निदान करें

<Tabs>
  <Tab title="Dashboard">
    1. **Admin → enforcement** पर जाएँ और मशीन को खोलें।
    2. इसकी अंतिम चेक-इन, असाइन किए गए deployment, और रिपोर्ट किए गए deployment की जांच करें।
    3. **Observe → policy** पर जाएँ और अनुमति-विहीन निर्णय का सत्र खोलें।
    4. सुनिश्चित करें कि कारण daemon पहुंच, संस्करण असंगति, या नीति स्वयं की रिपोर्ट करता है।

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    npm install -g failproofai@latest
    failproofai config
    ```

    `failproofai config` को फिर से चलाने से पैकेज अपग्रेड के बाद daemon अपडेट और पुनः शुरू होता है।
  </Tab>
</Tabs>

`failproofaid` का उपयोग करने के लिए कॉन्फ़िगर की गई मशीन पर, daemon एकमात्र मूल्यांकनकर्ता है। यदि यह अपहुंच है या इसका प्रोटोकॉल संस्करण CLI से मेल नहीं खाता है, तो हुक मूल्यांकन बंद हो जाता है। कार्रवाई को एक कारण के साथ अस्वीकार कर दिया जाता है जो ऑपरेटर को daemon की जांच या अपडेट करने के लिए निर्देशित करता है।

daemon कॉन्फ़िगरेशन से पहले, हुक नीतियों को प्रक्रिया में मूल्यांकित करते हैं। एक बार daemon कॉन्फ़िगरेशन रिकॉर्ड हो जाने के बाद, Failproof AI जब daemon विफल हो तो चुप्पी से दूसरे मूल्यांकनकर्ता को वापस नहीं करता है।

## विफलता-बंद निर्णय का जवाब दें

1. `failproofai config --status` चलाएँ।
2. यदि संस्करण भिन्न हैं, तो पैकेज को अपडेट करने के बाद `failproofai config` को फिर से चलाएँ।
3. यदि daemon अपहुंच है, तो इसकी सेवा स्थिति और स्थानीय लॉग का निरीक्षण करें।
4. एजेंट कार्य को केवल तभी पुनः शुरू करें जब ज्ञात नीति मूल्यांकन पथ स्वस्थ हो।

<Warning>
  अवरुद्ध कार्रवाई को बार-बार पुनः प्रयास न करें। विफलता-बंद प्रतिक्रिया का अर्थ है कि सिस्टम यह स्थापित नहीं कर सके कि कार्रवाई सुरक्षित थी।
</Warning>
