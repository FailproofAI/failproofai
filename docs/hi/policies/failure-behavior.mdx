सेटअप के बाद, स्थानीय `failproofaid` सेवा एकमात्र मूल्यांकनकर्ता है। यदि वह जवाब नहीं दे सकता, तो संरक्षित कार्य चुपचाप अनुमति दिए जाने के बजाय अस्वीकार कर दिए जाते हैं।

## मशीन-व्यापी ब्लॉक का निदान करें

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

सेवा की मरम्मत करने या मेल खाने वाले संस्करण को स्थापित करने के लिए `failproofai config` चलाएं।

दो विफलताएं समान दिख सकती हैं:

| विफलता | अर्थ |
| --- | --- |
| सेवा अनुपलब्ध | सॉकेट के पीछे कोई कार्यशील मूल्यांकनकर्ता नहीं है |
| संस्करण असमानता | CLI और सेवा प्रोटोकॉल पर असहमत हैं |

दोनों अस्वीकार करते हैं, लेकिन स्थिति उन्हें अलग से रिपोर्ट करती है।

## एक पैक लोड नहीं होगा

एक चयनित पैक जो अनुपलब्ध, परिवर्तित या अमान्य है, अपनी चयनित नीतियों द्वारा कवर किए गए ईवेंट को अस्वीकार कर देता है। यह एक टूटे हुए पैक को गायब होने से रोकता है जबकि मशीन सुरक्षित दिखाई दे रही है।

`failproofai policies` पैक का नाम और लोड त्रुटि दिखाता है।

```bash
failproofai policies
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

अपठनीय मेटाडेटा सुरक्षित अस्वीकार को उस डेटा से संकीर्ण करने के बजाय चौड़ा करता है जिस पर विश्वास नहीं किया जा सकता।

## क्या उपलब्ध रहता है

स्थानीय डैशबोर्ड और स्थिति कमांड नीति मूल्यांकन विफल होने के दौरान भी काम करते रहते हैं। उन्हें उस सेवा, पैक या संस्करण की पहचान करने के लिए उपयोग करें जिसकी मरम्मत की आवश्यकता है।

<Warning>
  सेवा या पैक फाइलों को हटाकर विफलता-बंद निर्णय के आसपास काम न करें। सेवा की मरम्मत करें, पैक को पुनः स्थापित करें, या CLI के माध्यम से असाइनमेंट को हटाएं ताकि मशीन एक ज्ञात स्थिति में वापस आ जाए।
</Warning>
