फ्लीट कवरेज इस बात का जवाब देता है कि क्या कोई नीति वह जगह है जहां जोखिम है। मशीनों को स्थिर आईडी और एक मानव-पठनीय लेबल से ट्रैक करें, फिर उनकी असाइन की गई और रिपोर्ट की गई तैनाती स्थिति की तुलना करें।

## कवरेज जांचें

<Tabs>
  <Tab title="Dashboard">
    1. **Admin → enforcement** पर जाएं और लागू करने और देखने वाले कुल की समीक्षा करें।
    2. आईडी या लेबल से मशीन खोजें, या नीति से रहित मशीनों के लिए फ़िल्टर करें।
    3. असाइन की गई नीतियों, रिपोर्ट की गई तैनाती, अंतिम चेक-इन और इतिहास की तुलना करने के लिए एक पंक्ति को विस्तारित करें।
    4. मशीन के पोलिंग अंतराल के बाद रीफ़्रेश करें जब लागू की गई तैनाती लंबित रहे।

    ![प्रवर्तन फ्लीट नीति कवरेज, मशीन तैनाती स्थिति, और अवलोकन और प्रवर्तन असाइनमेंट दिखा रहा है।](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    मशीन की एजेंट गतिविधि क्लाउड तक पहुंचती है यह पुष्टि करने के लिए `fp events --agent-id <agent-id> --since 24h` का उपयोग करें।
  </Tab>
</Tabs>

कवरेज दृश्यों का उपयोग खोजने के लिए करें:

- मशीनें जिन्होंने कभी नवीनतम तैनाती को नहीं खींचा
- नामांकित मशीनें जिन्होंने रिपोर्टिंग गतिविधि बंद कर दी
- एक नीति जो गलत परिवेश या समूह को असाइन की गई है
- एक बाधित अपडेट के बाद संस्करण ड्रिफ्ट

इसे पुनः कनेक्ट किए बिना एक मशीन का नाम बदलें:

```bash
failproofai config --machine-label checkout-runner-03
```

स्थानीय स्थिति की जांच करें:

```bash
failproofai config --status
```

<Tip>
  लेबल का उपयोग करें जो कार्यभार और वातावरण की पहचान करें। ऑटोस्केलिंग या मशीन प्रतिस्थापन के बाद अकेले होस्टनाम अक्सर अपर्याप्त होते हैं।
</Tip>
