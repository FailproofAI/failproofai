Fleet coverage Cloud द्वारा निर्दिष्ट और प्रत्येक मशीन द्वारा अंतिम बार लागू की गई चीजों की तुलना करता है।

## एक मशीन की जांच करें

```bash
failproofai config --status
failproofai flush --wait --timeout 120
```

Cloud से:

```bash
fp fleet list
fp fleet diff
fp fleet show <machine-id>
```

`fp fleet` को signed-in session की आवश्यकता है, API key नहीं।

| Command | यह क्या करता है |
| --- | --- |
| `fp fleet list` | मशीनों और deployment state की सूची बनाएं |
| `fp fleet show <machine>` | एक मशीन की policy set दिखाएं |
| `fp fleet deploy <machine> --add <ref>` | एक policy जोड़ें या update करें |
| `fp fleet deploy <machine> --remove <id>` | एक policy हटाएं |
| `fp fleet deploy <machine> --set <ref>...` | पूरे set को बदलें |
| `fp fleet diff [machine]` | इच्छित और लागू किए गए versions की तुलना करें |
| `fp fleet history <machine>` | deployment generations की सूची बनाएं |
| `fp fleet rollback <machine> <generation>` | एक generation restore करें |
| `fp fleet rename <machine> "<label>"` | Cloud label बदलें |

<Warning>
  `--set` संपूर्ण policy set को बदल देता है। एक साधारण `--add <id>` नई policy को तुरंत लागू करता है। Shadow rollout के लिए `--add <id>:observe` का उपयोग करें।
</Warning>

## Observe करें, फिर enforce करें

```bash
fp fleet deploy ci-runner-01 --add prod-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add prod-guard:enforce
```

Observe mode वास्तविक policy का मूल्यांकन करता है और agent को ब्लॉक किए बिना non-allow decisions को record करता है।

## Machine identity

Machine ID स्थिर है और मशीन की पहचान करता है। Label केवल display के लिए है और बदल सकता है:

```bash
failproofai config --machine-label checkout-runner-03
fp fleet rename <machine-id> "Checkout runner 03"
```

Label बदलने से मशीन reconnect या re-key नहीं होती है।
