scope का उपयोग करके तय करें कि कौन स्थानीय नीति प्राप्त करता है:

| Scope | लागू होता है |
| --- | --- |
| `user` | इस मशीन पर आपके समर्थित agents |
| `project` | इस project में चल रहे agents |
| `local` | केवल Claude, स्थानीय project सेटिंग्स में |
| `all` | केवल अनइंस्टॉल |

```bash
failproofai policies add block-sudo --scope user
failproofai policies add block-rm-rf --scope project
```

Hermes और OpenClaw केवल user scope का समर्थन करते हैं। अधिकांश अन्य harnesses user और project को समर्थन करते हैं। Claude स्थानीय scope को भी समर्थन करता है। [Harnesses](/hi/reference/harnesses) देखें।

## नीति पैरामीटर

नीति सेटिंग्स मिलने वाले scope पर `policies-config.json` में रहती हैं। जब संभव हो, स्थानीय dashboard के **Policies → Configure** दृश्य का उपयोग करें।

एक पैरामीटर एक नीति से संबंधित है और यह तय करता है कि वह नीति कैसे निर्णय लेती है। उदाहरण के लिए, एक allow-list एक blocking नीति को ज्ञात-सुरक्षित commands या paths को स्वीकार करने के लिए बना सकता है।

कस्टम नीति फ़ाइलें `.failproofai/policies/` से स्वचालित रूप से, या स्पष्ट रूप से लोड की जा सकती हैं:

```bash
failproofai policies -i -c ./guards.mjs --scope project
```

स्पष्ट पथों को हटाएं:

```bash
failproofai policies -u -c
```

## फ़ाइलें

| फ़ाइल | उद्देश्य |
| --- | --- |
| `~/.failproofai/config.json` | मशीन और collector सेटिंग्स |
| `policies-config.json` | scope के लिए सक्षम नीतियां और पैरामीटर |
| `.failproofai/policies/*policies.mjs` | Convention-loaded नीतियां |
| `~/.failproofai/policies/packs/installed.json` | स्थापित packs और चयन |

स्थापित pack artifacts को सीधे संपादित न करें। पुनः स्थापित करें या सही किया गया release प्रकाशित करें।
