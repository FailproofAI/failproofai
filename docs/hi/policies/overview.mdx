एक नीति एजेंट कार्रवाई को देखती है और तीन निर्णयों में से एक देती है:

- `allow` जारी रखता है।
- `instruct` एजेंट को मार्गदर्शन देता है जब इसका हार्नेस इसका समर्थन करता है।
- `deny` कार्रवाई को ब्लॉक करता है।

ज्ञात, दोहराए जाने योग्य व्यवहार के लिए नीतियों का उपयोग करें: संरक्षित फ़ाइलों को हटाना, रहस्य उजागर करना, गलत शाखा में पुश करना, या उत्पादन अवसंरचना में परिवर्तन करना।

## इस मशीन के लिए नीतियां जोड़ें

सेटअप कोई नीति पैक नहीं चुनता। सेटअप के बाद Failproof AI पैक जोड़ें:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai policies
```

पैकेज में कोई विशेषाधिकार प्राप्त अंतर्निहित पैक नहीं है। हमारा वही तरीके से इंस्टॉल होता है जैसे किसी और का।

नीतियां स्थानीय फ़ाइल, प्रकाशित पैक, या क्लाउड असाइनमेंट से भी आ सकती हैं:

| स्रोत | इसे जोड़ें |
| --- | --- |
| स्थानीय फ़ाइल | `*policies.{js,mjs,ts}` को `.failproofai/policies/` के तहत रखें |
| कोई भी फ़ाइल पथ | `failproofai policies -i -c <path>` |
| प्रकाशित पैक | `failproofai policies add <owner>/<repo>` |
| क्लाउड | डैशबोर्ड में असाइन करें या `fp fleet deploy` के साथ |

`block-failproofai-commands` हमेशा चलता है और इसे बंद नहीं किया जा सकता। यह एजेंट को अपने स्वयं के प्रवर्तन को अक्षम करने से रोकता है।

## प्रवर्तन से पहले देखें

ऑब्जर्व मोड वास्तविक नीति चलाता है और रिकॉर्ड करता है कि इसने क्या किया होता, लेकिन एजेंट को ब्लॉक नहीं करता।

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

<Warning>
  एक साधारण `fp fleet deploy <machine> --add <id>` तुरंत प्रवर्तन करता है। छाया रोलआउट के लिए `:observe` जोड़ें।
</Warning>

एक नीति जो ऑब्जर्व मोड में समय समाप्त हो जाती है, एक allow रिकॉर्ड करती है, क्योंकि यह प्रवर्तन के दौरान क्या होता। केवल गैर-allow अवलोकित निर्णय रिकॉर्ड किए जाते हैं।

क्लाउड के बिना उपयोग किए गए पैक के लिए, इसे `failproofai publish --effect observe` के साथ प्रकाशित करें।
