एक कार्यशील नीति बनाएं, इसे स्थानीय रूप से परीक्षण करें, फिर इसे एक पैक के रूप में प्रकाशित करें।

## बनाएं और परीक्षण करें

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

`--init` एक नीति लिखता है जो पहले से ही `git push --force` को ब्लॉक करती है। इसे संपादित करें, अपने एजेंट से ब्लॉक की गई कार्रवाई का प्रयास करने के लिए कहें, और स्थानीय डैशबोर्ड में **Policies → Activity** देखें।

एक पैक नीति में शामिल हो सकता है:

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-refunds",
  description: "Refunds above the limit need a human",
  category: "Billing",
  defaultEnabled: true,
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) => {
    // return allow(), instruct(), or deny()
  },
});
```

`defaultEnabled` का डिफ़ॉल्ट मान `false` है।

## प्रकाशित करें

अपनी फाइलों को कमिट करें, फिर चलाएं:

```bash
failproofai publish
```

Publish नीति फाइल को खोजता है, इसे इंस्टॉलेशन के दौरान उपयोग किए गए लोडर के साथ सत्यापित करता है, और पैक संपत्ति को GitHub रिलीज़ में अपलोड करता है। यह `GITHUB_TOKEN`, `GH_TOKEN`, या `gh auth login` का उपयोग करता है।

रिपॉजिटरी सार्वजनिक होनी चाहिए क्योंकि इंस्टॉलेशन अनाम HTTPS का उपयोग करता है।

डिफ़ॉल्ट संस्करण वर्तमान कमिट का 12-वर्णीय SHA है। Publish एक गंदे पेड़ या Git के बाहर एक निर्देशिका को अस्वीकार करता है जब तक कि आप `--version` प्रदान न करें। `HEAD` पर एक टैग SHA को हरा देता है।

उपयोगकर्ता इसे इसके साथ इंस्टॉल करते हैं:

```bash
failproofai policies add owner/repo
```

## प्रेक्षण मोड में प्रकाशित करें

```bash
failproofai publish --effect observe
```

प्रेक्षण मोड वास्तविक नीति का मूल्यांकन करता है और गैर-allow निर्णयों को रिकॉर्ड करता है, लेकिन एजेंट को जारी रहने देता है। टाइमआउट को allow के रूप में रिकॉर्ड किया जाता है।

जब प्रेक्षित मिलान सही हों तो `--effect enforce` के साथ फिर से प्रकाशित करें।

## उपयोगी विकल्प

| फ़्लैग | प्रभाव |
| --- | --- |
| `--init [file]` | एक स्टार्टर नीति लिखें |
| `--repo <owner>/<repo>` | रिपॉजिटरी चुनें या बनाएं |
| `--version <version>` | कमिट-आधारित संस्करण को ओवरराइड करें |
| `--effect enforce|observe` | चुनें कि पैक ब्लॉक करता है या नहीं |
| `--dry-run` | प्रकाशित किए बिना बनाएं और सत्यापित करें |
| `--allow-private` | निजी रूप से प्रकाशित करें, यह जानते हुए कि `policies add` इसे इंस्टॉल नहीं कर सकता |

```bash
failproofai publish --dry-run
failproofai publish ./guards.mjs --repo me/guards --version 2.0.0
```

<Note>
  प्रकाशन के बाद GitHub विषय `failproofai-policies` जोड़ें ताकि [Policy Hub](https://befailproof.ai/policy-hub/) पैक को अनुक्रमित कर सके। CLI इसे आपके लिए सेट नहीं करता है।
</Note>

<Warning>
  किसी नीति का नाम बदलना मौजूदा चयनों के लिए एक महत्वपूर्ण परिवर्तन है। रिलीज़ के पार नाम स्थिर रखें।
</Warning>
