Cloud टेलीमेट्री का निरीक्षण करने, cloud-प्रबंधित प्रवर्तन (नीतियों, फ़्लीट परिनियोजन, सुरक्षा निर्णय) का प्रबंधन करने, और ऑडिट, निष्कर्ष, समस्याएं, अलर्ट, कुंजियां, उपयोगकर्ता, क्वेरी और सेटिंग्स का प्रबंधन करने के लिए `fp` का उपयोग करें। स्थानीय हुक, नीतियों, कैप्चर और मशीन नामांकन के लिए [`failproofai`](/hi/reference/failproof-cli) का उपयोग करें।

आप होस्ट किए गए कोड, LLM-judge और Jev मूल्यांककर्ता भी लेख सकते हैं और परिनियोजित कर सकते हैं, डैशबोर्ड प्रबंधित कर सकते हैं, भावना का निरीक्षण कर सकते हैं, और टर्मिनल से डैशबोर्ड सहायक का उपयोग कर सकते हैं।

जारी किए गए Cloud CLI को एक अलग उपकरण के रूप में स्थापित करें:

```bash
uv tool install fp-cloud-cli
fp version
```

## साइन इन करें

```bash
fp login
fp whoami
```

## सिंटैक्स

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

वैश्विक विकल्प कमांड से पहले आने चाहिए:

```bash
fp --json sessions --since 24h
```

टर्मिनल सहायता के लिए `fp COMMAND --help` या `fp COMMAND SUBCOMMAND --help` चलाएँ।

## CLI कमांड

### एक मूल्यांककर्ता लेखन करें

`fp evaluators` परिभाषाएँ लेखन करता है; `fp evals` परिणाम पढ़ता है। एक सक्षम प्रबंधित इंस्टेंस आवश्यक है (`fp evaluators instances`)। लेखन के लिए `evaluations:trigger` आवश्यक है; सत्र ड्राई-रन और स्कीमा प्रोफाइलिंग के लिए `events:read` भी आवश्यक है।

कोड एक प्रतिबंधित Python अभिव्यक्ति है। इसे `error_free.py` के रूप में सहेजें:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev बाइनरी और graded rubric:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
निर्माण मूल्यांककर्ता को सक्षम करता है। तैनाती एक नई अपरिवर्तनीय संस्करण बनाती है, फिर पुरानी सक्षम संस्करण को अक्षम करती है। एक विफल फॉलो-अप नई संस्करण को प्रकाशित छोड़ देता है: पुनः प्रयास करने से पहले `evaluators list --all` का निरीक्षण करें।
Judge ड्राई-रन Cloud द्वारा अस्वीकृत हैं। Jev ड्राई-रन मॉडल बजट खर्च करते हैं।
बैकफिल कोड, judge और Jev मूल्यांककर्ता को कवर करता है और अधिकतम 90 दिन स्वीकार करता है; यह केवल सत्रों को कतारबद्ध करता है कि एक मूल्यांककर्ता ने अभी तक स्कोर नहीं किया है। Judge और Jev बैकफिल मॉडल बजट खर्च करते हैं, इसलिए पहले `fp evaluators backfill --dry-run` चलाएँ।
मानव आउटपुट बनाने/तैनाती से पहले प्रति-सत्र ड्राई-रन परिणाम दिखाता है।
विफल पूर्वावलोकन समीक्षा के बाद स्पष्ट रूप से `--force` पास न करने तक लेखन को रोकते हैं।
</Warning>

AI ड्राफ्टिंग के लिए `fp login` आवश्यक है और create/deploy द्वारा स्वीकृत एक विनिर्देश लिखता है:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# समीक्षा करने से पहले ड्राफ्ट की कुंजी, स्रोत और स्थिति की समीक्षा करें।
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| कमांड | विकल्प / व्यवहार |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | पूर्ण स्रोत/envelope |
| `fp evaluators create` | `--key`, `--name`, `--version`, दोहराया `--label`, `--condition EXPR\|@file`, एक स्रोत, दोहराया `--dry-run-on`, `--disabled`, विफल पूर्वावलोकन के लिए स्पष्ट `--force` |
| `fp evaluators deploy KEY` | समान स्रोत झंडे; `--version`, `--backfill 7d` (किसी भी तरह, 1–90 दिन), `--force`; संख्यात्मक संस्करण स्वचालित-वृद्धि; KEY एक अनुपलब्ध spec-file `eval_key` आपूर्ति करता है |
| `fp evaluators draft "intent"` | सत्र; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | स्रोत झंडे या `--file`, दोहराया `--session` (अधिकतम 10); कोई नहीं = केवल संकलन |
| `fp evaluators enable\|disable KEY[@VERSION]` | टॉगल करें |
| `fp evaluators label KEY[@VERSION]` | दोहराया `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | प्रबंधित फ़्लीट/स्कीमा/कार्य का निरीक्षण करें |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; कोड, judge और Jev |

कोड झंडे `--code FILE|-`, `--result-kind score|metric|assertion`, `--timeout S` हैं। Judge झंडे `--judge --criteria TEXT`, दोहराया `--step` और `--threshold` हैं। Jev झंडे `--jev noul --instructions --true --false` या `--jev score --instructions` 3–5 अलग `--level` मान, सबसे पहले सबसे खराब हैं।
Judge/Jev को स्कोर की आवश्यकता है; threshold 0–1 हैं। बाइनरी judge चरण अस्वीकृत हैं।

Spec फाइलें ठीक `eval_key`, `display_name`, `eval_version`, `result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds` रखती हैं।
Judge/Jev `evaluator_source` एक JSON envelope स्ट्रिंग है। पंक्ति ids, सक्षम स्थिति या AI तर्क मेटाडेटा शामिल न करें। `--file` और असतत spec झंडे अनन्य हैं; तैनाती फाइल के संस्करण को ओवरराइड कर सकती है। आउटपुट फाइलें कभी अधिलेखित नहीं होती हैं।

### नए डैशबोर्ड नियंत्रण

सभी कमांड वैश्विक `--json` स्वीकार करते हैं। अज्ञात-मार्ग 404 exit 6 के साथ "not available on this FailproofAI Cloud yet" निकलते हैं। लापता-रिकॉर्ड 404 भी exit 6 के साथ निकलते हैं लेकिन रिपोर्ट करते हैं कि रिकॉर्ड नहीं पाया गया। सत्र-केवल कमांड HTTP से पहले कुंजी मोड को अस्वीकार करते हैं (exit 2)।

मानव कमांड सारांश और तालिकाएँ उपयोग करते हैं। कच्चे JSON निर्यात के लिए, वैश्विक `--json` पास करें या `--out FILE` के साथ सहेजें; अन्यथा सत्र और JSON क्वेरी निर्यात एक पठनीय दृश्य दिखाते हैं। CSV निर्यात पाइपिंग के लिए सादा CSV बने रहते हैं।

लेखन अनुमोदन प्रस्तावित परिवर्तन दिखाते हैं और एक टर्मिनल पर प्रेरित करते हैं। स्क्रिप्ट और `--json` अस्वीकार करते हैं जब तक कि `--approve` स्पष्ट न हो। मौजूदा JSON आकार अपरिवर्तित रहते हैं जब कोई artifact लौटाया नहीं जाता है।

### प्रमाणीकरण

| कमांड | उद्देश्य | विकल्प |
| --- | --- | --- |
| `fp login` | एक ब्राउज़र से या ईमेल किए गए एक-बार कोड के साथ साइन इन करें, और एक संगठन चुनें। `--email` सीधे कोड पर जाता है। | `--email`, `-e`; `--org`; `--force` |
| `fp logout` | सहेजे गए उपयोगकर्ता सत्र को रद्द करें और हटाएँ। | — |
| `fp whoami` | वर्तमान पहचान, प्रमाणीकरण मोड, संगठन और अनुमति दिखाएँ। | — |
| `fp version` | स्थापित CLI संस्करण दिखाएँ। | — |
| `fp help` | शीर्ष-स्तर कमांड सहायता दिखाएँ। | — |

```bash
fp login
fp login --email you@example.com --org reliability-team
fp whoami
```

एक टर्मिनल पर, `fp login` एक लिंक पर शुरू होता है, अपने ब्राउज़र या SSO के साथ साइन इन करने के लिए, और इसे खोलता है (SSH पर या कोई प्रदर्शन के बिना यह केवल इसे दिखाता है, और यह किसी भी डिवाइस से काम करता है); इसे अधिकृत करें और टर्मिनल अपने आप समाप्त हो जाता है। वह टर्मिनल आपके सभी संगठनों में आपका एक्सेस प्राप्त करता है जब तक सत्र समाप्त न हो, इसलिए केवल एक लिंक को अधिकृत करें जो आपने अभी मांगा है। यदि login एक अलग नेटवर्क पर शुरू हुआ, तो सत्र मौजूद होने के बाद आपको एक ईमेल मिलता है, और पृष्ठ चेतावनी देता है कि परिनियोजन कहाँ बता सकता है। ईमेल द्वारा एक 6-अंकीय कोड के लिए **Tab** दबाएँ, और वापस जाने के लिए फिर से Tab दबाएँ। `--email`, `--json` और कोई भी बिना टर्मिनल के कोड का उपयोग करता है।

### इवेंट्स

```text
fp events [OPTIONS]
```

व्यक्तिगत agent events सूचीबद्ध करता है। डिफ़ॉल्ट light feed कच्चे payloads को बाहर करता है; केवल एक सीमित जांच के लिए `--full` का उपयोग करें।

| विकल्प | विवरण |
| --- | --- |
| `--limit`, `-n <n>` | अधिकतम कुल पंक्तियाँ। डिफ़ॉल्ट: `50`। |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, या `7d`। |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC रेंज; `--since` को ओवरराइड करता है। |
| `--env <value>` | पर्यावरण फिल्टर; दोहराएँ या अल्पविराम से अलग करें। |
| `--event-type <value>` | Event-type फिल्टर; दोहराएँ या अल्पविराम से अलग करें। |
| `--agent-id <value>` | Agent फिल्टर; दोहराएँ या अल्पविराम से अलग करें। |
| `--session-id <value>` | सत्र फिल्टर; दोहराएँ या अल्पविराम से अलग करें। |
| `--search <text>` | Payload टेक्स्ट खोज; दोहराया जा सकता है, किसी भी शब्द के साथ मिलान। |
| `--order asc\|desc` | समय क्रम। डिफ़ॉल्ट: सबसे नई पहले। |
| `--all` | `--limit` तक स्वचालित-पृष्ठ। |
| `--cursor <token>` | एक अपारदर्शी cursor से फिर से शुरू करें। |
| `--page-size <n>` | `--all` के साथ प्रति request पंक्तियाँ; अधिकतम `200`। |
| `--full` | भारी event endpoint के माध्यम से कच्चे payloads शामिल करें। |
| `--fields <csv>` | केवल चयनित फ़ील्ड लौटाएँ; `payload` के लिए अनुरोध full mode सक्षम करता है। |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` **`--limit` तक** पृष्ठ करता है, जो डिफ़ॉल्ट रूप से **50** है — तो `--all` अकेले 50 पंक्तियों पर रुक जाता है। जब यह जल्दी रुकता है तो प्रतिक्रिया से फिर से शुरू करने के लिए एक `next_cursor` ले जाता है; `"next_cursor": null` का अर्थ है feed वास्तव में समाप्त हो गया था।
</Note>

#### ऑडिट create विकल्प

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| विकल्प | विवरण |
| --- | --- |
| `--file <path>` | JSON पर परिभाषा आधारित करें, या stdin के लिए `-` का उपयोग करें। स्पष्ट झंडे फाइल मान को ओवरराइड करते हैं। |
| `--description <text>` | विफलता प्रश्न या उद्देश्य बताएँ। |
| `--enabled` / `--disabled` | चालू या बंद होने पर scheduling शुरू करें। डिफ़ॉल्ट: सक्षम। |
| `--schedule-interval-secs <n>` | `3600`–`604800`। डिफ़ॉल्ट: `86400`। |
| `--schedule-anchor <timestamp>` | ISO 8601 रूप में निश्चित UTC phase। डिफ़ॉल्ट: अगले 09:00 UTC। |
| `--window-mode since_last\|fixed` | अंतिम पूर्ण विश्लेषण की गई विंडो के बाद जारी रखें या बार-बार एक rolling window का निरीक्षण करें। डिफ़ॉल्ट: `since_last`। |
| `--lookback-window-secs <n>` | `3600`–`7776000`। डिफ़ॉल्ट: `604800`। |
| `--scope '<json>'` | `environments`, `agent_ids`, या अन्य समर्थित scope फ़ील्ड द्वारा फिल्टर करें। |
| `--ignore-error-type <type>` | त्रुटि प्रकारों को बाहर निकालें; दोहराएँ या अल्पविराम से अलग करें। |
| `--llm` / `--no-llm` | Agentic analysis को सक्षम या अक्षम करें। डिफ़ॉल्ट: सक्षम। |
| `--top-k <n>` | `1`–`500` findings बनाए रखें। डिफ़ॉल्ट: `50`। |
| `--sensitivity low\|medium\|high` | Reporting sensitivity सेट करें। डिफ़ॉल्ट: `medium`। |
| `--channels '<json>'` | Notification channel array। |
| `--text <brief>` | Inline brief, अधिकतम 8,192 characters। |
| `--text-file <path>` | फाइल से brief पढ़ें; `--text` के साथ पारस्परिक रूप से एकमात्र। |
| `--url <https-url>` | एक public HTTPS संदर्भ जोड़ें; पाँच बार तक दोहराएँ। |

Creation के दौरान context शामिल करें जब पहला run इसकी आवश्यकता हो। Creation परिभाषा और context को कतारबद्ध run शुरू होने से पहले एक साथ प्रतिबद्ध करता है।

<Note>
  `fp audits run` asynchronous है। `fp audits runs NAME` को poll करें जब तक latest run सफल या विफल न हो जाए इसके findings को पढ़ने से पहले।
</Note>

### नीतियाँ

Cloud-प्रबंधित policy संस्करण। **सत्र-केवल** — यहाँ हर कमांड एक API key के तहत exit `2` करता है, किसी भी request से पहले, क्योंकि ये root-only write routes हैं जानबूझकर `/v1` से अनुपस्थित हैं।

| कमांड | उद्देश्य | विकल्प |
| --- | --- | --- |
| `fp policies list` | Policy संस्करण सूचीबद्ध करें, प्रत्येक के kind (`regex`, `jev`, `both`) और Jev check names के साथ। | `--json` |
| `fp policies show POLICY_ID` | एक policy दिखाएँ, इसके source और Jev checks के साथ। | — |
| `fp policies publish NAME [PATH]` | एक संस्करण Mint करें: JavaScript (`regex`, डिफ़ॉल्ट), Jev checks एक JSON file से declarations (`jev`), या दोनों, जहाँ JavaScript इसके अपने checks द्वारा reviewable है। | `--kind`; `--source`; `--semantic`; `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | इसे हर deployment में वापस जोड़ें जहाँ से इसे हटाया गया था, प्रत्येक पर एक नई generation mint करते हुए। | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | इसे उन सभी deployments से हटाएँ जहाँ यह चल रहा है, प्रत्येक पर एक नई generation mint करते हुए। | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | एक policy संस्करण हटाएँ। | `--yes`, `-y` |
| `fp policies test PATH` | एक नीति को locally एक synthetic context के विरुद्ध चलाएँ। प्रत्येक policy के `match` filter को लागू करता है, तो एक जो दिए गए event/tool को कवर नहीं करता है वह run के बजाय `skipped` के रूप में रिपोर्ट किया जाता है। | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | सहायक के साथ एक policy का ड्राफ्ट करें। `policies:write` की आवश्यकता है। | — |

### फ़्लीट

कौन सी मशीनें कौन सी policies चलाती हैं। **सत्र-केवल**, ऊपर के समान कारण।

| कमांड | उद्देश्य | विकल्प |
| --- | --- | --- |
| `fp fleet list` | नामांकित मशीनें और उनकी deployment generation सूचीबद्ध करें। | — |
| `fp fleet show MACHINE_ID` | Policy set जो एक मशीन वर्तमान में चलाती है, Jev mode जो FailproofAI Cloud इससे निकालता है, और policy errors जो इसने रिपोर्ट किए हैं। | — |
| `fp fleet deploy MACHINE_ID` | **मशीन के पूरे policy set को replace करें।** Plan को print करता है और interactive terminal पर केवल बिना `--json` के पूछता है। Jev एक मशीन के लिए चालू है जबकि एक `jev` या `both` policy इसे deploy किया जाता है; `:observe` के साथ trial करें। | `--add`; `--remove`; `--set`; `--target POLICY=INTEGRATION[/agt_ID]` (एक assignment को एक integration या एक agent तक scope करें; OR को दोहराएँ); `--all-agents POLICY` (वह scope साफ करें); `--create`; `--yes`, `-y` |
| `fp fleet diff MACHINE_ID` | एक मशीन को दूसरी deployment के विरुद्ध compare करें। | — |
| `fp fleet history MACHINE_ID` | एक मशीन के लिए पिछली deployments, प्रत्येक के Jev mode के साथ। | — |
| `fp fleet rollback MACHINE_ID GENERATION` | एक अतीत generation के policy set को एक नई generation के रूप में फिर से स्थापित करें। | `--yes`, `-y` |
| `fp fleet rename MACHINE_ID` | एक मशीन को एक पठनीय नाम दें। | आवश्यक `--name` |

## वैश्विक झंडे

| झंडा | विवरण |
| --- | --- |
| `--json` | मशीन-पठनीय JSON उत्सर्जित करें। Errors विफल request के `request_id` को शामिल करते हैं। |
| `--base-url <url>` | एक self-hosted या development dashboard का उपयोग करें। |
| `--org <slug>` | इस invocation के लिए एक संगठन चुनें। |
| `--token <token>` | सहेजे गए user-session token को override करें। |
| `--api-key <key>` | Automation के साथ एक API key authenticate करें; कभी नहीं saved। |
| `--timeout <seconds>` | HTTP timeout; सकारात्मक होना चाहिए। डिफ़ॉल्ट: `30`। |
| `--quiet`, `-q` | stderr पर status output को suppress करें। |
| `--no-color` | Colored output अक्षम करें। |
| `--insecure` / `--secure` | TLS certificate verification को अक्षम या restore करें। |
| `--version` | Unboxed version को print करें और exit करें। |
| `--help`, `-h` | Help दिखाएँ। |

`--api-key` automation के लिए है। Login, organization switching और assistant commands को एक user session की आवश्यकता है।

  इन के `AGENTEYE_*` spellings **`fp` द्वारा read नहीं किए जाते** और कभी नहीं थे — CLI `FP_*` declare करता है (`fp_cli/app.py`), और एक unknown variable एक error नहीं है। `AGENTEYE_DASHBOARD_URL` setting CLI को retarget नहीं करता; यह ignore किया जाता है और command silently saved dashboard के विरुद्ध चलता है।
