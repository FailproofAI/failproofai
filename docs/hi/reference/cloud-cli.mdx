Cloud टेलीमेट्री का निरीक्षण करने, cloud-managed enforcement (policies, fleet deployments, guardrail decisions) प्रबंधित करने, और audits, findings, issues, alerts, keys, users, queries, और settings प्रबंधित करने के लिए `fp` का उपयोग करें। Local hooks, policies, capture, और machine enrollment के लिए [`failproofai`](/hi/reference/failproof-cli) का उपयोग करें।

आप hosted code, LLM-judge और Jev evaluators भी बना और deploy कर सकते हैं, dashboards प्रबंधित कर सकते हैं, sentiment का निरीक्षण कर सकते हैं, और terminal से dashboard assistant का उपयोग कर सकते हैं।

Released Cloud CLI को एक isolated tool के रूप में install करें:

```bash
uv tool install fp-cloud-cli
fp version
```

## Sign in करें

```bash
fp login
fp whoami
```

## Syntax

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Global options को command से पहले आना चाहिए:

```bash
fp --json sessions --since 24h
```

Terminal help के लिए `fp COMMAND --help` या `fp COMMAND SUBCOMMAND --help` चलाएं।

## CLI commands

### Evaluator बनाएं

`fp evaluators` definitions बनाता है; `fp evals` results पढ़ता है। एक enabled managed instance आवश्यक है (`fp evaluators instances`)। Authoring के लिए `evaluations:trigger` आवश्यक है; session dry-runs और schema profiling को भी `events:read` की आवश्यकता है।

Code एक restricted Python expression है। इसे `error_free.py` के रूप में save करें:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev binary और graded rubric:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
Creation evaluator को enable करता है। Deploy एक नया immutable version बनाता है, फिर पुराने enabled versions को disable करता है। एक failed follow-up नए version को published रखता है: retry करने से पहले `evaluators list --all` inspect करें।
Judge dry-runs को Cloud से refuse किया जाता है। Jev dry-runs model budget खर्च करते हैं।
Backfill code, judge और Jev evaluators को cover करता है और अधिकतम 90 days स्वीकार करता है; यह केवल sessions को queue करता है जिन्हें evaluator ने अभी तक score नहीं किया है। Judge और Jev backfills model budget खर्च करते हैं, इसलिए पहले `fp evaluators backfill --dry-run` चलाएं।
Human output creation/deploying से पहले per-session dry-run results दिखाता है।
Failed previews write को review के बाद explicitly `--force` pass करने तक रोकते हैं।
</Warning>

AI drafting के लिए `fp login` आवश्यक है और एक spec लिखता है जो create/deploy द्वारा स्वीकार किया जाता है:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review करें draft के key, source और condition को enable करने से पहले।
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Command | Options / behavior |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Full source/envelope |
| `fp evaluators create` | `--key`, `--name`, `--version`, repeated `--label`, `--condition EXPR\|@file`, one source, repeated `--dry-run-on`, `--disabled`, explicit `--force` for failed previews |
| `fp evaluators deploy KEY` | Same source flags; `--version`, `--backfill 7d` (any kind, 1–90 days), `--force`; numeric versions auto-increment; KEY supplies a missing spec-file `eval_key` |
| `fp evaluators draft "intent"` | Session; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Source flags or `--file`, repeated `--session` (maximum 10); none = compile only |
| `fp evaluators enable\|disable KEY[@VERSION]` | Toggle |
| `fp evaluators label KEY[@VERSION]` | Repeated `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | Inspect managed fleet/schema/jobs |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; code, judge और Jev |

Code flags `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S` हैं। Judge flags `--judge --criteria TEXT`, repeated `--step` और
`--threshold` हैं। Jev flags `--jev noul --instructions --true --false` या
`--jev score --instructions` with 3–5 distinct `--level` values, worst first हैं।
Judge/Jev को score की आवश्यकता है; thresholds 0–1 हैं। Binary judge steps को reject किया जाता है।

Spec files में exactly `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds` होते हैं।
Judge/Jev `evaluator_source` एक JSON envelope string है। Row ids,
enabled state, या AI reasoning metadata शामिल न करें। `--file` और discrete spec flags
exclusive हैं; deploy file के version को override कर सकता है। Output files कभी overwrite नहीं होती हैं।

### नए dashboard controls

सभी commands global `--json` स्वीकार करते हैं। Unknown-route 404s 6 के साथ exit करते हैं with "not available
on this FailproofAI Cloud yet"। Missing-record 404s भी 6 के साथ exit करते हैं लेकिन रिपोर्ट करते हैं कि
record नहीं मिला। Session-only commands HTTP से पहले key mode को deny करते हैं (exit 2)।

Human commands summaries और tables का उपयोग करते हैं। Raw JSON exports के लिए, global
`--json` pass करें या `--out FILE` से save करें; अन्यथा session और JSON query exports एक readable view दिखाते हैं। CSV exports plain CSV बने रहते हैं piping के लिए।

| Commands | Options / notes |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | Create `--name`, `--description`, `--file` definition; update unmentioned fields को preserve करता है |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | Add `--query ID --chart TYPE --title`; config/geometry या layout `--file` के through |
| `fp sessions show\|export\|history\|re-evaluate ID` | Export `--out`; history evaluation history है |
| `fp sessions import FILE...` | Claude Code transcripts, Codex rollouts या event JSONL (`.gz` ok); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; `events:add` की आवश्यकता है |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; list `--limit`; messages `--session-id` |
| `fp query compose "question"` | Session; `--run` |
| `fp query export [ID]` | Or `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Issues can `--create --title --summary` या `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; update `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | Session; आपके org के events से policy draft करता है, कभी publish नहीं करता |
| `fp policies backtest [FILE_OR_ID]` | Session; regex module को replay करता है; `jev`/`both` (published, या `--semantic checks.json`) estimate for free, `--run [--sample N]` Jev allowance खर्च करता है; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | Session; क्या एक policy इस issue को prevent कर सकता है |
| `fp issues facets` | Values जो inbox filters ले सकते हैं, counts के साथ |
| `fp agent brief` | Session; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | Session; omitted slug derive करता है, org को switch नहीं करता |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | Permission sets; create `--name --permission`; update replace `--permission` या merge `--add/--remove`; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | Deletion by id |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` को API key की आवश्यकता है; plan (offers और trial) और claim को signed-in session की आवश्यकता है |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 tokens |
| `fp otel status\|enable\|disable` | Cloud org ingest switch, local capture नहीं |
| `fp slack status\|disconnect` | Session |

`fp agent ask` artifact SQL को `queries:run` के through tables/stats के रूप में render करता है।
Write approvals proposed change दिखाता है और terminal पर prompt करता है। Scripts और
`--json` decline करते हैं जब तक `--approve` explicit न हो। Existing JSON shapes
unchanged रहते हैं जब कोई artifact return न हो।

### Events

```text
fp events [OPTIONS]
```

Individual agent events को list करता है। Default light feed raw payloads को exclude करता है; `--full` को केवल एक bounded investigation के लिए use करें।

| Option | Description |
| --- | --- |
| `--limit`, `-n <n>` | Maximum total rows। Default: `50`। |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, या `7d`। |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC range; `--since` को override करता है। |
| `--env <value>` | Environment filter; repeat या comma-separate values। |
| `--event-type <value>` | Event-type filter; repeat या comma-separate values। |
| `--agent-id <value>` | Agent filter; repeat या comma-separate values। |
| `--session-id <value>` | Session filter; repeat या comma-separate values। |
| `--search <text>` | Payload text search; repeatable, any term matching के साथ। |
| `--order asc\|desc` | Time order। Default: newest first। |
| `--all` | Auto-paginate up to `--limit`। |
| `--cursor <token>` | एक opaque cursor से resume करें। |
| `--page-size <n>` | `--all` के साथ rows per request; maximum `200`। |
| `--full` | Heavier event endpoint के through raw payloads शामिल करें। |
| `--fields <csv>` | केवल selected fields return करें; `payload` को request करने से full mode enable होता है। |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` **up to `--limit`** paginate करता है, जो **50** को default करता है — तो `--all` अपने आप में 50 rows पर रुकता है। जब यह जल्दी रुकता है तो response एक
  `next_cursor` से resume करने के लिए carry करता है; `"next_cursor": null` का मतलब है feed सच में exhausted था।
</Note>

#### Audit create options

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Option | Description |
| --- | --- |
| `--file <path>` | Definition को JSON पर base करें, या stdin के लिए `-` का उपयोग करें। Explicit flags file values को override करते हैं। |
| `--description <text>` | Failure question या purpose को state करें। |
| `--enabled` / `--disabled` | Scheduling को on या off शुरू करें। Default: enabled। |
| `--schedule-interval-secs <n>` | `3600`–`604800`। Default: `86400`। |
| `--schedule-anchor <timestamp>` | Fixed UTC phase in ISO 8601 form। Default: next 09:00 UTC। |
| `--window-mode since_last\|fixed` | Last fully analyzed window के बाद continue करें या repeatedly एक rolling window को inspect करें। Default: `since_last`। |
| `--lookback-window-secs <n>` | `3600`–`7776000`। Default: `604800`। |
| `--scope '<json>'` | `environments`, `agent_ids`, या other supported scope fields द्वारा filter करें। |
| `--ignore-error-type <type>` | Error types को exclude करें; repeat या comma-separate करें। |
| `--llm` / `--no-llm` | Agentic analysis को enable या disable करें। Default: enabled। |
| `--top-k <n>` | `1`–`500` findings retain करें। Default: `50`। |
| `--sensitivity low\|medium\|high` | Reporting sensitivity को set करें। Default: `medium`। |
| `--channels '<json>'` | Notification channel array। |
| `--text <brief>` | Inline brief, maximum 8,192 characters। |
| `--text-file <path>` | Brief को एक file से read करें; `--text` के साथ mutually exclusive। |
| `--url <https-url>` | एक public HTTPS reference add करें; up to five times repeat करें। |

Creation के दौरान context को शामिल करें जब first run को इसकी आवश्यकता हो। Creation definition और context को एक साथ commit करता है queued run शुरू होने से पहले।

<Note>
  `fp audits run` asynchronous है। Poll `fp audits runs NAME` करें जब तक latest run succeed या fail न हो जाए इससे पहले कि आप उसकी findings को read करें।
</Note>

### Policies

Cloud-managed policy versions। **Session-only** — यहां हर command एक API key के तहत `2` को exit करता है, किसी भी request से पहले, क्योंकि ये root-only write routes deliberately `/v1` से absent हैं।

| Command | Purpose | Options |
| --- | --- | --- |
