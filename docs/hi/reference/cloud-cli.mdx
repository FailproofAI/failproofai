`fp` का उपयोग Cloud टेलीमेट्री का निरीक्षण करने और ऑडिट, फाइंडिंग, समस्याएं, अलर्ट, कुंजियाँ, उपयोगकर्ता, क्वेरी और सेटिंग्स को प्रबंधित करने के लिए करें। स्थानीय हुक, नीतियां, कैप्चर और मशीन नामांकन के लिए [`failproofai`](/hi/reference/failproof-cli) का उपयोग करें।

रिलीज़ किए गए Cloud CLI को एक अलग उपकरण के रूप में स्थापित करें:

```bash
uv tool install fp-cloud-cli
fp version
```

## साइन इन करें

```bash
fp login
fp whoami
```

## सिंटैक्स

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

ग्लोबल विकल्प कमांड से पहले आने चाहिए:

```bash
fp --json sessions --since 24h
```

टर्मिनल सहायता के लिए `fp COMMAND --help` या `fp COMMAND SUBCOMMAND --help` चलाएं।

## CLI कमांड

### प्रमाणीकरण

| कमांड | उद्देश्य | विकल्प |
| --- | --- | --- |

| `fp logout` | सहेजे गए उपयोगकर्ता सत्र को रद्द करें और हटाएं। | — |
| `fp whoami` | वर्तमान पहचान, प्रमाणीकरण मोड, संगठन और अनुमतियां दिखाएं। | — |
| `fp version` | स्थापित CLI संस्करण दिखाएं। | — |
| `fp help` | शीर्ष-स्तरीय कमांड सहायता दिखाएं। | — |

```bash
fp login --email you@example.com --org reliability-team
fp whoami
```

### घटनाएं

```text
fp events [OPTIONS]
```

व्यक्तिगत एजेंट घटनाओं को सूचीबद्ध करता है। डिफ़ॉल्ट light फीड raw पेलोड को बाहर करता है; `--full` का उपयोग केवल सीमित जांच के लिए करें।

| विकल्प | विवरण |
| --- | --- |
| `--limit`, `-n <n>` | अधिकतम कुल पंक्तियां। डिफ़ॉल्ट: `50`। |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, या `7d`। |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC रेंज; `--since` को ओवरराइड करता है। |
| `--env <value>` | पर्यावरण फ़िल्टर; दोहराएं या कॉमा से अलग करें। |
| `--event-type <value>` | ईवेंट-प्रकार फ़िल्टर; दोहराएं या कॉमा से अलग करें। |
| `--agent-id <value>` | एजेंट फ़िल्टर; दोहराएं या कॉमा से अलग करें। |
| `--session-id <value>` | सत्र फ़िल्टर; दोहराएं या कॉमा से अलग करें। |
| `--search <text>` | पेलोड टेक्स्ट खोज; दोहराई जा सकती है, कोई भी शब्द मेल खाता है। |
| `--order asc\|desc` | समय क्रम। डिफ़ॉल्ट: सबसे नया पहले। |
| `--all` | `--limit` तक स्वचालित पेजिनेशन। |
| `--cursor <token>` | अपारदर्शी कर्सर से फिर से शुरू करें। |
| `--page-size <n>` | `--all` के साथ प्रति अनुरोध पंक्तियां; अधिकतम `200`। |
| `--full` | भारी इवेंट एंडपॉइंट के माध्यम से raw पेलोड शामिल करें। |
| `--fields <csv>` | केवल चयनित फ़ील्ड लौटाएं; `payload` का अनुरोध full मोड को सक्षम करता है। |

```bash
fp events --session-id <session-id> --order asc --all
fp --json events --full --session-id <session-id> --all
```

### API कुंजियां

| कमांड | उद्देश्य | विकल्प |
| --- | --- | --- |
| `fp keys list` | संगठन कुंजियों को सूचीबद्ध करें। | `--show-id`; `--fields <csv>` |
| `fp keys show NAME` | एक कुंजी और इसकी अनुदान दिखाएं। | — |
| `fp keys create NAME` | एक कुंजी बनाएं और इसका रहस्य एक बार प्रकट करें। | `--permission-set`; `--add`; `--remove` |
| `fp keys update NAME` | अनुमति सेट को बदलें या अनुदान को समायोजित करें। | `--permission-set`; `--add`; `--remove`; `--yes`, `-y` |
| `fp keys regenerate NAME` | रहस्य को घुमाएं और प्रतिस्थापन को एक बार प्रकट करें। | `--yes`, `-y` |
| `fp keys disable NAME` | एक कुंजी को स्थायी रूप से रद्द करें। | `--yes`, `-y` |

अनुमति टोकन `resource:action` का उपयोग करते हैं, जैसे `events:add`। `--add` को दोहराएं, टोकन को कॉमा से अलग करें, या `events:read.add` जैसी डॉटेड कार्रवाई का उपयोग करें।

#### ऑडिट बनाएं विकल्प

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| विकल्प | विवरण |
| --- | --- |
| `--file <path>` | परिभाषा को JSON पर आधारित करें, या stdin के लिए `-` का उपयोग करें। स्पष्ट फ्लैग फ़ाइल मान को ओवरराइड करते हैं। |
| `--description <text>` | विफलता प्रश्न या उद्देश्य बताएं। |
| `--enabled` / `--disabled` | शेड्यूलिंग को चालू या बंद से शुरू करें। डिफ़ॉल्ट: सक्षम। |
| `--schedule-interval-secs <n>` | `3600`–`604800`। डिफ़ॉल्ट: `86400`। |
| `--schedule-anchor <timestamp>` | ISO 8601 रूप में निश्चित UTC चरण। डिफ़ॉल्ट: अगला 09:00 UTC। |
| `--window-mode since_last\|fixed` | अंतिम पूर्ण रूप से विश्लेषण की गई विंडो के बाद जारी रखें या बार-बार एक रोलिंग विंडो का निरीक्षण करें। डिफ़ॉल्ट: `since_last`। |
| `--lookback-window-secs <n>` | `3600`–`7776000`। डिफ़ॉल्ट: `604800`। |
| `--scope '<json>'` | `environments`, `agent_ids`, या अन्य समर्थित स्कोप फ़ील्ड द्वारा फ़िल्टर करें। |
| `--ignore-error-type <type>` | त्रुटि प्रकारों को बाहर करें; दोहराएं या कॉमा से अलग करें। |
| `--llm` / `--no-llm` | एजेंटिक विश्लेषण को सक्षम या अक्षम करें। डिफ़ॉल्ट: सक्षम। |
| `--top-k <n>` | `1`–`500` फाइंडिंग रखें। डिफ़ॉल्ट: `50`। |
| `--sensitivity low\|medium\|high` | रिपोर्टिंग संवेदनशीलता सेट करें। डिफ़ॉल्ट: `medium`। |
| `--channels '<json>'` | सूचना चैनल सरणी। |
| `--text <brief>` | इनलाइन संक्षिप्त, अधिकतम 8,192 वर्ण। |
| `--text-file <path>` | फ़ाइल से संक्षिप्त पढ़ें; `--text` के साथ पारस्परिक रूप से एक्सक्लूसिव। |
| `--url <https-url>` | एक सार्वजनिक HTTPS संदर्भ जोड़ें; पांच बार तक दोहराएं। |

निर्माण के दौरान संदर्भ शामिल करें जब पहले चलाने को इसकी आवश्यकता हो। निर्माण परिभाषा और संदर्भ को कतार में डाली गई चलाने से पहले एक साथ कमिट करता है।

<Note>
  `fp audits run` अतुल्यकालिक है। `fp audits runs NAME` तक पोल करें जब तक कि नवीनतम चलाना सफल या विफल न हो जाए इससे पहले इसकी फाइंडिंग पढ़ें।
</Note>

### समस्याएं

| कमांड | उद्देश्य | विकल्प |
| --- | --- | --- |
| `fp issues list` | समस्याओं को सूचीबद्ध करें। | `--state`; `--alert-id`; `--limit`, `-n`; `--show-id` |
| `fp issues count` | खुली या चयनित समस्या स्थितियों को गिनें। | `--state` |
| `fp issues show INCIDENT_ID` | समस्या विवरण, टिप्पणी, सदस्य और कार्यकलाप दिखाएं। | — |
| `fp issues open` | एक मैनुअल या अलर्ट-लिंक्ड समस्या खोलें। | आवश्यक `--summary`; वैकल्पिक `--title`, `--alert-id`, `--severity` |
| `fp issues ack INCIDENT_ID` | एक समस्या को स्वीकार करें। | — |
| `fp issues assign INCIDENT_ID` | असाइन करने वाले को प्रतिस्थापित करें; उन्हें साफ करने के लिए विकल्प को छोड़ दें। | दोहराई जा सकने वाली `--assignee` |
| `fp issues resolve INCIDENT_ID` | एक समस्या को हल करें। | `--yes`, `-y` |
| `fp issues comment-list INCIDENT_ID` | टिप्पणियों को सूचीबद्ध करें। | — |
| `fp issues comment-add INCIDENT_ID` | एक टिप्पणी जोड़ें। | `--body`, `--file` में से बिल्कुल एक |
| `fp issues comment-delete INCIDENT_ID COMMENT_ID` | एक टिप्पणी हटाएं। | `--yes`, `-y` |
| `fp issues subscribers INCIDENT_ID` | सदस्यों को सूचीबद्ध करें। | — |
| `fp issues subscribe INCIDENT_ID` | अपने आप या किसी अन्य ऑपरेटर को सदस्य बनाएं। | `--email` |
| `fp issues unsubscribe INCIDENT_ID` | एक सदस्यता को हटाएं। | `--email` |

मान्य समस्या स्थितियां `firing`, `acknowledged`, और `resolved` हैं। स्टैंडअलोन समस्या गंभीरताएं `info`, `warning`, और `critical` हैं।

## ग्लोबल फ्लैग

| फ्लैग | विवरण |
| --- | --- |
| `--json` | मशीन-पठनीय JSON उत्सर्जित करें। |
| `--base-url <url>` | स्व-होस्ट किए गए या विकास डैशबोर्ड का उपयोग करें। |
| `--org <slug>` | इस आह्वान के लिए एक संगठन चुनें। |
| `--token <token>` | सहेजे गए उपयोगकर्ता-सत्र टोकन को ओवरराइड करें। |
| `--api-key <key>` | API कुंजी के साथ स्वचालन को प्रमाणित करें; कभी सहेजा नहीं जाता। |
| `--timeout <seconds>` | HTTP टाइमआउट; सकारात्मक होना चाहिए। डिफ़ॉल्ट: `30`। |
| `--quiet`, `-q` | stderr पर स्थिति आउटपुट को दबाएं। |
| `--no-color` | रंगीन आउटपुट को अक्षम करें। |
| `--insecure` / `--secure` | TLS प्रमाणपत्र सत्यापन को अक्षम या पुनः स्थापित करें। |
| `--version` | अनबॉक्स किया गया संस्करण प्रिंट करें और बाहर निकलें। |
| `--help`, `-h` | सहायता दिखाएं। |

`--api-key` स्वचालन के लिए है। लॉगिन, संगठन स्विचिंग, और सहायक कमांड के लिए उपयोगकर्ता सत्र की आवश्यकता है।

<Warning>
  कमांड जो हटाते हैं, रद्द करते हैं, दबाते हैं, हल करते हैं, या कॉन्फ़िगरेशन को बदलते हैं डिफ़ॉल्ट रूप से प्रॉम्प्ट करते हैं। सक्रिय संगठन और लक्ष्य को सत्यापित करने के बाद ही `--yes` का उपयोग करें।
</Warning>
