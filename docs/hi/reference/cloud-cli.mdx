`fp` का उपयोग Cloud टेलीमेट्री का निरीक्षण करने, क्लाउड-प्रबंधित प्रवर्तन (नीतियां, फ्लीट तैनातियां, गार्डरेल निर्णय) प्रबंधित करने, और ऑडिट, निष्कर्ष, समस्याएं, अलर्ट, कुंजियां, उपयोगकर्ता, क्वेरीज और सेटिंग्स प्रबंधित करने के लिए करें। स्थानीय हुक, नीतियां, कैप्चर और मशीन नामांकन के लिए [`failproofai`](/hi/reference/failproof-cli) का उपयोग करें।

रिलीज़ किए गए Cloud CLI को एक अलग-थलग टूल के रूप में इंस्टॉल करें:

```bash
uv tool install fp-cloud-cli
fp version
```

## साइन इन करें

```bash
fp login
fp whoami
```

## सिंटैक्स

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

ग्लोबल विकल्प कमांड से पहले आने चाहिए:

```bash
fp --json sessions --since 24h
```

टर्मिनल सहायता के लिए `fp COMMAND --help` या `fp COMMAND SUBCOMMAND --help` चलाएं।

```bash

```

### ईवेंट

```text
fp events [OPTIONS]
```

अलग-अलग एजेंट ईवेंट सूचीबद्ध करता है। डिफ़ॉल्ट लाइट फीड कच्चे पेलोड को बाहर करता है; `--full` का उपयोग केवल सीमित जांच के लिए करें।

| विकल्प | विवरण |
| --- | --- |
| `--limit`, `-n <n>` | अधिकतम कुल पंक्तियां। डिफ़ॉल्ट: `50`। |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, या `7d`। |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC रेंज; `--since` को ओवरराइड करता है। |
| `--env <value>` | पर्यावरण फ़िल्टर; मान दोहराएं या अल्पविराम से अलग करें। |
| `--event-type <value>` | ईवेंट-प्रकार फ़िल्टर; दोहराएं या अल्पविराम से अलग करें। |
| `--agent-id <value>` | एजेंट फ़िल्टर; दोहराएं या अल्पविराम से अलग करें। |
| `--session-id <value>` | सेशन फ़िल्टर; दोहराएं या अल्पविराम से अलग करें। |
| `--search <text>` | पेलोड टेक्स्ट खोज; दोहराए जाने योग्य, किसी भी शब्द से मेल खाता है। |
| `--order asc\|desc` | समय क्रम। डिफ़ॉल्ट: सबसे नया पहले। |
| `--all` | `--limit` तक स्वचालित-पेजिनेट करें। |
| `--cursor <token>` | एक अपारदर्शी कर्सर से फिर से शुरू करें। |
| `--page-size <n>` | `--all` के साथ प्रति अनुरोध पंक्तियां; अधिकतम `200`। |
| `--full` | भारी ईवेंट एंडपॉइंट के माध्यम से कच्चे पेलोड शामिल करें। |
| `--fields <csv>` | केवल चयनित फ़ील्ड लौटाएं; `payload` अनुरोध करने से पूर्ण मोड सक्षम होता है। |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` **`--limit` तक** पेजिनेट करता है, जो **50** को डिफ़ॉल्ट करता है — तो `--all` अपने आप 50 पंक्तियों पर रुक जाता है। जब यह जल्दी रुकता है तो प्रतिक्रिया एक `next_cursor` ले जाती है जहां से फिर से शुरू करने के लिए; `"next_cursor": null` का मतलब है कि फीड वास्तव में समाप्त हो गया था।
</Note>

### API कुंजियां

| कमांड | उद्देश्य | विकल्प |
| --- | --- | --- |
| `fp keys list` | संगठन कुंजियां सूचीबद्ध करें। | `--show-id`; `--fields <csv>` |
| `fp keys show NAME` | एक कुंजी और उसके अनुदान दिखाएं। | — |
| `fp keys create NAME` | एक कुंजी बनाएं और इसका रहस्य एक बार प्रकट करें। | `--permission-set`; `--add`; `--remove` |
| `fp keys update NAME` | अनुमति सेट को प्रतिस्थापित करें या अनुदान को समायोजित करें। | `--permission-set`; `--add`; `--remove`; `--yes`, `-y` |
| `fp keys regenerate NAME` | रहस्य को घुमाएं और प्रतिस्थापन एक बार प्रकट करें। | `--yes`, `-y` |
| `fp keys disable NAME` | एक कुंजी को स्थायी रूप से रद्द करें। | `--yes`, `-y` |

अनुमति टोकन `resource:action` का उपयोग करते हैं, जैसे `events:add`। `--add` को दोहराएं, अल्पविराम से अलग करें, या डॉटेड क्रियाओं का उपयोग करें जैसे `events:read.add`।

| `fp audits resolve FINDING_ID` | एक निष्कर्ष को भविष्य के दमन के बिना ठीक के रूप में चिह्नित करें। | `--yes`, `-y` |
| `fp audits reopen FINDING_ID` | एक निष्कर्ष को लाइव कतार में लौटाएं और दमन को साफ़ करें। | — |
| `fp audits assign FINDING_ID` | निष्कर्ष मालिक सेट करें। | आवश्यक `--to <email>` |

#### ऑडिट बनाएं विकल्प

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| विकल्प | विवरण |
| --- | --- |
| `--file <path>` | JSON पर परिभाषा को आधार करें, या stdin के लिए `-` का उपयोग करें। स्पष्ट फ़्लैग फ़ाइल मान को ओवरराइड करते हैं। |
| `--description <text>` | विफलता प्रश्न या उद्देश्य बताएं। |
| `--enabled` / `--disabled` | शेड्यूलिंग को चालू या बंद करने से शुरू करें। डिफ़ॉल्ट: सक्षम। |
| `--schedule-interval-secs <n>` | `3600`–`604800`। डिफ़ॉल्ट: `86400`। |
| `--schedule-anchor <timestamp>` | ISO 8601 फॉर्म में निश्चित UTC चरण। डिफ़ॉल्ट: अगला 09:00 UTC। |
| `--window-mode since_last\|fixed` | अंतिम पूरी तरह से विश्लेषण किए गए विंडो के बाद जारी रखें या बार-बार एक रोलिंग विंडो का निरीक्षण करें। डिफ़ॉल्ट: `since_last`। |
| `--lookback-window-secs <n>` | `3600`–`7776000`। डिफ़ॉल्ट: `604800`। |
| `--scope '<json>'` | `environments`, `agent_ids`, या अन्य समर्थित स्कोप फ़ील्ड द्वारा फ़िल्टर करें। |
| `--ignore-error-type <type>` | त्रुटि प्रकारों को बाहर करें; दोहराएं या अल्पविराम से अलग करें। |
| `--llm` / `--no-llm` | एजेंटिक विश्लेषण को सक्षम या अक्षम करें। डिफ़ॉल्ट: सक्षम। |
| `--top-k <n>` | `1`–`500` निष्कर्ष बनाए रखें। डिफ़ॉल्ट: `50`। |
| `--sensitivity low\|medium\|high` | रिपोर्टिंग संवेदनशीलता सेट करें। डिफ़ॉल्ट: `medium`। |
| `--channels '<json>'` | सूचना चैनल सरणी। |
| `--text <brief>` | इनलाइन संक्षिप्त, अधिकतम 8,192 वर्ण। |
| `--text-file <path>` | फ़ाइल से संक्षिप्त पढ़ें; `--text` के साथ परस्पर अनन्य। |
| `--url <https-url>` | एक सार्वजनिक HTTPS संदर्भ जोड़ें; पांच बार तक दोहराएं। |

निर्माण के दौरान संदर्भ शामिल करें जब पहले रन को इसकी आवश्यकता हो। निर्माण परिभाषा और संदर्भ को एक साथ प्रतिबद्ध करता है कि कतार में डाले गए रन से पहले।

<Note>
  `fp audits run` अतुल्यकालिक है। अपने निष्कर्षों को पढ़ने से पहले `fp audits runs NAME` को तब तक पोल करें जब तक नवीनतम रन सफल या विफल न हो।
</Note>

### नीतियां

Cloud-प्रबंधित नीति संस्करण। **सेशन-केवल** — यहां हर कमांड एक API कुंजी के तहत `2` से बाहर निकलता है, किसी भी अनुरोध से पहले, क्योंकि ये रूट-केवल लेखन मार्ग हैं जानबूझकर `/v1` से अनुपस्थित हैं।

| कमांड | उद्देश्य | विकल्प |
| --- | --- | --- |
| `fp policies list` | नीति संस्करण सूचीबद्ध करें। | `--json` |
| `fp policies show POLICY_ID` | एक नीति दिखाएं, इसके स्रोत के साथ। | — |
| `fp policies publish NAME PATH` | एक स्थानीय `.mjs` से एक संस्करण बनाएं। | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | इसे हर तैनाती में वापस जोड़ें जहां से इसे हटाया गया था, प्रत्येक पर एक नई पीढ़ी बनाते हुए। | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | इसे हर तैनाती से निकालें जो इसे ले जाती है, प्रत्येक पर एक नई पीढ़ी बनाते हुए। | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | एक नीति संस्करण हटाएं। | `--yes`, `-y` |
| `fp policies test PATH` | एक नीति को स्थानीय रूप से एक सिंथेटिक संदर्भ के विरुद्ध चलाएं। प्रत्येक नीति के `match` फ़िल्टर को लागू करता है, तो जो दिए गए ईवेंट/टूल को कवर नहीं करता है वह चलाए जाने के बजाय `skipped` रिपोर्ट किया जाता है। | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | सहायक के साथ एक नीति का मसौदा तैयार करें। `policies:write` की जरूरत है। | — |
