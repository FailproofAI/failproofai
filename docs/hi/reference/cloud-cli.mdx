`fp` का उपयोग Cloud टेलीमेट्री निरीक्षण करने, क्लाउड-प्रबंधित प्रवर्तन (policies, fleet deployments, guardrail निर्णय) प्रबंधित करने, और audits, findings, issues, alerts, keys, users, queries, और settings प्रबंधित करने के लिए करें। स्थानीय hooks, policies, capture, और machine enrollment के लिए [`failproofai`](/hi/reference/failproof-cli) का उपयोग करें।

Cloud CLI को एक isolated tool के रूप में install करें:

```bash
uv tool install fp-cloud-cli
fp version
```

## साइन इन करें

```bash
fp login
fp whoami
```

## सिंटैक्स

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Global options को command से पहले आना चाहिए:

```bash
fp --json sessions --since 24h
```

टर्मिनल help के लिए `fp COMMAND --help` या `fp COMMAND SUBCOMMAND --help` चलाएं।

### Events

```text
fp events [OPTIONS]
```

व्यक्तिगत agent events की सूची बनाता है। डिफ़ॉल्ट light feed raw payloads को exclude करता है; `--full` का उपयोग केवल bounded investigation के लिए करें।

| विकल्प | विवरण |
| --- | --- |
| `--limit`, `-n <n>` | अधिकतम कुल rows। डिफ़ॉल्ट: `50`। |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, या `7d`। |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC range; `--since` को override करता है। |
| `--env <value>` | Environment filter; values को repeat या comma-separate करें। |
| `--event-type <value>` | Event-type filter; repeat या comma-separate। |
| `--agent-id <value>` | Agent filter; repeat या comma-separate। |
| `--session-id <value>` | Session filter; repeat या comma-separate। |
| `--search <text>` | Payload text search; repeatable, किसी भी term के साथ matching। |
| `--order asc\|desc` | Time order। डिफ़ॉल्ट: newest first। |
| `--all` | `--limit` तक auto-paginate करें। |
| `--cursor <token>` | Opaque cursor से resume करें। |
| `--page-size <n>` | `--all` के साथ rows per request; अधिकतम `200`। |
| `--full` | Heavier event endpoint के माध्यम से raw payloads शामिल करें। |
| `--fields <csv>` | केवल चयनित fields return करें; `payload` requesting full mode को सक्षम करता है। |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` **`--limit` तक** पaginates करता है, जिसका डिफ़ॉल्ट **50** है — इसलिए `--all` अकेले 50 rows पर रुकता है। जब यह जल्दी रुकता है तो response एक `next_cursor` carry करता है; `"next_cursor": null` का मतलब है कि feed वास्तव में exhausted था।
</Note>

#### Audit create options

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| विकल्प | विवरण |
| --- | --- |
| `--file <path>` | JSON पर definition को base करें, या stdin के लिए `-` का उपयोग करें। Explicit flags file values को override करते हैं। |
| `--description <text>` | Failure question या purpose को state करें। |
| `--enabled` / `--disabled` | On या off पर scheduling को start करें। डिफ़ॉल्ट: enabled। |
| `--schedule-interval-secs <n>` | `3600`–`604800`। डिफ़ॉल्ट: `86400`। |
| `--schedule-anchor <timestamp>` | ISO 8601 form में fixed UTC phase। डिफ़ॉल्ट: अगला 09:00 UTC। |
| `--window-mode since_last\|fixed` | Last fully analyzed window के बाद continue करें या repeatedly एक rolling window को inspect करें। डिफ़ॉल्ट: `since_last`। |
| `--lookback-window-secs <n>` | `3600`–`7776000`। डिफ़ॉल्ट: `604800`। |
| `--scope '<json>'` | `environments`, `agent_ids`, या अन्य supported scope fields द्वारा filter करें। |
| `--ignore-error-type <type>` | Error types को exclude करें; repeat या comma-separate। |
| `--llm` / `--no-llm` | Agentic analysis को enable या disable करें। डिफ़ॉल्ट: enabled। |
| `--top-k <n>` | `1`–`500` findings को retain करें। डिफ़ॉल्ट: `50`। |
| `--sensitivity low\|medium\|high` | Reporting sensitivity को set करें। डिफ़ॉल्ट: `medium`। |
| `--channels '<json>'` | Notification channel array। |
| `--text <brief>` | Inline brief, अधिकतम 8,192 characters। |
| `--text-file <path>` | एक file से brief को read करें; `--text` के साथ mutually exclusive। |
| `--url <https-url>` | एक public HTTPS reference को add करें; up to पांच बार repeat करें। |

Creation के दौरान context को शामिल करें जब पहले run को इसकी आवश्यकता हो। Creation definition और context को एक साथ commit करता है queued run शुरू होने से पहले।

<Note>
  `fp audits run` asynchronous है। `fp audits runs NAME` को poll करें जब तक latest run succeed या fail न हो जाए।
</Note>

### Policies

क्लाउड-प्रबंधित policy versions। **Session-only** — यहां हर कमांड एक API key के तहत `2` exit करता है, किसी भी request से पहले, क्योंकि ये deliberately root-only write routes हैं जो `/v1` से absent हैं।

| कमांड | उद्देश्य | विकल्प |
| --- | --- | --- |
| `fp policies list` | Policy versions की सूची बनाएं। | `--json` |
| `fp policies show POLICY_ID` | एक policy, इसके source के साथ दिखाएं। | — |
| `fp policies publish NAME PATH` | एक local `.mjs` से एक version mint करें। | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | इसे हर deployment में वापस add करें जहां से यह हटाया गया था, प्रत्येक पर नया generation mint करते हुए। | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | इसे हर deployment से remove करें जो इसे carry कर रहा है, प्रत्येक पर नया generation mint करते हुए। | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | एक policy version को delete करें। | `--yes`, `-y` |
| `fp policies test PATH` | एक policy को locally एक synthetic context के विरुद्ध चलाएं। प्रत्येक policy के `match` filter को apply करता है, इसलिए एक जो दिए गए event/tool को cover नहीं करता है, `skipped` के रूप में reported है चलाने के बजाय। | `--event`; `--tool`; `--command`; `--file-path`; `--expect` |
| `fp policies compose PROMPT` | Assistant के साथ एक policy को draft करें। `policies:write` की आवश्यकता है। | — |

### Fleet

कौन सी machines कौन सी policies चलाती हैं। **Session-only**, ऊपर जैसा कारण।

| कमांड | उद्देश्य | विकल्प |
| --- | --- | --- |
| `fp fleet list` | Enrolled machines और उनके deployment generation की सूची बनाएं। | — |
| `fp fleet show MACHINE_ID` | Machine currently जो policy set चलाता है। | — |
| `fp fleet deploy MACHINE_ID` | **Machine के पूरे policy set को replace करता है।** Plan को print करता है और एक interactive terminal पर `--json` के बिना only पूछता है। | `--add`; `--remove`; `--set`; `--create`; `--yes`, `-y` |
| `fp fleet diff MACHINE_ID` | एक machine को दूसरे deployment के विरुद्ध compare करें। | — |
| `fp fleet history MACHINE_ID` | एक machine के लिए past deployments। | — |
| `fp fleet rollback MACHINE_ID` | एक previous deployment को restore करें। | `--yes`, `-y` |
| `fp fleet rename MACHINE_ID` | एक machine को एक readable name दें। | required `--name` |

### Guardrails

Enforcement ने वास्तव में क्या किया। **Session-only**, ऊपर जैसा कारण।

| --- | --- | --- |

## Global flags

| Flag | विवरण |
| --- | --- |
| `--json` | Machine-readable JSON को emit करें। |
| `--base-url <url>` | एक self-hosted या development dashboard का उपयोग करें। |
| `--org <slug>` | इस invocation के लिए एक organization select करें। |
| `--token <token>` | Saved user-session token को override करें। |
| `--api-key <key>` | Automation को एक API key के साथ authenticate करें; कभी save नहीं किया जाता। |
| `--timeout <seconds>` | HTTP timeout; सकारात्मक होना चाहिए। डिफ़ॉल्ट: `30`। |
| `--quiet`, `-q` | stderr पर status output को suppress करें। |
| `--no-color` | Colored output को disable करें। |
| `--insecure` / `--secure` | TLS certificate verification को disable या restore करें। |
| `--version` | Unboxed version को print करें और exit करें। |
| `--help`, `-h` | Help दिखाएं। |

`--api-key` automation के लिए intended है। Login, organization switching, और assistant commands को एक user session की आवश्यकता है।

<Warning>
  इन के `AGENTEYE_*` spellings **`fp` द्वारा read नहीं** किए जाते हैं और कभी नहीं थे — CLI `FP_*` (`fp_cli/app.py`) को declare करता है, और एक unknown variable एक error नहीं है। `AGENTEYE_DASHBOARD_URL` को set करने से CLI को retarget नहीं करता है; यह ignore किया जाता है और command silently saved dashboard के विरुद्ध चलता है।

  `AGENTEYE_HOME` और `AGENTEYE_ENVIRONMENT` अभी भी exist करते हैं, लेकिन वे **collector और telemetry SDK** को belong करते हैं, इस CLI को नहीं।
</Warning>
