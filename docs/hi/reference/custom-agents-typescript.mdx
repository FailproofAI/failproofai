<Note>
  यह SDK और Python वाला **एक ही स्पूल में एक ही इवेंट्स लिखते हैं**। Node एजेंट्स और Python एजेंट्स वाला एक फ्लीट एक सेट सेशन प्रोड्यूस करता है, दो नहीं, और डैशबोर्ड में कुछ भी उन्हें अलग नहीं करता। प्रति कंपनी नहीं, प्रति सेवा चुनें।
</Note>

## इंस्टॉल करें

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

फ्रेमवर्क एडाप्टर पैकेज में ही शिप होते हैं। फ्रेमवर्क्स **वैकल्पिक पीयर निर्भरताएं** हैं — घोषित किए जाते हैं ताकि समर्थित रेंज दिखें, कभी आपकी ओर से इंस्टॉल न हों, और केवल तब आयात किए जाएं जब आप `instrument()` को कॉल करें।

## Failproof डेमन से कनेक्ट करें

Python SDK के समान: **Admin → Keys** के तहत एक `events:add` कुंजी बनाएं, फिर [डेमन को कनेक्ट करें](/hi/start/setup#connect-a-machine-to-cloud) एजेंट मशीन पर। SDK डिस्क पर लिखता है; डेमन शिप करता है।

## कॉन्फ़िगरेशन

### OpenTelemetry स्पैन्स (ऑप्ट इन)

`npm install @opentelemetry/api @opentelemetry/sdk-trace-base` के साथ OpenTelemetry को अलग से इंस्टॉल करें।
फिर FailproofAI को अपने प्रोवाइडर के प्रोसेसर्स में जोड़ें:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

एक मौजूदा प्रोवाइडर के लिए, उसके अन्य प्रोसेसर्स को एक ही लिस्ट में रखें। प्रोवाइडर्स जो `addSpanProcessor` को एक्सपोज़ करते हैं उन्हें `{ provider }` के रूप में पास किया जा सकता है। विकल्प के बिना, सेटअप एक नया प्रोवाइडर रजिस्टर करता है केवल अगर कोई प्रोवाइडर पहले से रजिस्टर नहीं है।
`OtelSpanExporter` को अपने स्वयं के प्रोसेसर के साथ सीधे भी उपयोग किया जा सकता है।

एक्सपोर्ट्स कनेक्टेड FailproofAI डेमन के माध्यम से जाते हैं; SDK कोई नेटवर्क अनुरोध नहीं भेजता और कुंजी या स्थानीय श्रोता की जरूरत नहीं है। एक एडमिन से पूछें कि [OpenTelemetry इनजेस्ट](/hi/agenteye/opentelemetry) को सक्षम करें। एक बेयर `instrument()` इस एक्सपोर्टर को सक्षम नहीं करता। `uninstrument("otel")` केवल अपना ही प्रोसेसर अक्षम करता है।
आपके स्पैन एट्रिब्यूट्स सामग्री कैप्चर को नियंत्रित करते हैं; निकास से पहले अपने प्रोवाइडर को फ्लश करें।
OpenTelemetry एक वैकल्पिक एप्लिकेशन निर्भरता रहता है, हार्ड SDK निर्भरता नहीं।

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| विकल्प | यह क्या करता है |
| --- | --- |
| `environment` | हर इवेंट पर लेबल — `production`, `staging`, `prod-eu`। `dev` को डिफॉल्ट करता है। |
| `flushInterval` | टाइमर कितनी बार डिस्क पर लिखता है, सेकंड में। `0.5` को डिफॉल्ट करता है। |
| `baseDir` | कहां लिखना है। डेमन के स्पूल को डिफॉल्ट करता है, जो आप जो चाहते हैं उसके अलावा कुछ और जानते हैं। |

कुछ भी लागू नहीं होता जब तक सब कुछ वेलिडेट न हो, तो एक अस्वीकृत कॉल SDK को ठीक वैसे ही छोड़ देता है जैसे वह था नई `baseDir` के साथ नहीं और पुरानी अंतराल।

इसके बजाय पर्यावरण चर द्वारा सेट करें:

| वैरिएबल | यह क्या करता है |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | कोड परिवर्तन के बिना `environment` सेट करता है। एक `configure()` विकल्प इसे जीतता है। |
| `FAILPROOFAI_HOME` | Failproof AI रूट को स्थानांतरित करता है जो स्पूल को रखता है। |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (डिफॉल्ट), `error`, `silent`। |
| `FAILPROOFAI_SDK_STRICT` | `1` इंस्ट्रूमेंटेशन त्रुटियों को लॉग करने के बजाय थ्रो करता है। |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` एक फ्रेमवर्क-कम्पैटिबिलिटी समस्या को चेतावनी और जारी रखने के बजाय थ्रो करता है। |

<Warning>
  **`environment` में कोई कोमा नहीं।** इनजेस्ट उस फील्ड को कोमा पर विभाजित करता है अपने फिल्टर बनाने के लिए, और किसी भी इवेंट को छोड़ देता है जिसका लेबल एक — तो एक पूरा रन चुप्पी से गायब हो जाता है। `prod-eu` लिखें, `prod,eu` नहीं।

  `configure({ environment: "prod,eu" })` थ्रो करता है ताकि आप तुरंत पता चल जाए। `AGENTEYE_ENVIRONMENT` थ्रो नहीं कर सकता — कोई आपको कॉल नहीं कर रहा — तो यह एक बार चेतावनी देता है और `dev` को फॉलबैक करता है।
</Warning>

SDK की अपनी लॉग लाइनों को अपने लॉगर में `failproofai.setLogger({ debug, info, warn, error })` के साथ रूट करें।

## शटडाउन

बफर किए गए इवेंट्स `process.on("exit")` पर फ्लश किए जाते हैं।

एक प्रक्रिया जो एक सिग्नल द्वारा मारी जाती है वह कभी नहीं पहुंचती, और `SIGTERM` के लिए Node का डिफॉल्ट बिना एक्जिट हैंडलर चलाए समाप्त करना है — तो एक कंटेनराइज़्ड एजेंट जो भी खो देता है अंतिम अंतराल लिख नहीं गया था।

<Warning>
  **यह SDK आपके लिए एक सिग्नल हैंडलर इंस्टॉल नहीं करेगा।** एक रजिस्टर करना आपकी प्रक्रिया के व्यवहार को बदलता है: एक श्रोता Node के डिफॉल्ट समाप्ति को दबाता है, तो एक लाइब्रेरी जो एक को जोड़ता था वह चुप्पी से Ctrl-C को काम करने से रोक देगा। अपना स्वयं का जोड़ें:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

एक अल्पकालिक स्क्रिप्ट या एक सर्वरलेस हैंडलर को लौटने से पहले `await failproofai.flush()` करना चाहिए — अंतराल अकेले डिलीवरी की गारंटी नहीं देता।

## पहचान

हर इवेंट एक सेशन और एक एजेंट से संबंधित है। **स्कोप्स दोनों को भरते हैं**, तो आप शायद ही कभी उन्हें पास करते हैं:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId` या `agentId` को स्पष्ट रूप से पास करना अभी भी काम करता है और जीतता है। न तो बाउंड और न ही पास किए जाने के साथ, कॉल थ्रो करता है बजाय एक इवेंट उत्सर्जन करने के जो Cloud चुप्पी से छोड़ देगा।

<Note>
  पहचान `AsyncLocalStorage` पर सवारी करती है। यह `await`, `.then()`, टाइमर्स और स्कोप के अंदर बनाए गए किसी भी कॉलबैक का अनुसरण करता है। यह एक रन के दौरान स्टोर किए गए और दूसरे के दौरान आह्वान किए गए कॉलबैक का पालन नहीं करता है, या `worker_threads` की सीमा पार काम को न्यायित करता है — उन्हें `failproofai.propagate()` में लपेटें या उनके इवेंट्स अलग-थलग रहते हैं।
</Note>

### स्कोप्स

| स्कोप | उत्सर्जित करता है | वापस देता है |
| --- | --- | --- |
| `session(body)` | कुछ नहीं — केवल पहचान | जो `body` वापस देता है |
| `agent(id, options?, body)` | `agent_start`, फिर `agent_end` | जो `body` वापस देता है |
| `toolCall(name, options?, body)` | `tool_use`, फिर `tool_result` | जो `body` वापस देता है |

एक सिंक्रोनस बॉडी सिंक्रोनस रहता है: `agent("x", () => 1)` `1` वापस देता है, प्रॉमिस नहीं।

`toolCall` बॉडी के रिजॉल्व किए गए मान को टूल के `output` के रूप में रिकॉर्ड करता है, जब तक आप स्वयं `call.output` असाइन नहीं करते।

<Accordion title="एक्जिट शब्दार्थ" icon="arrow-right-from-bracket">

| क्या हुआ | इवेंट्स | `outcome` |
| --- | --- | --- |
| ब्लॉक लौटा | `agent_end` | `"success"`, या आपका `outcome` |
| ब्लॉक ने थ्रो किया | `error`, फिर `agent_end` | `"failed"` |
| एक `AbortError` | केवल `agent_end` | `"cancelled"` |

त्रुटि हमेशा फिर से थ्रो की जाती है।

एक टूल विफलता पत्ती पर रिकॉर्ड की जाती है — `tool_result` एक `error` स्ट्रिंग के साथ — और कोई रन-स्तर `error` इवेंट उत्सर्जित नहीं करता। एक जो एजेंट लूप पकड़ता है वह एक रन विफलता नहीं है, और एक जो प्रचारित करता है वह ठीक एक बार रिपोर्ट किया जाता है, बंद `agent()` द्वारा।

</Accordion>

<Accordion title="The `using` form" icon="brackets-curly">

जब काम एक ही फंक्शन नहीं है — एक कंस्ट्रक्टर में खोला गया स्कोप और टियरडाउन में बंद, या एक जो मौजूदा नियंत्रण प्रवाह को तोड़ता है:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, फिर agent_end
```

दोनों फॉर्म बाइट-समान इवेंट्स उत्सर्जित करते हैं। कॉलबैक फॉर्म को प्राथमिकता दें: यह `AsyncLocalStorage.run()` के अंदर चलता है, तो अनवाइंड करने के लिए कुछ नहीं है और संपूर्ण "यहां खोलें, वहां बंद करें" बग क्लास अप्राप्य है।

एक `using` ब्लॉक जो अपनी स्वयं की विफलता को पकड़ता है इसे `span.fail(error)` के साथ रिपोर्ट करता है — डिस्पोजर के पास स्वयं का कोई अपवाद चैनल नहीं है।

</Accordion>

## इवेंट कैटलॉग

Python SDK के समान पंद्रह विधियां, camelCase में। अधिकांश **जोड़ी** में आते हैं — आप ओपनर को कॉल करते हैं, फिर क्लोजर, और SDK अंतराल को समय देता है।

| | खोलता है | बंद करता है |
| --- | --- | --- |
| **एजेंट्स** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **मॉडल्स** | `modelRequest` | `modelResponse` |
| **टूल्स** | `toolUse` | `toolResult` |
| **हुक्स** | `hookTriggered` | `hookCompleted` |
| **मनुष्य** | `humanWait` | `humanInput` |

तीन अकेले खड़े हैं: `error`, `humanPause`, `humanInterrupt`।

<Accordion title="हर विधि के लिए हर फील्ड" icon="table">

हर विधि `sessionId` और `agentId` भी लेती है, जिन्हें स्कोप्स आपके लिए भरते हैं। कुछ भी छोड़ा जाना JSON `null` के रूप में भेजे जाने के बजाय छोड़ा जाता है।

| विधि | आवश्यक | वैकल्पिक |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

कोई अन्य कुंजी जो आप जोड़ते हैं वह एक कस्टम पेलोड फील्ड बन जाती है। कुछ भी फ्रेमवर्क-विशिष्ट नेमस्पेस `fw_*`; एक नाम जो घोषित फील्ड के साथ टकराता है उसे चुप्पी से एक प्रचारित कॉलम को अधिलेखित करने के बजाय अस्वीकार किया जाता है।

</Accordion>

<Warning>
  **`duration_ms` गणना की गई है, स्वीकृत नहीं।** चार बंद करने वाली विधियां अपने ओपनर से अंतराल को समय देती हैं और एक कॉलर-सप्लाई की गई `duration_ms` को अस्वीकार करती हैं — एक रिपोर्ट की गई अवधि अभेद्य है।

  जोड़े **सेशन** पर मेल खाते हैं और आईडी, कभी नहीं एजेंट पर। एक टूल `planner` के तहत खोला गया और `worker` के तहत बंद किया गया अभी भी मेल खाता है, जो नेस्टेड मल्टी-एजेंट रन वास्तव में करता है।
</Warning>

## फ्रेमवर्क एडाप्टर

```ts
await failproofai.instrument();              // जो कुछ भी यह पा सकता है
await failproofai.instrument("langchain");   // ठीक एक
failproofai.uninstrument();                  // सब कुछ वापस रखो
```

| फ्रेमवर्क | समर्थित | यह कैसे जुड़ता है |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, तो हर `invoke`/`stream`/`batch` कहीं भी `callbacks:` पास किए बिना कवर किया जाता है — या `langchainHandler()` को स्वयं पास करें और कुछ न पैच करें। |
| **Vercel AI SDK** | `ai` 4 – 7 | कॉल साइट पर `telemetry()`, या `instrument("ai")` पूरी प्रक्रिया के लिए `ai` 7 पर (`4–6` पर वह ऑप्ट-इन है — नीचे देखें)। |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, एजेंट का मॉडल और टूल रेजोल्यूशन, और वर्कफ्लो रन/स्टेप इंजन। |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (सदस्य) प्लस `AgentWorkflow.runStream`, वर्कफ्लो रन और उनके स्टेप्स के लिए। |

हर रेंज का परीक्षण वास्तविक फ्रेमवर्क रिलीज़ के विरुद्ध किया जाता है, दोनों सिरों पर, एक ES मॉड्यूल और CommonJS के रूप में, हर CI रन पर।

मैपिंग Python SDK की है, तो वही प्रोग्राम किसी भी भाषा में एक ही पेड़ ड्रा करता है। एक कंस्ट्रक्ट एक **एजेंट** है केवल अगर यह एक LLM निर्णय लूप का मालिक है — एक ग्राफ या श्रृंखला रन, एक AI SDK `generateText`/`streamText` कॉल, एक Mastra एजेंट, एक LlamaIndex एजेंट रन। एक LangGraph नोड या एक वर्कफ्लो स्टेप एक **हुक** है (`hook_triggered`/`hook_completed`), कभी नहीं एक नेस्टेड एजेंट। मॉडल कॉल्स `model_request`/`model_response` जोड़े हैं टोकन काउंट्स के साथ; टूल कॉल्स मॉडल की स्वयं की टूल कॉल आईडी ले जाते हैं। एक विफलता एक बार रिकॉर्ड की जाती है, जिस इवेंट पर यह हुई थी।

एक एडाप्टर जो इंस्टॉल करने में विफल रहता है वह लॉग किया जाता है और छोड़ दिया जाता है; अन्य अभी भी इंस्टॉल करते हैं, क्योंकि एक टूटा हुआ LlamaIndex आपको LangGraph कम नहीं करना चाहिए।

<Note>
  बिना तर्क के `instrument()` एक फ्रेमवर्क को यह जांचकर पहचानता है कि यह **रिजॉल्व** हो या नहीं, पहले से आयात की गई है या नहीं — Node ES मॉड्यूल के लिए Python के `sys.modules` के समान कुछ भी एक्सपोज़ नहीं करता। एक फ्रेमवर्क जो आप इंस्टॉल कर चुके हैं लेकिन उपयोग नहीं करते हैं वह आयात और पैच किया जाएगा। अगर यह महत्वपूर्ण हो तो आप जो चाहते हैं उसे नाम दें।
</Note>

<Note>
  इनमें से अधिकांश फ्रेमवर्क्स एक ES-मॉड्यूल बिल्ड और एक CommonJS बिल्ड शिप करते हैं, जिसे Node दो असंबंधित कॉपी के रूप में लोड करता है। एडाप्टर्स उस कॉपी को पैच करते हैं जिसे आपकी एप्लिकेशन लोड करती है (और CommonJS कॉपी भी अगर कुछ पहले से ही इसे `require` किया है), तो दोनों मॉड्यूल सिस्टम काम करते हैं। एक फ्रेमवर्क **आपके अपने आउटपुट में बंडल** किया गया esbuild या webpack द्वारा अप्राप्य है — वहां कॉल-साइट हेल्पर्स का उपयोग करें: `langchainHandler()`, `telemetry()`, `wrapTool()`।
</Note>

### बिना पैचिंग के LangChain

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

हैंडलर `instrument()` के साथ या बिना काम करता है और कभी डबल-रिकॉर्ड नहीं करता। `instrument("langchain")` `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` और `captureLimit` लेता है, जैसा Python एडाप्टर करता है; एक कॉल पर `metadata: { failproofai_sdk_session_id }` उस आह्वान के लिए सेशन चुनता है।

### Vercel AI SDK

AI SDK एक ES मॉड्यूल से प्लेन फंक्शन्स एक्सपोर्ट करता है, और एक ES मॉड्यूल नेमस्पेस विनिर्देश द्वारा अपरिवर्तनीय है — पैच करने के लिए कहीं नहीं है। यह एक्सटेंशन पॉइंट्स का उपयोग करता है जिसे SDK स्वयं दस्तावेज़ करता है:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // ai 7 पर, `telemetry: telemetry({ … })` — वही ऑब्जेक्ट, नया नाम
});
```

यह पूर्ण एकीकरण है: एक एजेंट स्पैन, प्रति स्टेप एक मॉडल अनुरोध/प्रतिक्रिया जोड़ी टोकन काउंट्स के साथ, और हर टूल कॉल। एक कॉल साइट हर मेजर पर काम करता है — `ai` 4–6 यह ले जाने वाला ट्रेसर पढ़ते हैं, `ai` 7 टेलीमेट्री इंटीग्रेशन पढ़ता है।

`instrument("ai")` `ai` 7 पर वही करता है **पूरी प्रक्रिया-व्यापी**: हर कॉल, AI SDK की वैश्विक टेलीमेट्री-एकीकरण सूची के माध्यम से, जो योगात्मक है और किसी और के कुछ नहीं लेता।

**`ai` 4–6 पर, `instrument("ai")` स्वयं द्वारा कुछ भी रिकॉर्ड नहीं करता, और एक चेतावनी लॉग करता है कि ऐसा है।** एक ही प्रक्रिया-व्यापी हुक जो इन मेजर्स के पास है वह वैश्विक OpenTelemetry ट्रेसर प्रोवाइडर है — एक एकल स्लॉट OpenTelemetry बाद में हाथ में लिए जाने से इंकार करता है। हमारे को रजिस्टर करना बाद में स्टार्टअप में आपके अपने `NodeSDK.start()` को चुप्पी से अस्वीकार कर देगा और आपके http/डेटाबेस स्पैन्स को एक ट्रेसर को भेजेगा जो कुछ भी निर्यात नहीं करता। कॉल साइट पर `telemetry()` का उपयोग करें या वहां `wrapModel` का। अगर प्रक्रिया कोई OpenTelemetry अपना नहीं चलाती, तो `instrument("ai", { registerGlobalTracer: true })` के साथ ऑप्ट इन करें: यह तब हर कॉल रिकॉर्ड करता है जो `experimental_telemetry: { isEnabled: true }` पास करता है, और केवल स्लॉट लेता है अगर यह अभी भी खाली है। `registerGlobalTracer: false` डिफॉल्ट रखता है और चेतावनी को चुप करता है।

अगर आप मॉडल को एक बार लपेटना पसंद करते हैं, `wrapModel` केवल मॉडल कॉल्स देखता है, क्योंकि टूल कॉल्स मॉडल परत के ऊपर होते हैं। चारों ओर कुछ भी नहीं के साथ बुलाया गया एक लपेटा मॉडल अपने स्वयं के रन के रूप में रिकॉर्ड किया जाता है। एक स्ट्रीम किया गया कॉल स्ट्रीम कैसे बंद होती है — `stop_reason: "cancelled"` जब उपभोक्ता इसे रद्द करता है, `"error"` त्रुटि के साथ जब यह आधा विफल हो:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

दोनों का उपयोग करना ठीक है: मिडलवेयर देखता है कि कॉल पहले से ही रिकॉर्ड की जा रही है और अस्वीकार करता है, तो प्रत्येक कॉल एक बार रिकॉर्ड की जाती है।

`functionId` एजेंट स्पैन का नाम देता है। इसे कम कार्डिनैलिटी रखें — यह `agent_id` में उतरता है, प्राथमिक डैशबोर्ड पहलू।

### Next.js

`next build` डिफॉल्ट रूप से आपके सर्वर की निर्भरताओं को बंडल करता है, और एक फ्रेमवर्क जो बिल्ड में बंडल किया गया है वह `instrument()` तक पहुंच नहीं सकता। कॉन्फ़िग को एक बार लपेटें और Next की स्टार्टअप हुक से `instrument()` को कॉल करें:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* आपका कॉन्फ़िग */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` LangChain, Mastra, LlamaIndex और SDK स्वयं को `serverExternalPackages` में जोड़ता है, आपकी सूची रखता है। इसके बिना, `instrument()` एक बार प्रति फ्रेमवर्क चेतावनी देता है जिसे यह नहीं पहुंच सकता बजाय चुप्पी से विफल होने के; अगर आप पैकेज को स्वयं सूचीबद्ध करते हैं, तो `FAILPROOFAI_NEXT_EXTERNALS=1` सेट करें। Vercel AI SDK और कॉल-साइट हेल्पर्स किसी भी तरह काम करते हैं। एक Edge मार्ग एक नो-ऑप बिल्ड प्राप्त करता है: SDK को आयात करना सुरक्षित है और कुछ नहीं रिकॉर्ड करता।

### स्ट्रीम किए गए कॉल्स पर टोकन काउंट्स

OpenAI-कम्पैटिबल API केवल जब क्लाइंट पूछता है तो स्ट्रीम पर उपयोग रिपोर्ट करते हैं। LangChain और Vercel AI SDK पूछते हैं; LlamaIndex के लिए `additionalChatOptions: { stream_options: { include_usage: true } }` को अपने `OpenAI` LLM में पास करें, और Mastra के लिए उपयोग सक्षम बिल्ड मॉडल को करें (उदाहरण के लिए `createOpenAICompatible({ includeUsage: true })`)। अन्यथा स्ट्रीम किए गए मॉडल कॉल्स कोई टोकन काउंट्स नहीं ले जाते।

### रनटाइम्स

Node ≥ 20.9, Bun और Deno — हर फ्रेमवर्क, एक ES मॉड्यूल और CommonJS के रूप में, Node के ट्रेस के विरुद्ध प्रत्येक पर परीक्षण किया जाता है। SDK `failproofaid` डेमन के बगल में चलता है, जो जो लिखता है वह शिप करता है।

## आपका स्वयं का एजेंट — कोई फ्रेमवर्क नहीं

एक एजेंट लूप के लिए जिसे आपने स्वयं लिखा है, या एक फ्रेमवर्क बिना एडाप्टर के। आप एडाप्टर्स के अंदर अंतर्निहित समान API के साथ इवेंट्स उत्सर्जित करते हैं, तो ट्रेस में समान आकार और गुणवत्ता होती है।

आपको यह जानने की जरूरत नहीं है कि एजेंट को कैसे संगठित किया जाता है। हर हाथ से बनाया गया एजेंट पहले से ही तीन जगहें हैं, इसके फंक्शन्स को जो भी कहा जाता है, और वे तीन पूरा एकीकरण हैं:

| कहां | क्या जोड़ना है | उत्सर्जित करता है |
| --- | --- | --- |
| जहां **एक रन** शुरू होता है और समाप्त होता है | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **एक फंक्शन जो मॉडल को कॉल करता है** | `event.modelRequest` पहले, `event.modelResponse` बाद — दोनों हिस्से, विफलता पर भी | प्रति मॉडल टर्न एक जोड़ी |
| **एक फंक्शन जो टूल्स चलाता है** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

पहचान परिवेशपूर्ण है: `agent()` के अंदर सब कुछ उस रन के सेशन में उतरता है बिना एक आईडी लिए, और प्रोग्राम में कुछ और नहीं बदलता — जो कुछ एजेंट पहले से ही अपने अपने डेटाबेस में लिखता है सहित।

- **एक सेवा या एक कार्यकर्ता:** अपना स्वयं का अनुरोध या जॉब आईडी `sessionId` के रूप में पास करें, तो डैशबोर्ड पर एक सेशन और आपके अपने लॉग्स या डेटाबेस में रिकॉर्ड एक ही स्ट्रिंग हैं।
- **सब-एजेंट्स:** `agent()` कॉल्स को नेस्ट करें। आंतरिक एक बाहरी के साथ सेशन में जुड़ता है क्योंकि इसका `parent_id`।
- **जोड़े उत्सर्जित करें।** एक `modelRequest` बिना `modelResponse` के एक स्पैन है जो डैशबोर्ड चलना दिखाता है हमेशा के लिए — इसलिए `catch`।

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) रिपॉजिटरी में पूर्ण, चलाने योग्य संस्करण है: एक वास्तविक OpenAI टूल लूप ठीक इसी तरह इंस्ट्रूमेंट किया गया, CI में हर बदलाव पर एक ES मॉड्यूल और CommonJS के रूप में चलाया गया।

import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});

## यह आपकी प्रक्रिया के साथ क्या नहीं करेगा

| | |
| --- | --- |
| **आपके एजेंट लूप को ब्लॉक करें** | इवेंट्स एक इन-मेमोरी कतार में जाते हैं; एक टाइमर उन्हें लिखता है। टाइमर `unref`'d है, तो इस पैकेज को आयात करना कभी एक स्क्रिप्ट को निकलने से नहीं रोकता। |
| **बिना सीमा के बढ़ें** | कतार गणना *और* द्वारा कैप की गई है मापी गई बाइट्स द्वारा। दोनों के पास, सबसे पुराने इवेंट्स को हटा दिया जाता है और एक चेतावनी कहती है तो — एक टेलीमेट्री बाहरपन OOM हत्या नहीं बन सकता। |
| **प्रक्रिया को नीचे ले जाएं** | एक अनकोडेबल इवेंट अकेले ड्रॉप किया जाता है, आसपास बैच नहीं। एक फेंकने वाला गेटर, एक वृत्ताकार संदर्भ, एक `BigInt`, एक अकेला सरोगेट: प्रत्येक को प्रचारित होने के बजाय संभाला जाता है। |
| **एक आधा-लिखित बैच छोड़ें** | सामग्री `fsync`ed है एक परमाणु पुनर्नाम से पहले, निर्देशिका `fsync`ed है बाद में, और एक विफल लिखना अपनी अस्थायी फाइल को साफ करता है। |
| **प्रतिलेख पठनीय छोड़ें** | बैच्स `0600` के अंदर हैं एक `0700` निर्देशिका। वे लक्ष्य, प्रॉम्प्ट्स, टूल तर्क और टूल आउटपुट ले जाते हैं। |
| **क्रेडेंशियल्स शिप करें** | API कुंजियां, टोकन्स, JWTs, bearer हेडर्स और गुप्त-आकार असाइनमेंट बाइट्स डिस्क तक पहुंचने से पहले संपादित किए जाते हैं। डेमन अपलोड से पहले फिर से संपादित करता है। |
