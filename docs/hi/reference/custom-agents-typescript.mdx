<Note>
  यह SDK और Python वाला एक ही स्पूल में **समान इवेंट लिखते हैं**। Node एजेंट और Python एजेंट के साथ एक फ्लीट एक सेट सेशन बनाता है, दो नहीं, और डैशबोर्ड में कुछ भी उन्हें अलग नहीं करता। कंपनी के अनुसार नहीं, प्रति सेवा चुनें।
</Note>

## इंस्टॉल करें

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

फ्रेमवर्क एडाप्टर पैकेज में ही शिप होते हैं। फ्रेमवर्क **वैकल्पिक पीयर डिपेंडेंसी** हैं — इसलिए घोषित किए गए हैं कि समर्थित रेंज दिखाई दें, कभी आपकी ओर से इंस्टॉल न हों, और केवल तब इंपोर्ट किए जाएं जब आप `instrument()` को कॉल करें।

## Failproof डेमॉन को कनेक्ट करें

Python SDK के समान: **settings → api keys** के तहत एक `events:add` कुंजी बनाएं, फिर [डेमॉन को कनेक्ट करें](/hi/start/setup#connect-a-machine-to-cloud) एजेंट मशीन पर। SDK डिस्क पर लिखता है; डेमॉन शिप करता है।

## कॉन्फ़िगरेशन

### OpenTelemetry स्पैन (ऑप्ट इन)

OpenTelemetry को अलग से `npm install @opentelemetry/api @opentelemetry/sdk-trace-base` के साथ इंस्टॉल करें।
फिर अपने प्रोवाइडर के प्रोसेसर में FailproofAI जोड़ें:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

मौजूदा प्रोवाइडर के लिए, इसके अन्य प्रोसेसर को एक ही सूची में रखें। जो प्रोवाइडर `addSpanProcessor` को एक्सपोज करते हैं, वे इसके बजाय `{ provider }` के रूप में पास किए जा सकते हैं। बिना विकल्पों के, सेटअप एक नया प्रोवाइडर रजिस्टर करता है केवल अगर कोई प्रोवाइडर पहले से रजिस्टर नहीं है।
`OtelSpanExporter` को अपने स्वयं के प्रोसेसर के साथ सीधे भी उपयोग किया जा सकता है।

निर्यात जुड़े FailproofAI डेमॉन के माध्यम से जाते हैं; SDK कोई नेटवर्क अनुरोध नहीं भेजता और कोई कुंजी या स्थानीय श्रोता की आवश्यकता नहीं है। [OpenTelemetry इनजेस्ट](/hi/agenteye/opentelemetry) क्लाउड में हमेशा चालू होता है। एक नंगा `instrument()` इस निर्यातक को सक्षम नहीं करता। `uninstrument("otel")` केवल अपने स्वयं के प्रोसेसर को अक्षम करता है।
आपकी स्पैन विशेषताएं सामग्री कैप्चर को नियंत्रित करती हैं; बाहर निकलने से पहले अपने प्रोवाइडर को फ्लश करें।
OpenTelemetry एक वैकल्पिक एप्लिकेशन डिपेंडेंसी रहता है, कठोर SDK डिपेंडेंसी नहीं।

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| विकल्प | यह क्या करता है |
| --- | --- |
| `environment` | हर इवेंट पर लेबल — `production`, `staging`, `prod-eu`। डिफ़ॉल्ट `dev` है। |
| `flushInterval` | टाइमर कितनी बार डिस्क पर लिखता है, सेकंड में। डिफ़ॉल्ट `0.5` है। |
| `baseDir` | कहाँ लिखना है। डिफ़ॉल्ट डेमॉन के स्पूल हैं, जो आप चाहते हैं जब तक आप अन्यथा न जानते हों। |

जब तक सभी की पुष्टि नहीं हो जाती, तब तक कुछ भी लागू नहीं होता है, इसलिए एक अस्वीकृत कॉल SDK को बिल्कुल वैसे ही छोड़ देता है जैसे यह था, न कि नए `baseDir` और पुरानी अंतराल के साथ।

इसके बजाय पर्यावरण चर द्वारा सेट करें:

| चर | यह क्या करता है |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | कोड परिवर्तन के बिना `environment` सेट करता है। एक `configure()` विकल्प इसे हरा देता है। |
| `FAILPROOFAI_HOME` | Failproof AI रूट को स्थानांतरित करता है जो स्पूल को धारण करता है। |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (डिफ़ॉल्ट), `error`, `silent`। |
| `FAILPROOFAI_SDK_STRICT` | `1` इंस्ट्रूमेंटेशन त्रुटियों को लॉग होने के बजाय फेंक देता है। |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` एक फ्रेमवर्क-संगतता समस्या को चेतावनी के बजाय फेंक देता है और आगे बढ़ता है। |

<Warning>
  **`environment` में कोई अल्पविराम नहीं।** इनजेस्ट अपने फ़िल्टर बनाने के लिए उस फील्ड को अल्पविराम पर विभाजित करता है, और किसी भी इवेंट को छोड़ देता है जिसके लेबल में एक है — इसलिए पूरा रन चुप्पी से गायब हो जाता है। `prod-eu` लिखें, `prod,eu` नहीं।

  `configure({ environment: "prod,eu" })` फेंकता है इसलिए आप तुरंत पता चल जाता है। `AGENTEYE_ENVIRONMENT` फेंक नहीं सकता — कोई आपको कॉल नहीं कर रहा — इसलिए यह एक बार चेतावनी देता है और `dev` पर वापस आ जाता है।
</Warning>

SDK की अपनी लॉग लाइनों को `failproofai.setLogger({ debug, info, warn, error })` के साथ अपने लॉगर में रूट करें।

## शटडाउन

बफर किए गए इवेंट `process.on("exit")` पर फ्लश होते हैं।

एक सिग्नल द्वारा मारी गई प्रक्रिया कभी भी वहां तक नहीं पहुंचती, और `SIGTERM` के लिए Node की डिफ़ॉल्ट एक्जिट हैंडलर्स को चलाए बिना समाप्त करना है — इसलिए एक कंटेनरीकृत एजेंट जो कुछ भी खो देता है कि आखिरी अंतराल ने लिखा नहीं था।

<Warning>
  **यह SDK आपके लिए एक सिग्नल हैंडलर इंस्टॉल नहीं करेगा।** एक को रजिस्टर करना आपकी प्रक्रिया के व्यवहार को बदलता है: एक श्रोता Node की डिफ़ॉल्ट समाप्ति को दबाता है, इसलिए एक लाइब्रेरी जो एक जोड़ी होती चुप्पी से Ctrl-C को काम करना बंद कर देती। अपना खुद का जोड़ें:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

एक अल्पकालिक स्क्रिप्ट या एक सर्वरलेस हैंडलर को वापसी से पहले `await failproofai.flush()` करना चाहिए — अंतराल अकेले डिलिवरी की गारंटी नहीं देता है।

## पहचान

हर इवेंट एक सेशन और एक एजेंट से संबंधित है। **स्कोप दोनों को भरते हैं**, इसलिए आप शायद ही कभी उन्हें पास करते हैं:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId` या `agentId` को स्पष्ट रूप से पास करना अभी भी काम करता है और जीत जाता है। न तो बंधे और न ही पास किए गए के साथ, कॉल फेंकता है बजाय एक इवेंट उत्सर्जन करने के जो क्लाउड चुप्पी से त्यागता है।

<Note>
  पहचान `AsyncLocalStorage` पर सवारी करती है। यह `await`, `.then()`, टाइमर और स्कोप के अंदर बनाया गया कोई भी कॉलबैक का पालन करता है। यह एक रन के दौरान संग्रहीत और दूसरे के दौरान आह्वान किए गए कॉलबैक का पालन **नहीं** करता है, या `worker_threads` सीमा के पार स्थानांतरित कार्य के साथ काम नहीं करता है — उन्हें `failproofai.propagate()` में लपेटें या उनके इवेंट अनलगा होते हैं।
</Note>

### स्कोप

| स्कोप | उत्सर्जन | रिटर्न |
| --- | --- | --- |
| `session(body)` | कुछ नहीं — केवल पहचान | जो भी `body` रिटर्न करता है |
| `agent(id, options?, body)` | `agent_start`, फिर `agent_end` | जो भी `body` रिटर्न करता है |
| `toolCall(name, options?, body)` | `tool_use`, फिर `tool_result` | जो भी `body` रिटर्न करता है |

एक सिंक्रोनस बॉडी सिंक्रोनस रहता है: `agent("x", () => 1)` `1` रिटर्न करता है, प्रॉमिस नहीं।

`toolCall` बॉडी के हल किए गए मान को टूल के `output` के रूप में रिकॉर्ड करता है, जब तक आप स्वयं `call.output` असाइन नहीं करते।

<Accordion title="एक्जिट सेमेंटिक्स" icon="arrow-right-from-bracket">

| क्या हुआ | इवेंट | `outcome` |
| --- | --- | --- |
| ब्लॉक ने रिटर्न किया | `agent_end` | `"success"`, या आपका `outcome` |
| ब्लॉक ने फेंका | `error`, फिर `agent_end` | `"failed"` |
| एक `AbortError` | केवल `agent_end` | `"cancelled"` |

त्रुटि हमेशा फिर से फेंकी जाती है।

एक टूल की विफलता पत्ती पर रिकॉर्ड की जाती है — `tool_result` एक `error` स्ट्रिंग के साथ — और **कोई** रन-स्तरीय `error` इवेंट उत्सर्जन नहीं करता है। एक जो एजेंट लूप पकड़ता है वह एक रन विफलता नहीं है, और एक जो प्रसारित होता है वह संलग्न `agent()` द्वारा बिल्कुल एक बार रिपोर्ट किया जाता है।

</Accordion>

<Accordion title="`using` फॉर्म" icon="brackets-curly">

जब काम एक एकल फ़ंक्शन नहीं है — एक निर्माता में खोला गया स्कोप और एक विध्वंस में बंद, या एक जो मौजूदा नियंत्रण प्रवाह को स्ट्रेडल करता है:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, फिर agent_end
```

दोनों फॉर्म बाइट-समान इवेंट उत्सर्जन करते हैं। कॉलबैक फॉर्म को प्राथमिकता दें: यह `AsyncLocalStorage.run()` के अंदर चलता है, इसलिए आगे बढ़ने के लिए कुछ भी नहीं है और पूरी "यहां खोली, वहां बंद" बग की कक्षा अप्राप्य है।

एक `using` ब्लॉक जो अपनी स्वयं की विफलता को पकड़ता है `span.fail(error)` के साथ रिपोर्ट करता है — डिस्पोज़र के पास अपना कोई अपवाद चैनल नहीं है।

</Accordion>

## इवेंट कैटलॉग

Python SDK के समान पंद्रह मेथड, camelCase में। अधिकांश **जोड़े** में आते हैं — आप ओपनर को कॉल करते हैं, फिर क्लोजर, और SDK अंतराल को समय देता है।

| | खुलता है | बंद करता है |
| --- | --- | --- |
| **एजेंट** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **मॉडल** | `modelRequest` | `modelResponse` |
| **टूल** | `toolUse` | `toolResult` |
| **हुक** | `hookTriggered` | `hookCompleted` |
| **मनुष्य** | `humanWait` | `humanInput` |

तीन स्टैंडअलोन हैं: `error`, `humanPause`, `humanInterrupt`।

<Accordion title="हर मेथड के लिए हर फील्ड" icon="table">

हर मेथड भी `sessionId` और `agentId` लेता है, जो स्कोप आपके लिए भरते हैं। कुछ भी छोड़ा गया JSON `null` के रूप में भेजने के बजाय छोड़ा जाता है।

| मेथड | आवश्यक | वैकल्पिक |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

कोई भी अन्य कुंजी जो आप जोड़ते हैं एक कस्टम पेलोड फील्ड बन जाती है। कुछ भी फ्रेमवर्क-विशिष्ट `fw_*` को नेमस्पेस करें; एक नाम जो एक घोषित फील्ड के साथ टकराता है चुप्पी से एक प्रचारित कॉलम को ओवरराइट करने के बजाय अस्वीकार किया जाता है।

</Accordion>

<Warning>
  **`duration_ms` गणना की गई है, स्वीकृत नहीं।** चार बंद करने वाले मेथड अपने ओपनर से अंतराल को समय देते हैं और कॉलर-आपूरित `duration_ms` को अस्वीकार करते हैं — एक रिपोर्ट की गई अवधि अनुक्रमणीय है।

  जोड़े **सेशन** और आईडी पर मेल खाते हैं, कभी भी एजेंट पर नहीं। एक टूल जो `planner` के तहत खुला है और `worker` के तहत बंद है अभी भी मेल खाता है, जो नेस्टेड मल्टी-एजेंट रन वास्तव में करते हैं।
</Warning>

## फ्रेमवर्क एडाप्टर

```ts
await failproofai.instrument();              // जो भी यह पा सकता है
await failproofai.instrument("langchain");   // बिल्कुल एक
failproofai.uninstrument();                  // सब कुछ वापस रखो
```

| फ्रेमवर्क | समर्थित | यह कैसे जुड़ता है |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, इसलिए हर `invoke`/`stream`/`batch` बिना `callbacks:` कहीं भी पास किए कवर किया जाता है — या `langchainHandler()` को स्वयं पास करें और कुछ भी पैच न करें। |
| **Vercel AI SDK** | `ai` 4 – 7 | कॉल साइट पर `telemetry()`, या पूरी प्रक्रिया पर `ai` 7 के लिए `instrument("ai")` (4–6 पर वह ऑप्ट-इन है — नीचे देखें)। |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, एजेंट का मॉडल और टूल रेजोल्यूशन, और वर्कफ़्लो रन/स्टेप इंजन। |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (सदस्यता) साथ ही `AgentWorkflow.runStream`, वर्कफ़्लो रन और उनके स्टेप के लिए। |

हर रेंज को दोनों सिरों पर, ES मॉड्यूल के रूप में और CommonJS के रूप में, हर CI रन पर असली फ्रेमवर्क रिलीज के विरुद्ध परीक्षण किया जाता है।

मैपिंग Python SDK का है, इसलिए एक ही प्रोग्राम दोनों भाषाओं में एक ही पेड़ को खींचता है। एक निर्माण एक **एजेंट** है केवल अगर यह एक LLM निर्णय लूप का मालिक है — एक ग्राफ़ या चेन रन, एक AI SDK `generateText`/`streamText` कॉल, एक Mastra एजेंट, एक LlamaIndex एजेंट रन। एक LangGraph नोड या एक वर्कफ़्लो स्टेप एक **हुक** है (`hook_triggered`/`hook_completed`), कभी भी एक नेस्टेड एजेंट नहीं। मॉडल कॉल टोकन गणना के साथ `model_request`/`model_response` जोड़े हैं; टूल कॉल मॉडल की अपनी टूल कॉल आईडी ले जाते हैं। एक विफलता उस इवेंट पर एक बार रिकॉर्ड की जाती है जहां यह हुआ।

एक एडाप्टर जो इंस्टॉल नहीं हो सकता वह लॉग किया जाता है और छोड़ा जाता है; अन्य अभी भी इंस्टॉल होते हैं, क्योंकि एक टूटा हुआ LlamaIndex आपको LangGraph खर्च नहीं करना चाहिए।

<Note>
  कोई भी तर्क के बिना `instrument()` एक फ्रेमवर्क का पता लगाता है कि क्या यह पहले से आयात किया जाता है नहीं बल्कि क्या यह **हल करता है** — Node ES मॉड्यूल के लिए Python के `sys.modules` का कोई समतुल्य नहीं दिखाता है। एक फ्रेमवर्क जो आपके पास इंस्टॉल है लेकिन उपयोग नहीं करते हैं आयात और पैच किया जाएगा। यदि यह महत्वपूर्ण है तो आप जो चाहते हैं उसे नाम दें।
</Note>

<Note>
  इनमें से अधिकांश फ्रेमवर्क एक ES-मॉड्यूल बिल्ड और एक CommonJS बिल्ड शिप करते हैं, जो Node दो असंबंधित प्रतियों के रूप में लोड करता है। एडाप्टर उस प्रति को पैच करते हैं जो आपकी एप्लिकेशन लोड करती है (और CommonJS प्रति भी यदि कुछ पहले से ही इसे `require` कर चुका है), इसलिए दोनों मॉड्यूल सिस्टम काम करते हैं। एक फ्रेमवर्क **अपने स्वयं के आउटपुट में बंडल** esbuild या webpack द्वारा `instrument()` की पहुंच से बाहर है — कॉल-साइट हेल्पर वहां उपयोग करें: `langchainHandler()`, `telemetry()`, `wrapTool()`।
</Note>

### पैचिंग के बिना LangChain

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

हैंडलर `instrument()` के साथ या बिना काम करता है और कभी भी दोहराता नहीं है। `instrument("langchain")` `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` और `captureLimit` लेता है, जैसा कि Python एडाप्टर करता है; एक कॉल पर `metadata: { failproofai_sdk_session_id }` उस आह्वान के लिए सेशन चुनता है।

### Vercel AI SDK

AI SDK एक ES मॉड्यूल से सादे फ़ंक्शन निर्यात करता है, और एक ES मॉड्यूल नेमस्पेस विनिर्देश द्वारा अपरिवर्तनीय है — पैच करने के लिए कहीं नहीं है। यह एक्सटेंशन बिंदु का उपयोग करता है जो SDK स्वयं दस्तावेज करता है:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // ai 7 पर, `telemetry: telemetry({ … })` — समान ऑब्जेक्ट, नया नाम
});
```

यह संपूर्ण एकीकरण है: एक एजेंट स्पैन, प्रति चरण में टोकन गणना के साथ एक मॉडल अनुरोध/प्रतिक्रिया जोड़ी, और हर टूल कॉल। एक कॉल साइट हर प्रमुख पर काम करता है — `ai` 4–6 यह ले जाने वाले ट्रेसर को पढ़ते हैं, `ai` 7 टेलीमेट्री एकीकरण को।

`instrument("ai")` **`ai` 7 पर** एक ही बात करता है: हर कॉल, AI SDK के वैश्विक टेलीमेट्री-एकीकरण सूची के माध्यम से, जो योगात्मक है और किसी और के पास से कुछ भी नहीं लेता है।

**`ai` 4–6 पर, `instrument("ai")` अपने आप से कुछ भी रिकॉर्ड नहीं करता है, और एक चेतावनी कहता है।** एक ही प्रक्रिया-व्यापी हुक जो उन प्रमुखों के पास है वह वैश्विक OpenTelemetry ट्रेसर प्रोवाइडर है — एक एकल स्लॉट OpenTelemetry हाथ नहीं देगा एक बार। हमारे को रजिस्टर करने से आपके स्वयं के `NodeSDK.start()` को बाद में स्टार्टअप में चुप्पी से अस्वीकार कर दिया जाएगा और आपके http/डेटाबेस स्पैन को एक ट्रेसर में भेज दिया जाएगा जो कुछ भी निर्यात नहीं करता है। कॉल साइट पर `telemetry()` का उपयोग करें या `wrapModel` वहां। यदि प्रक्रिया अपना कोई OpenTelemetry नहीं चलाती है, तो `instrument("ai", { registerGlobalTracer: true })` के साथ ऑप्ट इन करें: यह तब हर कॉल रिकॉर्ड करता है जो `experimental_telemetry: { isEnabled: true }` पास करता है, और केवल स्लॉट लेता है यदि यह अभी भी खाली है। `registerGlobalTracer: false` डिफ़ॉल्ट रखता है और चेतावनी को शांत करता है।

यदि आप मॉडल को एक बार लपेटना पसंद करेंगे, तो `wrapModel` केवल मॉडल कॉल देखता है, क्योंकि टूल कॉल मॉडल परत के ऊपर होते हैं। एक ने इसके चारों ओर कुछ नहीं के साथ लपेटा गया मॉडल इसके अपने रन के रूप में रिकॉर्ड किया जाता है। एक स्ट्रीम किया गया कॉल बंद हो जाता है हालांकि स्ट्रीम कैसे रुकती है — `stop_reason: "cancelled"` जब उपभोक्ता इसे रद्द करता है, `"error"` त्रुटि के साथ जब यह आधा विफल हो जाता है:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

दोनों का उपयोग करना ठीक है: मिडलवेयर नोटिस करता है कि कॉल पहले से रिकॉर्ड किया जा रहा है और स्थगित हो जाता है, इसलिए हर कॉल एक बार रिकॉर्ड किया जाता है।

`functionId` एजेंट स्पैन को नाम देता है। इसे कम-कार्डिनैलिटी रखें — यह `agent_id` में आता है, प्राथमिक डैशबोर्ड पहलू।

### Next.js

`next build` डिफ़ॉल्ट रूप से आपके सर्वर की डिपेंडेंसी को बंडल करता है, और एक फ्रेमवर्क बिल्ड में बंडल किया गया `instrument()` तक पहुंचता है। कॉन्फ़िग को एक बार लपेटें और Next के स्टार्टअप हुक से `instrument()` को कॉल करें:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* आपकी कॉन्फ़िग */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` LangChain, Mastra, LlamaIndex और SDK को `serverExternalPackages` में जोड़ता है, अपनी सूची रखता है। इसके बिना, `instrument()` एक बार प्रति फ्रेमवर्क चेतावनी देता है जो यह चुप्पी से पहुंच नहीं सकता; यदि आप पैकेज को स्वयं सूचीबद्ध करते हैं, तो `FAILPROOFAI_NEXT_EXTERNALS=1` सेट करें। Vercel AI SDK और कॉल-साइट हेल्पर दोनों तरीकों में काम करते हैं। एक Edge रूट एक नो-ऑप बिल्ड प्राप्त करता है: SDK को आयात करना सुरक्षित है और कुछ भी रिकॉर्ड नहीं करता है।

### स्ट्रीम किए गए कॉल पर टोकन गणना

OpenAI-संगत API केवल तभी स्ट्रीम पर उपयोग की रिपोर्ट करते हैं जब क्लाइंट पूछता है। LangChain और Vercel AI SDK पूछते हैं; LlamaIndex के लिए `additionalChatOptions: { stream_options: { include_usage: true } }` को इसके `OpenAI` LLM पर पास करें, और Mastra के लिए उपयोग सक्षम के साथ मॉडल बनाएं (उदाहरण के लिए `createOpenAICompatible({ includeUsage: true })`)। अन्यथा स्ट्रीम किए गए मॉडल कॉल कोई टोकन गणना ले जाते हैं।

### रनटाइम

Node ≥ 20.9, Bun और Deno — हर फ्रेमवर्क, ES मॉड्यूल और CommonJS के रूप में, Node के ट्रेस के विरुद्ध प्रत्येक पर परीक्षण किया जाता है। SDK `failproofaid` डेमॉन के बगल में चलता है, जो जो कुछ लिखता है वह शिप करता है।

## आपका स्वयं का एजेंट — कोई फ्रेमवर्क नहीं

एक एजेंट लूप जो आपने स्वयं लिखा है, या एक फ्रेमवर्क जिसके बिना कोई एडाप्टर है। आप एडाप्टर के समान API के साथ इवेंट उत्सर्जन करते हैं जो अंतर्निहित रूप से उपयोग करते हैं, इसलिए ट्रेस में एक ही आकार और गुणवत्ता है।

आपको यह जानने की आवश्यकता नहीं है कि एजेंट कैसे आयोजित है। हर हाथ से बनाया गया एजेंट पहले से ही तीन स्थान है, जो भी इसके कार्य कहे जाते हैं, और वे तीन पूरा एकीकरण है:

| कहाँ | क्या जोड़ें | उत्सर्जन |
| --- | --- | --- |
| जहां **एक रन** शुरू और समाप्त होता है | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **एक फ़ंक्शन जो मॉडल को कॉल करता है** | `event.modelRequest` पहले, `event.modelResponse` बाद में — दोनों हिस्से, विफलता पर भी | एक जोड़ी प्रति मॉडल मोड़ |
| **एक फ़ंक्शन जो टूल चलाता है** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

पहचान परिवेश है: `agent()` के अंदर सब कुछ उस रन के सेशन पर बिना आईडी लिए उतरता है, और प्रोग्राम में कुछ और नहीं बदलता है — जिसमें जो कुछ भी एजेंट पहले से अपने स्वयं के डेटाबेस में लिखता है।

- **एक सेवा या एक कार्यकर्ता:** अपनी स्वयं की अनुरोध या नौकरी आईडी को `sessionId` के रूप में पास करें, इसलिए डैशबोर्ड पर एक सेशन और आपके स्वयं के लॉग या डेटाबेस में रिकॉर्ड एक ही स्ट्रिंग है।
- **उप-एजेंट:** `agent()` कॉल को नेस्ट करें। आंतरिक बाहरी के साथ सेशन में शामिल होता है, `parent_id` के रूप में।
- **जोड़े उत्सर्जन करें।** एक `modelRequest` कोई `modelResponse` के साथ एक स्पैन है जो डैशबोर्ड हमेशा के लिए चलता दिखाता है — इसलिए `catch`।

रिपॉजिटरी में [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) पूर्ण, चलने योग्य संस्करण है: एक असली OpenAI टूल लूप बिल्कुल ऐसे ही इंस्ट्रूमेंट, CI में हर परिवर्तन पर ES मॉड्यूल और CommonJS के रूप में चलाया गया।

## मूल्यांकन

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
  npx failproofai-evaluator ./my-evals.js
```

प्रोटोकॉल, कार्यकर्ता सेटिंग और परिणाम प्रकार के लिए [Evaluator SDK संदर्भ](/hi/reference/evaluator-sdk) देखें।

<Warning>
  **एक मूल्यांकन को प्राप्त करना चाहिए।** एक सिंक्रोनस फ़ंक्शन जो कभी नहीं लौटता Node का एकमात्र धागा ब्लॉक करता है, और यह कर रहा है जब कोई टाइमआउट फायर नहीं कर सकता। `async` मूल्यांकन लिखें।
</Warning>

## यह आपकी प्रक्रिया के साथ क्या नहीं करेगा

| | |
| --- | --- |
| **आपके एजेंट लूप को ब्लॉक करें** | इवेंट एक इन-मेमोरी कतार में जाते हैं; एक टाइमर उन्हें लिखता है। टाइमर `unref` किया जाता है, इसलिए इस पैकेज को आयात करना कभी भी एक स्क्रिप्ट से बाहर निकलने को नहीं रोकता है। |
| **बिना बाउंड बढ़ें** | कतार को गणना *और* मापी गई बाइट द्वारा कैप किया जाता है। दोनों के पीछे, सबसे पुरानी इवेंट को त्यागा जाता है और एक चेतावनी कहता है — एक टेलीमेट्री बाहरी एक OOM किल नहीं बन जाना चाहिए। |
| **प्रक्रिया को नीचे लाएं** | एक अकेने अकेले ड्रॉप किया जाता है, इसके चारों ओर बैच नहीं। एक फेंकने वाला गेटर, एक गोलाकार संदर्भ, एक `BigInt`, एक अकेली सरोगेट: प्रत्येक प्रसारित होने के बजाय संभाला जाता है। |
| **आधी-लिखी बैच छोड़ें** | सामग्री एक परमाणु नाम बदलने से पहले `fsync` की जाती है, निर्देशिका के बाद `fsync` की जाती है, और एक विफल लेखन अपनी अस्थायी फ़ाइल को साफ करता है। |
| **प्रतिलेख पाठ्य छोड़ें** | बैच एक `0700` निर्देशिका के अंदर `0600` हैं। वे लक्ष्य, संकेत, टूल तर्क और टूल आउटपुट ले जाते हैं। |
| **प्रमाण पत्र शिप करें** | API कुंजी, टोकन, JWT, सहन शीर्ष लेख और गुप्त-आकार के असाइनमेंट बाइट डिस्क तक पहुंचने से पहले संपादित किए जाते हैं। डेमॉन अपलोड से पहले फिर से संपादित करता है। |
