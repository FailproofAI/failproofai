</Note>

## इंस्टॉल करें

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

फ्रेमवर्क एडेप्टर्स पैकेज में ही शिप होते हैं। फ्रेमवर्क्स **वैकल्पिक पीयर डिपेंडेंसीज़** हैं — घोषित करते हैं ताकि समर्थित रेंज दिखाई दे, कभी आपकी ओर से इंस्टॉल न हों, और केवल तब आयात करें जब आप `instrument()` कॉल करें।

## Failproof डेमन से कनेक्ट करें

Python SDK के समान: **Admin → Keys** के तहत एक `events:add` कुंजी बनाएं, फिर [डेमन को कनेक्ट करें](/hi/start/setup#connect-a-machine-to-cloud) एजेंट मशीन पर। SDK डिस्क पर लिखता है; डेमन शिप करता है।

## कॉन्फ़िगरेशन

### OpenTelemetry स्पैन्स (ऑप्ट इन)

`npm install @opentelemetry/api @opentelemetry/sdk-trace-base` के साथ OpenTelemetry अलग से इंस्टॉल करें।
फिर अपने प्रदाता के प्रोसेसर्स में FailproofAI जोड़ें:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

मौजूदा प्रदाता के लिए, इसके अन्य प्रोसेसर्स को एक ही सूची में रखें। प्रदाता जो `addSpanProcessor` को सामने लाते हैं, इसके बजाय `{ provider }` के रूप में पास किए जा सकते हैं। विकल्पों के बिना, सेटअप एक नया प्रदाता रजिस्टर करता है केवल अगर कोई प्रदाता पहले से पंजीकृत नहीं है।
`OtelSpanExporter` को सीधे अपने प्रोसेसर के साथ भी उपयोग किया जा सकता है।

निर्यात कनेक्टेड FailproofAI डेमन के माध्यम से जाता है; SDK कोई नेटवर्क अनुरोध नहीं भेजता है और कोई कुंजी या स्थानीय श्रोता की जरूरत नहीं है। एक प्रशासक को [OpenTelemetry इंजेस्ट](/hi/agenteye/opentelemetry) को सक्षम करने के लिए कहें। एक बेयर `instrument()` इस एक्सपोर्टर को सक्षम नहीं करता है। `uninstrument("otel")` केवल अपना प्रोसेसर अक्षम करता है।
आपके स्पैन एट्रिब्यूट्स सामग्री कैप्चर को नियंत्रित करते हैं; निकास से पहले अपना प्रदाता फ्लश करें।
OpenTelemetry एक वैकल्पिक एप्लिकेशन निर्भरता ही रहता है, कठोर SDK निर्भरता नहीं।

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| विकल्प | यह क्या करता है |
| --- | --- |
| `environment` | हर इवेंट पर लेबल — `production`, `staging`, `prod-eu`। डिफ़ॉल्ट `dev` है। |
| `flushInterval` | टाइमर कितनी बार डिस्क पर लिखता है, सेकंड में। डिफ़ॉल्ट `0.5` है। |
| `baseDir` | कहां लिखें। डिफ़ॉल्ट डेमन का स्पूल है, जो आप चाहते हैं जब तक आप अन्यथा नहीं जानते। |

कुछ भी लागू नहीं होता जब तक सब कुछ मान्य हो, इसलिए एक अस्वीकृत कॉल SDK को बिल्कुल वैसे छोड़ देता है जैसे वह था न कि नई `baseDir` और पुरानी अंतराल के साथ।

इसके बजाय पर्यावरण चर द्वारा सेट करें:

| चर | यह क्या करता है |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | कोड परिवर्तन के बिना `environment` सेट करता है। एक `configure()` विकल्प इसे जीतता है। |
| `FAILPROOFAI_HOME` | Failproof AI रूट को स्थानांतरित करता है जो स्पूल रखता है। |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (डिफ़ॉल्ट), `error`, `silent`। |
| `FAILPROOFAI_SDK_STRICT` | `1` इंस्ट्रूमेंटेशन त्रुटियों को लॉग किए जाने के बजाय फेंक देता है। |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` एक फ्रेमवर्क-संगतता समस्या को चेतावनी देने और आगे बढ़ने के बजाय फेंकता है। |

<Warning>
  **`environment` में कोई अल्पविराम नहीं।** इंजेस्ट उस फील्ड को अल्पविराम पर विभाजित करता है अपने फ़िल्टर बनाने के लिए, और किसी भी इवेंट को छोड़ देता है जिसका लेबल एक सामग्री है — इसलिए एक पूरा रन चुपचाप गायब हो जाता है। `prod-eu` लिखें, `prod,eu` नहीं।

  `configure({ environment: "prod,eu" })` फेंकता है ताकि आप तुरंत पता लगाएं। `AGENTEYE_ENVIRONMENT` नहीं फेंक सकता — कोई आपको कॉल नहीं कर रहा है — इसलिए यह एक बार चेतावनी देता है और `dev` में वापस आता है।
</Warning>

SDK की अपनी लॉग लाइनों को अपने लॉगर में `failproofai.setLogger({ debug, info, warn, error })` के साथ रूट करें।

## शटडाउन

बफर किए गए इवेंट्स `process.on("exit")` पर फ्लश किए जाते हैं।

एक प्रक्रिया जो एक सिग्नल द्वारा मारी जाती है वह कभी नहीं पहुंचती, और `SIGTERM` के लिए Node का डिफ़ॉल्ट बिना निकास हैंडलर चलाए समाप्त करना है — इसलिए एक कंटेनरयुक्त एजेंट जो आखिरी अंतराल नहीं लिखा था वह खो देता है।

<Warning>
  **यह SDK आपके लिए एक सिग्नल हैंडलर इंस्टॉल नहीं करेगा।** एक रजिस्टर करना आपकी प्रक्रिया के व्यवहार को बदलता है: एक श्रोता Node के डिफ़ॉल्ट समाप्ति को दबाता है, इसलिए एक लाइब्रेरी जो एक जोड़ता तो चुप से Ctrl-C को काम करने से रोकता। अपना खुद का जोड़ें:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

एक अल्पकालिक स्क्रिप्ट या एक सर्वरलेस हैंडलर को वापस लौटने से पहले `await failproofai.flush()` करना चाहिए — अंतराल अकेले डिलीवरी की गारंटी नहीं देता है।

## पहचान

हर इवेंट एक सेशन और एक एजेंट से संबंधित है। **स्कोप्स दोनों को भरते हैं**, इसलिए आप शायद ही कभी उन्हें पास करते हैं:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId` या `agentId` स्पष्ट रूप से पास करना अभी भी काम करता है और जीतता है। न बाध्य न पास किए गए साथ, कॉल फेंकता है बजाय Cloud चुपचाप त्याग दिए जाने वाले एक इवेंट को उत्सर्जित करने के।

<Note>
  पहचान `AsyncLocalStorage` पर चलती है। यह `await`, `.then()`, टाइमर और स्कोप के अंदर बनाए गए किसी भी कॉलबैक का पालन करता है। यह **एक रन के दौरान संग्रहीत और दूसरे के दौरान आमंत्रित कॉलबैक का पालन नहीं करता है**, या एक `worker_threads` सीमा के पार सौंपा गया काम — उन्हें `failproofai.propagate()` में लपेटें या उनके इवेंट्स अनुलग्न रहते हैं।
</Note>

### स्कोप्स

| स्कोप | उत्सर्जन करता है | रिटर्न्स |
| --- | --- | --- |
| `session(body)` | कुछ नहीं — केवल पहचान | जो कुछ `body` रिटर्न करता है |
| `agent(id, options?, body)` | `agent_start`, फिर `agent_end` | जो कुछ `body` रिटर्न करता है |
| `toolCall(name, options?, body)` | `tool_use`, फिर `tool_result` | जो कुछ `body` रिटर्न करता है |

एक सिंक्रोनस बॉडी सिंक्रोनस रहती है: `agent("x", () => 1)` `1` रिटर्न करता है, प्रॉमिस नहीं।

`toolCall` बॉडी की हल किए गए वैल्यू को टूल के `output` के रूप में रिकॉर्ड करता है, जब तक आप `call.output` को स्वयं असाइन नहीं करते।

<Accordion title="निकास सिमेंटिक्स" icon="arrow-right-from-bracket">

| क्या हुआ | इवेंट्स | `outcome` |
| --- | --- | --- |
| ब्लॉक लौटा | `agent_end` | `"success"`, या आपका `outcome` |
| ब्लॉक फेंका | `error`, फिर `agent_end` | `"failed"` |
| एक `AbortError` | केवल `agent_end` | `"cancelled"` |

त्रुटि हमेशा फिर से फेंकी जाती है।

एक टूल विफलता पत्ती पर रिकॉर्ड किया जाता है — `tool_result` एक `error` स्ट्रिंग के साथ — और कोई चलाएं-स्तरीय `error` इवेंट **नहीं** उत्सर्जित करता है। एक जो एजेंट लूप पकड़ता है वह चलाने की विफलता नहीं है, और एक जो प्रसारित होता है वह बिल्कुल एक बार रिपोर्ट किया जाता है, संलग्न `agent()` द्वारा।

</Accordion>

<Accordion title="The `using` form" icon="brackets-curly">

जब काम एक एकल फ़ंक्शन नहीं है — एक स्कोप कंस्ट्रक्टर में खोला और टियरडाउन में बंद, या एक जो मौजूदा नियंत्रण प्रवाह को स्ट्राडल करता है:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

दोनों रूप बाइट-समान इवेंट्स उत्सर्जित करते हैं। कॉलबैक फॉर्म को प्राथमिकता दें: यह `AsyncLocalStorage.run()` के अंदर चलता है, इसलिए अनवाइंड करने के लिए कुछ नहीं है और पूरी opening here, closed over there" बग्स की क्लास अप्राप्य है।

एक `using` ब्लॉक जो अपनी अपनी विफलता को पकड़ता है वह इसे `span.fail(error)` के साथ रिपोर्ट करता है — डिस्पोजर के पास अपना अपना अपवाद चैनल नहीं है।

</Accordion>

## इवेंट कैटलॉग

Python SDK के समान पंद्रह मेथड्स, camelCase में। अधिकांश **जोड़ी में** आते हैं — आप ओपनर कॉल करते हैं, फिर क्लोजर, और SDK अंतराल को समय देता है।

| | खोलता है | बंद करता है |
| --- | --- | --- |
| **एजेंट्स** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **मॉडल्स** | `modelRequest` | `modelResponse` |
| **टूल्स** | `toolUse` | `toolResult` |
| **हुक्स** | `hookTriggered` | `hookCompleted` |
| **मनुष्य** | `humanWait` | `humanInput` |

तीन अकेले खड़े हैं: `error`, `humanPause`, `humanInterrupt`।

<Accordion title="हर फील्ड, प्रति मेथड" icon="table">

हर मेथड भी `sessionId` और `agentId` लेता है, जो स्कोप्स आपके लिए भरते हैं। कुछ भी छोड़ा हुआ JSON `null` के रूप में भेजे जाने के बजाय ड्रॉप किया जाता है।

| मेथड | आवश्यक | वैकल्पिक |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

कोई अन्य कुंजी जो आप जोड़ते हैं एक कस्टम पेलोड फील्ड बन जाती है। किसी भी फ्रेमवर्क-विशिष्ट को `fw_*` नेमस्पेस करें; एक नाम जो घोषित फील्ड के साथ टकराता है उसे स्वचालित रूप से अधिलेखन करने के बजाय अस्वीकार किया जाता है।

</Accordion>

<Warning>
  **`duration_ms` कंप्यूट किया जाता है, स्वीकार नहीं किया जाता।** चार समापन मेथड्स अपने ओपनर से अंतराल को समय देते हैं और एक कॉलर-आपूर्ति की गई `duration_ms` को अस्वीकार करते हैं — एक रिपोर्ट किया हुआ अवधि unfalsifiable है।

  जोड़ी एजेंट पर कभी आईडी पर **सेशन** और आईडी पर मेल खाई जाती है। एक टूल `planner` के तहत खोला गया और `worker` के तहत बंद किया गया अभी भी जोड़ी बनाता है, जो नेस्टेड मल्टी-एजेंट रन्स वास्तव में करते हैं।
</Warning>

## फ्रेमवर्क एडेप्टर्स

```ts
await failproofai.instrument();              // जो कुछ भी यह खोज सकता है
await failproofai.instrument("langchain");   // बिल्कुल एक
failproofai.uninstrument();                  // सब कुछ वापस डालें
```

| फ्रेमवर्क | समर्थित | यह कैसे जुड़ता है |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, इसलिए हर `invoke`/`stream`/`batch` `callbacks:` कहीं भी पास किए बिना कवर किया जाता है — या `langchainHandler()` को स्वयं पास करें और कुछ भी पैच न करें। |
| **Vercel AI SDK** | `ai` 4 – 7 | कॉल साइट पर `telemetry()`, या `ai` 7 पर पूरी प्रक्रिया के लिए `instrument("ai")` (4–6 पर जो ऑप्ट-इन है — नीचे देखें)। |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, एजेंट का मॉडल और टूल रेजोल्यूशन, और वर्कफ़्लो रन/स्टेप इंजन। |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (सदस्यता) प्लस `AgentWorkflow.runStream`, वर्कफ़्लो रन और उनके चरणों के लिए। |

हर रेंज वास्तविक फ्रेमवर्क रिलीज के खिलाफ, दोनों सिरों पर, ES मॉड्यूल के रूप में और CommonJS के रूप में, हर CI रन पर परीक्षण की जाती है।

मैपिंग Python SDK की है, इसलिए एक ही प्रोग्राम किसी भी भाषा में एक ही पेड़ खींचता है। एक कंस्ट्रक्ट एक **एजेंट** है केवल अगर यह एक LLM निर्णय लूप के मालिक है — एक ग्राफ या चेन रन, एक AI SDK `generateText`/`streamText` कॉल, एक Mastra एजेंट, एक LlamaIndex एजेंट रन। एक LangGraph नोड या एक वर्कफ़्लो स्टेप एक **हुक** है (`hook_triggered`/`hook_completed`), कभी एक नेस्टेड एजेंट नहीं। मॉडल कॉल्स `model_request`/`model_response` जोड़ी हैं टोकन काउंट्स के साथ; टूल कॉल्स मॉडल की अपनी टूल कॉल आईडी ले जाते हैं। एक विफलता इवेंट पर एक बार रिकॉर्ड की जाती है यह हुआ।

एक एडेप्टर जो इंस्टॉल करने में विफल हो गया है लॉग किया जाता है और छोड़ दिया जाता है; बाकी अभी भी इंस्टॉल करते हैं, क्योंकि एक टूटा हुआ LlamaIndex आपको LangGraph की कीमत नहीं देना चाहिए।

<Note>
  कोई तर्क के साथ `instrument()` एक फ्रेमवर्क **का पता लगाता है क्या यह resolve करता है**, चाहे वह पहले से import हो — Node ES मॉड्यूल्स के लिए Python के `sys.modules` के बराबर को उजागर नहीं करता। एक फ्रेमवर्क जो आपके पास इंस्टॉल है लेकिन उपयोग नहीं करते हैं उसे आयात और पैच किया जाएगा। यदि वह महत्वपूर्ण हो तो जो आप चाहते हैं उसे नाम दें।
</Note>

<Note>
  अधिकांश ये फ्रेमवर्क्स एक ES-मॉड्यूल बिल्ड और एक CommonJS बिल्ड शिप करते हैं, जो Node दो असंबंधित कॉपीज़ के रूप में लोड करता है। एडेप्टर्स उस कॉपी को पैच करते हैं जिसे आपकी एप्लिकेशन लोड करती है (और CommonJS कॉपी भी यदि कुछ पहले से ही इसे `require` कर चुका है), इसलिए दोनों मॉड्यूल सिस्टम काम करते हैं। एक फ्रेमवर्क **अपने खुद के आउटपुट में बंडल** esbuild या webpack द्वारा अप्राप्य है — कॉल-साइट हेल्पर्स वहां उपयोग करें: `langchainHandler()`, `telemetry()`, `wrapTool()`।
</Note>

### पैचिंग के बिना LangChain

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

हैंडलर `instrument()` के साथ या बिना काम करता है और कभी दोहराता नहीं है। `instrument("langchain")` `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` और `captureLimit` लेता है, जैसे Python एडेप्टर करता है; एक कॉल पर `metadata: { failproofai_sdk_session_id }` उस आह्वान के लिए सेशन लेता है।

### Vercel AI SDK

AI SDK ES मॉड्यूल से सादे फ़ंक्शन्स निर्यात करता है, और एक ES मॉड्यूल नेमस्पेस विशेष द्वारा immutable है — पैच करने के लिए कहीं नहीं है। यह विस्तार बिंदु उपयोग करता है SDK स्वयं दस्तावेज:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // on ai 7, `telemetry: telemetry({ … })` — the same object, the new name
});
```

वह संपूर्ण एकीकरण है: एक एजेंट स्पैन, प्रति चरण एक मॉडल अनुरोध/प्रतिक्रिया जोड़ी टोकन काउंट्स के साथ, और हर टूल कॉल। एक कॉल साइट हर प्रमुख पर काम करता है — `ai` 4–6 यह ले जाता है tracer को पढ़ते हैं, `ai` 7 telemetry एकीकरण।

`instrument("ai")` **`ai` 7 पर** समान प्रक्रिया-व्यापी करता है: हर कॉल, AI SDK के वैश्विक telemetry-एकीकरण सूची के माध्यम से, जो योज्य है और किसी और के कुछ नहीं लेता।

**`ai` 4–6 पर, `instrument("ai")` अपने आप से कुछ नहीं रिकॉर्ड करता है, और एक चेतावनी लॉग करता है यह कहता है।** एकमात्र प्रक्रिया-व्यापी हुक वह प्रमुखों के पास वैश्विक OpenTelemetry tracer प्रदाता है — एक एकल स्लॉट OpenTelemetry एक बार हाथ पर देने से इनकार करता है लिया। हमारे को पंजीकृत करना अपने `NodeSDK.start()` बाद में स्टार्टअप को चुप करता है अस्वीकार करेगा और आपके http/डेटाबेस स्पैन्स को एक tracer में भेजेगा जो कुछ भी निर्यात नहीं करता। कॉल साइट पर `telemetry()` या `wrapModel` वहां उपयोग करें। यदि प्रक्रिया अपना खुद का OpenTelemetry नहीं चलाती, `instrument("ai", { registerGlobalTracer: true })` के साथ ऑप्ट इन करें: यह तब हर कॉल रिकॉर्ड करता है जो `experimental_telemetry: { isEnabled: true }` पास करता है, और केवल स्लॉट लेता है यदि यह अभी भी खाली है। `registerGlobalTracer: false` डिफ़ॉल्ट रखता है और चेतावनी को खामोश करता है।

यदि आप एक बार मॉडल लपेटना पसंद करेंगे, `wrapModel` केवल मॉडल कॉल्स दिखता है, क्योंकि टूल कॉल्स मॉडल परत के ऊपर होते हैं। कुछ नहीं के साथ लपेटा हुआ मॉडल अपने खुद के रन के रूप में रिकॉर्ड किया जाता है। एक स्ट्रीम किए गए कॉल को बंद करता है हालांकि स्ट्रीम रुकता है — `stop_reason: "cancelled"` जब उपभोक्ता इसे रद्द करता है, `"error"` त्रुटि के साथ जब यह आधा विफल हो:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

दोनों उपयोग करना ठीक है: मिडलवेयर कॉल पहले से रिकॉर्ड किया जा रहा है यह ध्यान देता है और आस्थगित करता है, इसलिए हर कॉल एक बार रिकॉर्ड किया जाता है।

`functionId` एजेंट स्पैन को नाम देता है। इसे कम-cardinality रखें — यह `agent_id` में उतरता है, प्राथमिक डैशबोर्ड पहलू।

### Next.js

`next build` डिफ़ॉल्ट रूप से अपने सर्वर की निर्भरताओं को बंडल करता है, और एक फ्रेमवर्क बिल्ड में बंडल किया गया `instrument()` तक पहुंच नहीं सकता है। कॉन्फ़िग एक बार लपेटें और Next के स्टार्टअप हुक से `instrument()` कॉल करें:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` LangChain, Mastra, LlamaIndex और SDK को स्वयं `serverExternalPackages` में जोड़ता है, आपकी सूची रखते हुए। इसके बिना, `instrument()` एक बार प्रति फ्रेमवर्क चेतावनी देता है यह तक नहीं पहुंच सकता बजाय चुप से विफल होने के; यदि आप पैकेज स्वयं सूचीबद्ध करते हैं, `FAILPROOFAI_NEXT_EXTERNALS=1` सेट करें। Vercel AI SDK और कॉल-साइट हेल्पर्स दोनों तरीकों से काम करते हैं। एक Edge रूट एक no-op बिल्ड प्राप्त करता है: SDK आयात करना सुरक्षित है और कुछ भी रिकॉर्ड नहीं करता है।

### स्ट्रीम किए गए कॉल्स पर टोकन काउंट्स

OpenAI-संगत API केवल एक स्ट्रीम पर उपयोग रिपोर्ट करता है जब क्लायंट मांगता है। LangChain और Vercel AI SDK मांगते हैं; LlamaIndex के लिए `additionalChatOptions: { stream_options: { include_usage: true } }` को अपने `OpenAI` LLM में पास करें, और Mastra के लिए मॉडल को उपयोग सक्षम के साथ बनाएं (उदाहरण के लिए `createOpenAICompatible({ includeUsage: true })`)। अन्यथा स्ट्रीम किए गए मॉडल कॉल्स कोई टोकन काउंट्स नहीं ले जाते हैं।

### रनटाइम्स

Node ≥ 20.9, Bun और Deno — हर फ्रेमवर्क, एक ES मॉड्यूल के रूप में और CommonJS के रूप में, Node के ट्रेस के विरुद्ध हर पर परीक्षण किया जाता है। SDK `failproofaid` डेमन के बगल में चलता है, जो यह लिखता है शिप करता है।

## आपका अपना एजेंट — कोई फ्रेमवर्क नहीं

एक एजेंट लूप आप स्वयं लिखते हैं, या एक फ्रेमवर्क के बिना एडेप्टर। आप एडेप्टर्स के अंदर एक ही API के साथ इवेंट्स उत्सर्जित करते हैं, इसलिए ट्रेस एक ही आकार और गुणवत्ता है।

आपको यह जानने की जरूरत नहीं है एजेंट कैसे संगठित है। हर हाथ से बनाया गया एजेंट पहले से ही तीन जगहें है, चाहे इसके फ़ंक्शन्स को क्या कहा जाए, और ये तीन पूरा एकीकरण हैं:

| जहां | क्या जोड़ें | उत्सर्जन करता है |
| --- | --- | --- |
| जहां **एक रन** शुरू और समाप्त होता है | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **एकमात्र फ़ंक्शन जो मॉडल कॉल करता है** | `event.modelRequest` से पहले, `event.modelResponse` बाद में — विफलता पर भी दोनों आधे | प्रति मॉडल टर्न एक जोड़ी |
| **एकमात्र फ़ंक्शन जो टूल्स चलाता है** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

पहचान ambient है: `agent()` के अंदर सब कुछ उस रन के सेशन पर उतरता है बिना एक आईडी लिए, और प्रोग्राम में कुछ भी अन्य नहीं बदलता है — जिसमें जो कुछ एजेंट पहले से अपने खुद के डेटाबेस में लिखता है।

- **एक सेवा या एक वर्कर:** अपनी अनुरोध या जॉब आईडी `sessionId` के रूप में पास करें, इसलिए डैशबोर्ड पर एक सेशन और आपके अपने लॉग्स या डेटाबेस में रिकॉर्ड एक ही स्ट्रिंग हैं।
- **सब-एजेंट्स:** `agent()` कॉल नेस्ट करें। आंतरिक बाहरी के साथ सेशन जुड़ता है इसके `parent_id` के रूप में।
- **जोड़ी उत्सर्जित करें।** एक `modelRequest` कोई `modelResponse` के साथ एक स्पैन है डैशबोर्ड हमेशा के लिए चलने के रूप में दिखाता है — इसलिए `catch`।

रिपोजिटरी में [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) संपूर्ण, चलाने योग्य संस्करण है: एक वास्तविक OpenAI टूल लूप बिल्कुल इसी तरह इंस्ट्रूमेंट किया गया, CI पर हर परिवर्तन पर ES मॉड्यूल के रूप में और CommonJS के रूप में चलाया गया।

## मूल्यांकन

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

प्रोटोकॉल, वर्कर सेटिंग्स और परिणाम प्रकारों के लिए [Evaluator SDK संदर्भ](/hi/reference/evaluator-sdk) देखें।

<Warning>
  **एक मूल्यांकन उपज करना चाहिए।** एक सिंक्रोनस फ़ंक्शन जो कभी नहीं लौटता Node के पास एकमात्र थ्रेड को ब्लॉक करता है, और कोई टाइमआउट भी इसके दौरान नहीं आग कर सकता। `async` मूल्यांकन लिखें।
</Warning>

| **बिना बाध्य बढ़ें** | कतार काउंट **और** मापा गए बाइट्स द्वारा कैप किया जाता है। किसी भी बिंदु को पार करते हुए, सबसे पुरानी इवेंट्स त्याग दी जाती हैं और एक चेतावनी कहती है — एक टेलीमेट्री आउटेज OOM किल नहीं बनना चाहिए। |
| **प्रक्रिया को नीचे लें** | एक unencodable इवेंट अकेले त्याग दिया जाता है, इसके चारों ओर बैच नहीं। एक फेंकने वाला getter, एक परिपत्र संदर्भ, एक `BigInt`, एक अकेला सरोगेट: हर एक हैंडल किया जाता है प्रचारित होने के बजाय। |
| **आधा-लिखी बैच छोड़ें** | सामग्री `fsync`'d है एक atomic rename से पहले, निर्देशिका है `fsync`'d बाद में, और एक विफल लिखना अपनी अस्थायी फाइल को साफ करता है। |
| **ट्रांसक्रिप्ट्स को पठनीय छोड़ें** | बैच्स `0600` एक `0700` निर्देशिका के अंदर हैं। वे लक्ष्य, प्रॉम्प्ट्स, टूल तर्क और टूल आउटपुट ले जाते हैं। |
| **साख शिप करें** | API कुंजीें, टोकन्स, JWTs, bearer हेडर्स और रहस्य-आकार की असाइनमेंट्स डिस्क तक पहुंचने से पहले संपादित किए जाते हैं। डेमन अपलोड से पहले फिर से संपादित करता है। |
