Node 20.9 या नया। ESM और CommonJS। कोई रनटाइम डिपेंडेंसीज नहीं।

<Note>
  यह SDK और Python वाला **एक ही स्पूल में एक ही इवेंट्स लिखते हैं**। Node एजेंट्स और Python एजेंट्स के साथ एक फ्लीट एक सेट सेशन्स बनाता है, दो नहीं, और डैशबोर्ड में कुछ भी उन्हें अलग नहीं करता। प्रति सर्विस चुनें, प्रति कंपनी नहीं।
</Note>

## इंस्टॉल करें

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

फ्रेमवर्क एडाप्टर्स पैकेज में ही शिप होते हैं। फ्रेमवर्क्स **ऑप्शनल पीयर डिपेंडेंसीज** हैं — घोषित किए गए ताकि समर्थित रेंज दिखें, कभी भी आपकी ओर से इंस्टॉल न हों, और केवल तब आयात किए जाएं जब आप `instrument()` को कॉल करें।

## Failproof डेमन से कनेक्ट करें

Python SDK के समान: **Admin → Keys** के तहत एक `events:add` कुंजी बनाएं, फिर [डेमन को कनेक्ट करें](/hi/start/setup#connect-a-machine-to-cloud) एजेंट मशीन पर। SDK डिस्क पर लिखता है; डेमन शिप करता है।

## कॉन्फ़िगरेशन

### OpenTelemetry स्पैन्स (ऑप्ट इन)

`npm install @opentelemetry/api @opentelemetry/sdk-trace-base` के साथ OpenTelemetry को अलग से इंस्टॉल करें।
फिर FailproofAI को अपने प्रोवाइडर के प्रोसेसर्स में जोड़ें:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

एक मौजूदा प्रोवाइडर के लिए, इसके अन्य प्रोसेसर्स को एक ही सूची में रखें। प्रोवाइडर्स जो `addSpanProcessor` को एक्सपोज़ करते हैं उसके बजाय `{ provider }` के रूप में पास किए जा सकते हैं। बिना विकल्पों के, सेटअप एक नया प्रोवाइडर रजिस्टर करता है केवल अगर कोई प्रोवाइडर पहले से रजिस्टर नहीं है।
`OtelSpanExporter` को सीधे अपने स्वयं के प्रोसेसर के साथ भी उपयोग किया जा सकता है।

Exports कनेक्ट किए गए FailproofAI डेमन के माध्यम से जाते हैं; SDK कोई नेटवर्क रिक्वेस्ट भेजता नहीं है और कुंजी या स्थानीय श्रोता की आवश्यकता नहीं है। एक एडमिन से [OpenTelemetry ingest](/hi/agenteye/opentelemetry) को सक्षम करने के लिए कहें। एक बेयर `instrument()` इस एक्सपोर्टर को सक्षम नहीं करता। `uninstrument("otel")` केवल अपने प्रोसेसर को अक्षम करता है।
आपके स्पैन एट्रिब्यूट्स कंटेंट कैप्चर नियंत्रित करते हैं; एक्जिट से पहले अपने प्रोवाइडर को फ्लश करें।
OpenTelemetry एक ऑप्शनल एप्लिकेशन डिपेंडेंसी रहता है, कठोर SDK डिपेंडेंसी नहीं।

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| विकल्प | यह क्या करता है |
| --- | --- |
| `environment` | हर इवेंट पर लेबल — `production`, `staging`, `prod-eu`। डिफ़ॉल्ट है `dev`। |
| `flushInterval` | टाइमर कितनी बार डिस्क पर लिखता है, सेकंड में। डिफ़ॉल्ट है `0.5`। |
| `baseDir` | कहां लिखें। डेमन के स्पूल को डिफ़ॉल्ट करता है, जो वह है जो आप चाहते हैं जब तक आप अन्यथा जानते हैं। |

कुछ भी लागू नहीं होता जब तक यह सभी सत्यापित न हो जाए, तो एक अस्वीकृत कॉल SDK को बिल्कुल वैसे छोड़ देता है जैसे यह था, एक नए `baseDir` और पुराने अंतराल के साथ के बजाय।

इसके बजाय पर्यावरण चर द्वारा सेट करें:

| वेरिएबल | यह क्या करता है |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | कोड परिवर्तन के बिना `environment` सेट करता है। एक `configure()` विकल्प इसे जीतता है। |
| `FAILPROOFAI_HOME` | Failproof AI रूट को स्थानांतरित करता है जो स्पूल रखता है। |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (डिफ़ॉल्ट), `error`, `silent`। |
| `FAILPROOFAI_SDK_STRICT` | `1` इंस्ट्रूमेंटेशन त्रुटियों को लॉग किए जाने के बजाय फेंकता है। |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` एक फ्रेमवर्क-संगतता समस्या को चेतावनी देने और जारी रखने के बजाय फेंकता है। |

<Warning>
  **`environment` में कोई अल्पविराम नहीं।** Ingest उस फील्ड को अल्पविराम पर विभाजित करता है अपने फ़िल्टर्स बनाने के लिए, और किसी भी इवेंट को छोड़ देता है जिसका लेबल एक शामिल करता है — तो एक पूरा रन चुप चाप गायब हो जाता है। `prod-eu` लिखें, `prod,eu` नहीं।

  `configure({ environment: "prod,eu" })` फेंकता है तो आप तुरंत पता चल जाए। `AGENTEYE_ENVIRONMENT` नहीं फेंक सकता — कुछ आपको कॉल नहीं कर रहा है — तो यह एक बार चेतावनी देता है और `dev` पर वापस गिरता है।
</Warning>

SDK की अपनी लॉग लाइनें अपने लॉगर में रूट करें `failproofai.setLogger({ debug, info, warn, error })` के साथ।

## शटडाउन

बफ़र्ड इवेंट्स `process.on("exit")` पर फ्लश किए जाते हैं।

एक सिग्नल द्वारा मार दी गई प्रक्रिया कभी वहां नहीं पहुंचती, और `SIGTERM` के लिए Node की डिफ़ॉल्ट एक्जिट हैंडलर्स को चलाए बिना समाप्त करना है — तो एक कंटेनरीकृत एजेंट जो खो देता है वह अंतिम अंतराल लिख नहीं पाया था।

<Warning>
  **यह SDK आपके लिए एक सिग्नल हैंडलर इंस्टॉल नहीं करेगा।** एक को रजिस्टर करना आपकी प्रक्रिया के व्यवहार को बदलता है: एक श्रोता Node की डिफ़ॉल्ट समाप्ति को दबाता है, तो एक लाइब्रेरी जो एक जोड़ता था चुप चाप Ctrl-C को काम करना बंद कर देगा। अपना जोड़ें:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

एक अल्पकालिक स्क्रिप्ट या सर्वरलेस हैंडलर को रिटर्न से पहले `await failproofai.flush()` करना चाहिए — अंतराल अकेले डिलीवरी की गारंटी नहीं देता।

## आइडेंटिटी

हर इवेंट एक सेशन और एक एजेंट से संबंधित है। **स्कोप्स दोनों को भरते हैं**, तो आप शायद ही कभी उन्हें पास करते हैं:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId` या `agentId` को स्पष्ट रूप से पास करना अभी भी काम करता है और जीतता है। न बाउंड और न ही पास के साथ, कॉल फेंकता है, एक इवेंट उत्सर्जन के बजाय Cloud चुप चाप त्यागेंगे।

<Note>
  Identity `AsyncLocalStorage` पर सवारी करता है। यह `await`, `.then()`, टाइमर्स और स्कोप के अंदर बनाए गए किसी भी कॉलबैक का पालन करता है। यह एक रन के दौरान संग्रहीत और दूसरे के दौरान लागू एक कॉलबैक का पालन **नहीं** करता है, या `worker_threads` की सीमा के पार हाथ से काम नहीं करता — उन्हें `failproofai.propagate()` में लपेटें या उनके इवेंट्स अलग संलग्न होते हैं।
</Note>

### स्कोप्स

| स्कोप | उत्सर्जन | रिटर्न |
| --- | --- | --- |
| `session(body)` | कुछ नहीं — केवल आइडेंटिटी | जो `body` रिटर्न करता है |
| `agent(id, options?, body)` | `agent_start`, फिर `agent_end` | जो `body` रिटर्न करता है |
| `toolCall(name, options?, body)` | `tool_use`, फिर `tool_result` | जो `body` रिटर्न करता है |

एक सिंक्रोनस बॉडी सिंक्रोनस रहता है: `agent("x", () => 1)` `1` रिटर्न करता है, एक वादा नहीं।

`toolCall` बॉडी के रिज़ॉल्व किए गए मान को टूल के `output` के रूप में रिकॉर्ड करता है, जब तक आप `call.output` को अपने आप असाइन न करें।

<Accordion title="निकास शब्दार्थ" icon="arrow-right-from-bracket">

| क्या हुआ | इवेंट्स | `outcome` |
| --- | --- | --- |
| ब्लॉक रिटर्न किया | `agent_end` | `"success"`, या आपका `outcome` |
| ब्लॉक फेंका | `error`, फिर `agent_end` | `"failed"` |
| एक `AbortError` | केवल `agent_end` | `"cancelled"` |

त्रुटि हमेशा फिर से फेंकी जाती है।

एक टूल विफलता लीफ पर रिकॉर्ड की जाती है — `tool_result` एक `error` स्ट्रिंग के साथ — और **कोई** रन-स्तरीय `error` इवेंट उत्सर्जित नहीं करता है। एक जो एजेंट लूप पकड़ता है वह एक रन विफलता नहीं है, और एक जो प्रसारित होता है बिल्कुल एक बार रिपोर्ट किया जाता है, संलग्न `agent()` द्वारा।

</Accordion>

<Accordion title="`using` फॉर्म" icon="brackets-curly">

जब काम एक एकल फ़ंक्शन नहीं है — एक कंस्ट्रक्टर में खोला गया स्कोप और टियरडाउन में बंद, या एक जो मौजूदा नियंत्रण प्रवाह को पार करता है:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, फिर agent_end
```

दोनों फॉर्म बाइट-समान इवेंट्स उत्सर्जित करते हैं। कॉलबैक फॉर्म को प्राथमिकता दें: यह `AsyncLocalStorage.run()` के अंदर चलता है, तो कुछ भी अनवाइंड करने के लिए नहीं है और संपूर्ण वर्ग का "यहां खोला, वहां बंद" बग अप्राप्य है।

एक `using` ब्लॉक जो अपनी स्वयं की विफलता को पकड़ता है इसे `span.fail(error)` के साथ रिपोर्ट करता है — डिस्पोजर के पास अपना कोई अपवाद चैनल नहीं है।

</Accordion>

## इवेंट कैटलॉग

Python SDK के समान पंद्रह मेथड्स, camelCase में। अधिकांश **जोड़े** में आते हैं — आप ओपनर को कॉल करते हैं, फिर क्लोजर, और SDK गैप को समय देता है।

| | खोलता है | बंद करता है |
| --- | --- | --- |
| **एजेंट्स** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **मॉडल्स** | `modelRequest` | `modelResponse` |
| **टूल्स** | `toolUse` | `toolResult` |
| **हुक्स** | `hookTriggered` | `hookCompleted` |
| **ह्यूमन्स** | `humanWait` | `humanInput` |

तीन अकेले खड़े हैं: `error`, `humanPause`, `humanInterrupt`।

<Accordion title="हर फील्ड, प्रति मेथड" icon="table">

हर मेथड `sessionId` और `agentId` भी लेता है, जो स्कोप्स आपके लिए भरते हैं। कुछ भी छोड़ा गया JSON `null` के रूप में भेजने के बजाय ड्रॉप किया जाता है।

| मेथड | आवश्यक | ऑप्शनल |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

कोई अन्य कुंजी जो आप जोड़ते हैं एक कस्टम पेलोड फील्ड बन जाती है। कुछ भी फ्रेमवर्क-विशिष्ट नेमस्पेस करें `fw_*`; एक नाम जो एक घोषित फील्ड के साथ टकराता है उसके बजाय एक प्रचारित कॉलम को चुप चाप ओवरराइट करने के बजाय अस्वीकार किया जाता है।

</Accordion>

<Warning>
  **`duration_ms` कंप्यूटेड है, स्वीकार नहीं।** चार बंद करने वाली मेथड्स उनके ओपनर से गैप को समय देते हैं और एक कॉलर-आपूर्ति किए गए `duration_ms` को अस्वीकार करते हैं — एक रिपोर्ट की गई अवधि गलत है।

  जोड़े **सेशन** और आइडी पर मेल खाते हैं, कभी एजेंट पर नहीं। एक टूल `planner` के तहत खोला और `worker` के तहत बंद अभी भी मेल खाता है, जो नेस्टेड मल्टी-एजेंट रन वास्तव में क्या करते हैं।
</Warning>

## फ्रेमवर्क एडाप्टर्स

```ts
await failproofai.instrument();              // जो कुछ भी यह खोज सकता है
await failproofai.instrument("langchain");   // बिल्कुल एक
failproofai.uninstrument();                  // सब कुछ वापस रखो
```

| फ्रेमवर्क | समर्थित | यह कैसे संलग्न करता है |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, तो हर `invoke`/`stream`/`batch` कहीं भी `callbacks:` पास किए बिना कवर किया जाता है — या `langchainHandler()` को अपने आप पास करें और कुछ भी पैच न करें। |
| **Vercel AI SDK** | `ai` 4 – 7 | कॉल साइट पर `telemetry()`, या `ai` 7 पर संपूर्ण प्रक्रिया के लिए `instrument("ai")` (4–6 पर वह ऑप्ट-इन है — नीचे देखें)। |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, एजेंट का मॉडल और टूल रेज़ोल्यूशन, और वर्कफ़्लो रन/स्टेप इंजन। |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (सबस्क्राइब किया) साथ ही `AgentWorkflow.runStream`, वर्कफ़्लो रन और उनके स्टेप्स के लिए। |

हर रेंज असली फ्रेमवर्क रिलीज़ के खिलाफ परीक्षण की जाती है, दोनों अंतों पर, एक ES मॉड्यूल के रूप में और CommonJS के रूप में, हर CI रन पर।

मैपिंग Python SDK की है, तो एक ही प्रोग्राम दोनों भाषाओं में डैशबोर्ड पर एक ही ट्री खींचता है। एक निर्माण एक **एजेंट** है केवल अगर यह एक LLM निर्णय लूप के मालिक है — एक ग्राफ या चेन रन, एक AI SDK `generateText`/`streamText` कॉल, एक Mastra एजेंट, एक LlamaIndex एजेंट रन। एक LangGraph नोड या वर्कफ़्लो स्टेप एक **हुक** है (`hook_triggered`/`hook_completed`), कभी एक नेस्टेड एजेंट नहीं। मॉडल कॉल्स `model_request`/`model_response` जोड़े हैं टोकन काउंट्स के साथ; टूल कॉल्स मॉडल की अपनी टूल कॉल आइडी ले जाते हैं। एक विफलता एक बार रिकॉर्ड की जाती है, वह इवेंट पर जहां यह हुई।

एक एडाप्टर जो इंस्टॉल करने में विफल रहता है लॉग किया जाता है और छोड़ा जाता है; अन्य अभी भी इंस्टॉल करते हैं, क्योंकि एक टूटा हुआ LlamaIndex आपको LangGraph की कीमत नहीं देना चाहिए।

<Note>
  बिना तर्क के `instrument()` एक फ्रेमवर्क का पता लगाता है कि क्या यह **रिज़ॉल्व करता है**, नहीं कि क्या यह पहले से इम्पोर्ट किया गया है — Node ES मॉड्यूल्स के लिए Python के `sys.modules` का कोई समकक्ष नहीं देता। एक फ्रेमवर्क जो आपने इंस्टॉल किया है लेकिन उपयोग नहीं किया इम्पोर्ट और पैच किया जाएगा। नाम दें जो आप चाहते हैं यदि यह महत्वपूर्ण है।
</Note>

<Note>
  इनमें से अधिकांश फ्रेमवर्क्स एक ES-मॉड्यूल बिल्ड और एक CommonJS बिल्ड शिप करते हैं, जो Node दो असंबंधित प्रतियों के रूप में लोड करता है। एडाप्टर्स वह प्रति पैच करते हैं जो आपका एप्लिकेशन लोड करता है (और CommonJS प्रति भी अगर कुछ पहले से `require` किया है), तो दोनों मॉड्यूल सिस्टम्स काम करते हैं। एक फ्रेमवर्क **अपने स्वयं के आउटपुट में बंडल** esbuild या webpack द्वारा अप्राप्य है — कॉल-साइट हेल्पर्स वहां उपयोग करें: `langchainHandler()`, `telemetry()`, `wrapTool()`।
</Note>

### पैचिंग के बिना LangChain

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

हैंडलर `instrument()` के साथ या उसके बिना काम करता है और कभी डबल-रिकॉर्ड नहीं करता। `instrument("langchain")` `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` और `captureLimit` लेता है, जैसा Python एडाप्टर करता है; कॉल पर `metadata: { failproofai_sdk_session_id }` उस आह्वान के लिए सेशन चुनता है।

### Vercel AI SDK

AI SDK एक ES मॉड्यूल से सादा फंक्शन्स एक्सपोर्ट करता है, और एक ES मॉड्यूल नेमस्पेस विनिर्देश द्वारा अपरिवर्तनीय है — पैच करने के लिए कहीं नहीं है। यह एक्सटेंशन पॉइंट्स का उपयोग करता है जो SDK स्वयं दस्तावेज़ करता है:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // ai 7 पर, `telemetry: telemetry({ … })` — एक ही ऑब्जेक्ट, नया नाम
});
```

वह संपूर्ण एकीकरण है: एक एजेंट स्पैन, हर स्टेप के साथ एक मॉडल रिक्वेस्ट/रेस्पांस जोड़ी टोकन काउंट्स के साथ, और हर टूल कॉल। एक कॉल साइट हर मेजर पर काम करता है — `ai` 4–6 ट्रेसर को यह ले जाता है पढ़ते हैं, `ai` 7 टेलीमेट्री एकीकरण।

`instrument("ai")` **`ai` 7 पर** एक ही प्रक्रिया-व्यापी करता है: हर कॉल, AI SDK की ग्लोबल टेलीमेट्री-एकीकरण सूची के माध्यम से, जो योगात्मक है और किसी को कुछ नहीं लेता।

**`ai` 4–6 पर, `instrument("ai")` अपने आप कुछ भी रिकॉर्ड नहीं करता है, और एक चेतावनी लॉग करता है कि इसलिए।** एकमात्र प्रक्रिया-व्यापी हुक जो इन मेजर्स के पास है ग्लोबल OpenTelemetry ट्रेसर प्रोवाइडर है — एक एकल स्लॉट OpenTelemetry हाथ देने से इंकार करता है एक बार लिया। हमारे को रजिस्टर करना बाद में स्टार्टअप में आपके स्वयं के `NodeSDK.start()` को चुप चाप इंकार कर देगा और आपके http/डेटाबेस स्पैन्स को एक ट्रेसर भेजेगा जो कुछ भी एक्सपोर्ट नहीं करता। कॉल साइट पर `telemetry()` उपयोग करें या `wrapModel` वहां। यदि प्रक्रिया कोई OpenTelemetry अपने आप नहीं चलाती, `instrument("ai", { registerGlobalTracer: true })` के साथ ऑप्ट इन करें: यह तब हर कॉल रिकॉर्ड करता है जो `experimental_telemetry: { isEnabled: true }` पास करता है, और केवल स्लॉट लेता है यदि यह अभी भी खाली है। `registerGlobalTracer: false` डिफ़ॉल्ट रखता है और चेतावनी को शांत करता है।

यदि आप मॉडल को एक बार लपेटना पसंद करेंगे, `wrapModel` केवल मॉडल कॉल्स देता है, क्योंकि टूल कॉल्स मॉडल लेयर के ऊपर होते हैं। इसके चारों ओर कुछ नहीं के साथ कॉल किया गया लपेटा हुआ मॉडल इसके स्वयं के रन के रूप में रिकॉर्ड किया जाता है। एक स्ट्रीम किया गया कॉल जैसे ही बंद होता है स्ट्रीम बंद होता है — `stop_reason: "cancelled"` जब उपभोक्ता इसे रद्द करता है, `"error"` त्रुटि के साथ जब यह बीच में विफल रहता है:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

दोनों उपयोग ठीक है: मिडलवेयर ध्यान देता है कि कॉल पहले से रिकॉर्ड की जा रही है और स्थगित करता है, तो हर कॉल एक बार रिकॉर्ड की जाती है।

`functionId` एजेंट स्पैन का नाम रखता है। इसे कम-कार्डिनैलिटी रखें — यह `agent_id` में जाता है, प्राथमिक डैशबोर्ड पहलू।

### Next.js

`next build` डिफ़ॉल्ट रूप से अपने सर्वर की डिपेंडेंसीज बंडल करता है, और एक फ्रेमवर्क बिल्ड में बंडल किया गया `instrument()` तक नहीं पहुंच सकता एक प्रति है। कॉन्फ़िग को एक बार लपेटें और Next के स्टार्टअप हुक से `instrument()` को कॉल करें:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* आपका कॉन्फ़िग */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` LangChain, Mastra, LlamaIndex और SDK को `serverExternalPackages` में जोड़ता है, आपकी अपनी सूची रखता है। इसके बिना, `instrument()` एक बार प्रति फ्रेमवर्क चेतावनी देता है जो यह नहीं पहुंच सकता है, जब तक चुप चाप विफल होने की जगह; यदि आप पैकेज्स को स्वयं सूची बनाते हैं, `FAILPROOFAI_NEXT_EXTERNALS=1` सेट करें। Vercel AI SDK और कॉल-साइट हेल्पर्स दोनों तरह से काम करते हैं। एक Edge रूट एक नो-ऑप बिल्ड पाता है: SDK को आयात करना सुरक्षित है और कुछ नहीं रिकॉर्ड करता है।

### स्ट्रीम किए गए कॉल्स पर टोकन काउंट्स

OpenAI-संगत API केवल स्ट्रीम पर उपयोग रिपोर्ट करते हैं जब क्लाइंट पूछता है। LangChain और Vercel AI SDK पूछते हैं; LlamaIndex के लिए `additionalChatOptions: { stream_options: { include_usage: true } }` को अपने `OpenAI` LLM को पास करें, और Mastra के लिए मॉडल को उपयोग सक्षम के साथ बनाएं (उदाहरण के लिए `createOpenAICompatible({ includeUsage: true })`)। अन्यथा स्ट्रीम किए गए मॉडल कॉल्स कोई टोकन काउंट्स नहीं ले जाते हैं।

### रनटाइम्स

Node ≥ 20.9, Bun और Deno — हर फ्रेमवर्क, एक ES मॉड्यूल और CommonJS के रूप में, Node के ट्रेस के विरुद्ध हर CI रन पर परीक्षण किया जाता है। SDK `failproofaid` डेमन के साथ चलता है, जो यह लिखता है वह शिप करता है।

## आपका अपना एजेंट — कोई फ्रेमवर्क नहीं

एक एजेंट लूप के लिए जो आपने स्वयं लिखा था, या एक फ्रेमवर्क जिसका कोई एडाप्टर नहीं है। आप एडाप्टर्स के तहत उसी API के साथ इवेंट्स उत्सर्जित करते हैं, तो ट्रेस का एक ही आकार और गुणवत्ता है।

आपको एजेंट कैसे संगठित है जानने की आवश्यकता नहीं है। हर हाथ-निर्मित एजेंट के पास पहले से ही तीन स्थान हैं, इसके फंक्शन्स को कुछ भी कहा जाता हो, और वह तीन संपूर्ण एकीकरण हैं:

| कहां | क्या जोड़ें | उत्सर्जन |
| --- | --- | --- |
| जहां **एक रन** शुरू और समाप्त होता है | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **एक फंक्शन जो मॉडल को कॉल करता है** | `event.modelRequest` पहले, `event.modelResponse` बाद — दोनों हिस्से, विफलता पर भी | प्रति मॉडल टर्न एक जोड़ी |
| **एक फंक्शन जो टूल्स चलाता है** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Identity परिवेश है: `agent()` के अंदर सब कुछ एक आइडी लिए बिना उस रन के सेशन पर जाता है, और प्रोग्राम में कुछ भी नहीं बदलता है — जिसमें जो कुछ एजेंट अपने स्वयं के डेटाबेस में पहले से लिखता है।

- **एक सर्विस या वर्कर:** अपना स्वयं का रिक्वेस्ट या जॉब आइडी `sessionId` के रूप में पास करें, तो डैशबोर्ड पर एक सेशन और आपके स्वयं के लॉग्स या डेटाबेस में रिकॉर्ड एक ही स्ट्रिंग है।
- **उप-एजेंट्स:** `agent()` कॉल्स को नेस्ट करें। आंतरिक एक सेशन को बाहरी के साथ अपने `parent_id` के रूप में जुड़ता है।
- **जोड़े उत्सर्जित करें।** एक `modelRequest` कोई `modelResponse` के साथ एक स्पैन है जो डैशबोर्ड हमेशा के लिए दिखाता है — इसलिए `catch`।

रिपॉजिटरी में [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) संपूर्ण, रन-योग्य संस्करण है: एक असली OpenAI टूल लूप बिल्कुल इसी तरह इंस्ट्रूमेंट किया गया, CI में हर परिवर्तन के रूप में चलाया गया एक ES मॉड्यूल और CommonJS के रूप में।

## मूल्यांकन

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

</Warning>

## यह आपकी प्रक्रिया को क्या नहीं करेगा

| | |
| --- | --- |
| **आपके एजेंट लूप को ब्लॉक करें** | इवेंट्स एक इन-मेमोरी कतार में जाते हैं; एक टाइमर उन्हें लिखता है। टाइमर `unref`'d है, तो इस पैकेज को आयात करना कभी एक स्क्रिप्ट को एक्जिट नहीं करता। |
| **बिना सीमा बढ़ें** | कतार गिनती *और* मापी हुई बाइट्स द्वारा सीमित है। प्रत्येक पास करने के लिए, सबसे पुरानी इवेंट्स त्यागी जाती हैं और एक चेतावनी ऐसा कहती है — एक टेलीमेट्री आउटेज एक OOM किल नहीं बनना चाहिए। |
| **प्रक्रिया को नीचे ले जाएं** | एक अनकोडेबल इवेंट अकेले ड्रॉप की जाती है, इसके चारों ओर बैच नहीं। एक फेंकने वाली गेटर, एक परिपत्र संदर्भ, एक `BigInt`, एक अकेली सरोगेट: हर एक प्रचारित के बजाय संभाली जाती है। |
| **एक अधूरा बैच छोड़ें** | कंटेंट `fsync`ed एक परमाणु पुनः नाम से पहले, निर्देशिका `fsync`ed बाद में, और एक असफल लिखना अपनी अस्थायी फ़ाइल को साफ करता है। |
| **ट्रांसक्रिप्ट्स को पठनीय छोड़ें** | बैचेज `0600` के अंदर `0700` निर्देशिका में हैं। वे लक्ष्य, संकेत, टूल तर्क और टूल आउटपुट ले जाते हैं। |
| **क्रेडेंशियल्स शिप करें** | API कुंजियां, टोकन्स, JWTs, बियरर हेडर्स और सीक्रेट-आकार असाइनमेंट्स डिस्क तक पहुंचने से पहले रीडैक्ट किए जाते हैं। डेमन अपलोड से पहले फिर से रीडैक्ट करता है। |
