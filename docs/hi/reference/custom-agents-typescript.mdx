<Note>
  यह SDK और Python वाला **एक ही स्पूल में समान इवेंट लिखते हैं**। Node एजेंट और Python एजेंट वाली एक फ्लीट एक सेशन सेट बनाती है, दो नहीं, और डैशबोर्ड में कुछ भी उन्हें अलग नहीं करता। प्रति कंपनी नहीं, प्रति सेवा चुनें।
</Note>

## इंस्टॉल करें

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

फ्रेमवर्क एडेप्टर पैकेज में ही भेज दिए जाते हैं। फ्रेमवर्क **वैकल्पिक पीयर निर्भरताएं** हैं — समर्थित श्रेणियां दिखाई देने के लिए घोषित, आपकी ओर से कभी इंस्टॉल नहीं किए जाते, और केवल तब आयात किए जाते हैं जब आप `instrument()` को कॉल करते हैं।

## Failproof डेमन को कनेक्ट करें

Python SDK के समान: **Admin → Keys** के अंतर्गत एक `events:add` की बनाएं, फिर [डेमन को कनेक्ट करें](/hi/start/setup#connect-a-machine-to-cloud) एजेंट मशीन पर। SDK डिस्क में लिखता है; डेमन भेज देता है।

## कॉन्फ़िगरेशन

### OpenTelemetry स्पैन (ऑप्ट इन)

`npm install @opentelemetry/api @opentelemetry/sdk-trace-base` के साथ OpenTelemetry को अलग से इंस्टॉल करें।
फिर अपने प्रोवाइडर के प्रोसेसर में FailproofAI जोड़ें:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

एक मौजूदा प्रोवाइडर के लिए, इसके अन्य प्रोसेसर को एक ही सूची में रखें। जो प्रोवाइडर `addSpanProcessor` को उजागर करते हैं, उन्हें इसके बजाय `{ provider }` के रूप में पास किया जा सकता है। विकल्पों के बिना, सेटअप केवल तभी एक नया प्रोवाइडर पंजीकृत करता है यदि कोई प्रोवाइडर पहले से पंजीकृत नहीं है।
`OtelSpanExporter` को अपने स्वयं के प्रोसेसर के साथ सीधे भी उपयोग किया जा सकता है।

निर्यात जुड़े हुए FailproofAI डेमन के माध्यम से जाते हैं; SDK कोई नेटवर्क अनुरोध भेजता नहीं है और न ही कुंजी या स्थानीय श्रोता की आवश्यकता है। एक एडमिन को [OpenTelemetry ingest](/hi/agenteye/opentelemetry) को सक्षम करने के लिए कहें। एक नंगा `instrument()` इस निर्यातक को सक्षम नहीं करता। `uninstrument("otel")` केवल अपने स्वयं के प्रोसेसर को अक्षम करता है। आपकी स्पैन विशेषताएं सामग्री कैप्चर को नियंत्रित करती हैं; निकास से पहले अपने प्रोवाइडर को फ्लश करें।
OpenTelemetry एक वैकल्पिक एप्लीकेशन निर्भरता रहता है, एक कठोर SDK निर्भरता नहीं।

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| विकल्प | यह क्या करता है |
| --- | --- |
| `environment` | हर इवेंट पर लेबल — `production`, `staging`, `prod-eu`। डिफ़ॉल्ट `dev` है। |
| `flushInterval` | टाइमर सेकंड में कितनी बार डिस्क में लिखता है। डिफ़ॉल्ट `0.5` है। |
| `baseDir` | कहां लिखें। डेमन के स्पूल को डिफ़ॉल्ट करता है, जो आप चाहते हैं जब तक आप अन्यथा जानते हैं। |

कुछ भी लागू नहीं किया जाता जब तक यह सब मान्य न हो, इसलिए एक अस्वीकृत कॉल SDK को बिल्कुल वैसे ही छोड़ देता है जैसे यह था, नई `baseDir` और पुरानी अंतराल के साथ नहीं।

इसके बजाय पर्यावरण चर द्वारा सेट करें:

| चर | यह क्या करता है |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | कोड परिवर्तन के बिना `environment` सेट करता है। एक `configure()` विकल्प इसके ऊपर जीतता है। |
| `FAILPROOFAI_HOME` | Failproof AI रूट को स्थानांतरित करता है जो स्पूल रखता है। |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (डिफ़ॉल्ट), `error`, `silent`। |
| `FAILPROOFAI_SDK_STRICT` | `1` इंस्ट्रूमेंटेशन त्रुटियों को लॉग किए जाने के बजाय फेंकने के लिए बनाता है। |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` फ्रेमवर्क-संगतता समस्या को चेतावनी देने और जारी रखने के बजाय फेंकने के लिए बनाता है। |

<Warning>
  **`environment` में कोई अल्पविराम नहीं।** इनजेस्ट उस फील्ड को अल्पविराम पर विभाजित करता है अपने फिल्टर बनाने के लिए, और किसी भी इवेंट को छोड़ देता है जिसमें एक है — इसलिए एक पूरा रन चुप चाप गायब हो जाता है। `prod,eu` नहीं, `prod-eu` लिखें।

  `configure({ environment: "prod,eu" })` फेंकता है ताकि आप तुरंत पता लगें। `AGENTEYE_ENVIRONMENT` नहीं फेंक सकता — कोई आपको कॉल नहीं कर रहा — तो यह एक बार चेतावनी देता है और `dev` पर गिर जाता है।
</Warning>

`failproofai.setLogger({ debug, info, warn, error })` के साथ SDK की अपनी लॉग लाइनों को अपने लॉगर में भेजें।

## शटडाउन

बफर किए गए इवेंट `process.on("exit")` पर फ्लश किए जाते हैं।

एक सिग्नल द्वारा मार दी गई प्रक्रिया कभी वहां तक नहीं पहुंचती है, और `SIGTERM` के लिए Node की डिफ़ॉल्ट निकास हैंडलर के बिना समाप्त करना है — इसलिए एक कंटेनरीकृत एजेंट जो भी अंतिम अंतराल में नहीं लिखा गया था उससे गुम हो जाता है।

<Warning>
  **यह SDK आपके लिए सिग्नल हैंडलर इंस्टॉल नहीं करेगा।** एक को पंजीकृत करना आपकी प्रक्रिया के व्यवहार को बदलता है: एक श्रोता Node की डिफ़ॉल्ट समाप्ति को दबाता है, इसलिए एक लाइब्रेरी जो एक जोड़ता था चुप चाप Ctrl-C को काम करने से बंद कर देगा। अपना स्वयं का जोड़ें:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

एक अल्पकालिक स्क्रिप्ट या सर्वरलेस हैंडलर को लौटने से पहले `await failproofai.flush()` करना चाहिए — अंतराल अकेले डिलीवरी की गारंटी नहीं देता है।

## पहचान

हर इवेंट एक सेशन और एक एजेंट से संबंधित है। **स्कोप दोनों को भर देते हैं**, तो आप शायद ही कभी उन्हें पास करते हैं:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId` या `agentId` को स्पष्ट रूप से पास करना अभी भी काम करता है और जीतता है। न बंधे और न पास किए जाने के साथ, कॉल फेंकता है बजाय एक इवेंट उत्सर्जित करने के जो Cloud चुप चाप त्याग देगा।

<Note>
  पहचान `AsyncLocalStorage` पर सवारी करती है। यह `await`, `.then()`, टाइमर और स्कोप के अंदर बनाए गए किसी भी कॉलबैक को अनुसरण करता है। यह एक रन के दौरान संग्रहीत और दूसरे के दौरान आमंत्रित कॉलबैक को अनुसरण **नहीं** करता है, या `worker_threads` सीमा के पार हाथ किए गए काम को — उन्हें `failproofai.propagate()` में लपेटें या उनके इवेंट अलग-थलग रहते हैं।
</Note>

### स्कोप

| स्कोप | उत्सर्जित करता है | लौटाता है |
| --- | --- | --- |
| `session(body)` | कुछ नहीं — केवल पहचान | जो `body` लौटाता है |
| `agent(id, options?, body)` | `agent_start`, फिर `agent_end` | जो `body` लौटाता है |
| `toolCall(name, options?, body)` | `tool_use`, फिर `tool_result` | जो `body` लौटाता है |

एक सिंक्रोनस बॉडी सिंक्रोनस रहती है: `agent("x", () => 1)` `1` लौटाता है, एक प्रॉमिस नहीं।

`toolCall` बॉडी के हल किए गए मूल्य को टूल के `output` के रूप में रिकॉर्ड करता है, जब तक आप `call.output` को स्वयं असाइन नहीं करते।

<Accordion title="निकास शब्दार्थ" icon="arrow-right-from-bracket">

| क्या हुआ | इवेंट | `outcome` |
| --- | --- | --- |
| ब्लॉक वापस आया | `agent_end` | `"success"`, या आपका `outcome` |
| ब्लॉक फेंका गया | `error`, फिर `agent_end` | `"failed"` |
| एक `AbortError` | केवल `agent_end` | `"cancelled"` |

त्रुटि हमेशा फिर से फेंकी जाती है।

एक टूल विफलता पत्ती पर रिकॉर्ड की जाती है — `tool_result` एक `error` स्ट्रिंग के साथ — और कोई भी रन-स्तर `error` इवेंट **नहीं** उत्सर्जित करता है। एक जो एजेंट लूप पकड़ता है वह एक रन विफलता नहीं है, और एक जो प्रचार करता है वह बिल्कुल एक बार रिपोर्ट किया जाता है, संलग्न `agent()` द्वारा।

</Accordion>

<Accordion title="`using` फॉर्म" icon="brackets-curly">

जब काम एक एकल फंक्शन नहीं है — एक स्कोप एक निर्माता में खोला गया और एक टियरडाउन में बंद, या एक जो मौजूदा नियंत्रण प्रवाह को फैलाता है:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, फिर agent_end
```

दोनों फॉर्म बाइट-समान इवेंट उत्सर्जित करते हैं। कॉलबैक फॉर्म को प्राथमिकता दें: यह `AsyncLocalStorage.run()` के अंदर चलता है, इसलिए कुछ भी अनवाइंड करने के लिए कुछ नहीं है और "यहां खोला, वहां बंद" बग का पूरा वर्ग अप्राप्य है।

एक `using` ब्लॉक जो अपनी अपनी विफलता को पकड़ता है, इसे `span.fail(error)` के साथ रिपोर्ट करता है — डिस्पोजर के पास अपना अपवाद चैनल नहीं है।

</Accordion>

## इवेंट कैटलॉग

Python SDK के समान पंद्रह मेथड, camelCase में। अधिकांश **जोड़े में** आते हैं — आप ओपनर को कॉल करते हैं, फिर क्लोजर, और SDK अंतराल को समय देता है।

| | खोलता है | बंद करता है |
| --- | --- | --- |
| **एजेंट** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **मॉडल** | `modelRequest` | `modelResponse` |
| **टूल** | `toolUse` | `toolResult` |
| **हुक** | `hookTriggered` | `hookCompleted` |
| **मानव** | `humanWait` | `humanInput` |

तीन अकेले खड़े हैं: `error`, `humanPause`, `humanInterrupt`।

<Accordion title="प्रत्येक मेथड, प्रति फील्ड" icon="table">

हर मेथड `sessionId` और `agentId` भी लेता है, जो स्कोप आपके लिए भर देते हैं। कुछ भी छोड़ा हुआ JSON `null` के रूप में भेजे जाने के बजाय गिरा दिया जाता है।

| मेथड | आवश्यक | वैकल्पिक |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

कोई भी अन्य कुंजी जो आप जोड़ते हैं एक कस्टम पेलोड फील्ड बन जाती है। कुछ भी फ्रेमवर्क-विशिष्ट `fw_*` को नेमस्पेस करें; एक नाम जो एक घोषित फील्ड के साथ टकराता है चुप चाप एक प्रचारित कॉलम को अधिलेखित करने के बजाय अस्वीकार कर दिया जाता है।

</Accordion>

<Warning>
  **`duration_ms` गणना की जाती है, स्वीकार नहीं की जाती है।** चार बंद करने वाले मेथड अपने ओपनर से अंतराल को समय देते हैं और एक कॉलर-आपूर्ति `duration_ms` को अस्वीकार करते हैं — एक रिपोर्ट किया गया अवधि अस्वीकार्य है।

  जोड़े **सेशन** पर मिलाए जाते हैं और आईडी, एजेंट पर कभी नहीं। एक टूल `planner` के अंतर्गत खोला गया और `worker` के अंतर्गत बंद किया गया अभी भी जोड़ता है, जो नेस्टेड बहु-एजेंट रन वास्तव में क्या करते हैं।
</Warning>

## फ्रेमवर्क एडेप्टर

```ts
await failproofai.instrument();              // जो कुछ भी यह पा सकता है
await failproofai.instrument("langchain");   // ठीक एक
failproofai.uninstrument();                  // सब कुछ वापस डालें
```

| फ्रेमवर्क | समर्थित | यह कैसे संलग्न करता है |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, तो हर `invoke`/`stream`/`batch` कहीं भी `callbacks:` पास किए बिना कवर किया जाता है — या `langchainHandler()` को स्वयं पास करें और कुछ भी पैच न करें। |
| **Vercel AI SDK** | `ai` 4 – 7 | कॉल साइट पर `telemetry()`, या `ai` 7 पर संपूर्ण प्रक्रिया के लिए `instrument("ai")` (4–6 पर जो ऑप्ट-इन है — नीचे देखें)। |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, एजेंट के मॉडल और टूल संकल्प, और वर्कफ़्लो रन/स्टेप इंजन। |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (सब्सक्राइब किया गया) प्लस `AgentWorkflow.runStream`, वर्कफ़्लो रन और उनके चरणों के लिए। |

हर श्रेणी वास्तविक फ्रेमवर्क रिलीज के विरुद्ध परीक्षण किया जाता है, दोनों सिरों पर, ES मॉड्यूल और CommonJS के रूप में, हर CI चलाने पर।

मैपिंग Python SDK की है, तो समान प्रोग्राम या तो भाषा में समान ट्री खींचता है। एक निर्माण **एजेंट** है केवल यदि यह LLM निर्णय लूप के मालिक है — एक ग्राफ या चेन रन, AI SDK `generateText`/`streamText` कॉल, Mastra एजेंट, LlamaIndex एजेंट रन। एक LangGraph नोड या वर्कफ़्लो स्टेप एक **हुक** है (`hook_triggered`/`hook_completed`), कभी भी नेस्टेड एजेंट नहीं। मॉडल कॉल `model_request`/`model_response` जोड़े हैं टोकन गणना के साथ; टूल कॉल मॉडल के अपने टूल कॉल आईडी ले जाते हैं। एक विफलता पत्ती पर एक बार रिकॉर्ड की जाती है — जहां यह हुआ।

एक एडेप्टर जो इंस्टॉल नहीं हो सकता है लॉग किया जाता है और छोड़ दिया जाता है; अन्य अभी भी इंस्टॉल करते हैं, क्योंकि एक टूटा हुआ LlamaIndex आपको LangGraph की कीमत नहीं देना चाहिए।

<Note>
  कोई तर्क के साथ `instrument()` एक फ्रेमवर्क का पता लगाता है कि क्या यह पहले से ही **आयात** किया गया है, की बजाय क्या यह **हल करता है** — Node ES मॉड्यूल के लिए Python के `sys.modules` के बराबर उजागर करता है। एक फ्रेमवर्क जो आपने इंस्टॉल किया है लेकिन उपयोग नहीं करते हैं आयात और पैच किया जाएगा। नाम करें जो आप चाहते हैं यदि वह मायने रखता है।
</Note>

<Note>
  इनमें से अधिकांश फ्रेमवर्क ES-मॉड्यूल बिल्ड और CommonJS बिल्ड भेज देते हैं, जो Node दो असंबंधित प्रतियों के रूप में लोड करता है। एडेप्टर आपके एप्लीकेशन लोड की प्रति को पैच करते हैं (और CommonJS प्रति भी अगर कुछ पहले से ही `require` किया है), तो दोनों मॉड्यूल सिस्टम काम करते हैं। एक फ्रेमवर्क **आपके अपने आउटपुट में बंडल किया गया** esbuild या webpack द्वारा पहुंच से बाहर है — कॉल-साइट सहायकों को वहां उपयोग करें: `langchainHandler()`, `telemetry()`, `wrapTool()`।
</Note>

### LangChain बिना पैच किए

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

हैंडलर `instrument()` के साथ या बिना काम करता है और कभी भी दोहरा-रिकॉर्ड नहीं करता। `instrument("langchain")` `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` और `captureLimit` लेता है, जैसा कि Python एडेप्टर करता है; `metadata: { failproofai_sdk_session_id }` एक कॉल पर उस आमंत्रण के लिए सेशन चुनता है।

### Vercel AI SDK

AI SDK ES मॉड्यूल से सादे फंक्शन निर्यात करता है, और ES मॉड्यूल नेमस्पेस विशेषज्ञता द्वारा अपरिवर्तनीय है — पैच करने के लिए कहीं नहीं है। यह SDK स्वयं दस्तावेजों को बढ़ाने के बिंदु का उपयोग करता है:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // ai 7 पर, `telemetry: telemetry({ … })` — समान वस्तु, नया नाम
});
```

यह संपूर्ण एकीकरण है: एक एजेंट स्पैन, टोकन गणना के साथ प्रति चरण एक मॉडल अनुरोध/प्रतिक्रिया जोड़ी, और हर टूल कॉल। एक कॉल साइट हर प्रमुख पर काम करता है — `ai` 4–6 ट्रेसर को ले जाता है, `ai` 7 टेलीमेट्री एकीकरण को।

`instrument("ai")` `ai` 7 पर समान प्रक्रिया-व्यापी करता है: हर कॉल, AI SDK की वैश्विक टेलीमेट्री-एकीकरण सूची के माध्यम से, जो योगात्मक है और किसी और से कुछ नहीं लेता है।

**`ai` 4–6 पर, `instrument("ai")` स्वयं द्वारा कुछ भी रिकॉर्ड नहीं करता है, और एक चेतावनी लॉग करता है कि ऐसा है।** केवल एकमात्र प्रक्रिया-व्यापी हुक जो इन प्रमुखों के पास है वह वैश्विक OpenTelemetry ट्रेसर प्रदाता है — एक एकल स्लॉट OpenTelemetry हाथ से इनकार करता है एक बार लिया। हमारे को पंजीकृत करना बाद में आपके स्वयं के `NodeSDK.start()` को चुप चाप अस्वीकार करेगा और आपके http/डेटाबेस स्पैन को एक ट्रेसर को भेजेगा जो कुछ भी निर्यात नहीं करता है। कॉल साइट पर `telemetry()` का उपयोग करें या `wrapModel` वहां। यदि प्रक्रिया अपने स्वयं के OpenTelemetry को चलाती नहीं है, `instrument("ai", { registerGlobalTracer: true })` के साथ ऑप्ट इन करें: यह तब हर कॉल रिकॉर्ड करता है जो `experimental_telemetry: { isEnabled: true }` को पास करता है, और केवल स्लॉट लेता है यदि यह अभी भी खाली है। `registerGlobalTracer: false` डिफ़ॉल्ट रखता है और चेतावनी को चुप कर देता है।

यदि आप मॉडल को एक बार लपेटना पसंद करेंगे, `wrapModel` केवल मॉडल कॉल देखता है, क्योंकि टूल कॉल मॉडल परत के ऊपर होते हैं। एक लपेटा हुआ मॉडल इसके चारों ओर कुछ भी नहीं के साथ कहा जाता है अपने स्वयं के रन के रूप में दर्ज किया जाता है। एक स्ट्रीमेड कॉल बंद करता है हालांकि स्ट्रीम बंद करता है — `stop_reason: "cancelled"` जब उपभोक्ता इसे रद्द करता है, `"error"` त्रुटि के साथ जब यह आधे रास्ते में विफल हो जाता है:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

दोनों का उपयोग ठीक है: मिडलवेयर नोटिस करता है कि कॉल पहले से ही रिकॉर्ड किया जा रहा है और आगे बढ़ता है, इसलिए हर कॉल एक बार रिकॉर्ड किया जाता है।

`functionId` एजेंट स्पैन का नाम देता है। इसे कम-कार्डिनैलिटी रखें — यह `agent_id` में उतरता है, प्राथमिक डैशबोर्ड पहलू।

### Next.js

`next build` डिफ़ॉल्ट रूप से आपके सर्वर की निर्भरताओं को बंडल करता है, और एक फ्रेमवर्क बिल्ड में बंडल किया गया एक प्रति है `instrument()` नहीं पहुंच सकता। कॉन्फ़िग को एक बार लपेटें और Next के स्टार्टअप हुक से `instrument()` को कॉल करें:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* आपका कॉन्फ़िग */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` LangChain, Mastra, LlamaIndex और SDK को स्वयं `serverExternalPackages` में जोड़ता है, आपकी अपनी सूची को रखता है। इसके बिना, `instrument()` प्रति फ्रेमवर्क एक बार चेतावनी देता है यह नहीं पहुंच सकता बजाय चुप विफलता के; यदि आप पैकेजों को स्वयं सूचीबद्ध करते हैं, `FAILPROOFAI_NEXT_EXTERNALS=1` सेट करें। Vercel AI SDK और कॉल-साइट सहायक दोनों तरह से काम करते हैं। एक Edge रूट एक नो-ऑप बिल्ड हो जाता है: SDK को आयात करना सुरक्षित है और कुछ भी रिकॉर्ड नहीं करता है।

### स्ट्रीमेड कॉल पर टोकन गणना

OpenAI-संगत API केवल तब उपयोग की रिपोर्ट करते हैं जब क्लाइंट पूछता है। LangChain और Vercel AI SDK पूछते हैं; LlamaIndex के लिए `additionalChatOptions: { stream_options: { include_usage: true } }` को इसके `OpenAI` LLM पास करें, और Mastra के लिए उपयोग सक्षम के साथ मॉडल बनाएं (उदाहरण के लिए `createOpenAICompatible({ includeUsage: true })`)। अन्यथा स्ट्रीमेड मॉडल कॉल कोई टोकन गणना नहीं ले जाते हैं।

### रनटाइम

Node ≥ 20.9, Bun और Deno — हर फ्रेमवर्क, ES मॉड्यूल और CommonJS के रूप में, Node के ट्रेस के विरुद्ध हर पर परीक्षण किया जाता है। SDK `failproofaid` डेमन के बगल में चलता है, जो जो लिखता है उसे भेज देता है।

## आपका अपना एजेंट — कोई फ्रेमवर्क नहीं

एक एजेंट लूप जो आपने स्वयं लिखा है, या एक फ्रेमवर्क बिना एडेप्टर के। आप एडेप्टर के नीचे समान API के साथ इवेंट उत्सर्जित करते हैं, तो ट्रेस का आकार और गुणवत्ता समान है।

आपको यह जानने की जरूरत नहीं है कि एजेंट कैसे आयोजित है। हर हाथ से बनाया गया एजेंट पहले से ही तीन जगह है, जो भी उसके फंक्शन कहे जाते हैं, और वे तीन पूरे एकीकरण हैं:

| कहां | क्या जोड़ें | उत्सर्जित करता है |
| --- | --- | --- |
| जहां **एक रन** शुरू और समाप्त होता है | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **एक फंक्शन जो मॉडल को कॉल करता है** | `event.modelRequest` पहले, `event.modelResponse` बाद में — दोनों हिस्से, विफलता पर भी | प्रति मॉडल बारी एक जोड़ी |
| **एक फंक्शन जो टूल चलाता है** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

पहचान परिवेशीय है: `agent()` के अंदर सब कुछ एक आईडी लिए बिना उस रन के सेशन पर उतरता है, और प्रोग्राम में और कुछ नहीं बदलता है — जो कुछ भी एजेंट पहले से ही अपने अपने डेटाबेस में लिखता है।

- **एक सेवा या एक कार्यकर्ता:** अपने अपनी अनुरोध या नौकरी आईडी को `sessionId` के रूप में पास करें, तो डैशबोर्ड पर एक सेशन और आपके अपने लॉग या डेटाबेस में रिकॉर्ड एक ही स्ट्रिंग हैं।
- **उप-एजेंट:** `agent()` कॉल नेस्ट करें। आंतरिक एक बाहरी के साथ सेशन में शामिल हो जाता है जैसा कि इसका `parent_id`।
- **जोड़ी उत्सर्जित करें।** एक `modelRequest` कोई `modelResponse` के साथ एक स्पैन है डैशबोर्ड हमेशा के लिए चलता दिखाता है — इसलिए `catch`।

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) रिपोजिटरी में संपूर्ण, रनेबल संस्करण है: एक वास्तविक OpenAI टूल लूप बिल्कुल इसी तरह इंस्ट्रूमेंट किया गया, CI में हर परिवर्तन के रूप में चलाया गया ES मॉड्यूल और CommonJS के रूप में।

## मूल्यांकन

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \

</Warning>

## यह आपकी प्रक्रिया के लिए क्या नहीं करेगा

| | |
| --- | --- |
| **आपके एजेंट लूप को ब्लॉक करें** | इवेंट एक इन-मेमोरी कतार में जाते हैं; एक टाइमर उन्हें लिखता है। टाइमर `unref`'d है, तो इस पैकेज को आयात करने से कभी भी एक स्क्रिप्ट निकल जाती है। |
| **बंधन के बिना बढ़ें** | कतार को गिनती **और** मापा गया बाइट द्वारा सीमित है। या तो पिछले, सबसे पुराने इवेंट त्यागे जाते हैं और एक चेतावनी कहती है — एक टेलीमेट्री आउटेज OOM मार बन नहीं सकता। |
| **प्रक्रिया को नीचे ले जाएं** | एक अनकोडेबल इवेंट अकेले गिरा दिया जाता है, इसके चारों ओर बैच नहीं। एक फेंकने वाला गेटर, एक वृत्ताकार संदर्भ, एक `BigInt`, एक अकेला सरोगेट: प्रत्येक हैंडल किया जाता है न कि प्रचारित। |
| **आधी-लिखी गई बैच छोड़ें** | सामग्री `fsync`ed है एक परमाणु नाम बदलने से पहले, निर्देशिका के बाद `fsync`ed है, और एक विफल लिखना अपनी अस्थायी फाइल को साफ करता है। |
| **पारदर्शी छोड़ दें** | बैच `0700` निर्देशिका के अंदर `0600` हैं। वे लक्ष्य, प्रॉम्प्ट, टूल तर्क और टूल आउटपुट ले जाते हैं। |
| **साख भेजें** | API कुंजी, टोकन, JWT, असर हेडर और गुप्त-आकार असाइनमेंट डिस्क तक पहुंचने से पहले संपादित किए जाते हैं। डेमन अपलोड से पहले फिर से संपादित करता है। |
