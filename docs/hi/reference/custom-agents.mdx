Python 3.10 या नया। कोई रनटाइम डिपेंडेंसीज नहीं।

## इंस्टॉल करें

```bash
pip install failproofai-sdk
```

पैकेज को `failproofai-sdk` के रूप में इंस्टॉल किया जाता है और Python में `failproofai_sdk` के रूप में इम्पोर्ट किया जाता है। `failproofai-sdk[langgraph]` जैसी फ्रेमवर्क एक्सट्रास फ्रेमवर्क को स्वयं इंस्टॉल करते हैं; एडेप्टर हमेशा बेस व्हील में आते हैं।

## कॉन्फ़िगरेशन

```python
import failproofai_sdk

failproofai_sdk.configure(
    base_dir=None,
    flush_interval=0.5,
    environment="production",
)
```

| आर्गुमेंट | यह क्या करता है |
| --- | --- |
| `environment` | हर ईवेंट पर लेबल — `production`, `staging`, `prod-eu`। डिफ़ॉल्ट `dev` है। |
| `flush_interval` | पृष्ठभूमि थ्रेड कितनी बार डिस्क पर लिखता है, सेकंड में। डिफ़ॉल्ट `0.5` है। |
| `base_dir` | कहां लिखना है। डिफ़ॉल्ट डेमन के स्पूल, जो आप चाहते हैं जब तक कि आप अन्यथा न जानते हों। |

इसके बजाय पर्यावरण चर द्वारा सेट करें:

| चर | यह क्या करता है |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | कोड परिवर्तन के बिना `environment` सेट करता है, जब लेबल डिप्लॉयमेंट के बजाय ऐप से संबंधित हो। एक `configure()` आर्गुमेंट इसे जीतता है। |
| `FAILPROOFAI_HOME` | Failproof AI रूट को स्थानांतरित करता है जो स्पूल को धारण करता है। |
| `FAILPROOFAI_SDK_STRICT` | `1` इंस्ट्रूमेंटेशन त्रुटियों को लॉग करने के बजाय उठाता है। |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` एक फ्रेमवर्क-संगतता समस्या को चेतावनी दिए जाने और जारी रहने के बजाय उठाता है। |

<Warning>
  **`environment` में कोई अल्पविराम नहीं।** इनजेस्ट अपने फिल्टर बनाने के लिए उस फील्ड को अल्पविराम पर विभाजित करता है, और किसी भी ईवेंट को छोड़ देता है जिसका लेबल एक युक्त है — इसलिए एक पूरा रन चुप चाप गायब हो जाता है। `prod-eu` लिखें, `prod,eu` नहीं।

  `configure(environment="prod,eu")` उठाता है ताकि आप तुरंत खोज लें। `AGENTEYE_ENVIRONMENT` उठा नहीं सकता — कोई आपको कॉल नहीं कर रहा है — इसलिए यह एक बार चेतावनी देता है और `dev` पर वापस आता है।
</Warning>

ईवेंट्स मेमोरी में कतारबद्ध हैं और हर `flush_interval` सेकंड में पृष्ठभूमि में लिखे जाते हैं, इंटरप्रेटर एक्जिट पर एक अंतिम फ्लश के साथ। एक प्रक्रिया जो सीधे मारी जाती है, वह कुछ भी खो देती है जो अभी तक लिखी नहीं गई थी।

## पहचान

हर ईवेंट एक सेशन और एक एजेंट से संबंधित है। **स्कोप दोनों को भरते हैं**, इसलिए आप शायद ही कभी उन्हें पास करते हैं:

```python
with failproofai_sdk.session():
    with failproofai_sdk.agent("planner"):
        failproofai_sdk.event.tool_use(tool_name="search", tool_call_id="c1")
```

`session_id` या `agent_id` को स्पष्ट रूप से पास करना अभी भी काम करता है और जीतता है। न तो बाउंड और न ही पास के साथ, कॉल `TypeError` उठाता है बजाय एक ईवेंट उत्सर्जित करने के जो Cloud चुप चाप त्यागता है।

<Note>
  पहचान संदर्भ चर पर सवारी करती है। यह `asyncio` कार्यों को स्वचालित रूप से अनुसरण करता है, लेकिन **नए थ्रेड्स नहीं** — एक वर्कर को `failproofai_sdk.propagate()` में लपेटें या इसके ईवेंट्स अनलगाए रहते हैं।
</Note>

## ईवेंट कैटलॉग

पंद्रह मेथड्स। अधिकांश **जोड़े** में आते हैं — आप ओपनर को कॉल करते हैं, फिर क्लोजर को, और SDK अंतराल को समय करता है।

| | खुलता है | बंद करता है |
| --- | --- | --- |
| **एजेंट्स** | `agent_start` | `agent_end` |
| | `agent_pause` | `agent_resume` |
| **मॉडल्स** | `model_request` | `model_response` |
| **टूल्स** | `tool_use` | `tool_result` |
| **हुक्स** | `hook_triggered` | `hook_completed` |
| **मानव** | `human_wait` | `human_input` |

तीन अकेले खड़े हैं: `error`, `human_pause`, `human_interrupt`।

<Accordion title="हर फील्ड, प्रति मेथड" icon="table">

हर मेथड भी `session_id` और `agent_id` लेता है, जिन्हें स्कोप आपके लिए भरते हैं। कुछ भी `None` के रूप में छोड़ दिया गया JSON `null` के रूप में भेजने के बजाय dropped है, और हर मेथड `None` रिटर्न करता है।

| मेथड | आवश्यक | वैकल्पिक |
| --- | --- | --- |
| `agent_start` | — | `goal`, `parent_id` |
| `agent_end` | — | `outcome`, `summary` |
| `agent_pause` | `pause_id` | `reason`, `user_id` |
| `agent_resume` | `pause_id` | `reason`, `user_id` |
| `model_request` | — | `model`, `messages`, `system`, `tools`, `request_id` |
| `model_response` | — | `model`, `stop_reason`, `input_tokens`, `output_tokens`, `content`, `role`, `request_id`, `duration_ms` |
| `tool_use` | `tool_name`, `tool_call_id` | `input` |
| `tool_result` | `tool_name`, `tool_call_id` | `output`, `error` |
| `hook_triggered` | `hook_name`, `hook_id` | `trigger_event`, `input` |
| `hook_completed` | `hook_name`, `hook_id` | `outcome`, `output`, `error` |
| `error` | `error_type`, `message` | `traceback` |
| `human_wait` | `input_id` | `prompt`, `options`, `reason` |
| `human_input` | `input_id` | `response` |
| `human_pause` | — | `reason`, `user_id` |
| `human_interrupt` | — | `reason`, `user_id`, `at_step` |

</Accordion>

<Warning>
  एक रन को विफल के रूप में चिह्नित करने के लिए, `outcome` `failed`, `error`, `timeout` या `rejected` में से एक होना चाहिए। कुछ भी अन्य — निकट-मिस `"failure"` सहित — एक सफलता के रूप में गिना जाता है।
</Warning>

## पेयरिंग और अवधि

**एक नियम: क्लोजिंग ईवेंट को अपने ओपनर के समान ID दें।** यह वह है जो उन्हें जोड़ता है, और क्या SDK को अंतराल को समय देता है।

| जोड़ी | मिलान किया गया |
| --- | --- |
| `tool_use` → `tool_result` | `tool_call_id` |
| `hook_triggered` → `hook_completed` | `hook_id` |
| `agent_pause` → `agent_resume` | `pause_id` |
| `human_wait` → `human_input` | `input_id` |
| `model_request` → `model_response` | `request_id` |

**`duration_ms` को स्वयं पास न करें।** SDK इसे मापता है, और इसे पास करना `ValueError` उठाता है।

एक अपवाद `model_response` है, जहां केवल आप वास्तविक प्रदाता विलंबता जानते हैं। मिलीसेकंड की एक पूरी संख्या पास करें — एक फ्लोट उठाता है, क्योंकि कॉलम एक 32-बिट पूर्णांक है और अन्यथा खाली रहेगा।

<Accordion title="एज केसेस" icon="circle-help">

- **Ids को केवल प्रति प्रकार, प्रति सेशन में अद्वितीय होने की आवश्यकता है।** एक टूल कॉल और एक हुक एक साझा कर सकते हैं; एक साथ चलने वाले दो सेशन बिना टकराए समान IDs पुन: उपयोग कर सकते हैं।
- **वे एक एजेंट के लिए स्कोप नहीं हैं।** एक जोड़ी एक एजेंट के तहत खुली और दूसरे के तहत बंद अभी भी मेल खाती है — जो बहु-एजेंट कोड में सामान्य मामला है।
- **`request_id` वैकल्पिक है लेकिन अनुशंसित है।** इसके बिना, मॉडल ईवेंट्स उस क्रम में जोड़ी बनाते हैं जिस क्रम में वे आते हैं, इसलिए एक ही एजेंट में दो समवर्ती कॉल्स गलत जोड़ी बना सकते हैं।
- **एक जोड़ी प्रक्रियाओं के पार विभाजित** अभी भी Cloud में मेल खाती है, लेकिन SDK इसे समय नहीं कर सकता — कोई भी प्रक्रिया दोनों आधे नहीं देखे।
- **अधिकतम 10,000 ओपनर्स एक साथ क्लोजर की प्रतीक्षा करते हैं।** उसके बाद सबसे पुराना dropped है, इसलिए एक रिसाव बिना सीमा के विकसित नहीं हो सकता।

</Accordion>

## आपके अपने फील्ड्स

कोई भी अतिरिक्त कीवर्ड जो आप पास करते हैं ईवेंट के साथ संग्रहीत है:

```python
failproofai_sdk.event.tool_use(
    tool_name="search", tool_call_id="c1",
    fw_tenant="acme", fw_region="eu-west-1",     # आपके अपने
)
```

अगर आप बाद में उन्हें क्वेरी करना चाहते हैं तो JSON प्रकारों को वरीयता दें। कुछ भी अन्य — एक UUID, एक datetime, एक `Decimal`, एक सेट, बाइट्स, एक मॉडल ऑब्जेक्ट — एक स्ट्रिंग के रूप में संग्रहीत है।

<Warning>
  **अपने फील्ड नामों को प्रीफिक्स करें।** एक्सट्रास आखिरी लागू होते हैं, इसलिए `model`, `tool_name` या `outcome` कहा जाने वाला एक फील्ड चुप चाप वास्तविक को ओवरराइट करता है। फ्रेमवर्क एडेप्टर `fw_` का उपयोग करते हैं; वही करें और कुछ भी टकरा नहीं सकता।

  यही कारण है कि एक गलत वर्तनी वाली वैकल्पिक फील्ड कभी त्रुटि नहीं करती — यह सिर्फ एक नया कस्टम फील्ड बन जाती है। अगर एक मानक फील्ड Cloud में लापता है, तो पहले वर्तनी की जांच करें।
</Warning>

ये पांच नाम आरक्षित हैं और तुरंत अस्वीकार कर दिए गए हैं: `timestamp`, `session_id`, `agent_id`, `type`, `environment`।

## डिलीवर करें और सत्यापित करें

<Tabs>
  <Tab title="डैशबोर्ड">
    **Observe → Events** में, पहले `agent_start` मौजूद है और `agent_end` आखिरी मौजूद है यह सत्यापित करें। फिर **Observe → Sessions** खोलें और पुष्टि करें कि मॉडल, टूल, मानव, हुक, और त्रुटि ईवेंट्स इरादे के क्रम में दिखाई देते हैं। समस्या निवारण कुंजी के रूप में सेशन ID का उपयोग करें।
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai flush --wait --timeout 60
    failproofai config --status
    fp sessions --since 1h --env production --session-id <session-id>
    fp events --since 1h --session-id <session-id> --full
    ```
  </Tab>
</Tabs>

अगर Cloud खाली है, तो `$FAILPROOFAI_HOME/custom-agents/events` की जांच करें, अन्यथा `~/.failproofai/custom-agents/events`। JSONL फाइलें SDK उत्सर्जन साबित करती हैं; एक बढ़ता हुआ स्पूल डेमन कॉन्फ़िगरेशन या डिलीवरी की ओर इशारा करता है, जबकि एक खाली स्पूल इंस्ट्रूमेंटेशन या प्रक्रिया जीवनकाल की ओर इशारा करता है।

<Note>
  स्पूल की जांच केवल तभी करें जब डेमन रुका हो। जब यह चलता है, तो यह मिलीसेकंड के भीतर प्रत्येक बैच को एकत्र और हटाता है, इसलिए एक निर्देशिका सूची कलेक्टर के साथ दौड़ लगाती है और उत्सर्जित की तुलना में बहुत कम ईवेंट्स दिखाती है।
</Note>

## एक कस्टम रनटाइम में विफलताओं को रोकें

असुरक्षित कार्य, आवश्यक साक्ष्य, और इरादे की प्रतिक्रिया को परिभाषित करने के लिए ऑडिट निष्कर्ष और लिंक किए गए ट्रेस का उपयोग करें। एक कस्टम प्रवर्तन एकीकरण को निष्पादन से पहले कार्रवाई को उजागर करना चाहिए, इसके संरचित इनपुट को नीति इंजन में पास करना चाहिए, और परिणामी allow, instruct, या deny निर्णय लागू करना चाहिए।

[Failproof AI से संपर्क करें](mailto:support@befailproof.ai) और हम आपके रनटाइम के मॉडल, टूल और जीवनचक्र सीमाओं को नीति हुक्स में मैप करने में मदद करेंगे, फिर एकीकरण को आपके साथ सत्यापित करेंगे।
