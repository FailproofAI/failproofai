Python 3.11 या नया। कोई रनटाइम डिपेंडेंसीज नहीं। एक फ्रेमवर्क का उपयोग कर रहे हैं? [LangChain, CrewAI, LlamaIndex और Pydantic AI](/hi/start/integrations) एक कॉल के साथ खुद को इंस्ट्रूमेंट करते हैं।

<Note>
  एक **TypeScript SDK** भी है, और दोनों एक ही स्पूल में समान इवेंट्स लिखते हैं। Node एजेंट्स और Python एजेंट्स वाला एक फ्लीट एक सेट सेशन बनाता है, दो नहीं। कंपनी के अनुसार नहीं, प्रति सेवा चुनें।
</Note>

## इंस्टॉल करें

```bash
pip install failproofai-sdk
```

पैकेज को `failproofai-sdk` के रूप में इंस्टॉल किया गया है और Python में `failproofai_sdk` के रूप में आयात किया गया है। `failproofai-sdk[langgraph]` जैसे फ्रेमवर्क एक्सट्रास फ्रेमवर्क को स्वयं इंस्टॉल करते हैं; अडैप्टर्स हमेशा बेस व्हील में शिप होते हैं।

## कॉन्फ़िगरेशन

### OpenTelemetry स्पैन्स (ऑप्ट इन)

अलग से `opentelemetry-sdk` इंस्टॉल करें, फिर ऑप्शनल एक्सपोर्टर संलग्न करें:

```python
import failproofai_sdk
from opentelemetry.sdk.trace import TracerProvider

provider = TracerProvider()
failproofai_sdk.instrument("otel", provider=provider)
with provider.get_tracer("my-agent").start_as_current_span(
    "agent", attributes={"gen_ai.operation.name": "invoke_agent"}
):
    pass
provider.force_flush()
```

सेटअप आपके पंजीकृत प्रदाता को उपयोग करता है यदि आप `provider` को छोड़ते हैं, केवल तब बनाता है
जब कोई पंजीकृत नहीं है। आप `failproofai_sdk.OtelSpanExporter()` को भी सीधे अपने
स्पैन प्रोसेसर को पास कर सकते हैं। अन्य एक्सपोर्टर्स अपरिवर्तित रहते हैं।

कनेक्टेड FailproofAI डेमन एक्सपोर्ट्स डिलीवर करता है; SDK को कोई नेटवर्क
सेटअप, कुंजी, या स्थानीय श्रोता की आवश्यकता नहीं है। एक एडमिन को
[OpenTelemetry ingest](/hi/agenteye/opentelemetry) को सक्षम करना होगा। एक बार `instrument()` कभी
OTEL को सक्षम नहीं करता। `uninstrument("otel")` केवल अपने स्वयं के प्रोसेसर को अक्षम करता है।
आपका इंस्ट्रूमेंटेशन कंटेंट कैप्चर को नियंत्रित करता है। एक्जिट से पहले प्रदाता को फ्लश करें।
SDK अभी भी शून्य हार्ड रनटाइम डिपेंडेंसीज घोषित करता है और OpenTelemetry को
केवल अनुरोध किए जाने पर आयात करता है।

```python
import failproofai_sdk

failproofai_sdk.configure(
    base_dir=None,
    flush_interval=0.5,
    environment="production",
)
```

| तर्क | यह क्या करता है |
| --- | --- |
| `environment` | हर इवेंट पर लेबल — `production`, `staging`, `prod-eu`। डिफॉल्ट है `dev`। |
| `flush_interval` | बैकग्राउंड थ्रेड कितनी बार डिस्क में लिखता है, सेकंड में। डिफॉल्ट है `0.5`। |
| `base_dir` | कहाँ लिखना है। डिफॉल्ट डेमन का स्पूल है, जो आप चाहते हैं जब तक आप अन्यथा न जानते हों। |

इसके बजाय एनवायरनमेंट वेरिएबल द्वारा सेट करें:

| वेरिएबल | यह क्या करता है |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | कोड परिवर्तन के बिना `environment` सेट करता है, जब लेबल डिप्लॉयमेंट के बजाय ऐप के लिए हो। एक `configure()` तर्क इस पर जीत हासिल करता है। |
| `FAILPROOFAI_HOME` | Failproof AI रूट को स्थानांतरित करता है जो स्पूल को रखता है। |
| `FAILPROOFAI_SDK_STRICT` | `1` इंस्ट्रूमेंटेशन त्रुटियों को लॉग किए जाने के बजाय उठाता है। |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` फ्रेमवर्क-संगतता समस्या को चेतावनी देने और जारी रखने के बजाय उठाता है। |

<Warning>
  **`environment` में कोई अल्पविराम नहीं।** Ingest उस फील्ड को अल्पविराम पर विभाजित करता है अपने फिल्टर्स बनाने के लिए, और किसी भी इवेंट को छोड़ता है जिसमें लेबल में एक है — तो पूरा रन चुपचाप गायब हो जाता है। `prod-eu` लिखें, न कि `prod,eu`।

  `configure(environment="prod,eu")` उठाता है तो आप तुरंत पता चल जाता है। `AGENTEYE_ENVIRONMENT` नहीं उठा सकता — कोई आपको कॉल नहीं कर रहा — तो यह एक बार चेतावनी देता है और `dev` पर वापस आता है।
</Warning>

इवेंट्स मेमोरी में क्यूड होते हैं और प्रत्येक `flush_interval` सेकंड में बैकग्राउंड में लिखे जाते हैं, इंटरप्रेटर एक्जिट पर एक अंतिम फ्लश के साथ। एक प्रक्रिया जो सीधे मार दी जाती है, जो अभी तक नहीं लिखा गया था वह खो जाता है।

## पहचान

हर इवेंट एक सेशन और एजेंट के लिए है। **स्कोप्स दोनों को भरते हैं**, तो आप शायद ही कभी उन्हें पास करते हैं:

```python
with failproofai_sdk.session():
    with failproofai_sdk.agent("planner"):
        failproofai_sdk.event.tool_use(tool_name="search", tool_call_id="c1")
```

`session_id` या `agent_id` को स्पष्ट रूप से पास करना अभी भी काम करता है और जीत हासिल करता है। न तो बाउंड और न ही पास के साथ, कॉल `TypeError` उठाता है बजाय एक इवेंट उत्सर्जित करने के जो Cloud चुपचाप त्यागता।

<Note>
  पहचान संदर्भ वेरिएबल पर सवारी करती है। यह `asyncio` कार्यों को स्वचालित रूप से अनुसरण करता है, लेकिन **नहीं** नए थ्रेड्स — एक वर्कर को `failproofai_sdk.propagate()` में लपेटें या इसके इवेंट्स अनुलग्न हो जाते हैं।
</Note>

## इवेंट कैटलॉग

पंद्रह विधियां। अधिकांश **जोड़ी** में आते हैं — आप ओपनर कॉल करते हैं, फिर क्लोजर, और SDK अंतराल को समय देता है।

| | खुलता है | बंद करता है |
| --- | --- | --- |
| **एजेंट्स** | `agent_start` | `agent_end` |
| | `agent_pause` | `agent_resume` |
| **मॉडल्स** | `model_request` | `model_response` |
| **टूल्स** | `tool_use` | `tool_result` |
| **हुक्स** | `hook_triggered` | `hook_completed` |
| **मानव** | `human_wait` | `human_input` |

तीन अलग खड़े हैं: `error`, `human_pause`, `human_interrupt`।

<Accordion title="हर फील्ड, प्रति विधि" icon="table">

हर विधि भी `session_id` और `agent_id` लेती है, जो स्कोप्स आपके लिए भरते हैं। कुछ भी `None` के रूप में छोड़ दिया गया JSON `null` के रूप में भेजने के बजाय dropped होता है, और हर विधि `None` रिटर्न करती है।

| विधि | आवश्यक | ऑप्शनल |
| --- | --- | --- |
| `agent_start` | — | `goal`, `parent_id` |
| `agent_end` | — | `outcome`, `summary` |
| `agent_pause` | `pause_id` | `reason`, `user_id` |
| `agent_resume` | `pause_id` | `reason`, `user_id` |
| `model_request` | — | `model`, `messages`, `system`, `tools`, `request_id` |
| `model_response` | — | `model`, `stop_reason`, `input_tokens`, `output_tokens`, `content`, `role`, `request_id`, `duration_ms` |
| `tool_use` | `tool_name`, `tool_call_id` | `input` |
| `tool_result` | `tool_name`, `tool_call_id` | `output`, `error` |
| `hook_triggered` | `hook_name`, `hook_id` | `trigger_event`, `input` |
| `hook_completed` | `hook_name`, `hook_id` | `outcome`, `output`, `error` |
| `error` | `error_type`, `message` | `traceback` |
| `human_wait` | `input_id` | `prompt`, `options`, `reason` |
| `human_input` | `input_id` | `response` |
| `human_pause` | — | `reason`, `user_id` |
| `human_interrupt` | — | `reason`, `user_id`, `at_step` |

</Accordion>

<Warning>
  किसी रन को विफल के रूप में चिह्नित करने के लिए, `outcome` अवश्य `failed`, `error`, `timeout` या `rejected` में से एक होना चाहिए। कुछ और भी — जिसमें क़रीब-मिस `"failure"` — सफलता के रूप में गिना जाता है।
</Warning>

## जोड़ी और अवधि

**एक नियम: क्लोजिंग इवेंट को अपने ओपनर के समान id दें।** वह है जो उन्हें जोड़ता है, और क्या SDK को अंतराल को समय देने देता है।

| जोड़ी | मेल खाता है |
| --- | --- |
| `tool_use` → `tool_result` | `tool_call_id` |
| `hook_triggered` → `hook_completed` | `hook_id` |
| `agent_pause` → `agent_resume` | `pause_id` |
| `human_wait` → `human_input` | `input_id` |
| `model_request` → `model_response` | `request_id` |

**`duration_ms` स्वयं पास न करें।** SDK इसे मापता है, और इसे पास करने से `ValueError` उठता है।

एकमात्र अपवाद `model_response` है, जहां केवल आप असली प्रदाता विलंबता जानते हैं। मिलीसेकंड की पूरी संख्या पास करें — एक फ्लोट उठाता है, क्योंकि कॉलम एक 32-बिट पूर्णांक है और अन्यथा खाली हो जाएगा।

<Accordion title="किनारे के मामले" icon="circle-help">

- **Ids केवल प्रति प्रकार, प्रति सेशन के लिए अद्वितीय होने की जरूरत है।** एक टूल कॉल और एक हुक एक साझा कर सकते हैं; एक साथ चलने वाले दो सेशन समान ids को टकराए बिना पुनः उपयोग कर सकते हैं।
- **वे एक एजेंट के लिए स्कोप्ड नहीं हैं।** एक जोड़ी एक एजेंट के तहत खुली और दूसरे के तहत बंद अभी भी मेल खाती है — जो बहु-एजेंट कोड में सामान्य मामला है।
- **`request_id` ऑप्शनल लेकिन अनुशंसित है।** इसके बिना, मॉडल इवेंट्स आने के क्रम में जोड़ी हैं, तो एक ही एजेंट में दो समवर्ती कॉल्स गलत हो सकते हैं।
- **एक जोड़ी प्रक्रियाओं में विभाजित** अभी भी Cloud में मेल खाती है, लेकिन SDK इसे समय नहीं दे सकता — दोनों में से किसी भी प्रक्रिया ने दोनों हिस्सों को नहीं देखा।
- **एक बार में सबसे अधिक 10,000 ओपनर्स एक क्लोजर की प्रतीक्षा करते हैं।** उसके पास सबसे पुराना dropped होता है, तो एक लीक बिना बंधे बढ़ नहीं सकता।

</Accordion>

## आपके अपने फील्ड्स

कोई भी अतिरिक्त कीवर्ड जो आप पास करते हैं इवेंट के साथ संग्रहीत होता है:

```python
failproofai_sdk.event.tool_use(
    tool_name="search", tool_call_id="c1",
    fw_tenant="acme", fw_region="eu-west-1",     # आपका अपना
)
```

यदि आप बाद में उन्हें क्वेरी करना चाहते हैं तो JSON प्रकार को प्राथमिकता दें। कुछ और भी — एक UUID, एक datetime, एक `Decimal`, एक सेट, बाइट्स, एक मॉडल ऑब्जेक्ट — एक स्ट्रिंग के रूप में संग्रहीत है।

<Warning>
  **आपके फील्ड नामों को प्रीफिक्स करें।** Extras अंतिम रूप से लागू होते हैं, तो `model`, `tool_name` या `outcome` कहा जाने वाला फील्ड चुपचाप असली को ओवरराइट करता है। फ्रेमवर्क एडेप्टर्स `fw_` उपयोग करते हैं; आप भी ऐसा ही करें और कुछ भी टकरा नहीं सकता।

  यह भी है क्यों एक गलत-वर्तनी ऑप्शनल फील्ड कभी त्रुटि नहीं करता — यह केवल एक नए कस्टम फील्ड बन जाता है। यदि एक मानक फील्ड Cloud में गुम है, पहले स्पेलिंग की जांच करें।
</Warning>

ये पाँच नाम आरक्षित हैं और बिल्कुल अस्वीकार किए जाते हैं: `timestamp`, `session_id`, `agent_id`, `type`, `environment`।

## डिलीवर और सत्यापित करें

<Tabs>
  <Tab title="डैशबोर्ड">
    **Observe → Events** में, पहले `agent_start` मौजूद है और `agent_end` अंत में मौजूद है यह सत्यापित करें। फिर **Observe → Sessions** खोलें और पुष्टि करें कि मॉडल, टूल, मानव, हुक, और त्रुटि इवेंट्स इच्छित क्रम में दिखाई देते हैं। सेशन ID को प्राथमिक समस्या निवारण कुंजी के रूप में उपयोग करें।
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai flush --wait --timeout 60
    failproofai config --status
    fp sessions --since 1h --env production --session-id <session-id>
    fp events --since 1h --session-id <session-id> --full
    ```
  </Tab>
</Tabs>

यदि Cloud खाली है, `$FAILPROOFAI_HOME/custom-agents/events` निरीक्षण करें, अन्यथा `~/.failproofai/custom-agents/events`। JSONL फाइलें SDK उत्सर्जन साबित करती हैं; बढ़ता स्पूल डेमन कॉन्फ़िगरेशन या डिलीवरी को इंगित करता है, जबकि एक खाली स्पूल इंस्ट्रूमेंटेशन या प्रक्रिया जीवनकाल को इंगित करता है।

<Note>
  स्पूल को केवल तब निरीक्षण करें जब डेमन रुका हो। जबकि यह चलता है, यह प्रत्येक बैच को मिलीसेकंड के भीतर एकत्र करता है और हटाता है, तो एक डायरेक्टरी लिस्टिंग कलेक्टर के साथ दौड़ता है और उत्सर्जित इवेंट्स के बजाय बहुत कम दिखाता है।
</Note>
