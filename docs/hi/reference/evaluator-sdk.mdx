एक मूल्यांकनकर्ता एक पूर्ण एजेंट सत्र प्राप्त करता है और गुणवत्ता संकेत लौटाता है जो आपको परवाह हैं: संख्यात्मक स्कोर, प्रत्येक स्कोर के लिए एक व्याख्या, और एक वैकल्पिक सारांश। Failproof AI इन परिणामों को ट्रेस के साथ संग्रहीत करता है और उन्हें एजेंट और वातावरण में चार्ट करता है।

पैकेज `agenteye-evaluator` है, जिसे `agenteye_evaluator` के रूप में आयात किया जाता है। इसके लिए Python 3.10 या नए संस्करण की आवश्यकता है और यह `fastapi`, `pydantic>=2`, और `structlog` पर निर्भर है।

<Warning>
  **सार्वजनिक PyPI से `pip install agenteye-evaluator` स्थापना पथ नहीं है।** पैकेज केवल एक निजी रिलीज़ कलाकृति के रूप में प्रकाशित है, और नाम सार्वजनिक PyPI पर दावा नहीं किया गया है — एक बिना योग्य स्थापना किसी अन्य के पैकेज को उस सेवा में खींच सकती है जो आपके उत्पादन प्रतिलेखों को पढ़ता है। नीचे दी गई सीढ़ी का उपयोग करें।
</Warning>

## एक मूल्यांकनकर्ता सेट अप करें

<Steps>
  <Step title="SDK स्थापित करें">
    इस सीढ़ी के नीचे जाएं और पहली जगह पर रुकें जो लागू हो।

    मोनोरेपो के अंदर, जहां `evaluator-sdk/` निर्देशिका मौजूद है:

    ```bash
    pip install ./evaluator-sdk
    ```

    अन्यथा, निजी रिलीज़ से। व्हील `agenteye-enterprise/releases` पर GitHub Releases से संलग्न हैं, टैग किए गए `evaluator-sdk/v<version>`, और आपको `gh auth login` और उस रिपॉजिटरी तक पहुंच की आवश्यकता है:

    ```bash
    gh release download evaluator-sdk/v<version> \
      --repo agenteye-enterprise/releases --pattern '*.whl'
    pip install ./agenteye_evaluator-*.whl
    ```

    यदि कोई भी काम नहीं करता है, तो अपने Failproof AI संपर्क से व्हील मांगें बजाय कोई स्थापना खोजने के।

    `uvicorn` जानबूझकर एक निर्भरता नहीं है, इसलिए सर्वर को अलग से स्थापित करें:

    ```bash
    pip install 'uvicorn[standard]'
    ```
  </Step>

  <Step title="स्कोर करने के लिए परिभाषित करें">
    `evaluator.py` बनाएं। यह उदाहरण जांचता है कि क्या एक सत्र में कोई विफल उपकरण कॉल है।

    ```python
    import os
    from agenteye_evaluator import Evaluator, EvalResponse

    app = Evaluator(token=os.environ.get("EVALUATOR_TOKEN"))

    @app.config
    def config():
        return {"inactivity_timeout_secs": 1800}

    @app.evaluator
    def evaluate(req):
        tool_errors = sum(
            1 for item in req.events
            if item.event_type == "tool_result" and item.payload.get("error")
        )
        return EvalResponse(
            scores={"tool_reliability": 1.0 if tool_errors == 0 else 0.0},
            reasoning={"tool_reliability": f"{tool_errors} tool errors"},
        )
    ```

    पूरा कंस्ट्रक्टर `Evaluator(token: str | None = None, *, title: str = "AgentEye Evaluator")` है। टोकन की तुलना `hmac.compare_digest` से की जाती है; `title` FastAPI ऐप शीर्षक है और सौंदर्य संबंधी है।

    <Warning>
      `token=None` प्रमाणीकरण को पूरी तरह से अक्षम करता है। यह एक लैपटॉप पर ठीक है और उत्पादन में एक खतरा है, जहां एंडपॉइंट पूरे सत्र प्रतिलेख प्राप्त करता है।
    </Warning>
  </Step>

  <Step title="इसे स्थानीय रूप से चलाएं और परीक्षण करें">
    एक साझा टोकन सेट करें, मूल्यांकनकर्ता शुरू करें, और पुष्टि करें कि इसका स्वास्थ्य एंडपॉइंट प्रतिक्रिया देता है।

    ```bash
    export EVALUATOR_TOKEN=<shared-token>
    uvicorn evaluator:app --host 0.0.0.0 --port 8080
    ```

    एक अन्य टर्मिनल में:

    ```bash
    curl http://127.0.0.1:8080/health
    ```

    प्रत्येक डेकोरेटर फ़ंक्शन को अपरिवर्तित रूप में लौटाता है, इसलिए `evaluate(req)` सीधे कॉल करने योग्य रहता है। यही है जो यूनिट टेस्ट को सस्ता बनाता है — एक `EvalRequest` बनाएं और हैंडलर को कॉल करें, कोई HTTP शामिल नहीं।
  </Step>
</Steps>

## मूल्यांकनकर्ता को Failproof AI से कनेक्ट करें

1. मूल्यांकनकर्ता को एक HTTPS URL पर तैनात करें जो Failproof AI Cloud द्वारा पहुंचने योग्य है।
2. उस URL के साथ `EVALUATOR_ENDPOINT` को कॉन्फ़िगर करें और `EVALUATOR_TOKEN` को मूल्यांकनकर्ता द्वारा उपयोग किए गए समान टोकन पर सेट करें। प्रबंधित Cloud के लिए, कनेक्शन को कॉन्फ़िगर करने के लिए [support@befailproof.ai](mailto:support@befailproof.ai) से संपर्क करें।
3. एक मूल्यांकन चलाएं और पुष्टि करें कि इसके स्कोर Failproof AI में दिखाई देते हैं।

## डेकोरेटर और मार्ग

| डेकोरेटर | मार्ग | आवश्यक |
| --- | --- | --- |
| `@app.evaluator` | `POST /evaluate` | हाँ। |
| `@app.job_lookup` | `GET /evaluate/{job_id}` | केवल यदि आप कभी `JobPending` लौटाते हैं। बिना इसके, पोल को 404 मिलता है। |
| `@app.config` | `GET /config` | नहीं, लेकिन किसी भी सत्र के लिए आवश्यक जो कभी `agent_end` उत्सर्जित नहीं करता है — नीचे देखें। |

प्रत्येक डेकोरेटर एक सिंक्रोनस या असिंक्रोनस फ़ंक्शन स्वीकार करता है, इसे अपरिवर्तित लौटाता है, और यदि आप इसे दो बार पंजीकृत करते हैं तो `ValueError` उठाता है।

| मार्ग | प्रमाणीकरण |
| --- | --- |
| `GET /health` | टोकन सेट होने पर भी खुला। |
| `POST /evaluate` | Bearer। |
| `GET /evaluate/{job_id}` | Bearer। |
| `GET /config` | Bearer। |

bearer स्कीम मैच केस-असंवेदनशील है। `GET /config` कोई `@app.config` पंजीकृत नहीं होने पर भी `{"default_poll_interval_secs": 10}` लौटाता है, इसलिए SDK हमेशा एक गति विज्ञापन करता है।

SDK मूल्यांकन अनुरोध निकायों को 25 MiB पर कैप करता है, निकाय पढ़ने से पहले `Content-Length` के विरुद्ध जांच की जाती है। कैप से अधिक एक 413 है, जो एक 4xx है और इसलिए टर्मिनल है। अज्ञात अनुरोध फ़ील्ड को अनदेखा किया जाता है इसलिए सेवाएं घटना अनुबंध बढ़ने के साथ संगत रहती हैं।

<Warning>
  `@app.config` को `inactivity_timeout_secs` के साथ पंजीकृत करना ही है जो फॉलबैक स्कैनर को सक्षम करता है। इसके बिना, एक सत्र जो कभी `agent_end` उत्सर्जित नहीं करता है — कुछ भी परित्यक्त, दुर्घटनाग्रस्त, या अभी भी निष्क्रिय — कभी भी मूल्यांकन के लिए कतारबद्ध नहीं है। शून्य या उससे कम मान को हटाया जाता है।
</Warning>

## SDK प्रकार

| प्रकार | फ़ील्ड |
| --- | --- |
| `AgentEvent` | `id`, `ts`, `event_type`, `payload` |
| `EvalRequest` | `schema_version`, `session_id`, `agent_id`, `environment`, `started_at`, `ended_at`, `events` |
| `EvalResponse` | `scores`, `reasoning`, `summary` |

## अनुरोध और प्रतिक्रिया फ़ील्ड

| फ़ील्ड | प्रकार | नोट्स |
| --- | --- | --- |
| `EvalRequest.schema_version` | `str` | वर्तमान में `"1"`। |
| `session_id`, `agent_id`, `environment` | `str` | सत्र पहचान और वातावरण। |
| `started_at` | `datetime` | पहली घटना का समय। |
| `ended_at` | `datetime \| None` | `agent_end` घटना का समय, "जब सत्र रुका" नहीं। निष्क्रियता स्कैनर द्वारा कतारबद्ध सत्रों में कभी `agent_end` नहीं था और `None` आते हैं। |
| `events` | `list[AgentEvent]` | पूर्ण क्रमबद्ध घटना स्ट्रीम। |
| `AgentEvent.id` | `int` | बैकएंड घटना पंक्ति पहचानकर्ता। |
| `AgentEvent.ts` | `datetime` | घटना समय। |
| `AgentEvent.event_type` | `str` | घटना परिवार जैसे `tool_use`। |
| `AgentEvent.payload` | `dict[str, Any]` | पूरी घटना JSON समतल, इसलिए घटना-विशिष्ट फ़ील्ड शीर्ष स्तर पर बैठते हैं और `payload["type"]` `event_type` को दोहराता है। |
| `EvalResponse.scores` | `dict[str, float] \| None` | संख्यात्मक आयाम मूल्यांकन में चार्ट किए गए। |
| `EvalResponse.reasoning` | `dict[str, str] \| None` | प्रति-स्कोर व्याख्या; कुंजियों को `scores` को प्रतिबिंबित करना चाहिए। |
| `EvalResponse.summary` | `str \| None` | समग्र मूल्यांकन कथा। सर्वर-पक्ष पर 8192 बाइट पर काट दिया गया; `last_error` 2048 पर। |

सीरियलाइज़ेशन `exclude_none` का उपयोग करता है, इसलिए अनसेट फ़ील्ड भेजे जाने के बजाय `null` के रूप में छोड़े जाते हैं।

<Warning>
  `ended_at` से अवधि प्राप्त करना वास्तविक डेटा पर दुर्घटनाग्रस्त होता है। प्रत्येक सत्र जो निष्क्रियता स्कैनर कतारबद्ध करता है `ended_at` को `None` पर सेट किए जाने पर आता है। घटाने से पहले इसकी जांच करें।
</Warning>

## प्रतिक्रिया आकार लौटाएं

आपका हैंडलर बिल्कुल तीन चीजों में से एक को लौटा सकता है। कुछ और एक `TypeError` है, जो एक 500 के रूप में सामने आता है।

| वापसी | Wire `status` | टर्मिनल |
| --- | --- | --- |
| `EvalResponse(...)` | `done` | हाँ — स्कोर संग्रहीत। |
| `JobPending(job_id=...)` | `pending` | नहीं — सर्वर पोल करता है। |
| `done`, `pending`, या `error` में `status` के साथ एक कच्चा `dict` | दिया गया | `error` टर्मिनल है। |

`error` स्थिति का कोई टाइप किया गया मॉडल नहीं है। टर्मिनल रूप से विफल होने के लिए आपको एक कच्चा dict लौटाना होगा, और `error` एक गैर-खाली `str` होना चाहिए:

```python
return {"status": "error", "error": "model service unavailable"}
```

<Warning>
  **उठाना रिपोर्टिंग नहीं है।** एक अपवाद एक सामान्य 500 बन जाता है जिसका निकाय `"evaluator raised an internal error"` है — आपका अपवाद पाठ सर्वर तक कभी नहीं पहुंचता है, और सर्वर हर 5xx को क्षणिक मानता है और इसे फिर से प्रयास करता है। जब आप विफलता को रिकॉर्ड किए जाने के लिए चाहते हैं तो `error` dict लौटाएं।
</Warning>

## असिंक्रोनस कार्य लौटाएं

`JobPending` का उपयोग करें जब मूल्यांकन एक अनुरोध के अंदर समाप्त नहीं हो सकता। जॉब ID Failproof AI के लिए अपारदर्शी है और परिणाम संग्रहीत होने या सर्वर टाइमआउट समाप्त होने तक आपकी सेवा द्वारा हल करने योग्य रहना चाहिए।

```python
from agenteye_evaluator import EvalRequest, EvalResponse, Evaluator, JobPending

app = Evaluator(token="shared-secret")

@app.evaluator
def start(req: EvalRequest) -> JobPending:
    job_id = enqueue(req)
    return JobPending(job_id=job_id, next_poll_secs=30)

@app.job_lookup
def lookup(job_id: str):
    result = get_result(job_id)
    if result is None:
        return JobPending(job_id=job_id, next_poll_secs=30)
    return EvalResponse(
        scores=result.scores,
        reasoning=result.reasoning,
        summary=result.summary,
    )
```

पोलिंग गति इस क्रम में चुनी जाती है: `JobPending.next_poll_secs`, `EvaluatorConfig.default_poll_interval_secs`, फिर सर्वर का `EVALUATOR_POLLING_INTERVAL_SECS`। मान 1 सेकंड और 1 घंटे के बीच सीमित हैं। सर्वर की डिफ़ॉल्ट वॉल-क्लॉक पोलिंग कैप एक घंटा है, जिसके बाद परिणाम `timeout` के रूप में रिकॉर्ड किया जाता है।

स्वचालित मूल्यांकन तैनाती-व्यापी है और जब `EVALUATOR_ENDPOINT` अनुपस्थित है तो अक्षम रहता है।

| चर | डिफ़ॉल्ट | उद्देश्य |
| --- | --- | --- |
| `EVALUATOR_ENDPOINT` | अनसेट | मूल्यांकनकर्ता सेवा का आधार URL। |
| `EVALUATOR_TOKEN` | अनसेट | `Evaluator(token=...)` के साथ साझा bearer टोकन। |
| `EVALUATOR_WORKERS` | `2` | समवर्ती डिस्पैचर कार्यकर्ता। |
| `EVALUATOR_CLAIM_BATCH` | `4` | डिस्पैचर पास प्रति कतारबद्ध सत्र। |
| `EVALUATOR_POLLING_INTERVAL_SECS` | `10` | फॉलबैक असिंक्रोनस पोलिंग गति। |
| `EVALUATOR_REQUEST_TIMEOUT_MS` | `30000` | प्रति-अनुरोध मूल्यांकनकर्ता टाइमआउट, POST और प्रत्येक पोल पर लागू। |
| `EVALUATOR_MAX_ATTEMPTS` | `5` | टर्मिनल विफलता से पहले डिलीवरी प्रयास। |
| `EVALUATOR_CONFIG_REFRESH_SECS` | `300` | `/config` के लिए रिफ़्रेश गति। |
| `EVALUATOR_MAX_POLL_DURATION_SECS` | `3600` | अधिकतम वॉल-क्लॉक असिंक्रोनस पोलिंग समय। |

उस तालिका के दो परिणाम स्पष्ट रूप से कहने के लायक हैं:

- **कार्यकर्ता गुना दावा बैच आपकी समवर्तिता है।** डिफ़ॉल्ट पर वह आपके एंडपॉइंट के विरुद्ध 8 समवर्ती कॉल हैं, तैनाती-व्यापी। सेवा को उस संख्या के लिए आकार दें, एक के लिए नहीं।
- **4xx टर्मिनल है और 5xx, 429, या ट्रांसपोर्ट विफलता को `EVALUATOR_MAX_ATTEMPTS` तक बैकऑफ के साथ फिर से प्रयास किया जाता है**। एक टोकन बेमेल एक 401 है, इसलिए यह दोबारा प्रयास करने के बजाय तुरंत विफल हो जाता है — यह पहली बार जांचना है जब कुछ नहीं आता है।

सर्वर यह भी प्रतिबंधित कर सकता है कि कौन से संगठन तैनाती-वैश्विक मूल्यांकनकर्ता का उपयोग करते हैं। एंडपॉइंट, टोकन, फिर से प्रयास, और संगठन-गेट परिवर्तनों को ऑपरेटर कॉन्फ़िगरेशन के रूप में मानें और उन्हें बदलने के बाद सर्वर को पुनः आरंभ या रोल करें।

## सुरक्षा और संचालन

- जब ट्रैफ़िक एक विश्वसनीय नेटवर्क सीमा को पार करता है तो मूल्यांकनकर्ता को HTTPS के पीछे रखें।
- एक गैर-खाली bearer टोकन कॉन्फ़िगर करें और इसे दोनों सेवाओं पर समान रखें। `token=None` हर कॉलर को स्वीकार करता है।
- टोकन को लॉग न करें या अनुरोध पेलोड से पूर्ण संवेदनशील संकेत। SDK नहीं करता: सत्यापन विफलताएं पेलोड को गूंजे बिना 422 लौटाती हैं, 500s कभी अपवाद पाठ को गूंजते नहीं हैं, और टोकन कोई लॉग फ़ील्ड में दिखाई नहीं देता है।
- सिंक्रोनस हैंडलर को आइडेम्पोटेंट बनाएं; फिर से प्रयास एक अनुरोध को दोहरा सकते हैं।
- असिंक्रोनस जॉब स्थिति को उत्पादन में प्रक्रिया मेमोरी के बाहर बनाए रखें।
- स्थिर स्कोर कुंजी लौटाएं। एक कुंजी का नाम बदलने से पुरानी को बदलने के बजाय एक नई चार्ट सीरीज़ बनती है।

SDK संरचित जीवनचक्र लॉग उत्सर्जित करता है जैसे `eval received`, `eval responded`, `job lookup`, `config returned`, `auth rejected`, और हैंडलर अपवाद। `/config` प्रतिक्रियाएं `source="user"` के विरुद्ध `source="default"` को टैग करती हैं, इसलिए आप बता सकते हैं कि आपका `@app.config` उठाया गया था या नहीं। यह लॉगिंग हैंडलर को कॉन्फ़िगर नहीं करता है; होस्ट एप्लिकेशन के लॉगिंग कॉन्फ़िगरेशन का उपयोग करें।
