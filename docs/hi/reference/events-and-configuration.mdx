## ईवेंट फैमिलीज़

- एजेंट स्टार्ट, एंड, पॉज़, और रेज़्यूम
- मॉडल रिक्वेस्ट और रेस्पांस
- टूल यूज़ और रिजल्ट
- हुक ट्रिगर्ड और कंप्लीटेड
- ह्यूमन वेट, इनपुट, पॉज़, और इंटरप्ट
- एक्सप्लिसिट एरर्स

हर ईवेंट में टाइमस्टैम्प, सेशन आईडी, एजेंट आईडी, ईवेंट टाइप, और एनवायरनमेंट होता है। ईवेंट-स्पेसिफिक फील्ड्स में मॉडल, टूल, कोरिलेशन, आउटकम, कंटेंट, ड्यूरेशन, या एरर डेटा होता है।

## एक ईवेंट कॉन्ट्रैक्ट इंस्पेक्ट करें

<Tabs>
  <Tab title="डैशबोर्ड">
    1. **Observe → Events** खोलें।
    2. एक छोटी टाइम विंडो सेट करें और एनवायरनमेंट, एजेंट, और ईवेंट टाइप के अनुसार फ़िल्टर करें।
    3. किसी ईवेंट को सिलेक्ट करें इसके नॉर्मलाइज़्ड फील्ड्स और रॉ पेलोड को इंस्पेक्ट करने के लिए, फिर इसके सेशन को एक्सीक्यूशन कॉन्टेक्स्ट देखने के लिए खोलें।
    4. अगर कोई पेयर्ड ड्यूरेशन मिसिंग है, तो वेरिफाई करें कि स्टार्ट और कंप्लीशन ईवेंट्स एक ही कोरिलेशन आईडी का उपयोग करते हैं।

    इवेंट्स स्ट्रीम का उपयोग करके डेटा को एक एजेंट रन तक सीमित करें और नॉर्मलाइज़्ड ईवेंट फील्ड्स को इंस्पेक्ट करें।

    ![एनवायरनमेंट, एजेंट, सेशन, और ईवेंट टाइप के लिए फ़िल्टर्स के साथ लाइव ईवेंट्स स्ट्रीम।](/images/dashboard/events-stream.png)

    फिर ईवेंट को इसके सेशन में फॉलो करें। ट्रेस दिखाता है कि इसके तुरंत पहले और बाद में क्या हुआ, जो तब आवश्यक है जब पेलोड अकेले अस्पष्ट हो।

    ![एक्सीक्यूशन कॉन्टेक्स्ट में ईवेंट को इंस्पेक्ट करने के लिए उपयोग किए गए लिंक्ड सेशन ट्रेस।](/images/dashboard/session-detail.png)

    जब कोई पेयर्ड ईवेंट या ड्यूरेशन मिसिंग हो तो दोनों व्यूज़ में कोरिलेशन आईडीज़ और टाइमस्टैम्प्स की तुलना करें।
  </Tab>
  <Tab title="CLI">
    वैलिड फ़िल्टर वैल्यूज़ खोजें, फिर एक सेशन के लिए पूरे ईवेंट पेलोड्स फेच करें:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    मशीन-रीडेबल इंस्पेक्शन के लिए `fp --json events ... --fields ts,event_type,session_id,payload` का उपयोग करें।
  </Tab>
</Tabs>

## रिजर्व्ड SDK फील्ड्स

`timestamp`, `session_id`, `agent_id`, `type`, या `environment` को कस्टम Python SDK फील्ड्स के रूप में उपयोग न करें। पेयर्ड ईवेंट ड्यूरेशन्स जैसे टूल रिजल्ट ड्यूरेशन SDK द्वारा कैलकुलेट किए जाते हैं और मैन्युअली सप्लाई नहीं किए जा सकते।

## लोकल बाउंडरीज़

- Failproof AI स्टेट `~/.failproofai` के अंतर्गत रहता है जब तक कि स्पष्ट रूप से अन्यथा कॉन्फ़िगर न किया जाए।
- `failproofai-sdk` अपनी लीगेसी बेस-डायरेक्टरी ओवरराइड के लिए `AGENTEYE_HOME` का उपयोग करता है।
- एनवायरनमेंट लेबल्स SDK कॉन्फ़िगरेशन या `AGENTEYE_ENVIRONMENT` के माध्यम से सेट किए जा सकते हैं।
- डेमॉन क्रेडेंशियल्स नॉन-सीक्रेट सेटिंग्स से अलग से स्टोर किए जाते हैं।

स्टेबल, लो-कार्डिनैलिटी एनवायरनमेंट नामों का उपयोग करें। डेमॉन एनवायरनमेंट लेबल्स में कॉमाज़ सपोर्टेड नहीं हैं।

## एक एनवायरनमेंट लेबल बदलें

<Tabs>
  <Tab title="डैशबोर्ड">
    एनवायरनमेंट लेबल्स एमिटिंग SDK या Failproof डेमॉन द्वारा असाइन किए जाते हैं। एक को बदलने के बाद, **Observe → Sessions** खोलें और एनवायरनमेंट फ़िल्टर का उपयोग करके कन्फर्म करें कि नए सेशन्स नई वैल्यू ले जाते हैं। मौजूदा सेशन्स अपना ओरिजिनल एनवायरनमेंट रिटेन करते हैं।

  </Tab>
  <Tab title="CLI">
    `failproofai-sdk` के लिए, कोड में या इसके लीगेसी एनवायरनमेंट वेरिएबल के साथ एनवायरनमेंट कॉन्फ़िगर करें। मशीन-लेवल सेटिंग्स बदलते समय डेमॉन कॉन्फ़िगरेशन को रीरन करें।

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
