स्थानीय CLI को `npm install -g failproofai` के साथ इंस्टॉल करें। इसे बिना किसी आर्गुमेंट के चलाएं ताकि स्थानीय नीति डैशबोर्ड खुले।

पैकेज के लिए Node.js 20.9 या नए संस्करण की आवश्यकता है। Bun 1.3 या नए संस्करण विकास और स्रोत इंस्टॉल के लिए समर्थित हैं। `failproofai configure` और `failproofai setup` क्रमशः `failproofai config` के उपनाम हैं; `failproofai p` एक उपनाम है `failproofai policies` के लिए।

## एक मशीन सेट अप करें

```bash
npm install -g failproofai
failproofai config \
  --connect https://app.befailproof.ai \
  --token <machine-key> \
  --machine-label checkout-prod-01
failproofai policies --install
failproofai config --status
```

स्थानीय नीति डैशबोर्ड खोलने के लिए बिना किसी आर्गुमेंट के `failproofai` चलाएं।

| कमांड | परिणाम |
| --- | --- |
| `failproofai config` | इंटरैक्टिव मशीन सेटअप चलाएं |
| `failproofai config --connect <url> --token <key>` | क्लाउड इनजेशन और नीति डिलीवरी कनेक्ट करें |
| `failproofai config --status` | कनेक्शन, डेमॉन, डिलीवरी और पॉज़ स्थिति दिखाएं |
| `failproofai policies` | बिल्ट-इन और कस्टम नीतियों को सूचीबद्ध करें |
| `failproofai policies --install` | हुक्स इंस्टॉल करें और नीतियों को सक्षम करें |
| `failproofai policy add <name>` | एक बिल्ट-इन नीति सक्षम करें |
| `failproofai policy remove <name>` | एक बिल्ट-इन नीति अक्षम करें |
| `failproofai policies --uninstall` | नीतियों को अक्षम करें या हार्नेस हुक्स को हटाएं |
| `failproofai audit` | स्थानीय एजेंट इतिहास स्कैन करें और स्थानीय ऑडिट दृश्य खोलें |
| `failproofai audit --schedule [days] --email <address>` | आवर्ती स्थानीय स्कैन शेड्यूल करें और उनकी निष्कर्षों को ईमेल करें |
| `failproofai audit --status` | रिपोर्ट पता, अंतराल, और अगली अनुसूचित स्कैन दिखाएं |
| `failproofai audit --no-schedule` | आवर्ती स्कैन बंद करें ऑडिट इतिहास मिटाए बिना |
| `failproofai harness list` | अतिरिक्त कैप्चर पथों को सूचीबद्ध करें |
| `failproofai flush --wait` | वर्तमान ईवेंट स्पूल डिलीवर करें |
| `failproofai backfill --since 30d` | पहले से पास किए गए इतिहास को फिर से पढ़ें |
| `failproofai config --pause [duration]` | एक स्थानीय सेशन को डिफ़ॉल्ट रूप से 30 मिनट के लिए पॉज़ करें, अधिकतम 8 घंटे तक |
| `failproofai config --resume` | एक पॉज़ किए गए स्थानीय सेशन को फिर से शुरू करें; सभी पॉज़ को हटाने के लिए `--all` जोड़ें |
| `failproofai update` | पैकेज माइग्रेशन पूरा करें और डेमॉन को अपडेट करें |
| `failproofai migrate --dry-run` | लंबित होम-लेआउट माइग्रेशन का पूर्वावलोकन करें या चलाएं |
| `failproofai uninstall` | पैकेज को हटाने से पहले हुक्स और डेमॉन को हटाएं |
| `failproofai --version` | इंस्टॉल किए गए पैकेज संस्करण को प्रिंट करें |
| `failproofai --help` | कमांड और वैश्विक उपयोग दिखाएं |

## कॉन्फ़िगरेशन फ्लैग्स

| फ्लैग | उपयोग |
| --- | --- |
| `--connect <url> --token <key>` | गैर-इंटरैक्टिव रूप से कनेक्ट करें |
| `--machine-id <id>` | स्थिर मशीन ID सेट करें |
| `--machine-label <name>` | डैशबोर्ड लेबल सेट या परिवर्तित करें |
| `--no-transcripts` | ट्रांसक्रिप्ट सामग्री के बिना निर्णय भेजें |
| `--disconnect` | क्लाउड नीति पुल और ईवेंट डिलीवरी बंद करें |
| `--status` | वर्तमान मशीन स्थिति दिखाएं |
| `--pause [duration]` | वर्तमान निर्देशिका में नवीनतम सेशन को पॉज़ करें; सेकंड, मिनट या घंटे स्वीकार करता है और डिफ़ॉल्ट रूप से 30 मिनट होता है |
| `--resume` | मिलान किए गए पॉज़ को जल्दी समाप्त करें |
| `--session <id>` | पॉज़ या फिर से शुरू करने के लिए एक स्पष्ट सेशन को लक्षित करें |
| `--all` | `--resume` के साथ, प्रत्येक सक्रिय पॉज़ को समाप्त करें |

स्थानीय पॉज़ एक सेशन के लिए बिल्ट-इन, कस्टम और सम्मेलन नीतियों को निलंबित करते हैं। वे हमेशा समाप्त होते हैं और क्लाउड-प्रबंधित नीतियों को अक्षम नहीं करते। `block-self-pause` एक इंस्ट्रुमेंटेड एजेंट को इस एस्केप हैच का स्वयं उपयोग करने से रोकता है।

## नीति फ्लैग्स

| फ्लैग | उपयोग |
| --- | --- |
| `--install`, `-i` | नीतियों को सक्षम करें और हार्नेस हुक्स इंस्टॉल करें |
| `--uninstall`, `-u` | नीतियों को अक्षम करें या हुक्स को हटाएं |
| `--cli <names...>` | एक या अधिक समर्थित हार्नेस को लक्षित करें |
| `--scope user\|project\|local\|all` | कॉन्फ़िगरेशन स्कोप चुनें; `all` अनइंस्टॉल के लिए है |
| `--beta` | बीटा नीतियों को शामिल करें |
| `--custom`, `-c <path>` | एक कस्टम नीति फ़ाइल को सत्यापित और लोड करें; दोहराने योग्य |

## डिलीवरी और रखरखाव फ्लैग्स

| कमांड | फ्लैग्स |
| --- | --- |
| `backfill` | `--since <30d\|6m\|YYYY-MM-DD>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` |

`failproofai update` को `npm install -g failproofai@latest` के बाद चलाया जाना चाहिए; यह होम-लेआउट माइग्रेशन करता है, मिलान डेमॉन बाइनरी को इंस्टॉल करता है, और सेवा को फिर से शुरू करता है। `--no-daemon` केवल लेआउट माइग्रेशन करता है।

## हार्नेस पथ

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

समर्थित हार्नेस नाम `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, और `goose` हैं।

लेबल व्युत्पन्न एजेंट ID को नेमस्पेस करते हैं जब दो रूट्स में एक ही प्रोजेक्ट की कॉपी होती है। डुप्लिकेट संग्रह या कर्सर भ्रष्टाचार को रोकने के लिए ओवरलैपिंग रूट्स और डुप्लिकेट लेबल को अस्वीकार किया जाता है। अतिरिक्त-पथ कॉन्फ़िगरेशन डेमॉन पुनरारंभ के बिना पुनः लोड होता है।

कंटेनर वातावरण फ़ाइल-कॉन्फ़िगर किए गए अतिरिक्त पथों को `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` नाम के अल्पविराम-पृथक वेरिएबल से बदल सकते हैं, उदाहरण के लिए:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## पर्यावरण वेरिएबल्स

स्थायी मशीन व्यवहार के लिए कॉन्फ़िगरेशन फ़ाइलों का उपयोग करें। पर्यावरण वेरिएबल्स कंटेनर, परीक्षण और एक प्रक्रिया के लिए सबसे उपयोगी हैं।

| वेरिएबल | उपयोग |
| --- | --- |
| `FAILPROOFAI_HOME` | संपूर्ण `~/.failproofai` लेआउट को स्थानांतरित करें |
| `FAILPROOFAI_LOG_LEVEL` | स्थानीय लॉगिंग वर्बोसिटी सेट करें |
| `FAILPROOFAI_HOOK_LOG_FILE` | हुक डायग्नोस्टिक्स को एक चयनित फ़ाइल में लिखें |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | इस प्रक्रिया के लिए अनाम टेलीमेट्री अक्षम करें |
| `FAILPROOFAI_NO_FIRST_RUN=1` | इंटरैक्टिव प्रथम-रन सेटअप को छोड़ें |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | पोस्ट-सेटअप स्थानीय ऑडिट को छोड़ें |
| `FAILPROOFAI_LLM_BASE_URL` | LLM नीतियों द्वारा उपयोग किए गए OpenAI-संगत एंडपॉइंट को ओवरराइड करें |
| `FAILPROOFAI_LLM_API_KEY` | LLM नीतियों द्वारा उपयोग किए गए API कुंजी की आपूर्ति करें |
| `FAILPROOFAI_LLM_MODEL` | LLM नीतियों द्वारा उपयोग किए गए मॉडल का चयन करें |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | कस्टम नीति मॉड्यूल लोडिंग को बाउंड करें |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | एक हार्नेस के लिए कॉन्फ़िगर किए गए अतिरिक्त कैप्चर पथों को बदलें |
| `NO_COLOR` | रंगीन टर्मिनल आउटपुट अक्षम करें |

एजेंट-विशिष्ट होम वेरिएबल्स जैसे `CLAUDE_PROJECTS_PATH`, `CURSOR_HOME`, `HERMES_HOME`, और `OPENCLAW_HOME` इस बात को ओवरराइड करते हैं कि Failproof AI उस हार्नेस के लिए स्थानीय सेशन को कहां खोजता है।

## एक मशीन को सुरक्षित रूप से पॉज़ करें या हटाएं

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

एक स्थानीय सेशन पॉज़ क्लाउड-प्रबंधित नीतियों को अक्षम नहीं करता। जब रोलआउट स्वयं समस्या है, तब क्लाउड प्रवर्तन वर्कफ़्लो के माध्यम से क्लाउड डिप्लॉयमेंट को पुनः स्थापित करें।

npm पैकेज को हटाने से पहले, इंस्टॉल किए गए हुक्स और डेमॉन को हटाएं:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

संस्करण-विशिष्ट विवरण के लिए `failproofai <command> --help` चलाएं।

<Warning>
  `npm rm -g failproofai` से पहले `failproofai uninstall` चलाएं; npm इंस्टॉल किए गए एजेंट हुक्स या डेमॉन सेवा को नहीं हटाता।
</Warning>
