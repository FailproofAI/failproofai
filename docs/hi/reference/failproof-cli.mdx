`npm install -g failproofai` के साथ इंस्टॉल करें। बिना किसी आर्गुमेंट के `failproofai` चलाएं ताकि स्थानीय डैशबोर्ड खुले।

## मुख्य कमांड

| कमांड | क्या करता है |
| --- | --- |
| `failproofai config` | एजेंट, बैकग्राउंड सर्विस, और वैकल्पिक Cloud कनेक्शन सेट अप करें |
| `failproofai config --token <key>` | सेटअप करें और बिना सवालों के कनेक्ट करें |
| `failproofai config --status` | कनेक्शन, सर्विस संस्करण, और पॉज़ स्थिति दिखाएं |
| `failproofai policies` | नीतियों की सूची दिखाएं और यह देखें कि वे चालू हैं या नहीं |
| `failproofai policies add <name>` | एक नीति चालू करें |
| `failproofai policies add <owner>/<repo>` | एक नीति पैक इंस्टॉल करें |
| `failproofai policies remove <name-or-pack>` | एक नीति बंद करें या पैक हटाएं |
| `failproofai policies show <owner>/<repo>` | इंस्टॉल करने से पहले एक पैक का निरीक्षण करें |
| `failproofai publish` | अपनी नीतियों को पैक के रूप में प्रकाशित करें |
| `failproofai audit` | स्थानीय एजेंट इतिहास स्कैन करें |
| `failproofai harness` | अतिरिक्त सेशन स्थानों का प्रबंधन करें |
| `failproofai flush` | कतारबद्ध इवेंट अभी भेजें |
| `failproofai backfill` | पुराने एजेंट इतिहास को फिर से पढ़ें |
| `failproofai update` | npm अपग्रेड पूरा करें और सर्विस को अपडेट करें |
| `failproofai uninstall` | हुक और सर्विस हटाएं |

`policy`, `pack`, और `p` को `policies` के लिए उपनाम के रूप में स्वीकार किया जाता है, लेकिन दस्तावेज़ `policies` का उपयोग करता है।

## मशीन सेट अप करें

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

सेटअप कोई नीति पैक नहीं चुनता। इससे पहले कि आप एक जोड़ें, केवल `block-failproofai-commands` चलता है।

अनुपस्थित Cloud सेटअप के लिए:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

ट्रांसक्रिप्ट के बिना निर्णय भेजने के लिए, पहले कनेक्ट करें और `~/.failproofai/config.json` में `collector.sessions` को `false` पर सेट करें। वर्तमान `--no-transcripts` सेटअप फ़्लैग को पार्स किया जाता है लेकिन वह सेटिंग लागू नहीं करता।

मशीन के कनेक्ट होने के बाद इसका नाम बदलने के लिए `--machine-label <name>` का उपयोग करें। `--connect <url>` एक पहले से सेट अप मशीन के लिए केवल नामांकन कमांड है।

## नीतियां और पैक

```bash
failproofai policies
failproofai policies add block-sudo
failproofai policies show owner/repo
failproofai policies add owner/repo --category git,database
failproofai policies remove owner/repo
```

स्लैश वाली कोई भी चीज़ एक पैक स्रोत है; बिना स्लैश वाली कोई भी चीज़ एक नीति नाम है।

उपयोगी पैक चयन फ़्लैग:

| फ़्लैग | उपयोग |
| --- | --- |
| `--policy a,b` | नाम दिए गए नीतियों का चयन करें |
| `--category x,y` | श्रेणियों का चयन करें |
| `--all` | सब कुछ चुनें |
| `--cli <agents...>` | नाम दिए गए हार्नेस तक सीमित करें |

कस्टम नीति किसी भी पथ से लोड करने के लिए `failproofai policies -i -c <path>` का उपयोग करें। `.failproofai/policies/` के तहत `*policies.{js,mjs,ts}` नाम की कन्वेंशन फ़ाइलें स्वचालित रूप से लोड होती हैं।

## प्रवर्तन को रोकें

```bash
failproofai config --pause 10m
failproofai config --status
failproofai config --resume
```

एक पॉज़ एक स्थानीय सेशन पर लागू होता है और हमेशा समाप्त हो जाता है। यह Cloud-प्रबंधित नीतियों या `block-failproofai-commands` को पॉज़ नहीं करता।

## ऑडिट और डिलीवरी

```bash
failproofai audit
failproofai audit --schedule 7 --email team@example.com
failproofai audit --status
failproofai flush --wait
failproofai backfill --since 30d --dry-run
```

`backfill` `~/.failproofai/config.json` को पढ़ता है। इतिहास को फिर से भेजने के लिए `--dry-run` हटाएं।

## अतिरिक्त सेशन स्थान

```bash
failproofai harness list
failproofai harness add-path claude work=/srv/team/.claude/projects
failproofai harness remove-path claude work
```

लेबल दो प्रतिलिपि किए गए होम्स को एक ही व्युत्पन्न एजेंट ID के अंतर्गत मर्ज होने से रोकते हैं।

समर्थित हार्नेस हैं `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, और `goose`। स्कोप समर्थन भिन्न होता है; [Harnesses](/hi/reference/harnesses) देखें।

## उपयोगी पर्यावरण चर

| चर | उपयोग |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | Cloud मशीन की |
| `FAILPROOFAI_CLOUD_URL` | Cloud URL को ओवरराइड करें |
| `FAILPROOFAI_HOME` | स्थानीय स्थिति निर्देशिका को स्थानांतरित करें |
| `FAILPROOFAI_NO_DOWNLOAD=1` | पैक और सर्विस डाउनलोड से इनकार करें |
| `FAILPROOFAI_DAEMON_BASE_URL` | एक सर्विस-बाइनरी मिरर का उपयोग करें |
| `FAILPROOFAI_PACK_BASE_URL` | एक पैक मिरर का उपयोग करें |
| `FAILPROOFAI_NO_FIRST_RUN=1` | पहली बार चलाने वाले संकेतों को अक्षम करें |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | अनाम CLI टेलीमेट्री अक्षम करें |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | एक हार्नेस के लिए अतिरिक्त पथ को प्रतिस्थापित करें |
| `NO_COLOR` | टर्मिनल रंग अक्षम करें |

## हटाएं या अपग्रेड करें

```bash
npm install -g failproofai@latest
failproofai update
```

पैकेज हटाने से पहले:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

<Warning>
  npm पैकेज को हटाने से पहले `failproofai uninstall` चलाएं। npm इंस्टॉल किए गए हुक या बैकग्राउंड सर्विस को नहीं हटाता।
</Warning>

अपने इंस्टॉल किए गए संस्करण में संपूर्ण विकल्प के लिए `failproofai help <command>` चलाएं।
