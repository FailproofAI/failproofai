`npm install -g failproofai` के साथ स्थानीय CLI इंस्टॉल करें। इसे कोई तर्क दिए बिना चलाएं तो स्थानीय नीति डैशबोर्ड खुल जाएगा।

पैकेज को Node.js 20.9 या नए संस्करण की आवश्यकता है। Bun 1.3 या नए संस्करण को विकास और स्रोत इंस्टॉल के लिए समर्थित किया जाता है। `failproofai configure` और `failproofai setup` दोनों `failproofai config` के लिए उपनाम हैं। `failproofai policy`, `failproofai pack` और `failproofai p` सभी `failproofai policies` की वर्तनी हैं — पैक्स और एकल नीतियां एक ही विचार के लिए तीन कमांड थीं और अब एक हैं। पुरानी वर्तनियां अभी भी काम करती हैं, दो अपवादों के साथ: `pack list <source>` अब `policies show <source>` है, और `pack build` अब `publish` है।

## एक मशीन सेट अप करें

CLI इंस्टॉल करें, फिर मशीन की कुंजी को शेल में पढ़ें। `read -s` इसे एक प्रॉम्प्ट पर लेता है जो प्रतिध्वनि नहीं करता, इसलिए यह कभी कमांड में प्रदर्शित नहीं होता:

```bash
npm install -g failproofai
read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
```

फिर मशीन को सेट अप करें और चुनें कि यह क्या लागू करता है:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

`failproofai config` पूरी सेटअप है: यह `failproofaid` सेवा को इंस्टॉल करता है (एक बार रूट — एक टर्मिनल में यह आपका sudo पासवर्ड मांगता है, और फिर से पूछता है यदि यह सेटअप खत्म होने से पहले समाप्त हो गया हो; बिना टर्मिनल के यह `sudo -n` का उपयोग करता है और कभी भी प्रॉम्प्ट नहीं करता), हर एजेंट CLI में हुक को वायर करता है जो यह पाता है, और क्लाउड से जुड़ता है। बिना टर्मिनल के — CI, कंटेनर, एजेंट इसे ड्राइव कर रहा है — यह पूछने के बजाय लागू करता है, और यदि कोई भी चीज़ जो पूछी गई थी वह नहीं हुई तो 1 से बाहर निकलता है।

एक टर्मिनल में, एक मशीन पर जो अभी तक कनेक्ट नहीं है **क्लाउड से कनेक्ट करें** चरण तुरंत **Failproof AI क्लाउड में लॉगिन** शुरू करता है; अन्य विकल्पों के लिए Tab दबाएं, **API कुंजी चिपकाएं** या **ओपन सोर्स का उपयोग करें**। लॉगिन एक लिंक खोलता है — या SSH पर प्रिंट करता है या बिना डिस्प्ले के, किसी भी डिवाइस पर खोलने के लिए — जहां आप साइन अप या साइन इन करते हैं, एक org चुनते या बनाते हैं, और मशीन को अधिकृत करते हैं; टर्मिनल स्वयं को मंजूरी उठाता है और दिखाता है कि किसने इसे अनुमोदित किया और किस org के लिए। कुंजी केवल तब बनाई जाती है जब सेटअप समाप्त हो जाता है, डेमन इंस्टॉल होने के बाद। एक मशीन पर जो पहले से एक कार्यशील कुंजी के साथ कनेक्ट है, यह चरण **वर्तमान कनेक्शन रखें** के साथ एक मेनू है, इसलिए सेटअप को फिर से चलाने से कभी भी ब्राउज़र खुद से नहीं खुलता; एक सहेजी गई कुंजी जो अब काम नहीं करती तुरंत लॉगिन फिर से शुरू करती है, और कहती है क्यों। फिर से लॉगिन करने से एक नई कुंजी बनती है और पुरानी को तब तक काम करने देती है जब तक आप इसे रद्द नहीं करते। ब्राउज़र लॉगिन से पहले का क्लाउड ऐसा कहता है और अन्य विकल्पों की पेशकश करता है।

यह **कोई** नीतियां नहीं चुनता। यह दूसरी कमांड का काम है, और इसके बिना एक ताजा कॉन्फ़िगर किया हुआ मशीन केवल हमेशा-चालू गार्ड लागू करता है।

`--token` पर पर्यावरण चर को प्राथमिकता दें: एक कमांड-लाइन तर्क बॉक्स पर हर उपयोगकर्ता के लिए `ps` से पठनीय है। यह सब है जो चर की रक्षा करता है — एक कुंजी किसी भी कमांड में टाइप की जाती है, `export` सहित, अभी भी शेल इतिहास में लैंड करती है, यही कारण है कि इसे ऊपर `read -s` के साथ पढ़ा जाता है। CI में, इसे गुप्त स्टोर से सेट करें और शेल ट्रेसिंग को (`set -x`) बंद रखें, या ट्रेस इसे प्रिंट करता है।

<Warning>
  `--connect <url>` एक मशीन को नामांकित करता है जो **पहले से सेट अप है**। यह नामांकन के सफल होते ही वापस आता है — यह डेमन को इंस्टॉल नहीं करता और कोई भी हुक को वायर नहीं करता। एक मशीन पर सादा `failproofai config` (या `failproofai config --token <key>`) का उपयोग करें जिसे अभी तक सेट अप नहीं किया गया है, अन्यथा यह कनेक्ट के रूप में पढ़ेगा जबकि कुछ भी इकट्ठा और लागू नहीं कर रहा है।
</Warning>

बिना तर्क के `failproofai` चलाएं तो स्थानीय नीति डैशबोर्ड खुल जाएगा।

| कमांड | परिणाम |
| --- | --- |
| `failproofai config` | मशीन को सेट अप करें: एजेंट, डेमन, और क्लाउड — ब्राउज़र के माध्यम से लॉगिन करें, एक कुंजी चिपकाएं, या ओपन सोर्स रहें। मशीन पर हर एजेंट को एक छोटा सा `failproofai` कौशल भी मिलता है जो इसे [FailproofAI कौशल](https://github.com/FailproofAI/skills) ऑनलाइन की ओर इशारा करता है |
| `failproofai config --token <key>` | एक पास में सेट अप और कनेक्ट करें, कुछ भी न पूछें। एक कुंजी जो `jev:evaluate` ले जाती है तथा [Jev को FailproofAI क्लाउड के माध्यम से](/hi/reference/jev-cloud) अवलोकन मोड में चालू करती है, जब तक कि `jev.json` पहले से मौजूद न हो या `--no-transcripts` दिया गया हो |
| `failproofai config --connect <url>` | एक मशीन को नामांकित करें जो **पहले से** सेट अप है — कोई डेमन नहीं, कोई हुक नहीं |
| `failproofai config --status` | कनेक्शन, डेमन, डिलीवरी, और पॉज स्थिति दिखाएं |
| `failproofai policies` | बिल्ट-इन, कस्टम, सम्मेलन, पैक, और क्लाउड-प्रबंधित नीतियों को सूचीबद्ध करें |
| `failproofai policies --install` | अपने एजेंट CLI में हुक को वायर करें। अपने आप में कोई भी नीति सक्षम नहीं करता |
| `failproofai policies add <name>` | एक नीति सक्षम करें — एक बिल्ट-इन, या एक स्थापित पैक से `<pack-id>:<name>` |
| `failproofai policies remove <name>` | एक नीति अक्षम करें, वही नामकरण |
| `failproofai policies --uninstall` | नीतियों को अक्षम करें या हार्नेस हुक को हटाएं |
| `failproofai policies show <owner>/<repo>` | एक पैक क्या ले जाता है, इसके मेनिफेस्ट से पढ़ें, इससे पहले कि आप इसे लें |
| `failproofai policies show <owner>/<repo> --releases` | हर संस्करण जो इसने प्रकाशित किया है, और कौन सा यहां है |
| `failproofai policies add <source>` | GitHub रिलीज़ से एक नीति पैक इंस्टॉल करें; कोई टैग नहीं नए को लेता है और इसे पिन करता है |
| `failproofai publish` | अपनी नीतियों को एक पैक के रूप में भेजें; `--init` इससे शुरू करने के लिए एक लिखता है, और `--min-cli-version <version>` सबसे पुराना CLI सेट करता है जो इसे इंस्टॉल कर सकता है ([पैक में Jev जांच](/hi/policies/publish-a-pack#jev-checks-in-a-pack)) |
| `failproofai policies remove <publisher/name>` | एक पैक को अनइंस्टॉल करें |
| `failproofai audit` | स्थानीय एजेंट इतिहास को स्कैन करें और स्थानीय ऑडिट दृश्य खोलें |
| `failproofai audit --schedule [days] --email <address>` | आवर्ती स्थानीय स्कैन शेड्यूल करें और उनके निष्कर्षों को ईमेल करें |
| `failproofai audit --status` | रिपोर्ट पता, अंतराल, और अगली निर्धारित स्कैन दिखाएं |
| `failproofai audit --no-schedule` | ऑडिट इतिहास को हटाए बिना आवर्ती स्कैन बंद करें |
| `failproofai harness list` | अतिरिक्त कैप्चर पथ सूचीबद्ध करें |
| `failproofai otel status` | वैकल्पिक [OpenTelemetry रिपोर्टिंग](/hi/reference/otel) का निरीक्षण करें |
| `failproofai jev --url <url> --key-stdin` | एक कदम में Jev सेट अप करें; प्रदाता URL के होस्ट से लिया जाता है |
| `failproofai jev setup --provider <kind> --key-stdin` | [Jev](/hi/reference/jev-providers) को अपने स्वयं के एंडपॉइंट और कुंजी के माध्यम से टूल कॉल का न्याय करने दें |
| `failproofai jev setup --provider failproofai` | Jev को [FailproofAI क्लाउड के माध्यम से](/hi/reference/jev-cloud) टूल कॉल का न्याय करने दें, इस मशीन की क्लाउड कुंजी के साथ |
| `failproofai jev setup --mode <m>` | Jev का मोड स्विच करें: `enforce`, `observe`, या `off` (कॉन्फ़िग रखता है, Jev से पूछना बंद करता है) |
| `failproofai jev status` | Jev कॉन्फ़िग, इसकी अनुमतियां और हाल के फॉलबैक दिखाएं; कभी नहीं कुंजी |
| `failproofai jev test` | एक लाइव Jev अनुरोध भेजें और इसकी विलंबता और संस्करण दिखाएं; जब उत्तर हुक के लिए देर से हो या गलत हो तो 1 से बाहर निकलता है |
| `failproofai jev models` | मॉडल आईडी सूचीबद्ध करें `GET <base>/models` कहता है एक एंडपॉइंट कौन से |
| `failproofai jev remove` | Jev को बंद करें; हुक पहले की तरह बिल्कुल regex नीतियों को चलाते हैं |
| `failproofai flush --wait` | वर्तमान ईवेंट स्पूल को डिलीवर करें |
| `failproofai backfill --since 30d` | पहले से पारित इतिहास को फिर से पढ़ें |
| `failproofai config --pause [duration]` | एक स्थानीय सत्र को डिफ़ॉल्ट रूप से 30 मिनट के लिए पॉज़ करें, 8 घंटे तक |
| `failproofai config --resume` | एक पॉज़ किए गए स्थानीय सत्र को फिर से शुरू करें; सभी पॉज़ को साफ़ करने के लिए `--all` जोड़ें |
| `failproofai update` | पैकेज माइग्रेशन समाप्त करें और डेमन को अपडेट करें |
| `failproofai migrate --dry-run` | लंबित होम-लेआउट माइग्रेशन का पूर्वावलोकन या चलाएं |
| `failproofai uninstall` | पैकेज को हटाने से पहले हुक, `failproofai` कौशल और डेमन को हटाएं |
| `failproofai --version` | स्थापित पैकेज संस्करण प्रिंट करें |
| `failproofai --help` | कमांड और वैश्विक उपयोग दिखाएं |
| `failproofai help <command>` | एक कमांड के विकल्प और उदाहरण दिखाएं, `failproofai <command> --help` के समान |

## कॉन्फ़िगरेशन फ्लैग

| फ्लैग | उपयोग |
| --- | --- |
| `--token <key>` | गैर-इंटरैक्टिव रूप से सेट अप और कनेक्ट करें; `FAILPROOFAI_CLOUD_TOKEN` से भी पढ़ें |
| `--oss` | क्लाउड कनेक्शन के बिना ओपन सोर्स का उपयोग करें; एक मौजूदा कनेक्शन जैसा है |
| `--agents <a,b>` | ये एजेंट, या `all` ट्रेस करें, बिना पूछे |
| `--url <url>` | `app.befailproof.ai` के अलावा कहीं कनेक्ट करें; `FAILPROOFAI_CLOUD_URL` से भी पढ़ें |
| `--connect <url>` | केवल नामांकन, एक पहले से सेट अप की गई मशीन पर। डेमन और हर हुक को छोड़ देता है |
| `--machine-id <id>` | `--connect` के लिए मशीन ID; एक स्थिर ID में डिफ़ॉल्ट |
| `--machine-label <name>` | अपने आप में, एक मशीन का नाम बदलें जो **पहले से कनेक्ट है**; यह कभी सेटअप नहीं चलाता। `--token` के साथ, उस नाम के तहत कनेक्ट करें; केवल `FAILPROOFAI_CLOUD_TOKEN` में सेट एक कुंजी पर्याप्त नहीं है, क्योंकि `--machine-label` बिना `--token` के एक नाम बदलना है। `--oss` या `--agents` के साथ, यह एक मशीन का नाम बदलता है जो पहले से कनेक्ट है और एक पर इनकार किया जाता है जो नहीं है: `--oss` कभी कनेक्ट नहीं होता है, और `--agents` को कनेक्ट करने के लिए एक कुंजी या एक इंटरैक्टिव क्लाउड साइन-इन की आवश्यकता है |
| `--no-transcripts` | ट्रांसक्रिप्ट सामग्री के बिना निर्णय भेजें, और क्लाउड Jev को चालू न करें, जो प्रत्येक जांचे जाने वाले टूल कॉल और हाल के प्रॉम्प्ट भेजेगा; FailproofAI क्लाउड को नाम देने वाली एक `jev.json` हटा दी जाती है |
| `--disconnect` | क्लाउड नीति पुल और ईवेंट डिलीवरी बंद करें। क्लाउड Jev कुंजी को भी हटाता है और एक `jev.json` जो FailproofAI क्लाउड को नाम देती है; आपकी स्वयं की Jev सेटअप जगह पर रहती है |
| `--status` | वर्तमान मशीन स्थिति दिखाएं |
| `--pause [duration]` | वर्तमान निर्देशिका में सबसे नए सत्र को पॉज़ करें; सेकंड, मिनट, या घंटे स्वीकार करता है और डिफ़ॉल्ट रूप से 30 मिनट |
| `--resume` | एक मिलान पॉज़ को जल्दी समाप्त करें |
| `--session <id>` | पॉज़ या फिर से शुरू करने के लिए एक स्पष्ट सत्र लक्ष्य |
| `--all` | `--resume` के साथ, हर सक्रिय पॉज़ को समाप्त करें |

स्थानीय पॉज़ एक सत्र के लिए बिल्ट-इन, कस्टम, सम्मेलन, और पैक नीतियों को निलंबित करते हैं। वे हमेशा समाप्त होते हैं, एक रन में पहले पॉज़ के बाद सबसे अधिक 8 घंटे, और वे क्लाउड-प्रबंधित नीतियों या `block-failproofai-commands` को अक्षम नहीं करते हैं, जो हमेशा चालू है और स्वयं को अक्षम या पॉज़ नहीं किया जा सकता है। वह गार्ड एक इंस्ट्रूमेंटेड एजेंट को स्वयं को पॉज़ करने का सीधा तरीका मना करता है: `failproofai config --pause` चलाना, या पॉज़ फ़ाइल को `~/.failproofai/state/sessions/` के तहत लिखना। यह कमांड पढ़ता है, स्क्रिप्ट नहीं जो जब यह चलती है तब क्या करती है, इसलिए एक स्क्रिप्ट एजेंट लिखता है और फिर चलाता है अभी भी उसी स्थिति तक पहुंच सकता है। एक पॉज़ फ़ाइल को एक सीमित समाप्ति और भविष्य में एक मिनट से अधिक नहीं की शुरुआत के लिए जांचा जाता है, यह नहीं कि किसने इसे लिखा।

## नीति फ्लैग

| फ्लैग | उपयोग |
| --- | --- |
| `--install`, `-i` | हार्नेस हुक इंस्टॉल करें। इसके बाद नाम उन नीतियों को सक्षम करते हैं; कोई नहीं होने पर, कोई नीति परिवर्तन नहीं |
| `--uninstall`, `-u` | नीतियों को अक्षम करें या हुक को हटाएं |
| `--cli <names...>` | एक या अधिक समर्थित हार्नेस लक्ष्य |
| `--scope user\|project\|local\|all` | कॉन्फ़िगरेशन स्कोप चुनें; `all` अनइंस्टॉल के लिए है |
| `--beta` | बीटा नीतियों को शामिल करें |
| `--custom`, `-c <path>` | `--install` के साथ, कस्टम नीति फ़ाइल को मान्य करें और लोड करें; दोहराव योग्य। `--uninstall -c` हर कस्टम नीति फ़ाइल को हटाता है |
| `--policy`, `--only <a,b>` | एक पैक से केवल ये नीतियां इंस्टॉल करें |
| `--category <x,y>` | एक पैक से केवल ये श्रेणियां इंस्टॉल करें |
| `--all` | हर नीति सूचीबद्ध करें; एक पैक के साथ, सभी इंस्टॉल करें |
| `--releases` | `show` के साथ, एक पैक की रिलीज़ और कौन सी इंस्टॉल है सूचीबद्ध करें |

## डिलीवरी और रखरखाव फ्लैग

| कमांड | फ्लैग |
| --- | --- |
| `backfill` | `--since <30d\|6m\|1y\|YYYY-MM-DD>`, `--agents <a,b>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` (`-y`) |

### हार्नेस प्रति बैकफिल

`backfill` इतिहास को फिर से भेजता है जो कलेक्टर पहले से ही पढ़ चुका है, क्लाउड से जुड़ी एक मशीन पर। `--since` अधिकांश हार्नेस के लिए विंडो सेट करता है, दो अपवादों के साथ:

- **Goose, OpenCode और Devin** अपना पूरा इतिहास भेजते हैं, जो भी `--since` कहता है: उनका इतिहास एक डेटाबेस में रहता है कलेक्टर बिना समय विंडो के पढ़ता है, इसलिए `--dry-run` उन्हें सभी सत्रों के रूप में रिपोर्ट करता है।
- **Hermes** इतिहास `backfill` द्वारा फिर से नहीं भेजा जाता है।

`npm install -g failproofai@latest` के बाद `failproofai update` को चलाया जाना चाहिए; यह होम-लेआउट माइग्रेशन करता है, मेल खाने वाले डेमन बाइनरी को इंस्टॉल करता है, और सेवा को फिर से शुरू करता है। फिर यह हर Hermes प्रोफ़ाइल को स्थानांतरित करता है जो पहले से ही FailproofAI का उपयोग करता है लिंक किए गए नेटिव प्लगइन में और प्रोफ़ाइल प्रति एक लाइन प्रिंट करता है। `--no-daemon` डेमन चरण को छोड़ देता है। `update` गैर-शून्य से बाहर निकलता है जब डेमन को प्रतिस्थापित नहीं किया जा सका, एक माइग्रेशन विफल हुआ, या एक Hermes प्रोफ़ाइल को माइग्रेट नहीं किया जा सका (उदाहरण के लिए क्योंकि चलाया जा रहा डेमन नेटिव प्लगइन को सेवा नहीं दे सकता है, जिसमें इसके शेल हुक जगह पर रहते हैं)।

## हार्नेस पथ

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

समर्थित हार्नेस नाम `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, और `goose` हैं।

लेबल नामांकित एजेंट आईडी जब दो रूट एक ही परियोजना की प्रतियां सम्मिलित हैं। ओवरलैपिंग रूट और डुप्लिकेट लेबल डुप्लिकेट कलेक्शन या कर्सर भ्रष्टाचार को रोकने के लिए अस्वीकृत हैं। अतिरिक्त-पथ कॉन्फ़िगरेशन एक डेमन पुनः आरंभ के बिना पुनः लोड करता है।

कंटेनर वातावरण फ़ाइल-कॉन्फ़िगर अतिरिक्त पथ को `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` नामित अल्पविराम-पृथक चर से बदल सकते हैं, उदाहरण के लिए:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## पर्यावरण चर

स्थायी मशीन व्यवहार के लिए कॉन्फ़िगरेशन फ़ाइलों का उपयोग करें। पर्यावरण चर कंटेनर, परीक्षण, और एक प्रक्रिया के लिए सबसे उपयोगी हैं।

| चर | उपयोग |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | क्लाउड कुंजी, `--token` की जगह। इसे प्राथमिकता दें: एक तर्क `ps` से पठनीय है। `read -s` से या CI गुप्त स्टोर से सेट करें, कभी नहीं कुंजी को कमांड में टाइप करके, जो किसी भी तरह से शेल इतिहास में लैंड करता है |
| `FAILPROOFAI_CLOUD_URL` | क्लाउड URL, `--url` की जगह। वही चर जो डेमन पढ़ता है |
| `FAILPROOFAI_HOME` | पूरी `~/.failproofai` लेआउट को स्थानांतरित करें |
| `FAILPROOFAI_LOG_LEVEL` | स्थानीय लॉगिंग शब्दसंख्या सेट करें |
| `FAILPROOFAI_HOOK_LOG_FILE` | हुक निदान को एक चयनित फ़ाइल में लिखें |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | इस प्रक्रिया के लिए अनाम टेलीमेट्री अक्षम करें |
| `FAILPROOFAI_NO_FIRST_RUN=1` | इंटरैक्टिव पहली-रन सेटअप छोड़ें |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | पोस्ट-सेटअप स्थानीय ऑडिट छोड़ें |
| `FAILPROOFAI_LLM_BASE_URL` | LLM नीतियों द्वारा उपयोग किए जाने वाले OpenAI-संगत एंडपॉइंट को ओवरराइड करें |
| `FAILPROOFAI_LLM_API_KEY` | LLM नीतियों द्वारा उपयोग की जाने वाली API कुंजी प्रदान करें |
| `FAILPROOFAI_LLM_MODEL` | LLM नीतियों द्वारा उपयोग किए जाने वाले मॉडल को चुनें |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | कस्टम नीति मॉड्यूल लोडिंग को बाउंड करें |
| `FAILPROOFAI_NO_DOWNLOAD=1` | पैक और डेमन बाइनरी फेच करना अस्वीकार करें; जो स्थापित है वह लागू करना रखता है |
| `FAILPROOFAI_PACK_BASE_URL` | `github.com` की जगह एक दर्पण से पैक फेच करें |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | एक हार्नेस के लिए कॉन्फ़िगर किए गए अतिरिक्त कैप्चर पथ को बदलें |
| `NO_COLOR` | रंगीन टर्मिनल आउटपुट अक्षम करें |

एजेंट-विशिष्ट होम चर जैसे `CLAUDE_PROJECTS_PATH`, `CURSOR_HOME`, `HERMES_HOME`, और `OPENCLAW_HOME` ओवरराइड करते हैं जहां Failproof AI उस हार्नेस के लिए स्थानीय सत्र खोजता है।

## एक मशीन को सुरक्षित रूप से पॉज़ या हटाएं

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

एक स्थानीय सत्र पॉज़ क्लाउड-प्रबंधित नीतियों को अक्षम नहीं करता है। क्लाउड में **fix → deploy policies** से क्लाउड डिप्लॉयमेंट को पुनः बहाल करें जब रोलआउट ही समस्या है।

npm पैकेज को हटाने से पहले, स्थापित हुक और डेमन को हटाएं:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

संस्करण-विशिष्ट विवरण के लिए `failproofai <command> --help` चलाएं।

<Warning>
  `npm rm -g failproofai` से पहले `failproofai uninstall` चलाएं; npm स्थापित एजेंट हुक, `failproofai` कौशल या डेमन सेवा को नहीं हटाता है।
</Warning>
