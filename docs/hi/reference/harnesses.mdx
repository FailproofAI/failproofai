एक हार्नेस वह है जिसमें आपका एजेंट वास्तव में चलता है। Failproof AI उनमें से बारह का समर्थन करता है, दो वर्गों में:

- **कोडिंग CLI** (10) — Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Factory Droid, Devin CLI, Antigravity CLI, Goose
- **चैट और सहायक गेटवे** (2) — Hermes (Slack, Telegram, cron), OpenClaw (self-hosted assistant)

एक ही नीतियां और एक ही सत्र इतिहास लागू होता है चाहे एजेंट किसी भी हार्नेस में चले। एक एडेप्टर परत प्रत्येक हार्नेस के मूल ईवेंट नामों, टूल नामों और टूल-इनपुट फील्ड को 29 विहित ईवेंट में मैप करती है, इससे पहले कि कोई नीति चले।

एक एजेंट जो **कोई भी** बारह हार्नेस में नहीं चलता, सीधे [Python SDK](/hi/reference/custom-agents) के साथ इंस्ट्रूमेंट किया जाता है। यह एक अलग अनुबंध है, और इसे स्पष्ट रूप से बताने लायक है: SDK ट्रेसिंग, सत्र, मूल्यांकन और ऑडिट प्रदान करता है — **यह स्वयं पर नीतियों को लागू नहीं करता।** किसी असुरक्षित कार्रवाई को निष्पादित होने से पहले ब्लॉक करने के लिए आपके रनटाइम के टूल सीमा पर एक प्रवर्तन हुक की आवश्यकता होती है; [हमसे संपर्क करें](mailto:support@befailproof.ai) और हम इसे मैप कर देंगे।

## हुक स्कोप

| हार्नेस | समर्थित हुक स्कोप |
| --- | --- |
| Claude Code | User, project, local |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | User, project |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | User, project |
| Hermes, OpenClaw | User |

Claude Code एकमात्र हार्नेस है जिसमें **local** स्कोप है। Hermes और OpenClaw का कोई प्रोजेक्ट कॉन्फ़िगरेशन नहीं है — वे केवल user scope हैं, और CLI उनके लिए `--scope project` को अस्वीकार करता है।

प्रत्येक इंटीग्रेशन नीतियों के चलने से पहले अपने मूल हुक ईवेंट नामों, टूल नामों और टूल-इनपुट फील्ड को सामान्यीकृत करता है। एक नीति केवल उन ईवेंट पर कार्य कर सकती है जो हार्नेस उजागर करता है; बिल्कुल उसी हार्नेस और संस्करण पर अंत-टर्न और निर्देश व्यवहार का परीक्षण करें जिसे आप तैनात करते हैं।

## प्रवर्तन क्षमता

"ब्लॉक" का अर्थ है कि वर्तमान एडेप्टर द्वारा लौटाया गया फैसला नामित हार्नेस द्वारा उपभोग किया जाता है। पोस्ट-टूल ब्लॉकिंग मॉडल को दिखाए गए परिणाम को प्रतिस्थापित कर सकती है लेकिन एक टूल साइड इफेक्ट को पूर्ववत नहीं कर सकती जो पहले से हुई हो।

| हार्नेस | सत्यापित ब्लॉकिंग ईवेंट | केवल-देखना या गैर-ब्लॉकिंग सावधानियां |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact`, और कई टास्क/कॉन्फ़िग ईवेंट | `PostToolUse`, session lifecycle, notifications, और post-failure ईवेंट observational हैं। |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | पोस्ट-टूल ब्लॉकिंग निष्पादन के बाद परिणाम को प्रतिस्थापित करती है; session-start और compact ईवेंट वर्तमान एडेप्टर में observational हैं। |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | पोस्ट-टूल ब्लॉकिंग निष्पादन के बाद परिणाम को प्रतिस्थापित करती है; session और notification ईवेंट observational हैं। |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` और session ईवेंट observational हैं। |
| OpenCode | `PreToolUse` | पोस्ट-टूल और lifecycle ईवेंट observational हैं; वर्तमान stop handling एक सत्यापित गेट के बजाय बाद के टर्न के लिए निर्देश है। `PermissionRequest` कभी नहीं चलता। |
| Pi | `PreToolUse`, `UserPromptSubmit` | पोस्ट-टूल और lifecycle ईवेंट observational हैं; stop guidance बाद के टर्न पर लागू होता है। |
| Hermes | `PreToolUse` | पोस्ट-टूल, session, और subagent-stop फैसले गेट नहीं हैं। कोई `Stop` ईवेंट installed नहीं है। |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | पोस्ट-टूल, session, subagent-stop, और compaction ईवेंट observational हैं। |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | पोस्ट-टूल और subagent-stop फैसले observational हैं। |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, conditional `PermissionRequest` | Permission हुक हर permission mode में नहीं चलते; पोस्ट-टूल और session ईवेंट observational हैं। |
| Antigravity CLI | `PreToolUse`, `Stop` | user-prompt और पोस्ट-टूल फैसले observational हैं; prompt निर्देश अभी भी inject किए जा सकते हैं। |
| Goose | `PreToolUse` | user-prompt, पोस्ट-टूल, और session ईवेंट observational हैं। एक मूल blocking stop हुक upstream में मौजूद है लेकिन वर्तमान एडेप्टर द्वारा installed नहीं है। |

दोनों कॉलम से अनुपस्थित एक ईवेंट **सत्यापित नहीं** है — इसे अज्ञात के रूप में मानें, कभी ब्लॉकिंग के रूप में नहीं।

### एक सूचीबद्ध गेट पर शर्तें

ऊपर की कई पंक्तियां वास्तविक गेट हैं जो फिर भी सीमित या सशर्त हैं। एक नीति जो इनमें से किसी एक पर निर्भर करती है, पंक्ति जितनी ही शर्त की आवश्यकता है।

| हार्नेस | ईवेंट | शर्त |
| --- | --- | --- |
| Claude Code | `Stop`, `SubagentStop` | `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` द्वारा capped, डिफ़ॉल्ट 8। अंत-टर्न पथ पर discarded |
| Cursor | `Stop` | `loop_limit` द्वारा capped, डिफ़ॉल्ट 5, और केवल तब उपभोग किया जाता है जब टर्न complete होता है — एक user abort या एक टर्न error इसे discards करता है |
| Cursor | `Stop` | **Cursor Cloud Agent VMs बिल्कुल भी `stop` या `subagentStop` हुक नहीं चलाते।** गेट केवल local सत्र को कवर करता है |
| Codex | `SubagentStop` | केवल ThreadSpawn subagent इसे dispatch करते हैं; अन्य प्रत्येक subagent स्रोत कभी हुक नहीं चलाता है |
| GitHub Copilot CLI | `SubagentStop` | `isSidekick` subagent के लिए पूरी तरह से skipped है |
| Devin CLI | `PermissionRequest` | `--permission-mode dangerous` के अंतर्गत कभी नहीं चलता, और auto-approved read-only टूल के लिए कभी नहीं |
| OpenCode | `PermissionRequest` | एक मृत हुक: `permission.ask` upstream में declared और documented है लेकिन कभी invoked नहीं होता, इसलिए नीति चलती ही नहीं है |
| Hermes | `Stop` | कोई `Stop` ईवेंट installed नहीं है, पसंद से। पाँच `require-*-before-stop` builtins Hermes पर inapplicable हैं |
| Goose | `Stop` | समान परिणाम: कोई `Stop` installed नहीं है, इसलिए पाँच `require-*-before-stop` builtins inapplicable हैं |

### जहाँ `instruct()` कम हो जाता है

एक `deny` एकमात्र फैसला नहीं है जो एक नीति लौटाती है। `instruct()` एजेंट को एक निर्देश देता है और कार्रवाई को आगे बढ़ने देता है — लेकिन हर हार्नेस के पास एक को ले जाने के लिए चैनल नहीं है। जहाँ कोई नहीं है, failproofai कार्रवाई की अनुमति देता है और निर्देश को stderr में लिखता है operator के लॉग के लिए; मॉडल इसे कभी नहीं देखता।

| हार्नेस | ईवेंट जहाँ `instruct()` stderr नोट में degrade होता है |
| --- | --- |
| Hermes | हर ईवेंट |
| Goose | हर ईवेंट |
| Pi | `Stop` को छोड़कर हर ईवेंट |
| OpenClaw | `Stop` को छोड़कर हर ईवेंट |
| Factory Droid | `Stop` को छोड़कर हर ईवेंट |
| Antigravity CLI | `Stop` और `UserPromptSubmit` को छोड़कर हर ईवेंट |

अन्यत्र, निर्देश हार्नेस के स्वयं के अतिरिक्त-संदर्भ चैनल के माध्यम से लौटाया जाता है।

## VS Code एजेंट मोड

VS Code का built-in Copilot Chat एजेंट मोड **तेरहवां integration नहीं है**। यह `.github/hooks/*.json`, `~/.copilot/hooks/*.json` और `~/.claude/settings.json` से हुक कॉन्फ़िगरेशन खोजता है — बिल्कुल वही पथ जो `copilot` और `claude` installs पहले से लिखते हैं — और समान Claude-shaped deny अनुबंध का उपयोग करता है। इनमें से किसी को भी installing पहले से ही VS Code agent-mode सत्र के अंदर प्रवर्तन करता है।

यह सुविधा एक preview है और एक active GitHub Copilot subscription के साथ-साथ agent mode की आवश्यकता है।

## कैप्चर और नीति हुक install करें

<Tabs>
  <Tab title="Dashboard">
    1. **Administration → Keys** खोलें और `events:add` और `policies:pull` के साथ एक key बनाएं, मशीन या environment के लिए नामित।
    2. target machine पर, प्रदर्शित key के साथ local CLI को कनेक्ट करें।

    ![नई-installed harness की reporting की पुष्टि करने के लिए उपयोग किया जाने वाला live Events stream।](/images/dashboard/events-stream.png)

    ![नई-connected harness से नीति निर्णय सत्यापित करने के लिए उपयोग किया जाने वाला Policy page।](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    `failproofai config` हर समर्थित एजेंट CLI जो यह पाता है में हुक को wire करता है, daemon को install करता है, और जब key मौजूद हो तो Cloud को कनेक्ट करता है:

    ```bash
    failproofai config --token <machine-key>
    failproofai policies add FailproofAI/policies
    ```

    Setup कोई नीतियां नहीं चुनता, जो कि दूसरी command वहाँ है क्यों है।

    एक हार्नेस को hand से wire करने के लिए — `--cli` omitted के साथ, `--install` यह detect करता है कि क्या installed है और prompt करता है:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    Project scope एक repository के साथ हुक कॉन्फ़िगरेशन को रखता है। User scope repositories के पार काम को cover करता है। ऊपर scope table को check करें `--cli` और `--scope` को combine करने से पहले; CLI एक unsupported pair को अस्वीकार करता है।

    मशीन और इसकी events को verify करें:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

    एक optional label के साथ एक path जोड़ें, फिर configured paths को inspect करें:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    `failproofai harness remove-path claude checkout` के साथ एक path को remove करें।

    label derived agent ids को namespace करता है। समान project की दो copies रखने वाले locations transcript से समान id को derive करते हैं, इसलिए बिना label के वे एक में merge हो जाते हैं। Overlapping roots और duplicate labels refused हैं — देखें [the CLI reference](/hi/reference/failproof-cli) प्रत्येक rejection क्यों है।
  </Tab>
