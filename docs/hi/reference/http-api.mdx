सार्वजनिक API आपके Failproof AI डैशबोर्ड के मूल पर `/v1` के अंतर्गत परोसा जाता है।

## एक कुंजी बनाएं और अनुरोध करें

<Tabs>
  <Tab title="Dashboard">
    1. **Administration → Keys** खोलें, **Create key** चुनें, और सबसे संकीर्ण अनुमति प्रीसेट चुनें जो एकीकरण को कवर करता हो।
    2. केवल आवश्यकतानुसार व्यक्तिगत अनुदान जोड़ें, कुंजी बनाएं, और इसके एकबारी रहस्य की प्रतिलिपि बनाएं।
    3. `/v1/sessions` के लिए एक परीक्षण अनुरोध करें और पुष्टि करें कि कुंजी Keys पृष्ठ में सक्रिय रहती है।
    4. जब एकीकरण स्वामित्व बदले तो इसके क्रिया मेनू से कुंजी को रोटेट या अक्षम करें।

    ![अनुमति प्रीसेट और व्यक्तिगत अनुदान के साथ नई API कुंजी ड्रॉअर।](/images/dashboard/key-create.png)

    ऊपर दिखाया गया ड्रॉअर है। एकबारी रहस्य केवल **create** चुनने के बाद दिखाई देता है; उस पुष्टि को बंद करने से पहले इसकी प्रतिलिपि बनाएं।
  </Tab>
  <Tab title="CLI">
    एक रीड कुंजी बनाएं और इसे `fp` या `curl` के साथ सीधे उपयोग करें:

    ```bash
    fp keys create reliability-reader \
      --permission-set read-only

    fp --api-key <key> sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/sessions?limit=20" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY"
    ```
  </Tab>
</Tabs>

कुंजियां एक संगठन और अनुमति सेट के लिए स्कोप की जाती हैं। एंडपॉइंट की आवश्यक अनुमति के बिना एक अनुरोध `403` लौटाता है और लापता अनुमति की पहचान करता है।

## संगठन चयन

एक संगठन कुंजी अपने संगठन पर स्वचालित रूप से कार्य करती है। एक इंस्टेंस-स्कोप की गई कुंजी प्रति अनुरोध एक संगठन चुन सकती है:

<Tabs>
  <Tab title="Dashboard">
    **Administration → Keys** खोलने से पहले डैशबोर्ड हेडर में संगठन स्विचर का उपयोग करें। वहां बनाई गई कुंजियां चयनित संगठन से संबंधित होती हैं। URL और कुंजी विवरण में संगठन slug की पुष्टि करें इससे पहले कि प्रमाणपत्र को स्वचालन में कॉपी करें।

  </Tab>
  <Tab title="CLI">
    कमांड से पहले `--org` का उपयोग करें, या एक इंस्टेंस-स्कोप की गई API कुंजी के लिए संगठन हेडर भेजें।

    ```bash
    fp orgs list
    fp --org reliability-team sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/usage" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "X-AgentEye-Org: reliability-team"
    ```
  </Tab>
</Tabs>

इस अनुभाग में वर्तमान पथ, पैरामीटर, अनुमति आवश्यकताओं, और स्थिति कोड के लिए जेनरेट किए गए एंडपॉइंट पृष्ठ का उपयोग करें। विनिर्देश सर्वर रूट एनोटेशन से जेनरेट किया जाता है और `/v1` राउटर के विरुद्ध जांचा जाता है।

वर्तमान विनिर्देश में संपूर्ण रूट, विधि, पैरामीटर, अनुमति, और स्थिति-कोड कवरेज है। कुछ प्रतिक्रिया निकायों को जानबूझकर अनटाइप किया जाता है क्योंकि सर्वर अभी भी उन्हें गतिशील JSON के रूप में बनाता है। एक प्रतिक्रिया स्कीमा के बिना एंडपॉइंट के चारों ओर दृढ़ रूप से टाइप किए गए क्लाइंट को जेनरेट करने से पहले एक वास्तविक प्रतिक्रिया का निरीक्षण करें।

JSON लिखने के लिए `Content-Type: application/json` का उपयोग करें। `401` को लापता या अमान्य प्रमाणीकरण के रूप में, `403` को आवश्यक अनुमति के बिना एक वैध पहचान के रूप में, `404` को लापता या संगठन-अप्राप्य संसाधन के रूप में, `409` को स्थिति संघर्ष के रूप में, और `422` को अमान्य क्षेत्र या अनुमति मान के रूप में मानें। त्रुटि प्रतिक्रियाओं में एक मानव-पठनीय संदेश शामिल है; अनुमति विफलताएं भी आवश्यक अनुदान का नाम बताती हैं।

इवेंट इंजेशन नई-पंक्ति-सीमांकित JSON का उपयोग करता है: प्रति पंक्ति एक संपूर्ण वस्तु। एक सफल प्रतिक्रिया में `accepted` और `skipped` दोनों की जांच करें। नेटवर्क विफलता या HTTP 408, 429, या 5xx प्रतिक्रिया के बाद संपूर्ण बैच को फिर से प्रयास करें; समान इवेंट को दोबारा चलाना सुरक्षित है। ऐतिहासिक बैच कई महीनों तक फैल सकते हैं। यदि इंजेशन `422` को `error: "event_too_large"` के साथ लौटाता है, तो फिर से प्रयास करने से पहले अपराधी इवेंट के पेलोड को कम करें। बैच को छोटे अनुरोधों में विभाजित करना एक व्यक्तिगत इवेंट को सिकुड़ता नहीं है। फ़ाइल आयात के लिए, पुनः प्रयास पर मूल `existing_before` कटऑफ का पुनः उपयोग करें ताकि आंशिक रूप से संग्रहीत सेशन समाप्त हो सके।

## अनुरोध आईडी

प्रत्येक प्रतिक्रिया एक `X-Request-Id` हेडर ले जाती है, और प्रत्येक JSON त्रुटि निकाय `request_id` के रूप में समान मान शामिल करता है। समर्थन से संपर्क करते समय इसे उद्धृत करें: यह उस एक अनुरोध की पहचान करता है।

आप अपने लॉग के साथ एक अनुरोध को सहसंबंधित करने के लिए अपना स्वयं का `X-Request-Id` भेज सकते हैं। 32 निम्नलिखित हेक्सादेशमलव वर्णों का उपयोग करें, जैसे कि डैश हटाए गए UUID v4। कोई अन्य मान एक नई ID से बदल दिया जाता है, जो प्रतिक्रिया में लौटाई जाती है।
