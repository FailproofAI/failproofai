सार्वजनिक API आपके Failproof AI डैशबोर्ड origin पर `/v1` के अंतर्गत उपलब्ध है।

## कुंजी बनाएं और अनुरोध करें

<Tabs>
  <Tab title="Dashboard">
    1. **Administration → Keys** खोलें, **Create key** चुनें, और एकीकरण को कवर करने वाली सबसे संकीर्ण अनुमति प्रीसेट चुनें।
    2. जरूरत पड़ने पर ही व्यक्तिगत अनुदान जोड़ें, कुंजी बनाएं, और इसके एक बार के रहस्य की प्रतिलिपि बनाएं।
    3. `/v1/sessions` को परीक्षण अनुरोध करें और Keys पृष्ठ में कुंजी सक्रिय रहने की पुष्टि करें।
    4. जब एकीकरण स्वामित्व बदले तो इसके क्रिया मेनू से कुंजी को घुमाएं या अक्षम करें।

    ![अनुमति प्रीसेट और व्यक्तिगत अनुदान के साथ नई API कुंजी ड्रॉअर।](/images/dashboard/key-create.png)

    ऊपर दिया गया ड्रॉअर दिखाया गया है। एक बार का रहस्य केवल **create** चुनने के बाद दिखाई देता है; उस पुष्टि को बंद करने से पहले इसकी प्रतिलिपि बनाएं।
  </Tab>
  <Tab title="CLI">
    एक read कुंजी बनाएं और इसे `fp` या `curl` के साथ सीधे उपयोग करें:

    ```bash
    fp keys create reliability-reader \
      --permission-set read-only

    fp --api-key <key> sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/sessions?limit=20" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY"
    ```
  </Tab>
</Tabs>

कुंजियों को एक संगठन और अनुमति समूह के लिए स्कोप किया जाता है। आवश्यक अनुमति के बिना कोई अनुरोध `403` लौटाता है और अनुपलब्ध अनुमति की पहचान करता है।

## संगठन चयन

एक संगठन कुंजी अपने संगठन पर स्वचालित रूप से कार्य करती है। एक instance-scoped कुंजी प्रति अनुरोध एक संगठन चुन सकती है:

<Tabs>
  <Tab title="Dashboard">
    **Administration → Keys** खोलने से पहले डैशबोर्ड हेडर में संगठन स्विचर का उपयोग करें। वहां बनाई गई कुंजियां चयनित संगठन से संबंधित होती हैं। क्रेडेंशियल को automation में कॉपी करने से पहले URL और कुंजी विवरण में संगठन slug की पुष्टि करें।

  </Tab>
  <Tab title="CLI">
    कमांड से पहले `--org` का उपयोग करें, या instance-scoped API कुंजी के लिए संगठन हेडर भेजें।

    ```bash
    fp orgs list
    fp --org reliability-team sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/usage" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "X-AgentEye-Org: reliability-team"
    ```
  </Tab>
</Tabs>

इस अनुभाग में वर्तमान पथ, पैरामीटर, अनुमति आवश्यकताएं, और स्थिति कोड के लिए उत्पन्न एंडपॉइंट पृष्ठों का उपयोग करें। विनिर्देश सर्वर मार्ग एनोटेशन से उत्पन्न होता है और `/v1` राउटर के विरुद्ध जांचा जाता है।

वर्तमान विनिर्देश में पूर्ण मार्ग, विधि, पैरामीटर, अनुमति, और स्थिति-कोड कवरेज है। कुछ प्रतिक्रिया निकाय जानबूझकर अनटाइप किए गए रहते हैं क्योंकि सर्वर उन्हें dynamic JSON के रूप में निर्माण करता है। प्रतिक्रिया स्कीमा के बिना किसी एंडपॉइंट के चारों ओर दृढ़ता से टाइप की गई क्लाइंट बनाने से पहले एक वास्तविक प्रतिक्रिया का निरीक्षण करें।

JSON लेखन के लिए `Content-Type: application/json` का उपयोग करें। `401` को प्रमाणीकरण की कमी या अमान्य के रूप में, `403` को आवश्यक अनुमति के बिना एक मान्य पहचान के रूप में, `404` को लापता या संगठन-अप्राप्य संसाधन के रूप में, `409` को स्थिति संघर्ष के रूप में, और `422` को अमान्य क्षेत्र या अनुमति मान के रूप में मानें। त्रुटि प्रतिक्रियाएं एक मानव-पठनीय संदेश शामिल करती हैं; अनुमति विफलताएं भी आवश्यक अनुदान का नाम देती हैं।

<Warning>
  नीति प्रवर्तन तैनाती सामान्य सार्वजनिक `/v1` सतह के बाहर जानबूझकर प्रबंधित की जाती है। समर्थित Cloud तैनाती कार्यप्रवाह का उपयोग करें।
</Warning>
