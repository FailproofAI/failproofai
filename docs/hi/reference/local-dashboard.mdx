`failproofai` को बिना किसी तर्क के चलाएं ताकि `http://localhost:8020` पर बंडल डैशबोर्ड शुरू हो। यह स्थानीय एजेंट इतिहास, नीति कॉन्फ़िगरेशन, ऑडिट परिणाम और हुक गतिविधि को सीधे मशीन से पढ़ता है।

स्थानीय डैशबोर्ड Failproof AI Cloud से अलग है। यह Cloud खाते के बिना काम करता है और यह साबित नहीं करता कि इवेंट आपके संगठन को पहुंचे थे।

## डैशबोर्ड क्षेत्र

| क्षेत्र | आप क्या प्राप्त कर सकते हैं |
| --- | --- |
| Policies → Activity | स्थानीय allow, instruct और deny निर्णयों का निरीक्षण करें; निर्णय, इवेंट, CLI, उपकरण, स्रोत, नीति और सेशन द्वारा फ़िल्टर करें। |
| Policies → Configure | बिल्ट-इन को सक्षम करें, समर्थित पैरामीटर संपादित करें, खोजी गई कस्टम नीतियों को टॉगल करें और टार्गेट हार्नेस चुनें। |
| Projects | समर्थित एजेंट इतिहास में खोजी गई प्रोजेक्ट्स ब्राउज़ करें और उनके सबसे हाल के सेशन की तुलना करें। |
| Project sessions | एक स्थानीय ट्रांसक्रिप्ट खोलें, कच्ची क्रमबद्ध प्रविष्टियां और उप-एजेंट देखें, इसे डाउनलोड करें और नीति गतिविधि को जोड़ें। |
| Audit | पिछले ऑफ़लाइन स्कैन, जोखिम भरे पैटर्न, शक्तियां, प्रभावित प्रोजेक्ट्स और सुझाई गई बिल्ट-इन नीतियों की समीक्षा करें। |
| Settings | निर्धारित स्थानीय स्कैन और ईमेल किए गए ऑडिट रिपोर्ट कॉन्फ़िगर करें जब डेमॉन/प्लेटफॉर्म उन्हें समर्थन करते हैं। |

## नीति गतिविधि की समीक्षा करें

<Tabs>
  <Tab title="Dashboard">
    1. **Policies → Activity** खोलें और निर्णय और स्रोत फ़िल्टर सेट करें।
    2. इवेंट, हार्नेस, उपकरण या नीति नाम द्वारा संकीर्ण करें।
    3. इसके कारण, मेल खाती नीतियां, स्रोत, निष्पादन मोड और अवधि का निरीक्षण करने के लिए एक पंक्ति को विस्तृत करें।
    4. निर्णय को ट्रांसक्रिप्ट संदर्भ में रखने के लिए सेशन लिंक का पालन करें।

    एक अस्वीकार-दिख रही पंक्ति एक हार्नेस/इवेंट जोड़ी पर अभी भी प्रेक्षणात्मक हो सकती है जो ब्लॉकिंग निर्णय का उपयोग नहीं करती है। विस्तृत दृश्य सत्यापित प्रवर्तन क्षमता को स्पष्ट करता है।
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    स्थानीय गतिविधि `~/.failproofai/hook-activity` के अंतर्गत संग्रहीत है। इन फ़ाइलों को संपादित करने के बजाय डैशबोर्ड का उपयोग करें।
  </Tab>
</Tabs>

## नीतियों को स्थानीय रूप से कॉन्फ़िगर करें

<Tabs>
  <Tab title="Dashboard">
    1. **Policies → Configure** खोलें और हार्नेस और कॉन्फ़िगरेशन स्कोप चुनें।
    2. एक बिल्ट-इन या खोजी गई कस्टम नीति सक्षम करें।
    3. एक पैरामीटर किए गए बिल्ट-इन के लिए, इसके कॉन्फ़िगरेशन नियंत्रण को खोलें और समर्थित मान सहेजें।
    4. गतिविधि पर लौटें और मेल खाती और गैर-मेल खाती कार्रवाई चलाएं।

    सम्मेलन नीतियां उनका प्रोजेक्ट या उपयोगकर्ता स्रोत दिखाती हैं। स्पष्ट कस्टम-पथ परिवर्तनों के लिए CLI कॉन्फ़िगरेशन को फिर से चलाने की आवश्यकता हो सकती है ताकि चयनित पथ रिकॉर्ड किया जाए।
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```
  </Tab>
</Tabs>

## प्रोजेक्ट्स और सेशन ब्राउज़ करें

प्रोजेक्ट्स पेज समर्थित स्थानीय इतिहास स्टोर को जोड़ता है। एक प्रोजेक्ट चुनें इसके सेशन को सूचीबद्ध करने के लिए, फिर कच्चे लॉग दर्शक, उप-एजेंट सेगमेंट, डाउनलोड क्रिया और सेशन-स्कोप नीति गतिविधि के लिए एक सेशन खोलें।

यदि कोई प्रोजेक्ट या सेशन अनुपलब्ध है, तो पुष्टि करें कि हार्नेस अपने डिफ़ॉल्ट इतिहास स्थान का उपयोग करता है या `failproofai harness add-path` के साथ एक अतिरिक्त रूट पंजीकृत करें।

## ऑफ़लाइन ऑडिट निर्धारित करें

<Tabs>
  <Tab title="Dashboard">
    **Settings** खोलें, निर्धारित स्कैनिंग सक्षम करें, इसका समर्थित अंतराल चुनें और जब उपलब्ध हो तो रिपोर्ट डिलीवरी कॉन्फ़िगर करें। पेज अगला रन, पिछला रन, निकास कोड और क्या पृष्ठभूमि डेमॉन प्लेटफॉर्म पर समर्थित है इसकी रिपोर्ट करता है।
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    एक अलग 1–90 दिन अंतराल सेट करने के लिए दिनों की संख्या बदलें। `failproofai audit --no-schedule` के साथ आवर्ती स्कैन अक्षम करें; तत्काल इंटरैक्टिव स्कैन के लिए `failproofai audit` चलाएं।
  </Tab>
</Tabs>

<Warning>
  स्थानीय डैशबोर्ड स्थानीय एजेंट इतिहास से संकेत, उपकरण इनपुट, फ़ाइल सामग्री और टर्मिनल आउटपुट प्रदर्शित कर सकता है। इसे केवल विश्वसनीय इंटरफेस पर बाइंड करें और समीक्षा पूर्ण होने पर प्रक्रिया को बंद करें।
</Warning>
