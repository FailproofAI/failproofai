एक AI टूल को Failproof AI Cloud से कनेक्ट करें और इससे अपने agents के डेटा के साथ काम करें। आपका टूल सेशन और events को क्वेरी कर सकता है, read-only SQL चला सकता है, dashboards, alerts, issues, audits, और policies को पढ़ सकता है, और यदि आपके पास अनुमति है, तो alert बनाना या policy deploy करना जैसे परिवर्तन कर सकता है।

हर कॉल **आपकी अपनी** अनुमतियों के साथ चलती है, **एक** organization में जो आप कनेक्ट करते समय चुनते हैं।

सभी के लिए एक पता है, hosted या self-hosted:

```text
https://gateway.befailproof.ai/mcp
```

## एक क्लाइंट कनेक्ट करें

अपने क्लाइंट में पता जोड़ें। पहली बार जब कोई टूल उपयोग किया जाता है, तो आपका ब्राउज़र खुल जाता है। चुनें कि आपका Failproof AI Cloud कहाँ है, साइन इन करें, एक organization चुनें, और **Allow** को चुनें। **Cancel** कुछ भी कनेक्ट नहीं करता।

पृष्ठ ऐप का नाम और जहाँ यह वापस आता है, उसे नाम देता है। एक ऐप जो अपने स्वयं के वेब पते द्वारा पहचाना नहीं जाता है, **unverified app** के रूप में चिह्नित किया जाता है, इसलिए केवल तभी जारी रखें यदि आपने अभी इसे अपने क्लाइंट से शुरू किया है।

<Tabs>
  <Tab title="Claude">
    claude.ai या Claude Desktop में, **Settings → Connectors → Add custom connector** पर जाएँ। इसका नाम `Failproof AI` रखें, पता दर्ज करें, **Add** को चुनें, फिर **Connect**।

    Team और Enterprise प्लान पर, एक owner पहले organization के लिए connector जोड़ता है। हर व्यक्ति फिर अपना खुद का account कनेक्ट करता है।
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    फिर Claude Code के अंदर `/mcp` चलाएँ, `failproofai` को चुनें, और **Authenticate** को चुनें।
  </Tab>
  <Tab title="Cursor">
    इसे `~/.cursor/mcp.json` में, या अपने प्रोजेक्ट के `.cursor/mcp.json` में जोड़ें:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor सर्वर के बगल में **Needs login** दिखाता है। साइन इन करने के लिए इसे चुनें।
  </Tab>
  <Tab title="Codex">
    इसे `~/.codex/config.toml` में जोड़ें:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    फिर `codex mcp login failproofai` चलाएँ।
  </Tab>
  <Tab title="अन्य क्लाइंट">
    कोई भी क्लाइंट जो OAuth के साथ Streamable HTTP पर remote MCP सर्वर को सपोर्ट करता है, काम करता है। इसे ऊपर दिया गया पता दें। कनफ़िगर करने के लिए कोई क्लाइंट ID या secret नहीं है।
  </Tab>
</Tabs>

## प्रति कनेक्शन एक organization

एक कनेक्शन केवल उस organization में काम करता है जो आपने चुना। दो organizations का उपयोग करने के लिए, सर्वर को अलग-अलग नामों के तहत दो बार जोड़ें, जैसे `failproofai-acme` और `failproofai-sandbox`, और प्रत्येक को अपने स्वयं के organization से कनेक्ट करें।

Demo organizations कनेक्शन स्वीकार नहीं करते। इसके बजाय अपना स्वयं का organization चुनें।

## अनुमतियाँ

एक कनेक्शन वह कर सकता है जो आप organization में कर सकते हैं, नीचे दिए गए सेट के भीतर। यह आपकी वर्तमान अनुमतियों का पालन करता है: यदि कोई admin आपको अधिक देता है, तो टूल को यह मिल जाता है, और यदि वे कुछ ले जाते हैं, तो टूल इसे अपनी अगली कॉल पर खो देता है।

| अनुमति | टूल को अनुमति देता है |
| --- | --- |
| `events:read` | Events को list करें, एक session का overview पढ़ें, agents और environments को list करें |
| `evaluations:read` | Sessions को list करें, और evaluation परिणाम और jobs को पढ़ें और summarize करें |
| `evaluations:trigger` | Evaluations बनाएँ, नए versions publish करें, उन्हें on या off करें, backfill करें, और एक session को फिर से evaluate करें |
| `dashboards:read`, `dashboards:write` | Dashboards को पढ़ें, या उन्हें बनाएँ, rename करें, और queries जोड़ें |
| `queries:read`, `queries:write` | Saved queries को पढ़ें, या उन्हें save और edit करें |
| `queries:run` | एक read-only SQL query चलाएँ और query schema को पढ़ें |
| `alerts:read`, `alerts:write` | Alerts को पढ़ें, या उन्हें बनाएँ, edit करें, pause करें, delete करें, और test करें |
| `issues:read` | Issues को पढ़ें, उन्हें acknowledge करें, और उन पर comment करें |
| `issues:create` | एक alert पर issue खोलें |
| `issues:close` | Issues को resolve और close करें |
| `audits:read`, `audits:write` | Audits, runs, और findings को पढ़ें, या audits बनाएँ, edit करें और एक run शुरू करें |
| `code_fixes:read` | देखें कि issue को कैसे ठीक करें, और इसका context अपने स्वयं के agent के लिए ठीक करने के लिए प्राप्त करें |
| `code_fixes:write` | Failproof AI Cloud में एक fix शुरू करें, जो आपके GitHub पर एक pull request खोलता है |
| `policies:read`, `policies:write` | Policies, machines, और deployments को पढ़ें, या policies को publish, deploy, और rollback करें |

कुछ टूल को कोई अनुमति की आवश्यकता नहीं है क्योंकि वे कोई organization डेटा नहीं पढ़ते: session और event links बनाना, और इस documentation को खोजना।

एक AI टूल कभी API keys, users, settings, या organization administration को touch नहीं कर सकता, और यह events भेज नहीं सकता।

## परिवर्तनों को मंजूरी देना

Writes पहले आपसे पूछते हैं यदि आपका क्लाइंट prompt दिखा सकता है। आप देखते हैं कि क्या बदलेगा और आगे बढ़ने के लिए **Approve this change** को चुनते हैं। यदि आप अस्वीकार करते हैं या लगभग 4 मिनट में जवाब नहीं देते हैं, तो कुछ नहीं बदलता। कुछ क्लाइंट एक मिनट के बाद प्रतीक्षा करना बंद कर देते हैं, इसलिए तुरंत उत्तर दें।

<Warning>
  एक क्लाइंट जो prompts को सपोर्ट नहीं करता है, उससे नहीं पूछा जाता है, और एक write तुरंत चलता है जैसे ही क्लाइंट कॉल करता है। वहाँ, आपके क्लाइंट की स्वयं की पुष्टि ही एकमात्र है, इसलिए write tools के लिए इसे on रखें।
</Warning>

## जुड़े हुए ऐप्स और रद्द करना

**Settings → Integrations → MCP** आपके जुड़े हुए ऐप्स को वर्तमान organization में list करता है, उनकी अनुमतियों और अंतिम उपयोग के साथ। **Revoke** एक ऐप को तुरंत काट देता है। अपने क्लाइंट में सर्वर को हटाना भी कनेक्शन को रद्द करता है।

आप प्रति organization 5 connected apps तक रख सकते हैं। एक ही ऐप को फिर से कनेक्ट करना इसके पहले कनेक्शन को replace करता है।

## Self-hosted deployments

कनेक्ट करते समय **Self-hosted Failproof AI Cloud** को चुनें, और जिस पते पर आप साइन इन करते हैं उसे दर्ज करें। आपके deployment को public HTTPS पर पहुँचा जा सकता है।

Tool calls और उनके परिणाम आपके AI टूल और आपके deployment के बीच hosted Failproof AI gateway के माध्यम से गुजरते हैं। Gateway उन्हें store नहीं करता।

## आपके डेटा के साथ क्या होता है

परिणाम जुड़े हुए AI टूल पर जाते हैं, और उस टूल के provider उन्हें अपनी शर्तों के तहत handle करते हैं। प्रत्येक tool call के लिए, Failproof AI टूल का नाम, इसका outcome, यह कितने समय तक चला, और organization को log करता है, कभी भी arguments या results को नहीं। [privacy policy](https://befailproof.ai/privacy/) देखें।

## समस्या निवारण

| आप क्या देखते हैं | क्या करें |

| "Started in another browser" | क्लाइंट द्वारा खोले गए ब्राउज़र में साइन-इन समाप्त करें, cookies की अनुमति के साथ, और क्लाइंट से फिर से शुरू करें |
| **Allow** के बाद एक error | लिंक एक बार काम करता है और 10 मिनट के बाद expire होता है, इसलिए क्लाइंट से फिर से शुरू करें |
| एक टूल जिसे आप expected करते हैं गायब है | आपके पास इस organization में इसकी अनुमति नहीं है। एक admin से पूछें। एक बार जब आपके पास यह हो तो आपको reconnect करने की आवश्यकता नहीं है |
| क्लाइंट आपसे साइन इन करने के लिए पूछता रहता है | कनेक्शन को revoke किया गया था, आप organization को छोड़ गए हैं, या यह 90 दिनों तक unused था। फिर से कनेक्ट करें |
| "आपके पास 5 connected apps हैं" | **Settings → Integrations → MCP** के तहत एक को revoke करें, फिर फिर से कनेक्ट करें |
