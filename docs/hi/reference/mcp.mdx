एक AI tool को Failproof AI Cloud से जोड़ें और इससे अपने agents के डेटा के साथ काम करें। आपका tool sessions और events को query कर सकता है, read-only SQL चला सकता है, dashboards, alerts, issues, audits और policies को पढ़ सकता है, और यदि आपके पास अनुमति है, तो alert बनाना या policy deploy करने जैसे परिवर्तन कर सकता है।

हर call आपकी **अपनी** अनुमतियों के साथ चलती है, **एक** organization में जिसे आप जोड़ते समय चुनते हैं।

सभी के लिए एक address है, hosted या self-hosted:

```text
https://gateway.befailproof.ai/mcp
```

## Client को जोड़ें

Address को अपने client में जोड़ें। जब पहली बार कोई tool use होता है, तो आपका browser खुल जाता है। चुनें कि आपका Failproof AI Cloud कहां है, sign in करें, एक organization चुनें, और **Allow** को select करें। **Cancel** से कोई भी connection नहीं होगा।

Page app का नाम और जहां यह वापस जाता है, वह दिखाता है। एक app जो अपने web address से identified नहीं होता है, को **unverified app** के रूप में चिह्नित किया जाता है, इसलिए केवल तभी आगे बढ़ें यदि आपने अभी इसे अपने client से शुरू किया है।

<Tabs>
  <Tab title="Claude">
    claude.ai या Claude Desktop में, **Settings → Connectors → Add custom connector** पर जाएं। इसका नाम `Failproof AI` रखें, address enter करें, **Add** को select करें, फिर **Connect** को select करें।

    Team और Enterprise plans पर, एक owner पहले organization के लिए connector जोड़ता है। फिर हर व्यक्ति अपने account को जोड़ता है।
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    फिर Claude Code के अंदर `/mcp` चलाएं, `failproofai` को select करें, और **Authenticate** को चुनें।
  </Tab>
  <Tab title="Cursor">
    इसे `~/.cursor/mcp.json` में, या अपने project के `.cursor/mcp.json` में जोड़ें:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor server के आगे **Needs login** दिखाता है। Sign in करने के लिए इसे select करें।
  </Tab>
  <Tab title="Codex">
    इसे `~/.codex/config.toml` में जोड़ें:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    फिर `codex mcp login failproofai` चलाएं।
  </Tab>
  <Tab title="Other clients">
    कोई भी client जो Streamable HTTP के साथ remote MCP servers को OAuth के साथ support करता है। इसे ऊपर दिया गया address दें। कोई client ID या secret configure करने के लिए नहीं है।
  </Tab>
</Tabs>

## एक connection में एक organization

एक connection केवल उस organization में काम करता है जिसे आपने चुना है। दो organizations का उपयोग करने के लिए, server को दो बार अलग-अलग नामों के अंतर्गत जोड़ें, जैसे `failproofai-acme` और `failproofai-sandbox`, और प्रत्येक को अपने organization से जोड़ें।

Demo organizations connections को स्वीकार नहीं करते। इसके बजाय अपना organization चुनें।

## अनुमतियां

एक connection आपके द्वारा organization में किए जा सकने वाले कार्यों को कर सकता है, नीचे दिए गए set के अंतर्गत। यह आपकी वर्तमान अनुमतियों का पालन करता है: यदि कोई admin आपको अधिक देता है, तो tool को यह मिल जाती है, और यदि वे कुछ हटाते हैं, तो tool इसे अपनी अगली call पर खो देता है।

| अनुमति | Tool को अनुमति देती है |
| --- | --- |
| `events:read` | Events को list करें, एक session का overview पढ़ें, agents और environments को list करें |
| `evaluations:read` | Sessions को list करें, और evaluation results और jobs को पढ़ें और summarize करें |
| `evaluations:trigger` | Evaluations बनाएं, नए versions publish करें, उन्हें चालू या बंद करें, backfill करें, और एक session को re-evaluate करें |
| `dashboards:read`, `dashboards:write` | Dashboards को पढ़ें, या उन्हें बनाएं, rename करें, और उनमें queries जोड़ें |
| `queries:read`, `queries:write` | Saved queries को पढ़ें, या उन्हें save और edit करें |
| `queries:run` | एक read-only SQL query चलाएं और query schema को पढ़ें |
| `alerts:read`, `alerts:write` | Alerts को पढ़ें, या उन्हें बनाएं, edit करें, pause करें, delete करें, और test करें |
| `issues:read` | Issues को पढ़ें, उन्हें acknowledge करें, और उन पर comment करें |
| `issues:create` | एक alert पर issue खोलें |
| `issues:close` | Issues को resolve और close करें |
| `audits:read`, `audits:write` | Audits, runs और findings को पढ़ें, या audits बनाएं, edit करें और एक run शुरू करें |
| `code_fixes:read` | देखें कि एक issue को कैसे ठीक करें, और अपने agent के लिए इसके context को प्राप्त करें |
| `code_fixes:write` | Failproof AI Cloud में एक fix शुरू करें, जो आपके GitHub पर एक pull request खोलता है |
| `policies:read`, `policies:write` | Policies, machines और deployments को पढ़ें, या policies को publish, deploy, और rollback करें |

कुछ tools को कोई अनुमति की आवश्यकता नहीं है क्योंकि वे कोई organization डेटा नहीं पढ़ते: session और event links को building करना, और इस documentation को search करना।

एक AI tool कभी भी API keys, users, settings या organization administration को touch नहीं कर सकता, और यह events भेज नहीं सकता।

## परिवर्तनों को मंजूरी देना

Writes पहले आपसे पूछते हैं यदि आपका client prompt दिखा सकता है। आप देखते हैं कि क्या बदलेगा और **Approve this change** को select करते हैं आगे बढ़ने के लिए। यदि आप decline करते हैं या लगभग 4 मिनट के अंदर उत्तर नहीं देते हैं, तो कुछ नहीं बदलता। कुछ clients एक मिनट के बाद प्रतीक्षा करना बंद कर देते हैं, इसलिए तुरंत उत्तर दें।

<Warning>
  एक client जो prompts को support नहीं करता है, उससे पूछा नहीं जाता है, और एक write तुरंत चलता है जब client call करता है। वहां, आपके client की अपनी confirmation ही एकमात्र है, इसलिए write tools के लिए इसे चालू रखें।
</Warning>

## Connected apps और revoking

**Settings → Integrations → MCP** वर्तमान organization में आपके connected apps को list करता है, उनकी अनुमतियों और अंतिम use के साथ। **Revoke** एक app को तुरंत काट देता है। अपने client में server को हटाना भी connection को revoke करता है।

आप प्रति organization में 5 connected apps तक कर सकते हैं। एक ही app को दोबारा जोड़ने से इसका पहले का connection replace हो जाता है।

## Self-hosted deployments

जोड़ते समय **Self-hosted Failproof AI Cloud** को चुनें, और उस address को enter करें जहां आप sign in करते हैं। आपके deployment को public HTTPS पर पहुंचा जा सकना चाहिए।

Tool calls और उनके results hosted Failproof AI gateway के माध्यम से pass होते हैं जब वे आपके AI tool और आपके deployment के बीच जाते हैं। Gateway उन्हें store नहीं करता है।

## आपके डेटा का क्या होता है

Results उस AI tool को जाते हैं जिसे आपने जोड़ा है, और उस tool का provider उन्हें अपनी शर्तों के अंतर्गत handle करता है। प्रत्येक tool call के लिए, Failproof AI tool का नाम, इसके outcome, यह कितने समय में ले गया, और organization को log करता है, कभी arguments या results नहीं। [privacy policy](https://befailproof.ai/privacy/) देखें।
