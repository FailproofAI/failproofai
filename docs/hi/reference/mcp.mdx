एक AI टूल को Failproof AI Cloud से कनेक्ट करें और इससे अपने agents के डेटा के साथ काम करें। आपका टूल sessions और events को query कर सकता है, read-only SQL चला सकता है, dashboards, alerts, insights, audits और policies को पढ़ सकता है, और यदि आपके पास अनुमति है, तो alert बनाने या policy deploy करने जैसे परिवर्तन कर सकता है।

हर कॉल **आपकी अपनी** अनुमतियों के साथ, **एक** organization में चलती है जिसे आप कनेक्ट करते समय चुनते हैं।

सभी के लिए एक पता है, hosted या self-hosted:

```text
https://gateway.befailproof.ai/mcp
```

## क्लाइंट को कनेक्ट करें

पते को अपने क्लाइंट में जोड़ें। पहली बार जब कोई टूल उपयोग किया जाता है, तो आपका ब्राउज़र खुलता है। चुनें कि आपका Failproof AI Cloud कहाँ है, साइन इन करें, एक organization चुनें, और **Allow** चुनें। **Cancel** कुछ भी कनेक्ट नहीं करता।

पृष्ठ ऐप का नाम और जहाँ यह वापस आता है, वह बताता है। एक ऐप जो अपने स्वयं के वेब पते से पहचाना नहीं जाता है, उसे **unverified app** चिह्नित किया जाता है, इसलिए केवल तभी जारी रखें यदि आपने अभी इसे अपने क्लाइंट से शुरू किया है।

<Tabs>
  <Tab title="Claude">
    claude.ai या Claude Desktop में, **Settings → Connectors → Add custom connector** पर जाएं। इसका नाम `Failproof AI` रखें, पता दर्ज करें, **Add** चुनें, फिर **Connect** चुनें।

    Team और Enterprise plans पर, एक owner पहले organization के लिए connector जोड़ता है। फिर हर व्यक्ति अपने खाते को कनेक्ट करता है।
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    फिर Claude Code के अंदर `/mcp` चलाएं, `failproofai` चुनें, और **Authenticate** चुनें।
  </Tab>
  <Tab title="Cursor">
    इसे `~/.cursor/mcp.json` में, या अपने project के `.cursor/mcp.json` में जोड़ें:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor server के बगल में **Needs login** दिखाता है। साइन इन करने के लिए इसे चुनें।
  </Tab>
  <Tab title="Codex">
    इसे `~/.codex/config.toml` में जोड़ें:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    फिर `codex mcp login failproofai` चलाएं।
  </Tab>
  <Tab title="Other clients">
    कोई भी क्लाइंट जो Streamable HTTP पर OAuth के साथ remote MCP servers को सपोर्ट करता है, काम करता है। इसे ऊपर दिया गया पता दें। कोई client ID या secret configure करने के लिए नहीं है।
  </Tab>
</Tabs>

## प्रति कनेक्शन एक organization

एक कनेक्शन केवल उस organization में कार्य करता है जिसे आपने चुना है। दो organizations का उपयोग करने के लिए, server को अलग-अलग नामों के तहत दो बार जोड़ें, जैसे `failproofai-acme` और `failproofai-sandbox`, और प्रत्येक को अपने organization से कनेक्ट करें।

Demo organizations कनेक्शन स्वीकार नहीं करते। इसके बजाय अपना organization चुनें।

## अनुमतियां

एक कनेक्शन वह कर सकता है जो आप organization में कर सकते हैं, नीचे दिए गए सेट के भीतर। यह आपकी वर्तमान अनुमतियों का पालन करता है: यदि कोई admin आपको अधिक देता है, तो टूल को वह मिल जाता है, और यदि वे कुछ ले लेते हैं, तो टूल को अपनी अगली कॉल पर नहीं मिलेगा।

| अनुमति | टूल को लेट देती है |
| --- | --- |
| `events:read` | Events सूचीबद्ध करें, session का overview पढ़ें, agents और environments सूचीबद्ध करें |
| `evaluations:read` | Sessions सूचीबद्ध करें, और evaluation results और jobs को पढ़ें और summarize करें |
| `evaluations:trigger` | Evaluations बनाएं, नए versions प्रकाशित करें, उन्हें चालू या बंद करें, backfill करें, और session को फिर से evaluate करें |
| `dashboards:read`, `dashboards:write` | Dashboards पढ़ें, या उन्हें बनाएं, rename करें, और queries जोड़ें |
| `queries:read`, `queries:write` | Saved queries पढ़ें, या उन्हें save और edit करें |
| `queries:run` | एक read-only SQL query चलाएं और query schema पढ़ें |
| `alerts:read`, `alerts:write` | Alerts पढ़ें, या उन्हें बनाएं, edit करें, pause करें, delete करें, और test करें |
| `issues:read` | Insights पढ़ें, उन्हें acknowledge करें, और उन पर comment करें |
| `issues:create` | एक alert पर insight खोलें |
| `issues:close` | Insights को resolve और close करें |
| `audits:read`, `audits:write` | Audits, runs, और findings पढ़ें, या audits बनाएं, edit करें और run शुरू करें |
| `code_fixes:read` | देखें कि insight को कैसे ठीक करें, और अपने agent को ठीक करने के लिए इसका context प्राप्त करें |
| `code_fixes:write` | Failproof AI Cloud में एक fix शुरू करें, जो आपके GitHub पर एक pull request खोलता है |
| `policies:read`, `policies:write` | Policies, machines, और deployments पढ़ें, या policies को publish, deploy, और rollback करें |

कुछ टूल्स को कोई अनुमति की आवश्यकता नहीं है क्योंकि वे organization डेटा नहीं पढ़ते: session और event links बनाना, और इस documentation को खोजना।

एक AI टूल कभी भी API keys, users, settings, या organization administration को touch नहीं कर सकता, और न ही events भेज सकता है।

## परिवर्तनों को मंजूरी देना

Writes पहले आपसे पूछते हैं यदि आपका क्लाइंट prompt दिखा सकता है। आप देखते हैं कि क्या बदलेगा और आगे बढ़ने के लिए **Approve this change** चुनते हैं। यदि आप अस्वीकार करते हैं या लगभग 4 मिनट के भीतर उत्तर नहीं देते हैं, तो कुछ नहीं बदलता है। कुछ क्लाइंट एक मिनट के बाद प्रतीक्षा करना बंद कर देते हैं, इसलिए तुरंत उत्तर दें।

<Warning>
  एक क्लाइंट जो prompts को सपोर्ट नहीं करता है, उससे नहीं पूछा जाता है, और एक write क्लाइंट द्वारा कॉल होते ही चलता है। वहाँ, आपके क्लाइंट की अपनी confirmation ही एकमात्र है, इसलिए write tools के लिए इसे चालू रखें।
</Warning>

## कनेक्टेड ऐप्स और रिवोक करना

**settings → integrations → MCP** वर्तमान organization में आपके कनेक्टेड ऐप्स को उनकी अनुमतियों और अंतिम use के साथ सूचीबद्ध करता है। **Revoke** एक ऐप को तुरंत काट देता है। अपने क्लाइंट में server को हटाना भी कनेक्शन को revoke कर देता है।

आप प्रति organization में 5 तक कनेक्टेड ऐप्स रख सकते हैं। एक ही ऐप को फिर से कनेक्ट करना इसके पहले के कनेक्शन को replace कर देता है।

## Self-hosted deployments

कनेक्ट करते समय **Self-hosted Failproof AI Cloud** चुनें, और वह पता दर्ज करें जहाँ आप साइन इन करते हैं। आपका deployment public HTTPS पर पहुंचने योग्य होना चाहिए।

Tool calls और उनके परिणाम hosted Failproof AI gateway के माध्यम से जाते हैं क्योंकि वे आपके AI tool और आपके deployment के बीच जाते हैं। gateway उन्हें store नहीं करता है।

## आपके डेटा का क्या होता है

परिणाम उस AI tool को जाते हैं जिससे आपने कनेक्ट किया है, और उस tool का provider अपनी शर्तों के तहत उन्हें संभालता है। प्रत्येक tool call के लिए, Failproof AI tool का नाम, इसका outcome, यह कितने समय तक चला, और organization को log करता है, कभी arguments या results को नहीं। [privacy policy](https://befailproof.ai/privacy/) देखें।
