एक AI टूल को Failproof AI Cloud से कनेक्ट करें और इससे अपने agents के डेटा के साथ काम करें। आपका टूल सेशन और events को क्वेरी कर सकता है, read-only SQL चला सकता है, डैशबोर्ड, alerts, issues, audits, और policies को पढ़ सकता है, और यदि आपके पास अनुमति है, तो alert बनाने या policy को deploy करने जैसे परिवर्तन कर सकता है।

हर कॉल **आपकी स्वयं की** अनुमतियों के साथ चलता है, **एक** organization में जिसे आप कनेक्ट करते समय चुनते हैं।

सभी के लिए एक पता है, hosted या self-hosted:

```text
https://gateway.befailproof.ai/mcp
```

## एक क्लाइंट को कनेक्ट करें

अपने क्लाइंट में पता जोड़ें। पहली बार जब कोई टूल उपयोग किया जाता है, तो आपका ब्राउज़र खुल जाता है। चुनें कि आपका Failproof AI Cloud कहाँ है, साइन इन करें, एक organization चुनें, और **Allow** को चुनें। **Cancel** कुछ भी कनेक्ट नहीं करता है।

पृष्ठ app का नाम और जहाँ यह वापस लौटता है, दिखाता है। एक app जो अपने स्वयं के web address द्वारा पहचाना नहीं जाता है, वह **unverified app** के रूप में चिह्नित होता है, इसलिए केवल तभी आगे बढ़ें यदि आपने अभी इसे अपने क्लाइंट से शुरू किया है।

<Tabs>
  <Tab title="Claude">
    claude.ai या Claude Desktop में, **Settings → Connectors → Add custom connector** पर जाएं। इसका नाम `Failproof AI` रखें, पता दर्ज करें, **Add** को चुनें, फिर **Connect**।

    Team और Enterprise plans पर, एक owner पहले organization के लिए connector को जोड़ता है। तब हर व्यक्ति अपना स्वयं का account कनेक्ट करता है।
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    फिर Claude Code के अंदर `/mcp` चलाएं, `failproofai` को चुनें, और **Authenticate** चुनें।
  </Tab>
  <Tab title="Cursor">
    इसे `~/.cursor/mcp.json` में, या अपने project के `.cursor/mcp.json` में जोड़ें:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor server के आगे **Needs login** दिखाता है। साइन इन करने के लिए इसे चुनें।
  </Tab>
  <Tab title="Codex">
    इसे `~/.codex/config.toml` में जोड़ें:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    फिर `codex mcp login failproofai` चलाएं।
  </Tab>
  <Tab title="Other clients">
    कोई भी क्लाइंट जो OAuth के साथ Streamable HTTP पर remote MCP servers को सपोर्ट करता है, काम करता है। इसे ऊपर दिया गया पता दें। कोई client ID या secret कॉन्फ़िगर करने के लिए नहीं है।
  </Tab>
</Tabs>

## प्रति कनेक्शन एक organization

एक कनेक्शन केवल उस organization में कार्य करता है जिसे आपने चुना है। दो organizations का उपयोग करने के लिए, सर्वर को दो बार विभिन्न नामों के तहत जोड़ें, जैसे `failproofai-acme` और `failproofai-sandbox`, और प्रत्येक को अपने organization से कनेक्ट करें।

Demo organizations कनेक्शन स्वीकार नहीं करते। इसके बजाय अपना organization चुनें।

## अनुमतियां

एक कनेक्शन वह कर सकता है जो आप organization में कर सकते हैं, नीचे दिए गए सेट के भीतर। यह आपकी वर्तमान अनुमतियों का पालन करता है: यदि कोई admin आपको अधिक देता है, तो टूल को यह मिल जाता है, और यदि वे कुछ दूर ले जाते हैं, तो टूल इसे अपने अगले कॉल पर खो देता है।

| अनुमति | टूल को अनुमति देता है |
| --- | --- |
| `events:read` | Events को सूचीबद्ध करें, एक सेशन का अवलोकन पढ़ें, agents और environments को सूचीबद्ध करें |
| `evaluations:read` | सेशन को सूचीबद्ध करें, और evaluation results और jobs को पढ़ें और संक्षेप में बताएं |
| `evaluations:trigger` | Evaluations बनाएं, नए versions प्रकाशित करें, उन्हें चालू या बंद करें, backfill करें, और एक सेशन का पुनः-मूल्यांकन करें |
| `dashboards:read`, `dashboards:write` | डैशबोर्ड पढ़ें, या उन्हें बनाएं, नाम बदलें, और queries जोड़ें |
| `queries:read`, `queries:write` | सहेजी गई queries को पढ़ें, या उन्हें सहेजें और edit करें |
| `queries:run` | एक read-only SQL query चलाएं और query schema को पढ़ें |
| `alerts:read`, `alerts:write` | Alerts को पढ़ें, या उन्हें बनाएं, edit करें, pause करें, delete करें, और test करें |
| `issues:read` | Issues को पढ़ें, उन्हें स्वीकार करें, और उन पर टिप्पणी करें |
| `issues:create` | किसी alert पर एक issue खोलें |
| `issues:close` | Issues को resolve और close करें |
| `audits:read`, `audits:write` | Audits, runs, और findings को पढ़ें, या audits बनाएं और edit करें तथा एक run शुरू करें |
| `code_fixes:read` | देखें कि किसी issue को कैसे ठीक करें, और अपने agent को fix करने के लिए इसका context प्राप्त करें |
| `code_fixes:write` | Failproof AI Cloud में एक fix शुरू करें, जो आपके GitHub पर एक pull request खोलता है |
| `policies:read`, `policies:write` | Policies, machines, और deployments को पढ़ें, या policies को publish, deploy, और rollback करें |

कुछ टूल को कोई अनुमति नहीं चाहिए क्योंकि वे कोई organization डेटा नहीं पढ़ते: सेशन और event links बनाना, और इस documentation को खोजना।

एक AI टूल कभी भी API keys, users, settings, या organization administration को छू नहीं सकता है, और यह events नहीं भेज सकता है।

## परिवर्तनों को मंजूरी देना

Writes पहले आपसे पूछते हैं यदि आपका क्लाइंट prompt दिखा सकता है। आप देखते हैं कि क्या बदलेगा और आगे बढ़ने के लिए **Approve this change** को चुनते हैं। यदि आप अस्वीकार करते हैं या लगभग 4 मिनट में जवाब नहीं देते, तो कुछ नहीं बदलता है। कुछ क्लाइंट एक मिनट के बाद इंतज़ार करना बंद कर देते हैं, इसलिए तुरंत उत्तर दें।

<Warning>
  एक क्लाइंट जो prompts को सपोर्ट नहीं करता है, उससे नहीं पूछा जाता है, और एक write तुरंत चलता है जब क्लाइंट कॉल करता है। वहाँ, आपके क्लाइंट की स्वयं की पुष्टि ही एकमात्र है, इसलिए इसे write tools के लिए चालू रखें।
</Warning>

## कनेक्टेड apps और revoke करना

**Settings → Integrations → MCP** वर्तमान organization में आपके कनेक्टेड apps को सूचीबद्ध करता है, उनकी अनुमतियों और अंतिम उपयोग के साथ। **Revoke** एक app को तुरंत बंद कर देता है। अपने क्लाइंट में सर्वर को हटाना भी कनेक्शन को revoke कर देता है।

आप प्रति organization 5 कनेक्टेड apps तक रख सकते हैं। एक ही app को फिर से कनेक्ट करना इसके पहले के कनेक्शन को replace कर देता है।

## Self-hosted deployments

कनेक्ट करते समय **Self-hosted Failproof AI Cloud** चुनें, और वह पता दर्ज करें जहाँ आप साइन इन करते हैं। आपके deployment को public HTTPS पर पहुंचा जा सकना चाहिए।

Tool calls और उनके परिणाम आपके AI tool और आपके deployment के बीच hosted Failproof AI gateway से होकर जाते हैं। Gateway उन्हें store नहीं करता है।

## आपके डेटा के साथ क्या होता है

परिणाम उस AI tool को जाते हैं जिसे आपने कनेक्ट किया है, और उस tool के provider इसे अपनी शर्तों के तहत handle करते हैं। हर tool call के लिए, Failproof AI tool के नाम, इसके परिणाम, कितना समय लगा, और organization को log करता है, कभी arguments या results को नहीं। [privacy policy](https://befailproof.ai/privacy/) देखें।

## Troubleshooting

| आप क्या देखते हैं | क्या करें |
| --- | --- |
| "Started in another browser" | उस ब्राउज़र में साइन-इन पूरा करें जो क्लाइंट ने खोला है, cookies की अनुमति के साथ, और क्लाइंट से फिर से शुरू करें |
| **Allow** के बाद एक error | लिंक एक बार काम करता है और 10 मिनट के बाद expire हो जाता है, इसलिए क्लाइंट से फिर से शुरू करें |
| एक tool जिसकी आप अपेक्षा करते हैं, वह गायब है | आप इस organization में इसकी अनुमति नहीं रखते। एक admin से पूछें। एक बार जब आपके पास यह हो तो आपको reconnect करने की आवश्यकता नहीं है |
| क्लाइंट आपसे sign in करने के लिए पूछता रहता है | कनेक्शन को revoke किया गया था, आप organization से चले गए, या यह 90 दिनों तक अप्रयुक्त रहा। फिर से कनेक्ट करें |
| "You have 5 connected apps" | **Settings → Integrations → MCP** के तहत एक को revoke करें, फिर फिर से कनेक्ट करें |
