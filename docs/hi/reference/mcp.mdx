एक AI टूल को Failproof AI Cloud से जोड़ें और इससे अपने agents के डेटा के साथ काम करें। आपका टूल सत्रों और इवेंट्स को क्वेरी कर सकता है, read-only SQL चला सकता है, डैशबोर्ड, अलर्ट, समस्याएं, ऑडिट और नीतियों को पढ़ सकता है, और यदि आपके पास अनुमति है, तो सतर्कता बनाना या नीति तैनात करने जैसे परिवर्तन कर सकता है।

प्रत्येक कॉल **आपकी अपनी** अनुमतियों के साथ चलती है, **एक** संगठन में जो आप कनेक्ट करते समय चुनते हैं।

सभी के लिए एक पता है, होस्ट किया गया या स्व-होस्ट किया गया:

```text
https://gateway.befailproof.ai/mcp
```

## क्लाइंट को कनेक्ट करें

अपने क्लाइंट में पता जोड़ें। पहली बार जब कोई टूल उपयोग किया जाता है, तो आपका ब्राउज़र खुलता है। चुनें कि आपका Failproof AI Cloud कहाँ है, साइन इन करें, एक संगठन चुनें, और **Allow** चुनें। **Cancel** कुछ नहीं जोड़ता है।

पृष्ठ ऐप का नाम और जहाँ यह लौटता है, वह नाम देता है। एक ऐप जो अपने स्वयं के वेब पते से पहचाना नहीं जाता है, उसे **unverified app** चिह्नित किया जाता है, इसलिए केवल तभी जारी रखें यदि आपने अभी अपने क्लाइंट से इसे शुरू किया है।

<Tabs>
  <Tab title="Claude">
    claude.ai या Claude Desktop में, **Settings → Connectors → Add custom connector** पर जाएं। इसका नाम `Failproof AI` रखें, पता दर्ज करें, **Add** चुनें, फिर **Connect** चुनें।

    Team और Enterprise योजनाओं पर, एक मालिक पहले संगठन के लिए कनेक्टर जोड़ता है। फिर प्रत्येक व्यक्ति अपने स्वयं के खाते को कनेक्ट करता है।
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    फिर Claude Code के अंदर `/mcp` चलाएं, `failproofai` चुनें, और **Authenticate** चुनें।
  </Tab>
  <Tab title="Cursor">
    इसे `~/.cursor/mcp.json` में, या अपने प्रोजेक्ट के `.cursor/mcp.json` में जोड़ें:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor सर्वर के आगे **Needs login** दिखाता है। साइन इन करने के लिए इसे चुनें।
  </Tab>
  <Tab title="Codex">
    इसे `~/.codex/config.toml` में जोड़ें:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    फिर `codex mcp login failproofai` चलाएं।
  </Tab>
  <Tab title="अन्य क्लाइंट">
    कोई भी क्लाइंट जो OAuth के साथ Streamable HTTP पर दूरस्थ MCP सर्वर का समर्थन करता है, काम करता है। इसे ऊपर दिया गया पता दें। कोई क्लाइंट ID या गुप्त कॉन्फ़िगर करने के लिए नहीं है।
  </Tab>
</Tabs>

## प्रति कनेक्शन एक संगठन

एक कनेक्शन केवल उस संगठन में कार्य करता है जो आपने चुना था। दो संगठनों का उपयोग करने के लिए, सर्वर को दो बार विभिन्न नामों के तहत जोड़ें, जैसे `failproofai-acme` और `failproofai-sandbox`, और प्रत्येक को अपने संगठन से जोड़ें।

डेमो संगठन कनेक्शन स्वीकार नहीं करते हैं। इसके बजाय अपना संगठन चुनें।

## अनुमतियां

एक कनेक्शन वह कर सकता है जो आप संगठन में कर सकते हैं, नीचे दिए गए सेट के भीतर। यह आपकी वर्तमान अनुमतियों का पालन करता है: यदि कोई admin आपको अधिक देता है, तो टूल इसे प्राप्त करता है, और यदि वे इसे ले जाते हैं, तो टूल इसे अपनी अगली कॉल पर खो देता है।

| अनुमति | टूल को अनुमति देता है |
| --- | --- |
| `events:read` | इवेंट्स सूचीबद्ध करें, एक सत्र का अवलोकन पढ़ें, agents और environments सूचीबद्ध करें |
| `evaluations:read` | सत्रों की सूची बनाएं, और मूल्यांकन परिणामों और कार्यों को पढ़ें और सारांशित करें |
| `evaluations:trigger` | मूल्यांकन बनाएं, नए संस्करण प्रकाशित करें, उन्हें चालू या बंद करें, बैकफिल करें, और एक सत्र का पुनः-मूल्यांकन करें |
| `dashboards:read`, `dashboards:write` | डैशबोर्ड पढ़ें, या उन्हें बनाएं, नाम बदलें, और क्वेरीज जोड़ें |
| `queries:read`, `queries:write` | सहेजी गई क्वेरीज पढ़ें, या उन्हें सहेजें और संपादित करें |
| `queries:run` | एक read-only SQL क्वेरी चलाएं और क्वेरी स्कीमा पढ़ें |
| `alerts:read`, `alerts:write` | अलर्ट पढ़ें, या उन्हें बनाएं, संपादित करें, रोकें, हटाएं, और परीक्षण करें |
| `issues:read` | समस्याओं को पढ़ें, उन्हें स्वीकार करें, और उन पर टिप्पणी करें |
| `issues:create` | एक अलर्ट पर समस्या खोलें |
| `issues:close` | समस्याओं को हल करें और बंद करें |
| `audits:read`, `audits:write` | ऑडिट, रन, और निष्कर्ष पढ़ें, या ऑडिट बनाएं, संपादित करें और एक रन शुरू करें |
| `code_fixes:read` | देखें कि किसी समस्या को कैसे ठीक करें, और अपने स्वयं के agent को ठीक करने के लिए इसका संदर्भ प्राप्त करें |
| `code_fixes:write` | Failproof AI Cloud में एक फिक्स शुरू करें, जो आपके GitHub पर एक pull request खोलता है |
| `policies:read`, `policies:write` | नीतियों, machines, और deployments को पढ़ें, या नीतियों को प्रकाशित, तैनात, और वापस लें |

कुछ टूल को कोई अनुमति की आवश्यकता नहीं है क्योंकि वे कोई संगठन डेटा नहीं पढ़ते हैं: सत्र और इवेंट लिंक बनाना, और इस दस्तावेज़ को खोजना।

एक AI टूल कभी API कुंजियों, उपयोगकर्ताओं, सेटिंग्स, या संगठन प्रशासन को स्पर्श नहीं कर सकता है, और यह इवेंट्स नहीं भेज सकता है।

## परिवर्तनों को मंजूरी देना

लिखने से पहले आपसे पूछते हैं कि क्या आपका क्लाइंट प्रॉम्प्ट दिखा सकता है। आप देखते हैं कि क्या बदलेगा और आगे बढ़ने के लिए **Approve this change** चुनते हैं। यदि आप अस्वीकार करते हैं या लगभग 4 मिनट के भीतर उत्तर नहीं देते हैं, तो कुछ भी नहीं बदलता है। कुछ क्लाइंट एक मिनट के बाद प्रतीक्षा करना बंद कर देते हैं, इसलिए जल्दी उत्तर दें।

<Warning>
  एक क्लाइंट जो प्रॉम्प्ट का समर्थन नहीं करता है, उससे नहीं पूछा जाता है, और एक लिखने वाली क्लाइंट द्वारा कॉल करने के तुरंत बाद चलती है। वहाँ, आपके क्लाइंट की स्वयं की पुष्टि ही एकमात्र है, इसलिए लिखने वाले टूल के लिए इसे चालू रखें।
</Warning>

## जुड़े ऐप्स और रद्द करना

**Settings → Integrations → MCP** वर्तमान संगठन में आपके जुड़े ऐप्स सूचीबद्ध करता है, उनकी अनुमतियों और अंतिम उपयोग के साथ। **Revoke** एक ऐप को तुरंत काट देता है। अपने क्लाइंट में सर्वर को हटाना भी कनेक्शन को रद्द कर देता है।

आप प्रति संगठन 5 जुड़े ऐप्स तक हो सकते हैं। एक ही ऐप को फिर से जोड़ने से इसका पहले का कनेक्शन बदल जाता है।

## स्व-होस्ट किए गए deployments

कनेक्ट करते समय **Self-hosted Failproof AI Cloud** चुनें, और जिस पते पर आप साइन इन करते हैं, उसे दर्ज करें। आपके deployment को सार्वजनिक HTTPS पर पहुँचा जा सकना चाहिए।

टूल कॉल और उनके परिणाम आपके AI टूल और आपके deployment के बीच होस्ट किए गए Failproof AI gateway से गुजरते हैं। gateway उन्हें संग्रहीत नहीं करता है।

## आपके डेटा का क्या होता है

परिणाम उस AI टूल पर जाते हैं जिसे आपने कनेक्ट किया था, और उस टूल का प्रदाता उन्हें अपनी शर्तों के तहत संभालता है। प्रत्येक टूल कॉल के लिए, Failproof AI टूल का नाम, इसका परिणाम, इसमें कितना समय लगा, और संगठन को लॉग करता है, कभी arguments या परिणामों को नहीं। [गोपनीयता नीति](https://befailproof.ai/privacy/) देखें।
