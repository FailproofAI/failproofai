एक AI टूल को Failproof AI Cloud से कनेक्ट करें और इससे अपने एजेंट के डेटा के साथ काम करें। आपका टूल सेशन और इवेंट्स को क्वेरी कर सकता है, रीड-ओनली SQL चला सकता है, डैशबोर्ड, अलर्ट, इश्यूज़, ऑडिट्स और पॉलिसीज़ को पढ़ सकता है, और यदि आपके पास अनुमति है, तो अलर्ट बनाने या पॉलिसी तैनात करने जैसे परिवर्तन कर सकता है।

हर कॉल **आपकी स्वयं की** अनुमतियों के साथ चलती है, **एक** संगठन में जिसे आप कनेक्ट करते समय चुनते हैं।

सभी के लिए एक पता है, होस्टेड या सेल्फ-होस्टेड:

```text
https://gateway.befailproof.ai/mcp
```

## क्लाइंट को कनेक्ट करें

इस पता को अपने क्लाइंट में जोड़ें। जब पहली बार कोई टूल उपयोग किया जाता है, तो आपका ब्राउज़र खुलता है। चुनें कि आपका Failproof AI Cloud कहाँ है, साइन इन करें, एक संगठन चुनें, और **Allow** को सिलेक्ट करें। **Cancel** कुछ भी कनेक्ट नहीं करता।

यह पृष्ठ ऐप का नाम और यह कहाँ लौटता है, दिखाता है। एक ऐप जो अपने स्वयं के वेब पता द्वारा पहचाना नहीं जाता है, **unverified app** के रूप में चिन्हित किया जाता है, इसलिए केवल तभी जारी रखें यदि आपने इसे अभी अपने क्लाइंट से शुरू किया है।

<Tabs>
  <Tab title="Claude">
    claude.ai या Claude Desktop में, **Settings → Connectors → Add custom connector** पर जाएं। इसका नाम `Failproof AI` रखें, पता दर्ज करें, **Add** को सिलेक्ट करें, फिर **Connect**।

    Team और Enterprise प्लानों पर, एक मालिक पहले संगठन के लिए कनेक्टर जोड़ता है। फिर हर व्यक्ति अपना स्वयं का खाता कनेक्ट करता है।
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    फिर Claude Code के अंदर `/mcp` चलाएं, `failproofai` को सिलेक्ट करें, और **Authenticate** को चुनें।
  </Tab>
  <Tab title="Cursor">
    इसे `~/.cursor/mcp.json` में, या अपनी प्रोजेक्ट के `.cursor/mcp.json` में जोड़ें:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor सर्वर के आगे **Needs login** दिखाता है। साइन इन करने के लिए इसे सिलेक्ट करें।
  </Tab>
  <Tab title="Codex">
    इसे `~/.codex/config.toml` में जोड़ें:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    फिर `codex mcp login failproofai` चलाएं।
  </Tab>
  <Tab title="Other clients">
    कोई भी क्लाइंट जो OAuth के साथ Streamable HTTP पर रिमोट MCP सर्वर्स को समर्थन करता है, काम करता है। इसे ऊपर दिया गया पता दें। कोई क्लाइंट ID या सीक्रेट कॉन्फ़िगर करने की आवश्यकता नहीं है।
  </Tab>
</Tabs>

## प्रति कनेक्शन एक संगठन

एक कनेक्शन केवल उस संगठन में कार्य करता है जिसे आपने चुना है। दो संगठनों का उपयोग करने के लिए, सर्वर को अलग-अलग नामों के तहत दो बार जोड़ें, जैसे `failproofai-acme` और `failproofai-sandbox`, और प्रत्येक को अपने संगठन से कनेक्ट करें।

डेमो संगठन कनेक्शन स्वीकार नहीं करते। इसके बजाय अपना संगठन चुनें।

## अनुमतियां

एक कनेक्शन वह कर सकता है जो आप संगठन में कर सकते हैं, नीचे दिए गए सेट के भीतर। यह आपकी वर्तमान अनुमतियों का पालन करता है: यदि कोई एडमिन आपको अधिक देता है, तो टूल को यह मिल जाता है, और यदि वे कुछ दूर ले जाते हैं, तो टूल को अगली कॉल पर इसे खो देता है।

| अनुमति | टूल को क्या करने देती है |
| --- | --- |
| `events:read` | इवेंट्स सूची बनाएं, सेशन का अवलोकन पढ़ें, एजेंट्स और एनवायरनमेंट्स सूची बनाएं |
| `evaluations:read` | सेशन सूची बनाएं, और मूल्यांकन परिणामों और कार्यों को पढ़ें और सारांशित करें |
| `evaluations:trigger` | मूल्यांकन बनाएं, नए संस्करण प्रकाशित करें, उन्हें चालू या बंद करें, बैकफिल करें, और सेशन का पुनः मूल्यांकन करें |
| `dashboards:read`, `dashboards:write` | डैशबोर्ड पढ़ें, या उन्हें बनाएं, नाम बदलें, और उनमें क्वेरी जोड़ें |
| `queries:read`, `queries:write` | सहेजी गई क्वेरी पढ़ें, या उन्हें सहेजें और संपादित करें |
| `queries:run` | एक रीड-ओनली SQL क्वेरी चलाएं और क्वेरी स्कीमा पढ़ें |
| `alerts:read`, `alerts:write` | अलर्ट पढ़ें, या उन्हें बनाएं, संपादित करें, रोकें, हटाएं, और परीक्षण करें |
| `issues:read` | इश्यूज़ पढ़ें, उन्हें स्वीकार करें, और उन पर टिप्पणी करें |
| `issues:create` | अलर्ट पर एक इश्यू खोलें |
| `issues:close` | इश्यूज़ को हल करें और बंद करें |
| `audits:read`, `audits:write` | ऑडिट्स, रन्स, और फाइंडिंग्स पढ़ें, या ऑडिट्स बनाएं, संपादित करें, और रन शुरू करें |
| `code_fixes:read` | देखें कि एक इश्यू को कैसे ठीक करें, और इसका संदर्भ प्राप्त करें ताकि आपका स्वयं का एजेंट इसे ठीक कर सके |
| `code_fixes:write` | Failproof AI Cloud में एक फिक्स शुरू करें, जो आपके GitHub पर एक पुल रिक्वेस्ट खोलता है |
| `policies:read`, `policies:write` | पॉलिसीज़, मशीनें, और तैनातियां पढ़ें, या पॉलिसीज़ प्रकाशित करें, तैनात करें, और रोल बैक करें |

कुछ टूल्स को कोई अनुमति की आवश्यकता नहीं है क्योंकि वे संगठन डेटा पढ़ते नहीं हैं: सेशन और इवेंट लिंक बनाना, और इस डॉक्यूमेंटेशन को खोजना।

एक AI टूल कभी API कुंजियों, उपयोगकर्ताओं, सेटिंग्स, या संगठन प्रशासन को नहीं छू सकता है, और यह इवेंट्स नहीं भेज सकता है।

## परिवर्तनों को मंजूरी देना

लेखन पहले आपसे पूछते हैं यदि आपका क्लाइंट प्रॉम्प्ट दिखा सकता है। आप देखते हैं कि क्या बदलेगा और आगे बढ़ने के लिए **Approve this change** को सिलेक्ट करते हैं। यदि आप अस्वीकार करते हैं या लगभग 4 मिनट में जवाब नहीं देते हैं, तो कुछ नहीं बदलता है। कुछ क्लाइंट्स एक मिनट के बाद प्रतीक्षा करना बंद कर देते हैं, इसलिए तुरंत जवाब दें।

<Warning>
  एक क्लाइंट जो प्रॉम्प्ट्स को समर्थन नहीं करता है, से नहीं पूछा जाता है, और एक लेखन क्लाइंट कॉल करने के तुरंत बाद चलता है। वहाँ, आपके क्लाइंट की स्वयं की पुष्टि एकमात्र है, इसलिए इसे लेखन टूल्स के लिए चालू रखें।
</Warning>

## जुड़े हुए ऐप्स और प्रतिसंहरण

**Settings → Integrations → MCP** वर्तमान संगठन में आपके जुड़े हुए ऐप्स को सूचीबद्ध करता है, उनकी अनुमतियों और अंतिम उपयोग के साथ। **Revoke** एक ऐप को तुरंत काट देता है। अपने क्लाइंट में सर्वर को हटाना भी कनेक्शन को प्रतिसंहृत करता है।

आप प्रति संगठन अधिकतम 5 जुड़े हुए ऐप्स रख सकते हैं। एक ही ऐप को फिर से कनेक्ट करना इसके पहले के कनेक्शन को बदल देता है।

## सेल्फ-होस्टेड तैनातियां

कनेक्ट करते समय **Self-hosted Failproof AI Cloud** चुनें, और उस पता को दर्ज करें जहाँ आप साइन इन करते हैं। आपकी तैनाती सार्वजनिक HTTPS पर पहुंचने योग्य होनी चाहिए।

टूल कॉल्स और उनके परिणाम आपके AI टूल और आपकी तैनाती के बीच अपने तरीके पर होस्टेड Failproof AI गेटवे के माध्यम से गुजरते हैं। गेटवे उन्हें स्टोर नहीं करता है।

## आपके डेटा का क्या होता है

परिणाम उस AI टूल में जाते हैं जिसे आपने कनेक्ट किया है, और उस टूल का प्रदाता उन्हें अपनी शर्तों के तहत संभालता है। प्रत्येक टूल कॉल के लिए, Failproof AI टूल का नाम, इसका परिणाम, यह कितना समय लगा, और संगठन लॉग करता है, कभी भी तर्क या परिणाम नहीं। [गोपनीयता नीति](https://befailproof.ai/privacy/) देखें।

| "You have 5 connected apps" | **Settings → Integrations → MCP** के तहत एक को प्रतिसंहृत करें, फिर फिर से कनेक्ट करें |
