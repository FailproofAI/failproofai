`failproofai otel` FailproofAI Cloud को वैकल्पिक OpenTelemetry रिपोर्टिंग कॉन्फ़िगर करता है। पहले `failproofai config` के साथ अपनी मशीन को कनेक्ट करें और एक संगठन व्यवस्थापक से **Settings → OpenTelemetry** को सक्षम करने के लिए कहें।

इंटरैक्टिव सेटअप Cloud की कुंजी फ़ील्ड और एजेंट पिकर के बाद OpenTelemetry के बारे में पूछता है। वैकल्पिक चरण डिफ़ॉल्ट रूप से No पर सेट है। हाँ चुनें OTEL एजेंट्स को चुनने के लिए; कनेक्शन लिखने के बाद वही सक्षम कोड चलता है। सेटअप से पहले Esc दबाने से कोई परिवर्तन लागू नहीं होता। अनअटेंडेड सेटअप, सप्लाई की गई कुंजी, ओपन-सोर्स मोड, और सहेजे गए कनेक्शन को रखने से आप शामिल नहीं होते।

## एजेंट सक्षम करें

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

समर्थित एजेंट `claude`, `codex`, और `copilot` (VS Code) हैं। Copilot सेटअप के लिए VS Code एक्जीक्यूटेबल या एक स्थापित Copilot एक्सटेंशन की आवश्यकता होती है। अकेली एक बची हुई सेटिंग्स डायरेक्टरी पर्याप्त नहीं है; जब कोई भी नहीं मिलता तो सेटअप Copilot को छोड़ देता है।

`--local` सीधे Cloud की बजाय स्थानीय रिले को भेजता है। Copilot स्वचालित रूप से रिले का उपयोग करता है क्योंकि इसकी सेटिंग्स प्रमाणीकरण हेडर को संग्रहीत नहीं कर सकती हैं।

रिले केवल आपकी मशीन पर सुनता है। आपका कॉन्फ़िगर किया गया FailproofAI डेमन कुछ सेकंड में परिवर्तन उठाता है; आपको इसे पुनः आरंभ करने की आवश्यकता नहीं है। यदि कोई अन्य एप्लिकेशन रिले पोर्ट के मालिक हैं, तो स्थिति इसे बंद के रूप में रिपोर्ट करता है और डेमन चलता रहता है।

<Warning>
टेक्स्ट कैप्चर डिफ़ॉल्ट रूप से चालू है। प्रॉम्प्ट्स और टूल विवरण को छोड़ने के लिए `--no-content` जोड़ें। एजेंट संस्करण विभिन्न सामग्री नियंत्रण उजागर कर सकते हैं; संवेदनशील डेटा के साथ उपयोग करने से पहले समीक्षा करें कि आपका एजेंट क्या निर्यात करता है।
</Warning>

Codex केवल बातचीत लॉग निर्यात करता है, आंतरिक रनटाइम ट्रेस या मेट्रिक्स नहीं। आपके Codex कॉन्फ़िगरेशन में एक स्पष्ट `log_user_prompt = false` बंद रहता है; सक्षम करना एक नोट प्रिंट करता है जब यह उस पसंद को संरक्षित करता है।

### एक रिपोर्टिंग पथ चुनें

यदि किसी एजेंट के लिए ट्रांसक्रिप्ट रिपोर्टिंग चालू है, तो सेटअप पूछता है:

> failproofai पहले से ही Claude Code सेशन को Cloud में भेजता है। इसके बजाय उन्हें OTEL के साथ भेजें? Claude Code के लिए ट्रांसक्रिप्ट अपलोड बंद हो जाता है।

डिफ़ॉल्ट No है। `--yes` प्रॉम्प्ट के बिना स्विच को स्वीकार करता है। अन्य एजेंट्स और नीति प्रवर्तन प्रभावित नहीं होते हैं।

Codex सेटअप अपनी एक्सपोर्टर सेटिंग्स लिखने से पहले कलेक्टर परिवर्तन की पुष्टि करने के लिए डेमन का इंतज़ार करता है। यदि पुष्टि समय सीमा समाप्त हो जाती है, तो सेटअप आपको Codex शुरू करने से पहले प्रतीक्षा करने के लिए चेतावनी देता है।

Config v2 `agents.selected` पर याद किए गए ट्रेसिंग सूची को रखता है (और `agents.seen` पर डिटेक्शन इतिहास)। प्रति-एजेंट ट्रांसक्रिप्ट प्राथमिकता `collector.agents.<agent>.sessions` पर रहती है, OTEL स्वामित्व `otel.agents` पर, और रिले सेटिंग्स `collector.otlp.enabled` / `collector.otlp.port` पर। ये अलग कुंजियाँ पुरानी OTEL कॉन्फ़िगरेशन को पठनीय रखती हैं: सेटअप ट्रेसिंग सूची को परिवहन प्राथमिकता या आपकी एजेंट सेटिंग्स को पुनः स्थापित करने के लिए आवश्यक स्थिति खोए बिना बदल सकता है।

## सेटअप निरीक्षण करें

```bash
failproofai otel status
```

स्थिति प्रत्येक एजेंट, चाहे इसकी सेटिंग्स FailproofAI द्वारा प्रबंधित हों, इसका गंतव्य, संगठन का इनजेस्ट स्विच, रिले स्थिति, और अंतिम रिले अपलोड परिणाम दिखाता है।

संगठन स्विच के लिए `unknown` का अर्थ है सर्वर ने इसे प्रदान नहीं किया या पहुँचा नहीं जा सकता। यह एक त्रुटि नहीं है और पुरानी Cloud संस्करण पर कॉन्फ़िगरेशन को रोकता नहीं है।

यदि Cloud अभी तक OTEL का समर्थन नहीं करता है, तो रिले अस्वीकृत निर्यात को बनाए रखता है। यदि संगठन इनजेस्ट बंद है, तो `enable` कुछ नहीं लिखता और त्रुटि के साथ बाहर निकलता है; पहले एक व्यवस्थापक से इसे चालू करने के लिए कहें।

## किसी एप्लिकेशन के लिए कॉन्फ़िगरेशन प्रिंट करें

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

आउटपुट एक OTLP/HTTP एक्सपोर्टर के लिए एक शेल पर्यावरण ब्लॉक है। Cloud आउटपुट `OTEL_EXPORTER_OTLP_ENDPOINT` को Cloud के OTLP बेस, `https://<cloud>/otel` पर सेट करता है, और एक्सपोर्टर `/v1/<signal>` को जोड़ता है; `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` जैसा एक प्रति-सिग्नल वेरिएबल को पूर्ण `https://<cloud>/otel/v1/logs` की आवश्यकता होती है। स्थानीय आउटपुट रिले को इंगित करता है, `http://127.0.0.1:<port>`। Cloud आउटपुट कॉन्फ़िगर की गई API कुंजी को शामिल करता है; इसे एक गुप्त के रूप में मानें। स्थानीय आउटपुट कुंजी को छोड़ देता है। स्थानीय आउटपुट का उपयोग करने के लिए, पहले एक स्थानीय एजेंट को सक्षम करें ताकि रिले चल रहा हो।

## पिछली सेटिंग्स को पुनः स्थापित करें

```bash
failproofai otel disable claude
failproofai otel disable all
```

अक्षम करना केवल FailproofAI द्वारा लिखी गई सेटिंग्स को पुनः स्थापित करता है, असंबंधित परिवर्तन रखता है, और प्रत्येक एजेंट की पूर्व ट्रांसक्रिप्ट-रिपोर्टिंग पसंद को पुनः स्थापित करता है। जब अंतिम प्रबंधित स्थानीय एजेंट अक्षम हो जाता है, तो रिले निर्यात स्वीकार करना बंद कर देता है।

Codex के लिए, अक्षम करना भी `collector.agents.codex.sessions_resume_after` (epoch मिलीसेकंड) को रिकॉर्ड करता है। मौजूदा रोलआउट बाइट्स को डिलीवर किए गए के रूप में माना जाता है इसलिए OTEL के साथ कैप्चर किए गए सेशन अपलोड नहीं होते हैं; बाद में जोड़े गए अभी भी ट्रांसक्रिप्ट रिपोर्टिंग के माध्यम से प्रवाहित होते हैं।

हर आदेश `--help` का समर्थन करता है। एप्लिकेशन और कोडिंग-एजेंट उदाहरणों के लिए [Cloud में OpenTelemetry](/hi/agenteye/opentelemetry) देखें।
