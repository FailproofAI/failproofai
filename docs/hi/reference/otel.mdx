`failproofai otel` FailproofAI Cloud को वैकल्पिक OpenTelemetry रिपोर्टिंग कॉन्फ़िगर करता है। पहले अपनी मशीन को `failproofai config` से कनेक्ट करें और किसी संगठन व्यवस्थापक से **Settings → OpenTelemetry** को सक्षम करने के लिए कहें।

इंटरैक्टिव सेटअप Cloud कुंजी फ़ील्ड और एजेंट पिकर के बाद OpenTelemetry के बारे में पूछता है। वैकल्पिक चरण डिफ़ॉल्ट रूप से No है। OTEL एजेंट्स चुनने के लिए Yes चुनें; कनेक्शन लिखे जाने के बाद समान सक्षम कोड चलता है। सेटअप से पहले Esc दबाने से कोई परिवर्तन लागू नहीं होता है। स्वचालित सेटअप, एक आपूर्ति की गई कुंजी, ओपन-सोर्स मोड, और एक सहेजे गए कनेक्शन को बनाए रखने से आप ऑप्ट इन नहीं होते।

## एजेंट को सक्षम करें

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

समर्थित एजेंट `claude`, `codex`, और `copilot` (VS Code) हैं। Copilot सेटअप के लिए एक VS Code निष्पादन योग्य या एक स्थापित Copilot एक्सटेंशन की आवश्यकता है। अकेले एक बचा हुआ सेटिंग्स निर्देशिका पर्याप्त नहीं है; जब न तो कोई नहीं मिलता तो सेटअप Copilot को छोड़ देता है।

`--local` सीधे Cloud के बजाय स्थानीय रिले को भेजता है। Copilot स्वचालित रूप से रिले का उपयोग करता है क्योंकि इसकी सेटिंग्स प्रमाणीकरण हेडर को स्टोर नहीं कर सकती।

रिले केवल आपकी मशीन पर सुनता है। आपका कॉन्फ़िगर किया गया FailproofAI डेमन कुछ सेकंड के भीतर परिवर्तन उठाता है; आपको इसे पुनः शुरू करने की आवश्यकता नहीं है। यदि कोई अन्य एप्लिकेशन रिले पोर्ट के मालिक हैं, तो स्थिति इसे बंद के रूप में रिपोर्ट करता है और डेमन चलता रहता है।

<Warning>
टेक्स्ट कैप्चर डिफ़ॉल्ट रूप से चालू है। प्रॉम्प्ट्स और टूल विवरण को छोड़ने के लिए `--no-content` जोड़ें। एजेंट संस्करण विभिन्न सामग्री नियंत्रण को उजागर कर सकते हैं; संवेदनशील डेटा के साथ इसका उपयोग करने से पहले समीक्षा करें कि आपका एजेंट क्या निर्यात करता है।
</Warning>

Codex केवल कनवर्सेशन लॉग निर्यात करता है, न कि आंतरिक रनटाइम ट्रेस या मेट्रिक्स। आपके Codex कॉन्फ़िगरेशन में एक स्पष्ट `log_user_prompt = false` बंद रहता है; सक्षम करने से एक नोट प्रिंट होता है जब यह उस विकल्प को संरक्षित करता है।

### रिपोर्टिंग पथ चुनें

यदि किसी एजेंट के लिए ट्रांसक्रिप्ट रिपोर्टिंग चालू है, तो सेटअप पूछता है:

> failproofai पहले से ही Claude Code सत्रों को Cloud को भेजता है। इसके बजाय OTEL के साथ भेजें? Claude Code के लिए ट्रांसक्रिप्ट अपलोड बंद हो जाता है।

डिफ़ॉल्ट No है। `--yes` एक प्रॉम्प्ट के बिना स्विच को स्वीकार करता है। अन्य एजेंट और नीति प्रवर्तन प्रभावित नहीं होते।

Codex सेटअप डेमन से कलेक्टर परिवर्तन की पुष्टि करने का इंतजार करता है इससे पहले कि इसके निर्यातक सेटिंग्स लिखे। यदि पुष्टि समय समाप्त हो जाता है, तो सेटअप आपको Codex शुरू करने से पहले प्रतीक्षा करने के लिए चेतावनी देता है।

Config v2 `agents.selected` पर याद किए गए ट्रेसिंग सूची को रखता है (और `agents.seen` पर पहचान इतिहास)। प्रति-एजेंट ट्रांसक्रिप्ट वरीयता `collector.agents.<agent>.sessions` पर रहती है, OTEL स्वामित्व `otel.agents` पर, और रिले सेटिंग्स `collector.otlp.enabled` / `collector.otlp.port` पर। ये अलग कुंजियां पुरानी OTEL कॉन्फ़िगरेशन को पठनीय रखती हैं: सेटअप परिवहन वरीयता या एजेंट सेटिंग्स को पुनः स्थापित करने के लिए आवश्यक स्थिति खोए बिना ट्रेसिंग सूची को बदल सकता है।

## सेटअप का निरीक्षण करें

```bash
failproofai otel status
```

स्थिति प्रत्येक एजेंट को दिखाती है, चाहे इसकी सेटिंग्स FailproofAI द्वारा प्रबंधित हों, इसका गंतव्य, संगठन का ingress स्विच, रिले स्थिति, और अंतिम रिले अपलोड परिणाम।

संगठन स्विच के लिए `unknown` का अर्थ है कि सर्वर ने इसे प्रदान नहीं किया या तक नहीं पहुंच सके। यह एक त्रुटि नहीं है और पुरानी Cloud संस्करण पर कॉन्फ़िगरेशन को रोकता नहीं है।

यदि Cloud अभी तक OTEL का समर्थन नहीं करता है, तो रिले अस्वीकृत निर्यातों को खारिज करने के बजाय रखता है। यदि संगठन ingress बंद है, तो `enable` कुछ नहीं लिखता है और त्रुटि के साथ बाहर निकलता है; पहले किसी प्रशासक से इसे चालू करने के लिए कहें।

## एक एप्लिकेशन के लिए कॉन्फ़िगरेशन प्रिंट करें

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

आउटपुट एक OTLP/HTTP निर्यातक के लिए एक शेल पर्यावरण ब्लॉक है। Cloud आउटपुट `OTEL_EXPORTER_OTLP_ENDPOINT` को Cloud के OTLP आधार, `https://<cloud>/otel` पर सेट करता है, और निर्यातक `/v1/<signal>` जोड़ता है; एक प्रति-सिग्नल चर जैसे `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` को पूर्ण `https://<cloud>/otel/v1/logs` की आवश्यकता होती है। स्थानीय आउटपुट रिले, `http://127.0.0.1:<port>` को इंगित करता है। Cloud आउटपुट कॉन्फ़िगर किए गए API कुंजी को शामिल करता है; इसे एक गोपनीय के रूप में मानें। स्थानीय आउटपुट कुंजी को छोड़ देता है। स्थानीय आउटपुट का उपयोग करने के लिए, पहले एक स्थानीय एजेंट को सक्षम करें ताकि रिले चल रहा हो।

## पिछली सेटिंग्स को पुनः स्थापित करें

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable केवल FailproofAI द्वारा लिखी गई सेटिंग्स को पुनः स्थापित करता है, संबंधित परिवर्तनों को रखता है, और प्रत्येक एजेंट की पिछली ट्रांसक्रिप्ट-रिपोर्टिंग पसंद को पुनः स्थापित करता है। जब अंतिम प्रबंधित स्थानीय एजेंट को अक्षम किया जाता है, तो रिले निर्यातों को स्वीकार करना बंद कर देता है।

Codex के लिए, disable भी `collector.agents.codex.sessions_resume_after` (epoch मिलीसेकंड) को रिकॉर्ड करता है। मौजूदा रोलआउट बाइट्स को डिलीवर किए गए के रूप में माना जाता है ताकि OTEL के साथ कैप्चर किए गए सत्र फिर से अपलोड न हों; बाद के परिशिष्ट अभी भी ट्रांसक्रिप्ट रिपोर्टिंग के माध्यम से प्रवाहित होते हैं।

प्रत्येक कमांड `--help` का समर्थन करता है। एप्लिकेशन और कोडिंग-एजेंट उदाहरणों के लिए [Cloud में OpenTelemetry](/hi/agenteye/opentelemetry) देखें।
