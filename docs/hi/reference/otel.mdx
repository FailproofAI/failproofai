`failproofai otel` FailproofAI Cloud को वैकल्पिक OpenTelemetry रिपोर्टिंग कॉन्फ़िगर करता है। पहले `failproofai config` के साथ अपनी मशीन को कनेक्ट करें और किसी संगठन व्यवस्थापक से **Settings → OpenTelemetry** सक्षम करने के लिए कहें।

इंटरेक्टिव सेटअप क्लाउड की फील्ड और एजेंट पिकर के बाद OpenTelemetry के बारे में पूछता है। वैकल्पिक चरण डिफ़ॉल्ट रूप से No पर सेट है। OTEL एजेंट्स चुनने के लिए Yes चुनें; कनेक्शन लिखे जाने के बाद समान सक्षम कोड चलता है। सेटअप से पहले Esc दबाने से कोई परिवर्तन नहीं होता। अनअटेंडेड सेटअप, आपूर्ति की गई कुंजी, ओपन-सोर्स मोड, और किसी सहेजे हुए कनेक्शन को रखना आपको सक्षम नहीं करता है।

## एजेंट सक्षम करें

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

समर्थित एजेंट्स हैं `claude`, `codex`, और `copilot` (VS Code)। Copilot सेटअप के लिए VS Code निष्पादन योग्य या एक स्थापित Copilot एक्सटेंशन की आवश्यकता होती है। एक बचा हुआ सेटिंग्स निर्देशिका अकेले पर्याप्त नहीं है; जब न तो मिलता है तो सेटअप Copilot को छोड़ देता है।

`--local` सीधे Cloud के बजाय स्थानीय रिले को भेजता है। Copilot रिले का स्वचालित रूप से उपयोग करता है क्योंकि इसकी सेटिंग्स प्रमाणीकरण हेडर को स्टोर नहीं कर सकती हैं।

रिले केवल आपकी मशीन पर सुनता है। आपका कॉन्फ़िगर किया गया FailproofAI डेमन कुछ सेकंड में परिवर्तन उठाता है; आपको इसे पुनः आरंभ करने की आवश्यकता नहीं है। यदि कोई अन्य एप्लिकेशन रिले पोर्ट के मालिक है, तो स्थिति इसे बंद के रूप में रिपोर्ट करता है और डेमन चलता रहता है।

<Warning>
पाठ कैप्चर डिफ़ॉल्ट रूप से सक्षम है। प्रॉम्प्ट्स और टूल विवरण छोड़ने के लिए `--no-content` जोड़ें। एजेंट संस्करण अलग-अलग सामग्री नियंत्रण प्रदर्शित कर सकते हैं; संवेदनशील डेटा के साथ इसका उपयोग करने से पहले समीक्षा करें कि आपका एजेंट क्या निर्यात करता है।
</Warning>

Codex केवल बातचीत लॉग निर्यात करता है, आंतरिक रनटाइम ट्रेस या मेट्रिक्स नहीं। आपकी Codex कॉन्फ़िगरेशन में एक स्पष्ट `log_user_prompt = false` बंद रहता है; सक्षम करना एक नोट प्रिंट करता है जब यह उस पसंद को संरक्षित करता है।

### एक रिपोर्टिंग पथ चुनें

यदि किसी एजेंट के लिए ट्रांसक्रिप्ट रिपोर्टिंग चालू है, तो सेटअप पूछता है:

> failproofai पहले से ही Claude Code सेशन को Cloud में भेजता है। उन्हें OTEL के साथ भेजें? Claude Code के लिए ट्रांसक्रिप्ट अपलोड बंद हो जाता है।

डिफ़ॉल्ट No है। `--yes` प्रॉम्प्ट के बिना स्विच को स्वीकार करता है। अन्य एजेंट्स और नीति प्रवर्तन अप्रभावित हैं।

Codex सेटअप डेमन को अपने एक्सपोर्टर सेटिंग्स लिखने से पहले कलेक्टर परिवर्तन की पुष्टि करने के लिए प्रतीक्षा करता है। यदि पुष्टि समय समाप्त हो जाता है, तो सेटअप आपको Codex शुरू करने से पहले प्रतीक्षा करने के लिए चेतावनी देता है।

Config v2 `agents.selected` पर याद किए गए ट्रेसिंग सूची को रखता है (और `agents.seen` पर पहचान इतिहास)। प्रति-एजेंट ट्रांसक्रिप्ट प्राथमिकता `collector.agents.<agent>.sessions` पर रहती है, OTEL स्वामित्व `otel.agents` पर, और रिले सेटिंग्स `collector.otlp.enabled` / `collector.otlp.port` पर। ये अलग कुंजियां पुरानी OTEL कॉन्फ़िगरेशन को पठनीय रखती हैं: सेटअप ट्रेसिंग सूची को बदल सकता है बिना परिवहन वरीयता या अपनी एजेंट सेटिंग्स को पुनः स्थापित करने के लिए आवश्यक स्थिति खोए।

## सेटअप का निरीक्षण करें

```bash
failproofai otel status
```

स्थिति हर एजेंट, चाहे इसकी सेटिंग्स FailproofAI द्वारा प्रबंधित हों, इसका गंतव्य, संगठन की ingest स्विच, रिले स्थिति, और अंतिम रिले अपलोड परिणाम दिखाता है।

संगठन स्विच के लिए `unknown` का अर्थ है कि सर्वर ने इसे प्रदान नहीं किया या तक नहीं पहुंच सकता था। यह एक त्रुटि नहीं है और एक पुराने Cloud संस्करण पर कॉन्फ़िगरेशन को रोकता नहीं है।

यदि Cloud अभी तक OTEL का समर्थन नहीं करता है, तो रिले अस्वीकृत निर्यात को त्यागने के बजाय रखता है। यदि संगठन ingest बंद है, `enable` कुछ नहीं लिखता है और एक त्रुटि के साथ निकलता है; इसे पहले चालू करने के लिए एक व्यवस्थापक से पूछें।

## एक एप्लिकेशन के लिए कॉन्फ़िगरेशन प्रिंट करें

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

आउटपुट एक OTLP/HTTP एक्सपोर्टर के लिए एक शेल पर्यावरण ब्लॉक है। Cloud आउटपुट `OTEL_EXPORTER_OTLP_ENDPOINT` को Cloud के OTLP आधार पर सेट करता है, `https://<cloud>/otel`, और एक्सपोर्टर `/v1/<signal>` जोड़ता है; `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` जैसे एक प्रति-संकेत चर को पूर्ण `https://<cloud>/otel/v1/logs` की आवश्यकता है। स्थानीय आउटपुट रिले, `http://127.0.0.1:<port>` पर इंगित करता है। Cloud आउटपुट कॉन्फ़िगर की गई API कुंजी को शामिल करता है; इसे एक रहस्य के रूप में मानें। स्थानीय आउटपुट कुंजी को छोड़ता है। स्थानीय आउटपुट का उपयोग करने के लिए, पहले एक स्थानीय एजेंट सक्षम करें ताकि रिले चल रहा हो।

## पिछली सेटिंग्स को पुनः स्थापित करें

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable केवल सेटिंग्स को पुनः स्थापित करता है जो FailproofAI ने लिखी हैं, असंबंधित परिवर्तन रखता है, और प्रत्येक एजेंट की पिछली ट्रांसक्रिप्ट-रिपोर्टिंग पसंद को पुनः स्थापित करता है। जब अंतिम प्रबंधित स्थानीय एजेंट अक्षम हो जाता है, तो रिले निर्यात स्वीकार करना बंद कर देता है।

Codex के लिए, disable भी `collector.agents.codex.sessions_resume_after` (epoch milliseconds) रिकॉर्ड करता है। मौजूदा रोलआउट बाइट्स को डिलीवर माना जाता है ताकि OTEL के साथ कैप्चर किए गए सेशन फिर से अपलोड न हों; बाद में जोड़ना अभी भी ट्रांसक्रिप्ट रिपोर्टिंग के माध्यम से प्रवाहित होता है।

हर कमांड `--help` का समर्थन करता है। अनुप्रयोग और कोडिंग-एजेंट उदाहरणों के लिए [OpenTelemetry in Cloud](/hi/agenteye/opentelemetry) देखें।
