`failproofai otel` FailproofAI Cloud को वैकल्पिक OpenTelemetry reporting कॉन्फ़िगर करता है। पहले `failproofai config` से अपनी मशीन को कनेक्ट करें। OpenTelemetry ingest Cloud में हमेशा चालू होता है, इसलिए इसे चालू करने के लिए कोई संगठन स्विच नहीं है।

इंटरैक्टिव सेटअप Cloud key फ़ील्ड और agent picker के बाद OpenTelemetry के बारे में पूछता है। यह वैकल्पिक चरण डिफ़ॉल्ट रूप से No पर सेट होता है। OTEL agents चुनने के लिए Yes चुनें; कनेक्शन लिखने के बाद वही enable code चलता है। Esc से पहले setup कुछ भी नहीं बदलता है। Unattended setup, एक आपूर्ति की गई key, open-source mode, और एक सहेजे गए कनेक्शन को रखने से आप opt in नहीं होते हैं।

## एक agent को enable करें

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

समर्थित agents `claude`, `codex`, और `copilot` (VS Code) हैं। Copilot सेटअप के लिए एक VS Code executable या एक installed Copilot extension की आवश्यकता होती है। एक leftover settings directory अकेले पर्याप्त नहीं है; जब कोई भी नहीं मिलता तो सेटअप Copilot को छोड़ देता है।

`--local` सीधे Cloud के बजाय local relay को भेजता है। Copilot स्वचालित रूप से relay का उपयोग करता है क्योंकि इसकी सेटिंग्स प्रमाणीकरण header को स्टोर नहीं कर सकती।

Relay केवल आपकी मशीन पर सुनता है। आपका कॉन्फ़िगर किया गया FailproofAI daemon सेकंड के भीतर परिवर्तन को उठाता है; आपको इसे पुनः शुरू करने की आवश्यकता नहीं है। यदि कोई अन्य एप्लिकेशन relay port के मालिक हैं, तो स्थिति इसे off के रूप में रिपोर्ट करती है और daemon चलता रहता है।

<Warning>
टेक्स्ट कैप्चर डिफ़ॉल्ट रूप से चालू है। Prompts और tool details को छोड़ने के लिए `--no-content` जोड़ें। Agent versions अलग-अलग content controls को expose कर सकते हैं; संवेदनशील डेटा के साथ इसका उपयोग करने से पहले समीक्षा करें कि आपका agent क्या export करता है।
</Warning>

Codex केवल conversation logs export करता है, internal runtime traces या metrics नहीं। आपके Codex configuration में एक explicit `log_user_prompt = false` बंद रहता है; enable एक नोट प्रिंट करता है जब यह उस पसंद को संरक्षित करता है।

### एक reporting path चुनें

यदि किसी agent के लिए transcript reporting चालू है, तो सेटअप पूछता है:

> failproofai पहले से Claude Code sessions को Cloud में भेजता है। इसके बजाय OTEL के साथ भेजें? Claude Code के लिए Transcript upload बंद हो जाता है।

डिफ़ॉल्ट No है। `--yes` एक prompt के बिना स्विच को स्वीकार करता है। अन्य agents और policy enforcement प्रभावित नहीं होते हैं।

Codex सेटअप अपनी exporter settings लिखने से पहले collector परिवर्तन की पुष्टि करने के लिए daemon की प्रतीक्षा करता है। यदि पुष्टि समय समाप्त हो जाती है, तो सेटअप आपको Codex शुरू करने से पहले प्रतीक्षा करने के लिए चेतावनी देता है।

Config v2 याद किए गए tracing list को `agents.selected` पर रखता है (और detection history को `agents.seen` पर)। Per-agent transcript preference `collector.agents.<agent>.sessions` पर रहता है, OTEL ownership `otel.agents` पर है, और relay settings `collector.otlp.enabled` / `collector.otlp.port` पर हैं। ये अलग-अलग keys पुरानी OTEL configurations को readable रखते हैं: सेटअप tracing list को बदल सकता है बिना transport preference या agent settings को पुनः स्थापित करने के लिए आवश्यक state खोए।

## सेटअप का निरीक्षण करें

```bash
failproofai otel status
```

Status हर agent, चाहे इसकी settings FailproofAI द्वारा प्रबंधित हों, इसका गंतव्य, संगठन का ingest switch, relay state, और अंतिम relay upload result दिखाता है।

संगठन switch के लिए `unknown` का मतलब है कि सर्वर ने इसे provide नहीं किया या reach नहीं कर सका। यह एक त्रुटि नहीं है और एक पुराने Cloud version पर configuration को रोकता नहीं है।

यदि Cloud अभी तक OTEL को support नहीं करता है, तो relay rejected exports को retain करता है बजाय इसे discard करने के। यदि एक पुराना Cloud version organisation ingest को off के रूप में रिपोर्ट करता है, तो `enable` कुछ नहीं लिखता है और एक त्रुटि के साथ बाहर निकलता है।

## एक एप्लिकेशन के लिए configuration प्रिंट करें

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

Output एक OTLP/HTTP exporter के लिए एक shell environment block है। Cloud output `OTEL_EXPORTER_OTLP_ENDPOINT` को Cloud के OTLP base, `https://<cloud>/otel` पर सेट करता है, और exporter `/v1/<signal>` जोड़ता है; एक per-signal variable जैसे `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` को full `https://<cloud>/otel/v1/logs` की आवश्यकता होती है। Local output relay की ओर इशारा करता है, `http://127.0.0.1:<port>`। Cloud output configured API key को शामिल करता है; इसे एक secret मानें। Local output key को छोड़ देता है। Local output का उपयोग करने के लिए, पहले एक local agent को enable करें ताकि relay चल रहा हो।

## पिछली सेटिंग्स को पुनः स्थापित करें

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable केवल FailproofAI द्वारा लिखी गई settings को restores करता है, unrelated changes को keeps करता है, और प्रत्येक agent की prior transcript-reporting choice को restores करता है। जब अंतिम managed local agent को disable किया जाता है, तो relay exports को स्वीकार करना बंद कर देता है।

Codex के लिए, disable भी `collector.agents.codex.sessions_resume_after` (epoch milliseconds) को record करता है। मौजूदा rollout bytes को delivered के रूप में treat किया जाता है इसलिए OTEL के साथ कैप्चर किए गए sessions को फिर से upload नहीं किया जाता है; बाद के appends अभी भी transcript reporting के माध्यम से flow करते हैं।

हर command `--help` को support करता है। एप्लिकेशन और coding-agent examples के लिए [OpenTelemetry in Cloud](/hi/agenteye/opentelemetry) देखें।
