`failproofai otel` FailproofAI Cloud के लिए वैकल्पिक OpenTelemetry रिपोर्टिंग को कॉन्फ़िगर करता है। पहले अपनी मशीन को `failproofai config` के साथ कनेक्ट करें और किसी संगठन प्रशासक से **Settings → OpenTelemetry** सक्षम करने के लिए कहें।

इंटरेक्टिव सेटअप Cloud की को फील्ड और एजेंट पिकर के बाद OpenTelemetry के बारे में पूछता है। यह वैकल्पिक चरण डिफ़ॉल्ट रूप से No पर सेट है। OTEL एजेंट्स चुनने के लिए Yes चुनें; कनेक्शन लिखे जाने के बाद समान enable कोड चलता है। Esc दबाने से सेटअप कोई परिवर्तन लागू नहीं करता। बिना किसी इंटरैक्शन के सेटअप, एक आपूर्ति की गई key, ओपन-सोर्स मोड, और एक सहेजे गए कनेक्शन को रखना आपको ऑप्ट इन नहीं करता।

## एक एजेंट सक्षम करें

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

समर्थित एजेंट्स `claude`, `codex`, और `copilot` (VS Code) हैं। Copilot सेटअप के लिए एक VS Code निष्पादन योग्य या एक स्थापित Copilot एक्सटेंशन की आवश्यकता है। केवल एक बचा हुआ सेटिंग्स निर्देशिका पर्याप्त नहीं है; जब न कोई भी नहीं मिलता है तो सेटअप Copilot को छोड़ देता है।

`--local` सीधे Cloud के बजाय स्थानीय रिले को भेजता है। Copilot स्वचालित रूप से रिले का उपयोग करता है क्योंकि इसकी सेटिंग्स प्रमाणीकरण हेडर को स्टोर नहीं कर सकते।

रिले केवल आपकी मशीन पर सुनता है। आपका कॉन्फ़िगर किया गया FailproofAI डेमन सेकंड के भीतर परिवर्तन को चुनता है; आपको इसे पुनः शुरू करने की आवश्यकता नहीं है। यदि कोई अन्य एप्लिकेशन रिले पोर्ट का मालिक है, तो स्थिति इसे off के रूप में रिपोर्ट करता है और डेमन चलता रहता है।

<Warning>
टेक्स्ट कैप्चर डिफ़ॉल्ट रूप से चालू है। प्रॉम्प्ट्स और टूल विवरण को छोड़ने के लिए `--no-content` जोड़ें। एजेंट संस्करण विभिन्न सामग्री नियंत्रण उजागर कर सकते हैं; संवेदनशील डेटा के साथ इसका उपयोग करने से पहले समीक्षा करें कि आपका एजेंट क्या निर्यात करता है।
</Warning>

Codex केवल वार्तालाप लॉग निर्यात करता है, आंतरिक रनटाइम ट्रेस या मेट्रिक्स नहीं। आपके Codex कॉन्फ़िगरेशन में एक स्पष्ट `log_user_prompt = false` बंद रहता है; enable एक नोट प्रिंट करता है जब यह उस पसंद को संरक्षित करता है।

### एक रिपोर्टिंग पथ चुनें

यदि किसी एजेंट के लिए ट्रांसक्रिप्ट रिपोर्टिंग चालू है, तो सेटअप पूछता है:

> failproofai पहले से ही Claude Code सत्रों को Cloud को भेजता है। इसके बजाय उन्हें OTEL के साथ भेजें? Claude Code के लिए ट्रांसक्रिप्ट अपलोड रुक जाता है।

डिफ़ॉल्ट No है। `--yes` एक प्रॉम्प्ट के बिना स्विच स्वीकार करता है। अन्य एजेंट्स और नीति प्रवर्तन प्रभावित नहीं हैं।

Codex सेटअप डेमन को कलेक्टर परिवर्तन की पुष्टि करने के लिए प्रतीक्षा करता है इसके निर्यातक सेटिंग्स लिखने से पहले। यदि पुष्टि समय समाप्त हो जाता है, तो सेटअप आपको Codex शुरू करने से पहले प्रतीक्षा करने के लिए चेतावनी देता है।

Config v2 `agents.selected` पर याद रखे गए ट्रेसिंग सूची रखता है (और `agents.seen` पर पहचान इतिहास)। प्रति-एजेंट ट्रांसक्रिप्ट पसंद `collector.agents.<agent>.sessions` पर रहती है, OTEL स्वामित्व `otel.agents` पर, और रिले सेटिंग्स `collector.otlp.enabled` / `collector.otlp.port` पर। ये अलग-अलग कुंजियां पुरानी OTEL कॉन्फ़िगरेशन को पठनीय रखती हैं: सेटअप ट्रेसिंग सूची को बदल सकता है परिवहन पसंद या आपकी एजेंट सेटिंग्स को पुनः स्थापित करने के लिए आवश्यक स्थिति को खोए बिना।

## सेटअप का निरीक्षण करें

```bash
failproofai otel status
```

स्थिति हर एजेंट दिखाती है, चाहे इसकी सेटिंग्स FailproofAI द्वारा प्रबंधित हों, इसकी गंतव्य, संगठन की अंतर्ग्रहण स्विच, रिले स्थिति, और अंतिम रिले अपलोड परिणाम।

संगठन स्विच के लिए `unknown` का अर्थ है कि सर्वर ने इसे प्रदान नहीं किया या इसे प्राप्त नहीं किया जा सका। यह एक त्रुटि नहीं है और एक पुराने Cloud संस्करण पर कॉन्फ़िगरेशन को रोकता नहीं है।

यदि Cloud अभी तक OTEL का समर्थन नहीं करता है, तो रिले अस्वीकृत निर्यातों को उन्हें त्यागने के बजाय बनाए रखता है। यदि संगठन अंतर्ग्रहण बंद है, तो `enable` कुछ नहीं लिखता और एक त्रुटि के साथ बाहर निकलता है; पहले किसी प्रशासक से इसे चालू करने के लिए कहें।

## एक एप्लिकेशन के लिए कॉन्फ़िगरेशन प्रिंट करें

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

आउटपुट एक OTLP/HTTP निर्यातक के लिए एक शेल पर्यावरण ब्लॉक है। Cloud आउटपुट `OTEL_EXPORTER_OTLP_ENDPOINT` को Cloud के OTLP बेस, `https://<cloud>/otel` पर सेट करता है, और निर्यातक `/v1/<signal>` जोड़ता है; `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` जैसे एक प्रति-सिग्नल चर को पूर्ण `https://<cloud>/otel/v1/logs` की आवश्यकता है। स्थानीय आउटपुट रिले को इंगित करता है, `http://127.0.0.1:<port>`। Cloud आउटपुट कॉन्फ़िगर की गई API key शामिल है; इसे एक गुप्त के रूप में मानें। स्थानीय आउटपुट key को छोड़ देता है। स्थानीय आउटपुट का उपयोग करने के लिए, पहले एक स्थानीय एजेंट सक्षम करें ताकि रिले चल रहा हो।

## पिछली सेटिंग्स को पुनः स्थापित करें

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable केवल FailproofAI द्वारा लिखी गई सेटिंग्स को पुनः स्थापित करता है, असंबंधित परिवर्तनों को रखता है, और प्रत्येक एजेंट की पूर्व ट्रांसक्रिप्ट-रिपोर्टिंग पसंद को पुनः स्थापित करता है। जब अंतिम प्रबंधित स्थानीय एजेंट अक्षम किया जाता है, तो रिले निर्यात स्वीकार करना बंद कर देता है।

Codex के लिए, disable `collector.agents.codex.sessions_resume_after` (epoch मिलीसेकंड) को भी रिकॉर्ड करता है। मौजूदा रोलआउट बाइट्स को वितरित के रूप में माना जाता है इसलिए OTEL के साथ कैप्चर किए गए सत्र अपलोड नहीं किए जाते हैं; बाद में जोड़े अभी भी ट्रांसक्रिप्ट रिपोर्टिंग के माध्यम से प्रवाहित होते हैं।

हर कमांड `--help` का समर्थन करता है। एप्लिकेशन और कोडिंग-एजेंट उदाहरणों के लिए [Cloud में OpenTelemetry](/hi/agenteye/opentelemetry) देखें।
