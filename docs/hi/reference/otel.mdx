`failproofai otel` FailproofAI Cloud को वैकल्पिक OpenTelemetry रिपोर्टिंग कॉन्फ़िगर करता है। पहले `failproofai config` के साथ अपनी मशीन को कनेक्ट करें। OpenTelemetry इनजेस्ट Cloud में हमेशा चालू रहता है, इसलिए इसे चालू करने के लिए कोई संगठन स्विच नहीं है।

इंटरएक्टिव सेटअप Cloud कुंजी फील्ड और एजेंट पिकर के बाद OpenTelemetry के बारे में पूछता है। वैकल्पिक चरण डिफ़ॉल्ट रूप से नहीं है। OTEL एजेंट्स चुनने के लिए हाँ चुनें; कनेक्शन लिखने के बाद एक ही सक्षमता कोड चलता है। सेटअप से पहले Esc दबाने से कोई परिवर्तन लागू नहीं होता। अनअटेंडेड सेटअप, एक सप्लाई की गई कुंजी, ओपन-सोर्स मोड, और एक सहेजे गए कनेक्शन को रखने से आप ऑप्ट इन नहीं होते।

## एक एजेंट को सक्षम करें

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

समर्थित एजेंट्स `claude`, `codex`, और `copilot` (VS Code) हैं। Copilot सेटअप के लिए VS Code एक्सीक्यूटेबल या एक इंस्टॉल किया गया Copilot एक्सटेंशन आवश्यक है। एक बचा हुआ सेटिंग्स डायरेक्टरी अकेला पर्याप्त नहीं है; जब कोई भी नहीं मिलता तो सेटअप Copilot को छोड़ देता है।

`--local` सीधे Cloud के बजाय स्थानीय रिले को भेजता है। Copilot स्वचालित रूप से रिले का उपयोग करता है क्योंकि इसकी सेटिंग्स प्रमाणीकरण हेडर को स्टोर नहीं कर सकती।

रिले केवल आपकी मशीन पर सुनता है। आपका कॉन्फ़िगर किया गया FailproofAI डेमॉन सेकंड के भीतर परिवर्तन को उठा लेता है; आपको इसे पुनः शुरू करने की आवश्यकता नहीं है। यदि कोई अन्य एप्लिकेशन रिले पोर्ट का मालिक है, तो स्थिति इसे बंद के रूप में रिपोर्ट करता है और डेमॉन चलता रहता है।

<Warning>
टेक्स्ट कैप्चर डिफ़ॉल्ट रूप से चालू है। प्रॉम्प्ट्स और टूल विवरण को छोड़ने के लिए `--no-content` जोड़ें। एजेंट संस्करण विभिन्न सामग्री नियंत्रण उजागर कर सकते हैं; संवेदनशील डेटा के साथ इसका उपयोग करने से पहले समीक्षा करें कि आपका एजेंट क्या निर्यात करता है।
</Warning>

Codex केवल वार्तालाप लॉग निर्यात करता है, आंतरिक रनटाइम ट्रेस या मेट्रिक्स नहीं। आपके Codex कॉन्फ़िगरेशन में एक स्पष्ट `log_user_prompt = false` बंद रहता है; सक्षम करना एक नोट प्रिंट करता है जब यह उस विकल्प को संरक्षित करता है।

### एक रिपोर्टिंग पथ चुनें

यदि किसी एजेंट के लिए ट्रांसक्रिप्ट रिपोर्टिंग चालू है, तो सेटअप पूछता है:

> failproofai पहले से ही Claude Code सेशन को Cloud में भेजता है। इसके बजाय OTEL के साथ उन्हें भेजें? Claude Code के लिए ट्रांसक्रिप्ट अपलोड बंद हो जाता है।

डिफ़ॉल्ट नहीं है। `--yes` प्रॉम्प्ट के बिना स्विच स्वीकार करता है। अन्य एजेंट्स और नीति प्रवर्तन अप्रभावित हैं।

Codex सेटअप अपनी निर्यातक सेटिंग्स लिखने से पहले कलेक्टर परिवर्तन की पुष्टि करने के लिए डेमॉन की प्रतीक्षा करता है। यदि पुष्टि समय समाप्त हो जाती है, तो सेटअप आपको Codex शुरू करने से पहले प्रतीक्षा करने के लिए चेतावनी देता है।

Config v2 याद किए गए ट्रेसिंग सूची को `agents.selected` पर रखता है (और पहचान इतिहास को `agents.seen` पर)। प्रति-एजेंट ट्रांसक्रिप्ट वरीयता `collector.agents.<agent>.sessions` पर रहती है, OTEL स्वामित्व `otel.agents` पर है, और रिले सेटिंग्स `collector.otlp.enabled` / `collector.otlp.port` पर हैं। ये अलग-अलग कुंजियाँ पुरानी OTEL कॉन्फ़िगरेशन को पठनीय रखती हैं: सेटअप ट्रेसिंग सूची को बदल सकता है बिना परिवहन वरीयता या आपकी एजेंट सेटिंग्स को पुनः स्थापित करने के लिए आवश्यक स्थिति खोए।

## सेटअप निरीक्षण करें

```bash
failproofai otel status
```

स्थिति प्रत्येक एजेंट, चाहे इसकी सेटिंग्स FailproofAI द्वारा प्रबंधित हों, इसका गंतव्य, संगठन का इनजेस्ट स्विच, रिले स्थिति, और अंतिम रिले अपलोड परिणाम दिखाता है।

संगठन स्विच के लिए `unknown` का मतलब है कि सर्वर ने इसे प्रदान नहीं किया या इसे पहुँचा नहीं जा सका। यह एक त्रुटि नहीं है और एक पुराने Cloud संस्करण पर कॉन्फ़िगरेशन को रोकता नहीं है।

यदि Cloud अभी तक OTEL का समर्थन नहीं करता है, तो रिले अस्वीकृत निर्यात को त्यागने के बजाय बनाए रखता है। यदि एक पुराना Cloud संस्करण संगठन इनजेस्ट को बंद के रूप में रिपोर्ट करता है, तो `enable` कुछ नहीं लिखता और एक त्रुटि के साथ बाहर निकलता है।

## एक एप्लिकेशन के लिए कॉन्फ़िगरेशन प्रिंट करें

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

आउटपुट एक OTLP/HTTP निर्यातकर्ता के लिए एक शेल पर्यावरण ब्लॉक है। Cloud आउटपुट `OTEL_EXPORTER_OTLP_ENDPOINT` को Cloud के OTLP आधार पर सेट करता है, `https://<cloud>/otel`, और निर्यातकर्ता `/v1/<signal>` जोड़ता है; `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` जैसा एक प्रति-संकेत चर पूर्ण `https://<cloud>/otel/v1/logs` की आवश्यकता है। स्थानीय आउटपुट रिले को इंगित करता है, `http://127.0.0.1:<port>`। Cloud आउटपुट कॉन्फ़िगर की गई API कुंजी को शामिल करता है; इसे एक गोपनीय के रूप में मानें। स्थानीय आउटपुट कुंजी को छोड़ देता है। स्थानीय आउटपुट का उपयोग करने के लिए, पहले एक स्थानीय एजेंट को सक्षम करें ताकि रिले चल रहा हो।

## पिछली सेटिंग्स को पुनः स्थापित करें

```bash
failproofai otel disable claude
failproofai otel disable all
```

अक्षम करना केवल FailproofAI द्वारा लिखी गई सेटिंग्स को पुनः स्थापित करता है, असंबंधित परिवर्तनों को रखता है, और प्रत्येक एजेंट की पूर्व ट्रांसक्रिप्ट-रिपोर्टिंग पसंद को पुनः स्थापित करता है। जब अंतिम प्रबंधित स्थानीय एजेंट को अक्षम किया जाता है, तो रिले निर्यात स्वीकार करना बंद कर देता है।

Codex के लिए, अक्षम करना भी `collector.agents.codex.sessions_resume_after` (epoch मिलीसेकंड) को रिकॉर्ड करता है। मौजूदा रोलआउट बाइट्स को डिलीवर किए गए के रूप में माना जाता है इसलिए OTEL के साथ कैप्चर किए गए सेशन को फिर से अपलोड नहीं किया जाता है; बाद की अपील्स अभी भी ट्रांसक्रिप्ट रिपोर्टिंग के माध्यम से प्रवाहित होती हैं।

हर आदेश `--help` को समर्थन करता है। Cloud में [OpenTelemetry](/hi/agenteye/opentelemetry) देखें आवेदन और कोडिंग-एजेंट उदाहरणों के लिए।
