`failproofai otel` FailproofAI Cloud को वैकल्पिक OpenTelemetry रिपोर्टिंग कॉन्फ़िगर करता है। पहले `failproofai config` के साथ अपनी मशीन को कनेक्ट करें और एक संगठन प्रशासक से **Settings → OpenTelemetry** को सक्षम करने के लिए कहें।

इंटरैक्टिव सेटअप क्लाउड कुंजी फ़ील्ड और एजेंट पिकर के बाद OpenTelemetry के बारे में पूछता है। वैकल्पिक चरण डिफ़ॉल्ट रूप से No पर सेट होता है। OTEL एजेंट्स को चुनने के लिए Yes चुनें; कनेक्शन लिखे जाने के बाद ही सक्षम कोड चलता है। सेटअप से पहले Esc दबाने से कोई परिवर्तन नहीं होता है। अनअटेंडेड सेटअप, आपूर्ति की गई कुंजी, ओपन-सोर्स मोड, और सहेजे गए कनेक्शन को रखने से आप ऑप्ट इन नहीं होते हैं।

## एक एजेंट को सक्षम करें

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

समर्थित एजेंट्स `claude`, `codex`, और `copilot` (VS Code) हैं। Copilot सेटअप के लिए VS Code एक्जीक्यूटेबल या इंस्टॉल किया गया Copilot एक्सटेंशन की आवश्यकता होती है। अकेली एक सेटिंग्स डायरेक्टरी पर्याप्त नहीं है; जब कोई भी नहीं मिलता तो सेटअप Copilot को छोड़ देता है।

`--local` सीधे Cloud के बजाय स्थानीय रिले को भेजता है। Copilot स्वचालित रूप से रिले का उपयोग करता है क्योंकि इसकी सेटिंग्स प्रमाणीकरण हेडर स्टोर नहीं कर सकती।

रिले केवल आपकी मशीन पर सुनता है। आपके कॉन्फ़िगर किए गए FailproofAI डेमॉन सेकंडों के भीतर परिवर्तन को हटा लेते हैं; आपको इसे पुनः शुरू करने की आवश्यकता नहीं है। यदि कोई अन्य एप्लिकेशन रिले पोर्ट के मालिक हैं, तो स्थिति इसे बंद की रिपोर्ट करती है और डेमॉन चलता रहता है।

<Warning>
टेक्स्ट कैप्चर डिफ़ॉल्ट रूप से चालू है। प्रॉम्प्ट्स और टूल विवरण को छोड़ने के लिए `--no-content` जोड़ें। एजेंट संस्करण विभिन्न सामग्री नियंत्रण प्रकट कर सकते हैं; संवेदनशील डेटा के साथ इसका उपयोग करने से पहले समीक्षा करें कि आपका एजेंट क्या निर्यात करता है।
</Warning>

Codex केवल बातचीत लॉग्स निर्यात करता है, आंतरिक रनटाइम ट्रेस या मेट्रिक्स नहीं। आपकी Codex कॉन्फ़िगरेशन में स्पष्ट `log_user_prompt = false` बंद रहता है; सक्षम करने पर यह नोट प्रिंट करता है जब यह उस पसंद को सुरक्षित रखता है।

### एक रिपोर्टिंग पथ चुनें

यदि किसी एजेंट के लिए प्रतिलेख रिपोर्टिंग चालू है, तो सेटअप पूछता है:

> failproofai पहले से ही Claude Code सत्रों को Cloud को भेजता है। इसके बजाय OTEL के साथ भेजें? Claude Code के लिए प्रतिलेख अपलोड बंद हो जाता है।

डिफ़ॉल्ट No है। `--yes` बिना प्रॉम्प्ट के स्विच स्वीकार करता है। अन्य एजेंट्स और नीति प्रवर्तन प्रभावित नहीं होते हैं।

Codex सेटअप डेमॉन से संग्राहक परिवर्तन की पुष्टि के लिए प्रतीक्षा करता है इससे पहले कि इसकी एक्सपोर्टर सेटिंग्स को लिखा जाए। यदि पुष्टि समय समाप्त हो जाती है, तो सेटअप आपको Codex शुरू करने से पहले प्रतीक्षा करने के लिए चेतावनी देता है।

Config v2 याद रखी गई ट्रेसिंग सूची को `agents.selected` पर रखता है (और पहचान इतिहास को `agents.seen` पर)। प्रति-एजेंट प्रतिलेख वरीयता `collector.agents.<agent>.sessions` पर रहती है, OTEL स्वामित्व `otel.agents` पर, और रिले सेटिंग्स `collector.otlp.enabled` / `collector.otlp.port` पर। ये अलग कुंजियां पुरानी OTEL कॉन्फ़िगरेशन को पठनीय रखते हैं: सेटअप ट्रेसिंग सूची को परिवहन वरीयता या आपकी एजेंट सेटिंग्स को पुनर्स्थापित करने के लिए आवश्यक स्थिति को खोए बिना बदल सकता है।

## सेटअप का निरीक्षण करें

```bash
failproofai otel status
```

स्थिति हर एजेंट को दिखाती है, क्या इसकी सेटिंग्स FailproofAI द्वारा प्रबंधित हैं, इसका गंतव्य, संगठन का अंतर्ग्रहण स्विच, रिले स्थिति, और अंतिम रिले अपलोड परिणाम।

संगठन स्विच के लिए `unknown` का अर्थ है सर्वर ने इसे प्रदान नहीं किया या पहुंचा नहीं जा सका। यह त्रुटि नहीं है और पुराने Cloud संस्करण पर कॉन्फ़िगरेशन को रोकता नहीं है।

यदि Cloud अभी तक OTEL का समर्थन नहीं करता है, तो रिले अस्वीकृत निर्यातों को त्यागने के बजाय रखता है। यदि संगठन अंतर्ग्रहण बंद है, तो `enable` कुछ नहीं लिखता और त्रुटि के साथ बाहर निकलता है; पहले एक प्रशासक को इसे चालू करने के लिए कहें।

## एक एप्लिकेशन के लिए कॉन्फ़िगरेशन प्रिंट करें

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

आउटपुट OTLP/HTTP एक्सपोर्टर के लिए शेल एनवायरनमेंट ब्लॉक है। Cloud आउटपुट `OTEL_EXPORTER_OTLP_ENDPOINT` को Cloud के OTLP बेस, `https://<cloud>/otel` में सेट करता है, और एक्सपोर्टर `/v1/<signal>` जोड़ता है; `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` जैसे प्रति-सिग्नल वेरिएबल को पूरा `https://<cloud>/otel/v1/logs` की जरूरत है। स्थानीय आउटपुट रिले को इंगित करता है, `http://127.0.0.1:<port>`। Cloud आउटपुट कॉन्फ़िगर की गई API कुंजी शामिल करता है; इसे गुप्त मानें। स्थानीय आउटपुट कुंजी को छोड़ता है। स्थानीय आउटपुट का उपयोग करने के लिए, पहले एक स्थानीय एजेंट को सक्षम करें ताकि रिले चल रहा हो।

## पिछली सेटिंग्स को पुनर्स्थापित करें

```bash
failproofai otel disable claude
failproofai otel disable all
```

अक्षम केवल FailproofAI द्वारा लिखी गई सेटिंग्स को पुनर्स्थापित करता है, असंबंधित परिवर्तन रखता है, और प्रत्येक एजेंट की पिछली प्रतिलेख-रिपोर्टिंग पसंद को पुनर्स्थापित करता है। जब अंतिम प्रबंधित स्थानीय एजेंट अक्षम होता है, तो रिले निर्यातों को स्वीकार करना बंद कर देता है।

Codex के लिए, अक्षम भी `collector.agents.codex.sessions_resume_after` (epoch मिलीसेकंड) रिकॉर्ड करता है। मौजूदा रोलआउट बाइट्स को डिलीवर माना जाता है इसलिए OTEL के साथ कैप्चर किए गए सत्र फिर से अपलोड नहीं होते हैं; बाद में जोड़े गए अभी भी प्रतिलेख रिपोर्टिंग के माध्यम से प्रवाहित होते हैं।

हर कमांड `--help` का समर्थन करता है। एप्लिकेशन और कोडिंग-एजेंट उदाहरणों के लिए [Cloud में OpenTelemetry](/hi/agenteye/opentelemetry) देखें।
