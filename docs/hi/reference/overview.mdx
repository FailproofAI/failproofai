अपने एजेंट के चलने की जगह के सबसे करीब एकीकरण चुनें।

यह अनुभाग दो कमांड-लाइन टूल को कवर करता है जिनके अलग-अलग काम हैं। `failproofai` उस मशीन पर चलता है जहां आपका एजेंट चलता है और एजेंट लूप के अंदर नीति को लागू करता है; `fp` Failproof AI Cloud से बात करता है और पढ़ता है कि वह लूप क्या करता है। मशीन सेटअप केवल Linux और macOS पर समर्थित है — `failproofai config` अन्य किसी भी चीज पर अस्वीकार करता है और कुछ नहीं लिखता, बजाय आधे-अधूरे कॉन्फ़िगर की गई मशीन के पीछे छोड़ने के।

जनित HTTP API पृष्ठ सार्वजनिक `/v1` सतह को कवर करते हैं। हाथ से लिखे गए पृष्ठ वर्कफ़्लो को समझाते हैं जो कई एंडपॉइंट को फैलाते हैं या उस सार्वजनिक सतह के बाहर प्रशासनिक इंटरफेस का उपयोग करते हैं।

## एजेंट को जोड़ें और डेटा सत्यापित करें

<Tabs>
  <Tab title="डैशबोर्ड">
    1. **Administration → Keys** खोलें, `events:add` और `policies:pull` के साथ एक कुंजी बनाएं, और गोपनीय की को कॉपी करें।
    2. ऊपर दिए गए मेल खाने वाले पृष्ठ का उपयोग करके एकीकरण को कॉन्फ़िगर करें।
    3. **Observe → Events** खोलें इवेंट के आने की पुष्टि करने के लिए, फिर **Observe → Sessions** को खोलें पूर्ण रन बनाने की पुष्टि करने के लिए।
    4. एकीकरण के वातावरण पर फ़िल्टर करें और ऑडिट के लिए आवश्यक मॉडल, टूल, त्रुटि, और नीति फील्ड के लिए एक सेशन का निरीक्षण करें।

    कुंजी ड्रॉअर से शुरू करें। चयनित अनुदान निर्धारित करते हैं कि क्या मशीन इवेंट भेज सकती है और Cloud-प्रबंधित नीतियां प्राप्त कर सकती है।

    ![नई API कुंजी ड्रॉअर का उपयोग इवेंट इंजेशन और नीति वितरण अनुमतियां प्रदान करने के लिए।](/images/dashboard/key-create.png)

    एकीकरण को जोड़ने के बाद, सेशन सूची का उपयोग करें यह पुष्टि करने के लिए कि इसके इवेंट अपेक्षित वातावरण में पूर्ण रन में समूहीकृत हो रहे हैं।

    ![सेशन सूची का उपयोग यह सत्यापित करने के लिए कि नया-जुड़ा एकीकरण पूर्ण एजेंट रन की रिपोर्ट कर रहा है।](/images/dashboard/sessions-list.png)

    एकीकरण को पूर्ण मानने से पहले इनमें से एक सेशन खोलें; ट्रेस में आपके ऑडिट के लिए आवश्यक मॉडल, टूल, त्रुटि, और नीति साक्ष्य शामिल होने चाहिए।
  </Tab>
  <Tab title="CLI">
    एक मशीन कुंजी बनाएं, इस मशीन को सेटअप और जोड़ें, नीति चुनें, फिर पहले सेशन को सत्यापित करें।

    ```bash
    fp keys create agent-production \
      --add events:add \
      --add policies:pull

    failproofai config --token <machine-key>

    failproofai policies add FailproofAI/policies

    failproofai flush --wait
    fp sessions --since 1h
    fp events --since 1h --limit 20
    ```

    न तो सत्यापन आदेश किसी वातावरण पर फ़िल्टर करता है, क्योंकि नई-कॉन्फ़िगर की गई मशीन हर इवेंट को `local` के रूप में स्टैम्प करती है। केवल `--env production` जोड़ें जब आप `collector.environment` सेट करें — देखें [वातावरण लेबल बदलें](/hi/reference/events-and-configuration#change-an-environment-label)।

    एक टोकन पास करना कनेक्ट करने का अनुरोध है, इसलिए `failproofai config --token <machine-key>` एक कमांड में वही करता है। वातावरण चर को प्राथमिकता दें: एक तर्क `ps` से बॉक्स पर हर उपयोगकर्ता द्वारा पठनीय है, और यह शेल इतिहास और CI लॉग में उतरता है।

    नीति चरण वैकल्पिक नहीं है। `failproofai config` डेमन को स्थापित करता है और हर समर्थित एजेंट CLI को वायर करता है, लेकिन यह जानबूझकर कोई नीति नहीं चुनता है, इसलिए नई-कॉन्फ़िगर की गई मशीन कुछ भी लागू नहीं करती जब तक आप एक पैक नहीं जोड़ते।

    जब दूसरा टूल परिणाम का उपभोग करेगा तो `fp --json sessions ...` का उपयोग करें। `--json`, `--org`, और `--base-url` जैसे वैश्विक फ़्लैग कमांड से पहले आने चाहिए।

    लोकल कमांड के लिए [Failproof AI CLI संदर्भ](/hi/reference/failproof-cli) देखें और `fp` कमांड के लिए [Failproof Cloud CLI संदर्भ](/hi/reference/cloud-cli#cli-commands) देखें।
  </Tab>
</Tabs>
