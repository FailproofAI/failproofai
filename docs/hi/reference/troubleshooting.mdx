शुरुआत करें:

```bash
failproofai config --status
failproofai policies
```

## एजेंट कनेक्ट नहीं है

सेटअप फिर से चलाएँ:

```bash
failproofai config
```

सेटअप Linux और macOS को समर्थित करता है। सेवा को इंस्टॉल करने के लिए एक बार प्रशासक एक्सेस की आवश्यकता है, लेकिन कभी sudo पासवर्ड के लिए संकेत नहीं देता।

[हार्नेसेस](/hi/reference/harnesses) में हार्नेस पथ और स्कोप जांचें।

## एक सत्र गायब है

```bash
failproofai flush --wait
failproofai backfill --since 30d --dry-run
failproofai harness list
```

पुरानी हिस्ट्री को फिर से भेजने के लिए `--dry-run` को छोड़ें। इसके साथ एक और ट्रांसक्रिप्ट स्थान जोड़ें:

```bash
failproofai harness add-path <harness> [label=]<path>
```

जब दोनों स्थान एक ही प्रोजेक्ट की प्रतियां रखते हैं तो लेबल का उपयोग करें।

## हर सुरक्षित कार्य अस्वीकृत है

एक कॉन्फ़िगर की गई मशीन पर, `failproofaid` एकमात्र मूल्यांकनकर्ता है। यदि यह उत्तर नहीं दे सकता, तो सुरक्षित कार्य बंद हो जाते हैं।

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

सेवा को मरम्मत या पुनः इंस्टॉल करने के लिए `failproofai config` चलाएँ।

## एक पैक अस्वीकृत है

`failproofai policies` उन पैकों का नाम बताते हैं जो लोड नहीं हो सकते। एक चुना हुआ पैक गायब होने के बजाय बंद हो जाता है।

सामान्य कारण:

- इंस्टॉलेशन के बाद आर्टिफैक्ट बदल गया।
- मैनिफेस्ट और बंडल की गई पॉलिसीज असहमत हैं।
- फ़ाइल गायब है या आयात नहीं की जा सकती।
- पैक एक असमर्थित इवेंट, टूल या पॉलिसी आकार का उपयोग करता है।

पैक को हटाएं या सही रिलीज़ इंस्टॉल करें:

```bash
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

## क्लाउड डिस्कनेक्ट है

कुंजी के लिए एक पर्यावरण चर पसंद करें:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
failproofai config --status
```

एक मशीन पॉलिसीज खींच सकती है और स्वतंत्र रूप से गतिविधि भेज सकती है। स्थिति दोनों की रिपोर्ट करती है।

## एक पॉलिसी ने ब्लॉक नहीं किया

तीन चीजें जांचें:

1. पॉलिसी चालू है: `failproofai policies`।
2. इसका इवेंट और टूल कार्य से मेल खाते हैं।
3. वह हार्नेस इवेंट को लागू कर सकता है।

एक टूल-कॉल डिनाई सभी 12 समर्थित हार्नेसेस पर सत्यापित है। अन्य इवेंट अलग-अलग हैं। [प्रवर्तन क्षमता](/hi/reference/harnesses#enforcement-capability) देखें।

## डाउनलोड ब्लॉक हैं

- `FAILPROOFAI_NO_DOWNLOAD=1` नेटवर्क डाउनलोड को अस्वीकार करता है।
- `FAILPROOFAI_DAEMON_BASE_URL` सेवा डाउनलोड को एक मिरर की ओर इंगित करता है।
- `FAILPROOFAI_PACK_BASE_URL` पैक डाउनलोड को एक मिरर की ओर इंगित करता है।

इंस्टॉल किए गए पैक तब भी लागू होते रहते हैं जब डाउनलोड अक्षम होते हैं।
