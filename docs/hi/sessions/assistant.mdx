Failproof AI Cloud सहायक आपके फ्लीट के बारे में प्राकृतिक भाषा में प्रश्नों का उत्तर देता है। यह सेशन और विफलताओं का विश्लेषण कर सकता है, क्वेरी चला सकता है, डैशबोर्ड बना सकता है, मूल्यांकन और सतर्कताओं की जांच कर सकता है, और आपको कार्य को उत्पाद स्क्रीन या CLI कमांड में अनुवाद किए बिना ऑडिट बनाने और चलाने में मदद कर सकता है। डैशबोर्ड में नियंत्रण को **Open agent chat** लेबल किया गया है; [`fp` CLI](/hi/reference/cloud-cli) पर यह `fp agent` कमांड समूह है।

```text
Why did production checkout agents regress this week?
Build a dashboard for tool failures, latency, and evaluation scores.
Create an audit that finds agents retrying the same failed action without changing approach.
Show me the sessions behind the most common audit finding.
```

सहायक सक्रिय संगठन में उपलब्ध डेटा और अनुमतियों के साथ काम करता है। अन्य उपयोगकर्ताओं या एजेंटों को प्रभावित करने वाले कार्यों को लागू करने से पहले इसके साक्ष्य और प्रस्तावित परिवर्तनों की समीक्षा करें।

<Note>
  सहायक डैशबोर्ड में चलता है और इसकी चैट एक व्यक्ति की होती हैं, इसलिए इसके पीछे कोई API मार्ग नहीं है जिसे कोई कुंजी कॉल कर सके। हर `fp agent` उप-कमांड को एक साइन-इन सेशन (`fp login`) और `agent:use` अनुमति की आवश्यकता होती है, और `--api-key` या `FP_API_KEY` के तहत 2 निकास देता है। एक API कुंजी कभी भी इस तक नहीं पहुंच सकती, इसलिए एक निर्धारित कार्य को `--token` या `FP_TOKEN` में एक साइन-इन सेशन टोकन ले जाना होगा। यह काम करता है — `fp agent ask` जब कोई TTY नहीं होता तो stdin से प्रश्न पढ़ता है — लेकिन एक सेशन टोकन `fp login` के लगभग 24 घंटे बाद समाप्त हो जाता है, जो सहायक को अप्राप्य स्वचालन के लिए एक खराब विकल्प बनाता है भले ही यह चलता हो।
</Note>

## सहायक से पूछें

<Tabs>
  <Tab title="Dashboard">
    1. **Open agent chat** चुनें और वर्णन करें कि आप क्या समझना, बनाना या संचालित करना चाहते हैं।
    2. सहायक के टूल कॉल, तालिकाओं और क्वेरी परिणामों की समीक्षा करें जबकि यह काम करता है।
    3. उद्धृत सेशन, सतर्कता या क्वेरी खोलें ताकि स्रोत डेटा के विरुद्ध परिणाम की पुष्टि की जा सके।
    4. एक भिन्न जांच के लिए एक नई चैट शुरू करें, या एक ही लाइन के विश्लेषण को जारी रखने के लिए चैट इतिहास का उपयोग करें।

    ![Cloud सहायक समर्थन विश्लेषण और क्वेरी के साथ एक अवलोकनीयता प्रश्न का उत्तर दे रहा है।](/images/dashboard/assistant.png)
  </Tab>
  <Tab title="CLI">
    `health` से शुरू करें। यह रिपोर्ट करता है कि क्या सहायक इस परिनियोजन के लिए सक्षम है और क्या इसके लिए एक LLM कॉन्फ़िगर किया गया है। जहां कोई LLM नहीं है, `ask` विफल हो जाता है और `models` कोई रिपोर्ट नहीं करता है — `chats`, `show`, `rename`, और `delete` स्वास्थ्य से कभी परामर्श नहीं करते और काम करते रहते हैं।

    ```bash
    fp agent health
    fp agent models
    fp agent ask "Which production checkout agents had the most tool errors in the last 24 hours?"
    ```

    `fp agent models` इस परिनियोजन को अनुमति देने वाले मॉडल और कौन सा डिफ़ॉल्ट है सूचीबद्ध करता है। `ask --model <name>` को एक पास करें। `--page-context <text>` के साथ आपके पास पहले से मौजूद पाठ में एक उत्तर को आधार दें, और जब यह एक फ़ाइल या एक पिछली कमांड से आए तो तर्क के रूप में पारित करने के बजाय stdin पर प्रश्न पाइप करें:

    ```bash
    cat incident-notes.md | fp agent ask --model <model>
    ```

    हर प्रश्न एक चैट में सहेजा जाता है। `--chat` के बिना यह एक नया शुरू करता है और इसकी संक्षिप्त आईडी प्रिंट करता है; `--chat` के साथ यह उस थ्रेड को जारी रखता है।

    ```bash
    fp agent chats
    fp agent show <chat-id>
    fp agent ask "Open representative sessions" --chat <chat-id>
    fp agent rename <chat-id> --title "checkout regression"
    fp agent delete <chat-id> --yes
    ```

    `fp agent chats` आपकी चैट को सबसे नए पहले `chat-id · title · messages · updated` के रूप में सूचीबद्ध करता है, जहां `updated` चैट की अंतिम गतिविधि की आयु है। दिखाई गई `chat-id` संक्षिप्त है — पहले 8 वर्ण — और `show`, `rename`, `delete`, और `ask --chat` सभी उस उपसर्ग को हल करते हैं। एक आईडी जो कुछ भी मेल नहीं खाता एक `chat not found` बॉक्स के साथ 6 निकास करता है; एक जो कई से मेल खाता है एक लंबे उपसर्ग के लिए पूछता है।

    `fp agent delete` पहले पुष्टि करता है। `--yes` तुरंत छोड़ देता है, और कोई भी गैर-इंटरैक्टिव आह्वान भी करता है: `--json` के तहत, या stdin रीडायरेक्ट के साथ, यह पूछे बिना आगे बढ़ता है।
  </Tab>
</Tabs>

## सहायक के साथ प्रभावी ढंग से काम करें

- पहले इसे एक लक्ष्य दें; जब वे सीमाएं महत्वपूर्ण हों तो एक पर्यावरण, वर्कफ़्लो या समय श्रेणी जोड़ें।
- उत्पन्न SQL और सारांश को अंतिम साक्ष्य के रूप में नहीं, बल्कि जांच सहायता के रूप में मानें।
- एक ऑडिट, समस्या, सतर्कता या नीति बनाने से पहले प्रतिनिधि सेशन खोलें।
- संगठन, पर्यावरण और समय फ़िल्टर को स्पष्ट रखें।
- उपयोगी SQL को एक क्वेरी के रूप में सहेजें ताकि कोई अन्य ऑपरेटर परिणाम को पुन: बना सके।

<Warning>
  दो अनुमति परतें लागू होती हैं, और वे अलग-अलग विफल होती हैं। `agent:use` सुविधा को नियंत्रित करता है: इसके बिना, `fp agent` और डैशबोर्ड चैट अनुपलब्ध हैं। उत्तर तब साइन-इन किए गए उपयोगकर्ता की डेटा अनुमतियों द्वारा बाध्य हैं — `events:read`, `evaluations:read`, `queries:run`, `policies:read` — इसलिए एक उपयोगकर्ता जो सहायक को खोल सकता है वह अभी भी उन डेटा के लिए एक खाली उत्तर प्राप्त कर सकता है जिसे वे नहीं पढ़ सकते हैं। प्रश्न को काम करने के लिए अनुमतियों को व्यापक न करें; इसके बजाय एक अधिकृत ऑपरेटर से जांच चलाने के लिए कहें। [Keys and permissions](/hi/admin/keys-and-permissions) देखें।
</Warning>
