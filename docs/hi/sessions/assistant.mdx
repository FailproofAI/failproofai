Failproof सहायक को Failproof AI में कुछ भी करने के लिए प्राकृतिक भाषा में निर्देश दें। यह सेशन और विफलताओं का विश्लेषण कर सकता है, क्वेरी चला सकता है, डैशबोर्ड बना सकता है, मूल्यांकन और अलर्ट की जांच कर सकता है, और ऑडिट बनाने और चलाने में मदद कर सकता है - बिना आपको कार्य को उत्पाद स्क्रीन या CLI कमांड में अनुवाद करने की आवश्यकता के।

```text
Why did production checkout agents regress this week?
Build a dashboard for tool failures, latency, and evaluation scores.
Create an audit that finds agents retrying the same failed action without changing approach.
Show me the sessions behind the most common audit finding.
```

असिस्टेंट सक्रिय संगठन में उपलब्ध डेटा और अनुमतियों के साथ काम करता है। अपने साक्ष्य की समीक्षा करें और अन्य उपयोगकर्ताओं या एजेंटों को प्रभावित करने वाले परिवर्तनों को लागू करने से पहले प्रस्तावित कार्यों की जांच करें।

## असिस्टेंट से पूछें

<Tabs>
  <Tab title="डैशबोर्ड">
    1. **एजेंट चैट खोलें** चुनें और वर्णन करें कि आप क्या समझना, बनाना या संचालित करना चाहते हैं।
    2. असिस्टेंट के टूल कॉल, टेबल और क्वेरी परिणामों की समीक्षा करें जबकि यह काम कर रहा है।
    3. उद्धृत सेशन, अलर्ट या क्वेरी को खोलें ताकि परिणाम को स्रोत डेटा के विरुद्ध सत्यापित किया जा सके।
    4. एक अलग जांच के लिए एक नई चैट शुरू करें, या विश्लेषण की एक ही पंक्ति को जारी रखने के लिए चैट इतिहास का उपयोग करें।

  </Tab>
  <Tab title="CLI">
    ```bash
    fp agent health
    fp agent models
    fp agent ask "Which production checkout agents had the most tool errors in the last 24 hours?"
    fp agent chats
    fp agent show <chat-id>
    fp agent ask "Open representative sessions" --chat <chat-id>
    ```

    एक जांच को पहचानने योग्य रखने के लिए `fp agent rename <chat-id> --title <title>` का उपयोग करें और इसे हटाने के लिए `fp agent delete <chat-id>` का उपयोग करें।
  </Tab>
</Tabs>

## असिस्टेंट के साथ प्रभावी ढंग से काम करें

- पहले इसे एक लक्ष्य दें; जब वे सीमाएं महत्वपूर्ण हों तो एक पर्यावरण, वर्कफ़्लो या समय श्रेणी जोड़ें।
- जेनरेट किए गए SQL और सारांश को अंतिम साक्ष्य के रूप में नहीं, बल्कि जांच सहायता के रूप में मानें।
- ऑडिट, समस्या, अलर्ट या नीति बनाने से पहले प्रतिनिधि सेशन खोलें।
- संगठन, पर्यावरण और समय फ़िल्टर को स्पष्ट रखें।
- उपयोगी SQL को क्वेरी के रूप में सहेजें ताकि कोई अन्य ऑपरेटर परिणाम को पुन: उत्पन्न कर सके।

<Warning>
  असिस्टेंट केवल वही पढ़ सकता है जो आपका वर्तमान उपयोगकर्ता एक्सेस कर सकता है। प्रश्न को काम करने के लिए अनुमतियों को व्यापक न करें; इसके बजाय एक अधिकृत ऑपरेटर से जांच चलाने के लिए कहें।
</Warning>
