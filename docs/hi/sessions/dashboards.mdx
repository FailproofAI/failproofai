डैशबोर्ड सहेजी गई क्वेरीज़ को एक ऑपरेशनल दृश्य में संयोजित करते हैं। किसी ऐसे निर्णय के चारों ओर एक बनाएं जिसे आप किसी से लेने की अपेक्षा करते हैं—हर उपलब्ध मीट्रिक के चारों ओर नहीं।

## डैशबोर्ड बनाएं

<Tabs>
  <Tab title="Dashboard">
    1. **Analyze → Queries** पर जाएं, एक सहेजी गई क्वेरी बनाएं या खोलें, और इसके परिणाम की पुष्टि करें।
    2. **add to dashboard** चुनें, फिर एक मौजूदा डैशबोर्ड चुनें या **Analyze → Dashboards** के तहत एक नया बनाएं।
    3. डैशबोर्ड खोलें, संपादन मोड में प्रवेश करें, टाइलें व्यवस्थित करें, और लेआउट सहेजें।
    4. जब आपको किसी टाइल के पीछे के डेटा या फ़िल्टर को बदलने की आवश्यकता हो तो क्वेरी पर वापस लौटें।

    ![event volume, errors, latency, और model token use के लिए सहेजी गई क्वेरीज़ से बना एक डैशबोर्ड।](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    Dashboard CRUD को वर्तमान Cloud CLI द्वारा उजागर नहीं किया गया है। CLI का उपयोग सहेजी गई क्वेरी बनाने और सत्यापित करने के लिए करें, फिर इसे UI में एक डैशबोर्ड में जोड़ें।

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

उपयोगी डैशबोर्ड समूहों में शामिल हैं:

- **Models:** volume, latency, token use, error rate, और evaluation scores।
- **Evaluations:** एजेंट या environment द्वारा success rate और score trends।
- **Tools:** call volume, failure rate, duration, और repeat calls।
- **Hooks and policies:** decisions, denials, और policy match rate।
- **Custom workflow metrics:** आपके स्वयं के event fields और SQL से परिणाम।

एक सहेजी गई क्वेरी के साथ शुरू करें, इसके परिणाम की पुष्टि करें, फिर इसे एक टाइल के रूप में जोड़ें। production और development फ़िल्टर को स्पष्ट रखें ताकि test traffic किसी regression को छिपा न दे।

<Tip>
  हर डैशबोर्ड को एक owner और एक response question दें, जैसे "क्या checkout-agent की विश्वसनीयता पिछले सप्ताह से बदतर है?"
</Tip>
