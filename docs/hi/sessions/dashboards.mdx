डैशबोर्ड सहेजी गई क्वेरीज़ को एक ऑपरेशनल व्यू में संयोजित करते हैं। किसी ऐसे निर्णय के आसपास एक बनाएँ जिसे आप किसी को लेने की अपेक्षा करते हैं—हर उपलब्ध मीट्रिक के आसपास नहीं।

## डैशबोर्ड बनाएँ

<Tabs>
  <Tab title="Dashboard">
    1. **Analyze → Queries** पर जाएँ, एक सहेजी गई क्वेरी बनाएँ या खोलें, और इसके परिणाम को सत्यापित करें।
    2. **add to dashboard** चुनें, फिर एक मौजूदा डैशबोर्ड चुनें या **Analyze → Dashboards** के तहत एक नया बनाएँ।
    3. डैशबोर्ड खोलें, संपादन मोड में प्रवेश करें, टाइल्स को व्यवस्थित करें, और लेआउट को सहेजें।
    4. जब आपको किसी टाइल के पीछे डेटा या फ़िल्टर को बदलने की आवश्यकता हो तो क्वेरी पर वापस जाएँ।

    ![ईवेंट वॉल्यूम, त्रुटियों, लेटेंसी और मॉडल टोकन उपयोग के लिए सहेजी गई क्वेरीज़ से बना एक डैशबोर्ड।](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    डैशबोर्ड CRUD वर्तमान Cloud CLI द्वारा उजागर नहीं किया गया है। सहेजी गई क्वेरी को बनाने और सत्यापित करने के लिए CLI का उपयोग करें, फिर इसे UI में एक डैशबोर्ड में जोड़ें।

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

उपयोगी डैशबोर्ड समूहों में शामिल हैं:

- **Models:** वॉल्यूम, लेटेंसी, टोकन उपयोग, त्रुटि दर, और मूल्यांकन स्कोर।
- **Evaluations:** एजेंट या परिवेश द्वारा सफलता दर और स्कोर रुझान।
- **Tools:** कॉल वॉल्यूम, विफलता दर, अवधि, और दोहराई गई कॉल।
- **Hooks and policies:** निर्णय, इनकार, और नीति मिलान दर।
- **Custom workflow metrics:** आपके स्वयं के ईवेंट फ़ील्ड और SQL से परिणाम।

एक सहेजी गई क्वेरी से शुरुआत करें, इसके परिणाम को सत्यापित करें, फिर इसे एक टाइल के रूप में जोड़ें। प्रोडक्शन और विकास फ़िल्टर को स्पष्ट रखें ताकि टेस्ट ट्रैफ़िक किसी प्रतिगमन को छिपा न दे।

<Tip>
  प्रत्येक डैशबोर्ड को एक मालिक और एक प्रतिक्रिया प्रश्न दें, जैसे "क्या checkout-agent की विश्वसनीयता पिछले हफ्ते से खराब है?"
</Tip>
