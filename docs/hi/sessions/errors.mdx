Errors आपको सत्रों में एक विफलता-प्रथम दृश्य प्रदान करता है। त्रुटि प्रकार, एजेंट, पर्यावरण, मॉडल, उपकरण, या समय विंडो द्वारा समूहीकृत करें ताकि बार-बार होने वाली परिचालन संबंधी समस्याओं को खोजा जा सके।

## त्रुटियों की जांच करें

<Tabs>
  <Tab title="Dashboard">
    1. **Observe → Errors** पर जाएँ।
    2. पर्यावरण, ईवेंट प्रकार, त्रुटि प्रकार, एजेंट, सत्र ID, या खोज पाठ के अनुसार फ़िल्टर करें।
    3. एक समूहीकृत त्रुटि को विस्तारित करें ताकि घटनाएँ देख सकें। किसी पंक्ति को चुनकर इसके सत्र में सटीक ईवेंट खोलें।
    4. किसी प्रतिनिधि त्रुटि पर घंटी नियंत्रण चुनकर समान त्रुटियों के लिए एक अलर्ट शुरू करें।

    ![त्रुटि पृष्ठ जो एक विफलता हिस्टोग्राम, समूहीकृत त्रुटियाँ, और अलर्ट बनाने के लिए नियंत्रण दिखाता है।](/images/dashboard/errors.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp errors --env production --since 24h
    fp errors --error-type TimeoutError --agent-id checkout-agent
    fp errors --aggregate --env production --since 7d
    ```

    जब आपको किसी त्रुटि सारांश के पीछे का कच्चा पेलोड चाहिए, तो `fp events --full --session-id <id>` का उपयोग करें।
  </Tab>
</Tabs>

## Errors का उपयोग करें जब आपको आवश्यकता हो

- उत्पादन में सबसे लगातार त्रुटि वर्ग खोजें।
- निर्धारित करें कि क्या एक उपकरण या मॉडल वृद्धि का कारण बनता है।
- एक कुल गणना से प्रतिनिधि सत्रों तक कूदें।
- पुनरावृत्ति के लिए एक अलर्ट बनाएँ।
- प्रभावित जनसंख्या को एक ऑडिट में शामिल करें।

एक त्रुटि एक देखी गई ईवेंट है। एक विफल मूल्यांकन एक गुणवत्ता निर्णय है, और एक ऑडिट खोज एक जांचा गया विफलता पैटर्न है। किस प्रतिक्रिया वर्कफ़्लो का उपयोग करना है यह तय करते समय उन अंतरों को ध्यान में रखें।
