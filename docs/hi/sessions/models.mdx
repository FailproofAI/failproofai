यह देखने के लिए मॉडल्स का उपयोग करें कि क्या किसी मॉडल, एजेंट, परिवेश या समय श्रेणी के साथ विश्वसनीयता या लागत बदली है।

<Tabs>
  <Tab title="Dashboard">
    1. **Observe → Models** पर जाएं।
    2. समय श्रेणी सेट करें, फिर परिवेश, मॉडल, एजेंट या सेशन ID के आधार पर फ़िल्टर करें।
    3. लेटेंसी, टोकन खपत, कॉन्टेक्स्ट-विंडो उपयोग और मॉडल वितरण की समीक्षा करें।
    4. चार्ट पॉइंट या वितरण खंड को चुनकर मिलान वाली घटनाओं को खोलें।

    ![मॉडल्स पेज जो लेटेंसी, पर्सेंटाइल, टोकन, लागत, कॉन्टेक्स्ट-विंडो और मॉडल-वितरण दृश्य दिखा रहा है।](/images/dashboard/models.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp list models
    fp events --event-type model_request,model_response --since 24h
    fp --json events --event-type model_response --since 24h --all --limit 500 --fields ts,agent_id,session_id,output_tokens,context_window,context_fill
    ```

    सभी तीन को `events:read` की आवश्यकता है।

    `--fields` कॉलम प्रोजेक्ट करता है; यह पंक्तियों को फ़िल्टर नहीं करता है। इसे `--event-type` और समय विंडो के साथ जोड़ी करें, अन्यथा आपको हर प्रकार की नवीनतम 50 घटनाएं मिलती हैं जिनमें `output_tokens` और `context_fill` सभी गैर-मॉडल वाली पर null होते हैं। `--all` `--limit` पर रुकता है, जो डिफ़ॉल्ट रूप से 50 है।

    `context_fill` को `context_window` के आगे पढ़ें: एक fill आंकड़ा इसे मापी गई विंडो के बिना कुछ नहीं है।

    डेमॉन प्रत्येक घटना को परिवेश `local` के साथ स्टैंप करता है जब तक कि आप इसे बदल न दें, इसलिए `--env production` स्टॉक इंस्टॉल पर कुछ भी मेल नहीं खाता है। देखें [एक परिवेश लेबल बदलें](/hi/reference/events-and-configuration#change-an-environment-label)।

## CLI क्या कर सकता है और क्या नहीं कर सकता है

डिफ़ॉल्ट इवेंट फीड पेलोड-मुक्त है। यह `output_tokens`, `context_window` और `context_fill` को प्रचारित कॉलम के रूप में ले जाता है, और एक मॉडल कॉल के बारे में कुछ नहीं:

| मान | यह कहां रहता है |
| --- | --- |
| आउटपुट टोकन, कॉन्टेक्स्ट विंडो, कॉन्टेक्स्ट fill | लाइट फीड कॉलम — `fp events` से सीधे उपलब्ध। |
| मॉडल नाम | पेलोड — `fp events --full` का उपयोग करें, एक सेशन तक सीमित। |
| इनपुट टोकन | पेलोड — SDK दोनों हिस्सों को रिकॉर्ड करता है, केवल आउटपुट हिस्सा प्रचारित होता है। |
| प्रति-कॉल लेटेंसी | लाइट फीड पर कोई `duration_ms` कॉलम नहीं, और SDK के `model_response` के पास भी कोई नहीं है। इसे अनुरोध को इसके प्रतिक्रिया के साथ जोड़कर व्युत्पन्न करें। |

`model_request` और `model_response` `request_id` पर जोड़ी जाती हैं। वह फील्ड ठीक इसलिए मौजूद है क्योंकि एक अनुरोध को इसके उत्तर से जोड़ा जा सकता है, और यह कच्ची घटनाओं से प्रति-कॉल लेटेंसी की गणना करने का एकमात्र तरीका है:

```bash
fp --json events --full --event-type model_request,model_response --session-id <session-id> --all --limit 500
```

मॉडल के नाम प्रत्येक हार्नेस के ट्रांसक्रिप्ट से शब्दशः आते हैं। कैप्चर पाथ में कुछ भी उन्हें सामान्य नहीं करता है, इसलिए एक अंतर्निहित मॉडल वितरण चार्ट में कई प्रदाता-विशिष्ट आइडी के तहत दिखाई दे सकता है। `fp list models` चलाएं यह देखने के लिए कि एक तैनाती के पास वास्तव में क्या स्पेलिंग हैं।

मॉडल-स्तरीय समग्र के लिए एक सहेजी गई क्वेरी का उपयोग करें जो समर्पित CLI कमांड के रूप में उजागर नहीं हैं।
