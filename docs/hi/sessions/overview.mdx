एक सेशन एक एजेंट रन है। यह प्रॉम्प्ट, मॉडल कॉल्स, टूल्स, त्रुटियों, मानव इनपुट, नीति निर्णयों और अंतिम परिणाम को जोड़ता है।

## सेशन कहाँ रहते हैं

<Tabs>
  <Tab title="Local">
    `failproofai` को चलाएँ ताकि डैशबोर्ड `http://localhost:8020` पर खुले। सेशन इतिहास इस मशीन पर रहता है।
  </Tab>
  <Tab title="Cloud">
    मशीन को कनेक्ट करें, फिर **Observe → Sessions** खोलें:

    ```bash
    export FAILPROOFAI_CLOUD_TOKEN="<key>"
    failproofai config
    ```

    क्लाउड डिफ़ॉल्ट रूप से पूर्ण ट्रांसक्रिप्ट प्राप्त करता है। केवल नीति निर्णय भेजने के लिए, पहले कनेक्ट करें, फिर `~/.failproofai/config.json` में `collector.sessions` को `false` पर सेट करें। वर्तमान `--no-transcripts` सेटअप फ्लैग उस सेटिंग को लागू नहीं करता है।
  </Tab>
</Tabs>

सेशन 12 समर्थित [एजेंट हार्नेसेस](/hi/reference/harnesses) से और [Python SDK](/hi/reference/custom-agents) के साथ इंस्ट्रूमेंटेड एजेंट्स से आते हैं।

## एक सेशन खोजें

क्लाउड में, समय, वातावरण, स्थिति, एजेंट या सेशन ID द्वारा फ़िल्टर करें। CLI से:

```bash
fp sessions --since 24h
fp sessions --status error,timeout --agent-id checkout-agent
fp --json sessions --session-id <session-id>
```

विफलताओं के लिए जिन्हें कभी मूल्यांकन नहीं किया गया, `fp errors --since 24h` का उपयोग करें। `fp sessions --status` नवीनतम मूल्यांकन परिणाम का उपयोग करता है, इसलिए एक अमूल्यांकित सेशन की कोई स्थिति नहीं होती है।

## एक रन पढ़ें

1. एजेंट के लक्ष्य और वातावरण की पुष्टि करें।
2. पहली त्रुटि या अप्रत्याशित निर्णय खोजें।
3. इसके तुरंत पहले मॉडल संदर्भ और टूल इनपुट का निरीक्षण करें।
4. पुनः प्रयास, विलंबता और मानव हस्तक्षेपों की जाँच करें।
5. मूल्यांकन और नीति निर्णयों की समीक्षा करें।

## यदि कोई सेशन लापता है

```bash
failproofai flush --wait
failproofai config --status
failproofai backfill --since 30d --dry-run
```

जब सेशन हार्नेस के सामान्य स्थान के बाहर रहते हैं, जैसे किसी अन्य प्रोफ़ाइल, कंटेनर होम या माउंटेड टीम निर्देशिका में, `failproofai harness add-path <harness> [<label>=]<path>` का उपयोग करें।
