एक सेशन सबसे अच्छा प्रारंभिक बिंदु है जब कोई एजेंट अप्रत्याशित रूप से व्यवहार करता है। यह एक रन से संबंधित मॉडल अनुरोध, प्रतिक्रियाएं, टूल कॉल, मानव इंटरैक्शन, त्रुटियां, मूल्यांकन और नीति निर्णयों को जोड़ता है।

सेशन वही दिखते हैं चाहे कोई भी हार्नेस उन्हें तैयार करे। Claude Code से रिपोजिटरी को फिर से लिखने वाला रन, Slack में एक ग्राहक का जवाब देने वाला Hermes एजेंट, और SDK से जुड़ी एक Python सेवा—सभी एक ही ट्रेस फॉर्मेट में आते हैं, इसलिए एक दृश्य पूरे फ्लीट को कवर करता है।

एक एजेंट रन को इसके लक्ष्य से मॉडल कॉल, टूल्स और अंतिम प्रतिक्रिया के माध्यम से ट्रैक करें।

## सेशन खोजें

यदि आप अपने रन भत्ते तक पहुंच गए हैं तो एक सेशन कोल्ड स्टोरेज में रखा गया था, उसी बिलिंग विंडो में भत्ते को बढ़ाने से पात्र सेशन सबसे पुराने को पहले रिलीज किए जाते हैं। डिलीवरी पुनः प्रयासी कोई सेशन को दो बार भत्ता उपभोग नहीं करते।

<Tabs>
  <Tab title="Dashboard">
    1. क्लाउड साइडबार में, **Observe → Sessions** पर जाएं।
    2. समय विंडो सेट करें, फिर वातावरण, स्थिति, एजेंट या सेशन ID द्वारा फ़िल्टर करें।
    3. जब आपको गुणवत्ता, लागत, टोकन या विलंबता स्लाइस की आवश्यकता हो तो स्कोर या मेट्रिक रेंज जोड़ें।
    4. ट्रेस खोलने के लिए कोई पंक्ति चुनें। सेशन ID के बगल में कॉपी नियंत्रण का उपयोग करें जब इसे साझा कर रहे हों।

## आप क्या कर सकते हैं

- एजेंट, वातावरण, समय, मॉडल, ईवेंट प्रकार या त्रुटि स्थिति द्वारा एक रन खोजें।
- सटीक अनुक्रम का पालन करें जिसने परिणाम का उत्पादन किया।
- सफल और विफल रनों की तुलना करें।
- ऑडिट खोज या सतर्क घटना द्वारा उपयोग किए गए साक्ष्य खोलें।
- जब आपको एक ऑफ़लाइन रिकॉर्ड की आवश्यकता हो तो एक सेशन निर्यात करें।

## एक विश्वसनीय जांच आदेश

1. सेशन लक्ष्य और वातावरण की पुष्टि करें।
2. पहली त्रुटि या अप्रत्याशित निर्णय खोजें—केवल अंतिम विफलता नहीं।
3. तुरंत पहले मॉडल संदर्भ और टूल इनपुट का निरीक्षण करें।
4. पुनः प्रयास, विलंबता और मानव हस्तक्षेप की जांच करें।
5. मूल्यांकन स्कोर और नीति निर्णयों की समीक्षा करें।
