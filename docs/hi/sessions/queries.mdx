प्रश्न डैशबोर्ड, ऑडिट और जांच के तहत लचीली परत हैं। किसी विचार का परीक्षण करने के लिए तदर्थ SQL का उपयोग करें, फिर जब यह एक आवर्ती वर्कफ़्लो का हिस्सा बन जाए तो प्रश्न को सहेजें।

## प्रश्न बनाएं और चलाएं

<Tabs>
  <Tab title="Dashboard">
    1. **Analyze → Queries** पर जाएं और **नया प्रश्न** चुनें।
    2. स्कीमा ब्राउज़र खोलें और घटना, सत्र या मूल्यांकन डेटा से फ़ील्ड चुनें।
    3. SQL लिखें, आवश्यकता होने पर पैरामीटर जोड़ें और प्रश्न चलाएं।
    4. इसे स्पष्ट नाम और विवरण के साथ सहेजें, फिर **डैशबोर्ड में जोड़ें** का उपयोग करें जब परिणाम की निगरानी की जानी चाहिए।

    प्रश्न संपादक घटना स्कीमा, SQL, पैरामीटर और एक परिणाम पूर्वावलोकन को जोड़ता है ताकि आप इसे सहेजने से पहले प्रश्न को मान्य कर सकें।

    ![स्कीमा ब्राउज़र और लाइव परिणाम ग्रिड के साथ SQL प्रश्न संपादक।](/images/dashboard/query-lab.png)

    सहेजे गए प्रश्न फिर साझा लाइब्रेरी में दिखाई देते हैं, जहां टीमके सदस्य उन्हें फिर से चला सकते हैं या उनके परिणामों को डैशबोर्ड में जोड़ सकते हैं।

    ![पुन: उपयोग योग्य बिल्ट-इन और कस्टम प्रश्नों वाली सहेजी गई प्रश्न लाइब्रेरी।](/images/dashboard/queries.png)

    स्पष्ट नाम और विवरण का उपयोग करें ताकि परिणाम अपने SQL को फिर से खोले बिना समझ में आ सके।
  </Tab>
  <Tab title="CLI">
    उस क्रम में काम करें जो SQL ही करता है: स्कीमा देखें, कथन को तदर्थ चलाएं, फिर एक बार नाम मिलने पर इसे सहेजें।

    ```bash
    fp query schema
    fp query schema events

    fp query run --sql "SELECT agent_id, count() FROM analytics.events GROUP BY agent_id"
    fp query run --sql @retry-loops.sql

    fp query create "retry loops" --sql @retry-loops.sql --description "repeated tool calls per session"
    ```

    इसके बाद सब कुछ प्रश्न के **नाम** को लेता है, id को नहीं:

    ```bash
    fp query list
    fp query run "retry loops"
    fp query show "retry loops"
    fp query update "retry loops" --sql @retry-loops-v2.sql --yes
    fp query delete "retry loops" --yes
    ```

    नाम प्रति संगठन अद्वितीय हैं, जो उन्हें एक सुरक्षित हैंडल बनाता है। UUID-आकार वाली id कहीं भी स्वीकार की जाती है जहां एक नाम है, लेकिन `fp query list` एक प्रिंट नहीं करता — इसके कॉलम `name`, `description`, `created by` और `created` हैं (जब प्रश्न बनाया गया था, संपादित नहीं)। एक छोटा id कॉलम के लिए `--show-id` जोड़ें, या `--json` पढ़ें, जो हमेशा पूर्ण id ले जाता है।

    `--arg` (उपनाम `--param`) के साथ एक सहेजे गए प्रश्न के स्थितीय पैरामीटर को बाइंड करें, क्रम में प्रत्येक `$1..$N` के लिए एक बार दोहराया गया:

    ```bash
    fp query run <query-name> --arg agent-codegen --arg 0.5
    ```

    | उप-कमांड | अनुमति | नोट्स |
    | --- | --- | --- |
    | `fp query schema [TABLE]` | `queries:read` | एक तालिका का नाम पास करें इसके कॉलम को फ़िल्टर करने के लिए। |
    | `fp query list` | `queries:read` | `--show-id` ids को प्रकट करता है; `--fields` कच्चे फ़ील्ड प्रोजेक्ट करता है। |
    | `fp query show <name>` | `queries:read` | मेटाडेटा कार्ड साथ ही पूर्ण SQL। |
    | `fp query create <name> --sql ...` | `queries:write` | एक नाम टकराव तुरंत अस्वीकार कर दिया जाता है। |
    | `fp query update <name>` | `queries:write` | कम से कम एक `--name`, `--sql`, `--description` पास करें। पहले पुष्टि करता है; एक no-op बिना सहेजे बाहर निकलता है। |
    | `fp query delete <name>` | `queries:delete` | पहले पुष्टि करता है, जो जाता है उसके पूर्वावलोकन के साथ। |
    | `fp query run <name>` या `--sql ...` | `queries:run` | दोनों में से बिल्कुल एक। `--limit` और `--all` तालिका पूर्वावलोकन को समायोजित करते हैं। |

    `update` और `delete` केवल एक इंटरैक्टिव टर्मिनल पर संकेत देते हैं। `--json` के तहत, या stdin को पुनः निर्देशित करने के साथ, वे बिना पूछे आगे बढ़ते हैं — तो `--yes` टर्मिनल केस के लिए है, स्क्रिप्ट के लिए नहीं।

    प्रश्न केवल-पढ़ने योग्य विश्लेषण पूल के खिलाफ चलते हैं। `--sql @file.sql` एक फ़ाइल से कथन पढ़ता है, जो संस्करण नियंत्रण में रखने के लायक रूप है।
  </Tab>
</Tabs>

## प्रश्न को स्क्रिप्ट करना

`fp --json query run` तालिका पूर्वावलोकन कैप की परवाह किए बिना प्रत्येक पंक्ति को `{columns: [{name, type}], rows: [[...]], truncated, elapsed_ms}` के रूप में आकार देता है:

```bash
fp --json query run "retry loops" | jq '.rows | length'
```

`fp --json query schema` `{schema, columns: [{table, column, type, nullable}]}` लौटाता है, जो स्कीमा ब्राउज़र का मशीन-पठनीय रूप है।

दो विफलताएं टेक्स्ट को पार्स करने के बजाय निकास कोड द्वारा संभालने के लायक हैं: एक नाम जिससे कुछ भी मेल नहीं खाता `✗ no query named "…"` प्रदान करता है और 6 से बाहर निकलता है, और एक SQL या निष्पादन त्रुटि `✗ query failed — …` प्रदान करता है जिसमें सर्वर का विवरण मुड़ा हुआ है।

## सामान्य उपयोग

- एक ही टूल में बार-बार कॉल के साथ सत्र खोजें।
- मॉडल या पर्यावरण के पार मूल्यांकन स्कोर की तुलना करें।
- मानव प्रतीक्षा और फिर से शुरू करने के बीच का समय मापें।
- नीति इनकार के बाद एक सफल विकल्प की पहचान करें।
- एक ऑडिट के लिए एक समूह बनाएं।

स्कीमा खोलें — डैशबोर्ड में **Analyze → Queries**, या `fp query schema` — अपरिचित फ़ील्ड के विरुद्ध लिखने से पहले। स्पष्ट समय और वातावरण फ़िल्टर पसंद करें, और अन्वेषण के दौरान परिणाम सीमाएं रखें।

<Warning>
  एक प्रश्न एक संदिग्ध पैटर्न की पहचान कर सकता है, लेकिन यह स्वयं से विफलता मोड स्थापित नहीं करता है। प्रतिनिधि ट्रेस खोलें या परिणाम को नीति में बदलने से पहले एक ऑडिट चलाएं।
</Warning>
