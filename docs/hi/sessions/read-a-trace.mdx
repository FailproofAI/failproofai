एक ट्रेस एक एजेंट रन की समय-सारणी है। पहली अप्रत्याशित घटना से शुरू करें, अंतिम त्रुटि से नहीं।

<Tabs>
  <Tab title="Dashboard">
    1. **Observe → Sessions** खोलें।
    2. एक सेशन चुनें।
    3. पहली त्रुटि, असामान्य टूल कॉल, लंबी प्रतीक्षा, या पॉलिसी निर्णय के लिए स्कैन करें।
    4. इवेंट खोलें और अनुरोध, प्रतिक्रिया, इनपुट और आउटपुट का निरीक्षण करें।

    ![एक सेशन विस्तृत दृश्य जिसमें इसके निष्पादन ग्राफ, इवेंट टाइमलाइन, मूल्यांकन पैनल, और टूल, मॉडल और हुक ब्रेकडाउन है।](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all --limit 5000
    fp --json events --full --session-id <session-id> --all --limit 2000
    ```

    `--full` का उपयोग केवल तब करें जब इवेंट सारांश में पर्याप्त साक्ष्य न हो। एक गैर-रिक्त `next_cursor` का अर्थ है कि सीमा अंत तक पहुंचने से पहले पहुंच गई।
  </Tab>
</Tabs>

## साक्ष्य का पालन करें

1. एजेंट, लक्ष्य, पर्यावरण और परिणाम की पुष्टि करें।
2. पहली त्रुटि या अप्रत्याशित निर्णय खोजें।
3. इसके तुरंत पहले के इवेंट का निरीक्षण करें।
4. अनुरोध और प्रतिक्रिया जोड़ियों में मिलान करने वाली आईडी का पालन करें।
5. साक्ष्य को एक ऑडिट, समस्या, या पॉलिसी में बदलें।

| जोड़ी | मिलान करने वाली फ़ील्ड |
| --- | --- |
| मॉडल अनुरोध और प्रतिक्रिया | `request_id` |
| टूल कॉल और परिणाम | `tool_call_id` |
| हुक शुरुआत और समापन | `hook_id` |
| एजेंट रुकना और फिर से शुरू करना | `pause_id` |
| मानव प्रतीक्षा और इनपुट | `input_id` |

एक निर्णय `hook_completed` पर दिखाई देता है। पंक्ति परिणाम और पॉलिसी स्रोत का नाम देती है। एक observe-mode निर्णय `failproofai_observed` में would-be निर्णय के साथ एक अनुमति के रूप में दिखाई देता है।

<Warning>
  लंबी सेशन अवधि हमेशा मॉडल विलंबता नहीं होती है। यह तय करने से पहले कि क्या ठीक करना है, मॉडल, टूल, हुक और मानव-प्रतीक्षा समय को अलग करें।
</Warning>
