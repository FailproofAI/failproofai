Failproof AI agents के कार्यों को record करता है और निर्णय लेता है कि वे क्या कर सकते हैं।

## Observe करें

| पद | अर्थ |
| --- | --- |
| Session | एक agent run |
| Event | एक session के अंदर एक कार्य |
| Trace | एक session का क्रमबद्ध दृश्य |
| Evaluation | एक स्कोर या निर्णय |
| Audit | कई sessions की समीक्षा |
| Finding | एक विफलता पैटर्न का प्रमाण |
| Issue | वह प्रतिक्रिया जिसका कोई स्वामित्व है |
| Alert | एक नियम जो पुनरावृत्ति को detect करता है |

## लागू करें

| पद | अर्थ |
| --- | --- |
| Harness | वह environment जहां एक agent चलता है |
| Hook | एक बिंदु जहां harness निर्णय के लिए पूछता है |
| Policy | एक नियम जो allow, guide, या block करता है |
| Policy pack | एक versioned policy set जिसे कोई भी install कर सकता है |
| Daemon | वह स्थानीय service जो policies का मूल्यांकन करती है |
| Deployment | एक मशीन को assign किए गए policies |

## कार्यप्रवाह

```text
Session → Audit → Finding → Issue → Policy
```

प्रमाण के साथ शुरू करें। दोहराई जाने वाली विफलता खोजें, प्रतिक्रिया assign करें, फिर इसे रोकें।

एक policy `allow`, `instruct`, या `deny` return करता है। `instruct` के माध्यम से guidance harness पर निर्भर करती है; जब कार्य रुकना चाहिए तो `deny` का उपयोग करें।

Observe mode निर्णय से अलग है। यह real policy को चलाता है और record करता है कि वह क्या करेगा जबकि agent को जारी रखने की अनुमति देता है।

<Warning>
  एक bare `fp fleet deploy <machine> --add <policy>` तुरंत लागू करता है। एक shadow rollout के लिए `:observe` जोड़ें।
</Warning>

Setup कोई policy pack नहीं चुनता है। इससे पहले कि आप एक जोड़ें, केवल `block-failproofai-commands` चलता है। compiled catalog में 9 categories में 39 policies हैं।

किसी भी agent environment में एक event को block करने की मान लेने से पहले [supported harnesses](/hi/reference/harnesses#enforcement-capability) देखें।
