| अवधारणा | इसका अर्थ | आप क्या प्राप्त कर सकते हैं |
| --- | --- | --- |
| Session | एक एजेंट कार्य या रन | किसी व्यक्तिगत परिणाम को पुनर्निर्मित करें |
| Event | सेशन में एक रिकॉर्ड की गई क्रिया | मॉडल कॉल, टूल उपयोग, त्रुटि, मानव क्रिया या नीति निर्णय का निरीक्षण करें |
| Trace | क्रमबद्ध और नेस्टेड सेशन दृश्य | डिस्कनेक्ट किए गए लॉग पढ़ने के बजाय कारणात्मकता को समझें |
| Evaluation | एक सेशन पर स्कोर या निर्णय | गुणवत्ता, अनुपालन, लागत या विलंबता को निरंतर ट्रैक करें |
| Audit | चयनित सेशन जनसंख्या की समीक्षा | एक निर्धारित लक्ष्य और गति के साथ विफलता पैटर्न खोजें |
| Finding | एक ऑडिट द्वारा खोजी गई साक्ष्य-समर्थित विफलता | विफलता मोड, गंभीरता और प्रभावित सेशन देखें |
| Issue | एक टिकाऊ प्रतिक्रिया रिकॉर्ड | किसी निष्कर्ष या सतर्कता घटना को असाइन, चर्चा और समाधान करें |
| Alert | एक नियम जो पुनरावृत्ति का पता लगाता है | जब कोई ज्ञात शर्त वापस आए तो प्रतिक्रिया देने वालों को सूचित करें |
| Policy | एजेंट गतिविधि के दौरान मूल्यांकन किया गया नियम | जोखिम भरे व्यवहार को देखें, ब्लॉक करें या पुनः निर्देशित करें |
| Deployment | मशीनों के लिए संस्करणयुक्त नीति रोलआउट | नीति को कहाँ चलाएं यह नियंत्रित करें और इसे सुरक्षित रूप से वापस रोल करें |

## विश्वसनीयता लूप

साक्ष्य से शुरू करें। एक सेशन दिखाता है कि क्या हुआ। एक ऑडिट यह निर्धारित करता है कि यह एक अलग गलती है या पैटर्न। एक निष्कर्ष विफलता मोड की पहचान करता है; एक issue प्रतिक्रिया का स्वामित्व रखता है। एक नीति समान व्यवहार को रोकता है, जबकि अलर्ट आपको बताते हैं कि यदि शर्त वापस आती है।

  एक स्थानीय `failproofai audit` स्थानीय एजेंट इतिहास को स्कैन करता है। एक आवर्ती क्लाउड ऑडिट Failproof AI Cloud में संग्रहीत सेशन की समीक्षा करता है। वे अलग-अलग वर्कफ़्लो हैं जिनके अलग-अलग दायरे और शेड्यूलिंग हैं।
