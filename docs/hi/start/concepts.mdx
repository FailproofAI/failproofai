| अवधारणा | इसका अर्थ | आप क्या हासिल कर सकते हैं |
| --- | --- | --- |
| Session | एक एजेंट कार्य या रन | किसी व्यक्तिगत परिणाम का पुनर्निर्माण करें |
| Event | एक सेशन में एक रिकॉर्ड की गई कार्रवाई | मॉडल कॉल, टूल उपयोग, त्रुटि, मानव कार्रवाई, या नीति निर्णय का निरीक्षण करें |
| Trace | क्रमबद्ध और नेस्टेड सेशन दृश्य | कारणता को समझें, न कि डिस्कनेक्ट किए गए लॉग को पढ़ें |
| Evaluation | किसी सेशन पर स्कोर या निर्णय | गुणवत्ता, अनुपालन, लागत, या विलंबता को लगातार ट्रैक करें |
| Audit | चयनित सेशन जनसंख्या की समीक्षा | एक विवरण और आवृत्ति के साथ विफलता पैटर्न खोजें |
| Finding | एक ऑडिट द्वारा खोजी गई साक्ष्य-समर्थित विफलता | विफलता मोड, गंभीरता, और प्रभावित सेशन देखें |
| Issue | एक टिकाऊ प्रतिक्रिया रिकॉर्ड | किसी खोज या सतर्कता घटना को असाइन, चर्चा और समाधान करें |
| Alert | एक नियम जो पुनरावृत्ति का पता लगाता है | जब कोई ज्ञात स्थिति वापस आए तो उत्तरदाताओं को सूचित करें |
| Policy | एजेंट गतिविधि के दौरान मूल्यांकन किया गया नियम | जोखिम भरे व्यवहार को देखें, अवरुद्ध करें, या पुनः निर्देशित करें |
| Deployment | मशीनों के लिए एक संस्करणित नीति रोलआउट | नियंत्रण करें कि नीति कहाँ चलती है और इसे सुरक्षित रूप से वापस करें |

## विश्वसनीयता लूप

साक्ष्य से शुरू करें। एक सेशन दिखाता है कि क्या हुआ। एक ऑडिट निर्धारित करता है कि यह एक अलग गलती है या एक पैटर्न। एक खोज विफलता मोड की पहचान करता है; एक मुद्दा प्रतिक्रिया का स्वामित्व रखता है। एक नीति समान व्यवहार को रोकती है, जबकि सतर्कताएं आपको बताती हैं कि क्या स्थिति वापस आती है।

  एक स्थानीय `failproofai audit` स्थानीय एजेंट इतिहास को स्कैन करता है। एक पुनरावर्ती क्लाउड ऑडिट Failproof AI Cloud में संग्रहीत सेशन की समीक्षा करता है। ये अलग-अलग वर्कफ़्लो हैं जिनके अलग-अलग दायरे और शेड्यूलिंग हैं।
