एक ऐसे व्यवहार से शुरू करें जिसे आप रोकना चाहते हैं और एक वैध कार्रवाई जो अभी भी काम करनी चाहिए।

## पहले एक समीक्षित नीति आज़माएं

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI में 39 समीक्षित नीतियां शामिल हैं। एक नई नीति लिखने से पहले [कैटलॉग](/hi/policies/builtin-catalog) देखें।

## अपनी खुद की लिखें और परीक्षा करें

<Steps>
  <Step title="एक कार्यशील नीति बनाएं">
    ```bash
    failproofai publish --init guards.mjs
    ```

    यह एक नीति लिखता है जो `git push --force` को ब्लॉक करती है। अपने नियम के लिए इसे संपादित करें।
  </Step>
  <Step title="इसे इस मशीन पर लागू करें">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    अपने एजेंट को ब्लॉक की गई कार्रवाई करने के लिए कहें, फिर स्थानीय डैशबोर्ड में **Policies → Activity** जांचें।
  </Step>
  <Step title="इसे रखें या हटाएं">
    इसे स्वचालित रूप से लोड करने के लिए `.failproofai/policies/` के अंतर्गत एक `*policies.mjs` फ़ाइल रखें।

    निम्न के साथ स्पष्ट कस्टम फ़ाइलों को हटाएं:

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## इसे साझा करें

एक सार्वजनिक पैक प्रकाशित करें:

```bash
failproofai publish
```

कोई भी इसे `failproofai policies add <owner>/<repo>` के साथ स्थापित कर सकता है। [Policy Hub](https://befailproof.ai/policy-hub/) इसे अनुक्रमित कर सके, इसके लिए स्वयं GitHub विषय `failproofai-policies` जोड़ें।

क्लाउड रोलआउट के लिए:

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  एक साधारण `--add checkout-guard` तुरंत लागू करता है। एजेंट को ब्लॉक किए बिना नीति क्या करेगी यह दर्ज करने के लिए `:observe` जोड़ें।
</Warning>

पूर्ण वर्कफ़्लो के लिए [एक पैक प्रकाशित करें](/hi/policies/publish-a-pack) या [नीतियां तैनात करें](/hi/policies/deploy) देखें।
