यह त्वरित शुरुआत एक मशीन को सेशन रिपोर्ट करने के लिए सेट अप करती है, एक ऑडिट चलाती है, और एक नीति तैनात करती है। Failproof AI को सेट अप करने के लिए स्किल का उपयोग करें, या मैनुअल चरणों का पालन करें।

**आपका पथ कौन सा है?** यदि आपका एजेंट 12 समर्थित [harnesses](/hi/reference/harnesses) में से किसी एक में चलता है — एक कोडिंग CLI, या Hermes या OpenClaw जैसा गेटवे — नीचे दिए गए चरणों का पालन करें; आपको Node.js 20.9 या बाद का संस्करण चाहिए। यदि आपके एजेंट के पास कोई harness नहीं है, तो इसे ट्रेसिंग और ऑडिट के लिए [Python SDK](/hi/reference/custom-agents) के साथ instrument करें, फिर [अपनी पहली विफलता जांच चलाएं](/hi/start/first-audit) पर फिर से शामिल हों; उस पथ पर प्रवर्तन के लिए आपके रनटाइम में एक hook की आवश्यकता है।

  <Tab title="मैनुअल सेटअप">
    ## स्थापित करें

<Steps>
  <Step title="Failproof AI स्थापित करें और कनेक्ट करें">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    वह एक कमांड पूरे सेटअप का है: यह स्थानीय daemon स्थापित करता है (एक बार root), हर एजेंट CLI में hooks जोड़ता है जो इसे मिलते हैं, और इस मशीन को Cloud से कनेक्ट करता है।

    **Cloud से कनेक्ट करें** पर, सेटअप तुरंत आपको FailproofAI Cloud में लॉगिन करना शुरू करता है (अन्य विकल्पों के लिए Tab दबाएं: एक API कुंजी पेस्ट करें, या ओपन सोर्स का उपयोग करें)। यह आपके ब्राउज़र में एक लिंक खोलता है (SSH पर, या बिना डिस्प्ले वाली मशीन पर, यह लिंक प्रिंट करता है ताकि आप इसे किसी भी डिवाइस पर खोल सकें)। साइन अप करें या साइन इन करें, संगठन की पुष्टि करें — या वहीं एक नया संगठन बनाएं — और **अधिकृत करें** पर क्लिक करें। कुंजी का नाम और अनुमतियां आपके लिए सेट की जाती हैं। आपको पहले से किसी खाते की आवश्यकता नहीं है।

    टर्मिनल अपने आप नोटिस करता है और दिखाता है कि किसने इसे अनुमोदित किया और किस संगठन के लिए। ट्रेस करने के लिए एजेंटों की पुष्टि करें, और सेटअप पूर्ण हो जाता है। मशीन की कुंजी केवल उस बिंदु पर बनाई जाती है, daemon स्थापित होने के बाद, इसलिए एक रन जिसे आप छोड़ देते हैं कोई कुंजी नहीं छोड़ता; यह **प्रशासन → कुंजियां** के अंतर्गत **cli login** के रूप में चिह्नित दिखाई देता है, जहां आप इसे रद्द कर सकते हैं।

    <Accordion title="कोई ब्राउज़र या टर्मिनल हाथ में नहीं? एक कुंजी का उपयोग करें (CI, कंटेनर, प्रावधान स्क्रिप्ट)">
      [Failproof AI डैशबोर्ड](https://app.befailproof.ai) में, **प्रशासन → कुंजियां** पर जाएं और `events:add` और `policies:pull` के साथ एक कुंजी बनाएं। यदि आप [FailproofAI Cloud के माध्यम से Jev](/hi/reference/jev-cloud) का उपयोग करने की योजना बनाते हैं, **machine** प्रीसेट चुनें, जो `jev:evaluate` भी प्रदान करता है। एकबारी रहस्य कॉपी करें और इसे लक्ष्य मशीन पर एक शेल में पढ़ें — `read -s` इसे एक प्रॉम्प्ट पर लेता है जो प्रतिध्वनि नहीं करता:

      ```bash
      read -rs FAILPROOFAI_KEY && export FAILPROOFAI_KEY
      FAILPROOFAI_CLOUD_TOKEN="$FAILPROOFAI_KEY" failproofai config
      ```

      `--token` के बजाय environment के माध्यम से कुंजी पास करना इसे `ps` से बाहर रखता है, जहां मशीन पर हर उपयोगकर्ता एक कमांड के तर्कों को पढ़ सकता है। यह इसे शेल history से बाहर नहीं रखता — `read -s` के साथ इसे पढ़ना वही है जो ऐसा करता है। CI में, इसे एक मास्क किए गए रहस्य के रूप में इंजेक्ट करें और शेल ट्रेसिंग (`set -x`) को बंद रखें, अन्यथा ट्रेस इसे प्रिंट करता है। एक इंटरैक्टिव रन में आप **Cloud से कनेक्ट करें** पर **एक API कुंजी पेस्ट करें** भी चुन सकते हैं।
    </Accordion>

    सेशन ट्रांसक्रिप्ट डिफ़ॉल्ट रूप से भेजे जाते हैं। ट्रांसक्रिप्ट सामग्री के बिना hook गतिविधि और नीति निर्णयों की रिपोर्ट करने के लिए `--no-transcripts` जोड़ें।

    <Warning>
      यहाँ `failproofai config --connect <url>` तक न पहुंचें। वह flag एक मशीन को enroll करता है जो **पहले से ही** सेट अप है और तुरंत वापस आता है — कोई daemon नहीं, कोई hooks नहीं — इसलिए मशीन Cloud में दिखाई देगी जबकि कुछ भी collect और enforce नहीं कर रही है।
    </Warning>

    यदि इस मशीन के पास पहले से एजेंट history है, तो अंतिम सात दिनों का पूर्वावलोकन और आयात करें, फिर delivery पूर्ण होने तक प्रतीक्षा करें। एक नई मशीन पर इस चरण को छोड़ें।

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    Failproof AI में **Sessions** खोलें और एक imported सेशन चुनें।
  </Step>
  <Step title="Failproof AI को एक harness से जोड़ें">
    पिछले चरण में पहले से ही हर एजेंट CLI को जोड़ा जा चुका है जो इसे मिला। जब आपको आवश्यकता हो तो एक harness के लिए इसे फिर से चलाएं, या बाद में स्थापित एक harness जोड़ने के लिए। 12 में से हर एक एक वैध `--cli` मान है — `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, `goose`।

    ```bash
    failproofai policies --install --cli claude --scope user     # एक कोडिंग CLI
    failproofai policies --install --cli hermes --scope user     # एक Slack/Telegram gateway
    ```

    किसी tool call को चलाने से पहले block करना सभी 12 पर सत्यापित है। Turn-end gates 8 पर सत्यापित हैं — प्रति-harness matrix के लिए [enforcement capability](/hi/reference/harnesses#enforcement-capability) देखें।
  </Step>
  <Step title="चुनें कि क्या enforce करना है">
    Hooks को जोड़ना कोई नीति enable नहीं करता। सेटअप जानबूझकर कोई नहीं चुनता — वह निर्णय आपका है — इसलिए एक पैक लें:

    ```bash
    failproofai policies add FailproofAI/policies
    ```

    पैक इसके GitHub release से प्राप्त किया जाता है, checksum-verified है, और सटीक tag पर pinned है जिसे यह resolve करता है। इसमें 39 नीतियां हैं और 10 को switch on करता है जिन्हें इसका manifest बिना निगरानी के enable करने के लिए safe के रूप में चिह्नित करता है। उन्हें local policy निर्णय देखने और Failproof AI आपके सेशन को audit करने और आपके एजेंटों के लिए नीतियां लिखने से पहले enforcement आजमाने के लिए उपयोग करें।

    किसी भी पैक को लेने से पहले `failproofai policies show <owner>/<repo>` के साथ पढ़ें, और एक का केवल भाग लेने के लिए [policy packs](/hi/policies/packs) देखें।

    जब तक यह चल नहीं जाता, तब तक केवल एक चीज enforce करती है `block-failproofai-commands` — always-on guard जो एक एजेंट को Failproof AI बंद करने से रोकता है। `failproofai policies` सूचीबद्ध करता है कि क्या on है।
  </Step>
  <Step title="व्यवहार को audit करें">
    [अपनी पहली विफलता जांच चलाएं](/hi/start/first-audit) का पालन करें। "उन सेशन खोजें जहां एजेंट ने एक विफल tool को उसके approach को बदले बिना retry किया" जैसे एक concrete लक्ष्य का उपयोग करें।
  </Step>
  <Step title="विफलता को रोकें">
    [एक नीति के साथ अपनी पहली विफलता को रोकें](/hi/start/first-policy) का पालन करें। observe mode में शुरू करें, matches की जांच करें, फिर reviewed संस्करण को enforce करें।
  </Step>
</Steps>

<Check>
  `failproofai config --status` चलाएं। एक स्वस्थ सेटअप cloud connection, daemon state, और enforcement को paused किया गया है या नहीं, रिपोर्ट करता है।
</Check>

## Jev सेटअप

समाप्त सेशन को ज्ञात उत्तरों के साथ एक प्रश्न के विरुद्ध स्कोर करने के लिए [Jev](/hi/start/use-jev) का उपयोग करें, या वे चलाने से पहले context में tool calls की समीक्षा करें। **Use Jev** पृष्ठ दोनों setup paths हैं।
