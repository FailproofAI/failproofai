Jev एजेंट रन के दो बिंदुओं पर मदद करता है: एक समाप्त सत्र को ज्ञात उत्तरों के साथ स्कोर करना, या आपने एजेंट से क्या करने के लिए कहा इसके संदर्भ में एक टूल कॉल की समीक्षा करना।

<Tabs>
  <Tab title="Jev evals">
    Jev eval का उपयोग करें जब एक समाप्त सत्र को कुछ ज्ञात उत्तरों वाले प्रश्न के साथ स्कोर किया जा सकता है, जैसे "क्या ग्राहक ने रिफंड के लिए कहा? हाँ या नहीं का उत्तर दें।" यह आपको सत्रों में पैटर्न खोजने में मदद करता है।

    ## eval बनाएँ

    Cloud डैशबोर्ड में, **Analyze → eval authoring → new eval** खोलें। एक निश्चित-उत्तर प्रश्न दर्ज करें, **draft** चुनें, और जांचें कि इसने एक classifier स्कोर चुना है। [इसे](/hi/evaluations/test) वास्तविक सत्रों पर परीक्षण करें, फिर इसे तैनात करें।

    ![साझा eval authoring फॉर्म जहाँ आप एक प्रश्न का वर्णन करते हैं, draft की समीक्षा करते हैं, और इसे तैनात करते हैं। यह स्क्रीनशॉट एक code draft दिखाता है; Jev के लिए एक निश्चित-उत्तर प्रश्न का उपयोग करें।](/images/dashboard/eval-authoring-draft.png)

    ## स्कोर पढ़ें

    एक नया सत्र पूरा होने के बाद, **Observe → Evaluations** खोलें या Cloud CLI का उपयोग करें:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI स्कोर पढ़ता है; Jev eval बनाना वर्तमान में डैशबोर्ड का उपयोग करता है। प्रश्न प्रकार और उदाहरणों के लिए [Jev evaluations](/hi/evaluations/jev) देखें।
  </Tab>
  <Tab title="Jev policies">
    Jev नीति समीक्षा का उपयोग करें जब एक स्ट्रिंग-मिलान नीति को यह तय करने के लिए आपके अनुरोध के संदर्भ की आवश्यकता हो कि टूल कॉल सुरक्षित है या नहीं। **observe** मोड में शुरू करें ताकि आप Jev के उत्तरों का निरीक्षण कर सकें जबकि आपकी स्थापित नीतियाँ अभी भी प्रत्येक कॉल का निर्णय लेती हैं।

    Jev की जाँचें एक पैक से आती हैं; Failproof AI कोई भी नहीं भेजता। जब तक आप उन्हें स्थापित नहीं करते, Jev कुछ नहीं पूछता, भले ही यह कॉन्फ़िगर किया गया हो:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Cloud Jev सेट करें

    Cloud डैशबोर्ड में, **Administration → Keys** खोलें और **machine** प्रीसेट के साथ एक कुंजी बनाएँ। [quickstart](/hi/start/quickstart) में दिखाए गए अनुसार इसे `failproofai config` के साथ उपयोग करें। एक मशीन पर जिसमें मौजूदा Jev कॉन्फ़िगरेशन नहीं है, यह Cloud Jev को observe मोड में सक्षम करता है। कनेक्शन को इसके साथ जांचें:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## अपने स्वयं के एंडपॉइंट का उपयोग करें

    स्थानीय डैशबोर्ड में, **Settings → Jev** खोलें। प्रदाता को चुनें, इसका टोकन पेस्ट करें, **observe** का चयन करें, और Jev को चालू करें।

    ![स्थानीय Jev सेटिंग्स पैनल जिसमें एक प्रदाता, टोकन फील्ड, और observe मोड चुना गया है।](/images/dashboard/jev-settings.png)

    या एक टर्मिनल से अपने एंडपॉइंट को कॉन्फ़िगर और परीक्षण करें:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    एक hooked एजेंट को `README.md` पर अपने फाइल-पढ़ने वाले टूल का उपयोग करने के लिए कहें। पुष्टि करें कि टूल कॉल सत्र में दिखाई देता है, फिर इसका निरीक्षण करें स्थानीय डैशबोर्ड में **Policies → Activity** के अंतर्गत। एक बार observe परिणाम सही दिखें, [Jev policies](/hi/policies/jev) समझाता है कि कब लागू करना है। प्रदाता विवरण और कॉन्फ़िगरेशन के लिए, [integration reference](/hi/reference/jev) देखें।
  </Tab>
