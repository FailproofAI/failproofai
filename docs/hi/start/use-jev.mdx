Jev एजेंट रन के दो बिंदुओं पर मदद करता है: एक समाप्त सत्र को ज्ञात उत्तरों के विरुद्ध स्कोर करें, या एजेंट से की गई अनुरोध के संदर्भ में एक टूल कॉल की समीक्षा करें।

<Tabs>
  <Tab title="Jev evals">
    Jev eval का उपयोग करें जब किसी समाप्त सत्र को कुछ ज्ञात उत्तरों वाले प्रश्न के विरुद्ध स्कोर किया जा सकता है, जैसे "क्या ग्राहक ने रिफंड के लिए कहा? हां या नहीं में उत्तर दें।" यह सत्रों में पैटर्न खोजने में मदद करता है।

    ## एक eval बनाएं

    Cloud डैशबोर्ड में, **Analyze → eval authoring → new eval** खोलें। एक निश्चित उत्तर वाला प्रश्न दर्ज करें, **draft** चुनें, और सत्यापित करें कि इसने एक classifier score चुना है। वास्तविक सत्रों पर इसे [परीक्षण](/hi/evaluations/test) करें, फिर इसे तैनात करें।

    ![साझा eval authoring फॉर्म जहां आप एक प्रश्न का वर्णन करते हैं, draft की समीक्षा करते हैं, और इसे तैनात करते हैं। यह स्क्रीनशॉट एक code draft दिखाता है; Jev के लिए निश्चित उत्तर वाले प्रश्न का उपयोग करें।](/images/dashboard/eval-authoring-draft.png)

    ## स्कोर पढ़ें

    एक नया सत्र पूरा होने के बाद, **Observe → Evaluations** खोलें या Cloud CLI का उपयोग करें:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI स्कोर पढ़ता है; Jev eval बनाना वर्तमान में डैशबोर्ड का उपयोग करता है। प्रश्न प्रकार और उदाहरणों के लिए [Jev evaluations](/hi/evaluations/jev) देखें।
  </Tab>
  <Tab title="Jev policies">
    Jev policy review का उपयोग करें जब एक string-matching policy को यह तय करने के लिए आपके अनुरोध के संदर्भ की आवश्यकता हो कि टूल कॉल सुरक्षित है या नहीं। **observe** मोड में शुरू करें ताकि आप Jev के उत्तरों का निरीक्षण कर सकें जबकि आपकी स्थापित नीतियां प्रत्येक कॉल का निर्णय लेती रहें।

    Jev की जांच एक पैक से आती हैं; Failproof AI कोई नहीं भेजता। जब तक आप उन्हें इंस्टॉल नहीं करते, Jev कुछ नहीं पूछता, भले ही यह कॉन्फ़िगर किया गया हो:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Cloud Jev सेट अप करें

    Cloud डैशबोर्ड में, **Administration → Keys** खोलें और **machine** प्रीसेट के साथ एक कुंजी बनाएं। [quickstart](/hi/start/quickstart) में दिखाए गए अनुसार इसे `failproofai config` के साथ उपयोग करें। एक मशीन पर जिसमें कोई मौजूदा Jev कॉन्फ़िगरेशन नहीं है, यह Cloud Jev को observe mode में सक्षम करता है। कनेक्शन की जांच करें:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## अपनी स्वयं की endpoint का उपयोग करें

    स्थानीय डैशबोर्ड में, **Settings → Jev** खोलें। प्रदाता चुनें, इसका टोकन पेस्ट करें, **observe** चुनें, और Jev को चालू करें।

    ![स्थानीय Jev सेटिंग्स पैनल एक प्रदाता, टोकन फ़ील्ड, और observe mode चुना हुआ है।](/images/dashboard/jev-settings.png)

    या अपनी endpoint को टर्मिनल से कॉन्फ़िगर और परीक्षण करें:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    एक hooked एजेंट को `README.md` पर अपने फ़ाइल-पठन टूल का उपयोग करने के लिए कहें। सत्यापित करें कि टूल कॉल सत्र में दिखाई देता है, फिर स्थानीय डैशबोर्ड में **Policies → Activity** के तहत इसका निरीक्षण करें। एक बार observe परिणाम सही दिखने लगें, [Jev policies](/hi/policies/jev) समझाता है कि कब लागू करना है। प्रदाता विवरण और कॉन्फ़िगरेशन के लिए, [integration reference](/hi/reference/jev) देखें।
  </Tab>
