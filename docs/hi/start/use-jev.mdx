Jev एजेंट रन में दो बिंदुओं पर मदद करता है: एक पूर्ण सत्र को ज्ञात उत्तरों के विरुद्ध स्कोर करें, या एजेंट से आपने जो मांगा है उसके संदर्भ में एक टूल कॉल की समीक्षा करें।

<Tabs>
  <Tab title="Jev evals">
    Jev eval का उपयोग करें जब एक पूर्ण सत्र को कुछ ज्ञात उत्तरों वाले प्रश्न के विरुद्ध स्कोर किया जा सकता है, जैसे "क्या ग्राहक ने रिफंड के लिए कहा? हां या नहीं में उत्तर दें।" यह आपको सत्रों में पैटर्न खोजने में मदद करता है।

    ## eval बनाएं

    Cloud डैशबोर्ड में, **Analyze → eval authoring → new eval** खोलें। एक निश्चित-उत्तर प्रश्न दर्ज करें, **draft** चुनें, और जांचें कि इसने एक क्लासिफायर स्कोर चुना है। वास्तविक सत्रों पर इसे [परीक्षण करें](/hi/evaluations/test), फिर इसे तैनात करें।

    ![साझा eval authoring फॉर्म जहां आप एक प्रश्न का वर्णन करते हैं, ड्राफ्ट की समीक्षा करते हैं, और इसे तैनात करते हैं। यह स्क्रीनशॉट एक कोड ड्राफ्ट दिखाता है; Jev के लिए एक निश्चित-उत्तर प्रश्न का उपयोग करें।](/images/dashboard/eval-authoring-draft.png)

    ## स्कोर पढ़ें

    एक नया सत्र पूरा होने के बाद, **Observe → Evaluations** खोलें या Cloud CLI का उपयोग करें:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI स्कोर पढ़ता है; Jev eval बनाना वर्तमान में डैशबोर्ड का उपयोग करता है। प्रश्न के प्रकार और उदाहरणों के लिए [Jev evaluations](/hi/evaluations/jev) देखें।
  </Tab>
  <Tab title="Jev policies">
    Jev नीति समीक्षा का उपयोग करें जब एक स्ट्रिंग-मिलान नीति को यह तय करने के लिए आपके अनुरोध के संदर्भ की आवश्यकता होती है कि टूल कॉल सुरक्षित है या नहीं। **observe** मोड में शुरू करें ताकि आप Jev के उत्तरों का निरीक्षण कर सकें जबकि आपकी स्थापित नीतियां अभी भी प्रत्येक कॉल पर निर्णय लेती हैं।

    Jev की जांचें एक पैक से आती हैं; Failproof AI कोई भी नहीं भेजता है। जब तक आप उन्हें स्थापित नहीं करते, Jev कुछ नहीं पूछता, भले ही यह कॉन्फ़िगर किया गया हो:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Cloud Jev सेट अप करें

    Cloud डैशबोर्ड में, **Administration → Keys** खोलें और **machine** प्रीसेट के साथ एक कुंजी बनाएं। इसे [quickstart](/hi/start/quickstart) में दिखाए गए अनुसार `failproofai config` के साथ उपयोग करें। मौजूदा Jev कॉन्फ़िगरेशन के बिना एक मशीन पर, यह Cloud Jev को observe मोड में सक्षम करता है। कनेक्शन की जांचें:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## अपना स्वयं का एंडपॉइंट उपयोग करें

    स्थानीय डैशबोर्ड में, **Settings → Jev** खोलें। प्रदाता चुनें, इसका टोकन पेस्ट करें, **observe** चुनें, और Jev को चालू करें।

    ![स्थानीय Jev सेटिंग्स पैनल जिसमें एक प्रदाता, टोकन फ़ील्ड, और observe मोड चयनित है।](/images/dashboard/jev-settings.png)

    या टर्मिनल से अपने एंडपॉइंट को कॉन्फ़िगर और परीक्षण करें:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    एक हुक किए गए एजेंट से कहें कि `README.md` पर अपने फ़ाइल-पढ़ने वाले टूल का उपयोग करे। पुष्टि करें कि टूल कॉल सत्र में दिखाई देता है, फिर स्थानीय डैशबोर्ड में **Policies → Activity** के तहत इसका निरीक्षण करें। एक बार observe परिणाम सही दिखें, [Jev policies](/hi/policies/jev) समझाता है कि कब लागू करें। प्रदाता विवरण और कॉन्फ़िगरेशन के लिए, [integration reference](/hi/reference/jev) देखें।
  </Tab>
