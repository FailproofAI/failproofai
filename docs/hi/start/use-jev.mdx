Jev एक एजेंट रन के दो बिंदुओं पर सहायता करता है: एक समाप्त सत्र को ज्ञात उत्तरों के विरुद्ध स्कोर करें, या आपने एजेंट को क्या करने के लिए कहा, इसके संदर्भ में एक टूल कॉल की समीक्षा करें।

<Tabs>
  <Tab title="Jev मूल्यांकन">
    Jev मूल्यांकन का उपयोग करें जब एक समाप्त सत्र को कुछ ज्ञात उत्तरों वाले प्रश्न के विरुद्ध स्कोर किया जा सकता है, जैसे "क्या ग्राहक ने रिफंड के लिए कहा? हां या नहीं का उत्तर दें।" यह आपको सत्रों में पैटर्न खोजने में मदद करता है।

    ## मूल्यांकन बनाएं

    Cloud डैशबोर्ड में, **analyse → checks → new check** (या **new evaluation**) खोलें। एक निश्चित-उत्तर प्रश्न का वर्णन करें, इसके द्वारा तैयार किए गए नियम की समीक्षा करें, और जांचें कि **यह कैसे जांच करता है** यह **निर्णय मॉडल** है — वह Jev है। इसे [वास्तविक सत्रों पर परीक्षण करें](/hi/evaluations/test), फिर इसे चालू करें।

    ![साझा किया गया मूल्यांकन लेखन फॉर्म जहां आप एक प्रश्न का वर्णन करते हैं, ड्राफ्ट की समीक्षा करते हैं, और इसे तैनात करते हैं। यह स्क्रीनशॉट एक कोड ड्राफ्ट दिखाता है; Jev के लिए निश्चित-उत्तर प्रश्न का उपयोग करें।](/images/dashboard/eval-authoring-draft.png)

    ## स्कोर पढ़ें

    एक नया सत्र पूरा होने के बाद, **analyse → checks → evals** खोलें और मूल्यांकन का चयन करें, या Cloud CLI का उपयोग करें:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI स्कोर पढ़ता है; Jev मूल्यांकन बनाना वर्तमान में डैशबोर्ड का उपयोग करता है। प्रश्न प्रकारों और उदाहरणों के लिए [Jev मूल्यांकन](/hi/evaluations/jev) देखें।
  </Tab>
  <Tab title="Jev नीतियां">
    Jev नीति समीक्षा का उपयोग करें जब एक स्ट्रिंग-मिलान नीति को यह तय करने के लिए आपके अनुरोध के संदर्भ की आवश्यकता हो कि टूल कॉल सुरक्षित है या नहीं। **observe** मोड में शुरू करें ताकि आप Jev के उत्तरों का निरीक्षण कर सकें जबकि आपकी स्थापित नीतियां अभी भी प्रत्येक कॉल को निर्धारित करें।

    Jev की जांचें एक पैक से आते हैं; Failproof AI कोई नहीं भेजता। जब तक आप उन्हें स्थापित नहीं करते, Jev कुछ नहीं पूछता, भले ही यह कॉन्फ़िगर किया हो:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Cloud Jev सेट करें

    Cloud डैशबोर्ड में, **settings → api keys** खोलें और **new key** के तहत, **a machine running failproofai** चुनें। इसे [त्वरित प्रारंभ](/hi/start/quickstart) में दिखाए गए `failproofai config` के साथ उपयोग करें। मौजूदा Jev कॉन्फ़िगरेशन के बिना एक मशीन पर, यह observe मोड में Cloud Jev को सक्षम करता है। कनेक्शन को इससे जांचें:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## अपना स्वयं का एंडपॉइंट उपयोग करें

    स्थानीय डैशबोर्ड में, **Settings → Jev** खोलें। प्रदाता का चयन करें, उसका टोकन चिपकाएं, **observe** का चयन करें, और Jev को चालू करें।

    ![स्थानीय Jev सेटिंग्स पैनल प्रदाता, टोकन फील्ड और observe मोड का चयन किया हुआ है।](/images/dashboard/jev-settings.png)

    या अपने एंडपॉइंट को एक टर्मिनल से कॉन्फ़िगर और परीक्षण करें:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    एक हुक किए गए एजेंट को `README.md` पर अपने फाइल-पढ़ने वाले टूल का उपयोग करने के लिए कहें। पुष्टि करें कि टूल कॉल सत्र में दिखाई देता है, फिर स्थानीय डैशबोर्ड में **Policies → Activity** के तहत इसका निरीक्षण करें। एक बार observe परिणाम सही दिखने लगें, [Jev नीतियां](/hi/policies/jev) समझाती हैं कि कब लागू करें। प्रदाता विवरण और कॉन्फ़िगरेशन के लिए, [एकीकरण संदर्भ](/hi/reference/jev) देखें।
  </Tab>
