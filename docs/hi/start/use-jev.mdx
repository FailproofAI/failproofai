Jev एजेंट रन के दो बिंदुओं पर मदद करता है: एक समाप्त सेशन को ज्ञात उत्तरों के विरुद्ध स्कोर करें, या टूल कॉल की समीक्षा करें कि आपने एजेंट से क्या करने के लिए कहा था।

<Tabs>
  <Tab title="Jev evals">
    Jev eval का उपयोग करें जब एक समाप्त सेशन को कुछ ज्ञात उत्तरों के साथ एक प्रश्न के विरुद्ध स्कोर किया जा सकता है, जैसे "क्या ग्राहक ने रिफंड मांगा? हां या नहीं का उत्तर दें।" यह आपको सेशन में पैटर्न खोजने में मदद करता है।

    ## एक eval बनाएं

    Cloud डैशबोर्ड में, **Analyze → eval authoring → new eval** खोलें। एक निश्चित-उत्तर प्रश्न दर्ज करें, **draft** का चयन करें, और जांचें कि इसने एक classifier score चुना है। [इसे परीक्षण करें](/hi/evaluations/test) वास्तविक सेशन पर, फिर इसे तैनात करें।

    ![साझा eval authoring फॉर्म जहां आप एक प्रश्न का वर्णन करते हैं, ड्राफ्ट की समीक्षा करते हैं, और इसे तैनात करते हैं। यह स्क्रीनशॉट एक कोड ड्राफ्ट दिखाता है; Jev के लिए निश्चित-उत्तर प्रश्न का उपयोग करें।](/images/dashboard/eval-authoring-draft.png)

    ## स्कोर पढ़ें

    एक नया सेशन पूरा होने के बाद, **Observe → Evaluations** खोलें या Cloud CLI का उपयोग करें:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI स्कोर पढ़ता है; Jev eval बनाना वर्तमान में डैशबोर्ड का उपयोग करता है। प्रश्न प्रकार और उदाहरणों के लिए [Jev evaluations](/hi/evaluations/jev) देखें।
  </Tab>
  <Tab title="Jev policies">
    Jev policy समीक्षा का उपयोग करें जब एक स्ट्रिंग-मैचिंग नीति को यह तय करने के लिए आपके अनुरोध का संदर्भ चाहिए कि एक टूल कॉल सुरक्षित है या नहीं। **observe** मोड में शुरू करें ताकि आप Jev के उत्तरों का निरीक्षण कर सकें जबकि आपकी स्थापित नीतियां अभी भी प्रत्येक कॉल का निर्णय लेती हैं।

    Jev की जांचें एक पैक से आती हैं; Failproof AI कोई नहीं भेजता है। जब तक आप उन्हें स्थापित नहीं करते, Jev कुछ नहीं पूछता, यहां तक कि जब इसे कॉन्फ़िगर किया गया हो:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Cloud Jev सेट करें

    Cloud डैशबोर्ड में, **Administration → Keys** खोलें और **machine** प्रीसेट के साथ एक कुंजी बनाएं। इसे `failproofai config` के साथ उपयोग करें जैसा [quickstart](/hi/start/quickstart) में दिखाया गया है। एक मशीन पर जिसमें कोई मौजूदा Jev कॉन्फ़िगरेशन नहीं है, यह Cloud Jev को observe मोड में सक्षम करता है। इससे कनेक्शन की जांच करें:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## अपना स्वयं का एंडपॉइंट उपयोग करें

    स्थानीय डैशबोर्ड में, **Settings → Jev** खोलें। प्रदाता चुनें, इसका टोकन पेस्ट करें, **observe** का चयन करें, और Jev को चालू करें।

    ![स्थानीय Jev सेटिंग्स पैनल जिसमें एक प्रदाता, टोकन फील्ड, और observe मोड चयनित है।](/images/dashboard/jev-settings.png)

    या अपने एंडपॉइंट को टर्मिनल से कॉन्फ़िगर और परीक्षण करें:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    एक hooked एजेंट से अपने file-reading टूल को `README.md` पर उपयोग करने के लिए कहें। पुष्टि करें कि वह टूल कॉल सेशन में दिखाई देता है, फिर स्थानीय डैशबोर्ड में **Policies → Activity** के तहत इसका निरीक्षण करें। एक बार observe परिणाम सही दिखने लगें, [Jev policies](/hi/policies/jev) समझाता है कि कब प्रवर्तित करें। प्रदाता विवरण और कॉन्फ़िगरेशन के लिए, [integration reference](/hi/reference/jev) देखें।
  </Tab>
