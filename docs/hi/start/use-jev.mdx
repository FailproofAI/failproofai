Jev एक एजेंट रन के दो बिंदुओं पर मदद करता है: एक समाप्त सेशन को ज्ञात उत्तरों के विरुद्ध स्कोर करें, या आपने एजेंट को क्या करने के लिए कहा था इसके संदर्भ में एक टूल कॉल की समीक्षा करें।

<Tabs>
  <Tab title="Jev evals">
    Jev eval का उपयोग करें जब एक समाप्त सेशन को कुछ ज्ञात उत्तरों वाले प्रश्न के विरुद्ध स्कोर किया जा सकता है, जैसे कि हां या नहीं उत्तर दें। यह आपको सेशन के पार पैटर्न खोजने में मदद करता है।

    ## एक eval बनाएं

    Cloud डैशबोर्ड में, **Analyze → eval authoring → new eval** खोलें। एक निश्चित-उत्तर प्रश्न दर्ज करें, **draft** चुनें, और जांचें कि इसने एक classifier स्कोर चुना है। वास्तविक सेशन पर [इसे टेस्ट करें](/hi/evaluations/test), फिर इसे तैनात करें।

    ![साझा eval authoring फॉर्म जहां आप एक प्रश्न का वर्णन करते हैं, draft की समीक्षा करते हैं, और इसे तैनात करते हैं। यह स्क्रीनशॉट एक code draft दिखाता है; Jev के लिए एक निश्चित-उत्तर प्रश्न का उपयोग करें।](/images/dashboard/eval-authoring-draft.png)

    ## स्कोर पढ़ें

    एक नया सेशन पूरा होने के बाद, **Observe → Evaluations** खोलें या Cloud CLI का उपयोग करें:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI स्कोर पढ़ता है; Jev eval बनाना वर्तमान में डैशबोर्ड का उपयोग करता है। प्रश्न प्रकार और उदाहरणों के लिए [Jev evaluations](/hi/evaluations/jev) देखें।
  </Tab>
  <Tab title="Jev policies">
    Jev policy समीक्षा का उपयोग करें जब एक string-matching policy को यह तय करने के लिए आपके अनुरोध के संदर्भ की आवश्यकता होती है कि क्या एक टूल कॉल सुरक्षित है। **observe** मोड में शुरू करें ताकि आप Jev के उत्तरों का निरीक्षण कर सकें जबकि आपकी स्थापित नीतियां प्रत्येक कॉल को तय करती रहें।

    Jev की जांच एक pack से आती है; Failproof AI कोई भी शिप नहीं करता। जब तक आप उन्हें स्थापित नहीं करते, Jev कुछ नहीं पूछता, भले ही इसे कॉन्फ़िगर किया गया हो:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Cloud Jev सेट अप करें

    Cloud डैशबोर्ड में, **Administration → Keys** खोलें और **machine** प्रीसेट के साथ एक कुंजी बनाएं। इसे [quickstart](/hi/start/quickstart) में दिखाए अनुसार `failproofai config` के साथ उपयोग करें। एक मशीन पर बिना किसी मौजूदा Jev कॉन्फ़िगरेशन के, यह observe मोड में Cloud Jev को सक्षम करता है। कनेक्शन की जांच करें:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## अपना खुद का endpoint उपयोग करें

    स्थानीय डैशबोर्ड में, **Settings → Jev** खोलें। प्रदाता चुनें, इसका token पेस्ट करें, **observe** चुनें, और Jev को चालू करें।

    ![स्थानीय Jev settings panel एक प्रदाता, token फील्ड, और observe मोड चयनित के साथ।](/images/dashboard/jev-settings.png)

    या अपने endpoint को एक terminal से कॉन्फ़िगर और टेस्ट करें:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    एक hooked एजेंट को `README.md` पर अपने file-reading टूल का उपयोग करने के लिए कहें। पुष्टि करें कि टूल कॉल सेशन में दिखाई देता है, फिर इसे स्थानीय डैशबोर्ड में **Policies → Activity** के अंतर्गत निरीक्षण करें। एक बार observe परिणाम सही दिखें, [Jev policies](/hi/policies/jev) बताता है कि कब enforce करना है। प्रदाता विवरण और कॉन्फ़िगरेशन के लिए, [integration reference](/hi/reference/jev) देखें।
  </Tab>
