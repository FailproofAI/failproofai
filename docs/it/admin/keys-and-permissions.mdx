Usa una chiave separata per ogni persona, macchina o job di automazione. Concedi solo le autorizzazioni di cui ha bisogno.

## Crea e ruota una chiave

Usa **Admin → Keys**, oppure la Cloud CLI:

```bash
fp keys list
fp keys create "audit automation" --add audits:read
fp keys disable "audit automation"
```

Memorizza il segreto quando viene creato; non verrà più visualizzato. Ruota creando una sostituzione, aggiornando il consumer, quindi disabilitando la vecchia chiave.

## Chiavi macchina

Una chiave macchina connette il servizio locale a Cloud:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Una macchina connessa potrebbe aver bisogno di due capacità:

- `policies:pull` per ricevere le policy gestite da Cloud.
- `events:add` per inviare decisioni e sessioni.

Lo stato riporta questi separatamente perché uno potrebbe funzionare mentre l'altro no.

## Autorizzazioni comuni

| Autorizzazione | Consente |
| --- | --- |
| `events:add` | Inviare eventi |
| `events:read` | Leggere eventi e errori |
| `evaluations:read` | Leggere sessioni e valutazioni |
| `audits:read` / `audits:write` | Rivedere o gestire audit |
| `policies:read` / `policies:write` | Rivedere o distribuire policy |
| `policies:pull` | Richiamare assegnazioni policy per la macchina |
| `keys:create` / `keys:disable` | Creare o disabilitare chiavi |
| `orgs:admin` | Amministrazione organizzazione a livello di istanza; non assegnabile a una chiave organizzativa |

Alcuni comandi amministrativi `fp fleet` e `fp guardrails` richiedono una sessione utente autenticata anziché una chiave API. Il loro testo di aiuto lo indica prima di effettuare una richiesta.

<Warning>
  Non riutilizzare mai credenziali di acquisizione come `AGENTEYE_KEY` o `AGENTEYE_API_KEY` come `FP_API_KEY`. Servono sistemi e autorizzazioni diversi.
</Warning>
