L'amministrazione è la metà Cloud di Failproof AI. Organizzazioni, membri, chiavi API, impostazioni dell'organizzazione e il consumo misurato richiedono tutti una connessione Cloud.

<Note>
  Failproof AI funziona anche senza alcun account. Una macchina locale applica la policy, mantiene la cronologia della sessione su disco, serve la [dashboard locale](/it/reference/local-dashboard) su `localhost:8020` e esegue `failproofai audit` senza inviare nulla da nessuna parte. Vedi [configurazione della macchina](/it/reference/events-and-configuration#machine-configuration) per le chiavi locali di `collector`. Salta il resto di questa sezione se non stai utilizzando il Cloud.
</Note>

## Dove si trovano i controlli

<Tabs>
  <Tab title="Dashboard">
    Il gruppo **admin** della barra laterale Cloud contiene **editor delle policy**, **applicazione**, **utilizzo**, **chiavi**, **utenti** e **impostazioni**.

    ![Il gruppo admin della barra laterale Cloud con editor delle policy, applicazione, utilizzo, chiavi, utenti e impostazioni.](/images/dashboard/admin-navigation.png)
  </Tab>
  <Tab title="CLI">
    Installa la Cloud CLI come strumento isolato, quindi accedi:

    ```bash
    uv tool install fp-cloud-cli
    fp login
    fp whoami
    fp usage
    ```

    Metti le opzioni globali prima del comando, ad esempio `fp --org reliability-team --json usage`.
  </Tab>
</Tabs>

## Umano connesso o chiave API

`fp` viene eseguito in una delle due modalità di autenticazione, e la divisione determina quali comandi funzionano. Un comando che una chiave API non può eseguire rifiuta prima di aprire una connessione e indica il motivo, piuttosto che lasciare che un 401 o un 403 lo rappresentino.

| Comando | Chiave API | Permesso |
| --- | --- | --- |
| `fp whoami` | Sì | nessuno |
| `fp usage` | Sì | `usage:read` |
| `fp keys list` / `show` | Sì | `keys:read` |
| `fp keys create` | Sì | `keys:create` |
| `fp keys disable` | Sì | `keys:disable` |
| `fp keys regenerate` | Sì | `keys:regenerate` |
| `fp keys update` | No | `keys:update`, che nessuna chiave può possedere |
| `fp users list` / `show` | Sì | `users:read` |
| `fp users create` | Sì | `users:create` |
| `fp users update` | Sì | `users:update` |
| `fp users disable` / `enable` | Sì | `users:delete` |
| `fp settings list` / `schema` | Sì | `settings:read` |
| `fp settings set` | Sì | `settings:write` |
| `fp orgs list` / `switch` / `current` / `perms` | No | solo sessione connessa |

`fp usage` è il comando da fornire a uno script di reporting: viene eseguito incustodito sotto una chiave e richiede solo `usage:read`.
