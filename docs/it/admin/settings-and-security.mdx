Le impostazioni dell'organizzazione interessano tutti gli utenti di quell'organizzazione Cloud. Modificale da **Admin → settings** o con `fp settings`.

```bash
fp settings list
fp settings set <key> <value>
```

## Gestione dei dati

Una macchina connessa invia per impostazione predefinita le decisioni relative alle policy e le trascrizioni complete della sessione. Per inviare solo le decisioni, imposta `collector.sessions` a `false` nel file `~/.failproofai/config.json` della macchina dopo la connessione. Il flag di configurazione `--no-transcripts` attuale non applica questa impostazione.

Le credenziali vengono cancellate sulla macchina prima del caricamento, ma la redazione è un livello di sicurezza minimo, non un sostituto del controllo degli accessi.

L'uso locale non richiede alcun account. La cronologia delle sessioni e i controlli rimangono sulla macchina, eccetto i controlli locali pianificati che inviano l'identità della macchina e un digest limitato dopo che hai dato il consenso. La telemetria CLI anonima può essere disabilitata con `FAILPROOFAI_TELEMETRY_DISABLED=1`.

## Credenziali

I token della macchina vengono archiviati in `~/.failproofai/` con autorizzazioni solo per il proprietario. Non vengono scritti nella definizione del servizio.

Utilizza chiavi separate per persone, automazione e macchine. Concedi a ciascuna solo i permessi di cui ha bisogno, ruotala quando cambia la proprietà e revocala quando la macchina o il flusso di lavoro viene ritirato.

## Checklist

- Richiedi i permessi utili più ristretti.
- Imposta `collector.sessions` a `false` dove il contenuto completo non è necessario.
- Controlla chi può distribuire policy di applicazione.
- Prova le policy in modalità osservazione prima dell'applicazione.
- Mantieni le etichette della macchina chiare e gli ID della macchina stabili.
- Esegui `failproofai config --status` dopo aver modificato le impostazioni di connessione.

Vedi [keys and permissions](/it/admin/keys-and-permissions) per il catalogo delle autorizzazioni.
