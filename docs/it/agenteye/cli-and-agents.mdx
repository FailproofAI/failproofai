L'intera distribuzione Failproof AI Observability, a un solo comando di distanza. Controlla la produzione, genera una chiave API, o riconosci un incidente senza lasciare il terminale, quindi automatizza qualsiasi cosa in CI, o lascia che un coding agent lo faccia per te in linguaggio naturale.

```bash
pipx install agenteye
agenteye login --email you@example.com      # a 6-digit code lands in your inbox
agenteye --json sessions --since 24h         # every agent run from the last day, newest first
```

*La CLI `agenteye` comunica con la tua dashboard. È uno strumento diverso dal collector, che invia gli eventi al server.*

## L'intera distribuzione, un comando a distanza

Smetti di saltare tra schede per rispondere a una domanda veloce. La CLI `agenteye` legge i tuoi dati e amministra la tua organizzazione da un unico binario, quindi un controllo che prima significava navigare nella dashboard diventa una sola linea che puoi rieseguire, aliasare, o incollare in un runbook. Hai a disposizione quattro superfici:

- **Leggi i tuoi dati:** `sessions`, `events`, `evals`, e `errors`, filtrati per tempo, agent e ambiente.
- **Gestisci la tua organizzazione:** `keys`, `users`, `settings`, `alerts`, e `incidents`.
- **Esegui analitiche:** SQL salvati più un runner `query` ad hoc sui tuoi dati di eventi.
- **Chiedi all'assistente:** `agent ask` raggiunge lo stesso analista di sola lettura con cui chatti nella dashboard.

Installalo una volta con `pipx`, accedi con un codice di 6 cifre ricevuto via email, e sei pronto. La sessione dura circa un giorno; riesegui `agenteye login` quando scade. Usalo per controllare rapidamente la produzione, provisioning di una chiave, o triage di un incidente in corso, tutto senza aprire un browser:

```bash
agenteye errors --since 24h --aggregate      # what is breaking, grouped by error type
agenteye incidents list --state firing       # what is on fire right now
agenteye keys create ci --add events:add     # a key that can only push events, secret shown once
```

Un'abitudine da conoscere: le opzioni globali come `--json` vanno prima del comando. `agenteye --json sessions` è corretto; `agenteye sessions --json` non lo è.

## Automatizzalo, integralo in CI

Ogni comando accetta `--json`, e questo cambia tutto. JSON pulito va a stdout mentre lo stato umano e gli avvisi vanno a stderr, quindi una cattura `--json` va dritta in `jq` senza alcuna linea da eliminare. Questo è ciò che rende la CLI ugualmente buona per te al prompt e per un coding agent che analizza l'output:

```bash
agenteye --json sessions --since 24h --status error | jq -r '.sessions[].session_id'
```

È costruita per funzionare in background. I prompt di conferma vengono saltati automaticamente quando nessun terminale è collegato, quindi nulla rimane sospeso in una pipeline, e ogni comando restituisce un exit code significativo: `0` successo, `4` non connesso, `5` permesso mancante (il messaggio lo nomina, ad esempio `alerts:write`), `3` dashboard non raggiungibile. Uno script può ramificarsi su un `4` per riauthenticarsi o su un `5` per dirti esattamente cosa chiedere a un amministratore, invece di fallire al buio.

## Lascia che un coding agent lo gestisca in linguaggio naturale

Ancora meglio, non dovresti nemmeno ricordare alcuno di questi flag. La **CLI skill** è una piccola cartella Agent Skill chiamata `agenteye-cli` che insegna a un coding agent come Claude Code o Codex a gestire la CLI da richieste in linguaggio naturale. Chiedi "c'è qualcosa di rotto oggi?" e l'agent sceglie il comando, lo esegue come te, e risponde in prosa.

Per Claude Code, basta mettere la cartella `agenteye-cli` in `~/.claude/skills/` e viene scoperta automaticamente. Failproof AI Observability fornisce la cartella; non c'è nulla di extra da installare, perché gestisce solo la CLI che hai già installato. Accedi tu stesso prima: la skill non può completare il login con il codice ricevuto via email per te.

Poiché l'agent esegue la CLI come te, può fare tutto ciò che il tuo login consente, letture e scritture: creare chiavi, modificare impostazioni, risolvere incidenti. Il prompt "sei sicuro?" della CLI non viene visualizzato per un agent, quindi la skill è scritta per indicare il comando esatto e aspettare il tuo OK prima di qualsiasi modifica. Tu sei il passo di conferma.

```text
tu    Perché la sessione run-001 ha fallito?

agent  Running: agenteye --json events --session-id run-001 --all
       L'checkout-agent ha colpito un TimeoutError nella sua terza tool call.
```

Le letture rimangono istantanee, e ogni scrittura si ferma per te:

```text
tu    Dai a CI una chiave che può solo spingere eventi.

agent  This creates an API key. I'll run:
         agenteye keys create ci --add events:add
       OK to proceed?

tu    yes

agent  Done. Key "ci" created with events:add only. The secret is shown once, so store it now.
```
