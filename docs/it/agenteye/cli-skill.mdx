Chiedi al tuo agente di codifica *"è successo qualcosa di grave oggi?"* e lascia che risponda dai tuoi dati Failproof AI Observability live, senza comandi da memorizzare. La **Failproof AI Observability CLI skill** (`agenteye-cli`) è una *Agent Skill*: una piccola cartella di istruzioni che un agente di codifica come Claude Code o Codex carica su richiesta. Insegna all'agente come operare il tuo deployment di Observability attraverso la [`agenteye` CLI](/it/agenteye/cli) partendo da richieste in linguaggio naturale come *"dai a CI una chiave che può solo inviare eventi"* o *"riconosci l'incident in corso e assegnalo a me".*

**Non** è un servizio o un binario separato; non c'è nulla da distribuire. Si basa sulla CLI che hai già installato: l'agente esegue `agenteye --json …`, analizza il JSON pulito e ti risponde in prosa. Tutto quello che può fare, potresti farlo tu stesso digitando gli stessi comandi.

---

## Come si relaziona alle altre interfacce di Failproof AI Observability

Failproof AI Observability ti offre quattro modi per raggiungere gli stessi dati e controlli. Si completano a vicenda:

| Interfaccia | Che cosa è | Dove viene eseguita | Usala quando |
|---|---|---|---|
| **[CLI](/it/agenteye/cli)** | Il riferimento di comandi e flag per `agenteye` | Il tuo terminale | Vuoi eseguire o scrivere uno script per un comando specifico |
| **[CLI recipes](/it/agenteye/cli-recipes)** | Modelli `jq`/pipeline da copiare e incollare | Il tuo terminale / script | Stai integrando la CLI nell'automazione |
| **CLI skill** (questo documento) | Una porta in linguaggio naturale sulla CLI | Il tuo agente di codifica, sulla tua workstation | Vuoi semplicemente chiedere e lasciare che l'agente scelga il comando |
| **[Evaluator skill](/it/agenteye/evaluator-skill)** | Una skill gemella che progetta e costruisce il tuo servizio di scoring | Il tuo agente di codifica, sulla tua workstation | Vuoi *produrre* score di valutazione piuttosto che leggerli |
| **[Python SDK skill](/it/agenteye/python-sdk-skill)** | Una skill gemella che strumenta il tuo agente in modo che emetta telemetria | Il tuo agente di codifica, sulla tua workstation | Vuoi che il tuo agente *produca* gli eventi che questa skill legge |
| **[AI assistant in-dashboard](/it/agenteye/assistant)** | Una chat integrata nella dashboard | Lato server (nella dashboard) | Vuoi Q&A in-dashboard sui tuoi dati |

La skill stessa non ha privilegi propri; trasforma semplicemente le tue parole in chiamate CLI che vengono eseguite come te:

```mermaid
flowchart TD
    YOU["tu: 'riconosci l'incident in corso'"] --> AGENT["agente di codifica (Claude Code / Codex)<br/>carica la skill agenteye-cli"]
    AGENT --> CLI["agenteye --json incidents ack ..."]
    CLI -->|la tua sessione CLI autenticata| API["API dashboard Observability"]
```

### vs. l'AI assistant in-dashboard: una distinzione importante

Questi sono due strumenti diversi con raggi di effetto molto diversi:

- L'**AI assistant in-dashboard** ([AI assistant](/it/agenteye/assistant)) è una chat integrata nella dashboard, alimentata dal servizio dell'agente. È **sola lettura più authoring con approvazione**: può elaborare query salvate e dashboard, ma ogni scrittura si interrompe per il tuo clic di approvazione esplicito e non cancella mai. È protetto dal permesso `agent:use` e vede sempre solo i dati per l'org che stai visualizzando.
- La **CLI skill** viene eseguita sulla *tua* workstation all'interno del *tuo* agente di codifica e guida la `agenteye` CLI come **te**. Può eseguire la **superficie completa della CLI, incluse le mutazioni** (creare/ruotare/disabilitare chiavi API, modificare le impostazioni dell'org, risolvere incident, eliminare query salvate), limitata solo dai permessi del tuo accesso CLI. Trattala esattamente come faresti con l'esecuzione di quei comandi a mano.

## Prerequisiti

1. La **`agenteye` CLI installata** e in `PATH` (vedi il riferimento [CLI](/it/agenteye/cli): `pipx install agenteye`).
2. Il tuo **URL della dashboard** impostato (`AGENTEYE_DASHBOARD_URL`, o l'agente passa `--base-url`).
3. Una **sessione effettuata**: esegui tu stesso `agenteye login` per primo. La skill **non può** completare il login con codice monouso inviato via email per te; ti dirà di eseguire `agenteye login` se la sessione manca o è scaduta (exit code CLI `4`).

**[github.com/FailproofAI/skills](https://github.com/FailproofAI/skills)** → [`skills/agenteye-cli/`](https://github.com/FailproofAI/skills/tree/main/skills/agenteye-cli)

Nulla è limitato — il repository è pubblico e la skill non ha bisogno di credenziali proprie, perché guida solo la `agenteye` CLI **pubblica** contro *la tua* dashboard, usando la sessione con cui *tu* hai effettuato l'accesso. Non devi chiedere a nessuno.

Nota che viene distribuita come sua propria cartella e **non** è dentro il pacchetto `pipx install agenteye`, quindi non cercarla lì.

## Installazione della skill

Il percorso più veloce è la CLI [`skills`](https://skills.sh), che recupera la cartella e la mette dove il tuo agente la cerca:

```bash
# Claude Code, solo questo progetto
npx skills add FailproofAI/skills --skill agenteye-cli -a claude-code

# ogni progetto (installa in ~/.claude/skills/)
npx skills add FailproofAI/skills --skill agenteye-cli -a claude-code -g --copy

# Codex invece
npx skills add FailproofAI/skills --skill agenteye-cli -a codex
```

Poi gestiscila come qualsiasi altra skill:

```bash
npx skills list -a claude-code      # cosa è installato
npx skills update agenteye-cli      # scarica l'ultima versione
npx skills remove agenteye-cli      # rimuovila
```

Preferisci installarla a mano? Una Agent Skill è solo una cartella contenente un `SKILL.md` (più riferimenti opzionali), quindi copiarla funziona anche:

- **Claude Code**: metti la cartella `agenteye-cli/` in `~/.claude/skills/` (ogni progetto) o `<tuo-repo>/.claude/skills/` (solo quel repo). Claude Code la scopre automaticamente — verifica con l'elenco `/skills`, o semplicemente fai una domanda che corrisponda alla sua descrizione.
- **Codex (OpenAI)**: Codex legge lo stesso `SKILL.md`. Il `agents/openai.yaml` fornito imposta `allow_implicit_invocation: true`, quindi Codex seleziona automaticamente la skill quando un'attività corrisponde; altrimenti invocala esplicitamente come `$agenteye-cli`.

## Sicurezza: le mutazioni NON richiamano un prompt quando un agente esegue la CLI

> **Avviso:** Leggi questo prima di permettere a un agente di apportare modifiche.

La CLI `agenteye` normalmente chiede *"sei sicuro?"* prima di un'azione distruttiva. **Lo salta automaticamente ogni volta che non è collegata a un terminale (che è esattamente come un agente di codifica la esegue), e `--json` lo salta anche.** Quindi il prompt di sicurezza **non** si attiverà per l'agente.

La skill è scritta per compensare: le è insegnato di indicare il comando esatto che eseguirà e ottenere il tuo **OK esplicito prima di qualsiasi cambio di stato**. Mantieni quella disciplina. Quando guidi Failproof AI Observability attraverso un agente, *tu* sei il passo di conferma. I comandi che cambiano lo stato da tenere d'occhio:

- `keys create` / `update` / `disable` / `regenerate`
- `users create` / `update` / `disable` / `enable`
- `settings set`
- `alerts create` / `update` / `delete` / `test`
- i sottocomandi di scrittura di `incidents`: `ack` / `assign` / `resolve` / `open` / `comment-add` / `comment-delete` / `subscribe` / `unsubscribe`
- `query create` / `update` / `delete`
- `agent rename` / `delete`
- `orgs switch`

Tutto sotto **Observe** (`events`, `sessions`, `evals`, `errors`, `list`, `whoami`, `orgs list/current/perms`) è di sola lettura e non cambia nulla.

Poiché l'agente agisce come **te**, può fare solo quello che il tuo accesso è autorizzato a fare; i permessi sono risolti **per org** (vedi [API keys](/it/agenteye/api-keys)). Un comando per cui non hai permesso restituisce exit code `5` con il permesso esatto nominato, quindi l'agente può dirti precisamente cosa chiedere a un amministratore piuttosto che fallire in modo opaco.

## Quello che puoi chiederle

Ecco come appare un vero viaggio di andata e ritorno, una lettura, poi un cambio che attende il tuo OK:

```text
tu    ▸ È successo qualcosa di grave nell'ultimo giorno?

agente ▸ Eseguo: agenteye --json errors --since 24h --aggregate
         3 tipi di errore nelle ultime 24h. Il più grande è TimeoutError
         (18 hit, tutti sul checkout-agent), poi RateLimited (5).
         Vuoi le sessioni che falliscono per TimeoutError?

tu    ▸ Dai a CI una chiave che può solo inviare eventi.

agente ▸ Questo crea una chiave API. Eseguirò:
         agenteye keys create ci --add events:add
         OK per procedere?

tu    ▸ sì

agente ▸ Fatto. Chiave "ci" creata con solo events:add.
         Il segreto è mostrato una sola volta, quindi memorizzalo ora. Non posso ristamparlo.
```

La skill mappa ogni intenzione in linguaggio naturale al comando `agenteye` giusto, scoprendo prima i valori validi (`list <kind>`, `whoami`) così non indovina, e indicando il comando esatto prima di qualsiasi cambio. Altri esempi:

- *"È successo qualcosa di grave / fallisce nelle ultime 24 ore?"* → `errors --since 24h --aggregate`, poi un breakdown.
- *"Perché la sessione `run-001` è fallita?"* → `events --session-id run-001 --all` + `evals --session-id run-001`.
- *"Come tende la qualità questa settimana?"* → `evals --aggregate --since 7d`, poi approfondisci negli esecuzioni con punteggio basso.
- *"Dai a CI una chiave che può solo inviare eventi."* → `keys create ci --add events:add` (indica il comando, poi lo crea e cattura il segreto monouso).
- *"Chi ha accesso? Rendi Dana in sola lettura."* → `users list` → `users update dana@… --permission-set read-only` (dopo conferma con te).
- *"Riconosci l'incident in corso e assegnalo a me."* → `incidents list --state firing` → `incidents ack <id>` / `incidents assign <id> tu@…`.

Per i comandi esatti, i flag e le forme JSON dietro questi, vedi il riferimento [CLI](/it/agenteye/cli) e [CLI recipes for agents](/it/agenteye/cli-recipes).
