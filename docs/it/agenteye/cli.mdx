Gestisci tutta Failproof AI Observability dal terminale o da uno script: niente giri tra i pannelli di controllo. La CLI `agenteye` interroga i tuoi dati (sessioni, log di eventi, valutazioni) e amministra la tua organizzazione (chiavi API, utenti, impostazioni, avvisi, incidenti, query salvate), quindi usala quando vuoi automatizzare un controllo, integrare Observability in CI, o permettere a un agente di codifica di ispezionare la produzione. Ogni comando supporta il flag `--json`, perciò funziona altrettanto bene per te da prompt o per un agente di codifica (Claude Code, Cursor) che esegue comandi e analizza i risultati.

Con un unico binario puoi:

- **Leggere i tuoi dati**: `sessions`, `events`, `evals`, `errors` (filtra per tempo, agente, ambiente, punteggio).
- **Gestire la tua organizzazione**: `keys`, `users`, `settings`, `alerts`, `incidents`.
- **Eseguire analisi**: SQL salvati e un runner di query ad hoc (`query`).
- **Chiedere all'assistente IA**: lo stesso analista di sola lettura con cui chatti nel pannello di controllo (`agent`).

> **Nota:** Questa è la CLI `agenteye`, uno strumento diverso dal daemon collector (`agenteye-collector`). La CLI comunica con il tuo pannello di controllo; il collector invia gli eventi al server.

## Quickstart

Da zero al tuo primo risultato in quattro righe. Punta la CLI al tuo pannello di controllo, accedi, conferma chi sei, quindi estrai le ultime 24 ore di esecuzioni:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # codice a 6 cifre inviato via email
agenteye whoami                                                                  # conferma utente + organizzazione attiva
agenteye --json sessions --since 24h                                             # una riga per esecuzione agente, ultime 24h
```

L'ultimo comando stampa un oggetto JSON delle sessioni più recenti (dal più nuovo al più vecchio, limitato a 50 di default). Puoi passarlo a `jq` per filtarlo, oppure ometti `--json` per una tabella formattata e colorata. Ogni riga contiene lo stato dell'esecuzione e, se un valutatore l'ha punteggiata, i suoi punteggi metrici (abbreviati qui):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

Il resto di questa pagina spiega ogni pezzo: [installazione](#installation) in isolamento, [accesso](#authentication), [configurazione](#configuration), le [convenzioni globali](#global-options--conventions) condivise da ogni comando, e il [riferimento completo dei comandi](#command-reference).

## Installation

La CLI è un pacchetto pubblico PyPI denominato **`agenteye`**. Installalo in un ambiente isolato così avrà sempre le sue proprie dipendenze:

```bash
pipx install agenteye
# oppure
uv tool install agenteye
```

Richiede Python 3.10+. Il comando installato è **`agenteye`**:

```bash
agenteye --version
agenteye --help
```

> **Nota:** Anche l'SDK Python di Failproof AI Observability usa il nome di distribuzione `agenteye`. Installare la CLI con `pipx` o `uv tool` (piuttosto che `pip install` in un virtualenv condiviso) evita collisioni tra i due. Un semplice `pip install agenteye` va bene solo se l'SDK non è installato nello stesso ambiente.

## Authentication

La CLI si autentica al **pannello di controllo** con un codice monouso inviato via email:

```bash
agenteye login --email you@example.com
# Un codice a 6 cifre ti viene inviato via email; incollalo quando richiesto.
```

Il token di sessione è memorizzato in `~/.agenteye/cli.json` (leggibile solo da te, modalità `0600`) ed è valido per 24 ore di default. Quando scade, esegui nuovamente `agenteye login`.

```bash
agenteye whoami     # mostra l'utente corrente, organizzazione attiva e permessi
agenteye logout     # revoca la sessione e cancella il token memorizzato
```

`whoami` non genera mai errori in caso di sessione mancante o scaduta; invece segnala `logged_in: false`, così uno script o un agente può sondare lo stato di autenticazione in sicurezza (può comunque uscire con codice diverso da zero se nessun URL base è impostato o il pannello di controllo non è raggiungibile).

**Requisiti:** la tua email deve essere abilitata per accedere al pannello di controllo (chiedi all'amministratore di Failproof AI Observability), e il pannello di controllo deve essere raggiungibile al suo URL base (vedi [Configurazione](#configuration)). Se richiedi un codice e non arriva, probabilmente la tua email non è ancora abilitata per l'accesso al pannello di controllo.

## Scegliere la tua organizzazione (multi-tenant)

Se il tuo account appartiene a più di un'organizzazione, scegli quella attiva **al momento del login**; viene salvata e usata per ogni comando successivo:

```bash
agenteye login --org acme           # autentica e imposta il tenant attivo in un passaggio
agenteye orgs list                  # le organizzazioni a cui puoi accedere (quella attiva è marcata)
agenteye orgs switch globex         # cambia il default salvato
agenteye --org globex sessions      # sovrascrive per un singolo comando
```

Se appartieni a esattamente un'organizzazione viene selezionata automaticamente e puoi ignorare completamente `--org`. Se ne hai diverse e non ne scegli una, la CLI le elenca e ti chiede di rieseguire con `--org <slug>`. L'organizzazione attiva viene inviata al pannello di controllo su ogni richiesta, e i tuoi permessi vengono risolti **per organizzazione**; `agenteye whoami` mostra l'organizzazione attiva, i tuoi permessi in essa, e tutte le tue appartenenze.

## Configuration

| Impostazione | Flag | Variabile d'ambiente | Default |
|---|---|---|---|
| URL base del pannello di controllo | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **obbligatorio** (nessun default) |
| Organizzazione/tenant attiva | `--org` | `AGENTEYE_ORG` | scelta al login; salvata in `~/.agenteye/cli.json` |
| Token di sessione | `--token` | `AGENTEYE_CLI_TOKEN` | da `~/.agenteye/cli.json` |
| Output JSON | `--json` | `AGENTEYE_CLI_JSON` | disattivato |
| Salta verifica TLS | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | disattivato (salvato al login) |
| Timeout richiesta (secondi) | `--timeout` | _(nessuno)_ | 30 |
| Disabilita telemetria d'uso | _(nessuno)_ | `AGENTEYE_ANALYTICS_DISABLED` (o `DO_NOT_TRACK`) | telemetria attualmente disabilitata; nulla viene inviato |

L'ordine di risoluzione è **flag → variabile d'ambiente → file di configurazione**. Non c'è un default; devi puntare la CLI al tuo pannello di controllo, either per-comando (`--base-url https://agenteye.example.com`) o una volta tramite l'ambiente (viene anche salvato dopo il tuo primo `login`):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

La directory di configurazione onora `AGENTEYE_HOME` (la stessa convenzione usata dall'SDK e dal collector); se impostata, `cli.json` si trova in `$AGENTEYE_HOME/cli.json`.

### TLS auto-firmato o interno

Se il tuo pannello di controllo è servito su HTTPS con un certificato auto-firmato o interno (per esempio, un nome host di load-balancer grezzo), la verifica TLS lo rifiuta con errore `CERTIFICATE_VERIFY_FAILED`. Passa `--insecure` per saltare la verifica del certificato:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` è **salvato in `cli.json` quando accedi**, così i comandi successivi saltano la verifica automaticamente; non devi ripetere il flag. Passa `--secure` per una chiamata verificata una sola volta, o per salvare di nuovo la verifica al tuo prossimo login. La CLI stampa un avviso a stderr prima di qualsiasi comando che contatti il pannello di controllo mentre la verifica è disabilitata. Saltare la verifica rimuove la protezione contro attacchi man-in-the-middle; assicurati di fidarti del percorso di rete verso il tuo pannello di controllo (VPN, subnet privato, ecc.) prima di affidarti a esso.

## Telemetria & privacy

> **Nota:** La CLI spedita **non invia alcuna telemetria d'uso oggi.** Un kill switch master è attivo, quindi nulla viene trasmesso indipendentemente dal tuo ambiente. La sezione sottostante descrive la capacità di opt-out per se e quando la telemetria fosse mai abilitata.

Anche se abilitata, la telemetria sarebbe **solo analitiche di utilizzo anonime**, mai i dati del tuo agente, sessione o evento:

- **Nessun dato di agente, sessione o evento lascia mai la tua infrastruttura.** Solo l'utilizzo della CLI verrebbe segnalato: il nome del comando e sottocomando (es. `keys create`), i **nomi** dei flag che hai usato (mai i loro valori), stato di successo/uscita e durata, più un evento per-azione per mutazioni (es. `api_key_created`, `query_run`) contenente solo nomi statici/enum e conteggi approssimativi. Il tuo URL del pannello di controllo, token di sessione, email, slug dell'organizzazione, id delle risorse, SQL, segreti della chiave e filtri di query **non verrebbero mai** inviati. Gli operatori verrebbero identificati solo da un id interno opaco, mai via email.
- **Opt out in anticipo** impostando `AGENTEYE_ANALYTICS_DISABLED=1` nell'ambiente della CLI (la CLI onora anche la convenzione cross-tool `DO_NOT_TRACK=1`). Questo prende effetto nel momento in cui la telemetria fosse mai attivata, così un ambiente consapevole della privacy può rimanere escluso permanentemente.
- Se la telemetria fosse abilitata, la CLI invierebbe direttamente a PostHog (`https://us.i.posthog.com`); una macchina con quell'host bloccato invierebbe silenziosamente nulla e la CLI non sarebbe interessata.

## Global options & conventions

Leggi questa una sola volta; si applica a ogni comando.

- **Le opzioni globali vanno PRIMA del comando.** `agenteye --json sessions` è corretto; `agenteye sessions --json` è un errore di utilizzo. I global sono `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, e `--no-color`.
- **`--json` stampa JSON puro su stdout, e nulla altro.** Linee di stato umane, avvisi ed errori vanno su **stderr**, così un'acquisizione stdout `--json` rimane pulita da passare a `jq` anche quando una linea di stato viene mostrata. Senza `--json` ottieni una vista formattata e colorata per occhi umani.
- **Scopri con `--help`.** Ogni comando e sottocomando ha `--help` (e l'alias `-h`): `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`. L'help di livello superiore elenca anche i codici di uscita e le opzioni globali. Non c'è un dump di superficie leggibile da macchina globale; usa `--help` per-comando, più il dominio-specifico `agenteye query schema` e `agenteye settings schema` per quei due registri.
- **Le conferme si saltano automaticamente per script e agenti.** I comandi Crea/Aggiorna/Elimina chiedono "sei sicuro?" in un terminale interattivo, ma **saltano automaticamente il prompt sotto `--json` o quando stdin non è un TTY** (un TTY è una sessione terminale interattiva; una pipe o un runner CI non lo è), così script e agenti non restano mai bloccati. Passa `--yes`/`-y` per saltarlo esplicitamente. Poiché il prompt non si attiverà per un agente, un agente dovrebbe confermare azioni distruttive con l'umano prima.
- **Paginazione:** i risultati sono dal più nuovo al più vecchio e pagina-cursore (ogni pagina restituisce un token che usi per recuperare il prossimo). `--limit N` (alias `-n`) limita le righe e **di default a 50**; `--all` auto-pagina (in chunk di 200 righe) **fino a `--limit`**, così un `--all` nudo si ferma ancora a 50. Per uno sweep completo passa un cap esplicito alto: `--all --limit 1000`. `--page-size N` controlla il chunk per-richiesta (massimo 200); `--cursor <id>` riprende da `next_cursor` di una pagina precedente.
- **Filtri temporali:** `--since` accetta una finestra relativa: `15m`, `1h`, `6h`, `24h`, `7d`, o `all` (i preset del pannello di controllo). Per un intervallo più lungo o personalizzato (diciamo gli ultimi 30 giorni), usa `--from`/`--to`: timestamp UTC ISO-8601 espliciti **con `T` e un fuso orario** (es. `2026-06-01T00:00:00Z`) che sovrascrivono `--since`. Un valore separato da spazi o senza fuso orario è un errore di utilizzo.
- **`--fields a,b,c`** (su `events`, `sessions`, `evals`, `errors`) limita l'output a quelle chiavi, per sia la tabella che `--json`. Nomi sconosciuti vengono rifiutati con l'elenco valido, un modo economico per scoprire i nomi dei campi.
- **`--file payload.json`** (o `--file -` per leggere da stdin) fornisce un corpo di richiesta JSON completo dove una risorsa ha una forma complessa (su `alerts create/update`, `settings set`, e `users create/update`). SQL di query salvate usa `--sql @file.sql` invece.
- **Filtri multi-valore** sono separati da virgola → matched come un set (unione dentro un filtro, AND tra filtri): `--event-type tool_use,tool_result`. Le opzioni Click non sono variadiche, quindi `--add a b` si rompe. Usa `--add a,b`, ripeti il flag (`--add a --add b`), o virgolette (`--add "a b"`).

## Command reference

### Usera i 5 comandi più frequentemente

La maggior parte del lavoro quotidiano gira attraverso una manciata di comandi di lettura. Inizia qui, poi raggiungi la superficie completa sottostante quando ne hai bisogno:

| Comando | Cosa fa | Provalo |
|---|---|---|
| `sessions` | Una riga per esecuzione agente: ora, ambiente, agente, stato, punteggio più recente. | `agenteye --json sessions --since 24h --status error` |
| `events` | La scia grezza per-passaggio dentro un'esecuzione (aggiungi `--full` per payload). | `agenteye --json events --session-id run-001 --all` |
| `evals` | Risultati di valutazione e punteggi; `--aggregate` li riassume. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | Solo gli eventi con errore; `--aggregate` per conteggi per tipo. | `agenteye --json errors --since 24h --aggregate` |
| `list` | Scopri i valori di filtro validi (agenti, ambienti, modelli, …). | `agenteye list agents` |

### Tutto quello che la CLI può fare

La superficie completa segue. La CLI ha **18 comandi di livello superiore**. Tutti i comandi di lettura accettano `--json` e le opzioni globali sopra; esegui `agenteye <command> -h` (o `<command> <subcommand> -h`) per l'elenco di flag esaustivo e la forma JSON di uno qualsiasi.

### Identity: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # codice monouso inviato via email; salva la sessione
agenteye logout                                       # cancella la sessione salvata su questa macchina
agenteye whoami                                       # utente corrente, organizzazione attiva, permessi
agenteye version                                      # stampa la versione della CLI (stesso come --version)
agenteye help                                         # help di livello superiore (stesso come --help)
```

`orgs` ispeziona e commuta il tenant attivo:

```bash
agenteye orgs list        # le tue organizzazioni + il tuo ruolo in ciascuna (quella attiva marcata)
agenteye orgs switch acme # cambia l'organizzazione attiva salvata (ometti lo slug per scegliere da lista su TTY)
agenteye orgs current     # carta d'identità per l'organizzazione attiva
agenteye orgs perms       # i tuoi permessi nell'organizzazione attiva, raggruppati per risorsa
```

### Observe (read-only): `events` · `sessions` · `evals` · `errors` · `list`

Nessuno di questi necessita una conferma. Filtri condivisi: `--session-id`, `--agent-id`, `--env` (**non** `--environment`), e l'intervallo temporale (`--since` / `--from` / `--to`).

```bash
# events (alias: la scia grezza per-passaggio), dal più nuovo al più vecchio
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: una riga per esecuzione agente (tempo/ambiente/agente/sessione/stato; nessun filtro di punteggio)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: risultati di valutazione + punteggi; --score filtra per metrica, --aggregate riassume
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # mix di stato + statistiche di punteggio per-chiave

# errors: eventi con errore; --aggregate per conteggi/sessioni/agenti/ultima visualizzazione
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: scopri valori di filtro validi prima di filtrare
agenteye list envs        # anche: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (su **`evals`**, non `sessions`) è ripetibile e AND-combinato; entrambi i limiti sono opzionali (`..0.5` significa ≤ 0.5, `0.9..` significa ≥ 0.9). Fino a 20 filtri di punteggio per richiesta. `evals --scores-full` è un flag di visualizzazione per la **tabella umana solo**; mostra ogni coppia di punteggio invece di i primi pochi più un conteggio `+N`. Non ha effetto sotto `--json`, che restituisce sempre l'oggetto di punteggio completo. Per leggere **una sessione da capo a fondo**, combina la scia di evento con la sua valutazione:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # i suoi punteggi + stato
```

### Manage (permission-gated): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: Chiavi API. Il segreto è generato localmente, inviato al server (che memorizza solo un hash), e **mostrato una sola volta** su creazione/rigenerazione; catturalo allora. Con `--json` appare solo nel campo `key`. Referenziato per **nome**.

```bash
agenteye keys list                                   # chiavi attive prime, poi revocate
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # ambito a quello di cui hai bisogno; stampa il segreto UNA SOLA VOLTA
agenteye keys create ops --permission-set standard --remove queries:run   # seed un preset, poi ritaglia
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # ruota il segreto (il vecchio smette di funzionare)
agenteye keys disable ci-bot --yes                   # revoca
```

I permessi funzionano come `(permission-set ∪ --add) − --remove`. I token sono `slug:action` (es. `events:read`) o `slug:action.action` per espandere diversi su una risorsa (`events:read.add` → `events:read`, `events:add`). Preset: `read-only`, `standard`, `admin`. I permessi solo-umani (`keys:update`) non possono essere concessi a una chiave.

**`users`**: membri dell'organizzazione, referenziati per **email** (un id UUID è anche accettato).

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predice + conferma
agenteye users disable dev@corp.com --yes            # ha protezioni/guardie automatiche
agenteye users enable dev@corp.com
```

**`settings`**: un registro fisso (leggi e cambia le chiavi esistenti; non puoi crearne di nuove).

```bash
agenteye settings list                               # chiave · valore · tipo · aggiornato (segreti mascherati)
agenteye settings schema                             # cosa accetta ogni chiave (tipo · intervallo · descrizione)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: definizioni di avviso, referenziate per **nome**. `create` accetta un NAME posizionale più flag o un corpo JSON completo via `--file`.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME è obbligatorio (posizionale)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # dispara una notifica di test
agenteye alerts delete high-errors --yes
```

**`incidents`**: incidenti di avviso, referenziati per id (id corti accettati). `show` stampa il registro completo delle attività; leggilo prima di agire.

```bash
agenteye incidents list --state firing                # anche: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assegnatario deve essere un operatore
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # aprine uno manualmente contro un avviso
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### Analytics & assistant: `query` · `agent`

**`query`**: SQL salvato contro il tuo analytics store più un runner ad hoc. Le query salvate sono referenziate per **nome**; l'SQL è convalidato lato server (solo SELECT/WITH, timeout di istruzione, cap di riga).

```bash
agenteye query schema [TABLE]                         # layout colonna delle viste di analisi
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # esegui una query salvata + un $1 posizionale
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: parla all'**assistente IA** integrato (lo stesso analista di sola lettura con cui puoi chattare nel pannello di controllo). Le chat sono referenziate per un chat-id corto (risoluzione per prefisso).

```bash
agenteye agent health                                 # l'assistente IA è configurato/raggiungibile
agenteye agent models                                 # modelli che puoi passare a --model (default marcato)
agenteye agent ask "which agents errored most in the last day?"    # avvia una chat; stampa il suo id corto
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continua quella chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## Exit codes

| Codice | Significato |
|---|---|
| 0 | Successo |
| 1 | Errore inatteso (es. il pannello di controllo ha restituito un 5xx) |
| 2 | Errore di utilizzo (argomenti non validi, comando/flag sconosciuto, collisione di nomi) |
| 3 | Impossibile raggiungere il pannello di controllo |
| 4 | Non autenticato o sessione scaduta; esegui `agenteye login` |
| 5 | Autenticato, ma il tuo account manca del permesso richiesto (il messaggio lo nomina) |
| 6 | La risorsa richiesta non è stata trovata (es. id di sessione o incidente sconosciuto) |

Questi rendono la CLI sicura da scrivere con script: un agente di codifica può diramare su un `4` per invitarti a re-autenticarti, o su un `5` per evidenziare il permesso mancante. Vedi [Ricette CLI per agenti](/it/agenteye/cli-recipes) per i pattern di gestione del codice di uscita e le forme di output JSON.
