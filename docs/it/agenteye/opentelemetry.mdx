OpenTelemetry ti permette di inviare tracce, log e metriche dell'agente a FailproofAI Cloud utilizzando il protocollo standard OTLP/HTTP. È facoltativo. Le tue integrazioni FailproofAI esistenti continuano a funzionare senza abilitarlo.

## Attiva l'ingest per la tua organizzazione

Un amministratore dell'organizzazione apre **Settings → OpenTelemetry** e attiva l'ingest. Usa una chiave API Cloud con permesso `events:add`, lo stesso permesso utilizzato per la segnalazione dell'agente.

Se l'ingest è disattivato, Cloud rifiuta le esportazioni OTLP, quindi `failproofai otel enable` non cambia nulla e i tuoi agenti continuano a inviare sessioni nel modo consueto. Esegui `failproofai otel status` per verificare l'interruttore dell'organizzazione e chiedi a un amministratore di attivarlo.

## Connetti un agente di codifica

Connetti la tua macchina con `failproofai config`, quindi scegli un agente:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Il comando di setup supporta Claude Code, Codex e Copilot e sceglie Cloud o un relay locale autenticato secondo necessità. Copilot utilizza il relay locale automaticamente. Avvia il daemon FailproofAI configurato prima di utilizzare il relay.

Se FailproofAI invia già i transcript delle sessioni di un agente, setup chiede se passare quell'agente a OTEL. L'impostazione predefinita è No. Accettare interrompe i caricamenti dei transcript per quell'agente; non modifica l'applicazione delle policy o la segnalazione degli altri agenti.

## Connetti un'applicazione

Usa l'instrumentazione OpenTelemetry della tua applicazione con queste variabili d'ambiente:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

L'endpoint è la base OTLP di Cloud, `https://app.befailproof.ai/otel`; l'esportatore aggiunge da sé `/v1/traces`, `/v1/logs` o `/v1/metrics`. Le variabili per singoli segnali come `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` vengono utilizzate così come sono, quindi richiedono il percorso completo, ad esempio `https://app.befailproof.ai/otel/v1/logs`.

Sostituisci `<key>` con la tua chiave API. Tieni il secret fuori dalla cronologia della shell, dalle registrazioni dello schermo e dalla configurazione sottoposta a commit. Per una macchina configurata, `failproofai otel env --service my-agent` stampa il blocco con la sua chiave esistente. L'output contiene una credenziale.

Cloud accetta esportazioni OTLP/HTTP per tracce, log e metriche, come protobuf o JSON, incluse le richieste compresse con gzip. Non accetta OTLP/gRPC.

Le metriche sono riconosciute per compatibilità dell'esportatore ma non vengono memorizzate o visualizzate. Le tracce degli agenti supportati e i log dell'agente di codifica diventano sessioni; i campi che l'agente non esporta rimangono assenti.

## Cattura il testo del prompt

<Warning>
La cattura del testo può includere prompt, argomenti degli strumenti e altri contenuti sensibili. `failproofai otel enable` la attiva. Aggiungi `--no-content` per mantenere disattivata la cattura di prompt e dettagli degli strumenti.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Per un agente che configuri manualmente, usa i suoi controlli di cattura dei contenuti propri:

<Tabs>
  <Tab title="Claude Code">
    Aggiungi queste variabili all'ambiente dell'agente accanto al blocco dell'applicazione precedente:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Imposta entrambe le variabili di contenuto su `0` per evitare di catturare prompt e dettagli degli strumenti.
  </Tab>
  <Tab title="Codex">
    Nella configurazione utente di Codex, utilizza le sue impostazioni OTEL:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Il contenuto della conversazione di Codex è nei log; lascia disabilitate le tracce di runtime interno e le metriche. Codex utilizza l'endpoint completo che fornisci. Imposta `log_user_prompt` su `false` per escludere i prompt; il comando setup preserva un `false` esplicito.
  </Tab>
  <Tab title="Gemini CLI">
    Usa le impostazioni di telemetria di Gemini con il relay locale:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI non è supportato da `failproofai otel enable`. Configuralo manualmente con un collector autenticato personalizzato. Imposta `logPrompts` su `false` per nessuna cattura di prompt.
  </Tab>
  <Tab title="Copilot in VS Code">
    Usa queste impostazioni utente di VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Esegui `failproofai otel enable copilot` per abilitare il relay autenticato. Imposta `captureContent` su `false` per omettere il contenuto.
  </Tab>
</Tabs>

## Verifica o annulla il setup

```bash
failproofai otel status
failproofai otel disable all
```

Lo status distingue le impostazioni gestite da FailproofAI dalla telemetria che hai configurato altrove. Disable ripristina le precedenti impostazioni gestite e la precedente scelta di caricamento dei transcript dell'agente.
