OpenTelemetry ti permette di inviare tracce, log e metriche degli agent a FailproofAI Cloud utilizzando il protocollo standard OTLP/HTTP. È facoltativo. Le tue integrazioni FailproofAI esistenti continuano a funzionare senza abilitarlo.

## Attiva l'acquisizione per la tua organizzazione

Un amministratore dell'organizzazione apre **Settings → OpenTelemetry** e attiva l'acquisizione. Utilizza una chiave API Cloud con permesso `events:add`, lo stesso permesso utilizzato per la segnalazione degli agent.

Se l'acquisizione è disattivata, Cloud rifiuta le esportazioni OTLP, quindi `failproofai otel enable` non cambia nulla e i tuoi agent continuano a inviare sessioni nel modo consueto. Esegui `failproofai otel status` per verificare l'interruttore dell'organizzazione e chiedi a un amministratore di attivarlo.

## Connetti un coding agent

Connetti la tua macchina con `failproofai config`, quindi scegli un agent:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Il comando di configurazione supporta Claude Code, Codex e Copilot e sceglie Cloud o un relay locale autenticato come appropriato. Copilot utilizza il relay locale automaticamente. Avvia il daemon FailproofAI configurato prima di utilizzare il relay.

Se FailproofAI invia già i trascritti di sessione di un agent, la configurazione chiede se passare quell'agent a OTEL. L'impostazione predefinita è No. Accettare interrompe i caricamenti dei trascritti per quell'agent; non cambia l'applicazione delle politiche o la segnalazione da altri agent.

## Connetti un'applicazione

Utilizza la strumentazione OpenTelemetry della tua applicazione con queste variabili d'ambiente:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

L'endpoint è la base OTLP di Cloud, `https://app.befailproof.ai/otel`; il tuo esportatore aggiunge `/v1/traces`, `/v1/logs` o `/v1/metrics` da solo. Le variabili per segnale specifico come `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` vengono utilizzate così come sono, quindi hanno bisogno del percorso completo, ad esempio `https://app.befailproof.ai/otel/v1/logs`.

Sostituisci `<key>` con la tua chiave API. Mantieni il segreto fuori dalla cronologia della shell, dalle registrazioni dello schermo e dalla configurazione committata. Per una macchina configurata, `failproofai otel env --service my-agent` stampa il blocco con la sua chiave esistente. Il suo output contiene una credenziale.

Cloud accetta esportazioni OTLP/HTTP per tracce, log e metriche, sia come protobuf che JSON, incluse le richieste compresse con gzip. Non accetta OTLP/gRPC.

Le metriche sono riconosciute per la compatibilità dell'esportatore ma non vengono archiviate o visualizzate. Le tracce degli agent supportate e i log dei coding-agent diventano sessioni; i campi che l'agent non esporta rimangono assenti.

## Acquisisci testo del prompt

<Warning>
L'acquisizione di testo può includere prompt, argomenti degli strumenti e altri contenuti sensibili. `failproofai otel enable` l'attiva. Aggiungi `--no-content` per mantenere disattivata l'acquisizione del prompt e dei dettagli degli strumenti.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Per un agent che configuri manualmente, utilizza i suoi controlli di acquisizione dei contenuti:

<Tabs>
  <Tab title="Claude Code">
    Aggiungi queste variabili all'ambiente del tuo agent insieme al blocco dell'applicazione sopra:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Imposta entrambe le variabili di contenuto su `0` per evitare di acquisire prompt e dettagli degli strumenti.
  </Tab>
  <Tab title="Codex">
    Nella configurazione dell'utente di Codex, utilizza le sue impostazioni OTEL:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Il contenuto della conversazione di Codex è nei log; lascia disabilitate le tracce di runtime interne e le metriche. Codex utilizza l'endpoint completo che fornisci. Imposta `log_user_prompt` su `false` per escludere i prompt; il comando di configurazione preserva un `false` esplicito.
  </Tab>
  <Tab title="Gemini CLI">
    Utilizza le impostazioni di telemetria di Gemini con il relay locale:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI non è supportato da `failproofai otel enable`. Configuralo manualmente con un collector autenticato tuo. Imposta `logPrompts` su `false` per nessuna acquisizione del prompt.
  </Tab>
  <Tab title="Copilot in VS Code">
    Utilizza queste impostazioni utente di VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Esegui `failproofai otel enable copilot` per abilitare il relay autenticato. Imposta `captureContent` su `false` per omettere il contenuto.
  </Tab>
</Tabs>

## Verifica o annulla la configurazione

Il relay conserva la telemetria attraverso errori di rete e server temporanei e ritenta dopo il recupero. Un rifiuto permanente `400`, incluso un evento troppo grande per essere archiviato, richiede la correzione del payload. Il relay mantiene il batch rifiutato per l'ispezione invece di inviarlo ripetutamente.

Dopo un `401` o `403`, sostituisci la credenziale con una chiave che concede `events:add` per la stessa organizzazione. La riconnessione non reinvia automaticamente le esportazioni OTLP conservate rifiutate per credenziali; chiedi al tuo operatore di recuperare tali batch. Mantienili nella loro organizzazione originale.

```bash
failproofai otel status
failproofai otel disable all
```

Lo stato distingue le impostazioni gestite da FailproofAI dalla telemetria che hai configurato altrove. Disabilita ripristina le impostazioni gestite precedenti e la scelta di caricamento dei trascritti precedente dell'agent.
