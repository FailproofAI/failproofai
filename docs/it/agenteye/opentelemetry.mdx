OpenTelemetry ti permette di inviare tracce, log e metriche dell'agente a FailproofAI Cloud utilizzando il protocollo standard OTLP/HTTP. È opzionale. Le tue integrazioni FailproofAI esistenti continuano a funzionare senza abilitarlo.

## Ottieni una chiave

L'ingest OTLP è sempre attivo per ogni organizzazione; non c'è nulla da abilitare. Usa una chiave Cloud API con permesso `events:add`, lo stesso permesso utilizzato per la segnalazione dell'agente.

Nel dashboard, **home → first-run setup** ha una card **connect with OpenTelemetry**: **create collector key** crea una chiave `events:add`, la mostra una sola volta con le variabili dell'esportatore e mostra lo stato della connessione. Puoi anche crearne una in **settings → api keys** scegliendo **sending logs only** in **new key**.

## Connetti un agente di codifica

Connetti la tua macchina con `failproofai config`, quindi scegli un agente:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Il comando di setup supporta Claude Code, Codex e Copilot e sceglie Cloud o un relay autenticato locale come appropriato. Copilot utilizza il relay locale automaticamente. Avvia il daemon FailproofAI configurato prima di utilizzare il relay.

Se FailproofAI invia già i transcript della sessione di un agente, il setup chiede se passare quell'agente a OTEL. L'impostazione predefinita è No. Accettando si interrompe il caricamento dei transcript per quell'agente; non cambia l'applicazione delle policy o la segnalazione da altri agenti.

## Connetti un'applicazione

Usa la strumentazione OpenTelemetry della tua applicazione con queste variabili d'ambiente:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

L'endpoint è la base OTLP del Cloud, `https://app.befailproof.ai/otel`; il tuo esportatore aggiunge `/v1/traces`, `/v1/logs` o `/v1/metrics` da solo. Le variabili per singolo segnale come `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` vengono utilizzate così come sono, quindi hanno bisogno del percorso completo, ad esempio `https://app.befailproof.ai/otel/v1/logs`.

Sostituisci `<key>` con la tua chiave API. Mantieni il segreto fuori dalla cronologia shell, dalle registrazioni dello schermo e dalla configurazione sottoposta a commit. Per una macchina configurata, `failproofai otel env --service my-agent` stampa il blocco con la sua chiave esistente. L'output contiene una credenziale.

Cloud accetta esportazioni OTLP/HTTP per tracce, log e metriche, come protobuf o JSON, incluse le richieste compresse con gzip. Non accetta OTLP/gRPC.

Le metriche sono riconosciute per la compatibilità dell'esportatore ma non vengono archiviate o visualizzate. Le tracce degli agenti supportati e i log degli agenti di codifica diventano sessioni; i campi che l'agente non esporta rimangono assenti.

## Cattura il testo del prompt

<Warning>
La cattura del testo può includere prompt, argomenti degli strumenti e altri contenuti sensibili. `failproofai otel enable` la attiva. Aggiungi `--no-content` per mantenere disattivata la cattura del prompt e dei dettagli dello strumento.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Per un agente che configuri manualmente, usa i suoi controlli di cattura dei contenuti:

<Tabs>
  <Tab title="Claude Code">
    Aggiungi queste variabili all'ambiente del tuo agente insieme al blocco dell'applicazione sopra:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Imposta entrambe le variabili di contenuto su `0` per evitare di catturare prompt e dettagli degli strumenti.
  </Tab>
  <Tab title="Codex">
    Nella configurazione utente di Codex, usa le sue impostazioni OTEL:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Il contenuto della conversazione di Codex è nei log; mantieni disabilitate le tracce e le metriche del runtime interno. Codex utilizza l'endpoint completo che fornisci. Imposta `log_user_prompt` su `false` per escludere i prompt; il comando di setup preserva un `false` esplicito.
  </Tab>
  <Tab title="Gemini CLI">
    Usa le impostazioni di telemetria di Gemini con il relay locale:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI non è supportato da `failproofai otel enable`. Configuralo manualmente con un collector autenticato personalizzato. Imposta `logPrompts` su `false` per nessuna cattura dei prompt.
  </Tab>
  <Tab title="Copilot in VS Code">
    Usa queste impostazioni utente di VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Esegui `failproofai otel enable copilot` per abilitare il relay autenticato. Imposta `captureContent` su `false` per omettere il contenuto.
  </Tab>
</Tabs>

## Verifica o annulla il setup

Il relay mantiene la telemetria attraverso i guasti temporanei della rete e del server e riprova dopo il ripristino. Un rifiuto permanente `400`, incluso un evento troppo grande per essere archiviato, richiede la correzione del payload. Il relay mantiene il batch rifiutato per l'ispezione piuttosto che inviarlo ripetutamente.

Dopo un `401` o `403`, sostituisci la credenziale con una chiave che conceda `events:add` per la stessa organizzazione. La riconnessione non invia automaticamente di nuovo le esportazioni OTLP conservate rifiutate per credenziali; chiedi al tuo operatore di recuperare quei batch. Mantienili nella loro organizzazione originale.

```bash
failproofai otel status
failproofai otel disable all
```

Lo stato distingue le impostazioni gestite da FailproofAI dalla telemetria che hai configurato altrove. Disabilitare ripristina le impostazioni gestite precedenti e la scelta precedente di caricamento del transcript dell'agente.
