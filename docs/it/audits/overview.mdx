## Locale o Cloud

| | Audit locale | Audit Cloud |
| --- | --- | --- |
| Comando | `failproofai audit` | `fp audits` |
| Legge | Cronologia degli agenti su questo computer | Sessioni nella tua organizzazione Cloud |
| Produce | Risultati locali su `localhost:8020/audit` | Risultati, problemi e avvisi condivisi |
| Richiede | Nessun account | Connessione Cloud e chiave API |

Usa un audit locale per una revisione rapida di un singolo computer. Usa Cloud quando un team ha bisogno di un audit ricorrente su più agenti e computer.

## Domande a cui un audit può rispondere

- Dove gli agenti si fermano senza escalare?
- Quali errori degli strumenti portano a tentativi inefficaci?
- Gli agenti accedono a dati al di fuori del flusso di lavoro previsto?
- Cosa è cambiato dopo un aggiornamento del modello, del prompt o dello strumento?

## Aprire gli audit Cloud

Vai a **Analyze → Audits**, oppure usa:

```bash
fp audits list
fp audits show <audit-name>
fp audits findings --status open --limit 20
```

I comandi di audit utilizzano il nome dell'audit o l'ID completo. I risultati sono referenziati dal loro ID.

## Dal risultato alla prevenzione

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert
```

Un risultato punta a prove. Un problema possiede la risposta. Una policy previene uno schema di azioni noto; un avviso monitora la ricorrenza.

Non tutti i risultati dovrebbero diventare una policy. Un risultato di tipo `policy` descrive una regola applicabile. Un `failure` o un `improvement` potrebbe richiedere invece una modifica al flusso di lavoro, al prompt, al modello o allo strumento.
