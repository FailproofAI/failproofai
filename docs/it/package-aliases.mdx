## Package ufficiale

Il package npm canonico è **`failproofai`**:

```bash
npm install -g failproofai
# or
bun add -g failproofai
```

---

## Perché possediamo i nomi alias

Il typosquatting è un attacco alla catena di fornitura comune in cui un attore malintenzionato registra un nome di package a una sola pressione di tasto di distanza da un package popolare. Gli utenti inconsapevoli che digita male il comando di installazione finiscono per eseguire codice controllato dall'attaccante con accesso completo al sistema - esattamente il tipo di minaccia che Failproof AI è progettato per difendere.

Per eliminare questa superficie, **possediamo preventivamente tutte le comuni varianti di ortografia e formattazione** di `failproofai` su npm. Nessuno di questi nomi può essere registrato da terze parti. Ognuno di essi è un thin proxy che installa e delega al vero package `failproofai`.

## Alias registrati

**Varianti di formattazione** - diversi modi per scrivere "failproof ai":

| Package | Stato |
|---------|--------|
| `failproof` | ✅ Pubblicato |
| `failproof-ai` | ⏳ In attesa di supporto npm |
| `fail-proof-ai` | ⏳ In attesa di supporto npm |
| `failproof_ai` | ⏳ In attesa di supporto npm |
| `fail_proof_ai` | ⏳ In attesa di supporto npm |
| `fail-proofai` | ⏳ In attesa di supporto npm |

**Typo `failprof*`** - manca una `o` da "proof":

| Package | Stato |
|---------|--------|
| `failprof` | ✅ Pubblicato |
| `failprof-ai` | ✅ Pubblicato |
| `failprofai` | ⏳ In attesa di supporto npm |
| `fail-prof-ai` | ⏳ In attesa di supporto npm |
| `failprof_ai` | ⏳ In attesa di supporto npm |

**Typo `faliproof*`** - `a` e `i` trasposte:

| Package | Stato |
|---------|--------|
| `faliproof` | ✅ Pubblicato |
| `faliproof-ai` | ✅ Pubblicato |
| `faliproofai` | ⏳ In attesa di supporto npm |

> **Perché in sospeso?** La politica di prevenzione dello spam di npm blocca i nomi che si normalizzano nella stessa stringa di un package esistente dopo aver rimosso la punteggiatura ed eseguito controlli di somiglianza. Abbiamo contattato il supporto npm per riservare questi nomi a scopi anti-squatting. Verranno attivati una volta approvati.

Puoi verificare che qualsiasi alias pubblicato sia di proprietà nostra:

```bash
npm info failproof
# Cercare: "ExosphereHost Inc." nel campo maintainers
```

## Come funzionano gli alias

Ogni package alias:

1. Elenca `failproofai` come dipendenza - quindi il package reale viene installato e il suo binary diventa disponibile
2. Espone un binary corrispondente al suo stesso nome (es. `failprof-ai`) che funge da proxy per tutti gli argomenti al binary `failproofai`

Il proxy è uno script Node di due righe; non c'è logica, nessuna chiamata di rete e nessuna raccolta dati oltre a quella che fa `failproofai` stesso.
