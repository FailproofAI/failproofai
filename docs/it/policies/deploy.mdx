Distribuisci una policy revisionata a una macchina alla volta. Inizia in modalità observe.

## Distribuire dalla CLI

```bash
fp policies test ./rule.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish no-force-push ./rule.mjs
fp fleet deploy <machine> --add no-force-push:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add no-force-push:enforce
```

La modalità observe valuta la policy reale e registra le decisioni non-allow, ma non blocca l'agente.

<Warning>
  Un semplice `--add no-force-push` applica immediatamente. Aggiungi `:observe` per un rollout in shadow mode.
</Warning>

Se l'applicazione causa problemi:

```bash
fp fleet history <machine>
fp fleet rollback <machine> <generation>
```

## Distribuire dal dashboard

1. Vai a **Admin → enforcement**.
2. Apri la macchina di destinazione.
3. Aggiungi la versione della policy con effetto **observe**.
4. Applica la distribuzione.
5. Rivedi i risultati sotto **Observe → policy**.
6. Promuovi la stessa versione a **enforce** quando le corrispondenze sono corrette.

![L'editor di distribuzione delle macchine con versioni delle policy, effetti enforce e observe, e l'azione apply deployment.](/images/dashboard/enforcement-editor.png)

## Sostituire o predisporre un set

- `--remove <id>` rimuove una policy.
- `--set <ref>...` sostituisce l'intero set di policy.
- `--create` prepara una distribuzione prima che una macchina si registri per la prima volta.
- `fp fleet diff <machine>` confronta lo stato previsto e quello applicato.

<Note>
  Senza Cloud, pubblica un pack con `failproofai publish --effect observe` e ispeziona le decisioni nel dashboard locale.
</Note>

Le macchine necessitano di `policies:pull` per ricevere le distribuzioni e `events:add` per segnalare le decisioni.
