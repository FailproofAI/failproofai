description: "Comprendi perché Failproof AI nega quando la valutazione non può essere eseguita."

---

Dopo la configurazione, il servizio locale `failproofaid` è l'unico valutatore. Se non riesce a rispondere, le azioni protette vengono negate anziché essere silenziosamente consentite.

## Diagnosticare un blocco a livello di macchina

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

Esegui `failproofai config` per riparare il servizio o installare la versione corrispondente.

Due errori possono sembrare simili:

| Errore | Significato |
| --- | --- |
| Servizio non raggiungibile | Il socket non ha alcun valutatore funzionante dietro di esso |
| Mancata corrispondenza di versione | La CLI e il servizio non sono d'accordo sul protocollo |

Entrambi negano, ma i report di stato li segnalano separatamente.

## Un pack non si carica

Un pack selezionato che è mancante, modificato o non valido nega gli eventi coperti dalle sue policy selezionate. Ciò impedisce che un pack rotto scompaia mentre la macchina appare protetta.

`failproofai policies` nomina il pack e l'errore di caricamento.

```bash
failproofai policies
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

I metadati illeggibili ampliano la negazione sicura anziché restringerla dai dati che non potevano essere considerati affidabili.

## Cosa rimane disponibile

La dashboard locale e i comandi di stato continuano a funzionare mentre la valutazione della policy sta fallendo. Usali per identificare il servizio, il pack o la versione che necessita riparazione.

<Warning>
  Non aggirare una decisione di negazione per errore eliminando i file del servizio o del pack. Ripara il servizio, reinstalla il pack o rimuovi l'assegnazione tramite la CLI in modo che la macchina torni a uno stato noto.
</Warning>
