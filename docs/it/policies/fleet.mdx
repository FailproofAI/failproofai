La copertura della flotta risponde alla domanda se una policy esiste dove esiste il rischio. Traccia le macchine tramite ID stabile ed etichetta leggibile, quindi confronta lo stato di distribuzione assegnato e segnalato.

## Verificare la copertura

<Tabs>
  <Tab title="Dashboard">
    1. Vai a **Admin → enforcement** e rivedi i totali di applicazione e osservazione.
    2. Cerca una macchina per ID o etichetta, oppure filtra le macchine a cui manca una policy.
    3. Espandi una riga per confrontare le policy assegnate, la distribuzione segnalata, l'ultimo check-in e la cronologia.
    4. Aggiorna dopo l'intervallo di polling della macchina quando una distribuzione applicata rimane in sospeso.

    ![La flotta Enforcement che mostra la copertura delle policy, lo stato di distribuzione della macchina e gli assegnamenti di osservazione e applicazione.](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    Usa `fp events --agent-id <agent-id> --since 24h` per confermare che l'attività dell'agente della macchina raggiunge Cloud.
  </Tab>
</Tabs>

Usa le visualizzazioni di copertura per trovare:

- Macchine che non hanno mai scaricato l'ultima distribuzione
- Macchine registrate che hanno smesso di segnalare attività
- Una policy assegnata all'ambiente o alla coorte sbagliata
- Variazione di versione dopo un aggiornamento interrotto

Rinomina una macchina senza riconnetterla:

```bash
failproofai config --machine-label checkout-runner-03
```

Verifica lo stato locale:

```bash
failproofai config --status
```

<Tip>
  Usa etichette che identifichino il carico di lavoro e l'ambiente. I soli nomi host sono spesso insufficienti dopo l'autoscaling o la sostituzione della macchina.
</Tip>
