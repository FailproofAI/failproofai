Usa lo scope per decidere chi riceve una policy locale:

| Scope | Si applica a |
| --- | --- |
| `user` | I tuoi agent supportati su questa macchina |
| `project` | Agent in esecuzione in questo progetto |
| `local` | Solo Claude, nelle impostazioni locali del progetto |
| `all` | Solo disinstallazione |

```bash
failproofai policies add block-sudo --scope user
failproofai policies add block-rm-rf --scope project
```

Hermes e OpenClaw supportano solo lo scope user. La maggior parte degli altri harness supporta user e project. Claude supporta anche lo scope local. Vedi [Harnesses](/it/reference/harnesses).

## Parametri delle policy

Le impostazioni delle policy risiedono in `policies-config.json` nello scope corrispondente. Quando possibile, usa la vista **Policies → Configure** del dashboard locale.

Un parametro appartiene a una sola policy e cambia il modo in cui quella policy decide. Ad esempio, una allow-list può far sì che una policy di blocco accetti comandi o percorsi noti come sicuri.

I file di policy personalizzati possono essere caricati automaticamente da `.failproofai/policies/`, o esplicitamente:

```bash
failproofai policies -i -c ./guards.mjs --scope project
```

Rimuovi i percorsi espliciti con:

```bash
failproofai policies -u -c
```

## File

| File | Scopo |
| --- | --- |
| `~/.failproofai/config.json` | Impostazioni della macchina e del collector |
| `policies-config.json` | Policy abilitate e parametri per uno scope |
| `.failproofai/policies/*policies.mjs` | Policy caricate per convenzione |
| `~/.failproofai/policies/packs/installed.json` | Pack installati e selezioni |

Non modificare direttamente gli artefatti dei pack installati. Reinstalla o pubblica una release corretta.
