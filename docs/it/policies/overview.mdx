Una politica monitora un'azione dell'agente e restituisce una di tre decisioni:

- `allow` consente di continuare.
- `instruct` fornisce indicazioni all'agente quando il suo harness lo supporta.
- `deny` blocca l'azione.

Usa le politiche per comportamenti noti e ripetibili: eliminazione di file protetti, esposizione di segreti, push su un ramo sbagliato o modifiche dell'infrastruttura di produzione.

## Aggiungi politiche a questa macchina

L'installazione non sceglie alcun pacchetto di politiche. Aggiungi il pacchetto Failproof AI dopo l'installazione:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai policies
```

Il pacchetto non contiene un pack built-in privilegiato. Il nostro si installa allo stesso modo di qualsiasi altro.

Le politiche possono provenire anche da un file locale, da un pacchetto pubblicato o da un'assegnazione Cloud:

| Origine | Aggiungila |
| --- | --- |
| File locale | Metti `*policies.{js,mjs,ts}` sotto `.failproofai/policies/` |
| Qualsiasi percorso di file | `failproofai policies -i -c <path>` |
| Pacchetto pubblicato | `failproofai policies add <owner>/<repo>` |
| Cloud | Assegnala nella dashboard o con `fp fleet deploy` |

`block-failproofai-commands` viene sempre eseguita e non può essere disattivata. Impedisce a un agente di disabilitare la propria imposizione.

## Osserva prima di applicare

La modalità osservazione esegue la vera politica e registra cosa avrebbe fatto, ma non blocca l'agente.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

<Warning>
  Un semplice `fp fleet deploy <machine> --add <id>` applica immediatamente. Aggiungi `:observe` per un rollout shadow.
</Warning>

Una politica che va in timeout in modalità osservazione registra un allow, perché è quello che accadrebbe durante l'imposizione. Vengono registrate solo le decisioni osservate non-allow.

Per un pacchetto utilizzato senza Cloud, pubblicalo con `failproofai publish --effect observe`.
