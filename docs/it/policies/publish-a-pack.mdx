Crea una policy funzionante, testala localmente, quindi pubblicala come pack.

## Crea e testa

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

`--init` scrive una policy che blocca già `git push --force`. Modificala, chiedi al tuo agente di provare l'azione bloccata, e controlla **Policies → Activity** nella dashboard locale.

Una policy pack può includere:

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-refunds",
  description: "Refunds above the limit need a human",
  category: "Billing",
  defaultEnabled: true,
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) => {
    // return allow(), instruct(), or deny()
  },
});
```

`defaultEnabled` è impostato di default a `false`.

## Pubblica

Effettua il commit dei tuoi file, quindi esegui:

```bash
failproofai publish
```

Publish trova il file della policy, lo valida con lo stesso loader utilizzato durante l'installazione, e carica gli asset del pack in una release su GitHub. Utilizza `GITHUB_TOKEN`, `GH_TOKEN`, o `gh auth login`.

Il repository deve essere pubblico perché l'installazione utilizza HTTPS anonimo.

La versione predefinita è lo SHA a 12 caratteri del commit attuale. Publish rifiuta un albero sporco o una directory al di fuori di Git a meno che tu non fornisca `--version`. Un tag su `HEAD` ha la precedenza rispetto allo SHA.

Gli utenti lo installano con:

```bash
failproofai policies add owner/repo
```

## Pubblica in modalità observe

```bash
failproofai publish --effect observe
```

La modalità observe valuta la policy reale e registra le decisioni non-allow, ma permette all'agente di continuare. Un timeout viene registrato come allow.

Pubblica di nuovo con `--effect enforce` quando le corrispondenze osservate sono corrette.

## Opzioni utili

| Flag | Effetto |
| --- | --- |
| `--init [file]` | Scrivi una policy di partenza |
| `--repo <owner>/<repo>` | Scegli o crea il repository |
| `--version <version>` | Sovrascrivi la versione basata sul commit |
| `--effect enforce|observe` | Scegli se il pack blocca |
| `--dry-run` | Compila e valida senza pubblicare |
| `--allow-private` | Pubblica privatamente, sapendo che `policies add` non può installarla |

```bash
failproofai publish --dry-run
failproofai publish ./guards.mjs --repo me/guards --version 2.0.0
```

<Note>
  Aggiungi l'argomento GitHub `failproofai-policies` dopo la pubblicazione affinché il [Policy Hub](https://befailproof.ai/policy-hub/) possa indicizzare il pack. La CLI non lo fa automaticamente per te.
</Note>

<Warning>
  Rinominare una policy è una modifica breaking per le selezioni esistenti. Mantieni i nomi stabili tra i rilasci.
</Warning>
