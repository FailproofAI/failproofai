Usa `fp` per ispezionare la telemetria Cloud, gestire l'enforcement gestito dal cloud (policy, distribuzioni della flotta, decisioni di guardrail) e gestire audit, risultati, problemi, avvisi, chiavi, utenti, query e impostazioni. Usa [`failproofai`](/it/reference/failproof-cli) per hook locali, policy, capture e registrazione delle macchine.

Puoi anche creare e distribuire codice ospitato, valutatori LLM-judge e Jev, gestire dashboard, ispezionare il sentiment e utilizzare l'assistente dashboard dal terminale.

Installa la Cloud CLI rilasciata come strumento isolato:

```bash
uv tool install fp-cloud-cli
fp version
```

## Accedi

```bash
fp login
fp whoami
```

## Sintassi

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Le opzioni globali devono venire prima del comando:

```bash
fp --json sessions --since 24h
```

Esegui `fp COMMAND --help` o `fp COMMAND SUBCOMMAND --help` per l'aiuto nel terminale.

## Comandi CLI

### Creare un valutatore

`fp evaluators` crea definizioni; `fp evals` legge i risultati. È richiesta un'istanza gestita abilitata (`fp evaluators instances`). La creazione richiede `evaluations:trigger`; le esecuzioni a secco della sessione e la profilazione dello schema richiedono anche `events:read`.

Il codice è un'espressione Python ristretta. Salva come `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

Giudice LLM:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Binario Jev e rubrica valutata:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
La creazione abilita il valutatore. Deploy crea una nuova versione immutabile, quindi disabilita le versioni abilitate più vecchie. Un follow-up non riuscito lascia la nuova versione pubblicata: ispeziona `evaluators list --all` prima di riprovare.
Le esecuzioni a secco del giudice sono rifiutate da Cloud. Le esecuzioni a secco di Jev consumano il budget del modello.
Il backfill copre valutatori di codice, giudice e Jev e accetta al massimo 90 giorni; mette in coda solo le sessioni che un valutatore non ha ancora valutato. I backfill di giudice e Jev consumano il budget del modello, quindi esegui prima `fp evaluators backfill --dry-run`.
L'output umano mostra i risultati dell'esecuzione a secco per sessione prima di creare/distribuire.
Le anteprime non riuscite interrompono la scrittura a meno che non passi esplicitamente `--force` dopo la revisione.
</Warning>

La bozza con IA richiede `fp login` e scrive una specifica accettata da create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Comando | Opzioni / comportamento |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Sorgente/envelope completa |
| `fp evaluators create` | `--key`, `--name`, `--version`, `--label` ripetuto, `--condition EXPR\|@file`, una sorgente, `--dry-run-on` ripetuto, `--disabled`, `--force` esplicito per anteprime non riuscite |
| `fp evaluators deploy KEY` | Stessi flag di sorgente; `--version`, `--backfill 7d` (qualsiasi tipo, 1–90 giorni), `--force`; le versioni numeriche si auto-incrementano; KEY fornisce un `eval_key` mancante da file di specifica |
| `fp evaluators draft "intent"` | Sessione; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Flag di sorgente o `--file`, `--session` ripetuto (massimo 10); nessuno = solo compilazione |
| `fp evaluators enable\|disable KEY[@VERSION]` | Attiva/disattiva |
| `fp evaluators label KEY[@VERSION]` | `--add` ripetuto, `--remove` |
| `fp evaluators instances\|schema\|jobs` | Ispeziona flotta/schema/job gestiti |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; codice, giudice e Jev |

I flag del codice sono `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. I flag del giudice sono `--judge --criteria TEXT`, `--step` ripetuto e
`--threshold`. I flag di Jev sono `--jev noul --instructions --true --false` o
`--jev score --instructions` con 3–5 distinti valori di `--level`, il peggiore per primo.
Giudice/Jev richiedono un punteggio; le soglie sono 0–1. I passaggi del giudice binario sono rifiutati.

I file di specifica contengono esattamente `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
`evaluator_source` di giudice/Jev è una stringa envelope JSON. Non includere ID di riga,
stato abilitato o metadati di ragionamento IA. `--file` e flag di specifica discreti si escludono a vicenda; deploy può ignorare la versione del file. I file di output non vengono mai sovrascritti.

### Nuovi controlli dashboard

Tutti i comandi accettano il global `--json`. I 404 di rotta sconosciuta escono 6 con non disponibile su questo FailproofAI Cloud ancora. I 404 di record mancante escono anche 6 ma segnalano che il record non è stato trovato. I comandi solo sessione negano la modalità chiave prima di HTTP (uscita 2).

I comandi umani utilizzano riepiloghi e tabelle. Per esportazioni JSON grezze, passa il global `--json` o salva con `--out FILE`; altrimenti le esportazioni di query di sessione e JSON mostrano una vista leggibile. Le esportazioni CSV rimangono CSV semplice per piping.

| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | Crea `--name`, `--description`, `--file` definizione; aggiorna conserva i campi non menzionati |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | Aggiungi `--query ID --chart TYPE --title`; config/geometria o layout via `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | Esporta `--out`; la cronologia è la cronologia della valutazione |
| `fp sessions import FILE...` | Trascritti Claude Code, distribuzioni Codex o JSONL di eventi (`.gz` ok); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; richiede `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; elenca `--limit`; messaggi `--session-id` |
| `fp query compose "question"` | Sessione; `--run` |
| `fp query export [ID]` | O `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | I problemi possono `--create --title --summary` o `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; aggiorna `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | Sessione; redige una policy dagli eventi della tua organizzazione, non pubblica mai |
| `fp policies backtest [FILE_OR_ID]` | Sessione; regex riproduce il modulo; `jev`/`both` (pubblicato, o `--semantic checks.json`) stima gratuitamente, `--run [--sample N]` consuma l'indennità Jev; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | Sessione; una policy potrebbe prevenire questo problema |
| `fp issues facets` | Valori che i filtri della posta in arrivo possono assumere, con conteggi |
| `fp agent brief` | Sessione; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | Sessione; deriva lo slug omesso, non cambia organizzazione |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | Insiemi di permessi; crea `--name --permission`; aggiorna sostituisci `--permission` o unisci `--add/--remove`; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | Eliminazione per id |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` ha bisogno di una chiave API; plan (offerte e trial) e claim richiedono una sessione connessa |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 token |
| `fp otel status\|enable\|disable` | Commutatore di acquisizione org Cloud, non capture locale |
| `fp slack status\|disconnect` | Sessione |

`fp agent ask` rende SQL di artefatto come tabelle/statistiche attraverso `queries:run`.
Le approvazioni di scrittura mostrano il cambiamento proposto e chiedono su un terminale. Gli script e `--json` rifiutano a meno che `--approve` non sia esplicito. Le forme JSON esistenti rimangono invariate quando nessun artefatto viene restituito.

```bash
fp login

fp whoami
```

Su un terminale, `fp login` inizia su un collegamento per accedere con il tuo browser o SSO e lo apre (su SSH o senza display mostra solo, e funziona da qualsiasi dispositivo); autorizzalo e il terminale finisce da solo. Quel terminale ottiene il tuo accesso in tutte le tue organizzazioni fino alla scadenza della sessione, quindi autorizza solo un collegamento che hai appena richiesto. Se l'accesso è iniziato su una rete diversa, ricevi un'email una volta che la sessione esiste e la pagina ti avverte dove la distribuzione può dire. Premi **Tab** per ricevere un codice di 6 cifre via email, e Tab di nuovo per tornare indietro. `--email`, `--json` e qualsiasi cosa senza un terminale usano il codice.

### Eventi

```text
fp events [OPTIONS]
```

Elenca i singoli eventi dell'agente. Il feed leggero predefinito esclude i payload grezzi; usa `--full` solo per un'indagine delimitata.

| Opzione | Descrizione |
| --- | --- |
| `--limit`, `-n <n>` | Numero massimo di righe totali. Predefinito: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, o `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Intervallo ISO 8601 UTC; ignora `--since`. |
| `--env <value>` | Filtro ambiente; ripeti o valori separati da virgola. |
| `--event-type <value>` | Filtro tipo evento; ripeti o valori separati da virgola. |
| `--agent-id <value>` | Filtro agente; ripeti o valori separati da virgola. |
| `--session-id <value>` | Filtro sessione; ripeti o valori separati da virgola. |
| `--search <text>` | Ricerca testo payload; ripetibile, con qualsiasi termine corrispondente. |
| `--order asc\|desc` | Ordine temporale. Predefinito: più recente per primo. |
| `--all` | Auto-pagina fino a `--limit`. |
| `--cursor <token>` | Riprendi da un cursore opaco. |
| `--page-size <n>` | Righe per richiesta con `--all`; massimo `200`. |
| `--full` | Includi payload grezzi tramite l'endpoint evento più pesante. |
| `--fields <csv>` | Restituisci solo i campi selezionati; richiedere `payload` abilita la modalità completa. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` pagina **fino a `--limit`**, che predefinito è **50** — quindi `--all` da solo si ferma a 50 righe. Quando si ferma presto la risposta contiene un `next_cursor` da cui riprendere; `"next_cursor": null` significa che il feed era davvero esaurito.
</Note>

#### Opzioni di creazione dell'audit

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Opzione | Descrizione |
| --- | --- |
| `--file <path>` | Basa la definizione su JSON, o usa `-` per stdin. I flag espliciti ignorano i valori del file. |
| `--description <text>` | Esponi la domanda di errore o lo scopo. |
| `--enabled` / `--disabled` | Avvia la pianificazione attiva o disattiva. Predefinito: abilitato. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Predefinito: `86400`. |
| `--schedule-anchor <timestamp>` | Fase UTC fissa in forma ISO 8601. Predefinito: prossime 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continua dopo l'ultima finestra completamente analizzata o ispeziona ripetutamente una finestra mobile. Predefinito: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Predefinito: `604800`. |
| `--scope '<json>'` | Filtra per `environments`, `agent_ids` o altri campi di scope supportati. |
| `--ignore-error-type <type>` | Escludi tipi di errore; ripeti o valori separati da virgola. |
| `--llm` / `--no-llm` | Abilita o disabilita l'analisi agentica. Predefinito: abilitato. |
| `--top-k <n>` | Conserva `1`–`500` risultati. Predefinito: `50`. |
| `--sensitivity low\|medium\|high` | Imposta la sensibilità di segnalazione. Predefinito: `medium`. |
| `--channels '<json>'` | Array di canale di notifica. |
| `--text <brief>` | Breve in linea, massimo 8.192 caratteri. |
| `--text-file <path>` | Leggi il breve da un file; mutuamente esclusivo con `--text`. |
| `--url <https-url>` | Aggiungi un riferimento HTTPS pubblico; ripeti fino a cinque volte. |

Includi contesto durante la creazione quando la prima esecuzione ne ha bisogno. La creazione impegna la definizione e il contesto insieme prima che l'esecuzione in coda inizi.

<Note>
  `fp audits run` è asincrono. Sonda `fp audits runs NAME` fino a quando l'ultima esecuzione non ha successo o fallisce prima di leggere i suoi risultati.
</Note>

### Policy

Versioni di policy gestite da Cloud. **Solo sessione** — ogni comando qui esce `2` sotto una chiave API, prima di qualsiasi richiesta, perché questi sono percorsi di scrittura solo root deliberatamente assenti da `/v1`.

| Comando | Scopo | Opzioni |
| --- | --- | --- |
| `fp policies list` | Elenca le versioni di policy, con il tipo di ciascuna (`regex`, `jev`, `both`) e i nomi di controllo Jev. | `--json` |
| `fp policies show POLICY_ID` | Mostra una policy, con la sua sorgente e i suoi controlli Jev. | — |
| `fp policies publish NAME [PATH]` | Mint una versione: JavaScript (`regex`, il predefinito), controlli Jev da un file JSON di dichiarazioni (`jev`), o entrambi, dove JavaScript è revisionabile dai suoi stessi controlli. | `--kind`; `--source`; `--semantic`; `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | Aggiungila di nuovo a ogni distribuzione da cui è stata rimossa, minando una nuova generazione su ciascuna. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | Rimuovila da ogni distribuzione che la trasporta, minando una nuova generazione su ciascuna. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | Elimina una versione di policy. | `--yes`, `-y` |
| `fp policies test PATH` | Esegui una policy localmente su un contesto sintetico. Applica il filtro `match` di ogni policy, quindi una che non copre l'evento/strumento dato è segnalata `skipped` piuttosto che eseguita. | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | Redigi una policy con l'assistente. Richiede `policies:write`. | — |

I flag espliciti ignorano le variabili di ambiente, che ignorano la configurazione salvata. In modalità chiave API, seleziona il tenant esplicitamente con `--org` o `FP_ORG`.

<Warning>
  Gli spelling `AGENTEYE_*` di questi **non sono letti da `fp`** e non lo sono mai stati — la CLI dichiara `FP_*` (`fp_cli/app.py`), e una variabile sconosciuta non è un errore. Impostare `AGENTEYE_DASHBOARD_URL` non rinclina la CLI; viene ignorato e il comando silenziosamente viene eseguito contro la dashboard salvata.

  `AGENTEYE_HOME` e `AGENTEYE_ENVIRONMENT` esistono ancora, ma appartengono al **collector e all'SDK telemetria**, non a questa CLI.
</Warning>

<Warning>
  I comandi che eliminano, revocano, sopprimono, risolvono o sostituiscono la configurazione richiedono per impostazione predefinita. Usa `--yes` solo dopo aver verificato l'organizzazione attiva e il target.
</Warning>
