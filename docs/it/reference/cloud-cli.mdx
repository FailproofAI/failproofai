Utilizza `fp` per ispezionare i dati telemetrici del Cloud, gestire l'applicazione delle policy cloud-managed (policy, distribuzioni della flotta, decisioni di guardrail), e gestire audit, risultati, problemi, avvisi, chiavi, utenti, query e impostazioni. Utilizza [`failproofai`](/it/reference/failproof-cli) per hook locali, policy, acquisizione e registrazione delle macchine.

Installa la Cloud CLI rilasciata come strumento isolato. Richiede Python 3.10 o versioni più recenti.

```bash
uv tool install fp-cloud-cli
fp version
```

La distribuzione è `fp-cloud-cli` e il comando installato è `fp` — differiscono perché `fp` era già stato utilizzato su PyPI.

## Accedi

`fp login` ti invia un codice a sei cifre tramite email e salva la sessione. Su un dashboard con certificato autofirmato, aggiungi `--insecure` al momento dell'accesso.

```bash
fp login
fp whoami
```

## Sintassi

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Le opzioni globali devono precedere il comando:

```bash
fp --json sessions --since 24h
```

Esegui `fp COMMAND --help` o `fp COMMAND SUBCOMMAND --help` per l'aiuto nel terminale.

### Eventi

```text
fp events [OPTIONS]
```

Elenca i singoli eventi dell'agent. Il feed leggero predefinito esclude i payload grezzi; usa `--full` solo per un'indagine limitata.

| Opzione | Descrizione |
| --- | --- |
| `--limit`, `-n <n>` | Numero massimo di righe totali. Default: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, o `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Intervallo ISO 8601 UTC; ignora `--since`. |
| `--env <value>` | Filtro ambiente; ripeti o separa i valori con virgola. |
| `--event-type <value>` | Filtro tipo di evento; ripeti o separa i valori con virgola. |
| `--agent-id <value>` | Filtro agent; ripeti o separa i valori con virgola. |
| `--session-id <value>` | Filtro sessione; ripeti o separa i valori con virgola. |
| `--search <text>` | Ricerca testo nel payload; ripetibile, qualsiasi termine corrisponde. |
| `--order asc\|desc` | Ordine temporale. Default: prima i più recenti. |
| `--all` | Pagina automaticamente fino a `--limit`. |
| `--cursor <token>` | Riprendi da un cursore opaco. |
| `--page-size <n>` | Righe per richiesta con `--all`; massimo `200`. |
| `--full` | Includi i payload grezzi tramite l'endpoint evento più pesante. |
| `--fields <csv>` | Restituisci solo i campi selezionati; richiedere `payload` abilita la modalità completa. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` pagina **fino a `--limit`**, che di default è **50** — quindi `--all` da solo si ferma a 50 righe. Quando si ferma prima il risultato contiene un `next_cursor` per riprendere; `"next_cursor": null` significa che il feed era veramente esaurito.
</Note>

#### Opzioni di creazione audit

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Opzione | Descrizione |
| --- | --- |
| `--file <path>` | Basa la definizione su JSON, o usa `-` per stdin. I flag espliciti ignorano i valori del file. |
| `--description <text>` | Dichiara la domanda di errore o lo scopo. |
| `--enabled` / `--disabled` | Avvia la pianificazione on o off. Default: abilitato. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Default: `86400`. |
| `--schedule-anchor <timestamp>` | Fase UTC fissa in forma ISO 8601. Default: prossime 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continua dopo l'ultima finestra completamente analizzata o ispeziona ripetutamente una finestra scorrevole. Default: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Default: `604800`. |
| `--scope '<json>'` | Filtra per `environments`, `agent_ids`, o altri campi di scope supportati. |
| `--ignore-error-type <type>` | Esclude tipi di errore; ripeti o separa con virgola. |
| `--llm` / `--no-llm` | Abilita o disabilita l'analisi agente. Default: abilitato. |
| `--top-k <n>` | Conserva `1`–`500` risultati. Default: `50`. |
| `--sensitivity low\|medium\|high` | Imposta la sensibilità della segnalazione. Default: `medium`. |
| `--channels '<json>'` | Array del canale di notifica. |
| `--text <brief>` | Breve inline, massimo 8.192 caratteri. |
| `--text-file <path>` | Leggi il breve da un file; mutuamente esclusivo con `--text`. |
| `--url <https-url>` | Aggiungi un riferimento HTTPS pubblico; ripeti fino a cinque volte. |

Includi il contesto durante la creazione quando la prima esecuzione lo richiede. La creazione conferma la definizione e il contesto insieme prima che inizi l'esecuzione in coda.

<Note>
  `fp audits run` è asincrono. Esegui il polling `fp audits runs NAME` finché l'esecuzione più recente non ha successo o non fallisce prima di leggerne i risultati.
</Note>

### Policy

Versioni di policy cloud-managed. **Solo sessione** — ogni comando qui eccetto `fp policies test` esce con codice `2` con una chiave API, prima di qualsiasi richiesta, perché questi sono percorsi di scrittura root-only deliberatamente assenti da `/v1`. `fp policies test` è l'eccezione deliberata: funziona interamente localmente contro `node` e non comunica con il server, quindi non porta né un requisito di autenticazione né un rifiuto della modalità chiave e funziona disconnesso e con una chiave API allo stesso modo.

| Comando | Scopo | Opzioni |
| --- | --- | --- |
| `fp policies list` | Elenca le versioni di policy, le più recenti di ogni policy per prime. | — |
| `fp policies show POLICY_ID` | Mostra una policy, con la sua fonte. | — |
| `fp policies publish POLICY_ID [SOURCE]` | Conia una nuova versione; non ne modifica una sul posto. `SOURCE` è un percorso, `@path`, o `-` per stdin — omettilo per incollare. | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | Aggiungila di nuovo a ogni distribuzione da cui è stata rimossa, coniando una nuova generazione su ognuna. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | Rimuovila da ogni distribuzione che la porta, coniando una nuova generazione su ognuna. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | Elimina una versione di policy. | `--yes`, `-y` |
| `fp policies test [SOURCE]` | Esegui una policy localmente contro un contesto sintetico. Applica il filtro `match` di ogni policy, quindi una che non copre l'evento/strumento dato viene segnalata come `skipped` piuttosto che eseguita. Richiede `node` su PATH. | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | Bozza una policy con l'assistente. Stampa la bozza e non fa nient'altro per default. Richiede `policies:write`. | `--out <path>`; `--publish <policy-id>` |

#### Riferimenti delle policy

`--add` e `--set` prendono un riferimento di policy, non un id bare:

| Forma | Significa |
| --- | --- |
| `id` | Versione corrente, effetto corrente |
| `id@3` | Versione 3, effetto corrente |
| `id:observe` | Versione corrente, registrato ma non applicato |
| `id@3:observe` | Versione 3, registrato ma non applicato |

L'effetto è `enforce` o `observe`. La risoluzione è: un effetto esplicito vince; altrimenti l'effetto già distribuito per quella policy; altrimenti `enforce`.

<Warning>
  Un `--add` bare **applica immediatamente**. `fp fleet deploy ci-runner-01 --add checkout-guard` inizia a bloccare su quella macchina non appena recupera. `:observe` è quello che rende un rollout shadow:

  ```bash
  fp fleet deploy ci-runner-01 --add checkout-guard:observe   # registra solo
  fp fleet deploy ci-runner-01 --add checkout-guard           # applica ora
  ```

  Observe non è spento. La policy è valutata per davvero, sotto lo stesso timeout di 10 secondi e la stessa gestione degli errori come una applicata, e ogni verdetto non-allow è registrato — solo l'applicazione è trattenuta. Questo è quello che rende la misurazione degna di leggere.
</Warning>

#### Delta, sostituzione e gare

`--add` e `--remove` leggono il set corrente della macchina e applicano un delta, quindi nulla di quello che non hai nominato è disturbato. Un `--add` bare su una policy che la macchina esegue già mantiene la versione bloccata piuttosto che aggiornarla silenziosamente; passa `id@version` per spostarla.

`--set` sostituisce tutto ed è l'unico modo per rilasciare le policy che non nomini. Non può essere combinato con `--add` o `--remove`. Non passare nessuno dei tre è un errore di utilizzo, non un no-op.

```bash
fp fleet deploy ci-runner-01 --add prod-guard@1:observe --remove old-rule
fp fleet deploy ci-runner-01 --set no-force-push --set no-secret-echo
```

La scrittura stessa è una sostituzione completa su ogni percorso, perché l'endpoint prende l'intero set di policy. Non c'è un blocco lato server, quindi la CLI registra la generazione che ha letto e rifiuta se il risultato non è esattamente uno in più — questo significa che qualcun altro ha distribuito in mezzo, e una sostituzione non si unisce. Rileggi con `fp fleet show`, quindi distribuisci di nuovo.

`--create` distribuisce a un id di macchina che non ha ancora fatto check-in, per pre-staging. Senza di esso, un id che il server non conosce è rifiutato, perché un errore di digitazione altrimenti conirebbe una macchina che nessuno possiede portando policy che nessuno raccoglie.

### Guardrail

Cosa l'applicazione ha effettivamente fatto. **Solo sessione**, stesso motivo di cui sopra.

| Comando | Scopo | Opzioni |
| --- | --- | --- |
| `fp guardrails summary` | Copertura, totali bloccati/valutati, una sparkline di negazione, e la tabella per-policy. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |
| `fp guardrails timeline` | Decisioni raggruppate sulla finestra, sommate su ogni fonte di policy. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |

Una riga `(no policy)` nel riepilogo è normale piuttosto che un vuoto: la maggior parte delle valutazioni sono allow a cui nulla ha obiezionato, e la riga mantiene il denominatore sullo schermo.

### Distribuisci una policy senza rompere nessuno

I tre gruppi sopra sono una sequenza. Decidi localmente, pubblica, ombra, misura, quindi applica.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

| Passaggio | Perché è lì |
| --- | --- |
| `fp policies test` | Nessun server e nessuna autenticazione. Esegui il file reale contro un contesto che descrivi e stampa allow, deny, o instruct per ogni policy registrata. `--expect` trasforma questo in un'asserzione CI. |
| `fp policies publish` | Conia una nuova versione immutabile; non ne modifica una sul posto. |
| `fp fleet deploy --add <id>:observe` | Il rollout shadow. **`:observe` non è opzionale qui** — un `--add` bare applica il momento in cui la macchina recupera. |
| `fp guardrails summary` | Separa le corrispondenze non sicure dal lavoro legittimo che la policy avrebbe anche bloccato. |
| `fp fleet deploy --add <id>:enforce` | Promozione, una volta che i verdetti registrati dicono quello che ti aspettavi. |
| `fp fleet rollback <machine> <generation>` | La strada indietro se l'applicazione va storta. |

L'equivalente single-machine, senza Cloud coinvolto, è pubblicare il pack con `failproofai publish --effect observe` e leggere i verdetti registrati sul [dashboard locale](/it/reference/local-dashboard).

## Flag globali

| Flag | Descrizione |
| --- | --- |
| `--json` | Emetti JSON leggibile da macchina. |
| `--base-url <url>` | Usa un dashboard self-hosted o di sviluppo. |
| `--org <slug>` | Seleziona un'organizzazione per questo invocazione. |
| `--token <token>` | Ignora il token della sessione utente salvato. |
| `--api-key <key>` | Autentica l'automazione con una chiave API; mai salvata. |
| `--timeout <seconds>` | Timeout HTTP; deve essere positivo. Default: `30`. |
| `--quiet`, `-q` | Sopprimi l'output di stato su stderr. |
| `--no-color` | Disabilita l'output colorato. |
| `--insecure` / `--secure` | Disabilita o ripristina la verifica del certificato TLS. |
| `--version` | Stampa la versione non scatolata ed esci. |
| `--help`, `-h` | Mostra l'aiuto. |

`--api-key` è destinato all'automazione. L'accesso, il cambio di organizzazione e i comandi dell'assistente richiedono una sessione utente.

## Variabili di ambiente

| Variabile | Equivalente o scopo |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | Trasferisci la directory di configurazione della CLI (default `~/.failproofai/fpcli`). |
| `FP_ANALYTICS_DISABLED` o `DO_NOT_TRACK` | Disabilita l'analisi anonima della CLI. |
| `NO_COLOR` | Disabilita l'output colorato. |

I flag espliciti ignorano le variabili di ambiente, che ignorano la configurazione salvata.

In modalità chiave API l'organizzazione salvata da un `fp login` umano è **ignorata**, non meramente ignora — solo un `--org` esplicito o `FP_ORG` è inviato. Nulla è ereditato da un login salvato, quindi passa `--org` ogni volta che la chiave può agire per più di un'organizzazione. Ometterla non fallisce ad alta voce: una chiave con scope di istanza senza `--org` si risolve lato server nell'organizzazione **default** e risponde con i dati di quell'organizzazione, senza errore da nessuna parte. Esegui `fp whoami` prima per confermare quale tenant una chiave sta effettivamente comunicando con.

<Warning>
  I nomi `AGENTEYE_*` di questi **non sono letti da `fp`** e non lo sono mai stati — la CLI dichiara `FP_*` (`fp_cli/app.py`), e una variabile sconosciuta non è un errore. Impostare `AGENTEYE_DASHBOARD_URL` non retarget la CLI; è ignorato e il comando silenziosamente esegue contro il dashboard salvato.

  `AGENTEYE_HOME` e `AGENTEYE_ENVIRONMENT` ancora esistono, ma appartengono al **collettore e all'SDK telemetria**, non a questa CLI.
</Warning>

<Warning>
  I comandi che eliminano, revocano, sopprimono, risolvono, o sostituiscono la configurazione richiedono conferma per default. Usa `--yes` solo dopo aver verificato l'organizzazione attiva e il target.
</Warning>
