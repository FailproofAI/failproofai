Usa `fp` per ispezionare la telemetria del Cloud, gestire l'enforcement gestito dal cloud (policy, distribuzioni di flotta, decisioni di guardrail) e gestire audit, finding, problemi, avvisi, chiavi, utenti, query e impostazioni. Usa [`failproofai`](/it/reference/failproof-cli) per hook locali, policy, acquisizione e iscrizione di macchine.

Puoi anche scrivere e distribuire codice ospitato, valutatori LLM-judge e Jev, gestire dashboard, ispezionare il sentiment e utilizzare l'assistente dashboard dal terminale.

Installa il Cloud CLI rilasciato come strumento isolato:

```bash
uv tool install fp-cloud-cli
fp version
```

## Accedi

```bash
fp login
fp whoami
```

## Sintassi

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Le opzioni globali devono precedere il comando:

```bash
fp --json sessions --since 24h
```

Esegui `fp COMMAND --help` o `fp COMMAND SUBCOMMAND --help` per l'aiuto nel terminale.

## Comandi CLI

### Scrivi un valutatore

`fp evaluators` scrive definizioni; `fp evals` legge i risultati. È richiesta un'istanza gestita abilitata (`fp evaluators instances`). La scrittura necessita di `evaluations:trigger`; le esecuzioni di prova della sessione e la profilatura dello schema necessitano anche di `events:read`.

Il codice è un'espressione Python limitata. Salva questo come `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

Giudice LLM:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Binario Jev e rubrica con valutazione:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
La creazione abilita il valutatore. Deploy crea una nuova versione immutabile, quindi disabilita le versioni abilitate precedenti. Un follow-up fallito lascia la nuova versione pubblicata: ispeziona `evaluators list --all` prima di riprovare.
I dry-run del giudice vengono rifiutati dal Cloud. I dry-run di Jev consumano il budget del modello.
Il backfill copre valutatori di codice, giudice e Jev e accetta al massimo 90 giorni; accoda solo le sessioni che un valutatore non ha ancora valutato. I backfill di giudice e Jev consumano il budget del modello, quindi esegui prima `fp evaluators backfill --dry-run`.
L'output umano mostra i risultati del dry-run per sessione prima di creare/distribuire.
Le anteprime non riuscite interrompono la scrittura a meno che non passi esplicitamente `--force` dopo la revisione.
</Warning>

La stesura AI richiede `fp login` e scrive una specifica accettata da create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Comando | Opzioni / comportamento |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Source/envelope completo |
| `fp evaluators create` | `--key`, `--name`, `--version`, `--label` ripetuto, `--condition EXPR\|@file`, una source, `--dry-run-on` ripetuto, `--disabled`, `--force` esplicito per anteprime non riuscite |
| `fp evaluators deploy KEY` | Stessi flag di source; `--version`, `--backfill 7d` (qualsiasi tipo, 1–90 giorni), `--force`; le versioni numeriche si incrementano automaticamente; KEY fornisce un `eval_key` di spec-file mancante |
| `fp evaluators draft "intent"` | Sessione; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Flag di source o `--file`, `--session` ripetuto (massimo 10); nessuno = solo compilazione |
| `fp evaluators enable\|disable KEY[@VERSION]` | Attiva/disattiva |
| `fp evaluators label KEY[@VERSION]` | `--add` ripetuto, `--remove` |
| `fp evaluators instances\|schema\|jobs` | Ispeziona flotta/schema/job gestiti |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; codice, giudice e Jev |

I flag del codice sono `--code FILE|-`, `--result-kind score|metric|assertion`, `--timeout S`. I flag del giudice sono `--judge --criteria TEXT`, `--step` ripetuto e `--threshold`. I flag di Jev sono `--jev noul --instructions --true --false` o `--jev score --instructions` con 3–5 valori `--level` distinti, dal peggiore al migliore.
Giudice/Jev richiedono un punteggio; i threshold sono 0–1. I passaggi del giudice binario vengono rifiutati.

I file di specifica contengono esattamente `eval_key`, `display_name`, `eval_version`, `result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
Il `evaluator_source` di giudice/Jev è una stringa con envelope JSON. Non includere ID riga, stato abilitato o metadati di ragionamento AI. `--file` e flag di specifica discreti si escludono a vicenda; deploy può sovrascrivere la versione del file. I file di output non vengono mai sovrascritti.

### Nuovi controlli dashboard

Tutti i comandi accettano il globale `--json`. I 404 per route sconosciute escono con 6 e non available on this FailproofAI Cloud yet. I 404 per record mancanti escono anche con 6 ma segnalano che il record non è stato trovato. I comandi solo sessione negano il modo chiave prima di HTTP (uscita 2).

I comandi umani usano riepiloghi e tabelle. Per le esportazioni JSON grezze, passa il globale `--json` o salva con `--out FILE`; altrimenti le esportazioni di sessione e query JSON mostrano una visualizzazione leggibile. Le esportazioni CSV rimangono in CSV semplice per il piping.

| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; elenco `--limit`; messaggi `--session-id` |
| `fp query compose "question"` | Sessione; `--run` |
| `fp query export [ID]` | O `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | I problemi possono `--create --title --summary` o `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; aggiorna `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | Sessione; bozza una policy dagli eventi della tua organizzazione, non pubblica mai |
| `fp policies backtest [FILE_OR_ID]` | Sessione; regex ripete il modulo; `jev`/`both` (pubblicato, o `--semantic checks.json`) stima gratuitamente, `--run [--sample N]` spende l'indennità Jev; `--kind`, `--hours`, `--agent-id`, `--env` |

| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 token |
| `fp otel status\|enable\|disable` | Switch di ingest dell'organizzazione Cloud, non acquisizione locale |
| `fp slack status\|disconnect` | Sessione |

`fp agent ask` rende SQL artefatto come tabelle/statistiche tramite `queries:run`.
Le approvazioni di scrittura mostrano il cambiamento proposto e richiedono sul terminale. Gli script e `--json` rifiutano a meno che `--approve` non sia esplicito. Le forme JSON esistenti rimangono invariate quando non viene restituito alcun artefatto.

### Eventi

```text
fp events [OPTIONS]
```

Elenca i singoli eventi dell'agente. Il feed leggero predefinito esclude i payload grezzi; usa `--full` solo per un'indagine limitata.

| Opzione | Descrizione |
| --- | --- |
| `--limit`, `-n <n>` | Righe totali massime. Predefinito: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, o `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Intervallo ISO 8601 UTC; sovrascrive `--since`. |
| `--env <value>` | Filtro ambiente; ripeti o separa con virgola i valori. |
| `--event-type <value>` | Filtro event-type; ripeti o separa con virgola i valori. |
| `--agent-id <value>` | Filtro agente; ripeti o separa con virgola i valori. |
| `--session-id <value>` | Filtro sessione; ripeti o separa con virgola i valori. |
| `--search <text>` | Ricerca testo payload; ripetibile, con qualsiasi termine che corrisponda. |
| `--order asc\|desc` | Ordine temporale. Predefinito: più recente per primo. |
| `--all` | Impaginazione automatica fino a `--limit`. |
| `--cursor <token>` | Riprendi da un cursore opaco. |
| `--page-size <n>` | Righe per richiesta con `--all`; massimo `200`. |
| `--full` | Includi payload grezzi tramite l'endpoint evento più pesante. |
| `--fields <csv>` | Restituisci solo i campi selezionati; richiedere `payload` abilita la modalità completa. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` impagina **fino a `--limit`**, che per impostazione predefinita è **50** — quindi `--all` da solo si ferma a 50 righe. Quando si ferma presto, la risposta contiene un `next_cursor` per riprendere; `"next_cursor": null` significa che il feed era davvero esaurito.
</Note>

#### Opzioni creazione audit

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Opzione | Descrizione |
| --- | --- |
| `--file <path>` | Basa la definizione su JSON, o usa `-` per stdin. I flag espliciti sovrascrivono i valori del file. |
| `--description <text>` | Dichiara la domanda di fallimento o lo scopo. |
| `--enabled` / `--disabled` | Avvia la programmazione attivata o disattivata. Predefinito: abilitato. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Predefinito: `86400`. |
| `--schedule-anchor <timestamp>` | Fase UTC fissa in forma ISO 8601. Predefinito: prossimo 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continua dopo la finestra completamente analizzata più recente o ispeziona ripetutamente una finestra mobile. Predefinito: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Predefinito: `604800`. |
| `--scope '<json>'` | Filtra per `environments`, `agent_ids` o altri campi di ambito supportati. |
| `--ignore-error-type <type>` | Escludi tipi di errore; ripeti o separa con virgola. |
| `--llm` / `--no-llm` | Abilita o disabilita l'analisi agentiva. Predefinito: abilitato. |
| `--top-k <n>` | Conserva `1`–`500` finding. Predefinito: `50`. |
| `--sensitivity low\|medium\|high` | Imposta la sensibilità di segnalazione. Predefinito: `medium`. |
| `--channels '<json>'` | Array del canale di notifica. |
| `--text <brief>` | Breve inline, massimo 8.192 caratteri. |
| `--text-file <path>` | Leggi il breve da un file; mutualmente esclusivo con `--text`. |
| `--url <https-url>` | Aggiungi un riferimento HTTPS pubblico; ripeti fino a cinque volte. |

Includi il contesto durante la creazione quando la prima esecuzione lo necessita. La creazione impegna la definizione e il contesto insieme prima che l'esecuzione accodata inizi.

<Note>
  `fp audits run` è asincrono. Esegui il polling di `fp audits runs NAME` fino a quando l'esecuzione più recente non riesce o fallisce prima di leggere i suoi finding.
</Note>

<Warning>
  Le ortografie `AGENTEYE_*` di queste **non vengono lette da `fp`** e non lo sono mai state — il CLI dichiara `FP_*` (`fp_cli/app.py`), e una variabile sconosciuta non è un errore. Impostare `AGENTEYE_DASHBOARD_URL` non reindirizza il CLI; viene ignorato e il comando viene eseguito silenziosamente rispetto al dashboard salvato.

  `AGENTEYE_HOME` e `AGENTEYE_ENVIRONMENT` esistono ancora, ma appartengono al **raccoglitore e al telemetry SDK**, non a questo CLI.
</Warning>

<Warning>
  I comandi che eliminano, revocano, sopprimono, risolvono o sostituiscono la configurazione richiedono per impostazione predefinita. Usa `--yes` solo dopo aver verificato l'organizzazione attiva e il target.
</Warning>
