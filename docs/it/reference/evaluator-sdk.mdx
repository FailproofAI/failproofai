Un valutatore riceve una sessione agente completata e restituisce i segnali di qualità che ti interessano: punteggi numerici, una spiegazione per ogni punteggio e un riepilogo opzionale. Failproof AI memorizza questi risultati accanto alla traccia e li traccia tra agenti e ambienti.

## Configura un valutatore

<Steps>
  <Step title="Installa l'Evaluator SDK">
    Installa l'SDK e il server utilizzato per eseguirlo.

    ```bash
    pip install failproofai-sdk uvicorn
    ```
  </Step>

  <Step title="Definisci cosa valutare">
    Crea `evaluator.py`. Questo esempio controlla se una sessione contiene chiamate di strumento non riuscite.

    ```python
    import os
    from failproofai.evaluator import Evaluator, EvalResponse

    app = Evaluator(token=os.environ.get("EVALUATOR_TOKEN"))

    @app.config
    def config():
        return {"inactivity_timeout_secs": 1800}

    @app.evaluator
    def evaluate(req):
        tool_errors = sum(
            1 for item in req.events
            if item.event_type == "tool_result" and item.payload.get("error")
        )
        return EvalResponse(
            scores={"tool_reliability": 1.0 if tool_errors == 0 else 0.0},
            reasoning={"tool_reliability": f"{tool_errors} tool errors"},
        )
    ```
  </Step>

  <Step title="Esegui e testa localmente">
    Imposta un token condiviso, avvia il valutatore e conferma che il suo endpoint di salute risponde.

    ```bash
    export EVALUATOR_TOKEN=<shared-token>
    uvicorn evaluator:app --host 0.0.0.0 --port 8080
    ```

    In un altro terminale:

    ```bash
    curl http://127.0.0.1:8080/health
    ```
  </Step>
</Steps>

## Connetti il valutatore a Failproof AI

1. Distribuisci il valutatore in un URL HTTPS raggiungibile da Failproof AI Cloud.
2. Configura `EVALUATOR_ENDPOINT` con quell'URL e imposta `EVALUATOR_TOKEN` sullo stesso token utilizzato dal valutatore. Per Cloud gestito, contatta [support@befailproof.ai](mailto:support@befailproof.ai) per configurare la connessione.
3. Esegui una valutazione e conferma che i suoi punteggi vengono visualizzati in Failproof AI.

<Tabs>
  <Tab title="Dashboard">
    Apri una sessione completata in **Observe → Sessions** e seleziona **Run evaluation** se non è stata valutata automaticamente. Esamina lo stato, i punteggi, il ragionamento e il riepilogo nel pannello **Evaluation** della sessione.

    Usa **Observe → Evaluations** per confrontare i punteggi tra agenti o ambienti. Usa **Observe → Metrics** per latenza, costo, token e altre misurazioni numeriche.

    Inizia con una sessione per confermare che il valutatore ha restituito le chiavi di punteggio previste e un ragionamento utile per quella specifica esecuzione.

    ![Una vista dei dettagli della sessione che mostra i punteggi di valutazione e il ragionamento accanto alla sua traccia.](/images/dashboard/session-detail.png)

    Una volta che i risultati individuali sono corretti, utilizza il dashboard di valutazione per confrontare questi punteggi nel tempo e tra agenti o ambienti.

    ![Un dashboard di qualità che traccia i punteggi del valutatore nel tempo.](/images/dashboard/dashboard-quality.png)

Per un'istanza Cloud auto-ospitata, la valutazione automatica è disabilitata fino a quando `EVALUATOR_ENDPOINT` non è impostato nel processo server. Riavvia il server dopo aver modificato le variabili di ambiente del valutatore.

Il servizio espone `GET /health`, `GET /config`, `POST /evaluate` e facoltativamente `GET /evaluate/{job_id}`. Restituisci `JobPending` per il lavoro asincrono e registra `@app.job_lookup` in modo che Failproof AI possa eseguirne il polling.

Quando un token è configurato, tutte le route ad eccezione health richiedono lo stesso bearer token che Failproof AI invia come `EVALUATOR_TOKEN`.

## Tipi SDK

| Tipo | Campi |
| --- | --- |
| `AgentEvent` | `id`, `ts`, `event_type`, `payload` |
| `EvalRequest` | `schema_version`, `session_id`, `agent_id`, `environment`, `started_at`, `ended_at`, `events` |
| `EvalResponse` | `scores`, `reasoning`, `summary` |
| `JobPending` | `job_id`, `next_poll_secs` |
| `EvaluatorConfig` | `inactivity_timeout_secs`, `default_poll_interval_secs` |

## Decoratori e route

| Decoratore | Route | Obbligatorio |
| --- | --- | --- |
| `@app.evaluator` | `POST /evaluate` | Sì |
| `@app.job_lookup` | `GET /evaluate/{job_id}` | Quando si restituisce `JobPending` |
| `@app.config` | `GET /config` | No |

L'SDK limita i corpi delle richieste di valutazione a 25 MiB. I campi di richiesta sconosciuti vengono ignorati in modo che i servizi rimangano compatibili man mano che il contratto di evento cresce.

## Restituisci il lavoro asincrono

Usa `JobPending` quando la valutazione non può essere completata in un'unica richiesta. L'ID del lavoro è opaco per Failproof AI e deve rimanere risolvibile dal tuo servizio fino a quando il risultato non viene raccolto o il timeout del server non scade.

```python
from failproofai.evaluator import EvalRequest, EvalResponse, Evaluator, JobPending

app = Evaluator(token="shared-secret")

@app.evaluator
def start(req: EvalRequest) -> JobPending:
    job_id = enqueue(req)
    return JobPending(job_id=job_id, next_poll_secs=30)

@app.job_lookup
def lookup(job_id: str):
    result = get_result(job_id)
    if result is None:
        return JobPending(job_id=job_id, next_poll_secs=30)
    return EvalResponse(
        scores=result.scores,
        reasoning=result.reasoning,
        summary=result.summary,
    )
```

La cadenza di polling viene selezionata in questo ordine: `JobPending.next_poll_secs`, `EvaluatorConfig.default_poll_interval_secs`, quindi `EVALUATOR_POLLING_INTERVAL_SECS` del server. I valori sono limitati tra 1 secondo e 1 ora. Il limite di polling a orologio da parete predefinito del server è un'ora.

## Campi di richiesta e risposta

| Campo | Tipo | Note |
| --- | --- | --- |
| `EvalRequest.schema_version` | `str` | Attualmente `"1"`. |
| `session_id`, `agent_id`, `environment` | `str` | Identità della sessione e ambiente. |
| `started_at` | `datetime` | Timestamp del primo evento. |
| `ended_at` | `datetime \| None` | Presente quando la sessione ha emesso un evento di fine. |
| `events` | `list[AgentEvent]` | Flusso di eventi ordinato completo. |
| `AgentEvent.id` | `int` | Identificatore della riga dell'evento del backend. |
| `AgentEvent.ts` | `datetime` | Timestamp dell'evento. |
| `AgentEvent.event_type` | `str` | Famiglia di eventi come `tool_use`. |
| `AgentEvent.payload` | `dict[str, Any]` | Payload dell'evento completo. |
| `EvalResponse.scores` | `dict[str, float] \| None` | Dimensioni numeriche tracciate nelle valutazioni. |
| `EvalResponse.reasoning` | `dict[str, str] \| None` | Spiegazioni per punteggio; le chiavi dovrebbero rispecchiare `scores`. |
| `EvalResponse.summary` | `str \| None` | Narrativa di valutazione complessiva. |

## Impostazioni dell'operatore del server

La valutazione automatica è a livello di distribuzione e rimane disabilitata quando `EVALUATOR_ENDPOINT` è assente.

| Variabile | Predefinito | Scopo |
| --- | --- | --- |
| `EVALUATOR_ENDPOINT` | non impostato | URL di base del servizio valutatore. |
| `EVALUATOR_TOKEN` | non impostato | Bearer token condiviso con `Evaluator(token=...)`. |
| `EVALUATOR_WORKERS` | `2` | Lavoratori del dispatcher concorrenti. |
| `EVALUATOR_CLAIM_BATCH` | `4` | Sessioni rivendicate per passaggio del dispatcher. |
| `EVALUATOR_POLLING_INTERVAL_SECS` | `10` | Cadenza di polling asincrono di fallback. |
| `EVALUATOR_REQUEST_TIMEOUT_MS` | `30000` | Timeout del valutatore per richiesta. |
| `EVALUATOR_MAX_ATTEMPTS` | `5` | Tentativi di consegna prima del fallimento terminale. |
| `EVALUATOR_CONFIG_REFRESH_SECS` | `300` | Cadenza di aggiornamento per `/config`. |
| `EVALUATOR_MAX_POLL_DURATION_SECS` | `3600` | Tempo di polling asincrono massimo a orologio da parete. |

Il server può anche vincolare quali organizzazioni utilizzano il valutatore globale a livello di distribuzione. Tratta le modifiche di endpoint, token, retry e organizzazione-gate come configurazione dell'operatore e riavvia o implementa il server dopo aver modificato queste impostazioni.

## Sicurezza e operazioni

- Metti il valutatore dietro HTTPS quando il traffico attraversa un confine di rete affidabile.
- Configura un bearer token non vuoto e mantienilo identico su entrambi i servizi.
- Non registrare il token o i prompt sensibili completi dai payload delle richieste.
- Rendi i gestori sincroni idempotenti; i tentativi possono ripetere una richiesta.
- Persisti lo stato del lavoro asincrono al di fuori della memoria del processo in produzione.
- Restituisci chiavi di punteggio stabili. Rinominare una chiave crea una nuova serie di grafici invece di modificare quella vecchia.

L'SDK emette log del ciclo di vita strutturati come `eval received`, `eval responded`, `job lookup`, `config returned`, `auth rejected` e eccezioni del gestore. Non configura gestori di logging; utilizza la configurazione di logging dell'applicazione host.
