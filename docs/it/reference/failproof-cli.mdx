Installa con `npm install -g failproofai`. Esegui `failproofai` senza argomenti per aprire il dashboard locale.

## Comandi principali

| Comando | Cosa fa |
| --- | --- |
| `failproofai config` | Configura gli agenti, il servizio in background e la connessione Cloud opzionale |
| `failproofai config --token <key>` | Configura e connetti senza domande |
| `failproofai config --status` | Mostra lo stato della connessione, la versione del servizio e lo stato di pausa |
| `failproofai policies` | Elenca le policy e se sono attive |
| `failproofai policies add <name>` | Attiva una policy |
| `failproofai policies add <owner>/<repo>` | Installa un policy pack |
| `failproofai policies remove <name-or-pack>` | Disattiva una policy o rimuovi un pack |
| `failproofai policies show <owner>/<repo>` | Ispeziona un pack prima di installarlo |
| `failproofai publish` | Pubblica le tue policy come pack |
| `failproofai audit` | Scansiona la cronologia degli agenti locali |
| `failproofai harness` | Gestisci posizioni di sessione aggiuntive |
| `failproofai flush` | Invia subito gli eventi in coda |
| `failproofai backfill` | Rileggi la cronologia più vecchia degli agenti |
| `failproofai update` | Completa un aggiornamento npm e aggiorna il servizio |
| `failproofai uninstall` | Rimuovi i hook e il servizio |

`policy`, `pack` e `p` sono accettati come alias per `policies`, ma la documentazione usa `policies`.

## Configura una macchina

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

La configurazione non sceglie alcun policy pack. Prima di aggiungerne uno, viene eseguito solo `block-failproofai-commands`.

Per la configurazione Cloud automatica:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Per inviare decisioni senza trascrizioni, connetti prima e imposta `collector.sessions` su `false` in `~/.failproofai/config.json`. Il flag di configurazione `--no-transcripts` attuale viene analizzato ma non applica quella impostazione.

Usa `--machine-label <name>` dopo che la macchina è collegata per rinominarla. `--connect <url>` è il comando di iscrizione più ristretto per una macchina già configurata.

## Policy e pack

```bash
failproofai policies
failproofai policies add block-sudo
failproofai policies show owner/repo
failproofai policies add owner/repo --category git,database
failproofai policies remove owner/repo
```

Qualsiasi cosa con una barra è una fonte pack; qualsiasi cosa senza è un nome di policy.

Flag utili per la selezione dei pack:

| Flag | Uso |
| --- | --- |
| `--policy a,b` | Seleziona policy nominate |
| `--category x,y` | Seleziona categorie |
| `--all` | Seleziona tutto |
| `--cli <agents...>` | Limita ai harness nominati |

Usa `failproofai policies -i -c <path>` per caricare una policy personalizzata da qualsiasi percorso. I file di convenzione denominati `*policies.{js,mjs,ts}` in `.failproofai/policies/` si caricano automaticamente.

## Pausa dell'enforcement

```bash
failproofai config --pause 10m
failproofai config --status
failproofai config --resume
```

Una pausa si applica a una sessione locale e scade sempre. Non mette in pausa le policy gestite dal Cloud o `block-failproofai-commands`.

## Audit e consegna

```bash
failproofai audit
failproofai audit --schedule 7 --email team@example.com
failproofai audit --status
failproofai flush --wait
failproofai backfill --since 30d --dry-run
```

`backfill` legge `~/.failproofai/config.json`. Rimuovi `--dry-run` per inviare di nuovo la cronologia.

## Posizioni di sessione aggiuntive

```bash
failproofai harness list
failproofai harness add-path claude work=/srv/team/.claude/projects
failproofai harness remove-path claude work
```

Le etichette impediscono alle sessioni da due home copiate di unirsi con lo stesso ID agente derivato.

Gli harness supportati sono `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity` e `goose`. Il supporto dello scope varia; vedi [Harnesses](/it/reference/harnesses).

## Variabili d'ambiente utili

| Variabile | Uso |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | Chiave della macchina Cloud |
| `FAILPROOFAI_CLOUD_URL` | Sovrascrivi l'URL del Cloud |
| `FAILPROOFAI_HOME` | Sposta la directory dello stato locale |
| `FAILPROOFAI_NO_DOWNLOAD=1` | Rifiuta i download di pack e servizi |
| `FAILPROOFAI_DAEMON_BASE_URL` | Usa uno specchio binario del servizio |
| `FAILPROOFAI_PACK_BASE_URL` | Usa uno specchio pack |
| `FAILPROOFAI_NO_FIRST_RUN=1` | Disabilita i prompt al primo avvio |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | Disabilita la telemetria CLI anonima |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | Sostituisci i percorsi aggiuntivi per un harness |
| `NO_COLOR` | Disabilita il colore del terminale |

## Rimuovi o aggiorna

```bash
npm install -g failproofai@latest
failproofai update
```

Prima di rimuovere il pacchetto:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

<Warning>
  Esegui `failproofai uninstall` prima di rimuovere il pacchetto npm. npm non rimuove i hook installati o il servizio in background.
</Warning>

Esegui `failproofai help <command>` per le opzioni complete nella tua versione installata.
