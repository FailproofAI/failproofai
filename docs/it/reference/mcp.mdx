Collega uno strumento AI a Failproof AI Cloud e lavora con i dati dei tuoi agenti da esso. Il tuo strumento può interrogare sessioni ed eventi, eseguire SQL di sola lettura, leggere dashboard, avvisi, problemi, audit e politiche, e, se disponi dell'autorizzazione, apportare modifiche come creare un avviso o distribuire una politica.

Ogni chiamata viene eseguita con **le tue proprie** autorizzazioni, in **un'unica** organizzazione che scegli al momento della connessione.

C'è un unico indirizzo per tutti, in hosting o self-hosted:

```text
https://gateway.befailproof.ai/mcp
```

## Connetti un client

Aggiungi l'indirizzo al tuo client. La prima volta che uno strumento viene utilizzato, il tuo browser si apre. Scegli dove si trova il tuo Failproof AI Cloud, accedi, seleziona un'organizzazione e scegli **Allow**. **Cancel** non connette nulla.

La pagina nomina l'app e dove ritorna. Un'app non identificata dal suo indirizzo web è contrassegnata come **unverified app**, quindi continua solo se hai appena avviato questo dal tuo client.

<Tabs>
  <Tab title="Claude">
    In claude.ai o Claude Desktop, vai a **Settings → Connectors → Add custom connector**. Denominalo `Failproof AI`, inserisci l'indirizzo, seleziona **Add**, quindi **Connect**.

    Nei piani Team ed Enterprise, un proprietario aggiunge il connettore per l'organizzazione per primo. Ogni persona quindi connette il proprio account.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    Quindi esegui `/mcp` all'interno di Claude Code, seleziona `failproofai` e scegli **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    Aggiungi questo a `~/.cursor/mcp.json`, o al `.cursor/mcp.json` del tuo progetto:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor mostra **Needs login** accanto al server. Selezionalo per accedere.
  </Tab>
  <Tab title="Codex">
    Aggiungi questo a `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    Quindi esegui `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    Qualsiasi client che supporti server MCP remoti su HTTP Streamable con OAuth funziona. Dagli l'indirizzo sopra. Non c'è nessun ID client o segreto da configurare.
  </Tab>
</Tabs>

## Un'organizzazione per connessione

Una connessione agisce solo nell'organizzazione che hai scelto. Per utilizzare due organizzazioni, aggiungi il server due volte con nomi diversi, come `failproofai-acme` e `failproofai-sandbox`, e collega ciascuno alla sua organizzazione.

Le organizzazioni demo non accettano connessioni. Scegli invece la tua organizzazione.

## Autorizzazioni

Una connessione può fare ciò che puoi fare nell'organizzazione, entro l'insieme sottostante. Segue le tue autorizzazioni attuali: se un amministratore ti concede di più, lo strumento lo acquisisce, e se ti toglie qualcosa, lo strumento lo perde alla sua prossima chiamata.

| Autorizzazione | Consente allo strumento di |
| --- | --- |
| `events:read` | Elencare eventi, leggere la panoramica di una sessione, elencare agenti e ambienti |
| `evaluations:read` | Elencare sessioni, leggere e riassumere risultati e lavori di valutazione |
| `evaluations:trigger` | Creare valutazioni, pubblicare nuove versioni, attivarle o disattivarle, backfill e rivalutare una sessione |
| `dashboards:read`, `dashboards:write` | Leggere dashboard, o creare, rinominare e aggiungere query a esse |
| `queries:read`, `queries:write` | Leggere query salvate, o salvarle e modificarle |
| `queries:run` | Eseguire una query SQL di sola lettura e leggere lo schema della query |
| `alerts:read`, `alerts:write` | Leggere avvisi, o creare, modificare, sospendere, eliminare e testare avvisi |
| `issues:read` | Leggere problemi, riconoscerli e commentarli |
| `issues:create` | Aprire un problema su un avviso |
| `issues:close` | Risolvere e chiudere problemi |
| `audits:read`, `audits:write` | Leggere audit, esecuzioni e risultati, o creare e modificare audit e avviare un'esecuzione |
| `code_fixes:read` | Vedere come risolvere un problema e ottenere il suo contesto affinché il tuo agente lo risolva |
| `code_fixes:write` | Avviare una correzione in Failproof AI Cloud, che apre una pull request su GitHub |
| `policies:read`, `policies:write` | Leggere politiche, macchine e distribuzioni, o pubblicare, distribuire e ripristinare politiche |

Alcuni strumenti non necessitano di autorizzazione perché non leggono dati dell'organizzazione: costruire link di sessione ed evento, e cercare in questa documentazione.

Uno strumento AI non può mai toccare chiavi API, utenti, impostazioni o amministrazione dell'organizzazione, e non può inviare eventi.

## Approvazione delle modifiche

Le scritture ti chiedono prima se il tuo client può mostrare il prompt. Vedi cosa cambierà e seleziona **Approve this change** per procedere. Se declini o non rispondi entro circa 4 minuti, nulla cambia. Alcuni client smettono di aspettare dopo un minuto, quindi rispondi prontamente.

<Warning>
  Un client che non supporta i prompt non viene chiesto, e una scrittura viene eseguita non appena il client effettua la chiamata. Lì, la conferma del tuo client è l'unica, quindi mantienila attiva per gli strumenti di scrittura.
</Warning>

## App connesse e revoca

**Settings → Integrations → MCP** elenca le tue app connesse nell'organizzazione corrente, con le loro autorizzazioni e ultimo utilizzo. **Revoke** disconnette un'app immediatamente. Rimuovere il server nel tuo client revoca anche la connessione.

Puoi avere fino a 5 app connesse per organizzazione. Collegare la stessa app di nuovo sostituisce la sua connessione precedente.

## Distribuzioni self-hosted

Scegli **Self-hosted Failproof AI Cloud** durante la connessione e inserisci l'indirizzo a cui accedi. La tua distribuzione deve essere raggiungibile tramite HTTPS pubblico.

Le chiamate dei tool e i loro risultati passano attraverso il gateway Failproof AI in hosting mentre viaggiano tra il tuo strumento AI e la tua distribuzione. Il gateway non li archivia.

## Cosa accade ai tuoi dati

I risultati vanno allo strumento AI che hai connesso, e il provider di quello strumento li gestisce secondo i suoi termini. Per ogni chiamata di tool, Failproof AI registra il nome dello strumento, il suo risultato, quanto tempo ha impiegato e l'organizzazione, mai gli argomenti o i risultati. Vedi la [privacy policy](https://befailproof.ai/privacy/).

## Risoluzione dei problemi

| Cosa vedi | Cosa fare |
| --- | --- |
| "Started in another browser" | Completa l'accesso nel browser che il client ha aperto, con i cookie consentiti, e ricomincia dal client |
| Un errore dopo **Allow** | Il link funziona una volta e scade dopo 10 minuti, quindi ricomincia dal client |
| Uno strumento che ti aspettavi è mancante | Non possiedi la sua autorizzazione in questa organizzazione. Chiedi a un amministratore. Non devi riconnetterti una volta che ce l'hai |
| Il client continua a chiederti di accedere | La connessione è stata revocata, hai lasciato l'organizzazione, o è rimasta inutilizzata per 90 giorni. Connettiti di nuovo |
| "You have 5 connected apps" | Revoca una sotto **Settings → Integrations → MCP**, quindi connettiti di nuovo |
