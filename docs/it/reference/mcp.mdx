Connetti uno strumento di intelligenza artificiale a Failproof AI Cloud e accedi ai dati dei tuoi agenti da lì. Il tuo strumento può interrogare sessioni ed eventi, eseguire SQL in sola lettura, leggere dashboard, avvisi, segnalazioni, audit e policy, e, se disponi dell'autorizzazione, apportare modifiche come creare un avviso o distribuire una policy.

Ogni chiamata viene eseguita con **i tuoi stessi** permessi, in **una** organizzazione che scegli al momento della connessione.

C'è un unico indirizzo per tutti, in hosting o self-hosted:

```text
https://gateway.befailproof.ai/mcp
```

## Connetti un client

Aggiungi l'indirizzo al tuo client. La prima volta che uno strumento viene utilizzato, il tuo browser si apre. Scegli dove si trova il tuo Failproof AI Cloud, accedi, seleziona un'organizzazione e fai clic su **Allow**. **Cancel** non connette nulla.

La pagina mostra il nome dell'app e dove torna. Un'app che non è identificata dal suo proprio indirizzo web è contrassegnata come **unverified app**, quindi continua solo se hai appena avviato questa dal tuo client.

<Tabs>
  <Tab title="Claude">
    In claude.ai o Claude Desktop, vai a **Settings → Connectors → Add custom connector**. Nomina il connettore `Failproof AI`, inserisci l'indirizzo, seleziona **Add**, quindi **Connect**.

    Nei piani Team e Enterprise, un proprietario aggiunge prima il connettore per l'organizzazione. Ogni persona connette quindi il proprio account.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    Quindi esegui `/mcp` all'interno di Claude Code, seleziona `failproofai` e scegli **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    Aggiungi questo a `~/.cursor/mcp.json`, o al `.cursor/mcp.json` del tuo progetto:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor mostra **Needs login** accanto al server. Selezionalo per accedere.
  </Tab>
  <Tab title="Codex">
    Aggiungi questo a `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    Quindi esegui `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    Qualsiasi client che supporti server MCP remoti su HTTP trasmissibile con OAuth funziona. Forniscigli l'indirizzo di cui sopra. Non c'è un ID client o un segreto da configurare.
  </Tab>
</Tabs>

## Un'organizzazione per connessione

Una connessione agisce solo nell'organizzazione che hai scelto. Per utilizzare due organizzazioni, aggiungi il server due volte con nomi diversi, come `failproofai-acme` e `failproofai-sandbox`, e connetti ognuno alla sua organizzazione.

Le organizzazioni demo non accettano connessioni. Scegli la tua organizzazione.

## Permessi

Una connessione può fare quello che puoi fare tu nell'organizzazione, all'interno dell'insieme seguente. Segue i tuoi permessi attuali: se un amministratore te ne concede di più, lo strumento li acquisisce, e se te ne toglie qualcuno, lo strumento li perde alla sua prossima chiamata.

| Permesso | Permette allo strumento di |
| --- | --- |
| `events:read` | Elencare eventi, leggere la panoramica di una sessione, elencare agenti e ambienti |
| `evaluations:read` | Elencare sessioni, leggere e riassumere risultati e lavori di valutazione |
| `evaluations:trigger` | Creare valutazioni, pubblicare nuove versioni, attivarle o disattivarle, eseguire il backfill e rivalutare una sessione |
| `dashboards:read`, `dashboards:write` | Leggere dashboard, o creare, rinominare e aggiungere query ad esse |
| `queries:read`, `queries:write` | Leggere query salvate, o salvarle e modificarle |
| `queries:run` | Eseguire una query SQL in sola lettura e leggere lo schema della query |
| `alerts:read`, `alerts:write` | Leggere avvisi, o crearli, modificarli, metterli in pausa, eliminarli e testarli |
| `issues:read` | Leggere segnalazioni, riconoscerle e commentarle |
| `issues:create` | Aprire una segnalazione su un avviso |
| `issues:close` | Risolvere e chiudere segnalazioni |
| `audits:read`, `audits:write` | Leggere audit, esecuzioni e risultati, o creare e modificare audit e avviare un'esecuzione |
| `code_fixes:read` | Vedere come correggere una segnalazione e ottenere il suo contesto affinché il tuo agente la corregga |
| `code_fixes:write` | Avviare una correzione in Failproof AI Cloud, che apre una pull request su GitHub |
| `policies:read`, `policies:write` | Leggere policy, macchine e distribuzioni, o pubblicare, distribuire e eseguire il rollback delle policy |

Alcuni strumenti non richiedono alcun permesso perché non leggono dati dell'organizzazione: creazione di link di sessioni e eventi, e ricerca in questa documentazione.

Uno strumento di intelligenza artificiale non può mai toccare chiavi API, utenti, impostazioni o amministrazione dell'organizzazione, e non può inviare eventi.

## Approvazione delle modifiche

Le scritture ti chiedono prima se il tuo client può mostrare il prompt. Vedi cosa cambierà e seleziona **Approve this change** per procedere. Se declini o non rispondi entro circa 4 minuti, nulla cambia. Alcuni client smettono di aspettare dopo un minuto, quindi rispondi prontamente.

<Warning>
  Un client che non supporta i prompt non verrà interrogato e una scrittura si eseguirà non appena il client effettua la chiamata. Lì, la tua conferma del client è l'unica, quindi mantienila attiva per gli strumenti di scrittura.
</Warning>

## App connesse e revoca

**Settings → Integrations → MCP** elenca le tue app connesse nell'organizzazione corrente, con i loro permessi e l'ultimo utilizzo. **Revoke** interrompe un'app immediatamente. La rimozione del server nel tuo client revoca anche la connessione.

Puoi avere fino a 5 app connesse per organizzazione. Connettere di nuovo la stessa app sostituisce la connessione precedente.

## Distribuzioni self-hosted

Scegli **Self-hosted Failproof AI Cloud** al momento della connessione e inserisci l'indirizzo con cui accedi. La tua distribuzione deve essere raggiungibile tramite HTTPS pubblico.

Le chiamate dello strumento e i loro risultati passano attraverso il gateway Failproof AI in hosting mentre si spostano tra il tuo strumento di intelligenza artificiale e la tua distribuzione. Il gateway non li archivia.

## Cosa succede ai tuoi dati

I risultati vengono inviati allo strumento di intelligenza artificiale che hai connesso, e il provider di quello strumento li gestisce secondo i suoi stessi termini. Per ogni chiamata dello strumento, Failproof AI registra il nome dello strumento, il suo risultato, quanto tempo ha impiegato e l'organizzazione, mai gli argomenti o i risultati. Consulta la [privacy policy](https://befailproof.ai/privacy/).

## Risoluzione dei problemi

| Cosa vedi | Cosa fare |
| --- | --- |
| "Started in another browser" | Completa l'accesso nel browser che il client ha aperto, con i cookie consentiti, e ricomincia dal client |
| Un errore dopo **Allow** | Il link funziona una volta e scade dopo 10 minuti, quindi ricomincia dal client |
| Uno strumento che ti aspettavi è mancante | Non disponi della sua autorizzazione in questa organizzazione. Chiedi a un amministratore. Non hai bisogno di riconnetterti una volta che l'hai ottenuta |
| Il client continua a chiederti di accedere | La connessione è stata revocata, hai lasciato l'organizzazione o è rimasta inutilizzata per 90 giorni. Connettiti di nuovo |
| "You have 5 connected apps" | Revoca uno in **Settings → Integrations → MCP**, quindi connettiti di nuovo |
