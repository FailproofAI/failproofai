`failproofai otel` configura la segnalazione facoltativa di OpenTelemetry a FailproofAI Cloud. Innanzitutto connetti il tuo computer con `failproofai config` e chiedi a un amministratore dell'organizzazione di abilitare **Settings → OpenTelemetry**.

La configurazione interattiva chiede informazioni su OpenTelemetry dopo il campo della chiave Cloud e il selettore di agente. Il passaggio facoltativo ha come predefinito No. Scegli Sì per selezionare gli agenti OTEL; lo stesso codice di abilitazione viene eseguito dopo la scrittura della connessione. Esc prima della configurazione non applica alcuna modifica. La configurazione automatica, una chiave fornita, la modalità open-source e il mantenimento di una connessione salvata non ti permetteranno di partecipare.

## Abilita un agente

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Gli agenti supportati sono `claude`, `codex` e `copilot` (VS Code). La configurazione di Copilot richiede un eseguibile di VS Code o un'estensione Copilot installata. Una sola directory di impostazioni rimanente non è sufficiente; la configurazione salta Copilot quando nessuno dei due viene trovato.

`--local` invia al relè locale invece di inviare direttamente a Cloud. Copilot utilizza il relè automaticamente perché le sue impostazioni non possono archiviare l'intestazione di autenticazione.

Il relè rimane in ascolto solo sul tuo computer. Il daemon FailproofAI configurato rileva il cambiamento entro pochi secondi; non è necessario riavviarlo. Se un'altra applicazione possiede la porta del relè, lo stato lo segnala come spento e il daemon continua a funzionare.

<Warning>
L'acquisizione di testo è attivata per impostazione predefinita. Aggiungi `--no-content` per omettere i prompt e i dettagli dello strumento. Le versioni degli agenti possono esporre diversi controlli del contenuto; rivedi cosa esporta il tuo agente prima di utilizzarlo con dati sensibili.
</Warning>

Codex esporta solo i registri di conversazione, non le tracce di runtime interne o le metriche. Un `log_user_prompt = false` esplicito nella tua configurazione di Codex rimane disattivato; l'abilitazione stampa una nota quando preserva questa scelta.

### Scegli un percorso di segnalazione

Se la segnalazione della trascrizione è attivata per un agente, la configurazione chiede:

> failproofai invia già le sessioni di Claude Code a Cloud. Inviarle con OTEL? L'upload della trascrizione per Claude Code si ferma.

L'impostazione predefinita è No. `--yes` accetta l'interruzione senza un prompt. Gli altri agenti e l'applicazione delle politiche non sono interessati.

La configurazione di Codex attende la conferma del daemon del cambio del collettore prima di scrivere le sue impostazioni di esportazione. Se la conferma scade, la configurazione ti avvisa di attendere prima di avviare Codex.

La configurazione v2 mantiene l'elenco di traccia ricordato in `agents.selected` (e la cronologia di rilevamento in `agents.seen`). La preferenza di trascrizione per agente rimane in `collector.agents.<agent>.sessions`, la proprietà OTEL in `otel.agents` e le impostazioni di relè in `collector.otlp.enabled` / `collector.otlp.port`. Queste chiavi separate mantengono le vecchie configurazioni OTEL leggibili: la configurazione può modificare l'elenco di traccia senza perdere la preferenza di trasporto o lo stato necessario per ripristinare le impostazioni del tuo agente.

## Ispeziona la configurazione

```bash
failproofai otel status
```

Lo stato mostra ogni agente, se le sue impostazioni sono gestite da FailproofAI, la sua destinazione, l'interruttore di acquisizione dell'organizzazione, lo stato del relè e il risultato dell'ultimo upload del relè.

`unknown` per l'interruttore dell'organizzazione significa che il server non l'ha fornito o non è stato raggiunto. Non è un errore e non impedisce la configurazione su una versione Cloud precedente.

Se Cloud non supporta ancora OTEL, il relè conserva le esportazioni rifiutate invece di scartarle. Se l'acquisizione dell'organizzazione è disattivata, `enable` non scrive nulla e esce con un errore; chiedi a un amministratore di attivarla prima.

## Stampa la configurazione per un'applicazione

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

L'output è un blocco di ambiente della shell per un esportatore OTLP/HTTP. L'output di Cloud imposta `OTEL_EXPORTER_OTLP_ENDPOINT` sulla base OTLP di Cloud, `https://<cloud>/otel`, e l'esportatore aggiunge `/v1/<signal>`; una variabile per segnale come `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` ha bisogno del full `https://<cloud>/otel/v1/logs`. L'output locale punta al relè, `http://127.0.0.1:<port>`. L'output di Cloud include la chiave API configurata; trattala come un segreto. L'output locale omette la chiave. Per utilizzare l'output locale, abilita prima un agente locale in modo che il relè sia in esecuzione.

## Ripristina le impostazioni precedenti

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable ripristina solo le impostazioni scritte da FailproofAI, mantiene i cambiamenti non correlati e ripristina la scelta di segnalazione della trascrizione precedente di ogni agente. Quando l'ultimo agente locale gestito è disabilitato, il relè smette di accettare esportazioni.

Per Codex, disable registra anche `collector.agents.codex.sessions_resume_after` (millisecondi epoch). I byte di rollout esistenti sono trattati come consegnati in modo che le sessioni acquisite con OTEL non vengano caricate di nuovo; gli accodamenti successivi continuano a fluire attraverso la segnalazione della trascrizione.

Ogni comando supporta `--help`. Vedi [OpenTelemetry in Cloud](/it/agenteye/opentelemetry) per esempi di applicazioni e agenti di codifica.
