`failproofai otel` configura la segnalazione facoltativa di OpenTelemetry a FailproofAI Cloud. Per prima cosa connetti il tuo computer con `failproofai config` e chiedi a un amministratore dell'organizzazione di abilitare **Impostazioni → OpenTelemetry**.

La configurazione interattiva ti chiede di OpenTelemetry dopo il campo della chiave Cloud e il selezionatore dell'agente. Il passaggio facoltativo predefinisce a No. Scegli Sì per selezionare gli agenti OTEL; lo stesso codice di abilitazione si esegue dopo che la connessione è stata scritta. Esc prima della configurazione non applica alcun cambiamento. La configurazione incustodita, una chiave fornita, la modalità open-source e il mantenimento di una connessione salvata non ti abilitano.

## Abilita un agente

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Gli agenti supportati sono `claude`, `codex` e `copilot` (VS Code). La configurazione di Copilot richiede un eseguibile VS Code o un'estensione Copilot installata. Una directory di impostazioni residua da sola non è sufficiente; la configurazione salta Copilot quando nessuno dei due viene trovato.

`--local` invia al relay locale anziché direttamente a Cloud. Copilot utilizza il relay automaticamente perché le sue impostazioni non possono memorizzare l'intestazione di autenticazione.

Il relay è in ascolto solo sulla tua macchina. Il daemon FailproofAI configurato rileva il cambiamento entro pochi secondi; non è necessario riavviarlo. Se un'altra applicazione possiede la porta del relay, il rapporto di stato lo segnala come disattivato e il daemon continua a funzionare.

<Warning>
L'acquisizione di testo è attiva per impostazione predefinita. Aggiungi `--no-content` per omettere i prompt e i dettagli dello strumento. Le versioni degli agenti possono esporre diversi controlli dei contenuti; esamina ciò che il tuo agente esporta prima di utilizzarlo con dati sensibili.
</Warning>

Codex esporta solo i registri di conversazione, non le tracce di runtime interno o le metriche. Un `log_user_prompt = false` esplicito nella tua configurazione Codex rimane disattivato; enable stampa una nota quando preserva quella scelta.

### Scegli un percorso di segnalazione

Se la segnalazione di trascrizione è attiva per un agente, la configurazione chiede:

> failproofai invia già le sessioni di Claude Code a Cloud. Inviarle con OTEL invece? Il caricamento della trascrizione per Claude Code si interrompe.

L'impostazione predefinita è No. `--yes` accetta il cambio senza un prompt. Gli altri agenti e l'applicazione delle politiche non sono influenzati.

La configurazione di Codex attende che il daemon confermi la modifica del collezionatore prima di scrivere le impostazioni dell'esportatore. Se la conferma va in timeout, la configurazione ti avverte di aspettare prima di avviare Codex.

Config v2 mantiene l'elenco di tracciamento ricordato in `agents.selected` (e la cronologia di rilevamento in `agents.seen`). La preferenza di trascrizione per agente rimane in `collector.agents.<agent>.sessions`, la proprietà OTEL in `otel.agents` e le impostazioni del relay in `collector.otlp.enabled` / `collector.otlp.port`. Queste chiavi separate mantengono le vecchie configurazioni OTEL leggibili: la configurazione può modificare l'elenco di tracciamento senza perdere la preferenza di trasporto o lo stato necessario per ripristinare le impostazioni dell'agente.

## Ispeziona configurazione

```bash
failproofai otel status
```

Lo stato mostra ogni agente, se le sue impostazioni sono gestite da FailproofAI, la sua destinazione, l'interruttore di acquisizione dell'organizzazione, lo stato del relay e l'ultimo risultato di caricamento del relay.

`unknown` per l'interruttore dell'organizzazione significa che il server non l'ha fornito o non è stato raggiunto. Non è un errore e non impedisce la configurazione su una versione precedente di Cloud.

Se Cloud non supporta ancora OTEL, il relay conserva le esportazioni rifiutate invece di scartarle. Se l'acquisizione dell'organizzazione è disattivata, `enable` non scrive nulla e esce con un errore; chiedi prima a un amministratore di attivarla.

## Stampa la configurazione per un'applicazione

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

L'output è un blocco di ambiente shell per un esportatore OTLP/HTTP. L'output Cloud imposta `OTEL_EXPORTER_OTLP_ENDPOINT` sulla base OTLP di Cloud, `https://<cloud>/otel`, e l'esportatore aggiunge `/v1/<signal>`; una variabile per segnale come `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` ha bisogno dell'URL completo `https://<cloud>/otel/v1/logs`. L'output locale punta al relay, `http://127.0.0.1:<port>`. L'output Cloud include la chiave API configurata; trattala come un segreto. L'output locale omette la chiave. Per utilizzare l'output locale, abilita prima un agente locale in modo che il relay sia in esecuzione.

## Ripristina impostazioni precedenti

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable ripristina solo le impostazioni scritte da FailproofAI, mantiene i cambiamenti non correlati e ripristina la scelta precedente di segnalazione di trascrizione di ogni agente. Quando l'ultimo agente locale gestito è disabilitato, il relay smette di accettare esportazioni.

Per Codex, disable registra anche `collector.agents.codex.sessions_resume_after` (epoch millisecondi). I byte di rollout esistenti vengono trattati come consegnati in modo che le sessioni acquisite con OTEL non vengano caricate di nuovo; gli appendi successivi continuano a fluire attraverso la segnalazione di trascrizione.

Ogni comando supporta `--help`. Vedi [OpenTelemetry in Cloud](/it/agenteye/opentelemetry) per esempi di applicazioni e agenti di codifica.
