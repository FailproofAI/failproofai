`failproofai otel` configura la segnalazione facoltativa di OpenTelemetry a FailproofAI Cloud. Per prima cosa connetti la tua macchina con `failproofai config`. L'acquisizione di OpenTelemetry è sempre attiva in Cloud, quindi non c'è alcun switch organizzativo da attivare.

La configurazione interattiva chiede informazioni su OpenTelemetry dopo il campo della chiave Cloud e il selettore dell'agente. Il passaggio facoltativo ha come default No. Scegli Sì per selezionare agenti OTEL; lo stesso codice di abilitazione viene eseguito dopo che la connessione è stata scritta. Premi Esc prima della configurazione per non applicare alcuna modifica. La configurazione automatica, una chiave fornita, la modalità open-source e il mantenimento di una connessione salvata non ti abiliteranno.

## Abilita un agente

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Gli agenti supportati sono `claude`, `codex` e `copilot` (VS Code). La configurazione di Copilot richiede un eseguibile VS Code o un'estensione Copilot installata. Una directory di impostazioni residua da sola non è sufficiente; la configurazione salta Copilot quando nessuno dei due viene trovato.

`--local` invia al relay locale invece di inviare direttamente a Cloud. Copilot utilizza il relay automaticamente perché le sue impostazioni non possono memorizzare l'intestazione di autenticazione.

Il relay ascolta solo sulla tua macchina. Il daemon FailproofAI configurato raccoglie il cambiamento entro pochi secondi; non è necessario riavviarlo. Se un'altra applicazione possiede la porta del relay, il rapporto di stato la segnala come spenta e il daemon continua a funzionare.

<Warning>
L'acquisizione di testo è attiva per impostazione predefinita. Aggiungi `--no-content` per omettere prompt e dettagli dello strumento. Le versioni dell'agente possono esporre diversi controlli del contenuto; controlla cosa esporta il tuo agente prima di utilizzarlo con dati sensibili.
</Warning>

Codex esporta solo i registri di conversazione, non le tracce di runtime interne o le metriche. Un `log_user_prompt = false` esplicito nella tua configurazione Codex rimane disattivato; l'abilitazione stampa una nota quando preserva quella scelta.

### Scegli un percorso di segnalazione

Se la segnalazione della trascrizione è attiva per un agente, la configurazione chiede:

> failproofai invia già sessioni Claude Code a Cloud. Inviarle con OTEL invece? L'upload della trascrizione per Claude Code si interrompe.

Il default è No. `--yes` accetta il cambio senza un prompt. Gli altri agenti e l'applicazione delle politiche rimangono inalterati.

La configurazione di Codex attende che il daemon confermi il cambiamento del collettore prima di scrivere le sue impostazioni di esportazione. Se la conferma scade, la configurazione ti avverte di attendere prima di avviare Codex.

La configurazione v2 mantiene l'elenco di tracciamento memorizzato in `agents.selected` (e la cronologia di rilevamento in `agents.seen`). La preferenza di trascrizione per agente rimane in `collector.agents.<agent>.sessions`, la proprietà OTEL in `otel.agents` e le impostazioni del relay in `collector.otlp.enabled` / `collector.otlp.port`. Queste chiavi separate mantengono le configurazioni OTEL precedenti leggibili: la configurazione può cambiare l'elenco di tracciamento senza perdere la preferenza di trasporto o lo stato necessario per ripristinare le impostazioni dell'agente.

## Ispeziona la configurazione

```bash
failproofai otel status
```

Lo stato mostra ogni agente, se le sue impostazioni sono gestite da FailproofAI, la sua destinazione, lo switch di acquisizione dell'organizzazione, lo stato del relay e il risultato dell'ultimo upload del relay.

`unknown` per lo switch dell'organizzazione significa che il server non lo ha fornito o non è stato raggiunto. Non è un errore e non impedisce la configurazione su una versione Cloud precedente.

Se Cloud non supporta ancora OTEL, il relay mantiene le esportazioni rifiutate invece di scartarle. Se una versione Cloud precedente segnala l'acquisizione dell'organizzazione come disattivata, `enable` non scrive nulla e esce con un errore.

## Stampa la configurazione per un'applicazione

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

L'output è un blocco di ambiente shell per un esportatore OTLP/HTTP. L'output Cloud imposta `OTEL_EXPORTER_OTLP_ENDPOINT` sulla base OTLP di Cloud, `https://<cloud>/otel`, e l'esportatore aggiunge `/v1/<signal>`; una variabile per segnale come `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` ha bisogno dell'intero `https://<cloud>/otel/v1/logs`. L'output locale punta al relay, `http://127.0.0.1:<port>`. L'output Cloud include la chiave API configurata; trattala come un segreto. L'output locale omette la chiave. Per utilizzare l'output locale, prima abilita un agente locale così il relay è in esecuzione.

## Ripristina le impostazioni precedenti

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disattiva ripristina solo le impostazioni che FailproofAI ha scritto, mantiene i cambiamenti non correlati e ripristina la scelta precedente di segnalazione della trascrizione di ogni agente. Quando l'ultimo agente locale gestito viene disabilitato, il relay smette di accettare esportazioni.

Per Codex, disattiva registra anche `collector.agents.codex.sessions_resume_after` (millisecondi di epoca). I byte di rollout esistenti sono trattati come consegnati quindi le sessioni acquisite con OTEL non vengono caricate di nuovo; gli append successivi continuano a fluire attraverso la segnalazione della trascrizione.

Ogni comando supporta `--help`. Vedi [OpenTelemetry in Cloud](/it/agenteye/opentelemetry) per esempi di applicazioni e agenti di codifica.
