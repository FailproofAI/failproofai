Inizia con:

```bash
failproofai config --status
failproofai policies
```

## Un agente non è connesso

Esegui di nuovo la configurazione:

```bash
failproofai config
```

La configurazione supporta Linux e macOS. Ha bisogno dell'accesso amministratore una sola volta per installare il servizio, ma non chiede mai una password sudo.

Controlla i percorsi e gli scope dei harness in [Harnesses](/it/reference/harnesses).

## Una sessione è mancante

```bash
failproofai flush --wait
failproofai backfill --since 30d --dry-run
failproofai harness list
```

Rimuovi `--dry-run` per inviare di nuovo la cronologia passata. Aggiungi un'altra posizione di trascrizione con:

```bash
failproofai harness add-path <harness> [label=]<path>
```

Usa un'etichetta quando due posizioni contengono copie dello stesso progetto.

## Ogni azione protetta viene negata

Su una macchina configurata, `failproofaid` è l'unico valutatore. Se non riesce a rispondere, le azioni protette falliscono in modo sicuro.

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

Esegui `failproofai config` per riparare o reinstallare il servizio.

## Un pack sta negando

`failproofai policies` elenca i pack che non riescono a caricarsi. Un pack selezionato fallisce in modo sicuro invece di scomparire.

Cause comuni:

- L'artefatto è cambiato dopo l'installazione.
- Il manifesto e le policy raggruppate non concordano.
- Il file è mancante o non può essere importato.
- Il pack utilizza un evento, uno strumento o una forma di policy non supportata.

Rimuovi il pack o installa una versione corretta:

```bash
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

## Cloud è disconnesso

Preferisci una variabile d'ambiente per la chiave:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
failproofai config --status
```

Una macchina può eseguire il pull delle policy e inviare attività in modo indipendente. Lo stato riporta entrambe.

## Una policy non ha bloccato

Verifica tre cose:

1. La policy è attiva: `failproofai policies`.
2. Il suo evento e strumento corrispondono all'azione.
3. Quell'harness può applicare l'evento.

Una negazione di tool-call è verificata su tutti i 12 harness supportati. Gli altri eventi variano. Vedi [enforcement capability](/it/reference/harnesses#enforcement-capability).

## I download sono bloccati

- `FAILPROOFAI_NO_DOWNLOAD=1` rifiuta i download di rete.
- `FAILPROOFAI_DAEMON_BASE_URL` indirizza i download del servizio a uno specchio.
- `FAILPROOFAI_PACK_BASE_URL` indirizza i download del pack a uno specchio.

I pack installati continuano a essere applicati quando i download sono disabilitati.
