Una sessione è un'esecuzione di un agente. Connette il prompt, le chiamate al modello, gli strumenti, gli errori, l'input umano, le decisioni di policy e il risultato finale.

## Dove vivono le sessioni

<Tabs>
  <Tab title="Local">
    Esegui `failproofai` per aprire la dashboard su `http://localhost:8020`. La cronologia delle sessioni rimane su questa macchina.
  </Tab>
  <Tab title="Cloud">
    Connetti la macchina, quindi apri **Observe → Sessions**:

    ```bash
    export FAILPROOFAI_CLOUD_TOKEN="<key>"
    failproofai config
    ```

    Cloud riceve trascritti completi per impostazione predefinita. Per inviare solo le decisioni di policy, connetti prima, quindi imposta `collector.sessions` su `false` in `~/.failproofai/config.json`. Il flag di setup `--no-transcripts` attuale non applica questa impostazione.
  </Tab>
</Tabs>

Le sessioni provengono dai 12 [harness di agente](/it/reference/harnesses) supportati e da agenti strumentati con [Python SDK](/it/reference/custom-agents).

## Trova una sessione

Nel Cloud, filtra per ora, ambiente, stato, agente o ID sessione. Dalla CLI:

```bash
fp sessions --since 24h
fp sessions --status error,timeout --agent-id checkout-agent
fp --json sessions --session-id <session-id>
```

Usa `fp errors --since 24h` per i fallimenti che non sono mai stati valutati. `fp sessions --status` utilizza il risultato della valutazione più recente, quindi una sessione non valutata non ha uno stato.

## Leggi un'esecuzione

1. Conferma l'obiettivo e l'ambiente dell'agente.
2. Trova il primo errore o la decisione inaspettata.
3. Ispeziona il contesto del modello e l'input dello strumento immediatamente prima.
4. Controlla i tentativi, la latenza e gli interruzioni umane.
5. Esamina le valutazioni e le decisioni di policy.

## Se una sessione manca

```bash
failproofai flush --wait
failproofai config --status
failproofai backfill --since 30d --dry-run
```

Usa `failproofai harness add-path <harness> [<label>=]<path>` quando le sessioni si trovano al di fuori della solita posizione dell'harness, come un altro profilo, una home del container o una directory del team montata.
