Le query sono il livello flessibile che sottende i dashboard, gli audit e le investigazioni. Usa SQL ad-hoc per testare un'idea, quindi salva la query quando diventa parte di un flusso di lavoro ricorrente.

## Crea ed esegui una query

<Tabs>
  <Tab title="Dashboard">
    1. Vai a **Analyze → Queries** e seleziona **new query**.
    2. Apri il browser dello schema e scegli i campi dai dati di evento, sessione o valutazione.
    3. Scrivi SQL, aggiungi parametri se necessario, ed esegui la query.
    4. Salvala con un nome e una descrizione chiari, quindi usa **add to dashboard** quando il risultato deve essere monitorato.

    L'editor di query combina lo schema dell'evento, SQL, parametri e un'anteprima dei risultati in modo da poter convalidare la domanda prima di salvarla.

    ![L'editor di query SQL con un browser dello schema e una griglia dei risultati in tempo reale.](/images/dashboard/query-lab.png)

    Le query salvate vengono quindi visualizzate nella libreria condivisa, dove i colleghi possono rieseguirle o aggiungere i loro risultati ai dashboard.

    ![La libreria Queries salvata contenente query integrate e personalizzate riutilizzabili.](/images/dashboard/queries.png)

    Usa un nome e una descrizione chiari in modo che il risultato rimanga comprensibile senza riaprire il suo SQL.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    Usa `fp query list` per trovare gli ID e `fp query delete <query-id>` per rimuovere una query salvata.
  </Tab>
</Tabs>

## Usi comuni

- Trovare sessioni con chiamate ripetute allo stesso strumento.
- Confrontare i punteggi di valutazione tra modelli o ambienti.
- Misurare il tempo tra un'attesa umana e la ripresa.
- Identificare i rifiuti delle policy seguiti da un'alternativa riuscita.
- Costruire una coorte per un audit.

Apri **Queries → Schema** prima di scrivere su campi non familiari. Preferisci filtri espliciti di tempo e ambiente, e mantieni limiti di risultati durante l'esplorazione.

<Warning>
  Una query può identificare un modello sospetto, ma non stabilisce da sola la modalità di errore. Apri tracce rappresentative o esegui un audit prima di trasformare il risultato in una policy.
</Warning>
