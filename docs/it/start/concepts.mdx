Failproof AI registra ciò che gli agenti fanno e decide cosa possono fare.

## Osservare

| Termine | Significato |
| --- | --- |
| Session | Un'esecuzione dell'agente |
| Event | Un'azione all'interno di una sessione |
| Trace | La visualizzazione ordinata di una sessione |
| Evaluation | Un punteggio o un giudizio |
| Audit | Una revisione di molte sessioni |
| Finding | Evidenza di un pattern di errore |
| Issue | La risposta di cui qualcuno è responsabile |
| Alert | Una regola che rileva la ricorrenza |

## Applicare

| Termine | Significato |
| --- | --- |
| Harness | L'ambiente in cui esegue un agente |
| Hook | Un punto in cui l'harness chiede una decisione |
| Policy | Una regola che consente, guida o blocca |
| Policy pack | Un set di policy versionato che chiunque può installare |
| Daemon | Il servizio locale che valuta le policy |
| Deployment | Policy assegnate a una macchina |

## Il flusso di lavoro

```text
Session → Audit → Finding → Issue → Policy
```

Inizia con l'evidenza. Trova l'errore ripetuto, assegna la risposta, quindi prevenilo.

Una policy restituisce `allow`, `instruct` o `deny`. La guida tramite `instruct` dipende dall'harness; utilizza `deny` quando l'azione deve essere interrotta.

La modalità Observe è separata dalla decisione. Esegue la policy reale e registra cosa farebbe mentre consente all'agente di continuare.

<Warning>
  Un semplice `fp fleet deploy <machine> --add <policy>` applica immediatamente. Aggiungi `:observe` per un rollout shadow.
</Warning>

La configurazione non sceglie alcun policy pack. Prima di aggiungerne uno, esegue solo `block-failproofai-commands`. Il catalogo compilato contiene 39 policy su 9 categorie.

Consulta gli [harness supportati](/it/reference/harnesses#enforcement-capability) prima di assumere che un evento possa bloccarsi in ogni ambiente agente.
