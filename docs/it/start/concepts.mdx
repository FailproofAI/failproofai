description: "L'insieme minimo di concetti utilizzati in Failproof AI."

---

| Concetto | Significato | Cosa puoi realizzare |
| --- | --- | --- |
| Session | Un'attività o un'esecuzione di un agente | Ricostruire un singolo risultato |
| Event | Un'azione registrata in una session | Ispezionare una chiamata al modello, un utilizzo di strumenti, un errore, un'azione umana o una decisione di policy |
| Trace | La visualizzazione ordinata e annidata della session | Comprendere la causalità invece di leggere log disconnessi |
| Evaluation | Un punteggio o un giudizio su una session | Tracciare continuamente la qualità, la conformità, il costo o la latenza |
| Audit | Una revisione di una popolazione di session selezionate | Cercare pattern di errori con un obiettivo e una cadenza definiti |
| Finding | Un errore rilevante supportato da prove scoperto da un audit | Visualizzare la modalità di errore, la gravità e le session interessate |
| Issue | Un record di risposta duraturo | Assegnare, discutere e risolvere un finding o un incidente di avviso |
| Alert | Una regola che rileva ricorrenze | Notificare i responsabili quando una condizione nota si ripete |
| Policy | Una regola valutata durante l'attività dell'agente | Osservare, bloccare o reindirizzare comportamenti rischiosi |
| Deployment | Un rilascio di policy versionato alle macchine | Controllare dove viene eseguita una policy e eseguire un rollback sicuro |

## Il ciclo di affidabilità

Parti dalle prove. Una session mostra ciò che è accaduto. Un audit determina se è un errore isolato o un pattern. Un finding identifica la modalità di errore; un issue gestisce la risposta. Una policy previene lo stesso comportamento, mentre gli alert ti informano se la condizione si ripete.

<Warning>
  Un `failproofai audit` locale analizza la cronologia dell'agente locale. Un audit Cloud ricorrente esamina le session archiviate in Failproof AI Cloud. Sono flussi di lavoro separati con scope e pianificazione diversi.
</Warning>
