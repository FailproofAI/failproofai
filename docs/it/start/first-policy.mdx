Inizia con un comportamento che vuoi bloccare e un'azione legittima che deve continuare a funzionare.

## Prova prima una policy revisionata

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI include 39 policy revisionate. Controlla il [catalogo](/it/policies/builtin-catalog) prima di scriverne una nuova.

## Scrivi e testa la tua

<Steps>
  <Step title="Crea una policy funzionante">
    ```bash
    failproofai publish --init guards.mjs
    ```

    Questo scrive una policy che blocca `git push --force`. Modificala per la tua regola.
  </Step>
  <Step title="Applicala su questa macchina">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    Chiedi al tuo agent di eseguire l'azione bloccata, quindi controlla **Policies → Activity** nel dashboard locale.
  </Step>
  <Step title="Mantienila o rimuovila">
    Metti un file `*policies.mjs` sotto `.failproofai/policies/` per caricarlo automaticamente.

    Rimuovi i file custom espliciti con:

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## Condividila

Pubblica un pack pubblico:

```bash
failproofai publish
```

Chiunque può quindi installarlo con `failproofai policies add <owner>/<repo>`. Aggiungi tu stesso il topic GitHub `failproofai-policies` in modo che il [Policy Hub](https://befailproof.ai/policy-hub/) possa indicizzarlo.

Per un rollout Cloud:

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  Un semplice `--add checkout-guard` applica la policy immediatamente. Aggiungi `:observe` per registrare cosa farebbe la policy senza bloccare l'agent.
</Warning>

Vedi [pubblica un pack](/it/policies/publish-a-pack) o [distribuisci policy](/it/policies/deploy) per il workflow completo.
