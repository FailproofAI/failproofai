## Prima di iniziare

Due cose che questo percorso presuppone, nessuna delle quali il codice qui sotto fa per te:

| Requisito | Motivo |
| --- | --- |
| Python 3.10 o più recente | È il minimo dichiarato dall'SDK. |
| Una macchina configurata con `failproofai config` | Quel comando installa il daemon failproofaid, e il daemon è l'unica cosa che spedisce ciò che l'SDK scrive. Senza di esso i batch si accumulano nella directory dello spool e non escono mai. |

<Note>
  **Questo percorso registra; non applica.** L'SDK cattura ciò che il tuo agente ha fatto. Le politiche si attivano da un hook all'interno di un CLI agente, quindi applicare su un agente framework significa mettere un hook nel tuo runtime — vedi [Politiche](/it/policies/overview).
</Note>

## Tre righe, qualunque framework

<CodeGroup>
```bash LangGraph
pip install 'failproofai-sdk[langgraph]'
```

```bash CrewAI
pip install 'failproofai-sdk[crewai]'
```

```bash LlamaIndex
pip install 'failproofai-sdk[llamaindex]'
```

```bash Pydantic AI
pip install 'failproofai-sdk[pydantic-ai]'
```

```bash Agenti personalizzati
pip install failproofai-sdk
```
</CodeGroup>

```python
import failproofai_sdk

failproofai_sdk.configure(environment="production")
failproofai_sdk.instrument()          # rileva i framework che hai importato

with failproofai_sdk.session():
    ...                               # la tua chiamata agente esistente, invariata
```

Niente decoratori sulle tue funzioni, nessun callback passato alle tue chiamate, nessun id fatto passare attraverso il tuo codice. Solo la chiamata all'interno della sessione è diversa:

<Tabs>
  <Tab title="LangGraph">
    ```python
    graph.invoke({"messages": [HumanMessage("...")]})
    ```
  </Tab>
  <Tab title="CrewAI">
    ```python
    Crew(agents=[analyst, writer], tasks=[gather, summarise]).kickoff()
    ```
  </Tab>
  <Tab title="LlamaIndex">
    ```python
    await agent.run("...")        # sotto `async with failproofai_sdk.session():`
    ```
  </Tab>
  <Tab title="Pydantic AI">
    ```python
    agent.run_sync("...")
    ```
  </Tab>
  <Tab title="Agenti personalizzati">
    ```python
    with failproofai_sdk.agent("planner"):
        with failproofai_sdk.tool_call("search", input={"q": q}) as t:
            t.output = search(q)
    ```
  </Tab>
</Tabs>

L'installazione extra riguarda il **framework**. Ogni adattatore è incluso nella wheel base, quindi un progetto che ha già il suo framework non ha bisogno di nulla di extra.

## Verifica l'arrivo

Esegui una sessione strumentata, quindi apri **Observe → Sessions** e seleziona il tuo ambiente. L'esecuzione appare come una traccia ricostruita.

Se non arriva nulla, conferma che la macchina è configurata e collegata con `failproofai config --status`. Se non lo è, esegui `failproofai config`. Vedi [Scegli la tua configurazione](/it/start/setup).

<Warning>
  Non controllare la directory dello spool per confermare la consegna. Il daemon Failproof raccoglie ed elimina ogni batch entro millisecondi, quindi leggerlo corre il rischio di mostrare molti meno eventi di quelli effettivamente emessi.
</Warning>

Per provare che l'SDK sta scrivendo, ferma prima il daemon, quindi esegui la tua sessione e guarda in `~/.failproofai/custom-agents/events/`. Con il daemon in esecuzione, una directory vuota è lo stato sano.

<CodeGroup>
```bash Linux
sudo systemctl stop failproofaid@$USER
```

```bash macOS
sudo launchctl bootout system/ai.failproof.failproofaid.$USER
```
</CodeGroup>

Esegui `failproofai config` dopo per riportarlo in funzione. Mentre il daemon è fermo, gli eventi hook su questa macchina non hanno un valutatore e vengono negati, quindi fermalo solo per il tempo che richiede il controllo.
