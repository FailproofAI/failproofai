Questo avvio rapido configura una macchina per segnalare sessioni, esegue un audit e distribuisce una policy. Utilizza la skill per configurare Failproof, oppure segui i passaggi manuali.

**Quale percorso è il tuo?** Se il tuo agente gira in uno dei 12 [harness](/it/reference/harnesses) supportati — una CLI di coding, o un gateway come Hermes o OpenClaw — segui i passaggi seguenti; hai bisogno di Node.js 20.9 o versioni successive. Se il tuo agente non ha un harness, strumentalo con l'[SDK Python](/it/reference/python-sdk) per il tracing e gli audit, quindi riprendi da [Esegui il tuo primo controllo di errore](/it/start/first-audit); l'enforcement su quel percorso necessita un hook nel tuo runtime.

<Tabs>
  <Tab title="Utilizza la skill">
    <Steps>
      <Step title="Installa le skill Failproof AI">
        ```bash
        npx skills add FailproofAI/skills
        ```
      </Step>
      <Step title="Chiedi al tuo agente di configurare tutto">
        ```text
        Set up Failproof AI for this project, connect this machine, install the right hooks and policies, and verify that a session arrives.
        ```

        Il tuo agente ispeziona il progetto, sceglie l'integrazione pertinente, esegue la configurazione e la verifica. Consulta il [repository delle skill FailproofAI](https://github.com/FailproofAI/skills) per le singole skill e le opzioni di installazione avanzate.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Configurazione manuale">
    ## Prima di iniziare

1. Apri la [dashboard Failproof AI](https://app.befailproof.ai) e crea un account o accedi con la tua email aziendale.
2. Vai a **Administration → Keys** e crea una chiave con `events:add` e `policies:pull`.
3. Copia il secret monouso e salvalo sulla macchina target:

```bash
export FAILPROOFAI_KEY="<one-time-secret>"
```

    ## Installazione

<Steps>
  <Step title="Installa e connetti Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config --connect https://app.befailproof.ai --token "$FAILPROOFAI_KEY"
    ```

    I transcript di sessione vengono inviati per impostazione predefinita. Aggiungi `--no-transcripts` per segnalare l'attività dell'hook e le decisioni delle policy senza contenuto di transcript.

    Se questa macchina ha già una cronologia di agenti, visualizza in anteprima e importa gli ultimi sette giorni, quindi attendi il completamento della consegna. Salta questo passaggio su una macchina nuova.

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    Apri **Sessions** in Failproof AI e seleziona una sessione importata.
  </Step>
  <Step title="Installa i hook dell'agente e le policy">
    Questo collega Failproof AI al tuo harness e installa le 40 policy built-in. Utilizzale per vedere le decisioni di policy locali e provare l'enforcement prima che Failproof AI auditi le tue sessioni e scrivi policy per i tuoi agenti.

    Lascia che il programma di installazione rilevi il tuo harness, oppure specificane uno esplicitamente. Ognuno dei 12 è un valore `--cli` valido — `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, `goose`.

    ```bash
    failproofai policies --install --cli claude --scope user     # una CLI di coding
    failproofai policies --install --cli hermes --scope user     # un gateway Slack/Telegram
    ```

    Il blocco di una chiamata di tool prima dell'esecuzione è verificato su tutti e 12. I gate di fine turno sono verificati su 8 — consulta [capacità di enforcement](/it/reference/harnesses#enforcement-capability) per la matrice per-harness.
  </Step>
  <Step title="Audita il comportamento">
    Segui [Esegui il tuo primo controllo di errore](/it/start/first-audit). Utilizza un obiettivo concreto come ad esempio "trovare sessioni dove l'agente ha ritentato uno strumento non riuscito senza cambiare il suo approccio."
  </Step>
  <Step title="Previeni l'errore">
    Segui [Previeni il tuo primo errore con una policy](/it/start/first-policy). Inizia in modalità di osservazione, ispeziona i corrispondenti, quindi applica l'enforce della versione revisionata.
  </Step>
</Steps>

<Check>
  Esegui `failproofai config --status`. Una configurazione corretta segnala la connessione al cloud, lo stato del daemon e se l'enforcement è in pausa.
</Check>
