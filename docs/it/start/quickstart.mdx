Configura Failproof AI su una macchina, poi rimani in locale o connettiti al Cloud.

Se il tuo agent gira in un [harness supportato](/it/reference/harnesses), segui questi passaggi. Per agent costruiti con LangChain, CrewAI, LlamaIndex, Pydantic AI, o il tuo runtime personalizzato, inizia con [instrumentare il tuo agent](/it/start/integrations).

## Lascia che il tuo agent guidi la configurazione

Installa la competenza ombrello Failproof AI in un agent compatibile:

```bash
npx skills add FailproofAI/skills
```

Questo installa la competenza ombrello e le sue sorelle specializzate. Usa `--skill
failproofai` se vuoi solo l'ombrello. Capisce la configurazione locale e Cloud,
la salute del daemon, le sessioni, i controlli, le policy e la risoluzione dei problemi. Guida il lavoro
e instrada le attività specializzate alla giusta competenza Failproof AI; non sostituisce
l'installazione CLI qui sotto.

## Configura la macchina

<Steps>
  <Step title="Installa e configura Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    La configurazione installa il servizio in background e connette ogni agent supportato che trova. Potrebbe chiedere l'accesso amministratore una volta. Supporta Linux e macOS.
  </Step>

  <Step title="Scegli le policy">
    La configurazione non sceglie alcun policy pack. Aggiungi il pack Failproof AI:

    ```bash
    failproofai policies add FailproofAI/policies
    failproofai policies
    ```

    Il secondo comando mostra ogni policy su questa macchina e se è attiva. Finché non aggiungi un pack, solo `block-failproofai-commands` è in esecuzione.
  </Step>

  <Step title="Controlla la macchina">
    ```bash
    failproofai config --status
    ```

    Questo segnala il servizio, la connessione Cloud e lo stato di pausa.
  </Step>
</Steps>

## Scegli locale o Cloud

<Tabs>
  <Tab title="Rimani in locale">
    Non è richiesto alcun account.

    ```bash
    failproofai
    failproofai audit
    ```

    Il primo comando apre il dashboard locale su `http://localhost:8020`. Il secondo scansiona la cronologia degli agent già su questa macchina.
  </Tab>

  <Tab title="Connettiti al Cloud">
    Crea una machine key in Failproof AI Cloud, poi esegui:

    ```bash
    failproofai config --token <machine-key>
    failproofai config --status
    ```

    Cloud riceve le decisioni di policy e i trascritti delle sessioni. Per inviare solo le decisioni, connettiti prima, poi imposta `collector.sessions` a `false` in `~/.failproofai/config.json`; il flag di configurazione `--no-transcripts` attuale non applica quella impostazione. Per shell condivise e CI, usa `FAILPROOFAI_CLOUD_TOKEN` invece di mettere la key nella cronologia dei comandi.
  </Tab>
</Tabs>

## Verifica

Esegui uno dei tuoi agent e chiedigli di eseguire un compito normale. Poi:

Un diniego di tool-call è verificato su tutti i 12 harness supportati. L'enforcement a fine turno
è verificato su 8; altre coppie harness-event potrebbero essere solo di osservazione o non verificate.

- Apri **Policies → Activity** nel dashboard locale per vedere le decisioni di policy.
- Apri **Observe → Sessions** nel Cloud per vedere l'esecuzione completa.
- Esegui `failproofai audit` per cercare pattern rischiosi o inefficienti.

<Warning>
  Dopo la configurazione, il servizio `failproofaid` è l'evaluator. Se non riesce a rispondere, le azioni protette vengono negate. Esegui `failproofai config --status` quando un agent si ferma inaspettatamente.
</Warning>
