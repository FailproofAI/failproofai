Failproof AI può essere eseguito interamente su una singola macchina o connettersi a Cloud per sessioni condivise e gestione delle policy.

## Locale, senza account

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai
```

Questo installa il servizio, connette gli agent supportati, aggiunge un pacchetto di policy e apre la dashboard su `http://localhost:8020`.

Esegui `failproofai audit` per scansionare la cronologia degli agent già presente sulla macchina.

## Connetti a Failproof AI Cloud

Crea una chiave macchina in Cloud, quindi esegui:

```bash
failproofai config --token <machine-key>
failproofai config --machine-label checkout-runner-01
failproofai policies add FailproofAI/policies
failproofai config --status
```

Oppure esporta `FAILPROOFAI_CLOUD_TOKEN=<machine-key>` ed esegui il comando `failproofai config` senza parametri. Preferisci la variabile d'ambiente su macchine condivise e in CI in modo che la chiave non finisca nella cronologia della shell o negli elenchi dei processi.

Cloud utilizza una sola connessione per due lavori separati:

- Recuperare le policy assegnate a questa macchina.
- Inviare le decisioni di policy e le trascrizioni delle sessioni.

Per inviare solo le decisioni, connetti prima, quindi imposta `collector.sessions` su `false` in `~/.failproofai/config.json`. Non fare affidamento su `--no-transcripts`: il percorso di configurazione attuale analizza il flag ma non lo applica. Vedi [events and configuration](/it/reference/events-and-configuration#machine-configuration).

<Note>
  `--machine-label` rinomina una macchina già connessa. Eseguilo dopo il comando di configurazione, non come parte della prima connessione.
</Note>

## Configurazione automatizzata

`failproofai config` non richiede un flag speciale non interattivo. In CI o in un contenitore applica la configurazione richiesta senza chiedere conferma.

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

L'accesso da amministratore è necessario una sola volta per installare il servizio di background. La configurazione non apre mai un prompt interattivo di password `sudo`: o riesce senza uno o stampa i comandi che un amministratore deve eseguire.

## Supporto per piattaforme

La configurazione supporta Linux e macOS. Su un'altra piattaforma viene chiusa senza scrivere hook o stato di configurazione parziale.
