人、マシン、または自動化ジョブごとに個別のキーを使用してください。必要な権限のみを付与します。

## キーの作成とローテーション

**Admin → Keys** またはCloud CLIを使用します：

```bash
fp keys list
fp keys create "audit automation" --add audits:read
fp keys disable "audit automation"
```

シークレットはキー作成時に保存してください。作成後は再表示されません。ローテーションを行う場合は、新しいキーを作成し、利用者側を更新した後、古いキーを無効化します。

## マシンキー

マシンキーはローカルサービスとCloudを接続します：

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

接続されたマシンには、次の2つのケイパビリティが必要になる場合があります：

- `policies:pull`：Cloudで管理されたポリシーを受信する。
- `events:add`：判定結果とセッションを送信する。

一方が機能しながらもう一方が機能しない場合があるため、Statusではこれらを別々に報告します。

## 主な権限一覧

| 権限 | 許可される操作 |
| --- | --- |
| `events:add` | イベントの送信 |
| `events:read` | イベントとエラーの読み取り |
| `evaluations:read` | セッションと評価の読み取り |
| `audits:read` / `audits:write` | 監査の確認または管理 |
| `policies:read` / `policies:write` | ポリシーの確認またはデプロイ |
| `policies:pull` | マシンへのポリシー割り当ての取得 |
| `keys:create` / `keys:disable` | キーの作成または無効化 |
| `orgs:admin` | インスタンスレベルの組織管理。組織キーには割り当て不可 |

一部の管理用 `fp fleet` および `fp guardrails` コマンドは、APIキーではなくサインイン済みユーザーセッションを必要とします。リクエストを行う前に、ヘルプテキストにその旨が記載されています。

<Warning>
  `AGENTEYE_KEY` や `AGENTEYE_API_KEY` などのインジェスト認証情報を `FP_API_KEY` として再利用しないでください。これらは異なるシステムと権限を対象としています。
</Warning>
