管理は Failproof AI のクラウド側の機能です。組織、メンバー、API キー、組織設定、および従量制の使用量はすべてクラウド接続が必要です。

<Note>
  Failproof AI はアカウントなしでも動作します。ローカルマシンはポリシーを適用し、セッション履歴をディスクに保存し、`localhost:8020` 上で[ローカルダッシュボード](/ja/reference/local-dashboard)を提供し、どこにも送信することなく `failproofai audit` を実行します。ローカルの `collector` キーについては[マシン設定](/ja/reference/events-and-configuration#machine-configuration)を参照してください。クラウドを使用しない場合は、このセクションの残りをスキップしてください。
</Note>

## コントロールの場所

<Tabs>
  <Tab title="ダッシュボード">
    クラウドサイドバーの **admin** グループには、**policy editor**、**enforcement**、**usage**、**keys**、**users**、**settings** が含まれています。

    ![policy editor、enforcement、usage、keys、users、settings を含むクラウドサイドバーの admin グループ。](/images/dashboard/admin-navigation.png)
  </Tab>
  <Tab title="CLI">
    Cloud CLI を独立したツールとしてインストールし、サインインします:

    ```bash
    uv tool install fp-cloud-cli
    fp login
    fp whoami
    fp usage
    ```

    グローバルオプションはコマンドの前に指定します。例: `fp --org reliability-team --json usage`
  </Tab>
</Tabs>

## サインイン済みユーザー、または API キー

`fp` は 2 つの認証モードのいずれかで動作し、その違いによって使用できるコマンドが決まります。API キーでは実行できないコマンドは、接続を開く前に拒否され、401 や 403 でその理由を代替させることなく、理由が明示されます。

| コマンド | API キー | 権限 |
| --- | --- | --- |
| `fp whoami` | 可 | なし |
| `fp usage` | 可 | `usage:read` |
| `fp keys list` / `show` | 可 | `keys:read` |
| `fp keys create` | 可 | `keys:create` |
| `fp keys disable` | 可 | `keys:disable` |
| `fp keys regenerate` | 可 | `keys:regenerate` |
| `fp keys update` | 不可 | `keys:update`（キーが保持できない権限） |
| `fp users list` / `show` | 可 | `users:read` |
| `fp users create` | 可 | `users:create` |
| `fp users update` | 可 | `users:update` |
| `fp users disable` / `enable` | 可 | `users:delete` |
| `fp settings list` / `schema` | 可 | `settings:read` |
| `fp settings set` | 可 | `settings:write` |
| `fp orgs list` / `switch` / `current` / `perms` | 不可 | サインイン済みセッションのみ |

`fp usage` はレポートスクリプトに適したコマンドです。キーのもとで無人実行でき、`usage:read` のみが必要です。
