Failproof AI Cloud は、ソフトウェア自体に関する使用状況テレメトリをメンテナーに送信します。エージェントのデータが含まれることは一切ありません。セルフホスト環境ではデフォルトで有効になっており、無効化することができます。

## 収集される情報

各イベントには5つのディメンションが含まれており、個人を特定する情報は一切含まれません。

| ディメンション | 例 | 内容 |
| --- | --- | --- |
| `product` | `agenteye` | 送信元のプロダクト |
| `component` | `dashboard`, `server`, `cli` | 送信元のプロダクト内コンポーネント |
| `app_version` | `0.0.1-beta.81` | 実行中のビルドバージョン |
| `deployment_kind` | `self_hosted` | カスタマーインストール・デモ・QA・開発環境のいずれか |
| `org_id` | UUID | アクションが発生した組織を示す不透明な識別子 |

これらに加えて、イベントには**何が使用されたかが記録されますが、その内容は記録されません**。具体的には、閲覧されたページ（`/:org/sessions/:id` のようなルートパターンで記録され、実際のURLは含まれません）、適用されたフィルターの種類と数、アクションの成否、処理にかかった時間などです。

Slack アプリは、ワークスペースの接続・切断、アカウントリンク、質問、投稿されたチャート、承認の決定、および固定カテゴリ別の失敗を記録します。Slack のワークスペース・ユーザー・チャンネルの ID、メールアドレス、質問・回答・SQL・トークンは一切含まれません。

### 組織名について

不透明な `org_id` とともに、組織名・URL スラッグ・ダッシュボードアドレスを1回だけ記録します。これはイベントごとではなく、組織レコードとして保存されます。これにより、導入状況の分析や報告された問題の調査の際に、パターンがどのアカウントに属するかを判別できます。プロダクトが送信する、あなたに関する唯一の識別情報です。

### 使用量の集計

サーバーは各組織の使用量集計（使用状況ページで確認できる数値と同じ）を報告します。これらはカウント数のみです。具体的には、イベント・セッション・エージェント・環境・評価実行・スコア・監査実行・保存済みクエリ・ダッシュボード・アラート・問題・API キー・メンバーの各件数と、計測期間の日付です。識別子・名前・クエリテキストは含まれず、誰かがサインインしているかどうかにかかわらず送信されます。

## 収集されない情報

- **プロンプト・モデルの応答・イベントの内容**（テキスト・プレフィックス・ハッシュのいずれの形式も含まない）
- **セッション・エージェント・トレースの識別子**
- **評価スコアの名前**
- **エラーメッセージ・例外テキスト・レスポンスボディ**（ステータスコードと固定リストのカテゴリのみ記録）
- **ツール引数・SQL・クエリテキスト**
- **接続アプリの詳細**（MCP クライアントの接続・取り消しでは、最大でも権限数のみ送信され、アプリ名やトークンは含まれない）
- **メールアドレス**
- **リファラー URL またはクエリ文字列**
- **スクリーン録画・DOM キャプチャ・クリックやカーソルのトラッキング**

## セルフホスト環境での無効化

ダッシュボードとサーバーの両方に `DO_NOT_TRACK=1` を設定してください。それぞれが独立して判断するため、一方にのみ設定した場合、もう一方は引き続き報告を行います。変更を反映するにはサーバーを再起動してください。

その他のオプトアウト設定とテレメトリが無効化されていることの確認方法については、リリースの README を参照してください。

## オプトアウト時の1回限りのピング

プロダクト設定で（`DO_NOT_TRACK` を使わずに）オプトアウトした場合、ダッシュボードはそれを記録する**匿名の1回限りのピング**を送信することがあります（プロセス起動ごとに1000分の1の確率）。これはオペレーターがテレメトリを無効化した件数を把握するためのものです。識別子は一切含まれません。組織・ユーザー・ホスト名・URL・IP はなく、プロダクト・コンポーネント・バージョン・デプロイ種別・理由のみです。オプトアウト済みのサーバーは何も送信しません。

`DO_NOT_TRACK` を使用した場合はこのピングも送信されません。ポリシーで外部へのテレメトリ送信が一切禁止されている場合は、この設定を使用してください。

## 送信先

TLS を使用してポート 443 経由で PostHog（`us.i.posthog.com`）に送信されます。ホスト名は1つだけなので、単一のエグレスルールでブロックすることもできます。

個人情報の取り扱いについての詳細は、[プライバシーポリシー](https://befailproof.ai/privacy/)をご覧ください。
