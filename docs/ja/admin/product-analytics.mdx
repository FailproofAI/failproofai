Failproof AI Cloud は**ソフトウェア自体に関する**利用状況テレメトリーをメンテナーに送信します。エージェントのデータが含まれることは一切ありません。セルフホスト環境ではデフォルトで有効になっており、オフにすることができます。

## 収集される情報

すべてのイベントは5つのディメンションを持ち、個人を特定する情報は一切含まれません。

| ディメンション | 例 | 内容 |
| --- | --- | --- |
| `product` | `agenteye` | 送信元のプロダクト |
| `component` | `dashboard`, `server`, `cli` | 送信元のプロダクトのコンポーネント |
| `app_version` | `0.0.1-beta.81` | 実行中のビルドバージョン |
| `deployment_kind` | `self_hosted` | カスタマーインストール、デモ環境、QA環境、開発マシンのいずれか |
| `org_id` | UUID | アクションが発生した組織を示す不透明な識別子 |

これらに加えて、イベントは**何が使用されたかのみを記録し、その内容は記録しません**。具体的には、閲覧されたページ（`/:org/sessions/:id` のようなルートパターンとして記録され、実際のURLは記録されません）、適用されたフィルターの種類と数、アクションの成否、所要時間などが含まれます。

Slackアプリは、ワークスペースの接続・切断、アカウントリンク、質問、チャート投稿、承認の決定、および固定カテゴリ別の失敗を記録します。Slackのワークスペース・ユーザー・チャンネルID、メールアドレス、質問・回答・SQL・トークンは一切含まれません。

### 組織名について

不透明な `org_id` とともに、組織名、URLスラッグ、およびダッシュボードアドレスを1度だけ記録します。これはすべてのイベントではなく、組織レコードとして保存されます。これにより、採用状況の分析や報告された問題の調査の際に、特定のパターンがどのアカウントに属するかを把握できます。これがプロダクトが送信する唯一の識別情報です。

### 利用状況の合計

サーバーは各組織の計測済み利用状況の合計を報告します。これはUsageページに表示される数値と同じです。内容はカウントのみです。イベント、セッション、エージェント、環境、評価実行、スコア、監査実行、保存済みクエリ、ダッシュボード、アラート、イシュー、APIキー、メンバー数、および計測期間の日付が含まれます。識別子・名前・クエリテキストは含まれず、誰かがサインインしているかどうかに関わらず送信されます。

## 収集されない情報

- **プロンプト、モデルの応答、イベントの内容** — テキスト、プレフィックス、ハッシュのいずれの形式でも収集しません
- **セッション・エージェント・トレースの識別子**
- **評価スコアの名前**
- **エラーメッセージ、例外テキスト、レスポンスボディ** — ステータスコードと固定リストのカテゴリのみ
- **ツールの引数、SQL、クエリテキスト**
- **接続アプリの詳細** — MCPクライアントの接続・失効時に送信されるのは最大でパーミッション数のみで、アプリ名やトークンは含まれません
- **メールアドレス**
- **リファラーURLやクエリ文字列**
- **スクリーン録画、DOMキャプチャ、クリック・カーソルトラッキング**

## セルフホスト環境でオフにする方法

ダッシュボードとサーバーの両方に `DO_NOT_TRACK=1` を設定してください。それぞれが独立して判断するため、一方にのみ設定した場合は、もう一方が引き続き報告を行います。変更を反映するにはサーバーを再起動してください。

リリースのREADMEには、その他のオプトアウト設定とテレメトリーがオフになっていることを確認する方法が記載されています。

## オプトアウト時の1回限りのpingについて

プロダクト設定で `DO_NOT_TRACK` を使用せずにオプトアウトした場合、ダッシュボードはプロセス起動ごとに1/1000の確率で**匿名の1回限りのping**を送信する場合があります。これはテレメトリーをオフにしたオペレーターの数を把握するためのものです。識別情報は一切含まれません。組織・ユーザー・ホスト名・URL・IPアドレスは含まれず、プロダクト・コンポーネント・バージョン・デプロイ種別・理由のみが送信されます。オプトアウト済みのサーバーは何も送信しません。

`DO_NOT_TRACK` を使用した場合はこのpingも送信されません。アウトバウンドテレメトリーを禁止するポリシーがある場合は、この方法を使用してください。

## 送信先

TLSを使用してポート443経由でPostHog（`us.i.posthog.com`）に送信されます。ホスト名は1つのみであるため、単一のエグレスルールでブロックすることも可能です。

個人情報の取り扱いについての詳細は、[プライバシーポリシー](https://befailproof.ai/privacy/)をご覧ください。
