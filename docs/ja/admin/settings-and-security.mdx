組織設定は、そのクラウド組織に属するすべてのユーザーに影響します。**Admin → settings** から変更するか、`fp settings` を使用してください。

```bash
fp settings list
fp settings set <key> <value>
```

## データ処理

接続されたマシンは、デフォルトでポリシー判断とセッションの完全なトランスクリプトを送信します。判断のみを送信するには、接続後にマシンの `~/.failproofai/config.json` で `collector.sessions` を `false` に設定してください。現在の `--no-transcripts` セットアップフラグは、この設定を適用しません。

認証情報はアップロード前にマシン上でスクラブされますが、この秘匿化はあくまで安全の最低ラインであり、アクセス制御の代替にはなりません。

ローカル専用での使用にアカウントは不要です。セッション履歴と監査はマシン上に保持されますが、スケジュールされたローカル監査はオプトイン後にマシンのアイデンティティと限定的なダイジェストを送信します。匿名の CLI テレメトリは `FAILPROOFAI_TELEMETRY_DISABLED=1` で無効化できます。

## 認証情報

マシントークンは `~/.failproofai/` 以下にオーナーのみがアクセスできる権限で保存されます。サービス定義には書き込まれません。

人、自動化、マシンにはそれぞれ別のキーを使用してください。各キーには必要最小限の権限のみを付与し、所有者が変わった際にはローテーションし、マシンやワークフローが廃止された際には失効させてください。

## チェックリスト

- 必要最小限の権限のみを要求する。
- 完全なコンテンツが不要な場合は `collector.sessions` を `false` に設定する。
- 強制ポリシーをデプロイできるユーザーを確認する。
- 強制適用の前に、オブザーブモードでポリシーをテストする。
- マシンのラベルを明確に保ち、マシン ID を安定させる。
- 接続設定を変更した後は `failproofai config --status` を実行する。

権限カタログについては [keys and permissions](/ja/admin/keys-and-permissions) を参照してください。
