使用状況では、現在の組織が30日間の計測ウィンドウ内でどれだけ使用したかを確認できます。ウィンドウは固定されており、組織ごとに基準点が設定されています。使用状況は読み取り専用であり、制限・クォータ・プランのしきい値は適用されず、表示もされません。どちらのインターフェースでもその旨が示されており、CLIパネルには「読み取り専用の使用状況、制限なし」と表示されます。

## 使用状況を確認する

<Tabs>
  <Tab title="ダッシュボード">
    1. **管理者 → 使用状況** に移動します。
    2. 組織と計測ウィンドウを確認します。ヘッダーにはウィンドウの開始日・終了日、現在の日付、経過割合が表示されます。
    3. ヒーローブロックを確認します：取り込まれたイベント数、セッション数、エージェント数、環境数。
    4. 2つのパイプラインを確認します：評価パイプライン（スコアとメトリクス付き）と監査パイプライン（問題とアラート付き）。それぞれ開始済みの実行数に対して完了した実行数が表示されます。
    5. ワークスペースとアクセスのブロックを確認します：保存済みクエリ、ダッシュボード、アラート、ユニーク問題数、メンバー数、APIキー数。

    表示される数値はキャッシュされており、リアルタイムではありません。変更後に最新の状態を確認するには、右上の更新ボタンを使用してください。

    ![計測ウィンドウ、取得されたイベント、評価・監査パイプライン、ワークスペースリソース、メンバー、APIキーを表示した使用状況ページ。](/images/dashboard/usage-overview.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp usage
    fp --json usage
    fp --org reliability-team --json usage
    ```

    `fp usage` には `usage:read` 権限が必要で、APIキーの下で実行されます。そのため、レポート用のcronジョブに適したコマンドです。

    `--json` を指定すると、ダッシュボードのレスポンスをそのまま返します：`org_id`、`billing_anchor`、`window`、`usage`、`calculated_at`、`stale_after`。`calculated_at` と `stale_after` を使って、数値がどれくらい古いかを確認できます。

    `fp usage` 固有のフラグはなく、グローバルな `--json` と `--org` のみ使用できます。現在のウィンドウのみを報告し、過去のウィンドウを後から照会することはできないため、スケジュール実行して `--json` のペイロードを保存することで独自の履歴を管理してください。

    ```bash
    fp --json usage | jq '.usage.events_ingested'
    ```
  </Tab>
</Tabs>

### メトリクスキー

JSONペイロードの `usage` 以下のすべてのキーです。スクリプトからパネルをパースする代わりにフィールド名で参照できます。

| グループ | キー |
| --- | --- |
| テレメトリ | `events_ingested`, `sessions`, `agents`, `environments` |
| 評価 | `evaluation_runs`, `evaluation_finishes`, `evaluations`, `metrics` |
| 監査 | `audit_runs`, `audit_finishes`, `issues_created`, `alerts_created` |
| ワークスペース | `queries_created`, `dashboards_created` |
| アクセス | `users_active`, `users_created`, `keys_active`, `keys_created` |

各パイプラインは開始数と完了数を個別に報告します。`audit_runs` と `audit_finishes` の間に差異がある場合、開始したものの完了しなかった処理があることを意味します。その下の問題数を解釈する前に確認する価値があります。

## 変化を調査する

取り込み量はマシンごとに決定され、中央管理ではありません。組織とウィンドウを起点として、レポートしているマシン上で何が変化したかを順に確認してください。

| 原因 | 確認場所 | 変更内容 |
| --- | --- | --- |
| セッションのトランスクリプトを送信しているマシンがある | 該当マシンの `~/.failproofai/config.json` 内の `collector.sessions` | `false` に設定すると、決定内容のみ送信されます |
| フックアクティビティが全件送信されている | 同ファイルの `collector.hooks_verbosity` | `decisions` は許可をper minuteで集計します。`off` はフックイベントを完全に停止します |
| 新しいキャプチャ場所が追加された | `failproofai harness list` | `failproofai harness remove-path <harness> <path or label>` で削除します |
| 履歴が再送信された | 該当マシンの `failproofai backfill` の実行 | 再送信はコンテンツハッシュで重複排除され、既存の行に統合されるため、二重計上にはなりません |
| 新しいインテグレーションがレポートを開始した | `agents` と `environments` の数、およびセッションリスト | ロールアウト前に新しいマシンのコレクター設定をスコープしてください |

使用状況はプランとの比較を行いません。その比較はプロダクト外で実施してください。
