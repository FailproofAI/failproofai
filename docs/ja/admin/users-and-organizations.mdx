組織はセッション、評価、監査、課題、アラート、クエリ、ダッシュボード、ユーザー、およびキーを分離します。管理リソースを変更する前に、アクティブな組織を確認してください。

## 組織を選択する

<Tabs>
  <Tab title="ダッシュボード">
    クラウドサイドバーの上部にある組織スイッチャーを使用します。その下に表示されるすべての項目（**admin** 内のすべてのページを含む）が、その組織に対する読み取りおよび書き込みの対象となります。
  </Tab>
  <Tab title="CLI">
    ```bash
    fp orgs list
    fp orgs switch reliability-team
    fp orgs current
    fp orgs perms
    ```

    スラッグを指定せずに `fp orgs switch` を実行すると、現在の組織を起点とした矢印キーによるピッカーが開きます。非インタラクティブな実行では番号付きプロンプトにフォールバックし、`--json` を指定した場合はスラッグが必須です。選択内容は `~/.failproofai/fpcli/cli-auth.json` に保存されるため、以降のコマンドでアクティブなテナントとして送信されます。1つのコマンドに限って上書きする場合は `--org <slug>` または `FP_ORG` を使用してください。
  </Tab>
</Tabs>

<Note>
  `fp orgs` コマンドはすべてサインイン済みの人間ユーザーを必要とし、APIキーでは使用できません。組織メンバーシップは個人に紐付くものであり、キーはすでに1つの組織に対して動作するためです。以下の `fp users` コマンドはどちらの方法でも動作します。
</Note>

## メンバーを管理する

<Tabs>
  <Tab title="ダッシュボード">
    1. **admin → users** に移動し、メールアドレスでメンバーを検索するか、`protected`、`admin`、`standard`、`read-only` のフィルターチップでリストを絞り込みます。
    2. **new user** を選択し、メールアドレスを入力して権限セットを選択し、必要に応じてメンバーごとの上書き設定を調整します。
    3. 後からメンバーを開いて、付与権限の変更、サインインの無効化、またはアカウントの再有効化を行います。

    ![メール検索ボックス、フィルターチップ、およびリソース別にグループ化された付与権限を表示するメンバーカードを含むユーザーページ。](/images/dashboard/users.png)

    このフレームの付与チップは `incidents:*` から `issues:*` へのリネーム前のものです。最新の情報は[共通権限](/ja/admin/keys-and-permissions#common-permissions)の一覧を参照してください。
  </Tab>
  <Tab title="CLI">
    ```bash
    fp users list
    fp users list --active-only
    fp users create engineer@example.com --permission-set standard
    fp users show engineer@example.com
    fp users update engineer@example.com --add audits:write
    fp users disable engineer@example.com
    fp users enable engineer@example.com
    ```

    メンバーはメールアドレスで指定され、大文字小文字を区別せずに解決されます。そのため、`fp users show Alice.Chen@Example.com` と `fp users create alice.chen@example.com` は同じ人物を指します。
  </Tab>
</Tabs>

### 付与権限と各動詞に必要なもの

メンバーの付与権限はキーと同じ演算を使用します。有効な付与権限は `(セット ∪ 追加) − 削除` となり、`--add` / `--remove` はドット区切りのアクションを展開するコンパクトな `slug:action.action` トークンを受け取ります。詳細は[キーと権限](/ja/admin/keys-and-permissions)を参照してください。

| 動詞 | 権限 | 備考 |
| --- | --- | --- |
| `fp users list` / `show` | `users:read` | `--active-only` は無効化されたメンバーを非表示にします。 |
| `fp users create` | `users:create` | `--permission-set` でロールの初期値を設定し、`--add` / `--remove` で上書きを重ねます。 |
| `fp users update` | `users:update` | `--permission-set` はメンバーのメンバーごとの上書きを**置き換えます**。`--add` / `--remove` のみの場合は現在の付与権限に対して増分的に適用されます。 |
| `fp users disable` / `enable` | `users:delete` | 無効化・有効化の両方に必要です。意図的に付与してください。 |

無効化はバリデーションメッセージではなく Forbidden エラーとして、2つのケースを明示的に拒否します。**protected** メンバーは無効化できず、自分自身のアカウントを無効化することもできません。すでに無効化されているメンバーの無効化、またはすでにアクティブなメンバーの有効化は、静かなノーオペレーションとなります。APIは無効化に削除操作を使用しますが、アカウントもメンバーシップレコードも削除されません。

メンバーシップに関わる組織設定が2つあります。`default_user_permissions` は新しい招待の権限セットの初期値を設定し、`allowed_sign_ins` はサインインコードを受信できるアドレスを制限します。これらは[設定ページ](/ja/admin/settings-and-security)から管理できます。

<Warning>
  ユーザーを無効化すると、現在選択中の組織だけでなく、すべての組織へのサインインがそのIDに対してブロックされます。再有効化するとグローバルなサインインと、この組織でのメンバーの権限が復元されます。
</Warning>

<Tip>
  サービスアカウントには、ワークロードと担当者に紐付けた分かりやすい名前を付けてください。組織間でキーを共有したり、個人とマシンの間でキーを共有したりしないでください。
</Tip>
