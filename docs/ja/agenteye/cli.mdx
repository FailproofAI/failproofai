ターミナルまたはスクリプトから Failproof AI Observability のすべての操作を行えます。ダッシュボードへの往復は不要です。`agenteye` CLI はデータ（セッション、イベントログ、評価）の照会と、組織の管理（API キー、ユーザー、設定、アラート、インシデント、保存済みクエリ）を担います。チェックの自動化、Observability の CI への組み込み、コーディングエージェントによる本番環境の検査を行いたいときに活用してください。すべてのコマンドが `--json` フラグをサポートしているため、プロンプト上での手動操作にも、コーディングエージェント（Claude Code、Cursor）がシェルアウトして結果をパースする用途にも等しく対応します。

1 つのバイナリで以下が行えます：

- **データの読み取り**: `sessions`、`events`、`evals`、`errors`（時間・エージェント・環境・スコアでフィルタリング）。
- **組織の管理**: `keys`、`users`、`settings`、`alerts`、`incidents`。
- **アナリティクスの実行**: 保存済み SQL とアドホッククエリランナー（`query`）。
- **AI アシスタントへの問い合わせ**: ダッシュボードでチャットできるものと同じ読み取り専用アナリスト（`agent`）。

> **注意:** これは `agenteye` CLI であり、コレクターデーモン（`agenteye-collector`）とは別のツールです。CLI はダッシュボードと通信し、コレクターはイベントをサーバーに送信します。

## クイックスタート

ゼロから最初の結果を得るまで 4 行で完了します。CLI にダッシュボードの URL を設定し、サインインして身元を確認した後、直近 1 日間の実行履歴を取得します：

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # メールで 6 桁のコードが届きます
agenteye whoami                                                                  # ユーザーとアクティブな組織を確認
agenteye --json sessions --since 24h                                             # エージェントの実行ごとに 1 行、直近 24 時間分
```

最後のコマンドは最新のセッションを JSON オブジェクトとして出力します（新しい順、デフォルトで最大 50 件）。`jq` にパイプして加工することも、`--json` を省略してボックス形式のカラー表示テーブルとして確認することもできます。各行には実行のステータスと、評価器がスコアを付けている場合はメトリクスのスコアが含まれます（以下は省略表示）：

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

このページの残りでは各項目を説明します：[インストール](#installation)の独立した手順、[サインイン](#authentication)、[設定](#configuration)、すべてのコマンドに共通する[グローバル規約](#global-options--conventions)、そして[コマンドリファレンス全体](#command-reference)です。

## インストール

CLI は PyPI で **`agenteye`** という名前で公開されています。依存関係を独立させるため、隔離した環境にインストールしてください：

```bash
pipx install agenteye
# または
uv tool install agenteye
```

Python 3.10 以上が必要です。インストールされるコマンドは **`agenteye`** です：

```bash
agenteye --version
agenteye --help
```

> **注意:** Failproof AI Observability Python SDK も `agenteye` というディストリビューション名を使用しています。`pipx` または `uv tool` で CLI をインストールする（共有の仮想環境に `pip install` するのではなく）ことで、両者の競合を回避できます。SDK が同じ環境にインストールされていない場合に限り、`pip install agenteye` による通常のインストールも問題ありません。

## 認証

CLI はメールで届くワンタイムコードを使って**ダッシュボード**に認証します：

```bash
agenteye login --email you@example.com
# 6 桁のコードがメールで届きます。プロンプトに貼り付けてください。
```

セッショントークンは `~/.agenteye/cli.json`（自分だけが読めるよう、モード `0600`）に保存され、デフォルトで 24 時間有効です。期限切れになったら、`agenteye login` を再実行してください。

```bash
agenteye whoami     # 現在のユーザー、アクティブな組織、権限を表示
agenteye logout     # セッションを無効化し、保存されたトークンを削除
```

`whoami` はセッションが存在しない場合や期限切れの場合もエラーにならず、代わりに `logged_in: false` を返します。これによりスクリプトやエージェントが安全に認証状態を確認できます（ベース URL が未設定またはダッシュボードに到達できない場合は、依然として非ゼロの終了コードで終了することがあります）。

**要件:** あなたのメールアドレスがダッシュボードへのサインインを許可されていること（Failproof AI Observability の管理者に確認してください）、およびダッシュボードがベース URL で到達可能であること（[設定](#configuration) を参照）が必要です。コードをリクエストしても届かない場合、そのメールアドレスはまだダッシュボードアクセスが有効化されていない可能性があります。

## 組織の選択（マルチテナント）

アカウントが複数の組織に所属している場合は、**ログイン時に**アクティブな組織を選択します。選択内容は保存され、以降のすべてのコマンドに使用されます：

```bash
agenteye login --org acme           # 認証とアクティブテナントの設定を一度に行う
agenteye orgs list                  # アクセス可能な組織一覧（アクティブな組織にマーク付き）
agenteye orgs switch globex         # 保存済みのデフォルトを変更
agenteye --org globex sessions      # 単一コマンドのみ上書き
```

組織が 1 つだけの場合は自動的に選択されるため、`--org` は無視できます。複数の組織に所属していて選択していない場合、CLI が一覧を表示し、`--org <slug>` を付けて再実行するよう促します。アクティブな組織はすべてのリクエストでダッシュボードに送信され、権限は**組織ごと**に解決されます。`agenteye whoami` はアクティブな組織、その組織での権限、すべてのメンバーシップを表示します。

## 設定

| 設定 | フラグ | 環境変数 | デフォルト |
|---|---|---|---|
| ダッシュボードのベース URL | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **必須**（デフォルトなし） |
| アクティブな組織/テナント | `--org` | `AGENTEYE_ORG` | ログイン時に選択。`~/.agenteye/cli.json` に保存 |
| セッショントークン | `--token` | `AGENTEYE_CLI_TOKEN` | `~/.agenteye/cli.json` から取得 |
| JSON 出力 | `--json` | `AGENTEYE_CLI_JSON` | オフ |
| TLS 検証をスキップ | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | オフ（ログイン時に保存） |
| リクエストタイムアウト（秒） | `--timeout` | _（なし）_ | 30 |
| 使用状況のテレメトリを無効化 | _（なし）_ | `AGENTEYE_ANALYTICS_DISABLED`（または `DO_NOT_TRACK`） | テレメトリは現在無効。何も送信されません |

解決の優先順位は **フラグ → 環境変数 → 設定ファイル** です。デフォルト値はないため、コマンドごと（`--base-url https://agenteye.example.com`）または環境変数経由で CLI にダッシュボードの場所を指定する必要があります（最初の `login` 実行後にも保存されます）：

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

設定ディレクトリは `AGENTEYE_HOME`（SDK とコレクターが使用するのと同じ慣例）を尊重します。設定されている場合、`cli.json` は `$AGENTEYE_HOME/cli.json` に置かれます。

### 自己署名証明書または内部 TLS

ダッシュボードが自己署名証明書または内部証明書を使った HTTPS で提供されている場合（例: ロードバランサーの生のホスト名）、TLS 検証は `CERTIFICATE_VERIFY_FAILED` エラーで拒否します。証明書の検証をスキップするには `--insecure` を渡してください：

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` はログイン時に **`cli.json` に保存される**ため、以降のコマンドは自動的に検証をスキップします。フラグを毎回指定する必要はありません。一度だけ検証ありで呼び出したい場合は `--secure` を、次回のログインで検証を再び有効にしたい場合も `--secure` を使用してください。CLI はダッシュボードへの接続中に検証が無効になっている場合、stderr に警告を出力します。検証をスキップするとマン・イン・ザ・ミドル攻撃に対する保護がなくなります。これを利用する前に、ダッシュボードへのネットワーク経路（VPN、プライベートサブネットなど）が信頼できることを確認してください。

## テレメトリとプライバシー

> **注意:** 現在出荷されている CLI は**使用状況テレメトリを一切送信しません。** マスターキルスイッチがオンになっており、環境に関わらず何も送信されません。以下のセクションでは、テレメトリが将来有効になった場合のためのオプトアウト機能について説明します。

有効になった場合でも、テレメトリは**匿名の使用状況分析のみ**であり、エージェント・セッション・イベントのデータは決して含まれません：

- **エージェント・セッション・イベントのデータはインフラストラクチャの外に出ることはありません。** 報告されるのは CLI の使用状況のみです：コマンドとサブコマンド名（例: `keys create`）、使用したフラグの**名前**（値は決して含まない）、成功/終了ステータス、処理時間、および変更操作のアクションごとのイベント（例: `api_key_created`、`query_run`）で、静的な名前/列挙値と大まかなカウントのみが含まれます。ダッシュボード URL、セッショントークン、メールアドレス、組織スラッグ、リソース ID、SQL、キーのシークレット、クエリフィルターは**決して送信されません。** オペレーターは不透明な内部 ID でのみ識別され、メールアドレスは使用されません。
- CLI の環境で `AGENTEYE_ANALYTICS_DISABLED=1` を設定することで**事前にオプトアウト**できます（CLI はクロスツールの `DO_NOT_TRACK=1` 慣例にも対応しています）。テレメトリが有効になった瞬間から効果を発揮するため、プライバシーを重視する環境では永続的にオプトアウト状態を維持できます。
- テレメトリが有効な場合、CLI は直接 PostHog（`https://us.i.posthog.com`）に送信します。このホストをブロックしているマシンでは何も送信されず、CLI の動作に影響はありません。

## グローバルオプションと規約

一度読めばすべてのコマンドに適用されます。

- **グローバルオプションはコマンドの前に指定します。** `agenteye --json sessions` が正しく、`agenteye sessions --json` は使用エラーです。グローバルオプションは `--json`、`--base-url`、`--org`、`--token`、`--insecure`/`--secure`、`--timeout`、`--quiet`、`--no-color` です。
- **`--json` は純粋な JSON のみを stdout に出力します。** 人間向けのステータス行、警告、エラーは **stderr** に出力されるため、ステータス行が表示される場合でも `--json` の stdout キャプチャを `jq` にパイプできます。`--json` なしの場合は、人間の目向けのボックス形式のカラー表示になります。
- **`--help` で調べられます。** すべてのコマンドとサブコマンドに `--help`（および `-h` エイリアス）があります：`agenteye -h`、`agenteye sessions -h`、`agenteye keys create -h`。トップレベルのヘルプには終了コードとグローバルオプションも一覧表示されます。グローバルなマシン読み取り可能なサーフェスダンプはありません。コマンドごとの `--help` に加え、`agenteye query schema` と `agenteye settings schema` を利用して各レジストリを確認してください。
- **確認プロンプトはスクリプトとエージェントでは自動的にスキップされます。** create/update/delete コマンドはインタラクティブなターミナルでは「実行してよいですか？」と尋ねますが、**`--json` が指定されているか、stdin が TTY でない場合は自動的にスキップ**されます（TTY はインタラクティブなターミナルセッションです。パイプや CI ランナーは TTY ではありません）。これにより、スクリプトやエージェントがハングすることはありません。明示的にスキップするには `--yes`/`-y` を使います。エージェントにはプロンプトが表示されないため、エージェントは破壊的な操作を実行する前に人間に確認を求めるべきです。
- **ページネーション:** 結果は新しい順にカーソルページネーションされます（各ページは次のページ取得に使うトークンを返します）。`--limit N`（エイリアス `-n`）は行数を制限し、**デフォルトは 50** です。`--all` は自動的にページネーションを行いますが（200 行のチャンク単位）、**`--limit` まで**に制限されるため、`--all` 単体でも 50 件で止まります。すべてを取得したい場合は高い上限値を明示してください：`--all --limit 1000`。`--page-size N` はリクエストごとのチャンクサイズを制御します（最大 200）。`--cursor <id>` は前のページの `next_cursor` から再開します。
- **時間フィルター:** `--since` は相対的なウィンドウを受け付けます：`15m`、`1h`、`6h`、`24h`、`7d`、または `all`（ダッシュボードのプリセット）。より長いまたはカスタムの範囲（例: 直近 30 日間）には `--from`/`--to` を使用します：**`T` とタイムゾーンを含む** 明示的な ISO-8601 UTC タイムスタンプ（例: `2026-06-01T00:00:00Z`）で、`--since` を上書きします。スペース区切りやタイムゾーンなしの値は使用エラーです。
- **`--fields a,b,c`**（`events`、`sessions`、`evals`、`errors` で使用可能）は出力をそれらのキーに限定します。テーブルと `--json` の両方に適用されます。不明な名前は有効な一覧と共にエラーとなり、フィールド名を調べる手軽な方法にもなります。
- **`--file payload.json`**（または `--file -` で stdin を読み込む）は、リソースの形状が複雑な場合に完全な JSON リクエストボディを提供します（`alerts create/update`、`settings set`、`users create/update` で使用）。保存済みクエリの SQL は代わりに `--sql @file.sql` を使います。
- **複数値フィルター**はカンマ区切りで指定し、集合としてマッチします（1 つのフィルター内は OR、フィルター間は AND）：`--event-type tool_use,tool_result`。Click のオプションは可変長ではないため、`--add a b` は動作しません。`--add a,b` を使うか、フラグを繰り返す（`--add a --add b`）か、クォートする（`--add "a b"`）かしてください。

## コマンドリファレンス

### 最もよく使う 5 つのコマンド

日常的な作業のほとんどは、いくつかの読み取りコマンドで完結します。まずここから始め、必要に応じて以下の全機能を参照してください：

| コマンド | 用途 | 試してみる |
|---|---|---|
| `sessions` | エージェントの実行ごとに 1 行：時間、環境、エージェント、ステータス、最新スコア。 | `agenteye --json sessions --since 24h --status error` |
| `events` | 実行内の各ステップの生のトレイル（`--full` でペイロードを含む）。 | `agenteye --json events --session-id run-001 --all` |
| `evals` | 評価結果とスコア。`--aggregate` で集計。 | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | エラーが発生したイベントのみ。`--aggregate` でタイプ別件数。 | `agenteye --json errors --since 24h --aggregate` |
| `list` | 有効なフィルター値（エージェント、環境、モデルなど）を探す。 | `agenteye list agents` |

### CLI の全機能

以下に全サーフェスを記載します。CLI には **18 のトップレベルコマンド**があります。すべての読み取りコマンドは `--json` と上記のグローバルオプションを受け付けます。任意のコマンドの完全なフラグ一覧と JSON の形状は `agenteye <command> -h`（または `<command> <subcommand> -h`）で確認できます。

### 認証: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # メールで届くワンタイムコード。セッションを保存します
agenteye logout                                       # このマシンの保存済みセッションを削除
agenteye whoami                                       # 現在のユーザー、アクティブな組織、権限
agenteye version                                      # CLI のバージョンを出力（--version と同じ）
agenteye help                                         # トップレベルのヘルプ（--help と同じ）
```

`orgs` はアクティブなテナントの確認と切り替えを行います：

```bash
agenteye orgs list        # 所属する組織と各組織でのロール（アクティブな組織にマーク付き）
agenteye orgs switch acme # 保存済みのアクティブ組織を変更（スラッグを省略すると TTY でリストから選択）
agenteye orgs current     # アクティブな組織の情報カード
agenteye orgs perms       # アクティブな組織における権限（リソース別にグループ化）
```

### 観測（読み取り専用）: `events` · `sessions` · `evals` · `errors` · `list`

これらは確認プロンプトが不要です。共通フィルター: `--session-id`、`--agent-id`、`--env`（`--environment` では**ありません**）、時間範囲（`--since` / `--from` / `--to`）。

```bash
# events（エイリアス: 各ステップの生のトレイル）、新しい順
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: エージェントの実行ごとに 1 行（時間/環境/エージェント/セッション/ステータス。スコアフィルタリングなし）
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: 評価結果とスコア。--score でメトリクスフィルタリング、--aggregate で集計
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # ステータスの内訳とキーごとのスコア統計

# errors: エラーが発生したイベント。--aggregate で件数/セッション/エージェント/最終発生時刻
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: フィルタリング前に有効なフィルター値を確認
agenteye list envs        # 他: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX`（**`evals`** で使用可能。`sessions` では不可）は繰り返し指定でき AND で組み合わされます。いずれかの境界は省略可能（`..0.5` は ≤ 0.5、`0.9..` は ≥ 0.9 を意味します）。リクエストあたり最大 20 のスコアフィルターを指定できます。`evals --scores-full` は**人間向けテーブルのみ**に対する表示フラグで、最初のいくつかのスコアペアと `+N` のカウント表示の代わりにすべてのスコアペアを表示します。`--json` では効果がなく、常に完全なスコアオブジェクトが返されます。**1 つのセッションを最初から最後まで読むには**、イベントトレイルと評価を組み合わせます：

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # スコアとステータス
```

### 管理（権限が必要）: `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: API キー。シークレットはローカルで生成されてサーバーに送信され（サーバーはハッシュのみ保存）、作成/再生成時に**一度だけ**表示されます。その場でキャプチャしてください。`--json` の場合は `key` フィールドにのみ表示されます。**名前**で参照されます。

```bash
agenteye keys list                                   # アクティブなキーが先、次に失効済みキー
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # 必要なスコープのみを付与。シークレットは一度だけ表示されます
agenteye keys create ops --permission-set standard --remove queries:run   # プリセットを元に調整
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # シークレットをローテート（古いものは使用不可になります）
agenteye keys disable ci-bot --yes                   # 失効させる
```

権限は `(permission-set ∪ --add) − --remove` として機能します。トークンは `slug:action`（例: `events:read`）または 1 つのリソースに複数のアクションを展開する `slug:action.action`（`events:read.add` → `events:read`、`events:add`）の形式です。プリセット: `read-only`、`standard`、`admin`。人間専用の権限（`keys:update`）はキーに付与できません。

**`users`**: 組織メンバー。**メールアドレス**で参照されます（UUID の id も受け付けます）。

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # 変更内容を確認してから実行
agenteye users disable dev@corp.com --yes            # 保護/自分自身に対するガードあり
agenteye users enable dev@corp.com
```

**`settings`**: 固定されたレジストリ（既存のキーを読み取り・変更できますが、新しいキーは作成できません）。

```bash
agenteye settings list                               # キー・値・型・更新日時（シークレットはマスク）
agenteye settings schema                             # 各キーが受け付ける値（型・範囲・説明）
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: アラート定義。**名前**で参照されます。`create` は位置引数の NAME とフラグ、または `--file` による完全な JSON ボディを受け付けます。

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME は必須（位置引数）
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # テスト通知を発火
agenteye alerts delete high-errors --yes
```

**`incidents`**: アラートインシデント。id で参照されます（短い id も受け付けます）。`show` は完全なアクティビティログを出力します。操作する前に確認してください。

```bash
agenteye incidents list --state firing                # 他: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # 担当者はオペレーターである必要があります
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # アラートに対して手動で開く
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### アナリティクスとアシスタント: `query` · `agent`

**`query`**: アナリティクスストアに対する保存済み SQL とアドホックランナー。保存済みクエリは**名前**で参照されます。SQL はサーバーサイドで検証されます（SELECT/WITH のみ、ステートメントタイムアウト、行数上限あり）。

```bash
agenteye query schema [TABLE]                         # アナリティクスビューのカラム構成
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # 保存済みクエリを実行し $1 に位置引数を渡す
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: 組み込みの **AI アシスタント**と対話します（ダッシュボードでチャットできるものと同じ読み取り専用アナリスト）。チャットは短い chat-id（プレフィックスで解決）で参照されます。

```bash
agenteye agent health                                 # AI アシスタントが設定済みで到達可能か確認
agenteye agent models                                 # --model に渡せるモデル一覧（デフォルトにマーク付き）
agenteye agent ask "which agents errored most in the last day?"    # チャットを開始し、短い id を出力
agenteye agent ask --chat <short-id> "and which tools did they call?"   # そのチャットを継続
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | 予期しないエラー（ダッシュボードが 5xx を返した場合など） |
| 2 | 使用エラー（無効な引数、不明なコマンド/フラグ、名前の衝突） |
| 3 | ダッシュボードに到達できない |
| 4 | 未ログインまたはセッション期限切れ。`agenteye login` を実行してください |
| 5 | 認証済みだが、必要な権限がありません（メッセージに権限名が示されます） |
| 6 | 要求されたリソースが見つかりません（不明なセッション ID やインシデント ID など） |

これらによって CLI は安全にスクリプト化できます。コーディングエージェントは `4` を受け取ったら再認証を促し、`5` を受け取ったら不足している権限を表示するといった分岐処理ができます。終了コードの処理パターンと JSON 出力の形状については、[エージェント向け CLI レシピ](/ja/agenteye/cli-recipes) を参照してください。
