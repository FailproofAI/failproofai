## データモデル

**イベント**
データの最小単位。1 つのイベントは、エージェントが実行した 1 つのステップ（`tool_use`、`model_request`、`hook_completed`、`error` など）を記録します。エージェントは [Python SDK](/ja/agenteye/python-sdk) を通じてイベントを送出し、**Events** ページにリアルタイムで表示されます。

**セッション**
`session_id` によって識別される、1 回のエージェント実行。セッションとは、その ID を共有するすべてのイベントの集合であり、**Sessions** ページで 1 行にまとめられ、詳細ページでは実行グラフとして描画されます。通常、セッションは `agent_start` で始まり `agent_end` で終了します。

**エージェント**
実行内で `agent_id` によって識別される、名前付きのアクター。1 回の実行に複数のエージェントが関与することがあります（たとえば、サマライザーのサブエージェントを起動するプランナーなど）。サブエージェントは `parent_id` を持ちます。これにより、Failproof AI Observability は実行グラフ上に各エージェントを専用のレーンとして描画できます。

**環境**
実行が発生した場所のラベル（`production`、`staging`、`dev`）。SDK を設定する際に一度だけ指定します。ほぼすべてのダッシュボードページで環境によるフィルタリングが可能です。

**コンテキストウィンドウ使用率**
1 回のレスポンスがモデルのコンテキストウィンドウ全体のうち何パーセントを消費したかを示す値。Failproof AI Observability は、認識しているモデルの `model_response` イベントにこの値を付与するため、プロンプトの増大や差し迫ったコンパクションをイベントストリームで直接確認できます。

## 品質

**評価（Evaluation）**
完了したセッションに対して、あなたが運用するスコアリングサービスが生成するクオリティスコア。評価はオプトイン形式です。評価器を接続するまでは、セッションは記録されますがスコアリングはされません。各評価には複数の名前付きスコア（例：`helpfulness`、`factuality`、`tool_efficiency`）を含めることができ、それぞれに短い根拠メモが付きます。[Evaluation suite](/ja/agenteye/evaluation-suite) を参照してください。

**スコアキー**
評価器が報告する 1 つの評価軸の名前（例：`helpfulness`）。アラートや監査は、特定のスコアキーを時系列で監視できます。

**評価器（Evaluator）**
あなたのスコアリングサービス。Failproof AI Observability は完了した実行のトランスクリプトを評価器に POST し、返されたスコアを保存します。デフォルトの評価器は提供されません。スコアリングロジックはあなた自身が実装します。

## 障害の発見と修正

**フック（Hook）**
エージェントフレームワークがステップの前後に実行するガードレールまたは副作用処理。コンテンツ安全チェック、PII の難読化、予算ガードなどが該当します。フックは `outcome`（allow、deny、modify）を持つ `hook_triggered` / `hook_completed` イベントを送出し、専用の観測ページで確認できます。

**アラートルール**
設定したしきい値をメトリクスが超えた際に発火するルール。対象となるメトリクスは、エラーレート、p95 レイテンシ、トークンコスト、評価器スコアなどです。ルールが発火すると、インシデントが作成され、指定したチャンネル（メール、Slack、Webhook、ダッシュボード内通知）に通知が送られます。[Alerts](/ja/agenteye/alerts) を参照してください。

**インシデント**
アラートルールが発火したときに作成されるオープンな問題。インシデントにはライフサイクル（確認、アサイン、解決）と、すべてのアクションを記録するアクティビティタイムラインがあります。手動で作成することも可能です。

**監査（Audit）**
ログをセッション横断的に分析し、まだルールを定義していない障害パターン（エラークラスター、低スコア、レイテンシの外れ値、ツール呼び出しのループ、完了しなかった実行など）を検出する定期調査（1 時間ごと〜週 1 回）。アラートが既知のメトリクスを監視するのに対し、監査は「次に何を調べるべきか」を教えてくれます。[Audits](/ja/agenteye/audits) を参照してください。

**ファインディング（Finding）**
監査の実行から得られる、優先度付きで証拠に裏付けられた結果の 1 つ。ファインディングはパターンに名前を付け、その根拠となる具体的なセッションへのリンクを持ち、トリアージライフサイクル（確認、解決、ミュート、却下）を備えています。Failproof AI Observability は実行をまたいでファインディングを重複排除するため、既知のパターンは新規追加されるのではなく更新されます。

**AI アシスタント**
ダッシュボード内のチャット機能。あなた自身のデータをもとに、エージェントに関する質問に自然な言葉で回答します。デフォルトでは読み取り専用であり、アシスタントが作成するもの（保存済みクエリやダッシュボードなど）は承認が必要で、削除操作は一切行えません。[AI assistant](/ja/agenteye/assistant) を参照してください。

## 運用について

**組織（テナント）**
独立したワークスペース。1 つの Failproof AI Observability インスタンスで複数の組織をホストでき、それぞれが独自のユーザー、キー、データを持ちます。すべてのダッシュボード URL は組織のスラッグ（`/<org-slug>/…`）でスコープされます。

**コレクター**
`agenteye-collector`。各エージェントマシンで動作する軽量デーモンで、SDK がディスクに書き込んだイベントをバッチ処理し、サーバーに送信します。

**API キー**
クライアントをサーバーに対して認証するためのスコープ付きトークン。キーには詳細なパーミッションが付与されます（たとえば、コレクター用の `events:add`、ダッシュボードキー用の読み取り専用スコープなど）。[API keys](/ja/agenteye/api-keys) を参照してください。

**サーバー**
イベントの取り込みと API サービス。イベントを受け取り、運用状態をデータベースに保存し、ダッシュボードと CLI を提供します。

**ダッシュボード**
Web UI。すべてのページは組織にスコープされており、サーバーの API を通じてデータを読み取ります。
