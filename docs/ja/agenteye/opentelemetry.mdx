OpenTelemetry を使用すると、標準の OTLP/HTTP プロトコルを通じて、エージェントのトレース・ログ・メトリクスを FailproofAI Cloud に送信できます。この機能はオプションです。既存の FailproofAI 連携は、有効化しなくても引き続き正常に動作します。

## キーの取得

OTLP の取り込みはすべての組織で常時有効になっており、特別な設定は不要です。エージェントレポートに使用するものと同じ `events:add` 権限を持つ Cloud API キーを使用してください。

ダッシュボードの **ホーム → 初回セットアップ** に **OpenTelemetry で接続** というカードがあります。**コレクターキーを作成** をクリックすると、`events:add` キーが作成され、エクスポーター変数とともに一度だけ表示され、接続状態も確認できます。また、**設定 → API キー** から **新しいキー** で **ログ送信のみ** を選択して作成することもできます。

## コーディングエージェントの接続

`failproofai config` でマシンを接続したあと、エージェントを選択します。

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

セットアップコマンドは Claude Code、Codex、Copilot に対応しており、状況に応じて Cloud または認証済みのローカルリレーを自動的に選択します。Copilot はローカルリレーを自動的に使用します。リレーを使用する前に、設定済みの FailproofAI デーモンを起動しておいてください。

FailproofAI がすでにエージェントのセッションのトランスクリプトを送信している場合、セットアップ時にそのエージェントを OTEL に切り替えるかどうか確認されます。デフォルトは「いいえ」です。承認するとそのエージェントのトランスクリプトのアップロードが停止しますが、ポリシーの適用や他のエージェントからのレポートには影響しません。

## アプリケーションの接続

アプリケーションの OpenTelemetry インストルメンテーションに以下の環境変数を設定してください。

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

エンドポイントは Cloud の OTLP ベース URL である `https://app.befailproof.ai/otel` です。エクスポーター側で `/v1/traces`、`/v1/logs`、または `/v1/metrics` が自動的に付加されます。`OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` のようなシグナルごとの変数はそのまま使用されるため、`https://app.befailproof.ai/otel/v1/logs` のようにフルパスで指定してください。

`<key>` は実際の API キーに置き換えてください。シェル履歴・画面録画・リポジトリへのコミットにシークレットが含まれないよう注意してください。設定済みのマシンでは、`failproofai otel env --service my-agent` を実行すると、既存のキーを含む設定ブロックが出力されます。この出力にはクレデンシャルが含まれます。

Cloud は protobuf または JSON 形式（gzip 圧縮リクエストを含む）のトレース・ログ・メトリクスの OTLP/HTTP エクスポートを受け付けます。OTLP/gRPC には対応していません。

メトリクスはエクスポーターの互換性のために受理されますが、保存・表示はされません。対応しているエージェントのトレースおよびコーディングエージェントのログはセッションとして扱われ、エージェントがエクスポートしないフィールドは存在しないものとして処理されます。

## プロンプトテキストのキャプチャ

<Warning>
テキストのキャプチャには、プロンプト・ツール引数・その他の機密コンテンツが含まれる場合があります。`failproofai otel enable` を実行するとキャプチャが有効になります。プロンプトおよびツール詳細のキャプチャを無効にするには `--no-content` を追加してください。
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

手動で設定したエージェントの場合は、そのエージェント自体のコンテンツキャプチャ設定を使用してください。

<Tabs>
  <Tab title="Claude Code">
    上記のアプリケーション設定ブロックと合わせて、エージェントの環境に以下の変数を追加してください。

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    プロンプトとツールの詳細をキャプチャしないようにするには、両方のコンテンツ変数を `0` に設定してください。
  </Tab>
  <Tab title="Codex">
    Codex のユーザー設定で、OTEL の設定を使用してください。

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex の会話内容はログに記録されます。内部ランタイムのトレースとメトリクスは無効のままにしてください。Codex は指定したエンドポイントをそのまま使用します。プロンプトを除外するには `log_user_prompt` を `false` に設定してください。セットアップコマンドは明示的な `false` の設定を保持します。
  </Tab>
  <Tab title="Gemini CLI">
    ローカルリレーを使用して Gemini のテレメトリ設定を行ってください。

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI は `failproofai otel enable` には対応していません。独自の認証済みコレクターを使用して手動で設定してください。プロンプトをキャプチャしない場合は `logPrompts` を `false` に設定してください。
  </Tab>
  <Tab title="Copilot in VS Code">
    以下の VS Code ユーザー設定を使用してください。

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    `failproofai otel enable copilot` を実行して認証済みリレーを有効化してください。コンテンツを除外するには `captureContent` を `false` に設定してください。
  </Tab>
</Tabs>

## セットアップの確認と取り消し

リレーは一時的なネットワーク障害やサーバー障害が発生してもテレメトリを保持し、復旧後に再試行します。ペイロードが大きすぎて保存できない場合など、`400` エラーが永続的に返される場合は、ペイロードを修正する必要があります。リレーは繰り返し送信する代わりに、拒否されたバッチを検査のために保持します。

`401` または `403` が返された場合は、同じ組織に対して `events:add` 権限を持つキーにクレデンシャルを置き換えてください。再接続しても、クレデンシャルの問題で拒否された保持済みの OTLP エクスポートは自動的に再送信されません。それらのバッチを回復する必要がある場合は、オペレーターに依頼してください。バッチは元の組織内で管理してください。

```bash
failproofai otel status
failproofai otel disable all
```

`status` コマンドは、FailproofAI が管理している設定と、他の場所で設定したテレメトリを区別して表示します。`disable` を実行すると、以前の管理設定とエージェントの以前のトランスクリプトアップロード設定が復元されます。
