OpenTelemetry を使うと、標準の OTLP/HTTP プロトコルを通じてエージェントのトレース、ログ、メトリクスを FailproofAI Cloud に送信できます。この機能はオプションです。既存の FailproofAI インテグレーションは、有効化しなくても引き続き動作します。

## キーを取得する

OTLP インジェストはすべての組織でデフォルトで有効になっており、特別な設定は不要です。エージェントレポートに使用するものと同じ `events:add` 権限を持つ Cloud API キーを使用してください。

ダッシュボードの **ホーム → 初回セットアップ** に **OpenTelemetry で接続** カードがあります。**コレクターキーを作成** をクリックすると `events:add` キーが作成され、エクスポーター変数とともに一度だけ表示され、接続ステータスも確認できます。また、**設定 → API キー** から **新しいキー** で **ログ送信のみ** を選択して作成することもできます。

## コーディングエージェントを接続する

`failproofai config` でマシンを接続したあと、エージェントを選択します。

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

セットアップコマンドは Claude Code、Codex、Copilot に対応しており、状況に応じて Cloud またはローカルの認証済みリレーを自動的に選択します。Copilot は自動的にローカルリレーを使用します。リレーを使用する前に、設定済みの FailproofAI デーモンを起動しておいてください。

FailproofAI がすでにエージェントのセッショントランスクリプトを送信している場合、セットアップ時にそのエージェントを OTEL に切り替えるかどうか確認されます。デフォルトは「いいえ」です。承諾するとそのエージェントのトランスクリプトアップロードが停止しますが、ポリシーの適用や他のエージェントからのレポートには影響しません。

## アプリケーションを接続する

アプリケーションの OpenTelemetry インストルメンテーションに以下の環境変数を設定してください。

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

エンドポイントは Cloud の OTLP ベース URL `https://app.befailproof.ai/otel` です。エクスポーター側が `/v1/traces`、`/v1/logs`、`/v1/metrics` を自動的に付加します。`OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` のようなシグナル別の変数はそのまま使用されるため、`https://app.befailproof.ai/otel/v1/logs` のようにフルパスで指定する必要があります。

`<key>` をご自身の API キーに置き換えてください。シェル履歴、画面録画、コミットされた設定ファイルにシークレットが含まれないよう注意してください。設定済みのマシンでは、`failproofai otel env --service my-agent` を実行すると既存のキーを含む変数ブロックが表示されます。その出力にはクレデンシャルが含まれます。

Cloud はトレース、ログ、メトリクスの OTLP/HTTP エクスポートを受け付けます。protobuf および JSON 形式（gzip 圧縮リクエストを含む）に対応しています。OTLP/gRPC には対応していません。

メトリクスはエクスポーター互換性のために受け付けられますが、保存・表示はされません。サポートされているエージェントトレースとコーディングエージェントログはセッションとして扱われ、エージェントがエクスポートしないフィールドは空欄になります。

## プロンプトテキストをキャプチャする

<Warning>
テキストキャプチャにはプロンプト、ツール引数、その他の機密コンテンツが含まれる場合があります。`failproofai otel enable` を実行するとこれが有効になります。プロンプトおよびツール詳細のキャプチャを無効にするには `--no-content` を追加してください。
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

手動で設定したエージェントの場合は、そのエージェント固有のコンテンツキャプチャ設定を使用してください。

<Tabs>
  <Tab title="Claude Code">
    上記のアプリケーション設定ブロックと合わせて、エージェントの環境に以下の変数を追加してください。

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    プロンプトとツール詳細のキャプチャを無効にするには、両方のコンテンツ変数を `0` に設定してください。
  </Tab>
  <Tab title="Codex">
    Codex のユーザー設定で、OTEL 設定を使用してください。

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex の会話コンテンツはログに記録されます。内部ランタイムのトレースとメトリクスは無効のままにしてください。Codex は指定したエンドポイントをそのまま使用します。プロンプトを除外するには `log_user_prompt` を `false` に設定してください。セットアップコマンドは明示的な `false` の設定を維持します。
  </Tab>
  <Tab title="Gemini CLI">
    ローカルリレーと合わせて Gemini のテレメトリ設定を使用してください。

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI は `failproofai otel enable` ではサポートされていません。独自の認証済みコレクターを使用して手動で設定してください。プロンプトをキャプチャしない場合は `logPrompts` を `false` に設定してください。
  </Tab>
  <Tab title="Copilot in VS Code">
    以下の VS Code ユーザー設定を使用してください。

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    `failproofai otel enable copilot` を実行して認証済みリレーを有効にしてください。コンテンツを除外するには `captureContent` を `false` に設定してください。
  </Tab>
</Tabs>

## 設定の確認と取り消し

リレーは一時的なネットワーク障害やサーバー障害の間もテレメトリを保持し、復旧後に再試行します。保存するには大きすぎるイベントを含む永続的な `400` エラーが返された場合は、ペイロードを修正する必要があります。リレーは繰り返し送信する代わりに、拒否されたバッチを検査のために保持します。

`401` または `403` が返された場合は、同じ組織に対して `events:add` 権限を持つキーにクレデンシャルを置き換えてください。再接続しても、クレデンシャルエラーで拒否された保持済みの OTLP エクスポートは自動的に再送されません。これらのバッチの復旧はオペレーターに依頼してください。バッチは元の組織に保持してください。

```bash
failproofai otel status
failproofai otel disable all
```

`status` コマンドは FailproofAI が管理している設定と、他の場所で設定したテレメトリを区別して表示します。`disable` を実行すると、以前の管理設定とエージェントの以前のトランスクリプトアップロード設定に戻ります。
