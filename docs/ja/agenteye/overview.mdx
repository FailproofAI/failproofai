Failproof AI Observability は、本番環境の AI エージェントを観測・評価・改善するためのセルフホスト型プラットフォームです。エージェントが行うすべての操作（ツール呼び出し、モデルリクエスト、フック、エラー）を記録し、各実行の品質をスコアリングし、気づいていなかった障害を検出して、すべて自社インフラ内で動作するダッシュボードに表示します。

AI エージェントを本番リリースしていて、実行がどこで失敗したのか毎回推測するのに疲れたなら、このページから始めてください。インストールの前に、Failproof AI Observability が提供するものと各機能の関係を説明します。

> **Failproof AI Observability は Failproof AI のエンタープライズ製品です。** 実際の動作をご覧になりたい場合は、デモをリクエストしてください: [nikita@befailproof.ai](mailto:nikita@befailproof.ai) までメールをお送りください。

## チームが活用する理由

- **エージェントが実際に何をしたかを把握できる。** すべての実行が読みやすい git スタイルの実行グラフになります。どのツールが並列で動いたか、どのサブエージェントが分岐したか、どこで停滞したか、何を消費したかが一目でわかります。
- **品質の低下を自動的に検出できる。** 小規模なスコアリングサービスを接続すると、Failproof AI Observability がすべての完了した実行をスコアリングするため、有用性の低下やハルシネーションの急増が自動的に表面化します。
- **ルールを書いていない障害も発見できる。** 定期監査がセッションをまたいでログからエラークラスター・レイテンシ外れ値・低スコア・停滞した実行を検出し、証拠付きの優先度付き調査結果として提示します。
- **重要なときに通知を受け取れる。** エラーレート・レイテンシ・コスト・評価スコアに対するしきい値ルールがトリガーされると、確認・割り当て・解決が可能なインシデントが作成されます。
- **自然な日本語で質問できる。** ダッシュボード内の AI アシスタントが「今週の本番環境での品質トレンドは？」といった質問に、自社データをもとに回答します。アシスタントが行う変更は承認が必要です。
- **データは自社で管理できる。** Failproof AI Observability はセルフホスト型です。イベント・プロンプト・分析データはすべて自社が管理するインフラに留まります。

## 提供される機能

Failproof AI Observability は 3 つの概念（**observe（観測）**、**analyze（分析）**、**admin（管理）**）を軸に構成されており、ダッシュボードの左サイドバーにも反映されています。

**Observe**（何が起きたかの生の記録）:

- **[イベントストリーム](/ja/agenteye/event-stream)**: すべての実行の各ステップのリアルタイムな記録（ツール呼び出し、モデル呼び出し、フック、エラー）。
- **[セッション](/ja/agenteye/sessions)**: それらのイベントを実行ごとに 1 行にまとめたもの。各実行はスコアリング可能で、git スタイルの実行グラフも付いています。
- **[パフォーマンスメトリクス](/ja/agenteye/telemetry)**: サーフェスごとのレイテンシヒートマップと、モデル・ツール・フックの p50/p95/p99 バイタル。テールスパイクと中央値の差が一目でわかります。
- **[エラートラッキング](/ja/agenteye/error-tracking)**: 発生したすべての問題を一元管理するトリアージ画面。アラートの発火からワンクリックでアクセスできます。

![Tools の observe ページ: 24 タイムビンにわたるレイテンシヒートマップ、パーセンタイルバンド、ツール分布バー](/agenteye/images/tools.png)

*各 observe サーフェスは、スパークラインと p50/p95/p99 バイタル、レイテンシヒートマップとパーセンタイルバンドを組み合わせて表示します。ここではツールの例を示しています。*

**Analyze**（活動を洞察に変える）:

- **[クエリ](/ja/agenteye/queries)** と **[ダッシュボード](/ja/agenteye/dashboards)**: イベントと評価データに対して保存された SQL クエリを、組織共有のダッシュボードにグラフ化します。
- **[評価](/ja/agenteye/evaluations)**: 自社の評価サービスが生成する品質スコア。スコアごとの理由付きで確認できます。
- **[監査](/ja/agenteye/audits)**: セッションをまたいで障害パターンを検出する定期調査。
- **[アラート](/ja/agenteye/alerts)** と **[インシデント](/ja/agenteye/incidents)**: 通知を送るしきい値ルールと、トリアージのためのインシデントワークフロー。

**Interfaces**（自分のやり方でデータにアクセス）:

- **[CLI](/ja/agenteye/cli-and-agents)**: ターミナルやスクリプトからデプロイ全体を操作でき、コーディングエージェントに自然言語で任せることもできます。
- **[AI アシスタント](/ja/agenteye/assistant)**: ダッシュボード内で、エージェントに関する質問を自然な言葉で行えます。
- **REST API**: ダッシュボードと CLI のすべての操作は、スコープ付き [API キー](/ja/agenteye/api-keys) を使って直接呼び出せる REST API に裏付けられています。イベントの取り込み、セッション・評価のクエリ、ダッシュボード・アラート・監査・ユーザー・キーの管理が可能で、Failproof AI Observability を自社ツールに組み込めます。

**Admin**（チームのための運用）:

- **[API キー](/ja/agenteye/api-keys)**: コレクター・ダッシュボード・アシスタント向けのスコープ付きトークン。
- **ユーザー**: パスワードレスのメールベース認証とアクセス許可リスト。
- **設定**: モデルのコンテキストウィンドウのオーバーライドを含む、組織ごとの設定。

## 仕組みの全体像

データはエージェントコードからダッシュボードへ一方向に流れます。エージェント（Python SDK 経由）がイベントを agenteye-collector に送信し、それがサーバーに転送され、サーバーがダッシュボードを提供します。スコアリングサービス（評価）と AI アシスタントサービス（ダッシュボード内チャット）の 2 つのオプションサービスで構成が完成します。

- **Python SDK**: エージェントに `agenteye.event.*` の呼び出しをいくつか追加するだけで、イベントがローカルにバッファリングされます。
- **agenteye-collector**: 各エージェントマシン上で動作する軽量デーモンで、イベントをバッチ処理してサーバーに転送します。
- **サーバー**: イベントを取り込み、自社データベースに運用状態を保持し、ダッシュボード・CLI・自社インテグレーションが使用する REST API を提供します。
- **ダッシュボード**: すべてを探索する場所。
- **オプションサービス**: スコアリングサービス（評価）と AI アシスタントサービス（ダッシュボード内チャット）。

ドキュメント全体で使用される用語（*event、session、evaluation、audit、finding、incident*）については、[コンセプト](/ja/agenteye/concepts) を参照してください。
