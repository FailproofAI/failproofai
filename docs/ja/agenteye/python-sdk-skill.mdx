コーディングエージェントに *「このエージェントに Failproof AI Observability を追加して」* と伝えるだけで、エージェントがループを読み取り、計装ポイントを判断し、コードを書き、イベントを検証してから完了とします。

**Python SDK スキル** (`agenteye-python-sdk`) は *Agent Skill* です。これはフォルダー形式の指示セットで、Claude Code や Codex などのコーディングエージェントがタスクに応じてオンデマンドで読み込みます。[Python SDK](/ja/agenteye/python-sdk) の使い方をエージェントに教えるものであり、ライブラリではなく、SDK の動作に一切変更を加えません。

## 計装は書くのは簡単、気づかぬうちに壊れるのも簡単

SDK は小さなものです。イベントメソッドは 13 個、すべてキーワード引数のみ。コーディングエージェントは [Python SDK](/ja/agenteye/python-sdk) リファレンスを読めば、1 分もかからずもっともらしい計装コードを生成できます。

問題は、この SDK は間違えても例外を投げないことです。間違った計装は正しい計装とまったく同じに見え、誰かがダッシュボードを開いて何も表示されないことに気づくまでわかりません。本当に時間を奪うミスはすべて「無音」です。

| ミス | 見え方 |
|---|---|
| `agent_start` がない | イベントはすべて届く。セッションはゼロ。 |
| 環境が設定されていない | すべて動いている、ただし `dev` 以下に記録される。 |
| `outcome="failure"` と指定 | 実行は成功に見える — カウントされるのは `failed`、`error`、`timeout`、`rejected` のみ。 |
| フィールド名のタイポ | そのまま受け入れられ、新しいフィールドとして保存される。 |
| スレッドプールからイベントを発行 | 無音でドロップされる。 |

これらはいずれも例外を投げません。テストにも引っかかりません。すべてスキルに記載されており、検出するためのチェックとともに契約として明示されています。

## スキルの実行ステップ

スキルは、丁寧なエンジニアが行うのと同じ 3 ステップを実行します。

1. **計画。** エージェントのループを読み取り、あなたにしか答えられない 2 つの質問をします。「1 回の実行とは何か（あなたの `session_id`）」「識別可能なアクターは誰か（あなたの `agent_id`）」です。コードを書く前に合意を取ります。後で変更すると履歴が分断され、トレンドが崩れるためです。
2. **実装。** アイデンティティを呼び出しサイトごとに渡すのではなく、実行ごとに 1 回だけバインドします。また、並行処理に安全な形式を選択します。これは重要な細部です。安易なショートカットを取ると、重複する 2 つの実行が 1 つのセッションに無音で混入します。
3. **検証。** エージェントを実行して生成されたイベントファイルを読み取り、`agent_start` が存在すること、環境が正しいこと、1 回の実行が 1 セッションを生成していることを確認します。

3 番目のステップこそ、みんなが省略しがちなものです。SDK はイベントをローカルファイルに書き込むため、サーバーも API キーもネットワークも不要で、ラップトップ上で完全な統合を証明できます。だからこそスキルはこのステップを必須としています。

## 他のスキルとの関係

3 つのスキル、明確な役割分担：

| スキル | 使うタイミング | 触れるもの |
|---|---|---|
| **Python SDK スキル**（このページ） | エージェントにテレメトリを *発行* させたいとき — 「オブザーバビリティを追加したい」「エージェントが表示されない」 | エージェントのリポジトリにコードを書く。読み取りはなし。 |
| **[Evaluator スキル](/ja/agenteye/evaluator-skill)** | 実行を *スコアリング* したいとき — 「何を計測すべきか」 | リポジトリにコードを書く。テレメトリを読む。 |
| **[CLI スキル](/ja/agenteye/cli-skill)** | 何が起きたかを *読み取りたい*、またはデプロイメントを操作したいとき | CLI をあなたの代わりに操作する（変更を含む） |

この順番で引き継がれます。このスキルでイベントを流し、Evaluator でスコアリングし、CLI で読み返す。エージェントがセッションを発行しない限り、評価するものも読み取るものもありません。ゼロから始めるなら、まずここから。

## 前提条件

1. **Python 3.10 以上** と計装したいエージェントのコードベース。
2. **SDK。** パブリックインデックスではなく、プライベートホイールとして顧客に配布されます — インストール方法はオンボーディングで説明されます。スキルはインストールパスを把握しており、見つからない場合は推測ではなく確認します。
3. **それ以外は不要。** ダッシュボードへのログイン、API キー、ネットワーク接続は必要ありません。スキルは SDK が書き込むイベントファイルで検証するため、オフラインで作業を完了・証明できます。

## 入手方法

スキルは公開の [`FailproofAI/skills`](https://github.com/FailproofAI/skills) コレクションにあります。

```bash
npx skills add FailproofAI/skills --skill agenteye-python-sdk -a claude-code
```

全プロジェクトにインストールする場合は `-g` を追加し、シンボリックリンクが使えない環境では `--copy` を使ってください。Codex の場合は `-a codex` を指定します。

## 手動でインストールする

Agent Skills は `SKILL.md` と参照ファイルを含むフォルダーです。インストーラーを使いたくない場合：

- **Claude Code**: `agenteye-python-sdk/` フォルダーを `~/.claude/skills/`（全プロジェクト対象）または `<your-repo>/.claude/skills/`（そのリポジトリのみ）にコピーします。Claude Code は自動的に検出します — `/skills` リストで確認するか、関連するタスクを尋ねてみてください。
- **Codex**: Codex も同じ `SKILL.md` を読み取ります。付属の `agents/openai.yaml` に `allow_implicit_invocation: true` が設定されているため、タスクが一致すれば自動選択されます。それ以外の場合は `$agenteye-python-sdk` として呼び出してください。

**計装したいコードが含まれるリポジトリで** エージェントを実行してください — スキルは提案の前にエージェントのループを読み取ります。

## セッションの例

```text
you   ▸ このエージェントに Failproof AI Observability を追加してください。

agent ▸ ループを確認しました — tools.py に 1 つのツールディスパッチャー、
        llm.py に 1 つの Anthropic ラッパーがあります。コードを書く前に
        2 つ確認させてください。

        「1 回の実行」とは何ですか？リクエストを並行処理しているので、
        ctx.request_id にある既存のリクエスト ID を使うと、ここのセッションと
        ログのリクエストが同じ文字列で対応できます。

        アクターは誰ですか？プランナーのパスとリサーチャーのパスがあります。
        それぞれ別にラベル付けしますか、それとも 1 つのエージェントとして
        扱いますか？

you   ▸ リクエスト ID で合っています。同一エージェントで、"assistant" と呼んでください。

agent ▸ 完了しました。ディスパッチャーと LLM クライアントをラップし、
        agent_start と agent_end が handle_request（エラーパスも含む）を
        括るようにしました。アイデンティティにはコンテキストローカルを使用しました
        — ディスパッチャーがスレッドプールでツールを実行しているため、
        単純なアプローチだと並行実行が無音で 1 つのセッションに混入していました。

        実際の実行で検証済み: 4 ファイルに 11 イベント —
        agent_start、model_request/response、tool_use/tool_result x3、
        agent_end (outcome=success)。environment=production、リクエストごとに
        1 セッション、所要時間のペアも確認済み。

        1 点、行っていないこと: batch.py のワーカープールが直接 executor に
        サブミットしているため、そこからのイベントはドロップされます。
        そちらも修正しますか？
```

注目すべきパターン: 提案の前にコードを読み、あなたにしか答えられない質問だけをし、既存の ID を再利用し、スレッドプールを確認したうえで並行安全な形式を選び、成功を宣言するのではなく **実際のイベントを読んで検証**し、そして無音で失敗するとわかっている箇所をフラグ立てしました。

## 使えるプロンプトの例

- *「エージェントがダッシュボードに表示されないのはなぜ？」* → 順を追って確認: イベントが書き込まれているか、`agent_start` があるか、環境は正しいか、コレクターが同じ場所を読んでいるか。
- *「すべてが dev 以下に入っている。」* → 環境が設定されていないか、後続の呼び出しでリセットされています。
- *「トークンのトラッキングを追加したい。」* → LLM ラッパーを見つけ、モデル、停止理由、使用量を記録します。
- *「サブエージェントも計装したい。」* → 1 セッション、個別のエージェントラベル、親の下にネスト。
- *「計装のテストを書きたい。」* → SDK を一時ディレクトリに向けて、書き込まれたイベントをアサートします。

## 注意事項

**検証させてください。** このスキルの価値を生むのは最後のステップです — エージェントを実行してイベントを読み返すこと。計装を書いて止まるエージェントは、簡単な半分しかやっていません。無音で失敗するのはもう一方の半分です。

**コードの前に名前を決めてください。** `session_id` と `agent_id` は、すべての画面がグループ化の軸に使います。後でリネームすると履歴が分断されます。古い実行は古いラベルのままで、トレンドが崩れます。スキルが尋ねるので、少し考えて答える価値があります。

**エージェントがパブリックインデックスからの SDK インストールを提案したら、スキルが読み込まれていません。** SDK はプライベート配布です。そのような提案は、コーディングエージェントがスキルに従わず推測していることを示す確かなサインです — そこで止め、スキルがインストールされているか確認してください。

それ以外の影響範囲は小さいものです。作業ディレクトリにコードを書き、指定した場所にイベントファイルを書き込みます。デプロイメントから何かを読み取ることも、変更を加えることもありません。
