アラートは測定可能な条件を監視し、その条件がトリガーされるとインシデントを作成します。ポリシーでブロックできるかどうかに関わらず、障害発生時に迅速な対応が必要な場合に使用してください。

## アラートの作成とテスト

<Tabs>
  <Tab title="ダッシュボード">
    1. **Analyze → Alerts** に移動し、**new alert** を選択します。代表的なエラーのベルアイコンからも開始できます。
    2. 名前、重大度、トリガーの種類、条件、評価間隔、違反回数、ウィンドウ、チャンネルを入力します。
    3. アラートを保存し、詳細ページを開いて **test** を実行します。
    4. **Analyze → Issues** に移動して、アラートによって作成されたインシデントの確認、担当者の割り当て、コメント、購読、解決を行います。

    フォームの前半では、アラートの識別情報とトリガーとなるシグナルを設定します。

    ![新規アラートフォームの前半部分。名前、説明、有効状態、トリガータイプを設定します。](/images/dashboard/alert-new-trigger.png)

    フォームの後半では、条件の持続時間、評価頻度、通知の送信先を設定します。

    ![新規アラートフォームの後半部分。違反ロジック、スケジュール、重大度、配信チャンネル、作成アクションを設定します。](/images/dashboard/alert-new-routing.png)

    保存後、アラート一覧でルールが有効になっていること、およびトリガー、ウィンドウ、重大度、チャンネルが意図した設定と一致していることを確認してください。

    ![アラートページ。アラートルールとそのトリガー、評価ウィンドウ、チャンネル、重大度が表示されています。](/images/dashboard/alerts.png)

    本番環境での対応に使用する前に、アラートをテストしてください。
  </Tab>
  <Tab title="CLI">
    ```bash
    fp alerts create high-errors \
      --trigger-kind metric_threshold \
      --severity warning \
      --trigger-spec '{"metric":"error_count","op":">","value":50,"window_secs":900}'

    fp alerts show high-errors
    fp alerts test high-errors
    fp alerts update high-errors --severity critical --yes
    ```

    `fp alerts list` でルールを確認し、`fp alerts delete <name>` で削除できます。

    完全なアラートコマンドセットについては、[`fp alerts` リファレンス](/ja/reference/cloud-cli#alerts)を参照してください。
  </Tab>
</Tabs>

アラート条件は、エラー、評価スコア、評価の組み合わせ、またはカスタム SQL に基づいて設定できます。受信者を追加し、ルールをテストして、作成されたインシデントを開いて確認、担当者割り当て、コメント、購読、解決を行ってください。

## 効果的なアラート設計

- 条件と影響を受けるワークフローを明確に命名する。
- 環境を明示的にスコープする。
- 無害な単発イベントに反応しないよう、ウィンドウと閾値を設定する。
- 担当者をセッションに誘導するリンクまたはクエリを含める。
- ルールを有効にする前にオーナーを割り当てる。

<Tip>
  監査の指摘事項を解決した後、同じ障害がポリシーのカバー範囲外で再発する可能性がある場合は、アラートを追加してください。
</Tip>
