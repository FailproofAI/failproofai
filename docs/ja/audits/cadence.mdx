---
title: "監査の実行頻度"
description: "定期監査の実行タイミングとレビュー対象データ量を設定します。"
icon: "calendar-clock"
---

エージェント、プロンプト、ツール、モデルの変更によって再発する可能性のある障害モードに対しては、定期監査を活用してください。

## スケジュールの変更

<Tabs>
  <Tab title="ダッシュボード">
    1. **Analyze → Audits** に移動し、対象の監査を開きます。
    2. 設定を開き、有効/無効の状態、実行間隔、UTC アンカー、ウィンドウモード、またはルックバック期間を変更します。
    3. 監査を保存し、監査カードで次回実行時刻を確認します。
    4. スコープまたはコンテキストを大幅に変更した後は、**run now** を一度実行してください。

    ![頻度、スイープウィンドウ、スコープ、分析設定、コンテキスト、通知チャンネルを表示した監査エディター。](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    スケジュールの制限、ウィンドウの動作、およびすべての監査コマンドについては、[`fp audits` リファレンス](/ja/reference/cloud-cli#audits)を参照してください。
  </Tab>
</Tabs>

リスクの深刻度とコストに応じて、実行頻度を選択してください。

| リスクのパターン | 推奨する実行頻度 |
| --- | --- |
| 本番環境での高影響アクション | 毎日 |
| ワークフローまたはモデルの回帰 | 毎週 |
| ガバナンスまたはアクセスレビュー | 毎月 |
| 一度限りのリリース調査 | 一回のみ実行 |

ルックバックウィンドウは実行頻度に合わせて設定し、実行間にデータの抜け漏れが生じたり、不必要に大量のデータを繰り返し検査したりしないようにしてください。監査の目的やコンテキストを変更した場合は、次回スケジュール実行の結果を参照する前に、手動で一度実行してください。

<Note>
  ローカルのスケジュール監査はマシン上で設定され、ローカルのエージェント履歴をスキャンします。クラウド監査のスケジュールはクラウドセッションで動作します。両者の結果と管理責任は別々に扱ってください。
</Note>
