---
title: "監査のスケジュール"
description: "定期監査の実行タイミングとレビュー対象データ量を設定します。"
icon: "calendar-clock"
---

エージェント、プロンプト、ツール、モデルが変化することで再発する可能性のある障害モードには、定期監査を活用してください。

## スケジュールの変更

<Tabs>
  <Tab title="ダッシュボード">
    1. **Analyze → Audits** に移動し、対象の監査を開きます。
    2. 設定を開き、有効/無効の状態、実行間隔、UTC基準時刻、ウィンドウモード、またはルックバック期間を変更します。
    3. 監査を保存し、監査カードで次回の実行時刻を確認します。
    4. スコープやコンテキストに大きな変更を加えた後は、**今すぐ実行**を一度使用してください。

    ![監査エディターでケイデンス、スイープウィンドウ、スコープ、分析設定、コンテキスト、通知チャンネルが表示されている画面。](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    スケジュールの範囲、ウィンドウの動作、すべての監査コマンドについては、[`fp audits` リファレンス](/ja/reference/cloud-cli#audits)を参照してください。
  </Tab>
</Tabs>

リスクの重大度とコストに応じて、以下を参考にケイデンスを選択してください。

| リスクパターン | 推奨ケイデンス |
| --- | --- |
| 影響度の高い本番環境の操作 | 毎日 |
| ワークフローまたはモデルの回帰 | 毎週 |
| ガバナンスまたはアクセスレビュー | 毎月 |
| 一回限りのリリース調査 | 一度だけ実行 |

実行間にギャップが生じたり、不必要に大きなデータ範囲を繰り返し検査したりしないよう、ルックバックウィンドウをケイデンスに合わせて設定してください。監査の目標やコンテキストを変更した後は、次回のスケジュール実行結果に依存する前に、一度手動で実行してください。

<Note>
  ローカルのスケジュール監査はマシン上で設定され、ローカルのエージェント履歴をスキャンします。クラウドの監査スケジュールはクラウドセッションを対象に動作します。それぞれの結果と管理責任は別々に扱ってください。
</Note>
