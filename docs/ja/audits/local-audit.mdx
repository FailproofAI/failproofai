Failproof AI Cloud にマシンを接続する前に、ローカル監査を使ってすぐにプライベートなレビューを行えます。マシン上にすでに保存されているエージェント履歴をスキャンし、組み込みポリシーを通じてツールのアクティビティを再現して、ローカルの結果ダッシュボードを開きます。

## インタラクティブ監査の実行

<Tabs>
  <Tab title="ダッシュボード">
    ローカル監査は、現在のマシン上の履歴を検出する必要があるため、CLI から開始します。`failproofai audit` を実行すると、スキャン後に Failproof AI がバンドルされたダッシュボードを起動し、**http://localhost:8020/audit** を開きます。

    監査ビューでは、セッション数、ツール呼び出し数、プロジェクト数、ポリシーヒット数を確認できます。頻度の高い検出結果から始め、対象のプロジェクトとエージェント履歴を調査してから、強制適用を有効にしてください。

    <Info>ローカル監査ダッシュボードは、Failproof AI Cloud の **Analyze → Audits** とは別のものです。ローカル監査はマシン上に保持され、アカウントもネットワーク接続も不要です。</Info>
  </Tab>
  <Tab title="CLI">
    ```bash
    npm install -g failproofai
    failproofai audit
    ```

    このコマンドは、検出されたすべての対応履歴に対して完全なスキャンを実行します。現在のコマンドは `--since`、`--cli`、`--project`、`--port`、`--no-open` などのフィルターには対応していません。

    ローカルダッシュボードを使用している間はプロセスを実行したままにしてください。終了したら <kbd>Ctrl</kbd>+<kbd>C</kbd> を押します。
  </Tab>
</Tabs>

現在の監査アダプターは、Claude Code、Codex、GitHub Copilot CLI、Cursor、OpenCode、Pi、Hermes、OpenClaw、Factory、Devin、Antigravity、Goose の履歴を読み取ることができます。スキャンされるのはローカルで利用可能な履歴のみです。

## 定期的なローカル監査のスケジュール設定

<Tabs>
  <Tab title="ダッシュボード">
    ローカルダッシュボードの **Settings** を開き、スケジュール監査を有効にして、間隔を選択し、検出結果を受け取るメールアドレスを設定します。ダッシュボードと CLI は同じマシン設定を更新します。
  </Tab>
  <Tab title="CLI">
    週次監査を有効にして、指定したアドレスに検出結果を送信する:

    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    間隔は 1〜90 日を受け付け、省略した場合のデフォルトは 7 日です。初回セットアップ時は必要に応じてサインインが行われます。`--email` はプロンプトなしでレポート送信先のアドレスを指定します。

    ローカル監査履歴を削除せずにスケジュールを停止する:

    ```bash
    failproofai audit --no-schedule
    ```
  </Tab>
</Tabs>

デーモンはバックグラウンドでスケジュールスキャンを実行し、ローカルダッシュボードが使用するキャッシュ結果を更新し、設定済みのレポートをメール送信します。インタラクティブなスキャンをすぐに実行したい場合は `failproofai audit` を使用してください。

## ローカルの証拠からクラウド運用への移行

ローカル監査は迅速なベースラインとして機能します。共有トレース、定期的な対象監査、検出結果と問題管理、アラート、組織全体のポリシー展開、またはフリートの健全性が必要になったら、マシンを Failproof AI Cloud に接続してください。

    ローカルで検証し、慎重に公開して、まず範囲の狭いマシングループにデプロイします。
  </Card>
</CardGroup>

<Warning>
  監査の出力はレビューのための証拠であり、フラグが立てられたすべてのアクションが安全でないことの証明ではありません。検出結果をブロッキング強制に変える前に、必ずコンテキストを確認してください。
</Warning>
