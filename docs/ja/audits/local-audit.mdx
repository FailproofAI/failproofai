ローカル監査は、このマシン上にすでに存在するエージェント履歴を読み取り、結果を `http://localhost:8020/audit` で開きます。アカウントは不要です。

```bash
failproofai audit
```

スキャンは、検出されたすべてのサポート対象ハーネスの履歴を対象とします。このバージョンに組み込まれた39のポリシーカタログを再実行します。インストール済みのパックやカスタムポリシーは含まれません。

## 結果の見方

最も頻度の高い検出結果から始め、強制適用を有効にする前に対象セッションを確認してください。

三つの制限事項があります：

- 監査はツールイベントを再構築しますが、`Stop` は対象外のため、`require-*-before-stop` ポリシーは表示されません。
- 「Audit-only」の8つのチェックは、完全に一致するポリシーを持たない非効率なパターンを特定します。
- `warn-repeated-tool-calls` は、再実行するとトランスクリプト側の状態が変更されるためスキップされます。

強制適用可能な検出結果については、結果に表示されるポリシーコマンドを使用してください。強制適用に依存する前に、[ハーネスの強制適用サポート](/ja/reference/harnesses#enforcement-capability)を確認してください。

キャッシュされた結果は `~/.failproofai/audit/dashboard.json` に保存され、7日後に期限切れになります。

## スキャンのスケジュール設定

```bash
failproofai audit --schedule 7
failproofai audit --status
failproofai audit --no-schedule
```

間隔は1〜90日で指定でき、デフォルトは7日です。初回のスケジュール設定にはインタラクティブなサインインが必要です。バックグラウンドサービスが実行中である必要があります。

### マシン外に送信される情報

インタラクティブな監査では、検出結果は送信されません。匿名のCLIテレメトリはデフォルトで有効になっています。無効にするには `FAILPROOFAI_TELEMETRY_DISABLED=1` を使用してください。

スケジュール設定をオプトインすると、スケジュールされたスキャンごとにマシンID、ラベル、プラットフォーム、スキャン期間が送信されます。有害なパターンが検出された場合は、カウント、タイムスタンプ、および最大3件の難読化されたサンプルを含む限定的なダイジェストも送信されます。問題のないスキャンでは、検出結果もメールも送信されません。

<Warning>
  監査結果はレビューのための根拠であり、フラグが立てられたすべてのアクションが安全でないことの証明ではありません。検出結果をブロッキング強制適用に変える前に、必ずセッションを確認してください。
</Warning>
