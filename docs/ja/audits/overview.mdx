監査は、多数のエージェント実行をある目標に照らして検証し、根拠に基づいた調査結果を返します。

## ローカル監査とクラウド監査

| | ローカル監査 | クラウド監査 |
| --- | --- | --- |
| コマンド | `failproofai audit` | `fp audits` |
| 参照先 | このマシン上のエージェント履歴 | クラウド組織内のセッション |
| 出力先 | `localhost:8020/audit` のローカル結果 | 共有された調査結果、Issue、アラート |
| 必要条件 | アカウント不要 | クラウド接続と API キー |

単一マシンの素早い確認にはローカル監査を使用してください。チームが複数のエージェントやマシンにまたがって定期的な監査を必要とする場合はクラウドを使用してください。

## 監査で答えられる質問

- エージェントはどこでエスカレーションせずに停止しているか？
- どのツール障害が非効率な再試行につながっているか？
- エージェントは意図したワークフロー外のデータにアクセスしているか？
- モデル、プロンプト、またはツールの更新後に何が変化したか？

## クラウド監査を開く

**Analyze → Audits** に移動するか、以下を使用してください：

```bash
fp audits list
fp audits show <audit-name>
fp audits findings --status open --limit 20
```

監査コマンドは監査名またはフル ID を使用します。調査結果はそれぞれ固有の ID で参照されます。

## 調査結果から予防措置へ

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert
```

調査結果は証拠を指し示します。Issue は対応方針を管理します。ポリシーは既知のアクションパターンを防止し、アラートは再発を監視します。

すべての調査結果がポリシーになるべきとは限りません。`policy` の調査結果は実施可能なルールを記述します。`failure` や `improvement` の場合は、代わりにワークフロー、プロンプト、モデル、またはツールの変更が必要になることがあります。
