監査は、選択したセッション群に対して指定された障害目標を検索します。トレースのエビデンス、評価結果、ポリシーヒット、参照コンテキストを組み合わせて、実際に対処できる調査結果を生成します。

スケジュール実行からエビデンスに裏付けられた障害の特定・修正まで、監査の流れをご確認ください。

## 監査を開く

<Tabs>
  <Tab title="ダッシュボード">
    **Analyze → Audits** に移動します。ページにはスケジュール状態、未解決の調査結果、最終実行日時、次回実行日時、実行間隔、ブリーフや参照ページの有無が表示されます。カードを選択すると設定と実行履歴を確認でき、**new audit** を選択すると新規作成できます。

    ![スケジュール、感度、実行状態が表示された定期監査の一覧ページ。](/images/dashboard/audits.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

以下のようなポピュレーションレベルの問いに答える必要がある場合に監査を使用してください。

- エージェントはどこでエスカレーションせずにタスクを中断しているか？
- どのツール障害が非効率なリトライにつながっているか？
- エージェントは意図したワークフロー外のデータにアクセスしていないか？
- モデル、プロンプト、またはツールのリリース後に何が変わったか？

## 監査レスポンスフロー

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert for recurrence
```

調査結果には障害モードの名称とエビデンスへの参照が含まれている必要があります。Issue が修復作業を担います。Policy は既知のアクションパターンを防止し、Alert は防止が不可能または監視が必要な場合に再発を検知します。
