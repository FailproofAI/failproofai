---
title: "監査レシピ"
description: "一般的なエージェント障害調査の出発点となるゴール集。"
icon: "book-open-check"
---

これらを出発点として使用し、エージェント、環境、期待されるワークフローを追加してください。

<Tabs>
  <Tab title="ダッシュボード">
    **分析 → 監査 → 新しい監査** に移動し、レシピを説明または概要にコピーしてから、関連する環境、エージェント、遡及期間、および参照 URL を追加します。監査を作成し、スケジュールを設定する前に最初の実行を確認してください。

    新しい監査フォームは、スコープ、コンテキスト、スケジュール、通知を追加することで、レシピを実行可能な障害チェックに変換します。

    ![フォーカスされたゴール、スケジュール、エージェントと環境のスコープ、コンテキスト、通知チャンネルが設定された新しい監査フォーム。](/images/dashboard/audit-new.png)

    作成後、定期的な実行に頼る前に、監査が期待されるステータスとスケジュールでリストに表示されることを確認してください。

    ![作成後にワークフロー固有の監査レシピが表示される監査ページ。](/images/dashboard/audits.png)

    最初の実行を開いて、その結果が意図した障害モードよりも広すぎる、または狭すぎる場合はレシピを改善してください。
  </Tab>
  <Tab title="CLI">
    レシピをテキストファイルとして保存し、作成時に添付します：

    ```bash
    fp audits create retry-loop-review \
      --scope '{"environments":["production"]}' \
      --text-file ./retry-loop-audit.txt \
      --schedule-interval-secs 86400
    ```
  </Tab>
</Tabs>

<AccordionGroup>
  <Accordion title="繰り返しのリトライループ">
    エージェントが入力を変更せず、代替ツールを選択せず、人間にエスカレーションもせずに、同じ失敗したツール呼び出しを繰り返すセッションを見つけます。
  </Accordion>
  <Accordion title="不適切なツールの使用">
    選択されたツールが指定されたタスクと一致しない、またはツールの入力がワークフローに必要な事前条件に違反しているセッションを見つけます。
  </Accordion>
  <Accordion title="安全でないデータアクセス">
    このエージェントに承認されたパスとサービス以外で機密データの読み取り、書き込み、または送信を行うセッションを見つけます。
  </Accordion>
  <Accordion title="タスクの放棄">
    要求された結果、明確なエラー、または人間への明示的な引き継ぎなしに終了するセッションを見つけます。
  </Accordion>
  <Accordion title="コストまたはレイテンシの回帰">
    モデル、ツール、または総実行時間が期待されるバジェットを超えるセッションを見つけ、原因となるイベントパターンを特定します。
  </Accordion>
  <Accordion title="人間へのエスカレーション漏れ">
    信頼度、繰り返しの失敗、またはポリシーのガイダンスにより人間の判断が必要であったにもかかわらず、エージェントが自律的に処理を続けたセッションを見つけます。
  </Accordion>
</AccordionGroup>
