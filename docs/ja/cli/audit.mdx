<Note>
  **ベータ機能。** 監査機能は初期フィードバックを収集しながらベータとして提供されています。
  ディテクターのカタログとレポート形式は、次の安定版リリース前に変更される可能性があります。
  問題があればIssueを作成してください。
</Note>

監査機能は過去のエージェントCLIのトランスクリプトをfailproofaiのポリシーエンジンで再実行し、
**`/audit` ダッシュボードページ**に共有可能なビジュアルレポートを生成します。
エージェントのアーキタイプ、0〜100のスコア、そしてどのポリシーが何を検出したかを確認できます。

## 実行方法

3つの方法があります。どれも同じ `/audit` レポートに到達します。

<CodeGroup>

```bash npx (インストール不要)
npx -y failproofai audit
```

```bash failproofai audit
failproofai audit
```

```bash failproofai (ダッシュボード)
failproofai
```

</CodeGroup>

  監査は**完全オフライン**で動作します。アカウントもネットワークも不要です。
  ダッシュボードは `Ctrl+C` で停止するまで稼働し続けます。
</Tip>

ダッシュボードはこのマシン上の過去のエージェントCLIトランスクリプト（Claude Code、Codex、Copilot、Cursor、OpenCode、Pi）をスキャンし、failproofaiが防ぐように設計された操作（環境変数のチェック、フォースプッシュ、冗長な `cd <cwd>` プレフィックス、スリープポーリングループ、編集直後のファイルの再読み込みなど）をエージェントが行った頻度をレポートします。

各トランスクリプトについて、すべてのツール使用イベントが39のビルトインポリシー**および**ランタイムポリシーではまだカバーされていないパターンを検出する8つの監査専用ディテクターを通じて再実行されます。カウントはすべてのセッションにわたってポリシー／ディテクターごとに集計されます。

## レポートの内容

`/audit` ページは1画面の共有可能な**ポスター**と、その下に4つのセクションで構成されています。

1. **ポスター** — エージェントのプロフィールを一目で確認できます。**アーキタイプ**（8種類のうちの1つ — `optimist`、`cowboy`、`explorer`、`goldfish`、`paranoid architect`、`precision builder`、`hammer`、`ghost`）、ペルソナキーワード、そのアーキタイプの希少性、およびティアバンド付きの**0〜100スコア**（`S` から `bottom tier` まで）が表示されます。XやLinkedInへの投稿やPNGダウンロードに対応しています。
2. **`// strengths`** — エージェントがすでに得意としていることをスキャンの実数で表示します（例：クリーンなツールコール率、`0` 回のmainへのプッシュ試行）。関連するポリシーに問題がない場合のみ表示されます。
3. **`// quirks`** — 見逃されたもの：failproofaiが検出できた動作のランク付けテーブル。*いつ*最後に発生したか、*何が漏れたか*（ブロックするビルトインポリシーも含む）、*深刻度*、*発生頻度*（`new` / `recurring` / `N× seen`）が表示されます。
4. **`// how to improve`** — 推奨される修正リスト：コピー＆ペーストできる `failproofai policy add <slug>` を含む各ポリシーの1行と、すべての推奨事項を一度に有効にして**予測スコア**を表示する**一括インストール**ボタンが表示されます。
5. **`// come back better`** — 習慣を作る：再監査の**リマインダー**（`3d` / `7d` / `14d` / `30d`）を設定するか、今すぐ再監査し、**友人を招待**して自身の監査を実行してもらいます（failproof.aiから送信され、あなたにCcされます）。リマインダーと招待にはサインインが必要です。

## スケジュール監査

**failproofaidデーモン**（[`failproofai config`](/ja/cli/install-policies) 参照）を実行している場合、
スケジュールに従って監査を再実行し、バックグラウンドで `/audit` レポートを更新できます。
この機能は**デフォルトでオフ**です。スキャンはこのマシン上のすべてのエージェントセッション
トランスクリプトの*内容*を読み取るためです。明示的に有効にしない限り、タイマーによるスキャンは行われません。

`~/.failproofai/config.toml` で有効にします。

```toml
[audit]
auto = true
interval_days = 7
```

| キー | 説明 |
|---|---|
| `auto` | `true` でスケジュールスキャンが有効になります。それ以外（未設定、`false`、`"yes"` など）はオフです。 |
| `interval_days` | スキャン間隔の日数。1〜90の範囲に制限されます。`0`、負の値、数値以外の場合は `7` にフォールバックします。 |

- スケジュールは**実時間（ウォールクロック）**ベースのため、サスペンドや再起動を経ても維持されます。スリープ中に期限を過ぎたノートパソコンは、起動後に**1回だけ**実行されます。積み残しは発生しません。
- 各実行は別個の低優先度（`nice 19`）プロセスです。ツールコールへの応答を維持するために、デーモンのフックパスは使用されません。
- `failproofai audit` またはダッシュボードの再実行がすでに進行中の場合、スキャンはスキップされます。失敗として扱われるのではなく、しばらく後に再試行されます。
- 進捗は `~/.failproofai/state/audit-schedule.json`（最終実行日時、次回予定日時）に記録されます。このファイルはデーモンが管理しています。スケジュールの変更は `config.toml` で行ってください。

<Note>
古いバージョンのfailproofaiでセットアップされたマシンでこれを有効にする場合は、
`failproofai config` を一度実行してください。デーモンのサービス定義がCLIを起動するために
必要なエントリを1つ追加する必要があり、その更新はこのコマンドの一部として行われます。
</Note>

## 監査専用ディテクター

これらはリアルタイムでは（まだ）適用されていない「問題のある動作」パターンを検出します。監査中のみ実行され、ライブのツールコールをブロックすることはありません。

| ディテクター | カウント対象 |
|---|---|
| `redundant-cd-cwd` | コマンドがすでに `cwd` で実行されているにもかかわらず、`cd <cwd> && …` で始まるBashコマンド。 |
| `prefer-edit-over-read-cat` | 単一のソースファイルに対する `cat`/`head`/`tail`/`less`/`more` の使用。`Read` ツールを使用してください。 |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` によるインプレース編集。`Edit` ツールを使用してください。 |
| `prefer-write-over-heredoc` | ヒアドキュメント / 複数行の `echo > file` によるファイル書き込み。`Write` ツールを使用してください。 |
| `sleep-polling-loop` | 長い `sleep N`（30秒以上）または `while …; sleep …; done` のポーリングループ。 |
| `find-from-root` | `find /`、`find /home`、`find /usr` など。`cwd` を起点にしてください。 |
| `git-commit-no-verify` | フックをスキップする `git commit … --no-verify` / `-n`。 |
| `reread-after-edit` | 同じセッション内で `Edit`/`Write` した直後のファイルへの `Read`。 |

## キャッシュ

- **トランスクリプトごとのキャッシュ** `~/.failproofai/cache/audit/<sha1>.json`：`(mtime, size, engineVersion, detectorVersion)` をキーとし、トランスクリプトやポリシー／ディテクターのコードが変更された際に自動的に無効化されます。各エントリには `cachedAt` タイムスタンプが**TTLメタデータ**として保存されています（キャッシュキーには含まれません）。**7日**を超えた古いエントリは読み取り時に拒否されるため、長期間の結果がディテクターの意図の変化を超えて残ることはありません。
- **全体の結果キャッシュ** `~/.failproofai/audit-dashboard.json`（モード0600）：ダッシュボードを再実行なしに即座に描画できます。こちらも**7日のTTL**を超えた場合は読み取り時に拒否されます。その場合、`/audit` は空の状態にフォールバックし、新しい実行を促します。レポート下部の `[ re-audit now ]` をクリックして更新してください。再監査は `noCache: true` を送信するため、トランスクリプトごとのキャッシュをバイパスして、キャッシュされた結果ではなくすべてのトランスクリプトを再スキャンします。実行はページ上部のスティッキーバーで進捗をストリーミング表示し、成功時には結果をその場で更新します（ページリロードなし。再監査が失敗した場合は前のレポートが保持されます）。

## 注意事項

- **変更なし。** 監査は読み取り専用モードで再実行されます。`warn-repeated-tool-calls` はスキップされます。これは、そのポリシーのセッションごとのサイドカーが変更される可能性があるためです。
- **ワークフローポリシーのスキップ。** `require-*-before-stop` ポリシーは `Stop` イベントと `execSync` でライブのgit状態に対してのみ発火します。「2025年に何が起きていたか」という意味のある解釈ができないため、監査のカウントには含まれません。
- **カスタムポリシーのスキップ。** ユーザーが追加したカスタムフックは再実行されません（元のセッション以降に変更されている可能性があります）。
