  次の安定版リリースまでに、検出器のカタログやレポート形式が変更される可能性があります。

</Note>

監査機能は、過去のエージェントCLIトランスクリプトをfailproofaiのポリシーエンジンで再生し、
**`/audit` ダッシュボードページ**に共有可能なビジュアルレポートを表示します。
エージェントのアーキタイプ、0〜100のスコア、そして各ポリシーが何を検出したかを確認できます。

## 実行方法

3つの方法があります — いずれも同じ `/audit` レポートに到達します。

<CodeGroup>

```bash npx (no install)
npx -y failproofai audit
```

```bash failproofai audit
failproofai audit
```

```bash failproofai (dashboard)
failproofai
```

</CodeGroup>

<Tip>
  使い方を確認するには `failproofai audit -h`（または `--help`）を実行してください。監査は**完全にオフライン**で動作します — アカウントやネットワーク接続は不要です。ダッシュボードは `Ctrl+C` で停止するまで起動し続けます。
</Tip>

ダッシュボードはこのマシン上の過去のエージェントCLIトランスクリプト（Claude Code、Codex、Copilot、Cursor、OpenCode、Pi）をスキャンし、failproofaiが防ぐように設計した操作 — 環境変数チェック、フォースプッシュ、冗長な `cd <cwd>` プレフィックス、スリープポーリングループ、編集直後のファイルの再読み込みなど — をエージェントが行った頻度をレポートします。

各トランスクリプトについて、すべてのツール使用イベントが39個の組み込みポリシー**および** ランタイムポリシーでまだカバーされていないパターンを検出する8個の監査専用ディテクターで再生されます。カウントはすべてのセッションにわたってポリシー/ディテクターごとに集計されます。

## 取得できる情報

`/audit` ページは1画面の共有可能な**ポスター**と、スクロールした先の4つのセクションで構成されます。

1. **ポスター** — エージェントのアイデンティティが一目でわかります: **アーキタイプ**（8種類のうちの1つ — `optimist`、`cowboy`、`explorer`、`goldfish`、`paranoid architect`、`precision builder`、`hammer`、`ghost`）、ペルソナキーワード、そのアーキタイプの希少性、ティアバンド付きの**0〜100スコア**（`S` から `bottom tier` まで）。XやLinkedInへの投稿や、PNGとしてのダウンロードに対応した共有向けのデザインです。
2. **`// strengths`** — エージェントがすでに得意としていること。スキャンによる実際の数値（クリーンなツール呼び出し率、`0` 回のmainへのプッシュ試行など）で表示され、該当ポリシーに問題がない場合にのみ表示されます。
3. **`// quirks`** — 見逃したもの: failproofaiが検出したはずの動作のランク付きテーブル — *いつ*発生したか、*何が見逃されたか*（およびブロックしたはずの組み込みポリシー）、*深刻度*、*発生頻度*（`new` / `recurring` / `N× seen`）。
4. **`// how to improve`** — 推奨される修正リスト: コピペ可能な `failproofai policy add <slug>` が1行ずつ、さらにすべての推奨設定を一度に有効化する **install all** ボタンと、実施した場合の**予測スコア**が表示されます。
5. **`// come back better`** — 習慣化を支援: 再監査のメール**リマインダー**（`3d` / `7d` / `14d` / `30d`）の設定や即時再監査、**友達を招待**して自分の監査を実行してもらう機能（failproof.aiから送信され、あなたにCc）。リマインダーと招待にはサインインが必要です。

## スケジュール監査

**failproofaid デーモン**を実行している場合（[`failproofai config`](/ja/cli/install-policies) を参照）、
スケジュールに従って監査を自動実行し、バックグラウンドで `/audit` レポートを更新できます。
デフォルトでは**オフ**です。スキャンはこのマシン上のすべてのエージェントセッションのトランスクリプトの*内容*を読み取るため、明示的に要求するまでタイマーによるスキャンは行われません。

`~/.failproofai/config.json` で有効化できます — ファイルに既存の設定と並べて `audit` キーを追加してください:

```json
{
  "audit": {
    "auto": true,
    "interval_days": 7
  }
}
```

| キー | 意味 |
|---|---|
| `auto` | `true` でスケジュールスキャンが有効になります。未設定・`false`・`"yes"` はすべてオフです。 |
| `interval_days` | スキャン間の日数。1〜90に制限され、`0`・負の値・非数値の場合は `7` にフォールバックします。 |

- スケジュールは**ウォールクロック（実時間）**ベースのため、サスペンドや再起動後も維持されます: 予定時刻を過ぎてスリープしていたノートPCは、起動後に**1回だけ**実行され、溜まった分が一度に実行されることはありません。
- 各実行は独立した低優先度（`nice 19`）プロセスです — ツール呼び出しへの応答を妨げないよう、デーモンのフックパスとは分離されています。
- `failproofai audit` またはダッシュボードの再実行がすでに進行中の場合、スキャンはスキップされ、失敗として扱われるのではなく直後に再試行されます。
- 進捗は `~/.failproofai/state/audit-schedule.json`（最終実行日時、次回予定日時）に記録されます。このファイルはデーモンが管理します — 実行頻度の変更は `config.json` で行ってください。

<Note>
古いバージョンのfailproofaiでセットアップしたマシンでこの機能を有効化した場合は、
`failproofai config` を一度実行してください。デーモンのサービス定義にCLIを起動するための追加エントリが必要で、このコマンドで更新されます。
</Note>

## 監査専用ディテクター

これらはリアルタイムで強制されていない（まだの）「非効率な動作」パターンを検出します。監査時にのみ実行され、ライブのツール呼び出しをブロックすることはありません。

| ディテクター | 検出内容 |
|---|---|
| `redundant-cd-cwd` | コマンドがすでに `cwd` で実行されているにもかかわらず `cd <cwd> && …` で始まるBashコマンド。 |
| `prefer-edit-over-read-cat` | 単一のソースファイルに対する `cat`/`head`/`tail`/`less`/`more` — `Read` ツールを使用してください。 |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` によるインプレース編集 — `Edit` ツールを使用してください。 |
| `prefer-write-over-heredoc` | ヒアドキュメントや複数行の `echo > file` によるファイル書き込み — `Write` ツールを使用してください。 |
| `sleep-polling-loop` | 長い `sleep N`（30秒以上）や `while …; sleep …; done` のポーリングループ。 |
| `find-from-root` | `find /`、`find /home`、`find /usr` など — `cwd` にスコープを絞ってください。 |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n` によるフック無効化コミット。 |
| `reread-after-edit` | 同一セッション内で `Edit`/`Write` した直後のファイルへの `Read`。 |

## キャッシュ

- `~/.failproofai/cache/audit/<sha1>.json` の**トランスクリプトごとのキャッシュ**は `(mtime, size, engineVersion, detectorVersion)` をキーとしており、トランスクリプトまたはポリシー/ディテクターコードが変更されると自動的に無効化されます。各エントリには **TTLメタデータ**として `cachedAt` タイムスタンプも保存されます（キャッシュキーには含まれません）。**7日**を超えたエントリは読み取り時に拒否されるため、古くなった結果がディテクターの進化した意図に反して使われることはありません。
- `~/.failproofai/audit-dashboard.json`（モード0600）の**全体結果キャッシュ**。ナビゲーション時に再実行なしでダッシュボードを即座にレンダリングできます。こちらも**7日のTTL**を超えると読み取り時に拒否されます — `/audit` は空の状態にフォールバックし、新たな実行を促します。レポート下部の `[ re-audit now ]` をクリックして更新してください — 再監査は `noCache: true` を送信するため、トランスクリプトごとのキャッシュをバイパスし、キャッシュ結果を返すのではなくすべてのトランスクリプトを再スキャンします。実行はページ上部のスティッキーストリップに進捗をストリーミング表示し、成功すると結果をインプレースで置き換えます（ページのリロードなし。再監査が失敗した場合は前のレポートが保持されます）。

## 注意事項

- **変更なし。** 監査は読み取り専用モードで再生されます。`warn-repeated-tool-calls` はセッションごとのサイドカーが変更されることを防ぐためスキップされます。
- **ワークフローポリシーのスキップ。** `require-*-before-stop` ポリシーは `Stop` イベント時にのみ発火し、ライブのgit状態に対して `execSync` を実行します — 「2025年に何が起こったか」という意味のある解釈ができないため、監査カウントには表示されません。
- **カスタムポリシーのスキップ。** ユーザーが提供したカスタムフックは再生されません（元のセッション以降に変更されている可能性があります）。
