---

```bash
failproofai migrate --dry-run   # プランを表示するだけで変更しない
failproofai migrate             # 実際に実行する
```

ほとんどの場合、このコマンドを直接入力する必要はありません。アップグレード後の最初のコマンド実行時に自動的に実行され、[`failproofai update`](/ja/cli/update) にも含まれています。実行前にプランを確認したい場合や、移行処理だけを単独で行いたい場合に直接使用してください。

## バージョンではなくレイアウトで管理

`~/.failproofai/VERSION` には、リリースバージョンではなく**レイアウト**番号（ディレクトリ構造の形式）が記録されています。移行処理はこの番号に基づいて行われるため、長期間バージョンが離れていても効率的に処理できます。

- npm のバージョンはリリースのたびに変わり、2つのレイアウトの間に数十回変わることもあります。
- そのため、**レイアウトに変更がない**まま30回リリースをスキップしたマシンでは、30回の空処理ではなく**移行処理がゼロ回**実行されます。
- 複数のレイアウトを一度にスキップした場合は、各ステップが順番に実行され、それぞれのステップは自分の前後の状態だけを把握して処理します。

npm はインストール済みパッケージを自動更新できないため、これは重要な特性です。一つのバージョンに何ヶ月も留まったあと一気に複数のレイアウトを跨ぐというケースは、例外ではなく通常の使われ方です。

## ドライラン

`--dry-run` は実行されるステップの連鎖と、事前にバックアップされるファイルを表示するだけで、実際には何も変更しません。移行処理・バックアップ・台帳への記録はいずれも行われません。

```
Layout 2 on disk; this build speaks 3.
1 step(s) would run:
  2 → 3  layout 2 → 3: carry config.toml and credentials.toml into JSON, move
         custom-policies/ back up into policies/, nest the policy config at the root

These would be copied to ~/.failproofai/migrations/backup-layout2 first:
  VERSION
  config.toml
  credentials.toml
```

## 保持されるデータと再構築されるデータ

ホームディレクトリの各パスが保持するデータの種類によって、移行時に破棄できるかどうかが決まります。ルールは次のとおりです。**派生データや再取得可能なデータは破棄してよい。ユーザーが入力した情報、未配信のデータ、マシンを識別する情報は保持する。**

| 保持されるデータ | 再構築または再取得されるデータ |
|---|---|
| `config.json` — 設定、`daemon.configured`、追加のキャプチャパス | 監査キャッシュ |
| `credentials.json` — クラウド登録情報 | クラウド管理のデプロイメント（次回のポーリング時に再取得・ダイジェスト検証される） |
| `policies-config.json` — ポリシーの選択とパラメータ | デーモンの一時状態 |
| `policies/` — 独自のポリシーファイルとそれらがインポートするヘルパー | |
| `hook-activity/` — ダッシュボードが参照する判定ログ | |
| アップロード待ちの未配信イベント | |
| `cursors/` — コレクターのウォーターマーク | |
| `bin/` 内のデーモンバイナリ | |

<Note>
  未配信のイベントは破棄せず保持します。失われた場合の影響が一時的な遅延ではなく永続的な損失となるためです。コレクターのウォーターマークはスプール内のデータを既に通過しているため、そのトランスクリプトの範囲が再び読み取られることはありません。移行処理はデーモンに対してスプール内のデータを完了後すぐに配信するよう指示するため、通常は保持すべきデータが残らない状態になります。
</Note>

*新しい*バージョンが `config.json`、`credentials.json`、`policies-config.json` に書き込んだキーも、古いリーダーによって削除されることなく保持されます。

## 移行後に残る記録

```
~/.failproofai/migrations/
  applied.json                 各ステップの記録: レイアウト、CLI、タイムスタンプ、処理時間、結果
  backup-layout<n>/            最初のステップ実行前に取得した、不可欠なファイルのコピー
```

`applied.json` は「このマシンで実際に何が行われたか」を答えるファイルです。アップグレード後に問題が発生した場合、最初に確認すべき情報であり、バグレポートに添付してください。

バックアップはディレクトリ全体のコピーではなく、意図的に小さく保たれています。設計上、移行処理は不可欠なデータを削除しないため、保険をかける必要があるのは*ステップの不具合*に対してであり、その影響を受けるのはこれらの少数のファイルだけです。

## ステップが失敗した場合

その時点でチェーンが停止します。`VERSION` は完了したステップによってのみ更新されるため、ホームディレクトリは古いレイアウトのまま残り、次のコマンド実行時に再試行されます。部分的な移行が完了したとみなされることはありません。失敗したステップは `"ok": false` として `applied.json` に記録され、バックアップは取得された場所に保存されたままになります。

## より新しいホームは移行されず拒否される

`~/.failproofai/` が現在実行している failproofai より**新しい**バージョンによって書き込まれていた場合、コマンドは停止し、代わりにアップグレードするよう案内します。そのデータは問題なく、新しい CLI で読み取れます。そこから「前方」へ移行するという概念は存在せず、リセットすると回復可能なデータが失われます。

```
This machine's failproofai directory was written by a newer version (layout 4;
this build speaks 3). Upgrade rather than migrate:
  npm install -g failproofai@latest
```

デーモンも同じルールを適用します。`failproofaid` は自身が対応していないレイアウトに対して、移動済みのパスを読み書きするのではなく、起動を拒否します。
