---
title: アップグレード後の更新
description: "npm が担えないアップグレードの残り半分を完了する：ホームの移行とデーモンの同期"
---

```bash
npm install -g failproofai@latest && failproofai update
```

アップグレードはこれだけです。`npm` が CLI を差し替え、`failproofai update` が残りを行います。

## 2つ目のコマンドが必要な理由

`npm install -g` が置き換えるのは CLI だけです。failproofai のインストールには、意図的にパッケージの外側に置かれた2つのコンポーネントが存在しており、npm を実行しても両方とも更新されません。

- **`~/.failproofai/`** — 設定、クラウド登録、ポリシー選択、履歴が含まれます。新バージョンでは構成が変わる場合があり、その再編成は両方の構成を把握したコードで行う必要があります。
- **`failproofaid` デーモンバイナリ** — `~/.failproofai/bin/failproofaid-<version>` に配置されています。`node_modules` の外側に置かれているのは意図的な設計です。実行中のサービスのファイルを差し替えると、稼働中のデーモンが異なるソースからビルドされたバイナリを参照することになり、またパッケージを削除するとサービスが起動のたびにクラッシュループに陥ります。

そのため `npm install -g` だけを実行した状態では、CLI は新しくなってもデーモンは古いままです。`failproofaid` は認識できないホームレイアウトに対して起動を拒否します — バージョン不一致を無言で許容するのではなく、明示的にエラーとするためです。この2つを揃えるのが `failproofai update` の役割です。

## 実行内容

<Steps>
  <Step title="未適用のレイアウト移行を実行する">
    `~/.failproofai/VERSION` に記録されたレイアウトを読み取り、現バージョンが扱えるレイアウトへと移行するステップを実行します。通常は何も行いません — [`failproofai migrate`](/ja/cli/migrate) を参照してください。
  </Step>
  <Step title="対応するデーモンバイナリを配置する">
    可能であれば npm がすでにダウンロード済みのプラットフォームパッケージから取得します（ネットワーク不要）。それが無い場合は、この正確なバージョンのリリースアセットから取得し、使用前に SHA-256 で検証します。
  </Step>
  <Step title="サービスを再起動して正常に復帰したことを確認する">
    想定ではなく実際に確認します — サービスマネージャーはプロセスをフォークした時点でアクティブと報告しますが、それは正常動作を意味しません。
  </Step>
</Steps>

## オプション

| フラグ | 効果 |
|--------|------|
| `--no-daemon` | ホームの移行のみ行い、デーモンは現在のバージョンのまま残します。 |

<Warning>
  `--no-daemon` を指定すると、バージョンがずれたデーモンがそのまま残ります。デーモンを必須とするよう設定されたマシンでは、デーモンが応答できない場合にすべてのフックイベントが **フェイルクローズ** になります — 移行後のホームに対して起動を拒否するデーモンは応答できません。デーモンの更新も一緒に実行することを推奨します。
</Warning>

## 問題が発生した場合

コマンドはゼロ以外の終了コードで終了し、どちらの処理が失敗したかを表示します。知っておくべき2つのケース：

- **移行ステップが完了しなかった。** ホームには*古い*レイアウトが記録されたままになるため、次回のコマンド実行時に再試行されます — 部分的な移行が成功したとしてホームが現行とマークされることはありません。実行前に設定と登録情報のコピーが `~/.failproofai/migrations/backup-layout<n>/` に保存されています。
- **パスワードなしでデーモンを再起動できなかった。** `sudo -n` を意図的に使用しているため、進捗表示の裏でパスワードを求めることはありません。コマンドは自分で実行すべき正確なコマンド行を表示します。

<Note>
  これらの操作はインタラクティブなセットアップウィザードを必要としません。設定、クラウド登録、ポリシー選択はアップグレードを経ても保持されるため、移行済みのマシンはアップグレード前とまったく同じように動作します — これは誰も座っていないマシン（CI ランナー、フリートボックス、ヘッドレスゲートウェイなど）で特に重要です。
</Note>

## 自動化

`failproofai update` は非インタラクティブで、何も行うことがない場合でも安全に実行できます — 「移行は不要でした」と報告して終了コード 0 で終了します。プロビジョニングスクリプトや Dockerfile でアップグレードのたびに実行するのが想定された使い方です。

```dockerfile
RUN npm install -g failproofai@latest && failproofai update --no-daemon
```

（イメージビルド時は `--no-daemon` を使用します。この時点ではまだ再起動するサービスが存在しないためです。）
