---
title: アップグレード後の更新
description: "npm では完結しないアップグレードの後半を完了する: ホームの移行とデーモンの同期"
---

```bash
npm install -g failproofai@latest && failproofai update
```

アップグレードはこれだけです。`npm` が CLI を置き換え、`failproofai update` が残りの処理を行います。

## 2つ目のコマンドが必要な理由

`npm install -g` が置き換えるのは CLI だけです。failproofai のインストールには、パッケージの外側に意図的に配置されたコンポーネントがさらに 2 つあり、npm の実行時にはどちらも移動しません。

- **`~/.failproofai/`** — 設定、クラウド登録、ポリシー選択、および履歴が格納されています。新バージョンでは構成が変わる場合があり、その再編成は新旧両方の構造を理解したコードによって行われる必要があります。
- **`failproofaid` デーモンバイナリ** (`~/.failproofai/bin/failproofaid-<version>`) — 意図的に `node_modules` の外に配置されています。実行中のサービス下でファイルを差し替えると、動作中のデーモンが異なるソースからビルドされたバイナリを参照することになり、パッケージを削除するとサービスが依存するファイルが消えて起動のたびにクラッシュループが発生します。

そのため、`npm install -g` だけを実行した時点では、CLI は新しくなっていますがデーモンは古いままです。`failproofaid` は、自身が理解できないホームレイアウトに対しては起動を拒否します。サイレントな不整合ではなく、明示的なエラーという形でミスマッチを報告するので、両方の半分を合わせる必要があります。それが `failproofai update` のステップです。

## 実行内容

<Steps>
  <Step title="保留中のレイアウト移行を実行する">
    `~/.failproofai/VERSION` に記録されたレイアウトを読み込み、現バージョンが想定する状態へと移行するステップを実行します。通常は何も行いません。詳細は [`failproofai migrate`](/ja/cli/migrate) を参照してください。
  </Step>
  <Step title="対応するデーモンバイナリを配置する">
    npm がダウンロード済みのプラットフォームパッケージから取得できる場合はネットワーク不要で取得し、それ以外の場合はこのバージョン専用のリリースアセットから取得します。使用前に SHA-256 で検証されます。
  </Step>
  <Step title="サービスを再起動して正常稼働を確認する">
    想定ではなく実際にプローブして確認します。サービスマネージャーはプロセスをフォークした瞬間にアクティブと報告しますが、それは正常動作を意味しません。
  </Step>
</Steps>

## オプション

| フラグ | 効果 |
|--------|------|
| `--no-daemon` | ホームの移行のみ行い、デーモンは現在のバージョンのまま残します。 |

<Warning>
  `--no-daemon` を使用すると、バージョンがずれたデーモンがそのまま残ります。デーモンを必須とするマシンでは、デーモンが応答できない場合にすべてのフックイベントが **フェイルクローズ** になります。移行済みのホームに対して起動を拒否するデーモンは応答できません。デーモン側の処理も実行することを推奨します。
</Warning>

## 問題が発生した場合

コマンドはゼロ以外の終了コードで終了し、どちらの処理が失敗したかを報告します。知っておくべきケースが 2 つあります。

- **移行ステップが完了しなかった場合。** ホームは *古い* レイアウトのままマークされ、次のコマンド実行時に再試行されます。部分的な移行が完了したとして現在のレイアウトにマークされることはありません。設定と登録のコピーは処理開始前に `~/.failproofai/migrations/backup-layout<n>/` に保存されています。
- **パスワードなしでデーモンを再起動できなかった場合。** `sudo -n` を意図的に使用しているため、進行表示の裏でパスワードプロンプトが表示されることはありません。コマンドは自分で実行すべき正確なコマンドラインを出力します。

<Note>
  これらの操作に対話的なセットアップウィザードは不要です。設定、クラウド登録、ポリシー選択はアップグレードをまたいで保持されるため、移行済みのマシンはアップグレード前と全く同じように施行を継続します。これが最も重要なのは、誰も前に座っていないマシン (CI ランナー、フリートボックス、ヘッドレスゲートウェイなど) です。
</Note>

## 自動化

`failproofai update` は非対話型で、何も行うことがない場合でも安全に実行できます。その場合は「移行は不要でした」と報告して終了コード 0 で終了します。プロビジョニングスクリプトや Dockerfile でアップグレードのたびに実行するのが想定される使い方です。

```dockerfile
RUN npm install -g failproofai@latest && failproofai update --no-daemon
```

(イメージビルド時はまだ再起動するサービスが存在しないため、`--no-daemon` を使用します。)
