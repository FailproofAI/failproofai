---
title: アップグレード後の更新
description: "npm では完了できないアップグレードの残り半分を実行する: ホームの移行とデーモンの同期"
---

```bash
npm install -g failproofai@latest && failproofai update
```

アップグレードはこれだけです。`npm` が CLI を置き換え、`failproofai update` が残りを処理します。

## 2番目のコマンドが必要な理由

`npm install -g` が置き換えるのは CLI のみです。failproofai のインストールには、意図的にパッケージの外部に置かれた2つのコンポーネントがあり、npm の実行時にはどちらも移動しません。

- **`~/.failproofai/`** — 設定、クラウド登録、ポリシーの選択、履歴が保存されています。新バージョンではこれらの構成が変わる可能性があり、新旧両方の形式を理解しているコードによってのみ再編成できます。
- **`failproofaid` デーモンバイナリ** — `~/.failproofai/bin/failproofaid-<version>` に配置されています。これは意図的に `node_modules` の外部に置かれています。実行中のサービスの下でファイルを差し替えると、稼働中のデーモンが異なるソースからビルドされたバイナリを参照することになり、またパッケージを削除すると起動のたびにクラッシュループするサービスの足元からバイナリが消えてしまいます。

したがって `npm install -g` だけを実行すると、CLI は新しくなるもののデーモンは更新されません。`failproofaid` は対応していないホームレイアウトに対して起動を拒否します — バージョン不一致を黙って無視するのではなく、明示的にエラーを出す設計です — そのため両方をそろえる必要があります。`failproofai update` がその手順です。

## 実行内容

<Steps>
  <Step title="保留中のレイアウト移行を実行する">
    `~/.failproofai/VERSION` に記録されているレイアウトを読み取り、現在のバージョンに対応した状態へ移行するための手順を実行します。通常は何もありません — [`failproofai migrate`](/ja/cli/migrate) を参照してください。
  </Step>
  <Step title="対応するデーモンバイナリを配置する">
    可能であれば npm がすでにダウンロードしているプラットフォームパッケージから取得します（ネットワーク不要）。それ以外の場合は、この正確なバージョンのリリースアセットから取得し、使用前に SHA-256 で検証します。
  </Step>
  <Step title="サービスを再起動して正常に復帰したことを確認する">
    確認は推測ではなくプローブで行います — サービスマネージャーはプロセスをフォークした瞬間にアクティブと報告しますが、それは正常に動作していることとは異なります。
  </Step>
</Steps>

## オプション

| フラグ | 効果 |
|--------|------|
| `--no-daemon` | ホームの移行のみを行い、デーモンは現在のバージョンのままにします。 |

<Warning>
  `--no-daemon` を使用すると、バージョンがずれたデーモンがそのまま残ります。デーモンを必要とするよう設定されたマシンでは、デーモンが応答できない場合にすべてのフックイベントが **フェイルクローズ** します — 移行済みのホームに対して起動を拒否するデーモンは応答できません。デーモンの更新も一緒に実行することを推奨します。
</Warning>

## 問題が発生した場合

コマンドはゼロ以外の終了コードで終了し、どちらの処理が失敗したかを表示します。知っておくべき2つのケースを示します。

- **移行ステップが完了しなかった場合。** ホームは古いレイアウトのままマークされるため、次回のコマンド実行時に再試行されます — 部分的な移行が完了したとしてホームが現在としてマークされることはありません。設定と登録のコピーは処理の開始前に `~/.failproofai/migrations/backup-layout<n>/` に保存されています。
- **パスワードなしでデーモンを再起動できなかった場合。** `sudo -n` が意図的に使用されているため、進行状況の表示中にプロンプトが表示されることはありません。コマンドは自分で実行すべき正確なコマンド行を出力します。

<Note>
  ここで説明した操作にインタラクティブなセットアップウィザードは必要ありません。設定、クラウド登録、ポリシーの選択はアップグレード後も保持されるため、移行済みのマシンはアップグレード前と同じようにポリシーを適用します — これは誰も操作しないマシン（CI ランナー、フリートボックス、ヘッドレスゲートウェイなど）で特に重要です。
</Note>

## 自動化

`failproofai update` は非インタラクティブで、何もすることがない場合でも安全に実行できます — 「移行は不要でした」と報告して終了コード 0 で終了します。プロビジョニングスクリプトや Dockerfile の各アップグレードの後に追加する使い方が想定されています。

```dockerfile
RUN npm install -g failproofai@latest && failproofai update --no-daemon
```

（イメージのビルド中はまだ再起動するサービスがないため、`--no-daemon` を使用します。）
