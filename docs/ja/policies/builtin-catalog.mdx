39 件の組み込みポリシーのうち 38 件は `FailproofAI/policies` パックとして提供されます。`block-failproofai-commands` はパッケージにコンパイル済みで同梱されています。これはパックが `alwaysOn` を宣言できないためです。インストール済みのパックが、このマシンで適用できる内容の信頼できる情報源です。

```bash
failproofai policies show FailproofAI/policies   # 公開済みカタログ
failproofai policies                             # ここで有効なもの
```

`failproofai policies` はカスタムファイル、規約ファイル、インストール済みパック、およびクラウド割り当てを一覧表示します。組み込みセクションはないため「どの組み込みが存在するか」には答えられません。その質問への回答は `policies show` および [Policy Hub](https://befailproof.ai/policy-hub/FailproofAI/policies/) にあります。

## デフォルトと選択方法

`failproofai policies add FailproofAI/policies` を引数なしで実行すると、パック自身のデフォルト、つまり以下の表で **on** と記載された 10 件が有効になります。`block-failproofai-commands` は選択に関係なく常に有効であり、この選択には含まれません。`--all` ですべてを取得し、`--category <slug>` および `--policy <name>` で一部を取得できます。各見出しの横に記載されているスラグが `--category` で照合される値です。

```bash
failproofai policies add FailproofAI/policies --category git,database
```

`block-failproofai-commands` は **常に有効** です。選択に含まれているかどうかに関わらず、すべての評価時に登録され、無効化や一時停止はできません。エージェントが無効にできるガードは、エージェントに対するガードとして機能しないためです。パックは `alwaysOn` を宣言できないため、このポリシーだけはパックではなくパッケージにコンパイル済みで同梱されています。

## サニタイズ — `sanitize`

これらは `PostToolUse` で実行され、ツールがすでに実行された後に動作します。**ツールの結果を検出して拒否します**。部分文字列を削除して残りを返すわけではありません。

ここでの拒否は、`PostToolUse` の判定を消費するハーネスでのみモデルに届きます。**codex** および **copilot** では、拒否理由がツールの結果全体と置き換わります。claude、cursor、opencode、pi、hermes、openclaw、factory、devin、antigravity、goose では `PostToolUse` は観察のみです。検出は記録されますが、出力は引き続きモデルに届きます。

| ポリシー | トリガー | デフォルト | 結果 |
| --- | --- | --- | --- |
| `sanitize-jwt` | `PostToolUse` | on | JWT を含むツール結果を拒否する。 |
| `sanitize-api-keys` | `PostToolUse` | on | OpenAI、Anthropic、GitHub、AWS、Stripe、Google のキーを含むツール結果を拒否する。 |
| `sanitize-connection-strings` | `PostToolUse` | on | 認証情報が埋め込まれたデータベース接続文字列を含むツール結果を拒否する。 |
| `sanitize-private-key-content` | `PostToolUse` | on | PEM 形式の秘密鍵コンテンツを含むツール結果を拒否する。 |
| `sanitize-bearer-tokens` | `PostToolUse` | on | `Authorization: Bearer` トークンを含むツール結果を拒否する。 |

## ワークフロー — `workflow`

5 件すべてが `Stop` で実行され、デフォルトは無効です。

| ポリシー | デフォルト | 結果 |
| --- | --- | --- |
| `require-commit-before-stop` | off | 追跡中の変更がコミットされていない間は完了を拒否する。 |
| `require-push-before-stop` | off | ローカルのみのコミットが残っている間は完了を拒否する。 |
| `require-pr-before-stop` | off | 現在のブランチのプルリクエストを要求する。 |
| `require-no-conflicts-before-stop` | off | 設定されたベースブランチに対してクリーンなマージを要求する。 |
| `require-ci-green-before-stop` | off | 現在の HEAD コミットの CI チェックの通過を要求する。以前のコミットの古い実行は無視される。 |

これらには `Stop` の判定を消費するハーネスが必要です。すべてのハーネスがそれに該当するわけではありません。

| ハーネス | `Stop` |
| --- | --- |
| claude、codex、copilot、cursor、openclaw、factory、devin、antigravity | ブロックを確認済み：拒否により次のターンが強制される |
| pi | 観察のみ。拒否理由はゲートではなく、指示として次のターンに持ち越される |
| goose、hermes | `Stop` フックがインストールされていないため、5 件とも発火しない |
| opencode | 未確認。`Stop` は opencode が判定を消費するイベントに含まれていない |

Cursor Cloud Agent VM ではストップフックが一切実行されないため、ローカルの Cursor は対象であっても、そこでの Cursor セッションはカバーされません。

<Note>
  `warn-*` ポリシーは `deny` ではなく `instruct` を返します（`prefer-package-manager` は `block-*` 以外の名前の中で例外であり、`deny` を返すため、`PreToolUse` の判定を消費するすべてのハーネス、つまり 12 件すべてでブロックします）。Hermes および Goose、`Stop` チャネル外の Pi・OpenClaw・Factory、`Stop` と `UserPromptSubmit` 以外の Antigravity では、`instruct` は allow に降格し、stderr にメモが出力されます。エージェントには通知されません。Antigravity の `UserPromptSubmit` は実際のセカンドチャネルであり、モデルが実行される前に一時的なメッセージとして指示が注入されます。
</Note>

## パラメーターリファレンス

選択したスコープの `policyParams` オブジェクト配下でパラメーターを設定します。型は各ポリシーによって検証されます。

| ポリシー | パラメーター | 型とデフォルト |
| --- | --- | --- |
| `sanitize-api-keys` | `additionalPatterns` | `pattern[]`、`[]`；各エントリに `regex` と `label` を含む |
| `block-read-outside-cwd` | `allowPaths` | `string[]`、`[]` |
| `block-sudo` | `allowPatterns` | `string[]`、`[]` |
| `block-rm-rf` | `allowPaths` | `string[]`、`[]` |
| インフラブロッカー | `allowPatterns` | `string[]`、`[]` |
| `block-secrets-write` | `additionalPatterns` | `string[]`、`[]` |
| `block-push-master` | `protectedBranches` | `string[]`、`["main", "master"]` |
| `block-work-on-main` | `protectedBranches` | `string[]`、`["main", "master"]` |
| `prefer-package-manager` | `allowed`、`blocked` | `string[]`、`[]` |
| `warn-large-file-write` | `thresholdKb` | `number`、`1024` |
| `require-push-before-stop` | `remote`、`baseBranch` | `string`、`"origin"`；`string`、`"main"` |
| `require-pr-before-stop` | `baseBranch` | `string`、`"main"` |
| `require-no-conflicts-before-stop` | `baseBranch` | `string`、`"main"` |

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status"]
    },
    "block-push-master": {
      "protectedBranches": ["main", "release"]
    }
  }
}
```

<Note>
  `policyParams` のキーとしてポリシー名を直接指定する方式は `FailproofAI/policies` に対してのみ有効です。他のパックでは、キーは `pack/<owner>/<repo>/<policy>` の形式になります。同じポリシー名を宣言した別の作成者のパックには、指定したパラメーターではなくスキーマのデフォルト値が適用されます。
</Note>

<Warning>
  許可パターンはエージェントが実行できる範囲を広げます。フリートにデプロイする前に、対象ハーネスで正確なトークン化とコマンドのバリアントをテストしてください。
</Warning>
