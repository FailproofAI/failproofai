`.failproofai/policies/` 配下に `policies.js`、`policies.mjs`、または `policies.ts` で終わるファイルを作成してください。規約ファイルはプロジェクトスコープおよびユーザースコープで自動的に読み込まれます。

## Cloudへの公開前にポリシーをテストする

<Tabs>
  <Tab title="ダッシュボード">
    1. カスタムポリシーを1台のテストマシンにインストールし、マッチするアクションと正当なアンマッチの両方をトリガーします。
    2. **Observe → policy** に移動し、2つの判定を比較します。
    3. リンクされた各セッションを開き、イベントペイロードにルールの根拠となる十分な証拠が含まれているか確認します。
    4. 動作が正しいことを確認したら、レビュー済みのソースを **Admin → policy editor** に移動してバージョンを公開します。

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies --install --custom ./security.policies.ts \
      --cli claude --scope project
    failproofai policies
    ```

    `.failproofai/policies/` 配下の規約ファイルは `--custom` なしで読み込まれます。壊れたモジュールで検証が失敗するようにする場合は、CI に明示的なインストールコマンドを記述してください。
  </Tab>
</Tabs>

```ts
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "protect-production-paths",
  description: "Block writes to production configuration",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Write" && ctx.toolName !== "Edit") return allow();
    const path = String(ctx.toolInput?.file_path ?? "").replaceAll("\\", "/");
    if (path.split("/").includes("production")) {
      return deny("Writes to production configuration require approval.");
    }
    return allow();
  },
});
```

これは `Write` と `Edit` の両方に対して、`production/config.yml`、`/srv/production/config.yml`、`/srv/production`、`C:\\production\\config.yml` にマッチします。`production` は完全なパスセグメントである必要があるため、`production-backup` のような名前にはマッチしません。

明示的なファイルを検証してインストールするには：

```bash
failproofai policies --install --custom ./security.policies.ts
```

ポリシーコンテキストには、イベントタイプ、正規化されたペイロード、ツール名と入力、セッションメタデータ、パラメータ、および利用可能な場合はソースCLIが含まれます。

## 失敗パスのテスト

エントリファイルまたはそれがインポートするローカルモジュールを変更した後は、検証を実行してください：

```bash
failproofai policies --install --custom ./security.policies.ts --scope project
```

strictなCLIパスは、ファイルの欠落、構文エラー、未解決のインポート、トップレベルの例外、モジュール読み込みのタイムアウトで失敗します。適用時に壊れたカスタムファイルはログに記録されてスキップされるため、組み込みポリシーは継続できます。読み込み警告は期待される適用の損失として扱い、本番ログでアラートを設定してください。

明示的なポリシー、規約ポリシー、Cloudで管理されるポリシーを通じてグローバルに一意な名前を使用してください。ポリシー関数は決定論的に保ち、外部呼び出しには短いタイムアウトを設定し、すべてのパスで意図した `allow`、`instruct`、または `deny` を返すようにしてください。

<Warning>
  カスタムポリシーはエンフォースメントコードです。期待されるマッチだけでなく、フィールドの欠落、代替ツール名、不正な入力もテストしてください。
</Warning>
