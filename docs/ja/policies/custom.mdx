ポリシーを作成する前に、[組み込みカタログ](/ja/policies/builtin-catalog)を確認してください。レビュー済みのルールは、新しく作成したものより通常安全です。

## 動作するポリシーから始める

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

スターターは `git push --force` をブロックします。編集してエージェントにブロックされたアクションを試させ、**Policies → Activity** で確認してください。

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "protect-production",
  description: "Production changes need a human",
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) =>
    String(ctx.toolInput?.command ?? "").includes("production")
      ? deny("Ask a human before changing production.")
      : allow(),
});
```

ポリシーは `allow()`、`deny(message)`、または `instruct(message)` を返します。アクションを停止させる必要がある場合は `deny` を使用してください。すべてのハーネスがエージェントへ指示を返せるわけではありません。

## 自動読み込み

`*policies.js`、`*policies.mjs`、または `*policies.ts` という名前のファイルを以下に配置します：

- `.failproofai/policies/` — 特定のプロジェクト向け
- `~/.failproofai/policies/` — ユーザー全体向け

## 失敗パスのテスト

安全でないアクションと、それに似た正当な操作の両方をテストしてください。その判断が別のルールではなく、自分のポリシーによるものであることを確認します。

テスト用ファイルを削除するには：

```bash
failproofai policies -u -c
```

ポリシーの準備ができたら、[パックを公開する](/ja/policies/publish-a-pack)か、[Cloud 経由でデプロイ](/ja/policies/deploy)してください。
