デプロイメントは、1つ以上のポリシーバージョンを対象の登録済みマシンセットに紐付けます。

## デプロイメントの適用

<Tabs>
  <Tab title="ダッシュボード">
    1. **Admin → enforcement** に移動し、対象マシンを見つけて行を展開します。
    2. **edit** を選択し、レビュー済みのポリシーバージョンを追加して、**observe** または強制効果を選択します。
    3. 変更を適用し、マシンの次回チェックインを待ってデプロイメントとカバレッジの状態を確認します。
    4. **Observe → policy** に移動してリアルタイムの判定を確認します。

    ![ポリシーバージョン、enforce および observe エフェクト、デプロイメント適用アクションを含むマシンデプロイメントエディター](/images/dashboard/enforcement-editor.png)
  </Tab>
  <Tab title="CLI">
    クラウドのデプロイメントエンドポイントは、通常の `fp` コマンドとして意図的に公開されていません。マシンをローカルで確認してから、ダッシュボードを通じてデプロイしてください。

    ```bash
    failproofai config --status
    ```

    デプロイ後は `fp sessions --env production --since 24h` および `fp events --event-type hook_completed` を使用して、アクティビティが Cloud に届いていることを確認します。
  </Tab>
</Tabs>

<Steps>
  <Step title="バージョンとターゲットの選択">
    変更可能なドラフトではなく、レビュー済みのバージョンをデプロイしてください。まず本番環境以外のマシンや、セッションを確認できる少数のコーホートから始めましょう。
  </Step>
  <Step title="判定の観察">
    作業をブロックせずに、マッチ結果・理由・影響を受けるツール・誤検知を確認します。
  </Step>
  <Step title="強制適用とカバレッジの確認">
    観察されたマッチが安全でないアクションと有効なアクションを区別できると判断できたら強制適用に移行し、すべての対象マシンがデプロイメントを取得して判定を報告していることを確認します。
  </Step>
</Steps>

マシンには `policies:pull` 権限が必要です。イベントレポートは `events:add` によって個別に制御されます。Cloud の分析と強制適用を期待する場合は、両方を確認してください。

<Warning>
  強制適用の管理は管理者向けの Cloud ワークフローです。ルート専用の強制適用ルートを通常のカスタマー `/v1` API エンドポイントとして扱わないでください。
</Warning>
