レビュー済みのポリシーを1台ずつマシンにデプロイします。まずはオブザーブモードから始めましょう。

## CLIからのロールアウト

```bash
fp policies test ./rule.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish no-force-push ./rule.mjs
fp fleet deploy <machine> --add no-force-push:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add no-force-push:enforce
```

オブザーブモードは実際のポリシーを評価し、allow以外の判断を記録しますが、エージェントをブロックしません。

<Warning>
  `--add no-force-push` を単独で使用すると即座に適用されます。シャドウロールアウトには `:observe` を付けてください。
</Warning>

適用によって問題が発生した場合:

```bash
fp fleet history <machine>
fp fleet rollback <machine> <generation>
```

## ダッシュボードからのデプロイ

1. **Admin → enforcement** に移動します。
2. 対象のマシンを開きます。
3. エフェクトを **observe** に設定してポリシーバージョンを追加します。
4. デプロイメントを適用します。
5. **Observe → policy** で結果を確認します。
6. マッチ内容が正しければ、同じバージョンを **enforce** に昇格させます。

## セットの置き換えまたは事前ステージング

- `--remove <id>` は1つのポリシーを削除します。
- `--set <ref>...` はポリシーセット全体を置き換えます。
- `--create` はマシンが最初にチェックインする前にデプロイメントを準備します。
- `fp fleet diff <machine>` は意図した状態と適用済みの状態を比較します。

<Note>
  Cloudなしで使用する場合は、`failproofai publish --effect observe` でパックを公開し、ローカルダッシュボードで判断内容を確認してください。
</Note>

マシンがデプロイメントを受け取るには `policies:pull` 権限が、判断を報告するには `events:add` 権限が必要です。
