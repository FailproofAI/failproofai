ポリシーエディターを使用して、発見された問題や課題をデプロイ可能なルールに変換します。ドラフトが本番環境の動作をサイレントに変更しないよう、オーサリングとデプロイメントを分離して管理します。

問題に繰り返し可能なアクションパターンがある場合は、**Analyze → issues** でその問題を開き、**generate policy** を選択します。Failproof AI はまずポリシーで問題を表現できるかどうかを説明し、レビュー済みの意図と発見内容のコンテキストをエディターに引き継ぎます。生成されたソースはPublishするまでドラフトのままです。

## ポリシーバージョンのPublish

<Tabs>
  <Tab title="Dashboard">
    1. **Admin → policy editor** に移動し、**compose** で障害モードを説明するか、JavaScriptのポリシーソースを貼り付けます。
    2. ソースを検証し、報告されたすべてのエラーを修正します。
    3. ポリシーのIDを入力してPublishし、**library** でバージョンの比較や無効化を行います。
    4. マシンへのロールアウトの準備ができたら **enforcement** を選択します。

    ![ポリシーのID、AIによるドラフト支援、ソース検証、およびPublishコントロールを備えたPolicy editorのcomposeビュー。](/images/dashboard/policy-editor.png)
  </Tab>
  <Tab title="CLI">
    Cloud CLIはポリシーバージョンをPublishしません。エディターにコピーする前に、ローカルでソースを検証してください：

    ```bash
    failproofai policies --install --custom ./checkout.policies.ts \
      --cli claude --scope project
    ```

    レビュー済みのバージョンは **Admin → policy editor** からPublishしてください。
  </Tab>
</Tabs>

## オーサリングチェックリスト

1. 運用上の言語で障害モードを命名する。
2. 判断に十分な証拠を含むフックイベントとツールを選択する。
3. 安全でない動作に一致する最も狭い条件を記述する。
4. エージェントまたはオペレーターに次に何をすべきかを伝える理由を返す。
5. 一致すべき例と、許可されたままであるべき例を追加する。
6. 新しいバージョンを保存してレビューをリクエストする。

エージェントが安全にコースを修正できる場合は `instruct` を使用します。アクションを許可することが受け入れがたいリスクや不可逆的なリスクをもたらす場合は `deny` を使用します。

<Info>
  ポリシーバージョンはイミュータブルなデプロイメント入力です。ドラフトを編集すると新しいバージョンが作成されます。すでにマシンに割り当てられたバージョンを上書きすることはありません。
</Info>
