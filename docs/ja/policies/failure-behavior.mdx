---

セットアップ後、ローカルの `failproofaid` サービスが唯一の評価者となります。応答できない場合、保護対象のアクションは暗黙的に許可されるのではなく、拒否されます。

## マシン全体のブロックを診断する

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

`failproofai config` を実行してサービスを修復するか、一致するバージョンをインストールしてください。

2 種類の失敗は見た目が似ています：

| 失敗の種類 | 意味 |
| --- | --- |
| サービスに到達できない | ソケットの背後に機能している評価者が存在しない |
| バージョンの不一致 | CLI とサービスがプロトコルについて合意していない |

どちらも拒否されますが、ステータスではそれぞれ別々に報告されます。

## パックが読み込まれない場合

選択されたパックが存在しない、変更されている、または無効な場合、そのパックの選択されたポリシーが対象とするイベントは拒否されます。これにより、マシンが保護されているように見える間に、壊れたパックが消えてしまうことを防ぎます。

`failproofai policies` はパック名と読み込みエラーを表示します。

```bash
failproofai policies
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

読み取り不能なメタデータは、信頼できないデータによって安全な拒否の範囲を狭めるのではなく、拡大します。

## 引き続き利用できるもの

ポリシー評価が失敗している間も、ローカルダッシュボードとステータスコマンドは引き続き動作します。これらを使用して、修復が必要なサービス、パック、またはバージョンを特定してください。

<Warning>
  サービスやパックのファイルを削除することで、失敗時閉鎖の決定を回避しようとしないでください。サービスを修復するか、パックを再インストールするか、または CLI を通じてアサインメントを削除し、マシンを既知の状態に戻してください。
</Warning>
