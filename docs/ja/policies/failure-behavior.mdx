Failproof AI は、強制実行に失敗した場合、リスクのある操作を無声で許可するのではなく、失敗を明示的に可視化するよう設計されています。

## failure-closed ブロックの診断

<Tabs>
  <Tab title="ダッシュボード">
    1. **Admin → enforcement** に移動し、対象マシンを開きます。
    2. 最終チェックイン、割り当てられたデプロイメント、報告されたデプロイメントを確認します。
    3. **Observe → policy** に移動し、拒否された決定のセッションを開きます。
    4. 理由としてデーモンの到達可能性、バージョンの不一致、またはポリシー自体のいずれが報告されているかを確認します。

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    npm install -g failproofai@latest
    failproofai config
    ```

    `failproofai config` を再実行すると、パッケージのアップグレード後にデーモンが更新・再起動されます。
  </Tab>
</Tabs>

`failproofaid` を使用するよう設定されたマシンでは、デーモンが唯一の評価者です。デーモンに到達できない場合、またはそのプロトコルバージョンが CLI と一致しない場合、フック評価は failure-closed となります。アクションは拒否され、オペレーターにデーモンの確認またはアップデートを促す理由が表示されます。

デーモン設定が行われる前は、フックはプロセス内でポリシーを評価します。デーモンの設定が記録された後、Failproof AI はデーモンが失敗した場合に別の評価者へ無声でフォールバックすることはありません。

## failure-closed の決定への対応

1. `failproofai config --status` を実行します。
2. バージョンが異なる場合は、パッケージを更新した後に `failproofai config` を再実行します。
3. デーモンに到達できない場合は、そのサービス状態とローカルログを確認します。
4. ポリシー評価のパスが正常であることを確認してからエージェントの作業を再開します。

<Warning>
  ブロックされたアクションを繰り返し再試行しないでください。failure-closed の応答は、システムがそのアクションの安全性を確認できなかったことを意味します。
</Warning>
