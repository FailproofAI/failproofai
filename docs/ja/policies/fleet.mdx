フリートカバレッジは、リスクが存在する場所にポリシーが存在するかどうかを確認するものです。安定したIDと人間が読めるラベルでマシンを追跡し、割り当てられたデプロイ状態と報告されたデプロイ状態を比較します。

## カバレッジの確認

<Tabs>
  <Tab title="ダッシュボード">
    1. **Admin → enforcement** に移動し、適用中（enforcing）および監視中（observing）の合計を確認します。
    2. IDまたはラベルでマシンを検索するか、ポリシーが割り当てられていないマシンをフィルタリングします。
    3. 行を展開して、割り当てられたポリシー、報告されたデプロイ状態、最終チェックイン、および履歴を比較します。
    4. 適用済みのデプロイが保留中のままの場合は、マシンのポーリング間隔後に更新します。

    ![ポリシーカバレッジ、マシンのデプロイ状態、監視および適用の割り当てを表示するEnforcementフリート画面。](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    `fp events --agent-id <agent-id> --since 24h` を使用して、マシンのエージェントアクティビティがクラウドに届いていることを確認します。
  </Tab>
</Tabs>

カバレッジビューを使用して以下を特定します：

- 最新のデプロイを一度も取得していないマシン
- アクティビティの報告を停止した登録済みマシン
- 誤った環境またはコホートに割り当てられたポリシー
- 中断されたアップデート後のバージョンのずれ

マシンを再接続せずに名前を変更する：

```bash
failproofai config --machine-label checkout-runner-03
```

ローカルの状態を確認する：

```bash
failproofai config --status
```

<Tip>
  ワークロードと環境を識別するラベルを使用してください。ホスト名だけでは、オートスケーリングやマシンの交換後に不十分になることがよくあります。
</Tip>
