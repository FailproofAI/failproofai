Jev は、ツール呼び出しの内容をユーザーがエージェントに依頼した内容と照合して評価します。文字列マッチングによるポリシーが正当な操作をブロックしてしまう場合や、文脈が必要なリスクのある操作を見逃してしまう場合に活用してください。Jev は `PreToolUse` または `PermissionRequest` ゲートで、既存のポリシーと並行して判断を返します。セッション終了**後**にスコアを確認する場合は、[Jev evaluations](/ja/evaluations/jev) をご利用ください。

## オブザーブモードで開始する

Failproof AI をインストールし、[対応ハーネス](/ja/reference/harnesses)にフックをアタッチします。failproofai 1.0.8-beta.0 以降を使用してください。

Failproof AI は Jev チェックを標準では含みません。パックとしてインストールしてください。インストールしない場合、Jev は何も評価できず呼び出されません。

```bash
failproofai policies add FailproofAI/jev-policies
```

次に、リクエストを Jev に送る方法を選択します。

| ルート | 最初のステップ |
| --- | --- |
| FailproofAI Cloud | `jev:evaluate` 権限を持つ **machine** キーで接続します。Jev の設定がないマシンでは、`failproofai config` を実行すると Jev がオブザーブモードで有効になります。 |
| 独自のプロバイダー | ローカルダッシュボードで **Settings → Jev** を開き、プロバイダーを選択してトークンを貼り付け、**observe** を選択します。または `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key` を実行します。 |

![ローカルダッシュボードの Jev 設定画面: プロバイダー、エンドポイント、トークン、および Jev を有効にする前のオブザーブモード。](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` はエンドポイントの疎通確認を行います。フックのパスを確認するには、フックを設定したエージェントにファイル読み取りツールで `README.md` を参照するよう指示します。そのツール呼び出しがセッションに記録されていることを確認してから、[ローカルダッシュボード](/ja/reference/local-dashboard#review-policy-activity)の **Policies → Activity** で内容を確認してください。`status` の Jev カウントが増加しているはずです。オブザーブモードでは、Jev が下したであろう判断を記録しつつ、既存のポリシー結果がそのまま適用されます。

## 強制タイミングを決める

**ハード**ポリシーは常に最終決定権を持ちます。Jev が deny を解除できるのは、明示的に **reviewable** とマークされたポリシーの deny のみであり、かつそのポリシーが指定した懸念事項について Jev が評価を行った場合に限られます。解除に依存する前に、[policy authority](/ja/policies/authority) を確認してください。Jev は独自に警告を出したり deny したりすることもできます。Jev が判断できない場合は、ポリシーの結果がその呼び出しを決定します。

オブザーブの結果が期待通りであれば、**Settings → Jev** で強制モードに切り替えるか、次のコマンドを実行してください。

```bash
failproofai jev setup --mode enforce
```

プロバイダー URL、Cloud キー、設定、フォールバック、各リクエストで送信されるデータについては、[Jev integration reference](/ja/reference/jev) を参照してください。
