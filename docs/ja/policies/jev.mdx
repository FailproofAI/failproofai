Jevはツール呼び出しを、ユーザーがエージェントに依頼した内容と照らし合わせて評価します。文字列マッチングポリシーが有効な操作をブロックしたり、コンテキストが必要なリスクのある操作を見逃したりする場合に活用してください。`PreToolUse` または `PermissionRequest` ゲートで、既存のポリシーと並行して判定を返します。セッション終了**後**にスコアを取得する場合は、[Jev evaluations](/ja/evaluations/jev) を使用してください。

## observeモードで開始する

Failproof AI をインストールし、[対応ハーネス](/ja/reference/harnesses)にフックをアタッチします。failproofai 1.0.8-beta.0 以降を使用してください。

Failproof AI にはJevチェックが同梱されていません。パックとしてインストールする必要があります。インストールしない場合、Jevに問い合わせる内容がなく、呼び出されることもありません。

```bash
failproofai policies add FailproofAI/jev-policies
```

次に、リクエストをJevに送信する方法を選択します。

| ルート | 最初のステップ |
| --- | --- |
| FailproofAI Cloud | `jev:evaluate` 権限を持つ **machine** キーで接続します。Jevの設定がないマシンでは、`failproofai config` を実行するとJevがobserveモードで有効になります。 |
| 独自のプロバイダー | ローカルダッシュボードで **Settings → Jev** を開き、プロバイダーを選択してトークンを貼り付け、**observe** を選択します。または `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key` を実行します。 |

![ローカルダッシュボードのJev設定画面：プロバイダー、エンドポイント、トークン、およびJevを有効にする前のobserveモード。](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` はエンドポイントを確認します。フックのパスを確認するには、フックをアタッチしたエージェントに `README.md` のファイル読み取りツールを使用させてください。そのツール呼び出しがセッションに表示されることを確認し、[ローカルダッシュボード](/ja/reference/local-dashboard#review-policy-activity)の **Policies → Activity** で内容を確認します。`status` のJevカウントが増加しているはずです。observeモードでは、Jevが判断したであろう内容を記録しつつ、既存のポリシー結果がそのまま適用されます。

## 適用タイミングを決定する

**hard** ポリシーは常に最終的な決定権を持ちます。Jevが deny を覆せるのは、明示的に **reviewable** とマークされたポリシーの deny に限られ、かつそのポリシーの指定された懸念事項をJevが確認した場合のみです。クリアランスに依存する前に、[policy authority](/ja/policies/authority) を確認してください。Jevは独自に警告や deny を発することもできます。Jevが回答できない場合は、ポリシーの結果がその呼び出しを決定します。

observeの結果が適切であることを確認したら、**Settings → Jev** でenforceモードに切り替えるか、次のコマンドを実行してください。

```bash
failproofai jev setup --mode enforce
```

プロバイダーURL、Cloudキー、設定、フォールバック、各リクエストで送信されるデータについては、[Jev integration reference](/ja/reference/jev) を参照してください。
