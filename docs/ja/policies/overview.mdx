---
title: "ポリシー"
description: "既知の失敗が繰り返される前に、エージェントを誘導またはブロックします。"
icon: "shield-check"
---

ポリシーはエージェントのアクションを監視し、次の3つのいずれかの判断を返します。

- `allow` — 処理を続行します。
- `instruct` — ハーネスが対応している場合、エージェントにガイダンスを提供します。
- `deny` — アクションをブロックします。

保護されたファイルの削除、シークレットの露出、誤ったブランチへのプッシュ、本番インフラの変更など、既知の再現可能な動作にポリシーを使用してください。

## このマシンにポリシーを追加する

セットアップではポリシーパックは選択されません。セットアップ後に Failproof AI パックを追加します。

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai policies
```

このパッケージには特権的な組み込みパックは含まれていません。当社のパックも他のパックと同じ方法でインストールされます。

ポリシーはローカルファイル、公開済みパック、またはクラウドの割り当てからも取得できます。

| ソース | 追加方法 |
| --- | --- |
| ローカルファイル | `.failproofai/policies/` に `*policies.{js,mjs,ts}` を配置する |
| 任意のファイルパス | `failproofai policies -i -c <path>` |
| 公開済みパック | `failproofai policies add <owner>/<repo>` |
| クラウド | ダッシュボードまたは `fp fleet deploy` で割り当てる |

`block-failproofai-commands` は常に実行され、無効にすることはできません。これにより、エージェントが自身の実行制御を無効化することを防ぎます。

## 適用前に観察する

オブザーブモードでは、実際のポリシーを実行してその結果を記録しますが、エージェントをブロックしません。

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

<Warning>
  `fp fleet deploy <machine> --add <id>` のみを実行すると、即座に適用されます。シャドウロールアウトを行う場合は `:observe` を追加してください。
</Warning>

オブザーブモードでタイムアウトしたポリシーは allow として記録されます。これは適用中に実際に起こる動作と同じだからです。allow 以外のオブザーブ結果のみが記録されます。

クラウドを使用せずにパックを利用する場合は、`failproofai publish --effect observe` で公開してください。
