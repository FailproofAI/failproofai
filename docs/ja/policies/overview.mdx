ポリシーはエージェントのフックイベントを評価し、3つの判断のいずれかを返します：

- `allow` はアクションの続行を許可します。
- `instruct` はエージェントに修正のための指示を与えます。
- `deny` は理由を示してアクションをブロックします。

## 3つのポリシーサーフェスを活用する

<Tabs>
  <Tab title="ダッシュボード">
    1. **Observe → policy** に移動して、セッションのポリシー決定をフィルタリング・確認します。
    2. **Admin → policy editor** に移動して、ポリシーの作成・検証・公開・無効化、またはイミュータブルバージョンの確認を行います。
    3. **Admin → enforcement** に移動して、マシンにバージョンとエフェクトを割り当てます。

    ポリシーページを使用して、ポリシーの作成や実施変更を行う前に、すでにマッチしているものを把握してください。

    ![ポリシーページには、判断の合計数とローカルおよびクラウド管理のポリシーマッピングが表示されます。](/images/dashboard/policy-observe.png)

    エディタでは、失敗条件をソースに変換し、検証して、イミュータブルバージョンを公開します。

    ![イミュータブルなポリシーバージョンの作成と公開に使用するポリシーエディタ。](/images/dashboard/policy-editor.png)

    次に、Enforcement で公開済みバージョンと observe または enforce エフェクトをマシンに割り当てます。

    ![マシンのカバレッジと割り当てられたポリシーバージョンを表示するEnforcementフリート。](/images/dashboard/enforcement-fleet.png)

    デプロイ後はポリシーページで判断を確認し、作成・フリートビューが実際のエージェントアクティビティと結びついていることを確かめてください。
  </Tab>
  <Tab title="CLI">
    `failproofai` をローカルのポリシーインストールと検証に使用します：

    ```bash
    failproofai policies
    failproofai policy add block-rm-rf --scope project
    failproofai config --status
    ```

    `fp` を使用して、ポリシー決定を含むクラウドのセッションとイベントを検索します。クラウドでのポリシー作成とフリートへのデプロイは引き続きダッシュボードのワークフローです。
  </Tab>
</Tabs>

Failproof AI のポリシーには、3つの異なるサーフェスがあります：

1. **判断の分析** — セッション、ダッシュボード、監査ログで行います。
2. **バージョンの作成** — 組み込みルール、コード、またはポリシーエディタを使用します。
3. **バージョンのデプロイと実施** — 選択したマシン全体に適用します。

確認済みの失敗モードから始めてください。それを識別する最小限のイベントとツールのマッチを定義し、正当な例と安全でない例でテストした上で、実施前に観察モードで確認します。
