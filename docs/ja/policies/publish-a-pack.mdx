---
title: "ポリシーを公開する"
description: "ポリシーを公開 GitHub リリースとして配布し、誰でもインストールできるようにします。"
icon: "upload"
---

ポリシーを作成してローカルでテストしたら、パックとして公開しましょう。

## 作成とテスト

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

`--init` は `git push --force` をブロックするポリシーを生成します。編集してエージェントにブロック対象のアクションを試させ、ローカルダッシュボードの **Policies → Activity** で結果を確認してください。

パックのポリシーには以下のような内容を含められます：

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-refunds",
  description: "Refunds above the limit need a human",
  category: "Billing",
  defaultEnabled: true,
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) => {
    // return allow(), instruct(), or deny()
  },
});
```

`defaultEnabled` のデフォルト値は `false` です。

## 公開

ファイルをコミットしてから以下を実行します：

```bash
failproofai publish
```

公開時にポリシーファイルが検出され、インストール時と同じローダーでバリデーションが行われ、パックのアセットが GitHub リリースにアップロードされます。認証には `GITHUB_TOKEN`、`GH_TOKEN`、または `gh auth login` が使用されます。

インストールは匿名 HTTPS で行われるため、リポジトリは公開状態である必要があります。

デフォルトのバージョンは現在のコミットの 12 文字の SHA です。ワーキングツリーが dirty な場合や Git 管理外のディレクトリの場合、`--version` を指定しない限り公開は拒否されます。`HEAD` にタグが付いている場合は SHA よりタグが優先されます。

ユーザーは以下のコマンドでインストールできます：

```bash
failproofai policies add owner/repo
```

## オブザーブモードで公開する

```bash
failproofai publish --effect observe
```

オブザーブモードでは実際のポリシーが評価され、allow 以外の判定が記録されますが、エージェントの処理は継続されます。タイムアウトは allow として記録されます。

観測されたマッチ結果が正しければ、`--effect enforce` を付けて再度公開してください。

## 主なオプション

| フラグ | 効果 |
| --- | --- |
| `--init [file]` | スターターポリシーを生成する |
| `--repo <owner>/<repo>` | リポジトリを選択または作成する |
| `--version <version>` | コミットベースのバージョンを上書きする |
| `--effect enforce|observe` | パックがブロックするかどうかを選択する |
| `--dry-run` | 公開せずにビルドとバリデーションのみ実行する |
| `--allow-private` | プライベートリポジトリに公開する（`policies add` ではインストール不可）|

```bash
failproofai publish --dry-run
failproofai publish ./guards.mjs --repo me/guards --version 2.0.0
```

<Note>
  公開後に GitHub トピック `failproofai-policies` を追加すると、[Policy Hub](https://befailproof.ai/policy-hub/) がパックをインデックスできるようになります。CLI は自動で設定しません。
</Note>

<Warning>
  ポリシー名の変更は既存の選択に対して破壊的な変更となります。リリース間でポリシー名は変えないようにしてください。
</Warning>
