---
title: "ロールバック"
description: "ロールアウトが正常なエージェントの作業を妨げた場合に、既知の正常なポリシーデプロイメントを復元します。"
icon: "rotate-ccw"
---

ロールバックはデプロイ済みのバージョンを変更するか、ポリシーの割り当てを削除します。インシデントの経緯を説明する意思決定履歴は消去されません。

## マシンをロールバックする

<Tabs>
  <Tab title="ダッシュボード">
    1. **Admin → enforcement** に移動し、影響を受けたマシンを展開して、最後に正常だと確認されたポリシーセットを特定します。
    2. **edit** を選択し、それらのバージョンと効果を復元して、新しいデプロイメントを適用します。
    3. マシンのチェックインを待ち、報告されたデプロイメントを確認します。
    4. **Observe → policy** と影響を受けたセッションを開き、正常な作業がブロックされなくなったことを確認します。

  </Tab>
  <Tab title="CLI">
    戻るべきジェネレーションを見つけ、それを復元してから、適用されたことを確認します。

    ```bash
    fp fleet history ci-runner-01
    fp fleet rollback ci-runner-01 3
    fp fleet diff ci-runner-01
    failproofai config --status
    ```

    `fp fleet rollback` はカウンターを巻き戻すのではなく、古いセットを持つ**新しい**ジェネレーションを生成するため、履歴は追記専用のまま維持されます。そのジェネレーションが無効化または削除されたポリシーを参照している場合は実行を拒否します。配信不可能なセットを復元するのではなく、サーバーがその旨を通知します。

    `fp fleet diff` は意図と実際の配信状況の差異を表示します。マシンは次回のポーリングまでドリフト状態として表示されるため、ロールバックが反映されていないと判断する前に diff を確認してください。`failproofai config --status` でマシン自体の状態を確認できます。
  </Tab>
</Tabs>

## 一時停止はロールバックではない

一時停止はローカルにインストールされたすべてのポリシーを**1セッション**の間だけ停止し、常に自動的に期限切れになります。パック、カスタムファイル、規約ファイル、組み込みポリシーのすべてが対象です。クラウド管理のポリシーと常時有効な `block-failproofai-commands` ガードのみが引き続き適用されます。そのため、一時停止は不正なクラウドデプロイメントの回避策にはなりません。また、見た目よりも影響範囲が広くなります。パックは実質的にすべてのローカル強制適用の拠点であり、パックのフェイルクローズドガードも一時停止中はスキップされます。

| コマンド | 効果 |
|---|---|
| `failproofai config --pause` | このディレクトリの最新のエージェントセッションを30分間一時停止 |
| `failproofai config --pause 10m` | 指定した時間だけ一時停止。最大8時間。`s`/`m`/`h` のサフィックスが使用可能で、数値のみの場合は分を意味する |
| `failproofai config --pause --session <id>` | 特定のセッションを対象にする |
| `failproofai config --resume` | 一時停止を早期終了する |
| `failproofai config --resume --all` | すべてのアクティブな一時停止を終了する |
| `failproofai config --status` | 何が一時停止中で、いつ解除されるかを表示 |

## ロールバックすべき状況

- ポリシーが想定される本番操作をブロックしている場合。
- マッチ量がロールアウト時の予測を大幅に上回っている場合。
- ポリシーが、連携しているインテグレーションが提供しないフィールドに依存している場合。
- 新しいバージョンが意図した障害モード以外の動作を変更した場合。

ロールバック後は影響を受けたセッションを開き、誤検知を引き起こした条件を特定します。新しいバージョンを作成し、安全でないケースと正当なケースの両方をローカルでテストしてから、再度強制適用する前に observe フェーズに戻ります。

```bash
fp policies test ./policy.mjs --tool Bash --command '<the legitimate case>' --expect allow
fp policies publish my-policy ./policy.mjs
fp fleet deploy ci-runner-01 --add my-policy:observe
fp guardrails summary --since 24h --machine ci-runner-01
```

`:observe` がシャドウロールアウトを実現するキーです。`fp fleet deploy ... --add my-policy` のように効果を省略すると**即座に強制適用**されます。省略された効果はすでにデプロイ済みの効果に解決され、次に `enforce` に解決されます。つまり、直前にロールバックしたポリシーに対して使用すると、インシデントが再発します。observe モードでもポリシーは実際に評価され、allow 以外のすべての判定が記録されます。強制適用のみが保留されるため、`fp guardrails summary` で古いバージョンで問題が発生したのと同じトラフィックに対して新しいバージョンを検証できます。数値が適切であれば `--add my-policy:enforce` でプロモートしてください。

<Warning>
  インシデント発生中は強制適用の一時停止が適切な場合もありますが、そのスコープ内のすべてのアクティブなポリシーへの露出が広がります。可能な限り、特定のポリシーバージョンをロールバックすることを優先してください。
</Warning>
