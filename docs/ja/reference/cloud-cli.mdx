`fp` を使って、Cloud テレメトリの確認、クラウド管理型エンフォースメント（ポリシー、フリート展開、ガードレール判定）の管理、および監査・調査結果・課題・アラート・キー・ユーザー・クエリ・設定の管理を行います。ローカルフック、ポリシー、キャプチャ、マシン登録には [`failproofai`](/ja/reference/failproof-cli) を使用してください。

リリース済みの Cloud CLI を独立したツールとしてインストールします。Python 3.10 以上が必要です。

```bash
uv tool install fp-cloud-cli
fp version
```

ディストリビューション名は `fp-cloud-cli`、インストールされるコマンドは `fp` です。PyPI 上で `fp` がすでに使用されていたため、名前が異なります。

## サインイン

`fp login` はメールで 6 桁のコードを送信し、セッションを保存します。自己署名証明書を使用しているダッシュボードに接続する場合は、ログイン時に `--insecure` を追加してください。

```bash
fp login
fp whoami
```

## 構文

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

グローバルオプションはコマンドの前に指定する必要があります。

```bash
fp --json sessions --since 24h
```

ターミナルヘルプを表示するには `fp COMMAND --help` または `fp COMMAND SUBCOMMAND --help` を実行してください。

### イベント

```text
fp events [OPTIONS]
```

個々のエージェントイベントを一覧表示します。デフォルトの軽量フィードは生のペイロードを除外します。`--full` は範囲を絞った調査にのみ使用してください。

| オプション | 説明 |
| --- | --- |
| `--limit`, `-n <n>` | 取得する最大行数。デフォルト: `50`。 |
| `--since <window>` | `all`、`15m`、`1h`、`6h`、`24h`、または `7d`。 |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC の範囲指定。`--since` より優先されます。 |
| `--env <value>` | 環境フィルター。繰り返し指定またはカンマ区切りで複数指定可能。 |
| `--event-type <value>` | イベントタイプフィルター。繰り返し指定またはカンマ区切りで複数指定可能。 |
| `--agent-id <value>` | エージェントフィルター。繰り返し指定またはカンマ区切りで複数指定可能。 |
| `--session-id <value>` | セッションフィルター。繰り返し指定またはカンマ区切りで複数指定可能。 |
| `--search <text>` | ペイロードのテキスト検索。繰り返し指定可能で、いずれかの語句に一致すればヒット。 |
| `--order asc\|desc` | 時刻順。デフォルト: 新しい順。 |
| `--all` | `--limit` まで自動ページネーション。 |
| `--cursor <token>` | 不透明なカーソルから再開する。 |
| `--page-size <n>` | `--all` 使用時のリクエストあたりの行数。最大 `200`。 |
| `--full` | より重いイベントエンドポイントを通じて生のペイロードを含める。 |
| `--fields <csv>` | 指定したフィールドのみを返す。`payload` を指定するとフルモードが有効になる。 |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` は **`--limit` まで**ページネーションを行います。`--limit` のデフォルトは **50** なので、`--all` 単独では 50 行で停止します。早期に停止した場合、レスポンスには再開用の `next_cursor` が含まれます。`"next_cursor": null` はフィードが完全に消費されたことを意味します。
</Note>

#### 監査の作成オプション

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| オプション | 説明 |
| --- | --- |
| `--file <path>` | JSON で定義を作成するか、stdin には `-` を使用する。明示的なフラグはファイルの値より優先される。 |
| `--description <text>` | 検出したい問題やの目的を記述する。 |
| `--enabled` / `--disabled` | スケジューリングをオン/オフで開始する。デフォルト: 有効。 |
| `--schedule-interval-secs <n>` | `3600`〜`604800`。デフォルト: `86400`。 |
| `--schedule-anchor <timestamp>` | ISO 8601 形式の固定 UTC フェーズ。デフォルト: 次の 09:00 UTC。 |
| `--window-mode since_last\|fixed` | 最後に完全分析されたウィンドウの後から継続するか、ローリングウィンドウを繰り返し検査する。デフォルト: `since_last`。 |
| `--lookback-window-secs <n>` | `3600`〜`7776000`。デフォルト: `604800`。 |
| `--scope '<json>'` | `environments`、`agent_ids`、またはその他のサポートされたスコープフィールドでフィルタリングする。 |
| `--ignore-error-type <type>` | エラータイプを除外する。繰り返し指定またはカンマ区切りで複数指定可能。 |
| `--llm` / `--no-llm` | エージェンティック分析を有効または無効にする。デフォルト: 有効。 |
| `--top-k <n>` | `1`〜`500` 件の調査結果を保持する。デフォルト: `50`。 |
| `--sensitivity low\|medium\|high` | レポートの感度を設定する。デフォルト: `medium`。 |
| `--channels '<json>'` | 通知チャンネルの配列。 |
| `--text <brief>` | インラインブリーフ。最大 8,192 文字。 |
| `--text-file <path>` | ファイルからブリーフを読み込む。`--text` とは排他的。 |
| `--url <https-url>` | 公開 HTTPS 参照を追加する。最大 5 回繰り返し可能。 |

最初の実行にコンテキストが必要な場合は、作成時に含めてください。作成はキューに入れられた実行が始まる前に定義とコンテキストをまとめてコミットします。

<Note>
  `fp audits run` は非同期です。調査結果を読み取る前に、`fp audits runs NAME` をポーリングして最新の実行が成功または失敗するまで待ってください。
</Note>

### ポリシー

クラウド管理型のポリシーバージョン。**セッション専用** — `fp policies test` を除くここでのすべてのコマンドは、API キー下ではリクエストの前に終了コード `2` で終了します。これらは `/v1` から意図的に除外されたルートオンリーの書き込みルートだからです。`fp policies test` は意図的な例外で、`node` に対してローカルで完全に実行され、サーバーとは一切通信しないため、認証要件もキーモードの拒否もなく、ログアウト状態でも API キー下でも動作します。

| コマンド | 目的 | オプション |
| --- | --- | --- |
| `fp policies list` | ポリシーバージョンを一覧表示する。各ポリシーの最新バージョンが先頭。 | — |
| `fp policies show POLICY_ID` | ソースを含む 1 つのポリシーを表示する。 | — |
| `fp policies publish POLICY_ID [SOURCE]` | 新しいバージョンを作成する。既存のものをその場で編集することはない。`SOURCE` はパス、`@path`、または stdin の `-`。省略するとペースト入力になる。 | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | 削除されたすべてのデプロイメントに戻し追加する。それぞれに新しいジェネレーションを作成する。 | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | それを持つすべてのデプロイメントから削除する。それぞれに新しいジェネレーションを作成する。 | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | ポリシーバージョンを削除する。 | `--yes`, `-y` |
| `fp policies test [SOURCE]` | 合成コンテキストに対してポリシーをローカルで実行する。各ポリシーの `match` フィルターを適用するため、指定したイベント/ツールをカバーしないポリシーは実行されず `skipped` として報告される。PATH 上に `node` が必要。 | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | アシスタントでポリシーの草案を作成する。デフォルトでは草案を表示するだけで何もしない。`policies:write` が必要。 | `--out <path>`; `--publish <policy-id>` |

### フリート

どのマシンがどのポリシーを実行するか。**セッション専用** — ここでのすべてのコマンドは例外なく、API キー下では終了コード `2` で終了します。

| コマンド | 目的 | オプション |
| --- | --- | --- |
| `fp fleet list` | 登録済みマシンとそのデプロイメントジェネレーションを一覧表示する。 | — |
| `fp fleet show MACHINE_ID` | マシンが現在実行しているポリシーセットを表示する。 | — |
| `fp fleet deploy MACHINE_ID` | マシンが適用するものを変更する。最初に完全な結果セットを表示し、`--json` なしのインタラクティブターミナルでのみ確認を求める。 | `--add`; `--remove`; `--set`; `--create`; `--yes`, `-y` |
| `fp fleet diff [MACHINE_ID]` | 意図と実際の差分 — マシンが実行するよう指示されていることと最後にプルしたものの比較。ID を省略するとフリート全体を対象にする。 | — |
| `fp fleet history MACHINE_ID` | マシンのすべてのジェネレーション。新しい順。 | — |
| `fp fleet rollback MACHINE_ID GENERATION` | 過去のジェネレーションのポリシーセットを復元する。ジェネレーション番号は `fp fleet history MACHINE_ID` から取得する。 | `--yes`, `-y` |
| `fp fleet rename MACHINE_ID LABEL` | マシンに読みやすいラベルを付ける。ID 自体は変更されない。 | — |

```bash
fp fleet history ci-runner-01
fp fleet rollback ci-runner-01 3
fp fleet rename ci-runner-01 "CI runner (eu-west)"
```

#### ポリシー参照

`--add` と `--set` はベア ID ではなくポリシー参照を取ります。

| 形式 | 意味 |
| --- | --- |
| `id` | 現在のバージョン、現在のエフェクト |
| `id@3` | バージョン 3、現在のエフェクト |
| `id:observe` | 現在のバージョン、記録のみで適用なし |
| `id@3:observe` | バージョン 3、記録のみで適用なし |

エフェクトは `enforce` または `observe` です。解決順序: 明示的なエフェクトが優先される。次に、そのポリシーに対してすでにデプロイされているエフェクト。次に、`enforce`。

<Warning>
  ベアの `--add` は**即座に適用されます**。`fp fleet deploy ci-runner-01 --add checkout-guard` は、次にプルされた時点からそのマシンでブロックが開始されます。シャドウロールアウトにするには `:observe` が必要です。

  ```bash
  fp fleet deploy ci-runner-01 --add checkout-guard:observe   # records only
  fp fleet deploy ci-runner-01 --add checkout-guard           # enforces now
  ```

  observe はオフではありません。ポリシーは適用中のものと同じ 10 秒のタイムアウトと同じエラーハンドリングで実際に評価され、allow 以外のすべての判定が記録されます — 適用のみが保留されます。これが測定結果を読む価値のあるものにしています。
</Warning>

#### デルタ、置き換え、競合

`--add` と `--remove` はマシンの現在のセットを読み込んでデルタを適用するため、指定しなかったものは変更されません。ベアの `--add` でマシンがすでに実行しているポリシーを指定した場合、固定されたバージョンがそのまま保持され、暗黙的にアップグレードされることはありません。移動するには `id@version` を指定してください。

`--set` はすべてを置き換え、指定しなかったポリシーを削除する唯一の方法です。`--add` や `--remove` と組み合わせることはできません。3 つのどれも指定しないとエラーになります（no-op にはなりません）。

```bash
fp fleet deploy ci-runner-01 --add prod-guard@1:observe --remove old-rule
fp fleet deploy ci-runner-01 --set no-force-push --set no-secret-echo
```

書き込みはすべてのパスで完全な置き換えになります。エンドポイントはポリシーセット全体を受け取るためです。サーバー側のロックはないため、CLI は読み取ったジェネレーションを記録し、結果がちょうど 1 つ上でなければ拒否します — これは間に誰かがデプロイしたことを意味し、置き換えはマージしません。`fp fleet show` で再読み込みしてから再度デプロイしてください。

`--create` は、まだチェックインしていないマシン ID に対してデプロイします（事前ステージング用）。これなしでは、サーバーが知らない ID は拒否されます。タイポがあると誰も所有せず誰もポリシーを収集しないマシンが作成されてしまうためです。

### ガードレール

エンフォースメントが実際に行ったこと。**セッション専用** — 上記と同じ理由。

| コマンド | 目的 | オプション |
| --- | --- | --- |
| `fp guardrails summary` | カバレッジ、ブロック済み/評価済みの合計、deny のスパークライン、ポリシーごとのテーブルを表示する。 | `--since`（`1h`、`6h`、`24h`、`7d`）; `--machine` |
| `fp guardrails timeline` | ウィンドウ全体で集計された、すべてのポリシーソースにわたる決定のバケット表示。 | `--since`（`1h`、`6h`、`24h`、`7d`）; `--machine` |

サマリーの `(no policy)` 行はギャップではなく正常です。ほとんどの評価は誰も異議を唱えない allow であり、この行によって画面上に分母が表示されます。

### 誰も困らせずにポリシーをロールアウトする

上記の 3 つのグループは 1 つのシーケンスです。ローカルで検討し、公開し、シャドウし、測定し、それから適用します。

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

| ステップ | 目的 |
| --- | --- |
| `fp policies test` | サーバーも認証も不要。実際のファイルを説明したコンテキストに対して実行し、登録済みポリシーごとに allow、deny、または instruct を表示する。`--expect` はこれを CI アサーションに変える。 |
| `fp policies publish` | 新しい不変バージョンを作成する。既存のものをその場で編集することはない。 |
| `fp fleet deploy --add <id>:observe` | シャドウロールアウト。**`:observe` はここでは省略不可** — ベアの `--add` はマシンがプルした瞬間に適用される。 |
| `fp guardrails summary` | 安全でないマッチと、ポリシーがブロックしてしまう正当な作業を区別する。 |
| `fp fleet deploy --add <id>:enforce` | 記録された判定が期待通りになったら昇格する。 |
| `fp fleet rollback <machine> <generation>` | 適用後に問題が発生した場合の戻り方。 |

Cloud を介さない単一マシン相当の操作は、`failproofai publish --effect observe` でパックを公開し、[ローカルダッシュボード](/ja/reference/local-dashboard)で記録された判定を読むことです。

## グローバルフラグ

| フラグ | 説明 |
| --- | --- |
| `--json` | マシン可読な JSON を出力する。 |
| `--base-url <url>` | セルフホストまたは開発用ダッシュボードを使用する。 |
| `--org <slug>` | この実行の組織を選択する。 |
| `--token <token>` | 保存されたユーザーセッショントークンを上書きする。 |
| `--api-key <key>` | API キーで自動化を認証する。保存されない。 |
| `--timeout <seconds>` | HTTP タイムアウト。正の値でなければならない。デフォルト: `30`。 |
| `--quiet`, `-q` | stderr のステータス出力を抑制する。 |
| `--no-color` | カラー出力を無効にする。 |
| `--insecure` / `--secure` | TLS 証明書検証を無効または復元する。 |
| `--version` | バージョンを表示して終了する。 |
| `--help`, `-h` | ヘルプを表示する。 |

`--api-key` は自動化を目的としています。ログイン、組織の切り替え、アシスタントコマンドにはユーザーセッションが必要です。

## 環境変数

| 変数 | 対応するフラグまたは目的 |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | CLI 設定ディレクトリを変更する（デフォルト: `~/.failproofai/fpcli`）。 |
| `FP_ANALYTICS_DISABLED` または `DO_NOT_TRACK` | 匿名の CLI アナリティクスを無効にする。 |
| `NO_COLOR` | カラー出力を無効にする。 |

明示的なフラグが環境変数より優先され、環境変数は保存された設定より優先されます。

API キーモードでは、人間による `fp login` で保存された組織は**無視されます** — 単に上書きされるのではありません。明示的な `--org` または `FP_ORG` のみが送信されます。保存されたログインからは何も継承されないため、キーが複数の組織に対して操作できる場合は `--org` を渡してください。省略してもエラーにはなりません。`--org` なしのインスタンススコープのキーはサーバー側で**デフォルト**組織に解決され、そのデータが返されます。エラーは一切表示されません。最初に `fp whoami` を実行して、キーが実際にどのテナントと通信しているかを確認してください。

<Warning>
  これらの `AGENTEYE_*` 形式は **`fp` では読み込まれません** — 以前もそうでした。CLI は `FP_*` を宣言しており（`fp_cli/app.py`）、未知の変数はエラーになりません。`AGENTEYE_DASHBOARD_URL` を設定しても CLI のターゲットは変わらず、無視されて保存されたダッシュボードに対してコマンドが実行されます。

  `AGENTEYE_HOME` と `AGENTEYE_ENVIRONMENT` は引き続き存在しますが、それらはこの CLI ではなく**コレクターとテレメトリ SDK** に属しています。
</Warning>

<Warning>
  削除、失効、抑制、解決、または設定の置き換えを行うコマンドはデフォルトでプロンプトが表示されます。`--yes` は、アクティブな組織とターゲットを確認した後にのみ使用してください。
</Warning>
