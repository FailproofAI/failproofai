Cloud のテレメトリ確認、クラウド管理型エンフォースメント（ポリシー、フリートデプロイ、ガードレール決定）の管理、監査、発見事項、イシュー、アラート、キー、ユーザー、クエリ、設定の管理には `fp` を使用してください。ローカルフック、ポリシー、キャプチャ、マシン登録には [`failproofai`](/ja/reference/failproof-cli) を使用してください。

ホスト型コードのオーサリングとデプロイ、LLM ジャッジおよび Jev エバリュエーターの管理、ダッシュボードの管理、センチメントの確認、ターミナルからのダッシュボードアシスタントの利用も可能です。

リリース済みの Cloud CLI を独立したツールとしてインストールします：

```bash
uv tool install fp-cloud-cli
fp version
```

## サインイン

```bash
fp login
fp whoami
```

## 構文

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

グローバルオプションはコマンドの前に指定する必要があります：

```bash
fp --json sessions --since 24h
```

ターミナルヘルプを表示するには `fp COMMAND --help` または `fp COMMAND SUBCOMMAND --help` を実行してください。

## CLI コマンド

### エバリュエーターのオーサリング

`fp evaluators` は定義をオーサリングし、`fp evals` は結果を読み取ります。有効なマネージドインスタンスが必要です（`fp evaluators instances`）。オーサリングには `evaluations:trigger` が必要で、セッションドライランとスキーマプロファイリングには `events:read` も必要です。

コードは制限された Python 式を 1 つ記述します。次の内容を `error_free.py` として保存してください：

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM ジャッジ：

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev バイナリおよびグレード付きルーブリック：

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
作成するとエバリュエーターが有効になります。デプロイすると新しいイミュータブルバージョンが作成され、それより古い有効バージョンが無効になります。後続処理が失敗した場合、新しいバージョンは公開されたままになります。再試行前に `evaluators list --all` で確認してください。
ジャッジのドライランは Cloud によって拒否されます。Jev のドライランはモデルの予算を消費します。
バックフィルはコード、ジャッジ、Jev エバリュエーターに対応し、最大 90 日間を受け付けます。エバリュエーターがまだスコアリングしていないセッションのみをキューに追加します。ジャッジと Jev のバックフィルはモデル予算を消費するため、最初に `fp evaluators backfill --dry-run` を実行してください。
人間向け出力は、作成/デプロイ前にセッションごとのドライラン結果を表示します。
プレビューが失敗した場合、明示的に `--force` を渡さない限り書き込みは停止します。
</Warning>

AI ドラフティングには `fp login` が必要で、create/deploy が受け付けるスペックを出力します：

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# ドラフトの key、source、condition を有効化前に確認してください。
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| コマンド | オプション / 動作 |
| --- | --- |
| `fp evaluators list` | `--key`、`--all` |
| `fp evaluators show KEY[@VERSION]` | ソース/エンベロープ全体 |
| `fp evaluators create` | `--key`、`--name`、`--version`、繰り返し可能な `--label`、`--condition EXPR\|@file`、ソース 1 つ、繰り返し可能な `--dry-run-on`、`--disabled`、失敗プレビュー時の明示的 `--force` |
| `fp evaluators deploy KEY` | 同じソースフラグ；`--version`、`--backfill 7d`（任意の種類、1〜90 日）、`--force`；数値バージョンは自動インクリメント；KEY はスペックファイルの `eval_key` が欠落している場合に補完 |
| `fp evaluators draft "intent"` | セッション；`--kind code\|judge\|jev`、`--out` |
| `fp evaluators dry-run` | ソースフラグまたは `--file`、繰り返し可能な `--session`（最大 10 件）；なし = コンパイルのみ |
| `fp evaluators enable\|disable KEY[@VERSION]` | 切り替え |
| `fp evaluators label KEY[@VERSION]` | 繰り返し可能な `--add`、`--remove` |
| `fp evaluators instances\|schema\|jobs` | マネージドフリート/スキーマ/ジョブの確認 |
| `fp evaluators backfill` | `--from`、`--to`、`--key`、`--dry-run`；コード、ジャッジ、Jev |

コードフラグは `--code FILE|-`、`--result-kind score|metric|assertion`、`--timeout S` です。ジャッジフラグは `--judge --criteria TEXT`、繰り返し可能な `--step`、`--threshold` です。Jev フラグは `--jev noul --instructions --true --false` または `--jev score --instructions` と 3〜5 個の異なる `--level` 値（最悪のものを最初に）です。
ジャッジ/Jev はスコアが必要で、しきい値は 0〜1 の範囲です。バイナリジャッジのステップは拒否されます。

スペックファイルには `eval_key`、`display_name`、`eval_version`、`result_kind`、`labels`、`condition_source`、`evaluator_source`、`timeout_seconds` のみを含めてください。
ジャッジ/Jev の `evaluator_source` は JSON エンベロープ文字列です。行 ID、有効状態、AI 推論メタデータは含めないでください。`--file` と個別スペックフラグは排他的です。deploy はファイルのバージョンを上書きできます。出力ファイルは上書きされません。

### 新しいダッシュボードコントロール

すべてのコマンドはグローバル `--json` を受け付けます。未知のルートの 404 はコード 6 で終了し「not available on this FailproofAI Cloud yet」と表示されます。レコード未発見の 404 もコード 6 で終了しますが、レコードが見つからなかった旨を報告します。セッション専用コマンドは HTTP 前にキーモードを拒否します（終了コード 2）。

人間向けコマンドはサマリーとテーブルを使用します。生の JSON エクスポートにはグローバル `--json` を渡すか `--out FILE` で保存してください。それ以外の場合、セッションと JSON クエリのエクスポートは読みやすいビューを表示します。CSV エクスポートはパイプ処理用にプレーンな CSV のままです。

| コマンド | オプション / 備考 |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | create の `--name`、`--description`、`--file` 定義；update は言及されていないフィールドを保持 |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | add の `--query ID --chart TYPE --title`；config/geometry または `--file` によるレイアウト |
| `fp sessions show\|export\|history\|re-evaluate ID` | export の `--out`；history は評価履歴 |
| `fp sessions import FILE...` | Claude Code トランスクリプト、Codex ロールアウト、またはイベント JSONL（`.gz` 可）；`--format auto\|failproofai\|claude\|codex`、`--env`、`--dry-run`；`events:add` が必要 |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`；list の `--limit`；messages の `--session-id` |
| `fp query compose "question"` | セッション；`--run` |
| `fp query export [ID]` | または `--sql`；`--format csv\|json`、`--out` |
| `fp alerts recipients` / `fp alerts issues ID` | イシューに `--create --title --summary` または `--create --file` を使用可能 |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`、`--body TEXT\|@file`、`--file` JSON；update の `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | セッション；組織のイベントからポリシーをドラフト、公開はしない |
| `fp policies backtest [FILE_OR_ID]` | セッション；regex はモジュールをリプレイ；`jev`/`both`（公開済み、または `--semantic checks.json`）は無料で推定、`--run [--sample N]` は Jev アロワンスを消費；`--kind`、`--hours`、`--agent-id`、`--env` |
| `fp policies candidacy --issue ID` | セッション；ポリシーがこのイシューを防げるかどうかを確認 |
| `fp issues facets` | 受信トレイフィルターが取れる値とその件数 |
| `fp agent brief` | セッション；`--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | セッション；省略された slug を導出、org を切り替えない |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | パーミッションセット；create の `--name --permission`；update は `--permission` で置換または `--add/--remove` でマージ；`--description`、`--file` |
| `fp users delete ID` / `fp users defaults` | ID による削除 |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` は API キーが必要；plan（オファーとトライアル）と claim はサインイン済みセッションが必要 |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0〜1,000,000 トークン |
| `fp otel status\|enable\|disable` | Cloud org のインジェストスイッチ（ローカルキャプチャではない） |
| `fp slack status\|disconnect` | セッション |

`fp agent ask` は `queries:run` を通じてアーティファクト SQL をテーブル/統計としてレンダリングします。
書き込み承認はターミナルで提案された変更を表示してプロンプトを出します。スクリプトと `--json` は `--approve` が明示的に指定されていない限り拒否します。アーティファクトが返されない場合、既存の JSON の形状は変更されません。

```bash
fp login
fp login --email you@example.com --org reliability-team
fp whoami
```

ターミナルでは `fp login` がリンクを表示します。ブラウザまたは SSO でサインインするためのリンクで、自動的に開きます（SSH 経由またはディスプレイがない場合はリンクの表示のみで、任意のデバイスから利用できます）。認証するとターミナルが自動的に完了します。そのターミナルはセッションが期限切れになるまで、すべての組織でアクセス権を持ちます。自分がリクエストしたリンクのみ認証してください。ログインが異なるネットワークで開始された場合、セッションが作成されるとメールが届き、デプロイメントが判断できる範囲でページに警告が表示されます。**Tab** キーを押すとメールでの 6 桁コード入力に切り替わり、もう一度 Tab を押すと戻ります。`--email`、`--json`、ターミナルなしの場合はコード方式を使用します。

### イベント

```text
fp events [OPTIONS]
```

個別のエージェントイベントを一覧表示します。デフォルトのライトフィードは生ペイロードを除外します。`--full` は範囲を限定した調査にのみ使用してください。

| オプション | 説明 |
| --- | --- |
| `--limit`、`-n <n>` | 最大合計行数。デフォルト：`50`。 |
| `--since <window>` | `all`、`15m`、`1h`、`6h`、`24h`、または `7d`。 |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC 範囲；`--since` より優先。 |
| `--env <value>` | 環境フィルター；値を繰り返すかカンマ区切りで指定。 |
| `--event-type <value>` | イベントタイプフィルター；値を繰り返すかカンマ区切りで指定。 |
| `--agent-id <value>` | エージェントフィルター；値を繰り返すかカンマ区切りで指定。 |
| `--session-id <value>` | セッションフィルター；値を繰り返すかカンマ区切りで指定。 |
| `--search <text>` | ペイロードテキスト検索；繰り返し可能で、いずれかの語句が一致。 |
| `--order asc\|desc` | 時間順。デフォルト：新しい順。 |
| `--all` | `--limit` まで自動ページネーション。 |
| `--cursor <token>` | 不透明なカーソルから再開。 |
| `--page-size <n>` | `--all` 使用時のリクエストあたりの行数；最大 `200`。 |
| `--full` | 重いイベントエンドポイントを通じて生ペイロードを含める。 |
| `--fields <csv>` | 選択したフィールドのみ返す；`payload` をリクエストするとフルモードが有効になる。 |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` は **`--limit` まで**ページネーションを行い、デフォルトは **50** です。つまり `--all` 単体では 50 行で停止します。早期に停止した場合、レスポンスには続きを取得するための `next_cursor` が含まれます。`"next_cursor": null` はフィードが本当に終端に達したことを意味します。
</Note>

#### 監査作成オプション

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| オプション | 説明 |
| --- | --- |
| `--file <path>` | JSON を元に定義を作成、または stdin に `-` を使用。明示的なフラグはファイルの値を上書き。 |
| `--description <text>` | 失敗に関する問いや目的を記述。 |
| `--enabled` / `--disabled` | スケジューリングのオン/オフから開始。デフォルト：有効。 |
| `--schedule-interval-secs <n>` | `3600`〜`604800`。デフォルト：`86400`。 |
| `--schedule-anchor <timestamp>` | ISO 8601 形式の固定 UTC フェーズ。デフォルト：次の 09:00 UTC。 |
| `--window-mode since_last\|fixed` | 最後に完全解析したウィンドウ以降を継続、またはローリングウィンドウを繰り返し検査。デフォルト：`since_last`。 |
| `--lookback-window-secs <n>` | `3600`〜`7776000`。デフォルト：`604800`。 |
| `--scope '<json>'` | `environments`、`agent_ids`、またはその他のサポートされているスコープフィールドでフィルター。 |
| `--ignore-error-type <type>` | エラータイプを除外；繰り返すかカンマ区切りで指定。 |
| `--llm` / `--no-llm` | エージェンティック分析の有効/無効。デフォルト：有効。 |
| `--top-k <n>` | `1`〜`500` 件の発見事項を保持。デフォルト：`50`。 |
| `--sensitivity low\|medium\|high` | レポートの感度を設定。デフォルト：`medium`。 |
| `--channels '<json>'` | 通知チャンネルの配列。 |
| `--text <brief>` | インラインブリーフ、最大 8,192 文字。 |
| `--text-file <path>` | ファイルからブリーフを読み込む；`--text` とは相互排他。 |
| `--url <https-url>` | 公開 HTTPS リファレンスを追加；最大 5 回繰り返し可能。 |

最初の実行にコンテキストが必要な場合は、作成時に含めてください。作成は、キューに追加された実行が開始される前に定義とコンテキストをまとめてコミットします。

<Note>
  `fp audits run` は非同期です。発見事項を読む前に、`fp audits runs NAME` で最新の実行が成功または失敗するまでポーリングしてください。
</Note>

### ポリシー

クラウド管理型のポリシーバージョン。**セッション専用** — API キーでは HTTP リクエスト前にすべてのコマンドが `2` で終了します。これらは `/v1` から意図的に除外されたルート限定の書き込みルートであるためです。

| コマンド | 目的 | オプション |
| --- | --- | --- |
| `fp policies list` | ポリシーバージョンを一覧表示。各バージョンの種類（`regex`、`jev`、`both`）と Jev チェック名を含む。 | `--json` |
| `fp policies show POLICY_ID` | 1 つのポリシーとそのソースおよび Jev チェックを表示。 | — |
| `fp policies publish NAME [PATH]` | バージョンを発行：JavaScript（`regex`、デフォルト）、JSON ファイルからの Jev チェック（`jev`）、またはその両方（JavaScript が自身のチェックによってレビュー可能）。 | `--kind`；`--source`；`--semantic`；`--description`；`--no-verify` |
| `fp policies enable POLICY_ID` | 削除されたすべてのデプロイメントに再追加し、それぞれに新しいジェネレーションを発行。 | `--yes`、`-y` |
| `fp policies disable POLICY_ID` | それを含むすべてのデプロイメントから削除し、それぞれに新しいジェネレーションを発行。 | `--yes`、`-y` |
| `fp policies delete POLICY_ID` | ポリシーバージョンを削除。 | `--yes`、`-y` |
| `fp policies test PATH` | 合成コンテキストに対してポリシーをローカルで実行。各ポリシーの `match` フィルターを適用するため、指定されたイベント/ツールをカバーしないものは実行されずに `skipped` として報告。 | `--event`；`--tool`；`--command`；`--file`；`--expect` |
| `fp policies compose PROMPT` | アシスタントでポリシーをドラフト。`policies:write` が必要。 | — |

## グローバルフラグ

| フラグ | 説明 |
| --- | --- |
| `--json` | 機械可読 JSON を出力。エラーには失敗したリクエストの `request_id` が含まれる。 |
| `--base-url <url>` | セルフホストまたは開発ダッシュボードを使用。 |
| `--org <slug>` | この呼び出しの組織を選択。 |
| `--token <token>` | 保存されたユーザーセッショントークンを上書き。 |
| `--api-key <key>` | API キーで自動化を認証；保存されない。 |
| `--timeout <seconds>` | HTTP タイムアウト；正の値である必要がある。デフォルト：`30`。 |
| `--quiet`、`-q` | stderr への状態出力を抑制。 |
| `--no-color` | カラー出力を無効化。 |
| `--insecure` / `--secure` | TLS 証明書検証を無効化または復元。 |
| `--version` | バージョンを表示して終了。 |
| `--help`、`-h` | ヘルプを表示。 |

`--api-key` は自動化用途を想定しています。ログイン、組織の切り替え、アシスタントコマンドにはユーザーセッションが必要です。

</Warning>
