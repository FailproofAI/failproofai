`fp` を使用して、クラウドのテレメトリーの確認、クラウド管理のエンフォースメント（ポリシー、フリートデプロイ、ガードレールの判定）の管理、および監査・所見・課題・アラート・キー・ユーザー・クエリ・設定の管理を行います。ローカルフック、ポリシー、キャプチャ、マシン登録には [`failproofai`](/ja/reference/failproof-cli) を使用してください。

ホスト型コードや LLM ジャッジ、Jev エバリュエーターの作成・デプロイ、ダッシュボードの管理、センチメントの確認、ターミナルからのダッシュボードアシスタントの利用も可能です。

リリース済みの Cloud CLI を独立したツールとしてインストールします：

```bash
uv tool install fp-cloud-cli
fp version
```

## サインイン

```bash
fp login
fp whoami
```

## 構文

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

グローバルオプションはコマンドの前に指定する必要があります：

```bash
fp --json sessions --since 24h
```

ターミナルヘルプを表示するには `fp COMMAND --help` または `fp COMMAND SUBCOMMAND --help` を実行してください。

## CLI コマンド

### エバリュエーターの作成

`fp evaluators` は定義を作成し、`fp evals` は結果を読み取ります。有効なマネージドインスタンスが必要です（`fp evaluators instances`）。作成には `evaluations:trigger` が必要で、セッションのドライランとスキーマプロファイリングには `events:read` も必要です。

コードは制限付き Python 式 1 つです。以下を `error_free.py` として保存してください：

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM ジャッジ：

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev バイナリおよび段階的ルーブリック：

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
作成するとエバリュエーターが有効になります。デプロイすると新しい不変バージョンが作成され、古い有効バージョンが無効になります。後続の操作が失敗した場合、新しいバージョンは公開されたままになります。再試行前に `evaluators list --all` で確認してください。
ジャッジのドライランは Cloud によって拒否されます。Jev のドライランはモデルバジェットを消費します。
バックフィルはコード・ジャッジ・Jev エバリュエーターに対応し、最大 90 日まで受け付けます。エバリュエーターがまだスコアリングしていないセッションのみをキューに入れます。ジャッジおよび Jev のバックフィルはモデルバジェットを消費するため、先に `fp evaluators backfill --dry-run` を実行してください。
人間向けの出力では、作成・デプロイ前にセッションごとのドライラン結果が表示されます。
プレビューが失敗した場合、`--force` を明示的に指定しない限り書き込みは停止されます。
</Warning>

AI による下書きには `fp login` が必要で、create/deploy が受け付けるスペックを書き出します：

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# 有効化する前に下書きのキー、ソース、条件を確認してください。
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| コマンド | オプション / 動作 |
| --- | --- |
| `fp evaluators list` | `--key`、`--all` |
| `fp evaluators show KEY[@VERSION]` | ソース・エンベロープの詳細 |
| `fp evaluators create` | `--key`、`--name`、`--version`、繰り返し可能な `--label`、`--condition EXPR\|@file`、ソース 1 つ、繰り返し可能な `--dry-run-on`、`--disabled`、失敗したプレビューには明示的な `--force` |
| `fp evaluators deploy KEY` | 同じソースフラグ；`--version`、`--backfill 7d`（任意の種類、1〜90 日）、`--force`；数値バージョンは自動インクリメント；KEY はスペックファイルの欠落した `eval_key` を補完 |
| `fp evaluators draft "intent"` | セッション；`--kind code\|judge\|jev`、`--out` |
| `fp evaluators dry-run` | ソースフラグまたは `--file`、繰り返し可能な `--session`（最大 10）；なし = コンパイルのみ |
| `fp evaluators enable\|disable KEY[@VERSION]` | 切り替え |
| `fp evaluators label KEY[@VERSION]` | 繰り返し可能な `--add`、`--remove` |
| `fp evaluators instances\|schema\|jobs` | マネージドフリート・スキーマ・ジョブの確認 |
| `fp evaluators backfill` | `--from`、`--to`、`--key`、`--dry-run`；コード・ジャッジ・Jev |

コードフラグは `--code FILE|-`、`--result-kind score|metric|assertion`、`--timeout S` です。ジャッジフラグは `--judge --criteria TEXT`、繰り返し可能な `--step`、`--threshold` です。Jev フラグは `--jev noul --instructions --true --false` または `--jev score --instructions` に 3〜5 つの異なる `--level` 値（最低を先頭）を組み合わせます。ジャッジ/Jev にはスコアが必要で、しきい値は 0〜1 です。バイナリジャッジのステップは拒否されます。

スペックファイルには `eval_key`、`display_name`、`eval_version`、`result_kind`、`labels`、`condition_source`、`evaluator_source`、`timeout_seconds` のみを含めます。ジャッジ/Jev の `evaluator_source` は JSON エンベロープ文字列です。行 ID、有効状態、AI 推論メタデータは含めないでください。`--file` と個別のスペックフラグは排他的です。デプロイはファイルのバージョンを上書きできます。出力ファイルは上書きされません。

### 新しいダッシュボードコントロール

すべてのコマンドはグローバル `--json` を受け付けます。不明なルートの 404 はコード 6 で終了し「not available on this FailproofAI Cloud yet」と表示されます。レコードが見つからない 404 もコード 6 で終了しますが、レコードが見つからなかった旨を報告します。セッション専用コマンドは HTTP より前（終了コード 2）にキーモードを拒否します。

人間向けコマンドはサマリーとテーブルを使用します。生の JSON エクスポートにはグローバル `--json` を渡すか `--out FILE` で保存してください。それ以外の場合、セッションおよび JSON クエリのエクスポートは読みやすい形式で表示されます。CSV エクスポートはパイプ処理のためプレーンな CSV のまま出力されます。

| コマンド | オプション / 備考 |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | 作成は `--name`、`--description`、`--file` 定義；更新は未指定のフィールドを保持 |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | 追加は `--query ID --chart TYPE --title`；設定・ジオメトリまたはレイアウトは `--file` で指定 |
| `fp sessions show\|export\|history\|re-evaluate ID` | エクスポートは `--out`；history は評価履歴 |
| `fp sessions import FILE...` | Claude Code トランスクリプト、Codex ロールアウト、またはイベント JSONL（`.gz` も可）；`--format auto\|failproofai\|claude\|codex`、`--env`、`--dry-run`；`events:add` が必要 |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`；一覧は `--limit`；messages は `--session-id` |
| `fp query compose "question"` | セッション；`--run` |
| `fp query export [ID]` | または `--sql`；`--format csv\|json`、`--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Issues は `--create --title --summary` または `--create --file` が可能 |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`、`--body TEXT\|@file`、`--file` JSON；更新は `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | セッション；組織のイベントからポリシーを下書き、公開はしない |
| `fp policies backtest [FILE_OR_ID]` | セッション；regex はモジュールを再生；`jev`/`both`（公開済み、または `--semantic checks.json`）は無料で推定、`--run [--sample N]` は Jev allowance を消費；`--kind`、`--hours`、`--agent-id`、`--env` |
| `fp policies candidacy --issue ID` | セッション；ポリシーでこの課題を防げるかを判定 |
| `fp issues facets` | 受信箱フィルターが取り得る値とその件数 |
| `fp agent brief` | セッション；`--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | セッション；省略された slug を導出、組織の切り替えは行わない |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | 権限セット；作成は `--name --permission`；更新は `--permission` で置換または `--add/--remove` でマージ；`--description`、`--file` |
| `fp users delete ID` / `fp users defaults` | ID による削除 |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` は API キーが必要；plan（オファーとトライアル）および claim はサインイン済みセッションが必要 |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0〜1,000,000 トークン |
| `fp otel status\|enable\|disable` | クラウド組織のインジェストスイッチ（ローカルキャプチャではない） |
| `fp slack status\|disconnect` | セッション |

`fp agent ask` はアーティファクト SQL を `queries:run` 経由でテーブル・統計として表示します。書き込みの承認では、提案された変更が表示され、インタラクティブターミナルでプロンプトが表示されます。スクリプトと `--json` は `--approve` を明示しない限り拒否されます。アーティファクトが返されない場合、既存の JSON の形状は変更されません。

### イベント

```text
fp events [OPTIONS]
```

個々のエージェントイベントを一覧表示します。デフォルトの軽量フィードは生のペイロードを除外します。`--full` は範囲を限定した調査にのみ使用してください。

| オプション | 説明 |
| --- | --- |
| `--limit`、`-n <n>` | 最大合計行数。デフォルト：`50`。 |
| `--since <window>` | `all`、`15m`、`1h`、`6h`、`24h`、または `7d`。 |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC 範囲；`--since` を上書きします。 |
| `--env <value>` | 環境フィルター；繰り返しまたはカンマ区切りで指定。 |
| `--event-type <value>` | イベントタイプフィルター；繰り返しまたはカンマ区切りで指定。 |
| `--agent-id <value>` | エージェントフィルター；繰り返しまたはカンマ区切りで指定。 |
| `--session-id <value>` | セッションフィルター；繰り返しまたはカンマ区切りで指定。 |
| `--search <text>` | ペイロードテキスト検索；繰り返し可能、いずれかの語句に一致。 |
| `--order asc\|desc` | 時刻順。デフォルト：新しい順。 |
| `--all` | `--limit` まで自動ページネーション。 |
| `--cursor <token>` | 不透明なカーソルから再開。 |
| `--page-size <n>` | `--all` 使用時のリクエストあたりの行数；最大 `200`。 |
| `--full` | 重いイベントエンドポイント経由で生のペイロードを含める。 |
| `--fields <csv>` | 選択したフィールドのみを返す；`payload` を指定すると full モードが有効になります。 |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` は **`--limit` まで**ページネーションします。`--limit` のデフォルトは **50** です。そのため `--all` 単体では 50 行で停止します。途中で停止した場合、レスポンスには再開用の `next_cursor` が含まれます。`"next_cursor": null` はフィードが本当に終了したことを意味します。
</Note>

#### 監査作成オプション

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| オプション | 説明 |
| --- | --- |
| `--file <path>` | JSON を基に定義を作成。stdin には `-` を使用。明示的なフラグはファイルの値を上書き。 |
| `--description <text>` | 障害の問いや目的を記述。 |
| `--enabled` / `--disabled` | スケジューリングをオンまたはオフで開始。デフォルト：有効。 |
| `--schedule-interval-secs <n>` | `3600`〜`604800`。デフォルト：`86400`。 |
| `--schedule-anchor <timestamp>` | ISO 8601 形式の固定 UTC フェーズ。デフォルト：次の 09:00 UTC。 |
| `--window-mode since_last\|fixed` | 最後に完全に分析したウィンドウの後から継続するか、ローリングウィンドウを繰り返し検査するか。デフォルト：`since_last`。 |
| `--lookback-window-secs <n>` | `3600`〜`7776000`。デフォルト：`604800`。 |
| `--scope '<json>'` | `environments`、`agent_ids`、またはその他のサポートされているスコープフィールドでフィルター。 |
| `--ignore-error-type <type>` | エラータイプを除外；繰り返しまたはカンマ区切りで指定。 |
| `--llm` / `--no-llm` | エージェンティック分析を有効または無効化。デフォルト：有効。 |
| `--top-k <n>` | `1`〜`500` の所見を保持。デフォルト：`50`。 |
| `--sensitivity low\|medium\|high` | レポートの感度を設定。デフォルト：`medium`。 |
| `--channels '<json>'` | 通知チャネルの配列。 |
| `--text <brief>` | インラインブリーフ、最大 8,192 文字。 |
| `--text-file <path>` | ファイルからブリーフを読み込む；`--text` とは排他的。 |
| `--url <https-url>` | 公開 HTTPS 参照を追加；最大 5 回繰り返し可能。 |

最初の実行にコンテキストが必要な場合は、作成時に含めてください。作成はキューに入れられた実行が始まる前に、定義とコンテキストを同時にコミットします。

<Note>
  `fp audits run` は非同期です。所見を読み取る前に、`fp audits runs NAME` をポーリングして最新の実行が成功または失敗するまで待ってください。
</Note>

### ポリシー

クラウド管理のポリシーバージョン。**セッション専用** — API キー使用時はすべてのコマンドがリクエスト前にコード `2` で終了します。これらは `/v1` に意図的に存在しないルート専用の書き込みルートであるためです。

| コマンド | 目的 | オプション |
| --- | --- | --- |
| `fp policies list` | ポリシーバージョンを一覧表示。種類（`regex`、`jev`、`both`）と Jev チェック名も表示。 | `--json` |
| `fp policies show POLICY_ID` | 1 つのポリシーをソースと Jev チェックとともに表示。 | — |
| `fp policies publish NAME [PATH]` | バージョンを発行：JavaScript（`regex`、デフォルト）、宣言の JSON ファイルからの Jev チェック（`jev`）、または両方（`both`、JavaScript は独自のチェックでレビュー可能）。 | `--kind`；`--source`；`--semantic`；`--description`；`--no-verify` |
| `fp policies enable POLICY_ID` | 削除されたすべてのデプロイに戻し、それぞれに新しいジェネレーションを発行。 | `--yes`、`-y` |
| `fp policies disable POLICY_ID` | それを含むすべてのデプロイから削除し、それぞれに新しいジェネレーションを発行。 | `--yes`、`-y` |
| `fp policies delete POLICY_ID` | ポリシーバージョンを削除。 | `--yes`、`-y` |
| `fp policies test PATH` | 合成コンテキストに対してポリシーをローカルで実行。各ポリシーの `match` フィルターを適用するため、指定したイベント・ツールをカバーしないものは実行せず `skipped` と報告。 | `--event`；`--tool`；`--command`；`--file`；`--expect` |
| `fp policies compose PROMPT` | アシスタントでポリシーを下書き。`policies:write` が必要。 | — |

## グローバルフラグ

| フラグ | 説明 |
| --- | --- |
| `--json` | 機械可読な JSON を出力。エラーには失敗したリクエストの `request_id` が含まれます。 |
| `--base-url <url>` | セルフホストまたは開発ダッシュボードを使用。 |
| `--org <slug>` | この呼び出しの組織を選択。 |
| `--token <token>` | 保存されたユーザーセッショントークンを上書き。 |
| `--api-key <key>` | API キーで自動化を認証；保存されません。 |
| `--timeout <seconds>` | HTTP タイムアウト；正の値である必要があります。デフォルト：`30`。 |
| `--quiet`、`-q` | stderr のステータス出力を抑制。 |
| `--no-color` | カラー出力を無効化。 |
| `--insecure` / `--secure` | TLS 証明書の検証を無効化または復元。 |
| `--version` | バージョンを表示して終了。 |
| `--help`、`-h` | ヘルプを表示。 |

`--api-key` は自動化を目的としています。ログイン、組織の切り替え、アシスタントコマンドにはユーザーセッションが必要です。
