Python 3.10 以上が必要で、**ランタイム依存関係はゼロ** — これはポリシーであり、偶然ではありません。SDK は他者のエージェントプロセスにインストールされるため、宣言した依存関係はすべて継承されてしまいます。テストはコアモジュールをスキャンし、新しいインタープリターを起動して、どのフレームワークも `sys.modules` に含まれていないことを確認します。

## インストール

```bash
pip install failproofai-sdk
```

パッケージは `failproofai-sdk` としてインストールされ、Python では `failproofai_sdk` としてインポートします。`failproofai-sdk[langgraph]` のようなフレームワーク拡張はフレームワーク本体もインストールしますが、アダプターは常にベースホイールに含まれています。

## 設定

```python
import failproofai_sdk

failproofai_sdk.configure(
    base_dir=None,
    flush_interval=0.5,
    environment="production",
)
```

| 引数 | 動作 |
| --- | --- |
| `environment` | すべてのイベントに付くラベル — `production`、`staging`、`prod-eu` など。デフォルトは `dev`。 |
| `flush_interval` | バックグラウンドスレッドがディスクに書き込む間隔（秒）。デフォルトは `0.5`。 |
| `base_dir` | 書き込み先。デフォルトは `$FAILPROOFAI_HOME/custom-agents`、それ以外の場合は `~/.failproofai/custom-agents` — デーモンが監視するスプールで、特別な理由がない限りこのままにしておくことを推奨します。 |

`configure()` は**キーワード専用** — `configure(None, 0.5, "prod")` は `TypeError` になります。また、すべての引数をまとめて検証してから適用するため、`flush_interval` がゼロより大きい有限の数値でない場合は `ValueError` を発生させます。これにより、拒否された呼び出しは SDK を中途半端な状態にするのではなく、元の状態のまま保持します。

環境変数で設定する場合:

| 変数 | 動作 |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | コード変更なしで `environment` を設定します。ラベルがアプリではなくデプロイメントに属する場合に使用します。`configure()` の引数が優先されます。 |
| `FAILPROOFAI_HOME` | スプールを保持する Failproof AI のルートディレクトリを変更します。 |
| `FAILPROOFAI_SDK_STRICT` | `1` にするとインストルメンテーションエラーがログに記録される代わりに例外を発生させます。 |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` にするとフレームワーク互換性の問題が警告して継続する代わりに例外を発生させます。 |

<Warning>
  **`environment` にカンマを含めないでください。** インジェストはそのフィールドをカンマで分割してフィルターを構築するため、ラベルにカンマが含まれるイベントはすべてスキップされます。つまり、実行全体が静かに消えてしまいます。`prod,eu` ではなく `prod-eu` と記述してください。

  `configure(environment="prod,eu")` は即座に例外を発生させます。`AGENTEYE_ENVIRONMENT` は例外を発生させられない（呼び出し元がいない）ため、1回警告を出して `dev` にフォールバックします。
</Warning>

イベントはメモリ内にキューイングされ、バックグラウンドで `flush_interval` 秒ごとに書き込まれます。インタープリター終了時に最終フラッシュが行われます。プロセスが強制終了された場合、書き込まれていないデータは失われます。

## スコープ

`with` と `async with` の両方で使用できるコンテキストマネージャーが3つあります:

| スコープ | バインドするもの | 発行するもの |
| --- | --- | --- |
| `session()` | セッション ID。それを yield する | なし — ID のみ |
| `agent(name)` | エージェント ID、および外側のエージェントから推論された `parent_id` | 入口で `agent_start`、出口で `agent_end` |
| `tool_call(name)` | 新しいものなし — 外側の ID を継承 | 入口で `tool_use`、出口で `tool_result` |

```python
with failproofai_sdk.session():
    with failproofai_sdk.agent("planner"):
        with failproofai_sdk.tool_call("web_search", input={"q": q}) as t:
            t.output = search(q)
```

`tool_call()` はデフォルトで `tool_call_id` に新しい `uuid4().hex` を使用し、入口時に一度だけ ID を解決します。そのため、内部で独自のスコープをプッシュするツールがあっても、クロージングの `tool_result` が別のエージェントに紐付くことはありません。失敗した場合は `tool_result(error="TypeName: msg")` を発行し、**`error` イベントは発行しません** — ループがキャッチするツールの失敗はランレベルのエラーではなく、伝播するものは外側の `agent()` によって一度だけ報告されます。キャンセルの場合はエラー文字列なしでリーフを閉じます。

## アダプター

`instrument()` はサポートされているフレームワークを上記のスコープに接続します。引数なしの場合、このプロセスでインポート済みのフレームワークを自動検出します。名前を渡すと特定の1つだけをインストールします。

```python
failproofai_sdk.instrument()              # すでにインポートされているものすべて
failproofai_sdk.instrument("crewai")      # 特定の1つ
failproofai_sdk.uninstrument("crewai")    # 元の属性に戻す
```

4つの名前は `"langchain"`（LangGraph も対象。LangGraph は langchain-core のコールバックマネージャー上で動作するため）、`"crewai"`、`"llama_index"`、`"pydantic_ai"` です。フレームワークのインポートは呼び出し内部で行われます。これが `import failproofai_sdk` をゼロ依存に保つ仕組みです。

各フレームワークには専用ページがあります: [LangChain](/ja/start/integrations/langchain)、[CrewAI](/ja/start/integrations/crewai)、[LlamaIndex](/ja/start/integrations/llamaindex)、[Pydantic AI](/ja/start/integrations/pydantic-ai)。

## ID（アイデンティティ）

すべてのイベントはセッションとエージェントに属します。**スコープが両方を設定する**ため、明示的に渡す必要はほとんどありません:

```python
with failproofai_sdk.session():
    with failproofai_sdk.agent("planner"):
        failproofai_sdk.event.tool_use(tool_name="search", tool_call_id="c1")
```

`session_id` や `agent_id` を明示的に渡すことも引き続き可能で、その値が優先されます。

何もバインドされていない場合、この2つは**対称ではありません**:

| 省略したもの | 何もバインドされていない場合 |
| --- | --- |
| `session_id` | `TypeError` を発生させます。Cloud が静かに破棄するようなイベントを発行するのではなく |
| `agent_id` | `main` にフォールバックします。`agent()` なしで `session()` 内から発行されたイベントはすべて `main` という名前の単一エージェントの下に集まります |

セッション ID を勝手に生成すると、1回の実行が発行サイトの数だけセッションに分散してしまいます。これが `session_id` だけが例外を発生させる理由です。

`session_id` と `agent_id` は空チェックが行われる唯一の2つの名前です。非文字列は `TypeError` を、空またはスペースのみの ID は `ValueError` を発生させます。サーバーは空の ID を*受け入れる*ため、このチェックがなければ空の ID で送信されたすべてのイベントが単一の空 ID の下にグループ化され、存在しているように見えながら静かにマージされてしまいます。

<Note>
  ID はコンテキスト変数に乗ります。`asyncio` タスクには自動的に伝播しますが、**新しいスレッドには伝播しません** — ワーカーを `failproofai_sdk.propagate()` でラップしないと、そのイベントはどこにも紐付かなくなります。
</Note>

## イベントカタログ

15のメソッドがあります。ほとんどは**ペア** — オープナーとクローザー — になっています。

| | オープン | クローズ | SDK による計時 |
| --- | --- | --- | --- |
| **エージェント** | `agent_start` | `agent_end` | なし |
| | `agent_pause` | `agent_resume` | あり |
| **モデル** | `model_request` | `model_response` | なし — Cloud で相関 |
| **ツール** | `tool_use` | `tool_result` | あり |
| **フック** | `hook_triggered` | `hook_completed` | あり |
| **人間** | `human_wait` | `human_input` | あり |

単独で使用するものが3つあります: `error`、`human_pause`、`human_interrupt`。

<Accordion title="メソッドごとの全フィールド" icon="table">

すべてのメソッドは `session_id` と `agent_id` も受け取りますが、スコープが自動で設定します。`None` のままの値は JSON の `null` として送信されるのではなく破棄されます。また、すべてのメソッドは `None` を返します。

| メソッド | 必須 | 任意 |
| --- | --- | --- |
| `agent_start` | — | `goal`, `parent_id` |
| `agent_end` | — | `outcome`, `summary` |
| `agent_pause` | `pause_id` | `reason`, `user_id` |
| `agent_resume` | `pause_id` | `reason`, `user_id` |
| `model_request` | — | `model`, `messages`, `system`, `tools`, `request_id` |
| `model_response` | — | `model`, `stop_reason`, `input_tokens`, `output_tokens`, `content`, `role`, `request_id`, `duration_ms` |
| `tool_use` | `tool_name`, `tool_call_id` | `input` |
| `tool_result` | `tool_name`, `tool_call_id` | `output`, `error` |
| `hook_triggered` | `hook_name`, `hook_id` | `trigger_event`, `input` |
| `hook_completed` | `hook_name`, `hook_id` | `outcome`, `output`, `error` |
| `error` | `error_type`, `message` | `traceback` |
| `human_wait` | `input_id` | `prompt`, `options`, `reason` |
| `human_input` | `input_id` | `response` |
| `human_pause` | — | `reason`, `user_id` |
| `human_interrupt` | — | `reason`, `user_id`, `at_step` |

</Accordion>

<Warning>
  実行を失敗としてマークするには、`outcome` が `failed`、`error`、`timeout`、`rejected` のいずれかである必要があります。紛らわしいですが `"failure"` を含むそれ以外の値はすべて成功とみなされます。
</Warning>

## ペアリングと計時

**ルールは1つ: クロージングイベントにはオープナーと同じ ID を渡す。** これがペアを形成し、SDK が間隔を計測できるようにします。

| ペア | マッチするフィールド | トラッキングキー |
| --- | --- | --- |
| `tool_use` → `tool_result` | `tool_call_id` | `tool:{session_id}:{tool_call_id}` |
| `hook_triggered` → `hook_completed` | `hook_id` | `hook:{session_id}:{hook_id}` |
| `agent_pause` → `agent_resume` | `pause_id` | `pause:{session_id}:{pause_id}` |
| `human_wait` → `human_input` | `input_id` | `human:{session_id}:{input_id}` |

キーはセッションで名前空間化されており、これにより以下の両方のエッジケースが成立します。

上記4つのクローザーに対して**`duration_ms` を自分で渡さないでください**。SDK が計測するため、渡すと `ValueError` が発生します。

<Note>
  `model_request` と `model_response` は Cloud が `request_id` で相関するペアです。SDK はそれらを追跡せずローカルでは何も計測しません。そのため `model_response` だけが `duration_ms` を受け取る唯一のイベントです。ミリ秒の整数を渡してください — カラムが 32 ビット整数であるため、float を渡すと例外が発生し空のまま保存されてしまいます。
</Note>

<Accordion title="エッジケース" icon="circle-help">

- **ID はカインドごと、セッションごとに一意であればよい。** ツール呼び出しとフックは同じ ID を共有できます。同時に実行中の2つのセッションは、衝突せずに同じ ID を再利用できます。
- **エージェントにスコープされていない。** あるエージェントでオープンされ別のエージェントでクローズされたペアも正しくマッチします — マルチエージェントコードでは通常のケースです。
- **`request_id` は任意だが推奨。** これがないと、モデルイベントは到着順にペアリングされるため、同じエージェント内での2つの並行呼び出しがペアのミスマッチを起こす可能性があります。
- **プロセスをまたぐペア**も Cloud ではマッチしますが、SDK は計時できません — どちらのプロセスも両方の半分を見ていないためです。
- **最大10,000件のオープナーが同時にクローザーを待てます。** それを超えると最古のものが削除されるため、リークが無制限に成長することはありません。

</Accordion>

## 独自フィールド

渡した追加のキーワードはすべてイベントと一緒に保存されます:

```python
failproofai_sdk.event.tool_use(
    tool_name="search", tool_call_id="c1",
    fw_tenant="acme", fw_region="eu-west-1",     # 独自フィールド
)
```

後でクエリしたい場合は JSON 型を使用してください。それ以外のもの — UUID、datetime、`Decimal`、set、bytes、モデルオブジェクト — は文字列として保存されます。

<Warning>
  **11の名前は例外で、文字列化される代わりに例外を発生させます。** インジェストはそれぞれを型付きカラムに持ち上げ、それ以外のものには `200 OK` で静かに `NULL` を保存します。そのため、SDK は呼び出しサイトで拒否します。

  | 名前 | 必要な型 |
  | --- | --- |
  | `duration_ms`, `input_tokens`, `output_tokens` | 符号なし32ビット範囲の `int` |
  | `tool_name`, `tool_call_id`, `hook_name`, `hook_id`, `input_id`, `pause_id`, `error_type`, `model` | 文字列 — `None` は `ValueError`、非文字列は `TypeError` を発生させます |

  これは値が名前付きパラメーターとして渡された場合でも、独自のエクストラとして渡された場合でも適用されます。`model_response` は同じ理由で `input_tokens` と `output_tokens` を受け取り時にバリデーションします — これらはプロバイダーの usage オブジェクトから直接埋めることが多いためです。
</Warning>

<Warning>
  **フィールド名にプレフィックスを付けてください。** エクストラは最後に適用されるため、`model`、`tool_name`、`outcome` という名前のフィールドは本来のフィールドを静かに上書きしてしまいます。フレームワークアダプターは `fw_` を使用します。同様にすれば衝突は起きません。

  これはまた、スペルミスした任意フィールドが決してエラーにならない理由でもあります — 単に新しいカスタムフィールドになるだけです。Cloud で標準フィールドが見当たらない場合は、まずスペルを確認してください。
</Warning>

次の5つの名前は予約済みで、完全に拒否されます: `timestamp`、`session_id`、`agent_id`、`type`、`environment`。

## その他のエクスポート

| エクスポート | 内容 |
| --- | --- |
| `current()` | 現在バインドされている ID を `Identity` として返します。`current().session_id is None` は何もバインドされていないことを意味します |
| `Identity` | `session_id`、`agent_id`、`parent_id`、`depth`。自身が `None` になることはありません — フィールドを確認してください |
| `propagate(fn)` | `fn` をラップして、ラップ時にバインドされていた ID で実行されるようにします。`Thread`、`pool.submit`、`pool.map`、`run_in_executor` に必要です |
| `_writer.flush_now()` | バッファリングされたエントリをすぐにドレインして書き込みます。テストや終了前の強制フラッシュに使用します |
| `__version__` | インストールされている SDK のバージョン |

## デリバリーと検証

<Tabs>
  <Tab title="ダッシュボード">
    **Observe → Events** で、最初に `agent_start` が存在し、最後に `agent_end` が存在することを確認します。次に **Observe → Sessions** を開き、モデル、ツール、人間、フック、エラーのイベントが意図した順序で表示されることを確認します。トラブルシューティングの主キーとしてセッション ID を使用してください。
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai flush --wait --timeout 60
    failproofai config --status
    fp sessions --since 1h --env production --session-id <session-id>
    fp events --since 1h --session-id <session-id> --full
    ```
  </Tab>
</Tabs>

Cloud が空の場合は `$FAILPROOFAI_HOME/custom-agents/events`、それ以外の場合は `~/.failproofai/custom-agents/events` を確認してください。JSONL ファイルがあれば SDK が発行していることを証明します。スプールが増え続けている場合はデーモンの設定またはデリバリーに問題があり、スプールが空の場合はインストルメンテーションまたはプロセスのライフタイムに問題があります。

<Note>
  スプールはデーモンが停止しているときのみ確認してください。デーモンが動作中は、各バッチを数ミリ秒以内に収集して削除するため、ディレクトリ一覧はコレクターと競合し、実際に発行されたイベント数よりはるかに少なく表示されます。
</Note>

## カスタムランタイムでの障害防止

監査結果とリンクされたトレースを使用して、安全でないアクション、必要な証拠、意図した応答を定義します。カスタム実施インテグレーションは、実行前にアクションを公開し、構造化された入力をポリシーエンジンに渡し、その結果の allow、instruct、または deny 決定を適用する必要があります。

[Failproof AI にお問い合わせ](mailto:support@befailproof.ai) ください。ランタイムのモデル、ツール、ライフサイクル境界をポリシーフックにマッピングし、インテグレーションを一緒に検証するお手伝いをします。
