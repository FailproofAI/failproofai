Python 3.10 以降が必要です。実行時の依存関係はありません。

## インストール

```bash
pip install failproofai-sdk
```

パッケージは `failproofai-sdk` としてインストールされ、Python では `failproofai_sdk` としてインポートします。`failproofai-sdk[langgraph]` などのフレームワーク向けエクストラは、フレームワーク本体も一緒にインストールします。アダプターは常にベースホイールに含まれています。

## 設定

```python
import failproofai_sdk

failproofai_sdk.configure(
    base_dir=None,
    flush_interval=0.5,
    environment="production",
)
```

| 引数 | 説明 |
| --- | --- |
| `environment` | すべてのイベントに付与されるラベルです（例：`production`、`staging`、`prod-eu`）。デフォルトは `dev` です。 |
| `flush_interval` | バックグラウンドスレッドがディスクへ書き込む頻度（秒単位）です。デフォルトは `0.5` です。 |
| `base_dir` | 書き込み先のディレクトリです。デフォルトはデーモンのスプールになります。特別な理由がない限り変更不要です。 |

環境変数で設定することも可能です：

| 変数 | 説明 |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | コード変更なしで `environment` を設定します。ラベルがアプリではなくデプロイメントに属する場合に便利です。`configure()` の引数が優先されます。 |
| `FAILPROOFAI_HOME` | スプールを保持する Failproof AI のルートディレクトリを変更します。 |
| `FAILPROOFAI_SDK_STRICT` | `1` に設定すると、インストルメント化エラーがログ記録ではなく例外として発生します。 |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` に設定すると、フレームワークの互換性問題が警告を出して続行するのではなく、例外として発生します。 |

<Warning>
  **`environment` にカンマを使用しないでください。** インジェスト処理はこのフィールドをカンマで分割してフィルターを構築します。ラベルにカンマが含まれるとそのイベント全体が無視され、実行結果がサイレントに消えてしまいます。`prod,eu` ではなく `prod-eu` と記述してください。

  `configure(environment="prod,eu")` は即座に例外を発生させるので、すぐに気づくことができます。一方 `AGENTEYE_ENVIRONMENT` は呼び出し元がないため例外を発生させられず、1度警告を出した後 `dev` にフォールバックします。
</Warning>

イベントはメモリ内にキューイングされ、`flush_interval` 秒ごとにバックグラウンドで書き込まれます。インタープリター終了時には最終フラッシュが実行されます。プロセスが強制終了された場合、未書き込みのデータは失われます。

## ID 管理

すべてのイベントはセッションとエージェントに紐づきます。**スコープが両方を自動的に設定する**ため、通常は手動で渡す必要はありません：

```python
with failproofai_sdk.session():
    with failproofai_sdk.agent("planner"):
        failproofai_sdk.event.tool_use(tool_name="search", tool_call_id="c1")
```

`session_id` や `agent_id` を明示的に渡すことも可能で、その場合はそちらが優先されます。スコープも渡された値もない場合は、クラウドが静かに破棄するイベントを送信するのではなく、`TypeError` が発生します。

<Note>
  ID はコンテキスト変数で管理されます。`asyncio` タスクには自動的に引き継がれますが、**新しいスレッドには引き継がれません**。ワーカースレッドを `failproofai_sdk.propagate()` でラップしないと、そのスレッドのイベントは未関連付けのままになります。
</Note>

## イベントカタログ

15種類のメソッドがあります。ほとんどは**ペア**で提供されており、オープナーを呼び出した後にクローザーを呼び出すと、SDK が間隔を計測します。

| | オープン | クローズ |
| --- | --- | --- |
| **エージェント** | `agent_start` | `agent_end` |
| | `agent_pause` | `agent_resume` |
| **モデル** | `model_request` | `model_response` |
| **ツール** | `tool_use` | `tool_result` |
| **フック** | `hook_triggered` | `hook_completed` |
| **ヒューマン** | `human_wait` | `human_input` |

単独で使用するものが3つあります：`error`、`human_pause`、`human_interrupt`。

<Accordion title="メソッド別の全フィールド一覧" icon="table">

すべてのメソッドには `session_id` と `agent_id` も指定できますが、スコープが自動的に設定します。`None` のままにした値は JSON の `null` として送信されるのではなく省略されます。すべてのメソッドは `None` を返します。

| メソッド | 必須 | 任意 |
| --- | --- | --- |
| `agent_start` | — | `goal`, `parent_id` |
| `agent_end` | — | `outcome`, `summary` |
| `agent_pause` | `pause_id` | `reason`, `user_id` |
| `agent_resume` | `pause_id` | `reason`, `user_id` |
| `model_request` | — | `model`, `messages`, `system`, `tools`, `request_id` |
| `model_response` | — | `model`, `stop_reason`, `input_tokens`, `output_tokens`, `content`, `role`, `request_id`, `duration_ms` |
| `tool_use` | `tool_name`, `tool_call_id` | `input` |
| `tool_result` | `tool_name`, `tool_call_id` | `output`, `error` |
| `hook_triggered` | `hook_name`, `hook_id` | `trigger_event`, `input` |
| `hook_completed` | `hook_name`, `hook_id` | `outcome`, `output`, `error` |
| `error` | `error_type`, `message` | `traceback` |
| `human_wait` | `input_id` | `prompt`, `options`, `reason` |
| `human_input` | `input_id` | `response` |
| `human_pause` | — | `reason`, `user_id` |
| `human_interrupt` | — | `reason`, `user_id`, `at_step` |

</Accordion>

<Warning>
  実行を失敗としてマークするには、`outcome` に `failed`、`error`、`timeout`、`rejected` のいずれかを指定する必要があります。これ以外の値（`"failure"` のような惜しい値も含む）はすべて成功として扱われます。
</Warning>

## ペアリングと所要時間

**ルールはひとつ：クローズイベントにはオープナーと同じIDを渡すこと。** これによってペアが紐づけられ、SDK が時間を計測できます。

| ペア | 照合キー |
| --- | --- |
| `tool_use` → `tool_result` | `tool_call_id` |
| `hook_triggered` → `hook_completed` | `hook_id` |
| `agent_pause` → `agent_resume` | `pause_id` |
| `human_wait` → `human_input` | `input_id` |
| `model_request` → `model_response` | `request_id` |

**`duration_ms` を自分で渡さないでください。** SDK が自動計測します。渡した場合は `ValueError` が発生します。

唯一の例外は `model_response` です。実際のプロバイダーのレイテンシはあなた自身しか知り得ないためです。この場合、ミリ秒単位の整数値を渡してください。浮動小数点数を渡すと例外が発生します（このカラムは32ビット整数であり、そうでなければ空になってしまうためです）。

<Accordion title="エッジケース" icon="circle-help">

- **IDはイベントの種類とセッション単位でユニークであれば十分です。** ツール呼び出しとフックが同じIDを共有しても問題ありません。また、同時に実行中の2つのセッションが同じIDを再利用しても衝突しません。
- **IDはエージェントにスコープされません。** あるエージェントでオープンされたペアが別のエージェントでクローズされても、正しく照合されます。マルチエージェントコードではこれが通常の動作です。
- **`request_id` は任意ですが推奨されます。** 指定しない場合、モデルイベントは到着順にペアリングされるため、同一エージェント内で並行する2つの呼び出しのペアが入れ違いになる可能性があります。
- **プロセスをまたいで分割されたペア**もクラウド上では照合されますが、SDK はその時間を計測できません（どちらのプロセスも両方のイベントを見ていないためです）。
- **同時に待機できるオープナーは最大10,000件です。** これを超えると最も古いものから破棄されるため、リークが無限に増大することはありません。

</Accordion>

## カスタムフィールド

イベントに追加のキーワードを渡すと、そのままイベントと一緒に保存されます：

```python
failproofai_sdk.event.tool_use(
    tool_name="search", tool_call_id="c1",
    fw_tenant="acme", fw_region="eu-west-1",     # カスタムフィールド
)
```

後でクエリを実行したい場合は、JSON で表現可能な型を使用することをお勧めします。UUID、datetime、`Decimal`、set、bytes、モデルオブジェクトなど、それ以外の値は文字列として保存されます。

<Warning>
  **フィールド名にプレフィックスを付けてください。** カスタムフィールドは最後に適用されるため、`model`、`tool_name`、`outcome` といった名前のフィールドは、実際の値を黙って上書きしてしまいます。フレームワークアダプターは `fw_` プレフィックスを使用しています。同様にすれば衝突は起こりません。

  これは、任意フィールドのスペルミスがエラーにならない理由でもあります。新しいカスタムフィールドとして扱われてしまいます。クラウドで標準フィールドが見当たらない場合は、まずスペルを確認してください。
</Warning>

以下の5つの名前は予約済みであり、指定するとエラーになります：`timestamp`、`session_id`、`agent_id`、`type`、`environment`。

## 配信と確認

<Tabs>
  <Tab title="ダッシュボード">
    **Observe → Events** で、最初に `agent_start`、最後に `agent_end` が存在することを確認します。次に **Observe → Sessions** を開き、モデル、ツール、ヒューマン、フック、エラーの各イベントが意図した順序で表示されているかを確認します。トラブルシューティングの際はセッションIDを主要なキーとして使用してください。
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai flush --wait --timeout 60
    failproofai config --status
    fp sessions --since 1h --env production --session-id <session-id>
    fp events --since 1h --session-id <session-id> --full
    ```
  </Tab>
</Tabs>

クラウドにデータが届いていない場合は、`$FAILPROOFAI_HOME/custom-agents/events`（未設定の場合は `~/.failproofai/custom-agents/events`）を確認してください。JSONL ファイルが存在すれば SDK からの送信は成功しています。スプールが増え続けている場合はデーモンの設定や配信の問題です。スプールが空の場合はインストルメント化またはプロセスのライフタイムに問題があります。

<Note>
  スプールを確認するのはデーモンが停止しているときだけにしてください。デーモンが稼働中は、各バッチを数ミリ秒以内に収集・削除するため、ディレクトリ一覧をコレクターと競合して確認すると、実際に送信されたイベントよりもはるかに少ない件数しか表示されません。
</Note>

## カスタムランタイムでの障害防止

監査結果とリンクされたトレースを使用して、安全でないアクション、必要なエビデンス、意図された応答を定義します。カスタムエンフォースメントインテグレーションは、実行前にアクションを公開し、構造化された入力をポリシーエンジンに渡し、その結果である allow、instruct、または deny の判定を適用する必要があります。

[Failproof AI へお問い合わせください](mailto:support@befailproof.ai)。ランタイムのモデル・ツール・ライフサイクル境界をポリシーフックにマッピングし、インテグレーションの検証をサポートします。
