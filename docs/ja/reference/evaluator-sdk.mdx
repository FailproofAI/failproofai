エバリュエーターは完了したエージェントセッションを受け取り、必要な品質シグナルを返します：数値スコア、各スコアの説明、およびオプションのサマリーです。Failproof AI はこれらの結果をトレースと並べて保存し、エージェントや環境をまたいでチャートに表示します。

パッケージは `agenteye-evaluator` で、`agenteye_evaluator` としてインポートします。Python 3.10 以降が必要で、`fastapi`、`pydantic>=2`、`structlog` に依存します。

<Warning>
  **公開 PyPI からの `pip install agenteye-evaluator` はインストール方法ではありません。** このパッケージはプライベートリリースアーティファクトとしてのみ公開されており、公開 PyPI 上の名前は未取得です — 修飾なしのインストールを行うと、本番トランスクリプトを読み取るサービスに見知らぬ第三者のパッケージが混入する可能性があります。以下の手順に従ってください。
</Warning>

## エバリュエーターのセットアップ

<Steps>
  <Step title="SDK をインストールする">
    以下の手順を上から順に試し、最初に該当したところで止めてください。

    `evaluator-sdk/` ディレクトリが存在するモノレポ内の場合:

    ```bash
    pip install ./evaluator-sdk
    ```

    それ以外の場合は、プライベートリリースから取得します。ホイールは `agenteye-enterprise/releases` の GitHub Releases に添付されており、`evaluator-sdk/v<version>` のタグが付いています。`gh auth login` とそのリポジトリへのアクセス権が必要です:

    ```bash
    gh release download evaluator-sdk/v<version> \
      --repo agenteye-enterprise/releases --pattern '*.whl'
    pip install ./agenteye_evaluator-*.whl
    ```

    どちらも機能しない場合は、独自のインストール方法を試みるのではなく、Failproof AI の担当者にホイールを問い合わせてください。

    `uvicorn` は意図的に依存関係に含まれていないため、サーバーを別途インストールしてください:

    ```bash
    pip install 'uvicorn[standard]'
    ```
  </Step>

  <Step title="スコアリング対象を定義する">
    `evaluator.py` を作成します。この例では、セッションにツール呼び出しの失敗が含まれているかどうかを確認します。

    ```python
    import os
    from agenteye_evaluator import Evaluator, EvalResponse

    app = Evaluator(token=os.environ.get("EVALUATOR_TOKEN"))

    @app.config
    def config():
        return {"inactivity_timeout_secs": 1800}

    @app.evaluator
    def evaluate(req):
        tool_errors = sum(
            1 for item in req.events
            if item.event_type == "tool_result" and item.payload.get("error")
        )
        return EvalResponse(
            scores={"tool_reliability": 1.0 if tool_errors == 0 else 0.0},
            reasoning={"tool_reliability": f"{tool_errors} tool errors"},
        )
    ```

    完全なコンストラクターは `Evaluator(token: str | None = None, *, title: str = "AgentEye Evaluator")` です。トークンは `hmac.compare_digest` で比較されます。`title` は FastAPI アプリのタイトルであり、表示上のものです。

    <Warning>
      `token=None` は認証を完全に無効化します。ローカル環境では問題ありませんが、本番環境では重大なセキュリティホールとなります。エンドポイントはセッションのトランスクリプト全体を受信するためです。
    </Warning>
  </Step>

  <Step title="ローカルで実行してテストする">
    共有トークンを設定し、エバリュエーターを起動して、ヘルスエンドポイントが応答することを確認します。

    ```bash
    export EVALUATOR_TOKEN=<shared-token>
    uvicorn evaluator:app --host 0.0.0.0 --port 8080
    ```

    別のターミナルで:

    ```bash
    curl http://127.0.0.1:8080/health
    ```

    各デコレーターは関数をそのまま返すため、`evaluate(req)` は直接呼び出し可能な状態を保ちます。これによりユニットテストが手軽になります — `EvalRequest` を構築してハンドラーを呼び出すだけで、HTTP は不要です。
  </Step>
</Steps>

## エバリュエーターを Failproof AI に接続する

1. Failproof AI Cloud から到達可能な HTTPS URL にエバリュエーターをデプロイします。
2. `EVALUATOR_ENDPOINT` にその URL を設定し、`EVALUATOR_TOKEN` にエバリュエーターで使用しているトークンと同じ値を設定します。マネージド Cloud の場合は、[support@befailproof.ai](mailto:support@befailproof.ai) に連絡して接続の設定を依頼してください。
3. 評価を実行し、スコアが Failproof AI に表示されることを確認します。

<Tabs>
  <Tab title="ダッシュボード">
    **Observe → Sessions** で完了したセッションを開き、自動評価されていない場合は **Run evaluation** を選択します。セッションの **Evaluation** パネルでステータス、スコア、説明、サマリーを確認します。

    **Observe → Evaluations** を使用して、エージェントや環境をまたいでスコアを比較します。レイテンシー、コスト、トークンなどの数値測定には **Observe → Metrics** を使用します。

    まず1つのセッションで、エバリュエーターが期待されるスコアキーを返し、その特定の実行に対して有用な説明を返しているかを確認します。

    ![評価スコアと説明がトレースの隣に表示されているセッション詳細ビュー。](/images/dashboard/session-detail.png)

    個別の結果が正しく見えたら、評価ダッシュボードを使用して、時系列およびエージェントや環境をまたいでスコアを比較します。

    ![エバリュエーターのスコアを時系列でチャートに表示する品質ダッシュボード。](/images/dashboard/dashboard-quality.png)

    正常なチャートは安定したスコア名を使用します。キーを変更すると新しい系列が作成されます。
  </Tab>
  <Tab title="CLI">
    ```bash
    fp evals --since 1h --score tool_reliability:0..1
    fp evals --since 24h --aggregate
    ```
  </Tab>
</Tabs>

セルフホスト型 Cloud インスタンスの場合、`EVALUATOR_ENDPOINT` がサーバープロセスに設定されるまで自動評価は無効です。エバリュエーターの環境変数を変更した後はサーバーを再起動してください。

## デコレーターとルート

| デコレーター | ルート | 必須 |
| --- | --- | --- |
| `@app.evaluator` | `POST /evaluate` | 必須。 |
| `@app.job_lookup` | `GET /evaluate/{job_id}` | `JobPending` を返す場合のみ。登録しないとポーリングが 404 になります。 |
| `@app.config` | `GET /config` | 任意。ただし `agent_end` を発行しないセッションには必須 — 下記参照。 |

各デコレーターは同期・非同期いずれの関数も受け付け、関数をそのまま返します。同じデコレーターを2回登録すると `ValueError` が発生します。

| ルート | 認証 |
| --- | --- |
| `GET /health` | トークンが設定されていても公開。 |
| `POST /evaluate` | Bearer 認証。 |
| `GET /evaluate/{job_id}` | Bearer 認証。 |
| `GET /config` | Bearer 認証。 |

Bearer スキームのマッチは大文字・小文字を区別しません。`@app.config` が未登録の場合でも `GET /config` は `{"default_poll_interval_secs": 10}` を返すため、SDK は常にポーリング間隔を通知します。

SDK は評価リクエストボディを 25 MiB に制限しており、ボディを読み込む前に `Content-Length` で確認します。上限を超えると 413 が返され、4xx のため処理は終了します。未知のリクエストフィールドは無視されるため、イベントコントラクトが拡張されてもサービスとの互換性が維持されます。

<Warning>
  `inactivity_timeout_secs` を指定した `@app.config` を登録することで、フォールバックスキャナーが有効になります。登録しない場合、`agent_end` を一度も発行しなかったセッション（放棄・クラッシュ・アイドル中のものすべて）は評価キューに入れられません。0以下の値は無視されます。
</Warning>

## SDK の型

| 型 | フィールド |
| --- | --- |
| `AgentEvent` | `id`, `ts`, `event_type`, `payload` |
| `EvalRequest` | `schema_version`, `session_id`, `agent_id`, `environment`, `started_at`, `ended_at`, `events` |
| `EvalResponse` | `scores`, `reasoning`, `summary` |
| `JobPending` | `job_id`, `next_poll_secs` |
| `EvaluatorConfig` | `inactivity_timeout_secs`, `default_poll_interval_secs` |

## リクエストとレスポンスのフィールド

| フィールド | 型 | 備考 |
| --- | --- | --- |
| `EvalRequest.schema_version` | `str` | 現在は `"1"`。 |
| `session_id`, `agent_id`, `environment` | `str` | セッションの識別情報と環境。 |
| `started_at` | `datetime` | 最初のイベントのタイムスタンプ。 |
| `ended_at` | `datetime \| None` | `agent_end` イベントのタイムスタンプ（「セッションが停止した時刻」ではありません）。非アクティビティスキャナーによってキューに入れられたセッションは `agent_end` が存在せず、`None` で届きます。 |
| `events` | `list[AgentEvent]` | 順序付きの完全なイベントストリーム。 |
| `AgentEvent.id` | `int` | バックエンドのイベント行識別子。 |
| `AgentEvent.ts` | `datetime` | イベントのタイムスタンプ。 |
| `AgentEvent.event_type` | `str` | `tool_use` などのイベントファミリー。 |
| `AgentEvent.payload` | `dict[str, Any]` | イベント JSON 全体をフラット化したもの。イベント固有のフィールドはトップレベルに配置され、`payload["type"]` は `event_type` と重複します。 |
| `EvalResponse.scores` | `dict[str, float] \| None` | 評価でチャートに表示される数値ディメンション。 |
| `EvalResponse.reasoning` | `dict[str, str] \| None` | スコアごとの説明。キーは `scores` と対応させてください。 |
| `EvalResponse.summary` | `str \| None` | 評価全体のナレーティブ。サーバー側で 8192 バイトに切り詰められます。`last_error` は 2048 バイト。 |

シリアライゼーションは `exclude_none` を使用するため、未設定フィールドは `null` として送信されるのではなく省略されます。

<Warning>
  `ended_at` から経過時間を算出するとリアルデータでクラッシュします。非アクティビティスキャナーによってキューに入れられたすべてのセッションは `ended_at` が `None` で届きます。減算の前に必ず確認してください。
</Warning>

## 戻り値の形式

ハンドラーが返せるのは以下の3つのうちいずれか1つだけです。それ以外は `TypeError` となり、500 として表面化します。

| 戻り値 | ワイヤー上の `status` | 終了 |
| --- | --- | --- |
| `EvalResponse(...)` | `done` | はい — スコアが保存されます。 |
| `JobPending(job_id=...)` | `pending` | いいえ — サーバーがポーリングします。 |
| `status` が `done`、`pending`、または `error` の生の `dict` | 指定された値 | `error` は終了。 |

`error` ステータスには型付きモデルがありません。処理を終了させるには生のdictを返す必要があり、`error` は空でない `str` でなければなりません:

```python
return {"status": "error", "error": "model service unavailable"}
```

<Warning>
  **例外を送出してもエラーは記録されません。** 例外はボディが `"evaluator raised an internal error"` の汎用 500 になり、例外テキストはサーバーに届きません。サーバーはすべての 5xx を一時的なエラーとして扱い、再試行します。失敗を記録したい場合は `error` の dict を返してください。
</Warning>

## 非同期処理を返す

評価が1つのリクエスト内で完了できない場合は `JobPending` を使用します。ジョブ ID は Failproof AI に対して不透明であり、結果が収集されるかサーバーのタイムアウトが切れるまで、サービス側で解決可能な状態を維持する必要があります。

```python
from agenteye_evaluator import EvalRequest, EvalResponse, Evaluator, JobPending

app = Evaluator(token="shared-secret")

@app.evaluator
def start(req: EvalRequest) -> JobPending:
    job_id = enqueue(req)
    return JobPending(job_id=job_id, next_poll_secs=30)

@app.job_lookup
def lookup(job_id: str):
    result = get_result(job_id)
    if result is None:
        return JobPending(job_id=job_id, next_poll_secs=30)
    return EvalResponse(
        scores=result.scores,
        reasoning=result.reasoning,
        summary=result.summary,
    )
```

ポーリング間隔は次の優先順位で決定されます: `JobPending.next_poll_secs`、`EvaluatorConfig.default_poll_interval_secs`、サーバーの `EVALUATOR_POLLING_INTERVAL_SECS` の順です。値は1秒から1時間の間にクランプされます。サーバーのデフォルトのウォールクロックポーリング上限は1時間で、それを超えると結果は `timeout` として記録されます。

## サーバー運用者の設定

自動評価はデプロイメント全体に適用され、`EVALUATOR_ENDPOINT` が未設定の場合は無効のままです。

| 変数 | デフォルト | 用途 |
| --- | --- | --- |
| `EVALUATOR_ENDPOINT` | 未設定 | エバリュエーターサービスのベース URL。 |
| `EVALUATOR_TOKEN` | 未設定 | `Evaluator(token=...)` と共有する Bearer トークン。 |
| `EVALUATOR_WORKERS` | `2` | 並行ディスパッチャーワーカー数。 |
| `EVALUATOR_CLAIM_BATCH` | `4` | ディスパッチャーの1パスあたりに取得するセッション数。 |
| `EVALUATOR_POLLING_INTERVAL_SECS` | `10` | 非同期ポーリングのフォールバック間隔。 |
| `EVALUATOR_REQUEST_TIMEOUT_MS` | `30000` | リクエストごとのエバリュエータータイムアウト（POST および各ポーリングに適用）。 |
| `EVALUATOR_MAX_ATTEMPTS` | `5` | 終了失敗前の配信試行回数。 |
| `EVALUATOR_CONFIG_REFRESH_SECS` | `300` | `/config` のリフレッシュ間隔。 |
| `EVALUATOR_MAX_POLL_DURATION_SECS` | `3600` | 非同期ポーリングの最大ウォールクロック時間。 |

このテーブルから特に重要な点を2つ挙げます:

- **ワーカー数 × クレームバッチ数が同時実行数です。** デフォルト設定では、デプロイメント全体でエンドポイントへの同時呼び出しが8件になります。1件ではなくこの数に合わせてサービスをサイジングしてください。
- **4xx は終了扱いで、5xx・429・トランスポート障害はバックオフを伴って `EVALUATOR_MAX_ATTEMPTS` まで再試行されます。** トークンの不一致は 401 となり、再試行せずに即座に失敗します — 何も届かない場合はまずこれを確認してください。

サーバーは、デプロイメントグローバルなエバリュエーターを使用できる組織を制限することもできます。エンドポイント、トークン、再試行、組織ゲートの変更は運用者設定として扱い、変更後はサーバーを再起動またはロールアウトしてください。

## セキュリティと運用

- トラフィックが信頼されたネットワーク境界を越える場合は、エバリュエーターを HTTPS の背後に置いてください。
- 空でない Bearer トークンを設定し、両方のサービスで同一の値を保持してください。`token=None` はすべての呼び出し元を受け付けます。
- トークンやリクエストペイロードの機密性の高いプロンプト全体をログに記録しないでください。SDK はこれを行いません: バリデーション失敗時はペイロードをエコーせずに 422 を返し、500 では例外テキストをエコーせず、トークンはどのログフィールドにも表示されません。
- 同期ハンドラーはべき等にしてください。再試行によりリクエストが繰り返される可能性があります。
- 本番環境では非同期ジョブの状態をプロセスメモリ外で永続化してください。
- 安定したスコアキーを返してください。キーを変更すると古い系列が変わるのではなく、新しいチャート系列が作成されます。

SDK は `eval received`、`eval responded`、`job lookup`、`config returned`、`auth rejected`、ハンドラー例外などの構造化されたライフサイクルログを出力します。`/config` レスポンスには `source="user"` と `source="default"` のタグが付くため、`@app.config` が認識されているかどうかを確認できます。SDK はロギングハンドラーを設定しません。ホストアプリケーションのロギング設定を使用してください。
