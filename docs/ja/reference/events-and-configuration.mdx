## イベントファミリー

- エージェントの開始、終了、一時停止、再開
- モデルのリクエストとレスポンス
- ツールの使用と結果
- フックのトリガーと完了
- 人間の待機、入力、一時停止、割り込み
- 明示的なエラー

すべてのイベントには、タイムスタンプ、セッションID、エージェントID、イベントタイプ、および環境が含まれます。イベント固有のフィールドには、モデル、ツール、相関、結果、コンテンツ、継続時間、またはエラーのデータが含まれます。

## イベントコントラクトを調べる

<Tabs>
  <Tab title="ダッシュボード">
    1. **Observe → Events** を開きます。
    2. 短い時間範囲を設定し、環境、エージェント、イベントタイプでフィルタリングします。
    3. イベントを選択して正規化されたフィールドと生のペイロードを確認し、セッションを開いて実行コンテキストを確認します。
    4. ペアの継続時間が見つからない場合は、開始イベントと完了イベントが同じ相関IDを使用しているか確認してください。

    Eventsストリームを使用してデータを1つのエージェント実行に絞り込み、正規化されたイベントフィールドを調べます。

    ![環境、エージェント、セッション、イベントタイプのフィルターが付いたライブEventsストリーム。](/images/dashboard/events-stream.png)

    次に、イベントからそのセッションへと進みます。トレースには、そのイベントの直前と直後に何が起きたかが表示されます。これは、ペイロードだけでは判断が難しい場合に必要な情報です。

    ![実行コンテキストでイベントを調べるために使用されるリンクされたセッショントレース。](/images/dashboard/session-detail.png)

    ペアになったイベントや継続時間が見つからない場合は、両方のビューで相関IDとタイムスタンプを比較してください。
  </Tab>
  <Tab title="CLI">
    有効なフィルター値を確認し、1つのセッションのイベントペイロード全体を取得します：

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    機械可読な形式での確認には `fp --json events ... --fields ts,event_type,session_id,payload` を使用してください。
  </Tab>
</Tabs>

## 予約済みSDKフィールド

`timestamp`、`session_id`、`agent_id`、`type`、`environment` をカスタムPython SDKフィールドとして使用しないでください。ツール結果の継続時間などのペアイベントの継続時間はSDKによって計算されるため、手動で設定することはできません。

## ローカルの境界

- Failproof AI の状態は、明示的に別の設定をしない限り `~/.failproofai` 以下に保存されます。
- `failproofai-sdk` は常に `~/.failproofai/custom-agents` にスプールします。`FAILPROOFAI_HOME` でホームディレクトリを変更できますが、`custom-agents` セグメントは常に追加されるため、スプールをその外に配置することはできません。SDKの `configure(base_dir=...)` のみが別の場所に書き込みます。`AGENTEYE_HOME` は古い `agenteye-collector` が監視対象を決定するために読み取るものであり、SDKの書き込み先には影響しません。
- 環境ラベルはSDK設定または `AGENTEYE_ENVIRONMENT` で設定できます。
- デーモンの認証情報は、非シークレット設定とは別に保存されます。

安定した、カーディナリティの低い環境名を使用してください。デーモンの環境ラベルにカンマは使用できません。

## 環境ラベルを変更する

<Tabs>
  <Tab title="ダッシュボード">
    環境ラベルは、送信するSDKまたは Failproof デーモンによって割り当てられます。変更後は、**Observe → Sessions** を開き、環境フィルターを使用して新しいセッションに新しい値が反映されていることを確認してください。既存のセッションは元の環境を保持します。

  </Tab>
  <Tab title="CLI">
    `failproofai-sdk` の場合は、コード内またはレガシーの環境変数で環境を設定します。マシンレベルの設定を変更する場合はデーモンの設定を再実行してください。

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
