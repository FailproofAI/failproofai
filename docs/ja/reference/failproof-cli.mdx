`npm install -g failproofai` でインストールします。引数なしで `failproofai` を実行すると、ローカルダッシュボードが開きます。

## 主要コマンド

| コマンド | 内容 |
| --- | --- |
| `failproofai config` | エージェント、バックグラウンドサービス、オプションのCloud接続をセットアップします |
| `failproofai config --token <key>` | 質問なしでセットアップおよび接続します |
| `failproofai config --status` | 接続状態、サービスバージョン、一時停止状態を表示します |
| `failproofai policies` | ポリシーの一覧と有効/無効の状態を表示します |
| `failproofai policies add <name>` | 特定のポリシーを有効にします |
| `failproofai policies add <owner>/<repo>` | ポリシーパックをインストールします |
| `failproofai policies remove <name-or-pack>` | ポリシーを無効にするか、パックを削除します |
| `failproofai policies show <owner>/<repo>` | インストール前にパックの内容を確認します |
| `failproofai publish` | ポリシーをパックとして公開します |
| `failproofai audit` | ローカルのエージェント履歴をスキャンします |
| `failproofai harness` | 追加のセッションロケーションを管理します |
| `failproofai flush` | キューに溜まったイベントをすぐに送信します |
| `failproofai backfill` | 古いエージェント履歴を再読み込みします |
| `failproofai update` | npm のアップグレードを完了し、サービスを更新します |
| `failproofai uninstall` | フックとサービスを削除します |

`policy`、`pack`、`p` は `policies` のエイリアスとして使用できますが、ドキュメントでは `policies` を使用します。

## マシンのセットアップ

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

セットアップ時にポリシーパックは選択されません。パックを追加するまでは、`block-failproofai-commands` のみが実行されます。

Cloud の無人セットアップの場合:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

トランスクリプトなしで決定内容を送信するには、まず接続してから `~/.failproofai/config.json` の `collector.sessions` を `false` に設定します。現在の `--no-transcripts` セットアップフラグは解析されますが、その設定は適用されません。

マシンが接続された後に `--machine-label <name>` を使用して名前を変更できます。`--connect <url>` は、すでにセットアップ済みのマシンを登録するだけの、より限定的なコマンドです。

## ポリシーとパック

```bash
failproofai policies
failproofai policies add block-sudo
failproofai policies show owner/repo
failproofai policies add owner/repo --category git,database
failproofai policies remove owner/repo
```

スラッシュを含むものはパックのソース、含まないものはポリシー名として扱われます。

パック選択に役立つフラグ:

| フラグ | 用途 |
| --- | --- |
| `--policy a,b` | 指定した名前のポリシーを選択します |
| `--category x,y` | カテゴリを選択します |
| `--all` | すべてを選択します |
| `--cli <agents...>` | 指定したハーネスに限定します |

任意のパスからカスタムポリシーを読み込むには `failproofai policies -i -c <path>` を使用します。`.failproofai/policies/` 以下の `*policies.{js,mjs,ts}` という名前のファイルは自動的に読み込まれます。

## 強制執行の一時停止

```bash
failproofai config --pause 10m
failproofai config --status
failproofai config --resume
```

一時停止は1つのローカルセッションに適用され、常に期限切れになります。Cloud管理のポリシーや `block-failproofai-commands` は一時停止されません。

## 監査と配信

```bash
failproofai audit
failproofai audit --schedule 7 --email team@example.com
failproofai audit --status
failproofai flush --wait
failproofai backfill --since 30d --dry-run
```

`backfill` は `~/.failproofai/config.json` を読み込みます。`--dry-run` を外すと履歴を再送信します。

## 追加のセッションロケーション

```bash
failproofai harness list
failproofai harness add-path claude work=/srv/team/.claude/projects
failproofai harness remove-path claude work
```

ラベルを使用すると、コピーされた2つのホームのセッションが同じ派生エージェントIDの下にマージされるのを防ぎます。

サポートされているハーネスは `claude`、`codex`、`copilot`、`cursor`、`opencode`、`pi`、`hermes`、`openclaw`、`factory`、`devin`、`antigravity`、`goose` です。スコープのサポートは異なります。詳細は [Harnesses](/ja/reference/harnesses) を参照してください。

## 便利な環境変数

| 変数 | 用途 |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | CloudマシンのAPIキー |
| `FAILPROOFAI_CLOUD_URL` | Cloud URLを上書きします |
| `FAILPROOFAI_HOME` | ローカルの状態ディレクトリを移動します |
| `FAILPROOFAI_NO_DOWNLOAD=1` | パックおよびサービスのダウンロードを拒否します |
| `FAILPROOFAI_DAEMON_BASE_URL` | サービスバイナリのミラーを使用します |
| `FAILPROOFAI_PACK_BASE_URL` | パックのミラーを使用します |
| `FAILPROOFAI_NO_FIRST_RUN=1` | 初回起動時のプロンプトを無効にします |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | 匿名CLIテレメトリを無効にします |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | 特定のハーネスの追加パスを置き換えます |
| `NO_COLOR` | ターミナルのカラー表示を無効にします |

## 削除またはアップグレード

```bash
npm install -g failproofai@latest
failproofai update
```

パッケージを削除する前に:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

<Warning>
  npm パッケージを削除する前に `failproofai uninstall` を実行してください。npm はインストールされたフックやバックグラウンドサービスを削除しません。
</Warning>

インストール済みのバージョンで使用できる完全なオプションを確認するには、`failproofai help <command>` を実行してください。
