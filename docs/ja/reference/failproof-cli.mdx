`npm install -g failproofai` でローカル CLI をインストールします。引数なしで実行するとローカルポリシーダッシュボードが開きます。

このパッケージには Node.js 20.9 以降が必要です。開発およびソースインストールには Bun 1.3 以降がサポートされています。`failproofai configure` および `failproofai setup` は `failproofai config` のエイリアスです。`failproofai policy`、`failproofai pack`、`failproofai p` はいずれも `failproofai policies` の別名です — パックと単体ポリシーはもともと 3 つのコマンドで 1 つの概念を表していましたが、現在は 1 つに統合されています。古い表記は引き続き使用できますが、2 つの例外があります: `pack list <source>` は `policies show <source>` に、`pack build` は `publish` になりました。

## マシンのセットアップ

CLI をインストールし、マシンキーをシェルに読み込みます。`read -s` はエコーしないプロンプトでキーを取得するため、コマンドに表示されることはありません:

```bash
npm install -g failproofai
read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
```

次に、マシンをセットアップし、適用するポリシーを選択します:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

`failproofai config` はセットアップのすべてを担います: `failproofaid` サービスのインストール（root として 1 回 — ターミナルでは sudo パスワードを求め、セットアップが完了する前にタイムアウトした場合は再度確認します; ターミナルなしの場合は `sudo -n` を使用してプロンプトは表示しません）、見つかったすべてのエージェント CLI へのフックの接続、Cloud への接続を行います。ターミナルなしの環境（CI、コンテナ、エージェントによる操作）では、確認なしで適用し、要求された処理が完了しなかった場合は終了コード 1 で終了します。

ターミナルでは、未接続のマシンでの **Connect to cloud** ステップはすぐに **FailproofAI Cloud へのログイン** を開始します。Tab キーを押すと、**Paste an API key** または **Use open source** の選択肢が表示されます。ログインするとリンクが開き（SSH 接続時やディスプレイがない場合は印刷されるので、任意のデバイスで開けます）、サインアップまたはサインイン、組織の選択または作成、マシンの承認を行います。ターミナルは承認を自動的に検出し、承認者と組織を表示します。キーはデーモンのインストール後、セットアップ完了時のみ発行されます。有効なキーで既に接続されているマシンでは、このステップは **Keep current connection** が先頭に表示されるメニューになるため、セットアップを再実行してもブラウザが自動的に開くことはありません。動作しなくなった保存済みキーは即座にログインを再開し、理由を表示します。再ログインすると新しいキーが作成され、古いキーは失効させるまで有効です。ブラウザログイン以前の Cloud の場合はその旨が表示され、他のオプションが提示されます。

ポリシーは**何も**選択されません。それは 2 番目のコマンドの役割であり、指定しない場合、設定したばかりのマシンは常時稼働のガードのみを適用します。

`--token` よりも環境変数を優先してください: コマンドライン引数はマシン上のすべてのユーザーが `ps` から読み取ることができます。変数が防ぐのはその点だけです — `export` を含むコマンドに入力したキーはシェル履歴に残ります。そのため、上記のように `read -s` で読み込んでいます。CI では、シークレットストアから設定し、シェルトレース（`set -x`）をオフにしてください。オンにすると値が印刷されます。

<Warning>
  `--connect <url>` は**すでにセットアップ済みの**マシンを登録します。登録が成功するとすぐに返ります — デーモンのインストールもフックの接続も行いません。まだセットアップされていないマシンには通常の `failproofai config`（または `failproofai config --token <key>`）を使用してください。そうしないと、接続済みとして認識されながら何も収集・適用しない状態になります。
</Warning>

引数なしで `failproofai` を実行するとローカルポリシーダッシュボードが開きます。

| コマンド | 説明 |
| --- | --- |
| `failproofai config` | マシンをセットアップ: エージェント、デーモン、Cloud — ブラウザでログイン、キーを貼り付け、またはオープンソースで使用。マシン上のすべてのエージェントに [FailproofAI skills](https://github.com/FailproofAI/skills) を指し示す小さな `failproofai` スキルも追加されます |
| `failproofai config --token <key>` | 確認なしで一括セットアップと接続。`jev:evaluate` 権限を持つキーは、`jev.json` が既に存在するか `--no-transcripts` が指定されている場合を除き、観察モードで [Jev through FailproofAI Cloud](/ja/reference/jev-cloud) を有効にします |
| `failproofai config --connect <url>` | **すでに**セットアップされたマシンを登録 — デーモンなし、フックなし |
| `failproofai config --status` | 接続、デーモン、配信、一時停止の状態を表示 |
| `failproofai policies` | ビルトイン、カスタム、規約、パック、Cloud 管理ポリシーを一覧表示 |
| `failproofai policies --install` | エージェント CLI にフックを接続。単独ではポリシーを有効にしません |
| `failproofai policies add <name>` | ポリシーを 1 つ有効化 — ビルトイン、またはインストール済みパックの `<pack-id>:<name>` |
| `failproofai policies remove <name>` | ポリシーを 1 つ無効化、同じ命名規則 |
| `failproofai policies --uninstall` | ポリシーを無効化またはハーネスフックを削除 |
| `failproofai policies show <owner>/<repo>` | パックの内容をマニフェストから確認（インストール前に） |
| `failproofai policies show <owner>/<repo> --releases` | 公開されたすべてのバージョンと現在のバージョン |
| `failproofai policies add <source>` | GitHub リリースからポリシーパックをインストール。タグなしの場合は最新を取得してピン留め |
| `failproofai publish` | 自分のポリシーをパックとして公開。`--init` でひな形を生成、`--min-cli-version <version>` でインストール可能な最古の CLI バージョンを設定（[Jev checks in a pack](/ja/policies/publish-a-pack#jev-checks-in-a-pack)） |
| `failproofai policies remove <publisher/name>` | パックをアンインストール |
| `failproofai audit` | ローカルエージェント履歴をスキャンしてローカル監査ビューを開く |
| `failproofai audit --schedule [days] --email <address>` | 定期的なローカルスキャンをスケジュールし、結果をメールで送信 |
| `failproofai audit --status` | レポート先アドレス、間隔、次回スキャン予定を表示 |
| `failproofai audit --no-schedule` | 監査履歴を削除せずに定期スキャンを停止 |
| `failproofai harness list` | 追加のキャプチャパスを一覧表示 |
| `failproofai otel status` | オプションの [OpenTelemetry レポート](/ja/reference/otel) を確認 |
| `failproofai jev --url <url> --key-stdin` | Jev を一括セットアップ。プロバイダーは URL のホストから自動取得 |
| `failproofai jev setup --provider <kind> --key-stdin` | [Jev](/ja/reference/jev-providers) が自分のエンドポイントとキーでツール呼び出しを判定するよう設定 |
| `failproofai jev setup --provider failproofai` | このマシンの Cloud キーを使って [FailproofAI Cloud 経由](/ja/reference/jev-cloud) で Jev がツール呼び出しを判定するよう設定 |
| `failproofai jev setup --mode <m>` | Jev のモードを切り替え: `enforce`、`observe`、または `off`（設定を保持しつつ Jev への問い合わせを停止） |
| `failproofai jev status` | Jev の設定、権限、最近のフォールバックを表示（キーは表示しない） |
| `failproofai jev test` | Jev リクエストを 1 件実行し、レイテンシとバージョンを表示。応答が遅いまたは不正な場合は終了コード 1 |
| `failproofai jev models` | エンドポイントの `GET <base>/models` が返すモデル ID を一覧表示 |
| `failproofai jev remove` | Jev をオフにする。フックは以前と同様に正規表現ポリシーを実行 |
| `failproofai flush --wait` | 現在のイベントスプールを配信 |
| `failproofai backfill --since 30d` | 以前に通過した履歴を再読み込み |
| `failproofai config --pause [duration]` | 現在のディレクトリの 1 セッションをデフォルト 30 分（最大 8 時間）一時停止 |
| `failproofai config --resume` | 一時停止中の 1 セッションを再開。`--all` ですべての一時停止を解除 |
| `failproofai update` | パッケージの移行を完了してデーモンを更新 |
| `failproofai migrate --dry-run` | ホームレイアウトの移行をプレビューまたは実行 |
| `failproofai uninstall` | パッケージ削除前にフック、`failproofai` スキル、デーモンを削除 |
| `failproofai --version` | インストール済みパッケージのバージョンを表示 |
| `failproofai --help` | コマンドと使い方を表示 |

## 設定フラグ

| フラグ | 用途 |
| --- | --- |
| `--token <key>` | 非対話型でセットアップと接続。`FAILPROOFAI_CLOUD_TOKEN` からも読み取り |
| `--url <url>` | `app.befailproof.ai` 以外の場所に接続。`FAILPROOFAI_CLOUD_URL` からも読み取り |
| `--connect <url>` | すでにセットアップ済みのマシンで登録のみ。デーモンとすべてのフックをスキップ |
| `--machine-id <id>` | 固定マシン ID を設定 |
| `--machine-label <name>` | **すでに接続されている**マシンの名前を変更。単独ではセットアップを実行しないため、`failproofai config` の後に指定してください（実行中には指定しない） |
| `--no-transcripts` | トランスクリプトの内容なしで判定を送信し、Cloud Jev を有効にしません（確認済みのツール呼び出しと最近のプロンプトを送信する）。FailproofAI Cloud 経由で Jev を実行している `jev.json` は削除されます |
| `--disconnect` | Cloud ポリシーの取得とイベント配信を停止。Cloud Jev キーおよび FailproofAI Cloud を参照する `jev.json` も削除。自分の Jev セットアップはそのまま残ります |
| `--status` | 現在のマシン状態を表示 |
| `--pause [duration]` | 現在のディレクトリの最新セッションを一時停止。秒、分、または時間を指定でき、デフォルトは 30 分 |
| `--resume` | 該当する一時停止を早期終了 |
| `--session <id>` | 一時停止または再開の対象セッションを指定 |
| `--all` | `--resume` と組み合わせて、すべてのアクティブな一時停止を終了 |

ローカルセッションの一時停止は、1 セッションのビルトイン、カスタム、規約、パックポリシーを停止します。常に期限があり、Cloud 管理ポリシーは無効化されません。`block-failproofai-commands` — 常に有効で、無効化も一時停止もできません — は、インストルメントされたエージェントがこのエスケープハッチ自体を使用することを防ぎます。

## ポリシーフラグ

| フラグ | 用途 |
| --- | --- |
| `--install`, `-i` | ハーネスフックをインストール。後続の名前はそれらのポリシーを有効化。指定なしの場合はポリシー変更なし |
| `--uninstall`, `-u` | ポリシーを無効化またはフックを削除 |
| `--cli <names...>` | 1 つ以上のサポートされたハーネスを対象に指定 |
| `--scope user\|project\|local\|all` | 設定スコープを選択。`all` はアンインストール用 |
| `--beta` | ベータポリシーを含める |
| `--custom`, `-c <path>` | カスタムポリシーファイルを検証してロード。繰り返し指定可能 |

## 配信とメンテナンスフラグ

| コマンド | フラグ |
| --- | --- |
| `backfill` | `--since <30d\|6m\|YYYY-MM-DD>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` |

`failproofai update` は `npm install -g failproofai@latest` の後に実行してください。ホームレイアウトの移行、対応するデーモンバイナリのインストール、サービスの再起動を行います。また、FailproofAI を使用している Hermes プロファイルをリンク済みのネイティブプラグインに移行し、プロファイルごとに 1 行を表示します。`--no-daemon` はデーモンのステップをスキップします。`update` は、デーモンの置換に失敗した場合、移行が失敗した場合、または Hermes プロファイルの移行に失敗した場合（例: 実行中のデーモンがネイティブプラグインを提供できない場合、その場合はシェルフックがそのまま残ります）に非ゼロで終了します。

## ハーネスパス

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

サポートされているハーネス名は `claude`、`codex`、`copilot`、`cursor`、`opencode`、`pi`、`hermes`、`openclaw`、`factory`、`devin`、`antigravity`、`goose` です。

ラベルは、2 つのルートが同じプロジェクトのコピーを含む場合に、派生エージェント ID の名前空間を分けます。重複するルートと重複するラベルは、コレクションの重複やカーソルの破損を防ぐために拒否されます。追加パスの設定はデーモンを再起動せずにリロードされます。

コンテナ環境では、ファイルで設定された追加パスを、`FAILPROOFAI_<HARNESS>_EXTRA_PATHS` という名前のカンマ区切り変数で置き換えることができます。例:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## 環境変数

永続的なマシン動作には設定ファイルを使用してください。環境変数はコンテナ、テスト、1 プロセスに対して最も有効です。

| 変数 | 用途 |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | `--token` の代わりに使用する Cloud キー。こちらを優先してください: 引数はマシン上のすべてのユーザーが `ps` から読み取れます。`read -s` または CI シークレットストアで設定し、コマンドに直接入力しないでください（どちらの方法でもシェル履歴に残ります） |
| `FAILPROOFAI_CLOUD_URL` | `--url` の代わりに使用する Cloud URL。デーモンも読み取る変数です |
| `FAILPROOFAI_HOME` | `~/.failproofai` のレイアウト全体を別の場所に移動 |
| `FAILPROOFAI_LOG_LEVEL` | ローカルログの詳細レベルを設定 |
| `FAILPROOFAI_HOOK_LOG_FILE` | フックの診断情報を指定ファイルに書き込む |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | このプロセスの匿名テレメトリを無効化 |
| `FAILPROOFAI_NO_FIRST_RUN=1` | インタラクティブな初回セットアップをスキップ |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | セットアップ後のローカル監査をスキップ |
| `FAILPROOFAI_LLM_BASE_URL` | LLM ポリシーが使用する OpenAI 互換エンドポイントを上書き |
| `FAILPROOFAI_LLM_API_KEY` | LLM ポリシーが使用する API キーを指定 |
| `FAILPROOFAI_LLM_MODEL` | LLM ポリシーが使用するモデルを選択 |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | カスタムポリシーモジュールのロードタイムアウトを制限 |
| `FAILPROOFAI_NO_DOWNLOAD=1` | パックとデーモンバイナリの取得を拒否。インストール済みのものは引き続き適用 |
| `FAILPROOFAI_PACK_BASE_URL` | `github.com` の代わりにミラーからパックを取得 |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | 1 つのハーネスの設定済み追加キャプチャパスを置き換え |
| `NO_COLOR` | ターミナルのカラー出力を無効化 |

`CLAUDE_PROJECTS_PATH`、`CURSOR_HOME`、`HERMES_HOME`、`OPENCLAW_HOME` などのエージェント固有のホーム変数は、Failproof AI がそのハーネスのローカルセッションを検出する場所を上書きします。

## マシンの一時停止と安全な削除

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

ローカルセッションの一時停止は Cloud 管理ポリシーを無効にしません。ロールアウト自体に問題がある場合は、Cloud の適用ワークフローを通じて Cloud デプロイメントを復元してください。

npm パッケージを削除する前に、インストール済みのフックとデーモンを削除してください:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

バージョン固有の詳細については `failproofai <command> --help` を実行してください。

<Warning>
  `npm rm -g failproofai` の前に `failproofai uninstall` を実行してください。npm はインストール済みのエージェントフック、`failproofai` スキル、デーモンサービスを削除しません。
</Warning>
