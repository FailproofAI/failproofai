ハーネスとは、エージェントが実際に動作する環境のことです。Failproof AI は12種類のハーネスを2つのクラスに分けてサポートしています。

- **コーディングCLI**（10種）— Claude Code、Codex、GitHub Copilot CLI、Cursor、OpenCode、Pi、Factory Droid、Devin CLI、Antigravity CLI、Goose
- **チャット・アシスタントゲートウェイ**（2種）— Hermes（Slack、Telegram、cron）、OpenClaw（セルフホスト型アシスタント）

どのハーネスでエージェントが動作していても、同じポリシーと同じセッション履歴が適用されます。アダプター層が各ハーネスのネイティブイベント名、ツール名、ツール入力フィールドを29の標準イベントにマッピングしてから、ポリシーが実行されます。

12種類のいずれにも属さないエージェントは、[Python SDK](/ja/reference/custom-agents) を使って直接インスツルメントします。これは別のコントラクトであり、明確に説明しておく価値があります。SDKはトレーシング、セッション、評価、監査を提供しますが、**それ自体ではポリシーを適用しません。** 安全でないアクションが実行される前にブロックするには、ランタイムのツール境界にエンフォースメントフックが必要です。[お問い合わせ](mailto:support@befailproof.ai)いただければ、マッピングをご支援します。

| ハーネス | サポートされているフックスコープ |
| --- | --- |
| Claude Code | User、project、local |
| Codex、GitHub Copilot CLI、Cursor、OpenCode、Pi | User、project |
| Factory Droid、Devin CLI、Antigravity CLI、Goose | User、project |
| Hermes、OpenClaw | User |

各インテグレーションは、ポリシーが実行される前にネイティブフックイベント名、ツール名、ツール入力フィールドを正規化します。ポリシーはハーネスが公開するイベントに対してのみ作用します。ターン終了時の動作やインストラクションの動作は、デプロイする実際のハーネスとバージョンでテストしてください。

## エンフォースメント機能

「ブロック」とは、現在のアダプターが返す評決が、指定されたハーネスによって消費されることを意味します。ポストツールブロッキングはモデルに表示される結果を置き換えることができますが、すでに発生したツールの副作用を取り消すことはできません。

| ハーネス | 検証済みブロッキングイベント | 観察のみまたは非ブロッキングの注意事項 |
| --- | --- | --- |
| Claude Code | `PreToolUse`、`UserPromptSubmit`、`PermissionRequest`、`Stop`、`SubagentStop`、`PreCompact`、およびいくつかのタスク/設定イベント | `PostToolUse`、セッションライフサイクル、通知、失敗後のイベントは観察のみです。 |
| Codex | `PreToolUse`、`PermissionRequest`、`UserPromptSubmit`、`Stop`、`SubagentStop`、`PostToolUse` | ポストツールブロッキングは実行後に結果を置き換えます。セッション開始とコンパクトイベントは現在のアダプターでは観察のみです。 |
| GitHub Copilot CLI | `PreToolUse`、`UserPromptSubmit`、`PermissionRequest`、`Stop`、`SubagentStop`、`PostToolUse` | ポストツールブロッキングは実行後に結果を置き換えます。セッションと通知イベントは観察のみです。 |
| Cursor | `PreToolUse`、`UserPromptSubmit`、`Stop` | `PostToolUse` とセッションイベントは観察のみです。 |
| OpenCode | `PreToolUse` | ポストツールおよびライフサイクルイベントは観察のみです。現在の停止処理は検証済みゲートではなく、後のターンへのガイダンスです。 |
| Pi | `PreToolUse`、`UserPromptSubmit` | ポストツールおよびライフサイクルイベントは観察のみです。停止ガイダンスは後のターンに適用されます。 |
| Hermes | `PreToolUse` | ポストツール、セッション、サブエージェント停止の評決はゲートではありません。 |
| OpenClaw | `PreToolUse`、`UserPromptSubmit`、`Stop` | ポストツール、セッション、サブエージェント停止、コンパクションイベントは観察のみです。 |
| Factory Droid | `PreToolUse`、`UserPromptSubmit`、`Stop`、`PreCompact` | ポストツールとサブエージェント停止の評決は観察のみです。 |
| Devin CLI | `PreToolUse`、`UserPromptSubmit`、`Stop`、条件付き `PermissionRequest` | パーミッションフックはすべてのパーミッションモードで動作するわけではありません。ポストツールとセッションイベントは観察のみです。 |
| Antigravity CLI | `PreToolUse`、`Stop` | ユーザープロンプトとポストツールの評決は観察のみです。プロンプトインストラクションは引き続き注入できます。 |
| Goose | `PreToolUse` | ユーザープロンプト、ポストツール、セッションイベントは観察のみです。ネイティブのブロッキング停止フックが上流に存在しますが、現在のアダプターではインストールされていません。 |

機能はバージョンに依存します。エージェントCLIをアップグレードした後は、特にポリシーが共通のプリツールゲートではなく、プロンプト、停止、パーミッション、またはポストツールの動作に依存している場合は、再テストしてください。

## キャプチャとポリシーフックのインストール

<Tabs>
  <Tab title="ダッシュボード">
    1. **Administration → Keys** を開き、`events:add` と `policies:pull` の権限を持つキーをマシンまたは環境の名前で作成します。
    2. 対象マシンで、表示されたキーを使ってローカルCLIを接続し、ハーネスフックをインストールします。
    3. 新しいエージェントセッションを開始し、**Observe → Events** でそのフックとセッションイベントを確認します。
    4. 同じ時間枠で **Observe → policy** を開き、ポリシー決定がそのマシンに帰属していることを確認します。

    接続はマシンキーから始まります。シークレットをコピーする前に、インジェスションとポリシー配信の両方の権限が含まれていることを確認してください。

    ![イベントインジェストとポリシー配信の権限を付与するために使用する新しいAPIキードロワー。](/images/dashboard/key-create.png)

    フックをインストールした後、Events ストリームには接続したマシンと環境からの新しいイベントが表示されるはずです。

    ![新しくインストールされたハーネスが報告しているかどうかを確認するためのライブEventsストリーム。](/images/dashboard/events-stream.png)

    最後に、ポリシー決定が同じマシンに帰属していることを確認します。これにより、ハーネスがトレースイベントだけでなくポリシーアクティビティも報告していることが確認できます。

    ![新しく接続されたハーネスからのポリシー決定を確認するためのPolicyページ。](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    検出されたすべてのハーネスにフックをインストールします。

    ```bash
    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>
    failproofai policies --install
    ```

    または、特定のハーネスと設定スコープを指定します。

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    プロジェクトスコープはフック設定をリポジトリと一緒に保持します。ユーザースコープはリポジトリをまたいだ作業をカバーします。Claude Code はローカルスコープもサポートしていますが、サポート状況はハーネスによって異なり、CLIはサポートされていない組み合わせを拒否します。

    マシンとそのイベントを確認します。

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## デフォルト以外のセッションパスの追加

<Tabs>
  <Tab title="ダッシュボード">
    追加パスはクラウドではなくマシン上で登録されます。追加した後、**Observe → Sessions** を開き、マシンの環境でフィルタリングして、新しいパスからのセッションが表示されることを確認します。監査で使用する前に、セッションを開いてエージェント、ハーネス、イベントのタイムスタンプを確認してください。

    ![追加のキャプチャパスからデータを受信している環境にフィルタリングされたSessionsリスト。](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    オプションのラベルを付けてパスを追加し、設定済みのパスを確認します。

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    パスを削除するには `failproofai harness remove-path claude checkout` を使用します。
  </Tab>
</Tabs>

<Tip>
  インストール後に新しいセッションを1つ実行してください。ロールアウトを拡大する前に、ライブイベントストリームと実際のポリシー決定の両方を確認してください。
</Tip>
