ハーネスとは、エージェントが実際に動作する環境のことです。Failproof AI は12種類のハーネスをサポートしており、2つのカテゴリに分かれています。

- **コーディングCLI**（10種類）— Claude Code、Codex、GitHub Copilot CLI、Cursor、OpenCode、Pi、Factory Droid、Devin CLI、Antigravity CLI、Goose
- **チャット・アシスタントゲートウェイ**（2種類）— Hermes（Slack、Telegram、cron）、OpenClaw（セルフホスト型アシスタント）

どのハーネスでエージェントが動作していても、同じポリシーと同じセッション履歴が適用されます。各ハーネスのネイティブなイベント名、ツール名、ツール入力フィールドを29の標準イベントにマッピングするアダプターレイヤーが、ポリシー実行前に機能します。

12種類のいずれにも該当しないハーネスでエージェントが動作している場合は、[Python SDK](/ja/reference/custom-agents) を使って直接インストルメント化してください。これは異なる契約であり、明示しておく必要があります。SDKはトレーシング、セッション、評価、監査を提供しますが、**それ自体ではポリシーを適用しません。** 安全でないアクションを実行前にブロックするには、ランタイムのツール境界に適用フックが必要です。[お問い合わせ](mailto:support@befailproof.ai)いただければ、マッピングを対応いたします。

| ハーネス | サポートされているフックスコープ |
| --- | --- |
| Claude Code | ユーザー、プロジェクト、ローカル |
| Codex、GitHub Copilot CLI、Cursor、OpenCode、Pi | ユーザー、プロジェクト |
| Factory Droid、Devin CLI、Antigravity CLI、Goose | ユーザー、プロジェクト |
| Hermes、OpenClaw | ユーザー |

各インテグレーションは、ポリシー実行前にネイティブなフックイベント名、ツール名、ツール入力フィールドを正規化します。ポリシーはハーネスが公開するイベントにのみ作用できます。ターン終了時および指示動作は、実際にデプロイするハーネスとバージョンでテストしてください。

## 適用能力

「ブロック」とは、現在のアダプターが返す判定が指定のハーネスによって消費されることを意味します。ポストツールのブロックはモデルに表示される結果を置き換えることができますが、すでに発生したツールの副作用を元に戻すことはできません。

| ハーネス | 検証済みブロックイベント | 観察専用または非ブロックの注意事項 |
| --- | --- | --- |
| Claude Code | `PreToolUse`、`UserPromptSubmit`、`PermissionRequest`、`Stop`、`SubagentStop`、`PreCompact`、および複数のタスク・設定イベント | `PostToolUse`、セッションライフサイクル、通知、および障害後イベントは観察専用です。 |
| Codex | `PreToolUse`、`PermissionRequest`、`UserPromptSubmit`、`Stop`、`SubagentStop`、`PostToolUse` | ポストツールのブロックは実行後に結果を置き換えます。セッション開始およびコンパクトイベントは現在のアダプターでは観察専用です。 |
| GitHub Copilot CLI | `PreToolUse`、`UserPromptSubmit`、`PermissionRequest`、`Stop`、`SubagentStop`、`PostToolUse` | ポストツールのブロックは実行後に結果を置き換えます。セッションおよび通知イベントは観察専用です。 |
| Cursor | `PreToolUse`、`UserPromptSubmit`、`Stop` | `PostToolUse` およびセッションイベントは観察専用です。 |
| OpenCode | `PreToolUse` | ポストツールおよびライフサイクルイベントは観察専用です。現在の停止処理は検証済みゲートではなく、後のターンへのガイダンスです。 |
| Pi | `PreToolUse`、`UserPromptSubmit` | ポストツールおよびライフサイクルイベントは観察専用です。停止ガイダンスは後のターンに適用されます。 |
| Hermes | `PreToolUse` | `deny()` はブロックします。`instruct()` は呼び出しを停止しません。呼び出しは実行され、ガイダンスはその結果の先頭に配置されます。ポストツール、セッション、およびサブエージェント停止の判定はゲートではありません。 |
| OpenClaw | `PreToolUse`、`UserPromptSubmit`、`Stop` | ポストツール、セッション、サブエージェント停止、およびコンパクションイベントは観察専用です。 |
| Factory Droid | `PreToolUse`、`UserPromptSubmit`、`Stop`、`PreCompact` | ポストツールおよびサブエージェント停止の判定は観察専用です。 |
| Devin CLI | `PreToolUse`、`UserPromptSubmit`、`Stop`、条件付き `PermissionRequest` | 権限フックはすべての権限モードで実行されるわけではありません。ポストツールおよびセッションイベントは観察専用です。 |
| Antigravity CLI | `PreToolUse`、`Stop` | ユーザープロンプトおよびポストツールの判定は観察専用です。プロンプト指示は引き続きインジェクトできます。 |
| Goose | `PreToolUse` | ユーザープロンプト、ポストツール、およびセッションイベントは観察専用です。ネイティブのブロッキング停止フックがアップストリームに存在しますが、現在のアダプターではインストールされていません。 |

機能はバージョンに依存します。エージェントCLIをアップグレードした後は再テストしてください。特に、ポリシーが共通のプリツールゲートではなく、プロンプト、停止、権限、またはポストツールの動作に依存している場合は重要です。

### Hermesネイティブプラグイン

Hermes はシェルコマンドではなく、プロファイルローカルのネイティブプラグインを通じて統合されています。インストール時に、すべてのデフォルトおよび名前付きHermesプロファイルの `plugins/failproofai` が npm パッケージに同梱されたプラグイン（シンボリックリンクを作成できない場合はコピー）にリンクされ、そのプロファイルの `config.yaml` で有効化され、レガシーな FailproofAI シェルフックエントリのみが移行されます。プラグインはリンクされているため、`npm install -g failproofai@latest` を実行するだけで再インストールなしに更新されます。これにより、フックごとのプロセス生成が回避されます。このプラグインは Hermes 0.20.0 以降をサポートしています。

レガシーシェルフック（1.0.5以前でインストールされたもの）は、Hermes の cron ジョブをチェック**しません**。各 cron 実行は独自のフックスコープを構築し、ネイティブプラグインはそれに参加しますが、`config.yaml` のシェルフックは参加しません。`failproofai update` は FailproofAI をすでに使用しているすべてのプロファイルをリンク済みプラグインに移行します。実行中のデーモンがプラグインを提供できない場合、`update` はシェルフックをそのままにしてゼロ以外で終了します。`failproofai config` を実行してデーモンを更新してから、再度 `failproofai update` を実行してください。cron ジョブは次回の実行時にプラグインをロードします。実行中のゲートウェイとインタラクティブセッションはプラグインをロードするために再起動が必要です。

Hermes では、`deny()` は呼び出しをブロックし、`instruct()` はブロックしません。呼び出しは実行され、ガイダンスはその結果の先頭に配置されます。JSON 結果の場合は最初のキー `failproof_policy_reminder` として、あるいは先頭に `[FailproofAI policy reminder (...)]` 行として追加されます。これにより、モデルは出力と一緒にガイダンスを読み取り、結果をパースするスクリプトも引き続き機能します。ポリシーのリマインダーはターンごとに1回表示され、大きな結果の場合は短くまとめられます。アクションを絶対に実行させたくない場合は `deny()` を使用してください。`instruct()` はもはやアクションを事前に停止しません。`execute_code` スクリプトから行われたツール呼び出しのリマインダーは、モデルが読む `execute_code` の結果に配置されます。スクリプト自身の結果コピーはそのまま保持されます。モデルはリマインダーを返答内で引用しないよう指示されています。

プラグインミドルウェアのない Hermes ビルドでは、一致する呼び出しを「FailproofAI policy guidance」として1回保留するフォールバック動作が行われます。次のモデルレスポンスで繰り返されるか、別のツールで同じ処理が行われる可能性がありますが、再度保留はされません。

ツール名は Hermes のバージョン間で一致します。`process_manage`、`cronjob_manage`、`todo_list`（Hermes 0.21）は `process`、`cronjob`、`todo`（Hermes 0.20）と同等として扱われます。Hermes がプラグインをロードするたびに、プロファイルの `plugin-data/agent-plugin-failproofai-5296f299/` ディレクトリに `heartbeat.json` が書き込まれ、Hermesのバージョン、プラグインのパスとバージョン、Hermes が受け入れたフックが記録されます。`failproofai config --status` を実行して、無効化、不完全、重複、または新たに未設定のプロファイル、あるいはレガシーシェルフックを使用しているプロファイル（「Hermes cron jobs are not checked」と報告される）を検出してください。

### OpenClawプラグイン

OpenClaw は、すべてのプロファイルの `openclaw.json` に登録されたインプロセスゲートウェイプラグインとして FailproofAI をロードします。Hermes プラグインと同様に、ソケット経由でローカルの `failproofaid` デーモンに各判定を問い合わせるため、実行中のデーモンが必要です。デーモンがない場合はインストールを拒否し、デーモンが応答できない場合はツール呼び出しとプロンプトがブロックされ、その理由がゲートウェイログに記録されます。`npm install -g failproofai@latest` の後、OpenClaw ゲートウェイを再起動して更新されたプラグインをロードしてください。

### Codexフック信頼性

Codex 0.129 以降では、`~/.codex/hooks.json` のフックは、インタラクティブな `codex`（「フックのレビュー」）で承認された後にのみ実行されます。承認されるまでは、ヘッドレスの `codex exec` を含むすべての Codex セッションでスキップされます。Codex のシステム設定（Linux および macOS の `/etc/codex/config.toml`）にあるフックはこの承認なしに実行されます。

そのため、`failproofai config`（またはユーザースコープでの `policies --install --cli codex`）が sudo を使用できる場合、Codex フックを `/etc/codex/config.toml` に書き込みます。`# >>> failproofai managed hooks >>>` と `# <<< failproofai managed hooks <<<` の間に挿入され、ファイルの残りの部分はそのまま保持されます。このファイルはマシン上のすべてのアカウントに適用されます。`failproofai uninstall` および `failproofai config` で Codex のチェックを外すと、このブロックが削除されます。

sudo なし、および Windows では、フックは `~/.codex/hooks.json` に保持されます。この場合、`failproofai config` と `failproofai config --status` はフックが承認されるまで Codex を適用中とカウントせず、修正方法を表示します。`failproofai config` を再実行して sudo を許可するか、`codex` を一度開いてフックを承認してください。

## キャプチャおよびポリシーフックのインストール

<Tabs>
  <Tab title="ダッシュボード">
    1. **管理 → キー** を開き、マシンまたは環境に名前を付けた `events:add` と `policies:pull` 権限を持つキーを作成します。
    2. 対象マシンで、表示されたキーを使ってローカルCLIを接続し、ハーネスフックをインストールします。
    3. 新しいエージェントセッションを開始し、**観察 → イベント** でフックとセッションイベントを確認します。
    4. 同じ時間ウィンドウで **観察 → ポリシー** を開き、ポリシー決定がマシンに帰属していることを確認します。

    接続はマシンキーから始まります。シークレットをコピーする前に、インジェストとポリシー配信の両方の権限が含まれていることを確認してください。

    ![イベントインジェストとポリシー配信の権限を付与するための新しいAPIキードロワー。](/images/dashboard/key-create.png)

    フックをインストールした後、接続したマシンと環境からの新しいイベントがイベントストリームに表示されます。

    ![新たにインストールされたハーネスがレポートしていることを確認するためのライブイベントストリーム。](/images/dashboard/events-stream.png)

    最後に、ポリシー決定が同じマシンに帰属していることを確認します。これにより、ハーネスがトレースイベントだけでなくポリシーアクティビティも報告していることが確認できます。

    ![新たに接続されたハーネスからのポリシー決定を確認するためのポリシーページ。](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    マシンキーをシェルに読み込みます。`read -s` はエコーしないプロンプトで入力を受け取るため、コマンドやシェル履歴に表示されることはありません。

    ```bash
    read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
    ```

    次にマシンをセットアップします。これにより、検出されたすべてのハーネスのフックが配線され、デーモンがインストールされ、Cloudに接続されます。

    ```bash
    failproofai config
    failproofai policies add FailproofAI/policies
    ```

    セットアップ自体はポリシーを有効にしません。2番目のコマンドがその役割を担います。

    または、特定のハーネスと設定スコープを指定することもできます。

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    プロジェクトスコープはフック設定をリポジトリと共に保持します。ユーザースコープはリポジトリをまたいだ作業をカバーします。Claude Code はローカルスコープもサポートしていますが、サポート状況はハーネスによって異なり、CLIはサポートされていない組み合わせを拒否します。

    マシンとそのイベントを確認します。

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## デフォルト以外のセッションパスの追加

<Tabs>
  <Tab title="ダッシュボード">
    追加パスはCloudではなくマシン上に登録されます。追加後、**観察 → セッション** を開き、マシンの環境でフィルタリングして、新しいパスからのセッションが表示されることを確認します。セッションを開き、監査で使用する前にエージェント、ハーネス、イベントタイムスタンプを確認してください。

    ![追加キャプチャパスからデータを受信している環境にフィルタリングされたセッション一覧。](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    オプションのラベルを付けてパスを追加し、設定済みパスを確認します。

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    `failproofai harness remove-path claude checkout` でパスを削除します。
  </Tab>
</Tabs>

<Tip>
  インストール後に新しいセッションを1つ実行してください。ロールアウトを拡大する前に、ライブイベントストリームと実際のポリシー決定の両方を確認してください。
</Tip>
