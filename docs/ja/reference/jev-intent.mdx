[Jev ポリシーレビュー](/ja/policies/jev)を設定すると、エバリュエーターはゲートされた各ツール呼び出しを、ハーネスがエージェントに提示したテキストではなく、**人間が要求した内容**と照らし合わせて判断します。「はい、強制プッシュしてください」のような返答で **reviewable** ポリシーをクリアできるのはそのためです。これはエバリュエーターの核心であり、要求を読み取れない正規表現では実際の作業の3分の1をブロックしてしまいます。

そのテキストは一箇所から来ます: **ハーネス自身がプロンプト送信イベント時にフックに渡すプロンプト**です。Failproof AI は人間が入力した部分(ハーネスのラッピングを除去し、シークレットを編集し、上限を設けた上で)を、自身のステートディレクトリ配下の `0600` ファイルに記録します。ディスク上の内容は参照されません。セッション・トランスクリプトはエージェントが1コマンドで書き換え可能なファイルであるため、プロンプトの作成者を問い合わせることは一切ありません。

## このアプローチが受け入れるリスク

コマンドを実行できるエージェントは、ハーネスにプロンプトを送信させることができます。`claude -p "…"`、`codex exec`、`copilot -p`、`cursor-agent -p`、`devin -p`、`droid -p`、`goose run -t`、`pi -p` はいずれも、エージェントが制御する子セッションにおいて、人間が入力した場合と同じプロンプト送信イベントを同じペイロードで発火させます。また、Failproof AI 自身のフックバイナリを実行して、自ら作成したペイロードを渡すこともできます。Failproof AI の内部からはいずれも本物との区別がつきません。どちらも同じプログラムが同じ stdin を読み取っているためです。

**つまり、シェルを持つエージェントは自分自身のコンセントを偽造できます。** これは 2026-09-23 に意図的に行われたトレードオフであり、その両面は以下の通りです:

- **得られるもの。** 代替案は実装・計測済みです: ハーネスが人間をプロンプトの作成者として明示するフィールドを必須とし、それがない場合は何も記録しないというものです。しかし、そのようなフィールドを送信する既存ハーネスは存在しないため、このバージョンでは**すべてのハーネスで何も記録されませんでした**。Jev はインテントなしですべての呼び出しを判断し、ポリシーをクリアできませんでした。発火しないキャプチャは安全な製品ではなく、製品として機能しません。
- **できないこと。** 記録されたプロンプトは、**reviewable** とマークされたポリシーのみをクリアできます。**hard** ポリシーは Jev の判断によって決してクリアされないため、偽造されたプロンプトがハードな deny を allow に変えることは不可能です。また、フックをスキップしてもエージェントには何の利益もありません。ハーネスはツール呼び出しに対して独立して Failproof AI を呼び出すためです。
- **最悪の場合できること。** 最悪のケースは、15の reviewable 組み込みポリシーのうちの1つをクリアすることですが、**そのうち12はブロック**です。`protect-env-vars`、`block-env-files`、`block-read-outside-cwd`、`block-rm-rf`、`block-force-push`、`block-secrets-write`、および6つのインフラ CLI ブロック(`block-kubectl`、`block-terraform`、`block-aws-cli`、`block-gcloud`、`block-az-cli`、`block-helm`)はすべて deny です。そのため、偽造されたコンセントにより、環境シークレットの表示、`.env` ファイルの読み取り、プロジェクト外の読み取り、`rm -rf`、強制プッシュ、シークレットファイルへの書き込み、またはライブインフラの変更において、実際の deny が allow に変わる可能性があります。`warn-git-amend`、`warn-destructive-sql`、`warn-global-package-install` のみが警告です。デフォルトインストールでは12のうち2つ(`protect-env-vars` と `block-env-files`)が有効で、残り10は誰かが有効化したマシンにのみ影響します。どのプロンプトもリーチできないのは、すべての hard なもの(block-sudo、`block-curl-pipe-sh`、`block-push-master`、`block-work-on-main`、エージェントが Failproof AI を無効化するのを止めるガード、および reviewable とマークされていないその他の組み込みポリシー)です。[ポリシー権限](/ja/policies/authority)では15すべてとその審査方法を一覧で確認できます。

依然として拒否されるのは、安価にチェックでき、エージェントが単に要求するだけでは取得できないもの全てです: ハーネス自身のペイロードがマシン送信済みとしてマークしたターン、サブエージェントを指定するペイロード、プレーンな名前でないセッション ID、プロンプト送信以外のイベント、そしてハーネスのラッピングのみのテキスト(複数のハーネスが次のユーザーターンとして返す Failproof AI 自身のストップゲートワードを含む)。

## ハーネス別テーブル

「テキストフィールド」は Failproof AI のハーネスごとの正規化後の stdin ペイロードフィールドです。「記録済み」はプロンプトが人間のリクエストとして保存されるかどうかを示します。

| ハーネス | `--cli` | プロンプトイベント → 正規化 | テキストフィールド | 記録済み | エージェントの最終メッセージの読み取り元 |
| --- | --- | --- | --- | --- | --- |
| Claude Code | `claude` | `UserPromptSubmit` | `prompt` | あり。ただしペイロードの `source` が誰も送信していないターンを示す場合(`loop_wakeup`、`schedule_wakeup`、`poll_event`、`system`)を除く。`user`、`sdk`、不明な値、および `source` を送信しないビルドはすべて記録される | セッション・トランスクリプト(`transcript_path`) |
| Codex | `codex` | `user_prompt_submit` → `UserPromptSubmit` | `prompt` | あり | ロールアウト JSONL (`agent_message`、`AgentMessage`) |
| GitHub Copilot CLI | `copilot` | `UserPromptSubmit` | `prompt` | あり | `events.jsonl`(`assistant.message`) |
| Cursor | `cursor` | `beforeSubmitPrompt` → `UserPromptSubmit` | `prompt` | あり。プロンプト全体が `<user_query>` ラッパーの場合はそれを除去 | エージェントトランスクリプト JSONL |
| OpenCode | `opencode` | `message.updated`(user ロール) → `UserPromptSubmit` | `prompt` | あり。ただし現在の OpenCode はそのイベントにテキストを含まないため、実際には何も記録されない。同一メッセージの繰り返しは1回のみ記録 | なし(セッションは SQLite) |
| Pi | `pi` | `input` → `UserPromptSubmit` | `prompt` | あり。ただし `input_source` が `extension` の場合を除く。別の拡張機能の `sendUserMessage()` であり、そのテキストはモデルが生成したもの、またはリポジトリ由来の可能性がある | Pi セッション JSONL |
| Hermes | `hermes` | なし | — | なし — Hermes にはプロンプト送信イベントが存在しない | — |
| OpenClaw | `openclaw` | `before_agent_run` → `UserPromptSubmit` | `prompt` | あり。ただし実行メタデータが機械実行を示す場合を除く: `user` 以外の `trigger`、`external_user` 以外の `inputProvenance.kind`、または `senderIsOwner: false` | なし(`before_agent_run` にはトランスクリプトパスが含まれない) |
| Factory Droid | `factory` | `UserPromptSubmit` | `prompt` | あり | ドロイドセッション JSONL |
| Devin CLI | `devin` | `UserPromptSubmit` | `prompt` | あり | なし(セッションは SQLite) |
| Antigravity CLI | `antigravity` | `PreInvocation` → `UserPromptSubmit` | なし | なし — `PreInvocation` はターン内の*すべての*モデル呼び出し前に発火し、プロンプトテキストを含まない | — |
| Goose | `goose` | `UserPromptSubmit` | `message` | あり | なし(セッションは SQLite) |

2つのハーネスは何も記録しませんが、いずれも同じ理由です: イベントに人間のテキストが含まれていません。Hermes にはプロンプト送信イベントがありません。ネイティブプラグインが `pre_llm_call` を自ら処理し、ツール、セッション、サブエージェントイベントのみを転送します。Antigravity の `PreInvocation` は、人間のターンとその後の5つのモデル呼び出し前すべてで発火し、プロンプトフィールドを含みません。フックは同じ会話に `userMessage` ステップを注入することもできます。どちらのイベントにも記録すべきものがありません。

## プロンプトを人間のものとみなす条件

1. **イベント。** Failproof AI がハーネスのプロンプト送信イベントに対して呼び出され、ハンドラーがそれを `UserPromptSubmit` に正規化する。
2. **ペイロード。** ハーネスがフックの stdin に書き込み、上記のフィールドにテキストが含まれている。ペイロードなしで Failproof AI に到達した呼び出しは何も記録しない。
3. **ペイロード内のどの要素もターンを除外しない。** サブエージェント(`agent_id`)を指定するペイロードは、エージェントが自身にプロンプトを送っている。マシン送信ターンを示す `source`、`input_source`、または OpenClaw の実行マーカーは拒否される。**不在の**マーカーは何も除外しない。これが何も記録しなかったバージョンとの違いです。ここに挙げる各マーカーは、すべての既存ビルドで不在です。
4. **ラッピングを除去した後に何かが残る**(下記参照)。

**セッション・トランスクリプトはプロンプトの作成者の証拠にはなりません。** このページの以前のバージョンではトランスクリプトのクロスチェックが記述されていました: トランスクリプトがモデルによるスケジュール設定を示した場合はプロンプトを拒否し、前のプロンプトが参照したトランスクリプトを継続している必要がある、というものでした。そのチェックは廃止されました。トランスクリプトはエージェントがすでにシェルを持つファイルであり、切り詰め、置換、読み取りバジェットを超えたパディング、ターン開始時のスナップショットと終了時の復元、エージェントが記述したエントリによる修正が可能です。毎回の強化の後、同じ偽造の別の方法が出現したため、修正ではなく仕組み全体を削除しました。

トランスクリプトを読み取るのは1つのことだけです: **エージェントの最後の表示メッセージ**。そのメッセージはエージェントが書いたものであることが明確であり、Jev にはその旨が伝えられます。それ単独でコンセントになることはありません。

## プロンプトから保持される内容

ハーネスはプロンプトに人間の言葉以上のものを含めます。保存前に以下の処理が行われます:

- `<system-reminder>` ブロックは除去され、周囲の人間の言葉は保持されます。
- セッション継続サマリー(「このセッションは以前の会話から継続されています…」)は完全に削除されます。
- タスク通知、ローカルコマンド出力、割り込みマーカーは完全に削除されます。
- 別のエージェントまたはセッションが書いたターンは完全に削除されます: Claude Code はこれらを `<cross-session-message>`、`<teammate-message>`、`<agent-message>`、`<coordinator-relay>`、`<channel source=…>` でラップします。
- Failproof AI 自身のメッセージは完全に削除されます。ストップゲートの `MANDATORY ACTION REQUIRED from failproofai …` または `Instruction from failproofai: …` は、Cursor、Copilot、Devin、OpenClaw では次のユーザーターンとして返ってきますが、プレーンであっても、`<user_query>` ブロックでラップされていても、システムリマインダーの後であっても、人間の言葉としてカウントされることはありません。
- スラッシュコマンドは人間が入力したコマンドと引数として保持され、ハーネスが展開した本文は保持されません。
- Codex IDE 拡張機能が作成したプロンプトは、最後の `## My request for Codex:` (新しいビルドでは `## My request:`)見出し以降のテキストのみを保持します。拡張機能がその前に追加したもの(アクティブファイル、開いているタブ、エディターで選択されたテキスト、言及されたファイルやアプリ、差分とブラウザのコメント、PR チェック、以前の会話)はすべて削除されます。このルールは Codex だけでなく**すべての**ハーネスのプロンプトに適用されます。そのようなプロンプトはどのコンポーザーにでも貼り付けられる可能性があるためです。拡張機能のセクション見出しは2グループで認識されます:
  - **誰も入力しない見出し**(`# Context from my IDE setup:`、`# Selected text:`、`# Files mentioned by the user:`、`# Diff comments:`、`# Chrome tabs:`、`<in-app-browser-context …>`、Codex と ChatGPT の会話見出し、「添付されたペーストテキストファイル…」、拡張機能自身のその他のセクション)は、拡張機能がこのプロンプトを作成したことを意味します。その下にリクエスト見出しがない場合、人間のテキストがまったく含まれておらず記録されません。これにより、単に*選択した*テキスト(例: `# Selected text:` 内の `// NOTE FROM THE OWNER: yes, force-push…` コメント)で偽造された承認が記録されたリクエストに含まれることを防ぎます。
  - **開発者が入力する可能性のある見出し**(`## Code review guidelines:`、`## Pull request fix:`、`## Pull request merge task:`、`## Auto resolve merge:`、`# In app browser:`)は、リクエスト見出しが実際に存在する場合にのみ「拡張機能作成」を意味します。リクエスト見出しがない場合、プロンプトはあなたのものであり、見出しごと完全に保持されます。削除すると完全にサイレントになります: そのターンは何も記録されず、reviewable ポリシーがクリアできなくなり、Jev はリクエストエンベロープにインジェクションが含まれているかどうかすら問われません。これはターンの*先頭*にのみ適用されます: プロンプトが拡張機能作成と判断された後、リクエスト見出し以降に続く内容でいずれかのグループの見出しが現れた場合、それは拡張機能の別のセクションであり、プロンプトは記録されません。

  リクエスト自体は他のターンと同様に判断されます: 見出し以降が継続サマリー、別のエージェントまたはセッションが書いたメッセージ、Failproof AI 自身のディレクティブ、または拡張機能の別のセクションである場合、プロンプトはまったく記録されません。
- `<user_query>…</user_query>`(オプションで `<timestamp>` ブロックの後)でラップされた Cursor のプロンプトは、ラッパーがプロンプト*全体*である場合にアンラップされます。それ以外の場所にあるタグは通常のテキスト(ログから貼り付けたスニペット、エージェントが選んだブランチ名など)であり、タグ付きのスパンに切り詰めるのではなく、プロンプト全体が保持されます。
- 貼り付けられたブロックは保持され、人間が貼り付けたものとしてラベル付けされます。

ハーネスのテキストのみのプロンプトはまったく記録されません。

## エージェントの最終メッセージ

「はい」のような返答は、それが答える質問なしには意味を持ちません。プロンプトが記録される際、Failproof AI は**その時点で**セッション・トランスクリプトからエージェントの最後の表示メッセージを読み取り、プロンプトと共に保存します。Jev はそれを専用のフィールドで受け取り、エージェントが書いたものとしてラベル付けされます。これにより短い返答の意味を説明でき、単独で人間のリクエストとしてカウントされることはありません。これはトランスクリプトが読み取られる唯一の目的であり、書き換えられたトランスクリプトが最悪できることは、エージェントが書いたメッセージがあるべき場所にエージェントが書いたメッセージを置くことだけです。

トランスクリプトの末尾から最大4 MB を読み取ります。対応するトランスクリプト形式は Claude Code、Codex ロールアウト(古い `agent_message` イベントと新しい `AgentMessage` アイテム)、Cursor、Copilot の `events.jsonl`、Pi、Factory、OpenClaw のセッション JSONL です。Claude Code 自身の合成メッセージ、API エラーメッセージ、サブエージェント(サイドチェーン)メッセージはスキップされます。セッションを SQLite で管理する Goose と OpenCode、トランスクリプトが単一の JSON ドキュメントである Devin、`before_agent_run` イベントにトランスクリプトパスが含まれない OpenClaw にはスナップショットがありません。

## ストレージ

| プロパティ | 値 |
| --- | --- |
| 場所 | `~/.failproofai/state/semantic/sessions/<profile>/<session-id>.json`。`<profile>` はプロンプトが入力されたエージェントプロファイル: FailproofAI が認識するエージェントの場合は `<integration>.<instance-id>`(Cloud ポリシーがターゲットとするアイデンティティ)、それ以外は `<integration>` のみ |
| パーミッション | ファイル `0600`、ディレクトリ `0700`。その上の `~/.failproofai` までの各ディレクトリも同じルールに従います。他のユーザーが**書き込み**できるディレクトリは名前変更して置き換えられる可能性があるため、読み取りパスは可能な限り書き込みビットを除去し、除去できない場合は**何も読み取りません**。記録されたプロンプトはその場合、偽造されるのではなく不在となり、何もクリアされません |
| セッションごとの保持数 | 最後の5プロンプト。直前のプロンプトと同一のプロンプトは新しいスロットを取らずに置き換えられます |
| ウィンドウ | 6時間より古いプロンプトは無視されます |
| サイズ | 各プロンプトとエージェントメッセージは先頭と末尾を保持しつつ6,000文字に制限されます |
| シークレット | 書き込み前に `sanitize-*` ポリシーと同じパターンで編集されます。48,000文字を超えるテキストは最初の28,800文字と最後の19,200文字として編集され、シークレットが分割されている可能性がある切り取り箇所の隣接テキストは保存されません |

文字、数字、`.`、`_`、`-` 以外の文字を含む、または128文字を超えるセッション ID はファイル名として使用されないため、それらのセッションには何も記録されません。

セッションファイルはプロンプトが記録されてはじめて作成されます。保持するのはプロンプトのみであり、オリジン状態もトランスクリプトマークも含まれません。6時間ウィンドウを超えてサイレントになった場合、次の新しいセッションが最初のプロンプトを書き込む際に削除されます。

プロンプトは、記録された際と同じエージェントプロファイルおよびセッション ID でのみ読み取られます。セッション ID はエージェントから来るため、2つのプロファイルが同じ ID を使用する可能性があります。プロファイルでキーイングすることで、あるプロファイルの言葉が別のプロファイルのリクエストとしてカウントされることを防ぎます。このレイアウト以前のファイル(`sessions/<session-id>.json`)はどのプロファイルが書いたかを示せないため、読み取られることなく6時間ウィンドウで期限切れになります。

Jev エンドポイントが設定されていない限り、何も記録されません。FailproofAI Cloud Jev モードでは、Cloud Jev チェックが割り当てられておらず、インストール済みパックのチェックも審査しないエージェントプロファイルについては何も記録されません。

### プロジェクトルート

「プロジェクト内」(つまり `read-outside-workspace` やその他のパスチェックが判断する基準)とは、セッションの**最初のレビュー済み呼び出し**時点でのプロジェクト内を意味します。ルートはその時点で固定され、以降の `cd` によって移動しません。ただし `cd` は相対パスの解決方法を変更します。`cd` に追随させると、あるコマンドでの `cd ~/.ssh` が次のコマンドのプロジェクトを `~/.ssh` にしてしまいます。

ピンは `~/.failproofai/state/semantic/roots/<session-id>.json` であり、`{root, at}` を保持します。ファイルは `0600`、ディレクトリは `0700` で、上記と同じセッション ID ルールが適用されます。7日以上古いファイルは新しいセッションがルートをピンする際に削除されます。他のユーザーが書き込めるディレクトリ内の `roots` は無視され、代わりにライブディレクトリのルートが使用されます。セッションを再ピンするには、そのファイルを削除します。

## 既知の制限

- **プロンプトの信頼性はフック呼び出しの信頼性に依存します。** ここに記載されているすべての処理は、ハーネスがフックの stdin に書き込んだペイロードを読み取ります。コマンドを実行できるエージェントは、ハーネスをヘッドレスで実行する(`claude -p` および上記の7つのコマンド)か、Failproof AI 自身のフックバイナリを作成したペイロードで実行することができ、誰も入力していないプロンプトを記録できます。これはページ上部で説明したトレードオフです: reviewable ポリシーのみクリアでき、hard ポリシーは決してクリアできません。ただし、reviewable な組み込みポリシーの15のうち12は deny であるため、偽造されたプロンプトによってその12のポリシーで実際のブロックが allow に変わる可能性があります。
- **サブエージェント検出は Claude の形式に依存しています。** `agent_id` を含むペイロードは、どのハーネスでも記録されません。これは Claude Code、Factory Droid、Devin が使用するフィールドです。Codex はサブエージェントスレッド内でプロンプトイベントを発火させ、Copilot はインプロセスのサイドキックを実行し、Goose は `delegate` ツールを持ち、OpenClaw はペルソナを実行しますが、いずれもペイロードにこれが認識できる形でマークされないため、それらのハーネスのサブエージェントプロンプトはセッション自身のものとして記録されます。OpenClaw の `openclaw.agentId` はそのマークでは**ありません**: 出荷済みプラグインはすべての実行(オーナーのものを含む)でこれを設定します。
- **マーカーを含まないスケジューラー。** Claude Code の `schedule_wakeup` と `loop_wakeup`、および OpenClaw の `cron` と `heartbeat` トリガーは、それらのハーネスがペイロードでそう示しているため拒否されます。Goose 自身のスケジューラー(`goose schedule add`)と Codex の `codex exec` は何も示さないため、それらが開始した実行は他と同様に記録されます。
- **エージェントの最終メッセージは、エージェントが選んだメッセージである可能性があります。** トランスクリプトは認証されていないため、自身のトランスクリプトを書くエージェントは「最終メッセージ」の内容を決定できます。エージェントが書いたものとしてラベル付けされ、それ単独では何もクリアしません。ただし、`decide.ts` の v1 パスでは確定的な「ユーザーがこのターゲットを指定したか」チェックを満たすことができるため、トランスクリプトを制御するエージェントは、オーバーライドが必要とするターゲット名を提供できることに注意してください。
- **拡張機能のマシン見出しで始まるプロンプトは全体が削除されます。** `# Selected text:`、`# Diff comments:`、`# Chrome tabs:` または上記の第1グループのセクション見出しでプロンプトを始め、`## My request:` 見出しを書かなかった場合、そのターンには何も記録されず、クリアされるものもありません。これは意図的です: これらのセクションには他の誰かが制御するテキスト(選択したコード、レビュアーの差分コメント、ページタイトル)が含まれており、それをあなたの言葉として記録する方が問題です。開発者が入力する可能性のある見出しは第2グループにあり、それ単独でプロンプトを削除することはありません。
- **OpenCode は実際には何も記録しません。** 現在の OpenCode では `message.updated` イベントにテキストが含まれておらず、タスクツールが作成する子セッションでも発火します。その子セッションの「ユーザー」メッセージは親エージェントが書いたものです。
- **`CODEX_HOME` は** `lib/codex-sessions.ts` のロールアウト検出では**考慮されません**。これはエージェントメッセージのスナップショットを探す場所のみに影響し、プロンプトが記録されるかどうかには影響しません。
