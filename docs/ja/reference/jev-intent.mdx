[Jev ポリシーレビュー](/ja/policies/jev)を設定すると、評価器はゲートされた各ツール呼び出しを、ハーネスがエージェントに提示したテキストではなく、**人間が求めたもの**と照らし合わせて判断します。「はい、強制プッシュしてください」のような返答は **reviewable** ポリシーをクリアできます。これがまさに評価器のポイントです。リクエストを読み取れない正規表現は、実際の作業の3分の1をブロックしてしまいます。

そのテキストは1か所から来ます。**ハーネス自身がプロンプト送信イベント時にフックに渡すプロンプト**です。Failproof AI は人間が入力した部分（ハーネスのラッピングを除去し、シークレットを秘匿化し、上限を設けた上で）を、自身のステートディレクトリ配下の `0600` ファイルに記録します。ディスク上のセッショントランスクリプトは参照されません。トランスクリプトはエージェントが1つのコマンドで書き換えられるファイルであるため、誰がプロンプトを書いたかを確認するためには使用しません。

## このトレードオフが受け入れるリスク

コマンドを実行できるエージェントはハーネスにプロンプトを送信させることができます。`claude -p "…"`、`codex exec`、`copilot -p`、`cursor-agent -p`、`devin -p`、`droid -p`、`goose run -t`、`pi -p` はいずれも、人間が入力した場合と同じプロンプト送信イベントを、同じペイロードで、エージェントが制御する子セッションから発火させます。また、Failproof AI 自身のフックバイナリを実行し、エージェントが作成したペイロードを供給することもできます。Failproof AI の内部では、いずれも本物と区別できません。どちらも同じプログラムが同じ stdin を読み取っているだけです。

**つまり、シェルを持つエージェントは自分自身の同意を偽造できます。** これは 2026-09-23 に行われた意図的なトレードオフであり、その両面を以下に示します。

- **得られるもの。** 代替案は構築され、計測されました。ハーネスがプロンプトの作者として人間を指定するフィールドを必須とし、指定がない場合は何も記録しない、という方式です。しかし、現行のどのハーネスもそのようなフィールドを送信しないため、そのバージョンでは**あらゆるハーネスで何も記録されませんでした**。Jev はすべての呼び出しを明示されたインテントなしで判断し、1つのポリシーもクリアできませんでした。一度も発火しないキャプチャは、より安全な製品ではなく、製品として機能しません。
- **できないこと。** 記録されたプロンプトは **reviewable** とマークされたポリシーをクリアするだけです。**hard** ポリシーは Jev の判断では絶対にクリアされないため、偽造されたプロンプトが hard な deny を allow に変えることはできません。フックをスキップしてもエージェントには何も得られません。ハーネスはツール呼び出しに対して独立して Failproof AI を呼び出すからです。
- **完全な状況でできること。** 最悪のケースは、15個の reviewable な組み込みポリシーのうちの1つをクリアすることです。そして**その15個中12個はブロック**します。`protect-env-vars`、`block-env-files`、`block-read-outside-cwd`、`block-rm-rf`、`block-force-push`、`block-secrets-write`、および6つのインフラ CLI ブロック（`block-kubectl`、`block-terraform`、`block-aws-cli`、`block-gcloud`、`block-az-cli`、`block-helm`）は deny であるため、偽造された同意は、環境シークレットの出力、`.env` ファイルの読み取り、プロジェクト外の読み取り、`rm -rf`、force-push、シークレットファイルへの書き込み、またはライブインフラの変更について、実際の deny を allow に変える可能性があります。`warn-git-amend`、`warn-destructive-sql`、`warn-global-package-install` はナッジにすぎません。デフォルトインストールでは12個のうち2個（`protect-env-vars` と `block-env-files`）が有効になります。残りの10個は、誰かが明示的に有効にしたマシンにのみ適用されます。どのプロンプトも到達できないのは、hard なものすべてです。`block-sudo`、`block-curl-pipe-sh`、`block-push-master`、`block-work-on-main`、エージェントが Failproof AI を無効化するのを防ぐガード、および reviewable とマークされていない他のすべての組み込みポリシーが該当します。[ポリシー権限](/ja/policies/authority)には、15個すべてとそれぞれのレビュー方法が記載されています。

依然として拒否されるものは、チェックが容易でエージェントが単に要求するだけでは取得できないものすべてです。ハーネス自身のペイロードがマシン送信のターンとしてマークしているもの、サブエージェントを指定するペイロード、単純な名前でないセッション ID、プロンプト送信イベントでないイベント、およびハーネスのラッピングのみからなるテキスト（Failproof AI 自身のストップゲートワードを含む。複数のハーネスはこれを次のユーザーターンとしてフィードバックします）。

## ハーネス別テーブル

「テキストフィールド」は Failproof AI のハーネスごとの正規化後の stdin ペイロードフィールドです。「記録」はプロンプトが人間のリクエストとして保持されるかどうかを示します。

| ハーネス | `--cli` | プロンプトイベント → 正規化 | テキストフィールド | 記録 | エージェントの最終メッセージの読み取り元 |
| --- | --- | --- | --- | --- | --- |
| Claude Code | `claude` | `UserPromptSubmit` | `prompt` | はい。ただしペイロードの `source` が誰も送信していないターンを指定する場合（`loop_wakeup`、`schedule_wakeup`、`poll_event`、`system`）を除く。`user`、`sdk`、不明な値、および `source` を送信しないビルドはすべて記録される | セッショントランスクリプト（`transcript_path`） |
| Codex | `codex` | `user_prompt_submit` → `UserPromptSubmit` | `prompt` | はい | ロールアウト JSONL（`agent_message`、`AgentMessage`） |
| GitHub Copilot CLI | `copilot` | `UserPromptSubmit` | `prompt` | はい | `events.jsonl`（`assistant.message`） |
| Cursor | `cursor` | `beforeSubmitPrompt` → `UserPromptSubmit` | `prompt` | はい。プロンプト全体が `<user_query>` ラッパーの場合はそれを剥がした上で記録 | エージェントトランスクリプト JSONL |
| OpenCode | `opencode` | `message.updated`（user ロール）→ `UserPromptSubmit` | `prompt` | はい。ただし現行の OpenCode はそのイベントにテキストを含まないため、実際には何も記録されない。同じメッセージの繰り返しは1回だけ記録 | なし（セッションは SQLite） |
| Pi | `pi` | `input` → `UserPromptSubmit` | `prompt` | はい。ただし `input_source` が `extension` の場合を除く（別の拡張機能の `sendUserMessage()` であり、テキストがモデルによって書かれたりリポジトリから派生したりする可能性がある） | Pi セッション JSONL |
| Hermes | `hermes` | なし | — | なし — Hermes にはプロンプト送信イベントが存在しない | — |
| OpenClaw | `openclaw` | `before_agent_run` → `UserPromptSubmit` | `prompt` | はい。ただしランのメタデータがマシンによるランとしてマークしている場合を除く（`user` 以外の `trigger`、`external_user` 以外の `inputProvenance.kind`、または `senderIsOwner: false`） | なし（`before_agent_run` はトランスクリプトパスを含まない） |
| Factory Droid | `factory` | `UserPromptSubmit` | `prompt` | はい | droid セッション JSONL |
| Devin CLI | `devin` | `UserPromptSubmit` | `prompt` | はい | なし（セッションは SQLite） |
| Antigravity CLI | `antigravity` | `PreInvocation` → `UserPromptSubmit` | なし | なし — `PreInvocation` はターン内の*すべての*モデル呼び出しの前に発火し、プロンプトテキストを含まない | — |
| Goose | `goose` | `UserPromptSubmit` | `message` | はい | なし（セッションは SQLite） |

2つのハーネスは何も記録しません。いずれも同じ理由で、イベントが人間のテキストを配信しないからです。Hermes にはプロンプト送信イベントがありません。ネイティブプラグインが `pre_llm_call` を自ら処理し、ツール、セッション、サブエージェントのイベントのみを転送します。Antigravity の `PreInvocation` は人間のターンとその後に続く5回の呼び出しを含む、すべてのモデル呼び出しの前に発火し、プロンプトフィールドを含みません。フックは同じ会話に `userMessage` ステップを注入することもできます。どちらのイベントにも記録すべきものが何もありません。

## プロンプトが人間のものとみなされる条件

1. **イベント。** Failproof AI がハーネスのプロンプト送信イベントに対して呼び出され、ハンドラーがそれを `UserPromptSubmit` に正規化している。
2. **ペイロード。** ハーネスがフックの stdin にペイロードを書き込み、上記のフィールドにテキストを含んでいる。ペイロードなしで Failproof AI に到達した呼び出しは何も記録しない。
3. **ペイロード内のどの要素もターンを除外しない。** サブエージェント（`agent_id`）を指定するペイロードはエージェントが自分自身にプロンプトを送っているものです。マシン送信のターンを指定する `source`、`input_source`、または OpenClaw のランマーカーは拒否されます。**存在しない**マーカーは何も除外しません。これが何も記録しなかったバージョンとの違いです。ここにあるすべてのマーカーは、現行のすべてのビルドで存在しません。
4. **ラッピングを除去した後に何かが残っている**（以下参照）。

**セッショントランスクリプトはプロンプトを誰が書いたかの証拠にはなりません。** このページの以前のバージョンではトランスクリプトのクロスチェックについて説明していました。モデルがプロンプトをスケジュールしていることがトランスクリプトに示されている場合、またはトランスクリプトが前のプロンプトが見たものを継続していない場合にプロンプトを拒否する、という仕組みです。そのチェックはなくなりました。トランスクリプトはエージェントがすでにシェルを持っているファイルです。切り捨て、置き換え、読み取り予算を超えたパディング、ターン開始時のスナップショットと終了時の復元、あるいはエージェントが書いたエントリによる再構築が可能です。強化のたびに同じ偽造の別のやり方が生まれたため、修正ではなくメカニズム全体が削除されました。

トランスクリプトは今でも1つのことのために読まれます。**エージェントの最後に表示されたメッセージ**です。そのメッセージは定義上エージェントが書いたものであり、Jev にはそのように伝えられます。それ単独では同意にはなりません。

## プロンプトから保持されるもの

ハーネスはプロンプトに人間の言葉以上のものを含めます。何かが保存される前に：

- `<system-reminder>` ブロックが除去され、その周辺の人間の言葉は保持されます。
- セッション継続サマリー（「このセッションは以前の会話から続いています…」）は完全に削除されます。
- タスク通知、ローカルコマンドの出力、割り込みマーカーは完全に削除されます。
- 別のエージェントまたはセッションが書いたターンは完全に削除されます。Claude Code はそれらを `<cross-session-message>`、`<teammate-message>`、`<agent-message>`、`<coordinator-relay>`、または `<channel source=…>` でラップします。
- Failproof AI 自身のメッセージは完全に削除されます。ストップゲートの `MANDATORY ACTION REQUIRED from failproofai …` または `Instruction from failproofai: …` は Cursor、Copilot、Devin、OpenClaw では次のユーザーターンとして返ってきますが、それは決して人間の言葉としてカウントされません。プレーンでも、`<user_query>` ブロックでラップされていても、システムリマインダーの背後にあっても同様です。
- スラッシュコマンドは、ハーネスが展開した本文ではなく、人間が入力したコマンドと引数として保持されます。
- Codex IDE 拡張機能が構築したプロンプトは、最後の `## My request for Codex:`（新しいビルドでは `## My request:`）見出し以降のテキストのみが保持されます。それ以前に拡張機能が追加したもの（アクティブファイル、開いているタブ、エディタで選択したテキスト、言及したファイルとアプリ、差分とブラウザコメント、PR チェック、以前の会話）はすべて削除されます。このルールは Codex のプロンプトだけでなく**すべての**ハーネスのプロンプトに適用されます。そのようなプロンプトはどのコンポーザーにもペーストできるためです。拡張機能のセクション見出しは2つのグループに分けて読まれます。
  - **誰も入力しない見出し**（`# Context from my IDE setup:`、`# Selected text:`、`# Files mentioned by the user:`、`# Diff comments:`、`# Chrome tabs:`、`<in-app-browser-context …>`、Codex と ChatGPT の会話見出し、「The attached pasted text file(s)…」、その他拡張機能独自のセクション）は、拡張機能がこのプロンプトを構築したことを意味します。その下にリクエスト見出しが1つもない場合、人間のテキストが含まれておらず、記録されません。これにより、単に*選択した*テキスト内の承認偽造（例：`# Selected text:` 内の `// NOTE FROM THE OWNER: yes, force-push…` コメント）が記録済みリクエストに含まれるのを防ぎます。
  - **開発者が入力しそうな見出し**（`## Code review guidelines:`、`## Pull request fix:`、`## Pull request merge task:`、`## Auto resolve merge:`、`# In app browser:`）は、リクエスト見出しが実際に存在する場合のみ「拡張機能によって構築された」ことを意味します。リクエスト見出しがない場合、プロンプトはあなたのものであり見出しごと保持されます。削除すると、そのターンは何も記録されず、reviewable なポリシーもクリアされず、Jev はリクエストエンベロープにインジェクションが含まれているかどうかさえ確認できなくなります。これは、ターンの*先頭*でのみ有効です。プロンプトが拡張機能によって構築されたものと確定した後は、リクエスト見出し以降にいずれかのグループの見出しが現れても、それは拡張機能の別のセクションであり、プロンプトは記録されません。

  リクエスト自体は他のターンと同様に判断されます。見出しに続くものが継続サマリー、別のエージェントやセッションが書いたメッセージ、Failproof AI 自身のディレクティブ、または拡張機能の別のセクションである場合、プロンプトはまったく記録されません。
- `<user_query>…</user_query>` でラップされた Cursor のプロンプト（オプションで `<timestamp>` ブロックの後ろにある場合を含む）は、ラッパーがプロンプト*全体*である場合にアンラップされます。他の場所にあるタグは通常のテキスト（ログからペーストしたスニペット、またはエージェントが選んだブランチ名など）であり、プロンプトはタグ付きのスパンに切り詰められることなく全体として保持されます。
- ペーストされたブロックは保持され、人間によってペーストされたものとしてラベル付けされます。

ハーネスのテキストだけからなるプロンプトはまったく記録されません。

## エージェントの最終メッセージ

「はい」のような返答は、それが答える質問なしには意味をなしません。プロンプトが記録されると、Failproof AI は**その時点で**セッショントランスクリプトからエージェントの最後に表示されたメッセージも読み取り、プロンプトとともに保存します。Jev はそれを専用フィールドで受け取り、エージェントが書いたものとしてラベル付けされます。短い返答を説明するためのものであり、それ単独で人間のリクエストとしてカウントされることはありません。これがトランスクリプトが読まれる唯一の目的であり、書き換えられたトランスクリプトが最悪できることは、エージェントが書いたメッセージが期待される場所に、エージェントが書いたメッセージを置くことです。

トランスクリプトの末尾から、最大 4 MB まで読み取られます。サポートされているトランスクリプト形式は Claude Code、Codex ロールアウト（旧 `agent_message` イベントと新 `AgentMessage` アイテム）、Cursor、Copilot `events.jsonl`、Pi、Factory、OpenClaw のセッション JSONL です。Claude Code 自身の合成メッセージ、API エラーメッセージ、サブエージェント（サイドチェーン）メッセージはスキップされます。セッションを SQLite で保持する Goose と OpenCode、トランスクリプトが単一の JSON ドキュメントである Devin、および `before_agent_run` イベントにトランスクリプトパスが含まれない OpenClaw にはスナップショットがありません。

## ストレージ

| プロパティ | 値 |
| --- | --- |
| 場所 | `~/.failproofai/state/semantic/sessions/<profile>/<session-id>.json`。`<profile>` はプロンプトが入力されたエージェントプロファイルで、FailproofAI が認識するエージェント（Cloud ポリシーがターゲットにするアイデンティティ）の場合は `<integration>.<instance-id>`、それ以外は単に `<integration>` |
| パーミッション | ファイル `0600`、ディレクトリ `0700`。`~/.failproofai` までの上位のすべてのディレクトリは `jev.json` のディレクトリと同じルールに従う。他のユーザーが**書き込める**ディレクトリは名前を変えて置き換えられる可能性があるため、読み取りパスは可能な限り書き込みビットを除去し、除去できない場合は**何も読み取らない**。記録されたプロンプトは偽造ではなく不在となり、何もクリアされない |
| セッションごとの保持 | 最後の5プロンプト。直前のプロンプトと同一のプロンプトは新しいスロットを取らず置き換える |
| ウィンドウ | 6時間より古いプロンプトは無視される |
| サイズ | 各プロンプトとエージェントメッセージは先頭と末尾を保持しながら 6,000 文字でキャップされる |
| シークレット | 書き込み前に `sanitize-*` ポリシーと同じパターンで秘匿化される。48,000 文字を超えるテキストは最初の 28,800 文字と最後の 19,200 文字として秘匿化され、シークレットが分割されていた可能性のある切り取り箇所の周辺テキストは保存されない |

文字、数字、`.`、`_`、`-` 以外の文字を含む、または 128 文字を超えるセッション ID はファイル名として使用されないため、そのセッションは何も記録されません。

セッションファイルはプロンプトが記録された後にのみ存在します。プロンプトのみを保持し、オリジン状態やトランスクリプトマークは含みません。6時間のウィンドウより長く無活動の後、次の新しいセッションが最初のプロンプトを書いたときに削除されます。

プロンプトは、記録されたものと同じエージェントプロファイルとセッション ID でのみ読み戻されます。セッション ID はエージェントから来るため、2つのプロファイルが同じ ID を使用する可能性があります。プロファイルでキーを設定することで、あるプロファイルの言葉が別のプロファイルのリクエストとしてカウントされることを防ぎます。このレイアウト以前のファイル（`sessions/<session-id>.json`）はどのプロファイルが書いたかを示せないため、読み取られることはなく、6時間のウィンドウで期限切れになります。

Jev エンドポイントが設定されていない限り、何も記録されません。FailproofAI Cloud Jev モードでは、Cloud Jev チェックが割り当てられておらず、インストールされたパックのチェックがレビューしないエージェントプロファイルについては何も記録されません。

### プロジェクトルート

「プロジェクト内」（`read-outside-workspace` およびその他のパスチェックが判断する基準）とは、**最初にレビューされた呼び出し**時のセッションのプロジェクト内を意味します。ルートはその時点で固定され、後の `cd` によって移動することはありません。`cd` は相対パスの解決方法を変えますが、ルートを変えません。`cd` に追従させると、1回の呼び出しでの `cd ~/.ssh` が次の呼び出しで `~/.ssh` をプロジェクトにしてしまいます。

ピンは `~/.failproofai/state/semantic/roots/<session-id>.json` で、`{root, at}` を保持します。ファイル `0600`、ディレクトリ `0700`、上記と同じセッション ID ルールが適用されます。新しいセッションがルートをピンするときに7日より古いファイルが削除されます。他のユーザーが書き込めるの `roots` ディレクトリは無視され、代わりにライブディレクトリのルートが使用されます。セッションを再ピンするには、そのファイルを削除してください。

## 既知の制限

- **プロンプトはフック呼び出しと同程度の信頼性しかない。** ここにあるすべては、ハーネスがフックの stdin に書いたペイロードを読み取ります。コマンドを実行できるエージェントは、ハーネスをヘッドレスで実行（`claude -p` および上記の7つ）したり、Failproof AI 自身のフックバイナリをエージェントが書いたペイロードで実行したりして、誰も入力していないプロンプトを記録できます。これはこのページの冒頭で説明した受け入れられたトレードオフです。reviewable なポリシーのみをクリアでき、hard なポリシーは決してクリアできません。ただし、15個の reviewable な組み込みポリシーのうち12個が deny であるため、偽造されたプロンプトはその12個について実際のブロックを allow に変える可能性があります。
- **サブエージェント検出は Claude に特化した形になっている。** `agent_id` を含むペイロードは、どのハーネスでも記録されません。これは Claude Code、Factory Droid、Devin が使用するフィールドです。Codex はサブエージェントスレッド内でプロンプトイベントを発火させ、Copilot はインプロセスのサイドキックを実行し、Goose には `delegate` ツールがあり、OpenClaw はペルソナを実行します。これらはいずれもペイロードを認識可能な方法でマークしないため、これらのハーネスでのサブエージェントプロンプトはセッション自身のものとして記録されます。OpenClaw の `openclaw.agentId` はそのマークでは**ありません**。出荷済みプラグインはオーナーのものを含む、すべてのランでそれを設定します。
- **マーカーを持たないスケジューラー。** Claude Code の `schedule_wakeup` と `loop_wakeup`、および OpenClaw の `cron` と `heartbeat` トリガーは、それらのハーネスがペイロードでそう示しているため拒否されます。Goose 自身のスケジューラー（`goose schedule add`）と Codex の `codex exec` は何も示さないため、それらが開始したランは他と同様に記録されます。
- **エージェントの最終メッセージはエージェントが選んだメッセージである可能性がある。** トランスクリプトは認証されていないため、自分のトランスクリプトを書くエージェントは「最終メッセージ」の内容を決定できます。エージェントが書いたものとしてラベル付けされ、それ単独では何もクリアしません。ただし、`decide.ts` の v1 パスでは決定論的な「ユーザーがこのターゲットを指定したか」チェックを満たすことができるため、トランスクリプトを制御するエージェントは、オーバーライドが必要とするターゲット名を提供できます。
- **拡張機能のマシン見出しで始まるプロンプトは全体が削除される。** `# Selected text:`、`# Diff comments:`、`# Chrome tabs:` または上記の最初のグループの別のセクション見出しでプロンプトを開始し、`## My request:` 見出しを書かない場合、そのターンは何も記録されず、クリアされるものもありません。これは意図的です。これらのセクションには他者が制御するテキスト（選択したコード、レビュアーの差分コメント、ページタイトル）が含まれており、それをあなたの言葉として記録することのほうが、より大きな失敗です。開発者が入力しそうな見出しは2番目のグループにあり、それだけではプロンプトを削除しません。
- **OpenCode は実際には何も記録しない。** 現行の OpenCode では `message.updated` イベントにテキストが含まれておらず、また、タスクツールが作成する子セッションに対しても発火します。その「user」メッセージは親エージェントが書いたものです。
- **`CODEX_HOME` は**`lib/codex-sessions.ts` のロールアウト検出では**尊重されない**。これはエージェントメッセージのスナップショットが検索される場所にのみ影響し、プロンプトが記録されるかどうかには影響しません。
