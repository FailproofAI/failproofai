[Jev ポリシーレビュー](/ja/policies/jev) を設定すると、エバリュエーターはゲート対象のツール呼び出しごとに、**人間が何を要求したか** に基づいて判定します。ハーネスがエージェントに提示したテキストは参照しません。「はい、強制プッシュしてください」のような返答で **reviewable** ポリシーをクリアできます — 要求を読めない正規表現が実際の作業の 3 分の 1 をブロックしてしまうため、これがエバリュエーターの存在意義です。

そのテキストの取得元は一つです: **ハーネス自身がプロンプト送信イベント時にフックへ渡すプロンプト** です。Failproof AI は人間がタイプした部分 — ハーネスのラッピングを除去し、シークレットを削除し、上限を設けた上で — を `0600` パーミッションのファイルとして自身のステートディレクトリに記録します。ディスク上のセッションログは参照しません。セッションのトランスクリプトはエージェントが 1 つのコマンドで書き換えられるファイルなので、プロンプトの作成者を問い合わせることはありません。

## 受け入れているリスクについて

コマンドを実行できるエージェントは、ハーネスにプロンプトを送信させることができます。`claude -p "…"`、`codex exec`、`copilot -p`、`cursor-agent -p`、`devin -p`、`droid -p`、`goose run -t`、`pi -p` はいずれも、エージェントが制御する子セッションで、人間がタイプした場合とまったく同じプロンプト送信イベントを同じペイロードで発火させます。また Failproof AI 自身のフックバイナリを実行し、自らが書いたペイロードを渡すこともできます。Failproof AI の内部からは本物との区別ができません — どちらも同じプログラムが同じ stdin を読み取る動作です。

**つまり、シェルを持つエージェントは自分自身への同意を偽造できます。** これは 2026-09-23 に意図的に行われたトレードオフであり、その両面は次のとおりです:

- **得られるもの。** 代替案が構築・測定されました: 人間がプロンプトの作成者であることをハーネスが明示するフィールドを必須とし、それがなければ何も記録しない設計です。現在出荷されているハーネスにそのようなフィールドを送信するものは存在しないため、そのバージョンでは **すべてのハーネスで何も記録されませんでした** — Jev は意図が不明なまますべての呼び出しを判定し、どのポリシーもクリアできませんでした。一度も発動しないキャプチャは安全な製品ではなく、製品ではありません。
- **できないこと。** 記録されたプロンプトは **reviewable** とマークされたポリシーのみをクリアします。**hard** ポリシーは Jev がどう言おうともクリアされないため、偽造されたプロンプトによって hard の deny が allow に変わることはありません — フックをスキップしてもエージェントには何の利益もありません。ハーネスはツール呼び出しに対して Failproof AI を独立して呼び出します。
- **最大限に悪用された場合にできること。** 最悪の場合、15 の reviewable 組み込みポリシーのうちの 1 つをクリアできます — **そのうち 12 はブロック** します。`protect-env-vars`、`block-env-files`、`block-read-outside-cwd`、`block-rm-rf`、`block-force-push`、`block-secrets-write`、および 6 つのインフラ CLI ブロック (`block-kubectl`、`block-terraform`、`block-aws-cli`、`block-gcloud`、`block-az-cli`、`block-helm`) は deny です。偽造された同意によって、環境シークレットの表示、`.env` ファイルの読み取り、プロジェクト外の読み取り、`rm -rf`、強制プッシュ、シークレットファイルへの書き込み、またはライブインフラの変更において、実際の deny を allow に変えることができます。`warn-git-amend`、`warn-destructive-sql`、`warn-global-package-install` のみがnudge です。デフォルトインストールでは 12 のうち 2 つ (`protect-env-vars` と `block-env-files`) が有効になり、残りの 10 は誰かが明示的に有効にしたマシンにのみ適用されます。いかなるプロンプトも到達できないのは hard とされているもの全て — `block-sudo`、`block-curl-pipe-sh`、`block-push-master`、`block-work-on-main`、エージェントが Failproof AI を無効化するのを防ぐガード、および reviewable とマークされていないその他すべての組み込みポリシーです。[ポリシーの権限](/ja/policies/authority) に 15 すべてとそれぞれのレビュー方法が記載されています。

依然として拒否されるのは、安価に確認でき、エージェントが単に要求するだけでは取得できないもの全てです: ハーネス自身のペイロードがマシン送信としてマークするターン、サブエージェントを名指しするペイロード、単純な名前ではないセッション ID、プロンプト送信以外のイベント、そしてハーネスのラッピングのみのテキスト — 複数のハーネスが次のユーザーターンとして返す Failproof AI 自身のストップゲートワードを含みます。

## ハーネス別テーブル

「テキストフィールド」は Failproof AI のハーネス別正規化後の stdin ペイロードフィールドです。「記録済み」はプロンプトが人間のリクエストとして保持されるかどうかを示します。

| ハーネス | `--cli` | プロンプトイベント → 正規化 | テキストフィールド | 記録済み | エージェントの最終メッセージ取得元 |
| --- | --- | --- | --- | --- | --- |
| Claude Code | `claude` | `UserPromptSubmit` | `prompt` | 記録される。ただしペイロードの `source` が誰も送信していないターンを示す場合を除く (`loop_wakeup`、`schedule_wakeup`、`poll_event`、`system`)。`user`、`sdk`、不明な値、`source` を送信しないビルドはすべて記録される | セッショントランスクリプト (`transcript_path`) |
| Codex | `codex` | `user_prompt_submit` → `UserPromptSubmit` | `prompt` | 記録される | ロールアウト JSONL (`agent_message`、`AgentMessage`) |
| GitHub Copilot CLI | `copilot` | `UserPromptSubmit` | `prompt` | 記録される | `events.jsonl` (`assistant.message`) |
| Cursor | `cursor` | `beforeSubmitPrompt` → `UserPromptSubmit` | `prompt` | 記録される。プロンプト全体が `<user_query>` ラッパーの場合はそれを剥がす | エージェントトランスクリプト JSONL |
| OpenCode | `opencode` | `message.updated` (user ロール) → `UserPromptSubmit` | `prompt` | 記録される — ただし現在の OpenCode はそのイベントにテキストを含まないため、実際には何も記録されない。同一メッセージの繰り返しは 1 回のみ記録される | なし (セッションは SQLite) |
| Pi | `pi` | `input` → `UserPromptSubmit` | `prompt` | 記録される。ただし `input_source` が `extension` の場合を除く — テキストがモデルによって生成またはリポジトリから派生した可能性がある別の拡張機能の `sendUserMessage()` | Pi セッション JSONL |
| Hermes | `hermes` | なし | — | 記録されない — Hermes にはプロンプト送信イベントがない | — |
| OpenClaw | `openclaw` | `before_agent_run` → `UserPromptSubmit` | `prompt` | 記録される。ただしランのメタデータがマシン実行を示す場合を除く: `user` 以外の `trigger`、`external_user` 以外の `inputProvenance.kind`、または `senderIsOwner: false` | なし (`before_agent_run` はトランスクリプトパスを持たない) |
| Factory Droid | `factory` | `UserPromptSubmit` | `prompt` | 記録される | droid セッション JSONL |
| Devin CLI | `devin` | `UserPromptSubmit` | `prompt` | 記録される | なし (セッションは SQLite) |
| Antigravity CLI | `antigravity` | `PreInvocation` → `UserPromptSubmit` | なし | 記録されない — `PreInvocation` はターン内の*すべての*モデル呼び出し前に発火し、プロンプトテキストを持たない | — |
| Goose | `goose` | `UserPromptSubmit` | `message` | 記録される | なし (セッションは SQLite) |

2 つのハーネスは何も記録しませんが、いずれも同じ理由です: イベントに人間のテキストが含まれていません。Hermes にはプロンプト送信イベントがありません — ネイティブプラグインが `pre_llm_call` を自ら処理し、ツール、セッション、サブエージェントイベントのみを転送します。Antigravity の `PreInvocation` は人間のターンとその後に続く 5 つのターンすべてで、すべてのモデル呼び出しの前に発火し、プロンプトフィールドを持ちません。フックは同じ会話に `userMessage` ステップを注入することもできます。どちらのイベントにも記録すべきものがありません。

## プロンプトを人間のものとみなす条件

1. **イベント。** Failproof AI がハーネスのプロンプト送信イベントに対して呼び出され、ハンドラーがそれを `UserPromptSubmit` に正規化していること。
2. **ペイロード。** ハーネスがフックの stdin に書き込んでおり、上記のフィールド名でテキストが含まれていること。ペイロードなしで Failproof AI に到達した呼び出しは何も記録されない。
3. **ペイロード内にターンを除外するものがない。** サブエージェントを名指しするペイロード (`agent_id`) はエージェントが自分自身にプロンプトを送っているもの。マシン送信ターンを示す `source`、`input_source`、または OpenClaw のランマーカーは拒否される。**マーカーが存在しない** ことは何も除外しない — これが何も記録しなかったバージョンとの違いであり、ここに挙げるマーカーはすべての出荷ビルドで不在だ。
4. **ラッピングを除去した後に何かが残っている**（後述）。

**セッショントランスクリプトはプロンプトの作成者の証拠にはならない。** このページの以前のバージョンではトランスクリプトのクロスチェックが記載されていました: モデルがプロンプトをスケジューリングしたとトランスクリプトが示した場合は拒否し、トランスクリプトは前のプロンプトが参照したものの続きでなければならないというものでした。そのチェックは廃止されました。トランスクリプトはエージェントがすでにシェルでアクセスできるファイルです — 切り詰め、置換、読み取りバジェットを超えたパディング、ターン開始時のスナップショットと終了時の復元、エージェントが書いたエントリによる再編成などが可能です。強化のたびに同じ偽造の別の手法が登場したため、修正するのではなくメカニズム全体を削除しました。

トランスクリプトは今も一つのことに使用されます: **エージェントの最後に見えるメッセージ**。そのメッセージは定義上エージェントが書いたものであり、Jev にそのように伝えられます。それ単独では同意にはなりません。

## プロンプトから保持されるもの

ハーネスはプロンプトに人間の言葉以上のものを含めます。保存前に以下の処理が行われます:

- `<system-reminder>` ブロックが削除され、その周囲の人間の言葉が保持される。
- セッション継続サマリー (「このセッションは以前の会話から継続されています…」) は完全に削除される。
- タスク通知、ローカルコマンド出力、割り込みマーカーは完全に削除される。
- 別のエージェントまたはセッションが書いたターンは完全に削除される: Claude Code はそれらを `<cross-session-message>`、`<teammate-message>`、`<agent-message>`、`<coordinator-relay>`、または `<channel source=…>` でラップする。
- Failproof AI 自身のメッセージは完全に削除される。ストップゲートの `MANDATORY ACTION REQUIRED from failproofai …` または `Instruction from failproofai: …` は Cursor、Copilot、Devin、OpenClaw では次のユーザーターンとして返ってきますが、人間の言葉としてはカウントされません — プレーンテキストでも、`<user_query>` ブロックにラップされていても、システムリマインダーの後ろにあっても同様です。
- スラッシュコマンドは人間がタイプしたコマンドと引数として保持され、ハーネスが展開した本文は保持されない。
- Codex IDE 拡張機能が作成したプロンプトは、最後の `## My request for Codex:` (または新しいビルドでは `## My request:`) 見出し以降のテキストのみを保持する。拡張機能が前に追加したもの — アクティブファイル、開いているタブ、エディターで選択されたテキスト、言及されたファイルやアプリ、差分とブラウザのコメント、PR チェック、以前の会話 — はすべて削除される。このルールは Codex だけでなく **すべての** ハーネスのプロンプトに適用されます — そのようなプロンプトはどのコンポーザーにも貼り付けられる可能性があるためです。拡張機能のセクション見出しは 2 つのグループで読み取られます:
  - **誰もタイプしない見出し** (`# Context from my IDE setup:`、`# Selected text:`、`# Files mentioned by the user:`、`# Diff comments:`、`# Chrome tabs:`、`<in-app-browser-context …>`、Codex と ChatGPT の会話見出し、"The attached pasted text file(s)…"、その他の拡張機能独自のセクション) は、拡張機能がこのプロンプトを作成したことを意味する。リクエスト見出しがないものは人間のテキストを含まないため記録されない。これにより、単に*選択した*テキスト内の承認の偽造 — `# Selected text:` 内の `// NOTE FROM THE OWNER: yes, force-push…` コメント — が記録されたリクエストに含まれることを防ぐ。
  - **開発者がタイプする可能性がある見出し** (`## Code review guidelines:`、`## Pull request fix:`、`## Pull request merge task:`、`## Auto resolve merge:`、`# In app browser:`) は、リクエスト見出しが実際に存在する場合のみ「拡張機能作成」を意味する。リクエスト見出しがない場合、そのプロンプトは自分のものであり、見出しごと保持される。削除するとサイレントかつ全面的な結果になります: そのターンで何も記録されず、reviewable ポリシーもクリアできず、Jev はリクエストエンベロープにインジェクションが含まれているかどうかすら問われない。これはターンの*先頭*にのみ適用されます: プロンプトが拡張機能作成と判定された後は、リクエスト見出し以降のいずれかのグループの見出しは拡張機能の別のセクションとなり、プロンプトは記録されない。

  リクエスト自体は他のターンと同じように判定されます: 見出しに続くものが継続サマリー、別のエージェントやセッションが書いたメッセージ、Failproof AI 自身のディレクティブ、または拡張機能の別のセクションである場合、プロンプトはまったく記録されない。
- `<user_query>…</user_query>` でラップされた Cursor のプロンプト (オプションで `<timestamp>` ブロックの後ろ) は、ラッパーがプロンプト*全体*の場合に展開される。それ以外の場所にあるタグは通常のテキスト — ログから貼り付けたスニペット、エージェントが選んだブランチ名など — であり、タグのスパンに切り詰めるのではなくプロンプト全体が保持される。
- 貼り付けられたブロックは保持され、人間が貼り付けたものとしてラベル付けされる。

ハーネステキストのみのプロンプトはまったく記録されない。

## エージェントの最終メッセージ

「はい」という返答は、それが答える質問なしには意味を持ちません。プロンプトが記録されると、Failproof AI はセッショントランスクリプトから**その時点での**エージェントの最後に見えるメッセージも読み取り、プロンプトと共に保存します。Jev はそれを専用フィールドで受け取り、エージェントが書いたものとしてラベル付けされます: 短い返答を説明しますが、単独では人間のリクエストとしてカウントされません。これはトランスクリプトが読み取られる唯一のことであり、書き換えられたトランスクリプトが最悪できることは、エージェントが書いたメッセージがあるべき場所にエージェントが書いたメッセージを置くことです。

トランスクリプトの末尾から最大 4 MB を読み取ります。サポートされているトランスクリプト形式は Claude Code、Codex ロールアウト (古い `agent_message` イベントと新しい `AgentMessage` アイテム)、Cursor、Copilot の `events.jsonl`、Pi、Factory、OpenClaw のセッション JSONL です。Claude Code 自身の合成メッセージ、API エラーメッセージ、サブエージェント (サイドチェーン) メッセージはスキップされます。セッションを SQLite で保持する Goose と OpenCode、トランスクリプトが単一の JSON ドキュメントである Devin、`before_agent_run` イベントがトランスクリプトパスを持たない OpenClaw にはスナップショットがありません。

## ストレージ

| プロパティ | 値 |
| --- | --- |
| 場所 | `~/.failproofai/state/semantic/sessions/<profile>/<session-id>.json`。`<profile>` は プロンプトがタイプされたエージェントプロファイル: FailproofAI が認識するエージェントの場合は `<integration>.<instance-id>` (Cloud ポリシーがターゲットとするID)、それ以外の場合は `<integration>` のみ |
| パーミッション | ファイル `0600`、ディレクトリ `0700`。その上の `~/.failproofai` までのすべてのディレクトリも同じルールが適用される: 他のユーザーが**書き込み**できるディレクトリは名前変更して置換できるため、読み取りパスは可能な限りその書き込みビットを削除し、削除できない場合は**何も読まない**。記録されたプロンプトは偽造されるのではなく不在となり、何もクリアされない |
| セッションごとの保持 | 最後の 5 プロンプト。直前と同一のプロンプトは新しいスロットを取らずに置き換える |
| ウィンドウ | 6 時間より古いプロンプトは無視される |
| サイズ | 各プロンプトとエージェントメッセージは先頭と末尾を保持しながら 6,000 文字にキャップされる |
| シークレット | 書き込み前に `sanitize-*` ポリシーと同じパターンで削除される。48,000 文字を超えるテキストは最初の 28,800 文字と最後の 19,200 文字として削除され、シークレットが分割されていた可能性がある切り取り箇所の隣接テキストは保存されない |

文字、数字、`.`、`_`、`-` 以外の文字を含むセッション ID、または 128 文字を超えるものはファイル名として使用されないため、それらには何も記録されない。

セッションファイルはプロンプトが記録された後にのみ存在します。プロンプトのみを保持し — オリジンの状態もトランスクリプトのマークも含みません — 6 時間ウィンドウより長く無音状態が続いた後、次のセッションが最初のプロンプトを書き込む際に削除されます。

プロンプトは、記録されたのと同じエージェントプロファイルとセッション ID の組み合わせにのみ読み取られます。セッション ID はエージェントから来るため、2 つのプロファイルが同じ ID を使用する可能性があります。プロファイルでキーを付けることで、あるプロファイルの言葉が別のプロファイルのリクエストとしてカウントされるのを防ぎます。このレイアウト以前のファイル (`sessions/<session-id>.json`) はどのプロファイルが書いたかを示す情報がないため読み取られず、6 時間ウィンドウで期限切れになります。

Jev エンドポイントが設定されていない限り、何も記録されません。FailproofAI Cloud の Jev モードでは、Cloud Jev チェックが割り当てられておらず、インストールされたパックのチェックがレビューしないエージェントプロファイルについては何も記録されません。

### プロジェクトルート

「プロジェクト内」— `read-outside-workspace` と他のパスチェックが判定する対象 — とは、セッションの**最初のレビュー対象呼び出し**時にいたプロジェクト内を意味します。ルートはその時点でピン留めされ、後続の `cd` によって移動しません。ただし `cd` は相対パスの解決方法を変更します。`cd` に追随させると、ある呼び出しでの `cd ~/.ssh` が次の呼び出しで `~/.ssh` をプロジェクトにしてしまいます。

ピンは `~/.failproofai/state/semantic/roots/<session-id>.json` に保存され、`{root, at}` を保持します: ファイル `0600`、ディレクトリ `0700`、上記と同じセッション ID ルールが適用されます。7 日より古いファイルは新しいセッションがルートをピン留めする際に削除されます。他のユーザーが書き込み可能な `roots` ディレクトリは無視され、代わりにライブディレクトリのルートが使用されます。セッションを再ピン留めするには、そのファイルを削除してください。

## 既知の制限

- **プロンプトはフック呼び出しと同程度の信頼性しかない。** ここに記載されているすべては、ハーネスがフックの stdin に書き込んだペイロードを読み取ります。コマンドを実行できるエージェントは、ハーネスをヘッドレスで実行したり (`claude -p` と上記の 7 つ)、または Failproof AI 自身のフックバイナリを自ら書いたペイロードで実行して、誰もタイプしていないプロンプトを記録することができます。これはこのページの冒頭で説明した受け入れ済みのトレードオフです: reviewable ポリシーのみをクリアし、hard ポリシーは決してクリアしませんが、15 の reviewable 組み込みポリシーのうち 12 は deny なので、偽造されたプロンプトによってその 12 では実際のブロックが allow に変わる可能性があります。
- **サブエージェント検出は Claude の形状に依存している。** `agent_id` を持つペイロードはどのハーネスでも記録されません。これは Claude Code、Factory Droid、Devin が使用するフィールドです。Codex はサブエージェントスレッド内でプロンプトイベントを発火させ、Copilot はインプロセスのサイドキックを実行し、Goose には `delegate` ツールがあり、OpenClaw はペルソナを実行しますが — いずれもこれが認識できる形でペイロードにマークしないため、それらのハーネスでのサブエージェントプロンプトはセッション自身のものとして記録されます。OpenClaw の `openclaw.agentId` はそのマークでは**ありません**: 出荷されたプラグインはオーナーのものを含むすべての実行でそれを設定します。
- **マーカーを持たないスケジューラー。** Claude Code の `schedule_wakeup` と `loop_wakeup`、および OpenClaw の `cron` と `heartbeat` トリガーは、それらのハーネスがペイロードでそのように示しているため拒否されます。Goose 自身のスケジューラー (`goose schedule add`) と Codex の `codex exec` は何も示さないため、それらによって開始された実行は他のものと同様に記録されます。
- **エージェントの最終メッセージはエージェントが選んだメッセージである可能性がある。** トランスクリプトは認証されていないため、自分のトランスクリプトを書けるエージェントは「最終メッセージ」の内容を決定できます。エージェントが書いたとしてラベル付けされ、それ単独では何もクリアしませんが、`decide.ts` の v1 パスでは確定的な「ユーザーがこのターゲットを名指しした」チェックを満たすことができるため、トランスクリプトを制御するエージェントがオーバーライドに必要なターゲット名を提供できることに注意してください。
- **拡張機能の機械的な見出しで始まるプロンプトは全体が削除される。** `# Selected text:`、`# Diff comments:`、`# Chrome tabs:` または上記の最初のグループの別のセクション見出しでプロンプトを開始し、`## My request:` 見出しを書かなければ、そのターンには何も記録されません — したがってクリアされるものも何もありません。これは意図的です: これらのセクションには他の誰かが制御するテキスト (選択したコード、レビュアーの差分コメント、ページタイトル) が含まれており、それを自分の言葉として記録することの方が深刻な問題です。開発者がタイプする可能性がある見出しは 2 つ目のグループにあり、単独でプロンプトを削除することはありません。
- **OpenCode は実際には何も記録しない。** `message.updated` イベントは現在の OpenCode ではテキストを含まず、またタスクツールが作成する子セッションでも発火します。その「ユーザー」メッセージは親エージェントが書いたものです。
- **`CODEX_HOME` は尊重されない** `lib/codex-sessions.ts` のロールアウトディスカバリーによって。これはエージェントメッセージのスナップショットを探す場所にのみ影響し、プロンプトが記録されるかどうかには影響しません。
