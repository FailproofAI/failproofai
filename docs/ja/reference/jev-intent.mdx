[Jev ポリシーレビュー](/ja/policies/jev)を設定すると、エバリュエーターはゲートされた各ツール呼び出しを、ハーネスがエージェントに提示したテキストではなく、**人間が何を求めたか**を基準に判断します。「はい、強制プッシュしてください」のような返答は **reviewable** ポリシーをクリアできます — リクエストを読み取れない正規表現が実際の作業の3分の1をブロックしてしまうのに対し、これがエバリュエーターの存在意義です。

そのテキストは一箇所から来ます。**ハーネス自身がプロンプト送信イベント時にフックに渡すプロンプト**です。Failproof AI は、人間がタイプした部分（ハーネスのラッピングを除去し、シークレットを編集し、文字数を制限した状態）を、自身のステートディレクトリ配下の `0600` ファイルに記録します。ディスク上の何も参照しません。セッションのトランスクリプトはエージェントが1つのコマンドで書き換えられるファイルであるため、誰がプロンプトを書いたかを問い合わせることはありません。

## このアプローチが受け入れるリスク（率直に）

コマンドを実行できるエージェントは、ハーネスにプロンプトを送信させることができます。`claude -p "…"`、`codex exec`、`copilot -p`、`cursor-agent -p`、`devin -p`、`droid -p`、`goose run -t`、`pi -p` はいずれも、エージェントが制御する子セッション内で、人間がタイプした場合と同じプロンプト送信イベントを、同じペイロードで発火させます。また、Failproof AI 自身のフックバイナリを実行して、自分が書いたペイロードを与えることもできます。Failproof AI の内部では、どちらも本物と区別できません — どちらも同じプログラムが同じ stdin を読み取っているからです。

**つまり、シェルを持つエージェントは自分自身の同意を偽造できます。** これは 2026-09-23 に意図的に受け入れたトレードオフであり、その両面は以下の通りです。

- **得られるもの。** 代替案は構築して計測しました。ハーネスが人間をプロンプトの作者として指定するフィールドを要求し、そうでなければ何も記録しない方式です。しかし、既存のハーネスはそのようなフィールドを送信しないため、そのバージョンは**すべてのハーネスで何も記録できませんでした** — Jev はすべての呼び出しを意図不明として判断し、1つのポリシーもクリアできませんでした。一度も発動しないキャプチャは、より安全な製品ではなく、製品として機能しません。
- **できないこと。** 記録されたプロンプトは、**reviewable** としてマークされたポリシーをクリアするためだけに使われます。**hard** ポリシーは Jev が何を言っても絶対にクリアされないため、偽造されたプロンプトがハードな deny を allow に変えることはできません — フックをスキップしてもエージェントには何の得にもなりません。ハーネスはツール呼び出しのために独立して Failproof AI を呼び出すためです。
- **最大規模でできること。** 最悪の場合でも、15 の reviewable 組み込みポリシーのうちの1つをクリアできるだけです — そして**15 のうち 12 はブロック**します。`protect-env-vars`、`block-env-files`、`block-read-outside-cwd`、`block-rm-rf`、`block-force-push`、`block-secrets-write`、および 6 つのインフラ CLI ブロック（`block-kubectl`、`block-terraform`、`block-aws-cli`、`block-gcloud`、`block-az-cli`、`block-helm`）は deny であるため、偽造された同意は、環境シークレットの表示、`.env` ファイルの読み取り、プロジェクト外の読み取り、`rm -rf`、強制プッシュ、シークレットファイルの書き込み、ライブインフラの変更についての本物の deny を allow に変えることができます。`warn-git-amend`、`warn-destructive-sql`、`warn-global-package-install` のみが通知です。デフォルトのインストールでは 12 のうち `protect-env-vars` と `block-env-files` の 2 つのみが有効になっており、残りの 10 は誰かが明示的に有効にしたマシンにのみ影響します。どのプロンプトも届かないのは、すべての hard なもの — `block-sudo`、`block-curl-pipe-sh`、`block-push-master`、`block-work-on-main`、エージェントが Failproof AI を無効化するのを防ぐガード、および reviewable としてマークされていない他のすべての組み込みポリシーです。[ポリシー権限](/ja/policies/authority)では 15 すべてと各ポリシーがどのように review されるかを一覧しています。

まだ拒否されるのは、確認が容易であり、エージェントが単に要求するだけでは取得できないものすべてです。ハーネス自身のペイロードが機械送信とマークしたターン、サブエージェントを指定するペイロード、プレーンな名前ではないセッション ID、プロンプト送信イベント以外のイベント、そしてハーネスのラッピングのみからなるテキスト — いくつかのハーネスが次のユーザーターンとしてフィードバックする Failproof AI 自身のストップゲートワードを含みます。

## ハーネス別テーブル

「テキストフィールド」は Failproof AI のハーネスごとの正規化後の stdin ペイロードフィールドです。「記録済み」はプロンプトが人間のリクエストとして保持されるかどうかを示します。

| ハーネス | `--cli` | プロンプトイベント → 正規化 | テキストフィールド | 記録済み | エージェントの最終メッセージ取得元 |
| --- | --- | --- | --- | --- | --- |
| Claude Code | `claude` | `UserPromptSubmit` | `prompt` | はい。ただし、ペイロードの `source` が誰も送信していないターンを指名する場合（`loop_wakeup`、`schedule_wakeup`、`poll_event`、`system`）を除く。`user`、`sdk`、不明な値、および `source` を送信しないビルドはすべて記録される | セッショントランスクリプト（`transcript_path`） |
| Codex | `codex` | `user_prompt_submit` → `UserPromptSubmit` | `prompt` | はい | ロールアウト JSONL（`agent_message`、`AgentMessage`） |
| GitHub Copilot CLI | `copilot` | `UserPromptSubmit` | `prompt` | はい | `events.jsonl`（`assistant.message`） |
| Cursor | `cursor` | `beforeSubmitPrompt` → `UserPromptSubmit` | `prompt` | はい。プロンプト全体が `<user_query>` ラッパーの場合はそれを剥がす | エージェントトランスクリプト JSONL |
| OpenCode | `opencode` | `message.updated`（user ロール）→ `UserPromptSubmit` | `prompt` | はい — ただし現在の OpenCode はそのイベントにテキストを持たないため、実際には何も記録されない。同一メッセージの繰り返しは1回のみ記録される | なし（セッションは SQLite） |
| Pi | `pi` | `input` → `UserPromptSubmit` | `prompt` | はい。ただし `input_source` が `extension` の場合を除く — 別の拡張機能の `sendUserMessage()` であり、そのテキストはモデルが書いたものやリポジトリ由来のものである可能性がある | Pi セッション JSONL |
| Hermes | `hermes` | なし | — | いいえ — Hermes にはプロンプト送信イベントがない | — |
| OpenClaw | `openclaw` | `before_agent_run` → `UserPromptSubmit` | `prompt` | はい。ただし、実行メタデータがその実行を機械のものとしてマークしている場合を除く：`user` 以外の `trigger`、`external_user` 以外の `inputProvenance.kind`、または `senderIsOwner: false` | なし（`before_agent_run` はトランスクリプトパスを持たない） |
| Factory Droid | `factory` | `UserPromptSubmit` | `prompt` | はい | droid セッション JSONL |
| Devin CLI | `devin` | `UserPromptSubmit` | `prompt` | はい | なし（セッションは SQLite） |
| Antigravity CLI | `antigravity` | `PreInvocation` → `UserPromptSubmit` | なし | いいえ — `PreInvocation` はターン内の*すべての*モデル呼び出し前に発火し、プロンプトテキストを持たない | — |
| Goose | `goose` | `UserPromptSubmit` | `message` | はい | なし（セッションは SQLite） |

2 つのハーネスは何も記録しませんが、どちらも同じ理由です。イベントが人間のテキストを配信しないのです。Hermes にはプロンプト送信イベントがありません — そのネイティブプラグインは `pre_llm_call` を自ら処理し、ツール、セッション、サブエージェントイベントのみを転送します。Antigravity の `PreInvocation` は、人間のターンとその後の 5 つのモデル呼び出しすべての前に発火し、プロンプトフィールドを持ちません。フックは同じ会話に `userMessage` ステップを挿入することもできます。どちらのイベントにも記録すべきものがありません。

## プロンプトを人間のものとみなす条件

1. **イベント。** Failproof AI がハーネスのプロンプト送信イベントに対して呼び出され、ハンドラーがそれを `UserPromptSubmit` に正規化する。
2. **ペイロード。** ハーネスがフックの stdin に書き込み、上記で指定されたフィールドにテキストを含む。ペイロードなしで Failproof AI に到達した呼び出しは何も記録しない。
3. **ペイロード内のいかなるものもそのターンを除外しない。** サブエージェントを指定するペイロード（`agent_id`）は、エージェントが自分自身にプロンプトを送っていることを示す。機械送信のターンを指定する `source`、`input_source`、または OpenClaw の実行マーカーは拒否される。**不在の**マーカーは何も除外しません — これが何も記録しなかったバージョンとの違いです。なぜなら、ここにあるすべてのマーカーは既存のすべての出荷ビルドで不在だからです。
4. **ラッピングを除去した後に何かが残る**（以下参照）。

**セッショントランスクリプトは誰がプロンプトを書いたかの証拠ではありません。** このページの以前のバージョンではトランスクリプトのクロスチェックを説明していました。モデルがそれをスケジュールしたとトランスクリプトが示している場合はプロンプトを拒否し、前のプロンプトが見ていたものにトランスクリプトが継続していることを要求するというものでした。そのチェックは廃止されました。トランスクリプトは、エージェントがすでにシェルを持っているファイルです — 切り詰め、置換、読み取りバジェット超過のパディング、ターン開始時のスナップショットとターン終了時の復元、エージェントが書いたエントリによる修正が可能です。強化を施すたびに同じ偽造の別の方法が生まれたため、修正するのではなく、仕組み全体を除去しました。

トランスクリプトがまだ読まれることは1つあります：**エージェントの最後の表示メッセージ**です。そのメッセージは定義上エージェントが書いたものであり、Jev にそのように伝えられ、単独では絶対に同意になりません。

## プロンプトから何が保持されるか

ハーネスはプロンプトに人間の言葉以上のものを含めます。何かが保存される前に：

- `<system-reminder>` ブロックは除去され、その周りの人間の言葉は保持される。
- セッション継続サマリー（「このセッションは以前の会話から継続されています…」）は完全に削除される。
- タスク通知、ローカルコマンド出力、割り込みマーカーは完全に削除される。
- 別のエージェントまたはセッションが書いたターンは完全に削除される。Claude Code はそれらを `<cross-session-message>`、`<teammate-message>`、`<agent-message>`、`<coordinator-relay>`、または `<channel source=…>` でラップする。
- Failproof AI 自身のメッセージは完全に削除される。ストップゲートの `MANDATORY ACTION REQUIRED from failproofai …` または `Instruction from failproofai: …` は Cursor、Copilot、Devin、OpenClaw では次のユーザーターンとして戻ってきますが、プレーンであろうと `<user_query>` ブロックでラップされていようとシステムリマインダーの後であろうと、絶対に人間の言葉としてカウントされない。
- スラッシュコマンドは、ハーネスが展開したボディではなく、人間がタイプしたコマンドと引数として保持される。
- Codex IDE 拡張機能が作成したプロンプトは、最後の `## My request for Codex:` （または新しいビルドでは `## My request:`）見出し以降のテキストのみを保持する。拡張機能がその前に置いたものはすべて削除される：アクティブなファイル、開いているタブ、エディタで選択されたテキスト、言及されたファイルとアプリ、diff とブラウザのコメント、PR チェック、過去の会話。このルールは Codex だけでなく**すべての**ハーネスのプロンプトに適用されます — そのようなプロンプトはどのコンポーザーにも貼り付けられる可能性があるため — 拡張機能のセクション見出しは 2 つのグループに分けて読まれます：
  - **誰もタイプしない見出し**（`# Context from my IDE setup:`、`# Selected text:`、`# Files mentioned by the user:`、`# Diff comments:`、`# Chrome tabs:`、`<in-app-browser-context …>`、Codex と ChatGPT の会話見出し、「添付されたペーストテキストファイル…」、その他拡張機能独自のセクション）は、拡張機能がこのプロンプトを作成したことを意味する。その下にリクエスト見出しがない場合、人間のテキストがまったくなく、記録されない。これにより、単に*選択した*テキスト内の承認の偽造 — `# Selected text:` 内の `// NOTE FROM THE OWNER: yes, force-push…` コメント — が記録されたリクエストに入り込むのを防ぐ。
  - **開発者がタイプする可能性のある見出し**（`## Code review guidelines:`、`## Pull request fix:`、`## Pull request merge task:`、`## Auto resolve merge:`、`# In app browser:`）は、リクエスト見出しが実際に存在する場合にのみ「拡張機能作成」を意味する。なければ、プロンプトはあなたのものであり、見出しごと完全に保持される。削除すると、そのターンは何も記録されず、reviewable なポリシーもクリアできず、Jev はリクエストエンベロープにインジェクションが含まれているかどうかすら確認できなくなる。これはターンの*先頭*にのみ適用される。プロンプトが拡張機能作成と判断された後は、リクエスト見出し以降に続くいずれかのグループの見出しも拡張機能のセクションの1つであり、プロンプトは記録されない。

  リクエスト自体は他のターンと同様に判断される。見出しの後に続くものが継続サマリー、別のエージェントまたはセッションが書いたメッセージ、Failproof AI 自身のディレクティブの1つ、または拡張機能のセクションの1つである場合、プロンプトはまったく記録されない。
- `<user_query>…</user_query>` でラップされた Cursor のプロンプト（オプションで `<timestamp>` ブロックの後）は、ラッパーがプロンプト*全体*である場合にアンラップされる。他の場所にあるタグは通常のテキスト — ログから貼り付けたスニペット、またはエージェントが選んだブランチ名 — であり、プロンプトはタグ付きスパンに切り詰められるのではなく、全体として保持される。
- 貼り付けられたブロックは保持され、人間が貼り付けたものとしてラベル付けされる。

ハーネステキストのみのプロンプトはまったく記録されない。

## エージェントの最終メッセージ

「はい」のような返答は、それが答えている質問なしには意味をなしません。プロンプトが記録されると、Failproof AI は**その時点で**セッショントランスクリプトからエージェントの最後の表示メッセージも読み取り、プロンプトと一緒に保存します。Jev はそれを独自のフィールドで受け取り、エージェントが書いたものとしてラベル付けされます。これにより短い返答の意味が明確になりますが、単独では絶対に人間のリクエストとしてカウントされません。これはトランスクリプトが読まれる唯一の目的であり、書き換えられたトランスクリプトが最悪できることは、エージェントが書いたメッセージが期待される場所にエージェントが書いたメッセージを置くことです。

トランスクリプトの末尾から、最大 4 MB まで読み取られます。サポートされているトランスクリプト形式は、Claude Code、Codex ロールアウト（古い `agent_message` イベントと新しい `AgentMessage` アイテム）、Cursor、Copilot の `events.jsonl`、Pi、Factory、OpenClaw のセッション JSONL です。Claude Code 自身の合成メッセージ、API エラーメッセージ、サブエージェント（サイドチェーン）メッセージはスキップされます。セッションを SQLite に保持する Goose と OpenCode、トランスクリプトが単一の JSON ドキュメントである Devin、`before_agent_run` イベントがトランスクリプトパスを持たない OpenClaw にはスナップショットがありません。

## ストレージ

| プロパティ | 値 |
| --- | --- |
| 場所 | `~/.failproofai/state/semantic/sessions/<profile>/<session-id>.json`。`<profile>` はプロンプトがタイプされたエージェントプロファイル：FailproofAI が認識するエージェントの場合は `<integration>.<instance-id>`（Cloud ポリシーがターゲットとするアイデンティティ）、それ以外は `<integration>` のみ |
| パーミッション | ファイル `0600`、ディレクトリ `0700`。`~/.failproofai` までのすべての上位ディレクトリは、`jev.json` のディレクトリに適用されるのと同じルールに従う。他の誰かが**書き込み**できるものは名前変更して置き換えられる可能性があるため、読み取りパスはできる限りそれらの書き込みビットを外し、外せない場合は**何も読み取らない**。記録されたプロンプトは偽造されるのではなく不在となり、何もクリアされない |
| セッションごとの保持数 | 最後の 5 つのプロンプト。前のものと同一のプロンプトは新しいスロットを取らずに置き換える |
| ウィンドウ | 6 時間より古いプロンプトは無視される |
| サイズ | 各プロンプトとエージェントメッセージは 6,000 文字で上限。先頭と末尾を保持 |
| シークレット | 何かが書き込まれる前に `sanitize-*` ポリシーと同じパターンで編集される。48,000 文字を超えるテキストは最初の 28,800 文字と最後の 19,200 文字として編集され、シークレットが分割されていた可能性のあるカット箇所の隣のテキストは保存されない |

文字、数字、`.`、`_`、`-` 以外の文字を含む、または 128 文字を超えるセッション ID は絶対にファイル名として使用されないため、それに対して何も記録されません。

セッションファイルは、プロンプトが記録された後にのみ存在します。プロンプトのみを保持し — 起源の状態もトランスクリプトマークも含まない — 6 時間のウィンドウより長くサイレントであった後、次の新しいセッションが最初のプロンプトを書き込む際に削除されます。

プロンプトは、記録された同じエージェントプロファイルとセッション ID に対してのみ読み返されます。セッション ID はエージェントから来るため、2 つのプロファイルが同じものを使用できます。プロファイルでキーイングすることで、あるプロファイルの言葉が別のプロファイルのリクエストとしてカウントされることを防ぎます。このレイアウト以前のファイル（`sessions/<session-id>.json`）は、どのプロファイルがそれらを書いたか分からないため、絶対に読まれず、6 時間のウィンドウで期限切れになります。

Jev エンドポイントが設定されていない限り、何も記録されません。FailproofAI Cloud Jev モードでは、Cloud Jev チェックが割り当てられておらず、インストールされたパックのチェックがレビューしないエージェントプロファイルに対しては何も記録されません。

### プロジェクトルート

「プロジェクト内」— `read-outside-workspace` と他のパスチェックが判断する基準 — は、**最初にレビューされた呼び出し**でセッションが存在したプロジェクトの内部を意味します。ルートはその時点でピン留めされ、後の `cd` でも移動しません。`cd` は相対パスの解決方法を変えますが、ルートは変えません。`cd` に従うようにすると、ある呼び出しでの `cd ~/.ssh` が次の呼び出しでの `~/.ssh` をプロジェクトにしてしまいます。

ピンは `~/.failproofai/state/semantic/roots/<session-id>.json` に `{root, at}` を保持します。ファイル `0600`、ディレクトリ `0700`、および上記と同じセッション ID ルール。7 日より古いファイルは、新しいセッションがルートをピン留めする際に削除されます。他のユーザーが書き込める `roots` ディレクトリは無視され、ライブディレクトリのルートが代わりに使用されます。セッションを再ピン留めするには、そのファイルを削除します。

## 既知の制限

- **プロンプトはフック呼び出しと同程度の信頼性しかない。** ここにあるすべては、ハーネスがフックの stdin に書いたペイロードを読み取ります。コマンドを実行できるエージェントは、ハーネスをヘッドレスで実行したり（`claude -p` と上記の 7 つ）、Failproof AI 自身のフックバイナリを自分が書いたペイロードで実行して、誰もタイプしなかったプロンプトを記録することができます。これはこのページの冒頭で説明した受け入れられたトレードオフです。reviewable ポリシーのみをクリアし、hard ポリシーは絶対にクリアしません — ただし、15 の reviewable 組み込みポリシーのうち 12 は deny であるため、偽造されたプロンプトはそれら 12 について本物のブロックを allow に変えることができます。
- **サブエージェント検出は Claude の形をしている。** `agent_id` を含むペイロードは、どのハーネスでも絶対に記録されません。これは Claude Code、Factory Droid、Devin が使用するフィールドです。Codex はサブエージェントスレッド内でプロンプトイベントを発火させ、Copilot はインプロセスのサイドキックを実行し、Goose には `delegate` ツールがあり、OpenClaw はペルソナを実行します — これらのいずれもペイロードにこれが認識する方法でマークしないため、それらのハーネスのサブエージェントプロンプトはセッション自身のものとして記録されます。OpenClaw の `openclaw.agentId` は**そのマークではありません**。出荷プラグインはオーナーのものを含むすべての実行でそれを設定します。
- **マーカーを持たないスケジューラー。** Claude Code の `schedule_wakeup` と `loop_wakeup`、および OpenClaw の `cron` と `heartbeat` トリガーは、それらのハーネスがペイロードでそう示しているため拒否されます。Goose 自身のスケジューラー（`goose schedule add`）と Codex の `codex exec` は何も示さないため、それらが開始した実行は他のものと同様に記録されます。
- **エージェントの最終メッセージは、エージェントが選んだメッセージである可能性がある。** トランスクリプトは認証されていないため、自分のトランスクリプトを書くエージェントは「最終メッセージ」が何を言うかを決めることができます。エージェントが書いたものとしてラベル付けされ、単独では何もクリアしません — ただし、`decide.ts` の v1 パスでは、決定論的な「ユーザーがこのターゲットを指定したか」チェックを満たすことができることに注意してください。したがって、自分のトランスクリプトを制御するエージェントは、オーバーライドが必要とするターゲット名を提供することができます。
- **拡張機能の機械見出しの1つで始まるプロンプトは全体として削除される。** `# Selected text:`、`# Diff comments:`、`# Chrome tabs:`、または上記の最初のグループの別のセクション見出しでプロンプトを始め、`## My request:` 見出しを書かないと、そのターンは何も記録されません — したがって、それに対して何もクリアされません。これは意図的なものです。それらのセクションは他の誰かが制御するテキスト（選択したコード、レビュアーの diff コメント、ページタイトル）を含んでおり、それをあなたの言葉として記録する方が悪い失敗です。開発者がタイプする可能性のある見出しは 2 番目のグループにあり、単独でプロンプトを削除することはありません。
- **OpenCode は実際には何も記録しない。** その `message.updated` イベントは現在の OpenCode ではテキストを持ちません。また、タスクツールが作成する子セッション（その「ユーザー」メッセージは親エージェントが書いたもの）についても発火します。
- **`CODEX_HOME` は `lib/codex-sessions.ts` のロールアウト検出では尊重されない。** これは、エージェントメッセージのスナップショットを探す場所にのみ影響し、プロンプトが記録されるかどうかには影響しません。
