これは、独自キーを使用した[Jevポリシー](/ja/policies/jev)のプロバイダーおよび設定リファレンスです。正規表現ポリシーは文字列をマッチングします。`rm -rf build/`（自分が要求したもの）と`rm -rf ~`（プランに紛れ込んだもの）の違いを判別できないため、ある場所では過剰にブロックし、別の場所では不十分になります。**Jev**（TypeSafeのクラシファイアー）は、実際に何を要求したかと照らし合わせてツール呼び出しを読み取り、一つの高速なリクエストでyes/noの質問群に答えます。

独自のJevエンドポイントとキーを設定すると、Failproof AIは正規表現ポリシーの**代わりではなく、並行して**各ツール呼び出しについてJevに問い合わせます。

- **hard**ポリシーのdenyは確定です。Jevはそれを解除できません。reviewableとして明示的にマークされ、対象のJevチェックが指定されていない限り、すべてのポリシーはhardです。したがって、何も記載していないカスタム、パック、またはCloudポリシーはhardとなり、常時オンの自己保護ガードも常にhardです。
- **reviewable**ポリシーのdenyは解除される場合がありますが、そのポリシーがカバーしている具体的な懸念事項についてJevに問い合わせ、「問題なし」または「ユーザーがこれを要求した」と回答した場合のみです。ユーザーが呼び出しを要求していない状況で、懸念事項が実在すると判断したチェックはdenyを維持します。そのチェック自体の判定が警告に過ぎない場合でも同様です（ツール呼び出し前の警告はエージェントを停止しないため）。また、そのチェックがdenyできるもの（シークレット漏洩、認証情報の窃取、破壊的な削除など）である場合、その呼び出しに対して何も解除されません。
- ブロックは、その呼び出しが要求したタスクのステップであり、それ以上の範囲に達しない場合、**警告**に変わることがあります。JevはそのdenyをEおよび警告に軟化させ、その警告（呼び出しの実際の問題点を明示したもの）がポリシーのブロックを置き換えます。
- Jevは、正規表現が表現できない危害に対して独自に警告またはdenyを出すこともできます。
- Jevが回答できない場合（タイムアウト、レート制限、サーバーエラー、クレジット不足、予期しないモデルバージョン）、その呼び出しはJevなしの場合と同様に正規表現の結果を受け取ります。
- Jevは、呼び出し全体を読み取り、かつ具体的な懸念事項について問い合わせられた場合を除き、ポリシー単独よりも呼び出しを許可しやすくすることはありません。それ未満のもの（全体を送信するには大きすぎる呼び出し、インジェクションの疑い）は解除を取り消し、すべてのdenyを維持します。

<Note>
Jevの設定がなければ何も変わりません。フックは従来通り正規表現ポリシーを実行します。設定が唯一のオプトイン手段です。
</Note>

<Tip>
FailproofAI Cloudをご利用ですか？独自のキーは不要です。`jev:evaluate`を持つキーで接続されたマシンは、組織のプランでJevを使用できます。[FailproofAI Cloud経由のJev](/ja/reference/jev-cloud)をご覧ください。
</Tip>

## 始める前に

**failproofai 1.0.8-beta.0以降**をインストールし、エージェントが動作するマシンの[サポートされているハーネス](/ja/reference/harnesses)にフックをアタッチしてください。新しいマシンの場合は[クイックスタート](/ja/start/quickstart)を、Cloudを使用しない場合は[ローカルエンフォースメントの設定](/ja/start/setup#enforce-locally)に従ってください。インストール済みのCLIを`failproofai --version`で確認してください。

下記のプロバイダーからAPIキーを取得するか、互換エンドポイントとそのキーを用意してください。Jevは`PreToolUse`または`PermissionRequest`ゲートで名前付きツール呼び出しをレビューします。独自の判定を出すことができますが、既存のポリシーdenyを解除するには、[reviewable](/ja/policies/authority)とマークされたポリシーのインストールも必要です。Hardポリシーのdenyは確定のままです。

## プロバイダーの選択

Jevには5つのルートからアクセスできます。いずれか一つのキーを用意してください。

| プロバイダー | `--provider` | エンドポイント | デフォルトモデル | 備考 |
| --- | --- | --- | --- | --- |
| TypeSafe | `typesafe` | `api.typesafe.ai/v1/systemone` | `jev-1.13.0` | バージョンを固定。 |
| OpenRouter | `openrouter` | `openrouter.ai/api/v1/systemone` | `typesafe/jev-1.13` | リクエストはゼロデータリテンションエンドポイントにのみルーティングされ、他のプロバイダーへのフォールバックはありません。`typesafe/jev-1.13-20260917`のような日付付きバージョンを報告します。 |
| Vercel AI Gateway | `vercel` | `ai-gateway.vercel.sh/typesafe/v1/systemone` | `typesafe-ai/jev` | Jevをエイリアスでのみ識別するため、回答したバージョンは未検証として記録されます。 |
| Cloudflare Workers AI | `cloudflare` | `api.cloudflare.com/client/v4/accounts/<id>/ai/run` | `typesafe/jev` | `--account-id`が必要です。キーあたり毎秒約6リクエストがHTTP 429の前に計測されました。 |
| 独自エンドポイント | `custom` | `<base-url>/systemone` | `jev-1.13.0` | TypeSafeのリクエストボディを受け付け、回答したモデルを報告するエンドポイントであれば何でも可。`https`のみ。ローカルテスト用にループバックホスト（localhost、`127.0.0.1`、`::1`）への平文`http`も受け付けます。 |

<Warning>
Vercel独自のBring-Your-Own-Key機能では、リクエストが失敗するとVercelの認証情報でサイレントリトライされます。すべての呼び出しを自分のTypeSafeアカウントのみに課金・記録する必要がある場合は、TypeSafeを直接使用してください。
</Warning>

## セットアップ

コマンド一つで、エンドポイントとキーを設定します。既存のポリシーが引き続き呼び出しを決定しながら、Jevの判定を確認できるよう、まず`observe`モードで開始します。

```bash
failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
```

### URLがプロバイダーを決定する

プロバイダーを明示的に指定する必要はありません。URLの**ホスト**がプロバイダーを示します。

| URLホスト | プロバイダー | 追加要件 |
| --- | --- | --- |
| `api.typesafe.ai` | `typesafe` | — |
| `openrouter.ai` | `openrouter` | — |
| `ai-gateway.vercel.sh` | `vercel` | — |
| `api.cloudflare.com` | `cloudflare` | `--account-id <32-hex-account-id>` |
| その他のホスト | `custom` | — 指定したURLがベースURLになります |

これには3つの結論があります。

- **プロバイダー自身のAPIのURLはオーバーライドを書きません。** `--url https://api.typesafe.ai/v1`は、`--provider typesafe`とまったく同じ設定を生成します。既知のプロバイダーで異なるパスまたはホストを指定すると、`--base-url`が保存するのと同様にベースURLとして保存されます。
- **`--provider`は推論を上書きします。** これにより、自社ホストからプロバイダーのAPIをしゃべるプロキシに到達できます（例：`--url https://jev-proxy.internal/v1 --provider typesafe`）。
- **ホストと矛盾する`--provider`は拒否されます**（推測されません）。`--provider openrouter --url https://api.typesafe.ai/v1`は何も書かず理由を説明します。二つの指定がキーの送信先について異なることを示しているためです。同じペアは`jev setup --base-url`およびダッシュボードのJev設定からも拒否されます。（`--provider custom`は矛盾ではありません。「このURLをそのまま扱う」という意味です。ただし、カスタムルートではアカウントごとのエンドポイントに到達できないCloudflareのホストは例外です。）

`--url`は設定ファイルの`baseUrl`とまったく同じバリデーションが行われ、同じメッセージで拒否されます。`https`、またはいずれのモードでもループバックホスト（localhost、`127.0.0.1`、`::1`）への平文`http`。リスク：ループバックサーバーを認証するものは何もないため、ダウン中に別のローカルプロセスがそのポートを取得して応答する可能性があります。ローカルテスト以外では`https`を使用してください。

### キー

`--key-stdin`でパイプするか、ターミナルでコマンドをそれなしに実行してマスクされたプロンプトにキーを貼り付けます。どちらの方法でも設定ファイルに直接保存され、表示されることはありません。

<Tabs>
  <Tab title="TypeSafe">
    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    ```
  </Tab>
  <Tab title="OpenRouter">
    ```bash
    failproofai jev --url https://openrouter.ai/api/v1 --mode observe --key-stdin < ~/openrouter.key
    ```
  </Tab>
  <Tab title="Vercel">
    ```bash
    failproofai jev --url https://ai-gateway.vercel.sh/typesafe/v1 --mode observe \
      --key-stdin < ~/vercel-gateway.key
    ```
  </Tab>
  <Tab title="Cloudflare">
    ```bash
    failproofai jev --url https://api.cloudflare.com/client/v4 \
      --account-id <32-hex-account-id> --mode observe --key-stdin < ~/cloudflare.token
    ```
  </Tab>
  <Tab title="Custom">
    ```bash
    failproofai jev --url https://jev.internal.example.com/v1 --mode observe --key-stdin < ~/jev.key
    ```
  </Tab>
</Tabs>

`failproofai jev setup`は同じフラグを受け付け、すべての長い形式です。URLではなくプロバイダーを指定したい場合は`setup --provider <kind>`を使用します。

### `--token`とコスト

`--token <token>`はキーをコマンドラインに置きます。マシンを設定する最速の方法ですが、設定ファイル以外にキーが残る唯一の方法でもあります。

```bash
failproofai jev --url https://openrouter.ai/api/v1 --token <token>
```

<Warning>
コマンドライン引数はシェルの履歴ファイルに残り、コマンド実行中はプロセスリストに表示されます。自分と同じユーザーで実行しているものは`/proc`から読み取れます。`--token`を使用するたびに`setup`がその旨を表示します。共有マシン、録画セッション、または履歴ファイルが同期される場所では`--key-stdin`を推奨します。この方法で渡したキーは、重要であればローテーションしてください。
</Warning>

`--token`、`--key-stdin`、`--key-from-env`は相互排他的です。一つだけ指定してください。

次に、キー、エンドポイント、回答したJevを確認するために小さなライブリクエストを送信します。

```bash
failproofai jev test
```

```text
  failproofai jev test                                            ok · 523 ms

  provider      cloudflare
  model asked   typesafe/jev
  answered by   jev-1.13.0 (Jev 1.13 family — verified)
  latency       523 ms — within the 3000 ms timeout
```

回答がタイムアウト後に届いた場合（すべてのフックが`timeout`として正規表現にフォールバックする）、またはチェック質問への回答が誤っている場合、`jev test`はタイトルにその旨を示して終了コード1で終了します。

フックはツール呼び出しのたびに設定を読み取るため、次の呼び出しから適用されます。デーモンの有無にかかわらず、再起動は不要です。

## 動作の確認

```bash
failproofai jev status
failproofai jev status --json
```

`status`はプロバイダー、エンドポイント、モデル、モード、設定ファイルとそのパーミッションを表示し、キーは表示しません。その下には最近のアクティビティのサマリーが表示されます。Jevが評価した呼び出し数、正規表現にフォールバックした回数とその理由、レイテンシー、解除されたreviewableポリシーなどです。

## 実際の呼び出しの確認

フックされたエージェントで新しいセッションを開始します。ファイル読み取りツールを使って`README.md`のタイトルを報告するよう依頼してください。セッションにそのツール呼び出しが含まれていることを確認し、`failproofai jev status`を再度実行します。最近の評価済み呼び出し数が増加しているはずです。[ローカルダッシュボード](/ja/reference/local-dashboard#review-policy-activity)の**Policies → Activity**を開いて、呼び出しのJev判定とモードを確認してください。observeモードでは、ポリシーの結果が引き続き呼び出しを決定します。reviewableポリシーがマッチし、Jevがすべての名前付きチェックを解除した場合のみ解除が表示されます。通常の読み取りでは解除すべきポリシーがない場合があります。

## Observeモード

デフォルトは`enforce`です。Jevに決定を変更させずに監視するには、`observe`に切り替えます。Jevは引き続き問い合わせられ、判定は記録されますが、適用されるのは正規表現の結果です。

```bash
failproofai jev setup --mode observe
failproofai jev setup --mode enforce
failproofai jev setup --mode off
```

`off`は設定（エンドポイントとキー）を維持したままJevへの問い合わせを停止します。フックは設定なしと同様に正規表現ポリシーを実行し、`failproofai jev status`は「off (switched off)」と表示します。`--mode observe`または`--mode enforce`で再開できます。

同じプロバイダーで`setup`を再実行すると保存済みキーが維持されるため、モード切り替えはフラグ一つで完了します。プロバイダーを切り替えると最初からやり直しとなり、そのプロバイダーのキーを求められます。リクエストを別のホストに移す`--base-url`も同様です。保存済みキーは、指定されたホストまたはそのプロバイダーの独自APIにのみ送信されます。

## 設定ファイル

すべては`~/.failproofai/jev.json`という一つのファイルに保存され、`setup`によって書き込まれます。

```json
{
  "provider": "cloudflare",
  "apiKey": "<your key>",
  "accountId": "<32-hex-account-id>",
  "mode": "enforce",
  "timeoutMs": 3000
}
```

| フィールド | 意味 |
| --- | --- |
| `provider` | `typesafe`、`openrouter`、`vercel`、`cloudflare`、`custom`のいずれか、またはFailproofAI Cloud接続からキーを取得する`failproofai`（このファイルではなく）。[FailproofAI Cloud経由のJev](/ja/reference/jev-cloud)を参照。 |
| `apiKey` | `Authorization: Bearer <key>`として送信されます。 |
| `baseUrl` | `custom`では必須。それ以外ではプロバイダーのAPIベースを置き換えます。`https`必須。`localhost`への平文`http`は`mode: observe`でのみ受け付けられます。ローカルポートを認証するものは何もないため、プロキシがダウン中はマシン上の任意のプロセス（判定対象のエージェントを含む）が代わりに応答する可能性があります。 |
| `accountId` | Cloudflareのみ：32文字の小文字16進数。 |
| `model` | プロバイダーのデフォルトモデルIDを置き換えます。バージョン付きIDはJev 1.13を指定する必要があります。APIキーのような形式の値は拒否されます（折り返し表示もされません）。そのため、`--model`に貼り付けたキーは保存・送信されません。 |
| `timeoutMs` | ツール呼び出しが正規表現結果を使用する前にJevを待つ時間。100〜10000、デフォルトは3000。 |
| `mode` | `enforce`（デフォルト）、`observe`、または`off`（設定を維持し、Jevを実行しない）。 |

3つのルールが保護します。

- **オーナーのみ。** パーミッション`0600`で書き込まれます。他のユーザーまたはグループが読み書きできるコピーは**拒否**され、`chmod 600 ~/.failproofai/jev.json`または`setup`を再実行するまでフックは正規表現にフォールバックします。ディレクトリも確認されます。`~/.failproofai`は他の誰にも**書き込み可能**であってはなりません。そこに書き込めれば、ファイル自体のパーミッションに関わらずファイルを置き換えられるためです。`setup`はそれを発見した場合、書き込みビットを削除します。`failproofai jev status`は設定が拒否された場合にその旨を表示し、ファイルが指定するエンドポイントを示します。他の誰かが変更した可能性があるため、`chmod`の前に自分のファイルであることを確認してください。そのようなファイルで`setup`を再実行すると、保存済みキーはプロバイダーの独自APIにのみ送られます。他のエンドポイントが指定されている場合はキーの再入力（`--key-stdin`）、またはリクエストをプロバイダーに戻すための`--base-url default`が必要です。
- **グローバルのみ。** リポジトリはJevをオンにしたり、別のエンドポイントに向けたり、モデルを選択したりできません。プロジェクト内の`.failproofai/jev.json`は無視され、プロバイダー、URL、モデル、アカウントIDはそのファイルからのみ読み取られます。リポジトリのエージェント設定が設定できる環境変数からは読み取りません。（`FAILPROOFAI_HOME`はこの回避策にはなりません。Jevだけをリダイレクトするのではなく、ポリシーを含むfailproofaiディレクトリ全体を移動します。）
- **キーのみ環境変数から取得可能。** ファイルに`apiKey`がない場合、`FAILPROOFAI_JEV_API_KEY`がそのセッションに提供します（`setup --key-from-env`はそのようなファイルを書き込みます）。ファイルが保持するキーを置き換えることはなく、ファイルなしでJevをオンにすることもできません。変数が設定されていない場合、Jevはそのシェルで単純にオフになります。`failproofai jev status`はその旨を表示し、終了コード0で終了し、設定はそのままです（`status --json`は`"reason": "no-env-key"`付きの`"status": "key-missing"`を報告します）。`failproofaid`デーモンはシェルの環境を参照しないため、`failproofai config`でセットアップされたマシンでは、ファイルにキーを保持してください。

## 回答するJev

Failproof AIの決定しきい値はJev 1.13で調整されているため、そのファミリーからの回答のみが使用されます。`jev-1.13.x`、またはOpenRouterの`typesafe/jev-1.13-<date>`。プロバイダーがJevをエイリアスでのみ識別し、バージョンを報告しない場合（VercalとバージョンをいわないCloudflare）、回答は使用され未検証として記録されます。`custom`エンドポイントは回答したモデルを報告する必要があります。唯一の例外は、設定したバージョン未指定の`--model`名で、エコーバックされた場合は同様に未検証として記録されます。他のバージョンを報告する回答、またはバージョンを報告しない`custom`の回答は使用されません。その呼び出しは`model-mismatch`という理由で正規表現にフォールバックします。

## Jevが回答できない場合

以下のそれぞれは、その呼び出しに対して正規表現の結果にフォールバックし、その理由が記録されます。`failproofai jev status`がそれを集計します。

| 理由 | 原因 |
| --- | --- |
| `timeout` | `timeoutMs`以内に回答なし。 |
| `http-429` | プロバイダーがキーをレート制限した。 |
| `rate-limited` | Failproof AI独自のリミッターが、送信前に呼び出しを保留にした。秒間5リクエスト、バースト最大5、プロバイダーが`429`を返した後は一時的に停止。プロバイダー側ではありません。 |
| `http-500`、`http-502`、`http-503`、… | プロバイダーでのサーバーエラー。正確なステータスが記録されます。 |
| `out-of-credits` | HTTP 402：プロバイダーアカウントのクレジットが残っていない。 |
| `provider-refused` | "Model execution failed (Payment error)"というメッセージのCloudflareからのHTTP 402：プロバイダーがこのリクエストでモデルを実行することを拒否した。通常は請求の問題ではないため、クレジットを追加しても解決しません。 |
| `http-401`、`http-403` | キーが拒否された。 |
| `http-404` | `<base>/systemone`に何も提供されていない。ベースURLが誤っています。`/systemone`がベースURLに付加され、すべてのプロバイダーはそのバージョンルートで提供しています。`failproofai jev models`でエンドポイントが提供するものを確認できます。 |
| `network` | エンドポイントに到達できなかった。 |
| `http-301`、`http-302`、`http-307`、`http-308` | エンドポイントがリダイレクトで応答した。リダイレクトは絶対にフォローされません。回答は常に設定のURLからのみ受け付けます。最終URLに`--base-url`を設定してください。 |
| `malformed` | エンドポイントは応答したが、Jevの回答形式ではなかった（JSONでないボディ、または回答が含まれていないボディ）。 |
| `cloudflare-error`、`cloudflare-incomplete` | Cloudflareのエンベロープが失敗を報告した、または完了していないジョブ。 |
| `model-mismatch` | Jev 1.13以外のバージョンが回答した、または`custom`エンドポイントが回答したモデルを報告しなかった。 |
| `request-cut` | **障害ではありません。** Jevは回答しましたが、呼び出しの一部のみが表示されたため、その回答では何も解除されませんでした。[Jevが回答したが呼び出し全体ではなかった場合](#when-jev-answered-but-not-on-the-whole-call)を参照してください。 |

`failproofai jev status`は、`upstream-error`（回答にプロバイダー独自のエラーが含まれていた）や`config`などのまれな理由も表示することがあり、名前を付けられない理由は`other`として集計されます。

`request-cut`がこの表に含まれているのは、`failproofai jev status`が他と一緒に集計し、またすべてのdenyをそのまま維持するためです。ここで唯一、プロバイダーに関して何も示さない理由です。リクエストは届き、Jevは回答しました。上記のすべての行とは異なり、その回答はまだカウントされます。JevのdenyまたはWarningは、正規表現の結果の上に適用され、破棄されません。したがって、連続して発生している場合は、呼び出しが全体を送信するには大きすぎる状態でエバリュエーターに到達していることを意味し、エンドポイントが不調なわけではありません。クレジットを追加したりURLを変更しても数は減りません。

## Jevが回答したが呼び出し全体ではなかった場合

さらに2つのことが起こりえます。どちらもJevが回答に失敗したわけではありません。どちらも、呼び出しまたは会話のどれだけが一つのリクエストに収まったかに関するものです。

**呼び出し自体の一部が収まらなかった。** ツール呼び出しは固定バジェット内で送信され、特大のもの（非常に大きな`Write`、巨大なMCPボディ、上限まで埋め尽くされたコマンド）は収まった部分だけで送信されます。Jevは引き続き回答し、その回答はカウントされます。JevのdenyまたはWarningは通常通り適用されます。ただし、呼び出しの一部に対する判定はその呼び出し全体に対する判定ではないため、**解除**することはできません。したがって、すべてのポリシーdenyが維持され、呼び出しは`request-cut`という理由でフォールバックとして記録され、`failproofai jev status`が上記の理由と並んで集計します。これが示すルール：呼び出しを大きくすると解除が失われる可能性があり、解除を得ることはできません。

**メッセージが収まらなかった。** 貼り付けた長いプロンプト、エージェントの最後のメッセージ、またはこのエバリュエーター独自のストアがすでに上限に達していたプロンプト。**何も変わりません**。呼び出しは他と同様に判定・解除・記録され、フォールバックとしてカウントされません。入力した内容の長さが判定を決することはなく、切り捨てによって同意が生まれることはありません。プロンプトがすでに上限に達した状態で届いた場合、「これを要求しなかった」という結論は全く導き出せなくなります。

この二つの境界線は、誰がそのテキストを書いたかです。呼び出しはエージェントのものであり、その長さによって重大度を減らすルールはエージェントが利用できるルールになります。プロンプトはあなたのものであり、その長さをシグナルとして扱うことは、仕様やスタックトレースを貼り付けることへのペナルティにしかなりません。

## マシンから送信されるもの

Jevが評価する各ツール呼び出しについて、プロバイダーに一つのリクエストが送信され、以下を含みます。

- ツール呼び出し自体（APIキー、ベアラートークン、`KEY=`の代入などのシークレットは編集済み）
- 最近入力したプロンプト（エージェントのハーネスが追加したテキストは除去済み）
- 最新プロンプト前のエージェントの最後のメッセージ（エージェント作成としてラベル付き）
- パスがプロジェクト内にあるかどうかなど、ローカルで計算された情報（最初のレビュー済み呼び出し時のセッションのプロジェクトルート、[セッションに固定](/ja/reference/jev-intent#the-project-root)）、および現在のgitブランチ

送信先は設定のエンドポイントのみで、あなたのキーを使用します。

## オフにする

```bash
failproofai jev remove
```

これにより`~/.failproofai/jev.json`が削除されます。次のツール呼び出しから、フックは以前と同様に正規表現ポリシーを実行します。`~/.failproofai/state/semantic/`以下のセッションごとのストア（`sessions/`の記録済みプロンプト、`roots/`のプロジェクトルート）はそのまま残り、自動的に期限切れになります。Jevへの問い合わせを停止しながら設定を保持するには、代わりに`failproofai jev setup --mode off`を使用してください。

## コマンドリファレンス

| コマンド | 結果 |
| --- | --- |
| `failproofai jev --url <url> --key-stdin` | 一つのコマンドで設定。プロバイダーはURLのホストから決定 |
| `failproofai jev --url <url> --token <token>` | 同様、キーをコマンドラインに指定。履歴とプロセスリストに残ります |
| `failproofai jev setup --provider <kind> --key-stdin` | stdinにパイプされたキーで設定を書き込む |
| `failproofai jev setup --provider <kind>` | 同様、マスクされたプロンプトでキーを入力 |
| `failproofai jev setup --key-from-env` | キーを保存せず、セッションごとに`FAILPROOFAI_JEV_API_KEY`を読み取る |
| `failproofai jev setup --mode observe` | 保存済みキーを維持してモード（`enforce`、`observe`、`off`）を切り替える |
| `failproofai jev setup --model <id>` / `--base-url <url>` | モデルまたはAPIベースをオーバーライド。`default`でオーバーライドを削除 |
| `failproofai jev setup --timeout-ms <n>` | 呼び出しごとのバジェットを変更 |
| `failproofai jev status [--json]` | 設定、パーミッション、最近のアクティビティを表示。キーは表示されません |
| `failproofai jev test [--json]` | 一つのライブリクエスト：レイテンシーと回答したバージョン |
| `failproofai jev models [--provider <kind>] [--url <base>] [--json]` | エンドポイントの`/models`が報告するモデルID。設定済みのものをマーク |
| `failproofai jev remove` | 設定を削除。Jevはオフ |
