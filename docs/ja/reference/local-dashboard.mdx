`failproofai` を引数なしで実行すると、`http://localhost:8020` でバンドルされたダッシュボードが起動します。ローカルのエージェント履歴、ポリシー設定、監査結果、フックアクティビティをマシンから直接読み込みます。

セットアップが完了していないマシンでは、コマンドを実行すると初回セットアップが行われてからダッシュボードが開きます。これは対話型ターミナルでのみ動作します。パイプ経由またはCI環境では、誰も応答できないウィザードがコマンドをブロックしてはならないため、1行のヒントを表示してダッシュボードを開きます。`FAILPROOFAI_NO_FIRST_RUN=1` を設定すると、リダイレクトをスキップして直接ダッシュボードに進みます。

ローカルダッシュボードはFailproof AI Cloudとは独立しています。Cloudアカウントなしで動作し、イベントが組織に配信されたことを保証するものではありません。セットアップ済みのマシンでは、表示される判定は唯一の評価者である `failproofaid` デーモンによって行われたものです。セットアップが完了していないマシンでは、フックはインプロセスで評価されます。

## ダッシュボードのエリア

| エリア | できること |
| --- | --- |
| Policies → Activity | ローカルの allow、instruct、deny の判定を確認し、判定・イベント・CLI・ソース・ポリシー・セッションでフィルタリングする。 |
| Policies → Configure | インストール済みパックからポリシーを有効化し、サポートされているパラメータを編集し、検出されたカスタムポリシーや慣例ポリシーをトグルし、対象ハーネスを選択する。 |
| Projects | サポートされているエージェント履歴全体で検出されたプロジェクトを閲覧し、最新セッションを比較する。 |
| Project sessions | ローカルのトランスクリプトを1件開き、生の順序付きエントリとサブエージェントを確認し、ダウンロードして、ポリシーアクティビティと関連付ける。 |
| Audit | 直近のオフラインスキャン、リスクのあるパターン、強み、影響を受けるプロジェクト、推奨される組み込みポリシーを確認する。 |
| Settings | デーモン/プラットフォームがサポートしている場合、スケジュールされたローカルスキャンとメールによる監査レポートを設定する。 |

## ポリシーアクティビティの確認

<Tabs>
  <Tab title="ダッシュボード">
    1. **Policies → Activity** を開き、判定とソースのフィルターを設定します。
    2. イベント、ハーネス、ポリシー名、またはセッションで絞り込みます。
    3. 行には判定、イベント、ハーネス、ツール、ポリシー、パーミッションモード、および処理時間が表示されます。行を展開すると、詳細な理由、マッチしたすべてのポリシー、決定ソース、クラウドデプロイメント、セッションの作業ディレクトリとトランスクリプトパスが確認できます。ツール名は行に表示されますが、フィルター対象ではありません。
    4. セッションリンクをたどると、トランスクリプトのコンテキストの中で判定を確認できます。

    deny に見える行でも、ブロッキング判定を消費しないハーネス/イベントの組み合わせでは観察的なものにとどまる場合があります。詳細ビューでは、検証済みの強制実行機能が明示されます。
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    ローカルアクティビティは `~/.failproofai/hook-activity` に保存されます。これらのファイルを直接編集せず、ダッシュボードを使用してください。
  </Tab>
</Tabs>

## ポリシーのローカル設定

<Tabs>
  <Tab title="ダッシュボード">
    1. **Policies → Configure** を開き、ハーネスと設定スコープを選択します。このタブは `http://localhost:8020/policies?tab=policies` から直接アクセスできます。
    2. インストール済みパックのポリシー、または検出されたカスタムポリシーや慣例ポリシーを有効化します。
    3. パラメータ付きポリシーの場合は、設定コントロールを開いてサポートされている値を保存します。
    4. Activity に戻り、マッチするアクションとマッチしないアクションを実行します。

    パックがインストールされるまでリストは空です。このビルド自体にはポリシーが含まれていないため、まず `failproofai policies add FailproofAI/policies` を実行してください。慣例ポリシーにはプロジェクトまたはユーザーのソースが表示されます。カスタムパスを明示的に変更した場合は、選択したパスが記録されるようCLI設定を再実行する必要がある場合があります。
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies show FailproofAI/policies
    failproofai policies add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```

    `policies show <owner>/<repo>` はインストール前にパックの内容を確認します。`--scope` には `user`、`project`、`local` が指定できます。`local` をサポートするのは Claude Code のみで、HermesとOpenClawは `user` のみに対応しています。
  </Tab>
</Tabs>

## プロジェクトとセッションの閲覧

Projects ページは、サポートされているローカル履歴ストアを統合して表示します。プロジェクトを選択するとセッション一覧が表示され、セッションを開くと生ログビューア、サブエージェントセグメント、ダウンロード機能、セッションスコープのポリシーアクティビティが確認できます。

プロジェクトまたはセッションが見つからない場合は、ハーネスがデフォルトの履歴保存場所を使用しているか確認するか、`failproofai harness add-path <harness> [<label>=]<path>` で追加のルートを登録してください。

## オフライン監査のスケジュール設定

<Tabs>
  <Tab title="ダッシュボード">
    **Settings** を開き、スケジュールスキャンを有効化して、サポートされているインターバルを選択し、利用可能な場合はレポート配信を設定します。このページには次回の実行時刻、直近の実行時刻、終了コード、プラットフォームでバックグラウンドデーモンがサポートされているかどうかが表示されます。
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    日数を変更することで、1〜90日の範囲で異なるインターバルを設定できます。`failproofai audit --no-schedule` で定期スキャンを無効化すると、タイマーが停止しサインイン状態は維持されます。即時の対話型スキャンを実行するには `failproofai audit` を実行してください。

    スケジュール設定では、結果がメール送信されるため初回にサインインが必要です。`--email <address>` を指定するとアドレスを事前に設定でき、サインインのプロンプトをスキップできます。
  </Tab>
</Tabs>

<Note>
  分析結果と発見事項はこのマシン上にのみ保存されます。`FAILPROOFAI_TELEMETRY_DISABLED=1` を設定しない限り、匿名のCLIテレメトリがデフォルトで送信されます。スケジュールスキャンはマシンのメタデータも送信し、オプトイン後には限定的な発見事項のダイジェストが送信される場合があります。
</Note>

<Warning>
  ローカルダッシュボードはローカルのエージェント履歴から、プロンプト、ツール入力、ファイルコンテンツ、ターミナル出力を表示することがあります。信頼できるインターフェースにのみバインドし、確認が完了したらプロセスを停止してください。
</Warning>
