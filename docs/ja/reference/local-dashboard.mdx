引数なしで `failproofai` を実行すると、バンドルされたダッシュボードが `http://localhost:8020` で起動します。ローカルマシンからエージェント履歴、ポリシー設定、監査結果、フックアクティビティを直接読み込みます。

ローカルダッシュボードは Failproof AI Cloud とは独立しています。Cloud アカウントがなくても動作しますが、イベントが組織に届いたことを証明するものではありません。

## ダッシュボードのエリア

| エリア | できること |
| --- | --- |
| Policies → Activity | ローカルの allow、instruct、deny の決定を検査し、決定、イベント、CLI、ツール、ソース、ポリシー、セッションでフィルタリングする。 |
| Policies → Configure | ビルトインを有効化し、サポートされるパラメーターを編集し、検出されたカスタムポリシーを切り替え、対象ハーネスを選択する。 |
| Projects | サポートされているエージェント履歴全体で検出されたプロジェクトを閲覧し、最新セッションを比較する。 |
| Project sessions | ローカルのトランスクリプトを開き、未加工の順序付きエントリとサブエージェントを確認し、ダウンロードし、ポリシーアクティビティと関連付ける。 |
| Audit | 最後のオフラインスキャン、リスクのあるパターン、強み、影響を受けるプロジェクト、推奨されるビルトインポリシーを確認する。 |
| Settings | デーモン/プラットフォームがサポートしている場合に、スケジュールされたローカルスキャンとメール送信の監査レポートを設定する。 |

## ポリシーアクティビティを確認する

<Tabs>
  <Tab title="ダッシュボード">
    1. **Policies → Activity** を開き、決定とソースのフィルターを設定します。
    2. イベント、ハーネス、ツール、またはポリシー名で絞り込みます。
    3. 行を展開して、理由、マッチしたポリシー、ソース、実行モード、処理時間を確認します。
    4. セッションリンクをたどって、トランスクリプトのコンテキスト内で決定の位置を確認します。

    deny に見える行でも、ブロッキング判定を消費しないハーネス/イベントペアでは観察的なものにとどまることがあります。詳細ビューでは、強制実行の確認済み対応状況が明示されます。
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    ローカルアクティビティは `~/.failproofai/hook-activity` 以下に保存されます。これらのファイルを直接編集せず、ダッシュボードを使用してください。
  </Tab>
</Tabs>

## ポリシーをローカルで設定する

<Tabs>
  <Tab title="ダッシュボード">
    1. **Policies → Configure** を開き、ハーネスと設定スコープを選択します。
    2. ビルトインまたは検出済みのカスタムポリシーを有効にします。
    3. パラメーター付きのビルトインの場合は、その設定コントロールを開いてサポートされる値を保存します。
    4. Activity に戻り、マッチするアクションとマッチしないアクションを実行します。

    Convention ポリシーにはプロジェクトまたはユーザーのソースが表示されます。カスタムパスを明示的に変更した場合は、選択したパスが記録されるよう CLI 設定を再実行する必要があることがあります。
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```
  </Tab>
</Tabs>

## プロジェクトとセッションを閲覧する

Projects ページでは、サポートされているローカル履歴ストアを統合して表示します。プロジェクトを選択するとそのセッション一覧が表示され、セッションを開くと未加工のログビューア、サブエージェントセグメント、ダウンロードアクション、セッションスコープのポリシーアクティビティにアクセスできます。

プロジェクトやセッションが表示されない場合は、ハーネスがデフォルトの履歴の場所を使用しているか確認するか、`failproofai harness add-path` で追加のルートを登録してください。

## オフライン監査をスケジュールする

<Tabs>
  <Tab title="ダッシュボード">
    **Settings** を開き、スケジュールスキャンを有効にして、サポートされているインターバルを選択し、利用可能な場合はレポートの配信先を設定します。このページには次回の実行時刻、前回の実行時刻、終了コード、バックグラウンドデーモンがそのプラットフォームでサポートされているかどうかが表示されます。
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    日数を変更して 1〜90 日の異なるインターバルを設定できます。定期スキャンを無効にするには `failproofai audit --no-schedule` を使用します。即時の対話型スキャンを実行するには `failproofai audit` を実行してください。
  </Tab>
</Tabs>

<Warning>
  ローカルダッシュボードには、ローカルエージェント履歴からのプロンプト、ツール入力、ファイルコンテンツ、ターミナル出力が表示される場合があります。信頼できるインターフェースにのみバインドし、確認が完了したらプロセスを停止してください。
</Warning>
