`failproofai otel` は、FailproofAI Cloud へのオプションの OpenTelemetry レポートを設定します。まず `failproofai config` でマシンを接続してください。Cloud では OpenTelemetry の取り込みが常時有効なため、組織側でオンにするスイッチはありません。

インタラクティブセットアップでは、Cloud キーのフィールドとエージェント選択の後に OpenTelemetry について確認します。このオプションのステップはデフォルトで「No」です。「Yes」を選択すると OTEL エージェントを選べます。接続情報が書き込まれた後、同じ有効化コードが実行されます。セットアップ前に Esc を押しても何も変更されません。無人セットアップ、キーの直接指定、オープンソースモード、保存済み接続の維持のいずれもオプトインにはなりません。

## エージェントの有効化

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

サポートされているエージェントは `claude`、`codex`、`copilot`（VS Code）です。Copilot のセットアップには VS Code の実行ファイルまたはインストール済みの Copilot 拡張機能が必要です。設定ディレクトリが残っているだけでは不十分で、どちらも見つからない場合はセットアップが Copilot をスキップします。

`--local` を指定すると、Cloud に直接送信する代わりにローカルリレーに送信します。Copilot は設定に認証ヘッダーを保存できないため、自動的にリレーを使用します。

リレーはマシン上でのみ待ち受けます。設定済みの FailproofAI デーモンは数秒以内に変更を検知するため、再起動は不要です。別のアプリケーションがリレーポートを使用している場合、ステータスはオフと表示されますが、デーモンは引き続き動作します。

<Warning>
テキストのキャプチャはデフォルトで有効です。プロンプトやツールの詳細を省略するには `--no-content` を追加してください。エージェントのバージョンによってコンテンツ制御の仕様が異なる場合があります。機密データを扱う前に、エージェントがエクスポートする内容を確認してください。
</Warning>

Codex がエクスポートするのは会話ログのみで、内部のランタイムトレースやメトリクスは含まれません。Codex の設定に `log_user_prompt = false` が明示的に記載されている場合は無効のままになります。有効化時にその設定が維持される場合は、メモが表示されます。

### レポートパスの選択

エージェントのトランスクリプトレポートが有効な場合、セットアップで次の確認が表示されます：

> failproofai already sends Claude Code sessions to Cloud. Send them with OTEL instead? Transcript upload for Claude Code stops.

デフォルトは「No」です。`--yes` を指定するとプロンプトなしで切り替えを承認します。他のエージェントやポリシーの適用には影響しません。

Codex のセットアップでは、エクスポーター設定を書き込む前に、デーモンがコレクターの変更を確認するまで待機します。確認がタイムアウトした場合は、Codex を起動する前に待機するよう警告が表示されます。

Config v2 では、記憶されたトレースリストを `agents.selected`（検出履歴は `agents.seen`）に保持します。エージェントごとのトランスクリプト設定は `collector.agents.<agent>.sessions`、OTEL の所有権は `otel.agents`、リレー設定は `collector.otlp.enabled` / `collector.otlp.port` に保存されます。これらのキーを分離することで、古い OTEL 設定も読み取り可能な状態を維持します。セットアップはトランスポート設定やエージェント設定の復元に必要な状態を失わずにトレースリストを変更できます。

## セットアップの確認

```bash
failproofai otel status
```

ステータスでは、すべてのエージェントについて、設定が FailproofAI によって管理されているか、送信先、組織の取り込みスイッチ、リレーの状態、最後のリレーアップロード結果が表示されます。

組織スイッチが `unknown` の場合は、サーバーがそれを提供しなかったか、到達できなかったことを意味します。これはエラーではなく、旧バージョンの Cloud での設定を妨げません。

Cloud がまだ OTEL をサポートしていない場合、リレーは拒否されたエクスポートを破棄せずに保持します。旧バージョンの Cloud が組織の取り込みをオフと報告した場合、`enable` は何も書き込まずにエラーで終了します。

## アプリケーション用の設定を出力する

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

出力は OTLP/HTTP エクスポーター用のシェル環境変数ブロックです。Cloud の出力では `OTEL_EXPORTER_OTLP_ENDPOINT` を Cloud の OTLP ベース `https://<cloud>/otel` に設定し、エクスポーターが `/v1/<signal>` を追加します。`OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` のようなシグナルごとの変数には `https://<cloud>/otel/v1/logs` のような完全な URL が必要です。ローカル出力はリレー `http://127.0.0.1:<port>` を指します。Cloud の出力には設定済みの API キーが含まれるため、シークレットとして扱ってください。ローカル出力にはキーが含まれません。ローカル出力を使用するには、まずローカルエージェントを有効化してリレーを起動してください。

## 以前の設定を復元する

```bash
failproofai otel disable claude
failproofai otel disable all
```

無効化すると、FailproofAI が書き込んだ設定のみが復元され、関係のない変更は保持され、各エージェントの以前のトランスクリプトレポート設定が復元されます。最後に管理されているローカルエージェントが無効化されると、リレーはエクスポートの受け付けを停止します。

Codex の場合、無効化時に `collector.agents.codex.sessions_resume_after`（エポックミリ秒）も記録されます。既存のロールアウトバイト数は配信済みとして扱われるため、OTEL でキャプチャされたセッションが再度アップロードされることはありません。それ以降の追加分は引き続きトランスクリプトレポートを通じて送信されます。

すべてのコマンドは `--help` をサポートしています。アプリケーションおよびコーディングエージェントの例については、[OpenTelemetry in Cloud](/ja/agenteye/opentelemetry) を参照してください。
