`failproofai otel` は、FailproofAI Cloud へのオプションの OpenTelemetry レポートを設定します。まず `failproofai config` でマシンを接続し、組織の管理者に **Settings → OpenTelemetry** を有効化してもらってください。

インタラクティブなセットアップでは、Cloud キーフィールドとエージェント選択の後に OpenTelemetry について確認します。このオプション手順はデフォルトで「No」になっています。「Yes」を選択すると OTEL エージェントを選択できます。接続が書き込まれた後、同じ有効化コードが実行されます。セットアップ前に Esc を押しても何も変更されません。無人セットアップ、指定されたキー、オープンソースモード、および保存済み接続の維持では、オプトインは行われません。

## エージェントの有効化

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

サポートされているエージェントは `claude`、`codex`、`copilot`（VS Code）です。Copilot のセットアップには VS Code の実行ファイルまたはインストール済みの Copilot 拡張機能が必要です。設定ディレクトリが残っているだけでは不十分で、どちらも見つからない場合はセットアップが Copilot をスキップします。

`--local` は Cloud に直接送信する代わりにローカルリレーに送信します。Copilot は認証ヘッダーを設定に保存できないため、自動的にリレーを使用します。

リレーはあなたのマシン上でのみ待機します。設定済みの FailproofAI デーモンは数秒以内に変更を検出するため、再起動は不要です。別のアプリケーションがリレーポートを使用している場合、ステータスはオフと表示されますが、デーモンは引き続き動作します。

<Warning>
テキストキャプチャはデフォルトで有効です。プロンプトやツールの詳細を省略するには `--no-content` を追加してください。エージェントのバージョンによって異なるコンテンツ制御が公開されることがあります。機密データを扱う前に、エージェントがエクスポートする内容を確認してください。
</Warning>

Codex がエクスポートするのは会話ログのみで、内部ランタイムトレースやメトリクスは含まれません。Codex の設定に `log_user_prompt = false` が明示的に指定されている場合はオフのままになります。有効化時にその選択が保持される場合、メッセージが表示されます。

### レポートパスの選択

エージェントのトランスクリプトレポートが有効な場合、セットアップは次のように確認します：

> failproofai はすでに Claude Code セッションを Cloud に送信しています。代わりに OTEL で送信しますか？Claude Code のトランスクリプトアップロードは停止します。

デフォルトは「No」です。`--yes` を指定するとプロンプトなしで切り替えが受け入れられます。他のエージェントやポリシーの適用には影響しません。

Codex のセットアップは、エクスポーター設定を書き込む前に、デーモンがコレクターの変更を確認するまで待機します。確認がタイムアウトした場合、Codex を起動する前に待機するよう警告が表示されます。

Config v2 では、記憶されたトレースリストを `agents.selected`（検出履歴は `agents.seen`）に保持します。エージェントごとのトランスクリプト設定は `collector.agents.<agent>.sessions`、OTEL の所有権は `otel.agents`、リレー設定は `collector.otlp.enabled` / `collector.otlp.port` に保持されます。これらの独立したキーにより、古い OTEL 設定が読み取り可能なままになります。トランスポート設定やエージェント設定の復元に必要な状態を失うことなく、トレースリストを変更できます。

## セットアップの確認

```bash
failproofai otel status
```

ステータスには、各エージェント、FailproofAI による設定管理の有無、送信先、組織のインジェストスイッチ、リレーの状態、最後のリレーアップロード結果が表示されます。

組織スイッチが `unknown` の場合、サーバーがそれを提供しなかったか、接続できなかったことを意味します。これはエラーではなく、古い Cloud バージョンでの設定を妨げるものではありません。

Cloud がまだ OTEL をサポートしていない場合、リレーは拒否されたエクスポートを破棄せずに保持します。組織のインジェストがオフの場合、`enable` は何も書き込まずエラーで終了します。まず管理者にオンにするよう依頼してください。

## アプリケーション向け設定の出力

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

出力は OTLP/HTTP エクスポーター用のシェル環境ブロックです。Cloud 出力では `OTEL_EXPORTER_OTLP_ENDPOINT` を Cloud の OTLP ベース `https://<cloud>/otel` に設定し、エクスポーターは `/v1/<signal>` を追加します。`OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` のようなシグナルごとの変数には `https://<cloud>/otel/v1/logs` のような完全な URL が必要です。ローカル出力はリレー `http://127.0.0.1:<port>` を指します。Cloud 出力には設定済みの API キーが含まれます。これはシークレットとして扱ってください。ローカル出力にはキーは含まれません。ローカル出力を使用するには、まずローカルエージェントを有効化してリレーを起動しておく必要があります。

## 以前の設定の復元

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable は FailproofAI が書き込んだ設定のみを復元し、無関係な変更は保持して、各エージェントの以前のトランスクリプトレポート設定を復元します。最後に管理されていたローカルエージェントが無効化されると、リレーはエクスポートの受け付けを停止します。

Codex の場合、disable は `collector.agents.codex.sessions_resume_after`（エポックミリ秒）も記録します。既存のロールアウトバイトは配信済みとして扱われるため、OTEL でキャプチャされたセッションが再度アップロードされることはありません。その後の追記は引き続きトランスクリプトレポートを通じて送信されます。

すべてのコマンドは `--help` をサポートしています。アプリケーションおよびコーディングエージェントの例については [OpenTelemetry in Cloud](/ja/agenteye/opentelemetry) を参照してください。
