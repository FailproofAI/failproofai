`failproofai otel` は、FailproofAI Cloud へのオプションの OpenTelemetry レポートを設定します。まず `failproofai config` でマシンを接続し、組織の管理者に **Settings → OpenTelemetry** を有効にするよう依頼してください。

インタラクティブなセットアップでは、Cloud キーフィールドとエージェント選択の後に OpenTelemetry について確認します。このオプションのステップはデフォルトで「No」になっています。「Yes」を選択すると OTEL エージェントを選択できます。接続が書き込まれた後、同じ有効化コードが実行されます。セットアップ前に Esc を押しても変更は適用されません。無人セットアップ、指定済みキー、オープンソースモード、および保存済み接続の保持では、オプトインは行われません。

## エージェントの有効化

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

サポートされているエージェントは `claude`、`codex`、および `copilot`（VS Code）です。Copilot のセットアップには VS Code の実行ファイルまたはインストール済みの Copilot 拡張機能が必要です。設定ディレクトリのみが残っている状態では不十分です。どちらも見つからない場合、セットアップは Copilot をスキップします。

`--local` は、Cloud に直接送信するのではなく、ローカルリレーに送信します。Copilot は、設定に認証ヘッダーを保存できないため、自動的にリレーを使用します。

リレーはあなたのマシン上でのみ待ち受けます。設定済みの FailproofAI デーモンは数秒以内に変更を検知します。再起動は不要です。別のアプリケーションがリレーポートを使用している場合、ステータスはオフと表示され、デーモンは引き続き実行されます。

<Warning>
テキストキャプチャはデフォルトで有効です。プロンプトやツールの詳細を省略するには `--no-content` を追加してください。エージェントのバージョンによって公開されるコンテンツ制御が異なります。機密データと組み合わせて使用する前に、エージェントがエクスポートする内容を確認してください。
</Warning>

Codex がエクスポートするのは会話ログのみであり、内部ランタイムのトレースやメトリクスは含まれません。Codex の設定に `log_user_prompt = false` が明示的に記載されている場合、その設定はオフのままになります。有効化時にその選択が維持される場合、セットアップはその旨を通知します。

### レポートパスの選択

エージェントのトランスクリプトレポートが有効になっている場合、セットアップは次のように確認します：

> failproofai already sends Claude Code sessions to Cloud. Send them with OTEL instead? Transcript upload for Claude Code stops.

デフォルトは「No」です。`--yes` を指定すると、プロンプトなしで切り替えが実行されます。他のエージェントおよびポリシーの適用には影響しません。

Codex のセットアップは、エクスポーター設定を書き込む前に、コレクターの変更をデーモンが確認するまで待機します。確認がタイムアウトした場合、セットアップは Codex を起動する前に待機するよう警告します。

Config v2 では、記憶されたトレースリストを `agents.selected`（検出履歴は `agents.seen`）に保持します。エージェントごとのトランスクリプト設定は `collector.agents.<agent>.sessions`、OTEL の所有権は `otel.agents`、リレー設定は `collector.otlp.enabled` / `collector.otlp.port` に保持されます。これらの分離されたキーにより、古い OTEL 設定が読み取り可能な状態を維持します。セットアップはトランスポート設定やエージェント設定の復元に必要な状態を失わずに、トレースリストを変更できます。

## セットアップの確認

```bash
failproofai otel status
```

ステータスには、各エージェント、FailproofAI による設定管理の有無、送信先、組織の取り込みスイッチ、リレーの状態、および最後のリレーアップロード結果が表示されます。

組織スイッチが `unknown` の場合、サーバーがその情報を提供しなかったか、到達できなかったことを意味します。これはエラーではなく、旧バージョンの Cloud での設定を妨げるものではありません。

Cloud が OTEL をまだサポートしていない場合、リレーは拒否されたエクスポートを破棄せずに保持します。組織の取り込みがオフの場合、`enable` は何も書き込まずにエラーで終了します。まず管理者に有効化を依頼してください。

## アプリケーション向けの設定出力

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

出力は OTLP/HTTP エクスポーター用のシェル環境ブロックです。Cloud 出力では `OTEL_EXPORTER_OTLP_ENDPOINT` を Cloud の OTLP ベース `https://<cloud>/otel` に設定し、エクスポーターは `/v1/<signal>` を追加します。`OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` のようなシグナルごとの変数には、完全な `https://<cloud>/otel/v1/logs` が必要です。ローカル出力はリレー `http://127.0.0.1:<port>` を指します。Cloud 出力には設定済みの API キーが含まれます。これはシークレットとして扱ってください。ローカル出力にはキーは含まれません。ローカル出力を使用するには、まずローカルエージェントを有効化してリレーを起動してください。

## 以前の設定の復元

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable は FailproofAI が書き込んだ設定のみを復元し、無関係な変更は保持します。また、各エージェントの以前のトランスクリプトレポート設定を復元します。最後に管理されていたローカルエージェントが無効化されると、リレーはエクスポートの受け付けを停止します。

Codex の場合、disable は `collector.agents.codex.sessions_resume_after`（エポックミリ秒）も記録します。既存のロールアウトバイトは配信済みとして扱われるため、OTEL でキャプチャされたセッションが再度アップロードされることはありません。その後に追加されたデータは引き続きトランスクリプトレポートを通じて送信されます。

すべてのコマンドは `--help` をサポートしています。アプリケーションおよびコーディングエージェントの例については、[OpenTelemetry in Cloud](/ja/agenteye/opentelemetry) を参照してください。
