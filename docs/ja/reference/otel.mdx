`failproofai otel` は、FailproofAI Cloud へのオプションの OpenTelemetry レポートを設定します。まず `failproofai config` でマシンを接続し、組織の管理者に **Settings → OpenTelemetry** を有効化してもらってください。

インタラクティブセットアップでは、Cloud キーフィールドとエージェントピッカーの後に OpenTelemetry について確認します。このオプションのステップはデフォルトで「No」になっています。「Yes」を選択すると OTEL エージェントを選べます。同じ有効化コードが接続書き込み後に実行されます。セットアップ前に Esc を押しても何も変更されません。無人セットアップ、キーの指定、オープンソースモード、および保存済み接続の維持では自動的にオプトインされません。

## エージェントを有効化する

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

サポートされているエージェントは `claude`、`codex`、`copilot`（VS Code）です。Copilot のセットアップには VS Code の実行ファイルまたはインストール済みの Copilot 拡張機能が必要です。設定ディレクトリが残っているだけでは不十分で、どちらも見つからない場合はセットアップが Copilot をスキップします。

`--local` は Cloud に直接送信する代わりにローカルリレーに送信します。Copilot は設定に認証ヘッダーを保存できないため、自動的にリレーを使用します。

リレーはあなたのマシン上でのみ待ち受けます。設定済みの FailproofAI デーモンは数秒以内に変更を反映するため、再起動は不要です。別のアプリケーションがリレーポートを使用している場合、ステータスにはオフと表示されますが、デーモンは引き続き動作します。

<Warning>
テキストキャプチャはデフォルトで有効です。プロンプトやツールの詳細を除外するには `--no-content` を追加してください。エージェントのバージョンによってコンテンツ制御の仕様が異なる場合があります。機密データと組み合わせて使用する前に、エージェントがエクスポートする内容を確認してください。
</Warning>

Codex がエクスポートするのは会話ログのみで、内部ランタイムのトレースやメトリクスは含まれません。Codex 設定で明示的に `log_user_prompt = false` が指定されている場合はオフのままになります。有効化時にその選択が保持される旨のメモが表示されます。

### レポートパスを一つ選ぶ

エージェントのトランスクリプトレポートが有効になっている場合、セットアップで次の確認が表示されます：

> failproofai already sends Claude Code sessions to Cloud. Send them with OTEL instead? Transcript upload for Claude Code stops.

デフォルトは「No」です。`--yes` を指定するとプロンプトなしで切り替えを承認します。他のエージェントおよびポリシーの適用には影響しません。

Codex のセットアップでは、エクスポーター設定を書き込む前にデーモンがコレクターの変更を確認するまで待機します。確認がタイムアウトした場合、Codex を起動する前に待つよう警告が表示されます。

Config v2 では、記憶されたトレースリストを `agents.selected` に保持し（検出履歴は `agents.seen` に）、エージェントごとのトランスクリプト設定は `collector.agents.<agent>.sessions` に、OTEL のオーナーシップは `otel.agents` に、リレー設定は `collector.otlp.enabled` / `collector.otlp.port` に保持します。これらのキーを分離することで古い OTEL 設定が読み取り可能になり、トランスポート設定やエージェント設定の復元に必要な状態を失わずにトレースリストを変更できます。

## セットアップを確認する

```bash
failproofai otel status
```

ステータスには、すべてのエージェント、FailproofAI による設定管理の有無、送信先、組織のインジェストスイッチ、リレーの状態、および最後のリレーアップロード結果が表示されます。

組織スイッチが `unknown` の場合、サーバーが提供しなかったか、到達できなかったことを意味します。これはエラーではなく、古い Cloud バージョンでの設定を妨げません。

Cloud がまだ OTEL をサポートしていない場合、リレーは拒否されたエクスポートを破棄せずに保持します。組織のインジェストがオフの場合、`enable` は何も書き込まずエラーで終了します。管理者にオンにしてもらってください。

## アプリケーション向けに設定を出力する

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

出力は OTLP/HTTP エクスポーター用のシェル環境ブロックです。Cloud 出力では `OTEL_EXPORTER_OTLP_ENDPOINT` を Cloud の OTLP ベース `https://<cloud>/otel` に設定し、エクスポーターが `/v1/<signal>` を追加します。`OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` のようなシグナルごとの変数には `https://<cloud>/otel/v1/logs` の完全な URL が必要です。ローカル出力はリレーの `http://127.0.0.1:<port>` を指します。Cloud 出力には設定済みの API キーが含まれます。シークレットとして扱ってください。ローカル出力にはキーは含まれません。ローカル出力を使用するには、まずローカルエージェントを有効化してリレーを起動してください。

## 以前の設定を復元する

```bash
failproofai otel disable claude
failproofai otel disable all
```

disable は FailproofAI が書き込んだ設定のみを復元し、関係のない変更はそのまま保持し、各エージェントの以前のトランスクリプトレポート設定を復元します。最後に管理されているローカルエージェントが無効化されると、リレーはエクスポートの受け入れを停止します。

Codex の場合、disable は `collector.agents.codex.sessions_resume_after`（エポックミリ秒）も記録します。既存のロールアウトバイト数は配信済みとして扱われるため、OTEL でキャプチャされたセッションが再度アップロードされることはありません。その後の追記は引き続きトランスクリプトレポートを通じて送信されます。

すべてのコマンドは `--help` をサポートしています。アプリケーションおよびコーディングエージェントの例については [OpenTelemetry in Cloud](/ja/agenteye/opentelemetry) を参照してください。
