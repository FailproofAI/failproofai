`failproofai otel` は、FailproofAI Cloud へのオプショナルな OpenTelemetry レポートを設定します。まず `failproofai config` でマシンを接続してください。Cloud では OpenTelemetry の取り込みは常に有効になっているため、組織側でオンにするスイッチはありません。

インタラクティブなセットアップでは、Cloud キーの入力フィールドとエージェント選択の後に OpenTelemetry について確認します。このオプショナルなステップはデフォルトで「No」になっています。「Yes」を選択すると OTEL エージェントを選べます。接続情報が書き込まれた後、同じ有効化コードが実行されます。セットアップ中に Esc を押すと変更は何も適用されません。無人セットアップ、キーの直接指定、オープンソースモード、および保存済みの接続を維持する場合はオプトインされません。

## エージェントを有効にする

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

サポートされているエージェントは `claude`、`codex`、`copilot`（VS Code）です。Copilot のセットアップには VS Code の実行ファイルまたはインストール済みの Copilot 拡張機能が必要です。設定ディレクトリが残っているだけでは不十分で、どちらも見つからない場合はセットアップが Copilot をスキップします。

`--local` を指定すると、Cloud に直接送信する代わりにローカルリレーに送信します。Copilot は設定に認証ヘッダーを保存できないため、自動的にリレーを使用します。

リレーはマシン上でのみ待機します。設定済みの FailproofAI デーモンは数秒以内に変更を検知するため、再起動は不要です。別のアプリケーションがリレーポートを使用している場合、ステータスはオフと表示されますが、デーモンは稼働し続けます。

<Warning>
テキストキャプチャはデフォルトで有効です。プロンプトやツールの詳細を除外するには `--no-content` を追加してください。エージェントのバージョンによってコンテンツ制御の仕様が異なる場合があります。機密データと共に使用する前に、エージェントがエクスポートする内容を確認してください。
</Warning>

Codex がエクスポートするのは会話ログのみで、内部のランタイムトレースやメトリクスは含まれません。Codex の設定で `log_user_prompt = false` が明示的に指定されている場合は、その設定が維持されます。有効化の際にその選択が保持された場合は、メモが表示されます。

### レポートパスを1つ選択する

エージェントのトランスクリプトレポートが有効な場合、セットアップは次のように確認します：

> failproofai already sends Claude Code sessions to Cloud. Send them with OTEL instead? Transcript upload for Claude Code stops.

デフォルトは「No」です。`--yes` を指定するとプロンプトなしで切り替えが適用されます。他のエージェントやポリシーの適用には影響しません。

Codex のセットアップでは、エクスポーター設定を書き込む前に、デーモンがコレクターの変更を確認するのを待ちます。確認がタイムアウトした場合、Codex を起動する前に待機するよう警告が表示されます。

Config v2 では、記録されたトレーシングリストを `agents.selected`（検出履歴は `agents.seen`）に保持します。エージェントごとのトランスクリプト設定は `collector.agents.<agent>.sessions`、OTEL の所有権は `otel.agents`、リレー設定は `collector.otlp.enabled` / `collector.otlp.port` に保持されます。これらのキーを分離することで、既存の OTEL 設定が読み取り可能になります。セットアップはトランスポートの設定やエージェント設定の復元に必要な状態を失うことなく、トレーシングリストを変更できます。

## セットアップを確認する

```bash
failproofai otel status
```

ステータスでは、各エージェントについて、設定が FailproofAI によって管理されているかどうか、送信先、組織の取り込みスイッチの状態、リレーの状態、および最後のリレーアップロードの結果が表示されます。

組織のスイッチが `unknown` と表示される場合、サーバーが情報を提供しなかったか、到達できなかったことを意味します。これはエラーではなく、古い Cloud バージョンでの設定を妨げるものではありません。

Cloud がまだ OTEL をサポートしていない場合、リレーは拒否されたエクスポートを破棄せずに保持します。古い Cloud バージョンが組織の取り込みをオフと報告した場合、`enable` は何も書き込まずエラーで終了します。

## アプリケーション用の設定を出力する

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

出力は OTLP/HTTP エクスポーター用のシェル環境変数ブロックです。Cloud 向けの出力では `OTEL_EXPORTER_OTLP_ENDPOINT` が Cloud の OTLP ベース URL である `https://<cloud>/otel` に設定され、エクスポーターが `/v1/<signal>` を付加します。`OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` のようなシグナルごとの変数には、`https://<cloud>/otel/v1/logs` のような完全な URL が必要です。ローカル向けの出力はリレー `http://127.0.0.1:<port>` を指します。Cloud 向けの出力には設定済みの API キーが含まれます。これは機密情報として扱ってください。ローカル向けの出力にはキーは含まれません。ローカル出力を使用するには、まずローカルエージェントを有効にしてリレーを起動してください。

## 以前の設定を復元する

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable は FailproofAI が書き込んだ設定のみを復元し、関係のない変更はそのままにして、各エージェントの以前のトランスクリプトレポート設定を復元します。最後に管理されていたローカルエージェントが無効化されると、リレーはエクスポートの受け付けを停止します。

Codex の場合、disable は `collector.agents.codex.sessions_resume_after`（エポックミリ秒）も記録します。既存のロールアウトバイト数は配信済みとして扱われ、OTEL でキャプチャされたセッションが再度アップロードされることはありません。その後に追加されたデータは引き続きトランスクリプトレポートを通じて送信されます。

すべてのコマンドは `--help` をサポートしています。アプリケーションおよびコーディングエージェントの例については、[OpenTelemetry in Cloud](/ja/agenteye/opentelemetry) を参照してください。
