`failproofai otel` は、FailproofAI Cloud へのオプションの OpenTelemetry レポートを設定します。まず `failproofai config` でマシンを接続し、組織管理者に **Settings → OpenTelemetry** を有効化するよう依頼してください。

インタラクティブなセットアップでは、Cloud キーフィールドとエージェント選択の後に OpenTelemetry について確認します。このオプションのステップはデフォルトで「No」になっています。「Yes」を選択すると OTEL エージェントを選べます。接続が書き込まれた後、同じ有効化コードが実行されます。セットアップ前に Esc を押すと何も変更されません。無人セットアップ、指定済みキー、オープンソースモード、および保存済み接続の維持では、オプトインは行われません。

## エージェントを有効にする

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

サポートされているエージェントは `claude`、`codex`、および `copilot`（VS Code）です。Copilot のセットアップには VS Code の実行ファイルまたはインストール済みの Copilot 拡張機能が必要です。設定ディレクトリが残っているだけでは不十分で、どちらも見つからない場合はセットアップが Copilot をスキップします。

`--local` は Cloud に直接送信するのではなく、ローカルリレーに送信します。Copilot は認証ヘッダーを設定に保存できないため、自動的にリレーを使用します。

リレーはあなたのマシン上でのみ待機します。設定済みの FailproofAI デーモンは数秒以内に変更を検知するため、再起動は不要です。別のアプリケーションがリレーポートを使用している場合、ステータスはオフと表示されますが、デーモンは引き続き動作します。

<Warning>
テキストキャプチャはデフォルトで有効です。プロンプトやツールの詳細を省略するには `--no-content` を追加してください。エージェントのバージョンによってコンテンツ制御の方法が異なる場合があります。機密データで使用する前に、エージェントがエクスポートする内容を確認してください。
</Warning>

Codex は会話ログのみをエクスポートし、内部ランタイムトレースやメトリクスはエクスポートしません。Codex 設定で `log_user_prompt = false` を明示的に設定している場合はオフのまま維持されます。有効化する際にその選択が保持される場合は、注記が表示されます。

### レポートパスを1つ選択する

エージェントのトランスクリプトレポートが有効な場合、セットアップで次のように確認されます：

> failproofai already sends Claude Code sessions to Cloud. Send them with OTEL instead? Transcript upload for Claude Code stops.

デフォルトは「No」です。`--yes` を使用するとプロンプトなしで切り替えが受け入れられます。他のエージェントやポリシーの適用には影響しません。

Codex のセットアップでは、エクスポーター設定を書き込む前に、デーモンがコレクターの変更を確認するまで待機します。確認がタイムアウトした場合、Codex を起動する前に待つよう警告が表示されます。

Config v2 では、記憶されたトレーシングリストを `agents.selected`（検出履歴は `agents.seen`）に保持します。エージェントごとのトランスクリプト設定は `collector.agents.<agent>.sessions`、OTEL の所有権は `otel.agents`、リレー設定は `collector.otlp.enabled` / `collector.otlp.port` に保持されます。これらの分離されたキーにより、古い OTEL 設定が読み取り可能な状態を維持します。トランスポート設定やエージェント設定の復元に必要な状態を失わずに、トレーシングリストを変更できます。

## セットアップを確認する

```bash
failproofai otel status
```

ステータスでは、すべてのエージェント、設定が FailproofAI によって管理されているかどうか、送信先、組織のインジェストスイッチ、リレー状態、および最後のリレーアップロード結果が表示されます。

組織スイッチが `unknown` の場合、サーバーがそれを提供しなかったか、到達できなかったことを意味します。これはエラーではなく、古い Cloud バージョンでの設定を妨げるものではありません。

Cloud が OTEL をまだサポートしていない場合、リレーは拒否されたエクスポートを破棄せずに保持します。組織のインジェストがオフの場合、`enable` は何も書き込まずエラーで終了します。まず管理者に有効化を依頼してください。

## アプリケーションの設定を表示する

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

出力は OTLP/HTTP エクスポーター用のシェル環境ブロックです。Cloud の出力では `OTEL_EXPORTER_OTLP_ENDPOINT` を Cloud の OTLP ベース `https://<cloud>/otel` に設定し、エクスポーターが `/v1/<signal>` を追加します。`OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` のようなシグナルごとの変数には `https://<cloud>/otel/v1/logs` のような完全な URL が必要です。ローカル出力はリレー `http://127.0.0.1:<port>` を指します。Cloud の出力には設定済みの API キーが含まれます。これはシークレットとして扱ってください。ローカル出力にはキーは含まれません。ローカル出力を使用するには、まずローカルエージェントを有効にしてリレーを起動する必要があります。

## 以前の設定を復元する

```bash
failproofai otel disable claude
failproofai otel disable all
```

無効化すると、FailproofAI が書き込んだ設定のみが復元され、無関係な変更は保持され、各エージェントの以前のトランスクリプトレポート設定が復元されます。最後に管理されていたローカルエージェントが無効化されると、リレーはエクスポートの受け付けを停止します。

Codex の場合、無効化すると `collector.agents.codex.sessions_resume_after`（エポックミリ秒）も記録されます。既存のロールアウトバイトは配信済みとして扱われるため、OTEL でキャプチャされたセッションが再度アップロードされることはありません。その後の追記はトランスクリプトレポートを通じて引き続き送信されます。

すべてのコマンドは `--help` をサポートしています。アプリケーションおよびコーディングエージェントの例については、[OpenTelemetry in Cloud](/ja/agenteye/opentelemetry) を参照してください。
