`failproofai otel` は、FailproofAI Cloud へのオプションの OpenTelemetry レポートを設定します。まず `failproofai config` でマシンを接続し、組織の管理者に **Settings → OpenTelemetry** を有効化してもらってください。

インタラクティブなセットアップでは、Cloud キーフィールドとエージェント選択の後に OpenTelemetry について確認します。このオプションのステップはデフォルトで「No」になっています。「Yes」を選択すると OTEL エージェントを選べます。接続が書き込まれた後に、同じ有効化コードが実行されます。セットアップ前に Esc を押しても何も変更されません。無人セットアップ、キーの直接指定、オープンソースモード、保存済み接続の維持を行った場合はオプトインされません。

## エージェントを有効にする

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

サポートされているエージェントは `claude`、`codex`、`copilot`（VS Code）です。Copilot のセットアップには VS Code の実行ファイルか、インストール済みの Copilot 拡張機能が必要です。設定ディレクトリが残っているだけでは不十分で、どちらも見つからない場合はセットアップが Copilot をスキップします。

`--local` を使用すると、Cloud に直接送信するのではなくローカルリレーに送信します。Copilot は認証ヘッダーを設定に保存できないため、自動的にリレーを使用します。

リレーはマシン上でのみリッスンします。設定済みの FailproofAI デーモンは数秒以内に変更を検知します。再起動は不要です。別のアプリケーションがリレーポートを使用している場合、ステータスはオフと表示されますが、デーモンは引き続き動作します。

<Warning>
テキストのキャプチャはデフォルトで有効です。プロンプトやツールの詳細を除外するには `--no-content` を追加してください。エージェントのバージョンによってコンテンツの制御方法が異なる場合があります。機密データを扱う前に、エージェントがエクスポートする内容を確認してください。
</Warning>

Codex は会話ログのみをエクスポートします。内部のランタイムトレースやメトリクスはエクスポートされません。Codex の設定で `log_user_prompt = false` が明示的に指定されている場合、その設定は無効化されません。有効化時にその選択が保持される場合、セットアップはメモを表示します。

### レポートパスを1つ選択する

エージェントのトランスクリプトレポートが有効な場合、セットアップは次のように確認します：

> failproofai already sends Claude Code sessions to Cloud. Send them with OTEL instead? Transcript upload for Claude Code stops.

デフォルトは「No」です。`--yes` を指定するとプロンプトなしで切り替えが承認されます。他のエージェントやポリシー適用には影響しません。

Codex のセットアップは、エクスポーター設定を書き込む前に、デーモンがコレクターの変更を確認するのを待ちます。確認がタイムアウトした場合、セットアップは Codex を起動する前に待つよう警告します。

設定 v2 では、記憶されたトレーシングリストを `agents.selected`（検出履歴は `agents.seen`）に保持します。エージェントごとのトランスクリプト設定は `collector.agents.<agent>.sessions`、OTEL の所有権は `otel.agents`、リレー設定は `collector.otlp.enabled` / `collector.otlp.port` に保存されます。これらのキーを分離することで、古い OTEL 設定も読み取り可能になります。セットアップはトランスポート設定やエージェント設定の復元に必要な状態を失わずに、トレーシングリストを変更できます。

## セットアップを確認する

```bash
failproofai otel status
```

ステータスには、各エージェント、FailproofAI による設定の管理状況、送信先、組織のインジェストスイッチ、リレーの状態、最後のリレーアップロード結果が表示されます。

組織スイッチが `unknown` の場合、サーバーが情報を提供しなかったか、到達できなかったことを意味します。これはエラーではなく、古い Cloud バージョンでの設定を妨げるものではありません。

Cloud が OTEL をまだサポートしていない場合、リレーは拒否されたエクスポートを破棄せずに保持します。組織のインジェストがオフの場合、`enable` は何も書き込まずにエラーで終了します。まず管理者にオンにしてもらってください。

## アプリケーション用の設定を出力する

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

出力は OTLP/HTTP エクスポーター用のシェル環境ブロックです。Cloud 出力では `OTEL_EXPORTER_OTLP_ENDPOINT` に Cloud の OTLP ベース（`https://<cloud>/otel`）が設定され、エクスポーターは `/v1/<signal>` を追加します。`OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` のようなシグナルごとの変数には完全な `https://<cloud>/otel/v1/logs` が必要です。ローカル出力はリレー（`http://127.0.0.1:<port>`）を指します。Cloud 出力には設定済みの API キーが含まれます。シークレットとして扱ってください。ローカル出力にはキーは含まれません。ローカル出力を使用するには、先にローカルエージェントを有効化してリレーを起動しておく必要があります。

## 以前の設定を復元する

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable は FailproofAI が書き込んだ設定のみを復元し、無関係な変更は保持します。また、各エージェントの以前のトランスクリプトレポート設定も復元されます。最後に管理されたローカルエージェントが無効化されると、リレーはエクスポートの受け付けを停止します。

Codex の場合、disable は `collector.agents.codex.sessions_resume_after`（エポックミリ秒）も記録します。既存のロールアウトバイト数は配信済みとして扱われるため、OTEL でキャプチャされたセッションが再度アップロードされることはありません。それ以降に追加されたデータは引き続きトランスクリプトレポートを通じて流れます。

すべてのコマンドで `--help` がサポートされています。アプリケーションやコーディングエージェントの例については、[OpenTelemetry in Cloud](/ja/agenteye/opentelemetry) を参照してください。
