`failproofai otel` は、FailproofAI Cloud へのオプションのOpenTelemetryレポートを設定します。まず `failproofai config` でマシンを接続し、組織の管理者に **Settings → OpenTelemetry** を有効化してもらってください。

インタラクティブなセットアップでは、Cloudキーフィールドとエージェント選択の後にOpenTelemetryについて確認します。このオプションのステップはデフォルトでNoになっています。Yesを選択するとOTELエージェントを選べます。接続が書き込まれた後、同じ有効化コードが実行されます。セットアップ前にEscを押しても何も変更されません。無人セットアップ、指定済みキー、オープンソースモード、保存済み接続の維持のいずれの場合もオプトインにはなりません。

## エージェントを有効にする

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

サポートされているエージェントは `claude`、`codex`、`copilot`（VS Code）です。Copilotのセットアップには、VS Codeの実行可能ファイルまたはインストール済みのCopilot拡張機能が必要です。設定ディレクトリが残っているだけでは不十分で、どちらも見つからない場合はセットアップがCopilotをスキップします。

`--local` は、Cloudに直接送信する代わりにローカルリレー経由で送信します。Copilotは設定に認証ヘッダーを保存できないため、自動的にリレーを使用します。

リレーはあなたのマシン上でのみリッスンします。設定されたFailproofAIデーモンは数秒以内に変更を検知するため、再起動は不要です。別のアプリケーションがリレーポートを使用している場合、ステータスはオフと表示されますが、デーモンは引き続き実行されます。

<Warning>
テキストキャプチャはデフォルトで有効です。プロンプトやツールの詳細を省略するには `--no-content` を追加してください。エージェントのバージョンによって公開されるコンテンツ制御が異なる場合があります。機密データと共に使用する前に、エージェントがエクスポートする内容を確認してください。
</Warning>

Codexがエクスポートするのは会話ログのみで、内部ランタイムトレースやメトリクスは含まれません。Codexの設定に `log_user_prompt = false` が明示的に設定されている場合はオフのまま維持され、その選択が保持された際にenableが注意メッセージを表示します。

### レポートパスを1つ選択する

エージェントのトランスクリプトレポートがオンの場合、セットアップは次のように確認します：

> failproofai already sends Claude Code sessions to Cloud. Send them with OTEL instead? Transcript upload for Claude Code stops.

デフォルトはNoです。`--yes` を使用すると確認なしで切り替えが受け入れられます。他のエージェントとポリシーの適用には影響しません。

Codexのセットアップでは、エクスポーター設定を書き込む前に、デーモンがコレクターの変更を確認するまで待機します。確認がタイムアウトした場合、セットアップはCodexを起動する前に待つよう警告します。

Config v2は、記憶されたトレーシングリストを `agents.selected`（検出履歴は `agents.seen`）に保持します。エージェントごとのトランスクリプト優先設定は `collector.agents.<agent>.sessions`、OTELの所有権は `otel.agents`、リレー設定は `collector.otlp.enabled` / `collector.otlp.port` に保持されます。これらの分離されたキーにより、古いOTEL設定が読み取り可能な状態を維持します。トランスポートの優先設定やエージェント設定の復元に必要な状態を失うことなく、セットアップがトレーシングリストを変更できます。

## セットアップを確認する

```bash
failproofai otel status
```

ステータスには、すべてのエージェント、その設定がFailproofAIによって管理されているかどうか、送信先、組織のインジェストスイッチ、リレーの状態、および最後のリレーアップロード結果が表示されます。

組織スイッチが `unknown` の場合、サーバーがそれを提供しなかったか、到達できなかったことを意味します。これはエラーではなく、古いCloudバージョンでの設定を妨げるものではありません。

CloudがまだOTELをサポートしていない場合、リレーは拒否されたエクスポートを破棄せずに保持します。組織のインジェストがオフの場合、`enable` は何も書き込まずにエラーで終了します。まず管理者にオンにしてもらってください。

## アプリケーション用の設定を出力する

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

出力はOTLP/HTTPエクスポーター用のシェル環境ブロックです。Cloudの出力では `OTEL_EXPORTER_OTLP_ENDPOINT` にCloudのOTLPベース `https://<cloud>/otel` が設定され、エクスポーターが `/v1/<signal>` を追加します。`OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` のようなシグナルごとの変数には `https://<cloud>/otel/v1/logs` のような完全なURLが必要です。ローカルの出力はリレー `http://127.0.0.1:<port>` を指します。Cloudの出力には設定済みAPIキーが含まれます。これはシークレットとして扱ってください。ローカルの出力にはキーが含まれません。ローカルの出力を使用するには、まずローカルエージェントを有効にしてリレーを起動させてください。

## 以前の設定を復元する

```bash
failproofai otel disable claude
failproofai otel disable all
```

disableはFailproofAIが書き込んだ設定のみを復元し、無関係な変更は保持し、各エージェントの以前のトランスクリプトレポートの選択を復元します。最後に管理されていたローカルエージェントが無効になると、リレーはエクスポートの受け入れを停止します。

Codexの場合、disableは `collector.agents.codex.sessions_resume_after`（エポックミリ秒）も記録します。既存のロールアウトバイトは配信済みとして扱われるため、OTELでキャプチャされたセッションが再度アップロードされることはありません。それ以降の追加は引き続きトランスクリプトレポートを通じて送信されます。

すべてのコマンドは `--help` をサポートしています。アプリケーションおよびコーディングエージェントの例については、[OpenTelemetry in Cloud](/ja/agenteye/opentelemetry) を参照してください。
