エージェントがすでに動作している環境に最も近いインテグレーションを選択してください。

このセクションでは、それぞれ異なる役割を持つ2つのコマンドラインツールを取り上げます。`failproofai` はエージェントが動作するマシン上で実行され、エージェントループ内でポリシーを適用します。`fp` は Failproof AI Cloud と通信し、そのループの実行内容を取得します。マシンのセットアップは Linux と macOS のみサポートされています。それ以外の OS では `failproofai config` は拒否され、不完全な状態のマシンを残さないよう何も書き込みません。

生成された HTTP API ページは公開 `/v1` サーフェスを対象としています。手書きのページでは、複数のエンドポイントにまたがるワークフローや、その公開サーフェス外の管理インターフェースを使用するワークフローについて説明しています。

## エージェントを接続してデータを確認する

<Tabs>
  <Tab title="ダッシュボード">
    1. **Administration → Keys** を開き、`events:add` と `policies:pull` の権限を持つキーを作成してシークレットをコピーします。
    2. 上記の対応するページを使ってインテグレーションを設定します。
    3. **Observe → Events** を開いてイベントが届いていることを確認し、次に **Observe → Sessions** を開いて完全なランが形成されていることを確認します。
    4. インテグレーションの環境でフィルタリングし、監査に必要なモデル、ツール、エラー、ポリシーフィールドを含む1つのセッションを確認します。

    まずキードロワーから始めます。選択した権限によって、マシンがイベントを送信できるか、Cloud 管理ポリシーを受信できるかが決まります。

    ![イベント取り込みとポリシー配信の権限を付与するための新しい API キードロワー。](/images/dashboard/key-create.png)

    インテグレーションを接続したら、Sessions リストを使って、そのイベントが期待する環境で完全なランとしてグループ化されていることを確認します。

    ![新しく接続されたインテグレーションが完全なエージェントランを報告していることを確認するための Sessions リスト。](/images/dashboard/sessions-list.png)

    インテグレーションが完了したとみなす前に、これらのセッションのうち1つを開いてください。トレースには、監査に必要なモデル、ツール、エラー、ポリシーのエビデンスが含まれているはずです。
  </Tab>
  <Tab title="CLI">
    マシンキーを作成し、このマシンをセットアップして接続し、ポリシーを選択してから最初のセッションを確認します。

    ```bash
    fp keys create agent-production \
      --add events:add \
      --add policies:pull

    failproofai config --token <machine-key>

    failproofai policies add FailproofAI/policies

    failproofai flush --wait
    fp sessions --since 1h
    fp events --since 1h --limit 20
    ```

    どちらの確認コマンドも環境でフィルタリングしません。設定したばかりのマシンはすべてのイベントに `local` というスタンプを押すためです。`collector.environment` を設定した後にのみ `--env production` を追加してください。詳細は「[環境ラベルを変更する](/ja/reference/events-and-configuration#change-an-environment-label)」を参照してください。

    トークンを渡すことが接続のリクエストになるため、`failproofai config --token <machine-key>` は1つのコマンドで同じことを実行します。環境変数の使用を推奨します。引数はそのマシン上のすべてのユーザーが `ps` から読み取れる上、シェル履歴や CI ログにも残ります。

    ポリシーのステップは省略できません。`failproofai config` はデーモンをインストールしてサポートされているすべてのエージェント CLI を接続しますが、意図的にポリシーを選択しないため、設定直後のマシンはパックを追加するまで何も適用しません。

    別のツールが結果を使用する場合は `fp --json sessions ...` を使用してください。`--json`、`--org`、`--base-url` などのグローバルフラグはコマンドの前に指定する必要があります。

    ローカルコマンドについては [Failproof AI CLI リファレンス](/ja/reference/failproof-cli)を、`fp` コマンドについては [Failproof Cloud CLI リファレンス](/ja/reference/cloud-cli#cli-commands)を参照してください。
  </Tab>
</Tabs>
