Slackから[Failproof Assistant](/ja/sessions/assistant)に質問できます。チャンネルでアプリをメンションするか、ダイレクトメッセージを送るか、`/failproof <質問>`を使ってください。回答には**ご自身の** Failproof AI権限が使用され、グラフはスレッドに届き、何かを変更する操作は事前に承認を求めます。

公式アプリは1つです。Failproof AI Cloudがホスト型でも自己ホスト型でも同じように動作します。

<Note>
  回答はAIモデルによって生成されるため、不正確な場合があります。重要な内容はリンク先のソースデータで必ず確認してください。
</Note>

## ワークスペースを接続する

Failproof AIでは`settings:write`権限が必要です。Slack側では、ワークスペースの管理者またはオーナーであるか、アプリを追加するユーザーである必要があります。

<Tabs>
  <Tab title="Failproof AIから">
    1. **設定 → インテグレーション**に移動し、**Slackに追加**を選択します。
    2. Slackでアプリを承認します。
    3. Failproof AIに戻り、ワークスペースを組織に接続することを確認します。
  </Tab>
  <Tab title="Slackから">
    1. アプリを追加し、**ホーム**タブを開きます。
    2. **FailproofAI Cloudで続行**を選択するか、**自分のURLを使用**を選んでサインインするアドレスを入力します。
    3. 続行ボタンを選択し、サインインして組織を選択し、確認します。リンクは1回のみ有効で、10分後に期限切れになります。
  </Tab>
</Tabs>

1つのワークスペースは1つの組織に接続でき、1つの組織は1つのワークスペースに接続できます。

アカウントをお持ちでない場合は、まず[こちらで作成](https://app.befailproof.ai/login)してから接続してください。

## Slackでのあなたのアカウント紐付け

初めて質問すると、アプリはあなたがどのメンバーかを識別しようとします。

- **メールで自動的に**識別されます。接続済みワークスペースの正規メンバーであり、SlackのメールアドレスがConfirm済みで、組織内でそのメールアドレスを使用するメンバーが1人だけの場合。
- **それ以外の場合**は、Failproof AIを開いてSlackユーザーをアカウントに紐付けるプライベートな**アカウントをリンク**ボタンが表示されます。

## 質問する

| 場所 | 方法 |
| --- | --- |
| チャンネル | アプリをメンションする。続けるにはそのスレッドに返信（メンション不要） |
| ダイレクトメッセージ | アプリにメッセージを送る |
| アプリが参加しているグループダイレクトメッセージ | メンションし、スレッドに返信して続ける |
| Slack Connectチャンネル | アプリをメンションする |
| アプリが参加している任意の会話 | `/failproof <質問>`でスレッドが始まり回答が届く |
| `/failproof help` | アプリでできることを確認する |
| `/failproof status` | 接続中の組織と紐付けられているアカウントを確認する |
| `/failproof link` | 紐付けられているFailproof AIアカウントを確認する |

1つのスレッドは1つの会話です。同僚が同じスレッドでアプリをメンションすると、それぞれの権限に応じた回答が届きます。スレッドを開始した人だけが、メンションなしで会話を続けられます。

回答がデータの場合、アプリはグラフまたは表を投稿し、Failproof AIで開くためのリンクも添えます。

## 変更を承認する

アシスタントが行うすべての変更には、まず**承認**と**キャンセル**ボタンが表示され、**承認**の前にSlackがもう一度確認を求めます。ボタンに回答できるのは質問した本人のみで、5分後に期限切れになります。変更はその人の権限で実行されます。

Slackからアシスタントは、保存済みのクエリやダッシュボード、評価、アラート、監査、課題、ポリシーの変更、およびコード修正の提案ができます（それぞれ権限を持っている場合）。APIキー、ユーザー、設定は変更できません。

## リンクプレビュー

ホスト型Failproof AI CloudにおいてFailproof AIの課題、セッション、評価のリンクをSlackに貼り付けると、カードとして展開されます。カードに表示されるのは、貼り付けた人が閲覧できる情報のみです。自己ホスト型のアドレスへのリンクは展開されませんが、アシスタント自身の回答に含まれるカードは引き続き表示されます。

## Slack Connectチャンネル

別のワークスペースのメンバーも、組織のメンバーであればアカウントを紐付けた後にアプリを使用できます。回答はその会話にいるすべての人（組織のメンバーでない人も含む）に表示されるため、全員が見られる場所で質問することを意識してください。

アプリが回答するのは、チャンネル内の他のすべてのワークスペースに組織に紐付けられたメンバーがいる場合に限られます。それまでは、質問した人に理由を伝えます。

## アプリが要求するSlack権限

| Slack権限 | 理由 |
| --- | --- |
| `app_mentions:read` | アプリがメンションされたことを把握する |
| `channels:history`、`groups:history`、`im:history`、`mpim:history` | ダイレクトメッセージとアプリのスレッドへの返信を受信する。アプリは他のメッセージを無視し、過去のメッセージを読むことはない |
| `channels:read`、`groups:read`、`im:read`、`mpim:read` | どのタイプの会話にいるかを確認し、回答を誰が見られるかを把握する |
| `chat:write` | 回答と承認ボタンを投稿する |
| `commands` | `/failproof`を提供する |
| `files:write` | グラフを投稿する |
| `links:read`、`links:write` | 貼り付けられたFailproof AIリンクのプレビューを表示する |
| `users:read`、`users:read.email` | あなたをFailproof AIアカウントと照合し、名前を表示する |

## 切断する

**設定 → インテグレーション**に移動して**切断**を選択するか、アプリの**ホーム**タブの**切断**を使うか、Slackからアプリを削除してください。

いずれの方法でも、ワークスペースの接続、ボットトークン、紐付けられたアカウント、スレッドの記録が削除されます。過去のSlackの会話はダッシュボードで引き続き閲覧できます。その後、組織はすぐに任意のワークスペースを接続できます。

## データとプライバシー

質問と回答は、スレッドを開始した人のもとで組織のダッシュボードに会話として保存されます。SlackのデータがAIモデルのトレーニングに使用されることはありません。アプリが受け取る情報と保持期間については、[プライバシーポリシー](https://befailproof.ai/privacy/)をご覧ください。

## トラブルシューティング

| 表示されるメッセージ | 対処方法 |
| --- | --- |
| 「このワークスペースはまだFailproofAI Cloudに接続されていません」 | ワークスペース管理者がアプリの**ホーム**タブを開いて選択する |
| 「このリンクは期限切れか、すでに使用されています」 | **ホーム**タブでCloudを再度選択して新しいリンクを取得する |
| 「この組織はすでにSlackワークスペースに接続されています」 | 先に設定で切断する |
| 「そのSlackワークスペースは別の組織に接続されています」 | 先にその組織から切断する |
| 「アシスタントを使用するにはアカウントをリンクしてください」 | ボタンを選択してFailproof AIで確認する |
| グループダイレクトメッセージでアプリが返答しない | Slackにアプリを再度追加してグループ権限を付与する。既存の接続は維持される |
| 「あなたの組織からの回答をここには投稿しません」 | そのワークスペースにいる組織メンバーがアプリをメンションしてアカウントを紐付ける |

それでも解決しない場合は、[support@befailproof.ai](mailto:support@befailproof.ai)までメールでお問い合わせください。
