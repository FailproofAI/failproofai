---

まず以下を実行してください：

```bash
failproofai config --status
failproofai policies
```

## エージェントが接続されていない

セットアップを再実行してください：

```bash
failproofai config
```

セットアップは Linux と macOS に対応しています。サービスのインストール時に一度だけ管理者権限が必要ですが、sudo パスワードの入力を求めることはありません。

ハーネスのパスとスコープについては [Harnesses](/ja/reference/harnesses) を参照してください。

## セッションが見つからない

```bash
failproofai flush --wait
failproofai backfill --since 30d --dry-run
failproofai harness list
```

過去の履歴を再送信するには `--dry-run` を外してください。以下のコマンドでトランスクリプトの場所を追加できます：

```bash
failproofai harness add-path <harness> [label=]<path>
```

同じプロジェクトのコピーが 2 か所に存在する場合は、ラベルを使用してください。

## 保護されたアクションがすべて拒否される

設定済みのマシンでは、`failproofaid` が唯一の評価者です。応答できない場合、保護されたアクションはフェイルクローズされます。

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

`failproofai config` を実行してサービスを修復または再インストールしてください。

## 特定のパックが拒否している

`failproofai policies` を実行すると、読み込めないパックが表示されます。選択したパックは削除されずにフェイルクローズされます。

よくある原因：

- インストール後にアーティファクトが変更された。
- マニフェストとバンドルされたポリシーの内容が一致していない。
- ファイルが見つからないか、インポートできない。
- パックがサポートされていないイベント、ツール、またはポリシーの形式を使用している。

パックを削除するか、修正済みのリリースをインストールしてください：

```bash
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

## クラウドが切断されている

キーには環境変数の使用を推奨します：

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
failproofai config --status
```

マシンはポリシーの取得とアクティビティの送信を独立して行えます。ステータスにはその両方が表示されます。

## ポリシーがブロックしなかった

以下の 3 点を確認してください：

1. ポリシーが有効になっている：`failproofai policies`
2. そのイベントとツールがアクションに一致している。
3. そのハーネスがイベントを強制できる。

ツールコールの deny は、サポートされている全 12 のハーネスで検証されています。その他のイベントは異なります。[強制実行の対応状況](/ja/reference/harnesses#enforcement-capability) を参照してください。

## ダウンロードがブロックされている

- `FAILPROOFAI_NO_DOWNLOAD=1` を設定すると、ネットワークダウンロードが拒否されます。
- `FAILPROOFAI_DAEMON_BASE_URL` でサービスのダウンロード先をミラーに向けます。
- `FAILPROOFAI_PACK_BASE_URL` でパックのダウンロード先をミラーに向けます。

インストール済みのパックは、ダウンロードが無効になっていても引き続き機能します。
