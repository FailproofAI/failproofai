ダッシュボードは、保存済みクエリを組み合わせて運用ビューを構成します。利用可能なすべてのメトリクスを羅列するのではなく、意思決定を行う場面を想定して構築してください。

## ダッシュボードを作成する

<Tabs>
  <Tab title="ダッシュボード">
    1. **Analyze → Queries** に移動し、保存済みクエリを作成または開いて、その結果を検証します。
    2. **add to dashboard** を選択し、既存のダッシュボードを選ぶか、**Analyze → Dashboards** から新規作成します。
    3. ダッシュボードを開き、編集モードに入ってタイルを配置し、レイアウトを保存します。
    4. タイルの背後にあるデータやフィルターを変更したい場合は、クエリに戻って修正します。

    ![イベントボリューム、エラー、レイテンシ、モデルトークン使用量の保存済みクエリから構成されたダッシュボード。](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    ダッシュボードの CRUD 操作は現在の Cloud CLI では提供されていません。CLI を使って保存済みクエリを構築・検証し、その後 UI からダッシュボードに追加してください。

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

有用なダッシュボードグループの例：

- **Models:** ボリューム、レイテンシ、トークン使用量、エラーレート、評価スコア。
- **Evaluations:** エージェントまたは環境ごとの成功率とスコアのトレンド。
- **Tools:** 呼び出し回数、失敗率、実行時間、繰り返し呼び出し。
- **Hooks and policies:** 判定結果、拒否件数、ポリシーマッチ率。
- **Custom workflow metrics:** 独自イベントフィールドと SQL による結果。

保存済みクエリから始めて結果を検証し、タイルとして追加していきましょう。本番環境と開発環境のフィルターを明示的に設定し、テストトラフィックが回帰を隠さないようにしてください。

<Tip>
  すべてのダッシュボードにオーナーと回答すべき問いを設定しましょう。例：「checkout-agent の信頼性は先週より悪化しているか？」
</Tip>
