エラー機能は、セッション全体にわたって失敗を優先して表示するビューを提供します。エラータイプ、エージェント、環境、モデル、ツール、または時間ウィンドウでグループ化して、繰り返し発生する運用上の問題を特定できます。

## エラーを調査する

<Tabs>
  <Tab title="ダッシュボード">
    1. **Observe → Errors** に移動します。
    2. 環境、イベントタイプ、エラータイプ、エージェント、セッション ID、または検索テキストでフィルタリングします。
    3. グループ化されたエラーを展開して発生状況を確認します。行を選択すると、そのセッション内の該当イベントが表示されます。
    4. 代表的なエラーのベルコントロールを選択して、類似エラーのアラートを設定します。

    ![障害ヒストグラム、グループ化されたエラー、アラート作成コントロールが表示されたエラーページ](/images/dashboard/errors.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp errors --env production --since 24h
    fp errors --error-type TimeoutError --agent-id checkout-agent
    fp errors --aggregate --env production --since 7d
    ```

    エラーサマリーの背後にある生のペイロードが必要な場合は、`fp events --full --session-id <id>` を使用してください。
  </Tab>
</Tabs>

## エラー機能を活用する場面

- 本番環境で最も頻繁に発生するエラークラスを特定する。
- 特定のツールやモデルがスパイクの原因になっているかを判断する。
- 集計カウントから代表的なセッションにジャンプする。
- 再発に備えたアラートを作成する。
- 影響を受けた対象を監査に含める。

エラーとは観測されたイベントです。失敗した評価は品質的な判断であり、監査の所見は調査済みの障害パターンです。どのレスポンスワークフローを使用するかを決める際は、これらの区別を意識してください。
