評価は、エージェントセッションに対して一貫した判断を適用します。監査のときだけでなく、継続的に計測すべきシグナルに活用してください。

エバリュエーターは完了したセッションを受け取ります。「完了」とは、セッションが終了イベントを送出した場合、またはエバリュエーターの `inactivity_timeout_secs` を超えてイベントの送出が止まった場合を指します。実行中のセッションはスコアリングされません。

<Note>
  自動評価はデプロイメント全体に適用されますが、オペレーターが `EVALUATOR_ENDPOINT` を設定するまでは無効です。設定されるまで、このビューは空になり、`fp evals` は何も返さず、`fp sessions` はすべての行のステータスが空白になります。これは通常、エバリュエーターが設定されていないことを意味し、スコアが悪かったわけではありません。[Evaluator SDK](/ja/reference/evaluator-sdk) を参照してください。
</Note>

## 評価品質のレビュー

<Tabs>
  <Tab title="ダッシュボード">
    1. **Observe → Evaluations** に移動します。
    2. 系列を追加し、エージェント、環境、評価スコア、統計値、カーブを選択します。
    3. 環境、エージェント、またはスコアキーを比較するために系列を追加します。
    4. 結果を選択して対応するセッションを開くか、フィルタリングしたビューを共有します。レイテンシ、トークン数、コストなどの大きさに関する値には **Observe → Metrics** を使用してください。

    ![平均評価スコアと時系列のトレンドを示す品質ダッシュボード。](/images/dashboard/dashboard-quality.png)

    ドリルダウンからセッションを開くと、スコアごとの推論内容を確認できます。

    ![完全なトレースと並んで評価スコアと推論を表示するセッション詳細ビュー。](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp list score_filters
    fp evals --agent-id checkout-agent --aggregate
    fp evals --aggregate --status error --since 7d
    fp evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3 --since 7d
    fp evals --scores-full --since 24h
    ```

    ここに挙げたコマンドはすべて `evaluations:read` が必要です。`fp sessions` も同様で、これは最新の評価結果を読み取ります。そのため、`events:read` のスコープのみ持つキーでは、トレースは見えてもスコアは見えません。

    まず `fp list score_filters` を実行してください。このデプロイメントが実際に生成するスコアキーが返されるため、`--score` フィルターを推測ではなく確認に基づいて指定できます。

    `--score KEY:MIN..MAX` は各境界値を省略可能で、繰り返し指定できます。すべての範囲が同時に満たされる必要があります（例：`helpfulness:0.5..0.8`、`tool_efficiency:..0.3`、`factuality:0.9..`）。不正な値はリクエスト送信前に拒否され、暗黙的に無視されることはありません。`--status` には `done`、`error`、`timeout` のいずれか一つを指定します。`--scores-full` は最初の数件と `+N` の代わりに、すべてのスコアペアを表示します。`--all` は `--limit`（デフォルト50件）で停止します。

    グローバルオプションはコマンドの前に指定するため、自動化では `fp --json evals --aggregate` のように記述します。

    デーモンは環境を変更しない限り、すべてのイベントに `local` という環境名を付与します。そのため、標準インストールでは `--env production` には何もマッチしません。[環境ラベルの変更](/ja/reference/events-and-configuration#change-an-environment-label)を参照してください。
  </Tab>
</Tabs>

## エバリュエーターのメッセージ仕様

| メッセージ | フィールド |
| --- | --- |
| `EvalRequest`（受信） | `schema_version`（現在は `"1"`）、`session_id`、`agent_id`、`environment`、`started_at`、`ended_at`、および `events` — 完全な順序付きストリーム（各イベントは完全なペイロードを持つ）。 |
| `EvalResponse`（送信） | 数値キーの `scores`、それに対応する `reasoning`、および `summary`。 |
| `JobPending`（送信） | `job_id` と `next_poll_secs`。1リクエスト内で完了できない処理向け。 |

`ended_at` はセッションが終了イベントを送出した場合にのみ存在します。非アクティブにより配信されたセッションにはこのフィールドがありません。ポーリング間隔は `next_poll_secs`、次にエバリュエーターの `default_poll_interval_secs`、次にサーバーの `EVALUATOR_POLLING_INTERVAL_SECS` の順に従い、1秒から1時間の間にクランプされ、ウォールクロックで最大1時間となります。

リクエストには完全なイベントペイロードが含まれるため、エバリュエーターはトランスクリプトの全内容を参照できます。エバリュエーターへの配信を設計する際は、マシンがどのデータを送信してよいかを決める上でトランスクリプトの配信と同等に扱ってください。

## 評価に適した対象

- タスクの完了度または正確性
- 根拠の妥当性とハルシネーションリスク
- ツールの選択とツール効率
- ポリシーまたはプロセスへの準拠
- コストとレイテンシの予算
- 必要なヒューマンエスカレーション

スコアキーは安定した識別子です。名前を変更すると、既存の系列を変更するのではなく新しいチャート系列が開始されるため、トレンドが静かに途切れてしまいます。チャートに表示する前に名前を決めておいてください。

## スコアからレスポンスへ

トレンドを追跡するためにダッシュボードにスコアを表示します。閾値や複合条件に対してアラートを作成します。集団全体でスコアが低下した場合は監査を実施して原因を調査し、原因が再現可能なアクションであれば、ポリシーをデプロイしてください。
