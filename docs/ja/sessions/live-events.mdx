ライブイベントを使うと、計装の確認や、リスクのある実行をセッション終了を待たずにリアルタイムで監視できます。

## アクティビティの監視

<Tabs>
  <Tab title="ダッシュボード">
    1. **Observe → Events** に移動します。
    2. まず現在の時間ウィンドウとフィルターなしで開始し、データが届いていることを確認します。
    3. 環境、イベントタイプ、エージェント、またはセッションでフィルタリングします。ペイロードのテキスト検索も利用できます。
    4. イベントを選択してサマリーと詳細を確認し、セッションリンクをたどって完全なトレースを表示します。

    ![時間、環境、イベントタイプ、エージェント、モデル、コンテキスト、セッション、テキストフィルターを備えたライブイベントストリーム。](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    デフォルトのフィードでは生のペイロードは省略されます。`--full` は範囲を絞ったセッション調査の場合にのみ使用してください。
  </Tab>
</Tabs>

イベントストリームを使って、次の3つの即時的な疑問に答えましょう：

- 対象のエージェントが正しい環境にレポートしているか？
- モデル呼び出し、ツール呼び出し、ポリシー判断が順番どおりに届いているか？
- セッションが進行を停止したり、同じアクションを繰り返し始めていないか？

イベントタイプには、エージェントのライフサイクルイベント、モデルのリクエストとレスポンス、ツールの使用と結果、フックの実行、人間の待機と割り込み、そして明示的なエラーが含まれます。ツール呼び出しとその結果など、ペアになったイベントはコリレーションIDで紐付けられます。

<Tip>
  新しいインテグレーションを確認する際は、ライブビューのフィルターを広めに保ってください。最初のイベントが確認できてからフィルターを追加しましょう。誤ったフィルターを設定すると、インジェストが失敗しているように見えることがあります。
</Tip>

イベントが表示されない場合は、`failproofai config --status` を実行してから、[インジェストのトラブルシューティング](/ja/reference/troubleshooting)を参照してください。
