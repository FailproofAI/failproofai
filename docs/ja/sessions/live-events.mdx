ライブイベントを使用すると、インストゥルメンテーションの確認や、リスクの高い実行をセッション完了を待たずに監視できます。

## アクティビティの監視

<Tabs>
  <Tab title="ダッシュボード">
    1. **Observe → Events** に移動します。
    2. まず現在の時間ウィンドウでフィルターなしから開始し、データが届いていることを確認します。
    3. 環境、イベントタイプ、エージェント、セッションでフィルタリングします。ペイロードのテキスト検索も利用できます。
    4. イベントを選択してサマリーと詳細を確認します。セッションリンクをたどることでトレース全体を表示できます。

    ![HermesチャットゲートウェイからのトラフィックとコーディングCLIの実行を並べて表示し、時間・環境・イベントタイプ・エージェント・モデル・コンテキスト・セッションでフィルタリングしたライブイベントストリーム。](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    デフォルトのフィードではRAWペイロードは省略されます。`--full` は範囲を限定したセッション調査にのみ使用してください。
  </Tab>
</Tabs>

イベントストリームを活用することで、次の3つの問いにすぐ答えられます：

- 対象のエージェントが正しい環境にレポートしているか？
- モデル呼び出し、ツール呼び出し、ポリシー判定が順番どおりに届いているか？
- セッションが進行を停止したり、同じアクションを繰り返し始めたりしていないか？

イベントタイプには、エージェントライフサイクルイベント、モデルのリクエストとレスポンス、ツールの使用と結果、フック実行、ヒューマンウェイトと割り込み、明示的なエラーが含まれます。ツール呼び出しとその結果など、対になるイベントはCorrelation IDで紐付けられます。

<Tip>
  新しいインテグレーションを検証する際は、ライブビューを広い範囲で表示したままにしてください。フィルターは最初のイベントを確認してから追加しましょう。誤ったフィルターを設定すると、インジェストが失敗しているように見えてしまいます。
</Tip>

イベントが表示されない場合は、`failproofai config --status` を実行してから[インジェストのトラブルシューティング](/ja/reference/troubleshooting)を行ってください。

サポートされている12種類の[ハーネス](/ja/reference/harnesses)上で動作しないエージェントも、[Python SDK](/ja/reference/custom-agents) を通じて同じイベントタイプを報告できます。これには、ゲートウェイや本番エージェントが必要とするヒューマン・イン・ザ・ループイベント（`human_wait`、`human_input`、`human_interrupt`）も含まれます。
