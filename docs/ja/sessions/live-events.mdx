ライブイベントを使うと、インストルメンテーションの動作確認や、リスクの高い実行をセッション完了を待たずに監視できます。

## アクティビティの監視

<Tabs>
  <Tab title="ダッシュボード">
    1. **Observe → Events** に移動します。
    2. まず現在の時間ウィンドウでフィルターなしの状態から始め、データが届いていることを確認します。
    3. 環境、イベントタイプ、エージェント、またはセッションでフィルタリングします。ペイロードのテキスト検索も利用できます。
    4. イベントを選択すると、サマリーと詳細を確認できます。セッションリンクをたどると全トレースが表示されます。

    ![Hermes チャットゲートウェイとコーディング CLI 実行からのトラフィックを表示するライブイベントストリーム。時間、環境、イベントタイプ、エージェント、モデル、コンテキスト、セッションでフィルタリングされています。](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    デフォルトのフィードでは生のペイロードは省略されます。`--full` は範囲が限定されたセッションの調査時のみ使用してください。
  </Tab>
</Tabs>

イベントストリームを使って、次の3つの疑問にすぐ答えられます。

- 期待するエージェントが正しい環境に報告しているか？
- モデル呼び出し、ツール呼び出し、ポリシー判定が順番に届いているか？
- セッションが進行を停止したり、同じアクションを繰り返したりしていないか？

イベントタイプには、エージェントライフサイクルイベント、モデルのリクエストとレスポンス、ツールの使用と結果、フック実行、ヒューマンウェイトと割り込み、明示的なエラーが含まれます。ツール呼び出しとその結果など、対になるイベントはコリレーション ID で紐付けられます。

<Tip>
  新しいインテグレーションを確認する際は、ライブビューを広い範囲で表示したままにしてください。最初のイベントを確認してからフィルターを追加しましょう。誤ったフィルターを設定すると、インジェストに失敗しているように見えてしまいます。
</Tip>

イベントが表示されない場合は、`failproofai config --status` を実行してから、[インジェストのトラブルシューティング](/ja/reference/troubleshooting)を参照してください。

サポートされている12種類の[ハーネス](/ja/reference/harnesses)のいずれかで実行されないエージェントも、[Python SDK](/ja/reference/custom-agents) を通じて同じイベントタイプを報告します。ゲートウェイや本番環境のエージェントが依存するヒューマンインザループイベント（`human_wait`、`human_input`、`human_interrupt`）も含まれます。
