ライブイベントを使用すると、インストルメンテーションの確認や、リスクのある実行をセッション終了を待たずに監視できます。

## アクティビティの監視

<Tabs>
  <Tab title="ダッシュボード">
    1. **Observe → Events** に移動します。
    2. 現在の時間ウィンドウでフィルターなしから始め、データが届いていることを確認します。
    3. 環境、イベントタイプ、エージェント、またはセッションでフィルタリングします。ペイロードテキストの検索にはサーチを使用してください。
    4. イベントを選択して概要と詳細を確認します。セッションリンクをたどると完全なトレースが表示されます。

    ![Hermes チャットゲートウェイのトラフィックとコーディング CLI の実行をリアルタイムで表示するイベントストリーム。時間、環境、イベントタイプ、エージェント、モデル、コンテキスト、セッションでフィルタリング可能。](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    デフォルトのフィードでは生のペイロードは省略されます。`--full` は範囲を限定したセッション調査のみに使用してください。
  </Tab>
</Tabs>

イベントストリームを使用して、次の3つの即時的な疑問に答えられます。

- 期待されるエージェントが正しい環境に報告しているか？
- モデル呼び出し、ツール呼び出し、ポリシー決定が順番に届いているか？
- セッションが進行を停止したり、同じアクションを繰り返し始めていないか？

イベントタイプには、エージェントのライフサイクルイベント、モデルのリクエストとレスポンス、ツールの使用と結果、フックの実行、ヒューマンウェイトと割り込み、明示的なエラーが含まれます。ツール呼び出しとその結果などのペアイベントは相関IDで紐付けられます。

<Tip>
  新しいインテグレーションを検証する際は、ライブビューを広い範囲で表示したままにしてください。最初のイベントを確認してからフィルターを追加してください。誤ったフィルターはインジェスションの失敗と見分けがつかないことがあります。
</Tip>

イベントが表示されない場合は、`failproofai config --status` を実行してから、[インジェスションのトラブルシューティング](/ja/reference/troubleshooting)を参照してください。

サポートされている12種類の[ハーネス](/ja/reference/harnesses)のいずれかで実行されないエージェントも、[Python SDK](/ja/reference/custom-agents) を通じて同じイベントタイプを報告します。ゲートウェイや本番エージェントが依存するヒューマン・イン・ザ・ループイベント（`human_wait`、`human_input`、`human_interrupt`）も含まれます。
