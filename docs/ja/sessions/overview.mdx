セッションは、エージェントが予期しない動作をした際の最適な調査起点です。1回の実行に属するモデルのリクエスト・レスポンス、ツール呼び出し、人間とのインタラクション、エラー、評価、ポリシー判定をまとめて確認できます。

セッションの表示形式は、どのハーネスで生成されたかに関わらず統一されています。リポジトリを書き換える Claude Code の実行、Slack で顧客に回答する Hermes エージェント、SDK でインストルメントされた Python サービスのいずれも、同じトレース形式で記録されるため、1つのビューでフリート全体をカバーできます。

エージェントの1回の実行を、ゴールからモデル呼び出し、ツール、最終レスポンスまで追跡できます。

## セッションを探す

<Tabs>
  <Tab title="ダッシュボード">
    1. クラウドのサイドバーで **Observe → Sessions** に移動します。
    2. 時間範囲を設定し、環境・ステータス・エージェント・セッション ID でフィルタリングします。
    3. 品質・コスト・トークン・レイテンシのスライスが必要な場合は、スコアやメトリクスの範囲を追加します。
    4. 行を選択してトレースを開きます。セッション ID の横にあるコピーコントロールを使って共有できます。

    ![環境・エージェント・ステータス・評価スコアのフィルターとともに、実行ごとに1行表示されるセッションリスト。](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    `--agents` でマルチエージェント実行を展開、`--all` でページネーション、`--fields` で出力カラムを選択できます。
  </Tab>
</Tabs>

## できること

- エージェント・環境・時間・モデル・イベントタイプ・エラー状態で実行を検索する。
- ある結果を生み出した正確なシーケンスを追跡する。
- 成功した実行と失敗した実行を比較する。
- 監査の発見事項やアラートインシデントで使用された証拠を開く。
- オフラインの記録が必要な場合にセッションをエクスポートする。

## 信頼性の高い調査手順

1. セッションのゴールと環境を確認する。
2. 最終的な失敗だけでなく、最初のエラーや予期しない判断を特定する。
3. その直前のモデルコンテキストとツールの入力を確認する。
4. リトライ・レイテンシ・人間による割り込みを確認する。
5. 評価スコアとポリシー判定をレビューする。
