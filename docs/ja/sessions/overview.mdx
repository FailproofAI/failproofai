セッションは、エージェントが予期しない動作をしたときの最良の出発点です。モデルリクエスト、レスポンス、ツール呼び出し、人間との対話、エラー、評価、ポリシー決定を一つのランとしてまとめて表示します。

セッションは、どのハーネスで生成されたかに関わらず同じ形式で表示されます。リポジトリを書き換える Claude Code の実行、Slack でカスタマーに回答する Hermes エージェント、SDK でインストゥルメント化された Python サービスはすべて同じトレース形式に収まるため、一つのビューでフリート全体を把握できます。

一つのエージェント実行を、ゴールからモデル呼び出し、ツール、最終レスポンスまで追跡します。

## セッションを探す

実行数の上限に達した後にセッションがコールドストレージに保存されていた場合、同じ請求期間内に上限を引き上げると、対象のセッションが古い順にリリースされます。配信の再試行によってセッションの消費カウントが二重になることはありません。

<Tabs>
  <Tab title="ダッシュボード">
    1. Cloud サイドバーで **Observe → Sessions** に移動します。
    2. 時間ウィンドウを設定し、環境、ステータス、エージェント、またはセッション ID でフィルタリングします。
    3. 品質、コスト、トークン、レイテンシのスライスが必要な場合は、スコアやメトリクスの範囲を追加します。
    4. 行を選択してトレースを開きます。共有する際はセッション ID の横にあるコピーコントロールを使用します。

    ![環境、エージェント、ステータス、評価スコアのフィルターとともに、実行ごとに一行表示されるセッションリスト。](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    マルチエージェント実行を展開するには `--agents`、ページネーションするには `--all`、出力カラムを選択するには `--fields` を追加します。
  </Tab>
</Tabs>

## できること

- エージェント、環境、時間、モデル、イベントタイプ、またはエラー状態で実行を検索する。
- 特定の結果を生み出した正確なシーケンスを追跡する。
- 成功した実行と失敗した実行を比較する。
- 監査の発見やアラートインシデントで使用されたエビデンスを開く。
- オフラインの記録が必要な場合はセッションをエクスポートする。

## 信頼性の高い調査手順

1. セッションのゴールと環境を確認する。
2. 最終的な失敗だけでなく、最初のエラーや予期しない判断を見つける。
3. その直前のモデルコンテキストとツール入力を検査する。
4. 再試行、レイテンシ、人間の介入を確認する。
5. 評価スコアとポリシー決定をレビューする。
