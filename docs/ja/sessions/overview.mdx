セッションとは、エージェントの1回の実行を指します。プロンプト、モデル呼び出し、ツール、エラー、人間の入力、ポリシーの決定、そして最終的な結果を一連でつなぎます。

## セッションの保存場所

<Tabs>
  <Tab title="ローカル">
    `failproofai` を実行すると、`http://localhost:8020` でダッシュボードが開きます。セッション履歴はこのマシン上に保存されます。
  </Tab>
  <Tab title="クラウド">
    マシンを接続してから、**Observe → Sessions** を開きます。

    ```bash
    export FAILPROOFAI_CLOUD_TOKEN="<key>"
    failproofai config
    ```

    クラウドはデフォルトで完全なトランスクリプトを受信します。ポリシーの決定のみを送信するには、まず接続してから `~/.failproofai/config.json` の `collector.sessions` を `false` に設定してください。現在の `--no-transcripts` セットアップフラグでは、この設定は適用されません。
  </Tab>
</Tabs>

セッションは、12のサポート対象[エージェントハーネス](/ja/reference/harnesses)と[Python SDK](/ja/reference/custom-agents)でインストゥルメント化されたエージェントから取得されます。

## セッションを検索する

クラウドでは、時刻、環境、ステータス、エージェント、またはセッションIDでフィルタリングできます。CLIからの場合：

```bash
fp sessions --since 24h
fp sessions --status error,timeout --agent-id checkout-agent
fp --json sessions --session-id <session-id>
```

評価されなかった失敗には `fp errors --since 24h` を使用してください。`fp sessions --status` は最新の評価結果を使用するため、未評価のセッションにはステータスがありません。

## 実行内容を読む

1. エージェントのゴールと環境を確認します。
2. 最初のエラーまたは予期しない決定を見つけます。
3. その直前のモデルコンテキストとツールの入力を調べます。
4. リトライ、レイテンシ、人間による中断を確認します。
5. 評価とポリシーの決定をレビューします。

## セッションが見つからない場合

```bash
failproofai flush --wait
failproofai config --status
failproofai backfill --since 30d --dry-run
```

別のプロファイル、コンテナのホーム、またはマウントされたチームディレクトリなど、セッションがハーネスの通常の場所以外に存在する場合は、`failproofai harness add-path <harness> [<label>=]<path>` を使用してください。
