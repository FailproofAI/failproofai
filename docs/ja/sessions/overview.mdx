セッションは、エージェントが予期しない動作をした際の最良の出発点です。1回の実行に属するモデルへのリクエスト、レスポンス、ツール呼び出し、人間との対話、エラー、評価、ポリシー決定を一か所に集約します。

セッションの表示形式は、どのハーネスが生成したかに関わらず統一されています。リポジトリを書き換える Claude Code の実行、Slack で顧客対応する Hermes エージェント、SDK でインストルメントされた Python サービス——いずれも同じトレース形式に格納されるため、1つのビューでフリート全体を把握できます。

エージェントの1回の実行を、目標設定からモデル呼び出し、ツール利用、最終レスポンスまで追跡します。

## セッションを見つける

<Tabs>
  <Tab title="ダッシュボード">
    1. Cloud サイドバーで **Observe → Sessions** に移動します。
    2. 時間ウィンドウを設定し、環境・ステータス・エージェント・セッション ID でフィルタリングします。
    3. 品質・コスト・トークン・レイテンシで絞り込む場合は、スコアやメトリクスの範囲を追加します。
    4. 行を選択してトレースを開きます。セッション ID の横にあるコピーコントロールを使って共有できます。

    ![環境・エージェント・ステータス・評価スコアのフィルターとともに、1行1実行で表示されたセッション一覧。](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    `--agents` でマルチエージェント実行を展開、`--all` でページネーション、`--fields` で出力カラムを選択できます。
  </Tab>
</Tabs>

## できること

- エージェント・環境・時間・モデル・イベント種別・エラー状態でセッションを検索する。
- ある結果を生んだ正確な処理シーケンスを追跡する。
- 成功した実行と失敗した実行を比較する。
- 監査の発見事項やアラートインシデントで使用された証拠を開く。
- オフライン記録が必要な場合にセッションをエクスポートする。

## 信頼できる調査の順序

1. セッションの目標と環境を確認する。
2. 最終的な失敗だけでなく、最初のエラーや予期しない判断を見つける。
3. その直前のモデルコンテキストとツール入力を調べる。
4. リトライ・レイテンシ・人間による割り込みを確認する。
5. 評価スコアとポリシー決定をレビューする。
