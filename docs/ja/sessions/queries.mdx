クエリは、ダッシュボード・監査・調査の基盤となる柔軟なレイヤーです。アドホックな SQL でアイデアを検証し、定期的なワークフローの一部になったらクエリを保存しましょう。

## クエリの作成と実行

<Tabs>
  <Tab title="ダッシュボード">
    1. **Analyze → Queries** に移動し、**new query** を選択します。
    2. スキーマブラウザを開き、イベント・セッション・評価データからフィールドを選択します。
    3. SQL を記述し、必要に応じてパラメータを追加してクエリを実行します。
    4. わかりやすい名前と説明を付けて保存し、結果をモニタリングする場合は **add to dashboard** を使用します。

    クエリエディタには、イベントスキーマ・SQL・パラメータ・結果プレビューが一体化されており、保存前に問いを検証できます。

    ![スキーマブラウザとライブ結果グリッドを備えた SQL クエリエディタ。](/images/dashboard/query-lab.png)

    保存したクエリは共有ライブラリに表示され、チームメンバーが再実行したり、結果をダッシュボードに追加したりできます。

    ![再利用可能な組み込みクエリとカスタムクエリを収録した保存済みクエリライブラリ。](/images/dashboard/queries.png)

    SQL を開き直さなくても結果が理解できるよう、わかりやすい名前と説明を付けてください。
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    `fp query list` で ID を確認し、`fp query delete <query-id>` で保存済みクエリを削除できます。
  </Tab>
</Tabs>

## 主な使用例

- 同じツールへの呼び出しが繰り返されているセッションを検索する。
- モデルや環境をまたいで評価スコアを比較する。
- ヒューマンウェイトと再開の間の経過時間を計測する。
- ポリシーによる拒否の後に成功した代替手段を特定する。
- 監査用のコホートを作成する。

不慣れなフィールドに対してクエリを書く前に、**Queries → Schema** を確認してください。時間と環境のフィルタは明示的に指定し、探索中は結果件数の上限を設けることを推奨します。

<Warning>
  クエリは疑わしいパターンを特定できますが、それだけで障害モードが確定するわけではありません。結果をポリシーに反映する前に、代表的なトレースを開くか監査を実施してください。
</Warning>
