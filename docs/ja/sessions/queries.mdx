クエリは、ダッシュボード・監査・調査を支える柔軟なレイヤーです。アドホック SQL でアイデアを検証し、定期的なワークフローの一部になったらクエリを保存してください。

## クエリの作成と実行

<Tabs>
  <Tab title="ダッシュボード">
    1. **Analyze → Queries** を開き、**new query** を選択します。
    2. スキーマブラウザを開き、イベント・セッション・評価データからフィールドを選択します。
    3. SQL を記述し、必要に応じてパラメータを追加してクエリを実行します。
    4. わかりやすい名前と説明を付けて保存し、結果をモニタリングしたい場合は **add to dashboard** を使用します。

    クエリエディタにはイベントスキーマ、SQL、パラメータ、結果プレビューが一体化されており、保存前に問いを検証できます。

    ![スキーマブラウザとライブ結果グリッドを備えた SQL クエリエディタ。](/images/dashboard/query-lab.png)

    保存されたクエリは共有ライブラリに表示され、チームメンバーが再実行したりダッシュボードに結果を追加したりできます。

    ![再利用可能な組み込みクエリとカスタムクエリを含む保存済みクエリライブラリ。](/images/dashboard/queries.png)

    SQL を開き直さなくても結果が理解できるよう、わかりやすい名前と説明を付けてください。
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    IDを調べるには `fp query list` を、保存済みクエリを削除するには `fp query delete <query-id>` を使用します。
  </Tab>
</Tabs>

## 主な用途

- 同じツールへの繰り返し呼び出しが含まれるセッションを検索する。
- モデルや環境をまたいで評価スコアを比較する。
- 人間の待機から再開までの時間を計測する。
- ポリシーによる拒否の後に成功した代替手段が取られたケースを特定する。
- 監査のためのコホートを作成する。

未知のフィールドに対してクエリを書く前に **Queries → Schema** を開いてください。時間や環境のフィルタは明示的に指定し、探索中は結果件数の上限を設定することをお勧めします。

<Warning>
  クエリは疑わしいパターンを特定できますが、それだけで障害モードを確定することはできません。結果をポリシーに反映する前に、代表的なトレースを開くか監査を実行してください。
</Warning>
