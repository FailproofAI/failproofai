Jevは、エージェントに送られた各メッセージを4つの感情について0〜100でスコアリングします。**怒り（angry）**、**フラストレーション（frustrated）**、**満足（happy）**、**混乱（confused）** の4つに加えて、エージェントのパフォーマンスを示す3つのシグナルも評価します。

- **Correcting（訂正）**: エージェントが誤っていると指摘している。
- **Resolved（解決）**: エージェントが問題を解決したことを確認している。
- **Doubtful（疑念）**: エージェントの回答が正しいか、または実際に作業が完了しているかを疑問視している。

センチメント分析を活用することで、ユーザーが我慢の限界に近づいている会話、繰り返し訂正が入るエージェント、うまく機能している返答などを発見できます。これはJevに組み込まれたスコアリング機能であり、エバリュエーションを自分で作成する必要はありません。独自の固定回答式の質問については、[Jev evalを作成する](/ja/evaluations/jev)を参照してください。

<Note>
  センチメント分析は、管理者が組織向けに有効化するまでオフになっています。Jevはメッセージごとに1件のスコアリングリクエストを実行し、そのメッセージとその直前のエージェント返答を受け取ります。スコアリングには組織のモデル予算が使用されます。
</Note>

## 有効化する

1. **Administration → Settings** に移動します。
2. **Human input sentiment** の下にあるスイッチを **オン** にして保存します。

最初に直近1日分のメッセージがスコアリングされます。その後、新しいメッセージは到着から1〜2分以内にスコアリングされます。

## レビューする会話を見つける

**Observe → Sentiment** を開きます。期間、環境、エージェント、セッションIDでフィルタリングできます。ヘッダーにはメッセージ数とセッション数が表示され、**フラグが付いた** メッセージの数と上位シグナルも確認できます。angry、frustrated、correcting、confused、またはdoubtfulのスコアが100点中35点に達すると、そのメッセージにフラグが立てられます。

![メッセージ数・セッション数、フラグ付きメッセージ、時系列のJevスコアを表示するSentimentダッシュボード。](/images/dashboard/sentiment-overview.png)

**Score over time** を使ってシグナルを比較します。表示するスコアを選択し、任意のポイントをクリックすると、その時間帯のメッセージを確認できます。**By agent** テーブルでは、特定のシグナルがどのエージェントに集中しているかがわかります。**Messages** では、最もスコアの高いネガティブなものから並べ替えたり、個別のスコアで絞り込んだりできます。セッション内でメッセージを開くと、前後の会話の流れを読んでから何が問題だったかを判断できます。

![最も強いネガティブスコア順に並んだSentimentメッセージリスト。各メッセージにはソースセッションへのリンクが表示されている。](/images/dashboard/sentiment-messages.png)

## スコアリング対象のメッセージ

ユーザーが入力したメッセージのみが対象です。

- SDKを使ってカスタムエージェントがヒューマン入力として記録したメッセージ。
- Claude Code、Codex、OpenCode、pi、Hermes、OpenClawに入力されたプロンプト（セッションのトランスクリプト送信がデフォルトで有効な場合）。スケジュールジョブ、注入された指示、サブエージェントへのハンドオフ、エージェントのランタイム自体が書いたテキストはスコアリングされません。また、`claude -p`、`codex exec`、`hermes -z` などの非インタラクティブな実行も対象外です。これらのプロンプトはスクリプトが生成したものであり、人間が入力したものではないためです。

スコアリングはユーザー自身の言葉を評価します。「fix it」のような短くぶっきらぼうな指示は怒りとはみなされず、質問することは混乱とはみなされません。新しいリクエストは訂正とはみなされず、感謝の言葉だけでは解決済みとはみなされません。
