Jev は、エージェントに送られた各メッセージに対して、4 つの感情スコアを 0〜100 で付与します。対象となるのは **angry（怒り）**、**frustrated（苛立ち）**、**happy（満足）**、**confused（混乱）** の 4 つです。さらに、エージェントのパフォーマンスに関する 3 つのシグナルも計測します：

- **Correcting（訂正）**: ユーザーがエージェントの誤りを指摘している。
- **Resolved（解決）**: ユーザーが問題の解決を確認している。
- **Doubtful（疑念）**: ユーザーがエージェントの回答の正確さや、作業の完了を疑っている。

センチメント分析を活用することで、ユーザーが我慢の限界に達している会話、エージェントへの訂正が繰り返されているケース、反応の良い返答などを発見できます。これは Jev の組み込みスコアリング機能であり、評価を自作する必要はありません。独自の固定回答質問に使用する場合は、[Jev eval を作成](/ja/evaluations/jev)してください。

<Note>
  センチメント機能は、管理者が組織向けに有効化するまでオフになっています。Jev はメッセージごとに 1 件のスコアリングリクエストを実行し、そのメッセージとその直前のエージェント返答を受け取ります。スコアリングには組織のモデル予算が使用されます。
</Note>

## 有効化する方法

1. **Administration → Settings** に移動します。
2. **Human input sentiment** の項目でスイッチを **オン** にして保存します。

最初に直近 1 日分のメッセージがスコアリングされます。その後、新着メッセージは到着から 1〜2 分以内にスコアリングされます。

## レビューする会話を見つける

**Observe → Sentiment** を開きます。時間、環境、エージェント、またはセッション ID でフィルタリングできます。ヘッダーにはメッセージ数とセッション数が表示され、**フラグの立ったメッセージ**の件数とトップシグナルが確認できます。angry、frustrated、correcting、confused、または doubtful のスコアが 100 点満点中 35 点に達すると、そのメッセージにフラグが立てられます。

![メッセージ数・セッション数、フラグ付きメッセージ、時系列の Jev スコアを表示したセンチメントダッシュボード。](/images/dashboard/sentiment-overview.png)

**Score over time** を使ってシグナルを比較できます。表示するスコアを選択し、グラフ上のポイントをクリックすると、その時間帯のメッセージを確認できます。**By agent** テーブルでは、シグナルが集中しているエージェントを把握できます。**Messages** では、最も強いネガティブスコア順に並べ替えたり、特定のスコアだけを絞り込んだりできます。セッション内でメッセージを開くと、その周辺の会話を読み、何が問題だったかを判断できます。

![最も強いネガティブスコア順に並べ替えられたセンチメントメッセージ一覧。各メッセージにはソースセッションへのリンクが表示されます。](/images/dashboard/sentiment-messages.png)

## スコアリング対象のメッセージ

スコアリングされるのは、人間が入力したメッセージのみです：

- SDK を使ってカスタムエージェントが human input として記録したメッセージ。
- Claude Code、Codex、OpenCode、pi、Hermes、OpenClaw にタイプされたプロンプト（セッションのトランスクリプト送信がデフォルトで有効な場合）。ただし、スケジュールされたジョブ、注入された指示、サブエージェントへのハンドオフ、エージェントのランタイム自体が書き込んだテキストはスコアリング対象外です。また、`claude -p`、`codex exec`、`hermes -z` のような非インタラクティブな実行も対象外です。これらのプロンプトはスクリプトが生成したものであり、人間が入力したものではないためです。

スコアリングはユーザー自身の言葉を評価します。「fix it」のような短く率直な指示は怒りとはみなされず、質問は混乱とはみなされません。新しいリクエストは訂正には当たらず、感謝の言葉だけでは解決済みとはカウントされません。
