| コンセプト | 意味 | 達成できること |
| --- | --- | --- |
| Session | エージェントの1つのタスクまたは実行 | 個別の結果を再構築する |
| Event | セッション内に記録された1つのアクション | モデル呼び出し、ツール使用、エラー、人間のアクション、またはポリシー判断を検査する |
| Trace | 順序付けられ入れ子になったセッションビュー | 分断されたログを読む代わりに因果関係を把握する |
| Evaluation | セッションに対するスコアまたは判断 | 品質、コンプライアンス、コスト、またはレイテンシを継続的に追跡する |
| Audit | 選択したセッション母集団のレビュー | 目的とサイクルを定めて障害パターンを探索する |
| Finding | 監査によって発見された証拠に基づく障害 | 障害モード、重大度、および影響を受けるセッションを確認する |
| Issue | 永続的な対応記録 | 発見事項またはアラートインシデントを割り当て、議論し、解決する |
| Alert | 再発を検知するルール | 既知の条件が再現したときに対応者へ通知する |
| Policy | エージェントの活動中に評価されるルール | リスクのある動作を観察、ブロック、またはリダイレクトする |
| Deployment | マシンへのバージョン管理されたポリシーのロールアウト | ポリシーの実行場所を制御し、安全にロールバックする |

## 信頼性ループ

証拠から始めます。セッションは何が起きたかを示します。監査は、それが単発のミスかパターンかを判断します。Finding は障害モードを特定し、Issue が対応を担います。Policy は同じ動作を防ぎ、Alert はその条件が再発した場合に通知します。

<Warning>
  ローカルの `failproofai audit` はローカルのエージェント履歴をスキャンします。定期的なクラウド監査は Failproof AI Cloud に保存されたセッションをレビューします。これらはスコープとスケジュールが異なる独立したワークフローです。
</Warning>
