| コンセプト | 意味 | 実現できること |
| --- | --- | --- |
| Session | 1つのエージェントタスクまたは実行 | 個々の結果を再構築する |
| Event | セッション内で記録された1つのアクション | モデル呼び出し、ツール使用、エラー、人間のアクション、またはポリシー決定を検査する |
| Trace | 順序付けられネストされたセッションビュー | 断片化したログを読む代わりに因果関係を理解する |
| Evaluation | セッションに対するスコアまたは判断 | 品質、コンプライアンス、コスト、またはレイテンシを継続的に追跡する |
| Audit | 選択されたセッション集合のレビュー | 目的とスケジュールを定めて障害パターンを検索する |
| Finding | 監査によって発見された証拠に基づく障害 | 障害モード、深刻度、および影響を受けたセッションを確認する |
| Issue | 永続的な対応記録 | Finding またはアラートインシデントを割り当て、議論し、解決する |
| Alert | 再発を検知するルール | 既知の条件が再発したとき担当者に通知する |
| Policy | エージェントの活動中に評価されるルール | リスクのある動作を観察、ブロック、またはリダイレクトする |
| Deployment | マシンへのバージョン管理されたポリシーのロールアウト | ポリシーを実行する場所を制御し、安全にロールバックする |

## 信頼性ループ

証拠から始めます。セッションは何が起きたかを示します。監査は、それが孤立したミスかパターンかを判断します。Finding は障害モードを特定し、Issue が対応を担います。Policy は同じ動作を防ぎ、Alert は条件が再発した場合に通知します。

<Warning>
  ローカルの `failproofai audit` はローカルのエージェント履歴をスキャンします。定期的な Cloud 監査は Failproof AI Cloud に保存されたセッションをレビューします。これらはスコープとスケジューリングが異なる、別々のワークフローです。
</Warning>
