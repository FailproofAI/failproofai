| コンセプト | 意味 | 達成できること |
| --- | --- | --- |
| Session | 1 つのエージェントタスクまたは実行 | 個々の結果を再構築する |
| Event | セッション内で記録された 1 つのアクション | モデルの呼び出し、ツールの使用、エラー、人のアクション、またはポリシーの決定を検査する |
| Trace | 順序付けられネストされたセッションビュー | 分断されたログを読む代わりに因果関係を理解する |
| Evaluation | セッションに対するスコアまたは判定 | 品質、コンプライアンス、コスト、またはレイテンシを継続的に追跡する |
| Audit | 選択されたセッション集合のレビュー | 目的とケイデンスを明示してエラーパターンを検索する |
| Finding | 監査によって発見された証拠に基づく障害 | 障害モード、重大度、および影響を受けたセッションを確認する |
| Issue | 永続的な対応レコード | 発見した問題やアラートインシデントをアサイン・議論・解決する |
| Alert | 再発を検出するルール | 既知の状態が再び発生したときに担当者へ通知する |
| Policy | エージェントのアクティビティ中に評価されるルール | リスクのある動作を観察、ブロック、またはリダイレクトする |
| Deployment | マシンへのバージョン管理されたポリシーのロールアウト | ポリシーが実行される場所を制御し、安全にロールバックする |

## 信頼性ループ

証拠から始めます。セッションは何が起きたかを示します。監査はそれが孤立したミスなのかパターンなのかを判断します。Finding は障害モードを特定し、Issue が対応を担います。Policy は同じ動作を防ぎ、Alert はその状態が再発したときに通知します。

<Warning>
  ローカルの `failproofai audit` はローカルのエージェント履歴をスキャンします。定期的なクラウド監査は Failproof AI Cloud に保存されたセッションをレビューします。これらはスコープとスケジューリングが異なる別々のワークフローです。
</Warning>
