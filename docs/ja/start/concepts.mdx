Failproof AI はエージェントの行動を記録し、何を許可するかを決定します。

## 観察

| 用語 | 意味 |
| --- | --- |
| Session | エージェントの1回の実行 |
| Event | セッション内の1つのアクション |
| Trace | セッションの時系列ビュー |
| Evaluation | スコアまたは判定 |
| Audit | 複数セッションのレビュー |
| Finding | 障害パターンの証拠 |
| Issue | 担当者が対応する事象 |
| Alert | 再発を検知するルール |

## 適用

| 用語 | 意味 |
| --- | --- |
| Harness | エージェントが実行される環境 |
| Hook | ハーネスが判断を求めるポイント |
| Policy | 許可・誘導・ブロックするルール |
| Policy pack | 誰でもインストールできるバージョン管理されたポリシーセット |
| Daemon | ポリシーを評価するローカルサービス |
| Deployment | マシンに割り当てられたポリシー |

## ワークフロー

```text
Session → Audit → Finding → Issue → Policy
```

証拠から始めます。繰り返し発生する障害を特定し、対応を割り当て、再発を防止します。

ポリシーは `allow`、`instruct`、または `deny` を返します。`instruct` によるガイダンスはハーネスに依存します。アクションを停止させる必要がある場合は `deny` を使用してください。

観察モードは判断とは独立しています。実際のポリシーを実行して結果を記録しながら、エージェントの処理は継続させます。

<Warning>
  `fp fleet deploy <machine> --add <policy>` を単独で実行すると即座に適用されます。シャドウロールアウトには `:observe` を追加してください。
</Warning>

セットアップではポリシーパックは選択されません。追加するまでは `block-failproofai-commands` のみが実行されます。コンパイル済みカタログには9カテゴリにわたる39のポリシーが含まれています。

すべてのエージェント環境でイベントをブロックできると仮定する前に、[サポートされているハーネス](/ja/reference/harnesses#enforcement-capability)を確認してください。
