---
title: "最初の失敗チェックを実行する"
description: "Cloud ダッシュボードまたは fp CLI からオーディットを作成し、最初の検出結果を確認します。"
icon: "scan-search"
---

オーディットはセッションの集合をランク付きの証拠付き失敗検出結果に変換します。まず一つの絞り込んだ失敗の問いから始めましょう。

<Tabs>
  <Tab title="ダッシュボード">
    <Steps>
      <Step title="オーディットを開く">
        Cloud サイドバーで **Analyze → Audits** に移動し、**new audit** を選択します。
      </Step>
      <Step title="オーディットを設定する">
        名前と直接的な失敗目標を入力します。例えば「入力を変更したりエスカレーションしたりせずに同じ失敗した支払い呼び出しを再試行している本番セッションを見つける」などです。エージェント、環境、時間ウィンドウ、スケジュールを選択します。オーディターがワークフロールールを必要とする場合は、簡単なブリーフと参照 URL を追加してください。
      </Step>
      <Step title="作成して実行を待つ">
        **create audit** を選択します。最初の実行はすぐにキューに入ります。オーディットカードを開いて、queued → running → complete と進む様子を確認します。
      </Step>
    </Steps>

    実行が完了したら、検出結果を開いてそのセッション証拠を確認します。その後、承認・割り当て・却下・ミュート・解決のいずれかのアクションを取ることができます。

    ![完了したオーディット検出結果。失敗の説明、推奨アクション、裏付け証拠、影響を受けたセッションが表示されています。](/images/dashboard/audit-finding.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits create payment-retry-failures \
      --description "Find production sessions that retry a failed payment call without changing input or escalating" \
      --scope '{"environments":["production"]}' \
      --text "Escalate after two unchanged payment failures"

    fp audits list
    fp audits runs payment-retry-failures
    fp audits findings --audit payment-retry-failures
    fp audits finding <finding-id>
    ```

    参照コンテキストを追加し、ソースが変更されたときに更新します：

    ```bash
    fp audits context-set payment-retry-failures --url https://example.com/payment-runbook
    fp audits context-refresh payment-retry-failures
    fp audits run payment-retry-failures
    ```

    `fp audits ack <finding-id>`、`fp audits assign <finding-id> --to <email>`、`fp audits dismiss <finding-id>`、`fp audits mute <finding-id>`、`fp audits resolve <finding-id>`、または `fp audits reopen <finding-id>` を使用して、検出結果をトリアージのフローに沿って進めます。
  </Tab>
</Tabs>

次は、確認済みの再現可能なアクションに対して[最初の失敗をポリシーで防ぐ](/ja/start/first-policy)に進みましょう。
