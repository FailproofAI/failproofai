---
title: "ポリシーで最初の障害を防ぐ"
description: "ポリシーのバージョンを作成し、observeモードでデプロイしてから、適用します。"
icon: "shield-check"
---

安全でない操作と、引き続き許可する必要がある正当な操作を明確に説明できるようになってから、ポリシーを使用してください。

<Tabs>
  <Tab title="ダッシュボード">
    <Steps>
      <Step title="ポリシーを作成する">
        **Admin → policy editor** に移動します。デモポリシーから始め、ソースを確認または編集してから **publish version** を選択します。公開すると、マシンにデプロイできる不変のバージョンが作成されます。

        ![公開準備が整ったデモポリシーが表示されたPolicy editorの作成画面。](/images/dashboard/policy-editor.png)
      </Step>
      <Step title="マシンにデプロイする">
        **Admin → enforcement** に移動し、対象のマシンを展開して **edit this machine** を選択します。公開済みのデモポリシーを追加し、バージョンを固定して **observe** を選択してから、デプロイを適用します。

        ![デプロイ適用前にobserveモードで公開済みポリシーバージョンが選択されたマシンデプロイメントエディタ。](/images/dashboard/enforcement-editor.png)
      </Step>
      <Step title="ポリシーを検証する">
        そのマシンで新しいエージェントセッションを実行し、**Observe → policy** を開きます。マシンを選択し、デモポリシーがポリシーマッピングと決定タイムラインに表示されていることを確認します。observeモードでは、操作をブロックせずにポリシーが行う動作を記録します。

        ![決定の合計、時系列での適用アクティビティ、ローカルおよびクラウド管理のポリシーマッピングを表示するPolicyページ。](/images/dashboard/policy-observe.png)
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    クラウドポリシーの作成とフリートデプロイメントは管理者向けのワークフローです。ローカルCLIを使用して、公開前に同じポリシーを検証してください。

    ```bash
    failproofai policies --install --custom ./payment-retry.policies.ts \
      --cli claude --scope project
    failproofai config --status
    ```

    `fp` を使用して、クラウドで確認できるポリシーの決定を検査します。

    ```bash
    fp events --event-type hook_completed --env production --since 24h
    fp sessions --env production --since 24h
    ```

    どちらの手順もCLIから実行できます。`fp policies publish <id> <file>` でバージョンを作成し、`fp fleet deploy <machine-id> --add <id>` でマシンに適用します。ダッシュボードでは、これらに相当する操作が **Admin → policy editor** と **Admin → enforcement** から行えます。
  </Tab>
</Tabs>
