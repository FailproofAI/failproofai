エージェントはすでに記録する価値のあるすべてのものを生成しています — モデル呼び出し、ツール呼び出し、ノード境界、人間の待機、失敗など。フレームワークはそれを捨ててしまいますが、SDKは保持します。

## 始める前に

このパスが前提とする2つの事項（以下のコードでは対応されません）：

| 要件 | 理由 |
| --- | --- |
| Python 3.10 以上 | SDK が宣言する最低バージョン。 |
| `failproofai config` でセットアップ済みのマシン | このコマンドは failproofaid デーモンをインストールします。SDKが書き込んだデータを送信するのはデーモンだけです。デーモンがなければ、バッチはスプールディレクトリに溜まるだけで送信されません。 |

<Note>
  **このパスは記録するものであり、強制するものではありません。** SDKはエージェントの動作をキャプチャします。ポリシーはエージェント CLI 内のフックから実行されるため、フレームワークエージェントに強制を適用するには自分のランタイムにフックを追加する必要があります — [ポリシー](/ja/policies/overview) を参照してください。
</Note>

## どのフレームワークでも3行で

<CodeGroup>
```bash LangGraph
pip install 'failproofai-sdk[langgraph]'
```

```bash CrewAI
pip install 'failproofai-sdk[crewai]'
```

```bash LlamaIndex
pip install 'failproofai-sdk[llamaindex]'
```

```bash Pydantic AI
pip install 'failproofai-sdk[pydantic-ai]'
```

```bash Custom agents
pip install failproofai-sdk
```
</CodeGroup>

```python
import failproofai_sdk

failproofai_sdk.configure(environment="production")
failproofai_sdk.instrument()          # インポートしたフレームワークを自動検出

with failproofai_sdk.session():
    ...                               # 既存のエージェント呼び出し（変更不要）
```

関数へのデコレーター、呼び出しへのコールバックの追加、コード全体へのID埋め込みは一切不要です。変わるのはセッション内の呼び出しだけです：

<Tabs>
  <Tab title="LangGraph">
    ```python
    graph.invoke({"messages": [HumanMessage("...")]})
    ```
  </Tab>
  <Tab title="CrewAI">
    ```python
    Crew(agents=[analyst, writer], tasks=[gather, summarise]).kickoff()
    ```
  </Tab>
  <Tab title="LlamaIndex">
    ```python
    await agent.run("...")        # `async with failproofai_sdk.session():` の下で
    ```
  </Tab>
  <Tab title="Pydantic AI">
    ```python
    agent.run_sync("...")
    ```
  </Tab>
  <Tab title="Custom agents">
    ```python
    with failproofai_sdk.agent("planner"):
        with failproofai_sdk.tool_call("search", input={"q": q}) as t:
            t.output = search(q)
    ```
  </Tab>
</Tabs>

追加インストールで**フレームワーク**が有効になります。すべてのアダプターはベースホイールに同梱されているため、すでにフレームワークを持つプロジェクトでは追加インストールは不要です。

## 届いたか確認する

インストルメントされたセッションを1回実行し、**Observe → Sessions** を開いて環境を選択します。実行結果が再構成されたトレースとして表示されます。

何も届かない場合は、`failproofai config --status` でマシンのセットアップと接続状態を確認してください。接続されていない場合は `failproofai config` を実行します。[セットアップの選択](/ja/start/setup) を参照してください。

<Warning>
  配信確認のためにスプールディレクトリを確認しないでください。Failproof デーモンは各バッチをミリ秒以内に収集・削除するため、読み取るとコレクターと競合し、実際に送信されたイベントよりはるかに少ない数しか表示されません。
</Warning>

SDKが実際に書き込んでいることを確認するには、まずデーモンを停止してからセッションを実行し、`~/.failproofai/custom-agents/events/` を確認してください。デーモンが動作中の場合、ディレクトリが空であることが正常な状態です。

<CodeGroup>
```bash Linux
sudo systemctl stop failproofaid@$USER
```

```bash macOS
sudo launchctl bootout system/ai.failproof.failproofaid.$USER
```
</CodeGroup>

確認後は `failproofai config` を実行して元に戻してください。デーモンが停止している間、このマシンのフックイベントは評価者がいないため拒否されます。停止は確認に必要な時間だけにとどめてください。
