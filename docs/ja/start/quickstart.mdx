このクイックスタートでは、1台のマシンをセッション報告に設定し、監査を実行して、ポリシーをデプロイします。スキルを使って Failproof をセットアップするか、手動手順に従ってください。

**あなたに合ったパスはどれ？** エージェントが12種類のサポートされた[ハーネス](/ja/reference/harnesses)のいずれかで動作している場合（コーディングCLI、またはHermesやOpenClawのようなゲートウェイ）、以下の手順に従ってください。Node.js 20.9以降が必要です。エージェントにハーネスがない場合は、[Python SDK](/ja/reference/custom-agents)でトレースと監査のインストルメントを行い、[最初の障害チェックを実行する](/ja/start/first-audit)から再参加してください。そのパスでの実施にはランタイムへのフックが必要です。

      </Step>

  <Tab title="手動セットアップ">
    ## インストール

<Steps>
  <Step title="Failproof AI をインストールして接続する">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    このコマンド1つでセットアップのすべてが完了します。ローカルデーモンをインストールし（rootは一度のみ）、検出されたすべてのエージェントCLIにフックを設定し、このマシンをクラウドに接続します。

    **クラウドへの接続**では、セットアップがすぐに FailproofAI Cloud へのログインを開始します（Tabキーで他のオプション：APIキーの貼り付け、またはオープンソースの使用に切り替えられます）。ブラウザでリンクが開きます（SSHや画面のないマシンでは、任意のデバイスで開けるようリンクが表示されます）。サインアップまたはサインインし、組織を確認（またはその場で作成）して**承認**をクリックします。キーの名前と権限は自動で設定されます。事前にアカウントは不要です。

    ターミナルが自動で検知し、誰がどの組織で承認したかを表示します。トレースするエージェントを確認すると、セットアップが完了します。マシンのキーはデーモンのインストール後、その時点で初めて作成されるため、途中で中断しても鍵は残りません。**管理 → キー**に**cli login**とマークされて表示され、そこで失効させることができます。

    <Accordion title="ブラウザやターミナルが使えない場合はキーを使用する（CI、コンテナ、プロビジョニングスクリプト）">
      [Failproof AI ダッシュボード](https://app.befailproof.ai)で**管理 → キー**に移動し、`events:add`と`policies:pull`の権限でキーを作成します。[FailproofAI Cloud 経由のJev](/ja/reference/jev-cloud)を使用する予定がある場合は、`jev:evaluate`も付与する**マシン**プリセットを選択してください。ワンタイムシークレットをコピーし、ターゲットマシンのシェルで読み込みます。`read -s`はエコーしないプロンプトで入力を受け付けます：

      ```bash
      read -rs FAILPROOFAI_KEY && export FAILPROOFAI_KEY
      FAILPROOFAI_CLOUD_TOKEN="$FAILPROOFAI_KEY" failproofai config
      ```

      `--token`ではなく環境変数でキーを渡すことで`ps`への露出を防ぎます。マシン上のすべてのユーザーがコマンドの引数を読めるためです。シェル履歴への露出は防げませんが、`read -s`で読み込むことでそれを防ぎます。CIではマスクされたシークレットとして注入し、シェルトレース（`set -x`）はオフにしてください。トレースが出力してしまいます。インタラクティブな実行では、**クラウドへの接続**で**APIキーを貼り付ける**を選択することもできます。
    </Accordion>

    セッションのトランスクリプトはデフォルトで送信されます。`--no-transcripts`を追加すると、トランスクリプトの内容なしにフックアクティビティとポリシー決定を報告します。

    <Warning>
      ここで`failproofai config --connect <url>`は使用しないでください。このフラグは**すでに**セットアップ済みのマシンを登録してすぐに返るもので、デーモンもフックも設定されません。そのためマシンはクラウドに表示されるにもかかわらず、何も収集・実施されない状態になります。
    </Warning>

    このマシンにすでにエージェントの履歴がある場合は、過去7日分をプレビューしてインポートし、配信が完了するまで待ちます。新しいマシンではこのステップをスキップしてください。

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    Failproof AI の**セッション**を開き、インポートしたセッションを選択します。
  </Step>
  <Step title="Failproof AI をハーネスに接続する">
    前のステップで検出されたすべてのエージェントCLIはすでに設定されています。必要に応じて特定のハーネスに対して明示的に再実行するか、後からインストールしたハーネスを追加するときに使用してください。12種類すべてが有効な`--cli`の値です — `claude`、`codex`、`copilot`、`cursor`、`opencode`、`pi`、`hermes`、`openclaw`、`factory`、`devin`、`antigravity`、`goose`。

    ```bash
    failproofai policies --install --cli claude --scope user     # コーディングCLI
    failproofai policies --install --cli hermes --scope user     # Slack/Telegramゲートウェイ
    ```

    実行前のツール呼び出しのブロックは12種類すべてで検証済みです。ターン終了時のゲートは8種類で検証済みです — ハーネスごとのマトリクスについては[実施能力](/ja/reference/harnesses#enforcement-capability)を参照してください。
  </Step>
  <Step title="実施するものを選択する">
    フックの設定はポリシーを有効にしません。セットアップは意図的に何も選択しません — その決定はあなたのものです — ですからパックを取得してください：

    ```bash
    failproofai policies add FailproofAI/policies
    ```

    パックはGitHubリリースから取得され、チェックサムで検証され、解決された正確なタグに固定されます。39のポリシーが含まれており、マニフェストが無人で有効化しても安全とマークした10個がオンになります。これらを使って、Failproof AI がセッションを監査してエージェント用のポリシーを作成する前に、ローカルのポリシー決定を確認し、実施を試してください。

    取得前に`failproofai policies show <owner>/<repo>`でパックの内容を確認し、一部だけ取得する方法については[ポリシーパック](/ja/policies/packs)を参照してください。

    これを実行するまで、実施されるのは`block-failproofai-commands`のみです — エージェントが Failproof AI をオフにするのを防ぐ常時オンのガードです。`failproofai policies`で何がオンになっているか確認できます。
  </Step>
  <Step title="動作を監査する">
    [最初の障害チェックを実行する](/ja/start/first-audit)に従ってください。「エージェントがアプローチを変えずに失敗したツールを再試行したセッションを見つける」といった具体的な目標を使用してください。
  </Step>
  <Step title="障害を防止する">
    [ポリシーで最初の障害を防止する](/ja/start/first-policy)に従ってください。監視モードで開始し、マッチを確認してから、レビュー済みのバージョンを実施してください。
  </Step>
</Steps>

<Check>
  `failproofai config --status`を実行してください。正常なセットアップでは、クラウド接続、デーモンの状態、実施が一時停止されているかどうかが報告されます。
</Check>

## Jev のセットアップ

[Jev](/ja/start/use-jev)を使用して、既知の回答がある質問に対して完了したセッションをスコアリングしたり、実行前にコンテキストでツール呼び出しをレビューしたりできます。**Jev を使用する**ページに両方のセットアップパスがあります。
