1台のマシンに Failproof AI をセットアップして、ローカルのまま使うか、クラウドに接続するかを選べます。

エージェントが[対応ハーネス](/ja/reference/harnesses)で動作している場合は、以下の手順に従ってください。LangChain、CrewAI、LlamaIndex、Pydantic AI、または独自のランタイムで構築されたエージェントの場合は、[エージェントのインストルメント化](/ja/start/integrations)から始めてください。

## エージェントにセットアップをガイドさせる

対応エージェントに Failproof AI アンブレラスキルをインストールします：

```bash
npx skills add FailproofAI/skills
```

これによりアンブレラスキルとその専門スキルがインストールされます。アンブレラスキルのみが必要な場合は `--skill
failproofai` を使用してください。ローカルおよびクラウドのセットアップ、デーモンの状態確認、セッション、監査、ポリシー、トラブルシューティングについて理解しており、作業を導きながら適切な Failproof AI スキルに専門タスクをルーティングします。以下の CLI インストールを置き換えるものではありません。

## マシンをセットアップする

<Steps>
  <Step title="Failproof AI をインストールして設定する">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    セットアップによりバックグラウンドサービスがインストールされ、検出されたすべての対応エージェントに接続されます。管理者アクセスを一度求められる場合があります。Linux と macOS に対応しています。
  </Step>

  <Step title="ポリシーを選択する">
    セットアップではポリシーパックは選択されません。Failproof AI パックを追加します：

    ```bash
    failproofai policies add FailproofAI/policies
    failproofai policies
    ```

    2番目のコマンドは、このマシン上のすべてのポリシーとその有効状態を表示します。パックを追加するまでは、`block-failproofai-commands` のみが実行されます。
  </Step>

  <Step title="マシンの状態を確認する">
    ```bash
    failproofai config --status
    ```

    サービス、クラウド接続、および一時停止状態を報告します。
  </Step>
</Steps>

## ローカルかクラウドかを選択する

<Tabs>
  <Tab title="ローカルのまま使う">
    アカウントは不要です。

    ```bash
    failproofai
    failproofai audit
    ```

    最初のコマンドは `http://localhost:8020` でローカルダッシュボードを開きます。2番目のコマンドはこのマシン上のエージェント履歴をスキャンします。
  </Tab>

  <Tab title="クラウドに接続する">
    Failproof AI Cloud でマシンキーを作成し、次を実行します：

    ```bash
    failproofai config --token <machine-key>
    failproofai config --status
    ```

    クラウドはポリシーの判定結果とセッションのトランスクリプトを受信します。判定結果のみを送信する場合は、まず接続してから `~/.failproofai/config.json` の `collector.sessions` を `false` に設定してください。現在の `--no-transcripts` セットアップフラグはその設定を適用しません。共有シェルや CI 環境では、コマンド履歴にキーが残らないよう、`FAILPROOFAI_CLOUD_TOKEN` 環境変数を使用してください。
  </Tab>
</Tabs>

## 動作を確認する

エージェントを起動して、通常のタスクを実行させます。その後：

ツールコールの deny は対応する全12ハーネスで検証済みです。ターン終了時の強制適用は8ハーネスで検証済みです。その他のハーネスとイベントの組み合わせは観測のみ、または未検証の場合があります。

- ローカルダッシュボードの **Policies → Activity** を開いて、ポリシーの判定結果を確認します。
- クラウドの **Observe → Sessions** を開いて、完全な実行内容を確認します。
- `failproofai audit` を実行して、リスクのあるパターンや非効率なパターンを探します。

<Warning>
  セットアップ後、`failproofaid` サービスが評価エンジンとなります。応答できない場合、保護されたアクションは拒否されます。エージェントが予期せず停止した場合は `failproofai config --status` を実行してください。
</Warning>
