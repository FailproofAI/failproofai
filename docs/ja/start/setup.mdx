Failproof AI は単一マシン上で完結して動作することも、Cloud に接続してセッションの共有やポリシー管理を行うこともできます。

## ローカル・アカウント不要

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai
```

これによりサービスがインストールされ、対応エージェントが接続され、ポリシーパックが追加され、`http://localhost:8020` にダッシュボードが開きます。

`failproofai audit` を実行すると、マシン上に既存のエージェント履歴をスキャンできます。

## Failproof AI Cloud に接続する

Cloud でマシンキーを作成し、次のコマンドを実行します：

```bash
failproofai config --token <machine-key>
failproofai config --machine-label checkout-runner-01
failproofai policies add FailproofAI/policies
failproofai config --status
```

または `FAILPROOFAI_CLOUD_TOKEN=<machine-key>` をエクスポートして、`failproofai config` をそのまま実行することもできます。共有マシンや CI 環境では環境変数の使用を推奨します。シェル履歴やプロセス一覧にキーが残らないためです。

Cloud は一つの接続で二つの役割を担います：

- このマシンに割り当てられたポリシーを取得する。
- ポリシーの判定結果とセッショントランスクリプトを送信する。

判定結果のみを送信するには、まず接続してから `~/.failproofai/config.json` 内の `collector.sessions` を `false` に設定してください。`--no-transcripts` には依存しないでください。現在のセットアッププロセスはこのフラグを解析しますが、適用はされません。詳細は [イベントと設定](/ja/reference/events-and-configuration#machine-configuration) を参照してください。

<Note>
  `--machine-label` は既に接続済みのマシンをリネームします。最初の接続コマンドと一緒にではなく、セットアップコマンドの後に実行してください。
</Note>

## 無人セットアップ

`failproofai config` は特別な非対話フラグを必要としません。CI やコンテナ環境では、プロンプトを表示せずにリクエストされたセットアップを適用します。

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

バックグラウンドサービスのインストールには、一度だけ管理者権限が必要です。セットアップは対話型の `sudo` パスワードプロンプトを開きません。パスワードなしで成功するか、管理者が実行すべきコマンドを表示します。

## プラットフォームサポート

セットアップは Linux と macOS に対応しています。それ以外のプラットフォームでは、フックや中途半端なセットアップ状態を書き込まずに終了します。
