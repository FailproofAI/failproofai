각 사람, 머신, 자동화 작업마다 별도의 키를 사용하세요. 필요한 권한만 부여하세요.

## 키 생성 및 교체

**Admin → Keys**를 사용하거나 Cloud CLI를 이용하세요:

```bash
fp keys list
fp keys create "audit automation" --add audits:read
fp keys disable "audit automation"
```

키가 생성될 때 시크릿을 저장하세요. 이후에는 다시 표시되지 않습니다. 교체 키를 생성하고, 사용처를 업데이트한 다음, 기존 키를 비활성화하여 키를 교체하세요.

## 머신 키

머신 키는 로컬 서비스를 Cloud에 연결합니다:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

연결된 머신에는 두 가지 기능이 필요할 수 있습니다:

- `policies:pull` — Cloud에서 관리하는 정책을 수신합니다.
- `events:add` — 결정 및 세션 데이터를 전송합니다.

하나는 정상 작동하고 다른 하나는 그렇지 않을 수 있기 때문에, 상태 보고에서는 이 두 기능을 별도로 표시합니다.

## 주요 권한

| 권한 | 허용 범위 |
| --- | --- |
| `events:add` | 이벤트 전송 |
| `events:read` | 이벤트 및 오류 조회 |
| `evaluations:read` | 세션 및 평가 조회 |
| `audits:read` / `audits:write` | 감사 검토 또는 관리 |
| `policies:read` / `policies:write` | 정책 검토 또는 배포 |
| `policies:pull` | 머신 정책 할당 가져오기 |
| `keys:create` / `keys:disable` | 키 생성 또는 비활성화 |
| `orgs:admin` | 인스턴스 수준의 조직 관리; 조직 키에는 할당할 수 없음 |

일부 관리용 `fp fleet` 및 `fp guardrails` 명령은 API 키 대신 로그인된 사용자 세션이 필요합니다. 요청 전에 해당 명령의 도움말 텍스트에 이 내용이 명시되어 있습니다.

<Warning>
  `AGENTEYE_KEY` 또는 `AGENTEYE_API_KEY`와 같은 수집 자격 증명을 `FP_API_KEY`로 재사용하지 마세요. 이들은 서로 다른 시스템과 권한을 위한 것입니다.
</Warning>
