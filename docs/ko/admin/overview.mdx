관리는 Failproof AI의 Cloud 영역입니다. 조직, 멤버, API 키, 조직 설정, 미터링된 사용량은 모두 Cloud 연결이 필요합니다.

<Note>
  Failproof AI는 계정 없이도 실행됩니다. 로컬 머신은 정책을 적용하고, 세션 이력을 디스크에 저장하며, `localhost:8020`에서 [로컬 대시보드](/ko/reference/local-dashboard)를 제공하고, 어디에도 데이터를 전송하지 않고 `failproofai audit`을 실행합니다. 로컬 `collector` 키에 대한 내용은 [머신 설정](/ko/reference/events-and-configuration#machine-configuration)을 참고하세요. Cloud를 사용하지 않는다면 이 섹션의 나머지 부분은 건너뛰어도 됩니다.
</Note>

## 컨트롤 위치

<Tabs>
  <Tab title="대시보드">
    Cloud 사이드바의 **admin** 그룹에는 **policy editor**, **enforcement**, **usage**, **keys**, **users**, **settings**가 있습니다.

    ![policy editor, enforcement, usage, keys, users, settings가 포함된 Cloud 사이드바의 admin 그룹.](/images/dashboard/admin-navigation.png)
  </Tab>
  <Tab title="CLI">
    Cloud CLI를 독립 도구로 설치한 후 로그인합니다:

    ```bash
    uv tool install fp-cloud-cli
    fp login
    fp whoami
    fp usage
    ```

    전역 옵션은 명령어 앞에 입력합니다. 예: `fp --org reliability-team --json usage`
  </Tab>
</Tabs>

## 로그인된 사용자 또는 API 키

`fp`는 두 가지 인증 모드 중 하나로 실행되며, 이 구분에 따라 사용 가능한 명령어가 결정됩니다. API 키로 수행할 수 없는 명령어는 연결을 시도하기 전에 거부되며, 401이나 403으로 대체하는 대신 그 이유를 명확히 알려줍니다.

| 명령어 | API 키 | 권한 |
| --- | --- | --- |
| `fp whoami` | 가능 | 없음 |
| `fp usage` | 가능 | `usage:read` |
| `fp keys list` / `show` | 가능 | `keys:read` |
| `fp keys create` | 가능 | `keys:create` |
| `fp keys disable` | 가능 | `keys:disable` |
| `fp keys regenerate` | 가능 | `keys:regenerate` |
| `fp keys update` | 불가 | `keys:update` (어떤 키도 보유 불가) |
| `fp users list` / `show` | 가능 | `users:read` |
| `fp users create` | 가능 | `users:create` |
| `fp users update` | 가능 | `users:update` |
| `fp users disable` / `enable` | 가능 | `users:delete` |
| `fp settings list` / `schema` | 가능 | `settings:read` |
| `fp settings set` | 가능 | `settings:write` |
| `fp orgs list` / `switch` / `current` / `perms` | 불가 | 로그인된 세션 전용 |

`fp usage`는 리포팅 스크립트에 적합한 명령어입니다. 키를 사용해 무인으로 실행되며 `usage:read` 권한만 필요합니다.
