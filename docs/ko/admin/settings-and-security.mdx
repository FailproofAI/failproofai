배포별 운영 값과 모델 컨텍스트 윈도우 재정의에는 설정을 사용하세요. API 또는 CLI를 통해 값을 변경하기 전에 설정 스키마를 먼저 확인하세요.

## 조직 설정 변경

<Tabs>
  <Tab title="대시보드">
    1. **관리 → 설정**으로 이동하여 설정 그룹을 찾고 설명과 현재 소스를 확인합니다.
    2. 값을 변경하고 저장합니다.
    3. 모델 컨텍스트 윈도우의 경우, 모델 재정의를 추가하거나 업데이트하고 유효 한도를 확인합니다.
    4. 변경된 값에 의존하는 세션과 메트릭을 재확인합니다.

    ![조직 인증 및 운영 설정이 표시된 설정 페이지.](/images/dashboard/settings.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp settings list
    fp settings schema
    fp settings set <key> --value <scalar>
    fp settings set alerts.email_default_recipients \
      --json-value '["oncall@example.com"]'
    ```

    설치된 CLI에서 사용하는 값 유형과 확인 플래그에 대한 정보는 `fp settings set --help`를 실행하세요.
  </Tab>
</Tabs>

## 데이터 처리 선택

Failproof AI CLI를 연결하면 기본적으로 트랜스크립트가 전송됩니다. 트레이스와 감사가 해당 내용에 의존하기 때문입니다. 프롬프트, 파일 내용, 터미널 입력이 로컬에 남아야 하는 경우 `--no-transcripts`를 사용하세요. 이 경우에도 훅 활동과 정책 결정은 계속 보고될 수 있습니다.

로컬 수집 자격 증명은 비밀이 아닌 데몬 설정과 별도로 저장되며, 제한적인 권한으로 작성됩니다. API 키는 여전히 프로덕션 시크릿으로 관리해야 합니다.

## 조직 설정 참조

대시보드에서 편집 가능한 모든 설정은 조직 범위입니다. 배포 전체 동작은 서버 환경 구성으로 유지됩니다.

| 키 | 기본값 | 목적 |
| --- | --- | --- |
| `allowed_sign_ins` | `[]` | 기존 멤버를 정확한 이메일 또는 `*@domain` 형식으로 제한합니다. 빈 목록은 추가 제한이 없음을 의미합니다. |
| `session_ttl_secs` | `86400` | 대시보드 세션 유효 기간으로, 허용 범위는 60초~30일입니다. |
| `otp_ttl_secs` | `600` | OTP 및 매직 링크 유효 기간으로, 허용 범위는 60~1800초입니다. |
| `alerts.email_default_recipients` | `[]` | 알림 이메일 채널에서 별도로 재정의하지 않을 때 사용하는 기본 수신자입니다. |
| `alerts.slack_default_webhook` | 비어 있음 | 기본 Slack 수신 웹훅 URL입니다. |
| `alerts.webhook_default_url` | 비어 있음 | 기본 범용 JSON 웹훅 URL입니다. |
| `alerts.webhook_signing_secret` | 비어 있음 | `X-AgentEye-Signature` 헤더에 사용하는 HMAC-SHA256 키로, 읽을 때 마스킹됩니다. |
| `alerts.enabled_channels` | 이메일, Slack, 웹훅 | 알림 규칙이 발송할 수 있는 조직 전체 채널 종류입니다. |
| `default_user_permissions` | `standard` | 새 초대 시 기본으로 선택되는 권한 집합 이름입니다. |

`allowed_sign_ins`는 권한을 부여하는 것이 아니라 필터 역할을 합니다. 해당 사람은 이미 조직 멤버여야 합니다. 모든 멤버를 허용하려면 빈 목록을 사용하세요. 단독 값 `*`는 거부됩니다. 알림 URL은 루프백 개발 주소를 제외하고 반드시 HTTPS를 사용해야 합니다.

## 보안 체크리스트

- 클라우드 연결에는 HTTPS를 사용하세요.
- 키의 권한 범위를 최소한으로 설정하세요.
- 프로덕션 환경과 비프로덕션 환경을 분리하세요.
- 배포 전에 트랜스크립트 및 편집(redaction) 설정을 검토하세요.
- 사용자, 키, 조직 변경 사항을 감사하세요.
- 배포 환경에 맞는 백업, 보존 및 인시던트 대응 요건을 테스트하세요.

<Warning>
  트랜스크립트 캡처를 끄면 감사 및 조사에서 증명할 수 있는 내용이 달라집니다. 해당 결정과 예상되는 제한 사항을 기록해 두세요.
</Warning>
