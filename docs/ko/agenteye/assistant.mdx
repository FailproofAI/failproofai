에이전트 데이터에 대해 일반 언어로 질문하면 근거로 바로 연결되는 답변을 얻을 수 있습니다. SQL을 작성할 필요도, 대시보드를 뒤질 필요도 없습니다. **Failproof AI Observability** 어시스턴트는 팀 누구나 에이전트에 관한 답을 가장 빠르게 얻을 수 있는 방법입니다.

![대시보드 내에서 일반 언어 질문에 답변하는 Failproof AI Observability 어시스턴트. 실시간 에이전트 활동 테이블, 에이전트별 모델 사용 현황, 텍스트 요약, 그리고 실행된 쿼리가 인라인으로 표시됩니다.](/agenteye/images/assistant.png)
*일반 언어로 질문하면 자신의 데이터를 기반으로 구성된 답변을 받습니다. 여기서는 어떤 에이전트가 가장 바쁜지, 어떤 모델을 사용하는지 분석하고, 모든 수치를 검증할 수 있도록 실행된 쿼리도 함께 보여줍니다.*

별도로 배워야 할 것이 없습니다. 채팅을 열고, 알고 싶은 것을 입력하고, 돌아오는 링크를 따라가기만 하면 됩니다:

```
You:  which sessions errored today?
AI:   5 sessions errored today, newest first. Each one is linked:
      • checkout-agent   14:02   tool timeout
      • billing-agent    11:47   unhandled error
      • ...and 3 more

You:  summarize this session          (asked while viewing a run)
AI:   This run took 12 steps across 3 tools and failed near the end when a
      payment tool returned an error. It scored low on your "resolved" eval.
      Links: the session, the failing event, and that evaluation.
```

## 그냥 물어보고, 바로 증거로 이동하세요

추측을 멈추고 쿼리 작성도 그만하세요. "이번 주 프로덕션에서 품질 추이가 어떤가요?", "오늘 오류가 발생한 세션은 어떤 것들인가요?", "이 세션을 요약해줘"라고 물으면 직접 쿼리를 만들고 결과를 읽는 대신 몇 초 만에 명확한 답을 얻을 수 있습니다.

모든 답변에는 근거가 함께 제공됩니다. 어시스턴트는 답에 도달하기 위해 사용한 정확한 세션, 저장된 쿼리, 대시보드를 링크로 연결해주므로 말만 믿는 것이 아니라 클릭해서 직접 확인할 수 있습니다. 또한 **페이지 인식** 기능도 있어서, 특정 세션을 보는 중에 "이 세션"에 대해 물으면 어떤 실행을 말하는지 이미 알고 있습니다. 기록 전환기에서 이전 대화를 나중에 다시 열어 이어서 진행할 수도 있습니다.

## 좋은 답변을 저장된 쿼리나 대시보드로 변환하기

보관할 가치가 있는 답변은 어시스턴트에게 저장하도록 요청하세요. 어시스턴트가 저장된 쿼리를 위한 SQL 초안을 작성하거나, 해당 쿼리들로 대시보드를 구성한 다음 **승인 / 거부** 카드를 보여줍니다. 승인을 클릭하기 전까지는 아무것도 저장되지 않으므로, "그냥 물어보기"의 속도와 최종 결정권이 항상 사용자에게 있다는 안심감을 모두 누릴 수 있습니다.

**Queries** 페이지에서는 한 단계 더 나아가 SQL 작성자 역할도 합니다. 원하는 쿼리를 설명하면("지난 7일간 에이전트별 오류율 보여줘") SQL이 에디터에 바로 스트리밍되며, 변경 사항이 적용되기 전에 **수락** 또는 **거부**할 수 있도록 diff 뷰가 열립니다.

![Observability Queries 페이지와 SQL 에디터](/agenteye/images/query-lab.png)
*Queries 페이지: 어시스턴트가 읽기 전용 초안 쿼리를 스트리밍하면 수락 또는 거부할 수 있는 에디터입니다.*

여기서 질문을 통해 SQL을 작성하면 에디터의 **Run** 버튼과 동일한 `queries:run` 권한을 사용합니다. 그 외 모든 곳에서의 채팅은 `agent:use` 권한이 필요합니다.

## 팀 전체에 안심하고 공개할 수 있습니다

어시스턴트가 무엇을 건드릴지 걱정 없이 모든 팀원에게 열어줄 수 있습니다:

- **이미 볼 수 있는 것만 읽습니다.** 답변은 사용자 본인의 읽기 권한 범위로 제한되므로 데이터 접근 범위가 넓어지지 않습니다.
- **모든 쓰기 작업은 사용자 확인을 기다립니다.** 저장된 쿼리와 대시보드는 명시적인 승인 클릭 이후에만 생성되며, 이 승인 단계를 끄는 설정은 없습니다.
- **아무것도 삭제할 수 없습니다.** 삭제 도구는 노출되지 않으며 어시스턴트는 삭제 권한을 갖지 않습니다. 삭제는 대시보드에서 사용자가 직접 처리합니다.
- **소속 조직 내에서만 작동합니다.** 어시스턴트는 현재 보고 있는 조직의 데이터만 볼 수 있습니다.
- **질문은 사용자의 것으로 남습니다.** 프롬프트와 답변은 자체 Observability 데이터베이스에 저장되며, 제품 분석은 사용 메타데이터만 기록하고 프롬프트 텍스트는 절대 기록하지 않습니다.

## 어디서 찾을 수 있나요

어시스턴트는 소속 조직(`/<org-slug>/...`) 하위 모든 페이지의 오른쪽 끝에 함께 있습니다. 레일을 클릭하거나 `⌘J` / `Ctrl+J`를 눌러 전체 채팅 패널로 확장할 수 있으며, 가장자리를 드래그해 크기를 조절할 수 있습니다. 설정한 너비는 새로고침 후에도 기억됩니다. 사용하려면 **`agent:use`** 권한이 필요하며, 권한이 없으면 레일이 비활성화(회색)됩니다. 배포 환경에서 아직 활성화되지 않은 경우(LLM 연결이 필요함) 작동하는 채팅 대신 흐릿한 레일이 표시됩니다.
