에이전트 데이터에 대해 일반적인 언어로 질문하고, 근거 자료로 바로 연결되는 답변을 받아보세요. SQL을 작성할 필요도, 대시보드를 뒤질 필요도 없습니다. **Failproof AI Observability** 어시스턴트는 팀 누구든 에이전트에 대한 답변을 가장 빠르게 얻을 수 있는 방법입니다.

![The Failproof AI Observability assistant answering a plain-English question inside the dashboard, showing a live Agent Activity table, a per-agent model-usage breakdown, and written takeaways, with the queries it ran shown inline](/agenteye/images/assistant.png)
*일반 언어로 질문하면 자체 데이터를 기반으로 한 답변을 받을 수 있습니다. 여기서는 어떤 에이전트가 가장 바쁜지, 어떤 모델을 사용하는지 분석해주고, 실행한 쿼리도 함께 보여줘서 모든 수치를 직접 확인할 수 있습니다.*

별도로 배울 것이 없습니다. 채팅을 열고, 알고 싶은 것을 입력하고, 돌아온 링크를 따라가기만 하면 됩니다:

```
You:  which sessions errored today?
AI:   5 sessions errored today, newest first. Each one is linked:
      • checkout-agent   14:02   tool timeout
      • billing-agent    11:47   unhandled error
      • ...and 3 more

You:  summarize this session          (asked while viewing a run)
AI:   This run took 12 steps across 3 tools and failed near the end when a
      payment tool returned an error. It scored low on your "resolved" eval.
      Links: the session, the failing event, and that evaluation.
```

## 그냥 물어보고, 바로 근거로 이동하세요

더 이상 추측하거나 쿼리를 작성할 필요가 없습니다. "이번 주 프로덕션의 품질 추이는?", "오늘 오류가 발생한 세션은?", 혹은 "이 세션을 요약해줘"라고 물으면, 쿼리를 만들고 직접 해석하는 대신 몇 초 안에 명확한 답변을 얻을 수 있습니다.

모든 답변에는 근거가 함께 제공됩니다. 어시스턴트는 답변 도출에 사용한 정확한 세션, 저장된 쿼리, 대시보드를 링크로 제공하므로, 그냥 믿는 대신 직접 클릭해서 확인할 수 있습니다. 또한 **페이지 인식** 기능도 있어, 특정 세션을 보는 중에 "이 세션"에 대해 물으면 어떤 실행을 가리키는지 이미 알고 있습니다. 기록 전환기에서 이전 대화를 다시 열어 이어서 진행할 수도 있습니다.

## 좋은 답변을 저장된 쿼리나 대시보드로 전환하세요

답변이 보존할 가치가 있다면, 어시스턴트에게 저장하도록 요청하세요. 저장된 쿼리를 위한 SQL 초안을 작성하거나, 해당 쿼리로 대시보드를 구성한 뒤 **승인 / 거부** 카드를 보여줍니다. 승인을 클릭하기 전까지는 아무것도 저장되지 않으므로, "그냥 물어보기"의 속도와 최종 결정권이 항상 여러분에게 있다는 안심감을 동시에 누릴 수 있습니다.

**쿼리** 페이지에서는 한 단계 더 나아가 SQL 작성 도우미 역할을 합니다. 원하는 쿼리를 설명하면("지난 7일간 에이전트별 오류율 보기"), SQL을 에디터에 바로 스트리밍하고 diff 뷰를 열어 변경 사항을 **수락** 또는 **거부**할 수 있습니다.

![The Observability Queries page and its SQL editor](/agenteye/images/query-lab.png)
*쿼리 페이지: 어시스턴트가 초안 읽기 전용 쿼리를 스트리밍하면, 이 에디터에서 수락하거나 거부할 수 있습니다.*

여기서 질문으로 SQL을 작성하면 `queries:run` 권한이 사용되며, 이는 에디터의 **실행** 버튼과 동일한 권한입니다. 다른 모든 곳에서의 채팅은 `agent:use` 권한이 필요합니다.

## 전체 팀에게 안심하고 공개할 수 있습니다

어시스턴트가 무엇을 건드릴지 걱정 없이 모든 팀원에게 공개할 수 있습니다:

- **이미 볼 수 있는 것만 읽습니다.** 답변은 자신의 읽기 권한 범위로 제한되므로, 데이터 접근 범위가 확장되지 않습니다.
- **모든 쓰기 작업은 여러분을 기다립니다.** 저장된 쿼리와 대시보드는 명시적으로 승인을 클릭한 후에만 생성되며, 이 게이트를 끄는 설정은 없습니다.
- **아무것도 삭제할 수 없습니다.** 삭제 도구가 노출되지 않으며, 어시스턴트는 삭제 권한을 갖지 않습니다. 삭제는 대시보드에서 여러분의 손으로만 가능합니다.
- **조직 내에서만 작동합니다.** 어시스턴트는 현재 보고 있는 조직만 볼 수 있습니다.
- **질문은 여러분의 것입니다.** 프롬프트와 답변은 자체 Observability 데이터베이스에 저장되며, 제품 분석은 사용 메타데이터만 기록하고 프롬프트 텍스트는 절대 기록하지 않습니다.

## 위치 안내

어시스턴트는 조직 하위 모든 페이지(`/<org-slug>/...`)의 오른쪽 가장자리에 항상 위치합니다. 레일을 클릭하거나 `⌘J` / `Ctrl+J`를 눌러 전체 채팅 패널로 확장하고, 가장자리를 드래그해 크기를 조절할 수 있으며 너비는 새로고침 후에도 유지됩니다. 사용하려면 **`agent:use`** 권한이 필요하며, 없을 경우 레일이 흐리게 표시됩니다. 배포 환경에서 아직 활성화되지 않은 경우(LLM 연결이 필요합니다), 작동하는 채팅 대신 음소거된 레일이 표시됩니다.
