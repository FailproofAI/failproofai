## 데이터 모델

**이벤트(Event)**
데이터의 가장 작은 단위입니다. 하나의 이벤트는 에이전트가 수행한 단일 단계를 기록합니다: `tool_use`, `model_request`, `hook_completed`, `error` 등. 에이전트는 [Python SDK](/ko/agenteye/python-sdk)를 통해 이벤트를 내보내며, **Events** 페이지에서 실시간으로 확인할 수 있습니다.

**세션(Session)**
`session_id`로 식별되는 하나의 에이전트 실행 단위입니다. 세션은 해당 ID를 공유하는 모든 이벤트를 묶어 **Sessions** 페이지에서 단일 행으로 표시하고, 상세 페이지에서는 실행 그래프로 시각화합니다. 세션은 보통 `agent_start`로 시작해 `agent_end`로 끝납니다.

**에이전트(Agent)**
`agent_id`로 식별되는, 실행 내의 명명된 행위자입니다. 하나의 실행에 여러 에이전트가 참여할 수 있습니다. 예를 들어 플래너가 요약 서브 에이전트를 생성하는 경우입니다. 서브 에이전트는 `parent_id`를 가지며, 이를 통해 Failproof AI Observability가 실행 그래프에서 각 에이전트를 별도의 레인으로 표시할 수 있습니다.

**환경(Environment)**
실행이 발생한 위치를 나타내는 레이블입니다: `production`, `staging`, `dev`. SDK를 구성할 때 한 번 설정합니다. 대시보드의 거의 모든 페이지에서 환경별로 필터링할 수 있습니다.

**컨텍스트 윈도우 사용률(Context-window fill)**
모델의 응답이 컨텍스트 윈도우를 얼마나 채웠는지를 나타내는 비율입니다. Failproof AI Observability는 인식된 모델의 `model_response` 이벤트에 이 정보를 기록하므로, 프롬프트 증가 추세와 임박한 컴팩션을 이벤트 스트림에서 바로 확인할 수 있습니다.

## 품질

**평가(Evaluation)**
완료된 세션에 대한 품질 점수로, 직접 운영하는 채점 서비스가 생성합니다. 평가는 선택 기능입니다. 평가자를 연결하기 전까지는 세션이 기록되기만 하고 채점되지 않습니다. 각 평가는 여러 개의 명명된 점수(예: `helpfulness`, `factuality`, `tool_efficiency`)를 포함할 수 있으며, 각 점수에는 짧은 근거 메모가 함께 기록됩니다. [Evaluation suite](/ko/agenteye/evaluation-suite)를 참고하세요.

**점수 키(Score key)**
평가자가 보고하는 하나의 평가 차원 이름입니다(예: `helpfulness`). 알림과 감사는 특정 점수 키를 시간에 따라 모니터링할 수 있습니다.

**평가자(Evaluator)**
직접 운영하는 채점 서비스입니다. Failproof AI Observability는 완료된 실행의 트랜스크립트를 평가자에게 POST하고 반환된 점수를 저장합니다. 기본 평가자는 제공하지 않으며, 채점 로직은 직접 구현합니다.

## 장애 발견 및 수정

**훅(Hook)**
에이전트 프레임워크가 단계 전후로 실행하는 가드레일 또는 사이드 이펙트입니다: 콘텐츠 안전성 검사, PII 제거, 비용 제한 등. 훅은 `outcome`(allow, deny, modify)이 포함된 `hook_triggered` / `hook_completed` 이벤트를 내보내며, 전용 관찰 페이지를 제공합니다.

**알림 규칙(Alert rule)**
설정한 임계값을 지표가 초과할 때 발동되는 규칙입니다: 오류율, p95 지연 시간, 토큰 비용, 평가자 점수 등. 규칙이 발동되면 인시던트가 생성되고 선택한 채널(이메일, Slack, 웹훅, 대시보드 내 알림)로 알림이 전송됩니다. [Alerts](/ko/agenteye/alerts)를 참고하세요.

**인시던트(Incident)**
알림 규칙이 발동될 때 생성되는 열린 이슈입니다. 인시던트는 수명 주기(확인, 담당자 지정, 해결)와 모든 조치를 기록하는 활동 타임라인을 가집니다. 수동으로 생성할 수도 있습니다.

**감사(Audit)**
아직 규칙을 정의하지 않은 장애 패턴을 찾기 위해 세션 *전반에 걸쳐* 로그를 분석하는 반복 조사입니다(시간별~주간). 오류 클러스터, 낮은 점수, 지연 시간 이상값, 툴 호출 루프, 완료되지 않은 실행 등을 탐지합니다. 알림이 이미 알고 있는 지표를 감시한다면, 감사는 다음에 살펴볼 곳을 알려줍니다. [Audits](/ko/agenteye/audits)를 참고하세요.

**발견 사항(Finding)**
감사 실행에서 나온 순위가 매겨진 증거 기반의 결과입니다. 발견 사항은 패턴을 명시하고, 해당 패턴의 근거가 되는 정확한 세션에 링크하며, 트리아지 수명 주기(확인, 해결, 뮤트, 기각)를 가집니다. Failproof AI Observability는 실행 간 발견 사항을 중복 제거하므로, 이미 알려진 패턴은 새로 쌓이는 대신 업데이트됩니다.

**AI 어시스턴트(The AI assistant)**
대시보드 내 채팅으로, 자신의 데이터를 바탕으로 에이전트에 관한 질문에 일반 영어로 답변합니다. 기본적으로 읽기 전용이며, 어시스턴트가 생성하는 항목(저장된 쿼리, 대시보드)은 승인 절차를 거쳐야 하고 삭제는 절대 수행할 수 없습니다. [AI assistant](/ko/agenteye/assistant)를 참고하세요.

## 운영

**조직(Organization, 테넌트)**
독립된 워크스페이스입니다. 하나의 Failproof AI Observability 인스턴스에 여러 조직을 호스팅할 수 있으며, 각 조직은 고유한 사용자, 키, 데이터를 가집니다. 모든 대시보드 URL은 조직 슬러그(`/<org-slug>/…`) 아래에 범위가 지정됩니다.

**컬렉터(Collector)**
`agenteye-collector`는 각 에이전트 머신에서 실행되는 경량 데몬으로, SDK가 디스크에 기록한 이벤트를 배치 처리하여 서버로 전송합니다.

**API 키(API key)**
클라이언트가 서버에 인증하는 데 사용하는 범위가 지정된 토큰입니다. 키는 세분화된 권한을 가집니다(예: 컬렉터용 `events:add`, 대시보드 키용 읽기 전용 범위). [API keys](/ko/agenteye/api-keys)를 참고하세요.

**서버(Server)**
이벤트를 수집하고, 데이터베이스에 운영 상태를 저장하며, 대시보드와 CLI를 제공하는 수집 및 API 서비스입니다.

**대시보드(Dashboard)**
웹 UI입니다. 모든 페이지는 조직에 범위가 지정되며 서버 API를 통해 데이터를 읽습니다.
