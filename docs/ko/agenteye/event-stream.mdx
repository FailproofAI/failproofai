에이전트가 무언가를 하는 순간, 바로 확인하세요. 이벤트 스트림은 프로덕션의 모든 에이전트를 실시간으로 파악할 수 있는 창구입니다. 기다릴 필요도, 로그를 grep할 필요도, 무슨 일이 있었는지 추측할 필요도 없습니다.

![실시간 이벤트 스트림: 색상으로 구분된 이벤트 행이 실시간으로 업데이트되며, 환경·에이전트·세션·이벤트 유형·자유 텍스트로 필터링 가능](/agenteye/images/events-stream.png)

*조직 내 모든 에이전트의 모든 이벤트를 최신순으로, 발생하는 즉시 업데이트합니다.*

## 모든 에이전트를 실시간으로 파악

에이전트가 실행을 시작하거나, 모델을 호출하거나, 툴을 실행하거나, 훅을 작동시키거나, 오류가 발생하면 해당 행이 발생하는 즉시 스트림 상단에 나타납니다. 조직 내 모든 에이전트의 모든 이벤트를 최신순으로 추적하므로, 오래된 정보가 아닌 항상 최신 상태를 파악할 수 있습니다.

즉, 어딘가의 서버에서 로그 파일을 tail할 필요도, 여러 머신에서 grep할 필요도, 타임스탬프를 직접 맞춰볼 필요도 없습니다. 페이지 하나만 열면 이미 프로덕션을 모니터링하고 있는 셈입니다.

행은 유형별로 색상이 구분되어 있어 줄마다 일일이 읽지 않고도 스트림을 한눈에 파악할 수 있습니다. 각 행에서 한눈에 확인할 수 있는 정보는 다음과 같습니다:

- **유형**: 색상으로 구분된 `agent_start`, `model_response`, `tool_use`, `hook_completed`, `error` 등.
- **한 줄 요약**: 무슨 일이 있었는지 대략 파악하는 데 대부분 충분합니다.
- **해당 단계의 토큰 수**.
- **컨텍스트 윈도우 사용량 배지**: 해당되는 경우 표시되어, 프롬프트 증가와 컴팩션 임박 상황을 문제가 되기 전에 미리 확인할 수 있습니다.

실시간으로 모니터링하면 잘못된 배포, 무한 루프, 오류 급증을 다음 날 로그 검토가 아닌 발생하는 즉시 포착할 수 있습니다.

## 문제가 된 단 하나의 실행 찾기

뭔가 이상해 보일 때, 모든 데이터를 쏟아붓는 파이어호스는 필요 없습니다. 문제가 된 단 하나의 실행만 찾으면 됩니다. 스트림은 빠르게 필터링됩니다: 환경, 에이전트, 세션, 이벤트 유형, 또는 자유 텍스트로 좁혀나갈 수 있습니다.

세션 ID나 에이전트 ID로 필터링해 첫 번째 이벤트부터 마지막 이벤트까지 하나의 실행을 추적하세요. 이벤트 유형으로 필터링해 특정 종류의 활동만 격리할 수도 있습니다. 예를 들어 조직 전체의 `error`만 한 화면에서 볼 수 있습니다. 필터를 중첩하면 "모든 것, 전체"에서 "이 에이전트, 프로덕션, 오류 발생"으로 몇 번의 클릭만에 좁혀나간 뒤 바로 조치를 취할 수 있습니다.

자유 텍스트 검색은 이미 알고 있는 메시지, 툴 이름, 또는 ID로 곧바로 찾아주므로, 고객 리포트가 몇 초 만에 정확한 실행으로 연결됩니다.

## 위치

이벤트 스트림은 조직의 홈 화면입니다. 로그인하면 처음 도달하는 화면이 `/<org-slug>/`이므로, 도착하는 즉시 트리아지를 시작할 수 있습니다.

그 이면에서는, 에이전트가 SDK를 통해 이벤트를 내보내고, 콜렉터가 이를 Failproof AI Observability 서버로 전송하며, 스트림은 사용자가 직접 관리하는 인프라에 이벤트가 도착하는 대로 추적합니다. 원시 이벤트 추적 대신 집계된 뷰를 원한다면, 각 실행의 이벤트가 Sessions에서 한 행으로 접혀 있으며 클릭 한 번으로 이동할 수 있습니다.

이 스트림은 다른 모든 관찰 화면이 기반으로 삼는 진실의 원천입니다. 다른 곳에서 수치가 이상해 보일 때, 실제로 무슨 일이 있었는지 확인하는 곳이 바로 이 스트림입니다.
