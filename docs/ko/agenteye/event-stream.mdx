에이전트가 무언가를 하는 순간, 바로 확인할 수 있습니다. 이벤트 스트림은 프로덕션 환경의 모든 에이전트를 실시간으로 파악할 수 있는 창구입니다. 대기 시간도, 로그 검색도, 무슨 일이 있었는지 추측할 필요도 없습니다.

![실시간 이벤트 스트림: 환경, 에이전트, 세션, 이벤트 유형, 자유 텍스트로 필터링 가능한 색상 코드 이벤트 행이 실시간으로 업데이트됩니다](/agenteye/images/events-stream.png)

*조직 내 모든 에이전트의 모든 이벤트가 최신순으로 정렬되어 실시간으로 업데이트됩니다.*

## 모든 에이전트를 실시간으로 파악

에이전트가 실행을 시작하거나, 모델을 호출하거나, 도구를 실행하거나, 훅을 동작시키거나, 오류가 발생하는 순간 해당 행이 스트림 상단에 즉시 나타납니다. 조직 내 모든 에이전트의 이벤트를 최신순으로 추적하므로, 오래된 정보가 아닌 항상 최신 상태를 확인할 수 있습니다.

특정 서버의 로그 파일을 tailing하거나, 여러 머신에 걸쳐 로그를 검색하거나, 타임스탬프를 일일이 맞춰볼 필요가 없습니다. 페이지 하나만 열면 이미 프로덕션을 실시간으로 모니터링하고 있는 것입니다.

행은 유형별로 색상으로 구분되어, 각 줄을 일일이 읽지 않고도 스트림을 한눈에 파악할 수 있습니다. 각 행에서 다음 정보를 한눈에 확인할 수 있습니다:

- **유형**: 색상 코드로 표시 — `agent_start`, `model_response`, `tool_use`, `hook_completed`, `error` 등
- **한 줄 요약**: 내용 파악을 위해 항목을 열어볼 필요가 거의 없습니다.
- **단계별 토큰 수**
- **컨텍스트 윈도우 사용량 배지**: 해당하는 경우 표시되어, 프롬프트 증가나 컴팩션 임박 상황을 문제가 되기 전에 미리 파악할 수 있습니다.

실시간으로 모니터링하면 잘못된 배포, 무한 루프, 오류 급증 등을 다음 날 로그 리뷰가 아닌 발생하는 즉시 포착할 수 있습니다.

## 문제가 된 실행 찾기

무언가 이상해 보일 때, 모든 데이터를 쏟아붓는 파이어호스가 필요한 것이 아닙니다. 문제가 된 단 하나의 실행을 찾아야 합니다. 스트림은 빠르게 필터링됩니다: 환경, 에이전트, 세션, 이벤트 유형, 또는 자유 텍스트로 필터링할 수 있습니다.

세션 ID 또는 에이전트 ID로 필터링하면 첫 번째 이벤트부터 마지막 이벤트까지 하나의 실행 전체를 추적할 수 있습니다. 이벤트 유형으로 필터링하면 특정 종류의 활동만 격리할 수 있습니다. 예를 들어, 조직 전체의 모든 `error`를 한 화면에서 볼 수 있습니다. 필터를 조합하면 "모든 환경의 모든 것"에서 "프로덕션 환경에서 오류가 발생하는 이 에이전트"로 몇 번의 클릭만으로 범위를 좁힌 다음, 바로 조치를 취할 수 있습니다.

자유 텍스트 검색으로 이미 알고 있는 메시지, 도구 이름, 또는 ID를 바로 찾을 수 있어, 고객 문의를 받은 후 몇 초 만에 정확한 실행 기록을 찾아낼 수 있습니다.

## 접근 방법

이벤트 스트림은 조직의 홈 화면입니다. 로그인하면 가장 먼저 `/<org-slug>/` 화면으로 이동하므로, 도착하는 순간 바로 트리아지를 시작할 수 있습니다.

내부적으로 에이전트는 SDK를 통해 이벤트를 전송하고, 컬렉터가 이를 Failproof AI 옵저버빌리티 서버로 전달하며, 스트림은 여러분이 관리하는 인프라에 이벤트가 도착하는 대로 실시간으로 추적합니다. 원시 추적 대신 요약된 뷰를 원할 경우, 각 실행의 이벤트가 Sessions에서 단일 행으로 압축되며 클릭 한 번으로 확인할 수 있습니다.

이벤트 스트림은 다른 모든 옵저버빌리티 화면이 기반으로 하는 원시 데이터 소스입니다. 다른 곳에서 숫자가 이상해 보일 때, 실제로 무슨 일이 있었는지 확인하는 곳이 바로 이 스트림입니다.
