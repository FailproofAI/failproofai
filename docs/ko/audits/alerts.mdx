알림은 측정 가능한 조건을 모니터링하다가 조건이 충족되면 인시던트를 생성합니다. 정책이 실패를 차단할 수 있는지 여부에 관계없이, 실패에 신속한 대응이 필요한 경우에 사용하세요.

## 알림 생성 및 테스트

<Tabs>
  <Tab title="대시보드">
    1. **Analyze → Alerts**로 이동하여 **new alert**를 선택합니다. 대표적인 오류의 벨 아이콘에서 시작할 수도 있습니다.
    2. 이름, 심각도, 트리거 종류, 조건, 평가 주기, 위반 횟수, 윈도우, 채널을 입력합니다.
    3. 알림을 저장하고 상세 페이지를 열어 **test**를 실행합니다.
    4. **Analyze → Issues**로 이동하여 알림으로 생성된 인시던트를 확인, 담당자 지정, 논의, 구독, 해결합니다.

    폼의 첫 번째 부분에서는 알림과 트리거할 신호를 정의합니다.

    ![이름, 설명, 활성화 상태, 트리거 유형이 포함된 새 알림 폼의 첫 번째 부분.](/images/dashboard/alert-new-trigger.png)

    두 번째 부분에서는 조건이 지속되어야 하는 기간, 평가 빈도, 알림을 전송할 위치를 설정합니다.

    ![위반 로직, 스케줄, 심각도, 전달 채널, 생성 액션이 포함된 새 알림 폼의 두 번째 부분.](/images/dashboard/alert-new-routing.png)

    저장 후 Alerts 목록에서 규칙이 활성화되어 있으며 트리거, 윈도우, 심각도, 채널이 의도한 대로 설정되어 있는지 확인합니다.

    ![트리거, 평가 윈도우, 채널, 심각도와 함께 알림 규칙을 표시하는 Alerts 페이지.](/images/dashboard/alerts.png)

    프로덕션 대응에 의존하기 전에 알림을 테스트하세요.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp alerts create high-errors \
      --trigger-kind metric_threshold \
      --severity warning \
      --trigger-spec '{"metric":"error_count","op":">","value":50,"window_secs":900}'

    fp alerts show high-errors
    fp alerts test high-errors
    fp alerts update high-errors --severity critical --yes
    ```

    `fp alerts list`로 규칙을 검토하고, `fp alerts delete <name>`으로 규칙을 삭제합니다.

    전체 알림 명령 목록은 [`fp alerts` 참조](/ko/reference/cloud-cli#alerts)를 확인하세요.
  </Tab>
</Tabs>

알림 조건은 오류, 평가 점수, 평가 조합, 또는 커스텀 SQL을 기반으로 설정할 수 있습니다. 수신자를 추가하고 규칙을 테스트한 후, 생성된 인시던트를 열어 확인, 담당자 지정, 댓글 작성, 구독, 해결 작업을 진행합니다.

## 효과적인 알림 설계

- 조건과 영향을 받는 워크플로우를 명확히 명명합니다.
- 환경을 명시적으로 범위 지정합니다.
- 단발성 무해한 이벤트에 반응하지 않도록 윈도우와 임계값을 설정합니다.
- 대응자가 세션으로 이동할 수 있는 링크나 쿼리를 포함합니다.
- 규칙을 활성화하기 전에 담당자를 지정합니다.

<Tip>
  감사 결과를 해결한 후, 동일한 실패가 정책의 적용 범위 밖에서 재발할 수 있는 경우 알림을 추가하세요.
</Tip>
