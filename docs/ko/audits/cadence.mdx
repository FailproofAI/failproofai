에이전트, 프롬프트, 도구, 모델이 변경되면서 재발할 수 있는 장애 유형에는 반복 감사를 사용하세요.

## 일정 변경

<Tabs>
  <Tab title="대시보드">
    1. **분석 → 감사**로 이동하여 해당 감사를 엽니다.
    2. 설정을 열고 활성화 상태, 실행 간격, UTC 기준 시각, 윈도우 모드 또는 조회 기간을 변경합니다.
    3. 감사를 저장하고 감사 카드에서 다음 실행 시간을 확인합니다.
    4. 범위나 컨텍스트가 크게 변경된 후에는 **지금 실행**을 한 번 사용하세요.

    ![감사 편집기에서 주기, 스윕 윈도우, 범위, 분석 설정, 컨텍스트, 알림 채널을 표시하는 화면.](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    일정 경계값, 윈도우 동작 방식, 모든 감사 명령어는 [`fp audits` 참고 문서](/ko/reference/cloud-cli#audits)를 확인하세요.
  </Tab>
</Tabs>

리스크의 심각도와 비용을 고려하여 주기를 선택하세요:

| 리스크 패턴 | 권장 시작 주기 |
| --- | --- |
| 영향도 높은 프로덕션 액션 | 매일 |
| 워크플로우 또는 모델 회귀 | 매주 |
| 거버넌스 또는 접근 권한 검토 | 매월 |
| 일회성 릴리스 조사 | 1회 실행 |

조회 기간은 실행 주기에 맞게 설정하여 누락 구간이 발생하거나 불필요하게 넓은 범위를 반복 검토하는 일이 없도록 하세요. 감사의 목표나 컨텍스트를 변경한 후에는 다음 예약 실행 결과에 의존하기 전에 수동으로 한 번 실행하세요.

<Note>
  로컬 예약 감사는 해당 머신에서 설정되며 로컬 에이전트 기록을 검사합니다. 클라우드 감사 일정은 Cloud 세션을 기반으로 동작합니다. 각각의 결과와 소유권은 별도로 관리하세요.
</Note>
