로컬 감사는 이 머신에 이미 저장된 에이전트 히스토리를 읽어 `http://localhost:8020/audit`에서 결과를 엽니다. 계정이 필요하지 않습니다.

```bash
failproofai audit
```

스캔은 발견된 모든 지원 하네스의 히스토리를 대상으로 합니다. 이 버전에 내장된 39개 정책 카탈로그를 재실행하며, 설치된 팩과 커스텀 정책은 포함되지 않습니다.

## 결과 읽기

가장 자주 발견된 항목부터 시작한 뒤, 적용을 활성화하기 전에 해당 세션을 열어 확인하세요.

세 가지 제한 사항이 있습니다:

- 감사는 `Stop`이 아닌 도구 이벤트를 재구성하므로, `require-*-before-stop` 정책은 표시되지 않습니다.
- 8개의 "감사 전용" 검사는 정확히 매칭되는 정책 없이 낭비적인 패턴을 식별합니다.
- `warn-repeated-tool-calls`는 재실행 시 트랜스크립트 측 상태를 변경할 수 있어 건너뜁니다.

적용 가능한 발견 항목에 대해서는 결과에 표시된 정책 명령어를 사용하세요. 적용 전에 [하네스 적용 지원](/ko/reference/harnesses#enforcement-capability)을 먼저 확인하세요.

캐시된 결과는 `~/.failproofai/audit/dashboard.json`에 저장되며 7일 후 만료됩니다.

## 스캔 예약

```bash
failproofai audit --schedule 7
failproofai audit --status
failproofai audit --no-schedule
```

간격은 1~90일을 허용하며 기본값은 7일입니다. 처음 예약할 때는 대화형 로그인이 필요합니다. 백그라운드 서비스가 실행 중이어야 합니다.

### 머신 외부로 전송되는 데이터

대화형 감사는 발견 항목을 전송하지 않습니다. 익명 CLI 텔레메트리는 기본적으로 활성화되어 있으며, `FAILPROOFAI_TELEMETRY_DISABLED=1`로 비활성화할 수 있습니다.

예약을 선택한 후에는 각 예약 스캔 시 머신 ID, 레이블, 플랫폼, 스캔 기간이 전송됩니다. 유해한 패턴이 발견된 경우에는 횟수, 타임스탬프, 최대 3개의 편집된 예시가 포함된 제한적인 요약도 함께 전송됩니다. 문제 없는 스캔은 발견 항목이나 이메일을 전송하지 않습니다.

<Warning>
  감사 결과는 검토를 위한 근거이지, 플래그된 모든 작업이 안전하지 않다는 증거가 아닙니다. 발견 항목을 차단 적용으로 전환하기 전에 반드시 세션을 확인하세요.
</Warning>
