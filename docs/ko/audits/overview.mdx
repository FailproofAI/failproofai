감사는 선택된 세션 집합에서 명시된 실패 목표를 탐색합니다. 트레이스 증거, 평가 결과, 정책 히트, 참조 컨텍스트를 결합하여 실행 가능한 결과를 생성합니다.

감사가 예약된 실행부터 수정 가능한 증거 기반 실패까지 어떻게 진행되는지 확인하세요.

## 감사 열기

<Tabs>
  <Tab title="대시보드">
    **분석 → 감사**로 이동합니다. 페이지에는 예약 상태, 열린 결과, 마지막 실행, 다음 실행, 주기, 감사에 브리프 또는 참조 페이지가 있는지 여부가 표시됩니다. 카드를 선택하면 설정과 실행 기록을 볼 수 있고, **새 감사**를 선택하면 감사를 생성할 수 있습니다.

    ![예약, 민감도, 실행 상태가 표시된 반복 감사 목록의 감사 페이지.](/images/dashboard/audits.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

다음과 같은 집단 수준의 질문에 답해야 할 때 감사를 사용하세요:

- 에이전트가 에스컬레이션 없이 작업을 포기하는 경우는 어디인가?
- 어떤 도구 실패가 비효율적인 재시도로 이어지는가?
- 에이전트가 의도된 워크플로 외부의 데이터에 접근하고 있는가?
- 모델, 프롬프트, 또는 도구 릴리스 이후 무엇이 변경되었는가?

## 감사 응답 흐름

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert for recurrence
```

결과는 실패 모드를 명시하고 증거를 가리켜야 합니다. 이슈는 수정 조치를 담당합니다. 정책은 알려진 액션 패턴을 방지하고, 알림은 방지가 불가능하거나 모니터링이 필요한 경우 재발을 감지합니다.
