## 로컬 또는 클라우드

| | 로컬 감사 | 클라우드 감사 |
| --- | --- | --- |
| 명령어 | `failproofai audit` | `fp audits` |
| 읽기 | 이 머신의 에이전트 기록 | 클라우드 조직의 세션 |
| 결과 | `localhost:8020/audit`의 로컬 결과 | 공유 발견 사항, 이슈, 알림 |
| 요구 사항 | 계정 불필요 | 클라우드 연결 및 API 키 |

한 머신을 빠르게 검토할 때는 로컬 감사를 사용하세요. 팀이 에이전트와 머신 전반에 걸쳐 반복적인 감사를 수행해야 할 때는 클라우드를 사용하세요.

## 감사로 답할 수 있는 질문

- 에이전트가 에스컬레이션 없이 멈추는 지점은 어디인가?
- 어떤 도구 실패가 비효율적인 재시도로 이어지는가?
- 에이전트가 의도한 워크플로우 외부의 데이터에 접근하고 있는가?
- 모델, 프롬프트, 또는 도구 업데이트 이후 무엇이 변경되었는가?

## 클라우드 감사 열기

**Analyze → Audits**로 이동하거나 다음 명령어를 사용하세요:

```bash
fp audits list
fp audits show <audit-name>
fp audits findings --status open --limit 20
```

감사 명령어는 감사 이름 또는 전체 ID를 사용합니다. 발견 사항은 고유 ID로 참조됩니다.

## 발견 사항에서 예방으로

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert
```

발견 사항은 증거를 가리킵니다. 이슈는 대응 방안을 담당합니다. 정책은 알려진 행동 패턴을 방지하고, 알림은 재발을 감시합니다.

모든 발견 사항이 정책이 될 필요는 없습니다. `policy` 발견 사항은 시행 가능한 규칙을 설명합니다. `failure` 또는 `improvement`는 대신 워크플로우, 프롬프트, 모델, 또는 도구 변경이 필요할 수 있습니다.
