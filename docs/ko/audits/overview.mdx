감사(audit)는 선택된 세션 집합에서 특정 장애 목표를 탐색합니다. 트레이스 증거, 평가 결과, 정책 히트, 참조 컨텍스트를 결합하여 실행 가능한 조사 결과를 생성합니다.

감사가 예약 실행에서 증거 기반의 수정 가능한 장애로 이어지는 과정을 확인하세요.

## 감사 열기

<Tabs>
  <Tab title="대시보드">
    **Analyze → Audits**로 이동합니다. 페이지에는 예약 상태, 미해결 결과, 마지막 실행, 다음 실행, 주기, 감사에 브리프 또는 참조 페이지가 있는지 여부가 표시됩니다. 카드를 선택하면 설정과 실행 이력을 확인할 수 있으며, **new audit**을 선택하면 새 감사를 생성할 수 있습니다.

    ![일정, 민감도, 실행 상태가 표시된 반복 감사 목록 페이지.](/images/dashboard/audits.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

다음과 같은 집합 수준의 질문에 답해야 할 때 감사를 사용하세요.

- 에이전트가 에스컬레이션 없이 작업을 포기하는 지점은 어디인가?
- 어떤 도구 장애가 비효율적인 재시도로 이어지는가?
- 에이전트가 의도된 워크플로 외부의 데이터에 접근하고 있는가?
- 모델, 프롬프트, 또는 도구 릴리스 이후 무엇이 변경되었는가?

## 감사 응답 흐름

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert for recurrence
```

조사 결과는 장애 유형을 명시하고 증거를 가리켜야 합니다. 이슈는 수정 조치를 담당합니다. 정책은 알려진 액션 패턴을 예방하며, 알림은 예방이 불가능하거나 모니터링이 필요할 때 재발을 감지합니다.
