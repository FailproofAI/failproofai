---
title: "감사 레시피"
description: "일반적인 에이전트 실패 조사를 위한 시작 목표 모음입니다."
icon: "book-open-check"
---

이 레시피들을 시작 목표로 활용한 후, 해당 에이전트, 환경, 예상 워크플로를 추가하세요.

<Tabs>
  <Tab title="대시보드">
    **분석 → 감사 → 새 감사**로 이동하여 레시피 하나를 설명 또는 요약란에 붙여넣은 다음, 관련 환경, 에이전트, 조회 기간, 참조 URL을 추가합니다. 감사를 생성한 후 예약하기 전에 첫 번째 실행 결과를 확인하세요.

    새 감사 양식은 범위, 컨텍스트, 주기, 알림을 추가하여 레시피를 실행 가능한 실패 점검으로 변환합니다.

    ![집중된 목표, 일정, 에이전트 및 환경 범위, 컨텍스트, 알림 채널로 구성된 새 감사 양식.](/images/dashboard/audit-new.png)

    생성 후, 반복 실행에 의존하기 전에 감사가 예상 상태와 일정으로 목록에 나타나는지 확인하세요.

    ![생성 후 워크플로별 감사 레시피가 표시되는 감사 페이지.](/images/dashboard/audits.png)

    첫 번째 실행 결과를 열어보고, 발견된 내용이 의도한 실패 모드보다 너무 광범위하거나 좁을 경우 레시피를 수정하세요.
  </Tab>
  <Tab title="CLI">
    레시피를 텍스트 파일로 저장하고 생성 시 첨부합니다:

    ```bash
    fp audits create retry-loop-review \
      --scope '{"environments":["production"]}' \
      --text-file ./retry-loop-audit.txt \
      --schedule-interval-secs 86400
    ```
  </Tab>
</Tabs>

<AccordionGroup>
  <Accordion title="반복적인 재시도 루프">
    에이전트가 입력을 변경하거나 대안 도구를 선택하거나 사람에게 에스컬레이션하지 않고 동일한 실패한 도구 호출을 반복하는 세션을 찾습니다.
  </Accordion>
  <Accordion title="잘못된 도구 사용">
    선택한 도구가 명시된 작업과 일치하지 않거나, 도구 입력이 워크플로의 필수 전제 조건을 위반하는 세션을 찾습니다.
  </Accordion>
  <Accordion title="안전하지 않은 데이터 접근">
    이 에이전트에 승인된 경로 및 서비스 외부에서 민감한 데이터를 읽거나, 쓰거나, 전송하는 세션을 찾습니다.
  </Accordion>
  <Accordion title="작업 포기">
    요청된 결과, 명확한 오류, 또는 사람에게의 명시적인 인계 없이 종료되는 세션을 찾습니다.
  </Accordion>
  <Accordion title="비용 또는 지연 시간 회귀">
    모델, 도구, 또는 총 실행 시간이 예상 예산을 초과하는 세션을 찾고, 그 원인이 되는 이벤트 패턴을 식별합니다.
  </Accordion>
  <Accordion title="사람 에스컬레이션 누락">
    신뢰도, 반복 실패, 또는 정책 지침에 따라 사람의 판단이 필요했지만 에이전트가 자율적으로 계속 진행한 세션을 찾습니다.
  </Accordion>
</AccordionGroup>
