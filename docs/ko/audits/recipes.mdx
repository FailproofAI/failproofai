---
title: "감사 레시피"
description: "일반적인 에이전트 실패 조사를 위한 시작 목표."
icon: "book-open-check"
---

이것들을 시작 목표로 사용하고, 에이전트, 환경, 예상 워크플로우를 추가하세요.

<Tabs>
  <Tab title="대시보드">
    **분석 → 감사 → 새 감사**로 이동하여 레시피 하나를 설명 또는 브리프에 복사한 다음, 관련 환경, 에이전트, 조회 기간, 참조 URL을 추가하세요. 감사를 생성하고 스케줄링하기 전에 첫 번째 실행 결과를 검토하세요.

    새 감사 양식은 범위, 컨텍스트, 주기, 알림을 추가하여 레시피를 실행 가능한 실패 점검으로 변환합니다.

    ![집중된 목표, 스케줄, 에이전트 및 환경 범위, 컨텍스트, 알림 채널이 구성된 새 감사 양식.](/images/dashboard/audit-new.png)

    생성 후, 반복 실행에 의존하기 전에 감사가 예상 상태와 스케줄로 목록에 표시되는지 확인하세요.

    ![생성 후 워크플로우 특화 감사 레시피가 나타나는 감사 페이지.](/images/dashboard/audits.png)

    첫 번째 실행을 열고, 결과가 의도한 실패 모드보다 넓거나 좁은 경우 레시피를 수정하세요.
  </Tab>
  <Tab title="CLI">
    레시피를 텍스트 파일로 저장하고 생성 시 첨부하세요:

    ```bash
    fp audits create retry-loop-review \
      --scope '{"environments":["production"]}' \
      --text-file ./retry-loop-audit.txt \
      --schedule-interval-secs 86400
    ```
  </Tab>
</Tabs>

<AccordionGroup>
  <Accordion title="반복적인 재시도 루프">
    에이전트가 입력을 변경하거나, 대체 도구를 선택하거나, 사람에게 에스컬레이션하지 않고 동일한 실패한 도구 호출을 반복하는 세션을 찾으세요.
  </Accordion>
  <Accordion title="잘못된 도구 사용">
    선택한 도구가 명시된 작업과 일치하지 않거나, 도구 입력이 워크플로우의 필수 전제 조건을 위반하는 세션을 찾으세요.
  </Accordion>
  <Accordion title="안전하지 않은 데이터 접근">
    이 에이전트에 대해 승인된 경로 및 서비스 외부에서 민감한 데이터를 읽기, 쓰기, 또는 전송하는 세션을 찾으세요.
  </Accordion>
  <Accordion title="작업 중단">
    요청된 결과, 명확한 오류, 또는 사람에 대한 명시적인 인계 없이 종료되는 세션을 찾으세요.
  </Accordion>
  <Accordion title="비용 또는 지연 시간 회귀">
    모델, 도구, 또는 총 소요 시간이 예상 예산을 초과하는 세션을 찾고, 원인이 되는 이벤트 패턴을 파악하세요.
  </Accordion>
  <Accordion title="사람 에스컬레이션 누락">
    신뢰도 부족, 반복적인 실패, 또는 정책 지침으로 인해 사람의 결정이 필요했지만 에이전트가 자율적으로 계속 진행한 세션을 찾으세요.
  </Accordion>
</AccordionGroup>
