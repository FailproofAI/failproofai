감사의 목표와 대상 범위가 다른 운영자도 유효한 발견 사항이 무엇인지 알 수 있을 만큼 구체화된 후에 감사를 실행하세요.

## 실행 및 검토

<Tabs>
  <Tab title="대시보드">
    1. **Analyze → Audits**로 이동하여 감사를 열고 **run now**를 선택합니다. 대기 중 응답은 디스패처가 곧 시작할 것임을 의미합니다.
    2. 새 실행을 열어 상태, 창, 지속 시간, 발견 항목 수, 보고서를 검토합니다.
    3. 증거 세션을 선택하면 정확한 추적 정보가 열립니다.
    4. 감사 페이지로 돌아가 설정을 편집하거나, 스케줄을 비활성화하거나, 이전 실행 기록을 확인합니다.

    ![열린 발견 항목, 마지막 및 다음 실행 상태, 스윕 창, 컨텍스트, 즉시 실행 컨트롤, 순위별 발견 항목이 표시된 감사 상세 페이지.](/images/dashboard/audit-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits run checkout-reliability
    fp audits runs checkout-reliability --limit 10
    fp --json audits runs checkout-reliability
    fp audits findings --audit checkout-reliability
    ```

    실행 기록, 발견 항목, 분류 명령에 대한 자세한 내용은 [`fp audits` 참조](/ko/reference/cloud-cli#audits)를 확인하세요.
  </Tab>
</Tabs>

## 실행 전 확인 사항

- 선택한 시간 창 내에 세션이 존재하는지 확인합니다.
- 환경 및 에이전트 필터를 검증합니다.
- 참조 컨텍스트가 최신 상태인지 확인합니다.
- 목표가 원하는 결론이 아닌 장애 모드를 설명하고 있는지 확인합니다.

## 실행 결과 검토

실행 상태, 세션 커버리지, 모델 분석 실행 여부부터 확인하세요. 그런 다음 각 발견 항목의 심각도, 설명, 증거 세션, 지원 쿼리, 제안된 예방 경로를 검토합니다.

발견 항목 상태를 사용하여 확인, 음소거, 기각, 해결, 재개, 또는 작업 할당을 수행합니다. 발견 항목이 기각되더라도 증거는 보존하세요. 해당 결정이 내려진 이유를 설명하기 때문입니다.

## 빈 실행 또는 지연된 실행 해석

| 실행 상태 | 의미 | 조치 사항 |
| --- | --- | --- |
| 분석이 실행되었지만 발견 항목이 없음 | 선택된 증거가 설정된 민감도에서 발견 항목을 지지하지 않았습니다. | 범위에 대표적인 세션이 포함되어 있는지 확인한 후, 목표나 컨텍스트가 너무 모호하지 않는 한 결과를 정상으로 처리합니다. |
| 모델 분석이 건너뛰어지거나 실패함 | 실행은 발견 항목 없이 완료되지만 에이전트 조사를 수행하지 않았습니다. 결정론적 자격 증명 및 PII 스캔은 여전히 실행 통계에 매칭 수를 보고하지만 발견 항목을 생성하지 않습니다. | 분석 서비스 또는 구성을 수정하고 다시 실행합니다. 빈 결과를 해당 집단이 정상이라는 증거로 해석하지 마세요. |
| 모델 분석이 비활성화됨 | 실행은 발견 항목 없이 성공합니다. 결정론적 스캔은 모델 분석을 대체하거나 발견 항목을 생성하지 않습니다. | 발견 항목을 생성할 수 없는 감사에 의존하는 대신, 모델 분석을 활성화하거나 감사를 비활성화합니다. |
| 분석 용량이 즉시 가용하지 않음 | 감사가 대기 상태로 유지되며 집단을 건너뛰는 대신 재시도합니다. | 용량이 확보될 때까지 기다리거나 감사 앵커를 분산합니다. 자체 호스팅 운영자는 감사 에이전트 복제본과 이에 맞는 디스패처 용량을 확장해야 합니다. |
| 재시도 창 동안 용량이 계속 가용하지 않음 | 실행이 발견 항목 없이 중단되며, 이메일 전송이 가능한 경우 실패 알림이 발송됩니다. | 감사 플릿이 포화 상태이거나 반복적으로 재시작 중인지 확인합니다. |

분석이 실행되지 않은 경우, `since_last` 감사는 분석되지 않은 해당 창을 다음 성공적인 실행을 위해 열어 둡니다. 건너뛴 분석은 장애가 사라졌다는 증거가 아니므로 기존 발견 항목은 종료되지 않습니다.

## 실패 알림 이해

실행 실패 또는 모델 분석 단계 실패 시 감사의 이메일 수신자가 사용됩니다. 감사에 이메일 채널이 없는 경우, Failproof AI는 조직의 `alerts.email_default_recipients` 설정으로 폴백하여 자동으로 실패한 감사에도 에스컬레이션 경로가 유지됩니다.

이메일은 조직에 대해 활성화되어 있어야 하며 SMTP가 구성되어 있어야 합니다. 그렇지 않으면 실패가 기록되지만 이메일은 전송되지 않습니다. 실행 실패는 감사의 고정 스케줄 앵커를 이동시키지 않습니다.

모든 실행은 각 에이전트에 사용된 정확한 [에이전트 컨텍스트](/ko/audits/agent-contracts)를 계약 스냅샷으로 저장합니다. 이후의 편집은 이전 실행에 기록된 증거 기준을 변경하지 않습니다.

<Warning>
  검증되지 않은 발견 항목에서 직접 차단 정책을 배포하지 마세요. 인용된 추적 정보를 열어 해당 규칙이 안전하지 않은 동작과 정당한 작업을 올바르게 구분하는지 확인하세요.
</Warning>
