감사의 품질은 범위 설정에서 시작됩니다. "문제를 찾아라"와 같은 광범위한 요청은 구체적인 실패 질문보다 유용한 결과를 내기 어렵습니다.

## 감사 구성

<Tabs>
  <Tab title="대시보드">
    1. **분석 → 감사 → 새 감사**로 이동하여 이름과 설명을 입력합니다.
    2. 주기, 시간 창, 에이전트/환경 범위, 무시할 오류, 민감도, 최대 발견 건수를 설정합니다.
    3. **에이전트** 섹션에서 에이전트 컨텍스트를 추가하거나 검토한 후, 운영자 브리프와 공개 HTTPS 참조 URL을 추가합니다.
    4. 알림 채널을 선택하고 **감사 생성**을 클릭합니다. 첫 번째 실행은 즉시 대기열에 추가됩니다.

    ![이름, 설명, 주기, 시간 창, 환경 및 에이전트 범위, 무시할 오류, 분석 설정, 브리프, 참조 페이지, 알림 채널이 포함된 새 감사 양식.](/images/dashboard/audit-new.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits create checkout-reliability \
      --description "Find checkout failures that agents do not recover from" \
      --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
      --schedule-interval-secs 86400 \
      --window-mode since_last \
      --sensitivity medium \
      --text-file ./checkout-audit-brief.txt \
      --url https://runbooks.example.com/checkout
    ```

    첫 번째 실행은 즉시 대기열에 추가됩니다. 브리프와 참조 URL은 생성 시점에 포함해야 해당 실행에 적용됩니다.

    전체 [`fp audits create` 레퍼런스](/ko/reference/cloud-cli#audits)를 참조하세요.
  </Tab>
</Tabs>

<Tip>
  알려진 실패 세션 하나와 정상 세션 여러 개로 시작하세요. 이렇게 하면 감사에 긍정적인 예시와 비교 기준이 모두 제공됩니다.
</Tip>

<Info>
  감사 컨텍스트는 별도의 리소스로 저장되므로, 감사를 편집해도 참조 자료가 실수로 삭제되지 않습니다.
</Info>
