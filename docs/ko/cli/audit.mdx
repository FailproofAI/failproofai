<Note>
  **베타 기능.** 초기 피드백을 수집하는 동안 감사 기능은 베타로 제공됩니다.
  다음 안정 버전이 출시되기 전에 감지기 카탈로그와 리포트 형식이 변경될 수 있습니다.
  문제가 발견되면 이슈를 등록해 주세요.
</Note>

감사 기능은 과거 에이전트 CLI 트랜스크립트를 failproofai의 정책 엔진으로 재생하고,
**`/audit` 대시보드 페이지**에서 공유 가능한 시각적 리포트를 렌더링합니다 —
에이전트의 아키타입, 0–100 점수, 그리고 어떤 정책이 무엇을 잡아냈는지 정확히 확인할 수 있습니다.

## 실행 방법

세 가지 방법 모두 동일한 `/audit` 리포트로 이동합니다.

<CodeGroup>

```bash npx (설치 불필요)
npx -y failproofai audit
```

```bash failproofai audit
failproofai audit
```

```bash failproofai (대시보드)
failproofai
```

</CodeGroup>

<CardGroup cols={3}>
  <Card title="설치 불필요" icon="bolt">
    `npx -y failproofai audit`는 failproofai를 가져와 스캔을 실행하고
    대시보드를 자동으로 엽니다 — 사전 설치가 필요 없습니다.
  </Card>
  <Card title="CLI에서 실행" icon="terminal">
    `failproofai audit`는 터미널에서 스캔을 실행하고,
    완료되면 `localhost:8020/audit`을 자동으로 엽니다.
  </Card>
  <Card title="대시보드에서 실행" icon="gauge">

  </Card>

<Tip>
  사용법을 확인하려면 `failproofai audit -h` (또는 `--help`)를 실행하세요. 감사는 **완전히
  오프라인**으로 실행됩니다 — 계정이나 네트워크가 필요 없습니다 — 대시보드는 `Ctrl+C`로
  중지할 때까지 계속 서비스됩니다.
</Tip>

대시보드는 이 머신에서 과거 에이전트 CLI 트랜스크립트(Claude Code, Codex, Copilot, Cursor, OpenCode, Pi)를 스캔하고, 에이전트가 failproofai가 차단하도록 설계된 행동을 얼마나 자주 했는지 보고합니다 — 환경 변수 확인, 강제 푸시, 불필요한 `cd <cwd>` 접두사, sleep 폴링 루프, 방금 수정한 파일 재읽기 등이 포함됩니다.

각 트랜스크립트에서 모든 도구 사용 이벤트는 39개의 내장 정책 **및** 런타임 정책에서 아직 다루지 않는 패턴을 감지하는 8개의 감사 전용 감지기를 통해 재생됩니다. 카운트는 모든 세션에 걸쳐 정책/감지기별로 집계됩니다.

## 제공되는 내용

`/audit` 페이지는 단일 화면의 공유 가능한 **포스터**와 그 아래 네 개의 섹션으로 구성됩니다:

1. **포스터** — 에이전트의 정체성 한눈에 보기: **아키타입** (8가지 중 하나 — `optimist`, `cowboy`, `explorer`, `goldfish`, `paranoid architect`, `precision builder`, `hammer`, `ghost`), 페르소나 키워드, 해당 아키타입의 희귀도, 그리고 등급 밴드(`S`부터 `bottom tier`까지)가 포함된 **0–100 점수**. 공유용으로 제작 — X 또는 LinkedIn에 게시하거나 PNG로 다운로드하세요.
2. **`// strengths`** — 에이전트가 이미 잘 하는 것들을 스캔의 실제 수치로 표시 (예: clean-tool-call %, push-to-main 시도 `0`회), 관련 정책에 깨끗한 기록이 있는 경우에만 표시됩니다.
3. **`// quirks`** — 놓친 것들: failproofai가 잡아낼 수 있었던 행동의 순위 테이블 — *언제* 마지막으로 발생했는지, *무엇이 놓쳤는지* (그리고 차단했을 내장 정책), *심각도*, 그리고 얼마나 자주 *발견*됐는지(`new` / `recurring` / `N× seen`).
4. **`// how to improve`** — 권장 수정 목록: 복사-붙여넣기용 `failproofai policy add <slug>`가 포함된 정책 별 한 행, 모든 권장 사항을 한 번에 활성화하는 **install all** 버튼과 적용 시의 **예상 점수** 표시.
5. **`// come back better`** — 습관 만들기: 재감사 이메일 **알림** 설정(`3d` / `7d` / `14d` / `30d`) 또는 지금 재감사, 그리고 자신의 감사를 실행할 **친구 초대** (failproof.ai에서 발송, 참조 수신). 알림과 초대는 로그인이 필요합니다.

## 예약 감사

**failproofaid 데몬**을 실행 중이라면 ([`failproofai config`](/ko/cli/install-policies) 참조),
일정에 따라 감사를 재실행하고 백그라운드에서 `/audit` 리포트를 새로 고칠 수 있습니다.
스캔이 이 머신의 모든 에이전트 세션 트랜스크립트 *내용*을 읽기 때문에 **기본적으로 꺼져 있습니다** —
요청하기 전까지는 타이머로 스캔이 실행되지 않습니다.

`~/.failproofai/config.json`에서 활성화 — 파일에 이미 있는 내용 옆에 `audit` 키를 추가하세요:

```json
{
  "audit": {
    "auto": true,
    "interval_days": 7
  }
}
```

| 키 | 의미 |
|---|---|
| `auto` | `true`로 설정하면 예약 스캔이 활성화됩니다. 없거나 `false`, `"yes"` 등은 비활성화입니다. |
| `interval_days` | 스캔 간격(일). 1–90으로 제한되며, `0`, 음수 또는 숫자가 아닌 값은 `7`로 대체됩니다. |

- 일정은 **벽시계** 기준이므로 절전 및 재부팅 후에도 유지됩니다: 예약 시간을 지나 절전했던 노트북은
  깨어났을 때 **한 번** 실행되며, 밀린 작업이 누적되지 않습니다.
- 각 실행은 별도의 낮은 우선순위(`nice 19`) 프로세스로 실행됩니다 — 도구 호출에 응답하는 데몬의
  훅 경로를 절대 차지하지 않습니다.
- `failproofai audit` 또는 대시보드의 재실행이 이미 진행 중인 경우 스캔을 건너뜁니다;
  실패로 처리하는 대신 잠시 후 재시도합니다.
- 진행 상황은 `~/.failproofai/state/audit-schedule.json`에 기록됩니다 (마지막 실행,
  다음 예정). 데몬이 해당 파일을 소유합니다 — `config.json`에서 주기를 변경하세요.

<Note>
이전 버전의 failproofai로 설정된 머신에서 이 기능을 활성화한 경우,
`failproofai config`를 한 번 실행하세요. 데몬의 서비스 정의에 CLI를 시작하기 위한
추가 항목이 필요하며, 해당 명령의 일부로 새로 고침이 수행됩니다.
</Note>

## 감사 전용 감지기

런타임에 아직 적용되지 않는 "비효율적인 행동" 패턴을 감지합니다. 감사 중에만 실행되며 실시간 도구 호출을 절대 차단하지 않습니다.

| 감지기 | 감지 대상 |
|---|---|
| `redundant-cd-cwd` | 명령이 이미 `cwd`에서 실행됨에도 `cd <cwd> && …`로 시작하는 Bash 명령. |
| `prefer-edit-over-read-cat` | 단일 소스 파일에 대한 `cat`/`head`/`tail`/`less`/`more` — `Read` 도구를 사용하세요. |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` 인플레이스 편집 — `Edit` 도구를 사용하세요. |
| `prefer-write-over-heredoc` | Heredoc / 멀티라인 `echo > file` 파일 작성 — `Write` 도구를 사용하세요. |
| `sleep-polling-loop` | 긴 `sleep N` (≥ 30초) 또는 `while …; sleep …; done` 폴링 루프. |
| `find-from-root` | `find /`, `find /home`, `find /usr` 등 — 대신 `cwd`로 범위를 제한하세요. |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, 훅 건너뜀. |
| `reread-after-edit` | 동일 세션에서 `Edit`/`Write` 직후 같은 파일을 `Read`함. |

## 캐시

- **트랜스크립트별 캐시**: `~/.failproofai/cache/audit/<sha1>.json`에 `(mtime, size, engineVersion, detectorVersion)` 키로 저장 — 트랜스크립트나 정책/감지기 코드가 변경되면 자동으로 무효화됩니다. 각 항목에는 `cachedAt` 타임스탬프가 **TTL 메타데이터**로 저장됩니다 (캐시 키의 일부가 아님); **7일**이 지난 항목은 읽기 시 거부되어 오래된 결과가 진화하는 감지기 의도를 넘어 유지되지 않도록 합니다.
- **전체 결과 캐시**: `~/.failproofai/audit-dashboard.json`(모드 0600). 대시보드가 재실행 없이 내비게이션 즉시 렌더링되도록 합니다. **7일 TTL** 이후 읽기 시 거부됩니다 — `/audit`은 빈 상태로 폴백되고 새 실행을 요청합니다. 리포트 하단의 `[ re-audit now ]`를 클릭하여 새로 고침 — 재감사는 `noCache: true`를 전송하여 트랜스크립트별 캐시를 우회하고 캐시된 결과 대신 모든 트랜스크립트를 재스캔합니다; 실행은 고정 상단 스트립을 통해 진행 상황을 스트리밍하고 성공 시 결과를 제자리에서 교체합니다 (페이지 새로 고침 없음; 재감사 실패 시 이전 리포트 유지).

## 참고 사항

- **변경 없음.** 감사는 읽기 전용 모드로 재생됩니다. `warn-repeated-tool-calls`는 세션별 사이드카가 수정될 수 있으므로 건너뜁니다.
- **워크플로 정책 건너뜀.** `require-*-before-stop` 정책은 `Stop` 이벤트 시에만 실행되고 라이브 git 상태에 대해 `execSync`를 호출합니다 — "2025년에 어떻게 됐을지"에 대한 의미 있는 해석이 없으므로 감사 카운트에 나타나지 않습니다.
- **커스텀 정책 건너뜀.** 사용자가 제공한 커스텀 훅은 재생되지 않습니다 (원래 세션 이후 변경됐을 수 있음).
