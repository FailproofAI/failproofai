<Note>
  **베타 기능.** 감사 기능은 초기 피드백을 수집하는 동안 베타로 제공됩니다.
  다음 안정 버전 출시 전에 감지기 카탈로그와 리포트 형식이 변경될 수 있습니다.
  이상한 점이 있으면 이슈를 열어 주세요.
</Note>

감사 기능은 과거 에이전트 CLI 트랜스크립트를 failproofai의 정책 엔진을 통해 다시 실행하고, **`/audit` 대시보드 페이지**에서 공유 가능한 시각적 리포트를 렌더링합니다 — 에이전트의 아키타입, 0~100 점수, 그리고 어떤 정책이 어떤 문제를 포착했을지 정확히 확인할 수 있습니다.

## 실행 방법

세 가지 방법 모두 동일한 `/audit` 리포트로 연결됩니다.

<CodeGroup>

```bash npx (no install)
npx -y failproofai audit
```

```bash failproofai audit
failproofai audit
```

```bash failproofai (dashboard)
failproofai
```

</CodeGroup>

<Tip>
  `failproofai audit -h` (또는 `--help`)를 실행하면 사용법을 확인할 수 있습니다.
  감사는 **완전 오프라인**으로 실행됩니다 — 계정이나 네트워크가 필요 없으며,
  `Ctrl+C`로 중지할 때까지 대시보드가 계속 서빙됩니다.
</Tip>

대시보드는 이 머신의 과거 에이전트 CLI 트랜스크립트(Claude Code, Codex, Copilot, Cursor, OpenCode, Pi)를 스캔하고, 에이전트가 failproofai가 차단하도록 설계된 행동들 — 환경 변수 확인, 강제 푸시, 불필요한 `cd <cwd>` 접두사, sleep 폴링 루프, 방금 편집한 파일 재읽기 등 — 을 얼마나 자주 했는지 리포트합니다.

각 트랜스크립트에서 모든 도구 사용 이벤트는 39개의 내장 정책 **및** 런타임 정책에서 아직 다루지 않는 패턴을 포착하는 8개의 감사 전용 감지기를 통해 다시 실행됩니다. 집계된 횟수는 모든 세션에 걸쳐 정책/감지기별로 표시됩니다.

## 결과물

`/audit` 페이지는 단일 화면의 공유 가능한 **포스터**와 네 개의 하단 섹션으로 구성됩니다:

1. **포스터** — 에이전트의 정체성을 한눈에 확인: **아키타입** (8가지 중 하나 — `optimist`, `cowboy`, `explorer`, `goldfish`, `paranoid architect`, `precision builder`, `hammer`, `ghost`), 페르소나 키워드, 아키타입의 희귀도, 그리고 티어 밴드(`S`부터 `bottom tier`까지)와 함께 표시되는 **0~100 점수**. 공유에 최적화되어 있어 X나 LinkedIn에 게시하거나 PNG로 다운로드할 수 있습니다.
2. **`// strengths`** — 에이전트가 이미 잘 하고 있는 것들을 스캔의 실제 수치로 표시합니다 (예: 클린 도구 호출 %, `0`번의 push-to-main 시도). 관련 정책에 문제가 없는 경우에만 표시됩니다.
3. **`// quirks`** — 그냥 지나친 것들: failproofai가 포착했을 행동의 순위별 테이블 — 마지막 발생 *시점*, *무엇이 지나쳤는지* (그리고 차단했을 내장 정책), *심각도*, 발생 빈도 (`new` / `recurring` / `N× seen`).
4. **`// how to improve`** — 처방된 수정 목록: 복사-붙여넣기 가능한 `failproofai policy add <slug>`가 있는 정책별 한 행, 모든 권장 사항을 한 번에 활성화하는 **install all** 버튼, 그리고 적용 시 **예상 점수** 표시.
5. **`// come back better`** — 습관 만들기: 재감사 이메일 **리마인더** (`3d` / `7d` / `14d` / `30d`) 설정 또는 지금 재감사, 그리고 친구를 초대해 자체 감사를 실행하도록 합니다 (failproof.ai에서 발송, 참조로 본인에게 CC). 리마인더와 초대는 로그인이 필요합니다.

## 예약 감사

**failproofaid 데몬**을 실행 중인 경우([`failproofai config`](/ko/cli/install-policies) 참조),
일정에 따라 감사를 자동으로 재실행하고 `/audit` 리포트를 백그라운드에서
새로 고칠 수 있습니다. 스캔은 이 머신의 모든 에이전트 세션 트랜스크립트의
*내용*을 읽기 때문에 **기본적으로 비활성화**되어 있으며,
명시적으로 요청하기 전까지 타이머로 스캔이 실행되지 않습니다.

`~/.failproofai/config.toml`에서 활성화하세요:

```toml
[audit]
auto = true
interval_days = 7
```

| 키 | 의미 |
|---|---|
| `auto` | `true`이면 예약 스캔이 활성화됩니다. 그 외 — 없음, `false`, `"yes"` — 는 비활성화입니다. |
| `interval_days` | 스캔 사이의 일수. 1~90으로 제한되며, `0`, 음수 또는 숫자가 아닌 값은 `7`로 대체됩니다. |

- 스케줄은 **벽시계** 기준이므로 일시 정지 및 재부팅 후에도 유지됩니다:
  예정 시간을 지나 절전 상태였던 노트북은 깨어날 때 **한 번**만 실행되며,
  백로그가 쌓이지 않습니다.
- 각 실행은 별도의 낮은 우선순위(`nice 19`) 프로세스로 진행됩니다 —
  도구 호출 응답을 위해 항상 자유롭게 유지되는 데몬의 훅 경로와 분리됩니다.
- `failproofai audit` 또는 대시보드의 재실행이 이미 진행 중인 경우 스캔이 건너뛰어지며,
  실패로 처리되지 않고 잠시 후 재시도됩니다.
- 진행 상황은 `~/.failproofai/state/audit-schedule.json`에 기록됩니다 (마지막 실행,
  다음 예정 시간). 데몬이 해당 파일을 관리합니다 — 주기 변경은 `config.toml`에서 하세요.

<Note>
이전 버전의 failproofai로 설정된 머신에서 이 기능을 활성화한 경우,
`failproofai config`를 한 번 실행하세요. 데몬의 서비스 정의에 CLI를 실행하기 위한
추가 항목이 필요하며, 해당 명령을 통해 갱신됩니다.
</Note>

## 감사 전용 감지기

이 감지기들은 실시간으로 아직 강제되지 않는 "비효율적인 행동" 패턴을 감지합니다. 감사 중에만 실행되며 실시간 도구 호출을 절대 차단하지 않습니다.

| 감지기 | 감지 내용 |
|---|---|
| `redundant-cd-cwd` | 명령이 이미 `cwd`에서 실행되고 있음에도 `cd <cwd> && …`로 시작하는 Bash 명령. |
| `prefer-edit-over-read-cat` | 단일 소스 파일에 대한 `cat`/`head`/`tail`/`less`/`more` — `Read` 도구 사용 권장. |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` 인플레이스 편집 — `Edit` 도구 사용 권장. |
| `prefer-write-over-heredoc` | 히어독 / 여러 줄 `echo > file`로 파일 작성 — `Write` 도구 사용 권장. |
| `sleep-polling-loop` | 긴 `sleep N` (≥ 30초) 또는 `while …; sleep …; done` 폴링 루프. |
| `find-from-root` | `find /`, `find /home`, `find /usr` 등 — `cwd`로 범위 제한 권장. |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, 훅 건너뜀. |
| `reread-after-edit` | 같은 세션에서 방금 `Edit`/`Write`한 파일을 `Read`하는 경우. |

## 캐시

- `~/.failproofai/cache/audit/<sha1>.json`의 **트랜스크립트별 캐시**는 `(mtime, size, engineVersion, detectorVersion)`을 키로 사용합니다 — 트랜스크립트나 정책/감지기 코드가 변경되면 자동으로 무효화됩니다. 각 항목에는 **TTL 메타데이터**로 `cachedAt` 타임스탬프도 저장됩니다 (캐시 키의 일부가 아님). **7일**이 지난 항목은 오래된 결과가 진화하는 감지기 의도보다 오래 유지되지 않도록 읽기 시 거부됩니다.
- `~/.failproofai/audit-dashboard.json`의 **전체 결과 캐시** (모드 0600). 대시보드가 재실행 없이 탐색 즉시 렌더링될 수 있게 합니다. **7일 TTL**이 지나면 읽기 시 거부됩니다 — `/audit`은 빈 상태로 대체되며 새 실행을 요청합니다. 리포트 하단의 `[ re-audit now ]`를 클릭해 새로 고치세요 — 재감사는 `noCache: true`를 전송하여 트랜스크립트별 캐시를 우회하고 캐시된 결과 대신 모든 트랜스크립트를 재스캔합니다. 실행은 상단 고정 스트립을 통해 진행 상황을 스트리밍하고 성공 시 결과를 제자리에서 교체합니다 (페이지 새로 고침 없음; 재감사 실패 시 이전 리포트 유지).

## 참고 사항

- **수정 없음.** 감사는 읽기 전용 모드로 다시 실행됩니다. `warn-repeated-tool-calls`는 세션별 사이드카가 수정될 수 있어 건너뜁니다.
- **워크플로 정책 건너뜀.** `require-*-before-stop` 정책은 `Stop` 이벤트와 라이브 git 상태에 대한 `execSync`에서만 실행됩니다 — "2025년에 어떤 일이 일어났을까"라는 의미 있는 해석이 없으므로 감사 횟수에 표시되지 않습니다.
- **커스텀 정책 건너뜀.** 사용자가 제공한 커스텀 훅은 다시 실행되지 않습니다 (원래 세션 이후 변경되었을 수 있음).
