<Note>
  **베타 기능.** 감사 기능은 초기 피드백을 수집하는 동안 베타로 제공됩니다.
  디텍터 카탈로그와 리포트 형식은 다음 안정 버전 출시 전에 변경될 수 있습니다.
  이상한 점이 있으면 이슈를 열어주세요.
</Note>

감사 기능은 과거 에이전트 CLI 트랜스크립트를 failproofai의 정책 엔진을 통해 재실행하고,
**`/audit` 대시보드 페이지**에 공유 가능한 시각적 리포트를 렌더링합니다 —
에이전트의 아키타입, 0~100점 점수, 그리고 어떤 정책이 무엇을 포착했을지 정확히 보여줍니다.

## 실행 방법

세 가지 방법 모두 동일한 `/audit` 리포트로 이동합니다.

<CodeGroup>

```bash npx (설치 불필요)
npx -y failproofai audit
```

```bash failproofai audit
failproofai audit
```

```bash failproofai (대시보드)
failproofai
```

</CodeGroup>

<CardGroup cols={3}>
  <Card title="설치 불필요" icon="bolt">

    대시보드를 열어줍니다 — 사전 설치가 필요 없습니다.
  </Card>
  <Card title="CLI에서 실행" icon="terminal">
    `failproofai audit`은 터미널에서 스캔을 실행한 후,

  </Card>
  <Card title="대시보드에서 실행" icon="gauge">

  </Card>

<Tip>
  `failproofai audit -h` (또는 `--help`)를 실행하면 사용법을 확인할 수 있습니다.
  감사는 **완전 오프라인**으로 실행됩니다 — 계정이나 네트워크가 필요 없으며 —
  `Ctrl+C`로 중지할 때까지 대시보드가 계속 서비스됩니다.
</Tip>

대시보드는 이 머신의 과거 에이전트 CLI 트랜스크립트(Claude Code, Codex, Copilot, Cursor, OpenCode, Pi)를 스캔하고, failproofai가 차단하도록 설계된 작업들을 에이전트가 얼마나 자주 수행했는지 보고합니다 — 환경변수 체크, 강제 푸시, 불필요한 `cd <cwd>` 접두어, sleep 폴링 루프, 방금 편집한 파일 재읽기 등이 포함됩니다.

각 트랜스크립트에 대해 모든 도구 사용 이벤트는 39개의 내장 정책 **및** 런타임 정책으로 아직 커버되지 않는 패턴을 포착하는 8개의 감사 전용 디텍터를 통해 재실행됩니다. 집계된 횟수는 모든 세션에 걸쳐 정책/디텍터별로 표시됩니다.

## 제공 내용

`/audit` 페이지는 단일 화면의 공유 가능한 **포스터**와 그 아래 네 개의 섹션으로 구성됩니다:

1. **포스터** — 에이전트의 정체성을 한눈에: **아키타입** (8가지 중 하나 — `optimist`, `cowboy`, `explorer`, `goldfish`, `paranoid architect`, `precision builder`, `hammer`, `ghost`), 페르소나 키워드, 해당 아키타입의 희귀도, 그리고 등급 밴드가 있는 **0~100점 점수** (`S`부터 `bottom tier`까지). 공유용으로 설계 — X나 LinkedIn에 게시하거나 PNG로 다운로드할 수 있습니다.
2. **`// strengths`** — 에이전트가 이미 잘하고 있는 것들을 스캔의 실제 수치로 표시 (예: 깨끗한 도구 호출 %, `0`번의 main 푸시 시도). 관련 정책에 클린 기록이 있는 경우에만 표시됩니다.
3. **`// quirks`** — 놓친 것들: failproofai가 포착했을 동작의 순위별 테이블 — *마지막 발생 시점*, *놓친 내용* (및 차단했을 내장 정책), *심각도*, 그리고 얼마나 자주 *발생했는지* (`new` / `recurring` / `N× seen`).
4. **`// how to improve`** — 처방된 수정 목록: 복사-붙여넣기 가능한 `failproofai policy add <slug>`가 있는 정책별 행, **모두 설치** 버튼으로 모든 권장 사항을 한 번에 활성화하고 그렇게 했을 때의 **예상 점수**를 표시합니다.
5. **`// come back better`** — 습관 만들기: 재감사 이메일 **알림** 설정 (`3d` / `7d` / `14d` / `30d`) 또는 지금 재감사, **친구 초대**로 직접 감사를 실행하도록 안내 (failproof.ai에서 발송, 수신인에 참조 포함). 알림과 초대는 로그인이 필요합니다.

## 예약된 감사

**failproofaid 데몬**을 실행하는 경우 ([`failproofai config`](/ko/cli/install-policies) 참조),
예약에 따라 감사를 재실행하고 백그라운드에서 `/audit` 리포트를 새로 고칠 수 있습니다.
스캔은 이 머신의 모든 에이전트 세션 트랜스크립트 *내용*을 읽기 때문에
**기본적으로 비활성화**되어 있으며 — 직접 요청하기 전까지는 타이머로 스캔이 실행되지 않습니다.

`~/.failproofai/config.toml`에서 활성화:

```toml
[audit]
auto = true
interval_days = 7
```

| 키 | 의미 |
|---|---|
| `auto` | `true`로 설정하면 예약 스캔이 활성화됩니다. 다른 값 — 없음, `false`, `"yes"` — 은 비활성화입니다. |
| `interval_days` | 스캔 간격(일). 1~90으로 고정되며; `0`, 음수, 숫자가 아닌 값은 `7`로 대체됩니다. |

- 예약은 **실제 시계** 기준이므로 절전 및 재부팅 후에도 유지됩니다: 예정 시간을 지나 절전 상태였던 노트북은 깨어날 때 **한 번** 실행되며, 밀린 작업은 누적되지 않습니다.
- 각 실행은 별도의 저우선순위(`nice 19`) 프로세스로 — 데몬의 훅 경로가 아니므로 도구 호출 응답을 위해 항상 비어 있습니다.
- `failproofai audit` 또는 대시보드의 재실행이 이미 진행 중인 경우 스캔은 건너뛰고, 실패로 처리하지 않고 잠시 후 재시도합니다.
- 진행 상황은 `~/.failproofai/state/audit-schedule.json`에 기록됩니다 (마지막 실행, 다음 예정 시각). 데몬이 해당 파일을 관리하며 — 주기는 `config.toml`에서 변경하세요.

<Note>
이전 버전의 failproofai로 설정된 머신에서 이 기능을 활성화한 경우,
`failproofai config`를 한 번 실행하세요. 데몬의 서비스 정의에 CLI를 실행하기 위한
추가 항목이 필요하며, 해당 명령으로 갱신됩니다.
</Note>

## 감사 전용 디텍터

이 디텍터들은 실시간으로 (아직) 적용되지 않는 "잘못된 동작" 패턴을 감지합니다. 감사 중에만 실행되며 실시간 도구 호출을 차단하지 않습니다.

| 디텍터 | 집계 내용 |
|---|---|
| `redundant-cd-cwd` | 명령이 이미 `cwd`에서 실행됨에도 `cd <cwd> && …`로 시작하는 Bash 명령. |
| `prefer-edit-over-read-cat` | 단일 소스 파일에 대한 `cat`/`head`/`tail`/`less`/`more` — `Read` 도구를 사용하세요. |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` 인플레이스 편집 — `Edit` 도구를 사용하세요. |
| `prefer-write-over-heredoc` | Heredoc / 멀티라인 `echo > file` 파일 쓰기 — `Write` 도구를 사용하세요. |
| `sleep-polling-loop` | 긴 `sleep N` (≥ 30초) 또는 `while …; sleep …; done` 폴링 루프. |
| `find-from-root` | `find /`, `find /home`, `find /usr` 등 — `cwd`로 범위를 좁히세요. |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, 훅 건너뜀. |
| `reread-after-edit` | 같은 세션에서 `Edit`/`Write` 직후 해당 파일을 `Read`하는 경우. |

## 캐시

- **트랜스크립트별 캐시** `~/.failproofai/cache/audit/<sha1>.json`에 `(mtime, size, engineVersion, detectorVersion)` 키로 저장 — 트랜스크립트나 정책/디텍터 코드가 변경되면 자동으로 무효화됩니다. 각 항목은 **TTL 메타데이터**로 `cachedAt` 타임스탬프도 저장합니다(캐시 키의 일부는 아님). **7일**이 지난 항목은 읽기 시 거부되므로 장기간 유지된 결과가 발전하는 디텍터 의도보다 오래 남지 않습니다.
- **전체 결과 캐시** `~/.failproofai/audit-dashboard.json` (모드 0600). 대시보드가 재실행 없이 탐색 시 즉시 렌더링될 수 있도록 합니다. **7일 TTL**이 지나면 읽기 시 거부되며 — `/audit`은 빈 상태로 폴백하고 새 실행을 요청합니다. 리포트 하단의 `[ re-audit now ]`를 클릭하면 새로 고침할 수 있습니다 — 재감사는 `noCache: true`를 전송하므로 트랜스크립트별 캐시를 우회하고 캐시된 결과 대신 모든 트랜스크립트를 다시 스캔합니다. 실행 진행 상황은 상단의 고정 스트립으로 스트리밍되고, 성공 시 결과를 그 자리에서 교체합니다(페이지 새로 고침 없음; 재감사 실패 시 이전 리포트가 유지됩니다).

## 참고 사항

- **변경 없음.** 감사는 읽기 전용 모드로 재실행됩니다. `warn-repeated-tool-calls`는 세션별 사이드카가 수정될 수 있으므로 건너뜁니다.
- **워크플로 정책 건너뜀.** `require-*-before-stop` 정책은 `Stop` 이벤트와 라이브 git 상태에 대한 `execSync`에서만 실행됩니다 — "2025년에 어떻게 되었을까"라는 의미 있는 해석이 없으므로 감사 집계에 나타나지 않습니다.
- **커스텀 정책 건너뜀.** 사용자가 제공한 커스텀 훅은 재실행되지 않습니다 (원본 세션 이후 변경되었을 수 있음).
