```bash
failproofai migrate --dry-run   # 계획만 출력하고 아무것도 변경하지 않음
failproofai migrate             # 실제 실행
```

대부분의 경우 이 명령을 직접 입력할 필요는 없습니다. 업그레이드 후 처음 명령을 실행할 때 자동으로 실행되며, [`failproofai update`](/ko/cli/update)에도 포함되어 있습니다. 실행 전에 계획을 확인하거나 마이그레이션만 단독으로 실행하고 싶을 때 직접 사용하세요.

## 버전이 아닌 레이아웃 기준

`~/.failproofai/VERSION`에는 **레이아웃** 번호가 기록됩니다. 이는 릴리스 버전이 아니라 디렉토리 구조를 나타냅니다. 마이그레이션은 이 번호를 기준으로 동작하므로, 버전을 크게 건너뛰어도 부담이 없습니다.

- npm 버전은 릴리스마다 바뀌며, 두 레이아웃 사이에 수십 개의 릴리스가 있을 수 있습니다.
- 따라서 **레이아웃 변경 없이** 서른 번의 릴리스를 건너뛴 머신은 마이그레이션을 **한 번도 실행하지 않습니다**. 불필요한 no-op 서른 번이 발생하지 않습니다.
- 여러 레이아웃을 한 번에 건너뛰는 경우, 각 단계가 순서대로 실행되며 각 단계는 자신의 시작과 끝만 알고 있습니다.

이는 npm이 설치된 패키지를 자체적으로 업데이트할 수 없기 때문에 중요합니다. 한 버전에 수개월간 머물다가 여러 레이아웃을 한 번에 건너뛰는 상황은 예외적인 케이스가 아니라 일반적인 경우입니다.

## Dry run

`--dry-run`은 실행될 체인과 먼저 저장될 파일들을 정확하게 출력하며, 마이그레이션, 백업, 기록 항목 등 아무것도 변경하지 않습니다.

```
Layout 2 on disk; this build speaks 3.
1 step(s) would run:
  2 → 3  layout 2 → 3: carry config.toml and credentials.toml into JSON, move
         custom-policies/ back up into policies/, nest the policy config at the root

These would be copied to ~/.failproofai/migrations/backup-layout2 first:
  VERSION
  config.toml
  credentials.toml
```

## 보존되는 항목과 재생성되는 항목

홈 디렉토리의 모든 경로는 보유하는 데이터의 종류를 나타내며, 이에 따라 마이그레이션 시 삭제 여부가 결정됩니다. 규칙은 다음과 같습니다. **파생되거나 다시 가져올 수 있는 데이터는 삭제될 수 있으며, 사용자가 직접 입력한 데이터, 아직 전달되지 않은 데이터, 머신을 식별하는 데이터는 보존됩니다.**

| 보존 | 재생성 또는 재취득 |
|---|---|
| `config.json` — 설정, `daemon.configured`, 추가 캡처 경로 | 감사 캐시 |
| `credentials.json` — 클라우드 등록 정보 | 클라우드 관리 배포 (다음 폴링 시 재취득 및 다이제스트 검증) |
| `policies-config.json` — 정책 선택 및 파라미터 | 데몬 임시 상태 |
| `policies/` — 사용자 정의 정책 파일 및 임포트된 헬퍼 파일 | |
| `hook-activity/` — 대시보드에서 읽는 결정 로그 | |
| 업로드 대기 중인 미전달 이벤트 | |
| `cursors/` — 콜렉터 워터마크 | |
| `bin/`의 데몬 바이너리 | |

<Note>
  미전달 이벤트는 삭제하면 복구가 불가능하기 때문에 보존됩니다. 단순히 느린 것이 아니라 영구적인 손실이 됩니다. 콜렉터의 워터마크가 이미 스풀에 있는 항목보다 앞으로 진행되었기 때문에, 해당 트랜스크립트 범위를 다시 읽을 수 없게 됩니다. 마이그레이션은 완료 즉시 데몬에게 스풀에 있는 내용을 전달하도록 요청하므로, 일반적으로 보존할 항목이 남아 있지 않습니다.
</Note>

*최신* 버전이 `config.json`, `credentials.json`, `policies-config.json`에 기록한 키도 이전 버전 리더에 의해 삭제되지 않고 보존됩니다.

## 남겨지는 기록

```
~/.failproofai/migrations/
  applied.json                 단계별 항목: 레이아웃, CLI, 타임스탬프, 소요 시간, 결과
  backup-layout<n>/            첫 번째 단계 실행 전에 복사된 중요 파일들
```

`applied.json`은 업그레이드 후 문제가 발생했을 때 가장 먼저 확인해야 할 질문인 "이 머신이 실제로 어떤 과정을 거쳤는가"에 대한 답을 제공합니다. 버그 리포트에 첨부하세요.

백업은 전체 디렉토리 복사본이 아닌 의도적으로 작은 크기로 유지됩니다. 마이그레이션은 설계상 더 이상 복구 불가능한 항목을 삭제하지 않으므로, 보험이 필요한 경우는 *단계의 결함*뿐이며, 이 몇 가지 파일이 그러한 결함의 영향을 받는 부분입니다.

## 단계 실패 시

해당 지점에서 체인이 중지됩니다. `VERSION`은 완료된 단계에 의해서만 스탬프가 찍히므로, 홈 디렉토리는 이전 레이아웃으로 표시된 채 유지되고 다음 명령 실행 시 재시도됩니다. 불완전한 마이그레이션으로 인해 홈 디렉토리가 현재 상태로 표시되는 일은 없습니다. 해당 단계는 `applied.json`에 `"ok": false`로 기록되며, 백업은 생성된 위치에 그대로 유지됩니다.

## 더 최신 홈 디렉토리는 마이그레이션되지 않고 거부됩니다

`~/.failproofai/`가 현재 실행 중인 failproofai보다 **더 최신** 버전에 의해 작성된 경우, 명령이 중지되고 업그레이드를 권장합니다. 해당 데이터는 정상이며 최신 CLI로 읽을 수 있습니다. 데이터를 "앞으로" 마이그레이션하는 개념 자체가 존재하지 않으며, 초기화하면 복구 가능한 데이터가 손실됩니다.

```
This machine's failproofai directory was written by a newer version (layout 4;
this build speaks 3). Upgrade rather than migrate:
  npm install -g failproofai@latest
```

데몬도 동일한 규칙을 적용합니다. `failproofaid`는 이해하지 못하는 레이아웃에 대해 시작을 거부하며, 이동된 경로를 읽고 쓰려 하지 않습니다.
