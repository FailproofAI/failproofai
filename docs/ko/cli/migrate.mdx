```bash
failproofai migrate --dry-run   # 계획만 출력하고 아무것도 변경하지 않음
failproofai migrate             # 실제 실행
```

대부분의 경우 직접 입력할 필요가 없습니다. 업그레이드 후 첫 번째 명령 실행 시 자동으로 수행되며, [`failproofai update`](/ko/cli/update)에도 포함되어 있습니다. 실행 전에 계획을 확인하거나, 마이그레이션만 단독으로 실행하고 싶을 때 직접 사용하세요.

## 버전이 아닌 레이아웃 기준

`~/.failproofai/VERSION`에는 **레이아웃** 번호가 기록됩니다. 이는 디렉터리의 구조를 나타내는 번호로, 해당 파일을 작성한 릴리즈 버전과는 다릅니다. 마이그레이션은 이 번호를 기준으로 실행되므로, 버전을 많이 건너뛰더라도 비용이 거의 들지 않습니다.

- npm 버전은 릴리즈마다 변경되며, 두 레이아웃 사이에 수십 개의 버전이 존재할 수 있습니다.
- 따라서 **레이아웃 변경 없이** 서른 개의 릴리즈를 건너뛴 머신은 마이그레이션을 **한 번도** 실행하지 않습니다. 무의미한 작업 서른 번이 아닙니다.
- 여러 레이아웃을 한 번에 건너뛴 머신은 각 단계를 순서대로 실행하며, 각 단계는 자신의 시작과 끝만 알면 됩니다.

npm은 설치된 패키지를 자체적으로 업데이트할 수 없기 때문에 이 방식이 중요합니다. 한 버전에서 몇 달씩 머물다가 여러 레이아웃을 한 번에 넘어가는 상황은 예외적인 경우가 아니라 일반적인 경우입니다.

## 드라이 런

`--dry-run`은 실행될 체인과 사전에 저장될 파일 목록을 출력하며, 마이그레이션, 백업, 이력 기록 등 아무것도 실제로 변경하지 않습니다.

```
Layout 2 on disk; this build speaks 3.
1 step(s) would run:
  2 → 3  layout 2 → 3: carry config.toml and credentials.toml into JSON, move
         custom-policies/ back up into policies/, nest the policy config at the root

These would be copied to ~/.failproofai/migrations/backup-layout2 first:
  VERSION
  config.toml
  credentials.toml
```

## 보존되는 데이터와 재구성되는 데이터

홈 디렉터리의 각 경로는 보유한 데이터의 종류를 선언하며, 이에 따라 마이그레이션이 해당 데이터를 삭제할 수 있는지 결정됩니다. 원칙은 다음과 같습니다. **파생되거나 다시 가져올 수 있는 데이터는 삭제될 수 있지만, 직접 입력한 데이터, 아직 전송되지 않은 데이터, 머신을 식별하는 데이터는 모두 보존됩니다.**

| 보존됨 | 재구성 또는 재취득 |
|---|---|
| `config.json` — 설정, `daemon.configured`, 추가 캡처 경로 | 감사 캐시 |
| `credentials.json` — 클라우드 등록 정보 | 클라우드 관리 배포 (다음 폴링 시 재취득 및 다이제스트 검증) |
| `policies-config.json` — 정책 선택 및 파라미터 | 데몬 임시 상태 |
| `policies/` — 직접 작성한 정책 파일 및 해당 파일에서 가져오는 헬퍼 | |
| `hook-activity/` — 대시보드가 읽는 결정 로그 | |
| 업로드 대기 중인 미전송 이벤트 | |
| `cursors/` — 콜렉터 워터마크 | |
| `bin/`의 데몬 바이너리 | |

<Note>
  미전송 이벤트는 삭제하지 않고 보존합니다. 손실이 발생하면 복구가 느린 게 아니라 영구적이기 때문입니다. 콜렉터의 워터마크가 스풀에 쌓인 데이터보다 이미 앞서 있기 때문에, 해당 트랜스크립트 범위는 다시 읽히지 않습니다. 마이그레이션은 완료되는 즉시 데몬에 스풀에 쌓인 데이터를 전송하도록 요청하므로, 일반적으로는 보존할 데이터가 남아 있지 않습니다.
</Note>

*더 최신* 버전이 `config.json`, `credentials.json`, `policies-config.json`에 기록한 키도 이전 버전의 리더에 의해 삭제되지 않고 보존됩니다.

## 마이그레이션 기록

```
~/.failproofai/migrations/
  applied.json                 각 단계별 항목: 레이아웃, CLI, 타임스탬프, 소요 시간, 결과
  backup-layout<n>/            첫 번째 단계 실행 전에 대체 불가능한 파일을 복사해 둔 백업
```

`applied.json`은 "이 머신이 실제로 어떤 과정을 거쳤는가"에 대한 답을 제공합니다. 업그레이드 후 문제가 발생했을 때 가장 먼저 확인해야 할 파일이며, 버그 리포트에 첨부해 주세요.

백업은 디렉터리 전체를 복사하는 대신 의도적으로 작게 유지됩니다. 마이그레이션은 설계상 대체 불가능한 데이터를 삭제하지 않으므로, 보험이 필요한 경우는 *단계 내 결함*이며, 결함이 발생할 경우 영향을 받는 파일은 이 몇 개뿐입니다.

## 단계 실패 시

해당 단계에서 체인이 중단됩니다. `VERSION`은 완료된 단계에서만 업데이트되므로, 홈 디렉터리는 이전 레이아웃으로 표시된 채 유지되고 다음 명령 실행 시 재시도됩니다. 부분적으로 마이그레이션이 완료된 상태에서 현재 버전으로 표시되는 일은 없습니다. 해당 단계는 `"ok": false`와 함께 `applied.json`에 기록되며, 백업은 생성된 위치에 그대로 남아 있습니다.

## 더 새로운 홈 디렉터리는 마이그레이션 거부

`~/.failproofai/`가 현재 실행 중인 failproofai보다 **더 최신** 버전으로 작성된 경우, 명령이 중단되고 업그레이드를 안내합니다. 해당 데이터는 정상 상태이며 더 최신 CLI에서 읽을 수 있습니다. "앞으로" 마이그레이션하는 것은 존재하지 않는 개념이며, 초기화할 경우 복구 가능한 데이터가 손실됩니다.

```
This machine's failproofai directory was written by a newer version (layout 4;
this build speaks 3). Upgrade rather than migrate:
  npm install -g failproofai@latest
```

데몬에도 동일한 규칙이 적용됩니다. `failproofaid`는 인식할 수 없는 레이아웃에 대해 실행을 거부하며, 이동된 경로를 읽고 쓰는 대신 시작 자체를 하지 않습니다.
