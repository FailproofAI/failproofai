```bash
failproofai migrate --dry-run   # 계획만 출력하고 아무것도 변경하지 않음
failproofai migrate             # 실제 실행
```

대부분의 경우 이 명령을 직접 입력할 필요가 없습니다. 업그레이드 후 첫 번째 명령 실행 시 자동으로 실행되며, [`failproofai update`](/ko/cli/update)에도 포함되어 있습니다. 실행 계획을 미리 확인하고 싶거나, 마이그레이션만 단독으로 실행하고 싶을 때 직접 사용하세요.

## 버전이 아닌 레이아웃 기준

`~/.failproofai/VERSION` 파일에는 **레이아웃** 번호가 기록됩니다. 이는 특정 릴리스 버전이 아닌 디렉토리의 구조를 나타내는 번호입니다. 마이그레이션은 이 번호를 기준으로 동작하기 때문에 긴 공백도 부담 없이 처리됩니다:

- npm 버전은 릴리스마다 변경되며, 두 레이아웃 사이에도 수십 개의 버전이 존재할 수 있습니다.
- 따라서 **레이아웃 변경 없이** 서른 번의 릴리스를 건너뛴 머신은 마이그레이션을 **한 번도** 실행하지 않습니다. 아무 의미 없는 작업 서른 번이 실행되는 것이 아닙니다.
- 여러 레이아웃을 한 번에 건너뛴 경우에는 각 단계가 순서대로 실행되며, 각 단계는 자신의 시작과 끝만 알고 있습니다.

npm은 설치된 패키지를 자체적으로 업데이트할 수 없기 때문에 이 방식이 중요합니다. 한 버전에 몇 달간 머물다가 여러 레이아웃을 한꺼번에 건너뛰는 것은 드문 경우가 아니라 일반적인 상황입니다.

## 드라이 런

`--dry-run`은 실행될 단계의 순서와 사전에 저장될 파일 목록을 정확히 출력하며, 마이그레이션, 백업, 기록 등 실제로는 아무것도 변경하지 않습니다:

```
Layout 2 on disk; this build speaks 3.
1 step(s) would run:
  2 → 3  layout 2 → 3: carry config.toml and credentials.toml into JSON, move
         custom-policies/ back up into policies/, nest the policy config at the root

These would be copied to ~/.failproofai/migrations/backup-layout2 first:
  VERSION
  config.toml
  credentials.toml
```

## 보존되는 항목과 재생성되는 항목

홈 디렉토리의 각 경로는 보유하는 데이터의 종류를 선언하며, 이를 기준으로 마이그레이션 시 삭제 가능 여부가 결정됩니다. 규칙은 다음과 같습니다: **파생되거나 재취득 가능한 데이터는 삭제될 수 있으며, 직접 입력한 데이터, 아직 전송되지 않은 데이터, 머신을 식별하는 데이터는 보존됩니다.**

| 보존 항목 | 재생성 또는 재취득 항목 |
|---|---|
| `config.json` — 설정, `daemon.configured`, 추가 캡처 경로 | 감사 캐시 |
| `credentials.json` — 클라우드 등록 정보 | 클라우드 관리 배포 (다음 폴링 시 재취득 및 다이제스트 검증) |
| `policies-config.json` — 정책 선택 및 파라미터 | 데몬 임시 상태 |
| `policies/` — 직접 작성한 정책 파일 및 해당 파일이 임포트하는 헬퍼 | |
| `hook-activity/` — 대시보드가 읽는 결정 로그 | |
| 아직 업로드 대기 중인 미전송 이벤트 | |
| `cursors/` — 컬렉터 워터마크 | |
| `bin/`의 데몬 바이너리 | |

<Note>
  미전송 이벤트는 삭제되지 않고 보존됩니다. 삭제될 경우 속도가 느린 것이 아니라 영구적으로 손실되기 때문입니다. 컬렉터의 워터마크가 이미 스풀에 쌓인 데이터를 지나쳤기 때문에, 트랜스크립트의 해당 범위를 다시 읽을 방법이 없습니다. 마이그레이션은 완료 직후 데몬이 스풀에 남은 데이터를 즉시 전송하도록 요청하므로, 실제로는 보존할 항목이 남지 않는 경우가 대부분입니다.
</Note>

*최신* 버전이 `config.json`, `credentials.json` 또는 `policies-config.json`에 기록한 키는 이전 버전의 리더가 읽더라도 삭제되지 않고 보존됩니다.

## 남겨지는 기록

```
~/.failproofai/migrations/
  applied.json                 단계별 기록: 레이아웃, CLI, 타임스탬프, 소요 시간, 결과
  backup-layout<n>/            첫 번째 단계 실행 전 복사된 대체 불가 파일들
```

`applied.json`은 "이 머신이 실제로 어떤 과정을 거쳤는가"라는 질문에 답합니다. 업그레이드 후 문제가 발생했을 때 가장 먼저 확인해야 할 파일이며, 버그 리포트에 첨부하세요.

백업은 디렉토리 전체를 복사하지 않고 의도적으로 작게 유지됩니다. 마이그레이션 설계상 대체 불가 항목은 더 이상 삭제되지 않기 때문에, 실질적인 위험 요소는 *단계 내의 결함*이며, 이 몇 개의 파일이 그 피해를 직접 받는 부분입니다.

## 단계 실패 시

해당 지점에서 체인이 중단됩니다. `VERSION`은 완료된 단계에 의해서만 갱신되므로, 홈 디렉토리는 이전 레이아웃으로 유지되고 다음 명령 실행 시 재시도됩니다. 부분적인 마이그레이션 결과로 홈이 최신 상태로 표시되는 일은 없습니다. 해당 단계는 `applied.json`에 `"ok": false`로 기록되며, 백업은 생성된 위치에 그대로 남습니다.

## 더 최신 홈 디렉토리는 마이그레이션 거부

현재 실행 중인 failproofai보다 **최신** 버전이 `~/.failproofai/`를 작성한 경우, 명령이 중단되고 업그레이드를 안내합니다. 해당 데이터는 정상이며 최신 CLI로 읽을 수 있습니다. "앞으로 마이그레이션"하는 개념 자체가 존재하지 않으며, 초기화하면 복구 가능한 데이터가 손실됩니다.

```
This machine's failproofai directory was written by a newer version (layout 4;
this build speaks 3). Upgrade rather than migrate:
  npm install -g failproofai@latest
```

데몬도 동일한 규칙을 적용합니다. `failproofaid`는 자신이 지원하지 않는 레이아웃에 대해 이동된 경로를 읽고 쓰는 대신, 해당 레이아웃을 처리하는 것을 거부하고 시작을 중단합니다.
