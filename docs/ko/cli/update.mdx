```bash
npm install -g failproofai@latest && failproofai update
```

전체 업그레이드 과정은 이것이 전부입니다. `npm`은 CLI를 교체하고, `failproofai update`가 나머지를 처리합니다.

## 두 번째 명령이 필요한 이유

`npm install -g`는 단 하나, CLI만 교체합니다. failproofai 설치의 다른 두 구성 요소는 의도적으로 패키지 외부에 존재하며, npm 실행 시 어느 것도 이동하지 않습니다:

- **`~/.failproofai/`**: 설정, 클라우드 등록, 정책 선택 및 기록이 저장됩니다. 새 버전은 이를 다르게 구성할 수 있으며, 재구성은 두 가지 구조를 모두 아는 코드가 처리해야 합니다.
- **`failproofaid` 데몬 바이너리**: `~/.failproofai/bin/failproofaid-<version>` 경로에 위치합니다. 이는 의도적으로 `node_modules` 내부에 *두지 않습니다*. 실행 중인 서비스 아래의 파일을 교체하는 업그레이드는 라이브 데몬을 다른 소스에서 빌드된 바이너리로 연결하게 되고, 패키지를 제거하면 서비스가 부팅마다 크래시 루프에 빠지게 됩니다.

따라서 `npm install -g`만 실행하면 CLI는 새로운 버전이지만 데몬은 그렇지 않습니다. `failproofaid`는 자신이 인식하지 못하는 홈 디렉터리 레이아웃에 대해 시작을 거부합니다. 이는 불일치를 조용히 넘기지 않고 명시적으로 알리는 방식입니다. 두 부분을 함께 맞추는 것이 바로 `failproofai update`의 역할입니다.

## 수행 내용

<Steps>
  <Step title="대기 중인 레이아웃 마이그레이션 실행">
    `~/.failproofai/VERSION`에 기록된 레이아웃을 읽고, 현재 버전이 사용하는 레이아웃으로 전환하는 단계를 실행합니다. 대부분의 경우 아무 작업도 필요하지 않습니다 — [`failproofai migrate`](/ko/cli/migrate)를 참조하세요.
  </Step>
  <Step title="일치하는 데몬 바이너리 배치">
    npm이 이미 다운로드한 플랫폼 패키지에서 가능한 경우 네트워크 없이 처리하며, 그렇지 않은 경우 정확한 버전의 릴리스 에셋에서 가져옵니다. 사용 전에 SHA-256로 검증됩니다.
  </Step>
  <Step title="서비스 재시작 및 복구 확인">
    가정이 아닌 실제 프로브를 통해 확인합니다. 서비스 관리자는 프로세스가 포크되는 즉시 활성 상태로 보고하지만, 이는 실제로 동작하는 것과 다릅니다.
  </Step>
</Steps>

## 옵션

| 플래그 | 효과 |
|--------|------|
| `--no-daemon` | 홈 디렉터리만 마이그레이션하고 데몬은 현재 버전으로 유지합니다. |

<Warning>
  `--no-daemon`을 사용하면 버전이 맞지 않는 데몬이 그대로 남습니다. 데몬을 필요로 하도록 설정된 머신에서는 데몬이 응답하지 못하면 모든 훅 이벤트가 **차단(fails closed)** 됩니다. 마이그레이션된 홈에 대해 시작을 거부하는 데몬은 응답할 수 없습니다. 데몬 절반도 함께 실행하는 것을 권장합니다.
</Warning>

## 문제가 발생한 경우

명령이 0이 아닌 종료 코드로 종료되며 어느 절반이 실패했는지 알려줍니다. 알아두어야 할 두 가지 경우:

- **마이그레이션 단계가 완료되지 않은 경우.** 홈 디렉터리는 *이전* 레이아웃으로 표시된 채 남으므로, 다음 명령 실행 시 재시도합니다. 부분 마이그레이션이 성공한 것처럼 홈이 현재 버전으로 표시되는 일은 절대 없습니다. 설정 및 등록 정보의 복사본이 실행 전에 `~/.failproofai/migrations/backup-layout<n>/`에 저장됩니다.
- **비밀번호 없이 데몬을 재시작할 수 없는 경우.** `sudo -n`이 의도적으로 사용되므로, 진행 표시 중에는 어떤 프롬프트도 나타나지 않습니다. 명령은 직접 실행해야 할 정확한 명령줄을 출력합니다.

<Note>
  이 과정에서 대화형 설정 마법사는 필요하지 않습니다. 설정, 클라우드 등록 및 정책 선택은 업그레이드 후에도 유지되므로, 마이그레이션된 머신은 이전과 동일하게 정책을 적용합니다. 이는 CI 러너, 플릿 서버, 헤드리스 게이트웨이처럼 아무도 앉아 있지 않는 머신에서 특히 중요합니다.
</Note>

## 자동화

`failproofai update`는 비대화형이며, 아무것도 할 일이 없을 때 실행해도 안전합니다. "no migration was needed"를 출력하고 0으로 종료합니다. 프로비저닝 스크립트나 Dockerfile에서 매 업그레이드 후 실행하는 것이 권장 사용법입니다:

```dockerfile
RUN npm install -g failproofai@latest && failproofai update --no-daemon
```

(이미지 빌드에서는 `--no-daemon`을 사용합니다. 아직 재시작할 서비스가 없기 때문입니다.)
