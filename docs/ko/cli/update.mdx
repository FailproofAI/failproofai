```bash
npm install -g failproofai@latest && failproofai update
```

업그레이드는 이게 전부입니다. `npm`이 CLI를 교체하고, `failproofai update`가 나머지를 처리합니다.

## 두 번째 명령이 필요한 이유

`npm install -g`는 CLI 하나만 교체합니다. failproofai 설치의 다른 두 구성 요소는 의도적으로 패키지 외부에 위치하며, npm이 실행되어도 어느 쪽도 이동하지 않습니다:

- **`~/.failproofai/`** — 설정, 클라우드 등록, 정책 선택, 히스토리가 저장되는 곳입니다. 새 버전은 디렉터리 구조가 달라질 수 있으며, 이 재편은 이전 구조와 새 구조를 모두 아는 코드가 처리해야 합니다.
- **`failproofaid` 데몬 바이너리** — `~/.failproofai/bin/failproofaid-<version>`에 위치합니다. 의도적으로 `node_modules` 외부에 배치되어 있습니다. 실행 중인 서비스 아래에서 파일을 교체하면 다른 소스로 빌드된 바이너리를 가리키게 되고, 패키지를 삭제하면 서비스가 부팅할 때마다 크래시 루프에 빠지게 됩니다.

따라서 `npm install -g`만 실행하면 CLI는 새 버전이지만 데몬은 그렇지 않습니다. `failproofaid`는 자신이 이해하지 못하는 홈 레이아웃에 대해 시작을 거부합니다 — 조용히 넘어가는 방식이 아니라 명확하게 오류를 표시합니다 — 따라서 두 절반을 함께 맞춰야 합니다. `failproofai update`가 바로 그 단계입니다.

## 수행 작업

<Steps>
  <Step title="대기 중인 레이아웃 마이그레이션 실행">
    `~/.failproofai/VERSION`에 기록된 레이아웃을 읽고, 현재 버전이 사용하는 레이아웃으로 전환하는 단계를 실행합니다. 대부분의 경우 아무것도 없습니다 — [`failproofai migrate`](/ko/cli/migrate)를 참고하세요.
  </Step>
  <Step title="일치하는 데몬 바이너리 배치">
    가능한 경우 npm이 이미 다운로드한 플랫폼 패키지에서 가져옵니다(네트워크 불필요). 그렇지 않으면 정확히 이 버전에 해당하는 릴리스 에셋에서 가져오며, 사용 전에 SHA-256 검증을 수행합니다.
  </Step>
  <Step title="서비스 재시작 및 정상 복귀 확인">
    가정이 아닌 실제 프로브로 확인합니다 — 서비스 매니저는 프로세스가 포크되는 순간 활성 상태로 보고하는데, 이는 실제로 작동 중인 것과 다릅니다.
  </Step>
</Steps>

## 옵션

| 플래그 | 효과 |
|--------|------|
| `--no-daemon` | 홈만 마이그레이션하고 데몬은 현재 버전으로 유지합니다. |

<Warning>
  `--no-daemon`을 사용하면 버전이 맞지 않는 데몬이 그대로 남습니다. 데몬을 필요로 하도록 구성된 머신에서는 데몬이 응답하지 못하면 모든 훅 이벤트가 **차단 방향으로 실패**합니다 — 그리고 마이그레이션된 홈에 대해 시작을 거부하는 데몬은 응답할 수 없습니다. 데몬 절반도 함께 실행하는 것을 권장합니다.
</Warning>

## 문제가 발생한 경우

명령은 0이 아닌 종료 코드와 함께 어느 절반이 실패했는지 알려줍니다. 알아두어야 할 두 가지 경우:

- **마이그레이션 단계가 완료되지 않은 경우.** 홈은 *이전* 레이아웃으로 표시된 채로 남아, 다음 명령 실행 시 재시도합니다 — 부분 마이그레이션만으로는 홈이 현재 버전으로 표시되지 않습니다. 실행 전에 설정과 등록 정보의 복사본이 `~/.failproofai/migrations/backup-layout<n>/`에 저장됩니다.
- **비밀번호 없이 데몬을 재시작할 수 없는 경우.** `sudo -n`이 의도적으로 사용되므로 진행 표시 중에 프롬프트가 나타나지 않습니다. 명령은 직접 실행해야 하는 정확한 명령줄을 출력합니다.

<Note>
  이 과정은 대화형 설정 마법사가 필요하지 않습니다. 설정, 클라우드 등록, 정책 선택은 업그레이드 후에도 그대로 유지되므로, 마이그레이션된 머신은 이전과 동일하게 적용됩니다 — 이는 아무도 앞에 앉아 있지 않은 머신, 즉 CI 러너, 플릿 박스, 헤드리스 게이트웨이에서 가장 중요합니다.
</Note>

## 자동화

`failproofai update`는 비대화형이며 할 일이 없을 때도 안전하게 실행할 수 있습니다 — "마이그레이션이 필요하지 않았습니다"라고 보고하고 0으로 종료합니다. 프로비저닝 스크립트나 Dockerfile에서 모든 업그레이드 후에 실행하는 것이 의도된 사용 방식입니다:

```dockerfile
RUN npm install -g failproofai@latest && failproofai update --no-daemon
```

(이미지 빌드에서는 `--no-daemon`을 사용합니다. 아직 재시작할 서비스가 없기 때문입니다.)
