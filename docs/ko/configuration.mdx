failproofai는 JSON 설정 파일을 사용하여 어떤 정책이 활성화되어 있는지, 정책이 어떻게 동작하는지, 그리고 커스텀 정책을 어디서 불러오는지를 제어합니다. 설정은 팀과 쉽게 공유할 수 있도록 설계되어 있습니다. 리포지토리에 커밋하면 모든 개발자가 동일한 에이전트 안전망을 사용할 수 있습니다.

---

## 설정 범위

세 가지 설정 범위가 있으며, 우선순위 순서로 평가됩니다:

| 범위 | 파일 경로 | 용도 |
|------|-----------|------|
| **project** | `.failproofai/policies-config.json` | 리포지토리별 설정, 버전 관리에 커밋 |
| **local** | `.failproofai/policies-config.local.json` | 개인 리포지토리 오버라이드, gitignore 처리 |
| **global** | `~/.failproofai/policies-config.json` | 모든 프로젝트에 적용되는 사용자 수준 기본값 |

failproofai가 훅 이벤트를 받으면 현재 작업 디렉토리에 존재하는 세 파일을 모두 불러와 병합합니다.

### 병합 규칙

**`enabledPolicies`** - 세 범위의 합집합입니다. 어느 수준에서든 활성화된 정책은 적용됩니다.

```text
project:  ["block-sudo"]
local:    ["block-rm-rf"]
global:   ["block-sudo", "sanitize-api-keys"]

resolved: ["block-sudo", "block-rm-rf", "sanitize-api-keys"]  ← 중복 제거된 합집합
```

**`policyParams`** - 특정 정책에 대한 파라미터를 처음으로 정의한 범위가 전적으로 우선합니다. 정책 파라미터 내부 값의 깊은 병합은 이루어지지 않습니다.

```text
project:  block-sudo → { allowPatterns: ["sudo apt-get update"] }
global:   block-sudo → { allowPatterns: ["sudo systemctl status"] }

resolved: { allowPatterns: ["sudo apt-get update"] }   ← project 우선, global 무시
```

```text
project:  (block-sudo 항목 없음)
local:    (block-sudo 항목 없음)
global:   block-sudo → { allowPatterns: ["sudo systemctl status"] }

resolved: { allowPatterns: ["sudo systemctl status"] }  ← global로 폴스루
```

**`customPoliciesPaths` / `customPoliciesPath`** - 어느 한 형태든 먼저 정의한 범위가 우선합니다.

**`disabledCustomPolicies`** - 모든 범위의 합집합입니다. 대시보드에서 명시적 또는 컨벤션 정책 파일의 개별 정책을 끄면 소스 한정 ID가 여기에 기록됩니다. 목록에 없는 정책은 기본적으로 활성화 상태로 유지되며, ID에는 소스 파일 정보가 포함되어 여러 파일에서 동일한 이름의 정책을 독립적으로 제어할 수 있습니다.

**`llm`** - 처음으로 정의한 범위가 우선합니다.

## 설정 파일 형식

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-push-master",
    "sanitize-api-keys",
    "sanitize-jwt",
    "block-env-files",
    "block-read-outside-cwd"
  ],
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    },
    "block-push-master": {
      "protectedBranches": ["main", "release", "prod"]
    },
    "block-rm-rf": {
      "allowPaths": ["/tmp"]
    },
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company"]
    },
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo API key" }
      ]
    },
    "warn-large-file-write": {
      "thresholdKb": 512
    }
  },
  "customPoliciesPath": "/home/alice/myproject/my-policies.js"
}
```

## 필드 참조

### `enabledPolicies`

타입: `string[]`

활성화할 정책 이름 목록입니다. 이름은 `failproofai policies`에서 표시되는 정책 식별자와 정확히 일치해야 합니다. 전체 목록은 [기본 제공 정책](/ko/built-in-policies)을 참조하세요.

`enabledPolicies`에 없는 정책은 `policyParams`에 항목이 있더라도 비활성 상태입니다.

### `policyParams`

타입: `Record<string, Record<string, unknown>>`

정책별 파라미터 오버라이드입니다. 외부 키는 정책 이름이고, 내부 키는 정책별로 다릅니다. 각 정책에서 사용 가능한 파라미터는 [기본 제공 정책](/ko/built-in-policies)에서 확인할 수 있습니다.

정책에 파라미터가 있지만 별도로 지정하지 않으면 정책의 기본값이 사용됩니다. `policyParams`를 전혀 설정하지 않은 사용자는 이전 버전과 동일한 동작을 유지합니다.

정책 파라미터 블록 내의 알 수 없는 키는 훅 실행 시 조용히 무시되지만, `failproofai policies`를 실행하면 경고로 표시됩니다.

#### `hint` (공통 설정)

타입: `string` (선택 사항)

정책이 `deny` 또는 `instruct`를 반환할 때 이유에 추가되는 메시지입니다. 정책 자체를 수정하지 않고도 Claude에게 실행 가능한 지침을 제공할 때 활용하세요.

기본 제공 정책, 커스텀 정책(`custom/`), 프로젝트 컨벤션(`.failproofai-project/`), 사용자 컨벤션(`.failproofai-user/`) 등 모든 정책 유형에서 동작합니다.

```json
{
  "policyParams": {
    "block-force-push": {
      "hint": "Try creating a fresh branch instead."
    },
    "block-sudo": {
      "allowPatterns": ["sudo apt-get"],
      "hint": "Use apt-get directly without sudo."
    },
    "custom/my-policy": {
      "hint": "Ask the user for approval first."
    }
  }
}
```

`block-force-push`가 거부할 때 Claude는 다음과 같이 확인합니다: *"Force-pushing is blocked. Try creating a fresh branch instead."*

문자열이 아닌 값과 빈 문자열은 조용히 무시됩니다. `hint`가 설정되지 않으면 동작은 변경되지 않습니다(하위 호환성 유지).

### `customPoliciesPath`

타입: `string` (절대 경로)

커스텀 훅 정책이 포함된 JavaScript 파일의 경로입니다. `failproofai policies --install --custom <path>`를 실행하면 자동으로 설정됩니다(경로는 저장 전에 절대 경로로 변환됩니다).

파일은 훅 이벤트마다 새로 불러오며 캐싱이 없습니다. 작성 방법은 [커스텀 정책](/ko/custom-policies)을 참조하세요.

### 컨벤션 기반 정책

명시적인 `customPoliciesPath` 외에도, failproofai는 `.failproofai/policies/` 디렉토리에서 정책 파일을 자동으로 탐색하고 불러옵니다:

| 수준 | 디렉토리 | 범위 |
|------|----------|------|
| 프로젝트 | `.failproofai/policies/` | 버전 관리를 통해 팀과 공유 |
| 사용자 | `~/.failproofai/policies/` | 개인용, 모든 프로젝트에 적용 |

<Note>
  정책 파일을 `~/.failproofai/policies/`에 바로 넣으면 됩니다. 같은 위치에 있는
  `cloud-policies/` 폴더는 조직이 이 머신에 배포한 정책을 담고 있습니다.
  탐색은 하위 디렉토리로 내려가지 않으므로 해당 폴더는 스캔되지 않으며,
  `policies/`에 넣은 파일과 충돌할 일이 없습니다.

  `~/.failproofai/policies/custom-policies/`를 사용하던 이전 버전에서 업그레이드하는 경우,
  해당 폴더의 모든 내용(정책 파일, 임포트하는 `lib/` 헬퍼, 읽어들이는 데이터 파일)은
  `failproofai` 명령을 처음 실행할 때 자동으로 상위 폴더로 이동되며, 무엇이 이동되었는지
  알려줍니다.
</Note>

**파일 매칭:** `*policies.{js,mjs,ts}` 패턴과 일치하는 파일만 불러옵니다(예: `security-policies.mjs`, `workflow-policies.js`). 디렉토리의 다른 파일은 무시됩니다.

**설정 불필요:** 컨벤션 정책은 `policies-config.json`에 별도 항목이 필요하지 않습니다. 디렉토리에 파일을 넣기만 하면 다음 훅 이벤트부터 자동으로 적용됩니다.

**통합 로딩:** 프로젝트와 사용자 컨벤션 디렉토리를 모두 스캔합니다. 두 수준에서 일치하는 파일이 모두 불러와집니다(`customPoliciesPath`는 첫 번째 범위 우선 방식인 것과 달리).

자세한 내용과 예제는 [커스텀 정책](/ko/custom-policies)을 참조하세요.

### `llm`

타입: `object` (선택 사항)

AI 호출을 수행하는 정책을 위한 LLM 클라이언트 설정입니다. 대부분의 경우 필요하지 않습니다.

```json
{
  "llm": {
    "model": "claude-sonnet-4-6",
    "apiKey": "sk-ant-..."
  }
}
```

## CLI에서 설정 관리하기

`policies --install` 및 `policies --uninstall` 명령은 에이전트 CLI의 훅 설정 파일(훅 진입점)에 기록하며, `policies-config.json`은 직접 관리하는 파일입니다. 두 파일은 별개입니다:

- **에이전트 CLI 설정** — 각 도구 사용 시 에이전트가 `failproofai --hook <event>`를 호출하도록 지시합니다:
  - **Claude Code**: `~/.claude/settings.json` (사용자), `<cwd>/.claude/settings.json` (프로젝트), `<cwd>/.claude/settings.local.json` (로컬)
  - **OpenAI Codex**: `~/.codex/hooks.json` (사용자), `<cwd>/.codex/hooks.json` (프로젝트) — Codex에는 `local` 범위가 없습니다
  - **GitHub Copilot CLI _(베타)_**: `~/.copilot/hooks/failproofai.json` (사용자), `<cwd>/.github/hooks/failproofai.json` (프로젝트) — Copilot에는 `local` 범위가 없습니다. 훅 항목은 `timeoutSec`와 함께 Copilot의 OS별 `bash`/`powershell` 명령 필드를 사용하며, 파일에는 최상위 `version: 1` 마커가 포함됩니다. Copilot CLI 지원은 **베타**로, 공개 문서에 명시되지 않은 `events.jsonl` 레코드 스키마를 더 많은 실제 세션에서 검증하고 있습니다. **VS Code Copilot Chat 에이전트 모드(미리 보기)**는 `.github/hooks/*.json`, `~/.copilot/hooks/*.json`, `~/.claude/settings.json`(` chat.hookFilesLocations` 설정으로 제어)에서 훅 설정을 읽으며, 동일한 Claude 형태의 `{hookSpecificOutput:{permissionDecision:"deny",…}}` 계약을 사용합니다. 이는 `copilot` 통합과 `claude` 통합(`~/.claude/settings.json`)이 이미 기록하는 경로와 동일하므로, `failproofai policies --install --cli copilot`(또는 `--cli claude`)를 실행하면 **별도의 `vscode` 통합 없이도 VS Code 에이전트 모드에서 즉시 적용됩니다**(VS Code의 탐색 로그에서 직접 확인됨).
  - **Cursor Agent _(베타)_**: `~/.cursor/hooks.json` (사용자), `<cwd>/.cursor/hooks.json` (프로젝트) — Cursor에는 `local` 범위가 없습니다. 훅 항목은 Claude 형태의 `{type, command, timeout}` 구조를 사용하지만(`bash`/`powershell` 분리 없음), Cursor의 [훅 스키마](https://cursor.com/docs/hooks)에 따라 camelCase 이벤트 키(`preToolUse`, `beforeSubmitPrompt`, …) 아래 플랫 배열로 저장됩니다. 파일에는 최상위 `version: 1` 마커가 포함됩니다. 핸들러는 `CURSOR_EVENT_MAP`을 통해 camelCase를 PascalCase로 정규화하므로 기존 기본 제공 정책이 변경 없이 동작합니다. Cursor Agent 지원은 **베타**로, 공개 문서에 명시되지 않은 Cursor의 디스크 상 트랜스크립트 형식을 더 많은 실제 설치에서 검증하고 있습니다.
  - **OpenCode _(베타)_**: `~/.config/opencode/opencode.json` + `~/.config/opencode/plugins/failproofai.mjs` (사용자), `<cwd>/.opencode/opencode.json` + `<cwd>/.opencode/plugins/failproofai.mjs` (프로젝트) — OpenCode에는 `local` 범위가 없습니다. 다른 다섯 CLI와 달리, OpenCode에는 **외부 명령 훅 시스템이 없습니다**: `opencode.json`의 `plugin: []` 배열에 명시적으로 등록된 인프로세스 JS/TS 플러그인을 불러옵니다(`.opencode/plugins/`에서의 자동 탐색은 opencode v1.14.33에서 플러그인 로딩 방식이 **아닙니다**). 설치 시 failproofai 바이너리를 서브프로세스로 호출하고, 바이너리의 Claude 형태 JSON 응답을 플러그인 시맨틱으로 변환하는 소형 플러그인 심이 생성됩니다: 도구 이벤트 거부는 `throw new Error()`(도구 호출 취소), `instruct` 및 `Stop`/`SubagentStop` 거부는 `client.session.prompt(...)`(거부 이유를 다음 사용자 메시지로 제출 — `session.idle`은 알림 전용이고 예외 발생이 no-op이므로 유일한 강제 재시도 채널), allow는 no-op입니다. 심은 도구 이름(소문자 → `OPENCODE_TOOL_MAP`을 통해 PascalCase)과 도구 입력 인자 키(`OPENCODE_TOOL_INPUT_MAP`을 통해 `Read`/`Write`/`Edit`의 camelCase → snake_case, 예: `filePath` → `file_path`, `oldString` → `old_string`)를 정규화한 후 바이너리로 전달합니다. 따라서 `block-read-outside-cwd`, `block-env-files`, `block-secrets-write` 같은 경로 확인 기본 정책이 OpenCode 도구 호출에서도 변경 없이 동작합니다. 세션은 `~/.local/share/opencode/opencode.db`의 OpenCode SQLite DB에 저장되며, 대시보드의 세션 뷰어는 `opencode db --format json` 및 `opencode export <id>`를 통해 읽어옵니다. OpenCode 지원은 **베타**로, 더 많은 버전과 실제 세션에서 동작을 검증하고 있습니다. [OpenCode 플러그인 문서](https://opencode.ai/docs/plugins/)를 참조하세요.
  - **Pi _(베타)_**: `~/.pi/agent/settings.json` (사용자), `<cwd>/.pi/settings.json` (프로젝트) — Pi에는 `local` 범위가 없습니다. Pi는 시작 시 TypeScript 확장 패키지를 로드하며, 설정 파일은 플랫 문자열 배열 `{"packages": ["./relative/path", …]}` 형태입니다. failproofai는 번들된 `pi-extension/` 디렉토리를 가리키는 단일 packages 배열 항목을 기록합니다. 확장은 내부적으로 Pi의 `tool_call`/`user_bash`/`input`/`session_start` 이벤트를 구독하고 `failproofai --hook <Event> --cli pi`를 셸 호출합니다. 핸들러는 `PI_EVENT_MAP`을 통해 underscore_lower_snake_case를 PascalCase로 정규화하므로 기존 기본 제공 정책이 변경 없이 동작합니다. 도구 입력 인자도 `PI_TOOL_INPUT_MAP`을 통해 정규화됩니다(Pi의 Read/Write/Edit는 `file_path` 대신 `path`를 사용하며, 최상위 키 매핑으로 `block-env-files`와 `block-secrets-write`가 동작합니다 — `block-read-outside-cwd`는 이미 `path` 폴백이 있었음). Pi 지원은 **베타**로, Pi의 확장 API와 세션 로그 구조가 안정화되는 동안 검증 중입니다.
  - **Hermes (hermes-agent)**: `~/.hermes/config.yaml` (**사용자 범위만** — Hermes에는 프로젝트/로컬 설정이 없습니다). Hermes는 Slack/Telegram **게이트웨이**이므로, 설치 한 번으로 모든 플랫폼(Slack/Telegram/cli/cron)과 내부 서브에이전트의 도구 호출을 가로챕니다. 훅 항목은 Hermes의 snake_case 이벤트(`pre_tool_call`/`post_tool_call`/`on_session_start`/`on_session_end`/`subagent_stop`)를 키로 하는 `hooks:` 맵 아래 `{command, timeout}` 쌍(timeout은 **초** 단위)입니다. 핸들러는 `HERMES_EVENT_MAP`으로 이벤트를, `HERMES_TOOL_MAP`으로 도구 이름을 정규화하므로 기본 제공 정책이 변경 없이 동작합니다. 설정은 주석 보존 YAML `Document` 라운드트립으로 편집되어 운영자의 다른 설정이 유지되며, 설치 시 `hooks_auto_accept: true`로 설정되어 TTY 없는 헤드리스 게이트웨이에서 동의 프롬프트 없이 훅이 실행됩니다. 평가자는 Hermes의 `{"decision":"block","reason"}` stdout 계약을 출력합니다(Hermes는 종료 코드를 무시). **제한 사항:** Hermes에는 턴 종료 `Stop` 이벤트가 없으므로 `require-*-before-stop` 기본 정책은 동작하지 않습니다(오류가 아닌 해당 없음); `instruct`는 allow-with-logged-note로 저하됩니다(추가 컨텍스트 채널 없음); 출력 시크릿 리댁션(`sanitize-*`)은 셸 훅 계약으로 도구 출력을 재작성할 수 없습니다. Hermes는 **오프라인 감사** 소스이기도 합니다 — 대시보드는 `~/.hermes/state.db`에서 게이트웨이 세션을 직접 읽습니다.
  - **OpenClaw (openclaw gateway)**: `~/.openclaw/openclaw.json` (**사용자 범위만** — OpenClaw에는 프로젝트/로컬 설정이 없습니다). Hermes와 마찬가지로 OpenClaw는 셀프 호스팅 멀티채널 **게이트웨이**로, 설치 한 번으로 모든 채널과 내부 서브에이전트의 도구 호출을 가로챕니다. 적용은 OpenClaw의 **인프로세스 플러그인 훅**을 통해 이루어집니다(파일 기반 내부 훅은 관찰 전용이며 차단 불가). 따라서 OpenCode/Pi와 마찬가지로 failproofai는 failproofai 바이너리를 비동기 스폰하고 판결을 변환하는 정적 `openclaw-plugin/` 패키지를 제공합니다. 설치 시 배포된 플러그인 디렉토리를 `openclaw.json`의 `plugins.load.paths[]`에 등록하고 `plugins.entries.failproofai`에서 활성화합니다(`hooks.allowConversationAccess: true` 포함, 원시 대화 훅에 필요). 평가자는 플랫 `{permission, reason}` 판결을 출력하며, 심은 각 훅의 네이티브 반환 형태로 매핑합니다: `before_tool_call → {block:true, blockReason}` (**PreToolUse**), `before_agent_run → {outcome:"block", reason}` (**UserPromptSubmit**), `before_agent_finalize → {action:"revise", reason}` (**Stop** — 실제 턴 종료 게이트이므로 `require-*-before-stop` 기본 정책이 OpenClaw에서 **적용됩니다**, Hermes와 달리). 이벤트와 도구 이름은 바이너리 측에서 `OPENCLAW_EVENT_MAP`/`OPENCLAW_TOOL_MAP`(`exec→Bash`, `read→Read`, …)을 통해 정규화되므로 기본 제공 정책이 변경 없이 동작합니다. 심은 스폰/파싱/타임아웃 오류 시 허용으로 폴백합니다. OpenClaw는 **오프라인 감사** 소스이기도 합니다 — 대시보드는 `~/.openclaw/agents/<agentId>/sessions/<uuid>.jsonl`의 JSONL 세션을 읽습니다.
  - **Factory Droid (`droid`)**: `~/.factory/hooks.json` (사용자), `<cwd>/.factory/hooks.json` (프로젝트) — Factory에는 `local` 범위가 없습니다. droid는 Claude 스타일의 외부 명령 훅 시스템을 제공하지만, droid v0.171.0에서 직접 검증된 두 가지 특이점이 있습니다: (1) 이벤트 이름은 `hooks.json`의 **최상위 레벨**에 위치합니다 — **`"hooks"` 래퍼가 없습니다**(droid가 거부). 도구 이벤트(`PreToolUse`/`PostToolUse`)에는 `"matcher": "*"`가 있고, 비도구 이벤트에는 없습니다. (2) 거부는 JSON 결정이 아닌 훅 **종료 코드 2 + stderr**로 이루어집니다 — 평가자의 `factory` 브랜치는 도구/프롬프트 이벤트에서 종료 코드 2를 반환하고, 턴 종료 `Stop` 이벤트에서만 `{decision:"block", reason}`을 반환합니다(droid의 유일한 강제 재시도 채널). 이벤트는 이미 PascalCase이므로 이벤트 맵이 필요 없으며, 페이로드는 Claude snake_case입니다. 도구 이름만 `FACTORY_TOOL_MAP`(`Execute→Bash`, `Create→Write`, `FetchUrl→WebFetch`, …)을 통해 정규화됩니다. Factory는 **오프라인 감사** 소스이기도 합니다 — 대시보드는 `~/.factory/sessions/<encoded-cwd>/<sessionId>.jsonl`의 디스크 상 JSONL 세션을 읽습니다.
  - **Devin CLI (`devin`, Cognition)**: `~/.config/devin/config.json` (사용자), `<cwd>/.devin/config.json` (프로젝트) — Devin에는 `local` 범위가 없습니다. Devin은 devin v3000.1.27에서 직접 검증된 **순수 Claude 클론**입니다: 표준 Claude `"hooks"` 래퍼 스키마를 사용하고(쓰기는 병합 보존 방식이므로 설정 파일의 다른 키 — `org_id`, `theme_mode`, … — 가 유지됨), 이미 PascalCase인 이벤트 이름(이벤트 맵 없음, 핸들러 브랜치 없음)과 Claude snake_case stdin 페이로드(정규화 없음)를 사용합니다. 평가자의 `devin` 브랜치는 **모든** 이벤트에서 종료 코드 0으로 `{"decision":"block","reason"}` JSON을 stdout으로 출력하여 거부합니다(검증됨 — `--permission-mode dangerous`를 오버라이드함). 턴 종료 `Stop` 이벤트에서는 이유에 MANDATORY-ACTION 강제 재시도 문구가 포함되므로 `require-*-before-stop` 기본 정책이 적용됩니다. 도구 이름만 `DEVIN_TOOL_MAP`(`exec→Bash`; `tool_input.command`는 이미 정규형)을 통해 정규화됩니다. Devin은 **오프라인 감사** 소스이기도 합니다 — 대시보드는 `~/.local/share/devin/cli/sessions.db`의 SQLite 세션을 읽습니다(각 `sessions` 행에 실제 `working_directory`가 있으므로 Claude처럼 프로젝트 cwd별로 세션이 그룹화됨).
  - **Antigravity CLI (`agy`)**: `~/.gemini/config/hooks.json` (사용자), `<cwd>/.agents/hooks.json` (프로젝트) — Antigravity에는 `local` 범위가 없습니다. Factory/Devin과 달리 Antigravity는 agy v1.1.2에서 직접 검증된 **독자적인** 계약(Claude 클론이 아님)을 갖습니다. `hooks.json`은 **이름 있는 훅** 스키마를 사용합니다: 최상위 키가 훅 *이름*(`"failproofai"`)이고, 그 값이 이벤트→핸들러 맵입니다. 도구 이벤트(`PreToolUse`/`PostToolUse`)는 핸들러를 `{matcher:"*", hooks:[…]}`로 감싸고, `PreInvocation`/`Stop`은 **플랫** 핸들러 배열입니다(다른 이름 있는 훅은 보존됨). stdin 페이로드는 **camelCase protojson**(`toolCall:{name,args}`, `conversationId`, `workspacePaths`, `transcriptPath`)으로, failproofai는 정책 실행 전에 snake_case로 정규화하고 `run_command`의 PascalCase 인자(`CommandLine`/`Cwd`)를 `ANTIGRAVITY_TOOL_INPUT_MAP`으로 매핑합니다. 평가자의 `antigravity` 브랜치는 Antigravity의 **독자적인** 응답 형태를 사용합니다: `{decision:"deny", reason}`으로 도구/프롬프트를 차단하고(종료 코드 0), 턴 종료 `Stop`에서 `{decision:"continue", reason}`으로 루프를 재진입합니다(`require-*-before-stop` 기본 정책 적용), `PreInvocation`(→ `UserPromptSubmit`)에서 `{injectSteps:[{ephemeralMessage}]}`로 지시를 주입합니다. 도구 이름은 `ANTIGRAVITY_TOOL_MAP`(`run_command→Bash`, `view_file→Read`, …)을 통해 정규화됩니다. Antigravity는 **오프라인 감사** 소스이기도 합니다 — 대시보드는 `~/.gemini/antigravity-cli/brain/<conversationId>/.system_generated/logs/transcript_full.jsonl`의 플레인 JSONL 트랜스크립트를 읽습니다(대화 인덱스는 `conversation_summaries.db`에 있음).
  - **Goose (codename goose, Block)**: `~/.agents/plugins/failproofai/hooks/hooks.json` (사용자), `<cwd>/.agents/plugins/failproofai/hooks/hooks.json` (프로젝트) — Goose에는 `local` 범위가 없습니다. 적용은 Goose의 **훅** 시스템, 즉 크로스 에이전트 **Open Plugins** 스펙을 사용합니다: 설치 시 `failproofai` 플러그인 디렉토리만 넣으면 Goose가 시작 시 자동 탐색하여 `~/.config/goose/config.yaml`에 자가 등록합니다. `hooks.json`은 최상위 `"hooks"` 래퍼가 있는 Open Plugins 스키마를 사용하며, 모든 이벤트에서 matcher가 **생략**됩니다 — 빈 `"*"`는 아무것도 매칭하지 않는 잘못된 정규식입니다(goose v1.43.0에서 직접 검증). 이벤트 이름은 이미 PascalCase이며(이벤트 맵 없음), stdin 페이로드는 핸들러가 `hook_event_name`/`cwd`로 정규화하는 `event`/`working_dir`를 사용합니다. 평가자의 `goose` 브랜치는 종료 코드 0으로 `{"decision":"block","reason"}` JSON을 stdout으로 출력하여 거부하며, **`PreToolUse`** 이벤트에서만 적용됩니다(goose ≥ v1.37.0에서 제공). 이는 셸 도구와 **위임된 서브에이전트 내부**에서 모두 발생하므로 유일한 충분한 거부 지점입니다. 다른 훅 오류는 **허용**으로 폴백합니다. Goose에는 **`Stop` 이벤트가 없으므로** `require-*-before-stop` 기본 정책은 적용되지 않습니다(Hermes와 동일). 도구 이름은 `GOOSE_TOOL_MAP`(`shell→Bash`, `write→Write`, `todo__todo_write→TodoWrite`, …)으로, 경로 키는 `GOOSE_TOOL_INPUT_MAP`(`path`/`source` → `file_path`)으로 정규화됩니다. Goose는 **오프라인 감사** 소스이기도 합니다 — 대시보드는 `~/.local/share/goose/sessions/sessions.db`의 SQLite 세션을 읽습니다(각 `sessions` 행에 실제 `working_dir`가 있으므로 Devin처럼 프로젝트 cwd별로 세션이 그룹화됩니다. `--no-session` 임시 실행은 필터링됩니다).
- **`policies-config.json`** — failproofai가 평가할 정책과 파라미터를 지정합니다(모든 에이전트 CLI에서 공유)

특정 에이전트를 대상으로 하려면 `--cli claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose`를 전달합니다(공백으로 구분하거나 반복 사용으로 여러 개 선택 가능):

```bash
failproofai policies --install --cli codex --scope project
failproofai policies --install --cli copilot --scope project
failproofai policies --install --cli cursor --scope project
failproofai policies --install --cli opencode --scope project
failproofai policies --install --cli pi --scope project
failproofai policies --install --cli hermes --scope user
failproofai policies --install --cli openclaw --scope user
failproofai policies --install --cli factory --scope project
failproofai policies --install --cli devin --scope project
failproofai policies --install --cli antigravity --scope project
failproofai policies --install --cli goose --scope project
failproofai policies --install --cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose
```

`--cli`를 생략하면 `failproofai`가 설치된 에이전트 CLI를 자동 감지합니다(`which claude` / `which codex` / `which copilot` / `which cursor-agent` / `which opencode` / `which pi` / `which hermes` / `which openclaw` / `which droid` / `which devin` / `which agy` / `which goose`):

- **CLI 하나 감지** — 프롬프트 없이 해당 CLI를 자동 선택합니다.
- **여러 CLI 감지** (인터랙티브 터미널) — 화살표 키 단일 선택 프롬프트를 표시합니다. `감지됨 (N)` 섹션(`N개 감지됨 전체 설치` 집계 행 + 각 감지된 CLI 개별 항목)과 `미설치 (M) · 미리 훅 설치` 섹션(감지되지 않은 지원 CLI 목록, 사전 설치 옵션)으로 구분됩니다(↑↓ 이동, Enter 선택, ^C 종료). 삭제 플로우는 감지됨 섹션만 표시합니다.
- **여러 CLI 감지** (비인터랙티브 실행, CI, TTY 없음) — 프롬프트 없이 감지된 모든 CLI에 설치합니다.
- **감지 없음** — `claude`로 폴백하며, PATH에서 에이전트 바이너리를 찾을 수 없다는 경고를 표시합니다. 훅 명령은 그래도 기록되므로 나중에 설치하면 바로 활성화됩니다.

`policies-config.json`은 언제든지 직접 편집할 수 있으며, 변경 사항은 재시작 없이 다음 훅 이벤트부터 즉시 적용됩니다.

## 업그레이드 시 설정 유지

새 버전의 failproofai는 `~/.failproofai/`의 구조를 변경할 수 있습니다. 그럴 경우, 업그레이드 후 첫 번째 명령 실행 시 디렉토리가 마이그레이션되며, **설정은 재설정되지 않고 그대로 유지됩니다**:

| 유지됨 | 재구성됨 |
|--------|---------|
| 정책 선택 및 파라미터(`policies-config.json`) | 감사 캐시 |
| `daemon.configured` 및 추가 캡처 경로를 포함한 설정(`config.json`) | 클라우드 관리 정책 배포 — 다음 폴링 시 재패치 및 다이제스트 검증 |
| 클라우드 등록(`credentials.json`) | 데몬 임시 상태 |
| `policies/`의 직접 작성한 정책 파일 및 가져오는 헬퍼 | |
| 대시보드가 읽는 결정 로그 및 아직 전달되지 않은 이벤트 | |

*최신* failproofai가 기록한 키도 보존되며, 이전 버전 리더에 의해 삭제되지 않습니다. 따라서 버전 간 이동 시 어느 방향으로도 설정이 자동으로 사라지지 않습니다.

마이그레이션 후 별도의 설정 재실행이 **필요하지 않습니다**: 마이그레이션된 머신은 이전과 동일하게 적용하므로, 아무도 없는 머신에서의 업그레이드도 안전합니다. 모든 마이그레이션은 `~/.failproofai/migrations/applied.json`에 기록되며, 복구 불가능한 파일은 실행 전에 `~/.failproofai/migrations/backup-layout<n>/`에 복사됩니다.

한 줄 업그레이드는 [`failproofai update`](/ko/cli/update)를, `--dry-run`을 포함한 세부 사항은 [`failproofai migrate`](/ko/cli/migrate)를 참조하세요.

## 예시: 팀 기본값이 있는 프로젝트 수준 설정

`.failproofai/policies-config.json`을 리포지토리에 커밋합니다:

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-push-master",
    "sanitize-api-keys",
    "block-env-files"
  ],
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "release", "hotfix"]
    }
  }
}
```

각 개발자는 팀원에게 영향을 주지 않고 개인 오버라이드를 위해 `.failproofai/policies-config.local.json`(gitignore 처리)을 생성할 수 있습니다.
