39개의 내장 정책 중 38개는 `FailproofAI/policies` 팩으로 제공됩니다. `block-failproofai-commands`는 팩에서 `alwaysOn`을 선언할 수 없기 때문에 패키지에 컴파일되어 포함됩니다. 설치된 팩이 이 머신에서 적용할 수 있는 내용의 기준입니다:

```bash
failproofai policies show FailproofAI/policies   # the catalog, as published
failproofai policies                             # what is enabled here
```

`failproofai policies`는 커스텀 파일, 컨벤션 파일, 설치된 팩 및 Cloud 할당 목록을 표시합니다. 내장 섹션은 없으므로 "어떤 내장 정책이 있는지"에 대한 답을 제공하지 않습니다 — 그 질문에 대한 답은 `policies show`와 [Policy Hub](https://befailproof.ai/policy-hub/FailproofAI/policies/)에서 확인할 수 있습니다.

## 기본값 및 선택 방법

`failproofai policies add FailproofAI/policies`만 실행하면 팩 자체의 기본값이 활성화됩니다 — 아래 표에서 **on**으로 표시된 10개 항목입니다. `block-failproofai-commands`는 선택 여부와 관계없이 항상 활성화되며 해당 선택에 포함되지 않습니다. `--all`은 전체를 선택하고, `--category <slug>` 및 `--policy <name>`은 일부만 선택합니다. 각 제목 옆의 슬러그가 `--category`와 매칭되는 값입니다:

```bash
failproofai policies add FailproofAI/policies --category git,database
```

`block-failproofai-commands`는 **항상 활성화**되어 있습니다. 이 정책은 선택 목록에 포함되어 있는지 여부와 관계없이 모든 평가에서 동작하며, 비활성화하거나 일시 중지할 수 없습니다 — 에이전트가 끌 수 있는 적용 장치는 실질적인 보호 수단이 아닙니다. 팩에서 `alwaysOn`을 선언할 수 없기 때문에, 이 정책만 팩이 아닌 패키지에 직접 컴파일되어 포함됩니다.

## Sanitize — `sanitize`

이 정책들은 도구가 실행된 후 `PostToolUse`에서 동작합니다. **도구 결과를 감지하고 거부**하며, 일부 문자열만 삭제하고 나머지를 반환하지 않습니다.

여기서의 거부는 `PostToolUse` 판정을 소비하는 하네스에서만 모델에 전달됩니다 — **codex**와 **copilot**에서는 거부 이유가 전체 도구 결과를 대체합니다. claude, cursor, opencode, pi, hermes, openclaw, factory, devin, antigravity, goose에서는 `PostToolUse`가 관찰 전용입니다: 감지 내용은 기록되지만 출력은 여전히 모델에 전달됩니다.

| 정책 | 트리거 | 기본값 | 결과 |
| --- | --- | --- | --- |
| `sanitize-jwt` | `PostToolUse` | on | JWT가 포함된 도구 결과 거부. |
| `sanitize-api-keys` | `PostToolUse` | on | OpenAI, Anthropic, GitHub, AWS, Stripe 또는 Google 키가 포함된 도구 결과 거부. |
| `sanitize-connection-strings` | `PostToolUse` | on | 자격 증명이 포함된 데이터베이스 연결 문자열이 있는 도구 결과 거부. |
| `sanitize-private-key-content` | `PostToolUse` | on | PEM 개인 키 콘텐츠가 포함된 도구 결과 거부. |
| `sanitize-bearer-tokens` | `PostToolUse` | on | `Authorization: Bearer` 토큰이 포함된 도구 결과 거부. |

## Workflow — `workflow`

5개 모두 `Stop`에서 동작하며 기본적으로 비활성화되어 있습니다.

| 정책 | 기본값 | 결과 |
| --- | --- | --- |
| `require-commit-before-stop` | off | 트래킹된 변경 사항이 커밋되지 않은 상태에서 완료 거부. |
| `require-push-before-stop` | off | 커밋이 로컬에만 존재하는 상태에서 완료 거부. |
| `require-pr-before-stop` | off | 현재 브랜치에 대한 풀 리퀘스트 요구. |
| `require-no-conflicts-before-stop` | off | 설정된 베이스 브랜치와의 클린 머지 요구. |
| `require-ci-green-before-stop` | off | 현재 HEAD 커밋의 CI 검사 통과 요구 (이전 커밋의 오래된 실행은 무시). |

이 정책들은 `Stop` 판정을 소비하는 하네스에서만 작동합니다. 모든 하네스가 해당되는 것은 아닙니다:

| 하네스 | `Stop` |
| --- | --- |
| claude, codex, copilot, cursor, openclaw, factory, devin, antigravity | 차단 확인됨: 거부가 추가 턴을 강제합니다 |
| pi | 관찰 모드. 거부 이유는 게이트가 아닌 지침으로 다음 턴에 전달됩니다 |
| goose, hermes | `Stop` 훅이 설치되어 있지 않으므로 이 5가지 정책이 절대 실행되지 않습니다 |
| opencode | 미검증. `Stop`은 opencode가 판정을 소비하는 이벤트에 포함되지 않습니다 |

Cursor Cloud Agent VM에는 stop 훅이 전혀 설치되어 있지 않으므로, 로컬 Cursor는 적용되더라도 해당 환경의 Cursor 세션은 보호받지 못합니다.

<Note>
  `warn-*` 정책은 `deny`가 아닌 `instruct`를 반환합니다. (`prefer-package-manager`는 `block-*`이 아닌 이름 중 예외로, `deny`를 반환하므로 `PreToolUse` 판정을 소비하는 모든 하네스 — 12개 전체 — 에서 차단됩니다.) Hermes와 Goose, `Stop` 채널 외부의 Pi, OpenClaw, Factory, 그리고 `Stop`과 `UserPromptSubmit` 외부의 Antigravity에서는 `instruct`가 allow + stderr 메모로 다운그레이드됩니다 — 에이전트에게 알림이 전달되지 않습니다. Antigravity의 `UserPromptSubmit`은 실제 두 번째 채널입니다: 모델이 실행되기 전에 지침이 일시적 메시지로 주입됩니다.
</Note>

## 파라미터 참조

선택된 스코프의 `policyParams` 객체 아래에 파라미터를 구성합니다. 타입은 각 정책에 의해 검증됩니다.

| 정책 | 파라미터 | 타입 및 기본값 |
| --- | --- | --- |
| `sanitize-api-keys` | `additionalPatterns` | `pattern[]`, `[]`; 각 항목에 `regex`와 `label` 포함 |
| `block-read-outside-cwd` | `allowPaths` | `string[]`, `[]` |
| `block-sudo` | `allowPatterns` | `string[]`, `[]` |
| `block-rm-rf` | `allowPaths` | `string[]`, `[]` |
| 인프라 차단 정책 | `allowPatterns` | `string[]`, `[]` |
| `block-secrets-write` | `additionalPatterns` | `string[]`, `[]` |
| `block-push-master` | `protectedBranches` | `string[]`, `["main", "master"]` |
| `block-work-on-main` | `protectedBranches` | `string[]`, `["main", "master"]` |
| `prefer-package-manager` | `allowed`, `blocked` | `string[]`, `[]` |
| `warn-large-file-write` | `thresholdKb` | `number`, `1024` |
| `require-push-before-stop` | `remote`, `baseBranch` | `string`, `"origin"`; `string`, `"main"` |
| `require-pr-before-stop` | `baseBranch` | `string`, `"main"` |
| `require-no-conflicts-before-stop` | `baseBranch` | `string`, `"main"` |

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status"]
    },
    "block-push-master": {
      "protectedBranches": ["main", "release"]
    }
  }
}
```

<Note>
  `policyParams` 키로 사용되는 단순 정책 이름은 `FailproofAI/policies`에 대해서만 적용됩니다. 다른 팩의 경우 키는 `pack/<owner>/<repo>/<policy>` 형식이어야 합니다 — 동일한 정책 이름을 선언한 다른 팩은 사용자의 파라미터가 아닌 스키마 기본값을 적용받습니다.
</Note>

<Warning>
  allow 패턴은 에이전트가 수행할 수 있는 범위를 넓힙니다. 플리트 전체에 배포하기 전에 대상 하네스에서 정확한 토크나이제이션과 명령 변형을 테스트하세요.
</Warning>
