검토된 정책을 한 번에 하나의 머신에 배포하세요. 관찰 모드로 시작하는 것을 권장합니다.

## CLI에서 롤아웃

```bash
fp policies test ./rule.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish no-force-push ./rule.mjs
fp fleet deploy <machine> --add no-force-push:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add no-force-push:enforce
```

관찰 모드는 실제 정책을 평가하고 allow 외의 결정을 기록하지만, 에이전트를 차단하지는 않습니다.

<Warning>
  `--add no-force-push`만 단독으로 사용하면 즉시 적용됩니다. 섀도 롤아웃을 위해 `:observe`를 추가하세요.
</Warning>

적용 후 문제가 발생한 경우:

```bash
fp fleet history <machine>
fp fleet rollback <machine> <generation>
```

## 대시보드에서 배포

1. **Admin → enforcement**으로 이동합니다.
2. 대상 머신을 엽니다.
3. 효과를 **observe**로 설정하여 정책 버전을 추가합니다.
4. 배포를 적용합니다.
5. **Observe → policy**에서 결과를 검토합니다.
6. 매칭 결과가 올바르면 동일한 버전을 **enforce**로 승격합니다.

## 정책 세트 교체 또는 사전 준비

- `--remove <id>` — 정책 하나를 제거합니다.
- `--set <ref>...` — 전체 정책 세트를 교체합니다.
- `--create` — 머신이 처음 체크인하기 전에 배포를 미리 준비합니다.
- `fp fleet diff <machine>` — 의도된 상태와 실제 적용된 상태를 비교합니다.

<Note>
  Cloud 없이 사용하는 경우, `failproofai publish --effect observe`로 팩을 게시하고 로컬 대시보드에서 결정 사항을 확인하세요.
</Note>

머신이 배포를 수신하려면 `policies:pull` 권한이 필요하고, 결정 사항을 보고하려면 `events:add` 권한이 필요합니다.
