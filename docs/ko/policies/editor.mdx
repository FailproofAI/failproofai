정책 편집기를 사용해 발견된 문제를 배포 가능한 규칙으로 전환하세요. 초안이 운영 중인 동작을 몰래 변경하지 않도록 작성과 배포를 분리하여 관리합니다.

문제에 반복 가능한 행동 패턴이 있다면, **Analyze → issues**에서 해당 문제를 열고 **generate policy**를 선택하세요. Failproof AI는 먼저 정책으로 해당 문제를 표현할 수 있는지 설명한 후, 검토된 의도와 발견 컨텍스트를 편집기로 가져옵니다. 생성된 소스는 게시하기 전까지 초안 상태로 유지됩니다.

## 정책 버전 게시

<Tabs>
  <Tab title="Dashboard">
    1. **Admin → policy editor**로 이동한 후 **compose**에서 장애 유형을 설명하거나 JavaScript 정책 소스를 붙여넣습니다.
    2. 소스를 유효성 검사하고 보고된 모든 오류를 수정합니다.
    3. 정책 식별 정보를 입력하고 게시한 다음, **library**를 사용해 버전을 비교하거나 비활성화합니다.
    4. 버전이 머신 롤아웃에 준비되면 **enforcement**를 선택합니다.

    ![정책 식별 정보, AI 지원 초안 작성, 소스 유효성 검사, 게시 컨트롤이 포함된 정책 편집기 compose 화면.](/images/dashboard/policy-editor.png)
  </Tab>
  <Tab title="CLI">
    Cloud CLI는 정책 버전을 게시하지 않습니다. 편집기에 복사하기 전에 소스를 로컬에서 유효성 검사하세요:

    ```bash
    failproofai policies --install --custom ./checkout.policies.ts \
      --cli claude --scope project
    ```

    검토된 버전은 **Admin → policy editor**에서 게시합니다.
  </Tab>
</Tabs>

## 작성 체크리스트

1. 운영 언어로 장애 유형의 이름을 지정합니다.
2. 판단에 충분한 증거를 포함하는 훅 이벤트와 도구를 선택합니다.
3. 안전하지 않은 동작과 일치하는 가장 좁은 조건을 작성합니다.
4. 에이전트 또는 운영자에게 다음에 무엇을 해야 하는지 알려주는 이유를 반환합니다.
5. 일치해야 하는 예시와 반드시 허용되어야 하는 예시를 추가합니다.
6. 새 버전을 저장하고 검토를 요청합니다.

에이전트가 안전하게 방향을 수정할 수 있을 때는 `instruct`를 사용하세요. 해당 작업을 허용하면 용납할 수 없거나 되돌릴 수 없는 위험이 생길 때는 `deny`를 사용하세요.

<Info>
  정책 버전은 변경 불가능한 배포 입력값입니다. 초안을 편집하면 새 버전이 생성되며, 이미 머신에 할당된 버전을 덮어쓰지 않습니다.
</Info>
