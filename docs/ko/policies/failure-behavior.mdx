설정 후 로컬 `failproofaid` 서비스가 유일한 평가자입니다. 응답할 수 없는 경우, 보호된 작업은 자동으로 허용되는 대신 차단됩니다.

## 머신 전체 차단 진단

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

`failproofai config`를 실행하여 서비스를 복구하거나 일치하는 버전을 설치하세요.

두 가지 실패는 유사하게 보일 수 있습니다:

| 실패 유형 | 의미 |
| --- | --- |
| 서비스 연결 불가 | 소켓 뒤에 작동 중인 평가자가 없음 |
| 버전 불일치 | CLI와 서비스의 프로토콜 버전이 다름 |

둘 다 차단되지만, 상태 보고에서 별도로 표시됩니다.

## 팩이 로드되지 않을 때

선택한 팩이 누락되었거나, 변경되었거나, 유효하지 않은 경우 해당 팩의 선택된 정책이 적용되는 이벤트가 차단됩니다. 이는 손상된 팩이 머신이 보호된 것처럼 보이는 상태에서 사라지는 것을 방지합니다.

`failproofai policies`는 팩 이름과 로드 오류를 표시합니다.

```bash
failproofai policies
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

읽을 수 없는 메타데이터는 신뢰할 수 없는 데이터를 기반으로 범위를 좁히는 대신, 안전 차단 범위를 더 넓게 설정합니다.

## 계속 사용 가능한 기능

정책 평가가 실패하는 동안에도 로컬 대시보드와 상태 명령은 계속 작동합니다. 이를 사용하여 복구가 필요한 서비스, 팩, 또는 버전을 확인하세요.

<Warning>
  서비스나 팩 파일을 삭제하여 실패-차단(failure-closed) 결정을 우회하지 마세요. 서비스를 복구하거나, 팩을 재설치하거나, CLI를 통해 할당을 제거하여 머신을 알려진 상태로 되돌리세요.
</Warning>
