policy는 에이전트 작업을 감시하고 다음 세 가지 결정 중 하나를 반환합니다:

- `allow` — 계속 진행합니다.
- `instruct` — 하네스가 지원하는 경우 에이전트에게 안내를 제공합니다.
- `deny` — 작업을 차단합니다.

보호된 파일 삭제, 시크릿 노출, 잘못된 브랜치로 push, 프로덕션 인프라 변경 등 알려진 반복 가능한 동작에 policy를 사용하세요.

## 이 머신에 policy 추가하기

설치 시 기본적으로 policy 팩이 선택되지 않습니다. 설치 후 Failproof AI 팩을 추가하세요:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai policies
```

이 패키지에는 특권이 부여된 빌트인 팩이 포함되어 있지 않습니다. 저희 팩도 다른 팩과 동일한 방식으로 설치됩니다.

policy는 로컬 파일, 배포된 팩, 또는 Cloud 할당에서도 가져올 수 있습니다:

| 소스 | 추가 방법 |
| --- | --- |
| 로컬 파일 | `.failproofai/policies/` 아래에 `*policies.{js,mjs,ts}` 파일 배치 |
| 임의 파일 경로 | `failproofai policies -i -c <path>` |
| 배포된 팩 | `failproofai policies add <owner>/<repo>` |
| Cloud | 대시보드 또는 `fp fleet deploy`로 할당 |

`block-failproofai-commands`는 항상 실행되며 비활성화할 수 없습니다. 이는 에이전트가 자체 적용을 비활성화하는 것을 방지합니다.

## 적용 전 관찰하기

관찰 모드는 실제 policy를 실행하고 어떤 결정을 내렸을지 기록하지만, 에이전트를 차단하지는 않습니다.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

<Warning>
  `fp fleet deploy <machine> --add <id>`만 단독으로 사용하면 즉시 적용됩니다. 섀도 롤아웃을 위해 `:observe`를 추가하세요.
</Warning>

관찰 모드에서 타임아웃이 발생한 policy는 allow로 기록됩니다. 적용 중에도 동일한 결과가 발생하기 때문입니다. allow가 아닌 관찰된 결정만 기록됩니다.

Cloud 없이 팩을 사용하는 경우 `failproofai publish --effect observe`로 배포하세요.
