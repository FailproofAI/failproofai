Policy 팩은 공개 GitHub 릴리스로 배포되는 버전 관리 Policy 세트입니다. 이 패키지 자체에는 별도의 팩이 포함되어 있지 않으며, 다른 팩과 동일한 방식으로 설치할 수 있습니다.

```bash
failproofai policies show FailproofAI/policies
failproofai policies add FailproofAI/policies
```

`show`는 팩의 코드를 실행하지 않고 매니페스트만 읽습니다.

## 설치할 항목 선택

```bash
failproofai policies add owner/repo --policy block-refunds
failproofai policies add owner/repo --category billing,git
failproofai policies add owner/repo --all
```

선택 옵션을 지정하지 않으면 팩 게시자의 기본값이 사용됩니다. 최신 릴리스를 다시 추가해도 기존 선택 항목은 유지됩니다.

슬래시가 포함된 항목은 팩 소스이며, 슬래시가 없는 항목은 Policy 이름입니다.

## 릴리스 고정

| 소스 | 결과 |
| --- | --- |
| `owner/repo` | 최신 릴리스 (확인 후 고정됨) |
| `owner/repo@a1b2c3d4e5f6` | 커밋 기반의 정확한 릴리스 |
| `owner/repo@v2.1.0` | 정확한 이름의 릴리스 |
| GitHub 릴리스 URL | 해당 URL의 릴리스 |

팩은 일반적으로 빌드 시점의 12자리 커밋 SHA를 사용합니다. `failproofai policies show owner/repo --releases`를 사용하면 릴리스 순서를 확인할 수 있습니다.

## 설치된 팩 관리

```bash
failproofai policies
failproofai policies remove block-refunds
failproofai policies add block-refunds
failproofai policies remove owner/repo
```

설치된 두 팩에 동일한 Policy 이름이 포함된 경우, CLI는 모호한 단독 이름 사용을 거부합니다. 하나의 팩을 통해 Policy를 선택하거나 다른 팩을 제거하세요.

## 안전성과 가용성

각 릴리스에는 매니페스트, 번들된 Policy 코드, 체크섬이 포함됩니다. Failproof AI는 팩을 로드하기 전에 기록된 다이제스트를 검증합니다. 체크섬은 바이트가 릴리스와 일치함을 증명하지만, 게시자가 누구인지는 증명하지 않습니다.

선택된 팩을 로드할 수 없는 경우, 해당 팩이 선언한 이벤트에 대해 차단(fail closed) 동작이 적용됩니다. [Policy 실패 동작](/ko/policies/failure-behavior)을 참고하세요.

| 변수 | 효과 |
| --- | --- |
| `FAILPROOFAI_NO_DOWNLOAD=1` | 새로운 다운로드를 거부하며, 설치된 팩은 계속 실행됨 |
| `FAILPROOFAI_PACK_BASE_URL` | 미러 서버 사용 |
| `FAILPROOFAI_PACK_DIR` | 팩 저장 위치 변경 |

[Policy Hub](https://befailproof.ai/policy-hub/)에서 팩을 검색하거나 [직접 게시](/ko/policies/publish-a-pack)할 수 있습니다.
