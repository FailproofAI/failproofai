정책을 작성하고 로컬에서 테스트한 후 팩으로 게시하세요.

## 작성 및 테스트

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

`--init`은 `git push --force`를 차단하는 정책 파일을 생성합니다. 파일을 수정하고, 에이전트에게 차단된 작업을 시도하도록 요청한 뒤, 로컬 대시보드의 **Policies → Activity**에서 결과를 확인하세요.

팩 정책에는 다음과 같은 내용을 포함할 수 있습니다:

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-refunds",
  description: "Refunds above the limit need a human",
  category: "Billing",
  defaultEnabled: true,
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) => {
    // return allow(), instruct(), or deny()
  },
});
```

`defaultEnabled`의 기본값은 `false`입니다.

## 게시

파일을 커밋한 후 다음을 실행하세요:

```bash
failproofai publish
```

게시 명령은 정책 파일을 찾아 설치 시 사용되는 것과 동일한 로더로 유효성을 검사한 뒤, 팩 에셋을 GitHub 릴리스에 업로드합니다. `GITHUB_TOKEN`, `GH_TOKEN`, 또는 `gh auth login`을 사용합니다.

설치 시 익명 HTTPS를 사용하므로 저장소는 반드시 공개 상태여야 합니다.

기본 버전은 현재 커밋의 12자리 SHA입니다. 작업 트리가 더럽거나 Git 외부 디렉터리인 경우 `--version`을 지정하지 않으면 게시가 거부됩니다. `HEAD`에 태그가 있으면 SHA보다 태그가 우선합니다.

사용자는 다음 명령으로 설치할 수 있습니다:

```bash
failproofai policies add owner/repo
```

## 관찰 모드로 게시

```bash
failproofai publish --effect observe
```

관찰 모드는 실제 정책을 평가하고 allow가 아닌 결정을 기록하지만, 에이전트는 계속 실행됩니다. 타임아웃은 allow로 기록됩니다.

관찰된 매칭이 올바르다고 판단되면 `--effect enforce`로 다시 게시하세요.

## 유용한 옵션

| 플래그 | 설명 |
| --- | --- |
| `--init [file]` | 시작용 정책 파일 생성 |
| `--repo <owner>/<repo>` | 저장소 선택 또는 생성 |
| `--version <version>` | 커밋 기반 버전 재정의 |
| `--effect enforce|observe` | 팩의 차단 여부 선택 |
| `--dry-run` | 게시 없이 빌드 및 유효성 검사만 수행 |
| `--allow-private` | `policies add`로 설치할 수 없음을 인지한 채로 비공개 게시 |

```bash
failproofai publish --dry-run
failproofai publish ./guards.mjs --repo me/guards --version 2.0.0
```

<Note>
  게시 후 GitHub 토픽에 `failproofai-policies`를 추가하면 [Policy Hub](https://befailproof.ai/policy-hub/)에서 팩을 색인할 수 있습니다. CLI는 이를 자동으로 설정하지 않습니다.
</Note>

<Warning>
  정책 이름 변경은 기존 선택에 대한 호환성 파괴 변경입니다. 릴리스 간에 이름을 안정적으로 유지하세요.
</Warning>
