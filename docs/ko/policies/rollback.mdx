icon: "rotate-ccw"
---

롤백은 배포된 버전을 변경하거나 정책 할당을 제거합니다. 인시던트를 설명하는 결정 이력은 삭제되지 않습니다.

## 머신 롤백

<Tabs>
  <Tab title="대시보드">
    1. **Admin → enforcement**로 이동하여 영향받은 머신을 펼치고 마지막으로 알려진 정상 정책 세트를 확인합니다.
    2. **edit**를 선택하고 해당 버전과 효과를 복원한 뒤 새 배포를 적용합니다.
    3. 머신 체크인을 기다린 후 보고된 배포를 확인합니다.
    4. **Observe → policy**와 영향받은 세션을 열어 유효한 작업이 더 이상 차단되지 않는지 확인합니다.

  </Tab>
  <Tab title="CLI">
    클라우드 배포 롤백은 대시보드 워크플로입니다. 로컬 상태를 통해 수정된 배포가 머신에 적용되었는지 확인합니다:

    ```bash
    failproofai config --status
    ```

    `failproofai config --pause`는 로컬 세션 하나에 대해 내장, 커스텀, 컨벤션 정책을 일시 중지합니다. 클라우드 관리 정책은 일시 중지되지 않으므로, 잘못된 클라우드 배포에 대한 임시 해결책이 될 수 없습니다.
  </Tab>
</Tabs>

## 롤백해야 하는 경우

- 정책이 예상된 프로덕션 작업을 차단하는 경우.
- 매치 볼륨이 관측된 롤아웃 예측보다 현저히 높은 경우.
- 정책이 인테그레이션에서 제공하지 않는 필드에 의존하는 경우.
- 새 버전이 의도된 실패 모드 외의 동작을 변경하는 경우.

롤백 후 영향받은 세션을 열어 오탐(false positive)을 유발한 조건을 파악합니다. 새 버전을 만들고 안전하지 않은 케이스와 정상적인 케이스를 모두 테스트한 다음, 관찰 단계를 다시 진행합니다.

<Warning>
  인시던트 중 강제 적용을 일시 중지하는 것이 적절할 수 있지만, 해당 범위의 모든 활성 정책에 대한 노출이 넓어집니다. 가능하면 특정 정책 버전을 롤백하는 방법을 우선적으로 사용하십시오.
</Warning>
