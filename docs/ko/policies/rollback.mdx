icon: "rotate-ccw"

롤백은 배포된 버전을 변경하거나 정책 할당을 제거합니다. 인시던트를 설명하는 결정 이력은 삭제되지 않습니다.

## 머신 롤백

<Tabs>
  <Tab title="대시보드">
    1. **Admin → enforcement**로 이동하여 영향을 받은 머신을 펼치고, 마지막으로 정상 작동했던 정책 세트를 확인합니다.
    2. **edit**를 선택하여 해당 버전과 효과를 복원하고 새 배포를 적용합니다.
    3. 머신이 체크인될 때까지 기다린 후 보고된 배포를 확인합니다.
    4. **Observe → policy**를 열고 영향을 받은 세션을 확인하여 유효한 작업이 더 이상 차단되지 않는지 검증합니다.

  </Tab>
  <Tab title="CLI">
    클라우드 배포 롤백은 대시보드 워크플로입니다. 로컬 상태를 통해 수정된 배포가 머신에 적용되었는지 확인하세요:

    ```bash
    failproofai config --status
    ```

    `failproofai config --pause`는 하나의 로컬 세션에 대해 내장, 커스텀, 관례 정책을 일시 중지합니다. 클라우드 관리 정책은 일시 중지되지 않으므로, 잘못된 클라우드 배포에 대한 임시 해결책이 될 수 없습니다.
  </Tab>
</Tabs>

## 롤백이 필요한 경우

- 정책이 예상된 프로덕션 작업을 차단할 때.
- 매칭 건수가 관측된 롤아웃에서 예측한 것보다 현저히 높을 때.
- 정책이 특정 인테그레이션에서 제공하지 않는 필드에 의존할 때.
- 새 버전이 의도한 실패 모드 범위를 벗어난 동작 변경을 일으킬 때.

롤백 후, 영향을 받은 세션을 열어 오탐(false positive)을 유발한 조건을 파악합니다. 새 버전을 만들고 위험한 경우와 정상적인 경우를 모두 테스트한 뒤, 관찰 단계를 다시 진행합니다.

<Warning>
  인시던트 발생 중에는 적용 중단이 적절할 수 있지만, 해당 범위의 모든 활성 정책에 대한 노출이 넓어집니다. 가능한 경우 특정 정책 버전을 롤백하는 방법을 우선적으로 선택하세요.
</Warning>
