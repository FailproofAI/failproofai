`fp`를 사용하여 Cloud 원격 측정을 검사하고, 클라우드 관리형 적용(정책, 플릿 배포, 가드레일 결정)을 관리하며, 감사, 발견 사항, 이슈, 알림, 키, 사용자, 쿼리, 설정을 관리하세요. 로컬 훅, 정책, 캡처, 머신 등록에는 [`failproofai`](/ko/reference/failproof-cli)를 사용하세요.

호스팅된 코드, LLM 판사 및 Jev 평가자를 작성하고 배포하며, 대시보드를 관리하고, 감정을 검사하고, 터미널에서 대시보드 어시스턴트를 사용할 수도 있습니다.

릴리스된 Cloud CLI를 격리된 도구로 설치하세요:

```bash
uv tool install fp-cloud-cli
fp version
```

## 로그인

```bash
fp login
fp whoami
```

## 문법

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

전역 옵션은 명령 앞에 위치해야 합니다:

```bash
fp --json sessions --since 24h
```

터미널 도움말을 보려면 `fp COMMAND --help` 또는 `fp COMMAND SUBCOMMAND --help`를 실행하세요.

## CLI 명령

### 평가자 작성

`fp evaluators`는 정의를 작성하고, `fp evals`는 결과를 읽습니다. 활성화된 관리형 인스턴스가 필요합니다(`fp evaluators instances`). 작성에는 `evaluations:trigger`가 필요하고, 세션 드라이 런 및 스키마 프로파일링에는 `events:read`도 필요합니다.

코드는 하나의 제한된 Python 표현식입니다. 이것을 `error_free.py`로 저장하세요:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM 판사:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev 이진 및 등급 루브릭:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
생성 시 평가자가 활성화됩니다. 배포는 새로운 불변 버전을 생성한 다음 이전에 활성화된 버전을 비활성화합니다. 후속 작업이 실패하면 새 버전이 게시된 상태로 남습니다: 재시도 전에 `evaluators list --all`을 검사하세요.
판사 드라이 런은 Cloud에서 거부됩니다. Jev 드라이 런은 모델 예산을 소비합니다.
백필은 코드, 판사 및 Jev 평가자를 포함하며 최대 90일을 허용합니다; 아직 평가자가 점수를 매기지 않은 세션만 대기열에 추가합니다. 판사 및 Jev 백필은 모델 예산을 소비하므로 먼저 `fp evaluators backfill --dry-run`을 실행하세요.
사람이 읽는 출력은 생성/배포 전에 세션별 드라이 런 결과를 표시합니다.
실패한 미리 보기는 검토 후 명시적으로 `--force`를 전달하지 않는 한 쓰기를 중단합니다.
</Warning>

AI 초안 작성에는 `fp login`이 필요하며 create/deploy가 허용하는 사양을 작성합니다:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# 활성화하기 전에 초안의 키, 소스 및 조건을 검토하세요.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| 명령 | 옵션 / 동작 |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | 전체 소스/봉투 |
| `fp evaluators create` | `--key`, `--name`, `--version`, 반복 `--label`, `--condition EXPR\|@file`, 소스 하나, 반복 `--dry-run-on`, `--disabled`, 실패한 미리 보기에 대한 명시적 `--force` |
| `fp evaluators deploy KEY` | 동일한 소스 플래그; `--version`, `--backfill 7d` (모든 종류, 1–90일), `--force`; 숫자 버전 자동 증가; KEY는 누락된 사양 파일 `eval_key` 제공 |
| `fp evaluators draft "intent"` | 세션; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | 소스 플래그 또는 `--file`, 반복 `--session` (최대 10개); 없음 = 컴파일만 |
| `fp evaluators enable\|disable KEY[@VERSION]` | 전환 |
| `fp evaluators label KEY[@VERSION]` | 반복 `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | 관리형 플릿/스키마/작업 검사 |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; 코드, 판사 및 Jev |

코드 플래그는 `--code FILE|-`, `--result-kind score|metric|assertion`, `--timeout S`입니다. 판사 플래그는 `--judge --criteria TEXT`, 반복 `--step` 및 `--threshold`입니다. Jev 플래그는 `--jev noul --instructions --true --false` 또는 3–5개의 구별되는 `--level` 값(최악부터)이 있는 `--jev score --instructions`입니다.
판사/Jev는 점수가 필요하고, 임계값은 0–1입니다. 이진 판사 단계는 거부됩니다.

사양 파일에는 정확히 `eval_key`, `display_name`, `eval_version`, `result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`가 포함됩니다.
판사/Jev `evaluator_source`는 JSON 봉투 문자열입니다. 행 ID, 활성화 상태 또는 AI 추론 메타데이터를 포함하지 마세요. `--file`과 개별 사양 플래그는 상호 배타적입니다; deploy는 파일의 버전을 재정의할 수 있습니다. 출력 파일은 덮어쓰지 않습니다.

### 새 대시보드 컨트롤

모든 명령은 전역 `--json`을 허용합니다. 알 수 없는 경로의 404는 "not available on this FailproofAI Cloud yet"와 함께 종료 코드 6으로 종료됩니다. 누락된 레코드의 404도 종료 코드 6으로 종료되지만 레코드를 찾을 수 없다고 보고합니다. 세션 전용 명령은 HTTP 전에 키 모드를 거부합니다(종료 코드 2).

사람이 읽는 명령은 요약과 표를 사용합니다. 원시 JSON 내보내기에는 전역 `--json`을 전달하거나 `--out FILE`로 저장하세요; 그렇지 않으면 세션 및 JSON 쿼리 내보내기가 읽기 쉬운 형태로 표시됩니다. CSV 내보내기는 파이핑을 위해 일반 CSV로 유지됩니다.

| 명령 | 옵션 / 참고 사항 |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | 생성 `--name`, `--description`, `--file` 정의; 업데이트는 언급되지 않은 필드 보존 |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | 추가 `--query ID --chart TYPE --title`; `--file`을 통한 구성/기하학 또는 레이아웃 |
| `fp sessions show\|export\|history\|re-evaluate ID` | 내보내기 `--out`; history는 평가 이력 |
| `fp sessions import FILE...` | Claude Code 전사, Codex 롤아웃 또는 이벤트 JSONL (`.gz` 허용); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; `events:add` 필요 |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; 목록 `--limit`; 메시지 `--session-id` |
| `fp query compose "question"` | 세션; `--run` |
| `fp query export [ID]` | 또는 `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | 이슈는 `--create --title --summary` 또는 `--create --file` 가능 |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; 업데이트 `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | 세션; 조직의 이벤트에서 정책 초안 작성, 게시 안 함 |
| `fp policies backtest [FILE_OR_ID]` | 세션; regex는 모듈을 재생; `jev`/`both` (게시됨, 또는 `--semantic checks.json`) 무료 추정, `--run [--sample N]`은 Jev 허용량 소비; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | 세션; 정책이 이 이슈를 방지할 수 있는지 여부 |
| `fp issues facets` | 받은 편지함 필터가 취할 수 있는 값(횟수 포함) |
| `fp agent brief` | 세션; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | 세션; 생략된 슬러그 파생, 조직 전환 안 함 |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | 권한 집합; 생성 `--name --permission`; 업데이트 교체 `--permission` 또는 병합 `--add/--remove`; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | ID로 삭제 |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows`는 API 키 필요; plan(제안 및 체험) 및 claim은 로그인된 세션 필요 |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 토큰 |
| `fp otel status\|enable\|disable` | Cloud 조직 수집 스위치, 로컬 캡처 아님 |
| `fp slack status\|disconnect` | 세션 |

`fp agent ask`는 `queries:run`을 통해 아티팩트 SQL을 표/통계로 렌더링합니다.
쓰기 승인은 제안된 변경 사항을 표시하고 대화형 터미널에서 프롬프트를 표시합니다. 스크립트와 `--json`은 `--approve`가 명시적으로 지정되지 않으면 거부합니다. 아티팩트가 반환되지 않을 때는 기존 JSON 형태가 변경되지 않습니다.

### 이벤트

```text
fp events [OPTIONS]
```

개별 에이전트 이벤트를 나열합니다. 기본 경량 피드는 원시 페이로드를 제외합니다; `--full`은 제한된 조사에만 사용하세요.

| 옵션 | 설명 |
| --- | --- |
| `--limit`, `-n <n>` | 최대 총 행 수. 기본값: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, 또는 `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC 범위; `--since`를 재정의합니다. |
| `--env <value>` | 환경 필터; 값을 반복하거나 쉼표로 구분합니다. |
| `--event-type <value>` | 이벤트 유형 필터; 값을 반복하거나 쉼표로 구분합니다. |
| `--agent-id <value>` | 에이전트 필터; 값을 반복하거나 쉼표로 구분합니다. |
| `--session-id <value>` | 세션 필터; 값을 반복하거나 쉼표로 구분합니다. |
| `--search <text>` | 페이로드 텍스트 검색; 반복 가능, 임의 용어 일치. |
| `--order asc\|desc` | 시간 순서. 기본값: 최신순. |
| `--all` | `--limit`까지 자동 페이지 매김. |
| `--cursor <token>` | 불투명 커서에서 재개. |
| `--page-size <n>` | `--all`과 함께 요청당 행 수; 최대 `200`. |
| `--full` | 더 무거운 이벤트 엔드포인트를 통해 원시 페이로드 포함. |
| `--fields <csv>` | 선택한 필드만 반환; `payload` 요청 시 전체 모드 활성화. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all`은 **`--limit`까지** 페이지를 매기며, 기본값은 **50**입니다 — 따라서 `--all` 단독으로는 50행에서 멈춥니다. 일찍 멈추면 응답에 재개할 `next_cursor`가 포함됩니다; `"next_cursor": null`은 피드가 실제로 소진되었음을 의미합니다.
</Note>

#### 감사 생성 옵션

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| 옵션 | 설명 |
| --- | --- |
| `--file <path>` | JSON을 기반으로 정의를 구성하거나 stdin에 `-` 사용. 명시적 플래그가 파일 값을 재정의합니다. |
| `--description <text>` | 실패 질문 또는 목적을 기술합니다. |
| `--enabled` / `--disabled` | 스케줄링을 켜거나 끈 상태로 시작합니다. 기본값: 활성화. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. 기본값: `86400`. |
| `--schedule-anchor <timestamp>` | ISO 8601 형식의 고정 UTC 위상. 기본값: 다음 09:00 UTC. |
| `--window-mode since_last\|fixed` | 마지막으로 완전히 분석된 창 이후 계속하거나 롤링 창을 반복적으로 검사합니다. 기본값: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. 기본값: `604800`. |
| `--scope '<json>'` | `environments`, `agent_ids` 또는 기타 지원되는 범위 필드로 필터링합니다. |
| `--ignore-error-type <type>` | 오류 유형 제외; 반복하거나 쉼표로 구분합니다. |
| `--llm` / `--no-llm` | 에이전틱 분석을 활성화하거나 비활성화합니다. 기본값: 활성화. |
| `--top-k <n>` | `1`–`500`개의 발견 사항 유지. 기본값: `50`. |
| `--sensitivity low\|medium\|high` | 보고 민감도 설정. 기본값: `medium`. |
| `--channels '<json>'` | 알림 채널 배열. |
| `--text <brief>` | 인라인 브리프, 최대 8,192자. |
| `--text-file <path>` | 파일에서 브리프 읽기; `--text`와 상호 배타적. |
| `--url <https-url>` | 공개 HTTPS 참조 추가; 최대 다섯 번 반복. |

첫 번째 실행에 컨텍스트가 필요한 경우 생성 중에 포함하세요. 생성 시 대기열에 추가된 실행이 시작되기 전에 정의와 컨텍스트를 함께 커밋합니다.

<Note>
  `fp audits run`은 비동기적입니다. 발견 사항을 읽기 전에 최신 실행이 성공하거나 실패할 때까지 `fp audits runs NAME`을 폴링하세요.
</Note>

`--api-key`는 자동화를 위한 것입니다. 로그인, 조직 전환 및 어시스턴트 명령에는 사용자 세션이 필요합니다.

## 환경 변수

| 변수 | 동등하거나 목적 |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | CLI 구성 디렉토리 재배치 (기본값 `~/.failproofai/fpcli`). |
| `FP_ANALYTICS_DISABLED` 또는 `DO_NOT_TRACK` | 익명 CLI 분석 비활성화. |
| `NO_COLOR` | 색상 출력 비활성화. |

명시적 플래그는 환경 변수보다 우선하고, 환경 변수는 저장된 구성보다 우선합니다. API 키 모드에서는 `--org` 또는 `FP_ORG`로 테넌트를 명시적으로 선택하세요.

<Warning>
  이 변수들의 `AGENTEYE_*` 철자는 **`fp`에서 읽히지 않으며** 읽힌 적도 없습니다 — CLI는 `FP_*`를 선언하고(`fp_cli/app.py`), 알 수 없는 변수는 오류가 아닙니다. `AGENTEYE_DASHBOARD_URL`을 설정해도 CLI의 대상이 변경되지 않습니다; 무시되며 명령은 저장된 대시보드를 기준으로 자동으로 실행됩니다.

  `AGENTEYE_HOME`과 `AGENTEYE_ENVIRONMENT`는 여전히 존재하지만, 이 CLI가 아닌 **수집기 및 원격 측정 SDK**에 속합니다.
</Warning>
