`fp`를 사용하여 Cloud 텔레메트리를 검사하고, 클라우드 관리형 적용(정책, 플릿 배포, 가드레일 결정)을 관리하며, 감사, 발견 사항, 이슈, 알림, 키, 사용자, 쿼리, 설정을 관리하세요. 로컬 훅, 정책, 캡처, 머신 등록은 [`failproofai`](/ko/reference/failproof-cli)를 사용하세요.

릴리스된 Cloud CLI를 격리된 도구로 설치하세요. Python 3.10 이상이 필요합니다.

```bash
uv tool install fp-cloud-cli
fp version
```

배포 패키지 이름은 `fp-cloud-cli`이고 설치되는 명령어는 `fp`입니다. PyPI에서 `fp`라는 이름이 이미 사용 중이었기 때문에 이름이 다릅니다.

## 로그인

`fp login`은 이메일로 6자리 코드를 보내고 세션을 저장합니다. 자체 서명 인증서를 사용하는 대시보드에 연결할 경우 로그인 시 `--insecure`를 추가하세요.

```bash
fp login
fp whoami
```

## 문법

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

전역 옵션은 명령어 앞에 위치해야 합니다:

```bash
fp --json sessions --since 24h
```

터미널 도움말은 `fp COMMAND --help` 또는 `fp COMMAND SUBCOMMAND --help`를 실행하세요.

### 이벤트

```text
fp events [OPTIONS]
```

개별 에이전트 이벤트를 나열합니다. 기본 경량 피드는 원시 페이로드를 제외합니다. `--full`은 범위가 제한된 조사에만 사용하세요.

| 옵션 | 설명 |
| --- | --- |
| `--limit`, `-n <n>` | 최대 총 행 수. 기본값: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, 또는 `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC 범위; `--since`를 덮어씁니다. |
| `--env <value>` | 환경 필터; 반복하거나 쉼표로 구분하여 값을 지정합니다. |
| `--event-type <value>` | 이벤트 타입 필터; 반복하거나 쉼표로 구분하여 값을 지정합니다. |
| `--agent-id <value>` | 에이전트 필터; 반복하거나 쉼표로 구분하여 값을 지정합니다. |
| `--session-id <value>` | 세션 필터; 반복하거나 쉼표로 구분하여 값을 지정합니다. |
| `--search <text>` | 페이로드 텍스트 검색; 반복 가능하며, 어떤 검색어든 일치하면 포함됩니다. |
| `--order asc\|desc` | 시간 정렬 순서. 기본값: 최신 항목 먼저. |
| `--all` | `--limit`까지 자동 페이지네이션. |
| `--cursor <token>` | 불투명 커서에서 재개합니다. |
| `--page-size <n>` | `--all` 사용 시 요청당 행 수; 최대 `200`. |
| `--full` | 더 무거운 이벤트 엔드포인트를 통해 원시 페이로드를 포함합니다. |
| `--fields <csv>` | 선택한 필드만 반환합니다; `payload`를 요청하면 전체 모드가 활성화됩니다. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all`은 **`--limit`까지** 페이지네이션하며, 기본값은 **50**입니다. 따라서 `--all`만 단독으로 사용하면 50행에서 중단됩니다. 조기에 중단될 경우 응답에 재개를 위한 `next_cursor`가 포함됩니다. `"next_cursor": null`은 피드가 실제로 소진되었음을 의미합니다.
</Note>

#### 감사 생성 옵션

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| 옵션 | 설명 |
| --- | --- |
| `--file <path>` | JSON을 기반으로 정의하거나, stdin에는 `-`를 사용합니다. 명시적 플래그는 파일 값을 덮어씁니다. |
| `--description <text>` | 실패 질문이나 목적을 기술합니다. |
| `--enabled` / `--disabled` | 스케줄링을 켜거나 끈 상태로 시작합니다. 기본값: 활성화됨. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. 기본값: `86400`. |
| `--schedule-anchor <timestamp>` | ISO 8601 형식의 고정 UTC 위상. 기본값: 다음 09:00 UTC. |
| `--window-mode since_last\|fixed` | 마지막으로 완전히 분석된 창 이후로 계속하거나 롤링 창을 반복적으로 검사합니다. 기본값: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. 기본값: `604800`. |
| `--scope '<json>'` | `environments`, `agent_ids` 또는 다른 지원되는 스코프 필드로 필터링합니다. |

  `fp audits run`은 비동기식입니다. 발견 사항을 읽기 전에 `fp audits runs NAME`을 폴링하여 최신 실행이 성공하거나 실패할 때까지 기다리세요.

### 정책

클라우드 관리형 정책 버전입니다. **세션 전용** — `fp policies test`를 제외한 모든 명령어는 API 키로 실행 시 요청 전에 종료 코드 `2`로 종료됩니다. 이는 이러한 경로들이 `/v1`에 의도적으로 없는 루트 전용 쓰기 경로이기 때문입니다. `fp policies test`는 의도적인 예외입니다: `node`에 대해 완전히 로컬에서 실행되며 서버와 통신하지 않으므로 인증 요구 사항이나 키 모드 거부가 없으며, 로그아웃 상태 및 API 키 모두에서 작동합니다.

| 명령어 | 목적 | 옵션 |
| --- | --- | --- |
| `fp policies list` | 정책 버전 목록을 표시합니다. 각 정책의 최신 버전이 먼저 표시됩니다. | — |
| `fp policies show POLICY_ID` | 소스와 함께 하나의 정책을 표시합니다. | — |
| `fp policies publish POLICY_ID [SOURCE]` | 새 버전을 생성합니다; 기존 버전을 절대 편집하지 않습니다. `SOURCE`는 경로, `@path`, 또는 stdin의 경우 `-`입니다 — 생략하면 붙여넣기 모드가 됩니다. | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | 제거된 모든 배포에 다시 추가하여 각각 새 세대를 생성합니다. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | 해당 정책을 포함한 모든 배포에서 제거하여 각각 새 세대를 생성합니다. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | 정책 버전을 삭제합니다. | `--yes`, `-y` |
| `fp policies test [SOURCE]` | 합성 컨텍스트에 대해 정책을 로컬에서 실행합니다. 각 정책의 `match` 필터를 적용하므로, 주어진 이벤트/도구를 다루지 않는 정책은 실행되지 않고 `skipped`로 보고됩니다. PATH에 `node`가 필요합니다. | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | 어시스턴트를 사용하여 정책 초안을 작성합니다. 기본적으로 초안을 출력하고 다른 작업은 수행하지 않습니다. `policies:write`가 필요합니다. | `--out <path>`; `--publish <policy-id>` |


#### 정책 참조

`--add`와 `--set`은 단순 ID가 아닌 정책 참조를 사용합니다:

| 형식 | 의미 |
| --- | --- |
| `id` | 현재 버전, 현재 효과 |
| `id@3` | 버전 3, 현재 효과 |
| `id:observe` | 현재 버전, 기록되지만 적용되지 않음 |
| `id@3:observe` | 버전 3, 기록되지만 적용되지 않음 |

효과는 `enforce` 또는 `observe`입니다. 결정 순서는 다음과 같습니다: 명시적 효과가 우선 적용되고, 그렇지 않으면 해당 정책에 이미 배포된 효과가 사용되며, 그렇지 않으면 `enforce`가 적용됩니다.

<Warning>
  단순 `--add`는 **즉시 적용됩니다**. `fp fleet deploy ci-runner-01 --add checkout-guard`는 해당 머신이 다음에 가져오는 즉시 차단을 시작합니다. `:observe`가 섀도우 롤아웃을 만드는 방법입니다:

  ```bash
  fp fleet deploy ci-runner-01 --add checkout-guard:observe   # records only
  fp fleet deploy ci-runner-01 --add checkout-guard           # enforces now
  ```

  Observe는 비활성화가 아닙니다. 정책은 적용 정책과 동일한 10초 타임아웃 및 동일한 오류 처리 하에 실제로 평가되며, 모든 비-allow 판정이 기록됩니다 — 다만 적용만 보류됩니다. 바로 그것이 측정값을 읽을 가치 있게 만드는 이유입니다.
</Warning>

#### 델타, 교체, 경쟁 조건

`--add`와 `--remove`는 머신의 현재 세트를 읽고 델타를 적용하므로, 명시하지 않은 항목은 변경되지 않습니다. 머신이 이미 실행 중인 정책에 단순 `--add`를 사용하면 자동으로 업그레이드하지 않고 고정된 버전을 유지합니다; 버전을 변경하려면 `id@version`을 전달하세요.

`--set`은 모든 것을 교체하며 명시하지 않은 정책을 제거하는 유일한 방법입니다. `--add` 또는 `--remove`와 함께 사용할 수 없습니다. 세 가지 중 어느 것도 전달하지 않으면 no-op이 아닌 사용 오류입니다.

```bash
fp fleet deploy ci-runner-01 --add prod-guard@1:observe --remove old-rule
fp fleet deploy ci-runner-01 --set no-force-push --set no-secret-echo
```

쓰기 자체는 모든 경로에서 전체 교체입니다. 엔드포인트가 전체 정책 세트를 받기 때문입니다. 서버 측 잠금이 없으므로 CLI는 읽은 세대를 기록하고 결과가 정확히 하나 더 높지 않으면 거부합니다 — 이는 그 사이에 다른 사람이 배포했음을 의미하며, 교체는 병합하지 않습니다. `fp fleet show`로 다시 읽은 후 다시 배포하세요.

`--create`는 아직 체크인하지 않은 머신 ID에 배포하기 위한 사전 준비용입니다. 이 옵션 없이는 서버가 알지 못하는 ID가 거부됩니다. 오타가 있으면 아무도 소유하지 않고 아무도 수집하지 않는 정책을 가진 머신이 생성될 수 있기 때문입니다.

### 가드레일

실제로 적용이 수행한 내용입니다. **세션 전용**, 위와 동일한 이유입니다.

| 명령어 | 목적 | 옵션 |
| --- | --- | --- |
| `fp guardrails summary` | 커버리지, 차단/평가 합계, 거부 스파크라인, 정책별 테이블을 표시합니다. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |
| `fp guardrails timeline` | 창 전체에 걸쳐 모든 정책 소스를 합산한 결정을 버킷으로 표시합니다. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |

요약의 `(no policy)` 행은 갭이 아닌 정상적인 상태입니다: 대부분의 평가는 아무도 이의를 제기하지 않는 allow이며, 이 행은 화면에 분모를 유지합니다.

### 중단 없이 정책 롤아웃하기

위의 세 그룹은 하나의 시퀀스입니다. 로컬에서 결정하고, 게시하고, 섀도우 테스트하고, 측정한 후 적용하세요.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

| 단계 | 존재하는 이유 |
| --- | --- |
| `fp policies test` | 서버 없음, 인증 없음. 설명한 컨텍스트에 대해 실제 파일을 실행하고 등록된 정책당 allow, deny, 또는 instruct를 출력합니다. `--expect`는 이를 CI 어설션으로 변환합니다. |
| `fp policies publish` | 새로운 불변 버전을 생성합니다; 기존 버전을 절대 편집하지 않습니다. |
| `fp fleet deploy --add <id>:observe` | 섀도우 롤아웃입니다. **여기서 `:observe`는 선택 사항이 아닙니다** — 단순 `--add`는 머신이 가져오는 즉시 적용됩니다. |
| `fp guardrails summary` | 정책이 차단했을 합법적인 작업에서 안전하지 않은 매칭을 분리합니다. |
| `fp fleet deploy --add <id>:enforce` | 기록된 판정이 예상한 내용을 말해주면 프로모션합니다. |
| `fp fleet rollback <machine> <generation>` | 적용이 잘못될 경우 돌아가는 방법입니다. |

Cloud 없이 단일 머신에 해당하는 방법은 `failproofai publish --effect observe`로 팩을 게시하고 [로컬 대시보드](/ko/reference/local-dashboard)에서 기록된 판정을 읽는 것입니다.

API 키 모드에서는 사람이 `fp login`으로 저장한 조직이 **무시됩니다** — 단순히 재정의되는 것이 아니라 완전히 무시되며, 명시적인 `--org` 또는 `FP_ORG`만 전송됩니다. 저장된 로그인에서 상속되는 것은 없으므로, 키가 하나 이상의 조직에 대해 작업할 수 있는 경우 `--org`를 전달하세요. 생략해도 큰 소리로 실패하지 않습니다: `--org` 없이 인스턴스 범위 키는 서버 측에서 **기본** 조직으로 확인되어 해당 조직의 데이터로 응답하며, 어디에도 오류가 발생하지 않습니다. `fp whoami`를 먼저 실행하여 키가 실제로 어느 테넌트와 통신하는지 확인하세요.

  이러한 변수들의 `AGENTEYE_*` 철자는 **`fp`에서 읽히지 않으며** 읽힌 적도 없습니다 — CLI는 `FP_*`를 선언하며 (`fp_cli/app.py`), 알 수 없는 변수는 오류가 아닙니다. `AGENTEYE_DASHBOARD_URL`을 설정해도 CLI의 대상이 변경되지 않습니다; 무시되어 명령어는 저장된 대시보드를 대상으로 조용히 실행됩니다.

  `AGENTEYE_HOME`과 `AGENTEYE_ENVIRONMENT`는 여전히 존재하지만, 이 CLI가 아닌 **수집기와 텔레메트리 SDK**에 속합니다.
</Warning>
