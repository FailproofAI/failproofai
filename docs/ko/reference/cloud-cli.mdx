`fp`를 사용하여 Cloud 텔레메트리를 검사하고, 클라우드 관리형 적용(정책, 플리트 배포, 가드레일 결정)을 관리하며, 감사, 발견 사항, 이슈, 알림, 키, 사용자, 쿼리, 설정을 관리할 수 있습니다. 로컬 훅, 정책, 캡처, 머신 등록에는 [`failproofai`](/ko/reference/failproof-cli)를 사용하세요.

또한 호스팅된 코드, LLM 판정 및 Jev 평가자를 작성하고 배포하고, 대시보드를 관리하고, 감성을 검사하며, 터미널에서 대시보드 어시스턴트를 사용할 수 있습니다.

릴리스된 Cloud CLI를 독립형 도구로 설치합니다:

```bash
uv tool install fp-cloud-cli
fp version
```

## 로그인

```bash
fp login
fp whoami
```

## 구문

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

전역 옵션은 명령 앞에 위치해야 합니다:

```bash
fp --json sessions --since 24h
```

터미널 도움말을 보려면 `fp COMMAND --help` 또는 `fp COMMAND SUBCOMMAND --help`를 실행하세요.

## CLI 명령

### 평가자 작성

`fp evaluators`는 정의를 작성하고, `fp evals`는 결과를 읽습니다. 활성화된 관리형 인스턴스가 필요합니다(`fp evaluators instances`). 작성에는 `evaluations:trigger`가 필요하고, 세션 드라이런 및 스키마 프로파일링에는 `events:read`도 필요합니다.

코드는 제한된 단일 Python 표현식입니다. 이를 `error_free.py`로 저장하세요:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM 판정:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev 이진 및 등급 루브릭:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
생성 시 평가자가 활성화됩니다. 배포는 새로운 불변 버전을 생성한 후 이전 활성화된 버전을 비활성화합니다. 후속 작업이 실패하면 새 버전이 게시된 상태로 남습니다. 재시도 전에 `evaluators list --all`을 검사하세요.
판정 드라이런은 Cloud에서 거부됩니다. Jev 드라이런은 모델 예산을 소비합니다.
백필은 코드, 판정 및 Jev 평가자를 지원하며 최대 90일까지 허용합니다. 아직 평가자가 채점하지 않은 세션만 대기열에 추가됩니다. 판정 및 Jev 백필은 모델 예산을 소비하므로 먼저 `fp evaluators backfill --dry-run`을 실행하세요.
휴먼 출력은 생성/배포 전에 세션별 드라이런 결과를 보여줍니다.
미리보기가 실패하면 검토 후 명시적으로 `--force`를 전달하지 않는 한 쓰기가 중단됩니다.
</Warning>

AI 초안 작성에는 `fp login`이 필요하며, create/deploy에서 사용할 수 있는 spec을 생성합니다:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# 활성화하기 전에 초안의 key, source, condition을 검토하세요.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| 명령 | 옵션 / 동작 |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | 전체 소스/봉투 |
| `fp evaluators create` | `--key`, `--name`, `--version`, 반복 `--label`, `--condition EXPR\|@file`, 하나의 소스, 반복 `--dry-run-on`, `--disabled`, 실패한 미리보기에 대한 명시적 `--force` |
| `fp evaluators deploy KEY` | 동일한 소스 플래그; `--version`, `--backfill 7d` (모든 종류, 1–90일), `--force`; 숫자 버전은 자동 증가; KEY는 누락된 spec-file `eval_key`를 제공 |
| `fp evaluators draft "intent"` | 세션; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | 소스 플래그 또는 `--file`, 반복 `--session` (최대 10개); 없으면 컴파일만 수행 |
| `fp evaluators enable\|disable KEY[@VERSION]` | 토글 |
| `fp evaluators label KEY[@VERSION]` | 반복 `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | 관리형 플리트/스키마/작업 검사 |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; 코드, 판정 및 Jev |

코드 플래그는 `--code FILE|-`, `--result-kind score|metric|assertion`, `--timeout S`입니다. 판정 플래그는 `--judge --criteria TEXT`, 반복 `--step`, `--threshold`입니다. Jev 플래그는 `--jev noul --instructions --true --false` 또는 최악 순서로 3–5개의 고유한 `--level` 값을 갖는 `--jev score --instructions`입니다.
판정/Jev는 점수가 필요하며, 임계값은 0–1입니다. 이진 판정 단계는 거부됩니다.

Spec 파일에는 정확히 `eval_key`, `display_name`, `eval_version`, `result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`가 포함됩니다.
판정/Jev `evaluator_source`는 JSON 봉투 문자열입니다. 행 ID, 활성화 상태 또는 AI 추론 메타데이터를 포함하지 마세요. `--file`과 개별 spec 플래그는 상호 배타적입니다. deploy는 파일의 버전을 재정의할 수 있습니다. 출력 파일은 덮어쓰지 않습니다.

### 새 대시보드 컨트롤

모든 명령은 전역 `--json`을 허용합니다. 알 수 없는 경로의 404는 "not available on this FailproofAI Cloud yet"과 함께 종료 코드 6으로 종료됩니다. 레코드가 없는 404도 종료 코드 6으로 종료되지만 레코드를 찾을 수 없다고 보고합니다. 세션 전용 명령은 HTTP 이전에 키 모드를 거부합니다(종료 코드 2).

휴먼 명령은 요약과 표를 사용합니다. 원시 JSON 내보내기는 전역 `--json`을 전달하거나 `--out FILE`로 저장하세요. 그렇지 않으면 세션 및 JSON 쿼리 내보내기가 읽기 가능한 형식으로 표시됩니다. CSV 내보내기는 파이핑을 위해 일반 CSV로 유지됩니다.

| 명령 | 옵션 / 참고 |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | Create: `--name`, `--description`, `--file` 정의; update는 언급되지 않은 필드를 보존 |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | Add: `--query ID --chart TYPE --title`; `--file`을 통한 config/geometry 또는 layout |
| `fp sessions show\|export\|history\|re-evaluate ID` | Export: `--out`; history는 평가 이력 |
| `fp sessions import FILE...` | Claude Code 트랜스크립트, Codex 롤아웃 또는 이벤트 JSONL (`.gz` 가능); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; `events:add` 필요 |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; list: `--limit`; messages: `--session-id` |
| `fp query compose "question"` | 세션; `--run` |
| `fp query export [ID]` | 또는 `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Issues는 `--create --title --summary` 또는 `--create --file` 가능 |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; update: `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | 세션; 조직의 이벤트에서 정책 초안 작성, 게시하지 않음 |
| `fp policies backtest [FILE_OR_ID]` | 세션; regex는 모듈을 재실행; `jev`/`both` (게시됨 또는 `--semantic checks.json`)는 무료로 추정, `--run [--sample N]`은 Jev 허용량 소비; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | 세션; 이 이슈를 정책이 방지할 수 있는지 여부 |
| `fp issues facets` | 받은 편지함 필터가 가질 수 있는 값과 개수 |
| `fp agent brief` | 세션; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | 세션; 생략된 slug를 도출하며, 조직을 전환하지 않음 |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | 권한 세트; create: `--name --permission`; update: `--permission` 교체 또는 `--add/--remove` 병합; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | ID로 삭제 |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows`는 API 키 필요; plan(제안 및 체험)과 claim은 로그인된 세션 필요 |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1,000,000 토큰 |
| `fp otel status\|enable\|disable` | Cloud 조직 수집 스위치, 로컬 캡처가 아님 |
| `fp slack status\|disconnect` | 세션 |

`fp agent ask`는 `queries:run`을 통해 아티팩트 SQL을 테이블/통계로 렌더링합니다.
쓰기 승인은 제안된 변경 사항을 표시하고 터미널에서 프롬프트를 표시합니다. 스크립트와 `--json`은 `--approve`가 명시적으로 지정되지 않으면 거부합니다. 아티팩트가 반환되지 않으면 기존 JSON 형태는 변경되지 않습니다.

### 인증

| 명령 | 목적 | 옵션 |
| --- | --- | --- |
| `fp login` | 브라우저 또는 이메일로 받은 일회용 코드로 로그인하고 조직을 선택합니다. `--email`은 코드로 바로 이동합니다. | `--email`, `-e`; `--org`; `--force` |
| `fp logout` | 저장된 사용자 세션을 취소하고 삭제합니다. | — |
| `fp whoami` | 현재 ID, 인증 모드, 조직 및 권한을 표시합니다. | — |
| `fp version` | 설치된 CLI 버전을 표시합니다. | — |
| `fp help` | 최상위 명령 도움말을 표시합니다. | — |

```bash
fp login
fp login --email you@example.com --org reliability-team
fp whoami
```

터미널에서 `fp login`은 링크로 시작하여 브라우저나 SSO로 로그인하고 열립니다(SSH 또는 디스플레이가 없는 경우 링크만 표시되며, 모든 기기에서 작동합니다). 승인하면 터미널이 자동으로 완료됩니다. 해당 터미널은 세션이 만료될 때까지 모든 조직에서 접근 권한을 얻으므로, 직접 요청한 링크만 승인하세요. 로그인이 다른 네트워크에서 시작된 경우, 세션이 생성되면 이메일을 받고 페이지에서 배포 위치를 알 수 있는 경우 경고를 표시합니다. 대신 이메일로 6자리 코드를 받으려면 **Tab**을 누르고, 돌아가려면 Tab을 다시 누르세요. `--email`, `--json` 및 터미널이 없는 경우에는 코드를 사용합니다.

### 이벤트

```text
fp events [OPTIONS]
```

개별 에이전트 이벤트를 나열합니다. 기본 경량 피드는 원시 페이로드를 제외합니다. `--full`은 범위가 제한된 조사에만 사용하세요.

| 옵션 | 설명 |
| --- | --- |
| `--limit`, `-n <n>` | 최대 총 행 수. 기본값: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, 또는 `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC 범위; `--since`를 재정의합니다. |
| `--env <value>` | 환경 필터; 반복하거나 쉼표로 구분하여 값을 지정합니다. |
| `--event-type <value>` | 이벤트 타입 필터; 반복하거나 쉼표로 구분하여 값을 지정합니다. |
| `--agent-id <value>` | 에이전트 필터; 반복하거나 쉼표로 구분하여 값을 지정합니다. |
| `--session-id <value>` | 세션 필터; 반복하거나 쉼표로 구분하여 값을 지정합니다. |
| `--search <text>` | 페이로드 텍스트 검색; 반복 가능하며, 조건 중 하나라도 일치하면 됩니다. |
| `--order asc\|desc` | 시간 순서. 기본값: 최신 순. |
| `--all` | `--limit`까지 자동 페이지네이션. |
| `--cursor <token>` | 불투명한 커서에서 재개합니다. |
| `--page-size <n>` | `--all`에서 요청당 행 수; 최대 `200`. |
| `--full` | 더 무거운 이벤트 엔드포인트를 통해 원시 페이로드를 포함합니다. |
| `--fields <csv>` | 선택한 필드만 반환합니다; `payload`를 요청하면 전체 모드가 활성화됩니다. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all`은 기본값이 **50**인 `--limit`**까지** 페이지네이션합니다. 따라서 `--all`만 사용하면 50행에서 멈춥니다. 일찍 멈추면 응답에 `next_cursor`가 포함되어 재개할 수 있습니다. `"next_cursor": null`은 피드가 실제로 소진되었음을 의미합니다.
</Note>

### 평가

```text
fp evals [OPTIONS]
```

| 옵션 | 설명 |
| --- | --- |
| `--aggregate` | 개별 평가 대신 총계 및 점수별 통계를 표시합니다. |
| `--limit`, `-n <n>` | 최대 목록 행 수. 기본값: `50`. |
| `--since`, `--from`, `--to` | 시간 범위를 선택합니다. |
| `--env`, `--status`, `--agent-id`, `--session-id` | 필터당 정확히 하나의 값으로 범위를 좁힙니다. |
| `--score KEY:MIN..MAX` | 점수 범위; 반복 가능하며 모든 범위가 일치해야 합니다. |
| `--all`, `--cursor`, `--page-size` | 목록 페이지네이션을 제어합니다. |
| `--fields <csv>` | 선택한 필드만 반환합니다. |
| `--full-ids` | 전체 세션 ID를 표시합니다. |
| `--scores-full` | 터미널 출력에서 모든 점수를 표시합니다. |

#### 감사 create 옵션

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| 옵션 | 설명 |
| --- | --- |
| `--file <path>` | JSON을 기반으로 정의하거나, stdin에는 `-`를 사용합니다. 명시적 플래그가 파일 값을 재정의합니다. |
| `--description <text>` | 실패 질문이나 목적을 설명합니다. |
| `--enabled` / `--disabled` | 스케줄링을 켜거나 끄고 시작합니다. 기본값: 활성화됨. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. 기본값: `86400`. |
| `--schedule-anchor <timestamp>` | ISO 8601 형식의 고정 UTC 위상. 기본값: 다음 09:00 UTC. |
| `--window-mode since_last\|fixed` | 마지막으로 완전히 분석된 창 이후를 계속하거나 롤링 창을 반복적으로 검사합니다. 기본값: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. 기본값: `604800`. |
| `--scope '<json>'` | `environments`, `agent_ids` 또는 기타 지원되는 범위 필드로 필터링합니다. |
| `--ignore-error-type <type>` | 오류 타입을 제외합니다; 반복하거나 쉼표로 구분합니다. |
| `--llm` / `--no-llm` | 에이전틱 분석을 활성화하거나 비활성화합니다. 기본값: 활성화됨. |
| `--top-k <n>` | `1`–`500`개의 발견 사항을 유지합니다. 기본값: `50`. |
| `--sensitivity low\|medium\|high` | 보고 감도를 설정합니다. 기본값: `medium`. |
| `--channels '<json>'` | 알림 채널 배열. |
| `--text <brief>` | 인라인 개요, 최대 8,192자. |
| `--text-file <path>` | 파일에서 개요를 읽습니다; `--text`와 상호 배타적입니다. |
| `--url <https-url>` | 공개 HTTPS 참조를 추가합니다; 최대 5번 반복합니다. |

첫 번째 실행에 컨텍스트가 필요한 경우 생성 시 포함하세요. 생성은 대기열에 추가된 실행이 시작되기 전에 정의와 컨텍스트를 함께 커밋합니다.

<Note>
  `fp audits run`은 비동기입니다. 발견 사항을 읽기 전에 최신 실행이 성공하거나 실패할 때까지 `fp audits runs NAME`을 폴링하세요.
</Note>

### 정책

Cloud 관리형 정책 버전입니다. **세션 전용** — 여기의 모든 명령은 `/v1`에 의도적으로 없는 루트 전용 쓰기 경로이므로 API 키 하에서 어떤 요청보다 먼저 `2`로 종료됩니다.

| 명령 | 목적 | 옵션 |
| --- | --- | --- |
| `fp policies list` | 정책 버전 목록과 각 버전의 종류(`regex`, `jev`, `both`) 및 Jev 검사 이름을 표시합니다. | `--json` |
| `fp policies show POLICY_ID` | 하나의 정책을 소스 및 Jev 검사와 함께 표시합니다. | — |
| `fp policies publish NAME [PATH]` | 버전을 생성합니다: JavaScript(`regex`, 기본값), JSON 선언 파일의 Jev 검사(`jev`), 또는 JavaScript가 자체 검사에 의해 검토 가능한 둘 다(`both`). | `--kind`; `--source`; `--semantic`; `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | 제거된 모든 배포에 다시 추가하고 각각에 새 세대를 생성합니다. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | 이를 보유한 모든 배포에서 제거하고 각각에 새 세대를 생성합니다. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | 정책 버전을 삭제합니다. | `--yes`, `-y` |
| `fp policies test PATH` | 합성 컨텍스트에 대해 정책을 로컬로 실행합니다. 각 정책의 `match` 필터를 적용하므로 주어진 이벤트/도구를 다루지 않는 정책은 실행되지 않고 `skipped`로 보고됩니다. | `--event`; `--tool`; `--command`; `--file`; `--expect` |

## 전역 플래그

| 플래그 | 설명 |
| --- | --- |
| `--json` | 머신 판독 가능한 JSON을 출력합니다. 오류에는 실패한 요청의 `request_id`가 포함됩니다. |
| `--base-url <url>` | 자체 호스팅 또는 개발 대시보드를 사용합니다. |
| `--org <slug>` | 이 호출에 대한 조직을 선택합니다. |
| `--token <token>` | 저장된 사용자 세션 토큰을 재정의합니다. |
| `--api-key <key>` | API 키로 자동화를 인증합니다; 저장되지 않습니다. |
| `--timeout <seconds>` | HTTP 타임아웃; 양수여야 합니다. 기본값: `30`. |
| `--quiet`, `-q` | stderr의 상태 출력을 억제합니다. |
| `--no-color` | 컬러 출력을 비활성화합니다. |
| `--insecure` / `--secure` | TLS 인증서 검증을 비활성화하거나 복원합니다. |
| `--version` | 버전을 출력하고 종료합니다. |
| `--help`, `-h` | 도움말을 표시합니다. |

`--api-key`는 자동화를 위한 것입니다. 로그인, 조직 전환 및 어시스턴트 명령에는 사용자 세션이 필요합니다.

명시적 플래그는 환경 변수를 재정의하고, 환경 변수는 저장된 구성을 재정의합니다. API 키 모드에서는 `--org` 또는 `FP_ORG`를 사용하여 테넌트를 명시적으로 선택하세요.

<Warning>
  이 변수들의 `AGENTEYE_*` 형식은 **`fp`에서 읽히지 않으며** 읽힌 적도 없습니다 — CLI는 `FP_*`를 선언하며 (`fp_cli/app.py`), 알 수 없는 변수는 오류가 아닙니다. `AGENTEYE_DASHBOARD_URL`을 설정해도 CLI의 대상이 변경되지 않습니다; 무시되고 명령은 저장된 대시보드에 대해 자동으로 실행됩니다.

  `AGENTEYE_HOME`과 `AGENTEYE_ENVIRONMENT`는 여전히 존재하지만, 이 CLI가 아닌 **컬렉터 및 텔레메트리 SDK**에 속합니다.
</Warning>

<Warning>
  삭제, 취소, 억제, 해결 또는 구성 교체 명령은 기본적으로 확인을 요청합니다. `--yes`는 활성 조직과 대상을 확인한 후에만 사용하세요.
</Warning>
