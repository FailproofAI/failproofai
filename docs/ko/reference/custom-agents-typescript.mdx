Node 20.9 이상. ESM 및 CommonJS 지원. 런타임 의존성 없음.

<Note>
  이 SDK와 Python SDK는 **동일한 스풀에 동일한 이벤트를 기록합니다**. Node 에이전트와 Python 에이전트가 혼합된 플릿은 두 개의 세션 집합이 아닌 하나의 세션 집합을 생성하며, 대시보드에서도 둘을 구분하지 않습니다. 회사 단위가 아닌 서비스 단위로 선택하세요.
</Note>

## 설치

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

프레임워크 어댑터는 패키지 자체에 포함되어 있습니다. 프레임워크는 **선택적 피어 의존성**으로 처리됩니다 — 지원 범위를 명시하기 위해 선언되지만, 자동으로 설치되지 않으며 `instrument()`를 호출할 때만 임포트됩니다.

## Failproof 데몬 연결

Python SDK와 동일합니다: **Admin → Keys**에서 `events:add` 키를 생성한 후 에이전트 머신에서 [데몬을 연결](/ko/start/setup#connect-a-machine-to-cloud)하세요. SDK는 디스크에 기록하고, 데몬이 전송합니다.

## 설정

### OpenTelemetry 스팬 (opt in)

`npm install @opentelemetry/api @opentelemetry/sdk-trace-base`로 OpenTelemetry를 별도로 설치하세요.
그런 다음 프로바이더의 프로세서에 FailproofAI를 추가합니다:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

기존 프로바이더가 있다면 동일한 리스트에 나머지 프로세서를 그대로 유지하세요. `addSpanProcessor`를 노출하는 프로바이더는 `{ provider }`로 직접 전달할 수 있습니다. 옵션 없이 설정하면, 이미 등록된 프로바이더가 없는 경우에만 새 프로바이더를 등록합니다.
`OtelSpanExporter`를 직접 자체 프로세서와 함께 사용할 수도 있습니다.

익스포트는 연결된 FailproofAI 데몬을 통해 이루어지며, SDK는 네트워크 요청을 보내지 않고 키나 로컬 리스너가 필요하지 않습니다. 관리자에게 [OpenTelemetry 인제스트](/ko/agenteye/opentelemetry) 활성화를 요청하세요. 단순 `instrument()` 호출은 이 익스포터를 활성화하지 않습니다. `uninstrument("otel")`은 자체 프로세서만 비활성화합니다.
스팬 속성이 콘텐츠 캡처를 제어하므로, 종료 전에 프로바이더를 플러시하세요.
OpenTelemetry는 SDK의 하드 의존성이 아닌 선택적 애플리케이션 의존성으로 유지됩니다.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| 옵션 | 설명 |
| --- | --- |
| `environment` | 모든 이벤트에 붙는 레이블 — `production`, `staging`, `prod-eu`. 기본값은 `dev`. |
| `flushInterval` | 타이머가 디스크에 쓰는 주기(초 단위). 기본값은 `0.5`. |
| `baseDir` | 쓰기 경로. 기본값은 데몬의 스풀로, 특별한 이유가 없다면 변경할 필요 없음. |

전체 값이 유효성 검사를 통과해야만 적용되므로, 거부된 호출은 새 `baseDir`와 기존 인터벌이 혼합된 상태 없이 SDK를 이전 상태 그대로 유지합니다.

환경 변수로도 설정할 수 있습니다:

| 변수 | 설명 |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | 코드 변경 없이 `environment`를 설정합니다. `configure()` 옵션이 우선합니다. |
| `FAILPROOFAI_HOME` | 스풀을 보관하는 Failproof AI 루트 경로를 변경합니다. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (기본값), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1`로 설정하면 계측 오류를 로그 대신 예외로 던집니다. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1`로 설정하면 프레임워크 호환성 문제 발생 시 경고 후 계속하는 대신 예외를 던집니다. |

<Warning>
  **`environment`에 쉼표를 사용하지 마세요.** 인제스트가 해당 필드를 쉼표로 분리하여 필터를 구성하는데, 레이블에 쉼표가 포함된 이벤트는 모두 무시됩니다 — 전체 실행 결과가 조용히 사라질 수 있습니다. `prod,eu`가 아니라 `prod-eu`로 작성하세요.

  `configure({ environment: "prod,eu" })`는 즉시 예외를 던져 바로 알 수 있게 합니다. `AGENTEYE_ENVIRONMENT`는 예외를 던질 수 없으므로 — 호출하는 주체가 없기 때문에 — 경고를 한 번 출력하고 `dev`로 폴백합니다.
</Warning>

`failproofai.setLogger({ debug, info, warn, error })`로 SDK 자체 로그 라인을 자신의 로거로 라우팅할 수 있습니다.

## 종료 처리

버퍼링된 이벤트는 `process.on("exit")`에서 플러시됩니다.

시그널로 종료된 프로세스는 이 단계에 도달하지 못하며, Node의 `SIGTERM` 기본 동작은 종료 핸들러를 실행하지 않고 종료하는 것이므로 — 컨테이너화된 에이전트는 마지막 인터벌이 아직 쓰지 못한 데이터를 잃게 됩니다.

<Warning>
  **이 SDK는 시그널 핸들러를 자동으로 등록하지 않습니다.** 핸들러를 등록하면 프로세스 동작이 바뀝니다: 리스너가 추가되면 Node의 기본 종료가 억제되어, 라이브러리가 임의로 등록할 경우 Ctrl-C가 조용히 작동하지 않게 됩니다. 직접 추가하세요:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

단명하는 스크립트나 서버리스 핸들러는 반환 전에 `await failproofai.flush()`를 호출해야 합니다 — 타이머만으로는 전달이 보장되지 않습니다.

## 아이덴티티

모든 이벤트는 세션과 에이전트에 속합니다. **스코프가 둘 다 채워주므로** 직접 전달하는 경우는 거의 없습니다:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId`나 `agentId`를 명시적으로 전달하는 것도 여전히 가능하며, 명시적 값이 우선합니다. 바인딩도 전달도 없는 경우, Cloud가 조용히 버릴 이벤트를 내보내는 대신 호출이 예외를 던집니다.

<Note>
  아이덴티티는 `AsyncLocalStorage`를 통해 전달됩니다. `await`, `.then()`, 타이머, 스코프 내부에서 생성된 모든 콜백을 따라갑니다. 한 실행 중에 저장된 콜백이 다른 실행 중에 호출되거나, `worker_threads` 경계를 넘어 전달된 작업에는 **따라가지 않습니다** — 그런 경우에는 `failproofai.propagate()`로 감싸야 하며, 그렇지 않으면 해당 이벤트는 연결되지 않은 상태로 기록됩니다.
</Note>

### 스코프

| 스코프 | 발행하는 것 | 반환값 |
| --- | --- | --- |
| `session(body)` | 없음 — 아이덴티티 전달만 | `body`의 반환값 |
| `agent(id, options?, body)` | `agent_start`, 그 다음 `agent_end` | `body`의 반환값 |
| `toolCall(name, options?, body)` | `tool_use`, 그 다음 `tool_result` | `body`의 반환값 |

동기 바디는 동기로 유지됩니다: `agent("x", () => 1)`은 프로미스가 아닌 `1`을 반환합니다.

`toolCall`은 바디의 resolved 값을 도구의 `output`으로 기록하며, `call.output`을 직접 할당한 경우에는 그 값을 사용합니다.

<Accordion title="종료 시맨틱" icon="arrow-right-from-bracket">

| 발생한 상황 | 이벤트 | `outcome` |
| --- | --- | --- |
| 블록이 반환됨 | `agent_end` | `"success"`, 또는 지정한 `outcome` |
| 블록이 예외를 던짐 | `error`, 그 다음 `agent_end` | `"failed"` |
| `AbortError` | `agent_end`만 | `"cancelled"` |

오류는 항상 다시 던져집니다.

도구 실패는 리프에 기록됩니다 — `error` 문자열이 포함된 `tool_result` — 이며 실행 레벨의 `error` 이벤트는 **발행되지 않습니다**. 에이전트 루프가 잡은 오류는 실행 실패가 아니며, 전파되는 오류는 감싸는 `agent()`에 의해 정확히 한 번 보고됩니다.

</Accordion>

<Accordion title="`using` 형식" icon="brackets-curly">

작업이 단일 함수가 아닌 경우 — 생성자에서 열리고 테어다운에서 닫히는 스코프, 또는 기존 제어 흐름에 걸쳐있는 경우:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

두 형식 모두 바이트 단위로 동일한 이벤트를 발행합니다. 콜백 형식을 권장합니다: `AsyncLocalStorage.run()` 내부에서 실행되므로 언와인딩이 필요 없고, "여기서 열었는데 저기서 닫음" 류의 버그가 원천적으로 불가능합니다.

자체 실패를 잡는 `using` 블록은 `span.fail(error)`로 보고합니다 — 디스포저 자체에는 예외 채널이 없습니다.

</Accordion>

## 이벤트 카탈로그

Python SDK와 동일한 15가지 메서드를 camelCase로 제공합니다. 대부분 **쌍으로** 구성됩니다 — 오프너를 호출하고 클로저를 호출하면 SDK가 그 사이의 시간을 측정합니다.

| | 오프너 | 클로저 |
| --- | --- | --- |
| **에이전트** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **모델** | `modelRequest` | `modelResponse` |
| **도구** | `toolUse` | `toolResult` |
| **훅** | `hookTriggered` | `hookCompleted` |
| **휴먼** | `humanWait` | `humanInput` |

단독으로 사용하는 메서드 세 가지: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="메서드별 전체 필드" icon="table">

모든 메서드는 `sessionId`와 `agentId`도 받으며, 스코프가 이를 대신 채워줍니다. 생략된 항목은 JSON `null`로 전송되지 않고 그냥 제외됩니다.

| 메서드 | 필수 | 선택 |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

추가한 다른 키는 커스텀 페이로드 필드가 됩니다. 프레임워크 특화 항목은 `fw_*`로 네임스페이스를 붙이세요. 선언된 필드와 이름이 충돌하는 경우 조용히 덮어쓰지 않고 거부됩니다.

</Accordion>

<Warning>
  **`duration_ms`는 계산되는 값으로, 입력을 받지 않습니다.** 클로저 메서드 네 가지는 오프너로부터 경과 시간을 측정하며, 호출자가 제공한 `duration_ms`는 거부됩니다 — 보고된 지속 시간은 위변조가 불가능해야 합니다.

  쌍은 에이전트가 아닌 **세션**과 아이디로 매칭됩니다. `planner` 아래에서 열리고 `worker` 아래에서 닫힌 도구도 올바르게 쌍이 맞춰지는데, 이는 중첩 멀티에이전트 실행이 실제로 하는 방식입니다.
</Warning>

## 프레임워크 어댑터

```ts
await failproofai.instrument();              // 찾을 수 있는 모든 것
await failproofai.instrument("langchain");   // 정확히 하나
failproofai.uninstrument();                  // 모두 원래대로
```

| 프레임워크 | 지원 범위 | 연결 방식 |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`를 통해 `invoke`/`stream`/`batch` 모두 `callbacks:`를 별도로 전달하지 않아도 커버됨 — 또는 `langchainHandler()`를 직접 전달하고 패치 없이 사용. |
| **Vercel AI SDK** | `ai` 4 – 7 | 호출 지점에서 `telemetry()` 사용, 또는 `ai` 7에서는 `instrument("ai")`로 전체 프로세스 적용 (4–6에서는 opt-in — 아래 참조). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, 에이전트의 모델 및 도구 해석, 워크플로 실행/스텝 엔진. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (구독) 및 `AgentWorkflow.runStream` — 워크플로 실행과 스텝 커버. |

모든 범위는 실제 프레임워크 릴리스를 대상으로, 양 끝단에서, ES 모듈과 CommonJS 모두, 매 CI 실행마다 테스트됩니다.

매핑은 Python SDK와 동일하므로, 동일한 프로그램이 어느 언어에서도 같은 트리를 그립니다. LLM 결정 루프를 소유한 경우에만 **에이전트**로 취급됩니다 — 그래프 또는 체인 실행, AI SDK의 `generateText`/`streamText` 호출, Mastra 에이전트, LlamaIndex 에이전트 실행이 해당합니다. LangGraph 노드나 워크플로 스텝은 중첩 에이전트가 아닌 **훅**(`hook_triggered`/`hook_completed`)입니다. 모델 호출은 토큰 수를 포함한 `model_request`/`model_response` 쌍이며, 도구 호출은 모델 자체의 도구 호출 아이디를 가집니다. 실패는 발생한 이벤트에 한 번만 기록됩니다.

설치에 실패한 어댑터는 로그에 기록되고 건너뜁니다. 나머지 어댑터는 계속 설치됩니다 — LlamaIndex 오류가 LangGraph 계측에 영향을 주면 안 되기 때문입니다.

<Note>
  인수 없는 `instrument()`는 프레임워크가 이미 임포트되었는지가 아니라 **resolve 가능한지** 여부로 감지합니다 — Node는 ES 모듈에 대해 Python의 `sys.modules`에 해당하는 것을 노출하지 않습니다. 설치는 되어 있지만 사용하지 않는 프레임워크도 임포트되고 패치됩니다. 중요한 경우에는 원하는 것을 명시적으로 지정하세요.
</Note>

<Note>
  이 프레임워크들 대부분은 ES 모듈 빌드와 CommonJS 빌드를 별도로 제공하며, Node는 이를 서로 무관한 두 복사본으로 로드합니다. 어댑터는 애플리케이션이 로드하는 복사본을 패치하고 (이미 `require`된 경우 CommonJS 복사본도 패치), 두 모듈 시스템 모두 작동합니다. esbuild나 webpack으로 **번들에 포함된** 프레임워크는 도달할 수 없습니다 — 그 경우 호출 지점 헬퍼를 사용하세요: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### 패치 없이 LangChain 사용

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

핸들러는 `instrument()` 유무와 관계없이 작동하며 이중 기록이 없습니다. `instrument("langchain")`은 Python 어댑터와 동일하게 `sessionId`, `captureContent`, `includeChains`, `graphCallbacks`, `captureLimit`를 받습니다. 호출 시 `metadata: { failproofai_sdk_session_id }`로 해당 호출의 세션을 지정할 수 있습니다.

### Vercel AI SDK

AI SDK는 ES 모듈에서 일반 함수를 익스포트하는데, ES 모듈 네임스페이스는 명세상 불변이므로 — 패치할 곳이 없습니다. SDK 자체가 문서화한 확장 지점을 사용합니다:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // ai 7에서는 `telemetry: telemetry({ … })` — 동일한 객체, 새로운 이름
});
```

이것이 전체 통합입니다: 에이전트 스팬, 스텝당 토큰 수를 포함한 모델 request/response 쌍, 그리고 모든 도구 호출. 하나의 호출 지점이 모든 메이저 버전에서 동작합니다 — `ai` 4–6은 tracer를, `ai` 7은 telemetry 통합을 읽습니다.

`instrument("ai")`는 **`ai` 7에서** 프로세스 전체에 동일하게 적용됩니다: AI SDK의 전역 텔레메트리 통합 목록을 통해 모든 호출을 커버하며, 추가적으로 작동하고 다른 것을 빼앗지 않습니다.

**`ai` 4–6에서 `instrument("ai")`는 자체적으로 아무것도 기록하지 않으며 경고 한 번을 출력합니다.** 이 메이저 버전들에서 프로세스 전체에 걸친 훅은 전역 OpenTelemetry tracer 프로바이더뿐인데 — 이는 한 번 사용되면 OpenTelemetry가 양보하지 않는 단일 슬롯입니다. 이것을 등록하면 이후 시작 시 `NodeSDK.start()`가 조용히 거부되고, http/database 스팬이 아무것도 익스포트하지 않는 tracer로 가게 됩니다. 호출 지점에서 `telemetry()`를 사용하거나 `wrapModel`을 사용하세요. 프로세스에 자체 OpenTelemetry가 없다면 `instrument("ai", { registerGlobalTracer: true })`로 opt-in하세요: 이렇게 하면 `experimental_telemetry: { isEnabled: true }`를 전달하는 모든 호출을 기록하고, 슬롯이 비어 있을 때만 사용합니다. `registerGlobalTracer: false`는 기본 동작을 유지하고 경고를 없앱니다.

모델만 한 번에 감싸고 싶다면 `wrapModel`을 사용하세요. 단, 도구 호출은 모델 레이어 위에서 발생하므로 모델 호출만 볼 수 있습니다. 아무것도 감싸지 않고 호출된 래핑된 모델은 자체 실행으로 기록됩니다. 스트리밍 호출은 스트림이 멈추는 방식에 따라 닫힙니다 — 소비자가 취소하면 `stop_reason: "cancelled"`, 중간에 실패하면 오류와 함께 `"error"`:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

둘 다 사용해도 괜찮습니다: 미들웨어가 호출이 이미 기록 중임을 감지하고 위임하므로, 각 호출은 한 번만 기록됩니다.

`functionId`는 에이전트 스팬의 이름입니다. 카디널리티를 낮게 유지하세요 — `agent_id`에 기록되며, 대시보드의 주요 패싯입니다.

### Next.js

`next build`는 기본적으로 서버 의존성을 번들링하며, 번들에 포함된 프레임워크는 `instrument()`가 도달할 수 없는 복사본입니다. 설정을 한 번 감싸고 Next의 시작 훅에서 `instrument()`를 호출하세요:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai`는 LangChain, Mastra, LlamaIndex, SDK 자체를 `serverExternalPackages`에 추가하며 기존 목록을 유지합니다. 없으면 `instrument()`가 도달하지 못하는 프레임워크마다 경고를 한 번씩 출력하며 조용히 실패하지는 않습니다. 패키지를 직접 나열하는 경우 `FAILPROOFAI_NEXT_EXTERNALS=1`을 설정하세요. Vercel AI SDK와 호출 지점 헬퍼는 어느 경우에도 작동합니다. Edge 라우트는 no-op 빌드를 받으므로: SDK를 임포트해도 안전하며 아무것도 기록하지 않습니다.

### 스트리밍 호출의 토큰 수

OpenAI 호환 API는 클라이언트가 요청할 때만 스트림에서 사용량을 보고합니다. LangChain과 Vercel AI SDK는 이를 요청합니다. LlamaIndex는 `OpenAI` LLM에 `additionalChatOptions: { stream_options: { include_usage: true } }`를 전달하고, Mastra는 사용량이 활성화된 모델로 빌드하세요 (예: `createOpenAICompatible({ includeUsage: true })`). 그렇지 않으면 스트리밍 모델 호출에 토큰 수가 포함되지 않습니다.

### 런타임

Node ≥ 20.9, Bun, Deno — 모든 프레임워크를 ES 모듈과 CommonJS 모두, 각각에서 Node 트레이스 대비 테스트합니다. SDK는 `failproofaid` 데몬과 함께 실행되며, 데몬이 기록된 내용을 전송합니다.

## 직접 작성한 에이전트 — 프레임워크 없이

직접 작성한 에이전트 루프나 어댑터가 없는 프레임워크를 위한 방법입니다. 어댑터가 내부적으로 사용하는 것과 동일한 API로 이벤트를 발행하므로, 트레이스의 형태와 품질이 동일합니다.

에이전트가 어떻게 구성되어 있는지 알 필요 없습니다. 직접 작성한 에이전트라면 함수 이름에 관계없이 세 군데가 있고, 그 세 곳이 전체 통합입니다:

| 위치 | 추가할 것 | 발행하는 이벤트 |
| --- | --- | --- |
| **하나의 실행**이 시작되고 끝나는 곳 | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **모델을 호출하는 단 하나의 함수** | `event.modelRequest` 이전, `event.modelResponse` 이후 — 실패 시에도 두 쌍 모두 | 모델 턴당 하나의 쌍 |
| **도구를 실행하는 단 하나의 함수** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

아이덴티티는 ambient합니다: `agent()` 내부의 모든 것은 아이디를 받지 않아도 해당 실행의 세션에 속하며, 프로그램의 다른 부분 — 에이전트가 자체 데이터베이스에 쓰는 것 포함 — 은 아무것도 바뀌지 않습니다.

- **서비스 또는 워커:** 자체 request나 job id를 `sessionId`로 전달하면, 대시보드의 세션과 자체 로그 또는 데이터베이스의 레코드가 동일한 문자열이 됩니다.
- **서브에이전트:** `agent()` 호출을 중첩합니다. 내부 호출은 외부를 `parent_id`로 하여 세션에 합류합니다.
- **쌍을 발행하세요.** `modelResponse` 없는 `modelRequest`는 대시보드에서 영원히 실행 중으로 표시되는 스팬이 됩니다 — `catch`가 필요한 이유입니다.

저장소의 [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts)가 완전하고 실행 가능한 버전입니다: 이 방식으로 계측된 실제 OpenAI 도구 루프가 ES 모듈과 CommonJS 모두로 모든 변경마다 CI에서 실행됩니다.

## 평가

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

프로토콜, 워커 설정, 결과 타입에 대한 내용은 [Evaluator SDK 레퍼런스](/ko/reference/evaluator-sdk)를 참조하세요.

<Warning>
  **평가는 반드시 yield해야 합니다.** 절대 반환하지 않는 동기 함수는 Node의 단일 스레드를 블록하며, 그 동안에는 타임아웃도 발생할 수 없습니다. `async` 평가를 작성하세요.
</Warning>

## 프로세스에 미치는 영향

| | |
| --- | --- |
| **에이전트 루프를 블로킹하지 않습니다** | 이벤트는 인메모리 큐에 쌓이고 타이머가 씁니다. 타이머는 `unref`되어 있으므로, 이 패키지를 임포트해도 스크립트 종료가 지연되지 않습니다. |
| **무한히 늘어나지 않습니다** | 큐는 개수와 측정된 바이트 수 모두로 제한됩니다. 어느 쪽이든 초과하면 가장 오래된 이벤트가 버려지고 경고가 출력됩니다 — 텔레메트리 장애가 OOM 킬이 되어서는 안 됩니다. |
| **프로세스를 종료시키지 않습니다** | 인코딩할 수 없는 이벤트 하나만 버려지며, 주변 배치에는 영향이 없습니다. 예외를 던지는 getter, 순환 참조, `BigInt`, 단독 서로게이트: 각각이 처리되고 전파되지 않습니다. |
| **절반만 쓰인 배치를 남기지 않습니다** | 콘텐츠는 atomic rename 전에 `fsync`되고, 이후 디렉토리도 `fsync`됩니다. 실패한 쓰기는 임시 파일을 정리합니다. |
| **트랜스크립트를 읽을 수 있는 상태로 두지 않습니다** | 배치는 `0700` 디렉토리 내에 `0600` 권한으로 저장됩니다. goal, 프롬프트, 도구 인수, 도구 출력을 담고 있습니다. |
| **자격 증명을 전송하지 않습니다** | API 키, 토큰, JWT, bearer 헤더, secret처럼 보이는 할당문은 디스크에 쓰이기 전에 편집됩니다. 데몬도 업로드 전에 다시 편집합니다. |
