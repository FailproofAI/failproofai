Node 20.9 이상. ESM과 CommonJS 지원. 런타임 의존성 없음.

<Note>
  이 SDK와 Python SDK는 **동일한 스풀에 동일한 이벤트를 기록합니다**. Node 에이전트와 Python 에이전트가 혼재하는 플릿은 두 개가 아닌 하나의 세션 집합을 생성하며, 대시보드에서는 이 둘을 구분하지 않습니다. 회사 단위가 아닌 서비스 단위로 선택하세요.
</Note>

## 설치

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

프레임워크 어댑터는 패키지 자체에 포함되어 있습니다. 프레임워크는 **선택적 피어 의존성**입니다 — 지원되는 버전 범위를 명시하기 위해 선언되었을 뿐, 자동으로 설치되지 않으며 `instrument()`를 호출할 때만 임포트됩니다.

## Failproof 데몬 연결

Python SDK와 동일합니다: **Admin → Keys**에서 `events:add` 키를 생성한 후, 에이전트 머신에서 [데몬을 연결](/ko/start/setup#connect-a-machine-to-cloud)하세요. SDK는 디스크에 기록하고, 데몬이 전송합니다.

## 설정

### OpenTelemetry 스팬 (옵트인)

`npm install @opentelemetry/api @opentelemetry/sdk-trace-base`로 OpenTelemetry를 별도로 설치하세요.
그런 다음 FailproofAI를 프로바이더의 프로세서에 추가합니다:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

기존 프로바이더의 경우, 다른 프로세서들도 같은 목록에 유지하세요. `addSpanProcessor`를 노출하는 프로바이더는 `{ provider }`로 전달할 수 있습니다. 옵션 없이 사용하면, 이미 등록된 프로바이더가 없을 때만 새 프로바이더를 등록합니다.
`OtelSpanExporter`는 자체 프로세서와 함께 직접 사용할 수도 있습니다.

익스포트는 연결된 FailproofAI 데몬을 통해 이루어집니다. SDK는 네트워크 요청을 보내지 않으며 키나 로컬 리스너가 필요하지 않습니다. 관리자에게 [OpenTelemetry 인제스트](/ko/agenteye/opentelemetry) 활성화를 요청하세요. 단순히 `instrument()`를 호출하는 것만으로는 이 익스포터가 활성화되지 않습니다. `uninstrument("otel")`는 자체 프로세서만 비활성화합니다.
스팬 속성이 콘텐츠 캡처를 제어합니다. 종료 전에 프로바이더를 플러시하세요.
OpenTelemetry는 SDK의 하드 의존성이 아닌 선택적 애플리케이션 의존성으로 유지됩니다.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| 옵션 | 동작 |
| --- | --- |
| `environment` | 모든 이벤트에 붙는 레이블 — `production`, `staging`, `prod-eu`. 기본값은 `dev`. |
| `flushInterval` | 타이머가 디스크에 기록하는 주기(초). 기본값은 `0.5`. |
| `baseDir` | 기록 위치. 특별한 이유가 없으면 기본값인 데몬의 스풀을 사용하세요. |

모든 항목이 유효성 검사를 통과해야만 적용되므로, 거부된 호출은 새 `baseDir`과 기존 인터벌이 혼재하는 상태가 아닌, SDK를 이전 상태 그대로 유지합니다.

환경 변수로 설정하는 방법:

| 변수 | 동작 |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | 코드 변경 없이 `environment`를 설정합니다. `configure()` 옵션이 우선합니다. |
| `FAILPROOFAI_HOME` | 스풀을 포함하는 Failproof AI 루트 디렉터리를 변경합니다. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (기본값), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1`로 설정하면 계측 오류가 로깅 대신 throw됩니다. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1`로 설정하면 프레임워크 호환성 문제가 경고 후 계속 진행되는 대신 throw됩니다. |

<Warning>
  **`environment`에 쉼표를 사용하지 마세요.** 인제스트는 이 필드를 쉼표로 분리하여 필터를 만들며, 레이블에 쉼표가 포함된 이벤트는 무시합니다 — 따라서 전체 실행이 조용히 사라질 수 있습니다. `prod,eu`가 아닌 `prod-eu`로 작성하세요.

  `configure({ environment: "prod,eu" })`는 즉시 알 수 있도록 throw됩니다. `AGENTEYE_ENVIRONMENT`는 throw할 수 없습니다 — 호출하는 주체가 없기 때문에 — 따라서 한 번 경고를 남기고 `dev`로 폴백합니다.
</Warning>

`failproofai.setLogger({ debug, info, warn, error })`를 사용하여 SDK 자체 로그 라인을 자신의 로거로 라우팅하세요.

## 종료

버퍼링된 이벤트는 `process.on("exit")`에서 플러시됩니다.

시그널로 종료된 프로세스는 해당 핸들러에 도달하지 못하며, Node의 `SIGTERM` 기본 동작은 종료 핸들러 없이 프로세스를 종료하는 것입니다 — 따라서 컨테이너화된 에이전트는 마지막 인터벌에서 아직 기록되지 않은 데이터를 잃습니다.

<Warning>
  **이 SDK는 시그널 핸들러를 자동으로 설치하지 않습니다.** 시그널 핸들러를 등록하면 프로세스 동작이 변경됩니다: 리스너를 추가하면 Node의 기본 종료가 억제되므로, 라이브러리가 임의로 추가하면 Ctrl-C가 조용히 동작하지 않게 됩니다. 직접 추가하세요:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

단발성 스크립트나 서버리스 핸들러는 반환 전에 `await failproofai.flush()`를 호출해야 합니다 — 인터벌만으로는 전송을 보장하지 않습니다.

## 식별자

모든 이벤트는 세션과 에이전트에 속합니다. **스코프가 두 가지를 모두 채워주므로** 직접 전달하는 경우는 드뭅니다:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId`나 `agentId`를 명시적으로 전달하는 것도 가능하며, 명시적으로 전달한 값이 우선합니다. 스코프에 바인딩되지 않고 전달도 하지 않으면, Cloud가 조용히 버릴 이벤트를 내보내는 대신 throw됩니다.

<Note>
  식별자는 `AsyncLocalStorage`로 전달됩니다. `await`, `.then()`, 타이머, 그리고 스코프 내에서 생성된 모든 콜백에서 동작합니다. 하지만 한 실행 중에 저장되어 다른 실행 중에 호출되는 콜백이나 `worker_threads` 경계를 넘어 전달된 작업에서는 동작하지 **않습니다** — 해당 경우에는 `failproofai.propagate()`로 래핑하지 않으면 이벤트가 연결되지 않습니다.
</Note>

### 스코프

| 스코프 | 방출 | 반환 |
| --- | --- | --- |
| `session(body)` | 없음 — 식별자 전달만 | `body`가 반환하는 값 |
| `agent(id, options?, body)` | `agent_start`, 이후 `agent_end` | `body`가 반환하는 값 |
| `toolCall(name, options?, body)` | `tool_use`, 이후 `tool_result` | `body`가 반환하는 값 |

동기 바디는 동기로 유지됩니다: `agent("x", () => 1)`은 프로미스가 아닌 `1`을 반환합니다.

`toolCall`은 바디의 resolve된 값을 도구의 `output`으로 기록합니다. `call.output`을 직접 할당하면 그 값이 사용됩니다.

<Accordion title="종료 시맨틱" icon="arrow-right-from-bracket">

| 발생한 일 | 이벤트 | `outcome` |
| --- | --- | --- |
| 블록이 반환됨 | `agent_end` | `"success"`, 또는 직접 지정한 `outcome` |
| 블록에서 throw됨 | `error`, 이후 `agent_end` | `"failed"` |
| `AbortError` | `agent_end`만 | `"cancelled"` |

오류는 항상 다시 throw됩니다.

도구 실패는 리프 노드에 기록됩니다 — `error` 문자열이 포함된 `tool_result` — 이며 실행 레벨의 `error` 이벤트는 **발생하지 않습니다**. 에이전트 루프가 잡은 오류는 실행 실패가 아니며, 전파된 오류는 감싸는 `agent()`에 의해 정확히 한 번 보고됩니다.

</Accordion>

<Accordion title="`using` 형식" icon="brackets-curly">

작업이 단일 함수가 아닌 경우 — 생성자에서 열리고 teardown에서 닫히거나, 기존 제어 흐름에 걸쳐 있는 스코프의 경우:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

두 형식 모두 바이트 단위로 동일한 이벤트를 방출합니다. 콜백 형식을 권장합니다: `AsyncLocalStorage.run()` 내에서 실행되므로 해제할 것이 없고, "여기서 열고 저기서 닫는" 버그가 원천적으로 불가능합니다.

자체적으로 실패를 잡는 `using` 블록은 `span.fail(error)`로 실패를 보고합니다 — disposer에는 자체적인 예외 채널이 없습니다.

</Accordion>

## 이벤트 카탈로그

Python SDK와 동일한 15개의 메서드이며, camelCase 형식입니다. 대부분 **쌍으로** 제공됩니다 — 오프너를 호출한 후 클로저를 호출하면 SDK가 그 간격을 측정합니다.

| | 오픈 | 클로즈 |
| --- | --- | --- |
| **에이전트** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **모델** | `modelRequest` | `modelResponse` |
| **도구** | `toolUse` | `toolResult` |
| **훅** | `hookTriggered` | `hookCompleted` |
| **휴먼** | `humanWait` | `humanInput` |

독립 이벤트는 세 가지: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="메서드별 전체 필드" icon="table">

모든 메서드는 `sessionId`와 `agentId`도 받으며, 스코프가 이를 채워줍니다. 생략된 필드는 JSON `null`로 전송되는 대신 제거됩니다.

| 메서드 | 필수 | 선택 |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

추가하는 다른 키는 커스텀 페이로드 필드가 됩니다. 프레임워크 전용 항목은 `fw_*`로 네임스페이스를 지정하세요. 선언된 필드와 이름이 충돌하면 승격된 열을 조용히 덮어쓰는 대신 거부됩니다.

</Accordion>

<Warning>
  **`duration_ms`는 계산되는 값이며, 입력값으로 허용되지 않습니다.** 네 가지 클로징 메서드는 오프너로부터의 간격을 측정하며, 호출자가 제공한 `duration_ms`를 거부합니다 — 보고된 지속 시간은 위조 불가능해야 합니다.

  쌍은 **세션**과 id로 매칭되며, 에이전트로는 매칭되지 않습니다. `planner` 아래에서 열리고 `worker` 아래에서 닫힌 도구도 쌍으로 연결됩니다. 중첩된 멀티 에이전트 실행에서 실제로 발생하는 동작입니다.
</Warning>

## 프레임워크 어댑터

```ts
await failproofai.instrument();              // whatever it can find
await failproofai.instrument("langchain");   // exactly one
failproofai.uninstrument();                  // put everything back
```

| 프레임워크 | 지원 버전 | 연결 방식 |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure` 방식으로 연결되므로, 모든 `invoke`/`stream`/`batch`에서 `callbacks:`를 전달하지 않아도 커버됩니다 — 또는 `langchainHandler()`를 직접 전달하고 패칭 없이 사용할 수 있습니다. |
| **Vercel AI SDK** | `ai` 4 – 7 | 호출 지점에서 `telemetry()`를 사용하거나, `ai` 7에서는 `instrument("ai")`로 전체 프로세스에 적용합니다 (4–6에서는 옵트인 — 아래 참고). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, 에이전트의 모델 및 도구 해석, 워크플로우 실행/스텝 엔진. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (구독) 및 `AgentWorkflow.runStream` — 워크플로우 실행과 스텝에 적용됩니다. |

모든 버전 범위는 실제 프레임워크 릴리스를 기준으로, 양 끝단 모두, ES 모듈과 CommonJS 양쪽에서, 매 CI 실행마다 테스트됩니다.

매핑은 Python SDK와 동일하므로, 동일한 프로그램이 어떤 언어에서든 같은 트리를 그립니다. LLM 결정 루프를 소유하는 경우에만 **에이전트**로 취급됩니다 — 그래프나 체인 실행, AI SDK의 `generateText`/`streamText` 호출, Mastra 에이전트, LlamaIndex 에이전트 실행이 해당됩니다. LangGraph 노드나 워크플로우 스텝은 중첩 에이전트가 아닌 **훅**(`hook_triggered`/`hook_completed`)입니다. 모델 호출은 토큰 수가 포함된 `model_request`/`model_response` 쌍이며, 도구 호출에는 모델의 도구 호출 id가 포함됩니다. 실패는 발생한 이벤트에 한 번만 기록됩니다.

설치에 실패한 어댑터는 로깅되고 건너뛰어집니다. 나머지 어댑터는 계속 설치됩니다 — LlamaIndex 문제가 LangGraph를 희생시켜서는 안 되기 때문입니다.

<Note>
  인자 없이 `instrument()`를 호출하면 프레임워크를 이미 임포트되었는지가 아닌 **해석 가능한지** 여부로 감지합니다 — Node는 ES 모듈에 대해 Python의 `sys.modules`에 해당하는 기능을 제공하지 않습니다. 설치했지만 사용하지 않는 프레임워크도 임포트되고 패칭됩니다. 특정 프레임워크만 원한다면 이름을 명시하세요.
</Note>

<Note>
  대부분의 프레임워크는 ES 모듈 빌드와 CommonJS 빌드를 모두 제공하며, Node는 이를 서로 관련 없는 두 개의 복사본으로 로드합니다. 어댑터는 애플리케이션이 로드하는 복사본(그리고 이미 `require`된 CommonJS 복사본도)을 패칭하므로 두 모듈 시스템 모두 동작합니다. esbuild나 webpack으로 **번들된 프레임워크**는 접근이 불가능합니다 — 이 경우 호출 지점 헬퍼를 사용하세요: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### 패칭 없이 LangChain 사용하기

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

핸들러는 `instrument()` 유무와 관계없이 동작하며 이중 기록이 발생하지 않습니다. `instrument("langchain")`은 Python 어댑터와 동일하게 `sessionId`, `captureContent`, `includeChains`, `graphCallbacks`, `captureLimit`를 받습니다. 호출 시 `metadata: { failproofai_sdk_session_id }`를 전달하면 해당 호출의 세션을 지정할 수 있습니다.

### Vercel AI SDK

AI SDK는 ES 모듈에서 일반 함수를 익스포트하며, ES 모듈 네임스페이스는 명세상 불변입니다 — 패칭할 위치가 없습니다. SDK 자체가 문서화한 확장 포인트를 사용합니다:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // on ai 7, `telemetry: telemetry({ … })` — the same object, the new name
});
```

이것이 완전한 통합입니다: 에이전트 스팬, 스텝별 토큰 수가 포함된 모델 요청/응답 쌍, 그리고 모든 도구 호출. 하나의 호출 지점이 모든 메이저 버전에서 동작합니다 — `ai` 4–6은 전달된 트레이서를 읽고, `ai` 7은 텔레메트리 통합을 사용합니다.

`instrument("ai")`는 **`ai` 7에서** 동일한 작업을 프로세스 전체에 적용합니다: AI SDK의 전역 텔레메트리 통합 목록을 통해 모든 호출에 적용되며, 가산적으로 동작하여 다른 누구의 것도 가져가지 않습니다.

**`ai` 4–6에서는 `instrument("ai")`가 자체적으로 아무것도 기록하지 않으며, 이를 알리는 경고를 한 번 로깅합니다.** 해당 메이저 버전이 가진 유일한 프로세스 전체 훅은 전역 OpenTelemetry 트레이서 프로바이더입니다 — 한번 점유되면 OpenTelemetry가 양보하지 않는 단일 슬롯입니다. 이를 등록하면 이후 시작 시 `NodeSDK.start()`가 조용히 거부되고 http/데이터베이스 스팬이 아무것도 익스포트하지 않는 트레이서로 전송됩니다. 호출 지점에서 `telemetry()`를 사용하거나 `wrapModel`을 사용하세요. 프로세스에서 자체 OpenTelemetry를 실행하지 않는 경우, `instrument("ai", { registerGlobalTracer: true })`로 옵트인하세요: 그러면 `experimental_telemetry: { isEnabled: true }`를 전달하는 모든 호출을 기록하며, 슬롯이 비어 있을 때만 점유합니다. `registerGlobalTracer: false`는 기본값을 유지하고 경고를 억제합니다.

모델을 한 번만 래핑하려면 `wrapModel`을 사용하세요. 단, 도구 호출은 모델 레이어 위에서 발생하므로 모델 호출만 볼 수 있습니다. 아무것도 감싸지 않고 래핑된 모델을 호출하면 자체 실행으로 기록됩니다. 스트리밍 호출은 스트림이 종료되는 방식으로 닫힙니다 — 컨슈머가 취소하면 `stop_reason: "cancelled"`, 중간에 실패하면 오류와 함께 `"error"`:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

둘 다 사용해도 괜찮습니다: 미들웨어는 이미 기록 중인 호출을 감지하고 양보하므로, 각 호출은 한 번만 기록됩니다.

`functionId`는 에이전트 스팬의 이름을 지정합니다. 카디널리티를 낮게 유지하세요 — 주요 대시보드 패싯인 `agent_id`에 사용됩니다.

### Next.js

`next build`는 기본적으로 서버 의존성을 번들링하며, 빌드에 번들된 프레임워크는 `instrument()`가 접근할 수 없는 복사본이 됩니다. 설정을 한 번 래핑하고 Next의 시작 훅에서 `instrument()`를 호출하세요:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai`는 LangChain, Mastra, LlamaIndex, SDK 자체를 `serverExternalPackages`에 추가하며, 기존 목록을 유지합니다. 이 없이는 `instrument()`가 접근할 수 없는 프레임워크마다 한 번씩 경고를 남기고 조용히 실패하지 않습니다. 직접 패키지를 목록에 추가한 경우 `FAILPROOFAI_NEXT_EXTERNALS=1`을 설정하세요. Vercel AI SDK와 호출 지점 헬퍼는 어떤 방식으로든 동작합니다. Edge 라우트는 no-op 빌드를 받습니다: SDK 임포트는 안전하며 아무것도 기록하지 않습니다.

### 스트리밍 호출의 토큰 수

OpenAI 호환 API는 클라이언트가 요청할 때만 스트림에서 사용량을 보고합니다. LangChain과 Vercel AI SDK는 자동으로 요청합니다. LlamaIndex의 경우 `OpenAI` LLM에 `additionalChatOptions: { stream_options: { include_usage: true } }`를 전달하고, Mastra의 경우 사용량이 활성화된 모델로 빌드하세요 (예: `createOpenAICompatible({ includeUsage: true })`). 그렇지 않으면 스트리밍 모델 호출에 토큰 수가 포함되지 않습니다.

### 런타임

Node ≥ 20.9, Bun, Deno — 모든 프레임워크가 ES 모듈과 CommonJS 양쪽에서, Node의 트레이스 기준으로 각각 테스트됩니다. SDK는 기록한 내용을 전송하는 `failproofaid` 데몬과 함께 실행됩니다.

## 직접 만든 에이전트 — 프레임워크 없이

직접 작성한 에이전트 루프나 어댑터가 없는 프레임워크를 위한 방법입니다. 어댑터가 내부적으로 사용하는 것과 동일한 API로 이벤트를 방출하므로, 트레이스의 형태와 품질이 동일합니다.

에이전트가 어떻게 구성되어 있는지 알 필요가 없습니다. 모든 수작업 에이전트는 함수 이름이 무엇이든 이미 세 가지 위치를 가지고 있으며, 그 세 가지가 전체 통합입니다:

| 위치 | 추가할 내용 | 방출 |
| --- | --- | --- |
| **하나의 실행**이 시작되고 끝나는 곳 | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **모델을 호출하는 단 하나의 함수** | 이전에 `event.modelRequest`, 이후에 `event.modelResponse` — 실패 시에도 두 쌍 모두 | 모델 턴당 하나의 쌍 |
| **도구를 실행하는 단 하나의 함수** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

식별자는 주변 컨텍스트에서 자동으로 제공됩니다: `agent()` 내부의 모든 것은 id를 받지 않아도 해당 실행의 세션에 속하며, 에이전트가 자체 데이터베이스에 기록하는 내용을 포함해 프로그램의 다른 부분은 변경되지 않습니다.

- **서비스 또는 워커:** 자체 요청 또는 작업 id를 `sessionId`로 전달하면, 대시보드의 세션과 자체 로그나 데이터베이스의 레코드가 동일한 문자열을 사용합니다.
- **서브 에이전트:** `agent()` 호출을 중첩합니다. 내부 에이전트는 외부 에이전트를 `parent_id`로 하여 동일한 세션에 합류합니다.
- **쌍을 방출하세요.** `modelResponse` 없는 `modelRequest`는 대시보드에서 영원히 실행 중으로 표시되는 스팬입니다 — 따라서 `catch`가 필요합니다.

저장소의 [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts)는 완전하고 실행 가능한 버전입니다: 정확히 이 방식으로 계측된 실제 OpenAI 도구 루프로, ES 모듈과 CommonJS 양쪽에서 변경 시마다 CI에서 실행됩니다.

## 평가

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

프로토콜, 워커 설정 및 결과 타입은 [Evaluator SDK 레퍼런스](/ko/reference/evaluator-sdk)를 참고하세요.

<Warning>
  **평가는 반드시 yield해야 합니다.** 반환하지 않는 동기 함수는 Node가 가진 단 하나의 스레드를 차단하며, 그 동안 어떤 타임아웃도 실행될 수 없습니다. `async` 평가를 작성하세요.
</Warning>

## 프로세스에 영향을 주지 않는 것들

| | |
| --- | --- |
| **에이전트 루프 차단 없음** | 이벤트는 인메모리 큐에 들어가고, 타이머가 디스크에 기록합니다. 타이머는 `unref`되어 있으므로, 이 패키지를 임포트해도 스크립트 종료가 차단되지 않습니다. |
| **무한 증가 없음** | 큐는 개수와 바이트 수 양쪽으로 제한됩니다. 어느 하나를 초과하면 오래된 이벤트부터 버려지고 경고가 표시됩니다 — 텔레메트리 장애가 OOM 킬로 이어져서는 안 됩니다. |
| **프로세스 다운 없음** | 인코딩할 수 없는 이벤트 하나만 버려지고, 주변 배치는 영향을 받지 않습니다. throw하는 getter, 순환 참조, `BigInt`, lone surrogate: 모두 전파되지 않고 처리됩니다. |
| **불완전한 배치 없음** | 내용은 원자적 rename 이전에 `fsync`되고, 디렉터리는 이후에 `fsync`되며, 실패한 쓰기는 임시 파일을 정리합니다. |
| **읽기 가능한 트랜스크립트 없음** | 배치는 `0700` 디렉터리 내에서 `0600` 권한입니다. 목표, 프롬프트, 도구 인수, 도구 출력을 포함합니다. |
| **자격증명 전송 없음** | API 키, 토큰, JWT, bearer 헤더, 시크릿 형태의 할당은 바이트가 디스크에 도달하기 전에 편집됩니다. 데몬은 업로드 전에 다시 한 번 편집합니다. |
