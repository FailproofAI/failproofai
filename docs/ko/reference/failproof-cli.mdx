`npm install -g failproofai`로 설치하세요. 인수 없이 `failproofai`를 실행하면 로컬 대시보드가 열립니다.

## 핵심 명령어

| 명령어 | 기능 |
| --- | --- |
| `failproofai config` | 에이전트, 백그라운드 서비스 및 선택적 Cloud 연결 설정 |
| `failproofai config --token <key>` | 질문 없이 설정 및 연결 |
| `failproofai config --status` | 연결 상태, 서비스 버전 및 일시 정지 상태 표시 |
| `failproofai policies` | 정책 목록 및 활성화 여부 표시 |
| `failproofai policies add <name>` | 정책 하나 활성화 |
| `failproofai policies add <owner>/<repo>` | 정책 팩 설치 |
| `failproofai policies remove <name-or-pack>` | 정책 비활성화 또는 팩 제거 |
| `failproofai policies show <owner>/<repo>` | 설치 전 팩 내용 확인 |
| `failproofai publish` | 정책을 팩으로 게시 |
| `failproofai audit` | 로컬 에이전트 기록 스캔 |
| `failproofai harness` | 추가 세션 위치 관리 |
| `failproofai flush` | 대기 중인 이벤트 즉시 전송 |
| `failproofai backfill` | 이전 에이전트 기록 재읽기 |
| `failproofai update` | npm 업그레이드 완료 및 서비스 업데이트 |
| `failproofai uninstall` | 훅 및 서비스 제거 |

`policy`, `pack`, `p`는 `policies`의 별칭으로 사용할 수 있지만, 문서에서는 `policies`를 사용합니다.

## 머신 설정

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

설정 시 기본적으로 정책 팩이 선택되지 않습니다. 팩을 추가하기 전까지는 `block-failproofai-commands`만 실행됩니다.

비대화형 Cloud 설정의 경우:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

트랜스크립트 없이 결정 사항만 전송하려면, 먼저 연결한 후 `~/.failproofai/config.json`에서 `collector.sessions`를 `false`로 설정하세요. 현재 `--no-transcripts` 설정 플래그는 파싱되지만 해당 설정을 적용하지는 않습니다.

머신이 연결된 후 `--machine-label <name>`을 사용하여 이름을 변경할 수 있습니다. `--connect <url>`은 이미 설정된 머신에 대한 등록 전용 명령어입니다.

## 정책 및 팩

```bash
failproofai policies
failproofai policies add block-sudo
failproofai policies show owner/repo
failproofai policies add owner/repo --category git,database
failproofai policies remove owner/repo
```

슬래시가 포함된 것은 팩 소스이고, 슬래시가 없는 것은 정책 이름입니다.

유용한 팩 선택 플래그:

| 플래그 | 용도 |
| --- | --- |
| `--policy a,b` | 이름으로 정책 선택 |
| `--category x,y` | 카테고리로 선택 |
| `--all` | 모두 선택 |
| `--cli <agents...>` | 지정된 harness로 제한 |

`failproofai policies -i -c <path>`를 사용하여 임의 경로에서 커스텀 정책을 로드하세요. `.failproofai/policies/` 아래에 `*policies.{js,mjs,ts}` 규칙으로 명명된 파일은 자동으로 로드됩니다.

## 정책 적용 일시 정지

```bash
failproofai config --pause 10m
failproofai config --status
failproofai config --resume
```

일시 정지는 하나의 로컬 세션에만 적용되며 항상 만료됩니다. Cloud 관리 정책이나 `block-failproofai-commands`는 일시 정지되지 않습니다.

## 감사 및 전달

```bash
failproofai audit
failproofai audit --schedule 7 --email team@example.com
failproofai audit --status
failproofai flush --wait
failproofai backfill --since 30d --dry-run
```

`backfill`은 `~/.failproofai/config.json`을 읽습니다. `--dry-run`을 제거하면 기록을 다시 전송합니다.

## 추가 세션 위치

```bash
failproofai harness list
failproofai harness add-path claude work=/srv/team/.claude/projects
failproofai harness remove-path claude work
```

레이블은 복사된 두 홈 디렉토리의 세션이 동일한 파생 에이전트 ID 아래에 병합되는 것을 방지합니다.

지원되는 harness는 `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, `goose`입니다. 스코프 지원은 harness마다 다릅니다. [Harnesses](/ko/reference/harnesses)를 참조하세요.

## 유용한 환경 변수

| 변수 | 용도 |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | Cloud 머신 키 |
| `FAILPROOFAI_CLOUD_URL` | Cloud URL 재정의 |
| `FAILPROOFAI_HOME` | 로컬 상태 디렉토리 변경 |
| `FAILPROOFAI_NO_DOWNLOAD=1` | 팩 및 서비스 다운로드 거부 |
| `FAILPROOFAI_DAEMON_BASE_URL` | 서비스 바이너리 미러 사용 |
| `FAILPROOFAI_PACK_BASE_URL` | 팩 미러 사용 |
| `FAILPROOFAI_NO_FIRST_RUN=1` | 첫 실행 프롬프트 비활성화 |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | 익명 CLI 텔레메트리 비활성화 |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | 특정 harness의 추가 경로 교체 |
| `NO_COLOR` | 터미널 색상 비활성화 |

## 제거 또는 업그레이드

```bash
npm install -g failproofai@latest
failproofai update
```

패키지를 제거하기 전에:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

<Warning>
  npm 패키지를 제거하기 전에 `failproofai uninstall`을 실행하세요. npm은 설치된 훅이나 백그라운드 서비스를 제거하지 않습니다.
</Warning>

설치된 버전의 전체 옵션을 확인하려면 `failproofai help <command>`를 실행하세요.
