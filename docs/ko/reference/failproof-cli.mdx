`npm install -g failproofai`로 로컬 CLI를 설치하세요. 인수 없이 실행하면 로컬 정책 대시보드가 열립니다.

이 패키지는 Node.js 20.9 이상이 필요합니다. Bun 1.3 이상은 개발 및 소스 설치에서 지원됩니다. `failproofai configure`와 `failproofai setup`은 `failproofai config`의 별칭입니다. `failproofai policy`, `failproofai pack`, `failproofai p`는 모두 `failproofai policies`의 다른 표기법입니다 — 팩과 단일 정책은 하나의 개념에 대한 세 가지 명령이었으나 이제 하나로 통합되었습니다. 이전 표기법은 여전히 작동하지만 두 가지 예외가 있습니다: `pack list <source>`는 이제 `policies show <source>`이며, `pack build`는 이제 `publish`입니다.

## 머신 설정

CLI를 설치한 후 머신 키를 셸로 읽어들입니다. `read -s`는 에코되지 않는 프롬프트에서 키를 입력받으므로 명령어에 노출되지 않습니다:

```bash
npm install -g failproofai
read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
```

그런 다음 머신을 설정하고 적용할 정책을 선택합니다:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

`failproofai config`는 설정의 전부입니다: `failproofaid` 서비스를 설치하고(루트 권한으로 한 번 — 터미널에서는 sudo 비밀번호를 요청하며, 설정이 완료되기 전에 만료된 경우 다시 요청합니다; 터미널이 없는 경우 `sudo -n`을 사용하며 프롬프트를 표시하지 않습니다), 발견된 모든 에이전트 CLI에 훅을 연결하고, Cloud에 접속합니다. 터미널이 없는 환경 — CI, 컨테이너, 에이전트가 직접 실행하는 경우 — 에서는 묻지 않고 적용하며, 요청된 작업이 하나라도 완료되지 않으면 종료 코드 1로 종료합니다.

터미널에서 아직 연결되지 않은 머신의 **Connect to cloud** 단계는 즉시 **FailproofAI Cloud 로그인**을 시작합니다; Tab을 눌러 **Paste an API key** 또는 **Use open source** 옵션을 선택할 수 있습니다. 로그인하면 링크가 열립니다 — SSH나 디스플레이가 없는 환경에서는 링크를 출력하여 다른 기기에서 열 수 있습니다 — 링크에서 가입 또는 로그인하고, 조직을 선택하거나 생성한 뒤 머신을 승인합니다; 터미널은 승인을 자동으로 감지하고 승인자와 조직을 표시합니다. 키는 데몬이 설치된 후 설정이 완료될 때만 발급됩니다. 이미 유효한 키로 연결된 머신에서는 **Keep current connection**이 첫 번째 옵션으로 표시되므로, 설정을 다시 실행해도 브라우저가 자동으로 열리지 않습니다; 더 이상 작동하지 않는 저장된 키는 즉시 로그인을 다시 시작하고 그 이유를 표시합니다. 다시 로그인하면 새 키가 발급되며 기존 키는 취소할 때까지 계속 작동합니다. 브라우저 로그인 이전 버전의 Cloud는 이를 알리고 다른 옵션을 제공합니다.

정책은 **선택하지 않음**으로 초기화됩니다. 그것은 두 번째 명령의 역할이며, 해당 명령 없이는 새로 설정된 머신이 항상 켜져 있는 가드 외에 아무것도 적용하지 않습니다.

`--token` 대신 환경 변수를 사용하세요: 명령줄 인수는 해당 서버의 모든 사용자가 `ps`로 읽을 수 있습니다. 환경 변수가 보호하는 것은 그것뿐입니다 — `export`를 포함해 명령어에 직접 입력된 키는 여전히 셸 히스토리에 남으므로, 위와 같이 `read -s`로 읽어들이는 것입니다. CI에서는 시크릿 저장소에서 설정하고 셸 추적(`set -x`)을 끄세요, 그렇지 않으면 추적 로그에 키가 출력됩니다.

<Warning>
  `--connect <url>`은 **이미 설정된** 머신을 등록합니다. 등록이 완료되는 즉시 반환됩니다 — 데몬을 설치하거나 훅을 연결하지 않습니다. 아직 설정되지 않은 머신에는 일반 `failproofai config`(또는 `failproofai config --token <key>`)를 사용하세요, 그렇지 않으면 연결된 것으로 표시되지만 아무것도 수집하거나 적용하지 않습니다.
</Warning>

인수 없이 `failproofai`를 실행하면 로컬 정책 대시보드가 열립니다.

| 명령어 | 결과 |
| --- | --- |
| `failproofai config` | 머신 설정: 에이전트, 데몬, Cloud — 브라우저 로그인, 키 붙여넣기, 또는 오픈소스 사용. 머신의 모든 에이전트에 온라인 [FailproofAI skills](https://github.com/FailproofAI/skills)를 가리키는 소형 `failproofai` 스킬도 추가됩니다 |
| `failproofai config --token <key>` | 아무것도 묻지 않고 한 번에 설정 및 연결. `jev:evaluate` 권한이 있는 키는 `jev.json`이 이미 존재하거나 `--no-transcripts`가 지정되지 않은 한 observe 모드로 [Jev through FailproofAI Cloud](/ko/reference/jev-cloud)를 활성화합니다 |
| `failproofai config --connect <url>` | **이미** 설정된 머신 등록 — 데몬 및 훅 없음 |
| `failproofai config --status` | 연결, 데몬, 전송 및 일시 중지 상태 표시 |
| `failproofai policies` | 내장, 사용자 정의, 컨벤션, 팩 및 Cloud 관리 정책 목록 |
| `failproofai policies --install` | 에이전트 CLI에 훅 연결. 자체적으로는 정책을 활성화하지 않음 |
| `failproofai policies add <name>` | 정책 하나 활성화 — 내장 정책이나 설치된 팩의 `<pack-id>:<name>` |
| `failproofai policies remove <name>` | 정책 하나 비활성화, 동일한 명명 방식 |
| `failproofai policies --uninstall` | 정책 비활성화 또는 하네스 훅 제거 |
| `failproofai policies show <owner>/<repo>` | 팩이 포함하는 내용을 매니페스트에서 읽어 설치 전에 확인 |
| `failproofai policies show <owner>/<repo> --releases` | 팩이 게시한 모든 버전과 현재 설치된 버전 |
| `failproofai policies add <source>` | GitHub 릴리즈에서 정책 팩 설치; 태그 없이 실행하면 최신 버전을 받아 고정 |
| `failproofai publish` | 자신의 정책을 팩으로 배포; `--init`으로 시작점을 작성하고, `--min-cli-version <version>`으로 설치 가능한 최소 CLI 버전 설정 ([팩의 Jev 검사](/ko/policies/publish-a-pack#jev-checks-in-a-pack)) |
| `failproofai policies remove <publisher/name>` | 팩 제거 |
| `failproofai audit` | 로컬 에이전트 히스토리 스캔 및 로컬 감사 뷰 열기 |
| `failproofai audit --schedule [days] --email <address>` | 반복 로컬 스캔 예약 및 결과를 이메일로 전송 |
| `failproofai audit --status` | 보고서 주소, 주기 및 다음 예약 스캔 표시 |
| `failproofai audit --no-schedule` | 감사 히스토리를 삭제하지 않고 반복 스캔 중지 |
| `failproofai harness list` | 추가 캡처 경로 목록 |
| `failproofai otel status` | 선택적 [OpenTelemetry 보고](/ko/reference/otel) 검사 |
| `failproofai jev --url <url> --key-stdin` | 한 번에 Jev 설정; 프로바이더는 URL의 호스트에서 가져옴 |
| `failproofai jev setup --provider <kind> --key-stdin` | [Jev](/ko/reference/jev-providers)가 자신의 엔드포인트와 키로 도구 호출을 판단하도록 설정 |
| `failproofai jev setup --provider failproofai` | 이 머신의 Cloud 키를 사용해 Jev가 [FailproofAI Cloud를 통해](/ko/reference/jev-cloud) 도구 호출을 판단하도록 설정 |
| `failproofai jev setup --mode <m>` | Jev 모드 전환: `enforce`, `observe`, 또는 `off` (설정을 유지하고 Jev 요청 중지) |
| `failproofai jev status` | Jev 설정, 권한 및 최근 폴백 표시; 키는 표시하지 않음 |
| `failproofai jev test` | 실제 Jev 요청 하나를 전송하고 지연 시간과 버전 표시; 훅 응답이 늦거나 잘못된 경우 종료 코드 1로 종료 |
| `failproofai jev models` | `GET <base>/models`가 엔드포인트에서 제공한다고 반환한 모델 ID 목록 |
| `failproofai jev remove` | Jev 비활성화; 훅은 이전과 동일하게 정규식 정책만 실행 |
| `failproofai flush --wait` | 현재 이벤트 스풀 전송 |
| `failproofai backfill --since 30d` | 이전에 처리된 히스토리 재전송 |
| `failproofai config --pause [duration]` | 현재 디렉토리의 로컬 세션을 기본 30분 동안 일시 중지, 최대 8시간 |
| `failproofai config --resume` | 일시 중지된 로컬 세션 재개; `--all`을 추가하면 모든 일시 중지 해제 |
| `failproofai update` | 패키지 마이그레이션 완료 및 데몬 업데이트 |
| `failproofai migrate --dry-run` | 대기 중인 홈 레이아웃 마이그레이션 미리보기 또는 실행 |
| `failproofai uninstall` | 패키지 제거 전 훅, `failproofai` 스킬 및 데몬 제거 |
| `failproofai --version` | 설치된 패키지 버전 출력 |
| `failproofai --help` | 명령어 및 전역 사용법 표시 |
| `failproofai help <command>` | 특정 명령어의 옵션과 예제 표시, `failproofai <command> --help`와 동일 |

## 설정 플래그

| 플래그 | 용도 |
| --- | --- |
| `--token <key>` | 비대화형으로 설정 및 연결; `FAILPROOFAI_CLOUD_TOKEN`에서도 읽음 |
| `--oss` | Cloud 연결 없이 오픈소스 사용; 기존 연결은 그대로 유지 |
| `--agents <a,b>` | 묻지 않고 이 에이전트들 또는 `all`을 추적 |
| `--url <url>` | `app.befailproof.ai` 이외의 주소에 연결; `FAILPROOFAI_CLOUD_URL`에서도 읽음 |
| `--connect <url>` | 이미 설정된 머신에서 등록만 수행. 데몬 및 모든 훅 건너뜀 |
| `--machine-id <id>` | `--connect`용 머신 ID; 기본값은 안정적인 ID |
| `--machine-label <name>` | 단독 사용 시 **이미 연결된** 머신의 이름을 변경; 설정을 실행하지 않음. `--token`과 함께 사용 시 해당 이름으로 연결; `FAILPROOFAI_CLOUD_TOKEN`에만 설정된 키는 충분하지 않음(이유: `--machine-label`을 `--token` 없이 사용하면 이름 변경임). `--oss` 또는 `--agents`와 함께 사용 시 이미 연결된 머신의 이름을 변경하며, 연결되지 않은 머신의 설정 전에는 거부됨: `--oss`는 연결하지 않고, `--agents`는 연결을 위해 키 또는 대화형 Cloud 로그인이 필요함 |
| `--no-transcripts` | 트랜스크립트 내용 없이 결정만 전송하고, 각 확인된 도구 호출과 최근 프롬프트를 전송하는 Cloud Jev를 활성화하지 않음; FailproofAI Cloud를 통해 Jev를 실행 중인 `jev.json`은 제거됨 |
| `--disconnect` | Cloud 정책 풀 및 이벤트 전송 중지. Cloud Jev 키와 FailproofAI Cloud를 지정하는 `jev.json`도 제거; 자체 Jev 설정은 그대로 유지 |
| `--status` | 현재 머신 상태 표시 |
| `--pause [duration]` | 현재 디렉토리의 최신 세션 일시 중지; 초, 분, 시간 단위를 받으며 기본값은 30분 |
| `--resume` | 일치하는 일시 중지 조기 종료 |
| `--session <id>` | 일시 중지 또는 재개할 명시적 세션 지정 |
| `--all` | `--resume`과 함께 사용 시 모든 활성 일시 중지 종료 |

로컬 일시 중지는 한 세션에 대해 내장, 사용자 정의, 컨벤션 및 팩 정책을 중단합니다. 항상 만료되며, 실행 중 첫 번째 일시 중지 후 최대 8시간입니다. Cloud 관리 정책이나 항상 켜져 있으며 비활성화하거나 일시 중지할 수 없는 `block-failproofai-commands`는 비활성화하지 않습니다. 해당 가드는 계측된 에이전트가 직접 자신을 일시 중지할 수 있는 방법인 `failproofai config --pause` 실행이나 `~/.failproofai/state/sessions/` 아래 일시 중지 파일 작성을 거부합니다. 명령어 자체를 읽으며 스크립트 실행 시 수행하는 작업은 읽지 않으므로, 에이전트가 작성하고 실행하는 스크립트는 동일한 상태에 도달할 수 있습니다. 일시 중지 파일은 제한된 만료 시간과 미래 1분 이내의 시작 시간을 확인하며, 작성자는 확인하지 않습니다.

## 정책 플래그

| 플래그 | 용도 |
| --- | --- |
| `--install`, `-i` | 하네스 훅 설치. 이후의 이름은 해당 정책을 활성화; 없으면 정책 변경 없음 |
| `--uninstall`, `-u` | 정책 비활성화 또는 훅 제거 |
| `--cli <names...>` | 하나 이상의 지원되는 하네스 대상 지정 |
| `--scope user\|project\|local\|all` | 설정 범위 선택; `all`은 제거용 |
| `--beta` | 베타 정책 포함 |
| `--custom`, `-c <path>` | `--install`과 함께 사용 시 사용자 정의 정책 파일 유효성 검사 및 로드; 반복 가능. `--uninstall -c`는 모든 사용자 정의 정책 파일 제거 |
| `--policy`, `--only <a,b>` | 팩에서 이 정책들만 설치 |
| `--category <x,y>` | 팩에서 이 카테고리들만 설치 |
| `--all` | 모든 정책 목록; 팩과 함께 사용 시 전체 설치 |
| `--releases` | `show`와 함께 사용 시 팩의 릴리즈 목록과 설치된 버전 표시 |

## 전송 및 유지보수 플래그

| 명령어 | 플래그 |
| --- | --- |
| `backfill` | `--since <30d\|6m\|1y\|YYYY-MM-DD>`, `--agents <a,b>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` (`-y`) |

### 하네스별 백필

`backfill`은 Cloud에 연결된 머신에서 수집기가 이미 읽은 히스토리를 재전송합니다. `--since`는 대부분의 하네스에 대한 기간을 설정하지만, 두 가지 예외가 있습니다:

- **Goose, OpenCode 및 Devin**은 `--since` 설정에 관계없이 전체 히스토리를 전송합니다: 이들의 히스토리는 수집기가 시간 창 없이 읽는 데이터베이스에 저장되므로, `--dry-run`은 모든 세션으로 보고합니다.
- **Hermes** 히스토리는 `backfill`로 재전송되지 않습니다.

`failproofai update`는 `npm install -g failproofai@latest` 후에 실행해야 합니다; 홈 레이아웃 마이그레이션을 수행하고, 일치하는 데몬 바이너리를 설치하고, 서비스를 재시작합니다. 그런 다음 FailproofAI를 이미 사용하는 모든 Hermes 프로필을 연결된 네이티브 플러그인으로 이동하고 프로필당 한 줄을 출력합니다. `--no-daemon`은 데몬 단계를 건너뜁니다. `update`는 데몬을 교체할 수 없거나, 마이그레이션이 실패하거나, Hermes 프로필을 마이그레이션할 수 없을 때(예: 실행 중인 데몬이 네이티브 플러그인을 제공할 수 없어 셸 훅이 그대로 유지되는 경우) 비정상 종료 코드로 종료됩니다.

## 하네스 경로

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

지원되는 하네스 이름은 `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, `goose`입니다.

레이블은 두 루트가 동일한 프로젝트 복사본을 포함할 때 파생된 에이전트 ID의 네임스페이스를 구분합니다. 중복된 루트와 중복 레이블은 중복 수집이나 커서 손상을 방지하기 위해 거부됩니다. 추가 경로 설정은 데몬 재시작 없이 다시 로드됩니다.

컨테이너 환경에서는 `FAILPROOFAI_<HARNESS>_EXTRA_PATHS`라는 쉼표로 구분된 변수로 파일에 설정된 추가 경로를 대체할 수 있습니다. 예를 들어:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## 환경 변수

지속적인 머신 동작에는 설정 파일을 사용하세요. 환경 변수는 컨테이너, 테스트, 단일 프로세스에 가장 유용합니다.

| 변수 | 용도 |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | `--token` 대신 사용하는 Cloud 키. 이 방법을 권장합니다: 인수는 모든 사용자가 `ps`로 읽을 수 있습니다. `read -s`나 CI 시크릿 저장소에서 설정하고, 명령어에 직접 입력하지 마세요 — 어떤 방법으로든 셸 히스토리에 남습니다 |
| `FAILPROOFAI_CLOUD_URL` | `--url` 대신 사용하는 Cloud URL. 데몬이 읽는 것과 동일한 변수 |
| `FAILPROOFAI_HOME` | `~/.failproofai` 전체 레이아웃 재배치 |
| `FAILPROOFAI_LOG_LEVEL` | 로컬 로깅 상세도 설정 |
| `FAILPROOFAI_HOOK_LOG_FILE` | 선택한 파일에 훅 진단 정보 기록 |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | 이 프로세스의 익명 텔레메트리 비활성화 |
| `FAILPROOFAI_NO_FIRST_RUN=1` | 대화형 첫 실행 설정 건너뜀 |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | 설정 후 로컬 감사 건너뜀 |
| `FAILPROOFAI_LLM_BASE_URL` | LLM 정책에서 사용하는 OpenAI 호환 엔드포인트 재정의 |
| `FAILPROOFAI_LLM_API_KEY` | LLM 정책에서 사용하는 API 키 제공 |
| `FAILPROOFAI_LLM_MODEL` | LLM 정책에서 사용하는 모델 선택 |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | 사용자 정의 정책 모듈 로딩 시간 제한 |
| `FAILPROOFAI_NO_DOWNLOAD=1` | 팩 및 데몬 바이너리 다운로드 거부; 설치된 것은 계속 적용됨 |
| `FAILPROOFAI_PACK_BASE_URL` | `github.com` 대신 미러에서 팩 다운로드 |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | 하나의 하네스에 대해 설정된 추가 캡처 경로 대체 |
| `NO_COLOR` | 컬러 터미널 출력 비활성화 |

`CLAUDE_PROJECTS_PATH`, `CURSOR_HOME`, `HERMES_HOME`, `OPENCLAW_HOME` 등 에이전트별 홈 변수는 Failproof AI가 해당 하네스의 로컬 세션을 검색하는 위치를 재정의합니다.

## 머신 안전하게 일시 중지 또는 제거

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

로컬 세션 일시 중지는 Cloud 관리 정책을 비활성화하지 않습니다. 롤아웃 자체가 문제일 경우 Cloud의 **fix → deploy policies**에서 Cloud 배포를 복원하세요.

npm 패키지를 제거하기 전에 설치된 훅과 데몬을 먼저 제거하세요:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

버전별 세부 사항은 `failproofai <command> --help`를 실행하세요.

<Warning>
  `npm rm -g failproofai` 전에 `failproofai uninstall`을 실행하세요; npm은 설치된 에이전트 훅, `failproofai` 스킬 또는 데몬 서비스를 제거하지 않습니다.
</Warning>
