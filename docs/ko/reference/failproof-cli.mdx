`npm install -g failproofai`로 로컬 CLI를 설치하세요. 인수 없이 실행하면 로컬 정책 대시보드가 열립니다.

이 패키지는 Node.js 20.9 이상이 필요합니다. Bun 1.3 이상은 개발 및 소스 설치에서 지원됩니다. `failproofai configure`와 `failproofai setup`은 `failproofai config`의 별칭입니다. `failproofai policy`, `failproofai pack`, `failproofai p`는 모두 `failproofai policies`의 다른 표기법입니다 — 팩과 단일 정책은 하나의 개념에 대한 세 가지 명령이었으나 이제 하나로 통합되었습니다. 이전 표기법은 여전히 동작하지만, 두 가지 예외가 있습니다: `pack list <source>`는 이제 `policies show <source>`이며, `pack build`는 이제 `publish`입니다.

## 머신 설정

CLI를 설치한 후 머신 키를 셸에서 읽어 들입니다. `read -s`는 에코 없이 프롬프트에서 입력받으므로 명령어에 노출되지 않습니다:

```bash
npm install -g failproofai
read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
```

그런 다음 머신을 설정하고 적용할 정책을 선택합니다:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

`failproofai config`는 설정의 전 과정을 담당합니다: `failproofaid` 서비스를 설치하고(루트 권한으로 최초 1회 — 터미널에서는 sudo 비밀번호를 요청하며, 설정 완료 전에 만료된 경우 다시 요청합니다; 터미널이 없을 경우 `sudo -n`을 사용하며 프롬프트를 표시하지 않음), 발견된 모든 에이전트 CLI에 훅을 연결하고, Cloud에 연결합니다. 터미널이 없는 환경 — CI, 컨테이너, 에이전트가 직접 구동하는 경우 — 에서는 묻지 않고 바로 적용하며, 요청된 작업 중 하나라도 실패하면 종료 코드 1로 종료합니다.

터미널에서 아직 연결되지 않은 머신의 **Connect to cloud** 단계는 즉시 **FailproofAI Cloud 로그인**을 시작합니다; Tab을 눌러 다른 옵션인 **Paste an API key** 또는 **Use open source**를 선택할 수 있습니다. 로그인하면 링크가 열리며 — SSH나 디스플레이가 없는 환경에서는 어떤 장치에서든 열 수 있도록 링크를 출력합니다 — 회원가입 또는 로그인, 조직 선택 또는 생성, 머신 승인을 진행합니다; 터미널은 승인을 자동으로 감지하고 누가 어느 조직을 위해 승인했는지 표시합니다. 키는 데몬 설치 후 설정이 완료될 때만 발급됩니다. 이미 유효한 키로 연결된 머신에서는 이 단계가 **Keep current connection**이 첫 번째로 표시되는 메뉴로 나타나므로, 설정을 다시 실행해도 브라우저가 자동으로 열리지 않습니다; 더 이상 작동하지 않는 저장된 키는 즉시 로그인을 다시 시작하며 그 이유를 표시합니다. 다시 로그인하면 새 키가 발급되고 이전 키는 취소하기 전까지 계속 작동합니다. 브라우저 로그인 이전 버전의 Cloud는 이를 알리고 다른 옵션을 제공합니다.

정책은 **없음**으로 선택됩니다. 그것은 두 번째 명령의 역할이며, 이 없이는 새로 설정된 머신이 항상 활성화된 가드 외에는 아무것도 적용하지 않습니다.

`--token`보다 환경 변수를 선호하세요: 명령줄 인수는 서버의 모든 사용자가 `ps`로 읽을 수 있습니다. 변수가 보호하는 것은 그것뿐입니다 — `export`를 포함한 어떤 명령에 입력된 키도 셸 히스토리에 남으므로, 위에서 `read -s`로 읽어 들이는 이유가 그것입니다. CI에서는 시크릿 스토어에서 설정하고 셸 추적(`set -x`)을 끄세요. 추적을 켜면 값이 출력됩니다.

<Warning>
  `--connect <url>`는 **이미 설정된** 머신을 등록합니다. 등록이 성공하는 즉시 반환되며 — 데몬을 설치하지 않고 어떤 훅도 연결하지 않습니다. 아직 설정되지 않은 머신에서는 일반 `failproofai config`(또는 `failproofai config --token <key>`)를 사용하세요. 그렇지 않으면 수집과 적용은 하지 않으면서 연결된 것으로 표시됩니다.
</Warning>

인수 없이 `failproofai`를 실행하면 로컬 정책 대시보드가 열립니다.

| 명령어 | 결과 |
| --- | --- |
| `failproofai config` | 머신 설정: 에이전트, 데몬, Cloud — 브라우저 로그인, 키 붙여넣기, 또는 오픈 소스 유지. 머신의 모든 에이전트에는 [FailproofAI skills](https://github.com/FailproofAI/skills) 온라인을 가리키는 소규모 `failproofai` 스킬도 추가됨 |
| `failproofai config --token <key>` | 아무것도 묻지 않고 한 번에 설정 및 연결. `jev:evaluate`가 포함된 키는 `jev.json`이 이미 존재하거나 `--no-transcripts`가 지정되지 않은 경우 관찰 모드로 [FailproofAI Cloud를 통한 Jev](/ko/reference/jev-cloud)도 활성화함 |
| `failproofai config --connect <url>` | **이미** 설정된 머신 등록 — 데몬 및 훅 없음 |
| `failproofai config --status` | 연결, 데몬, 전달, 일시 정지 상태 표시 |
| `failproofai policies` | 내장, 커스텀, 관례, 팩, Cloud 관리 정책 목록 표시 |
| `failproofai policies --install` | 에이전트 CLI에 훅 연결. 자체적으로는 어떤 정책도 활성화하지 않음 |
| `failproofai policies add <name>` | 정책 하나 활성화 — 내장 정책 또는 설치된 팩의 `<pack-id>:<name>` |
| `failproofai policies remove <name>` | 정책 하나 비활성화, 동일한 명명 규칙 |
| `failproofai policies --uninstall` | 정책 비활성화 또는 하니스 훅 제거 |
| `failproofai policies show <owner>/<repo>` | 팩이 포함하는 내용을 매니페스트에서 읽어 설치 전에 확인 |
| `failproofai policies show <owner>/<repo> --releases` | 팩이 게시한 모든 버전과 현재 설치된 버전 |
| `failproofai policies add <source>` | GitHub 릴리스에서 정책 팩 설치; 태그 없이 사용하면 최신 버전을 가져와 고정 |
| `failproofai publish` | 자신의 정책을 팩으로 배포; `--init`으로 시작 파일 생성, `--min-cli-version <version>`으로 설치 가능한 최소 CLI 버전 설정 ([팩에서의 Jev 검사](/ko/policies/publish-a-pack#jev-checks-in-a-pack)) |
| `failproofai policies remove <publisher/name>` | 팩 제거 |
| `failproofai audit` | 로컬 에이전트 히스토리 스캔 및 로컬 감사 뷰 열기 |
| `failproofai audit --schedule [days] --email <address>` | 반복 로컬 스캔 예약 및 결과 이메일 발송 |
| `failproofai audit --status` | 보고서 주소, 간격, 다음 예약 스캔 표시 |
| `failproofai audit --no-schedule` | 감사 히스토리 삭제 없이 반복 스캔 중지 |
| `failproofai harness list` | 추가 캡처 경로 목록 표시 |
| `failproofai otel status` | 선택적 [OpenTelemetry 리포팅](/ko/reference/otel) 검사 |
| `failproofai jev --url <url> --key-stdin` | Jev를 한 번에 설정; 제공자는 URL의 호스트에서 가져옴 |
| `failproofai jev setup --provider <kind> --key-stdin` | [Jev](/ko/reference/jev-providers)가 자체 엔드포인트와 키를 통해 도구 호출을 판단하도록 설정 |
| `failproofai jev setup --provider failproofai` | 이 머신의 Cloud 키로 [FailproofAI Cloud를 통해](/ko/reference/jev-cloud) Jev가 도구 호출을 판단하도록 설정 |
| `failproofai jev setup --mode <m>` | Jev 모드 전환: `enforce`, `observe`, 또는 `off` (설정 유지, Jev 중지) |
| `failproofai jev status` | Jev 설정, 권한 및 최근 폴백 표시; 키는 표시하지 않음 |
| `failproofai jev test` | Jev 요청을 실제로 한 번 보내고 지연 시간과 버전 표시; 훅에서 응답이 늦거나 잘못된 경우 종료 코드 1로 종료 |
| `failproofai jev models` | 엔드포인트가 `GET <base>/models`에서 제공하는 모델 ID 목록 표시 |
| `failproofai jev remove` | Jev 끄기; 훅은 이전과 동일하게 정규식 정책만 실행 |
| `failproofai flush --wait` | 현재 이벤트 스풀 전달 |
| `failproofai backfill --since 30d` | 이전에 통과된 히스토리 재읽기 |
| `failproofai config --pause [duration]` | 기본 30분, 최대 8시간 동안 로컬 세션 하나 일시 정지 |
| `failproofai config --resume` | 일시 정지된 로컬 세션 하나 재개; `--all`을 추가하면 모든 일시 정지 해제 |
| `failproofai update` | 패키지 마이그레이션 완료 및 데몬 업데이트 |
| `failproofai migrate --dry-run` | 보류 중인 홈 레이아웃 마이그레이션 미리 보기 또는 실행 |
| `failproofai uninstall` | 패키지 제거 전 훅, `failproofai` 스킬, 데몬 제거 |
| `failproofai --version` | 설치된 패키지 버전 출력 |
| `failproofai --help` | 명령어 및 전체 사용법 표시 |

## 설정 플래그

| 플래그 | 용도 |
| --- | --- |
| `--token <key>` | 비대화형으로 설정 및 연결; `FAILPROOFAI_CLOUD_TOKEN`에서도 읽음 |
| `--url <url>` | `app.befailproof.ai` 이외의 곳에 연결; `FAILPROOFAI_CLOUD_URL`에서도 읽음 |
| `--connect <url>` | 이미 설정된 머신에서만 등록. 데몬 및 모든 훅 건너뜀 |
| `--machine-id <id>` | 안정적인 머신 ID 설정 |
| `--machine-label <name>` | **이미 연결된** 머신 이름 변경. 단독으로는 절대 설정을 실행하지 않으므로, 설정 도중이 아닌 `failproofai config` 이후에 사용 |
| `--no-transcripts` | 트랜스크립트 내용 없이 결정 사항 전송, Cloud Jev 활성화 안 함(각 확인된 도구 호출과 최근 프롬프트를 전송함); FailproofAI Cloud를 통해 Jev를 실행 중인 `jev.json`은 제거됨 |
| `--disconnect` | Cloud 정책 풀 및 이벤트 전달 중지. Cloud Jev 키와 FailproofAI Cloud를 지정한 `jev.json`도 제거; 자체 Jev 설정은 유지됨 |
| `--status` | 현재 머신 상태 표시 |
| `--pause [duration]` | 현재 디렉터리의 최신 세션 일시 정지; 초, 분, 시간 단위 허용, 기본값은 30분 |
| `--resume` | 일치하는 일시 정지 조기 종료 |
| `--session <id>` | 일시 정지 또는 재개의 대상 세션 명시 |
| `--all` | `--resume`과 함께 사용하여 모든 활성 일시 정지 종료 |

로컬 세션 일시 정지는 하나의 세션에 대해 내장, 커스텀, 관례, 팩 정책을 중단합니다. 항상 만료되며 Cloud 관리 정책은 비활성화하지 않습니다. `block-failproofai-commands` — 항상 활성화되어 있으며 자체적으로는 비활성화하거나 일시 정지할 수 없음 — 는 계측된 에이전트가 이 탈출구를 스스로 사용하지 못하도록 방지합니다.

## 정책 플래그

| 플래그 | 용도 |
| --- | --- |
| `--install`, `-i` | 하니스 훅 설치. 이후의 이름들은 해당 정책을 활성화; 없으면 정책 변경 없음 |
| `--uninstall`, `-u` | 정책 비활성화 또는 훅 제거 |
| `--cli <names...>` | 하나 이상의 지원되는 하니스 대상 지정 |
| `--scope user\|project\|local\|all` | 설정 범위 선택; `all`은 제거용 |
| `--beta` | 베타 정책 포함 |
| `--custom`, `-c <path>` | 커스텀 정책 파일 검증 및 로드; 반복 사용 가능 |

## 전달 및 유지 관리 플래그

| 명령어 | 플래그 |
| --- | --- |
| `backfill` | `--since <30d\|6m\|YYYY-MM-DD>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` |

`failproofai update`는 `npm install -g failproofai@latest` 이후에 실행해야 합니다; 홈 레이아웃 마이그레이션을 수행하고, 일치하는 데몬 바이너리를 설치하며, 서비스를 재시작합니다. 그런 다음 이미 FailproofAI를 사용하는 모든 Hermes 프로필을 연결된 네이티브 플러그인으로 이동하고 프로필당 한 줄씩 출력합니다. `--no-daemon`은 데몬 단계를 건너뜁니다. `update`는 데몬을 교체할 수 없거나, 마이그레이션이 실패하거나, Hermes 프로필을 마이그레이션할 수 없는 경우(예: 실행 중인 데몬이 네이티브 플러그인을 제공할 수 없는 경우, 이때 셸 훅은 그대로 유지됨) 비정상 종료합니다.

## 하니스 경로

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

지원되는 하니스 이름은 `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, `goose`입니다.

레이블은 두 루트가 동일한 프로젝트의 복사본을 포함할 때 파생된 에이전트 ID를 네임스페이스로 구분합니다. 중복 루트와 중복 레이블은 수집 중복이나 커서 손상을 방지하기 위해 거부됩니다. 추가 경로 설정은 데몬 재시작 없이 다시 로드됩니다.

컨테이너 환경에서는 파일로 설정된 추가 경로를 `FAILPROOFAI_<HARNESS>_EXTRA_PATHS`라는 쉼표로 구분된 변수로 대체할 수 있습니다. 예를 들면:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## 환경 변수

지속적인 머신 동작에는 설정 파일을 사용하세요. 환경 변수는 컨테이너, 테스트, 단일 프로세스에 가장 유용합니다.

| 변수 | 용도 |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | `--token` 대신 Cloud 키. 이 방식을 권장: 인수는 모든 사용자가 `ps`로 읽을 수 있음. `read -s`로 설정하거나 CI 시크릿 스토어에서 설정하고, 절대 명령어에 직접 입력하지 마세요 — 어떤 방식이든 셸 히스토리에 남음 |
| `FAILPROOFAI_CLOUD_URL` | `--url` 대신 Cloud URL. 데몬이 읽는 것과 동일한 변수 |
| `FAILPROOFAI_HOME` | 전체 `~/.failproofai` 레이아웃 이동 |
| `FAILPROOFAI_LOG_LEVEL` | 로컬 로깅 상세도 설정 |
| `FAILPROOFAI_HOOK_LOG_FILE` | 선택한 파일에 훅 진단 기록 |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | 이 프로세스의 익명 원격 측정 비활성화 |
| `FAILPROOFAI_NO_FIRST_RUN=1` | 대화형 첫 실행 설정 건너뜀 |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | 설정 후 자동 로컬 감사 건너뜀 |
| `FAILPROOFAI_LLM_BASE_URL` | LLM 정책에서 사용하는 OpenAI 호환 엔드포인트 재정의 |
| `FAILPROOFAI_LLM_API_KEY` | LLM 정책에서 사용하는 API 키 제공 |
| `FAILPROOFAI_LLM_MODEL` | LLM 정책에서 사용하는 모델 선택 |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | 커스텀 정책 모듈 로딩 시간 제한 |
| `FAILPROOFAI_NO_DOWNLOAD=1` | 팩 및 데몬 바이너리 다운로드 거부; 설치된 것은 계속 적용 |
| `FAILPROOFAI_PACK_BASE_URL` | `github.com` 대신 미러에서 팩 가져오기 |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | 하나의 하니스에 대한 설정된 추가 캡처 경로 대체 |
| `NO_COLOR` | 터미널 색상 출력 비활성화 |

`CLAUDE_PROJECTS_PATH`, `CURSOR_HOME`, `HERMES_HOME`, `OPENCLAW_HOME`과 같은 에이전트별 홈 변수는 Failproof AI가 해당 하니스의 로컬 세션을 검색하는 위치를 재정의합니다.

## 머신 안전하게 일시 정지 또는 제거

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

로컬 세션 일시 정지는 Cloud 관리 정책을 비활성화하지 않습니다. 롤아웃 자체가 문제인 경우 Cloud 적용 워크플로를 통해 Cloud 배포를 복원하세요.

npm 패키지를 제거하기 전에 설치된 훅과 데몬을 먼저 제거하세요:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

버전별 세부 정보는 `failproofai <command> --help`를 실행하세요.

<Warning>
  `npm rm -g failproofai` 전에 `failproofai uninstall`을 실행하세요; npm은 설치된 에이전트 훅, `failproofai` 스킬 또는 데몬 서비스를 제거하지 않습니다.
</Warning>
