하네스란 에이전트가 실제로 실행되는 환경을 의미합니다. Failproof AI는 두 가지 유형으로 구분되는 12개의 하네스를 지원합니다:

- **코딩 CLI** (10개) — Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Factory Droid, Devin CLI, Antigravity CLI, Goose
- **채팅 및 어시스턴트 게이트웨이** (2개) — Hermes (Slack, Telegram, cron), OpenClaw (셀프 호스팅 어시스턴트)

에이전트가 어떤 하네스에서 실행되든 동일한 정책과 동일한 세션 히스토리가 적용됩니다. 하나의 어댑터 레이어가 각 하네스의 네이티브 이벤트 이름, 도구 이름, 도구 입력 필드를 정책 실행 전에 29개의 표준 이벤트로 매핑합니다.

12개 중 **어떤 하네스도 사용하지 않는** 에이전트는 [Python SDK](/ko/reference/custom-agents)를 통해 직접 계측합니다. 이는 별도의 계약이므로 명확히 짚고 넘어갈 필요가 있습니다. SDK는 추적, 세션, 평가 및 감사를 제공하지만 **자체적으로 정책을 적용하지는 않습니다.** 도구 실행 전에 안전하지 않은 작업을 차단하려면 런타임의 도구 경계에 적용 훅이 필요합니다. [문의하기](mailto:support@befailproof.ai)를 통해 연락하시면 매핑을 도와드리겠습니다.

| 하네스 | 지원되는 훅 범위 |
| --- | --- |
| Claude Code | User, project, local |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | User, project |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | User, project |
| Hermes, OpenClaw | User |

각 통합은 정책 실행 전에 네이티브 훅 이벤트 이름, 도구 이름, 도구 입력 필드를 정규화합니다. 정책은 하네스가 노출하는 이벤트에 대해서만 동작할 수 있으므로, 실제로 배포하는 하네스와 버전에서 직접 턴 종료 및 지시 동작을 테스트하세요.

## 적용 기능

"차단"은 현재 어댑터가 반환한 판결이 해당 하네스에서 처리됨을 의미합니다. 사후 도구 차단은 모델에 표시되는 결과를 대체할 수 있지만, 이미 발생한 도구 사이드 이펙트는 되돌릴 수 없습니다.

| 하네스 | 검증된 차단 이벤트 | 관찰 전용 또는 비차단 주의사항 |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact` 및 여러 태스크/설정 이벤트 | `PostToolUse`, 세션 라이프사이클, 알림 및 실패 후 이벤트는 관찰용입니다. |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | 사후 도구 차단은 실행 후 결과를 대체하며, 세션 시작 및 compact 이벤트는 현재 어댑터에서 관찰용입니다. |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | 사후 도구 차단은 실행 후 결과를 대체하며, 세션 및 알림 이벤트는 관찰용입니다. |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` 및 세션 이벤트는 관찰용입니다. |
| OpenCode | `PreToolUse` | 사후 도구 및 라이프사이클 이벤트는 관찰용이며, 현재 stop 처리는 검증된 게이트가 아닌 이후 턴에 대한 가이던스입니다. |
| Pi | `PreToolUse`, `UserPromptSubmit` | 사후 도구 및 라이프사이클 이벤트는 관찰용이며, stop 가이던스는 이후 턴에 적용됩니다. |
| Hermes | `PreToolUse` | `deny()`는 차단합니다. `instruct()`는 호출을 중단하지 않으며, 호출이 실행된 후 가이던스가 결과 앞에 배치됩니다. 사후 도구, 세션, 서브에이전트 stop 판결은 게이트가 아닙니다. |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | 사후 도구, 세션, 서브에이전트 stop, compaction 이벤트는 관찰용입니다. |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | 사후 도구 및 서브에이전트 stop 판결은 관찰용입니다. |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, 조건부 `PermissionRequest` | 권한 훅은 모든 권한 모드에서 실행되지 않으며, 사후 도구 및 세션 이벤트는 관찰용입니다. |
| Antigravity CLI | `PreToolUse`, `Stop` | 사용자 프롬프트 및 사후 도구 판결은 관찰용이지만, 프롬프트 지시 주입은 여전히 가능합니다. |
| Goose | `PreToolUse` | 사용자 프롬프트, 사후 도구, 세션 이벤트는 관찰용입니다. 네이티브 차단 stop 훅이 업스트림에 존재하지만 현재 어댑터에서는 설치되지 않습니다. |

기능은 버전에 따라 달라집니다. 특히 정책이 일반적인 사전 도구 게이트가 아닌 프롬프트, stop, 권한 또는 사후 도구 동작에 의존하는 경우, 에이전트 CLI를 업그레이드한 후 반드시 재테스트하세요.

### Hermes 네이티브 플러그인

Hermes는 셸 커맨드 대신 프로필 로컬 네이티브 플러그인을 통해 통합됩니다. 설치 시 모든 기본 및 명명된 Hermes 프로필의 `plugins/failproofai`를 npm 패키지에 포함된 플러그인으로 연결하고(심볼릭 링크를 생성할 수 없는 경우 복사), 해당 프로필의 `config.yaml`에서 활성화하며, 레거시 FailproofAI 셸 훅 항목만 마이그레이션합니다. 플러그인이 링크되어 있으므로 `npm install -g failproofai@latest`로 재설치 없이 업데이트됩니다. 이를 통해 각 훅마다 프로세스를 새로 생성하는 오버헤드를 방지합니다. 플러그인은 Hermes 0.20.0 이상을 지원합니다.

레거시 셸 훅(1.0.5 이하에서 설치된 것)은 Hermes cron 작업을 확인하지 **않습니다**. 각 cron 실행은 자체적인 훅 범위를 구성하며 네이티브 플러그인은 여기에 참여하지만 `config.yaml` 셸 훅은 그렇지 않습니다. `failproofai update`는 FailproofAI를 이미 사용 중인 모든 프로필을 링크된 플러그인으로 마이그레이션합니다. 실행 중인 데몬이 플러그인을 서비스할 수 없는 경우, `update`는 셸 훅을 그대로 유지하고 비정상 종료합니다. `failproofai config`로 데몬을 업데이트한 후 `failproofai update`를 다시 실행하세요. Cron 작업은 다음 실행 시 플러그인을 로드합니다. 실행 중인 게이트웨이와 인터랙티브 세션에서 로드하려면 재시작이 필요합니다.

Hermes에서 `deny()`는 호출을 차단하지만 `instruct()`는 그렇지 않습니다. 호출이 실행된 후 가이던스가 결과 앞에 배치됩니다 — JSON 결과의 첫 번째 키인 `failproof_policy_reminder`로, 또는 선행 `[FailproofAI policy reminder (...)]` 줄로 — 모델이 출력과 함께 읽을 수 있고, 결과를 파싱하는 스크립트도 계속 작동합니다. 정책 리마인더는 턴당 한 번 표시되며, 대용량 결과에서는 간략하게 유지됩니다. 작업이 절대 발생해서는 안 되는 경우 `deny()`를 사용하세요. `instruct()`는 더 이상 작업을 먼저 중단하지 않습니다. `execute_code` 스크립트에서 수행된 도구 호출은 모델이 읽는 `execute_code` 결과에 리마인더를 배치하며, 스크립트 자체의 결과 복사본은 그대로 유지됩니다. 모델은 리마인더를 응답에 인용하지 않도록 지시받습니다.

플러그인 미들웨어 없이 빌드된 Hermes는 일치하는 호출을 "FailproofAI policy guidance"로 한 번 보류하는 방식으로 폴백합니다. 다음 모델 응답에서 이를 반복하거나 다른 도구로 동일한 작업을 수행할 수 있으며, 더 이상 보류되지 않습니다.

도구 이름은 Hermes 버전 간에 매칭됩니다. `process_manage`, `cronjob_manage`, `todo_list` (Hermes 0.21)는 `process`, `cronjob`, `todo` (Hermes 0.20)와 동일하게 처리됩니다. Hermes가 플러그인을 로드할 때마다 프로필의 `plugin-data/agent-plugin-failproofai-5296f299/` 디렉토리에 `heartbeat.json`을 기록하며, 여기에는 Hermes 버전, 플러그인 경로 및 버전, Hermes가 수락한 훅이 기록됩니다. `failproofai config --status`를 실행하여 비활성화되었거나 불완전하거나 중복되거나 새로 구성되지 않은 프로필, 또는 여전히 레거시 셸 훅을 사용하는 프로필("Hermes cron jobs are not checked"로 보고됨)을 감지하세요.

### OpenClaw 플러그인

OpenClaw은 모든 프로필의 `openclaw.json`에 등록된 인프로세스 게이트웨이 플러그인으로 FailproofAI를 로드합니다. Hermes 플러그인과 마찬가지로, 로컬 `failproofaid` 데몬에 소켓을 통해 각 판결을 요청하므로 실행 중인 데몬이 필요합니다. 데몬 없이는 설치가 거부되며, 데몬이 응답할 수 없는 경우 도구 호출과 프롬프트가 차단되고 이유가 게이트웨이 로그에 기록됩니다. `npm install -g failproofai@latest` 후 업데이트된 플러그인을 로드하려면 OpenClaw 게이트웨이를 재시작하세요.

### Codex 훅 신뢰

Codex 0.129 이상은 인터랙티브 `codex`에서 승인("Review hooks")한 후에만 `~/.codex/hooks.json`의 훅을 실행합니다. 승인 전까지는 헤드리스 `codex exec`를 포함한 모든 Codex 세션에서 훅이 건너뜁니다. Codex 시스템 설정인 Linux 및 macOS의 `/etc/codex/config.toml`에 있는 훅은 해당 승인 없이 실행됩니다.

따라서 `failproofai config`(또는 user 범위에서 `policies --install --cli codex`)가 sudo를 사용할 수 있는 경우, Codex 훅을 `/etc/codex/config.toml`에 `# >>> failproofai managed hooks >>>` 와 `# <<< failproofai managed hooks <<<` 사이에 기록하고 나머지 파일은 그대로 유지합니다.

이 파일은 머신의 모든 계정에 적용되므로, 파일 내의 각 훅은 root 소유의 간단한 스크립트인 `/opt/failproofai-codex/codex-hook`을 실행합니다. 이 스크립트는 훅을 설정한 각 계정에 대해 해당 계정 자신의 failproofai에 이벤트를 전달하고, 다른 계정에 대해서는 아무 작업도 하지 않습니다. Codex 훅에 failproofai를 사용하려는 다른 계정은 직접 설정해야 합니다.

블록을 작성하기 전과 모든 `failproofai update` 시, failproofai는 `/etc/codex/config.toml` 자체, 스크립트, 그 위의 모든 디렉토리, 실행하는 `sh`, `id`, `cat`이 root 소유이고 다른 사람이 쓸 수 없는지, 그리고 각 계정의 failproofai가 해당 계정 또는 root에 속하는지 확인합니다. 설치 시 이 확인이 실패하면 훅은 `~/.codex/hooks.json`에 유지됩니다. 업데이트 시 확인에 실패한 스크립트는 블록에서 제거되고, failproofai 확인에 실패한 계정은 스크립트에서 제외됩니다. 수정 후 `failproofai config`를 다시 실행하세요. `failproofai update`는 또한 이전 버전으로 작성된 블록을 sudo가 필요한 스크립트를 사용하도록 재작성합니다.

`failproofai uninstall` 및 `failproofai config`에서 Codex 체크 해제는 해당 계정을 다시 제거하며, 더 이상 계정이 없으면 블록도 함께 제거됩니다.

sudo 없이는, 그리고 Windows에서는 훅이 `~/.codex/hooks.json`에 유지됩니다. `failproofai config` 및 `failproofai config --status`는 훅이 승인될 때까지 Codex를 적용 중으로 간주하지 않으며, 수정 방법을 안내합니다. `failproofai config`를 다시 실행하여 sudo를 허용하거나, `codex`를 한 번 열어 훅을 승인하면 됩니다.

    ```bash
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```

## 비기본 세션 경로 추가

<Tabs>
  <Tab title="대시보드">
    추가 경로는 Cloud가 아닌 머신에 등록됩니다. 경로를 추가한 후 **trace → sessions**를 열어 머신 환경으로 필터링하고, 새 경로에서 세션이 나타나는지 확인하세요. 감사에 활용하기 전에 세션을 열어 에이전트, 하네스, 이벤트 타임스탬프를 확인하세요.

    ![추가 캡처 경로에서 데이터를 수신하는 환경으로 필터링된 Sessions 목록.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    선택적 레이블과 함께 경로를 추가한 후 설정된 경로를 확인합니다:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    `failproofai harness remove-path claude checkout`으로 경로를 제거합니다.
  </Tab>
</Tabs>

<Tip>
  설치 후 새 세션을 하나 실행하세요. 롤아웃을 확장하기 전에 라이브 이벤트 스트림과 실제 정책 결정 모두를 확인하세요.
</Tip>
