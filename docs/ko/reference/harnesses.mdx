하네스(harness)란 에이전트가 실제로 실행되는 환경을 의미합니다. Failproof AI는 두 가지 유형으로 분류된 12개의 하네스를 지원합니다.

- **코딩 CLI** (10개) — Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Factory Droid, Devin CLI, Antigravity CLI, Goose
- **채팅 및 어시스턴트 게이트웨이** (2개) — Hermes (Slack, Telegram, cron), OpenClaw (셀프호스팅 어시스턴트)

어떤 하네스에서 에이전트가 실행되더라도 동일한 정책과 동일한 세션 히스토리가 적용됩니다. 어댑터 레이어 하나가 각 하네스의 네이티브 이벤트 이름, 도구 이름, 도구 입력 필드를 정책 실행 전에 29개의 표준 이벤트로 매핑합니다.

12개 중 **어느 하네스에도 해당하지 않는** 에이전트는 [Python SDK](/ko/reference/python-sdk)를 통해 직접 계측할 수 있습니다. 이는 별도의 계약 방식으로, 명확히 짚고 넘어갈 필요가 있습니다. SDK는 트레이싱, 세션, 평가, 감사 기능을 제공하지만 **자체적으로 정책을 적용하지는 않습니다.** 실행 전에 안전하지 않은 동작을 차단하려면 런타임의 도구 경계에 적용 훅이 필요합니다. [문의하기](mailto:support@befailproof.ai)를 통해 연락 주시면 매핑 작업을 도와드립니다.

| 하네스 | 지원되는 훅 스코프 |
| --- | --- |
| Claude Code | User, project, local |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | User, project |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | User, project |
| Hermes, OpenClaw | User |

각 통합은 정책 실행 전에 네이티브 훅 이벤트 이름, 도구 이름, 도구 입력 필드를 정규화합니다. 정책은 해당 하네스가 노출하는 이벤트에만 작용할 수 있으므로, 실제 배포에 사용할 정확한 하네스와 버전에서 턴 종료 및 명령 동작을 테스트하세요.

## 적용 기능

"차단(Block)"은 현재 어댑터가 반환한 판정을 지정된 하네스가 수용함을 의미합니다. 도구 사후 차단(Post-tool blocking)은 모델에 표시되는 결과를 교체할 수 있지만, 이미 발생한 도구 부작용을 되돌릴 수는 없습니다.

| 하네스 | 검증된 차단 이벤트 | 관찰 전용 또는 비차단 주의 사항 |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact` 및 여러 태스크/설정 이벤트 | `PostToolUse`, 세션 라이프사이클, 알림, 장애 후 이벤트는 관찰 전용입니다. |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | 도구 사후 차단은 실행 후 결과를 교체하며, 세션 시작 및 compact 이벤트는 현재 어댑터에서 관찰 전용입니다. |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | 도구 사후 차단은 실행 후 결과를 교체하며, 세션 및 알림 이벤트는 관찰 전용입니다. |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` 및 세션 이벤트는 관찰 전용입니다. |
| OpenCode | `PreToolUse` | 도구 사후 및 라이프사이클 이벤트는 관찰 전용이며, 현재 stop 처리는 검증된 게이트가 아닌 이후 턴에 대한 가이드입니다. |
| Pi | `PreToolUse`, `UserPromptSubmit` | 도구 사후 및 라이프사이클 이벤트는 관찰 전용이며, stop 가이드는 이후 턴에 적용됩니다. |
| Hermes | `PreToolUse` | 도구 사후, 세션, subagent-stop 판정은 게이트로 작동하지 않습니다. |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | 도구 사후, 세션, subagent-stop, compaction 이벤트는 관찰 전용입니다. |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | 도구 사후 및 subagent-stop 판정은 관찰 전용입니다. |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, 조건부 `PermissionRequest` | 권한 훅은 모든 권한 모드에서 실행되지 않으며, 도구 사후 및 세션 이벤트는 관찰 전용입니다. |
| Antigravity CLI | `PreToolUse`, `Stop` | 사용자 프롬프트 및 도구 사후 판정은 관찰 전용이나, 프롬프트 명령 주입은 여전히 가능합니다. |
| Goose | `PreToolUse` | 사용자 프롬프트, 도구 사후, 세션 이벤트는 관찰 전용입니다. 네이티브 차단 stop 훅이 상위에 존재하지만 현재 어댑터에는 설치되어 있지 않습니다. |

기능은 버전에 따라 달라집니다. 에이전트 CLI를 업그레이드한 후, 특히 공통 도구 사전 게이트(pre-tool gate)가 아닌 프롬프트, stop, 권한, 도구 사후 동작에 의존하는 정책이 있는 경우 반드시 재테스트하세요.

## 캡처 및 정책 훅 설치

<Tabs>
  <Tab title="대시보드">
    1. **Administration → Keys**를 열고 머신 또는 환경에 맞는 이름으로 `events:add` 및 `policies:pull` 권한이 있는 키를 생성합니다.
    2. 대상 머신에서 표시된 키로 로컬 CLI를 연결하고 하네스 훅을 설치합니다.
    3. 새 에이전트 세션을 시작한 후 **Observe → Events**에서 해당 훅과 세션 이벤트를 확인합니다.
    4. 동일한 시간 범위에서 **Observe → policy**를 열고 해당 머신에 정책 결정이 귀속되는지 확인합니다.

    연결은 머신 키로 시작됩니다. 시크릿을 복사하기 전에 수집 및 정책 전달 권한이 모두 포함되어 있는지 확인하세요.

    ![이벤트 수집 및 정책 전달 권한을 부여하는 데 사용되는 새 API 키 드로어.](/images/dashboard/key-create.png)

    훅을 설치한 후 Events 스트림에 연결한 머신 및 환경의 새 이벤트가 표시되어야 합니다.

    ![새로 설치된 하네스가 보고 중임을 확인하는 데 사용되는 실시간 Events 스트림.](/images/dashboard/events-stream.png)

    마지막으로, 동일한 머신에 정책 결정이 귀속되는지 확인합니다. 이를 통해 하네스가 트레이스 이벤트뿐만 아니라 정책 활동도 보고하고 있음을 확인할 수 있습니다.

    ![새로 연결된 하네스의 정책 결정을 검증하는 데 사용되는 Policy 페이지.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    감지된 모든 하네스에 훅 설치:

    ```bash
    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>
    failproofai policies --install
    ```

    또는 특정 하네스와 설정 스코프를 지정하여 설치:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    Project 스코프는 훅 설정을 리포지토리에 함께 보관합니다. User 스코프는 리포지토리 전반의 작업을 포괄합니다. Claude Code는 local 스코프도 지원하며, 지원 여부는 하네스마다 다르고 CLI는 지원되지 않는 조합을 거부합니다.

    머신 및 이벤트 확인:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## 기본값이 아닌 세션 경로 추가

<Tabs>
  <Tab title="대시보드">
    추가 경로는 클라우드가 아닌 머신에 등록됩니다. 경로를 추가한 후 **Observe → Sessions**을 열고, 해당 머신의 환경으로 필터링하여 새 경로의 세션이 표시되는지 확인합니다. 감사에 활용하기 전에 세션을 열어 에이전트, 하네스, 이벤트 타임스탬프를 점검하세요.

    ![추가 캡처 경로에서 데이터를 수신하는 환경으로 필터링된 Sessions 목록.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    선택적 레이블과 함께 경로를 추가한 후 설정된 경로를 확인합니다:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    `failproofai harness remove-path claude checkout`으로 경로를 제거합니다.
  </Tab>
</Tabs>

<Tip>
  설치 후 새 세션을 한 번 실행해 보세요. 롤아웃을 확대하기 전에 실시간 이벤트 스트림과 실제 정책 결정 모두를 확인하세요.
</Tip>
