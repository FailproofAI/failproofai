이 문서는 [Jev 정책](/ko/policies/jev)의 Cloud 경로 참조입니다. TypeSafe의 분류기인 Jev는 각 도구 호출을 실제로 요청한 내용과 비교하여 읽고, 정책과 함께 응답합니다. 정책을 대체하는 것이 아닙니다. **FailproofAI Cloud**를 통해 연결된 머신은 이미 사용 중인 키로 Jev를 사용합니다. TypeSafe 계정, 두 번째 키, 별도의 엔드포인트 설정이 필요 없습니다. 각 호출은 조직의 기존 플랜 허용량에서 차감됩니다.

Jev의 모든 동작은 [직접 키 설정](/ko/reference/jev-providers)과 동일합니다. 하드 정책은 최종 결정을 유지하고, 검토 가능한 정책의 deny는 Jev가 정확히 해당 사안에 대해 질의받은 경우에만 해제되며, 오류 발생 시에는 해당 호출에 대한 정규식 결과로 폴백됩니다.

<Note>
**failproofai 1.0.8-beta.0** 이상이 필요합니다. 1.0.7에는 Jev가 없습니다. 버전 정렬 상 1.0.7 베타보다 위에 표시되더라도 마찬가지입니다. Jev 설정이 없으면 아무것도 변경되지 않습니다. 훅은 항상 그래왔던 것처럼 정규식 정책을 그대로 실행합니다.
</Note>

## 시작 전 준비

에이전트가 실행되는 머신에 Failproof AI를 설치하고 훅을 [지원되는 하네스](/ko/reference/harnesses)에 연결하세요. 처음 시작하는 경우 [빠른 시작](/ko/start/quickstart) 가이드의 훅 설치 단계까지 따라하세요. `failproofai --version`으로 설치된 CLI를 확인하고, Jev 이전 버전이라면 업데이트하세요. 머신 키를 생성하려면 조직의 **Administration → Keys** 페이지에 대한 접근 권한도 필요합니다.

Jev는 `PreToolUse` 또는 `PermissionRequest` 게이트에서 명명된 도구 호출을 검토합니다. 세션의 모든 이벤트를 검토하지는 않습니다. Jev가 정책 deny를 해제하는 것을 확인하려면 [reviewable](/ko/policies/authority)로 표시된 정책이 설치되어 있어야 합니다. 그 외의 모든 정책 deny는 최종 결정으로 유지됩니다.

## 활성화 방법

1. **Jev가 포함된 키를 생성합니다.** FailproofAI Cloud 대시보드에서 **Administration → Keys → Create key**를 열고 **machine** 프리셋을 선택합니다. 머신에 필요한 세 가지 권한이 부여됩니다: `events:add`(활동 전송), `policies:pull`(정책 수신), `jev:evaluate`(Jev, 조직 플랜에서 차감). 키는 나머지 두 권한 없이 `jev:evaluate`만 가질 수 없습니다.
2. 해당 키로 **머신을 연결**합니다. 프롬프트에서 일회성 시크릿을 읽은 다음 전체 설정 명령을 실행합니다:

   ```bash
   read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
   failproofai config
   ```

   `failproofai config`는 데몬을 설치하고, 찾은 에이전트 CLI에 훅을 연결하며, 머신을 연결합니다. 환경 변수를 사용하면 키가 명령 인수와 셸 히스토리에 남지 않습니다. 하네스를 나중에 설치한 경우 [명시적으로 연결](/ko/start/quickstart)하세요.

   조직이 호스팅 서비스 대신 자체 FailproofAI Cloud를 운영하는 경우 주소를 추가하세요: `--url https://<your dashboard host>` (또는 `FAILPROOFAI_CLOUD_URL` 환경 변수로 내보내기). 없으면 키가 호스팅 서비스에서 확인되어 연결이 실패합니다. 해당 호스트의 인증서가 사설 CA에서 발급된 경우 `NODE_EXTRA_CA_CERTS`가 아닌 머신의 시스템 신뢰 저장소에 CA를 설치하세요(예: `update-ca-certificates` 사용). 이벤트를 전송하고 정책을 가져오는 데몬이 시스템 저장소를 읽습니다. [문제 해결](/ko/reference/troubleshooting)을 참조하세요.

이것이 전부입니다. 연결 시 키가 저장되고, 머신에 Jev 설정이 **없는** 경우 FailproofAI Cloud용 설정이 작성됩니다. 머신의 첫 번째 배포(약 30초 이내)부터 FailproofAI Cloud가 모드를 설정합니다: Jev 정책이 배포된 경우 `enforce`, 없는 경우 `off`입니다([모드 설정 주체](#who-sets-the-mode) 참조). 출력에 다음과 같이 표시됩니다:

```text
  Jev       configured through FailproofAI Cloud; waiting for FailproofAI Cloud's Jev mode, which arrives with this machine's first deployment (within ~30 s) and decides.
```

FailproofAI Cloud가 배포하는 검사는 Cloud에서 실행됩니다. 머신에 자체 검사를 추가하려면 팩을 설치하세요:

```bash
failproofai policies add FailproofAI/jev-policies
```

**`--no-transcripts`를 사용하여 연결하면 Jev가 활성화되지 않습니다.** Jev는 검사된 각 도구 호출과 최근 프롬프트를 FailproofAI Cloud로 전송하는데, 이는 결정만 전송하도록 요청된 연결이 보내는 것보다 더 많습니다. 키는 여전히 저장되고, 출력에 Jev가 사용 가능하며 활성화 방법이 표시됩니다:

```bash
failproofai jev setup --provider failproofai
```

이 명령은 FailproofAI Cloud를 통한 Jev를 **비활성화**하기도 합니다. FailproofAI Cloud를 통해 Jev를 실행하는 `jev.json`(트랜스크립트 활성화 상태의 이전 연결로 남겨진 것)은 `config --disconnect`가 사용하는 것과 동일한 규칙으로 제거되며, 출력에 이 머신에서 FailproofAI Cloud를 통한 Jev가 비활성 상태로 유지된다고 표시됩니다. 자체 Jev 엔드포인트용 `jev.json`은 그대로 유지되고, `--mode off`로 비활성화한 FailproofAI Cloud 설정도 마찬가지입니다.

<Warning>
연결 시 기존 `~/.failproofai/jev.json`을 **절대 덮어쓰지 않습니다**. 이미 자체 Jev 엔드포인트를 사용 중이라면 계속 사용됩니다. 출력에 파일이 설정된 대로 유지되었다고 표시되며, 해당 파일이 Jev를 비활성 상태로 두는 경우(거부됨 또는 비활성화됨) 그 이유와 수정 방법도 표시됩니다. 해당 머신을 FailproofAI Cloud로 전환하려면 `failproofai jev setup --provider failproofai`를 실행하세요.
</Warning>

## 모드 설정 주체

FailproofAI Cloud에 연결된 머신에서는 **FailproofAI Cloud가 Jev 모드를 설정**합니다. 머신의 어떤 것도 모드를 설정하지 않습니다:

- Jev(또는 정규식 + Jev) 정책이 머신에 배포된 경우 `enforce`: 해당 정책이 대상으로 하는 에이전트의 모든 검사된 도구 호출이 FailproofAI Cloud로 전송되며, FailproofAI Cloud는 자체 검사와 함께 해당 검사를 요청합니다. Cloud Jev 정책이 대상으로 하지 않는 에이전트의 호출이고 자체 팩 검사도 없는 경우 전혀 전송되지 않습니다. `enforce` 모드에서 Jev의 자체 deny 검사는 정규식 판정을 검토하는 것뿐만 아니라 호출을 차단하기도 합니다.
- 배포된 정책이 없는 경우 `off`: `jev.json`의 내용에 관계없이 Jev가 전혀 작동하지 않습니다.

Jev 정책을 실제 적용 전에 시험해보려면 효과를 **observe**로 설정하여 배포하세요. 검사는 여전히 요청되고 결과는 정책 페이지에 **would-have**로 기록되지만, 호출을 차단하거나 해제하지 않습니다. `failproofai jev setup --mode`와 대시보드의 **Settings → Jev** 스위치는 모드가 FailproofAI Cloud에 의해 관리됨을 표시하며 아무것도 변경하지 않습니다. `jev.json`은 다른 프로바이더를 지정하더라도 Cloud 검사에 사용되지 않습니다. `failproofai config --disconnect`를 실행하면 Jev가 머신 자체의 `jev.json`으로 돌아갑니다.

`failproofai jev status`는 `Jev checks run on FailproofAI Cloud (mode: enforce)`라고 표시됩니다. 각 `both` 정책을 검토하는 검사도 나열됩니다. 플릿 페이지는 모드를 가진 머신이 요청할 수 없는 이유를 표시합니다:

- `transcripts_disabled`: 머신이 `--no-transcripts`로 연결되어 Jev가 활성화되지 않습니다.
- `jev_unconfigured`: 머신의 키에 `jev:evaluate`가 없습니다.
- `jev_rate_limited`: FailproofAI Cloud가 조직의 Jev 속도 제한으로 인해 일부 호출을 거부했으며, 해당 호출은 정규식 정책만으로 결정되었습니다.
- `jev_unavailable`: 연속으로 여러 호출이 실패하여 머신이 한 번에 1분씩 FailproofAI Cloud의 Jev를 건너뜁니다. 자동으로 재시도합니다.

FailproofAI Cloud가 5초 이내에 응답하지 않으면 Jev 장애 시와 마찬가지로 정규식 정책만으로 결정됩니다. 연속 3회 실패 후 머신은 한 번에 1분씩 요청을 중단하므로, Cloud 장애 시 모든 도구 호출이 느려지지 않습니다.

세션 일시 중지(`failproofai config --pause`)는 Cloud 관리 정책을 중지하지 않는 것과 마찬가지로 FailproofAI Cloud의 Jev 검사를 중지하지 않습니다. 머신에 설치된 팩의 Jev 검사는 일시 중지됩니다.

## 동작 확인

```bash
failproofai jev status
failproofai jev test
```

`status`는 프로바이더를 **FailproofAI Cloud**로 표시하고, 머신이 연결된 Cloud 호스트, 모드, 키 소스를 **FailproofAI Cloud connection**으로 표시합니다. 키 자체는 표시되지 않습니다. FailproofAI Cloud `jev.json`이 있지만 Jev를 실행할 수 없는 경우 그 이유를 표시합니다:

| `status` 표시 | `status --json` | 의미 |
| --- | --- | --- |
| **off — no Jev key is stored for this machine's FailproofAI Cloud connection** | `key-lacks-jev` | 머신은 연결되어 있지만 Jev 키가 저장되지 않았습니다: 키에 `jev:evaluate`가 없거나 연결 시 확인에 실패했습니다. `FAILPROOFAI_CLOUD_TOKEN`에 키를 설정하여 `failproofai config`를 다시 실행하세요. 권한이 없는 경우 **machine** 키를 사용하세요. |
| **off — this machine is not connected to FailproofAI Cloud** | `not-connected` | 이 머신에 FailproofAI Cloud 연결이 없어 Jev 키가 속할 연결이 없습니다. |

`failproofai config --disconnect` 후에는 FailproofAI Cloud `jev.json`이 더 이상 존재하지 않습니다(비활성화된 경우는 유지). 따라서 `status`는 단순히 Jev가 off라고 보고합니다. `status --json`은 설정이 없거나 거부된 경우에도 동일한 정보를 포함합니다(`provider: "failproofai"`, `keySource: "cloud"`, `cloudConnected`, `keyCarriesJev`). `permissions`는 항상 `jev.json`의 것이며, `credentials.json`에 관한 거부는 `credentialsPermissions`를 추가하고, 하나의 명령으로 수정 가능한 경우 `fix`도 추가됩니다. `test`는 실제 요청을 하나 전송하고 지연 시간과 응답한 Jev 버전을 보고합니다. 훅 타임아웃 이후에 응답이 도착하거나(훅이 `timeout`을 기록함) 검사 질문에 잘못 응답하면 종료 코드 1로 종료되며 제목에 표시됩니다.

대시보드의 **Settings → Jev** 패널에도 **FailproofAI Cloud connection**이 표시됩니다: 머신이 보고하는 조직과 키에 Jev가 포함되어 있는지 여부. 네트워크 호출 없이 머신 자체 파일에서 읽습니다.

## 실제 호출 확인

연결된 에이전트에서 새 세션을 시작합니다. `README.md`에 대해 파일 읽기 도구를 사용하고 제목을 보고하도록 요청합니다. 세션에 해당 도구 호출이 포함되어 있는지 확인한 다음 `failproofai jev status`를 다시 실행합니다. 최근 평가된 호출 수가 증가해야 합니다. [로컬 대시보드](/ko/reference/local-dashboard#review-policy-activity)의 **Policies → Activity**를 열어 해당 호출의 Jev 판정과 모드를 검사합니다. Cloud에서는 조직의 **Policies** 페이지에 전달된 활동에 대한 Jev 결과가 표시됩니다. observe 모드에서는 판정이 **would-have**로 기록되고 정책 결과가 여전히 호출을 결정합니다. 검토 가능한 정책이 일치하고 Jev가 명명된 검사를 해제한 경우에만 해제가 나타납니다.

## 정책 페이지에 전달되는 내용

머신은 이미 훅 활동을 FailproofAI Cloud(`events:add`)로 전송합니다. Jev가 활성화되면 각 게이트된 호출의 기록에 실행된 평가기, Jev의 결정, 해제된 정책, 폴백 이유(해당 시), 지연 시간, 응답한 모델이 포함됩니다. 명령이나 프롬프트가 아닌 결정, 코드, 이름만 포함됩니다. 조직의 **Policies** 페이지에서:

- Jev 자체 판정으로 결정된 호출(enforce 모드)은 **Jev**에 귀속되며, 결정 검사가 팩에서 온 경우 해당 팩과 버전도 기록에 표시됩니다.
- observe 모드에서 Jev의 deny 또는 경고는 관찰 중인 롤아웃 옆에 **would-have**로 표시됩니다.
- Jev가 해제한 정책(또는 observe 모드에서 해제했을 정책)은 정책별로 집계됩니다.
- Jev가 참여한 결정(차단, 경고, 해제, 또는 observe 모드의 would-have)은 요청한 각 검사와 해당 검사의 결론을 나열합니다: 판정, 이유(`not-detected`, `exempt`, `fired`, `op-requested` 등), 증거 `p`, `exempt` 응답과 각 프로브의 응답. observe로 배포된 정책의 검사도 나열되며 watched로 표시됩니다. 절대 차단하지 않습니다. Jev는 자유 형식 이유가 아닌 확률로 응답합니다. 단순 allow는 카운트로 집계되며 이 목록을 포함하지 않습니다.

## Jev가 응답할 수 없는 경우

다음 각각은 해당 호출에 대한 정책 결과로 폴백되고 이유와 함께 기록됩니다:

| 이유 | 원인 |
| --- | --- |
| `out-of-credits` | 조직이 플랜 허용량을 모두 사용했습니다. |
| `http-401`, `http-403` | 키가 취소되었거나 `jev:evaluate`가 없습니다. 해당 권한이 있는 키로 다시 연결하세요. |
| `http-429` | FailproofAI Cloud가 조직의 Jev를 속도 제한하고 있습니다. 요청된 대기 시간(`Retry-After`, 최대 60초)이 끝날 때까지 머신은 아무것도 전송하지 않고 모든 호출이 즉시 폴백됩니다. 이렇게 보류된 호출은 `http-429`로 기록되거나, 머신의 자체 속도 제한이 먼저 적용된 경우 `rate-limited`로 기록됩니다. |
| `http-429` (일일 한도) | 조직이 일일 Jev 호출 한도를 사용했습니다: FailproofAI Cloud 운영자가 다른 한도를 설정하지 않은 경우 **UTC 기준 하루 10,000건**. 카운트가 00:00 UTC에 재설정될 때까지 모든 호출이 폴백됩니다. 머신은 최대 1분에 한 번 다시 요청하므로 재설정 후 1분 이내에 감지합니다. `failproofai jev test`는 "Daily Jev limit for this org reached; resets at 00:00 UTC."라고 표시됩니다. |
| `http-422` | Jev가 이 호출의 요청을 거부했습니다. 일반적으로 도구 호출에 Jev의 토큰 예산을 초과하는 밀집된 텍스트(base64, hex, 압축된 코드)가 포함된 경우입니다. 해당 호출은 매번 폴백됩니다. 장애가 아닙니다. |
| `http-502` | Jev를 현재 사용할 수 없습니다. |
| `http-503` | 이 Cloud가 조직에 대해 Jev를 제공할 수 없습니다: 모델 게이트웨이 없음, 조직이 아직 프로비저닝되지 않음, 또는 게이트웨이 다운. 관리자에게 문의하세요. 훅은 최대 1분에 한 번 다시 요청합니다. |
| `http-404` | 이 FailproofAI Cloud는 아직 Jev를 제공하지 않습니다. |
| `timeout` | `timeoutMs`(기본값 3000) 이내에 응답이 없습니다. FailproofAI Cloud가 머신의 Jev 모드를 설정하는 동안 대기 시간은 5000ms이며 `jev.json`의 `timeoutMs`는 사용되지 않습니다. |
| `model-mismatch` | 1.13 이외의 Jev 버전이 응답했습니다. |

## 키의 위치와 전송 대상

- 키는 `~/.failproofai/credentials.json`(`0600`, 소유자 전용 디렉토리)에 한 번 저장되며, 다른 FailproofAI Cloud 자격 증명 옆에 있습니다. `jev.json`에는 이 경로에 대한 키가 없습니다. 거기에 키를 작성하면 설정이 유효하지 않게 됩니다.
- `credentials.json`에 소유자 이외의 사람(그룹 또는 기타, 읽기 또는 쓰기)에 대한 **모든** 권한이 있거나, 디렉토리가 소유자 이외의 사람이 **쓸** 수 있는 경우, 읽지 않고 **거부**되며 수정할 때까지 Jev가 비활성화됩니다: 파일에 `chmod 600`, 디렉토리에 `chmod 700`(또는 재연결, 파일을 `0600`으로 다시 작성하고 디렉토리를 소유자 전용으로 만듭니다). 다른 사람이 읽기만 할 수 있는 디렉토리는 괜찮습니다. 쓸 수 있으면 파일을 교체할 수 있습니다.
- 키는 함께 온 연결이 머신에 있는 동안에만 유효합니다: 동일한 파일에 같은 키를 가진 동일한 FailproofAI Cloud에 대한 정책 또는 보고 자격 증명. 연결 없이 남겨진 Jev 키는 무시되고 Jev는 비활성 상태로 유지됩니다. 이는 이전 버전의 failproofai `config --disconnect`가 Jev 키를 그대로 두거나(제거 방법을 모름), 이전 버전의 failproofai `config --token`이 다른 키로 연결할 때 발생합니다. FailproofAI Cloud에서 다른 키는 다른 조직에 속할 수 있습니다. Jev를 다시 활성화하려면 **machine** 키로 다시 연결하세요.
- 키는 확인된 Cloud 오리진에만 전송됩니다. 다른 곳을 가리키는 `jev.json`은 거부됩니다.
- **머신의 에이전트가 읽을 수 있습니다.** `credentials.json`은 소유자 전용이고 에이전트는 해당 소유자로 실행됩니다. failproofai 자체 파일을 읽는 것은 의도적으로 허용됩니다(변경만 `block-failproofai-commands`로 차단됨). 따라서 에이전트와 이 파일 사이에 있는 것은 `block-read-outside-cwd`(검토 가능한 정책)뿐이며, 홈 디렉토리에서 시작된 세션에서는 아무것도 없습니다. `jev:evaluate`가 있는 키는 사용되는 위치에 관계없이 조직의 Jev 허용량을(일일 한도까지) 소비합니다. 따라서 머신 키를 다른 지출 자격 증명처럼 취급하세요: 에이전트가 읽었을 가능성이 있다면 Keys 페이지에서 비활성화하고 새 키로 재연결하세요.
- 전역 파일만이 이를 결정합니다. 저장소는 Cloud Jev를 활성화하거나, 다른 곳을 가리키거나, 키를 제공할 수 없으며, `FAILPROOFAI_JEV_API_KEY`는 이 경로에서 무시됩니다.
- Jev가 평가하는 각 호출에 대해 하나의 요청이 FailproofAI Cloud로 전송됩니다. [직접 키 페이지](/ko/reference/jev-providers#what-leaves-the-machine)에 나열된 내용(시크릿 편집됨)을 포함합니다. FailproofAI Cloud는 이를 TypeSafe로 전달하며 기록하거나 보관하지 않습니다.

## 비활성화 방법

연결된 머신에서 FailproofAI Cloud가 Jev 정책을 배포하지 않으면 Jev가 비활성화됩니다: 해당 Jev 정책을 제거하거나 보관하세요.

| 명령 | 결과 |
| --- | --- |
| FailproofAI Cloud에서 머신의 Jev 정책 제거 | 다음 폴링(약 30초) 시 Cloud 모드가 `off`가 됩니다: `jev.json`의 내용에 관계없이 Jev가 전혀 작동하지 않습니다. |
| `failproofai config --disconnect` | 머신 연결을 해제합니다: 키가 제거되고, `jev.json`이 FailproofAI Cloud를 가리키며 비활성화되지 않은 경우 함께 제거됩니다. 자체 엔드포인트용 `jev.json`은 유지됩니다. |

다음 도구 호출부터 훅은 이전과 동일하게 정규식 정책을 실행합니다.
