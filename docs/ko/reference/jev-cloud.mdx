이 문서는 [Jev 정책](/ko/policies/jev)의 Cloud 경로 참조입니다. TypeSafe의 분류기인 Jev는 각 도구 호출을 실제로 요청한 내용과 대조하여 읽고, 정책 대신이 아니라 정책과 함께 판단을 내립니다. **FailproofAI Cloud**를 통해 연결된 머신은 이미 연결에 사용하는 동일한 키로 Jev를 사용합니다. TypeSafe 계정, 별도의 키, 구성할 엔드포인트가 필요 없습니다. 각 호출은 조직의 기존 플랜 허용량에서 청구됩니다.

Jev의 모든 동작은 [자체 키 설정](/ko/reference/jev-providers)과 동일합니다. 하드 정책은 최종적으로 유지되고, 검토 가능한 정책의 deny는 Jev가 정확히 해당 관심사에 대해 질문받은 경우에만 해제되며, 모든 장애는 해당 호출의 정규식 결과로 폴백됩니다.

<Note>
**failproofai 1.0.8-beta.0** 이상이 필요합니다. 1.0.7은 1.0.7 베타보다 정렬 순서가 높더라도 Jev가 없습니다. Jev 설정이 없으면 아무것도 변경되지 않습니다. 훅은 항상 그래왔던 것처럼 정규식 정책을 정확히 실행합니다.
</Note>

## 시작하기 전에

에이전트가 실행되는 머신에 Failproof AI를 설치하고 훅을 [지원되는 하네스](/ko/reference/harnesses)에 연결합니다. 처음 시작하는 경우 훅 설치를 통해 [퀵스타트](/ko/start/quickstart)를 따르세요. `failproofai --version`으로 설치된 CLI를 확인하고, Jev 이전 버전이라면 업데이트하세요. 머신 키를 생성하려면 조직의 **Administration → Keys** 페이지에 대한 접근 권한도 필요합니다.

Jev는 `PreToolUse` 또는 `PermissionRequest` 게이트에서 명명된 도구 호출을 검토합니다. 세션의 모든 이벤트를 검토하지는 않습니다. Jev가 정책 deny를 해제하는 것을 확인하려면 [검토 가능](/ko/policies/authority)으로 표시된 설치된 정책이 필요합니다. 다른 모든 정책 deny는 최종적으로 유지됩니다.

## 활성화하기

1. **Jev가 포함된 키를 생성합니다.** FailproofAI Cloud 대시보드에서 **Administration → Keys → Create key**를 열고 **machine** 프리셋을 선택합니다. 머신에 필요한 세 가지 권한이 부여됩니다: `events:add`(활동 전송), `policies:pull`(정책 수신), `jev:evaluate`(Jev, 조직 플랜에서 청구). 키는 나머지 두 권한 없이 `jev:evaluate`를 가질 수 없습니다.
2. 해당 키로 **머신을 연결합니다**. 프롬프트에서 일회성 시크릿을 읽은 다음 전체 설정 명령을 실행합니다:

   ```bash
   read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
   failproofai config
   ```

   `failproofai config`는 데몬을 설치하고, 발견된 에이전트 CLI에 훅을 연결하며, 머신을 연결합니다. 환경 변수는 키가 명령의 인수와 셸 기록에 남지 않도록 합니다. 하네스가 나중에 설치된 경우 [명시적으로 연결](/ko/start/quickstart)하세요.

   조직이 호스팅 서비스 대신 자체 FailproofAI Cloud를 운영하는 경우 주소를 추가합니다: `--url https://<your dashboard host>` (또는 `FAILPROOFAI_CLOUD_URL` 내보내기). 없으면 키가 호스팅 서비스에 대해 확인되고 연결이 실패합니다. 해당 호스트의 인증서가 사설 CA에서 온 경우 `NODE_EXTRA_CA_CERTS`가 아닌 머신의 시스템 신뢰 저장소에 CA를 설치합니다(예: `update-ca-certificates` 사용). 이벤트를 전송하고 정책을 가져오는 데몬은 시스템 저장소를 읽습니다. [문제 해결](/ko/reference/troubleshooting)을 참조하세요.

이것으로 충분합니다. 연결하면 키가 저장되고, 머신에 Jev 설정이 **없는** 경우 FailproofAI Cloud용 설정이 작성됩니다. 머신의 첫 번째 배포(약 30초 이내)부터 FailproofAI Cloud가 모드를 설정합니다. Jev 정책이 배포된 동안은 `enforce`, 없을 때는 `off`입니다([모드를 설정하는 주체](#모드를-설정하는-주체) 참조). 출력에 표시됩니다:

```text
  Jev       configured through FailproofAI Cloud; waiting for FailproofAI Cloud's Jev mode, which arrives with this machine's first deployment (within ~30 s) and decides.
```

FailproofAI Cloud가 배포하는 검사는 Cloud에서 실행됩니다. 머신에 자체 검사를 추가하려면 팩을 설치하세요:

```bash
failproofai policies add FailproofAI/jev-policies
```

**`--no-transcripts`를 사용하면 연결해도 Jev가 활성화되지 않습니다.** Jev는 검사된 각 도구 호출과 최근 프롬프트를 FailproofAI Cloud에 전송하는데, 이는 결정만 전송하도록 요청된 연결보다 더 많은 정보를 보내는 것입니다. 키는 여전히 저장되며, 출력에는 Jev를 사용할 수 있고 활성화 방법이 표시됩니다:

```bash
failproofai jev setup --provider failproofai
```

또한 FailproofAI Cloud를 통한 Jev를 **끄기**도 합니다. FailproofAI Cloud를 통해 Jev를 실행하는 `jev.json`(트랜스크립트가 켜진 이전 연결에서 남겨진)은 `config --disconnect`가 사용하는 것과 동일한 규칙에 의해 제거되고, 출력에는 이 머신에서 FailproofAI Cloud를 통한 Jev가 꺼진 상태로 유지된다고 표시됩니다. 자체 Jev 엔드포인트에 대한 `jev.json`과 꺼놓은(`--mode off`) FailproofAI Cloud `jev.json`은 그대로 유지됩니다.

<Warning>
연결은 기존 `~/.failproofai/jev.json`을 **절대 덮어쓰지 않습니다**. 이미 자체 Jev 엔드포인트를 사용하고 있다면 계속 사용되며, 출력에는 파일이 설정된 대로 유지되었다고 표시됩니다. 해당 파일이 Jev를 꺼놓은 경우(거부되었거나 꺼진 경우)에는 그 이유와 수정 방법도 표시됩니다. 해당 머신을 FailproofAI Cloud로 전환하려면 `failproofai jev setup --provider failproofai`를 실행하세요.
</Warning>

## 모드를 설정하는 주체

FailproofAI Cloud에 연결된 머신에서는 **FailproofAI Cloud가 Jev 모드를 설정합니다**. 머신의 어떤 것도 모드를 설정하지 않습니다:

- Jev(또는 정규식 + Jev) 정책이 머신에 배포된 동안은 `enforce`: 해당 정책이 대상으로 하는 에이전트의 모든 검사된 도구 호출이 FailproofAI Cloud로 전송되고, FailproofAI Cloud는 해당 검사와 함께 설치된 팩의 검사를 함께 요청합니다. Cloud Jev 정책이 대상으로 하지 않는 에이전트의 호출이고 자체 팩 검사도 없으면 전혀 전송되지 않습니다. `enforce` 모드에서는 Jev 자체의 deny 검사가 정규식 판정을 검토하는 것과 함께 호출을 차단합니다.
- 배포된 정책이 없을 때는 `off`: `jev.json`이 무엇을 나타내든 Jev가 전혀 없습니다.

Jev 정책이 작동하기 전에 시험해보려면 효과를 **observe**로 배포하세요. 검사는 여전히 요청되고 수행했을 내용은 정책 페이지에 **would-have**로 기록되지만, 호출을 차단하거나 해제하지 않습니다. `failproofai jev setup --mode`와 대시보드의 **Settings → Jev** 스위치는 모드가 FailproofAI Cloud에 의해 관리된다고 표시하며 아무것도 변경하지 않습니다. `jev.json`은 다른 프로바이더를 지정하더라도 Cloud의 검사에 사용되지 않습니다. `failproofai config --disconnect`는 Jev를 머신 자체의 `jev.json`으로 돌려줍니다.

`failproofai jev status`는 `Jev checks run on FailproofAI Cloud (mode: enforce)`라고 표시합니다. 또한 각 `both` 정책을 검토하는 검사의 이름도 나열합니다. 플릿 페이지에는 모드가 있는 머신이 요청할 수 없는 이유가 표시됩니다:

- `transcripts_disabled`: 머신이 `--no-transcripts`로 연결되어 Jev가 켜지지 않습니다.
- `jev_unconfigured`: 머신의 키에 `jev:evaluate`가 없습니다.
- `jev_rate_limited`: FailproofAI Cloud가 조직의 Jev 속도 제한으로 인해 머신의 일부 호출을 거부했으며, 해당 호출은 정규식 정책만으로 결정되었습니다.
- `jev_unavailable`: 연속으로 여러 번의 호출이 실패하여 머신이 한 번에 1분씩 FailproofAI Cloud의 Jev를 건너뜁니다. 자동으로 재시도합니다.

FailproofAI Cloud가 5초 이내에 응답하지 않으면 Jev 중단 시와 마찬가지로 정규식 정책만 결정합니다. 3번 연속 실패 후 머신은 한 번에 1분씩 요청을 중단하므로 Cloud 중단이 모든 도구 호출을 느리게 만들지 않습니다.

세션 일시 중지(`failproofai config --pause`)는 Cloud 관리 정책을 중단하지 않는 것처럼 FailproofAI Cloud의 Jev 검사를 중단하지 않습니다. 머신에 설치된 팩의 Jev 검사는 일시 중지됩니다.

## 동작 확인하기

```bash
failproofai jev status
failproofai jev test
```

`status`는 프로바이더를 **FailproofAI Cloud**로, 머신이 연결된 Cloud 호스트, 모드, 키 소스를 키가 아닌 **FailproofAI Cloud connection**으로 표시합니다. FailproofAI Cloud `jev.json`이 있지만 Jev를 실행할 수 없을 때 이유를 설명합니다:

| `status` 표시 | `status --json` | 의미 |
| --- | --- | --- |
| **off — no Jev key is stored for this machine's FailproofAI Cloud connection** | `key-lacks-jev` | 머신이 연결되어 있지만 Jev 키가 저장되지 않았습니다: 키에 `jev:evaluate`가 없거나 연결 시 확인하지 못했습니다. `FAILPROOFAI_CLOUD_TOKEN`에 키를 넣어 `failproofai config`를 다시 실행하세요. 권한이 없으면 **machine** 키를 사용하세요. |
| **off — this machine is not connected to FailproofAI Cloud** | `not-connected` | 이 머신에 Jev 키가 속할 FailproofAI Cloud 연결이 없습니다. |

`failproofai config --disconnect` 이후에는 FailproofAI Cloud `jev.json`이 더 이상 없으므로(꺼진 경우는 유지) `status`는 단순히 Jev를 꺼진 것으로 보고합니다. `status --json`은 설정이 없거나 거부된 경우에도 동일한 사실(`provider: "failproofai"`, `keySource: "cloud"`, `cloudConnected`, `keyCarriesJev`)을 전달합니다. `permissions`는 항상 `jev.json`의 권한이며, `credentials.json`에 대한 거부는 `credentialsPermissions`를 추가하고, 하나의 명령으로 수정 가능한 경우 `fix`도 추가됩니다. `test`는 하나의 라이브 요청을 전송하고 지연 시간과 응답한 Jev 버전을 보고합니다. 응답이 훅 타임아웃 후에 도착하거나(훅이 `timeout`을 기록함) 검사 질문에 잘못 답변한 경우 1로 종료하고 제목에 표시합니다.

대시보드의 **Settings → Jev** 패널은 네트워크 호출 없이 머신 자체 파일에서 읽어 **FailproofAI Cloud connection**: 머신이 보고하는 조직과 키에 Jev가 포함되어 있는지 여부를 표시합니다.

## 실제 호출 확인하기

연결된 에이전트에서 새 세션을 시작합니다. `README.md`에서 파일 읽기 도구를 사용하여 제목을 보고하도록 요청합니다. 세션에 해당 도구 호출이 포함되어 있는지 확인한 다음 `failproofai jev status`를 다시 실행합니다. 최근 평가된 호출 수가 증가해야 합니다. [로컬 대시보드](/ko/reference/local-dashboard#review-policy-activity)의 **Policies → Activity**를 열어 해당 호출의 Jev 판정과 모드를 검사합니다. Cloud에서는 조직의 **Policies** 페이지에 전달된 활동에 대한 Jev 결과가 표시됩니다. observe 모드에서는 판정이 **would-have**로 기록되고 정책 결과가 여전히 호출을 결정합니다. 해제는 검토 가능한 정책이 일치하고 Jev가 명명된 검사를 해제한 경우에만 나타납니다.

## 정책 페이지에 도달하는 내용

머신은 이미 훅 활동을 FailproofAI Cloud(`events:add`)로 전송합니다. Jev가 켜진 상태에서 각 게이트된 호출의 레코드는 어떤 평가기가 실행되었는지, Jev가 무엇을 결정했는지, 어떤 정책을 해제했는지, 언제 폴백했는지, 지연 시간, 응답한 모델을 포함합니다. 명령이나 프롬프트가 아닌 결정, 코드, 이름만 포함됩니다. 조직의 **Policies** 페이지에서:

- Jev 자체 판정이 결정한 호출(enforce 모드)은 **Jev**에 귀속되며, 결정 검사가 팩에서 온 경우 레코드에 해당 팩과 버전도 명시됩니다.
- observe 모드에서는 Jev의 deny 또는 경고가 관찰 중인 롤아웃 옆에 **would-have**로 표시됩니다.
- Jev가 해제하거나 observe 모드에서 해제했을 정책은 정책별로 집계됩니다.
- Jev가 참여한 결정(차단, 경고, 해제 또는 observe 모드의 would-have)에는 요청된 각 검사와 해당 검사의 결론이 나열됩니다: 판정, 이유(`not-detected`, `exempt`, `fired`, `op-requested`, …), 증거 `p`, `exempt` 답변 및 각 프로브의 답변. 관찰(observe)로 배포된 정책의 검사도 나열되며 watched로 표시되고 절대 차단하지 않습니다. Jev는 산문이 아닌 확률로 응답하므로 자유 텍스트 이유가 없습니다. 단순 허용은 집계 수로 합산되며 이 목록을 포함하지 않습니다.

## Jev가 응답할 수 없을 때

다음 모든 경우는 해당 호출에 대한 정책 결과로 폴백되고 이유와 함께 기록됩니다:

| 이유 | 원인 |
| --- | --- |
| `out-of-credits` | 조직이 플랜 허용량을 사용했습니다. |
| `http-401`, `http-403` | 키가 취소되었거나 `jev:evaluate`가 없습니다. 해당 권한이 있는 키로 다시 연결하세요. |
| `http-429` | FailproofAI Cloud가 조직의 Jev를 속도 제한하고 있습니다. 요청한 대기 시간(`Retry-After`, 최대 60초)이 끝날 때까지 머신은 아무것도 전송하지 않으며 모든 호출이 즉시 폴백됩니다. 그런 식으로 보류된 호출은 `http-429`로 기록되거나, 머신 자체 속도 제한이 먼저 보류하면 `rate-limited`로 기록됩니다. |
| `http-429` (일일 제한) | 조직이 일일 Jev 호출을 사용했습니다: FailproofAI Cloud 운영자가 다른 한도를 설정하지 않는 한 **UTC 일 기준 10,000회**. 00:00 UTC에 카운트가 초기화될 때까지 모든 호출이 폴백됩니다. 머신은 여전히 분당 최대 한 번씩 다시 요청하므로 1분 이내에 초기화를 감지합니다. `failproofai jev test`는 "Daily Jev limit for this org reached; resets at 00:00 UTC."라고 표시합니다. |
| `http-422` | Jev가 이 호출의 요청을 거부했습니다. 일반적으로 도구 호출에 Jev의 토큰 예산을 초과하는 밀집 텍스트(base64, hex, 축소 코드)가 포함된 경우입니다. 해당 호출은 매번 폴백됩니다. 중단이 아닙니다. |
| `http-502` | Jev를 현재 사용할 수 없습니다. |
| `http-503` | 이 Cloud가 조직의 Jev를 제공할 수 없습니다: 모델 게이트웨이 없음, 아직 프로비저닝되지 않은 조직, 또는 게이트웨이 다운. 관리자에게 문의하세요. 훅은 분당 최대 한 번씩 다시 요청합니다. |
| `http-404` | 이 FailproofAI Cloud는 아직 Jev를 제공하지 않습니다. |
| `timeout` | `timeoutMs` 이내에 응답 없음(기본값 3000). FailproofAI Cloud가 머신의 Jev 모드를 설정하는 동안 대기 시간은 5000ms이며 `jev.json`의 `timeoutMs`는 사용되지 않습니다. |
| `model-mismatch` | 1.13 이외의 Jev 버전이 응답했습니다. |

## 키의 위치와 전송 대상

- 키는 `~/.failproofai/credentials.json`(`0600`, 소유자 전용 디렉토리)에 한 번 저장되며, 다른 FailproofAI Cloud 자격 증명과 함께 있습니다. `jev.json`은 이 경로의 키를 보유하지 않습니다. 거기에 키를 작성하면 설정이 유효하지 않아집니다.
- `credentials.json`에 소유자 이외의 누군가(그룹 또는 기타, 읽기 또는 쓰기)에 대한 권한이 있거나, 디렉토리를 소유자 이외의 누군가가 **쓸 수** 있으면 **거부**되어 읽히지 않으며 수정할 때까지 Jev가 꺼집니다: 파일에 `chmod 600`, 디렉토리에 `chmod 700` (또는 파일을 `0600`으로 다시 작성하고 디렉토리를 소유자 전용으로 만드는 재연결). 다른 사람이 읽기만 할 수 있는 디렉토리는 괜찮습니다. 쓸 수 있는 디렉토리는 파일 교체를 허용합니다.
- 키는 함께 온 연결이 머신에 있는 동안에만 유효합니다: 동일한 파일에 동일한 키를 사용하는 동일한 FailproofAI Cloud의 정책 또는 보고 자격 증명. 연결 없이 남겨진 Jev 키는 무시되고 Jev가 꺼집니다. 이는 구버전 failproofai의 `config --disconnect`가 Jev 키를 제거하지 않고 남겨두거나(제거 방법을 모름), 구버전 failproofai의 `config --token`이 다른 키로 연결할 때 발생할 수 있습니다. FailproofAI Cloud에서는 다른 조직에 속한 키일 수 있습니다. Jev를 다시 켜려면 **machine** 키로 다시 연결하세요.
- 키는 검증된 Cloud 오리진에만 전송됩니다. 다른 곳을 가리키는 `jev.json`은 거부됩니다.
- **머신의 에이전트가 키를 읽을 수 있습니다.** `credentials.json`은 소유자 전용이며, 에이전트는 해당 소유자로 실행됩니다. failproofai 자체 파일 읽기는 의도적으로 허용됩니다(`block-failproofai-commands`로 변경만 차단). 따라서 에이전트와 이 파일 사이에 있는 것은 `block-read-outside-cwd`— *검토 가능한* 정책 — 뿐이며, 홈 디렉토리에서 시작된 세션에서는 아무것도 없습니다. `jev:evaluate`가 있는 키는 사용되는 곳에서 조직의 Jev 허용량(일일 한도까지)을 소비하므로, 머신 키를 다른 지출 자격 증명처럼 취급하세요. 에이전트가 키를 읽었을 가능성이 있다면 Keys 페이지에서 비활성화하고 새 키로 다시 연결하세요.
- 이것은 전역 파일만이 결정합니다. 저장소는 Cloud Jev를 켜거나, 다른 곳을 가리키거나, 키를 제공할 수 없으며, `FAILPROOFAI_JEV_API_KEY`는 이 경로에서 무시됩니다.
- Jev가 평가하는 각 호출에 대해 하나의 요청이 FailproofAI Cloud로 전송되며, [자체 키 페이지](/ko/reference/jev-providers#what-leaves-the-machine)에 나열된 내용(시크릿 편집됨)을 포함합니다. FailproofAI Cloud는 이를 TypeSafe로 전달하며 기록하거나 보관하지 않습니다.

## 비활성화하기

연결된 머신에서 FailproofAI Cloud가 해당 머신에 Jev 정책을 배포하지 않으면 Jev가 꺼집니다: 거기서 Jev 정책을 제거하거나 보관하세요.

| 명령 | 결과 |
| --- | --- |
| FailproofAI Cloud에서 머신의 Jev 정책 제거 | Cloud 모드가 다음 폴링(약 30초)에서 `off`가 됩니다: `jev.json`이 무엇을 나타내든 Jev가 전혀 없습니다. |
| `failproofai config --disconnect` | 머신 연결을 끊습니다: 키가 제거되고, `jev.json`이 FailproofAI Cloud를 지정하고 꺼지지 않은 경우 함께 제거됩니다. 자체 엔드포인트의 `jev.json`은 유지됩니다. |

다음 도구 호출부터 훅은 이전과 정확히 동일하게 정규식 정책을 실행합니다.
