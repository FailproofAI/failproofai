`failproofai`를 인수 없이 실행하면 `http://localhost:8020`에서 번들된 대시보드가 시작됩니다. 대시보드는 로컬 에이전트 기록, 정책 구성, 감사 결과, 훅 활동을 머신에서 직접 읽어옵니다.

설정이 완료되지 않은 머신에서는 명령을 실행하면 대시보드를 열기 전에 최초 실행 설정이 진행됩니다. 이는 대화형 터미널에서만 수행됩니다. 파이프 연결이나 CI 환경에서는 한 줄짜리 힌트를 출력하고 대시보드를 바로 엽니다. 응답할 수 없는 마법사가 입력한 명령을 절대 차단해서는 안 되기 때문입니다. `FAILPROOFAI_NO_FIRST_RUN=1`을 설정하면 리디렉션을 건너뛰고 대시보드로 바로 이동합니다.

로컬 대시보드는 Failproof AI Cloud와 별개입니다. Cloud 계정 없이도 작동하며, 이벤트가 조직에 전달되었음을 증명하지 않습니다. 설정이 완료된 머신에서는 `failproofaid` 데몬이 내린 결정이 표시됩니다. 이 데몬이 유일한 평가자입니다. 설정이 완료되지 않은 머신에서는 훅이 프로세스 내부에서 평가됩니다.

## 대시보드 영역

| 영역 | 수행 가능한 작업 |
| --- | --- |
| Policies → Activity | 로컬 allow, instruct, deny 결정을 검사하고, 결정, 이벤트, CLI, 소스, 정책, 세션별로 필터링합니다. |
| Policies → Configure | 설치된 팩에서 정책을 활성화하고, 지원되는 매개변수를 편집하며, 발견된 커스텀 및 컨벤션 정책을 토글하고, 대상 하네스를 선택합니다. |
| Projects | 지원되는 에이전트 기록에서 발견된 프로젝트를 탐색하고 가장 최근 세션을 비교합니다. |
| Project sessions | 로컬 트랜스크립트 하나를 열고, 원시 순서 항목과 서브에이전트를 검토하며, 다운로드하고, 정책 활동과 연관 지어 분석합니다. |
| Audit | 마지막 오프라인 스캔, 위험 패턴, 강점, 영향받은 프로젝트, 추천 빌트인 정책을 검토합니다. |
| Settings | 데몬/플랫폼이 지원하는 경우 예약된 로컬 스캔과 이메일 감사 보고서를 구성합니다. |

## 정책 활동 검토

<Tabs>
  <Tab title="대시보드">
    1. **Policies → Activity**를 열고 결정 및 소스 필터를 설정합니다.
    2. 이벤트, 하네스, 정책 이름, 세션별로 범위를 좁힙니다.
    3. 행에는 결정, 이벤트, 하네스, 도구, 정책, 권한 모드, 지속 시간이 표시됩니다. 행을 펼치면 전체 이유, 매칭된 모든 정책, 결정 소스, 클라우드 배포, 세션의 작업 디렉터리 및 트랜스크립트 경로를 확인할 수 있습니다. 도구 이름은 행에 표시되지만 필터 항목은 아닙니다.
    4. 세션 링크를 따라가면 트랜스크립트 컨텍스트에서 해당 결정을 확인할 수 있습니다.

    거부된 것처럼 보이는 행도 차단 판정을 소비하지 않는 하네스/이벤트 쌍에서는 관찰 용도로만 사용될 수 있습니다. 상세 보기에서는 검증된 적용 가능성을 명시합니다.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    로컬 활동은 `~/.failproofai/hook-activity` 아래에 저장됩니다. 이 파일을 직접 편집하는 대신 대시보드를 사용하세요.
  </Tab>
</Tabs>

## 로컬에서 정책 구성

<Tabs>
  <Tab title="대시보드">
    1. **Policies → Configure**를 열고 하네스와 구성 범위를 선택합니다. 이 탭은 `http://localhost:8020/policies?tab=policies`에서 직접 접근할 수 있습니다.
    2. 설치된 팩에서 정책을 활성화하거나, 발견된 커스텀 또는 컨벤션 정책을 활성화합니다.
    3. 매개변수가 있는 정책의 경우 구성 컨트롤을 열고 지원되는 값을 저장합니다.
    4. Activity로 돌아가 매칭 및 비매칭 작업을 실행합니다.

    팩이 설치되기 전까지 목록은 비어 있습니다. 이 빌드는 자체 정책을 컴파일하지 않으므로 먼저 `failproofai policies add FailproofAI/policies`를 실행하세요. 컨벤션 정책은 해당 프로젝트 또는 사용자 소스를 표시합니다. 명시적인 커스텀 경로 변경 시 선택한 경로가 기록되도록 CLI 구성을 다시 실행해야 할 수 있습니다.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies show FailproofAI/policies
    failproofai policies add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```

    `policies show <owner>/<repo>`는 팩을 설치하기 전에 내용을 확인합니다. `--scope`는 `user`, `project`, `local` 중 하나를 사용합니다. `local`은 Claude Code에서만 지원되며, Hermes와 OpenClaw는 `user`만 지원합니다.
  </Tab>
</Tabs>

## 프로젝트 및 세션 탐색

Projects 페이지는 지원되는 로컬 기록 저장소를 통합하여 보여줍니다. 프로젝트를 선택하면 세션 목록이 표시되고, 세션을 열면 원시 로그 뷰어, 서브에이전트 세그먼트, 다운로드 기능, 세션 범위의 정책 활동을 확인할 수 있습니다.

프로젝트나 세션이 누락된 경우, 하네스가 기본 기록 위치를 사용하는지 확인하거나 `failproofai harness add-path <harness> [<label>=]<path>`로 추가 루트를 등록하세요.

## 오프라인 감사 예약

<Tabs>
  <Tab title="대시보드">
    **Settings**를 열고 예약 스캔을 활성화한 후 지원되는 간격을 선택하고, 사용 가능한 경우 보고서 전달을 구성합니다. 페이지에는 다음 실행 시간, 마지막 실행 시간, 종료 코드, 플랫폼에서 백그라운드 데몬 지원 여부가 표시됩니다.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    일 수를 변경하여 1~90일 범위의 다른 간격을 설정할 수 있습니다. `failproofai audit --no-schedule`로 반복 스캔을 비활성화하면 타이머가 중지되고 로그인 상태는 유지됩니다. 즉각적인 대화형 스캔을 실행하려면 `failproofai audit`을 사용하세요.

    예약 설정 시 결과가 이메일로 전송되므로 처음에는 로그인이 필요합니다. `--email <address>`로 이메일 주소를 미리 제공하면 로그인 프롬프트를 건너뜁니다.
  </Tab>
</Tabs>

<Note>
  분석 결과와 발견 사항은 이 머신에 저장됩니다. `FAILPROOFAI_TELEMETRY_DISABLED=1`을 설정하지 않으면 기본적으로 익명 CLI 텔레메트리가 전송됩니다. 예약된 스캔은 머신 메타데이터도 전송하며, 옵트인 후 제한된 발견 사항 요약을 전송할 수 있습니다.
</Note>

<Warning>
  로컬 대시보드는 로컬 에이전트 기록에서 프롬프트, 도구 입력, 파일 내용, 터미널 출력을 표시할 수 있습니다. 신뢰할 수 있는 인터페이스에만 바인딩하고, 검토가 완료되면 프로세스를 종료하세요.
</Warning>
