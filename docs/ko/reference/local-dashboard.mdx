`failproofai`를 인수 없이 실행하면 `http://localhost:8020`에서 번들 대시보드가 시작됩니다. 이 대시보드는 로컬 에이전트 기록, 정책 구성, 감사 결과, 훅 활동을 머신에서 직접 읽어옵니다.

로컬 대시보드는 Failproof AI Cloud와 별개입니다. Cloud 계정 없이도 작동하며, 이벤트가 조직에 전달되었음을 보장하지는 않습니다.

## 대시보드 영역

| 영역 | 수행할 수 있는 작업 |
| --- | --- |
| Policies → Activity | 로컬 allow, instruct, deny 결정을 검사하고, 결정·이벤트·CLI·도구·소스·정책·세션별로 필터링합니다. |
| Policies → Configure | 내장 정책을 활성화하고, 지원 파라미터를 편집하며, 검색된 커스텀 정책을 토글하고, 대상 하네스를 선택합니다. |
| Projects | 지원되는 에이전트 기록 전반에 걸쳐 검색된 프로젝트를 탐색하고 가장 최근 세션을 비교합니다. |
| Project sessions | 로컬 트랜스크립트를 열어 정렬된 원시 항목과 서브에이전트를 검토하고, 다운로드하거나 정책 활동과 연관 지을 수 있습니다. |
| Audit | 마지막 오프라인 스캔, 위험 패턴, 강점, 영향받은 프로젝트, 제안된 내장 정책을 검토합니다. |
| Settings | 데몬/플랫폼에서 지원하는 경우 예약된 로컬 스캔과 이메일 감사 보고서를 구성합니다. |

## 정책 활동 검토

<Tabs>
  <Tab title="대시보드">
    1. **Policies → Activity**를 열고 결정 및 소스 필터를 설정합니다.
    2. 이벤트, 하네스, 도구 또는 정책 이름으로 범위를 좁힙니다.
    3. 행을 확장하여 이유, 매칭된 정책, 소스, 실행 모드, 소요 시간을 확인합니다.
    4. 세션 링크를 따라가 트랜스크립트 맥락 안에서 해당 결정의 위치를 파악합니다.

    거부된 것처럼 보이는 행도 차단 판정을 사용하지 않는 하네스/이벤트 쌍에서는 관찰 목적으로만 기록될 수 있습니다. 상세 보기에서는 검증된 적용 가능 여부를 명시합니다.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    로컬 활동은 `~/.failproofai/hook-activity` 아래에 저장됩니다. 이 파일을 직접 편집하는 대신 대시보드를 사용하세요.
  </Tab>
</Tabs>

## 로컬에서 정책 구성

<Tabs>
  <Tab title="대시보드">
    1. **Policies → Configure**를 열고 하네스 및 구성 범위를 선택합니다.
    2. 내장 정책이나 검색된 커스텀 정책을 활성화합니다.
    3. 파라미터화된 내장 정책의 경우 구성 컨트롤을 열고 지원하는 값을 저장합니다.
    4. Activity로 돌아가 일치하는 동작과 일치하지 않는 동작을 실행합니다.

    관례(Convention) 정책은 프로젝트 또는 사용자 소스를 표시합니다. 명시적인 커스텀 경로 변경 사항은 선택한 경로가 기록되도록 CLI 구성을 다시 실행해야 할 수 있습니다.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```
  </Tab>
</Tabs>

## 프로젝트 및 세션 탐색

Projects 페이지는 지원되는 로컬 기록 저장소를 통합합니다. 프로젝트를 선택하면 해당 세션 목록이 표시되며, 세션을 열면 원시 로그 뷰어, 서브에이전트 세그먼트, 다운로드 기능, 세션 범위의 정책 활동을 확인할 수 있습니다.

프로젝트나 세션이 표시되지 않는 경우, 하네스가 기본 기록 위치를 사용하고 있는지 확인하거나 `failproofai harness add-path`를 사용하여 추가 루트를 등록하세요.

## 오프라인 감사 예약

<Tabs>
  <Tab title="대시보드">
    **Settings**를 열고 예약 스캔을 활성화한 뒤, 지원되는 간격을 선택하고 가능한 경우 보고서 전송을 구성합니다. 이 페이지에는 다음 실행 시간, 마지막 실행 시간, 종료 코드, 백그라운드 데몬이 해당 플랫폼에서 지원되는지 여부가 표시됩니다.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    일수를 변경하여 1~90일 범위에서 다른 간격을 설정할 수 있습니다. `failproofai audit --no-schedule`로 반복 스캔을 비활성화하고, `failproofai audit`을 실행하면 즉시 대화형 스캔이 시작됩니다.
  </Tab>
</Tabs>

<Warning>
  로컬 대시보드는 로컬 에이전트 기록에서 프롬프트, 도구 입력, 파일 내용, 터미널 출력을 표시할 수 있습니다. 신뢰할 수 있는 인터페이스에만 바인딩하고, 검토가 완료되면 프로세스를 중지하세요.
</Warning>
