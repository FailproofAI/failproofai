에이전트가 실행되는 환경에 가장 적합한 통합 방법을 선택하세요.

이 섹션에서는 서로 다른 역할을 하는 두 가지 커맨드라인 도구를 다룹니다. `failproofai`는 에이전트가 실행되는 머신에서 동작하며 에이전트 루프 내부에서 정책을 적용하고, `fp`는 Failproof AI Cloud와 통신하여 해당 루프의 실행 결과를 조회합니다. 머신 설정은 Linux 및 macOS에서만 지원되며, `failproofai config`는 그 외 환경에서는 실행을 거부하고 아무것도 기록하지 않습니다. 이는 설정이 불완전한 상태로 머신을 방치하지 않기 위함입니다.

자동 생성된 HTTP API 페이지는 공개 `/v1` 엔드포인트를 다룹니다. 직접 작성된 페이지는 여러 엔드포인트에 걸친 워크플로우나 해당 공개 엔드포인트 외부의 관리 인터페이스를 사용하는 경우를 설명합니다.

## 에이전트 연결 및 데이터 검증

<Tabs>
  <Tab title="대시보드">
    1. **Administration → Keys**를 열고, `events:add` 및 `policies:pull` 권한이 부여된 키를 생성한 후 시크릿을 복사합니다.
    2. 위의 해당 페이지에서 통합을 설정합니다.
    3. **Observe → Events**를 열어 이벤트가 수신되는지 확인한 다음, **Observe → Sessions**에서 이벤트들이 완전한 실행으로 묶이는지 확인합니다.
    4. 통합의 환경으로 필터링하고, 감사에 필요한 모델, 도구, 오류, 정책 필드가 포함된 세션 하나를 검사합니다.

    키 드로어부터 시작하세요. 선택한 권한에 따라 해당 머신이 이벤트를 전송하고 Cloud 관리 정책을 수신할 수 있는지 여부가 결정됩니다.

    ![이벤트 수집 및 정책 전달 권한을 부여하는 데 사용되는 새 API 키 드로어.](/images/dashboard/key-create.png)

    통합을 연결한 후 Sessions 목록을 사용하여 해당 이벤트가 예상 환경에서 완전한 실행으로 그룹화되는지 확인합니다.

    ![새로 연결된 통합이 완전한 에이전트 실행을 보고하는지 확인하는 데 사용되는 Sessions 목록.](/images/dashboard/sessions-list.png)

    통합이 완료된 것으로 간주하기 전에 세션 중 하나를 열어 확인하세요. 트레이스에는 감사에 필요한 모델, 도구, 오류, 정책 증거가 포함되어 있어야 합니다.
  </Tab>
  <Tab title="CLI">
    머신 키를 생성하고, 이 머신을 설정하여 연결한 다음, 정책을 선택하고 첫 번째 세션을 검증합니다.

    ```bash
    fp keys create agent-production \
      --add events:add \
      --add policies:pull

    failproofai config --token <machine-key>

    failproofai policies add FailproofAI/policies

    failproofai flush --wait
    fp sessions --since 1h
    fp events --since 1h --limit 20
    ```

    두 검증 명령 모두 환경을 기준으로 필터링하지 않습니다. 새로 설정된 머신은 모든 이벤트에 `local`을 태그로 붙이기 때문입니다. `collector.environment`를 설정한 후에만 `--env production`을 추가하세요 — [환경 레이블 변경](/ko/reference/events-and-configuration#change-an-environment-label)을 참조하세요.

    토큰을 전달하는 것이 연결 요청이므로, `failproofai config --token <machine-key>` 명령 하나로 동일한 작업을 수행합니다. 가능하면 환경 변수를 사용하는 것이 좋습니다. 인수는 해당 머신의 모든 사용자가 `ps`로 확인할 수 있으며, 셸 히스토리와 CI 로그에도 남습니다.

    정책 단계는 선택 사항이 아닙니다. `failproofai config`는 데몬을 설치하고 지원되는 모든 에이전트 CLI를 연결하지만, 의도적으로 정책을 선택하지 않습니다. 따라서 새로 설정된 머신은 팩을 추가하기 전까지 아무것도 적용하지 않습니다.

    다른 도구가 결과를 사용할 경우에는 `fp --json sessions ...`를 사용하세요. `--json`, `--org`, `--base-url`과 같은 전역 플래그는 반드시 명령 앞에 위치해야 합니다.

    로컬 명령에 대해서는 [Failproof AI CLI 참조](/ko/reference/failproof-cli)를, `fp` 명령에 대해서는 [Failproof Cloud CLI 참조](/ko/reference/cloud-cli#cli-commands)를 참조하세요.
  </Tab>
</Tabs>
