생성된 [HTTP API 참조](/ko/reference/http-api)는 공개 `/v1` 인터페이스를 다룹니다. 수동으로 작성된 페이지는 여러 엔드포인트에 걸친 워크플로우나 해당 공개 인터페이스 외부의 관리 인터페이스를 사용하는 경우를 설명합니다.

## 에이전트 연결 및 데이터 확인

<Tabs>
  <Tab title="대시보드">
    1. **Administration → Keys**를 열고, `events:add` 및 `policies:pull` 권한으로 키를 생성한 후 시크릿을 복사합니다.
    2. 위의 해당 페이지를 참조하여 통합을 구성합니다.
    3. **Observe → Events**를 열어 이벤트가 수신되는지 확인한 후, **Observe → Sessions**에서 완전한 실행으로 그룹화되는지 확인합니다.
    4. 통합의 환경으로 필터링하고 세션 하나를 열어 감사에 필요한 모델, 도구, 오류 및 정책 필드를 검토합니다.

    키 드로어부터 시작하세요. 선택한 권한에 따라 머신이 이벤트를 전송하고 Cloud 관리형 정책을 수신할 수 있는지 결정됩니다.

    ![이벤트 수집 및 정책 전달 권한을 부여하는 데 사용되는 새 API 키 드로어.](/images/dashboard/key-create.png)

    통합을 연결한 후, Sessions 목록을 사용하여 해당 이벤트가 예상 환경에서 완전한 실행으로 그룹화되고 있는지 확인하세요.

    ![새로 연결된 통합이 완전한 에이전트 실행을 보고하는지 확인하는 데 사용되는 Sessions 목록.](/images/dashboard/sessions-list.png)

    통합이 완료된 것으로 간주하기 전에 이러한 세션 중 하나를 여세요. 트레이스에는 감사에 필요한 모델, 도구, 오류 및 정책 증거가 포함되어 있어야 합니다.
  </Tab>
  <Tab title="CLI">
    머신 키를 생성하고, Failproof 데몬을 연결한 후 첫 번째 세션을 확인합니다.

    ```bash
    fp keys create agent-production \
      --add events:add \
      --add policies:pull

    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>

    failproofai flush --wait
    fp sessions --since 1h --env production
    fp events --since 1h --env production --limit 20
    ```

    다른 도구가 결과를 처리해야 할 경우 `fp --json sessions ...`를 사용하세요. `--json`, `--org`, `--base-url`과 같은 전역 플래그는 명령어 앞에 위치해야 합니다.

    로컬 명령어는 [Failproof AI CLI 참조](/ko/reference/failproof-cli)를, `fp` 명령어는 [Failproof Cloud CLI 참조](/ko/reference/cloud-cli#cli-commands)를 참조하세요.
  </Tab>
</Tabs>
