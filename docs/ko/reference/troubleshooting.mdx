다음 명령으로 시작하세요:

```bash
failproofai config --status
failproofai policies
```

## 에이전트가 연결되지 않음

설정을 다시 실행하세요:

```bash
failproofai config
```

설정은 Linux 및 macOS를 지원합니다. 서비스를 설치할 때 관리자 권한이 한 번 필요하지만, sudo 비밀번호를 별도로 묻지 않습니다.

[Harnesses](/ko/reference/harnesses)에서 하네스 경로와 스코프를 확인하세요.

## 세션이 누락됨

```bash
failproofai flush --wait
failproofai backfill --since 30d --dry-run
failproofai harness list
```

이전 기록을 다시 전송하려면 `--dry-run`을 제거하세요. 다음 명령으로 트랜스크립트 위치를 추가할 수 있습니다:

```bash
failproofai harness add-path <harness> [label=]<path>
```

동일한 프로젝트의 복사본이 두 위치에 있을 경우 레이블을 사용하세요.

## 보호된 모든 작업이 거부됨

설정된 머신에서 `failproofaid`가 유일한 평가자입니다. 응답할 수 없으면 보호된 작업은 차단(fail closed) 방식으로 실패합니다.

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

서비스를 복구하거나 재설치하려면 `failproofai config`를 실행하세요.

## 특정 팩이 거부됨

`failproofai policies`는 로드할 수 없는 팩의 이름을 표시합니다. 선택된 팩이 로드에 실패하면 사라지지 않고 차단(fail closed) 상태가 됩니다.

일반적인 원인:

- 설치 후 아티팩트가 변경되었습니다.
- 매니페스트와 번들된 정책이 일치하지 않습니다.
- 파일이 없거나 임포트할 수 없습니다.
- 팩이 지원되지 않는 이벤트, 도구 또는 정책 형식을 사용합니다.

팩을 제거하거나 수정된 릴리스를 설치하세요:

```bash
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

## 클라우드 연결이 끊김

키는 환경 변수로 설정하는 것을 권장합니다:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
failproofai config --status
```

머신은 정책 가져오기와 활동 전송을 독립적으로 수행할 수 있습니다. 상태 명령은 두 가지를 모두 보고합니다.

## 정책이 차단하지 않음

세 가지를 확인하세요:

1. 정책이 활성화되어 있는지: `failproofai policies`
2. 이벤트와 도구가 해당 작업과 일치하는지
3. 해당 하네스가 이벤트를 적용할 수 있는지

도구 호출 deny는 지원되는 12개의 모든 하네스에서 검증됩니다. 다른 이벤트는 하네스마다 다를 수 있습니다. [적용 기능](/ko/reference/harnesses#enforcement-capability)을 참조하세요.

## 다운로드가 차단됨

- `FAILPROOFAI_NO_DOWNLOAD=1`은 네트워크 다운로드를 거부합니다.
- `FAILPROOFAI_DAEMON_BASE_URL`은 서비스 다운로드를 미러로 연결합니다.
- `FAILPROOFAI_PACK_BASE_URL`은 팩 다운로드를 미러로 연결합니다.

다운로드가 비활성화된 경우에도 설치된 팩은 계속 적용됩니다.
