평가는 에이전트 세션에 일관된 판단을 적용합니다. 감사 시에만 조사하는 것이 아니라 지속적으로 측정해야 하는 신호에 활용하세요.

평가자는 완료된 세션을 수신합니다. 완료란 세션이 종료 이벤트를 발생시켰거나, 평가자의 `inactivity_timeout_secs`보다 오랫동안 이벤트 발생이 중단된 경우를 의미합니다. 실행 중인 세션은 점수화되지 않습니다.

<Note>
  자동 평가는 배포 전체에 적용되며, 운영자가 `EVALUATOR_ENDPOINT`를 설정하기 전까지는 비활성 상태입니다. 설정 전에는 이 화면이 비어 있고, `fp evals`는 아무것도 반환하지 않으며, `fp sessions`는 모든 행의 상태를 공백으로 표시합니다. 이는 대부분 평가자가 구성되지 않은 것을 의미하며, 점수가 나쁜 항목이 없다는 뜻이 아닙니다. [Evaluator SDK](/ko/reference/evaluator-sdk)를 참고하세요.
</Note>

## 평가 품질 검토

<Tabs>
  <Tab title="대시보드">
    1. **Observe → Evaluations**으로 이동합니다.
    2. 시리즈를 추가하고 에이전트, 환경, 평가 점수, 통계, 곡선을 선택합니다.
    3. 시리즈를 추가하여 환경, 에이전트, 점수 키를 비교합니다.
    4. 결과를 선택하여 해당 세션을 열거나 필터링된 뷰를 공유합니다. 지연 시간, 토큰, 비용 및 기타 수치 값은 **Observe → Metrics**를 사용하세요.

    ![평균 평가 점수와 시간 경과에 따른 추세를 보여주는 품질 대시보드.](/images/dashboard/dashboard-quality.png)

    드릴다운에서 세션을 열어 점수별 추론 내용을 확인하세요:

    ![전체 트레이스 옆에 평가 점수와 추론을 보여주는 세션 상세 뷰.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp list score_filters
    fp evals --agent-id checkout-agent --aggregate
    fp evals --aggregate --status error --since 7d
    fp evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3 --since 7d
    fp evals --scores-full --since 24h
    ```

    여기서 모든 명령에는 `evaluations:read` 권한이 필요합니다. `fp sessions`도 동일한 최신 평가 결과를 읽으므로 마찬가지입니다. 따라서 `events:read` 범위로 제한된 키는 트레이스는 볼 수 있지만 점수는 볼 수 없습니다.

    `fp list score_filters`부터 시작하세요. 이 명령은 현재 배포에서 실제로 생성되는 점수 키를 반환하므로, `--score` 필터를 추측이 아닌 검증 가능한 값으로 사용할 수 있습니다.

    `--score KEY:MIN..MAX`는 각 경계값이 선택 사항이며 반복 사용 가능하고, 모든 범위 조건이 함께 충족되어야 합니다: `helpfulness:0.5..0.8`, `tool_efficiency:..0.3`, `factuality:0.9..`. 잘못된 값은 요청 전에 거부되며 조용히 무시되지 않습니다. `--status`는 `done`, `error`, `timeout` 중 정확히 하나를 받습니다. `--scores-full`은 처음 몇 개와 `+N` 대신 모든 점수 쌍을 출력합니다. `--all`은 기본값 50인 `--limit`에서 중단됩니다.

    전역 옵션은 명령 앞에 오므로, 자동화 시에는 `fp --json evals --aggregate`와 같이 사용합니다.

    데몬은 변경하지 않는 한 모든 이벤트에 환경값 `local`을 스탬프하므로, 기본 설치에서는 `--env production`이 아무것도 매칭하지 않습니다. [환경 레이블 변경](/ko/reference/events-and-configuration#change-an-environment-label)을 참고하세요.
  </Tab>
</Tabs>

## 평가자가 주고받는 내용

| 메시지 | 필드 |
| --- | --- |
| `EvalRequest` (수신) | `schema_version` (현재 `"1"`), `session_id`, `agent_id`, `environment`, `started_at`, `ended_at`, `events` — 각 이벤트의 전체 페이로드를 포함한 완전한 순서의 스트림. |
| `EvalResponse` (송신) | 숫자 키로 된 `scores`, 이를 반영하는 키로 된 `reasoning`, 그리고 `summary`. |
| `JobPending` (송신) | `job_id`와 `next_poll_secs` — 단일 요청 내에 완료할 수 없는 작업에 사용. |

`ended_at`는 세션이 종료 이벤트를 발생시킨 경우에만 존재합니다. 따라서 비활성으로 인해 디스패치된 세션에는 이 필드가 없습니다. 폴링 주기는 `next_poll_secs`, 평가자의 `default_poll_interval_secs`, 서버의 `EVALUATOR_POLLING_INTERVAL_SECS` 순으로 따르며, 1초에서 1시간 사이로 고정되고 벽시계 기준 1시간의 상한이 있습니다.

요청에는 완전한 이벤트 페이로드가 포함되므로, 평가자는 전체 트랜스크립트 내용을 확인할 수 있습니다. 평가자 전달을 어떤 데이터를 기계에 보낼지 결정할 때 트랜스크립트 전달로 간주하여 처리하세요.

## 좋은 평가 대상

- 작업 완료 또는 정확성
- 근거성 및 환각 위험
- 도구 선택 및 도구 효율성
- 정책 또는 프로세스 컴플라이언스
- 비용 및 지연 시간 예산
- 필요한 사람의 에스컬레이션

점수 키는 안정적인 식별자입니다. 키 이름을 변경하면 기존 시리즈가 변경되는 것이 아니라 새로운 차트 시리즈가 시작되므로, 트렌드가 조용히 끊어집니다. 차트로 시각화하기 전에 이름을 먼저 결정하세요.

## 점수에서 대응까지

대시보드에 점수를 표시하여 추세를 추적하세요. 임계값이나 복합 조건에 대한 알림을 생성하세요. 특정 모집단 전반에서 점수가 하락하면 감사를 실행하여 원인을 조사하고, 원인이 반복 가능한 행동인 경우 정책을 배포하세요.
