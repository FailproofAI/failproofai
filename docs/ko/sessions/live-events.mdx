라이브 이벤트를 통해 계측이 제대로 이루어지고 있는지 확인하고, 세션이 끝나기를 기다리지 않고도 위험한 실행 과정을 모니터링할 수 있습니다.

## 활동 모니터링

<Tabs>
  <Tab title="대시보드">
    1. **Observe → Events**로 이동합니다.
    2. 데이터가 수신되고 있는지 확인하기 위해 현재 시간 범위를 선택하고 필터를 적용하지 않은 상태로 시작합니다.
    3. 환경, 이벤트 유형, 에이전트, 또는 세션별로 필터링합니다. 페이로드 텍스트 검색에는 검색 기능을 활용하세요.
    4. 이벤트를 선택하여 요약 및 세부 정보를 확인합니다. 전체 트레이스를 보려면 해당 세션 링크를 따라가세요.

    ![시간, 환경, 이벤트 유형, 에이전트, 모델, 컨텍스트, 세션별로 필터링된 라이브 이벤트 스트림 — Hermes 채팅 게이트웨이와 코딩 CLI 실행에서 발생한 트래픽이 표시됩니다.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    기본 피드에는 원시 페이로드가 포함되지 않습니다. `--full`은 범위가 제한된 세션 조사에서만 사용하세요.
  </Tab>
</Tabs>

이벤트 스트림을 활용하여 다음 세 가지 즉각적인 질문에 답하세요:

- 예상된 에이전트가 올바른 환경에 보고하고 있는가?
- 모델 호출, 툴 호출, 정책 결정이 순서대로 수신되고 있는가?
- 세션이 진행을 멈추거나 동일한 작업을 반복하고 있지는 않은가?

이벤트 유형에는 에이전트 수명 주기 이벤트, 모델 요청 및 응답, 툴 사용 및 결과, 훅 실행, 사람의 대기 및 인터럽트, 그리고 명시적 오류가 포함됩니다. 상관 관계 ID는 툴 호출과 그 결과처럼 쌍을 이루는 이벤트를 연결합니다.

<Tip>
  새로운 통합을 검증하는 동안에는 라이브 뷰를 넓게 유지하세요. 첫 번째 이벤트를 확인한 후에만 필터를 추가하세요. 잘못된 필터를 적용하면 수집 실패처럼 보일 수 있습니다.
</Tip>

이벤트가 표시되지 않으면 `failproofai config --status`를 실행한 후 [수집 문제 해결](/ko/reference/troubleshooting)을 참고하세요.

지원되는 12개의 [하네스](/ko/reference/harnesses) 중 하나에서 실행되지 않는 에이전트는 [Python SDK](/ko/reference/custom-agents)를 통해 동일한 이벤트 유형을 보고합니다. 여기에는 게이트웨이 및 프로덕션 에이전트가 의존하는 사람 참여(human-in-the-loop) 이벤트(`human_wait`, `human_input`, `human_interrupt`)도 포함됩니다.
