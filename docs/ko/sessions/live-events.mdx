실시간 이벤트를 통해 계측(instrumentation)이 올바르게 작동하는지 확인하고, 세션이 완료될 때까지 기다리지 않고도 위험한 실행 상황을 모니터링할 수 있습니다.

## 활동 모니터링

<Tabs>
  <Tab title="대시보드">
    1. **Observe → Events**로 이동합니다.
    2. 데이터가 수신되는지 확인하기 위해 현재 시간 범위를 선택하고 필터를 적용하지 않은 상태로 시작합니다.
    3. 환경, 이벤트 유형, 에이전트, 세션으로 필터링합니다. 페이로드 텍스트 검색에는 검색 기능을 활용하세요.
    4. 이벤트를 선택하면 요약 및 세부 정보를 확인할 수 있습니다. 세션 링크를 따라가면 전체 트레이스를 볼 수 있습니다.

    ![시간, 환경, 이벤트 유형, 에이전트, 모델, 컨텍스트, 세션, 텍스트 필터가 포함된 실시간 Events 스트림.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    기본 피드에는 원시 페이로드가 포함되지 않습니다. `--full` 옵션은 범위가 한정된 세션 조사 시에만 사용하세요.
  </Tab>
</Tabs>

이벤트 스트림을 활용하면 다음 세 가지 핵심 질문에 즉시 답할 수 있습니다.

- 예상한 에이전트가 올바른 환경에 보고하고 있는가?
- 모델 호출, 도구 호출, 정책 결정이 순서대로 수신되고 있는가?
- 세션이 진행을 멈추거나 동일한 작업을 반복하기 시작했는가?

이벤트 유형에는 에이전트 생명주기 이벤트, 모델 요청 및 응답, 도구 사용 및 결과, 훅 실행, 사람의 대기 및 중단, 명시적 오류가 포함됩니다. 상관 관계 ID(Correlation ID)는 도구 호출과 그 결과처럼 쌍을 이루는 이벤트를 연결합니다.

<Tip>
  새로운 통합을 검증할 때는 실시간 뷰를 넓게 유지하세요. 첫 번째 이벤트가 확인된 후에만 필터를 추가하세요. 잘못된 필터를 적용하면 수집(ingestion)이 실패한 것처럼 보일 수 있습니다.
</Tip>

이벤트가 나타나지 않는다면 `failproofai config --status`를 실행한 후 [수집 문제 해결](/ko/reference/troubleshooting)을 참고하세요.
