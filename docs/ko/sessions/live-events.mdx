라이브 이벤트를 통해 계측이 올바르게 작동하는지 확인하고, 세션이 완료될 때까지 기다리지 않고 위험한 실행을 실시간으로 모니터링할 수 있습니다.

## 활동 모니터링

<Tabs>
  <Tab title="대시보드">
    1. **Observe → Events**로 이동합니다.
    2. 데이터가 수신되는지 확인하려면 현재 시간 범위에서 필터 없이 시작하세요.
    3. 환경, 이벤트 유형, 에이전트, 또는 세션으로 필터링합니다. 페이로드 텍스트는 검색을 사용하세요.
    4. 이벤트를 선택하면 요약 및 세부 정보를 확인할 수 있습니다. 세션 링크를 따라가면 전체 트레이스를 볼 수 있습니다.

    ![시간, 환경, 이벤트 유형, 에이전트, 모델, 컨텍스트, 세션으로 필터링된 라이브 이벤트 스트림 — Hermes 채팅 게이트웨이와 코딩 CLI 실행의 트래픽이 표시됩니다.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    기본 피드에는 원시 페이로드가 포함되지 않습니다. `--full` 옵션은 범위가 정해진 세션 조사에서만 사용하세요.
  </Tab>
</Tabs>

이벤트 스트림을 활용해 다음 세 가지 즉각적인 질문에 답할 수 있습니다:

- 예상된 에이전트가 올바른 환경에 보고하고 있는가?
- 모델 호출, 툴 호출, 정책 결정이 순서대로 수신되고 있는가?
- 세션이 진행을 멈추거나 동일한 작업을 반복하고 있지는 않은가?

이벤트 유형에는 에이전트 라이프사이클 이벤트, 모델 요청 및 응답, 툴 사용 및 결과, 훅 실행, 사람의 대기 및 인터럽트, 명시적 오류가 포함됩니다. 상관 관계 ID는 툴 호출과 그 결과처럼 쌍을 이루는 이벤트를 연결합니다.

<Tip>
  새로운 통합을 검증할 때는 라이브 뷰를 넓게 유지하세요. 첫 번째 이벤트가 확인된 후에만 필터를 추가하세요. 잘못된 필터를 적용하면 수집 실패처럼 보일 수 있습니다.
</Tip>

이벤트가 표시되지 않으면 `failproofai config --status`를 실행한 후 [수집 문제 해결](/ko/reference/troubleshooting)을 참고하세요.

지원되는 12개의 [하네스](/ko/reference/harnesses) 중 하나에서 실행되지 않는 에이전트는 [Python SDK](/ko/reference/custom-agents)를 통해 동일한 이벤트 유형을 보고하며, 게이트웨이 및 프로덕션 에이전트가 의존하는 human-in-the-loop 이벤트(`human_wait`, `human_input`, `human_interrupt`)도 포함됩니다.
