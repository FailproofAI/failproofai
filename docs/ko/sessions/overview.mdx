세션은 하나의 에이전트 실행을 의미합니다. 프롬프트, 모델 호출, 도구, 오류, 사용자 입력, 정책 결정, 최종 결과를 하나로 연결합니다.

## 세션 위치

<Tabs>
  <Tab title="로컬">
    `failproofai`를 실행하면 `http://localhost:8020`에서 대시보드가 열립니다. 세션 기록은 해당 머신에 저장됩니다.
  </Tab>
  <Tab title="클라우드">
    머신을 연결한 후 **Observe → Sessions**를 엽니다:

    ```bash
    export FAILPROOFAI_CLOUD_TOKEN="<key>"
    failproofai config
    ```

    클라우드는 기본적으로 전체 트랜스크립트를 수신합니다. 정책 결정만 전송하려면 먼저 연결한 다음 `~/.failproofai/config.json`에서 `collector.sessions`를 `false`로 설정하세요. 현재 `--no-transcripts` 설정 플래그는 해당 설정을 적용하지 않습니다.
  </Tab>
</Tabs>

세션은 지원되는 12개의 [에이전트 하네스](/ko/reference/harnesses)와 [Python SDK](/ko/reference/custom-agents)로 계측된 에이전트에서 전송됩니다.

## 세션 찾기

클라우드에서는 시간, 환경, 상태, 에이전트, 세션 ID로 필터링할 수 있습니다. CLI에서는 다음과 같이 사용합니다:

```bash
fp sessions --since 24h
fp sessions --status error,timeout --agent-id checkout-agent
fp --json sessions --session-id <session-id>
```

평가되지 않은 실패의 경우 `fp errors --since 24h`를 사용하세요. `fp sessions --status`는 최신 평가 결과를 기준으로 하므로, 평가되지 않은 세션은 상태가 없습니다.

## 실행 내용 확인

1. 에이전트의 목표와 환경을 확인합니다.
2. 첫 번째 오류 또는 예상치 못한 결정을 찾습니다.
3. 바로 직전의 모델 컨텍스트와 도구 입력을 검사합니다.
4. 재시도, 지연 시간, 사용자 개입을 확인합니다.
5. 평가 결과와 정책 결정을 검토합니다.

## 세션이 없는 경우

```bash
failproofai flush --wait
failproofai config --status
failproofai backfill --since 30d --dry-run
```

세션이 하네스의 일반적인 위치가 아닌 다른 프로필, 컨테이너 홈, 마운트된 팀 디렉터리 등에 있을 경우 `failproofai harness add-path <harness> [<label>=]<path>`를 사용하세요.
