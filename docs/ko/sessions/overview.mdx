세션은 에이전트가 예상과 다르게 동작할 때 가장 좋은 출발점입니다. 하나의 실행에 속하는 모델 요청, 응답, 도구 호출, 사람의 개입, 오류, 평가, 정책 결정을 한데 모아 보여줍니다.

세션은 어떤 하네스에서 생성되었든 동일한 형태로 표시됩니다. 저장소를 재작성하는 Claude Code 실행, Slack에서 고객에게 응답하는 Hermes 에이전트, SDK로 계측된 Python 서비스 모두 동일한 트레이스 형식으로 저장되므로, 하나의 뷰로 전체 플릿을 파악할 수 있습니다.

에이전트 실행의 목표부터 모델 호출, 도구 사용, 최종 응답까지 하나의 흐름으로 따라가 보세요.

## 세션 찾기

실행 허용량을 초과하여 세션이 콜드 스토리지에 보관된 경우, 동일한 청구 주기 내에 허용량을 늘리면 가장 오래된 세션부터 순서대로 해제됩니다. 전송 재시도가 발생해도 세션이 허용량을 두 번 소비하지는 않습니다.

<Tabs>
  <Tab title="대시보드">
    1. 클라우드 사이드바에서 **Observe → Sessions**으로 이동합니다.
    2. 시간 범위를 설정한 후 환경, 상태, 에이전트, 세션 ID로 필터링합니다.
    3. 품질, 비용, 토큰, 지연 시간 기준으로 범위를 좁히려면 점수 또는 메트릭 범위를 추가합니다.
    4. 행을 선택하면 해당 트레이스가 열립니다. 세션 ID 옆의 복사 버튼을 사용해 공유하세요.

    ![환경, 에이전트, 상태, 평가 점수 필터와 함께 실행별로 한 행씩 표시되는 세션 목록.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    멀티 에이전트 실행을 펼치려면 `--agents`를, 페이지네이션하려면 `--all`을, 출력 컬럼을 선택하려면 `--fields`를 추가합니다.
  </Tab>
</Tabs>

## 할 수 있는 작업

- 에이전트, 환경, 시간, 모델, 이벤트 유형, 오류 상태로 실행을 찾습니다.
- 특정 결과를 만들어낸 정확한 실행 순서를 추적합니다.
- 성공한 실행과 실패한 실행을 비교합니다.
- 감사 결과나 알림 인시던트에 사용된 근거를 확인합니다.
- 오프라인 기록이 필요할 때 세션을 내보냅니다.

## 체계적인 조사 순서

1. 세션의 목표와 환경을 확인합니다.
2. 최종 실패뿐 아니라 첫 번째 오류 또는 예상치 못한 결정을 찾습니다.
3. 그 직전의 모델 컨텍스트와 도구 입력을 검토합니다.
4. 재시도, 지연 시간, 사람의 개입을 확인합니다.
5. 평가 점수와 정책 결정을 검토합니다.
