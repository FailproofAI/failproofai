에이전트가 예상치 못한 동작을 보일 때 세션이 최적의 출발점입니다. 세션은 하나의 실행에 속하는 모델 요청, 응답, 도구 호출, 사람의 개입, 오류, 평가, 정책 결정을 하나로 묶어줍니다.

세션은 어떤 환경에서 생성됐든 동일한 형태로 표시됩니다. 저장소를 재작성하는 Claude Code 실행, Slack에서 고객에게 응답하는 Hermes 에이전트, SDK로 계측된 Python 서비스 모두 동일한 트레이스 형식으로 저장되므로, 단일 뷰로 전체 플릿을 파악할 수 있습니다.

에이전트 실행의 목표부터 모델 호출, 도구 사용, 최종 응답까지 전 과정을 추적하세요.

## 세션 찾기

<Tabs>
  <Tab title="대시보드">
    1. 클라우드 사이드바에서 **Observe → Sessions**으로 이동합니다.
    2. 시간 범위를 설정한 후 환경, 상태, 에이전트, 세션 ID로 필터링합니다.
    3. 품질, 비용, 토큰, 지연 시간 기준으로 좁혀볼 때는 점수 또는 메트릭 범위를 추가합니다.
    4. 행을 선택하면 트레이스가 열립니다. 세션 ID 옆의 복사 컨트롤을 사용하면 공유할 수 있습니다.

    ![환경, 에이전트, 상태, 평가 점수 필터와 함께 실행당 한 행으로 표시되는 Sessions 목록.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    `--agents`를 추가하면 멀티 에이전트 실행을 펼쳐 볼 수 있고, `--all`로 페이지네이션을, `--fields`로 출력 컬럼을 선택할 수 있습니다.
  </Tab>
</Tabs>

## 할 수 있는 작업

- 에이전트, 환경, 시간, 모델, 이벤트 유형, 오류 상태로 실행을 검색합니다.
- 특정 결과를 만들어낸 정확한 순서를 추적합니다.
- 성공한 실행과 실패한 실행을 비교합니다.
- 감사 결과나 알림 인시던트의 근거 자료를 확인합니다.
- 오프라인 기록이 필요할 때 세션을 내보냅니다.

## 신뢰할 수 있는 조사 순서

1. 세션의 목표와 환경을 확인합니다.
2. 최종 실패만이 아니라, 첫 번째 오류 또는 예상치 못한 결정을 찾습니다.
3. 해당 시점 직전의 모델 컨텍스트와 도구 입력을 검사합니다.
4. 재시도, 지연 시간, 사람의 개입 여부를 확인합니다.
5. 평가 점수와 정책 결정을 검토합니다.
