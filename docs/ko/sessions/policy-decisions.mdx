정책 결정은 에이전트 실행 중 Failproof AI가 수행한 작업을 보여줍니다.

<Tabs>
  <Tab title="대시보드">
    **Observe → policy**로 이동하여 결정 내역, 차단율, 머신, 배포된 할당을 검토합니다.

    ![정책 페이지에서 결정 합계, 머신 필터, 시간별 적용 활동, 정책 매핑 테이블을 보여줍니다.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp guardrails summary --since 24h
    fp guardrails timeline --since 24h
    failproofai policies
    failproofai config --status
    ```

    `--since`는 `1h`, `6h`, `24h`, `7d`를 사용합니다. `--machine <id>`를 추가하면 특정 머신에 집중할 수 있습니다.
  </Tab>
</Tabs>

## 관찰 롤아웃 읽기

관찰 모드는 실제 정책을 실행하고 `deny` 또는 `instruct` 결정을 기록합니다. 에이전트는 계속 진행이 허용됩니다.

```bash
fp fleet deploy <machine> --add <policy>:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add <policy>:enforce
```

<Warning>
  `--add <policy>`만 단독으로 사용하면 기존 배포가 없을 경우 즉시 적용됩니다. 섀도 롤아웃을 위해 `:observe`를 추가하세요.
</Warning>

allow가 아닌 관찰된 결정만 기록됩니다. 타임아웃은 allow로 기록되는데, 이는 적용 모드에서도 동일하게 처리되기 때문입니다.

기록된 deny가 하네스가 해당 작업을 실제로 중단했다는 증거는 아닙니다. 도구 호출 deny는 지원되는 12개 하네스 전체에서 검증되며, 다른 이벤트는 경우에 따라 다릅니다. [적용 기능](/ko/reference/harnesses#enforcement-capability)을 참조하세요.

## 예상치 못한 결과 조사

| 표시 내용 | 확인 사항 |
| --- | --- |
| 결정 없음 | `failproofai config --status` 및 세션 일시 정지 여부 |
| 정책 이름 없이 다수의 거부 | [정책 실패 동작](/ko/policies/failure-behavior) |
| 보호된 모든 작업 거부 | `failproofaid` 서비스 정상 여부 |
| 비활성화할 수 없는 거부 | `block-failproofai-commands`는 항상 활성화됨 |
| `--env production` 데이터 없음 | 새 머신은 `local` 환경을 사용함 |
