쿼리는 대시보드, 감사, 조사 아래에 있는 유연한 계층입니다. 임시 SQL로 아이디어를 검증한 후, 반복 워크플로에 포함될 때 쿼리를 저장하세요.

## 쿼리 생성 및 실행

<Tabs>
  <Tab title="대시보드">
    1. **Analyze → Queries**로 이동하여 **new query**를 선택합니다.
    2. 스키마 브라우저를 열고 이벤트, 세션, 평가 데이터에서 필드를 선택합니다.
    3. SQL을 작성하고 필요한 경우 파라미터를 추가한 후 쿼리를 실행합니다.
    4. 명확한 이름과 설명으로 저장한 후, 결과를 모니터링해야 하는 경우 **add to dashboard**를 사용합니다.

    쿼리 에디터는 이벤트 스키마, SQL, 파라미터, 결과 미리보기를 통합하여 저장 전에 질문을 검증할 수 있습니다.

    ![스키마 브라우저와 실시간 결과 그리드가 포함된 SQL 쿼리 에디터.](/images/dashboard/query-lab.png)

    저장된 쿼리는 공유 라이브러리에 표시되며, 팀원들이 다시 실행하거나 결과를 대시보드에 추가할 수 있습니다.

    ![재사용 가능한 기본 제공 및 커스텀 쿼리가 포함된 저장된 쿼리 라이브러리.](/images/dashboard/queries.png)

    SQL을 다시 열지 않아도 결과를 이해할 수 있도록 명확한 이름과 설명을 사용하세요.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    `fp query list`로 ID를 찾고, `fp query delete <query-id>`로 저장된 쿼리를 삭제합니다.
  </Tab>
</Tabs>

## 주요 활용 사례

- 동일한 도구에 반복 호출이 있는 세션을 찾습니다.
- 모델 또는 환경별 평가 점수를 비교합니다.
- 사람의 대기와 재개 사이의 시간을 측정합니다.
- 정책 거부 후 성공적인 대안이 이어지는 패턴을 식별합니다.
- 감사를 위한 코호트를 구성합니다.

익숙하지 않은 필드를 대상으로 쿼리를 작성하기 전에 **Queries → Schema**를 먼저 확인하세요. 명시적인 시간 및 환경 필터를 사용하고, 탐색 중에는 결과 개수 제한을 유지하세요.

<Warning>
  쿼리는 의심스러운 패턴을 식별할 수 있지만, 그 자체만으로 장애 모드를 확정짓지는 않습니다. 결과를 정책으로 전환하기 전에 대표적인 트레이스를 열거나 감사를 실행하세요.
</Warning>
