쿼리는 대시보드, 감사, 조사 작업의 기반이 되는 유연한 계층입니다. 임시 SQL로 아이디어를 빠르게 검증하고, 반복적인 워크플로우의 일부가 되면 쿼리를 저장해 두세요.

## 쿼리 생성 및 실행

<Tabs>
  <Tab title="대시보드">
    1. **Analyze → Queries**로 이동하여 **new query**를 선택합니다.
    2. 스키마 브라우저를 열고 이벤트, 세션, 평가 데이터에서 필드를 선택합니다.
    3. SQL을 작성하고 필요에 따라 파라미터를 추가한 뒤 쿼리를 실행합니다.
    4. 명확한 이름과 설명을 붙여 저장하고, 결과를 모니터링해야 할 경우 **add to dashboard**를 사용합니다.

    쿼리 에디터는 이벤트 스키마, SQL, 파라미터, 결과 미리보기를 하나로 결합하여 저장 전에 쿼리의 정확성을 검증할 수 있도록 합니다.

    ![스키마 브라우저와 실시간 결과 그리드가 포함된 SQL 쿼리 에디터.](/images/dashboard/query-lab.png)

    저장된 쿼리는 공유 라이브러리에 표시되며, 팀원들이 재실행하거나 대시보드에 결과를 추가할 수 있습니다.

    ![재사용 가능한 기본 제공 쿼리와 사용자 정의 쿼리가 포함된 저장된 쿼리 라이브러리.](/images/dashboard/queries.png)

    명확한 이름과 설명을 작성해 두면 SQL을 다시 열지 않아도 결과의 의미를 파악할 수 있습니다.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    `fp query list`로 ID를 확인하고, `fp query delete <query-id>`로 저장된 쿼리를 삭제할 수 있습니다.
  </Tab>
</Tabs>

## 주요 활용 사례

- 동일한 도구를 반복 호출한 세션 찾기
- 모델 또는 환경별 평가 점수 비교
- 사람의 대기와 재개 사이의 시간 측정
- 정책 거부 후 성공적인 대안이 적용된 사례 식별
- 감사를 위한 코호트 구성

익숙하지 않은 필드에 쿼리를 작성하기 전에 **Queries → Schema**를 먼저 열어보세요. 시간 및 환경 필터를 명시적으로 지정하고, 탐색 중에는 결과 수 제한을 유지하는 것이 좋습니다.

<Warning>
  쿼리는 의심스러운 패턴을 식별할 수 있지만, 그 자체로 장애 모드를 확정하지는 않습니다. 결과를 정책으로 전환하기 전에 대표적인 트레이스를 열어보거나 감사를 실행하세요.
</Warning>
