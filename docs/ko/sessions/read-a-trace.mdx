트레이스는 단순한 이벤트 스트림을 실행의 인과 관계 스토리로 변환합니다. 마지막 오류에서 거슬러 올라가는 것이 아니라, 처음으로 흐름이 달라진 지점부터 읽으세요.

## 트레이스 열기

<Tabs>
  <Tab title="대시보드">
    1. **Observe → Sessions**으로 이동하여 세션을 엽니다.
    2. 프로파일 요약을 통해 결과, 타이밍, 오류, 평가 점수를 확인합니다.
    3. 타임라인과 미니맵을 훑어봅니다. 세션이 크다면 이벤트 유형이나 시간으로 필터링하세요.
    4. 이벤트를 선택하여 상세 내용을 확인합니다. 평가자 JSON은 **export**를 사용하거나, 페이지 URL을 복사하여 선택한 증거에 대한 딥 링크를 공유할 수 있습니다.

    ![실행 그래프, 이벤트 타임라인, 평가 패널, 그리고 도구·모델·훅 분석이 포함된 세션 상세 보기 화면.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    먼저 간략한 이벤트 피드를 사용하세요. 이벤트 요약만으로 충분한 정보를 얻기 어려울 때만 전체 페이로드를 요청하세요.
  </Tab>
</Tabs>

<Steps>
  <Step title="전체 맥락 파악">
    에이전트, 환경, 타이밍, 결과, 실행 시간을 확인한 후, 오류·긴 스팬·반복 도구 호출·사람 대기·정책 거부 결정 등을 살펴보세요.
  </Step>
  <Step title="첫 번째 의심 이벤트 펼치기">
    요청, 응답, 도구 입력, 출력, 상관 ID를 검사합니다. 민감한 콘텐츠는 트랜스크립트 캡처가 활성화되어 있고 사용자 권한이 허용된 경우에만 표시됩니다.
  </Step>
  <Step title="이전 컨텍스트 살펴보기">
    원인은 대부분 한 이벤트 이전에 있습니다. 잘못된 모델 응답, 누락된 도구 결과, 또는 오래된 가정이 그 원인일 수 있습니다.
  </Step>
  <Step title="증거를 행동으로 전환">
    세션을 감사 범위에 추가하거나, 이슈와 연결하거나, 장애 유형을 바탕으로 정책을 작성하세요.
  </Step>
</Steps>

<Warning>
  실행 시간이 길다고 해서 항상 모델 지연을 의미하지는 않습니다. 무엇을 수정할지 결정하기 전에 모델, 도구, 훅, 사람 대기 시간을 각각 분리하여 분석하세요.
</Warning>
