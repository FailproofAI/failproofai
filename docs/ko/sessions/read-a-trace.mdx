트레이스는 평탄한 이벤트 스트림을 실행의 인과 관계 이야기로 변환합니다. 마지막 오류에서 거슬러 올라가지 말고, 처음 분기가 발생한 지점부터 읽으세요.

## 트레이스 열기

<Tabs>
  <Tab title="대시보드">
    1. **Observe → Sessions**으로 이동해 세션을 엽니다.
    2. 프로필 요약을 사용해 결과, 타이밍, 오류, 평가 점수를 확인합니다.
    3. 타임라인과 미니맵을 훑어봅니다. 세션이 클 경우 이벤트 유형이나 시간으로 필터링하세요.
    4. 이벤트를 선택해 세부 내용을 확인합니다. 평가자 JSON을 내보내려면 **export**를 사용하거나, 페이지 URL을 복사해 선택한 증거에 대한 딥 링크를 공유하세요.

    ![실행 그래프, 이벤트 타임라인, 평가 패널, 도구·모델·훅 분류가 포함된 세션 상세 보기.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    먼저 경량 이벤트 피드를 사용하세요. 이벤트 요약에 충분한 정보가 없을 때만 전체 페이로드를 요청하세요.
  </Tab>
</Tabs>

<Steps>
  <Step title="전체 상황 파악">
    에이전트, 환경, 타이밍, 결과, 실행 시간을 확인한 후, 오류, 긴 스팬, 반복된 도구 호출, 사람의 대기 시간, 거부된 정책 결정을 찾아보세요.
  </Step>
  <Step title="첫 번째 의심 이벤트 펼치기">
    요청, 응답, 도구 입력, 출력, 상관 ID를 검사합니다. 민감한 내용은 트랜스크립트 캡처가 활성화되어 있고 필요한 권한이 있을 때만 표시됩니다.
  </Step>
  <Step title="이전 컨텍스트 검토">
    원인은 대부분 한 이벤트 앞에 있습니다. 잘못된 모델 응답, 누락된 도구 결과, 또는 오래된 가정이 원인일 수 있습니다.
  </Step>
  <Step title="증거를 행동으로 전환">
    세션을 감사 범위에 추가하거나, 이슈에 연결하거나, 발견된 장애 패턴을 바탕으로 정책을 작성하세요.
  </Step>
</Steps>

<Warning>
  실행 시간이 길다고 해서 항상 모델 지연이 원인은 아닙니다. 무엇을 수정할지 결정하기 전에 모델, 도구, 훅, 사람 대기 시간을 각각 분리해서 확인하세요.
</Warning>
