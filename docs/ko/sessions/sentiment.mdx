Jev는 사용자가 에이전트에 보낸 각 메시지를 **angry(분노)**, **frustrated(불만)**, **happy(만족)**, **confused(혼란)** 의 네 가지 감정에 대해 0~100점으로 채점하고, 에이전트의 응대 품질을 나타내는 세 가지 신호도 함께 측정합니다.

- **Correcting**: 사용자가 에이전트의 답변이 틀렸다고 지적하는 경우.
- **Resolved**: 사용자가 에이전트가 문제를 해결했다고 확인하는 경우.
- **Doubtful**: 사용자가 에이전트의 답변이 사실인지, 혹은 작업을 실제로 수행했는지 의심하는 경우.

감정 분석을 활용하면 사용자의 인내심이 한계에 달한 대화, 반복적으로 수정 요청이 발생하는 에이전트, 그리고 반응이 좋은 답변을 찾아낼 수 있습니다. 이 기능은 Jev에 내장된 채점 방식으로, 별도의 평가를 직접 작성할 필요가 없습니다. 직접 정답이 정해진 질문에 대한 평가를 만들고 싶다면 [Jev eval 생성하기](/ko/evaluations/jev)를 참고하세요.

<Note>
  감정 분석은 관리자가 조직 전체에 대해 활성화하기 전까지는 비활성 상태입니다. Jev는 메시지당 채점 요청을 한 번 수행하며, 채점 시 해당 메시지와 그 직전의 에이전트 답변을 함께 수신합니다. 채점에는 조직의 모델 예산이 사용됩니다.
</Note>

## 활성화 방법

1. **Administration → Settings** 로 이동합니다.
2. **Human input sentiment** 항목에서 스위치를 **켜고** 저장합니다.

먼저 지난 하루의 메시지가 채점되고, 이후 새 메시지는 도착 후 1~2분 이내에 채점됩니다.

## 검토할 대화 찾기

**Observe → Sentiment** 를 엽니다. 시간, 환경, 에이전트, 세션 ID로 필터링할 수 있습니다. 헤더에는 메시지 및 세션 수, **flagged(플래그 처리된)** 메시지 수, 가장 두드러진 신호가 표시됩니다. angry, frustrated, correcting, confused, doubtful 점수 중 하나라도 100점 만점에 35점 이상이 되면 해당 메시지에 플래그가 붙습니다.

![메시지 및 세션 수, 플래그 처리된 메시지, 시간별 Jev 점수를 보여주는 Sentiment 대시보드.](/images/dashboard/sentiment-overview.png)

**Score over time** 을 사용해 신호를 비교하세요. 표시할 점수를 선택한 후 특정 시점을 클릭하면 해당 시간 구간의 메시지를 확인할 수 있습니다. **By agent** 표에서는 특정 신호가 집중되는 에이전트를 파악할 수 있습니다. **Messages** 에서는 가장 높은 부정 점수 순으로 정렬하거나 개별 점수를 선택할 수 있습니다. 메시지를 열어 해당 세션의 전후 대화 맥락을 읽고 무엇이 문제였는지 판단하세요.

![가장 높은 부정 점수 순으로 정렬된 Sentiment 메시지 목록과 각 원본 세션으로의 링크.](/images/dashboard/sentiment-messages.png)

## 채점 대상 메시지

사람이 직접 작성한 메시지만 채점됩니다.

- SDK를 통해 사용자 입력으로 기록된 커스텀 에이전트의 메시지.
- 세션 트랜스크립트가 전송될 때(기본값) Claude Code, Codex, OpenCode, pi, Hermes, OpenClaw에 직접 입력된 프롬프트. 단, 에이전트 런타임이 자체적으로 작성하는 예약 작업, 주입된 지시문, 서브 에이전트 핸드오프 등의 텍스트는 채점되지 않습니다. `claude -p`, `codex exec`, `hermes -z` 같은 비대화형 실행도 채점 대상이 아닙니다. 이러한 프롬프트는 사람이 아닌 스크립트가 작성한 것이기 때문입니다.

채점은 사용자 본인의 표현을 기준으로 판단합니다. "fix it"처럼 짧고 단도직입적인 지시는 분노로 간주하지 않으며, 질문을 하는 것 자체는 혼란으로 보지 않습니다. 새로운 요청은 수정 요청으로 보지 않고, 단순한 감사 인사는 해결로 집계하지 않습니다.
