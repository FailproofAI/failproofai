Failproof AI는 에이전트가 수행하는 작업을 기록하고, 허용 가능한 작업을 결정합니다.

## 관찰 (Observe)

| 용어 | 의미 |
| --- | --- |
| Session | 에이전트의 단일 실행 |
| Event | 세션 내 단일 액션 |
| Trace | 세션의 순서대로 정렬된 뷰 |
| Evaluation | 점수 또는 판단 |
| Audit | 다수 세션에 대한 검토 |
| Finding | 장애 패턴의 증거 |
| Issue | 담당자가 소유한 대응 사항 |
| Alert | 재발을 감지하는 규칙 |

## 적용 (Enforce)

| 용어 | 의미 |
| --- | --- |
| Harness | 에이전트가 실행되는 환경 |
| Hook | 하네스가 결정을 요청하는 지점 |
| Policy | 허용, 안내, 또는 차단하는 규칙 |
| Policy pack | 누구나 설치할 수 있는 버전 관리된 정책 세트 |
| Daemon | 정책을 평가하는 로컬 서비스 |
| Deployment | 특정 머신에 할당된 정책 |

## 워크플로우

```text
Session → Audit → Finding → Issue → Policy
```

증거에서 시작하세요. 반복되는 장애를 발견하고, 대응 책임자를 지정한 다음, 재발을 방지하세요.

정책은 `allow`, `instruct`, 또는 `deny`를 반환합니다. `instruct`를 통한 안내는 harness에 따라 달라지므로, 액션을 반드시 중단해야 할 때는 `deny`를 사용하세요.

관찰 모드는 결정과 분리되어 있습니다. 실제 정책을 실행하고 그 결과를 기록하면서도 에이전트는 계속 실행할 수 있습니다.

<Warning>
  `fp fleet deploy <machine> --add <policy>`를 그대로 실행하면 즉시 적용됩니다. 섀도 롤아웃을 위해서는 `:observe`를 추가하세요.
</Warning>

초기 설정에서는 어떠한 policy pack도 선택하지 않습니다. 추가하기 전까지는 `block-failproofai-commands`만 실행됩니다. 컴파일된 카탈로그에는 9개 카테고리에 걸쳐 39개의 정책이 포함되어 있습니다.

특정 에이전트 환경에서 이벤트가 차단 가능하다고 가정하기 전에 [지원되는 harness](/ko/reference/harnesses#enforcement-capability)를 먼저 확인하세요.
