| 개념 | 의미 | 달성할 수 있는 것 |
| --- | --- | --- |
| Session | 에이전트 작업 또는 실행 단위 | 개별 결과 재구성 |
| Event | 세션에서 기록된 단일 동작 | 모델 호출, 도구 사용, 오류, 사람의 행동, 또는 정책 결정 검사 |
| Trace | 세션의 순서 및 중첩 뷰 | 분리된 로그를 읽는 대신 인과관계 파악 |
| Evaluation | 세션에 대한 점수 또는 판단 | 품질, 규정 준수, 비용 또는 지연 시간을 지속적으로 추적 |
| Audit | 선택된 세션 집합에 대한 검토 | 명확한 목표와 주기를 가지고 실패 패턴 탐색 |
| Finding | 감사를 통해 발견된 증거 기반 실패 | 실패 유형, 심각도, 영향받은 세션 확인 |
| Issue | 지속적인 대응 기록 | finding 또는 알림 사건을 할당, 논의, 해결 |
| Alert | 재발을 감지하는 규칙 | 알려진 조건이 다시 발생할 때 담당자에게 알림 |
| Policy | 에이전트 활동 중 평가되는 규칙 | 위험한 동작을 관찰, 차단 또는 리디렉션 |
| Deployment | 머신에 대한 버전화된 정책 배포 | 정책이 실행되는 위치를 제어하고 안전하게 롤백 |

## 신뢰성 루프

증거에서 시작합니다. 세션은 무슨 일이 일어났는지를 보여줍니다. 감사는 그것이 일회성 실수인지 패턴인지를 판단합니다. finding은 실패 유형을 식별하고, issue는 대응을 담당합니다. policy는 동일한 동작을 방지하고, alert는 해당 조건이 다시 발생할 경우 알려줍니다.

<Warning>
  로컬 `failproofai audit`은 로컬 에이전트 기록을 스캔합니다. 반복 실행되는 Cloud 감사는 Failproof AI Cloud에 저장된 세션을 검토합니다. 두 가지는 범위와 스케줄링이 다른 별개의 워크플로입니다.
</Warning>
