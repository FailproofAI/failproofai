먼저 차단하고 싶은 동작과 계속 허용되어야 하는 정상적인 작업을 파악하세요.

## 검토된 정책으로 시작하기

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI에는 39개의 검토된 정책이 포함되어 있습니다. 새로 작성하기 전에 [카탈로그](/ko/policies/builtin-catalog)를 먼저 확인하세요.

## 직접 작성하고 테스트하기

<Steps>
  <Step title="작동하는 정책 만들기">
    ```bash
    failproofai publish --init guards.mjs
    ```

    이 명령은 `git push --force`를 차단하는 정책을 생성합니다. 원하는 규칙에 맞게 수정하세요.
  </Step>
  <Step title="이 머신에 적용하기">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    에이전트에게 차단된 작업을 수행하도록 요청한 후, 로컬 대시보드의 **Policies → Activity**에서 결과를 확인하세요.
  </Step>
  <Step title="유지하거나 제거하기">
    `.failproofai/policies/` 디렉터리 아래에 `*policies.mjs` 파일을 두면 자동으로 로드됩니다.

    명시적으로 추가한 커스텀 파일은 다음 명령으로 제거할 수 있습니다:

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## 공유하기

공개 팩을 게시하세요:

```bash
failproofai publish
```

그러면 누구든 `failproofai policies add <owner>/<repo>`로 설치할 수 있습니다. [Policy Hub](https://befailproof.ai/policy-hub/)에서 인덱싱될 수 있도록 GitHub 토픽 `failproofai-policies`를 직접 추가하세요.

Cloud 배포를 위한 절차:

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  `--add checkout-guard`만 단독으로 사용하면 즉시 적용됩니다. `:observe`를 추가하면 에이전트를 차단하지 않고 정책이 수행할 동작을 기록만 합니다.
</Warning>

전체 워크플로우는 [팩 게시하기](/ko/policies/publish-a-pack) 또는 [정책 배포하기](/ko/policies/deploy)를 참고하세요.
