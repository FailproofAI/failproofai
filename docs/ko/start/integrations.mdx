## 시작하기 전에

이 경로가 전제하는 두 가지 사항으로, 아래 코드가 자동으로 처리해주지 않습니다:

| 요구사항 | 이유 |
| --- | --- |
| Python 3.10 이상 | SDK가 선언하는 최소 버전입니다. |
| `failproofai config`로 설정된 머신 | 이 명령어는 failproofaid 데몬을 설치하며, SDK가 기록한 내용을 전송하는 것은 데몬뿐입니다. 데몬이 없으면 배치가 스풀 디렉토리에 쌓이고 전송되지 않습니다. |

<Note>
  **이 경로는 기록만 합니다. 정책을 적용하지는 않습니다.** SDK는 에이전트가 수행한 작업을 캡처합니다. 정책은 에이전트 CLI 내부의 훅에서 실행되므로, 프레임워크 에이전트에 정책을 적용하려면 자체 런타임에 훅을 추가해야 합니다 — [Policies](/ko/policies/overview)를 참조하세요.
</Note>

## 어떤 프레임워크든 세 줄로

<CodeGroup>
```bash LangGraph
pip install 'failproofai-sdk[langgraph]'
```

```bash CrewAI
pip install 'failproofai-sdk[crewai]'
```

```bash LlamaIndex
pip install 'failproofai-sdk[llamaindex]'
```

```bash Pydantic AI
pip install 'failproofai-sdk[pydantic-ai]'
```

```bash Custom agents
pip install failproofai-sdk
```
</CodeGroup>

```python
import failproofai_sdk

failproofai_sdk.configure(environment="production")
failproofai_sdk.instrument()          # 임포트한 프레임워크를 자동 감지합니다

with failproofai_sdk.session():
    ...                               # 기존 에이전트 호출 코드, 변경 없음
```

함수에 데코레이터를 추가할 필요도 없고, 호출에 콜백을 전달할 필요도 없으며, 코드 전체에 id를 연결할 필요도 없습니다. 달라지는 것은 세션 내부의 호출뿐입니다:

<Tabs>
  <Tab title="LangGraph">
    ```python
    graph.invoke({"messages": [HumanMessage("...")]})
    ```
  </Tab>
  <Tab title="CrewAI">
    ```python
    Crew(agents=[analyst, writer], tasks=[gather, summarise]).kickoff()
    ```
  </Tab>
  <Tab title="LlamaIndex">
    ```python
    await agent.run("...")        # `async with failproofai_sdk.session():` 아래에서 사용
    ```
  </Tab>
  <Tab title="Pydantic AI">
    ```python
    agent.run_sync("...")
    ```
  </Tab>
  <Tab title="Custom agents">
    ```python
    with failproofai_sdk.agent("planner"):
        with failproofai_sdk.tool_call("search", input={"q": q}) as t:
            t.output = search(q)
    ```
  </Tab>
</Tabs>

추가 설치는 **프레임워크**를 위한 것입니다. 모든 어댑터는 기본 휠에 포함되어 있으므로, 이미 프레임워크가 설치된 프로젝트는 추가 설치가 전혀 필요 없습니다.

## 데이터 수신 확인

계측된 세션을 한 번 실행한 후 **Observe → Sessions**를 열고 환경을 선택하세요. 해당 실행이 재구성된 트레이스로 표시됩니다.

아무것도 도착하지 않는다면, `failproofai config --status`로 머신이 설정되고 연결되어 있는지 확인하세요. 연결되지 않은 경우 `failproofai config`를 실행하세요. [설정 선택](/ko/start/setup)을 참조하세요.

<Warning>
  전송 여부를 확인하기 위해 스풀 디렉토리를 확인하지 마세요. Failproof 데몬은 각 배치를 수밀리초 내에 수집하고 삭제하므로, 디렉토리를 읽으면 실제로 전송된 이벤트보다 훨씬 적게 표시됩니다.
</Warning>

SDK가 실제로 기록하고 있는지 확인하려면, 먼저 데몬을 중지한 후 세션을 실행하고 `~/.failproofai/custom-agents/events/`를 확인하세요. 데몬이 실행 중일 때 디렉토리가 비어 있는 것은 정상 상태입니다.

<CodeGroup>
```bash Linux
sudo systemctl stop failproofaid@$USER
```

```bash macOS
sudo launchctl bootout system/ai.failproof.failproofaid.$USER
```
</CodeGroup>

이후 `failproofai config`를 실행하여 데몬을 다시 시작하세요. 데몬이 중지된 동안에는 이 머신의 훅 이벤트에 평가자가 없으므로 거부됩니다. 따라서 확인에 필요한 시간 동안만 중지하세요.
