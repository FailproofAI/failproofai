이 빠른 시작 가이드는 한 대의 머신에서 세션을 보고하도록 설정하고, 감사를 실행하며, 정책을 배포합니다. 스킬을 활용하거나 수동 절차를 따라 Failproof AI를 설정하세요.

**어떤 경로를 선택할까요?** 에이전트가 지원되는 12개 [하네스](/ko/reference/harnesses) 중 하나에서 실행된다면 — 코딩 CLI, 또는 Hermes나 OpenClaw 같은 게이트웨이 — 아래 단계를 따르세요. Node.js 20.9 이상이 필요합니다. 에이전트에 하네스가 없다면 [Python SDK](/ko/reference/custom-agents)로 트레이싱 및 감사를 위한 계측을 한 다음 [첫 번째 오류 검사 실행](/ko/start/first-audit)에서 다시 합류하세요. 해당 경로에서 적용(enforcement)은 런타임에 훅이 필요합니다.

  <Tab title="수동 설정">
    ## 설치

<Steps>
  <Step title="Failproof AI 설치 및 연결">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    이 명령 하나로 설정이 완료됩니다. 로컬 데몬을 설치하고(루트 권한 1회), 감지된 모든 에이전트 CLI에 훅을 연결하며, 이 머신을 Cloud에 연결합니다.

    **Cloud 연결** 단계에서는 즉시 FailproofAI Cloud 로그인을 시작합니다(다른 옵션은 Tab 키: API 키 붙여넣기, 또는 오픈 소스 사용). 브라우저에서 링크를 열어줍니다(SSH 환경이거나 디스플레이가 없는 머신에서는 링크를 출력하므로 다른 기기에서 열 수 있습니다). 가입 또는 로그인하고, 조직을 확인하거나 새로 만든 뒤 **Authorize**를 클릭하세요. 키 이름과 권한은 자동으로 설정됩니다. 사전에 계정이 필요하지 않습니다.

    터미널이 자동으로 이를 감지하고 승인자와 해당 조직을 표시합니다. 트레이싱할 에이전트를 확인하면 설정이 완료됩니다. 머신 키는 데몬 설치 후 해당 시점에만 생성되므로, 중단한 실행에는 키가 남지 않습니다. 키는 **Administration → Keys** 아래에 **cli login**으로 표시되며, 여기서 취소할 수 있습니다.

    <Accordion title="브라우저나 터미널을 사용할 수 없나요? 키를 사용하세요 (CI, 컨테이너, 프로비저닝 스크립트)">
      [Failproof AI 대시보드](https://app.befailproof.ai)에서 **Administration → Keys**로 이동하여 `events:add` 및 `policies:pull` 권한의 키를 생성하세요. [FailproofAI Cloud를 통한 Jev](/ko/reference/jev-cloud) 사용 계획이 있다면, `jev:evaluate`도 부여하는 **machine** 프리셋을 선택하세요. 일회용 시크릿을 복사하고 대상 머신의 셸에서 읽어들이세요 — `read -s`는 에코되지 않는 프롬프트로 입력받습니다:

      ```bash
      read -rs FAILPROOFAI_KEY && export FAILPROOFAI_KEY
      FAILPROOFAI_CLOUD_TOKEN="$FAILPROOFAI_KEY" failproofai config
      ```

      키를 `--token` 대신 환경 변수로 전달하면 머신의 모든 사용자가 커맨드 인수를 볼 수 있는 `ps`에 노출되지 않습니다. 셸 히스토리에서 숨기는 것은 `read -s`로 입력하는 방식이 처리합니다. CI에서는 마스크된 시크릿으로 주입하고 셸 트레이싱(`set -x`)을 비활성화하세요. 그렇지 않으면 트레이스에 키가 출력됩니다. 대화형 실행에서는 **Cloud 연결** 단계에서 **API 키 붙여넣기**를 선택할 수도 있습니다.
    </Accordion>

    기본적으로 세션 트랜스크립트가 전송됩니다. 트랜스크립트 내용 없이 훅 활동 및 정책 결정만 보고하려면 `--no-transcripts`를 추가하세요.

    <Warning>
      여기서 `failproofai config --connect <url>`을 사용하지 마세요. 해당 플래그는 **이미** 설정된 머신을 등록하고 즉시 반환합니다 — 데몬도, 훅도 없이 — 따라서 머신이 Cloud에 나타나지만 아무것도 수집하거나 적용하지 않습니다.
    </Warning>

    이 머신에 이미 에이전트 히스토리가 있다면, 최근 7일치를 미리 보고 가져온 다음 전송이 완료될 때까지 기다리세요. 새 머신에서는 이 단계를 건너뛰세요.

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    Failproof AI의 **Sessions**를 열고 가져온 세션을 선택하세요.
  </Step>
  <Step title="Failproof AI를 하네스에 연결">
    이전 단계에서 이미 감지된 모든 에이전트 CLI에 연결되었습니다. 필요할 때 또는 이후에 설치된 하네스를 추가할 때 특정 하네스에 대해 다시 실행하세요. 12개 모두 유효한 `--cli` 값입니다 — `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, `goose`.

    ```bash
    failproofai policies --install --cli claude --scope user     # 코딩 CLI
    failproofai policies --install --cli hermes --scope user     # Slack/Telegram 게이트웨이
    ```

    툴 호출이 실행되기 전에 차단하는 기능은 12개 모두에서 검증됩니다. 턴 종료 게이트는 8개에서 검증됩니다 — 하네스별 매트릭스는 [적용 기능](/ko/reference/harnesses#enforcement-capability)을 참조하세요.
  </Step>
  <Step title="적용할 항목 선택">
    훅 연결만으로는 정책이 활성화되지 않습니다. 설정은 의도적으로 아무것도 선택하지 않습니다 — 그 결정은 여러분의 몫입니다 — 따라서 팩을 가져오세요:

    ```bash
    failproofai policies add FailproofAI/policies
    ```

    팩은 GitHub 릴리스에서 가져와 체크섬으로 검증되고, 정확한 태그에 고정됩니다. 39개의 정책을 포함하며, 매니페스트에서 무인 활성화가 안전하다고 표시된 10개를 켭니다. Failproof AI가 세션을 감사하고 에이전트에 맞는 정책을 작성하기 전에 로컬 정책 결정을 확인하고 적용을 시험해보세요.

    팩을 가져오기 전에 `failproofai policies show <owner>/<repo>`로 내용을 확인하고, 일부만 가져오는 방법은 [정책 팩](/ko/policies/packs)을 참조하세요.

    이 단계를 실행하기 전까지는 `block-failproofai-commands`만 적용됩니다 — 에이전트가 Failproof AI를 끄는 것을 방지하는 항상 켜진 가드입니다. `failproofai policies`로 활성화된 항목을 확인하세요.
  </Step>
  <Step title="동작 감사">
    [첫 번째 오류 검사 실행](/ko/start/first-audit)을 따르세요. "에이전트가 접근 방식을 변경하지 않고 실패한 툴을 재시도한 세션 찾기"와 같이 구체적인 목표를 사용하세요.
  </Step>
  <Step title="오류 방지">
    [정책으로 첫 번째 오류 방지](/ko/start/first-policy)를 따르세요. 관찰 모드로 시작하고, 매칭 항목을 검사한 다음, 검토된 버전을 적용하세요.
  </Step>
</Steps>

## Jev 설정

[Jev](/ko/start/use-jev)를 사용하면 완료된 세션을 알려진 답변이 있는 질문에 대해 채점하거나, 실행 전에 컨텍스트 내 툴 호출을 검토할 수 있습니다. **Jev 사용** 페이지에서 두 가지 설정 경로를 모두 확인할 수 있습니다.
