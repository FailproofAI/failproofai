머신 한 대에 Failproof AI를 설정한 다음, 로컬로 유지하거나 Cloud에 연결하세요.

에이전트가 [지원되는 하네스](/ko/reference/harnesses)에서 실행된다면 아래 단계를 따르세요. LangChain, CrewAI, LlamaIndex, Pydantic AI 또는 자체 런타임으로 구축된 에이전트는 [에이전트 계측](/ko/start/integrations)부터 시작하세요.

## 에이전트가 설정을 안내하도록 하기

호환되는 에이전트에 Failproof AI 우산 스킬을 설치하세요:

```bash
npx skills add FailproofAI/skills
```

이 명령은 우산 스킬과 전문 하위 스킬들을 설치합니다. 우산 스킬만 원한다면 `--skill
failproofai`를 사용하세요. 로컬 및 Cloud 설정, 데몬 상태, 세션, 감사, 정책, 문제 해결을 이해하며, 작업을 안내하고 전문 작업을 적합한 Failproof AI 스킬로 라우팅합니다. 아래의 CLI 설치를 대체하지는 않습니다.

## 머신 설정

<Steps>
  <Step title="Failproof AI 설치 및 구성">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    설정 과정에서 백그라운드 서비스를 설치하고 찾은 모든 지원 에이전트를 연결합니다. 관리자 권한을 한 번 요청할 수 있습니다. Linux와 macOS를 지원합니다.
  </Step>

  <Step title="정책 선택">
    설정 시 기본적으로 정책 팩이 선택되지 않습니다. Failproof AI 팩을 추가하세요:

    ```bash
    failproofai policies add FailproofAI/policies
    failproofai policies
    ```

    두 번째 명령은 이 머신의 모든 정책과 활성화 여부를 보여줍니다. 팩을 추가하기 전까지는 `block-failproofai-commands`만 실행됩니다.
  </Step>

  <Step title="머신 상태 확인">
    ```bash
    failproofai config --status
    ```

    서비스, Cloud 연결, 일시 정지 상태를 보고합니다.
  </Step>
</Steps>

## 로컬 또는 Cloud 선택

<Tabs>
  <Tab title="로컬 유지">
    계정이 필요하지 않습니다.

    ```bash
    failproofai
    failproofai audit
    ```

    첫 번째 명령은 `http://localhost:8020`에서 로컬 대시보드를 엽니다. 두 번째 명령은 이 머신에 이미 있는 에이전트 기록을 스캔합니다.
  </Tab>

  <Tab title="Cloud 연결">
    Failproof AI Cloud에서 머신 키를 생성한 다음 실행하세요:

    ```bash
    failproofai config --token <machine-key>
    failproofai config --status
    ```

    Cloud는 정책 결정과 세션 기록을 수신합니다. 결정만 전송하려면 먼저 연결한 후 `~/.failproofai/config.json`에서 `collector.sessions`를 `false`로 설정하세요. 현재 `--no-transcripts` 설정 플래그는 해당 설정을 적용하지 않습니다. 공유 셸과 CI에서는 키를 명령 기록에 남기지 않도록 `FAILPROOFAI_CLOUD_TOKEN`을 사용하세요.
  </Tab>
</Tabs>

## 검증하기

에이전트 중 하나를 실행하고 일반적인 작업을 수행하도록 요청하세요. 그런 다음:

도구 호출 거부는 지원되는 12개 하네스 모두에서 검증됩니다. 턴 종료 강제 적용은 8개에서 검증되며, 그 외 하네스-이벤트 조합은 관찰 전용이거나 미검증일 수 있습니다.

- 로컬 대시보드의 **Policies → Activity**를 열어 정책 결정을 확인하세요.
- Cloud의 **Observe → Sessions**를 열어 전체 실행 내역을 확인하세요.
- `failproofai audit`를 실행하여 위험하거나 낭비적인 패턴을 찾아보세요.

<Warning>
  설정 후 `failproofaid` 서비스가 평가자 역할을 합니다. 서비스가 응답할 수 없으면 보호된 작업이 거부됩니다. 에이전트가 예기치 않게 멈출 경우 `failproofai config --status`를 실행하세요.
</Warning>
