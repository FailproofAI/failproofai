Failproof AI는 단일 머신에서 완전히 실행하거나, Cloud에 연결하여 세션 공유 및 정책 관리를 사용할 수 있습니다.

## 로컬 설치 (계정 불필요)

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai
```

이 명령은 서비스를 설치하고, 지원되는 에이전트를 연결하며, 정책 팩을 추가한 뒤 `http://localhost:8020`에서 대시보드를 엽니다.

`failproofai audit`을 실행하면 이미 해당 머신에 있는 에이전트 기록을 스캔할 수 있습니다.

## Failproof AI Cloud 연결

Cloud에서 머신 키를 생성한 후 다음 명령을 실행하세요:

```bash
failproofai config --token <machine-key>
failproofai config --machine-label checkout-runner-01
failproofai policies add FailproofAI/policies
failproofai config --status
```

또는 `FAILPROOFAI_CLOUD_TOKEN=<machine-key>`를 환경 변수로 내보낸 뒤 `failproofai config`만 실행해도 됩니다. 공유 머신이나 CI 환경에서는 환경 변수 방식을 권장합니다. 키가 셸 히스토리나 프로세스 목록에 남지 않기 때문입니다.

Cloud 연결은 두 가지 역할을 하나의 연결로 처리합니다:

- 이 머신에 할당된 정책을 가져옵니다.
- 정책 결정 내역과 세션 트랜스크립트를 전송합니다.

결정 내역만 전송하려면 먼저 연결한 후 `~/.failproofai/config.json`에서 `collector.sessions`를 `false`로 설정하세요. `--no-transcripts`는 사용하지 마세요. 현재 설정 경로에서 해당 플래그를 파싱하지만 실제로 적용되지 않습니다. 자세한 내용은 [이벤트 및 설정](/ko/reference/events-and-configuration#machine-configuration)을 참고하세요.

<Note>
  `--machine-label`은 이미 연결된 머신의 이름을 변경합니다. 최초 연결 명령이 아닌, 설정 명령 이후에 실행하세요.
</Note>

## 비대화형 설치

`failproofai config`는 별도의 비대화형 플래그가 필요하지 않습니다. CI 환경이나 컨테이너에서도 프롬프트 없이 요청된 설정을 적용합니다.

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

백그라운드 서비스를 설치할 때는 관리자 권한이 한 번 필요합니다. 설치 과정에서 대화형 `sudo` 비밀번호 프롬프트는 표시되지 않습니다. 비밀번호 없이 성공하거나, 관리자가 직접 실행해야 할 명령을 출력합니다.

## 플랫폼 지원

설치는 Linux 및 macOS를 지원합니다. 지원하지 않는 플랫폼에서는 훅이나 부분적인 설정 상태를 기록하지 않고 종료됩니다.
