Deploy a reviewed policy to one machine at a time. Start in observe mode.

## Roll out from the CLI

```bash
fp policies test ./rule.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish no-force-push ./rule.mjs
fp fleet deploy <machine> --add no-force-push:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add no-force-push:enforce
```

Observe mode evaluates the real policy and records non-allow decisions, but does not block the agent.

<Warning>
  A bare `--add no-force-push` enforces immediately. Add `:observe` for a shadow rollout.
</Warning>

If enforcement causes problems:

```bash
fp fleet history <machine>
fp fleet rollback <machine> <generation>
```

## Deploy from the dashboard

1. Go to **Admin → enforcement**.
2. Open the target machine.
3. Add the policy version with effect **observe**.
4. Apply the deployment.
5. Review results under **Observe → policy**.
6. Promote the same version to **enforce** when the matches are correct.

![The machine deployment editor with policy versions, enforce and observe effects, and the apply deployment action.](/images/dashboard/enforcement-editor.png)

## Replace or pre-stage a set

- `--remove <id>` removes one policy.
- `--set <ref>...` replaces the complete policy set.
- `--create` prepares a deployment before a machine first checks in.
- `fp fleet diff <machine>` compares intended and applied state.

<Note>
  Without Cloud, publish a pack with `failproofai publish --effect observe` and inspect decisions in the local dashboard.
</Note>

Machines need `policies:pull` to receive deployments and `events:add` to report decisions.
