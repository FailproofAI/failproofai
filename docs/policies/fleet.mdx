title: "Fleet coverage"
description: "See which machines received and applied the intended policies."

---

Fleet coverage compares what Cloud assigned with what each machine last applied.

## Check a machine

```bash
failproofai config --status
failproofai flush --wait --timeout 120
```

From Cloud:

```bash
fp fleet list
fp fleet diff
fp fleet show <machine-id>
```

`fp fleet` requires a signed-in session, not an API key.

| Command | What it does |
| --- | --- |
| `fp fleet list` | List machines and deployment state |
| `fp fleet show <machine>` | Show one machine's policy set |
| `fp fleet deploy <machine> --add <ref>` | Add or update one policy |
| `fp fleet deploy <machine> --remove <id>` | Remove one policy |
| `fp fleet deploy <machine> --set <ref>...` | Replace the whole set |
| `fp fleet diff [machine]` | Compare intended and applied versions |
| `fp fleet history <machine>` | List deployment generations |
| `fp fleet rollback <machine> <generation>` | Restore a generation |
| `fp fleet rename <machine> "<label>"` | Change the Cloud label |

<Warning>
  `--set` replaces the complete policy set. A bare `--add <id>` enforces a new policy immediately. Use `--add <id>:observe` for a shadow rollout.
</Warning>

## Observe, then enforce

```bash
fp fleet deploy ci-runner-01 --add prod-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add prod-guard:enforce
```

Observe mode evaluates the real policy and records non-allow decisions without blocking the agent.

## Machine identity

The machine ID is stable and identifies the machine. The label is display-only and can change:

```bash
failproofai config --machine-label checkout-runner-03
fp fleet rename <machine-id> "Checkout runner 03"
```

Changing the label does not reconnect or re-key the machine.
