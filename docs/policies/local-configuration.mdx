Use scope to decide who receives a local policy:

| Scope | Applies to |
| --- | --- |
| `user` | Your supported agents on this machine |
| `project` | Agents running in this project |
| `local` | Claude only, in the local project settings |
| `all` | Uninstall only |

```bash
failproofai policies add block-sudo --scope user
failproofai policies add block-rm-rf --scope project
```

Hermes and OpenClaw support user scope only. Most other harnesses support user and project. Claude also supports local scope. See [Harnesses](/reference/harnesses).

## Policy parameters

Policy settings live in `policies-config.json` at the matching scope. Use the local dashboard's **Policies → Configure** view when possible.

A parameter belongs to one policy and changes how that policy decides. For example, an allow-list can make a blocking policy accept known-safe commands or paths.

Custom policy files can be loaded automatically from `.failproofai/policies/`, or explicitly:

```bash
failproofai policies -i -c ./guards.mjs --scope project
```

Remove explicit paths with:

```bash
failproofai policies -u -c
```

## Files

| File | Purpose |
| --- | --- |
| `~/.failproofai/config.json` | Machine and collector settings |
| `policies-config.json` | Enabled policies and parameters for a scope |
| `.failproofai/policies/*policies.mjs` | Convention-loaded policies |
| `~/.failproofai/policies/packs/installed.json` | Installed packs and selections |

Do not edit installed pack artifacts directly. Reinstall or publish a corrected release.
