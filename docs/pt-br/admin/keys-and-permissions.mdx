Use uma chave separada para cada pessoa, máquina ou tarefa de automação. Conceda apenas as permissões necessárias.

## Criar e rotacionar uma chave

Use **Admin → Keys**, ou o Cloud CLI:

```bash
fp keys list
fp keys create "audit automation" --add audits:read
fp keys disable "audit automation"
```

Guarde o segredo no momento em que ele for criado; ele não será exibido novamente. Rotacione criando uma chave substituta, atualizando o consumidor e, em seguida, desativando a chave antiga.

## Chaves de máquina

Uma chave de máquina conecta o serviço local ao Cloud:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Uma máquina conectada pode precisar de duas capacidades:

- `policies:pull` para receber políticas gerenciadas pelo Cloud.
- `events:add` para enviar decisões e sessões.

O Status reporta essas capacidades separadamente, pois uma pode funcionar enquanto a outra não.

## Permissões comuns

| Permissão | Permite |
| --- | --- |
| `events:add` | Enviar eventos |
| `events:read` | Ler eventos e erros |
| `evaluations:read` | Ler sessões e avaliações |
| `audits:read` / `audits:write` | Revisar ou gerenciar auditorias |
| `policies:read` / `policies:write` | Revisar ou implantar políticas |
| `policies:pull` | Obter atribuições de políticas da máquina |
| `keys:create` / `keys:disable` | Criar ou desativar chaves |
| `orgs:admin` | Administração de organização em nível de instância; não atribuível a uma chave de organização |

Alguns comandos administrativos do `fp fleet` e `fp guardrails` exigem uma sessão de usuário autenticada em vez de uma chave de API. O texto de ajuda desses comandos indica isso antes de realizar qualquer requisição.

<Warning>
  Nunca reutilize credenciais de ingestão como `AGENTEYE_KEY` ou `AGENTEYE_API_KEY` como `FP_API_KEY`. Elas pertencem a sistemas e permissões diferentes.
</Warning>
