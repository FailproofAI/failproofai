Administração é a parte Cloud do Failproof AI. Organizações, membros, chaves de API, configurações da organização e consumo medido precisam de uma conexão com a Cloud.

<Note>
  O Failproof AI também funciona sem nenhuma conta. Uma máquina local aplica políticas, mantém seu histórico de sessão em disco, serve o [painel local](/pt-br/reference/local-dashboard) em `localhost:8020` e executa `failproofai audit` sem enviar nada para lugar algum. Consulte [configuração da máquina](/pt-br/reference/events-and-configuration#machine-configuration) para as chaves `collector` locais. Ignore o restante desta seção se você não estiver usando a Cloud.
</Note>

## Onde ficam os controles

<Tabs>
  <Tab title="Dashboard">
    O grupo **admin** na barra lateral da Cloud contém **editor de políticas**, **enforcement**, **uso**, **chaves**, **usuários** e **configurações**.

    ![O grupo admin da barra lateral da Cloud com editor de políticas, enforcement, uso, chaves, usuários e configurações.](/images/dashboard/admin-navigation.png)
  </Tab>
  <Tab title="CLI">
    Instale o CLI da Cloud como uma ferramenta isolada e faça login:

    ```bash
    uv tool install fp-cloud-cli
    fp login
    fp whoami
    fp usage
    ```

    Coloque as opções globais antes do comando, por exemplo `fp --org reliability-team --json usage`.
  </Tab>
</Tabs>

## Usuário autenticado ou chave de API

O `fp` opera em um de dois modos de autenticação, e essa distinção determina quais comandos funcionam. Um comando que uma chave de API não pode executar é recusado antes de abrir uma conexão e exibe o motivo, em vez de deixar um 401 ou 403 falar por si.

| Comando | Chave de API | Permissão |
| --- | --- | --- |
| `fp whoami` | Sim | nenhuma |
| `fp usage` | Sim | `usage:read` |
| `fp keys list` / `show` | Sim | `keys:read` |
| `fp keys create` | Sim | `keys:create` |
| `fp keys disable` | Sim | `keys:disable` |
| `fp keys regenerate` | Sim | `keys:regenerate` |
| `fp keys update` | Não | `keys:update`, que nenhuma chave pode ter |
| `fp users list` / `show` | Sim | `users:read` |
| `fp users create` | Sim | `users:create` |
| `fp users update` | Sim | `users:update` |
| `fp users disable` / `enable` | Sim | `users:delete` |
| `fp settings list` / `schema` | Sim | `settings:read` |
| `fp settings set` | Sim | `settings:write` |
| `fp orgs list` / `switch` / `current` / `perms` | Não | somente sessão autenticada |

`fp usage` é o comando ideal para scripts de relatório: executa de forma autônoma com uma chave e requer apenas `usage:read`.
