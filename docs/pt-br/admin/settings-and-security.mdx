As configurações da organização afetam todos os membros dessa organização no Cloud. Altere-as em **Admin → settings** ou com `fp settings`.

```bash
fp settings list
fp settings set <key> <value>
```

## Tratamento de dados

Por padrão, uma máquina conectada envia decisões de política e transcrições completas de sessão. Para enviar apenas as decisões, defina `collector.sessions` como `false` no arquivo `~/.failproofai/config.json` da máquina após a conexão. A flag de configuração `--no-transcripts` não aplica essa configuração.

As credenciais são removidas na máquina antes do envio, mas a redação é uma camada de segurança mínima — não um substituto para controle de acesso.

O uso exclusivamente local não requer uma conta. O histórico de sessões e as auditorias permanecem na máquina, exceto que auditorias locais agendadas enviam a identidade da máquina e um resumo limitado após você optar por isso. A telemetria anônima da CLI pode ser desativada com `FAILPROOFAI_TELEMETRY_DISABLED=1`.

## Credenciais

Os tokens de máquina são armazenados em `~/.failproofai/` com permissões exclusivas do proprietário. Eles não são gravados na definição do serviço.

Use chaves separadas para pessoas, automações e máquinas. Conceda a cada uma apenas as permissões necessárias, faça a rotação ao mudar de responsável e revogue ao desativar a máquina ou o fluxo de trabalho.

## Lista de verificação

- Exija as permissões mínimas necessárias.
- Defina `collector.sessions` como `false` onde o conteúdo completo não for necessário.
- Revise quem pode implantar políticas de aplicação.
- Teste as políticas no modo de observação antes de aplicá-las.
- Mantenha os rótulos de máquinas claros e os IDs de máquinas estáveis.
- Execute `failproofai config --status` após alterar as configurações de conexão.

Consulte [chaves e permissões](/pt-br/admin/keys-and-permissions) para o catálogo de permissões.
