O OpenTelemetry permite enviar traces, logs e métricas de agentes para o FailproofAI Cloud usando o protocolo padrão OTLP/HTTP. É opcional. Suas integrações existentes com o FailproofAI continuam funcionando sem precisar habilitá-lo.

## Ativar a ingestão para sua organização

Um administrador da organização acessa **Settings → OpenTelemetry** e ativa a ingestão. Use uma chave de API do Cloud com a permissão `events:add`, a mesma utilizada para o envio de relatórios de agentes.

Se a ingestão estiver desativada, o Cloud recusará as exportações OTLP, portanto `failproofai otel enable` não terá efeito e seus agentes continuarão enviando sessões da forma habitual. Execute `failproofai otel status` para verificar a configuração da organização e solicite a um administrador que a ative.

## Conectar um agente de codificação

Conecte sua máquina com `failproofai config` e escolha um agente:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

O comando de configuração é compatível com Claude Code, Codex e Copilot e escolhe automaticamente entre o Cloud ou um relay local autenticado, conforme necessário. O Copilot usa o relay local automaticamente. Inicie o daemon do FailproofAI configurado antes de usar o relay.

Se o FailproofAI já envia transcrições de sessão de um agente, o processo de configuração perguntará se você deseja migrar esse agente para OTEL. O padrão é Não. Ao aceitar, o envio de transcrições para esse agente será interrompido; isso não altera a aplicação de políticas nem os relatórios de outros agentes.

## Conectar uma aplicação

Use a instrumentação OpenTelemetry da sua aplicação com estas variáveis de ambiente:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

O endpoint é a base OTLP do Cloud, `https://app.befailproof.ai/otel`; seu exportador adiciona automaticamente `/v1/traces`, `/v1/logs` ou `/v1/metrics`. Variáveis por sinal, como `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, são usadas como estão, portanto precisam do caminho completo, por exemplo `https://app.befailproof.ai/otel/v1/logs`.

Substitua `<key>` pela sua chave de API. Mantenha o segredo fora do histórico do shell, gravações de tela e arquivos de configuração commitados. Em uma máquina configurada, `failproofai otel env --service my-agent` exibe o bloco com a chave existente. A saída contém uma credencial.

O Cloud aceita exportações OTLP/HTTP de traces, logs e métricas, em protobuf ou JSON, incluindo requisições comprimidas com gzip. OTLP/gRPC não é suportado.

As métricas são confirmadas por compatibilidade com exportadores, mas não são armazenadas nem exibidas. Traces de agentes e logs de agentes de codificação suportados tornam-se sessões; campos que o agente não exporta permanecem ausentes.

## Capturar texto de prompts

<Warning>
A captura de texto pode incluir prompts, argumentos de ferramentas e outros conteúdos sensíveis. `failproofai otel enable` ativa essa captura. Adicione `--no-content` para manter a captura de prompts e detalhes de ferramentas desativada.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Para um agente configurado manualmente, use os próprios controles de captura de conteúdo do agente:

<Tabs>
  <Tab title="Claude Code">
    Adicione estas variáveis ao ambiente do seu agente junto com o bloco da aplicação acima:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Defina ambas as variáveis de conteúdo como `0` para evitar a captura de prompts e detalhes de ferramentas.
  </Tab>
  <Tab title="Codex">
    Na configuração de usuário do Codex, utilize suas configurações de OTEL:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    O conteúdo das conversas do Codex fica nos logs; deixe os traces internos de runtime e as métricas desativados. O Codex usa o endpoint completo que você fornecer. Defina `log_user_prompt` como `false` para excluir os prompts; o comando de configuração preserva um `false` explícito.
  </Tab>
  <Tab title="Gemini CLI">
    Use as configurações de telemetria do Gemini com o relay local:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    O Gemini CLI não é suportado pelo `failproofai otel enable`. Configure-o manualmente com um collector autenticado próprio. Defina `logPrompts` como `false` para desativar a captura de prompts.
  </Tab>
  <Tab title="Copilot in VS Code">
    Use estas configurações de usuário do VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Execute `failproofai otel enable copilot` para habilitar o relay autenticado. Defina `captureContent` como `false` para omitir o conteúdo.
  </Tab>
</Tabs>

## Verificar ou desfazer a configuração

```bash
failproofai otel status
failproofai otel disable all
```

O status distingue as configurações gerenciadas pelo FailproofAI da telemetria configurada em outro lugar. O comando disable restaura as configurações gerenciadas anteriores e a escolha prévia de envio de transcrições do agente.
