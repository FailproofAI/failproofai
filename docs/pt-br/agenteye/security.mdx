O Failproof AI Observability foi desenvolvido para operar próximo aos seus agentes em produção, o que significa que ele tem acesso aos seus prompts, entradas de ferramentas e saídas. Esta página explica como os dados são mantidos isolados, controlados e sob o seu domínio. Se você está avaliando o Failproof AI Observability para uma revisão de segurança, comece por aqui.

---

## Seus dados permanecem no seu ambiente

O Failproof AI Observability é auto-hospedado. Eventos, prompts, respostas do modelo e análises são armazenados nos seus próprios bancos de dados, no seu próprio ambiente. Nada é enviado a um SaaS de terceiros para armazenamento, e seus dados permanecem na sua própria conta na nuvem.

---

## Isolamento de tenants

Uma única instância do Failproof AI Observability pode hospedar várias organizações, e cada uma é isolada na camada de armazenamento — garantido pelo banco de dados, não apenas pela interface:

- Os dados operacionais de uma organização (usuários, chaves, dashboards, consultas salvas) são restritos àquela org, e leituras entre organizações são bloqueadas pelo próprio banco de dados.
- Cada evento ingerido é marcado com a organização proprietária, de modo que os eventos de uma organização nunca podem ser lidos por outra.

Cada rota de dashboard é delimitada por um slug de organização (`/<org-slug>/…`).

---

## Autenticação

O Failproof AI Observability utiliza autenticação sem senha, baseada em e-mail. Não há senha para ser roubada ou vazada. O usuário solicita um código de uso único (ou um magic link de um clique), que é enviado por e-mail e expira rapidamente. O acesso é controlado por uma **lista de permissões**: somente endereços de e-mail (ou domínios) que você autorizar poderão se autenticar.

## Acesso restrito com chaves de API

Cada cliente se autentica com uma chave de API que possui permissões granulares e de menor privilégio. Um coletor precisa apenas de `events:add`; uma chave de dashboard ou assistente pode ser somente leitura; ações destrutivas (excluir, regenerar) são concessões separadas que você escolhe incluir.

![A página de chaves de API: as permissões de cada chave, com código de cores por escopo de leitura, escrita e destrutivo](/agenteye/images/api-keys.png)

Mantenha a chave bootstrap de administrador para a configuração inicial e emita chaves com escopo reduzido para todo o restante. Consulte [Chaves de API](/pt-br/agenteye/api-keys).

---

## Um assistente somente leitura com aprovação obrigatória

O [assistente de IA](/pt-br/agenteye/assistant) integrado ao dashboard responde a perguntas sobre seus dados, mas é restrito por design:

- É **somente leitura por padrão**: o SQL que executa passa por uma proteção que permite apenas consultas `SELECT`/`WITH`, instrução única, com limite de linhas.
- Tudo o que ele cria (uma consulta salva, um dashboard) é **sujeito à aprovação**: você analisa e aprova cada escrita antes que ela aconteça.
- Ele **nunca pode excluir**.

Assim, um colega de equipe pode perguntar "quais agentes apresentaram mais erros esta semana?" e agir com base na resposta, sem que o assistente possa alterar ou remover seus dados por conta própria.

## Em trânsito

Todo o tráfego ocorre via HTTPS. Você encerra o TLS com seus próprios certificados, de modo que o tráfego entre coletor e servidor e entre navegador e servidor é criptografado em trânsito.
