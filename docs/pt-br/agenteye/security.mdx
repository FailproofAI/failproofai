O Failproof AI Observability foi projetado para ficar próximo dos seus agentes em produção, o que significa que ele vê seus prompts, entradas de ferramentas e saídas. Esta página explica como ele mantém esses dados isolados, controlados e nas suas mãos. Se você está avaliando o Failproof AI Observability para uma revisão de segurança, comece por aqui.

---

## Seus dados ficam no seu ambiente

O Failproof AI Observability é self-hosted. Eventos, prompts, respostas de modelos e análises são armazenados nos seus próprios bancos de dados, no seu próprio ambiente. Nada é enviado para um SaaS de terceiros para armazenamento, e seus dados permanecem na sua própria conta de nuvem.

---

## Isolamento de tenants

Uma única instância do Failproof AI Observability pode hospedar muitas organizações, e cada uma é isolada na camada de armazenamento — garantido pelo banco de dados, não apenas pela interface:

- Os dados operacionais de uma organização (usuários, chaves, dashboards, consultas salvas) têm escopo definido para aquela organização, e leituras entre organizações são bloqueadas pelo próprio banco de dados.
- Cada evento ingerido é marcado com a organização proprietária, portanto os eventos de uma organização jamais podem ser lidos por outra.

Cada rota de dashboard tem escopo definido sob um slug de organização (`/<org-slug>/…`).

---

## Login

O Failproof AI Observability utiliza login sem senha, baseado em e-mail. Não há senha para ser roubada por phishing ou vazada. O usuário solicita um código de uso único (ou um magic link de um clique), que é enviado por e-mail e expira rapidamente. O login é controlado por uma **lista de permissões**: somente endereços de e-mail (ou domínios) que você autorizar poderão se autenticar.

## Acesso com escopo via API keys

Cada cliente se autentica com uma API key que possui permissões granulares com privilégio mínimo. Um coletor precisa apenas de `events:add`; uma chave de dashboard ou assistente pode ser somente leitura; ações destrutivas (deletar, regenerar) são concessões separadas que você escolhe incluir.

![A página de API keys: concessões de permissão de cada chave, codificadas por cores conforme o escopo de leitura, escrita e destrutivo](/agenteye/images/api-keys.png)

Mantenha a chave de bootstrap de administrador para a configuração inicial, e emita chaves com escopo restrito para todo o restante. Veja [API keys](/pt-br/agenteye/api-keys).

---

## Um assistente somente leitura com aprovação obrigatória

O [assistente de IA](/pt-br/agenteye/assistant) no dashboard responde perguntas sobre seus dados, mas é limitado por design:

- É **somente leitura por padrão**: seu SQL é executado por meio de um guard que permite apenas consultas `SELECT`/`WITH`, instrução única, com limite de linhas.
- Tudo o que ele cria (uma consulta salva, um dashboard) requer **aprovação**: você revisa e aprova cada escrita antes que ela aconteça.
- Ele **jamais pode deletar**.

Assim, um colega pode perguntar "quais agentes apresentaram mais erros esta semana?" e agir com base na resposta, sem que o assistente consiga alterar ou remover seus dados por conta própria.

---

## Em trânsito

Todo o tráfego é transmitido via HTTPS. Você encerra o TLS com seus próprios certificados, de modo que o tráfego de coletor para servidor e de navegador para servidor é criptografado em trânsito.
