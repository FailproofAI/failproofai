Uma auditoria pesquisa um conjunto selecionado de sessões com um objetivo de falha definido. Ela combina evidências de traces, resultados de avaliações, correspondências de políticas e contexto de referência para produzir descobertas sobre as quais você pode agir.

Veja como uma auditoria vai desde uma execução agendada até falhas embasadas em evidências que você pode corrigir.

## Abrir auditorias

<Tabs>
  <Tab title="Dashboard">
    Acesse **Analyze → Audits**. A página exibe o estado do agendamento, descobertas abertas, última execução, próxima execução, cadência e se a auditoria possui um briefing ou páginas de referência. Selecione um card para acessar as configurações e o histórico de execuções; selecione **new audit** para criar uma nova.

    ![A página de Audits exibindo auditorias recorrentes com seu agendamento, sensibilidade e estado de execução.](/images/dashboard/audits.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

Use uma auditoria quando precisar responder a uma pergunta em nível de população, como:

- Em quais pontos os agentes abandonam tarefas sem escalar?
- Quais falhas de ferramenta levam a novas tentativas ineficazes?
- Os agentes estão acessando dados fora do fluxo de trabalho previsto?
- O que mudou após a publicação de um modelo, prompt ou ferramenta?

## Fluxo de resposta de auditoria

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert for recurrence
```

Uma descoberta deve nomear o modo de falha e apontar para as evidências. Uma issue gerencia a remediação. Uma política previne um padrão de ação conhecido; um alerta detecta recorrência quando a prevenção não é possível ou requer monitoramento.
