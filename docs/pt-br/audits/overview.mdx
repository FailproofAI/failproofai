## Local ou na Nuvem

| | Auditoria local | Auditoria na nuvem |
| --- | --- | --- |
| Comando | `failproofai audit` | `fp audits` |
| Lê | Histórico de agentes nesta máquina | Sessões na sua organização na nuvem |
| Produz | Resultados locais em `localhost:8020/audit` | Conclusões, problemas e alertas compartilhados |
| Requer | Nenhuma conta | Conexão com a nuvem e chave de API |

Use uma auditoria local para uma revisão rápida de uma única máquina. Use a nuvem quando uma equipe precisar de auditorias recorrentes em múltiplos agentes e máquinas.

## Perguntas que uma auditoria pode responder

- Em quais pontos os agentes param sem escalar o problema?
- Quais falhas de ferramentas levam a novas tentativas ineficazes?
- Os agentes estão acessando dados fora do fluxo de trabalho pretendido?
- O que mudou após uma atualização de modelo, prompt ou ferramenta?

## Abrir auditorias na nuvem

Acesse **Analyze → Audits** ou use:

```bash
fp audits list
fp audits show <audit-name>
fp audits findings --status open --limit 20
```

Os comandos de auditoria utilizam o nome ou o ID completo da auditoria. As conclusões são referenciadas pelo seu próprio ID.

## Da conclusão à prevenção

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert
```

Uma conclusão aponta para evidências. Um problema define a resposta. Uma política previne um padrão de ação conhecido; um alerta monitora recorrências.

Nem toda conclusão precisa se tornar uma política. Uma conclusão do tipo `policy` descreve uma regra que pode ser aplicada. Uma conclusão do tipo `failure` ou `improvement` pode exigir uma mudança no fluxo de trabalho, no prompt, no modelo ou na ferramenta.
