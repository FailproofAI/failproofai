A qualidade de uma auditoria começa pelo seu escopo. Uma solicitação ampla como "encontre problemas" produz resultados menos úteis do que uma pergunta de falha concreta.

## Configurar a auditoria

<Tabs>
  <Tab title="Dashboard">
    1. Acesse **Analyze → Audits → New audit** e insira o nome e a descrição.
    2. Defina a cadência, a janela de tempo, o escopo de agente/ambiente, erros ignorados, sensibilidade e número máximo de achados.
    3. Em **agents**, adicione ou revise o contexto do agente, depois adicione o briefing do operador e quaisquer URLs de referência HTTPS públicas.
    4. Escolha os canais de notificação e selecione **create audit**. A primeira execução é enfileirada imediatamente.

    ![O formulário de nova auditoria com nome, descrição, cadência, janela, escopo de ambiente e agente, erros ignorados, configurações de análise, briefing, páginas de referência e canais de notificação.](/images/dashboard/audit-new.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits create checkout-reliability \
      --description "Find checkout failures that agents do not recover from" \
      --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
      --schedule-interval-secs 86400 \
      --window-mode since_last \
      --sensitivity medium \
      --text-file ./checkout-audit-brief.txt \
      --url https://runbooks.example.com/checkout
    ```

    A primeira execução é enfileirada imediatamente. Inclua o briefing e as URLs de referência durante a criação para que a execução os receba.

    Consulte a referência completa de [`fp audits create`](/pt-br/reference/cloud-cli#audits).
  </Tab>
</Tabs>

<Tip>
  Comece com uma sessão com falha conhecida e várias sessões normais. Isso fornece à auditoria tanto um exemplo positivo quanto um conjunto de comparação.
</Tip>

<Info>
  O contexto da auditoria é armazenado como um recurso próprio, de modo que editar uma auditoria não remove acidentalmente o material de referência.
</Info>
