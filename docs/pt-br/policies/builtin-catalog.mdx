38 das 39 políticas integradas são fornecidas como o pacote `FailproofAI/policies`; `block-failproofai-commands` vem compilada no pacote porque um pack não pode declarar `alwaysOn`. O pack instalado é a fonte verdadeira do que esta máquina pode impor:

```bash
failproofai policies show FailproofAI/policies   # o catálogo, como publicado
failproofai policies                             # o que está habilitado aqui
```

`failproofai policies` lista arquivos customizados, arquivos de convenção, packs instalados e atribuições Cloud. Não tem seção de integrados, portanto não consegue responder "quais integrados existem" — `policies show` e o [Policy Hub](https://befailproof.ai/policy-hub/FailproofAI/policies/) são onde essa pergunta é respondida.

## Padrões e como selecionar

Um simples `failproofai policies add FailproofAI/policies` ativa os padrões próprios do pack — as 10 linhas marcadas como **on** abaixo. `block-failproofai-commands` está ativada independentemente e não faz parte dessa seleção. `--all` ativa tudo; `--category <slug>` e `--policy <name>` selecionam um subconjunto. O slug ao lado de cada título é o que `--category` corresponde:

```bash
failproofai policies add FailproofAI/policies --category git,database
```

`block-failproofai-commands` está **sempre ativa**. Ela se registra em toda avaliação, esteja ou não presente na sua seleção, e não pode ser desativada ou pausada — uma proteção contra o agente desligar a aplicação que o próprio agente pode desligar não é uma proteção. Um pack não pode declarar `alwaysOn`, razão pela qual esta política específica vem compilada no pacote em vez de fazer parte do pack.

## Sanitização — `sanitize`

Essas políticas rodam no `PostToolUse`, após a ferramenta já ter executado. Elas **detectam e recusam o resultado da ferramenta**; não redatam uma substring e devolvem o restante.

Uma recusa aqui só chega ao modelo nos harnesses que consomem um veredito `PostToolUse` — **codex** e **copilot**, onde o motivo substitui todo o resultado da ferramenta. No claude, cursor, opencode, pi, hermes, openclaw, factory, devin, antigravity e goose, `PostToolUse` é somente observação: a detecção é registrada e a saída ainda chega ao modelo.

| Política | Gatilho | Padrão | Resultado |
| --- | --- | --- | --- |
| `sanitize-jwt` | `PostToolUse` | on | Recusar um resultado de ferramenta contendo um JWT. |
| `sanitize-api-keys` | `PostToolUse` | on | Recusar um resultado de ferramenta contendo uma chave OpenAI, Anthropic, GitHub, AWS, Stripe ou Google. |
| `sanitize-connection-strings` | `PostToolUse` | on | Recusar um resultado de ferramenta contendo uma string de conexão de banco de dados com credenciais embutidas. |
| `sanitize-private-key-content` | `PostToolUse` | on | Recusar um resultado de ferramenta contendo conteúdo de chave privada PEM. |
| `sanitize-bearer-tokens` | `PostToolUse` | on | Recusar um resultado de ferramenta contendo um token `Authorization: Bearer`. |

## Fluxo de trabalho — `workflow`

Todas as cinco rodam no `Stop` e estão desativadas por padrão.

| Política | Padrão | Resultado |
| --- | --- | --- |
| `require-commit-before-stop` | off | Recusar conclusão enquanto houver trabalho rastreado não commitado. |
| `require-push-before-stop` | off | Recusar conclusão enquanto houver commits apenas locais. |
| `require-pr-before-stop` | off | Exigir um pull request para a branch atual. |
| `require-no-conflicts-before-stop` | off | Exigir um merge limpo em relação à branch base configurada. |
| `require-ci-green-before-stop` | off | Exigir que as verificações de CI no commit HEAD atual passem, ignorando execuções obsoletas em commits anteriores. |

Essas precisam de um harness cujo veredito `Stop` seja consumido. Isso não se aplica a todos os harnesses:

| Harness | `Stop` |
| --- | --- |
| claude, codex, copilot, cursor, openclaw, factory, devin, antigravity | Verificado para bloquear: a recusa força outro turno |
| pi | Observação. O motivo é levado ao próximo turno como instrução, não como bloqueio |
| goose, hermes | Nenhum hook `Stop` é instalado, portanto estas cinco nunca disparam |
| opencode | Não verificado. `Stop` não está entre os eventos dos quais opencode consome um veredito |

VMs do Cursor Cloud Agent não executam hooks de stop, portanto uma sessão do Cursor nesse ambiente não tem cobertura, mesmo que o Cursor local tenha.

<Note>
  As políticas `warn-*` retornam `instruct`, não `deny`. (`prefer-package-manager` é a exceção entre os nomes que não começam com `block-*`: retorna `deny`, portanto bloqueia em todos os harnesses que consomem um veredito `PreToolUse` — o que inclui todos os doze.) No Hermes e Goose, no Pi, OpenClaw e Factory fora do canal `Stop`, e no Antigravity fora de `Stop` e `UserPromptSubmit`, `instruct` se degrada para allow com uma nota no stderr — o agente não é notificado. O `UserPromptSubmit` do Antigravity é um segundo canal real: a instrução é injetada como uma mensagem transitória antes de o modelo executar.
</Note>

## Referência de parâmetros

Configure parâmetros no objeto `policyParams` do escopo selecionado. Os tipos são validados por cada política.

| Política | Parâmetro | Tipo e padrão |
| --- | --- | --- |
| `sanitize-api-keys` | `additionalPatterns` | `pattern[]`, `[]`; entradas contêm `regex` e `label` |
| `block-read-outside-cwd` | `allowPaths` | `string[]`, `[]` |
| `block-sudo` | `allowPatterns` | `string[]`, `[]` |
| `block-rm-rf` | `allowPaths` | `string[]`, `[]` |
| Bloqueadores de infraestrutura | `allowPatterns` | `string[]`, `[]` |
| `block-secrets-write` | `additionalPatterns` | `string[]`, `[]` |
| `block-push-master` | `protectedBranches` | `string[]`, `["main", "master"]` |
| `block-work-on-main` | `protectedBranches` | `string[]`, `["main", "master"]` |
| `prefer-package-manager` | `allowed`, `blocked` | `string[]`, `[]` |
| `warn-large-file-write` | `thresholdKb` | `number`, `1024` |
| `require-push-before-stop` | `remote`, `baseBranch` | `string`, `"origin"`; `string`, `"main"` |
| `require-pr-before-stop` | `baseBranch` | `string`, `"main"` |
| `require-no-conflicts-before-stop` | `baseBranch` | `string`, `"main"` |

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status"]
    },
    "block-push-master": {
      "protectedBranches": ["main", "release"]
    }
  }
}
```

<Note>
  Um nome de política simples como chave em `policyParams` é aceito apenas para `FailproofAI/policies`. Para qualquer outro pack, a chave é `pack/<owner>/<repo>/<policy>` — um pack de terceiros que declare o mesmo nome de política recebe os padrões do schema, não os seus parâmetros.
</Note>

<Warning>
  Um padrão de permissão amplia o que um agente pode fazer. Teste a tokenização exata e as variantes de comando no harness alvo antes de implantá-lo em uma frota.
</Warning>
