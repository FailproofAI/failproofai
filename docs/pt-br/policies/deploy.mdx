Implante uma política revisada em uma máquina por vez. Comece no modo de observação.

## Publicar pelo CLI

```bash
fp policies test ./rule.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish no-force-push ./rule.mjs
fp fleet deploy <machine> --add no-force-push:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add no-force-push:enforce
```

O modo de observação avalia a política real e registra decisões que não sejam allow, mas não bloqueia o agente.

<Warning>
  Usar `--add no-force-push` sem sufixo aplica a política imediatamente. Adicione `:observe` para uma implantação em modo shadow.
</Warning>

Se a aplicação causar problemas:

```bash
fp fleet history <machine>
fp fleet rollback <machine> <generation>
```

## Implantar pelo dashboard

1. Acesse **Admin → enforcement**.
2. Abra a máquina de destino.
3. Adicione a versão da política com efeito **observe**.
4. Aplique a implantação.
5. Revise os resultados em **Observe → policy**.
6. Promova a mesma versão para **enforce** quando as correspondências estiverem corretas.

![O editor de implantação da máquina com versões de políticas, efeitos enforce e observe, e a ação de aplicar implantação.](/images/dashboard/enforcement-editor.png)

## Substituir ou pré-configurar um conjunto

- `--remove <id>` remove uma política.
- `--set <ref>...` substitui o conjunto completo de políticas.
- `--create` prepara uma implantação antes de a máquina fazer o primeiro check-in.
- `fp fleet diff <machine>` compara o estado pretendido com o estado aplicado.

<Note>
  Sem o Cloud, publique um pacote com `failproofai publish --effect observe` e inspecione as decisões no dashboard local.
</Note>

As máquinas precisam de `policies:pull` para receber implantações e de `events:add` para reportar decisões.
