Use o editor de políticas para transformar uma descoberta ou problema em uma regra publicável. Mantenha a criação separada da publicação para que um rascunho não possa alterar silenciosamente o comportamento em produção.

Quando um problema tem um padrão de ação repetível, abra-o em **Analyze → issues** e selecione **generate policy**. O Failproof AI primeiro explica se uma política pode expressar o problema, e então leva o contexto do intent revisado e da descoberta para o editor. O código gerado permanece como rascunho até que você o publique.

## Publicar uma versão de política

<Tabs>
  <Tab title="Dashboard">
    1. Vá para **Admin → policy editor** e, em **compose**, descreva o modo de falha ou cole o código-fonte da política em JavaScript.
    2. Valide o código-fonte e corrija todos os erros reportados.
    3. Insira a identidade da política e publique-a; em seguida, use **library** para comparar ou desativar versões.
    4. Selecione **enforcement** quando a versão estiver pronta para implantação em máquinas.

    ![A view de composição do editor de políticas com identidade da política, criação assistida por IA, validação do código-fonte e controles de publicação.](/images/dashboard/policy-editor.png)
  </Tab>
  <Tab title="CLI">
    Publique pela CLI com `fp policies publish`. O comando cria uma **nova versão** e nunca edita uma existente, além de verificar a sintaxe do código com node antes de enviar — nada downstream faz isso, portanto um erro de sintaxe só apareceria na máquina no momento da aplicação:

    ```bash
    fp policies test ./checkout.policy.mjs --command "git push --force" --expect deny
    fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
    ```

    Publicar não implanta nada — uma nova versão fica inativa até que `fp fleet deploy` a coloque em uma máquina. `fp policies compose "<plain English>"` cria um rascunho do código com o assistente Cloud e o exibe para revisão, sem publicá-lo.

    Para instalar uma política diretamente em um agente CLI local (não no Cloud), use `failproofai policies --install --custom ./checkout.policies.ts --cli claude --scope project`.
  </Tab>
</Tabs>

## Lista de verificação para criação de políticas

1. Nomeie o modo de falha em linguagem operacional.
2. Selecione os eventos de hook e as ferramentas que contêm evidências suficientes para decidir.
3. Escreva a condição mais restrita possível que corresponda ao comportamento inseguro.
4. Retorne uma mensagem que informe ao agente ou operador o que fazer a seguir.
5. Adicione exemplos que devem corresponder e exemplos que precisam permanecer permitidos.
6. Salve uma nova versão e solicite revisão.

Use `instruct` quando o agente puder corrigir o curso com segurança. Use `deny` quando permitir a ação criaria um risco inaceitável ou irreversível.

<Info>
  Versões de políticas são entradas de implantação imutáveis. Editar um rascunho cria uma nova versão; não deve reescrever a versão já atribuída às máquinas.
</Info>
