Após a configuração, o serviço local `failproofaid` é o único avaliador. Se ele não conseguir responder, as ações protegidas são negadas em vez de silenciosamente permitidas.

## Diagnosticar um bloqueio em nível de máquina

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

Execute `failproofai config` para reparar o serviço ou instalar a versão correspondente.

Dois tipos de falha podem parecer semelhantes:

| Falha | Significado |
| --- | --- |
| Serviço inacessível | O socket não possui um avaliador funcionando por trás dele |
| Incompatibilidade de versão | O CLI e o serviço discordam sobre o protocolo |

Ambos resultam em negação, mas o status os reporta separadamente.

## Um pack não carrega

Um pack selecionado que está ausente, alterado ou inválido nega os eventos cobertos por suas políticas selecionadas. Isso impede que um pack com problemas desapareça enquanto a máquina aparenta estar protegida.

`failproofai policies` indica o nome do pack e o erro de carregamento.

```bash
failproofai policies
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

Metadados ilegíveis ampliam a negação segura em vez de restringi-la com base em dados não confiáveis.

## O que continua disponível

O painel local e os comandos de status continuam funcionando enquanto a avaliação de políticas estiver falhando. Use-os para identificar o serviço, pack ou versão que precisa de reparo.

<Warning>
  Não contorne uma decisão de falha fechada excluindo arquivos do serviço ou do pack. Repare o serviço, reinstale o pack ou remova a atribuição pelo CLI para que a máquina retorne a um estado conhecido.
</Warning>
