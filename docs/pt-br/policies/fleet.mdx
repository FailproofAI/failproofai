A cobertura da frota compara o que o Cloud atribuiu com o que cada máquina aplicou por último.

## Verificar uma máquina

```bash
failproofai config --status
failproofai flush --wait --timeout 120
```

Pelo Cloud:

```bash
fp fleet list
fp fleet diff
fp fleet show <machine-id>
```

`fp fleet` requer uma sessão autenticada, não uma chave de API.

| Comando | O que faz |
| --- | --- |
| `fp fleet list` | Lista as máquinas e o estado de implantação |
| `fp fleet show <machine>` | Exibe o conjunto de políticas de uma máquina |
| `fp fleet deploy <machine> --add <ref>` | Adiciona ou atualiza uma política |
| `fp fleet deploy <machine> --remove <id>` | Remove uma política |
| `fp fleet deploy <machine> --set <ref>...` | Substitui o conjunto completo de políticas |
| `fp fleet diff [machine]` | Compara as versões esperada e aplicada |
| `fp fleet history <machine>` | Lista as gerações de implantação |
| `fp fleet rollback <machine> <generation>` | Restaura uma geração anterior |
| `fp fleet rename <machine> "<label>"` | Altera o rótulo no Cloud |

<Warning>
  `--set` substitui o conjunto completo de políticas. Um simples `--add <id>` aplica imediatamente uma nova política. Use `--add <id>:observe` para uma implantação em modo sombra.
</Warning>

## Observar, depois aplicar

```bash
fp fleet deploy ci-runner-01 --add prod-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add prod-guard:enforce
```

O modo de observação avalia a política real e registra as decisões que não são allow sem bloquear o agente.

## Identidade da máquina

O ID da máquina é estável e a identifica de forma única. O rótulo é apenas para exibição e pode ser alterado:

```bash
failproofai config --machine-label checkout-runner-03
fp fleet rename <machine-id> "Checkout runner 03"
```

Alterar o rótulo não reconecta nem gera uma nova chave para a máquina.
