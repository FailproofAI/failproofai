Crie uma política funcional, teste localmente e publique como um pacote.

## Criar e testar

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

`--init` cria uma política que já bloqueia `git push --force`. Edite-a, peça ao seu agente para tentar a ação bloqueada e verifique **Policies → Activity** no painel local.

Uma política de pacote pode incluir:

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-refunds",
  description: "Refunds above the limit need a human",
  category: "Billing",
  defaultEnabled: true,
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) => {
    // return allow(), instruct(), or deny()
  },
});
```

`defaultEnabled` tem valor padrão `false`.

## Publicar

Faça o commit dos seus arquivos e execute:

```bash
failproofai publish
```

O comando localiza o arquivo de política, valida-o com o mesmo carregador usado durante a instalação e faz o upload dos assets do pacote para uma release do GitHub. Ele utiliza `GITHUB_TOKEN`, `GH_TOKEN` ou `gh auth login`.

O repositório deve ser público, pois a instalação usa HTTPS anônimo.

A versão padrão é o SHA de 12 caracteres do commit atual. O comando recusa uma árvore com alterações não commitadas ou um diretório fora do Git, a menos que você forneça `--version`. Uma tag em `HEAD` tem precedência sobre o SHA.

Os usuários instalam com:

```bash
failproofai policies add owner/repo
```

## Publicar em modo observe

```bash
failproofai publish --effect observe
```

O modo observe avalia a política real e registra decisões que não sejam allow, mas permite que o agente continue. Um timeout é registrado como allow.

Publique novamente com `--effect enforce` quando as correspondências observadas estiverem corretas.

## Opções úteis

| Flag | Efeito |
| --- | --- |
| `--init [file]` | Cria uma política inicial |
| `--repo <owner>/<repo>` | Escolhe ou cria o repositório |
| `--version <version>` | Substitui a versão baseada no commit |
| `--effect enforce|observe` | Define se o pacote bloqueia ou não |
| `--dry-run` | Constrói e valida sem publicar |
| `--allow-private` | Publica de forma privada, sabendo que `policies add` não conseguirá instalá-lo |

```bash
failproofai publish --dry-run
failproofai publish ./guards.mjs --repo me/guards --version 2.0.0
```

<Note>
  Adicione o tópico `failproofai-policies` no GitHub após a publicação para que o [Policy Hub](https://befailproof.ai/policy-hub/) possa indexar o pacote. A CLI não define isso automaticamente.
</Note>

<Warning>
  Renomear uma política é uma mudança incompatível para seleções existentes. Mantenha os nomes estáveis entre as versões.
</Warning>
