Use `fp` para inspecionar a telemetria do Cloud, gerenciar a aplicação de regras gerenciada na nuvem (políticas, implantações de frota, decisões de guardrail) e administrar auditorias, descobertas, incidentes, alertas, chaves, usuários, consultas e configurações. Use [`failproofai`](/pt-br/reference/failproof-cli) para hooks locais, políticas, captura e cadastro de máquinas.

Instale o Cloud CLI publicado como uma ferramenta isolada. É necessário Python 3.10 ou mais recente.

```bash
uv tool install fp-cloud-cli
fp version
```

A distribuição é `fp-cloud-cli` e o comando instalado é `fp` — eles diferem porque `fp` já estava ocupado no PyPI.

## Entrar

`fp login` envia um código de seis dígitos por e-mail e salva a sessão. Para um dashboard com certificado autoassinado, adicione `--insecure` no momento do login.

```bash
fp login
fp whoami
```

## Sintaxe

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

As opções globais devem vir antes do comando:

```bash
fp --json sessions --since 24h
```

Execute `fp COMMAND --help` ou `fp COMMAND SUBCOMMAND --help` para obter ajuda no terminal.

### Eventos

```text
fp events [OPTIONS]
```

Lista eventos individuais de agentes. O feed leve padrão exclui payloads brutos; use `--full` somente para uma investigação delimitada.

| Opção | Descrição |
| --- | --- |
| `--limit`, `-n <n>` | Total máximo de linhas. Padrão: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` ou `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Intervalo UTC em ISO 8601; substitui `--since`. |
| `--env <value>` | Filtro de ambiente; repita ou separe por vírgula. |
| `--event-type <value>` | Filtro de tipo de evento; repita ou separe por vírgula. |
| `--agent-id <value>` | Filtro de agente; repita ou separe por vírgula. |
| `--session-id <value>` | Filtro de sessão; repita ou separe por vírgula. |
| `--search <text>` | Busca no texto do payload; repetível, com correspondência em qualquer termo. |
| `--order asc\|desc` | Ordem temporal. Padrão: mais recente primeiro. |
| `--all` | Pagina automaticamente até `--limit`. |
| `--cursor <token>` | Retomar a partir de um cursor opaco. |
| `--page-size <n>` | Linhas por requisição com `--all`; máximo `200`. |
| `--full` | Inclui payloads brutos via endpoint de eventos mais detalhado. |
| `--fields <csv>` | Retornar apenas campos selecionados; solicitar `payload` ativa o modo completo. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` pagina **até `--limit`**, cujo padrão é **50** — portanto `--all` sozinho
  para em 50 linhas. Quando para antes, a resposta traz um `next_cursor` para
  continuar; `"next_cursor": null` significa que o feed foi realmente esgotado.
</Note>

#### Opções de criação de auditoria

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Opção | Descrição |
| --- | --- |
| `--file <path>` | Basear a definição em JSON, ou usar `-` para stdin. Flags explícitas substituem os valores do arquivo. |
| `--description <text>` | Descrever a pergunta de falha ou o propósito. |
| `--enabled` / `--disabled` | Iniciar o agendamento ativado ou desativado. Padrão: habilitado. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Padrão: `86400`. |
| `--schedule-anchor <timestamp>` | Fase UTC fixa no formato ISO 8601. Padrão: próximo 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continuar após a última janela totalmente analisada ou inspecionar repetidamente uma janela deslizante. Padrão: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Padrão: `604800`. |
| `--scope '<json>'` | Filtrar por `environments`, `agent_ids` ou outros campos de escopo suportados. |
| `--ignore-error-type <type>` | Excluir tipos de erros; repita ou separe por vírgula. |
| `--llm` / `--no-llm` | Ativar ou desativar a análise agêntica. Padrão: habilitado. |
| `--top-k <n>` | Reter `1`–`500` descobertas. Padrão: `50`. |
| `--sensitivity low\|medium\|high` | Definir a sensibilidade do relatório. Padrão: `medium`. |
| `--channels '<json>'` | Array de canais de notificação. |
| `--text <brief>` | Briefing inline, máximo de 8.192 caracteres. |
| `--text-file <path>` | Ler o briefing de um arquivo; mutuamente exclusivo com `--text`. |
| `--url <https-url>` | Adicionar uma referência HTTPS pública; repita até cinco vezes. |

Inclua o contexto durante a criação quando a primeira execução precisar dele. A criação confirma a definição e o contexto juntos antes do início da execução enfileirada.

<Note>
  `fp audits run` é assíncrono. Consulte `fp audits runs NAME` periodicamente até que a execução mais recente seja concluída com sucesso ou falha antes de ler suas descobertas.
</Note>

#### Referências de política

`--add` e `--set` recebem uma referência de política, não um id simples:

| Forma | Significado |
| --- | --- |
| `id` | Versão atual, efeito atual |
| `id@3` | Versão 3, efeito atual |
| `id:observe` | Versão atual, registrada mas não aplicada |
| `id@3:observe` | Versão 3, registrada mas não aplicada |

O efeito é `enforce` ou `observe`. A resolução é: um efeito explícito vence; caso contrário, o efeito já implantado para essa política; caso contrário, `enforce`.

<Warning>
  Um `--add` simples **aplica imediatamente**. `fp fleet deploy ci-runner-01 --add checkout-guard` começa a bloquear nessa máquina assim que ela fizer a próxima busca. `:observe` é o que torna isso um rollout em modo sombra:

  ```bash
  fp fleet deploy ci-runner-01 --add checkout-guard:observe   # apenas registra
  fp fleet deploy ci-runner-01 --add checkout-guard           # aplica agora
  ```

  Observe não é desligado. A política é avaliada de verdade, com o mesmo timeout de 10 segundos e o mesmo tratamento de erros de uma política em modo enforce, e cada veredicto diferente de allow é registrado — apenas a aplicação é retida. É isso que torna a medição válida.
</Warning>

#### Deltas, substituição e condições de corrida

`--add` e `--remove` leem o conjunto atual da máquina e aplicam um delta, portanto nada que você não mencionou é alterado. Um `--add` simples em uma política que a máquina já executa mantém sua versão fixada em vez de atualizá-la silenciosamente; passe `id@version` para movê-la.

`--set` substitui tudo e é a única forma de remover políticas que você não menciona. Não pode ser combinado com `--add` ou `--remove`. Não passar nenhum dos três é um erro de uso, não uma operação nula.

```bash
fp fleet deploy ci-runner-01 --add prod-guard@1:observe --remove old-rule
fp fleet deploy ci-runner-01 --set no-force-push --set no-secret-echo
```

A escrita em si é uma substituição completa em cada caminho, pois o endpoint recebe o conjunto de políticas inteiro. Não há bloqueio no lado do servidor, portanto a CLI registra a geração que leu e recusa se o resultado não for exatamente uma geração acima — isso significa que alguém mais fez uma implantação no meio-tempo, e uma substituição não faz merge. Releia com `fp fleet show` e implante novamente.

`--create` implanta em um id de máquina que ainda não fez check-in, para pré-configuração. Sem ele, um id que o servidor desconhece é recusado, pois um erro de digitação criaria uma máquina sem dono carregando políticas que ninguém coleta.

### Guardrails

O que a aplicação de regras realmente fez. **Somente sessão**, pelo mesmo motivo acima.

| Comando | Finalidade | Opções |
| --- | --- | --- |
| `fp guardrails summary` | Cobertura, totais de bloqueado/avaliado, um sparkline de negações e a tabela por política. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |
| `fp guardrails timeline` | Decisões agrupadas ao longo da janela, somadas por todas as fontes de política. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |

Uma linha `(no policy)` no resumo é normal, não uma lacuna: a maioria das avaliações são allows que ninguém objetou, e a linha mantém o denominador visível na tela.

### Publicar uma política sem quebrar nada

Os três grupos acima formam uma sequência. Decida localmente, publique, faça shadow, meça e então aplique.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

| Etapa | Por que ela existe |
| --- | --- |
| `fp policies test` | Sem servidor e sem autenticação. Executa o arquivo real contra um contexto que você descreve e imprime allow, deny ou instruct por política registrada. `--expect` transforma isso em uma asserção de CI. |
| `fp policies publish` | Cria uma nova versão imutável; nunca edita uma existente. |
| `fp fleet deploy --add <id>:observe` | O rollout em modo sombra. **`:observe` não é opcional aqui** — um `--add` simples aplica no momento em que a máquina fizer a busca. |
| `fp guardrails summary` | Separa as correspondências inseguras do trabalho legítimo que a política também teria bloqueado. |
| `fp fleet deploy --add <id>:enforce` | Promoção, uma vez que os veredictos registrados confirmam o esperado. |
| `fp fleet rollback <machine> <generation>` | O caminho de volta caso a aplicação dê errado. |

O equivalente para uma única máquina, sem envolver o Cloud, é publicar o pacote com `failproofai publish --effect observe` e ler os veredictos registrados no [dashboard local](/pt-br/reference/local-dashboard).

## Flags globais

| Flag | Descrição |
| --- | --- |
| `--json` | Emitir JSON legível por máquina. |
| `--base-url <url>` | Usar um dashboard self-hosted ou de desenvolvimento. |
| `--org <slug>` | Selecionar uma organização para esta invocação. |
| `--token <token>` | Substituir o token da sessão de usuário salva. |
| `--api-key <key>` | Autenticar automação com uma chave de API; nunca salva. |
| `--timeout <seconds>` | Timeout HTTP; deve ser positivo. Padrão: `30`. |
| `--quiet`, `-q` | Suprimir a saída de status no stderr. |
| `--no-color` | Desativar saída colorida. |
| `--insecure` / `--secure` | Desativar ou restaurar a verificação de certificado TLS. |
| `--version` | Imprimir a versão instalada e sair. |
| `--help`, `-h` | Exibir ajuda. |

`--api-key` é destinado à automação. Login, troca de organização e comandos do assistente requerem uma sessão de usuário.

## Variáveis de ambiente

| Variável | Equivalente ou finalidade |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | Relocar o diretório de configuração da CLI (padrão `~/.failproofai/fpcli`). |
| `FP_ANALYTICS_DISABLED` ou `DO_NOT_TRACK` | Desativar a telemetria anônima da CLI. |
| `NO_COLOR` | Desativar saída colorida. |

Flags explícitas substituem variáveis de ambiente, que substituem a configuração salva.

No modo de chave de API, a organização salva por um `fp login` humano é **ignorada**, não apenas substituída — somente um `--org` explícito ou `FP_ORG` é enviado. Nada é herdado de um login salvo, portanto passe `--org` sempre que a chave puder agir em mais de uma organização. Omiti-lo não falha de forma explícita: uma chave com escopo de instância sem `--org` resolve no lado do servidor para a organização **padrão** e responde com os dados dessa organização, sem erro em lugar algum. Execute `fp whoami` primeiro para confirmar a qual tenant uma chave está realmente se conectando.

<Warning>
  As grafias `AGENTEYE_*` dessas variáveis **não são lidas por `fp`** e nunca foram — a CLI declara `FP_*` (`fp_cli/app.py`), e uma variável desconhecida não é um erro. Definir `AGENTEYE_DASHBOARD_URL` não redireciona a CLI; ela é ignorada e o comando executa silenciosamente contra o dashboard salvo.

  `AGENTEYE_HOME` e `AGENTEYE_ENVIRONMENT` ainda existem, mas pertencem ao **coletor e ao SDK de telemetria**, não a esta CLI.
</Warning>

<Warning>
  Comandos que excluem, revogam, suprimem, resolvem ou substituem configurações solicitam confirmação por padrão. Use `--yes` somente após verificar a organização ativa e o alvo.
</Warning>
