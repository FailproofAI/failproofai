Use `fp` para inspecionar telemetria Cloud e gerenciar auditorias, achados, problemas, alertas, chaves, usuários, consultas e configurações. Use [`failproofai`](/pt-br/reference/failproof-cli) para hooks locais, políticas, captura e registro de máquinas.

Instale o Cloud CLI como uma ferramenta isolada:

```bash
uv tool install fp-cli
fp version
```

## Autenticar

```bash
fp login
fp whoami
```

## Sintaxe

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

As opções globais devem vir antes do comando:

```bash
fp --json sessions --since 24h
```

Execute `fp COMMAND --help` ou `fp COMMAND SUBCOMMAND --help` para ajuda no terminal.

## Comandos da CLI

### Autenticação

| Comando | Finalidade | Opções |
| --- | --- | --- |
| `fp login` | Entrar com um código de uso único enviado por e-mail e selecionar uma organização. | `--email`, `-e`; `--org`; `--force` |

```bash
fp login --email voce@exemplo.com --org equipe-confiabilidade
fp whoami
```

### Eventos

```text
fp events [OPTIONS]
```

Lista eventos individuais de agentes. O feed padrão simplificado exclui payloads brutos; use `--full` apenas para investigações delimitadas.

| Opção | Descrição |
| --- | --- |
| `--limit`, `-n <n>` | Total máximo de linhas. Padrão: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` ou `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Intervalo UTC ISO 8601; substitui `--since`. |
| `--env <value>` | Filtro de ambiente; repita ou separe por vírgula. |
| `--event-type <value>` | Filtro de tipo de evento; repita ou separe por vírgula. |
| `--agent-id <value>` | Filtro de agente; repita ou separe por vírgula. |
| `--session-id <value>` | Filtro de sessão; repita ou separe por vírgula. |
| `--search <text>` | Busca em texto do payload; repetível, com correspondência de qualquer termo. |
| `--order asc\|desc` | Ordem temporal. Padrão: mais recente primeiro. |
| `--all` | Paginação automática até `--limit`. |
| `--cursor <token>` | Retomar a partir de um cursor opaco. |
| `--page-size <n>` | Linhas por requisição com `--all`; máximo `200`. |
| `--full` | Incluir payloads brutos pelo endpoint de eventos completo. |
| `--fields <csv>` | Retornar apenas os campos selecionados; solicitar `payload` ativa o modo completo. |

```bash
fp events --session-id <session-id> --order asc --all
fp --json events --full --session-id <session-id> --all
```

### Chaves de API

| Comando | Finalidade | Opções |
| --- | --- | --- |
| `fp keys list` | Listar chaves da organização. | `--show-id`; `--fields <csv>` |
| `fp keys show NAME` | Exibir uma chave e suas concessões. | — |
| `fp keys create NAME` | Criar uma chave e revelar seu segredo uma única vez. | `--permission-set`; `--add`; `--remove` |
| `fp keys update NAME` | Substituir o conjunto de permissões ou ajustar concessões. | `--permission-set`; `--add`; `--remove`; `--yes`, `-y` |
| `fp keys regenerate NAME` | Rotacionar o segredo e revelar o substituto uma única vez. | `--yes`, `-y` |
| `fp keys disable NAME` | Revogar permanentemente uma chave. | `--yes`, `-y` |

Os tokens de permissão usam o formato `resource:action`, como `events:add`. Repita `--add`, separe tokens por vírgula ou use ações com ponto como `events:read.add`.

#### Opções de criação de auditoria

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Opção | Descrição |
| --- | --- |
| `--file <path>` | Basear a definição em JSON, ou use `-` para stdin. Flags explícitas substituem os valores do arquivo. |
| `--description <text>` | Descrever a pergunta de falha ou o propósito. |
| `--enabled` / `--disabled` | Iniciar o agendamento ativado ou desativado. Padrão: ativado. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Padrão: `86400`. |
| `--schedule-anchor <timestamp>` | Fase UTC fixa no formato ISO 8601. Padrão: próximo 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continuar após a última janela completamente analisada ou inspecionar repetidamente uma janela contínua. Padrão: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Padrão: `604800`. |
| `--scope '<json>'` | Filtrar por `environments`, `agent_ids` ou outros campos de escopo suportados. |
| `--ignore-error-type <type>` | Excluir tipos de erros; repita ou separe por vírgula. |
| `--llm` / `--no-llm` | Ativar ou desativar a análise agêntica. Padrão: ativado. |
| `--top-k <n>` | Manter `1`–`500` achados. Padrão: `50`. |
| `--sensitivity low\|medium\|high` | Definir a sensibilidade dos relatórios. Padrão: `medium`. |
| `--channels '<json>'` | Array de canais de notificação. |
| `--text <brief>` | Briefing inline, máximo de 8.192 caracteres. |
| `--text-file <path>` | Ler o briefing de um arquivo; mutuamente exclusivo com `--text`. |
| `--url <https-url>` | Adicionar uma referência HTTPS pública; repita até cinco vezes. |

Inclua o contexto durante a criação quando a primeira execução precisar dele. A criação confirma a definição e o contexto juntos antes de a execução enfileirada começar.

<Note>
  `fp audits run` é assíncrono. Consulte `fp audits runs NAME` até que a execução mais recente seja concluída com sucesso ou falhe antes de ler seus achados.
</Note>

### Problemas

| Comando | Finalidade | Opções |
| --- | --- | --- |
| `fp issues list` | Listar problemas. | `--state`; `--alert-id`; `--limit`, `-n`; `--show-id` |
| `fp issues count` | Contar problemas abertos ou estados selecionados. | `--state` |
| `fp issues show INCIDENT_ID` | Exibir detalhes, comentários, assinantes e atividade de um problema. | — |
| `fp issues open` | Abrir um problema manual ou vinculado a um alerta. | `--summary` obrigatório; `--title`, `--alert-id`, `--severity` opcionais |
| `fp issues ack INCIDENT_ID` | Confirmar o recebimento de um problema. | — |
| `fp issues assign INCIDENT_ID` | Substituir responsáveis; omita a opção para limpá-los. | `--assignee` repetível |
| `fp issues resolve INCIDENT_ID` | Resolver um problema. | `--yes`, `-y` |
| `fp issues comment-list INCIDENT_ID` | Listar comentários. | — |
| `fp issues comment-add INCIDENT_ID` | Adicionar um comentário. | exatamente uma de `--body`, `--file` |
| `fp issues comment-delete INCIDENT_ID COMMENT_ID` | Excluir um comentário. | `--yes`, `-y` |
| `fp issues subscribers INCIDENT_ID` | Listar assinantes. | — |
| `fp issues subscribe INCIDENT_ID` | Assinar você mesmo ou outro operador. | `--email` |
| `fp issues unsubscribe INCIDENT_ID` | Remover uma assinatura. | `--email` |

Os estados válidos de problema são `firing`, `acknowledged` e `resolved`. As severidades de problemas avulsos são `info`, `warning` e `critical`.

## Flags globais

| Flag | Descrição |
| --- | --- |
| `--json` | Emitir JSON legível por máquina. |
| `--base-url <url>` | Usar um dashboard auto-hospedado ou de desenvolvimento. |
| `--org <slug>` | Selecionar uma organização para esta invocação. |
| `--token <token>` | Substituir o token de sessão de usuário salvo. |
| `--api-key <key>` | Autenticar automação com uma chave de API; nunca é salva. |
| `--timeout <seconds>` | Tempo limite HTTP; deve ser positivo. Padrão: `30`. |
| `--quiet`, `-q` | Suprimir saída de status no stderr. |
| `--no-color` | Desativar saída colorida. |
| `--insecure` / `--secure` | Desativar ou restaurar a verificação de certificado TLS. |
| `--version` | Imprimir a versão e sair. |
| `--help`, `-h` | Exibir ajuda. |

`--api-key` é destinado a automações. Login, troca de organização e comandos do assistente requerem uma sessão de usuário.

## Variáveis de ambiente

| Variável | Equivalente ou finalidade |
| --- | --- |
| `AGENTEYE_DASHBOARD_URL` | `--base-url` |
| `AGENTEYE_ORG` | `--org` |
| `AGENTEYE_CLI_TOKEN` | `--token` |
| `AGENTEYE_CLI_API_KEY` | `--api-key` |
| `AGENTEYE_CLI_JSON` | `--json` |
| `AGENTEYE_INSECURE` | `--insecure` |
| `AGENTEYE_HOME` | Realocar o diretório de configuração atual da CLI. |
| `AGENTEYE_ANALYTICS_DISABLED` ou `DO_NOT_TRACK` | Desativar analytics anônimas da CLI. |
| `NO_COLOR` | Desativar saída colorida. |

Flags explícitas substituem variáveis de ambiente, que substituem a configuração salva. No modo de chave de API, selecione o tenant explicitamente com `--org` ou `AGENTEYE_ORG`.

<Warning>
  Comandos que excluem, revogam, suprimem, resolvem ou substituem configurações solicitam confirmação por padrão. Use `--yes` somente após verificar a organização ativa e o alvo.
</Warning>
