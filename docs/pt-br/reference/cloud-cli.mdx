Use `fp` para inspecionar a telemetria do Cloud, gerenciar a aplicação de políticas gerenciadas na nuvem (políticas, implantações de frota, decisões de guardrails) e administrar auditorias, descobertas, incidentes, alertas, chaves, usuários, consultas e configurações. Use [`failproofai`](/pt-br/reference/failproof-cli) para hooks locais, políticas, captura e registro de máquinas.

Você também pode criar e implantar código hospedado, avaliadores LLM-judge e Jev, gerenciar
dashboards, inspecionar sentimento e usar o assistente de dashboard pelo terminal.

Instale o Cloud CLI lançado como uma ferramenta isolada:

```bash
uv tool install fp-cloud-cli
fp version
```

## Login

```bash
fp login
fp whoami
```

## Sintaxe

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

As opções globais devem vir antes do comando:

```bash
fp --json sessions --since 24h
```

Execute `fp COMMAND --help` ou `fp COMMAND SUBCOMMAND --help` para obter ajuda no terminal.

## Comandos da CLI

### Criar um avaliador

`fp evaluators` cria definições; `fp evals` lê resultados. Uma instância gerenciada habilitada é necessária (`fp evaluators instances`). A criação requer `evaluations:trigger`; execuções de teste de sessão e perfilamento de schema também requerem `events:read`.

O código é uma expressão Python restrita. Salve isso como `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Rubrica binária e graduada Jev:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
A criação habilita o avaliador. O deploy cria uma nova versão imutável e, em seguida, desabilita versões mais antigas que estavam habilitadas. Uma falha no acompanhamento deixa a nova versão publicada: inspecione `evaluators list --all` antes de tentar novamente.
Execuções de teste do tipo judge são recusadas pelo Cloud. Execuções de teste Jev consomem budget de modelo.
O preenchimento retroativo abrange avaliadores de código, judge e Jev e aceita no máximo 90 dias; ele enfileira apenas sessões que um avaliador ainda não pontuou. Preenchimentos retroativos de judge e Jev consomem budget de modelo, portanto execute `fp evaluators backfill --dry-run` primeiro.
A saída em modo humano exibe resultados de execuções de teste por sessão antes de criar/implantar.
Pré-visualizações com falha interrompem a escrita, a menos que você passe explicitamente `--force` após a revisão.
</Warning>

A criação por IA requer `fp login` e grava uma especificação aceita por create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Comando | Opções / comportamento |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Código-fonte/envelope completo |
| `fp evaluators create` | `--key`, `--name`, `--version`, `--label` (repetível), `--condition EXPR\|@file`, uma fonte, `--dry-run-on` (repetível), `--disabled`, `--force` explícito para pré-visualizações com falha |
| `fp evaluators deploy KEY` | Mesmas flags de fonte; `--version`, `--backfill 7d` (qualquer tipo, 1–90 dias), `--force`; versões numéricas são incrementadas automaticamente; KEY fornece um `eval_key` ausente no arquivo de especificação |
| `fp evaluators draft "intent"` | Sessão; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Flags de fonte ou `--file`, `--session` (repetível, máximo 10); nenhum = somente compilar |
| `fp evaluators enable\|disable KEY[@VERSION]` | Alternar |
| `fp evaluators label KEY[@VERSION]` | `--add`, `--remove` (repetíveis) |
| `fp evaluators instances\|schema\|jobs` | Inspecionar frota gerenciada/schema/jobs |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; código, judge e Jev |

As flags de código são `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. As flags de judge são `--judge --criteria TEXT`, `--step` (repetível) e
`--threshold`. As flags Jev são `--jev noul --instructions --true --false` ou
`--jev score --instructions` com 3–5 valores distintos em `--level`, do pior para o melhor.
Judge/Jev requerem uma pontuação; os thresholds variam entre 0 e 1. Passos binários de judge são rejeitados.

Os arquivos de especificação contêm exatamente `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
O `evaluator_source` de Judge/Jev é uma string de envelope JSON. Não inclua IDs de linha,
estado habilitado ou metadados de raciocínio de IA. `--file` e flags de especificação avulsas são
exclusivos entre si; o deploy pode sobrescrever a versão do arquivo. Arquivos de saída nunca são sobrescritos.

### Novos controles de dashboard

Todos os comandos aceitam `--json` global. Erros 404 de rota desconhecida terminam com código 6 e a mensagem "not available on this FailproofAI Cloud yet". Erros 404 de registro ausente também terminam com código 6, mas informam que o registro não foi encontrado. Comandos exclusivos de sessão rejeitam o modo de chave antes do HTTP (código de saída 2).

Comandos em modo humano usam resumos e tabelas. Para exportações JSON brutas, passe `--json` global ou salve com `--out FILE`; caso contrário, as exportações de sessão e consulta JSON exibem uma visão legível. Exportações CSV permanecem como CSV simples para piping.

| `fp sessions import FILE...` | Transcrições Claude Code, rollouts do Codex ou JSONL de eventos (`.gz` ok); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; requer `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; list com `--limit`; messages com `--session-id` |
| `fp query compose "question"` | Sessão; `--run` |
| `fp query export [ID]` | Ou `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Issues podem `--create --title --summary` ou `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; update com `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | Sessão; cria uma política a partir dos eventos da sua organização, nunca publica |
| `fp policies backtest [FILE_OR_ID]` | Sessão; regex reproduz o módulo; `jev`/`both` (publicado, ou `--semantic checks.json`) estima gratuitamente, `--run [--sample N]` consome allowance Jev; `--kind`, `--hours`, `--agent-id`, `--env` |

| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | Conjuntos de permissões; create com `--name --permission`; update substituindo `--permission` ou mesclando com `--add/--remove`; `--description`, `--file` |

| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` requer uma chave de API; plan (ofertas e trial) e claim requerem uma sessão autenticada |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1.000.000 tokens |
| `fp otel status\|enable\|disable` | Chave de ingestão da organização no Cloud, não a captura local |
| `fp slack status\|disconnect` | Sessão |

`fp agent ask` renderiza SQL de artefatos como tabelas/estatísticas via `queries:run`.
Aprovações de escrita exibem a alteração proposta e solicitam confirmação em um terminal interativo. Scripts e
`--json` recusam a menos que `--approve` seja explícito. Estruturas JSON existentes permanecem
inalteradas quando nenhum artefato é retornado.

### Eventos

```text
fp events [OPTIONS]
```

Lista eventos individuais de agentes. O feed padrão leve exclui payloads brutos; use `--full` apenas para uma investigação delimitada.

| Opção | Descrição |
| --- | --- |
| `--limit`, `-n <n>` | Total máximo de linhas. Padrão: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` ou `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Intervalo UTC em ISO 8601; substitui `--since`. |
| `--env <value>` | Filtro de ambiente; repita ou separe valores por vírgula. |
| `--event-type <value>` | Filtro de tipo de evento; repita ou separe valores por vírgula. |
| `--agent-id <value>` | Filtro de agente; repita ou separe valores por vírgula. |
| `--session-id <value>` | Filtro de sessão; repita ou separe valores por vírgula. |
| `--search <text>` | Busca de texto no payload; repetível, com correspondência de qualquer termo. |
| `--order asc\|desc` | Ordem temporal. Padrão: mais recente primeiro. |
| `--all` | Paginação automática até `--limit`. |
| `--cursor <token>` | Retomar a partir de um cursor opaco. |
| `--page-size <n>` | Linhas por requisição com `--all`; máximo `200`. |
| `--full` | Incluir payloads brutos via endpoint de evento mais pesado. |
| `--fields <csv>` | Retornar apenas os campos selecionados; solicitar `payload` habilita o modo completo. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` pagina **até `--limit`**, que por padrão é **50** — portanto `--all` sozinho
  para em 50 linhas. Quando para antes do fim, a resposta carrega um
  `next_cursor` para retomar; `"next_cursor": null` significa que o feed foi
  realmente esgotado.
</Note>

#### Opções de criação de auditoria

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Opção | Descrição |
| --- | --- |
| `--file <path>` | Basear a definição em JSON ou usar `-` para stdin. Flags explícitas substituem os valores do arquivo. |
| `--description <text>` | Descrever a questão de falha ou o propósito. |
| `--enabled` / `--disabled` | Iniciar o agendamento ativado ou desativado. Padrão: habilitado. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Padrão: `86400`. |
| `--schedule-anchor <timestamp>` | Fase UTC fixa no formato ISO 8601. Padrão: próximo 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continuar após a última janela totalmente analisada ou inspecionar repetidamente uma janela deslizante. Padrão: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Padrão: `604800`. |
| `--scope '<json>'` | Filtrar por `environments`, `agent_ids` ou outros campos de escopo suportados. |
| `--ignore-error-type <type>` | Excluir tipos de erro; repita ou separe por vírgula. |
| `--llm` / `--no-llm` | Habilitar ou desabilitar a análise agêntica. Padrão: habilitado. |
| `--top-k <n>` | Reter `1`–`500` descobertas. Padrão: `50`. |
| `--sensitivity low\|medium\|high` | Definir a sensibilidade de relatório. Padrão: `medium`. |
| `--channels '<json>'` | Array de canais de notificação. |
| `--text <brief>` | Briefing inline, máximo 8.192 caracteres. |

## Variáveis de ambiente

| Variável | Equivalente ou finalidade |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |

| `NO_COLOR` | Desabilitar saída colorida. |

Flags explícitas substituem variáveis de ambiente, que substituem a configuração salva. No modo de chave de API, selecione o tenant explicitamente com `--org` ou `FP_ORG`.

<Warning>
  As grafias `AGENTEYE_*` dessas variáveis **não são lidas pelo `fp`** e nunca foram — a CLI declara `FP_*` (`fp_cli/app.py`), e uma variável desconhecida não é um erro. Definir `AGENTEYE_DASHBOARD_URL` não redireciona a CLI; ela é ignorada e o comando é executado silenciosamente contra o dashboard salvo.

  `AGENTEYE_HOME` e `AGENTEYE_ENVIRONMENT` ainda existem, mas pertencem ao **coletor e ao SDK de telemetria**, não a esta CLI.
</Warning>

<Warning>
  Comandos que excluem, revogam, suprimem, resolvem ou substituem configurações solicitam confirmação por padrão. Use `--yes` somente após verificar a organização ativa e o alvo.
</Warning>
