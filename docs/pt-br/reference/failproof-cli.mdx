Instale o CLI local com `npm install -g failproofai`. Execute sem argumentos para abrir o painel de políticas local.

O pacote requer Node.js 20.9 ou mais recente. Bun 1.3 ou mais recente é suportado para desenvolvimento e instalações a partir do código-fonte. `failproofai configure` e `failproofai setup` são aliases de `failproofai config`. `failproofai policy`, `failproofai pack` e `failproofai p` são todas grafias de `failproofai policies` — packs e políticas individuais eram três comandos para uma mesma ideia e agora são um só. As grafias antigas ainda funcionam, com duas exceções: `pack list <source>` agora é `policies show <source>`, e `pack build` agora é `publish`.

## Configurar uma máquina

Instale o CLI, em seguida leia a chave da máquina no shell. `read -s` solicita a entrada em um prompt sem eco, para que nunca apareça em um comando:

```bash
npm install -g failproofai
read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
```

Em seguida, configure a máquina e escolha o que ela irá impor:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

`failproofai config` realiza toda a configuração: instala o serviço `failproofaid` (como root uma vez — em um terminal solicita sua senha sudo e solicita novamente se ela expirar antes de a configuração terminar; sem terminal usa `sudo -n` e nunca exibe prompts), conecta hooks em todos os CLIs de agente encontrados e conecta ao Cloud. Sem terminal — CI, container, um agente controlando — aplica as configurações em vez de perguntar, e encerra com código 1 se algo que foi solicitado não aconteceu.

Em um terminal, a etapa **Conectar ao cloud** em uma máquina ainda não conectada inicia o **login no FailproofAI Cloud** imediatamente; pressione Tab para as outras opções, **Colar uma chave de API** ou **Usar código aberto**. O login abre um link — ou o imprime via SSH ou sem display, para abrir em qualquer dispositivo — onde você se cadastra ou faz login, escolhe ou cria uma organização e autoriza a máquina; o terminal detecta a aprovação por conta própria e mostra quem aprovou e para qual organização. A chave é criada apenas quando a configuração termina, após o daemon ser instalado. Em uma máquina já conectada com uma chave funcionando, a etapa exibe um menu com **Manter conexão atual** em primeiro lugar, então executar a configuração novamente nunca abre um navegador por conta própria; uma chave salva que não funciona mais inicia o login novamente imediatamente e informa o motivo. Fazer login novamente gera uma nova chave e mantém a antiga funcionando até você revogá-la. Um Cloud de antes do login via navegador informa isso e oferece as outras opções.

A configuração escolhe **nenhuma** política. Essa é a função do segundo comando e, sem ele, uma máquina recém-configurada não impõe nada além da proteção sempre ativa.

Prefira a variável de ambiente a `--token`: um argumento de linha de comando pode ser lido via `ps` por todos os usuários do sistema. É tudo que a variável protege — uma chave digitada em qualquer comando, incluindo `export`, ainda fica no histórico do shell, por isso é lida com `read -s` acima. Em CI, defina-a a partir do armazenamento de segredos e mantenha o rastreamento do shell (`set -x`) desativado, ou o trace a imprimirá.

<Warning>
  `--connect <url>` registra uma máquina que **já está configurada**. Retorna assim que o registro é bem-sucedido — não instala o daemon e não conecta nenhum hook. Use o simples `failproofai config` (ou `failproofai config --token <key>`) em uma máquina que ainda não foi configurada, ou ela aparecerá como conectada enquanto não coleta nem impõe nada.
</Warning>

Execute `failproofai` sem argumentos para abrir o painel de políticas local.

| Comando | Resultado |
| --- | --- |
| `failproofai config` | Configura a máquina: agentes, daemon e Cloud — faça login pelo navegador, cole uma chave ou use código aberto. Cada agente na máquina também recebe uma pequena skill `failproofai` que o aponta para as [FailproofAI skills](https://github.com/FailproofAI/skills) online |
| `failproofai config --token <key>` | Configura e conecta em uma única etapa, sem fazer perguntas. Uma chave com `jev:evaluate` também ativa o [Jev pelo FailproofAI Cloud](/pt-br/reference/jev-cloud) em modo de observação, a menos que um `jev.json` já exista ou `--no-transcripts` seja passado |
| `failproofai config --connect <url>` | Registra uma máquina que **já** está configurada — sem daemon, sem hooks |
| `failproofai config --status` | Exibe estado de conexão, daemon, entrega e pausa |
| `failproofai policies` | Lista políticas integradas, personalizadas, de convenção, de pack e gerenciadas pelo Cloud |
| `failproofai policies --install` | Conecta hooks aos CLIs dos seus agentes. Por si só não ativa nenhuma política |
| `failproofai policies add <name>` | Ativa uma política — integrada, ou `<pack-id>:<name>` de um pack instalado |
| `failproofai policies remove <name>` | Desativa uma política, mesma nomenclatura |
| `failproofai policies --uninstall` | Desativa políticas ou remove hooks do harness |
| `failproofai policies show <owner>/<repo>` | O que um pack contém, lido do seu manifesto, antes de você instalá-lo |
| `failproofai policies show <owner>/<repo> --releases` | Todas as versões publicadas e qual está instalada |
| `failproofai policies add <source>` | Instala um pack de políticas a partir de um release do GitHub; sem tag usa o mais recente e o fixa |
| `failproofai publish` | Publica suas próprias políticas como um pack; `--init` cria um para começar, e `--min-cli-version <version>` define o CLI mais antigo que pode instalá-lo ([Jev checks in a pack](/pt-br/policies/publish-a-pack#jev-checks-in-a-pack)) |
| `failproofai policies remove <publisher/name>` | Desinstala um pack |
| `failproofai audit` | Varre o histórico do agente local e abre a visualização de auditoria local |
| `failproofai audit --schedule [days] --email <address>` | Agenda varreduras locais recorrentes e envia os resultados por e-mail |
| `failproofai audit --status` | Exibe endereço do relatório, intervalo e próxima varredura agendada |
| `failproofai audit --no-schedule` | Para varreduras recorrentes sem excluir o histórico de auditoria |
| `failproofai harness list` | Lista caminhos de captura adicionais |
| `failproofai otel status` | Inspeciona o [relatório OpenTelemetry](/pt-br/reference/otel) opcional |
| `failproofai jev --url <url> --key-stdin` | Configura o Jev em uma etapa; o provedor é extraído do host da URL |
| `failproofai jev setup --provider <kind> --key-stdin` | Permite que o [Jev](/pt-br/reference/jev-providers) avalie chamadas de ferramentas através do seu próprio endpoint e chave |
| `failproofai jev setup --provider failproofai` | Permite que o Jev avalie chamadas de ferramentas [pelo FailproofAI Cloud](/pt-br/reference/jev-cloud), com a chave Cloud desta máquina |
| `failproofai jev setup --mode <m>` | Alterna o modo do Jev: `enforce`, `observe` ou `off` (mantém a configuração, para de consultar o Jev) |
| `failproofai jev status` | Exibe a configuração do Jev, suas permissões e fallbacks recentes; nunca a chave |
| `failproofai jev test` | Envia uma requisição Jev ao vivo e exibe sua latência e versão; encerra com código 1 quando a resposta está atrasada para hooks ou incorreta |
| `failproofai jev models` | Lista os IDs de modelos que `GET <base>/models` indica que um endpoint serve |
| `failproofai jev remove` | Desativa o Jev; os hooks executam as políticas de regex exatamente como antes |
| `failproofai flush --wait` | Entrega o spool de eventos atual |
| `failproofai backfill --since 30d` | Relê o histórico previamente processado |
| `failproofai config --pause [duration]` | Pausa uma sessão local por 30 minutos por padrão, até 8 horas |
| `failproofai config --resume` | Retoma uma sessão local pausada; adicione `--all` para limpar todas as pausas |
| `failproofai update` | Finaliza migrações de pacotes e atualiza o daemon |
| `failproofai migrate --dry-run` | Visualiza ou executa migrações pendentes de layout do diretório home |
| `failproofai uninstall` | Remove hooks, a skill `failproofai` e o daemon antes de remover o pacote |
| `failproofai --version` | Imprime a versão do pacote instalado |
| `failproofai --help` | Exibe comandos e uso global |
| `failproofai help <command>` | Exibe opções e exemplos de um comando, igual a `failproofai <command> --help` |

## Flags de configuração

| Flag | Uso |
| --- | --- |
| `--token <key>` | Configura e conecta sem interação; também lido de `FAILPROOFAI_CLOUD_TOKEN` |
| `--oss` | Usa código aberto sem conexão ao Cloud; uma conexão existente é mantida como está |
| `--agents <a,b>` | Rastreia estes agentes, ou `all`, sem perguntar |
| `--url <url>` | Conecta a um endereço diferente de `app.befailproof.ai`; também lido de `FAILPROOFAI_CLOUD_URL` |
| `--connect <url>` | Apenas registra, em uma máquina já configurada. Ignora o daemon e todos os hooks |
| `--machine-id <id>` | ID da máquina para `--connect`; padrão é um ID estável |
| `--machine-label <name>` | Sozinho, renomeia uma máquina **já conectada**; nunca executa a configuração. Com `--token`, conecta com esse nome; uma chave definida apenas em `FAILPROOFAI_CLOUD_TOKEN` não é suficiente, pois `--machine-label` sem `--token` é uma renomeação. Com `--oss` ou `--agents`, renomeia uma máquina já conectada e é rejeitado antes da configuração em uma que não está: `--oss` nunca conecta, e `--agents` precisa de uma chave ou login interativo no Cloud para conectar |
| `--no-transcripts` | Envia decisões sem conteúdo de transcrição e não ativa o Cloud Jev, que enviaria cada chamada de ferramenta verificada e o prompt recente; um `jev.json` que executa o Jev pelo FailproofAI Cloud é removido |
| `--disconnect` | Para pulls de políticas do Cloud e entrega de eventos. Também remove a chave do Cloud Jev e um `jev.json` que nomeia o FailproofAI Cloud; sua própria configuração do Jev é mantida |
| `--status` | Exibe o estado atual da máquina |
| `--pause [duration]` | Pausa a sessão mais recente no diretório atual; aceita segundos, minutos ou horas e tem padrão de 30 minutos |
| `--resume` | Encerra antecipadamente uma pausa correspondente |
| `--session <id>` | Alvo de uma sessão explícita para pausa ou retomada |
| `--all` | Com `--resume`, encerra todas as pausas ativas |

Pausas locais suspendem políticas integradas, personalizadas, de convenção e de pack para uma sessão. Sempre expiram, no máximo 8 horas após a primeira pausa em uma execução, e não desativam políticas gerenciadas pelo Cloud ou `block-failproofai-commands`, que está sempre ativa e não pode ser desativada ou pausada. Essa proteção recusa as formas diretas pelas quais um agente instrumentado poderia pausar a si mesmo: executar `failproofai config --pause` ou escrever o arquivo de pausa em `~/.failproofai/state/sessions/`. Ela lê comandos, não o que um script faz quando é executado, portanto um script que o agente escreve e depois executa ainda pode atingir o mesmo estado. Um arquivo de pausa é verificado quanto a uma expiração limitada e um início de no máximo um minuto no futuro, não quanto a quem o escreveu.

## Flags de políticas

| Flag | Uso |
| --- | --- |
| `--install`, `-i` | Instala hooks do harness. Nomes após ele ativam essas políticas; sem nenhum, nenhuma política é alterada |
| `--uninstall`, `-u` | Desativa políticas ou remove hooks |
| `--cli <names...>` | Alvo de um ou mais harnesses suportados |
| `--scope user\|project\|local\|all` | Escolhe o escopo de configuração; `all` é para desinstalação |
| `--beta` | Inclui políticas beta |
| `--custom`, `-c <path>` | Com `--install`, valida e carrega um arquivo de política personalizada; repetível. `--uninstall -c` remove todos os arquivos de política personalizada |
| `--policy`, `--only <a,b>` | Instala apenas essas políticas de um pack |
| `--category <x,y>` | Instala apenas essas categorias de um pack |
| `--all` | Lista todas as políticas; com um pack, instala tudo |
| `--releases` | Com `show`, lista os releases de um pack e qual está instalado |

## Flags de entrega e manutenção

| Comando | Flags |
| --- | --- |
| `backfill` | `--since <30d\|6m\|1y\|YYYY-MM-DD>`, `--agents <a,b>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` (`-y`) |

### Backfill por harness

`backfill` reenvia o histórico que o coletor já leu, em uma máquina conectada ao Cloud. `--since` define a janela para a maioria dos harnesses, com duas exceções:

- **Goose, OpenCode e Devin** enviam todo o seu histórico, independentemente do que `--since` especifica: o histórico deles fica em um banco de dados que o coletor lê sem janela de tempo, então `--dry-run` os reporta como todas as sessões.
- O histórico do **Hermes** não é reenviado pelo `backfill`.

`failproofai update` deve ser executado após `npm install -g failproofai@latest`; ele realiza migrações de layout do diretório home, instala o binário do daemon correspondente e reinicia o serviço. Em seguida, move todos os perfis do Hermes que já usam o FailproofAI para o plugin nativo vinculado e imprime uma linha por perfil. `--no-daemon` ignora a etapa do daemon. `update` encerra com código não-zero quando o daemon não pôde ser substituído, uma migração falhou ou um perfil do Hermes não pôde ser migrado (por exemplo, porque o daemon em execução não consegue servir o plugin nativo; nesse caso, seus hooks de shell são mantidos).

## Caminhos do harness

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

Os nomes de harness suportados são `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity` e `goose`.

Labels criam namespaces para IDs de agentes derivados quando duas raízes contêm cópias do mesmo projeto. Raízes sobrepostas e labels duplicadas são rejeitadas para evitar coleta duplicada ou corrupção do cursor. A configuração de caminhos extras recarrega sem reiniciar o daemon.

Ambientes de container podem substituir caminhos extras configurados por arquivo com uma variável separada por vírgulas chamada `FAILPROOFAI_<HARNESS>_EXTRA_PATHS`, por exemplo:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## Variáveis de ambiente

Use arquivos de configuração para comportamento persistente da máquina. Variáveis de ambiente são mais úteis para containers, testes e um único processo.

| Variável | Uso |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | A chave do Cloud, em vez de `--token`. Prefira esta: um argumento pode ser lido via `ps` por todos os usuários. Defina com `read -s` ou a partir de um armazenamento de segredos de CI, nunca digitando a chave em um comando, que fica no histórico do shell de qualquer forma |
| `FAILPROOFAI_CLOUD_URL` | A URL do Cloud, em vez de `--url`. A mesma variável que o daemon lê |
| `FAILPROOFAI_HOME` | Realoca o layout completo de `~/.failproofai` |
| `FAILPROOFAI_LOG_LEVEL` | Define a verbosidade do log local |
| `FAILPROOFAI_HOOK_LOG_FILE` | Grava diagnósticos de hook em um arquivo selecionado |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | Desativa a telemetria anônima para este processo |
| `FAILPROOFAI_NO_FIRST_RUN=1` | Ignora a configuração interativa de primeira execução |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | Ignora a auditoria local pós-configuração |
| `FAILPROOFAI_LLM_BASE_URL` | Substitui o endpoint compatível com OpenAI usado por políticas LLM |
| `FAILPROOFAI_LLM_API_KEY` | Fornece a chave de API usada por políticas LLM |
| `FAILPROOFAI_LLM_MODEL` | Seleciona o modelo usado por políticas LLM |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | Limita o tempo de carregamento do módulo de política personalizada |
| `FAILPROOFAI_NO_DOWNLOAD=1` | Recusa buscar packs e binários do daemon; o que está instalado continua impondo |
| `FAILPROOFAI_PACK_BASE_URL` | Busca packs de um espelho em vez de `github.com` |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | Substitui os caminhos de captura extras configurados para um harness |
| `NO_COLOR` | Desativa a saída colorida no terminal |

Variáveis home específicas de agente, como `CLAUDE_PROJECTS_PATH`, `CURSOR_HOME`, `HERMES_HOME` e `OPENCLAW_HOME`, substituem onde o Failproof AI descobre sessões locais para aquele harness.

## Pausar ou remover uma máquina com segurança

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

Uma pausa de sessão local não desativa políticas gerenciadas pelo Cloud. Restaure deployments do Cloud em **fix → deploy policies** no Cloud quando o próprio rollout for o problema.

Antes de remover o pacote npm, remova os hooks instalados e o daemon:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

Execute `failproofai <command> --help` para detalhes específicos da versão.

<Warning>
  Execute `failproofai uninstall` antes de `npm rm -g failproofai`; o npm não remove os hooks de agente instalados, a skill `failproofai` ou o serviço do daemon.
</Warning>
