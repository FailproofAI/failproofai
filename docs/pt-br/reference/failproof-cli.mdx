Instale com `npm install -g failproofai`. Execute `failproofai` sem argumentos para abrir o painel local.

## Comandos principais

| Comando | O que faz |
| --- | --- |
| `failproofai config` | Configura agentes, o serviço em segundo plano e a conexão opcional com o Cloud |
| `failproofai config --token <key>` | Configura e conecta sem perguntas |
| `failproofai config --status` | Exibe a conexão, a versão do serviço e o estado de pausa |
| `failproofai policies` | Lista as políticas e se estão ativas |
| `failproofai policies add <name>` | Ativa uma política |
| `failproofai policies add <owner>/<repo>` | Instala um pacote de políticas |
| `failproofai policies remove <name-or-pack>` | Desativa uma política ou remove um pacote |
| `failproofai policies show <owner>/<repo>` | Inspeciona um pacote antes de instalá-lo |
| `failproofai publish` | Publica suas políticas como um pacote |
| `failproofai audit` | Analisa o histórico local do agente |
| `failproofai harness` | Gerencia locais de sessão extras |
| `failproofai flush` | Envia eventos em fila imediatamente |
| `failproofai backfill` | Relê histórico mais antigo do agente |
| `failproofai update` | Conclui uma atualização npm e atualiza o serviço |
| `failproofai uninstall` | Remove hooks e o serviço |

`policy`, `pack` e `p` são aliases aceitos para `policies`, mas a documentação usa `policies`.

## Configurar uma máquina

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

A configuração não seleciona nenhum pacote de políticas. Antes de adicionar um, apenas `block-failproofai-commands` é executado.

Para configuração do Cloud sem supervisão:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Para enviar decisões sem transcrições, conecte-se primeiro e defina `collector.sessions` como `false` em `~/.failproofai/config.json`. O flag de configuração `--no-transcripts` atual é interpretado, mas não aplica essa configuração.

Use `--machine-label <name>` após a máquina estar conectada para renomeá-la. `--connect <url>` é o comando mais específico de registro para uma máquina já configurada.

## Políticas e pacotes

```bash
failproofai policies
failproofai policies add block-sudo
failproofai policies show owner/repo
failproofai policies add owner/repo --category git,database
failproofai policies remove owner/repo
```

Qualquer entrada com barra é uma fonte de pacote; sem barra é um nome de política.

Flags úteis para seleção de pacotes:

| Flag | Uso |
| --- | --- |
| `--policy a,b` | Seleciona políticas pelo nome |
| `--category x,y` | Seleciona categorias |
| `--all` | Seleciona tudo |
| `--cli <agents...>` | Restringe a harnesses específicos |

Use `failproofai policies -i -c <path>` para carregar uma política personalizada de qualquer caminho. Arquivos de convenção com o nome `*policies.{js,mjs,ts}` dentro de `.failproofai/policies/` são carregados automaticamente.

## Pausar a aplicação de políticas

```bash
failproofai config --pause 10m
failproofai config --status
failproofai config --resume
```

Uma pausa se aplica a uma sessão local e sempre expira. Ela não pausa políticas gerenciadas pelo Cloud nem o `block-failproofai-commands`.

## Auditoria e entrega

```bash
failproofai audit
failproofai audit --schedule 7 --email team@example.com
failproofai audit --status
failproofai flush --wait
failproofai backfill --since 30d --dry-run
```

`backfill` lê `~/.failproofai/config.json`. Remova `--dry-run` para reenviar o histórico.

## Locais de sessão extras

```bash
failproofai harness list
failproofai harness add-path claude work=/srv/team/.claude/projects
failproofai harness remove-path claude work
```

Rótulos evitam que sessões de dois diretórios copiados sejam mescladas sob o mesmo ID de agente derivado.

Os harnesses suportados são `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity` e `goose`. O suporte a escopos varia; consulte [Harnesses](/pt-br/reference/harnesses).

## Variáveis de ambiente úteis

| Variável | Uso |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | Chave de máquina do Cloud |
| `FAILPROOFAI_CLOUD_URL` | Substitui a URL do Cloud |
| `FAILPROOFAI_HOME` | Move o diretório de estado local |
| `FAILPROOFAI_NO_DOWNLOAD=1` | Recusa downloads de pacotes e serviços |
| `FAILPROOFAI_DAEMON_BASE_URL` | Usa um espelho do binário do serviço |
| `FAILPROOFAI_PACK_BASE_URL` | Usa um espelho de pacotes |
| `FAILPROOFAI_NO_FIRST_RUN=1` | Desativa prompts de primeira execução |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | Desativa a telemetria anônima da CLI |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | Substitui caminhos extras de um harness específico |
| `NO_COLOR` | Desativa as cores do terminal |

## Remover ou atualizar

```bash
npm install -g failproofai@latest
failproofai update
```

Antes de remover o pacote:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

<Warning>
  Execute `failproofai uninstall` antes de remover o pacote npm. O npm não remove os hooks instalados nem o serviço em segundo plano.
</Warning>

Execute `failproofai help <command>` para ver todas as opções disponíveis na versão instalada.
