Comece com:

```bash
failproofai config --status
failproofai policies
```

## Um agente não está conectado

Execute a configuração novamente:

```bash
failproofai config
```

A configuração suporta Linux e macOS. Ela precisa de acesso de administrador uma única vez para instalar o serviço, mas nunca solicita uma senha sudo.

Verifique os caminhos e escopos dos harnesses em [Harnesses](/pt-br/reference/harnesses).

## Uma sessão está faltando

```bash
failproofai flush --wait
failproofai backfill --since 30d --dry-run
failproofai harness list
```

Remova `--dry-run` para reenviar o histórico antigo. Adicione outro local de transcrição com:

```bash
failproofai harness add-path <harness> [label=]<path>
```

Use um rótulo quando dois locais contiverem cópias do mesmo projeto.

## Toda ação protegida está sendo negada

Em uma máquina configurada, `failproofaid` é o único avaliador. Se ele não conseguir responder, as ações protegidas falham de forma fechada.

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

Execute `failproofai config` para reparar ou reinstalar o serviço.

## Um pacote está negando

`failproofai policies` lista os pacotes que não conseguem carregar. Um pacote selecionado falha de forma fechada em vez de desaparecer.

Causas comuns:

- O artefato foi alterado após a instalação.
- O manifesto e as políticas agrupadas estão em desacordo.
- O arquivo está ausente ou não pode ser importado.
- O pacote usa um evento, ferramenta ou formato de política não suportado.

Remova o pacote ou instale uma versão corrigida:

```bash
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

## A nuvem está desconectada

Prefira uma variável de ambiente para a chave:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
failproofai config --status
```

Uma máquina pode buscar políticas e enviar atividade de forma independente. O status reporta ambos.

## Uma política não bloqueou

Verifique três coisas:

1. A política está ativa: `failproofai policies`.
2. Seu evento e ferramenta correspondem à ação.
3. Esse harness consegue aplicar o evento.

Uma negação de chamada de ferramenta é verificada em todos os 12 harnesses suportados. Outros eventos variam. Consulte [capacidade de aplicação](/pt-br/reference/harnesses#enforcement-capability).

## Downloads estão bloqueados

- `FAILPROOFAI_NO_DOWNLOAD=1` recusa downloads de rede.
- `FAILPROOFAI_DAEMON_BASE_URL` direciona os downloads do serviço para um espelho.
- `FAILPROOFAI_PACK_BASE_URL` direciona os downloads de pacotes para um espelho.

Pacotes instalados continuam sendo aplicados quando os downloads estão desabilitados.
