Dashboards combinam consultas salvas em uma visão operacional. Construa um em torno de uma decisão que você espera que alguém tome — não em torno de todas as métricas disponíveis.

## Criar um dashboard

<Tabs>
  <Tab title="Dashboard">
    1. Acesse **Analyze → Queries**, crie ou abra uma consulta salva e valide o resultado.
    2. Selecione **add to dashboard**, depois escolha um dashboard existente ou crie um em **Analyze → Dashboards**.
    3. Abra o dashboard, entre no modo de edição, organize os tiles e salve o layout.
    4. Volte à consulta quando precisar alterar os dados ou filtros por trás de um tile.

    ![Um dashboard composto por consultas salvas para volume de eventos, erros, latência e uso de tokens do modelo.](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    O CRUD de dashboards não está disponível no Cloud CLI atual. Use o CLI para criar e verificar a consulta salva, depois adicione-a a um dashboard pela interface web.

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

Grupos úteis de dashboards incluem:

- **Models:** volume, latência, uso de tokens, taxa de erros e pontuações de avaliação.
- **Evaluations:** taxa de sucesso e tendências de pontuação por agente ou ambiente.
- **Tools:** volume de chamadas, taxa de falhas, duração e chamadas repetidas.
- **Hooks and policies:** decisões, negações e taxa de correspondência de políticas.
- **Custom workflow metrics:** resultados dos seus próprios campos de eventos e SQL.

Comece com uma consulta salva, valide o resultado e então adicione-a como tile. Mantenha os filtros de produção e desenvolvimento explícitos para que o tráfego de testes não oculte uma regressão.

<Tip>
  Defina um responsável e uma pergunta de referência para cada dashboard, como "A confiabilidade do checkout-agent está pior do que na semana passada?"
</Tip>
