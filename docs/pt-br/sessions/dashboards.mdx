Dashboards combinam consultas salvas em uma visão operacional. Construa um em torno de uma decisão que você espera que alguém tome — não em torno de todas as métricas disponíveis.

## Criar um dashboard

<Tabs>
  <Tab title="Dashboard">
    1. Acesse **Analyze → Queries**, crie ou abra uma consulta salva e valide seu resultado.
    2. Selecione **add to dashboard**, depois escolha um dashboard existente ou crie um em **Analyze → Dashboards**.
    3. Abra o dashboard, entre no modo de edição, organize os tiles e salve o layout.
    4. Retorne à consulta quando precisar alterar os dados ou filtros por trás de um tile.

    ![Um dashboard composto de consultas salvas para volume de eventos, erros, latência e uso de tokens do modelo.](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    O CRUD de dashboards não está disponível na CLI Cloud atual. Use a CLI para criar e verificar a consulta salva, depois adicione-a a um dashboard na interface.

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

Grupos de dashboard úteis incluem:

- **Modelos:** volume, latência, uso de tokens, taxa de erros e pontuações de avaliação.
- **Avaliações:** taxa de sucesso e tendências de pontuação por agente ou ambiente.
- **Ferramentas:** volume de chamadas, taxa de falha, duração e chamadas repetidas.
- **Hooks e políticas:** decisões, negações e taxa de correspondência de políticas.
- **Métricas de fluxo de trabalho personalizadas:** resultados dos seus próprios campos de eventos e SQL.

Comece com uma consulta salva, valide seu resultado e depois adicione-a como um tile. Mantenha os filtros de produção e desenvolvimento explícitos para que o tráfego de testes não oculte uma regressão.

<Tip>
  Dê a cada dashboard um responsável e uma pergunta de referência, como "A confiabilidade do checkout-agent está pior do que na semana passada?"
</Tip>
