Os eventos em tempo real ajudam você a confirmar a instrumentação e acompanhar uma execução arriscada sem precisar aguardar o término da sessão.

## Monitorar atividade

<Tabs>
  <Tab title="Dashboard">
    1. Acesse **Observe → Events**.
    2. Comece com a janela de tempo atual e sem filtros para confirmar que os dados estão chegando.
    3. Filtre por ambiente, tipo de evento, agente ou sessão. Use a busca para texto no payload.
    4. Selecione um evento para inspecionar seu resumo e detalhes. Siga o link da sessão para o rastreamento completo.

    ![O stream de eventos ao vivo mostrando tráfego de um gateway de chat Hermes ao lado de execuções de CLI de codificação, filtrado por tempo, ambiente, tipo de evento, agente, modelo, contexto e sessão.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    O feed padrão omite os payloads brutos. Use `--full` apenas para investigações limitadas a uma sessão específica.
  </Tab>
</Tabs>

Use o stream de eventos para responder três perguntas imediatas:

- O agente esperado está reportando ao ambiente correto?
- As chamadas de modelo, chamadas de ferramenta e decisões de política estão chegando na ordem correta?
- A sessão parou de progredir ou começou a repetir uma ação?

Os tipos de evento incluem eventos de ciclo de vida do agente, requisições e respostas de modelo, uso de ferramentas e resultados, execução de hooks, esperas e interrupções humanas, e erros explícitos. IDs de correlação conectam eventos pareados, como uma chamada de ferramenta e seu resultado.

<Tip>
  Mantenha a visualização ao vivo ampla enquanto verifica uma nova integração. Adicione filtros somente após ver o primeiro evento; um filtro incorreto pode parecer uma falha na ingestão.
</Tip>

Se nenhum evento aparecer, execute `failproofai config --status` e depois [solucione problemas de ingestão](/pt-br/reference/troubleshooting).

Agentes que não executam em um dos 12 [harnesses](/pt-br/reference/harnesses) suportados reportam os mesmos tipos de evento através do [Python SDK](/pt-br/reference/custom-agents), incluindo os eventos de humano no loop (`human_wait`, `human_input`, `human_interrupt`) dos quais os agentes de gateway e produção dependem.
