As decisões de políticas mostram o que o Failproof AI fez durante a execução de um agente.

<Tabs>
  <Tab title="Dashboard">
    Acesse **Observe → policy** para revisar decisões, taxa de bloqueio, máquinas e atribuições implantadas.

    ![A página de Policy mostrando totais de decisões, um filtro de máquina, atividade de aplicação ao longo do tempo e a tabela de mapeamento de políticas.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp guardrails summary --since 24h
    fp guardrails timeline --since 24h
    failproofai policies
    failproofai config --status
    ```

    `--since` aceita `1h`, `6h`, `24h` ou `7d`. Adicione `--machine <id>` para focar em uma máquina específica.
  </Tab>
</Tabs>

## Interpretar um rollout em modo observe

O modo observe executa a política real e registra qualquer decisão `deny` ou `instruct`. O agente ainda pode continuar.

```bash
fp fleet deploy <machine> --add <policy>:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add <policy>:enforce
```

<Warning>
  Um `--add <policy>` simples aplica enforcement imediatamente quando a política não possui implantação existente. Adicione `:observe` para um rollout em modo shadow.
</Warning>

Apenas decisões observadas que não sejam allow são registradas. Um timeout é registrado como allow, pois é exatamente o que acontece no modo enforce.

Um deny registrado não é prova de que o harness interrompeu a ação. Denies de chamadas de ferramentas são verificados em todos os 12 harnesses suportados; outros eventos podem variar. Consulte [capacidade de enforcement](/pt-br/reference/harnesses#enforcement-capability).

## Investigar um resultado inesperado

| O que você vê | O que verificar |
| --- | --- |
| Nenhuma decisão | `failproofai config --status` e se a sessão está pausada |
| Muitos denials sem nome de política | [Comportamento em caso de falha de política](/pt-br/policies/failure-behavior) |
| Toda ação protegida sendo negada | Se o serviço `failproofaid` está saudável |
| Um deny que não é possível desativar | `block-failproofai-commands` está sempre ativado |
| Nenhum dado para `--env production` | Novas máquinas usam o ambiente `local` |
