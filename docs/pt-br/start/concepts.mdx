O Failproof AI registra o que os agentes fazem e decide o que eles podem fazer.

## Observar

| Termo | Significado |
| --- | --- |
| Session | Uma execução de agente |
| Event | Uma ação dentro de uma session |
| Trace | A visualização ordenada de uma session |
| Evaluation | Uma pontuação ou julgamento |
| Audit | Uma revisão de várias sessions |
| Finding | Evidência de um padrão de falha |
| Issue | A resposta que alguém é responsável por conduzir |
| Alert | Uma regra que detecta recorrência |

## Aplicar

| Termo | Significado |
| --- | --- |
| Harness | O ambiente onde um agente é executado |
| Hook | Um ponto onde o harness solicita uma decisão |
| Policy | Uma regra que permite, orienta ou bloqueia |
| Policy pack | Um conjunto de policies versionado que qualquer pessoa pode instalar |
| Daemon | O serviço local que avalia policies |
| Deployment | Policies atribuídas a uma máquina |

## O fluxo de trabalho

```text
Session → Audit → Finding → Issue → Policy
```

Comece com evidências. Identifique a falha recorrente, atribua a resposta e então previna sua repetição.

Uma policy retorna `allow`, `instruct` ou `deny`. A orientação via `instruct` depende do harness; use `deny` quando a ação precisa ser interrompida.

O modo de observação é independente da decisão. Ele executa a policy real e registra o que ela faria, enquanto permite que o agente continue.

<Warning>
  Um `fp fleet deploy <machine> --add <policy>` simples aplica as regras imediatamente. Adicione `:observe` para um rollout em modo sombra.
</Warning>

A configuração inicial não escolhe nenhum policy pack. Antes de adicionar um, apenas `block-failproofai-commands` é executado. O catálogo compilado contém 39 policies em 9 categorias.

Consulte os [harnesses suportados](/pt-br/reference/harnesses#enforcement-capability) antes de assumir que um event pode bloquear em qualquer ambiente de agente.
