Comece com um comportamento que você quer bloquear e uma ação legítima que ainda deve funcionar.

## Experimente uma política revisada primeiro

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI inclui 39 políticas revisadas. Consulte o [catálogo](/pt-br/policies/builtin-catalog) antes de escrever uma nova.

## Escreva e teste a sua própria

<Steps>
  <Step title="Crie uma política funcional">
    ```bash
    failproofai publish --init guards.mjs
    ```

    Isso cria uma política que bloqueia `git push --force`. Edite-a para a sua regra.
  </Step>
  <Step title="Aplique-a nesta máquina">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    Peça ao seu agente para executar a ação bloqueada e, em seguida, verifique **Policies → Activity** no painel local.
  </Step>
  <Step title="Mantenha ou remova">
    Coloque um arquivo `*policies.mjs` em `.failproofai/policies/` para carregá-lo automaticamente.

    Remova arquivos personalizados explícitos com:

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## Compartilhe

Publique um pacote público:

```bash
failproofai publish
```

Qualquer pessoa poderá instalá-lo com `failproofai policies add <owner>/<repo>`. Adicione o tópico do GitHub `failproofai-policies` manualmente para que o [Policy Hub](https://befailproof.ai/policy-hub/) possa indexá-lo.

Para uma implantação na nuvem:

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  Um `--add checkout-guard` simples aplica a política imediatamente. Adicione `:observe` para registrar o que a política faria sem bloquear o agente.
</Warning>

Consulte [publicar um pacote](/pt-br/policies/publish-a-pack) ou [implantar políticas](/pt-br/policies/deploy) para o fluxo completo.
