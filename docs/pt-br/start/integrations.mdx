## Antes de começar

Dois requisitos que este caminho assume, e que o código abaixo não resolve por você:

| Requisito | Por quê |
| --- | --- |
| Python 3.10 ou mais recente | O mínimo declarado pelo SDK. |
| Uma máquina configurada com `failproofai config` | Esse comando instala o daemon failproofaid, e o daemon é o único responsável por enviar o que o SDK grava. Sem ele, os lotes se acumulam no diretório de spool e nunca saem. |

<Note>
  **Este caminho registra; não aplica políticas.** O SDK captura o que seu agente fez. As políticas são disparadas por um hook dentro de uma CLI de agente, então aplicar políticas a um agente de framework significa adicionar um hook ao seu próprio runtime — veja [Policies](/pt-br/policies/overview).
</Note>

## Três linhas, independente do framework

<CodeGroup>
```bash LangGraph
pip install 'failproofai-sdk[langgraph]'
```

```bash CrewAI
pip install 'failproofai-sdk[crewai]'
```

```bash LlamaIndex
pip install 'failproofai-sdk[llamaindex]'
```

```bash Pydantic AI
pip install 'failproofai-sdk[pydantic-ai]'
```

```bash Custom agents
pip install failproofai-sdk
```
</CodeGroup>

```python
import failproofai_sdk

failproofai_sdk.configure(environment="production")
failproofai_sdk.instrument()          # detects the frameworks you imported

with failproofai_sdk.session():
    ...                               # your existing agent call, unchanged
```

Sem decoradores nas suas funções, sem callbacks passados nas suas chamadas, sem ids espalhados pelo seu código. Apenas a chamada dentro da sessão é diferente:

<Tabs>
  <Tab title="LangGraph">
    ```python
    graph.invoke({"messages": [HumanMessage("...")]})
    ```
  </Tab>
  <Tab title="CrewAI">
    ```python
    Crew(agents=[analyst, writer], tasks=[gather, summarise]).kickoff()
    ```
  </Tab>
  <Tab title="LlamaIndex">
    ```python
    await agent.run("...")        # under `async with failproofai_sdk.session():`
    ```
  </Tab>
  <Tab title="Pydantic AI">
    ```python
    agent.run_sync("...")
    ```
  </Tab>
  <Tab title="Custom agents">
    ```python
    with failproofai_sdk.agent("planner"):
        with failproofai_sdk.tool_call("search", input={"q": q}) as t:
            t.output = search(q)
    ```
  </Tab>
</Tabs>

O extra instala o **framework**. Todos os adaptadores já vêm no pacote base, portanto um projeto que já possui seu framework não precisa de nenhum extra.

## Verifique se chegou

Execute uma sessão instrumentada e abra **Observe → Sessions**, selecionando seu ambiente. A execução aparece como um trace reconstruído.

Se nada aparecer, confirme que a máquina está configurada e conectada com `failproofai config --status`. Se não estiver, execute `failproofai config`. Veja [Choose your setup](/pt-br/start/setup).

<Warning>
  Não verifique o diretório de spool para confirmar a entrega. O daemon do Failproof coleta e exclui cada lote em milissegundos, então ler o diretório cria uma condição de corrida com o coletor e exibe muito menos eventos do que foram emitidos.
</Warning>

Para verificar se o SDK está gravando, pare o daemon primeiro, execute sua sessão e verifique `~/.failproofai/custom-agents/events/`. Com o daemon em execução, um diretório vazio é o estado esperado.

<CodeGroup>
```bash Linux
sudo systemctl stop failproofaid@$USER
```

```bash macOS
sudo launchctl bootout system/ai.failproof.failproofaid.$USER
```
</CodeGroup>

Execute `failproofai config` depois para restaurar o daemon. Enquanto ele estiver parado, eventos de hook nesta máquina não terão avaliador e serão negados, portanto pare-o apenas pelo tempo necessário para a verificação.
