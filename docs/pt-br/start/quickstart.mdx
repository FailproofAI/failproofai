Este guia de início rápido configura uma máquina para reportar sessões, executa uma auditoria e implanta uma política. Use a skill para configurar o Failproof AI, ou siga os passos manuais.

**Qual é o seu caminho?** Se seu agente roda em um dos 12 [harnesses](/pt-br/reference/harnesses) suportados — uma CLI de codificação, ou um gateway como Hermes ou OpenClaw — siga os passos abaixo; você precisará de Node.js 20.9 ou superior. Se seu agente não possui harness, instrumente-o com o [SDK Python](/pt-br/reference/custom-agents) para rastreamento e auditorias, depois retorne em [Execute sua primeira verificação de falha](/pt-br/start/first-audit); a aplicação de políticas nesse caminho requer um hook no seu runtime.

  <Tab title="Configuração manual">
    ## Instalação

<Steps>
  <Step title="Instale e conecte o Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    Esse único comando cobre toda a configuração: instala o daemon local (uma vez como root), conecta os hooks a todas as CLIs de agente encontradas e conecta esta máquina ao Cloud.

    Em **Connect to cloud**, a configuração inicia o login no FailproofAI Cloud imediatamente (pressione Tab para as outras opções: colar uma chave de API ou usar open source). Ele abre um link no seu navegador (via SSH, ou em uma máquina sem display, imprime o link para que você possa abri-lo em qualquer dispositivo). Cadastre-se ou faça login, confirme a organização — ou crie uma ali mesmo — e clique em **Authorize**. O nome e as permissões da chave são definidos automaticamente. Não é necessário ter uma conta previamente.

    O terminal detecta isso sozinho e exibe quem autorizou e para qual organização. Confirme os agentes a rastrear e a configuração é concluída. A chave da máquina só é criada nesse momento, após a instalação do daemon, portanto uma execução abandonada não deixa nenhuma chave para trás; ela aparece em **Administration → Keys** marcada como **cli login**, onde pode ser revogada.

    <Accordion title="Sem navegador ou terminal disponível? Use uma chave (CI, containers, scripts de provisionamento)">
      No [painel do Failproof AI](https://app.befailproof.ai), vá em **Administration → Keys** e crie uma chave com `events:add` e `policies:pull`. Se você planeja usar o [Jev pelo FailproofAI Cloud](/pt-br/reference/jev-cloud), escolha o preset **machine**, que também concede `jev:evaluate`. Copie o segredo de uso único e leia-o em um shell na máquina de destino — `read -s` o recebe em um prompt que não exibe a entrada:

      ```bash
      read -rs FAILPROOFAI_KEY && export FAILPROOFAI_KEY
      FAILPROOFAI_CLOUD_TOKEN="$FAILPROOFAI_KEY" failproofai config
      ```

      Passar a chave pela variável de ambiente em vez de `--token` evita que ela apareça no `ps`, onde qualquer usuário da máquina pode ler os argumentos de um comando. Isso não a remove do histórico do shell — usar `read -s` é o que evita isso. Em ambientes de CI, injete-a como um segredo mascarado e mantenha o rastreamento do shell (`set -x`) desativado, ou o trace a exibirá. Em uma execução interativa, você também pode escolher **Paste an API key** em **Connect to cloud**.
    </Accordion>

    Transcrições de sessão são enviadas por padrão. Adicione `--no-transcripts` para reportar atividade de hook e decisões de política sem o conteúdo das transcrições.

    <Warning>
      Não use `failproofai config --connect <url>` aqui. Essa flag registra uma máquina que **já** está configurada e retorna imediatamente — sem daemon, sem hooks — portanto a máquina apareceria no Cloud sem coletar nem aplicar nada.
    </Warning>

    Se esta máquina já possui histórico de agente, visualize e importe os últimos sete dias, depois aguarde a conclusão da entrega. Pule esta etapa em uma máquina nova.

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    Abra **Sessions** no Failproof AI e selecione uma sessão importada.
  </Step>
  <Step title="Conecte o Failproof AI a um harness">
    A etapa anterior já conectou todas as CLIs de agente detectadas. Execute novamente para um harness específico quando necessário, ou para adicionar um harness instalado posteriormente. Todos os 12 são valores válidos para `--cli` — `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, `goose`.

    ```bash
    failproofai policies --install --cli claude --scope user     # uma CLI de codificação
    failproofai policies --install --cli hermes --scope user     # um gateway Slack/Telegram
    ```

    O bloqueio de uma chamada de ferramenta antes de sua execução é verificado em todos os 12. Gates de fim de turno são verificados em 8 — consulte a [capacidade de aplicação](/pt-br/reference/harnesses#enforcement-capability) para a matriz por harness.
  </Step>
  <Step title="Escolha o que aplicar">
    Conectar os hooks não ativa nenhuma política. A configuração não escolhe nenhuma deliberadamente — essa decisão é sua — portanto, adote um pacote:

    ```bash
    failproofai policies add FailproofAI/policies
    ```

    O pacote é obtido de seu release no GitHub, verificado pelo checksum e fixado na tag exata que foi resolvida. Ele contém 39 políticas e ativa as 10 que seu manifesto marca como seguras para habilitar sem supervisão. Use-as para ver decisões de política locais e experimentar a aplicação antes que o Failproof AI audite suas sessões e crie políticas para seus agentes.

    Leia qualquer pacote antes de adotá-lo com `failproofai policies show <owner>/<repo>`, e consulte [pacotes de políticas](/pt-br/policies/packs) para adotar apenas parte de um.

    Até que isso seja executado, o único recurso de aplicação ativo é `block-failproofai-commands` — a proteção sempre ativa que impede um agente de desligar o Failproof AI. `failproofai policies` lista o que está ativo.
  </Step>
  <Step title="Audite o comportamento">
    Siga [Execute sua primeira verificação de falha](/pt-br/start/first-audit). Use um objetivo concreto, como "encontrar sessões em que o agente repetiu uma ferramenta com falha sem mudar sua abordagem."
  </Step>
  <Step title="Previna a falha">
    Siga [Previna sua primeira falha com uma política](/pt-br/start/first-policy). Comece no modo de observação, inspecione as correspondências e depois aplique a versão revisada.
  </Step>
</Steps>

<Check>
  Execute `failproofai config --status`. Uma configuração saudável reporta a conexão com o cloud, o estado do daemon e se a aplicação está pausada.
</Check>

## Configuração do Jev

Use o [Jev](/pt-br/start/use-jev) para pontuar sessões concluídas em relação a uma pergunta com respostas conhecidas, ou para revisar chamadas de ferramentas em contexto antes de serem executadas. A página **Use Jev** contém ambos os caminhos de configuração.
