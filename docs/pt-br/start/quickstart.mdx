Configure o Failproof AI em uma máquina e fique local ou conecte ao Cloud.

Se o seu agente roda em um [harness compatível](/pt-br/reference/harnesses), siga estes passos. Para agentes criados com LangChain, CrewAI, LlamaIndex, Pydantic AI ou seu próprio runtime, comece por [instrumentar seu agente](/pt-br/start/integrations).

## Deixe seu agente guiar a configuração

Instale a skill guarda-chuva do Failproof AI em um agente compatível:

```bash
npx skills add FailproofAI/skills
```

Isso instala a skill guarda-chuva e suas skills especialistas associadas. Use `--skill
failproofai` se quiser apenas a guarda-chuva. Ela entende configuração local e Cloud,
saúde do daemon, sessões, auditorias, políticas e resolução de problemas. Ela guia o trabalho
e direciona tarefas especializadas para a skill correta do Failproof AI; ela não substitui
a instalação via CLI descrita abaixo.

## Configure a máquina

<Steps>
  <Step title="Instale e configure o Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    A instalação inicializa o serviço em segundo plano e conecta todos os agentes compatíveis encontrados. Pode solicitar acesso de administrador uma única vez. Compatível com Linux e macOS.
  </Step>

  <Step title="Escolha as políticas">
    A instalação não seleciona nenhum pacote de políticas. Adicione o pacote do Failproof AI:

    ```bash
    failproofai policies add FailproofAI/policies
    failproofai policies
    ```

    O segundo comando exibe todas as políticas desta máquina e indica quais estão ativas. Até que você adicione um pacote, apenas `block-failproofai-commands` é executada.
  </Step>

  <Step title="Verifique a máquina">
    ```bash
    failproofai config --status
    ```

    Este comando informa o status do serviço, a conexão com o Cloud e o estado de pausa.
  </Step>
</Steps>

## Escolha local ou Cloud

<Tabs>
  <Tab title="Ficar local">
    Não é necessária nenhuma conta.

    ```bash
    failproofai
    failproofai audit
    ```

    O primeiro comando abre o dashboard local em `http://localhost:8020`. O segundo escaneia o histórico de agentes já presente nesta máquina.
  </Tab>

  <Tab title="Conectar ao Cloud">
    Crie uma chave de máquina no Failproof AI Cloud e execute:

    ```bash
    failproofai config --token <machine-key>
    failproofai config --status
    ```

    O Cloud recebe as decisões de políticas e os transcritos de sessão. Para enviar apenas as decisões, conecte primeiro e depois defina `collector.sessions` como `false` em `~/.failproofai/config.json`; a flag de instalação `--no-transcripts` não aplica essa configuração. Para shells compartilhados e CI, use `FAILPROOFAI_CLOUD_TOKEN` em vez de colocar a chave no histórico de comandos.
  </Tab>
</Tabs>

## Verifique o funcionamento

Execute um dos seus agentes e peça para ele realizar uma tarefa normal. Em seguida:

A negação de chamadas de ferramentas é verificada em todos os 12 harnesses compatíveis. A aplicação no fim de turno é verificada em 8; outros pares harness-evento podem ser apenas de observação ou não verificados.

- Abra **Policies → Activity** no dashboard local para ver as decisões de políticas.
- Abra **Observe → Sessions** no Cloud para ver a execução completa.
- Execute `failproofai audit` para identificar padrões arriscados ou ineficientes.

<Warning>
  Após a configuração, o serviço `failproofaid` é o avaliador. Se ele não conseguir responder, as ações protegidas serão negadas. Execute `failproofai config --status` quando um agente parar inesperadamente.
</Warning>
