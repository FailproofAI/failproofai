O Failproof AI pode ser executado inteiramente em uma máquina ou conectado ao Cloud para sessões compartilhadas e gerenciamento de políticas.

## Local, sem conta

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai
```

Isso instala o serviço, conecta os agentes compatíveis, adiciona um pacote de políticas e abre o painel em `http://localhost:8020`.

Execute `failproofai audit` para escanear o histórico de agentes já presente na máquina.

## Conectar ao Failproof AI Cloud

Crie uma chave de máquina no Cloud e execute:

```bash
failproofai config --token <machine-key>
failproofai config --machine-label checkout-runner-01
failproofai policies add FailproofAI/policies
failproofai config --status
```

Ou exporte `FAILPROOFAI_CLOUD_TOKEN=<machine-key>` e execute apenas `failproofai config`. Prefira a variável de ambiente em máquinas compartilhadas e em CI para que a chave não fique registrada no histórico do shell ou nas listagens de processos.

O Cloud usa uma única conexão para duas funções distintas:

- Baixar as políticas atribuídas a esta máquina.
- Enviar decisões de políticas e transcrições de sessões.

Para enviar apenas as decisões, conecte-se primeiro e depois defina `collector.sessions` como `false` em `~/.failproofai/config.json`. Não dependa de `--no-transcripts`: o caminho de configuração atual analisa a flag, mas não a aplica. Consulte [eventos e configuração](/pt-br/reference/events-and-configuration#machine-configuration).

<Note>
  `--machine-label` renomeia uma máquina que já está conectada. Execute após o comando de configuração, não como parte da primeira conexão.
</Note>

## Configuração autônoma

`failproofai config` não requer uma flag especial para modo não interativo. Em CI ou em um contêiner, ele aplica a configuração solicitada sem solicitar confirmações.

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

O acesso de administrador é necessário uma única vez para instalar o serviço em segundo plano. A configuração nunca abre um prompt interativo de senha `sudo`: ela é concluída sem um ou exibe os comandos que um administrador precisa executar.

## Suporte a plataformas

A configuração é compatível com Linux e macOS. Em outra plataforma, o processo é encerrado sem gravar hooks ou estado parcial de configuração.
