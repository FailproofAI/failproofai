Use `fp` to inspect Cloud telemetry, manage cloud-managed enforcement (policies, fleet deployments, guardrail decisions), and manage audits, findings, issues, alerts, keys, users, queries, and settings. Use [`failproofai`](/reference/failproof-cli) for local hooks, policies, capture, and machine enrollment.

You can also author and deploy hosted code, LLM-judge and Jev evaluators, manage
dashboards, inspect sentiment, and use the dashboard assistant from the terminal.

Install the released Cloud CLI as an isolated tool:

```bash
uv tool install fp-cloud-cli
fp version
```

## Sign in

```bash
fp login
fp whoami
```

## Syntax

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Global options must come before the command:

```bash
fp --json sessions --since 24h
```

Run `fp COMMAND --help` or `fp COMMAND SUBCOMMAND --help` for terminal help.

## CLI commands

### Author an evaluator

`fp evaluators` authors definitions; `fp evals` reads results. An enabled managed
instance is required (`fp evaluators instances`). Authoring needs
`evaluations:trigger`; session dry-runs and schema profiling also need `events:read`.

Code is one restricted Python expression. Save this as `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev binary and graded rubric:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
Creation enables the evaluator. Deploy creates a new immutable version, then
disables older enabled versions. A failed follow-up leaves the new version
published: inspect `evaluators list --all` before retrying.
Judge dry-runs are refused by Cloud. Jev dry-runs spend model budget.
Backfill excludes judge/Jev and accepts at most 90 days.
</Warning>

AI drafting requires `fp login` and writes a spec accepted by create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Command | Options / behavior |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Full source/envelope |
| `fp evaluators create` | `--key`, `--name`, `--version`, repeated `--label`, `--condition EXPR\|@file`, one source, repeated `--dry-run-on`, `--disabled` |
| `fp evaluators deploy KEY` | Same source flags; `--version`, code-only `--backfill 7d`; numeric versions auto-increment |
| `fp evaluators draft "intent"` | Session; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Source flags or `--file`, repeated `--session` (maximum 10); none = compile only |
| `fp evaluators enable\|disable KEY[@VERSION]` | Toggle |
| `fp evaluators label KEY[@VERSION]` | Repeated `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | Inspect managed fleet/schema/jobs |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run` |

Code flags are `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. Judge flags are `--judge --criteria TEXT`, repeated `--step` and
`--threshold`. Jev flags are `--jev noul --instructions --true --false` or
`--jev score --instructions` with 3–5 distinct `--level` values, worst first.
Judge/Jev require a score; thresholds are 0–1. Binary judge steps are rejected.

Spec files contain exactly `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
Judge/Jev `evaluator_source` is a JSON envelope string. Do not include row ids,
enabled state, or AI reasoning metadata. `--file` and discrete spec flags are
exclusive; deploy can override the file's version. Output files are never overwritten.

### Events

```text
fp events [OPTIONS]
```

Lists individual agent events. The default light feed excludes raw payloads; use `--full` only for a bounded investigation.

| Option | Description |
| --- | --- |
| `--limit`, `-n <n>` | Maximum total rows. Default: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, or `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC range; overrides `--since`. |
| `--env <value>` | Environment filter; repeat or comma-separate values. |
| `--event-type <value>` | Event-type filter; repeat or comma-separate values. |
| `--agent-id <value>` | Agent filter; repeat or comma-separate values. |
| `--session-id <value>` | Session filter; repeat or comma-separate values. |
| `--search <text>` | Payload text search; repeatable, with any term matching. |
| `--order asc\|desc` | Time order. Default: newest first. |
| `--all` | Auto-paginate up to `--limit`. |
| `--cursor <token>` | Resume from an opaque cursor. |
| `--page-size <n>` | Rows per request with `--all`; maximum `200`. |
| `--full` | Include raw payloads through the heavier event endpoint. |
| `--fields <csv>` | Return only selected fields; requesting `payload` enables full mode. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` paginates **up to `--limit`**, which defaults to **50** — so `--all` on
  its own stops at 50 rows. When it stops early the response carries a
  `next_cursor` to resume from; `"next_cursor": null` means the feed really was
  exhausted.
</Note>

#### Audit create options

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Option | Description |
| --- | --- |
| `--file <path>` | Base the definition on JSON, or use `-` for stdin. Explicit flags override file values. |
| `--description <text>` | State the failure question or purpose. |
| `--enabled` / `--disabled` | Start scheduling on or off. Default: enabled. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Default: `86400`. |
| `--schedule-anchor <timestamp>` | Fixed UTC phase in ISO 8601 form. Default: next 09:00 UTC. |
| `--window-mode since_last\|fixed` | Continue after the last fully analyzed window or repeatedly inspect a rolling window. Default: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Default: `604800`. |
| `--scope '<json>'` | Filter by `environments`, `agent_ids`, or other supported scope fields. |
| `--ignore-error-type <type>` | Exclude error types; repeat or comma-separate. |
| `--llm` / `--no-llm` | Enable or disable agentic analysis. Default: enabled. |
| `--top-k <n>` | Retain `1`–`500` findings. Default: `50`. |
| `--sensitivity low\|medium\|high` | Set reporting sensitivity. Default: `medium`. |
| `--channels '<json>'` | Notification channel array. |
| `--text <brief>` | Inline brief, maximum 8,192 characters. |
| `--text-file <path>` | Read the brief from a file; mutually exclusive with `--text`. |
| `--url <https-url>` | Add a public HTTPS reference; repeat up to five times. |

Include context during creation when the first run needs it. Creation commits the definition and context together before the queued run begins.

<Note>
  `fp audits run` is asynchronous. Poll `fp audits runs NAME` until the latest run succeeds or fails before reading its findings.
</Note>

`--api-key` is intended for automation. Login, organization switching, and assistant commands require a user session.

## Environment variables

| Variable | Equivalent or purpose |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | Relocate the CLI configuration directory (default `~/.failproofai/fpcli`). |
| `FP_ANALYTICS_DISABLED` or `DO_NOT_TRACK` | Disable anonymous CLI analytics. |
| `NO_COLOR` | Disable colored output. |

Explicit flags override environment variables, which override saved configuration. In API-key mode, select the tenant explicitly with `--org` or `FP_ORG`.

<Warning>
  The `AGENTEYE_*` spellings of these are **not read by `fp`** and never were — the CLI declares `FP_*` (`fp_cli/app.py`), and an unknown variable is not an error. Setting `AGENTEYE_DASHBOARD_URL` does not retarget the CLI; it is ignored and the command silently runs against the saved dashboard instead.

  `AGENTEYE_HOME` and `AGENTEYE_ENVIRONMENT` do still exist, but they belong to the **collector and the telemetry SDK**, not to this CLI.
</Warning>

<Warning>
  Commands that delete, revoke, suppress, resolve, or replace configuration prompt by default. Use `--yes` only after verifying the active organization and target.
</Warning>
