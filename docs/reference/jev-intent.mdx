When you configure your own Jev endpoint, the Jev evaluator judges each tool call against **what the human asked for**, not against whatever text the harness put in front of the agent. A reply such as "yes, force-push it" can clear a reviewable policy, so the only text that ever counts as the human's is text a human typed into the harness's prompt box.

A prompt is recorded **only when the hook event itself establishes that a person typed it** — the event Failproof AI was invoked for, and the fields the harness wrote on the hook's stdin. Nothing on disk is consulted: the session transcript is a file the agent can rewrite, so it is never asked who wrote a prompt. Anything missing, empty or merely probable records nothing.

Failing closed here can only make enforcement stricter. With no recorded prompt, Jev has no task to judge the call against, so it cannot clear any reviewable policy and the beyond-the-task check stays off. Nothing is ever allowed because a prompt could not be captured.

This page lists, for each of the 12 supported harnesses, where that text comes from. Harnesses that never deliver human text through a prompt event are also listed, with the reason.

## Per-harness table

"Text field" is the stdin payload field after Failproof AI's per-harness normalization. "Recorded" says whether the prompt is kept as the human's request.

| Harness | `--cli` | Prompt event → canonical | Text field | Recorded | Agent's last message read from |
| --- | --- | --- | --- | --- | --- |
| Claude Code | `claude` | `UserPromptSubmit` | `prompt` | Only when the payload's `source` is `user`, Claude Code's own name for the interactive composer. A build that does not send the field records nothing | the session transcript (`transcript_path`) |
| Codex | `codex` | `user_prompt_submit` → `UserPromptSubmit` | `prompt` | No | — |
| GitHub Copilot CLI | `copilot` | `UserPromptSubmit` | `prompt` | Yes | the session's `events.jsonl` |
| Cursor | `cursor` | `beforeSubmitPrompt` → `UserPromptSubmit` | `prompt` | Yes | the agent transcript JSONL |
| OpenCode | `opencode` | `message.updated` (user role) → `UserPromptSubmit` | `prompt` | No | — |
| Pi | `pi` | `input` → `UserPromptSubmit` | `prompt` | Only when Pi marks it as typed or sent by an RPC client (`input_source`: `interactive` or `rpc`), never input another extension sent | the session JSONL |
| Hermes | `hermes` | none | — | No | — |
| OpenClaw | `openclaw` | `before_agent_run` → `UserPromptSubmit` | `prompt` | Only when marked as the owner's own message — which the shipped plugin never marks, so nothing is recorded today | none (`before_agent_run` carries no transcript path) |
| Factory Droid | `factory` | `UserPromptSubmit` | `prompt` | No | — |
| Devin CLI | `devin` | `UserPromptSubmit` | `prompt` | Yes | none (its transcript is one JSON document, not JSONL) |
| Antigravity CLI | `antigravity` | `PreInvocation` → `UserPromptSubmit` | none | No | — |
| Goose | `goose` | `UserPromptSubmit` | `message` | Yes | none (sessions are stored in SQLite) |

When a harness records nothing, Jev still evaluates every tool call, but with no task to judge against. Nothing can be cleared on the grounds that the human asked for it, and the check that flags a call reaching beyond the human's task stays off.

## What makes a prompt the human's

Three things, and nothing else:

1. **The event.** Failproof AI was invoked for the harness's prompt-submit event, which the handler canonicalizes to `UserPromptSubmit`. For a harness that fires this event only when a person submits a message, that alone is the evidence.
2. **The payload.** The harness writes the payload on the hook's stdin. The agent cannot edit it. Where a harness fires this event for prompts nobody typed as well — a scheduled task, a `/loop` wakeup, another extension, a heartbeat run, a message from someone else in a shared chat — a prompt counts only when the harness's own field says this one was typed. A payload without that field records nothing; so does a call that reaches Failproof AI without its payload at all.
3. **Nothing else.** A payload that names a sub-agent (`agent_id`) is the agent prompting itself and is never recorded. A session id that is not a plain name is never used. Text that is entirely harness wrapping is dropped (see below).

**The session transcript is not evidence of who wrote a prompt.** Earlier versions of this page described a transcript cross-check: the prompt was refused if the transcript showed the model scheduling it, and the transcript had to continue the one the previous prompt saw. That check is gone. A transcript is a file the agent already has a shell over — it can be truncated, replaced, padded past the read budget, snapshotted at the start of a turn and restored at the end, or made to read well again with entries the agent wrote. Each round of hardening was followed by another spelling of the same forgery, so the whole mechanism was removed rather than repaired. What is left is what a harness tells us directly, and prompts that cannot be established that way are simply not recorded.

The transcript is still read for one thing: **the agent's last visible message**. That message is agent-written by definition, Jev is told so, and it is never consent on its own.

## Harnesses that are not recorded

- **Claude Code before the `source` field.** `UserPromptSubmit` fires for more than typed prompts: a scheduled task coming due (`CronCreate`, a routine), a dynamic `/loop` wakeup, a `-p` or Agent SDK run, and machine-injected turns (peer and channel messages, task notifications, auto-continuation) all go through the same path. Claude Code names the author in the event's own `source` field (`user`, `sdk`, `system`, `loop_wakeup`, `schedule_wakeup`, `poll_event`), and only `user` is recorded. The field is optional in Claude Code's hook-input schema — "Payloads may omit it while the field rolls out" — and **2.1.280 does not send it**, so on that build no Claude Code prompt is recorded at all. `sdk` is not recorded either: an agent holding a shell can start its own `claude -p`, and that session reports `sdk` just as a scripted run does.
- **Codex** fires `user_prompt_submit` inside sub-agent threads too, whose prompts the parent agent wrote, and its hook payload carries no mark of which thread the event belongs to. The only witness was the rollout's `session_meta.source`, a file on disk the agent can rewrite, so Codex prompts are not recorded.
- **Factory Droid** has Claude-shaped payloads and transcripts, ships a `SubagentStop` event, and sends no `source` field. Whether it fires `UserPromptSubmit` for prompts the model arranged has not been verified, and unverified is not the same as typed, so droid prompts are not recorded.
- **Hermes** has no prompt-submit event. Its native plugin handles `pre_llm_call` itself and forwards only tool, session and subagent events.
- **Antigravity CLI** maps `PreInvocation` to `UserPromptSubmit`, but `PreInvocation` fires before *every* model call in a turn, carries no prompt text, and hooks can inject `userMessage` steps into the same conversation. Nothing in it identifies a human turn.
- **OpenCode** reports prompts through the `message.updated` bus event. In current OpenCode the message it carries has no text parts, so the forwarded prompt is empty. The event also fires again on every update to the same message, for the child sessions the task tool creates (whose "user" message the parent agent wrote), and for the re-prompts Failproof AI itself sends to deliver an instruction.
- **Pi** fires `input` for what the human types and also for text another extension sends with `sendUserMessage()`, which can be written by the model or built from repository content. Pi says which in the event's `source`, and the Pi bridge forwards it as `input_source`. A Pi prompt is recorded only when that field is `interactive` (typed in Pi, or passed to `pi -p`) or `rpc` (sent by the program driving Pi in RPC mode). Input another extension sent is never recorded, and neither is a prompt from a bridge too old to forward the field.
- **OpenClaw** fires `before_agent_run` for heartbeat, cron, memory and inter-session runs as well as for chat messages, and on a shared channel the sender may not be the owner. OpenClaw states that a missing classification does not establish human origin, and it sets the owner flag only when it knows the sender. So a prompt is recorded only when the payload carries all three of `openclaw.trigger: "user"`, `openclaw.inputProvenance.kind: "external_user"` and `openclaw.senderIsOwner: true`. A missing field counts as not typed by the owner, so on a shared channel a message from anyone else in the chat is never recorded. The current plugin does not forward these fields, so no OpenClaw prompt is recorded yet.

## What is kept from a prompt

Harnesses put more than the human's words into a prompt. Before anything is stored:

- `<system-reminder>` blocks are removed, and the human's words around them are kept.
- A session-continuation summary ("This session is being continued from a previous conversation…") is dropped entirely.
- Task notifications, local-command output and interruption markers are dropped entirely.
- A turn another agent or session wrote is dropped entirely: Claude Code wraps those in `<cross-session-message>`, `<teammate-message>`, `<agent-message>`, `<coordinator-relay>` or `<channel source=…>`.
- Failproof AI's own messages are dropped entirely. A stop gate's `MANDATORY ACTION REQUIRED from failproofai …` or an `Instruction from failproofai: …` can come back as the next user turn on some harnesses (Cursor submits a stop gate's follow-up message as one), and they never count as the human's words.
- A slash command is kept as the command and arguments the human typed, never the body the harness expanded it into.
- A prompt the Codex IDE extension built keeps only the text after its last `## My request for Codex:` (or, in newer builds, `## My request:`) heading. Everything the extension put before it is dropped: the active file, open tabs, text selected in the editor, mentioned files and apps, diff and browser comments, PR checks, earlier conversations. Such a prompt starts with one of the extension's section headings (`# Context from my IDE setup:`, `# Selected text:`, `# Files mentioned by the user:` and the others it writes); one with no request heading is not recorded. The request itself is judged like any other turn: if what follows the heading is a continuation summary, a message another agent or session wrote, one of Failproof AI's own directives, or another of the extension's sections, the prompt is not recorded at all. (Codex prompts are not recorded live today; this cleaning also runs over replayed transcripts.)
- Pasted blocks are kept and labelled as pasted by the human.
- A Cursor prompt wrapped the way Cursor's own transcripts wrap a query (an optional `<timestamp>…</timestamp>`, then one `<user_query>…</user_query>` block) has the wrapper removed, but only when that wrapper is the whole prompt. A `<user_query>` tag anywhere else is part of the text: the whole prompt is kept, and the tagged span is never picked out as the request. Failproof AI's own messages are dropped whether or not they are wrapped.

A prompt that is nothing but harness text is not recorded at all.

## The agent's last message

A reply like "yes" means nothing without the question it answers. When a prompt is recorded, Failproof AI also reads the agent's last visible message from the session transcript **at that moment**, and stores it with the prompt. Jev receives it in its own field, labelled as written by the agent: it explains a short reply and never counts as the human's request. It is the one thing the transcript is read for, and the worst a rewritten transcript can do is put a message the agent wrote where a message the agent wrote is expected.

It is read from the end of the transcript, at most the last 4 MB. Supported transcript formats are Claude Code, Codex rollouts (older `agent_message` events and newer `AgentMessage` items), Cursor, Copilot `events.jsonl`, and the Pi, Factory and OpenClaw session JSONL. Claude Code's own synthetic and API-error messages and subagent (sidechain) messages are skipped. There is no snapshot for Goose and OpenCode, which keep sessions in SQLite, for Devin, whose transcript is a single JSON document, or for OpenClaw, whose `before_agent_run` event carries no transcript path.

## Storage

| Property | Value |
| --- | --- |
| Location | `~/.failproofai/state/semantic/sessions/<session-id>.json` |
| Permissions | file `0600`, directory `0700` |
| Kept per session | the last 5 prompts |
| Window | prompts older than 6 hours are ignored |
| Size | each prompt and agent message is capped at 1,200 characters, keeping the head and the tail |
| Secrets | redacted with the same patterns as the `sanitize-*` policies before anything is written. A text longer than 9,600 characters is redacted as its first 5,760 and last 3,840 characters, and the text next to those cuts, where a secret could have been split, is never stored |

A session ID containing anything but letters, digits, `.`, `_` and `-`, or longer than 128 characters, is never used as a file name, so nothing is recorded for it.

A session file exists only once a prompt has been recorded in it. It holds prompts and nothing else — no origin state, no transcript mark — and it is deleted once it has been silent for longer than the six-hour window, the next time a new session writes its first prompt.

Nothing is recorded unless a Jev endpoint is configured.

## Known limits

- **Claude Code records nothing on 2.1.280.** The `source` field this depends on is declared in that build's hook-input schema but is not populated (the payload builder computes the value and the field is compiled out of the object it builds), so every Claude Code prompt fails the check. Intent capture for Claude Code starts working, with no change here, on the first build that sends the field. Until then Jev judges Claude Code calls with no stated intent: every reviewable policy that fires, stands.
- **Codex and Factory Droid record nothing at all,** for the reasons in the table above. Both were previously recorded on the strength of a file the agent can write.
- **Headless and SDK runs record nothing.** `claude -p` and Agent SDK sessions report `source: "sdk"`, which is also what an agent's own `claude -p` subprocess reports, so neither is treated as the operator asking. `codex exec` records nothing because Codex records nothing. `pi -p` and Pi's RPC mode do still count: Pi reports those as `interactive` and `rpc`, and Pi has no equivalent of a prompt the model scheduled for itself.
- **Subagents.** A payload that carries `agent_id` is never recorded, on any harness. Claude Code 2.1.280 does not set it on `UserPromptSubmit`; the check is there for the build that starts to. Whether Copilot, Cursor, Devin or Goose fire their prompt event inside a subagent has not been verified — none of them is known to, and none of them provides a field that would say so. A subagent that Pi starts as its own `pi -p` process reports its task as `interactive`, so it counts as that subagent session's own request.
- **A recorded prompt is only as trustworthy as the hook invocation.** Everything here reads the payload the harness wrote on the hook's stdin. An agent that can run commands can also run Failproof AI's hook binary itself and feed it a payload it wrote, which would record a prompt nobody typed. Nothing inside this module can tell that invocation from the harness's own — both are the same program reading the same stdin — so this is the trust boundary the whole hook model already sits on rather than something the origin checks can close. It is written down here because *writing* intent is the one thing an agent gains from it: skipping the hook cannot clear a policy, since the harness invokes Failproof AI for the tool call independently.
- **An agent's last message can be a message the agent chose.** The transcript is not authenticated, so an agent that writes its own transcript can decide what its "last message" says. That is the same thing it could do by simply saying it, which is why the field is labelled agent-written and never clears anything on its own.
- **`CODEX_HOME` is not honoured** by the rollout discovery in `lib/codex-sessions.ts`. This no longer affects whether a prompt is recorded, only where an agent-message snapshot is looked for.
