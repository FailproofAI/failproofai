Start with:

```bash
failproofai config --status
failproofai policies
```

## An agent is not connected

Run setup again:

```bash
failproofai config
```

Setup supports Linux and macOS. It needs administrator access once to install the service, but never prompts for a sudo password.

Check harness paths and scopes in [Harnesses](/reference/harnesses).

## A session is missing

```bash
failproofai flush --wait
failproofai backfill --since 30d --dry-run
failproofai harness list
```

Drop `--dry-run` to resend old history. Add another transcript location with:

```bash
failproofai harness add-path <harness> [label=]<path>
```

Use a label when two locations contain copies of the same project.

## Every protected action is denied

On a configured machine, `failproofaid` is the only evaluator. If it cannot answer, protected actions fail closed.

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

Run `failproofai config` to repair or reinstall the service.

## One pack is denying

`failproofai policies` names packs that cannot load. A selected pack fails closed instead of disappearing.

Common causes:

- The artifact changed after installation.
- The manifest and bundled policies disagree.
- The file is missing or cannot be imported.
- The pack uses an unsupported event, tool, or policy shape.

Remove the pack or install a corrected release:

```bash
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

## Cloud is disconnected

Prefer an environment variable for the key:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
failproofai config --status
```

A machine can pull policies and send activity independently. Status reports both.

## A policy did not block

Check three things:

1. The policy is on: `failproofai policies`.
2. Its event and tool match the action.
3. That harness can enforce the event.

A tool-call deny is verified on all 16 supported harnesses. Other events vary. See [enforcement capability](/reference/harnesses#enforcement-capability).

## Downloads are blocked

- `FAILPROOFAI_NO_DOWNLOAD=1` refuses network downloads.
- `FAILPROOFAI_DAEMON_BASE_URL` points service downloads at a mirror.
- `FAILPROOFAI_PACK_BASE_URL` points pack downloads at a mirror.

Installed packs keep enforcing when downloads are disabled.
