Администрирование — это облачная часть Failproof AI. Организации, участники, ключи API, параметры организации и дозированное потребление требуют подключения к облаку.

<Note>
  Failproof AI также работает без учётной записи. Локальная машина применяет политику, сохраняет историю сеанса на диске, обслуживает [локальную панель управления](/ru/reference/local-dashboard) на `localhost:8020` и запускает `failproofai audit` без отправки данных куда-либо. Смотрите [конфигурацию машины](/ru/reference/events-and-configuration#machine-configuration) для локальных ключей `collector`. Пропустите остаток этого раздела, если вы не используете облако.
</Note>

## Аутентифицированный пользователь или ключ API

`fp` работает в одном из двух режимов аутентификации, и это разделение определяет, какие команды работают. Команда, которую не может выполнить ключ API, отказывает перед открытием соединения и указывает причину, вместо того чтобы вернуть 401 или 403.

| Команда | Ключ API | Разрешение |
| --- | --- | --- |
| `fp whoami` | Да | отсутствует |
| `fp usage` | Да | `usage:read` |
| `fp keys list` / `show` | Да | `keys:read` |
| `fp keys create` | Да | `keys:create` |
| `fp keys disable` | Да | `keys:disable` |
| `fp keys regenerate` | Да | `keys:regenerate` |
| `fp keys update` | Нет | `keys:update`, который не может иметь ни один ключ |
| `fp users list` / `show` | Да | `users:read` |
| `fp users create` | Да | `users:create` |
| `fp users update` | Да | `users:update` |
| `fp users disable` / `enable` | Да | `users:delete` |
| `fp settings list` / `schema` | Да | `settings:read` |
| `fp settings set` | Да | `settings:write` |
| `fp orgs list` / `switch` / `current` / `perms` | Нет | только аутентифицированный сеанс |

`fp usage` — это команда для скрипта отчётности: она выполняется без участия человека с ключом и требует только `usage:read`.
