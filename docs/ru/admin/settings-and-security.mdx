Настройки организации влияют на всех участников облачной организации. Измените их в **Admin → settings** или с помощью `fp settings`.

```bash
fp settings list
fp settings set <key> <value>
```

## Обработка данных

По умолчанию подключенная машина отправляет решения политик и полные стенограммы сеансов. Чтобы отправлять только решения, установите `collector.sessions` в значение `false` в файле `~/.failproofai/config.json` машины после подключения. Текущий флаг установки `--no-transcripts` не применяет эту настройку.

Учетные данные очищаются на машине перед загрузкой, но редактирование — это минимальный уровень защиты, а не замена контролю доступа.

Локальное использование не требует учетной записи. История сеансов и аудиты остаются на машине, за исключением запланированных локальных аудитов, которые отправляют идентификатор машины и ограниченный дайджест после вашего согласия. Анонимную телеметрию CLI можно отключить с помощью `FAILPROOFAI_TELEMETRY_DISABLED=1`.

## Учетные данные

Токены машины хранятся в `~/.failproofai/` с правами доступа только владельца. Они не записываются в определение сервиса.

Используйте отдельные ключи для людей, автоматизации и машин. Предоставьте каждому только необходимые разрешения, обновляйте ключ при смене владельца и отзывайте его, когда машина или рабочий процесс выводятся из эксплуатации.

## Контрольный список

- Требуйте наиболее узкие полезные разрешения.
- Установите `collector.sessions` в значение `false`, если полный контент не требуется.
- Проверьте, кто может развертывать применяемые политики.
- Протестируйте политики в режиме наблюдения перед применением.
- Держите метки машин четкими, а идентификаторы машин стабильными.
- Запустите `failproofai config --status` после изменения параметров подключения.

См. [keys and permissions](/ru/admin/keys-and-permissions) для каталога разрешений.
