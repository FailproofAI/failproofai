Используйте параметры для задания значений, специфичных для развертывания, и переопределения окна контекста модели. Перед изменением значения через API или CLI изучите схему параметров.

## Изменение параметра организации

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Administration → Settings**, найдите группу параметров и прочитайте описание и текущий источник.
    2. Измените значение и сохраните.
    3. Для окна контекста модели добавьте или обновите переопределение модели и подтвердите эффективный лимит.
    4. Перепроверьте сеансы и метрики, которые зависят от измененного значения.

    ![Страница Settings с параметрами аутентификации организации и операционными параметрами.](/images/dashboard/settings.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp settings list
    fp settings schema
    fp settings set <key> --value <scalar>
    fp settings set alerts.email_default_recipients \
      --json-value '["oncall@example.com"]'
    ```

    Запустите `fp settings set --help` для просмотра типа значения и флагов подтверждения, используемых установленным CLI.
  </Tab>
</Tabs>

## Выбор обработки данных

При подключении CLI Failproof AI по умолчанию отправляются стенограммы, так как следы и аудиты зависят от их содержания. Используйте `--no-transcripts`, если подсказки, содержимое файлов или ввод терминала должны оставаться локальными; активность hook и решения политик могут по-прежнему передаваться.

Локальные учетные данные для приема хранятся отдельно от параметров демона, не содержащих секретов, и записываются с ограничивающими разрешениями. Ключи API по-прежнему должны управляться как секреты производства.

## Справочник параметров организации

Все редактируемые на панели управления параметры имеют область действия организации. Поведение на уровне развертывания остается конфигурацией переменных окружения сервера.

| Ключ | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `allowed_sign_ins` | `[]` | Ограничьте существующих членов точными адресами электронной почты или `*@domain`; пустой список означает отсутствие дополнительных ограничений. |
| `session_ttl_secs` | `86400` | Время жизни сеанса панели управления; допустимый диапазон — от 60 секунд до 30 дней. |
| `otp_ttl_secs` | `600` | Время жизни OTP и волшебной ссылки; допустимый диапазон — 60–1800 секунд. |
| `alerts.email_default_recipients` | `[]` | Получатели по умолчанию, если канал оповещений по электронной почте их не переопределяет. |
| `alerts.slack_default_webhook` | пусто | URL входящего вебхука Slack по умолчанию. |
| `alerts.webhook_default_url` | пусто | URL вебхука JSON по умолчанию. |
| `alerts.webhook_signing_secret` | пусто | Ключ HMAC-SHA256, используемый для заголовка `X-AgentEye-Signature`; чтение замаскировано. |
| `alerts.enabled_channels` | email, Slack, webhook | Типы каналов на уровне организации, которые могут использоваться правилами оповещений. |
| `default_user_permissions` | `standard` | Именованный набор разрешений, предварительно выбранный для новых приглашений. |

`allowed_sign_ins` — это фильтр, а не разрешение: человек должен уже быть членом организации. Используйте пустой список, чтобы разрешить каждому члену; само значение `*` отклоняется. URL оповещений должны использовать HTTPS, за исключением адресов обратной петли для разработки.

## Контрольный список безопасности

- Используйте HTTPS для подключений Cloud.
- Ограничьте ключи наименьшим набором разрешений.
- Отделите продакшн и непродакшн среды.
- Проверьте параметры захвата и редактирования стенограмм перед развертыванием.
- Проведите аудит изменений пользователя, ключей и организации.
- Протестируйте требования к резервному копированию, хранению и реагированию на инциденты для вашего развертывания.

<Warning>
  Отключение захвата стенограмм изменяет то, что могут доказать аудиты и расследования. Запишите решение и его ожидаемые ограничения.
</Warning>
