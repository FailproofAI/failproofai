Используйте Settings для операционных значений, специфичных для развертывания, и переопределений размера контекстного окна модели. Перед изменением значения через API или CLI изучите схему настроек.

## Изменение организационной настройки

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Administration → Settings**, найдите группу настроек и прочитайте её описание и текущий источник.
    2. Измените значение и сохраните его.
    3. Для контекстных окон моделей добавьте или обновите переопределение модели и подтвердите действующий лимит.
    4. Перепроверьте сессии и метрики, которые зависят от изменённого значения.

    ![Страница Settings, показывающая организационную аутентификацию и операционные настройки.](/images/dashboard/settings.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp settings list
    fp settings schema
    fp settings set <key> --value <scalar>
    fp settings set alerts.email_default_recipients \
      --json-value '["oncall@example.com"]'
    ```

    Запустите `fp settings set --help` для информации о типах значений и флагах подтверждения, используемых установленным CLI.
  </Tab>
</Tabs>

## Выбор обработки данных

Подключение Failproof AI CLI по умолчанию отправляет стенограммы, потому что трассы и аудиты зависят от их содержимого. Используйте `--no-transcripts`, когда приглашения, содержимое файлов или ввод терминала должны оставаться локальными; активность hook и решения по политикам всё ещё могут быть зарегистрированы.

Локальные учётные данные приёма хранятся отдельно от параметров демона, не содержащих секреты, и записываются с ограничительными правами доступа. API ключи всё ещё должны управляться как производственные секреты.

## Справочник организационных настроек

Все редактируемые в dashboard настройки имеют область организации. Поведение на уровне развертывания остаётся конфигурацией серверного окружения.

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `allowed_sign_ins` | `[]` | Ограничьте существующих участников точными адресами электронной почты или `*@domain`; пустой список означает отсутствие дополнительных ограничений. |
| `session_ttl_secs` | `86400` | Время жизни сессии dashboard; допустимый диапазон — от 60 секунд до 30 дней. |
| `otp_ttl_secs` | `600` | Время жизни OTP и magic-link; допустимый диапазон — 60–1800 секунд. |
| `alerts.email_default_recipients` | `[]` | Получатели по умолчанию, когда канал email-оповещений их не переопределяет. |
| `alerts.slack_default_webhook` | пусто | URL входящего webhook Slack по умолчанию. |
| `alerts.webhook_default_url` | пусто | URL generic JSON webhook по умолчанию. |
| `alerts.webhook_signing_secret` | пусто | Ключ HMAC-SHA256, используемый для заголовка `X-AgentEye-Signature`; чтения маскируются. |
| `alerts.enabled_channels` | email, Slack, webhook | Виды каналов на уровне организации, которые правила оповещений могут использовать. |
| `default_user_permissions` | `standard` | Именованный набор разрешений, предварительно выбранный для новых приглашений. |

`allowed_sign_ins` — это фильтр, а не разрешение: человек уже должен быть участником организации. Используйте пустой список для разрешения каждому участнику; значение `*` отклоняется. URL-адреса оповещений должны использовать HTTPS, кроме адресов loopback для разработки.

## Контрольный список безопасности

- Используйте HTTPS для подключений Cloud.
- Ограничивайте ключи наименьшим набором разрешений.
- Разделяйте окружения production и non-production.
- Проверьте настройки захвата стенограмм и редакции перед развёртыванием.
- Аудируйте изменения пользователей, ключей и организации.
- Протестируйте требования к резервному копированию, хранению и реагированию на инциденты для вашего развертывания.

<Warning>
  Отключение захвата стенограмм изменяет то, что аудиты и расследования могут доказать. Запишите решение и его ожидаемые ограничения.
</Warning>
