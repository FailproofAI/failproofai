Использование показывает, что текущая организация учитывала в течение своего текущего 30-дневного периода. Окно фиксировано и закреплено для каждой организации, а использование только для чтения: оно не применяет и не отображает ограничения, квоты или пороги плана. Обе поверхности это показывают — панель CLI выводит «использование только для чтения, ограничений не применяется».

## Просмотр использования

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **admin → usage**.
    2. Подтвердите организацию и период учета — заголовок показывает начало и конец периода, текущий день в нем и истекшее время.
    3. Прочитайте основной блок: полученные события, сеансы, агенты и окружения.
    4. Прочитайте два конвейера: оценки (с оценками и метриками) и аудиты (с проблемами и оповещениями), каждый показывает завершенные запуски в сравнении с начатыми запусками.
    5. Прочитайте блоки рабочего пространства и доступа: сохраненные запросы, приборные панели, оповещения, уникальные проблемы, члены и ключи API.

    Цифры кэшированы, не в реальном времени. Используйте элемент управления обновлением в верхнем правом углу после изменения, которое вы ожидаете увидеть.

    ![Страница использования, показывающая период учета, полученные события, конвейеры оценки и аудита, ресурсы рабочего пространства, членов и ключи API.](/images/dashboard/usage-overview.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp usage
    fp --json usage
    fp --org reliability-team --json usage
    ```

    `fp usage` требует `usage:read` и работает с ключом API, что делает его подходящей командой для cron отчетов.

    С `--json` возвращает ответ панели без изменений: `org_id`, `billing_anchor`, `window`, `usage`, `calculated_at` и `stale_after`. `calculated_at` и `stale_after` показывают, насколько старая цифра.

    `fp usage` не принимает собственные флаги — только глобальные `--json` и `--org`. Он выводит отчет о текущем периоде и ничего раньше, поэтому ведите собственную историю, запуская его по расписанию и сохраняя полезную нагрузку `--json` вместо того, чтобы ожидать возможности запроса более раннего периода позже.

    ```bash
    fp --json usage | jq '.usage.events_ingested'
    ```
  </Tab>
</Tabs>

### Ключи метрик

Всё в разделе `usage` в полезной нагрузке JSON, поэтому скрипт может назвать поле вместо разбора панели.

| Группа | Ключи |
| --- | --- |
| Телеметрия | `events_ingested`, `sessions`, `agents`, `environments` |
| Оценки | `evaluation_runs`, `evaluation_finishes`, `evaluations`, `metrics` |
| Аудиты | `audit_runs`, `audit_finishes`, `issues_created`, `alerts_created` |
| Рабочее пространство | `queries_created`, `dashboards_created` |
| Доступ | `users_active`, `users_created`, `keys_active`, `keys_created` |

Каждый конвейер отдельно выводит количество начатых и завершенных запусков, поэтому разрыв между `audit_runs` и `audit_finishes` означает работу, которая начилась и не завершилась — стоит проверить перед тем, как делать какие-либо выводы из количества проблем ниже.

## Исследование изменения

Объем приема данных определяется для каждой машины, а не централизованно. Начните с организации и периода, затем рассмотрите, что изменилось на машинах, отправляющих отчеты в нее.

| Причина | Где проверить | Что изменить |
| --- | --- | --- |
| Машина отправляет расшифровки сеансов | `collector.sessions` в `~/.failproofai/config.json` этой машины | Установите `false`, чтобы отправлять только решения |
| Действие хука отправляется полностью | `collector.hooks_verbosity` в том же файле | `decisions` агрегирует разрешение один раз в минуту; `off` полностью останавливает события хука |
| Была добавлена новая точка захвата | `failproofai harness list` | Удалите с помощью `failproofai harness remove-path <harness> <path or label>` |
| История была отправлена повторно | Запуски `failproofai backfill` машины | Повторная отправка выполняет дедупликацию по хешу содержимого и свертывает в уже существующие строки, поэтому не учитывается дважды |
| Новая интеграция начала отправлять отчеты | Количества `agents` и `environments` и список сеансов | Ограничьте параметры сборщика новой машины перед развертыванием |

Использование ничего не сравнивает с планом. Делайте это вне продукта.
