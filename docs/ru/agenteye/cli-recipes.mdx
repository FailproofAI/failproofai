Извлекайте данные сессий, событий и оценок (и запускайте переоценки) прямо из скрипта или кодирующего агента с чистым JSON в stdout, который напрямую передаётся в `jq`. Эти рецепты превращают данные Failproof AI Observability в то, что может запрашивать и автоматизировать пользователь терминала или AI-кодирующий агент (Claude Code, Cursor), без использования интерфейса панели управления.

Приведённые ниже примеры готовы к копированию и вставке для Failproof AI Observability CLI (`agenteye`). О установке, аутентификации и полном списке опций см. [CLI](/ru/agenteye/cli); запустите `agenteye -h` или `agenteye <command> -h` для встроенной справки.

## Золотые правила

1. **Глобальные опции идут *перед* командой.** `agenteye --json sessions` — правильно; `agenteye sessions --json` — нет. Глобальные опции: `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, `--no-color`.
2. **Передавайте `--json` при каждом парсинге выходных данных.** Данные идут в **stdout** как JSON; статус и ошибки идут в **stderr**, чтобы stdout оставался чистым для передачи в `jq`.
3. **Ветвитесь по коду выхода, не по тексту stderr**: `0` ок · `1` неожиданная ошибка · `2` неправильные аргументы · `3` не удалось достичь панели управления · `4` не авторизован или сессия истекла · `5` недостаточно прав · `6` ресурс не найден.
4. **Исследуйте с помощью `-h`.** Каждая команда документирует свои фильтры, форматы значений и форму JSON.

## Одноразовая настройка

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com   # чтобы не повторять --base-url
agenteye login --email you@example.com                       # вставьте отправленный по почте код; действителен ~24ч
```

## Проверьте аутентификацию перед работой

`whoami` никогда не выдаёт ошибку при отсутствии или истечении сессии; вместо этого она сообщает `logged_in:false`, так что агент может безопасно проверить состояние аутентификации. (Она может вернуть ненулевой код выхода, если не установлен базовый URL или панель управления недоступна.)

```bash
if [ "$(agenteye --json whoami | jq -r .logged_in)" != "true" ]; then
  echo "Not authenticated. Run: agenteye login" >&2; exit 1
fi
```

## Найдите сессии с ошибками или низкой оценкой

```bash
# сессии за последние 24 часа, в которых оценка завершилась с ошибкой
agenteye --json sessions --since 24h --status error | jq -r '.sessions[].session_id'

# оценки с баллом <= 0,5 по полезности для одного агента
agenteye --json evals --agent-id checkout-bot --score helpfulness:..0.5 \
  | jq '.evaluations[] | {session_id, scores}'
```

Фильтрация по баллам находится на команде **`evals`**, а не `sessions`. `--score KEY:MIN..MAX` можно повторять и комбинировать с AND; любая граница опциональна (`..0.5` означает ≤ 0,5, `0.9..` означает ≥ 0,9). Вы можете передать до 20 фильтров по баллам за один запрос; больше вернёт HTTP 400. `sessions` делит `--env`, `--status`, `--agent-id`, `--session-id` и фильтры по диапазону времени с `evals`, но не имеет `--score`.

## Прочитайте одну сессию полностью

Нет единой команды `session show`. Комбинируйте последовательность событий с оценкой сессии:

```bash
# последняя оценка сессии (статус + баллы)
agenteye --json evals --session-id run-001 | jq '.evaluations[0] | {status, scores}'

# каждое событие в сессии (поднимите --limit для полного просмотра)
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'

# только вызовы инструментов в сессии (--full требуется, чтобы получить исходный payload)
agenteye --json events --full --session-id run-001 --event-type tool_use,tool_result --all \
  | jq '.events[].payload'
```

> **Примечание:** По умолчанию `events` читает быструю ленту без payload. Каждое событие содержит вычисленное сервером однострочное `summary` плюс флаги типа `is_error` и подсчёты токенов, но `payload` возвращается как `{}`. Чтобы получить исходный payload, добавьте `--full` (или `--fields payload`). Полная лента медленнее в масштабе, поэтому держите её ограниченной: сочетайте `--full` с одним `--session-id`.

## Получите всё (постраничность)

Результаты отсортированы от новых к старым и используют курсор-постраничность.

```bash
# одна попытка: получите до 500 строк по 200 строк в странице
agenteye --json events --session-id run-001 --limit 500 --all > events.json

# ручная постраничность: передайте next_cursor обратно
page=$(agenteye --json events --limit 100)
cursor=$(echo "$page" | jq -r '.next_cursor // empty')
[ -n "$cursor" ] && agenteye --json events --limit 100 --cursor "$cursor"
```

## Уменьшите выход с помощью --fields

Ограничьте ключи (как в таблице, так и в `--json`), чтобы снизить объём данных, который должен прочитать агент.

```bash
agenteye --json sessions --since 7d --fields session_id,status,scores | jq -c '.sessions[]'
agenteye --json events --session-id run-001 --fields ts,event_type --all
```

Неизвестные имена полей отклоняются (выход `2`) со списком допустимых, дешёвый способ обнаружить имена полей.

## Обнаружьте допустимые значения фильтров

```bash
agenteye --json list envs | jq -r '.values[]'           # значения для --env
agenteye --json list tools | jq -r '.values[]'          # имена инструментов; также агентов, моделей, event_types, …
agenteye --json list score_filters | jq -r '.values[]'  # допустимый KEY для --score KEY:MIN..MAX
```

## Выберите вашу организацию (мультитенантность)

Если вы принадлежите более чем одной организации, выберите активного клиента при входе (это сохраняется):

```bash
agenteye login --org acme --email you@corp.com   # установите клиента одновременно с входом
agenteye --json orgs list | jq -r '.orgs[].org_slug'
agenteye --org globex --json sessions --since 24h   # переопределить для одной команды
```

Мультиорг-вход без `--org` возвращает ненулевой код и выводит организации для выбора.

## Создайте API-ключ для SDK/collector

```bash
# секрет выводится ОДИН РАЗ, с --json это поле .key
key=$(agenteye --json keys create ci-bot --add events:read.add | jq -r '.key')
agenteye keys regenerate ci-bot --yes    # ротация; agenteye keys disable ci-bot --yes для отзыва
```

## Запустите сохранённый или нерегламентированный запрос

```bash
agenteye --json query run --sql "select count(*) from analytics.events" | jq '.rows'
agenteye --json query run errs --arg prod | jq '.rows'   # сохранённый запрос + позиционный $1
```

## Анализируйте инцидент неинтерактивно

```bash
id=$(agenteye --json incidents list --state firing | jq -r '.incidents[0].id')
agenteye incidents ack "$id"
agenteye incidents assign "$id" --assignee you@corp.com
agenteye incidents resolve "$id" --yes
```

> **Примечание:** Мутации автоматически пропускают подтверждение при `--json` или когда stdin не является TTY, поэтому агенты никогда не зависают; передайте `--yes`/`-y`, чтобы пропустить явно в других местах.

## Обработка кода выхода в скрипте

```bash
out=$(agenteye --json sessions --since 1h) || code=$?
case "${code:-0}" in
  0) echo "$out" | jq '.sessions | length' ;;
  4) echo "Session expired - run 'agenteye login'." >&2 ;;
  5) echo "Missing permission (ask an admin for evaluations:read)." >&2 ;;
  3) echo "Dashboard unreachable - check the URL." >&2 ;;
  *) echo "Unexpected error (exit ${code})." >&2 ;;
esac
```

## Формы JSON-вывода

| Команда | stdout JSON (с `--json`) |
|---|---|
| `whoami` | `{"logged_in": true, "id", "email", "is_instance_admin", "active_org", "permissions": [...], "memberships": [...]}` или `{"logged_in": false}` |
| `orgs list` | `{"active_org", "orgs": [{"org_slug","org_name","permission_set","permissions"}]}` |
| `events` | `{"events": [...], "next_cursor": <cursor or null>}` |
| `evals` | `{"evaluations": [...], "next_cursor": <cursor or null>}` |
| `sessions` | `{"sessions": [...], "next_cursor": <cursor or null>}` |
| `errors` | `{"errors": [...], "next_cursor": <cursor or null>}` |
| `list <kind>` | `{"kind", "values": [...]}` |
| `keys list` / `keys create` | `{"keys": [...]}` / `{id, name, permissions, created_at, key}` (`key` показан один раз) |
| `query run` | `{columns: [{name,type}], rows: [[...]], truncated, elapsed_ms}` |
| `users list` / `settings list` | `{"users": [...]}` / `{"settings": [...]}` |
| `alerts list` / `incidents list` | `{"alerts": [...]}` / `{"incidents": [...]}` |
| create/update/delete (любая) | объект ресурса или `{"deleted": true, "id"}` для удалений |
| ошибка (любая, с `--json`) | `{"error": "...", "exit_code": <n>, "status"?: <http>, "hint"?: "..."}` в stdout |

- Каждый элемент **события** (`events`): `id, session_id, agent_id, event_type, ts, payload, environment, summary, is_error, error_type, output_tokens, context_window, context_fill`. Обратите внимание, что `payload` равен `{}`, если вы не запросили полную ленту с `--full` (или `--fields payload`).
- Каждый элемент **оценки** (`evals`): `id, session_id, agent_id, environment, status, scores, reasoning, summary, error, attempt_count, duration_ms, completed_at, created_at`.
- Каждый элемент **сессии** (`sessions`): `session_id, agent_id, environment, status, scores, event_count, started_at, last_event_at, first_event_id, last_event_id, latest_evaluation`.

`--fields` каждой команды принимает ровно имена полей своего собственного элемента. Набор отличается между `sessions` и `evals`, так что имя, допустимое для одного, может быть отклонено другим.
