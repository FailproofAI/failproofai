Извлекайте данные сеансов, событий и оценок (и запускайте переоценки) прямо из скрипта или кодирующего агента, с чистым JSON на stdout, который направляется прямо в `jq`. Эти рецепты превращают данные Failproof AI Observability в то, что может запросить и автоматизировать терминальный пользователь или AI кодирующий агент (Claude Code, Cursor), без необходимости кликать по панели управления.

Паттерны ниже готовы к копированию для CLI Failproof AI Observability (`agenteye`). Подробнее об установке, аутентификации и полном списке опций см. в разделе [CLI](/ru/agenteye/cli); запустите `agenteye -h` или `agenteye <command> -h` для встроенной справки.

## Золотые правила

1. **Глобальные опции идут *перед* командой.** `agenteye --json sessions` правильно; `agenteye sessions --json` неправильно. Глобальные опции: `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, `--no-color`.
2. **Передавайте `--json` каждый раз, когда парсите вывод.** Данные выводятся на **stdout** в формате JSON; статусы и ошибки идут на **stderr**, поэтому stdout остается чистым для передачи в `jq`.
3. **Ветвитесь по коду выхода**, а не по тексту stderr: `0` ок · `1` непредвиденная ошибка · `2` неверные аргументы · `3` невозможно достичь панели управления · `4` не залогирован или сессия истекла · `5` недостаточно прав · `6` ресурс не найден.
4. **Открывайте справку с `-h`.** Каждая команда документирует свои фильтры, форматы значений и форму JSON.

## Одноразовая настройка

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com   # чтобы не повторять --base-url
agenteye login --email you@example.com                       # вставьте код из письма; действителен ~24ч
```

## Проверьте аутентификацию перед работой

`whoami` никогда не выдает ошибку при отсутствии или истечении сеанса; вместо этого возвращает `logged_in:false`, поэтому агент может безопасно проверить состояние аутентификации. (Может все еще завершиться с ненулевым кодом, если не установлен URL базы или панель управления недоступна.)

```bash
if [ "$(agenteye --json whoami | jq -r .logged_in)" != "true" ]; then
  echo "Not authenticated. Run: agenteye login" >&2; exit 1
fi
```

## Найдите неудачные или низкооценённые сеансы

```bash
# сеансы за последние 24ч с ошибкой оценки
agenteye --json sessions --since 24h --status error | jq -r '.sessions[].session_id'

# оценки с баллом <= 0.5 по полезности для одного агента
agenteye --json evals --agent-id checkout-bot --score helpfulness:..0.5 \
  | jq '.evaluations[] | {session_id, scores}'
```

Фильтрация по баллам находится в **`evals`**, а не в `sessions`. `--score KEY:MIN..MAX` повторяется и комбинируется через AND; любая граница опциональна (`..0.5` означает ≤ 0.5, `0.9..` означает ≥ 0.9). Вы можете передать до 20 фильтров по баллам за запрос; больше возвращает HTTP 400. `sessions` имеет те же фильтры `--env`, `--status`, `--agent-id`, `--session-id` и диапазон времени, что и `evals`, но не имеет `--score`.

## Прочитайте один сеанс от начала до конца

Единой команды `session show` нет. Совместите цепочку событий с оценкой сеанса:

```bash
# последняя оценка сеанса (статус + баллы)
agenteye --json evals --session-id run-001 | jq '.evaluations[0] | {status, scores}'

# каждое событие в запуске (увеличьте --limit для полного сканирования)
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'

# только вызовы инструментов в сеансе (--full требуется для получения необработанной полезной нагрузки)
agenteye --json events --full --session-id run-001 --event-type tool_use,tool_result --all \
  | jq '.events[].payload'
```

> **Примечание:** По умолчанию `events` читает быстрый канал без полезной нагрузки. Каждое событие содержит вычисленное сервером однострочное поле `summary` плюс флаги вроде `is_error` и счетчики токенов, но `payload` возвращается как `{}`. Чтобы получить необработанную полезную нагрузку, добавьте `--full` (или `--fields payload`). Полный канал медленнее в масштабе, поэтому ограничивайте его: используйте `--full` с одним `--session-id`.

## Получите все (пагинация)

Результаты отсортированы новые-сначала и используют курсорную пагинацию.

```bash
# одновременно: получите до 500 строк по 200 строк за раз
agenteye --json events --session-id run-001 --limit 500 --all > events.json

# ручная пагинация: передайте next_cursor обратно
page=$(agenteye --json events --limit 100)
cursor=$(echo "$page" | jq -r '.next_cursor // empty')
[ -n "$cursor" ] && agenteye --json events --limit 100 --cursor "$cursor"
```

## Уменьшите вывод с помощью --fields

Ограничьте ключи (как в таблице, так и в `--json`) чтобы агенту было меньше читать.

```bash
agenteye --json sessions --since 7d --fields session_id,status,scores | jq -c '.sessions[]'
agenteye --json events --session-id run-001 --fields ts,event_type --all
```

Неизвестные имена полей отклоняются (выход `2`) с выводом допустимого списка - дешевый способ открыть имена полей.

## Откройте допустимые значения фильтров

```bash
agenteye --json list envs | jq -r '.values[]'           # значения для --env
agenteye --json list tools | jq -r '.values[]'          # имена инструментов; также agents, models, event_types, …
agenteye --json list score_filters | jq -r '.values[]'  # допустимый KEY для --score KEY:MIN..MAX
```

## Выберите вашу организацию (мультитенантность)

Если вы принадлежите более чем одной организации, выберите активного клиента при входе (сохраняется):

```bash
agenteye login --org acme --email you@corp.com   # установите клиента в одном шаге с входом
agenteye --json orgs list | jq -r '.orgs[].org_slug'
agenteye --org globex --json sessions --since 24h   # переопределите для одной команды
```

Вход в мультиорганизацию без `--org` завершается ненулевым кодом и выводит организации на выбор.

## Подготовьте ключ API для SDK/коллектора

```bash
# секрет выводится ОДИН РАЗ, с --json это поле .key
key=$(agenteye --json keys create ci-bot --add events:read.add | jq -r '.key')
agenteye keys regenerate ci-bot --yes    # ротация; agenteye keys disable ci-bot --yes для отзыва
```

## Запустите сохраненный или ad-hoc запрос

```bash
agenteye --json query run --sql "select count(*) from analytics.events" | jq '.rows'
agenteye --json query run errs --arg prod | jq '.rows'   # сохраненный запрос + позиционный $1
```

## Тriage инцидента неинтерактивно

```bash
id=$(agenteye --json incidents list --state firing | jq -r '.incidents[0].id')
agenteye incidents ack "$id"
agenteye incidents assign "$id" --assignee you@corp.com
agenteye incidents resolve "$id" --yes
```

> **Примечание:** Мутации автоматически пропускают запрос подтверждения под `--json` или когда stdin не является TTY, поэтому агенты никогда не зависают; передайте `--yes`/`-y` чтобы пропустить его явно в других местах.

## Обработка кода выхода в скрипте

```bash
out=$(agenteye --json sessions --since 1h) || code=$?
case "${code:-0}" in
  0) echo "$out" | jq '.sessions | length' ;;
  4) echo "Session expired - run 'agenteye login'." >&2 ;;
  5) echo "Missing permission (ask an admin for evaluations:read)." >&2 ;;
  3) echo "Dashboard unreachable - check the URL." >&2 ;;
  *) echo "Unexpected error (exit ${code})." >&2 ;;
esac
```

## Формы JSON вывода

| Команда | JSON на stdout (с `--json`) |
|---|---|
| `whoami` | `{"logged_in": true, "id", "email", "is_instance_admin", "active_org", "permissions": [...], "memberships": [...]}` или `{"logged_in": false}` |
| `orgs list` | `{"active_org", "orgs": [{"org_slug","org_name","permission_set","permissions"}]}` |
| `events` | `{"events": [...], "next_cursor": <cursor or null>}` |
| `evals` | `{"evaluations": [...], "next_cursor": <cursor or null>}` |
| `sessions` | `{"sessions": [...], "next_cursor": <cursor or null>}` |
| `errors` | `{"errors": [...], "next_cursor": <cursor or null>}` |
| `list <kind>` | `{"kind", "values": [...]}` |
| `keys list` / `keys create` | `{"keys": [...]}` / `{id, name, permissions, created_at, key}` (`key` показан один раз) |
| `query run` | `{columns: [{name,type}], rows: [[...]], truncated, elapsed_ms}` |
| `users list` / `settings list` | `{"users": [...]}` / `{"settings": [...]}` |
| `alerts list` / `incidents list` | `{"alerts": [...]}` / `{"incidents": [...]}` |
| create/update/delete (любой) | объект ресурса или `{"deleted": true, "id"}` для удалений |
| failure (любой, с `--json`) | `{"error": "...", "exit_code": <n>, "status"?: <http>, "hint"?: "..."}` на stdout |

- Каждый элемент **event** (`events`): `id, session_id, agent_id, event_type, ts, payload, environment, summary, is_error, error_type, output_tokens, context_window, context_fill`. Обратите внимание, что `payload` равен `{}` если вы не запросили полный канал с `--full` (или `--fields payload`).
- Каждый элемент **evaluation** (`evals`): `id, session_id, agent_id, environment, status, scores, reasoning, summary, error, attempt_count, duration_ms, completed_at, created_at`.
- Каждый элемент **session** (`sessions`): `session_id, agent_id, environment, status, scores, event_count, started_at, last_event_at, first_event_id, last_event_id, latest_evaluation`.

`--fields` каждой команды принимает ровно имена полей своего собственного элемента. Набор различается между `sessions` и `evals`, поэтому имя, допустимое для одного, может быть отклонено другим.
