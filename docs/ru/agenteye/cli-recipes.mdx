Извлекайте данные сессий, событий и оценок (и запускайте переоценку) прямо из скрипта или агента-кодировщика с чистым JSON на стандартном выводе, который можно передать прямо в `jq`. Эти рецепты превращают данные Failproof AI Observability в то, что может запросить и автоматизировать пользователь терминала или AI-агент (Claude Code, Cursor), без кликов по дашборду.

Приведённые ниже шаблоны готовы к копированию-вставке в CLI Failproof AI Observability (`agenteye`). Информацию об установке, аутентификации и полном списке опций см. в разделе [CLI](/ru/agenteye/cli); используйте `agenteye -h` или `agenteye <command> -h` для встроенной справки.

## Золотые правила

1. **Глобальные опции идут *перед* командой.** `agenteye --json sessions` — правильно; `agenteye sessions --json` — нет. Глобальные опции: `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, `--no-color`.
2. **Передавайте `--json` при обработке вывода.** Данные выводятся на **stdout** в JSON; статус и ошибки идут на **stderr**, так что stdout остаётся чистым для передачи в `jq`.
3. **Ветвитесь по коду выхода, не по тексту stderr**: `0` успех · `1` непредвиденная ошибка · `2` неверные аргументы · `3` дашборд недоступен · `4` не авторизован или сессия истекла · `5` недостаточно прав · `6` ресурс не найден.
4. **Ищите информацию с `-h`.** Каждая команда документирует свои фильтры, форматы значений и форму JSON.

## Первоначальная настройка

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com   # чтобы не повторять --base-url
agenteye login --email you@example.com                       # вставьте отправленный код; действителен ~24ч
```

## Проверьте аутентификацию перед работой

`whoami` никогда не выдаёт ошибку при отсутствии или истечении сессии; вместо этого выводит `logged_in:false`, так что агент может безопасно проверить статус аутентификации. (Может всё ещё завершиться ненулевым кодом, если не установлен базовый URL или дашборд недоступен.)

```bash
if [ "$(agenteye --json whoami | jq -r .logged_in)" != "true" ]; then
  echo "Not authenticated. Run: agenteye login" >&2; exit 1
fi
```

## Найдите сессии с ошибками или низкими оценками

```bash
# сессии за последние 24ч, у которых оценка ошибилась
agenteye --json sessions --since 24h --status error | jq -r '.sessions[].session_id'

# оценки со сметкой ≤ 0.5 по helpfulness для одного агента
agenteye --json evals --agent-id checkout-bot --score helpfulness:..0.5 \
  | jq '.evaluations[] | {session_id, scores}'
```

Фильтрация по оценкам находится в **`evals`**, а не в `sessions`. `--score KEY:MIN..MAX` повторяется и комбинируется через AND; оба граница не обязательны (`..0.5` означает ≤ 0.5, `0.9..` означает ≥ 0.9). За запрос можно передать до 20 фильтров по оценкам; больше вернёт HTTP 400. `sessions` разделяет фильтры `--env`, `--status`, `--agent-id`, `--session-id` и диапазоны времени с `evals`, но не имеет `--score`.

## Прочитайте одну сессию от начала до конца

Единой команды `session show` нет. Комбинируйте цепочку событий с оценкой сессии:

```bash
# последняя оценка сессии (статус + баллы)
agenteye --json evals --session-id run-001 | jq '.evaluations[0] | {status, scores}'

# каждое событие в прогоне (увеличьте --limit для полного сканирования)
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'

# только вызовы инструментов в сессии (--full требуется для получения исходных данных)
agenteye --json events --full --session-id run-001 --event-type tool_use,tool_result --all \
  | jq '.events[].payload'
```

> **Примечание:** По умолчанию `events` читает быстрый поток без payload. Каждое событие содержит вычисленный сервером однострочный `summary` плюс флаги типа `is_error` и подсчёты токенов, но `payload` возвращается как `{}`. Чтобы получить исходные данные, добавьте `--full` (или `--fields payload`). Полный поток медленнее в масштабе, так что ограничьте его: комбинируйте `--full` с одним `--session-id`.

## Получите всё (постраничный просмотр)

Результаты отсортированы по новизне и используют курсор-пагинацию.

```bash
# одним выстрелом: получите до 500 рядов в страницах по 200 рядов
agenteye --json events --session-id run-001 --limit 500 --all > events.json

# ручной просмотр: передайте next_cursor назад
page=$(agenteye --json events --limit 100)
cursor=$(echo "$page" | jq -r '.next_cursor // empty')
[ -n "$cursor" ] && agenteye --json events --limit 100 --cursor "$cursor"
```

## Сократите вывод с --fields

Ограничьте ключи (и в таблице, и в `--json`) чтобы уменьшить то, что должен прочитать агент.

```bash
agenteye --json sessions --since 7d --fields session_id,status,scores | jq -c '.sessions[]'
agenteye --json events --session-id run-001 --fields ts,event_type --all
```

Неизвестные имена полей отклоняются (выход `2`) со списком допустимых — дешёвый способ обнаружить имена полей.

## Обнаружьте допустимые значения фильтров

```bash
agenteye --json list envs | jq -r '.values[]'           # значения для --env
agenteye --json list tools | jq -r '.values[]'          # имена инструментов; также agents, models, event_types, …
agenteye --json list score_filters | jq -r '.values[]'  # допустимый KEY для --score KEY:MIN..MAX
```

## Выберите вашу организацию (мультитенант)

Если вы принадлежите более чем одной организации, выберите активный тенант при входе (он сохраняется):

```bash
agenteye login --org acme --email you@corp.com   # установите тенант на том же шаге, что и вход
agenteye --json orgs list | jq -r '.orgs[].org_slug'
agenteye --org globex --json sessions --since 24h   # переопределите для одной команды
```

Вход в мультиорганизацию без `--org` завершается ненулевым кодом и выводит организации для выбора.

## Выпустите ключ API для SDK/сборщика

```bash
# секрет выводится ОДИН РАЗ, с --json это поле .key
key=$(agenteye --json keys create ci-bot --add events:read.add | jq -r '.key')
agenteye keys regenerate ci-bot --yes    # ротация; agenteye keys disable ci-bot --yes для отзыва
```

## Запустите сохранённый или ad-hoc запрос

```bash
agenteye --json query run --sql "select count(*) from analytics.events" | jq '.rows'
agenteye --json query run errs --arg prod | jq '.rows'   # сохранённый запрос + позиционный $1
```

## Сортируйте инцидент неинтерактивно

```bash
id=$(agenteye --json incidents list --state firing | jq -r '.incidents[0].id')
agenteye incidents ack "$id"
agenteye incidents assign "$id" --assignee you@corp.com
agenteye incidents resolve "$id" --yes
```

> **Примечание:** Мутации автоматически пропускают приглашение подтверждения при `--json` или когда stdin не является TTY, так что агенты никогда не зависают; передайте `--yes`/`-y` чтобы пропустить его явно в другом месте.

## Обработка кодов выхода в скрипте

```bash
out=$(agenteye --json sessions --since 1h) || code=$?
case "${code:-0}" in
  0) echo "$out" | jq '.sessions | length' ;;
  4) echo "Session expired - run 'agenteye login'." >&2 ;;
  5) echo "Missing permission (ask an admin for evaluations:read)." >&2 ;;
  3) echo "Dashboard unreachable - check the URL." >&2 ;;
  *) echo "Unexpected error (exit ${code})." >&2 ;;
esac
```

## Формы вывода JSON

| Команда | stdout JSON (с `--json`) |
|---|---|
| `whoami` | `{"logged_in": true, "id", "email", "is_instance_admin", "active_org", "permissions": [...], "memberships": [...]}` или `{"logged_in": false}` |
| `orgs list` | `{"active_org", "orgs": [{"org_slug","org_name","permission_set","permissions"}]}` |
| `events` | `{"events": [...], "next_cursor": <cursor or null>}` |
| `evals` | `{"evaluations": [...], "next_cursor": <cursor or null>}` |
| `sessions` | `{"sessions": [...], "next_cursor": <cursor or null>}` |
| `errors` | `{"errors": [...], "next_cursor": <cursor or null>}` |
| `list <kind>` | `{"kind", "values": [...]}` |
| `keys list` / `keys create` | `{"keys": [...]}` / `{id, name, permissions, created_at, key}` (`key` показан один раз) |
| `query run` | `{columns: [{name,type}], rows: [[...]], truncated, elapsed_ms}` |
| `users list` / `settings list` | `{"users": [...]}` / `{"settings": [...]}` |
| `alerts list` / `incidents list` | `{"alerts": [...]}` / `{"incidents": [...]}` |
| create/update/delete (любое) | объект ресурса, или `{"deleted": true, "id"}` для удалений |
| ошибка (любое, с `--json`) | `{"error": "...", "exit_code": <n>, "status"?: <http>, "hint"?: "..."}` на stdout |

- Каждый элемент **события** (`events`): `id, session_id, agent_id, event_type, ts, payload, environment, summary, is_error, error_type, output_tokens, context_window, context_fill`. Обратите внимание, что `payload` является `{}` если вы не запросили полный поток с `--full` (или `--fields payload`).
- Каждый элемент **оценки** (`evals`): `id, session_id, agent_id, environment, status, scores, reasoning, summary, error, attempt_count, duration_ms, completed_at, created_at`.
- Каждый элемент **сессии** (`sessions`): `session_id, agent_id, environment, status, scores, event_count, started_at, last_event_at, first_event_id, last_event_id, latest_evaluation`.

`--fields` каждой команды принимает ровно имена полей её собственного элемента. Набор отличается между `sessions` и `evals`, так что имя, допустимое для одного, может быть отклонено другим.
