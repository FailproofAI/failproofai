Управляйте всеми аспектами Failproof AI Observability с терминала или скрипта: без необходимости заходить на панель управления. CLI `agenteye` позволяет запрашивать ваши данные (сессии, логи событий, оценки) и администрировать организацию (API-ключи, пользователи, параметры, оповещения, инциденты, сохранённые запросы), так что используйте его, когда нужно автоматизировать проверку, интегрировать Observability в CI или дать агенту доступ к инспекции production. Каждая команда поддерживает флаг `--json`, поэтому он работает одинаково хорошо как для вас в терминале, так и для агента кодирования (Claude Code, Cursor), который выполняет команду и парсит результат.

С помощью одного бинарного файла вы можете:

- **Читать ваши данные**: `sessions`, `events`, `evals`, `errors` (фильтровать по времени, агенту, окружению, оценке).
- **Управлять организацией**: `keys`, `users`, `settings`, `alerts`, `incidents`.
- **Запускать аналитику**: сохранённый SQL и runner для ad-hoc запросов (`query`).
- **Общаться с AI-ассистентом**: тот же аналитик, доступный только для чтения, с которым вы общаетесь на панели управления (`agent`).

> **Примечание:** Это CLI `agenteye`, отличный инструмент от демона-сборщика (`agenteye-collector`). CLI взаимодействует с вашей панелью управления; сборщик отправляет события на сервер.

## Быстрый старт

От нуля до первого результата за четыре строки. Укажите CLI адрес панели управления, войдите, подтвердите вашу личность, затем получите последний день запусков:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # отправлено 6-значный код
agenteye whoami                                                                  # подтвердите пользователя + активную org
agenteye --json sessions --since 24h                                             # одна строка на каждый запуск агента, последние 24ч
```

Последняя команда выводит объект JSON с самыми свежими сессиями (новые в начале, по умолчанию до 50). Пропустьте результат в `jq` для выборки, или опустите `--json`, чтобы получить красиво оформленную и раскрашенную таблицу. Каждая строка содержит статус запуска и, если оценщик его оценил, его метрики (сокращены здесь):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

В дальнейшем на этой странице объясняется каждая часть: [установка](#installation) отдельно, [вход](#authentication), [конфигурация](#configuration), [глобальные соглашения](#global-options--conventions), которые разделяют все команды, и [полный справочник команд](#command-reference).

## Установка

CLI — это публичный пакет PyPI с именем **`agenteye`**. Установите его в изолированной среде, чтобы он всегда имел свои собственные зависимости:

```bash
pipx install agenteye
# или
uv tool install agenteye
```

Требуется Python 3.10+. Установленная команда — **`agenteye`**:

```bash
agenteye --version
agenteye --help
```

> **Примечание:** Python SDK Failproof AI Observability также использует имя распределения `agenteye`. Установка CLI с помощью `pipx` или `uv tool` (вместо `pip install` в общую virtualenv) предотвращает их конфликт. Простой `pip install agenteye` допустим только если SDK не установлен в той же среде.

## Аутентификация

CLI аутентифицируется на **панели управления** с помощью одноразового кода, отправленного по электронной почте:

```bash
agenteye login --email you@example.com
# 6-значный код отправляется вам; вставьте его в запрос.
```

Маркер сессии хранится в `~/.agenteye/cli.json` (читаемый только вами, режим `0600`) и по умолчанию действителен 24 часа. Когда он истечёт, выполните `agenteye login` снова.

```bash
agenteye whoami     # показать текущего пользователя, активную org и разрешения
agenteye logout     # отозвать сессию и очистить сохранённый маркер
```

`whoami` никогда не выдаёт ошибку при отсутствующей или истекшей сессии; вместо этого выдаёт `logged_in: false`, так что скрипт или агент могут безопасно проверить статус аутентификации (всё ещё может выйти с ненулевым кодом, если не установлен базовый URL или панель управления недостижима).

**Требования:** ваша электронная почта должна быть разрешена для входа на панель управления (попросите администратора Failproof AI Observability), и панель управления должна быть доступна по своему базовому URL (см. [Конфигурация](#configuration)). Если вы запросили код и он не пришёл, ваша электронная почта, вероятно, ещё не активирована для доступа к панели управления.

## Выбор вашей организации (мультитенантность)

Если ваша учётная запись принадлежит более чем одной org, выберите активную **при входе**; она сохраняется и используется для каждой последующей команды:

```bash
agenteye login --org acme           # аутентифицируйтесь и установите активного тенанта в один шаг
agenteye orgs list                  # org-и, к которым вы можете получить доступ (активная отмечена)
agenteye orgs switch globex         # измените сохранённое значение по умолчанию
agenteye --org globex sessions      # переопределить для одной команды
```

Если вы принадлежите ровно одной org, она выбирается автоматически и вы можете полностью игнорировать `--org`. Если вы принадлежите нескольким и не выбрали одну, CLI выведет список и попросит вас повторно выполнить с `--org <slug>`. Активная org отправляется на панель управления при каждом запросе, и ваши разрешения разрешаются **для каждой org**; `agenteye whoami` показывает активную org, ваши разрешения в ней и все ваши членства.

## Конфигурация

| Параметр | Флаг | Переменная окружения | По умолчанию |
|---|---|---|---|
| Базовый URL панели управления | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **требуется** (нет значения по умолчанию) |
| Активная org/тенант | `--org` | `AGENTEYE_ORG` | выбирается при входе; сохраняется в `~/.agenteye/cli.json` |
| Маркер сессии | `--token` | `AGENTEYE_CLI_TOKEN` | из `~/.agenteye/cli.json` |
| Вывод JSON | `--json` | `AGENTEYE_CLI_JSON` | отключено |
| Пропустить проверку TLS | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | отключено (сохраняется при входе) |
| Timeout запроса (секунды) | `--timeout` | _(нет)_ | 30 |
| Отключить телеметрию использования | _(нет)_ | `AGENTEYE_ANALYTICS_DISABLED` (или `DO_NOT_TRACK`) | телеметрия в настоящее время отключена; ничего не отправляется |

Порядок разрешения: **флаг → переменная окружения → файл конфигурации**. Нет значения по умолчанию; вы должны указать CLI адрес вашей панели управления, либо для каждой команды (`--base-url https://agenteye.example.com`), либо один раз через окружение (это также сохраняется после вашего первого `login`):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

Директория конфигурации соблюдает `AGENTEYE_HOME` (то же соглашение, используемое SDK и сборщиком); если установлено, `cli.json` находится в `$AGENTEYE_HOME/cli.json`.

### Самоподписанный или внутренний TLS

Если ваша панель управления обслуживается через HTTPS с самоподписанным или внутренним сертификатом (например, сырый хостнейм load-balancer'а), проверка TLS отклонит его с ошибкой `CERTIFICATE_VERIFY_FAILED`. Передайте `--insecure` для пропуска проверки сертификата:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` **сохраняется в `cli.json` при входе**, поэтому позднейшие команды пропускают проверку автоматически; вам не нужно повторять флаг. Передайте `--secure` для единовременного проверенного вызова или чтобы вернуть проверку при следующем входе. CLI выводит предупреждение на stderr перед любой командой, которая контактирует с панелью управления с отключённой проверкой. Пропуск проверки снимает защиту от атак man-in-the-middle; убедитесь, что вы доверяете пути сети к вашей панели управления (VPN, приватная подсеть и т. д.) перед тем, как полагаться на это.

## Телеметрия и конфиденциальность

> **Примечание:** Поставленный CLI **не отправляет сегодня никаких данных телеметрии.** Главный выключатель включен, поэтому ничего не передаётся независимо от вашего окружения. Раздел ниже описывает возможность отказа на случай, если телеметрия когда-либо будет включена.

Даже если включена, телеметрия будет **только анонимной аналитикой использования**, никогда вашим агентом, сессией или данными событий:

- **Никакие данные агента, сессии или события никогда не покидают вашу инфраструктуру.** Только использование CLI будет отправляться: имя команды и подкоманды (например, `keys create`), **имена** используемых флагов (никогда их значения), статус успеха/выхода и длительность, плюс per-action событие для мутаций (например, `api_key_created`, `query_run`), несущее только статические имена/enums и приблизительные количества. Ваш URL панели управления, маркер сессии, электронная почта, slug org, id ресурсов, SQL, секреты ключей и фильтры запросов **никогда** не будут отправлены. Операторы будут идентифицированы только непрозрачным внутренним id, никогда по электронной почте.
- **Отказаться заранее** установив `AGENTEYE_ANALYTICS_DISABLED=1` в окружении CLI (CLI также соблюдает кросс-инструментальное соглашение `DO_NOT_TRACK=1`). Это вступает в силу в момент, когда телеметрия когда-либо включается, поэтому ориентированное на конфиденциальность окружение может остаться отказавшимся навсегда.
- Если телеметрия была включена, CLI отправит напрямую PostHog (`https://us.i.posthog.com`); машина с заблокированным хостом молча ничего не отправит и CLI останется незатронут.

## Глобальные опции и соглашения

Прочитайте это один раз; это применяется к каждой команде.

- **Глобальные опции идут ДО команды.** `agenteye --json sessions` правильно; `agenteye sessions --json` — ошибка использования. Глобальные: `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet` и `--no-color`.
- **`--json` выводит чистый JSON на stdout и больше ничего.** Статусные строки для человека, предупреждения и ошибки идут на **stderr**, поэтому захват stdout с `--json` остаётся чистым для пайпинга в `jq` даже когда показана статусная строка. Без `--json` вы получаете красиво оформленное и раскрашенное представление для человеческого взгляда.
- **Исследуйте с помощью `--help`.** Каждая команда и подкоманда имеет `--help` (и алиас `-h`): `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`. Справка верхнего уровня также перечисляет коды выхода и глобальные опции. Нет глобального machine-readable поверхностного дампа; используйте per-command `--help`, плюс domain-specific `agenteye query schema` и `agenteye settings schema` для этих двух реестров.
- **Подтверждения автоматически пропускаются для скриптов и агентов.** Команды создания/обновления/удаления запрашивают «вы уверены?» в интерактивном терминале, но **автоматически пропускают этот запрос под `--json` или всякий раз, когда stdin не является TTY** (TTY — это интерактивный сеанс терминала; pipe или CI runner не является), поэтому скрипты и агенты никогда не зависают. Передайте `--yes`/`-y` для явного пропуска. Потому что запрос не сработает для агента, агент должен подтвердить деструктивные действия с человеком сначала.
- **Пагинация:** результаты новые-в-начале и cursor-paginated (каждая страница возвращает токен, который вы используете для выборки следующей). `--limit N` (алиас `-n`) ограничивает строки и **по умолчанию 50**; `--all` автоматически пагинирует (в чанки по 200 строк) **вплоть до `--limit`**, поэтому голый `--all` всё равно останавливается на 50. Для полного сканирования передайте высокую явную границу: `--all --limit 1000`. `--page-size N` управляет per-request чанком (макс 200); `--cursor <id>` возобновляет с предыдущей страницы `next_cursor`.
- **Фильтры по времени:** `--since` принимает относительное окно: `15m`, `1h`, `6h`, `24h`, `7d` или `all` (предустановки панели управления). Для более длинного или пользовательского диапазона (скажем, последние 30 дней) используйте `--from`/`--to`: явные ISO-8601 UTC временные метки **с `T` и временной зоной** (например, `2026-06-01T00:00:00Z`), которые переопределяют `--since`. Разделённое пробелом или значение без временной зоны — это ошибка использования.
- **`--fields a,b,c`** (на `events`, `sessions`, `evals`, `errors`) ограничивает выводу этими ключами, для таблицы и `--json`. Неизвестные имена отклоняются с допустимым списком, дешёвый способ открыть имена полей.
- **`--file payload.json`** (или `--file -` для чтения stdin) предоставляет полное тело JSON запроса где ресурс имеет сложную форму (на `alerts create/update`, `settings set` и `users create/update`). Сохранённый SQL запроса использует `--sql @file.sql` вместо этого.
- **Фильтры с несколькими значениями** разделены запятыми → сопоставлены как набор (объединение внутри одного фильтра, AND через фильтры): `--event-type tool_use,tool_result`. Опции Click не являются вариативными, поэтому `--add a b` ломается. Используйте `--add a,b`, повторите флаг (`--add a --add b`) или заключите в кавычки (`--add "a b"`).

## Справочник команд

### Эти 5 команд вы будете использовать чаще всего

Большая часть повседневной работы выполняется через горсть команд чтения. Начните здесь, затем обращайтесь к полной поверхности ниже когда вам это нужно:

| Команда | Что она делает | Попробуйте |
|---|---|---|
| `sessions` | Одна строка на запуск агента: время, окружение, агент, статус, последняя оценка. | `agenteye --json sessions --since 24h --status error` |
| `events` | Сырой per-step путь внутри запуска (добавьте `--full` для payloads). | `agenteye --json events --session-id run-001 --all` |
| `evals` | Результаты оценок и оценки; `--aggregate` их сворачивает. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | Только errored события; `--aggregate` для подсчётов по типу. | `agenteye --json errors --since 24h --aggregate` |
| `list` | Откройте допустимые значения фильтров (агенты, окружения, модели, …). | `agenteye list agents` |

### Всё, что может делать CLI

Полная поверхность следует. CLI имеет **18 команд верхнего уровня**. Все команды чтения принимают `--json` и глобальные опции выше; выполните `agenteye <command> -h` (или `<command> <subcommand> -h`) для полного списка флагов и JSON формы любой одной.

### Идентичность: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # отправлено одноразовый код; сохраняет сессию
agenteye logout                                       # очистить сохранённую сессию на этой машине
agenteye whoami                                       # текущий пользователь, активная org, разрешения
agenteye version                                      # выводит версию CLI (то же самое что --version)
agenteye help                                         # справка верхнего уровня (то же самое что --help)
```

`orgs` инспектирует и переключает активного тенанта:

```bash
agenteye orgs list        # ваши org-и + ваша роль в каждой (активная отмечена)
agenteye orgs switch acme # измените сохранённую активную org (опустите slug для выбора из списка на TTY)
agenteye orgs current     # карточка идентичности для активной org
agenteye orgs perms       # ваши разрешения в активной org, сгруппированы по ресурсу
```

### Наблюдать (только чтение): `events` · `sessions` · `evals` · `errors` · `list`

Ни один из них не требует подтверждения. Общие фильтры: `--session-id`, `--agent-id`, `--env` (**не** `--environment`), и диапазон времени (`--since` / `--from` / `--to`).

```bash
# events (алиас: сырой per-step путь), новые в начале
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: одна строка на запуск агента (время/окружение/агент/сессия/статус; без фильтрации оценок)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: результаты оценок + оценки; --score фильтрует по метрике, --aggregate сворачивает
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # микс статусов + per-key статистика оценок

# errors: errored события; --aggregate для подсчётов/сессий/агентов/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: откройте допустимые значения фильтров перед фильтрацией
agenteye list envs        # также: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (на **`evals`**, не `sessions`) повторяется и AND-combined; любая граница опциональна (`..0.5` означает ≤ 0.5, `0.9..` означает ≥ 0.9). До 20 фильтров оценок на запрос. `evals --scores-full` — это флаг отображения для **таблицы только для человека**; он показывает каждую пару оценок вместо первых нескольких плюс количество `+N`. Это не влияет на `--json`, который всегда возвращает полный объект оценок. Чтобы прочитать **одну сессию от начала до конца**, объедините путь события с его оценкой:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # её оценки + статус
```

### Управлять (protected разрешениями): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: API ключи. Секрет генерируется локально, отправляется на сервер (который хранит только хеш) и **показывается один раз** при создании/регенерации; захватите его тогда. С `--json` он появляется только в поле `key`. На них ссылаются по **имени**.

```bash
agenteye keys list                                   # активные ключи в начале, затем отозванные
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # ограничьте тем, что нужно; выводит секрет ОДИН РАЗ
agenteye keys create ops --permission-set standard --remove queries:run   # посыпьте предустановкой, затем обрежьте
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # ротируйте секрет (старый перестаёт работать)
agenteye keys disable ci-bot --yes                   # отозвать
```

Разрешения работают как `(permission-set ∪ --add) − --remove`. Токены — это `slug:action` (например, `events:read`) или `slug:action.action` для расширения нескольких на одном ресурсе (`events:read.add` → `events:read`, `events:add`). Предустановки: `read-only`, `standard`, `admin`. Разрешения только для человека (`keys:update`) не могут быть выданы ключу.

**`users`**: члены org, на них ссылаются по **электронной почте** (также принимается UUID id).

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # предсказывает + подтверждает
agenteye users disable dev@corp.com --yes            # имеет protected/self охранники
agenteye users enable dev@corp.com
```

**`settings`**: фиксированный реестр (вы читаете и изменяете существующие ключи; вы не можете создавать новые).

```bash
agenteye settings list                               # ключ · значение · тип · updated (секреты замаскированы)
agenteye settings schema                             # что каждый ключ принимает (тип · диапазон · описание)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: определения оповещений, на них ссылаются по **имени**. `create` принимает позиционное NAME плюс флаги или полное тело JSON через `--file`.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME обязателен (позиционный)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # запустить тестовое уведомление
agenteye alerts delete high-errors --yes
```

**`incidents`**: alert инциденты, на них ссылаются по id (короткие id приемлемы). `show` выводит полный логи деятельности; прочитайте перед действием.

```bash
agenteye incidents list --state firing                # также: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # ответственный должен быть оператором
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # открыть одного вручную против оповещения
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### Аналитика и ассистент: `query` · `agent`

**`query`**: сохранённый SQL против вашего хранилища аналитики плюс ad-hoc runner. Сохранённые запросы на них ссылаются по **имени**; SQL проверяется на сервере (только SELECT/WITH, statement timeout, row cap).

```bash
agenteye query schema [TABLE]                         # layout столбцов аналитических представлений
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # запустить сохранённый запрос + позиционный $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: общается с встроенным **AI ассистентом** (то же самое аналитик только для чтения, с которым вы можете общаться на панели управления). Чаты на них ссылаются по short chat-id (prefix-resolved).

```bash
agenteye agent health                                 # настроен ли и достижим ли AI ассистент
agenteye agent models                                 # модели, которые вы можете передать в --model (default отмечена)
agenteye agent ask "which agents errored most in the last day?"    # начать чат; выводит его short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # продолжить этот чат
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

---

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Успех |
| 1 | Неожиданная ошибка (например, панель управления вернула 5xx) |
| 2 | Ошибка использования (неверные аргументы, неизвестная команда/флаг, конфликт имён) |
| 3 | Не может достичь панель управления |
| 4 | Не вошли или сессия истекла; выполните `agenteye login` |
| 5 | Аутентифицированы, но ваша учётная запись не имеет требуемого разрешения (сообщение его называет) |
| 6 | Запрошенный ресурс не найден (например, неизвестный session или incident id) |

Это делает CLI безопасным для скрипфинга: агент кодирования может ветвиться на `4` чтобы запросить у вас повторную аутентификацию, или на `5` чтобы поверхностное отсутствующее разрешение. См. [CLI рецепты для агентов](/ru/agenteye/cli-recipes) для обработки exit-code паттернов и JSON вывода форм.
