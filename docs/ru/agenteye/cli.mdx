Управляйте всей наблюдаемостью Failproof AI из терминала или скрипта: без необходимости обращаться к панели управления. CLI `agenteye` запрашивает ваши данные (сеансы, журналы событий, оценки) и администрирует вашу организацию (API ключи, пользователи, параметры, оповещения, инциденты, сохранённые запросы), поэтому используйте его для автоматизации проверок, интеграции наблюдаемости в CI или для того, чтобы кодирующий агент мог инспектировать production. Каждая команда поддерживает флаг `--json`, поэтому работает одинаково хорошо как для вас в терминале, так и для кодирующего агента (Claude Code, Cursor), который вызывает команду и парсит результат.

С одним бинарным файлом вы можете:

- **Читать ваши данные**: `sessions`, `events`, `evals`, `errors` (фильтр по времени, агенту, среде, оценке).
- **Управлять организацией**: `keys`, `users`, `settings`, `alerts`, `incidents`.
- **Запускать аналитику**: сохранённый SQL и интерпретатор ad-hoc запросов (`query`).
- **Обращаться к AI ассистенту**: того же read-only аналитика, с которым вы общаетесь в панели управления (`agent`).

> **Примечание:** Это CLI `agenteye`, отличный от демона-сборщика (`agenteye-collector`). CLI обращается к вашей панели управления; сборщик отправляет события на сервер.

## Быстрый старт

От нуля до первого результата за четыре строки. Укажите CLI адрес вашей панели управления, выполните вход, подтвердите вашу личность, затем получите последний день запусков:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # отправлен 6-значный код
agenteye whoami                                                                  # подтверждение пользователя + активная организация
agenteye --json sessions --since 24h                                             # одна строка на запуск агента, последние 24ч
```

Последняя команда выводит JSON объект с самыми свежими сеансами (новые первыми, максимум 50 по умолчанию). Передайте его в `jq` для фильтрации или уберите `--json` для красиво оформленной таблицы с цветом. Каждая строка содержит статус запуска и, если оценщик его оценил, его оценки метрик (сокращённо):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

Остальная часть этой страницы объясняет каждый элемент: [установка](#installation) отдельно, [вход](#authentication), [конфигурация](#configuration), [глобальные соглашения](#global-options--conventions), которые используют все команды, и [полный справочник команд](#command-reference).

## Установка

CLI — это открытый пакет PyPI с названием **`agenteye`**. Установите его в изолированную среду, чтобы он всегда имел свои собственные зависимости:

```bash
pipx install agenteye
# или
uv tool install agenteye
```

Требует Python 3.10+. Установленная команда — **`agenteye`**:

```bash
agenteye --version
agenteye --help
```

> **Примечание:** Python SDK для наблюдаемости Failproof AI также использует имя дистрибутива `agenteye`. Установка CLI с помощью `pipx` или `uv tool` (а не `pip install` в общую virtualenv) предотвращает их конфликт. Простой `pip install agenteye` допустим только если SDK не установлен в той же среде.

## Аутентификация

CLI аутентифицируется на **панели управления** с помощью отправленного по почте одноразового кода:

```bash
agenteye login --email you@example.com
# На вашу почту отправляется 6-значный код; вставьте его в приглашение.
```

Токен сеанса сохраняется в `~/.agenteye/cli.json` (доступен только вам, режим `0600`) и по умолчанию действует 24 часа. Когда он истекает, запустите `agenteye login` снова.

```bash
agenteye whoami     # показать текущего пользователя, активную организацию и права доступа
agenteye logout     # отозвать сеанс и очистить сохранённый токен
```

`whoami` никогда не завершается с ошибкой при отсутствующем или истёкшем сеансе; вместо этого выводит `logged_in: false`, поэтому скрипт или агент могут безопасно проверить статус аутентификации (может всё ещё выйти с ненулевым кодом, если базовый URL не установлен или панель управления недоступна).

**Требования:** ваша почта должна быть разрешена для входа на панель управления (обратитесь к администратору Failproof AI Observability), и панель управления должна быть доступна по своему базовому URL (см. [Конфигурация](#configuration)). Если вы запросили код и он не пришёл, ваша почта, скорее всего, ещё не включена для доступа к панели управления.

## Выбор организации (мультитенантность)

Если ваша учётная запись принадлежит нескольким организациям, выберите активную **при входе**; она сохраняется и используется для всех последующих команд:

```bash
agenteye login --org acme           # аутентификация и установка активного тенанта в одно время
agenteye orgs list                  # организации, которые вы можете использовать (активная отмечена)
agenteye orgs switch globex         # изменить сохранённое значение по умолчанию
agenteye --org globex sessions      # переопределить для отдельной команды
```

Если вы принадлежите ровно одной организации, она выбирается автоматически и вы можете полностью игнорировать `--org`. Если вы принадлежите нескольким и не выбираете одну, CLI выводит их список и просит вас повторить команду с `--org <slug>`. Активная организация отправляется на панель управления при каждом запросе, ваши права разрешаются **для каждой организации**; `agenteye whoami` показывает активную организацию, ваши права в ней и все ваши членства.

## Конфигурация

| Параметр | Флаг | Переменная окружения | По умолчанию |
|---|---|---|---|
| Базовый URL панели управления | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **требуется** (нет значения по умолчанию) |
| Активная организация/тенант | `--org` | `AGENTEYE_ORG` | выбирается при входе; сохраняется в `~/.agenteye/cli.json` |
| Токен сеанса | `--token` | `AGENTEYE_CLI_TOKEN` | из `~/.agenteye/cli.json` |
| Вывод JSON | `--json` | `AGENTEYE_CLI_JSON` | отключено |
| Пропустить проверку TLS | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | отключено (сохраняется при входе) |
| Тайм-аут запроса (секунды) | `--timeout` | _(нет)_ | 30 |
| Отключить телеметрию использования | _(нет)_ | `AGENTEYE_ANALYTICS_DISABLED` (или `DO_NOT_TRACK`) | телеметрия в настоящее время отключена; ничего не отправляется |

Порядок разрешения: **флаг → переменная окружения → файл конфигурации**. Значения по умолчанию нет; вы должны указать CLI адрес вашей панели управления либо для каждой команды (`--base-url https://agenteye.example.com`), либо один раз через окружение (оно также сохраняется после первого входа `login`):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

Каталог конфигурации соблюдает `AGENTEYE_HOME` (то же соглашение, используемое SDK и сборщиком); если установлено, `cli.json` находится в `$AGENTEYE_HOME/cli.json`.

### Самоподписанный или внутренний TLS

Если ваша панель управления обслуживается по HTTPS с самоподписанным или внутренним сертификатом (например, сырый балансировщик нагрузки), проверка TLS отклоняет его с ошибкой `CERTIFICATE_VERIFY_FAILED`. Передайте `--insecure` для пропуска проверки сертификата:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` **сохраняется в `cli.json` при входе**, поэтому более поздние команды автоматически пропускают проверку; вам не нужно повторять флаг. Передайте `--secure` для одноразового проверенного вызова или для сохранения проверки при следующем входе. CLI выводит предупреждение на stderr перед любой командой, которая обращается к панели управления с отключённой проверкой. Пропуск проверки снимает защиту от атак «человек-посередине»; убедитесь, что вы доверяете сетевому пути к вашей панели управления (VPN, частная подсеть и т. д.) перед тем, как полагаться на это.

## Телеметрия и приватность

> **Примечание:** Поставляемый CLI **в настоящее время не отправляет никакую телеметрию использования.** Главный выключатель включен, поэтому ничего не передаётся независимо от вашего окружения. Раздел ниже описывает возможность отказа на случай, если и когда телеметрия будет включена.

Даже если она будет включена, телеметрия была бы только **анонимной аналитикой использования**, никогда не вашим агентом, сеансом или данными событий:

- **Никогда не будут отправлены данные агента, сеанса или события из вашей инфраструктуры.** Будет передана только статистика использования CLI: имя команды и подкоманды (например, `keys create`), **названия** использованных флагов (никогда их значения), статус успеха/выхода и продолжительность, плюс событие per-action для мутаций (например, `api_key_created`, `query_run`), содержащее только статические имена/enums и грубые подсчёты. Ваш URL панели управления, токен сеанса, почта, slug организации, id ресурсов, SQL, секреты ключей и фильтры запросов **никогда** не будут отправлены. Операторы будут идентифицированы только по непрозрачному внутреннему id, никогда по почте.
- **Откажитесь заранее**, установив `AGENTEYE_ANALYTICS_DISABLED=1` в окружении CLI (CLI также соблюдает кроссплатформенное соглашение `DO_NOT_TRACK=1`). Это вступает в силу в момент включения телеметрии, поэтому окружение, озабоченное приватностью, может остаться отключенным навсегда.
- Если бы телеметрия была включена, CLI отправлял бы непосредственно в PostHog (`https://us.i.posthog.com`); машина с заблокированным этим хостом молча ничего не отправляла бы и CLI остался бы неповреждённым.

## Глобальные опции и соглашения

Прочитайте это один раз; это применяется ко всем командам.

- **Глобальные опции идут ДО команды.** `agenteye --json sessions` правильно; `agenteye sessions --json` ошибка в использовании. Глобальные опции: `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, и `--no-color`.
- **`--json` выводит чистый JSON на stdout и ничего больше.** Строки состояния человека, предупреждения и ошибки идут на **stderr**, поэтому захват `--json` stdout остаётся чистым для передачи в `jq` даже когда показана строка состояния. Без `--json` вы получаете красиво оформленный цветной вид для человеческих глаз.
- **Узнавайте с `--help`.** Каждая команда и подкоманда имеет `--help` (и псевдоним `-h`): `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`. Справка верхнего уровня также выводит коды выхода и глобальные опции. Нет глобальной машиночитаемой поверхности; используйте `--help` для отдельных команд, плюс специфичные для домена `agenteye query schema` и `agenteye settings schema` для этих двух реестров.
- **Подтверждения автоматически пропускаются для скриптов и агентов.** Команды create/update/delete выдают приглашение «вы уверены?» в интерактивном терминале, но **автоматически пропускают это приглашение под `--json` или когда stdin не является TTY** (TTY — это интерактивный сеанс терминала; pipe или CI runner нет), поэтому скрипты и агенты никогда не зависают. Передайте `--yes`/`-y` для явного пропуска. Так как приглашение не срабатывает для агента, агент должен подтвердить деструктивные действия с человеком сначала.
- **Пагинация:** результаты новые-первыми и cursor-пагинированы (каждая страница возвращает токен, который вы используете для получения следующей). `--limit N` (псевдоним `-n`) ограничивает строки и **по умолчанию 50**; `--all` автоматически пагинирует (в блоках по 200 строк) **вплоть до `--limit`**, поэтому простой `--all` всё ещё останавливается на 50. Для полного сканирования передайте высокий явный предел: `--all --limit 1000`. `--page-size N` управляет блоком per-request (макс 200); `--cursor <id>` возобновляет с `next_cursor` предыдущей страницы.
- **Фильтры времени:** `--since` принимает относительное окно: `15m`, `1h`, `6h`, `24h`, `7d` или `all` (предустановки панели управления). Для более длительного или пользовательского диапазона (например, последние 30 дней), используйте `--from`/`--to`: явные ISO-8601 UTC временные метки **с `T` и временной зоной** (например, `2026-06-01T00:00:00Z`), которые переопределяют `--since`. Значение, разделённое пробелом или без временной зоны, ошибка в использовании.
- **`--fields a,b,c`** (на `events`, `sessions`, `evals`, `errors`) ограничивает вывод теми ключами для таблицы и `--json`. Неизвестные имена отклоняются с выводом допустимого списка, дешёвый способ обнаружить имена полей.
- **`--file payload.json`** (или `--file -` для чтения из stdin) предоставляет полное тело JSON запроса, когда ресурс имеет сложную структуру (на `alerts create/update`, `settings set`, и `users create/update`). Сохранённый SQL запроса использует `--sql @file.sql` вместо этого.
- **Фильтры с несколькими значениями** разделяются запятыми → сопоставлены как набор (объединение в одном фильтре, AND через фильтры): `--event-type tool_use,tool_result`. Опции клика не вариадичны, поэтому `--add a b` ломается. Используйте `--add a,b`, повторите флаг (`--add a --add b`) или заключите в кавычки (`--add "a b"`).

## Справочник команд

### Вы будете использовать эти 5 команд чаще всего

Большинство повседневной работы выполняется через несколько команд чтения. Начните здесь, затем обращайтесь к полной поверхности ниже, когда вам это понадобится:

| Команда | Что она делает | Попробуйте |
|---|---|---|
| `sessions` | Одна строка на запуск агента: время, среда, агент, статус, последняя оценка. | `agenteye --json sessions --since 24h --status error` |
| `events` | Сырая per-step тропа внутри запуска (добавьте `--full` для полезной нагрузки). | `agenteye --json events --session-id run-001 --all` |
| `evals` | Результаты оценки и оценки; `--aggregate` их свёртывает. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | Только ошибочные события; `--aggregate` для подсчётов по типам. | `agenteye --json errors --since 24h --aggregate` |
| `list` | Обнаружьте допустимые значения фильтров (агенты, среды, модели, …). | `agenteye list agents` |

### Всё, что может делать CLI

Полная поверхность следует. CLI имеет **18 команд верхнего уровня**. Все команды чтения принимают `--json` и глобальные опции выше; запустите `agenteye <command> -h` (или `<command> <subcommand> -h`) для исчерпывающего списка флагов и JSON формы любой.

### Идентификация: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # отправлен одноразовый код; сохраняет сеанс
agenteye logout                                       # очистить сохранённый сеанс на этой машине
agenteye whoami                                       # текущий пользователь, активная организация, права доступа
agenteye version                                      # вывести версию CLI (то же, что --version)
agenteye help                                         # справка верхнего уровня (то же, что --help)
```

`orgs` инспектирует и переключает активного тенанта:

```bash
agenteye orgs list        # ваши организации + ваша роль в каждой (активная отмечена)
agenteye orgs switch acme # изменить сохранённую активную организацию (пропустите slug для выбора из списка на TTY)
agenteye orgs current     # карточка идентификации активной организации
agenteye orgs perms       # ваши права в активной организации, сгруппированные по ресурсу
```

### Наблюдение (только для чтения): `events` · `sessions` · `evals` · `errors` · `list`

Ни одна из них не требует подтверждения. Общие фильтры: `--session-id`, `--agent-id`, `--env` (**не** `--environment`), и диапазон времени (`--since` / `--from` / `--to`).

```bash
# events (псевдоним: сырая per-step тропа), новые первыми
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: одна строка на запуск агента (время/среда/агент/сеанс/статус; без фильтрации оценок)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: результаты оценок + оценки; --score фильтрует по метрике, --aggregate свёртывает
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # микс статусов + per-key оценка статистики

# errors: ошибочные события; --aggregate для подсчётов/сеансов/агентов/последнего-видения
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: обнаружьте допустимые значения фильтров перед фильтрацией
agenteye list envs        # также: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (на **`evals`**, не `sessions`) повторяемо и AND-комбинировано; либо граница опциональна (`..0.5` означает ≤ 0.5, `0.9..` означает ≥ 0.9). До 20 фильтров оценок на запрос. `evals --scores-full` — флаг отображения **только для человеческой таблицы**; показывает каждую пару оценок вместо первых нескольких плюс `+N` подсчёт. Не влияет на `--json`, которые всегда возвращают полный объект оценки. Чтобы прочитать **один сеанс от начала до конца**, комбинируйте тропу событий с его оценкой:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # его оценки + статус
```

### Управление (gated по правам): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: API ключи. Секрет генерируется локально, отправляется на сервер (который сохраняет только хеш), и **показывается один раз** на create/regenerate; захватите его тогда. С `--json` он появляется только в поле `key`. Указывается по **имени**.

```bash
agenteye keys list                                   # активные ключи первыми, затем отозванные
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # область действия к тому, что вам нужно; выводит секрет ОДИН РАЗ
agenteye keys create ops --permission-set standard --remove queries:run   # сеять предустановку, затем обрезать
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # ротировать секрет (старый перестаёт работать)
agenteye keys disable ci-bot --yes                   # отозвать
```

Права работают как `(permission-set ∪ --add) − --remove`. Токены — это `slug:action` (например, `events:read`) или `slug:action.action` для расширения нескольких на одном ресурсе (`events:read.add` → `events:read`, `events:add`). Предустановки: `read-only`, `standard`, `admin`. Права, доступные только человеку (`keys:update`), не могут быть предоставлены ключу.

**`users`**: члены организации, на которых ссылаются по **почте** (также принимается UUID id).

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # предсказывает + подтверждает
agenteye users disable dev@corp.com --yes            # имеет защищённые/самозащитные охраны
agenteye users enable dev@corp.com
```

**`settings`**: фиксированный реестр (вы читаете и изменяете существующие ключи; вы не можете создавать новые).

```bash
agenteye settings list                               # ключ · значение · тип · обновлено (секреты скрыты)
agenteye settings schema                             # что принимает каждый ключ (тип · диапазон · описание)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: определения оповещений, на которые ссылаются по **имени**. `create` принимает позиционный NAME плюс флаги или полное тело JSON через `--file`.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME требуется (позиционный)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # отправить тестовое уведомление
agenteye alerts delete high-errors --yes
```

**`incidents`**: инциденты оповещений, на которые ссылаются по id (приемлемы короткие id). `show` выводит полный журнал активности; прочитайте перед действием.

```bash
agenteye incidents list --state firing                # также: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # назначенный должен быть оператором
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # открыть один вручную против оповещения
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### Аналитика и ассистент: `query` · `agent`

**`query`**: сохранённый SQL против вашего аналитического хранилища плюс интерпретатор ad-hoc. Сохранённые запросы указываются по **имени**; SQL проверяется на стороне сервера (только SELECT/WITH, тайм-аут оператора, ограничение строк).

```bash
agenteye query schema [TABLE]                         # макет колонок аналитических представлений
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # запустить сохранённый запрос + позиционный $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: обращается к встроенному **AI ассистенту** (того же read-only аналитика, с которым вы можете общаться в панели управления). Чаты указываются по короткому chat-id (prefix-resolved).

```bash
agenteye agent health                                 # configured/reachable ли AI ассистент
agenteye agent models                                 # модели, которые вы можете передать в --model (по умолчанию отмечена)
agenteye agent ask "which agents errored most in the last day?"    # начинает чат; выводит его short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # продолжить этот чат
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Успех |
| 1 | Неожиданная ошибка (например, панель управления вернула 5xx) |
| 2 | Ошибка в использовании (неверные аргументы, неизвестная команда/флаг, коллизия имён) |
| 3 | Невозможно достичь панель управления |
| 4 | Не вошли или сеанс истёк; запустите `agenteye login` |
| 5 | Аутентифицирован, но ваша учётная запись не имеет требуемого разрешения (сообщение его называет) |
| 6 | Запрошенный ресурс не найден (например, неизвестный сеанс или id инцидента) |

Это делает CLI безопасным для написания скриптов: кодирующий агент может ветвиться на `4` для запроса повторной аутентификации или на `5` для поверхности отсутствующего разрешения. См. [Рецепты CLI для агентов](/ru/agenteye/cli-recipes) для паттернов обработки кодов выхода и форм JSON вывода.
