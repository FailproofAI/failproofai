Ваши инженеры уже используют OpenAI Codex каждый день. Захват сессий Codex переносит эти сеансы кодирования в AgentEye как обычные сессии и события, чтобы вы могли искать, воспроизводить и оценивать их вместе со всем остальным, что вы наблюдаете. Это дополняет [Python SDK](/ru/agenteye/python-sdk): SDK инструментирует агентов, которых вы пишете, а эта функция захватывает работу с Codex, которую уже делает ваша команда — без каких-либо изменений в том, как они его запускают.

Небольшой фоновый сборщик считывает локальные транскрипты сессий Codex по мере их создания и отправляет их в AgentEye. Один сборщик на машину захватывает все локальные поверхности Codex одновременно — не требуется настройка для каждой поверхности.

Тот же сборщик захватывает и других агентов — см. [OpenClaw](/ru/agenteye/openclaw-capture) и [Hermes](/ru/agenteye/hermes-capture). Включите каждого, которого вы используете; один сборщик может захватывать несколько одновременно.

---

## Что захватывается

Каждая поверхность Codex, которая работает **локально**, создает одинаковые транскрипты сессий на диске, и сборщик захватывает все из них:

- **CLI** Codex и `codex exec`
- **расширение VS Code / IDE**
- **приложение рабочего стола**, когда оно запускает сессию локально

Каждая сессия Codex становится [сессией](/ru/agenteye/sessions) AgentEye; её сообщения пользователя и ассистента, рассуждения, вызовы инструментов, результаты инструментов и использование токенов становятся соответствующими [событиями](/ru/agenteye/event-stream). Поверхность, из которой поступила каждая сессия (CLI, IDE или рабочий стол), записывается, так что вы можете их различать.

> **Облачные сессии не захватываются.** Приложение рабочего стола все чаще запускает сессии в облаке Codex и хранит только их метаданные на машине — нет локального транскрипта для чтения. Захватываются только локально выполняемые сессии.

## Включение

Захват отключен до момента его включения. Установите сборщик с ключом API, имеющим разрешение `events:add` (см. [Ключи API](/ru/agenteye/api-keys)), и включите захват Codex:

```bash
curl -fsSL https://raw.githubusercontent.com/FailproofAI/agenteye-collector/main/install.sh \
  | sh -s -- --key <YOUR_API_KEY> --codex-enabled
```

Это установит сборщик, зарегистрирует его как фоновый сервис и начнет захват. Подтвердите, что он работает:

```bash
agenteye-collector health
```

При первом запуске ваши существующие сессии Codex заполняются один раз, а затем новая активность поступает в течение нескольких секунд. Файлы самого Codex только читаются — никогда не изменяются, не перемещаются или не удаляются — и каждая сессия отправляется ровно один раз, даже при перезагрузках.

## Где это отображается

Захватанные сессии появляются в **Sessions**, а их события в потоке **Events**, так же как любой другой наблюдаемый вами агент — поэтому [воспроизведение сессий](/ru/agenteye/sessions), [поиск](/ru/agenteye/queries), [оценки](/ru/agenteye/evaluations) и [оповещения](/ru/agenteye/alerts) работают с ними. Отфильтруйте по агенту Codex, чтобы увидеть их отдельно.

---

## Приватность

Транскрипты Codex содержат полную сессию — включая вывод команд, содержимое файлов и всё, что Codex прочитал или написал — и могут содержать секреты. Захватанные сессии отправляются как есть, поэтому включайте захват только на машинах и для команд, где централизация этого содержимого в AgentEye целесообразна, и дайте сборщику ключ с областью действия только `events:add`. См. [Security](/ru/agenteye/security), чтобы узнать, как ваши данные хранятся в изоляции.
