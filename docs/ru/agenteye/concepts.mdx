## Модель данных

**Event (событие)**
Наименьшая единица данных. Одно событие записывает один шаг, который выполнил ваш агент: `tool_use`, `model_request`, `hook_completed`, `error` и так далее. Ваш агент отправляет события через [Python SDK](/ru/agenteye/python-sdk); они появляются в реальном времени на странице **Events**.

**Session (сессия)**
Один запуск агента, идентифицируемый по `session_id`. Сессия — это все события, которые имеют этот идентификатор, свёрнутые в один ряд на странице **Sessions** и отображённые как граф выполнения на странице детализации. Сессия обычно начинается с `agent_start` и заканчивается с `agent_end`.

**Agent (агент)**
Именованный участник в запуске, идентифицируемый по `agent_id`. Запуск может включать несколько агентов: например, планировщик, который порождает под-агента суммаризатора. Под-агенты содержат `parent_id`, что позволяет Failproof AI Observability отображать их на отдельных дорожках в графе выполнения.

**Environment (окружение)**
Метка для места, где произошёл запуск: `production`, `staging`, `dev`. Вы устанавливаете её один раз при конфигурации SDK. Почти каждая страница дашборда может фильтроваться по окружению.

**Context-window fill (заполнение контекстного окна)**
Процент контекстного окна модели, который потребил ответ. Failproof AI Observability проставляет эту метрику на событиях `model_response` для распознаваемых моделей, благодаря чему рост промптов и предстоящая компактификация видны прямо в потоке событий.

## Качество

**Evaluation (оценка)**
Оценка качества завершённой сессии, выданная сервисом оценивания, который вы запускаете. Оценки опциональны: до подключения оценивателя сессии записываются, но не оцениваются. Каждая оценка может содержать несколько именованных показателей (например `helpfulness`, `factuality`, `tool_efficiency`), каждый с кратким обоснованием. См. [Evaluation suite](/ru/agenteye/evaluation-suite).

**Score key (ключ оценки)**
Название одного измерения, которое выдаёт оцениватель, например `helpfulness`. Оповещения и аудиты могут отслеживать конкретный ключ оценки во времени.

**Evaluator (оцениватель)**
Ваш сервис оценивания. Failproof AI Observability отправляет транскрипт завершённого запуска методом POST и сохраняет полученные оценки. Стандартный оцениватель не поставляется; логика оценивания — ваша.

## Поиск и исправление сбоев

**Hook (хук)**
Guardrail или побочный эффект, который выполняет ваш фреймворк агента вокруг шага: проверка безопасности контента, редактирование PII, контроль бюджета. Хуки отправляют события `hook_triggered` / `hook_completed` с `outcome` (allow, deny, modify) и получают собственную страницу наблюдения.

**Alert rule (правило оповещения)**
Правило, которое срабатывает, когда метрика пересекает установленный вами порог: коэффициент ошибок, p95 латентность, стоимость токенов или оценка оценивателя. Когда правило срабатывает, оно открывает инцидент и уведомляет выбранные вами каналы (электронная почта, Slack, webhook, на дашборде). См. [Alerts](/ru/agenteye/alerts).

**Incident (инцидент)**
Открытая проблема, созданная при срабатывании правила оповещения. Инциденты имеют жизненный цикл (подтверждение, назначение, разрешение) и временную шкалу активности, которая записывает каждое действие. Вы также можете открыть её вручную.

**Audit (аудит)**
Повторяющееся расследование (ежечасное до еженедельного), которое анализирует логи *поперёк* сессий в поисках паттернов сбоев, для которых вы не написали правило: кластеры ошибок, низкие оценки, выбросы латентности, циклы вызовов инструментов и запуски, которые никогда не завершились. Где оповещение отслеживает метрику, о которой вы уже знаете, аудит подсказывает вам, на что смотреть дальше. См. [Audits](/ru/agenteye/audits).

**Finding (находка)**
Один ранжированный результат, подкреплённый доказательствами, из запуска аудита. Находка называет паттерн, ссылается на точные сессии за ним и имеет жизненный цикл сортировки (подтверждение, разрешение, игнорирование, отклонение). Failproof AI Observability дедублицирует находки от запуска к запуску, поэтому известный паттерн обновляется вместо накопления.

**The AI assistant (ИИ-ассистент)**
Встроенный чат дашборда, который отвечает на вопросы о ваших агентах на простом английском языке на основе ваших данных. По умолчанию режим только для чтения; всё, что создаёт (сохранённый запрос, дашборд), требует одобрения, и он никогда не может удалять. См. [AI assistant](/ru/agenteye/assistant).

## Её запуск

**Organization (tenant) (организация)**
Изолированное рабочее пространство. Один экземпляр Failproof AI Observability может размещать множество организаций, каждая со своими пользователями, ключами и данными. Каждый URL дашборда ограничен вашей аббревиатурой организации (`/<org-slug>/…`).

**Collector (сборщик)**
`agenteye-collector`, лёгкий демон, который работает на каждой машине агента, агрегирует события, которые SDK записывает на диск, и отправляет их на сервер.

**API key (API ключ)**
Токен с ограничением, который аутентифицирует клиента против сервера. Ключи имеют детальные разрешения (например `events:add` для сборщика, области только для чтения для ключа дашборда). См. [API keys](/ru/agenteye/api-keys).

**Server (сервер)**
Сервис приёма и API. Он принимает события, сохраняет операционное состояние в ваши базы данных и обслуживает дашборд и CLI.

**Dashboard (дашборд)**
Веб-интерфейс. Каждая страница ограничена организацией и использует API сервера.
