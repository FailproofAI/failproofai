## Модель данных

**Event (событие)**
Наименьшая единица данных. Одно событие записывает один шаг, который предпринял ваш агент: `tool_use`, `model_request`, `hook_completed`, `error` и так далее. Ваш агент отправляет события через [Python SDK](/ru/agenteye/python-sdk); они появляются в реальном времени на странице **Events**.

**Session (сеанс)**
Один запуск агента, идентифицируемый `session_id`. Сеанс — это все события с одинаковым идентификатором, объединённые в один ряд на странице **Sessions** и представленные в виде графика выполнения на странице деталей. Сеанс обычно начинается с `agent_start` и заканчивается `agent_end`.

**Agent (агент)**
Именованный участник запуска, идентифицируемый `agent_id`. Запуск может включать несколько агентов: например, планировщик, который запускает вспомогательного агента-суммаризатора. Вспомогательные агенты имеют `parent_id`, что позволяет Failproof AI Observability отображать их на отдельных дорожках в графике выполнения.

**Environment (окружение)**
Метка, указывающая, где произошёл запуск: `production`, `staging`, `dev`. Вы устанавливаете её один раз при конфигурации SDK. Почти каждая страница панели управления может фильтроваться по окружению.

**Context-window fill (заполнение контекстного окна)**
Процент контекстного окна модели, использованный ответом. Failproof AI Observability проставляет эту метрику на события `model_response` для распознаваемых моделей, поэтому рост промпта и предстоящее сжатие контекста видны прямо в потоке событий.

## Качество

**Evaluation (оценка)**
Оценка качества завершённого сеанса, созданная службой оценки, которую вы запускаете. Оценки являются опциональными: до подключения оценивающей службы сеансы записываются, но не оцениваются. Каждая оценка может содержать несколько именованных баллов (например `helpfulness`, `factuality`, `tool_efficiency`), каждый с кратким пояснением. См. [Evaluation suite](/ru/agenteye/evaluation-suite).

**Score key (ключ оценки)**
Название одного измерения, о котором сообщает оценивающая служба, например `helpfulness`. Оповещения и аудиты могут отслеживать конкретный ключ оценки во времени.

**Evaluator (оценивающая служба)**
Ваша служба оценки. Failproof AI Observability отправляет на неё POST-запрос с расшифровкой завершённого запуска и сохраняет возвращаемые оценки. По умолчанию никакая служба оценки не поставляется; логика оценки — это ваша задача.

## Поиск и исправление сбоев

**Hook (хук)**
Ограничение или побочный эффект, который платформа вашего агента выполняет вокруг шага: проверка безопасности содержимого, редактирование PII, контроль бюджета. Хуки отправляют события `hook_triggered` / `hook_completed` с `outcome` (allow, deny, modify) и имеют свою страницу наблюдения.

**Alert rule (правило оповещения)**
Правило, которое срабатывает, когда метрика пересекает установленный вами порог: частота ошибок, p95 задержки, стоимость токенов или оценка оценивающей службы. Когда правило срабатывает, оно открывает инцидент и уведомляет выбранные вами каналы (email, Slack, webhook, в панели управления). См. [Alerts](/ru/agenteye/alerts).

**Incident (инцидент)**
Открытая проблема, созданная при срабатывании правила оповещения. Инциденты имеют жизненный цикл (acknowledge, assign, resolve) и ленту активности, которая записывает каждое действие. Вы также можете открыть инцидент вручную.

**Audit (аудит)**
Повторяющееся расследование (почасово или еженедельно), которое анализирует ваши логи *по всем* сеансам в поиске паттернов сбоев, для которых вы не написали правило: кластеры ошибок, низкие оценки, аномалии задержек, циклы вызовов инструментов и незавершённые запуски. Если оповещение отслеживает известную вам метрику, аудит подскажет, на что обратить внимание дальше. См. [Audits](/ru/agenteye/audits).

**Finding (вывод)**
Один ранжированный результат аудита с подтверждающими доказательствами. Вывод указывает на паттерн, ссылается на точные сеансы за ним и имеет жизненный цикл триажа (acknowledge, resolve, mute, dismiss). Failproof AI Observability дедублирует выводы от запуска к запуску, так что известный паттерн обновляется вместо накопления.

**The AI assistant (AI-помощник)**
Встроенный в панель управления чат, который отвечает на вопросы о ваших агентах на простом английском, на основе ваших собственных данных. По умолчанию он работает в режиме только чтения; всё, что он создаёт (сохранённый запрос, панель управления), требует одобрения, и он никогда не может удалять. См. [AI assistant](/ru/agenteye/assistant).

## Запуск

**Organization (tenant) (организация)**
Изолированное рабочее пространство. Один экземпляр Failproof AI Observability может размещать множество организаций, каждая со своими пользователями, ключами и данными. Каждый URL панели управления находится в области вашего слага организации (`/<org-slug>/…`).

**Collector (сборщик)**
`agenteye-collector`, лёгкий демон, который работает на каждом устройстве агента, пакетирует события, которые SDK записывает на диск, и отправляет их на сервер.

**API key (API ключ)**
Ограниченный токен, который аутентифицирует клиента на сервере. Ключи имеют детальные разрешения (например `events:add` для сборщика, области только для чтения для ключа панели управления). См. [API keys](/ru/agenteye/api-keys).

**Server (сервер)**
Сервис приёма и API. Он принимает события, сохраняет операционное состояние в ваши базы данных и обслуживает панель управления и CLI.

**Dashboard (панель управления)**
Веб-интерфейс. Каждая страница находится в области организации и осуществляет доступ через API сервера.
