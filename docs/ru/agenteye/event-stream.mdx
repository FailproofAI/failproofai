В момент, когда ваш агент что-то делает, вы это видите. Поток событий — это ваш живой пульс каждого агента в production: никакого ожидания, никакого поиска по логам, никакого угадывания того, что произошло.

![Живой поток событий: строки событий с цветовой кодировкой, обновляющиеся в реальном времени, фильтруемые по окружению, агенту, сессии, типу события и свободному тексту](/agenteye/images/events-stream.png)

*Каждое событие от каждого агента в вашей организации, самые новые в начале, обновляется по мере их возникновения.*

## Ваш живой пульс на каждом агенте

Когда агент запускает run, вызывает модель, срабатывает инструмент, выполняет hook или попадает в ошибку, строка появляется в начале потока в момент события. Поток отслеживает все события со всех агентов в вашей организации, самые новые в начале, поэтому у вас всегда есть актуальная картина вместо устаревшей.

Это означает, что не нужно просматривать файлы логов на каком-то сервере, не нужно искать по машинам, не нужно вручную сопоставлять временные метки. Вы открываете одну страницу и уже смотрите production.

Строки имеют цветовую кодировку по типам, поэтому вы можете читать поток с первого взгляда вместо разбора каждой строки. С первого взгляда каждая строка показывает вам:

- **Её тип**, с цветовой кодировкой: `agent_start`, `model_response`, `tool_use`, `hook_completed`, `error` и другие.
- **Однострочный краткий обзор** того, что произошло, чтобы вам редко нужно было открывать что-то только для того, чтобы понять суть.
- **Количество токенов** для этого шага.
- **Значок заполнения контекстного окна**, где это применимо, чтобы рост prompt и приближающаяся компактизация были видны до того, как они станут проблемой.

Просмотр в реальном времени означает, что вы ловите неудачное развёртывание, бесконечный цикл или всплеск ошибок по мере их возникновения, а не в завтрашнем обзоре логов.

## Найдите единственный run, который важен

Когда что-то выглядит не так, вам не нужен весь поток. Вам нужен единственный run, который сломался. Поток фильтруется быстро: по окружению, по агенту, по сессии, по типу события или по свободному тексту.

Фильтруйте по id сессии или id агента, чтобы проследить один run от его первого события до последнего. Фильтруйте по типу события, чтобы выделить один вид активности, например все `error` по организации в одном представлении. Комбинируйте фильтры, чтобы сузить от "всё, везде" до "этот агент, в prod, ошибающийся" за несколько кликов, затем действуйте в соответствии с тем, что вы нашли.

Поиск по свободному тексту сразу же переходит к сообщению, названию инструмента или id, который у вас уже есть под рукой, поэтому отчёт клиента превращается в точный run за считанные секунды.

## Где его найти

Поток событий — это главная страница вашей организации. Войдите и это первая страница, на которую вы попадёте, в `/<org-slug>/`, поэтому сортировка начинается со второй, когда вы приезжаете.

За кулисами ваши агенты генерируют события через SDK, collector отправляет их на ваш сервер Failproof AI Observability, а поток отслеживает их при поступлении в инфраструктуру под вашим контролем. Когда вам нужен свёрнутый вид вместо необработанного следа, события каждого run свёртываются в одну строку на Sessions, в одном клике.

Это необработанный источник истины, на котором строятся все остальные observe поверхности, поэтому когда число выглядит неправильно где-то ещё, поток — это место, где вы подтверждаете, что на самом деле произошло.
