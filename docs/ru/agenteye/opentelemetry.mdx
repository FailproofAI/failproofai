OpenTelemetry позволяет отправлять трассировки агентов, логи и метрики в FailproofAI Cloud, используя стандартный протокол OTLP/HTTP. Это опционально. Ваши существующие интеграции FailproofAI продолжают работать без его включения.

## Включите прием данных для вашей организации

Администратор организации открывает **Settings → OpenTelemetry** и включает прием данных. Используйте API-ключ Cloud с разрешением `events:add` — то же разрешение, которое используется для отчетности агента.

Если прием отключен, Cloud отклоняет экспорт OTLP, поэтому `failproofai otel enable` ничего не меняет, и ваши агенты продолжают отправлять сеансы обычным способом. Запустите `failproofai otel status`, чтобы проверить переключатель организации, и попросите администратора его включить.

## Подключите кодирующего агента

Подключите вашу машину с помощью `failproofai config`, затем выберите агента:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Команда setup поддерживает Claude Code, Codex и Copilot и выбирает Cloud или локальное аутентифицированное реле по мере необходимости. Copilot использует локальное реле автоматически. Запустите сконфигурированный демон FailproofAI перед использованием реле.

Если FailproofAI уже отправляет транскрипты сеансов агента, setup спрашивает, переключить ли этого агента на OTEL. По умолчанию — Нет. Подтверждение остановит загрузку транскриптов для этого агента; это не изменит применение политик или отчетность от других агентов.

## Подключите приложение

Используйте инструментацию OpenTelemetry вашего приложения с этими переменными окружения:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Endpoint — это OTLP-база Cloud, `https://app.befailproof.ai/otel`; ваш экспортер добавляет `/v1/traces`, `/v1/logs` или `/v1/metrics` самостоятельно. Переменные для отдельных сигналов, такие как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, используются как есть, поэтому им нужен полный путь, например `https://app.befailproof.ai/otel/v1/logs`.

Замените `<key>` на ваш API-ключ. Держите секрет подальше от истории shell, записей экрана и зафиксированной конфигурации. Для сконфигурированной машины `failproofai otel env --service my-agent` выводит блок с его существующим ключом. Его выходные данные содержат учетные данные.

Cloud принимает экспорт OTLP/HTTP для трассировок, логов и метрик в формате protobuf или JSON, включая сжатые запросы gzip. Он не принимает OTLP/gRPC.

Метрики подтверждаются для совместимости экспортера, но не сохраняются и не отображаются. Поддерживаемые трассировки агентов и логи кодирующего агента становятся сеансами; поля, которые агент не экспортирует, остаются отсутствующими.

## Захватите текст подсказки

<Warning>
Захват текста может включать подсказки, аргументы инструментов и другое чувствительное содержимое. `failproofai otel enable` включает его. Добавьте `--no-content`, чтобы отключить захват подсказок и деталей инструментов.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Для агента, который вы настраиваете вручную, используйте его собственные элементы управления захватом контента:

<Tabs>
  <Tab title="Claude Code">
    Добавьте эти переменные в окружение вашего агента рядом с блоком приложения выше:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Установите обе переменные контента на `0`, чтобы избежать захвата подсказок и деталей инструментов.
  </Tab>
  <Tab title="Codex">
    В пользовательской конфигурации Codex используйте его параметры OTEL:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Содержание разговора Codex находится в логах; оставьте внутренние трассировки и метрики выполнения отключенными. Codex использует полный endpoint, который вы указываете. Установите `log_user_prompt` на `false`, чтобы исключить подсказки; команда setup сохраняет явное значение `false`.
  </Tab>
  <Tab title="Gemini CLI">
    Используйте параметры телеметрии Gemini с локальным реле:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI не поддерживается `failproofai otel enable`. Настройте его вручную с помощью своего собственного аутентифицированного сборщика. Установите `logPrompts` на `false` для отключения захвата подсказок.
  </Tab>
  <Tab title="Copilot в VS Code">
    Используйте эти параметры пользователя VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Запустите `failproofai otel enable copilot` для включения аутентифицированного реле. Установите `captureContent` на `false`, чтобы исключить содержимое.
  </Tab>
</Tabs>

## Проверьте или отмените настройку

```bash
failproofai otel status
failproofai otel disable all
```

Status различает параметры, управляемые FailproofAI, и телеметрию, которую вы настроили в другом месте. Disable восстанавливает предыдущие управляемые параметры и предыдущий выбор загрузки транскрипта агента.
