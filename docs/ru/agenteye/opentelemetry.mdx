OpenTelemetry позволяет отправлять трассировки, логи и метрики агента в FailproofAI Cloud, используя стандартный протокол OTLP/HTTP. Это необязательно. Ваши существующие интеграции FailproofAI продолжат работать без его включения.

## Включите прием данных для вашей организации

Администратор организации открывает **Settings → OpenTelemetry** и включает прием данных. Используйте облачный API-ключ с разрешением `events:add` — то же разрешение, которое используется для отчетов агента.

Если прием отключен, Cloud отклонит экспорт OTLP, поэтому `failproofai otel enable` не изменит ничего, и ваши агенты будут отправлять сеансы обычным способом. Запустите `failproofai otel status`, чтобы проверить переключатель организации, и попросите администратора его включить.

## Подключите кодирующего агента

Подключите вашу машину с помощью `failproofai config`, затем выберите агента:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Команда настройки поддерживает Claude Code, Codex и Copilot и выбирает Cloud или локальное аутентифицированное реле как необходимо. Copilot использует локальное реле автоматически. Запустите настроенный демон FailproofAI перед использованием реле.

Если FailproofAI уже отправляет стенограммы сеансов агента, настройка спросит, переключить ли этого агента на OTEL. По умолчанию ответ «Нет». Если согласиться, загрузка стенограмм для этого агента остановится; это не повлияет на применение политик или отчетность других агентов.

## Подключите приложение

Используйте инструментализацию OpenTelemetry вашего приложения с этими переменными окружения:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Конечная точка — это база OTLP Cloud `https://app.befailproof.ai/otel`; ваш экспортер добавит `/v1/traces`, `/v1/logs` или `/v1/metrics` сам. Переменные для отдельных сигналов, такие как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, используются как есть, поэтому им нужен полный путь, например `https://app.befailproof.ai/otel/v1/logs`.

Замените `<key>` на ваш API-ключ. Держите секрет подальше от истории shell, видеозаписей и зафиксированной конфигурации. Для настроенной машины `failproofai otel env --service my-agent` выводит блок с существующим ключом. Его вывод содержит учетные данные.

Cloud принимает экспорты OTLP/HTTP для трассировок, логов и метрик в формате protobuf или JSON, включая сжатые gzip-запросы. Он не принимает OTLP/gRPC.

Метрики признаются для совместимости экспортера, но не хранятся и не отображаются. Поддерживаемые трассировки агента и логи кодирующего агента становятся сеансами; поля, которые агент не экспортирует, остаются отсутствующими.

## Захватите текст подсказок

<Warning>
Захват текста может включать подсказки, аргументы инструментов и другое конфиденциальное содержимое. `failproofai otel enable` его включает. Добавьте `--no-content`, чтобы оставить захват подсказок и деталей инструментов отключенным.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Для агента, который вы настраиваете вручную, используйте его собственные управления захватом содержимого:

<Tabs>
  <Tab title="Claude Code">
    Добавьте эти переменные в окружение вашего агента наряду с блоком приложения выше:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Установите обе переменные содержимого на `0`, чтобы избежать захвата подсказок и деталей инструментов.
  </Tab>
  <Tab title="Codex">
    В пользовательской конфигурации Codex используйте его параметры OTEL:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Содержимое диалогов Codex находится в логах; оставьте внутренние трассировки среды выполнения и метрики отключенными. Codex использует полную конечную точку, которую вы предоставляете. Установите `log_user_prompt` на `false`, чтобы исключить подсказки; команда настройки сохранит явный `false`.
  </Tab>
  <Tab title="Gemini CLI">
    Используйте параметры телеметрии Gemini с локальным реле:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI не поддерживается `failproofai otel enable`. Настройте его вручную с аутентифицированным сборщиком собственного производства. Установите `logPrompts` на `false` для отсутствия захвата подсказок.
  </Tab>
  <Tab title="Copilot in VS Code">
    Используйте эти параметры пользователя VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Запустите `failproofai otel enable copilot`, чтобы включить аутентифицированное реле. Установите `captureContent` на `false`, чтобы исключить содержимое.
  </Tab>
</Tabs>

## Проверьте или отмените настройку

Реле сохраняет телеметрию при временных сбоях сети и сервера и повторяет попытки после восстановления. Постоянный отказ `400`, включая событие, которое слишком велико для хранения, требует исправления полезной нагрузки. Реле сохраняет отклоненный пакет для проверки, а не отправляет его повторно.

После `401` или `403` замените учетные данные на ключ, предоставляющий `events:add` для той же организации. Повторное подключение не отправит автоматически сохраненные экспорты OTLP, отклоненные из-за учетных данных; попросите вашего оператора восстановить эти пакеты. Держите их в исходной организации.

```bash
failproofai otel status
failproofai otel disable all
```

Статус различает параметры, управляемые FailproofAI, и телеметрию, которую вы настроили где-то еще. Отключение восстанавливает предыдущие управляемые параметры и предыдущий выбор загрузки стенограмм агента.
