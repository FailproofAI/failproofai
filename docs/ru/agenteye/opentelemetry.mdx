OpenTelemetry позволяет отправлять трассировку агента, логи и метрики в FailproofAI Cloud, используя стандартный протокол OTLP/HTTP. Это опционально. Ваши существующие интеграции FailproofAI продолжают работать без его включения.

## Включите прием данных для вашей организации

Администратор организации открывает **Settings → OpenTelemetry** и включает прием данных. Используйте API ключ Cloud с разрешением `events:add` — такое же разрешение используется для отчетности агента.

Если прием отключен, Cloud отклоняет OTLP экспорты, поэтому `failproofai otel enable` ничего не изменит, и ваши агенты будут отправлять сессии обычным способом. Выполните `failproofai otel status`, чтобы проверить переключатель организации, и попросите администратора его включить.

## Подключите кодирующего агента

Подключите вашу машину с помощью `failproofai config`, затем выберите агента:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Команда установки поддерживает Claude Code, Codex и Copilot и выбирает Cloud или локальное аутентифицированное реле по мере необходимости. Copilot использует локальное реле автоматически. Запустите настроенный демон FailproofAI перед использованием реле.

Если FailproofAI уже отправляет транскрипты сессий агента, установка спросит, переключить ли этот агент на OTEL. По умолчанию ответ — нет. Согласие остановит загрузку транскриптов для этого агента; это не изменит применение политик и отчетность от других агентов.

## Подключите приложение

Используйте инструментацию OpenTelemetry вашего приложения с этими переменными окружения:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Конечная точка — это OTLP база Cloud `https://app.befailproof.ai/otel`; ваш экспортер добавляет `/v1/traces`, `/v1/logs` или `/v1/metrics` самостоятельно. Переменные для отдельных сигналов, такие как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, используются как есть, поэтому им нужен полный путь, например `https://app.befailproof.ai/otel/v1/logs`.

Замените `<key>` на ваш API ключ. Держите секрет подальше от истории shell, записей экрана и закоммиченной конфигурации. Для настроенной машины `failproofai otel env --service my-agent` выведет блок с существующим ключом. Его вывод содержит учетные данные.

Cloud принимает OTLP/HTTP экспорты для трассировки, логов и метрик в формате protobuf или JSON, включая сжатые gzip запросы. Он не принимает OTLP/gRPC.

Метрики подтверждаются для совместимости экспортера, но не сохраняются и не отображаются. Поддерживаемые трассировки агента и логи кодирующего агента становятся сессиями; поля, которые агент не экспортирует, остаются отсутствующими.

## Захватывайте текст приглашения

<Warning>
Захват текста может включать приглашения, аргументы инструментов и другой чувствительный контент. `failproofai otel enable` включает это. Добавьте `--no-content`, чтобы отключить захват приглашений и деталей инструментов.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Для агента, которого вы настраиваете вручную, используйте его собственные средства управления захватом контента:

<Tabs>
  <Tab title="Claude Code">
    Добавьте эти переменные в окружение вашего агента рядом с блоком приложения выше:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Установите обе переменные контента в `0`, чтобы избежать захвата приглашений и деталей инструментов.
  </Tab>
  <Tab title="Codex">
    В пользовательской конфигурации Codex используйте его параметры OTEL:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Содержимое беседы Codex находится в логах; оставьте внутренние трассировки времени выполнения и метрики отключенными. Codex использует полную конечную точку, которую вы предоставляете. Установите `log_user_prompt` в `false`, чтобы исключить приглашения; команда установки сохранит явное значение `false`.
  </Tab>
  <Tab title="Gemini CLI">
    Используйте параметры телеметрии Gemini с локальным реле:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI не поддерживается `failproofai otel enable`. Настройте его вручную с вашим собственным аутентифицированным сборщиком. Установите `logPrompts` в `false` для отсутствия захвата приглашений.
  </Tab>
  <Tab title="Copilot в VS Code">
    Используйте эти параметры пользователя VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Выполните `failproofai otel enable copilot`, чтобы включить аутентифицированное реле. Установите `captureContent` в `false`, чтобы пропустить контент.
  </Tab>
</Tabs>

## Проверьте или отмените настройку

Реле сохраняет телеметрию при временных сбоях сети и сервера и повторяет попытки после восстановления. Постоянное отклонение `400`, включая событие, которое слишком велико для сохранения, требует исправления полезной нагрузки. Реле сохраняет отклоненный пакет для проверки, а не повторно отправляет его.

После `401` или `403` замените учетные данные на ключ, предоставляющий `events:add` для той же организации. Переподключение не автоматически отправляет заново сохраненные OTLP экспорты, отклоненные по причине учетных данных; попросите вашего оператора восстановить эти пакеты. Сохраняйте их в исходной организации.

```bash
failproofai otel status
failproofai otel disable all
```

Статус различает параметры, управляемые FailproofAI, и телеметрию, которую вы настроили в другом месте. Отключение восстанавливает предыдущие управляемые параметры и предыдущий выбор загрузки транскриптов агента.
