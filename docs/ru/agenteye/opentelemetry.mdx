OpenTelemetry позволяет отправлять трассировки агента, логи и метрики в FailproofAI Cloud, используя стандартный протокол OTLP/HTTP. Это опционально. Ваши существующие интеграции FailproofAI продолжают работать без его включения.

## Получить ключ

Приём OTLP всегда активен для каждой организации; нет ничего, что нужно включать. Используйте облачный API-ключ с разрешением `events:add`, то же разрешение, которое используется для отчётности агента.

В панели управления **home → first-run setup** есть карточка **connect with OpenTelemetry**: **create collector key** создаёт ключ `events:add`, показывает его один раз с переменными экспортера и отображает статус подключения. Вы также можете создать ключ в разделе **settings → api keys**, выбрав **sending logs only** под **new key**.

## Подключить coding agent

Подключите вашу машину с помощью `failproofai config`, затем выберите агента:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Команда настройки поддерживает Claude Code, Codex и Copilot и выбирает Cloud или локальный аутентифицированный релей в зависимости от ситуации. Copilot использует локальный релей автоматически. Запустите настроенный демон FailproofAI перед использованием релея.

Если FailproofAI уже отправляет стенограммы сеанса агента, при настройке спрашивается, переключить ли этого агента на OTEL. По умолчанию ответ — Нет. При согласии загрузка стенограмм для этого агента прекращается; это не влияет на принудительное применение политик или отчётность от других агентов.

## Подключить приложение

Используйте инструментацию OpenTelemetry вашего приложения с этими переменными окружения:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Конечная точка — это OTLP-базис Cloud, `https://app.befailproof.ai/otel`; ваш экспортер добавляет `/v1/traces`, `/v1/logs` или `/v1/metrics` самостоятельно. Переменные для отдельных сигналов, такие как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, используются как есть, поэтому они требуют полного пути, например `https://app.befailproof.ai/otel/v1/logs`.

Замените `<key>` на ваш API-ключ. Держите секрет в тайне от истории shell, записей экрана и добавленной в репозиторий конфигурации. Для настроенной машины `failproofai otel env --service my-agent` выведет блок с существующим ключом. Его вывод содержит учётные данные.

Cloud принимает экспорты OTLP/HTTP для трассировок, логов и метрик в формате protobuf или JSON, включая сжатые gzip-запросы. Он не принимает OTLP/gRPC.

Метрики подтверждаются для совместимости с экспортером, но не сохраняются и не отображаются. Поддерживаемые трассировки агента и логи coding-agent становятся сеансами; поля, которые агент не экспортирует, остаются отсутствующими.

## Захватить текст подсказки

<Warning>
Захват текста может включать подсказки, аргументы инструментов и другой чувствительный контент. `failproofai otel enable` включает это. Добавьте `--no-content`, чтобы отключить захват подсказок и деталей инструментов.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Для агента, который вы настраиваете вручную, используйте его собственные элементы управления захватом контента:

<Tabs>
  <Tab title="Claude Code">
    Добавьте эти переменные в окружение вашего агента рядом с блоком приложения выше:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Установите обе переменные контента на `0`, чтобы избежать захвата подсказок и деталей инструментов.
  </Tab>
  <Tab title="Codex">
    В пользовательской конфигурации Codex используйте его параметры OTEL:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Контент диалога Codex находится в логах; оставьте внутренние трассировки времени выполнения и метрики отключёнными. Codex использует полную конечную точку, которую вы предоставляете. Установите `log_user_prompt` на `false`, чтобы исключить подсказки; команда настройки сохраняет явное значение `false`.
  </Tab>
  <Tab title="Gemini CLI">
    Используйте параметры телеметрии Gemini с локальным релеем:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI не поддерживается `failproofai otel enable`. Настройте его вручную с использованием аутентифицированного коллектора на ваш выбор. Установите `logPrompts` на `false`, чтобы отключить захват подсказок.
  </Tab>
  <Tab title="Copilot в VS Code">
    Используйте эти параметры пользователя VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Запустите `failproofai otel enable copilot`, чтобы включить аутентифицированный релей. Установите `captureContent` на `false`, чтобы исключить контент.
  </Tab>
</Tabs>

## Проверить или отменить настройку

Релей сохраняет телеметрию при временных сбоях сети и сервера и повторяет попытки после восстановления. Постоянный отказ `400`, включая событие, которое слишком велико для хранения, требует исправления полезной нагрузки. Релей сохраняет отклонённый пакет для проверки, а не повторно отправляет его.

После `401` или `403` замените учётные данные на ключ, предоставляющий `events:add` для той же организации. Переподключение не автоматически переотправляет сохранённые экспорты OTLP, отклонённые из-за учётных данных; попросите у вашего оператора восстановить эти пакеты. Держите их в их исходной организации.

```bash
failproofai otel status
failproofai otel disable all
```

Статус различает параметры, управляемые FailproofAI, и телеметрию, которую вы настроили в другом месте. Отключение восстанавливает предыдущие управляемые параметры и предыдущий выбор агента по загрузке стенограмм.
