OpenTelemetry позволяет отправлять traces, логи и метрики агента в FailproofAI Cloud, используя стандартный протокол OTLP/HTTP. Это опционально. Ваши существующие интеграции FailproofAI продолжат работать без его включения.

## Включите приём для вашей организации

Администратор организации открывает **Settings → OpenTelemetry** и включает приём. Используйте Cloud API ключ с разрешением `events:add` — тем же разрешением, что используется для отчётности агента.

Если приём отключён, Cloud отклоняет OTLP экспорты, поэтому `failproofai otel enable` ничего не меняет, и ваши агенты продолжают отправлять сессии обычным способом. Запустите `failproofai otel status` для проверки переключателя организации и попросите администратора его включить.

## Подключите coding agent

Подключите вашу машину с помощью `failproofai config`, затем выберите агента:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Команда setup поддерживает Claude Code, Codex и Copilot и выбирает Cloud или локальный аутентифицированный relay по мере необходимости. Copilot использует локальный relay автоматически. Запустите настроенный FailproofAI daemon перед использованием relay.

Если FailproofAI уже отправляет транскрипты сессий агента, setup спросит, переключить ли этого агента на OTEL. По умолчанию — Нет. Принятие останавливает загрузку транскриптов для этого агента; это не влияет на соблюдение политик или отчётность других агентов.

## Подключите приложение

Используйте инструментацию OpenTelemetry вашего приложения с этими переменными окружения:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Endpoint — это OTLP base Cloud, `https://app.befailproof.ai/otel`; ваш exporter добавляет `/v1/traces`, `/v1/logs` или `/v1/metrics` сам. Переменные для отдельных сигналов, такие как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, используются как есть, поэтому им нужен полный путь, например `https://app.befailproof.ai/otel/v1/logs`.

Замените `<key>` на ваш API ключ. Держите секрет подальше от истории shell, записей экрана и committed конфигурации. Для настроенной машины `failproofai otel env --service my-agent` выводит блок с его существующим ключом. Его вывод содержит учётные данные.

Cloud принимает OTLP/HTTP экспорты для traces, логов и метрик в формате protobuf или JSON, включая gzip-сжатые запросы. Он не принимает OTLP/gRPC.

Метрики принимаются для совместимости exporter, но не сохраняются и не отображаются. Поддерживаемые traces агента и логи coding-agent становятся сессиями; поля, которые агент не экспортирует, остаются отсутствующими.

## Захватите текст промпта

<Warning>
Захват текста может включать промпты, аргументы инструментов и другое конфиденциальное содержимое. `failproofai otel enable` включает его. Добавьте `--no-content` для отключения захвата промптов и деталей инструментов.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Для агента, который вы настраиваете вручную, используйте его собственные элементы управления захватом содержимого:

<Tabs>
  <Tab title="Claude Code">
    Добавьте эти переменные в окружение вашего агента рядом с блоком приложения выше:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Установите обе переменные содержимого на `0` для избежания захвата промптов и деталей инструментов.
  </Tab>
  <Tab title="Codex">
    В пользовательской конфигурации Codex используйте его параметры OTEL:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Содержимое диалогов Codex находится в логах; оставьте отключенными внутренние traces среды выполнения и метрики. Codex использует полный endpoint, который вы предоставляете. Установите `log_user_prompt` на `false` для исключения промптов; команда setup сохраняет явное `false`.
  </Tab>
  <Tab title="Gemini CLI">
    Используйте параметры телеметрии Gemini с локальным relay:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI не поддерживается `failproofai otel enable`. Настройте его вручную с использованием аутентифицированного collector по вашему выбору. Установите `logPrompts` на `false` для отключения захвата промптов.
  </Tab>
  <Tab title="Copilot в VS Code">
    Используйте эти параметры пользователя VS Code:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Запустите `failproofai otel enable copilot` для включения аутентифицированного relay. Установите `captureContent` на `false` для исключения содержимого.
  </Tab>
</Tabs>

## Проверьте или отмените настройку

Relay сохраняет телеметрию при временных сбоях сети и сервера и повторяет попытки после восстановления. Постоянный отказ `400`, включая событие, слишком большое для сохранения, требует исправления payload. Relay хранит отклонённый batch для проверки вместо повторной его отправки.

После `401` или `403` замените учётные данные на ключ, предоставляющий `events:add` для той же организации. Переподключение не автоматически переотправляет сохранённые OTLP экспорты, отклонённые из-за учётных данных; попросите вашего оператора восстановить эти batches. Храните их в их исходной организации.

```bash
failproofai otel status
failproofai otel disable all
```

Status различает параметры, управляемые FailproofAI, и телеметрию, которую вы настроили где-либо ещё. Disable восстанавливает предыдущие управляемые параметры и предыдущий выбор агента для загрузки транскриптов.
