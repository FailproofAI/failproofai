Смотрите ровно, что сделали ваши AI агенты в production: каждый запуск агента, вызов инструмента, запрос к модели, хук и вмешательство человека. Failproof AI Observability Python SDK записывает этот след из внутри кода вашего агента, чтобы вы могли отлаживать, аудировать и оценивать то, что произошло. Используйте его всякий раз, когда хотите, чтобы Failproof AI Observability наблюдал за вашими агентами.

Под капотом SDK пишет структурированные события в локальные JSONL файлы, и демон сборщика их поднимает и автоматически отправляет на платформу. Вам не нужно управлять этими файлами самостоятельно.

## Установка

SDK распространяется клиентам как приватный wheel, а не из публичного индекса пакетов. Ваш онбординг охватывает, как его получить, установить и закрепить версию — поговорите с вашим контактом в Failproof AI, если вам нужен доступ.

После установки проверьте, что у вас она есть:

```bash
python -c "import agenteye; print(agenteye.__version__)"
```

Предпочитаете позволить кодирующему агенту выполнить всю интеграцию? [Python SDK Agent Skill](/ru/agenteye/python-sdk-skill) знает путь установки, планирует точки инструментирования, пишет их и проверяет, что события приходят.

## Быстрый старт

```python
import agenteye

agenteye.configure(environment="production")

agenteye.event.agent_start(session_id="run-001", agent_id="planner", goal="answer user query")

agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    input={"query": "latest AI research"},
)

agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    output={"results": ["..."]},
)

agenteye.event.agent_end(session_id="run-001", agent_id="planner", outcome="success")
```

### Инструментирование реального вызова

На практике вы обёртываете существующий код агента. Обрамляйте вызов модели с `model_request` перед и `model_response` после, чтобы два события охватывали реальный запрос и Failproof AI Observability мог их связать:

```python
import anthropic
import agenteye

agenteye.configure(environment="production")
client = anthropic.Anthropic()

messages = [{"role": "user", "content": "Summarise today's incidents."}]

agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6",
    messages=messages,
)

reply = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=512,
    messages=messages,
)

agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model=reply.model,
    stop_reason=reply.stop_reason,
    input_tokens=reply.usage.input_tokens,
    output_tokens=reply.usage.output_tokens,
    content=[block.model_dump() for block in reply.content],
)
```

Обёртывайте вызовы инструментов так же с `tool_use` и `tool_result`, переиспользуя один `tool_call_id` в паре.

Вот как выглядят эти события, когда они попадают в панель, раскрашенные по типам и фильтруемые по окружению, агенту и сессии:

## configure()

```python
agenteye.configure(
    base_dir=None,           # Path | str | None. Default: $AGENTEYE_HOME или ~/.agenteye
    flush_interval=0.5,      # float, секунды между циклами промывки
    environment=None,        # str | None. Метка окружения развёртывания
)
```

Вызовите один раз перед любым вызовом `event.*`. Безопасно опустить; значения по умолчанию работают из коробки. Все аргументы только по ключевому слову; передавайте их по имени, как показано выше.

Когда `base_dir` равно `None` (по умолчанию), SDK читает `$AGENTEYE_HOME`, если установлена,
в противном случае откатывается на `~/.agenteye`. Это соответствует собственному разрешению сборщика,
поэтому одна переменная окружения `AGENTEYE_HOME` конфигурирует общую очередь событий для обоих
SDK и сборщика.

## Окружение

Пометьте каждое событие окружением развёртывания (`production`, `staging`, `qa`, `canary` и т.д.). Установите один раз; SDK автоматически добавляет его к каждому событию.

**Вариант 1: через `configure()`:**

```python
agenteye.configure(environment="production")
```

**Вариант 2: через переменную окружения:**

```bash
export AGENTEYE_ENVIRONMENT=production
```

**Приоритет:** `configure(environment=...)` выигрывает над переменной окружения. Если ни то, ни другое не установлено, по умолчанию `"dev"`.

Значение окружения появляется как фильтр первого класса в панели и хранится на сервере для быстрых запросов.

> **Предупреждение:** Значения окружения не должны содержать литеральную запятую `,`. Фильтры панели используют мультиселект, разделённый запятыми, по проводу (`?environment=prod,staging`), поэтому окружение с именем `prod,blue` будет разделено на два значения. События с окружениями, содержащими запятые, отклоняются во время приёма.

## Данные и конфиденциальность

SDK записывает только поля, которые вы явно передаёте. Подсказки, сообщения, входы и выходы инструментов, и содержимое модели захватываются только потому, что вы передаёте их вызову `event.*`. Ничего не читается из вашего процесса и не захватывается неявно. Любое поле, которое вы оставили не установленным, полностью опускается из события; оно не пишется на диск.

Это делает редакцию вашим выбором и вашей ответственностью. Если подсказка или полезная нагрузка инструмента содержит PII или секреты, которые вы не хотели бы хранить, удалите или замаскируйте это перед передачей методу события.

## Справочник событий

Большинство событий идут парами начало/конец, которые делят идентификатор корреляции: `tool_use` и `tool_result` делят `tool_call_id`, `hook_triggered` и `hook_completed` делят `hook_id`, и `human_wait` и `human_input` делят `input_id`. Выпустите событие начала, сделайте работу, затем выпустите событие конца с тем же ID. Failproof AI Observability соответствует паре и вычисляет `duration_ms` для вас, поэтому вы никогда не передаёте `duration_ms` сами.

![График выполнения в стиле git сессии рядом с её временной шкалой событий, восстановленный из парных событий, с панелью разбивки по инструментам/моделям/хукам](/agenteye/images/session-detail.png)

Все методы событий требуют эти два поля:

| Поле | Тип | Описание |
|---|---|---|
| `session_id` | `str` | Идентифицирует запуск агента верхнего уровня |
| `agent_id` | `str` | Идентифицирует, какой агент в сессии выпустил событие |

Все методы также принимают произвольные `**kwargs` для пользовательских метаданных (см. [Пользовательские поля](#пользовательские-поля)).

---

### `event.agent_start()`

Выпускается, когда агент начинает работу.

```python
agenteye.event.agent_start(
    session_id="run-001",
    agent_id="planner",
    goal="answer user query",   # str | None
    parent_id=None,             # str | None - parent_id агента для вложенных агентов
)
```

---

### `event.agent_end()`

Выпускается, когда агент завершает работу.

```python
agenteye.event.agent_end(
    session_id="run-001",
    agent_id="planner",
    outcome="success",          # str | None
    summary="Answered query",   # str | None
)
```

---

### `event.tool_use()`

Выпускается, когда агент вызывает инструмент. Пара с `tool_result`; SDK автоматически вычисляет `duration_ms`.

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",     # str, обязательный
    tool_call_id="toolu_01",    # str, обязательный - ключ корреляции для соответствующего tool_result
    input={"query": "..."},     # dict | None
)
```

---

### `event.tool_result()`

Выпускается, когда инструмент возвращает результат. Коррелирует с `tool_use` через `tool_call_id`.

```python
agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",        # должно соответствовать предыдущему tool_use
    output={"results": ["..."]},    # Any | None
    error=None,                     # str | None - установите, если инструмент выбросил исключение
    # duration_ms вычисляется автоматически - не передавайте его
)
```

---

### `event.model_request()`

Выпускается непосредственно перед отправкой подсказки в LLM.

```python
agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - любая строка поставщика/модели; не валидируется
    messages=[                   # list[dict] | None - ходы разговора
        {"role": "user", "content": "..."},
    ],
    system="You are helpful.",   # Any | None - str или список блоков содержимого
    tools=[                      # list[dict] | None - схемы инструментов, предложенные модели
        {"name": "search", "input_schema": {"type": "object"}},
    ],
)
```

Записи `messages` принимают либо простое содержимое строки `content`, либо содержимое в стиле Anthropic со списком блоков `content`. Параметры семпла (`temperature`, `max_tokens` и т.д.) могут быть переданы как дополнительные kwargs.

---

### `event.model_response()`

Выпускается, когда LLM возвращает ответ.

```python
agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - любая строка поставщика/модели; не валидируется
    stop_reason="end_turn",     # str | None
    input_tokens=1024,          # int | None
    output_tokens=256,          # int | None
    content=[                    # Any | None - str или список блоков содержимого
        {"type": "text", "text": "..."},
    ],
    role="assistant",            # str | None
)
```

`content` принимает либо простую строку (универсальные поставщики), либо список блоков содержимого в стиле Anthropic. Вызовы инструментов находятся внутри `content` как блоки `{"type": "tool_use", ...}`, без отдельного поля `tool_calls`.

---

### `event.hook_triggered()`

Выпускается, когда хук срабатывает. Пара с `hook_completed`; SDK автоматически вычисляет `duration_ms`.

```python
agenteye.event.hook_triggered(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",   # str, обязательный
    hook_id="hook-abc",         # str, обязательный - ключ корреляции
    trigger_event="tool_use",   # str | None
    input={"tool": "search"},   # Any | None
)
```

---

### `event.hook_completed()`

Выпускается, когда хук завершает работу. Коррелирует с `hook_triggered` через `hook_id`.

```python
agenteye.event.hook_completed(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",
    hook_id="hook-abc",         # должно соответствовать предыдущему hook_triggered
    outcome="allow",            # str | None
    output=None,                # Any | None
    error=None,                 # str | None
    # duration_ms вычисляется автоматически - не передавайте его
)
```

---

### `event.error()`

Выпускается, когда происходит необработанная ошибка.

```python
agenteye.event.error(
    session_id="run-001",
    agent_id="planner",
    error_type="TimeoutError",  # str, обязательный
    message="timed out",        # str, обязательный
    traceback="Traceback...",   # str | None
)
```

## События человека в цикле

События человека в цикле дают вам надзор над моментами, когда человек вмешивается в выполнение агента (ожидание одобрения, предоставление входных данных, пауза или остановка агента). Они позволяют вам измерять, как долго люди отвечают (SDK автоматически вычисляет `duration_ms` на парных событиях), аудировать, кто приостановил или прервал агента, и создавать рабочие процессы одобрения и надзора, которые отображаются в панели.

### `event.human_wait()`

Выпускается, когда агент приостанавливает выполнение, чтобы дождаться, пока человек предоставит входные данные. Пара с `human_input`; SDK автоматически вычисляет `duration_ms` (как долго человек ждал ответа).

```python
agenteye.event.human_wait(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",                          # str, обязательный - ключ корреляции для соответствующего human_input
    prompt="Do you approve this action?",        # str | None - вопрос, показанный человеку
    options=["approve", "reject", "defer"],      # list[str] | None - выборы, представленные человеку
    reason="approval_required",                  # str | None - почему агент ждёт
)
```

### `event.human_input()`

Выпускается, когда человек предоставляет входные данные и агент возобновляет работу. Коррелирует с `human_wait` через `input_id`. `duration_ms` вычисляется автоматически и не должна передаваться вызывающей стороной.

```python
agenteye.event.human_input(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",    # str, обязательный - должно соответствовать предыдущему human_wait
    response="approve",    # str | None - ответ человека (свободный текст или выбранная опция)
    # duration_ms вычисляется автоматически - не передавайте его
)
```

### `event.human_pause()`

Выпускается, когда человек активно приостанавливает агента (например, через управление панели). Агент приостановлен, но не завершён.

```python
agenteye.event.human_pause(
    session_id="run-001",
    agent_id="planner",
    reason="user_requested",  # str | None
    user_id="usr_42",         # str | None - кто приостановил агента
)
```

### `event.human_interrupt()`

Выпускается, когда человек активно останавливает агента во время выполнения. В отличие от `human_pause`, работа агента завершается, а не приостанавливается.

```python
agenteye.event.human_interrupt(
    session_id="run-001",
    agent_id="planner",
    reason="output_incorrect",       # str | None
    user_id="usr_42",                # str | None - кто прервал агента
    at_step="tool_use:web_search",   # str | None - что делал агент при остановке
)
```

## Пользовательские поля

Любые дополнительные аргументы ключевого слова добавляются к событию после стандартных полей:

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="db_query",
    tool_call_id="toolu_02",
    tenant_id="acme",           # пользовательское поле
    region="us-east-1",         # пользовательское поле
)
```

`timestamp`, `type` и `environment` зарезервированы и вызывают `ValueError` (`Reserved field names cannot be used as custom fields: [...]`), если переданы как пользовательские поля. `session_id` и `agent_id` — обязательные параметры на каждом методе события и не могут быть переданы во второй раз; Python вызывает `TypeError`, если вы это сделаете. Установите окружение с помощью `configure(environment=...)` (или переменной `AGENTEYE_ENVIRONMENT`) вместо этого.

Держите полезные нагрузки в виде структурированного JSON, когда хотите запрашивать их поля. Значения, которые JSON не поддерживает изначально—такие как datetime, UUID, decimal, sets, bytes или объекты моделей—преобразуются в строки, чтобы запись продолжалась безопасно.

## Как записываются события

События буферизуются в процессе и промываются на диск каждые `flush_interval` секунд (по умолчанию 500 мс). Каждая промывка пишет один JSONL файл:

```text
~/.agenteye/events/event-2026-04-01T12-00-00-000Z.jsonl
```

Сборщик следит за этим каталогом и загружает файлы автоматически. Вам не нужно управлять этими файлами напрямую.

Каждый файл пишется атомарно: SDK пишет во временный файл, а затем переименовывает его на место, поэтому сборщик никогда не видит половину написанного файла. Финальная промывка также выполняется при выходе вашего процесса, поэтому события, буферизованные в последний интервал, не теряются. Если сборщик в автономном режиме, события просто накапливаются как файлы на диске и отправляются, когда он возвращается в сеть.
