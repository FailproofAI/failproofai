Контекст агента告говорит аудитам, для чего существует каждый агент, что он должен производить и что он никогда не должен делать. Failproof AI хранит этот контекст как один контракт агента на агента.

Контекст агента принадлежит организации, а не одному аудиту. Вы пишете его один раз на агента, и каждый аудит на основе модели, область действия которого включает этого агента, его использует.

## Добавить контекст агента

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Analyze → audits**, выберите **agents** и выберите идентификатор агента, указанный в его сеансах.
    2. Выберите **add content** или **edit**.
    3. Опишите, для чего нужен агент, что он должен производить, что означает готовность, как часто он должен работать и что он никогда не должен делать.
    4. Сохраните контекст, затем вернитесь к форме аудита и подтвердите, что выбранный агент отображается как покрытый.

    ![Ящик Agents аудита, используемый для добавления назначения, периода выполнения, выходных данных, условий завершения и запрещённого поведения для агента.](/images/dashboard/agent-context.png)

    Вы также можете добавить или отредактировать контекст агента из ящика **agents** при создании или редактировании аудита. Он сохраняется независимо и сразу же доступен для каждого применимого аудита.
  </Tab>
  <Tab title="CLI">
    Cloud CLI ещё не предоставляет команды контракта. Используйте публичный API с ключом, имеющим `audits:read` и `audits:write`:

    ```bash
    curl -X POST "https://app.befailproof.ai/v1/audits/contracts" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "agent_id": "nightly-reconciler",
        "enabled": true,
        "body": "# Purpose\nReconcile yesterday'\''s payouts.\n\n## Outputs\nPublish a signed summary.\n\n## Must not\nNever modify ledger entries."
      }'
    ```

    Получите список контрактов с `GET /v1/audits/contracts`; получите один контракт с `GET /v1/audits/contracts/{id}`. Обновление с помощью `PUT` полностью заменяет содержимое и требует как `agent_id`, так и `body`.
  </Tab>
</Tabs>

## Напишите полезный контекст

Держите контекст под 5000 символов и сделайте его проверяемым. Полезный контекст обычно содержит:

- **Purpose:** почему существует агент
- **Outputs:** артефакты или действия, которые он должен производить
- **Done when:** условие, которое делает запуск успешным
- **Cadence:** как часто или когда он должен работать
- **Must not:** действия и результаты, которые всегда неприемлемы

```markdown
---
agent: nightly-reconciler
purpose: Reconcile yesterday's payouts and publish a signed summary.
cadence: Once daily after 02:00 UTC. Never more than once.
---

## Outputs
- A signed reconciliation summary in the finance channel.

## Done when
- Every payout is matched or explicitly flagged.

## Must not
- Modify ledger entries. Report discrepancies instead.
```

Контекст агента определяет ожидаемое поведение; он не может сказать анализу, к какому выводу прийти, или ограничить, какие доказательства он должен изучать. Агенты без контекста аудируются нормально, но Failproof AI не может судить об их поведении по организационному намерению.

## Приостановить или изменить контекст агента

- Приостановите контекст агента, когда аудиты должны его временно игнорировать. Приостановка обратима.
- Отредактируйте контекст, когда ответственность агента меняется. Новый текст применяется к будущим запускам.
- Проверьте **last matched**, когда запущенный агент никогда не использует свой контекст. Это обычно означает, что его идентификатор агента не совпадает с телеметрией.
- Удаляйте через API только когда текст должен быть навсегда уничтожен. Панель управления намеренно предлагает приостановку вместо удаления.

Каждый запуск аудита сохраняет точный снимок контекста агента, который он использовал. Редактирование, приостановка или удаление текущего ресурса контракта не переписывает основание предыдущих выводов.

<Info>
  Чтение контрактов требует `audits:read`. Создание, редактирование, приостановка или удаление требуют `audits:write`.
</Info>
