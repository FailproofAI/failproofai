Используйте периодические аудиты для сценариев отказа, которые могут повторяться по мере изменения агентов, подсказок, инструментов и моделей.

## Измените расписание

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Analyze → Audits** и откройте аудит.
    2. Откройте его параметры и измените состояние включения, интервал, якорь UTC, режим окна или lookback.
    3. Сохраните аудит и подтвердите время следующего запуска на карточке аудита.
    4. Используйте **run now** один раз после крупного изменения области или контекста.

    ![Редактор аудита, показывающий кадентность, окно развёртки, область, параметры анализа, контекст и каналы уведомлений.](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    См. справку [`fp audits`](/ru/reference/cloud-cli#audits) для границ расписания, поведения окна и всех команд аудита.
  </Tab>
</Tabs>

Выберите кадентность в зависимости от скорости и стоимости риска:

| Паттерн риска | Начальная частота |
| --- | --- |
| Высокоприоритетное действие в production | Ежедневно |
| Регрессия рабочего процесса или модели | Еженедельно |
| Проверка управления или доступа | Ежемесячно |
| Разовое исследование при выпуске | Запустить один раз |

Выровняйте окно lookback с кадентностью, чтобы запуски не оставляли пробелов и не проверяли повторно ненужно большую совокупность данных. После изменения цели или контекста аудита запустите его вручную один раз перед тем, как полагаться на следующий запланированный результат.

<Note>
  Локальные запланированные аудиты настраиваются на машине и сканируют локальную историю агента. Расписания облачных аудитов работают с облачными сеансами. Рассматривайте их результаты и владение отдельно.
</Note>
