Аудит ищет указанные сбои в выбранном наборе сеансов. Он объединяет данные трассировки, результаты оценок, срабатывания политик и справочный контекст, чтобы выявить проблемы, которые вы сможете устранить.

Посмотрите, как аудит переходит от планового запуска к подтвержденным данными сбоям, которые вы можете исправить.

## Открытие аудитов

<Tabs>
  <Tab title="Dashboard">
    Перейдите на **Analyze → Audits**. На странице отображаются статус расписания, открытые выводы, время последнего запуска, время следующего запуска, частота повторения и наличие страниц краткой сводки или справки. Выберите карту для просмотра настроек и истории запусков; выберите **new audit** для создания нового аудита.

    ![Страница Audits с повторяющимися аудитами, их расписанием, чувствительностью и статусом запуска.](/images/dashboard/audits.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

Используйте аудит, когда вам нужно ответить на вопрос уровня совокупности, например:

- Где агенты прекращают задачи без эскалации?
- Какие сбои инструментов приводят к неэффективным повторным попыткам?
- Обращаются ли агенты к данным за пределами предполагаемого рабочего процесса?
- Что изменилось после выпуска модели, подсказки или инструмента?

## Поток ответа аудита

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert for recurrence
```

Вывод должен назвать режим сбоя и указать на доказательства. Проблема отвечает за исправление. Политика предотвращает известный паттерн действий; оповещение выявляет повторение, когда профилактика невозможна или требует мониторинга.
