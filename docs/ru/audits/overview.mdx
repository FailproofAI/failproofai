Аудит проверяет выбранный набор сессий на предмет конкретной цели поиска сбоев. Он объединяет данные трассировки, результаты оценки, срабатывания политик и справочный контекст для создания выводов, на которые вы можете действовать.

Посмотрите, как аудит переходит от запланированного запуска к подтвержденным фактами сбоям, которые вы можете исправить.

## Открыть аудиты

<Tabs>
  <Tab title="Dashboard">
    Перейдите в **Analyze → Audits**. На странице отображается состояние расписания, открытые выводы, последний запуск, следующий запуск, периодичность и наличие у аудита страниц с описанием или справочной информацией. Выберите карточку для просмотра параметров и истории запусков; выберите **new audit**, чтобы создать новый аудит.

    ![Страница Audits с повторяющимися аудитами, их расписанием, чувствительностью и состоянием выполнения.](/images/dashboard/audits.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

Используйте аудит, когда нужно ответить на вопрос уровня совокупности, например:

- Где агенты отказывают от задач без эскалации?
- Какие сбои инструментов приводят к неэффективным повторным попыткам?
- Обращаются ли агенты к данным вне предусмотренного рабочего процесса?
- Что изменилось после выпуска модели, подсказки или инструмента?

## Процесс ответа на аудит

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert for recurrence
```

Вывод должен назвать режим сбоя и указать на доказательство. Проблема отвечает за исправление. Политика предотвращает известный паттерн действий; оповещение обнаруживает повторение, когда предотвращение невозможно или требует мониторинга.
