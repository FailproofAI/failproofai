## Локально или в облаке

| | Локальная проверка | Облачная проверка |
| --- | --- | --- |
| Команда | `failproofai audit` | `fp audits` |
| Читает | История агента на этом устройстве | Сеансы в вашей облачной организации |
| Создает | Локальные результаты по адресу `localhost:8020/audit` | Общие выводы, проблемы и оповещения |
| Требует | Без учетной записи | Подключение к облаку и API ключ |

Используйте локальную проверку для быстрого просмотра одного устройства. Используйте облако, когда команде нужна повторяющаяся проверка нескольких агентов и устройств.

## На какие вопросы может ответить проверка

- Где агенты останавливаются без эскалации?
- Какие сбои инструментов приводят к неэффективным повторным попыткам?
- Обращаются ли агенты к данным вне предусмотренного рабочего процесса?
- Что изменилось после обновления модели, промпта или инструмента?

## Открыть облачные проверки

Перейдите в **Analyze → Audits** или используйте:

```bash
fp audits list
fp audits show <audit-name>
fp audits findings --status open --limit 20
```

Команды проверки используют имя проверки или полный ID. Выводы ссылаются по собственному ID.

## От вывода к предотвращению

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert
```

Вывод указывает на доказательство. Проблема отвечает за ответ. Политика предотвращает известный паттерн действий; оповещение отслеживает повторение.

Не каждый вывод должен стать политикой. Вывод типа `policy` описывает правило, которое можно применить. `failure` или `improvement` может потребовать изменения рабочего процесса, промпта, модели или инструмента.
