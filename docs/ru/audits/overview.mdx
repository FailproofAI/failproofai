Аудит ищет отказы в выбранном наборе сессий в соответствии с указанной целью. Он объединяет доказательства из трассировок, результаты оценки, срабатывания политик и справочный контекст для получения выводов, которые можно исправить.

## Открытие аудитов

<Tabs>
  <Tab title="Dashboard">
    Перейдите в **Analyze → Audits**. Страница отображает запланированное состояние, открытые выводы, последний запуск, следующий запуск, периодичность и наличие страниц краткого обзора или справочной информации для аудита. Выберите карточку для просмотра параметров и истории запусков; выберите **new audit** для создания нового.

    ![Страница Audits, показывающая повторяющиеся аудиты с их расписанием, чувствительностью и состоянием запуска.](/images/dashboard/audits.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

Используйте аудит, когда нужно ответить на вопросы уровня совокупности, такие как:

- Где агенты отказываются от задач без эскалации?
- Какие отказы инструментов приводят к неэффективным повторным попыткам?
- Получают ли агенты доступ к данным вне предполагаемого рабочего процесса?
- Что изменилось после выпуска модели, подсказки или инструмента?

## Поток ответа на аудит

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert for recurrence
```

Вывод должен назвать режим отказа и указать на доказательства. Проблема (issue) отвечает за исправление. Политика предотвращает известный паттерн действий; оповещение обнаруживает повторение, когда предотвращение невозможно или требует мониторинга.
