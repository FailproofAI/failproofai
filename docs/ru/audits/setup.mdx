Качество аудита начинается с его области применения. Общий запрос типа "найти проблемы" дает менее полезные результаты, чем конкретный вопрос об отказе.

## Настройка аудита

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Analyze → Audits → New audit** и введите имя и описание.
    2. Установите периодичность, временное окно, область агентов/окружений, игнорируемые ошибки, чувствительность и максимальное количество найденных проблем.
    3. В разделе **agents** добавьте или просмотрите контекст агента, затем добавьте краткое описание оператора и любые общедоступные HTTPS ссылки для справки.
    4. Выберите каналы уведомлений и нажмите **create audit**. Первый запуск ставится в очередь немедленно.

    ![Форма создания нового аудита с именем, описанием, периодичностью, окном, областью окружения и агентов, игнорируемыми ошибками, параметрами анализа, кратким описанием, справочными страницами и каналами уведомлений.](/images/dashboard/audit-new.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits create checkout-reliability \
      --description "Find checkout failures that agents do not recover from" \
      --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
      --schedule-interval-secs 86400 \
      --window-mode since_last \
      --sensitivity medium \
      --text-file ./checkout-audit-brief.txt \
      --url https://runbooks.example.com/checkout
    ```

    Первый запуск ставится в очередь немедленно. Включите краткое описание и справочные URL-адреса во время создания, чтобы запуск их получил.

    См. полный справочник [`fp audits create`](/ru/reference/cloud-cli#audits).
  </Tab>
</Tabs>

<Tip>
  Начните с известной неудачной сессии и нескольких обычных сессий. Это дает аудиту как положительный пример, так и набор для сравнения.
</Tip>

<Info>
  Контекст аудита хранится как отдельный ресурс, поэтому редактирование аудита не приведет к случайному удалению справочного материала.
</Info>
