failproofai поставляется с 39 встроенными политиками, которые перехватывают распространённые режимы отказа агентов. Каждая политика срабатывает на определённом типе события hook и имени инструмента. Девятнадцать политик принимают параметры, которые позволяют настраивать их поведение без написания кода. Пять политик рабочего процесса требуют выполнения конвейера commit → push → PR → CI, прежде чем Claude сможет остановиться.

---

## Обзор

Политики организованы по категориям:

| Категория | Политики | Тип hook |
|----------|----------|-----------|
| [Опасные команды](#опасные-команды) | block-sudo, block-rm-rf, block-curl-pipe-sh, block-failproofai-commands, block-self-pause | PreToolUse |
| [Команды инфраструктуры](#команды-инфраструктуры) | block-kubectl, block-terraform, block-aws-cli, block-gcloud, block-az-cli, block-helm, block-gh-pipeline | PreToolUse |
| [Секреты (санитайзеры)](#секреты-санитайзеры) | sanitize-jwt, sanitize-api-keys, sanitize-connection-strings, sanitize-private-key-content, sanitize-bearer-tokens | PostToolUse |
| [Окружение](#окружение) | block-env-files, protect-env-vars | PreToolUse |
| [Доступ к файлам](#доступ-к-файлам) | block-read-outside-cwd, block-secrets-write | PreToolUse |
| [Git](#git) | block-push-master, block-work-on-main, block-force-push, warn-git-amend, warn-git-stash-drop, warn-all-files-staged | PreToolUse |
| [База данных](#база-данных) | warn-destructive-sql, warn-schema-alteration | PreToolUse |
| [Предупреждения](#предупреждения) | warn-large-file-write, warn-package-publish, warn-background-process, warn-global-package-install | PreToolUse |
| [Менеджеры пакетов](#менеджеры-пакетов) | prefer-package-manager | PreToolUse |
| [Рабочий процесс](#рабочий-процесс) | require-commit-before-stop, require-push-before-stop, require-pr-before-stop, require-no-conflicts-before-stop, require-ci-green-before-stop | Stop |

- **`block-`** — остановить агента от продолжения выполнения.
- **`warn-`** — дать агенту дополнительный контекст, чтобы он мог исправиться самостоятельно.
- **`sanitize-`** — удалить чувствительные данные из вывода инструмента, прежде чем агент их увидит.

### Пространства имён

Каждая политика находится в слоте `<namespace>/<name>`. Встроенные политики принадлежат пространству имён **`failproofai/`** — например, `failproofai/sanitize-jwt`. Пространство имён предотвращает конфликты при загрузке пользовательских или сторонних политик с похожими короткими названиями.

В вашей конфигурации вы можете обращаться к встроенной политике либо по короткому названию, либо по полному имени; обе формы разрешаются в одну политику:

```json
{
  "enabledPolicies": [
    "sanitize-jwt",
    "failproofai/block-rm-rf"
  ]
}
```

Если имя не содержит `/`, failproofai рассматривает его как принадлежащее пространству имён по умолчанию `failproofai`. Имена, уже содержащие `/` (например `myorg/foo`, `custom/my-hook`), остаются без изменений.
- **`require-`** — заблокировать событие Stop до выполнения условий.

---

<Tip>
Каждая политика поддерживает опциональное поле `hint` в `policyParams`. Подсказка добавляется к сообщению deny или instruct, которое видит Claude, давая практическое руководство без изменения кода политики. Работает со встроенными, пользовательскими и конвенционными политиками. См. [Конфигурация → hint](/ru/configuration#hint-cross-cutting) для деталей.
</Tip>

## Опасные команды

Предотвратите агентам выполнение операций, которые сложно отменить или которые могут повредить хост-систему.

### `block-sudo`

**Событие:** PreToolUse (Bash)  
**По умолчанию:** Отклоняет любую команду `sudo` или `doas`.

Блокирует команду, которая запускает двоичный файл повышения прав **в позиции команды**. Сопоставление является структурным, а не текстовым: команда разбивается на сегменты так, как это делала бы оболочка, удаляются назначения префиксов (`FOO=bar`), перенаправления и средства запуска с их флагами (`env`, `nohup`, `timeout`, `xargs`, `sh -c`, …), а результирующий двоичный файл сравнивается по **basename**. Таким образом, `/usr/bin/sudo`, `env sudo`, `timeout 5 sudo`, `"sudo"`, `\sudo` и `bash -c "sudo …"` все отклоняются, а `doas` рассматривается как та же возможность под другим названием.

Поскольку он привязан к позиции команды, а не к появлению слова в любом месте, он **не** срабатывает на команды, которые просто его упоминают — `grep -r sudo /etc`, `cat /etc/sudoers`, `git commit -m "fix sudo handling"` или чередование `grep`, содержащее это слово, работают нормально.

<Warning>
Это останавливает очевидную попытку; это не закрывает класс. Агент, который может запускать произвольную оболочку, всё ещё может достичь повышения прав косвенно — через переменную (`S=sudo; $S …`), канал с base64-декодированием или скрипт-обёртку на диске — поскольку никакая проверка одной строки команды не может следить за ними. Рассматривайте это как страховку от ошибок и случайного повышения прав, а не как границу безопасности против решительного агента. Реальная граница должна быть обеспечена ниже уровня оболочки.
</Warning>

**Параметры:**

| Параметр | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | Точные префиксы команд, которые разрешены. Каждая запись сопоставляется с распарсенными токенами argv. |

**Пример:**

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    }
  }
}
```

С этой конфигурацией `sudo systemctl status nginx` разрешена, но `sudo rm /etc/hosts` отклонена.

<Note>
Шаблоны сопоставляются с распарсенными токенами, а не с исходной строкой команды. Это предотвращает обход через добавленные операторы оболочки (например, `sudo systemctl status x; rm -rf /` не соответствует `sudo systemctl status *`).
</Note>

### `block-self-pause`

**Событие:** PreToolUse (Bash)  
**По умолчанию:** Отклоняет `failproofai config --pause`, что приостанавливает применение политик на сеанс. Паузирование — это решение человека — агент, способный это запустить, мог бы отключить все остальные политики одной командой.

Более узкая, чем [`block-failproofai-commands`](#block-failproofai-commands) намеренно, и не охватываемая ею: эта политика привязана к границе команды, поэтому `npx -y failproofai config --pause` не соответствует ей, и поскольку она широкая, часто отключается, чтобы агенты могли запускать `failproofai audit`. `--resume` и `--status` разрешены — ни один из них не удаляет применение политик.

Это останавливает прямую попытку, а не весь класс: агент всё ещё может достичь того же состояния через псевдоним или скрипт-обёртку. Полное закрытие требует, чтобы пауза была вообще недостижима из вызова инструмента.

Нет параметров.

## Команды инфраструктуры

Остановите кодирующих агентов от запуска инфраструктурных CLI или инициирования конвейеров CI/CD. Все политики в этой категории **opt-in** (`defaultEnabled: false`) — агенты, которым действительно нужно вызывать `kubectl`, `terraform` и т.д., не будут прерваны, если только вы не включите политику. При включении каждый вызов сопоставленного CLI отклоняется, если команда не соответствует записи в `allowPatterns`.

Грамматика шаблонов такая же, как в [`block-sudo`](#block-sudo): токены сопоставляются с распарсенными argv, `*` — это подстановочный символ для одного токена, и любая команда, содержащая самостоятельный оператор оболочки (`&&`, `||`, `|`, `;`) или токен с встроенными метасимволами оболочки, отклоняется перед сопоставлением списка разрешённых для предотвращения обхода через инъекцию.

### `block-kubectl`

**Событие:** PreToolUse (Bash)  
**По умолчанию:** Отклоняет любой вызов `kubectl`.

**Параметры:**

| Параметр | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | Префиксы команд kubectl, которые разрешены. |

**Пример:**

```json
{
  "policyParams": {
    "block-kubectl": {
      "allowPatterns": ["kubectl get *", "kubectl describe *", "kubectl logs *"]
    }
  }
}
```

С этой конфигурацией `kubectl get pods` разрешена, но `kubectl apply -f deploy.yaml` отклонена.

### `block-gh-pipeline`

**Событие:** PreToolUse (Bash)  
**По умолчанию:** Отклоняет следующие подкоманды `gh` CLI, которые изменяют состояние или инициируют конвейеры:

- `gh workflow run`, `gh workflow enable`, `gh workflow disable`
- `gh run rerun`, `gh run cancel`
- `gh pr merge`
- `gh release create`, `gh release delete`
- `gh cache delete`
- `gh secret set`, `gh secret delete`

Подкоманды `gh`, предназначенные только для чтения, такие как `gh pr view`, `gh pr list`, `gh run list`, `gh release view` и `gh api repos/.../...` **не** сопоставляются с этой политикой — они обычно нужны для проверок рабочего процесса (включая собственные проверки failproofai `require-ci-green-before-stop`).

**Параметры:**

| Параметр | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | Специфические скриптовые вызовы, которые нужно разрешить, даже если они были бы отклонены. |

**Пример:**

```json
{
  "policyParams": {
    "block-gh-pipeline": {
      "allowPatterns": ["gh run rerun *"]
    }
  }
}
```

## Секреты (санитайзеры)

Остановите агентов от утечки учётных данных в их контекст или вывод. Политики-санитайзеры срабатывают на событиях **PostToolUse**. Когда Claude запускает команду Bash, читает файл или вызывает любой инструмент, эти политики проверяют вывод перед его возвратом Claude. Если обнаружен паттерн секрета, политика возвращает решение deny, которое предотвращает возврат вывода.

### `sanitize-jwt`

**Событие:** PostToolUse (все инструменты)  
**По умолчанию:** Скрывает JWT-токены (три сегмента base64url, разделённые `.`).

Нет параметров.

---

### `sanitize-api-keys`

**Событие:** PostToolUse (все инструменты)  
**По умолчанию:** Скрывает распространённые форматы ключей API: Anthropic (`sk-ant-`), OpenAI (`sk-`), GitHub PATs (`ghp_`), AWS ключи доступа (`AKIA`), Stripe ключи (`sk_live_`, `sk_test_`), и ключи Google API (`AIza`).

**Параметры:**

| Параметр | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `additionalPatterns` | `{ regex: string; label: string }[]` | `[]` | Дополнительные регулярные выражения для рассмотрения как секреты. |

**Пример:**

```json
{
  "policyParams": {
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo internal API key" },
        { "regex": "pat_[0-9a-f]{40}", "label": "Internal PAT" }
      ]
    }
  }
}
```

---

### `sanitize-connection-strings`

**Событие:** PostToolUse (все инструменты)  
**По умолчанию:** Скрывает строки подключения к базе данных, которые содержат встроенные учётные данные (например `postgresql://user:password@host/db`).

Нет параметров.

---

### `sanitize-private-key-content`

**Событие:** PostToolUse (все инструменты)  
**По умолчанию:** Скрывает блоки PEM (`-----BEGIN PRIVATE KEY-----`, `-----BEGIN RSA PRIVATE KEY-----` и т.д.).

Нет параметров.

---

### `sanitize-bearer-tokens`

**Событие:** PostToolUse (все инструменты)  
**По умолчанию:** Скрывает заголовки `Authorization: Bearer <token>`, где токен имеет 20 или более символов.

Нет параметров.

## Окружение

Защитите чувствительную конфигурацию окружения от чтения или раскрытия агентами.

Не блокирует `.envrc` или другие файлы, смежные с окружением — только файлы с именем ровно `.env`.

**По умолчанию:** Отклоняет команды, которые выводят переменные окружения: `printenv`, `env`, `echo $VAR`.

## Доступ к файлам

Держите агентов в рамках границ проекта и вдали от чувствительных файлов.

### `block-read-outside-cwd`

**Событие:** PreToolUse (Read, Bash)  
**По умолчанию:** Отклоняет чтение файлов вне корня проекта. Граница — `CLAUDE_PROJECT_DIR` (устанавливаемая один раз за сеанс Claude Code), с откатом на текущий рабочий каталог сеанса, когда эта переменная не установлена. Использование корня проекта вместо активного `cwd` означает, что граница остаётся стабильной даже после того, как Claude перейдёт в подкаталог.

**Параметры:**

| Параметр | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `allowPaths` | `string[]` | `[]` | Префиксы абсолютных путей, которые разрешены, даже если находятся вне корня проекта. |

**Пример:**

```json
{
  "policyParams": {
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company/config"]
    }
  }
}
```

---

### `block-secrets-write`

**Событие:** PreToolUse (Write, Edit)  
**По умолчанию:** Отклоняет записи в файлы, обычно используемые для приватных ключей и сертификатов: `id_rsa`, `id_ed25519`, `*.key`, `*.pem`, `*.p12`, `*.pfx`.

**Параметры:**

| Параметр | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `additionalPatterns` | `string[]` | `[]` | Дополнительные шаблоны имён файлов (glob-стиль) для блокировки. |

**Пример:**

```json
{
  "policyParams": {
    "block-secrets-write": {
      "additionalPatterns": [".token", ".secret"]
    }
  }
}
```

## Git

Предотвратите случайные push'и, force-push'и и ошибки ветвей, которые сложно отменить.

### `block-push-master`

**Событие:** PreToolUse (Bash)  
**По умолчанию:** Отклоняет `git push origin main` и `git push origin master`.

**Параметры:**

| Параметр | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `protectedBranches` | `string[]` | `["main", "master"]` | Имена ветвей, на которые нельзя отправлять напрямую. |

**Пример:**

```json
{
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "master", "release", "prod"]
    }
  }
}
```

<Tip>
Чтобы разрешить отправку на все ветви (эффективно отключив эту политику без удаления из `enabledPolicies`), установите `protectedBranches: []`.
</Tip>

## Менеджеры пакетов

Вынудите агента использовать разрешённые менеджеры пакетов.

### `prefer-package-manager`

**Событие:** PreToolUse (Bash)  
**По умолчанию:** Отключено. При включении блокирует любую команду менеджера пакетов, которая не в списке `allowed`, и указывает Claude переписать команду, используя разрешённый менеджер.

Обнаруживает: pip, pip3, python -m pip, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo.

| Параметр | Тип | По умолчанию | Описание |
|-----------|------|---------|-------------|
| `allowed` | string[] | `[]` | Разрешённые имена менеджеров пакетов. Любой обнаруженный менеджер, не в этом списке, блокируется. Если пусто, политика не действует. |
| `blocked` | string[] | `[]` | Дополнительные имена менеджеров для блокировки помимо встроенного списка (например `['pdm', 'pipx']`). |

Встроенный список блокировки охватывает: pip, pip3, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo. Используйте `blocked` для добавления менеджеров не в этот список.

**Пример конфигурации:**

```json
{
  "enabledPolicies": ["prefer-package-manager"],
  "policyParams": {
    "prefer-package-manager": {
      "allowed": ["uv", "bun"],
      "blocked": ["pdm", "pipx"]
    }
  }
}
```

С этой конфигурацией `pip install flask` и `pdm install flask` оба отклоняются с сообщением, указывающим Claude использовать `uv` или `bun` вместо этого. Команды типа `uv pip install flask` разрешены, потому что `uv` находится в списке разрешённых и проверяется первым.

## Рабочий процесс

Вынудите дисциплинированный рабочий процесс конца сеанса. Эти политики срабатывают на событии **Stop** и отклоняют попытку агента остановиться до выполнения каждого условия. Они следуют естественной цепи зависимостей: commit → push → PR → CI. Если политика отклоняется, более поздние политики в цепи пропускаются (отклонение прерывает).

Все политики рабочего процесса **fail-open**: если требуемый инструмент недоступен (например `gh` не установлен, нет git remote), политика разрешает с информационным сообщением, объясняющим, почему проверка была пропущена.

### Семантика Stop для каждого CLI

Применение Stop выглядит немного по-разному в шести поддерживаемых CLI, потому что каждый из них раскрывает другой контракт hook-события «агент завершил». **Результат** одинаковый — агент не может остановиться, пока врата рабочего процесса не пройдены — но **механика** отличается. Таблица ниже резюмирует; только Pi имеет видимую пользователю странность, стоящую понимания перед включением политики `require-*-before-stop`.

| CLI | Когда врата срабатывают | Что вы видите |
|---|---|---|
| Claude Code | То же самое действие агента, немедленно | Claude продолжает работу — исправляет проблему, затем пытается завершить снова. Никаких прерываний, видимых вам. |
| Codex | То же самое действие агента, немедленно | То же, как Claude. |
| GitHub Copilot CLI | То же самое действие агента, немедленно | То же, как Claude (использует `{decision:"block", reason}` канал Copilot — проверено эмпирически для Copilot CLI 1.0.41). |
| Cursor Agent | То же самое действие агента, немедленно | То же, как Claude (использует `{followup_message}` канал Cursor — ограничено `loop_limit`, по умолчанию 5 повторов). |
| OpenCode | То же самое действие агента, немедленно | То же, как Claude (использует вызов `client.session.prompt(...)` SDK OpenCode, маршрутизированный через `hookSpecificOutput.additionalContext`). |
| **Pi (pi-coding-agent)** | **Следующий ход пользователя** | **Pi видимо остаётся** когда врата срабатывают — её действие агента выходит и вы возвращаетесь к приглашению. Врата затем срабатывают следующий раз, когда вы отправляете приглашение: failproofai добавляет директиву `MANDATORY ACTION REQUIRED` в системное приглашение этого хода, инструктирующую LLM завершить шаг рабочего процесса (commit, push и т.д.) перед тем, как сделать то, о чём вы попросили. |

<Note>
**Ограничение Pi.** `AgentEndEvent` Pi (эквивалент upstream `Stop` hook'а Claude) не имеет типа Result — к моменту его срабатывания действие агента Pi уже завершилось. Pi не может быть вынуждена повторить то же действие, как это может Claude / Copilot / Cursor / OpenCode. failproofai смещает врата к событию Pi `before_agent_start` (которое срабатывает после следующего приглашения пользователя), так что проверка рабочего процесса всё ещё применяется, просто на следующем ходу, а не на текущем.

**Что это означает на практике:**

- После остановки Pi, причина отклонения захватывается в памяти, связанной с ID сеанса Pi. Самое следующее приглашение, которое вы отправляете в том же процессе Pi, её осушает: LLM видит директиву `MANDATORY ACTION REQUIRED` в верхней части своего системного приглашения, делает commit (или push / открывает PR / ждёт CI) и только затем продолжает с вашим запросом. Захваченная причина отклонения одноразовая — после осушения врата чистые.
- Врата ограничены жизненным циклом процесса Pi. Если вы `Ctrl+C` Pi или выходите между ходами, запись в памяти удаляется вместе с процессом и врата пропущены. Claude, Copilot, Cursor и OpenCode имеют ту же границу (убейте агента и врата пропущены) — Pi просто делает это более видимым, потому что агент видимо выходит перед срабатыванием врат.
- Ожидающее отклонение также очищается при `session_shutdown` по любой причине (`new` / `resume` / `fork` / `quit`), поэтому устаревшие врата от предыдущего сеанса не могут утечь в новый сеанс, запущенный в том же процессе Pi.

Если вам нужно повторение того же цикла, как у Claude, запустите ваши политики `Stop` под любым из других пяти поддерживаемых CLI. Мы отслеживаем Pi upstream для будущего типа Result на `AgentEndEvent`, который позволил бы нам закрыть этот разрыв.
</Note>

### `require-no-conflicts-before-stop`

**Событие:** Stop  
**По умолчанию:** Отклоняет остановку, когда текущая ветвь не может чисто слиться в базовую ветвь. Политика сначала подтверждает наличие `OPEN` PR на GitHub для ветви — без одного, нет цели слияния для применения, поэтому вся политика переключается в открытый режим и разрешает. Когда `OPEN` PR подтверждён, запускаются два независимых зонда:

1. **Local** — `git merge-tree --write-tree --name-only origin/<baseBranch> HEAD`. При конфликте сообщение отклонения называет конфликтующие файлы, так что Claude точно знает, что разрешить.
2. **GitHub** — переиспользует результат `gh pr view --json mergeable,state`, уже полученный в предварительной проверке. Перехватывает конфликты, которые устаревший локальный `origin/<baseBranch>` мог бы пропустить (например, кто-то посадил конфликтующий PR на `main` с момента последней выборки). Результат `CONFLICTING` отклоняется. Результат `UNKNOWN` тоже отклоняется и инструктирует Claude ждать ~10 секунд и переподтвердить перед попыткой остановки снова — это предотвращает ложные отрицания, пока GitHub пересчитывает.

Полностью пропускает (разрешает) когда: `gh` не установлен, не существует PR для ветви, состояние PR не `OPEN` (например `MERGED`, `CLOSED`), или `gh pr view` возвращает непарсируемый вывод. Также работает в открытом режиме, когда `origin/<baseBranch>` отсутствует локально или когда нет commits впереди base — те Layer 1 проходы всё ещё консультируют кэшированную слияемость PR перед разрешением.

**Параметры:**

| Параметр | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `baseBranch` | `string` | `"main"` | Базовая ветвь для проверки конфликтов против. |

<Note>
GitHub CLI (`gh`) требуется для этой политики. Политика использует `gh pr view` для подтверждения
наличия `OPEN` PR перед запуском любого зонда конфликта — без `gh`, политика
переключается в открытый режим и разрешает. Запустите `gh auth login` с личным токеном доступа, имеющим
область `repo` для чтения доступа к pull requests.
</Note>

Удалите специфическую политику из `enabledPolicies` в вашей конфигурации или переключите её в вкладке Policies в панели управления.

```json
{
```

Политики, не указанные в `enabledPolicies`, не запускаются, даже если существуют записи `policyParams` для них.
