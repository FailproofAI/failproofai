  Каталог детекторов и формат отчета могут измениться перед следующим стабильным релизом. Пожалуйста, откройте issue, если что-то выглядит неправильно.
</Note>

Аудит теперь доступен как **страница /audit на панели управления**, а не как подкоманда CLI. Откройте его из панели навигации панели управления (между Policies и Projects) или посетите `http://localhost:8020/audit` непосредственно при запуске `failproofai` локально.

```bash
failproofai          # открыть панель управления, затем нажать "Audit"
```

Панель управления сканирует прошлые транскрипты CLI агента на этом компьютере (Claude Code, Codex, Copilot, Cursor, OpenCode, Pi, Gemini) и сообщает, как часто агент выполнял действия, которые failproofai предназначен останавливать — проверки переменных окружения, force pushes, избыточные префиксы `cd <cwd>`, polling-циклы со sleep, повторное чтение только что отредактированных файлов и многое другое.

Для каждого транскрипта каждое событие tool-use переигрывается через 39 встроенных политик **и** через 8 детекторов только для аудита, которые выявляют паттерны, еще не охватываемые политиками времени выполнения. Счетчики агрегируются по политикам / детекторам во всех сессиях.

## Что вы получите

Страница `/audit` состоит из шести разделов:

1. **Identity** — ваш агент классифицирован в один из 8 архетипов (`optimist`, `cowboy`, `explorer`, `goldfish`, `paranoid architect`, `precision builder`, `hammer`, `ghost`) на основе взвешенного сигнала по всем проверенным транскриптам.
2. **Strengths** — реальные числа из сканирования (процент чистых вызовов, "0 утечек учетных данных" и т.д.), полученные при срабатывании соответствующих политик sanitize.
3. **Score** — 0-100 с диапазонами S/A/B/C/D/F и прогнозируемым улучшением, если будет включена каждая рекомендуемая политика.
4. **Findings** — карточки по политикам с информацией о том, что произошло, затратах, собранных доказательствах и точной командой `failproofai policy add <slug>` для включения встроенной функции реального времени, которая бы это поймала.
5. **Prescribed policies** — агрегированный список установки с однострочной командой `failproofai policies --install`.
6. **Re-audit reminder** — "приходите улучшенными." Установите напоминание по электронной почте на 7 дней через api-server (требует входа; см. [`failproofai auth`](/ru/cli/auth)).

## Детекторы только для аудита

Эти детекторы выявляют паттерны "глупого поведения", которые (еще) не применяются в реальном времени. Они работают только во время аудита и никогда не блокируют живой tool call.

| Детектор | Что он подсчитывает |
|---|---|
| `redundant-cd-cwd` | Команды Bash, начинающиеся с `cd <cwd> && …`, хотя команды уже работают в `cwd`. |
| `prefer-edit-over-read-cat` | `cat`/`head`/`tail`/`less`/`more` на одном исходном файле — используйте инструмент `Read`. |
| `prefer-edit-over-sed-awk` | In-place редактирования `sed -i` / `awk … > file` — используйте инструмент `Edit`. |
| `prefer-write-over-heredoc` | Heredoc / многострочный `echo > file` для записи файлов — используйте инструмент `Write`. |
| `sleep-polling-loop` | Длительные `sleep N` (≥ 30s) или `while …; sleep …; done` polling-циклы. |
| `find-from-root` | `find /`, `find /home`, `find /usr` и т.д. — ограничьте область до `cwd`. |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, пропуск hooks. |
| `reread-after-edit` | `Read` файла, который был только что `Edit`/`Write` в той же сессии. |

## Кэши

- **Кэш для каждого транскрипта** в `~/.failproofai/cache/audit/<sha1>.json` с ключом `(mtime, size, engineVersion, detectorVersion)` — автоматически инвалидируется, когда изменяется транскрипт или код политик/детекторов. Каждая запись также хранит временную метку `cachedAt` как **TTL метаданные** (не часть ключа кэша); записи старше **7 дней** отклоняются при чтении, чтобы долгоживущие результаты не пережили эволюцию намерения детектора.
- **Кэш всего результата** в `~/.failproofai/audit-dashboard.json` (режим 0600). Позволяет панели управления отображаться мгновенно при навигации без переза​пуска. Также отклоняется при чтении после **7-дневного TTL** — `/audit` затем переходит в пустое состояние и предлагает свежий запуск. Нажмите `[ re-audit now ]` рядом с концом отчета, чтобы обновить; новый запуск выводит прогресс через липкую верхнюю полосу и заменяет результат на месте при успехе (перезагрузка страницы не требуется).

## Примечания

- **Без мутаций.** Аудит переигрывается в режиме только для чтения. `warn-repeated-tool-calls` пропускается, потому что его per-session sidecar иначе был бы изменен.
- **Политики рабочего процесса пропущены.** Политики `require-*-before-stop` срабатывают только на событиях `Stop` и `execSync` против живого состояния git — они не имеют значимой интерпретации "что бы произошло в 2025 году", поэтому они не появляются в счетчиках аудита.
- **Пользовательские политики пропущены.** Пользовательские hooks, предоставленные пользователем, не переигрываются (они могли измениться с момента исходной сессии).
