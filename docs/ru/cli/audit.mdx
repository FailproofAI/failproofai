<Note>
  **Функция на этапе бета-тестирования.** Аудит выпущен как бета-версия, пока мы собираем ранние отзывы.
  Каталог детекторов и формат отчёта могут измениться перед следующим стабильным релизом.
  Пожалуйста, откройте issue, если что-то выглядит неправильно.
</Note>

Аудит переигрывает ваши прошлые стенограммы agent-CLI через механизм политик failproofai и создаёт красивый, визуальный отчёт на **странице панели `/audit`** — архетип агента, оценка от 0 до 100 и ровно те политики, которые бы это поймали.

## Запустить

Три способа входа — все ведут на один и тот же отчёт `/audit`.

<CodeGroup>

```bash npx (без установки)
npx -y failproofai audit
```

```bash failproofai audit
failproofai audit
```

```bash failproofai (панель)
failproofai
```

</CodeGroup>

<Tip>
  Запустите `failproofai audit -h` (или `--help`) чтобы увидеть справку. Аудит работает **полностью
  офлайн** — не требует аккаунта или сети — и панель продолжает работать
  до тех пор, пока вы не остановите её с помощью `Ctrl+C`.
</Tip>

Панель сканирует прошлые стенограммы agent CLI на этой машине (Claude Code, Codex, Copilot, Cursor, OpenCode, Pi) и отчитывается, как часто агент делал вещи, которые failproofai создана чтобы остановить — проверки переменных окружения, force push, избыточные префиксы `cd <cwd>`,循环polling циклы со sleep, повторное чтение только что отредактированных файлов и многое другое.

Для каждой стенограммы каждое событие tool-use переигрывается через 39 встроенных политик **и** через 8 детекторов, доступных только при аудите, которые ловят паттерны, ещё не покрытые runtime-политиками. Счётчики агрегируются для каждой политики / детектора по всем сессиям.

## Что вы получите

Страница `/audit` — это постер на один экран, который можно поделиться, а затем четыре раздела ниже:

1. **Постер** — идентичность вашего агента с первого взгляда: его **архетип** (один из 8 — `optimist`, `cowboy`, `explorer`, `goldfish`, `paranoid architect`, `precision builder`, `hammer`, `ghost`), его ключевые слова персоны, насколько редок этот архетип, и **оценка от 0 до 100** с полосой уровня (`S` до `bottom tier`). Создан для делиться — опубликуйте на X или LinkedIn, или скачайте как PNG.
2. **`// strengths`** — что ваш агент уже делает хорошо, как реальные числа из сканирования (например, clean-tool-call %, `0` попыток push-to-main), показано только где соответствующая политика имеет чистый результат.
3. **`// quirks`** — что прошло мимо: отсортированная таблица поведений, которые failproofai бы поймала — *когда* это произошло в последний раз, *что прошло* (и встроенная политика, которая бы это заблокировала), его *серьёзность*, и как часто это было *видно* (`new` / `recurring` / `N× seen`).
4. **`// how to improve`** — рекомендуемый список исправлений: одна строка для каждой политики с копируемой `failproofai policy add <slug>`, плюс кнопка **install all**, которая включает все рекомендации сразу и показывает вашу **projected score**, если бы вы это сделали.
5. **`// come back better`** — выработайте привычку: установите **reminder** на переаудит (`3d` / `7d` / `14d` / `30d`) или переаудитируйте сейчас, и **пригласите друга** запустить свой собственный аудит (отправлено с failproof.ai, Cc вам). Reminders и приглашения требуют входа.

## Запланированные аудиты

Если вы запускаете **failproofaid daemon** (см. [`failproofai config`](/ru/cli/install-policies)),
он может переигрывать аудит для вас по расписанию и обновлять отчёт `/audit` в
фоне. Это **отключено по умолчанию**, потому что сканирование читает *содержимое*
каждой стенограммы сессии агента на этой машине — ничего не сканируется по таймеру
пока вы этого не попросите.

Включите это в `~/.failproofai/config.json` — добавьте ключ `audit` рядом с
чем-либо другим, что файл уже содержит:

```json
{
  "audit": {
    "auto": true,
    "interval_days": 7
  }
}
```

| Ключ | Значение |
|---|---|
| `auto` | `true` включает запланированное сканирование. Всё остальное — отсутствие, `false`, `"yes"` — отключено. |
| `interval_days` | Дни между сканированиями. Ограничено 1–90; `0`, отрицательное число или не-число вернёт по умолчанию `7`. |

- Расписание — это **wall-clock**, поэтому оно выживает спячку и перезагрузки: ноутбук,
  который был заснут дольше положенного времени, выполняет **один раз** при пробуждении, никогда очередь.
- Каждый запуск — это отдельный процесс с низким приоритетом (`nice 19`) — никогда путь daemon'а
  hook, который остаётся свободным для ответа на tool call'ы.
- Сканирование пропускается если `failproofai audit` или переигрывание панели уже
  выполняется; оно повторяется вскоре после этого, а не рассматривается как отказ.
- Прогресс записывается в `~/.failproofai/state/audit-schedule.json` (последний запуск,
  следующее время). Daemon'овладеет этим файлом — измените темп в `config.json`.

<Note>
Если вы включили это на машине, настроенной старой версией failproofai, запустите
`failproofai config` один раз. Определение сервиса daemon'а нуждается в одной дополнительной
записи перед тем как он сможет запустить CLI, и обновление является частью этой команды.
</Note>

## Детекторы, доступные только при аудите

Они обнаруживают паттерны глупого поведения, не (пока) принуждаемые в реальном времени. Они запускаются только при аудите и никогда не блокируют live tool call.

| Детектор | Что он подсчитывает |
|---|---|
| `redundant-cd-cwd` | Bash-команды, начинающиеся с `cd <cwd> && …` хотя команды уже запускаются в `cwd`. |
| `prefer-edit-over-read-cat` | `cat`/`head`/`tail`/`less`/`more` на одном исходном файле — используйте инструмент `Read`. |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` inline редакторы — используйте инструмент `Edit`. |
| `prefer-write-over-heredoc` | Heredoc / мульти-линейный `echo > file` написания файлов — используйте инструмент `Write`. |
| `sleep-polling-loop` | Длинный `sleep N` (≥ 30s) или `while …; sleep …; done` polling циклы. |
| `find-from-root` | `find /`, `find /home`, `find /usr` и т.д. — ограничьте до `cwd`. |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, пропуск hooks. |
| `reread-after-edit` | `Read` файла, который был только что `Edit`/`Write` в той же сессии. |

## Кэши

- **Per-transcript кэш** в `~/.failproofai/cache/audit/<sha1>.json` с ключом `(mtime, size, engineVersion, detectorVersion)` — автоматически инвалидируется когда стенограмма или код политики/детектора меняется. Каждая запись также хранит `cachedAt` timestamp как **TTL метаданные** (не часть ключа кэша); записи старше **7 дней** отклоняются при чтении, чтобы долгоживущие результаты не пережили эволюцию намерения детектора.
- **Whole-result кэш** в `~/.failproofai/audit-dashboard.json` (mode 0600). Позволяет панели рендериться мгновенно при навигации без переигрывания. Также отклоняется при чтении после **7-дневного TTL** — `/audit` затем вернётся к пустому состоянию и предложит свежий запуск. Нажмите `[ re-audit now ]` около низа отчёта чтобы обновить — переаудит отправляет `noCache: true`, поэтому он обходит per-transcript кэш и переигрывает каждую стенограмму вместо возврата кэшированного результата; запуск потоковых обновлений прогресса через sticky верхнюю полосу и заменяет результат на месте при успехе (без перезагрузки страницы; неудачный переаудит сохраняет предыдущий отчёт).

## Примечания

- **Без изменений.** Аудит переигрывается в режиме только для чтения. `warn-repeated-tool-calls` пропускается потому что его per-session сопутствующий файл был бы иначе изменён.
- **Workflow политики пропускаются.** `require-*-before-stop` политики срабатывают только на `Stop` событиях и `execSync` против live git состояния — они не имеют значимого толкования "что бы произошло в 2025", поэтому они не появляются в счётчиках аудита.
- **Пользовательские политики пропускаются.** Предоставленные пользователем пользовательские hooks не переигрываются (они могли измениться с момента оригинальной сессии).
