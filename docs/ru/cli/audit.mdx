<Note>
  **Бета-функция.** Аудит поставляется в виде бета-версии, пока мы собираем начальные отзывы.
  Каталог детекторов и формат отчета могут измениться перед следующей стабильной
  версией. Пожалуйста, откройте issue, если что-то выглядит неправильно.
</Note>

Аудит воспроизводит ваши прошлые стенограммы агента CLI через механизм политик failproofai и отрисовывает доступный для общего доступа визуальный отчет на **странице `/audit` в панели инструментов** — архетип агента, оценку от 0 до 100 и точно указывает, какие политики перехватили бы что.

## Запуск аудита

Три способа запуска — все приводят к одному отчету `/audit`.

<CodeGroup>

```bash npx (без установки)
npx -y failproofai audit
```

```bash failproofai audit
failproofai audit
```

```bash failproofai (панель инструментов)
failproofai
```

</CodeGroup>

<CardGroup cols={3}>
  <Card title="Без установки" icon="bolt">

  </Card>

<Tip>
  Запустите `failproofai audit -h` (или `--help`), чтобы увидеть справку по использованию. Аудит работает **полностью
  в автономном режиме** — учетная запись или сетевое подключение не требуются — и панель инструментов
  продолжает работать до тех пор, пока вы не остановите ее с помощью `Ctrl+C`.
</Tip>

Панель инструментов сканирует прошлые стенограммы агента CLI на этой машине (Claude Code, Codex, Copilot, Cursor, OpenCode, Pi) и сообщает, как часто агент совершал действия, которые failproofai построен чтобы предотвратить — проверки переменных окружения, force push, избыточные префиксы `cd <cwd>`, циклы опроса со sleep, повторное чтение только что отредактированных файлов и многое другое.

Для каждой стенограммы каждое событие использования инструмента воспроизводится через 39 встроенных политик **и** через 8 детекторов, доступных только при аудите, которые ловят паттерны, еще не охваченные политиками выполнения. Счета агрегируются для каждой политики / детектора по всем сессиям.

## Что вы получаете

Страница `/audit` — это одноэкранный, доступный для общего доступа **постер**, за которым следуют четыре раздела ниже:

1. **Постер** — личность вашего агента с первого взгляда: его **архетип** (один из 8 — `оптимист`, `ковбой`, `исследователь`, `рыбка`, `параноик-архитектор`, `строитель точности`, `молот`, `привидение`), его ключевые слова личности, насколько редкий этот архетип, и **оценка от 0 до 100** с уровнем (`S` вплоть до `нижний уровень`). Разработан для общего доступа — опубликуйте в X или LinkedIn или загрузите как PNG.
2. **`// strengths`** — то, что ваш агент уже делает хорошо, как реальные числа из сканирования (например, clean-tool-call %, `0` попыток push-to-main), показано только там, где соответствующая политика имеет чистую запись.
3. **`// quirks`** — что прошло незаметно: ранжированная таблица поведений, которые failproofai перехватил бы — *когда* это в последний раз произошло, *что прошло* (и встроенная политика, которая это перехватила бы), его *серьезность* и как часто это было *замечено* (`новое` / `повторяющееся` / `N× замечено`).
4. **`// how to improve`** — список рекомендуемых исправлений: одна строка для каждой политики с копируемой командой `failproofai policy add <slug>`, плюс кнопка **установить все**, которая включает все рекомендации сразу и показывает вашу **прогнозируемую оценку**, если бы вы это сделали.
5. **`// come back better`** — выработайте привычку: установите напоминание о переаудите по электронной почте **reminder** (`3d` / `7d` / `14d` / `30d`) или переаудируйте сейчас, и **пригласите друга** запустить свой собственный аудит (отправлено с failproof.ai, в копии вам). Напоминания и приглашения требуют входа.

## Запланированные аудиты

Если вы запустите **демон failproofaid** (см. [`failproofai config`](/ru/cli/install-policies)),
он может переиспользовать аудит для вас по расписанию и обновить отчет `/audit` в
фоновом режиме. Это **отключено по умолчанию**, потому что сканирование читает *содержимое*
каждой стенограммы сессии агента на этой машине — ничего не сканируется по таймеру
до тех пор, пока вы этого не попросите.

Включите его в `~/.failproofai/config.toml`:

```toml
[audit]
auto = true
interval_days = 7
```

| Ключ | Значение |
|---|---|
| `auto` | `true` включает запланированное сканирование. Что-либо еще — отсутствует, `false`, `"yes"` — отключено. |
| `interval_days` | Дни между сканированиями. Ограничено 1–90; `0`, отрицательное число или не-число возвращается к `7`. |

- Расписание **по стене часов**, поэтому оно сохраняется при приостановке и перезагрузке: ноутбук,
  который был в спящем режиме после запланированного времени, запускает **один раз** при пробуждении, никогда накопленную очередь.
- Каждый запуск — это отдельный, низкоприоритетный (`nice 19`) процесс — никогда путь hook демона,
  который остается свободным для ответа на вызовы инструментов.
- Сканирование пропускается, если `failproofai audit` или переиспользование из панели инструментов уже
  выполняется; оно будет повторено вскоре после этого, а не трактуется как сбой.
- Прогресс записывается в `~/.failproofai/state/audit-schedule.json` (последний запуск,
  следующий срок). Демон владеет этим файлом — изменяйте кадинг в `config.toml`.

<Note>
Если вы включили это на машине, созданной старой версией failproofai, запустите
`failproofai config` один раз. Определение сервиса демона нуждается в одной дополнительной
записи перед запуском CLI, и обновление является частью этой команды.
</Note>

## Детекторы, доступные только при аудите

Они обнаруживают паттерны "глупого поведения", не (еще) принудительно применяемые в реальном времени. Они работают только во время аудита и никогда не блокируют живой вызов инструмента.

| Детектор | Что он подсчитывает |
|---|---|
| `redundant-cd-cwd` | Bash-команды, начинающиеся с `cd <cwd> && …`, даже хотя команды уже запускаются в `cwd`. |
| `prefer-edit-over-read-cat` | `cat`/`head`/`tail`/`less`/`more` на одном исходном файле — используйте инструмент `Read`. |
| `prefer-edit-over-sed-awk` | `sed -i` / `awk … > file` редактирование на месте — используйте инструмент `Edit`. |
| `prefer-write-over-heredoc` | Heredoc / многострочный `echo > file` при записи файлов — используйте инструмент `Write`. |
| `sleep-polling-loop` | Длительный `sleep N` (≥ 30s) или `while …; sleep …; done` циклы опроса. |
| `find-from-root` | `find /`, `find /home`, `find /usr` и т.д. — ограничьте область до `cwd`. |
| `git-commit-no-verify` | `git commit … --no-verify` / `-n`, пропуск hooks. |
| `reread-after-edit` | `Read` файла, который был только что `Edit`/`Write` в той же сессии. |

## Кэши

- **Кэш для каждой стенограммы** в `~/.failproofai/cache/audit/<sha1>.json`, проиндексированный по `(mtime, size, engineVersion, detectorVersion)` — автоматически инвалидируется при изменении стенограммы или кода политик/детекторов. Каждая запись также хранит временную метку `cachedAt` как **метаданные TTL** (не входит в ключ кэша); записи старше **7 дней** отклоняются при чтении, поэтому долгоживущие результаты не переживают развивающееся намерение детектора.
- **Кэш всего результата** в `~/.failproofai/audit-dashboard.json` (режим 0600). Позволяет панели инструментов отрисовываться мгновенно при навигации без повторного запуска. Также отклоняется при чтении после **7-дневного TTL** — `/audit` затем переходит в пустое состояние и подсказывает свежий запуск. Нажмите `[ re-audit now ]` рядом с нижней частью отчета для обновления — переаудит отправляет `noCache: true`, поэтому он обходит кэш для каждой стенограммы и повторно сканирует каждую стенограмму вместо возврата кэшированного результата; запуск потоком передает прогресс через липкую верхнюю полосу и меняет результат на месте при успехе (без перезагрузки страницы; неудачный переаудит сохраняет предыдущий отчет).

## Примечания

- **Без изменений.** Аудит воспроизводится в режиме только для чтения. `warn-repeated-tool-calls` пропускается, потому что его боковой файл для каждой сессии будет иначе изменен.
- **Политики рабочего процесса пропущены.** Политики `require-*-before-stop` срабатывают только при событиях `Stop` и `execSync` против живого состояния git — они не имеют значимой интерпретации "что бы произошло в 2025", поэтому они не появляются в подсчетах аудита.
- **Пользовательские политики пропущены.** Предоставленные пользователем пользовательские hooks не воспроизводятся (они могли измениться с момента исходной сессии).
