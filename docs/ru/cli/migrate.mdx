```bash
failproofai migrate --dry-run   # вывести план, ничего не менять
failproofai migrate             # выполнить миграцию
```

Большинство пользователей никогда не вводят эту команду. Она запускается
автоматически при первой команде после обновления, и [`failproofai update`](/ru/cli/update)
включает её в себя. Используйте эту команду напрямую, когда хотите увидеть план до
его выполнения или запустить миграцию отдельно.

## Привязка к структуре, а не версии

`~/.failproofai/VERSION` записывает номер **структуры** — форму директории,
а не релиз, который её создал. Миграции привязаны к этому номеру, что делает
большой перерыв в обновлениях дешёвым:

- Версии npm меняются при каждом релизе, дюжины версий между двумя структурами.
- Так что машина, пропустившая тридцать релизов без **изменения структуры**, запустит **ноль**
  миграций, а не тридцать пустых операций.
- А машина, пропустившая несколько структур сразу, запустит каждый шаг по порядку,
  где каждый шаг знает только свои два конца.

Это важно, потому что npm не может обновить установленный пакет самостоятельно.
Машина, которая стоит на одной версии месяцы, а потом прыгает на несколько структур —
обычный случай, а не редкий.

## Пробная прогонка

`--dry-run` выводит точную цепочку и файлы, которые будут сохранены первыми,
и вообще ничего не меняет — ни миграции, ни резервной копии, ни записи в лог:

```
На диске структура 2; эта сборка говорит о 3.
Будет запущено 1 шаг(а):
  2 → 3  структура 2 → 3: перенести config.toml и credentials.toml в JSON, переместить
         custom-policies/ обратно в policies/, вложить конфиг политик в корень

Эти файлы будут скопированы в ~/.failproofai/migrations/backup-layout2 первыми:
  VERSION
  config.toml
  credentials.toml
```

## Что переносится, что перестраивается

Каждый путь в домашней директории объявляет, какой тип данных он содержит,
и это определяет, может ли миграция его выбросить. Правило: **производные и пересчитываемые
данные могут быть удалены; всё, что вы ввели, что ещё не доставлено и что идентифицирует
машину — переносится.**

| Переносится | Перестраивается или пересчитывается |
|---|---|
| `config.json` — настройки, `daemon.configured`, дополнительные пути захвата | Кеш аудита |
| `credentials.json` — ваша регистрация в облаке | Развёртывания, управляемые облаком (пересчитываются и проверяются по хешу при следующем опросе) |
| `policies-config.json` — ваш выбор политик и их параметры | Рабочее состояние демона |
| `policies/` — ваши файлы политик и вспомогательные файлы, которые они импортируют | |
| `hook-activity/` — лог решений, который читает панель управления | |
| Недоставленные события, ещё в очереди на загрузку | |
| `cursors/` — водяные знаки коллектора | |
| Бинарный файл демона в `bin/` | |

<Note>
  Недоставленные события переносятся, а не удаляются, потому что потеря была бы
  постоянной, а не временной: водяной знак коллектора уже прошёл мимо всего,
  что сидит в буфере, поэтому ничто никогда не прочитает этот диапазон
  транскрипта снова. Миграция также просит демон доставить то, что в буфере,
  как только она завершится, поэтому обычный результат — что доставлять нечего.
</Note>

Ключи, которые *более новая* версия записала в `config.json`, `credentials.json`
или `policies-config.json`, тоже сохраняются, а не удаляются старым читателем.

## Запись, которую она оставляет

```
~/.failproofai/migrations/
  applied.json                 одна запись за шаг: структура, CLI, временная метка, длительность, результат
  backup-layout<n>/            копии неизменяемых файлов, сделанные перед первым шагом
```

`applied.json` — это то, что отвечает на вопрос «через что эта машина действительно прошла» —
первый вопрос, стоящий задать, когда после обновления что-то выглядит неправильно.
Приложите его к отчёту об ошибке.

Резервная копия намеренно маленькая, а не копия всей директории: миграция по дизайну
больше ничего неизменяемого не удаляет, поэтому что стоит страховать — это *дефект
в шаге*, и эти несколько файлов — то, где такой дефект принесёт вред.

## Если шаг не удаётся

Цепь останавливается там. `VERSION` отмечается временной меткой только шагом,
который завершился, поэтому директория остаётся отмеченной старой структурой,
и следующая команда повторит попытку — директория никогда не отмечается как текущая
на основе частичной миграции. Шаг записывается в `applied.json` с `"ok": false`,
и резервная копия остаётся там, где она была сделана.

## Более новая директория отказывается, не мигрируется

Если `~/.failproofai/` была написана **более новой** версией failproofai,
чем та, которую вы запускаете, команда останавливается и говорит вам
обновиться вместо этого. Эти данные в порядке, и новый CLI их прочитает;
миграция «вперёд» из них не существует, и её сброс разрушит что-то,
что можно восстановить.

```
Директория failproofai этой машины была написана более новой версией (структура 4;
эта сборка говорит о 3). Обновитесь вместо миграции:
  npm install -g failproofai@latest
```

Демон применяет то же правило: `failproofaid` отказывается запускаться
против структуры, которую он не понимает, вместо того, чтобы читать и писать
пути, которые переместились.
