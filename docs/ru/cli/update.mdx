title: Обновление после升级
description: "Завершите вторую половину升级, которую npm не может выполнить: мигрируйте домашнюю папку и синхронизируйте демон"
---

```bash
npm install -g failproofai@latest && failproofai update
```

Это и есть полное обновление. `npm` заменяет CLI; `failproofai update` делает
остальное.

## Зачем нужна вторая команда

`npm install -g` заменяет только одно — CLI. Два других компонента установки failproofai
находятся вне пакета намеренно, и ни один из них не перемещается при запуске npm:

- **`~/.failproofai/`**, ваши настройки, облачная регистрация, выбор политик и
  история. Новая версия может организовать её иначе, и переорганизация должна
  выполняться кодом, который знает обе структуры.
- **Бинарный файл демона `failproofaid`**, находящийся в
  `~/.failproofai/bin/failproofaid-<version>`. Он намеренно *не находится* внутри
  `node_modules`: обновление, которое заменило бы файл под работающим сервисом, переподключило бы
  живой демон к бинарнику, построенному из другого исходного кода, а удаление
  пакета удалило бы его из-под сервиса, который затем зависал в цикле перезагрузки
  при каждой загрузке.

Поэтому после самого `npm install -g` CLI новый, а демон — нет.
`failproofaid` отказывается запускаться против структуры домашней папки, которую он не понимает —
явная версия этого несоответствия, а не скрытая — поэтому две половины нужно
привести в соответствие. `failproofai update` — это этот шаг.

## Что это делает

<Steps>
  <Step title="Запускает любые ожидающие миграции структуры">
    Читает структуру, записанную в `~/.failproofai/VERSION` и запускает шаги, которые
    приводят её к структуре, понимаемой этой версией. Обычно никаких — см.
    [`failproofai migrate`](/ru/cli/migrate).
  </Step>
  <Step title="Помещает на место соответствующий бинарный файл демона">
    Из пакета платформы, который npm уже загрузил, где возможно (без сети),
    в противном случае из релиз-ассета для этой точной версии, проверенного SHA-256
    перед использованием.
  </Step>
  <Step title="Перезагружает сервис и подтверждает, что он вернулся">
    Проверяется, а не предполагается — менеджер сервисов сообщает о процессе как активном
    в момент разветвления, что не то же самое, что работает.
  </Step>
</Steps>

## Опции

| Флаг | Эффект |
|------|--------|
| `--no-daemon` | Мигрирует только домашнюю папку, оставляя демон в текущей версии. |

<Warning>
  `--no-daemon` оставляет демон с несоответствующей версией на месте. На машине, настроенной
  на требование демона, каждое событие хука **завершается с ошибкой** если демон не может
  ответить — и демон, который отказывается запускаться против мигрированной домашней папки,
  не может ответить. Лучше дать половине демона выполниться.
</Warning>

## Если что-то пошло не так

Команда выходит с ненулевым кодом и указывает, какая половина не удалась. Два случая,
о которых стоит знать:

- **Шаг миграции не завершился.** Домашняя папка остаётся помеченной со своей *старой*
  структурой, поэтому следующая команда повторяет попытку — домашняя папка никогда
  не помечается как текущая на основе частичной миграции. Копии ваших настроек и регистрации
  были сохранены перед запуском в `~/.failproofai/migrations/backup-layout<n>/`.
- **Демон не удалось перезагрузить без пароля.** `sudo -n` используется
  намеренно, поэтому ничего не подсказывается под отображением прогресса. Команда
  выводит точную строку для самостоятельного запуска.

<Note>
  Ничего здесь не требует интерактивного мастера установки. Ваши настройки, облачная
  регистрация и выбор политик сохраняются при обновлении, поэтому мигрированная машина
  обеспечивает именно такое же принуждение, как и раньше — что особенно важно на машинах,
  где никто не сидит: CI-ранер, машина во флоте, безголовый шлюз.
</Note>

## Автоматизация

`failproofai update` неинтерактивна и безопасна для запуска, когда нечего
делать — она сообщает о миграции не требуется» и выходит с 0. Размещение её после каждого
обновления в скрипте подготовки или Dockerfile — это предполагаемое использование:

```dockerfile
RUN npm install -g failproofai@latest && failproofai update --no-daemon
```

(`--no-daemon` при построении образа, где ещё нет сервиса для перезагрузки.)
