title: Обновление после upgrade
description: "Завершите вторую половину upgrade, которую npm не может сделать: перенесите домашнюю директорию и синхронизируйте демон"
---

```bash
npm install -g failproofai@latest && failproofai update
```

Это полный upgrade. `npm` заменяет CLI; `failproofai update` делает остальное.

## Почему нужна вторая команда

`npm install -g` заменяет только одно — CLI. Две другие части установки failproofai находятся вне пакета специально и не перемещаются при запуске npm:

- **`~/.failproofai/`**, ваши настройки, регистрация облака, выбор политик и история. Новая версия может организовать это по-другому, и реорганизация должна быть выполнена кодом, который знает обе структуры.
- **Двоичный файл демона `failproofaid`**, в `~/.failproofai/bin/failproofaid-<version>`. Он намеренно *не находится* в `node_modules`: upgrade, который заменил бы файл под работающим сервисом, переполучил бы живой демон на двоичный файл, собранный из другого исходного кода, а удаление пакета удалило бы его из-под сервиса, который затем бы crash-loop при каждой загрузке.

Итак, после одного `npm install -g` CLI новый, а демон — нет. `failproofaid` отказывается запускаться с макетом домашней директории, который он не понимает — громкая версия этого несоответствия вместо молчаливой — поэтому обе половины нужно привести в соответствие. `failproofai update` — это шаг.

## Что он делает

<Steps>
  <Step title="Запускает все ожидающие миграции макета">
    Читает макет, записанный в `~/.failproofai/VERSION` и выполняет шаги, которые приводят его к тому, который эта версия понимает. Обычно нет — см. [`failproofai migrate`](/ru/cli/migrate).
  </Step>
  <Step title="Устанавливает соответствующий двоичный файл демона">
    Из пакета платформы, который npm уже загрузил по возможности (без сети), в противном случае из ресурса релиза для этой точной версии, проверенного SHA-256 перед использованием.
  </Step>
  <Step title="Перезагружает сервис и подтверждает, что он запустился">
    Проверяется, а не предполагается — менеджер сервисов сообщает о активном процессе в момент его форка, что не то же самое, что его работа.
  </Step>
</Steps>

## Опции

| Флаг | Эффект |
|------|--------|
| `--no-daemon` | Перенесите только домашнюю директорию, оставив демон на текущей версии. |

<Warning>
  `--no-daemon` оставляет демон с несоответствующей версией на месте. На машине, настроенной на требование демона, каждое событие hook **завершается с ошибкой** если демон не может ответить — и демон, который отказывается запускаться с перенесённой домашней директорией, не может ответить. Лучше позвольте запуститься половине с демоном.
</Warning>

## Если что-то пошло не так

Команда выходит с ненулевым кодом и говорит, какая половина не удалась. Два случая, которые стоит знать:

- **Шаг миграции не завершился.** Домашняя директория остаётся отмеченной со своим *старым* макетом, поэтому следующая команда повторит попытку — домашняя директория никогда не помечается текущей на основе частичной миграции. Копии ваших настроек и регистрации были сохранены до запуска чего-либо в `~/.failproofai/migrations/backup-layout<n>/`.
- **Демон не удалось перезагрузить без пароля.** `sudo -n` используется намеренно, поэтому ничто никогда не подсказывает из-под отображения прогресса. Команда выводит точную строку для самостоятельного запуска.

<Note>
  Здесь ничего не требует интерактивного мастера установки. Ваши настройки, регистрация облака и выбор политик сохраняются при upgrade, поэтому перенесённая машина применяет политики точно так же, как раньше — что особенно важно на машинах без пользователей: CI runner, машина парка, headless шлюз.
</Note>

## Автоматизация

`failproofai update` неинтерактивный и безопасен для запуска, когда нечего делать — он сообщает о миграции, которая не была необходима, и выходит с кодом 0. Размещение его после каждого upgrade в скрипте подготовки или Dockerfile — это предусмотренное использование:

```dockerfile
RUN npm install -g failproofai@latest && failproofai update --no-daemon
```

(`--no-daemon` в сборке образа, где ещё нет сервиса для перезагрузки.)
