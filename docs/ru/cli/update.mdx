description: "Завершите вторую половину upgrade, которую npm не может выполнить: перенесите домашнюю директорию и синхронизируйте демон"
---

```bash
npm install -g failproofai@latest && failproofai update
```

Вот и всё обновление. `npm` заменяет CLI; `failproofai update` выполняет
остальное.

## Почему нужна вторая команда

`npm install -g` заменяет только одно — CLI. Два других компонента установки failproofai
живут вне пакета и намеренно не перемещаются при запуске npm:

- **`~/.failproofai/`** — ваши настройки, облачное подключение, выбор политик и
  история. Новая версия может организовать это иначе, и переорганизацию должен выполнить код,
  который знает обе структуры.
- **Бинарный файл демона `failproofaid`** в
  `~/.failproofai/bin/failproofaid-<version>`. Он намеренно *не находится* в
  `node_modules`: обновление, которое заменило бы файл под запущенным сервисом,
  переподключило бы живой демон к бинарнику, собранному из другого исходного кода,
  а удаление пакета удалило бы его из-под сервиса, который затем входил бы в цикл сбоев
  при каждой загрузке.

Поэтому после самого `npm install -g` CLI новый, а демон — нет.
`failproofaid` отказывается запускаться с расположением домашней директории, которое он
не понимает — громкий вариант этого несоответствия, а не тихий — поэтому обе
половины нужно привести в соответствие. `failproofai update` — это тот шаг.

## Что он делает

<Steps>
  <Step title="Выполняет все ожидающие миграции макета">
    Читает макет, записанный в `~/.failproofai/VERSION`, и выполняет шаги,
    которые приводят его к тому, который понимает эта версия. Обычно никаких — см.
    [`failproofai migrate`](/ru/cli/migrate).
  </Step>
  <Step title="Размещает соответствующий бинарный файл демона">
    Из пакета платформы, который npm уже загрузил, где возможно (без сети),
    или из asset релиза именно для этой версии, проверенного SHA-256 перед использованием.
  </Step>
  <Step title="Перезапускает сервис и подтверждает, что он восстановился">
    Проверяется, а не предполагается — менеджер сервисов сообщает активный процесс
    в момент его запуска, что не то же самое, что его корректная работа.
  </Step>
</Steps>

## Опции

| Флаг | Эффект |
|------|--------|
| `--no-daemon` | Перенесите только домашнюю директорию, оставив демон в текущей версии. |

<Warning>
  `--no-daemon` оставляет демон с рассогласованной версией. На машине, где требуется
  демон, каждое событие hook **отказывает безопасно**, если демон не может ответить —
  а демон, который отказывается запускаться с перенесённой домашней директорией,
  не может ответить. Предпочтительно позволить запуститься демон-половине.
</Warning>

## Если что-то пошло не так

Команда завершается с ненулевым кодом и говорит, какая половина не сработала. Два случая, которые стоит знать:

- **Шаг миграции не завершился.** Домашняя директория оставляется отмеченной *старым*
  макетом, поэтому следующая команда повторяет его — домашняя директория никогда не отмечается
  как текущая на основе частичной миграции. Копии ваших настроек и облачного подключения
  были сохранены перед запуском в `~/.failproofai/migrations/backup-layout<n>/`.
- **Демон не мог быть перезапущен без пароля.** `sudo -n` используется
  намеренно, так что ничего никогда не запрашивает из-под отображения прогресса. Команда
  выводит точную строку для запуска вручную.

<Note>
  Ничего здесь не требует интерактивного мастера настройки. Ваши настройки,
  облачное подключение и выбор политик сохраняются при обновлении, поэтому
  перенесённая машина работает ровно так же, как раньше — что особенно важно
  на машинах, где никто не сидит: CI runner, fleet box, безголовый шлюз.
</Note>

## Автоматизация

`failproofai update` не интерактивна и безопасна к запуску, когда нечего
делать — она сообщает "миграция не требовалась" и завершается с кодом 0. Размещение после каждого
обновления в скрипте провизионирования или Dockerfile — это предусмотренное использование:

```dockerfile
RUN npm install -g failproofai@latest && failproofai update --no-daemon
```

(`--no-daemon` при создании образа, где ещё нет сервиса для перезапуска.)
