Панель управления failproofai — это локальное веб-приложение для мониторинга сеансов ваших AI-агентов и управления политиками. Узнайте, что делали ваши агенты, пока вас не было.

---

## Запуск панели управления

```bash
failproofai
```

Открывается по адресу `http://localhost:8020`.

Панель управления читает локальные данные проектов, сеансов и конфигурации failproofai непосредственно из файловой системы. Дополнительные функции с аутентификацией, такие как напоминания об аудитах и приглашения, отправляют информацию, необходимую для этих запросов (включая адреса электронной почты), на удалённые API.

## Страницы

### Проекты

Список всех проектов Claude Code, OpenAI Codex, GitHub Copilot CLI _(бета)_, Cursor Agent _(бета)_, OpenCode _(бета)_, Pi _(бета)_, Hermes, OpenClaw, Factory Droid, Devin, Antigravity и Goose, найденных на вашем компьютере. Проекты Claude обнаруживаются из `~/.claude/projects/` (или из пути, установленного в `CLAUDE_PROJECTS_PATH`); проекты Codex обнаруживаются путём сканирования каждого транскрипта в `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` и группировки по `cwd`, записанному в первую запись сеанса; проекты Copilot CLI обнаруживаются путём сканирования каждого `~/.copilot/session-state/<sessionId>/workspace.yaml` (настраивается через `COPILOT_HOME`) и группировки по полю `cwd`; проекты Cursor Agent обнаруживаются путём сканирования метаданных для каждого сеанса в `~/.cursor/agent-sessions/<sessionId>/` (настраивается через `CURSOR_HOME`, с `conversations/` и `sessions/` в качестве резервных вариантов) для поиска скалярного значения `cwd` в `meta.json` / `session.json` / `workspace.yaml`; проекты OpenCode обнаруживаются путём запроса его БД SQLite по адресу `~/.local/share/opencode/opencode.db` через `opencode db --format json` (мы читаем таблицы `session` и `project` и группируем по `project_id`); проекты Pi обнаруживаются путём сканирования JSONL-транскриптов для каждого сеанса в `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` (настраивается через `PI_SESSIONS_DIR`) и извлечения `cwd` из первой записи каждого сеанса; сеансы шлюза Hermes читаются непосредственно из хранилища SQLite каждого профиля — `~/.hermes/state.db` плюс `~/.hermes/profiles/<name>/state.db` (переопределяется через `HERMES_HOME` или `HERMES_DB_PATH` для одной базы данных) — и группируются в проекты `hermes-<profile>-<source>` по профилю и `source` (Slack/Telegram/cli/cron — сеансы шлюза не имеют cwd); сеансы шлюза OpenClaw читаются из `~/.openclaw/agents/<agentId>/sessions/*.jsonl` и группируются в проекты `openclaw-<agentId>-<channel>` по агенту и каналу (также без cwd); проекты Factory Droid обнаруживаются из JSONL-транскриптов по адресу `~/.factory/sessions/<encoded-cwd>/*.jsonl` и группируются по cwd; проекты Devin из его БД SQLite по адресу `~/.local/share/devin/cli/sessions.db` (группируются по `working_directory` каждого сеанса); проекты Antigravity из JSONL-транскриптов по адресу `~/.gemini/antigravity-cli/brain/<conversationId>/…/transcript_full.jsonl` и группируются по cwd; проекты Goose из его БД SQLite по адресу `~/.local/share/goose/sessions/sessions.db` (группируются по `working_dir` каждого сеанса). Проект, который использовался несколькими CLI, отображается в виде одной строки со всеми совпадающими значками. Используйте раскрывающееся меню **CLI** над таблицей для фильтрации по определённому CLI агента; URL сохраняет ваш выбор как `?cli=claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose`.

Hermes и OpenClaw охватывают только пользователей и не имеют рабочей директории для группировки, поэтому они отображаются как **сворачиваемое дерево папок** — профиль (или агент) на верхнем уровне, его каналы под ним — в то время как каждый CLI на основе cwd остаётся плоской строкой. Строки папок суммируют количество сеансов и самую недавнюю активность всего, что находится под ними, свёрнутые папки запоминаются между посещениями, а поиск по ключевому слову разворачивает всё, что он совпадает.

Каждый проект показывает:
- Имя проекта (производное от пути папки)
- Значок CLI — `Claude Code` (оранжевый), `OpenAI Codex` (фиолетовый), `GitHub Copilot` (синий), `Cursor Agent` (изумрудный), `OpenCode` (янтарный), `Pi` (розовый) и/или `Hermes` (индиго)
- Дата самой последней активности сеанса

Нажмите на проект, чтобы увидеть его сеансы.

### Сеансы

Список всех сеансов в проекте. Каждый сеанс показывает:
- Идентификатор сеанса
- Времена начала и окончания
- Количество вызовов инструментов
- Счётчик активности хука (количество срабатываний политик)

Используйте фильтр по диапазону дат и поиск по идентификатору сеанса, чтобы сузить список. Сеансы распределяются по страницам.

Нажмите на сеанс, чтобы открыть просмотр сеанса.

### Просмотр сеанса

Просмотр сеанса отвечает на ключевой вопрос для автономных агентов: что делал агент и оставался ли он на правильном пути? Значок CLI рядом с заголовком указывает на то, является ли сеанс транскриптом Claude Code, OpenAI Codex, GitHub Copilot CLI, Cursor Agent, OpenCode, Pi, Hermes, OpenClaw, Factory Droid, Devin, Antigravity или Goose. Он показывает временную шкалу всего, что произошло в сеансе:

- **Сообщения** - текстовые ответы Claude и подсказки пользователя
- **Вызовы инструментов** - каждый инструмент, который вызвал Claude, с его входными и выходными данными
- **Активность политики** - для каждого вызова инструмента, какие политики сработали и какое решение они приняли

Панель статистики в верхней части показывает продолжительность сеанса, общее количество вызовов инструментов и сводку решений по хукам (количество разрешений / отклонений / инструкций).

Нажмите кнопку **Скачать логи**, чтобы экспортировать сеанс. Для сеансов Claude Code, Codex, Copilot, Cursor и Pi вы получите исходный JSONL-транскрипт на диске в виде побайтового копии; для OpenCode (сеансы которого находятся в SQLite, а не на диске) вы получите JSON-документ, зеркалирующий базовые таблицы `session` / `messages` / `parts`.

### Аудит

Ведомый характером отчёт о том, как ваш агент на самом деле вёл себя в прошлых сеансах. Запускает то же сканирование, что и CLI `failproofai audit`, но отображает его как одноэкранный общедоступный постер + четыре раздела ниже сворачиваемого контента:

1. **Постер** — заполняет первое окно видимости. Автономный регион захвата PNG с логотипом failproof_ai + метка аудита · индекс архетипа (`№ NN из 08`) + дата аудита · числовой балл (0–100) + процентильный ранг пилюли (`top 15%`) · имя архетипа (один из `the optimist`, `the cowboy`, `the explorer`, `the goldfish`, `the paranoid architect`, `the precision builder`, `the hammer`, `the ghost`) + полоса с 3 ключевыми словами · строка редкости `// only N% of agents are this archetype` · сигильная плитка 8×8 пикселей · нижний колонтитул `audit yours → failproof.ai`. Три кнопки доля находятся прямо за пределами поля захвата: `post your archetype` (X intent), `share on linkedin`, `download poster`. Захват работает через `html-to-image`, так что PNG соответствует отображению на экране пиксель за пиксель (пунктирные границы, маска логотипа SVG, градиенты, метрики шрифта — всё сохранено).
2. **Сильные стороны** — список с галочкой спокойствия ✓ поведений, которые ваш агент уже делает хорошо, полученных из данных прямого аудита (чистый коэффициент вызовов инструментов, без прямых отправок на main, нулевых утечек учётных данных, нулевых штормов повторных попыток) — каждый показывается только тогда, когда соответствующая политика имеет чистую запись во всём окне аудита.
3. **Особенности** — таблица того, что проскользнуло, отсортированная по серьёзности: `when · what slipped + the policy that would've caught it · severity pill · seen`, где повторяемость читается как `new` (один раз), `N× seen` (2–9 раз) или `recurring` (10+).
4. **Как улучшить** — список строк спокойствия, один на предписанную политику: имя политики белым цветом, однострочное описание, команда установки + кнопка копирования на правой стороне. Заголовок раздела читает `enable all N → projected <score> · <tier>` (балл, который вы получите со всеми применёнными исправлениями), а его кнопка `[install all]` копирует объединённую команду `failproofai policy add a b c …` для каждой предписанной политики.
5. **Вернитесь лучше** — две карточки рядом. Слева: установите напоминание (выбор кадроля `3d` / `7d` / `14d` / `30d`; сохраняется через `/api/auth/reminder` после аутентификации). Справа: разблокируйте преимущества failproof — `invite a friend` открывает модальное окно, которое принимает разделённый запятыми/пробелом/новой строкой список адресов электронной почты друзей (макс. 10 на отправку), отправляет их на `/api/audit/invite`, которое пересылается на `POST /v0/invite` api-сервера. Api-сервер отправляет одно письмо на каждого получателя из `invite@failproof.ai` с добавлением отправителя в копию и установкой `Reply-To`, так что получатель видит, кто его пригласил, а отправитель получает копию в своем почтовом ящике. Анонимные пользователи маршрутизируются через `AuthDialog` в первую очередь, так чтобы электронная почта отправителя была известна до отправки приглашений. Выполнение прав доступа / преимуществ — это последующее действие.

Управляется средой выполнения `failproofai audit` — см. [Аудит CLI](/ru/cli/audit) для базовой подсистемы сканирования, поддерживаемых флагов и инвариантов кэша для каждого транскрипта. Панель управления кэширует последний результат на `~/.failproofai/audit-dashboard.json` (режим `0600`, один слот, новые запуски перезаписывают) так что повторные посещения мгновенны; **как кэши для каждого транскрипта, так и целые результаты отклоняются при чтении, как только они старше 7 дней**, поэтому панель управления никогда не обслуживает результат недельной давности — после истечения TTL `/audit` переходит в пустое состояние и предлагает свежий запуск. Нажатие `[ re-audit now ]` рядом с нижней частью отчёта POSTs `/api/audit/run` с `noCache: true` — переаудит обходит кэш для каждого транскрипта и пересканирует каждый транскрипт с нуля вместо тихого возврата кэшированного результата — и панель управления опрашивает `/api/audit/status` на 1Hz до завершения запуска; липкая розовая полоса прогресса прикрепляется к верхней части области видимости во время запуска с истекшим таймером, и свежий результат встаёт на место при успехе (без полной перезагрузки страницы; неудачный переаудит оставляет предыдущий отчёт нетронутым). При сбое полоса становится красной с копией текста, основанной на `RerunError.kind` (`timeout` / `network` / `post_failed`). Пустое состояние (нет кэша или истекло) и состояние нулевых сеансов (кэш существует, но сканирование не обнаружило транскриптов) отображаются отдельно.

## Автоматическое обновление

Панель управления имеет переключатель автоматического обновления в верхней навигации. При включении текущая страница периодически обновляется, чтобы показывать новые сеансы и активность политики по мере их появления. Важно для мониторинга долгоживущих сеансов автономных агентов.

## Отключение страниц

Если вам нужны только некоторые части панели управления, установите `FAILPROOFAI_DISABLE_PAGES` на разделённый запятыми список имён страниц:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

Допустимые значения: `policies`, `projects`, `audit`.

## Настройка пути проектов

По умолчанию панель управления читает из стандартного каталога проектов Claude Code. Переопределите его для пользовательских настроек:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## Доступ с хоста, отличного от localhost

При запуске панели управления в **режиме разработки** (`npm run dev`) и доступе к ней с имени хоста, отличного от `localhost` — например, пользовательского домена, удалённого IP или туннелированного URL — вы можете увидеть предупреждение типа:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

Это Next.js, блокирующий кроссоригинный доступ к его HMR (горячая перезагрузка модулей) вебсокету, который является функцией только для разработки. Чтобы разрешить ваш хост, используйте флаг `--allowed-origins`:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

Для нескольких хостов или IP-адресов передайте разделённый запятыми список:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

Вы также можете установить переменную окружения `FAILPROOFAI_ALLOWED_DEV_ORIGINS` вместо этого:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
Это применяется только к режиму разработки. При запуске `failproofai` (режим продакшена) нет вебсокета HMR и нет проблемы с кроссоригинными ресурсами разработки.
</Note>
