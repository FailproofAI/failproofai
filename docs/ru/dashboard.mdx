Панель управления failproofai — это локальное веб-приложение для мониторинга сеансов ваших AI агентов и управления политиками. Смотрите, что делали ваши агенты, пока вас не было.

---

## Запуск панели управления

```bash
failproofai
```

Открывается на `http://localhost:8020`.

Панель управления читает данные напрямую из файловой системы — ваши папки проектов Claude Code и конфигурационные файлы failproofai. Ничего не записывается на удалённый сервис.

## Страницы

### Проекты

Выводит список всех найденных на вашем компьютере проектов Claude Code, OpenAI Codex, GitHub Copilot CLI _(бета)_, Cursor Agent _(бета)_, OpenCode _(бета)_, Pi _(бета)_ и Gemini CLI _(бета)_. Проекты Claude обнаруживаются из `~/.claude/projects/` (или пути, установленного через `CLAUDE_PROJECTS_PATH`); проекты Codex обнаруживаются путём сканирования всех транскриптов в `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` и группировки по `cwd`, указанному в первой записи каждого сеанса; проекты Copilot CLI обнаруживаются путём сканирования каждого `~/.copilot/session-state/<sessionId>/workspace.yaml` (настраивается через `COPILOT_HOME`) и группировки по полю `cwd`; проекты Cursor Agent обнаруживаются путём сканирования метаданных для каждого сеанса в `~/.cursor/agent-sessions/<sessionId>/` (настраивается через `CURSOR_HOME`, с проверкой `conversations/` и `sessions/` в качестве альтернативы) для поиска скалярного значения `cwd` в `meta.json` / `session.json` / `workspace.yaml`; проекты OpenCode обнаруживаются путём запроса к базе данных SQLite на `~/.local/share/opencode/opencode.db` через `opencode db --format json` (мы читаем таблицы `session` и `project` и группируем по `project_id`); проекты Pi обнаруживаются путём сканирования транскриптов JSONL для каждого сеанса в `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl` (настраивается через `PI_SESSIONS_DIR`) и извлечения `cwd` из первой записи каждого сеанса; проекты Gemini CLI обнаруживаются путём сканирования `~/.gemini/tmp/<basename>/chats/session-<timestamp>-<uuid-prefix>.jsonl` (настраивается через `GEMINI_SESSIONS_DIR`) и восстановления канонического cwd из соседнего текстового маркера `.project_root`. Проект, использованный несколькими CLI, отображается в виде одной строки со всеми соответствующими значками. Используйте раскрывающееся меню **CLI** над таблицей для фильтрации по определённому агенту CLI; URL сохраняет вашу выборку как `?cli=claude|codex|copilot|cursor|opencode|pi|gemini`.

Каждый проект показывает:
- Имя проекта (выведено из пути папки)
- Значок CLI — `Claude Code` (оранжевый), `OpenAI Codex` (фиолетовый), `GitHub Copilot` (синий), `Cursor Agent` (изумрудный), `OpenCode` (янтарный), `Pi` (розовый) и/или `Gemini CLI` (небесно-голубой)
- Дату самой свежей активности сеанса

Нажмите на проект, чтобы увидеть его сеансы.

### Сеансы

Выводит список всех сеансов в проекте. Каждый сеанс показывает:
- ID сеанса
- Временные метки начала и окончания
- Количество вызовов инструментов
- Количество срабатываний политик (hook activity)

Используйте фильтр по диапазону дат и поиск по ID сеанса, чтобы сузить список. Сеансы разбиты на страницы.

Нажмите на сеанс, чтобы открыть просмотрщик сеанса.

### Просмотрщик сеанса

Просмотрщик сеанса отвечает на ключевой вопрос для автономных агентов: что сделал агент и остался ли он в курсе? Значок CLI рядом с заголовком указывает, является ли сеанс транскриптом Claude Code, OpenAI Codex, GitHub Copilot CLI, Cursor Agent, OpenCode, Pi или Gemini CLI. Он показывает временную шкалу всего, что произошло в сеансе:

- **Сообщения** — текстовые ответы Claude и приглашения пользователя
- **Вызовы инструментов** — каждый инструмент, вызванный Claude, с его входными данными и выводом
- **Активность политик** — для каждого вызова инструмента, какие политики сработали и какое решение они вернули

Полоса статистики в верхней части показывает продолжительность сеанса, общее количество вызовов инструментов и сводку решений hook (количество allow / deny / instruct).

Нажмите кнопку **Download Logs** для экспорта сеанса. Для сеансов Claude Code, Codex, Copilot, Cursor, Pi и Gemini вы получите исходный JSONL транскрипт на диске побайтово; для OpenCode (сеансы которого находятся в SQLite, а не на диске) вы получите JSON документ, отражающий основные таблицы `session` / `messages` / `parts`.

### Аудит

Отчёт, ориентированный на личность, о том, как ваш агент на самом деле себя вёл во время прошлых сеансов. Выполняет то же сканирование, что и CLI `failproofai audit`, но отображает его как панель управления из шести разделов:

1. **Identity** — классифицирует вашего агента в один из 8 архетипов (`the optimist`, `the cowboy`, `the explorer`, `the goldfish`, `the paranoid architect`, `the precision builder`, `the hammer`, `the ghost`) на основе того, какие детекторы и политики сработали и как часто. Отображает 8×8 пиксельный сигил, пояснение архетипа, фреймворк "common in" / "primary risk" и заключительную однострочку.
2. **Show off your agent** — захватывает карточку идентификации как 1200×630 PNG, пригодный для публикации на X / LinkedIn (нажмите `make poster`).
3. **Strengths** — отмеченные зелёным поведения, которые ваш агент уже делает правильно, полученные из актуальных данных аудита (чистая скорость вызовов инструментов, средняя продолжительность сеанса, ноль утечек учётных данных, ноль штормов повторов и т. д.).
4. **Score + leaderboard** — оценка 0–100 с буквенной оценкой (S/A/B/C/D/F), гистограмма распределения, показывающая вашу позицию в когорте, текст ("a B starts at 71. you're 13 points away.") и таблица рейтинга с выделенной строкой.
5. **Findings** — карточки по каждому найденному результату, ранжированные по влиянию. Каждая карточка показывает, что произошло, какова стоимость, образец доказательств с реальными захваченными командами и политику failproofai, которая бы уловила тот же паттерн (`$ failproofai policy add <slug>`, нажимается для копирования).
6. **Prescribed policies + return loop** — сетка каждой неактивированной встроенной политики, которая закроет пробел, с выноской прогнозируемой оценки плюс CTA "re-audit in 7 days".

Приводится в движение выполнением `failproofai audit` — см. [Audit CLI](/ru/cli/audit) для основного механизма сканирования, поддерживаемых флагов и инвариантов кеша для каждого транскрипта. Панель управления кеширует последний результат в `~/.failproofai/audit-dashboard.json` (режим `0600`, один слот, новые запуски перезаписывают) поэтому повторные посещения мгновенны; **оба кеши для каждого транскрипта и полный результат отклоняются при чтении, если они старше 7 дней**, так что панель управления никогда не будет молча служить недельный результат — после TTL `/audit` переходит в пустое состояние и предлагает новый запуск. Нажатие `[ re-audit now ]` около дна отчёта POSTит на `/api/audit/run` и панель управления опрашивает `/api/audit/status` на 1Hz до завершения запуска; во время запуска к верхней части окна просмотра прикрепляется липкая розовая полоса прогресса с таймером истекшего времени, и результат меняется на месте при успехе (без полной перезагрузки страницы). При сбое полоса становится красной с текстом, зависящим от `RerunError.kind` (`timeout` / `network` / `post_failed`). Пустое состояние (без кеша или истекшего) и состояние нулевых сеансов (кеш существует, но сканирование не нашло транскриптов) отображаются отдельно.

## Автоматическое обновление

Панель управления имеет переключатель автоматического обновления в верхней навигации. Когда включено, текущая страница периодически обновляется для отображения новых сеансов и активности политик по мере их появления. Необходимо для мониторинга длительных сеансов автономных агентов.

---

## Отключение страниц

Если вам нужны только некоторые части панели управления, установите `FAILPROOFAI_DISABLE_PAGES` на список названий страниц, разделённых запятыми:

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

Допустимые значения: `policies`, `projects`, `audit`.

---

## Настройка пути к проектам

По умолчанию панель управления читает из стандартного каталога проектов Claude Code. Переопределите его для пользовательских установок:

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## Доступ с хоста, отличного от localhost

При запуске панели управления в **режиме разработки** (`npm run dev`) и доступе к ней с имени хоста, отличного от `localhost` — например, пользовательского домена, удалённого IP или туннелированного URL — вы можете увидеть предупреждение типа:

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

Это Next.js блокирует кроссориджинный доступ к своему WebSocket HMR (горячая перезагрузка модулей), который является функцией только для разработки. Чтобы разрешить ваш хост, используйте флаг `--allowed-origins`:

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

Для нескольких хостов или IP передайте список, разделённый запятыми:

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

Вы также можете установить переменную окружения `FAILPROOFAI_ALLOWED_DEV_ORIGINS` вместо этого:

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
Это применяется только к режиму разработки. При запуске `failproofai` (режим производства) WebSocket HMR отсутствует и нет проблемы с кроссориджинными ресурсами разработки.
</Note>
