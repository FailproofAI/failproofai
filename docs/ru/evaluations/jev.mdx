Jev оценка читает **завершённую сессию** и выдаёт оценку от 0 до 1. Используйте её, когда ответ известен заранее, например «Выразил ли клиент срочность?» или «Насколько клиент был разочарован?» Это помогает найти закономерности между запусками; оценка не останавливает вызов инструмента. Для решений, принятых **до** запуска инструмента, используйте [Jev политики](/ru/policies/jev).

## Создайте одну на панели управления

1. Откройте **analyse → checks → new evaluation** и выберите **decision model** в пункте **how should it score?**.
2. Опишите один вопрос и его возможные ответы. Например: «Пообещал ли агент возврат средств до проверки политики возврата? Ответьте да или нет.» На странице **review** проверьте **question** и что означают **yes** и **no**; модель решений всегда выдаёт оценку.
3. [Протестируйте её](/ru/evaluations/test) на недавних сессиях, затем [разверните](/ru/evaluations/deploy). Новые завершённые сессии будут оценены; [заполните историю](/ru/evaluations/deploy#score-sessions-you-already-have), если вам также нужны исторические данные.

При создании проекта failproof может выбрать между **code**, **decision model** (Jev) и [**llm as judge**](/ru/evaluations/judge). Проверьте его выбор перед развёртыванием. Jev выдаёт оценку без текстового обоснования; выберите judge, если вам нужно объяснение. Смотрите [справку по Jev оценкам](/ru/reference/jev-evaluations) для типов вопросов и ограничений оценок.

## Прочитайте оценки

Откройте **analyse → checks → evals** и выберите оценку для графика результатов по агентам и времени. Из терминала Cloud CLI может читать те же результаты:

```bash
fp evals --since 7d
fp evals --aggregate --since 7d
```

Из терминала `fp evaluators` создаёт и развёртывает Jev оценки, а `fp evals` читает их результаты. Смотрите [справку Cloud CLI](/ru/reference/cloud-cli#evaluations) для обоих.
