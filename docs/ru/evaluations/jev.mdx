Jev оценка читает **завершённую сессию** и выдаёт оценку от 0 до 1. Используйте её, когда ответ известен заранее, например «Выразил ли клиент срочность?» или «Насколько расстроен был клиент?» Это помогает найти закономерности между запусками; оценка не останавливает вызов инструмента. Для решений, принимаемых **перед** запуском инструмента, используйте [Jev policies](/ru/policies/jev).

## Создайте одну в панели управления

1. Откройте **analyse → checks → new evaluation** и выберите **decision model** в разделе **how should it score?**.
2. Опишите один вопрос и его возможные ответы. Например: «Пообещал ли агент возврат средств перед проверкой политики возвратов? Ответьте да или нет.» На странице **review** проверьте **question** и что означает **yes** и **no**; decision model всегда выдаёт оценку.
3. [Протестируйте](/ru/evaluations/test) на недавних сессиях, затем [разверните](/ru/evaluations/deploy). Новые завершённые сессии будут оценены; используйте [backfill](/ru/evaluations/deploy#score-sessions-you-already-have), если вам также нужна история.

При создании черновика failproof может выбирать между **code**, **decision model** (Jev) и [**llm as judge**](/ru/evaluations/judge). Проверьте его выбор перед развёртыванием. Jev выдаёт оценку без текстового обоснования; выберите judge, когда вам нужно объяснение. Смотрите [справку Jev оценок](/ru/reference/jev-evaluations) для типов вопросов и пределов оценок.

## Прочитайте оценки

Откройте **analyse → checks → evals** и выберите оценку, чтобы построить график результата по агентам и времени. Из терминала Cloud CLI может прочитать те же результаты:

```bash
fp evals --since 7d
fp evals --aggregate --since 7d
```

Из терминала `fp evaluators` создаёт и развёртывает Jev оценки, а `fp evals` читает их результаты. Смотрите [справку Cloud CLI](/ru/reference/cloud-cli#evaluations) для обоих.
