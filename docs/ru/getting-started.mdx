## Требования

- **Node.js** >= 20.9.0
- **Bun** >= 1.3.0 (опционально - требуется только для сборки из исходного кода)

## Установка

<CodeGroup>

```bash npm
npm install -g failproofai
```

```bash bun
bun add -g failproofai
```

</CodeGroup>

## Быстрый старт

<Steps>
  <Step title="Включите политики">
    Политики — это правила, которые выполняются до и после каждого вызова инструмента агентом. Они перехватывают деструктивные команды, утечки секретов и другие сбои до того, как они причинят ущерб.

    ```bash
    failproofai policies --install
    ```

    Это добавляет записи хуков в установленные CLI агентов (файл `~/.claude/settings.json` для Claude Code, `~/.codex/hooks.json` для OpenAI Codex, `~/.copilot/hooks/failproofai.json` для GitHub Copilot CLI, `~/.cursor/hooks.json` для Cursor Agent, сгенерированный плагин в `~/.config/opencode/plugins/failproofai.mjs` для OpenCode плюс запись в массиве `plugin` файла `~/.config/opencode/opencode.json`, `~/.pi/agent/settings.json` для Pi, `~/.hermes/config.yaml` для Hermes, `~/.openclaw/openclaw.json` для OpenClaw, `~/.factory/hooks.json` для Factory Droid, `~/.config/devin/config.json` для Devin CLI, `~/.gemini/config/hooks.json` для Antigravity CLI или автоматически обнаруживаемую директорию плагинов Goose в `~/.agents/plugins/failproofai/hooks/hooks.json`). При наличии более одного агента вы будете спрошены; передайте `--cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose` (любое подмножество), чтобы пропустить запрос.

    Поддержка GitHub Copilot CLI, Cursor Agent, OpenCode и Pi находится в статусе **beta** — установите с помощью `--cli copilot`, `--cli cursor`, `--cli opencode` или `--cli pi`. Hermes (hermes-agent, шлюз Slack/Telegram) устанавливается в пользовательской области с `--cli hermes` и является **также** источником офлайн-аудита. OpenClaw (шлюз openclaw, многоканальный самостоятельно размещаемый ассистент) устанавливается в пользовательской области с `--cli openclaw` — принудительное применение работает через встроенные хуки плагинов (`before_agent_finalize` — реальные ворота конца хода, поэтому встроенные `require-*-before-stop` работают) — и является **также** источником офлайн-аудита. Factory Droid (`droid`) устанавливается с `--cli factory` (область пользователя и проекта) и является **также** источником офлайн-аудита. Devin CLI (`devin`, Cognition) устанавливается с `--cli devin` (область пользователя и проекта) и является **также** источником офлайн-аудита. Antigravity CLI (`agy`) устанавливается с `--cli antigravity` (область пользователя и проекта) и является **также** источником офлайн-аудита. Goose (кодовое имя goose, Block) устанавливается с `--cli goose` (область пользователя и проекта) — установщик просто создает директорию плагинов в `~/.agents/plugins/failproofai/`, которую Goose автоматически обнаруживает, и она является **также** источником офлайн-аудита.

    ```bash
    failproofai policies --install --scope project
    failproofai policies --install --cli codex --scope project
    failproofai policies --install --cli copilot --scope project
    failproofai policies --install --cli cursor --scope project
    failproofai policies --install --cli opencode --scope project
    failproofai policies --install --cli pi --scope project
    failproofai policies --install --cli hermes --scope user
    failproofai policies --install --cli openclaw --scope user
    failproofai policies --install --cli factory --scope project
    failproofai policies --install --cli devin --scope project
    failproofai policies --install --cli antigravity --scope project
    failproofai policies --install --cli goose --scope project
    failproofai policies --install block-sudo block-rm-rf sanitize-api-keys
    ```
  </Step>
  <Step title="Проверка">
    ```bash
    failproofai policies
    ```

    Показывает все политики, включены ли они и любые настроенные параметры.
  </Step>
  <Step title="Запустите приборную панель">
    ```bash
    failproofai
    ```

    Открывает локальную приборную панель по адресу `http://localhost:8020`, где вы можете просматривать сеансы, инспектировать вызовы инструментов и управлять политиками.
  </Step>
  <Step title="Запустите вашего агента">
    Запустите Claude Code как обычно. Если агент попытается сделать что-то рискованное, failproofai автоматически это перехватит. Оставьте его работать без присмотра и просмотрите, что произошло, на приборной панели.
  </Step>
</Steps>

## Как работают политики

Каждый раз, когда агент запускает инструмент, Claude Code вызывает failproofai как подпроцесс:

```text
Claude Code  →  failproofai --hook PreToolUse  →  читает JSON из stdin
                                                 оценивает политики
                                                 пишет решение в stdout
```

Каждая политика возвращает одно из трех решений:

- **allow** - агент продолжает нормальную работу
- **deny** - действие блокируется, агенту объясняется почему
- **instruct** - дополнительный контекст добавляется в подсказку агента

<Note>
Политики выполняются в вашем локальном процессе. Ничего не отправляется на удаленный сервис.
</Note>

## Установка командных политик с помощью соглашений о политиках

Самый быстрый способ установить стандарты качества в вашей команде — это соглашение `.failproofai/policies/`. Поместите файлы политик в эту директорию, и они будут загружены автоматически — без флагов, без изменений конфига, без команд установки.

<Steps>
  <Step title="Создайте директорию политик">
    ```bash
    mkdir -p .failproofai/policies
    ```
  </Step>
  <Step title="Добавьте файлы политик">
    Скопируйте примеры для начинающих или напишите свои собственные:

    ```bash
    cp node_modules/failproofai/examples/convention-policies/*.mjs .failproofai/policies/
    ```

    Или создайте новый:

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Запустите тесты перед коммитом.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="Закоммитьте в git">
    ```bash
    git add .failproofai/policies/
    git commit -m "Add team quality policies"
    ```

    Каждый член команды, у которого установлен failproofai, автоматически получит эти политики. Никакой дополнительной настройки для каждого разработчика не требуется.
  </Step>
</Steps>

<Tip>
Закоммитьте `.failproofai/policies/` в ваш репозиторий, чтобы вся команда придерживалась одних и тех же стандартов. По мере того как ваша команда обнаруживает новые режимы отказов, добавляйте политики и пушьте — все получат обновление при следующем `git pull`. Со временем эти политики становятся живым стандартом качества, который постоянно совершенствуется.
</Tip>

## Хранение данных

Вся конфигурация и логи хранятся на вашей машине:

| Путь | Что хранится |
|------|----------------|
| `~/.failproofai/policies/local-policies/policies-config.json` | Глобальная конфигурация политик |
| `~/.failproofai/hook-activity/` | История выполнения хуков (страничный JSONL) |
| `~/.failproofai/logs/` | Логи отладки для ошибок пользовательских хуков |
| `.failproofai/policies-config.json` | Конфигурация для проекта (закоммичена) |
| `.failproofai/policies-config.local.json` | Личные переопределения (в .gitignore) |

---

## Удаление

```bash
failproofai policies --uninstall
```

Удаляет записи хуков из `~/.claude/settings.json`. Файлы конфигурации в `~/.failproofai/` сохраняются.
