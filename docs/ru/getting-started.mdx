## Требования

- **Node.js** >= 20.9.0
- **Bun** >= 1.3.0 (опционально — требуется только для сборки из исходного кода)

## Установка

<CodeGroup>

```bash npm
npm install -g failproofai
```

```bash bun
bun add -g failproofai
```

</CodeGroup>

## Быстрый старт

<Steps>
  <Step title="Включите политики">
    Политики — это правила, которые выполняются до и после каждого вызова инструмента агентом. Они перехватывают деструктивные команды, утечки секретов и другие режимы отказа еще до того, как они причинят вред.

    ```bash
    failproofai policies --install
    ```

    Это добавляет записи хуков в установленные интерфейсы командной строки агентов (Claude Code в `~/.claude/settings.json`, OpenAI Codex в `~/.codex/hooks.json`, GitHub Copilot CLI в `~/.copilot/hooks/failproofai.json`, Cursor Agent в `~/.cursor/hooks.json`, OpenCode в сгенерированный плагин в `~/.config/opencode/plugins/failproofai.mjs` и запись регистрации в массив `plugin` файла `~/.config/opencode/opencode.json`, Pi в `~/.pi/agent/settings.json`, Hermes в `~/.hermes/config.yaml`, OpenClaw в `~/.openclaw/openclaw.json`, Factory Droid в `~/.factory/hooks.json`, Devin CLI в `~/.config/devin/config.json`, Antigravity CLI в `~/.gemini/config/hooks.json` или Goose в автоматически обнаруживаемую директорию плагинов в `~/.agents/plugins/failproofai/hooks/hooks.json`). Если присутствует более одного, вам будет предложено выбрать; передайте `--cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose` (любой подмножество) чтобы пропустить запрос.

    Поддержка GitHub Copilot CLI, Cursor Agent, OpenCode и Pi находится на этапе **бета** — установите с помощью `--cli copilot`, `--cli cursor`, `--cli opencode` или `--cli pi`. Hermes (hermes-agent, шлюз Slack/Telegram) устанавливается с областью пользователя с помощью `--cli hermes` и **также** является источником автономного аудита. OpenClaw (шлюз openclaw, многоканальный помощник с собственным размещением) устанавливается с областью пользователя с помощью `--cli openclaw` — принудительное исполнение осуществляется через его встроенные хуки плагинов (`before_agent_finalize` — это настоящий барьер завершения хода, поэтому встроенные `require-*-before-stop` применяют политики) — и **также** является источником автономного аудита. Factory Droid (`droid`) устанавливается с помощью `--cli factory` (область пользователя и проекта) и **также** является источником автономного аудита. Devin CLI (`devin`, Cognition) устанавливается с помощью `--cli devin` (область пользователя и проекта) и **также** является источником автономного аудита. Antigravity CLI (`agy`) устанавливается с помощью `--cli antigravity` (область пользователя и проекта) и **также** является источником автономного аудита. Goose (кодовое имя goose, Block) устанавливается с помощью `--cli goose` (область пользователя и проекта) — инсталлятор просто создает директорию плагина в `~/.agents/plugins/failproofai/`, которую Goose автоматически обнаруживает, и это **также** является источником автономного аудита.

    ```bash
    failproofai policies --install --scope project
    failproofai policies --install --cli codex --scope project
    failproofai policies --install --cli copilot --scope project
    failproofai policies --install --cli cursor --scope project
    failproofai policies --install --cli opencode --scope project
    failproofai policies --install --cli pi --scope project
    failproofai policies --install --cli hermes --scope user
    failproofai policies --install --cli openclaw --scope user
    failproofai policies --install --cli factory --scope project
    failproofai policies --install --cli devin --scope project
    failproofai policies --install --cli antigravity --scope project
    failproofai policies --install --cli goose --scope project
    failproofai policies --install block-sudo block-rm-rf sanitize-api-keys
    ```
  </Step>
  <Step title="Проверка">
    ```bash
    failproofai policies
    ```

    Показывает каждую политику, включена ли она и все настроенные параметры.
  </Step>
  <Step title="Запустите панель управления">
    ```bash
    failproofai
    ```

    Открывает локальную панель управления на `http://localhost:8020`, где вы можете просматривать сеансы, проверять вызовы инструментов и управлять политиками.
  </Step>
  <Step title="Запустите агента">
    Запустите Claude Code обычным образом. Если агент попытается сделать что-то рискованное, failproofai автоматически перехватит это. Оставьте его работающим без присмотра и изучите произошедшее в панели управления.
  </Step>
</Steps>

## Как работают политики

Каждый раз, когда агент запускает инструмент, Claude Code вызывает failproofai как подпроцесс:

```text
Claude Code  →  failproofai --hook PreToolUse  →  читает JSON из stdin
                                                  оценивает политики
                                                  записывает решение в stdout
```

Каждая политика возвращает одно из трех решений:

- **allow** — агент продолжает работу нормально
- **deny** — действие блокируется, агенту сообщается причина
- **instruct** — дополнительный контекст добавляется в подсказку агента

<Note>
Политики выполняются в вашем локальном процессе. Ничего не отправляется на удаленный сервис.
</Note>

## Установка командных политик с использованием политик, основанных на соглашениях

Самый быстрый способ установить стандарты качества во всей команде — это соглашение `.failproofai/policies/`. Поместите файлы политик в эту директорию, и они будут загружены автоматически — без флагов, без изменения конфигурации, без команд установки.

<Steps>
  <Step title="Создайте директорию политик">
    ```bash
    mkdir -p .failproofai/policies
    ```
  </Step>
  <Step title="Добавьте файлы политик">
    Скопируйте примеры для начинающих или напишите свои:

    ```bash
    cp node_modules/failproofai/examples/convention-policies/*.mjs .failproofai/policies/
    ```

    Или создайте новый:

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Run tests before committing.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="Зафиксируйте в git">
    ```bash
    git add .failproofai/policies/
    git commit -m "Add team quality policies"
    ```

    Каждый член команды, у которого установлен failproofai, автоматически получит эти политики. Никакая персональная настройка для разработчиков не требуется.
  </Step>
</Steps>

<Tip>
Зафиксируйте `.failproofai/policies/` в вашем репозитории, чтобы вся команда придерживалась одних и тех же стандартов. По мере того, как ваша команда обнаруживает новые режимы отказа, добавляйте политики и отправляйте обновления — все получат их при следующем `git pull`. Со временем эти политики становятся живым стандартом качества, который постоянно совершенствуется.
</Tip>

## Хранилище данных

Вся конфигурация и логи остаются на вашей машине:

| Путь | Что там хранится |
|------|----------------|
| `~/.failproofai/policies-config.json` | Глобальная конфигурация политик |
| `~/.failproofai/policies/` | Ваши собственные политики — поместите `*-policies.mjs`, конфигурация не требуется |
| `~/.failproofai/policies/cloud-policies/` | Политики, развернутые на этой машине вашей организацией |
| `~/.failproofai/hook-activity/` | История выполнения хуков (постраничный JSONL) |
| `~/.failproofai/logs/` | Логи отладки для ошибок пользовательских хуков |
| `.failproofai/policies-config.json` | Конфигурация для каждого проекта (зафиксирована) |
| `.failproofai/policies-config.local.json` | Персональные переопределения (игнорируется gitом) |

---

## Удаление

```bash
failproofai policies --uninstall
```

Удаляет записи хуков из `~/.claude/settings.json`. Файлы конфигурации в `~/.failproofai/` сохраняются.
