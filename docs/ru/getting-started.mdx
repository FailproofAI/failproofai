## Требования

- **Node.js** >= 20.9.0
- **Bun** >= 1.3.0 (опционально — требуется только при сборке из исходного кода)

## Установка

<CodeGroup>

```bash npm
npm install -g failproofai
```

```bash bun
bun add -g failproofai
```

## Быстрый старт

<Steps>
  <Step title="Активируйте политики">
    Политики — это правила, которые запускаются перед и после каждого вызова инструмента агентом. Они перехватывают опасные команды, утечки секретов и другие сбои до того, как они причинят вред.

    ```bash
    failproofai policies --install
    ```

    Это добавляет записи хуков в установленные CLI агентов (Claude Code в `~/.claude/settings.json`, OpenAI Codex в `~/.codex/hooks.json`, GitHub Copilot CLI в `~/.copilot/hooks/failproofai.json`, Cursor Agent в `~/.cursor/hooks.json`, OpenCode в генерируемый плагин-шим `~/.config/opencode/plugins/failproofai.mjs` плюс запись регистрации в массиве `plugin` файла `~/.config/opencode/opencode.json`, Pi в `~/.pi/agent/settings.json`, Hermes в `~/.hermes/config.yaml`, OpenClaw в `~/.openclaw/openclaw.json`, Factory Droid в `~/.factory/hooks.json`, Devin CLI в `~/.config/devin/config.json`, Antigravity CLI в `~/.gemini/config/hooks.json`, или Goose в автоматически обнаруживаемый каталог плагинов `~/.agents/plugins/failproofai/hooks/hooks.json`). Если присутствует более одного, вам будет предложено выбрать; передайте `--cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose` (любое подмножество) чтобы пропустить этот шаг.

    Поддержка GitHub Copilot CLI, Cursor Agent, OpenCode и Pi находится в **бета-версии** — устанавливайте с `--cli copilot`, `--cli cursor`, `--cli opencode` или `--cli pi`. Hermes (hermes-agent, шлюз Slack/Telegram) устанавливается с областью пользователя через `--cli hermes` и также является **источником оффлайн-аудита**. OpenClaw (шлюз openclaw, самохостируемый многоканальный помощник) устанавливается с областью пользователя через `--cli openclaw` — применение работает через его встроенные хуки плагина (`before_agent_finalize` — настоящие ворота конца хода, поэтому встроенные `require-*-before-stop` работают) — и также является **источником оффлайн-аудита**. Factory Droid (`droid`) устанавливается через `--cli factory` (область пользователя и проекта) и также является **источником оффлайн-аудита**. Devin CLI (`devin`, Cognition) устанавливается через `--cli devin` (область пользователя и проекта) и также является **источником оффлайн-аудита**. Antigravity CLI (`agy`) устанавливается через `--cli antigravity` (область пользователя и проекта) и также является **источником оффлайн-аудита**. Goose (кодовое имя goose, Block) устанавливается через `--cli goose` (область пользователя и проекта) — установщик просто создаёт каталог плагина `~/.agents/plugins/failproofai/`, который Goose автоматически обнаруживает, и это также является **источником оффлайн-аудита**.

    ```bash
    failproofai policies --install --scope project
    failproofai policies --install --cli codex --scope project
    failproofai policies --install --cli copilot --scope project
    failproofai policies --install --cli cursor --scope project
    failproofai policies --install --cli opencode --scope project
    failproofai policies --install --cli pi --scope project
    failproofai policies --install --cli hermes --scope user
    failproofai policies --install --cli openclaw --scope user
    failproofai policies --install --cli factory --scope project
    failproofai policies --install --cli devin --scope project
    failproofai policies --install --cli antigravity --scope project
    failproofai policies --install --cli goose --scope project
    failproofai policies --install block-sudo block-rm-rf sanitize-api-keys
    ```
  </Step>
  <Step title="Проверка">
    ```bash
    failproofai policies
    ```

    Показывает каждую политику, активна ли она и все настроенные параметры.
  </Step>
  <Step title="Запустите панель управления">
    ```bash
    failproofai
    ```

    Открывает локальную панель управления по адресу `http://localhost:8020`, где вы можете просматривать сеансы, проверять вызовы инструментов и управлять политиками.
  </Step>
  <Step title="Запустите вашего агента">
    Запустите Claude Code как обычно. Если агент попытается что-то рискованное, failproofai автоматически это перехватит. Оставьте его работать без присмотра и проверьте, что произошло, в панели управления.
  </Step>
</Steps>

## Как работают политики

Каждый раз, когда агент запускает инструмент, Claude Code вызывает failproofai как подпроцесс:

```text
Claude Code  →  failproofai --hook PreToolUse  →  читает JSON из stdin
                                                 вычисляет политики
                                                 записывает решение в stdout
```

Каждая политика возвращает одно из трёх решений:

- **allow** — агент продолжает работу нормально
- **deny** — действие заблокировано, агенту объясняется почему
- **instruct** — дополнительный контекст добавляется в подсказку агента

<Note>
Политики выполняются в вашем локальном процессе. Ничто не отправляется удалённому сервису.
</Note>

## Настройте командные политики с использованием конвенционных политик

Самый быстрый способ установить стандарты качества в вашей команде — это использование конвенции `.failproofai/policies/`. Поместите файлы политик в этот каталог, и они будут загружены автоматически — без флагов, без изменений конфигурации, без команд установки.

<Steps>
  <Step title="Создайте каталог политик">
    ```bash
    mkdir -p .failproofai/policies
    ```
  </Step>
  <Step title="Добавьте файлы политик">
    Скопируйте примеры для начала или напишите свои:

    ```bash
    cp node_modules/failproofai/examples/convention-policies/*.mjs .failproofai/policies/
    ```

    Или создайте новый файл:

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Запустите тесты перед коммитом.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="Закоммитьте в git">
    ```bash
    git add .failproofai/policies/
    git commit -m "Add team quality policies"
    ```

    Каждый член команды, у которого установлен failproofai, автоматически получит эти политики. Никакой дополнительной настройки на каждого разработчика не требуется.
  </Step>
</Steps>

<Tip>
Закоммитьте `.failproofai/policies/` в ваш репозиторий, чтобы вся команда придерживалась одинаковых стандартов. По мере того как ваша команда обнаруживает новые сбои, добавляйте политики и отправляйте их — все получат обновления при следующем `git pull`. Со временем эти политики становятся живым стандартом качества, который постоянно улучшается.
</Tip>

## Хранение данных

Вся конфигурация и логи остаются на вашем компьютере:

| Путь | Что там хранится |
|------|------------------|
| `~/.failproofai/policies/local-policies/policies-config.json` | Глобальная конфигурация политик |
| `~/.failproofai/hook-activity/` | История выполнения хуков (разбиение на страницы JSONL) |
| `~/.failproofai/logs/` | Отладочные логи для ошибок пользовательских хуков |
| `.failproofai/policies-config.json` | Конфигурация отдельного проекта (сохранена) |
| `.failproofai/policies-config.local.json` | Личные переопределения (в .gitignore) |

---

## Удаление

```bash
failproofai policies --uninstall
```

Удаляет записи хуков из `~/.claude/settings.json`. Файлы конфигурации в `~/.failproofai/` сохраняются.
