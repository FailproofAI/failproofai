38 из 39 встроенных политик поставляются в составе пакета `FailproofAI/policies`; `block-failproofai-commands` встроена в пакет, так как пакет не может объявить `alwaysOn`. Установленный пакет является источником истины для того, что может обеспечивать эта машина:

```bash
failproofai policies show FailproofAI/policies   # каталог в опубликованном виде
failproofai policies                             # что включено здесь
```

`failproofai policies` перечисляет пользовательские файлы, файлы соглашений, установленные пакеты и облачные назначения. У неё нет встроенного раздела, поэтому она не может ответить на вопрос "какие встроенные политики существуют" — `policies show` и [Policy Hub](https://befailproof.ai/policy-hub/FailproofAI/policies/) — вот где этот вопрос находит ответ.

## Значения по умолчанию и как выбирать

Простая команда `failproofai policies add FailproofAI/policies` включает собственные значения по умолчанию пакета — 10 строк, отмеченных как **on** ниже. `block-failproofai-commands` всегда включена независимо и не является частью этого выбора. `--all` включает всё; `--category <slug>` и `--policy <name>` берут срез. Слаг рядом с каждым заголовком — это то, что совпадает с `--category`:

```bash
failproofai policies add FailproofAI/policies --category git,database
```

`block-failproofai-commands` **всегда включена**. Она регистрируется при каждой оценке независимо от того, появляется она в вашем выборе или нет, и её невозможно отключить или приостановить — охрана против отключения агентом принудительной защиты, которую агент может отключить, не является охраной. Пакет не может объявить `alwaysOn`, поэтому эта политика поставляется скомпилированной в пакет, а не в самом пакете.

## Sanitize — `sanitize`

Они работают на `PostToolUse`, после того как инструмент уже был запущен. Они **обнаруживают и отклоняют результат инструмента**; они не редактируют подстроку и не возвращают остальное.

Отказ здесь достигает модели только на платформах, которые потребляют вердикт `PostToolUse` — **codex** и **copilot**, где причина заменяет весь результат инструмента. На claude, cursor, opencode, pi, hermes, openclaw, factory, devin, antigravity и goose, `PostToolUse` только для наблюдения: обнаружение регистрируется, и вывод всё ещё достигает модели.

| Политика | Триггер | По умолчанию | Результат |
| --- | --- | --- | --- |
| `sanitize-jwt` | `PostToolUse` | on | Отклонить результат инструмента, содержащий JWT. |
| `sanitize-api-keys` | `PostToolUse` | on | Отклонить результат инструмента, содержащий ключ OpenAI, Anthropic, GitHub, AWS, Stripe или Google. |
| `sanitize-connection-strings` | `PostToolUse` | on | Отклонить результат инструмента, содержащий строку подключения к базе данных с внедёнными учётными данными. |
| `sanitize-private-key-content` | `PostToolUse` | on | Отклонить результат инструмента, содержащий содержимое закрытого ключа в формате PEM. |
| `sanitize-bearer-tokens` | `PostToolUse` | on | Отклонить результат инструмента, содержащий токен `Authorization: Bearer`. |

## Workflow — `workflow`

Все пять работают на `Stop` и отключены по умолчанию.

| Политика | По умолчанию | Результат |
| --- | --- | --- |
| `require-commit-before-stop` | off | Отклонить завершение при незафиксированной отслеживаемой работе. |
| `require-push-before-stop` | off | Отклонить завершение при локальных коммитах. |
| `require-pr-before-stop` | off | Требовать pull request для текущей ветки. |
| `require-no-conflicts-before-stop` | off | Требовать чистого merge в настроенную базовую ветку. |
| `require-ci-green-before-stop` | off | Требовать успешного прохождения проверок CI на текущем коммите HEAD, игнорируя устаревшие запуски на предыдущих коммитах. |

Эти политики нуждаются в платформе, чей вердикт `Stop` потребляется. Это не все платформы:

| Платформа | `Stop` |
| --- | --- |
| claude, codex, copilot, cursor, openclaw, factory, devin, antigravity | Проверено блокирование: отказ принудительно вызывает новый ход |
| pi | Наблюдение. Причина переносится в следующий ход как инструкция, не как ограничение |
| goose, hermes | Никакой хук `Stop` не установлен, поэтому эти пять никогда не срабатывают |
| opencode | Не проверено. `Stop` не среди событий, вердикты от которых потребляет opencode |

Cursor Cloud Agent VMs не запускают никакие хуки остановки вообще, поэтому сессия Cursor там не покрыта, хотя локальный Cursor защищён.

<Note>
  Политики `warn-*` возвращают `instruct`, а не `deny`. (`prefer-package-manager` — исключение среди неблокирующих имён: она возвращает `deny`, поэтому блокирует на каждой платформе, которая потребляет вердикт `PreToolUse` — то есть на всех двенадцати.) На Hermes и Goose, на Pi, OpenClaw и Factory вне канала `Stop` и на Antigravity вне `Stop` и `UserPromptSubmit`, `instruct` снижается до allow плюс заметка в stderr — агент не уведомляется. `UserPromptSubmit` Antigravity — это реальный второй канал: инструкция внедряется как временное сообщение перед запуском модели.
</Note>

## Справочник параметров

Настраивайте параметры в объекте `policyParams` выбранной области. Типы проверяются каждой политикой.

| Политика | Параметр | Тип и значение по умолчанию |
| --- | --- | --- |
| `sanitize-api-keys` | `additionalPatterns` | `pattern[]`, `[]`; записи содержат `regex` и `label` |
| `block-read-outside-cwd` | `allowPaths` | `string[]`, `[]` |
| `block-sudo` | `allowPatterns` | `string[]`, `[]` |
| `block-rm-rf` | `allowPaths` | `string[]`, `[]` |
| Infra blockers | `allowPatterns` | `string[]`, `[]` |
| `block-secrets-write` | `additionalPatterns` | `string[]`, `[]` |
| `block-push-master` | `protectedBranches` | `string[]`, `["main", "master"]` |
| `block-work-on-main` | `protectedBranches` | `string[]`, `["main", "master"]` |
| `prefer-package-manager` | `allowed`, `blocked` | `string[]`, `[]` |
| `warn-large-file-write` | `thresholdKb` | `number`, `1024` |
| `require-push-before-stop` | `remote`, `baseBranch` | `string`, `"origin"`; `string`, `"main"` |
| `require-pr-before-stop` | `baseBranch` | `string`, `"main"` |
| `require-no-conflicts-before-stop` | `baseBranch` | `string`, `"main"` |

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status"]
    },
    "block-push-master": {
      "protectedBranches": ["main", "release"]
    }
  }
}
```

<Note>
  Простое имя политики как ключ `policyParams` соблюдается только для `FailproofAI/policies`. Для любого другого пакета ключ — это `pack/<owner>/<repo>/<policy>` — пакет незнакомца, объявляющий то же имя политики, получает значения по умолчанию схемы, а не ваши параметры.
</Note>

  Шаблон разрешения расширяет то, что может делать агент. Протестируйте точную токенизацию и варианты команд на целевой платформе перед развёртыванием на всём парке.
</Warning>
