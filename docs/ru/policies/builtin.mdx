Встроенные политики охватывают обработку секретов, файлы окружения, деструктивные команды shell, защищённые ветки, облачные и инфраструктурные инструменты, публикацию пакетов, повторяющиеся вызовы и проверки завершения задач.

## Включение и проверка встроенной политики

<Tabs>
  <Tab title="Dashboard">
    1. Установите политику на подключённой машине с помощью локального CLI.
    2. Запустите безопасное тестовое действие в инструментированном агенте.
    3. Перейдите в **Observe → policy** и отфильтруйте по названию политики, окружению машины или решению.
    4. Откройте связанную сессию, чтобы подтвердить совпадение входных данных инструмента и полученное обоснование.

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies
    failproofai policy add block-rm-rf --cli claude --scope project
    failproofai config --status
    ```

    Удалите её с помощью `failproofai policy remove block-rm-rf --cli claude --scope project`.
  </Tab>
</Tabs>

Список доступных политик в установленной версии:

```bash
failproofai policies
```

Включение одной политики для проекта:

```bash
failproofai policy add block-rm-rf --scope project
```

Включение нескольких политик для выбранных тестов:

```bash
failproofai policies --install block-sudo block-force-push \
  --cli claude codex --scope project
```

Некоторые политики принимают параметры или помечены как бета-версия. Перед развёртыванием ознакомьтесь с описанием, соответствием области применения и поведением по умолчанию. Политика, защищающая один рабочий процесс, может блокировать допустимые операции в другом.
