Встроенные политики — это 39 поддерживаемых политик, охватывающих девять категорий отказов агентов. Все, кроме одной, **поставляются в виде пакета**, `FailproofAI/policies`, так же, как и политики других авторов. Сам пакет не имеет своего набора, поэтому при чистой установке ничего не применяется, пока вы не выберете его:

```bash
failproofai policies add FailproofAI/policies
```

Это включает стандартные настройки пакета — 10 из 38 политик, входящих в пакет. 39-я политика `block-failproofai-commands` включена в любом случае: она скомпилирована в пакет, регистрируется при каждой оценке и не может быть отключена или приостановлена. Пакет не может объявить `alwaysOn`, поэтому эта защита не использует канал пакета.

## Что охватывают девять категорий

| Категория | Слаг `--category` | Политики |
| --- | --- | --- |
| Sanitize | `sanitize` | 5 |
| Environment | `environment` | 3 |
| Dangerous Commands | `dangerous-commands` | 5 |
| Infra Commands | `infra-commands` | 7 |
| Git | `git` | 6 |
| Database | `database` | 2 |
| Packages & System | `packages-system` | 5 |
| AI Behavior | `ai-behavior` | 1 |
| Workflow | `workflow` | 5 |

Это счета скомпилированного каталога, и в сумме они дают 39. Пакет содержит 38 из них, потому что `block-failproofai-commands` имеет статус `alwaysOn` и никогда не использует канал пакета — поэтому `--category dangerous-commands` выбирает четыре остальные.

Возьмите часть вместо стандартных:

```bash
failproofai policies add FailproofAI/policies --category git,database
failproofai policies add FailproofAI/policies --policy block-rm-rf
failproofai policies add FailproofAI/policies --all
```

## Включить или отключить одну

```bash
failproofai policies add block-rm-rf --cli claude --scope project
failproofai policies remove block-rm-rf --cli claude --scope project
```

`policies add` и `policies remove` принимают ровно **одно** имя политики. Запустите их вообще без имени — и вы получите меню выбора с уже включённым. Для нескольких имён одновременно используйте форму установки:

```bash
failproofai policies --install block-sudo block-force-push \
  --cli claude codex --scope project
```

<Note>
  На машине без установленного пакета `failproofai policies add <builtin-name>` загружает `FailproofAI/policies` из её GitHub-релиза для разрешения имени — поэтому первой команде требуется сеть.
</Note>

## Не каждая политика применяется на каждом инструменте

Политика изменяет поведение только там, где инструмент использует вердикт для своего события. Перед тем, как полагаться на встроенную политику, стоит проверить два случая:

| События | Где была проверена смена поведения при deny |
| --- | --- |
| `PreToolUse` | Все 12 инструментов |
| `Stop` | claude, codex, copilot, cursor, openclaw, factory, devin, antigravity. Нет `Stop` хука на goose или hermes, pi переносит причину в следующий ход, и opencode не проверен |

Поэтому пять политик `require-*-before-stop` в категории Workflow могут быть включены на машине и всё равно никогда не сработают, в зависимости от того, какой агент там работает. Cursor Cloud Agent VMs вообще не запускают stop hooks.

Политики `warn-*` и `prefer-*` возвращают `instruct` вместо `deny`. На Hermes и Goose, а также вне канала `Stop` на Pi, OpenClaw, Factory и Antigravity, `instruct` деградирует до allow плюс примечание на stderr: оператор видит это в логах, агент — нет.

Некоторые политики принимают параметры. Проверьте описание, соответствие области и стандартные значения перед развёртыванием — политика, которая защищает один рабочий процесс, может блокировать допустимые операции в другом.
