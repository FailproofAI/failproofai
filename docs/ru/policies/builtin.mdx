Встроенные политики охватывают обработку секретов, файлы окружения, деструктивные команды оболочки, защищённые ветки, облачные и инфраструктурные инструменты, публикацию пакетов, повторные вызовы и проверки завершения задач.

## Включение и проверка встроенной политики

<Tabs>
  <Tab title="Dashboard">
    1. Установите политику на подключённом компьютере с помощью локального CLI.
    2. Выполните безопасное тестовое действие в инструментированном агенте.
    3. Перейдите в **Observe → policy** и отфильтруйте по имени политики, окружению машины или решению.
    4. Откройте связанную сессию, чтобы подтвердить совпадение входных данных инструмента и возвращённую причину.

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies
    failproofai policy add block-rm-rf --cli claude --scope project
    failproofai config --status
    ```

    Удалите её с помощью `failproofai policy remove block-rm-rf --cli claude --scope project`.
  </Tab>
</Tabs>

Списание политик, доступных в установленной версии:

```bash
failproofai policies
```

Включение одной политики для проекта:

```bash
failproofai policy add block-rm-rf --scope project
```

Включение нескольких политик для выбранных систем:

```bash
failproofai policies --install block-sudo block-force-push \
  --cli claude codex --scope project
```

Некоторые политики принимают параметры или помечены как бета. Перед развёртыванием ознакомьтесь с описанием, областью действия и поведением по умолчанию. Политика, которая защищает один рабочий процесс, может заблокировать допустимые операции в другом.
