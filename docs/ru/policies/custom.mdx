Создайте файл с расширением `policies.js`, `policies.mjs` или `policies.ts` в каталоге `.failproofai/policies/`. Файлы соглашения автоматически загружаются в области проекта и пользователя.

## Протестируйте политику перед публикацией в Cloud

<Tabs>
  <Tab title="Dashboard">
    1. Установите пользовательскую политику на одну тестовую машину и вызовите как соответствующее действие, так и правомерное несовпадение.
    2. Перейдите в **Observe → policy** и сравните два решения.
    3. Откройте каждую связанную сессию и проверьте, содержит ли полезная нагрузка события достаточно доказательств для правила.
    4. Когда поведение корректно, переместите проверенный исходный код в **Admin → policy editor** и опубликуйте версию.

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies --install --custom ./security.policies.ts \
      --cli claude --scope project
    failproofai policies
    ```

    Файлы соглашения в `.failproofai/policies/` загружаются без параметра `--custom`. Сохраняйте явную команду установки в CI, когда проверка должна отказаться при нарушенном модуле.
  </Tab>
</Tabs>

```ts
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "protect-production-paths",
  description: "Block writes to production configuration",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Write" && ctx.toolName !== "Edit") return allow();
    const path = String(ctx.toolInput?.file_path ?? "").replaceAll("\\", "/");
    if (path.split("/").includes("production")) {
      return deny("Writes to production configuration require approval.");
    }
    return allow();
  },
});
```

Это соответствует `production/config.yml`, `/srv/production/config.yml`, `/srv/production` и `C:\\production\\config.yml` для обоих инструментов `Write` и `Edit`. Это не соответствует названиям вроде `production-backup`, так как `production` должен быть полным сегментом пути.

Проверьте и установите явный файл:

```bash
failproofai policies --install --custom ./security.policies.ts
```

Контекст политики включает тип события, нормализованную полезную нагрузку, имя и входные данные инструмента, метаданные сессии, параметры и источник CLI, когда доступно.

## Протестируйте пути отказа

Запустите проверку после изменения файла входа или любого локального модуля, который он импортирует:

```bash
failproofai policies --install --custom ./security.policies.ts --scope project
```

Строгий путь CLI отказывает при отсутствующих файлах, синтаксических ошибках, неразрешённых импортах, исключениях верхнего уровня и тайм-аутах загрузки модулей. Во время принудительного исполнения нарушенный пользовательский файл регистрируется и пропускается, чтобы встроенные политики могли продолжить работу. Рассматривайте любое предупреждение загрузки как потерю ожидаемого принудительного исполнения и добавляйте оповещение об этом в журналы производства.

Используйте глобально уникальные имена для явных, соглашений и облачно управляемых политик. Сохраняйте функции политик детерминированными, привязывайте внешние вызовы с короткими тайм-аутами и возвращайте намеренный `allow`, `instruct` или `deny` на каждом пути.

<Warning>
  Пользовательская политика — это код принудительного исполнения. Тестируйте отсутствующие поля, альтернативные имена инструментов и неправильно сформированные входные данные — не только ожидаемое совпадение.
</Warning>
