Failproof AI разработан таким образом, чтобы сбой при принятии решения был видимым, а не молчаливо допускал рискованные операции.

## Диагностика блокировки при сбое

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Admin → enforcement** и откройте машину.
    2. Проверьте последнее подключение, назначенное развертывание и сообщенное развертывание.
    3. Перейдите в **Observe → policy** и откройте сеанс отклоненного решения.
    4. Подтвердите, указана ли причина на недоступность демона, несоответствие версий или саму политику.

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    npm install -g failproofai@latest
    failproofai config
    ```

    Повторный запуск `failproofai config` обновляет и перезапускает демон после обновления пакета.
  </Tab>
</Tabs>

На машине, настроенной для использования `failproofaid`, демон является единственным оценщиком. Если он недоступен или версия его протокола не совпадает с версией CLI, оценка хука завершается неудачей. Действие отклоняется с причиной, которая указывает оператору на необходимость проверить или обновить демон.

До конфигурации демона хуки оценивают политики в процессе. После записи конфигурации демона Failproof AI не молчаливо откатывается на второго оценщика при сбое демона.

## Ответ на решение с блокировкой при сбое

1. Запустите `failproofai config --status`.
2. Если версии отличаются, повторно запустите `failproofai config` после обновления пакета.
3. Если демон недоступен, проверьте состояние его сервиса и локальные логи.
4. Возобновите работу агента только после того, как известный путь оценки политики будет работоспособен.

<Warning>
  Не повторяйте заблокированное действие. Ответ с блокировкой при сбое означает, что система не смогла установить безопасность действия.
</Warning>
