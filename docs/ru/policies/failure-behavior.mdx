После настройки локальный сервис `failproofaid` — единственный оценщик. Если он не может дать ответ, защищённые действия отклоняются, а не молча разрешаются.

## Диагностика блокировки на уровне машины

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

Запустите `failproofai config`, чтобы восстановить сервис или установить совместимую версию.

Два типа отказа могут выглядеть похожим образом:

| Отказ | Значение |
| --- | --- |
| Сервис недоступен | Сокет не имеет работающего оценщика позади него |
| Несовпадение версий | CLI и сервис не согласны по протоколу |

Оба приводят к отказу, но статус сообщает о них отдельно.

## Пак не загружается

Выбранный пак, который отсутствует, изменился или невалиден, отклоняет события, охватываемые его выбранными политиками. Это предотвращает исчезновение неработающего пака, пока машина выглядит защищённой.

`failproofai policies` указывает пак и ошибку загрузки.

```bash
failproofai policies
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

Нечитаемые метаданные расширяют безопасный отказ вместо его сужения из данных, которым нельзя доверять.

## Что остаётся доступным

Локальная панель управления и команды статуса по-прежнему работают, пока оценка политик выполняется с ошибками. Используйте их для определения сервиса, пака или версии, которые требуют восстановления.

<Warning>
  Не обходите решение об отказе путём удаления файлов сервиса или пака. Восстановите сервис, переустановите пак или удалите назначение через CLI, чтобы машина вернулась в известное состояние.
</Warning>
