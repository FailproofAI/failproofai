Охват флота показывает, существует ли политика там, где существует риск. Отслеживайте машины по стабильному идентификатору и понятному человеку метке, затем сравнивайте назначенное и сообщаемое состояние развертывания.

## Проверка охвата

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Admin → enforcement** и проверьте итоги по применению и наблюдению.
    2. Найдите машину по ID или метке либо отфильтруйте машины без политики.
    3. Разверните строку, чтобы сравнить назначенные политики, сообщаемое развертывание, время последней проверки и историю.
    4. Обновите информацию после интервала опроса машины, если примененное развертывание остается в ожидании.

    ![Флот Enforcement, показывающий охват политик, состояние развертывания машины и назначения наблюдения и применения.](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    Используйте `fp events --agent-id <agent-id> --since 24h`, чтобы подтвердить, что активность агента машины достигает Cloud.
  </Tab>
</Tabs>

Используйте представления охвата для поиска:

- Машин, которые никогда не получали последнее развертывание
- Зарегистрированных машин, которые перестали сообщать о своей активности
- Политики, назначенной неправильной среде или когорте
- Дрейфа версий после прерванного обновления

Переименуйте машину без повторного подключения:

```bash
failproofai config --machine-label checkout-runner-03
```

Проверьте локальное состояние:

```bash
failproofai config --status
```

<Tip>
  Используйте метки, которые идентифицируют рабочую нагрузку и среду. Одних только имен хостов часто недостаточно после автомасштабирования или замены машины.
</Tip>
