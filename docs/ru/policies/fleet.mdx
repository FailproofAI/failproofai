Охват флота показывает, есть ли политика там, где существует риск. Отслеживайте машины по стабильному ID и удобочитаемому ярлыку, затем сравнивайте назначенное и сообщаемое состояние развертывания.

## Проверка охвата

<Tabs>
  <Tab title="Панель управления">
    1. Перейдите в **Admin → enforcement** и проверьте итоговые значения для режимов enforcement и observing.
    2. Найдите машину по ID или ярлыку либо отфильтруйте машины, у которых отсутствует политика.
    3. Разверните строку, чтобы сравнить назначенные политики, сообщаемое развертывание, время последней проверки и историю.
    4. Обновите результаты по истечении интервала опроса машины, если примененное развертывание остается в статусе ожидания.

    ![Флот Enforcement, показывающий охват политик, состояние развертывания машины и назначения observe и enforce.](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    Используйте `fp events --agent-id <agent-id> --since 24h`, чтобы подтвердить, что активность агента машины достигает Cloud.
  </Tab>
</Tabs>

Используйте представления охвата для поиска:

- Машин, которые никогда не загружали последнее развертывание
- Зарегистрированных машин, прекративших отправку активности
- Политики, назначенной неправильной среде или когорте
- Дрейф версий после прерванного обновления

Переименование машины без переподключения:

```bash
failproofai config --machine-label checkout-runner-03
```

Проверка локального состояния:

```bash
failproofai config --status
```

<Tip>
  Используйте ярлыки, которые определяют рабочую нагрузку и среду. Только имена хостов часто недостаточно после автомасштабирования или замены машины.
</Tip>
