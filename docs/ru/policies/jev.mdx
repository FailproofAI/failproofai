Jev анализирует вызов инструмента в сравнении с тем, что человек попросил сделать агента. Используйте это, когда политика на основе сопоставления строк блокирует допустимую работу или упускает рискованное действие, требующее контекста. Она отвечает вместе с вашими политиками на этапе `PreToolUse` или `PermissionRequest`. Чтобы получить оценку **после** завершения сеанса, используйте [Jev evaluations](/ru/evaluations/jev).

## Начните в режиме наблюдения

Установите Failproof AI и подключите hooks к [поддерживаемой среде](/ru/reference/harnesses). Используйте failproofai 1.0.8-beta.0 или более позднюю версию.

Failproof AI поставляется без проверок Jev. Установите их как пакет, иначе у Jev не будет вопросов и она никогда не будет вызвана:

```bash
failproofai policies add FailproofAI/jev-policies
```

Затем выберите, как запросы будут отправлены в Jev:

| Маршрут | Первый шаг |
| --- | --- |
| FailproofAI Cloud | Подключитесь с использованием **machine** ключа с разрешением `jev:evaluate`. На машине без конфигурации Jev команда `failproofai config` включает Jev в режиме наблюдения. |
| Ваш собственный провайдер | В локальной панели управления откройте **Settings → Jev**, выберите провайдера, вставьте его токен и выберите **observe**. Или выполните `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key`. |

![Параметры Jev в локальной панели управления: провайдер, endpoint, токен и режим наблюдения перед включением Jev.](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` проверяет endpoint. Чтобы проверить путь hook, попросите подключённого агента использовать его инструмент для чтения файлов на `README.md`. Подтвердите, что этот вызов инструмента появляется в сеансе, затем проверьте **Policies → Activity** в [локальной панели управления](/ru/reference/local-dashboard#review-policy-activity). Счётчик Jev в `status` должен увеличиться. Режим наблюдения записывает, что Jev решила бы, в то время как результат вашей существующей политики остаётся в силе.

## Решите, когда применять

**Жёсткая** политика всегда имеет последнее слово. Jev может отменить отказ только из политики, явно отмеченной как **reviewable**, и только когда она проверила названную проблему этой политики. Смотрите [authority политики](/ru/policies/authority) перед тем, как полагаться на одобрение. Jev также может выдавать предупреждение или отказ самостоятельно. Если она не может ответить, результат политики решает судьбу этого вызова.

После того как результаты наблюдения выглядят правильно, переключитесь в режим применения в **Settings → Jev** или выполните:

```bash
failproofai jev setup --mode enforce
```

Для URL провайдеров, Cloud ключей, конфигурации, fallback-ов и данных, отправляемых с каждым запросом, смотрите [Jev reference интеграции](/ru/reference/jev).
