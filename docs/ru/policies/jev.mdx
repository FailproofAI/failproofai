Jev проверяет вызов инструмента на соответствие тому, что пользователь попросил у агента. Используйте её когда политика сопоставления строк блокирует корректную работу или упускает рискованное действие, требующее контекста. Она дает ответ рядом с вашими политиками на этапе `PreToolUse` или `PermissionRequest`. Для оценки **после** окончания сессии используйте [оценки Jev](/ru/evaluations/jev).

## Начните в режиме наблюдения

Установите Failproof AI и подключите хуки к [поддерживаемому интеграционному слою](/ru/reference/harnesses). Используйте failproofai 1.0.8-beta.0 или более позднюю версию.

Failproof AI поставляется без проверок Jev. Установите их пакетом, иначе Jev не будет ничего проверять и никогда не будет вызвана:

```bash
failproofai policies add FailproofAI/jev-policies
```

Затем выберите, как запросы попадут к Jev:

| Маршрут | Первый шаг |
| --- | --- |
| FailproofAI Cloud | Подключитесь с использованием **машинного** ключа с правом `jev:evaluate`. На машине без конфигурации Jev команда `failproofai config` включает Jev в режиме наблюдения. |
| Ваш собственный провайдер | В локальной панели откройте **Settings → Jev**, выберите провайдера, вставьте его токен и выберите **observe**. Или выполните `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key`. |

![Параметры Jev в локальной панели: провайдер, endpoint, токен и режим наблюдения перед включением Jev.](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` проверяет endpoint. Чтобы проверить путь хука, попросите агента с хуками использовать свой инструмент чтения файлов на `README.md`. Убедитесь, что этот вызов инструмента появится в сессии, затем проверьте **Policies → Activity** в [локальной панели](/ru/reference/local-dashboard#review-policy-activity). Счетчик Jev в `status` должен увеличиться. Режим наблюдения записывает, какое решение принял бы Jev, в то время как ваш существующий результат политики остается в силе.

## Решите, когда применять

**Жесткая** политика всегда имеет окончательное слово. Jev может отменить только решение deny из политики, явно отмеченной как **reviewable**, и только когда она проверила названную задачу этой политики. Прежде чем полагаться на отмену, см. [полномочия политики](/ru/policies/authority). Jev также может выдать предупреждение или отказ самостоятельно. Если она не может ответить, результат политики определяет этот вызов.

После того как результаты наблюдения выглядят корректно, переключитесь в режим применения в **Settings → Jev** или выполните:

```bash
failproofai jev setup --mode enforce
```

Для URL провайдеров, облачных ключей, конфигурации, резервных вариантов и данных, отправляемых с каждым запросом, см. [справочник интеграции Jev](/ru/reference/jev).
