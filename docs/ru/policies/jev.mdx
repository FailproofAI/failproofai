Jev анализирует вызов инструмента с учётом того, что пользователь попросил агента сделать. Используйте его, когда политика на основе совпадений текста блокирует корректную работу или пропускает рискованное действие, требующее контекста. Он даёт ответ наряду с вашими политиками на gate `PreToolUse` или `PermissionRequest`. Для оценки **после** завершения сеанса используйте [Jev evaluations](/ru/evaluations/jev).

## Начните в режиме наблюдения

Установите Failproof AI и подключите hooks к [поддерживаемому окружению](/ru/reference/harnesses). Используйте failproofai версии 1.0.8-beta.0 или выше.

Failproof AI не содержит встроенных проверок Jev. Установите их как пакет, иначе Jev не будет задавать вопросы и никогда не будет вызван:

```bash
failproofai policies add FailproofAI/jev-policies
```

Затем выберите, как запросы будут передаваться Jev:

| Маршрут | Первый шаг |
| --- | --- |
| FailproofAI Cloud | Подключитесь с использованием **machine** ключа, имеющего `jev:evaluate`. На машине без конфигурации Jev команда `failproofai config` включает Jev в режиме наблюдения. |
| Ваш собственный провайдер | В локальной панели управления откройте **Settings → Jev**, выберите провайдера, вставьте его token и выберите **observe**. Или запустите `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key`. |

![Параметры Jev в локальной панели управления: провайдер, endpoint, token и режим наблюдения перед включением Jev.](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` проверяет endpoint. Чтобы проверить путь hook, попросите агента с hooks использовать его инструмент чтения файлов на `README.md`. Убедитесь, что этот вызов инструмента появляется в сеансе, затем проверьте **Policies → Activity** в [локальной панели управления](/ru/reference/local-dashboard#review-policy-activity). Количество Jev в `status` должно увеличиться. Режим наблюдения записывает, что решил бы Jev, тогда как результат вашей существующей политики остаётся в силе.

## Решите, когда применять

**Hard** политика всегда имеет решающий голос. Jev может отменить deny только из политики, явно отмеченной как **reviewable**, и только когда он проверил названную проблему этой политики. Перед тем как полагаться на согласование, см. [policy authority](/ru/policies/authority). Jev может также выдавать предупреждение или deny самостоятельно. Если он не может ответить, результат политики определяет этот вызов.

Когда результаты наблюдения выглядят правильно, переключитесь в режим enforce в **Settings → Jev** или запустите:

```bash
failproofai jev setup --mode enforce
```

Для URL провайдеров, облачных ключей, конфигурации, fallbacks и данных, отправляемых с каждым запросом, см. [Jev integration reference](/ru/reference/jev).
