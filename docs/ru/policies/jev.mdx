Jev проверяет вызов инструмента с учётом того, что человек попросил сделать агента. Используйте его, когда политика на основе сопоставления строк блокирует корректную работу или пропускает рискованное действие, требующее контекста. Jev отвечает рядом с вашими политиками на этапе `PreToolUse` или `PermissionRequest`. Для оценки **после** завершения сессии используйте [Jev evaluations](/ru/evaluations/jev).

## Начните в режиме наблюдения

Установите Failproof AI и подключите hooks к [поддерживаемой системе](/ru/reference/harnesses). Используйте failproofai 1.0.8-beta.0 или более позднюю версию.

Failproof AI не поставляется с проверками Jev. Установите их как пакет, иначе Jev не будет иметь что проверять и никогда не будет вызван:

```bash
failproofai policies add FailproofAI/jev-policies
```

Затем выберите, как запросы будут поступать в Jev:

| Маршрут | Первый шаг |
| --- | --- |
| FailproofAI Cloud | Подключитесь с использованием **machine** ключа с правом `jev:evaluate`. На машине без конфигурации Jev команда `failproofai config` включит Jev в режиме наблюдения. |
| Ваш собственный провайдер | В локальной панели управления откройте **Settings → Jev**, выберите провайдера, вставьте его токен и выберите **observe**. Или запустите `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key`. |

![Параметры Jev в локальной панели управления: провайдер, endpoint, токен и режим наблюдения перед включением Jev.](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` проверяет endpoint. Чтобы проверить путь hook, попросите подключённого агента использовать инструмент чтения файлов для `README.md`. Убедитесь, что этот вызов инструмента отображается в сессии, затем проинспектируйте **Policies → Activity** в [локальной панели управления](/ru/reference/local-dashboard#review-policy-activity). Счётчик Jev в `status` должен увеличиться. Режим наблюдения фиксирует, что решил бы Jev, пока ваш существующий результат политики остаётся в силе.

## Решите, когда применить

**Жёсткая** политика всегда имеет решающее слово. Jev может отменить отказ только из политики, явно помеченной как **reviewable**, и только когда он проверил её названную проблему. Перед тем как полагаться на разрешение, см. [policy authority](/ru/policies/authority). Jev также может предупредить или отказать самостоятельно. Если он не может ответить, результат политики определяет этот вызов.

Когда результаты наблюдения выглядят правильно, переключитесь в режим enforce в **Settings → Jev** или запустите:

```bash
failproofai jev setup --mode enforce
```

Для URL провайдеров, Cloud ключей, конфигурации, fallbacks и данных, отправляемых с каждым запросом, см. [Jev integration reference](/ru/reference/jev).
