Jev анализирует вызов инструмента с учетом того, что человек попросил агента сделать. Используйте его, когда политика совпадения строк блокирует допустимую работу или пропускает рискованное действие, требующее контекста. Он отвечает наряду с вашими политиками на вратах `PreToolUse` или `PermissionRequest`. Для оценки **после** завершения сеанса используйте [Jev evaluations](/ru/evaluations/jev).

## Начните с режима наблюдения

Установите Failproof AI и подключите хуки к [поддерживаемой системе](/ru/reference/harnesses). Используйте failproofai 1.0.8-beta.0 или более позднюю версию.

Failproof AI поставляется без проверок Jev. Установите их как пакет, иначе Jev не будет иметь ничего для проверки и никогда не будет вызван:

```bash
failproofai policies add FailproofAI/jev-policies
```

Затем выберите, как запросы достигнут Jev:

| Маршрут | Первый шаг |
| --- | --- |
| FailproofAI Cloud | Подключитесь с помощью **machine** ключа с разрешением `jev:evaluate`. На машине без конфигурации Jev команда `failproofai config` включает Jev в режиме наблюдения. |
| Ваш собственный поставщик | В локальной панели инструментов откройте **Settings → Jev**, выберите поставщика, вставьте его токен и выберите **observe**. Или выполните `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key`. |

![Параметры Jev локальной панели инструментов: поставщик, конечная точка, токен и режим наблюдения перед включением Jev.](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` проверяет конечную точку. Для проверки пути хука попросите подключенный агент использовать его инструмент чтения файлов для `README.md`. Убедитесь, что этот вызов инструмента появляется в сеансе, затем проверьте **Policies → Activity** в [локальной панели инструментов](/ru/reference/local-dashboard#review-policy-activity). Счетчик Jev в `status` должен увеличиться. Режим наблюдения записывает, что Jev решил бы, пока ваш существующий результат политики все еще применяется.

## Решите, когда применять

**Hard** политика всегда имеет последнее слово. Jev может отменить запрет только из политики, явно отмеченной как **reviewable**, и только если она проверила именованную проблему этой политики. Перед тем как полагаться на разрешение, см. [policy authority](/ru/policies/authority). Jev также может предупредить или отклонить самостоятельно. Если он не может ответить, результат политики определяет этот вызов.

После того как результаты наблюдения выглядят правильно, переключитесь в режим enforce в **Settings → Jev** или выполните:

```bash
failproofai jev setup --mode enforce
```

Для URL поставщиков, облачных ключей, конфигурации, резервных вариантов и данных, отправляемых с каждым запросом, см. [Jev integration reference](/ru/reference/jev).
