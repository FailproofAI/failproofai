Jev проверяет вызов инструмента против того, что попросил агента сделать человек. Используйте его, когда string-matching политика блокирует корректную работу или пропускает рискованное действие, требующее контекста. Он отвечает рядом с вашими политиками на шаге `PreToolUse` или `PermissionRequest`. Для оценки **после** завершения сеанса используйте [Jev evaluations](/ru/evaluations/jev).

## Начните с режима наблюдения

Установите Failproof AI и подключите hooks к [поддерживаемому harness](/ru/reference/harnesses). Используйте failproofai версии 1.0.8-beta.0 или позже.

Failproof AI поставляется без checks Jev. Установите их как пакет, иначе Jev не будет спрашивать ничего и никогда не будет вызван:

```bash
failproofai policies add FailproofAI/jev-policies
```

Затем выберите, как запросы попадают к Jev:

| Маршрут | Первый шаг |
| --- | --- |
| FailproofAI Cloud | Подключитесь с **machine** ключом, имеющим `jev:evaluate`. На машине без конфигурации Jev, `failproofai config` включает Jev в режим наблюдения. |
| Ваш собственный провайдер | В локальной панели управления откройте **Settings → Jev**, выберите провайдера, вставьте его токен и выберите **observe**. Или запустите `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key`. |

![Параметры Jev в локальной панели управления: провайдер, endpoint, токен и режим наблюдения перед включением Jev.](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` проверяет endpoint. Чтобы проверить путь hook, попросите подключенного агента использовать свой инструмент чтения файлов на `README.md`. Убедитесь, что вызов инструмента появляется в сеансе, затем проверьте **Policies → Activity** в [локальной панели управления](/ru/reference/local-dashboard#review-policy-activity). Счетчик Jev в `status` должен увеличиться. Режим наблюдения записывает, что решил бы Jev, пока ваш существующий результат политики все еще применяется.

## Решите, когда применять

**Hard** политика всегда имеет решающий голос. Jev может отменить deny только из политики, явно отмеченной как **reviewable**, и только если она проверила названную задачу этой политики. См. [policy authority](/ru/policies/authority) перед тем, как полагаться на разрешение. Jev также может предупредить или отклонить самостоятельно. Если он не может ответить, результат политики решает судьбу этого вызова.

После того как результаты наблюдения выглядят правильно, переключитесь на режим enforce в **Settings → Jev** или запустите:

```bash
failproofai jev setup --mode enforce
```

Информацию об URL провайдера, ключах Cloud, конфигурации, fallbacks и данных, отправляемых с каждым запросом, см. в [reference интеграции Jev](/ru/reference/jev).
