Failproof AI разделяет содержимое репозитория — подключение хуков, параметры политик, пользовательские политики — от машинного состояния, такого как учетные данные, установленные пакеты и демон.

## Выберите область действия

Область действия определяет, где подключаются хуки и в какой файл конфигурации вы записываете параметры и пути к пользовательским политикам:

- **User** применяется ко всем проектам на этой машине.
- **Project** принадлежит репозиторию и может быть закоммичена.
- **Local** переопределяет один проект для одного пользователя и должна оставаться в gitignore.

```bash
failproofai policies --install --cli claude --scope project   # wire hooks for this repository
failproofai policies --install --cli claude --scope user      # or for every project on this machine
failproofai policies
```

Не все инструменты поддерживают локальную область действия; CLI отклоняет область, которую выбранный инструмент не может представить.

То, какие политики пакета включены, **не** входит в область действия. Переключатель записывается вместе с установленным пакетом, поэтому `failproofai policies add <name>` включает политику для всей машины, независимо от `--scope`.

| Область действия | Файл конфигурации политик |
| --- | --- |
| Project | `<project>/.failproofai/policies-config.json` |
| Local | `<project>/.failproofai/policies-config.local.json` |
| User | `~/.failproofai/policies-config.json` |

Параметры политик используют первую область действия, которая определяет параметры для этой политики, в порядке project → local → user. Явные пути к пользовательским политикам используют первую область действия, которая их определяет.

## Настройте параметры политик

<Tabs>
  <Tab title="Dashboard">
    Откройте политику в локальной приборной панели, отредактируйте поддерживаемые параметры и сохраните в выбранную область действия. Запустите действие агента, которое совпадает и не совпадает, затем посмотрите решение в **Observe → policy**.

  </Tab>
  <Tab title="CLI">
    Отредактируйте `policies-config.json` в выбранной области действия, затем запустите `failproofai policies`: оно выдаст предупреждение о записи `policyParams`, которая называет политику, которую не несет ни один установленный пакет. Он не проверяет ключи внутри записи, поэтому проверьте их орфографию в таблице ниже.

    ```json
    {
      "policyParams": {
        "block-rm-rf": {
          "allowPaths": ["/tmp/build-output"]
        }
      }
    }
    ```

    ```bash
    failproofai policies
    ```
  </Tab>
</Tabs>

### Параметры, которые принимают политики Failproof AI

Каждая политика самостоятельно проверяет типы своих параметров.

| Политика | Параметр | Тип и значение по умолчанию |
| --- | --- | --- |
| `sanitize-api-keys` | `additionalPatterns` | `pattern[]`, `[]`; записи содержат `regex` и `label` |
| `block-read-outside-cwd` | `allowPaths` | `string[]`, `[]` |
| `block-sudo` | `allowPatterns` | `string[]`, `[]` |
| `block-rm-rf` | `allowPaths` | `string[]`, `[]` |
| Infrastructure blockers | `allowPatterns` | `string[]`, `[]` |
| `block-secrets-write` | `additionalPatterns` | `string[]`, `[]` |
| `block-push-master` | `protectedBranches` | `string[]`, `["main", "master"]` |
| `block-work-on-main` | `protectedBranches` | `string[]`, `["main", "master"]` |
| `prefer-package-manager` | `allowed`, `blocked` | `string[]`, `[]` |
| `warn-large-file-write` | `thresholdKb` | `number`, `1024` |
| `require-push-before-stop` | `remote`, `baseBranch` | `string`, `"origin"`; `string`, `"main"` |
| `require-pr-before-stop` | `baseBranch` | `string`, `"main"` |
| `require-no-conflicts-before-stop` | `baseBranch` | `string`, `"main"` |

<Warning>
  Разрешающий шаблон расширяет то, что может делать агент. Протестируйте точную токенизацию и варианты команд на целевом инструменте перед развертыванием на множество машин.
</Warning>

## Разберитесь в машинных файлах

`~/.failproofai` содержит отдельные файлы для отдельных границ доверия:

| Путь | Назначение |
| --- | --- |
| `config.json` | Некритичные параметры демона, аудита и телеметрии |
| `credentials.json` | Облачные учетные данные; хранятся с разрешениями только для владельца |
| `policies-config.json` | Параметры области пользователя и явные пути к пользовательским политикам |
| `policies/` | Условные политики пользователя, установленные пакеты и которые их политики включены, а также артефакты политик, управляемые облаком |
| `hook-activity/` | Локальный журнал решений политик |
| `state/` | Очередь демона, состояние здоровья, пауза и состояние выполнения |

Используйте `FAILPROOFAI_HOME` для перемещения полного макета машины для контейнера или изолированного теста. Не переумещайте отдельные каталоги состояния независимо.

<Warning>
  Никогда не коммитьте `credentials.json`. Коммитьте конфигурацию политик проекта и условные политики проекта только после проверки их как кода обеспечения.
</Warning>
