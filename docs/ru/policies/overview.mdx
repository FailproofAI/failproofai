Политика отслеживает действие агента и возвращает одно из трёх решений:

- `allow` — продолжить.
- `instruct` — дать агенту рекомендацию, если его окружение это поддерживает.
- `deny` — заблокировать действие.

Используйте политики для известного, повторяющегося поведения: удаление защищённых файлов, раскрытие секретов, push в неправильную ветку или изменение production-инфраструктуры.

## Добавьте политики на этот компьютер

Setup не выбирает пакет политик по умолчанию. Добавьте пакет Failproof AI после установки:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai policies
```

Пакет не содержит привилегированную встроенную политику. Наша устанавливается так же, как и любая другая.

Политики также могут поступать из локального файла, опубликованного пакета или облачного назначения:

| Источник | Способ добавления |
| --- | --- |
| Локальный файл | Поместите `*policies.{js,mjs,ts}` в `.failproofai/policies/` |
| Любой путь файла | `failproofai policies -i -c <path>` |
| Опубликованный пакет | `failproofai policies add <owner>/<repo>` |
| Облако | Назначьте в панели управления или с помощью `fp fleet deploy` |

`block-failproofai-commands` всегда работает и не может быть отключена. Она предотвращает отключение агентом собственного контроля.

## Наблюдайте перед внедрением

Режим наблюдения запускает реальную политику и записывает, что она сделала бы, но не блокирует агента.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

<Warning>
  Обычная команда `fp fleet deploy <machine> --add <id>` активирует контроль немедленно. Добавьте `:observe` для постепенного развёртывания в режиме наблюдения.
</Warning>

Политика, превысившая время ожидания в режиме наблюдения, записывает решение allow, потому что именно это произойдёт при активном контроле. Записываются только наблюдаемые решения, отличные от allow.

Для пакета, используемого без облака, опубликуйте его с помощью `failproofai publish --effect observe`.
