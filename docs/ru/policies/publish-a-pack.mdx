Создайте рабочую политику, протестируйте её локально, затем опубликуйте как пакет.

## Создание и тестирование

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

`--init` создаёт политику, которая уже блокирует `git push --force`. Отредактируйте её, попросите агента попробовать заблокированное действие и проверьте **Policies → Activity** в локальной панели управления.

Политика пакета может включать:

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-refunds",
  description: "Refunds above the limit need a human",
  category: "Billing",
  defaultEnabled: true,
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) => {
    // return allow(), instruct(), or deny()
  },
});
```

`defaultEnabled` по умолчанию имеет значение `false`.

## Публикация

Зафиксируйте ваши файлы, затем запустите:

```bash
failproofai publish
```

Publish находит файл политики, валидирует его тем же загрузчиком, который используется при установке, и загружает ресурсы пакета в GitHub релиз. Использует `GITHUB_TOKEN`, `GH_TOKEN` или `gh auth login`.

Репозиторий должен быть публичным, так как установка использует анонимный HTTPS.

Версия по умолчанию — это 12-символьный SHA текущего коммита. Publish отказывает при загрязнённом дереве или директории вне Git, если вы не укажете `--version`. Тег на `HEAD` имеет приоритет над SHA.

Пользователи устанавливают это командой:

```bash
failproofai policies add owner/repo
```

## Публикация в режиме наблюдения

```bash
failproofai publish --effect observe
```

Режим наблюдения вычисляет реальную политику и записывает решения, которые не являются разрешением, но позволяет агенту продолжить работу. Таймаут записывается как разрешение.

Опубликуйте снова с `--effect enforce`, когда наблюдаемые совпадения корректны.

## Полезные опции

| Флаг | Действие |
| --- | --- |
| `--init [file]` | Записать стартовую политику |
| `--repo <owner>/<repo>` | Выбрать или создать репозиторий |
| `--version <version>` | Переопределить версию, основанную на коммите |
| `--effect enforce\|observe` | Выбрать, блокирует ли пакет |
| `--dry-run` | Собрать и валидировать без публикации |
| `--allow-private` | Опубликовать приватно, зная, что `policies add` не может его установить |

```bash
failproofai publish --dry-run
failproofai publish ./guards.mjs --repo me/guards --version 2.0.0
```

<Note>
  Добавьте GitHub тему `failproofai-policies` после публикации, чтобы [Policy Hub](https://befailproof.ai/policy-hub/) мог индексировать пакет. CLI не делает это за вас.
</Note>

<Warning>
  Переименование политики — это критическое изменение для существующих выборок. Сохраняйте имена стабильными между релизами.
</Warning>
