Откат изменяет развернутую версию или удаляет назначение политики; при этом не стирается история решений, которая объясняет инцидент.

## Откатить машину

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Admin → enforcement**, разверните затронутую машину и определите последний известный хороший набор политик.
    2. Выберите **edit**, восстановите эти версии и эффекты, затем примените новое развертывание.
    3. Подождите регистрации машины, затем проверьте сообщаемое развертывание.
    4. Откройте **Observe → policy** и затронутые сеансы, чтобы подтвердить, что корректная работа больше не блокируется.

  </Tab>
  <Tab title="CLI">
    Найдите поколение, к которому вернуться, восстановите его, затем подтвердите доставку:

    ```bash
    fp fleet history ci-runner-01
    fp fleet rollback ci-runner-01 3
    fp fleet diff ci-runner-01
    failproofai config --status
    ```

    `fp fleet rollback` создает **новое** поколение, содержащее старый набор, а не откатывает счетчик, поэтому история остается добавляемой только. Он отказывается, если это поколение ссылается на политику, которая с тех пор была отключена или удалена — сервер сообщает об этом вместо того, чтобы восстанавливать набор, который невозможно доставить.

    `fp fleet diff` показывает намерение и доставку. Машина считается отклонившейся от курса до следующего опроса, поэтому проверьте различие перед тем, как заключить, что откат не прошел. `failproofai config --status` подтверждает это на самой машине.
  </Tab>
</Tabs>

## Пауза — это не откат

Пауза приостанавливает каждую локально установленную политику на **один сеанс** и всегда истекает сама по себе — пакеты, пользовательские файлы, файлы соглашений и встроенные программы. Только управляемые облаком политики и всегда включенный охранник `block-failproofai-commands` продолжают действовать. Таким образом, пауза не является обходным решением для плохого облачного развертывания, и радиус взрыва больше, чем кажется: пакет — это место, где по сути вся локальная enforcement находится, и охранник отказа пакета также пропускается в течение этого времени.

| Команда | Эффект |
|---|---|
| `failproofai config --pause` | Самый новый сеанс агента этого каталога, в течение 30 минут |
| `failproofai config --pause 10m` | Заданное время. Максимум 8ч; суффиксы `s`/`m`/`h`, число без суффикса означает минуты |
| `failproofai config --pause --session <id>` | Целевой конкретный сеанс |
| `failproofai config --resume` | Завершить паузу раньше |
| `failproofai config --resume --all` | Завершить все активные паузы |
| `failproofai config --status` | Что поставлено на паузу и когда она истечет |

## Когда откатить

- Политика блокирует ожидаемое действие в production.
- Объем совпадений существенно выше, чем предсказывал наблюдаемый откат.
- Политика зависит от полей, которые интеграция не предоставляет.
- Новая версия изменяет поведение за пределами предполагаемого режима отказа.

После отката откройте затронутые сеансы и определите условие, вызвавшее ложный срабатывание. Создайте новую версию, протестируйте как небезопасный, так и легитимный вариант локально, затем снова просмотрите перед повторным принятием:

```bash
fp policies test ./policy.mjs --tool Bash --command '<the legitimate case>' --expect allow
fp policies publish my-policy ./policy.mjs
fp fleet deploy ci-runner-01 --add my-policy:observe
fp guardrails summary --since 24h --machine ci-runner-01
```

`:observe` — это то, что делает это теневым откатом. Простой `fp fleet deploy ... --add my-policy` **применяет немедленно** — пропущенный эффект разрешается эффектом, уже развернутым, а затем `enforce` — что для только что откатанной политики означает возобновление инцидента. Режим Observe по-прежнему оценивает политику в реальности и записывает каждый вердикт, отличный от allow; только enforcement удерживается, поэтому `fp guardrails summary` измеряет новую версию против того же трафика, который сломал старую. Повысьте уровень с помощью `--add my-policy:enforce`, когда цифры позволяют.

<Warning>
  Приостановка enforcement может быть подходящей во время инцидента, но она расширяет воздействие для каждой активной политики в этой области. Предпочитайте откатить определенную версию политики, когда это возможно.
</Warning>
