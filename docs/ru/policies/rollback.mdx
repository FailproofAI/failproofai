Откат изменяет развернутую версию или удаляет назначение политики; при этом история решений, объясняющая инцидент, не стирается.

## Откатить машину

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Admin → enforcement**, разверните затронутую машину и определите её последний известный хороший набор политик.
    2. Выберите **edit**, восстановите эти версии и эффекты, затем примените новое развертывание.
    3. Дождитесь проверки машины, затем проверьте сообщённое развертывание.
    4. Откройте **Observe → policy** и затронутые сеансы, чтобы убедиться, что корректная работа больше не блокируется.

  </Tab>
  <Tab title="CLI">
    Откат облачного развертывания — это рабочий процесс через dashboard. Используйте локальный статус для проверки того, что исправленное развертывание достигло машины:

    ```bash
    failproofai config --status
    ```

    `failproofai config --pause` приостанавливает встроенные, пользовательские и условные политики на один локальный сеанс. Он не приостанавливает управляемые Cloud политики, поэтому это не решение для неправильного облачного развертывания.
  </Tab>
</Tabs>

## Когда откатывать

- Политика блокирует ожидаемое действие в production.
- Объём совпадений значительно выше, чем предсказала наблюдаемая выкатка.
- Политика зависит от полей, которые интеграция не предоставляет.
- Новая версия изменяет поведение вне предполагаемого режима отказа.

После отката откройте затронутые сеансы и определите условие, вызвавшее ложный срабатывание. Создайте новую версию, протестируйте как небезопасные, так и допустимые случаи, затем повторите фазу наблюдения.

<Warning>
  Приостановка enforcement может быть уместна во время инцидента, но она расширяет уязвимость для каждой активной политики в этой области. По возможности предпочитайте откат конкретной версии политики.
</Warning>
