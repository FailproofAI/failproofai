Используйте `fp` для проверки телеметрии Cloud, управления облачным принудительным применением (политики, развертывания флота, решения guardrail) и управления аудитами, находками, проблемами, оповещениями, ключами, пользователями, запросами и параметрами. Используйте [`failproofai`](/ru/reference/failproof-cli) для локальных хуков, политик, захвата и регистрации машин.

Установите выпущенный Cloud CLI как изолированный инструмент:

```bash
uv tool install fp-cloud-cli
fp version
```

## Вход в систему

```bash
fp login
fp whoami
```

## Синтаксис

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Глобальные параметры должны предшествовать команде:

```bash
fp --json sessions --since 24h
```

Запустите `fp COMMAND --help` или `fp COMMAND SUBCOMMAND --help` для справки в терминале.

### События

```text
fp events [OPTIONS]
```

Список отдельных событий агента. Легкий канал по умолчанию исключает необработанные полезные нагрузки; используйте `--full` только для ограниченного расследования.

| Параметр | Описание |
| --- | --- |
| `--limit`, `-n <n>` | Максимальное количество строк. По умолчанию: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` или `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Диапазон ISO 8601 UTC; переопределяет `--since`. |
| `--env <value>` | Фильтр окружения; повторяйте или разделяйте запятыми. |
| `--event-type <value>` | Фильтр типа события; повторяйте или разделяйте запятыми. |
| `--agent-id <value>` | Фильтр агента; повторяйте или разделяйте запятыми. |
| `--session-id <value>` | Фильтр сеанса; повторяйте или разделяйте запятыми. |
| `--search <text>` | Поиск текста в полезной нагрузке; повторяется с совпадением любого термина. |
| `--order asc\|desc` | Порядок времени. По умолчанию: новые в первую очередь. |
| `--all` | Автоматическая пагинация до `--limit`. |
| `--cursor <token>` | Возобновить с непрозрачного курсора. |
| `--page-size <n>` | Строк на запрос с `--all`; максимум `200`. |
| `--full` | Включить необработанные полезные нагрузки через более тяжелую конечную точку события. |
| `--fields <csv>` | Вернуть только выбранные поля; запрос `payload` включает полный режим. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` пагинирует **до `--limit`**, который по умолчанию равен **50** — так что `--all` сам по себе останавливается на 50 строках. Когда останавливается рано, ответ несет `next_cursor` для возобновления; `"next_cursor": null` означает, что канал действительно исчерпан.
</Note>

#### Параметры создания аудита

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Параметр | Описание |
| --- | --- |
| `--file <path>` | Основать определение на JSON или использовать `-` для stdin. Явные флаги переопределяют значения файла. |
| `--description <text>` | Сформулировать вопрос об отказе или цель. |
| `--enabled` / `--disabled` | Запустить планирование вкл. или выкл. По умолчанию: включено. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. По умолчанию: `86400`. |
| `--schedule-anchor <timestamp>` | Фиксированная фаза UTC в форме ISO 8601. По умолчанию: следующее 09:00 UTC. |
| `--window-mode since_last\|fixed` | Продолжить после последнего полностью проанализированного окна или повторно проверить скользящее окно. По умолчанию: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. По умолчанию: `604800`. |
| `--scope '<json>'` | Фильтровать по `environments`, `agent_ids` или другим поддерживаемым полям области. |
| `--ignore-error-type <type>` | Исключить типы ошибок; повторяйте или разделяйте запятыми. |
| `--llm` / `--no-llm` | Включить или отключить анализ с помощью агентов. По умолчанию: включено. |
| `--top-k <n>` | Сохранить `1`–`500` находок. По умолчанию: `50`. |
| `--sensitivity low\|medium\|high` | Установить чувствительность отчетности. По умолчанию: `medium`. |
| `--channels '<json>'` | Массив канала уведомлений. |
| `--text <brief>` | Встроенное краткое описание, максимум 8192 символа. |
| `--text-file <path>` | Прочитать краткое описание из файла; взаимоисключающие с `--text`. |
| `--url <https-url>` | Добавить публичную справку HTTPS; повторяйте до пяти раз. |

Включите контекст при создании, когда первый запуск его нужен. Создание фиксирует определение и контекст вместе перед началом поставленного в очередь запуска.

<Note>
  `fp audits run` асинхронный. Опрашивайте `fp audits runs NAME` до тех пор, пока последний запуск не завершится успехом или неудачей, перед чтением его находок.
</Note>

### Политики

Версии управляемых облаком политик. **Только для сеанса** — каждая команда здесь выходит с `2` под ключом API, перед любым запросом, так как это корневые маршруты записи, намеренно отсутствующие в `/v1`.

| Команда | Назначение | Параметры |
| --- | --- | --- |
| `fp policies list` | Список версий политик. | `--json` |
| `fp policies show POLICY_ID` | Показать одну политику с ее исходным кодом. | — |
| `fp policies publish NAME PATH` | Создать версию из локального `.mjs`. | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | Добавить обратно в каждое развертывание, из которого она была удалена, создав новое поколение на каждом. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | Удалить из каждого развертывания, которое ее использует, создав новое поколение на каждом. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | Удалить версию политики. | `--yes`, `-y` |
| `fp policies test PATH` | Запустить политику локально против синтетического контекста. Применяет фильтр `match` каждой политики, поэтому политика, которая не охватывает данное событие/инструмент, сообщается как `skipped` вместо запуска. | `--event`; `--tool`; `--command`; `--file-path`; `--expect` |
| `fp policies compose PROMPT` | Составить политику с помощью помощника. Требует `policies:write`. | — |

## Глобальные флаги

| Флаг | Описание |
| --- | --- |
| `--json` | Вывести машиночитаемый JSON. |
| `--base-url <url>` | Использовать самохостируемую или разработческую панель управления. |
| `--org <slug>` | Выбрать организацию для этого вызова. |
| `--token <token>` | Переопределить сохраненный маркер сеанса пользователя. |
| `--api-key <key>` | Аутентифицировать автоматизацию с помощью ключа API; никогда не сохраняется. |
| `--timeout <seconds>` | Тайм-аут HTTP; должен быть положительным. По умолчанию: `30`. |

## Переменные окружения

| Переменная | Эквивалент или назначение |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | Переместить каталог конфигурации CLI (по умолчанию `~/.failproofai/fpcli`). |
| `FP_ANALYTICS_DISABLED` или `DO_NOT_TRACK` | Отключить анонимную аналитику CLI. |
| `NO_COLOR` | Отключить цветной вывод. |

Явные флаги переопределяют переменные окружения, которые переопределяют сохраненную конфигурацию. В режиме ключа API выберите тенанта явно с `--org` или `FP_ORG`.

<Warning>
  Варианты `AGENTEYE_*` этих переменных **не читаются `fp`** и никогда не читались — CLI объявляет `FP_*` (`fp_cli/app.py`), и неизвестная переменная не является ошибкой. Установка `AGENTEYE_DASHBOARD_URL` не перенацеливает CLI; она игнорируется и команда молча запускается против сохраненной панели управления.

  `AGENTEYE_HOME` и `AGENTEYE_ENVIRONMENT` все еще существуют, но они принадлежат **сборщику и телеметрии SDK**, а не этому CLI.
</Warning>

<Warning>
  Команды, которые удаляют, отзывают, подавляют, разрешают или заменяют конфигурацию, запрашивают по умолчанию. Используйте `--yes` только после проверки активной организации и цели.
</Warning>
