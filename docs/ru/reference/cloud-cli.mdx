Используйте `fp` для проверки телеметрии Cloud, управления облачным обеспечением безопасности (политики, развёртывания парка, решения по guardrail) и управления аудитом, выводами, проблемами, оповещениями, ключами, пользователями, запросами и параметрами. Используйте [`failproofai`](/ru/reference/failproof-cli) для локальных хуков, политик, захвата и регистрации машин.

Установите выпущенный Cloud CLI как отдельный инструмент. Требуется Python 3.10 или новее.

```bash
uv tool install fp-cloud-cli
fp version
```

Дистрибутив называется `fp-cloud-cli`, а установленная команда — `fp` — они различаются, потому что `fp` уже был занят на PyPI.

## Вход в систему

`fp login` отправляет вам шестизначный код по электронной почте и сохраняет сеанс. Для использования с панелью управления с самоподписанным сертификатом добавьте `--insecure` при входе.

```bash
fp login
fp whoami
```

## Синтаксис

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Глобальные параметры должны идти перед командой:

```bash
fp --json sessions --since 24h
```

Запустите `fp COMMAND --help` или `fp COMMAND SUBCOMMAND --help` для справки в терминале.

### События

```text
fp events [OPTIONS]
```

Список отдельных событий агента. Лёгкий поток по умолчанию исключает необработанные полезные данные; используйте `--full` только для ограниченного расследования.

| Параметр | Описание |
| --- | --- |
| `--limit`, `-n <n>` | Максимальное количество строк. По умолчанию: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` или `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Диапазон ISO 8601 UTC; переопределяет `--since`. |
| `--env <value>` | Фильтр окружения; повторить или разделить запятыми значения. |
| `--event-type <value>` | Фильтр типа события; повторить или разделить запятыми значения. |
| `--agent-id <value>` | Фильтр агента; повторить или разделить запятыми значения. |
| `--session-id <value>` | Фильтр сеанса; повторить или разделить запятыми значения. |
| `--search <text>` | Поиск текста полезных данных; повторяемо, совпадает любой термин. |
| `--order asc\|desc` | Временной порядок. По умолчанию: самые новые первыми. |
| `--all` | Автоматически пагинировать вверх до `--limit`. |
| `--cursor <token>` | Возобновить от непрозрачного курсора. |
| `--page-size <n>` | Строк на запрос с `--all`; максимум `200`. |
| `--full` | Включить необработанные полезные данные через более тяжёлую конечную точку события. |
| `--fields <csv>` | Возвращать только выбранные поля; запрос `payload` включает режим полной информации. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` пагинирует **вверх до `--limit`**, который по умолчанию составляет **50** — поэтому `--all` отдельно
  останавливается на 50 строках. Когда он останавливается рано, ответ содержит
  `next_cursor` для возобновления; `"next_cursor": null` означает, что поток действительно был
  исчерпан.
</Note>

| Команда | Назначение | Параметры |

#### Параметры создания аудита

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Параметр | Описание |
| --- | --- |
| `--file <path>` | Основать определение на JSON или использовать `-` для stdin. Явные флаги переопределяют значения файла. |
| `--description <text>` | Указать вопрос об отказе или цель. |
| `--enabled` / `--disabled` | Начать планирование включённым или выключенным. По умолчанию: включено. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. По умолчанию: `86400`. |
| `--schedule-anchor <timestamp>` | Фиксированная фаза UTC в формате ISO 8601. По умолчанию: следующий 09:00 UTC. |
| `--window-mode since_last\|fixed` | Продолжить после последнего полностью анализированного окна или повторно проверить скользящее окно. По умолчанию: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. По умолчанию: `604800`. |
| `--scope '<json>'` | Фильтровать по `environments`, `agent_ids` или другим поддерживаемым полям области. |
| `--ignore-error-type <type>` | Исключить типы ошибок; повторить или разделить запятыми. |
| `--llm` / `--no-llm` | Включить или отключить агентский анализ. По умолчанию: включено. |
| `--top-k <n>` | Сохранить `1`–`500` выводов. По умолчанию: `50`. |
| `--sensitivity low\|medium\|high` | Установить чувствительность отчёта. По умолчанию: `medium`. |
| `--channels '<json>'` | Массив канала уведомлений. |
| `--text <brief>` | Встроенное краткое описание, максимум 8 192 символа. |
| `--text-file <path>` | Прочитать краткое описание из файла; взаимно исключающееся с `--text`. |
| `--url <https-url>` | Добавить общедоступную справочную ссылку HTTPS; повторить до пяти раз. |

Включите контекст при создании, когда первому запуску он требуется. Создание фиксирует определение и контекст вместе перед началом поставленного в очередь запуска.

<Note>
  `fp audits run` асинхронно. Опрашивайте `fp audits runs NAME` до тех пор, пока последний запуск не завершится успешно или ошибкой, прежде чем читать его выводы.
</Note>

### Политики

Управляемые облаком версии политик. **Только для сеансов** — каждая команда здесь, кроме `fp policies test`, выходит с кодом `2` под ключом API, перед любым запросом, потому что это корневые маршруты записи намеренно отсутствующие из `/v1`. `fp policies test` — намеренное исключение: запускается полностью локально на `node` и не обращается к серверу, поэтому не требует ни аутентификации, ни отказа режима ключей, и работает без входа и под ключом API одинаково.

| Команда | Назначение | Параметры |
| --- | --- | --- |
| `fp policies list` | Список версий политик, самые новые каждой политики первыми. | — |
| `fp policies show POLICY_ID` | Показать одну политику с её источником. | — |
| `fp policies publish POLICY_ID [SOURCE]` | Выпустить новую версию; никогда не редактирует одну на месте. `SOURCE` — путь, `@path` или `-` для stdin — опустите, чтобы вставить. | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | Добавить её обратно в каждое развёртывание, из которого она была удалена, выпустив новое поколение в каждом. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | Удалить её из каждого развёртывания, которое её содержит, выпустив новое поколение в каждом. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | Удалить версию политики. | `--yes`, `-y` |
| `fp policies test [SOURCE]` | Запустить политику локально против синтетического контекста. Применяет фильтр `match` каждой политики, поэтому та, которая не охватывает данное событие/инструмент, сообщается как `skipped`, а не запущена. Требует `node` на PATH. | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | Составить политику с ассистентом. Печатает черновик и больше ничего по умолчанию. Требует `policies:write`. | `--out <path>`; `--publish <policy-id>` |

### Парк

Какие машины запускают какие политики. **Только для сеансов** — каждая команда здесь, без исключения, выходит с кодом `2` под ключом API.

| Команда | Назначение | Параметры |
| --- | --- | --- |
| `fp fleet list` | Список зарегистрированных машин и их поколение развёртывания. | — |
| `fp fleet show MACHINE_ID` | Набор политик, которые машина в данный момент запускает. | — |
| `fp fleet deploy MACHINE_ID` | Изменить, что машина применяет. Печатает полный результирующий набор первым и запрашивает только на интерактивном терминале без `--json`. | `--add`; `--remove`; `--set`; `--create`; `--yes`, `-y` |
| `fp fleet diff [MACHINE_ID]` | Намерение против доставки — что машине сказано запускать против того, что она последняя загрузила. Опустите id для всего парка. | — |
| `fp fleet history MACHINE_ID` | Каждое поколение для машины, самые новые первыми. | — |
| `fp fleet rollback MACHINE_ID GENERATION` | Восстановить набор политик прошлого поколения. Номер поколения приходит из `fp fleet history MACHINE_ID`. | `--yes`, `-y` |
| `fp fleet rename MACHINE_ID LABEL` | Дать машине читаемый ярлык. Сам id никогда не меняется. | — |

```bash
fp fleet history ci-runner-01
fp fleet rollback ci-runner-01 3
fp fleet rename ci-runner-01 "CI runner (eu-west)"
```

#### Справочники политик

`--add` и `--set` берут справочник политики, не голый id:

| Форма | Означает |
| --- | --- |
| `id` | Текущая версия, текущий эффект |
| `id@3` | Версия 3, текущий эффект |
| `id:observe` | Текущая версия, записана, но не применяется |
| `id@3:observe` | Версия 3, записана, но не применяется |

Эффект — `enforce` или `observe`. Разрешение: явный эффект побеждает; иначе эффект уже развёрнут для этой политики; иначе `enforce`.

<Warning>
  Голый `--add` **применяется немедленно**. `fp fleet deploy ci-runner-01 --add checkout-guard` начинает блокировать на той машине как только она следующий раз загружается. `:observe` — это то, что делает её теневым развёртыванием:

  ```bash
  fp fleet deploy ci-runner-01 --add checkout-guard:observe   # только записывает
  fp fleet deploy ci-runner-01 --add checkout-guard           # применяет сейчас
  ```

  Observe — это не выключено. Политика оценивается по-настоящему, под тем же 10-секундным таймаутом и той же обработкой ошибок как применяемая, и каждый отличный от allow вердикт записывается — только применение удерживается. Вот что делает измерение достойным чтения.
</Warning>

#### Дельты, замена и гонки

`--add` и `--remove` читают текущий набор машины и применяют дельту, поэтому ничто, что вы не указали, не нарушается. Голый `--add` на политике, которую машина уже запускает, сохраняет её закреплённую версию, а не молча её обновляет; передайте `id@version` чтобы её переместить.

`--set` заменяет всё и единственный способ отбросить политики, которые вы не указали. Не может быть объединено с `--add` или `--remove`. Передача ни одного из трёх — это ошибка использования, а не отсутствие операции.

```bash
fp fleet deploy ci-runner-01 --add prod-guard@1:observe --remove old-rule
fp fleet deploy ci-runner-01 --set no-force-push --set no-secret-echo
```

Сама запись — полная замена на каждом пути, потому что конечная точка берёт весь набор политик. Нет серверной блокировки, поэтому CLI записывает поколение, которое прочитал, и отказывает, если результат не ровно на один выше — это означает, что кто-то другой развёртывал между тем, и замена не объединяет. Повторно прочитайте с `fp fleet show`, затем развёртывайте снова.

`--create` развёртывает на id машины, который ещё не проверился, для предварительной подготовки. Без него, id, который сервер не знает, отказывается, потому что опечатка иначе выпустит машину, которой никто не владеет, перевозящую политики, которые никто не собирает.

### Guardrails

Что применение действительно сделало. **Только для сеансов**, та же причина, что и выше.

| Команда | Назначение | Параметры |
| --- | --- | --- |
| `fp guardrails summary` | Покрытие, заблокировано/оценено итоги, диаграмма отказа и таблица для каждой политики. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |
| `fp guardrails timeline` | Решения разбиты по окну, суммированы во всех источниках политик. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |

Строка `(no policy)` в сводке нормальна, а не пробел: большинство оценок разрешают ничто, что кто-то возражал, и строка держит знаменатель на экране.

### Развёртывание политики без нарушения кого-либо

Три группы выше — это одна последовательность. Решить локально, опубликовать, затенить, измерить, затем применить.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

| Шаг | Почему он там |
| --- | --- |
| `fp policies test` | Нет сервера и нет аутентификации. Запускает реальный файл против контекста, который вы описываете, и печатает allow, deny или instruct на зарегистрированную политику. `--expect` превращает это в утверждение CI. |
| `fp policies publish` | Выпускает новую неизменяемую версию; никогда не редактирует одну на месте. |
| `fp fleet deploy --add <id>:observe` | Теневое развёртывание. **`:observe` не опционально здесь** — голый `--add` применяется в момент загрузки машины. |
| `fp guardrails summary` | Отделяет небезопасные совпадения от законной работы, которую политика также заблокировала бы. |
| `fp fleet deploy --add <id>:enforce` | Продвижение, как только записанные вердикты говорят то, что вы ожидали. |
| `fp fleet rollback <machine> <generation>` | Путь назад, если применение идёт неправильно. |

Одномашинный эквивалент, без Cloud, — публикация набора с `failproofai publish --effect observe` и чтение записанных вердиктов на [локальной панели](/ru/reference/local-dashboard).

## Переменные окружения

| Переменная | Эквивалент или назначение |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | Переместить каталог конфигурации CLI (по умолчанию `~/.failproofai/fpcli`). |
| `FP_ANALYTICS_DISABLED` или `DO_NOT_TRACK` | Отключить анонимную аналитику CLI. |
| `NO_COLOR` | Отключить цветной вывод. |

Явные флаги переопределяют переменные окружения, которые переопределяют сохранённую конфигурацию.

В режиме ключа API организация, сохранённая человеком `fp login`, **игнорируется**, не просто переопределяется — только явное `--org` или `FP_ORG` отправляется. Ничего не наследуется из сохранённого входа, поэтому передайте `--org` всякий раз, когда ключ может действовать для более чем одной организации. Его опущение не терпит неудачу громко: экземпляр с ключом без `--org` разрешает серверной стороне **стандартную** организацию и отвечает с данными этой организации, с ошибкой нигде. Сначала запустите `fp whoami`, чтобы подтвердить, какой тенант ключ действительно обсуждает.

<Warning>
  Написания `AGENTEYE_*` этих — **не читаются `fp`** и никогда не были — CLI объявляет `FP_*` (`fp_cli/app.py`), и неизвестная переменная не ошибка. Установка `AGENTEYE_DASHBOARD_URL` не перенаправляет CLI; это игнорируется и команда молча запускается против сохранённой панели вместо.

  `AGENTEYE_HOME` и `AGENTEYE_ENVIRONMENT` всё ещё существуют, но они принадлежат **сборщику и SDK телеметрии**, а не этому CLI.
</Warning>

<Warning>
  Команды, которые удаляют, отзывают, подавляют, разрешают или заменяют конфигурацию, запрашивают по умолчанию. Используйте `--yes` только после проверки активной организации и цели.
</Warning>
