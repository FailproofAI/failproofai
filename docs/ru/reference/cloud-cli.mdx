Используйте `fp` для проверки телеметрии Cloud, управления облачным принудительным применением (политики, развертывания флота, решения guardrail), а также управления аудитом, выводами, проблемами, оповещениями, ключами, пользователями, запросами и параметрами. Используйте [`failproofai`](/ru/reference/failproof-cli) для локальных хуков, политик, захвата и регистрации машин.

Вы также можете создавать и развертывать размещенный код, оценщики на основе LLM-judge и Jev, управлять панелями инструментов, проверять настроение и использовать ассистента панели инструментов из терминала.

Установите выпущенный Cloud CLI как отдельный инструмент:

```bash
uv tool install fp-cloud-cli
fp version
```

## Вход в систему

```bash
fp login
fp whoami
```

## Синтаксис

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Глобальные опции должны предшествовать команде:

```bash
fp --json sessions --since 24h
```

Запустите `fp COMMAND --help` или `fp COMMAND SUBCOMMAND --help` для справки в терминале.

## Команды CLI

### Создание оценщика

`fp evaluators` создает определения; `fp evals` читает результаты. Требуется включенный управляемый экземпляр (`fp evaluators instances`). Для создания требуется `evaluations:trigger`; сухие запуски сеанса и профилирование схемы также требуют `events:read`.

Код — это одно ограниченное выражение Python. Сохраните как `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Двоичный Jev и оцененная рубрика:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
Создание включает оценщик. Развертывание создает новую неизменяемую версию, затем отключает старые включенные версии. Неудача в последующей операции оставляет новую версию опубликованной: проверьте `evaluators list --all` перед повторной попыткой.
Сухие запуски judge отклоняются Cloud. Сухие запуски Jev расходуют бюджет модели.
Заполнение охватывает оценщики кода, judge и Jev и принимает максимум 90 дней; оно ставит в очередь только сеансы, которые оценщик еще не оценивал. Заполнение judge и Jev расходуют бюджет модели, поэтому сначала запустите `fp evaluators backfill --dry-run`.
Вывод человека показывает результаты сухого запуска для каждого сеанса перед созданием/развертыванием.
Неудачные предпросмотры останавливают запись, если вы явно не передадите `--force` после проверки.
</Warning>

Черновик AI требует `fp login` и записывает спецификацию, принимаемую create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Команда | Опции / поведение |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Полный источник/конверт |
| `fp evaluators create` | `--key`, `--name`, `--version`, повторяющийся `--label`, `--condition EXPR\|@file`, один источник, повторяющийся `--dry-run-on`, `--disabled`, явный `--force` для неудачных предпросмотров |
| `fp evaluators deploy KEY` | То же самое для флагов источника; `--version`, `--backfill 7d` (любого типа, 1–90 дней), `--force`; числовые версии автоматически увеличиваются; KEY предоставляет отсутствующий `eval_key` в файле спецификации |
| `fp evaluators draft "intent"` | Сеанс; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Флаги источника или `--file`, повторяющийся `--session` (максимум 10); отсутствие = только компиляция |
| `fp evaluators enable\|disable KEY[@VERSION]` | Переключение |
| `fp evaluators label KEY[@VERSION]` | Повторяющийся `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | Проверка управляемого флота/схемы/задач |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; код, judge и Jev |

Флаги кода — это `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. Флаги judge — это `--judge --criteria TEXT`, повторяющийся `--step` и
`--threshold`. Флаги Jev — это `--jev noul --instructions --true --false` или
`--jev score --instructions` с 3–5 отдельными значениями `--level`, худший первый.
Judge/Jev требуют оценку; пороги 0–1. Двоичные шаги judge отклоняются.

Файлы спецификации содержат ровно `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
`evaluator_source` judge/Jev — это строка конверта JSON. Не включайте идентификаторы строк,
состояние включения или метаданные рассуждений AI. `--file` и отдельные флаги спецификации
исключают друг друга; deploy может переопределить версию файла. Выходные файлы никогда не перезаписываются.

### Новые элементы управления панели инструментов

Все команды принимают глобальный `--json`. Неизвестные маршруты 404 выходят 6 с ошибкой "not available
on this FailproofAI Cloud yet". Отсутствующие записи 404 также выходят 6, но сообщают, что
запись не найдена. Команды только для сеанса отклоняют режим ключа перед HTTP (выход 2).

Команды человека используют сводки и таблицы. Для необработанного экспорта JSON передайте глобальный
`--json` или сохраните с `--out FILE`; иначе экспорт сеанса и JSON запросов показывает
читаемое представление. Экспорт CSV остается обычным CSV для передачи по конвейеру.

| Команды | Опции / примечания |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | Создание `--name`, `--description`, `--file` определение; обновление сохраняет неупомянутые поля |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | Добавление `--query ID --chart TYPE --title`; конфигурация/геометрия или макет через `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | Экспорт `--out`; история — это история оценки |
| `fp sessions import FILE...` | Claude Code стенограммы, Codex развертывания или события JSONL (`.gz` разрешено); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; требуется `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; список `--limit`; сообщения `--session-id` |
| `fp query compose "question"` | Сеанс; `--run` |
| `fp query export [ID]` | Или `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Проблемы можно `--create --title --summary` или `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; обновление `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | Сеанс; черновик политики из событий вашей организации, никогда не публикует |
| `fp policies backtest [FILE_OR_ID]` | Сеанс; regex воспроизводит модуль; `jev`/`both` (опубликованные или `--semantic checks.json`) оценивают бесплатно, `--run [--sample N]` расходует допуск Jev; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | Сеанс; может ли политика предотвратить эту проблему |
| `fp issues facets` | Значения, которые могут принимать фильтры входящих, с подсчетами |
| `fp agent brief` | Сеанс; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | Сеанс; выводит опущенный slug, не переключает организацию |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | Наборы разрешений; создание `--name --permission`; обновление заменяет `--permission` или объединяет `--add/--remove`; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | Удаление по id |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` требует ключ API; план (предложения и пробная версия) и требуют сеанс вошедшего пользователя |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 токенов |
| `fp otel status\|enable\|disable` | Переключатель приема облачной организации, не локальный захват |
| `fp slack status\|disconnect` | Сеанс |

`fp agent ask` отображает артефакты SQL в виде таблиц/статистики через `queries:run`.
Утверждения записи показывают предлагаемое изменение и приглашение на терминале. Скрипты и
`--json` отклоняют, если `--approve` не явно. Существующие формы JSON остаются
неизменными, когда артефакт не возвращается.

### События

```text
fp events [OPTIONS]
```

Перечисляет отдельные события агента. По умолчанию облегченный канал исключает необработанные полезные данные; используйте `--full` только для ограниченного расследования.

| Опция | Описание |
| --- | --- |
| `--limit`, `-n <n>` | Максимальное количество строк. По умолчанию: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` или `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Диапазон ISO 8601 UTC; переопределяет `--since`. |
| `--env <value>` | Фильтр окружения; повторить или разделить запятыми значения. |
| `--event-type <value>` | Фильтр типа события; повторить или разделить запятыми значения. |
| `--agent-id <value>` | Фильтр агента; повторить или разделить запятыми значения. |
| `--session-id <value>` | Фильтр сеанса; повторить или разделить запятыми значения. |
| `--search <text>` | Поиск текста полезной нагрузки; повторяемо, совпадение любого термина. |
| `--order asc\|desc` | Порядок времени. По умолчанию: новые первыми. |
| `--all` | Автоматическая пагинация до `--limit`. |
| `--cursor <token>` | Возобновить с непрозрачного курсора. |
| `--page-size <n>` | Строк на запрос с `--all`; максимум `200`. |
| `--full` | Включить необработанные полезные данные через более тяжелую конечную точку события. |
| `--fields <csv>` | Возвращать только выбранные поля; запрос `payload` включает полный режим. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` выполняет пагинацию **до `--limit`**, который по умолчанию **50** — поэтому `--all` само по себе останавливается на 50 строках. Когда он останавливается рано, ответ содержит `next_cursor` для возобновления; `"next_cursor": null` означает, что канал действительно был исчерпан.
</Note>

#### Опции создания аудита

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Опция | Описание |
| --- | --- |
| `--file <path>` | Основать определение на JSON или использовать `-` для stdin. Явные флаги переопределяют значения файла. |
| `--description <text>` | Обозначить вопрос об отказе или цель. |
| `--enabled` / `--disabled` | Начать планирование вкл. или выкл. По умолчанию: включено. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. По умолчанию: `86400`. |
| `--schedule-anchor <timestamp>` | Фиксированная фаза UTC в форме ISO 8601. По умолчанию: следующие 09:00 UTC. |
| `--window-mode since_last\|fixed` | Продолжить после последнего полностью проанализированного окна или повторно проверить скользящее окно. По умолчанию: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. По умолчанию: `604800`. |
| `--scope '<json>'` | Фильтр по `environments`, `agent_ids` или другим поддерживаемым полям области. |
| `--ignore-error-type <type>` | Исключить типы ошибок; повторить или разделить запятыми. |
| `--llm` / `--no-llm` | Включить или отключить агентный анализ. По умолчанию: включено. |
| `--top-k <n>` | Сохранить `1`–`500` выводов. По умолчанию: `50`. |
| `--sensitivity low\|medium\|high` | Установить чувствительность отчета. По умолчанию: `medium`. |
| `--channels '<json>'` | Массив канала уведомления. |
| `--text <brief>` | Встроенное краткое описание, максимум 8,192 символа. |
| `--text-file <path>` | Прочитать краткое описание из файла; взаимно исключается с `--text`. |
| `--url <https-url>` | Добавить общую HTTPS ссылку; повторить до пяти раз. |

Включите контекст во время создания, если первый запуск нуждается в нем. Создание фиксирует определение и контекст вместе перед началом поставленного запуска.

<Note>
  `fp audits run` асинхронна. Опрашивайте `fp audits runs NAME` до успеха или отказа последнего запуска перед чтением его выводов.
</Note>

### Политики

Версии политик, управляемые облаком. **Только для сеанса** — каждая команда здесь выходит `2` под ключом API, перед любым запросом, потому что это корневые маршруты записи, намеренно отсутствующие в `/v1`.

| Команда | Назначение | Опции |

<Warning>

  `AGENTEYE_HOME` и `AGENTEYE_ENVIRONMENT` все еще существуют, но они принадлежат **коллектору и телеметрии SDK**, а не этому CLI.
</Warning>
