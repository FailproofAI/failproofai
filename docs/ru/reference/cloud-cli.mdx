Используйте `fp` для проверки телеметрии Cloud, управления облачным принудительным применением (политик, развертыванием флота, решениями guardrail) и управления аудитами, находками, проблемами, оповещениями, ключами, пользователями, запросами и параметрами. Используйте [`failproofai`](/ru/reference/failproof-cli) для локальных хуков, политик, записи и регистрации машин.

Вы также можете создавать и развертывать размещенный код, оценки LLM-judge и Jev, управлять панелями мониторинга, анализировать тональность и использовать ассистент панели мониторинга из терминала.

Установите выпущенный Cloud CLI как изолированный инструмент:

```bash
uv tool install fp-cloud-cli
fp version
```

## Вход в систему

```bash
fp login
fp whoami
```

## Синтаксис

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Глобальные параметры должны идти перед командой:

```bash
fp --json sessions --since 24h
```

Запустите `fp COMMAND --help` или `fp COMMAND SUBCOMMAND --help` для справки в терминале.

## Команды CLI

### Создание оценщика

`fp evaluators` создает определения; `fp evals` читает результаты. Требуется включенный управляемый экземпляр (`fp evaluators instances`). Для создания требуется `evaluations:trigger`; тестовые запуски сеанса и профилирование схемы также требуют `events:read`.

Код — это одно ограниченное выражение Python. Сохраните это как `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Бинарный файл Jev и оцениваемая рубрика:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
Создание включает оценщик. Развертывание создает новую неизменяемую версию, затем отключает более старые включенные версии. Неудачное последующее действие оставляет новую версию опубликованной: проверьте `evaluators list --all` перед повторной попыткой.
Тестовые запуски judge отклоняются Cloud. Тестовые запуски Jev расходуют бюджет модели.
Заполнение охватывает оценщики code, judge и Jev и принимает максимум 90 дней; оно ставит в очередь только сеансы, которые оценщик еще не оценил. Заполнение judge и Jev расходуют бюджет модели, поэтому сначала запустите `fp evaluators backfill --dry-run`.
Вывод человека показывает результаты предварительного запуска по сеансам перед созданием/развертыванием.
Неудачные предпросмотры останавливают запись, если вы явно не передали `--force` после проверки.
</Warning>

Черновик AI требует `fp login` и создает спецификацию, принимаемую create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Команда | Параметры / поведение |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Полный исходный код/конверт |
| `fp evaluators create` | `--key`, `--name`, `--version`, повторяющиеся `--label`, `--condition EXPR\|@file`, один источник, повторяющиеся `--dry-run-on`, `--disabled`, явный `--force` для неудачных предпросмотров |
| `fp evaluators deploy KEY` | Те же флаги источника; `--version`, `--backfill 7d` (любой вид, 1–90 дней), `--force`; числовые версии автоматически увеличиваются; KEY предоставляет отсутствующий `eval_key` файла спецификации |
| `fp evaluators draft "intent"` | Сеанс; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Флаги источника или `--file`, повторяющиеся `--session` (максимум 10); ни одного = только компиляция |
| `fp evaluators enable\|disable KEY[@VERSION]` | Переключить |
| `fp evaluators label KEY[@VERSION]` | Повторяющиеся `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | Проверить управляемый флот/схему/задачи |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; code, judge и Jev |

Флаги кода — `--code FILE|-`, `--result-kind score|metric|assertion`, `--timeout S`. Флаги judge — `--judge --criteria TEXT`, повторяющиеся `--step` и `--threshold`. Флаги Jev — `--jev noul --instructions --true --false` или `--jev score --instructions` с 3–5 различными значениями `--level`, худшее первым. Judge/Jev требуют оценку; пороги — 0–1. Двоичные этапы judge отклоняются.

Файлы спецификации содержат ровно `eval_key`, `display_name`, `eval_version`, `result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`. `evaluator_source` judge/Jev — строка конверта JSON. Не включайте идентификаторы строк, состояние включения или метаданные рассуждений AI. `--file` и дискретные флаги спецификации являются взаимоисключающими; развертывание может переопределить версию файла. Выходные файлы никогда не перезаписываются.

### Новые элементы управления панели мониторинга

Все команды принимают глобальный `--json`. Неизвестные маршруты 404 выходят с кодом 6 с сообщением «недоступно в этом FailproofAI Cloud еще». Отсутствующие 404 также выходят с кодом 6, но сообщают, что запись не найдена. Команды только для сеанса отклоняют режим ключа перед HTTP (выход 2).

Команды для человека используют сводки и таблицы. Для необработанных экспортов JSON передайте глобальный `--json` или сохраните с `--out FILE`; в противном случае экспорты сеанса и JSON запросов показывают читаемый вид. Экспорты CSV остаются простым CSV для передачи по конвейеру.

| Команды | Параметры / примечания |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | Создание `--name`, `--description`, `--file` определение; обновление сохраняет неуказанные поля |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | Добавление `--query ID --chart TYPE --title`; конфигурация/геометрия или макет через `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | Экспорт `--out`; история — это история оценки |
| `fp sessions import FILE...` | Транскрипты Claude Code, развертывания Codex или событийный JSONL (`.gz` ok); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; требуется `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; список `--limit`; сообщения `--session-id` |
| `fp query compose "question"` | Сеанс; `--run` |
| `fp query export [ID]` | Или `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Проблемы могут `--create --title --summary` или `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; обновление `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | Сеанс; создает политику на основе событий вашей организации, никогда не публикует |
| `fp policies backtest [FILE_OR_ID]` | Сеанс; regex воспроизводит модуль; `jev`/`both` (опубликовано, или `--semantic checks.json`) оценить бесплатно, `--run [--sample N]` расходует допуск Jev; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | Сеанс; может ли политика предотвратить эту проблему |
| `fp issues facets` | Значения, которые могут принимать фильтры входящих, с количеством |
| `fp agent brief` | Сеанс; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | Сеанс; выводит пропущенный слаг, не переключает организацию |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | Наборы разрешений; создание `--name --permission`; обновление заменить `--permission` или объединить `--add/--remove`; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | Удаление по id |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` требует ключ API; plan (предложения и пробная версия) и claim требуют сеанс с входом |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 токенов |
| `fp otel status\|enable\|disable` | Переключатель приема облачной организации, не локальная запись |
| `fp slack status\|disconnect` | Сеанс |

`fp agent ask` выполняет артефакт SQL в виде таблиц/статистики через `queries:run`.
Одобрения записей показывают предложенное изменение и подсказку в терминале. Скрипты и `--json` отклоняют, если не передан явный `--approve`. Существующие формы JSON остаются неизменными, когда артефакт не возвращается.

```bash

fp whoami
```

В терминале `fp login` начинается со ссылки для входа с браузера или SSO и открывает ее (через SSH или без дисплея он только отображает, и это работает с любого устройства); авторизуйте ее, и терминал завершит работу самостоятельно. Этот терминал получает ваш доступ во все ваши организации до истечения сеанса, поэтому авторизуйте только ссылку, которую вы только что запросили. Если вход начался в другой сети, вы получите электронное письмо после создания сеанса, и страница предупредит вас, где развертывание может сказать. Нажмите **Tab** для 6-значного кода по электронной почте вместо этого и снова Tab, чтобы вернуться. `--email`, `--json` и все без терминала используют код.

### События

```text
fp events [OPTIONS]
```

Список отдельных событий агента. Легкий стандартный фид исключает необработанные полезные данные; используйте `--full` только для ограниченного исследования.

| Параметр | Описание |
| --- | --- |
| `--limit`, `-n <n>` | Максимальное общее количество строк. По умолчанию: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h` или `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Диапазон ISO 8601 UTC; переопределяет `--since`. |
| `--env <value>` | Фильтр окружения; повторите или разделите значения запятой. |
| `--event-type <value>` | Фильтр типа события; повторите или разделите значения запятой. |
| `--agent-id <value>` | Фильтр агента; повторите или разделите значения запятой. |
| `--session-id <value>` | Фильтр сеанса; повторите или разделите значения запятой. |
| `--search <text>` | Поиск текста полезных данных; повторяется, любой термин совпадает. |
| `--order asc\|desc` | Временной порядок. По умолчанию: самый новый первым. |
| `--all` | Автоматическая нумерация страниц вверх до `--limit`. |
| `--cursor <token>` | Возобновить с непрозрачного курсора. |
| `--page-size <n>` | Строки на запрос с `--all`; максимум `200`. |
| `--full` | Включить необработанные полезные данные через более тяжелую конечную точку события. |
| `--fields <csv>` | Возвращать только выбранные поля; запрос `payload` включает полный режим. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` нумерует страницы **вверх до `--limit`**, что по умолчанию **50** — поэтому `--all` само по себе останавливается на 50 строках. Когда оно рано останавливается, ответ содержит `next_cursor` для возобновления; `"next_cursor": null` означает, что фид действительно был исчерпан.
</Note>

#### Параметры создания аудита

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Параметр | Описание |
| --- | --- |
| `--file <path>` | Основать определение на JSON или использовать `-` для stdin. Явные флаги переопределяют значения файла. |
| `--description <text>` | Укажите вопрос об ошибке или назначение. |
| `--enabled` / `--disabled` | Начать планирование или выключить. По умолчанию: включено. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. По умолчанию: `86400`. |
| `--schedule-anchor <timestamp>` | Фиксированная фаза UTC в форме ISO 8601. По умолчанию: следующие 09:00 UTC. |
| `--window-mode since_last\|fixed` | Продолжить после последнего полностью проанализированного окна или повторно проверить скользящее окно. По умолчанию: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. По умолчанию: `604800`. |
| `--scope '<json>'` | Фильтр по `environments`, `agent_ids` или другие поддерживаемые поля области. |
| `--ignore-error-type <type>` | Исключить типы ошибок; повторите или разделите запятой. |
| `--llm` / `--no-llm` | Включить или отключить агентский анализ. По умолчанию: включено. |
| `--top-k <n>` | Сохранить `1`–`500` находок. По умолчанию: `50`. |
| `--sensitivity low\|medium\|high` | Установить чувствительность отчетности. По умолчанию: `medium`. |
| `--channels '<json>'` | Массив канала уведомления. |
| `--text <brief>` | Встроенное краткое описание, максимум 8192 символа. |
| `--text-file <path>` | Прочитать краткое описание из файла; взаимно исключающее с `--text`. |
| `--url <https-url>` | Добавить открытую справку HTTPS; повторите до пяти раз. |

Включите контекст во время создания, когда первому запуску это необходимо. Создание фиксирует определение и контекст вместе перед тем, как начнется поставленный в очередь запуск.

<Note>
  `fp audits run` асинхронна. Опросите `fp audits runs NAME` до тех пор, пока самый последний запуск не будет успешен или не пройдет перед чтением его находок.
</Note>
