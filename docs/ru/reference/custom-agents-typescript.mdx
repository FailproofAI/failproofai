Node 20.9 или новее. ESM и CommonJS. Без зависимостей в runtime.

<Note>
  Этот SDK и Python SDK записывают **одинаковые события в один буфер**. Парк с Node агентами и Python агентами создаёт один набор сессий, а не два, и ничто в панели управления их не различает. Выбирайте по сервису, а не по компании.
</Note>

## Установка

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Адаптеры фреймворков поставляются в самом пакете. Фреймворки — это **опциональные парные зависимости** — они объявлены, чтобы были видны поддерживаемые версии, никогда не устанавливаются автоматически и импортируются только при вызове `instrument()`.

## Подключение демона Failproof

Идентично Python SDK: создайте ключ `events:add` в разделе **Admin → Keys**, затем [подключите демон](/ru/start/setup#connect-a-machine-to-cloud) на машине с агентом. SDK пишет на диск; демон отправляет.

## Конфигурация

### OpenTelemetry spans (опционально)

Установите OpenTelemetry отдельно с помощью `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
Затем добавьте FailproofAI в процессоры вашего провайдера:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Для существующего провайдера сохраняйте его другие процессоры в одном списке. Провайдеры, которые предоставляют `addSpanProcessor`, можно вместо этого передать как `{ provider }`. Без опций функция регистрирует новый провайдер только если его ещё нет.
`OtelSpanExporter` также можно использовать напрямую с собственным процессором.

Экспорт проходит через подключённый демон FailproofAI; SDK не отправляет сетевые запросы и не требует ключа или локального слушателя. Попросите администратора включить [OpenTelemetry ingest](/ru/agenteye/opentelemetry). Простой `instrument()` не включает этот экспортер. `uninstrument("otel")` отключает только его собственный процессор.
Ваши атрибуты span контролируют захват содержимого; переведите провайдер перед выходом.
OpenTelemetry остаётся опциональной зависимостью приложения, а не обязательной зависимостью SDK.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Опция | Что делает |
| --- | --- |
| `environment` | Метка на каждом событии — `production`, `staging`, `prod-eu`. По умолчанию `dev`. |
| `flushInterval` | Как часто таймер пишет на диск, в секундах. По умолчанию `0.5`. |
| `baseDir` | Куда писать. По умолчанию буфер демона — это то, что вам нужно, если вы не знаете иначе. |

Ничего не применяется, если всё не валидно, поэтому отклонённый вызов оставляет SDK в точности в том же состоянии, а не с новым `baseDir` и старым интервалом.

Устанавливайте через переменную окружения вместо этого:

| Переменная | Что делает |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Устанавливает `environment` без изменения кода. Опция `configure()` имеет приоритет. |
| `FAILPROOFAI_HOME` | Перемещает корень Failproof AI, содержащий буфер. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (по умолчанию), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` делает ошибки инструментации выбрасываемыми вместо логирования. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` делает проблему совместимости фреймворка выбрасываемой вместо предупреждения и продолжения. |

<Warning>
  **Нет запятых в `environment`.** Ingest разбивает это поле по запятым для построения фильтров и пропускает любое событие, метка которого содержит запятую — поэтому весь запуск молча исчезает. Пишите `prod-eu`, а не `prod,eu`.

  `configure({ environment: "prod,eu" })` выбрасывает исключение, чтобы вы узнали сразу. `AGENTEYE_ENVIRONMENT` не может выбросить — никто не вызывает вас — поэтому предупреждает один раз и откатывает к `dev`.
</Warning>

Направьте собственные логи SDK в ваш логгер с помощью `failproofai.setLogger({ debug, info, warn, error })`.

## Завершение

Буферизованные события сбрасываются на `process.on("exit")`.

Процесс, убитый сигналом, никогда туда не доходит, и поведение Node по умолчанию для `SIGTERM` — завершить без запуска обработчиков выхода — поэтому контейнеризованный агент теряет всё, что последний интервал не написал.

<Warning>
  **Этот SDK не установит обработчик сигнала за вас.** Регистрация такого обработчика изменяет поведение вашего процесса: слушатель подавляет завершение по умолчанию в Node, поэтому библиотека, которая добавила его, молча остановила бы Ctrl-C. Добавьте свой:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Короткоживущий скрипт или обработчик serverless должны вызвать `await failproofai.flush()` перед возвратом — только интервала недостаточно для гарантии доставки.

## Идентичность

Каждое событие принадлежит сессии и агенту. **Области видимости заполняют оба**, поэтому вы редко их передаёте:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

Явная передача `sessionId` или `agentId` всё ещё работает и имеет приоритет. Без привязки и без передачи вызов выбрасывает исключение, а не излучает событие, которое Cloud молча отбросит.

<Note>
  Идентичность основана на `AsyncLocalStorage`. Она следует `await`, `.then()`, таймерам и любому обратному вызову, созданному внутри области видимости. Она **не** следует обратному вызову, сохранённому в одном запуске и вызванному в другом, или работе, переданной через границу `worker_threads` — оберните их в `failproofai.propagate()` или их события приземлятся не прикреплёнными.
</Note>

### Области видимости

| Область | Излучает | Возвращает |
| --- | --- | --- |
| `session(body)` | ничего — только идентичность | всё, что возвращает `body` |
| `agent(id, options?, body)` | `agent_start`, затем `agent_end` | всё, что возвращает `body` |
| `toolCall(name, options?, body)` | `tool_use`, затем `tool_result` | всё, что возвращает `body` |

Синхронное тело остаётся синхронным: `agent("x", () => 1)` возвращает `1`, а не промис.

`toolCall` записывает разрешённое значение тела как `output` инструмента, если вы не присвоили `call.output` сами.

<Accordion title="Семантика выхода" icon="arrow-right-from-bracket">

| Что произошло | События | `outcome` |
| --- | --- | --- |
| блок возвратил результат | `agent_end` | `success`, или ваш `outcome` |
| блок выбросил исключение | `error`, затем `agent_end` | `failed` |
| `AbortError` | только `agent_end` | `cancelled` |

Ошибка всегда повторно выбрасывается.

Отказ инструмента записывается на листе — `tool_result` с строкой `error` — и **не** излучает событие `error` уровня запуска. Тот, что перехватит цикл агента — это не отказ запуска, и тот, что распространяется — сообщается ровно один раз, посредством enclosing `agent()`.

</Accordion>

<Accordion title="Форма с `using`" icon="brackets-curly">

Когда работа — это не одна функция — область видимости, открытая в конструкторе и закрытая в teardown, или та, что пересекает существующий поток управления:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, затем agent_end
```

Обе формы излучают идентичные байты. Предпочитайте форму обратного вызова: она запускается внутри `AsyncLocalStorage.run()`, поэтому разворачивать ничего не нужно и весь класс ошибок «открыто здесь, закрыто там» недостижим.

Блок `using`, который ловит собственный отказ, сообщает о нём с помощью `span.fail(error)` — disposer не имеет собственного канала исключений.

</Accordion>

## Каталог событий

Те же пятнадцать методов, что и в Python SDK, в camelCase. Большинство идут **парами** — вы вызываете открывающий, затем закрывающий, и SDK отсчитывает промежуток.

| | Открывает | Закрывает |
| --- | --- | --- |
| **Агенты** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Модели** | `modelRequest` | `modelResponse` |
| **Инструменты** | `toolUse` | `toolResult` |
| **Хуки** | `hookTriggered` | `hookCompleted` |
| **Люди** | `humanWait` | `humanInput` |

Три стоят особо: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Каждое поле, для каждого метода" icon="table">

Каждый метод также принимает `sessionId` и `agentId`, которые области видимости заполняют за вас. Всё пропущенное удаляется, а не отправляется как JSON `null`.

| Метод | Требуется | Опционально |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Любой другой ключ, который вы добавите, становится полем пользовательской полезной нагрузки. Пространство имён всё специфичное для фреймворка с префиксом `fw_`; имя, конфликтующее с объявленным полем, отклоняется, а не молча перезаписывает повышенный столбец.

</Accordion>

<Warning>
  **`duration_ms` вычисляется, не принимается.** Четыре закрывающих метода отсчитывают промежуток от своего открывающего и отклоняют предоставленный вызывающим `duration_ms` — сообщённая длительность неопровержима.

  Пары соответствуют **сессии** и идентификатору, никогда не агенту. Инструмент, открытый под `planner` и закрытый под `worker`, всё ещё соответствует, что именно то, что делают вложенные многоагентные запуски.
</Warning>

## Адаптеры фреймворков

```ts
await failproofai.instrument();              // всё, что удастся найти
await failproofai.instrument("langchain");   // ровно один
failproofai.uninstrument();                  // вернуть всё обратно
```

| Фреймворк | Поддерживается | Как подключается |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, поэтому каждый `invoke`/`stream`/`batch` охватывается без передачи `callbacks:` куда-либо — или передайте `langchainHandler()` сами и ничего не патчьте. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` на месте вызова, или `instrument("ai")` для всего процесса на `ai` 7 (на 4–6 это опционально — см. ниже). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, разрешение модели агента и инструмента, и engine запуска/шага workflow. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (подписано) плюс `AgentWorkflow.runStream`, для запусков workflow и их шагов. |

Каждый диапазон тестируется против реальных выпусков фреймворков на обоих концах, как ES модуль и как CommonJS, на каждом запуске CI.

Отображение — это отображение Python SDK, поэтому одна и та же программа рисует одно и то же дерево на любом языке. Конструкция — это **агент** только если она владеет циклом решения LLM — запуск графика или цепочки, вызов `generateText`/`streamText` AI SDK, агент Mastra, запуск агента LlamaIndex. Узел LangGraph или шаг workflow — это **хук** (`hook_triggered`/`hook_completed`), никогда вложенный агент. Вызовы модели — это пары `model_request`/`model_response` с подсчётами токенов; вызовы инструмента содержат собственный id вызова инструмента модели. Отказ записывается один раз, в событие, где он произошёл.

Адаптер, который не установился, логируется и пропускается; другие всё ещё устанавливаются, потому что сломанный LlamaIndex не должен стоить вам LangGraph.

<Note>
  `instrument()` без аргумента обнаруживает фреймворк по тому, **разрешается** ли он, а не по тому, импортирован ли он уже — Node не предоставляет эквивалент Python `sys.modules` для ES модулей. Фреймворк, который вы установили, но не используете, будет импортирован и пропатчен. Назовите нужный вам, если это имеет значение.
</Note>

<Note>
  Большинство этих фреймворков поставляются с ES-модульной сборкой и CommonJS сборкой, которую Node загружает как две несвязанные копии. Адаптеры патчат копию, которую загружает ваше приложение (и CommonJS копию тоже, если что-то её уже `require`d), поэтому оба модульных системы работают. Фреймворк, **бандлизированный в вашу собственную выходную данную** посредством esbuild или webpack, недостижим — используйте там вспомогательные функции места вызова: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain без патчинга

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

Обработчик работает с `instrument()` или без него и никогда не двойной-записывает. `instrument("langchain")` принимает `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` и `captureLimit`, как делает адаптер Python; `metadata: { failproofai_sdk_session_id }` на вызове выбирает сессию для этого вызова.

### Vercel AI SDK

AI SDK экспортирует простые функции из ES модуля, и пространство имён ES модуля неизменяемо по спецификации — нечего там патчить. Он использует точки расширения, которые документирует сам SDK:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // на ai 7, `telemetry: telemetry({ … })` — тот же объект, новое имя
});
```

Это полная интеграция: span агента, пара запрос/ответ модели за шаг с подсчётом токенов, и каждый вызов инструмента. Одна сайт вызова работает на каждой major версии — `ai` 4–6 читают трейсер, который он носит, `ai` 7 интеграцию telemetry.

`instrument("ai")` делает то же самое по всему процессу **на `ai` 7**: каждый вызов, через глобальный список интеграций telemetry AI SDK, который аддитивен и ничего не берёт у кого-то другого.

**На `ai` 4–6, `instrument("ai")` по умолчанию ничего не записывает, и логирует одно предупреждение об этом.** Единственный hook по всему процессу, который есть у этих major версий — это глобальный провайдер OpenTelemetry tracer — единственный slot, который OpenTelemetry отказывает вернуть один раз взятый. Регистрация нашего молча отказала бы вашему собственному `NodeSDK.start()` позже при запуске и отправила бы ваши http/database spans трейсеру, который ничего не экспортирует. Используйте `telemetry()` на месте вызова или `wrapModel` там. Если процесс не запускает свой собственный OpenTelemetry, присоединитесь с `instrument("ai", { registerGlobalTracer: true })`: затем он записывает каждый вызов, который передаёт `experimental_telemetry: { isEnabled: true }`, и берёт slot только если он всё ещё пуст. `registerGlobalTracer: false` сохраняет по умолчанию и молчит предупреждение.

Если вы бы скорее обёртывали модель один раз, `wrapModel` видит только вызовы модели, потому что вызовы инструмента происходят над слоем модели. Обёрнутая модель, вызванная ни с чем вокруг неё, записывается как её собственный запуск. Потоковый вызов закрывается при том, как поток останавливается — `stop_reason: cancelled` когда потребитель отменяет его, `error` с ошибкой когда он терпит неудачу на полпути:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Использование обоих хорошо: middleware замечает, что вызов уже записывается, и откладывает, поэтому каждый вызов записывается один раз.

`functionId` называет span агента. Держите это низкой кардинальностью — это попадает в `agent_id`, первичный фасет панели.

### Next.js

`next build` бандлизирует зависимости вашего сервера по умолчанию, и фреймворк, бандлизированный в сборку — это копия, которую `instrument()` не может достичь. Оберните конфиг один раз и вызовите `instrument()` из hook запуска Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` добавляет LangChain, Mastra, LlamaIndex и сам SDK в `serverExternalPackages`, сохраняя ваш собственный список. Без этого, `instrument()` предупреждает один раз за фреймворк, который не может достичь, а не молча терпит неудачу; если вы перечислите пакеты сами, установите `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK и вспомогательные функции места вызова работают в любом случае. Edge route получает no-op сборку: импорт SDK безопасен и ничего не записывает.

### Подсчёты токенов на потоковых вызовах

OpenAI-совместимые API сообщают об использовании на потоке только когда клиент просит. LangChain и Vercel AI SDK просят; для LlamaIndex передайте `additionalChatOptions: { stream_options: { include_usage: true } }` его `OpenAI` LLM, и для Mastra соберите модель с включённым использованием (например `createOpenAICompatible({ includeUsage: true })`). В остальном потоковые вызовы модели не несут подсчётов токенов.

### Рантайм

Node ≥ 20.9, Bun и Deno — каждый фреймворк, как ES модуль и как CommonJS, тестируется на каждом против трейса Node. SDK работает рядом с демоном `failproofaid`, который отправляет то, что тот пишет.

## Ваш собственный агент — без фреймворка

Для цикла агента, который вы написали сами, или фреймворка без адаптера. Вы излучаете события с тем же API, который адаптеры используют под капотом, поэтому трейс имеет одну и ту же форму и качество.

Вам не нужно знать, как организован агент. Каждый рукоделный агент уже имеет три места, каким бы ни были названы его функции, и эти три — вся интеграция:

| Где | Что добавить | Излучает |
| --- | --- | --- |
| Где **один запуск** начинается и заканчивается | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Единственная функция, которая вызывает модель** | `event.modelRequest` перед, `event.modelResponse` после — обе половины, даже при отказе | одна пара за поворот модели |
| **Единственная функция, которая запускает инструменты** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Идентичность — амбиентна: всё внутри `agent()` приземляется на запуск сессии без принятия id, и ничто другое в программе не меняется — включая всё, что агент уже пишет в свою собственную базу данных.

- **Сервис или worker:** передайте свой собственный id запроса или работы как `sessionId`, поэтому сессия на панели и запись в ваши собственные логи или базу данных — это одна и та же строка.
- **Подагенты:** вложите вызовы `agent()`. Внутренний присоединяется к сессии с внешним как его `parent_id`.
- **Излучайте пары.** `modelRequest` без `modelResponse` — это span, который панель показывает как запущенный вечно — откуда `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) в репозитории — это полная, запущенная версия: реальный цикл инструмента OpenAI инструментирован ровно так, как здесь, запущен в CI на каждом изменении как ES модуль и как CommonJS.

## Оценки

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Смотрите [Evaluator SDK reference](/ru/reference/evaluator-sdk) для протокола, параметров worker и типов результатов.

<Warning>
  **Оценка должна выхода.** Синхронная функция, которая никогда не возвращается, блокирует единственный поток Node, и ни какой таймаут не может срабатывать, пока она это делает. Пишите `async` оценки.
</Warning>

## Что она не будет делать с вашим процессом

| | |
| --- | --- |
| **Блокировать ваш цикл агента** | События попадают в очередь в памяти; таймер пишет их. Таймер `unref`'d, поэтому импорт этого пакета никогда не остановит скрипт от выхода. |
| **Расти без граница** | Очередь ограничена по count *и* по измеренным байтам. Превысив любое, старые события отбрасываются и предупреждение говорит так — отказ telemetry не должен стать OOM kill. |
| **Завалить процесс** | Одно неодиозное событие отбрасывается само по себе, не пакет вокруг него. Выбрасывающий getter, циклическая ссылка, `BigInt`, одинокий surrogate: каждый обработан, а не распространён. |
| **Оставить半-написанный пакет** | Содержимое `fsync`'ено перед атомарным переименованием, директория `fsync`'ена после, и неудачная запись очищает свой временный файл. |
| **Оставить транскрипты читаемыми** | Пакеты `0600` внутри директории `0700`. Они носят цели, подсказки, аргументы инструмента и выход инструмента. |
| **Поставить credentials** | API ключи, токены, JWTs, bearer headers и похожие на секреты присвоения редактируются перед тем, как байты достигнут диска. Демон редактирует ещё раз перед загрузкой. |
