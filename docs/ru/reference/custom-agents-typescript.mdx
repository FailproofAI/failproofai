Node 20.9 или новее. ESM и CommonJS. Нет зависимостей во время выполнения.

<Note>
  Этот SDK и Python SDK записывают **одни и те же события в один и тот же буфер**. Парк из Node-агентов и Python-агентов создает одно множество сессий, а не два, и ничто в интерфейсе их не различает. Выбирайте по сервисам, а не по компаниям.

## Установка

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Адаптеры фреймворков поставляются в самом пакете. Фреймворки — это **опциональные зависимости от пользователя** — указаны так, чтобы были видны поддерживаемые диапазоны версий, никогда не устанавливаются без вашего ведома и импортируются только при вызове `instrument()`.

## Подключение демона Failproof

Идентично Python SDK: создайте ключ `events:add` в разделе **settings → api keys**, затем [подключите демон](/ru/start/setup#connect-a-machine-to-cloud) на машине с агентом. SDK пишет на диск; демон отправляет данные.

## Конфигурация

### Spans OpenTelemetry (opt-in)

Установите OpenTelemetry отдельно командой `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
Затем добавьте FailproofAI в процессоры вашего поставщика:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Для существующего поставщика держите его остальные процессоры в том же списке. Поставщики,
которые предоставляют `addSpanProcessor`, можно передать как `{ provider }`. Без
параметров setup регистрирует нового поставщика только если нет уже зарегистрированного.
`OtelSpanExporter` также можно использовать напрямую с вашим собственным процессором.

Экспорт идет через подключенный демон FailproofAI; SDK не делает сетевых запросов и не нуждается
в ключе или локальном слушателе. [Прием OpenTelemetry](/ru/agenteye/opentelemetry)
всегда включен в Cloud. Простой `instrument()` не
включает этот экспортер. `uninstrument("otel")` отключает только его собственный процессор.
Ваши атрибуты span контролируют сбор содержимого; очищайте поставщика перед выходом.
OpenTelemetry остается опциональной зависимостью приложения, а не жесткой зависимостью SDK.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Параметр | Что он делает |
| --- | --- |
| `environment` | Метка на каждом событии — `production`, `staging`, `prod-eu`. По умолчанию `dev`. |
| `flushInterval` | Как часто таймер пишет на диск, в секундах. По умолчанию `0.5`. |
| `baseDir` | Куда писать. По умолчанию буфер демона, что вам и нужно, если вы не знаете иное. |

Ничего не применяется, пока все не пройдет проверку, поэтому отклоненный вызов оставляет SDK в прежнем состоянии, а не с новым `baseDir` и старым интервалом.

Установите через переменную окружения вместо этого:

| Переменная | Что она делает |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Устанавливает `environment` без изменения кода. Параметр `configure()` имеет приоритет. |
| `FAILPROOFAI_HOME` | Перемещает корневую папку Failproof AI, которая содержит буфер. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (по умолчанию), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` заставляет ошибки подключения выбросить исключение вместо логирования. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` заставляет проблему совместимости фреймворка выбросить исключение вместо предупреждения и продолжения. |

<Warning>
  **Нет запятых в `environment`.** Прием разбивает это поле по запятым для построения фильтров и пропускает любое событие, метка которого содержит запятую — поэтому целый запуск будет молча потерян. Пишите `prod-eu`, а не `prod,eu`.

  `configure({ environment: "prod,eu" })` выбросит исключение, чтобы вы узнали сразу. `AGENTEYE_ENVIRONMENT` не может выбросить исключение — никто вас не вызывает — поэтому он предупредит один раз и вернется к `dev`.
</Warning>

Перенаправьте собственные логи SDK в ваш логгер с помощью `failproofai.setLogger({ debug, info, warn, error })`.

## Завершение

События из буфера сбрасываются при `process.on("exit")`.

Процесс, убитый сигналом, никогда не достигает этого, и стандартное поведение Node для `SIGTERM` — завершиться без запуска обработчиков выхода — поэтому контейнеризованный агент теряет то, что последний интервал не записал.

<Warning>
  **Этот SDK не установит для вас обработчик сигналов.** Регистрация обработчика изменяет поведение процесса: слушатель подавляет стандартное завершение Node, поэтому библиотека, которая добавила бы обработчик, бы молча сломала Ctrl-C. Добавьте свой собственный:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Краткосрочный скрипт или обработчик serverless должен вызвать `await failproofai.flush()` перед возвратом — один интервал не гарантирует доставку.

## Идентичность

Каждое событие принадлежит сессии и агенту. **Области действия заполняют обе**, поэтому вы редко их передаете:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

Явная передача `sessionId` или `agentId` все еще работает и имеет приоритет. Без привязанных или переданных значений вызов выбросит исключение, а не испустит событие, которое Cloud молча отклонит.

<Note>
  Идентичность основана на `AsyncLocalStorage`. Она следует `await`, `.then()`, таймерам и любому callback, созданному внутри области действия. Она **не** следует callback, сохраненному во время одного запуска и вызванному во время другого, или работе, переданной через границу `worker_threads` — оборачивайте их в `failproofai.propagate()` или их события останутся неприкрепленными.
</Note>

### Области действия

| Область | Испускает | Возвращает |
| --- | --- | --- |
| `session(body)` | ничего — только идентичность | то, что возвращает `body` |
| `agent(id, options?, body)` | `agent_start`, затем `agent_end` | то, что возвращает `body` |
| `toolCall(name, options?, body)` | `tool_use`, затем `tool_result` | то, что возвращает `body` |

Синхронное тело остается синхронным: `agent("x", () => 1)` возвращает `1`, а не promise.

`toolCall` записывает разрешенное значение тела как `output` инструмента, если только вы не присвоили `call.output` сами.

<Accordion title="Семантика выхода" icon="arrow-right-from-bracket">

| Что произошло | События | `outcome` |
| --- | --- | --- |
| блок вернул значение | `agent_end` | `"success"`, или ваш `outcome` |
| блок выбросил исключение | `error`, затем `agent_end` | `"failed"` |
| произошла `AbortError` | только `agent_end` | `"cancelled"` |

Исключение всегда переброшено.

Отказ инструмента записывается на листе — `tool_result` с `error` string — и испускает **никаких** событий на уровне запуска. Тот, который перехватывает цикл агента, — не отказ запуска, а тот, который распространяется, сообщается ровно один раз, enclosing `agent()`.

</Accordion>

<Accordion title="Форма `using`" icon="brackets-curly">

Когда работа — не одна функция — область, открытая в конструкторе и закрытая в очистке, или та, что пересекает существующий поток управления:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, затем agent_end
```

Обе формы испускают идентичные по байтам события. Предпочитайте форму callback: она выполняется внутри `AsyncLocalStorage.run()`, поэтому нечего разворачивать и весь класс ошибок типа „открыто здесь, закрыто там" недостижим.

Блок `using`, который перехватывает собственный отказ, сообщает об этом с помощью `span.fail(error)` — disposer не имеет собственного канала исключений.

</Accordion>

## Каталог событий

Те же пятнадцать методов, что и SDK Python, в camelCase. Большинство поставляются **парами** — вы вызываете открыватель, затем закрыватель, и SDK подсчитывает промежуток.

| | Открывает | Закрывает |
| --- | --- | --- |
| **Агенты** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Модели** | `modelRequest` | `modelResponse` |
| **Инструменты** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **Люди** | `humanWait` | `humanInput` |

Три стоят отдельно: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Каждое поле, по методам" icon="table">

Каждый метод также принимает `sessionId` и `agentId`, которые области действия заполняют за вас. Все пропущенное опускается, а не отправляется как JSON `null`.

| Метод | Обязательно | Опционально |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Любой другой ключ, который вы добавите, становится полем пользовательской нагрузки. Добавляйте префикс `fw_*` ко всему, зависимому от фреймворка; имя, конфликтующее с объявленным полем, отклоняется, а не молча перезаписывает продвигаемую колонку.

</Accordion>

<Warning>
  **`duration_ms` вычисляется, не принимается.** Четыре метода закрытия подсчитывают промежуток от своего открывателя и отклоняют `duration_ms`, предоставленный вызывающей стороной — сообщенная длительность неопровержима.

  Пары совпадают по **сессии** и id, никогда по агенту. Инструмент, открытый под `planner` и закрытый под `worker`, все еще совпадает, что и делают вложенные многоагентные запуски.
</Warning>

## Адаптеры фреймворков

```ts
await failproofai.instrument();              // все, что можно найти
await failproofai.instrument("langchain");   // ровно один
failproofai.uninstrument();                  // восстановить все
```

| Фреймворк | Поддерживается | Как подключается |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, поэтому все `invoke`/`stream`/`batch` покрыты без передачи `callbacks:` куда-либо — или передайте `langchainHandler()` сами и ничего не пatchируйте. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` на сайте вызова, или `instrument("ai")` для всего процесса на `ai` 7 (на 4–6 это opt-in — см. ниже). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, разрешение модели и инструментов агента, и engine выполнения workflow/step. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (subscribed) плюс `AgentWorkflow.runStream`, для запусков workflow и их steps. |

Каждый диапазон тестируется против реальных выпусков фреймворка с обеих концов, как ES модуль и CommonJS, на каждом запуске CI.

Это отображение из SDK Python, поэтому одна и та же программа рисует одно дерево на обоих языках. Конструкция — это **агент** только если она владеет циклом решений LLM — запуск графа или цепи, вызов Vercel AI SDK `generateText`/`streamText`, Mastra агент, запуск LlamaIndex агента. Узел LangGraph или step workflow — это **hook** (`hook_triggered`/`hook_completed`), никогда вложенный агент. Вызовы моделей — это пары `model_request`/`model_response` с подсчетами токенов; вызовы инструментов несут собственный id вызова инструмента модели. Отказ записывается один раз, на событие, где он произошел.

Адаптер, который не установился, логируется и пропускается; остальные все еще устанавливаются, потому что сломанный LlamaIndex не должен стоить вам LangGraph.

<Note>
  `instrument()` без аргумента обнаруживает фреймворк по тому, **разрешается** ли он, а не по тому, импортирован ли уже — Node не предоставляет эквивалент Python `sys.modules` для ES модулей. Фреймворк, который вы установили, но не используете, будет импортирован и patched. Назовите тот, который вам нужен, если это важно.
</Note>

<Note>
  Большинство этих фреймворков поставляют ES-module build и CommonJS build, которые Node загружает как две несвязанные копии. Адаптеры patchируют копию, которую загружает ваше приложение (и CommonJS копию тоже, если что-то уже `require`'d это), поэтому оба модульных системы работают. Фреймворк **bundled в ваш собственный output** esbuild или webpack недостижим — используйте там helpers вызова сайта: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain без patching

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

Handler работает с или без `instrument()` и никогда не делает double-record. `instrument("langchain")` принимает `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` и `captureLimit`, как делает adapter Python; `metadata: { failproofai_sdk_session_id }` на вызове выбирает сессию для этого вызова.

### Vercel AI SDK

AI SDK экспортирует plain функции из ES модуля, и ES модуль namespace неизменяем по спецификации — нет места для patching. Он использует точки расширения, которые сам SDK документирует:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // на ai 7, `telemetry: telemetry({ … })` — тот же объект, новое имя
});
```

Это полная интеграция: span агента, пара request/response модели за step с подсчетами токенов, и каждый вызов инструмента. Один сайт вызова работает на каждом major — `ai` 4–6 читают tracer, который он несет, `ai` 7 интеграцию telemetry.

`instrument("ai")` делает то же самое в масштабе процесса **на `ai` 7**: каждый вызов, через глобальный список интеграции telemetry AI SDK, который аддитивен и не берет ничего у остальных.

**На `ai` 4–6, `instrument("ai")` ничего не записывает сам и логирует одно предупреждение об этом.** Единственный hook в масштабе процесса, который есть у этих majors — это глобальный provider OpenTelemetry tracer — один slot, который OpenTelemetry отказывается отдать, когда взяли. Регистрация нашего молча отклонит ваш собственный `NodeSDK.start()` позже при startup и отправит ваши http/database spans в tracer, который ничего не экспортирует. Используйте `telemetry()` на сайте вызова или `wrapModel` там. Если процесс не запускает собственный OpenTelemetry, opt-in с `instrument("ai", { registerGlobalTracer: true })`: он затем записывает каждый вызов, который передает `experimental_telemetry: { isEnabled: true }`, и берет slot только если он все еще пуст. `registerGlobalTracer: false` сохраняет default и молчит об предупреждении.

Если вы предпочитаете завернуть модель один раз, `wrapModel` видит только вызовы модели, потому что вызовы инструментов происходят выше слоя модели. Завернутая модель, вызванная без ничего вокруг нее, записывается как ее собственный запуск. Streamed вызов закрывается тем, как поток останавливается — `stop_reason: "cancelled"` когда потребитель его отменяет, `"error"` с ошибкой когда это завершается пополам:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Использование обоих хорошо: middleware замечает вызов уже записывается и отступает, поэтому каждый вызов записывается один раз.

`functionId` называет span агента. Держите его низкой кардинальностью — он попадает в `agent_id`, первичный фасет интерфейса.

### Next.js

`next build` по умолчанию bundlирует зависимости вашего сервера, и фреймворк, bundled в build — это копия, которую `instrument()` не может достичь. Оборачивайте конфиг один раз и вызывайте `instrument()` из hook startup Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` добавляет LangChain, Mastra, LlamaIndex и сам SDK в `serverExternalPackages`, сохраняя ваш собственный список. Без этого, `instrument()` предупреждает один раз за фреймворк, который не может достичь, вместо молчаливого отказа; если вы лист пакеты сами, установите `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK и helpers вызова сайта работают в любом случае. Edge route получает no-op build: импорт SDK безопасен и ничего не записывает.

### Подсчеты токенов на streamed вызовах

API, совместимые с OpenAI, сообщают использование на потоке только когда клиент просит. LangChain и Vercel AI SDK просят; для LlamaIndex передайте `additionalChatOptions: { stream_options: { include_usage: true } }` его `OpenAI` LLM, и для Mastra постройте модель с включенным использованием (например `createOpenAICompatible({ includeUsage: true })`). Иначе streamed вызовы модели не имеют подсчетов токенов.

### Runtimes

Node ≥ 20.9, Bun и Deno — каждый фреймворк, как ES модуль и CommonJS, тестируется на каждом против Node trace. SDK работает рядом с `failproofaid` daemon, который отправляет то, что он пишет.

## Ваш собственный агент — без фреймворка

Для цикла агента, который вы написали сами, или фреймворка без адаптера. Вы испускаете события с тем же API, который адаптеры используют внизу, поэтому трассировка имеет ту же форму и качество.

Вам не нужно знать, как организован агент. Каждый ручной агент уже имеет три места, независимо от того, как называются его функции, и эти три — вся интеграция:

| Где | Что добавить | Испускает |
| --- | --- | --- |
| Где **один запуск** начинается и заканчивается | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Единственная функция, которая вызывает модель** | `event.modelRequest` перед, `event.modelResponse` после — обе половины, даже при отказе | одна пара за turn модели |
| **Единственная функция, которая запускает инструменты** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Идентичность окружающая: все внутри `agent()` попадает на сессию этого запуска без принятия id, и ничто больше в программе не меняется — включая то, что агент уже пишет в свою собственную базу данных.

- **Сервис или worker:** передайте ваш собственный request или job id как `sessionId`, чтобы сессия в интерфейсе и запись в ваших собственных логах или базе данных были одной и той же строкой.
- **Sub-agents:** вложите вызовы `agent()`. Внутренний присоединяется к сессии с внешним как его `parent_id`.
- **Испускайте пары.** `modelRequest` без `modelResponse` — это span, который интерфейс показывает как работающий вечно — отсюда `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) в репозитории — это полная, работающая версия: настоящий OpenAI tool loop, подключенный ровно так, как здесь, запускаемый в CI при каждом изменении как ES модуль и CommonJS.

## Оценки

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Смотрите [справочник Evaluator SDK](/ru/reference/evaluator-sdk) для протокола, настроек worker и типов результатов.

<Warning>
  **Оценка должна yield.** Синхронная функция, которая никогда не возвращается, блокирует единственный поток Node, и никакой timeout не может выстрелить пока это происходит. Пишите `async` оценки.
</Warning>

## Что он не будет делать с вашим процессом

| | |
| --- | --- |
| **Блокировать ваш цикл агента** | События попадают в очередь в памяти; таймер пишет их. Таймер `unref`'d, поэтому импорт этого пакета никогда не стопит выход скрипта. |
| **Расти без границ** | Очередь ограничена count *и* измеренными байтами. После любого, старейшие события отбрасываются и предупреждение об этом — outage телеметрии не должно стать OOM kill. |
| **Уронить процесс** | Одно неэнкодируемое событие опускается отдельно, не batch вокруг него. Выбрасывающий getter, circular reference, `BigInt`, lone surrogate: каждый обработан вместо распространения. |
| **Оставить half-written batch** | Содержимое `fsync`ed перед atomic rename, директория `fsync`ed после, и failed write очищает его временный файл. |
| **Оставить транскрипты читаемыми** | Batches `0600` внутри `0700` директории. Они несут goals, prompts, tool arguments и tool output. |
| **Отправить credentials** | API ключи, tokens, JWTs, bearer headers и secret-shaped assignments редактируются перед тем, как байты достигнут диска. Daemon редактирует снова перед upload. |
