Node 20.9 или новее. ESM и CommonJS. Без зависимостей времени выполнения.

<Note>
  Этот SDK и Python SDK записывают **одинаковые события в один и тот же буфер обмена**. Автопарк с Node-агентами и Python-агентами создаёт один набор сессий, а не два, и ничто в приборной панели их не различает. Выбирайте по сервису, а не по компании.

## Установка

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Адаптеры фреймворков поставляются в самом пакете. Фреймворки — **опциональные зависимости коллегиального уровня** — они объявлены, чтобы были видны поддерживаемые диапазоны, никогда не устанавливаются без вашего участия и импортируются только при вызове `instrument()`.

## Подключение демона Failproof

Идентично Python SDK: создайте ключ `events:add` в разделе **Admin → Keys**, затем [подключите демон](/ru/start/setup#connect-a-machine-to-cloud) на машине агента. SDK пишет на диск; демон отправляет данные.

## Конфигурация

### OpenTelemetry spans (опционально)

Установите OpenTelemetry отдельно с помощью `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
Затем добавьте FailproofAI к процессорам вашего провайдера:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Для существующего провайдера оставьте его остальные процессоры в том же списке. Провайдеры, которые предоставляют `addSpanProcessor`, могут быть переданы как `{ provider }`. Без опций инструментация регистрирует новый провайдер только если провайдер ещё не зарегистрирован.
`OtelSpanExporter` также может использоваться непосредственно с вашим собственным процессором.

Экспорт проходит через подключённый демон FailproofAI; SDK не отправляет сетевые запросы и не нуждается в ключе или локальном слушателе. Попросите администратора включить
[приём OpenTelemetry](/ru/agenteye/opentelemetry). Простой `instrument()` не включает этот экспортер. `uninstrument("otel")` отключает только его собственный процессор.
Ваши атрибуты span управляют захватом содержимого; очистите провайдер перед выходом.
OpenTelemetry остаётся опциональной зависимостью приложения, а не жёсткой зависимостью SDK.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Опция | Что это делает |
| --- | --- |
| `environment` | Метка на каждом событии — `production`, `staging`, `prod-eu`. По умолчанию `dev`. |
| `flushInterval` | Как часто таймер пишет на диск, в секундах. По умолчанию `0.5`. |
| `baseDir` | Где писать. По умолчанию буфер обмена демона, что вам и нужно, если вы не знаете иное. |

Ничего не применяется, если всё это не прошло валидацию, так что отклонённый вызов оставляет SDK в точности таким же, как он был, вместо того чтобы иметь новый `baseDir` и старый интервал.

Установите переменную окружения вместо этого:

| Переменная | Что это делает |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Устанавливает `environment` без изменения кода. Опция `configure()` имеет приоритет. |
| `FAILPROOFAI_HOME` | Перемещает корневую директорию Failproof AI, которая содержит буфер обмена. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (по умолчанию), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` заставляет ошибки инструментации выбрасываться вместо логирования. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` заставляет проблему совместимости фреймворка выбрасываться вместо предупреждения и продолжения. |

<Warning>
  **Без запятых в `environment`.** Приём разбивает это поле на запятые для построения фильтров и пропускает любое событие, метка которого содержит запятую — так что весь прогон молча исчезает. Напишите `prod-eu`, а не `prod,eu`.

  `configure({ environment: "prod,eu" })` выбрасывает исключение, чтобы вы сразу это узнали. `AGENTEYE_ENVIRONMENT` не может выбросить исключение — никто вас не вызывает — так что она предупреждает один раз и откатывается к `dev`.
</Warning>

Направьте собственные логи SDK в ваш логер с помощью `failproofai.setLogger({ debug, info, warn, error })`.

## Завершение

Буферизованные события очищаются при `process.on("exit")`.

Процесс, убитый сигналом, никогда это не достигает, и Node по умолчанию для `SIGTERM` завершает работу без выполнения обработчиков выхода — так что контейнеризованный агент теряет всё, что последний интервал не записал.

<Warning>
  **Этот SDK не будет установливать обработчик сигнала за вас.** Регистрация обработчика изменяет поведение вашего процесса: слушатель подавляет завершение по умолчанию в Node, так что библиотека, которая добавила бы его, молча остановила бы Ctrl-C от работы. Добавьте свой:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Короткоживущий скрипт или обработчик бессерверных функций должен выполнить `await failproofai.flush()` перед возвратом — одного интервала недостаточно для гарантии доставки.

## Идентичность

Каждое событие принадлежит сессии и агенту. **Области заполняют оба**, так что вы редко их передаёте:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

Передача `sessionId` или `agentId` явно по-прежнему работает и имеет приоритет. Если ни одно не связано и не передано, вызов выбрасывает исключение, а не отправляет событие, которое Cloud молча отбросит.

<Note>
  Идентичность работает на `AsyncLocalStorage`. Она следует за `await`, `.then()`, таймерами и любым обратным вызовом, созданным внутри области. Она **не** следует за обратным вызовом, сохранённым во время одного прогона и вызванным во время другого, и не работает с работой, переданной через границу `worker_threads` — оберните их в `failproofai.propagate()` или их события приземлятся без привязки.
</Note>

### Области

| Область | Отправляет | Возвращает |
| --- | --- | --- |
| `session(body)` | ничего — только идентичность | что возвращает `body` |
| `agent(id, options?, body)` | `agent_start`, затем `agent_end` | что возвращает `body` |
| `toolCall(name, options?, body)` | `tool_use`, затем `tool_result` | что возвращает `body` |

Синхронное тело остаётся синхронным: `agent("x", () => 1)` возвращает `1`, а не обещание.

`toolCall` записывает разрешённое значение тела как `output` инструмента, если вы сами не присвоили `call.output`.

<Accordion title="Семантика выхода" icon="arrow-right-from-bracket">

| Что произошло | События | `outcome` |
| --- | --- | --- |
| блок вернул значение | `agent_end` | `"success"`, или ваш `outcome` |
| блок выбросил исключение | `error`, затем `agent_end` | `"failed"` |
| `AbortError` | только `agent_end` | `"cancelled"` |

Исключение всегда переиспускается.

Сбой инструмента записывается на листе — `tool_result` с строкой `error` — и **не** отправляет событие `error` уровня прогона. Сбой, который перехватывает цикл агента, — это не сбой прогона, и сбой, который распространяется, сообщается ровно один раз, отнесённым `agent()`.

</Accordion>

<Accordion title="Форма `using`" icon="brackets-curly">

Когда работа — не одна функция — область, открытая в конструкторе и закрытая в очистке, или одна, которая пересекает существующий поток управления:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, затем agent_end
```

Обе формы отправляют события, идентичные по байтам. Предпочитайте форму обратного вызова: она работает внутри `AsyncLocalStorage.run()`, так что разворачивать нечего, и весь класс ошибок «открыто здесь, закрыто там» недостижим.

Блок `using`, который ловит свой собственный сбой, сообщает о нём с помощью `span.fail(error)` — у распределителя нет своего канала исключения.

</Accordion>

## Каталог событий

Те же пятнадцать методов, что и Python SDK, в camelCase. Большинство идут **парами** — вы вызываете открывающий, затем закрывающий, и SDK отсчитывает промежуток.

| | Открывает | Закрывает |
| --- | --- | --- |
| **Агенты** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Модели** | `modelRequest` | `modelResponse` |
| **Инструменты** | `toolUse` | `toolResult` |
| **Хуки** | `hookTriggered` | `hookCompleted` |
| **Люди** | `humanWait` | `humanInput` |

Три стоят отдельно: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Каждое поле для каждого метода" icon="table">

Каждый метод также принимает `sessionId` и `agentId`, которые области заполняют за вас. Всё опущенное отбрасывается, а не отправляется как JSON `null`.

| Метод | Обязательно | Опционально |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Любой другой ключ, который вы добавите, становится полем пользовательского сохранения. Добавьте пространство имён для всего, относящегося к фреймворку, как `fw_*`; имя, которое сталкивается с объявленным полем, отклоняется, а не молча перезаписывает повышенный столбец.

</Accordion>

<Warning>
  **`duration_ms` вычисляется, а не принимается.** Четыре закрывающих метода отсчитывают промежуток от своего открывающего и отклоняют предоставленный вызывающим `duration_ms` — сообщённую продолжительность невозможно подделать.

  Пары согласуются на **сессии** и id, никогда не на агенте. Инструмент, открытый под `planner` и закрытый под `worker`, по-прежнему согласуется, что это именно то, что на самом деле делают вложенные мультиагентные прогоны.
</Warning>

## Адаптеры фреймворков

```ts
await failproofai.instrument();              // что-нибудь, если сможет найти
await failproofai.instrument("langchain");   // ровно один
failproofai.uninstrument();                  // всё верните как было
```

| Фреймворк | Поддерживается | Как она подключается |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, так что каждый `invoke`/`stream`/`batch` покрыт без передачи `callbacks:` куда-либо — или передайте `langchainHandler()` сами и не патчьте ничего. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` на месте вызова, или `instrument("ai")` для всего процесса на `ai` 7 (на 4–6 это опционально — см. ниже). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, разрешение модели и инструмента агента, и двигатель запуска/шага рабочего процесса. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (подписан) плюс `AgentWorkflow.runStream`, для запусков рабочих процессов и их шагов. |

Каждый диапазон тестируется против реальных выпусков фреймворков, на обоих концах, как модуль ES и как CommonJS, на каждом прогоне CI.

Отображение — это отображение Python SDK, так что одна и та же программа рисует одно и то же дерево на обоих языках. Конструкция — это **агент** только если она владеет циклом принятия решений LLM — запуск графа или цепи, вызов `generateText`/`streamText` AI SDK, агент Mastra, запуск агента LlamaIndex. Узел LangGraph или шаг рабочего процесса — это **хук** (`hook_triggered`/`hook_completed`), никогда не вложенный агент. Вызовы модели — это пары `model_request`/`model_response` с подсчётами токенов; вызовы инструментов несут собственный id вызова инструмента модели. Сбой записывается один раз, на событии, где он произошёл.

Адаптер, который не может быть установлен, логируется и пропускается; остальные по-прежнему устанавливаются, потому что поломанный LlamaIndex не должен стоить вам LangGraph.

<Note>
  `instrument()` без аргумента обнаруживает фреймворк по тому, **разрешается ли** он, а не по тому, уже ли он импортирован — Node не предоставляет эквивалента Python `sys.modules` для модулей ES. Фреймворк, который вы установили, но не используете, будет импортирован и запатчен. Назовите тот, который вам нужен, если это имеет значение.
</Note>

<Note>
  Большинство этих фреймворков поставляются с модулем ES и модулем CommonJS, которые Node загружает как две несвязанные копии. Адаптеры патчат копию, которую загружает ваше приложение (и копию CommonJS тоже, если что-то уже `require`'d её), так что оба модульные системы работают. Фреймворк, **встроенный в ваш собственный вывод** с помощью esbuild или webpack, недостижим — используйте там помощников места вызова: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain без патчинга

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

Обработчик работает с `instrument()` или без него и никогда не записывает дважды. `instrument("langchain")` принимает `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` и `captureLimit`, как делает адаптер Python; `metadata: { failproofai_sdk_session_id }` на вызове выбирает сессию для этого вызова.

### Vercel AI SDK

AI SDK экспортирует обычные функции из модуля ES, и пространство имён модуля ES неизменяемо по спецификации — нет места для патчинга. Он использует точки расширения, которые сам SDK документирует:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // на ai 7, `telemetry: telemetry({ … })` — тот же объект, новое имя
});
```

Это полная интеграция: span агента, пара запрос/ответ модели за шаг с подсчётами токенов, и каждый вызов инструмента. Одно место вызова работает на каждый основной — `ai` 4–6 читают трассировщик, который он несёт, `ai` 7 интеграцию телеметрии.

`instrument("ai")` делает то же самое на весь процесс **на `ai` 7**: каждый вызов, через список интеграции глобальной телеметрии AI SDK, который дополнительный и ничего не берёт у других.

**На `ai` 4–6, `instrument("ai")` по себе ничего не записывает, и логирует одно предупреждение, говорящее об этом.** Единственный хук на весь процесс, который есть у этих основных, — это глобальный провайдер трассировщика OpenTelemetry — одиночный слот, который OpenTelemetry отказывается передавать, один раз взятый. Регистрация нашего молча отказала бы вашему собственному `NodeSDK.start()` позже во время запуска и отправила бы ваши http/database spans трассировщику, который ничего не экспортирует. Используйте `telemetry()` на месте вызова или `wrapModel` там. Если процесс не запускает никакой OpenTelemetry сам, выбирайте с помощью `instrument("ai", { registerGlobalTracer: true })`: он затем записывает каждый вызов, который проходит `experimental_telemetry: { isEnabled: true }`, и только берёт слот, если он ещё пуст. `registerGlobalTracer: false` хранит умолчание и молчит предупреждение.

Если вы предпочитаете обернуть модель один раз, `wrapModel` видит только вызовы модели, потому что вызовы инструмента происходят выше слоя модели. Обёрнутая модель, вызванная с ничем вокруг неё, записывается как её собственный прогон. Потоковый вызов закрывается, однако останавливается поток — `stop_reason: "cancelled"` когда потребитель его отменяет, `"error"` с ошибкой, когда он частично не выполняется:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Использование обоих хорошо: промежуточное ПО замечает, что вызов уже записывается, и отступает, так что каждый вызов записывается один раз.

`functionId` именует span агента. Держите его с низкой мощностью — он приземляется в `agent_id`, основной аспект приборной панели.

### Next.js

`next build` по умолчанию комплектует зависимости вашего сервера, и фреймворк, скомплектованный в сборку, — это копия, которой `instrument()` не может достичь. Оберните конфиг один раз и вызовите `instrument()` из хука запуска Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* ваш конфиг */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` добавляет LangChain, Mastra, LlamaIndex и сам SDK к `serverExternalPackages`, сохраняя ваш собственный список. Без него, `instrument()` предупреждает один раз за фреймворк, который не может достичь, вместо того чтобы молчать не выполнить; если вы указываете пакеты сами, установите `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK и помощники места вызова работают в любом случае. Edge-маршрут получает нет-оп-сборку: импортирование SDK безопасно и ничего не записывает.

### Подсчёты токенов на потоковых вызовах

API, совместимые с OpenAI, сообщают использование на потоке только когда клиент просит. LangChain и Vercel AI SDK просят; для LlamaIndex передайте `additionalChatOptions: { stream_options: { include_usage: true } }` его `OpenAI` LLM, и для Mastra постройте модель с включённым использованием (например `createOpenAICompatible({ includeUsage: true })`). В противном случае потоковые вызовы модели не несут подсчётов токенов.

### Рантаймы

Node ≥ 20.9, Bun и Deno — каждый фреймворк, как модуль ES и как CommonJS, тестируется на каждом против трассировки Node. SDK работает рядом с демоном `failproofaid`, который отправляет то, что он пишет.

## Ваш собственный агент — без фреймворка

Для цикла агента, который вы написали сами, или для фреймворка без адаптера. Вы отправляете события с тем же API, который адаптеры используют под капотом, так что след имеет ту же форму и качество.

Вам не нужно знать, как организован агент. Каждый самодельный агент уже имеет три места, какими бы его функциями они ни были названы, и эти три — вся интеграция:

| Где | Что добавить | Отправляет |
| --- | --- | --- |
| Где **один прогон** начинается и заканчивается | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Единственная функция, которая вызывает модель** | `event.modelRequest` перед, `event.modelResponse` после — обе половины, даже при сбое | одна пара за ход модели |
| **Единственная функция, которая запускает инструменты** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Идентичность — окружающая среда: всё внутри `agent()` приземляется на сессию этого прогона без принятия id, и ничто другое в программе не меняется — включая всё, что агент уже пишет в свою собственную базу данных.

- **Сервис или работник:** передайте свой собственный id запроса или работы как `sessionId`, так что сессия на приборной панели и запись в ваших собственных логах или базе данных — одна и та же строка.
- **Под-агенты:** вложите вызовы `agent()`. Внутренняя присоединяется к сессии с внешней как её `parent_id`.
- **Отправляйте пары.** `modelRequest` без `modelResponse` — это span, который приборная панель показывает как работающий вечно — отсюда `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) в хранилище — полная, работающая версия: настоящий цикл инструмента OpenAI, инструментированный ровно таким образом, запущенный в CI при каждом изменении как модуль ES и как CommonJS.

## Оценки

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Смотрите [справку Evaluator SDK](/ru/reference/evaluator-sdk) для протокола, параметров работника и типов результатов.

<Warning>
  **Оценка должна уступать.** Синхронная функция, которая никогда не возвращается, блокирует единственный поток Node, и никакой таймаут не может срабатывать, пока она это делает. Напишите `async` оценки.
</Warning>

## Что она не будет делать с вашим процессом

| | |
| --- | --- |
| **Блокировать ваш цикл агента** | События попадают в очередь в памяти; таймер пишет их. Таймер `unref`'d, так что импортирование этого пакета никогда не останавливает выход скрипта. |
| **Расти без границ** | Очередь ограничена по количеству *и* по измеренным байтам. Прошедшего любого, самые старые события отбрасываются, и предупреждение говорит об этом — сбой телеметрии не должен стать убийцей OOM. |
| **Снять процесс** | Одно неправильно кодируемое событие отбрасывается одно, не партия вокруг него. Выбрасывающий геттер, циклическая ссылка, `BigInt`, одиночный суррогат: каждое обрабатывается, а не распространяется. |
| **Оставить наполовину записанную партию** | Содержание `fsync`'ed перед атомарным переименованием, директория `fsync`'ed после, и неудачная запись очищает свой временный файл. |
| **Оставить расшифровки читаемыми** | Партии `0600` внутри директории `0700`. Они несут цели, подсказки, аргументы инструмента и вывод инструмента. |
| **Отправить учётные данные** | Ключи API, токены, JWT, заголовки bearer и присваивания формы секрета редактируются перед тем, как байты достигнут диска. Демон редактирует снова перед загрузкой. |
