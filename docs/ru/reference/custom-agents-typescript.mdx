Node 20.9 или новее. ESM и CommonJS. Без зависимостей во время выполнения.

<Note>
  Этот SDK и Python-версия записывают **одинаковые события в один буфер**. Парк с Node-агентами и Python-агентами создаёт один набор сессий, а не два, и в панели управления их ничего не различает. Выбирайте по сервисам, а не по компаниям.

## Установка

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Адаптеры фреймворков поставляются в самом пакете. Фреймворки — **необязательные peer-зависимости** — указаны так, чтобы поддерживаемые диапазоны версий были видны, они никогда не устанавливаются автоматически и импортируются только при вызове `instrument()`.

## Подключение демона Failproof

Идентично Python SDK: создайте ключ `events:add` в разделе **Admin → Keys**, затем [подключите демон](/ru/start/setup#connect-a-machine-to-cloud) на машине агента. SDK пишет на диск; демон передаёт данные.

## Конфигурация

### OpenTelemetry spans (опция)

Установите OpenTelemetry отдельно с помощью `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
Затем добавьте FailproofAI в процессоры вашего провайдера:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Для существующего провайдера оставьте его другие процессоры в том же списке. Провайдеры, предоставляющие `addSpanProcessor`, можно вместо этого передать как `{ provider }`. Без параметров установка регистрирует новый провайдер только если его ещё нет.
`OtelSpanExporter` можно также использовать напрямую с собственным процессором.

Экспорт происходит через подключённый демон FailproofAI; SDK не отправляет сетевые запросы и не нуждается в ключе или локальном прослушивателе. Попросите администратора включить
[OpenTelemetry ingest](/ru/agenteye/opentelemetry). Простой `instrument()` не активирует этот экспортёр. `uninstrument("otel")` отключает только его процессор.
Ваши span-атрибуты контролируют захват содержимого; выполните flush вашего провайдера перед выходом.
OpenTelemetry остаётся необязательной зависимостью приложения, а не жёсткой зависимостью SDK.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Параметр | Что это делает |
| --- | --- |
| `environment` | Метка на каждом событии — `production`, `staging`, `prod-eu`. По умолчанию `dev`. |
| `flushInterval` | Как часто таймер пишет на диск, в секундах. По умолчанию `0.5`. |
| `baseDir` | Куда писать. По умолчанию буфер демона, что вам и нужно, если вы не знаете иного. |

Ничего не применяется, пока не пройдёт валидация, поэтому отклонённый вызов оставляет SDK в его прежнем состоянии, а не с новым `baseDir` и старым интервалом.

Установите через переменную окружения:

| Переменная | Что это делает |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Устанавливает `environment` без изменения кода. Параметр `configure()` имеет приоритет. |
| `FAILPROOFAI_HOME` | Перемещает корневую директорию Failproof AI, которая содержит буфер. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (по умолчанию), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` заставляет ошибки инструментации бросать исключение вместо логирования. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` заставляет проблему совместимости фреймворка бросать исключение вместо предупреждения. |

<Warning>
  **Без запятых в `environment`.** Ingest разбивает это поле по запятым для построения фильтров и пропускает любое событие, метка которого содержит запятую — поэтому весь запуск тихо исчезнет. Пишите `prod-eu`, а не `prod,eu`.

  `configure({ environment: "prod,eu" })` бросает исключение, чтобы вы узнали сразу. `AGENTEYE_ENVIRONMENT` не может бросить исключение — вас никто не вызывает — поэтому он предупреждает один раз и возвращается к `dev`.
</Warning>

Маршрутизируйте собственные логи SDK в ваш логгер с помощью `failproofai.setLogger({ debug, info, warn, error })`.

## Завершение

События в буфере сбрасываются при `process.on("exit")`.

Процесс, убитый сигналом, никогда до этого не доходит, и по умолчанию Node для `SIGTERM` — завершиться без запуска обработчиков выхода — поэтому контейнеризованный агент теряет то, что последний интервал не записал.

<Warning>
  **Этот SDK не установит для вас обработчик сигнала.** Регистрация одного изменяет поведение вашего процесса: прослушиватель подавляет завершение Node по умолчанию, поэтому библиотека, которая добавила его, молча остановит работу Ctrl-C. Добавьте собственный:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Краткоживущий скрипт или обработчик serverless должен вызвать `await failproofai.flush()` перед возвратом — один интервал не гарантирует доставку.

## Идентичность

Каждое событие принадлежит сессии и агенту. **Области видимости заполняют оба**, поэтому вы редко передаёте их:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

Передача `sessionId` или `agentId` явно всё ещё работает и имеет приоритет. Без привязки или передачи вызов выбросит исключение вместо излучения события, которое Cloud молча отклонит.

<Note>
  Идентичность работает на `AsyncLocalStorage`. Она следует `await`, `.then()`, таймерам и любому обратному вызову, созданному внутри области. Она **не** следует обратному вызову, сохранённому во время одного запуска и вызванному во время другого, и не работает через границу `worker_threads` — оберните их в `failproofai.propagate()` или их события останутся неприкреплёнными.
</Note>

### Области видимости

| Область | Излучает | Возвращает |
| --- | --- | --- |
| `session(body)` | ничего — только идентичность | что бы ни вернул `body` |
| `agent(id, options?, body)` | `agent_start`, затем `agent_end` | что бы ни вернул `body` |
| `toolCall(name, options?, body)` | `tool_use`, затем `tool_result` | что бы ни вернул `body` |

Синхронный body остаётся синхронным: `agent("x", () => 1)` возвращает `1`, а не промис.

`toolCall` записывает разрешённое значение body как `output` инструмента, если вы не присвоили `call.output` сами.

<Accordion title="Семантика выхода" icon="arrow-right-from-bracket">

| Что произошло | События | `outcome` |
| --- | --- | --- |
| блок вернул результат | `agent_end` | `"success"`, или ваш `outcome` |
| блок выбросил исключение | `error`, затем `agent_end` | `"failed"` |
| `AbortError` | только `agent_end` | `"cancelled"` |

Исключение всегда переброшено.

Отказ инструмента записывается на листе — `tool_result` с ошибочной строкой — и излучает **никаких** событий на уровне запуска. Один, который ловит цикл агента, — не отказ запуска, а один, который распространяется, — указывается ровно один раз enclosing `agent()`.

</Accordion>

<Accordion title="Форма `using`" icon="brackets-curly">

Когда работа — не одна функция — область видимости, открытая в конструкторе и закрытая в teardown, или одна, которая пересекает существующий поток управления:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, затем agent_end
```

Обе формы излучают байт-идентичные события. Предпочитайте форму с обратным вызовом: она запускается внутри `AsyncLocalStorage.run()`, поэтому нечего разворачивать и весь класс багов через выхода невозможен.

Блок `using`, который ловит свой собственный отказ, сообщает о нём с помощью `span.fail(error)` — disposer не имеет собственного канала исключений.

</Accordion>

## Каталог событий

Те же пятнадцать методов, что и Python SDK, в camelCase. Большинство поставляются в **парах** — вы вызываете открывающий, затем закрывающий, и SDK отсчитывает промежуток.

| | Открывает | Закрывает |
| --- | --- | --- |
| **Агенты** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Модели** | `modelRequest` | `modelResponse` |
| **Инструменты** | `toolUse` | `toolResult` |
| **Хуки** | `hookTriggered` | `hookCompleted` |
| **Люди** | `humanWait` | `humanInput` |

Три стоят отдельно: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Каждое поле для каждого метода" icon="table">

Каждый метод также принимает `sessionId` и `agentId`, которые области видимости заполняют для вас. Что-либо пропущенное удаляется вместо отправки как JSON `null`.

| Метод | Обязательно | Опционально |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Любой другой ключ, который вы добавите, становится полем пользовательского payload. Используйте пространство имён для чего-либо специфичного для фреймворка как `fw_*`; имя, которое конфликтует с объявленным полем, отклоняется вместо молчаливого перезаписывания повышенной колонки.

</Accordion>

<Warning>
  **`duration_ms` вычисляется, не принимается.** Четыре закрывающих метода отсчитывают промежуток от их открывающего и отклоняют supplied `duration_ms` — сообщаемая продолжительность неподделываема.

  Пары сопоставляются на **сессии** и id, никогда не на агенте. Инструмент, открытый под `planner` и закрытый под `worker`, всё ещё спаривается, что и делают настоящие вложенные мультиагентные запуски.
</Warning>

## Адаптеры фреймворков

```ts
await failproofai.instrument();              // что угодно, что можно найти
await failproofai.instrument("langchain");   // ровно один
failproofai.uninstrument();                  // всё вернуть обратно
```

| Фреймворк | Поддерживается | Как присоединяется |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, поэтому каждый `invoke`/`stream`/`batch` охватывается без передачи `callbacks:` где-либо — или передайте `langchainHandler()` сами и ничего не патчьте. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` в месте вызова, или `instrument("ai")` для всего процесса на `ai` 7 (на 4–6 это opt-in — смотрите ниже). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, разрешение модели и инструментов агента, и engine запусков/шагов workflow. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (подписано) плюс `AgentWorkflow.runStream`, для запусков workflow и их шагов. |

Каждый диапазон протестирован против настоящих релизов фреймворков с обоих концов, как ES модуль и как CommonJS, на каждом запуске CI.

Отображение — то же самое, что и Python SDK, поэтому одна и та же программа рисует одно и то же дерево в любом языке. Конструкция — это **агент** только если она владеет цикл принятия решений LLM — запуск графа или цепи, вызов `generateText`/`streamText` AI SDK, агент Mastra, запуск агента LlamaIndex. Ноду LangGraph или шаг workflow — это **хук** (`hook_triggered`/`hook_completed`), никогда не вложенный агент. Вызовы модели — это пары `model_request`/`model_response` с подсчётом токенов; вызовы инструментов несут собственный id вызова инструмента модели. Отказ записывается один раз в событии, в котором он произошёл.

Адаптер, который не устанавливается, логируется и пропускается; остальные всё ещё устанавливаются, потому что сломанная LlamaIndex не должна стоить вам LangGraph.

<Note>
  `instrument()` без аргумента обнаруживает фреймворк по тому, **разрешается** ли он, а не по тому, уже ли он импортирован — Node не раскрывает эквивалент Python's `sys.modules` для ES модулей. Фреймворк, который у вас установлен, но не используется, будет импортирован и пропатчен. Назовите тот, который вам нужен, если это важно.
</Note>

<Note>
  Большинство этих фреймворков поставляют ES-модульную сборку и CommonJS-сборку, которые Node загружает как две не связанные копии. Адаптеры патчат копию, которую загружает ваше приложение (и CommonJS копию тоже, если что-то уже `require`'d её), поэтому обе системы модулей работают. Фреймворк **упакован в вашу собственную сборку** esbuild или webpack недостижим — используйте там помощников вызовов: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain без патчирования

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

Обработчик работает с `instrument()` или без и никогда не записывает дважды. `instrument("langchain")` принимает `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` и `captureLimit`, как делает Python адаптер; `metadata: { failproofai_sdk_session_id }` в вызове выбирает сессию для этого вызова.

### Vercel AI SDK

AI SDK экспортирует простые функции из ES модуля, и пространство имён ES модуля неизменяемо по спецификации — нет места для патчирования. Оно использует точки расширения, которые документирует сам SDK:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // на ai 7, `telemetry: telemetry({ … })` — тот же объект, новое имя
});
```

Это полная интеграция: span агента, пара запроса/ответа модели за шаг с подсчётом токенов, и каждый вызов инструмента. Одна точка вызова работает на каждой мажорной версии — `ai` 4–6 читают трейсер, который он несёт, `ai` 7 интеграцию телеметрии.

`instrument("ai")` делает то же самое процесс-широко **на `ai` 7**: каждый вызов, через глобальный список интеграций телеметрии AI SDK, который добавляет и ничего не берёт у кого-либо ещё.

**На `ai` 4–6, `instrument("ai")` ничего не записывает сам по себе и логирует одно предупреждение об этом.** Единственный процесс-широкий хук, который есть в этих мажорах — это глобальный провайдер трейсера OpenTelemetry — один слот, который OpenTelemetry отказывается передать после взятия. Регистрация нашего молча отклонит ваш собственный `NodeSDK.start()` позже при запуске и отправит ваши http/database spans трейсеру, который ничего не экспортирует. Используйте `telemetry()` в месте вызова или `wrapModel` там. Если процесс не запускает собственный OpenTelemetry, opt in с `instrument("ai", { registerGlobalTracer: true })`: он затем записывает каждый вызов, который передаёт `experimental_telemetry: { isEnabled: true }`, и принимает слот только если он всё ещё пуст. `registerGlobalTracer: false` сохраняет значение по умолчанию и подавляет предупреждение.

Если вы бы скорее обёрнули модель один раз, `wrapModel` видит только вызовы модели, потому что вызовы инструментов происходят выше слоя модели. Обёрнутая модель, вызванная с ничем вокруг, записывается как собственный запуск. Потоковый вызов закрывается, как бы не остановился поток — `stop_reason: "cancelled"` когда потребитель отменяет его, `"error"` с ошибкой когда он отказывает по дороге:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Использование обоих хорошо: middleware замечает, что вызов уже записывается и откладывает, поэтому каждый вызов записывается один раз.

`functionId` называет span агента. Держите низкой кардинальность — он попадает в `agent_id`, первичный facet панели управления.

### Next.js

`next build` упаковывает зависимости вашего сервера по умолчанию, и фреймворк, упакованный в сборку, — это копия, которую `instrument()` не может достичь. Оберните конфигурацию один раз и вызовите `instrument()` из хука запуска Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` добавляет LangChain, Mastra, LlamaIndex и сам SDK в `serverExternalPackages`, сохраняя ваш собственный список. Без него, `instrument()` предупреждает один раз за фреймворк, который он не может достичь, вместо молчаливого отказа; если вы сами указали пакеты, установите `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK и помощники вызовов работают в любом случае. Edge маршрут получает no-op сборку: импорт SDK безопасен и ничего не записывает.

### Подсчёт токенов на потоковых вызовах

OpenAI-совместимые API сообщают использование в потоке только когда клиент просит. LangChain и Vercel AI SDK просят; для LlamaIndex передайте `additionalChatOptions: { stream_options: { include_usage: true } }` его `OpenAI` LLM, и для Mastra постройте модель с включённым использованием (например `createOpenAICompatible({ includeUsage: true })`). В противном случае потоковые вызовы модели не несут подсчётов токенов.

### Рантаймы

Node ≥ 20.9, Bun и Deno — каждый фреймворк, как ES модуль и как CommonJS, протестирован на каждом против Node's трейса. SDK работает рядом с демоном `failproofaid`, который поставляет то, что он пишет.

## Ваш собственный агент — без фреймворка

Для цикла агента, который вы написали сами, или для фреймворка без адаптера. Вы излучаете события с тем же API, который адаптеры используют внизу, поэтому трейс имеет ту же форму и качество.

Вам не нужно знать, как организован агент. Каждый написанный вручную агент уже имеет три места, как бы ни назывались его функции, и эти три — вся интеграция:

| Где | Что добавить | Излучает |
| --- | --- | --- |
| Где **один запуск** начинается и заканчивается | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Одна функция, которая вызывает модель** | `event.modelRequest` перед, `event.modelResponse` после — обе половины, даже при отказе | одна пара за ход модели |
| **Одна функция, которая запускает инструменты** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Идентичность окружает: всё внутри `agent()` попадает на сессию того запуска без получения id, и ничего больше в программе не меняется — включая то, что агент уже пишет в свою собственную базу данных.

- **Сервис или рабочий:** передайте собственный id запроса или работы как `sessionId`, поэтому сессия на панели управления и запись в вашем собственном логе или базе данных — это одна и та же строка.
- **Подагенты:** вложите вызовы `agent()`. Внутренний присоединяется к сессии с внешним как его `parent_id`.
- **Излучайте пары.** `modelRequest` без `modelResponse` — это span, который панель управления показывает как работающий вечно — отсюда и `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) в репозитории — это полная, запускаемая версия: настоящий OpenAI tool loop, инструментированный точно так же, запущен в CI на каждом изменении как ES модуль и как CommonJS.

## Оценки

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Смотрите [справку Evaluator SDK](/ru/reference/evaluator-sdk) для протокола, параметров рабочего и типов результатов.

<Warning>
  **Оценка должна yield.** Синхронная функция, которая никогда не возвращает, блокирует один поток, который есть у Node, и никакой таймаут не может срабатить пока она это делает. Пишите `async` оценки.
</Warning>

## Что это не будет делать с вашим процессом

| | |
| --- | --- |
| **Блокировать цикл агента** | События попадают в буфер в памяти; таймер пишет их. Таймер — `unref`'d, поэтому импорт этого пакета никогда не останавливает выход скрипта. |
| **Расти без границ** | Буфер ограничен по счёту *и* по измеренным байтам. Прошлый любой, самые старые события отбрасываются и предупреждение говорит об этом — сбой телеметрии не должен стать OOM kill. |
| **Сбить процесс** | Одно неencoding событие опускается одно, не батч вокруг него. Бросающийся getter, циклическая ссылка, `BigInt`, одиночный суррогат: каждый обрабатывается вместо распространения. |
| **Оставить полусписанный батч** | Контент `fsync`ed перед атомным переименованием, директория `fsync`ed после, и неудавшая запись очищает свой временный файл. |
| **Оставить расшифровки читаемыми** | Батчи — `0600` внутри `0700` директории. Они несут цели, подсказки, аргументы инструмента и вывод инструмента. |
| **Отправить учётные данные** | Ключи API, токены, JWTs, bearer заголовки и secret-образные назначения редактируются перед тем, как байты достигают диска. Демон редактирует снова перед загрузкой. |
