Node 20.9 или новее. ESM и CommonJS. Нет зависимостей во время выполнения.

<Note>
  Этот SDK и Python SDK записывают **одни и те же события в одну и ту же очередь**. Парк с Node агентами и Python агентами создает один набор сессий, а не два, и ничего в дашборде их не различает. Выбирайте по сервису, а не по компании.
</Note>

## Установка

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Адаптеры фреймворков поставляются вместе с пакетом. Фреймворки — это **опциональные peer-зависимости** — указаны так, чтобы были видны поддерживаемые диапазоны, никогда не устанавливаются без вашего ведома, и импортируются только когда вы вызываете `instrument()`.

## Подключение демона Failproof

Идентично Python SDK: создайте ключ `events:add` в разделе **settings → api keys**, затем [подключите демон](/ru/start/setup#connect-a-machine-to-cloud) на машине агента. SDK пишет на диск; демон отправляет данные.

## Конфигурация

### OpenTelemetry spans (опционально)

Установите OpenTelemetry отдельно с помощью `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
Затем добавьте FailproofAI в процессоры вашего провайдера:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Для существующего провайдера оставьте его другие процессоры в том же списке. Провайдеры,
которые предоставляют `addSpanProcessor`, можно вместо этого передать как `{ provider }`. Без
параметров setup регистрирует новый провайдер только если провайдер еще не зарегистрирован.
`OtelSpanExporter` также можно использовать напрямую с вашим собственным процессором.

Экспорт идет через подключенный демон FailproofAI; SDK не отправляет сетевые
запросы и не требует ключ или локальный слушатель. [OpenTelemetry ingest](/ru/agenteye/opentelemetry)
всегда включен в Cloud. Простой `instrument()` этот экспортер не включает.
`uninstrument("otel")` отключает только его собственный процессор.
Ваши атрибуты span контролируют перехват содержимого; сбросьте провайдер перед выходом.
OpenTelemetry остается опциональной зависимостью приложения, а не обязательной зависимостью SDK.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Параметр | Что он делает |
| --- | --- |
| `environment` | Метка на каждом событии — `production`, `staging`, `prod-eu`. По умолчанию `dev`. |
| `flushInterval` | Как часто таймер пишет на диск, в секундах. По умолчанию `0.5`. |
| `baseDir` | Куда писать. По умолчанию очередь демона, что вам нужно, если вы не знаете иное. |

Ничего не применяется, пока не проверится все целиком, поэтому отклоненный вызов оставляет SDK в точности таким же, как был, вместо того чтобы иметь новый `baseDir` и старый интервал.

Установите вместо этого переменной окружения:

| Переменная | Что она делает |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Устанавливает `environment` без изменения кода. Параметр `configure()` имеет приоритет. |
| `FAILPROOFAI_HOME` | Перемещает корневой каталог Failproof AI, который содержит очередь. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (по умолчанию), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` заставляет ошибки инструментации выбрасывать исключение вместо логирования. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` заставляет проблему совместимости фреймворка выбросить исключение вместо предупреждения и продолжения. |

<Warning>
  **Нет запятых в `environment`.** Ingest разделяет это поле на запятые для создания своих фильтров и пропускает любое событие, метка которого содержит запятую — поэтому весь прогон тихо исчезнет. Пишите `prod-eu`, а не `prod,eu`.

  `configure({ environment: "prod,eu" })` выбросит исключение, чтобы вы узнали сразу. `AGENTEYE_ENVIRONMENT` не может выбросить — никто вас не вызывает — поэтому он предупредит один раз и вернется к `dev`.
</Warning>

Перенаправьте собственные строки логов SDK в ваш логгер с помощью `failproofai.setLogger({ debug, info, warn, error })`.

## Завершение

Буферизованные события сбрасываются при `process.on("exit")`.

Процесс, убитый сигналом, никогда не достигает этого, и значение Node по умолчанию для `SIGTERM` — прекратить работу без запуска обработчиков выхода — поэтому контейнеризованный агент теряет все, что последний интервал не записал.

<Warning>
  **Этот SDK не установит для вас обработчик сигналов.** Регистрация обработчика изменяет поведение вашего процесса: слушатель подавляет завершение Node по умолчанию, поэтому библиотека, которая добавила бы один, тихо остановит работу Ctrl-C. Добавьте свой собственный:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Краткосрочный скрипт или обработчик serverless должен выполнить `await failproofai.flush()` перед возвратом — один интервал не гарантирует доставку.

## Идентичность

Каждое событие принадлежит сессии и агенту. **Области заполняют оба**, поэтому вы редко их передаете:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

Явная передача `sessionId` или `agentId` все еще работает и имеет приоритет. Без привязки и передачи вызов выбрасывает исключение, а не выдает событие, которое Cloud тихо отклонит.

<Note>
  Идентичность основана на `AsyncLocalStorage`. Она следует `await`, `.then()`, таймерам и любому callback-у, созданному внутри области. Она **не** следует callback-у, сохраненному во время одного прогона и вызванному во время другого, или работе, переданной через границу `worker_threads` — оберните их в `failproofai.propagate()` или их события останутся неприкрепленными.
</Note>

### Области

| Область | Выдает | Возвращает |
| --- | --- | --- |
| `session(body)` | ничего — только идентичность | то, что возвращает `body` |
| `agent(id, options?, body)` | `agent_start`, затем `agent_end` | то, что возвращает `body` |
| `toolCall(name, options?, body)` | `tool_use`, затем `tool_result` | то, что возвращает `body` |

Синхронное тело остается синхронным: `agent("x", () => 1)` возвращает `1`, а не promise.

`toolCall` записывает разрешенное значение тела как `output` инструмента, если только вы не присвоите `call.output` самостоятельно.

<Accordion title="Семантика выхода" icon="arrow-right-from-bracket">

| Что произошло | События | `outcome` |
| --- | --- | --- |
| блок вернул значение | `agent_end` | `"success"`, или ваш `outcome` |
| блок выбросил исключение | `error`, затем `agent_end` | `"failed"` |
| `AbortError` | только `agent_end` | `"cancelled"` |

Исключение всегда переподбрасывается.

Ошибка инструмента записывается на листе — `tool_result` с строкой `error` — и **не** выдает событие `error` уровня запуска. Та, что перехвачена циклом агента, не является ошибкой запуска, а та, что распространяется, сообщается ровно один раз, через заключающий `agent()`.

</Accordion>

<Accordion title="Форма `using`" icon="brackets-curly">

Когда работа не одна функция — область, открытая в конструкторе и закрытая в слое разборки, или та, которая пересекает существующий поток управления:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, затем agent_end
```

Обе формы выдают идентичные в байтах события. Предпочитайте форму с callback: она работает внутри `AsyncLocalStorage.run()`, поэтому нет ничего, что нужно разворачивать, и весь класс ошибок типа "открыто здесь, закрыто там" недостижим.

Блок `using`, который перехватывает собственный отказ, сообщает о нем с `span.fail(error)` — disposer не имеет собственного канала исключений.

</Accordion>

## Каталог событий

Те же пятнадцать методов, что и в Python SDK, в camelCase. Большинство приходят в **парах** — вы вызываете открывающий, затем закрывающий, и SDK отсчитывает промежуток.

| | Открывает | Закрывает |
| --- | --- | --- |
| **Агенты** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Модели** | `modelRequest` | `modelResponse` |
| **Инструменты** | `toolUse` | `toolResult` |
| **Крючки** | `hookTriggered` | `hookCompleted` |
| **Люди** | `humanWait` | `humanInput` |

Три являются автономными: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Каждое поле, по методам" icon="table">

Каждый метод также принимает `sessionId` и `agentId`, которые области заполняют за вас. Все пропущенное отбрасывается вместо отправки как JSON `null`.

| Метод | Обязательные | Опциональные |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Любой другой ключ, который вы добавите, становится полем пользовательской нагрузки. Поместите в пространство имен все специфичное для фреймворка как `fw_*`; имя, которое конфликтует с объявленным полем, отклоняется, а не тихо перезаписывает продвинутый столбец.

</Accordion>

<Warning>
  **`duration_ms` вычисляется, не принимается.** Четыре закрывающих метода отсчитывают промежуток от своего открывающего и отклоняют предоставленный вызывающей стороной `duration_ms` — сообщаемую длительность невозможно подделать.

  Пары сопоставляются на **сессии** и id, никогда не на агенте. Инструмент, открытый под `planner` и закрытый под `worker`, все еще связывается в пару, что именно делают вложенные многоагентные запуски.
</Warning>

## Адаптеры фреймворков

```ts
await failproofai.instrument();              // что бы он ни смог найти
await failproofai.instrument("langchain");   // ровно один
failproofai.uninstrument();                  // вернуть все как было
```

| Фреймворк | Поддерживается | Как он присоединяется |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, поэтому каждый `invoke`/`stream`/`batch` охватывается без передачи `callbacks:` куда бы то ни было — или передайте `langchainHandler()` сами и ничего не патчьте. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` на сайте вызова, или `instrument("ai")` для всего процесса на `ai` 7 (на 4–6 это опт-ин — см. ниже). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, разрешение модели и инструментов агента, и движок запуска/шагов workflow. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (подписано) плюс `AgentWorkflow.runStream`, для запусков workflow и их шагов. |

Каждый диапазон тестируется против реальных выпусков фреймворков, на обоих концах, как ES модуль и как CommonJS, на каждом запуске CI.

Сопоставление — это Python SDK, поэтому одна и та же программа рисует одно и то же дерево на любом языке. Конструкция является **агентом** только если он владеет циклом принятия решений LLM — запуском графика или цепи, вызовом `generateText`/`streamText` AI SDK, агентом Mastra, запуском агента LlamaIndex. Узел LangGraph или шаг workflow — это **крючок** (`hook_triggered`/`hook_completed`), никогда не вложенный агент. Вызовы моделей — это пары `model_request`/`model_response` с подсчетом токенов; вызовы инструментов несут собственный id вызова инструмента модели. Ошибка записывается один раз, на событие, где она произошла.

Адаптер, который не установился, логируется и пропускается; остальные все еще устанавливаются, потому что сломанный LlamaIndex не должен стоить вам LangGraph.

<Note>
  `instrument()` без аргумента обнаруживает фреймворк по тому, **разрешается** ли он, а не по тому, импортирован ли он уже — Node не предоставляет эквивалент Python `sys.modules` для ES модулей. Фреймворк, который вы установили, но не используете, будет импортирован и пропатчен. Назовите тот, который хотите, если это имеет значение.
</Note>

<Note>
  Большинство этих фреймворков поставляют ES-модульную сборку и CommonJS сборку, которые Node загружает как две не связанные копии. Адаптеры патчат копию, которую загружает ваше приложение (и CommonJS копию тоже, если что-то уже `require`'d это), поэтому оба модульных систем работают. Фреймворк, **упакованный в ваш собственный вывод** esbuild или webpack, недостижим — используйте там помощники сайта вызова: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain без патчинга

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

Обработчик работает с `instrument()` или без него и никогда не записывает дважды. `instrument("langchain")` принимает `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` и `captureLimit`, как это делает Python адаптер; `metadata: { failproofai_sdk_session_id }` на вызове выбирает сессию для этого вызова.

### Vercel AI SDK

AI SDK экспортирует простые функции из ES модуля, и пространство имен ES модуля неизменяемо по спецификации — нет места для патчинга. Он использует точки расширения, которые сам SDK документирует:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // на ai 7, `telemetry: telemetry({ … })` — тот же объект, новое имя
});
```

Это полная интеграция: span агента, пара request/response модели за шаг с подсчетом токенов, и каждый вызов инструмента. Один сайт вызова работает на каждом мажоре — `ai` 4–6 читают трейсер, который он несет, `ai` 7 интеграцию телеметрии.

`instrument("ai")` делает то же самое в масштабе процесса **на `ai` 7**: каждый вызов, через глобальный список интеграции телеметрии AI SDK, который является аддитивным и не берет ничего у кого-либо еще.

**На `ai` 4–6, `instrument("ai")` по умолчанию не записывает ничего, и логирует одно предупреждение об этом.** Единственный крючок в масштабе процесса, который есть у этих мажоров, — это глобальный провайдер трейсера OpenTelemetry — один слот, который OpenTelemetry отказывается отдавать, если он уже занят. Регистрация наших отклонит вашу `NodeSDK.start()` позже при запуске и отправит ваши http/database spans в трейсер, который ничего не экспортирует. Используйте `telemetry()` на сайте вызова или `wrapModel` там. Если процесс не запускает собственный OpenTelemetry, установите с помощью `instrument("ai", { registerGlobalTracer: true })`: он затем записывает каждый вызов, который передает `experimental_telemetry: { isEnabled: true }`, и берет слот только если он все еще пуст. `registerGlobalTracer: false` сохраняет значение по умолчанию и подавляет предупреждение.

Если вы предпочли бы обернуть модель один раз, `wrapModel` видит только вызовы моделей, потому что вызовы инструментов происходят выше слоя модели. Обернутая модель, вызванная без ничего вокруг, записывается как ее собственный запуск. Потоковый вызов закрывается тем, как поток останавливается — `stop_reason: "cancelled"` когда потребитель его отменяет, `"error"` с ошибкой, когда он отказывает на полпути:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Использование обоих в порядке: middleware замечает, что вызов уже записывается, и откладывает, поэтому каждый вызов записывается один раз.

`functionId` называет span агента. Держите его низкомощным — это приземляется в `agent_id`, первичный фасет дашборда.

### Next.js

`next build` по умолчанию пакует зависимости вашего сервера, и фреймворк, упакованный в сборку, — это копия, которую `instrument()` не может достичь. Оберните конфиг один раз и вызовите `instrument()` из крючка запуска Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* ваш конфиг */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` добавляет LangChain, Mastra, LlamaIndex и сам SDK в `serverExternalPackages`, сохраняя ваш собственный список. Без него `instrument()` предупредит один раз за фреймворк, который не может достичь, вместо того чтобы молчаливо отказать; если вы перечислили пакеты сами, установите `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK и помощники сайта вызова работают в любом случае. Edge маршрут получает no-op сборку: импорт SDK безопасен и ничего не записывает.

### Подсчет токенов на потоковых вызовах

API, совместимые с OpenAI, сообщают использование на потоке только когда клиент просит. LangChain и Vercel AI SDK просят; для LlamaIndex передайте `additionalChatOptions: { stream_options: { include_usage: true } }` его OpenAI LLM, а для Mastra соберите модель с включенным использованием (например `createOpenAICompatible({ includeUsage: true })`). В противном случае потоковые вызовы моделей не содержат подсчет токенов.

### Времена выполнения

Node ≥ 20.9, Bun и Deno — каждый фреймворк, как ES модуль и как CommonJS, тестируется на каждом против трейса Node. SDK работает рядом с демоном `failproofaid`, который отправляет то, что он пишет.

## Ваш собственный агент — без фреймворка

Для цикла агента, который вы написали сами, или фреймворка без адаптера. Вы выдаете события с тем же API, который адаптеры используют внизу, поэтому трейс имеет ту же форму и качество.

Вам не нужно знать, как организован агент. Каждый сделанный вручную агент уже имеет три места, какими бы ни были названы его функции, и эти три — вся интеграция:

| Где | Что добавить | Выдает |
| --- | --- | --- |
| Где **один запуск** начинается и заканчивается | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Единственная функция, которая вызывает модель** | `event.modelRequest` перед, `event.modelResponse` после — обе половины, даже при отказе | одна пара за ход модели |
| **Единственная функция, которая запускает инструменты** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Идентичность является окружающей: все внутри `agent()` приземляется на запуск этой сессии без ввода id, и ничего больше в программе не изменяется — включая то, что агент уже пишет в свою собственную базу данных.

- **Сервис или рабочий:** передайте ваш собственный request или job id как `sessionId`, поэтому сессия на дашборде и запись в ваши собственные логи или базу данных — одна и та же строка.
- **Суб-агенты:** вложите вызовы `agent()`. Внутренний присоединяется к сессии с наружным как его `parent_id`.
- **Выдавайте пары.** `modelRequest` без `modelResponse` — это span, который дашборд показывает как работающий вечно — отсюда `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) в репозитории — это полная, исполняемая версия: реальный цикл инструмента OpenAI, инструментированный точно так же, запущенный в CI на каждом изменении как ES модуль и как CommonJS.

## Оценки

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Смотрите [справку Evaluator SDK](/ru/reference/evaluator-sdk) по протоколу, параметрам рабочего и типам результатов.

<Warning>
  **Оценка должна выполняться.** Синхронная функция, которая никогда не возвращается, блокирует единственный поток Node, и никакой timeout не может сработать, пока она это делает. Пишите `async` оценки.
</Warning>

## Что он не будет делать с вашим процессом

| | |
| --- | --- |
| **Блокировать ваш цикл агента** | События попадают в очередь в памяти; таймер пишет их. Таймер `unref`'ен, поэтому импорт этого пакета никогда не остановит выход скрипта. |
| **Расти без границ** | Очередь ограничена по количеству *и* по измеренным байтам. При превышении одного или другого, самые старые события отбрасываются и предупреждение об этом выводится — отказ телеметрии не должен стать убийством OOM. |
| **Привести процесс к отказу** | Одно неподдающееся кодированию событие отбрасывается отдельно, а не пакет вокруг него. Выбросивший getter, циклическая ссылка, `BigInt`, одиночный суррогат: каждый обрабатывается вместо распространения. |
| **Оставить наполовину написанный пакет** | Содержимое `fsync`'ено перед атомарным переименованием, каталог `fsync`'ен после, и неудачная запись очищает его временный файл. |
| **Оставить стенограммы читаемыми** | Пакеты — `0600` внутри каталога `0700`. Они содержат цели, подсказки, аргументы инструментов и выход инструментов. |
| **Отправить учетные данные** | Ключи API, токены, JWT, bearer заголовки и похожие на секреты присваивания удаляются перед тем как байты достигнут диска. Демон удаляет снова перед загрузкой. |
