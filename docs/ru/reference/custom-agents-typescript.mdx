Node 20.9 или новее. ESM и CommonJS. Без зависимостей во время выполнения.

<Note>
  Этот SDK и Python SDK записывают **одни и те же события в один и тот же буфер**. Парк с Node-агентами и Python-агентами создаёт один набор сеансов, а не два, и панель управления их не различает. Выбирайте по услуге, а не по компании.
</Note>

## Установка

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Адаптеры фреймворков поставляются в самом пакете. Фреймворки — это **необязательные peer-зависимости** — объявленные так, чтобы поддерживаемые диапазоны были видны, никогда не устанавливались от вашего имени и импортировались только при вызове `instrument()`.

## Подключение демона Failproof

Идентично Python SDK: создайте ключ `events:add` в разделе **Admin → Keys**, затем [подключите демона](/ru/start/setup#connect-a-machine-to-cloud) на машине агента. SDK записывает на диск; демон отправляет.

## Конфигурация

### Span-ы OpenTelemetry (опционально)

Установите OpenTelemetry отдельно с помощью `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
Затем добавьте FailproofAI к процессорам вашего поставщика:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Для существующего поставщика, держите его другие процессоры в одном списке. Поставщики, которые предоставляют `addSpanProcessor`, можно вместо этого передать как `{ provider }`. Без параметров установка регистрирует нового поставщика только если поставщик ещё не зарегистрирован. `OtelSpanExporter` также можно использовать напрямую со своим процессором.

Экспорт проходит через подключённого демона FailproofAI; SDK не отправляет сетевые запросы и не требует ключа или локального слушателя. Попросите администратора включить [приём OpenTelemetry](/ru/agenteye/opentelemetry). Простой `instrument()` не включает этот экспортер. `uninstrument("otel")` отключает только собственный процессор. Ваши span-атрибуты контролируют захват содержимого; выполните сброс вашего поставщика перед выходом. OpenTelemetry остаётся необязательной зависимостью приложения, а не жёсткой зависимостью SDK.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Параметр | Что он делает |
| --- | --- |
| `environment` | Метка на каждом событии — `production`, `staging`, `prod-eu`. По умолчанию `dev`. |
| `flushInterval` | Как часто таймер записывает на диск, в секундах. По умолчанию `0.5`. |
| `baseDir` | Куда писать. По умолчанию буфер демона, что вам нужно, если вы не знаете иначе. |

Ничего не применяется, пока всё это не пройдёт проверку, поэтому отклонённый вызов оставляет SDK в точности таким же, как был, вместо того чтобы получить новый `baseDir` и старый интервал.

Установите переменную окружения вместо этого:

| Переменная | Что она делает |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Устанавливает `environment` без изменения кода. Параметр `configure()` имеет приоритет. |
| `FAILPROOFAI_HOME` | Перемещает корень Failproof AI, который содержит буфер. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (по умолчанию), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` делает ошибки инструментации исключительными вместо логирования. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` делает проблему совместимости фреймворка исключительной вместо предупреждения и продолжения. |

<Warning>
  **Без запятых в `environment`.** Приём разбивает это поле по запятым для построения фильтров и пропускает любое событие, метка которого содержит одну — так что весь запуск исчезает молча. Пишите `prod-eu`, а не `prod,eu`.

  `configure({ environment: "prod,eu" })` выбрасывает исключение, чтобы вы узнали немедленно. `AGENTEYE_ENVIRONMENT` не может выбросить исключение — никто вас не вызывает — так что это предупреждает один раз и возвращается к `dev`.
</Warning>

Маршрутизируйте собственные строки логирования SDK в ваш логгер с помощью `failproofai.setLogger({ debug, info, warn, error })`.

## Завершение

Буферизованные события сбрасываются при `process.on("exit")`.

Процесс, убитый сигналом, никогда туда не дойдёт, и значение Node по умолчанию для `SIGTERM` — завершить без запуска обработчиков выхода — так что контейнеризованный агент теряет то, что последний интервал не записал.

<Warning>
  **Этот SDK не установит обработчик сигнала за вас.** Регистрация его меняет поведение вашего процесса: слушатель подавляет стандартное завершение Node, поэтому библиотека, которая добавила его, молча остановила бы Ctrl-C от работы. Добавьте свой:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Недолгоживущий скрипт или обработчик serverless должны `await failproofai.flush()` перед возвратом — только интервал не гарантирует доставку.

## Идентичность

Каждое событие принадлежит сеансу и агенту. **Области видимости заполняют оба**, поэтому вы редко их передаёте:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

Передача `sessionId` или `agentId` явно всё ещё работает и имеет приоритет. Без ни привязки ни передачи, вызов выбрасывает исключение вместо отправки события, которое Cloud молча отбросит.

<Note>
  Идентичность работает на `AsyncLocalStorage`. Она следует `await`, `.then()`, таймерам и любому обратному вызову, созданному внутри области. Она **не** следует обратному вызову, сохранённому во время одного запуска и вызванному во время другого, или работе, передаваемой через границу `worker_threads` — заверните их в `failproofai.propagate()` или их события окажутся неприсоединённые.
</Note>

### Области видимости

| Область | Отправляет | Возвращает |
| --- | --- | --- |
| `session(body)` | ничего — только идентичность | всё, что возвращает `body` |
| `agent(id, options?, body)` | `agent_start`, затем `agent_end` | всё, что возвращает `body` |
| `toolCall(name, options?, body)` | `tool_use`, затем `tool_result` | всё, что возвращает `body` |

Синхронное тело остаётся синхронным: `agent("x", () => 1)` возвращает `1`, а не обещание.

`toolCall` записывает разрешённое значение тела как `output` инструмента, если вы не присвоите `call.output` самостоятельно.

<Accordion title="Семантика выхода" icon="arrow-right-from-bracket">

| Что произошло | События | `outcome` |
| --- | --- | --- |
| блок вернул значение | `agent_end` | `"success"`, или ваш `outcome` |
| блок выбросил исключение | `error`, затем `agent_end` | `"failed"` |
| `AbortError` | только `agent_end` | `"cancelled"` |

Исключение всегда переброшено.

Отказ инструмента записывается на листе — `tool_result` с `error`-строкой — и отправляет **никакого** события на уровне запуска `error`. Один, который агент перехватывает, — не отказ запуска, и один, который распространяется, сообщается ровно один раз, инкапсулирующим `agent()`.

</Accordion>

<Accordion title="Форма `using`" icon="brackets-curly">

Когда работа — это не одна функция — область, открытая в конструкторе и закрытая в слезании, или та, которая пересекает существующий поток управления:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, затем agent_end
```

Обе формы отправляют события с идентичными байтами. Предпочитайте форму обратного вызова: она работает внутри `AsyncLocalStorage.run()`, поэтому нечего разворачивать, и весь класс ошибок «открыто здесь, закрыто там» недостижим.

Блок `using`, который перехватывает собственный отказ, сообщает о нём с помощью `span.fail(error)` — у одноразовика нет собственного канала исключения.

</Accordion>

## Каталог событий

Те же пятнадцать методов, что и Python SDK, в camelCase. Большинство поставляются в **парах** — вы вызываете открывающую, затем закрывающую, и SDK отсчитывает зазор.

| | Открывает | Закрывает |
| --- | --- | --- |
| **Агенты** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Модели** | `modelRequest` | `modelResponse` |
| **Инструменты** | `toolUse` | `toolResult` |
| **Крючки** | `hookTriggered` | `hookCompleted` |
| **Люди** | `humanWait` | `humanInput` |

Три стоят отдельно: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Каждое поле, по методу" icon="table">

Каждый метод также принимает `sessionId` и `agentId`, которые области заполняют за вас. Всё пропущенное опускается вместо отправки JSON `null`.

| Метод | Требуется | Опционально |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Любой другой ключ, который вы добавляете, становится полем пользовательской нагрузки. Определите пространство имён как `fw_*` для всего, специфичного фреймворку; имя, которое конфликтует с объявленным полем, отклоняется вместо молчаливого перезаписи продвигаемого столбца.

</Accordion>

<Warning>
  **`duration_ms` вычисляется, не принимается.** Четыре закрывающих метода отсчитывают зазор от своего открывающего и отклоняют поставляемый вызывающим `duration_ms` — сообщённая продолжительность неопровержима.

  Пары сопоставляются на **сеансе** и идентификаторе, никогда на агенте. Инструмент, открытый под `planner` и закрытый под `worker`, всё ещё сопоставляется, что делают вложенные многоагентные запуски.
</Warning>

## Адаптеры фреймворков

```ts
await failproofai.instrument();              // что бы ни было найдено
await failproofai.instrument("langchain");   // ровно один
failproofai.uninstrument();                  // всё вернуть назад
```

| Фреймворк | Поддерживается | Как он подключается |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, поэтому каждый `invoke`/`stream`/`batch` охватывается без передачи `callbacks:` куда-либо — или передайте `langchainHandler()` сами и ничего не патчьте. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` на месте вызова, или `instrument("ai")` для всего процесса на `ai` 7 (на 4–6 это опционально — см. ниже). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, разрешение модели и инструмента агента, и движок работы/шага рабочего процесса. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (подписан) плюс `AgentWorkflow.runStream`, для запусков рабочего процесса и их шагов. |

Каждый диапазон тестируется против реальных выпусков фреймворка, на обоих концах, как модуль ES и как CommonJS, на каждом запуске CI.

Сопоставление — это Python SDK, поэтому одна и та же программа рисует одно и то же дерево в любом языке. Конструкция — это **агент** только если она владеет петлей решений LLM — запуск графика или цепи, вызов Vercel AI SDK `generateText`/`streamText`, агент Mastra, запуск агента LlamaIndex. Узел LangGraph или шаг рабочего процесса — это **крючок** (`hook_triggered`/`hook_completed`), никогда не вложенный агент. Вызовы моделей — это пары `model_request`/`model_response` с количеством токенов; вызовы инструментов несут собственный идентификатор вызова инструмента модели. Отказ записывается один раз, на событие, в котором он произошёл.

Адаптер, который не устанавливается, логируется и пропускается; остальные всё ещё устанавливаются, потому что сломанный LlamaIndex не должен стоить вам LangGraph.

<Note>
  `instrument()` без аргумента обнаруживает фреймворк по тому, **разрешается** ли он, а не по тому, импортирован ли он уже — Node не предоставляет эквивалент Python `sys.modules` для модулей ES. Фреймворк, который вы установили, но не используете, будет импортирован и пропатчен. Назовите тот, который вам нужен, если это имеет значение.
</Note>

<Note>
  Большинство этих фреймворков поставляют сборку модулей ES и сборку CommonJS, которые Node загружает как две несвязанные копии. Адаптеры патчат копию, которую загружает ваше приложение (и сборку CommonJS тоже, если что-то уже её требовало), поэтому обе системы модулей работают. Фреймворк, **собранный в вашу собственную выходную сборку** esbuild или webpack, недостижим — используйте помощники на месте вызова: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain без патчинга

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

Обработчик работает с `instrument()` или без, и никогда не записывает дважды. `instrument("langchain")` принимает `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` и `captureLimit`, как и Python-адаптер; `metadata: { failproofai_sdk_session_id }` на вызове выбирает сеанс для этого вызова.

### Vercel AI SDK

AI SDK экспортирует простые функции из модуля ES, и пространство имён модуля ES неизменяемо по спецификации — патчить нечего. Это использует расширения, которые сам SDK документирует:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // на ai 7, `telemetry: telemetry({ … })` — один и тот же объект, новое имя
});
```

Это полная интеграция: span агента, пара запрос/ответ модели за шаг с количеством токенов, и каждый вызов инструмента. Один сайт вызова работает на каждом крупном — `ai` 4–6 читают трассировщик, который он несёт, `ai` 7 интеграцию телеметрии.

`instrument("ai")` делает то же самое по всему процессу **на `ai` 7**: каждый вызов, через список интеграции глобальной телеметрии AI SDK, который является дополнительным и ничего не берёт у кого-то другого.

**На `ai` 4–6, `instrument("ai")` ничего по своему изъ себе не записывает и логирует одно предупреждение об этом.** Единственный крючок по всему процессу, который есть у этих мажоров — это глобальный поставщик трассировщика OpenTelemetry — одна позиция, которую OpenTelemetry отказывается передать после захвата. Регистрация наша молча отклонила бы ваш позже в запуске `NodeSDK.start()` и отправила бы ваши пролёты http/базы данных трассировщику, который ничего не экспортирует. Используйте `telemetry()` на месте вызова или `wrapModel` там. Если процесс не запускает OpenTelemetry самостоятельно, согласитесь с `instrument("ai", { registerGlobalTracer: true })`: он затем записывает каждый вызов, который проходит `experimental_telemetry: { isEnabled: true }`, и берёт позицию только если она ещё пуста. `registerGlobalTracer: false` держит значение по умолчанию и подавляет предупреждение.

Если вы предпочитаете обернуть модель один раз, `wrapModel` видит только вызовы моделей, потому что вызовы инструментов происходят над слоем модели. Обёрнутая модель, вызванная с ничем вокруг, записывается как её собственный запуск. Потоковый вызов закрывается тем, как поток останавливается — `stop_reason: "cancelled"`, когда потребитель отменяет это, `"error"` с ошибкой, когда это не удаётся в пути:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Использование обоих — это нормально: промежуточное ПО замечает, что вызов уже записывается, и откладывает, поэтому каждый вызов записывается один раз.

`functionId` называет span агента. Держите его с низкой мощностью — он попадает в `agent_id`, основной фасет панели управления.

### Next.js

`next build` по умолчанию собирает зависимости вашего сервера, и фреймворк, собранный в сборку, — это копия, которую `instrument()` не может достичь. Оберните конфигурацию один раз и вызовите `instrument()` из крючка запуска Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` добавляет LangChain, Mastra, LlamaIndex и сам SDK в `serverExternalPackages`, сохраняя ваш собственный список. Без этого, `instrument()` предупреждает один раз за фреймворк, который не может достичь, вместо молчаливого отказа; если вы список пакетов самостоятельно, установите `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK и помощники на месте вызова работают в любом случае. Маршрут Edge получает сборку no-op: импорт SDK безопасен и ничего не записывает.

### Количество токенов при потоковых вызовах

API-интерфейсы совместимые с OpenAI сообщают об использовании на потоке только когда клиент просит. LangChain и Vercel AI SDK просят; для LlamaIndex передайте `additionalChatOptions: { stream_options: { include_usage: true } }` его `OpenAI` LLM, а для Mastra постройте модель с включённым использованием (например `createOpenAICompatible({ includeUsage: true })`). В противном случае потоковые вызовы моделей не несут количество токенов.

### Среды выполнения

Node ≥ 20.9, Bun и Deno — каждый фреймворк, как модуль ES и как CommonJS, тестируется на каждом из них против трассировки Node. SDK работает рядом с демоном `failproofaid`, который отправляет то, что он записывает.

## Ваш собственный агент — без фреймворка

Для вашего собственного цикла агента или фреймворка без адаптера. Вы отправляете события с тем же API, который адаптеры используют внизу, поэтому трассировка имеет ту же форму и качество.

Вам не нужно знать, как организован агент. Каждый самодельный агент уже имеет три места, независимо от того, как называются его функции, и эти три — вся интеграция:

| Где | Что добавить | Отправляет |
| --- | --- | --- |
| Где **один запуск** начинается и заканчивается | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Одна функция, которая вызывает модель** | `event.modelRequest` перед, `event.modelResponse` после — обе половины, даже при отказе | одна пара за ход модели |
| **Одна функция, которая запускает инструменты** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Идентичность окружающая: всё внутри `agent()` попадает в сеанс этого запуска без взятия идентификатора, и ничего больше в программе не изменяется — включая всё, что агент уже пишет в собственную базу данных.

- **Служба или рабочий:** передайте свой собственный идентификатор запроса или работы как `sessionId`, поэтому сеанс на панели управления и запись в ваши собственные логи или базу данных — это одна и та же строка.
- **Подагенты:** вложите вызовы `agent()`. Внутренний присоединяется к сеансу с внешним как его `parent_id`.
- **Отправьте пары.** `modelRequest` без `modelResponse` — это span, который панель управления показывает как вечно работающий — отсюда `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) в репозитории — это полная, работающая версия: реальный цикл инструмента OpenAI, инструментированный точно так же, запущен в CI при каждом изменении как модуль ES и как CommonJS.

## Оценки

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

См. [справку SDK оценщика](/ru/reference/evaluator-sdk) по протоколу, параметрам рабочего и типам результатов.

<Warning>
  **Оценка должна дать результат.** Синхронная функция, которая никогда не возвращается, блокирует единственный поток, который имеет Node, и никакой timeout не может срабатывать во время этого. Пишите `async` оценки.
</Warning>

## Что это не будет делать с вашим процессом

| | |
| --- | --- |
| **Блокировать цикл вашего агента** | События входят в очередь в памяти; таймер их записывает. Таймер `unref`'d, поэтому импорт этого пакета никогда не останавливает выход скрипта. |
| **Расти без ограничений** | Очередь ограничена по количеству *и* по измеренным байтам. Прошлые оба, самые старые события отбрасываются, и предупреждение говорит об этом — отказ телеметрии не должен стать убийством OOM. |
| **Сломать процесс** | Одно неподдающееся кодированию событие опускается самостоятельно, не партия вокруг него. Выбрасывающий гетер, циклическая ссылка, `BigInt`, одиночный суррогат: каждый обрабатывается вместо распространения. |
| **Оставить полузаписанную партию** | Содержимое `fsync`едится перед атомным переименованием, каталог `fsync`едится после, и ошибка записи очищает его временный файл. |
| **Оставить расшифровки читаемыми** | Партии — это `0600` внутри `0700` каталога. Они несут цели, подсказки, аргументы инструментов и выход инструмента. |
| **Отправить учётные данные** | API ключи, токены, JWT, заголовки bearer и секретообразные присвоения редактируются перед тем, как байты достигнут диска. Демон редактирует снова перед загрузкой. |
