## Установка

```bash
pip install failproofai-sdk
```

Пакет устанавливается как `failproofai-sdk` и импортируется в Python как `failproofai_sdk`. Расширения для фреймворков, такие как `failproofai-sdk[langgraph]`, устанавливают сам фреймворк; адаптеры всегда идут в базовом пакете.

## Конфигурация

```python
import failproofai_sdk

failproofai_sdk.configure(
    base_dir=None,
    flush_interval=0.5,
    environment="production",
)
```

| Аргумент | Что это делает |
| --- | --- |
| `environment` | Метка на каждом событии — `production`, `staging`, `prod-eu`. По умолчанию `dev`. |
| `flush_interval` | Как часто фоновый поток записывает на диск, в секундах. По умолчанию `0.5`. |
| `base_dir` | Где записывать. По умолчанию используется очередь демона, что верно, если вы не знаете иное. |

Установите через переменную окружения:

| Переменная | Что это делает |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Устанавливает `environment` без изменения кода, когда метка принадлежит развёртыванию, а не приложению. Аргумент `configure()` имеет приоритет. |
| `FAILPROOFAI_HOME` | Перемещает корень Failproof AI, содержащий очередь. |
| `FAILPROOFAI_SDK_STRICT` | `1` заставляет ошибки инструментирования вызывать исключение вместо логирования. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` заставляет проблему совместимости фреймворка вызывать исключение вместо предупреждения и продолжения работы. |

<Warning>
  **Без запятых в `environment`.** Ingest разделяет это поле по запятым для построения фильтров и пропускает любое событие, чья метка содержит запятую — вся сессия молча исчезает. Напишите `prod-eu`, а не `prod,eu`.

  `configure(environment="prod,eu")` вызывает исключение, чтобы вы сразу об этом узнали. `AGENTEYE_ENVIRONMENT` не может вызвать исключение — никто вас не вызывает — поэтому выдаёт предупреждение один раз и возвращается к `dev`.
</Warning>

События ставятся в очередь в памяти и записываются в фоне каждые `flush_interval` секунд, с финальной записью при выходе из интерпретатора. Процесс, убитый насильно, теряет всё, что ещё не было записано.

## Идентификация

Каждое событие принадлежит сессии и агенту. **Области видимости заполняют обе**, поэтому вы редко их передаёте:

```python
with failproofai_sdk.session():
    with failproofai_sdk.agent("planner"):
        failproofai_sdk.event.tool_use(tool_name="search", tool_call_id="c1")
```

Явное прохождение `session_id` или `agent_id` по-прежнему работает и имеет приоритет. Без привязанных или переданных значений вызов вызывает `TypeError` вместо отправки события, которое облако молча отбросит.

<Note>
  Идентификация работает на контекстных переменных. Она автоматически следует за задачами `asyncio`, но **не** за новыми потоками — оборните рабочий процесс в `failproofai_sdk.propagate()` или его события будут не присоединены.
</Note>

## Каталог событий

Пятнадцать методов. Большинство идут **парами** — вы вызываете открывающий метод, затем закрывающий, и SDK отмеряет разницу.

| | Открывает | Закрывает |
| --- | --- | --- |
| **Агенты** | `agent_start` | `agent_end` |
| | `agent_pause` | `agent_resume` |
| **Модели** | `model_request` | `model_response` |
| **Инструменты** | `tool_use` | `tool_result` |
| **Хуки** | `hook_triggered` | `hook_completed` |
| **Люди** | `human_wait` | `human_input` |

Три работают отдельно: `error`, `human_pause`, `human_interrupt`.

<Accordion title="Все поля по методам" icon="table">

Каждый метод также принимает `session_id` и `agent_id`, которые области видимости заполняют за вас. Всё оставленное как `None` выпадает при отправке вместо отправки JSON `null`, и каждый метод возвращает `None`.

| Метод | Обязательный | Опциональный |
| --- | --- | --- |
| `agent_start` | — | `goal`, `parent_id` |
| `agent_end` | — | `outcome`, `summary` |
| `agent_pause` | `pause_id` | `reason`, `user_id` |
| `agent_resume` | `pause_id` | `reason`, `user_id` |
| `model_request` | — | `model`, `messages`, `system`, `tools`, `request_id` |
| `model_response` | — | `model`, `stop_reason`, `input_tokens`, `output_tokens`, `content`, `role`, `request_id`, `duration_ms` |
| `tool_use` | `tool_name`, `tool_call_id` | `input` |
| `tool_result` | `tool_name`, `tool_call_id` | `output`, `error` |
| `hook_triggered` | `hook_name`, `hook_id` | `trigger_event`, `input` |
| `hook_completed` | `hook_name`, `hook_id` | `outcome`, `output`, `error` |
| `error` | `error_type`, `message` | `traceback` |
| `human_wait` | `input_id` | `prompt`, `options`, `reason` |
| `human_input` | `input_id` | `response` |
| `human_pause` | — | `reason`, `user_id` |
| `human_interrupt` | — | `reason`, `user_id`, `at_step` |

</Accordion>

<Warning>
  Чтобы отметить сессию как неудачную, `outcome` должен быть одним из `failed`, `error`, `timeout` или `rejected`. Всё остальное — включая почти совпадающее `"failure"` — считается успехом.
</Warning>

## Парирование и длительность

**Одно правило: передайте закрывающему событию такой же id, как его открывающему.** Это то, что их связывает, и что позволяет SDK отмерить разницу.

| Пара | Совпадение по |
| --- | --- |
| `tool_use` → `tool_result` | `tool_call_id` |
| `hook_triggered` → `hook_completed` | `hook_id` |
| `agent_pause` → `agent_resume` | `pause_id` |
| `human_wait` → `human_input` | `input_id` |
| `model_request` → `model_response` | `request_id` |

**Не передавайте `duration_ms` самостоятельно.** SDK измеряет его, и передача вызывает `ValueError`.

Единственное исключение — `model_response`, где только вы знаете реальную задержку провайдера. Передайте целое число миллисекунд — float вызовет ошибку, потому что столбец является 32-битным целым числом и иначе останется пустым.

<Accordion title="Граничные случаи" icon="circle-help">

- **Ids должны быть уникальными только для вида, для сессии.** Вызов инструмента и хук могут их делить; две сессии, работающие одновременно, могут повторно использовать одни и те же ids без столкновений.
- **Они не привязаны к агенту.** Пара, открытая под одним агентом и закрытая под другим, всё ещё совпадает — это нормальный случай в многоагентном коде.
- **`request_id` опциональный, но рекомендуется.** Без него события модели соединяются в порядке поступления, поэтому два одновременных вызова в одном агенте могут неправильно соединиться.
- **Пара, разделённая между процессами**, всё ещё совпадает в облаке, но SDK не может её отмерить — ничто в любом процессе не видело обе половины.
- **Не более 10 000 открывающих ждёт закрывающего одновременно.** После этого самое старое выбрасывается, поэтому утечка не может расти без границ.

</Accordion>

## Ваши собственные поля

Любое дополнительное ключевое слово, которое вы передаёте, сохраняется с событием:

```python
failproofai_sdk.event.tool_use(
    tool_name="search", tool_call_id="c1",
    fw_tenant="acme", fw_region="eu-west-1",     # ваши собственные
)
```

Предпочитайте JSON типы, если позже захотите их запросить. Всё остальное — UUID, datetime, `Decimal`, set, bytes, объект модели — сохраняется как строка.

<Warning>
  **Добавляйте префикс к названиям полей.** Дополнительные поля применяются последними, поэтому поле, названное `model`, `tool_name` или `outcome`, молча перезаписывает реальное. Адаптеры фреймворков используют `fw_`; делайте то же самое и ничто не может столкнуться.

  Это также объясняет, почему опечатка в опциональном поле никогда не ошибается — она просто становится новым пользовательским полем. Если стандартное поле отсутствует в облаке, сначала проверьте правописание.
</Warning>

Эти пять названий зарезервированы и отклоняются сразу: `timestamp`, `session_id`, `agent_id`, `type`, `environment`.

## Доставка и проверка

<Tabs>
  <Tab title="Панель управления">
    В **Observe → Events** сначала проверьте наличие `agent_start`, затем наличие `agent_end`. Затем откройте **Observe → Sessions** и подтвердите, что события модели, инструмента, человека, хука и ошибки появляются в намеченном порядке. Используйте ID сессии как основной ключ для поиска и устранения неисправностей.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai flush --wait --timeout 60
    failproofai config --status
    fp sessions --since 1h --env production --session-id <session-id>
    fp events --since 1h --session-id <session-id> --full
    ```
  </Tab>
</Tabs>

Если облако пусто, проверьте `$FAILPROOFAI_HOME/custom-agents/events`, иначе `~/.failproofai/custom-agents/events`. JSONL файлы доказывают отправку SDK; растущая очередь указывает на конфигурацию или доставку демона, в то время как пустая очередь указывает на инструментирование или время жизни процесса.

<Note>
  Проверяйте очередь только когда демон остановлен. Пока он работает, он собирает и удаляет каждый пакет за миллисекунды, поэтому список директории гонится с коллектором и показывает намного меньше событий, чем было отправлено.
</Note>

## Предотвращение сбоев в пользовательском рантайме

Используйте выводы аудита и связанные трейсы для определения небезопасного действия, требуемого доказательства и предполагаемого ответа. Интеграция пользовательского принудительного исполнения должна обнажить действие перед выполнением, передать его структурированный ввод механизму политики и применить результирующее решение allow, instruct или deny.

[Свяжитесь с Failproof AI](mailto:support@befailproof.ai) и мы поможем отобразить границы модели, инструмента и жизненного цикла вашего рантайма на хуки политики, затем проверим интеграцию с вами.
