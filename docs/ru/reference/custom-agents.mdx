## Установка

```bash
pip install failproofai-sdk
```

Пакет установлен как `failproofai-sdk` и импортируется в Python как `failproofai_sdk`. Дополнительные модули для фреймворков, такие как `failproofai-sdk[langgraph]`, устанавливают сам фреймворк; адаптеры всегда поставляются в базовом пакете.

## Конфигурация

### OpenTelemetry spans (опционально)

Установите `opentelemetry-sdk` отдельно, затем подключите опциональный экспортер:

```python
import failproofai_sdk
from opentelemetry.sdk.trace import TracerProvider

provider = TracerProvider()
failproofai_sdk.instrument("otel", provider=provider)
with provider.get_tracer("my-agent").start_as_current_span(
    "agent", attributes={"gen_ai.operation.name": "invoke_agent"}
):
    pass
provider.force_flush()
```

Настройка использует ваш зарегистрированный провайдер, если вы опустите `provider`, создавая его только
если ни один не зарегистрирован. Вы можете также передать `failproofai_sdk.OtelSpanExporter()`
напрямую вашему собственному обработчику спанов. Другие экспортеры остаются без изменений.

Подключённый демон FailproofAI доставляет экспорты; SDK не требует настройки сети,
ключа или локального слушателя. Администратор должен включить
[OpenTelemetry ingest](/ru/agenteye/opentelemetry). Голый `instrument()` никогда
не включает OTEL. `uninstrument("otel")` отключает только свой собственный процессор.
Ваша инструментация управляет захватом контента. Очистите провайдер перед выходом.
SDK по-прежнему заявляет ноль жёстких зависимостей среды выполнения и импортирует OpenTelemetry
только при необходимости.

```python
import failproofai_sdk

failproofai_sdk.configure(
    base_dir=None,
    flush_interval=0.5,
    environment="production",
)
```

| Аргумент | Что он делает |
| --- | --- |
| `environment` | Метка для каждого события — `production`, `staging`, `prod-eu`. По умолчанию `dev`. |
| `flush_interval` | Как часто фоновый поток записывает на диск, в секундах. По умолчанию `0.5`. |
| `base_dir` | Где писать. По умолчанию буфер демона, что вам нужно, если вы не знаете иное. |

Установите через переменную окружения:

| Переменная | Что она делает |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Устанавливает `environment` без изменения кода, когда метка принадлежит развёртыванию, а не приложению. Аргумент `configure()` выигрывает у неё. |
| `FAILPROOFAI_HOME` | Перемещает корень Failproof AI, который содержит буфер. |
| `FAILPROOFAI_SDK_STRICT` | `1` заставляет ошибки инструментации вызывать исключение вместо логирования. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` заставляет проблему совместимости фреймворка вызывать исключение вместо предупреждения и продолжения. |

<Warning>
  **Без запятых в `environment`.** Ingest разбивает это поле на запятые для построения фильтров и пропускает любое событие, метка которого содержит запятую — так целый проход молча исчезает. Пишите `prod-eu`, а не `prod,eu`.

  `configure(environment="prod,eu")` вызывает исключение, чтобы вы сразу узнали. `AGENTEYE_ENVIRONMENT` не может вызвать — никто вас не вызывает — поэтому он предупреждает один раз и возвращается к `dev`.
</Warning>

События ставятся в очередь в памяти и записываются в фоне каждые `flush_interval` секунд, с финальной очисткой при выходе интерпретатора. Процесс, убитый насильно, потеряет всё, что еще не было записано.

## Идентичность

Каждое событие принадлежит сессии и агенту. **Области заполняют обе**, поэтому вы редко их передаёте:

```python
with failproofai_sdk.session():
    with failproofai_sdk.agent("planner"):
        failproofai_sdk.event.tool_use(tool_name="search", tool_call_id="c1")
```

Передача `session_id` или `agent_id` явно всё ещё работает и выигрывает. Без ни привязки ни передачи вызов вызывает `TypeError` вместо испускания события, которое Cloud тихо отбросит.

<Note>
  Идентичность использует контекстные переменные. Она следует за `asyncio` задачами автоматически, но **не** новыми потоками — оберните рабочий в `failproofai_sdk.propagate()` или его события окажутся неприкреплёнными.
</Note>

## Каталог событий

Пятнадцать методов. Большинство поставляются **парами** — вы вызываете открывающий метод, затем закрывающий, и SDK измеряет разрыв.

| | Открывает | Закрывает |
| --- | --- | --- |
| **Agents** | `agent_start` | `agent_end` |
| | `agent_pause` | `agent_resume` |
| **Models** | `model_request` | `model_response` |
| **Tools** | `tool_use` | `tool_result` |
| **Hooks** | `hook_triggered` | `hook_completed` |
| **Humans** | `human_wait` | `human_input` |

Три работают самостоятельно: `error`, `human_pause`, `human_interrupt`.

<Accordion title="Каждое поле, по методу" icon="table">

Каждый метод также принимает `session_id` и `agent_id`, которые области заполняют за вас. Всё, что остаётся как `None`, отбрасывается, а не отправляется как JSON `null`, и каждый метод возвращает `None`.

| Метод | Обязательно | Опционально |
| --- | --- | --- |
| `agent_start` | — | `goal`, `parent_id` |
| `agent_end` | — | `outcome`, `summary` |
| `agent_pause` | `pause_id` | `reason`, `user_id` |
| `agent_resume` | `pause_id` | `reason`, `user_id` |
| `model_request` | — | `model`, `messages`, `system`, `tools`, `request_id` |
| `model_response` | — | `model`, `stop_reason`, `input_tokens`, `output_tokens`, `content`, `role`, `request_id`, `duration_ms` |
| `tool_use` | `tool_name`, `tool_call_id` | `input` |
| `tool_result` | `tool_name`, `tool_call_id` | `output`, `error` |
| `hook_triggered` | `hook_name`, `hook_id` | `trigger_event`, `input` |
| `hook_completed` | `hook_name`, `hook_id` | `outcome`, `output`, `error` |
| `error` | `error_type`, `message` | `traceback` |
| `human_wait` | `input_id` | `prompt`, `options`, `reason` |
| `human_input` | `input_id` | `response` |
| `human_pause` | — | `reason`, `user_id` |
| `human_interrupt` | — | `reason`, `user_id`, `at_step` |

</Accordion>

<Warning>
  Чтобы отметить запуск как неудачный, `outcome` должен быть одним из `failed`, `error`, `timeout` или `rejected`. Что-либо ещё — включая близкий промах `"failure"` — считается успехом.
</Warning>

## Разделение на пары и длительность

**Одно правило: передайте закрывающему событию тот же id, что и его открывающему.** Это то, что их объединяет и позволяет SDK измерить разрыв.

| Пара | Сопоставление |
| --- | --- |
| `tool_use` → `tool_result` | `tool_call_id` |
| `hook_triggered` → `hook_completed` | `hook_id` |
| `agent_pause` → `agent_resume` | `pause_id` |
| `human_wait` → `human_input` | `input_id` |
| `model_request` → `model_response` | `request_id` |

**Не передавайте `duration_ms` сами.** SDK измеряет это, и передача вызывает `ValueError`.

Единственное исключение — `model_response`, где только вы знаете реальную задержку провайдера. Передайте целое число миллисекунд — дробное число вызывает исключение, потому что колонка представляет собой 32-битное целое число и иначе окажется пустой.

<Accordion title="Граничные случаи" icon="circle-help">

- **Ids должны быть уникальными только для своего рода, в каждой сессии.** Вызов инструмента и хук могут поделиться одним; две одновременно работающие сессии могут переиспользовать одни и те же ids без столкновения.
- **Они не привязаны к агенту.** Пара, открытая под одним агентом и закрытая под другим, всё ещё соответствует — что является нормальным случаем в многоагентном коде.
- **`request_id` опционален, но рекомендуется.** Без него события модели объединяются в порядке их поступления, поэтому два одновременных вызова в одном агенте могут неправильно соединиться.
- **Пара, разбитая на несколько процессов**, всё ещё соответствует в Cloud, но SDK не может её измерить — ничто в обоих процессах не видело обе половины.
- **Максимум 10 000 открывающих ждут закрывающего одновременно.** После этого самый старый отбрасывается, поэтому утечка не может расти бесконечно.

</Accordion>

## Ваши собственные поля

Любой дополнительный ключевой аргумент, который вы передаёте, сохраняется вместе с событием:

```python
failproofai_sdk.event.tool_use(
    tool_name="search", tool_call_id="c1",
    fw_tenant="acme", fw_region="eu-west-1",     # ваши собственные
)
```

Предпочитайте типы JSON, если захотите запросить их позже. Что-либо ещё — UUID, datetime, `Decimal`, set, bytes, объект модели — сохраняется как строка.

<Warning>
  **Префиксируйте ваши имена полей.** Дополнительные поля применяются последними, поэтому поле с названием `model`, `tool_name` или `outcome` молча перезапишет реальное. Адаптеры фреймворков используют `fw_`; делайте то же самое и ничего не может столкнуться.

  Это также причина, по которой ошибочно написанное опциональное поле никогда не вызывает ошибку — оно просто становится новым пользовательским полем. Если стандартное поле отсутствует в Cloud, сначала проверьте написание.
</Warning>

Эти пять имён зарезервированы и отклонены в явном виде: `timestamp`, `session_id`, `agent_id`, `type`, `environment`.

## Доставка и проверка

<Tabs>
  <Tab title="Dashboard">
    В **Observe → Events** сначала проверьте, что `agent_start` существует, а затем что `agent_end` существует в конце. Затем откройте **Observe → Sessions** и подтвердите, что события модели, инструмента, человека, хука и ошибки появляются в предполагаемом порядке. Используйте ID сессии как основной ключ для поиска и устранения неисправностей.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai flush --wait --timeout 60
    failproofai config --status
    fp sessions --since 1h --env production --session-id <session-id>
    fp events --since 1h --session-id <session-id> --full
    ```
  </Tab>
</Tabs>

Если Cloud пуст, проверьте `$FAILPROOFAI_HOME/custom-agents/events`, иначе `~/.failproofai/custom-agents/events`. JSONL файлы доказывают излучение SDK; растущий буфер указывает на конфигурацию демона или доставку, пока пустой буфер указывает на инструментацию или время жизни процесса.

<Note>
  Проверяйте буфер только когда демон остановлен. Пока он работает, он собирает и удаляет каждый пакет за миллисекунды, поэтому списание каталога гонит коллектор и показывает гораздо меньше событий, чем было излучено.
</Note>

## Предотвращение сбоев в пользовательской среде выполнения
