Python 3.10 или новее и **нулевые зависимости во время выполнения** — это политика, а не случайность. SDK устанавливается в процессы агентов других людей, поэтому все объявленные им зависимости они унаследовали бы. Тест сканирует основные модули и запускает свежий интерпретатор, чтобы доказать, что ни один фреймворк не попадает в `sys.modules`.

## Установка

```bash
pip install failproofai-sdk
```

Пакет устанавливается как `failproofai-sdk` и импортируется в Python как `failproofai_sdk`. Расширения для фреймворков, такие как `failproofai-sdk[langgraph]`, устанавливают сам фреймворк; адаптеры всегда входят в базовый wheel.

## Конфигурация

```python
import failproofai_sdk

failproofai_sdk.configure(
    base_dir=None,
    flush_interval=0.5,
    environment="production",
)
```

| Аргумент | Назначение |
| --- | --- |
| `environment` | Метка на каждом событии — `production`, `staging`, `prod-eu`. По умолчанию `dev`. |
| `flush_interval` | Как часто фоновый поток записывает на диск, в секундах. По умолчанию `0.5`. |
| `base_dir` | Куда писать. По умолчанию `$FAILPROOFAI_HOME/custom-agents`, иначе `~/.failproofai/custom-agents` — буфер, за которым наблюдает демон, что вам нужно, если вы не знаете иначе. |

`configure()` **только именованные параметры** — `configure(None, 0.5, "prod")` вызывает `TypeError`. Она также проверяет каждый аргумент перед применением, и вызывает `ValueError`, если `flush_interval` не является конечным числом, большим нуля, поэтому отклоненный вызов оставляет SDK в точно таком же состоянии, а не в полупереведенном.

Установите через переменную окружения вместо этого:

| Переменная | Назначение |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Устанавливает `environment` без изменения кода, для когда метка принадлежит развертыванию, а не приложению. Аргумент `configure()` имеет приоритет над ней. |
| `FAILPROOFAI_HOME` | Переносит корень Failproof AI, который содержит буфер. |
| `FAILPROOFAI_SDK_STRICT` | `1` заставляет ошибки инструментирования выбрасываться вместо логирования. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` заставляет проблему совместимости фреймворка выбрасываться вместо предупреждения и продолжения. |

<Warning>
  **Без запятых в `environment`.** Ingest разбивает это поле на запятые для построения своих фильтров и пропускает любое событие, метка которого содержит одну — поэтому весь запуск молча исчезает. Напишите `prod-eu`, а не `prod,eu`.

  `configure(environment="prod,eu")` выбрасывает исключение, чтобы вы сразу узнали. `AGENTEYE_ENVIRONMENT` не может выбросить исключение — никто вас не вызывает — поэтому она выдает предупреждение один раз и откатывается на `dev`.
</Warning>

События ставятся в очередь в памяти и записываются в фоне каждые `flush_interval` секунд, с окончательной записью при выходе интерпретатора. Процесс, убитый полностью, теряет все, что еще не было записано.

## Области действия

Три менеджера контекста, каждый используется с `with` и `async with`:

| Область действия | Связывает | Выдает |
| --- | --- | --- |
| `session()` | ID сеанса. Возвращает его | Ничего — только идентификация |
| `agent(name)` | ID агента и `parent_id`, выведенный из содержащего агента | `agent_start` при входе, `agent_end` при выходе |
| `tool_call(name)` | Ничего нового — наследует содержащую идентификацию | `tool_use` при входе, `tool_result` при выходе |

```python
with failproofai_sdk.session():
    with failproofai_sdk.agent("planner"):
        with failproofai_sdk.tool_call("web_search", input={"q": q}) as t:
            t.output = search(q)
```

`tool_call()` по умолчанию устанавливает `tool_call_id` на свежий `uuid4().hex` и разрешает идентификацию один раз при входе, поэтому инструмент, который помещает свою собственную область действия внутрь, не может заставить закрывающийся `tool_result` приземлиться на другого агента. При ошибке он выдает `tool_result(error="TypeName: msg")` и **никакого события `error`** — ошибка инструмента, которую цикл ловит, не является ошибкой уровня запуска, и та, что распространяется, сообщается ровно один раз, содержащим `agent()`. Отмена закрывает лист без строки ошибки вообще.

## Адаптеры

`instrument()` подключает поддерживаемый фреймворк к областям действия выше. Без аргумента автоматически обнаруживает уже импортированные в этот процесс фреймворки; передайте имя, чтобы установить ровно один.

```python
failproofai_sdk.instrument()              # все уже импортировано
failproofai_sdk.instrument("crewai")      # ровно один
failproofai_sdk.uninstrument("crewai")    # восстановить исходные атрибуты
```

Четыре названия: `"langchain"` (включает LangGraph, так как LangGraph работает на менеджере обратных вызовов langchain-core), `"crewai"`, `"llama_index"` и `"pydantic_ai"`. Импорт фреймворка происходит внутри вызова, что позволяет `import failproofai_sdk` иметь нулевые зависимости.

Каждый фреймворк имеет свою страницу: [LangChain](/ru/start/integrations/langchain), [CrewAI](/ru/start/integrations/crewai), [LlamaIndex](/ru/start/integrations/llamaindex), [Pydantic AI](/ru/start/integrations/pydantic-ai).

## Идентичность

Каждое событие принадлежит сеансу и агенту. **Области действия заполняют оба**, поэтому вы редко их передаете:

```python
with failproofai_sdk.session():
    with failproofai_sdk.agent("planner"):
        failproofai_sdk.event.tool_use(tool_name="search", tool_call_id="c1")
```

Явная передача `session_id` или `agent_id` все еще работает и имеет приоритет.

Эти два **не** симметричны, когда ничего не связано:

| Пропущено | Ничего не связано |
| --- | --- |
| `session_id` | Выбрасывает `TypeError`, вместо выдачи события, которое Cloud молча отбросит |
| `agent_id` | Откатывается на `main`, поэтому события, выданные внутри `session()` без окружающего `agent()`, приземляются под одного агента по имени `main` |

Придумание ID сеанса рассеяло бы один запуск столько же сеансов, сколько у него есть сайтов эмиссии, вот почему только тот выбрасывает исключение.

`session_id` и `agent_id` также единственные два имени, проверяемые на пустоту: не-строка выбрасывает `TypeError`, а пустой или содержащий только пробел ID выбрасывает `ValueError`. Сервер *принимает* пустой ID, поэтому без этой проверки каждое событие, отправленное с одним, было бы сгруппировано под одним пустым ID и выглядело бы присутствующим при молчаливом объединении.

<Note>
  Идентичность работает на переменных контекста. Она автоматически следует за задачами `asyncio`, но **не** новыми потоками — оберните рабочий процесс в `failproofai_sdk.propagate()` или его события приземлятся несвязанными.
</Note>

## Каталог событий

Пятнадцать методов. Большинство идут в **парах** — открывающий и закрывающий.

| | Открывает | Закрывает | Временные метки SDK |
| --- | --- | --- | --- |
| **Агенты** | `agent_start` | `agent_end` | Нет |
| | `agent_pause` | `agent_resume` | Да |
| **Модели** | `model_request` | `model_response` | Нет — коррелируются в Cloud |
| **Инструменты** | `tool_use` | `tool_result` | Да |
| **Хуки** | `hook_triggered` | `hook_completed` | Да |
| **Люди** | `human_wait` | `human_input` | Да |

Три стоят отдельно: `error`, `human_pause`, `human_interrupt`.

<Accordion title="Каждое поле для каждого метода" icon="table">

Каждый метод также принимает `session_id` и `agent_id`, которые области действия заполняют для вас. Все остальное, оставленное как `None`, выпускается вместо отправки как JSON `null`, и каждый метод возвращает `None`.

| Метод | Обязательно | Опционально |
| --- | --- | --- |
| `agent_start` | — | `goal`, `parent_id` |
| `agent_end` | — | `outcome`, `summary` |
| `agent_pause` | `pause_id` | `reason`, `user_id` |
| `agent_resume` | `pause_id` | `reason`, `user_id` |
| `model_request` | — | `model`, `messages`, `system`, `tools`, `request_id` |
| `model_response` | — | `model`, `stop_reason`, `input_tokens`, `output_tokens`, `content`, `role`, `request_id`, `duration_ms` |
| `tool_use` | `tool_name`, `tool_call_id` | `input` |
| `tool_result` | `tool_name`, `tool_call_id` | `output`, `error` |
| `hook_triggered` | `hook_name`, `hook_id` | `trigger_event`, `input` |
| `hook_completed` | `hook_name`, `hook_id` | `outcome`, `output`, `error` |
| `error` | `error_type`, `message` | `traceback` |
| `human_wait` | `input_id` | `prompt`, `options`, `reason` |
| `human_input` | `input_id` | `response` |
| `human_pause` | — | `reason`, `user_id` |
| `human_interrupt` | — | `reason`, `user_id`, `at_step` |

</Accordion>

<Warning>
  Чтобы отметить запуск как неудачный, `outcome` должен быть одним из `failed`, `error`, `timeout` или `rejected`. Что-либо еще — включая почти совпадающий `"failure"` — считается успехом.
</Warning>

## Спаривание и продолжительность

**Одно правило: дайте закрывающему событию такой же ID, как и его открывающему.** Это то, что их спаривает и позволяет SDK времени брешь.

| Пара | Сопоставляется по | Ключ отслеживания |
| --- | --- | --- |
| `tool_use` → `tool_result` | `tool_call_id` | `tool:{session_id}:{tool_call_id}` |
| `hook_triggered` → `hook_completed` | `hook_id` | `hook:{session_id}:{hook_id}` |
| `agent_pause` → `agent_resume` | `pause_id` | `pause:{session_id}:{pause_id}` |
| `human_wait` → `human_input` | `input_id` | `human:{session_id}:{input_id}` |

Ключ имеет пространство имен сеансом, что является причиной, по которой оба граничных случая ниже верны.

**Не передавайте `duration_ms` сами** на этих четырех закрывающих. SDK измеряет его, и передача его выбрасывает `ValueError`.

<Note>
  `model_request` и `model_response` — это пара, которую Cloud коррелирует на `request_id`. SDK не отслеживает их и ничего не измеряет локально, вот почему `model_response` — единственное событие, которое принимает `duration_ms` от вас. Передайте целое число миллисекунд — число с плавающей точкой выбрасывает, потому что столбец является 32-битным целым числом и иначе приземлилась бы пусто.
</Note>

<Accordion title="Граничные случаи" icon="circle-help">

- **ID'ы должны быть уникальны только по типу, в одном сеансе.** Вызов инструмента и хук могут делить один; два сеанса, работающих одновременно, могут повторно использовать те же ID без столкновений.
- **Они не ограничены агентом.** Пара, открытая под одним агентом и закрытая под другим, все еще совпадает — что является нормальным случаем в коде с несколькими агентами.
- **`request_id` опционален, но рекомендуется.** Без него события модели спариваются в порядке прихода, поэтому два параллельных вызова в одном агенте могут неправильно спариться.
- **Пара, разделенная между процессами**, все еще совпадает в Cloud, но SDK не может ее рассчитать — ничего в обоих процессах не видело обоих половин.
- **Максимум 10,000 открывающих ждут закрывающих одновременно.** Прошедшие это самые старые отбрасываются, поэтому утечка не может расти без границ.

</Accordion>

## Ваши собственные поля

Любые лишние ключевые слова, которые вы передаете, сохраняются с событием:

```python
failproofai_sdk.event.tool_use(
    tool_name="search", tool_call_id="c1",
    fw_tenant="acme", fw_region="eu-west-1",     # ваши собственные
)
```

Предпочитайте JSON типы, если захотите их позже запросить. Что-либо еще — UUID, datetime, `Decimal`, набор, bytes, объект модели — хранится как строка.

<Warning>
  **Одиннадцать имен — исключение, и они выбрасывают вместо преобразования в строку.** Ingest поднимает каждое в типизированный столбец и хранит `NULL` для всего остального, при `200 OK`, невидимо — поэтому SDK отказывает им на сайте вызова вместо этого.

  | Имена | Должны быть |
  | --- | --- |
  | `duration_ms`, `input_tokens`, `output_tokens` | Целое число `int` в диапазоне беззнакового 32-бита |
  | `tool_name`, `tool_call_id`, `hook_name`, `hook_id`, `input_id`, `pause_id`, `error_type`, `model` | Строка — `None` выбрасывает `ValueError`, любой не-строка выбрасывает `TypeError` |

  Это применяется, прибыло ли значение как именованный параметр или как одна из ваших собственных добавок. `model_response` проверяет свои `input_tokens` и `output_tokens` при поступлении по той же причине — они, вероятно, заполняются прямо из объекта использования провайдера.
</Warning>

<Warning>
  **Добавьте префикс к именам ваших полей.** Добавки применяются последними, поэтому поле, называемое `model`, `tool_name` или `outcome`, молча перезаписывает реальное. Адаптеры фреймворков используют `fw_`; делайте то же самое и ничто не может столкнуться.

  Это также почему неправильно написанное опциональное поле никогда не вызывает ошибку — оно просто становится новым пользовательским полем. Если стандартное поле отсутствует в Cloud, сначала проверьте орфографию.
</Warning>

Эти пять имен зарезервированы и отклоняются полностью: `timestamp`, `session_id`, `agent_id`, `type`, `environment`.

## Другие экспорты

| Экспорт | Что это |
| --- | --- |
| `current()` | Идентичность, связанная прямо сейчас, как `Identity`. `current().session_id is None` означает ничего не связано |
| `Identity` | `session_id`, `agent_id`, `parent_id`, `depth`. Никогда не `None` сам — проверьте поля |
| `propagate(fn)` | Оборачивает `fn` так, чтобы он запускался с идентичностью, связанной в момент обертывания. Нужно для `Thread`, `pool.submit`, `pool.map`, `run_in_executor` |
| `_writer.flush_now()` | Слить и записать буферные записи немедленно, для теста или принудительной записи перед выходом |
| `__version__` | Установленная версия SDK |

## Доставка и проверка

<Tabs>
  <Tab title="Панель управления">
    В **Observe → Events**, сначала проверьте, что `agent_start` существует и `agent_end` существует последним. Затем откройте **Observe → Sessions** и подтвердите, что события модели, инструмента, человека, хука и ошибки появляются в предполагаемом порядке. Используйте ID сеанса как основной ключ устранения неполадок.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai flush --wait --timeout 60
    failproofai config --status
    fp sessions --since 1h --env production --session-id <session-id>
    fp events --since 1h --session-id <session-id> --full
    ```
  </Tab>
</Tabs>

Если Cloud пуст, проверьте `$FAILPROOFAI_HOME/custom-agents/events`, иначе `~/.failproofai/custom-agents/events`. Файлы JSONL доказывают эмиссию SDK; растущий буфер указывает на конфигурацию демона или доставку, в то время как пустой буфер указывает на инструментирование или время жизни процесса.

<Note>
  Проверяйте буфер только, когда демон остановлен. Пока он работает, он собирает и удаляет каждый пакет в течение миллисекунд, поэтому листинг каталога гонится с коллектором и показывает намного меньше событий, чем было выданно.
</Note>

## Предотвращение сбоев в пользовательском рантайме

Используйте результаты аудита и связанные трассы, чтобы определить небезопасное действие, требуемое доказательство и предполагаемый ответ. Пользовательская интеграция принудительного исполнения должна выставить действие перед выполнением, передать его структурированный ввод в движок политики и применить результирующее решение allow, instruct или deny.

[Свяжитесь с Failproof AI](mailto:support@befailproof.ai) и мы поможем вам отобразить границы модели, инструмента и жизненного цикла вашего рантайма на хуки политики, затем проверим интеграцию с вами.
