Evaluator получает завершённый сеанс агента и возвращает интересующие вас сигналы качества: числовые оценки, объяснение для каждой оценки и дополнительное резюме. Failproof AI хранит эти результаты рядом с трассировкой и строит графики по агентам и окружениям.

Пакет называется `agenteye-evaluator` и импортируется как `agenteye_evaluator`. Требуется Python 3.10 или новее и зависимости `fastapi`, `pydantic>=2` и `structlog`.

<Warning>
  **`pip install agenteye-evaluator` из публичного PyPI — это не правильный путь установки.** Пакет опубликован только как приватный артефакт релиза, а имя не зарезервировано на публичном PyPI — установка без уточнения может подтянуть чужой пакет в сервис, который читает ваши продакшн-транскрипты. Используйте лестницу ниже.
</Warning>

## Настройка evaluator

<Steps>
  <Step title="Установите SDK">
    Спускайтесь вниз по лестнице и остановитесь на первой подходящей ступени.

    Внутри монорепозитория, где существует директория `evaluator-sdk/`:

    ```bash
    pip install ./evaluator-sdk
    ```

    В противном случае — из приватного релиза. Wheels прикреплены к GitHub Releases на `agenteye-enterprise/releases`, помечены тегом `evaluator-sdk/v<version>`, и вам нужны `gh auth login` плюс доступ к этому репозиторию:

    ```bash
    gh release download evaluator-sdk/v<version> \
      --repo agenteye-enterprise/releases --pattern '*.whl'
    pip install ./agenteye_evaluator-*.whl
    ```

    Если ничего не подошло, попросите wheel у вашего контакта в Failproof AI вместо попытки самостоятельной установки.

    `uvicorn` намеренно не является зависимостью, поэтому установите сервер отдельно:

    ```bash
    pip install 'uvicorn[standard]'
    ```
  </Step>

  <Step title="Определите, что оценивать">
    Создайте `evaluator.py`. Этот пример проверяет, содержит ли сеанс какие-либо ошибки инструментов.

    ```python
    import os
    from agenteye_evaluator import Evaluator, EvalResponse

    app = Evaluator(token=os.environ.get("EVALUATOR_TOKEN"))

    @app.config
    def config():
        return {"inactivity_timeout_secs": 1800}

    @app.evaluator
    def evaluate(req):
        tool_errors = sum(
            1 for item in req.events
            if item.event_type == "tool_result" and item.payload.get("error")
        )
        return EvalResponse(
            scores={"tool_reliability": 1.0 if tool_errors == 0 else 0.0},
            reasoning={"tool_reliability": f"{tool_errors} tool errors"},
        )
    ```

    Полный конструктор — `Evaluator(token: str | None = None, *, title: str = "AgentEye Evaluator")`. Токен сравнивается с `hmac.compare_digest`; `title` — это название приложения FastAPI и является косметическим.

    <Warning>
      `token=None` полностью отключает аутентификацию. Это допустимо на ноутбуке, но является дырой в продакшене, где эндпоинт получает целые транскрипты сеансов.
    </Warning>
  </Step>

  <Step title="Запустите и протестируйте локально">
    Установите общий токен, запустите evaluator и подтвердите, что эндпоинт здоровья отвечает.

    ```bash
    export EVALUATOR_TOKEN=<shared-token>
    uvicorn evaluator:app --host 0.0.0.0 --port 8080
    ```

    В другом терминале:

    ```bash
    curl http://127.0.0.1:8080/health
    ```

    Каждый декоратор возвращает функцию неизменённой, поэтому `evaluate(req)` остаётся напрямую вызываемой. Это делает юнит-тесты дешёвыми — постройте `EvalRequest` и вызовите обработчик, никакого HTTP.
  </Step>
</Steps>

## Подключение evaluator к Failproof AI

1. Разверните evaluator по HTTPS URL, доступному для Failproof AI Cloud.
2. Настройте `EVALUATOR_ENDPOINT` с этим URL и установите `EVALUATOR_TOKEN` в тот же токен, который использует evaluator. Для управляемого облака обратитесь в [support@befailproof.ai](mailto:support@befailproof.ai) для настройки соединения.
3. Запустите оценку и подтвердите, что её оценки появились в Failproof AI.

<Tabs>
  <Tab title="Dashboard">
    Откройте завершённый сеанс в разделе **Observe → Sessions** и выберите **Run evaluation**, если он не был оценен автоматически. Посмотрите статус, оценки, рассуждения и резюме в панели **Evaluation** сеанса.

    Используйте **Observe → Evaluations** для сравнения оценок по агентам или окружениям. Используйте **Observe → Metrics** для задержек, стоимости, токенов и других числовых измерений.

    Начните с одного сеанса, чтобы подтвердить, что evaluator вернул ожидаемые ключи оценок и полезные рассуждения для этого конкретного запуска.

    ![Представление деталей сеанса с оценками оценки и рассуждениями рядом с его трассировкой.](/images/dashboard/session-detail.png)

    Когда отдельные результаты выглядят правильно, используйте дашборд оценок для сравнения этих оценок во времени и по агентам или окружениям.

    ![Дашборд качества, отображающий оценки evaluator во времени.](/images/dashboard/dashboard-quality.png)

    Здоровый график должен использовать стабильные имена оценок; изменение ключа создаёт отдельный ряд.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp evals --since 1h --score tool_reliability:0..1
    fp evals --since 24h --aggregate
    ```
  </Tab>
</Tabs>

Для самостоятельно размещённого облака автоматическая оценка отключена до тех пор, пока `EVALUATOR_ENDPOINT` не установлен на процессе сервера. Перезагрузите сервер после изменения переменных окружения evaluator.

## Декораторы и маршруты

| Декоратор | Маршрут | Обязательный |
| --- | --- | --- |
| `@app.evaluator` | `POST /evaluate` | Да. |
| `@app.job_lookup` | `GET /evaluate/{job_id}` | Только если вы когда-либо возвращаете `JobPending`. Без него опросы получают 404. |
| `@app.config` | `GET /config` | Нет, но требуется для любого сеанса, который никогда не выдаёт `agent_end` — см. ниже. |

Каждый декоратор принимает синхронную или асинхронную функцию, возвращает её неизменённой и выбрасывает `ValueError`, если вы регистрируете её дважды.

| Маршрут | Аутентификация |
| --- | --- |
| `GET /health` | Открыт даже при установленном токене. |
| `POST /evaluate` | Bearer. |
| `GET /evaluate/{job_id}` | Bearer. |
| `GET /config` | Bearer. |

Соответствие схемы bearer не зависит от регистра. `GET /config` без зарегистрированного `@app.config` всё равно возвращает `{"default_poll_interval_secs": 10}`, поэтому SDK всегда объявляет интервал.

SDK ограничивает телата запросов оценки на 25 МиБ, проверка выполняется по `Content-Length` перед чтением тела. Превышение лимита — это 413, что является 4xx и, следовательно, терминально. Неизвестные поля запроса игнорируются, чтобы сервисы оставались совместимыми по мере расширения контракта событий.

<Warning>
  Регистрация `@app.config` с `inactivity_timeout_secs` — это то, что включает сканер резервной копии. Без него сеанс, который никогда не выдал `agent_end` — всё заброшенное, сбойное или ещё ждущее — вообще никогда не ставится в очередь на оценку. Значения нуля или меньше отбрасываются.
</Warning>

## Типы SDK

| Тип | Поля |
| --- | --- |
| `AgentEvent` | `id`, `ts`, `event_type`, `payload` |
| `EvalRequest` | `schema_version`, `session_id`, `agent_id`, `environment`, `started_at`, `ended_at`, `events` |
| `EvalResponse` | `scores`, `reasoning`, `summary` |
| `JobPending` | `job_id`, `next_poll_secs` |
| `EvaluatorConfig` | `inactivity_timeout_secs`, `default_poll_interval_secs` |

## Поля запроса и ответа

| Поле | Тип | Примечания |
| --- | --- | --- |
| `EvalRequest.schema_version` | `str` | В настоящий момент `"1"`. |
| `session_id`, `agent_id`, `environment` | `str` | Идентификация сеанса и окружение. |
| `started_at` | `datetime` | Временная метка первого события. |
| `ended_at` | `datetime \| None` | Временная метка события `agent_end`, а не момент «когда сеанс остановился». Сеансы, поставленные в очередь сканером неактивности, никогда не имели `agent_end` и приходят как `None`. |
| `events` | `list[AgentEvent]` | Полный упорядоченный поток событий. |
| `AgentEvent.id` | `int` | Идентификатор строки события бэкенда. |
| `AgentEvent.ts` | `datetime` | Временная метка события. |
| `AgentEvent.event_type` | `str` | Семейство событий, такое как `tool_use`. |
| `AgentEvent.payload` | `dict[str, Any]` | Весь JSON события в сплющенном виде, поэтому специфичные для события поля находятся на верхнем уровне и `payload["type"]` дублирует `event_type`. |
| `EvalResponse.scores` | `dict[str, float] \| None` | Числовые измерения, отображаемые в оценках. |
| `EvalResponse.reasoning` | `dict[str, str] \| None` | Объяснения по оценкам; ключи должны зеркалировать `scores`. |
| `EvalResponse.summary` | `str \| None` | Общее нарратив оценки. Усекается на 8192 байт со стороны сервера; `last_error` на 2048. |

Сериализация использует `exclude_none`, поэтому неустановленные поля опускаются, а не отправляются как `null`.

<Warning>
  Получение длительности из `ended_at` падает на реальных данных. Каждый сеанс, который поставляет сканер неактивности, приходит с `ended_at`, установленным в `None`. Проверьте это перед вычитанием.
</Warning>

## Формы возврата

Ваш обработчик может возвращать ровно одно из трёх. Всё остальное — это `TypeError`, который проявляется как 500.

| Возврат | Wire `status` | Терминально |
| --- | --- | --- |
| `EvalResponse(...)` | `done` | Да — оценки сохранены. |
| `JobPending(job_id=...)` | `pending` | Нет — сервер опрашивает. |
| Сырой `dict` с `status` в `done`, `pending` или `error` | Как задано | `error` является терминальным. |

Статус `error` не имеет типизированной модели. Для терминального отказа вы должны вернуть сырой dict, и `error` должен быть непустой `str`:

```python
return {"status": "error", "error": "model service unavailable"}
```

<Warning>
  **Выброс исключения — это не сообщение.** Исключение становится обобщённой ошибкой 500, чьё тело — это `"evaluator raised an internal error"` — ваш текст исключения никогда не доходит до сервера, и сервер рассматривает каждый 5xx как временный и повторяет его. Верните dict `error`, когда вы хотите, чтобы отказ был записан.
</Warning>

## Возврат асинхронной работы

Используйте `JobPending`, когда оценка не может завершиться внутри одного запроса. Идентификатор работы непрозрачен для Failproof AI и должен оставаться разрешимым вашим сервисом до тех пор, пока результат не будет собран или не истечёт тайм-аут сервера.

```python
from agenteye_evaluator import EvalRequest, EvalResponse, Evaluator, JobPending

app = Evaluator(token="shared-secret")

@app.evaluator
def start(req: EvalRequest) -> JobPending:
    job_id = enqueue(req)
    return JobPending(job_id=job_id, next_poll_secs=30)

@app.job_lookup
def lookup(job_id: str):
    result = get_result(job_id)
    if result is None:
        return JobPending(job_id=job_id, next_poll_secs=30)
    return EvalResponse(
        scores=result.scores,
        reasoning=result.reasoning,
        summary=result.summary,
    )
```

Интервал опроса выбирается в таком порядке: `JobPending.next_poll_secs`, `EvaluatorConfig.default_poll_interval_secs`, затем `EVALUATOR_POLLING_INTERVAL_SECS` сервера. Значения зажимаются между 1 секундой и 1 часом. Лимит опроса по стенным часам по умолчанию сервера — один час, после чего результат записывается как `timeout`.

## Настройки оператора сервера

Автоматическая оценка осуществляется на уровне развёртывания и остаётся отключённой, когда `EVALUATOR_ENDPOINT` отсутствует.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `EVALUATOR_ENDPOINT` | не установлена | Базовый URL сервиса evaluator. |
| `EVALUATOR_TOKEN` | не установлена | Bearer токен, используемый совместно с `Evaluator(token=...)`. |
| `EVALUATOR_WORKERS` | `2` | Рабочих потоков dispatcher. |
| `EVALUATOR_CLAIM_BATCH` | `4` | Сеансов, запрашиваемых за проход dispatcher. |
| `EVALUATOR_POLLING_INTERVAL_SECS` | `10` | Интервал опроса асинхронности по умолчанию. |
| `EVALUATOR_REQUEST_TIMEOUT_MS` | `30000` | Тайм-аут оценки за запрос, применяется к POST и каждому опросу. |
| `EVALUATOR_MAX_ATTEMPTS` | `5` | Попыток доставки перед терминальным отказом. |
| `EVALUATOR_CONFIG_REFRESH_SECS` | `300` | Интервал обновления для `/config`. |
| `EVALUATOR_MAX_POLL_DURATION_SECS` | `3600` | Максимальное время опроса асинхронности по стенным часам. |

Из этой таблицы стоит выделить две последствия:

- **Работники, умноженные на размер пакета, — это ваша одновременность.** При значениях по умолчанию это 8 одновременных вызовов против вашего эндпоинта в масштабе развёртывания. Масштабируйте сервис для этого числа, а не для одного.
- **4xx терминально, а 5xx, 429 или отказ транспорта повторяются** с backoff до `EVALUATOR_MAX_ATTEMPTS`. Несоответствие токена — это 401, поэтому оно немедленно отказывает вместо повтора — вот что первым делом проверяют, когда ничего не приходит.

Сервер также может ограничить, какие организации используют развёрнутый evaluator на уровне развёртывания. Рассматривайте изменения эндпоинта, токена, повтора и затвора организации как конфигурацию оператора и перезагружайте или откатывайте сервер после их изменения.

## Безопасность и операции

- Поместите evaluator за HTTPS, когда трафик пересекает границу доверяемой сети.
- Настройте непустой bearer токен и держите его идентичным на обоих сервисах. `token=None` принимает каждого вызывающего.
- Не логируйте токен или полные чувствительные подсказки из полезных нагрузок запроса. SDK этого не делает: отказы валидации возвращают 422 без отражения полезной нагрузки, 500 никогда не отражают текст исключения, и токен не появляется в каком-либо логируемом поле.
- Делайте синхронные обработчики идемпотентными; повторы могут повторить запрос.
- Сохраняйте состояние асинхронной работы вне памяти процесса в продакшене.
- Возвращайте стабильные ключи оценок. Переименование ключа создаёт новый ряд графика, а не изменяет старый.

SDK выдаёт структурированные логи жизненного цикла, такие как `eval received`, `eval responded`, `job lookup`, `config returned`, `auth rejected` и исключения обработчика. Ответы `/config` помечают `source="user"` в сравнении с `source="default"`, поэтому вы можете определить, был ли выбран ваш `@app.config`. Это не настраивает обработчики логирования; используйте конфигурацию логирования приложения хоста.
