## Семейства событий

- Запуск, остановка, пауза и возобновление агента
- Запрос и ответ модели
- Использование инструмента и результат
- Запуск и завершение хука
- Ожидание человека, ввод, пауза и прерывание
- Явные ошибки

Каждое событие содержит временную метку, ID сессии, ID агента, тип события и окружение. События также содержат поля, специфичные для типа события: данные о модели, инструменте, корреляции, исходе, содержимом, длительности или ошибке.

## Проверка контракта события

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Observe → Events**.
    2. Установите короткий временной диапазон и отфильтруйте по окружению, агенту и типу события.
    3. Выберите событие для проверки его нормализованных полей и необработанной полезной нагрузки, затем откройте его сессию, чтобы увидеть контекст выполнения.
    4. Если отсутствует парное событие длительности, убедитесь, что события начала и завершения используют один и тот же ID корреляции.

    Используйте поток Events для сужения данных до одного запуска агента и проверки нормализованных полей события.

    ![Живой поток Events с фильтрами по окружению, агенту, сессии и типу события.](/images/dashboard/events-stream.png)

    Затем перейдите к событию в его сессию. Трассировка показывает, что произошло непосредственно до и после него, что необходимо, когда только полезной нагрузки недостаточно для понимания.

    ![Связанная трассировка сессии для проверки события в контексте выполнения.](/images/dashboard/session-detail.png)

    Сравните ID корреляции и временные метки в обоих представлениях, если отсутствует парное событие или длительность.
  </Tab>
  <Tab title="CLI">
    Обнаружьте допустимые значения фильтров, затем получите полные полезные нагрузки событий для одной сессии:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    Используйте `fp --json events ... --fields ts,event_type,session_id,payload` для проверки в формате, читаемом машиной.
  </Tab>
</Tabs>

## Зарезервированные поля SDK

Не используйте `timestamp`, `session_id`, `agent_id`, `type` или `environment` в качестве пользовательских полей Python SDK. Длительности парных событий, такие как длительность результата инструмента, рассчитываются SDK и не могут быть предоставлены вручную.

## Локальные границы

- Состояние Failproof AI находится в `~/.failproofai`, если не указано иное.
- `failproofai-sdk` использует `AGENTEYE_HOME` для своего переопределения базовой директории в режиме совместимости.
- Метки окружений можно установить через конфигурацию SDK или `AGENTEYE_ENVIRONMENT`.
- Учетные данные демона хранятся отдельно от параметров без тайны.

Используйте стабильные имена окружений с низкой кардинальностью. Запятые не поддерживаются в метках окружений демона.

## Изменение метки окружения

<Tabs>
  <Tab title="Dashboard">
    Метки окружений назначаются эмитирующим SDK или демоном Failproof. После изменения откройте **Observe → Sessions** и используйте фильтр окружений, чтобы подтвердить, что новые сессии содержат новое значение. Существующие сессии сохраняют свое исходное окружение.

  </Tab>
  <Tab title="CLI">
    Для `failproofai-sdk` настройте окружение в коде или с помощью его переменной окружения в режиме совместимости. Перезапустите конфигурацию демона при изменении параметров на уровне машины.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
