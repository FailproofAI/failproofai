## Семейства событий

- Запуск, остановка, пауза и возобновление агента
- Запрос и ответ модели
- Использование инструмента и результат
- Срабатывание и завершение хука
- Ожидание человека, ввод, пауза и прерывание
- Явные ошибки

Каждое событие содержит временную метку, ID сессии, ID агента, тип события и окружение. Поля, специфичные для события, содержат данные модели, инструмента, корреляции, результата, содержимого, длительности или ошибки.

## Проверка контракта события

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Observe → Events**.
    2. Установите короткий временной интервал и отфильтруйте по окружению, агенту и типу события.
    3. Выберите событие, чтобы проверить его нормализованные поля и необработанные данные, затем откройте его сессию, чтобы увидеть контекст выполнения.
    4. Если отсутствует связанная длительность, убедитесь, что события запуска и завершения используют одинаковый ID корреляции.

    Используйте поток Events для сужения данных до одного запуска агента и проверки нормализованных полей события.

    ![Поток Live Events с фильтрами для окружения, агента, сессии и типа события.](/images/dashboard/events-stream.png)

    Затем перейдите по событию в его сессию. Трассировка показывает, что произошло сразу до и после него, что необходимо, когда только полезной нагрузки недостаточно.

    ![Связанная трассировка сессии, используемая для проверки события в контексте выполнения.](/images/dashboard/session-detail.png)

    Сравните ID корреляции и временные метки в обоих представлениях, когда отсутствует связанное событие или длительность.
  </Tab>
  <Tab title="CLI">
    Найдите допустимые значения фильтров, затем получите полные полезные нагрузки событий для одной сессии:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    Используйте `fp --json events ... --fields ts,event_type,session_id,payload` для проверки, удобной для машин.
  </Tab>
</Tabs>

## Зарезервированные поля SDK

Не используйте `timestamp`, `session_id`, `agent_id`, `type` или `environment` в качестве пользовательских полей Python SDK. Длительности связанных событий, такие как длительность результата инструмента, рассчитываются SDK и не могут быть предоставлены вручную.

## Локальные границы

- Состояние Failproof AI находится в `~/.failproofai`, если не настроено иное.
- `failproofai-sdk` всегда использует очередь в `~/.failproofai/custom-agents`. `FAILPROOFAI_HOME` переводит этот каталог; сегмент `custom-agents` всегда добавляется, поэтому очередь не может быть размещена вне него. Только собственный `configure(base_dir=...)` SDK записывает в другие места. `AGENTEYE_HOME` читается старым `agenteye-collector` для определения того, что наблюдать, и больше не влияет на то, куда SDK записывает данные.
- Метки окружения можно устанавливать через конфигурацию SDK или `AGENTEYE_ENVIRONMENT`.
- Учетные данные демона хранятся отдельно от параметров без секретов.

Используйте стабильные метки окружения с низкой кардинальностью. Запятые не поддерживаются в метках окружения демона.

## Изменение метки окружения

<Tabs>
  <Tab title="Dashboard">
    Метки окружения назначаются передающим SDK или демоном Failproof. После изменения откройте **Observe → Sessions** и используйте фильтр окружения, чтобы подтвердить, что новые сессии содержат новое значение. Существующие сессии сохраняют свое исходное окружение.

  </Tab>
  <Tab title="CLI">
    Для `failproofai-sdk` настройте окружение в коде или с помощью его устаревшей переменной окружения. Перезапустите конфигурацию демона при изменении параметров уровня машины.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
