## Семейства событий

- Запуск, завершение, пауза и возобновление агента
- Запрос и ответ модели
- Использование инструмента и результат
- Хук активирован и завершён
- Ожидание человека, ввод, пауза и прерывание
- Явные ошибки

Каждое событие содержит временную метку, ID сессии, ID агента, тип события и окружение. Поля, специфичные для события, содержат данные модели, инструмента, корреляции, результата, содержимого, длительности или ошибки.

## Проверка контракта события

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Observe → Events**.
    2. Установите короткий временной диапазон и отфильтруйте по окружению, агенту и типу события.
    3. Выберите событие, чтобы проверить его нормализованные поля и исходный payload, затем откройте его сессию, чтобы увидеть контекст выполнения.
    4. Если отсутствует связанная длительность, убедитесь, что события начала и завершения используют один и тот же ID корреляции.

    Используйте поток Events для сужения данных до одного запуска агента и проверки нормализованных полей события.

    ![Живой поток Events с фильтрами по окружению, агенту, сессии и типу события.](/images/dashboard/events-stream.png)

    Затем отследите событие в его сессию. Трасса показывает, что произошло непосредственно до и после него, что необходимо, когда payload самостоятельно неоднозначен.

    ![Связанная трасса сессии, используемая для проверки события в контексте выполнения.](/images/dashboard/session-detail.png)

    Сравните ID корреляции и временные метки в обоих представлениях, если отсутствует связанное событие или длительность.
  </Tab>
  <Tab title="CLI">
    Найдите допустимые значения фильтров, затем получите полные payload события для одной сессии:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    Используйте `fp --json events ... --fields ts,event_type,session_id,payload` для проверки, удобной для машин.
  </Tab>
</Tabs>

## Зарезервированные поля SDK

Не используйте `timestamp`, `session_id`, `agent_id`, `type` или `environment` в качестве пользовательских полей Python SDK. Длительности связанных событий, такие как длительность результата инструмента, вычисляются SDK и не могут быть предоставлены вручную.

## Локальные границы

- Состояние Failproof AI находится в `~/.failproofai`, если не настроено иначе.
- `failproofai-sdk` использует `AGENTEYE_HOME` для переопределения устаревшего базового каталога.
- Метки окружения можно установить через конфигурацию SDK или `AGENTEYE_ENVIRONMENT`.
- Учётные данные демона хранятся отдельно от параметров без секретов.

Используйте стабильные, низкокардинальные имена окружений. Запятые не поддерживаются в метках окружения демона.

## Изменение метки окружения

<Tabs>
  <Tab title="Dashboard">
    Метки окружения назначаются передающим SDK или демоном Failproof. После изменения одной откройте **Observe → Sessions** и используйте фильтр окружения для подтверждения того, что новые сессии содержат новое значение. Существующие сессии сохраняют своё исходное окружение.

  </Tab>
  <Tab title="CLI">
    Для `failproofai-sdk` настройте окружение в коде или с помощью его устаревшей переменной окружения. Перезапустите конфигурацию демона при изменении параметров уровня машины.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
