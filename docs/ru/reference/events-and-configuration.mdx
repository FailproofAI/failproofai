## Два словаря событий

Failproof AI использует два разных типа события, и они никогда не совпадают по названию.

| Словарь | Создается | Названия выглядят как | Справка |
| --- | --- | --- | --- |
| События телеметрии | `failproofai-sdk`, изнутри вашего агента | `tool_use`, `tool_result`, `hook_triggered`, `model_response` | [Python SDK](/ru/reference/custom-agents) |
| События хуков | Оболочка агента, нормализованная Failproof AI | `PreToolUse`, `PostToolUse`, `Stop`, `UserPromptSubmit` | [Пользовательские политики](/ru/reference/policy-sdk#choose-the-event) |

Сторона хуков нормализует собственные имена событий каждой оболочки в 29 канонических типов. Сторона телеметрии имеет 15 методов и свой контракт полей. `hook_triggered` и `PreToolUse` — это не два варианта написания одного и того же.

## Семейства событий

- Запуск, завершение, пауза и возобновление агента
- Запрос и ответ модели
- Использование инструмента и результат
- Хук запущен и завершен
- Ожидание человека, ввод, пауза и прерывание
- Явные ошибки

Каждое событие содержит временную метку, ID сессии, ID агента, тип события и окружение. Поля конкретного события содержат данные о модели, инструменте, корреляции, результате, содержимом, продолжительности или ошибке.

## Зарезервированные поля SDK

Пять имен полностью отклоняются как пользовательские поля, потому что SDK устанавливает их для каждого события:

`timestamp`, `session_id`, `agent_id`, `type`, `environment`.

Еще одиннадцать принимаются, но проверяются по типу, потому что конечная точка приема извлекает их из полезной нагрузки в типизированные столбцы и молча сохраняет `NULL` для всего неправильного типа. SDK вместо этого вызывает исключение в месте вызова, где вы все еще можете увидеть, что произвело значение.

| Имена | Требуемый тип |
| --- | --- |
| `duration_ms`, `input_tokens`, `output_tokens` | `int`, в диапазоне беззнакового 32-битного числа. Float или bool вызывает исключение. |
| `tool_name`, `tool_call_id`, `hook_name`, `hook_id`, `input_id`, `pause_id`, `error_type`, `model` | `str`. `None` вызывает исключение, поскольку строка придет с 200 OK и будет невидима для каждого фильтра по этому полю. |

### Продолжительность

SDK измеряет интервал между четырьмя парными событиями и отклоняет `duration_ms`, который вы передаете сами: `tool_use` → `tool_result`, `hook_triggered` → `hook_completed`, `agent_pause` → `agent_resume` и `human_wait` → `human_input`.

`model_response` — исключение. SDK никогда не засекает вызовы модели, поэтому вы сами предоставляете `duration_ms` как целое число миллисекунд. Смотрите [правила корреляции](/ru/reference/custom-agents) для того, как пара сопоставляется.

## Локальные границы

- Состояние Failproof AI находится под `~/.failproofai`, если не установлено иное.
- `failproofai-sdk` всегда буферизует под `~/.failproofai/custom-agents`. `FAILPROOFAI_HOME` перемещает этот дом; сегмент `custom-agents` всегда добавляется, поэтому буферизация не может быть помещена вне него. Только собственный `configure(base_dir=...)` SDK пишет в другие места. `AGENTEYE_HOME` читается старым `agenteye-collector` для выбора того, что смотреть, и больше не влияет на то, где SDK пишет.
- Учетные данные находятся в `~/.failproofai/credentials.json`, записаны с правами `0600`. Они намеренно не в `config.json`, который написан обычной записью и наследует umask, поэтому он доступен для чтения каждому локальному пользователю на машине.

Используйте стабильные имена окружений с низкой кардинальностью. Запятая отклоняется обоими писателями: демон отказывается от нее в `collector.environment`, и SDK вызывает исключение при `configure(environment=...)`. Причина одна и та же с обеих сторон — конечная точка приема разбивает это поле по запятым и пропускает всю строку, отвечая `200 OK` без сохранения чего-либо.

## Конфигурация машины

Не секретные параметры демона находятся в `~/.failproofai/config.json`. `hooks_verbosity`, `redact` и `environment` не имеют флага CLI — отредактируйте файл напрямую. `sessions`, `hooks` и `machine_id` записываются `failproofai config` при подключении этой машины к Cloud.

| Ключ | Значения | По умолчанию | Что это контролирует |
| --- | --- | --- | --- |
| `collector.sessions` | `true` / `false` | `false`, и `true` после подключения к Cloud | Отправка расшифровок сессий агента. Расшифровка содержит подсказки, содержимое файлов и все, что было вставлено в терминал. |
| `collector.hooks` | `true` / `false` | `true` | Отправка активности хуков. Содержит решения и имена инструментов, никогда не содержимое файлов. |
| `collector.hooks_verbosity` | `all` / `decisions` / `off` | `decisions` | `decisions` сохраняет каждый deny и instruct в точном виде и агрегирует примерно 99% которые allow. |
| `collector.redact` | `minimal` / `off` | `minimal` | Редактирование, применяемое до того, как что-либо покидает машину. |
| `collector.environment` | любая строка без запятой | `local` | Метка, проставляемая на каждом событии, которое отправляет эта машина. |
| `collector.machine_id` | любая строка | id уже на диске, иначе новый случайный UUID | Машина, под которой панель инструментов группирует эти данные. Записывается с помощью `--machine-id`. Никогда не выводится из имени хоста. |

<Note>
  `failproofai backfill --help` указывает `~/.failproofai/config.toml`. Это устаревший путь из более ранней компоновки дома; текущая сборка его не пишет. Файл называется `config.json`.
</Note>

Подключение к Cloud отправляет как решения по политике, так и полные расшифровки сессий.

<Warning>
  `--no-transcripts` не отключает расшифровки на пути настройки. `failproofai config --token <key> --no-transcripts` парсит флаг, а затем никогда его не читает, и мастер подключается с включенными сессиями, поэтому расшифровки продолжают отправляться, пока вы думаете, что отказались.

  Чтобы отправлять только решения, установите `collector.sessions` в `false` в `~/.failproofai/config.json` после подключения:

  ```json
  {
    "collector": {
      "sessions": false
    }
  }
  ```
</Warning>

Backfill следует одинаковым параметрам сборщика, поэтому он никогда не отправляет то, что ваша конфигурация говорит, что вы не хотите. Повторная отправка безопасна: редактирование детерминировано, поэтому повторно отправленное событие хешируется идентично его первой отправке и коллапсирует в уже существующую строку.

## Изменение метки окружения

SDK и демон каждый проставляют свою собственную метку, и они устанавливаются в разных местах.

<Tabs>
  <Tab title="Python SDK">
    Установите это в коде или в окружении процесса, который создает события. По умолчанию `dev`.

    ```python
    import failproofai_sdk

    failproofai_sdk.configure(environment="production-us-east")
    ```

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    ```

    `AGENTEYE_ENVIRONMENT` читается только `failproofai-sdk`. Ни CLI, ни демон не читают это, поэтому его экспорт ничего не меняет на машине.
  </Tab>
  <Tab title="Daemon">
    Отредактируйте `collector.environment` в `~/.failproofai/config.json`. По умолчанию `local` и ни один флаг CLI это не устанавливает.

    ```json
    {
      "collector": {
        "environment": "production-us-east"
      }
    }
    ```

    ```bash
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
  <Tab title="Dashboard">
    Метки окружения назначаются SDK или демоном Failproof, которые их создают, поэтому здесь ничего менять не нужно. После изменения одной у источника откройте **Observe → Sessions** и используйте фильтр окружения, чтобы подтвердить, что новые сессии несут новое значение. Существующие сессии сохраняют свое исходное окружение.
  </Tab>
</Tabs>
