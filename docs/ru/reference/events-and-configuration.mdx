## Семейства событий

- Запуск, завершение, пауза и возобновление агента
- Запрос и ответ модели
- Использование инструмента и результат
- Hook запущен и завершен
- Ожидание человека, ввод, пауза и прерывание
- Явные ошибки

Каждое событие содержит временную метку, ID сессии, ID агента, тип события и окружение. Поля, специфичные для события, содержат данные о модели, инструменте, корреляции, результате, содержимом, длительности или ошибке.

## Проверка контракта события

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Observe → Events**.
    2. Установите короткий временной интервал и отфильтруйте по окружению, агенту и типу события.
    3. Выберите событие, чтобы проверить его нормализованные поля и исходный полезный груз, затем откройте его сессию, чтобы увидеть контекст выполнения.
    4. Если отсутствует парная длительность, убедитесь, что события запуска и завершения используют один и тот же ID корреляции.

    Используйте поток Events, чтобы сузить данные до одного запуска агента и проверить нормализованные поля события.

    ![Живой поток Events с фильтрами по окружению, агенту, сессии и типу события.](/images/dashboard/events-stream.png)

    Затем перейдите к событию в его сессию. Трасса показывает, что произошло непосредственно до и после него, что необходимо, когда полезный груз сам по себе неоднозначен.

    ![Связанная трасса сессии для проверки события в контексте выполнения.](/images/dashboard/session-detail.png)

    Сравните ID корреляции и временные метки в обоих представлениях, когда отсутствует парное событие или длительность.
  </Tab>
  <Tab title="CLI">
    Откройте действительные значения фильтров, затем получите полные полезные грузы событий для одной сессии:

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    Используйте `fp --json events ... --fields ts,event_type,session_id,payload` для проверки в машиночитаемом формате.
  </Tab>
</Tabs>

## Зарезервированные поля SDK

Не используйте `timestamp`, `session_id`, `agent_id`, `type` или `environment` как пользовательские поля Python SDK. Парные длительности событий, такие как длительность результата инструмента, рассчитываются SDK и не могут быть предоставлены вручную.

## Локальные границы

- Состояние Failproof AI хранится в `~/.failproofai`, если не настроено иное.
- `failproofai-sdk` всегда буферизирует под `~/.failproofai/custom-agents`. `FAILPROOFAI_HOME` перемещает этот домашний каталог; сегмент `custom-agents` всегда добавляется, поэтому буфер не может быть размещен вне него. Только собственная функция `configure(base_dir=...)` SDK записывает в другие места. `AGENTEYE_HOME` читается устаревшим `agenteye-collector` для выбора того, что наблюдать, и больше не влияет на место записи SDK.
- Метки окружений можно установить через конфигурацию SDK или `AGENTEYE_ENVIRONMENT`.
- Учетные данные демона хранятся отдельно от параметров без секретов.

Используйте стабильные, низкокардинальные названия окружений. Запятые не поддерживаются в метках окружений демона.

## Изменение метки окружения

<Tabs>
  <Tab title="Dashboard">
    Метки окружений назначаются излучающим SDK или демоном Failproof. После изменения откройте **Observe → Sessions** и используйте фильтр окружения, чтобы подтвердить, что новые сессии содержат новое значение. Существующие сессии сохраняют свое исходное окружение.

  </Tab>
  <Tab title="CLI">
    Для `failproofai-sdk` настройте окружение в коде или с помощью его устаревшей переменной окружения. Повторно запустите конфигурацию демона при изменении параметров на уровне машины.

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
