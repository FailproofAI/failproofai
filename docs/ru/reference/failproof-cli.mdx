Установите локальный CLI с помощью `npm install -g failproofai`. Запустите его без аргументов, чтобы открыть панель управления локальными политиками.

Пакет требует Node.js версии 20.9 или новее. Bun версии 1.3 или новее поддерживается для разработки и установки из исходников. `failproofai configure` и `failproofai setup` — это псевдонимы для `failproofai config`. `failproofai policy`, `failproofai pack` и `failproofai p` — все это варианты написания `failproofai policies` — пакеты и отдельные политики раньше были тремя командами для одной идеи, теперь это одна команда. Старые варианты написания по-прежнему работают, за двумя исключениями: `pack list <source>` теперь `policies show <source>`, а `pack build` теперь `publish`.

## Настройка машины

Установите CLI, затем прочитайте ключ машины в оболочку. `read -s` принимает его в приглашении, которое не отображается, поэтому он никогда не появляется в команде:

```bash
npm install -g failproofai
read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
```

Затем настройте машину и выберите, что она будет обеспечивать:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

`failproofai config` — это вся настройка: она устанавливает сервис `failproofaid` (root один раз — в терминале он просит ваш пароль sudo и просит его снова, если он истек до завершения настройки; без терминала используется `sudo -n` и никогда не требует вводить пароль), подключает hooks в каждый найденный CLI агента и подключается к Cloud. Без терминала — CI, контейнер, агент, который его управляет — она применяет вместо того, чтобы спрашивать, и выходит с кодом 1, если что-либо из того, о чём её попросили, не произошло.

В терминале шаг **Подключение к облаку** на машине, которая ещё не подключена, сразу же начинает **вход в FailproofAI Cloud**; нажмите Tab для других вариантов: **Вставить ключ API** или **Использовать открытый исходный код**. Вход открывает ссылку — или выводит её по SSH или без дисплея, чтобы открыть на любом устройстве — где вы регистрируетесь или входите, выбираете или создаёте организацию и авторизуете машину; терминал сам примет одобрение и покажет, кто его одобрил и для какой организации. Ключ создаётся только после завершения настройки, после установки daemon. На машине, которая уже подключена с работающим ключом, шаг представляет собой меню с **Сохранить текущее подключение** в начале, поэтому повторный запуск настройки никогда не открывает браузер сам по себе; сохранённый ключ, который больше не работает, сразу же начинает вход и объясняет почему. Повторный вход создаёт новый ключ и оставляет старый работающим, пока вы его не отозвёте. Cloud, созданный до входа через браузер, об этом говорит и предлагает другие варианты.

Он выбирает **нет** политик. Это работа второй команды, и без неё только что настроенная машина не обеспечивает ничего, кроме всегда включённой защиты.

Предпочитайте переменную окружения вместо `--token`: аргумент командной строки читается из `ps` каждым пользователем на машине. Это всё, что защищает переменная — ключ, введённый в любую команду, включая `export`, всё равно попадает в историю оболочки, поэтому он читается с `read -s` выше. В CI установите его из хранилища секретов и отключите трассировку оболочки (`set -x`), иначе трассировка выведет его.

<Warning>
  `--connect <url>` регистрирует машину, которая **уже настроена**. Она возвращается сразу после успешной регистрации — она не устанавливает daemon и не подключает никакие hooks. Используйте простую `failproofai config` (или `failproofai config --token <key>`) на машине, которая ещё не настроена, или она будет отображаться как подключённая, пока она собирает и не обеспечивает ничего.
</Warning>

Запустите `failproofai` без аргументов, чтобы открыть панель управления локальными политиками.

| Команда | Результат |
| --- | --- |
| `failproofai config` | Настройте машину: агенты, daemon и Cloud — войдите через браузер, вставьте ключ или оставайтесь с открытым исходным кодом. Каждый агент на машине также получает небольшой навык `failproofai`, который указывает его на [FailproofAI skills](https://github.com/FailproofAI/skills) в сети |
| `failproofai config --token <key>` | Настройте и подключитесь одним проходом без вопросов. Ключ, содержащий `jev:evaluate`, также включает [Jev через FailproofAI Cloud](/ru/reference/jev-cloud) в режиме наблюдения, если только `jev.json` ещё не существует или не задан `--no-transcripts` |
| `failproofai config --connect <url>` | Зарегистрируйте машину, которая **уже** настроена — без daemon, без hooks |
| `failproofai config --status` | Показать состояние подключения, daemon, доставки и паузы |
| `failproofai policies` | Список встроенных, пользовательских, соглашений, пакетов и управляемых Cloud политик |
| `failproofai policies --install` | Подключите hooks в ваши CLI агентов. Не включает никакую политику самостоятельно |
| `failproofai policies add <name>` | Включить одну политику — встроенную или `<pack-id>:<name>` из установленного пакета |
| `failproofai policies remove <name>` | Отключить одну политику с тем же именованием |
| `failproofai policies --uninstall` | Отключить политики или удалить hooks обвязки |
| `failproofai policies show <owner>/<repo>` | Что содержит пакет, прочитано из его манифеста, прежде чем вы его возьмёте |
| `failproofai policies show <owner>/<repo> --releases` | Каждая версия, которую он опубликовал, и какая установлена здесь |
| `failproofai policies add <source>` | Установить пакет политик из выпуска GitHub; без тега берётся самый новый и он фиксируется |
| `failproofai publish` | Опубликуйте свои собственные политики как пакет; `--init` пишет один для начала, и `--min-cli-version <version>` устанавливает самый старый CLI, который может его установить ([Jev проверяет в пакете](/ru/policies/publish-a-pack#jev-checks-in-a-pack)) |
| `failproofai policies remove <publisher/name>` | Удалить пакет |
| `failproofai audit` | Сканировать локальную историю агента и открыть локальное представление аудита |
| `failproofai audit --schedule [days] --email <address>` | Запланировать повторяющиеся локальные сканирования и отправлять их выводы по электронной почте |
| `failproofai audit --status` | Показать адрес отчёта, интервал и следующее запланированное сканирование |
| `failproofai audit --no-schedule` | Остановить повторяющиеся сканирования без удаления истории аудита |
| `failproofai harness list` | Список дополнительных путей захвата |
| `failproofai otel status` | Проверить опциональное [отчётность OpenTelemetry](/ru/reference/otel) |
| `failproofai jev --url <url> --key-stdin` | Настроить Jev в один шаг; провайдер берётся из хоста URL |
| `failproofai jev setup --provider <kind> --key-stdin` | Позволить [Jev](/ru/reference/jev-providers) судить вызовы инструментов через вашу собственную конечную точку и ключ |
| `failproofai jev setup --provider failproofai` | Позволить Jev судить вызовы инструментов [через FailproofAI Cloud](/ru/reference/jev-cloud) с ключом Cloud этой машины |
| `failproofai jev setup --mode <m>` | Переключить режим Jev: `enforce`, `observe` или `off` (сохраняет конфигурацию, прекращает обращаться к Jev) |
| `failproofai jev status` | Показать конфигурацию Jev, её разрешения и недавние откаты; никогда не ключ |
| `failproofai jev test` | Отправить один живой запрос Jev и показать его задержку и версию; выходит с 1, когда ответ запоздал для hooks или неправильный |
| `failproofai jev models` | Список идентификаторов моделей, которые `GET <base>/models` говорит конечная точка, обслуживает |
| `failproofai jev remove` | Отключить Jev; hooks запускают политики regex точно как раньше |
| `failproofai flush --wait` | Доставить текущую очередь событий |
| `failproofai backfill --since 30d` | Перечитать ранее прошедшую историю |
| `failproofai config --pause [duration]` | Приостановить одну локальную сессию на 30 минут по умолчанию, до 8 часов |
| `failproofai config --resume` | Возобновить одну приостановленную локальную сессию; добавьте `--all` для очистки всех пауз |
| `failproofai update` | Завершить миграции пакетов и обновить daemon |
| `failproofai migrate --dry-run` | Просмотр или запуск ожидающих миграций домашней структуры |
| `failproofai uninstall` | Удалить hooks, навык `failproofai` и daemon перед удалением пакета |
| `failproofai --version` | Вывести установленную версию пакета |
| `failproofai --help` | Показать команды и глобальное использование |
| `failproofai help <command>` | Показать параметры и примеры одной команды, то же самое что `failproofai <command> --help` |

## Флаги конфигурации

| Флаг | Использование |
| --- | --- |
| `--token <key>` | Настроить и подключиться неинтерактивно; также читать из `FAILPROOFAI_CLOUD_TOKEN` |
| `--oss` | Использовать открытый исходный код без подключения Cloud; существующее подключение остаётся как оно есть |
| `--agents <a,b>` | Отследить этих агентов или `all` без вопросов |
| `--url <url>` | Подключиться куда-то ещё, кроме `app.befailproof.ai`; также читать из `FAILPROOFAI_CLOUD_URL` |
| `--connect <url>` | Только регистрация на уже настроенной машине. Пропускает daemon и каждый hook |
| `--machine-id <id>` | ID машины для `--connect`; по умолчанию стабильный ID |
| `--machine-label <name>` | Сам по себе переименовать машину, которая **уже подключена**; никогда не запускает настройку. С `--token` подключиться под этим именем; ключа, установленного только в `FAILPROOFAI_CLOUD_TOKEN`, недостаточно, потому что `--machine-label` без `--token` — это переименование. С `--oss` или `--agents` он переименовывает уже подключённую машину и отказывает перед настройкой на той, которая не подключена: `--oss` никогда не подключает, а `--agents` нужен ключ или интерактивный вход в Cloud для подключения |
| `--no-transcripts` | Отправить решения без содержимого расшифровки и не включать Cloud Jev, которая отправит каждый проверенный вызов инструмента и недавнюю подсказку; `jev.json`, оставленный запущенным Jev через FailproofAI Cloud, удаляется |
| `--disconnect` | Остановить извлечение политик Cloud и доставку событий. Также удаляет ключ Cloud Jev и `jev.json`, который называет FailproofAI Cloud; ваша собственная установка Jev остаётся на месте |
| `--status` | Показать текущее состояние машины |
| `--pause [duration]` | Приостановить новейшую сессию в текущей директории; принимает секунды, минуты или часы и по умолчанию 30 минут |
| `--resume` | Завершить подходящую паузу раньше |
| `--session <id>` | Целевая явная сессия для паузы или возобновления |
| `--all` | С `--resume` завершить все активные паузы |

Локальные паузы приостанавливают встроенные, пользовательские, соглашения и политики пакетов для одной сессии. Они всегда заканчиваются, максимум через 8 часов после первой паузы в запуске, и они не отключают управляемые Cloud политики или `block-failproofai-commands`, который всегда включён и не может сам быть отключённым или поставленным на паузу. Эта защита отказывает прямым способам, которыми инструментированный агент мог бы поставить себя на паузу: запустить `failproofai config --pause` или написать файл паузы под `~/.failproofai/state/sessions/`. Он читает команды, а не то, что делает скрипт при его запуске, поэтому скрипт, который агент пишет и затем запускает, может всё равно достичь того же состояния. Файл паузы проверяется на ограниченное истечение и начало не более чем на минуту в будущее, не на то, кто его написал.

## Флаги политики

| Флаг | Использование |
| --- | --- |
| `--install`, `-i` | Установить hooks обвязки. Имена после него включают эти политики; без них никаких изменений политики |
| `--uninstall`, `-u` | Отключить политики или удалить hooks |
| `--cli <names...>` | Целевые одна или более поддерживаемых обвязок |
| `--scope user\|project\|local\|all` | Выбрать область конфигурации; `all` для удаления |
| `--beta` | Включить бета политики |
| `--custom`, `-c <path>` | С `--install`, проверить и загрузить файл пользовательской политики; повторяемо. `--uninstall -c` удаляет каждый файл пользовательской политики |
| `--policy`, `--only <a,b>` | Установить только эти политики из пакета |
| `--category <x,y>` | Установить только эти категории из пакета |
| `--all` | Список каждой политики; с пакетом установить всё |
| `--releases` | С `show` список выпусков пакета и который установлен |

## Флаги доставки и обслуживания

| Команда | Флаги |
| --- | --- |
| `backfill` | `--since <30d\|6m\|1y\|YYYY-MM-DD>`, `--agents <a,b>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` (`-y`) |

### Backfill по обвязке

`backfill` повторно отправляет историю, которую сборщик уже прочитал, на машине, подключённой к Cloud. `--since` устанавливает окно для большинства обвязок, с двумя исключениями:

- **Goose, OpenCode и Devin** отправляют всю свою историю, независимо от того, что говорит `--since`: их история живёт в базе данных, которую сборщик читает без временного окна, поэтому `--dry-run` сообщает о них как о всех сессиях.
- **Hermes** история не повторно отправляется `backfill`.

`failproofai update` должен быть запущен после `npm install -g failproofai@latest`; он выполняет миграции домашней структуры, устанавливает соответствующий бинарный файл daemon и перезапускает сервис. Затем он перемещает каждый профиль Hermes, который уже использует FailproofAI, в связанный встроенный плагин и выводит одну строку за профиль. `--no-daemon` пропускает шаг daemon. `update` выходит с ненулевым кодом, когда daemon не может быть заменён, миграция не удалась или профиль Hermes не может быть перенесён (например, потому что запущенный daemon не может обслуживать встроенный плагин, в этом случае его hooks оболочки остаются на месте).

## Пути обвязки

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

Поддерживаемые имена обвязок: `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity` и `goose`.

Метки пространства имён производных ID агентов, когда два корня содержат копии одного и того же проекта. Перекрывающиеся корни и дублирующиеся метки отклоняются, чтобы предотвратить дублирование сбора или повреждение курсора. Конфигурация дополнительного пути перезагружается без перезагрузки daemon.

Контейнерные окружения могут заменить файловые конфигурационные дополнительные пути переменной, разделённой запятыми, с именем `FAILPROOFAI_<HARNESS>_EXTRA_PATHS`, например:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## Переменные окружения

Используйте файлы конфигурации для постоянного поведения машины. Переменные окружения наиболее полезны для контейнеров, тестов и одного процесса.

| Переменная | Использование |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | Ключ Cloud вместо `--token`. Предпочитайте это: аргумент читается из `ps` каждым пользователем. Установите его с `read -s` или из хранилища секретов CI, никогда не вводя ключ в команду, который всё равно попадает в историю оболочки |
| `FAILPROOFAI_CLOUD_URL` | URL Cloud вместо `--url`. То же самое переменная, которую читает daemon |
| `FAILPROOFAI_HOME` | Переместить полный макет `~/.failproofai` |
| `FAILPROOFAI_LOG_LEVEL` | Установить локальный уровень детализации логирования |
| `FAILPROOFAI_HOOK_LOG_FILE` | Написать диагностику hooks в выбранный файл |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | Отключить анонимную телеметрию для этого процесса |
| `FAILPROOFAI_NO_FIRST_RUN=1` | Пропустить интерактивную настройку при первом запуске |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | Пропустить локальный аудит после настройки |
| `FAILPROOFAI_LLM_BASE_URL` | Переопределить совместимую конечную точку OpenAI, используемую политиками LLM |
| `FAILPROOFAI_LLM_API_KEY` | Предоставить ключ API, используемый политиками LLM |
| `FAILPROOFAI_LLM_MODEL` | Выбрать модель, используемую политиками LLM |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | Ограничить загрузку модуля пользовательской политики |
| `FAILPROOFAI_NO_DOWNLOAD=1` | Отказать в загрузке пакетов и бинарных файлов daemon; то, что установлено, продолжает обеспечивать |
| `FAILPROOFAI_PACK_BASE_URL` | Загрузить пакеты с зеркала вместо `github.com` |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | Заменить сконфигурированные дополнительные пути захвата для одной обвязки |
| `NO_COLOR` | Отключить цветной вывод терминала |

Переменные домашней директории, специфичные для агента, такие как `CLAUDE_PROJECTS_PATH`, `CURSOR_HOME`, `HERMES_HOME` и `OPENCLAW_HOME`, переопределяют то, где Failproof AI обнаруживает локальные сессии для этой обвязки.

## Безопасно приостановить или удалить машину

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

Локальная пауза сессии не отключает управляемые Cloud политики. Восстановите развёртывания Cloud из **fix → deploy policies** в Cloud, когда сам rollout — это проблема.

Перед удалением пакета npm удалите установленные hooks и daemon:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

Запустите `failproofai <command> --help` для подробностей, специфичных для версии.

<Warning>
  Запустите `failproofai uninstall` перед `npm rm -g failproofai`; npm не удаляет установленные hooks агента, навык `failproofai` или сервис daemon.
</Warning>
