Установите локальный CLI с помощью `npm install -g failproofai`. Запустите его без аргументов, чтобы открыть локальную панель управления политиками.

Пакет требует Node.js 20.9 или новее. Bun 1.3 или новее поддерживается для разработки и установки из исходников. `failproofai configure` и `failproofai setup` — это псевдонимы для `failproofai config`. `failproofai policy`, `failproofai pack` и `failproofai p` — все это варианты написания `failproofai policies` — пакеты и отдельные политики раньше были тремя командами для одной идеи, а теперь это одна команда. Старые варианты всё ещё работают, с двумя исключениями: `pack list <source>` теперь это `policies show <source>`, а `pack build` — это `publish`.

## Настройка машины

Установите CLI, затем прочитайте ключ машины в оболочку. `read -s` получает его в приглашении, которое не выводится на экран, поэтому оно никогда не появляется в команде:

```bash
npm install -g failproofai
read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
```

Затем настройте машину и выберите, что она будет применять:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

`failproofai config` — это вся настройка: она устанавливает службу `failproofaid` (один раз от root — в терминале она запрашивает ваш пароль sudo и спрашивает снова, если он истёк до завершения настройки; без терминала использует `sudo -n` и никогда не запрашивает пароль), подключает хуки к каждому найденному agent CLI и подключается к Cloud. Без терминала — в CI, контейнере, когда его запускает агент — применяет вместо вопроса и выходит с кодом 1, если что-то из запрошенного не произошло.

В терминале этап **Connect to cloud** на машине, которая ещё не подключена, сразу же начинает **logging in to FailproofAI Cloud**; нажмите Tab для других опций — **Paste an API key** или **Use open source**. Вход открывает ссылку — или выводит её через SSH или без дисплея, чтобы открыть на любом устройстве — где вы регистрируетесь или входите, выбираете или создаёте организацию и авторизуете машину; терминал самостоятельно подхватывает одобрение и показывает, кто его дал и для какой организации. Ключ создаётся только после завершения настройки, после установки демона. На машине, которая уже подключена с работающим ключом, этап — это меню с **Keep current connection** на первом месте, поэтому повторный запуск настройки никогда не открывает браузер автоматически; сохранённый ключ, который больше не работает, снова сразу же начинает вход и объясняет почему. Повторный вход создаёт новый ключ и оставляет старый рабочим, пока вы его не отозовёте. Cloud более старой версии говорит об этом и предлагает другие опции.

По умолчанию выбирается **no** политик. Это работа второй команды, и без неё только что настроенная машина не применяет ничего, кроме всегда включённой защиты.

Предпочитайте переменную окружения вместо `--token`: аргумент командной строки читается из `ps` каждым пользователем на машине. Это всё, что защищает переменная — ключ, напечатанный в любой команде, включая `export`, всё равно попадёт в историю оболочки, поэтому он читается с помощью `read -s` выше. В CI установите его из хранилища секретов и держите трассировку оболочки (`set -x`) отключённой, иначе трассировка выведет его.

<Warning>
  `--connect <url>` регистрирует машину, которая **уже настроена**. Она возвращается, как только регистрация успешна — она не устанавливает демон и не подключает никакие хуки. Используйте простой `failproofai config` (или `failproofai config --token <key>`) на машине, которая ещё не настроена, иначе она будет выглядеть подключённой, но не будет ничего собирать и применять.
</Warning>

Запустите `failproofai` без аргументов, чтобы открыть локальную панель управления политиками.

| Команда | Результат |
| --- | --- |
| `failproofai config` | Настроить машину: агенты, демон и Cloud — вход через браузер, вставить ключ или остаться на open source. Каждый агент на машине также получает небольшой скилл `failproofai`, который указывает на [FailproofAI skills](https://github.com/FailproofAI/skills) в интернете |
| `failproofai config --token <key>` | Настроить и подключиться за один раз, ничего не спрашивая. Ключ с `jev:evaluate` также включает [Jev through FailproofAI Cloud](/ru/reference/jev-cloud) в режиме наблюдения, если только `jev.json` не существует или не задан `--no-transcripts` |
| `failproofai config --connect <url>` | Зарегистрировать машину, которая **уже** настроена — без демона, без хуков |
| `failproofai config --status` | Показать состояние подключения, демона, доставки и паузы |
| `failproofai policies` | Список встроенных, пользовательских, конвенционных, пакетных политик и управляемых Cloud политик |
| `failproofai policies --install` | Подключить хуки к вашим agent CLI. На своём уровне не включает никакую политику |
| `failproofai policies add <name>` | Включить одну политику — встроенную или `<pack-id>:<name>` из установленного пакета |
| `failproofai policies remove <name>` | Отключить одну политику, тот же способ именования |
| `failproofai policies --uninstall` | Отключить политики или удалить хуки инструмента |
| `failproofai policies show <owner>/<repo>` | Что содержит пакет, прочитано из его манифеста, перед тем как вы его возьмёте |
| `failproofai policies show <owner>/<repo> --releases` | Каждая версия, которую он опубликовал, и какая из них здесь |
| `failproofai policies add <source>` | Установить пакет политик из выпуска GitHub; без тега берётся новейший и закрепляется |
| `failproofai publish` | Отправить свои политики как пакет; `--init` пишет один для начала, а `--min-cli-version <version>` устанавливает самый старый CLI, который может его установить ([Jev checks in a pack](/ru/policies/publish-a-pack#jev-checks-in-a-pack)) |
| `failproofai policies remove <publisher/name>` | Удалить пакет |
| `failproofai audit` | Сканировать локальную историю агента и открыть локальное представление аудита |
| `failproofai audit --schedule [days] --email <address>` | Запланировать повторяющиеся локальные сканы и отправить их результаты по почте |
| `failproofai audit --status` | Показать адрес отчёта, интервал и следующее запланированное сканирование |
| `failproofai audit --no-schedule` | Остановить повторяющиеся сканы без удаления истории аудита |
| `failproofai harness list` | Список дополнительных путей захвата |
| `failproofai otel status` | Проверить опциональное [OpenTelemetry reporting](/ru/reference/otel) |
| `failproofai jev --url <url> --key-stdin` | Настроить Jev за один шаг; провайдер берётся из хоста URL |
| `failproofai jev setup --provider <kind> --key-stdin` | Позволить [Jev](/ru/reference/jev-providers) оценивать вызовы инструментов через вашу конечную точку и ключ |
| `failproofai jev setup --provider failproofai` | Позволить Jev оценивать вызовы инструментов [through FailproofAI Cloud](/ru/reference/jev-cloud), с облачным ключом этой машины |
| `failproofai jev setup --mode <m>` | Переключить режим Jev: `enforce`, `observe` или `off` (сохраняет конфигурацию, перестаёт спрашивать Jev) |
| `failproofai jev status` | Показать конфигурацию Jev, его разрешения и недавние резервные варианты; никогда ключ |
| `failproofai jev test` | Отправить один реальный запрос Jev и показать его задержку и версию; выходит с 1, когда ответ опаздывает для хуков или неправильный |
| `failproofai jev models` | Список ID моделей, которые `GET <base>/models` говорит, что конечная точка обслуживает |
| `failproofai jev remove` | Отключить Jev; хуки запускают политики регулярных выражений точно как раньше |
| `failproofai flush --wait` | Доставить текущую очередь событий |
| `failproofai backfill --since 30d` | Перечитать ранее пройденную историю |
| `failproofai config --pause [duration]` | Приостановить одну локальную сессию на 30 минут по умолчанию, до 8 часов |
| `failproofai config --resume` | Возобновить одну приостановленную локальную сессию; добавьте `--all` для очистки всех пауз |
| `failproofai update` | Завершить миграции пакетов и обновить демон |
| `failproofai migrate --dry-run` | Просмотреть или запустить ожидающие миграции макета home |
| `failproofai uninstall` | Удалить хуки, скилл `failproofai` и демон перед удалением пакета |
| `failproofai --version` | Вывести установленную версию пакета |
| `failproofai --help` | Показать команды и глобальное использование |

## Флаги конфигурации

| Флаг | Использование |
| --- | --- |
| `--token <key>` | Настроить и подключиться неинтерактивно; также читает из `FAILPROOFAI_CLOUD_TOKEN` |
| `--url <url>` | Подключиться куда-то кроме `app.befailproof.ai`; также читает из `FAILPROOFAI_CLOUD_URL` |
| `--connect <url>` | Только регистрация на уже настроенной машине. Пропускает демон и каждый хук |
| `--machine-id <id>` | Установить стабильный ID машины |
| `--machine-label <name>` | Переименовать машину, которая **уже подключена**. Сама по себе никогда не запускает настройку, поэтому задайте её после `failproofai config`, не во время |
| `--no-transcripts` | Отправлять решения без содержимого расшифровки и не включать Cloud Jev, который отправляет каждый проверенный вызов инструмента и недавний запрос; удаляется `jev.json`, который запускает Jev через FailproofAI Cloud |
| `--disconnect` | Остановить загрузки политик Cloud и доставку событий. Также удаляет ключ Cloud Jev и `jev.json`, который указывает на FailproofAI Cloud; ваша собственная настройка Jev остаётся нетронутой |
| `--status` | Показать текущее состояние машины |
| `--pause [duration]` | Приостановить новейшую сессию в текущем каталоге; принимает секунды, минуты или часы и по умолчанию 30 минут |
| `--resume` | Завершить совпадающую паузу раньше |
| `--session <id>` | Выбрать явную сессию для паузы или возобновления |
| `--all` | С `--resume` завершить каждую активную паузу |

Локальные паузы приостанавливают встроенные, пользовательские, конвенционные и пакетные политики для одной сессии. Они всегда истекают и не отключают управляемые Cloud политики. `block-failproofai-commands` — который всегда включён и не может быть отключён или приостановлен сам — предотвращает использование инструментальным агентом этого лазейки.

## Флаги политик

| Флаг | Использование |
| --- | --- |
| `--install`, `-i` | Установить хуки инструмента. Имена после него включают эти политики; без них, никакие изменения политик |
| `--uninstall`, `-u` | Отключить политики или удалить хуки |
| `--cli <names...>` | Выбрать один или несколько поддерживаемых инструментов |
| `--scope user\|project\|local\|all` | Выбрать область конфигурации; `all` для удаления |
| `--beta` | Включить бета-политики |
| `--custom`, `-c <path>` | Проверить и загрузить пользовательский файл политики; повторяемо |

## Флаги доставки и обслуживания

| Команда | Флаги |
| --- | --- |
| `backfill` | `--since <30d\|6m\|YYYY-MM-DD>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` |

`failproofai update` следует запускать после `npm install -g failproofai@latest`; она выполняет миграции макета home, устанавливает соответствующий двоичный файл демона и перезапускает службу. Затем она перемещает каждый профиль Hermes, который уже использует FailproofAI в связанный встроенный плагин и выводит одну строку на профиль. `--no-daemon` пропускает этап демона. `update` выходит с ненулевым кодом, когда демон не может быть заменён, миграция не удалась или профиль Hermes не может быть перенесён (например, потому что запущенный демон не может служить встроенным плагином, в этом случае его хуки оболочки остаются на месте).

## Пути инструментов

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

Поддерживаемые имена инструментов — `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity` и `goose`.

Метки пространства имён производных ID агентов, когда два корневых каталога содержат копии одного проекта. Перекрывающиеся корневые каталоги и дублирующиеся метки отклоняются, чтобы предотвратить дублирование сбора или повреждение курсора. Конфигурация дополнительного пути перезагружается без перезапуска демона.

Окружение контейнера может заменить сконфигурированные в файле дополнительные пути переменной с разделением запятыми с именем `FAILPROOFAI_<HARNESS>_EXTRA_PATHS`, например:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## Переменные окружения

Используйте файлы конфигурации для постоянного поведения машины. Переменные окружения наиболее полезны для контейнеров, тестов и одного процесса.

| Переменная | Использование |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | Облачный ключ, вместо `--token`. Предпочитайте это: аргумент читается из `ps` каждым пользователем. Установите его с помощью `read -s` или из хранилища CI секретов, никогда не печатая ключ в команду, что попадёт в историю оболочки в любом случае |
| `FAILPROOFAI_CLOUD_URL` | Облачный URL, вместо `--url`. Та же переменная, которую читает демон |
| `FAILPROOFAI_HOME` | Переместить полный макет `~/.failproofai` |
| `FAILPROOFAI_LOG_LEVEL` | Установить уровень локального логирования |
| `FAILPROOFAI_HOOK_LOG_FILE` | Написать диагностику хуков в выбранный файл |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | Отключить анонимную телеметрию для этого процесса |
| `FAILPROOFAI_NO_FIRST_RUN=1` | Пропустить интерактивную первоначальную настройку |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | Пропустить локальный аудит после установки |
| `FAILPROOFAI_LLM_BASE_URL` | Переопределить конечную точку, совместимую с OpenAI, используемую политиками LLM |
| `FAILPROOFAI_LLM_API_KEY` | Предоставить ключ API, используемый политиками LLM |
| `FAILPROOFAI_LLM_MODEL` | Выбрать модель, используемую политиками LLM |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | Ограничить загрузку модуля пользовательской политики |
| `FAILPROOFAI_NO_DOWNLOAD=1` | Отказать в получении пакетов и двоичных файлов демона; что установлено, продолжает применяться |
| `FAILPROOFAI_PACK_BASE_URL` | Получать пакеты из зеркала вместо `github.com` |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | Заменить сконфигурированные дополнительные пути захвата для одного инструмента |
| `NO_COLOR` | Отключить цветной вывод терминала |

Переменные home, специфичные для агента, такие как `CLAUDE_PROJECTS_PATH`, `CURSOR_HOME`, `HERMES_HOME` и `OPENCLAW_HOME` переопределяют, где Failproof AI обнаруживает локальные сессии для этого инструмента.

## Безопасная паузирование или удаление машины

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

Локальная пауза сессии не отключает управляемые Cloud политики. Восстановите развёртывания Cloud через рабочий процесс применения Cloud, когда сам выпуск — это проблема.

Перед удалением npm пакета удалите установленные хуки и демон:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

Запустите `failproofai <command> --help` для деталей, специфичных для версии.

<Warning>
  Запустите `failproofai uninstall` перед `npm rm -g failproofai`; npm не удаляет установленные хуки агента, скилл `failproofai` или службу демона.
</Warning>
