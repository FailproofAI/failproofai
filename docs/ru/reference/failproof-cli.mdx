Установите с помощью `npm install -g failproofai`. Запустите `failproofai` без аргументов, чтобы открыть локальный панель управления.

## Основные команды

| Команда | Что она делает |
| --- | --- |
| `failproofai config` | Настройте агентов, фоновый сервис и дополнительное подключение к облаку |
| `failproofai config --token <key>` | Настройка и подключение без вопросов |
| `failproofai config --status` | Показать статус подключения, версию сервиса и состояние паузы |
| `failproofai policies` | Список политик и их статус включения |
| `failproofai policies add <name>` | Включить одну политику |
| `failproofai policies add <owner>/<repo>` | Установить пакет политик |
| `failproofai policies remove <name-or-pack>` | Отключить политику или удалить пакет |
| `failproofai policies show <owner>/<repo>` | Проверить пакет перед установкой |
| `failproofai publish` | Опубликовать ваши политики как пакет |
| `failproofai audit` | Сканировать локальную историю агента |
| `failproofai harness` | Управление дополнительными местоположениями сеансов |
| `failproofai flush` | Отправить очередные события немедленно |
| `failproofai backfill` | Перечитать более старую историю агента |
| `failproofai update` | Завершить обновление npm и обновить сервис |
| `failproofai uninstall` | Удалить хуки и сервис |

`policy`, `pack` и `p` также являются допустимыми сокращениями для `policies`, но документация использует `policies`.

## Настройка машины

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

Во время установки пакет политик не выбирается. Пока вы его не добавите, работает только `block-failproofai-commands`.

Для автоматизированной настройки облака:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Чтобы отправлять решения без записей транскриптов, сначала подключитесь и установите `collector.sessions` на `false` в `~/.failproofai/config.json`. Текущий флаг `--no-transcripts` при установке анализируется, но не применяет этот параметр.

Используйте `--machine-label <name>` после подключения машины, чтобы переименовать её. `--connect <url>` — это более узкая команда только для регистрации машины, уже настроенной.

## Политики и пакеты

```bash
failproofai policies
failproofai policies add block-sudo
failproofai policies show owner/repo
failproofai policies add owner/repo --category git,database
failproofai policies remove owner/repo
```

Всё со слэшем — это источник пакета; всё без слэша — это имя политики.

Полезные флаги выбора пакета:

| Флаг | Использование |
| --- | --- |
| `--policy a,b` | Выбрать именованные политики |
| `--category x,y` | Выбрать категории |
| `--all` | Выбрать всё |
| `--cli <agents...>` | Ограничить именованными harness |

Используйте `failproofai policies -i -c <path>` для загрузки пользовательской политики из любого пути. Файлы соглашений с именами `*policies.{js,mjs,ts}` в `.failproofai/policies/` загружаются автоматически.

## Пауза в принудительном применении

```bash
failproofai config --pause 10m
failproofai config --status
failproofai config --resume
```

Пауза применяется к одному локальному сеансу и всегда истекает. Она не паузирует облачные политики или `block-failproofai-commands`.

## Аудит и доставка

```bash
failproofai audit
failproofai audit --schedule 7 --email team@example.com
failproofai audit --status
failproofai flush --wait
failproofai backfill --since 30d --dry-run
```

`backfill` читает `~/.failproofai/config.json`. Удалите `--dry-run`, чтобы отправить историю снова.

## Дополнительные местоположения сеансов

```bash
failproofai harness list
failproofai harness add-path claude work=/srv/team/.claude/projects
failproofai harness remove-path claude work
```

Метки предотвращают объединение сеансов из двух скопированных домов под одним выведенным ID агента.

Поддерживаемые harness: `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity` и `goose`. Поддержка области действия различается; см. [Harnesses](/ru/reference/harnesses).

## Полезные переменные окружения

| Переменная | Использование |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | Облачный ключ машины |
| `FAILPROOFAI_CLOUD_URL` | Переопределить URL облака |
| `FAILPROOFAI_HOME` | Перемещение локального каталога состояния |
| `FAILPROOFAI_NO_DOWNLOAD=1` | Отказать в загрузке пакетов и сервиса |
| `FAILPROOFAI_DAEMON_BASE_URL` | Использовать зеркало бинарного файла сервиса |
| `FAILPROOFAI_PACK_BASE_URL` | Использовать зеркало пакетов |
| `FAILPROOFAI_NO_FIRST_RUN=1` | Отключить подсказки при первом запуске |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | Отключить анонимную телеметрию CLI |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | Заменить дополнительные пути для одного harness |
| `NO_COLOR` | Отключить цвет терминала |

## Удаление или обновление

```bash
npm install -g failproofai@latest
failproofai update
```

Перед удалением пакета:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

<Warning>
  Запустите `failproofai uninstall` перед удалением npm пакета. npm не удаляет установленные хуки и фоновый сервис.
</Warning>

Запустите `failproofai help <command>` для просмотра полного набора опций в вашей установленной версии.
