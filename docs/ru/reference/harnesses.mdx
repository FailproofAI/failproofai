Адаптер — это окружение, в котором фактически работает ваш агент. Failproof AI поддерживает двенадцать адаптеров, разделённых на два класса:

- **Coding CLIs** (10) — Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Factory Droid, Devin CLI, Antigravity CLI, Goose
- **Шлюзы чата и ассистентов** (2) — Hermes (Slack, Telegram, cron), OpenClaw (самостоятельно размещённый ассистент)

Одни и те же политики и одна и та же история сессий применяются независимо от того, в каком адаптере работает агент. Один слой адаптера преобразует названия событий, инструменты и поля входных данных каждого адаптера в 29 канонических событий перед выполнением любой политики.

Агент, работающий **ни в одном** из этих двенадцати адаптеров, инструментируется непосредственно с помощью [Python SDK](/ru/reference/custom-agents). Это другой контракт, и стоит сказать об этом ясно: SDK обеспечивает трассировку, сессии, оценки и аудиты — **он не применяет политики самостоятельно.** Блокировка небезопасного действия перед его выполнением требует hook-а принудительного выполнения на границе инструментов вашего runtime; [свяжитесь с нами](mailto:support@befailproof.ai) и мы это реализуем.

## Области действия hook-ов

| Адаптер | Поддерживаемые области действия hook-ов |
| --- | --- |
| Claude Code | User, project, local |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | User, project |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | User, project |
| Hermes, OpenClaw | User |

Claude Code — единственный адаптер с областью действия **local**. Hermes и OpenClaw не имеют конфигурации проекта вообще — они работают только с областью действия user, и CLI отклоняет `--scope project` для них.

Каждая интеграция нормализует названия событий hook-ов, инструменты и поля входных данных перед выполнением политик. Политика может работать только с событиями, которые предоставляет адаптер; тестируйте поведение end-of-turn и инструкции на точном адаптере и версии, которые вы развёртываете.

## Возможность принудительного выполнения

«Block» означает, что вердикт, возвращённый текущим адаптером, используется названным адаптером. Post-tool блокирование может заменить результат, показанный модели, но не может отменить побочный эффект инструмента, который уже произошёл.

| Адаптер | События проверенной блокировки | Наблюдение или отсутствие блокировки |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact` и несколько событий задач/конфигурации | `PostToolUse`, жизненный цикл сессии, уведомления и события после отказа — только для наблюдения. |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | Post-tool блокирование заменяет результат после выполнения; события start сессии и компактации — только для наблюдения в текущем адаптере. |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | Post-tool блокирование заменяет результат после выполнения; события сессии и уведомлений — только для наблюдения. |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` и события сессии — только для наблюдения. |
| OpenCode | `PreToolUse` | Post-tool и события жизненного цикла — только для наблюдения; текущая обработка stop — это указание для следующего хода, а не проверенные ворота. `PermissionRequest` никогда не выполняется вообще. |
| Pi | `PreToolUse`, `UserPromptSubmit` | Post-tool и события жизненного цикла — только для наблюдения; указание stop применяется к следующему ходу. |
| Hermes | `PreToolUse` | Post-tool, сессия и вердикты subagent-stop — не являются вратами. Событие `Stop` не установлено. |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | Post-tool, сессия, subagent-stop и события компактации — только для наблюдения. |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | Post-tool и вердикты subagent-stop — только для наблюдения. |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, условное `PermissionRequest` | Permission hook-и не выполняются в каждом режиме разрешений; post-tool и события сессии — только для наблюдения. |
| Antigravity CLI | `PreToolUse`, `Stop` | Вердикты user-prompt и post-tool — только для наблюдения; инструкции prompt всё ещё могут быть внедрены. |
| Goose | `PreToolUse` | События user-prompt, post-tool и сессии — только для наблюдения. Существует собственный hook stop блокирования выше по цепочке, но не установлен текущим адаптером. |

Событие, отсутствующее в обоих столбцах, **не проверено** — рассматривайте его как неизвестное, никогда не как блокирующее.

### Условия на перечисленных вратах

Несколько строк выше — это реальные враты, которые тем не менее ограничены или условны. Политика, зависящая от одного из них, нуждается в условии столько же, сколько в строке.

| Адаптер | Событие | Условие |
| --- | --- | --- |
| Claude Code | `Stop`, `SubagentStop` | Ограничено переменной `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`, по умолчанию 8. Отклоняется на путях end-turn |
| Cursor | `Stop` | Ограничено `loop_limit`, по умолчанию 5, и используется только при завершении хода — отмена пользователя или ошибка хода отклоняют его |
| Cursor | `Stop` | **Cursor Cloud Agent VMs вообще не выполняют hook-и `stop` или `subagentStop`.** Ворота покрывают только локальные сессии |
| Codex | `SubagentStop` | Только ThreadSpawn subagents отправляют это; любой другой источник subagent никогда не выполняет hook |
| GitHub Copilot CLI | `SubagentStop` | Полностью пропускается для `isSidekick` subagents |
| Devin CLI | `PermissionRequest` | Никогда не срабатывает под `--permission-mode dangerous` и никогда для автоматически утверждённых read-only инструментов |
| OpenCode | `PermissionRequest` | Неработающий hook: `permission.ask` объявлен и документирован выше по цепочке, но никогда не вызывается, поэтому политика вообще не выполняется |
| Hermes | `Stop` | Событие `Stop` не установлено по выбору. Пять встроенных `require-*-before-stop` неприменимы на Hermes |
| Goose | `Stop` | Тот же результат: `Stop` не установлен, поэтому пять встроенных `require-*-before-stop` неприменимы |

### Где `instruct()` снижается

`deny` — это не единственный вердикт, который возвращает политика. `instruct()` отправляет агенту директиву и позволяет действию продолжиться — но не все адаптеры имеют канал для её передачи. Если канала нет, failproofai разрешает действие и записывает инструкцию в stderr для логов оператора; модель никогда не видит её.

| Адаптер | События, где `instruct()` снижается до заметки в stderr |
| --- | --- |
| Hermes | Все события |
| Goose | Все события |
| Pi | Все события кроме `Stop` |
| OpenClaw | Все события кроме `Stop` |
| Factory Droid | Все события кроме `Stop` |
| Antigravity CLI | Все события кроме `Stop` и `UserPromptSubmit` |

Везде ещё инструкция возвращается через собственный канал дополнительного контекста адаптера.

## Режим агента VS Code

**Встроенный режим агента Copilot Chat в VS Code — это не тринадцатая интеграция.** Он обнаруживает конфигурацию hook-а из `.github/hooks/*.json`, `~/.copilot/hooks/*.json` и `~/.claude/settings.json` — точно из путей, которые установки `copilot` и `claude` уже записывают — и использует тот же Claude-подобный контракт deny. Установка одного из них уже применяет принудительное выполнение в сессиях режима агента VS Code.

Функция находится в режиме предпросмотра и требует активную подписку GitHub Copilot плюс режим агента.

## Установка захвата и policy hook-ов

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Administration → Keys** и создайте ключ с разрешениями `events:add` и `policies:pull`, назовите его для машины или окружения.
    2. На целевой машине подключите локальный CLI отображённым ключом.
    3. Запустите новую сессию агента, затем подтвердите её hook и события сессии в **Observe → Events**.
    4. Откройте **Observe → policy** для того же временного окна и подтвердите, что решение политики отнесено к машине.

    Соединение начинается с ключа машины. Подтвердите, что он включает как разрешения на приём, так и доставку политик перед копированием его секрета.

    ![Живой поток Events, используемый для подтверждения того, что недавно установленный адаптер сообщает о себе.](/images/dashboard/events-stream.png)

    Наконец, проверьте, что решения политики отнесены к той же машине. Это подтверждает, что адаптер сообщает как об активности политики, так и о событиях трассировки.

    ![Страница Policy, используемая для проверки решений политики с недавно подключённого адаптера.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    `failproofai config` подключает hook-и во все поддерживаемые CLI агентов, которые он находит, устанавливает daemon и подключает Cloud при наличии ключа:

    ```bash
    failproofai config --token <machine-key>
    failproofai policies add FailproofAI/policies
    ```

    Установка не выбирает политики, поэтому вторая команда есть.

    Чтобы подключить один адаптер вручную — с пропущенным `--install`, обнаруживает установленное и предлагает:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    Область Project хранит конфигурацию hook-а с репозиторием. Область User охватывает работу во всех репозиториях. Проверьте таблицу области выше перед объединением `--cli` и `--scope`; CLI отклоняет неподдерживаемую пару.

    Проверьте машину и её события:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

<Warning>
  В headless `copilot -p` запусках, начинающихся из свежего каталога, project-scope `.github/hooks/failproofai.json` **не** загружался. Рассматривайте область User как надёжную точку применения для Copilot в CI до тех пор, пока это не будет проверено иначе.
</Warning>

## Добавить non-default путь сессии

<Tabs>
  <Tab title="Dashboard">
    Дополнительные пути регистрируются на машине, а не в Cloud. После добавления одного, откройте **Observe → Sessions**, отфильтруйте по окружению машины и подтвердите, что сессии из нового пути появляются. Откройте сессию и проверьте агента, адаптер и временные метки событий перед использованием в аудите.

    ![Список Sessions, отфильтрованный по окружению, получающему данные из дополнительного пути захвата.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    Добавьте путь с дополнительной меткой, затем осмотрите настроенные пути:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    Удалите путь с `failproofai harness remove-path claude checkout`.

    Метка нормализует производные идентификаторы агентов. Два расположения, содержащие копии одного проекта, выводят один и тот же идентификатор из трансляции, поэтому без метки они объединяются в один агент. Перекрывающиеся корни и дублирующиеся метки отклоняются — см. [справку по CLI](/ru/reference/failproof-cli) для информации о том, почему каждый отказ существует.
  </Tab>
</Tabs>

<Tip>
  Запустите одну новую сессию после установки. Проверьте как живой поток событий, так и фактическое решение политики перед расширением развёртывания.
</Tip>
