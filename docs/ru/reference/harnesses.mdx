Адаптер — это среда, в которой фактически работает ваш агент. Failproof AI поддерживает двенадцать адаптеров, разделённых на два класса:

- **Coding CLIs** (10) — Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Factory Droid, Devin CLI, Antigravity CLI, Goose
- **Шлюзы чата и ассистентов** (2) — Hermes (Slack, Telegram, cron), OpenClaw (самостоятельно развёрнутый ассистент)

Одни и те же политики и одна и та же история сессий применяются независимо от того, в каком адаптере работает агент. Один слой адаптера преобразует собственные имена событий каждого адаптера, имена инструментов и поля входных данных инструментов в 29 канонических событий перед выполнением любой политики.

Агент, работающий **ни в одном из** двенадцати адаптеров, инструментируется непосредственно с помощью [Python SDK](/ru/reference/python-sdk). Это другой контракт, и стоит сказать ясно: SDK обеспечивает трассировку, сессии, оценки и аудиты — **он не применяет политики самостоятельно.** Блокировка небезопасного действия перед его выполнением требует перехвата применения в границе инструмента вашего времени выполнения; [свяжитесь с нами](mailto:support@befailproof.ai) и мы это реализуем.

| Адаптер | Поддерживаемые области перехвата |
| --- | --- |
| Claude Code | User, project, local |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | User, project |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | User, project |
| Hermes, OpenClaw | User |

Каждая интеграция нормализует собственные имена событий перехвата, имена инструментов и поля входных данных инструментов перед выполнением политик. Политика может действовать только на события, которые предоставляет адаптер; проверьте поведение конца хода и инструкции на точном адаптере и версии, которые вы развёртываете.

## Возможность применения

«Block» означает, что решение, возвращённое текущим адаптером, принимается названным адаптером. Блокировка после инструмента может заменить результат, показанный модели, но не может отменить побочный эффект инструмента, который уже произошёл.

| Адаптер | Проверенные события блокировки | Замечания только для наблюдения или без блокировки |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact` и несколько событий задачи/конфигурации | `PostToolUse`, жизненный цикл сессии, уведомления и события после ошибки доступны только для наблюдения. |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | Блокировка после инструмента заменяет результат после выполнения; события начала сессии и уплотнения доступны только для наблюдения в текущем адаптере. |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | Блокировка после инструмента заменяет результат после выполнения; события сессии и уведомления доступны только для наблюдения. |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` и события сессии доступны только для наблюдения. |
| OpenCode | `PreToolUse` | События после инструмента и жизненного цикла доступны только для наблюдения; текущая обработка остановки — это рекомендация для последующего хода, а не проверенный шлюз. |
| Pi | `PreToolUse`, `UserPromptSubmit` | События после инструмента и жизненного цикла доступны только для наблюдения; рекомендация остановки применяется к последующему ходу. |
| Hermes | `PreToolUse` | Решения после инструмента, сессии и остановки субагента не являются шлюзами. |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | События после инструмента, сессии, остановки субагента и уплотнения доступны только для наблюдения. |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | Решения после инструмента и остановки субагента доступны только для наблюдения. |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, условный `PermissionRequest` | Перехваты разрешений работают не во всех режимах разрешения; события после инструмента и сессии доступны только для наблюдения. |
| Antigravity CLI | `PreToolUse`, `Stop` | Решения по запросу пользователя и после инструмента доступны только для наблюдения; инструкции подсказок всё ещё можно внедрить. |
| Goose | `PreToolUse` | События запроса пользователя, после инструмента и сессии доступны только для наблюдения. Существует собственный перехват блокировки остановки выше по потоку, но он не установлен текущим адаптером. |

Возможности зависят от версии. Перепроверьте после обновления CLI агента, особенно если политика полагается на поведение подсказки, остановки, разрешения или после инструмента, а не на обычный шлюз перед инструментом.

## Установка перехватов захвата и политик

<Tabs>
  <Tab title="Панель управления">
    1. Откройте **Administration → Keys** и создайте ключ с правами `events:add` и `policies:pull`, назвав его по имени машины или окружения.
    2. На целевой машине подключите локальный CLI с отображённым ключом и установите перехваты адаптера.
    3. Запустите новую сессию агента, а затем подтвердите события перехвата и сессии в разделе **Observe → Events**.
    4. Откройте **Observe → policy** для того же временного окна и подтвердите, что решение политики атрибутировано машине.

    Соединение начинается с ключа машины. Убедитесь, что он включает оба разрешения на приём и доставку политик перед копированием его секрета.

    ![Ящик нового ключа API, используемый для предоставления разрешений на приём событий и доставку политик.](/images/dashboard/key-create.png)

    После установки перехватов поток событий должен показать новые события от машины и окружения, которые вы подключили.

    ![Живой поток событий, используемый для подтверждения того, что вновь установленный адаптер сообщает данные.](/images/dashboard/events-stream.png)

    Наконец, убедитесь, что решения политик атрибутируются той же машине. Это подтверждает, что адаптер сообщает как о деятельности политик, так и о событиях трассировки.

    ![Страница политики, используемая для проверки решений политик от вновь подключённого адаптера.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    Установите перехваты для каждого обнаруженного адаптера:

    ```bash
    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>
    failproofai policies --install
    ```

    Или выберите именованные адаптеры и область конфигурации:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    Область проекта хранит конфигурацию перехвата в репозитории. Область пользователя охватывает работу между репозиториями. Claude Code также поддерживает локальную область; поддержка варьируется по адаптерам и CLI отклоняет неподдерживаемые комбинации.

    Проверьте машину и её события:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## Добавьте нестандартный путь сессии

<Tabs>
  <Tab title="Панель управления">
    Дополнительные пути регистрируются на машине, а не в облаке. После добавления откройте **Observe → Sessions**, отфильтруйте по окружению машины и подтвердите, что сессии с нового пути появляются. Откройте сессию и проверьте агента, адаптер и временные метки событий перед использованием в аудите.

    ![Список сессий, отфильтрованный по окружению, получающему данные из дополнительного пути захвата.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    Добавьте путь с необязательной меткой, затем проверьте настроенные пути:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    Удалите путь с помощью `failproofai harness remove-path claude checkout`.
  </Tab>
</Tabs>

<Tip>
  Запустите одну новую сессию после установки. Проверьте как живой поток событий, так и актуальное решение политики перед расширением развёртывания.
</Tip>
