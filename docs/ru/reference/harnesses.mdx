Failproof AI поддерживает Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Hermes, OpenClaw, Factory Droid, Devin CLI, Antigravity CLI и Goose.

| Адаптер | Поддерживаемые области хуков |
| --- | --- |
| Claude Code | User, project, local |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | User, project |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | User, project |
| Hermes, OpenClaw | User |

Каждая интеграция нормализует собственные имена событий хуков, имена инструментов и поля входных данных инструментов перед запуском политик. Политика может действовать только на события, которые предоставляет адаптер; протестируйте поведение в конце хода и инструкции на точном адаптере и версии, которые вы развёртываете.

## Возможности применения

«Block» означает, что вердикт, возвращаемый текущим адаптером, потребляется названным адаптером. Блокировка после работы инструмента может заменить результат, показанный модели, но не может отменить побочный эффект инструмента, который уже произошёл.

| Адаптер | Проверенные события блокировки | Замечания об наблюдении или отсутствии блокировки |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact` и несколько событий задач/конфигурации | `PostToolUse`, жизненный цикл сессии, уведомления и события после ошибок являются наблюдательными. |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | Блокировка после работы инструмента заменяет результат после выполнения; события начала сессии и компактирования являются наблюдательными в текущем адаптере. |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | Блокировка после работы инструмента заменяет результат после выполнения; события сессии и уведомлений являются наблюдательными. |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` и события сессии являются наблюдательными. |
| OpenCode | `PreToolUse` | События после работы инструмента и жизненного цикла являются наблюдательными; текущая обработка стопа — это руководство для более позднего хода, а не проверенные ворота. |
| Pi | `PreToolUse`, `UserPromptSubmit` | События после работы инструмента и жизненного цикла являются наблюдательными; руководство стопа применяется к более позднему ходу. |
| Hermes | `PreToolUse` | Вердикты после работы инструмента, сессии и остановки субагента не являются воротами. |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | События после работы инструмента, сессии, остановки субагента и компактирования являются наблюдательными. |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | Вердикты после работы инструмента и остановки субагента являются наблюдательными. |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, условный `PermissionRequest` | Хуки разрешения выполняются не во всех режимах разрешения; события после работы инструмента и сессии являются наблюдательными. |
| Antigravity CLI | `PreToolUse`, `Stop` | Вердикты приглашения пользователя и после работы инструмента являются наблюдательными; инструкции в приглашении могут быть внедрены. |
| Goose | `PreToolUse` | События приглашения пользователя, после работы инструмента и сессии являются наблюдательными. Собственный хук блокировки стопа существует выше по течению, но не установлен текущим адаптером. |

Возможности зависят от версии. Переоцените после обновления CLI агента, особенно если политика полагается на поведение приглашения, стопа, разрешения или после работы инструмента, а не на обычные ворота до работы инструмента.

## Установка хуков захвата и политик

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Administration → Keys** и создайте ключ с разрешениями `events:add` и `policies:pull`, названный в честь машины или окружения.
    2. На целевой машине подключите локальный CLI, используя отображаемый ключ, и установите хуки адаптера.
    3. Запустите новую сессию агента, затем подтвердите её события хуков и сессии в разделе **Observe → Events**.
    4. Откройте **Observe → policy** для того же временного окна и подтвердите, что решение политики приписано машине.

    Соединение начинается с ключа машины. Убедитесь, что он включает как разрешения на приём, так и доставку политик, перед копированием его секрета.

    ![Ящик нового ключа API, используемый для предоставления разрешений на приём событий и доставку политик.](/images/dashboard/key-create.png)

    После установки хуков поток Events должен показывать новые события с машины и окружения, которые вы подключили.

    ![Поток живых Events, используемый для подтверждения того, что недавно установленный адаптер передаёт данные.](/images/dashboard/events-stream.png)

    Наконец, убедитесь, что решения политики приписаны той же машине. Это подтверждает, что адаптер передаёт как деятельность политики, так и события трассировки.

    ![Страница Policy, используемая для проверки решений политики из недавно подключённого адаптера.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    Установите хуки для каждого обнаруженного адаптера:

    ```bash
    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>
    failproofai policies --install
    ```

    Или выберите именованные адаптеры и область конфигурации:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    Область project хранит конфигурацию хуков с репозиторием. Область user охватывает работу во всех репозиториях. Claude Code также поддерживает область local; поддержка варьируется в зависимости от адаптера, и CLI отклоняет неподдерживаемые комбинации.

    Проверьте машину и её события:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## Добавить нестандартный путь сессии

<Tabs>
  <Tab title="Dashboard">
    Дополнительные пути регистрируются на машине, а не в облаке. После добавления откройте **Observe → Sessions**, отфильтруйте по окружению машины и подтвердите, что сессии с нового пути появляются. Откройте сессию и проверьте агента, адаптер и временные метки событий перед использованием в аудите.

    ![Список сессий, отфильтрованный по окружению, получающему данные от дополнительного пути захвата.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    Добавьте путь с дополнительной меткой, затем проверьте настроенные пути:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    Удалите путь с помощью `failproofai harness remove-path claude checkout`.
  </Tab>
</Tabs>

<Tip>
  Запустите одну новую сессию после установки. Проверьте как поток живых событий, так и фактическое решение политики перед расширением развёртывания.
</Tip>
