Адаптер — это то, в чём фактически работает ваш агент. Failproof AI поддерживает двенадцать адаптеров, разделённых на два класса:

- **Coding CLIs** (10) — Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Factory Droid, Devin CLI, Antigravity CLI, Goose
- **Chat и assistant гейтвеи** (2) — Hermes (Slack, Telegram, cron), OpenClaw (самостоятельно размещённый ассистент)

Одни и те же политики и одна и та же история сессий применяются независимо от того, в каком адаптере работает агент. Один слой адаптации преобразует собственные имена событий, названия инструментов и поля ввода инструментов каждого адаптера в 29 канонических событий перед применением любой политики.

Агент, работающий **ни в одном** из двенадцати адаптеров, инструментирован напрямую с помощью [Python SDK](/ru/reference/custom-agents). Это другой контракт, и стоит сказать прямо: SDK предоставляет трассировку, сессии, оценки и аудиты — **он не применяет политики самостоятельно.** Для блокировки опасного действия до его выполнения необходим хук принудительного исполнения на границе инструментов вашего runtime; [свяжитесь с нами](mailto:support@befailproof.ai) и мы его реализуем.

| Адаптер | Поддерживаемые области хуков |
| --- | --- |
| Claude Code | User, project, local |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | User, project |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | User, project |
| Hermes, OpenClaw | User |

Каждая интеграция нормализует собственные имена событий хука, названия инструментов и поля ввода инструментов перед применением политик. Политика может воздействовать только на события, которые предоставляет адаптер; тестируйте поведение в конце хода и инструкции на точном адаптере и версии, которые вы развёртываете.

## Возможности принудительного исполнения

"Блокировка" означает, что вердикт, возвращённый текущим адаптером, обрабатывается указанным адаптером. Блокировка после выполнения инструмента может заменить результат, показанный модели, но не может отменить побочный эффект инструмента, который уже произошёл.

| Адаптер | Проверенные события блокировки | Ограничения наблюдения или без блокировки |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact` и несколько событий задач/конфигурации | `PostToolUse`, жизненный цикл сессии, уведомления и события после сбоя носят информационный характер. |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | Блокировка после выполнения заменяет результат после исполнения; события начала сессии и компакции носят информационный характер в текущем адаптере. |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | Блокировка после выполнения заменяет результат после исполнения; события сессии и уведомления носят информационный характер. |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` и события сессии носят информационный характер. |
| OpenCode | `PreToolUse` | События после выполнения и жизненного цикла носят информационный характер; текущая обработка остановки — это рекомендация для последующего хода, а не проверенные ворота. |
| Pi | `PreToolUse`, `UserPromptSubmit` | События после выполнения и жизненного цикла носят информационный характер; рекомендация по остановке применяется к последующему ходу. |
| Hermes | `PreToolUse` | Вердикты после выполнения, сессии и остановки подагента не являются воротами. |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | События после выполнения, сессии, остановки подагента и компакции носят информационный характер. |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | Вердикты после выполнения и остановки подагента носят информационный характер. |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, условный `PermissionRequest` | Хуки разрешения работают не во всех режимах разрешений; события после выполнения и сессии носят информационный характер. |
| Antigravity CLI | `PreToolUse`, `Stop` | Вердикты о пользовательском приглашении и после выполнения носят информационный характер; инструкции к приглашению по-прежнему могут быть внедрены. |
| Goose | `PreToolUse` | События пользовательского приглашения, после выполнения и сессии носят информационный характер. Существует собственный хук блокировки остановки выше по потоку, но он не установлен текущим адаптером. |

Возможности зависят от версии. Повторно протестируйте после обновления CLI агента, особенно если политика опирается на поведение приглашения, остановки, разрешения или после выполнения, а не на обычные ворота перед выполнением.

## Установка хуков захвата и политик

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Administration → Keys** и создайте ключ с разрешениями `events:add` и `policies:pull`, названный для машины или окружения.
    2. На целевой машине подключите локальный CLI с отображаемым ключом и установите хуки адаптера.
    3. Запустите новую сессию агента, затем подтвердите его хуки и события сессии в разделе **Observe → Events**.
    4. Откройте **Observe → policy** для того же временного окна и подтвердите, что решение политики привязано к машине.

    Подключение начинается с ключа машины. Подтвердите, что он включает как разрешения на ингestion, так и доставку политик перед копированием его секрета.

    ![Новый ящик API-ключа, используемый для предоставления разрешений на ингestion событий и доставку политик.](/images/dashboard/key-create.png)

    После установки хуков поток событий должен показывать новые события с машины и окружения, которые вы подключили.

    ![Живой поток событий, используемый для подтверждения того, что вновь установленный адаптер отправляет отчёты.](/images/dashboard/events-stream.png)

    Наконец, проверьте, что решения политик привязаны к одной и той же машине. Это подтверждает, что адаптер отправляет отчёты как о действии политики, так и о событиях трассировки.

    ![Страница Policy, используемая для проверки решений политик из вновь подключённого адаптера.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    Установите хуки для каждого обнаруженного адаптера:

    ```bash
    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>
    failproofai policies --install
    ```

    Или направьте именованные адаптеры и область конфигурации:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    Область project хранит конфигурацию хука с репозиторием. Область user охватывает работу в разных репозиториях. Claude Code также поддерживает область local; поддержка варьируется в зависимости от адаптера и CLI отклоняет неподдерживаемые комбинации.

    Проверьте машину и её события:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## Добавьте неstandard путь сессии

<Tabs>
  <Tab title="Dashboard">
    Дополнительные пути регистрируются на машине, а не в Cloud. После добавления откройте **Observe → Sessions**, отфильтруйте по окружению машины и подтвердите, что появляются сессии с нового пути. Откройте сессию и проверьте агента, адаптер и временные метки событий перед использованием в аудите.

    ![Список Sessions, отфильтрованный по окружению, получающему данные с дополнительного пути захвата.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    Добавьте путь с дополнительной меткой, затем проверьте настроенные пути:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    Удалите путь с помощью `failproofai harness remove-path claude checkout`.
  </Tab>
</Tabs>

<Tip>
  Запустите одну новую сессию после установки. Проверьте как живой поток событий, так и фактическое решение политики перед расширением развёртывания.
</Tip>
