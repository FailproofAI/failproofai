Открытый API доступен по пути `/v1` на источнике вашей панели управления Failproof AI.

## Создайте ключ и отправьте запрос

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Administration → Keys**, выберите **Create key** и выберите самый ограниченный предустановленный набор разрешений, который охватывает интеграцию.
    2. Добавьте отдельные права доступа только при необходимости, создайте ключ и скопируйте его одноразовый секрет.
    3. Отправьте тестовый запрос на `/v1/sessions` и убедитесь, что ключ остается активным на странице Keys.
    4. Ротируйте или отключите ключ из меню действий, когда интеграция сменит владельца.

    ![Новое окно создания API-ключа с предустановками разрешений и отдельными правами доступа.](/images/dashboard/key-create.png)

    Окно создания показано выше. Одноразовый секрет появляется только после того, как вы выберите **create**; скопируйте его перед закрытием подтверждения.
  </Tab>
  <Tab title="CLI">
    Создайте ключ на чтение и используйте его напрямую с помощью `fp` или `curl`:

    ```bash
    fp keys create reliability-reader \
      --permission-set read-only

    fp --api-key <key> sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/sessions?limit=20" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY"
    ```
  </Tab>
</Tabs>

Ключи ограничены организацией и набором разрешений. Запрос без требуемого разрешения для конечной точки возвращает `403` и определяет отсутствующее разрешение.

## Выбор организации

Ключ организации действует на свою организацию автоматически. Ключ с областью действия экземпляра может выбрать организацию для каждого запроса:

<Tabs>
  <Tab title="Dashboard">
    Используйте переключатель организаций в заголовке панели управления перед открытием **Administration → Keys**. Ключи, созданные там, принадлежат выбранной организации. Подтвердите slug организации в URL и сведениях ключа перед копированием учетных данных в автоматизацию.

  </Tab>
  <Tab title="CLI">
    Используйте `--org` перед командой или отправьте заголовок организации для API-ключа с областью действия экземпляра.

    ```bash
    fp orgs list
    fp --org reliability-team sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/usage" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "X-AgentEye-Org: reliability-team"
    ```
  </Tab>
</Tabs>

Используйте созданные страницы конечных точек в этом разделе для получения актуальных путей, параметров, требований к разрешениям и кодов состояния. Спецификация генерируется из аннотаций маршрутов сервера и проверяется на маршрутизаторе `/v1`.

Текущая спецификация имеет полное покрытие маршрутов, методов, параметров, разрешений и кодов состояния. Некоторые тела ответов намеренно не типизированы, потому что сервер все еще создает их как динамический JSON. Проверьте реальный ответ перед генерированием строго типизированного клиента для конечной точки без схемы ответа.

Используйте `Content-Type: application/json` для записей JSON. Рассматривайте `401` как отсутствие или недействительность аутентификации, `403` как действительность без требуемого разрешения, `404` как отсутствие или недоступность ресурса для организации, `409` как конфликт состояния и `422` как недействительное поле или значение разрешения. Ответы об ошибках содержат удобочитаемое сообщение; отказы в разрешениях также называют требуемое право доступа.

<Warning>
  Развертывание политики обеспечения намеренно управляется вне обычной открытой поверхности `/v1`. Используйте поддерживаемый рабочий процесс развертывания в облаке.
</Warning>
