Запустите `failproofai` без аргументов, чтобы запустить встроенную панель мониторинга по адресу `http://localhost:8020`. Она читает локальные истории агентов, конфигурацию политик, результаты аудита и активность хуков непосредственно с машины.

На машине, которая не была настроена, простая команда запустит первоначальную настройку перед открытием панели мониторинга. Это происходит только в интерактивном терминале: при передаче по конвейеру или в CI выводится однострочная подсказка и открывается панель мониторинга, так как мастер, на вопросы которого никто не может ответить, не должен блокировать введённую вами команду. Установите `FAILPROOFAI_NO_FIRST_RUN=1`, чтобы полностью пропустить переход и сразу перейти к панели мониторинга.

Локальная панель мониторинга отделена от Failproof AI Cloud. Она работает без учётной записи Cloud и не подтверждает, что события были доставлены в вашу организацию. На машине, которая завершила настройку, решения, которые она показывает, принимаются демоном `failproofaid`, который является единственным оценщиком здесь; на машине, которая не была настроена, хуки оцениваются внутри процесса.

## Области панели мониторинга

| Область | Что вы можете сделать |
| --- | --- |
| Policies → Activity | Просматривайте локальные решения allow, instruct и deny; фильтруйте по решению, событию, CLI, источнику, политике и сеансу. |
| Policies → Configure | Активируйте политики из установленного пакета, отредактируйте поддерживаемые параметры, переключайте обнаруженные пользовательские и конвенционные политики и выберите целевые адаптеры. |
| Projects | Просмотрите обнаруженные проекты во всех поддерживаемых хранилищах истории агентов и сравните их последние сеансы. |
| Project sessions | Откройте одну локальную транскрипцию, просмотрите необработанные упорядоченные записи и подагентов, скачайте её и сопоставьте активность политик. |
| Audit | Просмотрите последнее автономное сканирование, рискованные паттерны, сильные стороны, затронутые проекты и предложенные встроенные политики. |
| Settings | Настройте запланированные локальные сканирования и отправку отчётов об аудите по электронной почте, если их поддерживает демон/платформа. |

## Просмотр активности политик

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Policies → Activity** и установите фильтры по решению и источнику.
    2. Уточните по событию, адаптеру, имени политики или сеансу.
    3. Строка содержит решение, событие, адаптер, инструмент, политику, режим разрешения и продолжительность. Разверните её, чтобы увидеть полную причину, все совпадающие политики, определяющий источник, развёртывание в облаке, рабочий каталог сеанса и путь транскрипции. Имя инструмента показано в строке, но не является фильтром.
    4. Следите по ссылке сеанса, чтобы поместить решение в контекст транскрипции.

    Строка с видимостью отказа может всё ещё быть наблюдательной для пары адаптер/событие, которая не использует блокирующие вердикты. Детальное представление указывает на подтверждённую способность принудительного выполнения.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    Локальная активность хранится в `~/.failproofai/hook-activity`. Используйте панель мониторинга вместо редактирования этих файлов.
  </Tab>
</Tabs>

## Настройка политик локально

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Policies → Configure** и выберите адаптеры и область конфигурации. Вкладка доступна непосредственно по адресу `http://localhost:8020/policies?tab=policies`.
    2. Активируйте политику из установленного пакета или обнаруженную пользовательскую или конвенционную политику.
    3. Для параметризованной политики откройте её элемент управления конфигурацией и сохраните поддерживаемые значения.
    4. Вернитесь в Activity и запустите совпадающие и несовпадающие действия.

    Список пуст, пока пакет не будет установлен — эта сборка не компилирует политики самостоятельно, поэтому сначала запустите `failproofai policies add FailproofAI/policies`. Конвенционные политики показывают источник проекта или пользователя. Явные изменения пользовательского пути могут потребовать повторного запуска конфигурации CLI, чтобы выбранный путь был записан.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policies show FailproofAI/policies
    failproofai policies add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```

    `policies show <owner>/<repo>` читает содержимое пакета перед его установкой. `--scope` принимает `user`, `project` или `local`; только Claude Code поддерживает `local`, а Hermes и OpenClaw принимают только `user`.
  </Tab>
</Tabs>

## Просмотр проектов и сеансов

Страница Projects объединяет поддерживаемые локальные хранилища истории. Выберите проект, чтобы увидеть список его сеансов, затем откройте сеанс для просмотра необработанного журнала, сегментов подагентов, действия загрузки и активности политик в области сеанса.

Если проект или сеанс отсутствуют, убедитесь, что адаптер использует своё расположение истории по умолчанию или зарегистрируйте дополнительный корень с помощью `failproofai harness add-path <harness> [<label>=]<path>`.

## Планирование автономных аудитов

<Tabs>
  <Tab title="Dashboard">
    Откройте **Settings**, включите запланированное сканирование, выберите его поддерживаемый интервал и настройте доставку отчётов, если это доступно. Страница сообщает следующий запуск, последний запуск, код выхода и поддерживает ли платформа фоновый демон.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    Измените количество дней, чтобы установить другой интервал 1–90 дней. Отключите повторяющиеся сканирования с помощью `failproofai audit --no-schedule`, что остановит таймер и оставит вас выполнившим вход; запустите `failproofai audit` для немедленного интерактивного сканирования.

    Планирование выполняет вход в первый раз, потому что результаты отправляются по электронной почте. `--email <address>` предоставляет адрес заранее и пропускает приглашение входа.
  </Tab>
</Tabs>

<Note>
  Анализ и результаты остаются на этой машине. Анонимная телеметрия CLI отправляется по умолчанию, если только вы не установите `FAILPROOFAI_TELEMETRY_DISABLED=1`. Запланированные сканирования также отправляют метаданные машины и могут отправить ограниченный дайджест результатов после вашего согласия.
</Note>

<Warning>
  Локальная панель мониторинга может отображать подсказки, ввод инструмента, содержимое файла и вывод терминала из локальных историй агентов. Привяжите её только к доверенным интерфейсам и остановите процесс после завершения просмотра.
</Warning>
