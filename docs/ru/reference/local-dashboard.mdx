Выполните `failproofai` без аргументов, чтобы запустить встроенную панель управления на `http://localhost:8020`. Она читает локальные истории агентов, конфигурацию политик, результаты аудита и активность крючков непосредственно с машины.

Локальная панель управления отделена от Failproof AI Cloud. Она работает без облачного аккаунта и не подтверждает, что события были доставлены в вашу организацию.

## Разделы панели управления

| Раздел | Что вы можете сделать |
| --- | --- |
| Policies → Activity | Изучите локальные решения allow, instruct и deny; фильтруйте по решению, событию, CLI, инструменту, источнику, политике и сеансу. |
| Policies → Configure | Включите встроенные политики, измените поддерживаемые параметры, переключайте обнаруженные пользовательские политики и выбирайте целевые обработчики. |
| Projects | Просмотрите обнаруженные проекты по историям поддерживаемых агентов и сравните их последние сеансы. |
| Project sessions | Откройте одну локальную транскрипцию, просмотрите необработанные упорядоченные записи и подагентов, загрузите её и сопоставьте активность политик. |
| Audit | Просмотрите последнее автономное сканирование, рискованные паттерны, преимущества, затронутые проекты и предлагаемые встроенные политики. |
| Settings | Настройте запланированные локальные сканирования и отправку отчётов аудита по электронной почте, если это поддерживается демоном/платформой. |

## Просмотр активности политик

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Policies → Activity** и установите фильтры по решению и источнику.
    2. Уточните поиск по событию, обработчику, инструменту или имени политики.
    3. Разверните строку, чтобы проверить её причину, соответствующие политики, источник, режим выполнения и длительность.
    4. Перейдите по ссылке сеанса, чтобы поместить решение в контекст транскрипции.

    Строка, похожая на отклонённую, может быть только информационной для пары обработчик/событие, которая не использует блокирующие вердикты. Представление деталей указывает на проверенную способность к применению.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    Локальная активность хранится в `~/.failproofai/hook-activity`. Используйте панель управления вместо редактирования этих файлов.
  </Tab>
</Tabs>

## Настройка политик локально

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Policies → Configure** и выберите обработчики и область конфигурации.
    2. Включите встроенную или обнаруженную пользовательскую политику.
    3. Для параметризованной встроенной политики откройте её элемент управления конфигурацией и сохраните поддерживаемые значения.
    4. Вернитесь на страницу Activity и запустите соответствующие и несоответствующие действия.

    Политики соглашения показывают их источник проекта или пользователя. Явные изменения пути пользовательской политики могут требовать повторного выполнения конфигурации CLI, чтобы выбранный путь был записан.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```
  </Tab>
</Tabs>

## Просмотр проектов и сеансов

Страница Projects объединяет поддерживаемые локальные хранилища истории. Выберите проект, чтобы список его сеансов, затем откройте сеанс для средства просмотра необработанного журнала, сегментов подагентов, действия загрузки и активности политик в пределах сеанса.

Если проект или сеанс отсутствует, подтвердите, что обработчик использует расположение истории по умолчанию, или зарегистрируйте дополнительный корень с помощью `failproofai harness add-path`.

## Планирование автономных аудитов

<Tabs>
  <Tab title="Dashboard">
    Откройте **Settings**, включите запланированное сканирование, выберите его поддерживаемый интервал и настройте доставку отчёта, если она доступна. На странице отображаются следующий запуск, последний запуск, код выхода и поддерживается ли фоновый демон на платформе.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    Измените количество дней, чтобы установить другой интервал от 1 до 90 дней. Отключите повторяющиеся сканирования с помощью `failproofai audit --no-schedule`; запустите `failproofai audit` для немедленного интерактивного сканирования.
  </Tab>
</Tabs>

<Warning>
  Локальная панель управления может отображать подсказки, входные данные инструментов, содержимое файлов и вывод терминала из локальных историй агентов. Привязывайте её только к доверенным интерфейсам и останавливайте процесс после завершения проверки.
</Warning>
