Запустите `failproofai` без аргументов, чтобы запустить встроенную панель управления по адресу `http://localhost:8020`. Она читает локальные истории агентов, конфигурацию политик, результаты аудитов и активность хуков непосредственно с машины.

Локальная панель управления отделена от Failproof AI Cloud. Она работает без учётной записи Cloud и не подтверждает, что события были доставлены в вашу организацию.

## Разделы панели управления

| Раздел | Что вы можете сделать |
| --- | --- |
| Policies → Activity | Просматривайте локальные решения allow, instruct и deny; фильтруйте по решению, событию, CLI, инструменту, источнику, политике и сеансу. |
| Policies → Configure | Включайте встроенные политики, редактируйте поддерживаемые параметры, переключайте обнаруженные пользовательские политики и выбирайте целевые шаблоны. |
| Projects | Просматривайте обнаруженные проекты в истории поддерживаемых агентов и сравнивайте их последние сеансы. |
| Project sessions | Откройте одну локальную расшифровку, просматривайте необработанные упорядоченные записи и подагентов, загружайте её и коррелируйте активность политик. |
| Audit | Просматривайте последнее автономное сканирование, рискованные паттерны, сильные стороны, затронутые проекты и предложенные встроенные политики. |
| Settings | Настройте запланированные локальные сканирования и отправленные по электронной почте отчёты аудита, если их поддерживает демон/платформа. |

## Просмотр активности политик

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Policies → Activity** и установите фильтры по решению и источнику.
    2. Сузьте по событию, шаблону, инструменту или имени политики.
    3. Разверните строку, чтобы проверить её причину, соответствующие политики, источник, режим выполнения и продолжительность.
    4. Следуйте по ссылке сеанса, чтобы поместить решение в контекст расшифровки.

    Строка, выглядящая как заблокированная, может быть наблюдательной на паре шаблон/событие, которая не использует блокирующие вердикты. Подробный вид указывает на подтверждённую способность принудительного исполнения.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai policies
    failproofai
    ```

    Локальная активность хранится в `~/.failproofai/hook-activity`. Используйте панель управления вместо редактирования этих файлов.
  </Tab>
</Tabs>

## Настройка политик локально

<Tabs>
  <Tab title="Dashboard">
    1. Откройте **Policies → Configure** и выберите шаблоны и область конфигурации.
    2. Включите встроенную или обнаруженную пользовательскую политику.
    3. Для встроенной политики с параметрами откройте её элемент управления конфигурацией и сохраните поддерживаемые значения.
    4. Вернитесь в Activity и запустите соответствующие и несоответствующие действия.

    Политики соглашения показывают их источник проекта или пользователя. Явные изменения пользовательского пути могут потребовать повторного запуска конфигурации CLI, чтобы выбранный путь был записан.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-sudo --scope project
    failproofai policies --install --custom ./security.policies.ts --scope project
    failproofai policies
    ```
  </Tab>
</Tabs>

## Просмотр проектов и сеансов

На странице Projects объединяются поддерживаемые локальные хранилища истории. Выберите проект, чтобы получить список его сеансов, затем откройте сеанс для просмотра необработанного журнала, сегментов подагентов, действия загрузки и активности политик в области сеанса.

Если проект или сеанс отсутствует, подтвердите, что шаблон использует своё местоположение истории по умолчанию, или зарегистрируйте дополнительный корень с помощью `failproofai harness add-path`.

## Планирование автономных аудитов

<Tabs>
  <Tab title="Dashboard">
    Откройте **Settings**, включите запланированное сканирование, выберите поддерживаемый интервал и настройте доставку отчёта, если она доступна. На странице отображается следующий запуск, последний запуск, код выхода и поддерживается ли фоновый демон на платформе.
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    Измените количество дней, чтобы установить другой интервал от 1 до 90 дней. Отключите повторяющиеся сканирования с помощью `failproofai audit --no-schedule`; запустите `failproofai audit` для немедленного интерактивного сканирования.
  </Tab>
</Tabs>

<Warning>
  Локальная панель управления может отображать подсказки, входные данные инструмента, содержимое файлов и вывод терминала из локальных историй агентов. Привязывайте её только к надёжным интерфейсам и остановите процесс по завершении проверки.
</Warning>
