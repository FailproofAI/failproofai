Подключите инструмент AI к Failproof AI Cloud и работайте с данными ваших агентов из него. Ваш инструмент может запрашивать сессии и события, выполнять операции чтения SQL, читать панели инструментов, алерты, задачи, аудиты и политики, а при наличии соответствующего разрешения вносить изменения, такие как создание алерта или развертывание политики.

Каждый вызов выполняется с **вашими собственными** разрешениями в **одной** организации, которую вы выбираете при подключении.

Один адрес для всех — размещенный или локальный:

```text
https://gateway.befailproof.ai/mcp
```

## Подключение клиента

Добавьте адрес в ваш клиент. При первом использовании инструмента откроется ваш браузер. Выберите, где находится ваш Failproof AI Cloud, войдите, выберите одну организацию и нажмите **Allow**. **Cancel** ничего не подключает.

На странице указаны имя приложения и адрес возврата. Приложение, не идентифицированное собственным веб-адресом, помечается как **unverified app**, поэтому продолжайте только если вы только что запустили это из собственного клиента.

<Tabs>
  <Tab title="Claude">
    В claude.ai или Claude Desktop перейдите в **Settings → Connectors → Add custom connector**. Назовите его `Failproof AI`, введите адрес, выберите **Add**, затем **Connect**.

    В планах Team и Enterprise владелец сначала добавляет соединитель для организации. Затем каждый человек подключает свою собственную учетную запись.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    Затем запустите `/mcp` в Claude Code, выберите `failproofai` и нажмите **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    Добавьте это в `~/.cursor/mcp.json` или в файл `.cursor/mcp.json` вашего проекта:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor показывает **Needs login** рядом с сервером. Выберите его для входа.
  </Tab>
  <Tab title="Codex">
    Добавьте это в `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    Затем запустите `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    Любой клиент, поддерживающий удаленные MCP-серверы через потоковый HTTP с OAuth, подойдет. Укажите ему адрес выше. Нет необходимости настраивать идентификатор клиента или секрет.
  </Tab>
</Tabs>

## Одна организация на подключение

Подключение действует только в организации, которую вы выбрали. Чтобы использовать две организации, добавьте сервер дважды под разными именами, такими как `failproofai-acme` и `failproofai-sandbox`, и подключите каждый к своей организации.

Демонстрационные организации не принимают подключения. Выберите собственную организацию вместо этого.

## Разрешения

Подключение может делать то, что вы можете делать в организации, в пределах набора ниже. Оно следует вашим текущим разрешениям: если администратор дает вам больше, инструмент их получит, а если отберет что-то, инструмент потеряет это при следующем вызове.

| Разрешение | Позволяет инструменту |
| --- | --- |
| `events:read` | Список событий, чтение обзора сессии, список агентов и сред |
| `evaluations:read` | Список сессий, чтение и суммирование результатов и заданий оценки |
| `evaluations:trigger` | Создание оценок, публикация новых версий, их включение или отключение, заполнение предыдущих данных и переоценка сессии |
| `dashboards:read`, `dashboards:write` | Чтение панелей инструментов или создание, переименование и добавление запросов к ним |
| `queries:read`, `queries:write` | Чтение сохраненных запросов или их сохранение и редактирование |
| `queries:run` | Выполнение одного запроса SQL, доступного только для чтения, и чтение схемы запроса |
| `alerts:read`, `alerts:write` | Чтение алертов или создание, редактирование, паузирование, удаление и тестирование их |
| `issues:read` | Чтение задач, их подтверждение и комментирование |
| `issues:create` | Открытие задачи по алерту |
| `issues:close` | Разрешение и закрытие задач |
| `audits:read`, `audits:write` | Чтение аудитов, прогонов и выводов, или создание и редактирование аудитов и запуск прогона |
| `code_fixes:read` | Просмотр способа исправления задачи и получение ее контекста для вашего собственного агента |
| `code_fixes:write` | Начало исправления в Failproof AI Cloud, которое открывает pull request на вашем GitHub |
| `policies:read`, `policies:write` | Чтение политик, машин и развертываний, или публикация, развертывание и откат политик |

Несколько инструментов не требуют разрешения, так как они не читают данные организации: создание ссылок на сессии и события, поиск в документации.

Инструмент AI никогда не может трогать ключи API, пользователей, параметры или администрирование организации, а также не может отправлять события.

## Утверждение изменений

Операции записи сначала запрашивают вас, если ваш клиент может показать подсказку. Вы видите, что изменится, и выбираете **Approve this change** для продолжения. Если вы откажетесь или не ответите в течение примерно 4 минут, ничего не изменится. Некоторые клиенты перестают ждать через минуту, поэтому ответьте быстро.

<Warning>
  Клиент, не поддерживающий подсказки, не будет запрошен, и запись будет выполнена сразу же, когда клиент сделает вызов. Там только собственное подтверждение вашего клиента будет единственным, поэтому держите его включенным для инструментов записи.
</Warning>

## Подключенные приложения и отзыв доступа

**Settings → Integrations → MCP** отображает список ваших подключенных приложений в текущей организации с их разрешениями и временем последнего использования. **Revoke** немедленно отключает приложение. Удаление сервера в вашем клиенте также отзывает подключение.

Вы можете иметь до 5 подключенных приложений на организацию. Повторное подключение того же приложения заменяет его предыдущее подключение.

## Локальные развертывания

Выберите **Self-hosted Failproof AI Cloud** при подключении и введите адрес, по которому вы входите. Ваше развертывание должно быть доступно через открытый HTTPS.

Вызовы инструментов и их результаты проходят через размещенный шлюз Failproof AI при передаче между вашим инструментом AI и вашим развертыванием. Шлюз их не хранит.

## Что происходит с вашими данными

Результаты отправляются инструменту AI, который вы подключили, и поставщик этого инструмента обрабатывает их согласно своим условиям. Для каждого вызова инструмента Failproof AI регистрирует имя инструмента, его результат, время выполнения и организацию, но никогда аргументы или результаты. См. [политику конфиденциальности](https://befailproof.ai/privacy/).

## Устранение неполадок

| Что вы видите | Что делать |
| --- | --- |
| "Started in another browser" | Завершите вход в браузере, который открыл клиент, с разрешенными cookies, и начните заново с клиента |
| Ошибка после **Allow** | Ссылка работает один раз и истекает через 10 минут, поэтому начните заново с клиента |
| Отсутствует ожидаемый инструмент | У вас нет его разрешения в этой организации. Попросите администратора. Вам не нужно переподключаться, когда вы его получите |
| Клиент постоянно просит вас войти | Подключение было отозвано, вы покинули организацию или оно не использовалось 90 дней. Подключитесь снова |
| "You have 5 connected apps" | Отозовите один из **Settings → Integrations → MCP**, затем подключитесь заново |
