Подключите инструмент AI к Failproof AI Cloud и работайте с данными ваших агентов из него. Ваш инструмент может запрашивать сеансы и события, запускать SQL-запросы только для чтения, читать панели управления, оповещения, проблемы, аудиты и политики, а также, если у вас есть необходимое разрешение, вносить изменения, такие как создание оповещения или развертывание политики.

Каждый вызов выполняется с **вашими собственными** правами доступа в **одной** организации, которую вы выбираете при подключении.

Существует один адрес для всех, размещен он или самостоятельно:

```text
https://gateway.befailproof.ai/mcp
```

## Подключение клиента

Добавьте адрес в ваш клиент. При первом использовании инструмента откроется ваш браузер. Выберите, где находится ваш Failproof AI Cloud, войдите, выберите одну организацию и нажмите **Allow**. **Cancel** не подключит ничего.

Страница указывает имя приложения и адрес, на который оно вернется. Приложение, не идентифицируемое собственным веб-адресом, помечается как **unverified app**, поэтому продолжайте только если вы только что запустили это из вашего собственного клиента.

<Tabs>
  <Tab title="Claude">
    В claude.ai или Claude Desktop перейдите в **Settings → Connectors → Add custom connector**. Назовите его `Failproof AI`, введите адрес, выберите **Add**, затем **Connect**.

    В планах Team и Enterprise владелец сначала добавляет соединитель для организации. Затем каждый человек подключает свой собственный аккаунт.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    Затем запустите `/mcp` в Claude Code, выберите `failproofai` и нажмите **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    Добавьте это в `~/.cursor/mcp.json` или в `.cursor/mcp.json` вашего проекта:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor показывает **Needs login** рядом с сервером. Выберите его для входа.
  </Tab>
  <Tab title="Codex">
    Добавьте это в `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    Затем запустите `codex mcp login failproofai`.
  </Tab>
  <Tab title="Другие клиенты">
    Любой клиент, поддерживающий удаленные MCP-серверы через потоковый HTTP с OAuth, работает. Передайте ему адрес выше. Нет необходимости настраивать ID или секрет клиента.
  </Tab>
</Tabs>

## Одна организация на подключение

Подключение действует только в выбранной вами организации. Для использования двух организаций добавьте сервер дважды под разными именами, такими как `failproofai-acme` и `failproofai-sandbox`, и подключите каждый к своей организации.

Демонстрационные организации не принимают подключения. Вместо этого выберите вашу собственную организацию.

## Разрешения

Подключение может делать то, что вы можете делать в организации, в пределах следующего набора. Оно соответствует вашим текущим разрешениям: если администратор предоставляет вам больше, инструмент получает это, и если они что-то отбирают, инструмент теряет это при следующем вызове.

| Разрешение | Позволяет инструменту |
| --- | --- |
| `events:read` | Перечислять события, читать обзор сеанса, перечислять агентов и окружения |
| `evaluations:read` | Перечислять сеансы, читать и резюмировать результаты и задания оценок |
| `evaluations:trigger` | Создавать оценки, публиковать новые версии, включать или отключать их, заполнять и переоценивать сеанс |
| `dashboards:read`, `dashboards:write` | Читать панели управления или создавать, переименовывать и добавлять к ним запросы |
| `queries:read`, `queries:write` | Читать сохраненные запросы или сохранять и редактировать их |
| `queries:run` | Запускать один SQL-запрос только для чтения и читать схему запроса |
| `alerts:read`, `alerts:write` | Читать оповещения или создавать, редактировать, приостанавливать, удалять и тестировать их |
| `issues:read` | Читать проблемы, подтверждать их и комментировать их |
| `issues:create` | Открывать проблему по оповещению |
| `issues:close` | Разрешать и закрывать проблемы |
| `audits:read`, `audits:write` | Читать аудиты, запуски и результаты или создавать и редактировать аудиты и запускать запуск |
| `code_fixes:read` | Посмотреть, как исправить проблему, и получить её контекст для вашего собственного агента |
| `code_fixes:write` | Начать исправление в Failproof AI Cloud, которое откроет pull request на вашем GitHub |
| `policies:read`, `policies:write` | Читать политики, машины и развертывания или публиковать, развертывать и откатывать политики |

Несколько инструментов не требуют разрешения, потому что они не читают данные организации: создание ссылок на сеансы и события, а также поиск в этой документации.

Инструмент AI никогда не может трогать API ключи, пользователей, параметры или администрирование организации, и не может отправлять события.

## Одобрение изменений

Операции записи сначала вас спрашивают, если ваш клиент может показать подсказку. Вы видите, какие изменения будут произведены, и выбираете **Approve this change** для продолжения. Если вы отказываетесь или не отвечаете в течение примерно 4 минут, ничего не изменится. Некоторые клиенты перестают ждать через минуту, поэтому ответьте быстро.

<Warning>
  Клиент, который не поддерживает подсказки, не будет спрошен, и операция записи выполнится, как только клиент сделает вызов. Там ваше собственное подтверждение клиента - единственное, поэтому держите его включенным для инструментов записи.
</Warning>

## Подключенные приложения и отозвание

**Settings → Integrations → MCP** перечисляет ваши подключенные приложения в текущей организации, с их разрешениями и последним использованием. **Revoke** мгновенно отключает приложение. Удаление сервера в вашем клиенте также отзывает подключение.

Вы можете иметь до 5 подключенных приложений на организацию. Подключение того же приложения снова заменяет его предыдущее подключение.

## Самостоятельно размещенные развертывания

Выберите **Self-hosted Failproof AI Cloud** при подключении и введите адрес, по которому вы входите. Ваше развертывание должно быть доступно через общедоступный HTTPS.

Вызовы инструментов и их результаты проходят через размещенный шлюз Failproof AI по пути между вашим инструментом AI и вашим развертыванием. Шлюз их не сохраняет.

## Что происходит с вашими данными

Результаты переходят в инструмент AI, который вы подключили, и провайдер этого инструмента обрабатывает их в соответствии с его собственными условиями. Для каждого вызова инструмента Failproof AI регистрирует имя инструмента, его результат, время выполнения и организацию, но никогда аргументы или результаты. См. [политику приватности](https://befailproof.ai/privacy/).

## Устранение неполадок

| Что вы видите | Что делать |
| --- | --- |
| "Started in another browser" | Завершите вход в браузер, открытый клиентом, с разрешенными куками, и начните заново из клиента |
| Ошибка после **Allow** | Ссылка работает один раз и истекает через 10 минут, поэтому начните заново из клиента |
| Отсутствует инструмент, который вы ожидали | У вас нет его разрешения в этой организации. Попросите администратора. Вам не нужно переподключаться после получения разрешения |
| Клиент продолжает просить вас войти | Подключение было отозвано, вы покинули организацию или оно не использовалось 90 дней. Подключитесь заново |
| "You have 5 connected apps" | Отозовите один под **Settings → Integrations → MCP**, затем подключитесь заново |
