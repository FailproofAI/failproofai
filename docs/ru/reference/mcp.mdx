Подключите инструмент искусственного интеллекта к Failproof AI Cloud и работайте с данными ваших агентов из этого инструмента. Ваш инструмент может запрашивать сессии и события, выполнять только для чтения SQL-запросы, читать панели управления, оповещения, проблемы, аудиты и политики, а также, если у вас есть соответствующее разрешение, вносить изменения, например создавать оповещение или развёртывать политику.

Каждый вызов выполняется с **вашими собственными** разрешениями в **одной** организации, которую вы выбираете при подключении.

Адрес один для всех — как для размещённых, так и для самостоятельно размещённых развёртываний:

```text
https://gateway.befailproof.ai/mcp
```

## Подключение клиента

Добавьте адрес в ваш клиент. При первом использовании инструмента откроется ваш браузер. Выберите, где находится ваш Failproof AI Cloud, войдите в систему, выберите одну организацию и нажмите **Allow**. **Cancel** ничего не подключает.

На странице отображаются имя приложения и адрес, на который оно возвращается. Приложение, которое не определяется собственным веб-адресом, помечено как **unverified app**, поэтому продолжайте только если вы только что запустили это из своего клиента.

<Tabs>
  <Tab title="Claude">
    В claude.ai или Claude Desktop перейдите в **Settings → Connectors → Add custom connector**. Назовите его `Failproof AI`, введите адрес, выберите **Add**, затем **Connect**.

    В планах Team и Enterprise владелец сначала добавляет соединитель для организации. Затем каждый человек подключает свою собственную учётную запись.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    Затем запустите `/mcp` в Claude Code, выберите `failproofai` и выберите **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    Добавьте это в `~/.cursor/mcp.json` или в ``.cursor/mcp.json` вашего проекта:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor отображает **Needs login** рядом с сервером. Выберите его, чтобы войти.
  </Tab>
  <Tab title="Codex">
    Добавьте это в `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    Затем запустите `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    Подходит любой клиент, который поддерживает удалённые MCP-серверы через потоковый HTTP с OAuth. Укажите адрес выше. Не нужно настраивать ID клиента или секрет.
  </Tab>
</Tabs>

## Одна организация на одно подключение

Подключение действует только в организации, которую вы выбрали. Чтобы использовать две организации, добавьте сервер дважды под разными именами, например `failproofai-acme` и `failproofai-sandbox`, и подключите каждый к своей организации.

Демонстрационные организации не принимают подключения. Вместо этого выберите вашу собственную организацию.

## Разрешения

Подключение может делать то, что вы можете делать в организации, в рамках приведённого ниже набора. Оно следует вашим текущим разрешениям: если администратор предоставит вам больше, инструмент получит это, и если они возьмут что-то назад, инструмент потеряет это при следующем вызове.

| Разрешение | Позволяет инструменту |
| --- | --- |
| `events:read` | Список событий, чтение обзора сессии, список агентов и окружений |
| `evaluations:read` | Список сессий, чтение и обобщение результатов оценки и заданий |
| `evaluations:trigger` | Создание оценок, публикация новых версий, включение и отключение, заполнение истории и переоценка сессии |
| `dashboards:read`, `dashboards:write` | Чтение панелей управления или создание, переименование и добавление запросов к ним |
| `queries:read`, `queries:write` | Чтение сохранённых запросов или их сохранение и редактирование |
| `queries:run` | Запуск одного SQL-запроса только для чтения и чтение схемы запроса |
| `alerts:read`, `alerts:write` | Чтение оповещений или создание, редактирование, приостановка, удаление и тестирование их |
| `issues:read` | Чтение проблем, подтверждение их и комментирование |
| `issues:create` | Открытие проблемы по оповещению |
| `issues:close` | Разрешение и закрытие проблем |
| `audits:read`, `audits:write` | Чтение аудитов, запусков и результатов или создание и редактирование аудитов и запуск проверки |
| `code_fixes:read` | Просмотр способа исправления проблемы и получение её контекста для исправления собственным агентом |
| `code_fixes:write` | Запуск исправления в Failproof AI Cloud, которое открывает запрос на слияние в вашу учётную запись GitHub |
| `policies:read`, `policies:write` | Чтение политик, машин и развёртываний или публикация, развёртывание и откат политик |

Несколько инструментов не требуют разрешения, так как они не читают данные организации: построение ссылок на сессии и события, а также поиск в этой документации.

Инструмент искусственного интеллекта никогда не может получить доступ к ключам API, пользователям, параметрам или администрированию организации, и не может отправлять события.

## Одобрение изменений

Записи сначала спрашивают вас, может ли ваш клиент показать подтверждение. Вы видите, что изменится, и выбираете **Approve this change**, чтобы продолжить. Если вы отклоните или не ответите в течение примерно 4 минут, ничего не изменится. Некоторые клиенты перестают ждать через минуту, поэтому ответьте быстро.

<Warning>
  Клиент, который не поддерживает подтверждения, не запрашивается, и запись выполняется как только клиент делает вызов. В этом случае подтверждение самого вашего клиента — единственное, поэтому держите его включённым для инструментов записи.
</Warning>

## Подключённые приложения и отзыв

**Settings → Integrations → MCP** перечисляет ваши подключённые приложения в текущей организации с их разрешениями и последним использованием. **Revoke** отключает приложение сразу. Удаление сервера в вашем клиенте также отзывает подключение.

Вы можете иметь до 5 подключённых приложений на одну организацию. Подключение того же приложения снова заменяет его предыдущее подключение.

## Самостоятельно размещённые развёртывания

Выберите **Self-hosted Failproof AI Cloud** при подключении и введите адрес, по которому вы входите. Ваше развёртывание должно быть доступно по открытому HTTPS.

Вызовы инструментов и их результаты проходят через размещённый шлюз Failproof AI на пути между вашим инструментом искусственного интеллекта и вашим развёртыванием. Шлюз не сохраняет их.

## Что происходит с вашими данными

Результаты передаются подключённому инструменту искусственного интеллекта, и поставщик этого инструмента обрабатывает их в соответствии со своими собственными условиями. Для каждого вызова инструмента Failproof AI регистрирует имя инструмента, его результат, время выполнения и организацию, никогда не аргументы или результаты. Посмотрите [политику конфиденциальности](https://befailproof.ai/privacy/).

## Устранение неполадок

| Что вы видите | Что делать |
| --- | --- |
| "Started in another browser" | Завершите вход в браузер, открытый клиентом, с разрешёнными куками, и начните заново из клиента |
| Ошибка после **Allow** | Ссылка работает один раз и истекает через 10 минут, поэтому начните заново из клиента |
| Отсутствует ожидаемый инструмент | Вы не имеете его разрешение в этой организации. Попросите администратора. Вам не нужно переподключаться, как только вы его получите |
| Клиент постоянно просит вас войти в систему | Подключение было отозвано, вы покинули организацию или оно не использовалось 90 дней. Подключитесь снова |
| "You have 5 connected apps" | Отзовите один в **Settings → Integrations → MCP**, затем подключитесь снова |
