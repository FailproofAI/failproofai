Подключите инструмент ИИ к Failproof AI Cloud и работайте с данными ваших агентов из него. Ваш инструмент может запрашивать сессии и события, запускать SQL-запросы только для чтения, читать панели управления, оповещения, проблемы, аудиты и политики, а также, если у вас есть разрешение, вносить изменения, такие как создание оповещения или развертывание политики.

Каждый вызов выполняется с **вашими собственными** разрешениями в **одной** организации, которую вы выбираете при подключении.

Существует один адрес для всех, размещенный или локальный:

```text
https://gateway.befailproof.ai/mcp
```

## Подключение клиента

Добавьте адрес в ваш клиент. При первом использовании инструмента ваш браузер откроется. Выберите, где находится ваш Failproof AI Cloud, выполните вход, выберите одну организацию и нажмите **Allow**. **Cancel** не подключит ничего.

На странице отображается имя приложения и адрес возврата. Приложение, которое не идентифицируется собственным веб-адресом, помечается как **unverified app**, поэтому продолжайте только если вы только что запустили это из своего клиента.

<Tabs>
  <Tab title="Claude">
    В claude.ai или Claude Desktop перейдите в **Settings → Connectors → Add custom connector**. Назовите его `Failproof AI`, введите адрес, выберите **Add**, затем **Connect**.

    На планах Team и Enterprise владелец сначала добавляет коннектор для организации. Затем каждый человек подключает свой собственный аккаунт.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    Затем запустите `/mcp` в Claude Code, выберите `failproofai` и нажмите **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    Добавьте это в `~/.cursor/mcp.json` или в `.cursor/mcp.json` вашего проекта:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor показывает **Needs login** рядом с сервером. Выберите его для входа.
  </Tab>
  <Tab title="Codex">
    Добавьте это в `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    Затем запустите `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    Любой клиент, поддерживающий удаленные MCP-серверы через Streamable HTTP с OAuth, работает. Предоставьте ему адрес выше. Нет необходимости настраивать ID или секрет клиента.
  </Tab>
</Tabs>

## Одна организация на подключение

Подключение действует только в выбранной вами организации. Чтобы использовать две организации, добавьте сервер дважды под разными именами, например `failproofai-acme` и `failproofai-sandbox`, и подключите каждый к своей организации.

Демо-организации не принимают подключения. Вместо этого выберите вашу собственную организацию.

## Разрешения

Подключение может делать то, что вы можете делать в организации, в пределах указанного ниже. Оно следует вашим текущим разрешениям: если администратор дает вам больше, инструмент получает это, а если они что-то отнимают, инструмент теряет это при следующем вызове.

| Разрешение | Позволяет инструменту |
| --- | --- |
| `events:read` | Перечислять события, читать обзор сессии, перечислять агентов и окружения |
| `evaluations:read` | Перечислять сессии, читать и суммировать результаты оценок и задания |
| `evaluations:trigger` | Создавать оценки, публиковать новые версии, включать или отключать их, заполнять данные и переоценивать сессию |
| `dashboards:read`, `dashboards:write` | Читать панели управления или создавать, переименовывать и добавлять запросы к ним |
| `queries:read`, `queries:write` | Читать сохраненные запросы или сохранять и редактировать их |
| `queries:run` | Запускать один SQL-запрос только для чтения и читать схему запроса |
| `alerts:read`, `alerts:write` | Читать оповещения или создавать, редактировать, приостанавливать, удалять и тестировать их |
| `issues:read` | Читать проблемы, подтверждать их и комментировать |
| `issues:create` | Открыть проблему по оповещению |
| `issues:close` | Решить и закрыть проблемы |
| `audits:read`, `audits:write` | Читать аудиты, выполнения и выводы или создавать и редактировать аудиты и начинать выполнение |
| `code_fixes:read` | Увидеть, как исправить проблему, и получить контекст для вашего собственного агента, чтобы исправить |
| `code_fixes:write` | Начать исправление в Failproof AI Cloud, которое открывает pull request на вашем GitHub |
| `policies:read`, `policies:write` | Читать политики, машины и развертывания или публиковать, развертывать и откатывать политики |

Несколько инструментов не требуют разрешения, поскольку они не читают данные организации: создание ссылок на сессии и события, а также поиск в этой документации.

Инструмент ИИ никогда не может трогать API-ключи, пользователей, параметры или администрирование организации, и не может отправлять события.

## Утверждение изменений

Операции записи сначала спрашивают вас, может ли ваш клиент показать подсказку. Вы видите, что изменится, и выбираете **Approve this change**, чтобы продолжить. Если вы отклоняете или не отвечаете в течение примерно 4 минут, ничего не меняется. Некоторые клиенты перестают ждать через минуту, поэтому отвечайте быстро.

<Warning>
  Клиент, который не поддерживает подсказки, не спрашивается, и запись запускается сразу же после вызова клиента. Там ваше собственное подтверждение клиента — это единственное, поэтому держите его включенным для инструментов записи.
</Warning>

## Подключенные приложения и отзыв разрешения

**Settings → Integrations → MCP** перечисляет ваши подключенные приложения в текущей организации с их разрешениями и последним использованием. **Revoke** отключает приложение немедленно. Удаление сервера в вашем клиенте также отзывает подключение.

Вы можете иметь до 5 подключенных приложений на организацию. Подключение того же приложения снова заменяет его более раннее подключение.

## Локальные развертывания

Выберите **Self-hosted Failproof AI Cloud** при подключении и введите адрес, на котором вы выполняете вход. Ваше развертывание должно быть доступно по общедоступному HTTPS.

Вызовы инструментов и их результаты проходят через размещенный шлюз Failproof AI на пути между вашим инструментом ИИ и вашим развертыванием. Шлюз их не сохраняет.

## Что происходит с вашими данными

Результаты переходят к подключенному вами инструменту ИИ, и поставщик этого инструмента обрабатывает их в соответствии со своими условиями. Для каждого вызова инструмента Failproof AI регистрирует имя инструмента, его результат, время выполнения и организацию, но никогда не регистрирует аргументы или результаты. См. [политику конфиденциальности](https://befailproof.ai/privacy/).

## Устранение неполадок

| Что вы видите | Что делать |
| --- | --- |
| Started in another browser | Завершите вход в браузере, который открыл клиент, с включенными cookies, и начните снова с клиента |
| Ошибка после **Allow** | Ссылка работает один раз и истекает через 10 минут, поэтому начните снова с клиента |
| Отсутствует ожидаемый инструмент | У вас нет его разрешения в этой организации. Попросите администратора. Вам не нужно переподключаться, как только вы его получите |
| Клиент продолжает просить вас выполнить вход | Подключение было отозвано, вы покинули организацию или оно не использовалось в течение 90 дней. Подключитесь снова |
| You have 5 connected apps | Отзовите одно в **Settings → Integrations → MCP**, затем подключитесь снова |
