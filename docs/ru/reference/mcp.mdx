Подключите AI инструмент к Failproof AI Cloud и работайте с данными ваших агентов из него. Ваш инструмент может запрашивать сеансы и события, выполнять SQL только для чтения, читать панели управления, оповещения, проблемы, аудиты и политики, а также, если у вас есть соответствующее разрешение, вносить изменения, такие как создание оповещения или развертывание политики.

Каждый вызов выполняется с **вашими собственными** разрешениями в **одной** организации, которую вы выбираете при подключении.

Существует один адрес для всех, размещаемый или самостоятельно размещаемый:

```text
https://gateway.befailproof.ai/mcp
```

## Подключение клиента

Добавьте адрес в ваш клиент. При первом использовании инструмента ваш браузер откроется. Выберите, где находится ваш Failproof AI Cloud, войдите, выберите одну организацию и нажмите **Allow**. **Cancel** не подключает ничего.

На странице отображается название приложения и адрес, на который оно возвращается. Приложение, которое не идентифицируется по собственному веб-адресу, помечается как **unverified app**, поэтому продолжайте, только если вы только что запустили это из собственного клиента.

<Tabs>
  <Tab title="Claude">
    В claude.ai или Claude Desktop перейдите в **Settings → Connectors → Add custom connector**. Назовите его `Failproof AI`, введите адрес, выберите **Add**, затем **Connect**.

    В планах Team и Enterprise владелец сначала добавляет соединитель для организации. Затем каждый человек подключает свою учетную запись.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    Затем запустите `/mcp` в Claude Code, выберите `failproofai` и нажмите **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    Добавьте это в `~/.cursor/mcp.json` или в файл вашего проекта `.cursor/mcp.json`:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor показывает **Needs login** рядом с сервером. Выберите его, чтобы войти.
  </Tab>
  <Tab title="Codex">
    Добавьте это в `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    Затем запустите `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    Любой клиент, поддерживающий удаленные MCP серверы через потоковый HTTP с OAuth, работает. Укажите адрес выше. Нет необходимости настраивать идентификатор клиента или секрет.
  </Tab>
</Tabs>

## Одна организация на подключение

Подключение действует только в выбранной вами организации. Чтобы использовать две организации, добавьте сервер дважды под разными именами, такими как `failproofai-acme` и `failproofai-sandbox`, и подключите каждый к своей организации.

Демо-организации не принимают подключения. Вместо этого выберите свою организацию.

## Разрешения

Подключение может делать то, что вы можете делать в организации, в пределах набора ниже. Оно следует вашим текущим разрешениям: если администратор даст вам больше, инструмент получит это, и если они что-то заберут, инструмент потеряет это при следующем вызове.

| Разрешение | Позволяет инструменту |
| --- | --- |
| `events:read` | Перечислять события, читать обзор сеанса, перечислять агентов и среды |
| `evaluations:read` | Перечислять сеансы, читать и суммировать результаты и задания оценок |
| `evaluations:trigger` | Создавать оценки, публиковать новые версии, включать или отключать их, выполнять заполнение и переоценку сеанса |
| `dashboards:read`, `dashboards:write` | Читать панели управления или создавать, переименовывать и добавлять к ним запросы |
| `queries:read`, `queries:write` | Читать сохраненные запросы или сохранять и редактировать их |
| `queries:run` | Выполнить один SQL запрос только для чтения и прочитать схему запроса |
| `alerts:read`, `alerts:write` | Читать оповещения или создавать, редактировать, приостанавливать, удалять и тестировать их |
| `issues:read` | Читать проблемы, признавать их и комментировать их |
| `issues:create` | Открыть проблему для оповещения |
| `issues:close` | Разрешить и закрыть проблемы |
| `audits:read`, `audits:write` | Читать аудиты, прогоны и результаты, или создавать и редактировать аудиты и начинать прогон |
| `code_fixes:read` | Посмотреть, как исправить проблему, и получить ее контекст для вашего собственного агента |
| `code_fixes:write` | Начать исправление в Failproof AI Cloud, которое открывает pull request на вашем GitHub |
| `policies:read`, `policies:write` | Читать политики, машины и развертывания, или публиковать, развертывать и откатывать политики |

Несколько инструментов не требуют разрешений, так как они не читают данные организации: построение ссылок на сеансы и события, а также поиск в этой документации.

AI инструмент никогда не может трогать API ключи, пользователей, параметры или администрирование организации, и он не может отправлять события.

## Одобрение изменений

Записи спрашивают вас в первую очередь, если ваш клиент может показать подсказку. Вы видите, что изменится, и выбираете **Approve this change**, чтобы продолжить. Если вы откажетесь или не ответите в течение примерно 4 минут, ничего не изменится. Некоторые клиенты перестают ждать через минуту, поэтому ответьте быстро.

<Warning>
  Клиент, который не поддерживает подсказки, не спрашивается, и запись запускается, как только клиент делает вызов. Там ваше собственное подтверждение клиента - единственное, поэтому держите его включенным для инструментов записи.
</Warning>

## Подключенные приложения и отзыв

**Settings → Integrations → MCP** перечисляет ваши подключенные приложения в текущей организации с их разрешениями и последним использованием. **Revoke** немедленно отключает приложение. Удаление сервера в вашем клиенте также отзывает подключение.

Вы можете иметь до 5 подключенных приложений на организацию. Повторное подключение того же приложения заменяет его более раннее подключение.

## Самостоятельно размещаемые развертывания

При подключении выберите **Self-hosted Failproof AI Cloud** и введите адрес, на который вы входите. Ваше развертывание должно быть доступно через общедоступный HTTPS.

Вызовы инструментов и их результаты проходят через размещаемый шлюз Failproof AI на пути между вашим AI инструментом и вашим развертыванием. Шлюз их не хранит.

## Что происходит с вашими данными

Результаты идут в подключенный вами AI инструмент, и провайдер этого инструмента обрабатывает их в соответствии со своими собственными условиями. Для каждого вызова инструмента Failproof AI регистрирует имя инструмента, его результат, сколько времени он занял, и организацию, никогда не аргументы или результаты. См. [политику конфиденциальности](https://befailproof.ai/privacy/).

## Устранение неполадок

| Что вы видите | Что делать |
| --- | --- |
| Started in another browser | Завершите вход в браузере, открытом клиентом, с разрешенными cookies, и начните снова с клиента |
| Ошибка после **Allow** | Ссылка работает один раз и истекает через 10 минут, поэтому начните снова с клиента |
| Отсутствует ожидаемый инструмент | У вас нет его разрешения в этой организации. Попросите администратора. Вам не нужно переподключаться после получения разрешения |
| Клиент продолжает просить вас войти | Подключение было отозвано, вы покинули организацию, или оно не использовалось 90 дней. Подключитесь снова |
| You have 5 connected apps | Отзовите одно в **Settings → Integrations → MCP**, затем подключитесь снова |
