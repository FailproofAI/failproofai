Подключите инструмент ИИ к Failproof AI Cloud и работайте с данными ваших агентов из него. Ваш инструмент может запрашивать сессии и события, выполнять читаемые SQL запросы, читать панели управления, оповещения, аналитику, аудиты и политики, а при наличии соответствующего разрешения вносить изменения, такие как создание оповещения или развертывание политики.

Каждый вызов выполняется с **вашими собственными** правами доступа в **одной** организации, которую вы выбираете при подключении.

Существует один адрес для всех, размещенный или локальный:

```text
https://gateway.befailproof.ai/mcp
```

## Подключение клиента

Добавьте адрес в ваш клиент. При первом использовании инструмента ваш браузер откроется. Выберите расположение Failproof AI Cloud, войдите в систему, выберите одну организацию и нажмите **Allow**. Нажатие **Cancel** не установит соединение.

На странице указаны название приложения и адрес возврата. Приложение, которое не идентифицируется по собственному веб-адресу, помечается как **unverified app**, поэтому продолжайте только если вы только что запустили это из вашего собственного клиента.

<Tabs>
  <Tab title="Claude">
    В claude.ai или Claude Desktop перейдите в **Settings → Connectors → Add custom connector**. Назовите его `Failproof AI`, введите адрес, выберите **Add**, затем **Connect**.

    В планах Team и Enterprise владелец сначала добавляет соединитель для организации. Затем каждый человек подключает свой собственный аккаунт.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http failproofai https://gateway.befailproof.ai/mcp
    ```

    Затем выполните `/mcp` в Claude Code, выберите `failproofai` и нажмите **Authenticate**.
  </Tab>
  <Tab title="Cursor">
    Добавьте это в `~/.cursor/mcp.json` или в `.cursor/mcp.json` вашего проекта:

    ```json
    {
      "mcpServers": {
        "failproofai": { "url": "https://gateway.befailproof.ai/mcp" }
      }
    }
    ```

    Cursor отобразит **Needs login** рядом с сервером. Выберите его для входа.
  </Tab>
  <Tab title="Codex">
    Добавьте это в `~/.codex/config.toml`:

    ```toml
    [mcp_servers.failproofai]
    url = "https://gateway.befailproof.ai/mcp"
    ```

    Затем выполните `codex mcp login failproofai`.
  </Tab>
  <Tab title="Other clients">
    Любой клиент, поддерживающий удаленные MCP серверы через Streamable HTTP с OAuth, будет работать. Дайте ему адрес выше. Нет необходимости конфигурировать клиент ID или секрет.
  </Tab>
</Tabs>

## Одна организация на соединение

Соединение действует только в выбранной организации. Чтобы использовать две организации, добавьте сервер дважды под разными именами, например `failproofai-acme` и `failproofai-sandbox`, и подключите каждый к своей организации.

Демонстрационные организации не принимают подключения. Вместо этого выберите свою организацию.

## Разрешения

Соединение может выполнять то же, что вы можете делать в организации, в пределах набора, показанного ниже. Оно следует вашим текущим разрешениям: если администратор дает вам больше, инструмент получает его, и если они отнимают что-то, инструмент теряет это при следующем вызове.

| Разрешение | Позволяет инструменту |
| --- | --- |
| `events:read` | Список событий, чтение обзора сессии, список агентов и окружений |
| `evaluations:read` | Список сессий, чтение и суммирование результатов оценки и заданий |
| `evaluations:trigger` | Создание оценок, публикация новых версий, включение и отключение, заполнение, переоценка сессии |
| `dashboards:read`, `dashboards:write` | Чтение панелей управления или создание, переименование и добавление запросов к ним |
| `queries:read`, `queries:write` | Чтение сохраненных запросов или их сохранение и редактирование |
| `queries:run` | Выполнение одного читаемого SQL запроса и чтение схемы запроса |
| `alerts:read`, `alerts:write` | Чтение оповещений или создание, редактирование, пауза, удаление и тестирование их |
| `issues:read` | Чтение аналитики, подтверждение и комментирование |
| `issues:create` | Открытие аналитики по оповещению |
| `issues:close` | Разрешение и закрытие аналитики |
| `audits:read`, `audits:write` | Чтение аудитов, запусков и результатов или создание, редактирование аудитов и запуск проверки |
| `code_fixes:read` | Просмотр способа исправления аналитики и получение ее контекста для собственного агента |
| `code_fixes:write` | Запуск исправления в Failproof AI Cloud, которое открывает pull request на GitHub |
| `policies:read`, `policies:write` | Чтение политик, машин и развертываний или публикация, развертывание и откат политик |

Несколько инструментов не требуют разрешений, так как они не читают данные организации: создание ссылок на сессии и события, поиск в этой документации.

Инструмент ИИ никогда не может коснуться ключей API, пользователей, параметров или администрирования организации, и не может отправлять события.

## Утверждение изменений

Запросы на запись сначала спрашивают вас, если ваш клиент может показать подсказку. Вы видите, что будет изменено, и выбираете **Approve this change**, чтобы продолжить. Если вы откажетесь или не ответите в течение примерно 4 минут, ничего не изменится. Некоторые клиенты прекращают ожидание через минуту, поэтому ответьте быстро.

<Warning>
  Клиент, который не поддерживает подсказки, не запрашивается, и запись выполняется как только клиент делает вызов. Там ваша собственная подтверждающая настройка клиента — единственная, поэтому держите её включенной для инструментов записи.
</Warning>

## Подключенные приложения и отзыв доступа

**settings → integrations → MCP** перечисляет ваши подключенные приложения в текущей организации с их разрешениями и последним использованием. **Revoke** немедленно отключает приложение. Удаление сервера в вашем клиенте также отзывает соединение.

Вы можете иметь до 5 подключенных приложений на организацию. Подключение одного и того же приложения снова заменяет его предыдущее соединение.

## Локальные развертывания

Выберите **Self-hosted Failproof AI Cloud** при подключении и введите адрес, по которому вы входите. Ваше развертывание должно быть доступно через публичный HTTPS.

Вызовы инструментов и их результаты проходят через размещенный шлюз Failproof AI между вашим инструментом ИИ и развертыванием. Шлюз их не хранит.

## Что происходит с вашими данными

Результаты отправляются подключенному вами инструменту ИИ, и его поставщик обрабатывает их на условиях своей собственной политики. Для каждого вызова инструмента Failproof AI логирует имя инструмента, его результат, время выполнения и организацию, никогда — аргументы или результаты. См. [политику конфиденциальности](https://befailproof.ai/privacy/).

## Решение проблем

| Что вы видите | Что делать |
| --- | --- |
| Started in another browser | Завершите вход в браузере, открытом клиентом, с разрешенными куками, и начните снова с клиента |
| Ошибка после **Allow** | Ссылка работает один раз и истекает через 10 минут, поэтому начните снова с клиента |
| Отсутствует ожидаемый инструмент | У вас нет его разрешения в этой организации. Попросите администратора. Вам не нужно переподключаться после его получения |
| Клиент постоянно просит вас войти | Соединение было отозвано, вы покинули организацию или оно не использовалось 90 дней. Подключитесь снова |
| You have 5 connected apps | Отозвите один под **settings → integrations → MCP**, затем подключитесь снова |
