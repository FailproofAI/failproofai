`failproofai otel` настраивает дополнительные отчёты OpenTelemetry в FailproofAI Cloud. Сначала подключите машину с помощью `failproofai config` и попросите администратора организации включить **Settings → OpenTelemetry**.

Интерактивная установка предлагает настроить OpenTelemetry после поля облачного ключа и выбора агента. Этот опциональный шаг по умолчанию имеет значение «Нет». Выберите «Да», чтобы выбрать OTEL агентов; тот же код включения запустится после записи подключения. Нажатие Esc перед завершением установки не применяет никаких изменений. Автоматическая установка, указанный ключ, режим с открытым исходным кодом и сохранённое подключение вас не подключают.

## Включение агента

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Поддерживаемые агенты: `claude`, `codex` и `copilot` (VS Code). Установка Copilot требует исполняемого файла VS Code или установленного расширения Copilot. Оставшаяся директория параметров недостаточна; установка пропускает Copilot, если ничего не найдено.

`--local` отправляет данные на локальный ретранслятор вместо прямой отправки в Cloud. Copilot использует ретранслятор автоматически, поскольку его параметры не могут хранить заголовок аутентификации.

Ретранслятор слушает только на вашей машине. Ваш настроенный демон FailproofAI подхватит изменение в течение нескольких секунд; перезагружать его не требуется. Если другое приложение занимает порт ретранслятора, статус отобразит его как отключённый, а демон будет продолжать работу.

<Warning>
Захват текста включён по умолчанию. Добавьте `--no-content`, чтобы опустить подсказки и детали инструментов. Разные версии агентов могут предоставлять разные элементы управления контентом; проверьте, что экспортирует ваш агент, перед использованием с чувствительными данными.
</Warning>

Codex экспортирует только журналы диалогов, а не внутренние трассировки или метрики выполнения. Явный параметр `log_user_prompt = false` в вашей конфигурации Codex остаётся выключенным; включение выведет примечание о сохранении этого выбора.

### Выбор одного пути отчётности

Если отчётность расшифровки включена для агента, установка спрашивает:

> failproofai уже отправляет сеансы Claude Code в Cloud. Отправить их через OTEL вместо этого? Загрузка расшифровок для Claude Code остановится.

По умолчанию — «Нет». `--yes` принимает переключение без подтверждения. На другие агенты и применение политик это не влияет.

Установка Codex ждёт подтверждения от демона об изменении сборщика перед записью параметров экспортера. Если подтверждение истечёт по времени, установка предупредит вас подождать перед запуском Codex.

Config v2 сохраняет список отслеживания в `agents.selected` (и историю обнаружения в `agents.seen`). Предпочтение расшифровки для каждого агента остаётся в `collector.agents.<agent>.sessions`, владение OTEL в `otel.agents` и параметры ретранслятора в `collector.otlp.enabled` / `collector.otlp.port`. Эти отдельные ключи сохраняют старые конфигурации OTEL читаемыми: установка может изменить список отслеживания без потери предпочтения транспорта или состояния, необходимого для восстановления параметров агента.

## Проверка установки

```bash
failproofai otel status
```

Статус показывает каждого агента, управляются ли его параметры FailproofAI, пункт назначения, переключатель приёма организации, состояние ретранслятора и последний результат загрузки ретранслятора.

`unknown` для переключателя организации означает, что сервер не предоставил его или не удалось связаться. Это не ошибка и не препятствует настройке на более старой версии Cloud.

Если Cloud ещё не поддерживает OTEL, ретранслятор сохраняет отклонённые экспорты вместо их удаления. Если приём организацией отключён, `enable` ничего не записывает и завершается с ошибкой; сначала попросите администратора включить это.

## Вывод конфигурации для приложения

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

Вывод — это блок переменных окружения оболочки для экспортера OTLP/HTTP. Вывод Cloud устанавливает `OTEL_EXPORTER_OTLP_ENDPOINT` в базу OTLP Cloud, `https://<cloud>/otel`, и экспортер добавляет `/v1/<signal>`; переменная для отдельного сигнала, такая как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, требует полного `https://<cloud>/otel/v1/logs`. Локальный вывод указывает на ретранслятор, `http://127.0.0.1:<port>`. Вывод Cloud включает настроенный ключ API; рассматривайте его как секрет. Локальный вывод ключ опускает. Чтобы использовать локальный вывод, сначала включите локального агента, чтобы ретранслятор работал.

## Восстановление предыдущих параметров

```bash
failproofai otel disable claude
failproofai otel disable all
```

Отключение восстанавливает только параметры, которые написал FailproofAI, сохраняет несвязанные изменения и восстанавливает предыдущий выбор отчётности расшифровок каждого агента. Когда последний управляемый локальный агент отключен, ретранслятор прекращает принимать экспорты.

Для Codex отключение также записывает `collector.agents.codex.sessions_resume_after` (миллисекунды эпохи). Существующие байты развёртывания рассматриваются как доставленные, поэтому сеансы, захваченные с помощью OTEL, не загружаются повторно; более поздние добавления по-прежнему проходят через отчётность расшифровок.

Каждая команда поддерживает `--help`. См. [OpenTelemetry в Cloud](/ru/agenteye/opentelemetry) для примеров приложений и кодовых агентов.
