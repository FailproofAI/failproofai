`failproofai otel` настраивает дополнительную отправку данных OpenTelemetry в FailproofAI Cloud. Сначала подключите машину с помощью `failproofai config` и попросите администратора организации включить **Settings → OpenTelemetry**.

Интерактивная установка спрашивает об OpenTelemetry после поля Cloud key и выбора агента. Дополнительный шаг по умолчанию установлен на No. Выберите Yes, чтобы выбрать OTEL агентов; тот же код включения выполняется после записи подключения. Нажатие Esc перед установкой не применяет никаких изменений. Автоматическая установка, предоставленный ключ, режим с открытым исходным кодом и сохранение существующего подключения не активируют опцию.

## Включить агента

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Поддерживаемые агенты — `claude`, `codex` и `copilot` (VS Code). Установка Copilot требует исполняемого файла VS Code или установленного расширения Copilot. Оставшейся директории настроек недостаточно; установка пропускает Copilot, если ничего из этого не найдено.

`--local` отправляет на локальный relay вместо прямой отправки в Cloud. Copilot использует relay автоматически, так как его настройки не могут хранить заголовок аутентификации.

Relay прослушивает только вашу машину. Ваш настроенный демон FailproofAI подхватит изменение в течение нескольких секунд; вам не нужно его перезагружать. Если другое приложение использует порт relay, статус сообщит, что он отключен, и демон продолжит работу.

<Warning>
Захват текста включен по умолчанию. Добавьте `--no-content` для исключения подсказок и деталей инструментов. Разные версии агентов могут предоставлять разные элементы управления содержимым; проверьте, что экспортирует ваш агент, перед использованием с конфиденциальными данными.
</Warning>

Codex экспортирует только журналы разговоров, а не внутренние трассировки времени выполнения или метрики. Явное `log_user_prompt = false` в вашей конфигурации Codex остается отключенным; enable выводит примечание, когда это сохраняет этот выбор.

### Выберите один путь отправки

Если отправка расшифровок включена для агента, установка спрашивает:

> failproofai уже отправляет сеансы Claude Code в Cloud. Отправлять их с OTEL вместо этого? Загрузка расшифровок для Claude Code остановится.

По умолчанию No. `--yes` принимает переключение без запроса. На другие агенты и применение политик это не влияет.

Установка Codex ждет, пока демон подтвердит изменение сборщика, прежде чем записать его настройки экспортера. Если подтверждение истекает, установка предупреждает вас подождать перед запуском Codex.

Config v2 сохраняет запомненный список трассировки в `agents.selected` (и историю обнаружения в `agents.seen`). Предпочтение расшифровок для каждого агента остается в `collector.agents.<agent>.sessions`, владение OTEL в `otel.agents` и настройки relay в `collector.otlp.enabled` / `collector.otlp.port`. Эти отдельные ключи сохраняют старые конфигурации OTEL читаемыми: установка может изменить список трассировки без потери предпочтения транспорта или состояния, необходимого для восстановления настроек агента.

## Проверить установку

```bash
failproofai otel status
```

Статус показывает каждого агента, управляются ли его настройки FailproofAI, его пункт назначения, переключатель приема организации, состояние relay и последний результат загрузки relay.

`unknown` для переключателя организации означает, что сервер не предоставил его или недоступен. Это не ошибка и не препятствует конфигурации в более старой версии Cloud.

Если Cloud еще не поддерживает OTEL, relay сохраняет отклоненные экспорты вместо их отбрасывания. Если прием организации отключен, `enable` ничего не пишет и выходит с ошибкой; попросите администратора сначала это включить.

## Вывести конфигурацию для приложения

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

Вывод — это блок окружения оболочки для экспортера OTLP/HTTP. Вывод Cloud устанавливает `OTEL_EXPORTER_OTLP_ENDPOINT` на базу OTLP Cloud, `https://<cloud>/otel`, и экспортер добавляет `/v1/<signal>`; переменная для конкретного сигнала, такая как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, требует полного `https://<cloud>/otel/v1/logs`. Локальный вывод указывает на relay, `http://127.0.0.1:<port>`. Вывод Cloud включает настроенный ключ API; обращайтесь с ним как с секретом. Локальный вывод опускает ключ. Чтобы использовать локальный вывод, сначала включите локального агента, чтобы relay работал.

## Восстановить предыдущие настройки

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable восстанавливает только настройки, которые написал FailproofAI, сохраняет несвязанные изменения и восстанавливает предыдущий выбор отправки расшифровок каждого агента. Когда последний управляемый локальный агент отключен, relay прекращает принимать экспорты.

Для Codex, disable также записывает `collector.agents.codex.sessions_resume_after` (миллисекунды epoch). Существующие байты развертывания рассматриваются как доставленные, поэтому сеансы, захваченные с OTEL, не загружаются повторно; более поздние добавления по-прежнему проходят через отправку расшифровок.

Все команды поддерживают `--help`. См. [OpenTelemetry в Cloud](/ru/agenteye/opentelemetry) для примеров приложений и кодирующих агентов.
