`failproofai otel` настраивает опциональную отправку данных OpenTelemetry в FailproofAI Cloud. Сначала подключите машину с помощью `failproofai config` и попросите администратора организации включить **Settings → OpenTelemetry**.

Интерактивная настройка спрашивает об OpenTelemetry после поля Cloud key и выбора агента. Опциональный шаг по умолчанию имеет значение No. Выберите Yes, чтобы выбрать OTEL агентов; тот же код включения запустится после записи соединения. Нажатие Esc перед завершением настройки не применит никаких изменений. Автоматическая настройка, предоставленный ключ, режим с открытым исходным кодом и сохранённое соединение вас не подключают.

## Включить агента

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Поддерживаемые агенты: `claude`, `codex` и `copilot` (VS Code). Настройка Copilot требует исполняемого файла VS Code или установленного расширения Copilot. Оставшейся директории настроек недостаточно; настройка пропускает Copilot, если ничего не найдено.

`--local` отправляет на локальный relay вместо прямой отправки в Cloud. Copilot использует relay автоматически, потому что его настройки не могут хранить заголовок аутентификации.

Relay слушает только на вашей машине. Ваш настроенный FailproofAI daemon заметит изменение в течение нескольких секунд; вам не нужно его перезагружать. Если другое приложение использует порт relay, состояние сообщает о нём как отключённом, и daemon продолжает работать.

<Warning>
Захват текста включён по умолчанию. Добавьте `--no-content`, чтобы опустить приглашения и детали инструментов. Разные версии агентов могут предоставлять разные элементы управления содержимым; проверьте, что экспортирует ваш агент, перед использованием с чувствительными данными.
</Warning>

Codex экспортирует только логи разговоров, не внутренние трассировки выполнения или метрики. Явный `log_user_prompt = false` в конфигурации Codex остаётся отключённым; enable выведет примечание, когда сохранит этот выбор.

### Выберите один путь отчётности

Если отчётность транскрипта включена для агента, настройка спросит:

> failproofai уже отправляет сеансы Claude Code в Cloud. Отправить их с OTEL вместо этого? Загрузка транскрипта для Claude Code прекратится.

По умолчанию No. `--yes` принимает переключение без запроса. Другие агенты и применение политик не затронуты.

Настройка Codex ждёт подтверждения от daemon об изменении collector перед записью его параметров exporter. Если подтверждение истечёт, настройка предупредит вас подождать перед запуском Codex.

Config v2 хранит запомненный список трассировки в `agents.selected` (а историю обнаружения в `agents.seen`). Предпочтение транскрипта для каждого агента остаётся в `collector.agents.<agent>.sessions`, владение OTEL в `otel.agents`, и параметры relay в `collector.otlp.enabled` / `collector.otlp.port`. Эти отдельные ключи сохраняют старые конфигурации OTEL читаемыми: настройка может изменить список трассировки без потери предпочтения транспорта или состояния, необходимого для восстановления настроек агента.

## Проверить настройку

```bash
failproofai otel status
```

Статус показывает каждого агента, управляются ли его настройки FailproofAI, его назначение, переключатель ingestion организации, состояние relay и последний результат загрузки relay.

`unknown` для переключателя организации означает, что сервер его не предоставил или не мог быть достигнут. Это не ошибка и не препятствует конфигурации на более старой версии Cloud.

Если Cloud ещё не поддерживает OTEL, relay сохраняет отклонённые экспорты вместо их отбрасывания. Если ingestion организации отключён, `enable` не пишет ничего и выходит с ошибкой; попросите администратора сначала его включить.

## Вывести конфигурацию для приложения

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

Выводом является блок переменных окружения shell для exporter OTLP/HTTP. Вывод Cloud устанавливает `OTEL_EXPORTER_OTLP_ENDPOINT` на OTLP base Cloud, `https://<cloud>/otel`, и exporter добавляет `/v1/<signal>`; переменная для конкретного сигнала, такая как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, нуждается в полном `https://<cloud>/otel/v1/logs`. Локальный вывод указывает на relay, `http://127.0.0.1:<port>`. Вывод Cloud включает настроенный ключ API; обращайтесь с ним как с секретом. Локальный вывод опускает ключ. Для использования локального вывода сначала включите локального агента, чтобы relay был запущен.

## Восстановить предыдущие настройки

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable восстанавливает только настройки, которые написал FailproofAI, сохраняет неrelated изменения и восстанавливает предыдущий выбор отчётности транскрипта каждого агента. Когда последний управляемый локальный агент отключен, relay прекращает принимать экспорты.

Для Codex, disable также записывает `collector.agents.codex.sessions_resume_after` (epoch миллисекунды). Существующие байты rollout рассматриваются как доставленные, поэтому сеансы, захваченные с OTEL, не загружаются повторно; более поздние дополнения всё равно проходят через отчётность транскрипта.

Каждая команда поддерживает `--help`. См. [OpenTelemetry в Cloud](/ru/agenteye/opentelemetry) для примеров приложений и coding-agents.
