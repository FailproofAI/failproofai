`failproofai otel` настраивает дополнительную отправку данных OpenTelemetry в FailproofAI Cloud. Сначала подключите вашу машину с помощью `failproofai config` и попросите администратора организации включить **Settings → OpenTelemetry**.

Интерактивная настройка предлагает OpenTelemetry после поля Cloud-ключа и выбора агента. Дополнительный шаг по умолчанию — No. Выберите Yes, чтобы выбрать OTEL-агентов; тот же код активации запускается после записи подключения. Нажатие Esc перед завершением настройки не применяет никаких изменений. Автоматизированная настройка, указанный ключ, режим с открытым исходным кодом и сохранение существующего подключения не включают OTEL.

## Включение агента

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Поддерживаемые агенты — это `claude`, `codex` и `copilot` (VS Code). Настройка Copilot требует исполняемого файла VS Code или установленного расширения Copilot. Оставшейся директории настроек недостаточно; настройка пропускает Copilot, если ничего из этого не найдено.

`--local` отправляет данные на локальное реле вместо прямой отправки в Cloud. Copilot использует реле автоматически, поскольку его настройки не могут хранить заголовок аутентификации.

Реле слушает только на вашей машине. Ваш настроенный демон FailproofAI применит изменение в течение нескольких секунд; перезагружать его не нужно. Если другое приложение занимает порт реле, статус отображает его как отключённый, а демон продолжает работу.

<Warning>
Захват текста включён по умолчанию. Добавьте `--no-content`, чтобы исключить приглашения и детали инструментов. Разные версии агентов могут предоставлять разные управления контентом; проверьте, что экспортирует ваш агент, перед использованием с чувствительными данными.
</Warning>

Codex экспортирует только журналы беседы, не внутренние трассировки или метрики времени выполнения. Явный `log_user_prompt = false` в конфигурации Codex остаётся отключённым; enable выводит примечание, когда сохраняет этот выбор.

### Выберите один путь отправки

Если отправка транскрипта включена для агента, настройка запрашивает:

> failproofai уже отправляет сеансы Claude Code в Cloud. Отправлять их с OTEL вместо этого? Загрузка транскрипта для Claude Code остановится.

По умолчанию — No. `--yes` принимает переключение без подтверждения. Другие агенты и применение политик не затронуты.

Настройка Codex ждёт, пока демон подтвердит изменение коллектора, перед записью настроек экспортера. Если подтверждение истекает по времени, настройка предупреждает вас дождаться перед запуском Codex.

Config v2 сохраняет запомненный список трассировки в `agents.selected` (и историю обнаружения в `agents.seen`). Предпочтение транскрипта для каждого агента остаётся в `collector.agents.<agent>.sessions`, владение OTEL в `otel.agents` и настройки реле в `collector.otlp.enabled` / `collector.otlp.port`. Эти отдельные ключи сохраняют старые конфигурации OTEL читаемыми: настройка может изменить список трассировки без потери предпочтения транспорта или состояния, необходимого для восстановления настроек вашего агента.

## Проверка настройки

```bash
failproofai otel status
```

Статус отображает каждый агент, управляются ли его настройки FailproofAI, его назначение, переключатель приёма организации, состояние реле и последний результат загрузки реле.

`unknown` для переключателя организации означает, что сервер не предоставил это значение или не удалось его достичь. Это не ошибка и не препятствует конфигурации на старой версии Cloud.

Если Cloud ещё не поддерживает OTEL, реле сохраняет отклонённые экспорты вместо их отбрасывания. Если приём организации отключён, `enable` не записывает ничего и завершается с ошибкой; сначала попросите администратора его включить.

## Вывод конфигурации для приложения

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

Результат — это блок переменных окружения оболочки для экспортера OTLP/HTTP. Выход Cloud устанавливает `OTEL_EXPORTER_OTLP_ENDPOINT` на базу OTLP Cloud, `https://<cloud>/otel`, и экспортер добавляет `/v1/<signal>`; переменная для конкретного сигнала, такая как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, нуждается в полном `https://<cloud>/otel/v1/logs`. Локальный выход указывает на реле, `http://127.0.0.1:<port>`. Выход Cloud включает настроенный API-ключ; обращайтесь с ним как с секретом. Локальный выход ключ не включает. Чтобы использовать локальный выход, сначала включите локального агента, чтобы реле работало.

## Восстановление предыдущих настроек

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable восстанавливает только настройки, которые написал FailproofAI, сохраняет несвязанные изменения и восстанавливает предыдущий выбор отправки транскрипта каждого агента. Когда отключается последний управляемый локальный агент, реле останавливает приём экспортов.

Для Codex disable также записывает `collector.agents.codex.sessions_resume_after` (эпоха в миллисекундах). Существующие байты развёртывания рассматриваются как доставленные, поэтому сеансы, захваченные с OTEL, не загружаются повторно; более поздние добавления по-прежнему проходят через отправку транскрипта.

Каждая команда поддерживает `--help`. Смотрите [OpenTelemetry в Cloud](/ru/agenteye/opentelemetry) для примеров приложений и кодирующих агентов.
