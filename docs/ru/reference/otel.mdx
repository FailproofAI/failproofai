`failproofai otel` настраивает опциональную отправку OpenTelemetry в FailproofAI Cloud. Сначала подключите вашу машину с помощью `failproofai config` и попросите администратора организации включить **Settings → OpenTelemetry**.

Интерактивная установка предложит OpenTelemetry после поля Cloud key и выбора агента. Опциональный шаг по умолчанию установлен на No. Выберите Yes, чтобы выбрать OTEL агентов; тот же код включения запустится после записи соединения. Нажатие Esc перед завершением установки не применит никаких изменений. Автоматическая установка, предоставленный ключ, режим открытого исходного кода и сохранённое соединение не активируют опцию.

## Включить агента

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Поддерживаемые агенты: `claude`, `codex` и `copilot` (VS Code). Установка Copilot требует исполняемого файла VS Code или установленного расширения Copilot. Только оставшийся каталог настроек недостаточно; установка пропустит Copilot, если ничего из этого не найдено.

`--local` отправляет на локальный relay вместо прямой отправки в Cloud. Copilot использует relay автоматически, поскольку его настройки не могут хранить заголовок аутентификации.

Relay прослушивает только вашу машину. Ваш настроенный FailproofAI демон подхватит изменение в течение нескольких секунд; перезагрузка не требуется. Если другое приложение использует порт relay, статус отобразит его как выключенный, а демон продолжит работу.

<Warning>
Захват текста включен по умолчанию. Добавьте `--no-content`, чтобы пропустить подсказки и детали инструментов. Разные версии агентов могут предоставлять разные элементы управления контентом; перед использованием с чувствительными данными проверьте, что экспортирует ваш агент.
</Warning>

Codex экспортирует только логи беседы, не внутренние трассировки выполнения или метрики. Явное `log_user_prompt = false` в вашей конфигурации Codex остаётся отключённым; enable выведет примечание, когда сохранит этот выбор.

### Выберите один путь отправки

Если отправка расшифровки включена для агента, установка спросит:

> failproofai уже отправляет сеансы Claude Code в Cloud. Отправлять их через OTEL вместо этого? Загрузка расшифровки для Claude Code прекратится.

По умолчанию установлено No. `--yes` принимает переключение без запроса. Другие агенты и применение политик не затронуты.

Установка Codex ждёт подтверждения демоном изменения сборщика перед записью параметров экспортёра. Если подтверждение истекает по времени, установка предупредит вас дождаться перед запуском Codex.

Config v2 хранит запомненный список трассировки в `agents.selected` (и историю обнаружения в `agents.seen`). Предпочтение расшифровки для каждого агента остаётся в `collector.agents.<agent>.sessions`, владение OTEL в `otel.agents` и настройки relay в `collector.otlp.enabled` / `collector.otlp.port`. Эти отдельные ключи сохраняют старые OTEL конфигурации читаемыми: установка может изменить список трассировки без потери предпочтения транспорта или состояния, необходимого для восстановления ваших настроек агента.

## Проверить установку

```bash
failproofai otel status
```

Status отображает каждого агента, управляются ли его настройки FailproofAI, его назначение, переключатель приёма организации, состояние relay и последний результат загрузки relay.

`unknown` для переключателя организации означает, что сервер его не предоставил или не смог быть достигнут. Это не ошибка и не препятствует конфигурации на более старой версии Cloud.

Если Cloud ещё не поддерживает OTEL, relay сохраняет отклонённые экспорты вместо их удаления. Если приём организации отключен, `enable` не записывает ничего и завершается с ошибкой; попросите администратора включить его сначала.

## Вывести конфигурацию для приложения

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

Результат — блок переменных окружения для экспортёра OTLP/HTTP. Результат Cloud устанавливает `OTEL_EXPORTER_OTLP_ENDPOINT` на базу OTLP Cloud, `https://<cloud>/otel`, и экспортёр добавляет `/v1/<signal>`; переменная для конкретного сигнала, такая как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, требует полного `https://<cloud>/otel/v1/logs`. Локальный результат указывает на relay, `http://127.0.0.1:<port>`. Результат Cloud включает настроенный ключ API; обращайтесь с ним как с секретом. Локальный результат опускает ключ. Для использования локального результата сначала включите локального агента, чтобы relay работал.

## Восстановить предыдущие настройки

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable восстанавливает только настройки, которые написал FailproofAI, сохраняет несвязанные изменения и восстанавливает предыдущий выбор отправки расшифровки каждого агента. Когда отключен последний управляемый локальный агент, relay прекращает принимать экспорты.

Для Codex disable также записывает `collector.agents.codex.sessions_resume_after` (миллисекунды эпохи). Существующие байты развёртывания рассматриваются как доставленные, поэтому сеансы, захваченные с OTEL, не будут загружены снова; более поздние добавления всё ещё проходят через отправку расшифровки.

Каждая команда поддерживает `--help`. Смотрите [OpenTelemetry in Cloud](/ru/agenteye/opentelemetry) для примеров приложений и кодирующих агентов.
