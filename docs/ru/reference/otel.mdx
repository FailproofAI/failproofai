`failproofai otel` настраивает опциональное сообщение OpenTelemetry в FailproofAI Cloud. Сначала подключите машину с помощью `failproofai config`, а затем попросите администратора организации включить **Settings → OpenTelemetry**.

Интерактивная установка задает вопросы об OpenTelemetry после поля Cloud key и выбора агента. Опциональный шаг по умолчанию отключен. Выберите Yes, чтобы выбрать OTEL агентов; тот же код включения запустится после сохранения подключения. Нажатие Esc перед установкой ничего не изменит. Автоматическая установка, предоставленный ключ, режим с открытым исходным кодом и сохранение существующего подключения вас не включают.

## Включение агента

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Поддерживаемые агенты: `claude`, `codex` и `copilot` (VS Code). Установка Copilot требует исполняемого файла VS Code или установленного расширения Copilot. одного остаточного каталога параметров недостаточно; установка пропускает Copilot, если ничего не найдено.

`--local` отправляет на локальный relay вместо прямой отправки в Cloud. Copilot использует relay автоматически, так как его параметры не могут хранить заголовок аутентификации.

Relay слушает только на вашей машине. Ваш настроенный FailproofAI daemon подхватит изменение в течение нескольких секунд; перезагружать его не нужно. Если другое приложение занимает порт relay, статус сообщит об этом как off, и daemon продолжит работу.

<Warning>
Захват текста включен по умолчанию. Добавьте `--no-content`, чтобы пропустить подсказки и детали инструментов. Разные версии агентов могут предоставлять различные элементы управления содержимым; проверьте, что экспортирует ваш агент, перед использованием с конфиденциальными данными.
</Warning>

Codex экспортирует только логи разговоров, не внутренние трассировки времени выполнения или метрики. Явное значение `log_user_prompt = false` в конфигурации Codex остается отключенным; enable выведет заметку, когда сохранит этот выбор.

### Выберите один путь отчетности

Если отчетность о стенограмме включена для агента, установка задает вопрос:

> failproofai уже отправляет сеансы Claude Code в Cloud. Отправить их с OTEL вместо этого? Загрузка стенограммы для Claude Code остановится.

По умолчанию значение No. `--yes` принимает переключение без подсказки. На другие агенты и принудительное применение политик это не влияет.

Установка Codex ждет подтверждения от daemon об изменении collector перед записью параметров exporter. Если подтверждение истечет по времени, установка предупредит вас подождать перед запуском Codex.

Config v2 хранит запомненный список трассировки в `agents.selected` (и историю обнаружения в `agents.seen`). Предпочтение стенограммы для каждого агента остается в `collector.agents.<agent>.sessions`, владение OTEL в `otel.agents` и параметры relay в `collector.otlp.enabled` / `collector.otlp.port`. Эти отдельные ключи сохраняют старые конфигурации OTEL доступными для чтения: установка может изменить список трассировки без потери предпочтения транспорта или состояния, необходимого для восстановления параметров агента.

## Проверка установки

```bash
failproofai otel status
```

Status показывает каждого агента, управляются ли его параметры FailproofAI, его пункт назначения, переключатель ingestion организации, состояние relay и результат последней загрузки relay.

`unknown` для переключателя организации означает, что сервер его не предоставил или не удалось до него добраться. Это не ошибка и не препятствует конфигурации на более старой версии Cloud.

Если Cloud еще не поддерживает OTEL, relay сохраняет отклоненные экспорты вместо их удаления. Если ingestion организации отключен, `enable` ничего не пишет и выходит с ошибкой; попросите администратора сначала его включить.

## Вывод конфигурации для приложения

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

Выход представляет собой блок окружения shell для exporter OTLP/HTTP. Cloud output устанавливает `OTEL_EXPORTER_OTLP_ENDPOINT` на OTLP base Cloud, `https://<cloud>/otel`, и exporter добавляет `/v1/<signal>`; переменная для каждого сигнала, такая как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, требует полного пути `https://<cloud>/otel/v1/logs`. Local output указывает на relay, `http://127.0.0.1:<port>`. Cloud output включает настроенный API ключ; обращайтесь с ним как с секретом. Local output опускает ключ. Чтобы использовать local output, сначала включите локальный агент, чтобы relay запустился.

## Восстановление предыдущих параметров

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable восстанавливает только параметры, которые написала FailproofAI, сохраняет несвязанные изменения и восстанавливает предыдущий выбор отчетности о стенограмме для каждого агента. Когда последний управляемый локальный агент отключен, relay прекращает принимать экспорты.

Для Codex disable также записывает `collector.agents.codex.sessions_resume_after` (epoch миллисекунды). Существующие байты rollout считаются доставленными, поэтому сеансы, захваченные с OTEL, не загружаются снова; более поздние добавления по-прежнему идут через отчетность о стенограмме.

Каждая команда поддерживает `--help`. Примеры приложений и кодирующих агентов см. в [OpenTelemetry в Cloud](/ru/agenteye/opentelemetry).
