`failproofai otel` настраивает опциональную отправку данных OpenTelemetry в FailproofAI Cloud. Сначала подключите вашу машину с помощью `failproofai config`. Прием OpenTelemetry всегда включен в Cloud, поэтому нет переключателя организации для активации.

Интерактивная установка спрашивает об OpenTelemetry после поля Cloud-ключа и выбора агента. Опциональный шаг по умолчанию установлен на Нет. Выберите Да, чтобы выбрать OTEL-агентов; тот же код активации запускается после записи соединения. Нажатие Esc перед завершением установки не применяет никакие изменения. Автоматическая установка, предоставленный ключ, режим открытого исходного кода и сохранение активного соединения вас не подключают.

## Включить агента

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Поддерживаемые агенты — это `claude`, `codex` и `copilot` (VS Code). Настройка Copilot требует исполняемого файла VS Code или установленного расширения Copilot. Оставшийся каталог параметров недостаточен; установка пропускает Copilot, если ничего не найдено.

`--local` отправляет на локальный ретранслятор вместо прямой отправки в Cloud. Copilot использует ретранслятор автоматически, так как его параметры не могут хранить заголовок аутентификации.

Ретранслятор слушает только вашу машину. Сконфигурированный демон FailproofAI подхватит изменение в течение нескольких секунд; вам не нужно его перезапускать. Если другое приложение занимает порт ретранслятора, статус отображает его как отключенный, а демон продолжает работать.

<Warning>
Захват текста включен по умолчанию. Добавьте `--no-content`, чтобы исключить подсказки и детали инструментов. Разные версии агентов могут предоставлять разные элементы управления содержимым; проверьте, что экспортирует ваш агент, перед использованием с чувствительными данными.
</Warning>

Codex экспортирует только логи разговоров, а не внутренние трассировки времени выполнения или метрики. Явный `log_user_prompt = false` в вашей конфигурации Codex остается отключенным; enable выводит примечание, когда сохраняет этот выбор.

### Выберите один путь отчетности

Если отчетность о транскриптах включена для агента, установка спрашивает:

> failproofai уже отправляет сеансы Claude Code в Cloud. Отправить их через OTEL вместо этого? Загрузка транскриптов для Claude Code остановится.

По умолчанию установлено Нет. `--yes` принимает переключение без подсказки. Другие агенты и принудительное применение политик не затрагиваются.

Установка Codex ждет подтверждения от демона об изменении сборщика перед записью параметров экспортера. Если подтверждение истекает по времени, установка предупреждает вас ждать перед запуском Codex.

Config v2 сохраняет запомненный список трассировки в `agents.selected` (и историю обнаружения в `agents.seen`). Предпочтение транскриптов для каждого агента остается в `collector.agents.<agent>.sessions`, принадлежность OTEL в `otel.agents` и параметры ретранслятора в `collector.otlp.enabled` / `collector.otlp.port`. Эти отдельные ключи делают старые конфигурации OTEL читаемыми: установка может изменить список трассировки без потери предпочтения транспорта или состояния, необходимого для восстановления параметров вашего агента.

## Проверить установку

```bash
failproofai otel status
```

Статус показывает каждого агента, управляются ли его параметры FailproofAI, его пункт назначения, переключатель приема организации, состояние ретранслятора и последний результат загрузки ретранслятора.

`unknown` для переключателя организации означает, что сервер его не предоставил или его не удалось достичь. Это не ошибка и не предотвращает конфигурацию на более старой версии Cloud.

Если Cloud еще не поддерживает OTEL, ретранслятор сохраняет отклоненный экспорт вместо их отброса. Если более старая версия Cloud отображает прием организации как отключенный, `enable` ничего не записывает и выходит с ошибкой.

## Вывести конфигурацию для приложения

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

Вывод — это блок переменных окружения оболочки для экспортера OTLP/HTTP. Вывод Cloud устанавливает `OTEL_EXPORTER_OTLP_ENDPOINT` на OTLP-базу Cloud, `https://<cloud>/otel`, и экспортер добавляет `/v1/<signal>`; переменная для конкретного сигнала, такая как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, требует полный `https://<cloud>/otel/v1/logs`. Локальный вывод указывает на ретранслятор, `http://127.0.0.1:<port>`. Вывод Cloud включает сконфигурированный API-ключ; относитесь к нему как к секрету. Локальный вывод опускает ключ. Для использования локального вывода сначала включите локального агента, чтобы ретранслятор был запущен.

## Восстановить предыдущие параметры

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable восстанавливает только параметры, которые записал FailproofAI, сохраняет несвязанные изменения и восстанавливает предыдущий выбор отчетности о транскриптах каждого агента. Когда отключается последний управляемый локальный агент, ретранслятор прекращает принимать экспорт.

Для Codex disable также записывает `collector.agents.codex.sessions_resume_after` (эпоха в миллисекундах). Существующие байты развертывания рассматриваются как доставленные, поэтому сеансы, зафиксированные с OTEL, не загружаются повторно; более поздние добавления по-прежнему идут через отчетность о транскриптах.

Каждая команда поддерживает `--help`. См. [OpenTelemetry в Cloud](/ru/agenteye/opentelemetry) для примеров приложений и агентов кодирования.
