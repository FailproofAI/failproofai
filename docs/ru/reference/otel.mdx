`failproofai otel` настраивает опциональную отправку данных OpenTelemetry в FailproofAI Cloud. Сначала подключите вашу машину с помощью `failproofai config`. Поглощение OpenTelemetry всегда включено в Cloud, поэтому нет переключателя организации для его включения.

Интерактивная установка спрашивает о OpenTelemetry после поля Cloud-ключа и выбора агента. Опциональный шаг по умолчанию установлен на No. Выберите Yes для выбора OTEL-агентов; тот же код включения запускается после записи подключения. Нажатие Esc перед завершением установки отменяет все изменения. Автоматическая установка с предоставленным ключом, режим с открытым исходным кодом и сохранение подключения вас не подключают.

## Включение агента

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

Поддерживаемые агенты — это `claude`, `codex` и `copilot` (VS Code). Настройка Copilot требует исполняемого файла VS Code или установленного расширения Copilot. Оставшийся каталог параметров недостаточен; установка пропускает Copilot, если ничего из этого не найдено.

`--local` отправляет на локальный ретранслятор вместо прямой отправки в Cloud. Copilot использует ретранслятор автоматически, так как его параметры не могут хранить заголовок аутентификации.

Ретранслятор слушает только вашу машину. Настроенный демон FailproofAI подхватит изменение в течение нескольких секунд; вам не нужно его перезагружать. Если другое приложение занимает порт ретранслятора, статус сообщит об этом как отключённый, и демон продолжит работать.

<Warning>
Захват текста включен по умолчанию. Добавьте `--no-content`, чтобы исключить подсказки и детали инструментов. Разные версии агентов могут предоставлять разные элементы управления содержимым; проверьте, что экспортирует ваш агент, перед использованием с чувствительными данными.
</Warning>

Codex экспортирует только журналы разговоров, а не внутренние трассировки времени выполнения или метрики. Явный `log_user_prompt = false` в вашей конфигурации Codex остаётся отключённым; включение выводит примечание при сохранении этого выбора.

### Выбор одного пути отчётности

Если отправка стенограмм включена для агента, установка спросит:

> failproofai уже отправляет сессии Claude Code в Cloud. Отправить их через OTEL? Загрузка стенограмм для Claude Code остановится.

По умолчанию установлено No. `--yes` принимает переключение без подтверждения. Другие агенты и принудительное применение политик не затронуты.

Установка Codex ждёт подтверждения от демона об изменении сборщика перед записью параметров экспортера. Если подтверждение истекает, установка предупреждает вас о необходимости ожидания перед запуском Codex.

Config v2 сохраняет запомненный список трассировки в `agents.selected` (и историю обнаружения в `agents.seen`). Предпочтение стенограмм для каждого агента остаётся в `collector.agents.<agent>.sessions`, принадлежность OTEL в `otel.agents` и параметры ретранслятора в `collector.otlp.enabled` / `collector.otlp.port`. Эти отдельные ключи делают старые конфигурации OTEL читаемыми: установка может изменить список трассировки без потери предпочтения транспорта или состояния, необходимого для восстановления параметров агента.

## Проверка установки

```bash
failproofai otel status
```

Статус показывает каждого агента, управляются ли его параметры FailproofAI, пункт назначения, переключатель поглощения организации, состояние ретранслятора и результат последней загрузки ретранслятора.

`unknown` для переключателя организации означает, что сервер не предоставил его или был недоступен. Это не ошибка и не препятствует конфигурации на более старой версии Cloud.

Если Cloud ещё не поддерживает OTEL, ретранслятор сохраняет отклонённые экспорты вместо их отказа. Если более старая версия Cloud сообщает об отключении поглощения организацией, `enable` не пишет ничего и выходит с ошибкой.

## Печать конфигурации для приложения

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

Выход — это блок переменных окружения оболочки для экспортера OTLP/HTTP. Вывод Cloud устанавливает `OTEL_EXPORTER_OTLP_ENDPOINT` на базу OTLP Cloud, `https://<cloud>/otel`, а экспортер добавляет `/v1/<signal>`; переменная для конкретного сигнала, такая как `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, нужна с полным `https://<cloud>/otel/v1/logs`. Локальный вывод указывает на ретранслятор, `http://127.0.0.1:<port>`. Вывод Cloud включает настроенный API-ключ; относитесь к нему как к секрету. Локальный вывод исключает ключ. Чтобы использовать локальный вывод, сначала включите локального агента, чтобы ретранслятор работал.

## Восстановление предыдущих параметров

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable восстанавливает только параметры, которые написал FailproofAI, сохраняет несвязанные изменения и восстанавливает предыдущий выбор отправки стенограмм каждого агента. Когда последний управляемый локальный агент отключён, ретранслятор прекращает принимать экспорты.

Для Codex disable также записывает `collector.agents.codex.sessions_resume_after` (эпоха в миллисекундах). Существующие байты развёртывания рассматриваются как доставленные, поэтому сессии, захваченные через OTEL, не загружаются повторно; более поздние добавления всё ещё проходят через отправку стенограмм.

Каждая команда поддерживает `--help`. Обратитесь к разделу [OpenTelemetry в Cloud](/ru/agenteye/opentelemetry) для примеров приложений и агентов кодирования.
