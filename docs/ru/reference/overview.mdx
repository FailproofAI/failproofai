Выберите интеграцию, которая лучше всего соответствует тому, где уже работает ваш агент.

В этом разделе рассказывается о двух инструментах командной строки с разными функциями. `failproofai` запускается на машине, где работает ваш агент, и обеспечивает выполнение политики внутри цикла агента; `fp` взаимодействует с Failproof AI Cloud и читает результаты работы этого цикла. Настройка машины поддерживается только на Linux и macOS — `failproofai config` отказывает на чём-либо другом и ничего не записывает, чтобы не оставлять полуконфигурированную машину.

Созданные страницы HTTP API охватывают открытую поверхность `/v1`. Написанные вручную страницы объясняют рабочие процессы, охватывающие несколько конечных точек, или используют административные интерфейсы за пределами этой открытой поверхности.

## Подключите агента и проверьте данные

<Tabs>
  <Tab title="Панель управления">
    1. Откройте **Administration → Keys**, создайте ключ с `events:add` и `policies:pull` и скопируйте секрет.
    2. Настройте интеграцию, используя соответствующую страницу выше.
    3. Откройте **Observe → Events**, чтобы подтвердить поступление событий, затем **Observe → Sessions**, чтобы подтвердить, что они образуют полные запуски.
    4. Отфильтруйте по окружению интеграции и проверьте один сеанс на предмет полей модели, инструмента, ошибки и политики, необходимых для аудитов.

    Начните с ящика ключей. Выбранные предоставления определяют, может ли машина отправлять события и получать управляемые Cloud политики.

    ![Новый ящик ключей API для предоставления разрешений на приём событий и доставку политик.](/images/dashboard/key-create.png)

    После подключения интеграции используйте список Sessions, чтобы подтвердить, что её события группируются в полные запуски в ожидаемом окружении.

    ![Список Sessions для проверки того, что только что подключённая интеграция сообщает о полных запусках агента.](/images/dashboard/sessions-list.png)

    Откройте один из этих сеансов, прежде чем считать интеграцию завершённой; трассировка должна содержать доказательства модели, инструмента, ошибки и политики, необходимые вашим аудитам.
  </Tab>
  <Tab title="CLI">
    Создайте ключ машины, настройте и подключите эту машину, выберите политики, затем проверьте первый сеанс.

    ```bash
    fp keys create agent-production \
      --add events:add \
      --add policies:pull

    failproofai config --token <machine-key>

    failproofai policies add FailproofAI/policies

    failproofai flush --wait
    fp sessions --since 1h
    fp events --since 1h --limit 20
    ```

    Команды проверки не фильтруют по окружению, потому что только что настроенная машина помечает каждое событие как `local`. Добавьте `--env production` только после установки `collector.environment` — см. [Измените метку окружения](/ru/reference/events-and-configuration#change-an-environment-label).

    Передача токена является запросом на подключение, поэтому `failproofai config --token <machine-key>` делает то же самое в одной команде. Предпочитайте переменную окружения: аргумент может быть прочитан из `ps` каждым пользователем на машине и попадает в историю оболочки и журналы CI.

    Шаг политики не является необязательным. `failproofai config` устанавливает демон и подключает каждый поддерживаемый CLI агента, но намеренно не выбирает никакие политики, так что только что настроенная машина ничего не применяет, пока вы не добавите набор.

    Используйте `fp --json sessions ...`, когда другой инструмент будет использовать результат. Глобальные флаги, такие как `--json`, `--org` и `--base-url`, должны предшествовать команде.

    См. [справочник CLI Failproof AI](/ru/reference/failproof-cli) для локальных команд и [справочник CLI Failproof Cloud](/ru/reference/cloud-cli#cli-commands) для команд `fp`.
  </Tab>
</Tabs>
