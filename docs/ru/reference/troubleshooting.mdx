Начните с:

```bash
failproofai config --status
failproofai policies
```

## Агент не подключен

Повторите настройку:

```bash
failproofai config
```

Настройка поддерживает Linux и macOS. Ей требуется доступ администратора один раз для установки сервиса, но она никогда не запрашивает пароль sudo.

Проверьте пути и области harness в [Harnesses](/ru/reference/harnesses).

## Сеанс отсутствует

```bash
failproofai flush --wait
failproofai backfill --since 30d --dry-run
failproofai harness list
```

Удалите `--dry-run`, чтобы повторно отправить старую историю. Добавьте еще одно расположение транскриптов с помощью:

```bash
failproofai harness add-path <harness> [label=]<path>
```

Используйте метку, когда две локации содержат копии одного и того же проекта.

## Все защищенные действия отклоняются

На настроенной машине `failproofaid` — единственный оценивальный агент. Если он не может ответить, защищенные действия завершаются с отказом.

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

Запустите `failproofai config`, чтобы восстановить или переустановить сервис.

## Один пакет отклоняет

`failproofai policies` указывает пакеты, которые не загружаются. Выбранный пакет завершается с отказом вместо того, чтобы исчезнуть.

Частые причины:

- Артефакт изменился после установки.
- Манифест и встроенные политики не согласуются.
- Файл отсутствует или не может быть импортирован.
- Пакет использует неподдерживаемое событие, инструмент или форму политики.

Удалите пакет или установите исправленный релиз:

```bash
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

## Облако отключено

Предпочтите переменную окружения для ключа:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
failproofai config --status
```

Машина может независимо загружать политики и отправлять активность. Статус отображает оба варианта.

## Политика не заблокировала

Проверьте три вещи:

1. Политика включена: `failproofai policies`.
2. Её событие и инструмент совпадают с действием.
3. Этот harness может обеспечить выполнение события.

Отказ вызова инструмента проверяется на всех 12 поддерживаемых harness. Другие события различаются. См. [возможность обеспечения выполнения](/ru/reference/harnesses#enforcement-capability).

## Загрузки заблокированы

- `FAILPROOFAI_NO_DOWNLOAD=1` запрещает загрузки из сети.
- `FAILPROOFAI_DAEMON_BASE_URL` указывает загрузки сервиса на зеркало.
- `FAILPROOFAI_PACK_BASE_URL` указывает загрузки пакетов на зеркало.

Установленные пакеты продолжают работать при отключении загрузок.
