Попросите Failproof Assistant выполнить что угодно в Failproof AI на естественном языке. Он может анализировать сеансы и ошибки, выполнять запросы, создавать панели управления, исследовать оценки и оповещения, а также помогать создавать и запускать аудиты без необходимости переводить задачу в экраны продукта или команды CLI.

```text
Why did production checkout agents regress this week?
Build a dashboard for tool failures, latency, and evaluation scores.
Create an audit that finds agents retrying the same failed action without changing approach.
Show me the sessions behind the most common audit finding.
```

Помощник работает с данными и разрешениями, доступными в активной организации. Проверьте его доказательства и предлагаемые изменения перед применением действий, которые влияют на других пользователей или агентов.

## Обратитесь к помощнику

<Tabs>
  <Tab title="Панель управления">
    1. Выберите **Open agent chat** и опишите, что вы хотите понять, создать или использовать.
    2. Проверяйте вызовы инструментов помощника, таблицы и результаты запросов во время его работы.
    3. Откройте указанный сеанс, оповещение или запрос, чтобы проверить результат против исходных данных.
    4. Начните новый чат для другого исследования или используйте историю чата, чтобы продолжить тот же анализ.

    ![The Cloud assistant answering an observability question with supporting analysis and queries.](/images/dashboard/assistant.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp agent health
    fp agent models
    fp agent ask "Which production checkout agents had the most tool errors in the last 24 hours?"
    fp agent chats
    fp agent show <chat-id>
    fp agent ask "Open representative sessions" --chat <chat-id>
    ```

    Используйте `fp agent rename <chat-id> --title <title>`, чтобы сохранить исследование узнаваемым, и `fp agent delete <chat-id>` для его удаления.
  </Tab>
</Tabs>

## Эффективная работа с помощником

- Сначала поставьте ему цель; добавляйте окружение, рабочий процесс или временной диапазон, когда эти границы имеют значение.
- Рассматривайте созданный SQL и резюме как вспомогательное средство исследования, а не окончательное доказательство.
- Откройте представительные сеансы перед созданием аудита, проблемы, оповещения или политики.
- Держите фильтры организации, окружения и времени в явном виде.
- Сохраняйте полезный SQL как запрос, чтобы другой оператор мог воспроизвести результат.

<Warning>
  Помощник может читать только то, к чему имеет доступ ваш текущий пользователь. Не расширяйте разрешения, чтобы заставить работать вопрос; вместо этого попросите авторизованного оператора провести исследование.
</Warning>
