Попросите Failproof Assistant выполнить любую задачу в Failproof AI на естественном языке. Он может анализировать сессии и сбои, выполнять запросы, создавать панели управления, расследовать оценки и алерты, помогать создавать и запускать аудиты — без необходимости переводить задачу в экраны продукта или команды CLI.

```text
Why did production checkout agents regress this week?
Build a dashboard for tool failures, latency, and evaluation scores.
Create an audit that finds agents retrying the same failed action without changing approach.
Show me the sessions behind the most common audit finding.
```

Помощник работает с данными и разрешениями, доступными в активной организации. Проверьте его доказательства и предложенные изменения перед применением действий, которые влияют на других пользователей или агентов.

## Обращение к помощнику

<Tabs>
  <Tab title="Dashboard">
    1. Выберите **Open agent chat** и опишите, что вы хотите понять, создать или использовать.
    2. Просмотрите вызовы инструментов, таблицы и результаты запросов помощника по мере работы.
    3. Откройте цитированную сессию, алерт или запрос, чтобы проверить результат по исходным данным.
    4. Начните новый чат для другого расследования или используйте историю чата для продолжения той же линии анализа.

    ![Облачный помощник, отвечающий на вопрос об observability с поддерживающим анализом и запросами.](/images/dashboard/assistant.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp agent health
    fp agent models
    fp agent ask "Which production checkout agents had the most tool errors in the last 24 hours?"
    fp agent chats
    fp agent show <chat-id>
    fp agent ask "Open representative sessions" --chat <chat-id>
    ```

    Используйте `fp agent rename <chat-id> --title <title>` для сохранения узнаваемости расследования и `fp agent delete <chat-id>` для его удаления.
  </Tab>
</Tabs>

## Эффективная работа с помощником

- Сначала сформулируйте цель; добавьте окружение, workflow или диапазон времени, когда эти границы имеют значение.
- Рассматривайте сгенерированный SQL и резюме как инструмент расследования, а не окончательное доказательство.
- Откройте репрезентативные сессии перед созданием аудита, проблемы, алерта или политики.
- Сохраняйте явными фильтры организации, окружения и времени.
- Сохраняйте полезный SQL в качестве запроса, чтобы другой оператор мог воспроизвести результат.

<Warning>
  Помощник может читать только то, к чему имеет доступ ваш текущий пользователь. Не расширяйте разрешения для решения вопроса; попросите авторизованного оператора выполнить расследование.
</Warning>
