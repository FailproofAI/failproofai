Попросите Failproof Assistant выполнить любую операцию в Failproof AI на естественном языке. Он может анализировать сессии и сбои, запускать запросы, строить панели управления, расследовать оценки и алерты, а также помогать создавать и запускать аудиты без необходимости преобразовывать задачу в экраны продукта или команды CLI.

```text
Why did production checkout agents regress this week?
Build a dashboard for tool failures, latency, and evaluation scores.
Create an audit that finds agents retrying the same failed action without changing approach.
Show me the sessions behind the most common audit finding.
```

Помощник работает с данными и разрешениями, доступными в активной организации. Проверьте его доказательства и предлагаемые изменения перед применением действий, которые влияют на других пользователей или агентов.

## Обратитесь к помощнику

<Tabs>
  <Tab title="Dashboard">
    1. Выберите **Open agent chat** и опишите, что вы хотите понять, создать или выполнить.
    2. Просмотрите вызовы инструментов помощника, таблицы и результаты запросов во время его работы.
    3. Откройте указанную сессию, алерт или запрос, чтобы проверить результат против исходных данных.
    4. Начните новый чат для другого расследования или используйте историю чата для продолжения той же линии анализа.

    ![Облачный помощник отвечает на вопрос об observability с вспомогательным анализом и запросами.](/images/dashboard/assistant.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp agent health
    fp agent models
    fp agent ask "Which production checkout agents had the most tool errors in the last 24 hours?"
    fp agent chats
    fp agent show <chat-id>
    fp agent ask "Open representative sessions" --chat <chat-id>
    ```

    Используйте `fp agent rename <chat-id> --title <title>` для сохранения узнаваемости расследования и `fp agent delete <chat-id>` для удаления.
  </Tab>
</Tabs>

## Эффективно работайте с помощником

- Сначала дайте ему цель; добавьте окружение, рабочий процесс или временной диапазон, когда эти границы важны.
- Рассматривайте сгенерированный SQL и резюме как вспомогательное средство расследования, а не окончательное доказательство.
- Откройте репрезентативные сессии перед созданием аудита, проблемы, алерта или политики.
- Держите фильтры организации, окружения и времени явными.
- Сохраняйте полезный SQL как запрос, чтобы другой оператор мог воспроизвести результат.

<Warning>
  Помощник может читать только то, что может получить текущий пользователь. Не расширяйте разрешения для решения вопроса; вместо этого попросите авторизованного оператора провести расследование.
</Warning>
