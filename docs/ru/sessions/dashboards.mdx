Панели управления объединяют сохранённые запросы в операционное представление. Создавайте панель вокруг решения, которое вы ожидаете принять, — а не вокруг каждого доступного метрика.

## Создание панели управления

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Analyze → Queries**, создайте или откройте сохранённый запрос и проверьте его результат.
    2. Выберите **add to dashboard**, затем выберите существующую панель или создайте новую в **Analyze → Dashboards**.
    3. Откройте панель, перейдите в режим редактирования, расставьте плитки и сохраните макет.
    4. Вернитесь к запросу, когда понадобится изменить данные или фильтры за плиткой.

    ![Панель управления, составленная из сохранённых запросов по объёму событий, ошибкам, задержкам и использованию токенов модели.](/images/dashboard/dashboard-fleet.png)
  </Tab>
  <Tab title="CLI">
    CRUD операции для панелей управления не доступны в текущем Cloud CLI. Используйте CLI для создания и проверки сохранённого запроса, затем добавьте его на панель в пользовательском интерфейсе.

    ```bash
    fp query schema
    fp query create "production error rate" --sql "SELECT ..."
    fp query run <query-id>
    ```
  </Tab>
</Tabs>

Полезные группы панелей управления включают:

- **Models:** объём, задержка, использование токенов, частота ошибок и оценки по результатам оценивания.
- **Evaluations:** тренды по коэффициенту успеха и оценкам по агентам или окружениям.
- **Tools:** объём вызовов, частота сбоев, длительность и повторные вызовы.
- **Hooks and policies:** решения, отказы и коэффициент совпадения политик.
- **Custom workflow metrics:** результаты ваших собственных полей событий и SQL.

Начните с сохранённого запроса, проверьте его результат, затем добавьте его как плитку. Держите фильтры для production и development явными, чтобы тестовый трафик не скрыл регрессию.

<Tip>
  Назначьте каждой панели управления владельца и вопрос для ответа, например "Надёжность checkout-agent'а хуже, чем на прошлой неделе?"
</Tip>
