Errors предоставляет вам ориентированный на сбои вид по всем сеансам. Группируйте по типу ошибки, агенту, окружению, модели, инструменту или временному окну, чтобы найти повторяющиеся операционные проблемы.

## Исследование ошибок

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Observe → Errors**.
    2. Отфильтруйте по окружению, типу события, типу ошибки, агенту, ID сеанса или поисковому запросу.
    3. Разверните сгруппированную ошибку, чтобы увидеть экземпляры. Выберите строку, чтобы открыть точное событие в его сеансе.
    4. Нажмите на значок звонка в представительной ошибке, чтобы создать оповещение для похожих ошибок.

    ![Страница Errors с гистограммой сбоев, сгруппированными ошибками и элементом управления для создания оповещения.](/images/dashboard/errors.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp errors --env production --since 24h
    fp errors --error-type TimeoutError --agent-id checkout-agent
    fp errors --aggregate --env production --since 7d
    ```

    Используйте `fp events --full --session-id <id>`, когда нужна исходная полезная нагрузка за сводкой по ошибкам.
  </Tab>
</Tabs>

## Используйте Errors когда нужно

- Найти наиболее частый класс ошибок в production.
- Определить, вызывает ли один инструмент или модель всплеск ошибок.
- Перейти от совокупного количества к представительским сеансам.
- Создать оповещение для повторений.
- Включить затронутую популяцию в аудит.

Ошибка — это наблюдаемое событие. Неудачная оценка — это суждение о качестве, а вывод аудита — это исследованный паттерн сбоя. Помните об этих различиях, выбирая, какой рабочий процесс ответа использовать.
