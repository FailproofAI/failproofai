Errors предоставляет представление сбоев в разрезе сеансов. Группируйте по типу ошибки, агенту, окружению, модели, инструменту или временному окну, чтобы найти повторяющиеся проблемы в эксплуатации.

## Исследование ошибок

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Observe → Errors**.
    2. Отфильтруйте по окружению, типу события, типу ошибки, агенту, ID сеанса или тексту поиска.
    3. Разверните сгруппированную ошибку, чтобы увидеть её вхождения. Выберите строку, чтобы открыть точное событие в его сеансе.
    4. Выберите значок колокольчика для репрезентативной ошибки, чтобы создать оповещение для похожих ошибок.

    ![Страница Errors с гистограммой сбоев, сгруппированными ошибками и элементом управления для создания оповещения.](/images/dashboard/errors.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp errors --env production --since 24h
    fp errors --error-type TimeoutError --agent-id checkout-agent
    fp errors --aggregate --env production --since 7d
    ```

    Используйте `fp events --full --session-id <id>`, если вам нужна исходная полезная нагрузка, лежащая в основе сводки ошибок.
  </Tab>
</Tabs>

## Используйте Errors, когда необходимо

- Найти наиболее частый класс ошибок в production.
- Определить, вызывает ли скачок один инструмент или модель.
- Перейти от агрегированного количества к репрезентативным сеансам.
- Создать оповещение о повторении.
- Включить затронутую совокупность в аудит.

Ошибка — это наблюдаемое событие. Неудачная оценка — это суждение о качестве, а вывод аудита — это исследованный паттерн сбоев. Учитывайте эти различия при выборе рабочего процесса ответа.
