Errors предоставляет вам представление отказов по всем сессиям. Группируйте по типу ошибки, агенту, окружению, модели, инструменту или временному окну, чтобы найти повторяющиеся операционные проблемы.

## Исследование ошибок

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Observe → Errors**.
    2. Отфильтруйте по окружению, типу события, типу ошибки, агенту, ID сессии или поисковому запросу.
    3. Разверните сгруппированную ошибку, чтобы увидеть её повторения. Выберите строку, чтобы открыть точное событие в его сессии.
    4. Выберите значок колокольчика на репрезентативной ошибке, чтобы создать оповещение для похожих ошибок.

    ![Страница Errors с гистограммой отказов, сгруппированными ошибками и элементом управления для создания оповещения.](/images/dashboard/errors.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp errors --env production --since 24h
    fp errors --error-type TimeoutError --agent-id checkout-agent
    fp errors --aggregate --env production --since 7d
    ```

    Используйте `fp events --full --session-id <id>`, когда вам нужна полная нагрузка за ошибкой.
  </Tab>
</Tabs>

## Используйте Errors, когда вам нужно

- Найти самый частый класс ошибок в production.
- Определить, вызывает ли один инструмент или модель всплеск.
- Перейти от совокупного подсчёта к репрезентативным сессиям.
- Создать оповещение для повторений.
- Включить затронутую популяцию в аудит.

Ошибка — это наблюдаемое событие. Неудачная оценка — это суждение о качестве, а результат аудита — это исследованный паттерн отказа. Сохраняйте эти различия при решении, какой рабочий процесс ответа использовать.
