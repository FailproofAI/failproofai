Оценки применяют согласованные суждения к сессиям агентов. Используйте их для сигналов, которые должны измеряться постоянно, а не исследоваться только во время аудита.

Оценивающее устройство получает завершённую сессию, что означает одно из двух: сессия отправила событие завершения или перестала отправлять события дольше, чем `inactivity_timeout_secs` оценивающего устройства. Нет оценки выполнения, которое ещё находится в процессе.

<Note>
  Автоматическая оценка работает на уровне всего развёртывания и отключена до тех пор, пока оператор не установит `EVALUATOR_ENDPOINT`. До этого момента это представление пусто, `fp evals` ничего не возвращает, а `fp sessions` показывает пустой статус для каждой строки — обычно это означает, что оценивающее устройство не настроено, а не что всё получило низкую оценку. See [Evaluator SDK](/ru/reference/evaluator-sdk).
</Note>

  <Tab title="CLI">
    ```bash
    fp list score_filters
    fp evals --agent-id checkout-agent --aggregate
    fp evals --aggregate --status error --since 7d
    fp evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3 --since 7d
    fp evals --scores-full --since 24h
    ```

    Всё здесь требует `evaluations:read` — включая `fp sessions`, который читает результат последней оценки. Вот почему ключ с областью `events:read` видит трассировки, но не оценки.

    Начните с `fp list score_filters`: он возвращает ключи оценок, которые это развёртывание действительно производит, что делает фильтр `--score` проверяемым, а не предположением.

    `--score KEY:MIN..MAX` имеет каждую границу опциональной и повторяемой, со всеми диапазонами обязательными вместе: `helpfulness:0.5..0.8`, `tool_efficiency:..0.3`, `factuality:0.9..`. Неправильное значение отклоняется до запроса, а не молча игнорируется. `--status` принимает ровно одно из `done`, `error` или `timeout`. `--scores-full` выводит каждую пару оценок вместо первых нескольких плюс `+N`. `--all` останавливается на `--limit`, который по умолчанию равен 50.

    Глобальные параметры идут перед командой, поэтому автоматизация читает `fp --json evals --aggregate`.

    Демон ставит метку времени для каждого события с окружением `local`, если вы его не измените, поэтому `--env production` не совпадает ни с чем при стандартной установке. See [Change an environment label](/ru/reference/events-and-configuration#change-an-environment-label).
  </Tab>
</Tabs>

## Что обменивает оценивающее устройство

| Сообщение | Поля |
| --- | --- |
| `EvalRequest` (вход) | `schema_version` (в настоящее время `"1"`), `session_id`, `agent_id`, `environment`, `started_at`, `ended_at` и `events` — полный упорядоченный поток, каждое событие содержит полный набор данных. |
| `EvalResponse` (выход) | `scores` как числовые ключи, `reasoning` отражающие их, и `summary`. |
| `JobPending` (выход) | `job_id` и `next_poll_secs` для работы, которая не может завершиться в одном запросе. |

`ended_at` присутствует только в том случае, если сессия отправила событие завершения, поэтому сессия, отправленная при неактивности, приходит без него. Кадр опроса следует `next_poll_secs`, затем `default_poll_interval_secs` оценивающего устройства, затем `EVALUATOR_POLLING_INTERVAL_SECS` сервера, ограниченный между одной секундой и одним часом с крышкой на одном часу по часам.

Поскольку запрос содержит полные наборы данных события, оценивающее устройство видит полное содержание транскрипта. Рассматривайте доставку оценивающего устройства как доставку транскрипта при принятии решения о том, какие данные может отправить машина.

## Хорошие цели для оценки

- Завершение задачи или правильность
- Обоснованность и риск галлюцинации
- Выбор инструмента и эффективность использования инструмента
- Соответствие политике или процессу
- Бюджеты стоимости и задержки
- Требуемая эскалация на человека

Ключи оценок — это стабильные идентификаторы. Переименование одного начинает новый ряд диаграммы вместо изменения старого, что молча нарушает тренд — выберите имя перед тем, как строить на его основе диаграмму.

## От оценки к ответу

Показывайте оценки на панелях управления для отслеживания тенденций. Создавайте оповещения для пороговых значений или сложных условий. Когда оценка снижается в популяции, проведите аудит, чтобы выяснить почему; когда причина — повторяющееся действие, разверните политику.
