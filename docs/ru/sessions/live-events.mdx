Live events помогают вам подтвердить инструментирование и отследить рискованный запуск без ожидания завершения сессии.

## Наблюдайте за активностью

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Observe → Events**.
    2. Начните с текущего временного окна без фильтров, чтобы подтвердить поступление данных.
    3. Фильтруйте по окружению, типу события, агенту или сессии. Используйте поиск для текста полезной нагрузки.
    4. Выберите событие, чтобы просмотреть его сводку и детали. Перейдите по ссылке сессии для полной трассировки.

    ![Поток live Events с фильтрами по времени, окружению, типу события, агенту, модели, контексту, сессии и тексту.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    Поток по умолчанию исключает необработанные полезные нагрузки. Используйте `--full` только для расследования ограниченной сессии.
  </Tab>
</Tabs>

Используйте поток событий, чтобы ответить на три ключевых вопроса:

- Отправляет ли ожидаемый агент данные в правильное окружение?
- Поступают ли вызовы модели, вызовы инструментов и решения политик по порядку?
- Прекратила ли сессия делать прогресс или началась повторять одно и то же действие?

Типы событий включают события жизненного цикла агента, запросы и ответы модели, использование инструментов и результаты, выполнение хуков, ожидание человека и прерывания, а также явные ошибки. ID корреляции связывают парные события, такие как вызов инструмента и его результат.

<Tip>
  Держите live представление широким при проверке новой интеграции. Добавляйте фильтры только после того, как вы увидите первое событие; неправильный фильтр может выглядеть как ошибка приема данных.
</Tip>

Если события не появляются, запустите `failproofai config --status`, затем [устраните неполадки с приемом](/ru/reference/troubleshooting).
