Живые события помогают подтвердить инструментацию и отслеживать рискованные запуски без ожидания завершения сессии.

## Просмотр активности

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Observe → Events**.
    2. Начните с текущего временного окна без фильтров, чтобы подтвердить поступление данных.
    3. Фильтруйте по окружению, типу события, агенту или сессии. Используйте поиск для поиска текста в полезной нагрузке.
    4. Выберите событие для изучения его сводки и деталей. Перейдите по ссылке сессии для полной трассировки.

    ![Поток живых событий, показывающий трафик от шлюза чата Hermes наряду с запусками coding-CLI, отфильтрованные по времени, окружению, типу события, агенту, модели, контексту и сессии.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    Поток по умолчанию не включает необработанные полезные нагрузки. Используйте `--full` только для исследования ограниченной сессии.
  </Tab>
</Tabs>

Используйте поток событий для ответа на три непосредственных вопроса:

- Отправляет ли ожидаемый агент отчеты в правильное окружение?
- Поступают ли вызовы моделей, вызовы инструментов и решения политик в правильном порядке?
- Прекратила ли сессия прогресс или начала повторять действие?

Типы событий включают события жизненного цикла агента, запросы и ответы моделей, использование и результаты инструментов, выполнение хуков, ожидание людьми и прерывания, а также явные ошибки. Идентификаторы корреляции связывают парные события, такие как вызов инструмента и его результат.

<Tip>
  Держите прямую трансляцию широкой при проверке новой интеграции. Добавляйте фильтры только после того, как увидите первое событие; неправильный фильтр может выглядеть как ошибка приема.
</Tip>

Если события не появляются, запустите `failproofai config --status`, затем [устраните неполадки с приемом](/ru/reference/troubleshooting).

Агенты, которые не работают в одной из 12 поддерживаемых [систем](/ru/reference/harnesses), передают те же типы событий через [Python SDK](/ru/reference/custom-agents), включая события взаимодействия с человеком (`human_wait`, `human_input`, `human_interrupt`), от которых зависят агенты шлюза и боевые агенты.
