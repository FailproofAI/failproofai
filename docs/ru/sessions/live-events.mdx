Живые события помогают вам подтвердить инструментализацию и следить за рисковым запуском без ожидания завершения сеанса.

## Просмотр активности

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Observe → Events**.
    2. Начните с текущего временного окна без фильтров, чтобы подтвердить поступление данных.
    3. Фильтруйте по окружению, типу события, агенту или сеансу. Используйте поиск для текста в полезной нагрузке.
    4. Выберите событие, чтобы просмотреть его сводку и детали. Следуйте ссылке сеанса для полной трассировки.

    ![Поток живых событий с фильтрами по времени, окружению, типу события, агенту, модели, контексту, сеансу и тексту.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    Канал по умолчанию опускает необработанные полезные нагрузки. Используйте `--full` только для ограниченного исследования сеанса.
  </Tab>
</Tabs>

Используйте поток событий, чтобы ответить на три немедленных вопроса:

- Сообщает ли ожидаемый агент в правильное окружение?
- Поступают ли вызовы модели, вызовы инструментов и решения политики в правильном порядке?
- Прекратил ли сеанс прогресс или начал повторять действие?

Типы событий включают события жизненного цикла агента, запросы и ответы модели, использование инструментов и результаты, выполнение hook'ов, ожидание человека и прерывания, а также явные ошибки. Идентификаторы корреляции связывают парные события, такие как вызов инструмента и его результат.

<Tip>
  Держите живое представление широким при проверке новой интеграции. Добавляйте фильтры только после того, как вы увидите первое событие; неправильный фильтр может выглядеть как ошибка при приёме данных.
</Tip>

Если события не отображаются, запустите `failproofai config --status`, затем [устраните неполадки при приёме](/ru/reference/troubleshooting).
