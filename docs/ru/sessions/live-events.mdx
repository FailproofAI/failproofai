Live events помогут вам подтвердить инструментирование и отследить рискованный запуск без ожидания завершения сеанса.

## Наблюдение за активностью

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Observe → Events**.
    2. Начните с текущего временного окна и без фильтров, чтобы подтвердить поступление данных.
    3. Фильтруйте по окружению, типу события, агенту или сеансу. Используйте поиск по тексту полезной нагрузки.
    4. Выберите событие, чтобы проинспектировать его резюме и детали. Перейдите по ссылке сеанса для полной трассировки.

    ![Поток Live Events, показывающий трафик от шлюза Hermes chat рядом с запусками coding-CLI, отфильтрованный по времени, окружению, типу события, агенту, модели, контексту и сеансу.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    Поток по умолчанию исключает исходные полезные нагрузки. Используйте `--full` только для ограниченного расследования сеанса.
  </Tab>
</Tabs>

Используйте поток событий, чтобы ответить на три срочных вопроса:

- Отправляет ли ожидаемый агент отчёты в правильное окружение?
- Поступают ли вызовы модели, вызовы инструментов и решения политики в порядке?
- Остановил ли сеанс прогресс или начал повторять действие?

Типы событий включают события жизненного цикла агента, запросы и ответы модели, использование и результаты инструментов, выполнение хуков, ожидание человека и прерывания, а также явные ошибки. ID корреляции связывают парные события, такие как вызов инструмента и его результат.

<Tip>
  Держите live view широким при проверке новой интеграции. Добавляйте фильтры только после того, как вы увидите первое событие; неправильный фильтр может выглядеть как неудачное поглощение.
</Tip>

Если события не появляются, выполните `failproofai config --status`, затем [устраните неполадки с поглощением](/ru/reference/troubleshooting).

Агенты, которые не работают в одном из 12 поддерживаемых [harnesses](/ru/reference/harnesses), отправляют те же типы событий через [Python SDK](/ru/reference/custom-agents), включая события взаимодействия с человеком (`human_wait`, `human_input`, `human_interrupt`), на которые полагаются шлюзовые и производственные агенты.
