Прямые события помогают подтвердить инструментирование и отследить рискованный запуск, не дожидаясь завершения сеанса.

## Наблюдение за активностью

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Observe → Events**.
    2. Начните с текущего временного окна и без фильтров, чтобы подтвердить поступление данных.
    3. Фильтруйте по окружению, типу события, агенту или сеансу. Используйте поиск для текста полезной нагрузки.
    4. Выберите событие, чтобы просмотреть его краткое описание и подробности. Перейдите по ссылке сеанса для полной трассировки.

    ![Поток прямых событий, показывающий трафик от шлюза чата Hermes наряду с запусками coding-CLI, отфильтрованные по времени, окружению, типу события, агенту, модели, контексту и сеансу.](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    Поток по умолчанию исключает сырые полезные нагрузки. Используйте `--full` только для расследования ограниченного сеанса.
  </Tab>
</Tabs>

Используйте поток событий для ответа на три критических вопроса:

- Сообщает ли ожидаемый агент в правильное окружение?
- Поступают ли вызовы моделей, вызовы инструментов и решения политик по порядку?
- Остановился ли сеанс в прогрессе или начал повторять действие?

Типы событий включают события жизненного цикла агента, запросы и ответы модели, использование и результаты инструментов, выполнение хуков, ожидание человека и прерывания, а также явные ошибки. Идентификаторы корреляции связывают парные события, такие как вызов инструмента и его результат.

<Tip>
  Держите прямой просмотр широким при проверке новой интеграции. Добавляйте фильтры только после того, как увидите первое событие; неправильный фильтр может выглядеть как сбой приема данных.
</Tip>

Если события не появляются, запустите `failproofai config --status`, затем [устраните неполадки приема данных](/ru/reference/troubleshooting).

Агенты, которые не работают в одном из 12 поддерживаемых [harnesses](/ru/reference/harnesses), сообщают об одинаковых типах событий через [Python SDK](/ru/reference/custom-agents), включая события взаимодействия человека (`human_wait`, `human_input`, `human_interrupt`), которые используют шлюзовые и производственные агенты.
