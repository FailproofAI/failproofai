Используйте Models для отслеживания изменений надежности или стоимости при использовании разных моделей, агентов, окружений или временных диапазонов.

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Observe → Models**.
    2. Установите временной диапазон и отфильтруйте по окружению, модели, агенту или ID сессии.
    3. Просмотрите задержку, потребление токенов, использование контекстного окна и распределение моделей.
    4. Выберите точку на графике или сегмент распределения, чтобы открыть соответствующие события.

    ![Страница Models с представлениями задержки, процентиля, токенов, стоимости, контекстного окна и распределения моделей.](/images/dashboard/models.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp list models
    fp events --event-type model_request,model_response --since 24h
    fp --json events --event-type model_response --since 24h --all --limit 500 --fields ts,agent_id,session_id,output_tokens,context_window,context_fill
    ```

    Все три команды требуют `events:read`.

    `--fields` выбирает колонки; он не фильтрует строки. Используйте его вместе с `--event-type` и временным окном, иначе вы получите 50 самых новых событий каждого типа с пустыми значениями `output_tokens` и `context_fill` для всех немодельных событий. `--all` работает с `--limit`, который по умолчанию равен 50.

    Читайте `context_fill` рядом с `context_window`: значение заполнения ничего не значит без окна, в отношении которого оно измеряется.

    Демон ставит временную метку каждого события с окружением `local`, если вы его не измените, поэтому `--env production` ничего не найдет при стандартной установке. См. [Change an environment label](/ru/reference/events-and-configuration#change-an-environment-label).
  </Tab>
</Tabs>

## Возможности и ограничения CLI

Поток событий по умолчанию не содержит полезной нагрузки. Он содержит `output_tokens`, `context_window` и `context_fill` как выбранные колонки и ничего больше о вызове модели:

| Значение | Где оно находится |
| --- | --- |
| Выходные токены, контекстное окно, заполнение контекста | Колонки облегченного потока — доступны непосредственно из `fp events`. |
| Имя модели | Полезная нагрузка — используйте `fp events --full`, ограничено одной сессией. |
| Входные токены | Полезная нагрузка — SDK записывает обе части, только выходная часть выбирается. |
| Задержка за вызов | Нет колонки `duration_ms` в облегченном потоке, и `model_response` SDK тоже ее не содержит. Получите ее, сопоставив запрос с его ответом. |

`model_request` и `model_response` сопоставляются по `request_id`. Это поле существует именно для того, чтобы запрос можно было сопоставить с его ответом, и это единственный способ вычислить задержку за вызов из необработанных событий:

```bash
fp --json events --full --event-type model_request,model_response --session-id <session-id> --all --limit 500
```

Имена моделей поступают в точности из стенограммы каждого хоста. Ничто в пути захвата их не нормализует, поэтому одна и та же базовая модель может отображаться под несколькими ID-й, специфичными для провайдера, в диаграмме распределения. Запустите `fp list models`, чтобы увидеть написание моделей, которые фактически используются в развертывании.

Используйте сохраненный запрос для агрегатов уровня модели, которые не открыты как отдельная команда CLI.
