Сессия — это лучшая отправная точка, когда агент ведёт себя неожиданно. Она объединяет запросы модели, ответы, вызовы инструментов, взаимодействия с человеком, ошибки, оценки и решения политик, относящиеся к одному запуску.

Сессии выглядят одинаково независимо от того, какой инструмент их создал. Запуск Claude Code, переписывающий репозиторий, агент Hermes, отвечающий на вопросы клиента в Slack, и служба Python, инструментированная с помощью SDK, все сохраняются в одном формате трассировки, поэтому один вид охватывает весь парк.

Следите за одним запуском агента от его цели через вызовы моделей, инструменты и финальный ответ.

## Найти сессию

<Tabs>
  <Tab title="Dashboard">
    1. На боковой панели Cloud перейдите в **Observe → Sessions**.
    2. Установите временное окно, затем фильтруйте по окружению, статусу, агенту или ID сессии.
    3. Добавьте диапазоны оценок или метрик, если вам нужен срез по качеству, стоимости, токенам или задержке.
    4. Выберите строку, чтобы открыть её трассировку. Используйте элемент копирования рядом с ID сессии при её передаче.

    ![Список сессий, показывающий по одной строке на запуск с фильтрами окружения, агента, статуса и оценки.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    Добавьте `--agents` для расширения многоагентных запусков, `--all` для разбиения на страницы или `--fields` для выбора столбцов вывода.
  </Tab>
</Tabs>

## Что вы можете делать

- Найти запуск по агенту, окружению, времени, модели, типу события или состоянию ошибки.
- Проследить точную последовательность, которая привела к результату.
- Сравнить успешные и неудачные запуски.
- Открыть доказательства, использованные аудиторским выводом или уведомлением об инциденте.
- Экспортировать сессию, когда вам нужна автономная запись.

## Надёжный порядок исследования

1. Подтвердите цель сессии и окружение.
2. Найдите первую ошибку или неожиданное решение — не только финальный сбой.
3. Проверьте контекст модели и входные данные инструмента непосредственно перед ним.
4. Проверьте повторные попытки, задержку и прерывания человеком.
5. Просмотрите оценки и решения политик.
