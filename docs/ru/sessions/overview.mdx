Сеанс — это лучшая отправная точка, когда агент ведет себя неожиданно. Он объединяет запросы к модели, ответы, вызовы инструментов, взаимодействия с человеком, ошибки, оценки и решения политик, относящиеся к одному запуску.

Сеансы выглядят одинаково независимо от того, какой инструмент их создал. Запуск Claude Code, переписывающий репозиторий, агент Hermes, отвечающий клиенту в Slack, и сервис на Python, оборудованный SDK, все используют один и тот же формат трассировки, поэтому одно представление охватывает весь парк.

Следуйте одному запуску агента от его цели через вызовы моделей, инструменты к финальному ответу.

## Найти сеанс

Если сеанс был перемещен в холодное хранилище после достижения лимита запусков,
увеличение лимита в пределах одного расчетного периода освобождает подходящие сеансы
в первую очередь старейшие. Повторные попытки доставки не заставляют сеанс потреблять лимит дважды.

<Tabs>
  <Tab title="Панель управления">
    1. В боковой панели Cloud перейдите к **Observe → Sessions**.
    2. Установите временное окно, затем отфильтруйте по окружению, статусу, агенту или ID сеанса.
    3. Добавьте диапазоны оценок или метрик, когда вам нужна срезка по качеству, стоимости, токенам или задержке.
    4. Выберите строку, чтобы открыть её трассировку. Используйте элемент копирования рядом с ID сеанса при его отправке.

    ![Список сеансов с одной строкой на запуск, фильтрами по окружению, агенту, статусу и оценке.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    Добавьте `--agents` для развертывания мультиагентных запусков, `--all` для разбиения по страницам или `--fields` для выбора столбцов вывода.
  </Tab>
</Tabs>

## Что вы можете сделать

- Найти запуск по агенту, окружению, времени, модели, типу события или состоянию ошибки.
- Следовать точной последовательности, которая привела к результату.
- Сравнивать успешные и неудачные запуски.
- Открыть доказательства, использованные поиском аудита или инцидентом оповещения.
- Экспортировать сеанс, когда вам нужна автономная запись.

## Надежный порядок расследования

1. Подтвердите цель сеанса и окружение.
2. Найдите первую ошибку или неожиданное решение — не только финальный отказ.
3. Проверьте контекст модели и входные данные инструмента непосредственно перед ним.
4. Проверьте повторные попытки, задержку и прерывания человеком.
5. Проверьте оценки и решения политик.
