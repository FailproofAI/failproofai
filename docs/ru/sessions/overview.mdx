Сеанс — это один запуск агента. Он связывает подсказку, вызовы модели, инструменты, ошибки, ввод пользователя, решения политики и финальный результат.

## Где находятся сеансы

<Tabs>
  <Tab title="Local">
    Запустите `failproofai`, чтобы открыть панель управления по адресу `http://localhost:8020`. История сеансов остаётся на этом компьютере.
  </Tab>
  <Tab title="Cloud">
    Подключите компьютер, затем откройте **Observe → Sessions**:

    ```bash
    export FAILPROOFAI_CLOUD_TOKEN="<key>"
    failproofai config
    ```

    Cloud получает полные расшифровки по умолчанию. Чтобы отправлять только решения политики, сначала подключитесь, затем установите `collector.sessions` в значение `false` в файле `~/.failproofai/config.json`. Текущий флаг установки `--no-transcripts` не применяет этот параметр.
  </Tab>
</Tabs>

Сеансы поступают от 12 поддерживаемых [оберток агентов](/ru/reference/harnesses) и от агентов, инструментированных с помощью [Python SDK](/ru/reference/custom-agents).

## Поиск сеанса

В Cloud фильтруйте по времени, окружению, статусу, агенту или ID сеанса. Из CLI:

```bash
fp sessions --since 24h
fp sessions --status error,timeout --agent-id checkout-agent
fp --json sessions --session-id <session-id>
```

Используйте `fp errors --since 24h` для сбоев, которые никогда не оценивались. `fp sessions --status` использует последний результат оценки, поэтому неоценённый сеанс не имеет статуса.

## Чтение запуска

1. Подтвердите цель и окружение агента.
2. Найдите первую ошибку или неожиданное решение.
3. Проверьте контекст модели и входные данные инструмента непосредственно перед этим.
4. Проверьте повторные попытки, задержку и прерывания со стороны пользователя.
5. Просмотрите оценки и решения политики.

## Если сеанс отсутствует

```bash
failproofai flush --wait
failproofai config --status
failproofai backfill --since 30d --dry-run
```

Используйте `failproofai harness add-path <harness> [<label>=]<path>`, когда сеансы находятся вне обычного местоположения обёртки, например в другом профиле, домашней папке контейнера или подключённом командном каталоге.
