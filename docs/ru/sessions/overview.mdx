Сессия — это лучшая точка старта, когда агент ведёт себя неожиданно. Она объединяет запросы к модели, ответы, вызовы инструментов, взаимодействия с человеком, ошибки, оценки и решения по политикам, относящиеся к одному прогону.

Сессии выглядят одинаково независимо от того, какая система их создала. Прогон Claude Code, переписывающий репозиторий, агент Hermes, отвечающий клиенту в Slack, и сервис на Python, инструментированный с помощью SDK, все попадают в один формат трассировки, поэтому один вид охватывает весь парк.

Проследите один прогон агента от его цели через вызовы моделей, инструменты и финальный ответ.

## Найти сессию

<Tabs>
  <Tab title="Dashboard">
    1. На панели Cloud перейдите в **Observe → Sessions**.
    2. Установите временное окно, затем отфильтруйте по среде, статусу, агенту или ID сессии.
    3. Добавьте диапазоны оценки или метрик, когда вам нужен срез по качеству, стоимости, токенам или задержке.
    4. Выберите строку, чтобы открыть её трассировку. Используйте элемент копирования рядом с ID сессии при её передаче.

    ![Список сессий с одной строкой за прогон, показывающий фильтры по среде, агенту, статусу и оценке.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    Добавьте `--agents` для развёртывания многоагентных прогонов, `--all` для постраничного просмотра или `--fields` для выбора столбцов вывода.
  </Tab>
</Tabs>

## Что вы можете делать

- Найти прогон по агенту, среде, времени, модели, типу события или состоянию ошибки.
- Проследить точную последовательность, которая привела к результату.
- Сравнивать успешные и неудачные прогоны.
- Открыть доказательства, использованные при обнаружении аудита или инциденте оповещения.
- Экспортировать сессию, когда вам нужна оффлайн-запись.

## Надёжный порядок расследования

1. Подтвердите цель сессии и среду.
2. Найдите первую ошибку или неожиданное решение — не только финальный отказ.
3. Изучите контекст модели и вход инструмента непосредственно перед этим.
4. Проверьте повторные попытки, задержку и прерывания человеком.
5. Просмотрите оценки и решения по политикам.
