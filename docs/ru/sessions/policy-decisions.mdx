Решения политик показывают, что делал Failproof AI во время выполнения агента.

<Tabs>
  <Tab title="Dashboard">
    Перейдите в **Observe → policy**, чтобы просмотреть решения, процент блокировок, машины и развёрнутые назначения.

    ![Страница Policy, показывающая итого решений, фильтр машин, активность enforcement во времени и таблицу сопоставления политик.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp guardrails summary --since 24h
    fp guardrails timeline --since 24h
    failproofai policies
    failproofai config --status
    ```

    `--since` принимает значения `1h`, `6h`, `24h` или `7d`. Добавьте `--machine <id>`, чтобы сосредоточиться на одной машине.
  </Tab>

## Прочитайте развёртывание в режиме observe

Режим observe запускает реальную политику и записывает любое решение `deny` или `instruct`. Агент по-прежнему может продолжать работу.

```bash
fp fleet deploy <machine> --add <policy>:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add <policy>:enforce
```

<Warning>
  Просто `--add <policy>` применяет enforcement немедленно, если у политики нет существующего развёртывания. Добавьте `:observe` для shadow развёртывания.
</Warning>

Записываются только наблюдаемые решения, не являющиеся allow. Timeout записывается как allow, так как это то же самое, что происходит в режиме enforce.

Записанный deny не является доказательством того, что harness остановил действие. Tool-call deny проверяются во всех 12 поддерживаемых harness; другие события различаются. См. [возможности enforcement](/ru/reference/harnesses#enforcement-capability).

## Исследуйте неожиданный результат

| Что вы видите | Проверьте |
| --- | --- |
| Нет решений | `failproofai config --status` и находится ли сессия на паузе |
| Много отказов без имени политики | [Поведение при ошибке политики](/ru/policies/failure-behavior) |
| Все защищённые действия отклонены | Является ли служба `failproofaid` здоровой |
| Отказ, который вы не можете отключить | `block-failproofai-commands` всегда включен |
| Нет данных для `--env production` | Новые машины используют окружение `local` |
