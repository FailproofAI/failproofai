Запросы — это гибкий уровень под панелями управления, аудитами и расследованиями. Используйте ad-hoc SQL для проверки идеи, а затем сохраните запрос, когда он станет частью регулярного рабочего процесса.

## Создание и выполнение запроса

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Analyze → Queries** и выберите **new query**.
    2. Откройте обозреватель схемы и выберите поля из данных событий, сессий или оценок.
    3. Напишите SQL, добавьте параметры при необходимости и выполните запрос.
    4. Сохраните его с понятным названием и описанием, затем используйте **add to dashboard**, когда результат должен отслеживаться.

    Редактор запросов объединяет схему событий, SQL, параметры и предпросмотр результатов, чтобы вы могли проверить вопрос перед сохранением.

    ![Редактор SQL-запросов с обозревателем схемы и сеткой живых результатов.](/images/dashboard/query-lab.png)

    Сохраненные запросы затем появляются в общей библиотеке, где коллеги могут переиспользовать их или добавить результаты на панели управления.

    ![Библиотека сохраненных Queries с переиспользуемыми встроенными и пользовательскими запросами.](/images/dashboard/queries.png)

    Используйте понятное название и описание, чтобы результат оставался понятным без повторного открытия его SQL.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    Используйте `fp query list` для поиска ID и `fp query delete <query-id>` для удаления сохраненного запроса.
  </Tab>
</Tabs>

## Типичное использование

- Найти сессии с повторяющимися вызовами одного инструмента.
- Сравнить оценки по моделям или окружениям.
- Измерить время между ожиданием человека и возобновлением.
- Определить отказы политики, за которыми следует успешная альтернатива.
- Создать когорту для аудита.

Откройте **Queries → Schema** перед написанием запросов с незнакомыми полями. Предпочитайте явные фильтры по времени и окружению, и ограничивайте результаты во время исследования.

<Warning>
  Запрос может выявить подозрительный паттерн, но он не устанавливает режим сбоя самостоятельно. Откройте репрезентативные трассировки или запустите аудит перед тем, как преобразовать результат в политику.
</Warning>
