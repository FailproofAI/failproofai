Запросы — это гибкий слой под панелями мониторинга, аудитами и расследованиями. Используйте ad-hoc SQL для проверки идеи, а затем сохраните запрос, когда он становится частью повторяющегося рабочего процесса.

## Создание и выполнение запроса

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Analyze → Queries** и выберите **new query**.
    2. Откройте обозреватель схемы и выберите поля из данных событий, сеансов или оценок.
    3. Напишите SQL, добавьте параметры при необходимости и выполните запрос.
    4. Сохраните его с понятным названием и описанием, затем используйте **add to dashboard**, если результат нужно мониторить.

    Редактор запросов объединяет схему событий, SQL, параметры и предпросмотр результатов, чтобы вы могли проверить вопрос перед сохранением.

    ![Редактор SQL-запросов с обозревателем схемы и живой таблицей результатов.](/images/dashboard/query-lab.png)

    Сохраненные запросы затем появляются в общей библиотеке, где коллеги могут переиспользовать их или добавить их результаты на панели мониторинга.

    ![Библиотека сохраненных запросов с переиспользуемыми встроенными и пользовательскими запросами.](/images/dashboard/queries.png)

    Используйте понятное название и описание, чтобы результат оставался понятным без повторного открытия его SQL.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    Используйте `fp query list`, чтобы найти ID, и `fp query delete <query-id>`, чтобы удалить сохраненный запрос.
  </Tab>
</Tabs>

## Основные варианты использования

- Поиск сеансов с повторяющимися вызовами одного и того же инструмента.
- Сравнение оценок между моделями или окружениями.
- Измерение времени между ожиданием человека и возобновлением работы.
- Выявление отказов политики, за которыми следует успешная альтернатива.
- Построение когорты для аудита.

Откройте **Queries → Schema** перед написанием запросов с незнакомыми полями. Предпочитайте явные фильтры по времени и окружению и ограничивайте результаты во время исследования.

<Warning>
  Запрос может выявить подозрительный паттерн, но он сам по себе не устанавливает режим отказа. Откройте представительные трассы или выполните аудит перед тем, как превратить результат в политику.
</Warning>
