Запросы — это гибкий слой под панелями инструментов, аудитами и расследованиями. Используйте произвольный SQL для проверки идеи, а затем сохраните запрос, когда он становится частью регулярного рабочего процесса.

## Создание и запуск запроса

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в раздел **Analyze → Queries** и выберите **new query**.
    2. Откройте браузер схемы и выберите поля из данных события, сессии или оценки.
    3. Напишите SQL, при необходимости добавьте параметры и запустите запрос.
    4. Сохраните его с понятным названием и описанием, затем используйте **add to dashboard**, когда результат должен отслеживаться.

    Редактор запросов объединяет схему события, SQL, параметры и предпросмотр результата, чтобы вы могли проверить вопрос перед сохранением.

    ![Редактор SQL-запросов с браузером схемы и сетью живых результатов.](/images/dashboard/query-lab.png)

    Сохранённые запросы затем появляются в общей библиотеке, где товарищи по команде могут переустановить их или добавить их результаты на панели инструментов.

    ![Библиотека сохранённых запросов, содержащая переиспользуемые встроенные и пользовательские запросы.](/images/dashboard/queries.png)

    Используйте понятное название и описание, чтобы результат оставался понятным без повторного открытия его SQL.
  </Tab>
  <Tab title="CLI">
    ```bash
    fp query schema
    fp query create "retry loops" --sql "SELECT ..."
    fp query run <query-id>
    fp query show <query-id>
    fp query update <query-id> --sql "SELECT ..."
    ```

    Используйте `fp query list` для поиска идентификаторов и `fp query delete <query-id>` для удаления сохранённого запроса.
  </Tab>
</Tabs>

## Типичные применения

- Найти сессии с повторными вызовами одного и того же инструмента.
- Сравнить оценки между моделями или средами.
- Измерить время между ожиданием человека и возобновлением.
- Определить отказы политики, за которыми следует успешная альтернатива.
- Создать когорту для аудита.

Откройте **Queries → Schema** перед написанием запросов к неизвестным полям. Предпочитайте явные фильтры по времени и среде, а также устанавливайте ограничения на результаты во время исследования.

<Warning>
  Запрос может выявить подозрительный паттерн, но это не устанавливает режим отказа самостоятельно. Откройте репрезентативные трассировки или запустите аудит перед тем, как превратить результат в политику.
</Warning>
