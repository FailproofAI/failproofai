Трасса преобразует плоский поток событий в причинно-следственную историю запуска. Читайте её с первого расхождения, а не в обратном порядке от последней ошибки.

## Откройте трассу

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите на страницу **Observe → Sessions** и откройте сеанс.
    2. Используйте сводку профиля для проверки результата, времени выполнения, ошибок и оценок.
    3. Просмотрите временную шкалу и миникарту. Фильтруйте типы событий или время для больших сеансов.
    4. Выберите событие для проверки. Используйте **export** для получения JSON оценивателя или скопируйте URL страницы, чтобы поделиться глубокой ссылкой на выбранное свидетельство.

    ![Представление деталей сеанса с графиком выполнения, временной шкалой событий, панелью оценок и разбивкой по инструментам, моделям и хукам.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    Сначала используйте лёгкий поток событий. Запрашивайте полные данные только если сводок событий недостаточно для получения доказательств.
  </Tab>
</Tabs>

<Steps>
  <Step title="Ориентируйтесь">
    Подтвердите агента, окружение, время выполнения, результат и длительность, затем поищите ошибки, длительные операции, повторяющиеся инструменты, ожидания человека и отклонённые решения политики.
  </Step>
  <Step title="Разверните первое подозрительное событие">
    Проверьте его запрос, ответ, входные данные инструмента, выходные данные и идентификатор корреляции. Конфиденциальный контент видны только при включенной записи транскрипции и если у вас есть необходимые разрешения.
  </Step>
  <Step title="Проверьте предшествующий контекст">
    Причина часто находится на одно событие раньше: некорректный ответ модели, отсутствующий результат инструмента или устаревшее предположение.
  </Step>
  <Step title="Превратите доказательства в действие">
    Добавьте сеанс в область аудита, свяжите его с проблемой или используйте сценарий отказа для разработки политики.
  </Step>
</Steps>

<Warning>
  Большая длительность не всегда означает задержку модели. Разделите время модели, инструмента, хука и ожидания человека перед тем, как решить, что исправить.
</Warning>
