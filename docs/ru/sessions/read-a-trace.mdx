Трассировка преобразует плоский поток событий в причинно-следственную историю выполнения. Читайте её с первого расхождения, а не в обратном направлении от последней ошибки.

## Открыть трассировку

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Observe → Sessions** и откройте сеанс.
    2. Используйте профиль для проверки результата, времени, ошибок и оценок.
    3. Просмотрите временную шкалу и миникарту. Фильтруйте типы событий или время для больших сеансов.
    4. Выберите событие для его проверки. Используйте **export** для JSON оценивателя или скопируйте URL страницы для общего доступа с прямой ссылкой на выбранные данные.

    ![Представление деталей сеанса с графиком выполнения, временной шкалой событий, панелью оценки и распределением по инструментам, модели и хукам.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    Сначала используйте лёгкий поток событий. Запрашивайте полные полезные нагрузки только когда резюме событий не содержат достаточно доказательств.
  </Tab>
</Tabs>

<Steps>
  <Step title="Ориентируйтесь">
    Подтвердите агента, окружение, время, результат и продолжительность, затем проверьте ошибки, длительные периоды, повторяющиеся инструменты, ожидания пользователя и отклонённые решения политики.
  </Step>
  <Step title="Разверните первое подозрительное событие">
    Проверьте его запрос, ответ, входные данные инструмента, выходные данные и идентификатор корреляции. Чувствительное содержимое видно только при включенной записи транскрипта и при наличии соответствующих прав доступа.
  </Step>
  <Step title="Проверьте предшествующий контекст">
    Причина часто находится в предыдущем событии: неправильный ответ модели, отсутствующий результат инструмента или устаревшее предположение.
  </Step>
  <Step title="Превратите доказательства в действие">
    Добавьте сеанс в область аудита, свяжите его с проблемой или используйте режим отказа для создания политики.
  </Step>
</Steps>

<Warning>
  Длительность не всегда означает задержку модели. Разделите время модели, инструмента, хука и ожидания пользователя перед тем, как решить, что исправить.
</Warning>
