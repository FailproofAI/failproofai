Трасса преобразует плоский поток событий в причинно-следственную историю выполнения. Читайте её с первого расхождения, а не в обратном направлении от последней ошибки.

## Открыть трассу

<Tabs>
  <Tab title="Dashboard">
    1. Перейдите в **Observe → Sessions** и откройте сеанс.
    2. Используйте сводку профиля для проверки результата, времени, ошибок и оценок валидации.
    3. Просмотрите временную шкалу и миниатюру. Фильтруйте типы событий или время при работе с большим сеансом.
    4. Выберите событие для его проверки. Используйте **export** для получения JSON оценщика или скопируйте URL страницы, чтобы поделиться прямой ссылкой на выбранное свидетельство.

    ![Представление деталей сеанса с графиком выполнения, временной шкалой событий, панелью валидации и разбивкой по инструментам, модели и перехватчикам.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    Используйте сначала облегчённый поток событий. Запрашивайте полные полезные данные только когда сводок событий недостаточно для получения доказательств.
  </Tab>
</Tabs>

<Steps>
  <Step title="Ориентируйтесь">
    Подтвердите агента, окружение, время, результат и продолжительность, затем просканируйте на предмет ошибок, длительных периодов, повторяющихся инструментов, ожиданий пользователя и отклонённых решений политик.
  </Step>
  <Step title="Расширьте первое подозрительное событие">
    Проверьте его запрос, ответ, вход инструмента, выход и ID корреляции. Конфиденциальное содержимое видимо только при включённой записи стенограммы и если ваши разрешения это позволяют.
  </Step>
  <Step title="Проверьте предыдущий контекст">
    Причина часто находится в предыдущем событии: неправильный ответ модели, отсутствующий результат инструмента или устаревшее предположение.
  </Step>
  <Step title="Превратите свидетельства в действие">
    Добавьте сеанс в область аудита, свяжите его с проблемой или используйте режим отказа для создания политики.
  </Step>
</Steps>

<Warning>
  Длительное время выполнения не всегда означает задержку модели. Отделите время модели, инструмента, перехватчика и ожидания пользователя перед тем, как решать, что исправлять.
</Warning>
