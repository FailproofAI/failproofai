Failproof AI записывает действия агентов и решает, что им разрешено делать.

## Observe

| Термин | Значение |
| --- | --- |
| Session | Один запуск агента |
| Event | Одно действие в рамках сессии |
| Trace | Упорядоченный вид сессии |
| Evaluation | Оценка или суждение |
| Audit | Проверка множества сессий |
| Finding | Свидетельство паттерна сбоя |
| Issue | Ответственность, которую кто-то берет на себя |
| Alert | Правило, которое обнаруживает повторяемость |

## Enforce

| Термин | Значение |
| --- | --- |
| Harness | Окружение, в котором выполняется агент |
| Hook | Точка, в которой harness запрашивает решение |
| Policy | Правило, которое разрешает, направляет или блокирует |
| Policy pack | Версионированный набор политик, который может установить кто-либо |
| Daemon | Локальный сервис, который оценивает политики |
| Deployment | Политики, назначенные машине |

## Рабочий процесс

```text
Session → Audit → Finding → Issue → Policy
```

Начните с свидетельств. Найдите повторяющийся сбой, определите ответ, затем предотвратьте его.

Политика возвращает `allow`, `instruct` или `deny`. Указания через `instruct` зависят от harness; используйте `deny`, когда действие должно остановиться.

Режим Observe отделен от принятия решения. Он запускает реальную политику и записывает, что она бы сделала, при этом позволяя агенту продолжить работу.

<Warning>
  Простая команда `fp fleet deploy <machine> --add <policy>` применяется немедленно. Добавьте `:observe` для развертывания в режиме тени.
</Warning>

Setup не выбирает никакой policy pack. Перед его добавлением работает только `block-failproofai-commands`. Скомпилированный каталог содержит 39 политик в 9 категориях.

Обратитесь к [поддерживаемым harness](/ru/reference/harnesses#enforcement-capability) перед предположением о том, что событие может быть заблокировано в каждой среде агента.
