Начните с поведения, которое вы хотите остановить, и легитимного действия, которое должно продолжать работать.

## Сначала попробуйте проверенную политику

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI включает 39 проверенных политик. Перед написанием новой проверьте [каталог](/ru/policies/builtin-catalog).

## Напишите и протестируйте свою

<Steps>
  <Step title="Создайте рабочую политику">
    ```bash
    failproofai publish --init guards.mjs
    ```

    Это создает политику, которая блокирует `git push --force`. Отредактируйте её для вашего правила.
  </Step>
  <Step title="Включите её на этом компьютере">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    Попросите вашего агента выполнить заблокированное действие, затем проверьте **Policies → Activity** в локальной панели управления.
  </Step>
  <Step title="Сохраните или удалите её">
    Поместите файл `*policies.mjs` в папку `.failproofai/policies/`, чтобы он загружался автоматически.

    Удалите явные пользовательские файлы с помощью:

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## Поделитесь ею

Опубликуйте публичный пакет:

```bash
failproofai publish
```

Затем любой может установить его с помощью `failproofai policies add <owner>/<repo>`. Добавьте тему GitHub `failproofai-policies` самостоятельно, чтобы [Policy Hub](https://befailproof.ai/policy-hub/) смог её индексировать.

Для развертывания в Cloud:

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  Простая команда `--add checkout-guard` включает политику немедленно. Добавьте `:observe`, чтобы записывать, что политика будет делать, не блокируя агента.
</Warning>

Полный рабочий процесс см. в разделах [опубликовать пакет](/ru/policies/publish-a-pack) или [развернуть политики](/ru/policies/deploy).
