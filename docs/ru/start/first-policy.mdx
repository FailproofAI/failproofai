---
title: "Предотвратьте первый отказ с помощью политики"
description: "Создайте версию политики, разверните её в режиме наблюдения, а затем включите её."
icon: "shield-check"
---

Используйте политику только после того, как сможете описать опасное действие и допустимые действия, которые должны остаться разрешены.

<Tabs>
  <Tab title="Dashboard">
    <Steps>
      <Step title="Создайте политику">
        Перейдите в **Admin → policy editor**. Начните с демо-политики, проверьте или отредактируйте её исходный код, затем выберите **publish version**. Публикация создаёт неизменяемую версию, которую можно развернуть на машинах.

        ![Представление редактора политики с демо-политикой готовой к публикации как неизменяемая версия.](/images/dashboard/policy-editor.png)
      </Step>
      <Step title="Разверните её на машине">
        Перейдите в **Admin → enforcement**, разверните целевую машину и выберите **edit this machine**. Добавьте опубликованную демо-политику, закрепите её версию, выберите **observe** и примените развёртывание.

        ![Редактор развёртывания машины с опубликованной версией политики выбранной в режиме наблюдения перед применением развёртывания.](/images/dashboard/enforcement-editor.png)
      </Step>
      <Step title="Проверьте политику">
        Запустите новый сеанс агента на этой машине, затем откройте **Observe → policy**. Выберите машину и подтвердите, что демо-политика появляется в сопоставлении политик и временной шкале решений. Режим наблюдения записывает то, что политика бы сделала, без блокировки действия.

        ![Страница политики, показывающая итоги решений, активность принудительного применения со временем и локальные и облачные сопоставления политик.](/images/dashboard/policy-observe.png)
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    Создание облачной политики и развёртывание на парке машин — это административные рабочие процессы. Используйте локальный CLI для проверки той же политики перед её публикацией:

    ```bash
    failproofai policies --install --custom ./payment-retry.policies.ts \
      --cli claude --scope project
    failproofai config --status
    ```

    Используйте `fp` для проверки видимых облаком решений по политикам:

    ```bash
    fp events --event-type hook_completed --env production --since 24h
    fp sessions --env production --since 24h
    ```

    Облачный CLI не предоставляет маршруты развёртывания принудительного применения только для root. Публикуйте версии из **Admin → policy editor** и развёртывайте их из **Admin → enforcement**.
  </Tab>
</Tabs>
