---
title: "Предотвратите первый отказ с помощью политики"
description: "Создайте версию политики, разверните её в режиме наблюдения, а затем включите её проверку."
icon: "shield-check"
---

Используйте политику только после того, как сможете описать небезопасное действие и законные действия, которые должны остаться разрешёнными.

<Tabs>
  <Tab title="Dashboard">
    <Steps>
      <Step title="Создайте политику">
        Перейдите в **Admin → policy editor**. Начните с демо-политики, проверьте или отредактируйте её исходный код, затем выберите **publish version**. Публикация создаёт неизменяемую версию, которую можно развернуть на машинах.

        ![Представление редактора политик с демо-политикой, готовой к публикации в виде неизменяемой версии.](/images/dashboard/policy-editor.png)
      </Step>
      <Step title="Разверните её на машине">
        Перейдите в **Admin → enforcement**, раскройте целевую машину и выберите **edit this machine**. Добавьте опубликованную демо-политику, зафиксируйте её версию, выберите **observe** и примените развёртывание.

        ![Редактор развёртывания машины с выбранной опубликованной версией политики в режиме наблюдения перед применением развёртывания.](/images/dashboard/enforcement-editor.png)
      </Step>
      <Step title="Проверьте политику">
        Запустите новый сеанс агента на этой машине, затем откройте **Observe → policy**. Выберите машину и подтвердите, что демо-политика отображается в сопоставлении политик и временной шкале решений. Режим наблюдения записывает, что политика делала бы, не блокируя действие.

        ![Страница Policy, показывающая итоги решений, активность применения политики во времени, локальные и управляемые облаком сопоставления политик.](/images/dashboard/policy-observe.png)
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    Создание облачных политик и развёртывание парка — это административные рабочие процессы. Используйте локальный CLI для проверки той же политики перед её публикацией:

    ```bash
    failproofai policies --install --custom ./payment-retry.policies.ts \
      --cli claude --scope project
    failproofai config --status
    ```

    Используйте `fp` для проверки видимых облаком решений политики:

    ```bash
    fp events --event-type hook_completed --env production --since 24h
    fp sessions --env production --since 24h
    ```

    Оба шага доступны и через CLI: `fp policies publish <id> <file>` создаёт версию, а `fp fleet deploy <machine-id> --add <id>` размещает её на машине. Эквивалентные действия в dashboard — **Admin → policy editor** и **Admin → enforcement**.
  </Tab>
</Tabs>
