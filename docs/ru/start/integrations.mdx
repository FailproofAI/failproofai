## Три строки, любой фреймворк

<CodeGroup>
```bash LangGraph
pip install 'failproofai-sdk[langgraph]'
```

```bash CrewAI
pip install 'failproofai-sdk[crewai]'
```

```bash LlamaIndex
pip install 'failproofai-sdk[llamaindex]'
```

```bash Pydantic AI
pip install 'failproofai-sdk[pydantic-ai]'
```

```bash Custom agents
pip install failproofai-sdk
```
</CodeGroup>

```python
import failproofai_sdk

failproofai_sdk.configure(environment="production")
failproofai_sdk.instrument()          # обнаруживает импортированные фреймворки

with failproofai_sdk.session():
    ...                               # твой существующий вызов агента, без изменений
```

Без декораторов на функциях, без коллбэка, передаваемого вызовам, без идентификаторов, пропущенных через твой код. Только вызов внутри сессии отличается:

<Tabs>
  <Tab title="LangGraph">
    ```python
    graph.invoke({"messages": [HumanMessage("...")]})
    ```
  </Tab>
  <Tab title="CrewAI">
    ```python
    Crew(agents=[analyst, writer], tasks=[gather, summarise]).kickoff()
    ```
  </Tab>
  <Tab title="LlamaIndex">
    ```python
    await agent.run("...")        # под `async with failproofai_sdk.session():`
    ```
  </Tab>
  <Tab title="Pydantic AI">
    ```python
    agent.run_sync("...")
    ```
  </Tab>
  <Tab title="Custom agents">
    ```python
    with failproofai_sdk.agent("planner"):
        with failproofai_sdk.tool_call("search", input={"q": q}) as t:
            t.output = search(q)
    ```
  </Tab>
</Tabs>

Дополнительная установка — это **фреймворк**. Каждый адаптер поставляется в базовом пакете, поэтому проект, который уже имеет свой фреймворк, не нуждается ни в чём дополнительном.

## Проверь доставку

Запусти одну инструментированную сессию, затем открой **Observe → Sessions** и выбери твоё окружение. Запуск появится как восстановленная трасса.

Если ничего не поступило, проверь, подключена ли машина командой `failproofai config --status`. Смотри [Настройка захвата](/ru/start/setup).

<Warning>
  Не проверяй директорию спула для подтверждения доставки. Daemon Failproof собирает и удаляет каждый пакет в течение миллисекунд, поэтому чтение спула гонится с коллектором и показывает гораздо меньше событий, чем было испущено.
</Warning>
