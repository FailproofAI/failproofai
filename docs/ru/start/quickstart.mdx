Установите Failproof AI на одну машину, затем работайте локально или подключитесь к облаку.

Если ваш агент работает в [поддерживаемой среде](/ru/reference/harnesses), следуйте этим шагам. Для агентов, построенных с помощью LangChain, CrewAI, LlamaIndex, Pydantic AI или вашей собственной среды выполнения, начните с [инструментирование вашего агента](/ru/start/integrations).

## Позвольте вашему агенту направлять установку

Установите зонтичный навык Failproof AI в совместимый агент:

```bash
npx skills add FailproofAI/skills
```

Это устанавливает зонтичный навык и его специализированные варианты. Используйте `--skill failproofai`, если вам нужен только зонтичный навык. Он разбирается в локальной и облачной установке, здоровье демона, сеансах, аудитах, политиках и устранении неполадок. Он направляет работу и маршрутизирует специализированные задачи к правильному навыку Failproof AI; он не заменяет установку CLI ниже.

## Установка на машину

<Steps>
  <Step title="Установите и настройте Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    Установка устанавливает фоновый сервис и подключает каждый найденный поддерживаемый агент. Один раз может запросить доступ администратора. Поддерживает Linux и macOS.
  </Step>

  <Step title="Выберите политики">
    Установка не выбирает пакет политик. Добавьте пакет Failproof AI:

    ```bash
    failproofai policies add FailproofAI/policies
    failproofai policies
    ```

    Вторая команда показывает все политики на этой машине и включены ли они. Пока вы не добавите пакет, работает только `block-failproofai-commands`.
  </Step>

  <Step title="Проверьте машину">
    ```bash
    failproofai config --status
    ```

    Это показывает сервис, облачное соединение и состояние паузы.
  </Step>
</Steps>

## Выберите локальный или облачный режим

<Tabs>
  <Tab title="Остаться локально">
    Учетная запись не требуется.

    ```bash
    failproofai
    failproofai audit
    ```

    Первая команда открывает локальную панель управления на `http://localhost:8020`. Вторая сканирует историю агента, уже находящуюся на этой машине.
  </Tab>

  <Tab title="Подключиться к облаку">
    Создайте ключ машины в облаке Failproof AI, затем запустите:

    ```bash
    failproofai config --token <machine-key>
    failproofai config --status
    ```

    Облако получает решения политик и стенограммы сеансов. Чтобы отправлять только решения, сначала подключитесь, затем установите `collector.sessions` на `false` в `~/.failproofai/config.json`; текущий флаг установки `--no-transcripts` не применяет этот параметр. Для общих оболочек и CI используйте `FAILPROOFAI_CLOUD_TOKEN` вместо того, чтобы помещать ключ в историю команд.
  </Tab>
</Tabs>

## Проверьте работу

Запустите один из ваших агентов и попросите его выполнить обычную задачу. Затем:

Запрет на вызов инструмента проверяется на всех 12 поддерживаемых средах. Принудительное завершение проверяется на 8; другие пары событий среды могут быть только наблюдательными или непроверенными.

- Откройте **Policies → Activity** в локальной панели управления, чтобы увидеть решения политик.
- Откройте **Observe → Sessions** в облаке, чтобы увидеть полный запуск.
- Запустите `failproofai audit`, чтобы поискать рискованные или неэффективные модели.

<Warning>
  После установки сервис `failproofaid` является оценщиком. Если он не может ответить, защищенные действия отклоняются. Запустите `failproofai config --status`, когда агент неожиданно останавливается.
</Warning>
