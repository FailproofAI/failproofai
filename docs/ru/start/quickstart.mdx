Этот быстрый старт позволит одной машине отправлять сеансы, запустить аудит и развернуть политику. Используйте скилл для настройки Failproof AI или следуйте ручным шагам.

**Какой путь для вас?** Если ваш агент работает с одной из 12 поддерживаемых [сред](/ru/reference/harnesses) — CLI для кодирования или шлюз вроде Hermes или OpenClaw — следуйте шагам ниже; вам нужен Node.js версии 20.9 или выше. Если у вашего агента нет среды, добавьте инструментацию с помощью [Python SDK](/ru/reference/custom-agents) для трассировки и аудитов, затем вернитесь к разделу [Запустите первую проверку сбоя](/ru/start/first-audit); принудительное исполнение на этом пути требует хука в вашей среде выполнения.

    <Steps>
      <Step title="Установите скиллы Failproof AI">
        ```bash
        npx skills add FailproofAI/skills
        ```
      </Step>
      <Step title="Попросите агента всё настроить">
        ```text
        Set up Failproof AI for this project, connect this machine, install the right hooks and policies, and verify that a session arrives.
        ```

        Ваш агент проверит проект, выберет релевантную интеграцию, выполнит настройку и проверит её. Смотрите [репозиторий FailproofAI skills](https://github.com/FailproofAI/skills) для отдельных скиллов и расширенных вариантов установки.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Ручная настройка">
    ## Установка

<Steps>
  <Step title="Установите и подключите Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    Эта одна команда — вся настройка: она устанавливает локальный демон (один раз с правами root), подключает хуки ко всем найденным CLI агентов и подключает эту машину к Cloud.

    На этапе **Connect to cloud** настройка сразу начнёт логировать вас в FailproofAI Cloud (нажмите Tab для других опций: вставить ключ API или использовать открытый исходный код). Она откроет ссылку в вашем браузере (через SSH или на машине без дисплея она выведет ссылку, чтобы вы могли открыть её на любом устройстве). Зарегистрируйтесь или войдите, подтвердите организацию — или создайте её прямо там — и нажмите **Authorize**. Имя ключа и разрешения установлены автоматически. Вам не нужна учётная запись заранее.

    Терминал заметит это самостоятельно и покажет, кто его одобрил и для какой организации. Подтвердите агентов для трассировки и настройка завершится. Ключ машины создаётся только на этом этапе, после установки демона, поэтому прерванный запуск не оставит ключ; он появляется в разделе **Administration → Keys** с меткой **cli login**, где вы можете его отозвать.

    <Accordion title="Нет браузера или терминала под рукой? Используйте ключ (CI, контейнеры, скрипты провизионирования)">
      На [панели Failproof AI](https://app.befailproof.ai) перейдите в **Administration → Keys** и создайте ключ с разрешениями `events:add` и `policies:pull`. Если вы планируете использовать [Jev через FailproofAI Cloud](/ru/reference/jev-cloud), выберите предустановку **machine**, которая также предоставляет `jev:evaluate`. Скопируйте одноразовый секрет и прочитайте его в оболочку на целевой машине — `read -s` берёт его из приглашения без эха:

      ```bash
      read -rs FAILPROOFAI_KEY && export FAILPROOFAI_KEY
      FAILPROOFAI_CLOUD_TOKEN="$FAILPROOFAI_KEY" failproofai config
      ```

      Передача ключа через переменную окружения вместо `--token` скрывает его от `ps`, где каждый пользователь на машине может прочитать аргументы команды. Это не скрывает его из истории оболочки — это делает чтение с `read -s`. В CI вводите его как маскированный секрет и отключайте трассировку оболочки (`set -x`), иначе трассировка выведет его. В интерактивном запуске вы также можете выбрать **Paste an API key** на этапе **Connect to cloud**.
    </Accordion>

    Стенограммы сеансов отправляются по умолчанию. Добавьте `--no-transcripts` для отправки активности хука и решений политики без содержимого стенограммы.

    <Warning>
      Не используйте здесь `failproofai config --connect <url>`. Этот флаг подключает машину, которая **уже** настроена, и сразу возвращается — никакого демона, никаких хуков — поэтому машина появится в Cloud без сбора и принудительного исполнения чего-либо.
    </Warning>

    Если эта машина уже имеет историю агентов, посмотрите предпросмотр и импортируйте последние семь дней, затем дождитесь завершения доставки. Пропустите этот шаг на новой машине.

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    Откройте **Sessions** в Failproof AI и выберите импортированный сеанс.
  </Step>
  <Step title="Подключите Failproof AI к среде">
    Предыдущий шаг уже подключил каждый найденный CLI агента. Переустановите его для одной среды явно когда потребуется или для добавления среды, установленной позже. Каждая из 12 сред — это корректное значение `--cli` — `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity`, `goose`.

    ```bash
    failproofai policies --install --cli claude --scope user     # coding CLI
    failproofai policies --install --cli hermes --scope user     # шлюз Slack/Telegram
    ```

    Блокировка вызова инструмента до его выполнения проверяется на всех 12. Шлюзы конца хода проверяются на 8 — смотрите [возможности принудительного исполнения](/ru/reference/harnesses#enforcement-capability) для матрицы по средам.
  </Step>
  <Step title="Выберите, что принудительно исполнять">
    Подключение хуков не включает никакую политику. Настройка намеренно не выбирает никакую — это ваше решение — поэтому возьмите пакет:

    ```bash
    failproofai policies add FailproofAI/policies
    ```

    Пакет загружается из его релиза на GitHub, проверяется контрольная сумма и фиксируется точный тег, который он разрешил. Он содержит 39 политик и включает 10, которые его манифест помечает как безопасные для автоматического включения. Используйте их для просмотра локальных решений политики и попробуйте принудительное исполнение перед тем, как Failproof AI аудирует ваши сеансы и создаёт политики для ваших агентов.

    Прочитайте любой пакет перед его использованием с `failproofai policies show <owner>/<repo>` и смотрите [пакеты политик](/ru/policies/packs) для использования только части одного.

    До запуска этого команда, единственное, что принудительно исполняется — это `block-failproofai-commands` — всегда включённая защита, которая предотвращает отключение агентом Failproof AI. `failproofai policies` показывает, что включено.
  </Step>
  <Step title="Проверьте поведение">
    Следуйте [Запустите первую проверку сбоя](/ru/start/first-audit). Используйте конкретную цель, такую как "найти сеансы, где агент повторил неудачный инструмент без изменения своего подхода."
  </Step>
  <Step title="Предотвратите сбой">
    Следуйте [Предотвратите первый сбой с политикой](/ru/start/first-policy). Начните в режиме наблюдения, проверьте совпадения, затем принудительно исполните проверенную версию.
  </Step>
</Steps>

<Check>
  Запустите `failproofai config --status`. Здоровая настройка показывает подключение облака, состояние демона и включено ли принудительное исполнение на паузе.
</Check>

## Настройка Jev

Используйте [Jev](/ru/start/use-jev) для оценки завершённых сеансов по вопросу с известными ответами или для проверки вызовов инструментов в контексте перед их запуском. На странице **Use Jev** указаны оба пути настройки.
