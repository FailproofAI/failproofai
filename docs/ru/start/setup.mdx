Failproof AI может работать полностью на одной машине или подключиться к Cloud для общих сессий и управления политиками.

## Локально, без учётной записи

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai
```

Эта команда устанавливает сервис, подключает поддерживаемые агенты, добавляет набор политик и открывает панель управления на `http://localhost:8020`.

Запустите `failproofai audit` для сканирования истории агентов, уже находящейся на машине.

## Подключение к Failproof AI Cloud

Создайте ключ машины в Cloud, затем выполните:

```bash
failproofai config --token <machine-key>
failproofai config --machine-label checkout-runner-01
failproofai policies add FailproofAI/policies
failproofai config --status
```

Или экспортируйте `FAILPROOFAI_CLOUD_TOKEN=<machine-key>` и запустите `failproofai config` без параметров. Предпочитайте переменную окружения на общих машинах и в CI, чтобы ключ не попал в историю команд или список процессов.

Cloud использует одно соединение для двух отдельных задач:

- Получение политик, назначенных этой машине.
- Отправка решений по политикам и стенограмм сессий.

Чтобы отправлять только решения, сначала подключитесь, затем установите `collector.sessions` в значение `false` в `~/.failproofai/config.json`. Не полагайтесь на `--no-transcripts`: текущий путь установки анализирует флаг, но не применяет его. См. [события и конфигурация](/ru/reference/events-and-configuration#machine-configuration).

<Note>
  `--machine-label` переименовывает уже подключённую машину. Запустите его после команды setup, а не как часть первого подключения.
</Note>

## Автоматическая установка

`failproofai config` не требует специального флага для неинтерактивного режима. В CI или контейнере он применяет запрошенную конфигурацию без запросов.

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Доступ администратора требуется один раз для установки фонового сервиса. Установка никогда не открывает интерактивный запрос пароля sudo: она либо выполняется без него, либо выводит команды, которые должен запустить администратор.

## Поддержка платформ

Установка поддерживает Linux и macOS. На другой платформе она завершается без записи хуков или состояния частичной установки.
