Jev помогает в двух точках выполнения агента: оценить завершённый сеанс по известным ответам или проверить вызов инструмента в контексте того, что вы попросили агента сделать.

<Tabs>
  <Tab title="Jev evals">
    Используйте оценку Jev, когда завершённый сеанс можно оценить по вопросу с несколькими известными ответами, например «Клиент просил возврат? Ответьте да или нет.» Это помогает найти закономерности между сеансами.

    ## Создание оценки

    В облачной панели управления откройте **analyse → checks → new check** (или **new evaluation**). Опишите один вопрос с фиксированным ответом, проверьте созданное правило и убедитесь, что **how it checks** — это **decision model** — то есть Jev. [Протестируйте его](/ru/evaluations/test) на реальных сеансах, затем активируйте.

    ![Общая форма создания оценки, где вы описываете вопрос, проверяете черновик и развёртываете его. На этом снимке экрана показан черновик кода; используйте вопрос с фиксированным ответом для Jev.](/images/dashboard/eval-authoring-draft.png)

    ## Чтение оценок

    После завершения нового сеанса откройте **analyse → checks → evals** и выберите оценку, или используйте облачный CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI читает оценки; создание оценки Jev в настоящее время использует панель управления. Типы вопросов и примеры см. в [Jev evaluations](/ru/evaluations/jev).
  </Tab>
  <Tab title="Jev policies">
    Используйте проверку политики Jev, когда политика сопоставления строк нуждается в контексте вашего запроса, чтобы решить, безопасен ли вызов инструмента. Начните с режима **observe**, чтобы вы могли проверить ответы Jev, пока ваши установленные политики по-прежнему решают каждый вызов.

    Проверки Jev поступают из пакета; Failproof AI не поставляет ни одного. Пока вы их не установите, Jev ничего не запрашивает, даже если он настроен:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Настройка облачного Jev

    В облачной панели управления откройте **settings → api keys** и в разделе **new key** выберите **a machine running failproofai**. Используйте её с `failproofai config`, как показано в [quickstart](/ru/start/quickstart). На машине без существующей конфигурации Jev это включает облачный Jev в режиме наблюдения. Проверьте соединение с помощью:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Использование собственной конечной точки

    В локальной панели управления откройте **Settings → Jev**. Выберите поставщика, вставьте его токен, выберите **observe** и включите Jev.

    ![Локальная панель параметров Jev с поставщиком, полем токена и выбранным режимом наблюдения.](/images/dashboard/jev-settings.png)

    Или настройте и протестируйте вашу конечную точку из терминала:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Попросите подключённого агента использовать его инструмент чтения файлов на `README.md`. Подтвердите, что вызов инструмента появляется в сеансе, затем проверьте его в разделе **Policies → Activity** в локальной панели управления. Когда результаты наблюдения выглядят правильно, в [Jev policies](/ru/policies/jev) объясняется, когда применять. Для сведений о поставщике и конфигурации см. [integration reference](/ru/reference/jev).
  </Tab>
</Tabs>
