Jev помогает на двух этапах выполнения агента: оценить завершённую сессию по известным ответам или проверить вызов инструмента в контексте того, что вы попросили делать агента.

<Tabs>
  <Tab title="Jev evals">
    Используйте оценку Jev, когда завершённую сессию можно оценить по вопросу с несколькими известными ответами, например: «Клиент попросил возврат? Ответьте да или нет.» Это помогает выявлять закономерности между сессиями.

    ## Создайте оценку

    В облачной панели управления откройте **Analyze → eval authoring → new eval**. Введите один вопрос с фиксированным ответом, выберите **draft** и убедитесь, что выбран классификационный балл. [Протестируйте его](/ru/evaluations/test) на реальных сессиях, затем разверните.

    ![Форма разработки общей оценки, где вы описываете вопрос, проверяете черновик и разворачиваете его. На этом снимке экрана показан черновик кода; используйте вопрос с фиксированным ответом для Jev.](/images/dashboard/eval-authoring-draft.png)

    ## Прочитайте баллы

    После завершения новой сессии откройте **Observe → Evaluations** или используйте облачный CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI считывает баллы; создание оценки Jev в настоящее время использует панель управления. Типы вопросов и примеры см. в разделе [Jev evaluations](/ru/evaluations/jev).
  </Tab>
  <Tab title="Jev policies">
    Используйте проверку политики Jev, когда политике на основе сравнения строк нужен контекст вашего запроса, чтобы решить, безопасен ли вызов инструмента. Начните в режиме **observe**, чтобы вы могли проверить ответы Jev, пока установленные политики по-прежнему определяют каждый вызов.

    Проверки Jev поступают из пакета; Failproof AI не поставляет ничего. Пока вы их не установите, Jev ничего не спрашивает, даже если он настроен:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Настройте облачный Jev

    В облачной панели управления откройте **Administration → Keys** и создайте ключ с предустановкой **machine**. Используйте его с `failproofai config`, как показано в [quickstart](/ru/start/quickstart). На машине без существующей конфигурации Jev это включает облачный Jev в режиме observe. Проверьте соединение с помощью:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Используйте собственную конечную точку

    В локальной панели управления откройте **Settings → Jev**. Выберите поставщика, вставьте его токен, выберите **observe** и включите Jev.

    ![Панель локальных параметров Jev с поставщиком, полем токена и выбранным режимом observe.](/images/dashboard/jev-settings.png)

    Или настройте и протестируйте конечную точку из терминала:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Попросите подключённого агента использовать его инструмент чтения файлов на `README.md`. Подтвердите, что этот вызов инструмента отображается в сессии, затем проверьте его в разделе **Policies → Activity** в локальной панели управления. Когда результаты observe выглядят правильно, в разделе [Jev policies](/ru/policies/jev) объясняется, когда приступать к обеспечению. Подробности поставщика и конфигурацию см. в [reference по интеграции](/ru/reference/jev).
  </Tab>
</Tabs>
