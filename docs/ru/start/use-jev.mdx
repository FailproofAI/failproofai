Jev помогает на двух этапах выполнения агента: оценить завершённую сессию по известным ответам или проверить вызов инструмента в контексте того, что вы попросили агента делать.

<Tabs>
  <Tab title="Jev evals">
    Используйте оценку Jev, когда завершённую сессию можно оценить по вопросу с несколькими известными ответами, например "Попросил ли клиент возврат? Ответьте да или нет." Это помогает вам находить закономерности в разных сессиях.

    ## Создание оценки

    На облачной панели управления откройте **Analyze → eval authoring → new eval**. Введите один вопрос с фиксированным ответом, выберите **draft** и убедитесь, что он выбрал классификационный балл. [Протестируйте его](/ru/evaluations/test) на реальных сессиях, затем разверните его.

    ![Форма создания общей оценки, где вы описываете вопрос, просматриваете черновик и развёртываете его. На этом снимке показан черновик кода; используйте вопрос с фиксированным ответом для Jev.](/images/dashboard/eval-authoring-draft.png)

    ## Чтение результатов

    После завершения новой сессии откройте **Observe → Evaluations** или используйте облачный CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI читает результаты; создание оценки Jev в настоящее время использует панель управления. Типы вопросов и примеры см. в [Jev evaluations](/ru/evaluations/jev).
  </Tab>
  <Tab title="Jev policies">
    Используйте проверку политики Jev, когда политике, основанной на сопоставлении строк, нужен контекст вашего запроса для определения безопасности вызова инструмента. Начните с режима **observe**, чтобы вы могли проверять ответы Jev, пока ваши установленные политики всё ещё решают каждый вызов.

    Проверки Jev поступают из пакета; Failproof AI не поставляет их. Пока вы их не установите, Jev ничего не спрашивает, даже если он настроен:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Настройка облачного Jev

    На облачной панели управления откройте **Administration → Keys** и создайте ключ с предустановкой **machine**. Используйте его с `failproofai config`, как показано в [quickstart](/ru/start/quickstart). На машине без существующей конфигурации Jev это включает облачный Jev в режиме observe. Проверьте соединение с помощью:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Использование собственной конечной точки

    На локальной панели управления откройте **Settings → Jev**. Выберите поставщика, вставьте его токен, выберите **observe** и включите Jev.

    ![Панель локальных настроек Jev с выбранным поставщиком, полем токена и режимом observe.](/images/dashboard/jev-settings.png)

    Или настройте и протестируйте вашу конечную точку из терминала:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Попросите подключённого агента использовать его инструмент чтения файлов для `README.md`. Убедитесь, что этот вызов инструмента появляется в сессии, затем проверьте его в разделе **Policies → Activity** на локальной панели управления. Когда результаты observe будут выглядеть правильно, в [Jev policies](/ru/policies/jev) объясняется, когда применять принудительно. Для деталей поставщика и конфигурации см. [integration reference](/ru/reference/jev).
  </Tab>
</Tabs>
