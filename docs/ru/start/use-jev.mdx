Jev помогает на двух этапах работы агента: оценить завершённую сессию по известным ответам или проверить вызов инструмента в контексте того, что вы просили делать агента.

<Tabs>
  <Tab title="Оценки Jev">
    Используйте оценку Jev, когда завершённую сессию можно оценить по вопросу с несколькими известными ответами, например «Клиент попросил возврат? Ответьте да или нет.» Это помогает найти закономерности в сессиях.

    ## Создание оценки

    В облачной панели откройте **Analyze → eval authoring → new eval**. Введите один вопрос с фиксированным ответом, выберите **draft** и убедитесь, что была выбрана оценка классификатора. [Протестируйте её](/ru/evaluations/test) на реальных сессиях, затем разверните.

    ![Форма для создания общей оценки, где вы описываете вопрос, проверяете черновик и развёртываете его. На скриншоте показан черновик кода; используйте вопрос с фиксированным ответом для Jev.](/images/dashboard/eval-authoring-draft.png)

    ## Чтение оценок

    После завершения новой сессии откройте **Observe → Evaluations** или используйте облачный CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI читает оценки; создание оценки Jev в настоящий момент использует панель. Смотрите [Jev evaluations](/ru/evaluations/jev) для типов вопросов и примеров.
  </Tab>
  <Tab title="Политики Jev">
    Используйте проверку политик Jev, когда политика, основанная на сопоставлении строк, нуждается в контексте вашего запроса, чтобы решить, безопасен ли вызов инструмента. Начните с режима **observe**, чтобы вы могли проверить ответы Jev, пока установленные политики всё ещё принимают решение по каждому вызову.

    Проверки Jev поступают из пакета; Failproof AI не поставляет ни одного. Пока вы их не установите, Jev ничего не спрашивает, даже если он настроен:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Настройка облачного Jev

    В облачной панели откройте **Administration → Keys** и создайте ключ с предустановкой **machine**. Используйте его с `failproofai config` как показано в [quickstart](/ru/start/quickstart). На машине без существующей конфигурации Jev это активирует облачный Jev в режиме observe. Проверьте соединение с помощью:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Использование собственной конечной точки

    В локальной панели откройте **Settings → Jev**. Выберите провайдера, вставьте его токен, выберите **observe** и включите Jev.

    ![Панель локальных параметров Jev с провайдером, полем токена и выбранным режимом observe.](/images/dashboard/jev-settings.png)

    Или настройте и протестируйте вашу конечную точку из терминала:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Попросите подключённого агента использовать инструмент чтения файлов на `README.md`. Убедитесь, что вызов инструмента появляется в сессии, затем проверьте его в разделе **Policies → Activity** в локальной панели. Когда результаты observe выглядят правильно, в [Jev policies](/ru/policies/jev) объясняется, когда их применять. Для деталей провайдера и конфигурации смотрите [integration reference](/ru/reference/jev).
  </Tab>
</Tabs>
