Jev помогает в двух точках выполнения агента: оценить завершённую сессию по известным ответам или проверить вызов инструмента в контексте того, что вы попросили агента сделать.

<Tabs>
  <Tab title="Jev evals">
    Используйте оценку Jev, когда завершённая сессия может быть оценена по вопросу с несколькими известными ответами, например «Клиент просил возврат? Ответьте да или нет.» Это помогает найти закономерности в сессиях.

    ## Создание оценки

    В облачной панели управления откройте **analyse → checks → new check** (или **new evaluation**). Опишите один вопрос с фиксированным ответом, проверьте правило, которое оно создаст, и убедитесь, что **how it checks** — это **decision model** — это Jev. [Протестируйте его](/ru/evaluations/test) на реальных сессиях, а затем включите его.

    ![Общая форма для создания оценок, где вы описываете вопрос, проверяете черновик и развёртываете его. На этом снимке экрана показан черновик кода; используйте вопрос с фиксированным ответом для Jev.](/images/dashboard/eval-authoring-draft.png)

    ## Прочитайте оценки

    После завершения новой сессии откройте **analyse → checks → evals** и выберите оценку или используйте облачный CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI читает оценки; создание оценки Jev в настоящее время использует панель управления. Типы вопросов и примеры см. в разделе [Jev evaluations](/ru/evaluations/jev).
  </Tab>
  <Tab title="Jev policies">
    Используйте проверку политики Jev, когда политике сопоставления строк нужен контекст вашего запроса для определения, безопасен ли вызов инструмента. Начните с режима **observe**, чтобы вы могли проверять ответы Jev, пока установленные политики всё ещё определяют каждый вызов.

    Проверки Jev поступают из пакета; Failproof AI не поставляет ни одного. Пока вы их не установите, Jev ничего не спрашивает, даже если он настроен:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Настройка облачного Jev

    В облачной панели управления откройте **settings → api keys** и в разделе **new key** выберите **a machine running failproofai**. Используйте его с `failproofai config`, как показано в [quickstart](/ru/start/quickstart). На машине без существующей конфигурации Jev это включает облачный Jev в режиме наблюдения. Проверьте соединение с помощью:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Используйте свой собственный endpoint

    В локальной панели управления откройте **Settings → Jev**. Выберите поставщика, вставьте его токен, выберите **observe** и включите Jev.

    ![Локальная панель параметров Jev с выбранным поставщиком, полем токена и режимом наблюдения.](/images/dashboard/jev-settings.png)

    Или настройте и протестируйте ваш endpoint из терминала:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Попросите зафиксированного агента использовать свой инструмент чтения файлов для `README.md`. Убедитесь, что вызов инструмента появляется в сессии, затем проверьте его в **Policies → Activity** в локальной панели управления. Когда результаты наблюдения выглядят правильно, [Jev policies](/ru/policies/jev) объясняет, когда их применять. Подробности поставщика и конфигурацию см. в [integration reference](/ru/reference/jev).
  </Tab>
</Tabs>
