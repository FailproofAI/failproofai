Jev помогает в двух точках выполнения агента: оценить завершённую сессию по известным ответам или проверить вызов инструмента в контексте того, что вы попросили агента сделать.

<Tabs>
  <Tab title="Jev evals">
    Используйте Jev eval, когда завершённую сессию можно оценить по вопросу с несколькими известными ответами, например «Клиент попросил возврат? Ответьте да или нет.» Это помогает найти закономерности в разных сессиях.

    ## Создайте оценку

    В облачной панели откройте **Analyze → eval authoring → new eval**. Введите один вопрос с фиксированным ответом, выберите **draft** и убедитесь, что выбран классификационный скор. [Протестируйте его](/ru/evaluations/test) на реальных сессиях, затем разверните его.

    ![Форма создания общей оценки, где вы описываете вопрос, проверяете черновик и развёртываете его. На этом скриншоте показан черновик кода; используйте вопрос с фиксированным ответом для Jev.](/images/dashboard/eval-authoring-draft.png)

    ## Прочитайте скоры

    После завершения новой сессии откройте **Observe → Evaluations** или используйте облачный CLI:

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI читает скоры; создание Jev eval в настоящее время использует панель. См. [Jev evaluations](/ru/evaluations/jev) для типов вопросов и примеров.
  </Tab>
  <Tab title="Jev policies">
    Используйте проверку политики Jev, когда политика, основанная на сопоставлении строк, нужна контекст вашего запроса для определения безопасности вызова инструмента. Начните в режиме **observe**, чтобы вы могли проверить ответы Jev, пока установленные политики по-прежнему решают каждый вызов.

    Проверки Jev поступают из набора; Failproof AI не поставляет ни одного. Пока вы их не установите, Jev ничего не спрашивает, даже если он настроен:

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## Настройте Cloud Jev

    В облачной панели откройте **Administration → Keys** и создайте ключ с предустановкой **machine**. Используйте его с `failproofai config`, как показано в [quickstart](/ru/start/quickstart). На машине без существующей конфигурации Jev это включает Cloud Jev в режиме observe. Проверьте соединение с помощью:

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## Используйте свою конечную точку

    В локальной панели откройте **Settings → Jev**. Выберите поставщика, вставьте его токен, выберите **observe** и включите Jev.

    ![Панель локальных параметров Jev с полями поставщика и токена и выбранным режимом observe.](/images/dashboard/jev-settings.png)

    Или настройте и протестируйте вашу конечную точку из терминала:

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    Попросите подключённого агента использовать его инструмент чтения файлов на `README.md`. Убедитесь, что вызов инструмента появляется в сессии, затем проверьте его в **Policies → Activity** в локальной панели. После того как результаты observe будут выглядеть правильно, в [Jev policies](/ru/policies/jev) объясняется, когда применять политику. Для деталей поставщика и конфигурации см. [integration reference](/ru/reference/jev).
  </Tab>
</Tabs>
