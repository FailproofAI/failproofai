Ask the failproof agent to do anything in Failproof AI in natural language. It can analyze sessions and failures, run queries, build dashboards, investigate evaluations and alerts, and help create and run audits without making you translate the task into product screens or CLI commands.

```text
Why did production checkout agents regress this week?
Build a dashboard for tool failures, latency, and evaluation scores.
Create an audit that finds agents retrying the same failed action without changing approach.
Show me the sessions behind the most common audit finding.
```

The failproof agent works with the data and permissions available in the active organization. Review its evidence and proposed changes before applying actions that affect other users or agents.

## Ask the failproof agent

<Tabs>
  <Tab title="Dashboard">
    1. On **home**, type in the chat box (“ask anything about your agents”), or open the dock on any page with **ask failproof** (⌘J / Ctrl+J) to ask about that page. Describe what you want to understand, create, or operate.
    2. Review the agent's tool calls, tables, and query results while it works.
    3. Open the cited session, alert, or query to verify the result against source data.
    4. Select **new chat** in the sidebar for a different investigation, or search the sidebar for an earlier chat to continue the same line of analysis.

    ![The failproof agent answering an observability question with supporting analysis and queries.](/images/dashboard/assistant.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp agent health
    fp agent models
    fp agent ask "Which production checkout agents had the most tool errors in the last 24 hours?"
    fp agent chats
    fp agent show <chat-id>
    fp agent ask "Open representative sessions" --chat <chat-id>
    ```

    Use `fp agent rename <chat-id> --title <title>` to keep an investigation recognizable and `fp agent delete <chat-id>` to remove it.
  </Tab>
</Tabs>

## Work effectively with the failproof agent

- Give it a goal first; add an environment, workflow, or time range when those boundaries matter.
- Treat generated SQL and summaries as an investigation aid, not final evidence.
- Open representative sessions before creating an audit, insight, alert, or policy.
- Keep organization, environment, and time filters explicit.
- Save useful SQL as a query so another operator can reproduce the result.

<Warning>
  The failproof agent can read only what your current user can access. Do not broaden permissions to make a question work; ask an authorized operator to run the investigation instead.
</Warning>
