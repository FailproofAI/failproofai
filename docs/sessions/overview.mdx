A session is one agent run. It connects the prompt, model calls, tools, errors, human input, policy decisions, and final result.

## Where sessions live

<Tabs>
  <Tab title="Local">
    Run `failproofai` to open the dashboard at `http://localhost:8020`. Session history stays on this machine.
  </Tab>
  <Tab title="Cloud">
    Connect the machine, then open **Observe → Sessions**:

    ```bash
    export FAILPROOFAI_CLOUD_TOKEN="<key>"
    failproofai config
    ```

    Cloud receives full transcripts by default. To send policy decisions only, connect first, then set `collector.sessions` to `false` in `~/.failproofai/config.json`. The current `--no-transcripts` setup flag does not apply that setting.
  </Tab>
</Tabs>

Sessions arrive from the 12 supported [agent harnesses](/reference/harnesses) and from agents instrumented with the [Python SDK](/reference/custom-agents).

## Find a session

In Cloud, filter by time, environment, status, agent, or session ID. From the CLI:

```bash
fp sessions --since 24h
fp sessions --status error,timeout --agent-id checkout-agent
fp --json sessions --session-id <session-id>
```

Use `fp errors --since 24h` for failures that were never evaluated. `fp sessions --status` uses the latest evaluation outcome, so an unevaluated session has no status.

## Read a run

1. Confirm the agent's goal and environment.
2. Find the first error or unexpected decision.
3. Inspect the model context and tool input immediately before it.
4. Check retries, latency, and human interruptions.
5. Review evaluations and policy decisions.

## If a session is missing

```bash
failproofai flush --wait
failproofai config --status
failproofai backfill --since 30d --dry-run
```

Use `failproofai harness add-path <harness> [<label>=]<path>` when sessions live outside the harness's usual location, such as another profile, container home, or mounted team directory.
