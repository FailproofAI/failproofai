A trace is the timeline of one agent run. Start at the first unexpected event, not the final error.

<Tabs>
  <Tab title="Dashboard">
    1. Open **Observe → Sessions**.
    2. Choose a session.
    3. Scan for the first error, unusual tool call, long wait, or policy decision.
    4. Open the event and inspect the request, response, input, and output.

    ![A session detail view with its execution graph, event timeline, evaluation panel, and tool, model, and hook breakdown.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all --limit 5000
    fp --json events --full --session-id <session-id> --all --limit 2000
    ```

    Use `--full` only when the event summary lacks enough evidence. A non-null `next_cursor` means the limit was reached before the end.
  </Tab>
</Tabs>

## Follow the evidence

1. Confirm the agent, goal, environment, and outcome.
2. Find the first error or unexpected decision.
3. Inspect the event immediately before it.
4. Follow matching IDs across request and response pairs.
5. Turn the evidence into an audit, issue, or policy.

| Pair | Matching field |
| --- | --- |
| Model request and response | `request_id` |
| Tool call and result | `tool_call_id` |
| Hook start and completion | `hook_id` |
| Agent pause and resume | `pause_id` |
| Human wait and input | `input_id` |

A decision appears on `hook_completed`. The row names the outcome and policy source. An observe-mode decision appears as an allow with the would-be verdict in `failproofai_observed`.

<Warning>
  Long session duration is not always model latency. Separate model, tool, hook, and human-wait time before deciding what to fix.
</Warning>
