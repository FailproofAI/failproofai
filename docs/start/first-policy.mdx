A **policy** evaluates agent actions and returns one of three decisions:

A policy runs *inside* the agent loop. Every tool call passes through it first, and it
returns one of three decisions:

| Decision | Effect |
|---|---|
| **allow** | The call proceeds. |
| **deny** | The call never runs. The agent is told why, in words it can act on. |
| **instruct** | The call runs, and the agent gets extra context to stay on track. |

---

## Check whether one already exists

Check the built-in catalog before writing a policy. It includes secret detection,
destructive-command blocking, branch protection, infrastructure guards, and workflow gates.

```bash
failproofai policies              # what is enabled here
```

If a built-in policy matches, enable and configure it. See
[Built-in policies](/built-in-policies).

## Write it

<Steps>

<Step title="Draft the rule">
  Open **fix → Policy editor** and write the JavaScript source. **Publish version** remains
  disabled until the source parses.

  ```js
  import { customPolicies, allow, deny } from "failproofai";

  customPolicies.add({
    name: "no-production-writes",
    description: "Block writes to paths containing 'production'",
    match: { events: ["PreToolUse"] },
    fn: async (ctx) => {
      if (ctx.toolName !== "Write" && ctx.toolName !== "Edit") return allow();
      const path = ctx.toolInput?.file_path ?? "";
      if (path.includes("production")) {
        return deny("Writes to production paths are blocked — open a PR instead");
      }
      return allow();
    },
  });
  ```

  The editor can draft a policy from a description. Review the diff before selecting
  **use this**.
</Step>

<Step title="Make the denial readable">
  State what was blocked and what the agent should do next. Actionable reasons reduce
  repeated attempts.
</Step>

<Step title="Publish a version">
  Publishing creates an immutable version. Publishing the same policy ID creates its next
  version.
</Step>

</Steps>

## Roll it out in observe mode first

<Steps>

<Step title="Pin it to one machine">
  Open **fix → Deploy Policies** and select a machine.

  Click a machine, select **edit this machine**, add your policy, pin the version, and set
  the effect to **observe**.
</Step>

<Step title="Apply">
  Changes remain staged until you apply them. Review policies added and removed.
</Step>

<Step title="Wait, then read what it would have blocked">
  The daemon polls every 30 seconds and verifies each artifact. Observe mode records
  decisions without blocking actions. Review those decisions for false positives.
</Step>

<Step title="Switch to enforce, then widen">
  Switch the test machine to **enforce**, then deploy to additional machines.
</Step>

</Steps>

<Note>
  Policy evaluation never makes a network request. Hooks read only the daemon's last
  verified local deployment, so a machine that loses its connection keeps enforcing what it
  last pulled. [How that works →](/daemon)
</Note>

---

## Verify the loop actually closed

Close the issue and review the next audit. If the finding returns, use its evidence to
adjust the policy. This completes the loop: **observe → evaluate → find → prevent →
observe again**.
