Start with a behavior you want to stop and a legitimate action that must still work.

## Try a reviewed policy first

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI includes 39 reviewed policies. Check the [catalog](/policies/builtin-catalog) before writing a new one.

## Write and test your own

<Steps>
  <Step title="Create a working policy">
    ```bash
    failproofai publish --init guards.mjs
    ```

    This writes a policy that blocks `git push --force`. Edit it for your rule.
  </Step>
  <Step title="Enforce it on this machine">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    Ask your agent to perform the blocked action, then check **Policies → Activity** in the local dashboard.
  </Step>
  <Step title="Keep or remove it">
    Put a `*policies.mjs` file under `.failproofai/policies/` to load it automatically.

    Remove explicit custom files with:

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## Share it

Publish a public pack:

```bash
failproofai publish
```

Anyone can then install it with `failproofai policies add <owner>/<repo>`. Add the GitHub topic `failproofai-policies` yourself so the [Policy Hub](https://befailproof.ai/policy-hub/) can index it.

For a Cloud rollout:

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  A bare `--add checkout-guard` enforces immediately. Add `:observe` to record what the policy would do without blocking the agent.
</Warning>

See [publish a pack](/policies/publish-a-pack) or [deploy policies](/policies/deploy) for the full workflow.
