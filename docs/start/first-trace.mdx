A **session** records one agent run, including its tool calls, model requests, hooks, and
errors. Choose one connection method below.

## Choose source

| Your agents… | You connect with | Code changes |
|---|---|---|
| run on a **supported harness** — Claude Code, Codex, Copilot, Cursor, OpenCode, Pi, Hermes, OpenClaw, Factory Droid, Devin, Antigravity, Goose | `failproofai config --connect` | none |
| are **custom agents you wrote** | the Python SDK | a few `agenteye.event.*` calls |

You can use both methods in one organization.

---

<Tabs>

<Tab title="Supported harness">

Install the CLI and connect the machine.

<Steps>

<Step title="Install">
  ```bash
  npm install -g failproofai
  ```

  Requires Node 20.9+ on Linux or macOS. Windows is not supported.
</Step>

<Step title="Connect">
  ```bash
  failproofai config --connect https://app.befailproof.ai --token <your-key>
  ```

  Use the key from [step 1](/start/sign-up). Connecting does not require root.

  For interactive setup, run `failproofai config` and choose **Paste an API key**.
</Step>

<Step title="Run agent">
  Start a short run in a supported CLI, such as asking it to read a file.
</Step>

<Step title="Send now">
  ```bash
  failproofai flush --wait
  ```

  Sessions upload automatically. `flush` sends queued data immediately.
</Step>

</Steps>

</Tab>

<Tab title="Custom agents (Python SDK)">

For agents you wrote yourself, the SDK emits events from inside your code.

<Note>
  The SDK is distributed as a private wheel. Ask your FailproofAI contact for access.
</Note>

<Steps>

<Step title="Configure SDK">
  ```python
  import agenteye

  agenteye.configure(environment="production")
  ```

  The package is named `agenteye`; the product it reports to is FailproofAI Cloud.
</Step>

<Step title="Record run">
  ```python
  agenteye.event.agent_start(
      session_id="run-001", agent_id="planner", goal="answer user query"
  )

  agenteye.event.tool_use(
      session_id="run-001", agent_id="planner",
      tool_name="web_search", tool_call_id="toolu_01",
      input={"query": "latest AI research"},
  )
  agenteye.event.tool_result(
      session_id="run-001", agent_id="planner",
      tool_name="web_search", tool_call_id="toolu_01",
      output={"results": ["..."]},
  )

  agenteye.event.agent_end(session_id="run-001", agent_id="planner", outcome="success")
  ```

  Pair each start with an end. Reuse `tool_call_id` for a tool call and its result.
</Step>

<Step title="Upload events">
  The SDK writes JSONL under `~/.agenteye/events/`. The collector uploads those files.
</Step>

</Steps>

See [Python SDK](/cloud/sdk) for the event reference and file format.

</Tab>

</Tabs>

## Confirm trace

Open **analyse → Sessions**. The run should appear as a row. Open it to view the execution
graph and event timeline.

If the row is not there:

<AccordionGroup>

<Accordion title="No session">
  ```bash
  failproofai config --status
  ```

  Check that the key has `events:add`. A key with only `policies:pull` sends no events.
</Accordion>

<Accordion title="No transcripts">
  Reconnect with `--no-transcripts` and only policy decisions are sent. What each mode does
  and does not send is spelled out in
  [What leaves this machine](/cloud/connect#what-leaves-this-machine).
</Accordion>

</AccordionGroup>

## Backfill history

Import earlier sessions that remain on disk:

```bash
failproofai backfill --since 6m
failproofai backfill --dry-run
```

Backfill is idempotent and cannot recover transcripts the agent CLI has deleted. Register
non-standard transcript locations before running it:

```bash
failproofai harness add-path claude ~/work/mirror/.claude/projects
failproofai harness add-path codex "vm-a=/mnt/vm-a/.codex/sessions"
```

See [Backfill](/cli/backfill) and [Harness paths](/cli/harness) for all options.
