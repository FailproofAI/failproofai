Set up Failproof AI on one machine, then stay local or connect Cloud.

If your agent runs in a [supported harness](/reference/harnesses), follow these steps. For agents built with LangChain, CrewAI, LlamaIndex, Pydantic AI, or your own runtime, start with [instrument your agent](/start/integrations).

## Let your agent guide setup

Install the Failproof AI umbrella skill into a compatible agent:

```bash
npx skills add FailproofAI/skills
```

This installs the umbrella skill and its specialist siblings. Use `--skill
failproofai` if you only want the umbrella. It understands local and Cloud setup,
daemon health, sessions, audits, policies, and troubleshooting. It guides the work
and routes specialized tasks to the right Failproof AI skill; it does not replace
the CLI installation below.

## Set up the machine

<Steps>
  <Step title="Install and configure Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    Setup installs the background service and connects every supported agent it finds. It may ask for administrator access once. It supports Linux and macOS.
  </Step>

  <Step title="Choose policies">
    Setup chooses no policy pack. Add the Failproof AI pack:

    ```bash
    failproofai policies add FailproofAI/policies
    failproofai policies
    ```

    The second command shows every policy on this machine and whether it is on. Until you add a pack, only `block-failproofai-commands` runs.
  </Step>

  <Step title="Check the machine">
    ```bash
    failproofai config --status
    ```

    This reports the service, Cloud connection, and pause state.
  </Step>
</Steps>

## Choose local or Cloud

<Tabs>
  <Tab title="Stay local">
    No account is required.

    ```bash
    failproofai
    failproofai audit
    ```

    The first command opens the local dashboard at `http://localhost:8020`. The second scans agent history already on this machine.
  </Tab>

  <Tab title="Connect Cloud">
    Create a machine key in Failproof AI Cloud, then run:

    ```bash
    failproofai config --token <machine-key>
    failproofai config --status
    ```

    Cloud receives policy decisions and session transcripts. To send decisions only, connect first, then set `collector.sessions` to `false` in `~/.failproofai/config.json`; the current `--no-transcripts` setup flag does not apply that setting. For shared shells and CI, use `FAILPROOFAI_CLOUD_TOKEN` instead of putting the key in command history.
  </Tab>
</Tabs>

## Verify it

Run one of your agents and ask it to perform a normal task. Then:

A tool-call deny is verified on all 16 supported harnesses. Turn-end enforcement
is verified on 10; other harness-event pairs may be observation-only or unverified.

- Open **Policies → Activity** in the local dashboard to see policy decisions.
- Open **Observe → Sessions** in Cloud to see the full run.
- Run `failproofai audit` to look for risky or wasteful patterns.

<Warning>
  After setup, the `failproofaid` service is the evaluator. If it cannot answer, protected actions are denied. Run `failproofai config --status` when an agent unexpectedly stops.
</Warning>
