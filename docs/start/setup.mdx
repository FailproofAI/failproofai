Failproof AI can run entirely on one machine or connect to Cloud for shared sessions and policy management.

## Local, no account

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai
```

This installs the service, connects supported agents, adds a policy pack, and opens the dashboard at `http://localhost:8020`.

Run `failproofai audit` to scan agent history already on the machine.

## Connect Failproof AI Cloud

Create a machine key in Cloud, then run:

```bash
failproofai config --token <machine-key>
failproofai config --machine-label checkout-runner-01
failproofai policies add FailproofAI/policies
failproofai config --status
```

Or export `FAILPROOFAI_CLOUD_TOKEN=<machine-key>` and run bare `failproofai config`. Prefer the environment variable on shared machines and in CI so the key does not land in shell history or process listings.

Cloud uses one connection for two separate jobs:

- Pull policies assigned to this machine.
- Send policy decisions and session transcripts.

To send decisions only, connect first, then set `collector.sessions` to `false` in `~/.failproofai/config.json`. Do not rely on `--no-transcripts`: the current setup path parses the flag but does not apply it. See [events and configuration](/reference/events-and-configuration#machine-configuration).

<Note>
  `--machine-label` renames a machine that is already connected. Run it after the setup command, not as part of the first connection.
</Note>

## Unattended setup

`failproofai config` does not require a special non-interactive flag. In CI or a container it applies the requested setup without prompting.

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Administrator access is needed once to install the background service. Setup never opens an interactive `sudo` password prompt: it either succeeds without one or prints the commands an administrator must run.

## Platform support

Setup supports Linux and macOS. On another platform it exits without writing hooks or partial setup state.
