Her kişi, makine veya otomasyon işi için ayrı bir anahtar kullanın. Yalnızca ihtiyaç duyduğu izinleri verin.

## Anahtar oluşturun ve döndürün

**Admin → Keys** seçeneğini veya Cloud CLI'yi kullanın:

```bash
fp keys list
fp keys create "audit automation" --add audits:read
fp keys disable "audit automation"
```

Anahtar oluşturulduğunda sırrı saklayın; bir daha gösterilmez. Eski anahtarı devre dışı bırakmadan önce bir yedek oluşturarak, tüketiciyi güncelleyerek döndürün.

## Makine anahtarları

Makine anahtarı yerel hizmeti Cloud'a bağlar:

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

Bağlı bir makine iki yeteneğe ihtiyaç duyabilir:

- Cloud tarafından yönetilen politikaları almak için `policies:pull`.
- Kararları ve oturumları göndermek için `events:add`.

Durum bunları ayrı olarak raporlar çünkü biri çalışırken diğeri çalışmayabilir.

## Yaygın izinler

| İzin | İzin Verir |
| --- | --- |
| `events:add` | Olayları gönder |
| `events:read` | Olayları ve hataları oku |
| `evaluations:read` | Oturumları ve değerlendirmeleri oku |
| `audits:read` / `audits:write` | Denetlemeleri gözden geçir veya yönet |
| `policies:read` / `policies:write` | Politikaları gözden geçir veya dağıt |
| `policies:pull` | Makine politikası atamalarını çek |
| `keys:create` / `keys:disable` | Anahtarlar oluştur veya devre dışı bırak |
| `orgs:admin` | Örnek düzeyinde kuruluş yönetimi; kuruluş anahtarına atanamaz |

Bazı idari `fp fleet` ve `fp guardrails` komutları, API anahtarı yerine oturum açmış bir kullanıcı oturumu gerektirir. Yardım metinleri istek yapmadan önce bunu belirtir.

<Warning>
  `AGENTEYE_KEY` veya `AGENTEYE_API_KEY` gibi yutma kimlik bilgilerini asla `FP_API_KEY` olarak yeniden kullanmayın. Farklı sistemlere ve izinlere hizmet ederler.
</Warning>
