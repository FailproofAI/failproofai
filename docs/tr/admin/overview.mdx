Yönetim, Failproof AI'nin Bulut tarafıdır. Kuruluşlar, üyeler, API anahtarları, kuruluş ayarları ve ölçülen tüketim, tümü bir Bulut bağlantısı gerektirir.

<Note>
  Failproof AI hiç hesap olmadan da çalışır. Yerel bir makine politikayı uygular, oturum geçmişini diskte tutar, `localhost:8020` üzerinde [yerel panoyu](/tr/reference/local-dashboard) sunar ve `failproofai audit` komutunu hiçbir yere bir şey göndermeden çalıştırır. Yerel `collector` anahtarları için [makine yapılandırması](/tr/reference/events-and-configuration#machine-configuration) bölümüne bakın. Bulut kullanmıyorsanız bu bölümün geri kalanını atlayabilirsiniz.
</Note>

## Kontroller nerede bulunur

<Tabs>
  <Tab title="Pano">
    Bulut kenar çubuğunun **admin** grubu **policy editor**, **enforcement**, **usage**, **keys**, **users** ve **settings** içerir.

    ![Bulut kenar çubuğunun admin grubu: policy editor, enforcement, usage, keys, users ve settings.](/images/dashboard/admin-navigation.png)
  </Tab>
  <Tab title="CLI">
    Bulut CLI'yi yalıtılmış bir araç olarak yükleyin, ardından oturum açın:

    ```bash
    uv tool install fp-cloud-cli
    fp login
    fp whoami
    fp usage
    ```

    Global seçenekleri komutten önce koyun, örneğin `fp --org reliability-team --json usage`.
  </Tab>
</Tabs>

## Oturum açmış insan veya API anahtarı

`fp` iki kimlik doğrulama modundan birinde çalışır ve bu ayrım hangi komutların çalışacağını belirler. Bir API anahtarının gerçekleştiremediği komut, bir bağlantı açmadan ve nedenini adlandırarak çalıştırılmayı reddeder; 401 veya 403 hatasının yerine geçer.

| Komut | API anahtarı | İzin |
| --- | --- | --- |
| `fp whoami` | Evet | yok |
| `fp usage` | Evet | `usage:read` |
| `fp keys list` / `show` | Evet | `keys:read` |
| `fp keys create` | Evet | `keys:create` |
| `fp keys disable` | Evet | `keys:disable` |
| `fp keys regenerate` | Evet | `keys:regenerate` |
| `fp keys update` | Hayır | `keys:update`, hiçbir anahtar tutamaz |
| `fp users list` / `show` | Evet | `users:read` |
| `fp users create` | Evet | `users:create` |
| `fp users update` | Evet | `users:update` |
| `fp users disable` / `enable` | Evet | `users:delete` |
| `fp settings list` / `schema` | Evet | `settings:read` |
| `fp settings set` | Evet | `settings:write` |
| `fp orgs list` / `switch` / `current` / `perms` | Hayır | yalnızca oturum açmış oturum |

`fp usage`, bir raporlama betiğine verilecek komuttur: bir anahtar altında katılımsız çalışır ve yalnızca `usage:read` gerektirir.
