Ayarları dağıtıma özgü işlemsel değerler ve model bağlam penceresi geçersiz kılmalarını yapılandırmak için kullanın. API veya CLI aracılığıyla bir değeri değiştirmeden önce ayarlar şemasını inceleyin.

## Bir kuruluş ayarını değiştirme

<Tabs>
  <Tab title="Dashboard">
    1. **Yönetim → Ayarlar** bölümüne gidin, ayar grubunu bulun ve açıklaması ile geçerli kaynağını okuyun.
    2. Değeri değiştirin ve kaydedin.
    3. Model bağlam pencereleri için, model geçersiz kılmasını ekleyin veya güncelleyin ve etkili sınırı onaylayın.
    4. Değiştirilen değere bağlı oturumları ve metrikleri yeniden kontrol edin.

    ![Kuruluş kimlik doğrulaması ve işlemsel ayarları gösteren Ayarlar sayfası.](/images/dashboard/settings.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp settings list
    fp settings schema
    fp settings set <key> --value <scalar>
    fp settings set alerts.email_default_recipients \
      --json-value '["oncall@example.com"]'
    ```

    Yüklü CLI tarafından kullanılan değer türü ve onay bayrakları için `fp settings set --help` komutunu çalıştırın.
  </Tab>
</Tabs>

## Veri işleme seçenekleri

Failproof AI CLI'yi bağlamak, izler ve denetimler içeriğe bağlı olduğundan varsayılan olarak transkripsiyonları gönderir. İstemler, dosya içeriği veya terminal girişi yerel kalması gerektiğinde `--no-transcripts` kullanın; kanca etkinliği ve politika kararları yine de raporlanabilir.

Yerel alım kimlik bilgileri, gizli olmayan arka plan program ayarlarından ayrı olarak depolanır ve kısıtlayıcı izinlerle yazılır. API anahtarları hala üretim sırları olarak yönetilmelidir.

## Kuruluş ayarı başvurusu

Tüm pano tarafından düzenlenebilir ayarlar kuruluş kapsamındadır. Dağıtım genelinde davranış, sunucu ortamı yapılandırması olarak kalır.

| Anahtar | Varsayılan | Amaç |
| --- | --- | --- |
| `allowed_sign_ins` | `[]` | Mevcut üyeleri tam e-posta adreslerine veya `*@domain` biçimine kısıtlayın; boş bir liste ek kısıtlama olmadığı anlamına gelir. |
| `session_ttl_secs` | `86400` | Dashboard oturum ömrü; kabul edilen aralık 60 saniye ile 30 gündür. |
| `otp_ttl_secs` | `600` | OTP ve sihirli bağlantı ömrü; kabul edilen aralık 60–1800 saniyedir. |
| `alerts.email_default_recipients` | `[]` | Bir uyarı e-posta kanalı bunları geçersiz kılmadığında varsayılan alıcılar. |
| `alerts.slack_default_webhook` | boş | Varsayılan Slack gelen webhook URL'si. |
| `alerts.webhook_default_url` | boş | Varsayılan genel JSON webhook URL'si. |
| `alerts.webhook_signing_secret` | boş | `X-AgentEye-Signature` başlığı için kullanılan HMAC-SHA256 anahtarı; okumalar maskelenmiştir. |
| `alerts.enabled_channels` | e-posta, Slack, webhook | Uyarı kurallarının gönderebileceği kuruluş genelinde kanal türleri. |
| `default_user_permissions` | `standard` | Yeni davetleri için önceden seçilen adlandırılmış izin seti. |

`allowed_sign_ins` bir izin değil, bir filtredir: bir kişi zaten bir kuruluş üyesi olmalıdır. Her üyeyi izin vermek için boş bir liste kullanın; `*` tek değeri reddedilir. Uyarı URL'leri, geri döngü geliştirme adresleri hariç HTTPS kullanmalıdır.

## Güvenlik denetim listesi

- Cloud bağlantıları için HTTPS kullanın.
- Anahtarları en küçük izin setine kapsamlandırın.
- Üretim ve üretim dışı ortamları ayırın.
- Yayınlamadan önce transkripsiyon ve redaksiyon ayarlarını gözden geçirin.
- Kullanıcı, anahtar ve kuruluş değişikliklerini denetleyin.
- Dağıtımınız için yedekleme, saklama ve olay müdahale gereksinimlerini test edin.

<Warning>
  Transkripsiyon yakalamayı kapatmak, denetimlerin ve araştırmaların ne ispat edebileceğini değiştirir. Kararı ve beklenen sınırlamalarını kaydedin.
</Warning>
