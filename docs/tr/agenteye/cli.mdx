Failproof AI Observability'nin tüm özelliklerini terminalden veya bir komut dosyasından yönetin: pano ziyaretlerine gerek yok. `agenteye` CLI'ı verilerinizi (oturumlar, olay günlükleri, değerlendirmeler) sorgular ve kuruluşunuzu yönetir (API anahtarları, kullanıcılar, ayarlar, uyarılar, olaylar, kaydedilmiş sorgular). Bir kontrolü otomatikleştirmek, Observability'yi CI'ye entegre etmek veya bir kodlama aracısına (Claude Code, Cursor) üretimi incelemesini sağlamak istediğinizde bundan yararlanın. Her komut `--json` bayrağını destekler, bu nedenle siz komut satırında olsanız da bir kodlama aracısı sonucu ayrıştırarak çalıştırsa da eşit derecede iyi çalışır.

Bir ikili dosya ile şunları yapabilirsiniz:

- **Verilerinizi okuyun**: `sessions`, `events`, `evals`, `errors` (zaman, ajan, ortam, puan'a göre filtre uygulayın).
- **Kuruluşunuzu yönetin**: `keys`, `users`, `settings`, `alerts`, `incidents`.
- **Analitik çalıştırın**: kaydedilmiş SQL ve geçici sorgu çalıştırıcı (`query`).
- **AI asistanına sorun**: panoda sohbet ettiğiniz aynı salt-okunur analist (`agent`).

> **Not:** Bu `agenteye` CLI'ıdır, toplayıcı daemon'u (`agenteye-collector`) ile farklı bir araçtır. CLI panonuz ile konuşur; toplayıcı olayları sunucuya gönderir.

## Hızlı Başlangıç

Sıfırdan ilk sonuca dört satırda. CLI'ı panonuza yönlendirin, oturum açın, kimliğinizi onaylayın, sonra son günün çalıştırmalarını çekin:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # emailed 6-digit code
agenteye whoami                                                                  # confirm user + active org
agenteye --json sessions --since 24h                                             # one row per agent run, last 24h
```

Bu son komut en son oturumların JSON nesnesini yazdırır (en yeni ilk, varsayılan olarak 50 ile sınırlı). `jq` içine yönlendirin veya `--json`'ı çıkararak kutulaşmış, renklendirilmiş bir tablo alın. Her satır çalıştırmanın durumunu ve varsa bir değerlendiricinin bunu puanlandırdığı metrik puanları içerir (burada kısaltılmış):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

Bu sayfanın geri kalanı her bir parçayı açıklar: [kurulum](#installation) yalıtımda, [oturum açma](#authentication), [yapılandırma](#configuration), her komutun paylaştığı [genel kurallar](#global-options--conventions) ve [tam komut başvurusu](#command-reference).

## Kurulum

CLI, **`agenteye`** adlı genel bir PyPI paketidir. Her zaman kendi bağımlılıklarına sahip olması için yalıtılmış bir ortama kurun:

```bash
pipx install agenteye
# or
uv tool install agenteye
```

Python 3.10+ gerektirir. Kurulan komut **`agenteye`**'dir:

```bash
agenteye --version
agenteye --help
```

> **Not:** Failproof AI Observability Python SDK da `agenteye` dağıtım adını kullanır. CLI'ı `pipx` veya `uv tool` (paylaşılan virtualenv'e `pip install` yerine) ile kurmak ikisinin çakışmasını önler. Düz `pip install agenteye` yalnızca SDK aynı ortama kurulmamışsa iyidir.

## Kimlik Doğrulama

CLI, **pano** ile e-posta gönderilen bir kerelik kod kullanarak kimlik doğrulaması yapar:

```bash
agenteye login --email you@example.com
# A 6-digit code is emailed to you; paste it at the prompt.
```

Oturum belirteci `~/.agenteye/cli.json` dosyasında depolanır (yalnızca sizin tarafınızdan okunabilir, mod `0600`) ve varsayılan olarak 24 saat geçerlidir. Süresi dolduğunda `agenteye login` komutunu tekrar çalıştırın.

```bash
agenteye whoami     # show the current user, active org, and permissions
agenteye logout     # revoke the session and clear the stored token
```

`whoami` eksik veya süresi dolmuş bir oturumda hata vermez; bunun yerine `logged_in: false` raporlar, bu nedenle bir komut dosyası veya ajan kimlik doğrulama durumunu güvenle araştırabilir (pano URL'si ayarlanmamışsa veya erişilemez ise yine de sıfır olmayan bir çıkış kodu verebilir).

**Gereksinimler:** e-postanız panoda oturum açmaya izin verilmiş olmalıdır (Failproof AI Observability yöneticinize sorun) ve pano temel URL'sinde erişilebilir olmalıdır (bkz. [Yapılandırma](#configuration)). Bir kod talep eder ve hiçbiri gelmezse, e-postanız muhtemelen henüz pano erişimi için etkinleştirilmemiştir.

## Kuruluşunuzu seçin (çok kiracılı)

Hesabınız birden fazla kuruluşa aitse, **oturum açarken** etkin olanı seçin; kaydedilir ve sonraki her komut için kullanılır:

```bash
agenteye login --org acme           # authenticate and set the active tenant in one step
agenteye orgs list                  # the orgs you can access (the active one is marked)
agenteye orgs switch globex         # change the saved default
agenteye --org globex sessions      # override for a single command
```

Tam olarak bir kuruluşa ait iseniz otomatik olarak seçilir ve `--org`'ı tamamen göz ardı edebilirsiniz. Birkaçına ait iseniz ve seçmezseniz, CLI bunları listeler ve sizi `--org <slug>` ile yeniden çalıştırmanızı ister. Etkin kuruluş her isteğinde panoya gönderilir ve izinleriniz **kuruluş başına** çözülür; `agenteye whoami` etkin kuruluşu, içindeki izinlerinizi ve tüm üyeliklerinizi gösterir.

## Yapılandırma

| Ayar | Bayrak | Ortam değişkeni | Varsayılan |
|---|---|---|---|
| Pano temel URL'si | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **gerekli** (varsayılan yok) |
| Etkin kuruluş/kiracı | `--org` | `AGENTEYE_ORG` | oturum açarken seçilir; `~/.agenteye/cli.json` dosyasında kaydedilir |
| Oturum belirteci | `--token` | `AGENTEYE_CLI_TOKEN` | `~/.agenteye/cli.json` dosyasından |
| JSON çıktısı | `--json` | `AGENTEYE_CLI_JSON` | kapalı |
| TLS doğrulamasını atla | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | kapalı (oturum açarken kaydedilir) |
| İstek zaman aşımı (saniye) | `--timeout` | _(yok)_ | 30 |
| Kullanım telemetrisini devre dışı bırak | _(yok)_ | `AGENTEYE_ANALYTICS_DISABLED` (veya `DO_NOT_TRACK`) | telemetri şu anda devre dışı; hiçbir şey gönderilmez |

Çözme sırası **bayrak → ortam değişkeni → yapılandırma dosyası**'dır. Varsayılan yoktur; CLI'ı panonuza işaret etmelisiniz, her komut (`--base-url https://agenteye.example.com`) veya bir kez ortam aracılığıyla (ilk `login`'den sonra da kaydedilir):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

Yapılandırma dizini `AGENTEYE_HOME` (SDK ve toplayıcı tarafından kullanılan aynı kural) onurlandırır; ayarlanmışsa `cli.json` `$AGENTEYE_HOME/cli.json` dosyasında bulunur.

### Kendi imzalı veya dahili TLS

Panonuz kendi imzalı veya dahili bir sertifika (örneğin ham bir yük dengeleyici ana bilgisayar adı) ile HTTPS üzerinden sunuluyorsa, TLS doğrulaması bunu `CERTIFICATE_VERIFY_FAILED` hatasıyla reddeder. Sertifika doğrulamasını atlamak için `--insecure` geçin:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` **oturum açarken `cli.json` dosyasına kaydedilir**, bu nedenle sonraki komutlar otomatik olarak doğrulamayı atlar; bayrağı tekrar etmeniz gerekmez. Tek seferlik doğrulanmış bir çağrı için `--secure` geçin veya sonraki oturum açmada doğrulamayı kaydetmek için. CLI, doğrulama devre dışı bırakılırken panoya bağlanan herhangi bir komuttan önce stderr'e bir uyarı yazdırır. Doğrulamayı atlamak ortadaki adam saldırılarına karşı korumayı kaldırır; panonuza ağ yoluna güvenmeniz gerekir (VPN, özel alt ağ vb.) buna güvenmeden önce emin olun.

## Telemetri ve Gizlilik

> **Not:** Gönderilen CLI **bugün hiçbir kullanım telemetrisi göndermiyor.** Ana bir kill anahtarı açıktır, bu nedenle ortamınızdan bağımsız olarak hiçbir şey iletilmez. Aşağıdaki bölüm telemetri etkinleştirilirse için opt-out yeteneğini açıklar.

Etkinleştirilse bile telemetri **yalnızca anonim kullanım analitiği** olacaktır, hiçbir zaman ajan, oturum veya olay verileriniz olmayacaktır:

- **Ajan, oturum veya olay verisi altyapınızdan asla çıkmaz.** Yalnızca CLI kullanımı raporlanacaktır: komut ve alt komut adı (örn. `keys create`), kullandığınız bayrakların **adları** (asla değerleri), başarı/çıkış durumu ve süresi, artı mutasyonlar için işlem başına bir olay (örn. `api_key_created`, `query_run`) yalnızca statik adları/enumerasyonlar ve kaba sayıları içerir. Pano URL'niz, oturum belirteci, e-posta, kuruluş kısaltması, kaynak kimlikleri, SQL, anahtar sırları ve sorgu filtreleri **asla** gönderilmeyecektir. Operatörler yalnızca opak bir dahili id tarafından tanımlanır, hiçbir zaman e-postayla değil.
- **Önceden opt-out** `AGENTEYE_ANALYTICS_DISABLED=1` CLI'ın ortamında ayarlayarak (CLI ayrıca çapraz araç `DO_NOT_TRACK=1` kuralını da onurlandırır). Bu, telemetri hiçbir zaman açılır açılmaz geçerli olur, bu nedenle gizliliğe duyarlı bir ortam kalıcı olarak opt-out kalabilir.
- Telemetri etkinleştirilirse CLI doğrudan PostHog (`https://us.i.posthog.com`) öğesine gönderirdi; o ana bilgisayar engellenen bir makine sessizce hiçbir şey gönderirmezdi ve CLI etkilenmezdi.

## Genel seçenekler ve kurallar

Bunu bir kez okuyun; bu her komut için geçerlidir.

- **Genel seçenekler komuttan ÖNCE gelir.** `agenteye --json sessions` doğrudur; `agenteye sessions --json` bir kullanım hatasıdır. Globallar `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet` ve `--no-color` seçenekleridir.
- **`--json` stdout'a saf JSON yazdırır ve başka hiçbir şey yazdırmaz.** İnsan durum satırları, uyarılar ve hatalar **stderr**'e gider, bu nedenle bir `--json` stdout yakalama `jq` içine yönlendirilse bile temiz kalır. `--json`'ı olmadan insan gözleri için kutulaşmış, renklendirilmiş bir görünüm alırsınız.
- **`--help` ile keşfedin.** Her komut ve alt komutun `--help` (ve `-h` diğer adı) vardır: `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`. Üst düzey yardım ayrıca çıkış kodlarını ve genel seçenekleri listeler. Genel makine tarafından okunabilir bir yüzey dökümü yoktur; komut başına `--help` artı `agenteye query schema` ve `agenteye settings schema` etki alanına özgü olanlar için kullanın.
- **Onaylar etkileşimli olmayan ortamlarda otomatik olarak atlanır.** Oluşturma/güncelleme/silme komutları etkileşimli bir terminalinde "emin misiniz?" sorar, ancak **`--json` altında veya stdin bir TTY olmadığında otomatik olarak bu istemi atlar** (TTY etkileşimli bir terminal oturumudur; bir pipe veya CI çalıştırıcı değildir), bu nedenle komut dosyaları ve ajanlar asla takılı kalmaz. Açıkça atlamak için `--yes`/`-y` geçin. İstem bir ajan için açılmayacağından, bir ajan yıkıcı eylemler hakkında önce insanı onaylamalıdır.
- **Sayfalandırma:** sonuçlar en yeni-ilk ve imleç-sayfalandırılmış (her sayfa sonraki sayfayı getirmek için kullandığınız bir belirteç döndürür). `--limit N` (diğer ad `-n`) satırları kapaklar ve **varsayılan olarak 50**; `--all` otomatik sayfalandırır (200 satır parçalarında) **`--limit`'e kadar**, bu nedenle çıplak `--all` yine 50'de durur. Tam bir tarama için yüksek açık bir kap geçin: `--all --limit 1000`. `--page-size N` istek başına parçayı (maksimum 200) kontrol eder; `--cursor <id>` önceki bir sayfanın `next_cursor` öğesinden devam eder.
- **Zaman filtreleri:** `--since` göreceli bir pencere alır: `15m`, `1h`, `6h`, `24h`, `7d` veya `all` (panonun ön ayarları). Daha uzun veya özel bir aralık için (örneğin son 30 gün), `--from`/`--to` kullanın: `T` ve bir zaman dilimi içeren açık ISO-8601 UTC zaman damgaları (örn. `2026-06-01T00:00:00Z`) `--since` geçersiz kılar. Boşluk ayrılmış veya zaman dilimi olmayan bir değer kullanım hatasıdır.
- **`--fields a,b,c`** (`events`, `sessions`, `evals`, `errors` üzerinde) çıktıyı tablo ve `--json` için bu anahtarlara kısıtlar. Bilinmeyen adlar geçerli liste ile reddedilir, alan adlarını keşfetmek için ucuz bir yol.
- **`--file payload.json`** (veya `--file -` stdin'den okumak için) bir kaynak karmaşık bir şekle sahipse tam JSON istek gövdesini sağlar (`alerts create/update`, `settings set` ve `users create/update` üzerinde). Kaydedilmiş sorgu SQL `--sql @file.sql` yerine kullanır.
- **Çok değerli filtreler** virgülle ayrılır → bir küme olarak eşleştirilir (bir filtre içinde birleşim, filtreler arasında VE): `--event-type tool_use,tool_result`. Click seçenekleri varyantik değildir, bu nedenle `--add a b` bozulur. `--add a,b` kullanın, bayrağı tekrarlayın (`--add a --add b`) veya alıntı yapın (`--add "a b"`).

## Komut Başvurusu

### En çok kullanacağınız 5 komut

Günlük çalışmanın çoğu bir avuç okuma komutu aracılığıyla çalışır. Buradan başlayın, sonra tam yüzeye ihtiyacınız olduğunda aşağıya ulaşın:

| Komut | Ne yaptığı | Deneyin |
|---|---|---|
| `sessions` | Ajan çalıştırması başına bir satır: zaman, ortam, ajan, durum, son puan. | `agenteye --json sessions --since 24h --status error` |
| `events` | Bir çalıştırmanın içindeki ham adım başına iz (yükleri için `--full` ekleyin). | `agenteye --json events --session-id run-001 --all` |
| `evals` | Değerlendirme sonuçları ve puanları; `--aggregate` bunları yuvarlar. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | Yalnızca hatalı olaylar; `--aggregate` tür ile sayıları. | `agenteye --json errors --since 24h --aggregate` |
| `list` | Geçerli filtre değerlerini keşfedin (ajanlar, ortamlar, modeller, …). | `agenteye list agents` |

### CLI'ın yapabileceği her şey

Tam yüzey aşağıda gelir. CLI'ın **18 üst düzey komutu** vardır. Tüm okuma komutları `--json` ve yukarıdaki genel seçenekleri kabul eder; herhangi birinin ayrıntılı bayrak listesi ve JSON şekli için `agenteye <command> -h` (veya `<command> <subcommand> -h`) çalıştırın.

### Kimlik: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # emailed one-time code; saves the session
agenteye logout                                       # clear the saved session on this machine
agenteye whoami                                       # current user, active org, permissions
agenteye version                                      # print the CLI version (same as --version)
agenteye help                                         # top-level help (same as --help)
```

`orgs` etkin kiracıyı inceler ve değiştirir:

```bash
agenteye orgs list        # your orgs + your role in each (active one marked)
agenteye orgs switch acme # change the saved active org (omit the slug to pick from a list on a TTY)
agenteye orgs current     # identity card for the active org
agenteye orgs perms       # your permissions in the active org, grouped by resource
```

### Gözlem (salt okunur): `events` · `sessions` · `evals` · `errors` · `list`

Bunların hiçbiri bir onay gerektirmez. Paylaşılan filtreler: `--session-id`, `--agent-id`, `--env` (**not** `--environment`), ve zaman aralığı (`--since` / `--from` / `--to`).

```bash
# events (alias: the raw per-step trail), newest first
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: one row per agent run (time/env/agent/session/status; no score filtering)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: evaluation results + scores; --score filters by metric, --aggregate rolls up
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # status mix + per-key score stats

# errors: errored events; --aggregate for counts/sessions/agents/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: discover valid filter values before you filter
agenteye list envs        # also: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (**`evals`** üzerinde, `sessions` değil) tekrarlanabilir ve VE-birleştirilir; her bir sınır isteğe bağlıdır (`..0.5` ≤ 0,5 anlamına gelir, `0.9..` ≥ 0,9 anlamına gelir). İstek başına 20 puan filtresi. `evals --scores-full` **yalnızca insan tablosu** için bir görüntü bayrağıdır; ilk birkaç artı `+N` sayısı yerine her puan çiftini gösterir. `--json` altında hiçbir etkisi yoktur, bu her zaman tam puan nesnesini döndürür. **Bir oturumu uçtan uca okumak** için olay izini değerlendirmesiyle birleştirin:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # its scores + status
```

### Yönet (izin-kapalı): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: API anahtarları. Gizli anahtar yerel olarak oluşturulur, sunucuya gönderilir (yalnızca bir karma depolar) ve oluşturma/yeniden oluşturmada **bir kez gösterilir**; o zaman yakala. `--json` ile yalnızca `key` alanında görüntülenir. **Ada** göre başvurulur.

```bash
agenteye keys list                                   # active keys first, then revoked
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # scope to what you need; prints the secret ONCE
agenteye keys create ops --permission-set standard --remove queries:run   # seed a preset, then trim
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rotate the secret (the old one stops working)
agenteye keys disable ci-bot --yes                   # revoke
```

İzinler `(permission-set ∪ --add) − --remove` olarak çalışır. Belirteçler `slug:action` (örn. `events:read`) veya bir kaynakta birden fazla genişletmek için `slug:action.action` olarak (örn. `events:read.add` → `events:read`, `events:add`). Ön ayarlar: `read-only`, `standard`, `admin`. İnsan tarafından kullanılan izinler (`keys:update`) bir anahtara verilemez.

**`users`**: kuruluş üyeleri, **e-posta** (UUID kimliği de kabul edilir) ile başvurulur.

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predicts + confirms
agenteye users disable dev@corp.com --yes            # has protected/self guards
agenteye users enable dev@corp.com
```

**`settings`**: sabit bir kayıt defteri (mevcut anahtarları okur ve değiştirir; yeni olanlar oluşturamazsınız).

```bash
agenteye settings list                               # key · value · type · updated (secrets masked)
agenteye settings schema                             # what each key accepts (type · range · description)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: uyarı tanımları, **ada** göre başvurulur. `create` konumsal NAME artı bayraklar veya `--file` aracılığıyla tam JSON gövdesi alır.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME is required (positional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # fire a test notification
agenteye alerts delete high-errors --yes
```

**`incidents`**: uyarı olayları, id tarafından başvurulur (kısa id'ler kabul edilir). `show` tam etkinlik günlüğünü yazdırır; harekete geçmeden önce okuyun.

```bash
agenteye incidents list --state firing                # also: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assignee must be an operator
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # open one manually against an alert
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### Analitik ve asistan: `query` · `agent`

**`query`**: analitik mağazanıza karşı kaydedilmiş SQL artı bir geçici çalıştırıcı. Kaydedilmiş sorgular **ada** göre başvurulur; SQL sunucu tarafı doğrulanır (yalnızca SELECT/WITH, ifade zaman aşımı, satır kapağı).

```bash
agenteye query schema [TABLE]                         # column layout of the analytics views
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # run a saved query + a positional $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: yerleşik **AI asistanı** ile konuşur (panoda da sohbet edebileceğiniz aynı salt-okunur analist). Sohbetler kısa bir sohbet-id (ön ek-çözülmüş) ile başvurulur.

```bash
agenteye agent health                                 # is the AI assistant configured/reachable
agenteye agent models                                 # models you can pass to --model (default marked)
agenteye agent ask "which agents errored most in the last day?"    # starts a chat; prints its short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continue that chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## Çıkış Kodları

| Kod | Anlam |
|---|---|
| 0 | Başarı |
| 1 | Beklenmeyen hata (örn. pano 5xx döndürdü) |
| 2 | Kullanım hatası (geçersiz argümanlar, bilinmeyen komut/bayrak, ad çakışması) |
| 3 | Panoya erişilemiyor |
| 4 | Oturum açılmadı veya oturum süresi doldu; `agenteye login` çalıştırın |
| 5 | Kimlik doğrulandı, ancak hesabınız gerekli izne sahip değil (ileti adını belirtir) |
| 6 | İstenen kaynak bulunamadı (örn. bilinmeyen oturum veya olay kimliği) |

Bunlar CLI'ı komut dosyası yapmak için güvenli kılar: bir kodlama aracısı kimlik doğrulamayı yeniden istemek için `4`'e veya eksik izni göstermek için `5`'e dala bilir. Ajanlar için çıkış kodu işleme kalıpları ve JSON çıkış şekilleri için [Ajanlar için CLI Tariflerine](/tr/agenteye/cli-recipes) bakın.
