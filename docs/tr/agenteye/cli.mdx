Failproof AI Observability'nin tüm özelliklerini terminalden veya bir script'ten yönetin: dashboard'a gitmek gerekmez. `agenteye` CLI, verilerinizi (oturumlar, etkinlik günlükleri, değerlendirmeler) sorgular ve kuruluşunuzu yönetir (API anahtarları, kullanıcılar, ayarlar, uyarılar, olaylar, kaydedilmiş sorgular). Bir denetimi otomatikleştirmek, Observability'i CI'ye entegre etmek veya bir kodlama aracısının üretim ortamını incelemesi gerektiğinde bunu kullanın. Her komut `--json` bayrağını destekler, bu nedenle hem siz bir isteme yazarken hem de bir kodlama aracısı (Claude Code, Cursor) sonucu çalıştırdığında ve ayrıştırdığında eşit derecede iyi çalışır.

Tek bir binary ile şunları yapabilirsiniz:

- **Verilerinizi okuyun**: `sessions`, `events`, `evals`, `errors` (zaman, ajan, ortam, puan ile filtreleyin).
- **Kuruluşunuzu yönetin**: `keys`, `users`, `settings`, `alerts`, `incidents`.
- **Analitik çalıştırın**: kaydedilmiş SQL ve bir ad-hoc sorgu çalıştırıcısı (`query`).
- **AI yardımcısına sorun**: dashboard'ta sohbet ettiğiniz aynı salt-okunur analist (`agent`).

> **Not:** Bu `agenteye` CLI'dir; toplayıcı daemon'u (`agenteye-collector`) olan farklı bir araçtır. CLI'ı dashboard'unuza bağlar; toplayıcı etkinlikleri sunucuya gönderir.

## Hızlı Başlangıç

Hiçbir şeyden ilk sonuca kadar dört satırda. CLI'ı dashboard'unuza yönlendirin, oturum açın, kimliğinizi onaylayın, ardından son günün çalışmalarını çekin:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # emailed 6-digit code
agenteye whoami                                                                  # confirm user + active org
agenteye --json sessions --since 24h                                             # one row per agent run, last 24h
```

Son komut, en yakın oturumların (en yenisi ilk, varsayılan olarak 50 ile sınırlı) bir JSON nesnesi yazdırır. `jq`'ye yönlendirin ve dilimleyin veya `--json`'ı bırakın ve kutulu, renklendirilmiş bir tablo alın. Her satır, çalıştırmanın durumunu ve varsa değerlendirici tarafından puanlandırıldıysa metrik puanlarını içerir (burada kısaltılmıştır):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

Bu sayfanın geri kalanı her bir parçayı açıklar: izole ortamda [kuruluş](#installation), [oturum açma](#authentication), [yapılandırma](#configuration), her komutun paylaştığı [genel kurallar](#global-options--conventions) ve [tam komut referansı](#command-reference).

## Kurulum

CLI, **`agenteye`** adlı genel bir PyPI paketidir. Her zaman kendi bağımlılıklarına sahip olması için izole bir ortamda kurun:

```bash
pipx install agenteye
# or
uv tool install agenteye
```

Python 3.10+ gerektirir. Yüklenen komut **`agenteye`**'dir:

```bash
agenteye --version
agenteye --help
```

> **Not:** Failproof AI Observability Python SDK de `agenteye` dağıtım adını kullanır. CLI'ı `pipx` veya `uv tool` ile kurarak (`pip install`'ı paylaşılan virtualenv'e kullanmak yerine) ikisinin çarpışmasını önlersiniz. Düz `pip install agenteye` yalnızca SDK aynı ortamda kurulu değilse iyidir.

## Doğrulama

CLI, **dashboard** ile bir e-posta ile gönderilen tek seferlik kod ile doğrulama yapar:

```bash
agenteye login --email you@example.com
# A 6-digit code is emailed to you; paste it at the prompt.
```

Oturum tokeni `~/.agenteye/cli.json` içinde (yalnızca siz tarafından okunabilir, mod `0600`) depolanır ve varsayılan olarak 24 saat geçerlidir. Süresi dolduğunda, `agenteye login` komutunu yeniden çalıştırın.

```bash
agenteye whoami     # show the current user, active org, and permissions
agenteye logout     # revoke the session and clear the stored token
```

`whoami`, eksik veya süresi dolmuş bir oturumda hata vermez; bunun yerine `logged_in: false` bildirir; böylece bir script veya ajan auth durumunu güvenli bir şekilde yoklayabilir (dashboard'a ulaşılamıyorsa veya taban URL ayarlanmamışsa yine de sıfır olmayan çıkış yapabilir).

**Gereksinimler:** e-postanız dashboard'ta oturum açmaya izin verilmelidir (Failproof AI Observability yöneticinize sorun) ve dashboard, taban URL'si adresinde erişilebilir olmalıdır (bkz. [Yapılandırma](#configuration)). Bir kod talep ederseniz ve hiçbiri gelmezse, e-postanız muhtemelen henüz dashboard erişimi için etkinleştirilmemiştir.

## Kuruluşunuzu seçin (çok kiracılı)

Hesabınız birden fazla kuruluşa aitse, **oturum açarken** etkin olanı seçin; kaydedilir ve sonraki her komut için kullanılır:

```bash
agenteye login --org acme           # authenticate and set the active tenant in one step
agenteye orgs list                  # the orgs you can access (the active one is marked)
agenteye orgs switch globex         # change the saved default
agenteye --org globex sessions      # override for a single command
```

Tam olarak bir kuruluşa aitseniz otomatik olarak seçilir ve `--org`'ı tamamen görmezden gelebilirsiniz. Birkaçına aitseniz ve bir tane seçmezseniz, CLI bunları listeler ve `--org <slug>` ile yeniden çalıştırmanızı ister. Etkin kuruluş, her istekte dashboard'a gönderilir ve izinleriniz **kuruluş başına** çözümlenir; `agenteye whoami` etkin kuruluşu, içindeki izinlerinizi ve tüm üyeliklerinizi gösterir.

## Yapılandırma

| Ayar | Bayrak | Ortam değişkeni | Varsayılan |
|---|---|---|---|
| Dashboard taban URL | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **gerekli** (varsayılan yok) |
| Etkin kuruluş/kiracı | `--org` | `AGENTEYE_ORG` | oturum açarken seçilir; `~/.agenteye/cli.json`'de kaydedilir |
| Oturum tokeni | `--token` | `AGENTEYE_CLI_TOKEN` | `~/.agenteye/cli.json`'den |
| JSON çıktısı | `--json` | `AGENTEYE_CLI_JSON` | kapalı |
| TLS doğrulamasını atla | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | kapalı (oturum açarken kaydedilir) |
| İstek zaman aşımı (saniye) | `--timeout` | _(yok)_ | 30 |
| Kullanım telemetrisini devre dışı bırak | _(yok)_ | `AGENTEYE_ANALYTICS_DISABLED` (veya `DO_NOT_TRACK`) | telemetri şu anda devre dışı; hiçbir şey gönderilmez |

Çözüm sırası **bayrak → ortam değişkeni → yapılandırma dosyası**. Varsayılan yoktur; CLI'ı dashboard'unuza yönlendirmelisiniz, komut başına (`--base-url https://agenteye.example.com`) veya ortam aracılığıyla bir kez (ilk `login`'den sonra da kaydedilir):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

Yapılandırma dizini `AGENTEYE_HOME` (SDK ve toplayıcı tarafından kullanılan aynı kuralı) onurlandırır; ayarlanırsa, `cli.json` `$AGENTEYE_HOME/cli.json` içinde yaşar.

### Kendi imzalı veya dahili TLS

Dashboard'unuz kendi imzalı veya dahili sertifika ile HTTPS üzerinden sunuluyorsa (örneğin, ham yük dengeleyici ana bilgisayar adı), TLS doğrulaması `CERTIFICATE_VERIFY_FAILED` hatası ile reddeder. Sertifika doğrulamasını atlamak için `--insecure` geçirin:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure`, **oturum açarken `cli.json` içinde kaydedilir**, bu nedenle sonraki komutlar otomatik olarak doğrulamayı atlar; bayrağı tekrarlamanız gerekmez. Tek seferlik doğrulanmış bir çağrı için `--secure` geçirin veya sonraki oturum açarken doğrulamayı geri kaydetmek için. CLI, dashboard'a temas edebilecek her komutt'dan önce stderr'e doğrulama devre dışı olduğu konusunda uyarı yazdırır. Doğrulamayı atlamak ortadaki adam saldırılarına karşı koruma kaldırır; dashboard'a ağ yolunu güvendiğinizden emin olun (VPN, özel alt ağ vb.) kullanmadan önce.

## Telemetri & gizlilik

> **Not:** Gönderilen CLI **bugün hiç kullanım telemetrisi göndermez.** Ana bir kill anahtarı açıktır, bu nedenle ortamınız ne olursa olsun hiçbir şey iletilmez. Aşağıdaki bölüm, telemetri etkinleştirilirse reddetme yeteneğini açıklar.

Etkinleştirilse bile, telemetri **yalnızca anonim kullanım analitikleri** olur, asla acenteniz, oturumunuz veya etkinlik verileriniz olmaz:

- **Ajan, oturum veya etkinlik verisi asla altyapınızdan ayrılmaz.** Yalnızca CLI kullanımı bildirilebilir: komut ve alt komut adı (örn. `keys create`), kullandığınız bayrakların **adları** (asla değerleri), başarı/çıkış durumu ve süre, artı mutasyonlar için işlem başına etkinlik (örn. `api_key_created`, `query_run`) yalnızca statik adları/enum'ları ve kaba sayıları içerir. Dashboard URL'niz, oturum tokeni, e-postanız, kuruluş slug'u, kaynak kimlikleri, SQL, anahtar sırları ve sorgu filtreleri **asla** gönderilmez. Operatörler yalnızca opak bir dahili kimlikle tanımlanır, asla e-posta ile değil.
- **Ön ayarını yaparak çıkın** `AGENTEYE_ANALYTICS_DISABLED=1`'i CLI'ın ortamında ayarlayın (CLI de araçlar arası `DO_NOT_TRACK=1` kuralını onurlandırır). Bu, telemetri etkinleştirilir etkinleştirilmez yürürlüğe girer, bu nedenle gizlilik bilincine sahip bir ortam kalıcı olarak çıkılı kalabilir.
- Telemetri etkinleştirilirse, CLI doğrudan PostHog'a (`https://us.i.posthog.com`) gönderir; bu ana bilgisayarın engellediği bir makine sessizce hiçbir şey göndermez ve CLI etkilenmez.

## Genel seçenekler & kurallar

Bunu bir kez okuyun; her komut için geçerlidir.

- **Genel seçenekler komuttan ÖNCEye gider.** `agenteye --json sessions` doğru; `agenteye sessions --json` bir kullanım hatasıdır. Globaller `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet` ve `--no-color`'dır.
- **`--json` saf JSON'u stdout'a ve başka hiçbir şeyi yazdırır.** İnsan durum satırları, uyarılar ve hatalar **stderr**'e gider, bu nedenle `--json` stdout yakalama, durum satırı gösterilse bile `jq`'ye yönlendirmek için temiz kalır. `--json` olmadan insan gözleri için kutulu, renklendirilmiş bir görünüm alırsınız.
- **`--help` ile keşfedin.** Her komut ve alt komutun `--help` (ve `-h` takma adı) vardır: `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`. Üst düzey yardım ayrıca çıkış kodlarını ve genel seçenekleri listeler. Genel makine tarafından okunabilir bir yüzey dökümü yoktur; komutu başına `--help`, artı alan tarafından spesifik `agenteye query schema` ve `agenteye settings schema` bu iki kayıt defter için kullanın.
- **Onaylamalar scriptler ve aracılar için otomatik olarak atlanır.** Oluştur/güncelle/sil komutları etkileşimli bir terminalde "emin misiniz?" ister, ancak **`--json` altında veya stdin bir TTY olmadığında otomatik olarak atlanır** (TTY etkileşimli bir terminal oturumudur; bir boru veya CI çalıştırıcısı değildir), bu nedenle scriptler ve aracılar asla takılmaz. Açıkça atlattırmak için `--yes`/`-y` geçirin. Ajan için istem ateşlemeyeceği için, bir ajan yıkıcı işlemleri insan ile önce onaylamalıdır.
- **Sayfalandırma:** sonuçlar en yenisi ilk ve imleç sayfalanmıştır (her sayfa bir sonraki getirmek için kullandığınız bir token döndürür). `--limit N` (takma ad `-n`) satırları kapaklar ve **varsayılan olarak 50**; `--all` otomatik sayfalandırır (200 satırlık parçalar içinde) **`--limit`'e kadar**, bu nedenle çıplak `--all` hala 50'de durur. Tam bir tarama için yüksek açık bir sınır geçin: `--all --limit 1000`. `--page-size N` istek başına parçayı denetler (maksimum 200); `--cursor <id>` önceki sayfanın `next_cursor`'ünden devam eder.
- **Zaman filtreleri:** `--since` göreli bir pencere alır: `15m`, `1h`, `6h`, `24h`, `7d` veya `all` (dashboard'un ön ayarları). Daha uzun veya özel bir aralık için (örneğin son 30 gün), `--from`/`--to` kullanın: açık ISO-8601 UTC zaman damgaları **`T` ve bir saat dilimi ile** (örn. `2026-06-01T00:00:00Z`) bu override `--since`. Boşluk ayrılmış veya saat dilimi'siz bir değer bir kullanım hatasıdır.
- **`--fields a,b,c`** (`events`, `sessions`, `evals`, `errors`'da) çıktısını tablo ve `--json` için bu anahtarlarla sınırlandırır. Bilinmeyen adlar geçerli listenin de reddetilen ve ucuz bir yoldu alan adlarını keşfetmek.
- **`--file payload.json`** (veya stdin okumak için `--file -`) bir kaynak karmaşık bir şekle sahip olduğunda tam bir JSON istek gövdesini sağlar (`alerts create/update`, `settings set` ve `users create/update`'de). Kaydedilmiş-sorgu SQL `--sql @file.sql` bunun yerine kullanır.
- **Çok değerli filtreler** virgülle ayrılmıştır → bir set olarak eşleştirilir (bir filtre içinde birleşim, filtreler arasında AND): `--event-type tool_use,tool_result`. Tıklama seçenekleri variadic değildir, bu nedenle `--add a b` bozulur. `--add a,b` kullanın, bayrağı tekrarlayın (`--add a --add b`) veya alıntı yapın (`--add "a b"`).

## Komut referansı

### Bu 5 komutu en çok kullanacaksınız

Çoğu günlük çalışma bir avuç okuma komutu aracılığıyla çalışır. Buradan başlayın, sonra ihtiyacınız olduğunda tam yüzey aşağıya ulaşın:

| Komut | Ne yapar | Deneyin |
|---|---|---|
| `sessions` | Ajan çalıştırması başına bir satır: zaman, ortam, ajan, durum, en yeni puan. | `agenteye --json sessions --since 24h --status error` |
| `events` | Bir çalıştırma içindeki ham adım adım izleme (yükleri için `--full` ekleyin). | `agenteye --json events --session-id run-001 --all` |
| `evals` | Değerlendirme sonuçları ve puanları; `--aggregate` bunları toplaştırır. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | Yalnızca hata alan etkinlikler; sayımlar için `--aggregate` türe göre. | `agenteye --json errors --since 24h --aggregate` |
| `list` | Geçerli filtre değerlerini keşfet (aracılar, ortamlar, modeller, …). | `agenteye list agents` |

### CLI'ın yapabileceği her şey

Tam yüzey aşağıdaki gibidir. CLI'ın **18 üst düzey komutu** vardır. Tüm okuma komutları `--json` ve yukarıdaki genel seçenekleri kabul eder; herhangi birinin ayrıntılı bayrak listesi ve JSON şekli için `agenteye <command> -h` (veya `<command> <subcommand> -h`) çalıştırın.

### Kimlik: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # emailed one-time code; saves the session
agenteye logout                                       # clear the saved session on this machine
agenteye whoami                                       # current user, active org, permissions
agenteye version                                      # print the CLI version (same as --version)
agenteye help                                         # top-level help (same as --help)
```

`orgs` etkin kiracıyı inceler ve değiştirir:

```bash
agenteye orgs list        # your orgs + your role in each (active one marked)
agenteye orgs switch acme # change the saved active org (omit the slug to pick from a list on a TTY)
agenteye orgs current     # identity card for the active org
agenteye orgs perms       # your permissions in the active org, grouped by resource
```

### Gözlem (salt okunur): `events` · `sessions` · `evals` · `errors` · `list`

Bunların hiçbiri onay gerektirmez. Paylaşılan filtreler: `--session-id`, `--agent-id`, `--env` (**değil** `--environment`) ve zaman aralığı (`--since` / `--from` / `--to`).

```bash
# events (alias: the raw per-step trail), newest first
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: one row per agent run (time/env/agent/session/status; no score filtering)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: evaluation results + scores; --score filters by metric, --aggregate rolls up
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # status mix + per-key score stats

# errors: errored events; --aggregate for counts/sessions/agents/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: discover valid filter values before you filter
agenteye list envs        # also: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (**`evals`**'da, `sessions`'ta değil) tekrarlanabilir ve AND-kombinedir; her iki sınır da isteğe bağlıdır (`..0.5` ≤ 0.5 anlamına gelir, `0.9..` ≥ 0.9 anlamına gelir). İstek başına 20 puana kadar skorlama filtreleri. `evals --scores-full` **yalnızca insan tablosu** için bir görüntüleme bayrağıdır; ilk birkaç yerine her puan çiftini gösterir artı `+N` sayısı. `--json` altında hiçbir etkisi yoktur, bu her zaman tam puan nesnesini döndürür. **Bir oturumu uçtan uca okumak** için, etkinlik izini değerlendirmesi ile birleştirin:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # its scores + status
```

### Yönet (izin geçidi): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: API anahtarları. Sır yerel olarak oluşturulur, sunucuya gönderilir (yalnızca bir hash depolar) ve oluşturma/yeniden oluşturmada **bir kez gösterilir**; o zaman yakala. `--json` ile yalnızca `key` alanında görünür. **Ad** ile referans alınır.

```bash
agenteye keys list                                   # active keys first, then revoked
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # scope to what you need; prints the secret ONCE
agenteye keys create ops --permission-set standard --remove queries:run   # seed a preset, then trim
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rotate the secret (the old one stops working)
agenteye keys disable ci-bot --yes                   # revoke
```

İzinler `(permission-set ∪ --add) − --remove` olarak çalışır. Tokenler `slug:action` (örn. `events:read`) veya bir kaynakta birkaçını genişletmek için `slug:action.action` (`events:read.add` → `events:read`, `events:add`). Ön ayarlar: `read-only`, `standard`, `admin`. İnsan tarafından-yalnızca izinler (`keys:update`) bir anahtara verilemez.

**`users`**: kuruluş üyeleri, **e-posta** ile referans alınır (UUID kimliği de kabul edilir).

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predicts + confirms
agenteye users disable dev@corp.com --yes            # has protected/self guards
agenteye users enable dev@corp.com
```

**`settings`**: sabit bir kayıt defteri (mevcut anahtarları okur ve değiştirir; yeni olanlar oluşturamazsınız).

```bash
agenteye settings list                               # key · value · type · updated (secrets masked)
agenteye settings schema                             # what each key accepts (type · range · description)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: uyarı tanımları, **ad** ile referans alınır. `create` konumsal bir NAME artı bayraklar veya `--file` aracılığıyla tam bir JSON gövdesi alır.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME is required (positional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # fire a test notification
agenteye alerts delete high-errors --yes
```

**`incidents`**: uyarı olayları, kimlikle referans alınır (kısa kimlikler kabul edilir). `show` tam etkinlik günlüğünü yazdırır; davranmadan önce okuyun.

```bash
agenteye incidents list --state firing                # also: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assignee must be an operator
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # open one manually against an alert
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### Analitik & yardımcı: `query` · `agent`

**`query`**: analitik mağazanıza karşı kaydedilmiş SQL artı bir ad-hoc çalıştırıcı. Kaydedilmiş sorgular **ad** ile referans alınır; SQL sunucu tarafında doğrulanır (SADECE SELECT/WITH, ifade zaman aşımı, satır başlığı).

```bash
agenteye query schema [TABLE]                         # column layout of the analytics views
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # run a saved query + a positional $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: yerleşik **AI yardımcısı** ile konuşur (dashboard'ta sohbet edebileceğiniz aynı salt-okunur analist). Sohbetler kısa bir sohbet kimliği (ön ek çözümlü) tarafından referans alınır.

```bash
agenteye agent health                                 # is the AI assistant configured/reachable
agenteye agent models                                 # models you can pass to --model (default marked)
agenteye agent ask "which agents errored most in the last day?"    # starts a chat; prints its short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continue that chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## Çıkış kodları

| Kod | Anlamı |
|---|---|
| 0 | Başarı |
| 1 | Beklenmedik hata (örn. dashboard 5xx döndürdü) |
| 2 | Kullanım hatası (geçersiz argümanlar, bilinmeyen komut/bayrak, ad çarpışması) |
| 3 | Dashboard'a ulaşılamıyor |
| 4 | Oturum açılmadı veya oturum süresi dolmuş; `agenteye login` çalıştırın |
| 5 | Doğrulanan, ancak hesabınız gerekli izne sahip değil (ileti adlandırır) |
| 6 | İstenen kaynak bulunamadı (örn. bilinmeyen oturum veya olay kimliği) |

Bunlar CLI'ı script etmek için güvenli yapar: bir kodlama aracısı yeniden doğrulama istemek için `4`'e veya eksik izni yüzey etmek için `5`'e dallanabilir. Bkz. [Aracılar için CLI tarifleri](/tr/agenteye/cli-recipes) çıkış-kod işleme desenleri ve JSON çıktı şekilleri için.
