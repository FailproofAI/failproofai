OpenTelemetry, standart OTLP/HTTP protokolünü kullanarak ajan izlerini, günlükleri ve ölçümleri FailproofAI Cloud'a göndermenizi sağlar. Bu isteğe bağlıdır. Mevcut FailproofAI entegrasyonlarınız bunu etkinleştirmeden çalışmaya devam eder.

## Kuruluşunuz için alımı açın

Kuruluş yöneticisi **Ayarlar → OpenTelemetry**'yi açar ve alımı etkinleştirir. `events:add` izni olan bir Cloud API anahtarı kullanın; bu, ajan raporlaması için kullanılan izinle aynıdır.

Alım kapalıysa, Cloud OTLP dışa aktarımlarını reddeder, bu nedenle `failproofai otel enable` hiçbir şey değiştirmez ve ajanlarınız oturumları her zamanki şekilde göndermeye devam eder. Kuruluş anahtarını kontrol etmek için `failproofai otel status` komutunu çalıştırın ve bir yöneticiden bunu etkinleştirmesini isteyin.

## Kodlama ajanını bağlayın

`failproofai config` ile makinenizi bağlayın, ardından bir ajan seçin:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Kurulum komutu Claude Code, Codex ve Copilot'ı destekler ve uygun olarak Cloud veya yerel kimliği doğrulanmış bir geçiş seçer. Copilot yerel geçişi otomatik olarak kullanır. Geçişi kullanmadan önce yapılandırılan FailproofAI daemon'unuzu başlatın.

FailproofAI zaten bir ajanın oturum transkriptlerini gönderiyorsa, kurulum o ajanı OTLP'ye geçirip geçirmeyeceğini sorar. Varsayılan Hayır'dır. Kabul etmek o ajan için transkript yüklemelerini durdurur; ilke uygulamasını veya diğer ajanlardan raporlamayı değiştirmez.

## Uygulamayı bağlayın

Uygulamanızın OpenTelemetry enstrümantasyonunu bu ortam değişkenleriyle kullanın:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Uç nokta Cloud'un OTLP tabanıdır: `https://app.befailproof.ai/otel`; dışa aktarıcınız `/v1/traces`, `/v1/logs` veya `/v1/metrics` ekler. `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` gibi sinyal başına değişkenler olduğu gibi kullanılır, bu nedenle tam yol gerekir (örneğin `https://app.befailproof.ai/otel/v1/logs`).

`<key>` yerini API anahtarınızla değiştirin. Sırrı shell geçmişinden, ekran kayıtlarından ve işlenmiş yapılandırmadan uzak tutun. Yapılandırılmış bir makine için, `failproofai otel env --service my-agent` bloğu mevcut anahtarıyla yazdırır. Çıkışı bir kimlik bilgisi içerir.

Cloud, protobuf veya JSON olarak, gzip ile sıkıştırılan istekler de dahil olmak üzere izler, günlükler ve ölçümleri için OTLP/HTTP dışa aktarımlarını kabul eder. OTLP/gRPC'yi kabul etmez.

Ölçümler dışa aktarıcı uyumluluğu için kabul edilir ancak depolanmaz veya görüntülenmez. Desteklenen ajan izleri ve kodlama-ajan günlükleri oturumlar haline gelir; ajanın dışa aktarmadığı alanlar eksik kalır.

## İstem metnini yakalayın

<Warning>
Metin yakalama istemi, araç bağımsız değişkenleri ve diğer hassas içeriği içerebilir. `failproofai otel enable` bunu açar. İstem ve araç ayrıntısı yakalamayı kapalı tutmak için `--no-content` ekleyin.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

El ile yapılandırdığınız bir ajan için, kendi içerik yakalama denetimlerini kullanın:

<Tabs>
  <Tab title="Claude Code">
    Bu değişkenleri ajanın ortamına yukarıdaki uygulama blokuyla birlikte ekleyin:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    İstem ve araç ayrıntılarını yakalamaktan kaçınmak için her iki içerik değişkenini `0` olarak ayarlayın.
  </Tab>
  <Tab title="Codex">
    Codex'in kullanıcı yapılandırmasında OTEL ayarlarını kullanın:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex konuşması içeriği günlüklerdedir; iç çalışma zamanı izleri ve ölçümleri devre dışı bırakın. Codex, sağladığınız tam uç noktayı kullanır. İstemlerini hariç tutmak için `log_user_prompt` değerini `false` olarak ayarlayın; kurulum komutu açık bir `false` değerini korur.
  </Tab>
  <Tab title="Gemini CLI">
    Gemini'nin telemetri ayarlarını yerel geçişle kullanın:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI, `failproofai otel enable` tarafından desteklenmez. Bunu kendi kimliği doğrulanmış bir toplayıcıyla el ile yapılandırın. İstem yakalamayı engellememek için `logPrompts` değerini `false` olarak ayarlayın.
  </Tab>
  <Tab title="VS Code'da Copilot">
    Bu VS Code kullanıcı ayarlarını kullanın:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Kimliği doğrulanmış geçişi etkinleştirmek için `failproofai otel enable copilot` komutunu çalıştırın. İçeriği atlamak için `captureContent` değerini `false` olarak ayarlayın.
  </Tab>
</Tabs>

## Kurulumu kontrol edin veya geri alın

Geçiş, geçici ağ ve sunucu arızalarında telemetriyi saklar ve kurtarmadan sonra yeniden dener. Daimi `400` reddi (depolamak için çok büyük bir olay da dahil olmak üzere), yükü düzeltmeyi gerektirir. Geçiş, reddedilen toplu işi tekrar tekrar göndermek yerine inceleme için tutar.

`401` veya `403` sonrasında, kimlik bilgisini aynı kuruluş için `events:add` izni veren bir anahtarla değiştirin. Yeniden bağlanmak, kimlik bilgileri için reddedilen saklanan OTLP dışa aktarımlarını otomatik olarak yeniden göndermez; bu toplu işleri kurtarması için operatörünüze sorun. Bunları orijinal kuruluşlarında tutun.

```bash
failproofai otel status
failproofai otel disable all
```

Durum, FailproofAI tarafından yönetilen ayarları başka yerlerde yapılandırdığınız telemetriden ayırır. Devre dışı bırakmak, önceki yönetilen ayarları ve ajanın önceki transkript yükleme seçimini geri yükler.
