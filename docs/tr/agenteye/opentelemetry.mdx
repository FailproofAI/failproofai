OpenTelemetry, standart OTLP/HTTP protokolünü kullanarak ajan izlerini, günlükleri ve metriklerini FailproofAI Cloud'a göndermenize olanak tanır. Bu isteğe bağlıdır. Mevcut FailproofAI entegrasyonlarınız bunu etkinleştirmeden çalışmaya devam eder.

## Kuruluşunuz için yutma işlevini açın

Bir kuruluş yöneticisi **Ayarlar → OpenTelemetry** bölümünü açar ve yutma işlevini açar. Ajan raporlaması için kullanılan aynı izne sahip `events:add` izniyle bir Cloud API anahtarı kullanın.

Yutma işlevi kapalıysa, Cloud OTLP dışa aktarımlarını reddeder, bu nedenle `failproofai otel enable` hiçbir şey değiştirmez ve ajanlarınız oturumları her zamanki gibi göndermeye devam eder. Kuruluş anahtarını kontrol etmek için `failproofai otel status` komutunu çalıştırın ve bir yöneticiden bunu açmasını isteyin.

## Bir kodlama ajanını bağlayın

`failproofai config` ile makinenizi bağlayın, ardından bir ajan seçin:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Kurulum komutu Claude Code, Codex ve Copilot'u destekler ve uygun şekilde Cloud'u veya yerel bir kimliği doğrulanmış geçişi seçer. Copilot yerel geçişi otomatik olarak kullanır. Geçişi kullanmadan önce yapılandırılmış FailproofAI daemon'u başlatın.

FailproofAI zaten bir ajanın oturum transkriptlerini gönderiyorsa, kurulum o ajanı OTEL'e geçirip geçirmeyeceğinizi sorar. Varsayılan değer Hayır'dır. Kabul etmek o ajan için transkript yüklemelerini durdurur; bu, ilke zorlamasını veya diğer ajanlardan raporlamayı değiştirmez.

## Bir uygulamayı bağlayın

Uygulamanızın OpenTelemetry enstrümantasyonunu bu ortam değişkenleriyle kullanın:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Uç nokta Cloud'un OTLP tabanıdır, `https://app.befailproof.ai/otel`; dışa aktarıcınız `/v1/traces`, `/v1/logs` veya `/v1/metrics` ekler. `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` gibi sinyal başına değişkenler olduğu gibi kullanılır, bu nedenle tam yol gerektirir; örneğin `https://app.befailproof.ai/otel/v1/logs`.

`<key>` yerine API anahtarınızı yazın. Sırrı kabuk geçmişinden, ekran kayıtlarından ve kayıtlı konfigürasyondan uzak tutun. Yapılandırılmış bir makine için `failproofai otel env --service my-agent`, bloğu mevcut anahtarıyla yazdırır. Çıktısı bir kimlik bilgisi içerir.

Cloud, protobuf veya JSON olarak ve gzip sıkıştırılmış istekler dahil olmak üzere, izler, günlükler ve metrikler için OTLP/HTTP dışa aktarımlarını kabul eder. OTLP/gRPC'yi kabul etmez.

Metrikler dışa aktarıcı uyumluluğu için kabul edilir ancak depolanmaz veya görüntülenmez. Desteklenen ajan izleri ve kodlama ajanı günlükleri oturumlar haline gelir; ajanın dışa aktarmadığı alanlar eksik kalır.

## İstem metnini yakala

<Warning>
Metin yakalama, istemler, araç bağımsız değişkenleri ve diğer hassas içeriği içerebilir. `failproofai otel enable` bunu açar. İstem ve araç-ayrıntı yakalamasını kapalı tutmak için `--no-content` ekleyin.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

El ile yapılandırdığınız bir ajan için kendi içerik-yakalama denetimlerini kullanın:

<Tabs>
  <Tab title="Claude Code">
    Bu değişkenleri ajanınızın ortamına yukarıdaki uygulama blokunun yanına ekleyin:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    İstemler ve araç ayrıntılarını yakalamaktan kaçınmak için her iki içerik değişkenini `0` olarak ayarlayın.
  </Tab>
  <Tab title="Codex">
    Codex'in kullanıcı yapılandırmasında, OTEL ayarlarını kullanın:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex konuşma içeriği günlüklerdedir; dahili çalışma zamanı izleri ve metriklerini devre dışı bırakın. Codex, sağladığınız tam uç noktayı kullanır. İstemleri dışarıda bırakmak için `log_user_prompt` öğesini `false` olarak ayarlayın; kurulum komutu açık bir `false` koruyor.
  </Tab>
  <Tab title="Gemini CLI">
    Yerel geçişle Gemini'nin telemetri ayarlarını kullanın:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI, `failproofai otel enable` tarafından desteklenmez. Kendi kimliği doğrulanmış toplayıcınızla el ile yapılandırın. İstem yakalaması olmadan için `logPrompts` öğesini `false` olarak ayarlayın.
  </Tab>
  <Tab title="VS Code'da Copilot">
    Bu VS Code kullanıcı ayarlarını kullanın:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Kimliği doğrulanmış geçişi etkinleştirmek için `failproofai otel enable copilot` komutunu çalıştırın. İçeriği hariç tutmak için `captureContent` öğesini `false` olarak ayarlayın.
  </Tab>
</Tabs>

## Kurulumu kontrol edin veya geri alın

```bash
failproofai otel status
failproofai otel disable all
```

Durum, FailproofAI tarafından yönetilen ayarları başka yerlerde yapılandırdığınız telemetriden ayırt eder. Devre dışı bırakma, önceki yönetilen ayarları ve ajanın önceki transkript-yükleme seçimini geri yükler.
