OpenTelemetry, standart OTLP/HTTP protokolünü kullanarak ajan izlerini, günlükleri ve metrikleri FailproofAI Cloud'a göndermenizi sağlar. Bu isteğe bağlıdır. Mevcut FailproofAI entegrasyonlarınız bunu etkinleştirmeden çalışmaya devam eder.

## Kuruluşunuz için alımı etkinleştirin

Bir kuruluş yöneticisi **Ayarlar → OpenTelemetry** açar ve alımı etkinleştirir. Ajan raporlaması için kullanılan aynı izin olan `events:add` izni ile bir Cloud API anahtarı kullanın.

Alım kapatılıysa, Cloud OTLP dışa aktarımlarını reddeder, bu nedenle `failproofai otel enable` hiçbir şey değişmez ve ajanlarınız oturumları her zamanki gibi göndermeye devam eder. Kuruluş anahtarını kontrol etmek için `failproofai otel status` çalıştırın ve bir yöneticiye bunu etkinleştirmesini isteyin.

## Bir kodlama ajanı bağlayın

`failproofai config` ile makinenizi bağlayın, ardından bir ajan seçin:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Kurulum komutu Claude Code, Codex ve Copilot'u destekler ve uygun şekilde Cloud veya yerel kimlik doğrulanmış bir aktarıcı seçer. Copilot yerel aktarıcıyı otomatik olarak kullanır. Aktarıcıyı kullanmadan önce yapılandırılmış FailproofAI daemon'ını başlatın.

FailproofAI zaten bir ajanın oturum transkripsiyonlarını gönderiyorsa, kurulum o ajanı OTEL'e geçirip geçirmeyeceğinizi sorar. Varsayılan Hayır'dır. Kabul etmek o ajan için transkript yüklemelerini durdurur; ilke yaptırımını veya diğer ajanlardan raporlamayı değiştirmez.

## Bir uygulamayı bağlayın

Uygulamanızın OpenTelemetry enstrümentasyonunu şu ortam değişkenleriyle kullanın:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Uç nokta Cloud'ın OTLP tabanıdır, `https://app.befailproof.ai/otel`; dışa aktarıcınız `/v1/traces`, `/v1/logs` veya `/v1/metrics` öğesini kendisi ekler. `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` gibi sinyal başına değişkenler olduğu gibi kullanılır, bu nedenle tam yolu gerekli, örneğin `https://app.befailproof.ai/otel/v1/logs`.

`<key>` yerine API anahtarınızı girin. Sırrı kabuk geçmişinin, ekran kayıtlarının ve işlenen yapılandırmanın dışında tutun. Yapılandırılmış bir makine için `failproofai otel env --service my-agent` bloğu mevcut anahtarıyla yazdırır. Çıktısı bir kimlik bilgisi içerir.

Cloud, protobuf veya JSON olarak, gzip sıkıştırılmış istekler de dahil olmak üzere izler, günlükler ve metrikler için OTLP/HTTP dışa aktarımlarını kabul eder. OTLP/gRPC'yi kabul etmez.

Metrikler dışa aktarıcı uyumluluğu için alınır ancak depolanmaz veya görüntülenmez. Desteklenen ajan izleri ve kodlama ajanı günlükleri oturumlar haline gelir; ajanın dışa aktarmadığı alanlar eksiktir.

## İstem metnini yakala

<Warning>
Metin yakalaması istemler, araç argümanları ve diğer hassas içeriği içerebilir. `failproofai otel enable` bunu etkinleştirir. İstem ve araç ayrıntısı yakalamasını kapalı tutmak için `--no-content` ekleyin.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Manuel olarak yapılandırdığınız bir ajan için kendi içerik yakalaması kontrolleri kullanın:

<Tabs>
  <Tab title="Claude Code">
    Bu değişkenleri ajanın ortamına yukarıdaki uygulama bloğunun yanında ekleyin:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    İstemler ve araç ayrıntılarını yakalamaktan kaçınmak için her iki içerik değişkenini `0` olarak ayarlayın.
  </Tab>
  <Tab title="Codex">
    Codex'in kullanıcı yapılandırmasında OTEL ayarlarını kullanın:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex sohbet içeriği günlüklerdedir; dahili çalışma zamanı izleri ve metrikleri devre dışı bırakın. Codex sağlanan tam uç noktayı kullanır. İstlemleri dışlamak için `log_user_prompt` öğesini `false` olarak ayarlayın; kurulum komutu açık `false` öğesini korur.
  </Tab>
  <Tab title="Gemini CLI">
    Yerel aktarıcı ile Gemini'nin telemetri ayarlarını kullanın:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI `failproofai otel enable` tarafından desteklenmez. Bunu kendi kimlik doğrulanmış toplayıcınız ile manuel olarak yapılandırın. İstem yakalaması olmamak için `logPrompts` öğesini `false` olarak ayarlayın.
  </Tab>
  <Tab title="Copilot in VS Code">
    Bu VS Code kullanıcı ayarlarını kullanın:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Kimlik doğrulanmış aktarıcıyı etkinleştirmek için `failproofai otel enable copilot` çalıştırın. İçeriği hariç tutmak için `captureContent` öğesini `false` olarak ayarlayın.
  </Tab>
</Tabs>

## Kurulumu kontrol edin veya geri alın

Aktarıcı geçici ağ ve sunucu arızaları boyunca telemetriyi tutar ve kurtarma sonrasında yeniden dener. Kalıcı `400` reddi (depolamak için çok büyük bir olay dahil), yükü düzeltmeyi gerektirir. Aktarıcı, reddedilen toplu işi bunu tekrar gönderme yerine inceleme için tutar.

`401` veya `403` sonrasında kimlik bilgisini aynı kuruluş için `events:add` izni veren bir anahtarla değiştirin. Yeniden bağlanmak, kimlik bilgileri nedeniyle reddedilen tutulan OTLP dışa aktarımlarını otomatik olarak yeniden göndermez; bu toplu işleri kurtarmak için operatörünüze isteyin. Bunları orijinal kuruluşlarında tutun.

```bash
failproofai otel status
failproofai otel disable all
```

Durum FailproofAI tarafından yönetilen ayarları başka yerlerde yapılandırdığınız telemetriden ayırt eder. Devre dışı bırak, önceki yönetilen ayarları ve ajanın önceki transkript yükleme seçimini geri yükler.
