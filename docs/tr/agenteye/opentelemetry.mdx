OpenTelemetry, standart OTLP/HTTP protokolünü kullanarak agent izlerini, günlükleri ve metriklerini FailproofAI Cloud'a göndermenizi sağlar. Bu isteğe bağlıdır. Mevcut FailproofAI entegrasyonlarınız bunu etkinleştirmeden çalışmaya devam eder.

## Kuruluşunuz için alımı açın

Bir kuruluş yöneticisi **Settings → OpenTelemetry** bölümünü açar ve alımı açar. `events:add` iznine sahip bir Cloud API anahtarı kullanın; bu, agent raporlaması için kullanılan anahtardır.

Alım kapalıysa, Cloud OTLP dışa aktarımlarını reddeder, bu nedenle `failproofai otel enable` hiçbir şey değiştirmez ve aracılarınız oturumları her zamanki şekilde göndermeye devam eder. `failproofai otel status` ile kuruluş anahtarını kontrol edin ve bir yöneticiden bunu açmasını isteyin.

## Bir coding agent bağlayın

`failproofai config` ile makinenizi bağlayın, ardından bir agent seçin:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Kurulum komutu Claude Code, Codex ve Copilot'u destekler ve uygun şekilde Cloud veya yerel kimlik doğrulamalı bir relay seçer. Copilot yerel relay'i otomatik olarak kullanır. Relay'i kullanmadan önce yapılandırılmış FailproofAI daemon'ını başlatın.

FailproofAI halihazırda bir agent'ın oturum transkriptlerini gönderiyorsa, kurulum bu agent'ı OTEL'e geçirip geçirmeyeceğini sorar. Varsayılan değer Hayır'dır. Kabul ettiyseniz, o agent için transkript yüklemeleri durdurulur; bu, politika uygulamasını veya diğer agent'lardan raporlamayı değiştirmez.

## Bir uygulamayı bağlayın

Uygulamanızın OpenTelemetry enstrümantasyonunu şu ortam değişkenleriyle kullanın:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Uç nokta Cloud'un OTLP tabanıdır, `https://app.befailproof.ai/otel`; dışa aktarıcınız `/v1/traces`, `/v1/logs` veya `/v1/metrics` ekler. `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` gibi sinyal başına değişkenler olduğu gibi kullanılır, bu nedenle tam yol gerekir, örneğin `https://app.befailproof.ai/otel/v1/logs`.

`<key>` yerine API anahtarınızı yazın. Sırrı shell geçmişi, ekran kaydı ve taahhütlü yapılandırmadan uzak tutun. Yapılandırılmış bir makine için, `failproofai otel env --service my-agent` bloğu mevcut anahtarıyla yazdırır. Çıktısı bir kimlik bilgisi içerir.

Cloud, protobuf veya JSON olarak izler, günlükler ve metrikler için OTLP/HTTP dışa aktarımlarını gzip sıkıştırılmış istekler de dahil olmak üzere kabul eder. OTLP/gRPC'yi kabul etmez.

Metrikler dışa aktarıcı uyumluluğu için onaylanmıştır ancak depolanmaz veya görüntülenmez. Desteklenen agent izleri ve coding-agent günlükleri oturumlar haline gelir; agent tarafından dışa aktarılmayan alanlar eksik kalır.

## İstem metnini yakalayın

<Warning>
Metin yakalama, istekleri, araç argümanlarını ve diğer hassas içeriği içerebilir. `failproofai otel enable` bunu açar. `--no-content` ekleyerek istem ve araç-detay yakalamayı kapalı tutun.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

El ile yapılandırdığınız bir agent için, agent'ın kendi içerik yakalama kontrollerini kullanın:

<Tabs>
  <Tab title="Claude Code">
    Bu değişkenleri agent'ınızın ortamına yukarıdaki uygulama bloğunun yanına ekleyin:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    İstemler ve araç detaylarını yakalamaktan kaçınmak için her iki içerik değişkenini `0` olarak ayarlayın.
  </Tab>
  <Tab title="Codex">
    Codex'in kullanıcı yapılandırmasında, OTEL ayarlarını kullanın:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex konuşma içeriği günlüklerde yer alır; iç çalışma zamanı izleri ve metriklerini devre dışı bırakın. Codex sağladığınız tam uç noktayı kullanır. İstemleri hariç tutmak için `log_user_prompt` öğesini `false` olarak ayarlayın; kurulum komutu açık bir `false` değerini korur.
  </Tab>
  <Tab title="Gemini CLI">
    Gemini'nin telemetri ayarlarını yerel relay ile kullanın:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI, `failproofai otel enable` tarafından desteklenmez. Bunu kendi kimlik doğrulamalı toplayıcınızla manuel olarak yapılandırın. İstem yakalamayı devre dışı bırakmak için `logPrompts` öğesini `false` olarak ayarlayın.
  </Tab>
  <Tab title="Copilot in VS Code">
    Bu VS Code kullanıcı ayarlarını kullanın:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Kimlik doğrulamalı relay'i etkinleştirmek için `failproofai otel enable copilot` komutunu çalıştırın. İçeriği hariç tutmak için `captureContent` öğesini `false` olarak ayarlayın.
  </Tab>
</Tabs>

## Kurulumu kontrol edin veya geri alın

Relay, geçici ağ ve sunucu arızaları arasında telemetriyi tutar ve kurtarıldıktan sonra yeniden dener. Kalıcı bir `400` reddi, depolanmak için çok büyük olan bir olay dahil olmak üzere, yükü düzeltmeyi gerektirir. Relay, reddedilen batch'i bunu tekrar tekrar göndermek yerine inceleme için tutar.

`401` veya `403` sonrasında, kimlik bilgisini aynı kuruluş için `events:add` iznine sahip bir anahtarla değiştirin. Yeniden bağlanmak, kimlik bilgileri için reddedilen tutulan OTLP dışa aktarımlarını otomatik olarak yeniden göndermez; bu batch'leri kurtarmak için operatörünüzden isteyin. Bunları orijinal kuruluşunda tutun.

```bash
failproofai otel status
failproofai otel disable all
```

Durum, FailproofAI tarafından yönetilen ayarları başka yerde yapılandırdığınız telemetriden ayırt eder. Devre dışı bırakma, önceki yönetilen ayarları ve agent'ın önceki transkript yükleme seçimini geri yükler.
