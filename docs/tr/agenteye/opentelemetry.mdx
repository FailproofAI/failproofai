OpenTelemetry, standart OTLP/HTTP protokolünü kullanarak aracı izlerini, günlükleri ve metriklerini FailproofAI Cloud'a göndermenizi sağlar. Bu isteğe bağlıdır. Mevcut FailproofAI entegrasyonlarınız bunu etkinleştirmeden çalışmaya devam eder.

## Kuruluşunuz için alımı açın

Bir kuruluş yöneticisi **Ayarlar → OpenTelemetry** bölümünü açarak alımı etkinleştirir. Aracı raporlaması için kullanılan aynı izin olan `events:add` izniyle bir Cloud API anahtarı kullanın.

Alım kapalıysa Cloud, OTLP dışa aktarmalarını reddeder; bu nedenle `failproofai otel enable` hiçbir şey değiştiremez ve aracılarınız oturumları her zamanki gibi göndermeye devam eder. Kuruluş anahtarını kontrol etmek için `failproofai otel status` komutunu çalıştırın ve bir yöneticiye açmasını isteyin.

## Bir kodlama aracını bağlayın

Makinenizi `failproofai config` ile bağlayın, ardından bir aracı seçin:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Kurulum komutu Claude Code, Codex ve Copilot'u destekler ve uygun şekilde Cloud'u veya yerel kimliği doğrulanmış bir aktarıcıyı seçer. Copilot yerel aktarıcıyı otomatik olarak kullanır. Aktarıcıyı kullanmadan önce yapılandırılmış FailproofAI daemon'unuzu başlatın.

FailproofAI zaten bir aracının oturum transkriptlerini gönderiyorsa, kurulum bu aracıyı OTEL'e geçirip geçirmeyeceğini sorar. Varsayılan değer Hayırdır. Kabul etmek o aracı için transkript yüklemelerini durdurur; bu, ilke uygulamayı veya diğer aracılardan raporlamayı değiştirmez.

## Bir uygulamayı bağlayın

Uygulamanızın OpenTelemetry enstrümentasyonunu bu ortam değişkenleriyle kullanın:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Uç nokta Cloud'un OTLP tabanıdır, `https://app.befailproof.ai/otel`; dışa aktarıcınız `/v1/traces`, `/v1/logs` veya `/v1/metrics` öğelerini kendi başına ekler. `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` gibi sinyal başına değişkenler olduğu gibi kullanılır; bu nedenle tam yolun gereklidir, örneğin `https://app.befailproof.ai/otel/v1/logs`.

`<key>` yerine API anahtarınızı yazın. Sırrı shell geçmişinden, ekran kayıtlarından ve işlenen yapılandırmadan uzak tutun. Yapılandırılmış bir makine için, `failproofai otel env --service my-agent` bloğu mevcut anahtarıyla yazdırır. Çıktısı bir kimlik bilgisi içerir.

Cloud, protobuf veya JSON olarak, gzip sıkıştırılmış istekler dahil olmak üzere izler, günlükler ve metrikler için OTLP/HTTP dışa aktarmalarını kabul eder. OTLP/gRPC'yi kabul etmez.

Metrikler dışa aktarıcı uyumluluğu için kabul edilir ancak depolanmaz veya görüntülenmez. Desteklenen aracı izleri ve kodlama aracı günlükleri oturumlar haline gelir; aracının dışa aktarmadığı alanlar mevcut olmaz.

## İstem metnini yakala

<Warning>
Metin yakalama, istekleri, araç argümanlarını ve diğer hassas içeriği içerebilir. `failproofai otel enable` bunu açar. İstem ve araç ayrıntısı yakalamayı kapalı tutmak için `--no-content` ekleyin.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

El ile yapılandırdığınız bir aracı için kendi içerik yakalama kontrollerini kullanın:

<Tabs>
  <Tab title="Claude Code">
    Bu değişkenleri aracının ortamına yukarıdaki uygulama bloğunun yanında ekleyin:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    İstekleri ve araç ayrıntılarını yakalamaktan kaçınmak için her iki içerik değişkenini `0` olarak ayarlayın.
  </Tab>
  <Tab title="Codex">
    Codex'in kullanıcı yapılandırmasında OTEL ayarlarını kullanın:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex konuşması içeriği günlüklerdedir; dahili çalışma zamanı izlerini ve metriklerini devre dışı bırakın. Codex sağladığınız tam uç noktayı kullanır. İstekleri dışarıda bırakmak için `log_user_prompt` öğesini `false` olarak ayarlayın; kurulum komutu açık `false` öğesini korur.
  </Tab>
  <Tab title="Gemini CLI">
    Yerel aktarıcı ile Gemini'nin telemetri ayarlarını kullanın:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI, `failproofai otel enable` tarafından desteklenmez. Bunu kendi kimliği doğrulanmış toplayıcınızla el ile yapılandırın. İstem yakalamama için `logPrompts` öğesini `false` olarak ayarlayın.
  </Tab>
  <Tab title="Copilot in VS Code">
    Bu VS Code kullanıcı ayarlarını kullanın:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Kimliği doğrulanmış aktarıcıyı etkinleştirmek için `failproofai otel enable copilot` komutunu çalıştırın. İçeriği hariç tutmak için `captureContent` öğesini `false` olarak ayarlayın.
  </Tab>
</Tabs>

## Kurulumu kontrol edin veya geri alın

```bash
failproofai otel status
failproofai otel disable all
```

Durum, FailproofAI tarafından yönetilen ayarları başka yerlerde yapılandırdığınız telemetriden ayırt eder. Devre dışı bırakmak, önceki yönetilen ayarları ve aracının önceki transkript yükleme seçeneğini geri yükler.
