Bu belge failproofai'nin dahili olarak nasıl çalıştığını açıklar: hook sistemi agent araç çağrılarını nasıl keser, yapılandırma nasıl yüklenir ve birleştirilir, politikalar nasıl değerlendirilir ve pano agent aktivitesini nasıl izler.

---

## Genel Bakış

failproofai iki bağımsız alt sistemden oluşur:

1. **Hook işleyicisi** - Claude Code'un her agent araç çağrısında çağırdığı hızlı bir CLI alt işlemi. Politikaları değerlendirir ve bir karar döndürür.
2. **Agent Monitor (Pano)** - Agent oturumlarını izlemek ve politikaları yönetmek için bir Next.js web uygulaması.

Her iki alt sistem de `~/.failproofai/` ve projenin `.failproofai/` dizinindeki yapılandırma dosyalarını paylaşır, ancak ayrı işlemler olarak çalışırlar ve yalnızca dosya sistemi aracılığıyla iletişim kurarlar.

## Hook işleyicisi

### Claude Code ile Entegrasyon

`failproofai policies --install` komutunu çalıştırdığınızda, `~/.claude/settings.json` dosyasına bunun gibi girdiler yazar:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "failproofai --hook PreToolUse"
          }
        ]
      }
    ],
    "PostToolUse": [ ... ]
  }
}
```

Claude Code daha sonra her araç çağrısından önce `failproofai --hook PreToolUse` komutunu bir alt işlem olarak çağırır ve stdin üzerinden bir JSON yükü iletir.

### Yük Formatı

```json
{
  "session_id": "abc123",
  "transcript_path": "/home/user/.claude/projects/myproject/sessions/abc123.jsonl",
  "cwd": "/home/user/myproject",
  "permission_mode": "default",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": { "command": "sudo apt install nodejs" }
}
```

`PostToolUse` olayları için yük, araçtan elde edilen çıktıyı içeren `tool_result` da içerir.

İşleyici 1 MB stdin sınırını uygular. Bu sınırı aşan yükler atılır ve tüm politikalar dolaylı olarak izin verir.

### Yanıt Formatı

**Reddetme (PreToolUse):**
```json
{
  "hookSpecificOutput": {
    "permissionDecision": "deny",
    "permissionDecisionReason": "Blocked by failproofai: sudo command blocked"
  }
}
```

**Reddetme (PostToolUse):**
```json
{
  "hookSpecificOutput": {
    "additionalContext": "Blocked by failproofai because: API key detected in output"
  }
}
```

**Talimat (Stop dışında herhangi bir olay):**
```json
{
  "hookSpecificOutput": {
    "additionalContext": "Instruction from failproofai: Verify tests pass before committing."
  }
}
```

**Stop olayı talimatı:**
- Çıkış kodu: `2`
- Sebep stderr'e yazılır (stdout'a değil)

**İzin Ver:**
- Çıkış kodu: `0`
- Boş stdout

**İzin Ver ve mesaj gönder:**

`allow(message)`, işlem izin verilse bile bir politikanın Claude'a bilgilendirici bağlam göndermesini sağlar. Hook işleyicisi aşağıdaki JSON'u **stdout'a** yazar (yapılandırma dosyasına değil — bu, reddetme ve talimat yanıtları gibi hook işleyicisinin Claude Code'a verdiği yanıt):

```json
// Hook işleyicisi işlemi tarafından stdout'a yazılır
{
  "hookSpecificOutput": {
    "additionalContext": "All CI checks passed on branch 'feat/my-feature'."
  }
}
```
- Çıkış kodu: `0` (işlem izin verilir)
- Birden fazla politika `allow` ile bir mesaj döndürdüğünde, mesajları yeni satırlarla bir tek `additionalContext` dizesi halinde birleştirilir
- Hiçbir politika mesaj sağlamadığında, stdout boştur (öncekiyle aynı)

### İşleme Hattı

`src/hooks/handler.ts` tam hattı uygular:

```text
stdin JSON
  → parse payload (max 1 MB)
  → extract session metadata (session_id, cwd, tool_name, tool_input, etc.)
  → readMergedHooksConfig(cwd)    ← merges project + local + global config
  → register enabled builtin policies with resolved params
  → load custom policies from customPoliciesPath (if set)
  → register custom policies into policy registry
  → evaluate all policies (builtins first, then custom)
      → first deny short-circuits
      → instruct decisions accumulate
      → allow messages accumulate
  → write JSON decision to stdout
  → persist event to ~/.failproofai/hook-activity/current.jsonl
  → exit
```

LLM çağrısı olmayan tipik yükler için tüm süreç 100 ms'den az sürer.

## Yapılandırma Yükleme

`src/hooks/hooks-config.ts` üç kapsamlı config yüklemesini uygular.

```text
[1] {cwd}/.failproofai/policies-config.json        ← project  (highest priority)
[2] {cwd}/.failproofai/policies-config.local.json  ← local
[3] ~/.failproofai/policies-config.json             ← global   (lowest priority)
```

Birleştirme mantığı:
- `enabledPolicies` - tüm üç dosya arasında tekilleştirilmiş birleşim
- `policyParams` - politika başına anahtar, tanımlayan ilk dosya tamamen kazanır
- `customPoliciesPath` - tanımlayan ilk dosya kazanır
- `llm` - tanımlayan ilk dosya kazanır

Web panosu, proje cwd ile çağrılmadığından okuma ve yazma için `readHooksConfig()` (yalnızca global) kullanır.

## Politika Değerlendirmesi

`src/hooks/policy-evaluator.ts` politikaları sırayla çalıştırır.

Her politika için:

1. Politikanın `params` şemasını arayın (varsa).
2. Birleştirilmiş configten `policyParams[policy.name]` okuyun.
3. Kullanıcı tarafından sağlanan değerleri şema varsayılanları üzerine birleştirerek `ctx.params` üretin.
4. Çözümlenen bağlamla `policy.fn(ctx)` çağırın.
5. Sonuç `deny` ise hemen durdurun ve bu kararı döndürün.
6. Sonuç `instruct` ise mesajı toplayın ve devam edin.
7. Sonuç `allow` ise sonraki politikaya devam edin.

Tüm politikalar çalıştıktan sonra:
- Herhangi bir `deny` döndürüldüyse, reddetme yanıtını yayınlayın.
- Herhangi bir `instruct` döndürülüyse, tüm mesajları birleştirilmiş olarak tek bir talimat yanıtı yayınlayın.
- Aksi takdirde, bir izin yanıtı yayınlayın (boş stdout, çıkış 0).

## Yerleşik Politikalar

`src/hooks/builtin-policies.ts` tüm 39 yerleşik politikayı `BuiltinPolicyDefinition` nesneleri olarak tanımlar:

```typescript
interface BuiltinPolicyDefinition {
  name: string;
  description: string;
  fn: (ctx: PolicyContext) => PolicyResult;
  match: {
    events: HookEventType[];
    tools?: string[];
  };
  defaultEnabled: boolean;
  category: string;
  beta?: boolean;
  params?: PolicyParamsSchema;
}
```

`params` kabul eden politikalar, her parametre için türler ve varsayılanlar içeren bir `PolicyParamsSchema` bildirir. Politika değerlendiricisi `fn` çağırmadan önce çözümlenen değerleri `ctx.params` içine enjekte eder. Politika fonksiyonları null-koruma olmadan `ctx.params` okur çünkü varsayılanlar her zaman ilk olarak uygulanır.

Politikalar içinde örüntü eşleştirmesi ham dize eşleştirmesi yerine ayrıştırılmış komut belirteçlerini (argv) kullanır. Bu, shell operatörü enjeksiyonu yoluyla bypass'ı önler (örneğin `sudo systemctl status *` için bir örüntü, komuta `; rm -rf /` eklemek suretiyle bypass edilemez).

## Özel Politikalar

`src/hooks/custom-hooks-registry.ts` bir `globalThis`-destekli kayıt defteri uygular:

```typescript
const REGISTRY_KEY = "__failproofai_custom_hooks__";

export const customPolicies = {
  add(hook: CustomHook): void { ... }
};

export function getCustomHooks(): CustomHook[] { ... }
export function clearCustomHooks(): void { ... }  // used in tests
```

`src/hooks/custom-hooks-loader.ts` kullanıcının politika dosyasını yükler:

1. Configten `customPoliciesPath` okuyun; yoksa atla.
2. Mutlak yola çözümleyin; dosyanın var olduğunu kontrol edin.
3. Tüm `from "failproofai"` importlarını gerçek dist yoluna yeniden yazın böylece `customPolicies` aynı `globalThis` kayıt defterine çözümlensin.
4. ESM uyumluluğunu sağlamak için transitif yerel importları yinelemeli olarak yeniden yazın.
5. Geçici `.mjs` dosyaları yazın ve giriş dosyasını `import()` edin.
6. Kayıtlı kancaları almak için `getCustomHooks()` çağırın.
7. Tüm geçici dosyaları bir `finally` bloğunda temizleyin.

Herhangi bir hata durumunda (dosya bulunamadı, söz dizimi hatası, import başarısızlığı), hata `~/.failproofai/hook.log` dosyasına kaydedilir ve yükleyici boş bir dizi döndürür. Yerleşik politikalar etkilenmez.

Özel politikalar tüm yerleşik politikaların ardından değerlendirilir. Özel bir politika `deny` yine de diğer özel politikaları kısa devreli eder (ancak tüm yerleşikler o noktaya kadar zaten çalışmıştır).

## Etkinlik Günlüğü

Her hook olayından sonra, işleyici `~/.failproofai/hook-activity/current.jsonl` dosyasına bir JSONL satırı ekler; bu dosya bir sayfaya ulaştığında `page-<timestamp>-<seq>.jsonl` dosyasına dönüşür:

```json
{
  "timestamp": "2026-04-06T12:34:56.789Z",
  "sessionId": "abc123",
  "eventType": "PreToolUse",
  "toolName": "Bash",
  "policyName": "block-sudo",
  "decision": "deny",
  "reason": "sudo command blocked by failproofai",
  "durationMs": 12
}
```

İzin vermeyen bir karar alan her politika için bir satır. İzin verme kararları günlüğe kaydedilmez (dosyayı küçük tutmak için).

## Pano Mimarisi

Pano, App Router ile React Server Bileşenleri ve Server Actions kullanan bir **Next.js 16** uygulamasıdır.

```text
app/
  layout.tsx                  ← Root layout (theme, telemetry, nav)
  projects/page.tsx           ← Server component: list all Claude projects
  project/[name]/page.tsx     ← Server component: list sessions in a project
  project/[name]/session/
    [sessionId]/page.tsx      ← Server component: render session viewer
  policies/page.tsx           ← Client component: policy management + activity log
  actions/
    get-hooks-config.ts       ← Read config + policy list
    update-hooks-config.ts    ← Toggle policy on/off
    update-policy-params.ts   ← Update policy parameters
    get-hook-activity.ts      ← Paginate/search activity log
    install-hooks-web.ts      ← Install/remove hooks from the browser
  api/
    download/[project]/[session]/route.ts   ← Per-CLI session export (JSONL or JSON)
```

**Veri Akışı:**

- Sayfa bileşenleri, proje/oturum verilerini doğrudan dosya sisteminden okumak için `lib/projects.ts` ve `lib/log-entries.ts` çağırırlar (okumalar için API katmanı yok).
- Politikalar sayfası tüm mutasyonlar için Server Actions kullanır (geçiş, parametreler güncellemesi, yükleme/kaldırma).
- Oturum görüntüleyici Claude'un JSONL transkript formatını ayrıştırır ve mesajlar ile araç çağrılarının bir zaman çizelgesini oluşturur.

**Temel Tasarım Kararları:**

- Veritabanı yok - tüm kalıcı durum düz dosyalardadır (`~/.failproofai/`, `~/.claude/projects/`).
- Mutasyonlar için Server Actions - CRUD işlemleri için REST API'ya gerek yok.
- Okuma sayfaları için React Server Bileşenleri - daha hızlı ilk yükleme, veri getirme için istemci paketi yok.
- İstemci bileşenleri yalnızca etkileşimliliğin gerekli olduğu yerlerde (politika geçişleri, aktivite arama, günlük görüntüleyici).
