Bu belge failproofai'nin içten nasıl çalıştığını açıklar: hook sistemi agent araç çağrılarını nasıl keser, yapılandırma nasıl yüklenir ve birleştirilir, politikalar nasıl değerlendirilir ve dashboard agent etkinliğini nasıl izler.

---

## Genel Bakış

failproofai iki bağımsız alt sisteme sahiptir:

1. **Hook işleyici** - Claude Code'un her agent araç çağrısında çağırdığı hızlı CLI alt işlemi. Politikaları değerlendirir ve bir karar döndürür.
2. **Agent Monitor (Dashboard)** - Agent oturumlarını izlemek ve politikaları yönetmek için bir Next.js web uygulaması.

Her iki alt sistem `~/.failproofai/` ve projenin `.failproofai/` dizininde bulunan yapılandırma dosyalarını paylaşır, ancak ayrı işlemler olarak çalışırlar ve yalnızca dosya sistemi üzerinden iletişim kurarlar.

## Hook işleyici

### Claude Code ile Entegrasyon

`failproofai policies --install` komutunu çalıştırdığınızda, `~/.claude/settings.json` dosyasına şu gibi girdiler yazılır:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "failproofai --hook PreToolUse"
          }
        ]
      }
    ],
    "PostToolUse": [ ... ]
  }
}
```

Claude Code daha sonra her araç çağrısından önce `failproofai --hook PreToolUse` komutunu bir alt işlem olarak çalıştırır ve stdin üzerinden bir JSON yükü iletir.

### Yük Formatı

```json
{
  "session_id": "abc123",
  "transcript_path": "/home/user/.claude/projects/myproject/sessions/abc123.jsonl",
  "cwd": "/home/user/myproject",
  "permission_mode": "default",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": { "command": "sudo apt install nodejs" }
}
```

`PostToolUse` olayları için yük ayrıca aracın çıktısı ile birlikte `tool_result` içerir.

İşleyici 1 MB stdin sınırını uygular. Bu sınırı aşan yükler atılır ve tüm politikalar dolaylı olarak izin verir.

### Yanıt Formatı

**Reddet (PreToolUse):**
```json
{
  "hookSpecificOutput": {
    "permissionDecision": "deny",
    "permissionDecisionReason": "failproofai tarafından engellendi: sudo komutu engellendi"
  }
}
```

**Reddet (PostToolUse):**
```json
{
  "hookSpecificOutput": {
    "additionalContext": "failproofai tarafından engellendi çünkü: Çıktıda API anahtarı tespit edildi"
  }
}
```

**Talimat (Stop dışında herhangi bir olay):**
```json
{
  "hookSpecificOutput": {
    "additionalContext": "failproofai'den talimat: Commit yapmadan önce testleri doğrulayın."
  }
}
```

**Stop olayı tavsiyesi:**
- Çıkış kodu: `2`
- Nedeni stderr'e yazılır (stdout'a değil)

**İzin Ver:**
- Çıkış kodu: `0`
- Boş stdout

**İletili İzin Ver:**

`allow(message)` bir politikanın, işleme izin verildiğinde bile Claude'a informatif bağlam göndermesini sağlar. Hook işleyici aşağıdaki JSON'u **stdout**'a yazar (config dosyasına değil — bu, işleyicinin Claude Code'a verdiği yanıttır, tıpkı yukarıdaki reddet ve talimat yanıtları gibi):

```json
// Hook işleyici işlemi tarafından stdout'a yazılır
{
  "hookSpecificOutput": {
    "additionalContext": "Tüm CI kontrolleri dal 'feat/my-feature' üzerinde geçti."
  }
}
```
- Çıkış kodu: `0` (operasyona izin verilir)
- Birden fazla politika ileti ile `allow` döndürdüğünde, iletileri yeni satırlarla birleştirilerek tek bir `additionalContext` dizesine dönüştürülür
- Hiçbir politika ileti sağlamadığında stdout boştur (önceden olduğu gibi)

### İşleme Pipeline'ı

`src/hooks/handler.ts` tam pipeline'ı uygular:

```text
stdin JSON
  → yük ayrıştır (en fazla 1 MB)
  → oturum meta verilerini çıkar (session_id, cwd, tool_name, tool_input, vb.)
  → readMergedHooksConfig(cwd)    ← proje + yerel + global config'i birleştirir
  → etkin yerleşik politikaları çözülen parametrelerle kayıt et
  → customPoliciesPath'tan özel politikaları yükle (ayarlanmışsa)
  → özel politikaları politika kaydına kayıt et
  → tüm politikaları değerlendir (yerleşikler ilk, sonra özel)
      → ilk reddet kısa devre yapar
      → talimat kararları biriktir
      → izin mesajları biriktir
  → JSON kararı stdout'a yaz
  → olayı ~/.failproofai/hook-activity/current.jsonl'ye uygula
  → çık
```

Tüm işlem, LLM çağrıları olmayan tipik yükler için 100ms altında çalışır.

## Yapılandırma Yükleme

`src/hooks/hooks-config.ts` üç kapsam config yüklemesi uygular.

```text
[1] {cwd}/.failproofai/policies-config.json        ← proje  (en yüksek öncelik)
[2] {cwd}/.failproofai/policies-config.local.json  ← yerel
[3] ~/.failproofai/policies-config.json             ← global   (en düşük öncelik)
```

Birleştirme mantığı:
- `enabledPolicies` - üç dosya arasında tekilleştirilmiş birleşim
- `policyParams` - politika başına anahtar, tanımlayan ilk dosya tamamen kazanır
- `customPoliciesPath` - tanımlayan ilk dosya kazanır
- `llm` - tanımlayan ilk dosya kazanır

Web dashboard, proje cwd'si olmadan çağrılmadığı için okuma ve yazma için `readHooksConfig()` (yalnızca global) kullanır.

## Politika Değerlendirmesi

`src/hooks/policy-evaluator.ts` politikaları sırayla çalıştırır.

Her politika için:

1. Politikanın `params` şemasını arayın (varsa).
2. Birleştirilmiş config'ten `policyParams[policy.name]` değerini okuyun.
3. Kullanıcı tarafından sağlanan değerleri şema varsayılanları üzerine birleştirerek `ctx.params` oluşturun.
4. Çözülen bağlam ile `policy.fn(ctx)` komutunu çağırın.
5. Sonuç `deny` ise, hemen durun ve bu kararı döndürün.
6. Sonuç `instruct` ise, iletiyi biriktirin ve devam edin.
7. Sonuç `allow` ise, bir sonraki politikaya geçin.

Tüm politikalar çalıştıktan sonra:
- Herhangi bir `deny` döndürüldüyse, reddet yanıtını yayınlayın.
- Herhangi bir `instruct` sonucu toplandıysa, tüm iletilerin birleştirildiği tek bir talimat yanıtı yayınlayın.
- Aksi takdirde, izin yanıtını yayınlayın (boş stdout, çıkış 0).

## Yerleşik Politikalar

`src/hooks/builtin-policies.ts` tüm 39 yerleşik politikayı `BuiltinPolicyDefinition` nesneleri olarak tanımlar:

```typescript
interface BuiltinPolicyDefinition {
  name: string;
  description: string;
  fn: (ctx: PolicyContext) => PolicyResult;
  match: {
    events: HookEventType[];
    tools?: string[];
  };
  defaultEnabled: boolean;
  category: string;
  beta?: boolean;
  params?: PolicyParamsSchema;
}
```

`params` kabul eden politikalar, her parametre için tür ve varsayılan değerlerle bir `PolicyParamsSchema` tanımlarlar. Politika değerlendirici, `fn` çağrılmadan önce çözülen değerleri `ctx.params` içine yerleştirir. Politika işlevleri, varsayılanlar her zaman önce uygulandığı için `ctx.params` değerini null kontrol etmeden okurlar.

Politikalar içindeki desen eşleştirmesi ham dize eşleştirmesi değil, ayrıştırılmış komut tokenlarını (argv) kullanır. Bu, shell işleci enjeksiyonu aracılığıyla atlatılmayı engeller (örneğin `sudo systemctl status *` için bir desen, komuta `; rm -rf /` eklenerek atlatılamaz).

## Özel Politikalar

`src/hooks/custom-hooks-registry.ts` bir `globalThis` destekli kayıt defteri uygular:

```typescript
const REGISTRY_KEY = "__failproofai_custom_hooks__";

export const customPolicies = {
  add(hook: CustomHook): void { ... }
};

export function getCustomHooks(): CustomHook[] { ... }
export function clearCustomHooks(): void { ... }  // testlerde kullanılır
```

`src/hooks/custom-hooks-loader.ts` kullanıcının politika dosyasını yükler:

1. Config'ten `customPoliciesPath` değerini okuyun; yoksa atla.
2. Mutlak yola çözümle; dosyayı kontrol et.
3. `customPolicies` kayıt defterine çözmek için tüm `from "failproofai"` içe aktarımlarını gerçek dist yoluna yeniden yazın.
4. ESM uyumluluğu sağlamak için geçişli yerel içe aktarımları özyinelemeli olarak yeniden yazın.
5. Geçici `.mjs` dosyalarını yazın ve giriş dosyasını `import()` edin.
6. Kayıtlı hook'ları almak için `getCustomHooks()` komutunu çağırın.
7. `finally` bloğunda tüm geçici dosyaları temizleyin.

Herhangi bir hatada (dosya bulunamadı, söz dizimi hatası, içe aktarma başarısızlığı), hata `~/.failproofai/hook.log` dosyasına yazılır ve yükleyici boş bir dizi döndürür. Yerleşik politikalar etkilenmez.

Özel politikalar tüm yerleşik politikalardan sonra değerlendirilir. Özel bir politika `deny` hala başka özel politikaları kısa devre yapabilir (ancak bu noktada tüm yerleşikler zaten çalışmıştır).

## Etkinlik Kaydı

Her hook olayından sonra, işleyici `~/.failproofai/hook-activity/current.jsonl` dosyasına bir JSONL satırı ekler ve bir sayfaya ulaştığında `page-<timestamp>-<seq>.jsonl` içine döner:

```json
{
  "timestamp": "2026-04-06T12:34:56.789Z",
  "sessionId": "abc123",
  "eventType": "PreToolUse",
  "toolName": "Bash",
  "policyName": "block-sudo",
  "decision": "deny",
  "reason": "failproofai tarafından sudo komutu engellendi",
  "durationMs": 12
}
```

İzin vermeyen bir karar alan her politika için bir satır. İzin verme kararları günlüğe kaydedilmez (dosyayı küçük tutmak için).

## Dashboard Mimarisi

Dashboard, React Server Components ve Server Actions kullanan App Router'ı olan bir **Next.js 16** uygulamasıdır.

```text
app/
  layout.tsx                  ← Kök düzeni (tema, telemetri, navigasyon)
  projects/page.tsx           ← Sunucu bileşeni: tüm Claude projelerini listele
  project/[name]/page.tsx     ← Sunucu bileşeni: projede oturumları listele
  project/[name]/session/
    [sessionId]/page.tsx      ← Sunucu bileşeni: oturum görüntüleyicisini renderle
  policies/page.tsx           ← İstemci bileşeni: politika yönetimi + etkinlik günlüğü
  actions/
    get-hooks-config.ts       ← Config + politika listesini oku
    update-hooks-config.ts    ← Politikayı aç/kapat
    update-policy-params.ts   ← Politika parametrelerini güncelle
    get-hook-activity.ts      ← Etkinlik günlüğünü sayfalandır/ara
    install-hooks-web.ts      ← Tarayıcıdan hook'ları yükle/kaldır
  api/
    download/[project]/[session]/route.ts   ← CLI oturumu başına dışa aktarım (JSONL veya JSON)
```

**Veri akışı:**

- Sayfa bileşenleri, proje/oturum verilerini doğrudan dosya sisteminden okumak için `lib/projects.ts` ve `lib/log-entries.ts` komutlarını çağırırlar (okumalar için API katmanı yoktur).
- Politikalar sayfası tüm değişiklikler için Server Actions kullanır (aç/kapat, parametreler güncellemesi, yükle/kaldır).
- Oturum görüntüleyicisi Claude'un JSONL transkript formatını ayrıştırır ve iletiler ile araç çağrılarının bir zaman çizelgesini renderler.

**Temel tasarım kararları:**

- Veritabanı yok - tüm kalıcı durum düz dosyalarda (`~/.failproofai/`, `~/.claude/projects/`).
- Değişiklikler için Server Actions - CRUD işlemleri için REST API gerekmez.
- Okuma sayfaları için React Server Components - daha hızlı ilk yükleme, veri getirme için istemci paketi yok.
- İstemci bileşenleri yalnızca etkileşimin gerekli olduğu yerlerde (politika değişimi, etkinlik arama, günlük görüntüleyici).
