failproofai, hangi politikaların etkin olduğunu, nasıl davrandıklarını ve özel politikaların nerede yüklendiğini kontrol etmek için JSON yapılandırma dosyalarını kullanır. Yapılandırma, takımınızla paylaşmak için tasarlanmıştır - onu deponuza işleyin ve her geliştirici aynı aracı güvenlik ağını alır.

---

## Yapılandırma kapsamları

Üç yapılandırma kapsamı vardır ve öncelik sırasında değerlendirilir:

| Kapsam | Dosya yolu | Amaç |
|-------|-----------|---------|
| **proje** | `.failproofai/policies-config.json` | Repo başına ayarlar, sürüm kontrolüne işlenir |
| **yerel** | `.failproofai/policies-config.local.json` | Kişisel repo başına geçersiz kılmalar, gitignore'da |
| **genel** | `~/.failproofai/policies-config.json` | Tüm projeler arasında kullanıcı düzeyinde varsayılanlar |

failproofai bir kanca olayı aldığında, mevcut çalışma dizini için var olan üç dosyanın tamamını yükler ve birleştirir.

### Birleştirme kuralları

**`enabledPolicies`** - üç kapsamın birleşimi. Herhangi bir düzeyde etkinleştirilmiş bir politika etkindir.

```text
proje:   ["block-sudo"]
yerel:   ["block-rm-rf"]
genel:   ["block-sudo", "sanitize-api-keys"]

çözümlendi: ["block-sudo", "block-rm-rf", "sanitize-api-keys"]  ← yinelenenler kaldırılmış birleşim
```

**`policyParams`** - belirli bir politika için parametreleri tanımlayan ilk kapsam tamamen kazanır. Bir politikanın parametreleri içindeki değerlerin derin birleştirilmesi yoktur.

```text
proje:   block-sudo → { allowPatterns: ["sudo apt-get update"] }
genel:   block-sudo → { allowPatterns: ["sudo systemctl status"] }

çözümlendi: { allowPatterns: ["sudo apt-get update"] }   ← proje kazanır, genel yoksayılır
```

```text
proje:   (block-sudo girdisi yok)
yerel:   (block-sudo girdisi yok)
genel:   block-sudo → { allowPatterns: ["sudo systemctl status"] }

çözümlendi: { allowPatterns: ["sudo systemctl status"] }  ← genel'e geri düşer
```

**`customPoliciesPaths` / `customPoliciesPath`** - her iki formda da tanımlayan ilk kapsam kazanır.

**`disabledCustomPolicies`** - tüm kapsamlar arasında birleşim. Pano, bireysel bir politikayı açık veya kuralpoli dosyasından kapattığınızda, kaynak nitelikli bir kimlik buraya yazar. Listede yer almayan politikalar varsayılan olarak etkindir; kimlikler kaynak dosyasını içerir, böylece birden fazla dosyadaki aynı adlı politikalar bağımsız olarak kontrol edilebilir.

**`llm`** - ilk tanımlayan kapsam kazanır.

## Yapılandırma dosyası formatı

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-push-master",
    "sanitize-api-keys",
    "sanitize-jwt",
    "block-env-files",
    "block-read-outside-cwd"
  ],
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    },
    "block-push-master": {
      "protectedBranches": ["main", "release", "prod"]
    },
    "block-rm-rf": {
      "allowPaths": ["/tmp"]
    },
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company"]
    },
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo API key" }
      ]
    },
    "warn-large-file-write": {
      "thresholdKb": 512
    }
  },
  "customPoliciesPath": "/home/alice/myproject/my-policies.js"
}
```

## Alan başvurusu

### `enabledPolicies`

Tür: `string[]`

Etkinleştirilecek politika adlarının listesi. Adlar, `failproofai policies` tarafından gösterilen politika tanımlayıcılarıyla tam olarak eşleşmelidir. Tam liste için [Yerleşik Politikalar](/tr/built-in-policies) sayfasına bakın.

`enabledPolicies` içinde olmayan politikalar, `policyParams` içinde girdileri olsa bile inaktiftir.

### `policyParams`

Tür: `Record<string, Record<string, unknown>>`

Politika başına parametre geçersiz kılmaları. Dış anahtar politika adıdır; iç anahtarlar politikaya özgüdür. Her politika, [Yerleşik Politikalar](/tr/built-in-policies) sayfasında kullanılabilir parametrelerini belgelendirir.

Bir politikanın parametreleri varsa ancak bunları belirtmezseniz, politikanın yerleşik varsayılanları kullanılır. `policyParams` yapılandırmayan kullanıcılar önceki sürümlerle aynı davranışı alırlar.

Bir politikanın params bloğu içindeki bilinmeyen anahtarlar, kanca çalışması zamanında sessizce yoksayılır ancak `failproofai policies` çalıştırdığınızda uyarı olarak işaretlenir.

#### `hint` (kesişimsel)

Tür: `string` (isteğe bağlı)

Bir politika `deny` veya `instruct` döndürdüğünde nedene eklenen bir mesaj. Politikanın kendisini değiştirmeden Claude'a işlem yapılabilir rehberlik vermek için kullanın.

Herhangi bir politika türü ile çalışır — yerleşik, özel (`custom/`), proje kuralı (`.failproofai-project/`) veya kullanıcı kuralı (`.failproofai-user/`).

```json
{
  "policyParams": {
    "block-force-push": {
      "hint": "Bunun yerine yeni bir dal oluşturmayı deneyin."
    },
    "block-sudo": {
      "allowPatterns": ["sudo apt-get"],
      "hint": "sudo olmadan apt-get'i doğrudan kullanın."
    },
    "custom/my-policy": {
      "hint": "Önce kullanıcıdan onay isteyin."
    }
  }
}
```

`block-force-push` reddedildiğinde, Claude şunu görür: *"Zorla itme engellendi. Bunun yerine yeni bir dal oluşturmayı deneyin."*

Dize olmayan değerler ve boş dizeler sessizce yoksayılır. `hint` ayarlanmamışsa davranış değişmez (geriye uyumlu).

### `customPoliciesPath`

Tür: `string` (mutlak yol)

Özel kanca politikaları içeren bir JavaScript dosyasının yolu. Bu, `failproofai policies --install --custom <path>` tarafından otomatik olarak ayarlanır (yol depolanmadan önce mutlak olarak çözümlenir).

Dosya, her kanca olayında yeniden yüklenir - önbelleğe alma yoktur. Yazma ayrıntıları için [Özel Politikalar](/tr/custom-policies) sayfasına bakın.

### Kuralpoli tabanlı politikalar

Açık `customPoliciesPath` yanında, failproofai `.failproofai/policies/` dizinlerinden politika dosyalarını otomatik olarak keşfeder ve yükler:

| Düzey | Dizin | Kapsam |
|-------|-------|--------|
| Proje | `.failproofai/policies/` | Sürüm kontrolü aracılığıyla takımla paylaşılır |
| Kullanıcı | `~/.failproofai/policies/` | Kişisel, tüm projelere uygulanır |

<Note>
  Politikalarınızı doğrudan `~/.failproofai/policies/` içine bırakın. Yanlarındaki `cloud-policies/` klasörü, kuruluşunuzun bu makineye dağıttığı politikaları tutar — keşif alt dizinlere inmez, bu nedenle asla taranmaz ve `policies/` içine koyduğunuz hiçbir şey onunla çakışamaz.

  `~/.failproofai/policies/custom-policies/` kullanılan bir sürümden yükseltme yapıyorsanız, bu klasördeki her şey — politika dosyalarınız, içeri aktardıkları tüm `lib/` yardımcıları ve okudukları veri dosyaları — bir `failproofai` komutu çalıştırdığınız ilk sefer otomatik olarak geri taşınır ve komut neyi taşıdığını size söyler.
</Note>

**Dosya eşleştirme:** Yalnızca `*policies.{js,mjs,ts}` ile eşleşen dosyalar yüklenir (örneğin `security-policies.mjs`, `workflow-policies.js`). Dizindeki diğer dosyalar yoksayılır.

**Yapılandırma gerekmez:** Kuralpoli politikaları `policies-config.json` içinde giriş gerektirmez. Dosyaları dizine bırakın ve bir sonraki kanca olayında alınırlar.

**Birleşim yüklemesi:** Hem proje hem de kullanıcı kuralpoli dizinleri taranır. Her iki düzeyden eşleşen tüm dosyalar yüklenir (`customPoliciesPath`in ilk-kapsam-kazanır kullanmadığı tersine).

Daha fazla ayrıntı ve örnek için [Özel Politikalar](/tr/custom-policies) sayfasına bakın.

### `llm`

Tür: `object` (isteğe bağlı)

AI çağrıları yapan politikalar için LLM istemcisi yapılandırması. Çoğu kurulum için gerekli değildir.

```json
{
  "llm": {
    "model": "claude-sonnet-4-6",
    "apiKey": "sk-ant-..."
  }
}
```

## CLI'den yapılandırmayı yönetme

`policies --install` ve `policies --uninstall` komutları aracı CLI'nizin kanca ayarları dosyasına yazarken (kanca giriş noktaları), `policies-config.json` doğrudan yönettiğiniz dosyadır. İkisi ayrıdır:

- **Aracı CLI ayarları** — aracıya her araç kullanımında `failproofai --hook <event>` çağırmasını söyler:
  - **Claude Code**: `~/.claude/settings.json` (kullanıcı), `<cwd>/.claude/settings.json` (proje), `<cwd>/.claude/settings.local.json` (yerel)
  - **OpenAI Codex**: `~/.codex/hooks.json` (kullanıcı), `<cwd>/.codex/hooks.json` (proje) — Codex'in yerel kapsamı yoktur
  - **GitHub Copilot CLI _(beta)_**: `~/.copilot/hooks/failproofai.json` (kullanıcı), `<cwd>/.github/hooks/failproofai.json` (proje) — Copilot'un yerel kapsamı yoktur. Kanca girdileri Copilot'un işletim sistemi anahtarlı `bash`/`powershell` komut alanlarını `timeoutSec` ile kullanır; dosya üst düzey `version: 1` işaretçisi taşır. Copilot CLI desteği **beta** durumdadır ve `events.jsonl` kayıt şemasını (genel belgeler belirtmez) daha fazla gerçek dünya oturumlarına karşı doğruluyoruz. **VS Code Copilot Chat aracı modu (Önizleme)** kanca yapılandırmalarını `.github/hooks/*.json`, `~/.copilot/hooks/*.json` ve `~/.claude/settings.json` (`chat.hookFilesLocations` ayarı tarafından yönetilen) dosyalarından okur ve aynı Claude benzeri `{hookSpecificOutput:{permissionDecision:"deny",…}}` sözleşmesini kullanır — `copilot` tümleştirmesi ve `claude` tümleştirmesi (`~/.claude/settings.json`) tarafından zaten yazılan tam yollar, böylece `failproofai policies --install --cli copilot` (veya `--cli claude`) **VS Code aracı modunda zaten uygulanır** ve ayrı `vscode` tümleştirmesi gerekmez (VS Code'un keşif günlüklerinden canlı onaylandı).
  - **Cursor Aracı _(beta)_**: `~/.cursor/hooks.json` (kullanıcı), `<cwd>/.cursor/hooks.json` (proje) — Cursor'un yerel kapsamı yoktur. Kanca girdileri Claude benzeri `{type, command, timeout}` formunu kullanır (`bash`/`powershell` bölünmesi yok), ancak Cursor'un [kanca şeması](https://cursor.com/docs/hooks) başına camelCase olay anahtarları (`preToolUse`, `beforeSubmitPrompt`, …) altında düz bir dizide depolanır; dosya üst düzey `version: 1` işaretçisi taşır. İşleyici camelCase → PascalCase öğesini `CURSOR_EVENT_MAP` aracılığıyla normalleştirir, böylece mevcut yerleşik politikalar değişmeden çalışır. Cursor Aracı desteği **beta** durumdadır ve Cursor'un disk üzerindeki transkript biçimini (genel belgeler tarafından belirtilmemiştir) daha fazla gerçek dünya kurulumuna karşı doğruluyoruz.
  - **OpenCode _(beta)_**: `~/.config/opencode/opencode.json` + `~/.config/opencode/plugins/failproofai.mjs` (kullanıcı), `<cwd>/.opencode/opencode.json` + `<cwd>/.opencode/plugins/failproofai.mjs` (proje) — OpenCode'un yerel kapsamı yoktur. Diğer beş CLI'nin aksine, OpenCode **harici komut kanca sistemi yok**: `.opencode/plugins/` üzerinden otomatik keşif **politikaların nasıl yükleneceği değildir** (opencode v1.14.33 üzerinde) ve `opencode.json` içindeki `plugin: []` dizisine açıkça kaydedilen işlem içi JS/TS eklentilerini yükler. Kurulum, failproofai ikili dosyasını alt işlem çağıran ve ikili dosyanın Claude şekli JSON yanıtını eklenti semantiğine çevirten küçük bir oluşturulan eklenti dolgusunu düşürür: araç olayı reddetmek için `throw new Error()` (araç çağrısını iptal eder), `instruct` ve `Stop` / `SubagentStop` reddetmek için `client.session.prompt(...)` (reddetme nedenini bir sonraki kullanıcı mesajı olarak gönderir — tek zorla yeniden deneme kanalı çünkü `session.idle` yalnızca bildirimdir ve ondan atma bir no-op'tur) ve izin vermek için no-op. Dolgusuz, hem araç adlarını (küçük harf → PascalCase aracılığıyla `OPENCODE_TOOL_MAP`) hem de araç girdisi arg anahtarlarını (camelCase → snake_case aracılığıyla `OPENCODE_TOOL_INPUT_MAP` `Read` / `Write` / `Edit` için, örn. `filePath` → `file_path`, `oldString` → `old_string`) normalleştirir ve ikili dosyaya iletir, böylece `block-read-outside-cwd`, `block-env-files` ve `block-secrets-write` gibi yol kontrol yerleşikleri OpenCode araç çağrılarında değişmeden çalışır. Oturumlar `~/.local/share/opencode/opencode.db` adresindeki opencode'un SQLite DB'sinde yaşar; panonun oturum görüntüleyicisi bunları `opencode db --format json` ve `opencode export <id>` aracılığıyla okur. OpenCode desteği **beta** durumdadır ve davranışı sürümler arasında ve daha fazla gerçek dünya oturumlarına karşı doğruluyoruz. [OpenCode eklentileri belgelerine](https://opencode.ai/docs/plugins/) bakın.
  - **Pi _(beta)_**: `~/.pi/agent/settings.json` (kullanıcı), `<cwd>/.pi/settings.json` (proje) — Pi'nin yerel kapsamı yoktur. Pi başlangıçta TypeScript uzantı paketlerini yükler; ayarlar dosyası düz bir dize dizisidir `{"packages": ["./relative/path", …]}`. failproofai, paketlenmiş `pi-extension/` dizinine işaret eden tek bir packages dizisi girdisi yazar. Uzantı, Pi'nin `tool_call` / `user_bash` / `input` / `session_start` olaylarına abone olur ve `failproofai --hook <Event> --cli pi` öğesine çıkış yapar; işleyici underscore_lower_snake_case → PascalCase öğesini `PI_EVENT_MAP` aracılığıyla normalleştirir, böylece mevcut yerleşik politikalar değişmeden çalışır. Araç girdisi args, `PI_TOOL_INPUT_MAP` aracılığıyla da normalleştirilir (Pi'nin Read / Write / Edit `file_path` yerine `path` sunar; üst düzey anahtarı eşlemek, `block-env-files` ve `block-secrets-write`'in çalışmasını sağlar — `block-read-outside-cwd` zaten bir `path` geri dönüşü vardı). Pi desteği **beta** durumdadır ve Pi'nin uzantı API'si ve oturum günlüğü düzeni stabilize olurken.
  - **Hermes (hermes-agent)**: `~/.hermes/config.yaml` (**yalnızca kullanıcı kapsamı** — Hermes'in proje/yerel yapılandırması yok). Hermes bir Slack/Telegram **ağ geçididir**, bu nedenle bir kurulum her platformdan (Slack/Telegram/cli/cron) araç çağrılarını **ve** dahili alt ajanları yakalar. Kanca girdileri Hermes'in snake_case olayları tarafından anahtarlanan `hooks:` haritası altında bir `{command, timeout}` çiftidir (`pre_tool_call` / `post_tool_call` / `on_session_start` / `on_session_end` / `subagent_stop`); işleyici olayları `HERMES_EVENT_MAP` aracılığıyla ve araç adlarını `HERMES_TOOL_MAP` aracılığıyla normalleştirir, böylece yerleşik politikalar değişmeden çalışır. Yapılandırma, yorum korumalı bir YAML `Document` gidiş dönüşü aracılığıyla düzenlenir, böylece operatörün diğer ayarları kalır ve kurulum, başlıksız ağ geçidinin (TTY yok) kancaları bir onay istemi olmadan çalıştırması için `hooks_auto_accept: true` öğesini ayarlar. Değerlendirici Hermes'in `{"decision":"block","reason"}` stdout sözleşmesini yayar (Hermes çıkış kodlarını yoksayar). **Sınırlamalar:** Hermes'in `Stop` olayı yok, bu nedenle `require-*-before-stop` yerleşikleri onun için hiçbir zaman çalmaz (uygulanamaz, bozuk değil); `instruct` izin ile yayınlanan nota gerilemez (ek bağlam kanalı yok); ve çıkış sırrı redaksiyonu (`sanitize-*`) kabuk kanca sözleşmesi üzerinden araç çıkışını yeniden yazamaz. Hermes aynı zamanda çevrimdışı bir **denetim** kaynağıdır — pano, ağ geçidi oturumlarını `~/.hermes/state.db` adresinden doğrudan okur.
  - **OpenClaw (openclaw gateway)**: `~/.openclaw/openclaw.json` (**yalnızca kullanıcı kapsamı** — OpenClaw'un proje/yerel yapılandırması yok). Hermes gibi, OpenClaw kendi kendini barındıran çok kanallı bir **ağ geçididir**, bu nedenle bir kurulum her kanaldan araç çağrılarını ve dahili alt ajanlarını yakalar. Uygulamayı, OpenClaw'un **işlem içi eklenti kancaları** aracılığıyla çalıştırır (dosya tabanlı dahili kancaları yalnızca gözlem içindir ve bloke edemez), bu nedenle — OpenCode/Pi gibi — failproofai, failproofai ikilisini çalıştıran ve kararı çevirip statik bir `openclaw-plugin/` paketi gönderir. Kurulum, kaydedilen eklenti dizinini `openclaw.json`'un `plugins.load.paths[]` içinde kaydeder ve `plugins.entries.failproofai` altında etkinleştirir (`hooks.allowConversationAccess: true` ile, ham konuşma kancaları için gerekli). Değerlendirici düz bir `{permission, reason}` kararı yayar ve dolgusuz, onu her kancanın yerel dönüş şekline eşler: `before_tool_call → {block:true, blockReason}` (**PreToolUse**), `before_agent_run → {outcome:"block", reason}` (**UserPromptSubmit**), ve `before_agent_finalize → {action:"revise", reason}` (**Stop** — gerçek bir dönüş bitişi kapısı, bu nedenle `require-*-before-stop` yerleşikleri **uygulanır** OpenClaw'da, Hermes'in aksine). Olaylar ve araç adları `OPENCLAW_EVENT_MAP` / `OPENCLAW_TOOL_MAP` (`exec→Bash`, `read→Read`, …) aracılığıyla ikili tarafından normalleştirilir, böylece yerleşik politikalar değişmeden çalışır; dolgusuz, herhangi bir yumurta/ayrıştırma/zaman aşımı hatasında açık başarısız olur. OpenClaw aynı zamanda çevrimdışı bir **denetim** kaynağıdır — pano, `~/.openclaw/agents/<agentId>/sessions/<uuid>.jsonl` adresindeki JSONL oturumlarını okur.
  - **Factory Droid (`droid`)**: `~/.factory/hooks.json` (kullanıcı), `<cwd>/.factory/hooks.json` (proje) — Factory'nin yerel kapsamı yoktur. droid, Claude benzeri harici komut kanca sistemi ile birlikte gelir, ancak droid v0.171.0'a karşı canlı doğrulanan iki tuhaflıkla: (1) olay adları `hooks.json` **üst düzeyinde** yaşar — **`"hooks"` sarıcısı yoktur** (droid bunu reddeder); araç olayları (`PreToolUse`/`PostToolUse`) `"matcher": "*"` taşır, araç olmayan olaylar bunu atlar. (2) Reddet, kanca **çıkış kodu 2 + stderr** tarafından yönlendirilir, JSON kararı değil — değerlendirici'nin `factory` dalı araç/istem olayları için çıkış 2 döndürür ve `{decision:"block", reason}` yalnızca dönüş sonu `Stop` olayında döndürür (droid'in tek zorla yeniden deneme kanalı). Olaylar zaten PascalCase'dir (olay haritası yok) ve yük Claude snake_case'dir; yalnızca araç adları `FACTORY_TOOL_MAP` aracılığıyla normalleştirilir (`Execute→Bash`, `Create→Write`, `FetchUrl→WebFetch`, …). Factory aynı zamanda çevrimdışı bir **denetim** kaynağıdır — pano, `~/.factory/sessions/<encoded-cwd>/<sessionId>.jsonl` adresindeki disk üzerindeki JSONL oturumlarını okur.
  - **Devin CLI (`devin`, Cognition)**: `~/.config/devin/config.json` (kullanıcı), `<cwd>/.devin/config.json` (proje) — Devin'in yerel kapsamı yoktur. Devin devin v3000.1.27'ye karşı canlı doğrulanan **saf Claude klonidir**: standart Claude `"hooks"`-sarıcı şemasını kullanır (yazma işlemleri birleştirme açısından korumalıdır, böylece yapılandırma dosyasının diğer anahtarları — `org_id`, `theme_mode`, … — kalır), zaten PascalCase olay adları (olay haritası yok, işleyici dalı yok) ve Claude snake_case stdin yükü (normalleştirme yok). Değerlendirici'nin `devin` dalı `{"decision":"block","reason"}` JSON'u çıkış 0'da stdout'a çıkış 0'da **her** olay için (doğrulandı — bloke, `--permission-mode dangerous` öğesini geçersiz kıldı); dönüş sonu `Stop` olayında neden, `require-*-before-stop` yerleşikleri uygulanabilir zorunlu eylem zorla yeniden deneme ifadesini taşır. Yalnızca araç adları `DEVIN_TOOL_MAP` aracılığıyla normalleştirilir (`exec→Bash`; `tool_input.command` zaten kanonik). Devin aynı zamanda çevrimdışı bir **denetim** kaynağıdır — pano, `~/.local/share/devin/cli/sessions.db` adresindeki SQLite oturumlarını okur (her `sessions` satırı gerçek bir `working_directory` taşır, bu nedenle oturumlar proje cwd'si tarafından Devin'de olduğu gibi gruplandırılır).
  - **Antigravity CLI (`agy`)**: `~/.gemini/config/hooks.json` (kullanıcı), `<cwd>/.agents/hooks.json` (proje) — Antigravity'nin yerel kapsamı yoktur. Factory/Devin'in aksine, Antigravity agy v1.1.2'ye karşı canlı doğrulanan **kendi** sözleşmesine sahiptir. `hooks.json` bir **adlandırılmış kanca** şeması kullanır: üst düzey anahtar bir kanca *adıdır* (`"failproofai"`) ve değeri olay→işleyiciler haritasıdır — araç olayları (`PreToolUse`/`PostToolUse`) işleyicileri `{matcher:"*", hooks:[…]}` içine sarar, `PreInvocation`/`Stop` ise **düz** işleyici dizileridir (diğer adlandırılmış kancalar korunur). stdin yükü **camelCase protojson**'dur (`toolCall:{name,args}`, `conversationId`, `workspacePaths`, `transcriptPath`) — failproofai politikalar çalışmadan önce snake_case'e normalleştirilir ve `run_command`'in PascalCase args (`CommandLine`/`Cwd`) öğesini `ANTIGRAVITY_TOOL_INPUT_MAP` aracılığıyla eşler. Değerlendirici'nin `antigravity` dalı Antigravity'nin **kendi** yanıt şekillerini kullanır: `{decision:"deny", reason}` bir araç/istemi (çıkış 0) bloke eder, `{decision:"continue", reason}` dönüş sonu `Stop` olayında döngüyü yeniden girer (böylece `require-*-before-stop` yerleşikleri uygulanır) ve `{injectSteps:[{ephemeralMessage}]}` `PreInvocation` (→ `UserPromptSubmit`) bir öğretim enjekte eder. Araç adları `ANTIGRAVITY_TOOL_MAP` (`run_command→Bash`, `view_file→Read`, …) aracılığıyla normalleştirilir. Antigravity aynı zamanda çevrimdışı bir **denetim** kaynağıdır — pano, `~/.gemini/antigravity-cli/brain/<conversationId>/.system_generated/logs/transcript_full.jsonl` (konuşma dizini `conversation_summaries.db`) adresindeki düz JSONL transkriptlerini okur.
  - **Goose (kodname goose, Block)**: `~/.agents/plugins/failproofai/hooks/hooks.json` (kullanıcı), `<cwd>/.agents/plugins/failproofai/hooks/hooks.json` (proje) — Goose'nun yerel kapsamı yoktur. Uygulamayı Goose'nun **kancaları** sistemi aracılığıyla çalıştırır, çapraz aracı **Açık Eklentiler** speci: yükleyici, `failproofai` eklenti dizinini bırakır ve Goose başlangıçta otomatik olarak keşfeder (kendisini `~/.config/goose/config.yaml` içinde kendi kaydediyor). `hooks.json`, üst düzey `"hooks"` sarıcısı **ile** Açık Eklentiler şeması kullanır ve eşleştirici **her olayda atlanır** — düz `"*"` hiçbir şeyi eşleştirmeyen geçersiz bir regex'tir (goose v1.43.0'a karşı canlı doğrulanır). Olay adları zaten PascalCase'dir (olay haritası yok); stdin yükü `event`/`working_dir` kullanır, işleyici tarafından `hook_event_name`/`cwd` öğesine normalleştirilir. Değerlendirici'nin `goose` dalı `{"decision":"block","reason"}` JSON'u çıkış 0'da stdout'a yayar, **yalnızca** **`PreToolUse`** olayında onaylanır (goose ≥ v1.37.0'da gönderilir) — kabuk aracı için ve temsilci alt ajanların içinde çalışır, bu nedenle tek yeterli reddet noktasıdır; diğer herhangi bir kanca hatası başarısız **olur**. Goose'nun **`Stop` olayı yoktur**, bu nedenle `require-*-before-stop` yerleşikleri uygulanmaz (Hermes gibi). Araç adları `GOOSE_TOOL_MAP` (`shell→Bash`, `write→Write`, `todo__todo_write→TodoWrite`, …) ve yol anahtarları `GOOSE_TOOL_INPUT_MAP` (`path`/`source` → `file_path`) aracılığıyla normalleştirilir. Goose aynı zamanda çevrimdışı bir **denetim** kaynağıdır — pano, `~/.local/share/goose/sessions/sessions.db` adresindeki SQLite oturumlarını okur (her `sessions` satırı gerçek bir `working_dir` taşır, bu nedenle oturumlar proje cwd'si tarafından Devin'de olduğu gibi gruplandırılır; `--no-session` çizme çalıştırmaları filtrelenir).
- **`policies-config.json`** — failproofai'ye hangi politikaları değerlendireceğini ve hangi parametrelerle (tüm aracı CLI'lerde paylaşılan) söyler

Belirli bir aracıyı hedeflemek için `--cli claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose` (boşluk ayrılmış veya herhangi bir alt küme için tekrarlanan) geçin:

```bash
failproofai policies --install --cli codex --scope project
failproofai policies --install --cli copilot --scope project
failproofai policies --install --cli cursor --scope project
failproofai policies --install --cli opencode --scope project
failproofai policies --install --cli pi --scope project
failproofai policies --install --cli hermes --scope user
failproofai policies --install --cli openclaw --scope user
failproofai policies --install --cli factory --scope project
failproofai policies --install --cli devin --scope project
failproofai policies --install --cli antigravity --scope project
failproofai policies --install --cli goose --scope project
failproofai policies --install --cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose
```

`--cli` atlanırsa, `failproofai` hangi aracı CLI'lerinin yüklü olduğunu algılar (`which claude` / `which codex` / `which copilot` / `which cursor-agent` / `which opencode` / `which pi` / `which hermes` / `which openclaw` / `which droid` / `which devin` / `which agy` / `which goose`):

- **Bir CLI algılandı** — bir istem olmadan bu CLI'yi otomatik olarak seçer.
- **Çok sayıda CLI algılandı** etkileşimli bir terminalde — bir `Detected (N)` bölümüne gruplandırılmış bir ok tuşu tek seçim isteği gösterir (bir `Install for all N detected` toplam satır + her algılanan CLI ayrı ayrı) ve `Not installed (M) · install hooks ahead of time` bölümü desteklenen her algılanmayan CLI'yi ileri yükleme seçeneği olarak listeler (↑↓ taşımak için, seçmek için Enter, çıkmak için ^C). Kaldırma akışı yalnızca Algılanan bölümü gösterir.
- **Çok sayıda CLI algılandı** etkileşimli olmayan bir çalıştırmada (CI, TTY yok) — bir istem olmadan algılanan tüm CLI'ler için yükler.
- **Hiçbiri algılanmadı** — `claude` öğesine geri düşer ve PATH'de aracı ikili dosyası bulunamadığı konusunda uyarır; kanca komutu, bir tane yüklediğiniz anda etkinleşmeleri için yazılmıştır.

`policies-config.json` öğesini istediğiniz zaman doğrudan düzenleyebilirsiniz; değişiklikler yeniden başlatmaya gerek olmadan bir sonraki kanca olayında etkili olur.

## Yükseltmeler yapılandırmanızı korur

failproofai'nin yeni bir sürümü `~/.failproofai/` öğesini farklı bir şekilde düzenleyebilir. Bunu yaptığında, yükseltme sonrasındaki ilk komut dizini taşır ve **yapılandırmanız taşınır, sıfırlanmaz**:

| Tutuldu | Yeniden oluşturuldu |
|---|---|
| Politika seçiminiz ve parametreleri (`policies-config.json`) | Denetim önbelleği |
| `daemon.configured` dahil olmak üzere ayarlarınız ve ek yakalama yolları (`config.json`) | Bulut tarafından yönetilen politika dağıtımları — bir sonraki anketlemede yeniden alınan ve özet doğrulanır |
| Bulut kaydı (`credentials.json`) | Daemon çizimi durumu |
| `policies/` içindeki kendi politika dosyalarınız ve içeri aktardıkları yardımcılar | |
| Panonun okuduğu karar günlüğü ve henüz teslim edilmemiş olaylar | |

Daha yeni bir `failproofai` tarafından yazılan anahtarlar, eski bir okuyucu tarafından bırakılması yerine korunur — bu nedenle sürümler arasında hareket sessizce ayarları iki yönde de atmaz.

Bunu **yapmaz** sonra kurulumu yeniden çalıştırmanız gerekir: taşınan bir makine öncesi yaptığı gibi tam olarak uygulanır, bu da yükseltmeyi kimsenin oturumda olmadığı makinelerde güvenli kılar. Her taşıma `~/.failproofai/migrations/applied.json` içinde kaydedilir ve yerine koyulmazsa dosyalar herhangi bir şey çalıştırılmadan önce `~/.failproofai/migrations/backup-layout<n>/` öğesine kopyalanır.

Tek satır yükseltme için [`failproofai update`](/tr/cli/update) ve ayrıntılar için [`failproofai migrate`](/tr/cli/migrate) (dahil `--dry-run`) öğesine bakın.

## Örnek: takım varsayılanlarıyla proje düzeyinde yapılandırma

`.failproofai/policies-config.json` öğesini deponuza işleyin:

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-push-master",
    "sanitize-api-keys",
    "block-env-files"
  ],
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "release", "hotfix"]
    }
  }
}
```

Her geliştirici daha sonra kişisel geçersiz kılmalar için `.failproofai/policies-config.local.json` (gitignore'da) oluşturabilir, bu da takım arkadaşlarını etkilemez.
