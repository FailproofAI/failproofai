## Claude Code için hook kurulumu

Failproof AI, Claude Code ile [hook sistemi](https://docs.anthropic.com/en/docs/claude-code/hooks) aracılığıyla entegre olur. `failproofai policies --install` komutunu çalıştırdığınızda, Claude Code'un `settings.json` dosyasında her araç çağrısında tetiklenen hook komutları kaydedilir.

<Steps>
  <Step title="failproofai yükleyin">
    ```bash
    npm install -g failproofai
    ```
  </Step>
  <Step title="Tüm yerleşik politikaları etkinleştirin">
    ```bash
    failproofai policies --install
    ```
  </Step>
  <Step title="Hook'ların kaydedildiğini doğrulayın">
    ```bash
    cat ~/.claude/settings.json | grep failproofai
    ```

    `PreToolUse`, `PostToolUse`, `Notification` ve `Stop` olayları için hook girdileri göreceksiniz.
  </Step>
  <Step title="Claude Code'u çalıştırın">
    ```bash
    claude
    ```

    Politikalar artık her araç çağrısında otomatik olarak çalışır. Claude'dan `sudo rm -rf /` çalıştırmasını istemeyi deneyin - engellenir.
  </Step>
</Steps>

## Agents SDK için hook kurulumu

[Agents SDK](https://docs.anthropic.com/en/docs/agents-sdk) ile geliştiriyorsanız, aynı hook sistemini programlı olarak kullanabilirsiniz.

<Steps>
  <Step title="failproofai'yi projenize yükleyin">
    ```bash
    npm install failproofai
    ```
  </Step>
  <Step title="Agent'inizde hook'ları yapılandırın">
    Agent işleminizi oluştururken hook komutlarını geçin. Hook'lar Claude Code'daki gibi aynı şekilde çalışır - stdin/stdout JSON aracılığıyla:

    ```bash
    failproofai --hook PreToolUse   # her araçtan önce çağrılır
    failproofai --hook PostToolUse  # her araçtan sonra çağrılır
    ```
  </Step>
  <Step title="Agent'iniz için özel bir politika yazın">
    ```javascript
    import { customPolicies, allow, deny } from "failproofai";

    customPolicies.add({
      name: "limit-to-project-dir",
      description: "Agent'i proje dizini içinde tutun",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        const path = String(ctx.toolInput?.file_path ?? "");
        if (path.startsWith("/") && !path.startsWith(ctx.session?.cwd ?? "")) {
          return deny("Agent proje dizini ile sınırlıdır");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="Özel politikayı yükleyin">
    ```bash
    failproofai policies --install --custom ./my-agent-policies.js
    ```
  </Step>
</Steps>

## Yıkıcı komutları engelle

En yaygın kurulum - agent'lerin geri döndürülemez hasara neden olmasını önle.

```bash
failproofai policies --install block-sudo block-rm-rf block-force-push block-curl-pipe-sh
```

Bunu ne yapar:
- `block-sudo` - tüm `sudo` komutlarını engeller
- `block-rm-rf` - özyinelemeli dosya silmeyi engeller
- `block-force-push` - `git push --force` komutunu engeller
- `block-curl-pipe-sh` - uzak betikleri shell'e yönlendirmeyi engeller

## Sır sızıntısını önle

Agent'lerin kimlik bilgilerini görmesini veya araç çıktısında sızıntısını önle.

```bash
failproofai policies --install sanitize-api-keys sanitize-jwt sanitize-connection-strings sanitize-bearer-tokens
```

Bunlar `PostToolUse` üzerinde çalışır - bir araç çalıştıktan sonra, agent görmezden önce çıktıyı temizlerler.

## Agent'ler dikkat istediğinde Slack uyarıları al

Boş uyarılarını Slack'e iletmek için notification hook'unu kullan.

```javascript
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "slack-on-idle",
  description: "Agent giriş beklerken Slack'e uyarı gönder",
  match: { events: ["Notification"] },
  fn: async (ctx) => {
    const webhookUrl = process.env.SLACK_WEBHOOK_URL;
    if (!webhookUrl) return allow();

    const message = String(ctx.payload?.message ?? "Agent bekleniyor");
    const project = ctx.session?.cwd ?? "bilinmiyor";

    try {
      await fetch(webhookUrl, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          text: `*${message}*\nProje: \`${project}\``,
        }),
        signal: AbortSignal.timeout(5000),
      });
    } catch {
      // Slack ulaşılamıyorsa asla agent'i engelleme
    }

    return allow();
  },
});
```

Yükleyin:

```bash
SLACK_WEBHOOK_URL=https://hooks.slack.com/... failproofai policies --install --custom ./slack-alerts.js
```

## Agent'leri bir branch'de tut

Agent'lerin branch'leri değiştirmesini veya korumalı branch'lere push yapmasını önle.

```javascript
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "stay-on-branch",
  description: "Agent'in diğer branch'lere geçişini önle",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = String(ctx.toolInput?.command ?? "");
    if (/git\s+checkout\s+(?!-b)/.test(cmd)) {
      return deny("Mevcut branch'te kal. Gerekirse -b ile yeni branch oluştur.");
    }
    return allow();
  },
});
```

## Commit yapmadan önce test yapılmasını iste

Agent'leri commit yapmadan önce test çalıştırmaya hatırlat.

```javascript
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "test-before-commit",
  description: "Agent'i commit yapmadan önce test çalıştırmaya hatırlat",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = String(ctx.toolInput?.command ?? "");
    if (/git\s+commit/.test(cmd)) {
      return instruct("Commit yapmadan önce test çalıştır. Önce `npm test` veya `bun test` kullan.");
    }
    return allow();
  },
});
```

## Production repo'yu kilitle

Ekibinizdeki her geliştirici aynı politikaları alacak şekilde proje düzeyinde bir yapılandırma commit et.

Repo'nuzda `.failproofai/policies-config.json` oluştur:

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-force-push",
    "block-push-master",
    "block-env-files",
    "sanitize-api-keys",
    "sanitize-jwt"
  ],
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "release", "production"]
    }
  }
}
```

Ardından commit et:

```bash
git add .failproofai/policies-config.json
git commit -m "failproofai takım politikaları ekle"
```

failproofai yüklenmiş olan her takım üyesi otomatik olarak bu kuralları alacak.

## Kural politikaları ile kuruluş genelinde bir kalite standardı oluştur

En etkili kurulum: `.failproofai/policies/` dosyasını projenize commit et; projenize uyarlanmış politikalarla. Her takım üyesi otomatik olarak alır - kurulum komutları, yapılandırma değişiklikleri yok.

<Steps>
  <Step title="Dizini oluştur ve politikalar ekle">
    ```bash
    mkdir -p .failproofai/policies
    ```

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    // Takımınızın tercih ettiği paket yöneticisini uygula
    // (ya da bunun yerine yerleşik prefer-package-manager politikasını etkinleştir)
    customPolicies.add({
      name: "enforce-bun",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        const cmd = String(ctx.toolInput?.command ?? "");
        if (/\bnpm\b/.test(cmd)) return deny("npm yerine bun kullan.");
        return allow();
      },
    });

    // Agent'i commit yapmadan önce test çalıştırmaya hatırlat
    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Commit yapmadan önce test çalıştır.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="Git'e commit et">
    ```bash
    git add .failproofai/policies/
    git commit -m "Takım kalite politikaları ekle"
    ```
  </Step>
  <Step title="İyileştirmeye devam et">
    Takımınız yeni hata modları yakaladığında, politikalar ekle ve push et. Herkes bir sonraki `git pull`'da güncellemeleri alır. Bu politikalar, takımınız ile birlikte gelişen canlı bir kalite standardı haline gelir.
  </Step>
</Steps>
