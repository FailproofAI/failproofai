## Claude Code için kancaları ayarlama

Failproof AI, Claude Code ile [kancalar sistemi](https://docs.anthropic.com/en/docs/claude-code/hooks) aracılığıyla entegre olur. `failproofai policies --install` komutunu çalıştırdığınızda, Claude Code'un `settings.json` dosyasında her araç çağrısında tetiklenen kanç komutlarını kaydeder.

<Steps>
  <Step title="failproofai'ı yükleyin">
    ```bash
    npm install -g failproofai
    ```
  </Step>
  <Step title="Tüm yerleşik politikaları etkinleştirin">
    ```bash
    failproofai policies --install
    ```
  </Step>
  <Step title="Kançaların kaydedildiğini doğrulayın">
    ```bash
    cat ~/.claude/settings.json | grep failproofai
    ```

    `PreToolUse`, `PostToolUse`, `Notification` ve `Stop` olayları için kanç girdileri göreceksiniz.
  </Step>
  <Step title="Claude Code'u çalıştırın">
    ```bash
    claude
    ```

    Politikalar artık her araç çağrısında otomatik olarak çalışır. Claude'dan `sudo rm -rf /` komutunu çalıştırmasını istemeyi deneyin - bu engellenir.
  </Step>
</Steps>

## Agents SDK için kancaları ayarlama

[Agents SDK](https://docs.anthropic.com/en/docs/agents-sdk) ile geliştiriyorsanız, aynı kanç sistemini programlı olarak kullanabilirsiniz.

<Steps>
  <Step title="failproofai'ı projenize yükleyin">
    ```bash
    npm install failproofai
    ```
  </Step>
  <Step title="Ajanınızda kançaları yapılandırın">
    Aracı oluştururken kanç komutlarını iletin. Kançalar Claude Code'daki gibi çalışır - stdin/stdout JSON aracılığıyla:

    ```bash
    failproofai --hook PreToolUse   # her araçtan önce çağrılır
    failproofai --hook PostToolUse  # her araçtan sonra çağrılır
    ```
  </Step>
  <Step title="Ajanınız için özel bir politika yazın">
    ```javascript
    import { customPolicies, allow, deny } from "failproofai";

    customPolicies.add({
      name: "limit-to-project-dir",
      description: "Ajanı proje dizini içinde tutun",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        const path = String(ctx.toolInput?.file_path ?? "");
        if (path.startsWith("/") && !path.startsWith(ctx.session?.cwd ?? "")) {
          return deny("Ajan proje dizini ile sınırlıdır");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="Özel politikayı yükleyin">
    ```bash
    failproofai policies --install --custom ./my-agent-policies.js
    ```
  </Step>
</Steps>

## Yıkıcı komutları engelleme

En yaygın kurulum - ajanların geri döndürülemez hasara neden olmasını önleyin.

```bash
failproofai policies --install block-sudo block-rm-rf block-force-push block-curl-pipe-sh
```

Bunun yaptığı:
- `block-sudo` - tüm `sudo` komutlarını engeller
- `block-rm-rf` - özyinelemeli dosya silmeyi engeller
- `block-force-push` - `git push --force` komutunu engeller
- `block-curl-pipe-sh` - uzak betikleri shell'e aktarmayı engeller

## Sır sızıntısını önleme

Ajanların araç çıktısında kimlik bilgilerini görmesini veya sızıtmasını engelleyin.

```bash
failproofai policies --install sanitize-api-keys sanitize-jwt sanitize-connection-strings sanitize-bearer-tokens
```

Bunlar `PostToolUse` üzerinde tetiklenir - bir araç çalıştıktan sonra, ajan çıktıyı görmeden önce temizlerler.

## Ajanların dikkat gerektirmesi durumunda Slack uyarıları alın

Boş uyarıları Slack'e iletmek için bildirim kancasını kullanın.

```javascript
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "slack-on-idle",
  description: "Ajan giriş beklediğinde Slack'e uyarı gönderin",
  match: { events: ["Notification"] },
  fn: async (ctx) => {
    const webhookUrl = process.env.SLACK_WEBHOOK_URL;
    if (!webhookUrl) return allow();

    const message = String(ctx.payload?.message ?? "Ajan beklemektedir");
    const project = ctx.session?.cwd ?? "bilinmiyor";

    try {
      await fetch(webhookUrl, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          text: `*${message}*\nProje: \`${project}\``,
        }),
        signal: AbortSignal.timeout(5000),
      });
    } catch {
      // Slack erişilemeyen durumlarda ajanı hiçbir zaman engellemeyin
    }

    return allow();
  },
});
```

Yükleyin:

```bash
SLACK_WEBHOOK_URL=https://hooks.slack.com/... failproofai policies --install --custom ./slack-alerts.js
```

## Ajanları bir şubede tutun

Ajanların dalları değiştirmesini veya korumalı dallara göndermesini engelleyin.

```javascript
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "stay-on-branch",
  description: "Ajanın başka dallara geçmesini engelleyin",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = String(ctx.toolInput?.command ?? "");
    if (/git\s+checkout\s+(?!-b)/.test(cmd)) {
      return deny("Geçerli şubede kalın. Gerekirse -b ile yeni bir şube oluşturun.");
    }
    return allow();
  },
});
```

## Taahhütlerden önce testleri zorunlu kılın

Ajanları taahhüt etmeden önce testleri çalıştırmaya hatırlatın.

```javascript
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "test-before-commit",
  description: "Ajanı taahhüt etmeden önce testleri çalıştırmaya hatırlatın",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();
    const cmd = String(ctx.toolInput?.command ?? "");
    if (/git\s+commit/.test(cmd)) {
      return instruct("Taahhüt etmeden önce testleri çalıştırın. Önce `npm test` veya `bun test` kullanın.");
    }
    return allow();
  },
});
```

## Üretim deposunu kilitleyin

Proje düzeyinde bir yapılandırma taahhüt edin, böylece takımınızdaki her geliştirici aynı politikaları alır.

Reponuzda `.failproofai/policies-config.json` oluşturun:

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-force-push",
    "block-push-master",
    "block-env-files",
    "sanitize-api-keys",
    "sanitize-jwt"
  ],
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "release", "production"]
    }
  }
}
```

Ardından taahhüt edin:

```bash
git add .failproofai/policies-config.json
git commit -m "failproofai takım politikalarını ekleyin"
```

failproofai yüklü olan her takım üyesi bu kuralları otomatik olarak alacaktır.

## Kural politikaları ile kurum genelinde kalite standartı oluşturun

En etkili kurulum: `.failproofai/policies/` dizinini reponuza taahhüt edin ve politikaları projenize göre uyarlayın. Her takım üyesi bunları otomatik olarak alır — kurulum komutları, yapılandırma değişiklikleri gerekmez.

<Steps>
  <Step title="Dizini oluşturun ve politikaları ekleyin">
    ```bash
    mkdir -p .failproofai/policies
    ```

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    // Takımınızın tercih ettiği paket yöneticisini zorunlu kılın
    // (veya bunun yerine yerleşik prefer-package-manager politikasını etkinleştirin)
    customPolicies.add({
      name: "enforce-bun",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        const cmd = String(ctx.toolInput?.command ?? "");
        if (/\bnpm\b/.test(cmd)) return deny("npm yerine bun kullanın.");
        return allow();
      },
    });

    // Ajanı taahhüt etmeden önce testleri çalıştırmaya hatırlatın
    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Taahhüt etmeden önce testleri çalıştırın.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="Git'e taahhüt edin">
    ```bash
    git add .failproofai/policies/
    git commit -m "Takım kalite politikalarını ekleyin"
    ```
  </Step>
  <Step title="İyileştirmeye devam edin">
    Takımınız yeni hata modlarıyla karşılaştıkça, politikalar ekleyin ve gönderin. Herkes bir sonraki `git pull` sırasında güncellemeleri alır. Bu politikalar takımınızla birlikte büyüyen canlı bir kalite standardı haline gelir.
  </Step>
</Steps>
