## Gereksinimler

- **Node.js** >= 20.9.0
- **Bun** >= 1.3.0 (opsiyonel - sadece kaynaktan derlemek için gerekli)

## Kurulum

<CodeGroup>

```bash npm
npm install -g failproofai
```

```bash bun
bun add -g failproofai
```

## Hızlı başlangıç

<Steps>
  <Step title="Politikaları etkinleştirin">
    Politikalar, her aracı araç çağrısından önce ve sonra çalışan kurallardır. Hasarlandırıcı komutları, gizli dizi sızıntılarını ve hasar vermeden önce diğer hata modlarını yakalarlar.

    ```bash
    failproofai policies --install
    ```

    Bu, yüklü aracı CLI'lerinize kancaya ilişkin girdiler yazar (Claude Code'un `~/.claude/settings.json`, OpenAI Codex'in `~/.codex/hooks.json`, GitHub Copilot CLI'nin `~/.copilot/hooks/failproofai.json`, Cursor Agent'ın `~/.cursor/hooks.json`, OpenCode'un `~/.config/opencode/plugins/failproofai.mjs` adresinde oluşturulan eklenti shim'i ve `~/.config/opencode/opencode.json` içindeki `plugin` dizisine bir kayıt girişi, Pi'nin `~/.pi/agent/settings.json`, Hermes'in `~/.hermes/config.yaml`, OpenClaw'ın `~/.openclaw/openclaw.json`, Factory Droid'in `~/.factory/hooks.json`, Devin CLI'nin `~/.config/devin/config.json`, Antigravity CLI'nin `~/.gemini/config/hooks.json` veya Goose'nin `~/.agents/plugins/failproofai/hooks/hooks.json` adresindeki otomatik keşfedilen eklenti dizini). Birden fazlası varsa size sorulacaktır; `--cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose` (herhangi bir alt küme) geçerek soruyu atlayabilirsiniz.

    GitHub Copilot CLI, Cursor Agent, OpenCode ve Pi desteği **beta** aşamasındadır — `--cli copilot`, `--cli cursor`, `--cli opencode` veya `--cli pi` ile kurun. Hermes (hermes-agent, bir Slack/Telegram ağ geçidi) `--cli hermes` ile kullanıcı kapsamında kuruludur ve **ayrıca** çevrimdışı denetim kaynağıdır. OpenClaw (openclaw ağ geçidi, kendi barındırılan çok kanallı bir asistan) `--cli openclaw` ile kullanıcı kapsamında kuruludur — yaptırım, işlem içi eklenti kancaları aracılığıyla çalıştırılır (`before_agent_finalize` gerçek bir tur sonu kapısıdır, bu nedenle `require-*-before-stop` yerleşikleri yaptırırlar) — ve **ayrıca** çevrimdışı denetim kaynağıdır. Factory Droid (`droid`) `--cli factory` ile kuruludur (kullanıcı + proje kapsamı) ve **ayrıca** çevrimdışı denetim kaynağıdır. Devin CLI (`devin`, Cognition) `--cli devin` ile kuruludur (kullanıcı + proje kapsamı) ve **ayrıca** çevrimdışı denetim kaynağıdır. Antigravity CLI (`agy`) `--cli antigravity` ile kuruludur (kullanıcı + proje kapsamı) ve **ayrıca** çevrimdışı denetim kaynağıdır. Goose (kod adı goose, Block) `--cli goose` ile kuruludur (kullanıcı + proje kapsamı) — kurucu sadece `~/.agents/plugins/failproofai/` adresinde bir eklenti dizini bırakır ve Goose bunu otomatik olarak keşfeder; ve **ayrıca** çevrimdışı denetim kaynağıdır.

    ```bash
    failproofai policies --install --scope project
    failproofai policies --install --cli codex --scope project
    failproofai policies --install --cli copilot --scope project
    failproofai policies --install --cli cursor --scope project
    failproofai policies --install --cli opencode --scope project
    failproofai policies --install --cli pi --scope project
    failproofai policies --install --cli hermes --scope user
    failproofai policies --install --cli openclaw --scope user
    failproofai policies --install --cli factory --scope project
    failproofai policies --install --cli devin --scope project
    failproofai policies --install --cli antigravity --scope project
    failproofai policies --install --cli goose --scope project
    failproofai policies --install block-sudo block-rm-rf sanitize-api-keys
    ```
  </Step>
  <Step title="Doğrulayın">
    ```bash
    failproofai policies
    ```

    Her politikayı, etkin olup olmadığını ve yapılandırılmış parametreleri gösterir.
  </Step>
  <Step title="Panoyu başlatın">
    ```bash
    failproofai
    ```

    `http://localhost:8020` adresinde yerel bir pano açar; burada oturumları göz atabilir, araç çağrılarını inceleyebilir ve politikaları yönetebilirsiniz.
  </Step>
  <Step title="Aracıyı çalıştırın">
    Claude Code'u her zamanki gibi başlatın. Aracı riskli bir şey yapmaya çalışırsa, failproofai bunu otomatik olarak engeller. Bunu çalışır durumda bırakın ve panoda ne olduğunu gözden geçirin.
  </Step>
</Steps>

## Politikalar nasıl çalışır

Bir aracı her araç çalıştırdığında, Claude Code failproofai'yi bir alt işlem olarak çağırır:

```text
Claude Code  →  failproofai --hook PreToolUse  →  stdin JSON'ı okur
                                                   politikaları değerlendirir
                                                   kararı stdout'a yazar
```

Her politika üç karardan biri döndürür:

- **allow** - aracı normal şekilde devam eder
- **deny** - işlem engellenir, aracıya neden engellendiği söylenir
- **instruct** - aracının istemine ek bağlam eklenir

<Note>
Politikalar yerel sürecinizde çalıştırılır. Uzak bir hizmete hiçbir şey gönderilmez.
</Note>

## Kural tabanlı politikalarla ekip politikalarını ayarlayın

Ekibiniz genelinde kalite standartları oluşturmanın en hızlı yolu `.failproofai/policies/` kuralıdır. Politika dosyalarını bu dizine bırakın ve bunlar otomatik olarak yüklenir — bayrak yok, yapılandırma değişikliği yok, kurulum komutu yok.

<Steps>
  <Step title="Politikalar dizinini oluşturun">
    ```bash
    mkdir -p .failproofai/policies
    ```
  </Step>
  <Step title="Politika dosyaları ekleyin">
    Başlatıcı örnekleri kopyalayın veya kendi örneklerinizi yazın:

    ```bash
    cp node_modules/failproofai/examples/convention-policies/*.mjs .failproofai/policies/
    ```

    Veya yeni bir tane oluşturun:

    ```js
    // .failproofai/policies/team-policies.mjs
    import { customPolicies, allow, deny, instruct } from "failproofai";

    customPolicies.add({
      name: "test-before-commit",
      match: { events: ["PreToolUse"] },
      fn: async (ctx) => {
        if (ctx.toolName !== "Bash") return allow();
        if (/git\s+commit/.test(ctx.toolInput?.command ?? "")) {
          return instruct("Commit yapmadan önce testleri çalıştırın.");
        }
        return allow();
      },
    });
    ```
  </Step>
  <Step title="Git'e işleyin">
    ```bash
    git add .failproofai/policies/
    git commit -m "Ekip kalite politikaları ekle"
    ```

    failproofai yüklü olan her ekip üyesi bu politikaları otomatik olarak alır. Geliştirici başına kurulum gerekmez.
  </Step>
</Steps>

<Tip>
`.failproofai/policies/` dizinini repolarınıza işleyin; böylece bütün ekip aynı standartları paylaşır. Ekibiniz yeni hata modları keşfettikçe politikalar ekleyin ve gönderin — herkes sonraki `git pull` komutunda güncellemeleri alır. Zamanla bu politikalar, gelişmeyi sürdüren bir yaşayan kalite standardı haline gelir.
</Tip>

## Veri depolama

Bütün yapılandırma ve günlükler makinenizde kalır:

| Yol | Ne depolar |
|------|----------------|
| `~/.failproofai/policies/local-policies/policies-config.json` | Genel politika yapılandırması |
| `~/.failproofai/hook-activity/` | Kanca yürütme geçmişi (sayfalandırılmış JSONL) |
| `~/.failproofai/logs/` | Özel kanca hataları için hata ayıklama günlükleri |
| `.failproofai/policies-config.json` | Proje başına yapılandırma (işlenen) |
| `.failproofai/policies-config.local.json` | Kişisel geçersiz kılmalar (gitignored) |

---

## Kaldırma

```bash
failproofai policies --uninstall
```

`~/.claude/settings.json` adresinden kanca girdilerini kaldırır. `~/.failproofai/` içindeki yapılandırma dosyaları tutulur.
