Yerleşik politikalar, aracı arızasının dokuz kategorisini kapsayan 39 adet sürdürülen politikadır. Biri hariç tümü **bir paket olarak sunulur**, `FailproofAI/policies`, başka herkesin politikaları tıpkı bu şekilde sunulur. Paket kendi başına bir pakete sahip değildir, bu nedenle yeni bir kurulum siz onu alana kadar hiçbir şeyi uygulamamaz:

```bash
failproofai policies add FailproofAI/policies
```

Bu, paketin kendi varsayılanlarını etkinleştirir — paketin taşıdığı 38 politikadan 10'u. 39. olan `block-failproofai-commands`, hangi koşulda olursa olsun açıktır: pakette derlenmiş olarak gönderilir, her değerlendirmede kaydedilir ve devre dışı bırakılamaz veya duraklatılamaz. Bir paket `alwaysOn` bildirmeyebilir, bu nedenle o koruma paketi kanalında dolaşmaz.

## Dokuz kategorinin kapsamı

| Kategori | `--category` slug | Politikalar |
| --- | --- | --- |
| Sanitize | `sanitize` | 5 |
| Environment | `environment` | 3 |
| Dangerous Commands | `dangerous-commands` | 5 |
| Infra Commands | `infra-commands` | 7 |
| Git | `git` | 6 |
| Database | `database` | 2 |
| Packages & System | `packages-system` | 5 |
| AI Behavior | `ai-behavior` | 1 |
| Workflow | `workflow` | 5 |

Bunlar derlenmiş katalog sayılarıdır ve toplam 39'dur. Paket bunların 38'ini taşır, çünkü `block-failproofai-commands` `alwaysOn` olup paket kanalında hiçbir zaman dolaşmaz — bu nedenle `--category dangerous-commands` diğer dördünü seçer.

Varsayılanların yerine bir dilim alın:

```bash
failproofai policies add FailproofAI/policies --category git,database
failproofai policies add FailproofAI/policies --policy block-rm-rf
failproofai policies add FailproofAI/policies --all
```

## Birini açın veya kapatın

```bash
failproofai policies add block-rm-rf --cli claude --scope project
failproofai policies remove block-rm-rf --cli claude --scope project
```

`policies add` ve `policies remove`, tam olarak **bir** politika adı alır. Adı olmadan çalıştırırsanız, zaten açık olanlar işaretli bir seçici alırsınız. Birden fazla ad için install formunu kullanın:

```bash
failproofai policies --install block-sudo block-force-push \
  --cli claude codex --scope project
```

<Note>
  Kurulan paket olmayan bir makinede, `failproofai policies add <builtin-name>` adını karşılamak için `FailproofAI/policies`'i GitHub sürümünden getirir — bu nedenle ilk komut ağa ihtiyaç duyar.
</Note>

## Her politika her araç seti üzerinde zorlamaz

Bir politika, yalnızca araç seti olayının kararını tükettiğinde davranışı değiştirir. Yerleşik bir politikaya güvenmeden önce kontrol etmeye değer iki durum vardır:

| Event | Reddedişin davranışı değiştirdiğinin doğrulandığı yer |
| --- | --- |
| `PreToolUse` | Tüm 12 araç seti |
| `Stop` | claude, codex, copilot, cursor, openclaw, factory, devin, antigravity. Hiçbir `Stop` hook goose veya hermes üzerine kurulmaz, pi sebebi bir sonraki dönüşe taşır ve opencode doğrulanmaz |

Bu nedenle Workflow kategorisindeki beş `require-*-before-stop` politikası bir makineye etkinleştirilebilir ve yine de hangi aracının orada çalıştığına bağlı olarak hiç harekete geçmeyebilir. Cursor Cloud Agent VM'leri hiç stop hook çalıştırmaz.

`warn-*` ve `prefer-*` politikaları `deny` yerine `instruct` döndürür. Hermes ve Goose üzerinde ve Pi, OpenClaw, Factory ve Antigravity'nin `Stop` kanalı dışında, `instruct` izin ve stderr'de bir nota düşer: operatör bunu günlüklerde görür, aracı görmez.

Bazı politikalar parametreleri kabul eder. Tanımlamayı, kapsam ve varsayılanı eşleştirin dağıtımdan önce — bir iş akışını koruyan bir politika, başka bir işlem akışında geçerli işlemleri engelleyebilir.
