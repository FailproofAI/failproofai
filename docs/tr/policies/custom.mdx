Bir politika yazmadan önce [yerleşik kataloğu](/tr/policies/builtin-catalog) kontrol edin. Gözden geçirilmiş bir kural genellikle yeni bir kuraldan daha güvenlidir.

## Çalışan bir politikadan başlayın

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

Başlangıç bloğu `git push --force` komutunu engeller. Düzenleyin, aracınızdan engellenen eylemi denemesini isteyin ve **Policies → Activity** bölümünü inceleyin.

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "protect-production",
  description: "Production changes need a human",
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) =>
    String(ctx.toolInput?.command ?? "").includes("production")
      ? deny("Ask a human before changing production.")
      : allow(),
});
```

Bir politika `allow()`, `deny(message)` veya `instruct(message)` döndürür. Eylem durdurulması gerektiğinde `deny` kullanın; her alet yöneticisi aracıya bir talimat geri iletebilir.

## Otomatik yükleme

Aşağıdaki konumlara `*policies.js`, `*policies.mjs` veya `*policies.ts` adıyla dosyalar koyun:

- `.failproofai/policies/` - tek bir proje için.
- `~/.failproofai/policies/` - kullanıcı hesabınız için.

## Hata yollarını test edin

Güvenli olmayan eylemi ve buna benzeyen meşru çalışmaları test edin. Kararın başka bir kuraldan değil, kendi politikanızdan geldiğini doğrulayın.

Açık test dosyalarını kaldırmak için:

```bash
failproofai policies -u -c
```

Politika hazır olduğunda, [bir paket yayınlayın](/tr/policies/publish-a-pack) veya [Bulut aracılığıyla dağıtın](/tr/policies/deploy).
