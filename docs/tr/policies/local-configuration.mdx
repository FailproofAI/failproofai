Failproof AI, policy seçimini makine ve daemon ayarlarından ayırır. Bu, depo policy seçimlerinin gözden geçirilebilir kalmasını sağlarken kimlik bilgileri ve daemon durumu depo dışında kalır.

## Policy kapsamı seçin

<Tabs>
  <Tab title="Dashboard">
    Policy dashboard'unu açmak için `failproofai` komutunu bağımsız değişken olmadan çalıştırın. Bir policy'yi etkinleştirmeden önce kullanıcı, proje veya yerel kapsamı seçin; böylece değişiklik istenen yapılandırma dosyasına yazılır.

    - **User** bu makinedeki tüm projeler arasında geçerlidir.
    - **Project** depoya aittir ve commit edilebilir.
    - **Local** bir projeyi bir kullanıcı için geçersiz kılar ve gitignore'da kalmalıdır.

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-rm-rf --scope user
    failproofai policy add block-force-push --scope project
    failproofai policy add warn-large-file-write --scope local
    failproofai policies
    ```

    Her harness yerel kapsamı desteklemez. CLI, seçilen harness'in temsil edemediği bir kapsamı reddeder.
  </Tab>
</Tabs>

| Kapsam | Policy yapılandırma dosyası |
| --- | --- |
| Project | `<project>/.failproofai/policies-config.json` |
| Local | `<project>/.failproofai/policies-config.local.json` |
| User | `~/.failproofai/policies-config.json` |

Etkinleştirilen policy'ler birleşim olarak birleştirilir. Policy parametreleri, bu policy için parametreleri tanımlayan ilk kapsamı kullanır; sıra project → local → user şeklindedir. Açık özel policy yolları, bunları tanımlayan ilk kapsamı kullanır.

## Policy parametrelerini yapılandırın

<Tabs>
  <Tab title="Dashboard">
    Policy'yi yerel dashboard'ta açın, desteklenen parametrelerini düzenleyin ve seçilen kapsamda kaydedin. Eşleşen ve eşleşmeyen bir agent eylemini çalıştırın, ardından kararı **Observe → policy** bölümünde inceleyin.

  </Tab>
  <Tab title="CLI">
    Seçilen kapsamın `policies-config.json` dosyasını düzenleyin, ardından bilinmeyen policy adlarını veya parametre anahtarlarını ortaya çıkarmak için `failproofai policies` komutunu çalıştırın.

    ```json
    {
      "enabledPolicies": ["block-rm-rf", "block-force-push"],
      "policyParams": {
        "block-rm-rf": {
          "allowPaths": ["/tmp/build-output"]
        }
      }
    }
    ```

    ```bash
    failproofai policies
    ```
  </Tab>
</Tabs>

## Makine dosyalarını anlayın

`~/.failproofai` farklı güven sınırları için ayrı dosyalar içerir:

| Yol | Amaç |
| --- | --- |
| `config.json` | Gizli olmayan daemon, denetim ve telemetri ayarları |
| `credentials.json` | Bulut kimlik bilgileri; yalnızca sahibin erişimine sahip izinlerle depolanır |
| `policies-config.json` | Kullanıcı kapsamı builtin seçimi, parametreleri ve açık özel yolları |
| `policies/` | Kullanıcı kural policy'leri ve Bulut tarafından yönetilen policy yapıtları |
| `hook-activity/` | Yerel policy karar günlüğü |
| `state/` | Daemon spool, sağlık, duraklatma ve çalışma zamanı durumu |

Bir container veya yalıtılmış test için makine düzeninin tamamını yeniden konumlandırmak üzere `FAILPROOFAI_HOME` kullanın. Durumu dizinlerini bağımsız olarak yeniden konumlandırmayın.

<Warning>
  `credentials.json` dosyasını hiçbir zaman commit etmeyin. Proje policy yapılandırması ve proje kural policy'lerini yalnızca bunları uygulama kodu olarak gözden geçirdikten sonra commit edin.
</Warning>
