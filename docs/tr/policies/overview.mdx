Bir ilke, bir aracı eylemini izler ve üç karardan birini döndürür:

- `allow` devam eder.
- `instruct` aracının koşulu desteklediğinde rehberlik sağlar.
- `deny` eylemi engeller.

İlkeleri bilinen, tekrarlanabilir davranışlar için kullanın: korumalı dosyaları silme, sırları açığa çıkarma, yanlış dalına itme veya üretim altyapısını değiştirme.

## Bu makineye ilkeler ekleyin

Setup hiçbir ilke paketi seçmez. Kurulumdan sonra Failproof AI paketini ekleyin:

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai policies
```

Paket ayrıcalıklı yerleşik bir paketi içermez. Bizimkiler, başka herhangi birinin yaptığı gibi kurulur.

İlkeler ayrıca yerel bir dosyadan, yayınlanan bir paketten veya Cloud atamasından gelebilir:

| Kaynak | Ekleyin |
| --- | --- |
| Yerel dosya | `.failproofai/policies/` altına `*policies.{js,mjs,ts}` koyun |
| Herhangi bir dosya yolu | `failproofai policies -i -c <path>` |
| Yayınlanan paket | `failproofai policies add <owner>/<repo>` |
| Cloud | Panodan veya `fp fleet deploy` ile atayın |

`block-failproofai-commands` her zaman çalışır ve kapatılamaz. Bir aracının kendi zorlamayı devre dışı bırakmasını engeller.

## Zorlamadan önce gözlemleyin

Gözlem modu gerçek ilkeyi çalıştırır ve ne yapacağını kaydeder, ancak aracıyı engellemez.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

<Warning>
  Basit `fp fleet deploy <machine> --add <id>` hemen uygulamayı zorlar. Gölge bir dağıtım için `:observe` ekleyin.
</Warning>

Gözlem modunda zaman aşımına uğrayan bir ilke, uygulanırken ne olacağı için izin kaydeder. Yalnızca gözlenen izin vermeyen kararlar kaydedilir.

Cloud olmadan kullanılan bir paket için bunu `failproofai publish --effect observe` ile yayınlayın.
