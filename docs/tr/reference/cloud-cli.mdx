Cloud telemetrilerini incelemek, bulut tarafından yönetilen zorunluluğu (politikalar, fleet dağıtımları, guardrail kararları) yönetmek ve denetimler, bulgular, sorunlar, uyarılar, anahtarlar, kullanıcılar, sorgular ve ayarları yönetmek için `fp` kullanın. Yerel kancalar, politikalar, yakalama ve makine kaydı için [`failproofai`](/tr/reference/failproof-cli) kullanın.

Ayrıca barındırılan kodu yazabilir ve dağıtabilir, LLM-judge ve Jev değerlendiricileri oluşturabilir, panoları yönetebilir, duygusal durumu inceleyebilir ve terminalden pano asistanını kullanabilirsiniz.

Yayınlanan Cloud CLI'yı ayrı bir araç olarak yükleyin:

```bash
uv tool install fp-cloud-cli
fp version
```

## Oturum açma

```bash
fp login
fp whoami
```

## Söz dizimi

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Global seçenekler komuttan önce gelmelidir:

```bash
fp --json sessions --since 24h
```

Terminal yardımı için `fp COMMAND --help` veya `fp COMMAND SUBCOMMAND --help` çalıştırın.

## CLI komutları

### Değerlendirici yazma

`fp evaluators` tanımları yazarken; `fp evals` sonuçları okur. Etkinleştirilmiş yönetilen bir örnek gerekir (`fp evaluators instances`). Yazma işlemi `evaluations:trigger` gerektirir; oturum kuru çalıştırmaları ve şema profili oluşturma işlemleri de `events:read` gerektirir.

Kod tek kısıtlı Python ifadesidir. Bunu `error_free.py` olarak kaydedin:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev ikili dosyası ve puanlanan rubrik:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
Oluşturma, değerlendiricileri etkinleştirir. Dağıtım yeni bir değişmez sürüm oluşturur, ardından eski etkinleştirilmiş sürümleri devre dışı bırakır. Başarısız bir takip işlemi yeni sürümü yayınlanmış bırakır: yeniden denemeden önce `evaluators list --all` inceleyin.
Judge kuru çalıştırmaları Cloud tarafından reddedilir. Jev kuru çalıştırmaları model bütçesini harcamaktadır.
Geri doldurma kod, judge ve Jev değerlendiricileri kapsar ve en fazla 90 gün kabul eder; yalnızca bir değerlendirici tarafından henüz puanlanmamış oturumları kuyruğa alır. Judge ve Jev geri doldurmalar model bütçesini harcamaktadır, bu nedenle ilk olarak `fp evaluators backfill --dry-run` çalıştırın.
İnsan çıktısı oluşturma/dağıtmadan önce oturum başına kuru çalıştırma sonuçlarını gösterir.
Başarısız ön izlemeler, incelemenin ardından açıkça `--force` iletmedikçe yazma işlemini durdurur.
</Warning>

AI taslaklaması `fp login` gerektirir ve create/deploy tarafından kabul edilen bir spec yazar:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Taslağın anahtarını, kaynağını ve koşulunu etkinleştirmeden önce inceleyin.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Komut | Seçenekler / davranış |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Tam kaynak/zarf |
| `fp evaluators create` | `--key`, `--name`, `--version`, tekrarlanan `--label`, `--condition EXPR\|@file`, bir kaynak, tekrarlanan `--dry-run-on`, `--disabled`, başarısız önizlemeler için açık `--force` |
| `fp evaluators deploy KEY` | Aynı kaynak bayrakları; `--version`, `--backfill 7d` (herhangi bir tür, 1–90 gün), `--force`; sayısal sürümler otomatik artış; KEY eksik spec-file `eval_key` sağlar |
| `fp evaluators draft "intent"` | Oturum; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Kaynak bayrakları veya `--file`, tekrarlanan `--session` (maksimum 10); hiçbiri = yalnızca derle |
| `fp evaluators enable\|disable KEY[@VERSION]` | Aç/Kapat |
| `fp evaluators label KEY[@VERSION]` | Tekrarlanan `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | Yönetilen fleet/şema/işleri inceleyin |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; kod, judge ve Jev |

Kod bayrakları `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. Judge bayrakları `--judge --criteria TEXT`, tekrarlanan `--step` ve
`--threshold`. Jev bayrakları `--jev noul --instructions --true --false` veya
`--jev score --instructions` ile en kötüsü önce 3–5 farklı `--level` değer.
Judge/Jev bir puan gerektirir; eşikler 0–1. İkili judge adımları reddedilir.

Spec dosyaları tam olarak `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds` içerir.
Judge/Jev `evaluator_source` bir JSON zarfı dizesidir. Satır kimliklerini, etkin durumu veya AI akıl yürütme meta verilerini eklemeyin. `--file` ve ayrı spec bayrakları karşılıklı olarak dışlayıcıdır; dağıtım dosyanın sürümünü geçersiz kılabilir. Çıktı dosyaları asla üzerine yazılmaz.

### Yeni pano kontrolleri

Tüm komutlar global `--json` kabul eder. Bilinmeyen rota 404leri 6 ile çıkarak başarısız olur ve "bu FailproofAI Cloud sürümünde henüz kullanılamıyor" rapor edilir. Eksik kayıt 404leri de 6 ile çıkar fakat kaydın bulunamadığını rapor eder. Yalnızca oturum komutları HTTP'den önce anahtar modunu reddeder (çıkış 2).

İnsan komutları özetler ve tablolar kullanır. Ham JSON dışa aktarımları için global `--json` iletin veya `--out FILE` ile kaydedin; aksi halde oturum ve JSON sorgu dışa aktarımları okunabilir bir görünüm gösterir. CSV dışa aktarımları borulama için düz CSV olarak kalır.

### Olaylar

```text
fp events [OPTIONS]
```

Bireysel ajan olaylarını listeler. Varsayılan hafif akış ham yükleri hariç tutar; `--full` yalnızca sınırlı bir araştırma için kullanın.

| Seçenek | Açıklama |
| --- | --- |
| `--limit`, `-n <n>` | Maksimum toplam satır. Varsayılan: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, veya `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC aralığı; `--since` geçersiz kılar. |
| `--env <value>` | Ortam filtresi; tekrar veya virgülü ayırın. |
| `--event-type <value>` | Olay türü filtresi; tekrar veya virgülü ayırın. |
| `--agent-id <value>` | Ajan filtresi; tekrar veya virgülü ayırın. |
| `--session-id <value>` | Oturum filtresi; tekrar veya virgülü ayırın. |
| `--search <text>` | Yük metin araması; tekrarlanabilir, herhangi bir terim eşleşmesi. |
| `--order asc\|desc` | Zaman sırası. Varsayılan: en yeni ilk. |
| `--all` | Otomatik sayfalandırma `--limit`'e kadar. |
| `--cursor <token>` | Opak imleçten devam edin. |
| `--page-size <n>` | `--all` ile istek başına satır; maksimum `200`. |
| `--full` | Daha ağır olay uç noktası aracılığıyla ham yükleri dahil edin. |
| `--fields <csv>` | Yalnızca seçilen alanları döndürün; `payload` isteme tam modu etkinleştirir. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` **`--limit`'e kadar** sayfalandırır, varsayılan **50** — bu nedenle `--all` kendi başına 50 satırda durur. Erken durduğunda yanıt devam etmek için bir
  `next_cursor` taşır; `"next_cursor": null` akışın gerçekten tükendiği anlamına gelir.
</Note>

#### Denetim oluştur seçenekleri

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Seçenek | Açıklama |
| --- | --- |
| `--file <path>` | Tanımı JSON'a dayandırın veya stdin için `-` kullanın. Açık bayraklar dosya değerlerini geçersiz kılar. |
| `--description <text>` | Başarısızlık sorusunu veya amacını belirtin. |
| `--enabled` / `--disabled` | Planlama başlat kapalı veya açık. Varsayılan: etkin. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Varsayılan: `86400`. |
| `--schedule-anchor <timestamp>` | ISO 8601 formunda sabit UTC fazı. Varsayılan: sonraki 09:00 UTC. |
| `--window-mode since_last\|fixed` | Son tamamen analiz edilen pencereden sonra devam edin veya yinelemeli olarak yuvarlak pencereyi inceleyin. Varsayılan: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Varsayılan: `604800`. |
| `--scope '<json>'` | `environments`, `agent_ids` veya desteklenen diğer kapsam alanlarına göre filtreleyin. |
| `--ignore-error-type <type>` | Hata türlerini hariç tutun; tekrar veya virgülü ayırın. |
| `--llm` / `--no-llm` | Ajansal analizi etkinleştirin veya devre dışı bırakın. Varsayılan: etkin. |
| `--top-k <n>` | `1`–`500` bulgusu tutun. Varsayılan: `50`. |
| `--sensitivity low\|medium\|high` | Raporlama duyarlılığını ayarlayın. Varsayılan: `medium`. |
| `--channels '<json>'` | Bildirim kanalı dizisi. |
| `--text <brief>` | Satır içi kısa bilgi, maksimum 8.192 karakter. |
| `--text-file <path>` | Kısa bilgiyi dosyadan okuyun; `--text` ile karşılıklı olarak dışlayıcı. |
| `--url <https-url>` | Genel HTTPS referansı ekleyin; en fazla beş kez tekrarlayın. |

İlk çalıştırmanın buna ihtiyacı olduğunda oluşturma sırasında bağlamı dahil edin. Oluşturma, kuyruğa alınan çalıştırma başlamadan önce tanımı ve bağlamı birlikte kaydeder.

<Note>
  `fp audits run` eşzamansız. En son çalıştırma başarılı veya başarısız olana kadar `fp audits runs NAME` yoklayın ve sonra bulgularını okuyun.
</Note>
