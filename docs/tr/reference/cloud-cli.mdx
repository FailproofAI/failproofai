Bulut telemetrisini incelemek, bulut tarafından yönetilen zorlama (politikalar, filo dağıtımları, guardrail kararları) yönetmek ve denetimler, bulgular, sorunlar, uyarılar, anahtarlar, kullanıcılar, sorgular ve ayarları yönetmek için `fp` kullanın. Yerel kancalar, politikalar, yakalama ve makine kaydı için [`failproofai`](/tr/reference/failproof-cli) kullanın.

Yayımlanan Bulut CLI'yi izole bir araç olarak yükleyin. Python 3.10 veya daha yeni bir sürüme ihtiyaç duyar.

```bash
uv tool install fp-cloud-cli
fp version
```

Dağıtım `fp-cloud-cli` ve yüklenen komut `fp` — farklıdırlar çünkü `fp` zaten PyPI'de kullanımda idi.

## Oturum aç

`fp login` size altı haneli bir kod gönderir ve oturumu kaydeder. Kendi imzalı bir sertifikaya sahip bir pano karşısında, oturum açarken `--insecure` ekleyin.

```bash
fp login
fp whoami
```

## Söz dizimi

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Genel seçenekler komuttan önce gelmelidir:

```bash
fp --json sessions --since 24h
```

Terminal yardımı için `fp COMMAND --help` veya `fp COMMAND SUBCOMMAND --help` çalıştırın.

### Olaylar

```text
fp events [OPTIONS]
```

Bireysel aracı olaylarını listeler. Varsayılan hafif akış ham yükleri hariç tutar; `--full` sadece sınırlı bir soruşturma için kullanın.

| Seçenek | Açıklama |
| --- | --- |
| `--limit`, `-n <n>` | Maksimum toplam satır. Varsayılan: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, veya `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC aralığı; `--since` geçersiz kılınır. |
| `--env <value>` | Ortam filtresi; değerleri tekrarlayın veya virgülle ayırın. |
| `--event-type <value>` | Olay türü filtresi; tekrarlayın veya virgülle ayırın. |
| `--agent-id <value>` | Aracı filtresi; tekrarlayın veya virgülle ayırın. |
| `--session-id <value>` | Oturum filtresi; tekrarlayın veya virgülle ayırın. |
| `--search <text>` | Yük metni araması; tekrarlanabilir, herhangi bir terim eşleşir. |
| `--order asc\|desc` | Zaman sırası. Varsayılan: en yeni ilk. |
| `--all` | `--limit`'e kadar otomatik sayfalandırma. |
| `--cursor <token>` | Opak imleçten devam edin. |
| `--page-size <n>` | `--all` ile istek başına satırlar; maksimum `200`. |
| `--full` | Daha ağır olay uç noktası aracılığıyla ham yükleri dahil edin. |
| `--fields <csv>` | Yalnızca seçilen alanları döndürün; `payload` istenmesi tam modu etkinleştirir. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` **`--limit`'e kadar** sayfalandırır, bu varsayılan olarak **50** — bu nedenle tek başına `--all` 50 satırda durur. Erken durdurulduğunda yanıt `next_cursor` içerir; `"next_cursor": null` akışın gerçekten tükendiği anlamına gelir.
</Note>

#### Denetim oluşturma seçenekleri

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Seçenek | Açıklama |
| --- | --- |
| `--file <path>` | Tanımı JSON'a dayandırın veya stdin için `-` kullanın. Açık bayraklar dosya değerlerini geçersiz kılar. |
| `--description <text>` | Başarısızlık sorusunu veya amacını belirtin. |
| `--enabled` / `--disabled` | Zamanlamayı açık veya kapalı başlatın. Varsayılan: etkin. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Varsayılan: `86400`. |
| `--schedule-anchor <timestamp>` | ISO 8601 biçiminde sabit UTC fazı. Varsayılan: sonraki 09:00 UTC. |
| `--window-mode since_last\|fixed` | Son tamamen analiz edilen pencereden sonra devam edin veya haddelenmiş bir pencereyi tekrar tekrar inceleyin. Varsayılan: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Varsayılan: `604800`. |
| `--scope '<json>'` | `environments`, `agent_ids` veya diğer desteklenen kapsam alanlarına göre filtreleyin. |
| `--ignore-error-type <type>` | Hata türlerini hariç tutun; tekrarlayın veya virgülle ayırın. |
| `--llm` / `--no-llm` | Aracı analizini etkinleştirin veya devre dışı bırakın. Varsayılan: etkin. |
| `--top-k <n>` | `1`–`500` bulgusu tutun. Varsayılan: `50`. |
| `--sensitivity low\|medium\|high` | Raporlama hassasiyetini ayarlayın. Varsayılan: `medium`. |
| `--channels '<json>'` | Bildirim kanalı dizisi. |
| `--text <brief>` | Satır içi özet, maksimum 8.192 karakter. |
| `--text-file <path>` | Özeti bir dosyadan okuyun; `--text` ile karşılıklı olarak münhasır. |
| `--url <https-url>` | Genel HTTPS başvurusu ekleyin; beş kez kadar tekrarlayın. |

İlk çalıştırmanın bunu ihtiyaç duyması durumunda oluşturma sırasında bağlam ekleyin. Oluşturma, tanımı ve bağlamı sıralanan çalıştırma başlamadan önce birlikte kaydeder.

<Note>
  `fp audits run` eşzamansızdır. Sonucunun bulgularını okumadan önce en son çalıştırma başarılı veya başarısız olana kadar `fp audits runs NAME` sorgulaması yapın.
</Note>

### Politikalar

Bulut tarafından yönetilen politika sürümleri. **Yalnızca oturum** — buradaki her komut `fp policies test` hariç API anahtarı altında `2` çıkışını yapar, herhangi bir istekten önce, çünkü bunlar kök tarafından yazılan rotalar ve kasten `/v1`'den kaldırılmıştır. `fp policies test` kasıtlı istisnadır: tamamen `node`'a karşı yerel olarak çalışır ve sunucuyla konuşmaz, bu nedenle ne kimlik doğrulama gereksinimi ne de anahtar modu reddi taşır ve oturum açılmadan ve API anahtarı altında da çalışır.

| Komut | Amaç | Seçenekler |
| --- | --- | --- |
| `fp policies list` | Politika sürümlerini, her politikanın en yenisini ilk olarak listeleyin. | — |
| `fp policies show POLICY_ID` | Bir politikayı, kaynağı ile gösterin. | — |
| `fp policies publish POLICY_ID [SOURCE]` | Yeni bir sürüm oluşturun; hiçbir zaman yerinde düzenlenmez. `SOURCE` bir yol, `@path` veya stdin için `-` — bunu yapıştırmak için atlayın. | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | Bunu kaldırıldığı her dağıtıma geri ekleyin, her birinde yeni bir nesil oluşturun. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | Bunu onu taşıyan her dağıtımdan kaldırın, her birinde yeni bir nesil oluşturun. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | Bir politika sürümünü silin. | `--yes`, `-y` |
| `fp policies test [SOURCE]` | Bir politikayı sentetik bir bağlama karşı yerel olarak çalıştırın. Her politikanın `match` filtresini uygulayın, bu nedenle verilen olay/araç kapsamında olmayan politika, çalıştırılmak yerine `skipped` olarak rapor edilir. PATH'ta `node` gerektirir. | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | Asistan ile bir politika taslağı oluşturun. Taslağı yazdırır ve varsayılan olarak başka bir şey yapmaz. `policies:write` gerekir. | `--out <path>`; `--publish <policy-id>` |

### Filo

Hangi makinelerin hangi politikaları çalıştırdığı. **Yalnızca oturum** — buradaki her komut, istisna olmaksızın, API anahtarı altında `2` çıkışını yapar.

| Komut | Amaç | Seçenekler |
| --- | --- | --- |
| `fp fleet list` | Kayıtlı makineleri ve dağıtım neslerini listeleyin. | — |
| `fp fleet show MACHINE_ID` | Bir makinenin şu anda çalıştırdığı politika seti. | — |
| `fp fleet deploy MACHINE_ID` | Bir makinenin ne uyguladığını değiştirin. Tam sonuçta ayarı ilk olarak yazdırır ve `--json` olmayan interaktif bir terminalde yalnızca sorar. | `--add`; `--remove`; `--set`; `--create`; `--yes`, `-y` |
| `fp fleet diff [MACHINE_ID]` | Niyet ve teslimat — bir makinenin son çektiği şeye karşı ne çalıştırması söylendiği. Filo için kimliği atlayın. | — |
| `fp fleet history MACHINE_ID` | Bir makine için her nesil, en yeni ilk. | — |
| `fp fleet rollback MACHINE_ID GENERATION` | Geçmiş bir neslin politika setini yeniden kurun. Nesil numarası `fp fleet history MACHINE_ID` adresinden gelir. | `--yes`, `-y` |
| `fp fleet rename MACHINE_ID LABEL` | Bir makineye okunabilir bir etiket verin. Kimliğin kendisi hiçbir zaman değişmez. | — |

```bash
fp fleet history ci-runner-01
fp fleet rollback ci-runner-01 3
fp fleet rename ci-runner-01 "CI runner (eu-west)"
```

#### Politika başvuruları

`--add` ve `--set` çıplak kimlik değil politika başvurusu alır:

| Form | Anlamı |
| --- | --- |
| `id` | Mevcut sürüm, mevcut etki |
| `id@3` | Sürüm 3, mevcut etki |
| `id:observe` | Mevcut sürüm, kaydedilmiş ancak uygulanmamış |
| `id@3:observe` | Sürüm 3, kaydedilmiş ancak uygulanmamış |

Etki `enforce` veya `observe`. Çözüm: açık bir etki kazanır; aksi takdirde söz konusu politika için zaten dağıtılan etki; aksi takdirde `enforce`.

<Warning>
  Çıplak `--add` **hemen uygulanır**. `fp fleet deploy ci-runner-01 --add checkout-guard` sonraki çekişinde o makinede engellemeyi başlatır. `:observe` bunu gölge dağıtım yapar:

  ```bash
  fp fleet deploy ci-runner-01 --add checkout-guard:observe   # yalnızca kaydeder
  fp fleet deploy ci-runner-01 --add checkout-guard           # şimdi uygulanır
  ```

  Observe kapalı değildir. Politika, bir uygulamaya konu olarak aynı 10 saniye zaman aşımı ve aynı hata işleme altında gerçekten değerlendirilir ve her izin vermeyen karara kaydedilir — yalnızca uygulama engellenir. Bu, ölçümü okumanın değerli yapan şeydir.
</Warning>

#### Deltalar, değiştirme ve yarışlar

`--add` ve `--remove` makinenin mevcut setini okur ve bir delta uygular, bu nedenle adlandırmadığınız hiçbir şey bozulur. Makinenin zaten çalıştırdığı bir politika üzerinde çıplak `--add` kayan sürümü sessizce yükseltmek yerine tutar; taşımak için `id@version` geçirin.

`--set` her şeyi değiştirir ve adlandırmadığınız politikaları bırakmanın tek yoludur. `--add` veya `--remove` ile birleştirilemez. Üçünü hiçbirini geçmemek bir kullanım hatasıdır, işlem olmaz.

```bash
fp fleet deploy ci-runner-01 --add prod-guard@1:observe --remove old-rule
fp fleet deploy ci-runner-01 --set no-force-push --set no-secret-echo
```

Yazma işleminin kendisi her yolda tam bir değiştirmedir, çünkü uç nokta tüm politika setini alır. Sunucu tarafında kilit olmadığından CLI, okuduğu nesli kaydeder ve sonuç tam olarak bir yüksek değilse reddeder — bu, birisi arada dağıtmış anlamına gelir ve değiştirme birleşmez. `fp fleet show` ile yeniden okuyun, ardından yeniden dağıtın.

`--create` henüz kontrol etmemiş bir makine kimliğine dağıtır, ön hazırlık için. Olmadan, sunucunun bilmediği kimlik reddedilir, çünkü bir yazım hatası yoksa sahip olmayan kimlikli makineler tarafından taşınan politikaları kimse toplaması için reddedilir.

### Guardrails

Zorlama gerçekten ne yaptı. **Yalnızca oturum**, yukarıdakiyle aynı sebep.

| Komut | Amaç | Seçenekler |
| --- | --- | --- |
| `fp guardrails summary` | Kapsam, engellenen/değerlendirilen toplamlar, inkar kıvılcımı ve politika başına tablo. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |
| `fp guardrails timeline` | Pencere üzerinde bölümlenen kararlar, her politika kaynağı genelinde toplandı. | `--since` (`1h`, `6h`, `24h`, `7d`); `--machine` |

Özet içinde `(no policy)` satırı boşluk yerine normaldir: çoğu değerlendirme, hiç kimsenin itiraz etmediği izinleri ayarlar ve satır paydayı ekranda tutar.

### Bir politikayı kimseyi kırmadan dışarı çıkarın

Yukarıdaki üç grup bir dizidir. Yerel olarak karar verin, yayımlayın, gölge yapın, ölçün, ardından uygulanır.

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

| Adım | Neden orada |
| --- | --- |
| `fp policies test` | Sunucu yok ve kimlik doğrulama yok. Gerçek dosyayı tarif ettiğiniz bir bağlama karşı çalıştırır ve kayıtlı politika başına izin ver, reddet veya talimat yazdırır. `--expect` bunu CI iddiasına dönüştürür. |
| `fp policies publish` | Yeni değişmez bir sürüm oluşturur; hiçbir zaman yerinde düzenlenmez. |
| `fp fleet deploy --add <id>:observe` | Gölge dağıtım. **`:observe` burada isteğe bağlı değildir** — çıplak `--add` makine çektiği an uygulanır. |
| `fp guardrails summary` | Güvenli olmayan eşleşmeleri, politikanın da bloklayacağı meşru çalışmadan ayırır. |
| `fp fleet deploy --add <id>:enforce` | Reklama koyma, kaydedilen kararlar beklediğinizi söylediğinde. |
| `fp fleet rollback <machine> <generation>` | Uygulama yanlış giderse geri dönüş yoludur. |

Bulut olmadan, yerel panodan `failproofai publish --effect observe` ile paketi yayımlayan ve kaydedilen kararlara okuyan tek makine eşdeğeridir [yerel pano](/tr/reference/local-dashboard).

## Genel bayraklar

| Bayrak | Açıklama |
| --- | --- |
| `--json` | Makine tarafından okunabilir JSON yayınlayın. |

| `--org <slug>` | Bu çağrı için bir kuruluş seçin. |
| `--token <token>` | Kaydedilen kullanıcı oturumu belirtecini geçersiz kılın. |
| `--api-key <key>` | API anahtarıyla otomasyon kimlik doğrulaması yapın; hiçbir zaman kaydedilmez. |

| `--no-color` | Renkli çıkışı devre dışı bırakın. |
| `--insecure` / `--secure` | TLS sertifikası doğrulamasını devre dışı bırakın veya geri yükleyin. |
| `--version` | Kutudan çıkarılmış sürümü yazdırın ve çıkın. |

`--api-key` otomasyon için tasarlanmıştır. Oturum açma, kuruluş değiştirme ve asistan komutları kullanıcı oturumu gerektirir.

## Ortam değişkenleri

| Değişken | Eşdeğeri veya amaç |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |
| `FP_TOKEN` | `--token` |
| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | CLI yapılandırma dizinini yeniden konumlandırın (varsayılan `~/.failproofai/fpcli`). |
| `FP_ANALYTICS_DISABLED` veya `DO_NOT_TRACK` | Anonim CLI analitiğini devre dışı bırakın. |
| `NO_COLOR` | Renkli çıkışı devre dışı bırakın. |

Açık bayraklar ortam değişkenlerini geçersiz kılar, bu da kaydedilen yapılandırmayı geçersiz kılar.

API anahtar modunda insan tarafından `fp login` tarafından kaydedilen kuruluş **yoksayılır**, sadece geçersiz kılınmaz — yalnızca açık `--org` veya `FP_ORG` gönderilir. Kaydedilmiş oturumdaki hiçbir şey devralınmaz, bu nedenle anahtar birden fazla kuruluş için hareket edebilirse `--org` geçirin. Bunu atlarsanız gür bir şekilde başarısız olmaz: örnek kapsamlı bir anahtar `--org` olmadan sunucu tarafında **varsayılan** kuruluşa çözülür ve bu kuruluşun verilerini hiçbir yerde hata olmadan döndürür. Anahtarın gerçekten hangi kiracıya konuştuğunu onaylamak için ilk olarak `fp whoami` çalıştırın.
