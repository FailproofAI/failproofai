## Kurulum

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Çerçeve adaptörleri paket içinde gemi halinde gelir. Çerçeveler **isteğe bağlı eş bağımlılıklardır** — desteklenen aralıkların görünmesi için bildirilir, sizin adınıza asla kurulmaz ve yalnızca `instrument()` çağırdığında içe aktarılır.

## Failproof daemon'ını bağlayın

Python SDK'sıyla aynı: **Admin → Keys** altında bir `events:add` anahtarı oluşturun, ardından [daemon'ı bağlayın](/tr/start/setup#connect-a-machine-to-cloud) ajan makinesinde. SDK diske yazar; daemon gönderiş yapar.

## Yapılandırma

### OpenTelemetry span'ları (opt-in)

OpenTelemetry'yi `npm install @opentelemetry/api @opentelemetry/sdk-trace-base` ile ayrı olarak kurun.
Ardından FailproofAI'yi sağlayıcının işlemcilerine ekleyin:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Mevcut bir sağlayıcı için, diğer işlemcilerini aynı listede tutun. `addSpanProcessor` ortaya koyan sağlayıcılar yerine `{ provider }` olarak aktarılabilir. Seçenekler olmadan, kurulum yalnızca başka bir sağlayıcı zaten kayıtlı değilse yeni bir sağlayıcıyı kaydeder.
`OtelSpanExporter` kendi işlemcinizle doğrudan da kullanılabilir.

Dışa aktarımlar bağlı FailproofAI daemon'u aracılığıyla yapılır; SDK hiçbir ağ isteği göndermez ve anahtar veya yerel dinleyici gerektirmez. Bir yöneticiden
[OpenTelemetry ingest](/tr/agenteye/opentelemetry) özelliğini etkinleştirmesini isteyin. Çıplak bir `instrument()` bu dışa aktarıcıyı etkinleştirmez. `uninstrument("otel")` yalnızca kendi işlemcisini devre dışı bırakır.
Span öznitelikleriniz içerik yakalamayı kontrol eder; çıkmadan önce sağlayıcınızı temizleyin.
OpenTelemetry isteğe bağlı bir uygulama bağımlılığı kalır, SDK'nın sabit bir bağımlılığı değil.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Seçenek | Ne işe yarar |
| --- | --- |
| `environment` | Her olay üzerindeki etiket — `production`, `staging`, `prod-eu`. Varsayılan olarak `dev`. |
| `flushInterval` | Zamanlayıcı ne sıklıkla diske yazarsa, saniye cinsinden. Varsayılan olarak `0.5`. |
| `baseDir` | Nereye yazılacak. Varsayılan olarak daemon'ın spool'u, aksi takdirde bilmediğiniz sürece istediğiniz şeydir. |

Hepsi doğrulanmadıkça hiçbir şey uygulanmaz, bu nedenle reddedilen bir çağrı SDK'yı yeni `baseDir` ve eski aralıkla değil, tam olarak olduğu gibi bırakır.

Bunun yerine ortam değişkeni ile ayarlayın:

| Değişken | Ne işe yarar |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Kod değişikliği olmadan `environment` öğesini ayarlar. Bir `configure()` seçeneği bunu kazanır. |
| `FAILPROOFAI_HOME` | Spool'u tutan Failproof AI kökünü taşır. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (varsayılan), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` enstrümantasyon hatalarını günlüğe kaydetmek yerine atmasını sağlar. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` çerçeve uyumluluğu sorununun uyarıyla devam etmek yerine atmasını sağlar. |

<Warning>
  **`environment`'te virgül yok.** Alım bu alanı virgüllerde böler filtreleri oluşturmak için ve etiketinde bir tane bulunan herhangi bir olayı atlar — bu nedenle tüm bir çalışma sessizce kaybolur. `prod,eu` değil `prod-eu` yazın.

  `configure({ environment: "prod,eu" })` hemen öğrenmeniz için atar. `AGENTEYE_ENVIRONMENT` atamaz — hiç kimse sizi çağırmıyor — bu nedenle bir kez uyarır ve `dev` olarak geri döner.
</Warning>

SDK'sının kendi günlük satırlarını `failproofai.setLogger({ debug, info, warn, error })` ile sizin günlükçüye yönlendirin.

## Kapatma

Arabelleğe alınan olaylar `process.on("exit")` üzerinde temizlenir.

Bir sinyal tarafından öldürülen bir işlem asla bu noktaya ulaşmaz ve Node'un `SIGTERM` için varsayılanı çıkış işleyicileri çalıştırmadan sonlandırmaktır — bu nedenle kapsayıcılı bir ajan son aralığın yazmadığı her şeyi kaybeder.

<Warning>
  **Bu SDK sizin için bir sinyal işleyici kurmayacaktır.** Bir taneyi kaydetmek sürecinizin davranışını değiştirir: bir dinleyici Node'un varsayılan sonlandırmayı bastırır, bu nedenle bir tane ekleyen bir kitaplık Ctrl-C'nin çalışmasını sessizce durdurur. Kendinizinizi ekleyin:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Kısa ömürlü bir komut dosyası veya sunucusuz bir işleyici, dönmeden önce `await failproofai.flush()` yapmalıdır — aralık tek başına teslimi garanti etmez.

## Kimlik

Her olay bir oturum ve bir ajanın ait olur. **Kapsamlar her ikisini doldurur**, bu nedenle onları nadiren geçirirsiniz:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId` veya `agentId` adını açıkça geçirmek yine de işe yarar ve kazanır. Ne bağlı ne de geçirilen olmayan, çağrı Cloud'un sessizce atacağı bir olay atmak yerine atar.

<Note>
  Kimlik `AsyncLocalStorage` üzerinde gidiş-geliş yapar. `await`, `.then()`, zamanlayıcılar ve kapsam içinde oluşturulan herhangi bir geri çağırma izler. Bir çalışma sırasında depolanan ve başka bir çalışma sırasında çağrılan bir geri çağırma izleme **yapmaz** veya bir `worker_threads` sınırı boyunca elle verilen şeyler çalışmaz — bunları `failproofai.propagate()` içine sarın veya olayları eklenmemiş olarak iniş yapın.
</Note>

### Kapsamlar

| Kapsam | Yayınlar | Döndürür |
| --- | --- | --- |
| `session(body)` | hiçbir şey — sadece kimlik | `body` ne döndürürse |
| `agent(id, options?, body)` | `agent_start`, ardından `agent_end` | `body` ne döndürürse |
| `toolCall(name, options?, body)` | `tool_use`, ardından `tool_result` | `body` ne döndürürse |

Senkron bir gövde senkron kalır: `agent("x", () => 1)` promise değil, `1` döndürür.

`toolCall` gövdenin çözülen değerini aracının `output` olarak kaydeder, siz `call.output` atamazsanız.

<Accordion title="Çıkış semantiği" icon="arrow-right-from-bracket">

| Ne oldu | Olaylar | `outcome` |
| --- | --- | --- |
| blok döndü | `agent_end` | `"success"`, veya sizin `outcome` |
| blok attı | `error`, ardından `agent_end` | `"failed"` |
| bir `AbortError` | yalnızca `agent_end` | `"cancelled"` |

Hata her zaman yeniden atılır.

Bir araç hatası yaprak üzerinde kaydedilir — `tool_result` bir `error` dizesiyle — ve **hiçbir** çalışma düzeyi `error` olayı yayınlamaz. Ajan döngüsünün yakaladığı bir çalışma hatası değildir ve yayılan bir hata tam olarak bir kez, kapsayan `agent()` tarafından bildirilir.

</Accordion>

<Accordion title="Kullanma formu" icon="brackets-curly">

İş tek bir işlev olmadığında — bir yapıcıda açılan ve bir yıkımda kapalı bir kapsam, veya mevcut kontrol akışını geçen bir kapsam:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, ardından agent_end
```

Her iki form byte-özdeş olaylar yayınlar. Geri çağırma formunu tercih edin: `AsyncLocalStorage.run()` içinde çalışır, bu nedenle gevşetilebilecek hiçbir şey yoktur ve bütün "burada açılan, orada kapalı" hataları sınıfı erişilmez.

Kendi başarısızlığını yakalayan bir `using` bloğu onu `span.fail(error)` ile bildirir — disposer'ın kendine ait hiçbir istisna kanalı yoktur.

</Accordion>

## Olay kataloğu

Python SDK'sıyla aynı on beş yöntem, camelCase'de. Çoğu **çiftler halinde** gelir — açıcıyı çağırırsınız, sonra kapatıcıyı çağırırsınız ve SDK boşluğu zamanlandırır.

| | Açar | Kapar |
| --- | --- | --- |
| **Ajanlar** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Modeller** | `modelRequest` | `modelResponse` |
| **Araçlar** | `toolUse` | `toolResult` |
| **Kancalar** | `hookTriggered` | `hookCompleted` |
| **İnsanlar** | `humanWait` | `humanInput` |

Üç yalnız duruyor: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Her yöntem başına her alan" icon="table">

Her yöntem ayrıca `sessionId` ve `agentId` alır, kapsamlar sizin için doldurur. Atıfta bulunulan her şey JSON `null` olarak gönderilmek yerine düşürülür.

| Yöntem | Gerekli | İsteğe bağlı |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Eklediğiniz diğer anahtarlar özel yük alanı olur. Çerçeveye özgü her şeyi `fw_*` ile ad alanına alın; bildirilen bir alan ile çakışan bir ad sessizce tanıtılan bir sütunu üzerine yazıp yazmaması yerine reddedilir.

</Accordion>

<Warning>
  **`duration_ms` hesaplanır, kabul edilmez.** Dört kapatma yöntemi açıcıdan boşluğu zamanlandırır ve çağrı yapan tarafından sağlanan `duration_ms` öğesini reddeder — bildirilen bir süre yanlışlanamaz.

  Çiftler oturumda ve kimlikte eşleştirilir, hiçbir zaman ajanında. Bir araç `planner` altında açılır ve `worker` altında kapatılırsa, yine de eşleşir, bu da iç içe geçen çok ajanı çalışıyor.
</Warning>

## Çerçeve adaptörleri

```ts
await failproofai.instrument();              // bulabildiği her şey
await failproofai.instrument("langchain");   // tam olarak bir
failproofai.uninstrument();                  // her şeyi geri koy
```

| Çerçeve | Desteklenen | Nasıl bağlanır |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, bu nedenle `callbacks:` hiçbir yere geçmeden her `invoke`/`stream`/`batch` kapsanır — veya `langchainHandler()` kendiniz geçin ve hiçbir şey yama uygulamayın. |
| **Vercel AI SDK** | `ai` 4 – 7 | Çağrı sitesinde `telemetry()` veya `instrument("ai")` tüm işlem için `ai` 7'de (4–6'da bu opt-in — aşağıya bakın). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, ajanın model ve araç çözümü ve iş akışı çalıştırma/adım motoru. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (abone) ve `AgentWorkflow.runStream`, iş akışı çalışmaları ve adımları için. |

Her aralık gerçek çerçeve sürümlerine karşı her iki uçta, ES modülü ve CommonJS olarak, her CI çalışmasında test edilir.

Eşleme Python SDK'sıdır, bu nedenle aynı program her iki dilde aynı ağacı çizer. Bir yapı **bir ajan** olur yalnızca bir LLM karar döngüsüne sahipse — bir grafik veya zincir çalıştırması, bir AI SDK `generateText`/`streamText` çağrısı, bir Mastra ajanı, bir LlamaIndex ajan çalıştırması. Bir LangGraph düğümü veya iş akışı adımı **bir kanca** (`hook_triggered`/`hook_completed`), asla iç içe geçen bir ajan değildir. Model çağrıları token sayıları olan `model_request`/`model_response` çiftleridir; araç çağrıları modelin kendi araç çağrı kimliğini taşır. Bir başarısızlık tam olarak bir kez, meydana geldiği olayda kaydedilir.

Kurulması başarısız olan bir adaptör günlüğe kaydedilir ve atlanır; diğerleri yine de kurulur, çünkü kırık bir LlamaIndex LangGraph'e mal olmamalıdır.

<Note>
  `instrument()` hiçbir argüman olmadan zaten içe aktarılıp aktarılmadığından ziyade **çözülüp çözülmediğine** göre bir çerçeveyi algılar — Node ES modülleri için Python'un `sys.modules` eşdeğerini ortaya koymaz. Kurulu olup kullanmadığınız bir çerçeve içe aktarılacak ve yamalanar. İsteseniz istediğiniz olanı adlandırın.
</Note>

<Note>
  Bu çerçevelerin çoğu bir ES modülü inşası ve bir CommonJS inşası gemi halinde getirir, Node bunları iki ilgisiz kopya olarak yükler. Adaptörler uygulamanızın yüklediği kopyayı (ve bir şey zaten `require` ettiyse CommonJS kopyasını da) yamalandırır, bu nedenle her iki modül sistemi çalışır. Bir çerçeve **esbuild veya webpack tarafından kendi çıkışınızda paketleme** `instrument()` tarafından erişilmez — orada çağrı sitesi yardımcılarını kullanın: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### Yamalama olmadan LangChain

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

İşleyici `instrument()` ile veya olmadan çalışır ve hiçbir zaman çift kaydı kaydetmez. `instrument("langchain")` `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` ve `captureLimit` alır, Python adaptörü yaptığı gibi; bir çağrıda `metadata: { failproofai_sdk_session_id }` o çağrı için oturumu seçer.

### Vercel AI SDK

AI SDK, bir ES modülünden düz işlevleri dışa aktarır ve bir ES modülü ad alanı belirtim tarafından değişmezdir — yamalama yapabileceği bir yer yoktur. SDK'nın kendisi dokumentleye ettiği uzantı noktaları kullanır:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // ai 7'de, `telemetry: telemetry({ … })` — aynı nesne, yeni ad
});
```

Bu tam entegrasyon: bir ajan span'ı, token sayıları olan her adım başına model isteği/yanıt çifti ve her araç çağrısı. Bir çağrı sitesi her büyük kısımdaki her — `ai` 4–6 taşıdığı iz alıcısını okur, `ai` 7 telemetri entegrasyonunu.

`instrument("ai")` aynı şeyi işlem geneline **`ai` 7'de** yapar: AI SDK'nın global telemetri entegrasyonu listesi aracılığıyla her çağrı, eklenebilir ve başka birinin hiçbir şeyini alıp almaz.

**`ai` 4–6'da, `instrument("ai")` kendisi hiçbir şey kaydetmez ve bunu söyleyen bir uyarı günlüğe kaydeder.** Bu büyüklüklerin sahip olduğu tek işlem geneli kancası global OpenTelemetry izleme sağlayıcısıdır — OpenTelemetry alındıktan sonra el vermeyeceği tek bir yuva. Bizimkini kaydetmek daha sonra başlangıçta sizin kendi `NodeSDK.start()` adını sessizce reddeder ve http/veritabanı takibini hiçbir şey dışa aktarılmayan bir iz alıcıya gönderir. `telemetry()` çağrı sitesinde veya `wrapModel` orada kullanın. Süreç kendi başına OpenTelemetry'ı çalıştırmazsa, `instrument("ai", { registerGlobalTracer: true })` ile kabul edin: o zaman `experimental_telemetry: { isEnabled: true }` geçen her çağrıyı kaydeder ve yalnızca yuva hala boş ise tutar. `registerGlobalTracer: false` varsayılanı tutar ve uyarıyı sessizleştirir.

Bunun yerine modeli bir kez sarmalamayı tercih ediyorsanız, `wrapModel` yalnızca model çağrılarını görür, çünkü araç çağrıları model katmanının üstünde gerçekleşir. Etrafında hiçbir şey ile sarılan sarılı bir model kendi çalışması olarak kaydedilir. Akışlı bir çağrı akış nasıl duruyorsa kapatılır — `stop_reason: "cancelled"` tüketici iptal ettiğinde, `"error"` yarı yolda başarısız olduğunda hatayla:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Her ikisini de kullanmak iyidir: ara yazılım çağrının zaten kaydedildiğini fark eder ve erteler, bu nedenle her çağrı bir kez kaydedilir.

`functionId` ajan span'ını adlandırır. Düşük önsembolü tutun — `agent_id` ana pano yönü ile iniş yapıyor.

### Next.js

`next build` varsayılan olarak sunucunuzun bağımlılıklarını paketler ve yapıya paketlenen bir çerçeve `instrument()` tarafından erişilebileceği bir kopyadır. Yapılandırmayı bir kez sarın ve `instrument()` öğesini Next'in başlangıç kancasından çağırın:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` LangChain, Mastra, LlamaIndex ve SDK'nın kendisini `serverExternalPackages` öğesine ekler, sizin listenizi tutar. Olmadan, `instrument()` onu erişemediği her çerçeve için bir kez uyarır yerine sessizce başarısız olur; paketleri kendiniz listelerseniz, `FAILPROOFAI_NEXT_EXTERNALS=1` öğesini ayarlayın. Vercel AI SDK ve çağrı sitesi yardımcıları her iki şekilde de çalışır. Bir Edge rotası hiçbir yapıdır: SDK'yı içe aktarmak güvenlidir ve hiçbir şey kaydetmez.

### Akışlı çağrılardan token sayıları

OpenAI uyumlu API'leri istemci sorduğunda bir akışta kullanımı bildirir. LangChain ve Vercel AI SDK sorar; LlamaIndex için `additionalChatOptions: { stream_options: { include_usage: true } }` adını `OpenAI` LLM'sine geçirin ve Mastra için modeli kullanım etkinleştirilmiş şekilde oluşturun (örneğin `createOpenAICompatible({ includeUsage: true })`). Aksi takdirde akışlı model çağrıları token sayılarını taşımaz.

### Çalışma zamanları

Node ≥ 20.9, Bun ve Deno — her çerçeve, bir ES modülü ve CommonJS olarak, her biri Node'un izine karşı test edilir. SDK, yazınanı gönderen `failproofaid` daemon'ının yanında çalışır.

## Kendi ajanınız — çerçeve yok

Kendiniz yazdığınız bir ajan döngüsü veya adaptörü olmayan bir çerçeve için. Adaptörlerin altında kullandığı aynı API ile olayları yayıp yayarınız, bu nedenle iz aynı şekle ve kaliteyeye sahiptir.

Ajanın nasıl organize edildiğini bilmeniz gerekmez. Her el yapımı ajan zaten üç yer vardır, işlevleri ne aranırsa, ve bu üçü tüm entegrasyon:

| Nerede | Eklenecekler | Yayınlar |
| --- | --- | --- |
| **Bir çalışma** başlayıp bittiği yer | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Modeli çağıran tek işlev** | Başında `event.modelRequest`, sonrada `event.modelResponse` — hata üzerine bile iki yarısı | model döndürüsü başına bir çift |
| **Araçları çalıştıran tek işlev** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Kimlik ortam: `agent()` içindeki her şey o çalışma oturumuna kimlik geçmeden iniş yapıyor ve sürecin başka bir yeri değişmiyor — ajan zaten yazıldığı her şey dahil olmak üzere kendi veritabanına.

- **Bir hizmet veya işçi:** kendi istek veya iş kimliğini `sessionId` olarak geçirin, bu nedenle pano üzerinde bir oturum ve kendi günlüğünüzdeki veya veritabanındaki kayıt aynı dizedir.
- **Alt ajanlar:** `agent()` çağrılarını iç içe geçirin. İçerdeki dış oturuma `parent_id` olarak katılır.
- **Çiftleri yayınla.** Hiçbir `modelResponse` olmayan bir `modelRequest` span'ı panoda sonsuza kadar çalışan panoda — bu nedenle `catch` alır.

Depo [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) tam, çalıştırılabilir sürümüdür: gerçek OpenAI araç döngüsü tam olarak bunu enstrümente ederek, ES modülü ve CommonJS olarak her değişiklik CI'de çalışır.

## Değerlendirmeler

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Protokol, çalışan ayarları ve sonuç türleri için [Evaluator SDK başvurusuna](/tr/reference/evaluator-sdk) bakın.

<Warning>
  **Bir değerlendirme vermelidir.** Asla dönmeyen senkron bir işlev Node'un sahip olduğu tek iş parçacığını bloke eder ve zaman çıkış sırasında ateşleyemez. `async` değerlendirmeler yazın.
</Warning>

## Sürecinize ne yapmayacak

| | |
| --- | --- |
| **Ajan döngünüzü engelleyin** | Olaylar bellek içi kuyruğa gider; bir zamanlayıcı onları yazar. Zamanlayıcı `unref` ediği için, bu paketi içe aktarmak hiçbir zaman komut dosyasını çıkmaktan durdurur. |
| **Sınırsız büyüyün** | Kuyruk sayıya *ve* ölçülen bayt ile kapsanır. Her ikisinin de ötesinde, en eski olaylar atılır ve bir uyarı öyle der — telemetri kesintisi bir OOM öldürmesine dönmemeli. |
| **Süreci aşağıda alın** | Bir kod çözmesi yapılamayan olay yalnız atılır, etrafındaki toplu iş değil. Atan bir alıcı, dairesel bir referans, bir `BigInt`, tek bir vekil: her biri yayınlanmak yerine ele alınır. |
| **Yarı yazılı bir toplu iş bırakın** | İçerik, atomik yeniden adlandırmadan önce `fsync` edilir, dizin sonra `fsync` edilir ve başarısız bir yazı geçici dosyasını temizler. |
| **Transkriptleri okunabilir bırakın** | Toplu işler bir `0700` dizininde `0600`. Amaçlar, istemleri, araç bağımsız değişkenleri ve araç çıkışını taşırlar. |
| **Kimlik bilgilerini gönderin** | API anahtarları, jetonlar, JWT'ler, taşıyıcı başlıkları ve sır benzeri atamalar baytlar diske ulaşmadan redakte edilir. Daemon yüklemeden önce tekrar redakte eder. |
