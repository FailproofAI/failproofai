## Yükle

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Framework adaptörleri paketin içinde gönderilir. Frameworkler **isteğe bağlı eş bağımlılıklardır** — desteklenen aralıklar görülsün diye bildirilir, asla sizin adınıza yüklenmez ve yalnızca `instrument()` çağırdığınızda içe aktarılır.

## Failproof daemon'a bağlan

Python SDK ile aynı: **ayarlar → api anahtarları** altında bir `events:add` anahtarı oluştur, ardından [daemon'u bağla](/tr/start/setup#connect-a-machine-to-cloud) ajan makinesinde. SDK diske yazar; daemon gönderir.

## Yapılandırma

### OpenTelemetry aralıkları (giriş)

OpenTelemetry'yi ayrı olarak `npm install @opentelemetry/api @opentelemetry/sdk-trace-base` ile yükle.
Sonra FailproofAI'ı sağlayıcınızın işlemcilerine ekle:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Mevcut bir sağlayıcı için, diğer işlemcilerini aynı listede tutun. `addSpanProcessor` ortaya koyan sağlayıcılar bunun yerine `{ provider }` olarak geçilebilir. Seçeneksiz, kurulum yalnızca hiçbir sağlayıcı zaten kaydedilmemişse yeni bir sağlayıcı kaydeder.
`OtelSpanExporter` ayrıca kendi işlemcinizle doğrudan kullanılabilir.

Dışa aktarımlar bağlı FailproofAI daemon'u üzerinden gider; SDK hiçbir ağ isteği göndermez ve anahtar veya yerel dinleyici gerektirmez. [OpenTelemetry alımı](/tr/agenteye/opentelemetry)
Cloud'da her zaman açıktır. Boş bir `instrument()` bu dışa aktarıcıyı etkinleştirmez. `uninstrument("otel")` yalnızca kendi işlemcisini devre dışı bırakır.
Span özniteliklerin içerik yakalamayı kontrol eder; çıkmadan önce sağlayıcınızı temizle.
OpenTelemetry, sabit bir SDK bağımlılığı değil, isteğe bağlı bir uygulama bağımlılığı olarak kalır.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Seçenek | Ne yapar |
| --- | --- |
| `environment` | Her olaydaki etiket — `production`, `staging`, `prod-eu`. Varsayılan `dev`. |
| `flushInterval` | Zamanlayıcının diske yazma sıklığı, saniye cinsinden. Varsayılan `0.5`. |
| `baseDir` | Nereye yazacak. Varsayılan daemon'un spoolaydır, bilmiyorsanız istediğiniz şey budur. |

Hepsi doğrulanmadıkça hiçbir şey uygulanmaz, bu nedenle reddedilen bir çağrı SDK'yı yeni bir `baseDir` ile değil, eski aralık ile tam olarak olduğu gibi bırakır.

Bunun yerine ortam değişkeniyle ayarla:

| Değişken | Ne yapar |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Kod değişikliği olmadan `environment` ayarlar. Bir `configure()` seçeneği onu geçersiz kılar. |
| `FAILPROOFAI_HOME` | Spoolaynı içeren Failproof AI kökünü taşı. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (varsayılan), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` enstrümantasyon hatalarının kaydedilmek yerine atılmasına neden olur. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` framework uyumluluğu sorununun uyarı vermek ve devam etmek yerine atılmasına neden olur. |

<Warning>
  **`environment` içinde virgül yok.** Alım bu alanı virgüllerde böler filtreleri oluşturmak için ve etiketi içeren virgül içeren herhangi bir olayı atlar — bu nedenle tüm bir çalışma sessizce kaybolur. `prod,eu` değil `prod-eu` yaz.

  `configure({ environment: "prod,eu" })` hemen bulabilmen için atılır. `AGENTEYE_ENVIRONMENT` atılamaz — hiç kimse seni çağırmıyor — bu yüzden bir kez uyarır ve `dev` öğesine geri döner.
</Warning>

SDK'nın kendi günlük satırlarını `failproofai.setLogger({ debug, info, warn, error })` ile günlüğünüze yönlendir.

## Kapatma

Arabelleğe alınan olaylar `process.on("exit")` işleminde temizlenir.

Bir sinyal tarafından öldürülen işlem buna asla ulaşmaz ve Node'un `SIGTERM` için varsayılanı çıkış işlemcileri çalıştırmadan sonlandırmaktır — bu nedenle konteynerize edilmiş bir ajan son aralığın yazmadığı şeyi kaybeder.

<Warning>
  **Bu SDK sizin için bir sinyal işlemcisi yüklemez.** Birini kaydettirmek işlemin davranışını değiştirir: bir dinleyici Node'un varsayılan sonlandırmasını bastırır, bu nedenle bir tane ekleyen bir kütüphane sessizce Ctrl-C'nin çalışmasını durdurur. Kendi ekle:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Kısa ömürlü bir komut dosyası veya sunucusuz bir işleyici dönmeden önce `await failproofai.flush()` yapmalıdır — aralık tek başına teslimatı garanti etmez.

## Kimlik

Her olay bir oturum ve bir ajana ait olur. **Kapsamlar her ikisini de doldurur**, bu nedenle çoğu zaman onları geçmezsiniz:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId` veya `agentId` açıkça geçmek hala işe yarar ve kazanır. Hiçbiri bağlanmadı veya geçilmediyse, çağrı Cloud'un sessizce atacağı bir olay yaymak yerine atılır.

<Note>
  Kimlik `AsyncLocalStorage` üzerinde gider. `await`, `.then()`, zamanlayıcıları ve kapsam içinde oluşturulan herhangi bir geri aramayı takip eder. Bir çalıştırma sırasında depolanan ve başka bir çalıştırma sırasında çağrılan bir geri aramayı takip **etmez** veya `worker_threads` sınırına geçen işleri çalıştırmaz — bunları `failproofai.propagate()` içine sar veya olayları eklenmemiş bir şekilde iner.
</Note>

### Kapsamlar

| Kapsam | Yayınlar | Döndürür |
| --- | --- | --- |
| `session(body)` | hiçbir şey — yalnızca kimlik | `body` ne döndürürse |
| `agent(id, options?, body)` | `agent_start`, sonra `agent_end` | `body` ne döndürürse |
| `toolCall(name, options?, body)` | `tool_use`, sonra `tool_result` | `body` ne döndürürse |

Senkron bir gövde senkron kalır: `agent("x", () => 1)` `1` döndürür, bir vaadi değil.

`toolCall` gövdenin çözülen değerini aracın `output` olarak kaydeder, sürece `call.output` kendiniz atamadıkça.

<Accordion title="Çıkış semantiği" icon="arrow-right-from-bracket">

| Ne oldu | Olaylar | `outcome` |
| --- | --- | --- |
| blok döndü | `agent_end` | `"success"`, veya sizin `outcome` |
| blok attı | `error`, sonra `agent_end` | `"failed"` |
| bir `AbortError` | yalnızca `agent_end` | `"cancelled"` |

Hata her zaman yeniden atılır.

Araç hatası yaprakta kaydedilir — `tool_result` bir `error` dizesiyle — ve hiçbir çalıştırma düzeyi `error` olayı **yayınlamaz**. Ajan döngüsünün yakaladığı bir değil, ve yayılan bir kez, kapsayan `agent()` tarafından bildirilir.

</Accordion>

<Accordion title="Kullanılan form" icon="brackets-curly">

İş tek bir işlev olmadığında — bir kurucu içinde açılan ve bir yıkımda kapatılan bir kapsam, veya mevcut kontrol akışını geçen bir kapsam:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

Her iki form da bayt-özdeş olaylar yayınlar. Geri arama formunu tercih et: `AsyncLocalStorage.run()` içinde çalışır, bu nedenle açılacak hiçbir şey yoktur ve "burada açıl, oraya kapal" hataları sınıfının tamamı ulaşılamaz.

Kendi arızasını yakalayan `using` bloğu onu `span.fail(error)` ile bildirir — disposer'ın kendi istisna kanalı yok.

</Accordion>

## Olay kataloğu

Python SDK ile aynı on beş metot, camelCase'de. Çoğu **çiftler** ile gelir — açıcıyı çağırırsın, sonra kapatıcı çağırırsın ve SDK boşluğu zamanlar.

| | Açar | Kapar |
| --- | --- | --- |
| **Ajanlar** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Modeller** | `modelRequest` | `modelResponse` |
| **Araçlar** | `toolUse` | `toolResult` |
| **Kancalar** | `hookTriggered` | `hookCompleted` |
| **İnsanlar** | `humanWait` | `humanInput` |

Üçü bağımsız durur: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Her metot başına her alan" icon="table">

Her metot `sessionId` ve `agentId`'yi de alır, kapsamlar sizin için doldurur. Atılan herhangi bir şey JSON `null` olarak gönderilmek yerine düşürülür.

| Metot | Gerekli | İsteğe bağlı |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Eklediğin başka herhangi bir anahtar özel bir yük alanı olur. Framework'e özgü herhangi bir şeyi `fw_*` olarak adlandır; bildirilmiş bir alanla çakışan bir ad sessizce terfi etmiş bir sütunu üzerine yazmak yerine reddedilir.

</Accordion>

<Warning>
  **`duration_ms` hesaplandı, kabul edilmedi.** Dört kapama metodu açıcıdan boşluğu zamanlar ve arayanın sağladığı `duration_ms` değerini reddeder — bildirilen bir süre çürütülemez.

  Çiftler **oturum** ve id'ye eşleştirilir, hiçbir zaman ajan'a. `planner` altında açılan ve `worker` altında kapatılan bir araç hala eşleşir, bu iç içe çok ajanı çalışmaktadır.
</Warning>

## Framework adaptörleri

```ts
await failproofai.instrument();              // bulabildiği şey
await failproofai.instrument("langchain");   // tam biri
failproofai.uninstrument();                  // her şeyi geri koy
```

| Framework | Desteklenen | Nasıl bağlı olur |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, yani her `invoke`/`stream`/`batch` herhangi yerde `callbacks:` geçmeden kapsanır — veya `langchainHandler()` kendin geç ve hiçbir şey yama. |
| **Vercel AI SDK** | `ai` 4 – 7 | Çağrı sitesinde `telemetry()`, veya `instrument("ai")` `ai` 7 üzerinde tüm işlem için (4–6'da bu opt-in — aşağıya bak). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, ajanın model ve araç çözünürlüğü ve iş akışı çalıştırma/adım motoru. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (abone) artı `AgentWorkflow.runStream`, iş akışı çalıştırmaları ve adımları için. |

Her aralık gerçek framework yayınlarına karşı, her iki uçta, ES modülü olarak ve CommonJS olarak, her CI çalıştırmasında sınanır.

Eşleme Python SDK'nınkidir, bu nedenle aynı program her iki dilde aynı ağacı çizer. Bir yapı **ajan** ancak bir LLM karar döngüsüne sahipse — bir grafik veya zincir çalıştırması, bir AI SDK `generateText`/`streamText` çağrısı, bir Mastra ajanı, bir LlamaIndex ajan çalıştırması. Bir LangGraph düğümü veya iş akışı adımı **kanca** (`hook_triggered`/`hook_completed`), hiçbir zaman iç içe ajan değil. Model çağrıları token sayılarıyla `model_request`/`model_response` çiftleridir; araç çağrıları modelin kendi araç çağrısı id'sini taşır. Hata meydana geldiği olay üzerinde kaydedilir.

Yüklemesi başarısız olan bir adaptör kaydedilir ve atlanır; diğerleri hala yüklenir, çünkü kesilen bir LlamaIndex sana LangGraph'a mal olmamalı.

<Note>
  Argüman olmadan `instrument()`, bir framework'ün zaten içe aktarılıp aktarılmadığına değil **çözülüp çözülmediğine** göre algılar — Node, ES modülleri için Python'un `sys.modules` eşdeğerini ortaya koymaz. Yüklediğin ama kullanmadığın bir framework içe aktarılacak ve yamalanacak. İstediğini adlandır eğer önemliyse.
</Note>

<Note>
  Bu frameworklerin çoğu bir ES modülü yapısı ve CommonJS yapısı, Node iki alakasız kopya olarak yükler. Adaptörler uygulamanızın yüklediği kopyayı yamaları (ve zaten birisi bunu `require` ettiyse CommonJS kopyasını da), bu nedenle her iki modül sistemi çalışır. esbuild veya webpack tarafından kendi çıktınıza **paketlenmiş** bir framework ulaşılamaz — orada çağrı sitesi yardımcılarını kullan: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### Yamamasız LangChain

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

İşleyici `instrument()` ile veya olmadan çalışır ve hiçbir zaman çift kaydı yapmaz. `instrument("langchain")` Python adaptörü gibi `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` ve `captureLimit`'i alır; bir çağrı üzerindeki `metadata: { failproofai_sdk_session_id }` bu çağrı için oturumu seçer.

### Vercel AI SDK

AI SDK, ES modülünden düz işlevleri dışa aktarır ve bir ES modülü ad alanı spesifikasyonla değişmezdir — yama yapılacak hiçbir yer yok. SDK'nın kendisinin belgelediği uzantı noktalarını kullanır:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // ai 7 üzerinde, `telemetry: telemetry({ … })` — aynı nesne, yeni ad
});
```

Bu tam entegrasyon: bir ajan aralığı, her adımda token sayılarıyla bir model istek/yanıt çifti ve her araç çağrısı. Bir çağrı sitesi her ana sürümde çalışır — `ai` 4–6 taşıdığı izleyiciyi oku, `ai` 7 telemetri entegrasyonunu.

`instrument("ai")` aynısını **`ai` 7 üzerinde** işlem genelindedir: her çağrı, AI SDK'nın küresel telemetri entegrasyonu listesi aracılığıyla, katkı yılı ve başka kimsenin hiçbir şey almaması.

**`ai` 4–6 üzerinde, `instrument("ai")` kendi kendine hiçbir şey kaydı yapmaz ve bunu söyleyen bir uyarı günlüğü kaydeder.** Bu majörler sahip olduğu tek işlem genelinde kanca, küresel OpenTelemetry izleyici sağlayıcısı — OpenTelemetry bir kez alındıktan sonra teslim etmeyi reddeder bir tek yuva. Bizimkini kaydetmek daha sonra başlangıçta `NodeSDK.start()` senin kendi yerinin sessizce reddedilmesine neden olur ve http/veritabanı yayınlarını hiçbir şey dışa aktarmayan bir izleyiciye gönder. Çağrı sitesinde `telemetry()` kullan veya `wrapModel` orada. İşlem kendi OpenTelemetry'sini çalıştırmıyorsa, `instrument("ai", { registerGlobalTracer: true })` ile opt-in et: ardından `experimental_telemetry: { isEnabled: true }` geçen her çağrıyı kaydeder ve yalnızca hala boşsa yuva alır. `registerGlobalTracer: false` varsayılanı tutar ve uyarıyı sessizleştirir.

Modeli bir kez saramak istiyorsan, `wrapModel` model çağrıları yalnızca gördüğü, çünkü araç çağrıları model katmanının üstünde olur. Etrafında hiçbir şey olmadan çağrılan saranmış bir model kendi çalışması olarak kaydedilir. Akışlı bir çağrı akış nasıl durursa kapar — akış tüketici tarafından iptal edilirse `stop_reason: "cancelled"`, hatayı yarıda atarsa `"error"`'ı:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Her ikisini de kullanmak iyidir: ara yazılım çağrısının zaten kaydedildiğini fark eder ve atar, bu nedenle her çağrı bir kez kaydedilir.

`functionId` ajan aralığını adlandırır. Düşük kardinaliteyi tut — `agent_id` içine iner, birincil pano yönü.

### Next.js

`next build` varsayılan olarak sunucunuzun bağımlılıklarını paketler ve yapıya paketlenmiş bir framework `instrument()` ulaşamayacağı bir kopyasıdır. Yapılandırmayı bir kez sar ve Next'in başlangıç kancasından `instrument()` çağır:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` LangChain, Mastra, LlamaIndex ve SDK'nın kendisini `serverExternalPackages`'a ekler, kendi listenizi tutar. Olmazsa, `instrument()` sessizce başarısız olmak yerine ulaşamadığı her framework için bir kez uyarır; paketleri kendin listeleyersen, `FAILPROOFAI_NEXT_EXTERNALS=1` ayarla. Vercel AI SDK ve çağrı sitesi yardımcıları her iki şekilde de çalışır. Bir Kenar rotası no-op yapısı alır: SDK'nı içe aktarmak güvenlidir ve hiçbir şey kaydı yapmaz.

### Akışlı çağrılarda token sayıları

OpenAI uyumlu API'lar, istemci sorduğunda bir akış üzerindeki kullanımı bildirir. LangChain ve Vercel AI SDK sordu; LlamaIndex için `additionalChatOptions: { stream_options: { include_usage: true } }` öğesini `OpenAI` LLM'ne geç ve Mastra için modeli kullanım etkinleştirilmiş şekilde oluştur (örneğin `createOpenAICompatible({ includeUsage: true })`). Aksi takdirde akışlı model çağrıları token sayısı taşımaz.

### Çalışma zamanları

Node ≥ 20.9, Bun ve Deno — her framework, ES modülü ve CommonJS olarak, Node'un izlemesine karşı her biri üzerinde sınanır. SDK `failproofaid` daemon'u yanında çalışır, yazdığını gönderir.

## Kendi ajanın — framework yok

Kendin yazdığın bir ajan döngüsü veya adaptörü olmayan bir framework için. Adaptörlerin altında kullandığı aynı API'yle olayları yayırsın, bu nedenle izleme aynı şekil ve kaliteye sahip.

Ajanın nasıl organize edildiğini bilmen gerekmez. Elle yapılmış her ajan zaten üç yere sahiptir, işlevleri ne çağrılırsa çağrılsın ve bu üç tümü bütün entegrasyondur:

| Nerede | Ne ekleyeceği | Yayınlar |
| --- | --- | --- |
| **Bir çalıştırma** başlar ve biter | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| Modeli çağıran **tek işlev** | `event.modelRequest` önce, `event.modelResponse` sonra — hatada bile her iki yarı | model sırası başına bir çift |
| Araçları çalıştıran **tek işlev** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Kimlik ortamsal: `agent()` içindeki her şey bir id almadan o çalıştırmanın oturumuna iner ve programdaki başka hiçbir şey değişmez — ajanın kendi veritabanına zaten yazdığı herhangi bir şey dahil.

- **Bir hizmet veya işçi:** kendi istek veya iş id'sini `sessionId` olarak geç, bu nedenle pano üzerindeki bir oturum ve kendi günlüğünüz veya veritabanınızdaki kayıt aynı dizedir.
- **Alt ajanlar:** `agent()` çağrılarını iç içe. İçteki oturuma dış olarak `parent_id` ile katılır.
- **Çiftleri yayınla.** `modelResponse` olmayan bir `modelRequest` sonsuza kadar çalışan bir aralık gösterir — bu nedenle `catch`.

Deponuzdaki [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) tam, çalıştırılabilir sürümdür: tam biri OpenAI araç döngüsü tam olarak bunun gibi enstrümante, CI üzerinde her değişiklik olarak ES modülü ve CommonJS olarak çalıştırılır.

## Değerlendirmeler

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \

```

## İşleminde ne yapmayacağı

| | |
| --- | --- |
| **Ajan döngünüzü engelle** | Olaylar bellek içi bir kuyruğa gider; zamanlayıcı yazarlar. Zamanlayıcı `unref`'dir, bu nedenle bu paketi içe aktarmak hiçbir zaman bir komut dosyasının çıkışını durdurmaz. |
| **Sınır olmadan büyü** | Kuyruk sayı ve ölçülen bayt ile sınırlanır. Her biri geçtikten sonra, en eski olaylar atılır ve bir uyarı söyler — telemetri kesintisi OOM öldürme haline gelmelidir. |
| **İşlemi aşağı al** | Bir kodlanamayan olay yalnız düşürülür, etrafındaki toplu iş değil. Atılan bir alıcı, döngüsel bir başvuru, bir `BigInt`, tek bir vekil: her işlenir veya yayılmak yerine yayılır. |
| **Yarı yazılmış bir toplu iş bırak** | İçerik adı değiştirilmeden önce `fsync`'lenmiş ve dizin sonra `fsync`'lenmiş ve başarısız yazma geçici dosyasını temizler. |
| **Transkriptler okunabilir bırak** | Toplu işler `0700` dizin içinde `0600`'dür. Hedefler, istemler, araç argümanları ve araç çıktısı taşırlar. |
| **Kimlik bilgisi gönder** | API anahtarları, jetonlar, JWT'ler, taşıyıcı başlıkları ve gizli şekilli atamalar diskine ulaşan baytlardan önce düzeltilir. Daemon upload'dan önce tekrar düzeltir. |
