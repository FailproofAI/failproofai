## Kurulum

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Framework adaptörleri paketin içinde gönderilir. Framework'ler **isteğe bağlı eş bağımlılıklar** — desteklenen aralıklar görünecek şekilde bildirilir, sizin adınıza hiçbir zaman kurulmaz ve yalnızca `instrument()` çağırdığınızda içe aktarılır.

## Failproof daemon'ı bağlayın

Python SDK'sı ile aynı: **Admin → Keys** altında bir `events:add` anahtarı oluşturun, ardından [daemon'ı aracı makinesinde bağlayın](/tr/start/setup#connect-a-machine-to-cloud). SDK diske yazar; daemon gönderir.

## Yapılandırma

### OpenTelemetry span'ları (devre dışı seçeneği)

OpenTelemetry'i `npm install @opentelemetry/api @opentelemetry/sdk-trace-base` ile ayrı olarak kurun.
Ardından FailproofAI'ı sağlayıcınızın işlemcilerine ekleyin:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Mevcut bir sağlayıcı için, diğer işlemcilerini aynı listede tutun. `addSpanProcessor` sunan sağlayıcılar bunun yerine `{ provider }` olarak geçirilebilir. Seçeneksiz, kurulum yalnızca başka bir sağlayıcı zaten kayıtlı değilse yeni bir sağlayıcı kaydeder.
`OtelSpanExporter` ayrıca kendi işlemcinizle doğrudan kullanılabilir.

İhracat bağlı FailproofAI daemon'ı üzerinden gider; SDK ağ istekleri göndermez ve anahtara veya yerel dinleyiciye ihtiyaç duymaz. Bir yöneticiden [OpenTelemetry alımını](/tr/agenteye/opentelemetry) etkinleştirmesini isteyin. Boş bir `instrument()` bu dışa aktarıcıyı etkinleştirmez. `uninstrument("otel")` yalnızca kendi işlemcisini devre dışı bırakır.
Span öznitelikleriniz içerik yakalamasını kontrol eder; çıkıştan önce sağlayıcınızı temizleyin.
OpenTelemetry isteğe bağlı bir uygulama bağımlılığı olarak kalır, SDK'nın sabit bağımlılığı değil.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Seçenek | Ne yaptığı |
| --- | --- |
| `environment` | Her olayda etiket — `production`, `staging`, `prod-eu`. Varsayılan olarak `dev`. |
| `flushInterval` | Zamanlayıcının diske yazma sıklığı, saniye cinsinden. Varsayılan olarak `0.5`. |
| `baseDir` | Nereye yazılacağı. Varsayılan olarak daemon'ın spool'u, aksi takdirde bilmiyorsanız istediğiniz şey. |

Tümü doğrulanmadığı sürece hiçbir şey uygulanmaz, bu nedenle reddedilen bir çağrı SDK'yı yeni `baseDir` ve eski aralıkla bırakmak yerine tam olarak olduğu gibi bırakır.

Bunun yerine ortam değişkeniyle ayarlayın:

| Değişken | Ne yaptığı |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | `environment`'ı kod değişikliği olmadan ayarlar. `configure()` seçeneği bunu geçersiz kılar. |
| `FAILPROOFAI_HOME` | Spool'u tutan Failproof AI kökünü taşır. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (varsayılan), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` enstrümentasyon hatalarının günlüğe kaydedilmek yerine throw etmesini sağlar. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` bir framework uyumluluğu sorununun uyarı vermek ve devam etmek yerine throw etmesini sağlar. |

<Warning>
  **`environment` içinde virgül yok.** İçe alma bu alanı virgülde bölerek filtrelerini oluşturur ve virgül içeren bir etiketi olan herhangi bir olayı atlar — böylece tüm bir çalıştırma sessizce kaybolur. `prod,eu` değil `prod-eu` yazın.

  `configure({ environment: "prod,eu" })` hemen fark etmeniz için throw eder. `AGENTEYE_ENVIRONMENT` throw edemez — hiç kimse sizi çağırmıyor — bu nedenle bir kez uyarır ve `dev` öğesine geri döner.
</Warning>

SDK'nın kendi günlük satırlarını `failproofai.setLogger({ debug, info, warn, error })` ile günlükçüğe yönlendirin.

## Kapatma

Arabelleğe alınan olaylar `process.on("exit")` üzerinde temizlenir.

Bir sinyal tarafından öldürülen işlem asla buna ulaşmaz ve `SIGTERM` için Node'un varsayılanı çıkış işleyicileri çalıştırmadan sonlandırmaktır — bu nedenle kapsayıcılı bir aracı son aralığın yazılmadığını kaybeder.

<Warning>
  **Bu SDK sizin için bir sinyal işleyicisi kurmayacak.** Birini kaydetmek işleminizin davranışını değiştirir: bir dinleyici Node'un varsayılan sonlandırmasını bastırır, bu nedenle bir tane ekleyen bir kütüphane sessizce Ctrl-C'nin çalışmasını durdururdu. Kendi yapınızı ekleyin:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Kısa süreli bir komut dosyası veya sunucusuz bir işleyici, döndürmeden önce `await failproofai.flush()` yapmalıdır — aralık tek başına teslimatı garanti etmez.

## Kimlik

Her olay bir oturum ve bir aracıya aittir. **Kapsamlar her ikisini de doldurur**, bu nedenle nadiren onları geçersiniz:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId` veya `agentId` açıkça geçmek hala çalışır ve kazanır. Ne bağlı ne de geçildiği halde, çağrı Cloud'un sessizce atmış olacağı bir olayı yayınlamak yerine throw eder.

<Note>
  Kimlik `AsyncLocalStorage` üzerinde yer alır. `await`, `.then()`, zamanlayıcılar ve kapsam içinde oluşturulan herhangi bir geri çağırma izler. Bir çalıştırma sırasında depolanan ve başka bir sırada çağrılan bir geri çağırma veya bir `worker_threads` sınırında elle alınan iş izlemez — bunları `failproofai.propagate()` içinde saralım veya olayları bağlantısız iniş yapın.
</Note>

### Kapsamlar

| Kapsam | Yayınlar | Döndürür |
| --- | --- | --- |
| `session(body)` | hiçbir şey — yalnızca kimlik | `body`'nin ne döndürdüğü |
| `agent(id, options?, body)` | `agent_start`, sonra `agent_end` | `body`'nin ne döndürdüğü |
| `toolCall(name, options?, body)` | `tool_use`, sonra `tool_result` | `body`'nin ne döndürdüğü |

Senkron bir gövde senkron kalır: `agent("x", () => 1)` bir promise değil `1` döndürür.

`toolCall` gövdenin çözülmüş değerini aracın `output` olarak kaydeder, siz `call.output` atamadığınız sürece.

<Accordion title="Çıkış semantiği" icon="arrow-right-from-bracket">

| Ne oldu | Olaylar | `outcome` |
| --- | --- | --- |
| blok döndü | `agent_end` | `"success"` veya sizin `outcome` |
| blok throw etti | `error`, sonra `agent_end` | `"failed"` |
| bir `AbortError` | yalnızca `agent_end` | `"cancelled"` |

Hata her zaman yeniden throw edilir.

Bir aracı başarısızlığı yaprağa kaydedilir — `tool_result` bir `error` dizesiyle — ve **hiç** çalıştırma düzeyinde `error` olayı yayınlamaz. Aracı döngüsünün yakaladığı çalıştırma başarısızlığı değildir ve yayılan bir kez, çevresel `agent()` tarafından bildirilir.

</Accordion>

<Accordion title="`using` formu" icon="brackets-curly">

İş tek bir fonksiyon olmadığında — bir yapıcıda açılan ve bir yıkımda kapatılan bir kapsam, veya mevcut kontrol akışını kapsayan:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

Her iki form bayt için aynı olaylar yayınlar. Geri çağırma formunu tercih edin: `AsyncLocalStorage.run()` içinde çalışır, bu nedenle geri sarılacak hiçbir şey yoktur ve "burada açılmış, orada kapatılmış" hataların tüm sınıfı ulaşılamaz.

Kendi başarısızlığını yakalayan bir `using` bloğu `span.fail(error)` ile bildirir — dispozerin kendi istisna kanalı yoktur.

</Accordion>

## Olay kataloğu

Python SDK'sı ile aynı on beş yöntem, camelCase'te. Çoğu **çiftler** halinde gelir — açıcıyı çağırır, sonra kapıcıyı, ve SDK boşluğu zamanlar.

| | Açar | Kapatır |
| --- | --- | --- |
| **Aracılar** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Modeller** | `modelRequest` | `modelResponse` |
| **Araçlar** | `toolUse` | `toolResult` |
| **Kancalar** | `hookTriggered` | `hookCompleted` |
| **İnsanlar** | `humanWait` | `humanInput` |

Üç bağımsız: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Yöntem başına her alan" icon="table">

Her yöntem ayrıca `sessionId` ve `agentId` alır, kapsamlar sizin için doldurur. Atlanmış hiçbir şey JSON `null` olarak gönderilmek yerine bırakılır.

| Yöntem | Gerekli | İsteğe Bağlı |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Eklediğiniz diğer herhangi bir anahtar özel bir yük alanı olur. Framework'e özel herhangi bir şeyi `fw_*` ile adlandırın; bildirilmiş bir alanla çakışan bir ad sessizce tanıtılan bir sütunu üzerine yazmak yerine reddedilir.

</Accordion>

<Warning>
  **`duration_ms` hesaplanır, kabul edilmez.** Dört kapatma yöntemi açıcıdan boşluğu zamanlar ve arayan tarafından sağlanan `duration_ms` reddeder — bildirilen süre sahteci yapılamaz.

  Çiftler oturuma ve kimliğe göre eşleştirilir, hiçbir zaman aracıya değil. `planner` altında açılan ve `worker` altında kapatılan bir araç hala eşleşir, bu iç içe çok aracılı çalıştırmaların gerçekten yaptığı şeydir.
</Warning>

## Framework adaptörleri

```ts
await failproofai.instrument();              // bulabildiği her şey
await failproofai.instrument("langchain");   // tam olarak bir tane
failproofai.uninstrument();                  // her şeyi geri koy
```

| Framework | Desteklenen | Nasıl bağlanır |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, yani her `invoke`/`stream`/`batch` hiçbir yerde `callbacks:` geçirmeden kapsanır — veya `langchainHandler()` kendini geçin ve hiçbir şeyi yama yapmayın. |
| **Vercel AI SDK** | `ai` 4 – 7 | Çağrı sitesinde `telemetry()` veya tüm işlem için `instrument("ai")` — `ai` 7'de (4–6'da bu devre dışı seçenek — aşağıya bakın). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, aracının model ve araç çözümü ve iş akışı çalıştırma/adım motoru. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (abone) artı `AgentWorkflow.runStream`, iş akışı çalıştırmaları ve adımları için. |

Her aralık, her CI çalıştırmasında, her iki uçta da, ES modülü ve CommonJS olarak gerçek framework sürümlerine karşı test edilir.

Eşleme Python SDK'sının eşlemesidir, bu nedenle aynı program her iki dilde aynı ağacı çizer. Bir yapı, bir LLM karar döngüsüne sahipse **aracı** — bir grafik veya zincir çalıştırması, bir AI SDK `generateText`/`streamText` çağrısı, Mastra aracısı, LlamaIndex aracısı çalıştırması. Bir LangGraph düğümü veya iş akışı adımı **kanca** (`hook_triggered`/`hook_completed`), asla iç içe aracı değil. Model çağrıları, belirteç sayılarıyla birlikte `model_request`/`model_response` çiftleridir; araç çağrıları modelin kendi araç çağrısı kimliğini taşır. Bir başarısızlık meydana geldiği olayda bir kez kaydedilir.

Kurulması başarısız olan bir adaptör günlüğe kaydedilir ve atlanır; diğerleri yine de kurulur, çünkü kırılmış bir LlamaIndex size LangGraph'ı mal etmemeli.

<Note>
  Bağımsız değişken olmadan `instrument()` bir framework'ü zaten içe aktarılıp aktarılmadığına göre değil, **çözülüp çözülmediğine** göre algılar — Node ES modülleri için Python'ın `sys.modules` eşdeğeri sunar. Yüklü ama kullanmayan bir framework içe aktarılır ve yama yapılır. İstediğinizi adlandırın, eğer bu önemliyse.
</Note>

<Note>
  Bu framework'lerin çoğu bir ES modül yapısı ve Node'un iki ilişkisiz kopya olarak yüklediği bir CommonJS yapısı gönderir. Adaptörler uygulamanızın yüklediği kopyaya yama yapar (ve bir şey zaten `require` ettiyse CommonJS kopyasına da), böylece her iki modül sistemi çalışır. Bir framework **esbuild veya webpack'e göre kendi çıktınıza paketlenir** ulaşılamaz — orada çağrı sitesi yardımcılarını kullanın: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### Yamalamadan LangChain

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

İşleyici `instrument()` ile veya olmadan çalışır ve asla çift kaydını yapmaz. `instrument("langchain")` `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` ve `captureLimit` alır, Python adaptörü yaptığı gibi; bir çağrıda `metadata: { failproofai_sdk_session_id }` o çağırma için oturumu seçer.

### Vercel AI SDK

AI SDK, bir ES modülünden düz işlevleri dışa aktarır ve bir ES modülü ad alanı belirtim tarafından değişmez — yamanacak hiçbir yer yoktur. SDK'nın kendisinin belgelediği uzantı noktalarını kullanır:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // ai 7'de, `telemetry: telemetry({ … })` — aynı nesne, yeni ad
});
```

Bu tüm entegrasyon: bir aracı aralığı, adım başına belirteç sayılarıyla bir model istek/yanıt çifti ve her araç çağrısı. Bir çağrı sitesi her majöre çalışır — `ai` 4–6 taşıdığı iz okur, `ai` 7 telemetri tümleştirmesi.

`instrument("ai")` **`ai` 7'de** aynı işlemi tüm işlem için yapar: AI SDK'nın global telemetri tümleştirme listesi, katkı yönlü ve kimse başkasından hiçbir şey almayan her çağrı.

**`ai` 4–6'da, `instrument("ai")` kendisi tarafından hiçbir şey kaydetmez ve bunun söyleyen bir uyarı günlüğe kaydeder.** Bu majörlerin sahip olduğu tek işlem çapında kanca, küresel OpenTelemetry iz sağlayıcısı — bir kez alındıktan sonra OpenTelemetry'nin teslim etmeyi reddettiği tek yuva. Bizim kaydetmek daha sonra başlangıçta sizin kendi `NodeSDK.start()` öğenizi sessizce reddedecek ve http/database aralıklarınızı hiçbir şey dışa aktarmayan bir izleyiciye gönderecektir. Çağrı sitesinde `telemetry()` kullanın veya orada `wrapModel`. İşlem kendi OpenTelemetry'sini çalıştırmıyorsa, `instrument("ai", { registerGlobalTracer: true })` ile devre dışı seçeneği açın: ardından `experimental_telemetry: { isEnabled: true }` geçen her çağrıyı kaydeder ve yalnızca hala boşsa yuvasını alır. `registerGlobalTracer: false` varsayılanı korur ve uyarıyı kaldırır.

Modeli bir kez sarmalamayı tercih ederseniz, `wrapModel` yalnızca model çağrılarını görür, çünkü araç çağrıları model katmanının üzerinde olur. Etrafında hiçbir şey ile sarmalanan bir model kendi çalıştırması olarak kaydedilir. Akışlı bir çağrı akışın nasıl durduğuna bağlı olarak kapanır — tüketici iptal ettiğinde `stop_reason: "cancelled"`, yarı yolda başarısız olduğunda `"error"` hatasıyla:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Her ikisini kullanmak iyidir: ara yazılım çağrının zaten kaydedildiğini fark eder ve erteler, bu nedenle her çağrı bir kez kaydedilir.

`functionId` aracı aralığını adlandırır. Düşük kardinalite tutun — birincil pano faset olan `agent_id` olarak iniş yapar.

### Next.js

`next build` sunucunuzun bağımlılıklarını varsayılan olarak paketler ve yapının içine paketlenen bir framework, `instrument()` ulaşamadığı bir kopyasıdır. Yapılandırmayı bir kez sarmalayın ve Next'in başlangıç kancasından `instrument()` çağırın:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` LangChain, Mastra, LlamaIndex ve SDK'nın kendisini `serverExternalPackages` öğesine ekler, sizin listesini korur. Bunu yapmazsanız, `instrument()` sessizce başarısız olmak yerine ulaşamadığı framework başına bir kez uyarır; paketleri kendiniz listelerseniz `FAILPROOFAI_NEXT_EXTERNALS=1` ayarlayın. Vercel AI SDK ve çağrı sitesi yardımcıları her iki şekilde de çalışır. Bir Edge rotası no-op yapısı alır: SDK'yı içe aktarmak güvenlidir ve hiçbir şey kaydetmez.

### Akışlı çağrılar üzerinde belirteç sayıları

OpenAI uyumlu API'ler, istemci sorduğunda bir akışta kullanımı yalnızca bildirir. LangChain ve Vercel AI SDK sordu; LlamaIndex için `additionalChatOptions: { stream_options: { include_usage: true } }` öğesini kendi `OpenAI` LLM'sine geçirin ve Mastra için modeli kullanım etkin olarak oluşturun (örneğin `createOpenAICompatible({ includeUsage: true })`). Aksi takdirde akışlı model çağrıları belirteç sayısı taşımaz.

### Çalışma zamanları

Node ≥ 20.9, Bun ve Deno — her framework, bir ES modülü ve CommonJS olarak her bireyde Node'un izine karşı test edilir. SDK, yazanları gönderen `failproofaid` daemon'ı yanında çalışır.

## Kendi aracınız — framework yok

Kendiniz yazdığınız bir aracı döngüsü veya adaptörü olmayan bir framework için. Olayları adaptörlerin altında kullandığı aynı API ile yayımlarsınız, bu nedenle iz aynı şekil ve kaliteye sahip.

Aracının nasıl organize edildiğini bilmeniz gerekmez. Fonksiyonları ne denirse densin, elde derlenen her aracının zaten üç yeri vardır ve bu üçü tüm entegrasyondur:

| Nerede | Ne eklenecek | Yayınlar |
| --- | --- | --- |
| Burada **bir çalıştırma** başlar ve biter | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| Modeli çağıran **tek işlev** | `event.modelRequest` önce, `event.modelResponse` sonra — başarısızlıkta da her iki yarı | model dönüşü başına bir çift |
| Araçları çalıştıran **tek işlev** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Kimlik ortam ortamı: `agent()` içindeki her şey bir kimlik almadan o çalıştırmanın oturumuna iniş yapar ve programdaki başka hiçbir şey değişmez — aracının zaten kendi veritabanına yazdığı da dahil.

- **Bir hizmet veya işçi:** kendi istek veya iş kimliğini `sessionId` olarak geçin, böylece panodaki bir oturum ve kendi günlüklerinizde veya veritabanınızda kayıt aynı dizedir.
- **Alt aracılar:** `agent()` çağrılarını iç içe yerleştirin. İç, dış oturuma `parent_id` olarak katılır.
- **Çiftleri yayınlayın.** Modelresponse `olmayan bir `modelRequest`, panonun sonsuza kadar çalışıyor olarak gösterdiği bir aralık — dolayısıyla `catch`.

Deponun [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts), tam, çalıştırılabilir sürümüdür: gerçek OpenAI aracı döngüsü tam olarak bu şekilde enstrümente edilmiş, her değişiklikte CI'da ES modülü ve CommonJS olarak çalıştırılır.

## Değerlendirmeler

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Protokol, işçi ayarları ve sonuç türleri için [Değerlendirici SDK başvurusuna](/tr/reference/evaluator-sdk) bakın.

<Warning>
  **Bir değerlendirme vermelidir.** Hiçbir zaman döndürmeyen senkron bir işlev Node'un sahip olduğu tek iş parçacığını engeller ve hiçbir zaman timeout ateşleyemez. `async` değerlendirmeler yazın.
</Warning>

## İşleminize ne yapmayacağı

| | |
| --- | --- |
| **Aracı döngünüzü engelle** | Olaylar hafızadaki kuyruğa gider; bir zamanlayıcı onları yazar. Zamanlayıcı `unref`'lenmiştir, bu nedenle bu paketi içe aktarmak hiçbir zaman komut dosyasını çıkıştan durdurur. |
| **Sınırlar olmaksızın büyü** | Kuyruk sayıya **ve** ölçülen baytlara göre kapatılır. Her biri geçtikten sonra, en eski olaylar atılır ve bir uyarı bunu söyler — telemetri kesintisi OOM öldürmesi olmamalı. |
| **İşlemi aşağı al** | Kodlanmayan bir olay yalnız bırakılır, etrafındaki toplu değil. Atma getter, döngüsel referans, `BigInt`, yalnız vekil: her birine ele alınır, yayılmaz. |
| **Yarı yazılı toplu bırak** | İçerik `fsync`'lenmiştir; atomik yeniden adlandırmadan ve dizin `fsync`'lenmiştir sonra ve başarısız yazma geçici dosyasını temizler. |
| **Transkriptleri okunabilir bırak** | Toplu işler `0600` içindedir bir `0700` dizin. Hedefler, istemler, araç argümanları ve araç çıktısı taşırlar. |
| **Kimlik bilgilerine gemi** | API anahtarları, belirteçler, JWT'ler, taşıyıcı başlıkları ve gizli şekilli atamalar, baytlar diske ulaşmadan önce redakte edilir. Daemon, yükleme yapılmadan önce tekrar redakte eder. |
