## Kurulum

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Framework adaptörleri paketin kendisinde gelir. Frameworkler **isteğe bağlı eş bağımlılıklardır** — desteklenen aralıklar görülsün diye beyan edilirler, asla sizin adınıza kurulmazlar ve sadece `instrument()` çağrısında içe aktarılırlar.

## Failproof daemon'ı bağlayın

Python SDK'sı ile aynıdır: **Admin → Keys** altında bir `events:add` anahtarı oluşturun, ardından [daemon'ı bağlayın](/tr/start/setup#connect-a-machine-to-cloud) ajan makinesinde. SDK diske yazar; daemon sevk eder.

## Yapılandırma

### OpenTelemetry span'ları (opt-in)

OpenTelemetry'yi ayrı olarak `npm install @opentelemetry/api @opentelemetry/sdk-trace-base` ile kurun.
Ardından FailproofAI'ı sağlayıcınızın işlemcilerine ekleyin:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Mevcut bir sağlayıcı için, diğer işlemcilerini aynı listede tutun. `addSpanProcessor` ortaya çıkaran sağlayıcılar bunun yerine `{ provider }` olarak geçirilebilir. Seçeneksiz, kurulum sadece bir sağlayıcı zaten kaydedilmişse yeni bir sağlayıcı kaydeder.
`OtelSpanExporter` kendi işlemcinizle doğrudan da kullanılabilir.

Dışarıya aktarmalar bağlı Failproof AI daemon'u üzerinden gider; SDK ağ istekleri göndermez ve anahtar veya yerel dinleyici gerektirmez. Bir yöneticiye [OpenTelemetry ingest](/tr/agenteye/opentelemetry) etkinleştirmesini söyleyin. Basit bir `instrument()` bu dışarıya aktarıcıyı etkinleştirmez. `uninstrument("otel")` sadece kendi işlemcisini devre dışı bırakır. Span öznitelikleriniz içerik yakalamayı kontrol eder; çıkıştan önce sağlayıcınızı temizleyin. OpenTelemetry isteğe bağlı bir uygulama bağımlılığı kalır, sabit bir SDK bağımlılığı değil.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Seçenek | Ne yaptığı |
| --- | --- |
| `environment` | Her olayın etiketi — `production`, `staging`, `prod-eu`. Varsayılan olarak `dev`. |
| `flushInterval` | Zamanlayıcının ne sıklıkta diske yazacağı, saniyeler cinsinden. Varsayılan olarak `0.5`. |
| `baseDir` | Nereye yazılacağı. Varsayılan olarak daemon'un spool'u, aksi takdirde bilmiyorsanız istediğiniz şeydir. |

Tümü doğrulandı mı diye hiçbir şey uygulanmaz, bu yüzden reddedilen bir çağrı SDK'yı tam olarak yeni bir `baseDir` ve eski aralığı olan şekilde bırakır.

Bunun yerine ortam değişkeni tarafından ayarlayın:

| Değişken | Ne yaptığı |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Kod değişikliği yapmadan `environment` ayarlar. Bir `configure()` seçeneği bunu geçersiz kılar. |
| `FAILPROOFAI_HOME` | Spool'u tutan Failproof AI kökünü taşır. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (varsayılan), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` enstrümantasyon hatalarının kayıt yerine fırlatılmasını sağlar. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` framework uyumluluğu sorununu uyarı vermek ve devam etmek yerine fırlatılmasını sağlar. |

<Warning>
  **`environment`'te virgül yok.** İçe aktarma bu alanı virgüllere bölerek filtrelerini oluşturur ve herhangi bir içeren olayı atlar — bu yüzden tüm bir çalıştırma sessizce ortadan kaybolur. `prod,eu` değil `prod-eu` yazın.

  `configure({ environment: "prod,eu" })` hemen öğrenmeniz için fırlatır. `AGENTEYE_ENVIRONMENT` fırlataması mümkün değildir — hiç kimse sizi çağırmıyor — bu yüzden bir kez uyarır ve `dev` olarak geri döner.
</Warning>

SDK'nın kendi günlük satırlarını `failproofai.setLogger({ debug, info, warn, error })` ile günlükçünüze yönlendirin.

## Kapatma

Arabelleğe alınan olaylar `process.on("exit")` üzerinde temizlenir.

Bir sinyal tarafından öldürülen işlem asla oraya ulaşmaz ve Node'un `SIGTERM` için varsayılanı çıkış işleyicileri çalıştırmadan sonlandırmaktır — bu yüzden konteynır haline getirilmiş bir ajan son aralığın yazmadığı her şeyi kaybeder.

<Warning>
  **Bu SDK sizin için sinyal işleyicisi kurmayacak.** Birinin kaydedilmesi işleminizin davranışını değiştirir: bir dinleyici Node'un varsayılan sonlandırmasını bastırır, bu yüzden bir kütüphane ekleyen bir işleyici Ctrl-C'nin çalışmayı sessizce durduracaktır. Kendi ekleyin:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Kısa ömürlü bir komut dosyası veya sunucusuz bir işleyici dönüştürülmeden önce `await failproofai.flush()` yapmalıdır — aralık tek başına teslimatı garanti etmez.

## Kimlik

Her olay bir oturum ve bir ajana aittir. **Kapsamlar her ikisini de doldurur**, bu yüzden nadiren geçersiniz:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId` veya `agentId` açıkça geçirmek hala çalışır ve kazanır. Biri de bağlı ne de geçilirse, çağrı Cloud'un sessizce atacağı bir olayı değil fırlatır.

<Note>
  Kimlik `AsyncLocalStorage` üzerinde sürülür. `await`, `.then()`, zamanlayıcılar ve kapsam içinde oluşturulan herhangi bir geri çağrıyı izler. Bir çalıştırma sırasında depolanan ve başka bir çalıştırma sırasında çağrılan bir geri çağrıyı izlemez — veya `worker_threads` sınırında teslim edilen çalışmayı - bunları `failproofai.propagate()` ile sarın veya olaylar bağlantısız karar verir.
</Note>

### Kapsamlar

| Kapsam | Yayınlar | Döndürür |
| --- | --- | --- |
| `session(body)` | hiçbir şey — sadece kimlik | `body` ne döndürürse |
| `agent(id, options?, body)` | `agent_start`, sonra `agent_end` | `body` ne döndürürse |
| `toolCall(name, options?, body)` | `tool_use`, sonra `tool_result` | `body` ne döndürürse |

Eşzamanlı bir gövde eşzamanlı kalır: `agent("x", () => 1)` bir söz değil `1` döndürür.

`toolCall` gövdenin çözülmüş değerini aracının `output` olarak kaydeder, siz `call.output` atamadıkça.

<Accordion title="Çıkış semantiği" icon="arrow-right-from-bracket">

| Ne oldu | Olaylar | `outcome` |
| --- | --- | --- |
| blok döndü | `agent_end` | `"success"` veya sizin `outcome` |
| blok fırlatıldı | `error`, sonra `agent_end` | `"failed"` |
| bir `AbortError` | sadece `agent_end` | `"cancelled"` |

Hata her zaman yeniden fırlatılır.

Bir araç hatası yaprakta kaydedilir — `tool_result` bir `error` dizesi ile — ve run düzeyinde **hiçbir** `error` olayı yayınlamaz. Ajan döngüsünün yakalaması bir çalıştırma hatası değildir ve yayılması tam olarak bir kez kapsayan `agent()` tarafından rapor edilir.

</Accordion>

<Accordion title="`using` formu" icon="brackets-curly">

Çalışmanın tek bir işlev olmadığında — bir oluşturucuda açılan ve bir temizlemede kapatılan bir kapsam veya mevcut kontrol akışını geçen bir kapsam:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

Her iki form bayt-aynı olaylar yayınlar. Geri çağrı formunu tercih edin: `AsyncLocalStorage.run()` içinde çalışır, bu yüzden geri açılacak hiçbir şey yoktur ve "burada açılmış, orada kapatılmış" hatalarının tüm sınıfı ulaşılamaz.

Kendi başarısızlığını yakalan bir `using` bloğu bunu `span.fail(error)` ile rapor eder — dağıtıcının kendi istisna kanalı yoktur.

</Accordion>

## Olay kataloğu

Python SDK'sı ile aynı on beş metod, camelCase'de. Çoğu **çiftler** halinde gelir — açıcıyı çağırır, sonra kapatıcıyı, ve SDK aralığı zamanlar.

| | Açar | Kapar |
| --- | --- | --- |
| **Ajanlar** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Modeller** | `modelRequest` | `modelResponse` |
| **Araçlar** | `toolUse` | `toolResult` |
| **Kancalar** | `hookTriggered` | `hookCompleted` |
| **İnsanlar** | `humanWait` | `humanInput` |

Üçü tek başına dur: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Her metod başına her alan" icon="table">

Her metod `sessionId` ve `agentId` de alır, kapsamlar bunları sizin için doldurur. Atlanan her şey JSON `null` olarak gönderilmek yerine bırakılır.

| Metod | Gerekli | İsteğe bağlı |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Eklediğiniz diğer anahtar özel bir yük alanı olur. Framework-spesifik her şeyi `fw_*` ile ad alanına alın; beyan edilen bir alanla çarpışan bir ad sessizce bir yükseltilmiş sütunun üzerine yazılmak yerine reddedilir.

</Accordion>

<Warning>
  **`duration_ms` hesaplanır, kabul edilmez.** Dört kapatma yöntemi açıcısından aralığı zamanlar ve arayanın sağladığı `duration_ms` reddeder — rapor edilen bir süre yanlışlanamaz.

  Çiftler **oturum** ve kimlikten eşleştirilir, ajandan asla. Bir araç `planner` altında açılmış ve `worker` altında kapatılmış yine de eşleşir, bu da iç içe çok ajanlı çalıştırmaların aslında ne yaptığıdır.
</Warning>

## Framework adaptörleri

```ts
await failproofai.instrument();              // bulabildiği her şey
await failproofai.instrument("langchain");   // tam olarak bir
failproofai.uninstrument();                  // her şeyi geri koyun
```

| Framework | Desteklenir | Nasıl bağlanır |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, bu yüzden her `invoke`/`stream`/`batch` hiçbir yere `callbacks:` geçirmeden kaplanır — veya `langchainHandler()` kendiniz geçirin ve hiçbir şeyi yamalayın. |
| **Vercel AI SDK** | `ai` 4 – 7 | Çağrı sitesinde `telemetry()` veya `ai` 7'de işlem boyunca `instrument("ai")` (4–6'da bu opt-in — aşağıya bakın). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, ajanın model ve araç çözümlemesi ve iş akışı çalıştırma/adım motoru. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (abone) artı `AgentWorkflow.runStream`, iş akışı çalıştırmaları ve adımları için. |

Her aralık gerçek framework yayınlarına karşı test edilir, her iki ucunda, ES modülü ve CommonJS olarak, her CI çalıştırmasında.

Haritalandırma Python SDK'sı olanıdır, bu yüzden aynı program her iki dilde de aynı ağacı çizer. Bir yapı sadece bir LLM karar döngüsüne sahipse bir **ajan** olandır — bir grafik veya zincir çalıştırma, bir AI SDK `generateText`/`streamText` çağrısı, bir Mastra ajanı, bir LlamaIndex ajan çalıştırması. Bir LangGraph düğümü veya iş akışı adımı bir **kanca**dır (`hook_triggered`/`hook_completed`), asla iç içe bir ajan değildir. Model çağrıları `model_request`/`model_response` çiftleridir belirteç sayılarıyla; araç çağrıları modelin kendi araç çağrısı kimliğini taşır. Bir başarısızlık olduğu olayda bir kez kaydedilir.

Yüklemeyi başarısız olan bir adaptör kaydedilir ve atlanır; diğerleri yine de yüklenir, çünkü bozuk bir LlamaIndex LangGraph'a mal olmamalıdır.

<Note>
  Bağımsız değişkensiz `instrument()` bir framework'ü zaten içe aktarılıp aktarılmadığına göre değil **çözümlenmesine** göre algılar — Node ES modülleri için Python'un `sys.modules`'ine eşdeğer bir şey göstermez. Kurulu ama kullanmadığınız bir framework içe aktarılacak ve yamalanacaktır. İstediğiniz olanı adı verin bunun önemli olması durumunda.
</Note>

<Note>
  Bu çerçevelerin çoğu bir ES modülü yapısı ve bir CommonJS yapısı gönderir, bu da Node ikisini ilgisiz kopyalar olarak yükler. Adaptörler uygulamanızın yüklediği kopyayı (ve bir şey zaten `require` etmişse CommonJS kopyasını da) yamalandırır, bu yüzden her iki modül sistemi çalışır. esbuild veya webpack tarafından kendi çıktınızın **içine paketlenmiş** bir framework ulaşılamaz — orada çağrı sitesi yardımcılarını kullanın: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### Yamalamadan LangChain

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

İşleyici `instrument()` ile veya onun olmadığı şekilde çalışır ve asla iki kez kaydı tutmaz. `instrument("langchain")` `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` ve `captureLimit` alır, Python adaptörü yapar; çağrı üzerine `metadata: { failproofai_sdk_session_id }` o çağrı için oturumu seçer.

### Vercel AI SDK

AI SDK'sı düz işlevleri bir ES modülünden dışa aktarır ve bir ES modülü ad alanı belirtim tarafından değişmez — yamalanacak bir yer yoktur. Belgelediği uzantı noktalarını kullanır:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // ai 7'de, `telemetry: telemetry({ … })` — aynı nesne, yeni ad
});
```

Bu tam entegrasyon: bir ajan span'ı, adım başına belirteç sayılarıyla bir model istek/yanıt çifti ve her araç çağrısı. Bir çağrı sitesi her büyüğe çalışır — `ai` 4–6 taşıdığı izleyiciyi okur, `ai` 7 telemetri entegrasyonunu.

`instrument("ai")` aynı işlemi **`ai` 7'de** yönetir: her çağrı, AI SDK'sının küresel telemetri entegrasyonu listesi aracılığıyla, katkı niteliğinde ve kimsenin başkasından hiçbir şey almaz.

**`ai` 4–6'da, `instrument("ai")` kendisi tarafından hiçbir şey kaydetmez ve bunun böyle olduğunu söyleyen bir uyarıyı kaydeder.** Bu büyüklüklerin sahip olduğu tek işlem genelinde kanca küresel OpenTelemetry izleyici sağlayıcısıdır — OpenTelemetry alındıktan sonra teslim etmeyi reddeder tek bir yuva. Bizimki kaydeden, daha sonra başlangıçta sizin `NodeSDK.start()` öğelerinizi sessizce reddedecek ve http/veritabanı span'larınızı hiçbir şey dışa aktarmayan bir izleyiciye gönderecektir. Çağrı sitesinde `telemetry()` kullanın veya orada `wrapModel`. İşlem kendi OpenTelemetry'si çalıştırmazsa, `instrument("ai", { registerGlobalTracer: true })` ile opt-in: daha sonra `experimental_telemetry: { isEnabled: true }` geçiren her çağrıyı kaydeder ve sadece hala boşsa yuva alır. `registerGlobalTracer: false` varsayılanı tutar ve uyarıyı susturur.

Modeli bir kez sarmalamayı tercih ederseniz, `wrapModel` sadece model çağrılarını görür, çünkü araç çağrıları model katmanının üstünde gerçekleşir. Hiçbir şey etrafında çağrılan sarılı bir model kendi çalıştırması olarak kaydedilir. Akan bir çağrı akış nasıl durduğu — `stop_reason: "cancelled"` tüketicisi iptal ettiğinde, `"error"` yarı yolda başarısız olduğunda hata ile kapatılır:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Her ikisini de kullanmak iyidir: ara yazılım çağrının zaten kaydedilmekte olduğunu fark eder ve erteler, bu yüzden her çağrı bir kez kaydedilir.

`functionId` ajan span'ını adlandırır. Düşük kardinaliteyi tutun — birincil pano yüzü olan `agent_id`'ye iner.

### Next.js

`next build` varsayılan olarak sunucunuzun bağımlılıklarını paketler ve yapıya paketlenmiş bir framework `instrument()` ulaşamayan bir kopyadır. Yapılandırmayı bir kez sarmalayın ve Next'in başlangıç kancasından `instrument()` çağırın:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` LangChain, Mastra, LlamaIndex ve SDK'yı `serverExternalPackages`'e ekler, sizin listenizi tutar. Onsuz, `instrument()` sessizce başarısız olmak yerine her framework'ü uyarır ulaşamadığını; paketleri kendiniz listelediyseniz, `FAILPROOFAI_NEXT_EXTERNALS=1` ayarlayın. Vercel AI SDK ve çağrı sitesi yardımcıları her iki şekilde de çalışır. Bir Edge rotası yapı yok eder: SDK'yı içe aktarmak güvenlidir ve hiçbir şey kaydetmez.

### Akan çağrılar üzerine belirteç sayıları

OpenAI-uyumlu API'ler sadece istemci istediğinde akışta kullanımı raporlar. LangChain ve Vercel AI SDK ister; LlamaIndex için `additionalChatOptions: { stream_options: { include_usage: true } }` geçirin onun `OpenAI` LLM'sine ve Mastra için modeli kullanım etkinleştirilmiş şekilde oluşturun (örneğin `createOpenAICompatible({ includeUsage: true })`). Aksi takdirde akan model çağrıları belirteç sayıları taşımaz.

### Çalışma zamanları

Node ≥ 20.9, Bun ve Deno — her framework, ES modülü ve CommonJS olarak, her birine karşı Node'un izinde test edilir. SDK `failproofaid` daemon'u yanında çalışır, hangi yazarsa onu sevk eder.

## Kendi ajanınız — framework yok

Yazmanız gereken bir ajan döngüsü için veya adaptörü olmayan bir framework. Olayları adaptörlerin altında kullandığı aynı API ile yayınlarsınız, bu yüzden iz aynı şekil ve kaliteye sahiptir.

Ajanın nasıl düzenlendiğini bilmeniz gerekmez. El yapımı her ajan zaten üç yeri var, işlevleri ne denir olursa olsun ve bu üçü entegrasyon tamamıdır:

| Nerede | Ne eklenecek | Yayınlar |
| --- | --- | --- |
| **Bir çalıştırma** başladığı ve bittiği yer | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Modeli çağıran işlev** | `event.modelRequest` önce, `event.modelResponse` sonra — başarısız olsa da her iki yarı | model dönüşü başına bir çift |
| **Araçları çalıştıran işlev** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Kimlik ortam: `agent()` içinde her şey o çalıştırmanın oturumunda kimlik almadan iner ve programda başka hiçbir şey değişmez — ajan zaten kendi veritabanına yazdığı her şey de dahil olmak üzere.

- **Hizmet veya işçi:** kendi istek veya iş kimliğini `sessionId` olarak geçirin, bu yüzden panodaki bir oturum ve kendi günlüklerinizde veya veritabanında kayıt aynı dizedir.
- **Alt ajanlar:** `agent()` çağrılarını iç içe geçirin. İçer dış ile aynı oturuma katılır `parent_id` olarak.
- **Çiftleri yayınlar.** Hiçbir `modelResponse` olmayan bir `modelRequest` pano çalışıyor olarak gösterdiği bir span'dır — bu yüzden `catch`.

Depo içinde [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) tam, çalıştırılabilir versiyondur: gerçek bir OpenAI araç döngüsü tam olarak bunun gibi enstrümante edilmiş, her değişiklikte CI'de ES modülü ve CommonJS olarak çalıştırılmış.

## Değerlendirmeler

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Protokol, işçi ayarları ve sonuç türleri için [Evaluator SDK referansı](/tr/reference/evaluator-sdk) görmek.

<Warning>
  **Bir değerlendirme vermelidir.** Asla döndürmeyen eşzamanlı bir işlev Node'un sahip olduğu bir iş parçacığını engeller ve hiçbir zaman çıkış işleyicileri sırasında başa çıkamaz. `async` değerlendirmeler yazın.
</Warning>

## İşleminize ne yapmayacağı

| | |
| --- | --- |
| **Ajan döngünüzü engelle** | Olaylar bellek içi sıraya girer; bir zamanlayıcı onları yazar. Zamanlayıcı `unref`'lenmiş, bu yüzden bu paketi içe aktarmak hiç zaman bir komut dosyasının çıkışını durdurmaz. |
| **Sınır olmaksızın büyü** | Sıra sayı *ve* ölçülen bayt cinsinden kapılır. Bir aşıldığında, en eski olaylar atılır ve bir uyarı söyleş — telemetri kesintisi OOM kılı haline gelmemelidir. |
| **İşlemi yıkıl** | Bir kodlanamayan olay tek başına atılır, etrafındaki toplu iş değil. Fırlatılmayan bir alıcı, dairesel bir başvuru, bir `BigInt`, tek bir vekil: her birine muamele edilir ve yayılmaz. |
| **Yarı yazılmış bir toplu iş bırak** | İçerik `fsync`'len bir atomik adlandırmadan önce, dizin adlandırmadan sonra `fsync`'len ve başarısız bir yazma geçici dosyasını temizler. |
| **Yazıların okunabilir bırakılır** | Toplu iş `0600` bir `0700` dizinin içine. Hedefler, istemler, araç argümanları ve araç çıktısı taşırlar. |
| **Kimlik bilgileri gemi** | API anahtarları, belirteçler, JWT'ler, taşıyıcı üstbilgiler ve gizli şekilli atamalar baytlar diske ulaşmadan önce redakte edilir. Daemon yükleme öncesinde yeniden redakte eder. |
