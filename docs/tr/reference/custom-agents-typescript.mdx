## Yükleme

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Framework adaptörleri paketin içinde gönderilir. Framework'ler **isteğe bağlı eş bağımlılıklardır** — desteklenen aralıklar görünür olacak şekilde bildirilir, sizin adınıza asla yüklenmez ve yalnızca `instrument()` çağırdığınızda içe aktarılır.

## Failproof daemon'a bağlanın

Python SDK ile özdeş: **Admin → Keys** altında bir `events:add` anahtarı oluşturun, ardından [daemon'a bağlayın](/tr/start/setup#connect-a-machine-to-cloud) ajan makinesinde. SDK diske yazar; daemon gönderir.

## Konfigürasyon

### OpenTelemetry span'ları (opt-in)

OpenTelemetry'yi `npm install @opentelemetry/api @opentelemetry/sdk-trace-base` ile ayrı olarak yükleyin.
Ardından FailproofAI'ı sağlayıcınızın işlemcilerine ekleyin:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Mevcut bir sağlayıcı için, diğer işlemcilerini aynı listede tutun. `addSpanProcessor` öğesini açığa çıkaran sağlayıcılar bunun yerine `{ provider }` olarak geçirilebilir. Seçenekler olmadan, kurulum yalnızca kayıtlı bir sağlayıcı yoksa yeni bir sağlayıcı kaydeder.
`OtelSpanExporter` kendi işlemcinizle doğrudan da kullanılabilir.

Dışa aktarmalar bağlantılı FailproofAI daemon'u üzerinden gider; SDK ağ istekleri göndermez ve anahtar veya yerel dinleyici gerekli değildir. Bir yönetici [OpenTelemetry alımını](/tr/agenteye/opentelemetry) etkinleştirmesini isteyin. Basit bir `instrument()` bu dışa aktarıcıyı etkinleştirmez. `uninstrument("otel")` yalnızca kendi işlemcisini devre dışı bırakır.
Span öznitelikleri içerik yakalamayı kontrol eder; çıkıştan önce sağlayıcınızı temizleyin.
OpenTelemetry isteğe bağlı bir uygulama bağımlılığı kalır, SDK bağımlılığı değil.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Seçenek | Yaptığı |
| --- | --- |
| `environment` | Her etkinlikteki etiket — `production`, `staging`, `prod-eu`. Varsayılan olarak `dev`. |
| `flushInterval` | Zamanlayıcının diske yazma sıklığı, saniye cinsinden. Varsayılan olarak `0.5`. |
| `baseDir` | Nereye yazacağı. Varsayılan olarak daemon'un spool'u, aksi halde bilmiyorsanız isteyeceğiniz şeydir. |

Hiçbir şey uygulanmaz, tümü doğrulanmadığı sürece, reddedilen bir çağrı SDK'yı tam olarak önceki durumda bırakır, yeni bir `baseDir` ve eski aralık ile değil.

Bunun yerine ortam değişkeni tarafından ayarlanır:

| Değişken | Yaptığı |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Kod değişikliği olmadan `environment` ayarlar. Bir `configure()` seçeneği bunu geçersiz kılar. |
| `FAILPROOFAI_HOME` | Spool'u tutan Failproof AI kökünü taşır. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (varsayılan), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` enstrümantasyon hatalarını günlüğe kaydedilmek yerine fırlatır. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` framework uyumluluk sorununu uyar ve devam etmek yerine fırlatır. |

<Warning>
  **`environment` içinde virgül yok.** Alım bu alanı virgülle bölür filtreleri oluşturmak için ve onu içeren herhangi bir etkinliği atlar — böylece tüm çalıştırma sessizce kaybolur. `prod,eu` değil `prod-eu` yazın.

  `configure({ environment: "prod,eu" })` hemen öğrenmeniz için fırlatır. `AGENTEYE_ENVIRONMENT` hata fırlatamazsa — hiç sizi çağırmıyor — bir kez uyarı verir ve `dev`'e geri döner.
</Warning>

SDK'nın kendi günlük satırlarını `failproofai.setLogger({ debug, info, warn, error })` ile günlükçünüze yönlendirin.

## Kapatma

Arabelleğe alınan etkinlikler `process.on("exit")` üzerinde temizlenir.

Bir sinyal tarafından öldürülen işlem asla buna ulaşmaz ve Node'un `SIGTERM` için varsayılanı, çıkış işleyicileri çalıştırmadan sonlandırmaktır — bu nedenle kapsayıcılı bir ajan, son aralığın yazılmamış olduğu şeyi kaybeder.

<Warning>
  **Bu SDK sizin için bir sinyal işleyicisi yüklemez.** Bir işleyici kaydetmek işleminizin davranışını değiştirir: bir dinleyici Node'un varsayılan sonlandırmasını bastırır, bu nedenle bir eklenmiş olan bir kitaplık Ctrl-C'nin çalışmasını sessizce durdururdu. Kendi şeyinizi ekleyin:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Kısa ömürlü bir betik veya sunucusuz işleyici, dönmeden önce `await failproofai.flush()` yapmalıdır — aralık tek başına teslimatı garanti etmez.

## Kimlik

Her etkinlik bir oturuma ve bir ajana aittir. **Kapsamlar her ikisini de doldurur**, bu nedenle nadiren geçirirsiniz:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

`sessionId` veya `agentId`'yi açıkça geçirmek hala işe yarar ve kazanır. İkisi bağlı veya geçirilmediyse, çağrı Cloud'un sessizce atacağı bir etkinlik yayınlamak yerine fırlatır.

<Note>
  Kimlik `AsyncLocalStorage` üzerinde gezintiler. `await`, `.then()`, zamanlayıcılar ve kapsamın içinde oluşturulan herhangi bir geri çağrıyı takip eder. Bir çalışma sırasında saklanan ve başka bir çalışma sırasında çağrılan bir geri çağrıyı, ya da bir `worker_threads` sınırı ötesine geçirilen işi **takip etmez** — bunları `failproofai.propagate()` içine sarın veya etkinlikleri ektesiz iner.
</Note>

### Kapsamlar

| Kapsam | Yayınlar | Döndürür |
| --- | --- | --- |
| `session(body)` | hiçbir şey — sadece kimlik | `body` ne döndürürse |
| `agent(id, options?, body)` | `agent_start`, sonra `agent_end` | `body` ne döndürürse |
| `toolCall(name, options?, body)` | `tool_use`, sonra `tool_result` | `body` ne döndürürse |

Senkron bir gövde senkron kalır: `agent("x", () => 1)` `1` döndürür, bir söz değil.

`toolCall` gövdenin çözülen değerini aracın `output` olarak kaydeder, aksi halde `call.output` kendinizi atamadığı sürece.

<Accordion title="Çıkış semantiği" icon="arrow-right-from-bracket">

| Ne oldu | Etkinlikler | `outcome` |
| --- | --- | --- |
| blok döndü | `agent_end` | `"success"`, veya sizin `outcome` |
| blok fırlatıldı | `error`, sonra `agent_end` | `"failed"` |
| bir `AbortError` | yalnızca `agent_end` | `"cancelled"` |

Hata her zaman yeniden fırlatılır.

Bir araç hatası yaprak üzerinde kaydedilir — `error` dizesi içeren `tool_result` — ve **hiçbir** çalıştırma düzeyi `error` etkinliği yayınlamaz. Ajan döngüsünün yakaladığı bir şey bir çalışma hatası değildir ve yayılan bir şey tam olarak bir kez, çevreleyen `agent()` tarafından bildirilir.

</Accordion>

<Accordion title="The `using` formu" icon="brackets-curly">

İş tek bir işlev olmadığında — bir kapsam bir kurucu içinde açılmış ve bir yıkımda kapatılmış, ya da mevcut kontrol akışını kesen bir kapsam:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, sonra agent_end
```

Her iki form de bayt-özdeş etkinlikleri yayınlar. Geri çağrı formunu tercih edin: `AsyncLocalStorage.run()` içinde çalışır, bu nedenle çözülecek hiçbir şey yoktur ve "burada açıldı, orada kapatıldı" hatalarının tüm sınıfı erişilmez.

Kendi hatası yakalayan bir `using` bloku `span.fail(error)` ile bildirir — disposer'ın kendi istisna kanalı yoktur.

</Accordion>

## Etkinlik kataloğu

Python SDK ile aynı on beş metod, camelCase'de. Çoğu **çiftler** halinde gelir — açıcısını çağırırsınız, sonra kapatıcısını, ve SDK boşluğu zamanlar.

| | Açar | Kapatır |
| --- | --- | --- |
| **Ajanlar** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Modeller** | `modelRequest` | `modelResponse` |
| **Araçlar** | `toolUse` | `toolResult` |
| **Kancalar** | `hookTriggered` | `hookCompleted` |
| **İnsanlar** | `humanWait` | `humanInput` |

Üç tek başına: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Her metod için her alan" icon="table">

Her metod `sessionId` ve `agentId`'yi de alır, hangileri kapsamlar sizin için doldurur. Atlanmış olan her şey JSON `null` olarak gönderilmek yerine bırakılır.

| Metod | Gerekli | İsteğe bağlı |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Eklediğiniz başka anahtar, özel yük alanı olur. Framework'e özgü `fw_*` olarak namespace'i yapın; bildirilen bir alanla çarpışan bir ad, sessizce tanıtılan sütunu üzerine yazmasına izin vermek yerine reddedilir.

</Accordion>

<Warning>
  **`duration_ms` hesaplanmıştır, kabul edilmemiştir.** Dört kapatan metod açıcısından boşluğu zamanlar ve çağıran tarafından sağlanan `duration_ms` hatasına — bildirilen bir süre yanlışlanabilir.

  Çiftler **oturumda** ve kimlikte eşleştirilir, ajanda asla. Bir araç `planner` altında açılmış ve `worker` altında kapatılmış hala eşleşir, bu da iç içe çok ajanlar çalıştırmaların gerçekte yaptığıdır.
</Warning>

## Framework adaptörleri

```ts
await failproofai.instrument();              // bulunan her şey
await failproofai.instrument("langchain");   // tam olarak bir tane
failproofai.uninstrument();                  // her şeyi geri koyun
```

| Framework | Desteklenen | Nasıl bağlı |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, bu nedenle her `invoke`/`stream`/`batch` hiçbir yere `callbacks:` geçmeden kapsanır — veya `langchainHandler()` kendiniz geçirin ve hiçbir şeyi yamalamayın. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` çağrı sitesinde, veya `ai` 7 (4–6 üzerinde opt-in olup — aşağıya bakınız) üzerinde tüm işlem için `instrument("ai")`. |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, ajanın model ve araç çözümü ve iş akışı çalıştırma/adım motoru. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (abone olunmuş) artı `AgentWorkflow.runStream`, iş akışı çalıştırmaları ve adımları için. |

Her aralık gerçek framework yayınlarına karşı, her iki ucunda, ES modülü ve CommonJS olarak, her CI çalıştırmasında test edilir.

Eşleme Python SDK'ninkidir, bu nedenle aynı program her iki dilde aynı ağacı çizer. Bir yapı, bir LLM karar döngüsüne sahipse **ajandır** — bir grafik veya zincir çalıştırması, bir AI SDK `generateText`/`streamText` çağrısı, bir Mastra ajanı, bir LlamaIndex ajan çalıştırması. Bir LangGraph düğümü veya iş akışı adımı bir **kanca** (kanca`hook_triggered`/`hook_completed`), asla iç ajan değildir. Model çağrıları `model_request`/`model_response` çiftleridir token sayılarıyla; araç çağrıları modelin kendi araç çağrısı kimliğini taşır. Bir hata, olduğu etkinlikte bir kez kaydedilir.

Yükleme başarısız olan bir adaptör günlüğe kaydedilir ve atlanır; diğerleri hala yüklenir, çünkü bozuk bir LlamaIndex'in sizi LangGraph'ın hesabında olmaması gerekir.

<Note>
  Bağımsız değişken olmayan `instrument()` bir framework'ü zaten içe aktarılıp aktarılmadığına değil, çözülüp çözülmediğine göre algılar — Node ES modülleri için Python'un `sys.modules` eşdeğerini açığa çıkarmaz. Yüklediğiniz ancak kullanmadığınız bir framework içe aktarılacak ve yamalanacaktır. İstediğiniz olanı adlandırın eğer bu önemliyse.
</Note>

<Note>
  Bu framework'lerin çoğu ES modülü derlemesi ve CommonJS derlemesi gönderir, bu da Node'un iki ilişkisiz kopya olarak yükler. Adaptörler, uygulamanızın yüklediği kopyayı yamarlar (ve bir şey zaten `require` ediyorsa CommonJS kopyasını da), bu nedenle her iki modül sistemi de çalışır. Esbuild veya webpack tarafından kendi çıktınıza **paketlenmiş** bir framework erişilmez — çağrı sitesi yardımcılarını orada kullanın: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain yamalama olmadan

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

İşleyici, `instrument()` ile veya olmaksızın çalışır ve asla çift kayıt yapmaz. `instrument("langchain")` `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` ve `captureLimit`'i alır, Python adaptörü yaptığı gibi; bir çağrı üzerine `metadata: { failproofai_sdk_session_id }` bu çağrı için oturumu seçer.

### Vercel AI SDK

AI SDK düz işlevleri bir ES modülünden dışa aktarır ve bir ES modülü ad alanı belirtim tarafından değişmez — yamalanacak yer yok. Belirtim tarafından SDK'nın kendisinin belgelediği uzantı noktaları kullanır:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // ai 7'de, `telemetry: telemetry({ … })` — aynı nesne, yeni ad
});
```

Bu tam entegrasyon: bir ajan yayılması, adım başına token sayılarıyla bir model isteği/yanıt çifti ve her araç çağrısı. Bir çağrı sitesi her ana sürümde işe yarar — `ai` 4–6 taşıdığı izleyiciyi okur, `ai` 7 telemetri entegrasyonunu.

`instrument("ai")` **`ai` 7 üzerinde** aynı işlem genelinde yapar: her çağrı, AI SDK'nın genel telemetri entegrasyon listesi aracılığıyla, katkı maddesi ve başkasının hiçbir şeyini almaz.

**`ai` 4–6 üzerinde, `instrument("ai")` kendisi tarafından hiçbir şey kaydedilmez ve bunun söyleyen bir uyarı günlüğe kaydeder.** Bu ana sürümlerin sahip olduğu tek işlem genelinde kanca genel OpenTelemetry izleyici sağlayıcısıdır — OpenTelemetry'nin bir kez alındıktan sonra teslim etmeden kaçınamayacağı tek bir yuva. Bizim yükleme, daha sonra başlangıçta sizin kendi `NodeSDK.start()` sessizce reddedecek ve http/database yayılmalarınızı hiçbir şeyi dışa aktarmayan bir izleyiciye gönderecekti. Çağrı sitesinde `telemetry()` veya `wrapModel` kullanın. Işlem kendi OpenTelemetry'sini hiç çalıştırmıyorsa, `instrument("ai", { registerGlobalTracer: true })` ile opt-in yapın: o zaman `experimental_telemetry: { isEnabled: true }` geçen her çağrıyı kaydeder ve yalnızca yuva boş kalırsa alır. `registerGlobalTracer: false` varsayılanı tutar ve uyarıyı sessizleştirir.

Modeli bir kez sarlamayı tercih ederseniz, `wrapModel` yalnızca model çağrılarını görür, çünkü araç çağrıları model katmanının üstünde gerçekleşir. Çevresi hiçbir şey olmadan çağrılan sarılmış bir model kendi çalıştırması olarak kaydedilir. Akış durdurulduğunda akış — `stop_reason: "cancelled"` tüketici iptal ettiğinde, `"error"` yarı yolda başarısız olduğunda hata ile kapatır:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Her ikisini de kullanmak tamam: ara yazılım çağrının zaten kaydedildiğini fark eder ve erteler, böylece her çağrı bir kez kaydedilir.

`functionId` ajan yayılmasını adlandırır. Düşük kardinalitesi tutun — `agent_id` sabit pano fasetin bu gibi iner.

### Next.js

`next build` varsayılan olarak sunucunun bağımlılıklarını paketler ve yapıya paketlenmiş bir framework `instrument()` erişemez bir kopya. Konfigürasyonu bir kez sarın ve `instrument()` Next'in başlangıç kancasından çağırın:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` LangChain, Mastra, LlamaIndex ve SDK'nın kendisini `serverExternalPackages`'e ekler, kendi listenizi tutar. Olmadan, `instrument()` erişemediği her framework için sessizce başarısız olmak yerine bir kez uyarı verir; paketleri kendi listeleniz, `FAILPROOFAI_NEXT_EXTERNALS=1` ayarla. Vercel AI SDK ve çağrı sitesi yardımcıları her iki şekilde de çalışır. Kenar rotası bir no-op yapısı alır: SDK'yı içe aktarmak güvenlidir ve hiçbir şey kaydedilmez.

### Akış çağrılarında token sayıları

OpenAI uyumlu API'ler yalnızca istemci sorduğunda bir akışta kullanımı raporlarlar. LangChain ve Vercel AI SDK sorularlar; LlamaIndex için `additionalChatOptions: { stream_options: { include_usage: true } }` OpenAI LLM'sine geçirin ve Mastra için modeli kullanım etkin olarak oluşturun (örneğin `createOpenAICompatible({ includeUsage: true })`). Aksi halde akış model çağrıları hiçbir token sayısı taşımaz.

### Çalışma zamanları

Node ≥ 20.9, Bun ve Deno — her framework, ES modülü ve CommonJS olarak, Node'un izlemesine karşı her birinde test edilir. SDK `failproofaid` daemon yanında çalışır, bu da yazılan şeyi gönderir.

## Kendi ajanınız — framework yok

Yazdığınız bir ajan döngüsü veya adaptörsü olmayan bir framework için. Adaptörlerin altında kullandığı aynı API ile etkinlikleri yayırsınız, bu nedenle izleme aynı şekil ve kalitede.

Ajanın nasıl organize edildiğini bilmeniz gerekmez. Elle inşa edilmiş her ajan zaten üç yeri vardır, işlevleri ne çağırılırsa olsun ve bu üç tüm entegrasyondur:

| Nerede | Eklemek ne | Yayınlar |
| --- | --- | --- |
| **Bir çalıştırma** başladığı ve bittiği yerde | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| Modeli çağıran **tek işlev** | Başarısız olması üzere, `event.modelRequest` önce, `event.modelResponse` sonra — her iki yarım | çağrı başına bir çift model dönüşü |
| Araçları çalıştıran **tek işlev** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Kimlik ortamsal: `agent()` içindeki her şey oturumun çalıştırılmasında, kimlik almadan, ve programın hiçbir başka yerinde — ajan zaten kendi veritabanına yazdığı şey de dahil olmak üzere hiçbir şey değişmez.

- **Bir hizmet veya işçi:** kendi istek veya iş kimliğini `sessionId` olarak geçirin, pano üzerinde bir oturumda ve kendi günlüklerimizdeki veya veritabanındaki kayıt aynı dizedir.
- **Alt-ajanlar:** `agent()` çağrılarını iç içe geçirin. İç olanı oturumda dış birlikte `parent_id` olarak katılır.
- **Çiftleri yayınlayın.** Hiçbir `modelResponse` olmayan bir `modelRequest` göstergeyi panoda sonsuza kadar çalışan gösterir — dolayısıyla `catch`.

Depo'daki [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts), tam, çalıştırılabilir versiyondur: gerçek OpenAI araç döngüsü tam olarak böyle enstrümante edilmiş, her değişiklikteki CI'da ES modülü ve CommonJS olarak çalıştırılmış.

## Değerlendirmeler

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Protokol, işçi ayarları ve sonuç türleri için [Evaluator SDK başvurusu](/tr/reference/evaluator-sdk) öğesine bakın.

<Warning>
  **Değerlendirme öncesi getirmelidir.** Asla döndürmeyen senkron bir işlev, Node'un sahip olduğu tek iş parçacığını engeller ve hiçbir zaman aşırı zaman aşımı çıkamadığı sürece bunu yapar. `async` değerlendirmeler yazın.
</Warning>

## Sürecinizdeki davranış olmayacak

| | |
| --- | --- |
| **Ajan döngünüzü engelle** | Etkinlikler bellek içi sıraya gider; bir zamanlayıcı bunları yazar. Zamanlayıcı `unref`'lenmiştir, bu nedenle bu paketi içe aktarmak hiçbir zaman bir betiğin çıkmasını durdurulmaz. |
| **Sınır olmadan büyü** | Kuyruk sayıya *ve* ölçülen bayta göre kapatılır. Temiz ötesi, en eski etkinlikler atılır ve bir uyarı bunu söyler — telemetri kesintisi bir OOM talimatına dönüşmemeli. |
| **Süreci aşağı al** | Bir kodlanmaz etkinlik tek başına bırakılır, etrafındaki toplu değil. Fırlatılan alıcı, dairesel referans, `BigInt`, tek vekil: her biri yayılmak yerine işlenir. |
| **Yarı yazılı toplu bırak** | İçerik atomik yeniden adlandırmadan önce `fsync`ed, dizin sonra `fsync`ed, ve başarısız yazma geçici dosyasını temizler. |
| **Yazı okunabilir bırak** | Toplu `0600` bir `0700` dizini içinde. Hedefler, istemler, araç argümanları ve araç çıktısı taşırlar. |
| **Gemi kimlik bilgileri** | API anahtarları, jetonlar, JWT'ler, taşıyıcı başlıkları ve gizli şekilli atamalar baytlar diske ulaşmadan önce boşaltılır. Daemon yüklemeden önce tekrar boşaltır. |
