Failproof AI, Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi, Hermes, OpenClaw, Factory Droid, Devin CLI, Antigravity CLI ve Goose'u destekler.

| Harness | Desteklenen hook kapsamları |
| --- | --- |
| Claude Code | User, project, local |
| Codex, GitHub Copilot CLI, Cursor, OpenCode, Pi | User, project |
| Factory Droid, Devin CLI, Antigravity CLI, Goose | User, project |
| Hermes, OpenClaw | User |

Her entegrasyon, politikalar çalışmadan önce yerel hook olay adlarını, araç adlarını ve araç giriş alanlarını normalleştirir. Bir politika yalnızca harness'in ortaya çıkardığı olaylara etki edebilir; dağıttığınız tam harness ve sürümde tur sonu ve talimat davranışını test edin.

## Uygulama yeteneği

"Block" (engelle), adlandırılmış harness tarafından tüketilen geçerli adaptörün döndürülen kararı anlamına gelir. Araçtan sonra engelleme, modele gösterilen sonucu değiştirebilir ancak zaten gerçekleşen bir araç yan etkisini geri alamaz.

| Harness | Doğrulanan engelleme olayları | Gözlem amaçlı veya engellenemeyen uyarılar |
| --- | --- | --- |
| Claude Code | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PreCompact` ve birkaç görev/yapılandırma olayı | `PostToolUse`, oturum yaşam döngüsü, bildirimler ve başarısızlık sonrası olaylar gözlemcidir. |
| Codex | `PreToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PostToolUse` | Araçtan sonra engelleme, yürütmeden sonra sonucu değiştirir; oturum başlangıcı ve kompakt olaylar mevcut adaptörde gözlemcidir. |
| GitHub Copilot CLI | `PreToolUse`, `UserPromptSubmit`, `PermissionRequest`, `Stop`, `SubagentStop`, `PostToolUse` | Araçtan sonra engelleme, yürütmeden sonra sonucu değiştirir; oturum ve bildirim olayları gözlemcidir. |
| Cursor | `PreToolUse`, `UserPromptSubmit`, `Stop` | `PostToolUse` ve oturum olayları gözlemcidir. |
| OpenCode | `PreToolUse` | Araçtan sonra ve yaşam döngüsü olayları gözlemcidir; mevcut durma işleme, doğrulanmış bir kapı yerine daha sonraki bir tur için rehberlikdir. |
| Pi | `PreToolUse`, `UserPromptSubmit` | Araçtan sonra ve yaşam döngüsü olayları gözlemcidir; durma rehberliği daha sonraki bir tura uygulanır. |
| Hermes | `PreToolUse` | Araçtan sonra, oturum ve subagent-stop kararları kapı değildir. |
| OpenClaw | `PreToolUse`, `UserPromptSubmit`, `Stop` | Araçtan sonra, oturum, subagent-stop ve kompaksiyon olayları gözlemcidir. |
| Factory Droid | `PreToolUse`, `UserPromptSubmit`, `Stop`, `PreCompact` | Araçtan sonra ve subagent-stop kararları gözlemcidir. |
| Devin CLI | `PreToolUse`, `UserPromptSubmit`, `Stop`, koşullu `PermissionRequest` | İzin kancaları her izin modunda çalışmaz; araçtan sonra ve oturum olayları gözlemcidir. |
| Antigravity CLI | `PreToolUse`, `Stop` | Kullanıcı istemi ve araçtan sonra kararlar gözlemcidir; isteme talimatlar yine de enjekte edilebilir. |
| Goose | `PreToolUse` | Kullanıcı istemi, araçtan sonra ve oturum olayları gözlemcidir. Yerli bir engelleme durma kancası yukarı akışta mevcut ancak mevcut adaptör tarafından yüklenmez. |

Yetenekler sürüme duyarlıdır. Bir agent CLI'yi yükselttikten sonra, özellikle bir politika genel ön araç kapısı yerine isteme, durma, izin veya araçtan sonra davranışına bağlı olduğunda yeniden test edin.

## Yakalama ve politika kancalarını yükle

<Tabs>
  <Tab title="Dashboard">
    1. **Administration → Keys** öğesini açın ve `events:add` ve `policies:pull` izinleriyle makine veya ortam için adlandırılmış bir anahtar oluşturun.
    2. Hedef makinede, yerel CLI'yi görüntülenen anahtarla bağlayın ve harness kancalarını yükleyin.
    3. Yeni bir agent oturumu başlatın, ardından **Observe → Events** altında hook ve oturum olaylarını onaylayın.
    4. Aynı zaman penceresi için **Observe → policy** öğesini açın ve bir politika kararının makineye atandığını onaylayın.

    Bağlantı bir makine anahtarıyla başlar. Sırrını kopyalamadan önce hem alım hem de politika teslimi izinlerini içerdiğini onaylayın.

    ![Etkinlik alımı ve politika teslimi izinleri vermek için kullanılan yeni API anahtarı çekmeceси.](/images/dashboard/key-create.png)

    Kancaları yükledikten sonra, Events akışı bağladığınız makineden ve ortamdan yeni olayları göstermelidir.

    ![Yeni yüklenen bir harness'in rapor ettiğini onaylamak için kullanılan canlı Events akışı.](/images/dashboard/events-stream.png)

    Son olarak, politika kararlarının aynı makineye atandığını doğrulayın. Bu, harness'in izleme olaylarının yanı sıra politika etkinliğini de rapor ettiğini doğrular.

    ![Yeni bağlanmış bir harness'ten gelen politika kararlarını doğrulamak için kullanılan Policy sayfası.](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    Tespit edilen her harness için kancaları yükleyin:

    ```bash
    failproofai config \
      --connect https://app.befailproof.ai \
      --token <machine-key>
    failproofai policies --install
    ```

    Veya adlandırılmış harnesses ve yapılandırma kapsamını hedefleyin:

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    Proje kapsamı hook yapılandırmasını bir depo ile tutar. Kullanıcı kapsamı depolar arasında çalışmayı kapsar. Claude Code ayrıca yerel kapsamı destekler; destek harness'e göre değişir ve CLI desteklenmeyen kombinasyonları reddeder.

    Makineyi ve olaylarını doğrulayın:

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## Varsayılan olmayan oturum yolu ekle

<Tabs>
  <Tab title="Dashboard">
    Ek yollar makinede kaydedilir, Cloud'da değil. Bir tane ekledikten sonra, **Observe → Sessions** öğesini açın, ortamı makineye filtreleyin ve yeni yoldan oturumların göründüğünü onaylayın. Bir oturumu açın ve buna güvenmeden önce aracı, harness'i ve etkinlik zaman damgalarını kontrol edin.

    ![Ek yakalama yolundan veri alan ortama filtrelenen Sessions listesi.](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    İsteğe bağlı bir etiketle bir yol ekleyin, ardından yapılandırılan yolları inceleyin:

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    `failproofai harness remove-path claude checkout` ile bir yolu kaldırın.
  </Tab>
</Tabs>

<Tip>
  Yüklemeden sonra bir yeni oturum çalıştırın. Dağıtımı genişletmeden önce hem canlı etkinlik akışını hem de gerçek bir politika kararını doğrulayın.
</Tip>
