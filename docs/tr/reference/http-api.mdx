Genel API, Failproof AI panonuz orijininde `/v1` altında sunulur.

## Anahtar oluşturun ve istek gönderin

<Tabs>
  <Tab title="Pano">
    1. **Administration → Keys** sayfasını açın, **Create key** seçeneğini seçin ve entegrasyonu karşılayan en dar izin ön ayarını seçin.
    2. Gerektiğinde yalnızca bireysel izinler ekleyin, anahtarı oluşturun ve bunun tek seferlik parolasını kopyalayın.
    3. `/v1/sessions` adresine bir test isteği yapın ve anahtarın Keys sayfasında aktif kalması yı doğrulayın.
    4. Entegrasyon mülkiyeti değiştiğinde, anahtarı kendi eylem menüsünden döndürün veya devre dışı bırakın.

    ![Yeni API anahtar çekmeceği izin ön ayarları ve bireysel izinlerle birlikte.](/images/dashboard/key-create.png)

    Yukarıda oluşturma çekmecesi gösterilmektedir. Tek seferlik parola yalnızca **create** seçeneğini belirledikten sonra görünür; o onayı kapatmadan önce kopyalayın.
  </Tab>
  <Tab title="CLI">
    Okuma anahtarı oluşturun ve `fp` veya `curl` ile doğrudan kullanın:

    ```bash
    fp keys create reliability-reader \
      --permission-set read-only

    fp --api-key <key> sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/sessions?limit=20" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY"
    ```
  </Tab>
</Tabs>

Anahtarlar bir kuruluşa ve izin kümesine kapsamlıdır. Endpoint'in gerekli izni olmayan bir istek `403` döndürür ve eksik izni tanımlar.

## Kuruluş seçimi

Bir kuruluş anahtarı otomatik olarak kendi kuruluşu üzerinde işlem yapar. Örnek kapsamlı bir anahtar, istek başına bir kuruluş seçebilir:

<Tabs>
  <Tab title="Pano">
    **Administration → Keys** sayfasını açmadan önce pano başlığındaki kuruluş değiştiriciyi kullanın. Orada oluşturulan anahtarlar seçili kuruluşa aittir. URL'deki kuruluş slug'ını ve kimlik bilgisini otomasyona kopyalamadan önce anahtar ayrıntısını doğrulayın.

  </Tab>
  <Tab title="CLI">
    Komuttan önce `--org` kullanın veya örnek kapsamlı bir API anahtarı için kuruluş başlığı gönderin.

    ```bash
    fp orgs list
    fp --org reliability-team sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/usage" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "X-AgentEye-Org: reliability-team"
    ```
  </Tab>
</Tabs>

Geçerli yollar, parametreler, izin gereksinimleri ve durum kodları için bu bölümdeki oluşturulan endpoint sayfalarını kullanın. Belirtim, sunucu rota ek açıklamalarından oluşturulur ve `/v1` yönlendiricisine karşı kontrol edilir.

Geçerli belirtim, tam rota, yöntem, parametre, izin ve durum kodu kapsamına sahiptir. Sunucu hala bazı yanıt gövdelerini dinamik JSON olarak yapılandırdığından bazı yanıt gövdeleri kasıtlı olarak yazılmamıştır. Yanıt şeması olmayan bir endpoint etrafında kesin olarak yazılmış bir istemci oluşturmadan önce gerçek bir yanıtı inceleyin.

JSON yazmaları için `Content-Type: application/json` kullanın. `401` öğesini eksik veya geçersiz kimlik doğrulamaya, `403` öğesini gerekli izin olmayan geçerli bir kimliğe, `404` öğesini eksik veya kuruluşa erişilemeyen kaynağa, `409` öğesini durum çakışmasına ve `422` öğesini geçersiz alan veya izin değerine karşılık olarak değerlendirin. Hata yanıtları okunabilir bir ileti içerir; izin hataları ayrıca gerekli izni de adlandırır.

<Warning>
  İlke yürürlüğe koyma dağıtımı, kasıtlı olarak olağan genel `/v1` yüzeyinin dışında yönetilir. Desteklenen Bulut dağıtım iş akışını kullanın.
</Warning>
