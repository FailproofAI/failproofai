Durdurmak istediğiniz bir davranıştan ve yine de çalışması gereken meşru bir eylemden başlayın.

## Önce incelenen bir politikayı deneyin

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI, 39 incelenen politika içerir. Yeni bir tane yazmadan önce [kataloğu](/tr/policies/builtin-catalog) kontrol edin.

## Kendi politikanızı yazın ve test edin

<Steps>
  <Step title="Çalışan bir politika oluşturun">
    ```bash
    failproofai publish --init guards.mjs
    ```

    Bu, `git push --force` komutunu engelleyen bir politika yazar. Kuralınıza uyarlamak için düzenleyin.
  </Step>
  <Step title="Bu makinede uygulayın">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    Agentinizden engellenen eylemi gerçekleştirmesini isteyin, ardından yerel pano da **Policies → Activity** kısmını kontrol edin.
  </Step>
  <Step title="Tutun veya kaldırın">
    `.failproofai/policies/` altına otomatik olarak yüklenecek şekilde bir `*policies.mjs` dosyası yerleştirin.

    Açık özel dosyaları şu komutla kaldırın:

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## Paylaşın

Herkese açık bir paket yayınlayın:

```bash
failproofai publish
```

Herhangi biri daha sonra `failproofai policies add <owner>/<repo>` ile yükleyebilir. GitHub konusu `failproofai-policies` ekleyerek [Policy Hub](https://befailproof.ai/policy-hub/) tarafından dizine alınabilir.

Cloud dağıtımı için:

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  Boş bir `--add checkout-guard` komutu hemen uygulamaya konur. Politikanın ajanı engellemeden ne yapacağını kaydetmek için `:observe` ekleyin.
</Warning>

Tam iş akışı için [paket yayınlama](/tr/policies/publish-a-pack) veya [politika dağıtımı](/tr/policies/deploy) bölümüne bakın.
