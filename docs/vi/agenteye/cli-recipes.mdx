Kéo dữ liệu phiên, sự kiện và đánh giá (và kích hoạt lại các đánh giá) trực tiếp từ script hoặc agent mã hóa, với JSON sạch trên stdout có thể đưa trực tiếp vào `jq`. Những công thức này chuyển đổi dữ liệu của Failproof AI Observability thành thứ gì đó mà người dùng terminal hoặc agent mã hóa AI (Claude Code, Cursor) có thể truy vấn và tự động hóa, mà không cần nhấp qua bảng điều khiển.

Những mẫu dưới đây sẵn sàng copy-paste cho CLI Failproof AI Observability (`agenteye`). Để cài đặt, xác thực và danh sách đầy đủ các tùy chọn, xem [CLI](/vi/agenteye/cli); chạy `agenteye -h` hoặc `agenteye <command> -h` để xem trợ giúp tích hợp.

## Các quy tắc vàng

1. **Các tùy chọn toàn cục đi *trước* lệnh.** `agenteye --json sessions` là đúng; `agenteye sessions --json` là sai. Các tùy chọn toàn cục là `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, `--no-color`.
2. **Truyền `--json` bất cứ khi nào bạn phân tích kết quả.** Dữ liệu đi tới **stdout** dưới dạng JSON; trạng thái và lỗi của con người đi tới **stderr**, do đó stdout vẫn sạch để đưa vào `jq`.
3. **Phân nhánh dựa trên mã thoát**, không phải trên văn bản stderr: `0` ok · `1` lỗi không mong muốn · `2` đối số xấu · `3` không thể tiếp cận bảng điều khiển · `4` chưa đăng nhập hoặc đã hết hạn · `5` thiếu quyền · `6` tài nguyên không tìm thấy.
4. **Khám phá với `-h`.** Mỗi lệnh ghi lại các bộ lọc, định dạng giá trị và hình dạng JSON.

## Cài đặt một lần

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com   # để bạn không phải lặp lại --base-url
agenteye login --email you@example.com                       # dán mã được gửi qua email; hợp lệ ~24h
```

## Xác nhận xác thực trước khi làm việc

`whoami` không bao giờ gặp lỗi trên phiên bị thiếu hoặc đã hết hạn; nó báo cáo `logged_in:false` thay thế, do đó một agent có thể an toàn kiểm tra trạng thái xác thực. (Nó vẫn có thể thoát khác 0 nếu không có URL cơ sở được đặt hoặc bảng điều khiển không thể truy cập được.)

```bash
if [ "$(agenteye --json whoami | jq -r .logged_in)" != "true" ]; then
  echo "Not authenticated. Run: agenteye login" >&2; exit 1
fi
```

## Tìm các phiên không thành công hoặc điểm thấp

```bash
# các phiên trong 24h qua có đánh giá gặp lỗi
agenteye --json sessions --since 24h --status error | jq -r '.sessions[].session_id'

# các đánh giá ghi điểm <= 0.5 về độ hữu ích, cho một agent
agenteye --json evals --agent-id checkout-bot --score helpfulness:..0.5 \
  | jq '.evaluations[] | {session_id, scores}'
```

Bộ lọc điểm số hoạt động trên **`evals`**, không phải `sessions`. `--score KEY:MIN..MAX` có thể lặp lại và kết hợp AND; bất kỳ ràng buộc nào là tùy chọn (`..0.5` có nghĩa là ≤ 0.5, `0.9..` có nghĩa là ≥ 0.9). Bạn có thể truyền tối đa 20 bộ lọc điểm trên mỗi yêu cầu; những cái khác trả về HTTP 400. `sessions` chia sẻ các bộ lọc `--env`, `--status`, `--agent-id`, `--session-id` và phạm vi thời gian với `evals`, nhưng không có `--score`.

## Đọc một phiên từ đầu đến cuối

Không có lệnh `session show` duy nhất. Kết hợp đường dẫn sự kiện với đánh giá của phiên:

```bash
# đánh giá mới nhất của phiên (trạng thái + điểm số)
agenteye --json evals --session-id run-001 | jq '.evaluations[0] | {status, scores}'

# mỗi sự kiện trong lần chạy (nâng --limit để quét đầy đủ)
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'

# chỉ các lệnh gọi công cụ trong một phiên (--full được yêu cầu để lấy payload thô)
agenteye --json events --full --session-id run-001 --event-type tool_use,tool_result --all \
  | jq '.events[].payload'
```

> **Lưu ý:** Theo mặc định, `events` đọc một nguồn cấp nhanh không có payload. Mỗi sự kiện mang một `summary` một dòng được tính toán bởi máy chủ cộng với các cờ như `is_error` và số lượng token, nhưng `payload` quay trở lại dưới dạng `{}`. Để kéo payload thô, thêm `--full` (hoặc `--fields payload`). Nguồn cấp đầy đủ chậm hơn ở quy mô, vì vậy hãy giữ nó bị ràng buộc: ghép `--full` với một `--session-id` duy nhất.

## Tìm nạp mọi thứ (phân trang)

Kết quả là mới nhất trước và được phân trang con trỏ.

```bash
# một lần: tìm nạp tối đa 500 hàng trong các trang 200 hàng
agenteye --json events --session-id run-001 --limit 500 --all > events.json

# phân trang thủ công: đưa next_cursor trở lại vào
page=$(agenteye --json events --limit 100)
cursor=$(echo "$page" | jq -r '.next_cursor // empty')
[ -n "$cursor" ] && agenteye --json events --limit 100 --cursor "$cursor"
```

## Làm mỏng đầu ra với --fields

Hạn chế các khóa (trong cả bảng và `--json`) để giảm những gì một agent phải đọc.

```bash
agenteye --json sessions --since 7d --fields session_id,status,scores | jq -c '.sessions[]'
agenteye --json events --session-id run-001 --fields ts,event_type --all
```

Các tên trường không xác định bị từ chối (thoát `2`) cùng với danh sách hợp lệ, một cách rẻ để khám phá các tên trường.

## Khám phá các giá trị bộ lọc hợp lệ

```bash
agenteye --json list envs | jq -r '.values[]'           # giá trị cho --env
agenteye --json list tools | jq -r '.values[]'          # tên công cụ; cũng có agent, model, event_type, …
agenteye --json list score_filters | jq -r '.values[]'  # KEY hợp lệ cho --score KEY:MIN..MAX
```

## Chọn tổ chức của bạn (đa người thuê)

Nếu bạn thuộc về nhiều tổ chức, hãy chọn người thuê hoạt động khi đăng nhập (nó sẽ được lưu):

```bash
agenteye login --org acme --email you@corp.com   # đặt người thuê trong cùng bước với đăng nhập
agenteye --json orgs list | jq -r '.orgs[].org_slug'
agenteye --org globex --json sessions --since 24h   # ghi đè cho một lệnh
```

Đăng nhập đa tổ chức mà không có `--org` thoát khác 0 và in các tổ chức để chọn.

## Cấp phát khóa API cho SDK/bộ sưu tập

```bash
# bí mật được in MỘT LẦN, với --json nó là trường .key
key=$(agenteye --json keys create ci-bot --add events:read.add | jq -r '.key')
agenteye keys regenerate ci-bot --yes    # quay vòng; agenteye keys disable ci-bot --yes để thu hồi
```

## Chạy truy vấn đã lưu hoặc ad-hoc

```bash
agenteye --json query run --sql "select count(*) from analytics.events" | jq '.rows'
agenteye --json query run errs --arg prod | jq '.rows'   # truy vấn đã lưu + $1 vị trí
```

## Phân loại sự cố không tương tác

```bash
id=$(agenteye --json incidents list --state firing | jq -r '.incidents[0].id')
agenteye incidents ack "$id"
agenteye incidents assign "$id" --assignee you@corp.com
agenteye incidents resolve "$id" --yes
```

> **Lưu ý:** Các phép biến đổi tự động bỏ qua lời nhắc xác nhận của chúng trong `--json` hoặc khi stdin không phải TTY, vì vậy các agent không bao giờ treo; chuyển `--yes`/`-y` để bỏ qua nó một cách rõ ràng ở nơi khác.

## Xử lý mã thoát trong script

```bash
out=$(agenteye --json sessions --since 1h) || code=$?
case "${code:-0}" in
  0) echo "$out" | jq '.sessions | length' ;;
  4) echo "Session expired - run 'agenteye login'." >&2 ;;
  5) echo "Missing permission (ask an admin for evaluations:read)." >&2 ;;
  3) echo "Dashboard unreachable - check the URL." >&2 ;;
  *) echo "Unexpected error (exit ${code})." >&2 ;;
esac
```

## Hình dạng đầu ra JSON

| Lệnh | JSON stdout (với `--json`) |
|---|---|
| `whoami` | `{"logged_in": true, "id", "email", "is_instance_admin", "active_org", "permissions": [...], "memberships": [...]}` hoặc `{"logged_in": false}` |
| `orgs list` | `{"active_org", "orgs": [{"org_slug","org_name","permission_set","permissions"}]}` |
| `events` | `{"events": [...], "next_cursor": <cursor or null>}` |
| `evals` | `{"evaluations": [...], "next_cursor": <cursor or null>}` |
| `sessions` | `{"sessions": [...], "next_cursor": <cursor or null>}` |
| `errors` | `{"errors": [...], "next_cursor": <cursor or null>}` |
| `list <kind>` | `{"kind", "values": [...]}` |
| `keys list` / `keys create` | `{"keys": [...]}` / `{id, name, permissions, created_at, key}` (`key` được hiển thị một lần) |
| `query run` | `{columns: [{name,type}], rows: [[...]], truncated, elapsed_ms}` |
| `users list` / `settings list` | `{"users": [...]}` / `{"settings": [...]}` |
| `alerts list` / `incidents list` | `{"alerts": [...]}` / `{"incidents": [...]}` |
| tạo/cập nhật/xóa (bất kỳ) | đối tượng tài nguyên, hoặc `{"deleted": true, "id"}` để xóa |
| lỗi (bất kỳ, với `--json`) | `{"error": "...", "exit_code": <n>, "status"?: <http>, "hint"?: "..."}` trên stdout |

- Mỗi mục **sự kiện** (`events`): `id, session_id, agent_id, event_type, ts, payload, environment, summary, is_error, error_type, output_tokens, context_window, context_fill`. Lưu ý rằng `payload` là `{}` trừ khi bạn yêu cầu nguồn cấp đầy đủ với `--full` (hoặc `--fields payload`).
- Mỗi mục **đánh giá** (`evals`): `id, session_id, agent_id, environment, status, scores, reasoning, summary, error, attempt_count, duration_ms, completed_at, created_at`.
- Mỗi mục **phiên** (`sessions`): `session_id, agent_id, environment, status, scores, event_count, started_at, last_event_at, first_event_id, last_event_id, latest_evaluation`.

`--fields` của mỗi lệnh chấp nhận chính xác các tên trường của mục riêng của nó. Tập hợp khác nhau giữa `sessions` và `evals`, vì vậy một tên hợp lệ cho cái này có thể bị từ chối bởi cái kia.
