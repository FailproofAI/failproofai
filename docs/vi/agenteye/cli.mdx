Điều khiển tất cả Failproof AI Observability từ terminal hoặc script: không cần qua dashboard. CLI `agenteye` truy vấn dữ liệu của bạn (sessions, event logs, evaluations) và quản lý tổ chức (API keys, users, settings, alerts, incidents, saved queries), vì vậy hãy sử dụng nó khi bạn muốn tự động hóa một kiểm tra, tích hợp Observability vào CI, hoặc cho một coding agent kiểm tra production. Mọi lệnh đều hỗ trợ cờ `--json`, vì vậy nó hoạt động tốt cho bạn ở dòng lệnh hoặc cho một coding agent (Claude Code, Cursor) thực thi và phân tích kết quả.

Với một binary duy nhất, bạn có thể:

- **Đọc dữ liệu của bạn**: `sessions`, `events`, `evals`, `errors` (lọc theo thời gian, agent, env, score).
- **Quản lý tổ chức**: `keys`, `users`, `settings`, `alerts`, `incidents`.
- **Chạy phân tích**: SQL đã lưu và trình chạy truy vấn ad-hoc (`query`).
- **Hỏi trợ lý AI**: cùng một analyst chỉ đọc mà bạn trò chuyện trong dashboard (`agent`).

> **Lưu ý:** Đây là CLI `agenteye`, một công cụ khác với daemon collector (`agenteye-collector`). CLI giao tiếp với dashboard của bạn; collector gửi các sự kiện đến máy chủ.

## Bắt đầu nhanh

Từ không có gì đến kết quả đầu tiên trong bốn dòng. Chỉ CLI đến dashboard của bạn, đăng nhập, xác nhận danh tính, rồi kéo dữ liệu từ ngày hôm qua:

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # emailed 6-digit code
agenteye whoami                                                                  # confirm user + active org
agenteye --json sessions --since 24h                                             # one row per agent run, last 24h
```

Lệnh cuối cùng in ra một object JSON của các sessions gần đây nhất (mới nhất trước, giới hạn 50 theo mặc định). Pipe nó vào `jq` để cắt, hoặc bỏ `--json` để có một bảng được khoanh và tô màu. Mỗi hàng chứa trạng thái của lần chạy và, nếu một evaluator đã chấm điểm nó, điểm số của các metric (rút gọn ở đây):

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

Phần còn lại của trang này giải thích từng phần: [cài đặt](#installation) riêng lẻ, [đăng nhập](#authentication), [cấu hình](#configuration), [các quy ước toàn cục](#global-options--conventions) mà mọi lệnh chia sẻ, và [tham chiếu lệnh đầy đủ](#command-reference).

## Cài đặt

CLI là một package PyPI công khai có tên **`agenteye`**. Cài đặt nó trong một môi trường bị cô lập để nó luôn có các phụ thuộc riêng:

```bash
pipx install agenteye
# or
uv tool install agenteye
```

Nó yêu cầu Python 3.10+. Lệnh được cài đặt là **`agenteye`**:

```bash
agenteye --version
agenteye --help
```

> **Lưu ý:** Failproof AI Observability Python SDK cũng sử dụng tên phân phối `agenteye`. Cài đặt CLI với `pipx` hoặc `uv tool` (thay vì `pip install` vào một virtualenv được chia sẻ) giữ hai cái không va chạm. Một `pip install agenteye` đơn giản là được nếu SDK không được cài đặt trong cùng một môi trường.

## Xác thực

CLI xác thực với **dashboard** bằng một mã một lần được gửi qua email:

```bash
agenteye login --email you@example.com
# A 6-digit code is emailed to you; paste it at the prompt.
```

Token phiên được lưu trữ trong `~/.agenteye/cli.json` (chỉ bạn có thể đọc được, chế độ `0600`) và hợp lệ trong 24 giờ theo mặc định. Khi nó hết hạn, chạy `agenteye login` lại.

```bash
agenteye whoami     # show the current user, active org, and permissions
agenteye logout     # revoke the session and clear the stored token
```

`whoami` không bao giờ gặp lỗi với phiên bị thiếu hoặc hết hạn; thay vào đó nó báo cáo `logged_in: false`, vì vậy một script hoặc agent có thể kiểm tra trạng thái auth một cách an toàn (nó vẫn có thể thoát với mã khác 0 nếu không có base URL được đặt hoặc dashboard không thể tiếp cận).

**Yêu cầu:** email của bạn phải được phép đăng nhập vào dashboard (yêu cầu quản trị viên Failproof AI Observability), và dashboard phải có thể tiếp cận được tại URL cơ sở của nó (xem [Cấu hình](#configuration)). Nếu bạn yêu cầu một mã và không có mã nào tới, email của bạn có thể chưa được kích hoạt để truy cập dashboard.

## Chọn tổ chức của bạn (multi-tenant)

Nếu tài khoản của bạn thuộc về nhiều hơn một tổ chức, chọn tổ chức hoạt động **khi đăng nhập**; nó được lưu và sử dụng cho mọi lệnh sau:

```bash
agenteye login --org acme           # authenticate and set the active tenant in one step
agenteye orgs list                  # the orgs you can access (the active one is marked)
agenteye orgs switch globex         # change the saved default
agenteye --org globex sessions      # override for a single command
```

Nếu bạn chỉ thuộc về chính xác một tổ chức, nó sẽ được chọn tự động và bạn có thể bỏ qua `--org` hoàn toàn. Nếu bạn thuộc về nhiều tổ chức và không chọn một tổ chức, CLI sẽ liệt kê chúng và yêu cầu bạn chạy lại với `--org <slug>`. Tổ chức hoạt động được gửi đến dashboard trên mọi yêu cầu, và quyền của bạn được giải quyết **theo tổ chức**; `agenteye whoami` hiển thị tổ chức hoạt động, quyền của bạn trong đó, và tất cả các thành viên của bạn.

## Cấu hình

| Cài đặt | Cờ | Biến môi trường | Mặc định |
|---|---|---|---|
| Dashboard base URL | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **bắt buộc** (không có mặc định) |
| Active org/tenant | `--org` | `AGENTEYE_ORG` | chọn khi đăng nhập; lưu trong `~/.agenteye/cli.json` |
| Session token | `--token` | `AGENTEYE_CLI_TOKEN` | từ `~/.agenteye/cli.json` |
| JSON output | `--json` | `AGENTEYE_CLI_JSON` | tắt |
| Skip TLS verification | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | tắt (lưu khi đăng nhập) |
| Request timeout (seconds) | `--timeout` | _(none)_ | 30 |
| Disable usage telemetry | _(none)_ | `AGENTEYE_ANALYTICS_DISABLED` (or `DO_NOT_TRACK`) | telemetry is currently disabled; nothing is sent |

Thứ tự phân giải là **flag → environment variable → config file**. Không có mặc định; bạn phải chỉ CLI đến dashboard của bạn, hoặc mỗi lệnh (`--base-url https://agenteye.example.com`) hoặc một lần qua environment (nó cũng được lưu sau `login` đầu tiên của bạn):

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

Thư mục cấu hình tôn trọng `AGENTEYE_HOME` (quy ước tương tự được sử dụng bởi SDK và collector); nếu được đặt, `cli.json` nằm trong `$AGENTEYE_HOME/cli.json`.

### Self-signed hoặc internal TLS

Nếu dashboard của bạn được phục vụ qua HTTPS với chứng chỉ self-signed hoặc nội bộ (ví dụ, tên máy chủ load-balancer thô), xác minh TLS sẽ từ chối nó với lỗi `CERTIFICATE_VERIFY_FAILED`. Truyền `--insecure` để bỏ qua xác minh chứng chỉ:

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` **được lưu vào `cli.json` khi bạn đăng nhập**, vì vậy các lệnh sau bỏ qua xác minh tự động; bạn không phải lặp lại cờ. Truyền `--secure` cho một lệnh xác minh được thực hiện một lần, hoặc để lưu lại xác minh vào lần đăng nhập tiếp theo. CLI in một cảnh báo đến stderr trước bất kỳ lệnh nào liên hệ với dashboard trong khi xác minh bị vô hiệu hóa. Bỏ qua xác minh sẽ loại bỏ bảo vệ chống lại các cuộc tấn công man-in-the-middle; hãy đảm bảo bạn tin tưởng đường dẫn mạng đến dashboard của bạn (VPN, subnet riêng, v.v.) trước khi dựa vào nó.

## Telemetry & privacy

> **Lưu ý:** CLI được gửi **không gửi telemetry sử dụng ngày hôm nay.** Một master kill switch được bật, vì vậy không có gì được truyền bất kể môi trường của bạn. Phần dưới đây mô tả khả năng opt-out cho trường hợp telemetry bao giờ được bật.

Ngay cả khi được bật, telemetry sẽ là **chỉ phân tích sử dụng ẩn danh**, không bao giờ agent, session, hoặc event data của bạn:

- **Không có agent, session, hoặc event data nào bao giờ rời khỏi cơ sở hạ tầng của bạn.** Chỉ sử dụng CLI sẽ được báo cáo: tên lệnh và subcommand (ví dụ `keys create`), **tên** của các cờ bạn đã sử dụng (không bao giờ giá trị của chúng), trạng thái thành công/thoát, và thời lượng, cộng với một sự kiện per-action cho các mutation (ví dụ `api_key_created`, `query_run`) chỉ mang tên tĩnh/enums và số lượng thô. Dashboard URL của bạn, session token, email, org slug, resource ids, SQL, key secrets, và query filters sẽ **không bao giờ** được gửi. Các operators sẽ được xác định chỉ bởi một id nội bộ opaque, không bao giờ bằng email.
- **Opt out trước thời gian** bằng cách đặt `AGENTEYE_ANALYTICS_DISABLED=1` trong môi trường CLI (CLI cũng tôn trọng quy ước cross-tool `DO_NOT_TRACK=1`). Điều này có hiệu lực ngay khi telemetry bao giờ được bật, vì vậy một môi trường conscious về quyền riêng tư có thể ở opted out vĩnh viễn.
- Nếu telemetry được bật, CLI sẽ gửi trực tiếp đến PostHog (`https://us.i.posthog.com`); một máy có host đó bị chặn sẽ im lặng gửi không có gì và CLI sẽ không bị ảnh hưởng.

## Global options & conventions

Đọc cái này một lần; nó áp dụng cho mọi lệnh.

- **Global options đi TRƯỚC lệnh.** `agenteye --json sessions` là đúng; `agenteye sessions --json` là một lỗi sử dụng. Các globals là `--json`, `--base-url`, `--org`, `--token`, `--insecure`/`--secure`, `--timeout`, `--quiet`, và `--no-color`.
- **`--json` in pure JSON để stdout, và không có gì khác.** Dòng trạng thái con người, cảnh báo, và lỗi đi đến **stderr**, vì vậy một `--json` stdout capture ở sạch để pipe vào `jq` ngay cả khi một dòng trạng thái được hiển thị. Không có `--json` bạn nhận được một chế độ xem boxed, tô màu cho mắt con người.
- **Khám phá với `--help`.** Mọi lệnh và subcommand có `--help` (và bí danh `-h`): `agenteye -h`, `agenteye sessions -h`, `agenteye keys create -h`. Trợ giúp top-level cũng liệt kê các exit codes và global options. Không có global machine-readable surface dump; sử dụng per-command `--help`, cộng với domain-specific `agenteye query schema` và `agenteye settings schema` cho hai registries đó.
- **Confirmations auto-skip cho scripts và agents.** Lệnh Create/update/delete yêu cầu "are you sure?" trong một terminal tương tác, nhưng **auto-skip prompt đó dưới `--json` hoặc bất cứ khi nào stdin không phải là TTY** (TTY là một phiên terminal tương tác; pipe hoặc CI runner không), vì vậy scripts và agents không bao giờ treo. Truyền `--yes`/`-y` để bỏ qua nó một cách rõ ràng. Vì prompt sẽ không kích hoạt cho một agent, một agent nên xác nhận các hành động có tính chất phá hoại với con người trước.
- **Pagination:** kết quả là mới nhất-đầu tiên và cursor-paginated (mỗi trang trả về một token bạn sử dụng để lấy tiếp theo). `--limit N` (bí danh `-n`) caps rows và **defaults to 50**; `--all` auto-paginates (in 200-row chunks) **up to `--limit`**, vì vậy một bare `--all` vẫn dừng lại ở 50. Để quét đầy đủ truyền một cap rõ ràng cao: `--all --limit 1000`. `--page-size N` điều khiển per-request chunk (tối đa 200); `--cursor <id>` tiếp tục từ `next_cursor` của trang trước.
- **Time filters:** `--since` nhận một cửa sổ tương đối: `15m`, `1h`, `6h`, `24h`, `7d`, hoặc `all` (các presets dashboard). Cho một phạm vi dài hơn hoặc tùy chỉnh (nói 30 ngày gần đây), sử dụng `--from`/`--to`: explicit ISO-8601 UTC timestamps **with `T` and a timezone** (ví dụ `2026-06-01T00:00:00Z`) mà ghi đè `--since`. Một giá trị được phân tách bằng dấu cách hoặc không có múi giờ là một lỗi sử dụng.
- **`--fields a,b,c`** (on `events`, `sessions`, `evals`, `errors`) hạn chế đầu ra cho những khóa đó, cho cả bảng và `--json`. Các tên không xác định bị từ chối với danh sách hợp lệ, một cách rẻ để khám phá tên trường.
- **`--file payload.json`** (hoặc `--file -` để đọc stdin) cung cấp phần thân yêu cầu JSON đầy đủ nơi một tài nguyên có hình dạng phức tạp (on `alerts create/update`, `settings set`, và `users create/update`). Saved-query SQL sử dụng `--sql @file.sql` thay thế.
- **Multi-value filters** được phân tách bằng dấu phẩy → khớp như một bộ (union trong một filter, AND qua các filter): `--event-type tool_use,tool_result`. Click options không phải là variadic, vì vậy `--add a b` bị hỏng. Sử dụng `--add a,b`, lặp cờ (`--add a --add b`), hoặc quote (`--add "a b"`).

## Command reference

### Bạn sẽ sử dụng 5 lệnh này nhiều nhất

Hầu hết công việc hàng ngày chạy qua một số lượng lệnh đọc. Bắt đầu ở đây, rồi tiếp cận bề mặt đầy đủ dưới đây khi bạn cần:

| Lệnh | Nó làm gì | Thử |
|---|---|---|
| `sessions` | Một hàng cho mỗi agent run: thời gian, env, agent, trạng thái, điểm số mới nhất. | `agenteye --json sessions --since 24h --status error` |
| `events` | Đường mòn per-step thô bên trong một lần chạy (thêm `--full` cho payloads). | `agenteye --json events --session-id run-001 --all` |
| `evals` | Kết quả đánh giá và điểm; `--aggregate` cuộn chúng lên. | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | Chỉ những sự kiện lỗi; `--aggregate` để đếm theo type. | `agenteye --json errors --since 24h --aggregate` |
| `list` | Khám phá các giá trị bộ lọc hợp lệ (agents, envs, models, …). | `agenteye list agents` |

### Tất cả những gì CLI có thể làm

Bề mặt đầy đủ sau đây. CLI có **18 top-level commands**. Tất cả các lệnh đọc chấp nhận `--json` và các global options ở trên; chạy `agenteye <command> -h` (hoặc `<command> <subcommand> -h`) cho danh sách cờ exhaustive và JSON shape của bất kỳ một.

### Identity: `login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # emailed one-time code; saves the session
agenteye logout                                       # clear the saved session on this machine
agenteye whoami                                       # current user, active org, permissions
agenteye version                                      # print the CLI version (same as --version)
agenteye help                                         # top-level help (same as --help)
```

`orgs` kiểm tra và chuyển đổi active tenant:

```bash
agenteye orgs list        # your orgs + your role in each (active one marked)
agenteye orgs switch acme # change the saved active org (omit the slug to pick from a list on a TTY)
agenteye orgs current     # identity card for the active org
agenteye orgs perms       # your permissions in the active org, grouped by resource
```

### Observe (read-only): `events` · `sessions` · `evals` · `errors` · `list`

Không có cái nào trong số này cần một confirmation. Bộ lọc được chia sẻ: `--session-id`, `--agent-id`, `--env` (**not** `--environment`), và phạm vi thời gian (`--since` / `--from` / `--to`).

```bash
# events (alias: the raw per-step trail), newest first
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions: one row per agent run (time/env/agent/session/status; no score filtering)
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals: evaluation results + scores; --score filters by metric, --aggregate rolls up
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # status mix + per-key score stats

# errors: errored events; --aggregate for counts/sessions/agents/last-seen
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list: discover valid filter values before you filter
agenteye list envs        # also: agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX` (on **`evals`**, not `sessions`) có thể lặp lại và AND-kết hợp; một trong hai ràng buộc là tùy chọn (`..0.5` có nghĩa ≤ 0.5, `0.9..` có nghĩa ≥ 0.9). Lên tới 20 score filters mỗi yêu cầu. `evals --scores-full` là một display flag cho **human table only**; nó cho thấy mỗi cặp điểm thay vì vài cái đầu tiên cộng với một `+N` count. Nó không có tác dụng dưới `--json`, luôn trả về đối tượng điểm hoàn chỉnh. Để đọc **one session end-to-end**, kết hợp đường mòn sự kiện với đánh giá của nó:

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # its scores + status
```

### Manage (permission-gated): `keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**: API keys. Bí mật được tạo cục bộ, gửi đến máy chủ (chỉ lưu trữ một hash), và **shown once** on create/regenerate; ghi lại nó sau đó. Với `--json` nó xuất hiện chỉ trong trường `key`. Được tham chiếu bởi **name**.

```bash
agenteye keys list                                   # active keys first, then revoked
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # scope to what you need; prints the secret ONCE
agenteye keys create ops --permission-set standard --remove queries:run   # seed a preset, then trim
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # rotate the secret (the old one stops working)
agenteye keys disable ci-bot --yes                   # revoke
```

Quyền hoạt động như `(permission-set ∪ --add) − --remove`. Tokens là `slug:action` (ví dụ `events:read`) hoặc `slug:action.action` để mở rộng một số trên một tài nguyên (`events:read.add` → `events:read`, `events:add`). Presets: `read-only`, `standard`, `admin`. Human-only permissions (`keys:update`) không thể được cấp cho một key.

**`users`**: org members, được tham chiếu bởi **email** (một UUID id cũng được chấp nhận).

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # predicts + confirms
agenteye users disable dev@corp.com --yes            # has protected/self guards
agenteye users enable dev@corp.com
```

**`settings`**: một registry cố định (bạn đọc và thay đổi các khóa hiện có; bạn không thể tạo ra những cái mới).

```bash
agenteye settings list                               # key · value · type · updated (secrets masked)
agenteye settings schema                             # what each key accepts (type · range · description)
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**: alert definitions, được tham chiếu bởi **name**. `create` takes a positional NAME cộng với cờ hoặc một phần thân JSON đầy đủ qua `--file`.

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME is required (positional)
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # fire a test notification
agenteye alerts delete high-errors --yes
```

**`incidents`**: alert incidents, được tham chiếu bởi id (short ids chấp nhận). `show` in nhật ký hoạt động đầy đủ; đọc nó trước khi hành động.

```bash
agenteye incidents list --state firing                # also: acknowledged, resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # assignee must be an operator
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # open one manually against an alert
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### Analytics & assistant: `query` · `agent`

**`query`**: saved SQL chống lại analytics store của bạn cộng với một ad-hoc runner. Saved queries được tham chiếu bởi **name**; SQL được xác nhận phía máy chủ (SELECT/WITH chỉ, statement timeout, row cap).

```bash
agenteye query schema [TABLE]                         # column layout of the analytics views
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # run a saved query + a positional $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**: nói chuyện với **AI assistant** tích hợp (cùng một analyst chỉ đọc mà bạn có thể trò chuyện trong dashboard). Chats được tham chiếu bởi một short chat-id (prefix-resolved).

```bash
agenteye agent health                                 # is the AI assistant configured/reachable
agenteye agent models                                 # models you can pass to --model (default marked)
agenteye agent ask "which agents errored most in the last day?"    # starts a chat; prints its short id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # continue that chat
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## Exit codes

| Mã | Ý nghĩa |
|---|---|
| 0 | Thành công |
| 1 | Lỗi không mong muốn (ví dụ dashboard trả về 5xx) |
| 2 | Usage error (invalid arguments, unknown command/flag, name collision) |
| 3 | Không thể tiếp cận dashboard |
| 4 | Chưa đăng nhập hoặc phiên hết hạn; chạy `agenteye login` |
| 5 | Đã xác thực, nhưng tài khoản của bạn thiếu quyền cần thiết (message xác định nó) |
| 6 | Tài nguyên được yêu cầu không được tìm thấy (ví dụ unknown session hoặc incident id) |

Những cái này làm cho CLI an toàn để script: một coding agent có thể branch trên `4` để nhắc bạn xác thực lại, hoặc `5` để surface quyền bị thiếu. Xem [CLI recipes for agents](/vi/agenteye/cli-recipes) cho các mẫu exit-code-handling và JSON output shapes.
