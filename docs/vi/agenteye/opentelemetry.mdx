OpenTelemetry cho phép bạn gửi traces, logs và metrics từ agent đến FailproofAI Cloud bằng giao thức tiêu chuẩn OTLP/HTTP. Đây là tùy chọn. Các tích hợp FailproofAI hiện tại của bạn vẫn tiếp tục hoạt động mà không cần bật nó.

## Bật tính năng ingest cho tổ chức của bạn

Người quản trị tổ chức mở **Settings → OpenTelemetry** và bật tính năng ingest. Sử dụng API key Cloud với quyền `events:add`, quyền tương tự được sử dụng để báo cáo agent.

Nếu ingest tắt, Cloud sẽ từ chối xuất OTLP, do đó `failproofai otel enable` không thay đổi gì và các agent của bạn tiếp tục gửi sessions theo cách thông thường. Chạy `failproofai otel status` để kiểm tra công tắc tổ chức và yêu cầu người quản trị bật nó.

## Kết nối một coding agent

Kết nối máy của bạn với `failproofai config`, sau đó chọn một agent:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Lệnh setup hỗ trợ Claude Code, Codex và Copilot và chọn Cloud hoặc relay được xác thực cuc bộ theo thích hợp. Copilot sử dụng relay cục bộ tự động. Hãy khởi động daemon FailproofAI được cấu hình của bạn trước khi sử dụng relay.

Nếu FailproofAI đã gửi các transcripts session của agent, setup sẽ hỏi liệu có nên chuyển agent đó sang OTEL. Mặc định là Không. Chấp nhận sẽ dừng tải lên transcripts cho agent đó; nó không thay đổi enforcement chính sách hoặc báo cáo từ các agent khác.

## Kết nối một ứng dụng

Sử dụng instrumentation OpenTelemetry của ứng dụng bạn với các biến môi trường sau:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Endpoint là cơ sở OTLP của Cloud, `https://app.befailproof.ai/otel`; exporter của bạn thêm `/v1/traces`, `/v1/logs` hoặc `/v1/metrics` vào chính nó. Các biến theo từng tín hiệu như `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` được sử dụng như-là, vì vậy chúng cần đường dẫn đầy đủ, ví dụ `https://app.befailproof.ai/otel/v1/logs`.

Thay thế `<key>` bằng API key của bạn. Giữ bí mật ra khỏi lịch sử shell, ghi hình màn hình và cấu hình được commit. Đối với máy được cấu hình, `failproofai otel env --service my-agent` in ra khối với API key hiện tại của nó. Output của nó chứa một credential.

Cloud chấp nhận xuất OTLP/HTTP cho traces, logs và metrics, dưới dạng protobuf hoặc JSON, bao gồm các yêu cầu nén gzip. Nó không chấp nhận OTLP/gRPC.

Metrics được xác nhận để tương thích với exporter nhưng không được lưu trữ hoặc hiển thị. Traces agent được hỗ trợ và coding-agent logs trở thành sessions; các trường mà agent không xuất vẫn bị thiếu.

## Capture prompt text

<Warning>
Text capture có thể bao gồm prompts, tool arguments và các nội dung nhạy cảm khác. `failproofai otel enable` bật nó lên. Thêm `--no-content` để giữ prompt và tool-detail capture tắt.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Đối với một agent bạn cấu hình thủ công, hãy sử dụng các kiểm soát capture nội dung của chính nó:

<Tabs>
  <Tab title="Claude Code">
    Thêm các biến này vào môi trường của agent bên cạnh khối ứng dụng ở trên:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Đặt cả hai biến nội dung thành `0` để tránh capture prompts và tool details.
  </Tab>
  <Tab title="Codex">
    Trong cấu hình người dùng của Codex, sử dụng cài đặt OTEL của nó:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Nội dung cuộc hội thoại của Codex nằm trong logs; để internal runtime traces và metrics tắt. Codex sử dụng endpoint hoàn chỉnh bạn cung cấp. Đặt `log_user_prompt` thành `false` để loại bỏ prompts; lệnh setup bảo toàn một `false` rõ ràng.
  </Tab>
  <Tab title="Gemini CLI">
    Sử dụng cài đặt telemetry của Gemini với relay cục bộ:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI không được hỗ trợ bởi `failproofai otel enable`. Cấu hình nó thủ công với một collector được xác thực của riêng bạn. Đặt `logPrompts` thành `false` để không capture prompt.
  </Tab>
  <Tab title="Copilot in VS Code">
    Sử dụng các cài đặt người dùng VS Code này:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Chạy `failproofai otel enable copilot` để bật relay được xác thực. Đặt `captureContent` thành `false` để bỏ qua nội dung.
  </Tab>
</Tabs>

## Kiểm tra hoặc hoàn tác setup

Relay giữ telemetry qua các lỗi mạng và máy chủ tạm thời và thử lại sau khi khôi phục. Một từ chối `400` vĩnh viễn, bao gồm một event quá lớn để lưu trữ, yêu cầu sửa chữa payload. Relay giữ lại batch bị từ chối để kiểm tra thay vì gửi lại nó liên tục.

Sau `401` hoặc `403`, thay thế credential bằng API key cấp `events:add` cho cùng một tổ chức. Kết nối lại không tự động gửi lại các xuất OTLP được giữ lại bị từ chối vì credentials; yêu cầu operator của bạn phục hồi những batch đó. Giữ chúng trong tổ chức ban đầu của chúng.

```bash
failproofai otel status
failproofai otel disable all
```

Status phân biệt cài đặt được quản lý bởi FailproofAI từ telemetry bạn cấu hình ở nơi khác. Disable khôi phục cài đặt được quản lý trước đó và lựa chọn tải lên transcript trước đó của agent.
