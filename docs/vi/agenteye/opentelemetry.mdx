OpenTelemetry cho phép bạn gửi các trace, log và metrics của agent đến FailproofAI Cloud bằng giao thức tiêu chuẩn OTLP/HTTP. Đây là tùy chọn. Các tích hợp FailproofAI hiện có của bạn tiếp tục hoạt động mà không cần bật nó.

## Lấy khóa

OTLP ingest luôn bật cho mọi tổ chức; không có gì cần bật. Sử dụng khóa Cloud API với quyền `events:add`, quyền tương tự được sử dụng để báo cáo agent.

Trong bảng điều khiển, **home → first-run setup** có thẻ **connect with OpenTelemetry**: **create collector key** tạo khóa `events:add`, hiển thị một lần cùng với các biến exporter và hiển thị trạng thái kết nối. Bạn cũng có thể tạo một khóa dưới **settings → api keys** bằng cách chọn **sending logs only** dưới **new key**.

## Kết nối một coding agent

Kết nối máy của bạn với `failproofai config`, sau đó chọn một agent:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Lệnh thiết lập hỗ trợ Claude Code, Codex và Copilot và chọn Cloud hoặc một relay được xác thực cục bộ theo thích hợp. Copilot sử dụng relay cục bộ tự động. Khởi động daemon FailproofAI đã cấu hình của bạn trước khi sử dụng relay.

Nếu FailproofAI đã gửi bản ghi phiên của agent, thiết lập sẽ hỏi có muốn chuyển agent đó sang OTEL không. Mặc định là Không. Chấp nhận sẽ dừng các tải lên bản ghi phiên cho agent đó; nó không thay đổi thực thi chính sách hoặc báo cáo từ các agent khác.

## Kết nối một ứng dụng

Sử dụng instrumentation OpenTelemetry của ứng dụng bạn với các biến môi trường sau:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Endpoint là cơ sở OTLP của Cloud, `https://app.befailproof.ai/otel`; exporter của bạn thêm `/v1/traces`, `/v1/logs` hoặc `/v1/metrics` cho riêng nó. Các biến cho từng tín hiệu như `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` được sử dụng như vậy, vì vậy chúng cần đường dẫn đầy đủ, ví dụ `https://app.befailproof.ai/otel/v1/logs`.

Thay thế `<key>` bằng khóa API của bạn. Giữ bí mật ra khỏi lịch sử shell, bản ghi màn hình và cấu hình được cam kết. Đối với máy được cấu hình, `failproofai otel env --service my-agent` in khối với khóa hiện tại của nó. Đầu ra của nó chứa thông tin xác thực.

Cloud chấp nhận các xuất OTLP/HTTP cho trace, log và metrics, dưới dạng protobuf hoặc JSON, bao gồm các yêu cầu được nén gzip. Nó không chấp nhận OTLP/gRPC.

Các metrics được xác nhận để tương thích với exporter nhưng không được lưu trữ hoặc hiển thị. Các trace và log được hỗ trợ của coding-agent trở thành phiên; các trường agent không xuất sẽ vắng mặt.

## Chụp text lời nhắc

<Warning>
Text capture có thể bao gồm lời nhắc, đối số công cụ và nội dung nhạy cảm khác. `failproofai otel enable` bật nó lên. Thêm `--no-content` để giữ chụp lời nhắc và chi tiết công cụ. tắt
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Đối với một agent bạn cấu hình theo cách thủ công, hãy sử dụng các điều khiển chụp nội dung của chính nó:

<Tabs>
  <Tab title="Claude Code">
    Thêm các biến này vào môi trường của agent cùng với khối ứng dụng ở trên:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Đặt cả hai biến nội dung thành `0` để tránh chụp lời nhắc và chi tiết công cụ.
  </Tab>
  <Tab title="Codex">
    Trong cấu hình người dùng của Codex, hãy sử dụng cài đặt OTEL của nó:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Nội dung hội thoại Codex nằm trong log; để vô hiệu hóa trace và metrics thời gian chạy nội bộ. Codex sử dụng endpoint đầy đủ bạn cung cấp. Đặt `log_user_prompt` thành `false` để bỏ qua lời nhắc; lệnh thiết lập bảo toàn `false` rõ ràng.
  </Tab>
  <Tab title="Gemini CLI">
    Sử dụng cài đặt telemetry của Gemini với relay cục bộ:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI không được hỗ trợ bởi `failproofai otel enable`. Cấu hình nó theo cách thủ công bằng một collector được xác thực của riêng bạn. Đặt `logPrompts` thành `false` để không chụp lời nhắc.
  </Tab>
  <Tab title="Copilot in VS Code">
    Sử dụng các cài đặt người dùng VS Code này:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Chạy `failproofai otel enable copilot` để bật relay được xác thực. Đặt `captureContent` thành `false` để bỏ nội dung.
  </Tab>
</Tabs>

## Kiểm tra hoặc hoàn tác thiết lập

Relay giữ lại telemetry thông qua các sự cố mạng và máy chủ tạm thời và thử lại sau khi phục hồi. Một lệnh từ chối `400` vĩnh viễn, bao gồm một sự kiện quá lớn để lưu trữ, yêu cầu sửa chữa tải trọng. Relay giữ lại lô bị từ chối để kiểm tra thay vì gửi nó lặp đi lặp lại.

Sau `401` hoặc `403`, thay thế thông tin xác thực bằng khóa cấp `events:add` cho cùng một tổ chức. Kết nối lại không tự động gửi lại các xuất OTLP được giữ lại bị từ chối vì thông tin xác thực; yêu cầu nhà điều hành của bạn khôi phục những lô đó. Giữ chúng trong tổ chức gốc của chúng.

```bash
failproofai otel status
failproofai otel disable all
```

Trạng thái phân biệt cài đặt được quản lý bởi FailproofAI với telemetry bạn cấu hình ở nơi khác. Vô hiệu hóa khôi phục cài đặt được quản lý trước đó và lựa chọn tải lên bản ghi phiên trước đó của agent.
