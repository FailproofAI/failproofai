OpenTelemetry cho phép bạn gửi traces, logs và metrics của agent đến FailproofAI Cloud bằng giao thức tiêu chuẩn OTLP/HTTP. Đây là tính năng tùy chọn. Các tích hợp FailproofAI hiện có của bạn tiếp tục hoạt động mà không cần bật tính năng này.

## Bật ingest cho tổ chức của bạn

Một quản trị viên tổ chức mở **Settings → OpenTelemetry** và bật ingest. Sử dụng Cloud API key với quyền `events:add`, cùng quyền được dùng để báo cáo agent.

Nếu ingest tắt, Cloud sẽ từ chối OTLP exports, vì vậy `failproofai otel enable` không thay đổi gì và các agent của bạn tiếp tục gửi sessions theo cách thông thường. Chạy `failproofai otel status` để kiểm tra công tắc tổ chức và yêu cầu quản trị viên bật nó lên.

## Kết nối một coding agent

Kết nối máy của bạn bằng `failproofai config`, sau đó chọn một agent:

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

Lệnh setup hỗ trợ Claude Code, Codex và Copilot và chọn Cloud hoặc một relay được xác thực cuc bộ một cách phù hợp. Copilot sử dụng relay cục bộ tự động. Khởi động daemon FailproofAI đã cấu hình trước khi sử dụng relay.

Nếu FailproofAI đã gửi session transcripts của một agent, setup sẽ hỏi có nên chuyển agent đó sang OTEL không. Mặc định là Không. Chấp nhận sẽ dừng uploads transcript cho agent đó; nó không thay đổi policy enforcement hoặc báo cáo từ các agent khác.

## Kết nối một ứng dụng

Sử dụng instrumentation OpenTelemetry của ứng dụng của bạn với các biến môi trường này:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

Endpoint là OTLP base của Cloud, `https://app.befailproof.ai/otel`; exporter của bạn tự thêm `/v1/traces`, `/v1/logs` hoặc `/v1/metrics`. Các biến cho mỗi tín hiệu như `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` được sử dụng nguyên xi, vì vậy chúng cần đường dẫn đầy đủ, ví dụ `https://app.befailproof.ai/otel/v1/logs`.

Thay `<key>` bằng API key của bạn. Giữ secret ra khỏi shell history, screen recordings và committed configuration. Đối với một máy được cấu hình, `failproofai otel env --service my-agent` in khối với key hiện có của nó. Output của nó chứa một credential.

Cloud chấp nhận OTLP/HTTP exports cho traces, logs và metrics, dưới dạng protobuf hoặc JSON, bao gồm các yêu cầu nén gzip. Nó không chấp nhận OTLP/gRPC.

Metrics được xác nhận cho khả năng tương thích exporter nhưng không được lưu trữ hoặc hiển thị. Supported agent traces và coding-agent logs trở thành sessions; các trường mà agent không export sẽ không có mặt.

## Capture prompt text

<Warning>
Text capture có thể bao gồm prompts, tool arguments và nội dung nhạy cảm khác. `failproofai otel enable` bật nó. Thêm `--no-content` để giữ prompt và tool-detail capture tắt.
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

Đối với một agent bạn cấu hình thủ công, sử dụng content-capture controls của chính nó:

<Tabs>
  <Tab title="Claude Code">
    Thêm các biến này vào môi trường của agent cùng với khối ứng dụng ở trên:

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    Đặt cả hai biến content thành `0` để tránh capturing prompts và tool details.
  </Tab>
  <Tab title="Codex">
    Trong Codex user configuration, sử dụng OTEL settings của nó:

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex conversation content nằm trong logs; hãy để internal runtime traces và metrics bị tắt. Codex sử dụng complete endpoint mà bạn cung cấp. Đặt `log_user_prompt` thành `false` để loại bỏ prompts; lệnh setup bảo tồn một `false` rõ ràng.
  </Tab>
  <Tab title="Gemini CLI">
    Sử dụng telemetry settings của Gemini với local relay:

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI không được hỗ trợ bởi `failproofai otel enable`. Cấu hình nó thủ công với một authenticated collector của riêng bạn. Đặt `logPrompts` thành `false` để không capture prompt.
  </Tab>
  <Tab title="Copilot in VS Code">
    Sử dụng các VS Code user settings này:

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    Chạy `failproofai otel enable copilot` để bật authenticated relay. Đặt `captureContent` thành `false` để bỏ qua content.
  </Tab>
</Tabs>

## Kiểm tra hoặc hoàn tác setup

```bash
failproofai otel status
failproofai otel disable all
```

Status phân biệt các settings được quản lý bởi FailproofAI từ telemetry bạn cấu hình ở nơi khác. Disable khôi phục previous managed settings và previous transcript-upload choice của agent.
