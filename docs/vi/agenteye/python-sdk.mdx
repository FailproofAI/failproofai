Xem chính xác những gì mà AI agents của bạn đã thực hiện trong production: mỗi agent run, tool call, model request, hook, và human intervention. Failproof AI Observability Python SDK ghi lại toàn bộ quá trình này từ bên trong code của agent, giúp bạn debug, audit, và đánh giá những gì đã xảy ra. Sử dụng nó bất cứ khi nào bạn muốn Failproof AI Observability theo dõi agents của mình.

Dưới nắp công cụ, SDK viết các sự kiện có cấu trúc vào các file JSONL cục bộ, và daemon collector sẽ nhận chúng và tự động gửi tới platform. Bạn không cần quản lý các file này.

> **Tip:** Mới làm quen với Failproof AI Observability? Trang này là tài liệu tham khảo sự kiện SDK hoàn chỉnh.

## Bắt đầu nhanh

```python
import agenteye

agenteye.configure(environment="production")

agenteye.event.agent_start(session_id="run-001", agent_id="planner", goal="answer user query")

agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    input={"query": "latest AI research"},
)

agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    output={"results": ["..."]},
)

agenteye.event.agent_end(session_id="run-001", agent_id="planner", outcome="success")
```

### Instrumentation cho một cuộc gọi thực

Trong thực tế, bạn wrap code agent hiện có của mình. Bao quanh một model call với `model_request` trước và `model_response` sau, để hai sự kiện bao trùm yêu cầu thực và Failproof AI Observability có thể ghép chúng:

```python
import anthropic
import agenteye

agenteye.configure(environment="production")
client = anthropic.Anthropic()

messages = [{"role": "user", "content": "Summarise today's incidents."}]

agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6",
    messages=messages,
)

reply = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=512,
    messages=messages,
)

agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model=reply.model,
    stop_reason=reply.stop_reason,
    input_tokens=reply.usage.input_tokens,
    output_tokens=reply.usage.output_tokens,
    content=[block.model_dump() for block in reply.content],
)
```

Wrap tool calls theo cách tương tự với `tool_use` và `tool_result`, tái sử dụng một `tool_call_id` giữa cặp đó.

Đây là những gì những sự kiện đó trông như thế nào khi chúng đến được dashboard, được mã hóa màu theo loại và có thể lọc theo environment, agent, và session:

## configure()

```python
agenteye.configure(
    base_dir=None,           # Path | str | None. Default: $AGENTEYE_HOME or ~/.agenteye
    flush_interval=0.5,      # float, seconds between flush cycles
    environment=None,        # str | None. Deployment environment label
)
```

Gọi một lần trước bất kỳ cuộc gọi `event.*` nào. An toàn để bỏ qua; defaults hoạt động ngay lập tức. Tất cả các arguments đều là keyword-only; truyền chúng theo tên như được hiển thị ở trên.

Khi `base_dir` là `None` (mặc định), SDK đọc `$AGENTEYE_HOME` nếu được đặt,
nếu không sẽ quay trở lại `~/.agenteye`. Điều này khớp với resolution của collector riêng,
vì vậy một biến env `AGENTEYE_HOME` duy nhất cấu hình spool event chia sẻ cho cả
SDK và collector.

## Môi trường

Gắn nhãn mỗi sự kiện với một deployment environment (`production`, `staging`, `qa`, `canary`, v.v.). Đặt nó một lần; SDK gắn nó vào mỗi sự kiện tự động.

**Tùy chọn 1: qua `configure()`:**

```python
agenteye.configure(environment="production")
```

**Tùy chọn 2: qua biến môi trường:**

```bash
export AGENTEYE_ENVIRONMENT=production
```

**Ưu tiên:** `configure(environment=...)` thắng biến môi trường. Nếu không có cái nào được đặt, mặc định là `"dev"`.

Giá trị environment xuất hiện như một bộ lọc hạng nhất trong dashboard và được lưu trữ trên server để truy vấn nhanh.

> **Warning:** Các giá trị Environment không được chứa `,` dấu phẩy. Các bộ lọc dashboard sử dụng multi-select được phân tách bằng dấu phẩy trên dây (`?environment=prod,staging`), vì vậy một environment được đặt tên `prod,blue` sẽ bị chia thành hai giá trị. Các sự kiện có environments chứa dấu phẩy bị từ chối vào thời điểm ingest.

## Dữ liệu và quyền riêng tư

SDK chỉ ghi lại những trường mà bạn explicitly truyền. Prompts, messages, tool inputs và outputs, và model content được capture chỉ vì bạn đã truyền chúng cho một cuộc gọi `event.*`. Không có gì được đọc từ process của bạn hoặc captured implicitly. Bất kỳ trường nào bạn để unset đều được bỏ qua hoàn toàn khỏi sự kiện; nó không được viết vào disk.

Điều đó làm cho redaction trở thành lựa chọn và trách nhiệm của bạn. Nếu một prompt hoặc tool payload chứa PII hoặc secrets mà bạn không muốn lưu trữ, hãy loại bỏ hoặc che chúng trước khi truyền chúng cho phương thức event.

## Event Reference

Hầu hết các sự kiện đến theo cặp start/end chia sẻ một correlation ID: `tool_use` và `tool_result` chia sẻ `tool_call_id`, `hook_triggered` và `hook_completed` chia sẻ `hook_id`, và `human_wait` và `human_input` chia sẻ `input_id`. Phát sự kiện start, làm công việc, sau đó phát sự kiện end với cùng ID. Failproof AI Observability khớp cặp và tính toán `duration_ms` cho bạn, vì vậy bạn không bao giờ truyền `duration_ms` chính mình.

![A session's git-style execution graph beside its event timeline, reconstructed from the paired events, with the tool/model/hook breakdown panel](/agenteye/images/session-detail.png)

Tất cả các phương thức event yêu cầu hai trường này:

| Field | Type | Description |
|---|---|---|
| `session_id` | `str` | Xác định agent run cấp top-level |
| `agent_id` | `str` | Xác định agent nào trong session phát sự kiện |

Tất cả các phương thức cũng chấp nhận `**kwargs` tùy ý cho metadata custom (xem [Custom Fields](#custom-fields)).

---

### `event.agent_start()`

Được phát khi một agent bắt đầu công việc.

```python
agenteye.event.agent_start(
    session_id="run-001",
    agent_id="planner",
    goal="answer user query",   # str | None
    parent_id=None,             # str | None - parent agent_id for nested agents
)
```

---

### `event.agent_end()`

Được phát khi một agent hoàn thành công việc.

```python
agenteye.event.agent_end(
    session_id="run-001",
    agent_id="planner",
    outcome="success",          # str | None
    summary="Answered query",   # str | None
)
```

---

### `event.tool_use()`

Được phát khi một agent gọi một tool. Ghép với `tool_result`; SDK tự động tính toán `duration_ms`.

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",     # str, required
    tool_call_id="toolu_01",    # str, required - correlation key for the matching tool_result
    input={"query": "..."},     # dict | None
)
```

---

### `event.tool_result()`

Được phát khi một tool trả về. Tương quan với `tool_use` qua `tool_call_id`.

```python
agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",        # must match the prior tool_use
    output={"results": ["..."]},    # Any | None
    error=None,                     # str | None - set if the tool raised
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.model_request()`

Được phát ngay trước khi gửi một prompt tới một LLM.

```python
agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    messages=[                   # list[dict] | None - conversation turns
        {"role": "user", "content": "..."},
    ],
    system="You are helpful.",   # Any | None - str or list of content blocks
    tools=[                      # list[dict] | None - tool schemas offered to the model
        {"name": "search", "input_schema": {"type": "object"}},
    ],
)
```

Các mục `messages` chấp nhận một `content` string thuần hoặc Anthropic-style list-of-blocks `content`. Sampling params (`temperature`, `max_tokens`, v.v.) có thể được truyền dưới dạng kwargs thêm.

---

### `event.model_response()`

Được phát khi LLM trả về một phản hồi.

```python
agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    stop_reason="end_turn",     # str | None
    input_tokens=1024,          # int | None
    output_tokens=256,          # int | None
    content=[                    # Any | None - str, or list of content blocks
        {"type": "text", "text": "..."},
    ],
    role="assistant",            # str | None
)
```

`content` chấp nhận một string thuần (generic providers) hoặc một danh sách các Anthropic-style content blocks. Tool calls nằm bên trong `content` dưới dạng `{"type": "tool_use", ...}` blocks, không có trường `tool_calls` riêng.

---

### `event.hook_triggered()`

Được phát khi một hook kích hoạt. Ghép với `hook_completed`; SDK tự động tính toán `duration_ms`.

```python
agenteye.event.hook_triggered(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",   # str, required
    hook_id="hook-abc",         # str, required - correlation key
    trigger_event="tool_use",   # str | None
    input={"tool": "search"},   # Any | None
)
```

---

### `event.hook_completed()`

Được phát khi một hook kết thúc. Tương quan với `hook_triggered` qua `hook_id`.

```python
agenteye.event.hook_completed(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",
    hook_id="hook-abc",         # must match the prior hook_triggered
    outcome="allow",            # str | None
    output=None,                # Any | None
    error=None,                 # str | None
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.error()`

Được phát khi một lỗi unhandled xảy ra.

```python
agenteye.event.error(
    session_id="run-001",
    agent_id="planner",
    error_type="TimeoutError",  # str, required
    message="timed out",        # str, required
    traceback="Traceback...",   # str | None
)
```

## Sự kiện Human-in-the-Loop

Các sự kiện human-in-the-loop cung cấp cho bạn sự giám sát những khoảnh khắc mà một người bước vào quá trình thực hiện của agent (chờ phê duyệt, cung cấp input, tạm dừng, hoặc dừng agent). Chúng cho phép bạn đo lường thời gian con người cần để phản ứng (SDK tự động tính toán `duration_ms` trên các sự kiện được ghép nối), audit người đã tạm dừng hoặc gián đoạn một agent, và xây dựng các luồng công việc phê duyệt và giám sát bề mặt trong dashboard.

### `event.human_wait()`

Được phát khi agent tạm dừng thực hiện để chờ một con người cung cấp input. Ghép với `human_input`; SDK tự động tính toán `duration_ms` (con người mất bao lâu để phản ứng).

```python
agenteye.event.human_wait(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",                          # str, required - correlation key for the matching human_input
    prompt="Do you approve this action?",        # str | None - the question shown to the human
    options=["approve", "reject", "defer"],      # list[str] | None - choices presented to the human
    reason="approval_required",                  # str | None - why the agent is waiting
)
```

### `event.human_input()`

Được phát khi một con người cung cấp input và agent tiếp tục. Tương quan với `human_wait` qua `input_id`. `duration_ms` được tự động tính toán và không được truyền bởi caller.

```python
agenteye.event.human_input(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",    # str, required - must match the prior human_wait
    response="approve",    # str | None - the human's answer (free text or selected option)
    # duration_ms is computed automatically - do not pass it
)
```

### `event.human_pause()`

Được phát khi một con người actively tạm dừng agent (ví dụ qua một dashboard control). Agent bị suspend nhưng không bị terminate.

```python
agenteye.event.human_pause(
    session_id="run-001",
    agent_id="planner",
    reason="user_requested",  # str | None
    user_id="usr_42",         # str | None - who paused the agent
)
```

### `event.human_interrupt()`

Được phát khi một con người actively dừng agent giữa quá trình thực hiện. Không giống như `human_pause`, công việc của agent bị terminate thay vì suspend.

```python
agenteye.event.human_interrupt(
    session_id="run-001",
    agent_id="planner",
    reason="output_incorrect",       # str | None
    user_id="usr_42",                # str | None - who interrupted the agent
    at_step="tool_use:web_search",   # str | None - what the agent was doing when stopped
)
```

## Custom Fields

Bất kỳ keyword arguments thêm nào được thêm vào sự kiện sau các trường chuẩn:

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="db_query",
    tool_call_id="toolu_02",
    tenant_id="acme",           # custom field
    region="us-east-1",         # custom field
)
```

`timestamp`, `type`, và `environment` được bảo vệ và tăng `ValueError` (`Reserved field names cannot be used as custom fields: [...]`) nếu được truyền dưới dạng custom fields. `session_id` và `agent_id` là required parameters trên mỗi phương thức event và không thể được cung cấp một lần thứ hai; Python tăng `TypeError` nếu bạn làm như vậy. Đặt environment với `configure(environment=...)` (hoặc biến `AGENTEYE_ENVIRONMENT`) thay thế.

Giữ payloads như structured JSON khi bạn muốn truy vấn các trường của chúng. Các giá trị mà JSON không natively hỗ trợ — chẳng hạn như datetimes, UUIDs, decimals, sets, bytes, hoặc model objects — được chuyển đổi thành strings để ghi lại tiếp tục an toàn.

## Cách Sự kiện Được Viết

Sự kiện được buffer trong-process và flushed vào disk mỗi `flush_interval` giây (mặc định 500 ms). Mỗi flush viết một file JSONL:

```text
~/.agenteye/events/event-2026-04-01T12-00-00-000Z.jsonl
```

Collector theo dõi thư mục này và tải lên files tự động. Bạn không cần quản lý các files này trực tiếp.

Mỗi file được viết atomically: SDK viết vào một file tạm thời và sau đó đổi tên nó vào vị trí, vì vậy collector không bao giờ thấy một file half-written. Một flush cuối cùng cũng chạy khi process của bạn thoát, vì vậy sự kiện được buffer trong interval cuối cùng không bị mất. Nếu collector offline, sự kiện đơn giản là tích tụ dưới dạng files trên disk và ship khi nó quay trở lại.
