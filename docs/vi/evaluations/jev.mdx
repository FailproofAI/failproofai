A Jev evaluation reads a **finished session** and gives a score from 0 to 1. Use it when the answer is known in advance, such as "Did the customer express urgency?" or "How frustrated was the customer?" It helps you find patterns across runs; it does not stop a tool call. For decisions made **before** a tool runs, use [Jev policies](/vi/policies/jev).

## Create one in the dashboard

1. Open **analyse → checks → new evaluation** and choose **decision model** under **how should it score?**.
2. Describe one question and its possible answers. For example: "Did the agent promise a refund before checking the refund policy? Answer yes or no." On **review**, check the **question** and what **yes means** and **no means**; a decision model always gives a score.
3. [Try it](/vi/evaluations/test) on recent sessions, then [deploy it](/vi/evaluations/deploy). New completed sessions are scored; [backfill](/vi/evaluations/deploy#score-sessions-you-already-have) if you also need history.

![The shared eval authoring form, where you describe a fixed-answer question, review the draft, and deploy after testing. The example shown is a code evaluation; a Jev question uses the same authoring flow.](/images/dashboard/eval-authoring-draft.png)

When it drafts, failproof can choose between **code**, a **decision model** (Jev), and an [**llm as judge**](/vi/evaluations/judge). Check its choice before deploying. Jev gives a score without prose reasoning; choose a judge when you need an explanation. See the [Jev evaluation reference](/vi/reference/jev-evaluations) for question types and score limits.

## Read the scores

Open **analyse → checks → evals** and select the evaluation to chart the result by agent and time. From a terminal, the Cloud CLI can read the same results:

```bash
fp evals --since 7d
fp evals --aggregate --since 7d
```

From a terminal, `fp evaluators` authors and deploys Jev evaluations and `fp evals` reads their results. See the [Cloud CLI reference](/vi/reference/cloud-cli#evaluations) for both.
