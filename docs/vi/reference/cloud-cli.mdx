Sử dụng `fp` để kiểm tra telemetry của Cloud, quản lý enforcement được quản lý bởi cloud (policies, fleet deployments, guardrail decisions), và quản lý audits, findings, issues, alerts, keys, users, queries, và settings. Sử dụng [`failproofai`](/vi/reference/failproof-cli) cho local hooks, policies, capture, và machine enrollment.

Cài đặt Cloud CLI phát hành dưới dạng công cụ độc lập:

```bash
uv tool install fp-cloud-cli
fp version
```

## Đăng nhập

```bash
fp login
fp whoami
```

## Cú pháp

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Các tùy chọn toàn cục phải đứng trước lệnh:

```bash
fp --json sessions --since 24h
```

Chạy `fp COMMAND --help` hoặc `fp COMMAND SUBCOMMAND --help` để xem trợ giúp trên terminal.


### Sự kiện

```text
fp events [OPTIONS]
```

Liệt kê các sự kiện agent riêng lẻ. Bộ feed nhẹ mặc định loại trừ các payload thô; chỉ sử dụng `--full` cho một cuộc điều tra có giới hạn.

| Tùy chọn | Mô tả |
| --- | --- |
| `--limit`, `-n <n>` | Số hàng tối đa. Mặc định: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, hoặc `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Phạm vi UTC ISO 8601; ghi đè `--since`. |
| `--env <value>` | Bộ lọc môi trường; lặp lại hoặc phân cách bằng dấu phẩy. |
| `--event-type <value>` | Bộ lọc loại sự kiện; lặp lại hoặc phân cách bằng dấu phẩy. |
| `--agent-id <value>` | Bộ lọc agent; lặp lại hoặc phân cách bằng dấu phẩy. |
| `--session-id <value>` | Bộ lọc session; lặp lại hoặc phân cách bằng dấu phẩy. |
| `--search <text>` | Tìm kiếm payload; có thể lặp lại, bất kỳ thuật ngữ nào cũng khớp. |
| `--order asc\|desc` | Thứ tự thời gian. Mặc định: mới nhất trước. |
| `--all` | Tự động phân trang cho đến `--limit`. |
| `--cursor <token>` | Tiếp tục từ một con trỏ không rõ. |
| `--page-size <n>` | Hàng trên mỗi yêu cầu với `--all`; tối đa `200`. |
| `--full` | Bao gồm payload thô thông qua endpoint sự kiện nặng hơn. |
| `--fields <csv>` | Chỉ trả về các trường đã chọn; yêu cầu `payload` kích hoạt chế độ đầy đủ. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` phân trang **lên đến `--limit`**, mặc định là **50** — vì vậy `--all` tự nó dừng ở 50 hàng. Khi nó dừng sớm, phản hồi mang theo `next_cursor` để tiếp tục từ đó; `"next_cursor": null` có nghĩa feed thực sự đã cạn kiệt.
</Note>

### Khóa API

| Lệnh | Mục đích | Tùy chọn |
| --- | --- | --- |
| `fp keys list` | Liệt kê các khóa tổ chức. | `--show-id`; `--fields <csv>` |
| `fp keys show NAME` | Hiển thị một khóa và các quyền của nó. | — |
| `fp keys create NAME` | Tạo một khóa và tiết lộ bí mật của nó một lần. | `--permission-set`; `--add`; `--remove` |
| `fp keys update NAME` | Thay thế bộ quyền hoặc điều chỉnh các quyền. | `--permission-set`; `--add`; `--remove`; `--yes`, `-y` |

| `fp keys disable NAME` | Vĩnh viễn thu hồi một khóa. | `--yes`, `-y` |

Các token quyền sử dụng `resource:action`, chẳng hạn như `events:add`. Lặp lại `--add`, phân cách bằng dấu phẩy, hoặc sử dụng các hành động có dấu chấm như `events:read.add`.

#### Tùy chọn create audit

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Tùy chọn | Mô tả |
| --- | --- |
| `--file <path>` | Dựa định nghĩa trên JSON, hoặc sử dụng `-` cho stdin. Các flag rõ ràng ghi đè các giá trị của file. |
| `--description <text>` | Nêu câu hỏi lỗi hoặc mục đích. |
| `--enabled` / `--disabled` | Bắt đầu lập lịch bật hoặc tắt. Mặc định: bật. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Mặc định: `86400`. |
| `--schedule-anchor <timestamp>` | Giai đoạn UTC cố định ở dạng ISO 8601. Mặc định: 09:00 UTC tiếp theo. |
| `--window-mode since_last\|fixed` | Tiếp tục sau cửa sổ được phân tích hoàn toàn cuối cùng hoặc lặp lại kiểm tra một cửa sổ lăn. Mặc định: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Mặc định: `604800`. |
| `--scope '<json>'` | Lọc theo `environments`, `agent_ids`, hoặc các trường phạm vi được hỗ trợ khác. |
| `--ignore-error-type <type>` | Loại trừ các loại lỗi; lặp lại hoặc phân cách bằng dấu phẩy. |
| `--llm` / `--no-llm` | Bật hoặc tắt phân tích agentic. Mặc định: bật. |
| `--top-k <n>` | Giữ lại `1`–`500` findings. Mặc định: `50`. |
| `--sensitivity low\|medium\|high` | Đặt độ nhạy báo cáo. Mặc định: `medium`. |
| `--channels '<json>'` | Mảng kênh thông báo. |
| `--text <brief>` | Tóm tắt nội tuyến, tối đa 8.192 ký tự. |
| `--text-file <path>` | Đọc tóm tắt từ một file; loại trừ lẫn nhau với `--text`. |
| `--url <https-url>` | Thêm một tài liệu tham khảo HTTPS công khai; lặp lại lên đến năm lần. |

Bao gồm ngữ cảnh trong khi tạo khi lần chạy đầu tiên cần nó. Tạo cam kết định nghĩa và ngữ cảnh cùng nhau trước khi lần chạy được xếp hàng bắt đầu.

<Note>
  `fp audits run` là không đồng bộ. Kiểm tra `fp audits runs NAME` cho đến khi lần chạy mới nhất thành công hoặc thất bại trước khi đọc các findings của nó.
</Note>

| `fp issues comment-add INCIDENT_ID` | Thêm một bình luận. | chính xác một trong `--body`, `--file` |
| `fp issues comment-delete INCIDENT_ID COMMENT_ID` | Xóa một bình luận. | `--yes`, `-y` |
| `fp issues subscribers INCIDENT_ID` | Liệt kê người đăng ký. | — |
| `fp issues subscribe INCIDENT_ID` | Đăng ký chính mình hoặc một nhà khai thác khác. | `--email` |

Các trạng thái vấn đề hợp lệ là `firing`, `acknowledged`, và `resolved`. Các mức độ vấn đề độc lập là `info`, `warning`, và `critical`.

### Policies

Các phiên bản policy được quản lý bởi cloud. **Session-only** — mọi lệnh ở đây thoát với mã `2` dưới một khóa API, trước bất kỳ yêu cầu nào, bởi vì đây là các tuyến ghi chỉ root được cố ý loại trừ khỏi `/v1`.

| Lệnh | Mục đích | Tùy chọn |
| --- | --- | --- |
| `fp policies list` | Liệt kê các phiên bản policy. | `--json` |
| `fp policies show POLICY_ID` | Hiển thị một policy, với mã nguồn của nó. | — |
| `fp policies publish NAME PATH` | Tạo một phiên bản từ một `.mjs` cục bộ. | `--description`; `--no-verify` |
| `fp policies enable POLICY_ID` | Thêm nó lại vào mọi deployment nó đã bị xóa khỏi, tạo một thế hệ mới trên mỗi deployment. | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | Xóa nó khỏi mọi deployment chứa nó, tạo một thế hệ mới trên mỗi deployment. | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | Xóa một phiên bản policy. | `--yes`, `-y` |
| `fp policies test PATH` | Chạy một policy tại chỗ so với một ngữ cảnh tổng hợp. Áp dụng bộ lọc `match` của mỗi policy, vì vậy một policy không bao gồm sự kiện/công cụ được cho sẽ được báo cáo `skipped` thay vì được chạy. | `--event`; `--tool`; `--command`; `--file`; `--expect` |
| `fp policies compose PROMPT` | Soạn thảo một policy với trợ lý. Cần `policies:write`. | — |

## Các flag toàn cục

| Flag | Mô tả |
| --- | --- |
| `--json` | Phát ra JSON có thể đọc bằng máy. |
| `--base-url <url>` | Sử dụng một dashboard tự lưu trữ hoặc phát triển. |
| `--org <slug>` | Chọn một tổ chức cho lệnh này. |
| `--token <token>` | Ghi đè token phiên người dùng đã lưu. |
| `--api-key <key>` | Xác thực tự động bằng khóa API; không bao giờ được lưu. |
| `--timeout <seconds>` | Timeout HTTP; phải dương. Mặc định: `30`. |
| `--quiet`, `-q` | Supress đầu ra trạng thái trên stderr. |
| `--no-color` | Vô hiệu hóa đầu ra màu. |
| `--insecure` / `--secure` | Vô hiệu hóa hoặc khôi phục xác minh chứng chỉ TLS. |
| `--version` | In phiên bản không được bọc và thoát. |
| `--help`, `-h` | Hiển thị trợ giúp. |

`--api-key` dành cho tự động hóa. Đăng nhập, chuyển tổ chức, và lệnh trợ lý yêu cầu một phiên người dùng.

| Biến | Tương đương hoặc mục đích |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |
| `FP_ORG` | `--org` |

| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | Chuyển vị trí thư mục cấu hình CLI (mặc định `~/.failproofai/fpcli`). |

Các flag rõ ràng ghi đè các biến môi trường, lại ghi đè cấu hình đã lưu. Trong chế độ khóa API, chọn tenant rõ ràng bằng `--org` hoặc `FP_ORG`.

<Warning>
  Các chính tả `AGENTEYE_*` của chúng **không được đọc bởi `fp`** và không bao giờ được — CLI khai báo `FP_*` (`fp_cli/app.py`), và một biến không xác định không phải là một lỗi. Đặt `AGENTEYE_DASHBOARD_URL` không định hướng lại CLI; nó bị bỏ qua và lệnh im lặng chạy lại dashboard đã lưu thay vì.

  `AGENTEYE_HOME` và `AGENTEYE_ENVIRONMENT` vẫn tồn tại, nhưng chúng thuộc về **bộ thu thập và telemetry SDK**, không phải CLI này.
</Warning>

<Warning>
  Các lệnh xóa, thu hồi, supress, giải quyết, hoặc thay thế cấu hình nhắc theo mặc định. Chỉ sử dụng `--yes` sau khi xác minh tổ chức hoạt động và mục tiêu.
</Warning>
