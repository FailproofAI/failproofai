Sử dụng `fp` để kiểm tra telemetry của Cloud, quản lý enforcement do cloud quản lý (policies, fleet deployments, guardrail decisions), và quản lý audits, findings, issues, alerts, keys, users, queries, và settings. Sử dụng [`failproofai`](/vi/reference/failproof-cli) cho local hooks, policies, capture, và machine enrollment.

Bạn cũng có thể tạo và triển khai mã được hosted, LLM-judge và Jev evaluators, quản lý dashboards, kiểm tra sentiment, và sử dụng dashboard assistant từ terminal.

Cài đặt Cloud CLI phát hành dưới dạng công cụ độc lập:

```bash
uv tool install fp-cloud-cli
fp version
```

## Đăng nhập

```bash
fp login
fp whoami
```

## Cú pháp

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Các tuỳ chọn toàn cục phải đứng trước lệnh:

```bash
fp --json sessions --since 24h
```

Chạy `fp COMMAND --help` hoặc `fp COMMAND SUBCOMMAND --help` để xem trợ giúp trên terminal.

## Các lệnh CLI

### Tạo một evaluator

`fp evaluators` tạo định nghĩa; `fp evals` đọc kết quả. Cần một instance managed được bật (`fp evaluators instances`). Tạo cần `evaluations:trigger`; session dry-runs và schema profiling cũng cần `events:read`.

Code là một biểu thức Python bị hạn chế. Lưu cái này thành `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM judge:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev binary và graded rubric:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
Tạo bật evaluator. Deploy tạo một phiên bản bất biến mới, sau đó tắt các phiên bản bật cũ hơn. Một follow-up thất bại để lại phiên bản mới được phát hành: kiểm tra `evaluators list --all` trước khi thử lại.
Judge dry-runs bị từ chối bởi Cloud. Jev dry-runs chi tiêu ngân sách model.
Backfill bao gồm code, judge và Jev evaluators và chấp nhận tối đa 90 ngày; nó chỉ xếp hàng các session mà evaluator chưa chấm điểm. Judge và Jev backfills chi tiêu ngân sách model, vì vậy chạy `fp evaluators backfill --dry-run` trước.
Output của con người hiển thị kết quả dry-run theo mỗi session trước khi tạo/triển khai.
Các bản xem trước thất bại dừng lại việc ghi trừ khi bạn rõ ràng chuyển `--force` sau khi xem xét.
</Warning>

AI drafting yêu cầu `fp login` và viết một spec được chấp nhận bởi create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Lệnh | Tuỳ chọn / Hành vi |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Full source/envelope |
| `fp evaluators create` | `--key`, `--name`, `--version`, lặp `--label`, `--condition EXPR\|@file`, một source, lặp `--dry-run-on`, `--disabled`, `--force` rõ ràng cho các bản xem trước thất bại |
| `fp evaluators deploy KEY` | Cùng các cờ source; `--version`, `--backfill 7d` (bất kỳ loại nào, 1–90 ngày), `--force`; các phiên bản số tự động tăng; KEY cung cấp một spec-file `eval_key` bị thiếu |
| `fp evaluators draft "intent"` | Session; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Cờ source hoặc `--file`, lặp `--session` (tối đa 10); không có = chỉ compile |
| `fp evaluators enable\|disable KEY[@VERSION]` | Chuyển đổi |
| `fp evaluators label KEY[@VERSION]` | Lặp `--add`, `--remove` |
| `fp evaluators instances\|schema\|jobs` | Kiểm tra managed fleet/schema/jobs |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; code, judge và Jev |

Các cờ Code là `--code FILE|-`, `--result-kind score|metric|assertion`,
`--timeout S`. Các cờ Judge là `--judge --criteria TEXT`, lặp `--step` và
`--threshold`. Các cờ Jev là `--jev noul --instructions --true --false` hoặc
`--jev score --instructions` với 3–5 giá trị `--level` phân biệt, trường hợp xấu nhất trước tiên.
Judge/Jev yêu cầu một score; thresholds là 0–1. Binary judge steps bị từ chối.

Các spec files chứa chính xác `eval_key`, `display_name`, `eval_version`,
`result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
Judge/Jev `evaluator_source` là một chuỗi JSON envelope. Không bao gồm row ids,
enabled state, hoặc AI reasoning metadata. `--file` và discrete spec flags là loại trừ nhau; deploy có thể ghi đè phiên bản của file. Các file output không bao giờ bị ghi đè.

### Các điều khiển dashboard mới

Tất cả các lệnh chấp nhận global `--json`. Unknown-route 404s thoát 6 với "not available
on this FailproofAI Cloud yet". Missing-record 404s cũng thoát 6 nhưng báo cáo rằng record
không được tìm thấy. Các lệnh chỉ session từ chối key mode trước HTTP (exit 2).

Các lệnh Human sử dụng summaries và tables. Để xuất raw JSON, chuyển global
`--json` hoặc lưu với `--out FILE`; nếu không session và JSON query exports hiển thị
một view có thể đọc được. CSV exports vẫn là plain CSV để piping.

| Lệnh | Tuỳ chọn / Ghi chú |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | Tạo `--name`, `--description`, `--file` định nghĩa; update giữ nguyên các trường không được đề cập |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | Thêm `--query ID --chart TYPE --title`; config/geometry hoặc layout qua `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | Export `--out`; history là evaluation history |
| `fp sessions import FILE...` | Claude Code transcripts, Codex rollouts hoặc event JSONL (`.gz` ok); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; cần `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; list `--limit`; messages `--session-id` |
| `fp query compose "question"` | Session; `--run` |
| `fp query export [ID]` | Hoặc `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Issues có thể `--create --title --summary` hoặc `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; update `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | Session; dự thảo policy từ events của tổ chức của bạn, không bao giờ phát hành |
| `fp policies backtest [FILE_OR_ID]` | Session; regex phát lại module; `jev`/`both` (published, hoặc `--semantic checks.json`) ước tính miễn phí, `--run [--sample N]` chi tiêu Jev allowance; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | Session; một policy có thể ngăn chặn vấn đề này |
| `fp issues facets` | Các giá trị mà các bộ lọc inbox có thể nhận, với số lượng |
| `fp agent brief` | Session; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | Session; dẫn xuất slug bị bỏ qua, không chuyển đổi org |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | Bộ quyền; tạo `--name --permission`; update thay thế `--permission` hoặc hợp nhất `--add/--remove`; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | Xóa theo id |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` cần API key; plan (offers và trial) và claim yêu cầu session đã đăng nhập |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 tokens |
| `fp otel status\|enable\|disable` | Cloud org ingest switch, không phải local capture |
| `fp slack status\|disconnect` | Session |

`fp agent ask` hiển thị artifact SQL dưới dạng bảng/thống kê thông qua `queries:run`.
Các phê duyệt ghi hiển thị thay đổi được đề xuất và yêu cầu trên terminal. Scripts và
`--json` từ chối trừ khi `--approve` rõ ràng. Các hình dạng JSON hiện có vẫn không thay đổi
khi không có artifact trả về.

### Events

```text
fp events [OPTIONS]
```

Liệt kê các agent events riêng lẻ. Feed nhẹ mặc định loại trừ raw payloads; sử dụng `--full` chỉ cho một cuộc điều tra bị giới hạn.

| Tuỳ chọn | Mô tả |
| --- | --- |
| `--limit`, `-n <n>` | Tổng hàng tối đa. Mặc định: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, hoặc `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Phạm vi UTC ISO 8601; ghi đè `--since`. |
| `--env <value>` | Bộ lọc Environment; lặp hoặc phân tách bằng dấu phẩy. |
| `--event-type <value>` | Bộ lọc event-type; lặp hoặc phân tách bằng dấu phẩy. |
| `--agent-id <value>` | Bộ lọc Agent; lặp hoặc phân tách bằng dấu phẩy. |
| `--session-id <value>` | Bộ lọc Session; lặp hoặc phân tách bằng dấu phẩy. |
| `--search <text>` | Tìm kiếm văn bản payload; có thể lặp lại, với bất kỳ thuật ngữ nào khớp. |
| `--order asc\|desc` | Thứ tự thời gian. Mặc định: mới nhất trước. |
| `--all` | Tự động phân trang lên tới `--limit`. |
| `--cursor <token>` | Tiếp tục từ con trỏ opaque. |
| `--page-size <n>` | Hàng mỗi yêu cầu với `--all`; tối đa `200`. |
| `--full` | Bao gồm raw payloads thông qua endpoint event nặng hơn. |
| `--fields <csv>` | Chỉ trả lại các trường đã chọn; yêu cầu `payload` bật chế độ đầy đủ. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` phân trang **lên tới `--limit`**, mặc định là **50** — vì vậy `--all` tự nó dừng ở 50 hàng. Khi nó dừng sớm, phản hồi chứa một
  `next_cursor` để tiếp tục từ; `"next_cursor": null` có nghĩa là feed thực sự đã
  được cạn kiệt.
</Note>

#### Audit create options

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Tuỳ chọn | Mô tả |
| --- | --- |
| `--file <path>` | Dựa trên định nghĩa JSON, hoặc sử dụng `-` cho stdin. Các cờ rõ ràng ghi đè giá trị của file. |
| `--description <text>` | Nêu câu hỏi thất bại hoặc mục đích. |
| `--enabled` / `--disabled` | Bắt đầu lập lịch bật hoặc tắt. Mặc định: bật. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Mặc định: `86400`. |
| `--schedule-anchor <timestamp>` | Giai đoạn UTC cố định ở dạng ISO 8601. Mặc định: 09:00 UTC tiếp theo. |
| `--window-mode since_last\|fixed` | Tiếp tục sau cửa sổ được phân tích hoàn toàn cuối cùng hoặc lặp lại kiểm tra một cửa sổ lăn. Mặc định: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Mặc định: `604800`. |
| `--scope '<json>'` | Lọc theo `environments`, `agent_ids`, hoặc các trường scope được hỗ trợ khác. |
| `--ignore-error-type <type>` | Loại trừ error types; lặp hoặc phân tách bằng dấu phẩy. |
| `--llm` / `--no-llm` | Bật hoặc tắt agentic analysis. Mặc định: bật. |
| `--top-k <n>` | Giữ `1`–`500` findings. Mặc định: `50`. |
| `--sensitivity low\|medium\|high` | Đặt độ nhạy báo cáo. Mặc định: `medium`. |
| `--channels '<json>'` | Mảng notification channel. |
| `--text <brief>` | Brief nội dòng, tối đa 8,192 ký tự. |
| `--text-file <path>` | Đọc brief từ một file; loại trừ lẫn nhau với `--text`. |
| `--url <https-url>` | Thêm một tham chiếu HTTPS công khai; lặp lại tới năm lần. |

Bao gồm context trong quá trình tạo khi lần chạy đầu tiên cần nó. Tạo cam kết định nghĩa và context với nhau trước khi quá trình chạy được xếp hàng bắt đầu.

<Note>
  `fp audits run` là bất đồng bộ. Poll `fp audits runs NAME` cho đến khi lần chạy mới nhất thành công hoặc thất bại trước khi đọc các findings của nó.
</Note>
