Sử dụng `fp` để kiểm tra telemetry của Cloud, quản lý enforcement do cloud quản lý (chính sách, triển khai fleet, quyết định guardrail), và quản lý kiểm toán, phát hiện, vấn đề, cảnh báo, khóa, người dùng, truy vấn và cài đặt. Sử dụng [`failproofai`](/vi/reference/failproof-cli) cho các hook cục bộ, chính sách, capture và đăng ký máy.

Bạn cũng có thể tạo và triển khai mã được lưu trữ, các trình đánh giá LLM-judge và Jev, quản lý bảng điều khiển, kiểm tra tâm lý và sử dụng trợ lý bảng điều khiển từ thiết bị đầu cuối.

Cài đặt Cloud CLI đã phát hành như một công cụ độc lập:

```bash
uv tool install fp-cloud-cli
fp version
```

## Đăng nhập

```bash
fp login
fp whoami
```

## Cú pháp

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

Các tùy chọn toàn cục phải đứng trước lệnh:

```bash
fp --json sessions --since 24h
```

Chạy `fp COMMAND --help` hoặc `fp COMMAND SUBCOMMAND --help` để xem trợ giúp trên thiết bị đầu cuối.

## Lệnh CLI

### Tạo một bộ đánh giá

`fp evaluators` tạo các định nghĩa; `fp evals` đọc kết quả. Cần có một instance được quản lý được bật (`fp evaluators instances`). Tạo cần `evaluations:trigger`; các lần chạy khô và hồ sơ lược đồ cũng cần `events:read`.

Mã là một biểu thức Python bị hạn chế. Lưu này dưới dạng `error_free.py`:

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

Bộ đánh giá LLM:

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Nhị phân Jev và rubric được xếp hạng:

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
Tạo bất kỳ bộ đánh giá nào. Deploy tạo một phiên bản bất biến mới, sau đó vô hiệu hóa các phiên bản được bật cũ hơn. Lỗi follow-up để phiên bản mới được xuất bản: kiểm tra `evaluators list --all` trước khi thử lại.
Các lần chạy khô của Judge bị từ chối bởi Cloud. Các lần chạy khô của Jev tiêu tốn ngân sách mô hình.
Backfill bao gồm các bộ đánh giá code, judge và Jev và chấp nhận tối đa 90 ngày; nó chỉ xếp hàng các phiên mà một bộ đánh giá chưa chấm điểm. Các backfill của Judge và Jev tiêu tốn ngân sách mô hình, vì vậy hãy chạy `fp evaluators backfill --dry-run` trước.
Đầu ra của người dùng cho thấy kết quả lần chạy khô cho mỗi phiên trước khi tạo/triển khai.
Bản xem trước không thành công sẽ dừng quá trình ghi trừ khi bạn rõ ràng chuyển `--force` sau khi xem xét.
</Warning>

Dự thảo AI yêu cầu `fp login` và viết một đặc tả được chấp nhận bởi create/deploy:

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# Review the draft's key, source and condition before enabling it.
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| Lệnh | Tùy chọn / hành vi |
| --- | --- |
| `fp evaluators list` | `--key`, `--all` |
| `fp evaluators show KEY[@VERSION]` | Nguồn và phong bì đầy đủ |
| `fp evaluators create` | `--key`, `--name`, `--version`, `--label` lặp lại, `--condition EXPR\|@file`, một nguồn, `--dry-run-on` lặp lại, `--disabled`, `--force` rõ ràng cho các bản xem trước không thành công |
| `fp evaluators deploy KEY` | Các cờ nguồn tương tự; `--version`, `--backfill 7d` (bất kỳ loại nào, 1–90 ngày), `--force`; các phiên bản số tự động tăng; KEY cung cấp một `eval_key` spec-file bị thiếu |
| `fp evaluators draft "intent"` | Phiên; `--kind code\|judge\|jev`, `--out` |
| `fp evaluators dry-run` | Cờ nguồn hoặc `--file`, `--session` lặp lại (tối đa 10); none = chỉ compile |
| `fp evaluators enable\|disable KEY[@VERSION]` | Chuyển đổi |
| `fp evaluators label KEY[@VERSION]` | `--add` lặp lại, `--remove` |
| `fp evaluators instances\|schema\|jobs` | Kiểm tra fleet/schema/jobs được quản lý |
| `fp evaluators backfill` | `--from`, `--to`, `--key`, `--dry-run`; code, judge và Jev |

Các cờ mã là `--code FILE|-`, `--result-kind score|metric|assertion`, `--timeout S`. Các cờ Judge là `--judge --criteria TEXT`, `--step` lặp lại và `--threshold`. Các cờ Jev là `--jev noul --instructions --true --false` hoặc `--jev score --instructions` với các giá trị `--level` riêng biệt 3–5, tệ nhất trước tiên.
Judge/Jev yêu cầu một điểm; các ngưỡng là 0–1. Các bước judge nhị phân bị từ chối.

Các tệp đặc tả chứa chính xác `eval_key`, `display_name`, `eval_version`, `result_kind`, `labels`, `condition_source`, `evaluator_source`, `timeout_seconds`.
Judge/Jev `evaluator_source` là một chuỗi phong bì JSON. Không bao gồm các id hàng, trạng thái được bật hoặc siêu dữ liệu lập luận AI. `--file` và cờ đặc tả rời rạc loại trừ lẫn nhau; deploy có thể ghi đè phiên bản của tệp. Các tệp đầu ra không bao giờ bị ghi đè.

### Các điều khiển bảng điều khiển mới

Tất cả các lệnh chấp nhận `--json` toàn cục. 404 route không xác định thoát 6 với "not available on this FailproofAI Cloud yet". 404 bản ghi bị thiếu cũng thoát 6 nhưng báo cáo rằng bản ghi không được tìm thấy. Các lệnh chỉ cho phiên từ chối chế độ khóa trước HTTP (thoát 2).

Các lệnh con người sử dụng tóm tắt và bảng. Đối với các xuất JSON thô, chuyển `--json` toàn cục hoặc lưu bằng `--out FILE`; ngoài ra các xuất truy vấn phiên và JSON hiển thị một chế độ xem có thể đọc được. Các xuất CSV vẫn là CSV thuần túy để ống dẫn.

| Lệnh | Tùy chọn / ghi chú |
| --- | --- |
| `fp dashboards list\|show ID\|create\|update ID\|delete ID` | Tạo `--name`, `--description`, `--file` định nghĩa; cập nhật bảo toàn các trường không được đề cập |
| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | Thêm `--query ID --chart TYPE --title`; config/geometry hoặc layout qua `--file` |
| `fp sessions show\|export\|history\|re-evaluate ID` | Xuất `--out`; history là lịch sử đánh giá |
| `fp sessions import FILE...` | Claude Code transcripts, Codex rollouts hoặc event JSONL (`.gz` ok); `--format auto\|failproofai\|claude\|codex`, `--env`, `--dry-run`; cần `events:add` |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`; liệt kê `--limit`; tin nhắn `--session-id` |
| `fp query compose "question"` | Phiên; `--run` |
| `fp query export [ID]` | Hoặc `--sql`; `--format csv\|json`, `--out` |
| `fp alerts recipients` / `fp alerts issues ID` | Các vấn đề có thể `--create --title --summary` hoặc `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`, `--body TEXT\|@file`, `--file` JSON; cập nhật `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | Phiên; dự thảo một chính sách từ các sự kiện của tổ chức bạn, không bao giờ xuất bản |
| `fp policies backtest [FILE_OR_ID]` | Phiên; regex phát lại mô-đun; `jev`/`both` (được xuất bản, hoặc `--semantic checks.json`) ước tính miễn phí, `--run [--sample N]` tiêu tốn phụ cấp Jev; `--kind`, `--hours`, `--agent-id`, `--env` |
| `fp policies candidacy --issue ID` | Phiên; có thể một chính sách ngăn chặn vấn đề này |
| `fp issues facets` | Các giá trị mà các bộ lọc hộp thư đến có thể nhận, với số lượng |
| `fp agent brief` | Phiên; `--range 24h\|7d` |
| `fp orgs create --name N [--slug S]` | Phiên; suy ra slug bị bỏ qua, không chuyển tổ chức |
| `fp roles list\|show NAME\|create\|update NAME\|delete NAME` | Bộ quyền; tạo `--name --permission`; cập nhật thay thế `--permission` hoặc hợp nhất `--add/--remove`; `--description`, `--file` |
| `fp users delete ID` / `fp users defaults` | Xóa theo id |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` cần một khóa API; kế hoạch (offers và trial) và yêu cầu yêu cầu một phiên đã đăng nhập |
| `fp settings context-windows list\|set MODEL TOKENS\|delete MODEL` | 0–1000000 mã thông báo |
| `fp otel status\|enable\|disable` | Cloud org ingest switch, không phải capture cục bộ |
| `fp slack status\|disconnect` | Phiên |

`fp agent ask` hiển thị SQL thành tạo vật như bảng/thống kê thông qua `queries:run`.
Phê duyệt viết hiển thị thay đổi được đề xuất và nhắc trên thiết bị đầu cuối. Các tập lệnh và `--json` từ chối trừ khi `--approve` rõ ràng. Các hình dạng JSON hiện có vẫn không thay đổi khi không có thành phố được trả lại.

Trên thiết bị đầu cuối, `fp login` bắt đầu trên một liên kết để đăng nhập bằng trình duyệt hoặc SSO của bạn và mở nó (qua SSH hoặc không có hiển thị, nó chỉ hiển thị nó và hoạt động từ bất kỳ thiết bị nào); ủy quyền nó và thiết bị đầu cuối kết thúc riêng của nó. Thiết bị đầu cuối đó nhận được quyền truy cập của bạn trong tất cả các tổ chức của bạn cho đến khi phiên hết hạn, vì vậy chỉ ủy quyền một liên kết mà bạn vừa yêu cầu. Nếu đăng nhập bắt đầu trên một mạng khác, bạn nhận được một email khi phiên tồn tại, và trang cảnh báo bạn nơi triển khai có thể cho bạn biết. Nhấn **Tab** để nhận mã 6 chữ số qua email, và nhấn Tab lần nữa để quay lại. `--email`, `--json` và bất cứ thứ gì không có thiết bị đầu cuối sử dụng mã.

### Sự kiện

```text
fp events [OPTIONS]
```

Liệt kê các sự kiện agent riêng lẻ. Nguồn cấp ánh sáng mặc định loại trừ các tải trọng thô; chỉ sử dụng `--full` cho một cuộc điều tra bị ràng buộc.

| Tùy chọn | Mô tả |
| --- | --- |
| `--limit`, `-n <n>` | Tối đa hàng tổng cộng. Mặc định: `50`. |
| `--since <window>` | `all`, `15m`, `1h`, `6h`, `24h`, hoặc `7d`. |
| `--from <timestamp>` / `--to <timestamp>` | Phạm vi UTC ISO 8601; ghi đè `--since`. |
| `--env <value>` | Bộ lọc môi trường; lặp lại hoặc phân cách bằng dấu phẩy. |
| `--event-type <value>` | Bộ lọc loại sự kiện; lặp lại hoặc phân cách bằng dấu phẩy. |
| `--agent-id <value>` | Bộ lọc agent; lặp lại hoặc phân cách bằng dấu phẩy. |
| `--session-id <value>` | Bộ lọc phiên; lặp lại hoặc phân cách bằng dấu phẩy. |
| `--search <text>` | Tìm kiếm văn bản tải trọng; có thể lặp lại, với bất kỳ thuật ngữ nào phù hợp. |
| `--order asc\|desc` | Thứ tự thời gian. Mặc định: mới nhất trước. |
| `--all` | Tự động phân trang lên đến `--limit`. |
| `--cursor <token>` | Tiếp tục từ con trỏ không rõ. |
| `--page-size <n>` | Hàng trên mỗi yêu cầu với `--all`; tối đa `200`. |
| `--full` | Bao gồm tải trọng thô thông qua điểm cuối sự kiện nặng hơn. |
| `--fields <csv>` | Trả về chỉ các trường được chọn; yêu cầu `payload` bật chế độ đầy đủ. |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` phân trang **lên đến `--limit`**, mặc định là **50** — vì vậy `--all` tự nó dừng lại tại 50 hàng. Khi nó dừng sớm, phản hồi mang lại `next_cursor` để tiếp tục từ; `"next_cursor": null` có nghĩa là nguồn cấp dữ liệu thực sự đã cạn kiệt.
</Note>

#### Tùy chọn tạo kiểm toán

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| Tùy chọn | Mô tả |
| --- | --- |
| `--file <path>` | Dựa trên định nghĩa JSON hoặc sử dụng `-` cho stdin. Các cờ rõ ràng ghi đè các giá trị tệp. |
| `--description <text>` | Phát biểu câu hỏi lỗi hoặc mục đích. |
| `--enabled` / `--disabled` | Bắt đầu lập lịch hoặc tắt. Mặc định: bật. |
| `--schedule-interval-secs <n>` | `3600`–`604800`. Mặc định: `86400`. |
| `--schedule-anchor <timestamp>` | Pha UTC cố định ở định dạng ISO 8601. Mặc định: 09:00 UTC tiếp theo. |
| `--window-mode since_last\|fixed` | Tiếp tục sau cửa sổ được phân tích đầy đủ cuối cùng hoặc lặp đi lặp lại kiểm tra một cửa sổ lăn. Mặc định: `since_last`. |
| `--lookback-window-secs <n>` | `3600`–`7776000`. Mặc định: `604800`. |
| `--scope '<json>'` | Lọc theo `environments`, `agent_ids` hoặc các trường phạm vi được hỗ trợ khác. |
| `--ignore-error-type <type>` | Loại trừ các loại lỗi; lặp lại hoặc phân cách bằng dấu phẩy. |
| `--llm` / `--no-llm` | Bật hoặc tắt phân tích agent. Mặc định: bật. |
| `--top-k <n>` | Giữ `1`–`500` phát hiện. Mặc định: `50`. |
| `--sensitivity low\|medium\|high` | Đặt độ nhạy báo cáo. Mặc định: `medium`. |
| `--channels '<json>'` | Mảng kênh thông báo. |
| `--text <brief>` | Bản tóm tắt nội dòng, tối đa 8.192 ký tự. |
| `--text-file <path>` | Đọc bản tóm tắt từ một tệp; loại trừ lẫn nhau với `--text`. |
| `--url <https-url>` | Thêm một tham khảo HTTPS công khai; lặp lại lên đến năm lần. |

Bao gồm bối cảnh trong quá trình tạo khi lần chạy đầu tiên cần nó. Tạo cam kết định nghĩa và bối cảnh cùng nhau trước khi lần chạy xếp hàng bắt đầu.

<Note>
  `fp audits run` là không đồng bộ. Thăm dò `fp audits runs NAME` cho đến khi lần chạy mới nhất thành công hoặc thất bại trước khi đọc các phát hiện của nó.
</Note>

| `FP_API_KEY` | `--api-key` |
| `FP_JSON` | `--json` |
| `FP_INSECURE` | `--insecure` |
| `FP_HOME` | Chuyển vị thư mục cấu hình CLI (mặc định `~/.failproofai/fpcli`). |
| `FP_ANALYTICS_DISABLED` hoặc `DO_NOT_TRACK` | Vô hiệu hóa phân tích CLI ẩn danh. |
| `NO_COLOR` | Vô hiệu hóa đầu ra có màu. |

Các cờ rõ ràng ghi đè các biến môi trường, ghi đè lên cấu hình đã lưu. Ở chế độ khóa API, chọn thuê bao rõ ràng với `--org` hoặc `FP_ORG`.

<Warning>
  Các cách viết `AGENTEYE_*` của những cách này **không được đọc bởi `fp`** và không bao giờ— CLI khai báo `FP_*` (`fp_cli/app.py`), và một biến không xác định không phải là lỗi. Đặt `AGENTEYE_DASHBOARD_URL` không nhắm mục tiêu lại CLI; nó bị bỏ qua và lệnh im lặng chạy dựa trên bảng điều khiển đã lưu thay thế.

  `AGENTEYE_HOME` và `AGENTEYE_ENVIRONMENT` vẫn tồn tại, nhưng chúng thuộc về **bộ sưu tập và SDK telemetry**, không phải CLI này.
</Warning>
