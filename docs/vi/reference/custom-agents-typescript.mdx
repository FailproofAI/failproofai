Node 20.9 trở lên. ESM và CommonJS. Không có runtime dependencies.

<Note>
  SDK này và SDK Python viết **cùng các sự kiện vào cùng một spool**. Một đội ngũ với các agents Node và agents Python tạo ra một tập hợp sessions, không phải hai, và không có gì trong bảng điều khiển phân biệt chúng. Chọn theo từng dịch vụ, không phải theo công ty.
</Note>

## Cài đặt

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Các framework adapters được đi kèm trong gói này. Các framework là **optional peer dependencies** — được khai báo để các phạm vi hỗ trợ visible, không bao giờ được cài đặt thay bạn, và chỉ được import khi bạn gọi `instrument()`.

## Kết nối Failproof daemon

Giống với SDK Python: tạo khóa `events:add` dưới **Admin → Keys**, sau đó [kết nối daemon](/vi/start/setup#connect-a-machine-to-cloud) trên máy agent. SDK ghi vào đĩa; daemon vận chuyển.

## Cấu hình

### OpenTelemetry spans (tùy chọn)

Cài đặt OpenTelemetry riêng biệt với `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
Sau đó thêm FailproofAI vào các processors của provider của bạn:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Đối với một provider hiện có, giữ các processors khác của nó trong cùng một danh sách. Các providers
expose `addSpanProcessor` có thể được truyền dưới dạng `{ provider }`. Không có tùy chọn, setup đăng ký
một provider mới chỉ khi không có provider nào đã được đăng ký.
`OtelSpanExporter` cũng có thể được sử dụng trực tiếp với processor của riêng bạn.

Các exports đi qua FailproofAI daemon được kết nối; SDK không gửi yêu cầu mạng
và không cần khóa hoặc local listener. Yêu cầu admin bật
[OpenTelemetry ingest](/vi/agenteye/opentelemetry). `instrument()` đơn lẻ không
bật exporter này. `uninstrument("otel")` chỉ vô hiệu hóa processor của chính nó.
Các span attributes của bạn kiểm soát content capture; flush provider của bạn trước khi thoát.
OpenTelemetry vẫn là optional application dependency, không phải hard SDK dependency.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Tùy chọn | Tác dụng |
| --- | --- |
| `environment` | Nhãn trên mọi sự kiện — `production`, `staging`, `prod-eu`. Mặc định là `dev`. |
| `flushInterval` | Tần suất timer ghi vào đĩa, tính bằng giây. Mặc định là `0.5`. |
| `baseDir` | Nơi ghi. Mặc định là spool của daemon, đó là điều bạn muốn trừ khi bạn biết ngược lại. |

Không có gì được áp dụng trừ khi tất cả đều được xác thực, vì vậy một lệnh bị từ chối sẽ để SDK chính xác như nó đã là thay vì có `baseDir` mới và interval cũ.

Đặt bằng biến môi trường thay thế:

| Biến | Tác dụng |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Đặt `environment` mà không cần thay đổi code. Tùy chọn `configure()` sẽ thắng nó. |
| `FAILPROOFAI_HOME` | Di chuyển Failproof AI root giữ spool. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (mặc định), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` làm cho lỗi instrumentation throw thay vì được ghi log. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` làm cho vấn đề tương thích framework throw thay vì cảnh báo và tiếp tục. |

<Warning>
  **Không có dấu phẩy trong `environment`.** Ingest chia tách trường đó trên dấu phẩy để xây dựng các bộ lọc của nó, và bỏ qua mọi sự kiện có nhãn chứa một — vì vậy toàn bộ một lần chạy im lặng biến mất. Viết `prod-eu`, không phải `prod,eu`.

  `configure({ environment: "prod,eu" })` throws để bạn tìm ra ngay lập tức. `AGENTEYE_ENVIRONMENT` không thể throw — không có gì gọi bạn — vì vậy nó cảnh báo một lần và quay lại `dev`.
</Warning>

Định tuyến các log lines của SDK vào logger của bạn với `failproofai.setLogger({ debug, info, warn, error })`.

## Tắt

Các sự kiện được buffer được flush trên `process.on("exit")`.

Một process bị kill bởi một signal không bao giờ đạt tới điều đó, và default của Node cho `SIGTERM` là kết thúc mà không chạy exit handlers — vì vậy một agent trong container mất bất cứ điều gì interval cuối cùng không ghi được.

<Warning>
  **SDK này sẽ không cài đặt một signal handler cho bạn.** Đăng ký một thay đổi hành vi của process của bạn: một listener tắt Node's default termination, vì vậy một library thêm một sẽ im lặng ngừng Ctrl-C hoạt động. Thêm của riêng bạn:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Một script ngắn hoặc một serverless handler nên `await failproofai.flush()` trước khi trả về — interval đơn độc không đảm bảo delivery.

## Danh tính

Mọi sự kiện thuộc về một session và một agent. **Các scopes điền cả hai**, vì vậy bạn hiếm khi truyền chúng:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

Truyền `sessionId` hoặc `agentId` một cách rõ ràng vẫn hoạt động và chiến thắng. Không có cả bound hay passed, lệnh gọi throws thay vì phát ra một sự kiện Cloud sẽ im lặng bỏ.

<Note>
  Danh tính được chuyên chở trên `AsyncLocalStorage`. Nó theo `await`, `.then()`, timers và bất kỳ callback nào được tạo bên trong scope. Nó **không** theo một callback được lưu trữ trong một lần chạy và gọi trong một lần chạy khác, hoặc công việc được vận chuyển qua `worker_threads` boundary — wrap những cái đó trong `failproofai.propagate()` hoặc các sự kiện của chúng hạ cánh không gắn.
</Note>

### Scopes

| Scope | Phát ra | Trả về |
| --- | --- | --- |
| `session(body)` | không có gì — chỉ danh tính | bất cứ điều gì `body` trả về |
| `agent(id, options?, body)` | `agent_start`, sau đó `agent_end` | bất cứ điều gì `body` trả về |
| `toolCall(name, options?, body)` | `tool_use`, sau đó `tool_result` | bất cứ điều gì `body` trả về |

Một body đồng bộ vẫn đồng bộ: `agent("x", () => 1)` trả về `1`, không phải một promise.

`toolCall` ghi lại giá trị đã giải quyết của body như là `output` của tool, trừ khi bạn gán `call.output` cho chính nó.

<Accordion title="Exit semantics" icon="arrow-right-from-bracket">

| Điều gì xảy ra | Sự kiện | `outcome` |
| --- | --- | --- |
| block trả về | `agent_end` | `"success"`, hoặc `outcome` của bạn |
| block threw | `error`, sau đó `agent_end` | `"failed"` |
| một `AbortError` | chỉ `agent_end` | `"cancelled"` |

Lỗi luôn được re-thrown.

Một tool failure được ghi lại trên leaf — `tool_result` với một chuỗi `error` — và phát ra **không có** run-level `error` event. Một cái agent loop bắt được không phải là một run failure, và một cái lan rộng được báo cáo chính xác một lần, bởi enclosing `agent()`.

</Accordion>

<Accordion title="Hình thức `using`" icon="brackets-curly">

Khi công việc không phải là một hàm duy nhất — một scope được mở trong constructor và đóng lại trong teardown, hoặc một mở rộng điều khiển luồng hiện có:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, sau đó agent_end
```

Cả hai hình thức phát ra byte-identical events. Ưu tiên hình thức callback: nó chạy bên trong `AsyncLocalStorage.run()`, vì vậy không có gì để unwind và toàn bộ lớp lỗi "opened here, closed over there" là không thể tiếp cận.

Một `using` block bắt được riêng failure của nó báo cáo nó với `span.fail(error)` — disposer không có exception channel của riêng nó.

</Accordion>

## Danh mục sự kiện

Cùng mười lăm phương thức như SDK Python, trong camelCase. Hầu hết đến trong **cặp** — bạn gọi opener, sau đó closer, và SDK tính toán khoảng cách.

| | Mở | Đóng |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Models** | `modelRequest` | `modelResponse` |
| **Tools** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **Humans** | `humanWait` | `humanInput` |

Ba đứng một mình: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Mọi trường, theo phương thức" icon="table">

Mọi phương thức cũng nhận `sessionId` và `agentId`, mà các scopes điền cho bạn. Bất cứ điều gì bị bỏ qua được loại bỏ thay vì được gửi dưới dạng JSON `null`.

| Phương thức | Bắt buộc | Tùy chọn |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Bất kỳ khóa nào khác bạn thêm trở thành custom payload field. Namespace bất cứ điều gì framework-specific `fw_*`; một tên va chạm với một khai báo field bị từ chối thay vì im lặng ghi đè một cột được thúc đẩy.

</Accordion>

<Warning>
  **`duration_ms` được tính toán, không được chấp nhận.** Bốn phương thức closing tính toán khoảng cách từ opener của chúng và từ chối một `duration_ms` do caller cung cấp — một thời gian khoá báo cáo là unfalsifiable.

  Các cặp được ghép trên **session** và id, không bao giờ trên agent. Một tool mở dưới `planner` và đóng dưới `worker` vẫn ghép, đó là những gì nested multi-agent runs thực sự làm.
</Warning>

## Framework adapters

```ts
await failproofai.instrument();              // bất cứ điều gì nó có thể tìm thấy
await failproofai.instrument("langchain");   // chính xác một
failproofai.uninstrument();                  // đặt tất cả trở lại
```

| Framework | Hỗ trợ | Nó gắn như thế nào |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, vì vậy mọi `invoke`/`stream`/`batch` được bao phủ mà không cần truyền `callbacks:` ở bất kỳ nơi nào — hoặc truyền `langchainHandler()` chính nó và không patch gì. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` tại call site, hoặc `instrument("ai")` cho toàn bộ process trên `ai` 7 (trên 4–6 đó là opt-in — xem dưới). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, model của agent và tool resolution, và workflow run/step engine. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (subscribed) cộng với `AgentWorkflow.runStream`, cho workflow runs và các steps của chúng. |

Mọi phạm vi được kiểm tra đối với framework releases thực tế, ở cả hai đầu, như một ES module và như CommonJS, trên mọi CI run.

Mapping là của SDK Python, vì vậy cùng một program vẽ cùng một cây trong hai ngôn ngữ. Một construct là một **agent** chỉ nếu nó sở hữu một LLM decision loop — một graph hoặc chain run, một AI SDK `generateText`/`streamText` call, một Mastra agent, một LlamaIndex agent run. Một LangGraph node hoặc một workflow step là một **hook** (`hook_triggered`/`hook_completed`), không bao giờ một nested agent. Model calls là `model_request`/`model_response` pairs với token counts; tool calls mang theo tool call id của chính model. Một failure được ghi lại một lần, trên sự kiện nó xảy ra.

Một adapter không cài đặt được ghi log và bỏ qua; những cái khác vẫn cài đặt, bởi vì một LlamaIndex bị hỏng không nên khiến bạn mất LangGraph.

<Note>
  `instrument()` không có đối số phát hiện một framework bằng cách nó **resolves**, không phải bằng cách nó đã được imported — Node không expose điều tương đương Python's `sys.modules` cho ES modules. Một framework bạn đã cài đặt nhưng không sử dụng sẽ được imported và patched. Đặt tên cái bạn muốn nếu điều đó quan trọng.
</Note>

<Note>
  Hầu hết những frameworks này ship một ES-module build và một CommonJS build, mà Node tải như hai bản sao không liên quan. Các adapters patch bản sao ứng dụng của bạn tải (và bản sao CommonJS cũng nếu có gì đó đã `require`d nó), vì vậy cả hai module systems hoạt động. Một framework **bundled vào output của riêng bạn** bởi esbuild hoặc webpack là ngoài tầm tay — sử dụng call-site helpers ở đó: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain không patch

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

Handler hoạt động với hoặc không có `instrument()` và không bao giờ double-records. `instrument("langchain")` nhận `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` và `captureLimit`, như adapter Python làm; `metadata: { failproofai_sdk_session_id }` trên một call chọn session cho invocation đó.

### Vercel AI SDK

AI SDK xuất các plain functions từ một ES module, và một ES module namespace là immutable theo specification — không có nơi nào để patch. Nó sử dụng các extension points mà SDK tự nó ghi chú:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // on ai 7, `telemetry: telemetry({ … })` — cùng object, tên mới
});
```

Đó là tích hợp hoàn chỉnh: một agent span, một model request/response pair mỗi step với token counts, và mọi tool call. Một call site hoạt động trên mọi major — `ai` 4–6 đọc tracer nó mang theo, `ai` 7 telemetry integration.

`instrument("ai")` làm tương tự process-wide **on `ai` 7**: mọi call, qua danh sách global telemetry-integration của AI SDK, đó là additive và lấy không từ ai khác.

**On `ai` 4–6, `instrument("ai")` ghi lại không có gì bằng chính nó, và ghi log một cảnh báo nói như vậy.** Process-wide hook duy nhất những majors đó có là global OpenTelemetry tracer provider — một single slot OpenTelemetry từ chối trao tay một lần được lấy. Đăng ký của chúng ta sẽ im lặng từ chối `NodeSDK.start()` của riêng bạn sau trong startup và gửi http/database spans của bạn tới một tracer xuất không có gì. Sử dụng `telemetry()` tại call site hoặc `wrapModel` ở đó. Nếu process chạy không OpenTelemetry của chính nó, opt in với `instrument("ai", { registerGlobalTracer: true })`: nó sau đó ghi lại mọi call mà vượt qua `experimental_telemetry: { isEnabled: true }`, và chỉ nhận slot nếu nó vẫn trống. `registerGlobalTracer: false` giữ default và tắt tiếng cảnh báo.

Nếu bạn muốn wrap model một lần, `wrapModel` thấy model calls chỉ, bởi vì tool calls xảy ra ở trên model layer. Một wrapped model gọi với không có gì xung quanh nó được ghi lại như riêng của nó run. Một streamed call đóng tuy nhiên stream dừng — `stop_reason: "cancelled"` khi consumer hủy nó, `"error"` với lỗi khi nó thất bại một phần:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Sử dụng cả hai là tốt: middleware nhận thấy call đã được ghi lại và từ chối, vì vậy mỗi call được ghi lại một lần.

`functionId` đặt tên cho agent span. Giữ nó low-cardinality — nó hạ cánh trong `agent_id`, primary dashboard facet.

### Next.js

`next build` bundles dependencies máy chủ của bạn theo mặc định, và một framework bundled vào build là một bản sao `instrument()` không thể tiếp cận. Wrap config một lần và gọi `instrument()` từ Next's startup hook:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` thêm LangChain, Mastra, LlamaIndex và SDK chính nó vào `serverExternalPackages`, giữ danh sách của riêng bạn. Không có nó, `instrument()` cảnh báo một lần cho mỗi framework nó không thể tiếp cận thay vì fail im lặng; nếu bạn liệt kê các packages chính nó, đặt `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK và call-site helpers hoạt động bằng cách nào đó. Một Edge route nhận một no-op build: importing SDK là an toàn và ghi lại không có gì.

### Token counts trên streamed calls

OpenAI-compatible APIs chỉ báo cáo usage trên một stream khi client hỏi. LangChain và Vercel AI SDK hỏi; cho LlamaIndex truyền `additionalChatOptions: { stream_options: { include_usage: true } }` cho `OpenAI` LLM của nó, và cho Mastra xây dựng model với usage enabled (ví dụ `createOpenAICompatible({ includeUsage: true })`). Ngược lại streamed model calls không mang token counts.

### Runtimes

Node ≥ 20.9, Bun và Deno — mọi framework, như một ES module và như CommonJS, được kiểm tra trên mỗi đối với Node's trace. SDK chạy bên cạnh `failproofaid` daemon, vận chuyển những gì nó viết.

## Agent của riêng bạn — không framework

Cho một agent loop bạn viết chính nó, hoặc một framework không có adapter. Bạn phát ra các sự kiện với cùng API các adapters sử dụng ở bên dưới, vì vậy trace có hình dạng và chất lượng tương tự.

Bạn không cần biết agent được tổ chức như thế nào. Mọi hand-built agent đã có ba nơi, bất kể các hàm của nó được gọi là gì, và những ba đó là tích hợp toàn bộ:

| Nơi | Gì để thêm | Phát ra |
| --- | --- | --- |
| Nơi **một run** bắt đầu và kết thúc | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Hàm duy nhất gọi model** | `event.modelRequest` trước, `event.modelResponse` sau — cả hai halves, thậm chí trên failure | một cặp mỗi model turn |
| **Hàm duy nhất chạy tools** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Danh tính là ambient: mọi thứ bên trong `agent()` hạ cánh trên run's session đó mà không có một id, và không có gì khác trong chương trình thay đổi — bao gồm bất cứ điều gì agent đã viết vào database riêng của nó.

- **Một dịch vụ hoặc một worker:** truyền request hoặc job id của riêng bạn như `sessionId`, vì vậy một session trên bảng điều khiển và bản ghi trong logs hoặc database của riêng bạn là chuỗi tương tự.
- **Sub-agents:** nest `agent()` calls. Cái bên trong tham gia session với cái ngoài như `parent_id` của nó.
- **Phát ra các cặp.** Một `modelRequest` không có `modelResponse` là một span bảng điều khiển hiển thị như chạy mãi mãi — do đó `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) trong repository là bản hoàn chỉnh, runnable: một real OpenAI tool loop được tích hợp chính xác như thế này, chạy trong CI trên mỗi thay đổi như một ES module và như CommonJS.

## Evaluations

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Xem [Evaluator SDK reference](/vi/reference/evaluator-sdk) cho protocol, worker settings và result types.

<Warning>
  **Một evaluation phải yield.** Một synchronous function bao giờ không trả về blocks thread duy nhất Node có, và không timeout nào có thể fire trong khi nó làm. Viết `async` evaluations.
</Warning>

## Những gì nó sẽ không làm cho process của bạn

| | |
| --- | --- |
| **Block agent loop của bạn** | Sự kiện đi vào một in-memory queue; một timer ghi chúng. Timer được `unref`'d, vì vậy importing package này không bao giờ dừng một script thoát. |
| **Phát triển không bị ràng buộc** | Queue bị capped bằng count *và* bằng measured bytes. Quá một trong hai, sự kiện cũ nhất bị loại bỏ và một cảnh báo nói vậy — một telemetry outage không phải trở thành một OOM kill. |
| **Lấy process xuống** | Một sự kiện unencodable được loại bỏ một mình, không phải batch xung quanh nó. Một throwing getter, một circular reference, một `BigInt`, một lone surrogate: mỗi cái được xử lý thay vì lan rộng. |
| **Để lại một half-written batch** | Content được `fsync`ed trước một atomic rename, directory được `fsync`ed sau, và một failed write làm sạch temporary file của nó. |
| **Để lại transcripts readable** | Batches là `0600` bên trong một `0700` directory. Chúng mang goals, prompts, tool arguments và tool output. |
| **Ship credentials** | API keys, tokens, JWTs, bearer headers và secret-shaped assignments được redacted trước bytes tiếp cận disk. Daemon redacts lại trước upload. |
