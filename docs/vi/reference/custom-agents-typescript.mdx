Node 20.9 trở lên. ESM và CommonJS. Không có runtime dependencies.

<Note>
  SDK này và SDK Python viết **các event giống nhau vào cùng một spool**. Một fleet có agent Node và agent Python tạo ra một tập hợp session, không phải hai, và không có gì trong dashboard phân biệt chúng. Chọn theo từng dịch vụ, không phải theo công ty.
</Note>

## Cài đặt

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Các framework adapter được ship trong package. Các framework là **optional peer dependencies** — được khai báo để các phạm vi được hỗ trợ có thể nhìn thấy, không bao giờ được cài đặt thay bạn và chỉ được import khi bạn gọi `instrument()`.

## Kết nối daemon Failproof

Giống hệt SDK Python: tạo một khóa `events:add` trong **Admin → Keys**, sau đó [kết nối daemon](/vi/start/setup#connect-a-machine-to-cloud) trên máy agent. SDK viết vào đĩa; daemon ship nó.

## Cấu hình

### OpenTelemetry spans (opt in)

Cài đặt OpenTelemetry riêng biệt với `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
Sau đó thêm FailproofAI vào processor của provider:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Với một provider hiện tại, giữ lại các processor khác trong cùng một danh sách. Các provider
hiển thị `addSpanProcessor` có thể được truyền là `{ provider }`. Không có option,
setup chỉ đăng ký một provider mới nếu chưa có provider được đăng ký.
`OtelSpanExporter` cũng có thể được sử dụng trực tiếp với processor của bạn.

Export đi qua daemon FailproofAI đã kết nối; SDK không gửi request mạng
và không cần khóa hoặc local listener. Yêu cầu admin bật
[OpenTelemetry ingest](/vi/agenteye/opentelemetry). `instrument()` không có option
không bật exporter này. `uninstrument("otel")` chỉ vô hiệu hóa processor của nó.
Span attribute của bạn kiểm soát việc capture content; flush provider trước khi thoát.
OpenTelemetry vẫn là một optional application dependency, không phải hard SDK dependency.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Option | Công dụng |
| --- | --- |
| `environment` | Nhãn trên mỗi event — `production`, `staging`, `prod-eu`. Mặc định là `dev`. |
| `flushInterval` | Bao lâu timer ghi vào đĩa, tính bằng giây. Mặc định là `0.5`. |
| `baseDir` | Nơi ghi. Mặc định là spool của daemon, đó là những gì bạn muốn trừ khi bạn biết cách khác. |

Không có gì được áp dụng trừ khi tất cả đều xác thực, vì vậy một lệnh bị từ chối sẽ để SDK chính xác như nó đã là thay vì có một `baseDir` mới và interval cũ.

Đặt bằng biến môi trường thay thế:

| Biến | Công dụng |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Đặt `environment` mà không cần thay đổi code. Option `configure()` sẽ thắng nó. |
| `FAILPROOFAI_HOME` | Di chuyển root Failproof AI giữ spool. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (mặc định), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` làm cho lỗi instrumentation throw thay vì được log. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` làm cho vấn đề framework-compatibility throw thay vì warn và tiếp tục. |

<Warning>
  **Không có dấu phẩy trong `environment`.** Ingest chia field đó trên dấu phẩy để xây dựng các filter của nó, và bỏ qua bất kỳ event nào có nhãn chứa một — vì vậy cả một run âm thầm biến mất. Viết `prod-eu`, không phải `prod,eu`.

  `configure({ environment: "prod,eu" })` throw để bạn phát hiện ngay lập tức. `AGENTEYE_ENVIRONMENT` không thể throw — không có gì gọi bạn — vì vậy nó cảnh báo một lần và quay lại `dev`.
</Warning>

Định tuyến các dòng log của SDK vào logger của bạn với `failproofai.setLogger({ debug, info, warn, error })`.

## Tắt

Các event được buffered được flush trên `process.on("exit")`.

Một process bị giết bởi tín hiệu không bao giờ đạt đến điều đó, và mặc định của Node cho `SIGTERM` là chấm dứt mà không chạy exit handler — vì vậy một agent được containerize sẽ mất những gì interval cuối cùng không ghi được.

<Warning>
  **SDK này sẽ không cài đặt signal handler cho bạn.** Đăng ký một cái thay đổi hành vi process của bạn: một listener triệt tiêu mặc định của Node, vì vậy một library thêm một cái sẽ âm thầm dừng Ctrl-C từ hoạt động. Thêm của riêng bạn:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Một script ngắn hạn hoặc handler serverless nên `await failproofai.flush()` trước khi trả về — interval một mình không đảm bảo delivery.

## Identity

Mỗi event thuộc về một session và một agent. **Các scope điền cả hai**, vì vậy bạn hiếm khi truyền chúng:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

Truyền `sessionId` hoặc `agentId` rõ ràng vẫn hoạt động và thắng. Với cả hai không bound cũng không truyền, lệnh gọi throw thay vì phát ra một event Cloud sẽ âm thầm discard.

<Note>
  Identity chạy trên `AsyncLocalStorage`. Nó theo `await`, `.then()`, timer và bất kỳ callback nào được tạo bên trong scope. Nó **không** theo một callback được lưu trữ trong một run và gọi trong một run khác, hoặc công việc handed qua một boundary `worker_threads` — wrap những cái trong `failproofai.propagate()` hoặc các event của chúng land unattached.
</Note>

### Scopes

| Scope | Phát ra | Trả về |
| --- | --- | --- |
| `session(body)` | nothing — identity chỉ | whatever `body` trả về |
| `agent(id, options?, body)` | `agent_start`, sau đó `agent_end` | whatever `body` trả về |
| `toolCall(name, options?, body)` | `tool_use`, sau đó `tool_result` | whatever `body` trả về |

Một body đồng bộ vẫn đồng bộ: `agent("x", () => 1)` trả về `1`, không phải promise.

`toolCall` ghi lại giá trị resolved của body như `output` của tool, trừ khi bạn gán `call.output` của bạn.

<Accordion title="Exit semantics" icon="arrow-right-from-bracket">

| Điều gì xảy ra | Events | `outcome` |
| --- | --- | --- |
| block trả về | `agent_end` | `"success"`, hoặc `outcome` của bạn |
| block throw | `error`, sau đó `agent_end` | `"failed"` |
| một `AbortError` | `agent_end` chỉ | `"cancelled"` |

Error luôn được re-throw.

Một tool failure được ghi trên leaf — `tool_result` với một string `error` — và phát ra **không có** run-level `error` event. Một cái agent loop bắt không phải là run failure, và một cái mà propagate được báo cáo chính xác một lần, bởi enclosing `agent()`.

</Accordion>

<Accordion title="Hình thức `using`" icon="brackets-curly">

Khi công việc không phải là một hàm duy nhất — một scope mở trong constructor và đóng trong teardown, hoặc một straddle existing control flow:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, sau đó agent_end
```

Cả hai hình thức phát ra byte-identical events. Ưu tiên hình thức callback: nó chạy bên trong `AsyncLocalStorage.run()`, vì vậy không có gì để unwind và toàn bộ class của các bug "opened here, closed over there" không thể tiếp cận.

Một `using` block bắt lỗi của riêng nó báo cáo nó với `span.fail(error)` — disposer không có exception channel của riêng nó.

</Accordion>

## Event catalog

Mười lăm method giống như SDK Python, trong camelCase. Hầu hết đi kèm **cặp** — bạn gọi opener, sau đó closer, và SDK time the gap.

| | Opens | Closes |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Models** | `modelRequest` | `modelResponse` |
| **Tools** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **Humans** | `humanWait` | `humanInput` |

Ba đứng riêng: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Mỗi field, mỗi method" icon="table">

Mỗi method cũng nhận `sessionId` và `agentId`, mà các scope điền cho bạn. Bất kỳ điều gì được bỏ qua được dropped thay vì được gửi như JSON `null`.

| Method | Yêu cầu | Tùy chọn |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Bất kỳ key nào khác bạn thêm trở thành một custom payload field. Namespace bất kỳ điều gì framework-specific `fw_*`; một tên va chạm với một declared field bị từ chối thay vì âm thầm overwriting một promoted column.

</Accordion>

<Warning>
  **`duration_ms` được tính toán, không được chấp nhận.** Bốn closing method time the gap từ opener của chúng và từ chối một caller-supplied `duration_ms` — một reported duration không thể giả mạo được.

  Các cặp được khớp trên **session** và id, không bao giờ trên agent. Một tool mở dưới `planner` và đóng dưới `worker` vẫn khớp, đó là những gì nested multi-agent runs thực sự làm.
</Warning>

## Framework adapters

```ts
await failproofai.instrument();              // whatever nó có thể tìm thấy
await failproofai.instrument("langchain");   // chính xác một
failproofai.uninstrument();                  // đặt mọi thứ lại
```

| Framework | Được hỗ trợ | Cách nó attach |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, vì vậy mỗi `invoke`/`stream`/`batch` được bao phủ mà không truyền `callbacks:` ở bất kỳ nơi nào — hoặc truyền `langchainHandler()` của riêng bạn và không patch bất kỳ điều gì. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` tại call site, hoặc `instrument("ai")` cho toàn bộ process trên `ai` 7 (trên 4–6 đó là opt-in — xem dưới). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, model của agent và tool resolution, và workflow run/step engine. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (subscribed) cộng với `AgentWorkflow.runStream`, cho workflow run và step của chúng. |

Mỗi phạm vi được kiểm tra đối với real framework release, ở cả hai đầu, như một ES module và như CommonJS, trên mỗi CI run.

Ánh xạ là của SDK Python, vì vậy chương trình tương tự vẽ cây tương tự trong một ngôn ngữ. Một construct chỉ là một **agent** nếu nó sở hữu LLM decision loop — một graph hoặc chain run, một AI SDK `generateText`/`streamText` call, một Mastra agent, một LlamaIndex agent run. Một LangGraph node hoặc một workflow step là một **hook** (`hook_triggered`/`hook_completed`), không bao giờ là một nested agent. Model call là `model_request`/`model_response` cặp với token count; tool call mang tool call id của chính model. Một failure được ghi một lần, trên event nó xảy ra.

Một adapter mà lỗi cài đặt được log và skipped; những cái khác vẫn cài đặt, bởi vì một broken LlamaIndex không nên mất bạn LangGraph.

<Note>
  `instrument()` không có argument phát hiện framework bằng cách nó **resolve**, không phải bằng cách nó đã được import — Node không hiển thị tương đương Python của `sys.modules` cho ES module. Một framework bạn đã cài đặt nhưng không sử dụng sẽ được import và patch. Đặt tên cái bạn muốn nếu điều đó quan trọng.
</Note>

<Note>
  Hầu hết các framework này ship một ES-module build và một CommonJS build, mà Node tải như hai unrelated copy. Các adapter patch the copy application của bạn tải (và CommonJS copy cũng nếu cái gì đó đã `require` nó), vì vậy cả hai module system hoạt động. Một framework **bundled thành output của bạn** bởi esbuild hoặc webpack là out of reach — sử dụng call-site helpers ở đó: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain không patching

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

Handler hoạt động với hoặc không có `instrument()` và không bao giờ double-record. `instrument("langchain")` nhận `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` và `captureLimit`, như adapter Python làm; `metadata: { failproofai_sdk_session_id }` trên một call chọn session cho invocation đó.

### Vercel AI SDK

AI SDK xuất các hàm plain từ một ES module, và một ES module namespace là immutable theo specification — không có nơi nào để patch. Nó sử dụng các extension point mà SDK chính nó tài liệu:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // trên ai 7, `telemetry: telemetry({ … })` — cùng một object, tên mới
});
```

Đó là toàn bộ integration: một agent span, một model request/response cặp mỗi step với token count, và mỗi tool call. Một call site hoạt động trên mỗi major — `ai` 4–6 đọc the tracer nó mang, `ai` 7 the telemetry integration.

`instrument("ai")` làm process-wide **trên `ai` 7**: mỗi call, qua AI SDK's global telemetry-integration list, mà là additive và không lấy gì từ ai khác.

**Trên `ai` 4–6, `instrument("ai")` ghi không có gì bằng chính nó, và log một cảnh báo nói như vậy.** Duy nhất process-wide hook những major đó có là global OpenTelemetry tracer provider — một single slot OpenTelemetry từ chối hand over một khi taken. Đăng ký của chúng tôi sẽ âm thầm từ chối `NodeSDK.start()` của bạn sau trong startup và gửi http/database span của bạn đến một tracer mà export không có gì. Sử dụng `telemetry()` tại call site hoặc `wrapModel` ở đó. Nếu process chạy không có OpenTelemetry của riêng nó, opt in với `instrument("ai", { registerGlobalTracer: true })`: nó sau đó ghi mỗi call mà pass `experimental_telemetry: { isEnabled: true }`, và chỉ nhận slot nếu nó vẫn empty. `registerGlobalTracer: false` giữ default và silence the warning.

Nếu bạn thích wrap model một lần, `wrapModel` thấy model call chỉ, bởi vì tool call xảy ra trên model layer. Một wrapped model gọi với không có gì xung quanh nó được ghi như run của riêng nó. Một streamed call đóng bất cách như stream dừng — `stop_reason: "cancelled"` khi consumer cancel nó, `"error"` với error khi nó fail part-way:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Sử dụng cả hai tốt: middleware nhận thấy call đã được ghi lại và defer, vì vậy mỗi call được ghi một lần.

`functionId` tên agent span. Giữ nó low-cardinality — nó land trong `agent_id`, primary dashboard facet.

### Next.js

`next build` bundled dependency của server theo mặc định, và một framework bundled vào build là một copy `instrument()` không thể tiếp cận. Wrap config một lần và gọi `instrument()` từ Next's startup hook:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` thêm LangChain, Mastra, LlamaIndex và SDK chính nó để `serverExternalPackages`, giữ danh sách của riêng bạn. Không có nó, `instrument()` cảnh báo một lần mỗi framework nó không thể tiếp cận thay vì fail âm thầm; nếu bạn danh sách các package chính bạn, đặt `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK và call-site helper hoạt động bất kỳ cách. Một Edge route nhận một no-op build: import SDK an toàn và ghi không có gì.

### Token count trên streamed call

OpenAI-compatible API chỉ báo cáo usage trên một stream khi client hỏi. LangChain và Vercel AI SDK hỏi; cho LlamaIndex pass `additionalChatOptions: { stream_options: { include_usage: true } }` tới `OpenAI` LLM của nó, và cho Mastra xây dựng model với usage bật (ví dụ `createOpenAICompatible({ includeUsage: true })`). Nếu không streamed model call mang không token count.

### Runtimes

Node ≥ 20.9, Bun và Deno — mỗi framework, như một ES module và như CommonJS, được kiểm tra trên mỗi đối với Node's trace. SDK chạy bên cạnh daemon `failproofaid`, mà ship những gì nó viết.

## Agent của riêng bạn — không có framework

Cho một agent loop bạn viết chính bạn, hoặc một framework không có adapter. Bạn phát ra các event với API tương tự adapters sử dụng dưới, vì vậy trace có hình dạng và chất lượng tương tự.

Bạn không cần biết agent được tổ chức như thế nào. Mỗi hand-built agent đã có ba nơi, cho dù các hàm của nó được gọi là gì, và ba cái đó là toàn bộ integration:

| Nơi | Những gì để thêm | Phát ra |
| --- | --- | --- |
| Nơi **một run** bắt đầu và kết thúc | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Một hàm duy nhất gọi model** | `event.modelRequest` trước, `event.modelResponse` sau — cả hai nửa, thậm chí trên failure | một cặp mỗi model turn |
| **Một hàm duy nhất chạy tool** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Identity là ambient: mọi thứ bên trong `agent()` land trên run's session mà không lấy một id, và không có gì khác trong chương trình thay đổi — bao gồm bất kỳ agent đã viết vào database của nó.

- **Một dịch vụ hoặc một worker:** truyền request của riêng bạn hoặc job id như `sessionId`, vì vậy một session trên dashboard và record trong log hoặc database của riêng bạn là cùng một string.
- **Sub-agents:** nest `agent()` call. Cái bên trong join session với cái bên ngoài như `parent_id`.
- **Phát ra các cặp.** Một `modelRequest` không có `modelResponse` là một span dashboard hiển thị như chạy mãi mãi — do đó `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) trong repository là toàn bộ, runnable version: một real OpenAI tool loop instrumented chính xác như thế này, chạy trong CI trên mỗi thay đổi như một ES module và như CommonJS.

## Evaluations

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Xem [Evaluator SDK reference](/vi/reference/evaluator-sdk) cho protocol, worker setting và result type.

<Warning>
  **Một evaluation phải yield.** Một synchronous function mà không bao giờ trả về block cái một thread Node có, và không timeout có thể fire khi nó làm. Viết `async` evaluation.
</Warning>

## Những gì nó sẽ không làm với process của bạn

| | |
| --- | --- |
| **Block agent loop của bạn** | Event đi vào một in-memory queue; một timer ghi chúng. Timer là `unref`'d, vì vậy import package này không bao giờ dừng script từ thoát. |
| **Grow không bound** | Queue được capped bằng count *và* bằng measured byte. Quá một, các event cũ nhất được discarded và một cảnh báo nói như vậy — một telemetry outage phải không trở thành OOM kill. |
| **Take process xuống** | Một event không thể mã hóa được dropped một mình, không batch xung quanh nó. Một throwing getter, một circular reference, một `BigInt`, một lone surrogate: mỗi được handle thay vì propagated. |
| **Leave một half-written batch** | Content là `fsync`ed trước một atomic rename, directory là `fsync`ed sau, và một failed write làm sạch temporary file của nó. |
| **Leave transcript readable** | Batch là `0600` bên trong một `0700` directory. Chúng mang goal, prompt, tool argument và tool output. |
| **Ship credential** | API key, token, JWT, bearer header và secret-shaped assignment được redacted trước byte tiếp cận đĩa. Daemon redact lại trước upload. |
