Node 20.9 hoặc mới hơn. ESM và CommonJS. Không có phụ thuộc runtime.

<Note>
  SDK này và SDK Python viết **cùng các sự kiện vào cùng một spool**. Một đội với các agent Node và agent Python tạo ra một tập hợp phiên, không phải hai, và không có gì trong bảng điều khiển phân biệt chúng. Chọn theo dịch vụ, không phải theo công ty.
</Note>

## Cài đặt

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Các bộ điều hợp framework được vận chuyển trong chính gói. Các framework là **phụ thuộc peer tùy chọn** — được khai báo để các phạm vi được hỗ trợ hiển thị, không bao giờ được cài đặt thay bạn, và chỉ được nhập khi bạn gọi `instrument()`.

## Kết nối daemon Failproof

Giống hệt SDK Python: tạo khóa `events:add` dưới **Admin → Keys**, sau đó [kết nối daemon](/vi/start/setup#connect-a-machine-to-cloud) trên máy agent. SDK ghi vào đĩa; daemon vận chuyển.

## Cấu hình

### OpenTelemetry spans (tùy chọn)

Cài đặt OpenTelemetry riêng biệt với `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
Sau đó thêm FailproofAI vào các bộ xử lý của nhà cung cấp của bạn:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Đối với nhà cung cấp hiện có, giữ các bộ xử lý khác của nó trong cùng danh sách. Các nhà cung cấp
công khai `addSpanProcessor` có thể được chuyển thành `{ provider }`. Không có tùy chọn,
setup đăng ký một nhà cung cấp mới chỉ khi không có nhà cung cấp nào được đăng ký sẵn.
`OtelSpanExporter` cũng có thể được sử dụng trực tiếp với bộ xử lý riêng của bạn.

Các lần xuất đi thông qua daemon FailproofAI được kết nối; SDK không gửi yêu cầu mạng
và không cần khóa hoặc trình nghe cục bộ. Hãy yêu cầu quản trị viên bật
[OpenTelemetry ingest](/vi/agenteye/opentelemetry). `instrument()` trần không bật
trình xuất này. `uninstrument("otel")` chỉ vô hiệu hóa bộ xử lý riêng của nó.
Các thuộc tính span của bạn kiểm soát việc chụp nội dung; xả nhà cung cấp của bạn trước khi thoát.
OpenTelemetry vẫn là phụ thuộc ứng dụng tùy chọn, không phải phụ thuộc SDK cứng.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Tùy chọn | Chức năng |
| --- | --- |
| `environment` | Nhãn trên mỗi sự kiện — `production`, `staging`, `prod-eu`. Mặc định là `dev`. |
| `flushInterval` | Tần suất bộ hẹn giờ ghi vào đĩa, tính bằng giây. Mặc định là `0.5`. |
| `baseDir` | Nơi ghi. Mặc định là spool của daemon, đó là những gì bạn muốn trừ khi bạn biết khác. |

Không có gì được áp dụng trừ khi tất cả được xác nhận, vì vậy lệnh gọi bị từ chối để lại SDK chính xác như trước đây thay vì có `baseDir` mới và khoảng thời gian cũ.

Đặt bằng biến môi trường thay thế:

| Biến | Chức năng |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Đặt `environment` mà không thay đổi mã. Tùy chọn `configure()` sẽ thắng nó. |
| `FAILPROOFAI_HOME` | Di chuyển gốc Failproof AI giữ spool. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (mặc định), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` làm cho lỗi thiết lập ném thay vì được ghi lại. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` làm cho vấn đề tương thích framework ném thay vì cảnh báo và tiếp tục. |

<Warning>
  **Không có dấu phẩy trong `environment`.** Ingest chia trường đó theo dấu phẩy để xây dựng các bộ lọc của nó, và bỏ qua bất kỳ sự kiện nào có nhãn chứa một — vì vậy toàn bộ lần chạy biến mất im lặng. Viết `prod-eu`, không phải `prod,eu`.

  `configure({ environment: "prod,eu" })` ném để bạn tìm ra ngay lập tức. `AGENTEYE_ENVIRONMENT` không thể ném — không ai gọi bạn — vì vậy nó cảnh báo một lần và quay lại `dev`.
</Warning>

Định tuyến các dòng nhật ký riêng của SDK vào logger của bạn với `failproofai.setLogger({ debug, info, warn, error })`.

## Tắt

Các sự kiện được đệm được xả trên `process.on("exit")`.

Quá trình bị giết bởi một tín hiệu không bao giờ đạt đến điều đó, và mặc định của Node cho `SIGTERM` là kết thúc mà không chạy trình xử lý thoát — vì vậy agent được chứa sẽ mất bất kỳ gì mà khoảng thời gian cuối cùng không ghi.

<Warning>
  **SDK này sẽ không cài đặt trình xử lý tín hiệu cho bạn.** Đăng ký một cách thay đổi hành vi của quá trình của bạn: một trình nghe đàn áp mặc định kết thúc của Node, vì vậy thư viện đã thêm một cách sẽ im lặng dừng Ctrl-C hoạt động. Thêm của bạn:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Tập lệnh hoặc trình xử lý serverless tồn tại trong thời gian ngắn nên `await failproofai.flush()` trước khi trả về — khoảng thời gian một mình không đảm bảo gửi.

## Danh tính

Mỗi sự kiện thuộc về một phiên và một agent. **Các phạm vi điền cả hai**, vì vậy bạn hiếm khi chuyển chúng:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

Chuyển `sessionId` hoặc `agentId` một cách rõ ràng vẫn hoạt động và chiến thắng. Không có bất kỳ thứ gì được ràng buộc cũng không được chuyển, cuộc gọi ném thay vì phát sự kiện Cloud sẽ yên tĩnh bỏ qua.

<Note>
  Danh tính đi trên `AsyncLocalStorage`. Nó theo `await`, `.then()`, bộ hẹn giờ và bất kỳ lệnh gọi lại nào được tạo bên trong phạm vi. Nó **không** theo cuộc gọi lại được lưu trữ trong một lần chạy và được gọi trong lần chạy khác, hoặc công việc được chuyển qua ranh giới `worker_threads` — bọc các công việc trong `failproofai.propagate()` hoặc các sự kiện của chúng hạ cánh không gắn.
</Note>

### Phạm vi

| Phạm vi | Phát | Trả về |
| --- | --- | --- |
| `session(body)` | không có gì — chỉ danh tính | bất kỳ `body` nào trả về |
| `agent(id, options?, body)` | `agent_start`, sau đó `agent_end` | bất kỳ `body` nào trả về |
| `toolCall(name, options?, body)` | `tool_use`, sau đó `tool_result` | bất kỳ `body` nào trả về |

Một phần thân đồng bộ vẫn đồng bộ: `agent("x", () => 1)` trả về `1`, không phải lời hứa.

`toolCall` ghi giá trị giải quyết của phần thân dưới dạng `output` của công cụ, trừ khi bạn tự gán `call.output`.

<Accordion title="Ngữ nghĩa thoát" icon="arrow-right-from-bracket">

| Điều gì xảy ra | Sự kiện | `outcome` |
| --- | --- | --- |
| khối được trả về | `agent_end` | `"success"`, hoặc `outcome` của bạn |
| khối ném | `error`, sau đó `agent_end` | `"failed"` |
| một `AbortError` | chỉ `agent_end` | `"cancelled"` |

Lỗi luôn được ném lại.

Lỗi công cụ được ghi lại trên lá — `tool_result` với chuỗi `error` — và phát **không** sự kiện `error` ở cấp chạy. Một cái mà vòng agent bắt được không phải là lỗi chạy, và cái mà truyền là được báo cáo chính xác một lần, bởi `agent()` đặt hàng.

</Accordion>

<Accordion title="Hình thức `using`" icon="brackets-curly">

Khi công việc không phải là một hàm duy nhất — một phạm vi được mở trong một hàm tạo và đóng trong một phần tháo rời, hoặc cái mà được xen kẽ với luồng kiểm soát hiện có:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

Cả hai hình thức phát các sự kiện giống nhau từng byte. Ưu tiên hình thức gọi lại: nó chạy bên trong `AsyncLocalStorage.run()`, vì vậy không có gì để tháo rời và toàn bộ lớp các lỗi "mở ở đây, đóng ở đó" không thể tiếp cận được.

Một khối `using` bắt lỗi riêng của nó báo cáo nó với `span.fail(error)` — bộ xử lý loại bỏ không có kênh ngoại lệ riêng của nó.

</Accordion>

## Danh mục sự kiện

Mười năm phương thức giống như SDK Python, trong camelCase. Hầu hết đều có **cặp** — bạn gọi người mở, sau đó người đóng, và SDK định thời gian khoảng cách.

| | Mở | Đóng |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Mô hình** | `modelRequest` | `modelResponse` |
| **Công cụ** | `toolUse` | `toolResult` |
| **Hook** | `hookTriggered` | `hookCompleted` |
| **Con người** | `humanWait` | `humanInput` |

Ba đứng một mình: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Mỗi trường, cho mỗi phương thức" icon="table">

Mỗi phương thức cũng có `sessionId` và `agentId`, mà các phạm vi điền cho bạn. Bất kỳ thứ gì bị bỏ qua được loại bỏ chứ không phải được gửi dưới dạng JSON `null`.

| Phương thức | Bắt buộc | Tùy chọn |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Bất kỳ khóa nào khác bạn thêm sẽ trở thành trường tải trọng tùy chỉnh. Không gian bất kỳ thứ gì cụ thể framework `fw_*`; một tên va chạm với trường khai báo bị từ chối chứ không phải yên tĩnh ghi đè một cột được quảng bá.

</Accordion>

<Warning>
  **`duration_ms` được tính toán, không được chấp nhận.** Bốn phương thức đóng định thời gian khoảng cách từ người mở của chúng và từ chối `duration_ms` do người gọi cung cấp — thời lượng được báo cáo là không thể làm giả.

  Các cặp được so khớp trên **phiên** và id, không bao giờ trên agent. Một công cụ mở dưới `planner` và đóng dưới `worker` vẫn cặp, đó là những gì các lần chạy đa agent lồng nhau thực sự làm.
</Warning>

## Bộ điều hợp framework

```ts
await failproofai.instrument();              // bất kỳ cái nào nó có thể tìm
await failproofai.instrument("langchain");   // chính xác một
failproofai.uninstrument();                  // đặt mọi thứ trở lại
```

| Framework | Được hỗ trợ | Cách nó gắn kết |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, vì vậy mỗi `invoke`/`stream`/`batch` được bao phủ mà không cần chuyển `callbacks:` ở bất kỳ đâu — hoặc chuyển `langchainHandler()` bạn cũng vá ứng dụng không gì. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` tại địa điểm gọi, hoặc `instrument("ai")` cho toàn bộ quy trình trên `ai` 7 (trên 4–6 là tùy chọn — xem dưới). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, mô hình của agent và độc lập công cụ, và engine chạy/bước quy trình làm việc. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (được đăng ký) cộng với `AgentWorkflow.runStream`, cho các chạy quy trình làm việc và các bước của chúng. |

Mỗi phạm vi được kiểm tra so với các bản phát hành framework thực tế, ở cả hai đầu, như mô-đun ES và CommonJS, trên mỗi lần chạy CI.

Ánh xạ là của SDK Python, vì vậy cùng một chương trình vẽ cùng một cây trong cả hai ngôn ngữ. Một xây dựng là một **agent** chỉ khi nó sở hữu vòng lặp quyết định LLM — chạy biểu đồ hoặc chuỗi, cuộc gọi `generateText`/`streamText` của AI SDK, một agent Mastra, một lần chạy agent LlamaIndex. Một nút LangGraph hoặc bước quy trình làm việc là một **hook** (`hook_triggered`/`hook_completed`), không bao giờ là agent lồng nhau. Các cuộc gọi mô hình là các cặp `model_request`/`model_response` với số lượng mã thông báo; các cuộc gọi công cụ mang id cuộc gọi công cụ riêng của mô hình. Lỗi được ghi lại một lần, trên sự kiện nó xảy ra.

Bộ điều hợp không cài đặt được ghi lại và bỏ qua; những cái khác vẫn cài đặt, vì LlamaIndex bị hỏng không nên tốn LangGraph của bạn.

<Note>
  `instrument()` không có đối số phát hiện framework theo việc nó **giải quyết**, không phải theo việc nó đã được nhập — Node không công khai tương đương với `sys.modules` của Python cho các mô-đun ES. Framework bạn đã cài đặt nhưng không sử dụng sẽ được nhập và vá. Đặt tên cái bạn muốn nếu điều đó quan trọng.
</Note>

<Note>
  Hầu hết các framework này vận chuyển bản dựng mô-đun ES và bản dựng CommonJS, mà Node tải dưới dạng hai bản sao không liên quan. Các bộ điều hợp vá bản sao ứng dụng của bạn tải (và bản sao CommonJS cũng nếu một cái đã `require` nó), vì vậy cả hai hệ thống mô-đun hoạt động. Một framework **được gói gọn vào kết quả của chính bạn** bởi esbuild hoặc webpack không thể tiếp cận — sử dụng các trợ giúp địa điểm gọi ở đó: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain mà không vá

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

Trình xử lý hoạt động với hoặc không có `instrument()` và không bao giờ bản ghi kép. `instrument("langchain")` lấy `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` và `captureLimit`, như bộ điều hợp Python làm; `metadata: { failproofai_sdk_session_id }` trên cuộc gọi chọn phiên cho lần gọi đó.

### Vercel AI SDK

AI SDK xuất các hàm đơn giản từ mô-đun ES, và không gian tên mô-đun ES không thể thay đổi được theo thông số kỹ thuật — không có nơi để vá. Nó sử dụng các điểm mở rộng mà SDK tự nó nêu:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // on ai 7, `telemetry: telemetry({ … })` — the same object, the new name
});
```

Đó là toàn bộ tích hợp: một khoảng agent, một cặp yêu cầu/phản hồi mô hình cho mỗi bước với số lượng mã thông báo, và mỗi cuộc gọi công cụ. Một địa điểm gọi hoạt động trên mỗi chính — `ai` 4–6 đọc tracer nó mang, `ai` 7 tích hợp telemetry.

`instrument("ai")` làm cách tương tự toàn bộ quy trình **trên `ai` 7**: mỗi cuộc gọi, thông qua danh sách tích hợp telemetry toàn cầu của AI SDK, được cộng lại và không lấy bất cứ điều gì từ người khác.

**Trên `ai` 4–6, `instrument("ai")` không ghi lại bất kỳ cái gì bởi chính nó, và ghi nhật ký một cảnh báo nói như vậy.** Lỗi toàn cầu duy nhất mà những chính có là trình cung cấp tracer OpenTelemetry toàn cầu — một lỗi duy nhất mà OpenTelemetry từ chối trao tay một khi lấy. Đăng ký của chúng tôi sẽ im lặng từ chối `NodeSDK.start()` của bạn sau trong khởi động và gửi span http/database của bạn đến tracer không xuất bất cứ điều gì. Sử dụng `telemetry()` tại địa điểm gọi hoặc `wrapModel` ở đó. Nếu quá trình không chạy OpenTelemetry của riêng nó, tùy chọn trong với `instrument("ai", { registerGlobalTracer: true })`: nó sau đó ghi lại mỗi cuộc gọi thông qua `experimental_telemetry: { isEnabled: true }`, và chỉ lấy lỗi nếu nó vẫn còn trống. `registerGlobalTracer: false` giữ mặc định và im lặng cảnh báo.

Nếu bạn muốn bọc mô hình một lần, `wrapModel` chỉ nhìn thấy các cuộc gọi mô hình, vì các cuộc gọi công cụ xảy ra ở trên lớp mô hình. Một mô hình được bọc gọi mà không có gì xung quanh nó được ghi lại như chạy riêng của nó. Một cuộc gọi được truyền đóng tuy nhiên dòng dừng — `stop_reason: "cancelled"` khi người tiêu dùng hủy nó, `"error"` với lỗi khi nó không thành công một phần:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Sử dụng cả hai là tốt: middleware nhận thấy cuộc gọi đã được ghi lại và xử lý, vì vậy mỗi cuộc gọi được ghi lại một lần.

`functionId` đặt tên agent span. Giữ nó cardinality thấp — nó hạ cánh trong `agent_id`, khía cạnh bảng điều khiển chính.

### Next.js

`next build` gói phụ thuộc máy chủ của bạn theo mặc định, và framework được gói gọn vào bản dựng là sao `instrument()` không thể tiếp cận. Bọc cấu hình một lần và gọi `instrument()` từ móc khởi động của Next:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` thêm LangChain, Mastra, LlamaIndex và chính SDK vào `serverExternalPackages`, giữ danh sách của bạn. Nếu không có nó, `instrument()` cảnh báo một lần cho mỗi framework nó không thể tiếp cận chứ không thất bại im lặng; nếu bạn tự liệt kê các gói, đặt `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK và trợ giúp địa điểm gọi hoạt động bằng cách nào đó. Lộ trình Edge nhận bản dựng không hoạt động: nhập SDK an toàn và ghi lại không có gì.

### Số lượng mã thông báo trên các cuộc gọi được truyền

Các API tương thích OpenAI chỉ báo cáo mức sử dụng trên một luồng khi máy khách yêu cầu. LangChain và Vercel AI SDK yêu cầu; đối với LlamaIndex chuyển `additionalChatOptions: { stream_options: { include_usage: true } }` đến LLM `OpenAI` của nó, và cho Mastra xây dựng mô hình với mức sử dụng được bật (ví dụ `createOpenAICompatible({ includeUsage: true })`). Ngoài ra các cuộc gọi mô hình được truyền không có số lượng mã thông báo.

### Runtimes

Node ≥ 20.9, Bun và Deno — mỗi framework, như mô-đun ES và CommonJS, được kiểm tra trên mỗi so với dấu vết của Node. SDK chạy bên cạnh daemon `failproofaid`, vận chuyển những gì nó viết.

## Agent riêng của bạn — không có framework

Cho vòng lặp agent bạn viết cho chính mình, hoặc framework mà không có bộ điều hợp. Bạn phát sự kiện với cùng một API các bộ điều hợp sử dụng bên dưới, vì vậy dấu vết có cùng một hình dạng và chất lượng.

Bạn không cần biết agent được tổ chức như thế nào. Mỗi agent được xây dựng bằng tay đã có ba nơi, bất kể các hàm của nó được gọi là gì, và ba cái này là toàn bộ tích hợp:

| Nơi | Cái để thêm | Phát |
| --- | --- | --- |
| Nơi **một lần chạy** bắt đầu và kết thúc | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Một hàm gọi mô hình** | `event.modelRequest` trước, `event.modelResponse` sau — cả hai nửa, ngay cả khi thất bại | một cặp cho mỗi lần quay mô hình |
| **Một hàm chạy công cụ** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Danh tính là môi trường: mọi thứ bên trong `agent()` hạ cánh trên phiên chạy đó mà không lấy id, và không có gì khác trong chương trình thay đổi — bao gồm bất kỳ cái gì agent viết vào cơ sở dữ liệu riêng của nó.

- **Một dịch vụ hoặc công nhân:** chuyển id yêu cầu hoặc công việc riêng của bạn làm `sessionId`, vì vậy một phiên trên bảng điều khiển và bản ghi trong nhật ký riêng hoặc cơ sở dữ liệu của bạn là chuỗi tương tự.
- **Sub-agents:** lồng các cuộc gọi `agent()`. Cái bên trong tham gia phiên với cái ngoài như `parent_id` của nó.
- **Phát các cặp.** `modelRequest` mà không có `modelResponse` là span bảng điều khiển hiển thị chạy mãi mãi — do đó `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) trong kho lưu trữ là phiên bản hoàn chỉnh, có thể chạy được: vòng công cụ OpenAI thực tế được thiết lập chính xác như thế này, chạy trong CI trên mỗi thay đổi như mô-đun ES và CommonJS.

## Đánh giá

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Xem [tham chiếu Evaluator SDK](/vi/reference/evaluator-sdk) cho giao thức, cài đặt công nhân và các loại kết quả.

</Warning>

## Cái nó sẽ không làm cho quá trình của bạn

| | |
| --- | --- |
| **Khóa vòng lặp agent của bạn** | Sự kiện đi vào hàng đợi trong bộ nhớ; bộ hẹn giờ viết chúng. Bộ hẹn giờ là `unref`'d, vì vậy nhập gói này không bao giờ dừng tập lệnh thoát. |
| **Phát triển mà không ràng buộc** | Hàng đợi được cấp bằng số *và* bởi byte đo lường. Quá cái nào, các sự kiện cũ nhất bị loại bỏ và cảnh báo nói như vậy — tảng ngoại được telemetry phải không trở thành vụ giết OOM. |
| **Lấy quá trình xuống** | Một sự kiện không thể mã hóa bị loại bỏ một mình, không phải lô xung quanh nó. Getter ném, tham chiếu vòng, `BigInt`, phím thay thế độc lập: mỗi cái được xử lý chứ không phải lan truyền. |
| **Để lại nửa lô được viết** | Nội dung được `fsync`ed trước khi đổi tên nguyên tử, thư mục được `fsync`ed sau, và viết không thành công làm sạch tệp tạm thời của nó. |
| **Để bản sao chép có thể đọc được** | Lô là `0600` bên trong thư mục `0700`. Họ mang mục tiêu, nhắc nhở, đối số công cụ và kết quả công cụ. |
| **Thuyền thông tin xác thực** | Khóa API, mã thông báo, JWT, tiêu đề người mang và gán hình dạng bí mật được sắc đỏ trước khi byte đến đĩa. Daemon làm sạch lại trước khi tải lên. |
