<Note>
  SDK này và SDK Python **ghi cùng một sự kiện vào cùng một spool**. Một fleet với các agents Node và agents Python tạo ra một tập sessions, không phải hai tập, và không có gì trong dashboard phân biệt chúng. Lựa chọn từng dịch vụ, không phải từng công ty.
</Note>

## Cài đặt

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

Các framework adapters được đóng gói trong chính package. Các frameworks là **optional peer dependencies** — được khai báo để các phạm vi được hỗ trợ hiển thị, không bao giờ được cài đặt thay bạn, và chỉ được import khi bạn gọi `instrument()`.

## Kết nối daemon Failproof

Giống hệt SDK Python: tạo một khóa `events:add` dưới **Admin → Keys**, sau đó [kết nối daemon](/vi/start/setup#connect-a-machine-to-cloud) trên máy agent. SDK ghi vào đĩa; daemon vận chuyển.

## Cấu hình

### OpenTelemetry spans (opt in)

Cài đặt OpenTelemetry riêng biệt với `npm install @opentelemetry/api @opentelemetry/sdk-trace-base`.
Sau đó thêm FailproofAI vào các processors của provider:

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

Đối với một provider hiện có, giữ các processors khác của nó trong cùng một danh sách. Các providers
có `addSpanProcessor` có thể được chuyển thành `{ provider }`. Không có tùy chọn, thiết lập đăng ký một provider mới chỉ nếu không có provider nào được đăng ký. `OtelSpanExporter` cũng có thể được sử dụng trực tiếp với processor của riêng bạn.

Các exports đi qua daemon FailproofAI được kết nối; SDK không gửi yêu cầu mạng và không cần khóa hoặc trình lắng nghe cục bộ. Yêu cầu admin bật [OpenTelemetry ingest](/vi/agenteye/opentelemetry). `instrument()` trần không bật exporter này. `uninstrument("otel")` chỉ vô hiệu hóa processor riêng của nó. Các thuộc tính span của bạn kiểm soát việc capture nội dung; flush provider trước khi thoát. OpenTelemetry vẫn là một optional application dependency, không phải hard SDK dependency.

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| Tùy chọn | Nó làm gì |
| --- | --- |
| `environment` | Nhãn trên mỗi sự kiện — `production`, `staging`, `prod-eu`. Mặc định là `dev`. |
| `flushInterval` | Bao thường timer ghi vào đĩa, tính bằng giây. Mặc định là `0.5`. |
| `baseDir` | Nơi để ghi. Mặc định là spool của daemon, đó là những gì bạn muốn trừ khi bạn biết khác. |

Không có gì được áp dụng trừ khi tất cả được xác thực, vì vậy một cuộc gọi bị từ chối sẽ để SDK chính xác như cũ thay vì có một `baseDir` mới và khoảng thời gian cũ.

Đặt bằng biến môi trường thay vào đó:

| Biến | Nó làm gì |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | Đặt `environment` mà không cần thay đổi mã. Tùy chọn `configure()` sẽ thắng nó. |
| `FAILPROOFAI_HOME` | Di chuyển gốc Failproof AI giữ spool. |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`, `info`, `warn` (mặc định), `error`, `silent`. |
| `FAILPROOFAI_SDK_STRICT` | `1` làm cho các lỗi tích hợp ném ra thay vì được ghi log. |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | `1` làm cho vấn đề tương thích framework ném ra thay vì cảnh báo và tiếp tục. |

<Warning>
  **Không có dấu phẩy trong `environment`.** Ingest chia tách trường đó thành dấu phẩy để xây dựng các bộ lọc của nó, và bỏ qua bất kỳ sự kiện nào có nhãn chứa một — vì vậy toàn bộ chạy sẽ biến mất một cách im lặng. Viết `prod-eu`, không phải `prod,eu`.

  `configure({ environment: "prod,eu" })` ném ra để bạn biết ngay lập tức. `AGENTEYE_ENVIRONMENT` không thể ném ra — không ai gọi bạn — vì vậy nó cảnh báo một lần và quay lại `dev`.
</Warning>

Định tuyến các dòng log riêng của SDK vào logger của bạn với `failproofai.setLogger({ debug, info, warn, error })`.

## Tắt

Các sự kiện được buffer được flush trên `process.on("exit")`.

Một quá trình bị kết thúc bởi một tín hiệu không bao giờ đạt được nó, và mặc định của Node cho `SIGTERM` là kết thúc mà không chạy exit handlers — vì vậy một agent được container hóa mất bất kỳ điều gì mà interval cuối cùng không ghi.

<Warning>
  **SDK này sẽ không cài đặt signal handler cho bạn.** Đăng ký một thay đổi hành vi của quá trình của bạn: một listener loại bỏ mặc định của Node, vì vậy một thư viện đã thêm một sẽ âm thầm dừng Ctrl-C hoạt động. Thêm của riêng bạn:

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

Một script ngắn hạn hoặc một serverless handler nên `await failproofai.flush()` trước khi trả về — interval một mình không đảm bảo delivery.

## Danh tính

Mỗi sự kiện thuộc về một session và một agent. **Các scopes điền cả hai vào**, vì vậy bạn hiếm khi chuyển chúng:

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

Chuyển `sessionId` hoặc `agentId` một cách rõ ràng vẫn hoạt động và thắng. Không có bound hay chuyển, cuộc gọi ném ra thay vì phát một sự kiện Cloud sẽ âm thầm loại bỏ.

<Note>
  Danh tính chạy trên `AsyncLocalStorage`. Nó theo dõi `await`, `.then()`, timers và bất kỳ callback nào được tạo bên trong scope. Nó **không** theo dõi một callback được lưu trữ trong một lần chạy và được gọi trong một lần khác, hoặc công việc được chuyển qua ranh giới `worker_threads` — bọc những cái trong `failproofai.propagate()` hoặc các sự kiện của chúng hạ cánh không được gắn.
</Note>

### Scopes

| Scope | Phát | Trả về |
| --- | --- | --- |
| `session(body)` | không có — chỉ danh tính | bất kỳ gì `body` trả về |
| `agent(id, options?, body)` | `agent_start`, sau đó `agent_end` | bất kỳ gì `body` trả về |
| `toolCall(name, options?, body)` | `tool_use`, sau đó `tool_result` | bất kỳ gì `body` trả về |

Một body đồng bộ vẫn đồng bộ: `agent("x", () => 1)` trả về `1`, không phải một promise.

`toolCall` ghi lại giá trị được resolve của body như là `output` của tool, trừ khi bạn gán `call.output` của riêng bạn.

<Accordion title="Exit semantics" icon="arrow-right-from-bracket">

| Điều gì đã xảy ra | Sự kiện | `outcome` |
| --- | --- | --- |
| block trả về | `agent_end` | `"success"`, hoặc `outcome` của bạn |
| block ném | `error`, sau đó `agent_end` | `"failed"` |
| một `AbortError` | chỉ `agent_end` | `"cancelled"` |

Lỗi luôn được ném lại.

Một tool failure được ghi lại trên leaf — `tool_result` với một chuỗi `error` — và phát **không** run-level `error` event. Một cái mà agent loop bắt không phải là run failure, và một cái lan truyền được báo cáo chính xác một lần, bởi bao quanh `agent()`.

</Accordion>

<Accordion title="Biểu mẫu `using`" icon="brackets-curly">

Khi công việc không phải là một hàm duy nhất — một scope được mở trong một constructor và đóng trong một teardown, hoặc một cái nhảy qua existing control flow:

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, sau đó agent_end
```

Cả hai biểu mẫu phát byte-identical events. Ưu tiên biểu mẫu callback: nó chạy bên trong `AsyncLocalStorage.run()`, vì vậy không có gì để unwind và toàn bộ lớp các bug "mở tại đây, đóng ở đó" là không thể tiếp cận.

Một `using` block bắt lỗi riêng của nó báo cáo nó với `span.fail(error)` — disposer không có exception channel riêng.

</Accordion>

## Danh mục sự kiện

Cùng mười lăm phương thức như SDK Python, trong camelCase. Hầu hết đều đi kèm **cặp** — bạn gọi opener, sau đó closer, và SDK tính toán khoảng cách.

| | Mở | Đóng |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **Models** | `modelRequest` | `modelResponse` |
| **Tools** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **Humans** | `humanWait` | `humanInput` |

Ba đứng riêng: `error`, `humanPause`, `humanInterrupt`.

<Accordion title="Mỗi trường, mỗi phương thức" icon="table">

Mỗi phương thức cũng nhận `sessionId` và `agentId`, mà các scopes điền vào cho bạn. Bất cứ cái gì bị bỏ qua được loại bỏ thay vì được gửi dưới dạng JSON `null`.

| Phương thức | Bắt buộc | Tùy chọn |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

Bất kỳ khóa nào khác bạn thêm đều trở thành một custom payload field. Namespace bất cứ cái gì framework-specific `fw_*`; một tên va chạm với một declared field bị từ chối thay vì âm thầm ghi đè một promoted column.

</Accordion>

<Warning>
  **`duration_ms` được tính toán, không được chấp nhận.** Bốn closing methods tính toán khoảng cách từ opener của chúng và từ chối một `duration_ms` được cung cấp bởi caller — một reported duration là unfalsifiable.

  Các cặp được khớp trên **session** và id, không bao giờ trên agent. Một tool được mở dưới `planner` và đóng dưới `worker` vẫn ghép đôi, đó là những gì nested multi-agent runs thực sự làm.
</Warning>

## Framework adapters

```ts
await failproofai.instrument();              // bất kỳ cái gì nó có thể tìm
await failproofai.instrument("langchain");   // chính xác một
failproofai.uninstrument();                  // đưa mọi thứ trở lại
```

| Framework | Được hỗ trợ | Cách nó gắn |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x, LangGraph.js 0.4 – 1.x | `CallbackManager.configure`, vì vậy mỗi `invoke`/`stream`/`batch` được bao phủ mà không cần chuyển `callbacks:` ở bất kỳ đâu — hoặc chuyển `langchainHandler()` của riêng bạn và không patch. |
| **Vercel AI SDK** | `ai` 4 – 7 | `telemetry()` tại call site, hoặc `instrument("ai")` cho toàn bộ quá trình trên `ai` 7 (trên 4–6 đó là opt-in — xem dưới). |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`, model và tool resolution của agent, và workflow run/step engine. |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager` (subscribed) cộng với `AgentWorkflow.runStream`, cho workflow runs và các steps của chúng. |

Mỗi phạm vi được kiểm tra so với các bản phát hành framework thực, ở cả hai đầu, như một ES module và như CommonJS, trên mỗi CI run.

Mapping là SDK Python, vì vậy cùng một chương trình vẽ cùng một cây ở một trong hai ngôn ngữ. Một construct là một **agent** chỉ nếu nó sở hữu một LLM decision loop — một graph hoặc chain run, một AI SDK `generateText`/`streamText` call, một Mastra agent, một LlamaIndex agent run. Một LangGraph node hoặc một workflow step là một **hook** (`hook_triggered`/`hook_completed`), không bao giờ là một nested agent. Model calls là `model_request`/`model_response` pairs với token counts; tool calls mang tool call id của riêng model. Một failure được ghi lại một lần, trên sự kiện nó xảy ra.

Một adapter không cài đặt được ghi log và bỏ qua; các cái khác vẫn cài đặt, bởi vì một LlamaIndex bị hỏng không nên làm bạn mất LangGraph.

<Note>
  `instrument()` không có đối số phát hiện framework bằng cách nó **resolves**, không phải bằng cách nó đã được import — Node không tiếp xúc tương đương của Python `sys.modules` cho ES modules. Một framework bạn đã cài đặt nhưng không sử dụng sẽ được import và patch. Đặt tên cái bạn muốn nếu điều đó có vấn đề.
</Note>

<Note>
  Hầu hết các frameworks này vận chuyển một ES-module build và một CommonJS build, mà Node tải như hai bản sao không liên quan. Các adapters patch bản sao ứng dụng của bạn tải (và bản sao CommonJS cũng nếu điều gì đó đã `require`d nó), vì vậy cả hai module systems hoạt động. Một framework **bundled vào output của riêng bạn** bởi esbuild hoặc webpack nằm ngoài tầm — sử dụng call-site helpers ở đó: `langchainHandler()`, `telemetry()`, `wrapTool()`.
</Note>

### LangChain không patch

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

Handler hoạt động với hoặc không có `instrument()` và không bao giờ double-record. `instrument("langchain")` nhận `sessionId`, `captureContent`, `includeChains`, `graphCallbacks` và `captureLimit`, khi SDK Python adapter làm; `metadata: { failproofai_sdk_session_id }` trên một call chọn session cho invocation đó.

### Vercel AI SDK

AI SDK xuất các hàm trơn từ một ES module, và một ES module namespace là immutable bằng thông số kỹ thuật — không có chỗ để patch. Nó sử dụng các extension points mà SDK chính nó ghi chép:

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // trên ai 7, `telemetry: telemetry({ … })` — cùng một object, tên mới
});
```

Đó là toàn bộ tích hợp: một agent span, một model request/response pair mỗi step với token counts, và mỗi tool call. Một call site hoạt động trên mỗi major — `ai` 4–6 đọc tracer nó mang theo, `ai` 7 the telemetry integration.

`instrument("ai")` làm cùng quá trình-wide **trên `ai` 7**: mỗi call, qua AI SDK's global telemetry-integration list, cái nào additive và không lấy bất cứ cái gì từ danh sách khác.

**Trên `ai` 4–6, `instrument("ai")` ghi không có gì bằng chính nó, và ghi log một cảnh báo nói vậy.** Duy nhất quá trình-wide hook những majors đó có là global OpenTelemetry tracer provider — một single slot OpenTelemetry từ chối để giao lại một khi được thực hiện. Đăng ký của chúng tôi sẽ im lặng từ chối của bạn `NodeSDK.start()` sau đó trong startup và gửi http/database spans của bạn đến một tracer không xuất. Sử dụng `telemetry()` tại call site hoặc `wrapModel` ở đó. Nếu quá trình chạy không OpenTelemetry của riêng nó, opt in với `instrument("ai", { registerGlobalTracer: true })`: nó sau đó ghi mỗi call chuyển `experimental_telemetry: { isEnabled: true }`, và chỉ nhận slot nếu nó vẫn trống. `registerGlobalTracer: false` giữ mặc định và im lặng cảnh báo.

Nếu bạn sẽ thích wrap model một lần, `wrapModel` thấy chỉ model calls, bởi vì tool calls xảy ra phía trên model layer. Một wrapped model gọi với không có gì xung quanh nó được ghi lại như chạy riêng của nó. Một streamed call đóng như thế nào stream dừng — `stop_reason: "cancelled"` khi consumer hủy nó, `"error"` với lỗi khi nó thất bại một phần:

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

Sử dụng cả hai tốt: middleware nhận thấy call đã được ghi lại và dở lại, vì vậy mỗi call được ghi lại một lần.

`functionId` đặt tên agent span. Giữ nó low-cardinality — nó hạ cánh trong `agent_id`, primary dashboard facet.

### Next.js

`next build` bundles dependencies server của bạn theo mặc định, và một framework bundled vào build là một bản sao `instrument()` không thể tiếp cận. Wrap config một lần và gọi `instrument()` từ Next's startup hook:

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` thêm LangChain, Mastra, LlamaIndex và SDK chính nó vào `serverExternalPackages`, giữ danh sách riêng của bạn. Không có nó, `instrument()` cảnh báo một lần mỗi framework nó không thể tiếp cận thay vì fail silently; nếu bạn liệt kê các packages chính nó, đặt `FAILPROOFAI_NEXT_EXTERNALS=1`. Vercel AI SDK và call-site helpers hoạt động bằng cách nào. Một Edge route nhận no-op build: importing SDK an toàn và ghi không có gì.

### Token counts trên streamed calls

OpenAI-compatible APIs chỉ báo cáo usage trên một stream khi client yêu cầu. LangChain và Vercel AI SDK yêu cầu; cho LlamaIndex chuyển `additionalChatOptions: { stream_options: { include_usage: true } }` đến `OpenAI` LLM của nó, và cho Mastra xây dựng model với usage enabled (ví dụ `createOpenAICompatible({ includeUsage: true })`). Nếu không streamed model calls mang không token counts.

### Runtimes

Node ≥ 20.9, Bun và Deno — mỗi framework, như một ES module và như CommonJS, được kiểm tra trên mỗi cái so với Node's trace. SDK chạy bên cạnh daemon `failproofaid`, mà vận chuyển những gì nó ghi.

## Agent riêng của bạn — không framework

Cho một agent loop bạn viết chính nó, hoặc một framework không có adapter. Bạn phát sự kiện với cùng API adapters sử dụng bên dưới, vì vậy trace có cùng hình dạng và chất lượng.

Bạn không cần biết agent được tổ chức như thế nào. Mỗi hand-built agent đã có ba nơi, bất kể hàm của nó được gọi là gì, và ba cái đó là toàn bộ tích hợp:

| Nơi | Điều gì để thêm | Phát |
| --- | --- | --- |
| Nơi **một run** bắt đầu và kết thúc | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **Một hàm gọi model** | `event.modelRequest` trước, `event.modelResponse` sau — cả hai nửa, thậm chí trên failure | một cặp mỗi model turn |
| **Một hàm chạy tools** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

Danh tính là ambient: tất cả bên trong `agent()` hạ cánh trên run's session đó mà không cần một id, và không có gì khác trong chương trình thay đổi — bao gồm bất kỳ gì agent đã ghi vào database riêng của nó.

- **Một dịch vụ hoặc một worker:** chuyển request hoặc job id riêng của bạn như `sessionId`, vì vậy một session trên dashboard và record trong logs hoặc database riêng của bạn là cùng một chuỗi.
- **Sub-agents:** nest `agent()` calls. Cái trong tham gia session với cái ngoài như `parent_id`.
- **Phát các cặp.** Một `modelRequest` không có `modelResponse` là một span dashboard hiển thị như chạy mãi mãi — do đó `catch`.

[`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) trong repository là phiên bản đầy đủ, runnable: một real OpenAI tool loop được tích hợp chính xác như thế này, chạy trong CI trên mỗi thay đổi như một ES module và như CommonJS.

## Evaluations

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

Xem [Evaluator SDK reference](/vi/reference/evaluator-sdk) cho protocol, worker settings và result types.

<Warning>
  **Một evaluation phải yield.** Một hàm đồng bộ không bao giờ trả về blocks one thread Node có, và không timeout có thể fire trong khi nó làm. Viết `async` evaluations.
</Warning>

## Điều gì nó sẽ không làm cho quá trình của bạn

| | |
| --- | --- |
| **Block agent loop của bạn** | Sự kiện đi vào một queue in-memory; một timer ghi chúng. Timer là `unref`'d, vì vậy importing package này không bao giờ dừng một script thoát. |
| **Phát triển không bị ràng buộc** | Queue bị capped bởi count *và* bởi measured bytes. Quá mỗi cái, các sự kiện cũ nhất bị loại bỏ và một cảnh báo nói vậy — một telemetry outage phải không trở thành một OOM kill. |
| **Lấy quá trình xuống** | Một unencodable event bị loại bỏ một mình, không batch xung quanh nó. Một throwing getter, một circular reference, một `BigInt`, một lone surrogate: mỗi cái được xử lý thay vì lan truyền. |
| **Để lại một half-written batch** | Nội dung là `fsync`ed trước một atomic rename, directory là `fsync`ed sau, và một failed write làm sạch tệp tạm thời của nó. |
| **Để lại transcripts readable** | Batches là `0600` bên trong một `0700` directory. Họ mang goals, prompts, tool arguments và tool output. |
| **Ship credentials** | API keys, tokens, JWTs, bearer headers và secret-shaped assignments được redacted trước bytes tiếp cận disk. Daemon redacts lại trước upload. |
