Cài đặt CLI cục bộ với `npm install -g failproofai`. Chạy nó mà không có tham số để mở bảng điều khiển chính sách cục bộ.

Gói yêu cầu Node.js 20.9 hoặc mới hơn. Bun 1.3 hoặc mới hơn được hỗ trợ cho phát triển và cài đặt từ nguồn. `failproofai configure` và `failproofai setup` là bí danh của `failproofai config`; `failproofai p` là bí danh của `failproofai policies`.

## Thiết lập một máy

```bash
npm install -g failproofai
failproofai config \
  --connect https://app.befailproof.ai \
  --token <machine-key> \
  --machine-label checkout-prod-01
failproofai policies --install
failproofai config --status
```

Chạy `failproofai` mà không có tham số để mở bảng điều khiển chính sách cục bộ.

| Lệnh | Kết quả |
| --- | --- |
| `failproofai config` | Chạy thiết lập máy tương tác |
| `failproofai config --connect <url> --token <key>` | Kết nối Cloud ingestion và chuyển giao chính sách |
| `failproofai config --status` | Hiển thị trạng thái kết nối, daemon, chuyển giao và tạm dừng |
| `failproofai policies` | Liệt kê chính sách tích hợp và tùy chỉnh |
| `failproofai policies --install` | Cài đặt hooks và bật chính sách |
| `failproofai policy add <name>` | Bật một chính sách tích hợp |
| `failproofai policy remove <name>` | Tắt một chính sách tích hợp |
| `failproofai policies --uninstall` | Tắt chính sách hoặc xóa hooks harness |
| `failproofai audit` | Quét lịch sử đại lý cục bộ và mở chế độ xem kiểm toán cục bộ |
| `failproofai audit --schedule [days] --email <address>` | Lên lịch quét cục bộ định kỳ và gửi phát hiện của chúng qua email |
| `failproofai audit --status` | Hiển thị địa chỉ báo cáo, khoảng thời gian và lần quét theo lịch tiếp theo |
| `failproofai audit --no-schedule` | Dừng quét định kỳ mà không xóa lịch sử kiểm toán |
| `failproofai harness list` | Liệt kê các đường dẫn capture bổ sung |
| `failproofai flush --wait` | Chuyển giao spool sự kiện hiện tại |
| `failproofai backfill --since 30d` | Đọc lại lịch sử đã qua trước đó |
| `failproofai config --pause [duration]` | Tạm dừng một phiên cục bộ trong 30 phút theo mặc định, tối đa 8 giờ |
| `failproofai config --resume` | Tiếp tục một phiên cục bộ đã tạm dừng; thêm `--all` để xóa tất cả tạm dừng |
| `failproofai update` | Hoàn thành di chuyển gói và cập nhật daemon |
| `failproofai migrate --dry-run` | Xem trước hoặc chạy di chuyển bố cục nhà đang chờ xử lý |
| `failproofai uninstall` | Xóa hooks và daemon trước khi xóa gói |
| `failproofai --version` | In phiên bản gói đã cài đặt |
| `failproofai --help` | Hiển thị các lệnh và cách sử dụng toàn cục |

## Cờ cấu hình

| Cờ | Sử dụng |
| --- | --- |
| `--connect <url> --token <key>` | Kết nối không tương tác |
| `--machine-id <id>` | Đặt ID máy ổn định |
| `--machine-label <name>` | Đặt hoặc thay đổi nhãn bảng điều khiển |
| `--no-transcripts` | Gửi quyết định mà không có nội dung bản ghi |
| `--disconnect` | Dừng kéo chính sách Cloud và chuyên giao sự kiện |
| `--status` | Hiển thị trạng thái máy hiện tại |
| `--pause [duration]` | Tạm dừng phiên mới nhất trong thư mục hiện tại; chấp nhận giây, phút hoặc giờ và mặc định là 30 phút |
| `--resume` | Kết thúc một tạm dừng phù hợp sớm |
| `--session <id>` | Nhắm mục tiêu một phiên rõ ràng để tạm dừng hoặc tiếp tục |
| `--all` | Với `--resume`, kết thúc mọi tạm dừng hoạt động |

Tạm dừng cục bộ tạm ngưng chính sách tích hợp, tùy chỉnh và quy ước cho một phiên. Chúng luôn hết hạn và không vô hiệu hóa chính sách do Cloud quản lý. `block-self-pause` ngăn một đại lý được hỗ trợ sử dụng lối thoát này cho chính nó.

## Cờ chính sách

| Cờ | Sử dụng |
| --- | --- |
| `--install`, `-i` | Bật chính sách và cài đặt hooks harness |
| `--uninstall`, `-u` | Tắt chính sách hoặc xóa hooks |
| `--cli <names...>` | Nhắm mục tiêu một hoặc nhiều harness được hỗ trợ |
| `--scope user\|project\|local\|all` | Chọn phạm vi cấu hình; `all` dành cho xóa |
| `--beta` | Bao gồm chính sách beta |
| `--custom`, `-c <path>` | Xác thực và tải tệp chính sách tùy chỉnh; có thể lặp lại |

## Cờ chuyên giao và bảo trì

| Lệnh | Cờ |
| --- | --- |
| `backfill` | `--since <30d\|6m\|YYYY-MM-DD>`, `--dry-run` |
| `flush` | `--wait`, `--timeout <seconds>` |
| `update` | `--no-daemon` |
| `migrate` | `--dry-run` |
| `uninstall` | `--purge`, `--dry-run`, `--yes` |

`failproofai update` nên được chạy sau `npm install -g failproofai@latest`; nó thực hiện di chuyển bố cục nhà, cài đặt nhị phân daemon phù hợp và khởi động lại dịch vụ. `--no-daemon` chỉ thực hiện di chuyển bố cục.

## Đường dẫn harness

```text
failproofai harness list [harness]
failproofai harness add-path <harness> [label=]<path>
failproofai harness remove-path <harness> <path-or-label>
```

Tên harness được hỗ trợ là `claude`, `codex`, `copilot`, `cursor`, `opencode`, `pi`, `hermes`, `openclaw`, `factory`, `devin`, `antigravity` và `goose`.

Nhãn không gian tách ID đại lý dẫn xuất khi hai gốc chứa bản sao của cùng một dự án. Gốc chồng chéo và nhãn trùng lặp bị từ chối để ngăn chặn tập hợp trùng lặp hoặc hỏng con trỏ. Cấu hình đường dẫn bổ sung tải lại mà không cần khởi động lại daemon.

Các môi trường container có thể thay thế các đường dẫn bổ sung được cấu hình tệp bằng một biến được phân tách bằng dấu phẩy có tên `FAILPROOFAI_<HARNESS>_EXTRA_PATHS`, ví dụ:

```bash
export FAILPROOFAI_OPENCLAW_EXTRA_PATHS="user1=/srv/openclaw-a,user2=/srv/openclaw-b"
```

## Biến môi trường

Sử dụng tệp cấu hình cho hành vi máy liên tục. Các biến môi trường hữu ích nhất cho container, test và một quá trình.

| Biến | Sử dụng |
| --- | --- |
| `FAILPROOFAI_HOME` | Chuyển vị trí bố cục `~/.failproofai` hoàn toàn |
| `FAILPROOFAI_LOG_LEVEL` | Đặt mức chi tiết ghi nhật ký cục bộ |
| `FAILPROOFAI_HOOK_LOG_FILE` | Ghi chẩn đoán hook vào một tệp được chọn |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | Vô hiệu hóa telemetry ẩn danh cho quá trình này |
| `FAILPROOFAI_NO_FIRST_RUN=1` | Bỏ qua thiết lập lần chạy đầu tiên tương tác |
| `FAILPROOFAI_NO_AUTO_AUDIT=1` | Bỏ qua kiểm toán cục bộ sau thiết lập |
| `FAILPROOFAI_LLM_BASE_URL` | Ghi đè điểm cuối tương thích OpenAI được sử dụng bởi chính sách LLM |
| `FAILPROOFAI_LLM_API_KEY` | Cung cấp khóa API được sử dụng bởi chính sách LLM |
| `FAILPROOFAI_LLM_MODEL` | Chọn mô hình được sử dụng bởi chính sách LLM |
| `FAILPROOFAI_POLICY_LOAD_TIMEOUT_MS` | Ràng buộc tải mô-đun chính sách tùy chỉnh |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | Thay thế các đường dẫn capture bổ sung được cấu hình cho một harness |
| `NO_COLOR` | Vô hiệu hóa đầu ra thiết bị đầu cuối màu |

Các biến nhà dành riêng cho đại lý như `CLAUDE_PROJECTS_PATH`, `CURSOR_HOME`, `HERMES_HOME` và `OPENCLAW_HOME` ghi đè nơi Failproof AI khám phá phiên cục bộ cho harness đó.

## Tạm dừng hoặc xóa một máy an toàn

```bash
failproofai config --pause
failproofai config --status
failproofai config --resume
```

Tạm dừng phiên cục bộ không vô hiệu hóa chính sách do Cloud quản lý. Khôi phục triển khai Cloud thông qua quy trình thực thi Cloud khi triển khai chính là vấn đề.

Trước khi xóa gói npm, hãy xóa các hooks và daemon đã cài đặt:

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

Chạy `failproofai <command> --help` để biết chi tiết cụ thể phiên bản.

<Warning>
  Chạy `failproofai uninstall` trước `npm rm -g failproofai`; npm không xóa các hook đại lý được cài đặt hoặc dịch vụ daemon.
</Warning>
