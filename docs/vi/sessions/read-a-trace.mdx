Một trace là dòng thời gian của một lần chạy agent. Hãy bắt đầu từ sự kiện bất thường đầu tiên, không phải từ lỗi cuối cùng.

<Tabs>
  <Tab title="Dashboard">
    1. Mở **Observe → Sessions**.
    2. Chọn một session.
    3. Tìm kiếm lỗi đầu tiên, lệnh gọi tool bất thường, thời gian chờ dài, hoặc quyết định policy.
    4. Mở sự kiện và kiểm tra request, response, input và output.

    ![Một session detail view với execution graph, event timeline, evaluation panel, và tool, model, hook breakdown.](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all --limit 5000
    fp --json events --full --session-id <session-id> --all --limit 2000
    ```

    Sử dụng `--full` chỉ khi tóm tắt sự kiện không cung cấp đủ bằng chứng. Một `next_cursor` không rỗng có nghĩa là giới hạn đã được đạt trước khi kết thúc.
  </Tab>
</Tabs>

## Theo dõi bằng chứng

1. Xác nhận agent, mục tiêu, môi trường và kết quả.
2. Tìm lỗi đầu tiên hoặc quyết định bất thường.
3. Kiểm tra sự kiện ngay trước nó.
4. Theo dõi các ID khớp nhau trên các cặp request và response.
5. Chuyển bằng chứng thành audit, issue, hoặc policy.

| Cặp | Trường khớp |
| --- | --- |
| Model request và response | `request_id` |
| Tool call và result | `tool_call_id` |
| Hook start và completion | `hook_id` |
| Agent pause và resume | `pause_id` |
| Human wait và input | `input_id` |

Một quyết định xuất hiện trên `hook_completed`. Dòng này đặt tên kết quả và nguồn policy. Một quyết định observe-mode xuất hiện như allow với verdict sẽ xảy ra trong `failproofai_observed`.

<Warning>
  Thời lượng session dài không phải lúc nào cũng là latency của model. Phân tách thời gian model, tool, hook và human-wait trước khi quyết định cần sửa chữa điều gì.
</Warning>
