failproofai có hai bộ test: **unit tests** (nhanh, được mock) và **end-to-end tests** (thực thi subprocess thực tế).

---

## Chạy các test

```bash
# Chạy tất cả unit tests một lần
bun run test:run

# Chạy unit tests ở chế độ watch
bun run test

# Chạy E2E tests (cần thiết lập - xem bên dưới)
bun run test:e2e

# Type-check mà không cần build
bunx tsc --noEmit

# Lint
bun run lint
```

## Unit tests

Unit tests nằm trong `__tests__/` và sử dụng [Vitest](https://vitest.dev) với `jsdom`.

```text
__tests__/

    builtin-policies.test.ts      # Logic chính sách cho mỗi builtin
    hooks-config.test.ts          # Tải config và hợp nhất scope
    policy-evaluator.test.ts      # Inject param và thứ tự đánh giá
    custom-hooks-registry.test.ts # globalThis registry add/get/clear
    custom-hooks-loader.test.ts   # ESM loader, transitive imports, xử lý lỗi

    ...

    logger.test.ts
    paths.test.ts

    ...

    get-hooks-config.test.ts
    get-hook-activity.test.ts
    ...

```

### Viết một unit test cho chính sách

```typescript
import { describe, it, expect, beforeEach } from "vitest";
import { getBuiltinPolicies } from "../../src/hooks/builtin-policies";
import { allow, deny } from "../../src/hooks/policy-types";

describe("block-sudo", () => {
  const policy = getBuiltinPolicies().find((p) => p.name === "block-sudo")!;

  it("denies sudo commands", () => {
    const ctx = {
      eventType: "PreToolUse" as const,
      payload: {},
      toolName: "Bash",
      toolInput: { command: "sudo apt install nodejs" },
      params: { allowPatterns: [] },
    };
    expect(policy.fn(ctx)).toEqual(deny("sudo command blocked by failproofai"));
  });

  it("allows non-sudo commands", () => {
    const ctx = {
      eventType: "PreToolUse" as const,
      payload: {},
      toolName: "Bash",
      toolInput: { command: "ls -la" },
      params: { allowPatterns: [] },
    };
    expect(policy.fn(ctx)).toEqual(allow());
  });

  it("allows patterns in allowPatterns", () => {
    const ctx = {
      eventType: "PreToolUse" as const,
      payload: {},
      toolName: "Bash",
      toolInput: { command: "sudo systemctl status nginx" },
      params: { allowPatterns: ["sudo systemctl status"] },
    };
    expect(policy.fn(ctx)).toEqual(allow());
  });
});
```

## End-to-end tests

E2E tests gọi binary `failproofai` thực tế như một subprocess, đưa payload JSON vào stdin, và kiểm tra output stdout và mã thoát. Điều này kiểm tra toàn bộ đường dẫn tích hợp mà Claude Code sử dụng.

### Thiết lập

E2E tests chạy binary trực tiếp từ mã nguồn repo. Trước lần chạy đầu tiên, hãy build bundle CJS mà các tệp custom hook sử dụng khi import từ `'failproofai'`:

```bash
bun build src/index.ts --outdir dist --target node --format cjs
```

Sau đó chạy các test:

```bash
bun run test:e2e
```

Rebuild `dist/` mỗi khi bạn thay đổi public hook API (`src/hooks/custom-hooks-registry.ts`, `src/hooks/policy-helpers.ts`, hoặc `src/hooks/policy-types.ts`).

### Cấu trúc E2E test

```text
__tests__/e2e/
  helpers/
    hook-runner.ts      # Tạo binary, đưa payload JSON vào, bắt mã thoát + stdout + stderr
    fixture-env.ts      # Các thư mục tạm thời cô lập theo từng test với tệp config
    payloads.ts         # Các factory payload chính xác với Claude cho mỗi loại sự kiện
  hooks/
    builtin-policies.e2e.test.ts   # Mỗi chính sách builtin với subprocess thực tế
    custom-hooks.e2e.test.ts       # Tải custom hook và đánh giá
    config-scopes.e2e.test.ts      # Hợp nhất config trên project/local/global
    policy-params.e2e.test.ts      # Inject tham số cho mỗi chính sách có tham số
```

### Sử dụng E2E helpers

**`FixtureEnv`** - môi trường cô lập theo từng test:

```typescript
import { createFixtureEnv } from "../helpers/fixture-env";

const env = createFixtureEnv();
// env.cwd    - thư mục tạm; truyền thành payload.cwd để chọn .failproofai/policies-config.json
// env.home   - thư mục home cô lập; không có rò rỉ ~/.failproofai thực tế

env.writeConfig({
  enabledPolicies: ["block-sudo"],
  policyParams: {
    "block-sudo": { allowPatterns: ["sudo systemctl status"] },
  },
});
```

`createFixtureEnv()` đăng ký dọn dẹp `afterEach` tự động.

**`runHook`** - gọi binary:

```typescript
import { runHook } from "../helpers/hook-runner";
import { Payloads } from "../helpers/payloads";

const result = await runHook(
  "PreToolUse",
  Payloads.preToolUse.bash("sudo apt install nodejs", env.cwd),
  { homeDir: env.home }
);

expect(result.exitCode).toBe(0);
expect(result.parsed?.hookSpecificOutput?.permissionDecision).toBe("deny");
```

**`Payloads`** - các payload factory có sẵn:

```typescript
Payloads.preToolUse.bash(command, cwd)
Payloads.preToolUse.write(filePath, content, cwd)
Payloads.preToolUse.read(filePath, cwd)
Payloads.postToolUse.bash(command, output, cwd)
Payloads.postToolUse.read(filePath, content, cwd)
Payloads.notification(message, cwd)
Payloads.stop(cwd)
```

### Viết một E2E test

```typescript
import { describe, it, expect } from "vitest";
import { createFixtureEnv } from "../helpers/fixture-env";
import { runHook } from "../helpers/hook-runner";
import { Payloads } from "../helpers/payloads";

describe("block-rm-rf (E2E)", () => {
  it("denies rm -rf", async () => {
    const env = createFixtureEnv();
    env.writeConfig({ enabledPolicies: ["block-rm-rf"] });

    const result = await runHook(
      "PreToolUse",
      Payloads.preToolUse.bash("rm -rf /", env.cwd),
      { homeDir: env.home }
    );

    expect(result.exitCode).toBe(0);
    expect(result.parsed?.hookSpecificOutput?.permissionDecision).toBe("deny");
  });

  it("allows non-recursive rm", async () => {
    const env = createFixtureEnv();
    env.writeConfig({ enabledPolicies: ["block-rm-rf"] });

    const result = await runHook(
      "PreToolUse",
      Payloads.preToolUse.bash("rm /tmp/file.txt", env.cwd),
      { homeDir: env.home }
    );

    expect(result.exitCode).toBe(0);
    expect(result.stdout).toBe("");  // allow → empty stdout
  });
});
```

### Hình dạng phản hồi E2E

| Quyết định | Mã thoát | stdout |
|----------|-----------|--------|
| `PreToolUse` deny | `0` | `{"hookSpecificOutput":{"permissionDecision":"deny","permissionDecisionReason":"..."}}` |
| `PostToolUse` deny | `0` | `{"hookSpecificOutput":{"additionalContext":"Blocked ... because: ..."}}` |
| Instruct (non-Stop) | `0` | `{"hookSpecificOutput":{"additionalContext":"Instruction from failproofai: ..."}}` |
| Stop instruct | `2` | stdout rỗng; lý do trong stderr |
| Allow | `0` | chuỗi rỗng |

### Config Vitest

E2E tests sử dụng `vitest.config.e2e.mts` với:

- `environment: "node"` - không cần browser globals
- `pool: "forks"` - cách ly quy trình thực sự (tests tạo subprocesses)
- `testTimeout: 20_000` - 20 giây cho mỗi test (khởi động binary + đánh giá hook)

Pool `forks` rất quan trọng: các worker dựa trên luồng chia sẻ `globalThis`, điều này có thể can thiệp với các test tạo subprocess. Các forks dựa trên quy trình tránh điều này.
