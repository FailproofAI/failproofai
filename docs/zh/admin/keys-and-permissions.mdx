为每位人员、每台机器或每个自动化任务使用独立的密钥，并仅授予其所需的权限。

## 创建和轮换密钥

使用 **Admin → Keys**，或通过 Cloud CLI 操作：

```bash
fp keys list
fp keys create "audit automation" --add audits:read
fp keys disable "audit automation"
```

密钥在创建时需立即保存，之后将不再显示。轮换密钥的步骤为：创建新密钥，更新使用方，然后停用旧密钥。

## 机器密钥

机器密钥用于将本地服务连接到 Cloud：

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

已连接的机器可能需要以下两项能力：

- `policies:pull`：接收 Cloud 管理的策略。
- `events:add`：发送决策记录和会话数据。

状态报告会分别显示这两项，因为其中一项可能正常而另一项异常。

## 常用权限

| 权限 | 说明 |
| --- | --- |
| `events:add` | 发送事件 |
| `events:read` | 读取事件和错误信息 |
| `evaluations:read` | 读取会话和评估记录 |
| `audits:read` / `audits:write` | 查看或管理审计记录 |
| `policies:read` / `policies:write` | 查看或部署策略 |
| `policies:pull` | 拉取机器策略分配 |
| `keys:create` / `keys:disable` | 创建或停用密钥 |
| `orgs:admin` | 实例级别的组织管理；不可分配给组织密钥 |

部分 `fp fleet` 和 `fp guardrails` 管理命令需要已登录的用户会话，而非 API 密钥。其帮助文本会在发起请求前注明这一要求。

<Warning>
  请勿将 `AGENTEYE_KEY` 或 `AGENTEYE_API_KEY` 等摄取凭据复用为 `FP_API_KEY`。它们服务于不同的系统，对应不同的权限。
</Warning>
