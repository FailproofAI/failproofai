管理功能是 Failproof AI 的 Cloud 端。组织、成员、API 密钥、组织设置和计量用量均需要 Cloud 连接。

<Note>
  Failproof AI 也可以在完全没有账户的情况下运行。本地机器可以执行策略、将会话历史保存在磁盘上、在 `localhost:8020` 上提供[本地仪表板](/zh/reference/local-dashboard)，并运行 `failproofai audit` 而不向任何地方发送任何内容。请参阅[机器配置](/zh/reference/events-and-configuration#machine-configuration)了解本地 `collector` 键。如果您不使用 Cloud，请跳过本节的其余内容。
</Note>

## 控制项所在位置

<Tabs>
  <Tab title="仪表板">
    Cloud 侧边栏的 **admin** 分组包含 **policy editor**、**enforcement**、**usage**、**keys**、**users** 和 **settings**。

    ![Cloud 侧边栏的 admin 分组，包含 policy editor、enforcement、usage、keys、users 和 settings。](/images/dashboard/admin-navigation.png)
  </Tab>
  <Tab title="CLI">
    将 Cloud CLI 作为独立工具安装，然后登录：

    ```bash
    uv tool install fp-cloud-cli
    fp login
    fp whoami
    fp usage
    ```

    将全局选项放在命令之前，例如 `fp --org reliability-team --json usage`。
  </Tab>
</Tabs>

## 已登录用户或 API 密钥

`fp` 以两种身份验证模式之一运行，这一划分决定了哪些命令可用。API 密钥无法执行的命令会在建立连接之前拒绝执行，并明确说明原因，而不是让 401 或 403 错误代替解释。

| 命令 | API 密钥 | 权限 |
| --- | --- | --- |
| `fp whoami` | 是 | 无 |
| `fp usage` | 是 | `usage:read` |
| `fp keys list` / `show` | 是 | `keys:read` |
| `fp keys create` | 是 | `keys:create` |
| `fp keys disable` | 是 | `keys:disable` |
| `fp keys regenerate` | 是 | `keys:regenerate` |
| `fp keys update` | 否 | `keys:update`（任何密钥均不可持有此权限） |
| `fp users list` / `show` | 是 | `users:read` |
| `fp users create` | 是 | `users:create` |
| `fp users update` | 是 | `users:update` |
| `fp users disable` / `enable` | 是 | `users:delete` |
| `fp settings list` / `schema` | 是 | `settings:read` |
| `fp settings set` | 是 | `settings:write` |
| `fp orgs list` / `switch` / `current` / `perms` | 否 | 仅限已登录会话 |

`fp usage` 是供报告脚本使用的命令：它可在密钥下无人值守地运行，仅需 `usage:read` 权限。
