Failproof AI Cloud 会向其维护者发送**有关软件本身**的使用遥测数据，不包含任何 Agent 数据。在自托管安装中，遥测默认开启，你可以将其关闭。

## 收集的内容

每个事件包含五个维度，不包含任何个人识别信息：

| 维度 | 示例 | 含义 |
| --- | --- | --- |
| `product` | `agenteye` | 发送事件的产品 |
| `component` | `dashboard`, `server`, `cli` | 产品中发送事件的部分 |
| `app_version` | `0.0.1-beta.81` | 你正在运行的版本 |
| `deployment_kind` | `self_hosted` | 是客户安装、演示环境、QA 环境还是开发机器 |
| `org_id` | 一个 UUID | 操作发生所属的组织，以不透明标识符表示 |

在此基础上，事件记录**使用了什么，而非其中的内容**：浏览了哪个页面（以路由模式表示，如 `/:org/sessions/:id`，而非真实 URL）、应用了哪种类型的过滤器及数量、操作是否成功，以及耗时多久。

Slack 应用会记录工作区的连接与断开、账户关联、提问、图表发布、审批决策以及按固定类别划分的错误。它从不包含 Slack 工作区、用户或频道 ID、电子邮件、问题、答案、SQL 或令牌。

### 你的组织名称

除不透明的 `org_id` 外，我们会将你的组织名称、URL slug 和仪表盘地址记录一次，存储在组织记录中而非每个事件中。这样当我们分析使用趋势或调查你反馈的问题时，可以识别某种模式属于哪个账户。这是产品发送的唯一一项关于你的可识别信息。

### 你的使用量统计

服务器会上报每个组织的计量使用量统计，与你在使用量页面看到的数字相同。这些仅为计数数据：事件、会话、Agent、环境、评估运行、评分、审计运行、已保存查询、仪表盘、告警、问题、API 密钥和成员数量，以及计量窗口的日期。这些数据不包含任何标识符、名称或查询文本，且无论是否有人登录都会上报。

## 从不收集的内容

- **不收集提示词、模型响应或事件内容**，无论是文本、前缀还是哈希值
- **不收集会话、Agent 或追踪标识符**
- **不收集评估器评分名称**
- **不收集错误消息、异常文本或响应体**，仅记录状态码和固定列表中的类别
- **不收集工具参数、SQL 或查询文本**
- **不收集已连接应用的详细信息**，连接或撤销 MCP 客户端时最多发送权限数量，不包含应用名称或任何令牌
- **不收集电子邮件地址**
- **不收集 Referrer URL 或查询字符串**
- **不收集屏幕录制、DOM 捕获，或点击和光标追踪**

## 在自托管安装中关闭遥测

在仪表盘和服务器上同时设置 `DO_NOT_TRACK=1`。两者独立判断，仅在其中一端设置会导致另一端仍在上报。重启服务器以使更改生效。

你的发布版 README 中介绍了其他退出设置以及如何确认遥测已关闭。

## 退出时的一次 ping

如果你通过产品设置（而非 `DO_NOT_TRACK`）退出遥测，仪表盘可能会发送**一次匿名 ping**记录此操作，每次进程启动触发概率为千分之一。这用于告知我们有多少运营者关闭了遥测。该 ping 不包含任何标识符：无组织、用户、主机名、URL 或 IP，仅包含产品、组件、版本、部署类型和原因。已退出遥测的服务器不会发送任何内容。

使用 `DO_NOT_TRACK` 时永远不会发送此 ping，因此如果你的策略禁止任何出站遥测，请使用该设置。

## 数据发送至何处

通过 TLS 在 443 端口发送至 PostHog（`us.i.posthog.com`）。只有一个主机名，因此你也可以通过单条出站规则将其屏蔽。

有关我们如何更广泛地处理个人信息，请参阅[隐私政策](https://befailproof.ai/privacy/)。
