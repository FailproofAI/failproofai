Failproof AI Cloud 会向其维护者发送**关于软件本身**的使用遥测数据，绝不包含您的 Agent 数据。在自托管安装中，遥测默认开启，您可以将其关闭。

## 收集哪些数据

每个事件携带五个维度，不包含任何可识别个人身份的信息：

| 维度 | 示例 | 含义 |
| --- | --- | --- |
| `product` | `agenteye` | 发送事件的产品 |
| `component` | `dashboard`, `server`, `cli` | 发送事件的产品组件 |
| `app_version` | `0.0.1-beta.81` | 您正在运行的构建版本 |
| `deployment_kind` | `self_hosted` | 是客户安装、演示环境、QA 环境还是开发机器 |
| `org_id` | 一个 UUID | 操作发生所在的组织，以不透明标识符表示 |

除此之外，事件还记录**使用了什么，而非其中的内容**：查看了哪个页面（以路由模式表示，例如 `/:org/sessions/:id`，而非真实 URL）、应用了多少种类型的筛选器、操作是否成功，以及耗时多长。

Slack 应用记录工作区的连接与断开、账户关联、提问、图表发送、审批决策以及按固定类别划分的失败情况。它从不包含 Slack 工作区、用户或频道 ID、邮箱、问题、回答、SQL 或令牌。

### 您的组织名称

除不透明的 `org_id` 外，我们还会记录您的组织名称、URL slug 和控制台地址，仅记录一次，存储在组织记录中而非每个事件中。这使我们在分析采用情况或排查您反馈的问题时，能够识别某个模式属于哪个账户。这是产品关于您所发送的唯一可识别信息。

### 您的使用量汇总

服务器会上报每个组织的计量使用量汇总，与您在使用量页面看到的数字相同。这些仅为计数数据：事件、会话、Agent、环境、评估运行、评分、审计运行、已保存查询、控制台、告警、问题、API 密钥和成员，以及计量周期的日期范围。它们不包含任何标识符、名称或查询文本，且无论是否有人登录都会上报。

## 从不收集哪些数据

- **不收集提示词、模型响应或事件内容**，无论是文本、前缀还是哈希值
- **不收集会话、Agent 或追踪标识符**
- **不收集评估器评分名称**
- **不收集错误消息、异常文本或响应体**，仅收集状态码和来自固定列表的类别
- **不收集工具参数、SQL 或查询文本**
- **不收集已连接应用的详细信息。** 连接或撤销 MCP 客户端最多发送权限数量，从不发送应用名称或任何令牌
- **不收集电子邮件地址**
- **不收集引用 URL 或查询字符串**
- **不进行屏幕录制、DOM 捕获或点击与光标追踪**

## 在自托管安装中关闭遥测

在控制台和服务器上均设置 `DO_NOT_TRACK=1`。两者独立判断，因此仅在其中一个上设置，另一个仍会上报数据。重启服务器以使更改生效。

您的版本 README 中说明了其他可选退出设置以及如何确认遥测已关闭。

## 退出时的一次性 ping

如果您通过产品设置而非 `DO_NOT_TRACK` 退出，控制台可能会发送**一次匿名 ping** 记录此行为，每次进程启动的概率为千分之一。这告诉我们有多少运营者关闭了遥测。它不包含任何标识符：无组织、用户、主机名、URL 或 IP，仅包含产品、组件、版本、部署类型和原因。已退出的服务器不发送任何数据。

使用 `DO_NOT_TRACK` 时永远不会发送此 ping，这也是当您的策略禁止任何出站遥测时应使用该设置的原因。

## 数据发往何处

通过 TLS 在 443 端口发送至 PostHog（`us.i.posthog.com`）。只有一个主机名，因此您也可以通过单条出口规则将其屏蔽。

有关我们如何更广泛地处理个人信息，请参阅[隐私政策](https://befailproof.ai/privacy/)。
