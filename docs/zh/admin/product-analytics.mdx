Failproof AI Cloud 向其维护者发送**有关软件本身**的使用遥测数据，从不包含您的代理数据。在自托管安装中，遥测默认开启，您可以将其关闭。

## 收集的内容

每个事件携带五个维度，不包含任何能识别个人身份的信息：

| 维度 | 示例 | 含义 |
| --- | --- | --- |
| `product` | `agenteye` | 发送事件的产品 |
| `component` | `dashboard`, `server`, `cli` | 产品中发送事件的部分 |
| `app_version` | `0.0.1-beta.81` | 您正在运行的版本 |
| `deployment_kind` | `self_hosted` | 是否为客户安装、我们的演示环境、QA 环境或开发机器 |
| `org_id` | 一个 UUID | 操作发生所在的组织，以不透明标识符表示 |

除上述维度外，事件还记录**使用了什么，而非内容是什么**：访问了哪个页面（以路由模式表示，如 `/:org/sessions/:id`，而非实际 URL）、应用了多少种类的筛选条件、操作是否成功，以及耗时多长。

Slack 应用会记录工作区连接与断开、账户关联、提问、图表发布、审批决策及按固定分类划分的失败情况，但绝不包含 Slack 工作区、用户或频道 ID、邮箱、提问内容、回答、SQL 或令牌。

### 您的组织名称

除不透明的 `org_id` 外，我们会记录您的组织名称、URL 标识符和仪表板地址，仅记录一次，存储在组织记录中而非每个事件中。这样当我们分析使用情况或排查您反映的问题时，可以识别出某个模式属于哪个账户。这是产品发送的关于您的唯一一条识别性信息。

### 您的使用量统计

服务端会上报每个组织的计量使用量总计，与您在使用量页面看到的数字相同。这些均为计数数据：事件、会话、代理、环境、评估运行、评分、审计运行、已保存查询、仪表板、告警、问题、API 密钥及成员，加上计量窗口的日期。其中不包含任何标识符、名称或查询文本，且无论是否有人登录均会上报。

## 从不收集的内容

- **不收集提示词、模型响应或事件内容**，无论是文本、前缀还是哈希值
- **不收集会话、代理或追踪标识符**
- **不收集评估器评分名称**
- **不收集错误消息、异常文本或响应体**，仅收集状态码和来自固定列表的分类
- **不收集工具参数、SQL 或查询文本**
- **不收集已连接应用的详情**，连接或撤销 MCP 客户端时，最多发送权限数量，不包含应用名称或任何令牌
- **不收集邮箱地址**
- **不收集来源 URL 或查询字符串**
- **不进行屏幕录制、DOM 捕获或点击/光标追踪**

## 在自托管安装中关闭遥测

在仪表板和服务端均设置 `DO_NOT_TRACK=1`。两者各自独立判断，因此只在其中一个上设置会导致另一个仍在上报。需重启服务端使更改生效。

您的版本 README 中描述了其他退出设置以及如何确认遥测已关闭。

## 退出时的一次 ping

如果您通过产品设置而非 `DO_NOT_TRACK` 退出，仪表板可能会发送**一次匿名 ping** 来记录此操作，每次进程启动触发概率为 1/1000。这用于告知我们有多少运营者关闭了遥测。该 ping 不包含任何标识符：无组织、用户、主机名、URL 或 IP，仅包含产品、组件、版本、部署类型和原因。已退出的服务端不发送任何数据。

使用 `DO_NOT_TRACK` 时永远不会发送此 ping，因此如果您的策略禁止任何出站遥测，请使用该设置。

## 数据发送至何处

通过 TLS 在 443 端口发送至 PostHog（`us.i.posthog.com`）。只有这一个主机名，因此您也可以通过一条出站规则将其屏蔽。

关于我们如何更广泛地处理个人信息，请参阅[隐私政策](https://befailproof.ai/privacy/)。
