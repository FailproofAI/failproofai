在问题越过您的红线时立即收到通知，消息直达您团队常用的渠道，而不是等到客户反映才知道。规则只需设置一次，Failproof AI Observability 便会按计划检查，并通过电子邮件、Slack、Webhook 或仪表板内通知的方式提醒您。

![告警页面：由告警规则卡片组成的网格，每张卡片显示触发条件、评估窗口、通知渠道，以及信息、警告或严重等级徽章](/agenteye/images/alerts.png)
*一览所有告警规则：监控对象、检查频率、通知渠道及紧急程度。*

## 在用户发现之前率先掌握问题

不必再盯着仪表板刷新以期捕捉到异常。每当有需要持续关注的信号时，设置一条告警，让通知直接送达您的工作场所：

- **电子邮件**，发送给需要知情的人员。
- **Slack**，附带跳转至事故详情按钮的富文本消息。
- **Webhook**，向 PagerDuty、Opsgenie 或您自定义的端点发送 JSON POST 请求，支持可选签名以便接收方验证来源。
- **仪表板内通知**，默认静默，适合在调试规则时使用，避免打扰他人。

一条规则可绑定任意组合的通知渠道，并携带严重等级（信息、警告或严重），确保紧急告警一眼可辨。

## 在表单中定义规则，无需编写 JSON

您在表单中描述"故障"的含义，Failproof AI Observability 便会为您生成底层规则。JSON 规格不过是表单在底层产出的内容，方便您阅读理解规则，但几乎无需手动编写。

![新建告警表单：名称与描述、启用开关，以及触发器选择器，提供指标阈值、自定义 SQL、评估分数、复合评估和单事件条件等选项](/agenteye/images/alert-new.png)
*选择触发器后，表单会自动切换到对应字段；点击保存即可写入规则。*

常规操作流程简洁明了：为规则命名，选择**触发器**（监控对象），设置**阈值和时间窗口**（严重程度及持续时长），绑定至少一个**通知渠道**，然后**保存**并点击**测试**，发送一次模拟通知，确认所有目标渠道均已正确接入。底层生成的规格大致如下：

```json
{ "metric": "p95_latency_ms", "op": ">", "value": 5000, "window_secs": 900 }
```

可监控的信号类型不止一种。请根据您对故障的理解选择合适的触发器：

| 触发器 | 触发条件 |
|---|---|
| **指标阈值** | 预设指标（错误率、p95 或 p99 延迟、事件或错误计数、Token 消耗）在指定时间窗口内越过设定值 |
| **自定义 SQL** | 您的只读查询返回行数据，或其计算值越过阈值 |
| **评估分数** | 某个评估器分数的均值（如幻觉率）越过阈值 |
| **复合评估** | 多项分数检查以 any、all 或至少 N 个的逻辑组合，用于捕捉仅在多个分数维度综合体现的回归 |
| **单事件** | 匹配到单个特定事件：特定 Agent、特定错误类型或消息子字符串 |

正在[错误页面](/zh/agenteye/error-tracking)排查故障？每一行都有一个 **+ 告警** 按钮，点击后会打开预填了该故障信息的告警创建表单，让您刚刚处理过的事故成为下次自动提醒您的规则。

**入口位置：** 告警功能位于 `/<org-slug>/alerts`。创建、编辑、删除和测试规则需要 **`alerts:write`** 权限；仅浏览则 `alerts:read` 即可。收件人选择器按姓名列出您组织的成员，无需离开表单即可指定通知对象。

## 只在真正异常时提醒我

单次不良测量不应触发告警。**M of N** 降噪过滤器控制在最近几次检查中有多少次失败才真正触发告警。设置为 **3 of 5** 时，规则仅在最近五次检查中有三次超阈值后才触发，避免抖动信号频繁误报；保持默认的 **1 of 1** 则首次超阈即触发。您还可以选择规则的运行频率，可选预设包括 1m、5m、15m 和 1h，与信号变化的实际速度相匹配。

## 告警触发后的处理流程

一次超阈会开启一个**事故**，并向您的通知渠道发送一次提醒。随后，您的团队可对事故进行确认、指派负责人、协同讨论并最终解决，全程记录清晰、责任明确。该分诊工作流有专属页面，详见[事故](/zh/agenteye/incidents)。
