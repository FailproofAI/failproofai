用自然语言向你的 Agent 数据提问，并获得直接链接到证据的答案。无需编写 SQL，无需翻遍各个仪表盘——**Failproof AI Observability** 助手是团队成员获取 Agent 相关答案最快捷的方式。

![Failproof AI Observability 助手在仪表盘中回答自然语言问题，展示实时 Agent 活动表、每个 Agent 的模型使用情况分解以及文字要点，并内联显示其执行的查询](/agenteye/images/assistant.png)
*用自然语言提问，获取基于你自己数据构建的答案。这里它分析了哪些 Agent 最繁忙、它们使用了哪些模型，并展示了其运行的查询，以便你验证每一个数字。*

无需学习任何东西。打开聊天窗口，输入你想知道的内容，然后点击它返回的链接：

```
You:  which sessions errored today?
AI:   5 sessions errored today, newest first. Each one is linked:
      • checkout-agent   14:02   tool timeout
      • billing-agent    11:47   unhandled error
      • ...and 3 more

You:  summarize this session          (asked while viewing a run)
AI:   This run took 12 steps across 3 tools and failed near the end when a
      payment tool returned an error. It scored low on your "resolved" eval.
      Links: the session, the failing event, and that evaluation.
```

## 直接提问，直达证据

你不再需要猜测，也不再需要编写查询。提问"本周生产环境的质量趋势如何？"、"今天哪些会话出错了？"或"总结一下这个会话"，几秒钟内即可获得直接答案，而无需自己构建查询并逐一解读。

每个答案都附有来源凭证。助手会链接到它用于得出答案的确切会话、已保存的查询和仪表盘，让你可以点击验证，而不必只是相信它的话。它还具备**页面感知能力**：当你正在查看某个会话时，询问"这个会话"，它已经知道你指的是哪次运行。之后可以从历史记录切换器中重新打开任何之前的对话，从上次中断的地方继续。

## 将好答案保存为查询或仪表盘

当某个答案值得保留时，可以让助手将其保存。它会为已保存的查询起草 SQL，或从这些查询中组建一个仪表盘，然后向你显示一张**批准 / 拒绝**卡片。在你点击"批准"之前，不会写入任何内容，因此你既能享受"直接提问"的速度，又始终保有最终决定权。

在**查询**页面，助手会更进一步，化身为 SQL 编写者：描述你想要的查询（"按 Agent 显示过去 7 天的错误率"），它会将 SQL 直接流式传输到编辑器，并打开差异视图，让你在落地前**接受**或**拒绝**更改。

![Observability 查询页面及其 SQL 编辑器](/agenteye/images/query-lab.png)
*查询页面：助手会在这个编辑器中流式传输一份草稿（只读查询），供你接受或拒绝。*

在此处通过提问来编写 SQL 使用的是 `queries:run` 权限，与编辑器中**运行**按钮背后的权限相同。其他地方的聊天功能需要 `agent:use` 权限。

## 可放心开放给全团队使用

你可以将助手开放给所有人，而不必担心它会触及什么：

- **它只读取你已有权限查看的内容。** 答案的范围限定在你自己的读取权限内，因此它永远不会扩大你的数据访问面。
- **每次写入操作都需要你确认。** 已保存的查询和仪表盘仅在你明确点击"批准"后才会创建，且没有任何设置可以关闭这道关卡。
- **它永远无法删除任何内容。** 不暴露任何删除工具，助手也不持有删除权限。删除操作始终由你在仪表盘中掌控。
- **它仅在你的组织内运作。** 助手始终只能看到你当前正在查看的组织。
- **你的问题只属于你。** 提示词和答案存储在你自己的 Observability 数据库中；产品分析仅记录使用元数据，而非你的提示词文本。

## 在哪里找到它

助手位于你的组织（`/<org-slug>/...`）下每个页面右侧边栏。点击边栏，或按 `⌘J` / `Ctrl+J`，可将其展开为完整的聊天面板；拖动边缘可调整大小，你设置的宽度在刷新后仍会保留。使用它需要 **`agent:use`** 权限，否则边栏将显示为灰色。如果你的部署尚未启用该功能（需要配置 LLM 连接），你将看到一个静默的边栏，而非可用的聊天界面。
