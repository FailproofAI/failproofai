*每项审计都是一个定期任务，负责挖掘您的会话数据并输出按优先级排列、有据可查的建议。*

## 不再猜测下一步要修复什么

告警用于捕获您已知需要关注的问题，而审计则用于捕获您尚未意识到的问题。按照您设定的计划，审计会读取所有 Agent 会话并寻找值得修复的模式，让您将时间花在处理发现结果上，而不是漫无目的地翻阅日志。

单次运行会针对生产环境中真正影响 Agent 的故障模式展开分析：

- **错误集群**：由共同根因导致的重复故障。
- **与基线的偏差**：行为悄然偏离已知正常状态的情况。
- **会话中的目标失败**：技术上完成执行但未完成任务的运行。
- **工具滥用**：使用错误的工具、传入错误的参数，或造成调用浪费的循环。
- **质量与成本的权衡**：您为本可以更低成本获得的输出付出了过多费用的情况。
- **覆盖盲区**：没有任何评估或告警在监控的行为。

您可以通过单一的**灵敏度**设置（低、中或高）控制分析力度，从而让嘈杂的预发布 Agent 和严格管控的生产 Agent 各自调整到所需的信号水平。

## 每条建议都附有证据

您无需凭信任接受任何发现。每条建议都会引用其来源的具体会话以及用于发现问题的 SQL 语句，让您只需点击一下即可查看证据并确认问题，而无需对结论进行逆向推断。

这也是保持审计诚实性的机制。服务器会验证每条引用的会话是否真实存在，并**丢弃任何证据站不住脚的建议**，因此审计只会调查，从不凭空捏造。最终出现在清单上的问题都是真实的、可复现的，并按重要程度排序，影响最大的问题位于顶部。

## 将修复转化为防护措施

修复问题只是成功的一半。另一半是确保问题不会悄然复发。每项发现都附带一个**一键快捷操作，可起草复发告警**，预填了合理的初始触发条件供您调整。关闭发现结果，启用告警，下次该模式再次出现时，您将收到通知，而不是在未来的审计中再次发现它。

## 在哪里找到它

审计位于仪表板的 **`/<org-slug>/audits`**（侧边栏路径：分析 → 审计）。查看运行记录和发现结果需要 **`audits:read`** 权限；创建、编辑和处理审计需要 **`audits:write`** 权限。设置审计的范围和频率，需要立即获得结果时点击 **立即运行**，无需等待下一次定时运行。
