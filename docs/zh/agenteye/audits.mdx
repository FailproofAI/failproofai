*每项审计都是一个周期性任务，负责挖掘您的会话数据并生成有优先级排序、有证据支撑的建议报告。*

## 不再猜测下一步该修什么

告警只能捕获您已知的问题，而审计能发现那些您尚未意识到的问题。按照您设定的计划，审计会读取您所有的 Agent 会话数据，主动寻找值得修复的模式，让您把时间花在落实发现上，而不是滚动日志、靠运气自己发现问题。

一次运行即可针对生产环境中真正破坏 Agent 的各类故障模式展开排查：

- **错误聚类**：由同一根本原因反复触发的故障。
- **相对基线的偏移**：行为悄悄偏离已知良好状态窗口。
- **会话转录中的目标失败**：技术上已完成但实际未完成任务的运行。
- **工具滥用**：使用了错误的工具、传入了错误的参数，或陷入循环耗尽调用次数。
- **质量与成本的权衡**：找出您为本可以更低成本获得的输出而多付费的地方。
- **覆盖盲区**：没有任何评估或告警在监控的行为。

您只需通过一个**灵敏度**设置（低、中、高）来决定排查力度，这样嘈杂的预发布 Agent 和严格管控的生产 Agent 都可以根据您期望的信号单独调整。

## 每条建议都附有凭证

您无需对任何发现盲目相信。每条建议都会引用其来源的精确会话记录和用于发现它的 SQL 语句，让您只需点击一下即可查看证据、确认问题，而无需费力推断一个结论。

这也是审计保持诚实的关键所在。服务器会验证每条被引用的会话是否真实存在，**并丢弃任何证据无法核实的建议**，因此审计只做调查，从不捏造结果。出现在您清单上的内容都是真实、可复现的，并按影响程度从高到低排序，最重要的改进点排在最前面。

## 将修复转化为防护措施

修复一个问题只是成功的一半，另一半是确保它不会悄悄卷土重来。每项发现都附有一个**一键生成复发告警的快捷方式**，预填了合理的起始触发条件供您调整。关闭发现、启用告警，下次该模式再次出现时，您会收到通知，而不是在未来的某次审计中再次发现它。

## 在哪里找到它

审计功能位于仪表板的 **`/<org-slug>/audits`** 页面（侧边栏依次进入 *analyze* → *audits*）。查看运行记录和发现内容需要 **`audits:read`** 权限；创建、编辑和处理审计需要 **`audits:write`** 权限。设置审计的范围和频率后，随时点击 **Run now** 即可立即获取结果，无需等待下次定时执行。
