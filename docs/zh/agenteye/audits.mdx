*每项审计都是一个周期性任务，持续挖掘您的会话数据并输出经过优先级排序、有据可查的建议。*

## 不再猜测下一步该修什么

告警能捕捉到您已知晓并主动监控的问题；审计则能发现那些您尚未意识到的问题。按照您设定的计划，审计会遍历您所有的 Agent 会话，寻找值得修复的模式——让您将时间花在处理发现上，而不是翻查日志、碰运气地寻找线索。

单次审计运行会针对生产环境中真正会让 Agent 出问题的故障模式展开排查：

- **错误聚类**：同一故障在共同根因下反复出现。
- **与基线的偏差**：行为悄然偏离已知的正常窗口。
- **会话记录中的目标未达成**：技术上已完成但实际上未执行任务的运行。
- **工具误用**：使用了错误的工具、传入了错误的参数，或陷入消耗大量调用次数的循环。
- **质量与成本的权衡**：在本可以更低成本获得相同输出的地方支付了过高费用。
- **覆盖盲区**：没有任何评估或告警在监控的行为。

您只需通过一个**灵敏度**设置（低、中、高）来控制审计力度，从而对嘈杂的预发布 Agent 和严格管控的生产 Agent 分别进行针对性调优。

## 每条建议都有据可查

您无需对任何发现盲目信任。每条建议都会引用其来源的具体会话以及用于发现问题的 SQL，让您只需点击一下便可查看证据并确认问题，而无需费力地反向推导某个结论。

当发现涉及凭据泄露时，系统会更进一步，直接链接到匹配的具体事件。点击后，您将精准跳转到会话中的那个时刻，且该事件已处于选中状态——而不是跳到一段冗长会话记录的顶部让您慢慢翻阅。链接中显示的是事件名称；检测到的敏感信息本身不会被复制到发现内容中，因此阅读一条发现不会成为您的凭据被二次记录的地方。如果某个事件因会话已超出您的数据保留期而不复存在，页面会明确告知，而不是让您疑惑自己是否点错了。

这也是保持审计诚实性的关键所在。服务器会验证每个被引用的会话确实存在，并**丢弃任何证据不成立的建议**，因此审计只负责调查，绝不凭空捏造。最终出现在您清单上的内容都是真实的、可复现的，并按影响程度排序，最具价值的改进项位居首位。

## 将修复转化为防护机制

修复一个问题只完成了一半。另一半是确保它不会悄悄卷土重来。每条发现都附带一个**一键创建复发告警的快捷方式**，并预填了一个合理的初始触发条件供您调整。关闭发现、启用告警，下次该模式再次出现时，您会收到通知，而不是在未来的审计中重新发现它。

## 在哪里找到它

审计功能位于仪表板的 **`/<org-slug>/audits`** 页面（侧边栏 → *analyze* → *audits*）。查看运行结果和发现需要 **`audits:read`** 权限；创建、编辑和处理审计需要 **`audits:write`** 权限。设置审计的范围和频率，然后在需要立即获取结果而不想等待下次定时执行时，点击 **Run now** 即可。
