只需一条命令，即可完成整个 Failproof AI 可观测性部署。无需离开终端，即可检查生产环境、创建 API 密钥或确认事件，还可以将任意操作编写成脚本集成到 CI 中，或用自然语言让代码智能体替你完成。

```bash
pipx install agenteye
agenteye login --email you@example.com      # 一个 6 位验证码将发送到你的邮箱
agenteye --json sessions --since 24h         # 过去 24 小时内的所有智能体运行记录，最新的排在最前
```

*`agenteye` CLI 与你的控制台通信，是一个独立工具，不同于负责向服务器发送事件的采集器。*

## 整个部署，一条命令搞定

不必再来回切换标签页来回答一个简单问题。`agenteye` CLI 通过单一二进制文件读取数据并管理你的组织，原本需要在控制台中点来点去的操作，现在只需一行命令就能完成——你可以反复执行、设置别名，或者直接粘贴到运维手册里。它提供四个功能入口：

- **读取数据：** `sessions`、`events`、`evals` 和 `errors`，支持按时间、智能体和环境进行过滤。
- **管理组织：** `keys`、`users`、`settings`、`alerts` 和 `incidents`。
- **运行分析：** 保存的 SQL 语句，以及针对事件数据的即席 `query` 执行器。
- **调用助手：** `agent ask` 可连接控制台中同款只读分析助手。

用 `pipx` 安装一次，通过邮件发送的 6 位验证码登录，即可开始使用。会话有效期约为一天，过期后重新执行 `agenteye login` 即可。无需打开浏览器，直接用它来检查生产环境、创建密钥或排查告警事件：

```bash
agenteye errors --since 24h --aggregate      # 查看出错情况，按错误类型分组汇总
agenteye incidents list --state firing       # 查看当前正在告警的事件
agenteye keys create ci --add events:add     # 创建一个只能推送事件的密钥，密钥内容仅显示一次
```

有一个使用习惯需要注意：`--json` 等全局选项必须放在命令之前。`agenteye --json sessions` 是正确的写法；`agenteye sessions --json` 则不正确。

## 编写脚本，集成到 CI

每条命令都支持 `--json`，这让一切变得不同。JSON 数据输出到 stdout，而人类可读的状态信息和警告输出到 stderr，因此 `--json` 的输出可以直接通过管道传给 `jq`，无需额外过滤多余内容。这正是 CLI 既适合你在命令提示符下手动使用，也适合代码智能体解析输出的原因：

```bash
agenteye --json sessions --since 24h --status error | jq -r '.sessions[].session_id'
```

它专为无人值守运行而设计。当没有终端连接时，确认提示会自动跳过，因此不会导致管道阻塞。每条命令都返回有意义的退出码：`0` 表示成功，`4` 表示未登录，`5` 表示缺少权限（消息中会具体说明，例如 `alerts:write`），`3` 表示控制台不可达。脚本可以根据 `4` 来重新认证，或根据 `5` 来明确告知需要向管理员申请哪些权限，而不是盲目失败。

## 用自然语言让代码智能体来驱动

更进一步，其实你根本不需要记住这些参数。**CLI 技能**是一个名为 `agenteye-cli` 的小型 Agent Skill 文件夹，它能让 Claude Code 或 Codex 等代码智能体通过自然语言请求来驱动 CLI。你只需问"今天有什么问题吗？"，智能体会自动选择合适的命令，以你的身份执行，并以自然语言给出答复。

对于 Claude Code，将 `agenteye-cli` 文件夹放入 `~/.claude/skills/` 即可自动发现。Failproof AI Observability 提供该文件夹，无需额外安装任何内容，因为它只是驱动你已经安装的 CLI。请先自行登录：该技能无法替你完成邮件验证码登录流程。

由于智能体以你的身份运行 CLI，它可以执行你的登录权限允许的一切操作，包括读取和写入：创建密钥、修改设置、解决事件。CLI 的"确认操作"提示不会向智能体触发，因此该技能的设计方式是：在执行任何变更操作前，明确说明将要执行的命令，并等待你确认。你就是那个确认步骤。

```text
你      为什么 session run-001 失败了？

智能体  正在执行：agenteye --json events --session-id run-001 --all
        checkout-agent 在第三次工具调用时遇到了 TimeoutError。
```

读取操作即时返回，所有写入操作都会等待你确认：

```text
你      给 CI 创建一个只能推送事件的密钥。

智能体  此操作将创建一个 API 密钥，我将执行：
          agenteye keys create ci --add events:add
        确认执行？

你      是的

智能体  完成。已创建密钥 "ci"，权限为仅 events:add。该密钥内容仅显示一次，请立即保存。
```
