通过终端或脚本驱动所有 Failproof AI Observability 功能，无需往返仪表盘。`agenteye` CLI 可查询你的数据（会话、事件日志、评估）并管理你的组织（API 密钥、用户、设置、告警、事件、保存的查询），适合用于自动化检查、将 Observability 接入 CI，或让编码 Agent 检查生产环境。每条命令都支持 `--json` 标志，无论是你在终端手动操作，还是编码 Agent（Claude Code、Cursor）调用并解析结果，都同样适用。

有了这一个二进制文件，你可以：

- **读取数据**：`sessions`、`events`、`evals`、`errors`（按时间、Agent、环境、评分过滤）。
- **管理组织**：`keys`、`users`、`settings`、`alerts`、`incidents`。
- **运行分析**：保存的 SQL 及临时查询运行器（`query`）。
- **咨询 AI 助手**：与仪表盘中相同的只读分析助手（`agent`）。

> **注意：** 这是 `agenteye` CLI，与采集守护进程（`agenteye-collector`）是不同的工具。CLI 与你的仪表盘通信；采集器负责将事件发送到服务器。

## 快速开始

从零到第一个结果，只需四行命令。将 CLI 指向你的仪表盘，登录，确认身份，然后拉取最近一天的运行记录：

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # 通过邮件发送 6 位验证码
agenteye whoami                                                                  # 确认用户 + 当前活跃组织
agenteye --json sessions --since 24h                                             # 每行一条 Agent 运行记录，最近 24 小时
```

最后一条命令会打印包含最近会话的 JSON 对象（最新的排在前面，默认最多返回 50 条）。可通过管道传给 `jq` 进行切片处理，或去掉 `--json` 以获得带边框、带颜色的表格展示。每行包含运行状态，以及评估器给出的评分（此处为简略版）：

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

本页其余部分将逐一介绍各个环节：[安装](#installation)（隔离环境）、[登录](#authentication)、[配置](#configuration)、每条命令共享的[全局规范](#global-options--conventions)，以及[完整命令参考](#command-reference)。

## 安装

CLI 是一个名为 **`agenteye`** 的公开 PyPI 包。建议安装在隔离环境中，以保证其始终拥有独立的依赖：

```bash
pipx install agenteye
# 或
uv tool install agenteye
```

需要 Python 3.10+。安装后的命令名为 **`agenteye`**：

```bash
agenteye --version
agenteye --help
```

> **注意：** Failproof AI Observability Python SDK 也使用 `agenteye` 作为发行包名。通过 `pipx` 或 `uv tool` 安装 CLI（而非 `pip install` 到共享虚拟环境）可以避免两者冲突。只有当 SDK 未安装在同一环境中时，才可以直接使用 `pip install agenteye`。

## 认证

CLI 通过邮件一次性验证码向**仪表盘**进行认证：

```bash
agenteye login --email you@example.com
# 系统会向你的邮箱发送一个 6 位验证码，粘贴到提示处即可。
```

会话令牌存储在 `~/.agenteye/cli.json`（仅你可读，权限为 `0600`），默认有效期为 24 小时。过期后，重新运行 `agenteye login` 即可。

```bash
agenteye whoami     # 显示当前用户、活跃组织及权限
agenteye logout     # 吊销会话并清除本机存储的令牌
```

`whoami` 在会话缺失或过期时不会报错，而是返回 `logged_in: false`，因此脚本或 Agent 可以安全地探测认证状态（但若未设置 base URL 或仪表盘不可达，仍可能以非零状态退出）。

**前提条件：** 你的邮箱必须被允许登录仪表盘（请联系你的 Failproof AI Observability 管理员），且仪表盘必须在其 base URL 处可访问（参见[配置](#configuration)）。如果请求了验证码但未收到，说明你的邮箱可能尚未开通仪表盘访问权限。

## 选择组织（多租户）

如果你的账号属于多个组织，请在**登录时**选择活跃组织；该选择将被保存并用于后续所有命令：

```bash
agenteye login --org acme           # 一步完成认证并设置活跃租户
agenteye orgs list                  # 列出你可访问的组织（当前活跃的会标记出来）
agenteye orgs switch globex         # 更改保存的默认组织
agenteye --org globex sessions      # 仅针对单条命令临时覆盖
```

如果你只属于一个组织，系统会自动选中，`--org` 可完全忽略。如果你属于多个组织但未指定，CLI 会列出所有组织并提示你带 `--org <slug>` 重新运行。活跃组织会随每个请求发送到仪表盘，权限也**按组织**解析；`agenteye whoami` 会显示当前活跃组织、你在其中的权限，以及你的所有成员资格。

## 配置

| 设置项 | 标志 | 环境变量 | 默认值 |
|---|---|---|---|
| 仪表盘 base URL | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **必填**（无默认值） |
| 活跃组织/租户 | `--org` | `AGENTEYE_ORG` | 登录时选择；保存在 `~/.agenteye/cli.json` |
| 会话令牌 | `--token` | `AGENTEYE_CLI_TOKEN` | 来自 `~/.agenteye/cli.json` |
| JSON 输出 | `--json` | `AGENTEYE_CLI_JSON` | 关闭 |
| 跳过 TLS 验证 | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | 关闭（登录时保存） |
| 请求超时（秒） | `--timeout` | _（无）_ | 30 |
| 禁用使用遥测 | _（无）_ | `AGENTEYE_ANALYTICS_DISABLED`（或 `DO_NOT_TRACK`） | 遥测当前已禁用；不发送任何数据 |

解析优先级为**标志 → 环境变量 → 配置文件**。无默认值，你必须为 CLI 指定仪表盘地址，可在每条命令中指定（`--base-url https://agenteye.example.com`），或通过环境变量一次性配置（首次 `login` 后也会自动保存）：

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

配置目录遵循 `AGENTEYE_HOME` 环境变量（与 SDK 和采集器使用相同的约定）；若已设置，`cli.json` 存放于 `$AGENTEYE_HOME/cli.json`。

### 自签名或内部 TLS

如果你的仪表盘使用自签名或内部证书（例如原始负载均衡器主机名）提供 HTTPS 服务，TLS 验证会报 `CERTIFICATE_VERIFY_FAILED` 错误。可传入 `--insecure` 跳过证书验证：

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` **在登录时会保存到 `cli.json`**，后续命令会自动跳过验证，无需重复传入该标志。若需对单次调用强制验证，可传入 `--secure`，或在下次登录时将验证保存回开启状态。在验证禁用期间，任何与仪表盘通信的命令执行前，CLI 都会向 stderr 打印警告。跳过验证会移除对中间人攻击的防护，请确保在依赖此选项之前，你信任到仪表盘的网络路径（VPN、私有子网等）。

## 遥测与隐私

> **注意：** 当前发布的 CLI **不发送任何使用遥测数据**。主开关处于关闭状态，无论你的环境如何，都不会传输任何数据。以下部分描述的是选择退出功能，供遥测功能未来可能启用时参考。

即便启用遥测，也**仅限匿名使用分析，绝不包含你的 Agent、会话或事件数据**：

- **你的 Agent、会话或事件数据绝不会离开你的基础设施。** 只会上报 CLI 使用情况：命令和子命令名称（例如 `keys create`）、你使用的标志**名称**（绝不含标志的值）、成功/退出状态、耗时，以及变更操作的每个动作事件（例如 `api_key_created`、`query_run`，仅包含静态名称/枚举和粗粒度计数）。你的仪表盘 URL、会话令牌、邮箱、组织 slug、资源 ID、SQL、密钥机密及查询过滤器**绝不会被发送**。运营者仅通过不透明的内部 ID 标识，不含邮箱。
- **提前选择退出**：在 CLI 的环境中设置 `AGENTEYE_ANALYTICS_DISABLED=1`（CLI 也支持跨工具的 `DO_NOT_TRACK=1` 约定）。一旦遥测功能启用，此设置立即生效，隐私敏感环境可永久保持退出状态。
- 若遥测被启用，CLI 会直接发送到 PostHog（`https://us.i.posthog.com`）；封锁该主机的机器将静默地不发送任何数据，CLI 功能不受影响。

## 全局选项与规范

请阅读本节；以下规范适用于每条命令。

- **全局选项必须放在命令之前。** `agenteye --json sessions` 是正确的；`agenteye sessions --json` 是用法错误。全局选项包括 `--json`、`--base-url`、`--org`、`--token`、`--insecure`/`--secure`、`--timeout`、`--quiet` 和 `--no-color`。
- **`--json` 仅向 stdout 输出纯 JSON，不含其他内容。** 人类可读的状态行、警告和错误信息输出到 **stderr**，因此即使有状态行显示，`--json` 的 stdout 捕获内容依然干净，可直接管道传给 `jq`。不加 `--json` 时，将显示带边框、带颜色的人类可读视图。
- **通过 `--help` 探索用法。** 每条命令和子命令都有 `--help`（以及 `-h` 别名）：`agenteye -h`、`agenteye sessions -h`、`agenteye keys create -h`。顶层帮助还列出了退出码和全局选项。没有全局的机器可读接口摘要；请使用各命令的 `--help`，以及特定领域的 `agenteye query schema` 和 `agenteye settings schema` 来查阅对应注册表。
- **确认提示在脚本和 Agent 下自动跳过。** 创建/更新/删除命令在交互式终端中会提示"是否确认"，但**在 `--json` 模式下或 stdin 不是 TTY 时会自动跳过该提示**（TTY 是交互式终端会话；管道或 CI 运行器不是），因此脚本和 Agent 永远不会卡住。可传入 `--yes`/`-y` 显式跳过。由于 Agent 不会触发确认提示，Agent 在执行破坏性操作前应先向人类确认。
- **分页：** 结果按最新优先排列，采用游标分页（每页返回一个令牌，用于获取下一页）。`--limit N`（别名 `-n`）限制行数，**默认为 50**；`--all` 自动翻页（每次 200 行）**直到达到 `--limit`**，因此裸 `--all` 仍会在 50 条时停止。若要完整扫描，请传入较大的显式上限：`--all --limit 1000`。`--page-size N` 控制每次请求的分块大小（最大 200）；`--cursor <id>` 从上一页的 `next_cursor` 处继续。
- **时间过滤：** `--since` 接受相对时间窗口：`15m`、`1h`、`6h`、`24h`、`7d` 或 `all`（仪表盘的预设值）。对于更长或自定义的时间范围（如最近 30 天），请使用 `--from`/`--to`：必须是**带 `T` 和时区的** ISO-8601 UTC 时间戳（例如 `2026-06-01T00:00:00Z`），会覆盖 `--since`。以空格分隔或不带时区的值是用法错误。
- **`--fields a,b,c`**（适用于 `events`、`sessions`、`evals`、`errors`）将输出限制为指定字段，对表格视图和 `--json` 均有效。未知字段名会被拒绝并给出有效列表，这是一种快速发现字段名的方式。
- **`--file payload.json`**（或 `--file -` 读取 stdin）用于在资源形状复杂时提供完整的 JSON 请求体（适用于 `alerts create/update`、`settings set` 和 `users create/update`）。保存的查询 SQL 改用 `--sql @file.sql`。
- **多值过滤器**以逗号分隔 → 作为集合匹配（同一过滤器内为并集，不同过滤器之间为 AND）：`--event-type tool_use,tool_result`。Click 选项不支持可变参数，所以 `--add a b` 会报错。请使用 `--add a,b`，重复该标志（`--add a --add b`），或加引号（`--add "a b"`）。

## 命令参考

### 最常用的 5 条命令

大多数日常工作都通过少数几条读取命令完成。先从这里开始，再按需查阅下方的完整接口：

| 命令 | 功能说明 | 示例 |
|---|---|---|
| `sessions` | 每行一条 Agent 运行记录：时间、环境、Agent、状态、最新评分。 | `agenteye --json sessions --since 24h --status error` |
| `events` | 运行内每步的原始追踪记录（加 `--full` 显示载荷）。 | `agenteye --json events --session-id run-001 --all` |
| `evals` | 评估结果和评分；`--aggregate` 汇总统计。 | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | 仅显示出错的事件；`--aggregate` 按类型统计数量。 | `agenteye --json errors --since 24h --aggregate` |
| `list` | 发现有效的过滤值（Agent、环境、模型等）。 | `agenteye list agents` |

### CLI 的全部功能

以下是完整接口说明。CLI 共有 **18 个顶级命令**。所有读取命令均支持 `--json` 和上述全局选项；运行 `agenteye <command> -h`（或 `<command> <subcommand> -h`）可查看任意命令的完整标志列表和 JSON 结构。

### 身份认证：`login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # 邮件一次性验证码；保存会话
agenteye logout                                       # 清除本机保存的会话
agenteye whoami                                       # 当前用户、活跃组织、权限
agenteye version                                      # 打印 CLI 版本（与 --version 相同）
agenteye help                                         # 顶层帮助（与 --help 相同）
```

`orgs` 用于查看和切换活跃租户：

```bash
agenteye orgs list        # 你的组织 + 你在每个组织中的角色（当前活跃的会标记）
agenteye orgs switch acme # 更改保存的活跃组织（在 TTY 下省略 slug 可从列表中选择）
agenteye orgs current     # 当前活跃组织的身份信息
agenteye orgs perms       # 你在当前活跃组织中的权限（按资源分组）
```

### 观测（只读）：`events` · `sessions` · `evals` · `errors` · `list`

这些命令均无需确认。共享过滤器：`--session-id`、`--agent-id`、`--env`（**不是** `--environment`）以及时间范围（`--since` / `--from` / `--to`）。

```bash
# events（别名：每步原始追踪），最新优先
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions：每行一条 Agent 运行记录（时间/环境/Agent/会话/状态；不支持评分过滤）
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals：评估结果 + 评分；--score 按指标过滤，--aggregate 汇总统计
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # 状态分布 + 各键评分统计

# errors：出错的事件；--aggregate 统计数量/会话/Agent/最后出现时间
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list：过滤前先发现有效的过滤值
agenteye list envs        # 还有：agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX`（适用于 **`evals`**，不适用于 `sessions`）可重复使用，多个条件之间为 AND 关系；任一边界均可省略（`..0.5` 表示 ≤ 0.5，`0.9..` 表示 ≥ 0.9）。每次请求最多支持 20 个评分过滤器。`evals --scores-full` 是**仅供人类表格视图**使用的展示标志；它会显示所有评分对，而非仅显示前几个加 `+N` 计数。在 `--json` 模式下无效，该模式始终返回完整的评分对象。若要**端到端读取一个会话**，可将事件追踪与评估结果结合：

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # 该会话的评分 + 状态
```

### 管理（需权限）：`keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**：API 密钥。密钥在本地生成后发送到服务器（服务器只存储哈希值），并在**创建/重新生成时仅显示一次**；请务必在此时记录。使用 `--json` 时，密钥仅出现在 `key` 字段中。通过**名称**引用。

```bash
agenteye keys list                                   # 活跃密钥优先，其次是已吊销的
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # 按需限定权限范围；仅打印一次密钥
agenteye keys create ops --permission-set standard --remove queries:run   # 以预设为基础，再裁剪
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # 轮换密钥（旧密钥立即失效）
agenteye keys disable ci-bot --yes                   # 吊销
```

权限计算方式为 `(permission-set ∪ --add) − --remove`。令牌格式为 `slug:action`（例如 `events:read`）或 `slug:action.action`（在同一资源上展开多个权限，如 `events:read.add` → `events:read`、`events:add`）。预设：`read-only`、`standard`、`admin`。仅限人类使用的权限（如 `keys:update`）不可授予密钥。

**`users`**：组织成员，通过**邮箱**引用（也接受 UUID 形式的 ID）。

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # 预测变更 + 确认
agenteye users disable dev@corp.com --yes            # 有保护账户/自身账户防护
agenteye users enable dev@corp.com
```

**`settings`**：固定注册表（只能读取和修改已有的键，不能创建新键）。

```bash
agenteye settings list                               # 键 · 值 · 类型 · 更新时间（机密值已遮蔽）
agenteye settings schema                             # 每个键的接受值说明（类型 · 范围 · 描述）
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**：告警定义，通过**名称**引用。`create` 接受一个位置参数 NAME 加标志，或通过 `--file` 提供完整的 JSON 请求体。

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME 为必填位置参数
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # 发送测试通知
agenteye alerts delete high-errors --yes
```

**`incidents`**：告警事件，通过 ID 引用（支持短 ID）。`show` 打印完整的活动日志；操作前请先阅读。

```bash
agenteye incidents list --state firing                # 也支持：acknowledged、resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # 被分配人必须是运营人员
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # 针对某告警手动开启事件
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### 分析与助手：`query` · `agent`

**`query`**：针对分析存储的保存 SQL 及临时查询运行器。保存的查询通过**名称**引用；SQL 在服务器端验证（仅支持 SELECT/WITH，有语句超时和行数上限）。

```bash
agenteye query schema [TABLE]                         # 分析视图的列结构
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # 运行保存的查询 + 位置参数 $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**：与内置 **AI 助手**对话（与仪表盘中的只读分析助手相同）。对话通过短 chat-id 引用（支持前缀解析）。

```bash
agenteye agent health                                 # AI 助手是否已配置/可访问
agenteye agent models                                 # 可传给 --model 的模型列表（默认模型已标记）
agenteye agent ask "which agents errored most in the last day?"    # 开启新对话；打印其短 ID
agenteye agent ask --chat <short-id> "and which tools did they call?"   # 继续该对话
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## 退出码

| 代码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 意外错误（例如仪表盘返回 5xx） |
| 2 | 用法错误（无效参数、未知命令/标志、名称冲突） |
| 3 | 无法访问仪表盘 |
| 4 | 未登录或会话已过期；请运行 `agenteye login` |
| 5 | 已认证，但账号缺少所需权限（错误信息中会指明具体权限） |
| 6 | 请求的资源不存在（例如未知的会话或事件 ID） |

这些退出码使 CLI 适合脚本化：编码 Agent 可以根据 `4` 提示你重新认证，或根据 `5` 显示缺少的权限。退出码处理模式和 JSON 输出结构请参见 [CLI recipes for agents](/zh/agenteye/cli-recipes)。
