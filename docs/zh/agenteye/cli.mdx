通过终端或脚本驱动所有 Failproof AI Observability 功能，无需来回切换仪表板。`agenteye` CLI 可查询你的数据（会话、事件日志、评估）并管理你的组织（API 密钥、用户、设置、告警、事件、已保存查询），适合自动化检查、将 Observability 接入 CI，或让编程智能体检查生产环境。每个命令都支持 `--json` 标志，无论是你在终端手动操作，还是编程智能体（Claude Code、Cursor）调用并解析结果，体验同样流畅。

一个二进制文件即可实现：

- **读取数据**：`sessions`、`events`、`evals`、`errors`（按时间、智能体、环境、分数过滤）。
- **管理组织**：`keys`、`users`、`settings`、`alerts`、`incidents`。
- **运行分析**：已保存的 SQL 和临时查询运行器（`query`）。
- **调用 AI 助手**：与仪表板中相同的只读分析师（`agent`）。

> **注意：** 这是 `agenteye` CLI，与采集器守护进程（`agenteye-collector`）是不同的工具。CLI 与你的仪表板通信；采集器负责将事件发送到服务器。

## 快速入门

从零开始，四行命令即可获得第一个结果。将 CLI 指向你的仪表板，登录，确认身份，然后拉取最近一天的运行记录：

```bash
pipx install agenteye
agenteye --base-url https://agenteye.example.com login --email you@example.com   # 邮件发送 6 位验证码
agenteye whoami                                                                  # 确认用户 + 当前组织
agenteye --json sessions --since 24h                                             # 每行一条智能体运行记录，最近 24 小时
```

最后一条命令会输出最近会话的 JSON 对象（默认最多 50 条，最新的排在最前面）。可以通过管道传给 `jq` 进行切片处理，或去掉 `--json` 获得带边框、彩色的表格视图。每行包含运行状态，以及评估器打分后的指标分数（此处为简略版）：

```json
{
  "sessions": [
    {
      "session_id": "run-8f2a",
      "agent_id": "checkout-bot",
      "environment": "prod",
      "status": "error",
      "scores": { "helpfulness": 0.42, "tool_efficiency": 0.55 },
      "event_count": 37,
      "started_at": "2026-07-16T09:14:02Z",
      "last_event_at": "2026-07-16T09:14:48Z"
    }
  ],
  "next_cursor": null
}
```

本页其余部分将逐一介绍各个部分：[安装](#installation)（隔离环境）、[登录](#authentication)、[配置](#configuration)、每个命令共用的[全局约定](#global-options--conventions)，以及[完整命令参考](#command-reference)。

## 安装

CLI 是一个公开发布在 PyPI 上的包，名为 **`agenteye`**。建议安装在独立环境中，以确保它始终拥有自己的依赖：

```bash
pipx install agenteye
# 或
uv tool install agenteye
```

需要 Python 3.10+。安装后的命令为 **`agenteye`**：

```bash
agenteye --version
agenteye --help
```

> **注意：** Failproof AI Observability Python SDK 也使用 `agenteye` 这个发行包名称。通过 `pipx` 或 `uv tool` 安装 CLI（而非 `pip install` 到共享虚拟环境）可避免两者冲突。仅当 SDK 未安装在同一环境中时，直接使用 `pip install agenteye` 才没有问题。

## 身份验证

CLI 通过邮件一次性验证码向**仪表板**进行认证：

```bash
agenteye login --email you@example.com
# 系统会向你发送 6 位验证码；在提示符处粘贴即可。
```

会话令牌存储在 `~/.agenteye/cli.json`（仅你本人可读，权限为 `0600`），默认有效期 24 小时。过期后，重新运行 `agenteye login` 即可。

```bash
agenteye whoami     # 显示当前用户、活跃组织及权限
agenteye logout     # 撤销会话并清除存储的令牌
```

`whoami` 在会话缺失或过期时不会报错，而是返回 `logged_in: false`，方便脚本或智能体安全地探测认证状态（如果未设置 base URL 或仪表板不可达，仍可能返回非零退出码）。

**要求：** 你的邮箱必须被允许登录仪表板（请联系你的 Failproof AI Observability 管理员），且仪表板必须可通过其 base URL 访问（参见[配置](#configuration)）。如果你请求了验证码但未收到，说明你的邮箱可能尚未开通仪表板访问权限。

## 选择组织（多租户）

如果你的账号属于多个组织，请在**登录时**选择活跃组织；该选择会被保存并用于后续所有命令：

```bash
agenteye login --org acme           # 认证并在一步中设置活跃租户
agenteye orgs list                  # 你可访问的组织（活跃组织已标记）
agenteye orgs switch globex         # 更改已保存的默认组织
agenteye --org globex sessions      # 仅对单条命令生效的覆盖设置
```

如果你只属于一个组织，系统会自动选择，无需关注 `--org`。如果你属于多个组织且未指定，CLI 会列出所有组织并提示你重新运行并加上 `--org <slug>`。活跃组织会随每次请求发送到仪表板，权限按**各组织**分别解析；`agenteye whoami` 会显示活跃组织、你在其中的权限以及你的所有成员资格。

## 配置

| 设置项 | 标志 | 环境变量 | 默认值 |
|---|---|---|---|
| 仪表板 base URL | `--base-url` | `AGENTEYE_DASHBOARD_URL` | **必填**（无默认值） |
| 活跃组织/租户 | `--org` | `AGENTEYE_ORG` | 登录时选择；保存在 `~/.agenteye/cli.json` |
| 会话令牌 | `--token` | `AGENTEYE_CLI_TOKEN` | 来自 `~/.agenteye/cli.json` |
| JSON 输出 | `--json` | `AGENTEYE_CLI_JSON` | 关闭 |
| 跳过 TLS 验证 | `--insecure` / `--secure` | `AGENTEYE_INSECURE` | 关闭（登录时保存） |
| 请求超时（秒） | `--timeout` | _（无）_ | 30 |
| 禁用使用遥测 | _（无）_ | `AGENTEYE_ANALYTICS_DISABLED`（或 `DO_NOT_TRACK`） | 遥测当前已禁用；不发送任何数据 |

解析优先级为**标志 → 环境变量 → 配置文件**。无默认值；你必须将 CLI 指向你的仪表板，可以每次命令单独指定（`--base-url https://agenteye.example.com`），也可以通过环境变量一次性设置（首次 `login` 后也会自动保存）：

```bash
export AGENTEYE_DASHBOARD_URL=https://agenteye.example.com
```

配置目录遵循 `AGENTEYE_HOME`（与 SDK 和采集器使用相同的约定）；如果已设置，`cli.json` 位于 `$AGENTEYE_HOME/cli.json`。

### 自签名或内部 TLS

如果你的仪表板使用自签名或内部证书通过 HTTPS 提供服务（例如原始负载均衡器主机名），TLS 验证会报 `CERTIFICATE_VERIFY_FAILED` 错误。使用 `--insecure` 跳过证书验证：

```bash
agenteye --base-url https://agenteye.internal --insecure login
```

`--insecure` **会在登录时保存到 `cli.json`**，因此后续命令会自动跳过验证，无需重复添加该标志。使用 `--secure` 可进行单次验证调用，或在下次登录时将验证重新保存为启用状态。CLI 在验证禁用期间，每次联系仪表板前都会向 stderr 输出警告。跳过验证会消除对中间人攻击的防护；在依赖此选项之前，请确保你信任到仪表板的网络路径（VPN、私有子网等）。

## 遥测与隐私

> **注意：** 当前发布的 CLI **不发送任何使用遥测数据。** 主开关处于关闭状态，无论你的环境如何配置，均不会传输任何数据。以下内容介绍的是退出遥测的能力，适用于未来遥测功能启用的情况。

即便启用，遥测也**仅限匿名使用分析**，绝不涉及你的智能体、会话或事件数据：

- **你的基础设施中的智能体、会话或事件数据永远不会离开。** 只会上报 CLI 使用情况：命令和子命令名称（例如 `keys create`）、你使用的标志**名称**（不含其值）、成功/退出状态、持续时间，以及变更操作的单次事件（例如 `api_key_created`、`query_run`，仅包含静态名称/枚举和粗略计数）。你的仪表板 URL、会话令牌、邮箱、组织 slug、资源 ID、SQL、密钥 secret 和查询过滤器**永远不会**被发送。操作者仅通过内部不透明 ID 标识，不会使用邮箱。
- **提前选择退出**：在 CLI 的环境中设置 `AGENTEYE_ANALYTICS_DISABLED=1`（CLI 也支持跨工具的 `DO_NOT_TRACK=1` 约定）。遥测一旦启用，该设置立即生效，注重隐私的环境可永久保持退出状态。
- 如果遥测启用，CLI 会直接发送到 PostHog（`https://us.i.posthog.com`）；封锁了该主机的机器将静默地不发送任何数据，CLI 本身不受影响。

## 全局选项与约定

请通读本节，适用于所有命令。

- **全局选项必须放在命令之前。** `agenteye --json sessions` 是正确的；`agenteye sessions --json` 是用法错误。全局选项包括 `--json`、`--base-url`、`--org`、`--token`、`--insecure`/`--secure`、`--timeout`、`--quiet` 和 `--no-color`。
- **`--json` 只向 stdout 输出纯 JSON，不输出其他内容。** 人类可读的状态行、警告和错误会输出到 **stderr**，因此即使显示了状态行，`--json` 的 stdout 内容也保持干净，可以直接通过管道传给 `jq`。不带 `--json` 时，将显示带边框、彩色的人性化视图。
- **使用 `--help` 探索功能。** 每个命令和子命令都有 `--help`（以及 `-h` 别名）：`agenteye -h`、`agenteye sessions -h`、`agenteye keys create -h`。顶层帮助还列出了退出码和全局选项。没有全局机器可读的接口汇总；请使用各命令的 `--help`，以及 `agenteye query schema` 和 `agenteye settings schema` 查看对应的注册表。
- **脚本和智能体下确认提示自动跳过。** 创建/更新/删除命令在交互式终端中会提示"确认吗？"，但**在 `--json` 模式下或 stdin 不是 TTY 时自动跳过该提示**（TTY 是交互式终端会话；管道或 CI 运行器不是），因此脚本和智能体不会挂起。使用 `--yes`/`-y` 可显式跳过。由于智能体中不会触发提示，智能体应在执行破坏性操作前先与人类确认。
- **分页：** 结果按最新优先并以游标分页方式返回（每页返回一个令牌用于获取下一页）。`--limit N`（别名 `-n`）限制行数，**默认为 50**；`--all` 自动分页（每次 200 行）**直到 `--limit`**，因此单独使用 `--all` 仍会在 50 条时停止。如需全量扫描，请指定较大的上限：`--all --limit 1000`。`--page-size N` 控制每次请求的块大小（最大 200）；`--cursor <id>` 从上一页的 `next_cursor` 继续。
- **时间过滤：** `--since` 接受相对时间窗口：`15m`、`1h`、`6h`、`24h`、`7d` 或 `all`（仪表板的预设值）。如需更长或自定义范围（例如最近 30 天），使用 `--from`/`--to`：显式的 ISO-8601 UTC 时间戳，**需包含 `T` 和时区**（例如 `2026-06-01T00:00:00Z`），会覆盖 `--since`。空格分隔或不含时区的值会报用法错误。
- **`--fields a,b,c`**（用于 `events`、`sessions`、`evals`、`errors`）将输出限制为指定字段，对表格和 `--json` 均生效。未知字段名会被拒绝并列出有效字段名，是发现字段名的便捷方式。
- **`--file payload.json`**（或 `--file -` 读取 stdin）在资源具有复杂结构时提供完整的 JSON 请求体（用于 `alerts create/update`、`settings set` 和 `users create/update`）。已保存查询的 SQL 使用 `--sql @file.sql` 代替。
- **多值过滤器**使用逗号分隔 → 作为集合匹配（同一过滤器内取并集，不同过滤器间取交集）：`--event-type tool_use,tool_result`。Click 选项不是可变参数，因此 `--add a b` 会报错。请使用 `--add a,b`、重复标志（`--add a --add b`）或加引号（`--add "a b"`）。

## 命令参考

### 最常用的 5 个命令

日常工作大多通过几个读取命令完成。从这里开始，按需再查阅下方的完整接口：

| 命令 | 功能 | 示例 |
|---|---|---|
| `sessions` | 每行一条智能体运行记录：时间、环境、智能体、状态、最新分数。 | `agenteye --json sessions --since 24h --status error` |
| `events` | 运行内部每一步的原始日志（加 `--full` 显示载荷）。 | `agenteye --json events --session-id run-001 --all` |
| `evals` | 评估结果和分数；`--aggregate` 汇总统计。 | `agenteye --json evals --aggregate --since 7d --env prod` |
| `errors` | 仅显示错误事件；`--aggregate` 按类型统计。 | `agenteye --json errors --since 24h --aggregate` |
| `list` | 发现有效的过滤器值（智能体、环境、模型等）。 | `agenteye list agents` |

### CLI 的完整功能

以下是完整接口说明。CLI 共有 **18 个顶级命令**。所有读取命令均支持 `--json` 和上述全局选项；运行 `agenteye <command> -h`（或 `<command> <subcommand> -h`）可查看任意命令的详尽标志列表和 JSON 结构。

### 身份认证：`login` · `logout` · `whoami` · `orgs` · `version` · `help`

```bash
agenteye login --email you@example.com [--org acme]   # 邮件一次性验证码；保存会话
agenteye logout                                       # 清除本机保存的会话
agenteye whoami                                       # 当前用户、活跃组织、权限
agenteye version                                      # 输出 CLI 版本（与 --version 相同）
agenteye help                                         # 顶层帮助（与 --help 相同）
```

`orgs` 用于查看和切换活跃租户：

```bash
agenteye orgs list        # 你的组织 + 你在各组织中的角色（活跃组织已标记）
agenteye orgs switch acme # 更改已保存的活跃组织（在 TTY 中省略 slug 可从列表中选择）
agenteye orgs current     # 活跃组织的身份信息
agenteye orgs perms       # 你在活跃组织中的权限，按资源分组
```

### 观测（只读）：`events` · `sessions` · `evals` · `errors` · `list`

这些命令均无需确认。共享过滤器：`--session-id`、`--agent-id`、`--env`（**非** `--environment`）以及时间范围（`--since` / `--from` / `--to`）。

```bash
# events（原始每步日志），最新优先
agenteye --json events --session-id run-001 --event-type tool_use,tool_result --all --limit 1000
agenteye --json events --since 1h --search timeout --all | jq '.events[].payload'

# sessions：每行一条智能体运行记录（时间/环境/智能体/会话/状态；不支持按分数过滤）
agenteye --json sessions --since 24h --status error
agenteye --json sessions --agent-id checkout-bot --env prod --all --limit 1000

# evals：评估结果 + 分数；--score 按指标过滤，--aggregate 汇总统计
agenteye --json evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3
agenteye --json evals --aggregate --since 7d --env prod        # 状态分布 + 各键分数统计

# errors：错误事件；--aggregate 统计数量/会话/智能体/最后出现时间
agenteye --json errors --since 24h --aggregate
agenteye --json errors --since 24h --error-type timeout --all --limit 1000

# list：过滤前先发现有效的过滤器值
agenteye list envs        # 同样支持：agents event_types score_filters models hooks tools error_types
```

`--score KEY:MIN..MAX`（用于 **`evals`**，不适用于 `sessions`）可重复使用并取 AND 组合；任一边界均可省略（`..0.5` 表示 ≤ 0.5，`0.9..` 表示 ≥ 0.9）。每次请求最多支持 20 个分数过滤器。`evals --scores-full` 是**仅用于人类表格**的显示标志；它会显示所有分数对，而非前几个加 `+N` 计数。在 `--json` 模式下无效，后者始终返回完整的分数对象。如需**端到端读取一个会话**，可将事件日志与其评估结合使用：

```bash
agenteye --json events --session-id run-001 --all --limit 1000 | jq '.events[] | {ts, event_type}'
agenteye --json evals  --session-id run-001                       # 其分数 + 状态
```

### 管理（权限限制）：`keys` · `users` · `settings` · `alerts` · `incidents`

**`keys`**：API 密钥。密钥在本地生成后发送到服务器（服务器仅存储哈希值），并**仅在创建/重新生成时显示一次**；请及时保存。使用 `--json` 时，密钥仅出现在 `key` 字段中。通过**名称**引用。

```bash
agenteye keys list                                   # 活跃密钥优先，然后是已撤销的
agenteye keys show ci-bot
agenteye keys create ci-bot --add events:read.add    # 按需设置权限范围；密钥仅打印一次
agenteye keys create ops --permission-set standard --remove queries:run   # 基于预设再调整
agenteye keys update ci-bot --add evaluations:read --yes
agenteye keys regenerate ci-bot --yes                # 轮换密钥（旧密钥立即失效）
agenteye keys disable ci-bot --yes                   # 撤销
```

权限计算方式为 `(permission-set ∪ --add) − --remove`。令牌格式为 `slug:action`（例如 `events:read`）或 `slug:action.action`（在一个资源上展开多个操作，例如 `events:read.add` → `events:read`、`events:add`）。预设：`read-only`、`standard`、`admin`。仅限人类使用的权限（`keys:update`）不能授予密钥。

**`users`**：组织成员，通过**邮箱**引用（也接受 UUID id）。

```bash
agenteye users list [--active-only]
agenteye users show dev@corp.com
agenteye users create dev@corp.com --permission-set standard
agenteye users update dev@corp.com --add alerts:write --remove queries:delete   # 预览 + 确认
agenteye users disable dev@corp.com --yes            # 有保护/自身限制
agenteye users enable dev@corp.com
```

**`settings`**：固定注册表（只能读取和修改已有键值；不能创建新键）。

```bash
agenteye settings list                               # 键 · 值 · 类型 · 更新时间（密钥已脱敏）
agenteye settings schema                             # 各键的接受值（类型 · 范围 · 描述）
agenteye settings set session_ttl_secs --value 86400 --yes
```

**`alerts`**：告警定义，通过**名称**引用。`create` 接受位置参数 NAME，以及标志或通过 `--file` 提供的完整 JSON 请求体。

```bash
agenteye alerts list
agenteye alerts show high-errors
agenteye alerts create high-errors --file alert.json          # NAME 为必填（位置参数）
agenteye alerts update high-errors --severity critical --yes
agenteye alerts test high-errors --yes                        # 发送测试通知
agenteye alerts delete high-errors --yes
```

**`incidents`**：告警事件，通过 ID 引用（支持短 ID）。`show` 会输出完整的活动日志；建议先查看再操作。

```bash
agenteye incidents list --state firing                # 也支持：acknowledged、resolved
agenteye incidents count
agenteye incidents show <id>
agenteye incidents ack <id>
agenteye incidents assign <id> you@corp.com           # 受让人必须是操作员
agenteye incidents resolve <id> --yes
agenteye incidents open --alert-id <id> --severity critical    # 针对某告警手动创建事件
agenteye incidents comment-add <id> "root cause: upstream 5xx"
agenteye incidents comment-list <id> ; agenteye incidents comment-delete <id> <comment-id>
agenteye incidents subscribe <id> ; agenteye incidents unsubscribe <id> ; agenteye incidents subscribers <id>
```

### 分析与助手：`query` · `agent`

**`query`**：针对分析存储运行已保存的 SQL 以及临时查询。已保存查询通过**名称**引用；SQL 在服务端进行验证（仅支持 SELECT/WITH，有语句超时和行数上限）。

```bash
agenteye query schema [TABLE]                         # 分析视图的列结构
agenteye query run --sql "select count(*) from analytics.events"
agenteye query run errs --arg prod --limit 100        # 运行已保存查询 + 位置参数 $1
agenteye query list ; agenteye query show errs
agenteye query create errs --sql @errs.sql --description "errored events (24h)"
agenteye query update errs --sql @errs.sql --yes ; agenteye query delete errs --yes
```

**`agent`**：与内置 **AI 助手**对话（与仪表板中相同的只读分析师）。对话通过短 chat-id（支持前缀解析）引用。

```bash
agenteye agent health                                 # AI 助手是否已配置/可访问
agenteye agent models                                 # 可传给 --model 的模型列表（默认模型已标记）
agenteye agent ask "which agents errored most in the last day?"    # 开始对话；输出短 chat-id
agenteye agent ask --chat <short-id> "and which tools did they call?"   # 继续该对话
agenteye agent chats ; agenteye agent show <short-id>
agenteye agent rename <short-id> --title "error triage" ; agenteye agent delete <short-id>
```

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 意外错误（例如仪表板返回 5xx） |
| 2 | 用法错误（无效参数、未知命令/标志、名称冲突） |
| 3 | 无法连接到仪表板 |
| 4 | 未登录或会话已过期；请运行 `agenteye login` |
| 5 | 已认证，但账号缺少所需权限（错误信息中会指明） |
| 6 | 请求的资源不存在（例如未知的会话或事件 ID） |

这些退出码使 CLI 便于脚本化：编程智能体可根据 `4` 提示你重新认证，或根据 `5` 显示缺失的权限。参见[面向智能体的 CLI 使用示例](/zh/agenteye/cli-recipes)，了解退出码处理模式和 JSON 输出结构。
