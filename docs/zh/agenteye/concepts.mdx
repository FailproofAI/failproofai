## 数据模型

**事件（Event）**
数据的最小单元。一个事件记录了 Agent 执行的单个步骤：`tool_use`、`model_request`、`hook_completed`、`error` 等。Agent 通过 [Python SDK](/zh/agenteye/python-sdk) 发出事件，这些事件会实时显示在 **Events** 页面上。

**会话（Session）**
一次 Agent 运行，由 `session_id` 标识。一个会话包含所有共享该 ID 的事件，汇总为 **Sessions** 页面上的一行，并在详情页中以执行图的形式呈现。会话通常以 `agent_start` 开始，以 `agent_end` 结束。

**Agent**
运行中的一个具名执行者，由 `agent_id` 标识。一次运行可以涉及多个 Agent：例如，一个规划器生成一个摘要子 Agent。子 Agent 携带 `parent_id`，Failproof AI 可观测性正是通过此字段在执行图中将其绘制在各自的泳道上。

**环境（Environment）**
标记运行发生的位置：`production`、`staging`、`dev`。在配置 SDK 时设置一次，几乎所有仪表板页面均可按环境筛选。

**上下文窗口占用率（Context-window fill）**
模型响应消耗的上下文窗口百分比。Failproof AI 可观测性会为已识别的模型在 `model_response` 事件上标记该值，使提示增长和即将发生的压缩在事件流中清晰可见。

## 质量

**评估（Evaluation）**
由你运行的评分服务为已完成的会话生成的质量分数。评估为可选功能：在接入评估器之前，会话只会被记录而不会被评分。每次评估可包含多个命名分数（例如 `helpfulness`、`factuality`、`tool_efficiency`），每个分数附带简短的推理说明。参见[评估套件](/zh/agenteye/evaluation-suite)。

**分数维度（Score key）**
评估器报告的某一维度名称，例如 `helpfulness`。告警规则和审计可以持续监控特定的分数维度。

**评估器（Evaluator）**
你的评分服务。Failproof AI 可观测性会将已完成运行的对话记录以 POST 请求发送给评估器，并存储其返回的分数。平台不内置默认评估器，评分逻辑由你自行定义。

## 发现与修复故障

**钩子（Hook）**
Agent 框架在某个步骤前后运行的守护机制或副作用处理器：内容安全检查、PII 脱敏、预算限制等。钩子会发出带有 `outcome`（allow、deny、modify）的 `hook_triggered` / `hook_completed` 事件，并拥有专属的观察页面。

**告警规则（Alert rule）**
当某项指标超过你设定的阈值时触发的规则，涵盖错误率、p95 延迟、Token 成本或评估器分数。规则触发时，将创建一个事故并通过你选择的渠道（邮件、Slack、Webhook、仪表板内通知）发送通知。参见[告警](/zh/agenteye/alerts)。

**事故（Incident）**
告警规则触发时创建的开放问题。事故具有完整的生命周期（确认、分配、解决），并附有记录每项操作的活动时间线。你也可以手动创建事故。

**审计（Audit）**
周期性调查（从每小时到每周不等），跨会话挖掘日志中尚未为其编写规则的故障模式：错误聚类、低分会话、延迟异常值、工具调用循环以及未正常结束的运行。如果说告警是在监控你已知的指标，那么审计则告诉你接下来应该关注什么。参见[审计](/zh/agenteye/audits)。

**发现（Finding）**
一次审计运行产生的经过排名、有据可查的结果。一条发现描述一种模式，链接到其背后的具体会话，并具有分级处理生命周期（确认、解决、静默、忽略）。Failproof AI 可观测性会在多次运行中对发现去重，使已知模式持续更新而不是不断累积。

**AI 助手（The AI assistant）**
仪表板内置的对话功能，基于你自己的数据，以自然语言回答关于 Agent 的问题。默认为只读模式；它创建的任何内容（已保存的查询、仪表板）均需经过审批，且永远无法执行删除操作。参见[AI 助手](/zh/agenteye/assistant)。

## 运行架构

**组织（Organization / 租户）**
独立的工作空间。一个 Failproof AI 可观测性实例可以托管多个组织，每个组织拥有各自的用户、密钥和数据。所有仪表板 URL 均以组织标识符为前缀（`/<org-slug>/…`）。

**采集器（Collector）**
`agenteye-collector`，运行在每台 Agent 机器上的轻量级守护进程，负责批量处理 SDK 写入磁盘的事件并将其发送至服务端。

**API 密钥（API key）**
用于客户端向服务端进行身份验证的作用域令牌。密钥携带细粒度权限（例如，采集器使用 `events:add`，仪表板密钥使用只读权限）。参见 [API 密钥](/zh/agenteye/api-keys)。

**服务端（Server）**
数据接收与 API 服务。负责接收事件、将运行状态存储在数据库中，并为仪表板和 CLI 提供服务。

**仪表板（Dashboard）**
Web 界面。每个页面均限定在某个组织范围内，并通过服务端 API 读取数据。
