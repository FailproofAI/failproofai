## 数据模型

**事件（Event）**
数据的最小单元。一个事件记录 Agent 执行的单个步骤：`tool_use`、`model_request`、`hook_completed`、`error` 等。Agent 通过 [Python SDK](/zh/agenteye/python-sdk) 发送事件，这些事件会实时显示在**事件（Events）**页面。

**会话（Session）**
一次 Agent 运行，由 `session_id` 标识。会话是共享同一 ID 的所有事件的集合，在**会话（Sessions）**页面汇总为一行，并在详情页以执行图的形式展示。会话通常以 `agent_start` 开始，以 `agent_end` 结束。

**Agent**
运行过程中具名的执行主体，由 `agent_id` 标识。一次运行可涉及多个 Agent：例如，一个规划器（planner）可以派生出一个摘要生成子 Agent。子 Agent 携带 `parent_id`，Failproof AI 可观测性正是通过这一字段在执行图中为它们绘制独立的泳道。

**环境（Environment）**
标识运行发生位置的标签：`production`、`staging`、`dev`。在配置 SDK 时设置一次即可。几乎所有仪表盘页面都支持按环境过滤。

**上下文窗口占用率（Context-window fill）**
某次响应所消耗的模型上下文窗口百分比。Failproof AI 可观测性会在其可识别的模型所产生的 `model_response` 事件上标注该值，从而使提示词增长趋势和即将触发的上下文压缩在事件流中一目了然。

## 质量

**评估（Evaluation）**
对已完成会话的质量评分，由您运行的评分服务生成。评估为可选功能：在接入评估器之前，会话只会被记录，不会被评分。每次评估可包含多个具名分数（例如 `helpfulness`、`factuality`、`tool_efficiency`），每项分数附有简短的推理说明。详见[评估套件](/zh/agenteye/evaluation-suite)。

**分数键（Score key）**
评估器上报的某一维度名称，例如 `helpfulness`。告警规则和审计可以随时间追踪特定的分数键。

**评估器（Evaluator）**
您的评分服务。Failproof AI 可观测性会将已完成运行的对话记录以 POST 方式发送至评估器，并存储其返回的分数。系统不内置默认评估器，评分逻辑由您自行实现。

## 发现与修复故障

**钩子（Hook）**
Agent 框架在某个步骤前后运行的防护措施或副作用处理：内容安全检查、PII 脱敏、预算控制等。钩子会发出 `hook_triggered` / `hook_completed` 事件，包含 `outcome`（allow、deny、modify），并在专属的观测页面中展示。

**告警规则（Alert rule）**
当某项指标超过您设定的阈值时触发的规则：错误率、p95 延迟、Token 成本或评估器分数。规则触发后，系统会创建一个事故（Incident）并通过您选择的渠道发送通知（邮件、Slack、Webhook、仪表盘内通知）。详见[告警](/zh/agenteye/alerts)。

**事故（Incident）**
告警规则触发时创建的待处理问题。事故具有完整的生命周期（确认、分配、解决）和记录所有操作的活动时间线。您也可以手动创建事故。

**审计（Audit）**
定期（每小时至每周）跨会话挖掘日志的调查任务，用于发现您尚未为之编写规则的故障模式：错误聚类、低分情况、延迟异常值、工具调用循环以及未正常结束的运行。告警关注的是您已知的指标，审计则告诉您接下来应该关注什么。详见[审计](/zh/agenteye/audits)。

**发现（Finding）**
审计运行产生的一条经过排序、有证据支撑的结果。一条发现会指明一种模式，链接到其背后的具体会话，并具备分类处理的生命周期（确认、解决、静默、忽略）。Failproof AI 可观测性会对多次运行产生的发现进行去重，使已知模式得到更新，而非不断堆积。

**AI 助手（The AI assistant）**
内置于仪表盘的对话式助手，以自然语言回答您关于 Agent 的问题，基于您自己的数据运行。默认为只读模式；其创建的任何内容（已保存的查询、仪表盘）均需经过审批，且永远无法执行删除操作。详见 [AI 助手](/zh/agenteye/assistant)。

## 部署运行

**组织（Organization，即租户）**
独立的工作空间。一个 Failproof AI 可观测性实例可承载多个组织，每个组织拥有独立的用户、密钥和数据。所有仪表盘 URL 均以您的组织 slug 作为路径前缀（`/<org-slug>/…`）。

**采集器（Collector）**
`agenteye-collector`，运行在每台 Agent 机器上的轻量级守护进程，负责批量处理 SDK 写入磁盘的事件，并将其发送到服务器。

**API 密钥（API key）**
用于向服务器验证客户端身份的作用域令牌。密钥具有细粒度的权限控制（例如，采集器使用 `events:add`，仪表盘密钥使用只读作用域）。详见 [API 密钥](/zh/agenteye/api-keys)。

**服务器（Server）**
数据接入与 API 服务。负责接收事件、将运营状态存储至数据库，并为仪表盘和 CLI 提供服务。

**仪表盘（Dashboard）**
Web UI。每个页面均隶属于某个组织，并通过服务器的 API 读取数据。
