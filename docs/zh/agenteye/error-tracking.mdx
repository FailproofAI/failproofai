## 所有故障，自动为你收集

当 Agent 出错时，你不应该还要去滚动实时事件流，祈祷在红色行消失之前赶紧看到它。**错误**页面替你完成收集工作。它将仪表板上所有标红的内容汇聚到一个统一的分诊界面，让你一眼看到的是什么在出错，而不是去哪里找。

它捕获的不仅仅是明显的错误。除了显式的 `error` 事件，Failproof AI Observability 还会浮现那些静默故障：任何 `tool_result`、`hook_completed` 或 `agent_end` 中携带失败信息的载荷都会出现在这里。工具返回了错误、或者 Hook 异常退出，不会再因为没有抛出响亮的异常就悄悄溜走。

页面顶部的直方图绘制了随时间变化的错误趋势。一眼就能判断这是持续的低频背景错误，还是几分钟前突然出现的峰值，让你立刻知道是否需要放下手头的事情去处理。

与所有观测界面一样，错误页面的作用域限定于你的组织，并支持按日期范围、环境、Agent 和会话进行筛选。这意味着你可以从整个集群的列表出发，迅速缩小到你真正关心的某个 Agent 或某个环境。

## 一个事件，而非上百条相同的行

一个依赖损坏可能在每分钟触发数百次相同的错误。不加处理的话，那就是一堵几乎一模一样的行组成的墙，把你真正需要看到的东西埋得严严实实。

Failproof AI Observability 会将同一会话、同一错误类型的重复故障折叠为单行。一次爆发呈现为一个事件。你数的是问题数量，而不是日志行数，真正重要的信号始终保持在顶部，而不是被自身的数量淹没。

## 从「有东西变红了」到确切事件

点击任意一行，直接进入该次运行的会话，定位到出错的确切事件。无需复制会话 ID，无需滚动去寻找出问题的那一刻：你直接到达现场，完整的执行图一览无余，让你看清 Agent 在出错前的每一步操作。

如果你拥有 `alerts:write` 权限，每行还有一个 **+ alert** 按钮。点击后，Observability 会打开一条新的告警规则，预填好用于捕获同类故障的条件。你刚刚分诊的事件，会成为下次第一时间通知你的规则，而不是让同样的问题再次打你一个措手不及。

**访问路径：** **错误**页面位于仪表板的观测区域，路径为 `/<org-slug>/errors`。
