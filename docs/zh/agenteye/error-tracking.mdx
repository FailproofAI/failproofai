## 所有故障，已为你自动汇集

当 Agent 出现故障时，你不应该还要盯着实时事件流滚动翻找，生怕红色行消失在屏幕之外。**错误**页面替你完成汇集工作。它将仪表板中所有标红的内容汇总到一个统一的分类处理界面，让你第一眼看到的是"什么正在出错"，而不是"去哪里找它"。

它捕获的不只是显而易见的错误。除了明确的 `error` 事件，Failproof AI Observability 还会将那些静默失败一并呈现：任何携带失败信息的 `tool_result`、`hook_completed` 或 `agent_end` 都会显示在此处。一个返回错误的工具，或一个异常退出的 hook，不会再因为没有抛出明显的异常而悄悄溜走。

页面顶部的直方图展示了错误随时间的分布情况。一眼就能判断这是持续的背景噪音，还是几分钟前突然出现的峰值，让你立刻决定是否需要放下手头的工作立即处理。

与所有观测界面一样，错误页面的数据范围限定在你的组织内，并支持按日期范围、环境、Agent 和会话进行筛选。这意味着你可以从整个集群的列表出发，快速缩小到你真正关心的某一个 Agent 或某一个环境。

## 一个事件，而非数百条重复行

单个依赖故障每分钟可能触发数百次相同的错误。原始状态下，这就是一堵几乎一模一样的日志墙，将你真正需要看到的信息完全淹没。

Failproof AI Observability 会将同一会话中相同错误类型的重复故障折叠为单行。一次集中爆发只呈现为一个事件。你数的是问题，而不是日志行，真正重要的信号始终置顶，不会被自身的数量所淹没。

## 从"有东西报红了"直达确切事件

点击任意一行，即可直接跳转到该次运行的会话内，并精准定位到发生故障的具体事件。无需复制会话 ID，无需滚动翻找出错时刻：你直接落在问题所在位置，完整的执行图一目了然，让你清晰看到 Agent 在出错前的所有操作。

如果你拥有 `alerts:write` 权限，每一行还会附带一个 **+ alert** 按钮。点击后，Observability 会打开一条新的告警规则，并自动填入用于捕获同类故障的配置。你刚刚处理过的事件，下次发生时就会主动通知你，而不是再次让你措手不及。

**访问路径：** **错误**页面位于仪表板的观测区域，路径为 `/<org-slug>/errors`。
