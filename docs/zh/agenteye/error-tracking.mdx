## 自动为您收集所有故障

当 Agent 出现故障时，您不必去滚动实时事件流，祈祷能在红色行消失之前捕捉到它们。**错误**页面会自动完成收集工作。它将仪表盘中所有会标红的内容汇聚到一个统一的分类界面，让您第一眼看到的是"什么在出错"，而不是"该去哪里找"。

它捕获的内容不止显而易见的那些。除了显式的 `error` 事件外，Failproof AI Observability 还会呈现那些静默失败：任何携带失败信息的 `tool_result`、`hook_completed` 或 `agent_end` 都会出现在这里。工具返回错误，或 Hook 异常退出，不再仅仅因为没有抛出明显的异常就悄悄溜走。

页面顶部的直方图展示错误随时间的分布。一眼便可判断这是持续的低频背景噪音，还是几分钟前突然出现的尖峰，从而立即决定是否需要放下手头工作。

与所有观测界面一样，错误页面以您的组织为范围，并支持按日期范围、环境、Agent 和会话进行筛选。这意味着您可以从全量列表出发，快速聚焦到您真正关心的某个 Agent 或某个环境。

## 一个事件，而非数百条相同记录

单个损坏的依赖项每分钟可能触发相同错误数百次。若原样展示，就是一堵几乎相同的日志行构成的墙，把您真正需要看到的内容完全淹没。

Failproof AI Observability 会将同一会话中相同错误类型的重复故障合并为一行。密集爆发呈现为单一事件。您统计的是问题数量，而非日志行数，真正重要的信号不会被自身的海量副本淹没，始终保持在首位。

## 从"某处出现红色告警"到精确事件

点击任意行，即可直接进入该次运行的会话，并定位到出错的精确事件。无需复制会话 ID，无需滚动查找出错时刻：您将直接到达现场，完整的执行图一览无余，让您清楚地看到 Agent 在出错前的行为轨迹。

如果您拥有 `alerts:write` 权限，每行还会带有一个 **+ alert** 按钮。点击后，Observability 将打开一条新的告警规则，并自动填入用于捕获相同故障的配置。您刚刚分类处理的事件，下次发生时将主动通知您，而不是再次打您一个措手不及。

**访问路径：** **错误**页面位于仪表盘的观测区域，路径为 `/<org-slug>/errors`。
