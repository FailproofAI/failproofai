Failproof AI Observability 可以自动对每次已完成的 Agent 运行进行质量评分：您只需提供一个小型评分服务，Observability 负责处理其余工作。您可以用它跟踪您关注的各个维度（帮助性、工具效率、事实准确性、安全性，由您自定义），及早发现回归问题，并一目了然地比较不同 Agent 或环境。评分功能为可选项：在服务器上设置 `EVALUATOR_ENDPOINT` 之前，该流水线不会执行任何操作。

> **注意：** 评分维度由您来定义。您的评估器可以返回任意数字类型的键；Observability 会存储、趋势分析并展示您返回的所有内容。

## 快速概览

1. **编写评分器。** 搭建一个小型 HTTP 服务，读取会话记录并返回评分。Observability 附带一个可直接使用的参考实现供您复制。请参阅[使用 SDK 编写评估器](#writing-an-evaluator-with-the-sdk)。
2. **将 Observability 指向该服务。** 在服务器进程上设置 `EVALUATOR_ENDPOINT`（以及共享的 `EVALUATOR_TOKEN`）。
3. **查看评分结果。** 每次完成的会话都会自动评分；结果将显示在会话详情页、会话列表网格以及已保存的看板中。

![会话详情视图，右侧边栏展示了评估摘要、按维度分类的评分条和推理文本](/agenteye/images/session-detail.png)

*配置评估器后，每次已完成的运行都会被评分，结果显示在会话的右侧边栏：顶部为摘要，下方为带有推理说明的各维度评分条。*

## 工作原理

```mermaid
flowchart LR
    ING["ingest /events<br/>agent_end"] --> SRV["Observability server"]
    SRV -->|"POST /evaluate"| EV["Evaluator service"]
    EV -->|"done or pending"| SRV
    SRV -->|"poll GET /evaluate/{job_id}"| EV
    EV -->|"done"| SRV
    SRV --> RES["evaluations<br/>terminal results"]
```

当 Observability SDK 为某个会话发出 `agent_end` 事件时，服务器会调度一次评估。然后它将完整的事件记录以 POST 请求发送给您的评估器服务，该服务可以：

- **内联返回结果**，格式为 `{"status":"done", "scores":{...}, "reasoning":{...}, "summary":"..."}`。结果将追加到会话的评估时间线中。`reasoning` 和 `summary` 为可选字段。
- **延迟处理**，格式为 `{"status":"pending", "job_id":"abc-123"}`。Observability 随后会调用 `GET {EVALUATOR_ENDPOINT}/evaluate/abc-123`，直到您的评估器返回 `{"status":"done", ...}` 或 `{"status":"error", "error":"..."}`。

  轮询频率基于单个任务：`pending` 响应中可包含 `next_poll_secs` 来覆盖默认值；否则 Observability 使用 `GET /config` 中的 `default_poll_interval_secs`；若该值也未设置，服务器则回退到 `EVALUATOR_POLLING_INTERVAL_SECS`（默认 10 秒）。所有值均限制在 [1s, 1h] 范围内。

从未发出 `agent_end` 的会话（例如，Agent 进程崩溃）也可以被处理：评估器的 `GET /config` 可以返回 `{"inactivity_timeout_secs": 1800}`，Observability 将对空闲时长超过该值的会话进行评估。将该字段设为 `null` 或省略它可禁用此回退机制。

当 `EVALUATOR_ENDPOINT` 未设置时，整个流水线完全不执行任何操作。

一个会话可以随时间**累积多次终止评估**：每个 `agent_end` 事件（以及从看板发起的每次手动重新评估）都会追加一条新的评估记录。这是评估已恢复对话的推荐方式：用户结束一个 Agent，稍后回来继续发送事件，再次结束 Agent，第二次评估将针对完整的更新后记录运行。看板将最近一次评估显示为主要结果，之前的评估则作为可折叠时间线展示。当某个会话的一次评估正在进行时，该会话后续的 `agent_end` 事件将被忽略；待当前评估完成后，下一个 `agent_end` 事件将按常规方式排入新的评估队列。

不活跃回退机制同样适用于已恢复的会话：如果在上一次终止评估之后有新事件到达，且会话随后空闲时长超过 `inactivity_timeout_secs`，则会排入一次新的评估。

瞬时故障（5xx、429、超时、网络错误）会以指数退避策略重试，最多重试 `EVALUATOR_MAX_ATTEMPTS` 次；4xx 响应为终止性错误。Observability 支持多个水平扩展的服务器实例并行运行；工作会进行分区，确保同一会话不会被同时分发两次。

## HTTP 协议规范

所有需要鉴权的路由均使用 **Bearer Token 认证**。两端必须配置相同的值：

- Observability 服务器：环境变量 `EVALUATOR_TOKEN`
- 评估器服务：以相同方式配置（`agenteye-evaluator` SDK 按惯例读取 `EVALUATOR_TOKEN`）

如果 `EVALUATOR_TOKEN` 未设置，服务器发送请求时不携带 `Authorization` 头；评估器可以接受匿名请求，这在纯内部网络中没有问题，但不建议在公网上使用。

### 评估器必须提供的路由

| 路由 | 请求体/参数 | 响应 |
|---|---|---|
| `GET /health` | 无 | `{"status":"ok"}`（公开，无需鉴权）|
| `GET /config` | 无 | `{"inactivity_timeout_secs": <int> \| null, "default_poll_interval_secs": <int> \| omitted}` |
| `POST /evaluate` | `EvalRequest` JSON | `{"status":"done", ...}` 或 `{"status":"pending", "job_id":"..."}` |
| `GET /evaluate/{id}` | 无 | 与 `/evaluate` 相同的响应结构 |

### 服务器发送的 `EvalRequest` 请求体

```json
{
  "schema_version": "1",
  "session_id":     "session-abc123",
  "agent_id":       "planner",
  "environment":    "production",
  "started_at":     "2026-05-10T12:00:00Z",
  "ended_at":       "2026-05-10T12:05:00Z",
  "events": [
    { "id": 1234, "ts": "...", "event_type": "agent_start", "payload": { ... } },
    ...
  ]
}
```

### 响应结构

**同步（done）：**

```json
{
  "status": "done",
  "scores": { "helpfulness": 0.85, "tool_efficiency": 0.6 },
  "reasoning": {
    "helpfulness": "answered the question directly with citations",
    "tool_efficiency": "called list_files three times when one would have done"
  },
  "summary": "strong answer quality, weak tool selection"
}
```

`reasoning`（每个评分的理由映射）和 `summary`（整体一段式叙述）均为可选字段。`reasoning` 中的键应与 `scores` 中的键对应；看板会在每个评分条下方内联渲染各条目。仅返回 `scores` 的旧版评估器仍可正常工作；`reasoning` 和 `summary` 将读取为 null，相应的 UI 元素将被省略。

**异步（deferred）：**

```json
{ "status": "pending", "job_id": "abc-123", "next_poll_secs": 30 }
```

`next_poll_secs` 为可选字段；若省略，服务器将回退到评估器 `/config` 中的 `default_poll_interval_secs`，然后再回退到其自身的 `EVALUATOR_POLLING_INTERVAL_SECS` 环境变量。

**评估器侧终止性错误：**

```json
{ "status": "error", "error": "model service unavailable" }
```

服务器将其他任何 2xx 响应体视为协议错误，并为该会话记录一个终止性 `error`。

## 使用 SDK 编写评估器

您无需手动实现 HTTP 协议。`agenteye-evaluator` Python 包提供了一个带类型的 FastAPI 封装，帮您处理鉴权、路由以及请求/响应结构。

Failproof AI Observability 还附带了一个**可直接运行的参考评估器**，它根据记录的结构对 `helpfulness`、`tool_efficiency` 和 `factuality` 进行评分。您可以将其作为起点，替换成自己的逻辑：LLM 评判、规则引擎，或任何符合您质量标准的方式。

最小可用评估器示例：

```python
import os
from agenteye_evaluator import Evaluator, EvalRequest, EvalResponse

app = Evaluator(token=os.environ["EVALUATOR_TOKEN"])

@app.evaluator
def run(req: EvalRequest) -> EvalResponse:
    # Inspect req.events (the full session transcript) and return scores.
    tool_calls = sum(1 for e in req.events if e.event_type == "tool_use")
    return EvalResponse(
        scores={"tool_calls": float(tool_calls)},
        reasoning={"tool_calls": f"{tool_calls} tool invocations in the transcript"},
        summary="tight tool loop" if tool_calls < 5 else "agent looped on tools",
    )
```

`app` 实例可在任何 ASGI 服务器下运行，使用 `uvicorn module:app` 即可启动。

对于需要延迟处理耗时任务的评估器，可返回 `JobPending` 并注册一个 `@app.job_lookup` 处理器；Observability 服务器会轮询 `GET /evaluate/{job_id}`，直到您返回终止状态或达到 `EVALUATOR_MAX_POLL_DURATION_SECS` 上限（默认 1 小时）。

完整的 API 参考、异步模式以及事件 schema 均已在 `agenteye-evaluator` SDK 的 README 中记录。

## 运行您的评估器

评估器是**您自己的服务**——Failproof AI Observability 不附带默认评估器，因此您需要在自己的服务环境中构建并运行它。它可在任何 ASGI 服务器下运行（例如 `uvicorn my_evaluator:app`）；按照 [HTTP 协议规范](#http-contract) 提供 `/health`、`/config` 和 `/evaluate` 路由，然后将服务器指向该地址（参见[配置服务器](#configuring-the-server)）。

评估器可访问后，`GET /health` 将返回 `{"status":"ok"}`。Agent 完整运行一次后，在服务器上调用 `GET /evaluations` 将返回一条 `status: "done"` 的记录，其中包含您的评估器生成的评分。

## 配置服务器

在服务器进程上设置以下环境变量：

| 环境变量 | 说明 |
|---|---|
| `EVALUATOR_ENDPOINT` | 评估器的基础 URL（如 `http://evaluator:9000`）。未设置则禁用流水线。|
| `EVALUATOR_TOKEN` | Bearer Token。必须与评估器服务配置的值完全一致。|
| `EVALUATOR_WORKERS` | 每个服务器实例的工作任务数（默认 2）。|
| `EVALUATOR_CLAIM_BATCH` | 每次工作器 tick 认领的行数（默认 4）。批次**并发**处理；评估器端点的有效并发数为 `EVALUATOR_WORKERS × EVALUATOR_CLAIM_BATCH`。|
| `EVALUATOR_POLL_IDLE_SECS` | 当没有待评估任务时，工作器在两次分发尝试之间的休眠时长（默认 2 秒）。|
| `EVALUATOR_POLLING_INTERVAL_SECS` | 当响应中的 `next_poll_secs` 和评估器的 `default_poll_interval_secs` 均未设置时，`GET /evaluate/{id}` 轮询频率的最终回退值（默认 10 秒）。|
| `EVALUATOR_REQUEST_TIMEOUT_MS` | 单次请求超时时间（默认 30000 毫秒）。|
| `EVALUATOR_MAX_ATTEMPTS` | 瞬时故障达到此次数后，结果将被记录为终止性 `error`（默认 5）。|
| `EVALUATOR_CONFIG_REFRESH_SECS` | `GET /config` 的刷新频率（默认 300 秒）。|
| `EVALUATOR_MAX_POLL_DURATION_SECS` | 会话在轮询队列中停留的最长时间，超时后将被标记为 `timeout`（默认 3600 秒）。防止评估器无限返回 `pending`。|

要开启自动评分，请在服务器上同时设置 `EVALUATOR_ENDPOINT` 和 `EVALUATOR_TOKEN`，然后重启服务器使配置生效。未设置 `EVALUATOR_ENDPOINT` 时，流水线保持无操作状态。

上述调优参数均为可选项；仅在需要覆盖默认值时，才在服务器上设置相应的环境变量。

## API 参考

| 方法 | 路径 | 所需权限 | 用途 |
|---|---|---|---|
| `GET` | `/evaluations` | `evaluations:read` | 查询终止性结果。支持 `session_id`、`agent_id`、`environment`、`status`（`done`/`error`/`timeout`）、`ts_from`、`ts_to`、`cursor`、`limit`、`score_filters`、`latest_per_session`。`limit` 默认为 50，上限为 200（注意：这与 `/events` 不同，后者上限为 1000）。`environment` 接受逗号分隔的列表（如 `environment=prod,staging`）；单个值仍然有效。使用 `latest_per_session=true` 时，响应中每个 `session_id` 最多包含一条记录（按 `completed_at` 取最新），用于会话列表页将会话的评估时间线折叠为当前主要结果。默认为 false（返回完整历史记录）。|
| `GET` | `/evaluations/aggregate` | `evaluations:read` | 对过滤后的数据集进行评估健康状况汇总：包括总数、done/error/timeout 分项统计、各评分键的统计数据（对任意 `scores` 键的 count/avg/min/max/p50）以及按时间分桶的时间线。接受与 `/evaluations` **相同的过滤参数**，另外还支持 `featured_keys`（要趋势分析的评分键，CSV 格式）和 `latest_per_session`。为看板功能提供支持；指标对整个匹配集合精确计算，不进行抽样。|
| `GET` | `/evaluations/environments` | `evaluations:read` | 从 `evaluations` 表中获取不重复的 environment 值。用于填充与评估数据范围相关的筛选下拉菜单。|
| `GET` | `/evaluation-jobs` | `evaluations:read` | 查看进行中的评估任务。支持按 `status`（`pending`/`polling`）过滤。|
| `GET` | `/events` | `events:read` | 流式获取会话的原始事件。支持 `session_id`、`agent_id`、`event_type`（CSV）、`environment`（CSV）、`ts_from`、`ts_to`、`cursor`、`limit` 和 `order`。`order` 为 `desc`（最新优先，默认）或 `asc`（最旧优先）；无法识别的值回退到 `desc`。通过响应中的 `next_cursor`（事件 id）进行游标分页：将其作为 `cursor` 参数传回以获取下一页；`asc` 模式下返回该 id 之后的事件，`desc` 模式下返回该 id 之前的事件。`limit` 默认为 50，上限为 1000。|
| `GET` | `/sessions/:session_id/export` | `events:read` | 返回评估器将接收到的该会话的精确 JSON 请求体，以可下载附件形式提供，文件名为 `session-<id>.json`。可用于将生产会话重放到 `agenteye-evaluator` 进行离线测试。字节内容与评估流水线实际发送的完全一致。|
| `POST` | `/sessions/:session_id/re-evaluate` | `evaluations:trigger` | 为会话排入一次新的评估；无论之前是否存在评估记录均可执行。新结果将**追加**到会话的评估时间线，而非覆盖之前的记录，因此历史评分仍然可见。成功排入返回 `202`，会话不存在返回 `404`，评估已在进行中返回 `409`。可在部署新评估器后使用，或用于未发出 `agent_end` 的会话。|

### 按评分范围过滤：`score_filters`

`GET /evaluations` 接受可选的 `score_filters` 参数，用于根据 `scores` 对象中的数值缩小结果范围。该参数为逗号分隔的 `key:min..max` 条目列表；两端均可省略。多个条目以逻辑 AND 方式组合。指定键不存在或非数值的记录将被排除。单次请求最多可包含 20 个过滤条目；超出则返回 HTTP 400。

示例：
```text
# helpfulness 在 [0.5, 0.8] 范围内
GET /evaluations?score_filters=helpfulness:0.5..0.8

# tool_efficiency 最大为 0.3（无下限）
GET /evaluations?score_filters=tool_efficiency:..0.3

# helpfulness >= 0.5 且 factuality >= 0.9
GET /evaluations?score_filters=helpfulness:0.5..,factuality:0.9..
```

每个 `/evaluations` 响应对象包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `evaluation_id` | string (UUID) | 该终止评估的规范标识符。每次终止评估都会生成一个新的 UUID；单个会话可包含多条评估记录。|
| `id` | string (UUID) | 向后兼容别名，与 `evaluation_id` 值相同。|
| `session_id` | string | 本次评估所针对的会话。一个会话在时间线中可有多条评估记录。|
| `agent_id` | string | 标识产生该会话的 Agent。|
| `environment` | string | 从会话复制的环境标签。|
| `status` | enum | `"done"`、`"error"`、`"timeout"` 之一。|
| `scores` | object \| null | 评估器返回的评分。|
| `reasoning` | object \| null | 评估器返回的可选每分推理映射。键通常与 `scores` 中的键对应。看板会在每个评分条下方渲染各条目。|
| `summary` | string \| null | 评估器返回的可选整体一段式叙述。看板将其渲染在各分项详情上方，作为评估的主要结论。|
| `error` | string \| null | 仅在 `"error"` / `"timeout"` 状态时填充。|
| `attempt_count` | integer | 分发尝试次数（≥ 1）。|
| `duration_ms` | integer \| null | 最后一次尝试的耗时。|
| `completed_at` | string (ISO 8601 UTC) | 终止结果被记录的时间。结果按 `completed_at` 排序（最新优先）。|
| `created_at` | string (ISO 8601 UTC) | 与 `completed_at` 时间戳相同（一次性写入语义）。|

## 查看结果

- **`/sessions/<id>`**：事件时间线 + 右侧边栏，展示会话的评分以及分发尝试中的任何错误。如果您的密钥具有 `evaluations:trigger` 权限，导出按钮旁边会显示**重新评估**按钮，可用于未发出 `agent_end` 的会话，或在部署新评估器后刷新评分。看板会轮询新结果，并在结果返回时更新右侧边栏。
- **`/sessions`**：可过滤的会话列表网格；评分列一目了然地显示每个会话的评估状态和评分。
- **`/dashboards`**：已保存的评估健康视图（参见下方[看板](#dashboards)）。

## 看板

**看板**页面（`/dashboards`）允许您将一组评估过滤条件保存为命名的可复用视图，并一目了然地监控该评估切片的状况。看板在**整个组织内共享**；所有拥有 `dashboards:read` 权限的成员都能看到相同的看板集合。

每个看板固定以下配置：

- **过滤条件**：与会话页面相同的控件：环境、状态、Agent、滚动时间窗口以及评分范围过滤器（`key:min..max`）。
- **显示配置**：要突出显示的评分键、绿/黄/红健康阈值、要展示的面板，以及是否折叠为每个会话的最新评估。

## 故障排查

**会话已存在但未创建任何评估。** 请确认服务器进程上已设置 `EVALUATOR_ENDPOINT`，服务器和评估器配置了相同的 `EVALUATOR_TOKEN` 值，以及评估器的 `/health` 端点可从服务器访问。未设置 `EVALUATOR_ENDPOINT` 时，流水线为无操作状态。

**进行中的评估任务积压。** 查询 `GET /evaluation-jobs` 查看进行中的队列。检查每行的 `attempt_count`、`next_attempt_at` 和 `last_error`。常见原因：评估器服务不可达或返回 5xx（按退避策略重试）、`EVALUATOR_TOKEN` 错误（401 为终止性错误），或异步评估器无限返回 `pending`（见下文）。

**会话已完成但无终止评估。** 查询 `GET /evaluation-jobs?status=polling`；任务可能仍在进行中。如果任务卡在 `pending` 状态，说明服务器无法访问评估器；请检查评估器是否正常运行以及 `EVALUATOR_TOKEN` 是否匹配。

**`HTTP 401 from evaluator: invalid bearer token`。** 服务器上的 `EVALUATOR_TOKEN` 与评估器服务配置的值不匹配。两者必须完全一致。

**异步评估器无限返回 `pending`。** 服务器会轮询 `GET /evaluate/{job_id}`，直到评估器返回 `done` 或 `error`，或达到 `EVALUATOR_MAX_POLL_DURATION_SECS` 上限（默认 1 小时）。超出上限后，评估将被记录为 `timeout` 并从进行中队列中移除。如果您的评估器确实需要超过默认时限，请提高 `EVALUATOR_MAX_POLL_DURATION_SECS` 的值。
