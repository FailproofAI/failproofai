质量问题会主动找上你，而不是等用户投诉你才知道。只需接入一次你自己的评分服务，Failproof AI Observability 就会自动对每个已完成的运行进行评分，一旦帮助性下降或幻觉激增，问题就会自动浮现，在用户感知之前。

![会话列表中的评分列：每次运行都带有评估状态标签，以及颜色编码的帮助性、真实性和工具效率徽章](/agenteye/images/sessions-list.png)

*会话列表中的每次运行都附带评分；红色、琥珀色和绿色徽章让低分运行一眼就能看出来，无需打开任何记录。*

## 告别手动抽查

过去你只能抽查少数几次运行，然后祈祷其余的都没问题。现在，每次完成的会话一结束就会立即按你关注的维度进行评分：帮助性、工具效率、真实性、安全性，以及你的质量标准涉及的任何方面。你定义评分键，Failproof AI Observability 负责存储、趋势分析和展示评估器返回的所有结果。没有任何运行会漏掉评分，你也不会再通过支持工单才发现指标回退。

评分会显示在 **`/<org-slug>/sessions`**（侧栏 → *观察* → *会话*）的会话列表中，每行一组徽章。只想查看不达标的运行？按评分范围筛选列表，例如帮助性低于 0.5，精准拉出值得细读的运行。查看评分需要 `evaluations:read` 权限。

## 了解运行低分的原因

数字告诉你某次运行表现不佳，会话页面则告诉你原因。打开任意一次运行，右侧面板会先展示摘要，再为每个维度显示一个进度条，并附上评估器对该维度的推理说明，让你能在几秒内从"真实性评分 0.4"直接定位到具体出错的断言。

![会话的右侧面板：顶部为评估摘要，下方是各维度评分条及推理说明，旁边是完整的事件时间线](/agenteye/images/session-detail.png)

*会话详情视图：摘要、各维度评分条及每项评分背后的推理说明，紧邻运行的事件时间线。*

部署了更精准的评估器，或者查看一次因崩溃未能完成评分的运行？**重新评估**按钮（需要 `evaluations:trigger` 权限）会就地对会话重新评分，并将最新结果追加到时间线，早期评分作为历史记录保留可见。入口位于 **`/<org-slug>/sessions/<session-id>`**。

## 监控整体质量趋势

单次运行评分偏低只是噪音，整个批次持续滑落才是信号。保存的仪表板将你的评分转化为可随时查看的趋势：按 Agent、按环境，对比本周与上周的平均帮助性。

![质量仪表板：各评估维度的平均分柱状图及随时间变化的趋势](/agenteye/images/dashboard-quality.png)

*保存的质量仪表板对你关注的评分键进行趋势追踪，让缓慢的指标漂移在演变为事故之前就显而易见。*

仪表板位于 **`/<org-slug>/dashboards`**（侧栏 → *分析* → *仪表板*），在整个组织内共享，每个卡片汇总匹配的会话数据：会话数量、各展示评分的平均值，以及趋势迷你图。点击"在会话中打开"可直接跳转到任意数据背后经过预筛选的运行列表。查看需要 `dashboards:read` 和 `evaluations:read` 权限。

## 一次接入评估器

评分功能为可选项，在你将 Failproof AI Observability 指向评分器之前完全不会启用。你只需搭建一个小型 HTTP 服务（Observability 提供一个可直接复制的参考实现），在服务器上设置两个值，此后每次运行都会自动评分。完整的配置说明、评分契约和 SDK 请参阅详细指南。

不确定该从哪些维度开始评分？[评估器 Agent 技能](/zh/agenteye/evaluator-skill)可以让你的编程 Agent 根据你自己的会话数据确定评分维度，然后构建并部署服务。
