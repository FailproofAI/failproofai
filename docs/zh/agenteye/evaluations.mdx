质量问题会主动找上你，而不是等用户投诉时你才知道。只需接入一次你自己的评分服务，Failproof AI Observability 就会自动对每次完成的运行进行评分，让帮助性下降或幻觉激增等问题在用户察觉之前就自动浮出水面。

![Sessions 网格带有评分列：每次运行显示评估状态标签，以及颜色编码的帮助性、事实性和工具效率徽章](/agenteye/images/sessions-list.png)

*Sessions 网格中的每次运行都附带评分；红色、橙色和绿色徽章让你无需打开任何对话记录就能一眼识别出表现较弱的运行。*

## 告别手动抽样检查

以前你只能抽查几次运行，寄希望于其余的没问题。现在，每个完成的会话一结束就会被立即评分，维度由你决定：帮助性、工具效率、事实性、安全性，或者任何你关注的质量标准。你定义评分维度，Failproof AI Observability 负责存储、趋势分析和展示评估器返回的所有数据。没有任何运行会漏评，你也不必再从支持工单中得知回归问题。

评分会显示在 **`/<org-slug>/sessions`**（侧边栏 → *observe* → *sessions*）的 Sessions 网格中，每行一组徽章。只想查看表现不佳的运行？按评分范围筛选网格，例如帮助性低于 0.5，精准定位到值得深入阅读的运行。查看评分需要 `evaluations:read` 权限。

## 了解运行低分原因

数字告诉你某次运行表现较弱，会话页面告诉你原因。打开任意一次运行，右侧边栏最上方显示摘要总结，然后按维度展示进度条，每条下方附有评估器自身的推理说明，让你从"事实性得分 0.4"迅速定位到具体出错的断言。

![会话右侧边栏：顶部是评估摘要，然后是带推理说明的各维度评分条，旁边是完整的事件时间线](/agenteye/images/session-detail.png)

*会话详情视图：摘要、各维度评分条及每个评分背后的推理，紧邻运行的事件时间线。*

上线了更精准的评估器，或者某次运行在评分前崩溃了？**重新评估**按钮（需要 `evaluations:trigger` 权限）可就地对该会话重新评分，并将最新结果追加到其时间线中，早期评分作为历史记录保留可见。该功能位于 **`/<org-slug>/sessions/<session-id>`**。

## 监控全局质量趋势

单次运行低分只是噪声，整批运行持续下滑才是信号。保存的仪表板将你的评分转化为可一目了然的趋势：本周与上周的平均帮助性对比，按 Agent、按环境细分。

![质量仪表板：各评估维度的平均评分柱状图，以及随时间变化的趋势](/agenteye/images/dashboard-quality.png)

*保存的质量仪表板对你关注的评分维度进行趋势分析，让缓慢的漂移在演变为事故之前就显而易见。*

仪表板位于 **`/<org-slug>/dashboards`**（侧边栏 → *analyze* → *dashboards*），在整个组织内共享。每张卡片汇总匹配的会话数据：运行次数、各维度平均评分，以及趋势迷你图。点击"在 Sessions 中打开"可直接跳转至任意数字背后经过预筛选的运行列表。查看需要 `dashboards:read` 加 `evaluations:read` 权限。

## 一次性接入评估器

评分功能默认关闭，直到你为 Failproof AI Observability 指定一个评分器后才会启用。你只需搭建一个小型 HTTP 服务（Observability 提供可直接复制的参考实现），在服务器上配置两个值，之后每次运行都会自动为你评分。完整的操作指南、评分契约和 SDK 详见深度指南。

不确定该评估哪些维度？[评估器 Agent 技能](/zh/agenteye/evaluator-skill)可让你的编程 Agent 基于你自己的会话数据确定评分维度，然后构建并部署该服务。
