Agent 的每一个动作，你都能即时看到。事件流是你对生产环境中每个 Agent 的实时脉搏：无需等待，无需 grep 日志，无需猜测刚才发生了什么。

*来自组织中每个 Agent 的所有事件，最新在前，实时更新。*

## 对每个 Agent 的实时脉搏

当 Agent 开始一次运行、调用模型、触发工具、执行 hook 或遇到错误时，对应的行会在事件发生的瞬间出现在流的顶部。它会持续追踪你组织中每个 Agent 的每一个事件，最新在前，让你始终掌握当前状态，而不是过时的信息。

这意味着无需在某台机器上 tail 日志文件，无需跨机器 grep，无需手动拼凑时间戳。打开一个页面，你已经在观察生产环境了。

每行按类型进行颜色编码，让你一眼就能读懂数据流，而不必逐行解析。每行一目了然地展示：

- **类型**，带颜色编码：`agent_start`、`model_response`、`tool_use`、`hook_completed`、`error` 等。
- **一行摘要**，描述发生了什么，大多数情况下无需展开即可了解大意。
- **该步骤的 token 计数**。
- **上下文窗口占用徽章**（适用时），让你在 prompt 增长和即将到来的压缩造成问题之前就能察觉。

实时观察意味着你能在糟糕的部署、失控的循环或错误爆发发生时立即发现，而不是在明天的日志审查中才知道。

## 找到那一个重要的运行

当某些事情看起来不对劲时，你不需要信息洪流，你需要的是那一个出问题的运行。数据流可以快速过滤：按环境、按 Agent、按会话、按事件类型，或按自由文本。

通过会话 id 或 Agent id 进行过滤，以跟踪某次运行从第一个事件到最后一个事件的全过程。通过事件类型过滤，可以隔离某一类活动，例如在一个视图中查看组织内的所有 `error`。叠加过滤条件，只需几次点击就能从"所有地方的所有内容"缩小到"这个 Agent，在生产环境中，正在报错"，然后针对发现的问题采取行动。

自由文本搜索可以直接定位到你手头已有的消息、工具名称或 id，让客户反馈在几秒内转化为精确的运行记录。

## 在哪里找到它

事件流是你组织的主页。登录后，它是你首先看到的界面，位于 `/<org-slug>/`，让你一到达就能立即开始分类排查。

在其背后，你的 Agent 通过 SDK 发出事件，收集器将其传送到你的 Failproof AI 可观测性服务器，数据流在你控制的基础设施中随着事件到达而实时追踪。当你想要汇总视图而非原始记录时，每次运行的事件会在"会话"页面中折叠为单行，一键即可访问。

这是所有其他可观测性界面的原始数据来源，因此当其他地方的数字看起来有误时，来事件流这里确认实际发生了什么。
