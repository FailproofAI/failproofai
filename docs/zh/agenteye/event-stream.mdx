智能体一旦有所动作，你立刻就能看到。事件流是你监控生产环境中每个智能体的实时脉搏：无需等待，无需翻查日志，无需猜测刚刚发生了什么。

![实时事件流：按颜色区分的事件行实时滚动，可按环境、智能体、会话、事件类型及自由文本筛选](/agenteye/images/events-stream.png)

*来自组织内所有智能体的每一个事件，最新的排在最前，实时更新。*

## 监控每个智能体的实时脉搏

当智能体启动运行、调用模型、触发工具、执行 hook 或遇到错误时，对应行会在事件发生的瞬间出现在流的顶部。它持续追踪组织内所有智能体的每一个事件，最新的排在最前，让你始终掌握最新动态而非过时信息。

这意味着无需在某台机器上追踪日志文件，无需跨机器 grep，无需手动拼接时间戳。打开一个页面，你就已经在监控生产环境了。

行按类型以颜色区分，让你一眼就能读懂事件流，而无需逐行解析。每一行一目了然地展示：

- **类型**，以颜色区分：`agent_start`、`model_response`、`tool_use`、`hook_completed`、`error` 等。
- **单行摘要**，描述发生了什么，让你通常无需展开就能了解大意。
- **该步骤的 token 用量**。
- **上下文窗口占用标签**（在适用的地方），让提示词增长和即将发生的压缩在造成影响前就清晰可见。

实时监控意味着你能在问题发生时就发现——无论是糟糕的部署、失控的循环还是大量报错——而非等到明天的日志审查时才知道。

## 快速定位那一次关键运行

当有异常时，你不需要全量数据，你只需要那一次出问题的运行。事件流可以快速筛选：按环境、按智能体、按会话、按事件类型或按自由文本。

通过 session id 或 agent id 筛选，可以从第一个事件到最后一个事件完整追踪某一次运行。通过事件类型筛选，可以隔离某类活动，例如在一个视图中查看整个组织内的所有 `error`。叠加多个筛选条件，几次点击就能从"所有环境、所有内容"缩小到"这个智能体、在 prod 环境、正在报错"，然后立即采取行动。

自由文本搜索可以直接定位到某条消息、某个工具名称或你手头已有的某个 id，让一份客户反馈在几秒内对应到具体的运行记录。

## 在哪里找到它

事件流是你的组织主页。登录后它是你进入的第一个界面，位于 `/<org-slug>/`，让分析处理在你到达的那一刻就开始。

在其背后，你的智能体通过 SDK 发出事件，采集器将它们发送到你的 Failproof AI 可观测性服务器，事件流则在事件到达时对其进行追踪——整个基础设施由你掌控。当你想要查看汇总视图而非原始记录时，每次运行的事件会在「会话」中折叠为单行，一键即达。

这是所有其他可观测性界面所依赖的原始真相来源，因此当其他地方的数据看起来不对时，事件流就是你确认实际发生了什么的地方。
