你的 Agent 一有动作，你立刻看见。事件流是你对生产环境中每个 Agent 的实时脉搏：无需等待，无需 grep 日志，无需猜测刚才发生了什么。

![实时事件流：按颜色区分类型的事件行实时滚动，可按环境、Agent、会话、事件类型和自由文本筛选](/agenteye/images/events-stream.png)

*来自组织中每个 Agent 的所有事件，最新的排在最前，实时更新。*

## 对每个 Agent 的实时脉搏

当 Agent 启动一次运行、调用模型、触发工具、执行 hook 或遇到错误时，对应的行会在事件发生的瞬间出现在流的顶部。它实时追踪组织中每个 Agent 的所有事件，最新的排在最前，让你始终掌握当前状态，而不是过时信息。

这意味着你无需在某台服务器上追踪日志文件，无需跨机器 grep，无需手动拼凑时间戳。打开一个页面，你已经在观察生产环境。

各行按类型用颜色区分，让你一眼就能读懂流内容，而不必逐行解析。每行一目了然地展示：

- **类型**，颜色区分：`agent_start`、`model_response`、`tool_use`、`hook_completed`、`error` 等。
- **一行摘要**，描述发生了什么，让你几乎不需要点开详情就能了解大意。
- **该步骤的 Token 用量**。
- **上下文窗口占用徽章**（适用时），让提示词增长和即将触发的压缩在造成影响之前就变得可见。

实时观察意味着你能在问题发生时就发现糟糕的部署、失控的循环或突发的错误，而不是等到明天的日志审查。

## 找到那一次关键运行

当某些情况看起来不对劲时，你不需要看所有信息，你需要的是那一次出问题的运行。事件流可以快速筛选：按环境、按 Agent、按会话、按事件类型，或按自由文本。

按会话 id 或 Agent id 筛选，从第一个事件到最后一个事件追踪某次运行的完整过程。按事件类型筛选，隔离某一类活动，例如在一个视图中查看整个组织的所有 `error`。叠加筛选条件，几次点击就能从"所有环境的一切"缩小到"这个 Agent，在生产环境，正在报错"，然后直接处理你找到的问题。

自由文本搜索可以直接定位到一条消息、一个工具名称或你手头已有的某个 id，让一份客户反馈在几秒内转化为精确的运行记录。

## 在哪里找到它

事件流是你的组织主页。登录后它是你看到的第一个界面，位于 `/<org-slug>/`，让你一到就可以开始排查问题。

在它背后，你的 Agent 通过 SDK 发送事件，收集器将它们传送到你的 Failproof AI Observability 服务器，事件流在它们到达时实时追踪——整套基础设施由你掌控。如果你想看汇总视图而不是原始记录，每次运行的事件会在 Sessions 中折叠为单独一行，一次点击即可查看。

这是所有其他观测界面赖以构建的原始事实来源，所以当其他地方的数字看起来有误时，事件流就是你确认实际发生了什么的地方。
