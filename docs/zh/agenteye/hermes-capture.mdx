[Hermes](https://hermes-agent.nousresearch.com) 可以在你的团队日常使用的任意平台上为他们提供服务——Slack、Telegram、CLI、计划任务。Hermes 会话捕获功能将所有这些内容以普通会话和事件的形式引入 AgentEye，让团队每天交互的助手与你自己编写的 Agent 一样具备可观测性。

一个轻量级后台采集器会在 Hermes 写入本地会话存储时即时读取，并将会话推送至 AgentEye。其工作方式与 [Codex](/zh/agenteye/codex-capture) 和 [OpenClaw](/zh/agenteye/openclaw-capture) 的捕获机制相同，单个采集器可同时捕获多个来源。

---

## 捕获内容

机器上所有 Hermes 会话均会被捕获，无论来自哪个渠道。每个会话都会成为 AgentEye 中的一个 [session](/zh/agenteye/sessions)；其中的用户消息、助手消息、工具调用及工具结果都会对应转换为 [events](/zh/agenteye/event-stream)。

会话的发起渠道——Slack、Telegram、CLI 或计划任务——会被记录在会话上，便于区分和按渠道筛选。同时还会记录该会话使用的模型、发起会话的聊天频道和用户，以及（当某个会话由另一个会话派生时）指向其父会话的链接。

会话在 Hermes 启动时即刻出现，无需等待任何消息发送；每一轮对话的回复及其工具调用均按实际发生顺序排列。会话结束后，还会记录结束原因、消耗的费用及使用的 Token 数量。

## 开启方式

捕获功能默认关闭，需手动启用。请使用具有 `events:add` 权限的 API Key 安装采集器（参见 [API keys](/zh/agenteye/api-keys)），并开启 Hermes 捕获：

```bash
curl -fsSL https://raw.githubusercontent.com/FailproofAI/agenteye-collector/main/install.sh \
  | sh -s -- --key <YOUR_API_KEY> --hermes-enabled
```

该命令会安装采集器、将其注册为后台服务并开始捕获。确认运行状态：

```bash
agenteye-collector health
```

需要在同一台机器上捕获多个 Agent？在同一条命令中添加各自的标志即可，例如 `--hermes-enabled --codex-enabled`。

首次运行时，已有的 Hermes 会话会进行一次性回填，此后的新活动将在数秒内实时推送。采集器只读取 Hermes 的原始数据，从不修改或删除，且每条消息只推送一次，重启后亦然。

`health` 命令还会告知采集器捕获的内容是否全部成功到达 AgentEye。若某批数据无法投递，系统会保留并重试，而非丢弃；只要还有数据未到达，健康检查就会报告不健康——因此"健康"意味着数据已成功到达，而不仅仅是进程在运行。

## 数据去向

捕获的会话显示在 **Sessions** 中，其事件显示在 **Events** 流中，与其他任何被观测的 Agent 完全相同——因此 [session replay](/zh/agenteye/sessions)、[search](/zh/agenteye/queries)、[evaluations](/zh/agenteye/evaluations) 和 [alerts](/zh/agenteye/alerts) 均可正常使用。通过筛选 Hermes Agent 可单独查看这些内容。

---

## 隐私说明

Hermes 会话包含完整的对话记录——包括命令输出、文件内容以及 Agent 读写的任何内容——并可能包含敏感信息。捕获的会话会原样推送，因此请仅在将这些内容集中存储至 AgentEye 合规的场景下启用捕获功能，并为采集器分配仅限 `events:add` 权限的 Key。数据隔离方式详见 [Security](/zh/agenteye/security)。
