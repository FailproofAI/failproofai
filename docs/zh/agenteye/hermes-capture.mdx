[Hermes](https://hermes-agent.nousresearch.com) 可在您的团队已有的任何工作场景中响应请求——Slack、Telegram、CLI、计划任务。Hermes 会话捕获功能将这一切以普通会话和事件的形式引入 AgentEye，让您每天与之交互的助手与您自己编写的 Agent 一样具备可观测性。

一个轻量级的后台采集器会在 Hermes 写入本地会话存储时实时读取，并将会话推送至 AgentEye。其工作方式与 [Codex](/zh/agenteye/codex-capture) 和 [OpenClaw](/zh/agenteye/openclaw-capture) 的捕获方式相同，一个采集器可同时捕获多个来源。

---

## 捕获内容

机器上的每一个 Hermes 会话都会被捕获，无论来自哪个渠道。每个会话会成为 AgentEye 的一个[会话](/zh/agenteye/sessions)；其中的用户消息、助手消息、工具调用及工具结果将对应转换为[事件](/zh/agenteye/event-stream)。

会话的发起渠道——Slack、Telegram、CLI 或计划任务——会记录在会话上，便于区分和按渠道筛选。同时还会记录会话所使用的模型、发起会话的聊天对象及用户，以及当某个会话由另一个会话派生时，指向其父会话的关联链接。

会话在 Hermes 启动时即刻出现，无需等待任何消息发送，每轮对话的回复与工具调用也会按实际发生顺序排列。会话结束时，您还能获取结束原因、消耗费用及 token 用量。

## 开启方式

捕获功能默认关闭，需手动启用。使用具有 `events:add` 权限的 API 密钥（参见 [API 密钥](/zh/agenteye/api-keys)）安装采集器，并开启 Hermes 捕获：

```bash
curl -fsSL https://raw.githubusercontent.com/FailproofAI/agenteye-collector/main/install.sh \
  | sh -s -- --key <YOUR_API_KEY> --hermes-enabled
```

该命令会安装采集器、将其注册为后台服务并开始捕获。确认运行状态：

```bash
agenteye-collector health
```

需要在同一台机器上捕获多个 Agent？在同一命令中添加各自的标志即可——例如 `--hermes-enabled --codex-enabled`。

首次运行时，现有的 Hermes 会话会进行一次历史补全，之后的新活动将在数秒内实时推送。Hermes 的原始数据只会被读取，不会被修改或删除；每条消息只会推送一次，即使重启后也不会重复。

`health` 命令还会告知采集器捕获的内容是否全部成功到达 AgentEye。若某批数据未能送达，系统会保留并重试，而非丢弃；在任何数据仍处于待发送状态时，检查结果将显示为不健康——因此"健康"意味着您的数据已成功到达，而不仅仅是进程在运行。

## 查看位置

捕获的会话出现在 **Sessions** 中，其事件出现在 **Events** 流中，与您观测的任何其他 Agent 完全一致——因此[会话回放](/zh/agenteye/sessions)、[搜索](/zh/agenteye/queries)、[评估](/zh/agenteye/evaluations)和[告警](/zh/agenteye/alerts)均可使用。按 Hermes Agent 筛选即可单独查看。

---

## 隐私说明

Hermes 会话包含完整的对话记录——包括命令输出、文件内容以及 Agent 读取或写入的任何内容——并可能包含敏感信息。捕获的会话会原样推送，因此请仅在将这些内容集中存储于 AgentEye 合规合适的场景下启用捕获，并为采集器配置仅限 `events:add` 权限的密钥。数据隔离机制详见[安全说明](/zh/agenteye/security)。
