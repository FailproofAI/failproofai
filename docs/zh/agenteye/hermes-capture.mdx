[Hermes](https://hermes-agent.nousresearch.com) 在你的团队已经习惯使用的任何地方为他们提供支持——Slack、Telegram、CLI、定时任务。Hermes 会话捕获将所有这些内容以普通会话和事件的形式引入 AgentEye，让你的团队每天交互的助手与你自己编写的 Agent 一样可观测。

一个小型后台采集器会实时读取 Hermes 在本地写入的会话存储，并将会话传送至 AgentEye。其工作方式与 [Codex](/zh/agenteye/codex-capture) 和 [OpenClaw](/zh/agenteye/openclaw-capture) 捕获相同，一个采集器可以同时捕获多个来源。

---

## 捕获内容

机器上的每个 Hermes 会话都会被捕获，无论来自哪个渠道。每个会话都会成为 AgentEye 中的一个[会话](/zh/agenteye/sessions)；其用户消息、助手消息、工具调用及工具结果将成为对应的[事件](/zh/agenteye/event-stream)。

会话的来源渠道——Slack、Telegram、CLI 或定时任务——会被记录在会话上，方便你区分和按渠道筛选。同时记录的还有该会话使用的模型、发起会话的聊天窗口和用户，以及当一个会话派生出子会话时，指向其父会话的链接。

会话一旦被 Hermes 启动就会立即出现，无论是否已有任何消息。一轮对话的回复和工具调用会按实际发生的顺序保留。当会话结束时，你还能看到会话结束的原因、消耗的费用以及使用的 token 数量。

## 如何启用

捕获功能默认关闭，需手动启用。使用具有 `events:add` 权限的 API 密钥安装采集器（参见 [API 密钥](/zh/agenteye/api-keys)），并开启 Hermes 捕获：

```bash
curl -fsSL https://raw.githubusercontent.com/FailproofAI/agenteye-collector/main/install.sh \
  | sh -s -- --key <YOUR_API_KEY> --hermes-enabled
```

该命令会安装采集器、将其注册为后台服务，并开始捕获。确认服务正在运行：

```bash
agenteye-collector health
```

需要在同一台机器上捕获多个 Agent？在同一命令中添加各自的标志，例如 `--hermes-enabled --codex-enabled`。

首次运行时，现有的 Hermes 会话会被一次性回填，此后新的活动将在数秒内实时推送。Hermes 自身的数据只会被读取，不会被修改或删除；即使采集器重启，每条消息也只会被发送一次。

`health` 命令还会告诉你采集器捕获的内容是否确实到达了 AgentEye。如果某批数据无法送达，它会被保留并重试，而不是丢弃；只要还有未发送的数据，健康检查就会报告为不健康——因此"健康"意味着你的数据已成功到达，而不仅仅是进程在运行。

## 数据展示位置

捕获的会话会出现在 **Sessions** 中，其事件出现在 **Events** 流中，与任何其他被观测的 Agent 完全一致——因此[会话回放](/zh/agenteye/sessions)、[搜索](/zh/agenteye/queries)、[评估](/zh/agenteye/evaluations)和[告警](/zh/agenteye/alerts)均可对其使用。按 Hermes Agent 筛选即可单独查看。

---

## 隐私说明

Hermes 会话包含完整的对话记录——包括命令输出、文件内容以及 Agent 读取或写入的任何内容——可能含有敏感信息。捕获的会话会原样发送，因此请仅在将此类内容集中存入 AgentEye 合适的场景下启用捕获，并为采集器提供仅限 `events:add` 权限的密钥。有关数据隔离方式，请参阅[安全性](/zh/agenteye/security)。
