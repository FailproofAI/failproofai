OpenTelemetry 允许你使用标准 OTLP/HTTP 协议将代理追踪、日志和指标发送到 FailproofAI Cloud。这是可选功能。你现有的 FailproofAI 集成无需启用它即可继续正常工作。

## 为你的组织开启数据摄取

组织管理员打开 **Settings → OpenTelemetry** 并启用数据摄取。使用具有 `events:add` 权限的 Cloud API 密钥，该权限与代理报告所用权限相同。

如果数据摄取已关闭，Cloud 将拒绝 OTLP 导出，因此 `failproofai otel enable` 不会生效，你的代理仍会以常规方式发送会话。运行 `failproofai otel status` 检查组织开关状态，并请管理员将其开启。

## 连接编码代理

通过 `failproofai config` 连接你的机器，然后选择一个代理：

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

该设置命令支持 Claude Code、Codex 和 Copilot，并根据情况选择 Cloud 或本地已认证中继。Copilot 自动使用本地中继。使用中继前，请先启动已配置的 FailproofAI 守护进程。

如果 FailproofAI 已在发送某个代理的会话记录，设置命令会询问是否将该代理切换到 OTEL。默认选项为"否"。确认后将停止该代理的记录上传，但不会影响策略执行或其他代理的报告。

## 连接应用程序

在应用程序的 OpenTelemetry 工具配置中使用以下环境变量：

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

端点是 Cloud 的 OTLP 基础地址 `https://app.befailproof.ai/otel`，你的导出器会自动追加 `/v1/traces`、`/v1/logs` 或 `/v1/metrics`。信号级变量（如 `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`）按原样使用，因此需要提供完整路径，例如 `https://app.befailproof.ai/otel/v1/logs`。

将 `<key>` 替换为你的 API 密钥。请勿将密钥泄露至 Shell 历史记录、屏幕录制或已提交的配置文件中。对于已配置的机器，`failproofai otel env --service my-agent` 会打印包含现有密钥的配置块。其输出内容包含凭据。

Cloud 接受 traces、logs 和 metrics 的 OTLP/HTTP 导出，支持 protobuf 或 JSON 格式，包括 gzip 压缩请求。不支持 OTLP/gRPC。

指标仅为导出器兼容性而确认接收，不会被存储或显示。受支持的代理追踪和编码代理日志将转换为会话；代理未导出的字段将保持缺失状态。

## 捕获提示词文本

<Warning>
文本捕获可能包含提示词、工具参数及其他敏感内容。`failproofai otel enable` 会开启此功能。添加 `--no-content` 可关闭提示词和工具详情的捕获。
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

对于手动配置的代理，请使用其自身的内容捕获控制选项：

<Tabs>
  <Tab title="Claude Code">
    在代理环境中，将以下变量与上方的应用程序配置块一并添加：

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    将两个内容变量均设为 `0` 可避免捕获提示词和工具详情。
  </Tab>
  <Tab title="Codex">
    在 Codex 的用户配置中，使用其 OTEL 设置：

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex 的对话内容保存在日志中；内部运行时追踪和指标保持禁用状态。Codex 使用你提供的完整端点地址。将 `log_user_prompt` 设为 `false` 可排除提示词；设置命令会保留显式的 `false` 配置。
  </Tab>
  <Tab title="Gemini CLI">
    配合本地中继使用 Gemini 的遥测设置：

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    `failproofai otel enable` 不支持 Gemini CLI。请使用你自己的已认证收集器手动配置。将 `logPrompts` 设为 `false` 可关闭提示词捕获。
  </Tab>
  <Tab title="Copilot in VS Code">
    使用以下 VS Code 用户设置：

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    运行 `failproofai otel enable copilot` 启用已认证中继。将 `captureContent` 设为 `false` 可省略内容捕获。
  </Tab>
</Tabs>

## 检查或撤销配置

```bash
failproofai otel status
failproofai otel disable all
```

Status 命令会区分由 FailproofAI 管理的设置与你在其他地方配置的遥测。Disable 命令会恢复之前的托管设置以及代理之前的记录上传选项。
