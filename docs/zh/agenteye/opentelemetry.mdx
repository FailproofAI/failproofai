OpenTelemetry 允许你使用标准 OTLP/HTTP 协议将代理追踪、日志和指标发送到 FailproofAI Cloud。此功能为可选项，不启用也不会影响现有 FailproofAI 集成的正常运行。

## 为组织开启数据接入

组织管理员进入 **Settings → OpenTelemetry**，开启数据接入。使用具有 `events:add` 权限的 Cloud API 密钥，该权限与代理上报所用权限相同。

如果数据接入未开启，Cloud 将拒绝 OTLP 导出，`failproofai otel enable` 将不起任何作用，代理仍会通过原有方式发送会话。运行 `failproofai otel status` 检查组织开关状态，并联系管理员开启。

## 连接编码代理

通过 `failproofai config` 完成本机配置后，选择对应代理：

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

该设置命令支持 Claude Code、Codex 和 Copilot，并会根据情况自动选择 Cloud 直连或本地认证中继。Copilot 默认使用本地中继。使用中继前，请先启动已配置的 FailproofAI 守护进程。

如果 FailproofAI 已在发送某个代理的会话记录，设置过程中会询问是否将该代理切换至 OTEL，默认选项为否。确认切换后，该代理的记录上传将停止；策略执行及其他代理的上报不受影响。

## 连接应用程序

在应用程序的 OpenTelemetry 埋点中配置以下环境变量：

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

端点为 Cloud 的 OTLP 基础路径 `https://app.befailproof.ai/otel`，导出器会自动追加 `/v1/traces`、`/v1/logs` 或 `/v1/metrics`。如使用 `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` 等按信号类型设置的变量，则需提供完整路径，例如 `https://app.befailproof.ai/otel/v1/logs`。

将 `<key>` 替换为你的 API 密钥。请勿将密钥保存在 shell 历史记录、屏幕录制或已提交的配置文件中。对于已完成配置的机器，`failproofai otel env --service my-agent` 会输出包含现有密钥的完整配置块，其输出内容包含凭证信息。

Cloud 支持以 protobuf 或 JSON 格式（包括 gzip 压缩请求）导出追踪、日志和指标的 OTLP/HTTP，不支持 OTLP/gRPC。

指标数据仅作导出器兼容性确认，不会被存储或展示。受支持的代理追踪和编码代理日志将转换为会话；代理未导出的字段将保持缺失状态。

## 捕获提示词内容

<Warning>
内容捕获可能包含提示词、工具参数及其他敏感内容。`failproofai otel enable` 会默认开启此功能。添加 `--no-content` 可关闭提示词和工具详情的捕获。
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

如需手动配置代理，请使用其自身的内容捕获控制项：

<Tabs>
  <Tab title="Claude Code">
    在代理环境中，将以下变量与上方应用程序配置块一同添加：

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    将两个内容变量均设为 `0` 可避免捕获提示词和工具详情。
  </Tab>
  <Tab title="Codex">
    在 Codex 的用户配置中，使用其 OTEL 设置：

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex 的对话内容记录在日志中；内部运行时追踪和指标应保持禁用。Codex 使用你提供的完整端点路径。将 `log_user_prompt` 设为 `false` 可排除提示词；设置命令会保留明确设置的 `false` 值。
  </Tab>
  <Tab title="Gemini CLI">
    通过本地中继使用 Gemini 的遥测设置：

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI 不支持 `failproofai otel enable`，请使用你自己的认证收集器手动配置。将 `logPrompts` 设为 `false` 可关闭提示词捕获。
  </Tab>
  <Tab title="VS Code 中的 Copilot">
    使用以下 VS Code 用户设置：

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    运行 `failproofai otel enable copilot` 启用认证中继。将 `captureContent` 设为 `false` 可省略内容捕获。
  </Tab>
</Tabs>

## 检查或撤销设置

中继会在网络或服务器临时故障期间保留遥测数据，并在恢复后自动重试。对于永久性 `400` 拒绝（包括因数据过大无法存储的情况），需要修正 payload 后重新发送。中继会保留被拒绝的批次以供检查，而不会反复重试。

收到 `401` 或 `403` 后，请替换为具有同一组织 `events:add` 权限的有效密钥。重新连接不会自动重发因凭证问题被拒绝的 OTLP 导出数据；请联系运维人员恢复这些批次，并保持其在原组织内。

```bash
failproofai otel status
failproofai otel disable all
```

Status 命令会区分由 FailproofAI 管理的设置与其他地方配置的遥测。Disable 命令会恢复之前的托管设置以及代理之前的记录上传选项。
