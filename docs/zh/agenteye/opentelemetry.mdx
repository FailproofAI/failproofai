OpenTelemetry 允许你使用标准 OTLP/HTTP 协议将智能体 traces、日志和指标发送至 FailproofAI Cloud。此功能为可选项，不启用也不会影响现有 FailproofAI 集成的正常运行。

## 为你的组织开启数据接收

组织管理员进入 **Settings → OpenTelemetry**，开启数据接收功能。请使用具有 `events:add` 权限的 Cloud API 密钥，该权限与智能体报告所用权限相同。

若数据接收未开启，Cloud 将拒绝 OTLP 导出，`failproofai otel enable` 命令不会生效，你的智能体将继续以常规方式发送会话数据。运行 `failproofai otel status` 可查看组织级开关状态，如需开启请联系管理员。

## 连接编码智能体

通过 `failproofai config` 完成本机配置后，选择对应的智能体：

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

该安装命令支持 Claude Code、Codex 和 Copilot，并会自动选择 Cloud 直连或本地已认证中继。Copilot 默认使用本地中继。使用中继前请先启动已配置的 FailproofAI 守护进程。

若 FailproofAI 已在发送某个智能体的会话记录，安装命令会询问是否将该智能体切换至 OTEL 模式，默认选项为"否"。确认切换后，该智能体的记录上传将停止；不影响其他智能体的策略执行和报告。

## 连接应用程序

在应用程序的 OpenTelemetry 埋点配置中，设置以下环境变量：

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

端点为 Cloud 的 OTLP 基础路径 `https://app.befailproof.ai/otel`，exporter 会自动在其后追加 `/v1/traces`、`/v1/logs` 或 `/v1/metrics`。对于 `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` 等按信号类型设置的变量，将直接使用原始值，因此需要提供完整路径，例如 `https://app.befailproof.ai/otel/v1/logs`。

将 `<key>` 替换为你的 API 密钥。请勿将密钥保存在 shell 历史记录、屏幕录制或已提交的配置文件中。对于已完成配置的机器，可运行 `failproofai otel env --service my-agent` 打印包含现有密钥的完整配置块。该命令的输出内容包含凭据，请妥善保管。

Cloud 接受 traces、日志和指标的 OTLP/HTTP 导出，支持 protobuf 或 JSON 格式，包括 gzip 压缩请求。不支持 OTLP/gRPC。

指标会被确认接收以保证 exporter 兼容性，但不会被存储或展示。受支持的智能体 traces 和编码智能体日志将转换为会话；智能体未导出的字段将保持缺失状态。

## 捕获提示词文本

<Warning>
文本捕获可能包含提示词、工具参数及其他敏感内容。`failproofai otel enable` 会默认开启此功能。如需关闭提示词和工具详情捕获，请添加 `--no-content` 参数。
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

若智能体为手动配置，请使用其自身的内容捕获控制项：

<Tabs>
  <Tab title="Claude Code">
    在智能体环境变量中，将以下变量与上述应用程序配置块一起添加：

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    将两个内容变量均设为 `0` 可避免捕获提示词和工具详情。
  </Tab>
  <Tab title="Codex">
    在 Codex 的用户配置中，使用其 OTEL 设置：

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex 对话内容记录在日志中；内部运行时 traces 和指标保持禁用状态。Codex 使用你提供的完整端点路径。将 `log_user_prompt` 设为 `false` 可不捕获提示词；安装命令会保留显式设置的 `false` 值。
  </Tab>
  <Tab title="Gemini CLI">
    通过本地中继使用 Gemini 的遥测设置：

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    Gemini CLI 不支持 `failproofai otel enable`，请使用你自己的已认证收集器手动配置。将 `logPrompts` 设为 `false` 可不捕获提示词。
  </Tab>
  <Tab title="VS Code 中的 Copilot">
    在 VS Code 用户设置中进行如下配置：

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    运行 `failproofai otel enable copilot` 以启用已认证中继。将 `captureContent` 设为 `false` 可不捕获内容。
  </Tab>
</Tabs>

## 检查或撤销配置

中继在遭遇临时网络故障或服务器故障时会保留遥测数据，并在恢复后自动重试。对于永久性 `400` 错误（包括数据量过大无法存储的情况），需要修正 payload 后重新发送。中继会保留被拒绝的批次以供检查，而不会反复重试发送。

收到 `401` 或 `403` 后，请替换为具有同一组织 `events:add` 权限的有效密钥。重新连接不会自动重发因凭据问题被拒绝的 OTLP 导出数据；如需恢复这些批次，请联系你的运维人员。请将其保留在原所属组织中。

```bash
failproofai otel status
failproofai otel disable all
```

`status` 命令会区分由 FailproofAI 管理的设置与你在其他地方配置的遥测。`disable` 命令会恢复之前的托管设置以及智能体之前的记录上传选项。
