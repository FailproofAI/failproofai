OpenTelemetry 允许你使用标准 OTLP/HTTP 协议将代理追踪、日志和指标发送到 FailproofAI Cloud。此功能为可选项，不启用也不会影响现有的 FailproofAI 集成。

## 获取密钥

每个组织的 OTLP 摄取功能始终开启，无需额外启用。使用具有 `events:add` 权限的 Cloud API 密钥即可，该权限与代理上报所用权限相同。

在控制台中，**首页 → 初始配置** 有一个 **通过 OpenTelemetry 连接** 卡片：点击 **创建 Collector 密钥** 可生成一个 `events:add` 密钥，系统会显示该密钥一次并附带导出器变量，同时显示连接状态。你也可以在 **设置 → API 密钥** 下，选择 **新建密钥** 时选择 **仅发送日志** 来创建密钥。

## 连接编码代理

使用 `failproofai config` 完成本机配置后，选择要连接的代理：

```bash
failproofai otel enable claude
failproofai otel enable codex
failproofai otel enable copilot
```

该设置命令支持 Claude Code、Codex 和 Copilot，并会根据情况自动选择 Cloud 或本地认证中继。Copilot 会自动使用本地中继。使用中继前，请先启动已配置的 FailproofAI 守护进程。

如果 FailproofAI 已在上传某个代理的会话记录，设置过程中会询问是否将该代理切换至 OTEL，默认选项为否。确认切换后，该代理将停止上传会话记录，但不会影响策略执行或其他代理的上报。

## 连接应用程序

在应用程序的 OpenTelemetry 埋点中使用以下环境变量：

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://app.befailproof.ai/otel
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Bearer%20<key>'
export OTEL_SERVICE_NAME=my-agent
```

该端点是 Cloud 的 OTLP 基础路径 `https://app.befailproof.ai/otel`，导出器会自动在末尾追加 `/v1/traces`、`/v1/logs` 或 `/v1/metrics`。如使用 `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` 等按信号类型设置的变量，则需提供完整路径，例如 `https://app.befailproof.ai/otel/v1/logs`。

将 `<key>` 替换为你的 API 密钥。请勿将密钥保存在 Shell 历史记录、屏幕录制或已提交的配置文件中。对于已完成配置的本机，可运行 `failproofai otel env --service my-agent` 打印包含现有密钥的完整配置块。该命令的输出包含凭据，请妥善保管。

Cloud 接受 traces、logs 和 metrics 的 OTLP/HTTP 导出，支持 protobuf 或 JSON 格式，包括 gzip 压缩请求，但不支持 OTLP/gRPC。

指标数据仅作应答（用于兼容导出器），不会被存储或展示。受支持的代理追踪和编码代理日志将转换为会话；代理未导出的字段将保持缺失状态。

## 捕获提示词文本

<Warning>
文本捕获可能包含提示词、工具参数及其他敏感内容。`failproofai otel enable` 会默认开启此功能。添加 `--no-content` 可关闭提示词和工具详情的捕获。
</Warning>

```bash
failproofai otel enable claude --no-content
failproofai otel enable codex --no-content
```

对于手动配置的代理，请使用其自身的内容捕获控制项：

<Tabs>
  <Tab title="Claude Code">
    在代理的环境变量中，将以下变量与上方的应用程序配置块一并添加：

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_METRICS_EXPORTER=otlp
    export OTEL_LOG_USER_PROMPTS=1
    export OTEL_LOG_TOOL_DETAILS=1
    ```

    将两个内容变量均设置为 `0` 可避免捕获提示词和工具详情。
  </Tab>
  <Tab title="Codex">
    在 Codex 的用户配置中，使用其 OTEL 设置：

    ```toml
    [otel]
    log_user_prompt = true
    exporter = { otlp-http = { endpoint = "https://app.befailproof.ai/otel/v1/logs", protocol = "json", headers = { Authorization = "Bearer <key>" } } }
    ```

    Codex 的会话内容记录在日志中；内部运行时追踪和指标应保持禁用。Codex 使用你提供的完整端点路径。将 `log_user_prompt` 设置为 `false` 可不捕获提示词；设置命令会保留显式设置的 `false` 值。
  </Tab>
  <Tab title="Gemini CLI">
    通过本地中继使用 Gemini 的遥测设置：

    ```json
    {
      "telemetry": {
        "enabled": true,
        "target": "local",
        "otlpEndpoint": "http://127.0.0.1:4318",
        "otlpProtocol": "http",
        "useCollector": true,
        "logPrompts": true
      }
    }
    ```

    `failproofai otel enable` 不支持 Gemini CLI，请使用自己的认证 Collector 手动进行配置。将 `logPrompts` 设置为 `false` 可不捕获提示词。
  </Tab>
  <Tab title="Copilot in VS Code">
    在 VS Code 用户设置中添加以下配置：

    ```json
    {
      "github.copilot.chat.otel.enabled": true,
      "github.copilot.chat.otel.exporterType": "otlp-http",
      "github.copilot.chat.otel.otlpEndpoint": "http://127.0.0.1:4318",
      "github.copilot.chat.otel.captureContent": true
    }
    ```

    运行 `failproofai otel enable copilot` 以启用认证中继。将 `captureContent` 设置为 `false` 可不捕获内容。
  </Tab>
</Tabs>

## 检查或撤销设置

中继会在网络或服务器出现临时故障时保留遥测数据，并在恢复后自动重试。如收到永久性 `400` 拒绝（包括因事件过大无法存储的情况），需修正请求负载。中继会保留被拒绝的批次以供排查，而不会反复重发。

收到 `401` 或 `403` 后，请将凭据替换为同一组织下具有 `events:add` 权限的密钥。重新连接不会自动重发因凭据被拒的 OTLP 导出数据；如需恢复这些批次，请联系你的运维人员，并确保其保留在原所属组织中。

```bash
failproofai otel status
failproofai otel disable all
```

`status` 命令会区分由 FailproofAI 管理的设置与你在其他地方配置的遥测。`disable` 命令会恢复之前的托管设置以及代理之前的会话记录上传选择。
