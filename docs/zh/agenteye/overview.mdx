Failproof AI Observability 是一个自托管平台，用于在生产环境中观测、评估和改进您的 AI agent。它记录 agent 的一切行为（每次工具调用、模型请求、hook 和错误），对每次运行的质量进行评分，并在您自己基础设施内运行的仪表板中呈现那些您未曾预料到的故障。

如果您在交付 AI agent，并且厌倦了猜测某次运行为何出错，那么本页就是您的起点。它将介绍 Failproof AI Observability 能为您提供什么，以及各个组成部分如何协同工作——在您安装任何内容之前。

## 为什么团队选择它

- **查看 agent 的实际行为。** 每次运行都会生成一个可读的 git 风格执行图：哪些工具并行运行、哪些子 agent 分叉、在哪里停滞，以及消耗了多少资源。
- **自动捕获质量回退。** 接入一个小型评分服务后，Failproof AI Observability 会对每次完成的运行打分，一旦有用性下降或幻觉激增，问题会自动浮现。
- **发现您未曾定义规则的故障。** 定期审计会跨会话挖掘日志，寻找错误集群、延迟异常值、低分和卡死运行，并将有据可查的排名发现呈现给您。
- **在关键时刻收到告警。** 阈值规则在错误率、延迟、成本或评估分数触发时创建事件，您可以确认、分配和解决这些事件。
- **用自然语言提问。** 仪表板内置 AI 助手，可以用自然语言回答"本周生产环境的质量趋势如何？"等问题，数据来自您自己的系统。它做出的任何更改都需要审批。
- **数据归您掌控。** Failproof AI Observability 是自托管的：事件、提示词和分析数据均保留在您控制的基础设施中。

## 您将获得什么

Failproof AI Observability 围绕三个理念组织（**观测**、**分析**和**管理**），在仪表板左侧边栏中有对应体现。

**观测**（发生了什么的原始真相）：

- **[事件流](/zh/agenteye/event-stream)**：每次运行的实时逐步记录（工具调用、模型调用、hook、错误）。
- **[会话](/zh/agenteye/sessions)**：将事件汇总为每次运行一行，每行均可打分，并附有 git 风格的执行图。
- **[性能指标](/zh/agenteye/telemetry)**：按维度划分的延迟热图，以及模型、工具和 hook 的 p50/p95/p99 关键指标，让尾部延迟峰值从中位数中凸显出来。
- **[错误追踪](/zh/agenteye/error-tracking)**：一个用于处理所有异常的分类界面，距触发告警只需一次点击。

![工具观测页面：延迟热图、百分位带以及 24 个时间段的工具分布柱状图](/agenteye/images/tools.png)

*每个观测界面将迷你折线图和 p50/p95/p99 关键指标与延迟热图及百分位带配对展示。图中所示为：工具。*

**分析**（将活动转化为答案）：

- **[查询](/zh/agenteye/queries)** 和 **[仪表板](/zh/agenteye/dashboards)**：基于事件和评估数据保存的 SQL 查询，以图表形式呈现在组织级共享仪表板中。
- **[评估](/zh/agenteye/evaluations)**：由您自己的评估服务生成的质量分数，附带每项评分的推理依据。
- **[审计](/zh/agenteye/audits)**：定期调查，跨会话呈现故障模式。
- **[告警](/zh/agenteye/alerts)** 和 **[事件](/zh/agenteye/incidents)**：向您发送通知的阈值规则，以及用于分类处理的事件工作流。

**接入方式**（以您习惯的方式访问数据）：

- **[CLI](/zh/agenteye/cli-and-agents)**：通过终端或脚本驱动整个部署流程，也可以让编码 agent 用自然语言替您完成。
- **[AI 助手](/zh/agenteye/assistant)**：直接在仪表板内，用自然语言询问关于您 agent 的问题。
- **REST API**：仪表板和 CLI 的所有功能均由 REST API 支撑，您可以使用有权限范围的 [API 密钥](/zh/agenteye/api-keys)直接调用——摄取事件、查询会话和评估、管理仪表板、告警、审计、用户和密钥，从而将 Failproof AI Observability 接入您自己的工具链。

**管理**（为您的团队运营）：

- **[API 密钥](/zh/agenteye/api-keys)**：为采集器、仪表板和助手划定权限范围的令牌。
- **用户**：基于邮箱白名单的无密码登录。
- **设置**：组织级配置，包括模型上下文窗口覆盖。

## 各部分如何协同工作

数据沿一个方向流动，从您的 agent 代码到仪表板：您的 agent（通过 Python SDK）将事件发送给 agenteye-collector，后者将事件批量传输到服务器，服务器再提供仪表板服务。另外还有两个可选服务——评分服务（评估）和 AI 助手服务（仪表板内聊天）。

- **Python SDK**：您在 agent 中添加少量 `agenteye.event.*` 调用；事件会在本地缓冲。
- **agenteye-collector**：每台 agent 机器上的轻量级守护进程，负责批量收集并传输事件至服务器。
- **服务器**：摄取您的事件，将运营状态保存在您自己的数据库中，并提供供仪表板、CLI 及您自定义集成使用的 REST API。
- **仪表板**：您探索一切内容的地方。
- **可选服务**：评分服务（评估）和 AI 助手服务（仪表板内聊天）。

关于文档中使用的术语（*事件、会话、评估、审计、发现、事件*），请参阅[概念](/zh/agenteye/concepts)。
