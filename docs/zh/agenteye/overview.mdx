Failproof AI Observability 是一个自托管平台，用于在生产环境中观测、评估和改进您的 AI 智能体。它记录智能体的所有操作（每次工具调用、模型请求、钩子和错误），对每次运行的质量进行评分，并将您未曾预料到的故障呈现出来——所有这些都在您自己基础设施内运行的控制台中完成。

如果您正在部署 AI 智能体，却苦于无法搞清楚某次运行为何出错，那么这就是您的起点。本页将介绍 Failproof AI Observability 能为您提供什么，以及各个组件如何协同工作——在您安装任何内容之前。

## 为什么团队选择它

- **看清智能体实际做了什么。** 每次运行都会生成一个可读的类 git 风格执行图：哪些工具并行运行、哪些子智能体分支出去、在哪里卡住，以及消耗了多少资源。
- **自动捕获质量回归。** 接入一个轻量评分服务后，Failproof AI Observability 会对每次完成的运行进行评分，帮助能力下降或幻觉激增等问题自动浮出水面。
- **发现您未曾预设规则的故障。** 定期审计会跨会话挖掘日志，查找错误聚类、延迟异常值、低分和卡住的运行，并将带有证据支撑的排名发现呈现给您。
- **在关键时刻收到告警。** 阈值规则在错误率、延迟、成本或评估分数触发时创建事件，您可以确认、分配和解决这些事件。
- **用自然语言提问。** 控制台内置 AI 助手，可基于您自己的数据回答「本周生产环境的质量趋势如何？」之类的问题。任何变更都需要审批。
- **数据归您所有。** Failproof AI Observability 是自托管的：事件、提示词和分析数据都保留在您控制的基础设施中。

## 功能全览

Failproof AI Observability 围绕三大理念组织（**观测**、**分析**和**管理**），对应控制台左侧边栏的结构。

**观测**（真实发生了什么）：

- **[事件流](/zh/agenteye/event-stream)**：每次运行的实时逐步记录（工具调用、模型调用、钩子、错误）。
- **[会话](/zh/agenteye/sessions)**：将这些事件汇总为每次运行一行，每行均可评分，并附带类 git 风格执行图。
- **[性能指标](/zh/agenteye/telemetry)**：按维度划分的延迟热图，以及模型、工具和钩子的 p50/p95/p99 关键指标，让尾部延迟峰值一目了然。
- **[错误追踪](/zh/agenteye/error-tracking)**：一个统一的故障分类界面，一键直达触发告警的详情。

![工具观测页面：24 个时间段的延迟热图、百分位带和工具分布条形图](/agenteye/images/tools.png)

*每个观测界面都将迷你趋势图和 p50/p95/p99 关键指标与延迟热图及百分位带相结合。图示：工具页面。*

**分析**（将活动转化为洞察）：

- **[查询](/zh/agenteye/queries)** 和 **[仪表板](/zh/agenteye/dashboards)**：对事件和评估数据执行已保存的 SQL 查询，以图表形式呈现在团队共享的组织级仪表板中。
- **[评估](/zh/agenteye/evaluations)**：由您自己的评估服务生成的质量分数，附带每项评分的推理过程。
- **[审计](/zh/agenteye/audits)**：定期调查，跨会话发现故障模式。
- **[告警](/zh/agenteye/alerts)** 和 **[事件](/zh/agenteye/incidents)**：触发通知的阈值规则，以及用于分类处理的事件工作流。

**接口**（以您喜欢的方式访问数据）：

- **[CLI](/zh/agenteye/cli-and-agents)**：从终端或脚本驱动整个部署，也可以让编程智能体用自然语言完成操作。
- **[AI 助手](/zh/agenteye/assistant)**：直接在控制台内用自然语言询问有关智能体的问题。
- **REST API**：控制台和 CLI 的所有功能都由 REST API 支撑，您可以使用有范围限制的 [API 密钥](/zh/agenteye/api-keys) 直接调用——摄取事件、查询会话和评估、管理仪表板、告警、审计、用户和密钥，从而将 Failproof AI Observability 集成到您自己的工具链中。

**管理**（为您的团队运维）：

- **[API 密钥](/zh/agenteye/api-keys)**：面向采集器、控制台和助手的范围化令牌。
- **用户**：基于电子邮件的无密码登录，支持白名单管理。
- **设置**：组织级配置，包括模型上下文窗口覆盖设置。

## 各组件如何协同

数据单向流动，从您的智能体代码流向控制台：您的智能体（通过 Python SDK）向 agenteye-collector 发送事件，后者将事件传输到服务器，服务器再为控制台提供数据。另有两个可选服务作为补充——评分服务（评估）和 AI 助手服务（控制台内聊天）。

- **Python SDK**：在您的智能体中添加少量 `agenteye.event.*` 调用；事件在本地缓冲。
- **agenteye-collector**：每台智能体机器上的轻量守护进程，批量将事件传输到服务器。
- **服务器**：摄取您的事件，将运营状态保存在您自己的数据库中，并提供控制台、CLI 和您的集成所使用的 REST API。
- **控制台**：探索所有内容的地方。
- **可选服务**：评分服务（评估）和 AI 助手服务（控制台内聊天）。

关于文档中使用的术语（*事件、会话、评估、审计、发现、事件*），请参阅[概念](/zh/agenteye/concepts)。
