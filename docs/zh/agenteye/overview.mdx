Failproof AI Observability 是一个自托管平台，用于在生产环境中观测、评估和改进您的 AI Agent。它记录 Agent 的所有行为（每次工具调用、模型请求、hook 及错误），对每次运行的质量进行评分，并将您未曾预料的故障呈现出来——所有这些都在您自有基础设施中运行的仪表盘内完成。

如果您在部署 AI Agent，并且厌倦了猜测某次运行为何出错，那么本页就是您的起点。在开始安装之前，本页将介绍 Failproof AI Observability 能为您提供什么，以及各个组件如何协同工作。

## 团队使用它的原因

- **看清 Agent 实际做了什么。** 每次运行都会转化为可读的 git 风格执行图：哪些工具并行运行、哪些子 Agent 分支出去、在哪里卡住，以及消耗了什么资源。
- **自动捕获质量回归。** 接入一个小型评分服务，Failproof AI Observability 便会对每次完成的运行进行评分，帮助能力下降或幻觉激增等问题自动浮出水面。
- **发现您未曾预设规则的故障。** 定期审计会跨会话挖掘日志，找出错误聚类、延迟异常值、低分运行和卡死的运行，并向您提供有优先级排序、有证据支撑的发现报告。
- **关键时刻收到告警。** 阈值规则在错误率、延迟、成本或评估分数触发时创建事件，您可以确认、分配和解决这些事件。
- **用自然语言提问。** 仪表盘内置的 AI 助手可以针对您自己的数据回答「本周生产环境的质量趋势如何？」之类的问题。它所做的任何变更都需要经过审批。
- **数据归您所有。** Failproof AI Observability 采用自托管方式：事件、提示词和分析数据全部保存在您控制的基础设施中。

## 功能概览

Failproof AI Observability 围绕三个核心理念组织——**观测（observe）**、**分析（analyze）** 和 **管理（admin）**——体现在仪表盘左侧边栏的结构上。

**观测**（记录真实发生的事情）：

- **[事件流](/zh/agenteye/event-stream)**：每次运行的实时逐步记录（工具调用、模型调用、hook、错误）。
- **[会话](/zh/agenteye/sessions)**：将事件汇总为每次运行一行，每行均可评分，并配有 git 风格执行图。
- **[性能指标](/zh/agenteye/telemetry)**：按维度划分的延迟热力图，以及模型、工具和 hook 的 p50/p95/p99 关键指标，尾部延迟毛刺一目了然。
- **[错误追踪](/zh/agenteye/error-tracking)**：将所有出错信息汇聚到一个分类处理界面，从触发的告警一键直达。

![工具观测页面：延迟热力图、百分位区间，以及 24 个时间段内的工具分布柱状图](/agenteye/images/tools.png)

*每个观测页面都将迷你折线图和 p50/p95/p99 关键指标与延迟热力图及百分位区间配对呈现。图示为：工具（Tools）页面。*

**分析**（将活动转化为洞察）：

- **[查询](/zh/agenteye/queries)** 和 **[仪表盘](/zh/agenteye/dashboards)**：对事件和评估数据执行已保存的 SQL 查询，并以图表形式呈现在团队共享的组织级仪表盘中。
- **[评估](/zh/agenteye/evaluations)**：由您自己的评估服务生成的质量分数，附带逐项评分理由。
- **[审计](/zh/agenteye/audits)**：定期调查，跨会话发现故障模式。
- **[告警](/zh/agenteye/alerts)** 和 **[事件](/zh/agenteye/incidents)**：触发通知的阈值规则，以及用于分类处理的事件工作流。

**接口**（以您偏好的方式访问数据）：

- **[CLI](/zh/agenteye/cli-and-agents)**：通过终端或脚本驱动整个部署，也可让编码 Agent 用自然语言完成操作。
- **[AI 助手](/zh/agenteye/assistant)**：在仪表盘内直接用自然语言查询您的 Agent 数据。
- **REST API**：仪表盘和 CLI 的所有功能均由 REST API 提供支持，您可以直接使用有范围限制的 [API 密钥](/zh/agenteye/api-keys) 进行调用——摄入事件、查询会话和评估结果、管理仪表盘、告警、审计、用户和密钥，从而将 Failproof AI Observability 集成到您自己的工具链中。

**管理**（为团队运维）：

- **[API 密钥](/zh/agenteye/api-keys)**：用于采集器、仪表盘和助手的有范围限制的令牌。
- **用户**：基于邮件的无密码登录，支持白名单。
- **设置**：按组织配置，包括模型上下文窗口的覆盖选项。

## 组件协作方式

数据单向流动，从您的 Agent 代码流向仪表盘：您的 Agent（通过 Python SDK）将事件发送到 agenteye-collector，后者将事件传输到服务器，服务器再为仪表盘提供数据。另有两个可选服务作为补充——评分服务（评估）和 AI 助手服务（仪表盘内的对话功能）。

- **Python SDK**：您在 Agent 代码中添加少量 `agenteye.event.*` 调用，事件在本地缓冲。
- **agenteye-collector**：部署在每台 Agent 机器上的轻量级守护进程，负责批量传输事件到服务器。
- **服务器**：摄入事件，将运营状态保存在您自己的数据库中，并提供 REST API 供仪表盘、CLI 及您的自定义集成使用。
- **仪表盘**：所有数据的探索入口。
- **可选服务**：评分服务（评估）和 AI 助手服务（仪表盘内的对话功能）。

关于文档中使用的专业术语（*事件、会话、评估、审计、发现、事件*），请参阅[概念说明](/zh/agenteye/concepts)。
