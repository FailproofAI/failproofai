Failproof AI Observability 是一个自托管平台，用于在生产环境中观测、评估和改进您的 AI agent。它记录 agent 的所有操作（每次工具调用、模型请求、hook 和错误），对每次运行的质量进行评分，并在您自己基础设施内运行的仪表板中呈现那些您未曾预料到的故障。

如果您部署了 AI agent，并且厌倦了猜测某次运行为何出错，那么这就是您的起点。本文将介绍 Failproof AI Observability 能为您提供什么，以及各组件如何协同工作——一切在安装之前就先说清楚。

## 团队使用它的原因

- **看清 agent 的实际行为。** 每次运行都会生成一个可读的类 git 执行图：哪些工具并行运行、哪些子 agent 分支出去、在哪里停滞，以及消耗了多少资源。
- **自动捕获质量回归。** 接入一个小型评分服务，Failproof AI Observability 便会对每次已完成的运行进行评分，帮助回答率下降或幻觉激增等问题能够自动浮现。
- **发现您没有编写规则的故障。** 定期审计会跨会话挖掘日志，寻找错误聚类、延迟异常值、低分运行和卡死运行，并向您提供经过排序且有证据支撑的发现。
- **在关键时刻收到告警。** 针对错误率、延迟、成本或评估分数设置阈值规则，触发事件后您可以确认、分配和解决。
- **用自然语言提问。** 仪表板内置 AI 助手，可基于您自己的数据回答"本周生产环境的质量趋势如何？"等问题。助手所做的任何变更均需审批。
- **数据归您所有。** Failproof AI Observability 是自托管的：事件、提示词和分析数据均保留在您控制的基础设施中。

## 功能概览

Failproof AI Observability 围绕三个核心理念组织——**观测（observe）**、**分析（analyze）** 和**管理（admin）**，在仪表板左侧边栏中均有对应入口。

**观测**（原始事实，记录发生了什么）：

- **[事件流](/zh/agenteye/event-stream)**：每次运行的实时逐步记录（工具调用、模型调用、hook、错误）。
- **[会话](/zh/agenteye/sessions)**：将事件汇总为每次运行一行，每行均可评分，并附有类 git 执行图。
- **[性能指标](/zh/agenteye/telemetry)**：按维度划分的延迟热力图，以及模型、工具和 hook 的 p50/p95/p99 关键指标，让尾部延迟峰值从中位数中一眼看出。
- **[错误追踪](/zh/agenteye/error-tracking)**：统一的问题分类界面，汇聚所有出错内容，一键直达触发中的告警。

![工具观测页面：延迟热力图、百分位区间，以及 24 个时间段的工具分布柱状图](/agenteye/images/tools.png)

*每个观测界面都将迷你折线图和 p50/p95/p99 关键指标与延迟热力图及百分位区间配对呈现。图示为：工具（Tools）。*

**分析**（将活动转化为洞察）：

- **[查询](/zh/agenteye/queries)** 和 **[仪表板](/zh/agenteye/dashboards)**：针对事件和评估数据保存的 SQL 查询，并以图表形式展示在团队共享的组织级仪表板中。
- **[评估](/zh/agenteye/evaluations)**：由您自己的评估服务产生的质量分数，附带每项分数的推理说明。
- **[审计](/zh/agenteye/audits)**：定期调查，跨会话发现故障模式。
- **[告警](/zh/agenteye/alerts)** 和 **[事件](/zh/agenteye/incidents)**：触发通知的阈值规则，以及用于分类处理的事件工作流。

**接口**（以您喜欢的方式访问数据）：

- **[CLI](/zh/agenteye/cli-and-agents)**：从终端或脚本管理整个部署，也可用自然语言让编码 agent 代劳。
- **[AI 助手](/zh/agenteye/assistant)**：直接在仪表板中用自然语言询问有关 agent 的问题。
- **REST API**：仪表板和 CLI 的所有功能均由 REST API 支撑，您可以通过有范围限制的 [API 密钥](/zh/agenteye/api-keys)直接调用——接收事件、查询会话和评估结果、管理仪表板、告警、审计、用户和密钥，从而将 Failproof AI Observability 集成到您自己的工具链中。

**管理**（为团队运营平台）：

- **[API 密钥](/zh/agenteye/api-keys)**：面向收集器、仪表板和助手的有范围限制的 token。
- **用户**：基于邮箱的无密码登录，支持白名单。
- **设置**：组织级配置，包括模型上下文窗口覆盖。

## 组件如何协同工作

数据单向流动，从您的 agent 代码流向仪表板：您的 agent（通过 Python SDK）将事件发送至 agenteye-collector，后者将其传输至服务端，服务端再向仪表板提供数据。另有两个可选服务作为补充——评分服务（评估）和 AI 助手服务（仪表板内对话）。

- **Python SDK**：在您的 agent 中添加若干 `agenteye.event.*` 调用；事件在本地缓冲。
- **agenteye-collector**：部署在每台 agent 机器上的轻量级守护进程，负责批量收集事件并传输至服务端。
- **服务端**：接收事件，在您自己的数据库中维护运营状态，并提供供仪表板、CLI 及您自己的集成使用的 REST API。
- **仪表板**：您探索所有内容的地方。
- **可选服务**：评分服务（评估）和 AI 助手服务（仪表板内对话）。

关于文档中使用的术语（*event、session、evaluation、audit、finding、incident*），请参阅[概念](/zh/agenteye/concepts)。
