精确查看 AI 智能体在生产环境中的行为：每次智能体运行、工具调用、模型请求、hook 触发及人工干预。Failproof AI 可观测性 Python SDK 从你的智能体代码内部记录完整的执行轨迹，让你能够调试、审计和评估发生了什么。任何时候你希望 Failproof AI 可观测性监测你的智能体，都可以使用它。

在底层实现上，SDK 将结构化事件写入本地 JSONL 文件，收集器守护进程会自动拾取这些文件并上传到平台。你无需自行管理这些文件。

## 安装

SDK 以私有 wheel 包的形式分发给客户，而非通过公共包索引获取。你的入职流程会介绍如何获取、安装并锁定版本——如需访问权限，请联系你的 Failproof AI 对接人。

安装完成后，通过以下命令确认安装成功：

```bash
python -c "import agenteye; print(agenteye.__version__)"
```

## 快速上手

```python
import agenteye

agenteye.configure(environment="production")

agenteye.event.agent_start(session_id="run-001", agent_id="planner", goal="answer user query")

agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    input={"query": "latest AI research"},
)

agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    output={"results": ["..."]},
)

agenteye.event.agent_end(session_id="run-001", agent_id="planner", outcome="success")
```

### 对真实调用进行埋点

在实践中，你需要在现有智能体代码外层添加追踪。在模型调用前发出 `model_request` 事件，调用后发出 `model_response` 事件，使这两个事件覆盖真实请求的完整生命周期，从而让 Failproof AI 可观测性将它们配对关联：

```python
import anthropic
import agenteye

agenteye.configure(environment="production")
client = anthropic.Anthropic()

messages = [{"role": "user", "content": "Summarise today's incidents."}]

agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6",
    messages=messages,
)

reply = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=512,
    messages=messages,
)

agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model=reply.model,
    stop_reason=reply.stop_reason,
    input_tokens=reply.usage.input_tokens,
    output_tokens=reply.usage.output_tokens,
    content=[block.model_dump() for block in reply.content],
)
```

工具调用同理，使用 `tool_use` 和 `tool_result` 进行包裹，并在一对事件中复用同一个 `tool_call_id`。

## configure()

```python
agenteye.configure(
    base_dir=None,           # Path | str | None. Default: $AGENTEYE_HOME or ~/.agenteye
    flush_interval=0.5,      # float, seconds between flush cycles
    environment=None,        # str | None. Deployment environment label
)
```

在调用任何 `event.*` 方法之前调用一次。可以省略，默认配置开箱即用。所有参数均为仅关键字参数，请按上方示例以名称传递。

当 `base_dir` 为 `None`（默认值）时，SDK 会优先读取 `$AGENTEYE_HOME` 环境变量，若未设置则回退到 `~/.agenteye`。这与收集器自身的路径解析逻辑一致，因此只需设置一个 `AGENTEYE_HOME` 环境变量，即可同时为 SDK 和收集器配置共享的事件缓冲目录。

## 环境标签

为每个事件添加部署环境标签（如 `production`、`staging`、`qa`、`canary` 等）。只需设置一次，SDK 会自动将其附加到每个事件上。

**方式一：通过 `configure()` 设置：**

```python
agenteye.configure(environment="production")
```

**方式二：通过环境变量设置：**

```bash
export AGENTEYE_ENVIRONMENT=production
```

**优先级：** `configure(environment=...)` 的优先级高于环境变量。若均未设置，默认值为 `"dev"`。

环境值在仪表板中作为一级过滤条件展示，并存储在服务器上以支持快速查询。

> **警告：** 环境值不得包含英文逗号 `,`。仪表板过滤器在传输时使用逗号分隔的多选格式（`?environment=prod,staging`），因此名为 `prod,blue` 的环境值会被拆分为两个值。包含逗号的环境值在数据接收时会被拒绝。

## 数据与隐私

SDK 仅记录你显式传递的字段。提示词、消息、工具输入/输出和模型内容，只有在你将其传递给 `event.*` 方法时才会被捕获。SDK 不会读取你的进程内容，也不会隐式捕获任何信息。任何未设置的字段都会从事件中完全省略，不会写入磁盘。

因此，数据脱敏是你的选择，也是你的责任。如果提示词或工具载荷中包含你不希望存储的个人信息或敏感数据，请在传递给事件方法之前进行清除或脱敏处理。

## 事件参考

大多数事件以开始/结束的配对形式出现，并共享一个关联 ID：`tool_use` 和 `tool_result` 共享 `tool_call_id`，`hook_triggered` 和 `hook_completed` 共享 `hook_id`，`human_wait` 和 `human_input` 共享 `input_id`。发出开始事件，执行操作，然后用相同的 ID 发出结束事件。Failproof AI 可观测性会自动配对并计算 `duration_ms`，你无需手动传递该值。

![会话的 git 风格执行图与事件时间线，由配对事件重建，附工具/模型/hook 细分面板](/agenteye/images/session-detail.png)

所有事件方法均要求以下两个字段：

| 字段 | 类型 | 描述 |
|---|---|---|
| `session_id` | `str` | 标识顶层智能体运行 |
| `agent_id` | `str` | 标识会话中发出该事件的智能体 |

所有方法还接受任意 `**kwargs` 用于自定义元数据（参见[自定义字段](#custom-fields)）。

---

### `event.agent_start()`

当智能体开始工作时发出。

```python
agenteye.event.agent_start(
    session_id="run-001",
    agent_id="planner",
    goal="answer user query",   # str | None
    parent_id=None,             # str | None - parent agent_id for nested agents
)
```

---

### `event.agent_end()`

当智能体完成工作时发出。

```python
agenteye.event.agent_end(
    session_id="run-001",
    agent_id="planner",
    outcome="success",          # str | None
    summary="Answered query",   # str | None
)
```

---

### `event.tool_use()`

当智能体调用工具时发出。与 `tool_result` 配对使用；SDK 自动计算 `duration_ms`。

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",     # str, required
    tool_call_id="toolu_01",    # str, required - correlation key for the matching tool_result
    input={"query": "..."},     # dict | None
)
```

---

### `event.tool_result()`

当工具返回结果时发出。通过 `tool_call_id` 与 `tool_use` 关联。

```python
agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",        # must match the prior tool_use
    output={"results": ["..."]},    # Any | None
    error=None,                     # str | None - set if the tool raised
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.model_request()`

在向 LLM 发送提示词之前发出。

```python
agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    messages=[                   # list[dict] | None - conversation turns
        {"role": "user", "content": "..."},
    ],
    system="You are helpful.",   # Any | None - str or list of content blocks
    tools=[                      # list[dict] | None - tool schemas offered to the model
        {"name": "search", "input_schema": {"type": "object"}},
    ],
)
```

`messages` 条目的 `content` 字段接受纯字符串或 Anthropic 风格的内容块列表。采样参数（`temperature`、`max_tokens` 等）可作为额外的 kwargs 传入。

---

### `event.model_response()`

当 LLM 返回响应时发出。

```python
agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - any provider/model string; not validated
    stop_reason="end_turn",     # str | None
    input_tokens=1024,          # int | None
    output_tokens=256,          # int | None
    content=[                    # Any | None - str, or list of content blocks
        {"type": "text", "text": "..."},
    ],
    role="assistant",            # str | None
)
```

`content` 接受纯字符串（通用提供商）或 Anthropic 风格的内容块列表。工具调用以 `{"type": "tool_use", ...}` 块的形式存在于 `content` 中，没有单独的 `tool_calls` 字段。

---

### `event.hook_triggered()`

当 hook 触发时发出。与 `hook_completed` 配对使用；SDK 自动计算 `duration_ms`。

```python
agenteye.event.hook_triggered(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",   # str, required
    hook_id="hook-abc",         # str, required - correlation key
    trigger_event="tool_use",   # str | None
    input={"tool": "search"},   # Any | None
)
```

---

### `event.hook_completed()`

当 hook 执行完成时发出。通过 `hook_id` 与 `hook_triggered` 关联。

```python
agenteye.event.hook_completed(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",
    hook_id="hook-abc",         # must match the prior hook_triggered
    outcome="allow",            # str | None
    output=None,                # Any | None
    error=None,                 # str | None
    # duration_ms is computed automatically - do not pass it
)
```

---

### `event.error()`

当发生未处理的错误时发出。

```python
agenteye.event.error(
    session_id="run-001",
    agent_id="planner",
    error_type="TimeoutError",  # str, required
    message="timed out",        # str, required
    traceback="Traceback...",   # str | None
)
```

## 人工干预事件

人工干预事件让你能够监督人员介入智能体执行的关键时刻（等待审批、提供输入、暂停或停止智能体）。通过这些事件，你可以衡量人员响应所需的时间（SDK 会自动计算配对事件的 `duration_ms`），审计谁暂停或中断了智能体，并构建在仪表板中可见的审批和监督工作流。

### `event.human_wait()`

当智能体暂停执行以等待人工输入时发出。与 `human_input` 配对使用；SDK 自动计算 `duration_ms`（即人员响应所用时长）。

```python
agenteye.event.human_wait(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",                          # str, required - correlation key for the matching human_input
    prompt="Do you approve this action?",        # str | None - the question shown to the human
    options=["approve", "reject", "defer"],      # list[str] | None - choices presented to the human
    reason="approval_required",                  # str | None - why the agent is waiting
)
```

### `event.human_input()`

当人工提供输入且智能体恢复执行时发出。通过 `input_id` 与 `human_wait` 关联。`duration_ms` 由 SDK 自动计算，调用方不得传递该值。

```python
agenteye.event.human_input(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",    # str, required - must match the prior human_wait
    response="approve",    # str | None - the human's answer (free text or selected option)
    # duration_ms is computed automatically - do not pass it
)
```

### `event.human_pause()`

当人工主动暂停智能体时发出（例如通过仪表板控件）。智能体被挂起但未终止。

```python
agenteye.event.human_pause(
    session_id="run-001",
    agent_id="planner",
    reason="user_requested",  # str | None
    user_id="usr_42",         # str | None - who paused the agent
)
```

### `event.human_interrupt()`

当人工在执行过程中主动停止智能体时发出。与 `human_pause` 不同，智能体的工作被终止而非挂起。

```python
agenteye.event.human_interrupt(
    session_id="run-001",
    agent_id="planner",
    reason="output_incorrect",       # str | None
    user_id="usr_42",                # str | None - who interrupted the agent
    at_step="tool_use:web_search",   # str | None - what the agent was doing when stopped
)
```

## 自定义字段

任何额外的关键字参数都会追加到事件的标准字段之后：

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="db_query",
    tool_call_id="toolu_02",
    tenant_id="acme",           # custom field
    region="us-east-1",         # custom field
)
```

`timestamp`、`type` 和 `environment` 为保留字段，若作为自定义字段传入，将抛出 `ValueError`（`Reserved field names cannot be used as custom fields: [...]`）。`session_id` 和 `agent_id` 是每个事件方法的必填参数，不能重复传入；若重复传入，Python 会抛出 `TypeError`。请通过 `configure(environment=...)` 或 `AGENTEYE_ENVIRONMENT` 环境变量来设置环境值。

如需查询字段内容，请保持载荷为结构化 JSON 格式。JSON 原生不支持的值类型——如 datetime、UUID、decimal、set、bytes 或模型对象——会被转换为字符串，以确保记录正常进行。

## 事件写入机制

事件在进程内缓冲，每隔 `flush_interval` 秒（默认 500 毫秒）刷新一次写入磁盘。每次刷新写入一个 JSONL 文件：

```text
~/.agenteye/events/event-2026-04-01T12-00-00-000Z.jsonl
```

收集器监控此目录并自动上传文件。你无需直接管理这些文件。

每个文件以原子方式写入：SDK 先写入临时文件，再重命名到目标位置，因此收集器不会读取到写入中途的文件。在进程退出时还会执行一次最终刷新，确保最后一个间隔内缓冲的事件不会丢失。如果收集器离线，事件会作为文件积累在磁盘上，待其恢复后自动上传。
