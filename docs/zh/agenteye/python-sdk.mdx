精确掌握 AI 智能体在生产环境中的每一步：每次运行、工具调用、模型请求、hook 及人工干预。Failproof AI Observability Python SDK 在智能体代码内部记录完整的执行轨迹，让你可以调试、审计和评估发生了什么。当你希望 Failproof AI Observability 对你的智能体进行可观测性监控时，使用此 SDK 即可。

SDK 底层将结构化事件写入本地 JSONL 文件，采集器守护进程会自动拾取并上传到平台。你无需自行管理这些文件。

## 安装

SDK 以私有 wheel 包的形式分发给客户，不通过公共包索引获取。具体获取、安装和版本固定方式会在引导流程中说明——如需访问权限，请联系你的 Failproof AI 对接人。

安装完成后，验证是否成功：

```bash
python -c "import agenteye; print(agenteye.__version__)"
```

希望让编码智能体完成整个集成流程？[Python SDK Agent Skill](/zh/agenteye/python-sdk-skill) 已知晓安装路径，可以规划埋点位置、编写代码并验证事件是否正常上报。

## 快速开始

```python
import agenteye

agenteye.configure(environment="production")

agenteye.event.agent_start(session_id="run-001", agent_id="planner", goal="answer user query")

agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    input={"query": "latest AI research"},
)

agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",
    output={"results": ["..."]},
)

agenteye.event.agent_end(session_id="run-001", agent_id="planner", outcome="success")
```

### 在真实调用中埋点

实际使用中，你只需在现有智能体代码外层包裹埋点调用。在模型调用前发送 `model_request`，调用后发送 `model_response`，使两个事件覆盖整个真实请求的时间范围，Failproof AI Observability 即可将它们配对：

```python
import anthropic
import agenteye

agenteye.configure(environment="production")
client = anthropic.Anthropic()

messages = [{"role": "user", "content": "Summarise today's incidents."}]

agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6",
    messages=messages,
)

reply = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=512,
    messages=messages,
)

agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model=reply.model,
    stop_reason=reply.stop_reason,
    input_tokens=reply.usage.input_tokens,
    output_tokens=reply.usage.output_tokens,
    content=[block.model_dump() for block in reply.content],
)
```

工具调用同理，使用 `tool_use` 和 `tool_result` 包裹，并在两个事件中复用同一个 `tool_call_id`。

## configure()

```python
agenteye.configure(
    base_dir=None,           # Path | str | None. 默认值：$AGENTEYE_HOME 或 ~/.agenteye
    flush_interval=0.5,      # float，刷新周期间隔（秒）
    environment=None,        # str | None. 部署环境标签
)
```

在任何 `event.*` 调用之前调用一次。可省略；默认配置开箱即用。所有参数均为仅关键字参数，请按上方示例以名称形式传入。

当 `base_dir` 为 `None`（默认值）时，SDK 会读取 `$AGENTEYE_HOME`（若已设置），否则回退到 `~/.agenteye`。该行为与采集器的解析逻辑一致，因此只需设置一个 `AGENTEYE_HOME` 环境变量，即可为 SDK 和采集器共同配置事件缓存目录。

## 环境

为每个事件标记部署环境（`production`、`staging`、`qa`、`canary` 等）。只需设置一次，SDK 会自动将其附加到所有事件上。

**方式一：通过 `configure()` 设置：**

```python
agenteye.configure(environment="production")
```

**方式二：通过环境变量设置：**

```bash
export AGENTEYE_ENVIRONMENT=production
```

**优先级：** `configure(environment=...)` 优先于环境变量。若两者均未设置，默认值为 `"dev"`。

环境值会作为一等过滤条件显示在控制面板中，并存储在服务端以支持快速查询。

> **警告：** 环境值不得包含英文逗号 `,`。控制面板过滤器在底层使用逗号分隔的多选格式（如 `?environment=prod,staging`），因此名为 `prod,blue` 的环境会被拆分为两个值。包含逗号的环境值在数据写入时会被拒绝。

## 数据与隐私

SDK 仅记录你显式传入的字段。提示词、消息、工具输入/输出及模型内容，只有在你主动传给 `event.*` 方法时才会被采集。SDK 不会读取你的进程信息，也不会隐式采集任何内容。未设置的字段会从事件中完全省略，不会写入磁盘。

因此，脱敏处理是你的选择和责任。如果提示词或工具载荷中包含你不希望存储的个人信息或密钥，请在传给事件方法之前进行脱敏或掩码处理。

## 事件参考

大多数事件以开始/结束配对的形式出现，并共享一个关联 ID：`tool_use` 和 `tool_result` 共享 `tool_call_id`，`hook_triggered` 和 `hook_completed` 共享 `hook_id`，`human_wait` 和 `human_input` 共享 `input_id`。先发送开始事件，执行实际操作，再以相同 ID 发送结束事件。Failproof AI Observability 会自动配对并计算 `duration_ms`，你无需自行传入。

![会话的 git 风格执行图及其事件时间线，由配对事件重建而成，附带工具/模型/hook 分布面板](/agenteye/images/session-detail.png)

所有事件方法都需要以下两个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | `str` | 标识顶层智能体运行实例 |
| `agent_id` | `str` | 标识会话中发送该事件的智能体 |

所有方法还接受任意 `**kwargs` 作为自定义元数据（参见[自定义字段](#custom-fields)）。

---

### `event.agent_start()`

智能体开始工作时发送。

```python
agenteye.event.agent_start(
    session_id="run-001",
    agent_id="planner",
    goal="answer user query",   # str | None
    parent_id=None,             # str | None - 嵌套智能体的父 agent_id
)
```

---

### `event.agent_end()`

智能体完成工作时发送。

```python
agenteye.event.agent_end(
    session_id="run-001",
    agent_id="planner",
    outcome="success",          # str | None
    summary="Answered query",   # str | None
)
```

---

### `event.tool_use()`

智能体调用工具时发送。需与 `tool_result` 配对；SDK 自动计算 `duration_ms`。

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",     # str，必填
    tool_call_id="toolu_01",    # str，必填 - 与对应 tool_result 的关联键
    input={"query": "..."},     # dict | None
)
```

---

### `event.tool_result()`

工具返回结果时发送。通过 `tool_call_id` 与 `tool_use` 关联。

```python
agenteye.event.tool_result(
    session_id="run-001",
    agent_id="planner",
    tool_name="web_search",
    tool_call_id="toolu_01",        # 必须与之前的 tool_use 匹配
    output={"results": ["..."]},    # Any | None
    error=None,                     # str | None - 工具抛出异常时设置
    # duration_ms 自动计算，无需传入
)
```

---

### `event.model_request()`

向 LLM 发送提示词之前发送。

```python
agenteye.event.model_request(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - 任意 provider/model 字符串，不作校验
    messages=[                   # list[dict] | None - 对话轮次
        {"role": "user", "content": "..."},
    ],
    system="You are helpful.",   # Any | None - 字符串或内容块列表
    tools=[                      # list[dict] | None - 提供给模型的工具 schema
        {"name": "search", "input_schema": {"type": "object"}},
    ],
)
```

`messages` 中的条目支持纯字符串 `content` 或 Anthropic 风格的内容块列表 `content`。采样参数（`temperature`、`max_tokens` 等）可作为额外 kwargs 传入。

---

### `event.model_response()`

LLM 返回响应时发送。

```python
agenteye.event.model_response(
    session_id="run-001",
    agent_id="planner",
    model="claude-sonnet-4-6", # str | None - 任意 provider/model 字符串，不作校验
    stop_reason="end_turn",     # str | None
    input_tokens=1024,          # int | None
    output_tokens=256,          # int | None
    content=[                    # Any | None - 字符串或内容块列表
        {"type": "text", "text": "..."},
    ],
    role="assistant",            # str | None
)
```

`content` 支持纯字符串（通用 provider）或 Anthropic 风格的内容块列表。工具调用以 `{"type": "tool_use", ...}` 块的形式存在于 `content` 中，没有单独的 `tool_calls` 字段。

---

### `event.hook_triggered()`

hook 触发时发送。需与 `hook_completed` 配对；SDK 自动计算 `duration_ms`。

```python
agenteye.event.hook_triggered(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",   # str，必填
    hook_id="hook-abc",         # str，必填 - 关联键
    trigger_event="tool_use",   # str | None
    input={"tool": "search"},   # Any | None
)
```

---

### `event.hook_completed()`

hook 执行完成时发送。通过 `hook_id` 与 `hook_triggered` 关联。

```python
agenteye.event.hook_completed(
    session_id="run-001",
    agent_id="planner",
    hook_name="pre_tool_use",
    hook_id="hook-abc",         # 必须与之前的 hook_triggered 匹配
    outcome="allow",            # str | None
    output=None,                # Any | None
    error=None,                 # str | None
    # duration_ms 自动计算，无需传入
)
```

---

### `event.error()`

发生未处理错误时发送。

```python
agenteye.event.error(
    session_id="run-001",
    agent_id="planner",
    error_type="TimeoutError",  # str，必填
    message="timed out",        # str，必填
    traceback="Traceback...",   # str | None
)
```

## 人机协作事件

人机协作事件让你能够监控人员介入智能体执行的关键时刻（等待审批、提供输入、暂停或终止智能体）。通过这些事件，你可以：衡量人工响应耗时（SDK 自动计算配对事件的 `duration_ms`）、审计谁暂停或中断了智能体，以及构建在控制面板中可视化的审批和监督工作流。

### `event.human_wait()`

智能体暂停执行、等待人工输入时发送。需与 `human_input` 配对；SDK 自动计算 `duration_ms`（即人工响应耗时）。

```python
agenteye.event.human_wait(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",                          # str，必填 - 与对应 human_input 的关联键
    prompt="Do you approve this action?",        # str | None - 展示给人工的问题
    options=["approve", "reject", "defer"],      # list[str] | None - 提供给人工的选项
    reason="approval_required",                  # str | None - 智能体等待的原因
)
```

### `event.human_input()`

人工提供输入、智能体恢复执行时发送。通过 `input_id` 与 `human_wait` 关联。`duration_ms` 自动计算，调用方不得传入。

```python
agenteye.event.human_input(
    session_id="run-001",
    agent_id="planner",
    input_id="inp-abc",    # str，必填 - 必须与之前的 human_wait 匹配
    response="approve",    # str | None - 人工的回答（自由文本或所选选项）
    # duration_ms 自动计算，无需传入
)
```

### `event.human_pause()`

人工主动暂停智能体时发送（例如通过控制面板操作）。智能体被挂起但未终止。

```python
agenteye.event.human_pause(
    session_id="run-001",
    agent_id="planner",
    reason="user_requested",  # str | None
    user_id="usr_42",         # str | None - 执行暂停操作的用户
)
```

### `event.human_interrupt()`

人工在智能体执行过程中主动停止时发送。与 `human_pause` 不同，此事件表示智能体工作被终止而非挂起。

```python
agenteye.event.human_interrupt(
    session_id="run-001",
    agent_id="planner",
    reason="output_incorrect",       # str | None
    user_id="usr_42",                # str | None - 执行中断操作的用户
    at_step="tool_use:web_search",   # str | None - 被停止时智能体正在执行的操作
)
```

## 自定义字段

任何额外的关键字参数都会追加到事件的标准字段之后：

```python
agenteye.event.tool_use(
    session_id="run-001",
    agent_id="planner",
    tool_name="db_query",
    tool_call_id="toolu_02",
    tenant_id="acme",           # 自定义字段
    region="us-east-1",         # 自定义字段
)
```

`timestamp`、`type` 和 `environment` 为保留字段，若作为自定义字段传入，会抛出 `ValueError`（`Reserved field names cannot be used as custom fields: [...]`）。`session_id` 和 `agent_id` 是每个事件方法的必填参数，不能重复传入；否则 Python 会抛出 `TypeError`。请使用 `configure(environment=...)` 或 `AGENTEYE_ENVIRONMENT` 变量设置环境值。

需要查询字段内容时，建议将载荷保持为结构化 JSON 格式。JSON 原生不支持的值类型——如 datetime、UUID、Decimal、set、bytes 或模型对象——会被转换为字符串，以确保记录正常进行。

## 事件写入方式

事件在进程内缓冲，每隔 `flush_interval` 秒（默认 500 毫秒）刷新一次到磁盘。每次刷新写入一个 JSONL 文件：

```text
~/.agenteye/events/event-2026-04-01T12-00-00-000Z.jsonl
```

采集器监视该目录并自动上传文件，你无需直接管理这些文件。

每个文件以原子方式写入：SDK 先写入临时文件，再重命名到目标位置，因此采集器永远不会读到写了一半的文件。进程退出时还会执行最后一次刷新，确保最后一个间隔内缓冲的事件不会丢失。如果采集器离线，事件会以文件形式在磁盘上积累，待采集器恢复后自动上传。
