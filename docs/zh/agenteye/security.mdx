Failproof AI Observability 被设计为紧邻您的生产智能体运行，这意味着它能够看到您的提示词、工具输入和输出。本页面说明了它如何对这些数据进行隔离、管控，并将控制权交到您手中。如果您正在对 Failproof AI Observability 进行安全审查评估，请从这里开始。

---

## 您的数据保留在您的环境中

Failproof AI Observability 采用自托管方式部署。事件、提示词、模型响应和分析数据均存储在您自己的数据库中，位于您自己的环境内。数据不会发送至任何第三方 SaaS 平台进行存储，始终保留在您自己的云账户中。

---

## 租户隔离

一个 Failproof AI Observability 实例可以托管多个组织，每个组织在存储层面相互隔离——这由数据库本身强制执行，而不仅仅依赖于 UI：

- 组织的运营数据（用户、密钥、仪表盘、已保存查询）均限定于该组织范围内，跨组织读取由数据库本身阻断。
- 每个摄入的事件都会被标记其所属组织，因此一个组织的事件绝无可能被另一个组织读取。

每个仪表盘路由都限定在组织 slug 下（`/<org-slug>/…`）。

---

## 登录

Failproof AI Observability 采用基于电子邮件的无密码登录方式。不存在可被网络钓鱼或泄露的密码。用户请求一次性验证码（或一键魔法链接），系统将其发送至用户邮箱，并在短时间内过期。登录受**白名单**控制：只有您允许的电子邮件地址（或域名）才能通过身份验证。

## 使用 API 密钥进行权限范围控制

每个客户端均使用携带细粒度最小权限的 API 密钥进行身份验证。采集器只需 `events:add` 权限；仪表盘或助手密钥可设为只读；破坏性操作（删除、重新生成）是独立的授权项，由您自行决定是否开放。

![API 密钥页面：每个密钥的权限授予情况，按读取、写入和破坏性操作范围以颜色区分](/agenteye/images/api-keys.png)

将管理员引导密钥保留用于初始配置，其他所有场景均签发权限受限的密钥。详见 [API 密钥](/zh/agenteye/api-keys)。

## 只读、需审批的 AI 助手

仪表盘内置的 [AI 助手](/zh/agenteye/assistant) 可基于您的数据回答问题，但其行为受到设计层面的约束：

- **默认只读**：其执行的 SQL 经过守卫过滤，仅允许 `SELECT`/`WITH` 查询，且为单语句、带行数上限。
- 它创建的任何内容（已保存查询、仪表盘）均需**审批才能生效**：每次写入操作发生前，您需要进行审核并确认。
- 它**永远无法执行删除操作**。

因此，团队成员可以询问"本周哪些智能体报错最多？"并基于答案采取行动，而无需担心助手会自行修改或删除您的数据。

## 传输安全

所有流量均通过 HTTPS 传输。您使用自己的证书终止 TLS，因此采集器到服务器以及浏览器到服务器的流量在传输过程中均已加密。
