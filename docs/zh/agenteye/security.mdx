Failproof AI Observability 专为贴近生产环境中的 Agent 而设计，这意味着它能够看到您的提示词、工具输入和输出内容。本页将说明它如何确保数据的隔离、受控，并始终掌握在您手中。如果您正在对 Failproof AI Observability 进行安全审查评估，请从这里开始。

---

## 您的数据保留在您的环境中

Failproof AI Observability 采用自托管方式部署。事件、提示词、模型响应和分析数据均存储在您自己的数据库中，位于您自己的环境内。没有任何数据会发送到第三方 SaaS 平台进行存储，您的数据始终保留在您自己的云账户中。

---

## 租户隔离

一个 Failproof AI Observability 实例可以托管多个组织，每个组织在存储层面彼此隔离——这由数据库强制执行，而不仅仅依赖 UI 层面的控制：

- 组织的操作数据（用户、密钥、仪表盘、已保存查询）仅限于该组织访问，跨组织读取由数据库本身阻断。
- 每个摄入的事件都会标记其所属组织，因此一个组织的事件永远不会被另一个组织读取。

每个仪表盘路由都以组织标识符为前缀（`/<org-slug>/…`）进行作用域限定。

---

## 登录方式

Failproof AI Observability 采用无密码、基于电子邮件的登录方式。不存在可被钓鱼或泄露的密码。用户请求一次性验证码（或一键魔法链接），该链接通过电子邮件发送给用户，并会在短时间内失效。登录受**白名单**保护：只有您明确允许的电子邮件地址（或域名）才能通过身份验证。

## 使用 API 密钥进行作用域访问控制

每个客户端都通过携带精细化最小权限的 API 密钥进行身份验证。数据采集器只需要 `events:add` 权限；仪表盘或助手密钥可以设置为只读；破坏性操作（删除、重新生成）是需要您主动选择授予的独立权限。

![API 密钥页面：每个密钥的权限授予情况，按读取、写入和破坏性作用域分色标注](/agenteye/images/api-keys.png)

管理员引导密钥仅用于初始设置，其他所有场景都应使用权限受限的密钥。请参阅 [API 密钥](/zh/agenteye/api-keys)。

## 只读且需审批的 AI 助手

仪表盘内置的 [AI 助手](/zh/agenteye/assistant) 可以对您的数据进行问答，但其行为受到设计层面的严格约束：

- **默认只读**：其 SQL 查询经过守卫模块过滤，仅允许执行 `SELECT`/`WITH` 语句，且每次只能执行单条语句，并设有行数上限。
- 任何创建操作（保存查询、创建仪表盘）都**需要审批**：您需要审查并批准每次写入操作才能生效。
- **永远无法执行删除操作**。

因此，团队成员可以询问"本周哪些 Agent 报错最多？"并根据答案采取行动，而无需担心助手会自行修改或删除您的数据。

---

## 传输安全

所有流量均通过 HTTPS 传输。您使用自己的证书终止 TLS，确保采集器到服务器以及浏览器到服务器的流量在传输过程中均经过加密。
