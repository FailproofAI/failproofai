Failproof AI Observability 专为贴近您的生产智能体而设计，这意味着它能看到您的提示词、工具输入和输出。本页面说明它如何保持数据隔离、受控，并始终掌握在您手中。如果您正在对 Failproof AI Observability 进行安全审查评估，请从这里开始。

---

## 您的数据始终保留在您的环境中

Failproof AI Observability 采用自托管方式。事件、提示词、模型响应和分析数据均存储在您自己的数据库中，位于您自己的环境内。任何数据都不会发送到第三方 SaaS 进行存储，您的数据始终保留在您自己的云账户中。

---

## 租户隔离

一个 Failproof AI Observability 实例可以托管多个组织，每个组织在存储层面相互隔离——由数据库强制执行，而不仅仅依赖 UI：

- 组织的运营数据（用户、密钥、仪表板、已保存的查询）均限定在该组织范围内，跨组织读取在数据库层面被阻止。
- 每个摄入的事件都会标记其所属组织，因此一个组织的事件永远无法被另一个组织读取。

每个仪表板路由都限定在组织 slug 下（`/<org-slug>/…`）。

---

## 登录

Failproof AI Observability 使用基于电子邮件的无密码登录方式。没有密码可供网络钓鱼或泄露。用户请求一次性验证码（或一键魔法链接），通过电子邮件发送给他们，并会在短时间内过期。登录受**白名单**限制：只有您允许的电子邮件地址（或域名）才能通过验证。

## 使用 API 密钥实现范围化访问

每个客户端都使用携带细粒度最小权限的 API 密钥进行认证。采集器只需要 `events:add`；仪表板或助手密钥可以设为只读；破坏性操作（删除、重新生成）是您可以选择是否包含的独立授权。

![API 密钥页面：每个密钥的权限授予，按读取、写入和破坏性范围进行颜色标记](/agenteye/images/api-keys.png)

保留管理员引导密钥用于设置，并为其他所有用途签发权限受限的密钥。请参阅 [API 密钥](/zh/agenteye/api-keys)。

---

## 只读、需审批的助手

仪表板内置的 [AI 助手](/zh/agenteye/assistant) 可以回答关于您数据的问题，但在设计上受到严格约束：

- **默认只读**：其 SQL 通过守卫运行，只允许 `SELECT`/`WITH` 查询、单条语句，并有行数上限。
- 它创建的任何内容（已保存的查询、仪表板）均**需要审批**：每次写入操作发生前，您都需要审查并批准。
- 它**永远无法删除数据**。

因此，团队成员可以询问"本周哪些智能体出错最多？"并据此采取行动，而无需担心助手会自行修改或删除您的数据。

---

## 传输中的安全

所有流量均通过 HTTPS 传输。您使用自己的证书终止 TLS，因此采集器到服务器以及浏览器到服务器的流量在传输过程中均已加密。
