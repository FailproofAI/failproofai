## 一眼掌握所有运行

原始事件流记录了每一步的真实情况，但当你面对数十次运行中的数千个步骤时，你需要的是整体视角，而非单个步骤。会话页面将一次运行的所有事件汇总成一行，让一天的活动变成一个可快速浏览的列表，而不是汹涌的信息洪流。

每一行都带有状态标签，在你点击之前就能一眼分辨失败的运行与正常的运行。按日期范围、环境、智能体或会话进行筛选，只需几次点击即可从"全部"聚焦到"我关心的那次运行"。

连接评估器后，每次完成的运行都会自动计分，最新分数会以徽章形式显示在对应行上。你可以按任意分数区间进行筛选，"显示本周所有低分生产运行"只需设置一个筛选条件，无需手动逐一检查。在你设置评估器之前，会话仍会完整记录运行内容，只是暂时没有分数。

## 以图形方式阅读完整运行

![会话的 git 风格执行图与事件时间轴并排展示，右侧面板显示工具、模型和 hook 的详细分解](/agenteye/images/session-detail.png)

*执行图（左侧）与事件时间轴并排显示；右侧栏列出本次运行的工具、模型、hook 及 Token 消耗明细。*

点击任意会话即可打开其执行图：这是一个 git 风格的视图，展示智能体、工具、hook 和模型调用随时间展开的完整过程。并行子智能体各自分布在独立的泳道中，让你清晰看到哪些工作并行执行、哪个子智能体出现了停滞、运行在哪里偏离了轨道——无需费力在一堵日志墙里反复回溯。

右侧栏提供每次运行的详细分解：哪些工具和模型参与运行、哪些 hook 触发、以及本次运行消耗的 Token 数量。这正是"为什么这次运行成本这么高？"或"哪个工具最慢？"等问题的答案，就摆在引发问题的执行图旁边。

每个事件都有独立地址，你可以将某个具体时刻的链接分享给他人，而不是笼统地说"在会话里，大概三分之二处"。从任意事件复制链接，或从[审计](/zh/agenteye/audits)发现或错误中跳转，会话将自动打开并定位到该事件。对于非常长的运行也同样适用：时间轴会加载一个有限窗口以保护浏览器性能，即使链接指向窗口范围之外的事件，也能准确定位，而不会把你甩在起点。如果该事件已超出你的数据保留窗口，页面会明确告知，而不是悄悄地什么都不选中。

## 在哪里找到它

每个仪表板页面都限定在你的组织范围内（`/<org-slug>/…`）。会话位于左侧边栏的 **Observe** 下，紧邻 Events，列表顶部提供日期范围、环境、智能体和会话筛选条件。每一行点击一次即可进入完整的执行图。

要开启分数徽章和分数区间筛选，请连接评估器，详见[评估](/zh/agenteye/evaluations)。
