即时发现模型、工具或 hook 变慢或产生费用，在用户感知之前捕获尾部延迟峰值。三个专属页面将原始计时数据转化为一目了然的 p50、p95 和 p99。

![Models 页面展示延迟热力图、百分位区间以及各模型的 token 数量、费用和上下文窗口占用情况](/agenteye/images/models.png)
*Models 页面：延迟热力图、百分位区间，以及各模型的 token 消耗、估算费用和上下文窗口占用率。*

## 别让平均值掩盖最糟糕的请求

平均延迟数字看起来令人安心，实则毫无意义：它掩盖了五十次调用中那一次会在凌晨两点触发告警的卡顿。Models、Tools 和 Hooks 页面拒绝这样做。三个页面共用同一套布局，学一次就能举一反三：

- **24 格迷你折线图**，一眼看出趋势：情况是否在恶化？
- **关键指标条**，包含 p50、p95 和 p99 延迟，典型请求与尾部请求并排呈现。
- **延迟热力图**，按 24 个时间格和延迟桶划分，直观展示慢请求集中在*何时*发生。
- **百分位区间**：以 p50 为中线，叠加 p25 到 p75 的阴影区间和 p10 到 p90 的浅色区间，并标注 p99 散点，让分布情况清晰可见，而非被平均值掩盖。

热力图与百分位区间共享悬停十字准线，尾部峰值在两张图上时间对齐，不再躲藏在单一均值线后面。所有三个页面均位于仪表盘的 **observe** 区域，可按日期范围、环境、Agent 和会话进行筛选，且均限定在您的组织范围内。

## Models：精确掌握每个模型的费用

Models 页面（如上图所示）直接回答账单总是引发的两个问题：用了哪个模型，花了多少钱。在共享延迟视图的基础上，它还新增了**各模型 token 消耗**、**估算费用**和**上下文窗口占用率**，让失控的 prompt 膨胀和即将触发的压缩在发生前就一览无余。

Failproof AI Observability 会自动识别常见的模型 ID。如果窗口数据看起来不对，或者您运行了自己的私有模型，可以在 **Settings** 的 **model context windows** 下进行修正或添加，占用率读数将随之更新。

## Tools：区分慢调用与失败调用

一次工具调用可能是慢，也可能是在静默失败，您需要在几秒内判断是哪种情况，而不是翻遍日志之后才知道。

![Tools 页面展示共享的延迟热力图和百分位区间，以及成功与失败分布和工具使用占比条形图](/agenteye/images/tools.png)
*Tools 页面：相同的热力图和百分位区间，加上成功与失败分布以及工具使用占比条形图。*

在共享延迟视图的基础上，Tools 页面新增了**成功与失败分布**和**工具使用占比条形图**，让您一眼看出哪些工具使用最频繁、哪些正在消耗您的错误预算。

## Hooks：精准定位具体的 hook 和触发事件

当某个生命周期 hook 拖慢了运行，"hook 很慢"这个结论根本没有可操作性。Hooks 页面帮您直接锁定问题所在。

![Hooks 页面在共享热力图和百分位区间之上，按 hook 名称和触发事件细分延迟数据](/agenteye/images/hooks.png)
*Hooks 页面：按 hook 名称和触发事件细分的延迟数据。*

在相同的延迟热力图和百分位区间之上，Hooks 页面按 **hook 名称**和**触发事件**细分活动数据，让您直接定位到需要关注的那一个 hook 和那一个事件。
