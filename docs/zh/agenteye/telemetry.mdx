即时发现模型、工具或 hook 的性能下降或费用飙升，在用户感知到尾延迟峰值之前将其捕获。三个专属页面将原始计时数据转化为一目了然的 p50、p95 和 p99 百分位数。

![Models 页面展示延迟热图、百分位带以及每个模型的 token 数量、费用和上下文窗口占用情况](/agenteye/images/models.png)
*Models 页面：延迟热图、百分位带，以及每个模型的 token 数量、预估费用和上下文窗口填充率。*

## 别让平均值掩盖最差的那次请求

平均延迟数字看起来令人安心，但实际上毫无意义：它掩盖了每五十次调用中那一次让你凌晨两点被叫醒的卡顿。Models、Tools 和 Hooks 页面拒绝这样做。三个页面结构相同，学会一个，其余全会：

- **24 格迷你图**，一眼看出趋势：情况是否在恶化？
- **关键指标条**，展示 p50、p95 和 p99 延迟，将典型请求与尾部请求并排呈现。
- **延迟热图**，按 24 个时间格和延迟区间划分，清晰显示慢请求*集中出现的时间段*。
- **百分位带**：以 p50 为中线，p25 到 p75 和 p10 到 p90 以阴影色带标注，p99 以点标记，让分布始终可见，而非被平均消除。

热图和百分位带共享悬停十字准线，使尾部峰值在两者之间时间对齐，而不是隐藏在单一均值线背后。在仪表盘的 **observe** 区域可找到这三个页面，均按组织划分作用域，支持按日期范围、环境、Agent 和会话进行筛选。

## Models：精确掌握每个模型的成本

Models 页面（见上图）回答了账单总会引发的两个问题：用的是哪个模型，花了多少钱。在共享延迟视图之上，它额外展示**每个模型的 token 消耗量**、**预估费用**和**上下文窗口填充率**，让 prompt 无控制增长和即将触发的压缩操作在发生之前就清晰可见。

Failproof AI Observability 会自动识别常见的模型 ID。如果某个窗口显示有误，或者你使用的是自己的私有模型，可在 **Settings** 的 **model context windows** 下进行修正或添加，填充率读数将随之更新。

## Tools：区分慢请求与失败请求

工具调用可能只是速度慢，也可能是悄悄地失败了——你希望在几秒内就能判断出是哪种情况，而不是翻遍日志之后才搞清楚。

![Tools 页面展示共享延迟热图和百分位带，以及成功/失败分布和工具使用占比条形图](/agenteye/images/tools.png)
*Tools 页面：相同的热图和百分位带，以及成功/失败分布和工具使用占比条形图。*

在共享延迟视图的基础上，Tools 页面新增了**成功/失败分布**和**工具使用占比条形图**，让你一眼看出哪些工具使用最频繁，哪些正在消耗你的错误预算。

## Hooks：定位具体的 hook 和触发事件

当某个生命周期 hook 拖慢了运行速度时，"hook 比较慢"这样的说法毫无可操作性。Hooks 页面帮你精确定位到具体那一个。

![Hooks 页面在共享热图和百分位带的基础上，按 hook 名称和触发事件对延迟进行细分](/agenteye/images/hooks.png)
*Hooks 页面：按 hook 名称和触发事件细分延迟数据。*

在相同的延迟热图和百分位带之上，Hooks 页面将活动按 **hook 名称**和**触发事件**进行细分，让你直接定位到需要关注的那一个 hook 和那一个事件。
