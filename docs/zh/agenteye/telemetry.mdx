即时发现模型、工具或 hook 出现性能下降或费用飙升，在用户感知到尾延迟峰值之前将其捕获。三个专属页面将原始耗时数据转化为一目了然的 p50、p95 和 p99 指标。

*Models 页面：延迟热力图、百分位带，以及各模型的 Token 用量、预估成本和上下文窗口填充情况。*

## 不再让平均值掩盖最差的表现

平均延迟数字看起来令人安心，实际上毫无意义：它会掩盖五十次调用中那一次卡住的请求——正是那次请求会在凌晨两点触发告警。Models、Tools 和 Hooks 页面拒绝这样做。三个页面共用相同的布局，学一次即可掌握全部：

- **24 格迷你折线图**，快速判断趋势：情况是否在恶化？
- **指标栏**，展示 p50、p95 和 p99 延迟，让典型耗时与尾部耗时并排呈现。
- **延迟热力图**，按 24 个时间格和延迟区间划分，直观显示慢请求集中在*何时*出现。
- **百分位带**：p50 中线搭配 p25 至 p75、p10 至 p90 的阴影区间，以及 p99 散点，让分布情况清晰可见，而非被平均值抹去。

热力图与百分位带共享悬停十字准线，尾部峰值可在两者之间对齐时间轴，而不会隐藏在单条均值线背后。在仪表盘的 **observe** 区域可找到这三个页面，均按组织划分范围，并可按日期范围、环境、Agent 和会话进行筛选。

## Models：精确掌握每个模型的成本

Models 页面（如上图所示）回答了账单始终会引发的两个问题：用的是哪个模型，花了多少钱。在共享延迟视图之上，它额外展示**各模型的 Token 消耗**、**预估成本**和**上下文窗口填充情况**，让失控的 Prompt 增长和即将到来的压缩操作在造成意外之前就能被察觉。

Failproof AI Observability 会自动识别常见的模型 ID。如果某个窗口显示有误，或者您运行的是自有私有模型，可在 **Settings** 的 **model context windows** 中进行修正或添加，填充数值将随之更新。

## Tools：区分慢请求与失败请求

工具调用可能是慢的，也可能是悄悄在失败，而您需要在几秒内判断是哪种情况，而不是翻遍日志才能发现。

![Tools 页面展示共享延迟热力图和百分位带，以及成功与失败分布和工具使用分布条形图](/agenteye/images/tools.png)
*Tools 页面：相同的热力图和百分位带，加上成功与失败分布图及工具使用分布条形图。*

在共享延迟视图之外，Tools 页面新增了**成功与失败分布**和**工具使用分布条形图**，让您一目了然地看出哪些工具被最频繁调用，哪些工具正在消耗您的错误预算。

## Hooks：定位具体的 hook 和触发事件

当某个生命周期 hook 拖慢了运行速度，"hooks 很慢"这样的结论无从下手。Hooks 页面帮您直接定位到问题所在。

![Hooks 页面在共享热力图和百分位带上方展示按 hook 名称和触发事件细分的延迟数据](/agenteye/images/hooks.png)
*Hooks 页面：按 hook 名称和触发事件细分的延迟数据。*

在相同的延迟热力图和百分位带之上，Hooks 页面将活动按 **hook 名称**和**触发事件**进行细分，让您直接定位到需要关注的单个 hook 和单个事件。
