告警用于监测某个可量化的条件，并在触发时创建事件。当某个故障需要及时响应时，无论策略是否能够拦截，都应使用告警。

## 创建并测试告警

<Tabs>
  <Tab title="控制台">
    1. 前往 **Analyze → Alerts**，选择 **new alert**。也可以从某条代表性错误的铃铛图标开始创建。
    2. 填写名称、严重级别、触发类型、条件、评估间隔、触发次数、时间窗口和通知渠道。
    3. 保存告警后，打开其详情页并运行 **test**。
    4. 前往 **Analyze → Issues**，对告警创建的事件执行确认、分配、讨论、订阅和解决操作。

    表单的第一部分用于标识告警及触发它的信号。

    ![新建告警表单的第一部分，包含名称、描述、启用状态和触发类型。](/images/dashboard/alert-new-trigger.png)

    第二部分用于控制条件需持续多长时间、评估频率以及通知发送位置。

    ![新建告警表单的第二部分，包含触发逻辑、计划、严重级别、投递渠道和创建操作。](/images/dashboard/alert-new-routing.png)

    保存后，使用告警列表确认规则已启用，并确认其触发条件、时间窗口、严重级别和渠道与预期一致。

    ![告警页面，展示告警规则及其触发条件、评估窗口、渠道和严重级别。](/images/dashboard/alerts.png)

    在将告警用于生产响应之前，请先进行测试。
  </Tab>
  <Tab title="CLI">
    ```bash
    fp alerts create high-errors \
      --trigger-kind metric_threshold \
      --severity warning \
      --trigger-spec '{"metric":"error_count","op":">","value":50,"window_secs":900}'

    fp alerts show high-errors
    fp alerts test high-errors
    fp alerts update high-errors --severity critical --yes
    ```

    使用 `fp alerts list` 查看规则，使用 `fp alerts delete <name>` 删除某条规则。

    完整的告警命令集请参阅 [`fp alerts` 参考文档](/zh/reference/cloud-cli#alerts)。
  </Tab>
</Tabs>

告警条件可以基于错误、评估分数、评估组合或自定义 SQL。添加接收人、测试规则，并打开生成的事件来执行确认、分配、评论、订阅和解决操作。

## 告警设计最佳实践

- 在名称中体现条件和受影响的工作流。
- 明确指定环境范围。
- 设置合理的时间窗口和阈值，避免对单个无害事件做出反应。
- 包含可引导响应人员定位会话的链接或查询。
- 在启用规则前指定负责人。

<Tip>
  在解决某个审计发现后，若同样的故障可能在策略覆盖范围之外再次发生，请添加相应的告警。
</Tip>
