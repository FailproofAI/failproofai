对于随着 Agent、提示词、工具和模型变化而可能反复出现的故障模式，请使用定期审计。

## 修改计划

<Tabs>
  <Tab title="控制台">
    1. 前往 **Analyze → Audits**，打开相应审计。
    2. 打开其设置，修改启用状态、间隔、UTC 锚点、窗口模式或回溯时长。
    3. 保存审计，并在审计卡片上确认下次运行时间。
    4. 在对范围或上下文进行重大变更后，使用 **立即运行** 手动执行一次。

    ![审计编辑器，显示频率、扫描窗口、范围、分析设置、上下文和通知渠道。](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    有关调度边界、窗口行为及所有审计命令，请参阅 [`fp audits` 参考文档](/zh/reference/cloud-cli#audits)。
  </Tab>
</Tabs>

根据风险的紧迫程度和成本选择合适的频率：

| 风险模式 | 建议起始频率 |
| --- | --- |
| 高影响生产操作 | 每日 |
| 工作流或模型回归 | 每周 |
| 合规或访问审查 | 每月 |
| 一次性发布调查 | 运行一次 |

将回溯窗口与频率对齐，确保每次运行既不留下空白，也不重复审查不必要的大量数据。在修改审计目标或上下文后，请先手动运行一次，再依赖下一次计划结果。

<Note>
  本地定期审计在机器上配置，并扫描本地 Agent 历史记录。云端审计计划则在 Cloud 会话上运行。请分开管理两者的结果和所有权。
</Note>
