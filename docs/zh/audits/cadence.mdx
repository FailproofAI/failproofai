随着 Agent、提示词、工具和模型的变化，某些故障模式可能会反复出现，请使用定期审计来持续追踪这些问题。

## 修改计划

<Tabs>
  <Tab title="控制台">
    1. 前往 **Analyze → Audits**，打开对应的审计。
    2. 进入设置，修改启用状态、间隔时间、UTC 锚点、窗口模式或回溯范围。
    3. 保存审计配置，并在审计卡片上确认下次运行时间。
    4. 在重大范围或上下文变更后，使用 **run now** 立即执行一次。

    ![审计编辑器，展示频率、扫描窗口、范围、分析设置、上下文及通知渠道。](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    有关计划时间范围、窗口行为及全部审计命令，请参阅 [`fp audits` 参考文档](/zh/reference/cloud-cli#audits)。
  </Tab>
</Tabs>

根据风险的紧迫程度和成本选择合适的频率：

| 风险类型 | 建议起始频率 |
| --- | --- |
| 高影响生产操作 | 每日 |
| 工作流或模型回归 | 每周 |
| 合规或访问权限审查 | 每月 |
| 一次性发布调查 | 单次运行 |

将回溯窗口与审计频率对齐，确保每次运行既不遗漏数据，也不重复检查不必要的大量历史记录。修改审计目标或上下文后，请先手动运行一次，再依赖后续的定时结果。

<Note>
  本地定期审计在本机配置，扫描本地 Agent 历史记录。云端审计计划在云会话上运行。请分别管理两者的结果与所有权。
</Note>
