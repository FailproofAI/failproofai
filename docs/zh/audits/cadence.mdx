对于随着 agent、提示词、工具和模型变化可能反复出现的故障模式，请使用定期审计。

## 修改计划

<Tabs>
  <Tab title="控制台">
    1. 前往 **Analyze → Audits**，打开相应审计。
    2. 打开其设置，修改启用状态、间隔、UTC 锚点、窗口模式或回溯时间。
    3. 保存审计，并在审计卡片上确认下次运行时间。
    4. 在重大范围或上下文变更后，手动执行一次 **run now**。

    ![审计编辑器，显示频率、扫描窗口、范围、分析设置、上下文和通知渠道。](/images/dashboard/audit-edit.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits edit checkout-reliability \
      --schedule-interval-secs 86400 \
      --schedule-anchor 2026-08-15T09:00:00Z \
      --lookback-window-secs 86400 \
      --yes

    fp audits edit checkout-reliability --disabled --yes
    fp audits edit checkout-reliability --enabled --yes
    ```

    请参阅 [`fp audits` 参考文档](/zh/reference/cloud-cli#audits)，了解计划边界、窗口行为及所有审计命令。
  </Tab>
</Tabs>

根据风险的紧迫性和成本选择频率：

| 风险类型 | 建议初始频率 |
| --- | --- |
| 高影响的生产操作 | 每日 |
| 工作流或模型回归 | 每周 |
| 合规或访问权限审查 | 每月 |
| 一次性发布调查 | 单次运行 |

回溯窗口应与频率保持一致，确保每次运行既不遗漏数据，也不重复审查不必要的大量历史记录。在修改审计目标或上下文后，请先手动运行一次，再依赖下次定期执行的结果。

<Note>
  本地定期审计在本机上配置，扫描本地 agent 历史记录；云端审计计划则基于云端会话运行。请将两者的结果和归属分开管理。
</Note>
