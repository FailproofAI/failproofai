在将机器接入 Failproof AI Cloud 之前，使用本地审计可以快速进行私密审查。它会扫描已存储在本机的 Agent 历史记录，通过内置策略重放工具活动，并打开本地结果仪表板。

## 运行交互式审计

<Tabs>
  <Tab title="仪表板">
    本地审计从 CLI 启动，因为它需要发现当前机器上的历史记录。运行 `failproofai audit`；扫描完成后，Failproof AI 会启动内置仪表板并打开 **http://localhost:8020/audit**。

    在审计视图中，查看会话数、工具调用数、项目数以及策略命中情况。建议先从高频发现入手，然后在启用强制执行之前检查受影响的项目和 Agent 历史记录。

    <Info>本地审计仪表板与 Failproof AI Cloud 中的**分析 → 审计**是独立的。本地审计数据保留在本机，无需账号或网络连接。</Info>
  </Tab>
  <Tab title="CLI">
    ```bash
    npm install -g failproofai
    failproofai audit
    ```

    该命令会对找到的所有受支持历史记录执行完整扫描。当前命令不支持 `--since`、`--cli`、`--project`、`--port` 或 `--no-open` 等过滤参数。

    使用本地仪表板期间请保持进程运行。完成后按 <kbd>Ctrl</kbd>+<kbd>C</kbd> 退出。
  </Tab>
</Tabs>

当前审计适配器可读取来自 Claude Code、Codex、GitHub Copilot CLI、Cursor、OpenCode、Pi、Hermes、OpenClaw、Factory、Devin、Antigravity 和 Goose 的历史记录。仅扫描本地可用的历史记录。

## 安排定期本地审计

<Tabs>
  <Tab title="仪表板">
    在本地仪表板中打开**设置**，启用定时审计，选择执行间隔，并设置接收发现结果的电子邮件地址。仪表板和 CLI 更新的是同一份机器配置。
  </Tab>
  <Tab title="CLI">
    启用每周审计并将发现结果发送至指定地址：

    ```bash
    failproofai audit --schedule 7 --email reliability@example.com
    failproofai audit --status
    ```

    间隔天数可设置为 1–90 天，省略时默认为 7 天。首次配置时会在需要时引导您登录；`--email` 可直接指定报告地址，无需交互提示。

    停止定时任务但保留本地审计历史记录：

    ```bash
    failproofai audit --no-schedule
    ```
  </Tab>
</Tabs>

守护进程在后台运行定时扫描，刷新本地仪表板使用的缓存结果，并发送已配置的报告邮件。如需立即运行交互式扫描，请使用 `failproofai audit`。

## 从本地证据迁移至 Cloud 运营

本地审计是快速建立基线的方式。当您需要共享追踪记录、周期性群体审计、发现与问题跟踪、告警、组织级策略部署或机群健康监控时，请将机器接入 Failproof AI Cloud。
