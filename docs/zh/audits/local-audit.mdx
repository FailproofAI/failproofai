本地审计读取已存储在本机上的 Agent 历史记录，并在 `http://localhost:8020/audit` 打开审计结果页面，无需账号即可使用。

```bash
failproofai audit
```

扫描范围涵盖所有已发现的受支持运行环境的历史记录。它会重放当前版本内置的 39 条策略目录；已安装的策略包和自定义策略不包含在内。

## 解读结果

从出现频率最高的发现开始，在启用强制执行之前先打开对应的会话进行核查。

有三点限制需要注意：

- 审计重建的是工具事件，而非 `Stop` 事件，因此 `require-*-before-stop` 策略不会出现在结果中。
- 八项"仅审计"检查用于识别资源浪费模式，但没有对应的精确匹配策略。
- `warn-repeated-tool-calls` 会被跳过，因为重放该策略会修改记录侧的状态。

对于可强制执行的发现项，请使用结果中显示的策略命令。在依赖强制执行之前，请先检查[运行环境的强制执行支持情况](/zh/reference/harnesses#enforcement-capability)。

缓存的审计结果存储在 `~/.failproofai/audit/dashboard.json`，有效期为七天。

## 定时扫描

```bash
failproofai audit --schedule 7
failproofai audit --status
failproofai audit --no-schedule
```

间隔时间接受 1 至 90 天，默认为 7 天。首次设置定时任务需要交互式登录。后台服务必须处于运行状态。

### 哪些数据会离开本机

交互式审计不会发送任何发现内容。匿名 CLI 遥测默认启用；可通过设置 `FAILPROOFAI_TELEMETRY_DISABLED=1` 来禁用。

启用定时扫描后，每次定时扫描会发送机器 ID、标签、平台及扫描时间窗口。若发现有害模式，还会发送一份包含计数、时间戳及最多三条脱敏示例的摘要。干净的扫描结果不会发送任何发现内容，也不会触发邮件通知。

<Warning>
  审计结果是供审查的参考依据，并不能证明每个被标记的操作都是不安全的。在将某项发现转化为阻断性强制措施之前，请先核查对应的会话记录。
</Warning>
