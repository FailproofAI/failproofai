审计会在选定的会话集合中搜索指定的故障目标，综合追踪证据、评估结果、策略命中记录和参考上下文，生成可付诸行动的发现结果。

## 打开审计

<Tabs>
  <Tab title="控制台">
    前往 **分析 → 审计**。页面显示计划状态、未处理发现、上次运行、下次运行、执行周期，以及审计是否包含摘要或参考页面。选择卡片可查看设置和运行历史；选择**新建审计**可创建审计。

    ![审计页面，显示定期审计的计划、敏感度和运行状态。](/images/dashboard/audits.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits list
    fp audits list --enabled-only --show-id
    fp audits show <audit-name>
    fp audits findings --status open --limit 20
    ```
  </Tab>
</Tabs>

当你需要回答以下类型的群体级问题时，可使用审计：

- 智能体在哪些环节放弃任务而未进行上报？
- 哪些工具故障导致了无效重试？
- 智能体是否访问了预期工作流之外的数据？
- 模型、提示词或工具发布后发生了哪些变化？

## 审计响应流程

```text
Session → Audit → Finding → Issue → Policy
                         ↘ Alert for recurrence
```

发现结果应指明故障模式并提供相应证据。问题（Issue）负责跟踪修复工作。策略（Policy）用于阻止已知的异常操作模式；当无法预防或需要持续监控时，告警（Alert）用于检测问题的再次发生。
