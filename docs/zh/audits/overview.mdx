## 本地审计与云端审计

| | 本地审计 | 云端审计 |
| --- | --- | --- |
| 命令 | `failproofai audit` | `fp audits` |
| 读取范围 | 本机上的 Agent 历史记录 | 云端组织中的会话 |
| 输出结果 | 本地结果，访问地址为 `localhost:8020/audit` | 共享的发现、问题和告警 |
| 所需条件 | 无需账号 | 需要云端连接和 API 密钥 |

如需快速审查单台机器，使用本地审计即可。如果团队需要跨 Agent 和多台机器进行定期审计，则使用云端审计。

## 审计可以回答的问题

- Agent 在哪些地方停止运行而未进行上报？
- 哪些工具失败导致了低效的重试？
- Agent 是否访问了预定工作流程之外的数据？
- 模型、提示词或工具更新后发生了哪些变化？

## 查看云端审计

进入 **分析 → 审计**，或使用以下命令：

```bash
fp audits list
fp audits show <audit-name>
fp audits findings --status open --limit 20
```

审计命令使用审计名称或完整 ID。发现结果通过其自身 ID 引用。

## 从发现到预防

```text
会话 → 审计 → 发现 → 问题 → 策略
                   ↘ 告警
```

发现结果指向具体证据，问题负责跟踪响应措施。策略用于防止已知的操作模式再次发生；告警则用于监控是否复现。

并非每条发现都需要转化为策略。`policy` 类发现描述的是可强制执行的规则；`failure` 或 `improvement` 类发现则可能需要对工作流程、提示词、模型或工具进行调整。
