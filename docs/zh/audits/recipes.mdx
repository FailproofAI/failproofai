---
title: "审计方案"
description: "常见 Agent 故障排查的起始目标。"
icon: "book-open-check"
---

将这些方案作为起始目标，然后添加您的 Agent、环境及预期工作流。

<Tabs>
  <Tab title="控制台">
    前往 **Analyze → Audits → New audit**，将某个方案复制到描述或简介中，然后添加相关环境、Agent、回溯时间范围和参考 URL。创建审计并在安排定时任务前先检查第一次运行结果。

    新审计表单通过添加范围、上下文、执行周期和通知，将方案转化为可执行的故障检查。

    ![配置了聚焦目标、计划、Agent 及环境范围、上下文和通知渠道的新审计表单。](/images/dashboard/audit-new.png)

    创建后，在依赖定期运行之前，请先确认审计以预期的状态和计划出现在列表中。

    ![审计页面，创建后显示特定工作流的审计方案。](/images/dashboard/audits.png)

    打开第一次运行结果，如果其发现结果比预期故障模式更宽泛或更狭窄，则对方案进行优化。
  </Tab>
  <Tab title="CLI">
    将方案保存为文本文件，并在创建时附加：

    ```bash
    fp audits create retry-loop-review \
      --scope '{"environments":["production"]}' \
      --text-file ./retry-loop-audit.txt \
      --schedule-interval-secs 86400
    ```
  </Tab>
</Tabs>

<AccordionGroup>
  <Accordion title="重复重试循环">
    找出 Agent 在未更改输入、未选择替代工具、也未上报给人工的情况下，重复执行相同失败工具调用的会话。
  </Accordion>
  <Accordion title="工具使用不当">
    找出所选工具与既定任务不匹配，或工具输入违反工作流所需前置条件的会话。
  </Accordion>
  <Accordion title="不安全的数据访问">
    找出在该 Agent 批准的路径和服务之外读取、写入或传输敏感数据的会话。
  </Accordion>
  <Accordion title="任务中止">
    找出未交付请求结果、未产生明确错误、也未明确移交给人工便结束的会话。
  </Accordion>
  <Accordion title="成本或延迟回归">
    找出模型、工具或总耗时超出预期预算的会话，并识别造成该问题的事件模式。
  </Accordion>
  <Accordion title="遗漏人工上报">
    找出因置信度不足、反复失败或策略指导要求人工决策，但 Agent 仍自主继续执行的会话。
  </Accordion>
</AccordionGroup>
