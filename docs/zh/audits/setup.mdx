审计的质量取决于其范围的界定。宽泛的请求（如"找出问题"）所产生的结果，远不如一个具体的故障问题来得有价值。

## 配置审计

<Tabs>
  <Tab title="控制台">
    1. 前往 **Analyze → Audits → New audit**，输入名称和描述。
    2. 设置执行频率、时间窗口、Agent/环境范围、忽略的错误、灵敏度以及最大发现数量。
    3. 在 **agents** 中，添加或查看 Agent 上下文，然后添加运营简报及相关公开 HTTPS 参考 URL。
    4. 选择通知渠道，点击 **create audit**。首次运行将立即加入队列。

    ![新建审计表单，包含名称、描述、执行频率、时间窗口、环境与 Agent 范围、忽略的错误、分析设置、简报、参考页面及通知渠道。](/images/dashboard/audit-new.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits create checkout-reliability \
      --description "Find checkout failures that agents do not recover from" \
      --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
      --schedule-interval-secs 86400 \
      --window-mode since_last \
      --sensitivity medium \
      --text-file ./checkout-audit-brief.txt \
      --url https://runbooks.example.com/checkout
    ```

    首次运行将立即加入队列。请在创建时一并提供简报和参考 URL，以便该次运行可以使用这些内容。

    查看完整的 [`fp audits create` 参考文档](/zh/reference/cloud-cli#audits)。
  </Tab>
</Tabs>

<Tip>
  建议从一个已知的失败会话和若干正常会话开始。这样可以为审计同时提供正向示例和对比集。
</Tip>

<Info>
  审计上下文作为独立资源存储，因此编辑审计不会意外删除参考材料。
</Info>
