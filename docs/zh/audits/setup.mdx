审计的质量取决于其范围。笼统的请求（如"查找问题"）产生的结果远不如具体的故障问题有用。

## 配置审计

<Tabs>
  <Tab title="控制台">
    1. 前往 **分析 → 审计 → 新建审计**，输入名称和描述。
    2. 设置节奏、时间窗口、Agent/环境范围、忽略的错误、敏感度和最大发现数。
    3. 在 **agents** 中，添加或查看 Agent 上下文，然后添加操作员简报和任意公开 HTTPS 参考 URL。
    4. 选择通知渠道，然后点击**创建审计**。第一次运行将立即进入队列。

    ![新审计表单，包含名称、描述、节奏、时间窗口、环境和 Agent 范围、忽略的错误、分析设置、简报、参考页面和通知渠道。](/images/dashboard/audit-new.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp audits create checkout-reliability \
      --description "Find checkout failures that agents do not recover from" \
      --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
      --schedule-interval-secs 86400 \
      --window-mode since_last \
      --sensitivity medium \
      --text-file ./checkout-audit-brief.txt \
      --url https://runbooks.example.com/checkout
    ```

    第一次运行将立即进入队列。请在创建时一并提供简报和参考 URL，以便该次运行能够使用它们。

    查看完整的 [`fp audits create` 参考文档](/zh/reference/cloud-cli#audits)。
  </Tab>
</Tabs>

<Tip>
  建议从一个已知的失败会话和若干正常会话开始。这样可以同时为审计提供正向示例和对比集。
</Tip>

<Info>
  审计上下文作为独立资源存储，因此编辑审计不会意外删除参考材料。
</Info>
