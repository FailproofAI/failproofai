failproofai 内置了 39 条策略，用于捕获常见的 Agent 失控模式。每条策略针对特定的 hook 事件类型和工具名称触发。其中 19 条策略支持参数配置，无需编写代码即可调整行为。5 条工作流策略在 Claude 停止之前强制执行提交 → 推送 → PR → CI 的流水线。

---

## 概述

策略按类别分组：

| 类别 | 策略 | Hook 类型 |
|----------|----------|-----------|
| [危险命令](#dangerous-commands) | block-sudo, block-rm-rf, block-curl-pipe-sh, block-failproofai-commands, block-self-pause | PreToolUse |
| [基础设施命令](#infra-commands) | block-kubectl, block-terraform, block-aws-cli, block-gcloud, block-az-cli, block-helm, block-gh-pipeline | PreToolUse |
| [密钥（脱敏器）](#secrets-sanitizers) | sanitize-jwt, sanitize-api-keys, sanitize-connection-strings, sanitize-private-key-content, sanitize-bearer-tokens | PostToolUse |
| [环境变量](#environment) | block-env-files, protect-env-vars | PreToolUse |
| [文件访问](#file-access) | block-read-outside-cwd, block-secrets-write | PreToolUse |
| [Git](#git) | block-push-master, block-work-on-main, block-force-push, warn-git-amend, warn-git-stash-drop, warn-all-files-staged | PreToolUse |
| [数据库](#database) | warn-destructive-sql, warn-schema-alteration | PreToolUse |
| [警告](#warnings) | warn-large-file-write, warn-package-publish, warn-background-process, warn-global-package-install | PreToolUse |
| [包管理器](#package-managers) | prefer-package-manager | PreToolUse |
| [工作流](#workflow) | require-commit-before-stop, require-push-before-stop, require-pr-before-stop, require-no-conflicts-before-stop, require-ci-green-before-stop | Stop |

- **`block-`** — 阻止 Agent 继续执行。
- **`warn-`** — 为 Agent 提供额外上下文，使其能够自我纠正。
- **`sanitize-`** — 在 Agent 看到工具输出之前，从中清除敏感数据。

### 命名空间

每条策略都位于 `<namespace>/<name>` 插槽中。内置策略属于 **`failproofai/`** 命名空间，例如 `failproofai/sanitize-jwt`。命名空间可防止与短名称相似的自定义或第三方策略发生冲突。

在配置中，您可以通过短名称或完全限定名称来引用内置策略，两种形式解析的是同一条策略：

```json
{
  "enabledPolicies": [
    "sanitize-jwt",
    "failproofai/block-rm-rf"
  ]
}
```

如果名称中不含 `/`，failproofai 会将其视为属于默认命名空间 `failproofai`。已包含 `/` 的名称（如 `myorg/foo`、`custom/my-hook`）将保持原样。
- **`require-`** — 阻止 Stop 事件，直到满足相应条件。

---

<Tip>
每条策略在 `policyParams` 中都支持可选的 `hint` 字段。该提示会附加到 Claude 看到的 deny 或 instruct 消息中，提供可操作的指导，而无需修改策略代码。适用于内置策略、自定义策略和约定策略。详见 [配置 → hint](/zh/configuration#hint-cross-cutting)。
</Tip>

## 危险命令

防止 Agent 执行难以撤销或可能损坏宿主系统的操作。

### `block-sudo`

**事件：** PreToolUse (Bash)
**默认行为：** 拒绝任何 `sudo` 或 `doas` 命令。

阻止**在命令位置**运行提权二进制文件的命令。匹配是结构化的而非文本式的：命令会像 shell 那样被拆分为片段，前置赋值（`FOO=bar`）、重定向以及带参数的运行器（`env`、`nohup`、`timeout`、`xargs`、`sh -c` 等）都会被剥离，最终将得到的二进制文件按**基本名**进行比较。因此 `/usr/bin/sudo`、`env sudo`、`timeout 5 sudo`、`"sudo"`、`\sudo` 和 `bash -c "sudo …"` 都会被拒绝，`doas` 也被视为具有相同能力但名称不同的命令。

由于锚定在命令位置而非该词在任意位置出现，以下命令**不会**触发此策略：`grep -r sudo /etc`、`cat /etc/sudoers`、`git commit -m "fix sudo handling"`，以及包含该词的 `grep` 交替模式均可正常运行。

<Warning>
这只能阻止显而易见的尝试，并不能封闭整个攻击面。能够运行任意 shell 的 Agent 仍然可以间接获得提权——通过变量（`S=sudo; $S …`）、base64 解码管道或磁盘上的包装脚本——因为对单个命令字符串的检查无法追踪这些路径。请将此视为防止误操作和随意提权的护栏，而非对抗蓄意 Agent 的安全边界。真正的安全边界必须在 shell 层以下强制执行。
</Warning>

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | 允许放行的精确命令前缀。每条记录与解析后的 argv token 进行匹配。 |

**示例：**

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    }
  }
}
```

使用此配置，`sudo systemctl status nginx` 被允许，但 `sudo rm /etc/hosts` 被拒绝。

<Note>
模式匹配的是解析后的 token，而非原始命令字符串。这可防止通过追加 shell 运算符来绕过（例如 `sudo systemctl status x; rm -rf /` 不会匹配 `sudo systemctl status *`）。
</Note>

**事件：** PreToolUse (Bash)
**默认行为：** 拒绝 `rm -rf`、`rm -fr` 及类似的递归删除形式。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|

**示例：**

```json
{
  "policyParams": {
    "block-rm-rf": {
      "allowPaths": ["/tmp", "/var/cache"]
    }
  }
}
```

**事件：** PreToolUse (Bash)
**默认行为：** 拒绝 `curl <url> | bash`、`curl <url> | sh`、`wget <url> | bash` 及类似模式。

无参数。

### `block-failproofai-commands`

**事件：** PreToolUse (Bash)
**默认行为：** 拒绝会卸载或禁用 failproofai 自身的命令（如 `npm uninstall failproofai`、`failproofai policies --uninstall`）。

无参数。

---

### `block-self-pause`

**事件：** PreToolUse (Bash)
**默认行为：** 拒绝 `failproofai config --pause`，该命令会在会话期间暂停策略执行。暂停应由人工决定——如果 Agent 能够运行该命令，就可以用一条命令关闭所有其他策略。

此策略有意设计得比 [`block-failproofai-commands`](#block-failproofai-commands) 更窄，且不包含在后者中：该策略锚定在命令边界，因此 `npx -y failproofai config --pause` 不会被其匹配；而且由于覆盖面广，该策略通常会被关闭以允许 Agent 运行 `failproofai audit`。`--resume` 和 `--status` 均被允许——两者都不会移除执行机制。

此策略阻止的是直接尝试，而非整个攻击类别：Agent 仍然可以通过别名或包装脚本达到相同状态。要彻底封闭，需要使暂停操作完全无法通过工具调用触达。

无参数。

## 基础设施命令

阻止编码 Agent 运行基础设施 CLI 或触发 CI/CD 流水线。本类别中的所有策略均为**按需启用**（`defaultEnabled: false`）——合法需要调用 `kubectl`、`terraform` 等命令的 Agent 不会受到干扰，除非您显式启用该策略。启用后，除非命令与 `allowPatterns` 中的某条记录匹配，否则所有匹配 CLI 的调用都会被拒绝。

模式语法与 [`block-sudo`](#block-sudo) 相同：token 与解析后的 argv 进行匹配，`*` 是单个 token 的通配符，任何包含独立 shell 运算符（`&&`、`||`、`|`、`;`）或含有内嵌 shell 元字符的 token 的命令，在进行白名单匹配之前都会被拒绝，以防止注入绕过。

### `block-kubectl`

**事件：** PreToolUse (Bash)
**默认行为：** 拒绝任何 `kubectl` 调用。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | 允许放行的 kubectl 命令前缀。 |

**示例：**

```json
{
  "policyParams": {
    "block-kubectl": {
      "allowPatterns": ["kubectl get *", "kubectl describe *", "kubectl logs *"]
    }
  }
}
```

使用此配置，`kubectl get pods` 被允许，但 `kubectl apply -f deploy.yaml` 被拒绝。

### `block-gh-pipeline`

**事件：** PreToolUse (Bash)
**默认行为：** 拒绝以下会改变状态或触发流水线的 `gh` CLI 子命令：

- `gh workflow run`、`gh workflow enable`、`gh workflow disable`
- `gh run rerun`、`gh run cancel`
- `gh pr merge`
- `gh release create`、`gh release delete`
- `gh cache delete`
- `gh secret set`、`gh secret delete`

只读的 `gh` 子命令（如 `gh pr view`、`gh pr list`、`gh run list`、`gh release view` 和 `gh api repos/.../...`）**不**在此策略的匹配范围内——这些命令是工作流检查的常规需求（包括 failproofai 自身的 `require-ci-green-before-stop`）。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | 即使会被默认拒绝，也允许放行的特定脚本调用。 |

**示例：**

```json
{
  "policyParams": {
    "block-gh-pipeline": {
      "allowPatterns": ["gh run rerun *"]
    }
  }
}
```

## 密钥（脱敏器）

防止 Agent 将凭据泄露到其上下文或输出中。脱敏器策略在 **PostToolUse** 事件上触发。当 Claude 运行 Bash 命令、读取文件或调用任何工具时，这些策略会在输出返回给 Claude 之前对其进行检查。如果检测到密钥模式，策略会返回拒绝决定，阻止输出被传回。

### `sanitize-jwt`

**事件：** PostToolUse（所有工具）
**默认行为：** 编辑 JWT token（由 `.` 分隔的三段 base64url 字符串）。

无参数。

---

### `sanitize-api-keys`

**事件：** PostToolUse（所有工具）
**默认行为：** 编辑常见的 API key 格式：Anthropic（`sk-ant-`）、OpenAI（`sk-`）、GitHub PAT（`ghp_`）、AWS 访问密钥（`AKIA`）、Stripe 密钥（`sk_live_`、`sk_test_`）以及 Google API key（`AIza`）。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `additionalPatterns` | `{ regex: string; label: string }[]` | `[]` | 需要视为密钥的额外正则表达式模式。 |

**示例：**

```json
{
  "policyParams": {
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo internal API key" },
        { "regex": "pat_[0-9a-f]{40}", "label": "Internal PAT" }
      ]
    }
  }
}
```

---

### `sanitize-connection-strings`

**事件：** PostToolUse（所有工具）
**默认行为：** 编辑包含内嵌凭据的数据库连接字符串（如 `postgresql://user:password@host/db`）。

无参数。

---

### `sanitize-private-key-content`

**事件：** PostToolUse（所有工具）
**默认行为：** 编辑 PEM 块（`-----BEGIN PRIVATE KEY-----`、`-----BEGIN RSA PRIVATE KEY-----` 等）。

无参数。

---

### `sanitize-bearer-tokens`

**事件：** PostToolUse（所有工具）
**默认行为：** 编辑 token 长度为 20 个或更多字符的 `Authorization: Bearer <token>` 请求头。

无参数。

## 环境变量

保护敏感的环境配置，防止 Agent 读取或暴露这些配置。

### `block-env-files`

**事件：** PreToolUse (Bash, Read)
**默认行为：** 拒绝通过 `cat .env`、以 `.env` 为文件路径的 Read 工具调用等方式读取 `.env` 文件。

不阻止 `.envrc` 或其他与环境相关的文件——仅阻止精确命名为 `.env` 的文件。

无参数。

---

### `protect-env-vars`

**事件：** PreToolUse (Bash)
**默认行为：** 拒绝打印环境变量的命令：`printenv`、`env`、`echo $VAR`。

无参数。

---

## 文件访问

使 Agent 在项目边界内工作，并远离敏感文件。

### `block-read-outside-cwd`

**事件：** PreToolUse (Read, Bash)
**默认行为：** 拒绝读取项目根目录以外的文件。边界由 `CLAUDE_PROJECT_DIR` 确定（由 Claude Code 在每个会话中设置一次），当该变量未设置时回退到会话的当前工作目录。使用项目根目录而非动态 `cwd` 意味着即使 Claude `cd` 进入子目录，边界也保持稳定。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `allowPaths` | `string[]` | `[]` | 即使在项目根目录之外也允许访问的绝对路径前缀。 |

**示例：**

```json
{
  "policyParams": {
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company/config"]
    }
  }
}
```

---

### `block-secrets-write`

**事件：** PreToolUse (Write, Edit)
**默认行为：** 拒绝写入通常用于私钥和证书的文件：`id_rsa`、`id_ed25519`、`*.key`、`*.pem`、`*.p12`、`*.pfx`。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `additionalPatterns` | `string[]` | `[]` | 需要阻止的额外文件名模式（glob 风格）。 |

**示例：**

```json
{
  "policyParams": {
    "block-secrets-write": {
      "additionalPatterns": [".token", ".secret"]
    }
  }
}
```

## Git

防止意外的推送、强制推送和难以撤销的分支误操作。

### `block-push-master`

**事件：** PreToolUse (Bash)
**默认行为：** 拒绝 `git push origin main` 和 `git push origin master`。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `protectedBranches` | `string[]` | `["main", "master"]` | 不允许直接推送的分支名称。 |

**示例：**

```json
{
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "master", "release", "prod"]
    }
  }
}
```

<Tip>
若要允许推送到所有分支（即在不从 `enabledPolicies` 中移除此策略的前提下将其禁用），可将 `protectedBranches` 设为 `[]`。
</Tip>

---

### `block-work-on-main`

**事件：** PreToolUse (Bash)
**默认行为：** 当工作树处于 `main` 或 `master` 分支时，拒绝 `git commit`、`git merge`、`git rebase` 和 `git cherry-pick`。创建分支和切换分支（`git checkout`、`git checkout -b`、`git switch`、`git switch -c`）不受影响。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `protectedBranches` | `string[]` | `["main", "master"]` | 在这些分支上禁止执行 commit/merge/rebase/cherry-pick 的分支名称。 |

---

### `block-force-push`

**事件：** PreToolUse (Bash)
**默认行为：** 拒绝 `git push --force` 和 `git push -f`。

无策略专属参数。可使用通用的 [`hint`](/zh/configuration#hint-cross-cutting) 来建议替代方案：

```json
{
  "policyParams": {
    "block-force-push": {
      "hint": "Create a new branch from your current HEAD (e.g. `git checkout -b <new-branch>`) and push that instead."
    }
  }
}
```

---

**事件：** PreToolUse (Bash)
**默认行为：** 在运行 `git commit --amend` 时指示 Claude 谨慎操作。不阻止该命令。

无参数。

**事件：** PreToolUse (Bash)
**默认行为：** 在运行 `git stash drop` 之前指示 Claude 进行确认。不阻止该命令。

无参数。

---

### `warn-all-files-staged`

**事件：** PreToolUse (Bash)
**默认行为：** 当 Claude 运行 `git add -A` 或 `git add .` 时，指示其检查正在暂存的内容。不阻止该命令。

无参数。

## 警告

在可能存在风险但非破坏性的操作之前，为 Agent 提供额外上下文。

### `warn-large-file-write`

**事件：** PreToolUse (Write)
**默认行为：** 在写入超过 1024 KB 的文件之前，指示 Claude 进行确认。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `thresholdKb` | `number` | `1024` | 触发警告的文件大小阈值（单位：KB）。 |

**示例：**

```json
{
  "policyParams": {
    "warn-large-file-write": {
      "thresholdKb": 256
    }
  }
}
```

<Note>
hook 处理器对 stdin 的负载大小限制为 1 MB。若要用较小内容测试此策略，请将 `thresholdKb` 设置为远低于 1024 的值。
</Note>

## 包管理器

强制规定 Agent 允许使用哪些包管理器。

### `prefer-package-manager`

**事件：** PreToolUse (Bash)
**默认行为：** 已禁用。启用后，将阻止不在 `allowed` 列表中的任何包管理器命令，并告知 Claude 改用允许的包管理器重写该命令。

可检测：pip、pip3、python -m pip、npm、npx、yarn、pnpm、pnpx、bun、bunx、uv、poetry、pipenv、conda、cargo。

| 参数 | 类型 | 默认值 | 描述 |
|-----------|------|---------|-------------|
| `allowed` | string[] | `[]` | 允许使用的包管理器名称。检测到的管理器若不在此列表中将被阻止。为空时，策略不执行任何操作。 |
| `blocked` | string[] | `[]` | 在内置列表之外额外需要阻止的管理器名称（如 `['pdm', 'pipx']`）。 |

内置阻止列表涵盖：pip、pip3、npm、npx、yarn、pnpm、pnpx、bun、bunx、uv、poetry、pipenv、conda、cargo。使用 `blocked` 可追加不在此列表中的管理器。

**示例配置：**

```json
{
  "enabledPolicies": ["prefer-package-manager"],
  "policyParams": {
    "prefer-package-manager": {
      "allowed": ["uv", "bun"],
      "blocked": ["pdm", "pipx"]
    }
  }
}
```

使用此配置，`pip install flask` 和 `pdm install flask` 都会被拒绝，并提示 Claude 改用 `uv` 或 `bun`。`uv pip install flask` 这类命令则被允许，因为 `uv` 在白名单中且优先检查。

## 工作流

强制执行规范的会话结束工作流。这些策略在 **Stop** 事件上触发，并阻止 Agent 停止，直到满足每个条件。它们遵循自然的依赖链：提交 → 推送 → PR → CI。如果某条策略拒绝，链中后续策略将被跳过（拒绝会短路后续检查）。

所有工作流策略都是**失败开放**的：如果所需工具不可用（如未安装 `gh`、无 git 远程仓库），策略允许通过并附带信息性消息说明检查被跳过的原因。

### 各 CLI 的 Stop 语义

Stop 执行在六种受支持的 CLI 中看起来略有不同，因为每种 CLI 暴露的"agent 已完成"hook 契约各不相同。**结果**是相同的——Agent 在工作流门控失败时无法停止——但**机制**有所差异。下表做了总结；只有 Pi 有一个用户可见的特性值得在启用 `require-*-before-stop` 策略之前了解。

| CLI | 门控触发时机 | 您看到的现象 |
|---|---|---|
| Claude Code | 同一 Agent 循环，立即触发 | Claude 继续工作——修复问题后再次尝试完成。您不会看到任何中断。 |
| Codex | 同一 Agent 循环，立即触发 | 与 Claude 相同。 |
| GitHub Copilot CLI | 同一 Agent 循环，立即触发 | 与 Claude 相同（使用 Copilot 的 `{decision:"block", reason}` 重试通道——已在 Copilot CLI 1.0.41 上通过实证验证）。 |
| Cursor Agent | 同一 Agent 循环，立即触发 | 与 Claude 相同（使用 Cursor 的 `{followup_message}` 通道——上限为 `loop_limit`，默认 5 次重试）。 |
| OpenCode | 同一 Agent 循环，立即触发 | 与 Claude 相同（使用 OpenCode 的 `client.session.prompt(...)` SDK 调用，通过 `hookSpecificOutput.additionalContext` 路由）。 |
| **Pi (pi-coding-agent)** | **下一个用户轮次** | **当门控触发时 Pi 会可见地停止**——其 Agent 循环退出，控制权返回到提示符。门控会在下次提交提示时触发：failproofai 会在该轮次的系统提示开头加入 `MANDATORY ACTION REQUIRED` 指令，指示 LLM 在执行您的请求之前完成工作流步骤（提交、推送等）。 |

<Note>
**Pi 的限制。** Pi 的 `AgentEndEvent`（上游等同于 Claude 的 Stop hook）没有 Result 类型——触发时，Pi 的 Agent 循环已经退出。Pi 无法像 Claude / Copilot / Cursor / OpenCode 那样被强制重试同一循环。failproofai 将门控转移到 Pi 的 `before_agent_start` 事件（在下一个用户提示后触发），以便工作流检查仍然生效，只是在下一轮而非当前轮次执行。

**实际影响：**

- Pi 停止后，拒绝原因会以 Pi 会话 ID 为键存储在内存中。您在同一 Pi 进程中提交的下一个提示会消耗它：LLM 在系统提示顶部看到 `MANDATORY ACTION REQUIRED` 指令，执行提交（或推送 / 创建 PR / 等待 CI），然后才继续处理您的请求。捕获的拒绝原因是一次性的——消耗后门控即清除。
- 门控受 Pi 进程生命周期约束。如果您在两次轮次之间按 `Ctrl+C` 退出 Pi，内存中的记录会随进程一起丢失，门控也就失效了。Claude、Copilot、Cursor 和 OpenCode 也有相同的约束（杀死 Agent 则门控失效）——只是 Pi 让这一点更加明显，因为 Agent 在门控触发之前就可见地退出了。
- 挂起的拒绝也会在任何原因（`new` / `resume` / `fork` / `quit`）导致的 `session_shutdown` 时被清除，因此先前会话中的过期门控不会泄漏到同一 Pi 进程中启动的新会话里。

如果您需要类似 Claude 的同循环重试，请在其他五种受支持的 CLI 之一下运行您的 Stop 策略。我们正在跟踪 Pi 上游，等待 `AgentEndEvent` 未来支持 Result 类型，届时可以弥补这一差距。
</Note>

### `require-commit-before-stop`

**默认行为：** 当存在未提交的更改（已修改、已暂存或未跟踪的文件）时，拒绝停止。当工作目录干净时，返回信息性消息。

### `require-pr-before-stop`

**事件：** Stop
**默认行为：** 当当前分支不存在 pull request，或现有 PR 已关闭且未合并时，拒绝停止。指示 Claude 使用 `gh pr create` 创建 PR。当 PR **已合并**时，策略允许通过（工作已发布），并提示切换离开该分支（`git checkout main && git pull`）。

<Note>

</Note>

### `require-no-conflicts-before-stop`

**事件：** Stop
**默认行为：** 当当前分支无法干净合并到基础分支时，拒绝停止。策略首先确认 GitHub 上该分支存在 `OPEN` 状态的 PR——若没有，则没有合并目标需要强制执行，整条策略短路为允许。确认存在 `OPEN` 状态的 PR 后，运行两个独立探测：

1. **本地** — `git merge-tree --write-tree --name-only origin/<baseBranch> HEAD`。发生冲突时，拒绝消息会列出冲突文件，以便 Claude 精确定位需要解决的内容。
2. **GitHub** — 复用预检中已获取的 `gh pr view --json mergeable,state` 结果。可捕获本地过期的 `origin/<baseBranch>` 会遗漏的冲突（例如自上次 fetch 以来有人将冲突 PR 合并到了 `main`）。`CONFLICTING` 结果会被拒绝。`UNKNOWN` 结果也会被拒绝，并指示 Claude 等待约 10 秒后重新检查再尝试停止——这可防止在 GitHub 重新计算期间出现假阴性。

在以下情况下完全跳过（允许通过）：未安装 `gh`、分支不存在 PR、PR 状态不是 `OPEN`（如 `MERGED`、`CLOSED`），或 `gh pr view` 返回无法解析的输出。当本地缺少 `origin/<baseBranch>` 或没有领先于基础分支的提交时，也会失败开放——这些第一层回退仍会在允许之前查询缓存的 PR 可合并性。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `baseBranch` | `string` | `"main"` | 用于冲突检查的基础分支。 |

<Note>
此策略需要 GitHub CLI（`gh`）。策略使用 `gh pr view` 确认存在 `OPEN` 状态的 PR 后才运行任何冲突探测——若没有 `gh`，策略短路为允许。运行 `gh auth login`，使用具有 `repo` 作用域以读取 pull request 的个人访问令牌。
</Note>

---

### `require-ci-green-before-stop`

**事件：** Stop
**默认行为：** 当当前分支的 CI 检查失败或仍在运行时，拒绝停止。同时检查 GitHub Actions 工作流运行和第三方 bot 检查（如 CodeRabbit、SonarCloud、Codecov）。将 `skipped`、`cancelled` 和 `neutral` 结论视为非失败状态（后者涵盖例如外部贡献者 PR 上 Socket Security 告警的情况，其中应用程序有意报告 neutral 而非 success/failure）。当所有检查通过时，返回信息性消息。

无参数。

<Note>
此策略需要安装并认证 [GitHub CLI](https://cli.github.com/)（`gh`）。
运行 `gh auth login`，使用具有 `repo` 作用域以读取 Actions 工作流运行和 Checks API 的个人访问令牌。若未安装或未认证 `gh`，策略失败开放并向 Claude 报告原因。
</Note>

## 禁用单条策略

从配置中的 `enabledPolicies` 移除指定策略，或在控制台的 Policies 标签页中将其关闭。

```json
{
  "enabledPolicies": [
    "block-rm-rf",
    "sanitize-api-keys"
  ]
}
```

未列入 `enabledPolicies` 的策略不会运行，即使存在对应的 `policyParams` 配置项也是如此。
