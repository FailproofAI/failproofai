failproofai 内置 39 条策略，用于捕获常见的智能体故障模式。每条策略在特定的钩子事件类型和工具名称上触发。其中 19 条策略支持参数配置，让你无需编写代码即可调整其行为。5 条工作流策略会在 Claude 停止之前强制执行 提交 → 推送 → PR → CI 的流水线。

---

## 概览

策略按类别分组：

| 类别 | 策略 | 钩子类型 |
|----------|----------|-----------|
| [危险命令](#dangerous-commands) | block-sudo, block-rm-rf, block-curl-pipe-sh, block-failproofai-commands, block-self-pause | PreToolUse |
| [基础设施命令](#infra-commands) | block-kubectl, block-terraform, block-aws-cli, block-gcloud, block-az-cli, block-helm, block-gh-pipeline | PreToolUse |
| [密钥（脱敏器）](#secrets-sanitizers) | sanitize-jwt, sanitize-api-keys, sanitize-connection-strings, sanitize-private-key-content, sanitize-bearer-tokens | PostToolUse |
| [环境变量](#environment) | block-env-files, protect-env-vars | PreToolUse |
| [文件访问](#file-access) | block-read-outside-cwd, block-secrets-write | PreToolUse |
| [Git](#git) | block-push-master, block-work-on-main, block-force-push, warn-git-amend, warn-git-stash-drop, warn-all-files-staged | PreToolUse |
| [数据库](#database) | warn-destructive-sql, warn-schema-alteration | PreToolUse |
| [警告](#warnings) | warn-large-file-write, warn-package-publish, warn-background-process, warn-global-package-install | PreToolUse |
| [包管理器](#package-managers) | prefer-package-manager | PreToolUse |
| [工作流](#workflow) | require-commit-before-stop, require-push-before-stop, require-pr-before-stop, require-no-conflicts-before-stop, require-ci-green-before-stop | Stop |

- **`block-`** — 阻止智能体继续执行。
- **`warn-`** — 向智能体提供额外上下文，以便其自我纠正。
- **`sanitize-`** — 在智能体看到工具输出之前，将其中的敏感数据抹除。

### 命名空间

每条策略都存在于一个 `<namespace>/<name>` 插槽中。内置策略属于 **`failproofai/`** 命名空间——例如 `failproofai/sanitize-jwt`。命名空间可以在你同时加载具有相似短名称的自定义或第三方策略时避免冲突。

在配置中，你可以通过短名称或完整限定名称来引用内置策略，两种形式均解析为同一策略：

```json
{
  "enabledPolicies": [
    "sanitize-jwt",
    "failproofai/block-rm-rf"
  ]
}
```

如果名称中不包含 `/`，failproofai 会将其视为属于默认命名空间 `failproofai`。已包含 `/` 的名称（例如 `myorg/foo`、`custom/my-hook`）将保持原样。
- **`require-`** — 阻止 Stop 事件，直到满足相应条件。

---

<Tip>
每条策略在 `policyParams` 中都支持可选的 `hint` 字段。该提示会附加到 Claude 看到的 deny 或 instruct 消息中，提供可操作的指导，而无需修改策略代码。适用于内置策略、自定义策略和约定策略。详见[配置 → hint](/zh/configuration#hint-cross-cutting)。
</Tip>

## 危险命令

防止智能体执行难以撤销或可能损害宿主系统的操作。

### `block-sudo`

**事件：** PreToolUse (Bash)  
**默认行为：** 拒绝任何 `sudo` 或 `doas` 命令。

阻止在**命令位置**运行提权二进制文件的命令。匹配是结构化的而非文本式的：命令会按 Shell 的方式分割成片段，前缀赋值（`FOO=bar`）、重定向以及带标志的运行器（`env`、`nohup`、`timeout`、`xargs`、`sh -c` 等）会被逐一剥离，最终将得到的二进制文件名与**basename** 进行比较。因此 `/usr/bin/sudo`、`env sudo`、`timeout 5 sudo`、`"sudo"`、`\sudo` 和 `bash -c "sudo …"` 均会被拒绝，`doas` 也被视为同等能力的不同名称。

由于锚定的是命令位置而非字符串中任意出现，**不会**对仅提及该词的命令触发——`grep -r sudo /etc`、`cat /etc/sudoers`、`git commit -m "fix sudo handling"` 或包含该词的 `grep` 模式均可正常运行。

<Warning>
这只能阻止明显的尝试，无法封堵所有路径。能够运行任意 Shell 的智能体仍可通过间接方式提权——通过变量（`S=sudo; $S …`）、base64 解码的管道，或磁盘上的封装脚本——因为对单个命令字符串的检查无法追踪这些路径。请将其视为防止误操作和随意提权的护栏，而非对抗蓄意智能体的安全边界。真正的安全边界必须在 Shell 层之下强制执行。
</Warning>

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | 允许执行的命令前缀。每条记录都与解析后的 argv 词元进行匹配。 |

**示例：**

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    }
  }
}
```

使用此配置，`sudo systemctl status nginx` 会被允许，但 `sudo rm /etc/hosts` 会被拒绝。

<Note>
模式匹配的是解析后的词元，而非原始命令字符串。这可防止通过附加 Shell 操作符绕过（例如 `sudo systemctl status x; rm -rf /` 不会匹配 `sudo systemctl status *`）。
</Note>

**事件：** PreToolUse (Bash)  
**默认行为：** 拒绝会卸载或禁用 failproofai 自身的命令（例如 `npm uninstall failproofai`、`failproofai policies --uninstall`）。

无参数。

---

### `block-self-pause`

**事件：** PreToolUse (Bash)  
**默认行为：** 拒绝 `failproofai config --pause`，该命令会暂停当前会话的策略执行。暂停应由人工决策——能够运行该命令的智能体可以通过一条命令关闭所有其他策略。

该策略有意比 [`block-failproofai-commands`](#block-failproofai-commands) 更窄，且不被其覆盖：该策略锚定在命令边界，因此 `npx -y failproofai config --pause` 不会匹配它；同时由于范围较宽，该策略常被关闭以允许智能体运行 `failproofai audit`。`--resume` 和 `--status` 是被允许的——两者均不会移除策略执行。

这只能阻止直接尝试，而非封堵整个路径：智能体仍可通过别名或封装脚本达到相同状态。要彻底封堵，需要让暂停操作在工具调用层面完全不可达。

无参数。

## 基础设施命令

阻止编码智能体运行基础设施 CLI 或触发 CI/CD 流水线。本类别的所有策略均为**按需启用**（`defaultEnabled: false`）——合理使用 `kubectl`、`terraform` 等工具的智能体不会受到干扰，除非你显式启用了该策略。启用后，除非命令匹配 `allowPatterns` 中的条目，否则对应 CLI 的每次调用都将被拒绝。

模式语法与 [`block-sudo`](#block-sudo) 相同：词元与解析后的 argv 进行匹配，`*` 是单个词元的通配符，任何包含独立 Shell 操作符（`&&`、`||`、`|`、`;`）或含有嵌入式 Shell 元字符词元的命令，都会在允许列表匹配之前被拒绝，以防止注入绕过。

### `block-kubectl`

**事件：** PreToolUse (Bash)  
**默认行为：** 拒绝任何 `kubectl` 调用。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | 允许执行的 kubectl 命令前缀。 |

**示例：**

```json
{
  "policyParams": {
    "block-kubectl": {
      "allowPatterns": ["kubectl get *", "kubectl describe *", "kubectl logs *"]
    }
  }
}
```

使用此配置，`kubectl get pods` 会被允许，但 `kubectl apply -f deploy.yaml` 会被拒绝。

### `block-gh-pipeline`

**事件：** PreToolUse (Bash)  
**默认行为：** 拒绝以下会改变状态或触发流水线的 `gh` CLI 子命令：

- `gh workflow run`、`gh workflow enable`、`gh workflow disable`
- `gh run rerun`、`gh run cancel`
- `gh pr merge`
- `gh release create`、`gh release delete`
- `gh cache delete`
- `gh secret set`、`gh secret delete`

只读的 `gh` 子命令，如 `gh pr view`、`gh pr list`、`gh run list`、`gh release view` 和 `gh api repos/.../...`，**不**会被此策略匹配——这些命令在工作流检查中（包括 failproofai 自身的 `require-ci-green-before-stop`）经常需要用到。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `allowPatterns` | `string[]` | `[]` | 即使会被默认拒绝，也允许执行的特定脚本化调用。 |

**示例：**

```json
{
  "policyParams": {
    "block-gh-pipeline": {
      "allowPatterns": ["gh run rerun *"]
    }
  }
}
```

## 密钥（脱敏器）

防止智能体将凭证泄露到其上下文或输出中。脱敏器策略在 **PostToolUse** 事件上触发。当 Claude 运行 Bash 命令、读取文件或调用任何工具时，这些策略会在输出返回给 Claude 之前对其进行检查。如果检测到密钥模式，策略会返回拒绝决策，阻止输出被传回。

### `sanitize-jwt`

**事件：** PostToolUse（所有工具）  
**默认行为：** 脱敏 JWT 令牌（三个以 `.` 分隔的 base64url 片段）。

无参数。

---

### `sanitize-api-keys`

**事件：** PostToolUse（所有工具）  
**默认行为：** 脱敏常见的 API 密钥格式：Anthropic（`sk-ant-`）、OpenAI（`sk-`）、GitHub PAT（`ghp_`）、AWS 访问密钥（`AKIA`）、Stripe 密钥（`sk_live_`、`sk_test_`）和 Google API 密钥（`AIza`）。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `additionalPatterns` | `{ regex: string; label: string }[]` | `[]` | 需额外视为密钥的正则表达式模式。 |

**示例：**

```json
{
  "policyParams": {
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo internal API key" },
        { "regex": "pat_[0-9a-f]{40}", "label": "Internal PAT" }
      ]
    }
  }
}
```

---

### `sanitize-connection-strings`

**事件：** PostToolUse（所有工具）  
**默认行为：** 脱敏包含嵌入凭证的数据库连接字符串（例如 `postgresql://user:password@host/db`）。

无参数。

---

### `sanitize-private-key-content`

**事件：** PostToolUse（所有工具）  
**默认行为：** 脱敏 PEM 块（`-----BEGIN PRIVATE KEY-----`、`-----BEGIN RSA PRIVATE KEY-----` 等）。

无参数。

---

### `sanitize-bearer-tokens`

**事件：** PostToolUse（所有工具）  
**默认行为：** 脱敏 `Authorization: Bearer <token>` 请求头中长度为 20 个或更多字符的令牌。

无参数。

## 环境变量

防止智能体读取或暴露敏感的环境配置。

### `block-env-files`

**事件：** PreToolUse (Bash, Read)  
**默认行为：** 拒绝通过 `cat .env`、将 `.env` 作为文件路径的 `Read` 工具调用等方式读取 `.env` 文件。

不会阻止 `.envrc` 或其他与环境相关的文件——仅阻止精确命名为 `.env` 的文件。

无参数。

---

### `protect-env-vars`

**事件：** PreToolUse (Bash)  
**默认行为：** 拒绝打印环境变量的命令：`printenv`、`env`、`echo $VAR`。

无参数。

---

## 文件访问

让智能体在项目边界内工作，远离敏感文件。

### `block-read-outside-cwd`

**事件：** PreToolUse (Read, Bash)  
**默认行为：** 拒绝读取项目根目录以外的文件。边界为 `CLAUDE_PROJECT_DIR`（由 Claude Code 在每次会话开始时设置一次），当该变量未设置时回退到会话的当前工作目录。使用项目根目录而非实时的 `cwd` 意味着即使 Claude `cd` 进入子目录后，边界仍然保持稳定。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `allowPaths` | `string[]` | `[]` | 即使在项目根目录之外也允许访问的绝对路径前缀。 |

**示例：**

```json
{
  "policyParams": {
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company/config"]
    }
  }
}
```

---

### `block-secrets-write`

**事件：** PreToolUse (Write, Edit)  
**默认行为：** 拒绝写入常用于私钥和证书的文件：`id_rsa`、`id_ed25519`、`*.key`、`*.pem`、`*.p12`、`*.pfx`。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `additionalPatterns` | `string[]` | `[]` | 额外需要阻止的文件名模式（glob 风格）。 |

**示例：**

```json
{
  "policyParams": {
    "block-secrets-write": {
      "additionalPatterns": [".token", ".secret"]
    }
  }
}
```

## Git

防止意外推送、强制推送以及难以撤销的分支误操作。

### `block-push-master`

**事件：** PreToolUse (Bash)  
**默认行为：** 拒绝 `git push origin main` 和 `git push origin master`。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `protectedBranches` | `string[]` | `["main", "master"]` | 不允许直接推送的分支名称。 |

**示例：**

```json
{
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "master", "release", "prod"]
    }
  }
}
```

<Tip>
如需允许推送到所有分支（即在不从 `enabledPolicies` 中移除该策略的情况下实际禁用它），请设置 `protectedBranches: []`。
</Tip>

---

### `block-work-on-main`

**事件：** PreToolUse (Bash)  
**默认行为：** 在工作树处于 `main` 或 `master` 分支时，拒绝 `git commit`、`git merge`、`git rebase` 和 `git cherry-pick`。创建和切换分支（`git checkout`、`git checkout -b`、`git switch`、`git switch -c`）不受影响。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `protectedBranches` | `string[]` | `["main", "master"]` | 在这些分支上禁止执行 commit/merge/rebase/cherry-pick 的分支名称。 |

---

### `block-force-push`

**事件：** PreToolUse (Bash)  
**默认行为：** 拒绝 `git push --force` 和 `git push -f`。

无策略专属参数。可使用跨切面的 [`hint`](/zh/configuration#hint-cross-cutting) 来建议替代方案：

```json
{
  "policyParams": {
    "block-force-push": {
      "hint": "Create a new branch from your current HEAD (e.g. `git checkout -b <new-branch>`) and push that instead."
    }
  }
}
```

---

### `warn-git-amend`

**事件：** PreToolUse (Bash)  
**默认行为：** 在运行 `git commit --amend` 时指示 Claude 谨慎操作。不会阻止该命令。

无参数。

---

### `warn-git-stash-drop`

**事件：** PreToolUse (Bash)  
**默认行为：** 在运行 `git stash drop` 之前指示 Claude 进行确认。不会阻止该命令。

无参数。

---

### `warn-all-files-staged`

**事件：** PreToolUse (Bash)  
**默认行为：** 在运行 `git add -A` 或 `git add .` 时指示 Claude 检查所暂存的内容。不会阻止该命令。

无参数。

## 警告

在执行潜在风险但非破坏性的操作前，向智能体提供额外上下文。

### `warn-large-file-write`

**事件：** PreToolUse (Write)  
**默认行为：** 在写入超过 1024 KB 的文件之前，指示 Claude 进行确认。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `thresholdKb` | `number` | `1024` | 触发警告的文件大小阈值（单位：KB）。 |

**示例：**

```json
{
  "policyParams": {
    "warn-large-file-write": {
      "thresholdKb": 256
    }
  }
}
```

<Note>
钩子处理程序对载荷的 stdin 输入限制为 1 MB。如需用较小内容测试此策略，请将 `thresholdKb` 设置为远低于 1024 的值。
</Note>

## 包管理器

强制规定智能体允许使用的包管理器。

### `prefer-package-manager`

**事件：** PreToolUse (Bash)  
**默认行为：** 禁用。启用后，阻止使用不在 `allowed` 列表中的任何包管理器命令，并告知 Claude 使用允许的管理器重写该命令。

可检测：pip, pip3, python -m pip, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo。

| 参数 | 类型 | 默认值 | 描述 |
|-----------|------|---------|-------------|
| `allowed` | string[] | `[]` | 允许使用的包管理器名称。检测到的管理器若不在此列表中则被阻止。为空时该策略为空操作。 |
| `blocked` | string[] | `[]` | 在内置列表之外额外需要阻止的管理器名称（例如 `['pdm', 'pipx']`）。 |

内置阻止列表涵盖：pip, pip3, npm, npx, yarn, pnpm, pnpx, bun, bunx, uv, poetry, pipenv, conda, cargo。使用 `blocked` 追加不在此列表中的管理器。

**配置示例：**

```json
{
  "enabledPolicies": ["prefer-package-manager"],
  "policyParams": {
    "prefer-package-manager": {
      "allowed": ["uv", "bun"],
      "blocked": ["pdm", "pipx"]
    }
  }
}
```

使用此配置，`pip install flask` 和 `pdm install flask` 均会被拒绝，并提示 Claude 改用 `uv` 或 `bun`。`uv pip install flask` 等命令是被允许的，因为 `uv` 在允许列表中且会优先检查。

## AI 行为

检测智能体卡住或行为异常的情况。

### `warn-repeated-tool-calls`

**事件：** PreToolUse（所有工具）  
**默认行为：** 当同一工具以相同参数被调用 3 次或以上时，指示 Claude 重新考虑——这是智能体陷入循环的常见迹象。

无参数。

## 工作流

强制执行规范的会话结束工作流。这些策略在 **Stop** 事件上触发，并阻止智能体在满足各项条件之前停止。它们遵循自然的依赖链：提交 → 推送 → PR → CI。如果某个策略拒绝，链中后续的策略将被跳过（拒绝会短路）。

所有工作流策略均为**故障开放**：如果所需工具不可用（例如未安装 `gh`、没有 git 远端），策略会放行并附上一条说明为何跳过检查的信息提示消息。

### 各 CLI 的 Stop 语义

Stop 策略执行在六种受支持的 CLI 之间的表现略有不同，因为每种 CLI 暴露的"智能体已完成"钩子协议各不相同。**结果**是相同的——智能体不能在工作流门控失败时逃过停止——但**机制**有所差异。下表概括了各 CLI 的情况；只有 Pi 有一个在你启用 `require-*-before-stop` 策略之前值得了解的用户可见特性。

| CLI | 门控触发时机 | 你看到的情况 |
|---|---|---|
| Claude Code | 同一智能体循环，立即触发 | Claude 继续工作——修复问题后再次尝试结束。对你无可见中断。 |
| Codex | 同一智能体循环，立即触发 | 与 Claude 相同。 |
| GitHub Copilot CLI | 同一智能体循环，立即触发 | 与 Claude 相同（使用 Copilot 的 `{decision:"block", reason}` 重试通道——已针对 Copilot CLI 1.0.41 实测验证）。 |
| Cursor Agent | 同一智能体循环，立即触发 | 与 Claude 相同（使用 Cursor 的 `{followup_message}` 通道——上限为 `loop_limit`，默认 5 次重试）。 |
| OpenCode | 同一智能体循环，立即触发 | 与 Claude 相同（使用 OpenCode 的 `client.session.prompt(...)` SDK 调用，通过 `hookSpecificOutput.additionalContext` 路由）。 |
| **Pi (pi-coding-agent)** | **下一个用户轮次** | **Pi 会在门控触发时可见地停止**——其智能体循环退出，你被返回到提示符。门控将在你下次提交提示时触发：failproofai 在该轮次的系统提示前面插入一条 `MANDATORY ACTION REQUIRED` 指令，指示 LLM 在执行你所要求的任务之前先完成工作流步骤（提交、推送等）。 |

<Note>
**Pi 的限制。** Pi 的 `AgentEndEvent`（上游等同于 Claude 的 `Stop` 钩子）没有 Result 类型——在其触发时，Pi 的智能体循环已经退出。Pi 无法像 Claude / Copilot / Cursor / OpenCode 那样被强制重试同一循环。failproofai 将门控转移到 Pi 的 `before_agent_start` 事件（在下一个用户提示后触发），使工作流检查仍然生效，只是在下一轮而非当前轮次执行。

**实际影响：**

- Pi 停止后，拒绝原因会以 Pi 会话 ID 为键存储在内存中。你在同一 Pi 进程中提交的下一条提示会消耗它：LLM 在系统提示顶部看到 `MANDATORY ACTION REQUIRED` 指令，先提交（或推送 / 创建 PR / 等待 CI），然后再继续处理你的请求。捕获的拒绝原因是一次性的——消耗后门控即清除。
- 门控受 Pi 进程生命周期的约束。如果你在两次轮次之间 `Ctrl+C` 退出 Pi 或关闭窗口，内存中的条目会随进程一起丢失，门控也会被错过。Claude、Copilot、Cursor 和 OpenCode 有同样的约束（关掉智能体则门控被错过）——Pi 只是因为智能体在门控触发前已可见地退出而让这一点更加明显。
- 待处理的拒绝也会在 `session_shutdown` 时（无论原因为 `new` / `resume` / `fork` / `quit`）被清除，因此来自先前会话的过期门控不会泄漏到同一 Pi 进程中启动的新会话里。

如果你需要类似 Claude 的同循环重试，请在其他五种受支持的 CLI 下运行你的 `Stop` 策略。我们正在跟踪 Pi 上游，期待未来 `AgentEndEvent` 支持 Result 类型，届时可以弥补这一差距。
</Note>

### `require-commit-before-stop`

**事件：** Stop  
**默认行为：** 当存在未提交的更改（已修改、已暂存或未跟踪的文件）时，拒绝停止。当工作目录干净时返回信息提示消息。

无参数。

---

### `require-push-before-stop`

**事件：** Stop  
**默认行为：** 当存在未推送的提交，或当前分支没有远端跟踪分支时，拒绝停止。必要时建议使用 `git push -u` 创建跟踪分支。如果未配置远端，则故障开放。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `remote` | `string` | `"origin"` | 推送目标的远端名称。 |

**示例：**

```json
{
  "policyParams": {
    "require-push-before-stop": {
      "remote": "upstream"
    }
  }
}
```

### `require-pr-before-stop`

**事件：** Stop  
**默认行为：** 当当前分支不存在拉取请求，或现有 PR 已关闭未合并时，拒绝停止。指示 Claude 使用 `gh pr create` 创建 PR。当 PR **已合并**时，策略放行（工作已交付），并提示切换离开该分支（`git checkout main && git pull`）。

无参数。

<Note>
此策略需要安装并完成身份验证的 [GitHub CLI](https://cli.github.com/)（`gh`）。
请使用具有 `repo` 范围的个人访问令牌运行 `gh auth login`，以获得对拉取请求的读取权限。如果 `gh` 未安装或未经身份验证，策略会故障开放并向 Claude 报告原因。
</Note>

---

### `require-no-conflicts-before-stop`

**事件：** Stop  
**默认行为：** 当当前分支无法与基础分支干净合并时，拒绝停止。策略首先确认该分支在 GitHub 上存在一个 `OPEN` 状态的 PR——若没有，则没有需要强制执行的合并目标，整个策略短路放行。确认存在 `OPEN` PR 后，运行两个独立的探测：

1. **本地探测** — `git merge-tree --write-tree --name-only origin/<baseBranch> HEAD`。发生冲突时，拒绝消息会列出冲突文件，让 Claude 清楚地知道需要解决哪些文件。
2. **GitHub 探测** — 复用已在预检中获取的 `gh pr view --json mergeable,state` 结果。可捕获过期的本地 `origin/<baseBranch>` 可能遗漏的冲突（例如自上次 fetch 以来有人在 `main` 上合并了一个冲突 PR）。`CONFLICTING` 结果会触发拒绝。`UNKNOWN` 结果也会触发拒绝，并指示 Claude 等待约 10 秒后再重新检查，然后再尝试停止——这可防止在 GitHub 重新计算期间出现假阴性。

以下情况下完全跳过（放行）：未安装 `gh`、该分支不存在 PR、PR 状态非 `OPEN`（例如 `MERGED`、`CLOSED`），或 `gh pr view` 返回无法解析的输出。当 `origin/<baseBranch>` 在本地不存在或当前分支相对基础分支没有领先提交时也故障开放——这些第一层回退仍会在放行前查询缓存的 PR 可合并性。

**参数：**

| 参数 | 类型 | 默认值 | 描述 |
|-------|------|---------|-------------|
| `baseBranch` | `string` | `"main"` | 用于检查冲突的基础分支。 |

<Note>
此策略需要 GitHub CLI（`gh`）。该策略使用 `gh pr view` 在运行任何冲突探测之前确认存在 `OPEN` PR——没有 `gh` 则策略短路放行。请使用具有 `repo` 范围的个人访问令牌运行 `gh auth login`，以获得对拉取请求的读取权限。
</Note>

---

### `require-ci-green-before-stop`

**事件：** Stop  
**默认行为：** 当当前分支的 CI 检查失败或仍在运行时，拒绝停止。同时检查 GitHub Actions 工作流运行和第三方机器人检查（例如 CodeRabbit、SonarCloud、Codecov）。将 `skipped`、`cancelled` 和 `neutral` 结论视为非失败状态（后者涵盖例如外部贡献者 PR 上 Socket Security 警告的情况，该应用会有意报告 neutral 而非 success/failure）。当所有检查通过时返回信息提示消息。

无参数。

<Note>
此策略需要安装并完成身份验证的 [GitHub CLI](https://cli.github.com/)（`gh`）。
请使用具有 `repo` 范围的个人访问令牌运行 `gh auth login`，以获得对 Actions 工作流运行和 Checks API 的读取权限。如果 `gh` 未安装或未经身份验证，策略会故障开放并向 Claude 报告原因。
</Note>

## 禁用单个策略

从配置的 `enabledPolicies` 中移除特定策略，或在控制台的"策略"标签页中将其关闭。

```json
{
  "enabledPolicies": [
    "block-rm-rf",
    "sanitize-api-keys"
  ]
}
```

未列在 `enabledPolicies` 中的策略不会运行，即使其 `policyParams` 条目存在也不例外。
