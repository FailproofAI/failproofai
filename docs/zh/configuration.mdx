failproofai 使用 JSON 配置文件来控制哪些策略处于激活状态、它们的行为方式以及自定义策略的加载路径。配置设计上便于与团队共享——将其提交到代码仓库，每位开发者都能获得相同的 Agent 安全防护。

---

## 配置作用域

共有三个配置作用域，按优先级顺序进行评估：

| 作用域 | 文件路径 | 用途 |
|-------|-----------|---------|
| **project** | `.failproofai/policies-config.json` | 单仓库设置，提交到版本控制 |
| **local** | `.failproofai/policies-config.local.json` | 个人单仓库覆盖项，已加入 gitignore |
| **global** | `~/.failproofai/policies-config.json` | 跨所有项目的用户级默认设置 |

当 failproofai 接收到钩子事件时，它会加载并合并当前工作目录下所有已存在的三个文件。

### 合并规则

**`enabledPolicies`** — 取三个作用域的并集。在任意级别启用的策略均处于激活状态。

```text
project:  ["block-sudo"]
local:    ["block-rm-rf"]
global:   ["block-sudo", "sanitize-api-keys"]

resolved: ["block-sudo", "block-rm-rf", "sanitize-api-keys"]  ← 去重后的并集
```

**`policyParams`** — 第一个为某策略定义参数的作用域完全优先。策略参数内部不进行深度合并。

```text
project:  block-sudo → { allowPatterns: ["sudo apt-get update"] }
global:   block-sudo → { allowPatterns: ["sudo systemctl status"] }

resolved: { allowPatterns: ["sudo apt-get update"] }   ← project 优先，global 被忽略
```

```text
project:  （无 block-sudo 条目）
local:    （无 block-sudo 条目）
global:   block-sudo → { allowPatterns: ["sudo systemctl status"] }

resolved: { allowPatterns: ["sudo systemctl status"] }  ← 回退到 global
```

**`customPoliciesPaths` / `customPoliciesPath`** — 第一个定义任意一种形式的作用域优先。

**`disabledCustomPolicies`** — 取所有作用域的并集。当你在控制面板中关闭来自显式或约定策略文件的某个单独策略时，控制面板会将带有来源限定的 ID 写入此处。未列出的策略默认保持启用状态；ID 包含来源文件信息，因此多个文件中同名策略可以独立控制。

**`llm`** — 第一个定义它的作用域优先。

## 配置文件格式

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-push-master",
    "sanitize-api-keys",
    "sanitize-jwt",
    "block-env-files",
    "block-read-outside-cwd"
  ],
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status", "sudo journalctl"]
    },
    "block-push-master": {
      "protectedBranches": ["main", "release", "prod"]
    },
    "block-rm-rf": {
      "allowPaths": ["/tmp"]
    },
    "block-read-outside-cwd": {
      "allowPaths": ["/shared/data", "/opt/company"]
    },
    "sanitize-api-keys": {
      "additionalPatterns": [
        { "regex": "myco_[A-Za-z0-9]{32}", "label": "MyCo API key" }
      ]
    },
    "warn-large-file-write": {
      "thresholdKb": 512
    }
  },
  "customPoliciesPath": "/home/alice/myproject/my-policies.js"
}
```

## 字段参考

### `enabledPolicies`

类型：`string[]`

要启用的策略名称列表。名称必须与 `failproofai policies` 显示的策略标识符完全匹配。完整列表请参见[内置策略](/zh/built-in-policies)。

未在 `enabledPolicies` 中列出的策略处于非激活状态，即使它们在 `policyParams` 中有条目也不例外。

### `policyParams`

类型：`Record<string, Record<string, unknown>>`

每个策略的参数覆盖项。外层键为策略名称，内层键为策略专属参数。每个策略的可用参数详见[内置策略](/zh/built-in-policies)。

如果某个策略有参数但你未指定，则使用该策略的内置默认值。未配置 `policyParams` 的用户与之前版本的行为完全一致。

策略参数块中的未知键在钩子触发时会被静默忽略，但在运行 `failproofai policies` 时会标记为警告。

#### `hint`（通用字段）

类型：`string`（可选）

当策略返回 `deny` 或 `instruct` 时，附加到原因中的消息。使用它可以在不修改策略本身的情况下为 Claude 提供可操作的指引。

适用于所有策略类型——内置策略、自定义策略（`custom/`）、项目约定策略（`.failproofai-project/`）或用户约定策略（`.failproofai-user/`）。

```json
{
  "policyParams": {
    "block-force-push": {
      "hint": "Try creating a fresh branch instead."
    },
    "block-sudo": {
      "allowPatterns": ["sudo apt-get"],
      "hint": "Use apt-get directly without sudo."
    },
    "custom/my-policy": {
      "hint": "Ask the user for approval first."
    }
  }
}
```

当 `block-force-push` 拒绝时，Claude 会看到：*"Force-pushing is blocked. Try creating a fresh branch instead."*

非字符串值和空字符串会被静默忽略。若未设置 `hint`，行为保持不变（向后兼容）。

### `customPoliciesPath`

类型：`string`（绝对路径）

包含自定义钩子策略的 JavaScript 文件路径。由 `failproofai policies --install --custom <path>` 自动设置（路径在存储前会被解析为绝对路径）。

每次钩子事件时都会重新加载该文件，不存在缓存。创作细节请参见[自定义策略](/zh/custom-policies)。

### 基于约定的策略

除了显式的 `customPoliciesPath` 之外，failproofai 还会自动发现并加载 `.failproofai/policies/` 目录中的策略文件：

| 级别 | 目录 | 作用域 |
|-------|-----------|-------|
| 项目 | `.failproofai/policies/` | 通过版本控制与团队共享 |
| 用户 | `~/.failproofai/policies/custom-policies/` | 个人专属，适用于所有项目 |

<Note>
  用户级目录在主目录重组时下移了一层。升级后首次运行任意 `failproofai`
  命令时，旧路径 `~/.failproofai/policies/` 下的文件会自动移入
  `custom-policies/` 目录，命令会告知你移动了哪些文件。
</Note>

**文件匹配规则：** 仅加载匹配 `*policies.{js,mjs,ts}` 的文件（例如 `security-policies.mjs`、`workflow-policies.js`）。目录中的其他文件会被忽略。

**无需配置：** 约定策略无需在 `policies-config.json` 中添加任何条目。只需将文件放入目录，下次钩子事件时即可自动加载。

**联合加载：** 项目级和用户级约定目录均会被扫描。两个级别的所有匹配文件都会被加载（与 `customPoliciesPath` 采用首个作用域优先不同）。

更多详情和示例请参见[自定义策略](/zh/custom-policies)。

### `llm`

类型：`object`（可选）

供执行 AI 调用的策略使用的 LLM 客户端配置。大多数情况下无需配置。

```json
{
  "llm": {
    "model": "claude-sonnet-4-6",
    "apiKey": "sk-ant-..."
  }
}
```

## 通过 CLI 管理配置

`policies --install` 和 `policies --uninstall` 命令会写入 Agent CLI 的钩子设置文件（钩子入口点），而 `policies-config.json` 则是你直接管理的文件。两者是独立的：

- **Agent CLI 设置** — 指示 Agent 在每次工具调用时执行 `failproofai --hook <event>`：
  - **Claude Code**：`~/.claude/settings.json`（用户级）、`<cwd>/.claude/settings.json`（项目级）、`<cwd>/.claude/settings.local.json`（本地级）
  - **OpenAI Codex**：`~/.codex/hooks.json`（用户级）、`<cwd>/.codex/hooks.json`（项目级）— Codex 没有 `local` 作用域
  - **GitHub Copilot CLI _(beta)_**：`~/.copilot/hooks/failproofai.json`（用户级）、`<cwd>/.github/hooks/failproofai.json`（项目级）— Copilot 没有 `local` 作用域。钩子条目使用 Copilot 的操作系统键控 `bash`/`powershell` 命令字段（含 `timeoutSec`）；文件顶层带有 `version: 1` 标记。Copilot CLI 支持目前为 **beta** 版，我们正在针对更多真实会话验证 `events.jsonl` 记录模式（公开文档未作说明）。**VS Code Copilot Chat Agent 模式（Preview）** 从 `.github/hooks/*.json`、`~/.copilot/hooks/*.json` 和 `~/.claude/settings.json` 读取钩子配置（由 `chat.hookFilesLocations` 设置控制），使用与 Claude 相同的 `{hookSpecificOutput:{permissionDecision:"deny",…}}` 协议——这些路径正好是 `copilot` 集成和 `claude` 集成（`~/.claude/settings.json`）已经写入的路径，因此 `failproofai policies --install --cli copilot`（或 `--cli claude`）**无需单独的 `vscode` 集成即可在 VS Code Agent 模式下生效**（已通过 VS Code 的发现日志确认）。
  - **Cursor Agent _(beta)_**：`~/.cursor/hooks.json`（用户级）、`<cwd>/.cursor/hooks.json`（项目级）— Cursor 没有 `local` 作用域。钩子条目使用 Claude 风格的 `{type, command, timeout}` 形式（无 `bash`/`powershell` 分割），但按 Cursor 的[钩子模式](https://cursor.com/docs/hooks)存储在平坦数组中，使用驼峰式事件键（`preToolUse`、`beforeSubmitPrompt` 等）；文件顶层带有 `version: 1` 标记。处理器通过 `CURSOR_EVENT_MAP` 将驼峰式转换为帕斯卡式，使现有内置策略无需修改即可触发。Cursor Agent 支持目前为 **beta** 版，我们正在针对更多真实安装验证 Cursor 的磁盘会话格式（公开文档未作说明）。
  - **OpenCode _(beta)_**：`~/.config/opencode/opencode.json` + `~/.config/opencode/plugins/failproofai.mjs`（用户级）、`<cwd>/.opencode/opencode.json` + `<cwd>/.opencode/plugins/failproofai.mjs`（项目级）— OpenCode 没有 `local` 作用域。与其他五个 CLI 不同，OpenCode **没有外部命令钩子系统**：它通过 `opencode.json` 中的 `plugin: []` 数组显式注册进程内 JS/TS 插件（`.opencode/plugins/` 的自动发现**不是** opencode v1.14.33 上的插件加载方式）。安装时会写入一个小型生成的插件垫片，该垫片以子进程方式调用 failproofai 二进制文件，并将二进制文件的 Claude 风格 JSON 响应转换为插件语义：工具事件拒绝时抛出 `throw new Error()`（取消工具调用），`instruct` 以及 `Stop`/`SubagentStop` 拒绝时调用 `client.session.prompt(...)`（将拒绝原因作为下一条用户消息提交——这是唯一的强制重试通道，因为 `session.idle` 仅用于通知且从中抛出异常无效），允许时为无操作。垫片在转发给二进制文件之前会规范化工具名称（小写→帕斯卡式，通过 `OPENCODE_TOOL_MAP`）和工具输入参数键（驼峰式→蛇形式，通过 `OPENCODE_TOOL_INPUT_MAP`，适用于 `Read`/`Write`/`Edit`，例如 `filePath`→`file_path`、`oldString`→`old_string`），因此 `block-read-outside-cwd`、`block-env-files` 和 `block-secrets-write` 等路径检查内置策略在 OpenCode 工具调用上无需修改即可触发。会话存储在 `~/.local/share/opencode/opencode.db` 的 opencode SQLite 数据库中；控制面板的会话查看器通过 `opencode db --format json` 和 `opencode export <id>` 读取它们。OpenCode 支持目前为 **beta** 版，我们正在跨版本验证行为并对照更多真实会话。详见 [OpenCode 插件文档](https://opencode.ai/docs/plugins/)。
  - **Pi _(beta)_**：`~/.pi/agent/settings.json`（用户级）、`<cwd>/.pi/settings.json`（项目级）— Pi 没有 `local` 作用域。Pi 在启动时加载 TypeScript 扩展包；设置文件是一个平坦的字符串数组 `{"packages": ["./relative/path", …]}`。failproofai 写入一个 packages 数组条目，指向其捆绑的 `pi-extension/` 目录。扩展内部订阅 Pi 的 `tool_call`/`user_bash`/`input`/`session_start` 事件，并通过 shell 调用 `failproofai --hook <Event> --cli pi`；处理器通过 `PI_EVENT_MAP` 将下划线小写蛇形式转换为帕斯卡式，使现有内置策略无需修改即可触发。工具输入参数也通过 `PI_TOOL_INPUT_MAP` 进行规范化（Pi 的 Read/Write/Edit 使用 `path` 而非 `file_path`；映射顶层键后 `block-env-files` 和 `block-secrets-write` 可以触发——`block-read-outside-cwd` 已有 `path` 回退）。Pi 支持目前为 **beta** 版，Pi 的扩展 API 和会话日志格式仍在稳定中。
  - **Hermes (hermes-agent)**：`~/.hermes/config.yaml`（**仅用户级作用域** — Hermes 没有项目/本地配置）。Hermes 是一个 Slack/Telegram **网关**，因此一次安装即可拦截来自所有平台（Slack/Telegram/cli/cron）**以及**内部子 Agent 的工具调用。钩子条目是 `{command, timeout}` 对（超时单位为**秒**），存储在 `hooks:` 映射下，以 Hermes 的蛇形式事件键（`pre_tool_call`/`post_tool_call`/`on_session_start`/`on_session_end`/`subagent_stop`）为键；处理器通过 `HERMES_EVENT_MAP` 规范化事件，通过 `HERMES_TOOL_MAP` 规范化工具名称，使内置策略无需修改即可触发。配置通过保留注释的 YAML `Document` 往返方式进行编辑，以保留运维人员的其他设置；安装时设置 `hooks_auto_accept: true`，使无头网关（无 TTY）无需同意提示即可运行钩子。评估器输出 Hermes 的 `{"decision":"block","reason"}` stdout 协议（Hermes 忽略退出码）。**限制：** Hermes 没有轮次结束的 `Stop` 事件，因此 `require-*-before-stop` 内置策略对其从不触发（不适用，非故障）；`instruct` 降级为允许并记录日志（无额外上下文通道）；输出密钥脱敏（`sanitize-*`）无法通过 shell 钩子协议重写工具输出。Hermes **同时也是**离线**审计**数据源——控制面板直接从 `~/.hermes/state.db` 读取其网关会话。
  - **OpenClaw (openclaw gateway)**：`~/.openclaw/openclaw.json`（**仅用户级作用域** — OpenClaw 没有项目/本地配置）。与 Hermes 类似，OpenClaw 是一个自托管的多通道**网关**，因此一次安装即可拦截来自所有通道及其内部子 Agent 的工具调用。执行通过 OpenClaw 的**进程内插件钩子**运行（其基于文件的内部钩子仅供观测，无法阻断），因此——与 OpenCode/Pi 类似——failproofai 提供一个静态的 `openclaw-plugin/` 包，该包异步启动 failproofai 二进制文件并转换裁决结果。安装时在 `openclaw.json` 的 `plugins.load.paths[]` 中注册已提供的插件目录，并在 `plugins.entries.failproofai` 下启用它（含 `hooks.allowConversationAccess: true`，原始对话钩子所必需）。评估器输出一个平坦的 `{permission, reason}` 裁决，垫片将其映射到每个钩子的原生返回形式：`before_tool_call → {block:true, blockReason}`（**PreToolUse**）、`before_agent_run → {outcome:"block", reason}`（**UserPromptSubmit**），以及 `before_agent_finalize → {action:"revise", reason}`（**Stop** — 这是真正的轮次结束门控，因此 `require-*-before-stop` 内置策略在 OpenClaw 上**生效**，与 Hermes 不同）。事件和工具名称在二进制端通过 `OPENCLAW_EVENT_MAP`/`OPENCLAW_TOOL_MAP`（`exec→Bash`、`read→Read` 等）进行规范化，使内置策略无需修改即可触发；垫片在任何启动/解析/超时错误时以开放方式失败。OpenClaw **同时也是**离线**审计**数据源——控制面板读取 `~/.openclaw/agents/<agentId>/sessions/<uuid>.jsonl` 处的 JSONL 会话。
  - **Factory Droid (`droid`)**：`~/.factory/hooks.json`（用户级）、`<cwd>/.factory/hooks.json`（项目级）— Factory 没有 `local` 作用域。droid 提供 Claude 风格的外部命令钩子系统，但经过 droid v0.171.0 现场验证，有两处特殊之处：(1) 事件名称位于 `hooks.json` 的**顶层**——**没有 `"hooks"` 包装器**（droid 会拒绝包装器）；工具事件（`PreToolUse`/`PostToolUse`）带有 `"matcher": "*"`，非工具事件则省略。(2) 拒绝由钩子**退出码 2 + stderr** 驱动，而非 JSON 决策——评估器的 `factory` 分支对工具/提示事件返回退出码 2，仅在轮次结束的 `Stop` 事件（droid 唯一的强制重试通道）上返回 `{decision:"block", reason}`。事件已为帕斯卡式（无需事件映射），有效载荷为 Claude 蛇形式；仅通过 `FACTORY_TOOL_MAP` 规范化工具名称（`Execute→Bash`、`Create→Write`、`FetchUrl→WebFetch` 等）。Factory **同时也是**离线**审计**数据源——控制面板读取 `~/.factory/sessions/<encoded-cwd>/<sessionId>.jsonl` 处的磁盘 JSONL 会话。
  - **Devin CLI (`devin`, Cognition)**：`~/.config/devin/config.json`（用户级）、`<cwd>/.devin/config.json`（项目级）— Devin 没有 `local` 作用域。经 devin v3000.1.27 现场验证，Devin 是一个**纯 Claude 克隆**：使用标准 Claude 的 `"hooks"` 包装器模式（写入时保留合并，使配置文件中的其他键——`org_id`、`theme_mode` 等——得以保留），已为帕斯卡式的事件名称（无需事件映射和处理器分支），以及 Claude 蛇形式的 stdin 有效载荷（无需规范化）。评估器的 `devin` 分支对**所有**事件在退出码 0 时通过 stdout 输出 `{"decision":"block","reason"}` JSON 进行拒绝（已验证——该阻断覆盖了 `--permission-mode dangerous`）；在轮次结束的 `Stop` 事件上，原因携带 MANDATORY-ACTION 强制重试措辞，使 `require-*-before-stop` 内置策略得以执行。仅通过 `DEVIN_TOOL_MAP` 规范化工具名称（`exec→Bash`；`tool_input.command` 已为规范形式）。Devin **同时也是**离线**审计**数据源——控制面板读取 `~/.local/share/devin/cli/sessions.db` 处的 SQLite 会话（每个 `sessions` 行包含真实的 `working_directory`，因此会话像 Claude 一样按项目工作目录分组）。
  - **Antigravity CLI (`agy`)**：`~/.gemini/config/hooks.json`（用户级）、`<cwd>/.agents/hooks.json`（项目级）— Antigravity 没有 `local` 作用域。与 Factory/Devin 不同，Antigravity 有其**自己**的协议（非 Claude 克隆），经 agy v1.1.2 现场验证。`hooks.json` 使用**命名钩子**模式：顶层键为钩子*名称*（`"failproofai"`），其值为事件→处理器映射——工具事件（`PreToolUse`/`PostToolUse`）将处理器包装在 `{matcher:"*", hooks:[…]}` 中，而 `PreInvocation`/`Stop` 则是**平坦**的处理器数组（其他命名钩子得以保留）。stdin 有效载荷为**驼峰式 protojson**（`toolCall:{name,args}`、`conversationId`、`workspacePaths`、`transcriptPath`）——failproofai 在策略运行前将其规范化为蛇形式，并通过 `ANTIGRAVITY_TOOL_INPUT_MAP` 映射 `run_command` 的帕斯卡式参数（`CommandLine`/`Cwd`）。评估器的 `antigravity` 分支使用 Antigravity **自己的**响应形式：`{decision:"deny", reason}` 阻断工具/提示（退出码 0），在轮次结束的 `Stop` 上使用 `{decision:"continue", reason}` 重新进入循环（使 `require-*-before-stop` 内置策略得以执行），以及 `{injectSteps:[{ephemeralMessage}]}` 在 `PreInvocation`（→`UserPromptSubmit`）上注入指令。工具名称通过 `ANTIGRAVITY_TOOL_MAP`（`run_command→Bash`、`view_file→Read` 等）进行规范化。Antigravity **同时也是**离线**审计**数据源——控制面板读取 `~/.gemini/antigravity-cli/brain/<conversationId>/.system_generated/logs/transcript_full.jsonl` 处的纯 JSONL 转录（对话索引在 `conversation_summaries.db` 中）。
  - **Goose (codename goose, Block)**：`~/.agents/plugins/failproofai/hooks/hooks.json`（用户级）、`<cwd>/.agents/plugins/failproofai/hooks/hooks.json`（项目级）— Goose 没有 `local` 作用域。执行使用 Goose 的**钩子**系统，即跨 Agent 的 **Open Plugins** 规范：安装程序只需放置 `failproofai` 插件目录，Goose 在启动时自动发现并将其自注册到 `~/.config/goose/config.yaml`。`hooks.json` 使用带有顶层 `"hooks"` 包装器的 Open Plugins 模式，且每个事件的匹配器均**省略**——裸 `"*"` 是一个匹配任何内容的无效正则表达式（经 goose v1.43.0 现场验证）。事件名称已为帕斯卡式（无需事件映射）；stdin 有效载荷使用 `event`/`working_dir`，处理器将其规范化为 `hook_event_name`/`cwd`。评估器的 `goose` 分支在退出码 0 时通过 stdout 输出 `{"decision":"block","reason"}` JSON 进行拒绝，仅在 **`PreToolUse`** 事件上生效（goose ≥ v1.37.0 中发布）——该事件对 shell 工具触发**且在委托的子 Agent 内部**也触发，因此是唯一充分的拒绝点；任何其他钩子错误以**开放**方式失败。Goose **没有 `Stop` 事件**，因此 `require-*-before-stop` 内置策略不适用（与 Hermes 相同）。工具名称通过 `GOOSE_TOOL_MAP`（`shell→Bash`、`write→Write`、`todo__todo_write→TodoWrite` 等）规范化，路径键通过 `GOOSE_TOOL_INPUT_MAP`（`path`/`source`→`file_path`）规范化。Goose **同时也是**离线**审计**数据源——控制面板读取 `~/.local/share/goose/sessions/sessions.db` 处的 SQLite 会话（每个 `sessions` 行包含真实的 `working_dir`，因此会话像 Devin 一样按项目工作目录分组；`--no-session` 临时运行会被过滤掉）。
- **`policies-config.json`** — 告知 failproofai 要评估哪些策略及其使用的参数（在所有 Agent CLI 间共享）

使用 `--cli claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose` 指定目标 Agent（以空格分隔或重复使用以指定任意子集）：

```bash
failproofai policies --install --cli codex --scope project
failproofai policies --install --cli copilot --scope project
failproofai policies --install --cli cursor --scope project
failproofai policies --install --cli opencode --scope project
failproofai policies --install --cli pi --scope project
failproofai policies --install --cli hermes --scope user
failproofai policies --install --cli openclaw --scope user
failproofai policies --install --cli factory --scope project
failproofai policies --install --cli devin --scope project
failproofai policies --install --cli antigravity --scope project
failproofai policies --install --cli goose --scope project
failproofai policies --install --cli claude codex copilot cursor opencode pi hermes openclaw factory devin antigravity goose
```

省略 `--cli` 时，`failproofai` 会检测已安装的 Agent CLI（`which claude` / `which codex` / `which copilot` / `which cursor-agent` / `which opencode` / `which pi` / `which hermes` / `which openclaw` / `which droid` / `which devin` / `which agy` / `which goose`）：

- **检测到一个 CLI** — 自动选择该 CLI，无需提示。
- **在交互终端中检测到多个 CLI** — 显示方向键单选提示，分为 `Detected (N)` 区域（含 `Install for all N detected` 汇总行以及每个已检测到的 CLI）和 `Not installed (M) · install hooks ahead of time` 区域（列出所有未检测到的支持 CLI 作为预安装选项；↑↓ 移动，Enter 选择，^C 退出）。卸载流程仅显示 Detected 区域。
- **在非交互运行（CI、无 TTY）中检测到多个 CLI** — 为所有检测到的 CLI 安装，无需提示。
- **未检测到任何 CLI** — 回退到 `claude`，并发出警告表示在 PATH 中未找到 Agent 二进制文件；钩子命令仍会被写入，待安装后即可激活。

你可以随时直接编辑 `policies-config.json`；更改会在下次钩子事件时立即生效，无需重启。

## 示例：包含团队默认值的项目级配置

将 `.failproofai/policies-config.json` 提交到代码仓库：

```json
{
  "enabledPolicies": [
    "block-sudo",
    "block-rm-rf",
    "block-push-master",
    "sanitize-api-keys",
    "block-env-files"
  ],
  "policyParams": {
    "block-push-master": {
      "protectedBranches": ["main", "release", "hotfix"]
    }
  }
}
```

每位开发者可以创建 `.failproofai/policies-config.local.json`（已加入 gitignore）进行个人覆盖，不会影响团队成员。
