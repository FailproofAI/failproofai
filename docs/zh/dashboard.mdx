failproofai 控制台是一个本地 Web 应用程序，用于监控 AI 智能代理会话并管理策略。查看代理在您离开期间执行了哪些操作。

---

## 启动控制台

```bash
failproofai
```

访问地址：`http://localhost:8020`。

控制台直接从文件系统读取本地项目、会话和 failproofai 配置数据。可选的已认证功能（如审计提醒和邀请）会将相关请求所需的信息（包括电子邮件地址）发送至远程 API。

## 页面

### 项目

列出您计算机上发现的所有 Claude Code、OpenAI Codex、GitHub Copilot CLI _(测试版)_、Cursor Agent _(测试版)_、OpenCode _(测试版)_、Pi _(测试版)_、Hermes、OpenClaw、Factory Droid、Devin、Antigravity 和 Goose 项目。Claude 项目从 `~/.claude/projects/`（或 `CLAUDE_PROJECTS_PATH` 指定的路径）发现；Codex 项目通过扫描 `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl` 下的所有记录并按每个会话首条记录中的 `cwd` 分组发现；Copilot CLI 项目通过扫描 `~/.copilot/session-state/<sessionId>/workspace.yaml`（可通过 `COPILOT_HOME` 配置）并按其 `cwd` 字段分组发现；Cursor Agent 项目通过扫描 `~/.cursor/agent-sessions/<sessionId>/`（可通过 `CURSOR_HOME` 配置，并以 `conversations/` 和 `sessions/` 作为备用路径）下各会话元数据中 `meta.json` / `session.json` / `workspace.yaml` 里的 `cwd` 标量发现；OpenCode 项目通过 `opencode db --format json` 查询位于 `~/.local/share/opencode/opencode.db` 的 SQLite 数据库发现（读取 `session` 和 `project` 表并按 `project_id` 分组）；Pi 项目通过扫描 `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl`（可通过 `PI_SESSIONS_DIR` 配置）下各会话的 JSONL 记录并从每个会话的首条记录中提取 `cwd` 发现；Hermes 网关会话直接从每个配置文件的 SQLite 存储（`~/.hermes/state.db` 及 `~/.hermes/profiles/<name>/state.db`，可通过 `HERMES_HOME` 或 `HERMES_DB_PATH` 覆盖）读取，并按配置文件和 `source`（Slack/Telegram/cli/cron——网关会话无 cwd）分组为 `hermes-<profile>-<source>` 项目；OpenClaw 网关会话从 `~/.openclaw/agents/<agentId>/sessions/*.jsonl` 读取，并按代理和频道分组为 `openclaw-<agentId>-<channel>` 项目（同样无 cwd）；Factory Droid 项目从 `~/.factory/sessions/<encoded-cwd>/*.jsonl` 的 JSONL 记录中发现并按 cwd 分组；Devin 项目从其位于 `~/.local/share/devin/cli/sessions.db` 的 SQLite 数据库发现（按每个会话的 `working_directory` 分组）；Antigravity 项目从 `~/.gemini/antigravity-cli/brain/<conversationId>/…/transcript_full.jsonl` 的 JSONL 记录中发现并按 cwd 分组；Goose 项目从其位于 `~/.local/share/goose/sessions/sessions.db` 的 SQLite 数据库发现（按每个会话的 `working_dir` 分组）。被多个 CLI 使用的项目将渲染为带有所有匹配徽章的单行。使用表格上方的 **CLI** 下拉菜单按特定代理 CLI 过滤；URL 会以 `?cli=claude|codex|copilot|cursor|opencode|pi|hermes|openclaw|factory|devin|antigravity|goose` 的形式保留您的选择。

Hermes 和 OpenClaw 是用户级别的，没有可分组的工作目录，因此渲染为**可折叠文件夹树**——配置文件（或代理）在顶层，其频道在下方——而所有基于 cwd 的 CLI 保持扁平行形式。文件夹行汇总其下所有内容的会话数和最新活动时间，折叠状态在访问之间保留，关键词搜索会展开匹配项。

每个项目显示：
- 项目名称（从文件夹路径派生）
- CLI 徽章——`Claude Code`（橙色）、`OpenAI Codex`（紫色）、`GitHub Copilot`（蓝色）、`Cursor Agent`（翠绿色）、`OpenCode`（琥珀色）、`Pi`（粉色）和/或 `Hermes`（靛蓝色）
- 最近一次会话活动的日期

点击项目可查看其会话。

### 会话

列出项目中的所有会话。每个会话显示：
- 会话 ID
- 开始和结束时间戳
- 工具调用次数
- Hook 活动次数（已触发的策略数）

使用日期范围过滤器和会话 ID 搜索来缩小列表范围。会话支持分页。

点击会话可打开会话查看器。

### 会话查看器

会话查看器回答了自主代理的关键问题：代理做了什么，是否保持在正确轨道上？标题旁的 CLI 徽章指示会话是 Claude Code、OpenAI Codex、GitHub Copilot CLI、Cursor Agent、OpenCode、Pi、Hermes、OpenClaw、Factory Droid、Devin、Antigravity 还是 Goose 的记录。它显示会话中发生的所有事件时间线：

- **消息** - Claude 的文本回复和用户提示
- **工具调用** - Claude 调用的每个工具，包含其输入和输出
- **策略活动** - 对于每次工具调用，哪些策略触发了以及返回了什么决策

顶部的统计栏显示会话时长、总工具调用次数以及 Hook 决策摘要（allow / deny / instruct 计数）。

点击**下载日志**按钮可导出会话。对于 Claude Code、Codex、Copilot、Cursor 和 Pi 会话，您将获得磁盘上原始的 JSONL 记录（逐字节）；对于 OpenCode（其会话存储在 SQLite 中而非磁盘上），您将获得一个镜像底层 `session` / `messages` / `parts` 表的 JSON 文档。

### 审计

一份个性化报告，展示您的代理在过去会话中的实际行为。运行与 `failproofai audit` CLI 相同的扫描，并将结果渲染为单屏可分享的海报加四个折叠下方的章节：

1. **海报** — 填满第一个视口。自包含的 PNG 截图区域，包含 failproof_ai 徽标 + 审计标签·原型索引（`№ NN of 08`）+ 审计日期·数字评分（0–100）+ 百分位排名标签（`top 15%`）·原型名称（`the optimist`、`the cowboy`、`the explorer`、`the goldfish`、`the paranoid architect`、`the precision builder`、`the hammer`、`the ghost` 之一）+ 3 个关键词条带·`// only N% of agents are this archetype` 稀有度说明·8×8 像素印记图案·`audit yours → failproof.ai` 页脚。截图框外紧贴三个分享按钮：`post your archetype`（X 意图）、`share on linkedin`、`download poster`。截图通过 `html-to-image` 执行，PNG 与屏幕渲染像素级一致（虚线边框、SVG 标志遮罩、渐变、字体度量——全部保留）。
2. **优势** — 以平静 ✓ 行列表的形式列出代理已做对的行为，来源于实时审计数据（工具调用清洁率、无直接推送至主分支、零凭证泄露、零重试风暴）——仅在相关策略在审计窗口内记录清洁时才显示。
3. **不足** — 按严重程度排序的问题列表：`时间 · 遗漏问题 + 本应捕获它的策略 · 严重程度标签 · 出现次数`，其中出现次数显示为 `new`（一次）、`N× seen`（2–9 次）或 `recurring`（10 次以上）。
4. **改进建议** — 平静的行列表，每项对应一个建议策略：白色策略名称、单行描述、右侧安装命令 + 复制按钮。章节标题显示 `enable all N → projected <score> · <tier>`（应用所有修复后可达到的评分），其 `[install all]` 按钮可复制包含所有建议策略的 `failproofai policy add a b c …` 组合命令。
5. **更好地回来** — 两张并排卡片。左侧：设置提醒（`3d` / `7d` / `14d` / `30d` 周期选择器；认证后通过 `/api/auth/reminder` 持久化）。右侧：解锁 failproof 特权——`invite a friend` 打开一个模态框，接受逗号/空格/换行分隔的好友电子邮件列表（每次最多 10 个），通过 POST 提交到 `/api/audit/invite`，再转发至 api-server 的 `POST /v0/invite`。api-server 从 `invite@failproof.ai` 向每位收件人发送一封邮件，发件人被抄送并设置 `Reply-To`，收件人可看到邀请者身份，发件人也会在收件箱收到副本。匿名用户会先通过 `AuthDialog` 流程以确认发件人邮箱，然后再发出邀请。权益/特权履行为后续功能。

由 `failproofai audit` 运行时驱动——有关底层扫描引擎、支持的标志和每个记录的缓存不变量，请参阅 [Audit CLI](/zh/cli/audit)。控制台将最新结果缓存在 `~/.failproofai/audit-dashboard.json`（模式 `0600`，单槽位，新运行覆盖旧结果），以便重新访问时即时加载；**一旦超过 7 天，每条记录缓存和整体结果缓存在读取时均会被拒绝**，因此控制台不会悄无声息地提供超过一周的陈旧结果——超过 TTL 后，`/audit` 会回落到空状态并提示重新运行。点击报告底部附近的 `[ re-audit now ]` 会以 `noCache: true` 向 `/api/audit/run` 发送 POST 请求——重新审计会绕过每条记录的缓存并从头重新扫描所有记录，而非静默返回缓存结果——控制台以 1Hz 的频率轮询 `/api/audit/status` 直到运行完成；运行期间，一条粉色进度条固定在视口顶部并显示已用时间，运行成功后新结果就地替换（无需整页刷新；重新审计失败时保留原有报告）。失败时进度条变红，并根据 `RerunError.kind`（`timeout` / `network` / `post_failed`）显示对应文案。空状态（无缓存或已过期）和零会话状态（缓存存在但扫描未找到任何记录）分别单独呈现。

## 自动刷新

控制台顶部导航栏中有一个自动刷新开关。启用后，当前页面会定期刷新，以显示新出现的会话和策略活动。对于监控长时间运行的自主代理会话至关重要。

## 禁用页面

如果您只需要控制台的某些部分，可将 `FAILPROOFAI_DISABLE_PAGES` 设置为以逗号分隔的页面名称列表：

```bash
FAILPROOFAI_DISABLE_PAGES=policies failproofai
```

有效值：`policies`、`projects`、`audit`。

---

## 配置项目路径

默认情况下，控制台从标准的 Claude Code 项目目录读取数据。可为自定义设置覆盖该路径：

```bash
CLAUDE_PROJECTS_PATH=/custom/path/to/projects failproofai
```

## 从非 localhost 主机访问

在**开发模式**（`npm run dev`）下运行控制台，并从 localhost 以外的主机名访问时（例如自定义域名、远程 IP 或隧道 URL），您可能会看到如下警告：

```text
⚠ Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from "dashboard.example.com".
```

这是 Next.js 阻止对其 HMR（热模块重载）WebSocket 的跨域访问——这是一个仅限开发模式的功能。要允许您的主机，请使用 `--allowed-origins` 标志：

```bash
npm run dev -- --allowed-origins dashboard.example.com
```

对于多个主机或 IP，传入逗号分隔的列表：

```bash
npm run dev -- --allowed-origins dashboard.example.com,192.168.1.5
```

也可以设置 `FAILPROOFAI_ALLOWED_DEV_ORIGINS` 环境变量：

```bash
FAILPROOFAI_ALLOWED_DEV_ORIGINS=dashboard.example.com npm run dev
```

<Note>
这仅适用于开发模式。在运行 `failproofai`（生产模式）时，不存在 HMR WebSocket，也不存在跨域开发资源问题。
</Note>
