托管的 Python 评估可以计数和比较：工具调用次数、错误数量、会话时长。但它无法判断答案是否*正确*、回复是否粗鲁，或者智能体在行动之前是否检查了策略。

**LLM 裁判**可以做到这些。你用自然语言描述什么是优质表现，模型读取会话后返回一个 0 到 1 的分数，并附上推理说明。

<Note>
每次运行裁判都会消耗一次模型调用，而代码评估则不需要任何成本。只在需要*理解*对话才能回答的问题上使用裁判——并为其设置条件，使其仅在相关会话上运行。
</Note>

## 我应该选哪种？

| 问题 | 使用方式 |
| --- | --- |
| 它是否调用了同一个工具两次？ | 代码 |
| 有多少个错误？ | 代码 |
| 会话是否在 30 秒内完成？ | 代码 |
| 客户是否表达了紧迫感？ | [分类器](/zh/evaluations/jev) |
| 客户有多沮丧？ | [分类器](/zh/evaluations/jev) |
| 答案是否真正正确？ | **裁判** |
| 回复是否粗鲁或敷衍？ | **裁判** |
| 它在承诺退款之前是否检查了退款政策？ | **裁判** |

经验法则：**可计数的 → 代码，可提前列举答案的 → [分类器](/zh/evaluations/jev)，需要解释说明的 → 裁判。** 裁判是唯一会用文字描述其所见的评估方式；当一个数字会让人追问"为什么？"时，就选用它。

你不必事先做出决定。描述你想衡量的内容，助手会自动选择，并告诉你它选择了哪种方式以及原因。你随时可以切换。

## 创建一个裁判

1. 进入 **Analyze → eval authoring**，选择 **new eval**。
2. 描述你想评判的内容，然后选择 **draft**。
3. 检查**标准**、**阈值**和**条件**，然后部署。

### 标准

用一两句话，以要求而非问题的形式表述：

> 助手在未先检查退款政策的情况下，不得承诺或批准退款。

具体说明什么情况会导致*失败*。"回复是否良好？"这类表述给出的数字毫无意义；而上面的句子给出的结果才是可以付诸行动的。

### 阈值

会话通过所需达到的最低分数。`0.7` 是一个合理的起点。完整的 0 到 1 分数始终会被记录，因此阈值只决定通过/失败——你可以查看分布情况并进行调整。

### 条件

与其他任何评估相同的 Python 条件，但在这里它的重要性远超其他。如果不设置条件，裁判将对你组织中的**每一个**会话运行，每次都消耗一次模型调用：

```python
session.count("tool_use") > 0
```

```python
session.agent_id == "support-bot" and session.count("error") > 0
```

如果你部署了一个没有条件的裁判，仪表板会向你发出警告。有时这是合理的——比如一个流量较低、你希望对其进行全面评判的智能体——但这应该是有意识的决策，而非无意之举。

## 裁判看到的内容

会话以轮次形式呈现，如果会话较长则按最新优先排列：

- 用户说了什么
- 助手如何回复
- **智能体调用的每一个工具，以及每次调用的返回结果，按顺序排列**

最后这一点使得"它是否在 Y *之前*做了 X"成为一个公平的问题。失败的工具调用会以失败的形式显示，因此"它是否从错误中优雅地恢复"同样是可以评判的。

非常长的会话会被截断以适应模型的上下文窗口。当发生截断时，推理中会明确说明——你不会看到基于部分会话的判断被当作基于完整会话的判断呈现。

## 解读结果

裁判与其他有分数的评估一样，会生成一个**分数**，因此它同样可以绘制图表、进行过滤并触发告警。除了数字之外，它还会存储裁判的**推理**——一段解释其所见内容的文字。当某个分数出乎意料时，先阅读这段推理；通常这要么说明这是一个确实值得关注的会话，要么说明标准需要进一步细化。

对于明确的情况，分数是稳定的，但并非逐位确定性的。将单个边界分数视为深入阅读该会话的提示，而非最终判决。

## 限制

- **测试功能尚不可用。** 试运行没有对应的会话分配，而正是这种分配授权了对模型预算的消耗——因此测试调用没有任何可以计费的对象。请针对较窄的条件进行部署，并阅读最初的几个结果。
- **回填功能不可用。** 对数月历史记录进行代码评估回填是免费的；而使用裁判进行回填则会在数分钟内耗尽你的全部预算。
- **编辑标准会发布新版本。** 新旧分数不具可比性，因此它们会被分开存储，而不是混合到同一条趋势线中。
- **裁判始终产生分数**，不会产生指标或断言。

## 当预算耗尽时

裁判会消耗你组织的模型预算。当预算耗尽时，裁判评估会以明确的原因停止，而不是静默失败，**代码评估则继续正常运行**。提高预算后，裁判将在下一个会话时恢复运行。
