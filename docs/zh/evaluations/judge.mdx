托管的 Python 评估可以计数和比较：调用了多少次工具、发生了多少个错误、一个会话持续了多长时间。但它无法判断某个答案是否*正确*、某个回复是否粗鲁，或者智能体在采取行动之前是否检查了策略。

**LLM 裁判**可以做到这些。你用自然语言描述好的标准，模型读取会话后返回一个 0 到 1 的分数及其推理过程。

<Note>
对每个运行的会话，裁判都会消耗一次模型调用，而代码评估不消耗任何费用。仅对需要*理解*对话的问题使用裁判——并为其设置条件，使其仅在相关会话上运行。
</Note>

## 我应该选哪种？

| 问题 | 使用方式 |
| --- | --- |
| 它是否两次调用了同一个工具？ | 代码 |
| 发生了多少个错误？ | 代码 |
| 会话是否在 30 秒以内？ | 代码 |
| 客户是否表达了紧迫感？ | [决策模型](/zh/evaluations/jev) |
| 客户有多沮丧？ | [决策模型](/zh/evaluations/jev) |
| 答案是否真的正确？ | **裁判** |
| 回复是否粗鲁或敷衍？ | **裁判** |
| 它在承诺退款之前是否检查了退款政策？ | **裁判** |

经验法则：**可计数的 → 代码，可提前列举的答案 → [决策模型](/zh/evaluations/jev)，需要解释说明的 → 裁判。** 裁判是用来描述其所见内容的；当一个数字会让人追问"为什么？"时，就选择裁判。

你不必提前做决定。描述你想要衡量的内容，failproof 会自动选择，然后告诉你它选择了哪种方式以及原因。你可以在**评分方式**下进行切换。

## 创建一个裁判

1. 前往**分析 → 检查 → 新建评估**，并在**评分方式**下选择 **llm as judge**。
2. 描述你想要评判的内容。
3. 在**审查**页面，检查标准（**裁判的评判依据**）、阈值（**达到或超过此分数则通过**）以及**条件**，然后部署。

### 标准

一到两句话，以要求而非问题的形式书写：

> 助手在未首先检查退款政策的情况下，不得承诺或批准退款。

具体说明什么情况下会*失败*。"回复是否足够好？"给你一个毫无意义的数字；而上面那句话给出的数字是你可以付诸行动的。

### 阈值

会话达到或超过此分数即为通过。`0.7` 是一个合理的起点。完整的 0 到 1 分数始终被存储，因此阈值只决定通过/失败——你可以查看分布情况并进行调整。

### 条件

与其他评估相同的 Python 条件，在这里尤为重要。如果没有条件，裁判将在你组织中的**每一个**会话上运行，每次都消耗一次模型调用：

```python
session.count("tool_use") > 0
```

```python
session.agent_id == "support-bot" and session.count("error") > 0
```

如果你在没有设置条件的情况下部署裁判，控制台会向你发出警告。有时候这是正确的做法——比如一个你希望完整评判的低流量智能体——但这应该是有意为之，而不是意外。

## 裁判看到了什么

会话内容，以轮次展示，如果会话较长则按最新在前排序：

- 用户说了什么
- 助手如何回复
- **智能体调用的每一个工具及其返回结果，按顺序排列**

最后一点正是让"它是否在 Y *之前*做了 X"成为合理问题的原因。失败的工具调用会被显示为失败，因此"它是否从错误中优雅地恢复"同样适用。

非常长的会话会被截断以适应模型的上下文。发生这种情况时，推理内容会明确说明——你不会看到基于部分会话的判断被当作完整会话的判断呈现。

## 解读结果

裁判像其他评分评估一样产生一个**分数**，因此它可以同样地以图表展示、过滤和触发警报。除了分数之外，它还存储裁判的**推理**——一段解释其所见内容的文字。当某个分数让你感到意外时，先阅读这段文字；通常要么是一个真正有趣的会话，要么是标准需要进一步细化的信号。

对于明确的情况，分数是稳定的，但并非逐位确定性的。将单个边界分数视为深入阅读该会话的提示，而非最终裁决。

## 限制

- **测试功能尚不可用。** 试运行没有会话分配支持，而正是这个分配授权使用你的模型预算——因此测试调用没有可计费的对象。请针对较窄的条件部署，并阅读最初几个结果。
- **回填会消耗你的模型预算。** 回填代码评估是免费的；用裁判对过去的会话评分，每个会话都需要消耗一次模型调用。勾选**部署后预览历史会话**，或在其页面上选择**对历史会话评分**：统计缺失内容是免费的，只有在你确认后才会开始评分。保持时间窗口范围较窄。
- **编辑标准会发布新版本。** 新旧分数不具可比性，因此它们会被分开保存，而不是混合到同一条趋势线中。
- **裁判始终产生分数**，而不是指标或断言。

## 当预算耗尽时

裁判会消耗你组织的模型预算。当预算耗尽时，裁判评估会以明确的原因停止，而不是静默失败，并且**代码评估继续正常运行**。提高预算后，它们将在下一个会话时恢复运行。
