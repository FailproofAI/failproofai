托管的 Python 评估可以计数和比较：工具调用了多少次、发生了多少错误、会话持续了多长时间。但它无法判断答案是否*正确*、回复是否粗鲁，或智能体在采取行动前是否检查了相关策略。

**LLM 评判器**则能做到这些。你用自然语言描述何为优质输出，模型读取会话后返回 0 到 1 之间的分数，并附上推理说明。

<Note>
评判器每运行一次会话就需要消耗一次模型调用，而代码评估则无需任何成本。请仅在需要*理解*对话内容的问题上使用评判器，并为其设置条件，使其仅在相关会话上运行。
</Note>

## 该选哪种？

| 问题 | 使用方式 |
| --- | --- |
| 是否调用了同一工具两次？ | 代码 |
| 发生了多少次错误？ | 代码 |
| 会话是否在 30 秒内完成？ | 代码 |
| 客户是否表达了紧迫感？ | [决策模型](/zh/evaluations/jev) |
| 客户有多沮丧？ | [决策模型](/zh/evaluations/jev) |
| 答案是否真正正确？ | **评判器** |
| 回复是否粗鲁或敷衍？ | **评判器** |
| 是否在承诺退款前检查了退款政策？ | **评判器** |

经验法则：**可计数的 → 代码，可提前列举答案的 → [决策模型](/zh/evaluations/jev)，需要解释说明的 → 评判器。** 评判器是那个会用文字描述其所见的工具；当一个数字会让人追问「为什么」时，请使用评判器。

你无需提前做出决定。描述你想要衡量的内容，failproof 会自动选择，然后告诉你它选了什么以及原因。你可以在**评分方式**下切换。

## 创建评判器

1. 前往**分析 → 检查 → 新建评估**，在**评分方式**下选择 **llm as judge**。
2. 描述你想要评判的内容。
3. 在**审核**页面，检查评判标准（**评判器关注的内容**）、阈值（**达到或超过此分数即通过**）以及**条件**，然后部署。

### 标准

一到两句话，以要求而非问题的形式表述：

> 助手在未首先检查退款政策的情况下，不得承诺或批准退款。

具体说明什么情况会导致**不通过**。「回复好不好？」只会给你一个毫无意义的数字；而上面的句子能给你一个可以付诸行动的结果。

### 阈值

会话达到或超过此分数即为通过。`0.7` 是一个合理的起始点。完整的 0 到 1 分数始终会被存储，因此阈值仅决定通过/不通过——你可以查看分布情况并进行调整。

### 条件

与其他评估相同的 Python 条件，但在这里意义重大得多。如果没有条件，评判器将在你组织中的**每一个**会话上运行，每次都消耗一次模型调用：

```python
session.count("tool_use") > 0
```

```python
session.agent_id == "support-bot" and session.count("error") > 0
```

如果你在没有条件的情况下部署评判器，控制台会向你发出警告。有时这样做是合理的——比如对一个低流量的智能体进行完整评判——但这应该是有意为之，而非无意之举。

## 评判器看到的内容

以轮次形式呈现的对话，如果会话较长则按最新优先排列：

- 用户说了什么
- 助手如何回复
- **智能体调用的每一个工具，以及该调用的返回结果，按顺序排列**

最后一点正是让「它是否在 Y *之前*做了 X」成为合理问题的原因。失败的工具调用会显示为失败，因此「它是否从错误中优雅地恢复」同样适用。

非常长的会话会被截断以适应模型的上下文。发生这种情况时，推理说明会明确指出——你永远不会看到基于部分会话所作的判断被呈现为针对全部内容的判断。

## 解读结果

评判器与其他评分评估一样产生**分数**，因此在图表、筛选和触发告警方面的操作相同。除数字外，它还会存储评判器的**推理说明**——即描述其所见内容的段落。当分数出乎意料时，请先阅读推理说明；通常要么是一个真正有趣的会话，要么是标准需要进一步细化的信号。

对于明确的情况，分数是稳定的，但并非逐位确定性的。将单个边界分数视为深入阅读该会话的提示，而非最终判决。

## 限制

- **测试功能尚不可用。** 试运行没有对应的会话分配，而正是该分配授权了模型预算的消耗——因此测试调用无从扣费。请针对较窄的条件进行部署，并阅读前几个结果。
- **回填会消耗你的模型预算。** 回填代码评估是免费的；使用评判器对历史会话评分则每个会话都需要一次模型调用。请勾选**部署后预览历史会话**，或在其页面上选择**对历史会话评分**：统计缺失内容是免费的，只有在你确认后才会开始评分。请将时间窗口控制在较小范围内。
- **编辑标准会发布新版本。** 新旧分数不具可比性，因此它们会被分开存储，而不是混入同一趋势线中。
- **评判器始终产生分数**，不会产生指标或断言。

## 当预算耗尽时

评判器会消耗你组织的模型预算。当预算耗尽时，评判器评估会以明确的原因停止，而非无声地失败，**代码评估则继续正常运行**。补充预算后，它们将在下一个会话中恢复运行。
