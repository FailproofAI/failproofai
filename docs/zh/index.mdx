Failproof AI 帮助团队了解 agent 的行为、找出故障发生的位置，并在相同行为再次出现之前部署防护措施。

<Columns cols={2}>
  <Card title="配置 Failproof" icon="wand-sparkles" href="/zh/start/quickstart">
    使用该技能对你的项目进行插桩、完成连接，并验证 agent 日志是否正常送达。
  </Card>
  <Card title="使用 Failproof 助手" icon="message-square-text" href="/zh/sessions/assistant">
    用自然语言分析、查询 agent 日志，构建仪表板并运行审计。
  </Card>
</Columns>

<Columns cols={3}>
  <Card title="查看 agent 的操作记录" icon="route" href="/zh/sessions/overview">
    在单个会话中追踪模型调用、工具使用、错误、人工输入、延迟及策略决策。
  </Card>
  <Card title="系统性地发现故障" icon="scan-search" href="/zh/audits/overview">
    对指定的会话集合进行审计，审阅有证据支撑的发现，并将问题作为 issue 进行跟踪。
  </Card>
  <Card title="防止故障再次发生" icon="shield-check" href="/zh/policies/overview">
    将已知的故障模式转化为策略，观察其影响，并将其部署到整个服务集群。
  </Card>
</Columns>

> **会话 → 审计 → 发现 → Issue → 策略**<br />
> 追踪发生了什么、找出故障、管理响应，然后防止相同行为在后续运行中再次出现。

## 从这里开始

如果你正在部署第一个经过插桩的 agent，请从[快速入门](/zh/start/quickstart)开始。如果数据已经在接收，请打开[会话](/zh/sessions/overview)，先检查一次真实运行记录，再配置审计或策略。
