## 官方包

npm 正式包名为 **`failproofai`**：

```bash
npm install -g failproofai
# or
bun add -g failproofai
```

---

## 为什么我们持有这些别名

错字抢注（Typosquatting）是一种常见的供应链攻击手段——攻击者注册一个与热门包名仅相差一个按键的恶意包。粗心大意的用户在输入安装命令时一旦拼错，就会以完整的系统权限运行攻击者控制的代码。这正是 Failproof AI 所致力于防范的威胁类型。

为了消除这一攻击面，**我们在 npm 上提前注册了 `failproofai` 所有常见的拼写错误和格式变体**。这些包名均无法被第三方注册。每个别名都是一个轻量级代理，安装后会委托给真正的 `failproofai` 包执行。

## 已注册的别名

**格式变体** — "failproof ai" 的不同书写方式：

| 包名 | 状态 |
|---------|--------|
| `failproof` | ✅ 已发布 |
| `failproof-ai` | ⏳ 等待 npm 审核 |
| `fail-proof-ai` | ⏳ 等待 npm 审核 |
| `failproof_ai` | ⏳ 等待 npm 审核 |
| `fail_proof_ai` | ⏳ 等待 npm 审核 |
| `fail-proofai` | ⏳ 等待 npm 审核 |

**`failprof*` 错字** — "proof" 中少了一个 `o`：

| 包名 | 状态 |
|---------|--------|
| `failprof` | ✅ 已发布 |
| `failprof-ai` | ✅ 已发布 |
| `failprofai` | ⏳ 等待 npm 审核 |
| `fail-prof-ai` | ⏳ 等待 npm 审核 |
| `failprof_ai` | ⏳ 等待 npm 审核 |

**`faliproof*` 错字** — `a` 和 `i` 的位置互换：

| 包名 | 状态 |
|---------|--------|
| `faliproof` | ✅ 已发布 |
| `faliproof-ai` | ✅ 已发布 |
| `faliproofai` | ⏳ 等待 npm 审核 |

> **为什么处于等待状态？** npm 的垃圾防护策略会拦截那些在去除标点符号并进行相似度检查后与已有包名规范化结果相同的包名。我们已联系 npm 支持团队，申请以防抢注为目的保留这些名称，审核通过后将予以激活。

您可以通过以下命令验证任意已发布别名是否由我们持有：

```bash
npm info failproof
# Look for: "ExosphereHost Inc." in the maintainers field
```

## 别名的工作原理

每个别名包会：

1. 将 `failproofai` 列为依赖项——这样真正的包会被安装，其二进制文件也随之可用
2. 暴露一个与自身包名匹配的二进制文件（例如 `failprof-ai`），将所有参数代理转发给 `failproofai` 二进制文件

该代理仅由两行 Node 脚本构成，没有任何逻辑处理、网络请求，也不会收集 `failproofai` 本身之外的任何数据。
