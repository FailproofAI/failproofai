39 条内置策略中的 38 条以 `FailproofAI/policies` 包的形式发布；`block-failproofai-commands` 直接编译进安装包，因为包声明不支持 `alwaysOn`。已安装的包是本机可执行策略的权威来源：

```bash
failproofai policies show FailproofAI/policies   # 已发布的目录
failproofai policies                             # 本机已启用的策略
```

`failproofai policies` 会列出自定义文件、约定文件、已安装的包以及云端分配。该命令没有内置策略部分，因此无法回答"哪些内置策略存在"——`policies show` 和 [Policy Hub](https://befailproof.ai/policy-hub/FailproofAI/policies/) 才能解答这个问题。

## 默认值与选择方式

直接执行 `failproofai policies add FailproofAI/policies` 会启用该包自身的默认策略——即下表中标记为 **on** 的 10 条。`block-failproofai-commands` 无论是否出现在选择中都会处于启用状态，且不在该选择范围内。`--all` 启用全部策略；`--category <slug>` 和 `--policy <name>` 启用指定子集。每个标题旁边的 slug 即为 `--category` 的匹配值：

```bash
failproofai policies add FailproofAI/policies --category git,database
```

`block-failproofai-commands` **始终处于启用状态**。无论是否出现在你的选择中，它都会在每次评估时生效，且无法被禁用或暂停——一个智能体可以关闭的防护，并不是真正的防护。由于包声明不支持 `alwaysOn`，这条策略才被直接编译进安装包而非放入包中。

## 脱敏 — `sanitize`

这些策略在 `PostToolUse` 阶段运行，即工具已执行完毕之后。它们**检测并拒绝工具返回结果**；不会对子字符串进行脱敏处理后返回剩余内容。

此处的拒绝操作仅在使用 `PostToolUse` 判决的运行环境中才会传达给模型——即 **codex** 和 **copilot**，在这两个环境中，拒绝原因会替换整个工具结果。在 claude、cursor、opencode、pi、hermes、openclaw、factory、devin、antigravity 和 goose 中，`PostToolUse` 仅为观察模式：检测结果会被记录，但输出仍会传递给模型。

| 策略 | 触发条件 | 默认状态 | 结果 |
| --- | --- | --- | --- |
| `sanitize-jwt` | `PostToolUse` | on | 拒绝包含 JWT 的工具结果。 |
| `sanitize-api-keys` | `PostToolUse` | on | 拒绝包含 OpenAI、Anthropic、GitHub、AWS、Stripe 或 Google 密钥的工具结果。 |
| `sanitize-connection-strings` | `PostToolUse` | on | 拒绝包含嵌入凭据的数据库连接字符串的工具结果。 |
| `sanitize-private-key-content` | `PostToolUse` | on | 拒绝包含 PEM 私钥内容的工具结果。 |
| `sanitize-bearer-tokens` | `PostToolUse` | on | 拒绝包含 `Authorization: Bearer` 令牌的工具结果。 |

## 工作流 — `workflow`

全部五条策略在 `Stop` 时触发，默认均关闭。

| 策略 | 默认状态 | 结果 |
| --- | --- | --- |
| `require-commit-before-stop` | off | 存在未提交的已跟踪改动时，拒绝完成任务。 |
| `require-push-before-stop` | off | 存在仅本地的提交时，拒绝完成任务。 |
| `require-pr-before-stop` | off | 要求当前分支存在 Pull Request。 |
| `require-no-conflicts-before-stop` | off | 要求与已配置的基础分支合并无冲突。 |
| `require-ci-green-before-stop` | off | 要求当前 HEAD 提交的 CI 检查通过，忽略之前提交上的过期运行结果。 |

这些策略需要运行环境能够消费 `Stop` 判决，但并非所有运行环境都支持：

| 运行环境 | `Stop` |
| --- | --- |
| claude、codex、copilot、cursor、openclaw、factory、devin、antigravity | 已验证可阻断：拒绝操作会强制进入下一轮对话 |
| pi | 仅观察。拒绝原因会作为指令带入下一轮对话，而非作为拦截门控 |
| goose、hermes | 未安装 `Stop` 钩子，因此这五条策略永远不会触发 |
| opencode | 未验证。`Stop` 不在 opencode 消费判决的事件列表中 |

Cursor Cloud Agent 虚拟机完全不运行停止钩子，因此即便本地 Cursor 不受影响，在那里运行的 Cursor 会话也不受这些策略保护。

<Note>
  `warn-*` 策略返回 `instruct`，而非 `deny`。（`prefer-package-manager` 是非 `block-*` 命名中的例外：它返回 `deny`，因此会在所有消费 `PreToolUse` 判决的运行环境中生效——共十二个。）在 Hermes 和 Goose 上，在 `Stop` 通道之外的 Pi、OpenClaw 和 Factory 上，以及在 `Stop` 和 `UserPromptSubmit` 之外的 Antigravity 上，`instruct` 会降级为允许操作并在 stderr 上附加一条说明——智能体不会收到通知。Antigravity 的 `UserPromptSubmit` 是一个真实的第二通道：指令会在模型运行前作为临时消息注入。
</Note>

## 参数参考

在所选作用域的 `policyParams` 对象下配置参数。各策略会对类型进行验证。

| 策略 | 参数 | 类型与默认值 |
| --- | --- | --- |
| `sanitize-api-keys` | `additionalPatterns` | `pattern[]`，`[]`；条目包含 `regex` 和 `label` |
| `block-read-outside-cwd` | `allowPaths` | `string[]`，`[]` |
| `block-sudo` | `allowPatterns` | `string[]`，`[]` |
| `block-rm-rf` | `allowPaths` | `string[]`，`[]` |
| 基础设施拦截策略 | `allowPatterns` | `string[]`，`[]` |
| `block-secrets-write` | `additionalPatterns` | `string[]`，`[]` |
| `block-push-master` | `protectedBranches` | `string[]`，`["main", "master"]` |
| `block-work-on-main` | `protectedBranches` | `string[]`，`["main", "master"]` |
| `prefer-package-manager` | `allowed`、`blocked` | `string[]`，`[]` |
| `warn-large-file-write` | `thresholdKb` | `number`，`1024` |
| `require-push-before-stop` | `remote`、`baseBranch` | `string`，`"origin"`；`string`，`"main"` |
| `require-pr-before-stop` | `baseBranch` | `string`，`"main"` |
| `require-no-conflicts-before-stop` | `baseBranch` | `string`，`"main"` |

```json
{
  "policyParams": {
    "block-sudo": {
      "allowPatterns": ["sudo systemctl status"]
    },
    "block-push-master": {
      "protectedBranches": ["main", "release"]
    }
  }
}
```

<Note>
  直接使用策略名称作为 `policyParams` 的键，仅对 `FailproofAI/policies` 有效。对于其他任何包，键的格式为 `pack/<owner>/<repo>/<policy>`——来自第三方包中声明了相同策略名称的包，将使用 schema 默认值，而非你配置的参数。
</Note>

<Warning>
  允许模式会扩大智能体的操作权限。在将其部署到整个机器群之前，请务必在目标运行环境上测试精确的标记化处理和命令变体。
</Warning>
