在编写策略之前，请先查看[内置目录](/zh/policies/builtin-catalog)。经过审核的规则通常比新规则更安全。

## 从可用策略开始

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

初始模板会阻止 `git push --force`。编辑它，让您的 agent 尝试执行被阻止的操作，然后在 **Policies → Activity** 中查看结果。

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "protect-production",
  description: "Production changes need a human",
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) =>
    String(ctx.toolInput?.command ?? "").includes("production")
      ? deny("Ask a human before changing production.")
      : allow(),
});
```

策略返回 `allow()`、`deny(message)` 或 `instruct(message)`。当操作必须停止时使用 `deny`；并非每个运行环境都能将指令传回给 agent。

## 自动加载

将命名为 `*policies.js`、`*policies.mjs` 或 `*policies.ts` 的文件放置在以下目录中：

- `.failproofai/policies/`：适用于单个项目。
- `~/.failproofai/policies/`：适用于当前用户。

## 测试失败路径

同时测试不安全的操作以及外观相似的合法操作。确认决策来自您的策略，而非其他规则。

使用以下命令删除显式测试文件：

```bash
failproofai policies -u -c
```

策略准备就绪后，可[发布为策略包](/zh/policies/publish-a-pack)或[通过 Cloud 部署](/zh/policies/deploy)。
