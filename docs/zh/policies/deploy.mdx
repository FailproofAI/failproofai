部署操作将一个或多个策略版本关联到一组已注册的目标机器。

## 应用部署

<Tabs>
  <Tab title="控制台">
    1. 前往 **Admin → enforcement**，找到目标机器并展开其行。
    2. 选择 **edit**，添加已审核的策略版本，并选择 **observe** 或对应的强制执行效果。
    3. 应用更改后，等待机器下次签入，确认其部署和覆盖状态。
    4. 前往 **Observe → policy** 查看实时决策。

    ![机器部署编辑器，包含策略版本、enforce 和 observe 效果以及应用部署操作。](/images/dashboard/enforcement-editor.png)
  </Tab>
  <Tab title="CLI">
    Cloud 部署端点不作为普通 `fp` 命令对外暴露。请先在本地检查机器状态，再通过控制台进行部署：

    ```bash
    failproofai config --status
    ```

    部署完成后，使用 `fp sessions --env production --since 24h` 和 `fp events --event-type hook_completed` 验证活动是否已上报至 Cloud。
  </Tab>
</Tabs>

<Steps>
  <Step title="选择版本和目标机器">
    部署已审核的版本而非可变草稿，建议从非生产环境的机器或可供检查会话的小批量机器开始。
  </Step>
  <Step title="观察决策">
    在不阻断工作的前提下，查看匹配项、原因、受影响的工具及误报情况。
  </Step>
  <Step title="强制执行并验证覆盖范围">
    当观察到的匹配项能够区分不安全操作与合规操作后，再提升至强制执行模式，然后确认所有目标机器均已拉取部署并正常上报决策。
  </Step>
</Steps>

机器需具备 `policies:pull` 能力。事件上报由 `events:add` 单独控制；当您期望进行 Cloud 分析和强制执行时，请确保两项能力均已开启。

<Warning>
  强制执行管理是 Cloud 的管理员工作流。请勿将仅限 root 使用的强制执行路由当作普通客户 `/v1` API 端点来使用。
</Warning>
