每次将经过审查的策略部署到一台机器上。从观察模式开始。

## 通过 CLI 发布

```bash
fp policies test ./rule.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish no-force-push ./rule.mjs
fp fleet deploy <machine> --add no-force-push:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add no-force-push:enforce
```

观察模式会评估真实策略并记录非 allow 的决策，但不会阻止 Agent。

<Warning>
  单独使用 `--add no-force-push` 会立即执行。添加 `:observe` 可进行影子发布。
</Warning>

如果执行导致问题：

```bash
fp fleet history <machine>
fp fleet rollback <machine> <generation>
```

## 通过控制台部署

1. 前往 **Admin → enforcement**。
2. 打开目标机器。
3. 添加效果为 **observe** 的策略版本。
4. 应用部署。
5. 在 **Observe → policy** 下查看结果。
6. 当匹配结果正确时，将相同版本提升为 **enforce**。

![机器部署编辑器，显示策略版本、enforce 和 observe 效果以及应用部署操作。](/images/dashboard/enforcement-editor.png)

## 替换或预暂存策略集

- `--remove <id>` 移除一个策略。
- `--set <ref>...` 替换完整的策略集。
- `--create` 在机器首次签入之前预备部署。
- `fp fleet diff <machine>` 比较预期状态与已应用状态。

<Note>
  在没有 Cloud 的情况下，使用 `failproofai publish --effect observe` 发布策略包，并在本地控制台中检查决策。
</Note>

机器需要 `policies:pull` 权限来接收部署，需要 `events:add` 权限来上报决策。
