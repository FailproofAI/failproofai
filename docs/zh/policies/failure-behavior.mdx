完成设置后，本地 `failproofaid` 服务是唯一的评估器。如果它无法响应，受保护的操作将被拒绝，而不是静默放行。

## 诊断全机器范围的阻断

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

运行 `failproofai config` 以修复服务或安装匹配的版本。

两种失败情况看起来相似：

| 失败类型 | 含义 |
| --- | --- |
| 服务不可达 | 套接字后面没有可用的评估器 |
| 版本不匹配 | CLI 与服务在协议上存在分歧 |

两者都会触发拒绝，但状态报告会分别说明。

## 策略包无法加载

已选定的策略包如果缺失、被修改或无效，则其所涵盖策略对应的事件将被拒绝。这可以防止损坏的策略包在机器看似受保护的情况下悄然失效。

`failproofai policies` 会显示策略包名称及加载错误信息。

```bash
failproofai policies
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

无法读取的元数据会扩大安全拒绝范围，而不是基于不可信的数据来缩小它。

## 仍可使用的功能

在策略评估失败期间，本地仪表板和状态命令仍可正常使用。使用它们来确定需要修复的服务、策略包或版本。

<Warning>
  请勿通过删除服务或策略包文件来绕过失败关闭决策。应修复服务、重新安装策略包，或通过 CLI 移除对应分配，以使机器恢复到已知状态。
</Warning>
