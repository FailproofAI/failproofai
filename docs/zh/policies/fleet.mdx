Fleet 覆盖率回答的是：风险所在之处是否存在相应的策略。通过稳定 ID 和易读标签来跟踪机器，然后比较其已分配和已报告的部署状态。

## 检查覆盖率

<Tabs>
  <Tab title="控制台">
    1. 前往 **Admin → enforcement**，查看"执行中"和"观察中"的总数。
    2. 按 ID 或标签搜索机器，或筛选缺少策略的机器。
    3. 展开某一行，比较已分配的策略、已报告的部署情况、最后签入时间及历史记录。
    4. 当已应用的部署仍处于待处理状态时，在机器的轮询间隔后刷新。

    ![Enforcement fleet 界面，显示策略覆盖率、机器部署状态以及观察和执行分配情况。](/images/dashboard/enforcement-fleet.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai config --status
    failproofai config --machine-label checkout-runner-03
    failproofai flush --wait
    ```

    使用 `fp events --agent-id <agent-id> --since 24h` 确认该机器的 Agent 活动已到达 Cloud。
  </Tab>
</Tabs>

使用覆盖率视图查找以下问题：

- 从未拉取最新部署的机器
- 已注册但停止报告活动的机器
- 分配到错误环境或分组的策略
- 更新中断后产生的版本漂移

无需重新连接即可重命名机器：

```bash
failproofai config --machine-label checkout-runner-03
```

检查本地状态：

```bash
failproofai config --status
```

<Tip>
  使用能标识工作负载和环境的标签。在自动扩缩容或机器更换后，单纯依赖主机名往往是不够的。
</Tip>
