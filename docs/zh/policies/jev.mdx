Jev 会根据用户对 Agent 的指令来审查工具调用。当字符串匹配策略误拦了合法操作，或遗漏了需要上下文判断的风险操作时，可使用 Jev。它会在 `PreToolUse` 或 `PermissionRequest` 关卡上与你的策略一并给出答复。如需在会话结束**后**进行评分，请使用 [Jev 评估](/zh/evaluations/jev)。

## 从观察模式开始

安装 Failproof AI 并将 hooks 附加到[支持的运行环境](/zh/reference/harnesses)。请使用 failproofai 1.0.8-beta.0 或更高版本。

Failproof AI 默认不包含任何 Jev 检查项。需以包的形式安装，否则 Jev 将无内容可查询，也不会被调用：

```bash
failproofai policies add FailproofAI/jev-policies
```

然后选择请求发送至 Jev 的方式：

| 路由 | 第一步 |
| --- | --- |
| FailproofAI Cloud | 使用携带 `jev:evaluate` 权限的**机器**密钥进行连接。在未配置 Jev 的机器上，`failproofai config` 会以观察模式开启 Jev。 |
| 你自己的提供商 | 在本地仪表盘中，打开 **Settings → Jev**，选择提供商，粘贴其 token，并选择 **observe**。或运行 `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key`。 |

![本地仪表盘的 Jev 设置页面：提供商、端点、token 以及开启 Jev 前的观察模式。](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` 用于检查端点。若要验证 hook 路径，可让已挂载 hook 的 Agent 使用其文件读取工具读取 `README.md`。确认该工具调用出现在会话中，然后在[本地仪表盘](/zh/reference/local-dashboard#review-policy-activity)的 **Policies → Activity** 中进行检查。`status` 中的 Jev 计数应随之增加。观察模式会记录 Jev 本应做出的决策，而实际生效的仍是你现有的策略结果。

## 决定何时强制执行

**硬性**策略始终拥有最终决定权。Jev 只能在策略明确标记为**可审核**且其检查了该策略所指定关注点的情况下，才能解除拒绝。在依赖放行结论之前，请参阅[策略权限](/zh/policies/authority)。Jev 也可以独立发出警告或拒绝。若 Jev 无法给出答复，则由策略结果决定该次调用的处理方式。

一旦观察结果符合预期，可在 **Settings → Jev** 中切换至强制执行模式，或运行：

```bash
failproofai jev setup --mode enforce
```

有关提供商 URL、Cloud 密钥、配置、降级处理以及每次请求所发送的数据，请参阅 [Jev 集成参考文档](/zh/reference/jev)。
