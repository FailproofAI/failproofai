Jev 根据用户要求 Agent 执行的任务来审查工具调用。当基于字符串匹配的策略误拦了正当操作，或遗漏了需要上下文才能判断的风险行为时，可使用 Jev。它在 `PreToolUse` 或 `PermissionRequest` 关卡处与您的策略一同返回结果。如需在会话结束**后**进行评分，请使用 [Jev 评估](/zh/evaluations/jev)。

## 以观察模式启动

安装 Failproof AI 并将钩子附加到[受支持的运行环境](/zh/reference/harnesses)。请使用 failproofai 1.0.8-beta.0 或更高版本。

Failproof AI 默认不内置任何 Jev 检查。请以包的形式安装，否则 Jev 将无内容可查询，也不会被调用：

```bash
failproofai policies add FailproofAI/jev-policies
```

然后选择请求路由到 Jev 的方式：

| 路由 | 第一步 |
| --- | --- |
| FailproofAI Cloud | 使用携带 `jev:evaluate` 权限的**机器**密钥进行连接。在未配置 Jev 的机器上，`failproofai config` 会以观察模式开启 Jev。 |
| 您自己的提供商 | 在本地控制台中，打开 **设置 → Jev**，选择提供商，粘贴其令牌，然后选择 **观察**。或运行 `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key`。 |

![本地控制台的 Jev 设置页面：提供商、端点、令牌，以及开启 Jev 前的观察模式。](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` 用于检查端点。如需检查钩子路径，可让一个已挂载钩子的 Agent 使用其文件读取工具读取 `README.md`。确认该工具调用出现在会话中，然后在[本地控制台](/zh/reference/local-dashboard#review-policy-activity)的 **策略 → 活动** 中进行检查。`status` 中的 Jev 计数应有所增加。观察模式会记录 Jev 本应做出的决策，同时仍以您现有的策略结果为准。

## 决定何时执行

**硬性**策略始终拥有最终决定权。Jev 只能解除明确标记为**可审查**的策略中的拒绝，且仅限于其审查了该策略所指定关注点的情况。在依赖 Jev 的放行决定之前，请参阅[策略权限](/zh/policies/authority)。Jev 也可以自主发出警告或拒绝。若 Jev 无法给出答复，则由策略结果决定该调用的处理方式。

一旦观察结果符合预期，请在 **设置 → Jev** 中切换至执行模式，或运行：

```bash
failproofai jev setup --mode enforce
```

有关提供商 URL、Cloud 密钥、配置、回退机制以及每次请求发送的数据，请参阅 [Jev 集成参考文档](/zh/reference/jev)。
