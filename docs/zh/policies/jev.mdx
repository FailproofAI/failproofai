Jev 会根据用户向 Agent 下达的指令来审查工具调用。当字符串匹配策略阻止了合法操作，或遗漏了需要结合上下文判断的风险操作时，可使用 Jev。它在 `PreToolUse` 或 `PermissionRequest` 门控处与您的策略一同给出答复。如需在会话结束**后**获取评分，请使用 [Jev evaluations](/zh/evaluations/jev)。

## 以观察模式启动

安装 Failproof AI 并将 hooks 挂载到[支持的运行框架](/zh/reference/harnesses)。请使用 failproofai 1.0.8-beta.0 或更高版本。

Failproof AI 默认不包含任何 Jev 检查项。请以包的形式安装，否则 Jev 将无检查项可执行，也不会被调用：

```bash
failproofai policies add FailproofAI/jev-policies
```

然后选择请求发送至 Jev 的方式：

| 路由 | 第一步 |
| --- | --- |
| FailproofAI Cloud | 使用携带 `jev:evaluate` 权限的**机器**密钥进行连接。在未配置 Jev 的机器上，`failproofai config` 会以观察模式开启 Jev。 |
| 自定义提供商 | 在本地仪表盘中，打开 **Settings → Jev**，选择提供商，粘贴其令牌，并选择 **observe**。或运行 `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key`。 |

![本地仪表盘的 Jev 设置页面：提供商、端点、令牌以及开启 Jev 前的观察模式。](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` 用于检查端点连通性。如需检查 hook 路径，可让已挂载 hook 的 Agent 使用其文件读取工具读取 `README.md`。确认该工具调用出现在会话中，然后在[本地仪表盘](/zh/reference/local-dashboard#review-policy-activity)中查看 **Policies → Activity**。`status` 中的 Jev 计数应有所增加。观察模式会记录 Jev 本应做出的决策，而实际生效的结果仍由您现有的策略决定。

## 决定何时执行

**硬性**策略始终拥有最终决定权。Jev 只能撤销明确标记为**可审查**的策略所产生的拒绝，且仅限于它检查过该策略所指定关注点的情况。在依赖 Jev 的放行结果之前，请参阅[策略权限](/zh/policies/authority)。Jev 也可以自主发出警告或拒绝操作。若 Jev 无法给出答复，则由策略结果决定该次调用。

一旦观察结果符合预期，可在 **Settings → Jev** 中切换至执行模式，或运行：

```bash
failproofai jev setup --mode enforce
```

关于提供商 URL、Cloud 密钥、配置、回退机制以及每次请求所发送的数据，请参阅 [Jev 集成参考文档](/zh/reference/jev)。
