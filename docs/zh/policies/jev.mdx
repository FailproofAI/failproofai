Jev 会根据用户向 Agent 下达的指令来审查工具调用。当字符串匹配策略阻止了合法操作，或遗漏了需要上下文才能判断的风险操作时，可以使用它。它会在 `PreToolUse` 或 `PermissionRequest` 门控处与您的策略一同给出答复。如需在会话结束**后**获取评分，请使用 [Jev evaluations](/zh/evaluations/jev)。

## 从观察模式开始

安装 Failproof AI 并将 hooks 挂载到[受支持的运行环境](/zh/reference/harnesses)。请使用 failproofai 1.0.8-beta.0 或更高版本。

Failproof AI 默认不包含任何 Jev 检查项。请以包的形式安装，否则 Jev 将无内容可查询，也不会被调用：

```bash
failproofai policies add FailproofAI/jev-policies
```

然后选择请求到达 Jev 的方式：

| 路由 | 第一步 |
| --- | --- |
| FailproofAI Cloud | 使用携带 `jev:evaluate` 权限的**机器**密钥进行连接。在没有 Jev 配置的机器上，`failproofai config` 会以观察模式开启 Jev。 |
| 您自己的提供商 | 在本地仪表板中，打开 **Settings → Jev**，选择提供商，粘贴其令牌，然后选择 **observe**。或者运行 `failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key`。 |

![本地仪表板的 Jev 设置页面：提供商、端点、令牌以及开启 Jev 前的观察模式。](/images/dashboard/jev-settings.png)

```bash
failproofai jev status
failproofai jev test
```

`test` 用于检查端点连通性。若要检查 hook 路径，可让已挂载 hook 的 Agent 对 `README.md` 使用其文件读取工具。确认该工具调用出现在会话中，然后在[本地仪表板](/zh/reference/local-dashboard#review-policy-activity)的 **Policies → Activity** 中进行检查。`status` 中的 Jev 计数应有所增加。观察模式会记录 Jev 本应做出的决策，而实际生效的仍是您现有的策略结果。

## 决定何时执行

**硬性**策略始终拥有最终决定权。Jev 只能撤销明确标记为**可审查**的策略所产生的拒绝，且仅在它检查了该策略所指定的关注点时才能撤销。在依赖撤销结果之前，请参阅[策略权威](/zh/policies/authority)。Jev 也可以自主发出警告或拒绝。如果它无法给出答复，则该次调用的结果由策略决定。

观察结果符合预期后，可在 **Settings → Jev** 中切换至执行模式，或运行：

```bash
failproofai jev setup --mode enforce
```

关于提供商 URL、Cloud 密钥、配置、回退机制以及每次请求发送的数据，请参阅 [Jev 集成参考文档](/zh/reference/jev)。
