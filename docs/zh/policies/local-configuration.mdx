Failproof AI 将策略选择与机器及守护进程设置分开管理。这样既能让仓库中的策略选择保持可审查，又能将凭据和守护进程状态保存在仓库之外。

## 选择策略范围

<Tabs>
  <Tab title="控制台">
    不带参数运行 `failproofai`，打开本地策略控制台。在启用策略之前，先选择用户、项目或本地范围，确保变更写入预期的配置文件。

    - **用户**范围适用于该机器上的所有项目。
    - **项目**范围属于仓库，可以提交。
    - **本地**范围为单个用户覆盖某个项目，应保持 gitignored 状态。

  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai policy add block-rm-rf --scope user
    failproofai policy add block-force-push --scope project
    failproofai policy add warn-large-file-write --scope local
    failproofai policies
    ```

    并非所有 harness 都支持本地范围。若所选 harness 不支持某个范围，CLI 将拒绝执行。
  </Tab>
</Tabs>

| 范围 | 策略配置文件 |
| --- | --- |
| 项目 | `<project>/.failproofai/policies-config.json` |
| 本地 | `<project>/.failproofai/policies-config.local.json` |
| 用户 | `~/.failproofai/policies-config.json` |

已启用的策略以联合方式合并。策略参数按 project → local → user 的顺序，使用第一个为该策略定义了参数的范围。显式自定义策略路径同样使用第一个定义它们的范围。

## 配置策略参数

<Tabs>
  <Tab title="控制台">
    在本地控制台中打开对应策略，编辑其支持的参数，并在所选范围内保存。运行一个匹配及一个不匹配的 agent 操作，然后在 **Observe → policy** 中查看决策结果。

  </Tab>
  <Tab title="CLI">
    编辑所选范围的 `policies-config.json`，然后运行 `failproofai policies` 以发现未知的策略名称或参数键。

    ```json
    {
      "enabledPolicies": ["block-rm-rf", "block-force-push"],
      "policyParams": {
        "block-rm-rf": {
          "allowPaths": ["/tmp/build-output"]
        }
      }
    }
    ```

    ```bash
    failproofai policies
    ```
  </Tab>
</Tabs>

## 了解机器文件

`~/.failproofai` 包含针对不同信任边界的独立文件：

| 路径 | 用途 |
| --- | --- |
| `config.json` | 非机密的守护进程、审计及遥测设置 |
| `credentials.json` | 云凭据；以仅所有者权限存储 |
| `policies-config.json` | 用户范围内置策略选择、参数及显式自定义路径 |
| `policies/` | 用户约定策略及云管理的策略产物 |
| `hook-activity/` | 本地策略决策日志 |
| `state/` | 守护进程队列、健康状态、暂停及运行时状态 |

使用 `FAILPROOFAI_HOME` 可将完整的机器目录布局迁移到容器或隔离测试环境中。请勿单独迁移各个状态目录。

<Warning>
  切勿提交 `credentials.json`。只有在将项目策略配置和项目约定策略作为执行代码审查之后，才可提交它们。
</Warning>
