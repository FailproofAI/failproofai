策略监视智能体的操作并返回以下三种决策之一：

- `allow` 继续执行。
- `instruct` 在其运行环境支持的情况下向智能体提供指导。
- `deny` 阻止该操作。

将策略用于已知的、可重复出现的行为：删除受保护的文件、暴露密钥、推送到错误的分支，或修改生产基础设施。

## 将策略添加到此机器

安装时默认不选择任何策略包。安装完成后添加 Failproof AI 包：

```bash
failproofai config
failproofai policies add FailproofAI/policies
failproofai policies
```

该软件包不包含特权内置包，我们的包与其他任何人的包安装方式相同。

策略也可以来自本地文件、已发布的包或 Cloud 分配：

| 来源 | 添加方式 |
| --- | --- |
| 本地文件 | 将 `*policies.{js,mjs,ts}` 放在 `.failproofai/policies/` 目录下 |
| 任意文件路径 | `failproofai policies -i -c <path>` |
| 已发布的包 | `failproofai policies add <owner>/<repo>` |
| Cloud | 在控制台中分配，或使用 `fp fleet deploy` |

`block-failproofai-commands` 始终运行且无法关闭，它能防止智能体自行禁用其强制执行机制。

## 先观察，再执行

观察模式会运行真实策略并记录其本应执行的操作，但不会阻止智能体。

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

<Warning>
  直接执行 `fp fleet deploy <machine> --add <id>` 会立即生效强制执行。请添加 `:observe` 进行影子灰度发布。
</Warning>

在观察模式下超时的策略会记录为 allow，因为这正是强制执行时会发生的情况。只有非 allow 的观察决策才会被记录。

对于不使用 Cloud 的包，可通过 `failproofai publish --effect observe` 发布。
