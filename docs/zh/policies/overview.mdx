title: "策略"
description: "在已知故障重复发生之前，观察、引导或阻止 Agent 操作。"
icon: "shield-check"
---

策略评估 Agent 钩子事件并返回以下三种决策之一：

- `allow` 允许操作继续执行。
- `instruct` 向 Agent 提供纠正性指导。
- `deny` 以附带原因的方式阻止操作。

## 使用三个策略界面

<Tabs>
  <Tab title="控制台">
    1. 前往 **观察 → 策略** 以筛选和检查会话中的策略决策。
    2. 前往 **管理 → 策略编辑器** 以编写、验证、发布、禁用或检查不可变版本。
    3. 前往 **管理 → 执行** 以将版本和效果分配给机器。

    在编写或更改执行规则之前，请先使用策略页面了解当前已匹配的内容。

    ![策略页面，显示决策总计以及本地和云端管理的策略映射。](/images/dashboard/policy-observe.png)

    编辑器用于将故障条件转化为源代码、验证并发布不可变版本。

    ![策略编辑器，用于编写和发布不可变策略版本。](/images/dashboard/policy-editor.png)

    执行界面随后将已发布的版本及其观察或强制执行效果分配给机器。

    ![执行机器群视图，显示机器覆盖范围和已分配的策略版本。](/images/dashboard/enforcement-fleet.png)

    部署后，请在策略页面上验证决策，以便将编写视图和机器群视图与真实的 Agent 活动相关联。
  </Tab>
  <Tab title="CLI">
    使用 `failproofai` 进行本地策略安装和验证：

    ```bash
    failproofai policies
    failproofai policy add block-rm-rf --scope project
    failproofai config --status
    ```

    使用 `fp` 查找包含策略决策的云端会话和事件。云端编写和机器群部署仍为控制台工作流。
  </Tab>
</Tabs>

策略在 Failproof AI 中具有三个独立界面：

1. **分析决策** — 在会话、控制台和审计中查看。
2. **编写版本** — 使用内置规则、代码或策略编辑器。
3. **部署和执行** — 将版本应用于所选机器。

从已确认的故障模式出发。定义能够识别该故障的最小事件和工具匹配条件，测试合法示例和不安全示例，然后先观察再强制执行。
