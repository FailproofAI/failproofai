创建可用的策略，在本地测试，然后将其发布为一个策略包。

## 创建与测试

```bash
failproofai publish --init guards.mjs
failproofai policies -i -c ./guards.mjs
```

`--init` 会生成一个已经阻止 `git push --force` 的策略文件。编辑它，让您的智能体尝试执行被阻止的操作，然后在本地控制台的 **Policies → Activity** 中查看结果。

策略包可以包含以下内容：

```js
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-refunds",
  description: "Refunds above the limit need a human",
  category: "Billing",
  defaultEnabled: true,
  match: { events: ["PreToolUse"], toolNames: ["Bash"] },
  fn: async (ctx) => {
    // return allow(), instruct(), or deny()
  },
});
```

`defaultEnabled` 的默认值为 `false`。

## 发布

提交您的文件，然后运行：

```bash
failproofai publish
```

发布命令会找到策略文件，使用与安装时相同的加载器对其进行验证，并将策略包资源上传到 GitHub Release。它会使用 `GITHUB_TOKEN`、`GH_TOKEN` 或 `gh auth login` 进行身份验证。

仓库必须是公开的，因为安装过程使用匿名 HTTPS。

默认版本号为当前提交的 12 位 SHA。如果工作区存在未提交的更改，或者当前目录不在 Git 仓库中，发布命令将拒绝执行，除非您提供 `--version`。若 `HEAD` 上存在标签，则标签优先于 SHA。

用户可通过以下命令安装：

```bash
failproofai policies add owner/repo
```

## 以观察模式发布

```bash
failproofai publish --effect observe
```

观察模式会执行真实的策略逻辑并记录非 allow 的决策结果，但允许智能体继续运行。超时情况会被记录为 allow。

当观察到的匹配结果符合预期后，再次使用 `--effect enforce` 发布。

## 常用选项

| 参数 | 说明 |
| --- | --- |
| `--init [file]` | 生成一个策略模板文件 |
| `--repo <owner>/<repo>` | 选择或创建目标仓库 |
| `--version <version>` | 覆盖基于提交生成的版本号 |
| `--effect enforce|observe` | 选择策略包是否实际阻止操作 |
| `--dry-run` | 仅构建和验证，不执行发布 |
| `--allow-private` | 允许私有发布，但需知晓 `policies add` 无法安装私有包 |

```bash
failproofai publish --dry-run
failproofai publish ./guards.mjs --repo me/guards --version 2.0.0
```

<Note>
  发布后，请为 GitHub 仓库添加话题标签 `failproofai-policies`，以便 [Policy Hub](https://befailproof.ai/policy-hub/) 能够索引该策略包。CLI 不会自动为您设置此标签。
</Note>

<Warning>
  重命名策略对现有配置而言是破坏性变更。请在各版本之间保持策略名称的稳定性。
</Warning>
