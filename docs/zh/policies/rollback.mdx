---
title: "回滚"
description: "在部署的策略干扰了正常 Agent 工作时，恢复已知的策略部署状态。"
icon: "rotate-ccw"
---

回滚会更改已部署的版本或移除策略分配，但不会清除解释该事件的决策历史记录。

## 回滚某台机器

<Tabs>
  <Tab title="控制台">
    1. 进入 **Admin → enforcement**，展开受影响的机器，找到其上一个已知正常的策略集。
    2. 选择 **edit**，恢复相应的版本和效果，然后应用新的部署。
    3. 等待机器签入，然后验证上报的部署状态。
    4. 打开 **Observe → policy** 及受影响的会话，确认正常工作不再被拦截。

  </Tab>
  <Tab title="CLI">
    云端部署回滚是控制台操作流程。使用本地状态命令确认已修正的部署是否已到达该机器：

    ```bash
    failproofai config --status
    ```

    `failproofai config --pause` 可在本地单个会话中暂停内置策略、自定义策略和约定策略，但不会暂停云端管理的策略，因此不能作为云端错误部署的临时解决方案。
  </Tab>
</Tabs>

## 何时回滚

- 某条策略拦截了预期中的生产操作。
- 匹配量明显高于观测阶段预测的水平。
- 某条策略依赖的字段未被集成提供。
- 新版本在预期故障模式之外改变了行为。

回滚后，打开受影响的会话，找出导致误报的条件。创建新版本，分别测试不安全场景和合法场景，然后重新进行观测阶段。

<Warning>
  在发生事件期间暂停执行有时是合理的，但这会扩大该范围内所有有效策略的暴露面。在可能的情况下，优先回滚特定策略版本。
</Warning>
