---
title: "回滚"
description: "在策略发布中断正常 Agent 工作时，恢复已知可用的策略部署。"
icon: "rotate-ccw"
---

回滚会更改已部署的版本或移除策略分配；它不会删除记录事件经过的决策历史。

## 回滚某台机器

<Tabs>
  <Tab title="Dashboard">
    1. 进入 **Admin → enforcement**，展开受影响的机器，找到其最后一个已知可用的策略集。
    2. 选择 **edit**，恢复这些版本和效果，然后应用新的部署。
    3. 等待机器签入，然后验证上报的部署状态。
    4. 打开 **Observe → policy** 以及受影响的会话，确认合法工作不再被拦截。

  </Tab>
  <Tab title="CLI">
    找到要回退的版本，将其恢复，然后确认已生效：

    ```bash
    fp fleet history ci-runner-01
    fp fleet rollback ci-runner-01 3
    fp fleet diff ci-runner-01
    failproofai config --status
    ```

    `fp fleet rollback` 会创建一个携带旧策略集的**新**版本，而不是将计数器倒退，因此历史记录始终是只追加的。如果该版本引用了已被禁用或删除的策略，命令会拒绝执行——服务器会明确告知，而不是静默恢复一个无法交付的策略集。

    `fp fleet diff` 显示预期配置与实际交付之间的差异。在机器下次轮询之前，它的状态会显示为已漂移，因此在得出回滚未生效的结论之前，请先检查 diff。`failproofai config --status` 可在机器本身上进行确认。
  </Tab>
</Tabs>

## 暂停不等于回滚

暂停会在**一个会话**期间挂起所有本地安装的策略，并始终会自动过期——包括 packs、自定义文件、规范文件和内置策略。只有云管理策略和始终开启的 `block-failproofai-commands` 守卫仍会继续执行。因此，暂停无法作为云端部署出错的变通方案，而且它的影响范围比看起来更广：pack 是本地执行的实际核心所在，pack 的 fail-closed 守卫在暂停期间也会被跳过。

| 命令 | 效果 |
|---|---|
| `failproofai config --pause` | 暂停当前目录中最新的 Agent 会话，持续 30 分钟 |
| `failproofai config --pause 10m` | 指定暂停时长。最长 8 小时；支持 `s`/`m`/`h` 后缀，裸数字表示分钟 |
| `failproofai config --pause --session <id>` | 指定某个特定会话 |
| `failproofai config --resume` | 提前结束暂停 |
| `failproofai config --resume --all` | 结束所有活跃的暂停 |
| `failproofai config --status` | 查看哪些内容正在暂停，以及何时解除 |

## 何时进行回滚

- 某个策略拦截了预期的生产操作。
- 匹配量明显高于发布观测阶段的预测。
- 某个策略依赖集成未提供的字段。
- 新版本在预期故障模式之外改变了行为。

回滚后，打开受影响的会话，找出导致误报的条件。创建新版本，在本地分别测试不安全场景和合法场景，然后在再次执行前重新经过 observe 阶段：

```bash
fp policies test ./policy.mjs --tool Bash --command '<the legitimate case>' --expect allow
fp policies publish my-policy ./policy.mjs
fp fleet deploy ci-runner-01 --add my-policy:observe
fp guardrails summary --since 24h --machine ci-runner-01
```

`:observe` 正是将其设为影子发布的关键。裸用 `fp fleet deploy ... --add my-policy` 会**立即执行**——省略 effect 时会解析为已部署的 effect，再退而使用 `enforce`——对于刚刚回滚的策略而言，这意味着重新引发同样的事故。Observe 模式仍会真实评估策略并记录每一条非 allow 的判决；只是不会实际拦截，因此 `fp guardrails summary` 能用触发旧版本问题的相同流量来衡量新版本的表现。当数据满足要求时，使用 `--add my-policy:enforce` 进行晋级。

<Warning>
  在事故期间暂停执行可能是合适的，但这会扩大该范围内所有活跃策略的暴露面。请尽量回滚特定的策略版本。
</Warning>
