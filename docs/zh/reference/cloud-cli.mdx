使用 `fp` 检查云端遥测数据、管理云端托管的策略执行（策略、机群部署、护栏决策），以及管理审计、发现项、问题、告警、密钥、用户、查询和设置。本地钩子、策略、数据采集和机器注册请使用 [`failproofai`](/zh/reference/failproof-cli)。

您还可以通过终端编写和部署托管代码、LLM 评判器与 Jev 评估器，管理仪表板，检查情感分析数据，并使用仪表板助手。

以独立工具方式安装已发布的 Cloud CLI：

```bash
uv tool install fp-cloud-cli
fp version
```

## 登录

```bash
fp login
fp whoami
```

## 语法

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

全局选项必须置于命令之前：

```bash
fp --json sessions --since 24h
```

运行 `fp COMMAND --help` 或 `fp COMMAND SUBCOMMAND --help` 可在终端查看帮助信息。

## CLI 命令

### 编写评估器

`fp evaluators` 负责编写定义；`fp evals` 负责读取结果。需要启用一个托管实例（`fp evaluators instances`）。编写需要 `evaluations:trigger` 权限；会话试运行和 schema 分析还需要 `events:read` 权限。

代码为一个受限的 Python 表达式。将以下内容保存为 `error_free.py`：

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM 评判器：

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev 二元评分与分级评分标准：

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
创建操作会启用该评估器。部署操作会创建一个新的不可变版本，然后禁用较旧的已启用版本。若后续步骤失败，新版本仍会保持已发布状态：重试前请先查看 `evaluators list --all`。
Cloud 拒绝评判器的试运行。Jev 试运行会消耗模型配额。
回填支持代码、评判器和 Jev 评估器，最多接受 90 天的数据；它只会将评估器尚未评分的会话加入队列。评判器和 Jev 的回填会消耗模型配额，因此请先运行 `fp evaluators backfill --dry-run`。
人工输出会在创建/部署前显示每个会话的试运行结果。
若预览失败，写入操作将被阻止，除非您在审查后明确传入 `--force`。
</Warning>

AI 草稿功能需要 `fp login`，并会生成一个可供 create/deploy 使用的规范文件：

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# 启用前请审查草稿的 key、source 和 condition。
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| 命令 | 选项 / 说明 |
| --- | --- |
| `fp evaluators list` | `--key`、`--all` |
| `fp evaluators show KEY[@VERSION]` | 完整 source/envelope |
| `fp evaluators create` | `--key`、`--name`、`--version`、可重复的 `--label`、`--condition EXPR\|@file`、一个 source、可重复的 `--dry-run-on`、`--disabled`、预览失败时显式传入 `--force` |
| `fp evaluators deploy KEY` | 相同的 source 标志；`--version`、`--backfill 7d`（任意类型，1–90 天）、`--force`；数字版本自动递增；KEY 会补充规范文件中缺失的 `eval_key` |
| `fp evaluators draft "intent"` | 会话；`--kind code\|judge\|jev`、`--out` |
| `fp evaluators dry-run` | Source 标志或 `--file`，可重复的 `--session`（最多 10 个）；不指定则仅编译 |
| `fp evaluators enable\|disable KEY[@VERSION]` | 切换启用/禁用状态 |
| `fp evaluators label KEY[@VERSION]` | 可重复的 `--add`、`--remove` |
| `fp evaluators instances\|schema\|jobs` | 检查托管机群/schema/任务 |
| `fp evaluators backfill` | `--from`、`--to`、`--key`、`--dry-run`；支持代码、评判器和 Jev |

代码标志：`--code FILE|-`、`--result-kind score|metric|assertion`、`--timeout S`。评判器标志：`--judge --criteria TEXT`、可重复的 `--step` 和 `--threshold`。Jev 标志：`--jev noul --instructions --true --false` 或 `--jev score --instructions`，配合 3–5 个不同的 `--level` 值（从最差到最优）。
评判器/Jev 需要 score；阈值范围为 0–1。二元评判器不支持步骤。

规范文件包含且仅包含：`eval_key`、`display_name`、`eval_version`、`result_kind`、`labels`、`condition_source`、`evaluator_source`、`timeout_seconds`。
评判器/Jev 的 `evaluator_source` 为 JSON envelope 字符串。不得包含行 ID、启用状态或 AI 推理元数据。`--file` 与离散规范标志互斥；deploy 可覆盖文件中的版本号。输出文件不会被覆盖。

### 事件

```text
fp events [OPTIONS]
```

列出各个 Agent 事件。默认轻量数据流不包含原始载荷；`--full` 仅用于有范围限制的调查。

| 选项 | 说明 |
| --- | --- |
| `--limit`, `-n <n>` | 最大总行数。默认值：`50`。 |
| `--since <window>` | `all`、`15m`、`1h`、`6h`、`24h` 或 `7d`。 |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC 时间范围；覆盖 `--since`。 |
| `--env <value>` | 环境过滤器；可重复使用或逗号分隔。 |
| `--event-type <value>` | 事件类型过滤器；可重复使用或逗号分隔。 |
| `--agent-id <value>` | Agent 过滤器；可重复使用或逗号分隔。 |
| `--session-id <value>` | 会话过滤器；可重复使用或逗号分隔。 |
| `--search <text>` | 载荷文本搜索；可重复使用，任意词匹配即返回。 |
| `--order asc\|desc` | 时间排序。默认：最新优先。 |
| `--all` | 自动分页，直至达到 `--limit`。 |
| `--cursor <token>` | 从不透明游标处恢复。 |
| `--page-size <n>` | 使用 `--all` 时每次请求的行数；最大值 `200`。 |
| `--full` | 通过较重的事件端点包含原始载荷。 |
| `--fields <csv>` | 仅返回选定字段；请求 `payload` 会启用完整模式。 |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` 分页直至达到 `--limit`，默认值为 **50** —— 因此单独使用 `--all` 会在 50 行时停止。提前停止时，响应中会携带 `next_cursor` 以便恢复；`"next_cursor": null` 表示数据流已真正耗尽。
</Note>

#### 审计创建选项

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| 选项 | 说明 |
| --- | --- |
| `--file <path>` | 基于 JSON 文件定义，或使用 `-` 从 stdin 读取。显式标志会覆盖文件中的值。 |
| `--description <text>` | 描述失败问题或目的。 |
| `--enabled` / `--disabled` | 开启或关闭调度。默认：启用。 |
| `--schedule-interval-secs <n>` | `3600`–`604800`。默认：`86400`。 |
| `--schedule-anchor <timestamp>` | ISO 8601 格式的固定 UTC 时间基准。默认：下一个 09:00 UTC。 |
| `--window-mode since_last\|fixed` | 从上一个完整分析窗口后继续，或反复检查滚动窗口。默认：`since_last`。 |
| `--lookback-window-secs <n>` | `3600`–`7776000`。默认：`604800`。 |
| `--scope '<json>'` | 按 `environments`、`agent_ids` 或其他支持的 scope 字段过滤。 |
| `--ignore-error-type <type>` | 排除错误类型；可重复使用或逗号分隔。 |
| `--llm` / `--no-llm` | 启用或禁用 Agentic 分析。默认：启用。 |
| `--top-k <n>` | 保留 `1`–`500` 个发现项。默认：`50`。 |
| `--sensitivity low\|medium\|high` | 设置报告灵敏度。默认：`medium`。 |
| `--channels '<json>'` | 通知渠道数组。 |
| `--text <brief>` | 内联简报，最多 8,192 个字符。 |
| `--text-file <path>` | 从文件读取简报；与 `--text` 互斥。 |
| `--url <https-url>` | 添加公开 HTTPS 参考链接；最多重复五次。 |

如果首次运行需要上下文，请在创建时一并提供。创建操作会在排队运行开始前将定义和上下文一起提交。

<Note>
  `fp audits run` 是异步操作。读取发现项之前，请轮询 `fp audits runs NAME`，直至最新一次运行成功或失败。
</Note>
