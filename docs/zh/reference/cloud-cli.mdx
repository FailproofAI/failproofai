使用 `fp` 检查云端遥测数据、管理云端强制执行（策略、机群部署、防护栏决策），以及管理审计、发现项、问题、警报、密钥、用户、查询和设置。使用 [`failproofai`](/zh/reference/failproof-cli) 处理本地钩子、策略、捕获和机器注册。

您还可以编写和部署托管代码、LLM 裁判和 Jev 评估器，管理仪表板、检查情感分析，并在终端中使用仪表板助手。

将已发布的 Cloud CLI 安装为独立工具：

```bash
uv tool install fp-cloud-cli
fp version
```

## 登录

```bash
fp login
fp whoami
```

## 语法

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

全局选项必须放在命令之前：

```bash
fp --json sessions --since 24h
```

运行 `fp COMMAND --help` 或 `fp COMMAND SUBCOMMAND --help` 查看终端帮助。

## CLI 命令

### 编写评估器

`fp evaluators` 编写定义；`fp evals` 读取结果。需要启用托管实例（`fp evaluators instances`）。编写需要 `evaluations:trigger` 权限；会话试运行和 schema 分析还需要 `events:read` 权限。

代码是一个受限的 Python 表达式。将以下内容保存为 `error_free.py`：

```python
EvalResult(score=Score(1.0 if session.count("error") == 0 else 0.0), reasoning="Error-free session")
```

```bash
fp --json evaluators create --key error_free --name "Error free" --code error_free.py --dry-run-on run-001
fp --json evaluators dry-run --code error_free.py --session run-001
fp --json evaluators deploy error_free --code error_free.py --version 2 --dry-run-on run-001
fp --json evaluators list --key error_free --all
```

LLM 裁判：

```bash
fp --json evaluators create --key relevance --name Relevance --judge --criteria "Grade relevance to the request" --threshold 0.7
fp --json evaluators deploy relevance --version 2 --judge --criteria "Grade relevance and completeness" --threshold 0.8
fp --json sessions re-evaluate run-001
fp --json sessions history run-001
```

Jev 二元和分级评分表：

```bash
fp --json evaluators create --key resolution --name Resolution --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved"
fp --json evaluators dry-run --jev noul --instructions "Was the request resolved?" --true "Resolved" --false "Unresolved" --session run-001
fp --json evaluators deploy resolution --version 2 --jev score --instructions "Grade resolution quality" --level "Unresolved" --level "Partly resolved" --level "Fully resolved"
```

<Warning>
创建操作会启用评估器。部署会创建一个新的不可变版本，然后禁用旧的已启用版本。若后续步骤失败，新版本仍会保持已发布状态：重试前请先检查 `evaluators list --all`。
云端会拒绝裁判试运行。Jev 试运行会消耗模型预算。
回填支持代码、裁判和 Jev 评估器，最多接受 90 天的数据；它只对评估器尚未评分的会话排队。裁判和 Jev 回填会消耗模型预算，因此请先运行 `fp evaluators backfill --dry-run`。
人工输出在创建/部署前会显示每个会话的试运行结果。
预览失败会阻止写入操作，除非您在审查后明确传入 `--force`。
</Warning>

AI 草稿需要 `fp login`，并生成可被 create/deploy 接受的规范：

```bash
fp --json evaluators draft "Measure error-free sessions with code" --kind code --out evaluator.json
# 启用前请检查草稿的 key、source 和 condition。
fp --json evaluators create --file evaluator.json --dry-run-on run-001
fp --json evaluators dry-run --file evaluator.json
```

| 命令 | 选项 / 说明 |
| --- | --- |
| `fp evaluators list` | `--key`、`--all` |
| `fp evaluators show KEY[@VERSION]` | 完整 source/envelope |
| `fp evaluators create` | `--key`、`--name`、`--version`、可重复的 `--label`、`--condition EXPR\|@file`、一个 source、可重复的 `--dry-run-on`、`--disabled`、预览失败时显式传入 `--force` |
| `fp evaluators deploy KEY` | 相同的 source 标志；`--version`、`--backfill 7d`（任意类型，1–90 天）、`--force`；数字版本自动递增；KEY 补充缺失的规范文件 `eval_key` |
| `fp evaluators draft "intent"` | 会话；`--kind code\|judge\|jev`、`--out` |
| `fp evaluators dry-run` | source 标志或 `--file`，可重复的 `--session`（最多 10 个）；无参数则仅编译 |
| `fp evaluators enable\|disable KEY[@VERSION]` | 切换启用/禁用 |
| `fp evaluators label KEY[@VERSION]` | 可重复的 `--add`、`--remove` |
| `fp evaluators instances\|schema\|jobs` | 检查托管机群/schema/作业 |
| `fp evaluators backfill` | `--from`、`--to`、`--key`、`--dry-run`；代码、裁判和 Jev |

代码标志为 `--code FILE|-`、`--result-kind score|metric|assertion`、`--timeout S`。裁判标志为 `--judge --criteria TEXT`、可重复的 `--step` 和 `--threshold`。Jev 标志为 `--jev noul --instructions --true --false` 或 `--jev score --instructions`，配合 3–5 个不同的 `--level` 值（从最差到最好）。裁判/Jev 需要分数；阈值范围为 0–1。不接受二元裁判步骤。

规范文件包含以下字段：`eval_key`、`display_name`、`eval_version`、`result_kind`、`labels`、`condition_source`、`evaluator_source`、`timeout_seconds`。裁判/Jev 的 `evaluator_source` 是一个 JSON envelope 字符串。请勿包含行 ID、启用状态或 AI 推理元数据。`--file` 与离散规范标志互斥；deploy 可覆盖文件中的版本。输出文件不会被覆盖。

### 新仪表板控件

所有命令均接受全局 `--json`。未知路由的 404 错误以退出码 6 退出，提示"not available on this FailproofAI Cloud yet"。记录缺失的 404 错误同样以退出码 6 退出，但提示记录未找到。仅限会话的命令在 HTTP 请求前拒绝密钥模式（退出码 2）。

人工命令使用摘要和表格显示。如需导出原始 JSON，请传入全局 `--json` 或使用 `--out FILE` 保存；否则会话和 JSON 查询导出将显示可读视图。CSV 导出保持纯 CSV 格式以便管道传输。

| `fp dashboards tiles ID list\|add\|update TILE\|remove TILE\|layout` | 添加时使用 `--query ID --chart TYPE --title`；通过 `--file` 配置/几何或布局 |
| `fp sessions show\|export\|history\|re-evaluate ID` | 导出使用 `--out`；history 为评估历史 |
| `fp sessions import FILE...` | Claude Code 转录、Codex 推出或事件 JSONL（支持 `.gz`）；`--format auto\|failproofai\|claude\|codex`、`--env`、`--dry-run`；需要 `events:add` 权限 |
| `fp events latency` | `--since` |
| `fp sentiment summary\|messages\|sessions\|session ID` | `--since`；列表使用 `--limit`；messages 使用 `--session-id` |
| `fp query compose "question"` | 会话；`--run` |
| `fp query export [ID]` | 或 `--sql`；`--format csv\|json`、`--out` |
| `fp alerts recipients` / `fp alerts issues ID` | issues 可使用 `--create --title --summary` 或 `--create --file` |
| `fp audits contracts list\|show ID\|create\|update ID` | `--agent-id`、`--body TEXT\|@file`、`--file` JSON；更新使用 `--enabled/--disabled` |
| `fp policies author "intent" [--kind regex\|jev\|both]` | 会话；根据您组织的事件草拟策略，不会发布 |

| `fp policies candidacy --issue ID` | 会话；策略能否阻止此问题 |

| `fp users delete ID` / `fp users defaults` | 按 ID 删除 |
| `fp usage windows` / `fp plan` / `fp plan claim OFFER` | `usage windows` 需要 API 密钥；plan（优惠和试用）和 claim 需要已登录会话 |

| `fp slack status\|disconnect` | 会话 |

### 事件

```text
fp events [OPTIONS]
```

列出各个代理事件。默认轻量 feed 不包含原始负载；仅在有限调查时使用 `--full`。

| 选项 | 描述 |
| --- | --- |
| `--limit`、`-n <n>` | 最大总行数。默认：`50`。 |
| `--since <window>` | `all`、`15m`、`1h`、`6h`、`24h` 或 `7d`。 |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC 范围；覆盖 `--since`。 |
| `--env <value>` | 环境筛选器；可重复或逗号分隔。 |
| `--event-type <value>` | 事件类型筛选器；可重复或逗号分隔。 |
| `--agent-id <value>` | 代理筛选器；可重复或逗号分隔。 |
| `--session-id <value>` | 会话筛选器；可重复或逗号分隔。 |
| `--search <text>` | 负载文本搜索；可重复，任意词匹配。 |
| `--order asc\|desc` | 时间顺序。默认：最新优先。 |
| `--all` | 自动分页直至 `--limit`。 |
| `--cursor <token>` | 从不透明游标处恢复。 |
| `--page-size <n>` | 使用 `--all` 时每次请求的行数；最大 `200`。 |
| `--full` | 通过较重的事件端点包含原始负载。 |
| `--fields <csv>` | 仅返回所选字段；请求 `payload` 会启用完整模式。 |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` 分页**最多到 `--limit`**，默认值为 **50**——因此单独使用 `--all` 时会在 50 行处停止。提前停止时，响应中会携带 `next_cursor` 供恢复；`"next_cursor": null` 表示 feed 已真正耗尽。
</Note>

#### 审计创建选项

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| 选项 | 描述 |
| --- | --- |
| `--file <path>` | 基于 JSON 定义，或使用 `-` 从 stdin 读取。显式标志会覆盖文件值。 |
| `--description <text>` | 说明失败问题或目的。 |
| `--enabled` / `--disabled` | 是否启动调度。默认：启用。 |
| `--schedule-interval-secs <n>` | `3600`–`604800`。默认：`86400`。 |
| `--schedule-anchor <timestamp>` | ISO 8601 格式的固定 UTC 相位。默认：下一个 09:00 UTC。 |
| `--window-mode since_last\|fixed` | 从上次完整分析窗口后继续，或重复检查滚动窗口。默认：`since_last`。 |
| `--lookback-window-secs <n>` | `3600`–`7776000`。默认：`604800`。 |
| `--scope '<json>'` | 按 `environments`、`agent_ids` 或其他支持的范围字段筛选。 |
| `--ignore-error-type <type>` | 排除错误类型；可重复或逗号分隔。 |
| `--llm` / `--no-llm` | 启用或禁用智能体分析。默认：启用。 |
| `--top-k <n>` | 保留 `1`–`500` 条发现项。默认：`50`。 |
| `--sensitivity low\|medium\|high` | 设置报告灵敏度。默认：`medium`。 |
| `--channels '<json>'` | 通知渠道数组。 |
| `--text <brief>` | 内联简要说明，最多 8,192 个字符。 |
| `--text-file <path>` | 从文件读取简要说明；与 `--text` 互斥。 |
| `--url <https-url>` | 添加公共 HTTPS 参考；最多重复五次。 |

首次运行需要上下文时，应在创建时一并提供。创建操作会在队列中的运行开始前提交定义和上下文。

<Note>
  `fp audits run` 是异步的。读取发现项前，请轮询 `fp audits runs NAME` 直到最新运行成功或失败。
</Note>
