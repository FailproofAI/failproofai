使用 `fp` 检查 Cloud 遥测数据、管理云端托管的执行规则（策略、机队部署、防护栏决策），以及管理审计、发现项、问题、告警、密钥、用户、查询和设置。本地钩子、策略、采集和机器注册请使用 [`failproofai`](/zh/reference/failproof-cli)。

以隔离工具的方式安装已发布的 Cloud CLI，需要 Python 3.10 或更高版本。

```bash
uv tool install fp-cloud-cli
fp version
```

发行包名为 `fp-cloud-cli`，安装后的命令为 `fp`——两者不同是因为 `fp` 在 PyPI 上已被占用。

## 登录

`fp login` 会向您发送一个六位数验证码并保存会话。若仪表板使用自签名证书，请在登录时添加 `--insecure`。

```bash
fp login
fp whoami
```

## 语法

```text
fp [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

全局选项必须置于命令之前：

```bash
fp --json sessions --since 24h
```

执行 `fp COMMAND --help` 或 `fp COMMAND SUBCOMMAND --help` 可在终端查看帮助。

### 事件

```text
fp events [OPTIONS]
```

列出各个代理事件。默认的轻量数据流不包含原始载荷；仅在有明确调查范围时使用 `--full`。

| 选项 | 说明 |
| --- | --- |
| `--limit`, `-n <n>` | 最大总行数。默认值：`50`。 |
| `--since <window>` | `all`、`15m`、`1h`、`6h`、`24h` 或 `7d`。 |
| `--from <timestamp>` / `--to <timestamp>` | ISO 8601 UTC 时间范围；覆盖 `--since`。 |
| `--env <value>` | 环境过滤器；可重复使用或以逗号分隔。 |
| `--event-type <value>` | 事件类型过滤器；可重复使用或以逗号分隔。 |
| `--agent-id <value>` | 代理过滤器；可重复使用或以逗号分隔。 |
| `--session-id <value>` | 会话过滤器；可重复使用或以逗号分隔。 |
| `--search <text>` | 载荷文本搜索；可重复使用，任意词项匹配即可。 |
| `--order asc\|desc` | 时间排序。默认：最新在前。 |
| `--all` | 自动分页至 `--limit` 上限。 |
| `--cursor <token>` | 从不透明游标处续传。 |
| `--page-size <n>` | 使用 `--all` 时每次请求的行数；最大 `200`。 |
| `--full` | 通过较重的事件端点获取原始载荷。 |
| `--fields <csv>` | 仅返回指定字段；请求 `payload` 将启用完整模式。 |

```bash
fp events --session-id <session-id> --order asc --all --limit 10000
fp --json events --full --session-id <session-id> --all --limit 10000
```

<Note>
  `--all` 会分页至 **`--limit` 上限**，而该上限默认为 **50**——因此单独使用 `--all` 时会在 50 行处停止。提前停止时，响应中会携带 `next_cursor` 供续传；`"next_cursor": null` 表示数据流已真正耗尽。
</Note>

#### 审计创建选项

```bash
fp audits create checkout-reliability \
  --description "Find checkout failures that agents do not recover from" \
  --scope '{"environments":["production"],"agent_ids":["checkout-agent"]}' \
  --schedule-interval-secs 86400 \
  --window-mode since_last \
  --sensitivity medium \
  --text-file ./checkout-audit-brief.txt \
  --url https://runbooks.example.com/checkout
```

| 选项 | 说明 |
| --- | --- |
| `--file <path>` | 基于 JSON 文件定义，或使用 `-` 从 stdin 读取。显式标志会覆盖文件中的值。 |
| `--description <text>` | 说明要排查的故障问题或目的。 |
| `--enabled` / `--disabled` | 启动时是否开启调度。默认：启用。 |
| `--schedule-interval-secs <n>` | `3600`–`604800`。默认值：`86400`。 |
| `--schedule-anchor <timestamp>` | ISO 8601 格式的固定 UTC 时间相位。默认：下一个 09:00 UTC。 |
| `--window-mode since_last\|fixed` | 从上次完整分析窗口之后继续，或反复检查一个滚动窗口。默认：`since_last`。 |
| `--lookback-window-secs <n>` | `3600`–`7776000`。默认值：`604800`。 |
| `--scope '<json>'` | 按 `environments`、`agent_ids` 或其他支持的 scope 字段过滤。 |
| `--ignore-error-type <type>` | 排除错误类型；可重复使用或以逗号分隔。 |
| `--llm` / `--no-llm` | 启用或禁用智能体分析。默认：启用。 |
| `--top-k <n>` | 保留 `1`–`500` 条发现项。默认值：`50`。 |
| `--sensitivity low\|medium\|high` | 设置报告灵敏度。默认：`medium`。 |
| `--channels '<json>'` | 通知渠道数组。 |
| `--text <brief>` | 内联简报，最多 8,192 个字符。 |
| `--text-file <path>` | 从文件读取简报；与 `--text` 互斥。 |
| `--url <https-url>` | 添加公共 HTTPS 参考链接；最多重复五次。 |

如果首次运行需要上下文，请在创建时一并提供。创建操作会在排队运行开始前将定义和上下文一起提交。

<Note>
  `fp audits run` 是异步的。在读取发现项之前，请轮询 `fp audits runs NAME` 直至最新一次运行成功或失败。
</Note>

### 策略

云端托管的策略版本。**仅限会话模式**——除 `fp policies test` 外，此处所有命令在 API 密钥下均会在发起任何请求之前以退出码 `2` 退出，因为这些是刻意从 `/v1` 中排除的仅 root 写入路由。`fp policies test` 是刻意设置的例外：它完全在本地针对 `node` 运行，不与任何服务器通信，因此既无认证要求，也无密钥模式拒绝，在未登录和使用 API 密钥时均可正常使用。

| 命令 | 用途 | 选项 |
| --- | --- | --- |
| `fp policies list` | 列出策略版本，每个策略的最新版本排在最前。 | — |
| `fp policies show POLICY_ID` | 显示某个策略及其源码。 | — |
| `fp policies publish POLICY_ID [SOURCE]` | 生成新版本；永远不会原地编辑现有版本。`SOURCE` 为路径、`@path` 或 `-`（从 stdin 读取）——省略则进入粘贴模式。 | `--description`；`--no-verify` |
| `fp policies enable POLICY_ID` | 将其重新添加到所有曾移除它的部署中，并在每个部署上生成新一代。 | `--yes`, `-y` |
| `fp policies disable POLICY_ID` | 从所有携带它的部署中移除，并在每个部署上生成新一代。 | `--yes`, `-y` |
| `fp policies delete POLICY_ID` | 删除某个策略版本。 | `--yes`, `-y` |
| `fp policies test [SOURCE]` | 在本地针对合成上下文运行策略。会应用每个策略的 `match` 过滤器，若某策略不覆盖给定的事件/工具，则报告为 `skipped` 而非执行。需要 PATH 中有 `node`。 | `--event`；`--tool`；`--command`；`--file`；`--expect` |
| `fp policies compose PROMPT` | 使用助手起草策略。默认情况下仅打印草稿，不执行其他操作。需要 `policies:write` 权限。 | `--out <path>`；`--publish <policy-id>` |

| `fp fleet deploy MACHINE_ID` | 更改某台机器执行的内容。会先打印完整的最终策略集，仅在非 `--json` 的交互式终端下才会询问确认。 | `--add`；`--remove`；`--set`；`--create`；`--yes`, `-y` |
| `fp fleet diff [MACHINE_ID]` | 意图与实际——机器被告知运行的策略与其最后一次拉取的策略之间的差异。省略 id 则检查整个机队。 | — |
| `fp fleet history MACHINE_ID` | 显示某台机器的所有代次，最新在前。 | — |
| `fp fleet rollback MACHINE_ID GENERATION` | 恢复某个历史代次的策略集。代次编号来自 `fp fleet history MACHINE_ID`。 | `--yes`, `-y` |
| `fp fleet rename MACHINE_ID LABEL` | 为机器设置一个可读标签。机器 id 本身不会改变。 | — |

```bash
fp fleet history ci-runner-01
fp fleet rollback ci-runner-01 3
fp fleet rename ci-runner-01 "CI runner (eu-west)"
```

#### 策略引用

`--add` 和 `--set` 接受策略引用，而非裸 id：

| 格式 | 含义 |
| --- | --- |
| `id` | 当前版本，当前效果 |
| `id@3` | 第 3 版，当前效果 |
| `id:observe` | 当前版本，仅记录不执行 |
| `id@3:observe` | 第 3 版，仅记录不执行 |

效果为 `enforce`（执行）或 `observe`（观察）。解析规则：显式指定的效果优先；其次使用该策略在部署中已有的效果；否则默认为 `enforce`。

<Warning>
  裸 `--add` 会**立即执行**。`fp fleet deploy ci-runner-01 --add checkout-guard` 会在该机器下次拉取时立即开始阻断。`:observe` 才是实现影子发布的方式：

  ```bash
  fp fleet deploy ci-runner-01 --add checkout-guard:observe   # 仅记录
  fp fleet deploy ci-runner-01 --add checkout-guard           # 立即执行
  ```

  observe 不等于关闭。策略会被真实评估，采用与执行模式相同的 10 秒超时和错误处理机制，所有非 allow 的判决都会被记录——只是不会真正执行。正因如此，这种测量才有参考价值。
</Warning>

#### 差量更新、替换与竞争条件

`--add` 和 `--remove` 会读取机器的当前策略集并应用差量，因此未提及的策略不会受到影响。对机器已运行的策略执行裸 `--add` 会保留其已固定的版本，而不会静默升级；如需移动版本，请传入 `id@version`。

`--set` 会替换全部策略，也是唯一能删除未命名策略的方式。它不能与 `--add` 或 `--remove` 组合使用。三者均不传入是使用错误，而非无操作。

```bash
fp fleet deploy ci-runner-01 --add prod-guard@1:observe --remove old-rule
fp fleet deploy ci-runner-01 --set no-force-push --set no-secret-echo
```

由于端点接收整个策略集，写操作本质上是对每条路径的完全替换。服务端没有锁，因此 CLI 会记录读取时的代次，若结果不恰好比当前代次高一，则拒绝操作——这意味着期间有其他人进行了部署，而替换操作不会合并。请使用 `fp fleet show` 重新读取后再次部署。

`--create` 用于预先部署到尚未签到的机器 id，以便提前准备。不使用此标志时，服务器不认识的 id 会被拒绝，否则一个拼写错误就可能生成一台无人所有、无人收集策略的机器。

### 防护栏

执行规则实际产生的效果。**仅限会话模式**，原因同上。

| 命令 | 用途 | 选项 |
| --- | --- | --- |
| `fp guardrails summary` | 覆盖率、拦截/评估总数、拒绝迷你图以及按策略汇总的表格。 | `--since`（`1h`、`6h`、`24h`、`7d`）；`--machine` |
| `fp guardrails timeline` | 在时间窗口内按桶聚合的决策，跨所有策略来源求和。 | `--since`（`1h`、`6h`、`24h`、`7d`）；`--machine` |

汇总表中出现 `(no policy)` 行是正常现象，而非数据缺口：大多数评估结果都是无任何策略反对的 allow，该行的作用是将分母保持在屏幕上。

### 不影响任何人的策略发布流程

以上三组命令构成一个完整序列：本地决策、发布、影子部署、度量，然后执行。

```bash
fp policies test ./checkout.policy.mjs --tool Bash --command "git push --force" --expect deny
fp policies publish checkout-guard ./checkout.policy.mjs --description "Block force-push"
fp fleet deploy ci-runner-01 --add checkout-guard:observe
fp guardrails summary --since 24h --machine ci-runner-01
fp fleet deploy ci-runner-01 --add checkout-guard:enforce
```

| 步骤 | 原因 |
| --- | --- |
| `fp policies test` | 无需服务器，无需认证。针对您描述的上下文运行真实文件，并为每个注册策略打印 allow、deny 或 instruct。`--expect` 可将其转为 CI 断言。 |
| `fp policies publish` | 生成新的不可变版本；永远不会原地编辑现有版本。 |
| `fp fleet deploy --add <id>:observe` | 影子发布。**此处 `:observe` 不可省略**——裸 `--add` 会在机器下次拉取时立即执行。 |
| `fp guardrails summary` | 将不安全的匹配与策略本会误拦截的合法操作区分开来。 |
| `fp fleet deploy --add <id>:enforce` | 在已记录的判决符合预期后进行提升。 |
| `fp fleet rollback <machine> <generation>` | 执行出现问题时的回退路径。 |

不涉及 Cloud 的单机等效方案，是使用 `failproofai publish --effect observe` 发布策略包，并在[本地仪表板](/zh/reference/local-dashboard)上查看已记录的判决。

| 变量 | 对应标志或用途 |
| --- | --- |
| `FP_DASHBOARD_URL` | `--base-url` |

| `NO_COLOR` | 禁用彩色输出。 |

显式标志会覆盖环境变量，环境变量会覆盖已保存的配置。

在 API 密钥模式下，由人工 `fp login` 保存的组织会被**忽略**，而非仅被覆盖——只有显式的 `--org` 或 `FP_ORG` 才会被发送。不会从已保存的登录中继承任何内容，因此当密钥可以操作多个组织时，请务必传入 `--org`。省略它不会报错：一个未指定 `--org` 的实例范围密钥会在服务端解析为**默认**组织并返回该组织的数据，全程无任何报错。建议先运行 `fp whoami` 确认密钥实际连接到了哪个租户。

<Warning>
  这些变量的 `AGENTEYE_*` 写法**不会被 `fp` 读取**，也从未被读取过——CLI 声明的是 `FP_*`（`fp_cli/app.py`），未知变量不会报错。设置 `AGENTEYE_DASHBOARD_URL` 不会重定向 CLI；它会被忽略，命令将静默地针对已保存的仪表板运行。

  `AGENTEYE_HOME` 和 `AGENTEYE_ENVIRONMENT` 确实存在，但它们属于**采集器和遥测 SDK**，而非本 CLI。
</Warning>

<Warning>
  执行删除、吊销、抑制、解决或替换配置的命令默认会提示确认。仅在验证活跃组织和目标无误后再使用 `--yes`。
</Warning>
