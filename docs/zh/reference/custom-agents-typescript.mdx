需要 Node 20.9 或更高版本。支持 ESM 和 CommonJS，无运行时依赖。

<Note>
  该 SDK 与 Python SDK **写入同一缓冲池中的相同事件**。由 Node agent 和 Python agent 组成的集群只会产生一套会话，而非两套，仪表盘中也不会加以区分。请按服务选择，而非按公司统一选择。
</Note>

## 安装

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

框架适配器已内置于包中。这些框架是**可选的 peer 依赖**——声明这些依赖是为了明确支持的版本范围，不会自动为你安装，只有在调用 `instrument()` 时才会被引入。

## 连接 Failproof 守护进程

与 Python SDK 相同：在 **settings → api keys** 下创建一个 `events:add` 密钥，然后在 agent 机器上[连接守护进程](/zh/start/setup#connect-a-machine-to-cloud)。SDK 负责写入磁盘，守护进程负责传输。

## 配置

### OpenTelemetry spans（可选接入）

单独安装 OpenTelemetry：`npm install @opentelemetry/api @opentelemetry/sdk-trace-base`。
然后将 FailproofAI 添加到你的 provider 处理器中：

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

如果你已有 provider，只需将其他处理器也放入同一列表中。暴露了 `addSpanProcessor` 的 provider 可直接以 `{ provider }` 的形式传入。若不传任何选项，只有在尚未注册 provider 的情况下，才会注册新的 provider。`OtelSpanExporter` 也可直接与你自定义的处理器配合使用。

导出数据通过已连接的 FailproofAI 守护进程传输；SDK 不发送任何网络请求，也不需要密钥或本地监听器。Cloud 中的 [OpenTelemetry 数据摄入](/zh/agenteye/opentelemetry)始终开启。单独调用 `instrument()` 不会启用此导出器。`uninstrument("otel")` 仅禁用其自身的处理器。内容采集由你的 span 属性控制；退出前请务必 flush 你的 provider。OpenTelemetry 仍为可选的应用依赖，而非 SDK 的强制依赖。

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| 选项 | 说明 |
| --- | --- |
| `environment` | 每个事件上的标签，例如 `production`、`staging`、`prod-eu`。默认为 `dev`。 |
| `flushInterval` | 定时器写入磁盘的间隔，单位为秒。默认为 `0.5`。 |
| `baseDir` | 写入目录。默认为守护进程的缓冲目录，通常无需修改。 |

只有全部选项均通过验证后才会生效，因此若调用被拒绝，SDK 将保持原有状态不变，不会出现 `baseDir` 已更新但间隔仍为旧值的情况。

也可通过环境变量进行配置：

| 变量 | 说明 |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | 无需修改代码即可设置 `environment`。`configure()` 中的同名选项优先级更高。 |
| `FAILPROOFAI_HOME` | 修改存放缓冲池的 Failproof AI 根目录。 |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`、`info`、`warn`（默认）、`error`、`silent`。 |
| `FAILPROOFAI_SDK_STRICT` | 设为 `1` 时，接入错误会抛出异常，而非仅记录日志。 |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | 设为 `1` 时，框架兼容性问题会抛出异常，而非警告后继续运行。 |

<Warning>
  **`environment` 中不能包含逗号。** 数据摄入会按逗号分割该字段以构建过滤器，标签中含有逗号的事件会被静默丢弃——导致整个运行批次无声无息地消失。请写 `prod-eu`，而非 `prod,eu`。

  `configure({ environment: "prod,eu" })` 会立即抛出异常，让你第一时间发现问题。`AGENTEYE_ENVIRONMENT` 无法抛出异常——没有调用方可以接收——因此它会警告一次并回退到 `dev`。
</Warning>

通过 `failproofai.setLogger({ debug, info, warn, error })` 可将 SDK 自身的日志输出接入你的日志系统。

## 关闭

缓冲中的事件会在 `process.on("exit")` 时刷新。

被信号杀死的进程永远不会触发该事件，而 Node 对 `SIGTERM` 的默认处理是直接终止进程而不执行退出处理器——因此容器化的 agent 会丢失最近一个写入间隔内尚未写入的数据。

<Warning>
  **本 SDK 不会为你安装信号处理器。** 注册信号处理器会改变进程的行为：监听器会抑制 Node 的默认终止逻辑，如果由库来添加，会导致 Ctrl-C 静默失效。请自行添加：

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

短生命周期脚本或 serverless 处理器应在返回前 `await failproofai.flush()`——仅靠定时器无法保证数据一定被写入。

## 身份标识

每个事件都属于某个会话和某个 agent。**作用域会自动填充这两者**，因此通常无需手动传入：

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

显式传入 `sessionId` 或 `agentId` 同样有效，且优先级更高。若二者均未绑定也未传入，调用会抛出异常，而非静默地发出一个 Cloud 会丢弃的事件。

<Note>
  身份标识基于 `AsyncLocalStorage` 传递，能跟随 `await`、`.then()`、定时器以及在作用域内创建的任何回调。**不支持**以下情况：在某次运行中存储的回调在另一次运行中被调用，或跨 `worker_threads` 边界传递的任务——对于这类情况，请用 `failproofai.propagate()` 包裹，否则相关事件将无法关联到对应运行。
</Note>

### 作用域

| 作用域 | 触发事件 | 返回值 |
| --- | --- | --- |
| `session(body)` | 无——仅设置身份标识 | `body` 的返回值 |
| `agent(id, options?, body)` | `agent_start`，然后 `agent_end` | `body` 的返回值 |
| `toolCall(name, options?, body)` | `tool_use`，然后 `tool_result` | `body` 的返回值 |

同步的 body 保持同步：`agent("x", () => 1)` 返回 `1`，而非 Promise。

`toolCall` 会将 body 的 resolved 值记录为工具的 `output`，除非你手动给 `call.output` 赋值。

<Accordion title="退出语义" icon="arrow-right-from-bracket">

| 发生情况 | 触发事件 | `outcome` |
| --- | --- | --- |
| 代码块正常返回 | `agent_end` | `"success"`，或你自定义的 `outcome` |
| 代码块抛出异常 | `error`，然后 `agent_end` | `"failed"` |
| 抛出 `AbortError` | 仅 `agent_end` | `"cancelled"` |

异常始终会被重新抛出。

工具失败记录在叶节点上——`tool_result` 携带 `error` 字符串——**不会**触发运行级别的 `error` 事件。被 agent 循环捕获的错误不属于运行失败；向上传播的错误则由外层 `agent()` 精确报告一次。

</Accordion>

<Accordion title="`using` 形式" icon="brackets-curly">

当工作不是单个函数时——例如在构造函数中开启作用域、在 teardown 中关闭，或横跨现有控制流的情况：

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result，然后 agent_end
```

两种形式触发的事件在字节层面完全相同。推荐使用回调形式：它在 `AsyncLocalStorage.run()` 内部运行，无需手动展开，从根本上避免了"在此处开启、在彼处关闭"这类 bug。

`using` 块若需捕获自身的失败，应通过 `span.fail(error)` 上报——disposer 本身没有异常传递通道。

</Accordion>

## 事件目录

与 Python SDK 相同的十五个方法，采用 camelCase 命名。大多数以**成对**形式出现——调用开启方法，再调用关闭方法，SDK 会自动计算时间差。

| | 开启 | 关闭 |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **模型** | `modelRequest` | `modelResponse` |
| **工具** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **人工** | `humanWait` | `humanInput` |

三个独立方法：`error`、`humanPause`、`humanInterrupt`。

<Accordion title="每个方法的所有字段" icon="table">

每个方法还接受 `sessionId` 和 `agentId`，作用域会自动填充。省略的字段会被直接丢弃，而非以 JSON `null` 的形式发送。

| 方法 | 必填字段 | 可选字段 |
| --- | --- | --- |
| `agentStart` | — | `goal`、`parentId` |
| `agentEnd` | — | `outcome`、`summary` |
| `agentPause` | `pauseId` | `reason`、`userId` |
| `agentResume` | `pauseId` | `reason`、`userId` |
| `modelRequest` | — | `model`、`messages`、`system`、`tools`、`requestId` |
| `modelResponse` | — | `model`、`stopReason`、`inputTokens`、`outputTokens`、`content`、`role`、`requestId` |
| `toolUse` | `toolName`、`toolCallId` | `input` |
| `toolResult` | `toolName`、`toolCallId` | `output`、`error` |
| `hookTriggered` | `hookName`、`hookId` | `triggerEvent`、`input` |
| `hookCompleted` | `hookName`、`hookId` | `outcome`、`output`、`error` |
| `error` | `errorType`、`message` | `traceback` |
| `humanWait` | `inputId` | `prompt`、`options`、`reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`、`userId` |
| `humanInterrupt` | — | `reason`、`userId`、`atStep` |

你添加的任何其他键都会成为自定义 payload 字段。框架专属的字段请以 `fw_*` 命名；与已声明字段同名的键会被拒绝，而非静默覆盖已提升的列。

</Accordion>

<Warning>
  **`duration_ms` 由系统计算，不接受外部传入。** 四个关闭方法会计算与对应开启方法之间的时间差，并拒绝调用方传入的 `duration_ms`——上报的时长必须无法被伪造。

  成对匹配基于**会话**和 id，而非 agent。在 `planner` 下开启、在 `worker` 下关闭的工具调用依然能够配对，这正是嵌套多 agent 运行的实际工作方式。
</Warning>

## 框架适配器

```ts
await failproofai.instrument();              // 自动检测并接入所有可用框架
await failproofai.instrument("langchain");   // 仅接入指定框架
failproofai.uninstrument();                  // 还原所有修改
```

| 框架 | 支持版本 | 接入方式 |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x，LangGraph.js 0.4 – 1.x | 通过 `CallbackManager.configure` 接入，每次 `invoke`/`stream`/`batch` 调用均自动覆盖，无需在任何地方传入 `callbacks:`——或者自行传入 `langchainHandler()` 而不修改任何全局状态。 |
| **Vercel AI SDK** | `ai` 4 – 7 | 在调用处使用 `telemetry()`，或通过 `instrument("ai")` 对 `ai` 7 进行进程级接入（4–6 版本需手动开启——见下文）。 |
| **Mastra** | `@mastra/core` 0.20 – 1.x | 覆盖 `Agent.generate`/`.stream`、agent 的模型与工具解析，以及 workflow 运行/步骤引擎。 |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | 通过订阅 `Settings.callbackManager` 以及 `AgentWorkflow.runStream`，覆盖 workflow 运行及其步骤。 |

每个版本范围均针对真实框架发布版本进行测试，包括两端边界值，以 ES 模块和 CommonJS 两种形式，在每次 CI 运行中均会执行。

映射关系与 Python SDK 相同，因此同一程序在两种语言下会绘制出相同的调用树。只有拥有 LLM 决策循环的构造才是 **agent**——包括 graph 或 chain 运行、AI SDK 的 `generateText`/`streamText` 调用、Mastra agent、LlamaIndex agent 运行。LangGraph 节点或 workflow 步骤是 **hook**（`hook_triggered`/`hook_completed`），而非嵌套 agent。模型调用以带 token 计数的 `model_request`/`model_response` 成对记录；工具调用携带模型自身的 tool call id。失败仅在发生所在的事件上记录一次。

若某个适配器安装失败，会记录日志并跳过；其他适配器仍照常安装，因为 LlamaIndex 的问题不应影响 LangGraph 的正常使用。

<Note>
  不带参数的 `instrument()` 通过模块是否**可解析**来检测框架，而非检查其是否已被导入——Node 对 ES 模块没有类似 Python `sys.modules` 的等价物。已安装但未使用的框架会被导入并打补丁。如果这一点对你有影响，请明确指定所需框架的名称。
</Note>

<Note>
  这些框架大多同时提供 ES 模块构建和 CommonJS 构建，Node 会将它们作为两份互不相关的副本加载。适配器会对你的应用实际加载的副本打补丁（如果已有代码 `require` 过，也会对 CommonJS 副本打补丁），因此两种模块系统均可正常工作。**被 esbuild 或 webpack 打包进你的输出中**的框架则无法触达——请在这种情况下使用调用处的辅助函数：`langchainHandler()`、`telemetry()`、`wrapTool()`。
</Note>

### 不打补丁地使用 LangChain

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

该处理器无论是否调用 `instrument()` 均可正常工作，且不会重复记录。`instrument("langchain")` 接受 `sessionId`、`captureContent`、`includeChains`、`graphCallbacks` 和 `captureLimit` 参数，与 Python 适配器一致；在调用时传入 `metadata: { failproofai_sdk_session_id }` 可为该次调用指定会话。

### Vercel AI SDK

AI SDK 从 ES 模块中导出普通函数，而 ES 模块命名空间按规范是不可变的——因此没有可以打补丁的地方。它使用 SDK 自身文档中描述的扩展点：

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // 在 ai 7 上，使用 `telemetry: telemetry({ … })` ——同一对象，新的参数名
});
```

这就是完整的集成：一个 agent span、每个步骤带 token 计数的 model request/response 对，以及所有工具调用。一处调用点适用于所有主版本——`ai` 4–6 读取其携带的 tracer，`ai` 7 则读取 telemetry integration。

`instrument("ai")` 对 **`ai` 7** 实现相同的进程级覆盖：通过 AI SDK 的全局 telemetry-integration 列表覆盖每个调用，该列表是追加式的，不影响其他任何人的配置。

**对于 `ai` 4–6，`instrument("ai")` 本身不会记录任何内容，并会输出一条相应警告。** 这些主版本唯一的进程级钩子是全局 OpenTelemetry tracer provider——该单一插槽一旦被占用，OpenTelemetry 便拒绝再次交出。注册我们的 provider 会静默地拒绝你在启动流程后续调用的 `NodeSDK.start()`，并将你的 http/database span 发送到一个不导出任何数据的 tracer。请在调用处使用 `telemetry()` 或 `wrapModel`。如果该进程本身不运行任何 OpenTelemetry，可通过 `instrument("ai", { registerGlobalTracer: true })` 显式开启：此后会记录所有传入 `experimental_telemetry: { isEnabled: true }` 的调用，且只有在插槽仍为空时才会占用它。`registerGlobalTracer: false` 保持默认行为并静默该警告。

如果你只想包装模型一次，`wrapModel` 仅能看到模型调用，因为工具调用发生在模型层之上。被包装的模型若在没有外层上下文的情况下被调用，会作为独立运行记录。流式调用以流结束的方式关闭——消费者取消时 `stop_reason: "cancelled"`，中途失败时为 `"error"` 并附带错误信息：

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

同时使用两者没有问题：中间件会检测到该调用已在记录中，并自动延后处理，确保每次调用只被记录一次。

`functionId` 用于命名 agent span。请保持其低基数——它会落在 `agent_id` 字段上，而该字段是仪表盘的主要分面维度。

### Next.js

`next build` 默认会将你服务器的依赖打包，被打包进构建产物的框架是 `instrument()` 无法触达的副本。请将配置包裹一次，并从 Next 的启动钩子中调用 `instrument()`：

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* 你的配置 */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` 会将 LangChain、Mastra、LlamaIndex 以及 SDK 本身添加到 `serverExternalPackages`，同时保留你自己的列表。若不使用它，`instrument()` 对于无法触达的每个框架会警告一次，而非静默失败；如果你自行列出了这些包，请设置 `FAILPROOFAI_NEXT_EXTERNALS=1`。Vercel AI SDK 和调用处的辅助函数在任何情况下均可正常工作。Edge 路由会获得一个无操作构建：导入 SDK 是安全的，不会记录任何内容。

### 流式调用的 token 计数

兼容 OpenAI 的 API 只有在客户端明确请求时才会在流中报告用量。LangChain 和 Vercel AI SDK 会自动请求；对于 LlamaIndex，请向其 `OpenAI` LLM 传入 `additionalChatOptions: { stream_options: { include_usage: true } }`；对于 Mastra，请在构建模型时启用 usage（例如 `createOpenAICompatible({ includeUsage: true })`）。否则流式模型调用将不携带 token 计数。

### 运行时

Node ≥ 20.9、Bun 和 Deno——每个框架，以 ES 模块和 CommonJS 两种形式，均在各运行时上对照 Node 的 trace 进行测试。SDK 与 `failproofaid` 守护进程协同运行，由守护进程负责数据传输。

## 自建 agent——不使用框架

适用于你自己编写的 agent 循环，或没有适配器支持的框架。你使用的是与适配器底层相同的 API 来触发事件，因此 trace 具有相同的结构和质量。

你无需了解 agent 的内部组织结构。每个手写 agent 无论函数名称如何，都已具备三个接入点，这三个点就是全部集成所需：

| 位置 | 需要添加的内容 | 触发事件 |
| --- | --- | --- |
| **一次运行**的开始和结束处 | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **调用模型的那个函数** | 调用前 `event.modelRequest`，调用后 `event.modelResponse`——包括失败情况 | 每次模型调用一对 |
| **执行工具的那个函数** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

身份标识是隐式传递的：`agent()` 内部的所有内容都会归属于该运行的会话，无需传入 id，且程序中的其他部分不受任何影响——包括 agent 自身已有的数据库写入逻辑。

- **服务或 worker：** 将你自己的请求或任务 id 作为 `sessionId` 传入，这样仪表盘上的会话与你自己日志或数据库中的记录就会共享同一个字符串。
- **子 agent：** 嵌套 `agent()` 调用。内层 agent 会以 `parent_id` 指向外层 agent 加入同一会话。
- **成对触发事件。** 没有对应 `modelResponse` 的 `modelRequest` 会在仪表盘上显示为永远运行中的 span——这就是为什么要在 `catch` 中也触发响应事件。

代码仓库中的 [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) 是完整可运行的版本：一个真实的 OpenAI 工具循环，按照上述方式接入，以 ES 模块和 CommonJS 两种形式在每次变更时于 CI 中运行。

## 评估

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

有关协议、worker 配置及结果类型的详细说明，请参阅 [Evaluator SDK 参考文档](/zh/reference/evaluator-sdk)。

<Warning>
  **评估函数必须让出控制权。** 永不返回的同步函数会阻塞 Node 唯一的线程，届时任何超时都无法触发。请编写 `async` 评估函数。
</Warning>

## 不会对你的进程做的事

| | |
| --- | --- |
| **阻塞 agent 循环** | 事件进入内存队列，由定时器统一写入。定时器已 `unref`，因此导入本包不会阻止脚本正常退出。 |
| **无限增长** | 队列同时受数量*和*字节数限制。超过任一阈值时，最旧的事件会被丢弃并输出警告——遥测故障不能演变成 OOM 崩溃。 |
| **导致进程崩溃** | 单个无法编码的事件会被单独丢弃，不影响同批次的其他事件。抛出异常的 getter、循环引用、`BigInt`、单独的代理字符：每种情况均会被妥善处理而非向上传播。 |
| **留下写了一半的批次** | 内容在原子重命名前会 `fsync`，目录在重命名后也会 `fsync`，写入失败时会清理临时文件。 |
| **留下可读的会话记录** | 批次文件权限为 `0600`，目录权限为 `0700`。这些文件包含目标、提示词、工具参数和工具输出。 |
| **传输凭据** | API 密钥、token、JWT、bearer 请求头及类似 secret 的赋值在字节写入磁盘前即会被脱敏。守护进程在上传前会再次脱敏。 |
