需要 Node 20.9 或更高版本。支持 ESM 和 CommonJS，无运行时依赖。

<Note>
  本 SDK 与 Python SDK **写入同一个 spool 中的相同事件**。由 Node 智能体和 Python 智能体组成的集群只会产生一组会话，而非两组，Dashboard 中也不会对二者加以区分。请按服务选择，而非按公司统一选择。
</Note>

## 安装

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

框架适配器已内置于包中。这些框架是**可选的 peer 依赖**——声明这些依赖是为了让支持的版本范围可见，不会代您安装，仅在调用 `instrument()` 时才会被导入。

## 连接 Failproof 守护进程

与 Python SDK 相同：在 **settings → api keys** 下创建一个 `events:add` 密钥，然后在智能体所在机器上[连接守护进程](/zh/start/setup#connect-a-machine-to-cloud)。SDK 将数据写入磁盘，守护进程负责传输。

## 配置

### OpenTelemetry spans（需手动开启）

通过 `npm install @opentelemetry/api @opentelemetry/sdk-trace-base` 单独安装 OpenTelemetry，然后将 FailproofAI 添加到您的 provider 处理器中：

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

如果已有现成的 provider，只需将其他处理器也放入同一列表中。暴露了 `addSpanProcessor` 的 provider 可以直接以 `{ provider }` 的形式传入。若不传选项，仅在尚未注册 provider 的情况下才会注册新的 provider。`OtelSpanExporter` 也可直接与您自己的处理器配合使用。

导出通过已连接的 FailproofAI 守护进程进行，SDK 不发送任何网络请求，也不需要密钥或本地监听器。Cloud 中的 [OpenTelemetry 数据接收](/zh/agenteye/opentelemetry)始终处于开启状态。单独调用 `instrument()` 不会启用此导出器。`uninstrument("otel")` 仅禁用其自身的处理器。span 属性的内容由您控制；退出前请务必刷新 provider。OpenTelemetry 仍是可选的应用依赖，而非 SDK 的强制依赖。

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| 选项 | 说明 |
| --- | --- |
| `environment` | 每个事件上的标签，例如 `production`、`staging`、`prod-eu`，默认为 `dev`。 |
| `flushInterval` | 定时器写入磁盘的频率，单位为秒，默认为 `0.5`。 |
| `baseDir` | 写入位置，默认为守护进程的 spool 目录，通常无需修改。 |

只有当所有配置项均通过验证时才会生效，因此若调用被拒绝，SDK 保持原有状态，不会出现 `baseDir` 已更新而间隔未更新的情况。

也可通过环境变量进行设置：

| 变量 | 说明 |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | 无需修改代码即可设置 `environment`，`configure()` 中的同名选项优先级更高。 |
| `FAILPROOFAI_HOME` | 修改存放 spool 的 Failproof AI 根目录。 |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`、`info`、`warn`（默认）、`error`、`silent`。 |
| `FAILPROOFAI_SDK_STRICT` | 设为 `1` 时，接入错误会抛出异常而非仅记录日志。 |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | 设为 `1` 时，框架兼容性问题会抛出异常而非仅警告后继续执行。 |

<Warning>
  **`environment` 中不得包含逗号。** 数据接收会按逗号拆分该字段以构建过滤条件，标签中含有逗号的事件会被静默丢弃——导致整次运行的数据无声无息地消失。请写 `prod-eu`，而非 `prod,eu`。

  `configure({ environment: "prod,eu" })` 会立即抛出异常，让您及时发现问题。`AGENTEYE_ENVIRONMENT` 无法抛出异常——没有调用方可以接收——因此它会警告一次并回退到 `dev`。
</Warning>

通过 `failproofai.setLogger({ debug, info, warn, error })` 可将 SDK 自身的日志输出路由到您的日志系统中。

## 关闭

缓冲的事件会在 `process.on("exit")` 时刷新。

被信号杀死的进程永远不会到达那一步，Node 对 `SIGTERM` 的默认行为是直接终止，不运行退出处理器——因此容器化智能体会丢失最后一个写入间隔尚未写入的数据。

<Warning>
  **本 SDK 不会为您安装信号处理器。** 注册信号处理器会改变进程的行为：监听器会抑制 Node 的默认终止行为，因此若某个库擅自注册了处理器，会导致 Ctrl-C 静默失效。请自行添加：

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

短期脚本或 serverless 处理函数应在返回前 `await failproofai.flush()`——仅靠定时器无法保证数据一定送达。

## 身份标识

每个事件都属于某个会话和某个智能体。**作用域会自动填充这两者**，因此通常无需手动传入：

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

显式传入 `sessionId` 或 `agentId` 同样有效，且优先级更高。若二者均未绑定也未传入，调用会抛出异常，而不是发出一个 Cloud 会静默丢弃的事件。

<Note>
  身份标识基于 `AsyncLocalStorage` 传递，能跟随 `await`、`.then()`、定时器以及在作用域内创建的任何回调。**不能**跟随在某次运行中存储、在另一次运行中调用的回调，也不能跨越 `worker_threads` 边界传递——对于此类情况，请使用 `failproofai.propagate()` 进行包装，否则相关事件将无法关联到正确的运行。
</Note>

### 作用域

| 作用域 | 触发事件 | 返回值 |
| --- | --- | --- |
| `session(body)` | 无——仅传递身份标识 | `body` 的返回值 |
| `agent(id, options?, body)` | `agent_start`，然后 `agent_end` | `body` 的返回值 |
| `toolCall(name, options?, body)` | `tool_use`，然后 `tool_result` | `body` 的返回值 |

同步的 body 保持同步：`agent("x", () => 1)` 返回 `1`，而非 Promise。

`toolCall` 会将 body 的 resolved 值记录为工具的 `output`，除非您手动赋值给 `call.output`。

<Accordion title="退出语义" icon="arrow-right-from-bracket">

| 情况 | 事件 | `outcome` |
| --- | --- | --- |
| 代码块正常返回 | `agent_end` | `"success"` 或您自定义的 `outcome` |
| 代码块抛出异常 | `error`，然后 `agent_end` | `"failed"` |
| 抛出 `AbortError` | 仅 `agent_end` | `"cancelled"` |

错误始终会被重新抛出。

工具调用失败记录在叶节点上——`tool_result` 携带 `error` 字符串——**不会**触发运行级别的 `error` 事件。被智能体循环捕获的错误不属于运行失败；向上传播的错误由外层的 `agent()` 准确记录一次。

</Accordion>

<Accordion title="`using` 形式" icon="brackets-curly">

当工作流程不是单一函数时——例如在构造函数中打开作用域、在销毁逻辑中关闭，或跨越现有控制流：

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result，然后 agent_end
```

两种形式生成字节完全相同的事件。推荐使用回调形式：它在 `AsyncLocalStorage.run()` 内部执行，无需手动清理，从根本上避免了"在此处打开、在彼处关闭"的 bug。

捕获了自身异常的 `using` 块应通过 `span.fail(error)` 上报错误——disposer 本身没有异常传递通道。

</Accordion>

## 事件目录

与 Python SDK 相同的十五个方法，采用 camelCase 命名。大多数方法**成对出现**——调用开始方法，再调用结束方法，SDK 会自动计算时间间隔。

| | 开始 | 结束 |
| --- | --- | --- |
| **智能体** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **模型** | `modelRequest` | `modelResponse` |
| **工具** | `toolUse` | `toolResult` |
| **Hook** | `hookTriggered` | `hookCompleted` |
| **人工** | `humanWait` | `humanInput` |

三个独立方法：`error`、`humanPause`、`humanInterrupt`。

<Accordion title="每个方法的所有字段" icon="table">

每个方法还接受 `sessionId` 和 `agentId`，作用域会自动填充。省略的字段会被直接丢弃，不会以 JSON `null` 的形式发送。

| 方法 | 必填 | 可选 |
| --- | --- | --- |
| `agentStart` | — | `goal`、`parentId` |
| `agentEnd` | — | `outcome`、`summary` |
| `agentPause` | `pauseId` | `reason`、`userId` |
| `agentResume` | `pauseId` | `reason`、`userId` |
| `modelRequest` | — | `model`、`messages`、`system`、`tools`、`requestId` |
| `modelResponse` | — | `model`、`stopReason`、`inputTokens`、`outputTokens`、`content`、`role`、`requestId` |
| `toolUse` | `toolName`、`toolCallId` | `input` |
| `toolResult` | `toolName`、`toolCallId` | `output`、`error` |
| `hookTriggered` | `hookName`、`hookId` | `triggerEvent`、`input` |
| `hookCompleted` | `hookName`、`hookId` | `outcome`、`output`、`error` |
| `error` | `errorType`、`message` | `traceback` |
| `humanWait` | `inputId` | `prompt`、`options`、`reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`、`userId` |
| `humanInterrupt` | — | `reason`、`userId`、`atStep` |

您添加的其他任何键都会成为自定义 payload 字段。框架专属字段请以 `fw_*` 命名；与已声明字段同名的键会被拒绝，而不会静默覆盖已提升的列。

</Accordion>

<Warning>
  **`duration_ms` 由系统计算，不接受外部传入。** 四个结束方法会自动计算与开始方法之间的时间间隔，并拒绝调用方传入的 `duration_ms`——上报的时长必须无法被伪造。

  配对是在**会话**和 id 上进行匹配的，与智能体无关。在 `planner` 下打开、在 `worker` 下关闭的工具调用依然能正确配对，这正是嵌套多智能体运行的实际行为。
</Warning>

## 框架适配器

```ts
await failproofai.instrument();              // 自动检测所有可用框架
await failproofai.instrument("langchain");   // 仅指定一个
failproofai.uninstrument();                  // 恢复所有原始状态
```

| 框架 | 支持版本 | 接入方式 |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x，LangGraph.js 0.4 – 1.x | `CallbackManager.configure`，因此每个 `invoke`/`stream`/`batch` 调用都会被覆盖，无需在任何地方传入 `callbacks:`——或者自行传入 `langchainHandler()` 而不进行任何 patch。 |
| **Vercel AI SDK** | `ai` 4 – 7 | 在调用处使用 `telemetry()`，或通过 `instrument("ai")` 对 `ai` 7 进行全进程接入（对于 4–6 版本需手动开启——见下文）。 |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`、智能体的模型与工具解析，以及工作流运行/步骤引擎。 |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager`（订阅式）加 `AgentWorkflow.runStream`，覆盖工作流运行及其步骤。 |

每个版本范围均会针对真实框架发布版本进行测试，涵盖两端边界，以 ES module 和 CommonJS 两种形式，在每次 CI 运行时执行。

映射关系与 Python SDK 一致，因此同一程序无论用哪种语言都能在 Dashboard 中绘制出相同的结构树。只有拥有 LLM 决策循环的构造才是**智能体**——图或链的运行、AI SDK 的 `generateText`/`streamText` 调用、Mastra 智能体、LlamaIndex 智能体运行。LangGraph 节点或工作流步骤是 **hook**（`hook_triggered`/`hook_completed`），而非嵌套智能体。模型调用以 `model_request`/`model_response` 配对形式记录并附带 token 数量；工具调用携带模型自身的 tool call id。每次错误只在发生的事件上记录一次。

适配器安装失败时会记录日志并跳过；其他适配器仍会继续安装，因为 LlamaIndex 出错不应影响 LangGraph 的接入。

<Note>
  不带参数的 `instrument()` 通过**模块是否能被解析**来检测框架，而非检测其是否已被导入——Node 对 ES module 没有等效于 Python `sys.modules` 的机制。已安装但未使用的框架会被导入并打 patch。如果这一点对您有影响，请明确指定所需框架名称。
</Note>

<Note>
  大多数这些框架同时提供 ES module 构建和 CommonJS 构建，Node 会将它们作为两个无关的副本加载。适配器会对您的应用程序加载的副本进行 patch（如果某些代码已经 `require` 过，也会对 CommonJS 副本进行 patch），因此两种模块系统均可正常工作。**被 esbuild 或 webpack 打包进您自己的输出的框架**则无法触达——请在此类场景中使用调用处的辅助函数：`langchainHandler()`、`telemetry()`、`wrapTool()`。
</Note>

### 不 patch 情况下使用 LangChain

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

该处理器无论是否调用 `instrument()` 均可正常工作，且不会重复记录。`instrument("langchain")` 接受 `sessionId`、`captureContent`、`includeChains`、`graphCallbacks` 和 `captureLimit` 参数，与 Python 适配器一致；在某次调用的元数据中传入 `metadata: { failproofai_sdk_session_id }` 可为该次调用指定会话。

### Vercel AI SDK

AI SDK 从 ES module 中导出纯函数，ES module 命名空间根据规范是不可变的——没有地方可以进行 patch。接入方式采用 SDK 自身文档中记录的扩展点：

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // 对于 ai 7，使用 `telemetry: telemetry({ … })` ——同一个对象，新的参数名
});
```

这就是完整的接入方式：一个智能体 span、每步一对携带 token 数量的模型请求/响应，以及所有工具调用。同一个调用处写法适用于所有主要版本——`ai` 4–6 读取其携带的 tracer，`ai` 7 读取 telemetry 集成。

**对于 `ai` 7**，`instrument("ai")` 通过 AI SDK 的全局 telemetry 集成列表实现全进程接入，该列表是追加式的，不会影响其他人的配置。

**对于 `ai` 4–6，`instrument("ai")` 本身不会记录任何内容，并会输出一条相应的警告。** 这些主要版本唯一的全进程 hook 是全局 OpenTelemetry tracer provider——这是一个单一插槽，OpenTelemetry 一旦被占用就拒绝交出。注册我们的 tracer 会在启动后期静默拒绝您自己的 `NodeSDK.start()` 调用，并将您的 http/数据库 span 发送到一个不导出任何内容的 tracer。请在调用处使用 `telemetry()`，或在那里使用 `wrapModel`。如果进程本身不运行任何 OpenTelemetry，可以通过 `instrument("ai", { registerGlobalTracer: true })` 选择启用：这样每个传入了 `experimental_telemetry: { isEnabled: true }` 的调用都会被记录，且仅在插槽仍为空时才会占用它。`registerGlobalTracer: false` 保持默认行为并静默忽略该警告。

如果您希望只包装模型一次，`wrapModel` 仅能看到模型调用，因为工具调用发生在模型层之上。被包装的模型在没有外层包装的情况下调用时，会被记录为其自身的一次运行。流式调用的结束方式取决于流的停止方式——消费者取消时为 `stop_reason: "cancelled"`，中途失败时为带有错误信息的 `"error"`：

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

同时使用两者没有问题：中间件会检测到该调用已被记录并自动让位，每次调用只会被记录一次。

`functionId` 用于命名智能体 span，请保持低基数——它会落入 `agent_id`，这是 Dashboard 的主要分面维度。

### Next.js

`next build` 默认会将服务端依赖打包，被打包进构建产物的框架是 `instrument()` 无法触达的副本。请一次性包装配置，并从 Next 的启动 hook 中调用 `instrument()`：

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* 您的配置 */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` 会将 LangChain、Mastra、LlamaIndex 和 SDK 本身添加到 `serverExternalPackages` 中，同时保留您已有的列表。若未使用该函数，`instrument()` 会对每个无法触达的框架发出一次警告，而不是静默失败；如果您已自行列出相关包，请设置 `FAILPROOFAI_NEXT_EXTERNALS=1`。Vercel AI SDK 和调用处辅助函数无论哪种方式均可正常使用。Edge 路由会获得一个无操作构建：导入 SDK 是安全的，但不会记录任何内容。

### 流式调用的 token 统计

兼容 OpenAI 的 API 只有在客户端明确请求时才会在流中报告用量。LangChain 和 Vercel AI SDK 会自动请求；对于 LlamaIndex，请向其 `OpenAI` LLM 传入 `additionalChatOptions: { stream_options: { include_usage: true } }`；对于 Mastra，请在构建模型时启用用量统计（例如 `createOpenAICompatible({ includeUsage: true })`）。否则流式模型调用将不携带 token 数量。

### 运行时

Node ≥ 20.9、Bun 和 Deno——每个框架，以 ES module 和 CommonJS 两种形式，均会在各运行时上与 Node 的 trace 进行对比测试。SDK 与 `failproofaid` 守护进程协同运行，由守护进程负责传输写入的数据。

## 自建智能体——无框架

适用于自己编写的智能体循环，或尚无适配器的框架。您使用与适配器底层相同的 API 触发事件，因此 trace 结构和质量与适配器方式完全一致。

您无需了解智能体的内部组织结构。每个手工构建的智能体都有三个位置，无论其函数名称如何，这三处就是完整的接入点：

| 位置 | 需要添加的内容 | 触发事件 |
| --- | --- | --- |
| **一次运行**的开始和结束处 | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **调用模型的那个函数** | 调用前 `event.modelRequest`，调用后 `event.modelResponse`——包括失败情况，两个都要 | 每次模型调用一对 |
| **执行工具的那个函数** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

身份标识是环境感知的：`agent()` 内部的所有内容都会自动归属到该运行的会话，无需传入 id，程序中的其他部分也不会受到任何影响——包括智能体已有的数据库写入逻辑。

- **服务或 worker：** 将您自己的请求或任务 id 作为 `sessionId` 传入，这样 Dashboard 上的会话与您自己的日志或数据库中的记录是同一个字符串。
- **子智能体：** 嵌套 `agent()` 调用。内层调用会以外层为 `parent_id` 加入同一会话。
- **成对触发事件。** 没有对应 `modelResponse` 的 `modelRequest` 会在 Dashboard 中显示为永远运行中的 span——这就是加 `catch` 的原因。

代码仓库中的 [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) 是完整可运行的版本：一个真实的 OpenAI 工具循环，按照完全相同的方式接入，以 ES module 和 CommonJS 两种形式在每次变更时于 CI 中运行。

## 评估

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \

<Warning>
  **评估函数必须让出执行权。** 永不返回的同步函数会阻塞 Node 唯一的线程，届时任何超时都无法触发。请编写 `async` 评估函数。
</Warning>

## 对您的进程无影响的方面

| | |
| --- | --- |
| **不阻塞智能体循环** | 事件进入内存队列，由定时器写入磁盘。定时器已 `unref`，因此导入本包不会阻止脚本正常退出。 |
| **不无限增长** | 队列同时受数量*和*字节大小的限制。超过任一限制时，最旧的事件会被丢弃并输出警告——遥测中断不能导致 OOM 崩溃。 |
| **不导致进程崩溃** | 单个无法编码的事件会被单独丢弃，不影响周围的批次。抛出异常的 getter、循环引用、`BigInt`、孤立代理项：每种情况都会被妥善处理而非向上传播。 |
| **不留下半写批次** | 内容在原子重命名前会 `fsync`，目录在重命名后会 `fsync`，写入失败时会清理临时文件。 |
| **不让日志文件可被随意读取** | 批次文件权限为 `0600`，存放在权限为 `0700` 的目录中。这些文件包含目标、提示词、工具参数和工具输出。 |
| **不上传凭据** | API 密钥、令牌、JWT、Bearer 请求头及形似密钥的赋值语句在写入磁盘前会被脱敏处理。守护进程在上传前会再次脱敏。 |
