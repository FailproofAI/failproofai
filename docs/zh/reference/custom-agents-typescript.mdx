需要 Node 20.9 或更高版本。支持 ESM 和 CommonJS，无运行时依赖。

<Note>
  本 SDK 与 Python SDK **写入同一个 spool 中的相同事件**。由 Node agent 和 Python agent 组成的集群只会产生一套会话记录，而非两套，且 Dashboard 中不会对它们加以区分。请按服务选择语言，而非按公司统一选定。
</Note>

## 安装

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

框架适配器已内置于包中。这些框架均为**可选的 peer 依赖**——声明它们是为了让支持的版本范围可见，不会代你安装，仅在你调用 `instrument()` 时才会被引入。

## 连接 Failproof 守护进程

与 Python SDK 相同：在 **Admin → Keys** 下创建一个 `events:add` 密钥，然后在 agent 机器上[连接守护进程](/zh/start/setup#connect-a-machine-to-cloud)。SDK 负责写入磁盘；守护进程负责上传。

## 配置

### OpenTelemetry spans（需手动开启）

通过 `npm install @opentelemetry/api @opentelemetry/sdk-trace-base` 单独安装 OpenTelemetry。
然后将 FailproofAI 添加到你的 provider 处理器中：

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

如果已有 provider，只需将其他处理器与上述处理器放在同一个列表中。对于提供 `addSpanProcessor` 方法的 provider，也可以直接以 `{ provider }` 的形式传入。若不传入任何选项，仅当尚未注册 provider 时，才会注册一个新的 provider。
`OtelSpanExporter` 也可以直接与你自定义的处理器配合使用。

导出通过已连接的 FailproofAI 守护进程进行；SDK 不发送任何网络请求，也不需要密钥或本地监听器。请联系管理员启用 [OpenTelemetry 数据接入](/zh/agenteye/opentelemetry)。单独调用 `instrument()` 不会启用该导出器。`uninstrument("otel")` 仅禁用其自身的处理器。内容捕获由你的 span 属性控制；退出前请确保 flush 你的 provider。OpenTelemetry 仍为可选的应用依赖，而非 SDK 的强制依赖。

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| 选项 | 说明 |
| --- | --- |
| `environment` | 附加到每个事件上的标签，如 `production`、`staging`、`prod-eu`，默认为 `dev`。 |
| `flushInterval` | 定时器写入磁盘的频率，单位为秒，默认为 `0.5`。 |
| `baseDir` | 写入目录，默认为守护进程的 spool 目录，通常无需修改。 |

只有当所有配置项均通过验证时才会生效，因此一次失败的调用不会造成 `baseDir` 已更新而间隔未更新的不一致状态。

也可以通过环境变量进行配置：

| 变量 | 说明 |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | 无需修改代码即可设置 `environment`。`configure()` 中的选项优先级更高。 |
| `FAILPROOFAI_HOME` | 修改 Failproof AI 根目录（包含 spool）的位置。 |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`、`info`、`warn`（默认）、`error`、`silent`。 |
| `FAILPROOFAI_SDK_STRICT` | 设为 `1` 时，接入错误将抛出异常而非记录日志。 |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | 设为 `1` 时，框架兼容性问题将抛出异常而非仅警告后继续运行。 |

<Warning>
  **`environment` 中不能包含逗号。** 数据接入层会按逗号分割该字段以构建过滤器，包含逗号的标签对应的所有事件都会被静默丢弃——整个运行记录就此消失。请写 `prod-eu`，而不是 `prod,eu`。

  `configure({ environment: "prod,eu" })` 会立即抛出异常，让你第一时间发现问题。`AGENTEYE_ENVIRONMENT` 无法抛出异常——没有地方可以通知你——因此它只会警告一次并回退到 `dev`。
</Warning>

通过 `failproofai.setLogger({ debug, info, warn, error })` 可将 SDK 自身的日志输出路由到你的日志系统中。

## 关闭

缓冲的事件会在 `process.on("exit")` 时 flush。

被信号终止的进程永远不会触发该回调，而 Node 对 `SIGTERM` 的默认行为是直接终止，不运行退出处理器——因此容器化 agent 会丢失上一个写入间隔尚未写入的所有事件。

<Warning>
  **本 SDK 不会为你安装信号处理器。** 注册信号处理器会改变进程行为：添加监听器会阻止 Node 的默认终止行为，因此一个库如果私自注册，会悄悄让 Ctrl-C 失效。请自行添加：

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

对于短生命周期的脚本或 serverless 处理器，应在返回前 `await failproofai.flush()`——仅靠定时器无法保证事件必然送达。

## 身份标识

每个事件都属于某个会话和某个 agent。**作用域会自动填充这两者**，因此通常无需手动传入：

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

显式传入 `sessionId` 或 `agentId` 同样有效，且优先级更高。若两者均未绑定也未传入，调用会抛出异常，而不是发出一个 Cloud 会静默丢弃的事件。

<Note>
  身份标识基于 `AsyncLocalStorage` 传递，能跟随 `await`、`.then()`、定时器以及在作用域内创建的任何回调。但**不能**跟随在一次运行中存储、在另一次运行中调用的回调，也无法跨越 `worker_threads` 边界——对这类情况请使用 `failproofai.propagate()` 进行包装，否则相关事件将无法关联到正确的会话。
</Note>

### 作用域

| 作用域 | 发送事件 | 返回值 |
| --- | --- | --- |
| `session(body)` | 无——仅设置身份标识 | `body` 的返回值 |
| `agent(id, options?, body)` | `agent_start`，然后 `agent_end` | `body` 的返回值 |
| `toolCall(name, options?, body)` | `tool_use`，然后 `tool_result` | `body` 的返回值 |

同步的 body 保持同步：`agent("x", () => 1)` 返回 `1`，而非 Promise。

`toolCall` 会将 body 的 resolved 值作为工具的 `output` 记录，除非你自行为 `call.output` 赋值。

<Accordion title="退出语义" icon="arrow-right-from-bracket">

| 情形 | 事件 | `outcome` |
| --- | --- | --- |
| 代码块正常返回 | `agent_end` | `"success"`，或你指定的 `outcome` |
| 代码块抛出异常 | `error`，然后 `agent_end` | `"failed"` |
| 抛出 `AbortError` | 仅 `agent_end` | `"cancelled"` |

错误总会被重新抛出。

工具失败记录在叶节点上——`tool_result` 携带 `error` 字符串——**不会**产生运行级别的 `error` 事件。被 agent 循环捕获的错误不算运行失败；向上传播的错误由外层 `agent()` 恰好报告一次。

</Accordion>

<Accordion title="`using` 形式" icon="brackets-curly">

当工作不是单一函数时——例如作用域在构造函数中打开、在析构函数中关闭，或横跨现有控制流——可使用以下形式：

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

两种形式发出的事件字节完全相同。建议优先使用回调形式：它在 `AsyncLocalStorage.run()` 内部执行，无需手动展开，从根本上避免了「在这里打开、在那里关闭」这类 bug。

如果 `using` 块自行捕获了失败，需通过 `span.fail(error)` 上报——disposer 本身没有异常传递通道。

</Accordion>

## 事件目录

与 Python SDK 相同的十五个方法，采用 camelCase 命名。大多数以**配对**形式出现——调用开始方法，再调用结束方法，SDK 会自动计算时间间隔。

| | 开始 | 结束 |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **模型** | `modelRequest` | `modelResponse` |
| **工具** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **人工** | `humanWait` | `humanInput` |

三个独立方法：`error`、`humanPause`、`humanInterrupt`。

<Accordion title="每个方法的完整字段" icon="table">

每个方法还接受 `sessionId` 和 `agentId`，作用域会自动填充这两个字段。省略的字段会被直接丢弃，而不是以 JSON `null` 的形式发送。

| 方法 | 必填 | 可选 |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

你添加的任何其他键都会成为自定义 payload 字段。框架专用字段请以 `fw_*` 命名；与已声明字段同名的键会被拒绝，而不会静默覆盖已提升为列的字段。

</Accordion>

<Warning>
  **`duration_ms` 由系统计算，不接受外部传入。** 四个结束方法会自动计算与对应开始方法之间的时间间隔，并拒绝调用方提供的 `duration_ms`——上报的耗时必须是不可伪造的。

  配对匹配基于**会话**和 id，与 agent 无关。在 `planner` 下打开、在 `worker` 下关闭的工具仍然能够正确配对，这正是嵌套多 agent 运行的实际工作方式。
</Warning>

## 框架适配器

```ts
await failproofai.instrument();              // 自动检测所有可用框架
await failproofai.instrument("langchain");   // 仅指定一个框架
failproofai.uninstrument();                  // 还原所有修改
```

| 框架 | 支持版本 | 接入方式 |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x，LangGraph.js 0.4 – 1.x | 通过 `CallbackManager.configure` 接入，所有 `invoke`/`stream`/`batch` 调用均自动覆盖，无需在任何地方传入 `callbacks:`——也可手动传入 `langchainHandler()` 而不进行任何 patch。 |
| **Vercel AI SDK** | `ai` 4 – 7 | 在调用处使用 `telemetry()`，或通过 `instrument("ai")` 对 `ai` 7 实现全进程覆盖（在 4–6 版本中需手动开启，详见下文）。 |
| **Mastra** | `@mastra/core` 0.20 – 1.x | 覆盖 `Agent.generate`/`.stream`、agent 的模型与工具解析，以及工作流的运行/步骤引擎。 |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | 通过 `Settings.callbackManager`（订阅方式）以及 `AgentWorkflow.runStream` 接入，涵盖工作流运行及其步骤。 |

每个版本范围均会针对真实的框架发布版本——包括两端边界——以 ES module 和 CommonJS 两种方式，在每次 CI 运行时进行测试。

映射规则与 Python SDK 相同，因此同一程序在两种语言中绘制出相同的调用树。只有拥有 LLM 决策循环的构件才被视为 **agent**——包括 graph 或 chain 运行、AI SDK 的 `generateText`/`streamText` 调用、Mastra agent 以及 LlamaIndex agent 运行。LangGraph 节点或工作流步骤是 **hook**（`hook_triggered`/`hook_completed`），而非嵌套 agent。模型调用以携带 token 数量的 `model_request`/`model_response` 配对形式记录；工具调用携带模型自身的 tool call id。失败仅记录一次，位于发生失败的事件上。

适配器安装失败时会记录日志并跳过，其他适配器仍会正常安装——LlamaIndex 出错不应影响 LangGraph 的接入。

<Note>
  不带参数的 `instrument()` 通过模块是否**可解析**来检测框架，而非是否已经被导入——Node 对 ES module 没有类似 Python `sys.modules` 的等价机制。已安装但未使用的框架会被导入并打补丁。如果这一点很重要，请明确指定你需要的框架名称。
</Note>

<Note>
  大多数框架同时提供 ES module 构建和 CommonJS 构建，Node 会将它们视为两个独立副本加载。适配器会对你的应用实际加载的副本打补丁（如果已有代码 `require` 过，也会对 CommonJS 副本打补丁），因此两种模块系统均可正常工作。**被 esbuild 或 webpack 打包进你自己输出产物**的框架无法被 patch——此时请使用调用处的辅助函数：`langchainHandler()`、`telemetry()`、`wrapTool()`。
</Note>

### 不 patch 的 LangChain 接入方式

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

该 handler 无论是否调用 `instrument()` 都能正常工作，且不会重复记录。`instrument("langchain")` 接受 `sessionId`、`captureContent`、`includeChains`、`graphCallbacks` 和 `captureLimit` 参数，与 Python 适配器一致；在调用时通过 `metadata: { failproofai_sdk_session_id }` 可为该次调用指定会话。

### Vercel AI SDK

AI SDK 从 ES module 中导出纯函数，而 ES module 命名空间在规范层面是不可变的——没有地方可以打补丁。因此接入方式使用 SDK 官方文档中提到的扩展点：

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // 在 ai 7 中，使用 `telemetry: telemetry({ … })` ——同一个对象，新的参数名
});
```

这就是完整的接入方式：一个 agent span、每个步骤一对携带 token 数量的模型请求/响应，以及所有工具调用。同一个调用处代码在所有主版本上均可工作——`ai` 4–6 读取其携带的 tracer，`ai` 7 读取 telemetry integration。

**在 `ai` 7 上，** `instrument("ai")` 通过 AI SDK 的全局 telemetry-integration 列表实现进程级覆盖：该列表是累加的，不会影响其他人的配置。

**在 `ai` 4–6 上，`instrument("ai")` 本身不记录任何内容，并会打印一条相关警告。** 这些主版本唯一的进程级 hook 是全局 OpenTelemetry tracer provider——这是一个单一槽位，一旦被占用，OpenTelemetry 便不会再将其释放。注册我们的 provider 会静默阻止你后续启动时调用的 `NodeSDK.start()`，并将你的 http/database span 发送到一个不导出任何数据的 tracer。请在调用处使用 `telemetry()`，或在那里使用 `wrapModel`。如果该进程本身不运行任何 OpenTelemetry，可通过 `instrument("ai", { registerGlobalTracer: true })` 手动开启：此时会记录所有传入 `experimental_telemetry: { isEnabled: true }` 的调用，并且仅在槽位仍为空时才会占用它。`registerGlobalTracer: false` 保持默认行为并静默该警告。

如果你只想包装一次模型，`wrapModel` 仅能看到模型调用，因为工具调用发生在模型层之上。被包装的模型若在没有外层 agent 的情况下被调用，会被记录为独立的一次运行。流式调用在流结束时关闭——消费方取消时为 `stop_reason: "cancelled"`，中途失败时为带有错误信息的 `"error"`：

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

同时使用两者没有问题：中间件会检测到该调用已被记录并自动让步，因此每次调用只会被记录一次。

`functionId` 用于命名 agent span，请保持低基数——它会落入 `agent_id`，这是 Dashboard 的主要分面维度。

### Next.js

`next build` 默认会将服务端依赖打包，被打包进构建产物的框架是 `instrument()` 无法触达的副本。请在配置中包裹一次，并从 Next 的启动 hook 中调用 `instrument()`：

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` 会将 LangChain、Mastra、LlamaIndex 以及 SDK 本身加入 `serverExternalPackages`，同时保留你自己的列表。若没有该配置，`instrument()` 会对每个无法触达的框架打印一次警告而非静默失败；如果你自行列出了这些包，请设置 `FAILPROOFAI_NEXT_EXTERNALS=1`。Vercel AI SDK 和调用处辅助函数无论如何都可以正常使用。Edge 路由会获得一个无操作的构建：导入 SDK 是安全的，不会记录任何内容。

### 流式调用的 token 统计

兼容 OpenAI 的 API 只有在客户端明确请求时才会在流中上报用量。LangChain 和 Vercel AI SDK 会自动请求；对于 LlamaIndex，请向其 `OpenAI` LLM 传入 `additionalChatOptions: { stream_options: { include_usage: true } }`；对于 Mastra，请在构建模型时启用用量统计（例如 `createOpenAICompatible({ includeUsage: true })`）。否则流式模型调用将不携带 token 数量。

### 运行时

Node ≥ 20.9、Bun 和 Deno——每个框架，以 ES module 和 CommonJS 两种形式，均在各运行时上针对 Node 的 trace 进行测试。SDK 与 `failproofaid` 守护进程协同运行，由守护进程负责上传其写入的数据。

## 自建 agent——不使用框架

适用于你自己编写 agent 循环，或使用没有适配器的框架的情况。你使用适配器底层相同的 API 来发送事件，因此 trace 具有相同的结构和质量。

你无需了解 agent 的内部组织方式。无论函数叫什么名字，每个手写的 agent 都有三个固定位置，这三处就是完整的接入点：

| 位置 | 需要添加的内容 | 发送事件 |
| --- | --- | --- |
| **一次运行**的开始和结束处 | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **调用模型的函数** | 调用前发送 `event.modelRequest`，调用后发送 `event.modelResponse`——即使失败也要发送两者 | 每次模型调用一对事件 |
| **执行工具的函数** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

身份标识是环境感知的：`agent()` 内部的所有内容都会自动归属到该运行的会话，无需手动传入 id，且程序中的其他部分不受任何影响——包括 agent 自身已有的数据库写入逻辑。

- **服务或 Worker：** 将你自己的请求或任务 id 作为 `sessionId` 传入，使 Dashboard 上的会话与你自己的日志或数据库中的记录共享同一个字符串。
- **子 agent：** 嵌套调用 `agent()`，内层调用会以外层为 `parent_id` 加入同一会话。
- **发送成对事件。** 没有对应 `modelResponse` 的 `modelRequest` 会在 Dashboard 上显示为永远运行中的 span——这就是为什么需要 `catch`。

仓库中的 [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) 是完整可运行的版本：一个真实的 OpenAI 工具循环，完全按照上述方式接入，并在每次变更时以 ES module 和 CommonJS 两种形式在 CI 中运行。

## 评估

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \

## SDK 对你的进程的承诺

| | |
| --- | --- |
| **不阻塞 agent 循环** | 事件进入内存队列，由定时器写入磁盘。定时器已 `unref`，因此导入本包不会阻止脚本正常退出。 |
| **不无限增长** | 队列同时受数量*和*字节数限制。超出任一限制时，最旧的事件会被丢弃并打印警告——遥测中断不能变成 OOM 崩溃。 |
| **不导致进程崩溃** | 单个无法编码的事件会被单独丢弃，不影响同批次的其他事件。抛出异常的 getter、循环引用、`BigInt`、单独的代理字符：每种情况都会被妥善处理而非向外传播。 |
| **不留下半写入的批次** | 内容在原子重命名前会 `fsync`，目录在重命名后会 `fsync`，写入失败时会清理临时文件。 |
| **不让转录内容可被任意读取** | 批次文件权限为 `0600`，存放于权限为 `0700` 的目录中。这些文件包含目标、提示词、工具参数和工具输出。 |
| **不上传凭证** | API 密钥、token、JWT、bearer header 以及形如密钥的赋值语句，在字节到达磁盘前会被脱敏处理。守护进程在上传前会再次脱敏。 |
