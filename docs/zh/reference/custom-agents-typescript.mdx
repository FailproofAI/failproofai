需要 Node 20.9 或更高版本。支持 ESM 和 CommonJS，无运行时依赖。

<Note>
  本 SDK 与 Python SDK **写入同一个 spool 中的相同事件**。由 Node 智能体和 Python 智能体混合组成的集群只会产生一组会话，而非两组，Dashboard 中也无法区分它们。请按服务选择语言，而非按公司统一。
</Note>

## 安装

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

框架适配器已内置于包中。这些框架是**可选的 peer 依赖**——声明它们是为了让支持的版本范围可见，不会代您安装，仅在调用 `instrument()` 时才会导入。

## 连接 Failproof 守护进程

与 Python SDK 相同：在 **Admin → Keys** 下创建一个 `events:add` 密钥，然后在智能体所在机器上[连接守护进程](/zh/start/setup#connect-a-machine-to-cloud)。SDK 负责写入磁盘，守护进程负责发送数据。

## 配置

### OpenTelemetry spans（需手动开启）

通过 `npm install @opentelemetry/api @opentelemetry/sdk-trace-base` 单独安装 OpenTelemetry。
然后将 FailproofAI 添加到您的 provider 处理器中：

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

如果已有 provider，只需将其他处理器保留在同一列表中。暴露了 `addSpanProcessor` 方法的 provider 也可以通过 `{ provider }` 的形式传入。如果不传入任何选项，仅当尚未注册任何 provider 时才会注册新 provider。`OtelSpanExporter` 也可以直接搭配您自己的处理器使用。

导出数据通过已连接的 FailproofAI 守护进程进行，SDK 本身不发送任何网络请求，也不需要密钥或本地监听器。请联系管理员启用 [OpenTelemetry 数据摄取](/zh/agenteye/opentelemetry)。单独调用 `instrument()` 不会启用该导出器。`uninstrument("otel")` 仅禁用其自身的处理器。内容捕获由您的 span 属性控制；退出前请务必 flush 您的 provider。OpenTelemetry 保持为可选的应用依赖，而非 SDK 的强制依赖。

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| 选项 | 作用 |
| --- | --- |
| `environment` | 每个事件上的标签，例如 `production`、`staging`、`prod-eu`。默认值为 `dev`。 |
| `flushInterval` | 定时器写入磁盘的频率，单位为秒。默认值为 `0.5`。 |
| `baseDir` | 写入位置。默认为守护进程的 spool 目录，除非您明确需要更改，否则保持默认即可。 |

只有所有参数均通过验证，配置才会生效。若调用被拒绝，SDK 的状态将保持不变，不会出现 `baseDir` 已更新但 interval 仍为旧值的情况。

也可以通过环境变量进行配置：

| 变量 | 作用 |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | 无需修改代码即可设置 `environment`。`configure()` 中的选项优先级更高。 |
| `FAILPROOFAI_HOME` | 修改 Failproof AI 根目录（包含 spool）的位置。 |
| `FAILPROOFAI_SDK_LOG_LEVEL` | 可选值：`debug`、`info`、`warn`（默认）、`error`、`silent`。 |
| `FAILPROOFAI_SDK_STRICT` | 设为 `1` 时，接入错误将抛出异常而非仅记录日志。 |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | 设为 `1` 时，框架兼容性问题将抛出异常，而非仅警告后继续运行。 |

<Warning>
  **`environment` 中不能包含逗号。** 数据摄取会按逗号分割该字段以构建过滤器，标签中含有逗号的事件会被静默丢弃——整个运行记录就此消失。请写 `prod-eu`，而非 `prod,eu`。

  `configure({ environment: "prod,eu" })` 会立即抛出异常，让您及时发现问题。`AGENTEYE_ENVIRONMENT` 无法抛出异常——没有调用方可以接收——因此它只会警告一次并回退到 `dev`。
</Warning>

通过 `failproofai.setLogger({ debug, info, warn, error })` 可将 SDK 自身的日志输出路由到您的日志系统中。

## 关闭

缓冲的事件会在 `process.on("exit")` 时刷新。

被信号终止的进程永远不会到达那一步，而 Node 对 `SIGTERM` 的默认处理是直接终止进程，不运行退出处理程序——因此容器化的智能体会丢失最后一个写入周期内尚未写出的数据。

<Warning>
  **本 SDK 不会为您安装信号处理器。** 注册信号处理器会改变进程的行为：添加监听器会阻止 Node 的默认终止行为，这样一个擅自注册的库会悄无声息地让 Ctrl-C 失效。请自行添加：

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

短期脚本或 serverless 处理器在返回前应执行 `await failproofai.flush()`——仅靠定时器无法保证数据已全部投递。

## 身份标识

每个事件都属于某个会话和某个智能体。**作用域会自动填充这两项**，因此您通常不需要手动传入：

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

显式传入 `sessionId` 或 `agentId` 同样有效，且优先级更高。如果两者都未绑定也未传入，调用将抛出异常，而不是发出一个会被 Cloud 静默丢弃的事件。

<Note>
  身份标识基于 `AsyncLocalStorage` 传递，能够跟随 `await`、`.then()`、定时器以及在作用域内创建的任何回调。它**无法**跟随在某次运行期间存储、在另一次运行期间调用的回调，也无法跨越 `worker_threads` 边界传递——对这类情况请使用 `failproofai.propagate()` 进行包装，否则相关事件将无法关联到正确的会话。
</Note>

### 作用域

| 作用域 | 发出的事件 | 返回值 |
| --- | --- | --- |
| `session(body)` | 无——仅设置身份标识 | `body` 的返回值 |
| `agent(id, options?, body)` | `agent_start`，然后 `agent_end` | `body` 的返回值 |
| `toolCall(name, options?, body)` | `tool_use`，然后 `tool_result` | `body` 的返回值 |

同步函数体保持同步：`agent("x", () => 1)` 返回 `1`，而非 Promise。

`toolCall` 会将函数体的 resolved 值作为工具的 `output` 记录，除非您自行赋值给 `call.output`。

<Accordion title="退出语义" icon="arrow-right-from-bracket">

| 发生的情况 | 事件 | `outcome` |
| --- | --- | --- |
| 代码块正常返回 | `agent_end` | `"success"`，或您指定的 `outcome` |
| 代码块抛出异常 | `error`，然后 `agent_end` | `"failed"` |
| 抛出 `AbortError` | 仅 `agent_end` | `"cancelled"` |

错误总会被重新抛出。

工具失败会记录在叶节点上——`tool_result` 中包含 `error` 字符串——并且**不会**发出运行级别的 `error` 事件。被智能体循环捕获的错误不属于运行失败；向上传播的错误则由外层 `agent()` 准确记录一次。

</Accordion>

<Accordion title="`using` 语法" icon="brackets-curly">

当工作不是单一函数时——比如在构造函数中开启作用域、在析构函数中关闭，或与现有控制流交叉：

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result，然后 agent_end
```

两种形式发出的事件在字节层面完全相同。推荐使用回调形式：它在 `AsyncLocalStorage.run()` 内部执行，无需手动清理，且完全避免了"在此处开启、在彼处关闭"这类 bug。

在 `using` 块中捕获到自身的失败时，使用 `span.fail(error)` 上报——disposer 本身没有异常传递通道。

</Accordion>

## 事件目录

与 Python SDK 相同的十五个方法，采用驼峰命名。大多数方法**成对出现**——调用开始方法，再调用结束方法，SDK 会自动计算间隔时长。

| | 开始 | 结束 |
| --- | --- | --- |
| **智能体** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **模型** | `modelRequest` | `modelResponse` |
| **工具** | `toolUse` | `toolResult` |
| **Hook** | `hookTriggered` | `hookCompleted` |
| **人工** | `humanWait` | `humanInput` |

三个独立方法：`error`、`humanPause`、`humanInterrupt`。

<Accordion title="每个方法的所有字段" icon="table">

每个方法还接受 `sessionId` 和 `agentId`，作用域会自动填充这两项。省略的字段会被直接丢弃，而非以 JSON `null` 的形式发送。

| 方法 | 必填 | 可选 |
| --- | --- | --- |
| `agentStart` | — | `goal`, `parentId` |
| `agentEnd` | — | `outcome`, `summary` |
| `agentPause` | `pauseId` | `reason`, `userId` |
| `agentResume` | `pauseId` | `reason`, `userId` |
| `modelRequest` | — | `model`, `messages`, `system`, `tools`, `requestId` |
| `modelResponse` | — | `model`, `stopReason`, `inputTokens`, `outputTokens`, `content`, `role`, `requestId` |
| `toolUse` | `toolName`, `toolCallId` | `input` |
| `toolResult` | `toolName`, `toolCallId` | `output`, `error` |
| `hookTriggered` | `hookName`, `hookId` | `triggerEvent`, `input` |
| `hookCompleted` | `hookName`, `hookId` | `outcome`, `output`, `error` |
| `error` | `errorType`, `message` | `traceback` |
| `humanWait` | `inputId` | `prompt`, `options`, `reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`, `userId` |
| `humanInterrupt` | — | `reason`, `userId`, `atStep` |

您添加的其他任何键都会成为自定义 payload 字段。框架专属字段请以 `fw_*` 命名；与已声明字段同名的键会被拒绝，而非静默覆盖已提升为列的字段。

</Accordion>

<Warning>
  **`duration_ms` 由系统计算，不接受外部传入。** 四个结束方法会自动计算与对应开始方法的时间间隔，并拒绝调用方传入的 `duration_ms`——上报的时长必须是不可篡改的。

  配对匹配基于**会话**和 id，而非基于智能体。在 `planner` 下开启、在 `worker` 下关闭的工具仍然能够正确配对，这正是嵌套多智能体运行的实际行为。
</Warning>

## 框架适配器

```ts
await failproofai.instrument();              // 自动检测并接入所有可用框架
await failproofai.instrument("langchain");   // 仅接入指定框架
failproofai.uninstrument();                  // 还原所有修改
```

| 框架 | 支持版本 | 接入方式 |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x，LangGraph.js 0.4 – 1.x | 通过 `CallbackManager.configure` 接入，所有 `invoke`/`stream`/`batch` 调用均自动覆盖，无需在任何地方传入 `callbacks:`——也可以自行传入 `langchainHandler()` 而不进行任何 patch。 |
| **Vercel AI SDK** | `ai` 4 – 7 | 在调用处使用 `telemetry()`，或通过 `instrument("ai")` 对整个进程接入（`ai` 7 适用；`ai` 4–6 需手动开启，详见下文）。 |
| **Mastra** | `@mastra/core` 0.20 – 1.x | 覆盖 `Agent.generate`/`.stream`、智能体的模型与工具解析，以及工作流运行/步骤引擎。 |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | 通过 `Settings.callbackManager`（订阅方式）以及 `AgentWorkflow.runStream` 接入，涵盖工作流运行及其步骤。 |

每个支持范围均针对真实框架发布版本进行测试，涵盖两端边界，同时以 ES 模块和 CommonJS 两种方式，在每次 CI 运行中进行验证。

映射关系与 Python SDK 一致，因此同一程序无论用哪种语言都能在 Dashboard 中绘制出相同的调用树。只有拥有 LLM 决策循环的构件才被视为**智能体**——包括图或链的运行、AI SDK 的 `generateText`/`streamText` 调用、Mastra 智能体、LlamaIndex 智能体运行。LangGraph 节点或工作流步骤被视为 **hook**（`hook_triggered`/`hook_completed`），而非嵌套智能体。模型调用以 `model_request`/`model_response` 配对记录，包含 token 数量；工具调用携带模型自身的 tool call id。失败仅记录一次，记录在发生失败的事件上。

适配器安装失败时会记录日志并跳过；其他适配器仍然正常安装——LlamaIndex 的问题不应影响 LangGraph。

<Note>
  不带参数的 `instrument()` 通过模块是否**可解析**来检测框架，而非检查它是否已被导入——Node 没有类似 Python `sys.modules` 的 ES 模块等效机制。已安装但未使用的框架同样会被导入并 patch。如果这一点对您有影响，请明确指定所需框架的名称。
</Note>

<Note>
  这些框架大多同时提供 ES 模块和 CommonJS 两种构建产物，Node 会将它们作为两个独立的副本加载。适配器会 patch 您应用实际加载的副本（以及已被 `require` 加载的 CommonJS 副本），因此两种模块系统均可正常工作。如果框架已被 esbuild 或 webpack **打包进您的输出产物**，则无法通过此方式 patch——此时请使用调用处的辅助函数：`langchainHandler()`、`telemetry()`、`wrapTool()`。
</Note>

### 不 patch 的 LangChain 接入方式

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

该处理器无论是否调用 `instrument()` 均可工作，且不会重复记录。`instrument("langchain")` 接受 `sessionId`、`captureContent`、`includeChains`、`graphCallbacks` 和 `captureLimit` 参数，与 Python 适配器一致；在调用时通过 `metadata: { failproofai_sdk_session_id }` 可为该次调用指定会话。

### Vercel AI SDK

AI SDK 从 ES 模块中导出纯函数，而 ES 模块命名空间按规范是不可变的——没有地方可以 patch。因此使用 SDK 自身提供的扩展点：

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // 在 ai 7 中，使用 `telemetry: telemetry({ … })` ——相同的对象，新的属性名
});
```

这就是完整的接入方式：一个智能体 span、每个步骤一对含 token 数量的模型请求/响应，以及所有工具调用。同一处调用点支持所有主要版本——`ai` 4–6 读取它携带的 tracer，`ai` 7 读取 telemetry integration。

**在 `ai` 7 上**，`instrument("ai")` 通过 AI SDK 的全局 telemetry-integration 列表实现进程级接入：涵盖所有调用，以附加方式注册，不影响其他任何人的配置。

**在 `ai` 4–6 上，`instrument("ai")` 本身不记录任何内容，并会输出一条警告说明此情况。** 这些主要版本唯一的进程级 hook 是全局 OpenTelemetry tracer provider——这是一个单一插槽，一旦被占用 OpenTelemetry 便拒绝再次交出。注册我们自己的 provider 会静默拒绝您后续在启动流程中调用的 `NodeSDK.start()`，并将您的 http/数据库 span 发送到一个不导出任何内容的 tracer。请在调用处使用 `telemetry()` 或 `wrapModel`。如果进程本身不运行任何 OpenTelemetry，可通过 `instrument("ai", { registerGlobalTracer: true })` 手动开启：此后所有传入 `experimental_telemetry: { isEnabled: true }` 的调用都会被记录，且仅在插槽仍为空时才会占用它。`registerGlobalTracer: false` 保持默认行为并静默警告。

如果您更倾向于只包装一次模型，`wrapModel` 仅能看到模型调用，因为工具调用发生在模型层之上。在没有外层包装的情况下调用被包装的模型，会将其作为独立运行记录。流式调用会在流结束时关闭——消费者取消时 `stop_reason` 为 `"cancelled"`，中途失败时为 `"error"` 并附带错误信息：

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

同时使用两种方式没有问题：中间件会检测到该调用已被记录并自动让步，因此每次调用只会被记录一次。

`functionId` 用于命名智能体 span，请保持低基数——它会写入 `agent_id`，这是 Dashboard 的主要分面维度。

### Next.js

`next build` 默认会将服务器依赖打包，被打包进构建产物的框架是 `instrument()` 无法触达的副本。在 Next 的启动 hook 中调用 `instrument()`，并一次性包装配置：

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* 您的配置 */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` 会将 LangChain、Mastra、LlamaIndex 以及 SDK 本身添加到 `serverExternalPackages`，同时保留您现有的列表。如果不使用它，`instrument()` 会对每个无法触达的框架发出一次警告而非静默失败；如果您已自行列出这些包，请设置 `FAILPROOFAI_NEXT_EXTERNALS=1`。Vercel AI SDK 和调用处辅助函数无论哪种方式均可正常工作。Edge 路由会获得无操作的构建：导入 SDK 是安全的，但不会记录任何内容。

### 流式调用的 token 数量

OpenAI 兼容 API 仅在客户端请求时才会在流中上报用量。LangChain 和 Vercel AI SDK 会自动请求；对于 LlamaIndex，请向其 `OpenAI` LLM 传入 `additionalChatOptions: { stream_options: { include_usage: true } }`；对于 Mastra，请在构建模型时启用用量上报（例如 `createOpenAICompatible({ includeUsage: true })`）。否则流式模型调用将不包含 token 数量。

### 运行时

Node ≥ 20.9、Bun 和 Deno——每个框架，以 ES 模块和 CommonJS 两种形式，均在各运行时上针对 Node 的 trace 进行测试。SDK 与 `failproofaid` 守护进程配合运行，由守护进程负责发送写入的数据。

## 自建智能体——无需框架

适用于自行编写智能体循环，或使用没有适配器的框架的情况。您使用适配器底层相同的 API 来发出事件，因此 trace 具有相同的结构和质量。

您无需了解智能体的具体组织方式。每个手工构建的智能体，无论函数名称如何，都已经包含三个关键位置，这三处就是完整的接入点：

| 位置 | 需要添加的内容 | 发出的事件 |
| --- | --- | --- |
| **一次运行**的开始和结束处 | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **调用模型的函数** | 调用前 `event.modelRequest`，调用后 `event.modelResponse`——包括失败情况，两个都要 | 每次模型调用一对事件 |
| **执行工具的函数** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

身份标识是隐式传递的：`agent()` 内部的所有内容都会自动归属到该运行的会话，无需传入任何 id，也无需修改程序中的其他任何部分——包括智能体已有的数据库写入逻辑。

- **服务或 Worker：** 将您自己的请求或任务 id 作为 `sessionId` 传入，这样 Dashboard 上的会话与您自己的日志或数据库中的记录就是同一个字符串。
- **子智能体：** 嵌套 `agent()` 调用。内层智能体会以 `parent_id` 指向外层智能体，共同加入同一个会话。
- **成对发出事件。** 没有对应 `modelResponse` 的 `modelRequest` 会在 Dashboard 中显示为永久运行中的 span——这就是为什么需要 `catch`。

仓库中的 [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) 是完整可运行的版本：一个真实的 OpenAI 工具循环，按照上述方式接入，以 ES 模块和 CommonJS 两种形式在每次变更时于 CI 中运行。

## 评估

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \

```

有关协议、Worker 配置和结果类型，请参阅 [Evaluator SDK 参考文档](/zh/reference/evaluator-sdk)。

<Warning>
  **评估函数必须让出控制权。** 永不返回的同步函数会阻塞 Node 的单线程，任何超时都无法触发。请将评估函数写成 `async`。
</Warning>

## SDK 对您的进程无影响的方面

| | |
| --- | --- |
| **不阻塞智能体循环** | 事件写入内存队列，由定时器统一写出。定时器已调用 `unref`，因此导入本包不会阻止脚本正常退出。 |
| **不无限增长** | 队列同时受数量上限和字节数上限双重约束。超出任一限制后，最旧的事件会被丢弃并输出警告——遥测故障不能演变成 OOM 崩溃。 |
| **不导致进程崩溃** | 单个无法编码的事件会被单独丢弃，不影响同批次的其他事件。抛出异常的 getter、循环引用、`BigInt`、孤立代理项——每种情况都会被妥善处理而非向上传播。 |
| **不留下半写入的批次** | 内容在原子重命名前会执行 `fsync`，目录在重命名后也会执行 `fsync`，写入失败时会清理临时文件。 |
| **不让转录内容可被任意读取** | 批次文件权限为 `0600`，存放于权限为 `0700` 的目录中。这些文件包含目标、提示词、工具参数和工具输出。 |
| **不上传凭据** | API 密钥、token、JWT、Bearer 请求头以及形如密钥的赋值，在字节写入磁盘前会被脱敏处理。守护进程在上传前还会再次脱敏。 |
