需要 Node 20.9 或更高版本。支持 ESM 和 CommonJS，无运行时依赖。

<Note>
  本 SDK 与 Python SDK **写入相同的事件到相同的 spool**。由 Node agent 和 Python agent 组成的集群只会生成一组会话，而非两组，仪表板中也不会对它们加以区分。请按服务选择，而非按公司统一选择。
</Note>

## 安装

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

框架适配器已内置于包中。这些框架是**可选的 peer 依赖**——声明它们是为了让支持的版本范围可见，不会自动为您安装，只有在调用 `instrument()` 时才会导入。

## 连接 Failproof 守护进程

与 Python SDK 相同：在 **Admin → Keys** 下创建 `events:add` 密钥，然后在 agent 机器上[连接守护进程](/zh/start/setup#connect-a-machine-to-cloud)。SDK 负责写入磁盘，守护进程负责传输。

## 配置

### OpenTelemetry spans（按需启用）

通过 `npm install @opentelemetry/api @opentelemetry/sdk-trace-base` 单独安装 OpenTelemetry。
然后将 FailproofAI 添加到您的 provider 处理器中：

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

如果已有 provider，只需将其他处理器保留在同一列表中即可。暴露了 `addSpanProcessor` 方法的 provider 也可以通过 `{ provider }` 的形式传入。如果不传入任何选项，仅当尚未注册 provider 时才会注册新 provider。`OtelSpanExporter` 也可直接与您自己的处理器配合使用。

导出通过已连接的 FailproofAI 守护进程进行，SDK 不发起任何网络请求，也不需要密钥或本地监听器。请联系管理员启用 [OpenTelemetry 数据摄入](/zh/agenteye/opentelemetry)。不带参数的 `instrument()` 不会启用此导出器。`uninstrument("otel")` 仅禁用其自身的处理器。内容捕获由您的 span 属性控制；退出前请刷新您的 provider。OpenTelemetry 仍为可选的应用依赖，而非 SDK 的强依赖。

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| 选项 | 说明 |
| --- | --- |
| `environment` | 每个事件上的标签——如 `production`、`staging`、`prod-eu`，默认为 `dev`。 |
| `flushInterval` | 定时器写入磁盘的间隔，单位为秒，默认为 `0.5`。 |
| `baseDir` | 写入位置，默认为守护进程的 spool 目录，通常无需修改。 |

只有全部配置项通过验证时才会应用，因此一次失败的调用不会导致 SDK 处于新 `baseDir` 旧间隔的混合状态。

也可通过环境变量进行设置：

| 变量 | 说明 |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | 无需修改代码即可设置 `environment`，`configure()` 中的选项优先级更高。 |
| `FAILPROOFAI_HOME` | 移动存放 spool 的 Failproof AI 根目录。 |
| `FAILPROOFAI_SDK_LOG_LEVEL` | `debug`、`info`、`warn`（默认）、`error`、`silent`。 |
| `FAILPROOFAI_SDK_STRICT` | 设为 `1` 时，接入错误将抛出异常而非仅记录日志。 |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | 设为 `1` 时，框架兼容性问题将抛出异常而非警告后继续运行。 |

<Warning>
  **`environment` 中不能包含逗号。** 数据摄入会按逗号分割该字段以构建过滤器，标签中含逗号的事件将被静默丢弃——整个运行记录就此消失。请写 `prod-eu`，而非 `prod,eu`。

  `configure({ environment: "prod,eu" })` 会立即抛出异常，让您及时发现问题。`AGENTEYE_ENVIRONMENT` 无法抛出异常——没有调用方可以接收——因此它会警告一次并回退到 `dev`。
</Warning>

通过 `failproofai.setLogger({ debug, info, warn, error })` 可将 SDK 自身的日志输出路由到您的日志系统。

## 关闭

缓冲的事件会在 `process.on("exit")` 时刷新。

被信号终止的进程永远不会到达那里，而 Node 对 `SIGTERM` 的默认行为是不运行退出处理器直接终止——因此容器化的 agent 会丢失最后一个间隔尚未写入的数据。

<Warning>
  **本 SDK 不会为您安装信号处理器。** 注册信号处理器会改变进程的行为：监听器会抑制 Node 的默认终止行为，因此一个添加了信号处理器的库会悄无声息地让 Ctrl-C 失效。请自行添加：

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

短生命周期脚本或 serverless 处理器在返回前应执行 `await failproofai.flush()`——仅靠定时器无法保证数据一定送达。

## 身份标识

每个事件都属于某个会话和某个 agent。**作用域会自动填充两者**，因此您通常无需手动传入：

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

显式传入 `sessionId` 或 `agentId` 同样有效，且优先级更高。若两者均未绑定也未传入，调用将抛出异常，而不是发出一个 Cloud 会静默丢弃的事件。

<Note>
  身份标识基于 `AsyncLocalStorage` 传递，能跟随 `await`、`.then()`、定时器以及在作用域内创建的任何回调。**不能**跟随在一次运行中存储、在另一次运行中调用的回调，也无法跨越 `worker_threads` 边界——请在这些场景中使用 `failproofai.propagate()` 进行包装，否则相关事件将无法关联到正确的会话。
</Note>

### 作用域

| 作用域 | 发出事件 | 返回值 |
| --- | --- | --- |
| `session(body)` | 无——仅设置身份标识 | `body` 的返回值 |
| `agent(id, options?, body)` | `agent_start`，然后 `agent_end` | `body` 的返回值 |
| `toolCall(name, options?, body)` | `tool_use`，然后 `tool_result` | `body` 的返回值 |

同步的 body 保持同步：`agent("x", () => 1)` 返回 `1`，而非 Promise。

`toolCall` 会将 body 的 resolved 值作为工具的 `output` 记录，除非您自行赋值给 `call.output`。

<Accordion title="退出语义" icon="arrow-right-from-bracket">

| 情况 | 事件 | `outcome` |
| --- | --- | --- |
| 代码块正常返回 | `agent_end` | `"success"` 或您指定的 `outcome` |
| 代码块抛出异常 | `error`，然后 `agent_end` | `"failed"` |
| `AbortError` | 仅 `agent_end` | `"cancelled"` |

错误始终会重新抛出。

工具失败记录在叶节点上——`tool_result` 中包含 `error` 字符串——**不会**产生运行级别的 `error` 事件。被 agent 循环捕获的错误不属于运行失败；向上传播的错误由外层 `agent()` 恰好报告一次。

</Accordion>

<Accordion title="`using` 形式" icon="brackets-curly">

当工作不是单一函数时——例如在构造函数中打开作用域、在销毁函数中关闭，或跨越现有控制流：

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result, then agent_end
```

两种形式发出的事件字节完全相同。建议优先使用回调形式：它在 `AsyncLocalStorage.run()` 内部运行，无需手动展开，从根本上避免了"在此处打开、在彼处关闭"这类错误。

`using` 块如需报告自身的失败，应调用 `span.fail(error)`——disposer 本身没有异常传递通道。

</Accordion>

## 事件目录

与 Python SDK 相同的十五个方法，采用驼峰命名。大多数方法**成对出现**——调用开启方法，再调用关闭方法，SDK 会计算两者之间的时间差。

| | 开启 | 关闭 |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **模型** | `modelRequest` | `modelResponse` |
| **工具** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **人工** | `humanWait` | `humanInput` |

三个独立方法：`error`、`humanPause`、`humanInterrupt`。

<Accordion title="每个方法的所有字段" icon="table">

每个方法还接受 `sessionId` 和 `agentId`，作用域会自动填充这两个字段。省略的字段会被丢弃，而不是以 JSON `null` 的形式发送。

| 方法 | 必填 | 可选 |
| --- | --- | --- |
| `agentStart` | — | `goal`、`parentId` |
| `agentEnd` | — | `outcome`、`summary` |
| `agentPause` | `pauseId` | `reason`、`userId` |
| `agentResume` | `pauseId` | `reason`、`userId` |
| `modelRequest` | — | `model`、`messages`、`system`、`tools`、`requestId` |
| `modelResponse` | — | `model`、`stopReason`、`inputTokens`、`outputTokens`、`content`、`role`、`requestId` |
| `toolUse` | `toolName`、`toolCallId` | `input` |
| `toolResult` | `toolName`、`toolCallId` | `output`、`error` |
| `hookTriggered` | `hookName`、`hookId` | `triggerEvent`、`input` |
| `hookCompleted` | `hookName`、`hookId` | `outcome`、`output`、`error` |
| `error` | `errorType`、`message` | `traceback` |
| `humanWait` | `inputId` | `prompt`、`options`、`reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`、`userId` |
| `humanInterrupt` | — | `reason`、`userId`、`atStep` |

您添加的任何其他键都会成为自定义 payload 字段。框架特定的字段请以 `fw_*` 命名；与已声明字段冲突的名称会被拒绝，而不是静默覆盖已提升的列。

</Accordion>

<Warning>
  **`duration_ms` 由系统计算，不接受外部传入。** 四个关闭方法会自动计算与开启方法之间的时间差，并拒绝调用者传入的 `duration_ms`——上报的时长必须是不可伪造的。

  配对匹配基于**会话**和 id，而非 agent。在 `planner` 下开启、在 `worker` 下关闭的工具调用仍能正确配对，这正是嵌套多 agent 运行的实际工作方式。
</Warning>

## 框架适配器

```ts
await failproofai.instrument();              // 自动检测所有可用框架
await failproofai.instrument("langchain");   // 仅指定一个
failproofai.uninstrument();                  // 恢复所有原始状态
```

| 框架 | 支持版本 | 接入方式 |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x，LangGraph.js 0.4 – 1.x | `CallbackManager.configure`，因此每次 `invoke`/`stream`/`batch` 调用均自动覆盖，无需在任何地方传入 `callbacks:`——或自行传入 `langchainHandler()` 而不进行任何 patch。 |
| **Vercel AI SDK** | `ai` 4 – 7 | 在调用处使用 `telemetry()`，或对 `ai` 7 使用 `instrument("ai")` 覆盖整个进程（对 `ai` 4–6 此方式为按需启用——见下文）。 |
| **Mastra** | `@mastra/core` 0.20 – 1.x | `Agent.generate`/`.stream`、agent 的模型和工具解析，以及工作流运行/步骤引擎。 |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | `Settings.callbackManager`（已订阅）加上 `AgentWorkflow.runStream`，覆盖工作流运行及其步骤。 |

每个版本范围均针对真实框架发布版进行测试，涵盖两端版本、ES 模块和 CommonJS，在每次 CI 运行时执行。

映射关系与 Python SDK 一致，因此同一程序在两种语言中绘制出相同的调用树。只有拥有 LLM 决策循环的构造才是 **agent**——包括图或链的运行、AI SDK 的 `generateText`/`streamText` 调用、Mastra agent、LlamaIndex agent 运行。LangGraph 节点或工作流步骤是 **hook**（`hook_triggered`/`hook_completed`），而非嵌套 agent。模型调用以 `model_request`/`model_response` 配对形式记录，包含 token 数量；工具调用携带模型自身的工具调用 id。失败只记录一次，记录在发生失败的事件上。

适配器安装失败时会记录日志并跳过；其他适配器仍会继续安装——一个损坏的 LlamaIndex 不应影响 LangGraph 的正常使用。

<Note>
  不带参数的 `instrument()` 通过**能否解析**来检测框架，而非检查其是否已被导入——Node 对 ES 模块没有类似 Python `sys.modules` 的等价机制。已安装但未使用的框架将被导入并 patch。如果这一点对您有影响，请明确指定所需框架。
</Note>

<Note>
  这些框架大多同时提供 ES 模块构建和 CommonJS 构建，Node 会将它们作为两个独立副本加载。适配器会 patch 您应用加载的那个副本（如果已有代码 `require` 过，也会 patch CommonJS 副本），因此两种模块系统均可正常工作。如果框架已被 esbuild 或 webpack **打包进您的输出**，则无法通过 patch 覆盖——请在此场景下使用调用处的辅助方法：`langchainHandler()`、`telemetry()`、`wrapTool()`。
</Note>

### 不 patch 的 LangChain 使用方式

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

该处理器无论是否调用 `instrument()` 均可工作，且不会重复记录。`instrument("langchain")` 接受 `sessionId`、`captureContent`、`includeChains`、`graphCallbacks` 和 `captureLimit` 参数，与 Python 适配器一致；在调用时传入 `metadata: { failproofai_sdk_session_id }` 可为该次调用指定会话。

### Vercel AI SDK

AI SDK 从 ES 模块中导出纯函数，ES 模块命名空间按规范是不可变的——没有地方可以 patch。SDK 使用其自身文档化的扩展点：

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // 对于 ai 7，使用 `telemetry: telemetry({ … })` ——同一对象，新的属性名
});
```

这就是完整的集成：一个 agent span、每步一对包含 token 数量的模型请求/响应，以及所有工具调用。同一个调用处代码兼容所有主要版本——`ai` 4–6 读取其携带的 tracer，`ai` 7 读取 telemetry 集成。

**对于 `ai` 7**，`instrument("ai")` 会通过 AI SDK 的全局 telemetry 集成列表实现相同的进程级覆盖，该列表是累加式的，不会影响其他人的配置。

**对于 `ai` 4–6，`instrument("ai")` 本身不记录任何内容，并会输出一条相关警告。** 这些主要版本唯一的进程级钩子是全局 OpenTelemetry tracer provider——这是一个单一插槽，一旦被占用 OpenTelemetry 就会拒绝再次注册。注册我们的 provider 会静默拒绝您后续在启动流程中调用的 `NodeSDK.start()`，并将您的 http/数据库 span 发送到一个不导出任何内容的 tracer。请在调用处使用 `telemetry()` 或 `wrapModel`。如果该进程自身没有运行任何 OpenTelemetry，可以通过 `instrument("ai", { registerGlobalTracer: true })` 按需启用：这样它会记录所有传入 `experimental_telemetry: { isEnabled: true }` 的调用，且只在插槽仍为空时才会占用它。`registerGlobalTracer: false` 保持默认行为并静默该警告。

如果您更倾向于只包装一次模型，`wrapModel` 只能看到模型调用，因为工具调用发生在模型层之上。一个被包装的模型在没有外部包装的情况下调用，会作为独立运行记录。流式调用在流结束时关闭——消费者取消时 `stop_reason` 为 `"cancelled"`，中途失败时为 `"error"` 并附带错误信息：

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

同时使用两者没有问题：中间件会检测到该调用已被记录并自动延让，确保每次调用只被记录一次。

`functionId` 是 agent span 的名称，请保持低基数——它对应到 `agent_id`，即仪表板中的主要分面维度。

### Next.js

`next build` 默认会打包服务端依赖，被打包进构建的框架是 `instrument()` 无法覆盖的副本。请一次性包装配置，并从 Next 的启动钩子调用 `instrument()`：

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* your config */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` 会将 LangChain、Mastra、LlamaIndex 和 SDK 本身添加到 `serverExternalPackages`，同时保留您现有的列表。如果不使用它，`instrument()` 对每个无法覆盖的框架会警告一次而非静默失败；如果您已自行列出这些包，请设置 `FAILPROOFAI_NEXT_EXTERNALS=1`。Vercel AI SDK 和调用处辅助方法在两种情况下均可正常工作。Edge 路由会获得一个无操作的构建：导入 SDK 是安全的，不会记录任何内容。

### 流式调用的 token 计数

兼容 OpenAI 的 API 只有在客户端明确请求时才会在流中报告用量。LangChain 和 Vercel AI SDK 会自动请求；对于 LlamaIndex，请向其 `OpenAI` LLM 传入 `additionalChatOptions: { stream_options: { include_usage: true } }`；对于 Mastra，请在构建模型时启用用量报告（例如 `createOpenAICompatible({ includeUsage: true })`）。否则流式模型调用将不包含 token 计数。

### 运行时

Node ≥ 20.9、Bun 和 Deno——每个框架，以 ES 模块和 CommonJS 两种形式，均在各运行时上针对 Node 的 trace 进行测试。SDK 与 `failproofaid` 守护进程协同运行，由守护进程负责传输写入的数据。

## 自建 agent——不使用框架

适用于您自己编写的 agent 循环，或没有适配器的框架。您使用与适配器底层相同的 API 发出事件，因此 trace 具有相同的结构和质量。

您无需了解 agent 的内部组织方式。无论函数名称是什么，每个手工构建的 agent 都有三个关键位置，这三个位置就是完整的接入点：

| 位置 | 需要添加的内容 | 发出事件 |
| --- | --- | --- |
| **一次运行**的开始和结束处 | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **调用模型的函数** | 调用前 `event.modelRequest`，调用后 `event.modelResponse`——包括失败情况的两端 | 每次模型调用一对 |
| **执行工具的函数** | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

身份标识是环境感知的：`agent()` 内部的所有内容都会关联到该运行的会话，无需传入 id，程序中的其他部分也不会受到影响——包括 agent 已写入其自身数据库的任何内容。

- **服务或 worker：** 将您自己的请求或任务 id 作为 `sessionId` 传入，这样仪表板上的会话与您自己日志或数据库中的记录使用相同的字符串标识。
- **子 agent：** 嵌套调用 `agent()`，内层 agent 会以外层 agent 的 `parent_id` 加入同一会话。
- **成对发送事件。** 没有对应 `modelResponse` 的 `modelRequest` 会在仪表板中显示为永久运行中的 span——这就是为什么需要 `catch`。

仓库中的 [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) 是完整可运行的版本：一个真实的 OpenAI 工具循环，按照完全相同的方式接入，在每次变更时以 ES 模块和 CommonJS 两种形式在 CI 中运行。

## 评估

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

## 对您的进程无副作用的保证

| | |
| --- | --- |
| **不阻塞 agent 循环** | 事件进入内存队列，由定时器写入磁盘。定时器已 `unref`，因此导入本包不会阻止脚本退出。 |
| **不无限增长** | 队列同时受计数和字节数限制。超出任一限制后，最旧的事件会被丢弃并输出警告——遥测服务中断不能演变成 OOM 崩溃。 |
| **不导致进程崩溃** | 一个无法编码的事件会被单独丢弃，不影响周围的批次。抛出异常的 getter、循环引用、`BigInt`、孤立的代理对：每种情况都会被妥善处理而非向上传播。 |
| **不留下写了一半的批次** | 内容在原子重命名前执行 `fsync`，目录在重命名后执行 `fsync`，失败的写入会清理其临时文件。 |
| **不让转录内容可被读取** | 批次文件权限为 `0600`，存储在 `0700` 目录中。它们包含目标、提示、工具参数和工具输出。 |
| **不泄露凭证** | API 密钥、token、JWT、Bearer 请求头及形如密钥的赋值语句在写入磁盘前会被脱敏处理。守护进程在上传前会再次脱敏。 |
