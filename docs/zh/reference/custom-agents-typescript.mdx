需要 Node 20.9 或更高版本。支持 ESM 和 CommonJS。无运行时依赖。

<Note>
  本 SDK 与 Python SDK **写入同一 spool 中的相同事件**。由 Node agents 和 Python agents 组成的集群只会产生一组会话，而非两组，Dashboard 中也不会对它们加以区分。请按服务选择，而非按公司统一选择。
</Note>

## 安装

```bash
npm install @failproofai/sdk
```

```ts
import * as failproofai from "@failproofai/sdk";

await failproofai.agent("planner", { goal: question }, async () => {
  const hits = await failproofai.toolCall("web_search", { input: { q } }, () => search(q));
});
```

框架适配器已内置于包中。这些框架是**可选的 peer 依赖**——如此声明是为了让支持的版本范围清晰可见，不会自动为您安装，只有在您调用 `instrument()` 时才会被导入。

## 连接 Failproof 守护进程

与 Python SDK 相同：在 **Admin → Keys** 下创建一个 `events:add` 密钥，然后在 agent 机器上[连接守护进程](/zh/start/setup#connect-a-machine-to-cloud)。SDK 负责写入磁盘，守护进程负责传输。

## 配置

### OpenTelemetry spans（需手动开启）

通过 `npm install @opentelemetry/api @opentelemetry/sdk-trace-base` 单独安装 OpenTelemetry。
然后将 FailproofAI 添加到您的 provider 处理器中：

```ts
import * as failproofai from "@failproofai/sdk";
import { BasicTracerProvider } from "@opentelemetry/sdk-trace-base";
import type { SpanProcessor } from "@opentelemetry/sdk-trace-base";

const spanProcessors: SpanProcessor[] = [];
await failproofai.instrument("otel", { spanProcessors });
const provider = new BasicTracerProvider({ spanProcessors });
const span = provider.getTracer("my-agent").startSpan("agent", {
  attributes: { "gen_ai.operation.name": "invoke_agent" },
});
span.end();
await provider.forceFlush();
```

如果已有 provider，只需将其他处理器保留在同一列表中即可。暴露了 `addSpanProcessor` 方法的 provider 也可以通过 `{ provider }` 的形式传入。如果不传任何选项，只有在尚未注册 provider 的情况下，安装过程才会注册一个新的 provider。`OtelSpanExporter` 也可以直接与您自定义的处理器配合使用。

导出通过已连接的 FailproofAI 守护进程进行；SDK 不发送任何网络请求，也不需要密钥或本地监听器。请联系管理员启用 [OpenTelemetry 数据摄入](/zh/agenteye/opentelemetry)。单独调用 `instrument()` 不会启用此导出器。`uninstrument("otel")` 仅禁用其自身的处理器。内容捕获由您的 span 属性控制；退出前请务必刷新您的 provider。OpenTelemetry 仍为可选的应用依赖，而非 SDK 的强制依赖。

```ts
failproofai.configure({
  environment: "production",
  flushInterval: 0.5,
  baseDir: undefined,
});
```

| 选项 | 作用 |
| --- | --- |
| `environment` | 每条事件上的标签——如 `production`、`staging`、`prod-eu`。默认为 `dev`。 |
| `flushInterval` | 定时器写入磁盘的频率，单位为秒。默认为 `0.5`。 |
| `baseDir` | 写入目录。默认为守护进程的 spool 目录，除非您明确需要更改，否则保持默认即可。 |

只有所有参数均通过验证，配置才会生效。若某次调用被拒绝，SDK 将保持原有状态不变，不会出现 `baseDir` 已更新而间隔未更新的情况。

也可通过环境变量进行配置：

| 变量 | 作用 |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | 无需修改代码即可设置 `environment`。`configure()` 中的选项优先级更高。 |
| `FAILPROOFAI_HOME` | 更改存放 spool 的 Failproof AI 根目录。 |
| `FAILPROOFAI_SDK_LOG_LEVEL` | 可选值：`debug`、`info`、`warn`（默认）、`error`、`silent`。 |
| `FAILPROOFAI_SDK_STRICT` | 设为 `1` 时，接入错误将抛出异常，而非仅记录日志。 |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | 设为 `1` 时，框架兼容性问题将抛出异常，而非仅警告后继续运行。 |

<Warning>
  **`environment` 中不能包含逗号。** 数据摄入会按逗号分割该字段以构建过滤器，标签中含有逗号的事件将被跳过——整个运行的数据会悄无声息地丢失。请写 `prod-eu`，而非 `prod,eu`。

  `configure({ environment: "prod,eu" })` 会立即抛出异常，让您及时发现问题。`AGENTEYE_ENVIRONMENT` 无法抛出异常（没有调用方可以接收），因此它会警告一次并回退到 `dev`。
</Warning>

通过 `failproofai.setLogger({ debug, info, warn, error })` 可将 SDK 自身的日志输出路由到您的日志记录器。

## 关闭

缓冲的事件会在 `process.on("exit")` 时刷新。

被信号终止的进程永远不会到达那一步，而 Node 对 `SIGTERM` 的默认行为是直接终止，不运行退出处理器——因此容器化的 agent 会丢失最后一个间隔内尚未写入的数据。

<Warning>
  **本 SDK 不会为您安装信号处理器。** 注册信号处理器会改变进程的行为：监听器会抑制 Node 的默认终止行为，因此一个擅自添加监听器的库会悄悄地导致 Ctrl-C 失效。请自行添加：

  ```ts
  for (const signal of ["SIGINT", "SIGTERM"] as const) {
    process.once(signal, () => {
      failproofai.flushSync();
      process.exit(0);
    });
  }
  ```
</Warning>

短暂运行的脚本或 serverless 处理函数应在返回前 `await failproofai.flush()`——仅靠定时器无法保证数据一定送达。

## 身份标识

每条事件都属于某个会话和某个 agent。**作用域会自动填充这两项**，因此您通常无需手动传入：

```ts
await failproofai.session(async () => {
  await failproofai.agent("planner", async () => {
    failproofai.event.toolUse({ toolName: "search", toolCallId: "c1" });
  });
});
```

显式传入 `sessionId` 或 `agentId` 同样有效，且优先级更高。若两者均未绑定也未传入，调用将抛出异常，而非静默地发出 Cloud 会丢弃的事件。

<Note>
  身份标识基于 `AsyncLocalStorage` 传递，能够跟随 `await`、`.then()`、定时器以及在作用域内创建的任何回调。但它**不会**跟随在某次运行中存储、在另一次运行中调用的回调，也不会跨 `worker_threads` 边界传递——对于此类情况，请使用 `failproofai.propagate()` 进行包装，否则相关事件将无法与会话关联。
</Note>

### 作用域

| 作用域 | 触发事件 | 返回值 |
| --- | --- | --- |
| `session(body)` | 无——仅设置身份标识 | `body` 的返回值 |
| `agent(id, options?, body)` | `agent_start`，然后 `agent_end` | `body` 的返回值 |
| `toolCall(name, options?, body)` | `tool_use`，然后 `tool_result` | `body` 的返回值 |

同步的 body 保持同步：`agent("x", () => 1)` 返回 `1`，而非 Promise。

`toolCall` 会将 body 的 resolved 值作为工具的 `output` 记录，除非您自行赋值 `call.output`。

<Accordion title="退出语义" icon="arrow-right-from-bracket">

| 发生的情况 | 触发事件 | `outcome` |
| --- | --- | --- |
| 代码块正常返回 | `agent_end` | `"success"` 或您自定义的 `outcome` |
| 代码块抛出异常 | `error`，然后 `agent_end` | `"failed"` |
| 抛出 `AbortError` | 仅 `agent_end` | `"cancelled"` |

错误始终会被重新抛出。

工具失败会记录在叶节点上——`tool_result` 中包含 `error` 字符串——**不会**触发运行级别的 `error` 事件。被 agent 循环捕获的错误不属于运行失败；向上传播的错误则只由外层的 `agent()` 报告一次。

</Accordion>

<Accordion title="`using` 形式" icon="brackets-curly">

当工作内容不是单一函数时——例如在构造函数中开启作用域、在析构函数中关闭，或者横跨现有控制流的情况：

```ts
{
  using span = failproofai.agent.open("planner", { goal });
  using call = failproofai.toolCall.open("search", { input: { q } });
  call.call.output = await search(q);
}  // tool_result，然后 agent_end
```

两种形式生成的事件在字节层面完全相同。推荐使用回调形式：它在 `AsyncLocalStorage.run()` 内部执行，无需手动展开，从根本上避免了"在此处开启、在彼处关闭"这类 bug。

`using` 代码块若需捕获自身的失败，请通过 `span.fail(error)` 上报——disposer 本身没有异常传递通道。

</Accordion>

## 事件目录

与 Python SDK 相同的十五个方法，采用驼峰命名。大多数方法**成对出现**——调用开始方法，再调用结束方法，SDK 会自动计算时间间隔。

| | 开始 | 结束 |
| --- | --- | --- |
| **Agents** | `agentStart` | `agentEnd` |
| | `agentPause` | `agentResume` |
| **模型** | `modelRequest` | `modelResponse` |
| **工具** | `toolUse` | `toolResult` |
| **Hooks** | `hookTriggered` | `hookCompleted` |
| **人工** | `humanWait` | `humanInput` |

三个独立方法：`error`、`humanPause`、`humanInterrupt`。

<Accordion title="每个方法的所有字段" icon="table">

每个方法还接受 `sessionId` 和 `agentId`，作用域会自动为您填充。省略的字段会被直接丢弃，而非以 JSON `null` 的形式发送。

| 方法 | 必填 | 可选 |
| --- | --- | --- |
| `agentStart` | — | `goal`、`parentId` |
| `agentEnd` | — | `outcome`、`summary` |
| `agentPause` | `pauseId` | `reason`、`userId` |
| `agentResume` | `pauseId` | `reason`、`userId` |
| `modelRequest` | — | `model`、`messages`、`system`、`tools`、`requestId` |
| `modelResponse` | — | `model`、`stopReason`、`inputTokens`、`outputTokens`、`content`、`role`、`requestId` |
| `toolUse` | `toolName`、`toolCallId` | `input` |
| `toolResult` | `toolName`、`toolCallId` | `output`、`error` |
| `hookTriggered` | `hookName`、`hookId` | `triggerEvent`、`input` |
| `hookCompleted` | `hookName`、`hookId` | `outcome`、`output`、`error` |
| `error` | `errorType`、`message` | `traceback` |
| `humanWait` | `inputId` | `prompt`、`options`、`reason` |
| `humanInput` | `inputId` | `response` |
| `humanPause` | — | `reason`、`userId` |
| `humanInterrupt` | — | `reason`、`userId`、`atStep` |

您添加的任何其他键都会成为自定义载荷字段。框架特定的字段请以 `fw_*` 命名；与已声明字段同名的键将被拒绝，而非静默覆盖已提升的列。

</Accordion>

<Warning>
  **`duration_ms` 是计算所得，不接受外部传入。** 四个结束方法会自动计算与对应开始方法的时间差，并拒绝调用方传入的 `duration_ms`——上报的时间必须无法被篡改。

  配对匹配基于**会话**和 id，而非 agent。在 `planner` 下开启、在 `worker` 下关闭的工具调用仍然能够正确配对，这正是嵌套多 agent 运行的实际工作方式。
</Warning>

## 框架适配器

```ts
await failproofai.instrument();              // 自动检测所有可用框架
await failproofai.instrument("langchain");   // 仅指定一个
failproofai.uninstrument();                  // 恢复所有原始状态
```

| 框架 | 支持版本 | 接入方式 |
| --- | --- | --- |
| **LangChain.js / LangGraph.js** | `@langchain/core` 0.3 – 1.x，LangGraph.js 0.4 – 1.x | 通过 `CallbackManager.configure` 接入，每次 `invoke`/`stream`/`batch` 调用均自动覆盖，无需在任何地方传入 `callbacks:`——也可自行传入 `langchainHandler()` 且不做任何 patch。 |
| **Vercel AI SDK** | `ai` 4 – 7 | 在调用处使用 `telemetry()`，或通过 `instrument("ai")` 对整个进程生效（仅限 `ai` 7，4–6 版本需手动开启——见下文）。 |
| **Mastra** | `@mastra/core` 0.20 – 1.x | 覆盖 `Agent.generate`/`.stream`、agent 的模型与工具解析，以及工作流的运行/步骤引擎。 |
| **LlamaIndex.TS** | `llamaindex` 0.11.4 – 0.x | 通过订阅 `Settings.callbackManager` 以及接入 `AgentWorkflow.runStream`，覆盖工作流运行及其步骤。 |

每个版本范围均在实际框架发布版本上进行测试，涵盖两端边界，以 ES 模块和 CommonJS 两种形式，在每次 CI 运行时验证。

其映射关系与 Python SDK 一致，因此同一程序在两种语言中生成相同的调用树。只有拥有 LLM 决策循环的构件才被视为 **agent**——包括 graph 或 chain 的运行、AI SDK 的 `generateText`/`streamText` 调用、Mastra agent，以及 LlamaIndex agent 运行。LangGraph 节点或工作流步骤被视为 **hook**（`hook_triggered`/`hook_completed`），而非嵌套 agent。模型调用以包含 token 计数的 `model_request`/`model_response` 对形式记录；工具调用携带模型自身的 tool call id。失败仅在其发生的事件上记录一次。

如果某个适配器安装失败，会记录日志并跳过；其他适配器仍会正常安装——LlamaIndex 出错不应影响 LangGraph 的接入。

<Note>
  不带参数调用 `instrument()` 时，框架检测依据是该框架能否**被解析**，而非是否已被导入——Node 对 ES 模块没有类似 Python `sys.modules` 的等价机制。已安装但未使用的框架会被导入并打 patch。如果这一点对您有影响，请明确指定所需框架。
</Note>

<Note>
  这些框架大多同时提供 ES 模块构建和 CommonJS 构建，Node 会将它们作为两个独立的副本加载。适配器会对您应用实际加载的副本进行 patch（如果已有代码通过 `require` 加载了 CommonJS 副本，也会一并 patch），因此两种模块系统均可正常工作。如果框架已被 esbuild 或 webpack **打包进您自己的输出**，则无法通过 patch 覆盖——此时请使用调用处的辅助工具：`langchainHandler()`、`telemetry()`、`wrapTool()`。
</Note>

### 不 patch 的 LangChain 用法

```ts
import { langchainHandler } from "@failproofai/sdk/langchain";
await graph.invoke(input, { callbacks: [langchainHandler()] });
```

该处理器无论是否调用 `instrument()` 均可正常工作，且不会重复记录。`instrument("langchain")` 接受 `sessionId`、`captureContent`、`includeChains`、`graphCallbacks` 和 `captureLimit` 参数，与 Python 适配器一致；在调用时传入 `metadata: { failproofai_sdk_session_id }` 可为该次调用指定会话。

### Vercel AI SDK

AI SDK 从 ES 模块导出纯函数，而 ES 模块命名空间按规范是不可变的——没有可供 patch 的位置。因此采用 SDK 自身文档记录的扩展点：

```ts
import { telemetry } from "@failproofai/sdk/ai";

const { text } = await generateText({
  model,
  prompt,
  experimental_telemetry: telemetry({ functionId: "answer-question" }),
  // 在 ai 7 上，使用 `telemetry: telemetry({ … })` ——相同的对象，新的属性名
});
```

这就是完整的集成方式：每个步骤产生一个 agent span、一对包含 token 计数的 model request/response，以及所有工具调用。同一调用处写法在所有主版本上均适用——`ai` 4–6 读取其携带的 tracer，`ai` 7 使用 telemetry integration。

`instrument("ai")` 在 **`ai` 7 上**可对整个进程生效：通过 AI SDK 的全局 telemetry-integration 列表覆盖所有调用，该列表为追加式，不会影响其他人的配置。

**在 `ai` 4–6 上，`instrument("ai")` 单独调用不会记录任何内容，并会输出一条警告说明原因。** 这些主版本唯一的全局 hook 是 OpenTelemetry 全局 tracer provider——这是一个单一插槽，一旦被占用，OpenTelemetry 就不会再让出。注册我们的 provider 会导致您后续在启动时调用 `NodeSDK.start()` 时静默失败，并将您的 http/数据库 spans 发送到一个不导出任何内容的 tracer。请在调用处使用 `telemetry()` 或 `wrapModel`。如果进程本身不运行任何 OpenTelemetry，可以通过 `instrument("ai", { registerGlobalTracer: true })` 手动开启：此后它会记录所有传入 `experimental_telemetry: { isEnabled: true }` 的调用，且只在插槽仍为空时才会占用它。`registerGlobalTracer: false` 保持默认行为并静默警告。

如果您更倾向于只包装一次模型，`wrapModel` 仅能看到模型调用，因为工具调用发生在模型层之上。被包装的模型若在无外层包装的情况下调用，会作为独立运行记录。流式调用以流结束的方式关闭——消费者取消时 `stop_reason: "cancelled"`，中途失败时 `"error"` 并附带错误信息：

```ts
import { wrapModel } from "@failproofai/sdk/ai";
const model = await wrapModel(openai("gpt-4o"));
```

同时使用两者没有问题：中间件会检测到该调用已被记录并自动延迟，确保每次调用只记录一次。

`functionId` 用于命名 agent span。请保持其低基数——它会落入 `agent_id`，这是 Dashboard 的主要分面维度。

### Next.js

`next build` 默认会将服务器依赖打包，被打包进构建产物的框架是 `instrument()` 无法触达的副本。请在配置文件中包装一次，并从 Next 的启动 hook 中调用 `instrument()`：

```ts
// next.config.ts
import { withFailproofai } from "@failproofai/sdk/next";
export default withFailproofai({ /* 您的配置 */ });
```

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const failproofai = await import("@failproofai/sdk");
  await failproofai.instrument();
}
```

`withFailproofai` 会将 LangChain、Mastra、LlamaIndex 和 SDK 本身添加到 `serverExternalPackages`，并保留您现有的列表。如果不使用它，`instrument()` 会对每个无法触达的框架发出一次警告，而非静默失败；如果您已自行列出这些包，请设置 `FAILPROOFAI_NEXT_EXTERNALS=1`。Vercel AI SDK 和调用处辅助工具无论哪种情况均可正常使用。Edge 路由会获得一个无操作构建：导入 SDK 是安全的，不会记录任何内容。

### 流式调用的 token 计数

兼容 OpenAI 的 API 只有在客户端明确请求时才会在流中报告用量。LangChain 和 Vercel AI SDK 会自动请求；对于 LlamaIndex，请向其 `OpenAI` LLM 传入 `additionalChatOptions: { stream_options: { include_usage: true } }`；对于 Mastra，请在构建模型时启用用量统计（例如 `createOpenAICompatible({ includeUsage: true })`）。否则流式模型调用将不包含 token 计数。

### 运行时

Node ≥ 20.9、Bun 和 Deno——每个框架，以 ES 模块和 CommonJS 两种形式，均在各运行时上针对 Node 的 trace 进行测试。SDK 与 `failproofaid` 守护进程协同运行，后者负责传输写入的数据。

## 自建 agent——无需框架

适用于您自行编写的 agent 循环，或没有适配器的框架。您通过适配器底层使用的相同 API 触发事件，因此 trace 具有相同的结构和质量。

您无需了解 agent 的内部组织方式。无论函数如何命名，每个手工构建的 agent 都有三个固定位置，这三处就是完整的集成点：

| 位置 | 需要添加的内容 | 触发事件 |
| --- | --- | --- |
| **一次运行**的开始和结束处 | `failproofai.agent("name", { goal }, async () => …)` | `agent_start` / `agent_end` |
| **调用模型的函数**内 | 调用前 `event.modelRequest`，调用后 `event.modelResponse`——包括失败情况，两个方法都要 | 每次模型调用产生一对 |
| **执行工具的函数**内 | `failproofai.toolCall(name, { toolCallId, input }, () => run())` | `tool_use` / `tool_result` |

```ts
async function callModel(messages) {
  const requestId = randomUUID();
  const started = Date.now();
  failproofai.event.modelRequest({ model: MODEL, requestId, messages });
  try {
    const reply = await client.chat.completions.create({ model: MODEL, messages, tools });
    failproofai.event.modelResponse({
      model: reply.model, requestId, stopReason: reply.choices[0].finish_reason,
      inputTokens: reply.usage?.prompt_tokens, outputTokens: reply.usage?.completion_tokens,
      duration_ms: Date.now() - started,
    });
    return reply.choices[0].message;
  } catch (error) {
    failproofai.event.modelResponse({ model: MODEL, requestId, stopReason: "error",
      error: String(error), duration_ms: Date.now() - started });
    throw error;
  }
}

async function dispatch(call) {
  const input = JSON.parse(call.function.arguments);
  return failproofai.toolCall(call.function.name, { toolCallId: call.id, input },
    () => runTool(call.function.name, input));
}

await failproofai.agent("inventory", { goal: question }, async () => {
  for (;;) {
    const message = await callModel(messages);
    if (!message.tool_calls?.length) return message.content;
    for (const call of message.tool_calls) await dispatch(call);
  }
});
```

身份标识是环境感知的：`agent()` 内部的所有内容都会自动归属于该运行的会话，无需传入 id，程序中的其他部分也不受影响——包括 agent 自身已写入数据库的内容。

- **服务或 worker：** 将您自己的请求或任务 id 作为 `sessionId` 传入，这样 Dashboard 上的会话与您自有日志或数据库中的记录就是同一个字符串。
- **子 agent：** 嵌套调用 `agent()`。内层 agent 会以外层 agent 为 `parent_id` 加入同一会话。
- **成对触发事件。** 没有对应 `modelResponse` 的 `modelRequest` 会在 Dashboard 上显示为永久运行的 span——因此需要 `catch`。

仓库中的 [`sdk/typescript/examples/research-agent.ts`](https://github.com/FailproofAI/failproofai/blob/main/sdk/typescript/examples/research-agent.ts) 是完整的可运行版本：一个真实的 OpenAI 工具循环，完全按照此方式接入，在每次代码变更时以 ES 模块和 CommonJS 两种形式在 CI 中运行。

## 评估

```ts
import { Evaluator, EvalResult, Score } from "@failproofai/sdk/evaluator";

export const app = new Evaluator({ name: "my-evals", version: "1" });

app.eval("tool_success_rate", { version: "1" }, (session) => {
  const results = session.eventsOfType("tool_result");
  const failures = results.filter((event) => event.payload.error != null).length;
  return new EvalResult({
    score: new Score(results.length === 0 ? 1 : 1 - failures / results.length),
    reasoning: `${failures} of ${results.length} tool calls failed`,
  });
});
```

```bash
FAILPROOFAI_EVALUATOR_URL=… FAILPROOFAI_EVALUATOR_TOKEN=… \
  npx failproofai-evaluator ./my-evals.js
```

有关协议、worker 配置和结果类型，请参阅 [Evaluator SDK 参考文档](/zh/reference/evaluator-sdk)。

<Warning>
  **评估函数必须让出控制权。** 永不返回的同步函数会阻塞 Node 的单线程，任何超时都无法在此期间触发。请编写 `async` 评估函数。
</Warning>

## 对您的进程无侵入性保证

| | |
| --- | --- |
| **不阻塞 agent 循环** | 事件进入内存队列，由定时器写入磁盘。定时器已调用 `unref`，因此导入本包不会阻止脚本正常退出。 |
| **不无限增长** | 队列同时受数量*和*字节数限制。超出任一限制后，最旧的事件将被丢弃并输出警告——遥测服务中断不应导致 OOM 崩溃。 |
| **不导致进程崩溃** | 单个无法编码的事件会被单独丢弃，不影响同批次的其他事件。抛出异常的 getter、循环引用、`BigInt`、孤立代理项：每种情况都会被妥善处理，而非向上传播。 |
| **不留下半写批次** | 内容在原子重命名前先 `fsync`，目录在重命名后再 `fsync`，写入失败时会清理临时文件。 |
| **不让转录内容可被读取** | 批次文件权限为 `0600`，存放于权限为 `0700` 的目录中。这些文件包含目标、提示、工具参数和工具输出。 |
| **不泄露凭证** | API 密钥、token、JWT、bearer 请求头及形似密钥的赋值语句在写入磁盘前会被脱敏处理。守护进程在上传前会再次脱敏。 |
