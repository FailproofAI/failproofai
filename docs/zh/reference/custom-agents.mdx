## 安装

```bash
pip install failproofai-sdk
```

该包以 `failproofai-sdk` 为名安装，在 Python 中以 `failproofai_sdk` 导入。框架扩展（如 `failproofai-sdk[langgraph]`）会同时安装对应框架本身；适配器始终随基础包一并发布。

## 连接 Failproof 守护进程

<Tabs>
  <Tab title="控制台">
    1. 前往 **Admin → Keys**，创建一个具有 `events:add` 权限的密钥。
    2. 在 agent 所在机器上[将 Failproof 守护进程连接至 Cloud](/zh/start/setup#connect-a-machine-to-cloud)。
    3. 运行一次已接入的 session，然后在 **Observe → Events** 下找到其准确 ID。
    4. 前往 **Observe → Sessions**，选择相同环境，打开重建后的追踪记录。

    ![自定义 Python agent session 重建为执行图和有序事件追踪。](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    将 `events:add` 密钥读入 shell。`read -s` 通过不回显的提示符输入，因此它不会出现在命令或 shell 历史记录中：

    ```bash
    read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
    ```

    ```bash

    failproofai config --status
    ```
  </Tab>

## 配置

### OpenTelemetry spans（可选开启）

单独安装 `opentelemetry-sdk`，然后挂载可选导出器：

```python
import failproofai_sdk
from opentelemetry.sdk.trace import TracerProvider

provider = TracerProvider()
failproofai_sdk.instrument("otel", provider=provider)
with provider.get_tracer("my-agent").start_as_current_span(
    "agent", attributes={"gen_ai.operation.name": "invoke_agent"}
):
    pass
provider.force_flush()
```

如果省略 `provider`，配置时会使用已注册的 provider；仅在没有已注册 provider 时才会新建一个。您也可以将 `failproofai_sdk.OtelSpanExporter()` 直接传入您自己的 span 处理器。其他导出器不受影响。

已连接的 FailproofAI 守护进程负责投递导出数据；SDK 无需任何网络配置、密钥或本地监听器。管理员需要开启 [OpenTelemetry 数据接入](/zh/agenteye/opentelemetry)。单独调用 `instrument()` 不会启用 OTEL。`uninstrument("otel")` 仅禁用其自身的处理器。内容采集由您的接入配置控制。退出前请刷新 provider。SDK 仍声明零硬性运行时依赖，仅在明确请求时才导入 OpenTelemetry。

```python
import failproofai_sdk

failproofai_sdk.configure(
    base_dir=None,
    flush_interval=0.5,
    environment="production",
)
```

| 参数 | 作用 |
| --- | --- |
| `environment` | 每个事件上的标签——`production`、`staging`、`prod-eu`。默认为 `dev`。 |
| `flush_interval` | 后台线程写入磁盘的时间间隔，单位为秒。默认为 `0.5`。 |
| `base_dir` | 写入路径。默认为守护进程的 spool 目录，除非您明确需要更改，否则保持默认即可。 |

也可通过环境变量进行设置：

| 变量 | 作用 |
| --- | --- |
| `AGENTEYE_ENVIRONMENT` | 无需修改代码即可设置 `environment`，适用于标签归属于部署而非应用本身的场景。`configure()` 中的同名参数优先级更高。 |
| `FAILPROOFAI_HOME` | 移动存放 spool 的 Failproof AI 根目录。 |
| `FAILPROOFAI_SDK_STRICT` | 设为 `1` 时，接入错误将抛出异常而非仅记录日志。 |
| `FAILPROOFAI_SDK_STRICT_INTEGRATIONS` | 设为 `1` 时，框架兼容性问题将抛出异常而非警告后继续执行。 |

<Warning>
  **`environment` 中不得含有逗号。** 数据接入会以逗号分割该字段来构建过滤条件，标签中含逗号的事件会被静默丢弃，导致整个运行记录消失无踪。请写 `prod-eu`，而非 `prod,eu`。

  `configure(environment="prod,eu")` 会立即抛出异常以便您及时发现。`AGENTEYE_ENVIRONMENT` 无法抛出异常（没有调用方可以捕获），因此只会警告一次并回退至 `dev`。
</Warning>

事件先在内存中排队，每隔 `flush_interval` 秒由后台线程写入，解释器退出时执行最终刷新。若进程被强制终止，尚未写入的事件将会丢失。

## 身份标识

每个事件归属于一个 session 和一个 agent。**作用域会自动填充这两者**，因此通常无需手动传入：

```python
with failproofai_sdk.session():
    with failproofai_sdk.agent("planner"):
        failproofai_sdk.event.tool_use(tool_name="search", tool_call_id="c1")
```

显式传入 `session_id` 或 `agent_id` 同样有效，且优先级更高。若既未绑定作用域也未传入参数，调用将抛出 `TypeError`，而不是发出一个 Cloud 会静默丢弃的事件。

<Note>
  身份标识依赖上下文变量传递。它会自动跟随 `asyncio` 任务传播，但**不会**自动跟随新线程——请用 `failproofai_sdk.propagate()` 包装工作线程，否则其事件将无法关联。
</Note>

## 事件目录

共十五个方法。大多数以**成对**形式出现——先调用开启方法，再调用关闭方法，SDK 会自动计算两者之间的耗时。

| | 开启 | 关闭 |
| --- | --- | --- |
| **Agents** | `agent_start` | `agent_end` |
| | `agent_pause` | `agent_resume` |
| **模型** | `model_request` | `model_response` |
| **工具** | `tool_use` | `tool_result` |
| **Hooks** | `hook_triggered` | `hook_completed` |
| **人工** | `human_wait` | `human_input` |

另有三个独立方法：`error`、`human_pause`、`human_interrupt`。

<Accordion title="每个方法的完整字段" icon="table">

每个方法还接受 `session_id` 和 `agent_id`，作用域会自动填充。值为 `None` 的字段会被直接丢弃，而非以 JSON `null` 形式发送；所有方法均返回 `None`。

| 方法 | 必填 | 可选 |
| --- | --- | --- |
| `agent_start` | — | `goal`, `parent_id` |
| `agent_end` | — | `outcome`, `summary` |
| `agent_pause` | `pause_id` | `reason`, `user_id` |
| `agent_resume` | `pause_id` | `reason`, `user_id` |
| `model_request` | — | `model`, `messages`, `system`, `tools`, `request_id` |
| `model_response` | — | `model`, `stop_reason`, `input_tokens`, `output_tokens`, `content`, `role`, `request_id`, `duration_ms` |
| `tool_use` | `tool_name`, `tool_call_id` | `input` |
| `tool_result` | `tool_name`, `tool_call_id` | `output`, `error` |
| `hook_triggered` | `hook_name`, `hook_id` | `trigger_event`, `input` |
| `hook_completed` | `hook_name`, `hook_id` | `outcome`, `output`, `error` |
| `error` | `error_type`, `message` | `traceback` |
| `human_wait` | `input_id` | `prompt`, `options`, `reason` |
| `human_input` | `input_id` | `response` |
| `human_pause` | — | `reason`, `user_id` |
| `human_interrupt` | — | `reason`, `user_id`, `at_step` |

</Accordion>

<Warning>
  若要将某次运行标记为失败，`outcome` 必须为以下值之一：`failed`、`error`、`timeout` 或 `rejected`。其他任何值——包括拼写相近的 `"failure"`——都会被视为成功。
</Warning>

## 配对与耗时

**唯一规则：关闭事件必须与其对应的开启事件使用相同的 id。** 这是配对的依据，也是 SDK 计算耗时的基础。

| 事件对 | 匹配字段 |
| --- | --- |
| `tool_use` → `tool_result` | `tool_call_id` |
| `hook_triggered` → `hook_completed` | `hook_id` |
| `agent_pause` → `agent_resume` | `pause_id` |
| `human_wait` → `human_input` | `input_id` |
| `model_request` → `model_response` | `request_id` |

**请勿自行传入 `duration_ms`。** SDK 会自动测量，手动传入将抛出 `ValueError`。

唯一例外是 `model_response`——只有您才知道真实的 provider 延迟。请传入整数毫秒值，浮点数会抛出异常，因为该列为 32 位整数，否则会导致存储为空。

<Accordion title="边界情况" icon="circle-help">

- **id 只需在同类事件、同一 session 内保持唯一。** 工具调用和 hook 可以共用同一个 id；同时运行的两个 session 也可以复用相同的 id 而不会冲突。
- **id 不限定于某个 agent 的作用域。** 在一个 agent 下开启、在另一个 agent 下关闭的事件对依然能成功匹配——这在多 agent 代码中是正常情况。
- **`request_id` 可选但推荐填写。** 不填时，模型事件按到达顺序配对，同一 agent 内的两个并发调用可能会错误配对。
- **跨进程的事件对**仍可在 Cloud 中完成匹配，但 SDK 无法计算耗时——因为没有任何一个进程同时见到了两半。
- **最多允许 10,000 个开启事件等待配对。** 超出此限制后，最旧的事件将被丢弃，以防内存泄漏无限增长。

</Accordion>

## 自定义字段

额外传入的关键字参数会随事件一并存储：

```python
failproofai_sdk.event.tool_use(
    tool_name="search", tool_call_id="c1",
    fw_tenant="acme", fw_region="eu-west-1",     # 自定义字段
)
```

如需后续查询，建议使用 JSON 兼容类型。其他类型——UUID、datetime、`Decimal`、集合、字节串、模型对象——均会以字符串形式存储。

<Warning>
  **请为自定义字段名添加前缀。** 自定义字段最后应用，因此名为 `model`、`tool_name` 或 `outcome` 的字段会静默覆盖原有字段。框架适配器使用 `fw_` 前缀；您也这样做就不会产生冲突。

  这也是为什么拼写错误的可选字段不会报错——它只会变成一个新的自定义字段。如果 Cloud 中某个标准字段缺失，请先检查拼写。
</Warning>

以下五个名称为保留字段，传入后会直接被拒绝：`timestamp`、`session_id`、`agent_id`、`type`、`environment`。

## 投递与验证

<Tabs>
  <Tab title="控制台">
    在 **Observe → Events** 中，确认 `agent_start` 是第一个事件，`agent_end` 是最后一个事件。然后打开 **Observe → Sessions**，确认模型、工具、人工、hook 和错误事件按预期顺序出现。以 session ID 作为排查问题的主要线索。
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai flush --wait --timeout 60
    failproofai config --status
    fp sessions --since 1h --env production --session-id <session-id>
    fp events --since 1h --session-id <session-id> --full
    ```
  </Tab>
</Tabs>

若 Cloud 中无数据，请检查 `$FAILPROOFAI_HOME/custom-agents/events`，否则检查 `~/.failproofai/custom-agents/events`。存在 JSONL 文件说明 SDK 已正常发出事件；spool 持续增大说明问题出在守护进程配置或数据投递上；spool 为空则说明问题出在接入代码或进程生命周期上。

<Note>
  仅在守护进程停止时检查 spool。守护进程运行期间，它会在毫秒内完成每批数据的采集和删除，因此目录列表会与采集器竞争，显示的事件数量远少于实际发出的数量。
</Note>

## 在自定义运行时中防止故障

利用审计发现和关联追踪来明确不安全操作、所需证据及预期响应。自定义执行接入方案必须在操作执行前暴露该操作，将其结构化输入传递给策略引擎，并应用返回的 allow、instruct 或 deny 决策。

[联系 Failproof AI](mailto:support@befailproof.ai)，我们将协助您将运行时的模型、工具和生命周期边界映射到策略钩子，并与您共同验证集成方案。
