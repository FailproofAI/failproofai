## 事件类型

- Agent 启动、结束、暂停和恢复
- 模型请求与响应
- 工具调用与结果
- Hook 触发与完成
- 人工等待、输入、暂停和中断
- 显式错误

每个事件都包含时间戳、会话 ID、Agent ID、事件类型和环境信息。事件特定字段包含模型、工具、关联、结果、内容、持续时间或错误数据。

## 检查事件契约

<Tabs>
  <Tab title="控制台">
    1. 打开 **Observe → Events**。
    2. 设置较短的时间窗口，并按环境、Agent 和事件类型进行筛选。
    3. 选择一个事件以检查其标准化字段和原始载荷，然后打开其会话查看执行上下文。
    4. 如果缺少配对的持续时间，请确认开始事件和完成事件使用相同的关联 ID。

    使用事件流将数据缩小到单次 Agent 运行，并检查标准化事件字段。

    ![带有环境、Agent、会话和事件类型筛选器的实时事件流。](/images/dashboard/events-stream.png)

    然后跟随事件进入其会话。追踪视图显示该事件前后发生的内容，当载荷本身不明确时，这一信息尤为必要。

    ![用于在执行上下文中检查事件的关联会话追踪。](/images/dashboard/session-detail.png)

    当配对事件或持续时间缺失时，请在两个视图中对比关联 ID 和时间戳。
  </Tab>
  <Tab title="CLI">
    先获取有效的筛选值，再拉取某个会话的完整事件载荷：

    ```bash
    fp list event_types
    fp list envs
    fp events --since 1h \
      --env production \
      --event-type tool_use,tool_result \
      --session-id <session-id> \
      --full
    ```

    使用 `fp --json events ... --fields ts,event_type,session_id,payload` 进行机器可读的检查。
  </Tab>
</Tabs>

## SDK 保留字段

请勿将 `timestamp`、`session_id`、`agent_id`、`type` 或 `environment` 用作自定义 Python SDK 字段。工具结果持续时间等配对事件的持续时间由 SDK 自动计算，无法手动提供。

## 本地边界

- Failproof AI 的状态默认存储在 `~/.failproofai` 下，除非明确配置了其他路径。
- `failproofai-sdk` 始终在 `~/.failproofai/custom-agents` 下进行缓冲写入。`FAILPROOFAI_HOME` 可重新定位该主目录；`custom-agents` 段始终会被追加，因此缓冲目录无法置于其外部。只有 SDK 自身的 `configure(base_dir=...)` 才会写入其他位置。`AGENTEYE_HOME` 由旧版 `agenteye-collector` 读取以确定监控目标，不再影响 SDK 的写入位置。
- 环境标签可通过 SDK 配置或 `AGENTEYE_ENVIRONMENT` 设置。
- 守护进程凭据与非敏感设置分开存储。

请使用稳定、低基数的环境名称。守护进程环境标签不支持逗号。

## 修改环境标签

<Tabs>
  <Tab title="控制台">
    环境标签由发出事件的 SDK 或 Failproof 守护进程分配。修改后，打开 **Observe → Sessions** 并使用环境筛选器确认新会话携带了新值。已有会话将保留其原始环境标签。

  </Tab>
  <Tab title="CLI">
    对于 `failproofai-sdk`，可在代码中配置环境，也可使用其旧版环境变量。修改机器级别设置时，请重新运行守护进程配置。

    ```bash
    export AGENTEYE_ENVIRONMENT=production-us-east
    failproofai config
    failproofai config --status
    fp sessions --since 1h --env production-us-east
    ```
  </Tab>
</Tabs>
