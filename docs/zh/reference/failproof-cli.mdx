使用 `npm install -g failproofai` 安装。不带参数运行 `failproofai` 可打开本地仪表板。

## 核心命令

| 命令 | 功能说明 |
| --- | --- |
| `failproofai config` | 配置 Agent、后台服务及可选的 Cloud 连接 |
| `failproofai config --token <key>` | 免交互配置并连接 |
| `failproofai config --status` | 显示连接状态、服务版本和暂停状态 |
| `failproofai policies` | 列出策略及其启用状态 |
| `failproofai policies add <name>` | 启用某条策略 |
| `failproofai policies add <owner>/<repo>` | 安装策略包 |
| `failproofai policies remove <name-or-pack>` | 禁用策略或移除策略包 |
| `failproofai policies show <owner>/<repo>` | 安装前查看策略包内容 |
| `failproofai publish` | 将你的策略发布为策略包 |
| `failproofai audit` | 扫描本地 Agent 历史记录 |
| `failproofai harness` | 管理额外的会话位置 |
| `failproofai flush` | 立即发送队列中的事件 |
| `failproofai backfill` | 重新读取较早的 Agent 历史记录 |
| `failproofai update` | 完成 npm 升级并更新服务 |
| `failproofai uninstall` | 移除钩子和服务 |

`policy`、`pack` 和 `p` 均为 `policies` 的别名，但文档统一使用 `policies`。

## 配置机器

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai config --status
```

初始配置不会选择任何策略包。在添加策略包之前，仅运行 `block-failproofai-commands`。

无人值守的 Cloud 配置方式：

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

如需在不发送会话记录的情况下上报决策，请先完成连接，然后在 `~/.failproofai/config.json` 中将 `collector.sessions` 设为 `false`。当前 `--no-transcripts` 启动标志已被解析，但不会自动应用该设置。

在机器完成连接后，使用 `--machine-label <name>` 可对其重命名。`--connect <url>` 是仅用于注册的命令，适用于已完成配置的机器。

## 策略与策略包

```bash
failproofai policies
failproofai policies add block-sudo
failproofai policies show owner/repo
failproofai policies add owner/repo --category git,database
failproofai policies remove owner/repo
```

包含斜杠的参数为策略包来源，不含斜杠的参数为策略名称。

常用策略包选择标志：

| 标志 | 用途 |
| --- | --- |
| `--policy a,b` | 选择指定名称的策略 |
| `--category x,y` | 按类别选择 |
| `--all` | 选择全部 |
| `--cli <agents...>` | 限定为指定的 Harness |

使用 `failproofai policies -i -c <path>` 可从任意路径加载自定义策略。`.failproofai/policies/` 目录下符合 `*policies.{js,mjs,ts}` 命名规范的文件会自动加载。

## 暂停策略执行

```bash
failproofai config --pause 10m
failproofai config --status
failproofai config --resume
```

暂停仅作用于当前本地会话，且始终会到期。它不会暂停 Cloud 管理的策略或 `block-failproofai-commands`。

## 审计与数据上报

```bash
failproofai audit
failproofai audit --schedule 7 --email team@example.com
failproofai audit --status
failproofai flush --wait
failproofai backfill --since 30d --dry-run
```

`backfill` 会读取 `~/.failproofai/config.json`。去掉 `--dry-run` 即可重新发送历史记录。

## 额外会话位置

```bash
failproofai harness list
failproofai harness add-path claude work=/srv/team/.claude/projects
failproofai harness remove-path claude work
```

标签可防止来自两个相同 Home 目录副本的会话因推导出相同 Agent ID 而被合并。

支持的 Harness 包括：`claude`、`codex`、`copilot`、`cursor`、`opencode`、`pi`、`hermes`、`openclaw`、`factory`、`devin`、`antigravity` 和 `goose`。各 Harness 的作用域支持情况不同，详见 [Harnesses](/zh/reference/harnesses)。

## 常用环境变量

| 变量 | 用途 |
| --- | --- |
| `FAILPROOFAI_CLOUD_TOKEN` | Cloud 机器密钥 |
| `FAILPROOFAI_CLOUD_URL` | 覆盖 Cloud URL |
| `FAILPROOFAI_HOME` | 修改本地状态目录路径 |
| `FAILPROOFAI_NO_DOWNLOAD=1` | 拒绝下载策略包和服务 |
| `FAILPROOFAI_DAEMON_BASE_URL` | 使用服务二进制镜像 |
| `FAILPROOFAI_PACK_BASE_URL` | 使用策略包镜像 |
| `FAILPROOFAI_NO_FIRST_RUN=1` | 禁用首次运行提示 |
| `FAILPROOFAI_TELEMETRY_DISABLED=1` | 禁用匿名 CLI 遥测 |
| `FAILPROOFAI_<HARNESS>_EXTRA_PATHS` | 替换某个 Harness 的额外路径 |
| `NO_COLOR` | 禁用终端颜色输出 |

## 移除或升级

```bash
npm install -g failproofai@latest
failproofai update
```

移除软件包前请先执行：

```bash
failproofai uninstall --dry-run
failproofai uninstall --yes
npm rm -g failproofai
```

<Warning>
  请在移除 npm 包之前运行 `failproofai uninstall`。npm 不会自动移除已安装的钩子或后台服务。
</Warning>

运行 `failproofai help <command>` 可查看当前安装版本的完整选项。
