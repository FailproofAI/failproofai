运行环境是指 Agent 实际运行所在的载体。Failproof AI 支持十二种，分为两类：

- **编程 CLI**（10 种）— Claude Code、Codex、GitHub Copilot CLI、Cursor、OpenCode、Pi、Factory Droid、Devin CLI、Antigravity CLI、Goose
- **聊天与助手网关**（2 种）— Hermes（Slack、Telegram、cron）、OpenClaw（自托管助手）

无论 Agent 运行在哪种环境中，适用的策略和会话历史记录均相同。一个适配层会在任何策略运行之前，将每种运行环境的原生事件名称、工具名称和工具输入字段映射到 29 个规范事件上。

如果 Agent 运行在**以上十二种之外**的环境中，则可直接使用 [Python SDK](/zh/reference/custom-agents) 进行埋点。这是一种不同的契约，值得明确说明：SDK 提供追踪、会话、评估和审计功能——**但它本身不执行策略。** 在不安全操作执行之前进行拦截，需要在运行时的工具边界处设置执行钩子；请[联系我们](mailto:support@befailproof.ai)，我们将为您完成映射。

| 运行环境 | 支持的钩子作用域 |
| --- | --- |
| Claude Code | 用户、项目、本地 |
| Codex、GitHub Copilot CLI、Cursor、OpenCode、Pi | 用户、项目 |
| Factory Droid、Devin CLI、Antigravity CLI、Goose | 用户、项目 |
| Hermes、OpenClaw | 用户 |

每个集成都会在策略运行之前对其原生钩子事件名称、工具名称和工具输入字段进行规范化。策略只能作用于该运行环境所暴露的事件；请在您实际部署的运行环境和版本上测试轮次结束和指令行为。

## 执行能力

"拦截"指当前适配器返回的裁决被指定运行环境所采纳。工具执行后的拦截可能会替换返回给模型的结果，但无法撤销已经发生的工具副作用。

| 运行环境 | 已验证的拦截事件 | 仅观测或非拦截说明 |
| --- | --- | --- |
| Claude Code | `PreToolUse`、`UserPromptSubmit`、`PermissionRequest`、`Stop`、`SubagentStop`、`PreCompact` 及若干任务/配置事件 | `PostToolUse`、会话生命周期、通知以及失败后事件仅供观测。 |
| Codex | `PreToolUse`、`PermissionRequest`、`UserPromptSubmit`、`Stop`、`SubagentStop`、`PostToolUse` | 工具执行后的拦截会在执行完成后替换结果；当前适配器中会话启动和压缩事件仅供观测。 |
| GitHub Copilot CLI | `PreToolUse`、`UserPromptSubmit`、`PermissionRequest`、`Stop`、`SubagentStop`、`PostToolUse` | 工具执行后的拦截会在执行完成后替换结果；会话和通知事件仅供观测。 |
| Cursor | `PreToolUse`、`UserPromptSubmit`、`Stop` | `PostToolUse` 和会话事件仅供观测。 |
| OpenCode | `PreToolUse` | 工具执行后和生命周期事件仅供观测；当前的停止处理是对后续轮次的引导，而非已验证的拦截门。 |
| Pi | `PreToolUse`、`UserPromptSubmit` | 工具执行后和生命周期事件仅供观测；停止引导适用于后续轮次。 |
| Hermes | `PreToolUse` | `deny()` 可拦截。`instruct()` 不会阻止调用：调用会继续执行，引导内容会置于其结果的开头。工具执行后、会话和子 Agent 停止裁决不是拦截门。 |
| OpenClaw | `PreToolUse`、`UserPromptSubmit`、`Stop` | 工具执行后、会话、子 Agent 停止和压缩事件仅供观测。 |
| Factory Droid | `PreToolUse`、`UserPromptSubmit`、`Stop`、`PreCompact` | 工具执行后和子 Agent 停止裁决仅供观测。 |
| Devin CLI | `PreToolUse`、`UserPromptSubmit`、`Stop`、条件性 `PermissionRequest` | 权限钩子并非在所有权限模式下都会运行；工具执行后和会话事件仅供观测。 |
| Antigravity CLI | `PreToolUse`、`Stop` | 用户提示和工具执行后裁决仅供观测；提示指令仍可注入。 |
| Goose | `PreToolUse` | 用户提示、工具执行后和会话事件仅供观测。上游存在原生拦截停止钩子，但当前适配器未安装。 |

功能与版本密切相关。升级 Agent CLI 后请重新测试，尤其是当策略依赖提示、停止、权限或工具执行后行为而非常见的工具执行前拦截门时。

### Hermes 原生插件

Hermes 通过 profile 本地的原生插件进行集成，而非通过 shell 命令。安装时会将每个默认和命名的 Hermes profile 的 `plugins/failproofai` 链接到 npm 包中附带的插件（在无法创建符号链接的情况下使用副本），在该 profile 的 `config.yaml` 中启用它，并仅迁移旧版 FailproofAI shell 钩子条目。由于插件使用链接方式，执行 `npm install -g failproofai@latest` 即可更新，无需重新安装。这避免了每次钩子触发时的进程派生。该插件支持 Hermes 0.20.0 及更高版本。

旧版 shell 钩子（由 1.0.5 及更早版本安装）**不会**检查 Hermes cron 任务：每次 cron 运行都会构建自己的钩子作用域，原生插件会加入其中，而 `config.yaml` 中的 shell 钩子则不会。`failproofai update` 会将所有已使用 FailproofAI 的 profile 迁移到链接插件。如果正在运行的守护进程无法为插件提供服务，`update` 会保留 shell 钩子原样并以非零状态退出；请先运行 `failproofai config` 更新守护进程，然后再次运行 `failproofai update`。Cron 任务在下次运行时会加载插件；重启正在运行的网关和交互式会话以在其中加载插件。

在 Hermes 上，`deny()` 会拦截调用，而 `instruct()` 不会：调用会继续执行，引导内容会置于其结果的开头——作为 JSON 结果的第一个键 `failproof_policy_reminder`，或作为前导的 `[FailproofAI policy reminder (...)]` 行——这样模型可以在读取输出时看到它，而解析结果的脚本也能继续正常工作。策略提醒在每个轮次中只显示一次，并在结果较大时保持简短。当某个操作绝对不应发生时，请使用 `deny()`：`instruct()` 不再首先阻止该操作。从 `execute_code` 脚本发起的工具调用会将其提醒附加到模型读取的 `execute_code` 结果上；脚本自身的结果副本保持不变。模型被告知永远不要在回复中引用提醒内容。

不含插件中间件的 Hermes 构建会回退为对匹配的调用暂停一次并显示"FailproofAI policy guidance"；下一次模型响应可能会重复该操作，或使用另一个工具执行相同的工作，而不再被暂停。

工具名称跨 Hermes 版本进行匹配：`process_manage`、`cronjob_manage` 和 `todo_list`（Hermes 0.21）被视为等同于 `process`、`cronjob` 和 `todo`（Hermes 0.20）。每次 Hermes 加载插件时，都会在 profile 的 `plugin-data/agent-plugin-failproofai-5296f299/` 目录中写入 `heartbeat.json`，记录 Hermes 版本、插件路径和版本以及 Hermes 接受的钩子。运行 `failproofai config --status` 可检测已禁用、不完整、重复或新未配置的 profile，或仍使用旧版 shell 钩子的 profile（报告为"Hermes cron jobs are not checked"）。

### OpenClaw 插件

OpenClaw 将 FailproofAI 作为进程内网关插件加载，并注册到每个 profile 的 `openclaw.json` 中。与 Hermes 插件类似，它通过套接字向本地 `failproofaid` 守护进程请求每个裁决，因此需要守护进程处于运行状态：安装时若守护进程未运行则会拒绝安装，若守护进程无法响应，工具调用和提示会被拦截，原因会写入网关日志。执行 `npm install -g failproofai@latest` 后，重启 OpenClaw 网关以加载更新的插件。

### Codex 钩子信任

Codex 0.129 及更高版本只有在您在交互式 `codex`（"Review hooks"）中批准钩子后，才会运行来自 `~/.codex/hooks.json` 的钩子；在此之前，每个 Codex 会话——包括无界面的 `codex exec`——都会跳过它。位于 Codex 系统配置（Linux 和 macOS 上为 `/etc/codex/config.toml`）中的钩子无需该批准即可运行。

因此，当 `failproofai config`（或用户作用域下的 `policies --install --cli codex`）可以使用 sudo 时，它会将 Codex 钩子写入 `/etc/codex/config.toml`，置于 `# >>> failproofai managed hooks >>>` 和 `# <<< failproofai managed hooks <<<` 之间，其余内容保持不变。该文件适用于机器上的每个账户。`failproofai uninstall` 和在 `failproofai config` 中取消勾选 Codex 会将该块移除。

若没有 sudo 权限，或在 Windows 上，钩子将保留在 `~/.codex/hooks.json` 中。`failproofai config` 和 `failproofai config --status` 在钩子获得批准之前不会将 Codex 视为已执行，并会说明修复方法：重新运行 `failproofai config` 并允许使用 sudo，或打开 `codex` 一次并批准钩子。

## 安装捕获和策略钩子

<Tabs>
  <Tab title="控制台">
    1. 打开**管理 → 密钥**，创建一个具有 `events:add` 和 `policies:pull` 权限的密钥，以机器或环境命名。
    2. 在目标机器上，使用显示的密钥连接本地 CLI 并安装运行环境钩子。
    3. 启动一个新的 Agent 会话，然后在**观测 → 事件**下确认其钩子和会话事件。
    4. 打开**观测 → 策略**并查看相同时间窗口，确认策略决策归属于该机器。

    连接从机器密钥开始。在复制其密钥前，请确认它同时包含数据采集和策略下发权限。

    ![用于授予事件采集和策略下发权限的新 API 密钥抽屉。](/images/dashboard/key-create.png)

    安装钩子后，事件流应显示来自您所连接的机器和环境的新事件。

    ![用于确认新安装的运行环境正在上报的实时事件流。](/images/dashboard/events-stream.png)

    最后，验证策略决策是否归属于同一台机器。这可确认运行环境同时上报策略活动和追踪事件。

    ![用于验证新连接运行环境策略决策的策略页面。](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    将机器密钥读入 shell。`read -s` 会在不回显的提示符下读取，因此它不会出现在命令或 shell 历史记录中：

    ```bash
    read -rs FAILPROOFAI_CLOUD_TOKEN && export FAILPROOFAI_CLOUD_TOKEN
    ```

    然后配置机器——这将为所有检测到的运行环境连接钩子、安装守护进程并连接到 Cloud：

    ```bash
    failproofai config
    failproofai policies add FailproofAI/policies
    ```

    配置本身不启用任何策略，这正是第二条命令的作用。

    或者指定命名的运行环境和配置作用域：

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    项目作用域将钩子配置保留在代码仓库中。用户作用域涵盖跨代码仓库的工作。Claude Code 还支持本地作用域；各运行环境的支持情况不同，CLI 会拒绝不支持的组合。

    验证机器及其事件：

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

## 添加非默认会话路径

<Tabs>
  <Tab title="控制台">
    额外路径在机器上注册，而非在 Cloud 中。添加后，打开**观测 → 会话**，筛选至该机器的环境，并确认来自新路径的会话出现。在依赖其进行审计之前，请打开一个会话并检查 Agent、运行环境和事件时间戳。

    ![过滤到接收额外捕获路径数据的环境的会话列表。](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    添加一个带有可选标签的路径，然后查看已配置的路径：

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    使用 `failproofai harness remove-path claude checkout` 删除路径。
  </Tab>
</Tabs>

<Tip>
  安装后运行一个新会话。在扩大部署范围之前，请验证实时事件流和实际策略决策。
</Tip>
