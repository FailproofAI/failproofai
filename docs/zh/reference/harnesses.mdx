运行环境（harness）是指 Agent 实际运行所在的容器或框架。Failproof AI 支持十二种运行环境，分为两类：

- **编码 CLI**（10 种）—— Claude Code、Codex、GitHub Copilot CLI、Cursor、OpenCode、Pi、Factory Droid、Devin CLI、Antigravity CLI、Goose
- **聊天与助手网关**（2 种）—— Hermes（Slack、Telegram、cron）、OpenClaw（自托管助手）

无论 Agent 运行在哪个环境中，使用的都是相同的策略和会话历史记录。一个适配器层会在任何策略运行之前，将每种运行环境的原生事件名称、工具名称和工具输入字段映射到 29 个规范事件上。

对于不属于上述十二种环境的 Agent，可直接使用 [Python SDK](/zh/reference/custom-agents) 进行接入。这是一种不同的接入方式，有必要明确说明：SDK 提供追踪、会话、评估和审计功能——**它本身不强制执行策略。** 若要在不安全操作执行前将其阻断，需要在运行时的工具边界处安装执行钩子；请[联系我们](mailto:support@befailproof.ai)，我们将为您完成映射。

## 钩子作用域

| 运行环境 | 支持的钩子作用域 |
| --- | --- |
| Claude Code | 用户、项目、本地 |
| Codex、GitHub Copilot CLI、Cursor、OpenCode、Pi | 用户、项目 |
| Factory Droid、Devin CLI、Antigravity CLI、Goose | 用户、项目 |
| Hermes、OpenClaw | 用户 |

Claude Code 是唯一支持 **本地（local）** 作用域的运行环境。Hermes 和 OpenClaw 完全没有项目配置——它们仅支持用户作用域，CLI 会拒绝对其使用 `--scope project`。

每个集成在策略运行前都会对原生钩子事件名称、工具名称和工具输入字段进行规范化处理。策略只能作用于运行环境所暴露的事件；请在实际部署的运行环境和版本上测试回合结束及指令行为。

## 执行能力

"阻断"表示当前适配器返回的裁决会被指定运行环境所消费。工具后阻断可能会替换呈现给模型的结果，但无法撤销已发生的工具副作用。

| 运行环境 | 已验证的阻断事件 | 仅观测或不可阻断的注意事项 |
| --- | --- | --- |
| Claude Code | `PreToolUse`、`UserPromptSubmit`、`PermissionRequest`、`Stop`、`SubagentStop`、`PreCompact` 及若干任务/配置事件 | `PostToolUse`、会话生命周期、通知及失败后事件仅用于观测。 |
| Codex | `PreToolUse`、`PermissionRequest`、`UserPromptSubmit`、`Stop`、`SubagentStop`、`PostToolUse` | 工具后阻断在执行完成后替换结果；会话启动和压缩事件在当前适配器中仅用于观测。 |
| GitHub Copilot CLI | `PreToolUse`、`UserPromptSubmit`、`PermissionRequest`、`Stop`、`SubagentStop`、`PostToolUse` | 工具后阻断在执行完成后替换结果；会话和通知事件仅用于观测。 |
| Cursor | `PreToolUse`、`UserPromptSubmit`、`Stop` | `PostToolUse` 和会话事件仅用于观测。 |
| OpenCode | `PreToolUse` | 工具后和生命周期事件仅用于观测；当前的停止处理是针对后续回合的指导，而非已验证的拦截点。`PermissionRequest` 完全不会运行。 |
| Pi | `PreToolUse`、`UserPromptSubmit` | 工具后和生命周期事件仅用于观测；停止指导适用于后续回合。 |
| Hermes | `PreToolUse` | 工具后、会话和子 Agent 停止裁决不作为拦截点。未安装 `Stop` 事件。 |
| OpenClaw | `PreToolUse`、`UserPromptSubmit`、`Stop` | 工具后、会话、子 Agent 停止及压缩事件仅用于观测。 |
| Factory Droid | `PreToolUse`、`UserPromptSubmit`、`Stop`、`PreCompact` | 工具后和子 Agent 停止裁决仅用于观测。 |
| Devin CLI | `PreToolUse`、`UserPromptSubmit`、`Stop`、条件性 `PermissionRequest` | 权限钩子并非在所有权限模式下均会运行；工具后和会话事件仅用于观测。 |
| Antigravity CLI | `PreToolUse`、`Stop` | 用户提示和工具后裁决仅用于观测；提示指令仍可被注入。 |
| Goose | `PreToolUse` | 用户提示、工具后和会话事件仅用于观测。上游存在原生阻断停止钩子，但当前适配器未安装。 |

两列均未出现的事件**未经验证**——请将其视为未知状态，而非阻断状态。

### 已列出拦截点的条件说明

上表中若干拦截点确实有效，但存在约束或条件。依赖这些拦截点的策略需要同时满足相应条件。

| 运行环境 | 事件 | 条件 |
| --- | --- | --- |
| Claude Code | `Stop`、`SubagentStop` | 受 `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` 限制，默认值为 8。在回合结束路径上会被丢弃 |
| Cursor | `Stop` | 受 `loop_limit` 限制，默认值为 5，且仅在回合正常完成时被消费——用户中止或回合错误会导致其被丢弃 |
| Cursor | `Stop` | **Cursor Cloud Agent 虚拟机不运行任何 `stop` 或 `subagentStop` 钩子。** 该拦截点仅覆盖本地会话 |
| Codex | `SubagentStop` | 仅 ThreadSpawn 子 Agent 会触发该事件；其他所有子 Agent 来源均不会运行该钩子 |
| GitHub Copilot CLI | `SubagentStop` | 对 `isSidekick` 子 Agent 完全跳过 |
| Devin CLI | `PermissionRequest` | 在 `--permission-mode dangerous` 模式下不会触发，对自动批准的只读工具也不会触发 |
| OpenCode | `PermissionRequest` | 无效钩子：`permission.ask` 在上游已声明并有文档说明，但从未被调用，因此策略根本不会运行 |
| Hermes | `Stop` | 有意不安装 `Stop` 事件。五个 `require-*-before-stop` 内置规则在 Hermes 上不适用 |
| Goose | `Stop` | 同上：未安装 `Stop`，因此五个 `require-*-before-stop` 内置规则同样不适用 |

### `instruct()` 降级的情况

策略返回的裁决不只有 `deny`。`instruct()` 向 Agent 传递指令并允许操作继续执行——但并非每个运行环境都有传递指令的通道。若不存在通道，failproofai 会允许该操作，并将指令写入 stderr 供操作员日志使用；模型不会看到该指令。

| 运行环境 | `instruct()` 降级为 stderr 注记的事件 |
| --- | --- |
| Hermes | 所有事件 |
| Goose | 所有事件 |
| Pi | 除 `Stop` 外的所有事件 |
| OpenClaw | 除 `Stop` 外的所有事件 |
| Factory Droid | 除 `Stop` 外的所有事件 |
| Antigravity CLI | 除 `Stop` 和 `UserPromptSubmit` 外的所有事件 |

在其他所有情况下，指令会通过运行环境自身的附加上下文通道返回。

## VS Code Agent 模式

VS Code 内置的 Copilot Chat Agent 模式**不是第十三种集成**。它从 `.github/hooks/*.json`、`~/.copilot/hooks/*.json` 和 `~/.claude/settings.json` 中发现钩子配置——这正是 `copilot` 和 `claude` 安装时已写入的路径——并使用相同的 Claude 式拒绝契约。安装其中任意一个，即可在 VS Code Agent 模式会话中实现策略执行。

该功能目前处于预览阶段，需要有效的 GitHub Copilot 订阅及 Agent 模式支持。

## 安装捕获和策略钩子

<Tabs>
  <Tab title="Dashboard">
    1. 打开 **Administration → Keys**，创建一个具有 `events:add` 和 `policies:pull` 权限的密钥，以机器或环境命名。
    2. 在目标机器上，使用显示的密钥连接本地 CLI。
    3. 启动一个新的 Agent 会话，然后在 **Observe → Events** 下确认其钩子和会话事件。
    4. 打开相同时间窗口的 **Observe → policy**，确认策略决策已归因到该机器。

    连接从机器密钥开始。复制密钥前，请确认其包含数据摄取和策略传递权限。

    ![新建 API 密钥面板，用于授予事件摄取和策略传递权限。](/images/dashboard/key-create.png)

    安装钩子后，Events 流应显示来自所连接机器和环境的新事件。

    ![实时 Events 流，用于确认新安装的运行环境正在上报数据。](/images/dashboard/events-stream.png)

    最后，验证策略决策已归因到同一台机器。这可确认运行环境在上报追踪事件的同时，也在上报策略活动。

    ![策略页面，用于验证新连接的运行环境所产生的策略决策。](/images/dashboard/policy-observe.png)
  </Tab>
  <Tab title="CLI">
    `failproofai config` 会将钩子接入所找到的所有受支持 Agent CLI，安装守护进程，并在存在密钥时连接到 Cloud：

    ```bash
    failproofai config --token <machine-key>
    failproofai policies add FailproofAI/policies
    ```

    初始化不会选择任何策略，因此需要执行第二条命令。

    若要手动接入单个运行环境——省略 `--cli` 时，`--install` 会检测已安装的环境并提示：

    ```bash
    failproofai policies --install \
      --cli claude codex cursor \
      --scope user
    ```

    项目作用域将钩子配置与代码仓库绑定。用户作用域覆盖跨仓库的工作。组合使用 `--cli` 和 `--scope` 之前，请查阅上方的作用域表；CLI 会拒绝不支持的组合。

    验证机器及其事件：

    ```bash
    failproofai config --status
    failproofai flush --wait
    fp events --since 1h --event-type hook_triggered,hook_completed
    ```
  </Tab>
</Tabs>

<Warning>
  在从空目录启动的无头 `copilot -p` 运行中，项目作用域的 `.github/hooks/failproofai.json` **未被**加载。在验证此问题之前，请将用户作用域视为 CI 中 Copilot 可靠的策略执行点。
</Warning>

## 添加非默认会话路径

<Tabs>
  <Tab title="Dashboard">
    额外路径在机器上注册，而非在 Cloud 中。添加后，打开 **Observe → Sessions**，筛选到该机器的环境，确认来自新路径的会话已显示。打开一个会话，在将其用于审计前，检查 Agent、运行环境和事件时间戳。

    ![Sessions 列表，已筛选至接收额外捕获路径数据的环境。](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    添加带有可选标签的路径，然后查看已配置的路径：

    ```bash
    failproofai harness add-path claude checkout=/srv/checkout/.claude
    failproofai harness list claude
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    ```

    使用 `failproofai harness remove-path claude checkout` 删除路径。

    标签用于命名空间化衍生的 Agent ID。两个保存同一项目副本的位置会从记录中派生出相同的 ID，因此若不使用标签，它们会合并为同一个 Agent。系统会拒绝重叠的根路径和重复的标签——请参阅 [CLI 参考](/zh/reference/failproof-cli)了解每种拒绝的原因。
  </Tab>
</Tabs>

<Tip>
  安装后运行一次新会话。在扩大部署范围前，验证实时事件流和实际的策略决策。
</Tip>
