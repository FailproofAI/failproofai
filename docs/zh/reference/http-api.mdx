公开 API 在您的 Failproof AI 控制台域名下的 `/v1` 路径提供服务。

## 创建密钥并发起请求

<Tabs>
  <Tab title="控制台">
    1. 打开**管理 → 密钥**，选择**创建密钥**，并选择覆盖该集成所需的最小权限预设。
    2. 仅在必要时添加单独授权，创建密钥并复制一次性密钥。
    3. 向 `/v1/sessions` 发起测试请求，并在密钥页面确认密钥处于活跃状态。
    4. 当集成变更所有者时，通过其操作菜单轮换或禁用密钥。

    ![新 API 密钥抽屉，包含权限预设和单独授权。](/images/dashboard/key-create.png)

    上图展示了创建抽屉。一次性密钥仅在您点击**创建**后显示；请在关闭确认窗口前复制它。
  </Tab>
  <Tab title="CLI">
    创建一个只读密钥，并直接配合 `fp` 或 `curl` 使用：

    ```bash
    fp keys create reliability-reader \
      --permission-set read-only

    fp --api-key <key> sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/sessions?limit=20" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY"
    ```
  </Tab>
</Tabs>

密钥的作用范围限定在某个组织和权限集。若请求缺少接口所需的权限，将返回 `403` 并指明缺少的权限项。

## 组织选择

组织密钥会自动作用于其所属组织。实例级密钥可按请求选择组织：

<Tabs>
  <Tab title="控制台">
    在打开**管理 → 密钥**之前，使用控制台头部的组织切换器。在此处创建的密钥归属于所选组织。在将凭据复制到自动化流程之前，请确认 URL 中的组织 slug 与密钥详情一致。

  </Tab>
  <Tab title="CLI">
    在命令前使用 `--org`，或为实例级 API 密钥发送组织请求头。

    ```bash
    fp orgs list
    fp --org reliability-team sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/usage" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "X-AgentEye-Org: reliability-team"
    ```
  </Tab>
</Tabs>

请使用本节中生成的接口页面，查阅当前路径、参数、权限要求和状态码。该规范由服务器路由注解生成，并与 `/v1` 路由器进行校验。

当前规范已完整覆盖路由、方法、参数、权限和状态码。部分响应体有意保持无类型状态，因为服务器仍以动态 JSON 的方式构建它们。在为没有响应 schema 的接口生成强类型客户端之前，请先检查真实响应。

JSON 写入请使用 `Content-Type: application/json`。`401` 表示身份验证缺失或无效，`403` 表示身份有效但缺少所需权限，`404` 表示资源不存在或无法在当前组织访问，`409` 表示状态冲突，`422` 表示字段或权限值无效。错误响应包含可读的错误信息；权限失败时还会指明所需授权项。

<Warning>
  策略执行的部署有意在常规公开 `/v1` 接口之外进行管理。请使用受支持的 Cloud 部署工作流。
</Warning>
