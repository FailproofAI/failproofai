公共 API 托管在您的 Failproof AI 控制台域名的 `/v1` 路径下。

## 创建密钥并发送请求

<Tabs>
  <Tab title="控制台">
    1. 打开 **Administration → Keys**，选择 **Create key**，然后选择覆盖该集成所需的最小权限预设。
    2. 仅在必要时添加单独授权，创建密钥并复制其一次性密钥值。
    3. 向 `/v1/sessions` 发送测试请求，并在 Keys 页面确认密钥处于活跃状态。
    4. 当集成更换归属时，通过其操作菜单轮换或禁用该密钥。

    ![新 API 密钥抽屉，包含权限预设和单独授权选项。](/images/dashboard/key-create.png)

    上图为创建抽屉界面。一次性密钥值仅在您点击 **create** 后出现；请在关闭确认提示前复制它。
  </Tab>
  <Tab title="CLI">
    创建一个只读密钥，并直接通过 `fp` 或 `curl` 使用：

    ```bash
    fp keys create reliability-reader \
      --permission-set read-only

    fp --api-key <key> sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/sessions?limit=20" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY"
    ```
  </Tab>
</Tabs>

密钥的作用范围为某个组织及其权限集。若请求缺少端点所需权限，将返回 `403` 并指明缺失的权限项。

## 组织选择

组织密钥会自动作用于其所属组织。实例级密钥可在每次请求时指定组织：

<Tabs>
  <Tab title="控制台">
    在打开 **Administration → Keys** 之前，使用控制台顶部的组织切换器选择目标组织。在该界面创建的密钥将归属于已选组织。在将凭据复制到自动化流程之前，请通过 URL 和密钥详情确认组织 slug。

  </Tab>
  <Tab title="CLI">
    在命令前使用 `--org`，或在请求头中为实例级 API 密钥指定组织。

    ```bash
    fp orgs list
    fp --org reliability-team sessions --since 24h
    ```

    ```bash
    curl "https://app.befailproof.ai/v1/usage" \
      -H "Authorization: Bearer $FAILPROOFAI_KEY" \
      -H "X-AgentEye-Org: reliability-team"
    ```
  </Tab>
</Tabs>

请参阅本节中生成的端点页面，获取当前路径、参数、权限要求及状态码信息。该规范由服务器路由注解生成，并已针对 `/v1` 路由器进行核验。

当前规范对路由、方法、参数、权限和状态码具有完整覆盖。部分响应体有意保留为非类型化，因为服务器仍以动态 JSON 方式构建它们。在为没有响应 schema 的端点生成强类型客户端之前，请先检查真实的响应内容。

JSON 写入请使用 `Content-Type: application/json`。`401` 表示身份验证缺失或无效，`403` 表示身份有效但缺少所需权限，`404` 表示资源不存在或无法在该组织下访问，`409` 表示状态冲突，`422` 表示字段或权限值无效。错误响应包含人类可读的消息；权限失败时还会指明所需授权项。

事件摄入使用换行符分隔的 JSON 格式：每行一个完整对象。请在成功响应中同时检查 `accepted` 和 `skipped` 字段。在网络故障或收到 HTTP 408、429 或 5xx 响应后，请重试整个批次；重放相同的事件是安全的。历史批次可以跨越多个月。若摄入返回 `422` 且 `error: "event_too_large"`，请在重试前缩减相关事件的 payload 大小。将批次拆分为更小的请求不会缩减单个事件的大小。对于文件导入，重试时请复用原始的 `existing_before` 截止时间，以便部分已存储的会话能够完成。

## 请求 ID

每个响应都携带 `X-Request-Id` 响应头，每个 JSON 错误体也以 `request_id` 字段包含相同的值。联系支持时请提供该值：它可唯一标识该次请求。

您可以发送自己的 `X-Request-Id` 以将请求与您的日志关联。请使用 32 个小写十六进制字符，例如去掉连字符的 UUID v4。任何其他格式的值将被替换为新 ID，并在响应中返回。

<Warning>
  策略执行部署有意在常规公共 `/v1` 接口之外进行管理。请使用受支持的 Cloud 部署工作流。
</Warning>
