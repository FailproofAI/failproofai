本页介绍 [Jev 评估](/zh/evaluations/jev) 背后的问题形式与评分规则。有些问题需要模型*读取*对话内容，但无需*描述*它。"客户是否表达了紧迫感？"只有两个答案。"他们有多沮丧？"有几个有序的选项。在提问之前，你已经知道所有可能的答案。

**分类器评估**正是为此而设计的。你写好问题及其可能的答案，一个专门为分类任务构建的小型模型会返回一个校准数值——从不输出自由文本。

<Note>
与裁判评估一样，分类器评估每次会话都需要消耗一次模型调用。不同之处在于，它使用的是小型、单一用途的模型，而非通用模型，因此速度更快、成本更低——但它不会解释自己的判断。如果你需要推理过程，请使用[裁判评估](/zh/evaluations/judge)。
</Note>

## 我该用哪种？

| 问题 | 使用方式 |
| --- | --- |
| 总共调用了多少次工具？ | 代码 |
| 会话是否在 30 秒内完成？ | 代码 |
| 客户是否表达了紧迫感？ | **分类器** |
| 应由哪个团队处理：账单、技术还是销售？ | **分类器** |
| 客户有多沮丧？ | **分类器** |
| 答案是否真的正确？ | **裁判** |
| 它是否遵循了我们的升级策略，你为何这么认为？ | **裁判** |

经验法则：**可计数 → 代码，可列举答案 → 分类器，需要解释 → 裁判。**

无需提前做出决定。描述你想要衡量的内容，助手会自动选择，告知你选择了哪种方式及原因，你也可以随时切换。

## 两种问题类型

### `noul` — 这是真的吗？

两个答案，你对二者分别进行描述。结果是"真"描述符合情况的概率：

```json
{
  "instructions": "Did the assistant promise a refund without first checking the refund policy?",
  "criteria": {
    "true":  "A refund was promised or issued with no prior policy check or approval",
    "false": "No refund was promised, or every refund followed a policy check"
  }
}
```

两面都要描述。"未表达紧迫感"是一个真实的答案，明确描述它会让另一面更加清晰。

### `score` — 程度如何？

一个有序的评分标准，**从最差开始排列**。结果是会话在量表上的位置，重新缩放为 0–1：

```json
{
  "instructions": "How frustrated is the customer?",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
```

**评分标准需要三到五个级别，且所有级别必须各不相同。** 这两个限制均有实际依据，并非风格要求：

- **两个级别**退化为 `noul` 已经能更好处理的情况，**超过五个级别**则会让模型倾向于给出中间值而非明确判断。同一问题对同一会话：两个级别时得分 0.00，三个级别时 0.01，十个级别时 0.55。
- **重复级别**会在它们之间任意分配答案。一次明显愤怒的会话，对照 `["Calm", "Frustrated", "Very angry"]` 得分 1.00，对照 `["Angry", "Angry", "Angry"]` 却得分 0.66——这是一个格式正确但毫无意义的数字。

没有顺序的类别——如"账单、技术或销售"——不构成评分标准。可以对每个类别分别提一个 `noul` 问题，或使用裁判评估。

## 解读结果

分类器生成一个 0 到 1 的**分数**，与裁判评估完全相同，因此可以用同样的方式制图、筛选和触发警报。有两点不同值得注意：

- **没有推理过程。** 该字段有意为空。这个模型不解释自己的判断，编造一个解释只会是捏造，而非功能。
- **不确定性有标注。** `score` 类型的问题会报告自身的置信度，模型不确定的结果会被标记为 `low_confidence`——因此"哪些结果需要人工审查"是一个过滤条件，而非猜测。`noul` 类型的问题不报告置信度，因此永远不会被标记。

很长的会话会被分段读取后合并。当一次会话太长无法完整读取时，结果中会说明跳过了多少轮——你永远不会看到基于部分内容的判断被当作基于全部内容来呈现。

## 限制

- **评分标准三到五个级别，全部不同。** 见上文；两个边界在创作时均会强制执行。
- **每次评估只有一个问题。** 要问两件事就创建两个评估，这也正是你在图表上想要的效果。
- **编辑问题会发布新版本。** 新旧分数不可比较，因此会分开存储，而不是混入同一条趋势线。
- **分类器始终输出分数**，从不输出指标或断言。
- **没有推理过程**，如上所述。如果一个数字会让人追问"为什么？"，请改用裁判评估。

## 测试与回填

与裁判评估不同，分类器评估**可以**在部署前进行测试——[测试它](/zh/evaluations/test)的方式与代码评估相同，对真实会话进行测试，在上线前查看分数。

它也可以对已有的会话进行[回填](/zh/evaluations/deploy#score-sessions-you-already-have)。每次会话都会消耗一次模型调用，因此请有针对性地确定时间窗口，而不是重放所有内容。
