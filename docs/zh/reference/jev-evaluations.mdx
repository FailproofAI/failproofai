本页介绍 [Jev 评估](/zh/evaluations/jev) 背后的问题形式与评分规则。有些问题需要模型*读取*对话内容，而无需*撰写*相关内容。"客户是否表达了紧迫感？"只有两个答案。"他们有多沮丧？"则有几个有序的选项。你在提问之前就已经知道所有可能的答案。

**分类器评估**正是为此而生。你编写问题及其可能给出的答案，一个专为分类构建的小型模型会返回一个校准后的数字——永远不会是自由文本。

<Note>
与裁判（judge）一样，分类器评估每个会话都需要调用一次模型。与裁判不同的是，它是一个专用的小型单一模型，而非通用模型，因此速度更快、成本更低——但它永远不会解释自身的判断。如果你需要推理过程，请使用[裁判（judge）](/zh/evaluations/judge)。
</Note>

## 我应该选哪种？

| 问题 | 使用方式 |
| --- | --- |
| 总共调用了多少次工具？ | 代码 |
| 会话时长是否不足 30 秒？ | 代码 |
| 客户是否表达了紧迫感？ | **分类器** |
| 应该由哪个团队处理：账单、技术还是销售？ | **分类器** |
| 客户有多沮丧？ | **分类器** |
| 答案是否真正正确？ | **裁判** |
| 它是否遵循了我们的升级策略，你为何这么认为？ | **裁判** |

经验法则：**可计数 → 代码，可列举答案 → 分类器，需要解释 → 裁判。**

你不必提前做出决定。描述你想衡量的内容，助手会自动选择，告知你选了哪种以及原因，你也可以随时切换。

## 两种问题类型

### `noul` — 这是否成立？

两个答案，分别描述两种情况。结果是"成立"描述符合实际的概率：

```json
{
  "instructions": "助手是否在未核查退款政策的情况下承诺了退款？",
  "criteria": {
    "true":  "在未事先核查或审批政策的情况下承诺或发放了退款",
    "false": "未承诺退款，或每次退款均经过了政策核查"
  }
}
```

两种情况都需要描述。"未表达紧迫感"是一个真实的答案，明确说明它能让另一个答案更加清晰。

### `score` — 这种情况有多明显？

一个有序的评分标准，**从最差开始**。结果是会话在该标准上的位置，重新缩放至 0–1：

```json
{
  "instructions": "客户有多沮丧？",
  "criteria": ["平静", "有些沮丧", "非常愤怒"]
}
```

**评分标准需要三到五个级别，且所有级别必须各不相同。** 两个限制都有明确依据，并非风格上的随意规定：

- **两个级别**退化为 `noul` 已能更好处理的情形，**超过五个级别**则会让模型倾向于给出中间值而非明确判断。同一会话同一问题，两个级别得分为 0.00，三个级别为 0.01，十个级别则为 0.55。
- **重复的级别**会在它们之间任意分配答案。一个明显愤怒的会话，对照 `["平静", "有些沮丧", "非常愤怒"]` 得分为 1.00，而对照 `["愤怒", "愤怒", "愤怒"]` 则得分为 0.66——这是一个格式正确却毫无意义的数字。

没有顺序的类别——"账单、技术还是销售"——不构成评分标准。请针对每个类别分别提一个 `noul` 问题，或者使用裁判。

## 解读结果

分类器生成一个 0 到 1 的**分数**，与裁判完全一致，因此在图表展示、筛选过滤和触发告警方面的用法相同。有两点差异值得关注：

- **没有推理过程。** 该字段有意留空。这个模型不解释自身判断，凭空捏造一个解释只会是虚构，而非功能。
- **不确定性有标注。** `score` 类型的问题会报告自身的置信度，模型不确定的结果会被标记为 `low_confidence`——因此"哪些内容应该交由人工审查"是一个筛选条件，而非凭感觉猜测。`noul` 类型的问题不报告置信度，因此不会被标记。

过长的会话会以片段形式读取并合并。当会话太长而无法完整读取时，结果会说明跳过了多少轮对话——你永远不会看到基于部分会话所做的判断被当作完整会话的判断呈现出来。

## 限制

- **评分标准三到五个级别，且各不相同。** 见上文；两个边界在编写时即强制执行。
- **每次评估只问一个问题。** 要问两件事，就建两个评估——这在图表上也更清晰。
- **编辑问题会发布新版本。** 新旧分数不具可比性，因此会分开保存，而不是混入同一条趋势线中。
- **分类器始终生成分数**，不会生成指标或断言。
- **没有推理过程**，如上所述。如果一个数字会让人追问"为什么？"，请改用裁判。

## 测试与回填

与裁判不同，分类器评估**可以**在部署前进行测试——[测试方式](/zh/evaluations/test)与代码评估相同，直接针对真实会话进行测试，在上线前先查看分数。

它也可以对你已有的会话进行[回填](/zh/evaluations/deploy#score-sessions-you-already-have)。由于每个会话都需要调用一次模型，请有意识地限定时间窗口范围，而不是对所有历史数据一律重跑。
