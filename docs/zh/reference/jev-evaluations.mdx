本页介绍 [Jev 评估](/zh/evaluations/jev)背后的问题形式与评分规则。有些问题需要模型*阅读*对话内容，但无需对其进行*描述*。"客户是否表达了紧迫感？"只有两个答案。"他们有多沮丧？"有几个有序的答案。你在提问前就知道所有答案。

**分类器评估**正是为此设计的。你编写问题及其可能的答案，一个专为分类构建的小型模型会返回一个校准数值——永远不会是自由文本。

<Note>
与裁判型评估一样，分类器评估每个会话需要消耗一次模型调用。与裁判不同的是，它是一个小型、单一用途的模型，而非通用模型，因此速度更快、成本更低——但它不会解释自身的判断。如果你需要推理过程，请使用[裁判](/zh/evaluations/judge)。
</Note>

## 我应该选哪种？

| 问题 | 使用方式 |
| --- | --- |
| 总共有多少次工具调用？ | 代码 |
| 会话时长是否不超过 30 秒？ | 代码 |
| 客户是否表达了紧迫感？ | **分类器** |
| 应由哪个团队处理：账单、技术还是销售？ | **分类器** |
| 客户有多沮丧？ | **分类器** |
| 答案是否实际正确？ | **裁判** |
| 是否遵循了我们的升级策略？请说明理由。 | **裁判** |

经验法则：**可计数 → 代码，可列举的答案 → 分类器，需要解释 → 裁判。**

你不必提前做出决定。描述你想要衡量的内容，助手会自动选择，告知你选择了哪种方式及原因，你也可以随时切换。

## 两种问题类型

### `noul` — 这是否成立？

两个答案，你对两者都进行描述。结果是"成立"描述符合实际情况的概率：

```json
{
  "instructions": "助手是否在未核查退款政策的情况下承诺退款？",
  "criteria": {
    "true":  "承诺或执行了退款，但未进行政策核查或审批",
    "false": "未承诺退款，或每次退款都经过了政策核查"
  }
}
```

两端都要描述。"未表达紧迫感"是一个真实的答案，明确说明它会让另一个答案更清晰。

### `score` — 程度如何？

有序评分标准，**从最差开始**。结果是会话在其中所处的位置，重新缩放至 0–1：

```json
{
  "instructions": "客户有多沮丧？",
  "criteria": ["平静", "沮丧", "非常愤怒"]
}
```

**评分标准需要三到五个级别，且所有级别必须各不相同。** 两个限制都有实际依据，并非风格偏好：

- **两个级别**退化为 `noul` 已能更好处理的情形；**超过五个级别**会导致模型倾向于中间值而非明确判断。同一问题对同一会话评分，两个级别得 0.00，三个级别得 0.01，十个级别则得 0.55。
- **重复级别**会在它们之间任意分配答案。一个明显愤怒的会话，对 `["平静", "沮丧", "非常愤怒"]` 得分为 1.00，而对 `["愤怒", "愤怒", "愤怒"]` 得分为 0.66——一个格式正确但毫无意义的数字。

没有顺序关系的类别——如"账单、技术还是销售"——不构成评分标准。请对每个类别分别用 `noul` 提问，或使用裁判。

## 读懂结果

分类器输出的**分数**范围为 0 到 1，与裁判完全一样，因此可以用相同方式绘制图表、过滤数据并触发告警。有两点值得注意：

- **没有推理过程。** 该字段有意留空。这个模型不会解释自身判断，凭空生成解释是捏造而非功能。
- **不确定性有标注。** `score` 类问题会报告自身的置信度，模型不确定的结果会被标记为 `low_confidence`——因此"哪些结果需要人工查看"是一个过滤条件，而非猜测。`noul` 类问题不报告置信度，因此不会被标记。

过长的会话会被分段阅读后合并。当一个会话过长无法完整阅读时，结果会说明跳过了多少轮对话——你永远不会看到基于部分会话的判断被当作完整会话判断呈现。

## 限制

- **评分标准三到五个级别，且各不相同。** 见上文；两端限制在编写时均会强制执行。
- **每个评估只有一个问题。** 问两件事就创建两个评估，这也是你在图表上所期望的。
- **编辑问题会发布新版本。** 新旧分数不可比较，因此会分开保存，而非混入同一趋势线。
- **分类器始终输出分数**，永远不会是指标或断言。
- **没有推理过程**，如上所述。如果某个数字会让人追问"为什么？"，请改用裁判。

## 测试与回填

与裁判不同，分类器评估**可以**在部署前进行测试——用与代码评估相同的方式，对真实会话进行[测试](/zh/evaluations/test)，在正式上线前先查看分数。

它还可以对已有会话进行[回填](/zh/evaluations/deploy#score-sessions-you-already-have)。每个会话需要消耗一次模型调用，因此请有意识地限定时间窗口范围，而不是重跑所有历史数据。
