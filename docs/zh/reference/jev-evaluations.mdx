本页介绍 [Jev 评估](/zh/evaluations/jev) 背后的问题形式与评分规则。有些问题需要模型*读取*对话，但不需要*撰写*相关内容。"客户是否表达了紧迫感？"只有两种答案。"他们有多沮丧？"有几个有序的答案。在提问之前，你就已知晓所有答案。

**分类器评估**正是为此而设。你编写问题及其可能的答案，一个专为分类构建的小型模型返回一个校准数值——永远不会是自由文本。

<Note>
与裁判评估一样，分类器评估每个会话都需要消耗一次模型调用。与裁判不同的是，它是一个小型的单一用途模型，而非通用模型，因此速度更快、成本更低——但它永远不会解释自身的判断。如果你需要推理过程，请使用[裁判评估](/zh/evaluations/judge)。
</Note>

## 我该用哪一种？

| 问题 | 使用方式 |
| --- | --- |
| 总共发生了多少次工具调用？ | 代码 |
| 会话时长是否不足 30 秒？ | 代码 |
| 客户是否表达了紧迫感？ | **分类器** |
| 应由哪个团队处理：账单、技术还是销售？ | **分类器** |
| 客户有多沮丧？ | **分类器** |
| 回答是否真正正确？ | **裁判** |
| 是否遵循了我们的升级策略，你为何这么认为？ | **裁判** |

经验法则：**可计数 → 代码，可列举的答案 → 分类器，需要解释 → 裁判。**

你不必提前做决定。描述你想衡量的内容，助手会自动选择，告诉你它的选择及原因，你随时可以切换。

## 两种问题类型

### `noul` — 这是否成立？

两个答案，你对两者都加以描述。结果是"成立"描述符合的概率：

```json
{
  "instructions": "助手是否在未核查退款政策的情况下承诺退款？",
  "criteria": {
    "true":  "在未事先核查或审批政策的情况下承诺或执行了退款",
    "false": "未承诺退款，或每次退款都经过了政策核查"
  }
}
```

两侧都要描述。"未表达紧迫感"是一个真实的答案，明确说明它会让另一侧的描述更加清晰。

### `score` — 程度有多深？

一个有序的评分标准，**从最差开始排列**。结果是会话在其中所处的位置，重新缩放至 0–1：

```json
{
  "instructions": "客户有多沮丧？",
  "criteria": ["平静", "沮丧", "非常愤怒"]
}
```

**评分标准需要三到五个等级，且所有等级必须各不相同。** 两个限制都是有实际依据的，并非风格上的考量：

- **两个等级**会退化为 `noul` 已经能更好处理的情况；**超过五个等级**会让模型趋向中间值而非明确表态。同一个问题对同一会话评分，两个等级得到 0.00，三个等级得到 0.01，十个等级得到 0.55。
- **重复等级**会在它们之间任意分配答案。一个明显愤怒的会话，对 `["平静", "沮丧", "非常愤怒"]` 评分为 1.00，而对 `["愤怒", "愤怒", "愤怒"]` 评分为 0.66——形式上合法，但毫无意义。

没有顺序的类别——如"账单、技术或销售"——不是评分标准。可以对每个类别分别提一个 `noul` 问题，或使用裁判评估。

## 解读结果

分类器生成一个 0 到 1 的**分数**，与裁判评估完全相同，因此它可以以同样的方式生成图表、应用过滤器并触发告警。有两点值得注意：

- **没有推理过程。** 该字段有意留空。这个模型不会解释自身判断，而捏造一个解释只是伪造，而非功能。
- **不确定性有标注。** `score` 问题会报告自身的置信度，模型不确定的结果会被标记为 `low_confidence`——因此"哪些结果需要人工审查"是一个过滤条件，而非猜测。`noul` 问题不报告置信度，因此永远不会被标记。

过长的会话会按摘录方式读取并合并。当会话过长无法完整读取时，结果会说明跳过了多少轮对话——你永远不会看到基于部分会话的判断被当作基于完整会话呈现出来。

## 限制

- **评分标准为三到五个等级，且各不相同。** 见上文；两个边界在创作时都会强制执行。
- **每个评估只有一个问题。** 如果要问两件事，就创建两个评估，这也是你在图表上真正需要的。
- **编辑问题会发布新版本。** 新旧分数不具可比性，因此它们会被分开存储，而非混入同一条趋势线。
- **分类器始终生成分数**，不会生成指标或断言。
- **没有推理过程**，如上所述。如果一个数字会让人追问"为什么？"，请改用裁判评估。

## 测试与回填

与裁判评估不同，分类器评估**可以**在部署前进行测试——用与代码评估相同的方式，针对真实会话进行[测试](/zh/evaluations/test)，在正式上线前查看分数。

它也可以对已有会话进行[回填](/zh/evaluations/deploy#score-sessions-you-already-have)。由于每个会话都需要消耗一次模型调用，请有意识地限定时间窗口，而不是重新处理所有历史数据。
