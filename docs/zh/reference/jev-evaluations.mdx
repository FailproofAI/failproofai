本页介绍 [Jev 评估](/zh/evaluations/jev) 背后的问题形式与评分规则。有些问题需要模型*读取*对话内容，但不需要*撰写*相关说明。"客户是否表达了紧迫感？"只有两个答案。"他们有多沮丧？"有几个有序的答案。在提问之前，你就已经知道所有可能的答案。

**分类器评估**正是为此而生。你编写问题及其可能的答案，一个专为分类而构建的小型模型会返回一个经过校准的数字——永远不会是自由文本。

<Note>
与裁判评估一样，分类器评估每个会话都需要消耗一次模型调用。但与裁判评估不同，它使用的是专用小型模型而非通用模型，因此速度更快、成本更低——但它不会解释自己的判断。如果你需要查看推理过程，请使用[裁判评估](/zh/evaluations/judge)。
</Note>

## 我该选哪种？

| 问题 | 使用方式 |
| --- | --- |
| 总共有多少次工具调用？ | 代码 |
| 会话是否在 30 秒内完成？ | 代码 |
| 客户是否表达了紧迫感？ | **分类器** |
| 应由哪个团队处理：账单、技术还是销售？ | **分类器** |
| 客户有多沮丧？ | **分类器** |
| 回答是否真的正确？ | **裁判** |
| 是否遵循了我们的升级策略，你为何这么认为？ | **裁判** |

经验法则：**可计数 → 代码，可列举答案 → 分类器，需要解释 → 裁判。**

你不必提前做出决定。描述你想要衡量的内容，助手会自动选择，告诉你它的选择及原因，你随时可以切换。

## 两种问题类型

### `noul` — 这是否成立？

两个答案，分别描述两种情况。结果是"成立"描述符合实际情况的概率：

```json
{
  "instructions": "助手是否在未核查退款政策的情况下承诺退款？",
  "criteria": {
    "true":  "未经事先核查或审批，直接承诺或执行了退款",
    "false": "未承诺退款，或每次退款均经过了政策核查"
  }
}
```

两种情况都需要描述。"未表达紧迫感"是一个真实的答案，明确说明它会让另一个答案更加清晰。

### `score` — 程度如何？

一个有序的评分标准，**从最差开始排列**。结果是会话在此标准中的位置，重新缩放至 0–1：

```json
{
  "instructions": "客户有多沮丧？",
  "criteria": ["平静", "沮丧", "非常愤怒"]
}
```

**评分标准需要三到五个级别，且所有级别必须不同。** 这两个限制都经过实测，并非随意规定：

- **两个级别**退化为 `noul` 已经能更好处理的情况，而**超过五个**会导致模型倾向于选择中间值而非做出明确判断。同一问题对同一会话评分，两个级别得 0.00，三个级别得 0.01，十个级别得 0.55。
- **重复级别**会在相同选项之间任意分配答案。一个明显愤怒的会话，对照 `["平静", "沮丧", "非常愤怒"]` 得分为 1.00，对照 `["愤怒", "愤怒", "愤怒"]` 则得分为 0.66——一个格式上正确但毫无意义的数字。

没有顺序关系的类别——如"账单、技术或销售"——不构成评分标准。可以对每个类别单独提出 `noul` 问题，或使用裁判评估。

## 读取结果

分类器产生一个 0 到 1 之间的**评分**，与裁判评估完全相同，因此可以用同样的方式绘制图表、筛选数据和触发警报。有两点值得注意：

- **没有推理说明。** 该字段有意留空。此模型不解释自身判断，而虚构一个解释是造假，而非功能。
- **不确定性会被标记。** `score` 问题会报告自身的置信度，模型不确定的结果会被标记为 `low_confidence`——因此"哪些结果需要人工审查"是一个筛选条件，而非猜测。`noul` 问题不报告置信度，因此永远不会被标记。

过长的会话会被分段读取后合并处理。当会话过长无法完整读取时，结果会说明有多少轮次被跳过——你永远不会看到基于部分会话的判断被当作完整会话的判断呈现。

## 限制

- **评分标准三到五个级别，所有级别必须不同。** 见上文；两个边界在编写时均会强制执行。
- **每个评估只有一个问题。** 如果要问两件事，就创建两个评估，这也正是你在图表上想要的效果。
- **修改问题会发布新版本。** 新旧评分无法比较，因此会分别保存，而不是混入同一趋势线中。
- **分类器始终产生评分**，不会生成指标或断言。
- **没有推理说明**，如上所述。如果一个数字会让人追问"为什么？"，请改用裁判评估。

## 测试与回填

与裁判评估不同，分类器评估**可以**在部署前进行测试——用与代码评估相同的方式对真实会话进行[测试](/zh/evaluations/test)，在正式上线前查看评分结果。

它也可以对已有会话进行[回填](/zh/evaluations/deploy#score-sessions-you-already-have)。由于每个会话需要消耗一次模型调用，请有意识地限定时间窗口，而不是重放所有历史数据。
