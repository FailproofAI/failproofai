本页介绍 [Jev 评估](/zh/evaluations/jev) 背后的问题形式与评分规则。有些问题需要模型*阅读*对话，但不需要对其*撰写*分析。"客户是否表达了紧迫感？"只有两个答案。"他们有多沮丧？"有几个有序的选项。所有答案在提问之前就已确定。

**分类器评估**正是为此而生。你编写问题及其可能的答案，专为分类任务构建的小型模型将返回一个校准后的数字——而非自由文本。

<Note>
与裁判评估一样，分类器评估每个会话都需要消耗一次模型调用。但与裁判不同，它使用的是专用的小型单一功能模型，而非通用模型，因此速度更快、成本更低——但它不会解释自己的判断。如果你需要推理过程，请使用[裁判评估](/zh/evaluations/judge)。
</Note>

## 我应该选哪种？

| 问题 | 使用方式 |
| --- | --- |
| 共有多少次工具调用？ | 代码 |
| 会话时长是否在 30 秒以内？ | 代码 |
| 客户是否表达了紧迫感？ | **分类器** |
| 该由哪个团队处理：账单、技术还是销售？ | **分类器** |
| 客户有多沮丧？ | **分类器** |
| 答案是否真的正确？ | **裁判** |
| 它是否遵循了我们的升级策略，你为何这么认为？ | **裁判** |

经验法则：**可计数 → 代码，答案可列举 → 分类器，需要解释 → 裁判。**

你不必事先做决定。描述你想要衡量的内容，助手会自动选择，告诉你它选择了哪种以及原因，你也可以随时切换。

## 两种问题类型

### `noul` — 这是否为真？

两个答案，你需要描述两者。返回结果是"真"描述符合实际情况的概率：

```json
{
  "instructions": "Did the assistant promise a refund without first checking the refund policy?",
  "criteria": {
    "true":  "A refund was promised or issued with no prior policy check or approval",
    "false": "No refund was promised, or every refund followed a policy check"
  }
}
```

两面都要描述。"未表达紧迫感"也是一个真实的答案，将其明确写出会使另一面的边界更清晰。

### `score` — 程度有多深？

一个有序的评分标准，**从最差开始排列**。返回结果是会话在该标准上的位置，归一化到 0–1 之间：

```json
{
  "instructions": "How frustrated is the customer?",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
```

**评分标准需要三到五个层级，且所有层级必须各不相同。** 两个限制均有实际意义，并非风格偏好：

- **两个层级**会退化成 `noul` 已经能更好处理的情况，而**超过五个层级**会让模型倾向于选择中间值而非做出明确判断。同一会话、同一问题：两个层级得分 0.00，三个层级得分 0.01，十个层级得分 0.55。
- **重复的层级**会在它们之间随机分配答案。一个明显愤怒的会话在 `["Calm", "Frustrated", "Very angry"]` 下得分 1.00，而在 `["Angry", "Angry", "Angry"]` 下得分 0.66——数字格式正确，但毫无意义。

没有顺序关系的分类——如"账单、技术还是销售"——不属于评分标准。可以为每个类别单独设置一个 `noul` 问题，或使用裁判评估。

## 解读结果

分类器生成一个 0 到 1 之间的**分数**，与裁判评估完全一致，因此可以用相同的方式绘图、过滤和触发提醒。有两点区别值得注意：

- **没有推理过程。** 该字段刻意留空。这个模型不解释自己的判断，凭空生成解释是捏造，而非功能。
- **不确定性会被标注。** `score` 类型问题会上报自身的置信度，模型不确定的结果会被标记为 `low_confidence`——因此"哪些需要人工审查"是一个过滤操作，而不是猜测。`noul` 类型问题不上报置信度，因此永远不会被标记。

超长会话将以摘录形式读取并合并。当会话过长无法完整阅读时，结果中会说明遗漏了多少轮对话——你永远不会看到基于部分内容做出的判断被当作基于全部内容呈现。

## 限制条件

- **评分标准需要三到五个层级，且各不相同。** 如上所述，两个边界均在编写时强制执行。
- **每个评估只有一个问题。** 如果你要问两件事，就创建两个评估——这样在图表上也更清晰。
- **编辑问题会发布新版本。** 新旧分数不具可比性，因此它们会被分开保存，而不是混入同一条趋势线。
- **分类器始终生成分数**，而非指标或断言。
- **没有推理过程**，如上所述。如果一个数字会让人追问"为什么？"，那就改用裁判评估。

## 测试与回填

与裁判评估不同，分类器评估**可以**在部署之前进行测试——像测试代码评估一样，针对真实会话进行[测试](/zh/evaluations/test)，在上线前先查看分数。

它也可以对已有的会话进行[回填](/zh/evaluations/deploy#score-sessions-you-already-have)。每个会话都需要消耗一次模型调用，因此请有针对性地设定时间窗口，而不是重放所有历史数据。
