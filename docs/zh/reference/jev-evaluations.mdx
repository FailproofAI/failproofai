本页介绍 [Jev 评估](/zh/evaluations/jev) 背后的问题结构与评分规则。有些问题需要模型*阅读*对话，而不需要对其*撰写*分析。"客户是否表达了紧迫感？"只有两个答案。"他们有多沮丧？"有几个有序的答案。提问之前，你就已经知道所有可能的答案。

**分类器评估**正是为此而生。你编写问题及其可能给出的答案，一个专为分类构建的小型模型会返回一个校准后的数值——而非自由文本。

<Note>
与评判器一样，分类器评估每次会话都需要消耗一次模型调用。但与评判器不同的是，它是一个小型的单用途模型，而非通用模型，因此速度更快、成本更低——但它永远不会解释自己的判断。如果你需要推理过程，请使用[评判器](/zh/evaluations/judge)。
</Note>

## 我应该选哪种？

| 问题 | 使用方式 |
| --- | --- |
| 共发生了多少次工具调用？ | 代码 |
| 会话时长是否低于 30 秒？ | 代码 |
| 客户是否表达了紧迫感？ | **分类器** |
| 该由哪个团队处理：账单、技术还是销售？ | **分类器** |
| 客户有多沮丧？ | **分类器** |
| 答案实际上是否正确？ | **评判器** |
| 它是否遵循了我们的升级策略，你为什么这么认为？ | **评判器** |

经验法则：**可计数 → 代码，答案可列举 → 分类器，需要解释 → 评判器。**

你不必提前决定。描述你想要衡量的内容，助手会帮你选择，告诉你选了哪种以及原因，你也可以随时切换。

## 两种问题类型

### `noul` — 这是真的吗？

两个答案，你对两者都加以描述。结果是"true"描述符合实际情况的概率：

```json
{
  "instructions": "Did the assistant promise a refund without first checking the refund policy?",
  "criteria": {
    "true":  "A refund was promised or issued with no prior policy check or approval",
    "false": "No refund was promised, or every refund followed a policy check"
  }
}
```

两面都要描述。"未表达紧迫感"也是一个真实的答案，明确说明它会让另一面的定义更加清晰。

### `score` — 程度如何？

一个有序的评分标准，**从最差开始**。结果是会话在其中的位置，重新缩放至 0–1：

```json
{
  "instructions": "How frustrated is the customer?",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
```

**评分标准需要三到五个级别，且每个级别必须各不相同。** 两个限制都有可量化的依据，并非风格偏好：

- **两个级别**会退化为 `noul` 已经能更好完成的功能；**超过五个级别**会让模型倾向于向中间靠拢而不敢明确作答。同一会话用两个级别评分为 0.00，三个级别为 0.01，十个级别为 0.55。
- **重复的级别**会在它们之间任意分配答案。一个明显愤怒的会话，对应 `["Calm", "Frustrated", "Very angry"]` 时评分为 1.00，而对应 `["Angry", "Angry", "Angry"]` 时评分为 0.66——这是一个格式上没有问题的数字，但毫无意义。

没有顺序的类别——例如"账单、技术还是销售"——不构成评分标准。请对每个类别使用 `noul` 提问，或改用评判器。

## 理解结果

分类器生成的**分数**范围为 0 到 1，与评判器完全一致，因此可以用同样的方式绘制图表、过滤数据和触发告警。有两点值得注意：

- **没有推理过程。** 该字段是有意为空的。这个模型不会解释自己，凭空捏造一个解释只会是虚构内容，而非实用功能。
- **不确定性会被标注。** `score` 类型的问题会报告自身的置信度，模型不确定的结果会被标记为 `low_confidence`——因此"哪些结果需要人工审查"是一个过滤条件，而不是猜测。`noul` 类型的问题不报告置信度，因此不会有此标记。

较长的会话会以摘录方式阅读后汇总。当会话过长无法完整阅读时，结果会说明有多少轮对话被省略——你永远不会看到一个基于部分会话作出的判断被呈现为基于全部会话的结论。

## 限制

- **评分标准须为三到五个级别，且各不相同。** 详见上文；两个边界均在编写时强制执行。
- **每个评估只允许一个问题。** 询问两件事，你就会得到两个评估——这也正是你在图表上想要的。
- **编辑问题会发布新版本。** 新旧分数不可比较，因此会分开保存，而不是混入同一条趋势线中。
- **分类器始终生成分数**，而非指标或断言。
- **没有推理过程**，如上所述。如果一个数字会让人追问"为什么？"，请改为编写评判器。

## 测试与回填

与评判器不同，分类器评估**可以**在部署前进行测试——[测试方式](/zh/evaluations/test)与代码评估相同：对真实会话运行测试，在正式上线前查看评分结果。

它也可以对你已有的会话进行[回填](/zh/evaluations/deploy#score-sessions-you-already-have)。每次会话都会消耗一次模型调用，因此请有针对性地设定时间窗口，而不是对所有历史记录全部重跑。
