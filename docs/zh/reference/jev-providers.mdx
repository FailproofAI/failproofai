本文是使用自带密钥配置 [Jev 策略](/zh/policies/jev)的提供商与配置参考。正则策略匹配字符串，它无法区分你主动要求的 `rm -rf build/` 和不小心混入计划中的 `rm -rf ~`，因此在某些地方拦截过度，在另一些地方又拦截不足。**Jev** 是 TypeSafe 的分类器，它根据你的实际请求内容来分析工具调用，并在一次快速请求中回答一系列是/否问题。

配置好自己的 Jev 端点和密钥后，Failproof AI 会在每次工具调用时**同时**向 Jev 和正则策略发起请求，而非以 Jev 取代正则策略：

- **硬性**策略的拒绝是最终决定，Jev 无法解除。除非策略被明确标记为可审查（reviewable）并指定了覆盖该策略的 Jev 检查项，否则所有策略默认为硬性——即自定义策略、Pack 策略或 Cloud 策略若未作任何说明，均为硬性策略；常驻的自我保护防护措施也始终为硬性。
- **可审查**策略的拒绝可以被解除，但前提是：Jev 被明确询问了该策略所关注的具体问题，且回答为"此处无问题"或"用户明确请求了此操作"。若某项检查确认存在问题，且用户并未请求该调用，则拒绝保持有效——即便该检查本身的结论仅为警告，因为在工具调用前，警告不会阻止代理执行。而当该检查属于可发出拒绝的类型（如密钥暴露、凭据泄露、破坏性删除等）时，该调用的任何拦截均不会被解除。
- 当调用是你所布置任务的一个步骤且影响范围未超出任务本身时，拦截仍可降级为**警告**：Jev 会将自身的拒绝软化为警告，该警告——指出调用的具体问题所在——将取代策略的拦截。
- Jev 也可以自主发出警告或拒绝，以应对正则无法描述的危害。
- 若 Jev 无法给出答案（超时、速率限制、服务器错误、积分不足、模型版本异常），该调用将沿用正则策略的结果，与未配置 Jev 时完全一致。
- 除非 Jev 读取了完整的调用内容并被询问了具体的关注点，否则 Jev 不会使调用获得比单独依靠策略更宽松的许可。若条件不满足——调用内容过大无法完整发送、疑似存在注入攻击——则解除授权将被撤回，所有拒绝维持有效。

<Note>
未配置 Jev 时，一切不变：Hook 将完全按照既往方式运行正则策略。配置文件本身就是完整的启用入口。
</Note>

<Tip>
使用 FailproofAI Cloud？你无需自备密钥：持有 `jev:evaluate` 权限密钥的机器可以在组织套餐下使用 Jev。详见 [通过 FailproofAI Cloud 使用 Jev](/zh/reference/jev-cloud)。
</Tip>

## 开始之前

在运行代理的机器上安装 **failproofai 1.0.8-beta.0 或更高版本**，并将其 Hook 附加到[支持的运行环境](/zh/reference/harnesses)。如果是新机器，请参照[快速入门](/zh/start/quickstart)；如果不使用 Cloud，请参照[配置本地执行](/zh/start/setup#enforce-locally)。使用 `failproofai --version` 检查已安装的 CLI 版本。

从下方提供商处获取 API 密钥，或准备好兼容端点及其密钥。Jev 在 `PreToolUse` 或 `PermissionRequest` 检查点审查具名工具调用。它可以自主发出裁决，但解除现有策略拒绝还需要安装标记为[可审查](/zh/policies/authority)的策略。硬性策略的拒绝始终为最终决定。

## 选择提供商

Jev 可通过五种途径访问，为其中任意一种提供密钥即可。

| 提供商 | `--provider` | 端点 | 默认模型 | 备注 |
| --- | --- | --- | --- | --- |
| TypeSafe | `typesafe` | `api.typesafe.ai/v1/systemone` | `jev-1.13.0` | 精确版本固定。 |
| OpenRouter | `openrouter` | `openrouter.ai/api/v1/systemone` | `typesafe/jev-1.13` | 请求仅路由至零数据保留端点，不回退至其他提供商。返回日期化版本号，如 `typesafe/jev-1.13-20260917`。 |
| Vercel AI Gateway | `vercel` | `ai-gateway.vercel.sh/typesafe/v1/systemone` | `typesafe-ai/jev` | 仅通过别名标识 Jev，因此响应版本记录为未验证。 |
| Cloudflare Workers AI | `cloudflare` | `api.cloudflare.com/client/v4/accounts/<id>/ai/run` | `typesafe/jev` | 需要 `--account-id`。实测每个密钥约每秒六次调用后触发 HTTP 429。 |
| 自定义端点 | `custom` | `<base-url>/systemone` | `jev-1.13.0` | 任何接受 TypeSafe 请求体并返回响应模型信息的端点。仅支持 `https`；本地测试时允许使用 plain `http` 连接回环地址（`localhost`、`127.0.0.1`、`::1`）。 |

<Warning>
使用 Vercel 自带密钥功能时，失败的请求会静默地使用 Vercel 自身的凭据重试。如果你需要所有调用均计费至且仅对你自己的 TypeSafe 账户可见，请直接使用 TypeSafe。
</Warning>

## 配置步骤

一条命令，指定端点和密钥。先以 `observe` 模式启动，以便在现有策略继续决策调用的同时查看 Jev 的裁决：

```bash
failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
```

### URL 决定提供商

你无需显式指定提供商：URL 的**主机名**即代表所使用的提供商。

| URL 主机名 | 提供商 | 额外参数 |
| --- | --- | --- |
| `api.typesafe.ai` | `typesafe` | — |
| `openrouter.ai` | `openrouter` | — |
| `ai-gateway.vercel.sh` | `vercel` | — |
| `api.cloudflare.com` | `cloudflare` | `--account-id <32-hex-account-id>` |
| 其他主机名 | `custom` | — 你提供的 URL 即为 base URL |

由此产生三条规则：

- **若 URL 是提供商的官方 API 地址，则不写入任何覆盖配置。** `--url https://api.typesafe.ai/v1` 与 `--provider typesafe` 产生完全相同的配置。若在已知提供商上指定了不同路径或主机名，则将其作为 base URL 存储，效果等同于 `--base-url`。
- **`--provider` 仍可覆盖自动推断**，这正是通过自定义主机名代理某提供商 API 的方式：`--url https://jev-proxy.internal/v1 --provider typesafe`。
- **`--provider` 与主机名矛盾时将被拒绝**，不会进行猜测。`--provider openrouter --url https://api.typesafe.ai/v1` 不会写入任何配置，并说明原因：两者对密钥发送目标的指定相互矛盾。同样，`jev setup --base-url` 和控制台的 Jev 设置页面也会拒绝此类冲突配置。（`--provider custom` 不构成矛盾——它表示"将此 URL 视为自身"——但 Cloudflare 主机除外，因为自定义路由无法访问其按账户划分的端点。）

`--url` 的验证规则与配置文件中 `baseUrl` 的验证规则完全一致，拒绝时措辞也相同：必须使用 `https`，或在任意模式下使用 plain `http` 连接回环地址（`localhost`、`127.0.0.1`、`::1`）。风险提示：回环服务器无需身份验证，因此在其停机时，同一台机器上的其他本地进程可能占用其端口并响应请求；本地测试以外的场景请使用 `https`。

### 密钥

通过 `--key-stdin` 管道传入，或在终端中不带该参数运行命令，在遮蔽提示符处粘贴密钥。两种方式均会将密钥直接写入配置文件，不会回显。

<Tabs>
  <Tab title="TypeSafe">
    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    ```
  </Tab>
  <Tab title="OpenRouter">
    ```bash
    failproofai jev --url https://openrouter.ai/api/v1 --mode observe --key-stdin < ~/openrouter.key
    ```
  </Tab>
  <Tab title="Vercel">
    ```bash
    failproofai jev --url https://ai-gateway.vercel.sh/typesafe/v1 --mode observe \
      --key-stdin < ~/vercel-gateway.key
    ```
  </Tab>
  <Tab title="Cloudflare">
    ```bash
    failproofai jev --url https://api.cloudflare.com/client/v4 \
      --account-id <32-hex-account-id> --mode observe --key-stdin < ~/cloudflare.token
    ```
  </Tab>
  <Tab title="Custom">
    ```bash
    failproofai jev --url https://jev.internal.example.com/v1 --mode observe --key-stdin < ~/jev.key
    ```
  </Tab>
</Tabs>

`failproofai jev setup` 接受相同的参数，是完整的长格式命令：若你更倾向于指定提供商而非 URL，可使用 `setup --provider <kind>`。

### `--token` 及其代价

`--token <token>` 将密钥直接写在命令行中，这是配置机器最快的方式，也是唯一会在配置文件以外留下密钥的方式：

```bash
failproofai jev --url https://openrouter.ai/api/v1 --token <token>
```

<Warning>
命令行参数执行后会留在 Shell 历史文件中，且命令运行期间会出现在进程列表中——任何以当前用户身份运行的程序均可通过 `/proc` 读取。每次使用 `--token` 时，`setup` 都会给出提示。在共享机器、录制会话或历史文件会同步的场景下，请优先使用 `--key-stdin`；若曾通过此方式传递密钥，视情况及时轮换。
</Warning>

`--token`、`--key-stdin` 和 `--key-from-env` 三者互斥，只能选择其一。

配置完成后，发送一次小的实时请求，检验密钥、端点以及响应的 Jev 版本：

```bash
failproofai jev test
```

```text
  failproofai jev test                                            ok · 523 ms

  provider      cloudflare
  model asked   typesafe/jev
  answered by   jev-1.13.0 (Jev 1.13 family — verified)
  latency       523 ms — within the 3000 ms timeout
```

当响应在超时后才到达（所有 Hook 都会回退至正则，原因记为 `timeout`）或检查问题的答案有误时，`jev test` 退出码为 1，并在标题中注明。

Hook 在每次工具调用时读取配置，因此下一次调用起即生效，无论是否使用守护进程，均无需重启。

## 查看运行状态

```bash
failproofai jev status
failproofai jev status --json
```

`status` 显示提供商、端点、模型、模式、配置文件及其权限，**不显示**密钥。下方还会汇总近期活动：Jev 评估了多少次调用、因何原因回退至正则的次数、延迟情况，以及解除了哪些可审查策略的拦截。

## 验证真实调用

在已附加 Hook 的代理中启动新会话。要求代理使用文件读取工具读取 `README.md` 并报告标题。确认会话中包含该工具调用后，再次运行 `failproofai jev status`：近期已评估调用数应有所增加。在[本地控制台](/zh/reference/local-dashboard#review-policy-activity)的 **Policies → Activity** 中查看该调用的 Jev 裁决和模式。在 observe 模式下，策略结果仍决定调用的最终处理；只有当可审查策略匹配且 Jev 通过了所有指定检查时，才会出现解除记录——普通的文件读取操作可能没有对应策略需要解除。

## Observe 模式

默认模式为 `enforce`。若要在不影响任何决策的情况下观察 Jev，请切换至 `observe` 模式：Jev 仍会被调用，裁决也会被记录，但最终执行的是正则策略的结果。

```bash
failproofai jev setup --mode observe
failproofai jev setup --mode enforce
failproofai jev setup --mode off
```

`off` 模式保留配置（端点和密钥），但停止向 Jev 发起请求：Hook 的运行方式与未配置时完全相同，`failproofai jev status` 显示"off (switched off)"。使用 `--mode observe` 或 `--mode enforce` 可重新启用。

对同一提供商重新运行 `setup` 会保留已存储的密钥，因此切换模式只需一个参数。切换提供商则需重新开始，并输入新提供商的密钥。将请求迁移至不同主机的 `--base-url` 也同样如此：已存储的密钥仅发送至最初配置时对应的主机或该提供商的官方 API。

## 配置文件

所有配置均存储在一个文件中：由 `setup` 写入的 `~/.failproofai/jev.json`：

```json
{
  "provider": "cloudflare",
  "apiKey": "<your key>",
  "accountId": "<32-hex-account-id>",
  "mode": "enforce",
  "timeoutMs": 3000
}
```

| 字段 | 说明 |
| --- | --- |
| `provider` | `typesafe`、`openrouter`、`vercel`、`cloudflare` 或 `custom`——也可以是 `failproofai`，其密钥来自 FailproofAI Cloud 连接而非本文件（详见[通过 FailproofAI Cloud 使用 Jev](/zh/reference/jev-cloud)）。 |
| `apiKey` | 以 `Authorization: Bearer <key>` 方式发送。 |
| `baseUrl` | `custom` 类型必填；用于覆盖其他提供商的 API base。必须使用 `https`。仅在 `mode: observe` 下接受 plain `http` 到 `localhost`：由于本地端口无需身份验证，当你的代理停机时，机器上的任何进程（包括被审查的代理本身）都可能占用其端口并响应。 |
| `accountId` | 仅限 Cloudflare：32 个小写十六进制字符。 |
| `model` | 覆盖提供商的默认模型 ID。带版本号的 ID 必须指向 Jev 1.13。形如 API 密钥的值将被拒绝（且不会回显），因此误将密钥粘贴到 `--model` 中不会被存储或作为模型名称发送。 |
| `timeoutMs` | 工具调用等待 Jev 响应的超时时间，超时后使用正则结果。范围 100–10000，默认 3000。 |
| `mode` | `enforce`（默认）、`observe` 或 `off`（保留配置，不运行 Jev）。 |

三条规则保护该文件：

- **仅限所有者访问。** 文件权限设置为 `0600`。若其他用户或组可读可写，则**拒绝**使用该配置，Hook 回退至正则，直到你运行 `chmod 600 ~/.failproofai/jev.json` 或重新运行 `setup`。目录也会被检查：`~/.failproofai` 不得被其他任何人**写入**，因为有写权限的人可以替换文件，无论文件本身的权限如何。`setup` 发现写权限时会自动移除。`failproofai jev status` 会提示配置被拒绝，并显示文件中记录的端点：由于他人可能已修改过该文件，请在执行 `chmod` 前确认文件内容属于你自己。对权限异常的文件重新运行 `setup` 时，已存储的密钥仅发送至提供商的官方 API；文件中指向其他端点的配置需要重新提供密钥（`--key-stdin`），或使用 `--base-url default` 将请求重定向回提供商。
- **仅限全局配置。** 仓库无法开启 Jev、指向其他端点或选择模型：项目内的 `.failproofai/jev.json` 会被忽略，提供商、URL、模型和账户 ID 仅从上述文件中读取——而非从环境变量中读取（仓库的代理设置可以设置环境变量）。（`FAILPROOFAI_HOME` 也不是绕过该限制的方法：它会移动整个 failproofai 目录（包括策略），而非单独重定向 Jev。）
- **密钥可从环境变量获取。** 若文件中没有 `apiKey`，`FAILPROOFAI_JEV_API_KEY` 将在当前会话中提供密钥（`setup --key-from-env` 会写入此类文件）。它不会替换文件中已有的密钥，也无法在没有配置文件的情况下单独启用 Jev。若该变量未设置，Jev 在当前 Shell 中简单地处于关闭状态：`failproofai jev status` 会给出提示，以退出码 0 退出，不修改配置（`status --json` 返回 `"status": "key-missing"` 及 `"reason": "no-env-key"`）。`failproofaid` 守护进程无法读取 Shell 环境变量，因此在通过 `failproofai config` 配置的机器上，请将密钥保存在文件中。

## 响应的 Jev 版本

Failproof AI 的决策阈值基于 Jev 1.13 进行校准，因此只有来自该系列的答案才会被采纳：`jev-1.13.x`，或 OpenRouter 的 `typesafe/jev-1.13-<date>`。若提供商仅通过别名标识 Jev 且不返回版本号（Vercel 以及未声明版本的 Cloudflare），则该答案会被采纳并记录为未验证。`custom` 端点必须返回响应模型信息；唯一的例外是你为其配置的不带版本号的 `--model` 名称，在回显时同样记录为未验证。若答案中报告了其他版本，或 `custom` 答案中未声明模型，则不予采纳：该调用回退至正则，原因记为 `model-mismatch`。

## Jev 无法给出答案时

以下每种情况均会回退至该调用的正则结果，并记录相应原因，`failproofai jev status` 会汇总统计：

| 原因 | 触发条件 |
| --- | --- |
| `timeout` | 在 `timeoutMs` 内未收到响应。 |
| `http-429` | 提供商对该密钥进行了速率限制。 |
| `rate-limited` | Failproof AI 自身的限速器在发送前拦截了该调用：每秒 5 次请求，支持最多 5 次突发，提供商返回 `429` 后会短暂暂停。非提供商原因。 |
| `http-500`、`http-502`、`http-503` 等 | 提供商侧服务器错误，记录具体状态码。 |
| `out-of-credits` | HTTP 402：提供商账户积分耗尽。 |
| `provider-refused` | Cloudflare 返回 HTTP 402，消息为"Model execution failed (Payment error)"：提供商拒绝在此请求上运行模型。通常非计费问题，充值无法解决。 |
| `http-401`、`http-403` | 密钥被拒绝。 |
| `http-404` | `<base>/systemone` 路径无响应，说明 base URL 有误——系统会将 `/systemone` 拼接至 base URL，所有提供商均在各自的版本根路径下提供该接口。`failproofai jev models` 可查看端点实际提供的接口。 |
| `network` | 无法访问端点。 |
| `http-301`、`http-302`、`http-307`、`http-308` | 端点返回了重定向。重定向不会被跟随，因此答案只会来自配置中的 URL；请将 `--base-url` 设置为最终 URL。 |
| `malformed` | 端点有响应，但内容不是 Jev 答案——响应体不是 JSON，或其中没有任何答案字段。 |
| `cloudflare-error`、`cloudflare-incomplete` | Cloudflare 信封报告了失败，或任务尚未完成。 |
| `model-mismatch` | 响应的 Jev 版本不是 1.13，或 `custom` 端点未声明响应的模型。 |
| `request-cut` | **非服务中断。** Jev 已响应，但只看到了部分调用内容，因此其答案未解除任何拦截。详见[Jev 已响应但未读取完整调用](#when-jev-answered-but-not-on-the-whole-call)。 |

`failproofai jev status` 还可能显示其他少见原因，如 `upstream-error`（答案中携带了提供商自身的错误）或 `config`，无法命名的原因统计为 `other`。

`request-cut` 列于此表，因为 `failproofai jev status` 会将其与其他原因一并汇总，且它同样会使所有拒绝保持有效。但它是这里唯一与提供商状况无关的原因：请求已到达，Jev 也已响应。与上方所有情况不同，该答案仍然有效——Jev 自身的拒绝或警告会在正则结果之上叠加，而非被丢弃。因此若连续出现此原因，说明调用内容过大、无法完整发送至评估器，而非端点异常，充值积分或更换 URL 均无济于事。

## Jev 已响应但未读取完整调用

还有两种情况需要说明，它们都不是 Jev 未能响应。两者均涉及调用内容或对话内容能否完整放入单次请求。

**部分调用内容未能放入请求。** 工具调用在固定的预算内发送，对于超大的调用——非常大的 `Write`、巨大的 MCP 请求体、填充到上限的命令——系统会发送能放入的部分。Jev 仍会响应，其答案仍然有效：自身的拒绝或警告正常生效。但它**无法解除**任何拦截，因为基于部分调用内容的裁决不能算作对整个调用的裁决。因此所有策略拒绝维持有效，该调用以 `request-cut` 原因记录为回退，`failproofai jev status` 与上述原因一并汇总。由此得出的规则：增大调用内容会使其失去解除资格，却永远无法换来解除授权。

**某条消息未能放入请求。** 你粘贴的长提示词、代理的最后一条消息，或已被该评估器的存储模块截断的提示词。**一切不变**：调用的裁决、解除和记录与其他调用完全一致，不计入回退。你输入内容的长度永远不会决定裁决结果，截断也不会制造知情同意：若提示词在到达时已被截断，"用户未请求此操作"不再能从中推断，而不是变成另一种结论。

两者的分界在于文本的作者。调用内容属于代理，若允许其长度降低严重性，则等于给代理提供了可操控的规则；提示词属于用户，将其长度视为信号只会惩罚粘贴规格文档或调用栈的用户。

## 哪些内容会离开本机

对于 Jev 评估的每次工具调用，会向你的提供商发送一次请求，携带以下内容：

- 工具调用本身，其中 API 密钥、Bearer Token 和 `KEY=` 赋值等密钥信息已被脱敏处理；
- 你最近输入的提示词，已移除代理运行环境添加的文本；
- 你最新提示词前代理的最后一条消息，标注为代理所写；
- 本地计算的事实信息，如路径是否在项目目录内——即会话首次被审查调用时所在的项目，[在会话期间固定](/zh/reference/jev-intent#the-project-root)——以及当前 Git 分支。

请求仅发送至你配置文件中指定的端点，使用你自己的密钥。

## 关闭 Jev

```bash
failproofai jev remove
```

此命令删除 `~/.failproofai/jev.json`。从下一次工具调用起，Hook 将完全按照之前的方式运行正则策略。`~/.failproofai/state/semantic/` 下的会话级存储（`sessions/` 中的已记录提示词、`roots/` 中的项目根目录）会保留原地并自然过期。若只想停止向 Jev 发起请求但保留配置，请改用 `failproofai jev setup --mode off`。

## 命令参考

| 命令 | 功能 |
| --- | --- |
| `failproofai jev --url <url> --key-stdin` | 一条命令完成配置；提供商由 URL 主机名推断 |
| `failproofai jev --url <url> --token <token>` | 同上，密钥写在命令行——Shell 历史和进程列表可见 |
| `failproofai jev setup --provider <kind> --key-stdin` | 通过 stdin 管道传入密钥并写入配置 |
| `failproofai jev setup --provider <kind>` | 同上，在遮蔽提示符处输入密钥 |
| `failproofai jev setup --key-from-env` | 不存储密钥；每次会话从 `FAILPROOFAI_JEV_API_KEY` 读取 |
| `failproofai jev setup --mode observe` | 切换模式（`enforce`、`observe` 或 `off`），保留已存储的密钥 |
| `failproofai jev setup --model <id>` / `--base-url <url>` | 覆盖模型或 API base；`default` 清除覆盖 |
| `failproofai jev setup --timeout-ms <n>` | 修改每次调用的超时预算 |
| `failproofai jev status [--json]` | 显示配置、权限和近期活动；不显示密钥 |
| `failproofai jev test [--json]` | 发送一次实时请求，显示延迟和响应版本 |
| `failproofai jev models [--provider <kind>] [--url <base>] [--json]` | 该端点 `/models` 返回的模型 ID 列表，标注当前配置的模型 |
| `failproofai jev remove` | 删除配置；Jev 关闭 |
