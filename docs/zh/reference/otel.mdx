`failproofai otel` 用于配置可选的 OpenTelemetry 上报功能，将数据发送至 FailproofAI Cloud。请先通过 `failproofai config` 连接您的机器，并请组织管理员启用 **Settings → OpenTelemetry**。

交互式设置会在 Cloud 密钥字段和智能体选择器之后询问 OpenTelemetry 相关选项。该可选步骤默认为"否"。选择"是"可选择 OTEL 智能体；连接写入后将运行相同的启用代码。在设置完成前按 Esc 不会应用任何更改。无人值守设置、手动提供密钥、开源模式以及保留已保存的连接均不会自动启用该功能。

## 启用智能体

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

支持的智能体包括 `claude`、`codex` 和 `copilot`（VS Code）。配置 Copilot 需要 VS Code 可执行文件或已安装的 Copilot 扩展。仅有残留的设置目录是不够的；若两者均未找到，设置程序将跳过 Copilot。

`--local` 将数据发送至本地中继，而非直接发送到 Cloud。Copilot 会自动使用中继，因为其设置无法存储认证请求头。

中继仅在您的本机上监听。您配置的 FailproofAI 守护进程将在数秒内感知变更，无需重启。若其他应用程序占用了中继端口，状态页面会将其显示为关闭，守护进程将继续运行。

<Warning>
默认情况下，文本捕获处于开启状态。添加 `--no-content` 可省略提示词和工具详情。不同智能体版本可能提供不同的内容控制选项；在将其用于敏感数据之前，请先了解您的智能体会导出哪些内容。
</Warning>

Codex 仅导出对话日志，不导出内部运行时跟踪或指标数据。若您的 Codex 配置中明确设置了 `log_user_prompt = false`，该设置将保持关闭；启用时若保留了此选项，程序会打印一条提示信息。

### 选择一种上报路径

若某智能体已开启会话记录上报，设置程序会询问：

> failproofai 已将 Claude Code 会话发送至 Cloud。是否改为通过 OTEL 发送？Claude Code 的会话记录上传将停止。

默认选项为"否"。`--yes` 可在不出现提示的情况下接受切换。其他智能体和策略执行不受影响。

Codex 设置会等待守护进程确认采集器变更后，再写入其导出器配置。若确认超时，设置程序会提示您在启动 Codex 之前等待确认完成。

Config v2 将已记住的追踪列表保存在 `agents.selected`（检测历史保存在 `agents.seen`）。各智能体的会话记录上报偏好保留在 `collector.agents.<agent>.sessions`，OTEL 归属保留在 `otel.agents`，中继设置保留在 `collector.otlp.enabled` / `collector.otlp.port`。这些独立的键使旧版 OTEL 配置保持可读性：设置程序可在不丢失传输偏好或智能体设置还原所需状态的情况下更改追踪列表。

## 检查设置状态

```bash
failproofai otel status
```

状态页面会显示每个智能体的信息，包括其设置是否由 FailproofAI 管理、目标目的地、组织的数据接入开关、中继状态以及最近一次中继上传结果。

组织开关显示 `unknown` 表示服务器未提供该信息或无法访问。这不是错误，也不会阻止在旧版 Cloud 上进行配置。

若 Cloud 尚不支持 OTEL，中继会保留被拒绝的导出数据，而不是将其丢弃。若组织的数据接入处于关闭状态，`enable` 命令将不写入任何内容并以错误退出；请先请管理员开启该功能。

## 为应用程序打印配置

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

输出内容为适用于 OTLP/HTTP 导出器的 Shell 环境变量块。Cloud 输出将 `OTEL_EXPORTER_OTLP_ENDPOINT` 设置为 Cloud 的 OTLP 基础地址 `https://<cloud>/otel`，导出器会追加 `/v1/<signal>`；若使用 `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` 等按信号类型设置的变量，则需要完整的 URL，例如 `https://<cloud>/otel/v1/logs`。本地输出指向中继地址 `http://127.0.0.1:<port>`。Cloud 输出包含已配置的 API 密钥，请将其视为机密信息。本地输出不包含密钥。若要使用本地输出，请先启用一个本地智能体以确保中继正在运行。

## 还原之前的设置

```bash
failproofai otel disable claude
failproofai otel disable all
```

禁用操作仅还原 FailproofAI 写入的设置，保留无关的更改，并恢复每个智能体之前的会话记录上报选项。当最后一个受管理的本地智能体被禁用时，中继将停止接受导出数据。

对于 Codex，禁用操作还会记录 `collector.agents.codex.sessions_resume_after`（纪元毫秒值）。现有的已推送字节数据将被视为已传输，因此通过 OTEL 捕获的会话不会被再次上传；后续追加的内容仍会通过会话记录上报流传输。

所有命令均支持 `--help`。有关应用程序和编程智能体的示例，请参阅 [OpenTelemetry in Cloud](/zh/agenteye/opentelemetry)。
