`failproofai otel` 用于配置向 FailproofAI Cloud 发送可选的 OpenTelemetry 数据。首先使用 `failproofai config` 连接您的机器，并请组织管理员启用 **Settings → OpenTelemetry**。

交互式设置会在 Cloud 密钥字段和代理选择器之后询问 OpenTelemetry 相关选项。该可选步骤默认为"否"。选择"是"以选取 OTEL 代理；写入连接后会运行相同的启用代码。在设置完成前按 Esc 不会应用任何更改。无人值守设置、已提供密钥、开源模式以及保留已保存连接均不会自动为您启用 OTEL。

## 启用代理

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

支持的代理包括 `claude`、`codex` 和 `copilot`（VS Code）。Copilot 设置需要 VS Code 可执行文件或已安装的 Copilot 扩展。仅有残留的 settings 目录是不够的；若两者均未找到，设置将跳过 Copilot。

`--local` 将数据发送至本地中继，而非直接发送至 Cloud。Copilot 会自动使用中继，因为其设置无法存储身份验证标头。

中继仅在您的机器上监听。您配置的 FailproofAI 守护进程将在数秒内接收到更改，无需重启。若另一个应用程序占用了中继端口，状态将显示为关闭，守护进程将继续运行。

<Warning>
默认情况下，文本捕获处于启用状态。添加 `--no-content` 可省略提示词和工具详情。不同代理版本可能提供不同的内容控制选项；在将其用于敏感数据之前，请先了解您的代理会导出哪些内容。
</Warning>

Codex 仅导出对话日志，不导出内部运行时跟踪或指标。若您的 Codex 配置中明确设置了 `log_user_prompt = false`，该设置将保持关闭；启用时若保留了该选项，程序会打印一条提示信息。

### 选择一条报告路径

若某代理的转录报告已启用，设置将询问：

> failproofai 已在向 Cloud 发送 Claude Code 会话。是否改用 OTEL 发送？Claude Code 的转录上传将停止。

默认为"否"。`--yes` 可在无需提示的情况下接受切换。其他代理和策略执行不受影响。

Codex 设置会等待守护进程确认 collector 更改后，再写入其导出器设置。若确认超时，设置将提示您在启动 Codex 之前等待。

Config v2 将已记录的跟踪列表保存在 `agents.selected`（检测历史保存在 `agents.seen`）。每个代理的转录偏好保存在 `collector.agents.<agent>.sessions`，OTEL 所有权保存在 `otel.agents`，中继设置保存在 `collector.otlp.enabled` / `collector.otlp.port`。这些独立的键使旧版 OTEL 配置保持可读性：设置可以在不丢失传输偏好或恢复代理设置所需状态的情况下更改跟踪列表。

## 检查设置

```bash
failproofai otel status
```

状态信息显示每个代理的情况，包括其设置是否由 FailproofAI 管理、目标地址、组织的数据接收开关、中继状态以及最近一次中继上传结果。

组织开关显示 `unknown` 表示服务器未提供该信息或无法访问。这不是错误，也不会阻止在旧版 Cloud 上进行配置。

若 Cloud 尚不支持 OTEL，中继会保留被拒绝的导出数据，而不是将其丢弃。若组织数据接收已关闭，`enable` 将不写入任何内容并以错误退出；请先请管理员开启该功能。

## 为应用程序打印配置

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

输出为 OTLP/HTTP 导出器的 Shell 环境变量块。Cloud 输出将 `OTEL_EXPORTER_OTLP_ENDPOINT` 设置为 Cloud 的 OTLP 基础地址 `https://<cloud>/otel`，导出器会附加 `/v1/<signal>`；若使用 `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` 等按信号类型设置的变量，则需要完整的 `https://<cloud>/otel/v1/logs`。本地输出指向中继地址 `http://127.0.0.1:<port>`。Cloud 输出包含已配置的 API 密钥，请将其视为机密信息。本地输出不包含密钥。若要使用本地输出，请先启用一个本地代理以确保中继正在运行。

## 恢复之前的设置

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable 仅恢复 FailproofAI 写入的设置，保留无关更改，并恢复每个代理之前的转录报告选项。当最后一个受管理的本地代理被禁用时，中继将停止接受导出数据。

对于 Codex，disable 还会记录 `collector.agents.codex.sessions_resume_after`（毫秒级 epoch 时间戳）。现有的已传输字节将被视为已送达，因此通过 OTEL 捕获的会话不会再次上传；后续追加的内容仍会通过转录报告传输。

每个命令均支持 `--help`。有关应用程序和编码代理示例，请参阅 [OpenTelemetry in Cloud](/zh/agenteye/opentelemetry)。
