`failproofai otel` 用于配置向 FailproofAI Cloud 发送可选的 OpenTelemetry 数据。请先通过 `failproofai config` 将本机连接到 Cloud。Cloud 端的 OpenTelemetry 数据接收始终处于开启状态，无需在组织层面进行任何切换。

交互式设置会在填写 Cloud 密钥和选择代理之后询问是否启用 OpenTelemetry，该步骤默认选择"否"。选择"是"后，可以选择 OTEL 代理；连接写入完成后，将执行相同的启用逻辑。在设置完成前按 Esc 不会应用任何更改。在无人值守模式、已提供密钥、开源模式，以及保留已保存连接的情况下，均不会自动为您启用 OTEL。

## 启用代理

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

支持的代理包括 `claude`、`codex` 和 `copilot`（VS Code）。设置 Copilot 需要可用的 VS Code 可执行文件或已安装的 Copilot 扩展；仅存在遗留的设置目录是不够的，若两者均未找到，设置将跳过 Copilot。

`--local` 表示将数据发送至本地中继，而非直接发送到 Cloud。Copilot 会自动使用中继，因为其配置中无法存储认证标头。

中继仅监听本机。您配置的 FailproofAI 守护进程将在数秒内感知到变更，无需重启。若其他应用程序占用了中继端口，状态页面将显示其为关闭，守护进程仍会继续运行。

<Warning>
文本捕获默认开启。如需排除提示词和工具详情，请添加 `--no-content`。不同版本的代理可能暴露不同的内容控制项；在将其用于敏感数据之前，请先确认您的代理会导出哪些内容。
</Warning>

Codex 仅导出对话日志，不导出内部运行时追踪或指标。若您的 Codex 配置中明确设置了 `log_user_prompt = false`，该设置将保持关闭；启用时，若保留了该选项，程序会打印相应提示。

### 选择单一上报路径

若某代理已开启对话记录上报，设置时将询问：

> failproofai 已在向 Cloud 发送 Claude Code 会话。是否改用 OTEL 发送？Claude Code 的对话记录上传将停止。

默认选择"否"。使用 `--yes` 可跳过提示直接确认切换。其他代理及策略执行不受影响。

Codex 的设置流程会等待守护进程确认收集器变更后，再写入其导出器配置。若确认超时，设置将提示您在启动 Codex 前先等待。

Config v2 将记住的追踪列表保存在 `agents.selected`（检测历史保存在 `agents.seen`）。每个代理的对话记录偏好保留在 `collector.agents.<agent>.sessions`，OTEL 所有权保留在 `otel.agents`，中继设置保留在 `collector.otlp.enabled` / `collector.otlp.port`。这些独立的键使旧版 OTEL 配置保持可读性：设置可以在不丢失传输偏好或恢复代理配置所需状态的情况下更改追踪列表。

## 检查设置状态

```bash
failproofai otel status
```

状态页面显示每个代理的信息，包括：其配置是否由 FailproofAI 管理、目标地址、组织的数据接收开关、中继状态，以及最近一次中继上传的结果。

组织开关显示为 `unknown` 表示服务器未提供该信息或无法访问，这不是错误，也不会影响在旧版 Cloud 上的配置操作。

若 Cloud 尚不支持 OTEL，中继将保留被拒绝的导出数据，而非直接丢弃。若旧版 Cloud 将组织数据接收报告为关闭，`enable` 将不写入任何内容并以错误退出。

## 为应用程序打印配置

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

输出为适用于 OTLP/HTTP 导出器的 Shell 环境变量块。Cloud 输出将 `OTEL_EXPORTER_OTLP_ENDPOINT` 设置为 Cloud 的 OTLP 基础地址 `https://<cloud>/otel`，导出器会自动拼接 `/v1/<signal>`；若使用 `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` 等按信号类型的变量，则需要完整路径，如 `https://<cloud>/otel/v1/logs`。本地输出指向中继地址 `http://127.0.0.1:<port>`。Cloud 输出包含已配置的 API 密钥，请将其视为机密信息。本地输出不包含密钥。如需使用本地输出，请先启用一个本地代理以确保中继正在运行。

## 恢复之前的设置

```bash
failproofai otel disable claude
failproofai otel disable all
```

禁用操作仅恢复由 FailproofAI 写入的设置，保留无关的更改，并恢复每个代理之前的对话记录上报选项。当最后一个受管理的本地代理被禁用后，中继将停止接受新的导出数据。

对于 Codex，禁用操作还会记录 `collector.agents.codex.sessions_resume_after`（Unix 毫秒时间戳）。现有的已推出字节将被视为已投递，以确保通过 OTEL 捕获的会话不会被再次上传；后续追加的内容仍将通过对话记录上报流转。

每条命令均支持 `--help`。有关应用程序和编码代理的示例，请参阅 [OpenTelemetry in Cloud](/zh/agenteye/opentelemetry)。
