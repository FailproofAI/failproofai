`failproofai otel` 用于配置向 FailproofAI Cloud 上报的可选 OpenTelemetry 功能。请先通过 `failproofai config` 将您的机器连接至 Cloud。Cloud 中的 OpenTelemetry 数据接收始终处于开启状态，无需在组织层面进行任何切换。

交互式设置会在填写 Cloud 密钥和选择智能体之后，询问是否配置 OpenTelemetry。该可选步骤默认为"否"。选择"是"可选择启用 OTEL 的智能体；连接信息写入后，相同的启用流程随即运行。在设置完成前按 Esc 不会应用任何更改。以下情况不会自动为您启用 OTEL：无人值守设置、提供密钥、开源模式，以及保留已有连接。

## 启用智能体

```bash
failproofai otel enable claude
failproofai otel enable codex --local
failproofai otel enable codex --no-content
failproofai otel enable copilot
failproofai otel enable all --yes
```

支持的智能体包括 `claude`、`codex` 和 `copilot`（VS Code）。配置 Copilot 需要存在 VS Code 可执行文件或已安装 Copilot 扩展。仅有残留的配置目录是不够的；若两者均未找到，设置将跳过 Copilot。

`--local` 表示将数据发送至本地中继而非直接上报至 Cloud。Copilot 会自动使用中继，因为其配置文件无法存储认证请求头。

中继仅在您的本机上监听。您配置的 FailproofAI 守护进程会在数秒内检测到变更，无需重启。如果另一个应用程序占用了中继端口，状态页面将显示其为关闭状态，守护进程仍会继续运行。

<Warning>
文本内容捕获默认开启。添加 `--no-content` 可省略提示词和工具详情。不同版本的智能体所暴露的内容控制选项有所不同；在处理敏感数据之前，请先确认您的智能体会导出哪些内容。
</Warning>

Codex 仅导出对话日志，不包含内部运行时追踪或指标数据。如果您在 Codex 配置中明确设置了 `log_user_prompt = false`，该设置将保持关闭；启用时，若此选项被保留，程序会打印相应提示信息。

### 选择一种上报路径

如果某个智能体已开启会话记录上报，设置时会询问：

> failproofai already sends Claude Code sessions to Cloud. Send them with OTEL instead? Transcript upload for Claude Code stops.

默认为"否"。使用 `--yes` 可跳过提示直接确认切换。其他智能体及策略执行不受影响。

Codex 设置会等待守护进程确认采集器变更后，再写入其导出器配置。若确认超时，设置会提示您在启动 Codex 前等待。

Config v2 将已记忆的追踪列表存储在 `agents.selected`（检测历史存储在 `agents.seen`）。每个智能体的会话记录偏好保存在 `collector.agents.<agent>.sessions`，OTEL 归属保存在 `otel.agents`，中继配置保存在 `collector.otlp.enabled` / `collector.otlp.port`。这些独立的键使旧版 OTEL 配置保持可读：设置可以在不丢失传输偏好或恢复智能体配置所需状态的情况下，更改追踪列表。

## 检查配置状态

```bash
failproofai otel status
```

状态信息会显示每个智能体的详情，包括其配置是否由 FailproofAI 管理、数据目标地址、组织的数据接收开关状态、中继状态，以及最近一次中继上传结果。

组织开关显示 `unknown` 表示服务器未提供该信息或无法访问。这不是错误，也不影响在旧版 Cloud 上进行配置。

如果 Cloud 尚不支持 OTEL，中继会保留被拒绝的导出数据而非丢弃。如果旧版 Cloud 将组织数据接收报告为关闭状态，`enable` 将不写入任何内容并以错误退出。

## 为应用程序打印配置信息

```bash
failproofai otel env --service my-agent
failproofai otel env --service my-agent --local
```

输出内容为 OTLP/HTTP 导出器的 Shell 环境变量块。Cloud 输出会将 `OTEL_EXPORTER_OTLP_ENDPOINT` 设置为 Cloud 的 OTLP 基础路径 `https://<cloud>/otel`，导出器会自动追加 `/v1/<signal>`；若使用 `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` 等按信号类型设置的变量，则需填写完整路径 `https://<cloud>/otel/v1/logs`。本地输出指向中继地址 `http://127.0.0.1:<port>`。Cloud 输出包含已配置的 API 密钥，请妥善保管。本地输出不包含密钥。使用本地输出前，请先启用一个本地智能体以确保中继正在运行。

## 恢复之前的配置

```bash
failproofai otel disable claude
failproofai otel disable all
```

Disable 仅恢复由 FailproofAI 写入的配置，保留无关更改，并为每个智能体恢复其之前的会话记录上报选项。当最后一个受管理的本地智能体被禁用时，中继将停止接受导出数据。

对于 Codex，禁用操作还会记录 `collector.agents.codex.sessions_resume_after`（Unix 毫秒时间戳）。现有的已传输字节将被视为已投递，确保通过 OTEL 捕获的会话不会被重复上传；后续追加的内容仍会通过会话记录上报流程处理。

所有命令均支持 `--help`。有关应用程序和编码智能体的示例，请参阅 [OpenTelemetry in Cloud](/zh/agenteye/opentelemetry)。
