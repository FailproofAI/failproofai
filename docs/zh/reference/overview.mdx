选择最接近您当前 agent 运行环境的集成方式。

本节介绍两个命令行工具，它们各司其职：`failproofai` 运行在 agent 所在的机器上，在 agent 循环内部执行策略；`fp` 与 Failproof AI Cloud 通信，读取该循环的运行记录。机器配置仅支持 Linux 和 macOS——`failproofai config` 在其他系统上会直接拒绝执行，不会写入任何内容，以免留下半配置状态的机器。

## 连接 agent 并验证数据

<Tabs>
  <Tab title="仪表板">
    1. 打开 **Administration → Keys**，创建一个具有 `events:add` 和 `policies:pull` 权限的密钥，并复制 secret。
    2. 使用上方对应页面完成集成配置。
    3. 打开 **Observe → Events** 确认事件已到达，再打开 **Observe → Sessions** 确认事件已组合成完整的运行记录。
    4. 按集成环境筛选，并检查某个会话中审计所需的模型、工具、错误和策略字段。

    从密钥抽屉开始。所选权限决定了机器能否发送事件和接收云端管理的策略。

    ![用于授予事件摄取和策略投递权限的新建 API 密钥抽屉。](/images/dashboard/key-create.png)

    连接集成后，使用会话列表确认其事件已在预期环境中被归组为完整的运行记录。

    ![用于验证新连接的集成是否正常上报完整 agent 运行记录的会话列表。](/images/dashboard/sessions-list.png)

    在确认集成完成之前，请打开其中一个会话；追踪记录中应包含审计所需的模型、工具、错误和策略信息。
  </Tab>
  <Tab title="CLI">
    创建机器密钥、配置并连接本机、选择策略，然后验证第一个会话。

    ```bash
    fp keys create agent-production \
      --add events:add \
      --add policies:pull

    failproofai config --token <machine-key>

    failproofai policies add FailproofAI/policies

    failproofai flush --wait
    fp sessions --since 1h
    fp events --since 1h --limit 20
    ```

    两个验证命令都不按环境过滤，因为新配置的机器会将每个事件标记为 `local`。只有在设置 `collector.environment` 之后，才需要加上 `--env production`——详见[更改环境标签](/zh/reference/events-and-configuration#change-an-environment-label)。

    传入 token 即表示请求连接，因此 `failproofai config --token <machine-key>` 一条命令即可完成所有操作。建议优先使用环境变量：以参数形式传入时，机器上的所有用户都可以通过 `ps` 读取，且会留存在 shell 历史记录和 CI 日志中。

    策略步骤不可省略。`failproofai config` 会安装守护进程并接入所有受支持的 agent CLI，但不会主动选择任何策略，因此新配置的机器在您添加策略包之前不会执行任何拦截。

    当其他工具需要消费输出结果时，请使用 `fp --json sessions ...`。`--json`、`--org`、`--base-url` 等全局标志必须放在命令之前。

    本地命令请参阅 [Failproof AI CLI 参考](/zh/reference/failproof-cli)，`fp` 命令请参阅 [Failproof Cloud CLI 参考](/zh/reference/cloud-cli#cli-commands)。
  </Tab>
</Tabs>
