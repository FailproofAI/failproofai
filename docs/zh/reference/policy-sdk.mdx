自定义策略将追踪记录或审计中发现的故障模式转化为 Agent 运行时的实时决策。策略可以允许某个操作、为 Agent 提供指导，或在操作引发新问题之前将其拒绝。

当行为依赖于你的工具、路径、命令、环境或操作规则时，请使用自定义策略。在动手编写之前，建议先查阅[内置策略目录](/zh/policies/builtin-catalog)，避免重复实现已有的控制规则。

## 编写自定义策略

<Tabs>
  <Tab title="控制台">
    1. 前往 **Admin → policy editor**，选择 **New policy**，描述你希望防范的故障。
    2. 添加策略源码，在编辑器中测试预期匹配项和安全的非匹配项，解决所有校验错误。
    3. 保存草稿，选择 **Publish version** 创建不可变版本。
    4. 前往 **Admin → enforcement**，以 **observe** 模式将该版本部署到测试机器，并在 **Observe → policy** 下验证其决策，确认无误后再执行强制执行。

    ![用于编写和发布自定义策略的策略编辑器。](/images/dashboard/policy-editor.png)
  </Tab>
  <Tab title="CLI">
    1. 创建 `.failproofai/policies/checkout-policies.ts`。文件名必须以 `policies.js`、`policies.mjs` 或 `policies.ts` 结尾。
    2. 使用 `customPolicies.add()` 注册一个或多个策略。
    3. 使用 `failproofai policies --install --custom ./.failproofai/policies/checkout-policies.ts --scope project` 校验并安装文件。
    4. 触发一个匹配操作和一个安全操作。运行 `failproofai policies`，然后在 **Observe → policy** 下查看归因决策。
  </Tab>
</Tabs>

## 从窄规则开始

以下策略仅在命令目标为生产环境时才拦截破坏性的 Kubernetes 命令。不在该故障模式范围内的操作均返回 `allow()`。

```ts
import { customPolicies, allow, deny } from "failproofai";

const DESTRUCTIVE_KUBECTL = /\bkubectl\s+(delete|replace)\b/i;
const PRODUCTION_TARGET = /(?:--context|--namespace|-n)\s+(prod|production)\b/i;

customPolicies.add({
  name: "block-destructive-production-kubectl",
  description: "Block destructive Kubernetes commands against production",
  match: { events: ["PreToolUse"] },
  fn: async ({ toolName, toolInput }) => {
    if (toolName !== "Bash") return allow();

    const command = String(toolInput?.command ?? "");
    if (!DESTRUCTIVE_KUBECTL.test(command)) return allow();
    if (!PRODUCTION_TARGET.test(command)) return allow();

    return deny(
      "Destructive production Kubernetes commands require the approved deployment workflow.",
    );
  },
});
```

好的策略应当足够精简，能用一句话说清楚。匹配可观察到的操作——而非你对 Agent 意图的推测——并在规则不适用时尽早返回 `allow()`。

## 选择决策类型

| 辅助函数 | 结果 | 适用场景 |
| --- | --- | --- |
| `allow(reason?)` | 操作继续执行。 | 策略不适用，或操作是安全的。 |
| `instruct(reason)` | 操作继续执行，并在支持的运行环境中附带指导信息。 | 希望引导 Agent 采用更好的方式，而不强制执行某个不变量。 |
| `deny(reason)` | 当事件和运行环境支持拦截时，操作被阻止。 | 操作不可继续执行。 |

为需要恢复的 Agent 填写原因说明，解释检测到了什么以及应当改为做什么。

<Warning>
  不要将 `instruct()` 用于安全边界。指导信息的传达方式因 Agent 运行环境而异。当操作必须被阻止时，请使用 `deny()`。
</Warning>

## 策略对象

```ts
customPolicies.add({
  name: "policy-name",
  description: "What this policy prevents",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => allow(),
});
```

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 策略的稳定标识符。请确保跨文件唯一。 |
| `description` | 否 | 人类可读的用途描述，显示在策略列表和决策记录中。 |
| `match.events` | 否 | 触发该策略的事件类型。省略 `match` 则对所有可用事件生效。 |
| `fn` | 是 | 同步或异步函数，返回 `allow`、`instruct` 或 `deny` 结果。 |

请在 `fn` 内部过滤工具。`match.toolNames` 不属于公开的自定义策略类型。

## 策略上下文

每个策略都会接收一个 `PolicyContext`。

| 字段 | 类型 | 内容说明 |
| --- | --- | --- |
| `eventType` | `HookEventType` | 当前正在评估的规范化事件。 |
| `toolName` | `string \| undefined` | 规范工具名称，如 `Bash`、`Read`、`Write` 或 `Edit`。 |
| `toolInput` | `Record<string, unknown> \| undefined` | 当前工具调用的规范化输入。 |
| `payload` | `Record<string, unknown>` | 完整的规范化事件载荷。 |
| `session` | `SessionMetadata \| undefined` | 会话 ID、工作目录、记录路径、权限模式以及可用时的运行环境元数据。 |
| `cli` | `string \| undefined` | 源 Agent 运行环境，如 `claude`、`codex` 或 `cursor`。 |
| `params` | `Record<string, unknown>` | 内置策略参数。自定义策略当前接收空对象。 |

请将所有可选值视为真正可选。不同的 Agent 版本和事件类型并不都提供相同的字段。

### 常用工具输入

Failproof AI 在支持的运行环境中对常用工具进行了规范化，因此策略通常可以使用统一的输入结构。

| 工具 | 常用字段 |
| --- | --- |
| `Bash` | `command` |
| `Read` | `file_path` |
| `Write` | `file_path`, `content` |
| `Edit` | `file_path`, `old_string`, `new_string` |
| `Grep` | `pattern`, `path` |

由于工具输入值的类型为 `unknown`，请使用防御性类型转换：

```ts
const command = String(ctx.toolInput?.command ?? "");
const filePath = String(ctx.toolInput?.file_path ?? "");
```

## 选择事件

| 事件 | 触发时机 | 典型用途 |
| --- | --- | --- |
| `PreToolUse` | 工具执行之前。 | 拦截或引导命令、写入、读取及外部操作。 |
| `PostToolUse` | 工具返回之后。 | 在结果到达 Agent 之前进行检查。拒绝会阻断整个结果，不支持对特定字段进行脱敏。 |
| `PermissionRequest` | Agent 请求权限时。 | 应用组织特定的权限规则。 |
| `UserPromptSubmit` | 提交的提示词继续执行之前。 | 拒绝禁止的指令或添加工作流指导。 |
| `Stop` | Agent 尝试完成任务时。 | 要求满足可达的完成条件，例如本地验证步骤。 |
| `SubagentStop` | 子 Agent 尝试完成任务时。 | 在委托工作返回父 Agent 之前进行把关。 |
| `SessionStart` / `SessionEnd` | 会话边界处。 | 记录或检查会话级状态。 |

事件的可用性和拦截行为取决于 Agent 运行环境。在混合集群中依赖某个事件之前，请先参阅 [Agent 运行环境](/zh/reference/harnesses)。

<Accordion title="所有策略事件名称">
  `SessionStart`、`SessionEnd`、`UserPromptSubmit`、`PreToolUse`、`PermissionRequest`、`PermissionDenied`、`PostToolUse`、`PostToolUseFailure`、`Notification`、`SubagentStart`、`SubagentStop`、`TaskCreated`、`TaskCompleted`、`Stop`、`StopFailure`、`TeammateIdle`、`InstructionsLoaded`、`ConfigChange`、`CwdChanged`、`FileChanged`、`WorktreeCreate`、`WorktreeRemove`、`PreCompact`、`PostCompact`、`Elicitation`、`ElicitationResult`、`UserPromptExpansion`、`PostToolBatch` 和 `Setup`。
</Accordion>

## 常用策略模式编写示例

### 拦截对受保护路径的写入

```ts
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "block-generated-file-edits",
  description: "Require generated files to be changed through their generator",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (!["Write", "Edit"].includes(ctx.toolName ?? "")) return allow();

    const filePath = String(ctx.toolInput?.file_path ?? "");
    if (!/(^|\/)(dist|generated)\//.test(filePath)) return allow();

    return deny("Edit the source and run the generator instead of changing generated output.");
  },
});
```

### 提供非阻断性指导

```ts
import { customPolicies, allow, instruct } from "failproofai";

customPolicies.add({
  name: "prefer-reviewed-deploy-command",
  description: "Guide agents toward the reviewed deployment wrapper",
  match: { events: ["PreToolUse"] },
  fn: async (ctx) => {
    if (ctx.toolName !== "Bash") return allow();

    const command = String(ctx.toolInput?.command ?? "");
    if (!/^kubectl\s+apply\b/.test(command.trim())) return allow();

    return instruct("Use ./scripts/deploy-reviewed instead of invoking kubectl directly.");
  },
});
```

### 为会话完成设置门控

```ts
import { execFileSync } from "node:child_process";
import { customPolicies, allow, deny } from "failproofai";

customPolicies.add({
  name: "require-clean-typecheck",
  description: "Require the project typecheck to pass before the agent finishes",
  match: { events: ["Stop"] },
  fn: async (ctx) => {
    const cwd = ctx.session?.cwd;
    if (!cwd) return allow();

    try {
      execFileSync("bunx", ["tsc", "--noEmit"], {
        cwd,
        stdio: "ignore",
        timeout: 8_000,
      });
      return allow();
    } catch {
      return deny("Fix the typecheck errors before finishing the task.");
    }
  },
});
```

<Warning>
  被拒绝的 `Stop` 事件可能导致 Agent 重试。请仅对 Agent 在当前环境中能够满足的条件设置门控，并为所有子进程或网络调用设置超时限制。
</Warning>

## 加载策略文件

### 约定文件

约定文件会自动加载：

```text
<project>/.failproofai/policies/security-policies.ts
~/.failproofai/policies/personal-policies.mjs
```

- 项目级和用户级策略目录均会被加载。
- 文件在各目录内按字母顺序加载。
- 文件名必须以 `policies.js`、`policies.mjs` 或 `policies.ts` 结尾。
- 同一文件中支持多次调用 `customPolicies.add()`。
- 支持从本地模块进行相对路径导入。
- 项目策略可以提交到版本库，使同一套规则随代码仓库一起流转。

### 显式文件

当校验或配置需要直接指定入口文件时，使用显式路径：

```bash
failproofai policies --install \
  --custom ./security.policies.ts \
  --custom ./workflow.policies.ts \
  --scope project
```

显式文件优先加载，其次是项目约定文件，最后是用户约定文件。同一文件若通过两种方式均被发现，只加载一次。

## 校验与测试

校验过程通过生产环境加载器执行模块，并确认其至少注册了一个策略。

```bash
failproofai policies --install \
  --custom ./.failproofai/policies/checkout-policies.ts \
  --scope project
failproofai policies
```

校验能捕获缺失文件、语法错误、未解析的导入、顶层异常以及模块加载超时，但不能证明你的匹配逻辑是否正确。

至少测试以下场景：

- 一个必须匹配并产生预期策略原因的操作。
- 一个相邻但安全、必须返回 `allow()` 的操作。
- 缺失或格式错误的工具字段。
- 命令语法、路径、引号、大小写和空白字符的变体。
- 不可用的子进程或网络依赖。

在 **Observe → policy** 下将结果归因到你的自定义策略。如果决策是由另一个内置策略做出的，则被拦截的测试结果并不充分。

## 运行时行为

- 内置策略在自定义策略之前评估。
- 第一个 `deny` 会停止后续策略的评估。
- 当没有策略拒绝事件时，多个 `instruct` 结果可以合并。
- 策略函数的执行时限为 10 秒。
- 抛出的异常或超时会被记录日志，并视为 `allow()`。
- 加载失败的约定文件会被跳过；其他自定义文件和内置策略继续运行。
- 顶层模块加载同样有 10 秒时限。
- 云端观察模式会运行策略，但会记录非允许决策而不强制执行。

保持策略模块的确定性和高效性。避免在顶层发起网络请求或启动服务器。在 `fn` 内部限制工作范围，捕获依赖失败，并有意识地决定该失败应当允许还是拒绝操作。

## API 导出

| 导出项 | 用途 |
| --- | --- |
| `customPolicies.add(policy)` | 在模块加载时注册自定义策略。 |
| `allow(reason?)` | 允许操作。 |
| `instruct(reason)` | 允许操作，并在支持的环境中提供指导信息。 |
| `deny(reason)` | 在支持的环境中阻止操作。 |
| `getCustomHooks()` | 返回当前在模块注册表中已注册的策略。 |
| `clearCustomHooks()` | 清空该注册表，主要用于测试和加载器。 |

TypeScript 导出 `PolicyContext`、`PolicyResult`、`CustomHook`、`PolicyDecision` 和 `PolicyFunction`。
