使用 `failproofai-sdk` 为自定义 Agent 添加追踪埋点，让 Failproof AI 能够重建每次运行过程、审计其行为，并发现有据可查的故障。SDK 会将结构化事件写入 Failproof 守护进程，再由其传送至云端。需要 Python 3.10 或更高版本。

追踪功能使自定义 Agent 具备可观测性和可审计性。若要在执行前阻止不安全操作，还需要在运行时中配置执行钩子。

</Info>

## 安装 `failproofai-sdk`

SDK 目前以私有 wheel 包形式分发。请向您的 Failproof AI 联系人获取当前版本及下载权限。

```bash
VERSION=<sdk-version>
pip install "./failproofai_sdk-${VERSION}-py3-none-any.whl"
python -c "import failproofai; print(failproofai.__version__)"
```

使用 `uv` 时，请先下载 wheel 包，然后运行 `uv add ./failproofai_sdk-${VERSION}-py3-none-any.whl`。建议将 wheel 包固定在私有制品仓库或依赖锁定文件中。

该包的安装名称为 `failproofai-sdk`，在 Python 中以 `failproofai` 导入。

## 为完整运行过程添加埋点

在进程启动时调用一次 `configure()`。每个事件调用均为仅限关键字参数，且需要稳定的 `session_id` 和 `agent_id`。

```python
import traceback
import uuid

import failproofai

failproofai.configure(environment="production")

session_id = uuid.uuid4().hex
agent_id = "checkout-agent"

failproofai.event.agent_start(
    session_id=session_id,
    agent_id=agent_id,
    goal="Resolve a failed checkout",
)

try:
    tool_call_id = uuid.uuid4().hex
    failproofai.event.tool_use(
        session_id=session_id,
        agent_id=agent_id,
        tool_name="lookup_order",
        tool_call_id=tool_call_id,
        input={"order_id": "ord_8421"},
    )
    result = {"status": "payment_failed"}
    failproofai.event.tool_result(
        session_id=session_id,
        agent_id=agent_id,
        tool_name="lookup_order",
        tool_call_id=tool_call_id,
        output=result,
    )
except Exception as exc:
    failproofai.event.error(
        session_id=session_id,
        agent_id=agent_id,
        error_type=type(exc).__name__,
        message=str(exc),
        traceback=traceback.format_exc(),
    )
    failproofai.event.agent_end(
        session_id=session_id,
        agent_id=agent_id,
        outcome="failed",
    )
    raise
else:
    failproofai.event.agent_end(
        session_id=session_id,
        agent_id=agent_id,
        outcome="success",
        summary="Escalated the failed payment",
    )
```

每个执行者发出一次 `agent_start`。对于子 Agent，请复用父 Agent 的 `session_id`，为每个执行者分配不同的 `agent_id`，并将 `parent_id` 设置为父 **agent ID**，而非 session ID。

## 配置参考

```python
failproofai.configure(
    base_dir=None,
    flush_interval=0.5,
    environment="production",
)
```

| 配置项 | 说明 |
| --- | --- |
| `base_dir` | 显式指定的缓冲根目录，优先级高于所有环境变量。 |
| `flush_interval` | 后台将内存数据写入 JSONL 的间隔秒数。默认值：`0.5`。 |
| `environment` | 每个事件上的部署标签，默认为 `dev`。 |
| `FAILPROOFAI_HOME` | 更改包含 `custom-agents` 缓冲目录的 Failproof AI 根目录。 |

设置了显式 `base_dir` 时，SDK 将写入该目录；否则将使用 `FAILPROOFAI_HOME` 或 `~/.failproofai` 下 Failproof 守护进程的 `custom-agents` 缓冲目录。

SDK 在内存中排队调用，并通过后台线程批量写入。它还会在 Python 的 `atexit` 处理阶段尝试最终刷写。对于短生命周期的 Worker，请允许解释器正常关闭；强制终止进程可能导致内存中的事件丢失。

## 事件目录

所有方法均返回 `None`。值为 `None` 的字段将被省略，而不是写为 JSON `null`。

| 方法 | 除身份标识外的必填字段 | 可选字段 |
| --- | --- | --- |
| `agent_start` | — | `goal`, `parent_id` |
| `agent_end` | — | `outcome`, `summary` |
| `agent_pause` | `pause_id` | `reason`, `user_id` |
| `agent_resume` | `pause_id` | `reason`, `user_id` |
| `model_request` | — | `model`, `messages`, `system`, `tools` |
| `model_response` | — | `model`, `stop_reason`, `input_tokens`, `output_tokens`, `content`, `role` |
| `tool_use` | `tool_name`, `tool_call_id` | `input` |
| `tool_result` | `tool_name`, `tool_call_id` | `output`, `error` |
| `hook_triggered` | `hook_name`, `hook_id` | `trigger_event`, `input` |
| `hook_completed` | `hook_name`, `hook_id` | `outcome`, `output`, `error` |
| `error` | `error_type`, `message` | `traceback` |
| `human_wait` | `input_id` | `prompt`, `options`, `reason` |
| `human_input` | `input_id` | `response` |
| `human_pause` | — | `reason`, `user_id` |
| `human_interrupt` | — | `reason`, `user_id`, `at_step` |

当某次完成应被记为失败时，请使用 `outcome="failed"`、`"error"`、`"timeout"` 或 `"rejected"`。其他值（包括 `"failure"`）不会被当前后端识别为失败。

## 关联与时长规则

- 对匹配的完成事件复用相同的 `tool_call_id`、`hook_id`、`pause_id` 或 `input_id`。
- SDK 会自动计算 `tool_result`、`hook_completed`、`agent_resume` 和 `human_input` 的 `duration_ms`。若手动传入该参数，将抛出 `ValueError`。
- 工具 ID 和钩子 ID 共享同一个进程级别的待处理映射表。请确保它们在并发会话间以及两个命名空间内全局唯一；使用提供商 ID 或 UUID 最为安全。
- 跨进程拆分的事件对仍可在下游关联，但 SDK 无法计算其进程内时长。
- 待处理映射表最多保存 10,000 条起始记录，超出时将淘汰最旧的条目。

## 自定义字段与载荷

每个事件都接受额外的关键字字段。当下游查询需要结构化数据时，请使用 JSON 兼容的值。不受支持的叶子类型（如 UUID、datetime、decimal、set、bytes 和模型对象）将由写入器转换为字符串。

保留的自定义字段名称为 `timestamp`、`session_id`、`agent_id`、`type` 和 `environment`。可选字段名拼写错误会被作为新的自定义字段接受，因此当某个标准字段未出现在云端时，请检查实际写出的 JSON。

## 传送与验证

<Tabs>
  <Tab title="控制台">
    在 **Observe → Events** 中，验证 `agent_start` 是否为第一条事件，`agent_end` 是否为最后一条。然后打开 **Observe → Sessions**，确认模型、工具、人工、钩子和错误事件按预期顺序出现。以 session ID 作为主要排查依据。
  </Tab>
  <Tab title="CLI">
    ```bash
    failproofai flush --wait --timeout 60
    failproofai config --status
    fp sessions --since 1h --env production --session-id <session-id>
    fp events --since 1h --session-id <session-id> --full
    ```
  </Tab>
</Tabs>

若云端为空，请检查 `$FAILPROOFAI_HOME/custom-agents/events`，否则检查 `~/.failproofai/custom-agents/events`。JSONL 文件证明 SDK 已成功写出；缓冲目录持续增长说明问题在于守护进程配置或传送；缓冲目录为空则说明问题在于埋点或进程生命周期。

## 在自定义运行时中阻止故障

利用审计发现和关联追踪来明确不安全操作、所需证据及预期响应。自定义执行集成必须在操作执行前将其暴露出来，将其结构化输入传递给策略引擎，并应用最终的 allow、instruct 或 deny 决策。

请发送邮件至 [support@befailproof.ai](mailto:support@befailproof.ai)，与我们共同设计并验证适合您运行时的集成方案。
