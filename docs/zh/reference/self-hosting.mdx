## 前提条件

- Kubernetes 1.27 或更高版本，且具备 cluster-admin 访问权限
- 支持 Kustomize 的 `kubectl`
- Helm 3
- 私有镜像仓库 `ghcr.io/agenteye-enterprise` 的访问权限
- 两个 DNS 名称：一个用于控制台，一个用于数据摄入
- PostgreSQL 和 ClickHouse 的持久化存储
- cert-manager 和 Traefik，或经过适配整合到 overlay 中的同等 Ingress 及证书基础设施
- 用于生产环境 OTP 登录和通知的 SMTP

源码树提供了面向 AWS/EKS 的 overlay 和单独的 GCP/GKE overlay。请勿混用两者的证书、负载均衡器或备份说明：GKE 使用其专属的 DNS-01、GCS 和自动扩缩容配置。

## 部署流程

<Steps>
  <Step title="准备集群">
    安装 cert-manager 和公网/控制台 Ingress 控制器，验证其负载均衡器，然后创建命名空间、镜像拉取凭据、数据库凭据、引导管理员密钥以及身份认证/SMTP 密钥。
  </Step>
  <Step title="配置公共域名">
    在 overlay 生成的域名环境文件中设置 `INGEST_DOMAIN` 和 `DASHBOARD_DOMAIN`，并创建指向对应负载均衡器的 DNS 记录。
  </Step>
  <Step title="应用并验证单个平台 overlay">
    使用 customer/EKS 或 GCP overlay。检查渲染后的 Kustomize 输出，应用它，并在接入机器之前确认所有工作负载和证书均达到预期状态。
  </Step>
  <Step title="引导访问和数据摄入">
    以受保护的管理员身份登录，创建组织范围的机器密钥，并通过公共摄入端点发送一个小型测试会话。
  </Step>
</Steps>

## 必需服务与可选服务

| 组件 | 要求 |
| --- | --- |
| ClickHouse | 必需。缺少规范事件存储时服务器将拒绝启动。 |
| PostgreSQL | 必需，用于用户、组织、保存对象和控制平面状态。 |
| Redis | 可选。不可用时，服务器和控制台将降级为基于数据库的行为。 |
| SMTP | 开发环境可选，生产环境的邮件 OTP 和通知投递必需。 |
| Evaluator | 可选。未配置 `EVALUATOR_ENDPOINT` 时，自动评估保持禁用状态。 |
| 助手/审计 LLM | 可选。未配置 LLM 连接时，助手和 LLM 支持的审计功能保持不活跃状态。 |
| 对象存储备份 | 强烈建议用于 PostgreSQL 和 ClickHouse 备份归档。 |

### 审计容量与失败投递

在可用时，在专用的 audit-agent 部署上运行审计。每个 audit-agent Pod 默认接受一个调查任务；请通过增加副本数来提升吞吐量，而不是在不增加内存的情况下提高单 Pod 并发数。服务器可同时分发 `server 副本数 × AUDIT_WORKERS` 个审计任务，因此调度器容量应足够大，以填满 audit-agent 集群。

当所有 audit-agent 槽位都被占用时，审计任务将等待并重试，时长最多为其周期的四分之一，上限为六小时。如果没有槽位空出，该次运行将在没有发现的情况下完成，并发送失败邮件。频繁出现"繁忙"失败需要增加 audit-agent 副本数或将调度锚点间隔调得更宽。频繁出现"正在关闭"失败则表明是 Pod 不稳定或滚动更新循环，而非容量不足。

失败通知需要启用邮件渠道和 SMTP。通知优先使用审计配置的收件人，若审计无邮件渠道则回退到 `alerts.email_default_recipients`。

## 身份认证与邮件

控制台使用邮件和一次性验证码。未配置 SMTP 时，开发环境部署会将 OTP 验证码输出到服务器日志。设置 `SMTP_HOST` 后，用户名、密码和发件人必须作为一组同时配置，否则服务器将拒绝启动。

`SMTP_TLS` 为布尔值。支持的加密传输方式为 STARTTLS，通常使用 587 端口；当前服务器传输层不支持 465 端口上的隐式 SMTPS。

请正确设置公共控制台 URL，因为 OTP、告警、事件和审计邮件均使用它生成深层链接。组织成员资格控制谁可以申请验证码；每个组织可在**管理 → 设置**中进一步限制其成员的登录方式。

## 多租户要求

在创建第二个组织之前，请配置一个强且稳定的组织 ClickHouse 派生密钥，并确保所有服务器副本上的该密钥完全一致。在未进行协调迁移的情况下轮换该密钥可能导致组织专属的 ClickHouse 用户成为孤立状态。

请将实例管理员监听器保持在内部网络。提供的运营控制台为可选功能，设计为通过 `kubectl port-forward` 使用，而非公共 Ingress。启用它需要专属的强 API 密钥、超级管理员邮箱以及可用的 SMTP 二次验证投递。

### 紧急组织 CLI

`agenteye-orgctl` 内置于服务器镜像中，直接与 PostgreSQL 和 ClickHouse 通信。在公共服务器或运营控制台不健康时仍可使用。

```bash
kubectl -n agenteye exec deploy/server -- \
  agenteye-orgctl org create --slug acme --name "Acme Corp"
kubectl -n agenteye exec deploy/server -- agenteye-orgctl org list
kubectl -n agenteye exec deploy/server -- \
  agenteye-orgctl member add --org acme --email ops@acme.com --set admin --protected
```

支持的组织操作包括：创建、列出、重命名、软删除、恢复、ClickHouse 用户重新配置、账单日期管理、功能标志以及不可逆清除。成员操作包括：添加、列出、更新、移除、权限覆盖以及受保护管理员状态管理。

请在清除前执行软删除。`org purge` 操作不可逆，且要求组织已被删除。受保护成员无法通过组织的普通用户页面被移除或降级，必须由运营人员显式取消保护后方可操作。

## 生产就绪检查清单

- 摄入和控制台 DNS 分别解析到预期的不同 Ingress 路径。
- TLS 有效；在部署要求时对摄入端点启用双向 TLS。
- PostgreSQL 和 ClickHouse 卷已配置容量告警。
- 备份涵盖两个数据存储，并具备经过验证的恢复流程。
- 健康检查对摄入静默、工作负载失败、证书过期、存储压力和过期备份发出告警。
- 结构化日志已收集，且未与现有集群日志管道重复采集。
- 未在没有队列实测数据的情况下更改评估器、审计和告警 Worker 的并发数。
- 升级前已记录固定的应用发布版本和回滚流程。

<Warning>
  部署清单包含特定于平台的安全性和可用性假设。在应用之前，请与您的平台团队一起审查渲染后的资源、网络策略、Ingress 暴露方式、密钥引用、存储类、中断预算和备份目标。
</Warning>
