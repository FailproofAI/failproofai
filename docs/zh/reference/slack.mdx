从 Slack 中使用 [failproof agent](/zh/sessions/assistant)。在频道中 @ 该应用、向它发送私信，或使用 `/failproof <问题>`。回答使用**您自己的** Failproof AI 权限，图表会出现在话题中，任何需要更改内容的操作都会先请您批准。

官方应用只有一个。无论您的 Failproof AI Cloud 是托管版还是自托管版，使用方式完全相同。

<Note>
  回答由 AI 模型生成，可能存在不准确之处。重要内容请以链接的原始数据为准。
</Note>

## 连接工作区

您需要在 Failproof AI 中拥有 `settings:write` 权限，在 Slack 中需要是工作区管理员或所有者，或者是添加应用的人员。

<Tabs>
  <Tab title="从 Failproof AI 操作">
    1. 进入 **设置 → 集成**，选择 **Add to Slack**。
    2. 在 Slack 中批准该应用。
    3. 返回 Failproof AI，确认将工作区连接到您的组织。
  </Tab>
  <Tab title="从 Slack 操作">
    1. 添加应用后，打开其 **Home** 标签页。
    2. 选择 **Continue with FailproofAI Cloud**，或选择 **Use my own URL** 并输入您的登录地址。
    3. 点击继续按钮，登录，选择组织并确认。该链接只能使用一次，10 分钟后失效。
  </Tab>
</Tabs>

一个工作区对应一个组织，一个组织对应一个工作区。

还没有账户？请先[注册](https://app.befailproof.ai/login)，再进行连接。

## 您在 Slack 中的身份

首次提问时，应用会识别您的成员身份：

- **自动通过电子邮件匹配**：当您是已连接工作区的正式成员、Slack 邮箱已确认，且组织中恰好只有一位成员使用该邮箱时，系统会自动识别。
- **否则**，您会收到一个私信中的 **Link your account** 按钮，点击后可在 Failproof AI 中将您的 Slack 用户与账户绑定。

## 提出问题

| 场景 | 操作方式 |
| --- | --- |
| 频道中 | @ 该应用。在其话题中回复即可继续对话，无需再次 @ |
| 私信 | 直接向应用发送消息 |
| 应用所在的群组私信 | @ 它，然后在话题中回复继续 |
| Slack Connect 频道 | @ 该应用 |
| 应用所在的任意会话 | `/failproof <问题>` 会开启一个包含回答的话题 |
| `/failproof help` | 查看应用的功能说明 |
| `/failproof status` | 查看已连接的组织及您绑定的身份 |
| `/failproof link` | 查看您绑定的 Failproof AI 账户 |

一个话题对应一段对话。同事可以在同一话题中 @ 该应用，应用会根据各自的权限分别回答。只有开启话题的人才能在无需 @ 的情况下继续对话。

当回答涉及数据时，应用会发布图表或表格，并附上在 Failproof AI 中打开的链接。

## 批准更改

failproof agent 进行的每项更改都会先显示 **Approve** 和 **Cancel** 按钮，且 Slack 在 **Approve** 前会再次确认。只有提问的人才能响应这些按钮，按钮在 5 分钟后失效，更改将以该人员的权限执行。

在 Slack 中，failproof agent 可以在您拥有相应权限的情况下，更改已保存的查询和仪表板、评估、告警、审计、洞察和策略，以及建议代码修复。它无法更改 API 密钥、用户或设置。

## 链接预览

在托管版 Failproof AI Cloud 上，粘贴到 Slack 中的 Failproof AI 洞察、会话和评估链接会展开为卡片。卡片仅显示触发者有权查看的内容。自托管地址的链接不会展开，但 failproof agent 自身回答中的卡片仍会正常显示。

## Slack Connect 频道

来自其他工作区的人员在绑定账户后，如果是该组织的成员，即可使用该应用。回答对会话中所有人可见，包括不属于您组织的人员，因此请在所有人都可能看到回答的场合中谨慎提问。

该应用仅在频道中所有其他工作区都有成员绑定到该组织后才会回答。在此之前，它会告知提问者原因。

## 应用申请的权限

| Slack 权限 | 用途 |
| --- | --- |
| `app_mentions:read` | 识别 @ 该应用的消息 |
| `channels:history`、`groups:history`、`im:history`、`mpim:history` | 接收私信及应用话题中的回复。应用会忽略其他消息，不会读取会话的历史记录 |
| `channels:read`、`groups:read`、`im:read`、`mpim:read` | 检查会话类型，以确认回答的可见范围 |
| `chat:write` | 发布回答和审批按钮 |
| `commands` | 提供 `/failproof` 命令 |
| `files:write` | 发布图表 |
| `links:read`、`links:write` | 显示粘贴的 Failproof AI 链接预览 |
| `users:read`、`users:read.email` | 将您与 Failproof AI 账户匹配，并显示姓名 |

## 断开连接

进入 **设置 → 集成** 并选择 **Disconnect**，在应用的 **Home** 标签页使用 **Disconnect**，或从 Slack 中移除该应用。

以上任意操作都会删除工作区的连接、机器人令牌、已绑定账户和话题记录。过去的 Slack 对话仍可在仪表板中查看。组织之后可立即连接任意工作区。

## 数据与隐私

问题和回答会作为对话保存在组织的仪表板中，归属于开启话题的人员。Slack 数据不会用于训练 AI 模型。请参阅[隐私政策](https://befailproof.ai/privacy/)了解应用接收的数据及其保留时长。

## 故障排查

| 问题描述 | 解决方法 |
| --- | --- |
| "This workspace isn't connected to a FailproofAI Cloud yet." | 由工作区管理员打开应用的 **Home** 标签页并选择一个 Cloud |
| "This link expired or was already used." | 在 **Home** 标签页重新选择您的 Cloud 以获取新链接 |
| "This org is already connected to a Slack workspace." | 请先在设置中断开连接 |
| "That Slack workspace is connected to another org." | 请先从该组织断开该工作区的连接 |
| "Link your account to use the assistant." | 点击按钮并在 Failproof AI 中确认 |
| 应用在群组私信中不回复 | 重新将应用添加到 Slack 以授予群组权限，您的连接会保留 |
| "I won't post answers from your organization here" | 由该工作区中属于该组织成员的人 @ 应用并绑定账户 |
