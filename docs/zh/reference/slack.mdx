在 Slack 中使用 [Failproof 助手](/zh/sessions/assistant)。在频道中 @ 提及该应用，直接向其发送消息，或使用 `/failproof <问题>`。回答使用**您自己的** Failproof AI 权限，图表会出现在对话线程中，任何会引发变更的操作都会先请求您审批。

只有一个官方应用，无论您的 Failproof AI Cloud 是托管版还是自托管版，使用方式完全相同。

<Note>
  回答由 AI 模型生成，可能存在不准确之处。请务必对照关联的源数据核实重要信息。
</Note>

## 连接工作区

您需要在 Failproof AI 中拥有 `settings:write` 权限，同时在 Slack 中是工作区管理员或所有者，或者是负责添加该应用的人员。

<Tabs>
  <Tab title="从 Failproof AI">
    1. 前往 **Settings → Integrations**，选择 **Add to Slack**。
    2. 在 Slack 中授权该应用。
    3. 返回 Failproof AI，确认将该工作区连接到您的组织。
  </Tab>
  <Tab title="从 Slack">
    1. 添加应用后，打开其 **Home** 标签页。
    2. 选择 **Continue with FailproofAI Cloud**，或选择 **Use my own URL** 并输入您的登录地址。
    3. 点击继续按钮，登录，选择组织并确认。该链接仅可使用一次，10 分钟后失效。
  </Tab>
</Tabs>

一个工作区对应一个组织，一个组织也只能对应一个工作区。

还没有账户？请先[创建一个](https://app.befailproof.ai/login)，然后再进行连接。

## 您在 Slack 中的身份

首次提问时，应用会自动识别您的成员身份：

- **通过邮箱自动匹配**：当您是已连接工作区的正式成员、Slack 邮箱已验证，且组织中有且仅有一名成员使用该邮箱时，系统会自动完成匹配。
- **其他情况**：您会收到一个私信发送的 **Link your account** 按钮，点击后会跳转至 Failproof AI，将您的 Slack 用户与账户关联。

## 提问方式

| 场景 | 操作方式 |
| --- | --- |
| 频道 | @ 提及该应用。在其对话线程中回复即可继续，无需再次提及 |
| 直接消息 | 直接向该应用发送消息 |
| 应用所在的群组直接消息 | 提及它，之后在对话线程中回复即可继续 |
| Slack Connect 频道 | 提及该应用 |
| 应用所在的任意对话 | `/failproof <问题>` 会创建一个包含回答的对话线程 |
| `/failproof help` | 查看该应用的功能说明 |
| `/failproof status` | 查看已连接的组织以及您关联的账户身份 |
| `/failproof link` | 查看您关联的 Failproof AI 账户 |

一个线程对应一段对话。同事可以在同一线程中提及该应用，应用会根据各自的权限分别作出回答。只有发起该线程的人可以在无需提及的情况下继续对话。

当回答涉及数据时，应用会发布图表或表格，并附上在 Failproof AI 中打开的链接。

## 审批变更

助手执行的每项变更都会先显示 **Approve** 和 **Cancel** 按钮，且 Slack 在 **Approve** 前还会再次确认。只有提问的人才能响应这些按钮，按钮在 5 分钟后失效，变更将以该人员的权限执行。

在 Slack 中，助手可以在您拥有相应权限的情况下，修改已保存的查询和仪表板、评估、告警、审计、问题、策略，以及建议代码修复。它无法更改 API 密钥、用户或设置。

## 链接预览

在托管版 Failproof AI Cloud 中，粘贴到 Slack 的 Failproof AI 问题、会话和评估链接会展开为卡片。卡片仅显示触发该预览的人员有权查看的内容。自托管地址的链接不会展开，但助手自身回答中的卡片仍会正常显示。

## Slack Connect 频道

其他工作区的人员在关联账户后，只要是组织成员，即可使用该应用。回答对对话中的所有人可见，包括不是您组织成员的人，因此请在所有人都可能看到回答的场合谨慎提问。

只有当频道中其他所有工作区都有成员与该组织关联后，应用才会开始回答。在此之前，应用会向提问者说明原因。

## 应用申请的权限

| Slack 权限 | 用途 |
| --- | --- |
| `app_mentions:read` | 识别何时有人提及该应用 |
| `channels:history`、`groups:history`、`im:history`、`mpim:history` | 接收直接消息以及应用线程中的回复。应用会忽略其他消息，且不会读取对话的历史记录 |
| `channels:read`、`groups:read`、`im:read`、`mpim:read` | 检查所在对话的类型，以便了解哪些人可以看到回答 |
| `chat:write` | 发布回答和审批按钮 |
| `commands` | 提供 `/failproof` 命令 |
| `files:write` | 发布图表 |
| `links:read`、`links:write` | 显示粘贴的 Failproof AI 链接预览 |
| `users:read`、`users:read.email` | 将您与 Failproof AI 账户匹配，并显示姓名 |

## 断开连接

前往 **Settings → Integrations** 并选择 **Disconnect**，或在应用的 **Home** 标签页使用 **Disconnect**，或直接从 Slack 中移除该应用。

以上任意操作都会删除该工作区的连接、机器人令牌、关联账户及线程记录。Slack 中的历史对话仍可在仪表板中查看。之后该组织可立即连接任意工作区。

## 数据与隐私

问题和回答会作为对话保存在您组织的仪表板中，归属于发起该线程的人员。Slack 数据不会被用于训练 AI 模型。请参阅[隐私政策](https://befailproof.ai/privacy/)了解应用接收的数据内容及保留时长。

## 故障排查

| 显示内容 | 处理方法 |
| --- | --- |
| "This workspace isn't connected to a FailproofAI Cloud yet." | 由工作区管理员打开应用的 **Home** 标签页并选择一个 Cloud |
| "This link expired or was already used." | 在 **Home** 标签页重新选择您的 Cloud 以获取新链接 |
| "This org is already connected to a Slack workspace." | 请先在设置中断开连接 |
| "That Slack workspace is connected to another org." | 请先从该组织中断开该工作区 |
| "Link your account to use the assistant." | 点击按钮并在 Failproof AI 中确认 |
| 应用在群组直接消息中没有回应 | 重新将应用添加到 Slack 以授予群组权限，您的连接会保留 |
| "I won't post answers from your organization here" | 请让该工作区中属于该组织成员的某人提及该应用并关联其账户 |

仍有问题？请发送邮件至 [support@befailproof.ai](mailto:support@befailproof.ai)。
