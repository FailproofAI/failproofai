在 Slack 中使用 [failproof agent](/zh/sessions/assistant)。在频道中 @ 提及该应用、向其发送私信，或使用 `/failproof <问题>`。回答使用**您自己的** Failproof AI 权限，图表会出现在对话线程中，任何涉及变更的操作都会先请您审批。

目前只有一个官方应用，无论您的 Failproof AI Cloud 是托管版还是自托管版，使用方式完全相同。

<Note>
  回答由 AI 模型生成，可能存在不准确之处。重要内容请以关联的原始数据为准。
</Note>

## 连接工作区

您需要在 Failproof AI 中拥有 `settings:write` 权限，并且在 Slack 中是工作区管理员或所有者，或者是负责添加该应用的人员。

<Tabs>
  <Tab title="从 Failproof AI 连接">
    1. 进入 **设置 → 集成**，选择 **Add to Slack**。
    2. 在 Slack 中授权该应用。
    3. 返回 Failproof AI，确认将该工作区连接到您的组织。
  </Tab>
  <Tab title="从 Slack 连接">
    1. 添加应用后，打开其 **Home** 标签页。
    2. 选择 **Continue with FailproofAI Cloud**，或选择 **Use my own URL** 并输入您登录时使用的地址。
    3. 点击继续按钮，登录后选择组织并确认。该链接仅可使用一次，10 分钟后失效。
  </Tab>
</Tabs>

一个工作区只能连接一个组织，一个组织也只能连接一个工作区。

还没有账号？请先[注册](https://app.befailproof.ai/login)，再进行连接。

## 您在 Slack 中的身份

首次提问时，应用会通过以下方式确认您的身份：

- **自动通过电子邮件匹配**：当您是已连接工作区的正式成员、Slack 邮箱已验证，且组织中恰好只有一位成员使用该邮箱时，系统会自动完成匹配。
- **其他情况**：您会收到一个私人 **Link your account** 按钮，点击后将跳转至 Failproof AI 完成 Slack 账号与您账户的关联。

## 提问方式

| 场景 | 操作方式 |
| --- | --- |
| 频道 | @ 提及该应用。在其对话线程中回复即可继续，无需再次 @ |
| 私信 | 直接向该应用发送消息 |
| 包含该应用的群组私信 | @ 提及它，然后在其线程中回复以继续 |
| Slack Connect 频道 | @ 提及该应用 |
| 任何包含该应用的会话 | `/failproof <问题>` 将以回答开启一个对话线程 |
| `/failproof help` | 查看应用的功能说明 |
| `/failproof status` | 查看已连接的组织及您关联的账户身份 |
| `/failproof link` | 查看您关联的 Failproof AI 账户 |

一个线程对应一次对话。同事可以在同一线程中 @ 提及应用，应用会按各自的权限分别回答。只有发起该线程的人可以不用 @ 直接继续对话。

当回答涉及数据时，应用会发布图表或表格，并附上在 Failproof AI 中打开的链接。

## 审批变更

failproof agent 执行的每项变更都会先显示 **Approve** 和 **Cancel** 按钮，且 Slack 在 **Approve** 前会再次确认。只有提问的人才能响应这些按钮，按钮在 5 分钟后失效，变更将以该人员的权限执行。

在 Slack 中，failproof agent 可以在您具备相应权限的情况下，修改已保存的查询和仪表板、评估、告警、审计、洞察和策略，以及提出代码修复建议。它无法修改 API 密钥、用户或设置。

## 链接预览

在托管版 Failproof AI Cloud 中，粘贴到 Slack 的 Failproof AI 洞察、会话和评估链接会展开为卡片。卡片仅显示触发该预览的人员有权查看的内容。自托管地址的链接不会展开，但 failproof agent 自身回答中的卡片仍会正常显示。

## Slack Connect 频道

来自其他工作区的用户，只要是该组织的成员并已完成账户关联，即可使用该应用。回答对会话中的所有人可见，包括非组织成员，因此请注意在所有人都能看到答案的场景下提问。

只有当频道内其他所有工作区都有成员关联到该组织后，应用才会开始回答。在此之前，它会告知提问者原因。

## 应用申请的权限

| Slack 权限 | 用途 |
| --- | --- |
| `app_mentions:read` | 识别何时有人 @ 提及应用 |
| `channels:history`、`groups:history`、`im:history`、`mpim:history` | 接收私信及应用线程中的回复。应用会忽略其他消息，且不会读取会话的历史消息 |
| `channels:read`、`groups:read`、`im:read`、`mpim:read` | 判断当前会话类型，以确认回答的可见范围 |
| `chat:write` | 发布回答和审批按钮 |
| `commands` | 提供 `/failproof` 命令 |
| `files:write` | 发布图表 |
| `links:read`、`links:write` | 显示粘贴的 Failproof AI 链接预览 |
| `users:read`、`users:read.email` | 将您与 Failproof AI 账户匹配，以及显示用户名称 |

## 断开连接

进入 **设置 → 集成** 并选择 **Disconnect**，或在应用的 **Home** 标签页使用 **Disconnect**，或从 Slack 中移除该应用。

以上任意操作都会删除该工作区的连接、机器人令牌、已关联账户及对话线程记录。过去的 Slack 对话仍可在仪表板中查看。组织之后可以立即重新连接任意工作区。

## 数据与隐私

问答内容将以对话形式保存在您组织的仪表板中，归属于发起该线程的人员。Slack 数据不会用于训练 AI 模型。有关应用接收的数据及保留时长，请参阅[隐私政策](https://befailproof.ai/privacy/)。

## 故障排查

| 看到的提示 | 处理方式 |
| --- | --- |
| "This workspace isn't connected to a FailproofAI Cloud yet." | 由工作区管理员打开应用的 **Home** 标签页并选择一个 Cloud |
| "This link expired or was already used." | 在 **Home** 标签页重新选择您的 Cloud 以获取新链接 |
| "This org is already connected to a Slack workspace." | 请先在设置中断开现有连接 |
| "That Slack workspace is connected to another org." | 请先从该组织断开该工作区的连接 |
| "Link your account to use the assistant." | 点击按钮并在 Failproof AI 中确认 |
| 应用在群组私信中没有回应 | 重新将应用添加到 Slack 以授予其群组权限，您的连接会保留 |
| "I won't post answers from your organization here" | 由该工作区中属于该组织成员的人员 @ 提及应用并关联其账户 |
