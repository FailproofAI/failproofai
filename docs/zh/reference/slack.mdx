在 Slack 中使用 [Failproof 助手](/zh/sessions/assistant)。在频道中 @ 提及该应用、向其发送私信，或使用 `/failproof <问题>`。回答使用**您自己的** Failproof AI 权限，图表会出现在对话线程中，任何可能引发变更的操作都会先请您审批。

目前只有一个官方应用，无论您的 Failproof AI Cloud 是托管版还是自托管版，使用方式完全相同。

<Note>
  回答由 AI 模型生成，可能存在不准确之处。重要内容请以链接的原始数据为准。
</Note>

## 连接工作区

您需要在 Failproof AI 中拥有 `settings:write` 权限，以及在 Slack 中担任工作区管理员或所有者，或者是添加该应用的人员。

<Tabs>
  <Tab title="从 Failproof AI 操作">
    1. 前往 **设置 → 集成**，选择 **添加到 Slack**。
    2. 在 Slack 中授权该应用。
    3. 返回 Failproof AI，确认将工作区连接到您的组织。
  </Tab>
  <Tab title="从 Slack 操作">
    1. 添加该应用，然后打开其 **主页** 选项卡。
    2. 选择 **继续使用 FailproofAI Cloud**，或选择 **使用我的自定义地址** 并输入您登录时使用的地址。
    3. 点击继续按钮，登录后选择组织并确认。该链接仅可使用一次，10 分钟后失效。
  </Tab>
</Tabs>

一个工作区连接一个组织，一个组织也只能连接一个工作区。

还没有账户？请先[创建一个](https://app.befailproof.ai/login)，再进行连接。

## 您在 Slack 中的身份识别

首次提问时，应用会自动确认您的成员身份：

- **通过邮箱自动匹配**：当您是已连接工作区的正式成员、Slack 邮箱已验证，且组织中恰好只有一位成员使用该邮箱时，系统会自动完成匹配。
- **其他情况**：您会收到一个私密的 **关联账户** 按钮，点击后将跳转至 Failproof AI，并将您的 Slack 用户与账户进行关联。

## 提问方式

| 场景 | 操作方式 |
| --- | --- |
| 频道 | @ 提及应用。在其对话线程中回复即可继续，无需再次 @ |
| 私信 | 直接向应用发送消息 |
| 应用所在的群组私信 | @ 提及应用，之后在线程中回复即可继续 |
| Slack Connect 频道 | @ 提及应用 |
| 应用所在的任意对话 | `/failproof <问题>` 将开启一个包含回答的线程 |
| `/failproof help` | 查看应用的功能说明 |
| `/failproof status` | 查看已连接的组织及您的关联身份 |
| `/failproof link` | 查看您关联的 Failproof AI 账户 |

一个线程对应一段对话。同事可以在同一线程中 @ 提及应用，它会根据各自的权限分别作出回答。只有发起该线程的人可以在不 @ 应用的情况下继续对话。

当回答涉及数据时，应用会发布图表或表格，并附上在 Failproof AI 中打开的链接。

## 审批变更

助手执行的每一项变更都会先显示 **审批** 和 **取消** 按钮，且 Slack 在 **审批** 前会再次确认。只有提问者才能响应这些按钮，按钮在 5 分钟后失效，变更将以该用户的权限执行。

在 Slack 中，助手可对已保存的查询与仪表板、评估、告警、审计、问题和策略进行变更，并可在您拥有相应权限时提供代码修复建议。它无法变更 API 密钥、用户或系统设置。

## 链接预览

在托管版 Failproof AI Cloud 中，粘贴到 Slack 的 Failproof AI 问题、会话和评估链接会展开为卡片。卡片仅显示触发该链接的用户有权查看的内容。自托管地址的链接不会展开，但助手自身回答中的卡片仍会正常显示。

## Slack Connect 频道

其他工作区的人员在关联账户后，只要是组织成员，即可使用该应用。回答对话中的所有人可见，包括不属于您组织的人员，因此请在提问时注意回答的可见范围。

只有在该频道中所有其他工作区都有成员关联到组织后，应用才会开始回答。在此之前，它会告知提问者原因。

## 应用申请的权限

| Slack 权限 | 用途 |
| --- | --- |
| `app_mentions:read` | 识别何时有人 @ 提及应用 |
| `channels:history`、`groups:history`、`im:history`、`mpim:history` | 接收私信及应用线程中的回复。应用会忽略其他消息，且不会读取对话的历史记录 |
| `channels:read`、`groups:read`、`im:read`、`mpim:read` | 检测对话类型，以确认回答的可见范围 |
| `chat:write` | 发布回答和审批按钮 |
| `commands` | 提供 `/failproof` 命令 |
| `files:write` | 发布图表 |
| `links:read`、`links:write` | 显示粘贴的 Failproof AI 链接预览 |
| `users:read`、`users:read.email` | 将您与 Failproof AI 账户匹配，并显示姓名 |

## 断开连接

前往 **设置 → 集成** 并选择 **断开连接**，或在应用的 **主页** 选项卡上使用 **断开连接**，或直接从 Slack 中移除该应用。

以上任意操作都会删除该工作区的连接信息、机器人令牌、已关联账户及线程记录。过去的 Slack 对话仍可在仪表板中查看。之后，组织可立即连接任意工作区。

## 数据与隐私

问题和回答会作为对话保存在您组织的仪表板中，归属于发起线程的用户。Slack 数据不会用于训练 AI 模型。如需了解应用接收的数据内容及保存时长，请参阅[隐私政策](https://befailproof.ai/privacy/)。

## 故障排查

| 您看到的内容 | 解决方法 |
| --- | --- |
| "此工作区尚未连接到 FailproofAI Cloud。" | 工作区管理员打开应用的 **主页** 选项卡进行选择 |
| "此链接已过期或已被使用。" | 在 **主页** 选项卡上重新选择您的 Cloud 以获取新链接 |
| "该组织已连接到一个 Slack 工作区。" | 请先在设置中断开连接 |
| "该 Slack 工作区已连接到其他组织。" | 请先从该组织断开连接 |
| "请关联您的账户以使用助手。" | 点击按钮并在 Failproof AI 中确认 |
| 应用在群组私信中无响应 | 重新将应用添加到 Slack 以授予群组权限，您的连接将保留 |
| "我不会在此处发布来自您组织的回答" | 该工作区中属于组织成员的人员 @ 提及应用并关联其账户 |
