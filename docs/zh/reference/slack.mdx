在 Slack 中使用 [Failproof 助手](/zh/sessions/assistant)。在频道中 @ 该应用、直接向其发送消息，或使用 `/failproof <问题>`。回答将使用**您自己的** Failproof AI 权限，图表会出现在话题中，任何涉及变更的操作都需要您先审批。

只有一个官方应用，无论您的 Failproof AI Cloud 是托管版还是自托管版，使用方式完全相同。

<Note>
  回答由 AI 模型生成，可能存在不准确之处。如有重要信息，请对照关联的源数据进行核实。
</Note>

## 连接工作区

您需要在 Failproof AI 中拥有 `settings:write` 权限，并且在 Slack 中是工作区管理员或所有者，或者是添加该应用的人。

<Tabs>
  <Tab title="从 Failproof AI 连接">
    1. 前往 **设置 → 集成**，选择 **添加到 Slack**。
    2. 在 Slack 中授权该应用。
    3. 返回 Failproof AI，确认将工作区连接到您的组织。
  </Tab>
  <Tab title="从 Slack 连接">
    1. 添加应用后，打开其 **主页** 标签。
    2. 选择 **使用 FailproofAI Cloud 继续**，或选择 **使用我自己的 URL** 并输入您登录时使用的地址。
    3. 点击继续按钮，登录，选择组织并确认。该链接仅可使用一次，且在 10 分钟后过期。
  </Tab>
</Tabs>

一个工作区只能连接到一个组织，一个组织也只能连接到一个工作区。

还没有账户？请先[创建一个](https://app.befailproof.ai/login)，再进行连接。

## 您在 Slack 中的身份

首次提问时，应用会自动识别您的身份：

- **通过邮箱自动识别**：当您是已连接工作区的正式成员、Slack 邮箱已验证，且组织中恰好只有一个成员使用该邮箱时，系统会自动匹配。
- **其他情况下**，您会收到一个私密的 **关联账户** 按钮，点击后将跳转至 Failproof AI，将您的 Slack 用户与账户关联。

## 提问方式

| 位置 | 方式 |
| --- | --- |
| 频道 | @ 提及该应用。在其话题中回复即可继续对话，无需再次提及 |
| 直接消息 | 直接向该应用发送消息 |
| 已加入该应用的群组直接消息 | 提及它，然后在其话题中回复以继续对话 |
| Slack Connect 频道 | 提及该应用 |
| 应用所在的任何对话 | `/failproof <问题>` 将开启一个包含回答的话题 |
| `/failproof help` | 查看应用的功能说明 |
| `/failproof status` | 查看已连接的组织以及您关联的身份 |
| `/failproof link` | 查看您关联的 Failproof AI 账户 |

一个话题即一次对话。同事可以在同一话题中 @ 该应用，它会根据每个人各自的权限进行回答。只有开启该话题的人可以在不 @ 的情况下继续对话。

当回答涉及数据时，应用会发布图表或表格，并附上在 Failproof AI 中打开的链接。

## 审批变更

助手执行的每项变更都会先显示 **审批** 和 **取消** 按钮，且 Slack 在执行 **审批** 前会再次确认。只有提问的人才能操作这些按钮，按钮在 5 分钟后失效，变更将以该人的权限执行。

在 Slack 中，助手可以修改已保存的查询和仪表板、评估、告警、审计、问题及策略，以及提出代码修复建议——前提是您拥有相应权限。助手无法修改 API 密钥、用户或设置。

## 链接预览

在已托管的 Failproof AI Cloud 中，粘贴到 Slack 的 Failproof AI 问题、会话和评估链接会自动展开为卡片。卡片仅显示触发预览的人有权查看的内容。指向自托管地址的链接不会展开，但助手自身回答中的卡片仍会正常显示。

## Slack Connect 频道

来自其他工作区的人在关联账户后，如果是组织成员，即可使用该应用。回答对对话中的所有人可见，包括非组织成员，因此请在所有人都可能看到答案的场合进行提问。

该应用仅在频道中所有其他工作区都有成员关联到组织后才会回答。在此之前，应用会告知提问者原因。

## 应用申请的权限

| Slack 权限 | 用途 |
| --- | --- |
| `app_mentions:read` | 获知有人提及该应用 |
| `channels:history`、`groups:history`、`im:history`、`mpim:history` | 接收直接消息及应用话题中的回复。应用会忽略其他消息，且不会读取对话的历史记录 |
| `channels:read`、`groups:read`、`im:read`、`mpim:read` | 检查对话类型，以便了解谁可以看到回答 |
| `chat:write` | 发布回答和审批按钮 |
| `commands` | 提供 `/failproof` 命令 |
| `files:write` | 发布图表 |
| `links:read`、`links:write` | 显示粘贴的 Failproof AI 链接预览 |
| `users:read`、`users:read.email` | 将您与 Failproof AI 账户匹配，并显示名称 |

## 断开连接

前往 **设置 → 集成** 并选择 **断开连接**，或在应用 **主页** 标签中使用 **断开连接**，或直接从 Slack 中移除该应用。

以上任意操作都会删除工作区的连接、bot 令牌、已关联账户及话题记录。过往的 Slack 对话仍可在仪表板中查阅。之后，该组织可以立即连接任意工作区。

## 数据与隐私

问答内容将作为对话保存在您组织的仪表板中，归属于开启该话题的人。Slack 数据不会用于训练 AI 模型。有关应用接收哪些数据及保留时长，请参阅[隐私政策](https://befailproof.ai/privacy/)。

## 故障排查

| 显示内容 | 处理方式 |
| --- | --- |
| "此工作区尚未连接到 FailproofAI Cloud。" | 工作区管理员打开应用的 **主页** 标签并选择一个 Cloud |
| "此链接已过期或已被使用。" | 在 **主页** 标签中重新选择您的 Cloud 以获取新链接 |
| "此组织已连接到一个 Slack 工作区。" | 请先在设置中断开连接 |
| "该 Slack 工作区已连接到另一个组织。" | 请先从该组织断开连接 |
| "请关联您的账户以使用助手。" | 点击按钮并在 Failproof AI 中确认 |
| 应用在群组直接消息中没有回应 | 重新将应用添加到 Slack 以授予其群组权限，您的连接将被保留 |
| "我不会在此处发布来自您组织的回答" | 该工作区中某位组织成员需提及该应用并关联其账户 |
