从以下命令开始：

```bash
failproofai config --status
failproofai policies
```

## 代理未连接

重新运行设置：

```bash
failproofai config
```

设置支持 Linux 和 macOS。安装服务时需要一次管理员权限，但不会提示输入 sudo 密码。

请在[执行环境](/zh/reference/harnesses)中查看执行路径和作用域。

## 会话丢失

```bash
failproofai flush --wait
failproofai backfill --since 30d --dry-run
failproofai harness list
```

去掉 `--dry-run` 可重新发送历史记录。使用以下命令添加新的记录文件位置：

```bash
failproofai harness add-path <harness> [label=]<path>
```

当两个位置包含同一项目的副本时，请使用标签加以区分。

## 所有受保护操作均被拒绝

在已配置的机器上，`failproofaid` 是唯一的评估器。如果它无法响应，受保护的操作将以拒绝方式关闭。

```bash
failproofai config --status
systemctl status failproofaid@$USER        # Linux
sudo launchctl print system/ai.failproof.failproofaid.$USER  # macOS
```

运行 `failproofai config` 来修复或重新安装服务。

## 某个策略包在拒绝请求

`failproofai policies` 会列出无法加载的策略包。已选择的策略包在无法加载时会以拒绝方式关闭，而不是直接消失。

常见原因：

- 构件在安装后被修改。
- 清单与捆绑的策略不一致。
- 文件丢失或无法导入。
- 该策略包使用了不支持的事件、工具或策略形式。

移除该策略包，或安装修正后的版本：

```bash
failproofai policies remove owner/repo
failproofai policies add owner/repo@<release>
```

## 云端连接断开

建议通过环境变量设置密钥：

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
failproofai config --status
```

机器可以独立地拉取策略和发送活动记录。状态命令会分别报告两者的状态。

## 某条策略未能拦截

请检查以下三点：

1. 该策略已启用：运行 `failproofai policies` 确认。
2. 其事件和工具与该操作相匹配。
3. 该执行环境能够执行此事件。

工具调用拒绝已在全部 12 个支持的执行环境上得到验证。其他事件因环境而异。请参阅[执行能力](/zh/reference/harnesses#enforcement-capability)。

## 下载被阻止

- `FAILPROOFAI_NO_DOWNLOAD=1` 会拒绝网络下载。
- `FAILPROOFAI_DAEMON_BASE_URL` 将服务下载指向镜像地址。
- `FAILPROOFAI_PACK_BASE_URL` 将策略包下载指向镜像地址。

下载被禁用时，已安装的策略包仍会继续执行。
