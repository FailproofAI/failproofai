Failproof AI 云端助手可以用自然语言回答有关您的 Agent 集群的问题。它能够分析会话和故障、执行查询、构建仪表板、调查评估和告警，以及帮助创建和运行审计——无需您将任务翻译成产品界面操作或 CLI 命令。在仪表板中，该控件标记为 **Open agent chat**；在 [`fp` CLI](/zh/reference/cloud-cli) 中，对应的是 `fp agent` 命令组。

```text
Why did production checkout agents regress this week?
Build a dashboard for tool failures, latency, and evaluation scores.
Create an audit that finds agents retrying the same failed action without changing approach.
Show me the sessions behind the most common audit finding.
```

该助手使用当前组织内可用的数据和权限进行工作。在应用会影响其他用户或 Agent 的操作之前，请仔细审查其依据和建议的变更。

<Note>
  该助手在仪表板中运行，其对话归属于具体用户，因此没有可供 API 密钥调用的 API 路由。每个 `fp agent` 子命令都需要已登录的会话（`fp login`）和 `agent:use` 权限，并且在使用 `--api-key` 或 `FP_API_KEY` 时会以退出码 2 退出。API 密钥永远无法访问该助手，因此定时任务必须通过 `--token` 或 `FP_TOKEN` 携带已登录的会话令牌。这是可行的——当没有 TTY 时，`fp agent ask` 会从 stdin 读取问题——但会话令牌在 `fp login` 后约 24 小时过期，这使得该助手不适合用于无人值守的自动化场景，即便它可以运行。
</Note>

## 向助手提问

<Tabs>
  <Tab title="仪表板">
    1. 点击 **Open agent chat**，描述您想了解、创建或操作的内容。
    2. 在助手工作时，查看其工具调用、数据表格和查询结果。
    3. 打开引用的会话、告警或查询，对照源数据验证结果。
    4. 针对不同的调查启动新对话，或利用历史记录继续同一条分析线索。

    ![The Cloud assistant answering an observability question with supporting analysis and queries.](/images/dashboard/assistant.png)
  </Tab>
  <Tab title="CLI">
    从 `health` 命令开始。它会报告该部署是否启用了助手，以及是否为其配置了 LLM。若没有配置 LLM，`ask` 会失败，`models` 不会返回任何结果——而 `chats`、`show`、`rename` 和 `delete` 完全不依赖 health 检查，始终可以正常工作。

    ```bash
    fp agent health
    fp agent models
    fp agent ask "Which production checkout agents had the most tool errors in the last 24 hours?"
    ```

    `fp agent models` 列出该部署允许使用的模型及默认模型。通过 `ask --model <name>` 指定模型。使用 `--page-context <text>` 为回答提供已有的文本背景，当问题来自文件或上一条命令时，可通过 stdin 管道传入，而不必作为参数传递：

    ```bash
    cat incident-notes.md | fp agent ask --model <model>
    ```

    每次提问都会保存到一个对话中。不带 `--chat` 时会新建对话并打印其短 ID；带 `--chat` 时会继续该对话线程。

    ```bash
    fp agent chats
    fp agent show <chat-id>
    fp agent ask "Open representative sessions" --chat <chat-id>
    fp agent rename <chat-id> --title "checkout regression"
    fp agent delete <chat-id> --yes
    ```

    `fp agent chats` 以 `chat-id · title · messages · updated` 的格式按最新优先列出您的对话，其中 `updated` 表示对话最后活跃的时间。显示的 `chat-id` 是短格式——即前 8 个字符——`show`、`rename`、`delete` 和 `ask --chat` 均支持该前缀匹配。若 ID 未匹配到任何内容，则以退出码 6 退出并显示 `chat not found` 提示；若匹配到多个，则提示输入更长的前缀。

    `fp agent delete` 默认会先确认。`--yes` 可跳过确认提示，非交互式调用时同样会跳过：在 `--json` 模式下，或当 stdin 被重定向时，命令会直接执行而不询问。
  </Tab>
</Tabs>

## 高效使用助手

- 先给出目标；当环境、工作流或时间范围有限定意义时，再添加这些约束条件。
- 将生成的 SQL 和摘要作为调查辅助工具，而非最终证据。
- 在创建审计、问题单、告警或策略之前，先打开有代表性的会话查看。
- 明确指定组织、环境和时间过滤条件。
- 将有用的 SQL 保存为查询，以便其他操作员复现结果。

<Warning>
  权限控制分为两层，且失败方式不同。`agent:use` 控制功能本身的访问：没有该权限，`fp agent` 和仪表板对话将不可用。在此之上，回答内容还受到已登录用户的数据权限约束——包括 `events:read`、`evaluations:read`、`queries:run`、`policies:read`——因此即使用户能打开助手，对于无权读取的数据仍可能获得空回答。请勿为了让某个问题可用而扩大权限；应让有权限的操作员来执行相关调查。参见[密钥与权限](/zh/admin/keys-and-permissions)。
</Warning>
