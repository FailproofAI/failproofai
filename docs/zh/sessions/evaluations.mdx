评估对 Agent 会话进行一致性判断。适用于需要持续测量而非仅在审计时才调查的信号。

评估器接收已完成的会话，即以下两种情况之一：会话发出了结束事件，或者停止发出事件的时间超过了评估器的 `inactivity_timeout_secs`。对仍在运行中的会话不进行评分。

<Note>
  自动评估是部署范围内的，在运营者设置 `EVALUATOR_ENDPOINT` 之前始终处于关闭状态。在此之前，此视图为空，`fp evals` 不返回任何内容，`fp sessions` 的每一行状态均显示为空白——这通常意味着未配置评估器，而非评分结果不佳。请参阅 [Evaluator SDK](/zh/reference/evaluator-sdk)。
</Note>

## 查看评估质量

<Tabs>
  <Tab title="Dashboard">
    1. 前往 **Observe → Evaluations**。
    2. 添加系列并选择 Agent、环境、评估分数、统计量和曲线。
    3. 添加系列以比较不同环境、Agent 或分数键。
    4. 选择结果以打开匹配的会话或共享过滤视图。使用 **Observe → Metrics** 查看延迟、Token、成本及其他量级值。

    ![显示平均评估分数及随时间变化趋势的质量仪表板。](/images/dashboard/dashboard-quality.png)

    从下钻视图中打开会话，可查看其各项分数的推理过程：

    ![会话详情视图，在完整追踪记录旁显示评估分数和推理过程。](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp list score_filters
    fp evals --agent-id checkout-agent --aggregate
    fp evals --aggregate --status error --since 7d
    fp evals --score helpfulness:0.5..0.8 --score tool_efficiency:..0.3 --since 7d
    fp evals --scores-full --since 24h
    ```

    以上所有操作均需要 `evaluations:read` 权限——包括 `fp sessions`，它读取相同的最新评估结果。这就是为什么仅限 `events:read` 的密钥可以看到追踪记录但无法看到分数。

    从 `fp list score_filters` 开始：它返回该部署实际生成的分数键，这样 `--score` 过滤器就有据可查，而不是凭空猜测。

    `--score KEY:MIN..MAX` 中每个边界均可省略且可重复使用，所有范围需同时满足：`helpfulness:0.5..0.8`、`tool_efficiency:..0.3`、`factuality:0.9..`。格式错误的值会在发送请求前被拒绝，而非被静默忽略。`--status` 仅接受 `done`、`error` 或 `timeout` 之一。`--scores-full` 打印所有分数对，而非仅显示前几个加上 `+N`。`--all` 在达到 `--limit` 时停止，默认值为 50。

    全局选项位于命令之前，因此自动化脚本使用 `fp --json evals --aggregate`。

    除非修改，否则守护进程会将每个事件标记为 `local` 环境，因此 `--env production` 在默认安装中不会匹配任何内容。请参阅[更改环境标签](/zh/reference/events-and-configuration#change-an-environment-label)。
  </Tab>
</Tabs>

## 评估器的数据交换

| 消息 | 字段 |
| --- | --- |
| `EvalRequest`（入） | `schema_version`（当前为 `"1"`）、`session_id`、`agent_id`、`environment`、`started_at`、`ended_at` 以及 `events`——完整的有序事件流，每个事件携带其完整负载。 |
| `EvalResponse`（出） | `scores`（数值键）、`reasoning`（与 scores 对应的键）以及 `summary`。 |
| `JobPending`（出） | `job_id` 和 `next_poll_secs`，适用于无法在单次请求内完成的工作。 |

仅当会话发出结束事件时才会有 `ended_at`，因此因不活跃而触发的会话到达时没有该字段。轮询频率依次遵循 `next_poll_secs`、评估器的 `default_poll_interval_secs`、服务器的 `EVALUATOR_POLLING_INTERVAL_SECS`，限制在 1 秒到 1 小时之间，总挂钟时间上限为 1 小时。

由于请求携带完整的事件负载，评估器可以看到完整的对话内容。在决定机器可以发送哪些数据时，请将评估器的数据传输视同对话内容的传输来处理。

## 良好的评估目标

- 任务完成度或正确性
- 可溯源性与幻觉风险
- 工具选择与使用效率
- 政策或流程合规性
- 成本与延迟预算
- 必要的人工升级处理

分数键是稳定的标识符。重命名一个分数键会开始一个新的图表系列，而不会更改旧的系列，这会悄然破坏趋势数据——在绘制图表之前确定好名称。

## 从分数到响应

在仪表板中展示分数以跟踪趋势。为阈值或复合条件创建告警。当某个分数在整体用户群中下降时，运行审计以调查原因；当原因是某个可重复的操作时，部署相应的策略。
