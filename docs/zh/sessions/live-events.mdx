实时事件帮助你确认埋点是否生效，并在不等待会话结束的情况下实时监控高风险运行。

## 观察活动

<Tabs>
  <Tab title="控制台">
    1. 前往 **Observe → Events**。
    2. 以当前时间窗口且不设任何过滤器开始，确认数据正在到达。
    3. 按环境、事件类型、agent 或会话进行过滤。使用搜索功能查找 payload 文本。
    4. 选择某个事件以查看其摘要和详情。通过其会话链接查看完整追踪。

    ![带有时间、环境、事件类型、agent、模型、上下文、会话和文本过滤器的实时 Events 流。](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    默认数据流不包含原始 payload。仅在对有限范围的会话进行排查时使用 `--full`。
  </Tab>
</Tabs>

使用事件流来即时回答以下三个问题：

- 预期的 agent 是否在向正确的环境上报？
- 模型调用、工具调用和策略决策是否按顺序到达？
- 会话是否已停止推进，或开始重复执行某个操作？

事件类型包括：agent 生命周期事件、模型请求与响应、工具使用及结果、hook 执行、人工等待与中断，以及显式错误。关联 ID 将成对的事件（如工具调用及其结果）关联在一起。

<Tip>
  在验证新集成时，保持实时视图不设过滤条件。看到第一个事件后再添加过滤器——错误的过滤条件可能让你误以为是数据采集失败。
</Tip>

如果没有任何事件出现，请运行 `failproofai config --status`，然后参阅[排查数据采集问题](/zh/reference/troubleshooting)。
