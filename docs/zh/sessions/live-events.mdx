实时事件帮助你确认埋点是否正常，并在不等待会话结束的情况下监控高风险运行。

## 查看活动

<Tabs>
  <Tab title="控制台">
    1. 进入 **Observe → Events**。
    2. 从当前时间窗口开始，不添加任何过滤器，确认数据正在到达。
    3. 按环境、事件类型、Agent 或会话进行过滤。使用搜索功能查找 payload 文本。
    4. 选择某个事件查看其摘要和详情。点击会话链接查看完整追踪记录。

    ![实时事件流，显示来自 Hermes 聊天网关的流量以及编码 CLI 运行记录，可按时间、环境、事件类型、Agent、模型、上下文和会话进行过滤。](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    默认输出不包含原始 payload。仅在对有限会话进行排查时使用 `--full`。
  </Tab>
</Tabs>

使用事件流可以快速回答以下三个问题：

- 预期的 Agent 是否正在向正确的环境上报数据？
- 模型调用、工具调用和策略决策是否按顺序到达？
- 会话是否停止了进展，或者开始重复某个操作？

事件类型包括：Agent 生命周期事件、模型请求与响应、工具调用与结果、hook 执行、人工等待与中断，以及显式错误。关联 ID 用于连接成对的事件，例如工具调用及其对应结果。

<Tip>
  在验证新集成时，建议保持实时视图的宽泛范围。看到第一个事件后再添加过滤器——错误的过滤条件可能看起来像是数据采集失败。
</Tip>

如果没有事件出现，请运行 `failproofai config --status`，然后参阅[排查数据采集问题](/zh/reference/troubleshooting)。

未在 12 种受支持的[运行环境](/zh/reference/harnesses)之一中运行的 Agent，可以通过 [Python SDK](/zh/reference/custom-agents) 上报相同的事件类型，包括网关和生产环境 Agent 所依赖的人机交互事件（`human_wait`、`human_input`、`human_interrupt`）。
