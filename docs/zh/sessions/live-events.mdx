实时事件可帮助你确认埋点是否正常，并在不等待会话结束的情况下监控高风险的运行过程。

## 监控活动

<Tabs>
  <Tab title="控制台">
    1. 前往 **Observe → Events**。
    2. 先使用当前时间窗口且不设任何过滤条件，确认数据正在正常接入。
    3. 按环境、事件类型、agent 或会话进行过滤，也可使用搜索功能查找 payload 文本。
    4. 选择某个事件以查看其摘要和详情，点击会话链接可查看完整追踪记录。

    ![实时 Events 流，展示来自 Hermes 聊天网关及编程 CLI 运行的流量，可按时间、环境、事件类型、agent、模型、上下文和会话进行过滤。](/images/dashboard/events-stream-current.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp events --env production --event-type tool_use,error --limit 100
    fp events --session-id <session-id> --order asc --all
    fp --json events --full --session-id <session-id> --all
    ```

    默认数据流不包含原始 payload。请仅在针对有限范围的会话进行排查时使用 `--full`。
  </Tab>
</Tabs>

使用事件流可即时回答以下三个问题：

- 预期的 agent 是否在向正确的环境上报数据？
- 模型调用、工具调用和策略决策是否按顺序到达？
- 会话是否已停止推进，或开始重复某个操作？

事件类型包括：agent 生命周期事件、模型请求与响应、工具使用及结果、hook 执行、人工等待与中断，以及显式错误。关联 ID 会将成对事件（如工具调用与其结果）串联起来。

<Tip>
  在验证新集成时，建议先保持实时视图的宽泛过滤。待看到第一个事件后再添加过滤条件——错误的过滤条件可能会让数据接入问题看起来像是采集失败。
</Tip>

若没有事件出现，请运行 `failproofai config --status`，然后参阅[排查数据接入问题](/zh/reference/troubleshooting)。

未运行在 12 种受支持的 [harnesses](/zh/reference/harnesses) 之一中的 agent，可通过 [Python SDK](/zh/reference/custom-agents) 上报相同类型的事件，包括网关和生产环境 agent 所依赖的人机协作事件（`human_wait`、`human_input`、`human_interrupt`）。
