当 Agent 行为异常时，会话是最佳的排查起点。它将属于同一次运行的模型请求、响应、工具调用、人工交互、错误、评估以及策略决策汇聚在一起。

无论由哪种运行框架产生，会话的格式都保持一致。在 Claude Code 中重写代码仓库的运行、在 Slack 中回复客户的 Hermes Agent，以及通过 SDK 埋点的 Python 服务，都会落入相同的追踪格式，因此一个视图即可覆盖整个 Agent 群。

跟踪一次 Agent 运行，从目标出发，经历模型调用、工具使用，直至最终响应。

## 查找会话

<Tabs>
  <Tab title="控制台">
    1. 在 Cloud 侧边栏中，前往 **Observe → Sessions**。
    2. 设置时间范围，然后按环境、状态、Agent 或会话 ID 进行筛选。
    3. 当需要按质量、成本、Token 或延迟切片时，添加分数或指标范围。
    4. 选择某一行以打开其追踪。分享时可使用会话 ID 旁边的复制按钮。

    ![会话列表，每次运行显示一行，包含环境、Agent、状态和评估分数筛选器。](/images/dashboard/sessions-list.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp sessions --env production --since 24h
    fp sessions --status error,timeout --agent-id checkout-agent
    fp --json sessions --session-id <session-id>
    ```

    添加 `--agents` 可展开多 Agent 运行，`--all` 可翻页，`--fields` 可选择输出列。
  </Tab>
</Tabs>

## 你可以做什么

- 按 Agent、环境、时间、模型、事件类型或错误状态查找运行记录。
- 追踪产生某一结果的精确执行序列。
- 对比成功与失败的运行。
- 打开审计发现或告警事件所依据的原始证据。
- 在需要离线记录时导出会话。

## 可靠的排查顺序

1. 确认会话目标和运行环境。
2. 找到第一个错误或意外决策——而不仅仅是最终的失败点。
3. 检查错误发生之前的模型上下文和工具输入。
4. 检查重试次数、延迟和人工中断情况。
5. 查看评估分数和策略决策。
