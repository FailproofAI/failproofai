追踪记录是一次 agent 运行的时间轴。从第一个意外事件入手，而不是从最终报错开始。

<Tabs>
  <Tab title="控制台">
    1. 打开 **Observe → Sessions**。
    2. 选择一个会话。
    3. 扫描第一个错误、异常工具调用、长时间等待或策略决策。
    4. 打开该事件，检查请求、响应、输入和输出。

    ![会话详情视图，包含执行图、事件时间轴、评估面板，以及工具、模型和 hook 的分类统计。](/images/dashboard/session-detail.png)
  </Tab>
  <Tab title="CLI">
    ```bash
    fp --json sessions --session-id <session-id>
    fp events --session-id <session-id> --order asc --all --limit 5000
    fp --json events --full --session-id <session-id> --all --limit 2000
    ```

    仅在事件摘要信息不足时使用 `--full`。`next_cursor` 非空表示在到达末尾之前已达到数量上限。
  </Tab>
</Tabs>

## 沿着证据追踪

1. 确认 agent、目标、环境和最终结果。
2. 找到第一个错误或意外决策。
3. 检查紧接其前的那个事件。
4. 通过匹配 ID 关联请求与响应对。
5. 将证据转化为审计记录、问题报告或策略。

| 配对类型 | 匹配字段 |
| --- | --- |
| 模型请求与响应 | `request_id` |
| 工具调用与结果 | `tool_call_id` |
| Hook 启动与完成 | `hook_id` |
| Agent 暂停与恢复 | `pause_id` |
| 人工等待与输入 | `input_id` |

决策结果显示在 `hook_completed` 上，该行记录了最终结论和策略来源。观察模式下的决策会显示为 allow，同时将本应生效的判定记录在 `failproofai_observed` 中。

<Warning>
  会话时长较长并不总是意味着模型延迟。在决定如何修复之前，请先分别统计模型、工具、hook 和人工等待各自占用的时间。
</Warning>
