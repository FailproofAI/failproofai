Jev 对用户发送给 agent 的每条消息，从 0 到 100 进行四种情绪评分——**愤怒**、**沮丧**、**高兴**和**困惑**——以及三个关于 agent 表现的信号：

- **纠正**：用户指出 agent 犯了错误。
- **已解决**：用户确认 agent 解决了他们的问题。
- **存疑**：用户质疑 agent 的回答是否准确，或者 agent 是否真正完成了工作。

使用情感分析可以发现用户耐心正在消耗的对话、被频繁纠正的 agent，以及反响良好的回复。这是内置的 Jev 评分功能，无需自行编写评估。如需针对固定答案的问题进行评估，请[创建 Jev 评估](/zh/evaluations/jev)。

<Note>
  情感分析默认关闭，需由管理员在组织级别开启。Jev 对每条消息发起一次评分请求，并在评分时获取该消息及其前一条 agent 回复。评分消耗组织的模型预算。
</Note>

## 开启情感分析

1. 前往 **Administration → Settings**。
2. 在 **Human input sentiment** 下，将其切换为**开启**并保存。

系统将优先对过去一天的消息进行评分。之后，新消息将在到达后的一两分钟内完成评分。

## 查找待审查的对话

打开 **Observe → Sentiment**。可按时间、环境、agent 或会话 ID 进行筛选。顶部统计栏显示消息和会话数量、**已标记**的消息数量，以及最主要的信号类型。当愤怒、沮丧、纠正、困惑或存疑分数达到 100 分中的 35 分时，该消息将被标记。

![情感分析仪表盘，显示消息和会话数量、已标记消息以及随时间变化的 Jev 评分。](/images/dashboard/sentiment-overview.png)

使用 **Score over time** 对比各信号。选择要展示的评分维度，然后点击某个时间点查看该时间段内的消息。**By agent** 表格展示信号的集中分布情况。在 **Messages** 中，可按最强负面评分排序，或选择单一评分维度。在会话中打开某条消息，阅读上下文对话，再判断问题所在。

![按最强负面评分排序的情感消息列表，附有指向各来源会话的链接。](/images/dashboard/sentiment-messages.png)

## 哪些消息会被评分

仅对用户本人撰写的消息评分：

- 通过 SDK 以人工输入方式记录的自定义 agent 消息。
- 在 Claude Code、Codex、OpenCode、pi、Hermes 和 OpenClaw 中输入的提示词（在发送会话记录时，即默认情况下）。定时任务、注入的指令、子 agent 交接及 agent 运行时自动生成的文本不在评分范围内。非交互式运行（如 `claude -p`、`codex exec` 和 `hermes -z`）同样不被评分——这些提示词由脚本生成，而非真人输入。

评分仅针对用户自身的表达。简短直白的指令（如"修好它"）不会被判定为愤怒，提问也不会被判定为困惑。新请求不构成纠正，单纯表达感谢也不计为已解决。
