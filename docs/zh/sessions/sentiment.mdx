Jev 对用户发送给 Agent 的每条消息，从 0 到 100 对四种情绪进行评分——**愤怒**、**沮丧**、**高兴**和**困惑**——以及三个反映 Agent 表现的信号：

- **纠正**：用户指出 Agent 给出了错误的回答。
- **已解决**：用户确认 Agent 解决了他们的问题。
- **存疑**：用户质疑 Agent 的回答是否正确，或是否真正完成了任务。

利用情感分析，可以找出用户逐渐失去耐心的对话、频繁被纠正的 Agent，以及表现良好的回复。这是 Jev 的内置评分功能，无需自行编写评估。如需针对固定答案问题创建评估，请[创建 Jev 评估](/zh/evaluations/jev)。

<Note>
  情感分析默认关闭，需由管理员在组织层面开启。Jev 对每条消息发起一次评分请求，并在评分时获取该消息及其前一条 Agent 回复。评分将消耗组织的模型预算。
</Note>

## 开启情感分析

1. 进入 **Administration → Settings**。
2. 在 **Human input sentiment** 下，将其切换为**开启**并保存。

最近一天的消息将优先被评分。此后，新消息将在到达后一两分钟内完成评分。

## 查找待审阅的对话

打开 **Observe → Sentiment**。可按时间、环境、Agent 或会话 ID 进行筛选。页头显示消息数和会话数，并标注**已标记**的消息数量及最主要的信号。当愤怒、沮丧、纠正、困惑或存疑任一评分达到 100 分中的 35 分时，该消息将被标记。

![情感分析仪表板，显示消息和会话数量、已标记消息以及随时间变化的 Jev 评分。](/images/dashboard/sentiment-overview.png)

使用 **Score over time** 对比各信号趋势。选择要显示的评分维度，然后点击某个时间点查看该时间段内的消息。**By agent** 表格展示信号集中分布的 Agent。在 **Messages** 中，可按最强负面评分排序，或选择单一评分维度。在会话中打开某条消息，可查看其上下文对话，再判断问题所在。

![情感消息列表，按最强负面评分排序，并附有指向各来源会话的链接。](/images/dashboard/sentiment-messages.png)

## 哪些消息会被评分

仅对用户本人发送的消息进行评分：

- 通过 SDK 将用户输入记录为 human input 的自定义 Agent 消息。
- 在 Claude Code、Codex、OpenCode、pi、Hermes 和 OpenClaw 中输入的提示词（当会话记录按默认方式发送时）。定时任务、注入的指令、子 Agent 移交内容以及 Agent 运行时自身生成的其他文本不会被评分。非交互式运行也不在评分范围内，例如 `claude -p`、`codex exec` 和 `hermes -z`——这些提示词由脚本生成，而非真人输入。

评分仅基于用户本人的表达。简短直接的指令（如"修一下"）不会被判定为愤怒，提问也不会被判定为困惑。新的请求不构成纠正，单纯的致谢也不算作已解决。
