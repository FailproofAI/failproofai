Jev 对用户发送给 Agent 的每条消息在四种情绪维度上打出 0 到 100 的分数——**愤怒**、**沮丧**、**高兴**和**困惑**——以及三个反映 Agent 表现的信号：

- **纠正**：用户指出 Agent 的回答有误。
- **已解决**：用户确认 Agent 解决了他们的问题。
- **存疑**：用户质疑 Agent 的回答是否属实，或 Agent 是否真的完成了任务。

通过情感分析，您可以找到用户逐渐失去耐心的对话、被反复纠正的 Agent，以及效果良好的回复。这是 Jev 内置的评分功能，无需您自行编写评估。若需针对固定答案的问题进行评估，请[创建 Jev 评估](/zh/evaluations/jev)。

<Note>
  情感分析默认关闭，需由管理员在组织层面开启。Jev 对每条消息发出一次评分请求，并在请求中附带该消息之前的 Agent 回复。评分会消耗组织的模型预算。
</Note>

## 开启情感分析

1. 前往 **Administration → Settings**。
2. 在 **Human input sentiment** 下，将其切换为**开启**并保存。

系统会优先对过去一天的消息进行评分。之后，新消息通常在到达后一两分钟内完成评分。

## 找到需要审查的对话

打开 **Observe → Sentiment**。可按时间、环境、Agent 或会话 ID 进行筛选。顶部统计区显示消息和会话数量、**标记**消息数量以及最突出的信号。当愤怒、沮丧、纠正、困惑或存疑分数达到 100 分中的 35 分时，该消息将被标记。

![情感分析仪表盘，显示消息和会话数量、标记消息以及随时间变化的 Jev 评分。](/images/dashboard/sentiment-overview.png)

使用**随时间变化的评分**来对比各信号。选择要显示的分数，然后点击某个时间点，即可查看该时间段内的消息。**按 Agent 分类**表格显示某一信号的集中分布情况。在**消息**视图中，可按最强负面分数排序，或筛选单一分数。在会话中打开某条消息，阅读上下文对话，再判断问题所在。

![按最强负面分数排序的情感消息列表，附带各消息来源会话的链接。](/images/dashboard/sentiment-messages.png)

## 哪些消息会被评分

仅对用户本人发送的消息评分：

- 通过 SDK 以人工输入方式记录的自定义 Agent 消息。
- 在 Claude Code、Codex、OpenCode、pi、Hermes 和 OpenClaw 中输入的提示词（在发送会话记录时，即默认情况下）。定时任务、注入的指令、子 Agent 交接以及 Agent 运行时自身写入的其他文本不会被评分。非交互式运行（如 `claude -p`、`codex exec` 和 `hermes -z`）同样不计入评分：这些提示词由脚本生成，而非真人输入。

评分仅针对用户自身的用词。简短直白的指令（如"修复它"）不会被判定为愤怒，提问也不会被判定为困惑。新的请求不属于纠正，单独的感谢语也不会被认定为已解决。
