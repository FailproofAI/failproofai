Jev 对用户发送给 Agent 的每条消息在四种情绪维度上进行 0 到 100 的评分——**愤怒**、**沮丧**、**高兴**和**困惑**——以及三个反映 Agent 表现的信号：

- **纠错**：用户指出 Agent 的回答有误。
- **已解决**：用户确认 Agent 解决了他们的问题。
- **存疑**：用户质疑 Agent 的回答是否准确，或其是否真正完成了任务。

借助情感分析，可以找到用户正在失去耐心的对话、被反复纠错的 Agent，以及效果良好的回复。这是 Jev 内置评分功能，无需自行编写评估规则。如需针对固定答案问题进行评估，请[创建 Jev 评估](/zh/evaluations/jev)。

<Note>
  情感分析默认关闭，需由管理员在组织层面开启。Jev 对每条消息发起一次评分请求，并在此之前接收该消息及 Agent 的回复。评分会消耗组织的模型预算。
</Note>

## 开启情感分析

1. 进入 **设置 → 常规**。
2. 在 **测量** 下，打开 **人工情感** 开关并确认。

系统会优先对过去一天的消息进行评分。此后，新消息将在到达后一两分钟内完成评分。

## 找到待审查的对话

打开 **追踪 → 情感**。可按时间、环境、Agent 或会话 ID 进行筛选。页头显示消息和会话的总数、**已标记**消息的数量，以及排名最高的信号。当愤怒、沮丧、纠错、困惑或存疑分数达到 100 分中的 35 分时，该消息将被标记。

![情感分析仪表盘，显示消息和会话数量、已标记消息及随时间变化的 Jev 评分。](/images/dashboard/sentiment-overview.png)

使用 **随时间变化的评分** 对比各信号。选择要显示的评分，然后点击某个时间点查看该时段的消息。**按 Agent 分类** 表格显示信号集中出现的位置。在 **消息** 视图中，可按最强负面评分排序，或筛选单一评分。在会话中打开某条消息，阅读上下文对话，再判断问题所在。

![情感分析消息列表，按最强负面评分排序，并附有指向各来源会话的链接。](/images/dashboard/sentiment-messages.png)

## 哪些消息会被评分

仅对用户本人发送的消息评分：

- 通过 SDK 以人工输入形式记录的自定义 Agent 消息。
- 在 Claude Code、Codex、OpenCode、pi、Hermes 和 OpenClaw 中输入的提示词（在会话记录被发送的情况下，这是默认行为）。定时任务、注入的指令、子 Agent 交接以及 Agent 运行时自身写入的其他文本不在评分范围内。非交互式运行（如 `claude -p`、`codex exec` 和 `hermes -z`）同样不计入评分，因为这些提示词由脚本生成，而非真实用户输入。

评分仅针对用户自身的用词。简短直接的指令（如"修好它"）不会被判定为愤怒，提问也不会被判定为困惑。新请求不构成纠错，单纯的感谢也不会被判定为已解决。
