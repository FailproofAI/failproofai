Jev 对用户发送给你的 Agent 的每条消息进行评分，分值范围 0 到 100，涵盖四种情绪——**愤怒**、**沮丧**、**开心**和**困惑**——以及三个关于 Agent 表现的信号：

- **纠正**：用户指出 Agent 出现了错误。
- **已解决**：用户确认 Agent 解决了他们的问题。
- **怀疑**：用户质疑 Agent 的回答是否准确，或其是否真正完成了任务。

使用情感分析可以发现用户正在失去耐心的对话、被反复纠正的 Agent，以及效果良好的回复。这是 Jev 内置的评分功能，无需编写评估。如需针对固定答案的问题进行评估，请[创建 Jev eval](/zh/evaluations/jev)。

<Note>
  情感分析默认关闭，需由管理员在组织级别开启。Jev 对每条消息发起一次评分请求，并在评分时获取该消息及其前面的 Agent 回复。评分会消耗组织的模型预算。
</Note>

## 开启功能

1. 进入 **Administration → Settings**。
2. 在 **Human input sentiment** 下，将其切换为**开启**并保存。

最近一天的消息会优先评分。此后，新消息将在到达后一两分钟内完成评分。

## 找到需要审查的对话

打开 **Observe → Sentiment**。可按时间、环境、Agent 或会话 ID 进行筛选。顶部统计显示消息数和会话数，标注了**已标记**的消息数量，并列出主要信号。当愤怒、沮丧、纠正、困惑或怀疑任一评分达到 100 分中的 35 分时，该消息即被标记。

![情感分析仪表盘，显示消息与会话数量、已标记消息及随时间变化的 Jev 评分。](/images/dashboard/sentiment-overview.png)

使用 **Score over time** 对比各信号趋势。选择要显示的评分维度，然后点击某个时间点查看该时段的消息。**By agent** 表格显示信号集中在哪些 Agent 上。在 **Messages** 中，可按最强负面评分排序，或筛选单一评分维度。在会话中打开某条消息，阅读上下文对话，再判断问题所在。

![按最强负面评分排序的情感消息列表，附有指向各源会话的链接。](/images/dashboard/sentiment-messages.png)

## 哪些消息会被评分

仅对用户本人发送的消息评分：

- 通过 SDK 以人类输入方式记录的自定义 Agent 消息。
- 在 Claude Code、Codex、OpenCode、pi、Hermes 和 OpenClaw 中输入的提示词（在会话记录被发送的情况下，即默认行为）。定时任务、注入指令、子 Agent 交接以及 Agent 运行时自身生成的文本不参与评分。非交互式运行同样不计入，例如 `claude -p`、`codex exec` 和 `hermes -z`：这些提示词由脚本生成，而非真实用户输入。

评分仅针对用户本人的表达。简短直接的指令（如"修好它"）不会被判定为愤怒，提问也不会被判定为困惑。提出新请求不等同于纠正，单纯的致谢也不会被视为已解决。
