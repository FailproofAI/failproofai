Jev 对用户发送给 Agent 的每条消息，从 0 到 100 进行四个情感维度的评分——**愤怒**、**沮丧**、**开心**和**困惑**——以及三个关于 Agent 表现的信号：

- **纠错**：用户指出 Agent 的回答有误。
- **已解决**：用户确认 Agent 解决了他们的问题。
- **存疑**：用户质疑 Agent 的回答是否准确，或是否真正完成了任务。

借助情感分析，你可以找出用户正在失去耐心的对话、被反复纠错的 Agent，以及效果良好的回复。这是 Jev 内置的评分功能，无需自行编写评估。如需针对固定答案的问题创建评估，请[创建 Jev 评估](/zh/evaluations/jev)。

<Note>
  情感分析默认关闭，需由管理员在组织层面开启。Jev 对每条消息发出一次评分请求，并在评分时获取该消息及其前一条 Agent 回复。评分会消耗组织的模型预算。
</Note>

## 开启功能

1. 进入 **Administration → Settings**。
2. 在 **Human input sentiment** 下，将开关切换为**开启**并保存。

系统会优先对过去一天的消息进行评分。之后，新消息将在到达后一两分钟内完成评分。

## 找到需要审查的对话

打开 **Observe → Sentiment**。可按时间、环境、Agent 或会话 ID 进行筛选。顶部统计栏显示消息和会话的数量、**被标记**消息的数量，以及最主要的信号类型。当愤怒、沮丧、纠错、困惑或存疑任一评分达到 100 分中的 35 分时，该消息即被标记。

![情感分析看板，显示消息和会话数量、被标记的消息以及随时间变化的 Jev 评分。](/images/dashboard/sentiment-overview.png)

使用 **Score over time** 对比各信号趋势。选择要显示的评分维度，然后点击某个时间点查看该时间段内的消息。**By agent** 表格显示信号集中在哪个 Agent 上。在 **Messages** 中，可按最强负面评分排序，或筛选单一评分维度。在会话中打开某条消息，阅读上下文对话，再判断问题所在。

![按最强负面评分排序的情感分析消息列表，每条消息附有跳转至原始会话的链接。](/images/dashboard/sentiment-messages.png)

## 哪些消息会被评分

仅对用户本人发送的消息进行评分：

- 通过 SDK 以人工输入方式记录的自定义 Agent 消息。
- 在 Claude Code、Codex、OpenCode、pi、Hermes 和 OpenClaw 中输入的提示词（在发送会话记录的情况下，即默认行为）。定时任务、注入的指令、子 Agent 交接以及由 Agent 运行时写入的其他文本不在评分范围内。非交互式运行同样不计入，例如 `claude -p`、`codex exec` 和 `hermes -z`：这些提示词由脚本生成，并非真人输入。

评分仅针对用户自身的表达。简短直白的指令（如"修一下"）不会被认定为愤怒，提问也不会被认定为困惑。新的请求不属于纠错，单纯的致谢也不算作"已解决"。
