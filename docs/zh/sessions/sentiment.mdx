Jev 对用户发送给 Agent 的每条消息在四种情绪维度上进行 0 到 100 分的评分——**愤怒**、**沮丧**、**高兴**和**困惑**——以及三个反映 Agent 表现的信号：

- **纠正**：用户指出 Agent 的回答有误。
- **已解决**：用户确认 Agent 解决了他们的问题。
- **存疑**：用户质疑 Agent 的回答是否准确，或是否真正完成了任务。

使用情感分析可以找出用户正在失去耐心的对话、频繁被纠正的 Agent，以及反响良好的回复。这是内置的 Jev 评分功能，无需自行编写评估。若需针对固定答案问题进行评估，请[创建 Jev 评估](/zh/evaluations/jev)。

<Note>
  情感分析功能默认关闭，需由管理员在组织层面开启。Jev 对每条消息发起一次评分请求，并在评分时获取该消息及其前一条 Agent 回复。评分会消耗组织的模型预算。
</Note>

## 开启功能

1. 进入 **设置 → 常规**。
2. 在 **测量** 下，将 **人类情感** 开关打开并确认。

最近一天的消息会优先完成评分。此后，新消息将在到达后一两分钟内完成评分。

## 找到需要审查的对话

打开 **追踪 → 情感**。可按时间、环境、Agent 或会话 ID 进行筛选。顶部统计了消息和会话数量，显示**被标记**的消息数量，并列出主要信号。当愤怒、沮丧、纠正、困惑或存疑分数达到 100 分中的 35 分时，该消息将被标记。

![情感仪表盘，显示消息和会话数量、被标记的消息以及随时间变化的 Jev 评分。](/images/dashboard/sentiment-overview.png)

使用 **随时间变化的评分** 来对比各信号。选择要显示的评分，然后点击某个时间点查看该时间段的消息。**按 Agent 分类** 表格显示信号集中出现的位置。在 **消息** 视图中，可按最强负面评分排序，或选择单个评分查看。在会话中打开某条消息，阅读上下文对话后再判断问题所在。

![按最强负面评分排序的情感消息列表，附有指向各来源会话的链接。](/images/dashboard/sentiment-messages.png)

## 哪些消息会被评分

仅对用户本人撰写的消息评分：

- 通过 SDK 以人类输入方式记录的自定义 Agent 消息。
- 在 Claude Code、Codex、OpenCode、pi、Hermes 和 OpenClaw 中输入的提示词（在发送会话记录的默认模式下）。定时任务、注入的指令、子 Agent 切换以及 Agent 运行时自身生成的其他文本不会被评分。非交互式运行方式（如 `claude -p`、`codex exec` 和 `hermes -z`）同样不计入评分——这些提示词由脚本生成，而非真实用户输入。

评分仅针对用户本人的表达。简短直接的指令（如"修好它"）不会被判定为愤怒，提问也不会被判定为困惑。提出新请求不属于纠正，单独表达感谢也不算作已解决。
