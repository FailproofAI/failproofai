---
title: "核心概念"
description: "Failproof AI 中使用的一组核心概念。"
icon: "boxes"
---

| 概念 | 含义 | 可实现的目标 |
| --- | --- | --- |
| Session | 一次 Agent 任务或运行 | 还原单次执行的具体结果 |
| Event | Session 中记录的一个操作 | 查看模型调用、工具使用、错误、人工操作或策略决策 |
| Trace | 有序且嵌套的 Session 视图 | 理解因果关系，而非阅读零散的日志 |
| Evaluation | 对 Session 的评分或判断 | 持续追踪质量、合规性、成本或延迟 |
| Audit | 对选定 Session 集合的审查 | 以明确目标和节奏搜寻故障模式 |
| Finding | 由 Audit 发现的有据可查的故障 | 查看故障模式、严重程度及受影响的 Session |
| Issue | 持久化的响应记录 | 分配、讨论并解决一个 Finding 或告警事件 |
| Alert | 用于检测问题重现的规则 | 在已知条件再次出现时通知响应人员 |
| Policy | 在 Agent 活动期间执行的规则 | 观察、拦截或重定向风险行为 |
| Deployment | 针对机器的版本化策略发布 | 控制策略的运行范围并安全回滚 |

## 可靠性闭环

从证据出发。Session 展示了发生了什么；Audit 判断这是孤立的错误还是一种模式；Finding 识别故障模式，Issue 负责跟进响应；Policy 防止相同行为再次发生，而 Alert 则在该条件重现时发出通知。

<Warning>
  本地 `failproofai audit` 扫描本地 Agent 历史记录。周期性的 Cloud Audit 审查存储在 Failproof AI Cloud 中的 Session。二者是范围和调度均不同的独立工作流。
</Warning>
