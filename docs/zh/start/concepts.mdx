Failproof AI 记录 Agent 的行为并决定其被允许执行的操作。

## 观测

| 术语 | 含义 |
| --- | --- |
| Session | 一次 Agent 运行 |
| Event | Session 中的一个操作 |
| Trace | Session 的有序视图 |
| Evaluation | 评分或判断结果 |
| Audit | 对多个 Session 的审查 |
| Finding | 故障模式的证据 |
| Issue | 由某人负责跟进的响应 |
| Alert | 检测重复发生情况的规则 |

## 执行

| 术语 | 含义 |
| --- | --- |
| Harness | Agent 运行所在的环境 |
| Hook | Harness 请求决策的时间点 |
| Policy | 允许、引导或阻止操作的规则 |
| Policy pack | 任何人均可安装的版本化策略集 |
| Daemon | 评估 Policy 的本地服务 |
| Deployment | 分配给某台机器的 Policy |

## 工作流程

```text
Session → Audit → Finding → Issue → Policy
```

从证据出发。找出反复出现的故障，指定负责人，然后加以预防。

Policy 返回 `allow`、`instruct` 或 `deny`。通过 `instruct` 进行引导取决于 Harness 的支持；当操作必须被阻止时，请使用 `deny`。

观测模式与决策过程相互独立。它会运行真实的 Policy 并记录其将执行的操作，同时允许 Agent 继续运行。

<Warning>
  直接执行 `fp fleet deploy <machine> --add <policy>` 会立即生效并强制执行。添加 `:observe` 可进行影子发布。
</Warning>

初始设置不会选择任何 Policy pack。在添加之前，仅有 `block-failproofai-commands` 处于运行状态。已编译的策略目录包含 9 个类别共 39 条 Policy。

在假设某个事件可以在所有 Agent 环境中阻止操作之前，请先查阅[支持的 Harness](/zh/reference/harnesses#enforcement-capability)。
