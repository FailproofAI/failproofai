---
title: "用策略预防第一次故障"
description: "编写一个策略版本，以观察模式部署，然后强制执行。"
icon: "shield-check"
---

只有当你能够描述不安全的操作以及必须保持允许的合法操作时，才应使用策略。

<Tabs>
  <Tab title="控制台">
    <Steps>
      <Step title="编写策略">
        前往 **Admin → policy editor**。从演示策略开始，查看或编辑其源代码，然后选择 **publish version**。发布后将创建不可变的版本，你可以将其部署到机器上。

        ![策略编辑器编写视图，其中演示策略已准备好发布为不可变版本。](/images/dashboard/policy-editor.png)
      </Step>
      <Step title="将其部署到机器">
        前往 **Admin → enforcement**，展开目标机器，然后选择 **edit this machine**。添加已发布的演示策略，固定其版本，选择 **observe**，然后应用部署。

        ![机器部署编辑器，在应用部署之前以观察模式选择了已发布的策略版本。](/images/dashboard/enforcement-editor.png)
      </Step>
      <Step title="验证策略">
        在该机器上运行一个新的 Agent 会话，然后打开 **Observe → policy**。选择该机器，并确认演示策略出现在策略映射和决策时间线中。观察模式会记录策略的预期行为，而不会阻止操作的执行。

        ![策略页面显示决策总数、随时间变化的强制执行活动，以及本地和云端托管的策略映射。](/images/dashboard/policy-observe.png)
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    云端策略编写和机群部署属于管理工作流。在发布之前，可使用本地 CLI 验证相同的策略：

    ```bash
    failproofai policies --install --custom ./payment-retry.policies.ts \
      --cli claude --scope project
    failproofai config --status
    ```

    使用 `fp` 检查云端可见的策略决策：

    ```bash
    fp events --event-type hook_completed --env production --since 24h
    fp sessions --env production --since 24h
    ```

    这两个步骤也可通过 CLI 完成：`fp policies publish <id> <file>` 用于创建版本，`fp fleet deploy <machine-id> --add <id>` 用于将其部署到机器上。对应的控制台操作为 **Admin → policy editor** 和 **Admin → enforcement**。
  </Tab>
</Tabs>
