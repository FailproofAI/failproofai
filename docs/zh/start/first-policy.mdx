---
title: "通过策略预防首次故障"
description: "编写策略版本，以观察模式部署，然后执行。"
icon: "shield-check"
---

只有在能够明确描述不安全操作以及必须保持允许的合法操作之后，才应使用策略。

<Tabs>
  <Tab title="仪表板">
    <Steps>
      <Step title="编写策略">
        前往 **Admin → policy editor**。从演示策略开始，查看或编辑其源码，然后选择 **publish version**。发布操作会创建不可变版本，该版本可部署到机器上。

        ![策略编辑器的编写视图，演示策略已准备好发布为不可变版本。](/images/dashboard/policy-editor.png)
      </Step>
      <Step title="将其部署到机器">
        前往 **Admin → enforcement**，展开目标机器，然后选择 **edit this machine**。添加已发布的演示策略，固定其版本，选择 **observe** 模式，并应用部署。

        ![机器部署编辑器，已发布的策略版本在应用部署前以观察模式选中。](/images/dashboard/enforcement-editor.png)
      </Step>
      <Step title="验证策略">
        在该机器上运行一个新的 Agent 会话，然后打开 **Observe → policy**。选择该机器，确认演示策略出现在策略映射和决策时间线中。观察模式会记录策略本会执行的操作，而不会阻止实际操作。

        ![策略页面，显示决策总计、随时间变化的执行活动以及本地和云端管理的策略映射。](/images/dashboard/policy-observe.png)
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    云端策略编写和机群部署属于管理工作流。在发布之前，可使用本地 CLI 验证相同的策略：

    ```bash
    failproofai policies --install --custom ./payment-retry.policies.ts \
      --cli claude --scope project
    failproofai config --status
    ```

    使用 `fp` 检查云端可见的策略决策：

    ```bash
    fp events --event-type hook_completed --env production --since 24h
    fp sessions --env production --since 24h
    ```

    Cloud CLI 不提供仅限管理员的执行部署路由。请从 **Admin → policy editor** 发布版本，并从 **Admin → enforcement** 部署它们。
  </Tab>
</Tabs>
