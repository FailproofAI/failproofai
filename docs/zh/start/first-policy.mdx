从你想要阻止的行为和必须仍然正常工作的合法操作开始。

## 先尝试已审核的策略

```bash
failproofai policies
failproofai policies add block-rm-rf
```

Failproof AI 包含 39 个已审核策略。在编写新策略之前，请查看[策略目录](/zh/policies/builtin-catalog)。

## 编写并测试你自己的策略

<Steps>
  <Step title="创建一个可用的策略">
    ```bash
    failproofai publish --init guards.mjs
    ```

    这会生成一个阻止 `git push --force` 的策略。将其编辑为你自己的规则。
  </Step>
  <Step title="在本机上强制执行">
    ```bash
    failproofai policies -i -c ./guards.mjs
    ```

    让你的 Agent 执行被阻止的操作，然后在本地仪表盘中查看 **Policies → Activity**。
  </Step>
  <Step title="保留或移除策略">
    将 `*policies.mjs` 文件放在 `.failproofai/policies/` 目录下，即可自动加载。

    使用以下命令移除显式自定义文件：

    ```bash
    failproofai policies -u -c
    ```
  </Step>
</Steps>

## 分享策略

发布一个公开的策略包：

```bash
failproofai publish
```

任何人都可以通过 `failproofai policies add <owner>/<repo>` 安装它。自行添加 GitHub topic `failproofai-policies`，以便 [Policy Hub](https://befailproof.ai/policy-hub/) 对其进行索引。

云端部署流程：

```bash
fp policies publish checkout-guard ./guards.mjs
fp fleet deploy <machine> --add checkout-guard:observe
fp guardrails summary --since 24h --machine <machine>
fp fleet deploy <machine> --add checkout-guard:enforce
```

<Warning>
  直接使用 `--add checkout-guard` 会立即强制执行。添加 `:observe` 可以在不阻止 Agent 的情况下记录策略的预期行为。
</Warning>

完整工作流程请参阅[发布策略包](/zh/policies/publish-a-pack)或[部署策略](/zh/policies/deploy)。
