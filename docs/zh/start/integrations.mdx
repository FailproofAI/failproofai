## 开始之前

以下两项前提条件，下方代码均不会自动处理：

| 要求 | 原因 |
| --- | --- |
| Python 3.10 或更高版本 | SDK 声明的最低版本要求。 |
| 已通过 `failproofai config` 完成机器配置 | 该命令会安装 failproofaid 守护进程，而守护进程是唯一负责发送 SDK 写入内容的组件。若缺少守护进程，批次数据会堆积在缓冲目录中，永远无法发出。 |

<Note>
  **此路径仅用于记录，不执行策略。** SDK 捕获您的 Agent 所做的事情。策略从 Agent CLI 内部的 hook 触发，因此对框架 Agent 执行策略意味着需要在您自己的运行时中添加 hook——请参阅 [策略](/zh/policies/overview)。
</Note>

## 三行代码，适用任意框架

<CodeGroup>
```bash LangGraph
pip install 'failproofai-sdk[langgraph]'
```

```bash CrewAI
pip install 'failproofai-sdk[crewai]'
```

```bash LlamaIndex
pip install 'failproofai-sdk[llamaindex]'
```

```bash Pydantic AI
pip install 'failproofai-sdk[pydantic-ai]'
```

```bash Custom agents
pip install failproofai-sdk
```
</CodeGroup>

```python
import failproofai_sdk

failproofai_sdk.configure(environment="production")
failproofai_sdk.instrument()          # 自动检测您已导入的框架

with failproofai_sdk.session():
    ...                               # 您现有的 Agent 调用，无需改动
```

无需在函数上添加装饰器，无需向调用传递回调，也无需在代码中传递各种 ID。唯一的变化是将原有调用包裹在 session 中：

<Tabs>
  <Tab title="LangGraph">
    ```python
    graph.invoke({"messages": [HumanMessage("...")]})
    ```
  </Tab>
  <Tab title="CrewAI">
    ```python
    Crew(agents=[analyst, writer], tasks=[gather, summarise]).kickoff()
    ```
  </Tab>
  <Tab title="LlamaIndex">
    ```python
    await agent.run("...")        # 在 `async with failproofai_sdk.session():` 下使用
    ```
  </Tab>
  <Tab title="Pydantic AI">
    ```python
    agent.run_sync("...")
    ```
  </Tab>
  <Tab title="Custom agents">
    ```python
    with failproofai_sdk.agent("planner"):
        with failproofai_sdk.tool_call("search", input={"q": q}) as t:
            t.output = search(q)
    ```
  </Tab>
</Tabs>

额外安装的包用于支持对应**框架**。所有适配器均已内置于基础安装包中，因此已安装框架的项目无需额外安装任何内容。

## 确认数据已到达

运行一次已添加监测的 session，然后打开 **Observe → Sessions** 并选择您的环境。该次运行将以重建的追踪链路形式呈现。

如果没有数据到达，请使用 `failproofai config --status` 确认机器已完成配置且处于连接状态。如果未连接，请运行 `failproofai config`。详见[选择您的配置方式](/zh/start/setup)。

<Warning>
  请勿通过查看缓冲目录来确认数据是否已发送。Failproof 守护进程会在数毫秒内收集并删除每批数据，因此读取该目录会与收集器产生竞争，显示的事件数量将远少于实际发出的数量。
</Warning>

若要验证 SDK 是否正在写入数据，请先停止守护进程，再运行您的 session，然后查看 `~/.failproofai/custom-agents/events/` 目录。在守护进程运行时，该目录为空才是正常状态。

<CodeGroup>
```bash Linux
sudo systemctl stop failproofaid@$USER
```

```bash macOS
sudo launchctl bootout system/ai.failproof.failproofaid.$USER
```
</CodeGroup>

检查完成后，运行 `failproofai config` 以恢复守护进程。守护进程停止期间，此机器上的 hook 事件将没有评估器，会被拒绝，因此请尽量缩短停止时间。
