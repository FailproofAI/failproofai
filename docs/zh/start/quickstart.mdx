本快速入门将帮助你完成以下操作：让一台机器上报会话、运行审计，并部署策略。你可以使用技能包来配置 Failproof AI，也可以按照手动步骤操作。

**选择你的路径：** 如果你的 Agent 运行在 12 个受支持的[运行环境](/zh/reference/harnesses)之一中——例如编码 CLI，或 Hermes、OpenClaw 等网关——请按照以下步骤操作；你需要 Node.js 20.9 或更高版本。如果你的 Agent 没有运行环境，可使用 [Python SDK](/zh/reference/custom-agents) 进行追踪和审计，然后从[运行首次故障检查](/zh/start/first-audit)处继续；此路径上的执行能力需要在你的运行时中添加 hook。

        npx skills add FailproofAI/skills

      <Step title="让你的 Agent 完成所有配置">
        ```text
        Set up Failproof AI for this project, connect this machine, install the right hooks and policies, and verify that a session arrives.
        ```

        你的 Agent 会检查项目、选择相关集成、执行配置，并验证会话是否已到达。请参阅 [FailproofAI skills 仓库](https://github.com/FailproofAI/skills)了解各项技能及高级安装选项。
      </Step>
    </Steps>

  <Tab title="手动配置">
    ## 开始之前

1. 打开 [Failproof AI 控制台](https://app.befailproof.ai)，创建账号或使用工作邮箱登录。
2. 前往 **Administration → Keys**，创建一个具有 `events:add` 和 `policies:pull` 权限的密钥。
3. 复制一次性密钥，并将其存储在目标机器上：

```bash
export FAILPROOFAI_KEY="<one-time-secret>"
```

    ## 安装

<Steps>
  <Step title="安装并连接 Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config --connect https://app.befailproof.ai --token "$FAILPROOFAI_KEY"
    ```

    默认情况下会发送会话记录。添加 `--no-transcripts` 可在不包含记录内容的情况下上报 hook 活动和策略决策。

    如果该机器上已有 Agent 历史记录，可预览并导入最近七天的数据，然后等待传输完成。在全新机器上可跳过此步骤。

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    在 Failproof AI 中打开 **Sessions**，选择一个已导入的会话。
  </Step>
  <Step title="安装 Agent hook 和策略">
    此步骤将 Failproof AI 挂载到你的运行环境，并安装 40 条内置策略。使用这些策略可以查看本地策略决策，并在 Failproof AI 审计你的会话并为 Agent 编写策略之前试用执行能力。

    可让安装程序自动检测你的运行环境，也可以显式指定一个。12 个运行环境均为有效的 `--cli` 值——`claude`、`codex`、`copilot`、`cursor`、`opencode`、`pi`、`hermes`、`openclaw`、`factory`、`devin`、`antigravity`、`goose`。

    ```bash
    failproofai policies --install --cli claude --scope user     # 编码 CLI
    failproofai policies --install --cli hermes --scope user     # Slack/Telegram 网关
    ```

    在工具调用执行前拦截已在全部 12 个运行环境中验证。轮次结束门控在 8 个环境中验证——各运行环境的详细情况请参阅[执行能力](/zh/reference/harnesses#enforcement-capability)矩阵。
  </Step>
  <Step title="审计行为">
    按照[运行首次故障检查](/zh/start/first-audit)操作。使用具体目标，例如"查找 Agent 在未改变方案的情况下重试失败工具的会话"。
  </Step>
  <Step title="预防故障">
    按照[通过策略预防首次故障](/zh/start/first-policy)操作。先以观察模式启动，检查匹配项，然后对已审核的版本启用执行。
  </Step>
</Steps>

<Check>
  运行 `failproofai config --status`。配置正常时，将显示云连接状态、守护进程状态，以及执行是否已暂停。
</Check>
