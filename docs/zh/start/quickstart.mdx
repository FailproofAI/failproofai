本快速入门指南将帮助您让一台机器开始上报会话、运行审计，并部署策略。您可以使用技能包完成设置，或按照手动步骤操作。

**选择适合您的路径：** 如果您的 Agent 运行在 12 个受支持的[执行环境](/zh/reference/harnesses)之一中——例如编码 CLI，或 Hermes、OpenClaw 等网关——请按照以下步骤操作；您需要 Node.js 20.9 或更高版本。如果您的 Agent 没有执行环境，请使用 [Python SDK](/zh/reference/custom-agents) 为其添加追踪和审计功能，然后跳转至[运行首次故障检查](/zh/start/first-audit)；该路径的执行策略需要在您的运行时中添加 hook。

  <Tab title="手动设置">
    ## 安装

<Steps>
  <Step title="安装并连接 Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    这一条命令完成全部设置：安装本地守护进程（需 root 权限，仅需一次），将 hook 接入所找到的每个 Agent CLI，并将本机连接到云端。

    在 **Connect to cloud** 步骤中，设置会立即引导您登录 FailproofAI Cloud（按 Tab 可切换其他选项：粘贴 API 密钥，或使用开源版本）。它会在您的浏览器中打开一个链接（通过 SSH 或在无显示器的机器上，它会打印链接，以便您在任意设备上打开）。注册或登录，确认组织——或直接在此创建一个——然后点击 **Authorize**。密钥的名称和权限会自动为您设置好，无需提前创建账户。

    终端会自动感知并显示是谁授权以及对应的组织。确认要追踪的 Agent 后，设置即完成。机器密钥仅在守护进程安装完成后才会创建，因此中途放弃的安装不会留下任何密钥；它会出现在 **Administration → Keys** 下，标记为 **cli login**，您可以在那里撤销它。

    <Accordion title="没有浏览器或终端？使用密钥（CI、容器、provisioning 脚本）">
      在 [Failproof AI 控制台](https://app.befailproof.ai) 中，前往 **Administration → Keys** 并创建一个具有 `events:add` 和 `policies:pull` 权限的密钥。如果您计划使用 [通过 FailproofAI Cloud 的 Jev](/zh/reference/jev-cloud)，请选择 **machine** 预设，该预设还会额外授予 `jev:evaluate` 权限。复制一次性密钥，并通过 shell 读入目标机器——`read -s` 会以不回显的方式提示输入：

      ```bash
      read -rs FAILPROOFAI_KEY && export FAILPROOFAI_KEY
      FAILPROOFAI_CLOUD_TOKEN="$FAILPROOFAI_KEY" failproofai config
      ```

      通过环境变量而非 `--token` 传递密钥，可避免密钥出现在 `ps` 输出中（机器上的任何用户都能读取命令参数）。但这并不能防止密钥出现在 shell 历史记录中——使用 `read -s` 读取才能做到这一点。在 CI 中，请将其作为掩码密钥注入，并关闭 shell 追踪（`set -x`），否则追踪日志会将其打印出来。在交互式运行中，您也可以在 **Connect to cloud** 步骤中选择 **Paste an API key**。
    </Accordion>

    默认情况下会发送会话记录。添加 `--no-transcripts` 可仅上报 hook 活动和策略决策，而不包含记录内容。

    <Warning>
      请勿在此处使用 `failproofai config --connect <url>`。该标志用于注册一台**已完成**设置的机器，执行后立即返回——不安装守护进程，不配置 hook——因此该机器会出现在 Cloud 中，但实际上不会收集或执行任何内容。
    </Warning>

    如果这台机器上已有 Agent 历史记录，可预览并导入最近七天的数据，然后等待传输完成。新机器请跳过此步骤。

    ```bash
    failproofai backfill --since 7d --dry-run
    failproofai backfill --since 7d
    failproofai flush --wait
    ```

    在 Failproof AI 中打开 **Sessions** 并选择一个已导入的会话。
  </Step>
  <Step title="将 Failproof AI 接入执行环境">
    上一步已自动接入所有检测到的 Agent CLI。如有需要，可针对某个执行环境单独重新运行，或用于添加后续安装的执行环境。12 个执行环境均为有效的 `--cli` 值——`claude`、`codex`、`copilot`、`cursor`、`opencode`、`pi`、`hermes`、`openclaw`、`factory`、`devin`、`antigravity`、`goose`。

    ```bash
    failproofai policies --install --cli claude --scope user     # a coding CLI
    failproofai policies --install --cli hermes --scope user     # a Slack/Telegram gateway
    ```

    工具调用前的拦截在全部 12 个执行环境上均已验证。轮次结束关卡在 8 个上已验证——请参阅[执行能力](/zh/reference/harnesses#enforcement-capability)了解各执行环境的详细矩阵。
  </Step>
  <Step title="选择要执行的策略">
    接入 hook 不会启用任何策略。设置故意不做任何选择——这个决定由您来做——请获取一个策略包：

    ```bash
    failproofai policies add FailproofAI/policies
    ```

    该策略包从其 GitHub Release 获取，经过校验和验证，并固定到解析到的确切标签。它包含 39 条策略，并默认开启其清单标记为可无人值守启用的 10 条。使用它们可以查看本地策略决策，并在 Failproof AI 审计您的会话并为您的 Agent 编写策略之前尝试执行。

    在获取策略包之前，可通过 `failproofai policies show <owner>/<repo>` 预览其内容，或参阅[策略包](/zh/policies/packs)了解如何只获取其中一部分。

    在此之前，唯一执行中的策略是 `block-failproofai-commands`——这是一个始终开启的守卫，防止 Agent 关闭 Failproof AI。`failproofai policies` 命令会列出当前启用的策略。
  </Step>
  <Step title="审计行为">
    按照[运行首次故障检查](/zh/start/first-audit)操作。请使用具体目标，例如"找出 Agent 在工具调用失败后未改变方法就直接重试的会话"。
  </Step>
  <Step title="预防故障">
    按照[使用策略预防首次故障](/zh/start/first-policy)操作。从观察模式开始，检查匹配项，然后执行经过审查的版本。
  </Step>
</Steps>

<Check>
  运行 `failproofai config --status`。健康的设置会报告云连接状态、守护进程状态以及执行是否已暂停。
</Check>
