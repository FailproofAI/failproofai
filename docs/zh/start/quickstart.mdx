在一台机器上设置 Failproof AI，然后选择本地运行或连接 Cloud。

如果您的 Agent 运行在[支持的运行环境](/zh/reference/harnesses)中，请按以下步骤操作。对于使用 LangChain、CrewAI、LlamaIndex、Pydantic AI 或自定义运行时构建的 Agent，请从[接入您的 Agent](/zh/start/integrations) 开始。

## 让您的 Agent 引导配置

将 Failproof AI 总技能安装到兼容的 Agent 中：

```bash
npx skills add FailproofAI/skills
```

这将安装总技能及其专项子技能。如果只需要总技能，可使用 `--skill
failproofai`。它能理解本地和 Cloud 的配置、守护进程健康状态、会话、审计、策略及故障排查，负责引导工作并将专项任务路由到对应的 Failproof AI 技能；它不会替代下方的 CLI 安装步骤。

## 配置机器

<Steps>
  <Step title="安装并配置 Failproof AI">
    ```bash
    npm install -g failproofai
    failproofai config
    ```

    安装过程会部署后台服务，并连接所有已找到的支持 Agent。可能需要一次管理员权限授权。支持 Linux 和 macOS。
  </Step>

  <Step title="选择策略">
    安装默认不启用任何策略包。添加 Failproof AI 策略包：

    ```bash
    failproofai policies add FailproofAI/policies
    failproofai policies
    ```

    第二条命令会显示本机上的所有策略及其启用状态。在您添加策略包之前，只有 `block-failproofai-commands` 处于运行状态。
  </Step>

  <Step title="检查机器状态">
    ```bash
    failproofai config --status
    ```

    该命令会报告服务状态、Cloud 连接情况以及暂停状态。
  </Step>
</Steps>

## 选择本地运行或连接 Cloud

<Tabs>
  <Tab title="本地运行">
    无需账号。

    ```bash
    failproofai
    failproofai audit
    ```

    第一条命令会在 `http://localhost:8020` 打开本地仪表盘。第二条命令会扫描本机上已有的 Agent 历史记录。
  </Tab>

  <Tab title="连接 Cloud">
    在 Failproof AI Cloud 中创建机器密钥，然后运行：

    ```bash
    failproofai config --token <machine-key>
    failproofai config --status
    ```

    Cloud 将接收策略决策和会话记录。如果只希望发送决策而不发送记录，请先完成连接，然后在 `~/.failproofai/config.json` 中将 `collector.sessions` 设置为 `false`；当前的 `--no-transcripts` 安装标志不会应用该设置。对于共享 Shell 和 CI 环境，建议使用 `FAILPROOFAI_CLOUD_TOKEN` 环境变量，而不是将密钥写入命令历史。
  </Tab>
</Tabs>

## 验证配置

运行您的某个 Agent，让其执行一项普通任务，然后：

工具调用拒绝已在全部 12 个支持的运行环境中得到验证。回合结束时的策略执行已在 8 个环境中得到验证；其他运行环境与事件的组合可能仅处于观测状态或尚未验证。

- 在本地仪表盘的 **Policies → Activity** 中查看策略决策。
- 在 Cloud 的 **Observe → Sessions** 中查看完整运行记录。
- 运行 `failproofai audit` 以排查存在风险或资源浪费的模式。

<Warning>
  配置完成后，`failproofaid` 服务将作为评估器运行。如果它无法响应，受保护的操作将被拒绝。当 Agent 意外停止时，请运行 `failproofai config --status` 进行排查。
</Warning>
