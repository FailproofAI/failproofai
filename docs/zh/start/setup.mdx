Failproof AI 可以完全在单台机器上运行，也可以连接到 Cloud 以实现共享会话和策略管理。

## 本地模式，无需账户

```bash
npm install -g failproofai
failproofai config
failproofai policies add FailproofAI/policies
failproofai
```

此操作将安装服务、连接受支持的代理、添加策略包，并在 `http://localhost:8020` 打开仪表板。

运行 `failproofai audit` 可扫描机器上已有的代理历史记录。

## 连接 Failproof AI Cloud

在 Cloud 中创建机器密钥，然后运行：

```bash
failproofai config --token <machine-key>
failproofai config --machine-label checkout-runner-01
failproofai policies add FailproofAI/policies
failproofai config --status
```

或者导出 `FAILPROOFAI_CLOUD_TOKEN=<machine-key>` 后直接运行 `failproofai config`。在共享机器和 CI 环境中，建议使用环境变量方式，以避免密钥出现在 shell 历史记录或进程列表中。

Cloud 连接承担两项独立职责：

- 拉取分配给该机器的策略。
- 发送策略决策和会话记录。

如果只需发送决策，可先完成连接，然后在 `~/.failproofai/config.json` 中将 `collector.sessions` 设置为 `false`。请勿依赖 `--no-transcripts`：当前设置流程会解析该标志，但不会实际生效。详见[事件与配置](/zh/reference/events-and-configuration#machine-configuration)。

<Note>
  `--machine-label` 用于重命名已连接的机器。请在运行设置命令之后再执行此操作，而非在首次连接时一并使用。
</Note>

## 无人值守设置

`failproofai config` 不需要特殊的非交互式标志。在 CI 或容器环境中，它会直接应用所请求的设置，无需任何提示。

```bash
export FAILPROOFAI_CLOUD_TOKEN="<key>"
failproofai config
```

安装后台服务时需要管理员权限，且仅需一次。设置过程不会弹出交互式 `sudo` 密码提示：要么无需密码直接成功，要么打印出管理员需要手动执行的命令。

## 平台支持

设置功能支持 Linux 和 macOS。在其他平台上，程序将直接退出，不会写入任何钩子或部分设置状态。
