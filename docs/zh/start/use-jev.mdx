Jev 在 Agent 运行的两个节点发挥作用：对已完成的会话进行评分（与已知答案比对），或在工具调用发生时结合你的任务上下文进行审查。

<Tabs>
  <Tab title="Jev 评估">
    当一个已完成的会话可以用有限答案的问题进行评分时，使用 Jev eval，例如"客户是否要求退款？请回答是或否。"它帮助你发现跨会话的规律。

    ## 创建评估

    在 Cloud 控制台中，打开 **Analyze → eval authoring → new eval**。输入一个固定答案的问题，选择 **draft**，并确认它选择了分类器评分。在真实会话上[测试](/zh/evaluations/test)，然后部署。

    ![共享的 eval 编写表单，你可以在其中描述问题、审查草稿并部署。此截图显示的是代码草稿；对于 Jev 请使用固定答案的问题。](/images/dashboard/eval-authoring-draft.png)

    ## 查看评分

    新会话完成后，打开 **Observe → Evaluations**，或使用 Cloud CLI：

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI 用于读取评分；目前创建 Jev eval 需要通过控制台操作。问题类型和示例请参阅 [Jev evaluations](/zh/evaluations/jev)。
  </Tab>
  <Tab title="Jev policies">
    当字符串匹配策略需要结合请求上下文来判断工具调用是否安全时，使用 Jev policy 审查。先在 **observe** 模式下运行，这样你可以查看 Jev 的判断结果，同时已安装的 policies 仍负责最终决策。

    Jev 的检查规则来自规则包；Failproof AI 默认不附带任何规则包。在你安装之前，Jev 不会提出任何问题，即便已完成配置：

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## 配置 Cloud Jev

    在 Cloud 控制台中，打开 **Administration → Keys**，使用 **machine** 预设创建一个密钥。按照[快速入门](/zh/start/quickstart)的说明通过 `failproofai config` 使用该密钥。在没有现有 Jev 配置的机器上，这将以 observe 模式启用 Cloud Jev。使用以下命令检查连接状态：

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## 使用自定义端点

    在本地控制台中，打开 **Settings → Jev**。选择提供商，粘贴其 token，选择 **observe**，然后开启 Jev。

    ![本地 Jev 设置面板，包含提供商选择、token 输入框以及 observe 模式选项。](/images/dashboard/jev-settings.png)

    或者在终端中配置并测试你的端点：

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    让一个已挂钩的 Agent 使用其文件读取工具读取 `README.md`。确认该工具调用出现在会话中，然后在本地控制台的 **Policies → Activity** 下查看详情。一旦 observe 结果符合预期，请参阅 [Jev policies](/zh/policies/jev) 了解何时启用强制执行。有关提供商详情和配置说明，请参阅[集成参考](/zh/reference/jev)。
  </Tab>
</Tabs>
