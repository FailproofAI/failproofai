Jev 在智能体运行的两个阶段发挥作用：对已完成的会话按已知答案评分，或在你向智能体下达指令的上下文中审查工具调用。

<Tabs>
  <Tab title="Jev 评估">
    当一个已完成的会话可以针对具有若干已知答案的问题进行评分时，使用 Jev 评估，例如"客户是否请求退款？请回答是或否。"它可以帮助你发现跨会话的规律。

    ## 创建评估

    在 Cloud 控制台中，打开 **Analyze → eval authoring → new eval**。输入一个固定答案问题，选择 **draft**，并确认已选择分类器评分。在真实会话上[测试它](/zh/evaluations/test)，然后发布。

    ![共享评估创作表单，你可以在其中描述问题、审查草稿并发布。此截图展示的是代码草稿；Jev 请使用固定答案问题。](/images/dashboard/eval-authoring-draft.png)

    ## 查看评分

    新会话完成后，打开 **Observe → Evaluations**，或使用 Cloud CLI：

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI 用于读取评分；目前创建 Jev 评估需通过控制台操作。问题类型和示例请参阅 [Jev 评估](/zh/evaluations/jev)。
  </Tab>
  <Tab title="Jev 策略">
    当字符串匹配策略需要结合你的请求上下文来判断工具调用是否安全时，使用 Jev 策略审查。先以 **observe** 模式启动，这样你可以在已安装的策略仍决定每次调用的同时，检查 Jev 的判断结果。

    Jev 的检查来自策略包；Failproof AI 不预置任何包。在你安装之前，即使已配置 Jev，它也不会进行任何检查：

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## 配置 Cloud Jev

    在 Cloud 控制台中，打开 **Administration → Keys**，使用 **machine** 预设创建一个密钥。按[快速入门](/zh/start/quickstart)中的说明配合 `failproofai config` 使用。在没有现有 Jev 配置的机器上，这将以 observe 模式启用 Cloud Jev。通过以下命令检查连接状态：

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## 使用自定义端点

    在本地控制台中，打开 **Settings → Jev**。选择提供商，粘贴其令牌，选择 **observe**，然后开启 Jev。

    ![本地 Jev 设置面板，已选择提供商、令牌字段和 observe 模式。](/images/dashboard/jev-settings.png)

    或者在终端中配置并测试你的端点：

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    让一个已挂钩的智能体使用其文件读取工具读取 `README.md`。确认该工具调用出现在会话中，然后在本地控制台的 **Policies → Activity** 下检查它。一旦 observe 结果看起来符合预期，[Jev 策略](/zh/policies/jev)会说明何时启用强制执行。有关提供商详情和配置，请参阅[集成参考](/zh/reference/jev)。
  </Tab>
</Tabs>
