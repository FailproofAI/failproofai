Jev 在智能体运行的两个环节发挥作用：对已完成的会话按已知答案打分，或在您向智能体下达指令的上下文中审查工具调用。

<Tabs>
  <Tab title="Jev evals">
    当一个已完成的会话可以针对少量已知答案进行评分时，请使用 Jev eval，例如"客户是否要求退款？请回答是或否。"它能帮助您发现跨会话的规律。

    ## 创建 eval

    在 Cloud 仪表板中，依次打开 **Analyze → eval authoring → new eval**。输入一个固定答案的问题，选择 **draft**，并确认它选择了分类器评分方式。在真实会话上[测试](/zh/evaluations/test)后，再将其部署。

    ![共享的 eval 创作表单，您可以在此描述问题、审阅草稿并进行部署。截图展示的是代码草稿；Jev 请使用固定答案类型的问题。](/images/dashboard/eval-authoring-draft.png)

    ## 查看评分

    新会话完成后，打开 **Observe → Evaluations**，或使用 Cloud CLI：

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI 用于读取评分；创建 Jev eval 目前需通过仪表板完成。有关问题类型和示例，请参阅 [Jev evaluations](/zh/evaluations/jev)。
  </Tab>
  <Tab title="Jev policies">
    当基于字符串匹配的 policy 需要结合您的请求上下文来判断工具调用是否安全时，请使用 Jev policy 审查。建议先以 **observe** 模式启动，这样您可以查看 Jev 的判断结果，同时让已安装的 policies 继续处理每次调用。

    Jev 的检查规则来自规则包；Failproof AI 默认不附带任何规则包。在您安装之前，即使已完成配置，Jev 也不会进行任何检查：

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## 配置 Cloud Jev

    在 Cloud 仪表板中，打开 **Administration → Keys**，使用 **machine** 预设创建一个密钥。按照[快速入门](/zh/start/quickstart)中的说明，配合 `failproofai config` 使用该密钥。在未配置 Jev 的机器上，此操作会以 observe 模式启用 Cloud Jev。通过以下命令检查连接状态：

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## 使用自定义端点

    在本地仪表板中，打开 **Settings → Jev**。选择提供商，粘贴其令牌，选择 **observe**，然后开启 Jev。

    ![本地 Jev 设置面板，包含提供商选项、令牌输入框，以及已选中的 observe 模式。](/images/dashboard/jev-settings.png)

    或者在终端中配置并测试您的端点：

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    让一个已挂钩的智能体对 `README.md` 使用其文件读取工具。确认该工具调用出现在会话记录中，然后在本地仪表板的 **Policies → Activity** 下检查它。一旦 observe 结果符合预期，请参阅 [Jev policies](/zh/policies/jev) 了解何时开启强制执行。有关提供商详情和配置说明，请参阅[集成参考](/zh/reference/jev)。
  </Tab>
</Tabs>
