Jev 在智能体运行的两个阶段发挥作用：对已完成的会话按已知答案打分，或在您向智能体下达指令的上下文中审查工具调用。

<Tabs>
  <Tab title="Jev 评估">
    当一个已完成的会话可以针对少数已知答案的问题进行打分时，请使用 Jev 评估，例如"客户是否要求退款？请回答是或否。"它可以帮助您在会话间发现规律。

    ## 创建评估

    在 Cloud 控制台中，打开 **analyse → checks → new check**（或 **new evaluation**）。描述一个固定答案的问题，审查其生成的规则，并确认 **how it checks** 为 **decision model**——即 Jev。在真实会话上[测试](/zh/evaluations/test)，然后启用它。

    ![共享评估编写表单，您可以在此描述问题、审查草稿并部署。此截图展示的是代码草稿；Jev 请使用固定答案问题。](/images/dashboard/eval-authoring-draft.png)

    ## 查看评分

    新会话完成后，打开 **analyse → checks → evals** 并选择相应评估，或使用 Cloud CLI：

    ```bash
    fp evals --since 7d
    fp evals --aggregate --since 7d
    ```

    CLI 用于读取评分；创建 Jev 评估目前需通过控制台完成。问题类型和示例请参阅 [Jev 评估](/zh/evaluations/jev)。
  </Tab>
  <Tab title="Jev 策略">
    当字符串匹配策略需要结合请求上下文来判断工具调用是否安全时，请使用 Jev 策略审查。先以 **observe** 模式启动，这样您可以在已安装策略仍负责决策的同时查看 Jev 的结果。

    Jev 的检查来自策略包；Failproof AI 不预置任何包。在您安装之前，即使已完成配置，Jev 也不会进行任何检查：

    ```bash
    failproofai policies add FailproofAI/jev-policies
    ```

    ## 设置 Cloud Jev

    在 Cloud 控制台中，打开 **settings → api keys**，在 **new key** 下选择 **a machine running failproofai**。按[快速开始](/zh/start/quickstart)中的说明配合 `failproofai config` 使用。在未配置 Jev 的机器上，此操作会以 observe 模式启用 Cloud Jev。通过以下命令检查连接状态：

    ```bash
    failproofai jev status
    failproofai jev test
    ```

    ## 使用自定义端点

    在本地控制台中，打开 **Settings → Jev**。选择提供商，粘贴其令牌，选择 **observe**，然后开启 Jev。

    ![本地 Jev 设置面板，包含提供商选择、令牌输入框和已选中的 observe 模式。](/images/dashboard/jev-settings.png)

    或通过终端配置并测试您的端点：

    ```bash
    failproofai jev --url https://api.typesafe.ai/v1 --mode observe --key-stdin < ~/typesafe.key
    failproofai jev test
    ```

    让一个已挂载 hook 的智能体对 `README.md` 使用其文件读取工具。确认该工具调用出现在会话中，然后在本地控制台的 **Policies → Activity** 下检查它。一旦 observe 结果符合预期，请参阅 [Jev 策略](/zh/policies/jev)了解何时启用强制执行。有关提供商详情和配置说明，请参阅[集成参考](/zh/reference/jev)。
  </Tab>
</Tabs>
